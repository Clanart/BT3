### Title
`compute_v2_review_set` drops amended-commit changes from the review set, letting the Stop-hook security review silently skip reviewed content - ([File: plugins/security-guidance/hooks/diffstate.py])

### Summary
`compute_v2_review_set` computes the reviewable file set as `dirty_now ∩ changed_since`, where `dirty_now` is derived from `git status --porcelain` (plus a linear-HEAD-advance diff) and `changed_since` is derived from a diff against the turn-start baseline SHA. When a user/agent commits and then amends that commit (or otherwise performs a history-rewriting sequence that leaves the working tree clean), `dirty_now` becomes empty because the tree is clean and `_is_ancestor(head_at_capture, current_head)` returns `False` (the pre-amend commit is not an ancestor of the amended commit), so the `head_at_capture..HEAD` diff is never unioned in. `changed_since` still correctly reflects the file changed relative to `baseline_sha`, but the intersection with an empty `dirty_now` yields an empty `review_set`, causing the Stop hook to treat the change as "no changes since baseline" and skip the security review entirely.

### Finding Description
`capture_git_baseline` (`plugins/security-guidance/hooks/diffstate.py:163-204`) is invoked from `handle_user_prompt_submit` on `UserPromptSubmit` [1](#0-0) , capturing `baseline_sha` (a `git stash create` object) and `head_at_capture` (`git rev-parse HEAD`) into session state.

At Stop time, `compute_v2_review_set` (`plugins/security-guidance/hooks/diffstate.py:353-438`) builds the review set:
- `tracked_dirty, untracked = _git_status_porcelain(repo)` — empty if the working tree is clean.
- The linear-advance branch only adds `head_at_capture..HEAD` diff to `dirty_now` when `_is_ancestor(repo, head_at_capture, current_head)` is `True` [2](#0-1) . `git merge-base --is-ancestor` (`plugins/security-guidance/hooks/gitutil.py:377-387`) returns `False` for an amended commit, since `--amend` produces a new commit object that is a *sibling* of the original, not a descendant of it.
- `changed_since = _git_name_only(repo, baseline_sha)` still correctly detects the file differs from the pre-turn stash baseline [3](#0-2) .
- `review_set = dirty_now & changed_since` [4](#0-3)  — with `dirty_now` empty (clean tree, no linear-advance path taken) and `changed_since` non-empty, the intersection is empty regardless of what actually changed.

At the call site, an empty `review_paths` causes an immediate skip: `if not review_paths: ... _skip(9, ...)` [5](#0-4) . This means the Stop hook exits without ever building a diff, running the Haiku vulnerability scan, or reporting findings — the dangerous amended content is never reviewed, and no error/warning surfaces to the user.

The plugin's own documentation states the intended invariant explicitly: "Mid-session commits are handled correctly (diff is against the snapshot, not HEAD)" [6](#0-5) , and `compute_v2_review_set`'s docstring says review_set should be the intersection of dirty-vs-HEAD and changed-vs-baseline specifically to filter out untouched pre-turn WIP — not to drop genuinely new content [7](#0-6) . The `--amend` (or any rebase/reset/rewrite sequence that leaves a clean tree while breaking ancestry) case violates this invariant: the review set stops being bound to what was actually touched.

### Impact Explanation
This is a Security-control bypass: the Stop hook is the only mechanism blocking Claude from ending a turn with unreviewed, potentially vulnerable code (it exits with code 2 to force continuation on findings). By committing malicious/vulnerable code and then amending the commit within the same turn (a completely ordinary git workflow — e.g., "fix typo in commit message" or "add one more file to the commit"), the dangerous content silently bypasses the LLM security review with no warning emitted, no metrics indicating a problem beyond a generic skip reason, and no user-visible signal that review was skipped due to a logic gap rather than a legitimately clean diff.

### Likelihood Explanation
This requires no privilege beyond normal use of Claude Code driving Bash tool calls (`git commit`, `git commit --amend`) inside a standard cloned repository — well within "attacker controls normal git operations in a cloned repo." It is fully deterministic: any commit followed by an amend (or any tree-rewrite that leaves the working tree clean but breaks `is-ancestor`, e.g. `git reset --hard <new-sha>` to an unrelated commit with same net content) triggers the empty-intersection bug every time. No race condition or timing dependency is needed.

### Recommendation
Do not intersect on ancestry-gated `dirty_now`; when `head_at_capture` and `current_head` differ but `head_at_capture` is *not* an ancestor of `current_head` (rewrite detected), fall back to unioning `changed_since` directly into `dirty_now` (or skip the intersection and trust `changed_since` alone) rather than silently excluding those files. At minimum, treat "amend/rewrite detected" as its own explicit branch that forces `dirty_now` to include `_git_name_only(repo, baseline_sha)`'s output (equivalent to disabling the intersection filter) so the invariant "review set stays bound to what actually changed since baseline" holds even when HEAD moves non-linearly.

### Proof of Concept
Unit/integration test plan (extending existing test patterns for `compute_v2_review_set`):
1. Init a git repo, create initial commit (file `safe.py`) — this is `HEAD` at session start.
2. Simulate UPS: call `capture_git_baseline(repo)` → `baseline_sha`; capture `head_at_capture = git rev-parse HEAD`.
3. Simulate Claude's turn: write `evil.py` with a dangerous pattern (e.g. `os.system(user_input)`), `git add`, `git commit -m "add feature"`.
4. Simulate an amend: `git commit --amend --no-edit` (working tree now clean, HEAD SHA changed, old HEAD is not an ancestor of new HEAD).
5. Call `compute_v2_review_set(repo, baseline_sha, head_at_capture, {})`.
6. **Expected (post-fix) assertion**: `review_paths` must contain the absolute path to `evil.py`.
7. **Current (pre-fix) failing assertion**: `review_paths == []` because `dirty_now` is empty (clean tree) and the `is_ancestor` check fails, so the intersection with `changed_since` (which does contain `evil.py`) yields nothing — reproducing the bypass.
8. Additionally assert that `handle_stop_hook` on this state does not call `_skip(9)` and does proceed to `get_git_diff`/`analyze_code_security` with `evil.py` included.

def handle_user_prompt_submit(input_data):
    """
    Handle UserPromptSubmit — capture git baseline SHA.
    Called on every user prompt. Updates the baseline so the stop hook
    only reviews changes made since the last prompt.

    Does NOT reset touched_paths/fire_count/previous_findings — those are
    consumed by Stop (consume_stop_state) and time-expired respectively.
    UPS racing the asyncRewake Stop hook caused a meaningful share of reviews
    to be lost when the wipe landed before Stop's state read.

    """
    cwd = input_data.get("cwd", "")
    if not cwd:
        debug_log("UPS: no cwd, skipping baseline capture")
        sys.exit(0)

    session_id = input_data.get("session_id", "default")
    # stash-create and ls-files both walk the worktree (~2-5s each in a very
    # large repo). Run them concurrently so UPS latency stays ≈ max(both).
    import concurrent.futures as _cf
    with _cf.ThreadPoolExecutor(max_workers=2) as _ex:
        _f_sha = _ex.submit(capture_git_baseline, cwd)
        _f_ut = _ex.submit(_list_untracked, cwd)
        sha = _f_sha.result()
