### Title
Secret key shares leak in plaintext via `fmt::Debug` on `ThresholdKeys`/`ThresholdView` through the `Interpolation::Constant` field - (File: crypto/dkg/src/lib.rs)

### Summary
`ThresholdCore` and `ThresholdView` implement `fmt::Debug` with deliberate redaction: they print public fields and call `finish_non_exhaustive()` to omit `secret_share`. However, both implementations do print the `interpolation` field. For `Interpolation::Constant`, that field is `Vec<F>` containing "constant coefficients, one for each of the secret key shares" — i.e., the secret shares themselves (used for n-of-n multisigs, per the `t != n` rejection in `ThresholdKeys::new`). Any diagnostic/log dump of these types leaks every participant's secret share in plaintext, enabling full group private key recovery, despite the code's evident intent to redact secrets.

### Finding Description
In `crypto/dkg/src/lib.rs`, `ThresholdCore::fmt` (lines 266–276) lists `params`, `group_key`, `verification_shares`, and `interpolation`, then uses `finish_non_exhaustive()` specifically so `secret_share` is not printed. `ThresholdView::fmt` (lines 316–329) does the same, omitting `secret_share` while including `interpolation` (line 320).

`Interpolation<C::F>` derives `Debug` (line 211), and `Interpolation::Constant` wraps `Vec<F>` whose documentation states these are "constant coefficients, one for each of the secret key shares" (lines 213–219). `ThresholdKeys::new` enforces `Constant` interpolation only when `t == n` (lines 367–372), meaning `c[i]` is literally participant `i`'s secret share of the group private key.

Because `ThresholdKeys` derives `Debug` (line 291, delegating into `ThresholdCore`), and `ThresholdView` has its own `Debug`, any `{:?}` formatting — debug logging, error traces, panic diagnostics — emits all n secret shares. Summing them (or interpolating) recovers the group private key.

This mirrors the KIC advisory exactly: a field expected to be non-sensitive diagnostic output (`Plugins` / `interpolation`) resolves and emits secret material in plaintext while sibling fields are properly redacted.

### Impact Explanation
Full compromise of the threshold group key. With `t == n` (the only configuration using `Constant` interpolation), all n secret shares are disclosed in one `Debug` output, so an observer can reconstruct the private key with a simple sum — no threshold, no collusion model needed. This subsumes "key share recovery": it is total key recovery from a single diagnostic print.

### Likelihood Explanation
Medium. Exploitation requires the `Debug` output to reach an unprivileged party — e.g., a downstream processor/coordinator logging key material structs in error paths, or diagnostic dumps — which is outside these crates' control but is a realistic integrator pattern and is precisely the threat model the redacted `finish_non_exhaustive()` design was built for. The code clearly intends `Debug` to be safe; it fails for `Constant` interpolation. Reachability by an unprivileged party depends on integrator logging, keeping this at Medium rather than High.

### Recommendation
Implement `fmt::Debug` manually for `Interpolation<F>` that prints only the variant tag (e.g., `"Constant(..)"` / `"Lagrange"`) without the coefficient vector, or wrap the coefficients in a newtype with a redacting `Debug`. Alternatively, remove `interpolation` from the `debug_struct` field lists in `ThresholdCore::fmt` and `ThresholdView::fmt`.

### Proof of Concept
```rust
// crypto/dkg (Ristretto shown; applies to any Ciphersuite)
let params = ThresholdParams::new(2, 2, Participant::new(1).unwrap()).unwrap();
// For t == n, Constant interpolation carries the raw secret shares
let c0 = <Ristretto as Ciphersuite>::F::random(&mut OsRng);
let c1 = <Ristretto as Ciphersuite>::F::random(&mut OsRng);
let mut vs = HashMap::new();
vs.insert(Participant::new(1).unwrap(), <Ristretto as Ciphersuite>::generator() * c0);
vs.insert(Participant::new(2).unwrap(), <Ristretto as Ciphersuite>::generator() * c1);

let keys = ThresholdKeys::<Ristretto>::new(
    params,
    Interpolation::Constant(vec![c0, c1]),
    Zeroizing::new(c0),
    vs,
).unwrap();

// Expected-redacted diagnostic output actually contains both secret shares
let dump = format!("{:?}", keys); // prints interpolation: Constant([c0, c1])
// group private key = c0 + c1, fully recoverable from `dump`
```
The same leak occurs via `ThresholdView`'s `Debug` (line 320) whenever `keys.view(..)` is formatted.
