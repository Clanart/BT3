### Title
KIP-71 `GasTarget` governance parameter accepts zero, causing division-by-zero panic in `NextMagmaBlockBaseFee` and halting block processing on every node - (File: params/kip71_config.go)

### Summary
The reported Notional bug is a classic "governance/state-derived divisor can become zero, causing a division-by-zero revert/panic that permanently DoSes a core protocol function." The Kaia analog is the `Kip71GasTarget` governance parameter, which is validated with a no-op format checker (accepting any `uint64`, including `0`), and is then used unguarded as a divisor in `KIP71Config.NextMagmaBlockBaseFee()`, the function that computes each block's base fee per KIP-71 (used since the Magma hardfork).

### Finding Description
`Kip71GasTarget`'s format checker performs no validation at all: [1](#0-0) 

Unlike its sibling `Kip71BaseFeeDenominator`, which explicitly rejects `0`: [2](#0-1) 

`GasTarget` has no such check, so a governance vote (or genesis/`ChainConfig` misconfiguration) setting `reward.governance.kip71.gastarget` (or the `Kip71GasTarget` param) to `0` is accepted by the parameter system.

That value then flows into `NextMagmaBlockBaseFee`, which computes the next block's base fee: [3](#0-2) 

Specifically:
- `gasTarget := kc.GasTarget` is used unguarded (unlike `BaseFeeDenominator`, which has an explicit `if kc.BaseFeeDenominator == 0` fallback at lines 71-76).
- If `gasTarget == 0` and `parentGasUsed > gasTarget` (true for any block that used any gas, since `parentGasUsed = min(parentHeaderGasUsed, upperGasLimit)` and any real block has gas used ≥ 0, actually gas used could be 0 too, but any nonzero usage triggers this branch), the code computes:
  ```
  gasUsedDelta := new(big.Int).SetUint64(parentGasUsed - gasTarget) // = parentGasUsed
  x := new(big.Int).Mul(parentBaseFee, gasUsedDelta)
  y := x.Div(x, new(big.Int).SetUint64(gasTarget))  // <-- division by zero: gasTarget == 0
  ```
- In Go, `big.Int.Div` by a zero divisor **panics** (it does not return an error), and this is not caught anywhere in the header verification / block finalization call path (`VerifyMagmaHeader` at lines 45-56 calls this function directly).

This mirrors the reported Notional bug exactly: a value that can become zero (here, `GasTarget`, analogous to `primeCashPV`) is used as an un-checked divisor in a core state-transition function (`calculateTokensToMint` ↔ `NextMagmaBlockBaseFee`), causing every subsequent invocation to fail/panic once the zero condition is reached.

### Impact Explanation
`NextMagmaBlockBaseFee` is called by every node during block header validation (`VerifyMagmaHeader`) and during block assembly/finalization to compute the required `baseFee` for every subsequent block after the Magma hardfork. If `GasTarget` is set to `0` via a governance vote (which any validator/governing node could propose and which is accepted without validation) and any block thereafter uses any gas above the (now zero) target, **every node** attempting to compute or verify the next block's base fee will panic. This is a chain-halting Denial-of-Service: no node can produce or validate blocks (base fee mismatch/panic) - a total consensus liveness failure, not merely a "no minting" annoyance as in the original report, making this severity high given the systemic and irreversible nature (the chain cannot self-heal without a hard fork/patch since every future block requires this computation).

### Likelihood Explanation
Likelihood depends on governance being able to set `GasTarget = 0`. This requires either a malicious/erroneous governance vote passing (`GovernanceMode` such as "single" allows the governing node alone to set arbitrary parameter values immediately) or a misconfigured genesis. Given there is no format check rejecting zero (unlike the sibling parameter `BaseFeeDenominator`), this is a plausible operational error or a deliberate action by a compromised/malicious governing node, and the impact (total chain halt) is severe enough to warrant a Medium/High rating even though it requires a governance-level action to trigger the zero value.

### Recommendation
Add a `FormatChecker` for `Kip71GasTarget` that rejects zero, consistent with `Kip71BaseFeeDenominator`:
```go
Kip71GasTarget: {
    Canonicalizer: uint64Canonicalizer,
    FormatChecker: func(cv any) bool {
        v, ok := cv.(uint64)
        return ok && v != 0
    },
    ...
}
```
Additionally, as defense-in-depth, `NextMagmaBlockBaseFee` should guard against `gasTarget == 0` the same way it already guards `BaseFeeDenominator == 0` (lines 71-76 in `params/kip71_config.go`), falling back to a safe default rather than dividing unconditionally.

### Proof of Concept
1. Governance (or genesis) sets `Kip71GasTarget` (`reward.governance.kip71.gastarget`) to `0` via a passing vote - accepted because `FormatChecker` for this param never checks for a nonzero value (`kaiax/gov/param.go:324-333`).
2. Once the parameter takes effect at the target block, any subsequent block with `header.GasUsed > 0` causes `parentGasUsed > gasTarget` (since `gasTarget == 0`).
3. `NextMagmaBlockBaseFee` executes `x.Div(x, new(big.Int).SetUint64(gasTarget))` with `gasTarget = 0`, which panics inside `math/big`.
4. This function is invoked by `VerifyMagmaHeader` on every node validating the new header and again during block assembly - causing the panic to occur network-wide, halting the chain.

```go
func (kc *KIP71Config) NextMagmaBlockBaseFee(parentHeaderNumber *big.Int, parentHeaderBaseFee *big.Int, parentHeaderGasUsed uint64) *big.Int {
	// governance parameters
	lowerBoundBaseFee := new(big.Int).SetUint64(kc.LowerBoundBaseFee)
	upperBoundBaseFee := new(big.Int).SetUint64(kc.UpperBoundBaseFee)
	makeEvenByCeil(lowerBoundBaseFee)
	makeEvenByFloor(upperBoundBaseFee)

	// If the parent is the magma disabled block or genesis, then return the lowerBoundBaseFee (default 25ston)
	if parentHeaderNumber.Cmp(new(big.Int).SetUint64(0)) == 0 || parentHeaderBaseFee == nil {
		return makeEvenByFloor(lowerBoundBaseFee)
	}

	var baseFeeDenominator *big.Int
	if kc.BaseFeeDenominator == 0 {
		// To avoid panic, set the fluctuation range small
		baseFeeDenominator = new(big.Int).SetUint64(64)
	} else {
		baseFeeDenominator = new(big.Int).SetUint64(kc.BaseFeeDenominator)
	}
	gasTarget := kc.GasTarget
	upperGasLimit := kc.MaxBlockGasUsedForBaseFee

	// check the case of upper/lowerBoundBaseFee is updated by governance mechanism
	parentBaseFee := parentHeaderBaseFee
	if parentBaseFee.Cmp(upperBoundBaseFee) >= 0 {
		parentBaseFee = upperBoundBaseFee
	} else if parentBaseFee.Cmp(lowerBoundBaseFee) <= 0 {
		parentBaseFee = lowerBoundBaseFee
	}

	// upper gas limit cut off the impulse of used gas to upper bound
	parentGasUsed := min(parentHeaderGasUsed, upperGasLimit)
	if parentGasUsed == gasTarget {
		return makeEvenByFloor(parentBaseFee)
	} else if parentGasUsed > gasTarget {
		// shortcut. If parentBaseFee is already reached upperbound, do not calculate.
		if parentBaseFee.Cmp(upperBoundBaseFee) == 0 {
			return makeEvenByFloor(upperBoundBaseFee)
		}
		// If the parent block used more gas than its target,
		// the baseFee of the next block should increase.
		// baseFeeDelta = max(1, parentBaseFee * (parentGasUsed - gasTarget) / gasTarget / baseFeeDenominator)
		gasUsedDelta := new(big.Int).SetUint64(parentGasUsed - gasTarget)
		x := new(big.Int).Mul(parentBaseFee, gasUsedDelta)
		y := x.Div(x, new(big.Int).SetUint64(gasTarget))
		baseFeeDelta := math.BigMax(x.Div(y, baseFeeDenominator), common.Big1)

		nextBaseFee := x.Add(parentBaseFee, baseFeeDelta)
		if nextBaseFee.Cmp(upperBoundBaseFee) > 0 {
			return makeEvenByFloor(upperBoundBaseFee)
		}
		return makeEvenByFloor(nextBaseFee)
	} else {
		// shortcut. If parentBaseFee is already reached lower bound, do not calculate.
		if parentBaseFee.Cmp(lowerBoundBaseFee) == 0 {
			return makeEvenByFloor(lowerBoundBaseFee)
		}
		// Otherwise if the parent block used less gas than its target,
		// the baseFee of the next block should decrease.
		// baseFeeDelta = parentBaseFee * (gasTarget - parentGasUsed) / gasTarget / baseFeeDenominator
		gasUsedDelta := new(big.Int).SetUint64(gasTarget - parentGasUsed)
		x := new(big.Int).Mul(parentBaseFee, gasUsedDelta)
		y := x.Div(x, new(big.Int).SetUint64(gasTarget))
		baseFeeDelta := x.Div(y, baseFeeDenominator)

		nextBaseFee := x.Sub(parentBaseFee, baseFeeDelta)
		if nextBaseFee.Cmp(lowerBoundBaseFee) < 0 {
			return makeEvenByFloor(lowerBoundBaseFee)
		}
		return makeEvenByFloor(nextBaseFee)
	}
```
