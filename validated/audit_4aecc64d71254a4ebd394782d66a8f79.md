### Title
Front-running bribe harvests by voting into `delegatedPool` right before `harvestAll()` dilutes/steals unclaimed yield from prior delegatedPool voters - ([File: rewards/DelegateVoteRewardPool.sol])

### Summary
`DelegateVoteRewardPool.harvestAll()` has no access-control modifier and can be called by anyone, immediately after which `_manageRewards` → `_queueNewRewardsWithoutTransfer` spreads the freshly-harvested bribe amount over `totalSupply` at that instant. [1](#0-0)  Because staking into this pool via `WombatBribeManager.vote()` has no time lock and reward distribution is a single instantaneous injection (not a time-weighted stream), an attacker can vote into `delegatedPool` immediately before triggering a harvest, capture a pro-rata share of bribes that accrued entirely before their deposit, then withdraw their vote right after, extracting yield that would otherwise have gone to long-term voters.

### Finding Description
`DelegateVoteRewardPool` inherits `stakeFor`/`withdrawFor` from `BribeRewardPool`, gated only by `onlyOperator` (the `WombatBribeManager`), which any vlMGP holder can trigger indirectly by calling `WombatBribeManager.vote([delegatedPool],[+X])`: [2](#0-1) 

`harvestAll()` itself has **no modifier at all**: [1](#0-0) 

It calls `WombatBribeManager.claimAllBribes(address(this))`, which harvests all pending bribes accrued by the delegated voting power since the last harvest (this reward amount `R` is fixed at call time, based on bribes accrued over the *entire prior interval*, regardless of when the caller joined), then routes them to `_manageRewards` → `_queueNewRewardsWithoutTransfer`: [3](#0-2) 

The reward-per-token increment is computed as `_amountReward * 1e_decimals / totalSupply`, using `totalSupply` **at the moment of the harvest**, i.e. after any just-completed `stakeFor` calls have already inflated it. Because `updateRewards` (called during `stakeFor`) only checkpoints the attacker's already-accrued rewards using the rewardPerToken value **before** their deposit, it correctly prevents them from stealing rewards accrued prior to their entry via `rewardPerTokenStored` — but it does **not** prevent them from being included in the very next `_provisionReward` injection, since that computation happens after their balance is already counted in `totalSupply`. [4](#0-3) [5](#0-4) 

Concretely: attacker calls `vote([delegatedPool],[+X])` → stakes `X`, raising `totalSupply` from `S` to `S+X`. Attacker (or anyone) then calls `harvestAll()`, which harvests bribe amount `R` accrued entirely from the vote-weight of long-term stakers over the prior period, and distributes it as `rewardPerTokenStored += R * 1e_dec / (S+X)`. The attacker instantly becomes entitled to `X * R / (S+X)` of that harvest despite contributing zero time toward earning it, extractable immediately via `getReward(attacker)` (also unrestricted) and `WombatBribeManager.claimAllBribes`: [6](#0-5) [7](#0-6) 

The attacker can then immediately unwind by calling `vote([delegatedPool],[-X])`, which calls `withdrawFor` with no cooldown or lockup on the vote allocation itself: [8](#0-7) 

None of the existing checks (`onlyOperator` on `stakeFor`, `updateRewards` checkpointing) stop this, since they only protect against stealing *previously accrued but unclaimed* `rewardPerTokenStored`, not against being counted in a *fresh, about-to-be-distributed* lump-sum injection. There is no time-weighted emission (no `rewardRate`/`periodFinish` streaming), so the entire freshly harvested bribe is exposed to whoever holds a balance at the exact block of `_provisionReward`.

### Impact Explanation
Long-term `delegatedPool` voters have a portion of their earned bribe yield diverted to a last-moment depositor who contributed no time-weighted voting power to generating that yield. This matches the "theft of unclaimed yield" impact class. The magnitude scales with the size of the stake `X` the attacker can shift into `delegatedPool` immediately before a harvest, relative to existing `totalSupply` `S`; extractable value is `X * R / (S+X)`, taken directly from what other voters would have earned.

### Likelihood Explanation
This requires only:
- Attacker already holds locked vlMGP with unused (or reallocatable) voting power — a normal condition for any vlMGP holder.
- Ability to call `WombatBribeManager.vote()` (public, unprivileged) and `DelegateVoteRewardPool.harvestAll()` (public, unprivileged, no access control).
- No flash loan needed since vlMGP votes can be freely reallocated between pools with no lockup on the vote allocation itself.
- The attack is repeatable every time bribes are pending to be harvested (e.g., can be front-run right before any legitimate `castVotes()` call, which itself triggers `harvestAll()`), making it low-cost and reliably exploitable by any vlMGP holder, including via a bot watching for pending, unharvested bribes.

### Recommendation
Convert the delegated-pool reward distribution to a time-weighted/streamed model (e.g., Synthetix-style `rewardRate` + `periodFinish` drip) instead of instantaneous lump-sum injection based on current `totalSupply`, or add a minimum staking duration / harvest-cooldown before newly staked balances become eligible for freshly harvested rewards. Additionally, add access control (e.g., restrict to `onlyOperator` or add a fee/cooldown) on `harvestAll()` so it cannot be triggered arbitrarily to time an entry.

### Proof of Concept
Foundry test plan:
1. Deploy `DelegateVoteRewardPool`, `WombatBribeManager`, and mock `Voter`/`Bribe` contracts such that a fixed bribe amount `R` accrues to `delegatedPool` over a simulated voting period, while only a "long-term" staker (`S` vlMGP) is registered.
2. Advance time/blocks so `R` accrues in the underlying bribe contract but is not yet harvested.
3. In a single block/transaction: have `attacker` call `WombatBribeManager.vote([delegatedPool],[X])` to stake `X` vlMGP into `delegatedPool`.
4. Immediately call `DelegateVoteRewardPool.harvestAll()` (as the attacker or any third party) to trigger `claimAllBribes` and `_queueNewRewardsWithoutTransfer` with the full `R`.
5. Read `earned(attacker, rewardToken)` and `earned(longTermStaker, rewardToken)`.
6. Assert `earned(attacker, rewardToken) ≈ X * R / (S + X) > 0`, and `earned(longTermStaker, rewardToken) ≈ S * R / (S + X) < R` (strictly less than the full `R` the long-term staker would have received absent the attacker's last-minute deposit).
7. Have attacker call `WombatBribeManager.claimAllBribes(attacker)` (or `getReward(attacker)` directly) to withdraw the extracted amount, then `vote([delegatedPool],[-X])` to fully unwind the position in the same test, confirming zero net capital lockup cost beyond gas.

    function _queueNewRewardsWithoutTransfer(
        uint256 _amountReward,
        address _rewardToken
    ) internal {
        if (!isRewardToken[_rewardToken]) {
            rewardTokens.push(_rewardToken);
            isRewardToken[_rewardToken] = true;
        }
        Reward storage rewardInfo = rewards[_rewardToken];
        rewardInfo.historicalRewards =
            rewardInfo.historicalRewards +
            _amountReward;
        if (totalSupply == 0) {
            rewardInfo.queuedRewards += _amountReward;
        } else {
            if (rewardInfo.queuedRewards > 0) {
                _amountReward += rewardInfo.queuedRewards;
                rewardInfo.queuedRewards = 0;
            }
            rewardInfo.rewardPerTokenStored =
                rewardInfo.rewardPerTokenStored +
                (_amountReward * 10 ** this.stakingDecimals()) /
                totalSupply;
        }
        emit RewardAdded(_amountReward, _rewardToken);
    }
