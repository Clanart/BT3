### Title
Missing bounds checking in `is_clvm_canonical`/`is_atom_canonical` allows an out-of-bounds read (`IndexError`) on attacker-controlled spend bundle solutions - (File: `chia/full_node/mempool_manager.py`)

### Summary
`is_clvm_canonical()` and its helper `is_atom_canonical()` in `chia/full_node/mempool_manager.py` walk a raw CLVM byte buffer to determine whether it is encoded in the "shortest form," which is required for a spend to be eligible for dedup/fast-forward processing in the mempool. The walking logic advances an `offset` and indexes directly into the buffer (`clvm_buffer[offset]`) without first checking that `offset` is still within bounds. A truncated or malformed CLVM buffer — reachable from an unprivileged spend-bundle submitter's solution bytes — can drive `offset` past the end of the buffer and trigger an unhandled `IndexError`, echoing the root cause of ALPINE-CVE-2021-3121 ("skippy peanut butter"): unmarshal logic that lacks index validation before dereferencing attacker-controlled length/offset fields. [1](#0-0) [2](#0-1) 

### Finding Description
`is_atom_canonical(clvm_buffer, offset)` reads `clvm_buffer[offset]` to get the atom's tag byte, computes a `prefix_len` based on which bit pattern matched, and then loops `prefix_len` times, each iteration doing `offset += 1; atom_len |= clvm_buffer[offset]` with no check that `offset < len(clvm_buffer)`: [3](#0-2) 

`is_clvm_canonical(clvm_buffer)` similarly loops reading `b = clvm_buffer[offset]`, and for pair tokens (`0xFF`) simply increments `offset` and continues to the next iteration without verifying that a following byte exists: [4](#0-3) 

Both functions assume the buffer is well-formed and long enough to satisfy every length-prefix/pair-token they encounter, exactly analogous to the CVE-2021-3121 issue where GoGo Protobuf's `unmarshal.go` failed to validate an index before use. Because this buffer is derived from spend-bundle solution bytes submitted by an ordinary wallet user/spend-bundle submitter (used during mempool item eligibility classification per `.cursor/context/clvm-execution.md`, which documents this function's location and DEDUP-eligibility role), a crafted, truncated CLVM atom (e.g., a length-prefix byte claiming multiple additional prefix bytes but supplying none, or a trailing `0xFF` pair token with no following bytes) will cause `clvm_buffer[offset]` to raise `IndexError` instead of returning a controlled `False`/rejection. [5](#0-4) 

### Impact Explanation
An unhandled `IndexError` raised from mempool item processing on a maliciously-crafted but otherwise well-formed spend bundle could interrupt the eligibility-check code path (dedup/fast-forward classification during mempool admission), potentially causing spend-bundle processing to fail or be aborted in ways not anticipated by callers that don't wrap this call in an exception handler. This matches the "spend-triggered transaction-processing halt" impact category: a single submitted spend bundle can, through a path only reachable by CLVM buffer content, cause an unexpected exception in full node mempool logic rather than a clean rejection.

### Likelihood Explanation
Likelihood is moderate: reaching this code requires only submitting a spend bundle whose solution's serialized CLVM bytes are crafted to end mid-atom-length-prefix or mid-pair-token — something within reach of any unprivileged spend-bundle submitter. I was not able to fully confirm, within the available search budget, the exact call site(s) of `is_clvm_canonical()` and whether an outer `try/except` in `pre_validate_spendbundle()` or elsewhere already catches generic exceptions and demotes them to a rejection rather than propagating; this uncertainty should be resolved by direct code review of the call sites before treating this as a confirmed live DoS.

### Recommendation
Add explicit bounds checks in `is_atom_canonical()` and `is_clvm_canonical()` before every buffer index/slice, returning `False` (not-canonical) or raising a well-defined `ValueError` (consistent with the pattern already used in `chia/full_node/full_block_utils.py`'s `skip_bytes`/`skip_list`, which validate lengths against remaining buffer size before slicing) instead of allowing a raw `IndexError` to propagate from attacker-controlled input. [6](#0-5) 

### Proof of Concept
Construct a CLVM buffer whose final atom declares a multi-byte length prefix but is truncated before the required bytes are present, e.g. a buffer ending in `0xF8` (2+8+8+8+8-bit length prefix atom tag) with zero trailing bytes. Calling `is_clvm_canonical(buffer)` (or `is_atom_canonical(buffer, offset)` directly at that offset) will index past the end of `clvm_buffer` and raise `IndexError` rather than returning `False`. Embedding such a buffer as the CLVM solution of an otherwise-valid spend bundle would cause code paths in `chia/full_node/mempool_manager.py` that call `is_clvm_canonical()` on the spend's serialized bytes to raise this unhandled exception. [7](#0-6)

def is_atom_canonical(clvm_buffer: bytes, offset: int) -> tuple[int, bool]:
    b = clvm_buffer[offset]
    if (b & 0b11000000) == 0b10000000:
        # 6 bits length prefix
        mask = 0b00111111
        prefix_len = 0
        min_value = 1
    elif (b & 0b11100000) == 0b11000000:
        # 5 + 8 bits length prefix
        mask = 0b00011111
        prefix_len = 1
        min_value = 1 << 6
    elif (b & 0b11110000) == 0b11100000:
        # 4 + 8 + 8 bits length prefix
        mask = 0b00001111
        prefix_len = 2
        min_value = 1 << (5 + 8)
    elif (b & 0b11111000) == 0b11110000:
        # 3 + 8 + 8 + 8 bits length prefix
        mask = 0b00000111
        prefix_len = 3
        min_value = 1 << (4 + 8 + 8)
    elif (b & 0b11111100) == 0b11111000:
        # 2 + 8 + 8 + 8 + 8 bits length prefix
        mask = 0b00000011
        prefix_len = 4
        min_value = 1 << (3 + 8 + 8 + 8)
    elif (b & 0b11111110) == 0b11111100:
        # 1 + 8 + 8 + 8 + 8 + 8 bits length prefix
        mask = 0b00000001
        prefix_len = 5
        min_value = 1 << (2 + 8 + 8 + 8 + 8)

    atom_len = b & mask
    for i in range(prefix_len):
        atom_len <<= 8
        offset += 1
        atom_len |= clvm_buffer[offset]

    return 1 + prefix_len + atom_len, atom_len >= min_value


def is_clvm_canonical(clvm_buffer: bytes) -> bool:
    """
    checks whether the CLVM serialization is all canonical representation.
    atoms can be serialized in more than one way by using more bytes than
    necessary to encode the length prefix. This functions ensures that all atoms are
    encoded with the shortest representation. back-references are not allowed
    and will make this function return false
    """
    assert clvm_buffer != b""

    offset = 0
    tokens_left = 1
    while True:
        b = clvm_buffer[offset]

        # pair
        if b == 0xFF:
            tokens_left += 1
            offset += 1
            continue

        # back references cannot be considered canonical, since they may be
        # encoded in many different ways
        if b == 0xFE:
            return False

        # small atom or NIL
        if b <= 0x80:
            tokens_left -= 1
            offset += 1
        else:
            atom_len, canonical = is_atom_canonical(clvm_buffer, offset)
            if not canonical:
                return False
            tokens_left -= 1
            offset += atom_len

        if tokens_left == 0:
            break

    # if there's garbage at the end, it's not canonical
    return offset == len(clvm_buffer)

### `is_clvm_canonical(clvm_buffer)`

Checks that a CLVM program uses shortest-form atom encoding:

- No unnecessary length prefix bytes
- No back-references (`0xFE` byte)
- No trailing garbage

### When enforced

Required for DEDUP-eligible spends. Without canonical form, identical
solutions could have different serializations, breaking dedup.

### `is_atom_canonical(clvm_buffer, offset)`

Validates a single atom's length prefix encoding. The CLVM format uses
variable-length prefixes (1-6 bytes) based on atom size. Each prefix
length has a minimum atom size threshold.

def skip_list(buf: memoryview, skip_item: Callable[[memoryview], memoryview]) -> memoryview:
    if len(buf) < 4:
        raise ValueError(f"list count prefix requires 4 bytes, remaining buffer {len(buf)}")
    n = int.from_bytes(buf[:4], "big", signed=False)
    buf = buf[4:]
    if n > len(buf):
        raise ValueError(f"list count {n} exceeds remaining buffer {len(buf)}")
    for _ in range(n):
        buf = skip_item(buf)
    return buf


def skip_bytes(buf: memoryview) -> memoryview:
    if len(buf) < 4:
        raise ValueError(f"byte length prefix requires 4 bytes, remaining buffer {len(buf)}")
    n = int.from_bytes(buf[:4], "big", signed=False)
    buf = buf[4:]
    if n > len(buf):
        raise ValueError(f"byte length {n} exceeds remaining buffer {len(buf)}")
    return buf[n:]
