Confirmed: `types.CreateDenom(strContract)` derives the denom deterministically from the ERC20 contract's address, so re-registration at the same address reproduces the same denom used previously.

### Title
Token-pair denom hijack via self-destruct + CREATE2 metamorphic redeploy allows destruction of legitimate user coin balances - (File: x/erc20/keeper/msg_server.go, x/erc20/keeper/proposals.go)

### Summary
The external report's bug class is "a deleted/reused identifier slot is not fully invalidated before a downstream consumer trusts it as fresh, allowing an attacker-controlled create/transfer action to silently overwrite a system-managed record." The Cosmos EVM analog is in the `x/erc20` module: a `TokenPair` for an externally-owned (`OWNER_EXTERNAL`) ERC20 contract is deleted only when its bytecode is observed as removed (self-destructed) [1](#0-0) , but the bank `denom` bound to that pair, `types.CreateDenom(contractAddress)`, is purely a function of the EVM address [2](#0-1) . If a contract deployed via `CREATE2` self-destructs and is later redeployed at the *same address* with different (malicious) bytecode — a well-known "metamorphic contract" pattern the attacker fully controls when they chose the `CREATE2` salt/init code originally — a new, permissionless `RegisterERC20` call [3](#0-2)  will succeed because `IsERC20Registered`/`IsDenomRegistered` were cleared by the earlier `DeleteTokenPair` [4](#0-3) , and `registerERC20` will re-derive the identical denom string for the new (malicious) contract [5](#0-4) .

### Finding Description
1. A user deploys ERC20 contract `C` via a `CREATE2` factory (attacker chooses salt/init-code) and it gets registered as a `TokenPair` (`OWNER_EXTERNAL`) with denom `erc20/0xC...`. Other users legitimately convert real value into this denom via `ConvertERC20`, which mints Cosmos coins 1:1 while escrowing the ERC20 tokens on the module address [6](#0-5) .
2. The attacker self-destructs `C`. Any user subsequently calling `ConvertERC20`/`ConvertCoin` on that pair triggers the "selfdestructed" branch, which unconditionally calls `k.DeleteTokenPair(ctx, pair)` [1](#0-0) [7](#0-6) . This clears the ERC20-map, denom-map, and allowances [4](#0-3)  — but does **not** touch the bank coin supply of `erc20/0xC...` that is still circulating among other holders, and does not burn/freeze it.
3. The attacker redeploys a malicious contract at the exact same address `C` (the metamorphic `CREATE2` trick), then calls `RegisterERC20` again (permissionless if `PermissionlessRegistration` is enabled, otherwise via governance-controlled path once, which is still not sufficient protection since the identity binding is address-based) [3](#0-2) . `registerERC20` re-derives the identical denom `erc20/0xC...` from the address and creates a fresh `TokenPair` pointing legitimate, still-circulating coin balances at the attacker's new, arbitrary bytecode [5](#0-4) .
4. Any holder of the old `erc20/0xC...` coin who now calls `ConvertCoin` will have `ConvertCoinNativeERC20` escrow (burn) their real coins and call `transfer` on the attacker's malicious contract [8](#0-7) . Because the attacker fully controls the contract's code, it can report success and any `balanceOf` deltas the invariant checks expect, defeating the `ErrBalanceInvariance` guard while never delivering real value, and the module unconditionally burns the escrowed coins.

### Impact Explanation
This breaks the "asset-representation path" invariant (1:1 accounting between native coins and ERC20-visible balances) called out in the smart-audit pivots. Legitimate users' bank coin balances backed by real economic value are irreversibly burned in exchange for a token controlled by the attacker's arbitrary, unaudited bytecode, i.e. permanent loss/theft of spendable user value — a Critical impact matching the allowed-impact gate ("permanent freezing, locking, theft ... of spendable user value across native balances ... ERC20 representations"). No privileged action is required by the attacker other than ordinary, permissionless `CREATE2` contract deployment, `SELFDESTRUCT`, redeployment, and `MsgRegisterERC20`/`MsgConvertCoin` — all standard user-facing transaction flows.

### Likelihood Explanation
Requires: (a) the attacker to have deployed the original contract via a `CREATE2` factory they control (so they can redeploy different code at the same address later — a well-documented technique), (b) `PermissionlessRegistration` enabled or an accommodating governance registration, and (c) at least one other user having previously converted coins into that denom and continuing to hold a balance when the address is hijacked. This is a realistic, self-contained attack chain fully within the reach of an unprivileged user and does not depend on relayer/validator/admin misbehavior, but it does require some setup (deploying the metamorphic factory beforehand and waiting for third-party adoption of the token pair), so likelihood is moderate rather than trivial.

### Recommendation
- Prevent silent, permissionless deletion+re-registration cycles for the same address: either (1) permanently blacklist an ERC20 address for `TokenPair` registration once it has ever been registered and later deleted (self-destructed), or (2) tie the denom identity to something immutable beyond the raw address (e.g., include the original codehash or a monotonically increasing registration nonce in the denom/id), so a redeployed contract at the same address cannot inherit a stale, still-circulating coin denom.
- Alternatively, when `DeleteTokenPair` is triggered due to self-destruct detection, also permanently disable the corresponding denom (e.g., mark it non-convertible/non-mintable forever) rather than merely removing the mapping, so it cannot be silently re-bound to new bytecode.
- Add an explicit check in `registerERC20`/`CreateCoinMetadata` rejecting registration if the denom was previously registered and deleted, even though it is not currently present in the active maps.

### Proof of Concept
Not independently reproduced in this analysis (no sandbox/tooling available); the trace above is derived purely from static code reading of `x/erc20/keeper/msg_server.go` (`ConvertERC20`/`ConvertCoin`/`convertERC20IntoCoinsForNativeToken`/`ConvertCoinNativeERC20`), `x/erc20/keeper/token_pairs.go` (`DeleteTokenPair`), and `x/erc20/keeper/proposals.go` (`registerERC20`/`CreateCoinMetadata`). A concrete PoC would need: deploying a `CREATE2` factory contract, deploying ERC20 `C`, registering it, having a second account convert coin into `erc20/0xC`, self-destructing `C`, triggering the delete path via a `ConvertERC20`/`ConvertCoin` call, redeploying malicious code at the same address via the factory, re-registering it, and then convert-cycling the original holder's coin against the new malicious contract to demonstrate the burn without real value transfer.

	pair types.TokenPair,
	msg *types.MsgConvertERC20,

		return nil, sdkerrors.Wrap(types.ErrEVMCall, "failed to retrieve balance")
	}

	transferData, err := erc20.Pack("transfer", types.ModuleAddress, msg.Amount.BigInt())
	if err != nil {
		return nil, err

	if err != nil {
		return nil, err
	}

	// Check evm call response
	var unpackedRet types.ERC20BoolResponse
	if len(res.Ret) == 0 {
		// if the token does not return a value, check for the transfer event in logs
		if err := validateTransferEventExists(res.Logs, contract); err != nil {
			return nil, err
		}
	} else {
		if err := erc20.UnpackIntoInterface(&unpackedRet, "transfer", res.Ret); err != nil {
			return nil, err
		}
		if !unpackedRet.Value {
			return nil, sdkerrors.Wrap(errortypes.ErrLogic, "failed to execute transfer")
		}
	}

	// Check expected escrow balance after transfer execution
	// NOTE: coin fields already validated in the ValidateBasic() of the message
	coins := sdk.Coins{sdk.Coin{Denom: pair.Denom, Amount: msg.Amount}}
	tokens := coins[0].Amount.BigInt()
	balanceTokenAfter := k.BalanceOf(ctx, erc20, contract, types.ModuleAddress)
	if balanceTokenAfter == nil {
		return nil, sdkerrors.Wrap(types.ErrEVMCall, "failed to retrieve balance")
	}

	expToken := big.NewInt(0).Add(balanceToken, tokens)

	if r := balanceTokenAfter.Cmp(expToken); r != 0 {
		return nil, sdkerrors.Wrapf(
			types.ErrBalanceInvariance,
			"invalid token balance - expected: %v, actual: %v",
			expToken, balanceTokenAfter,
		)
	}

	// Mint coins
	if err := k.bankKeeper.MintCoins(ctx, types.ModuleName, coins); err != nil {
		return nil, err
	}

	// Send minted coins to the receiver
	if err := k.bankKeeper.SendCoinsFromModuleToAccount(ctx, types.ModuleName, receiver, coins); err != nil {
		return nil, err
	}

func (k Keeper) ConvertCoinNativeERC20(
	ctx sdk.Context,
	pair types.TokenPair,
	amount math.Int,
	receiver common.Address,
	sender sdk.AccAddress,
) error {
	if !amount.IsPositive() {
		return sdkerrors.Wrap(types.ErrNegativeToken, "converted coin amount must be positive")
	}

	erc20 := contracts.ERC20MinterBurnerDecimalsContract.ABI
	contract := pair.GetERC20Contract()

	balanceToken := k.BalanceOf(ctx, erc20, contract, receiver)
	if balanceToken == nil {
		return sdkerrors.Wrap(types.ErrEVMCall, "failed to retrieve balance")
	}

	// Escrow Coins on module account
	coins := sdk.Coins{{Denom: pair.Denom, Amount: amount}}
	if err := k.bankKeeper.SendCoinsFromAccountToModule(ctx, sender, types.ModuleName, coins); err != nil {
		return sdkerrors.Wrap(err, "failed to escrow coins")
	}

	// Unescrow Tokens and send to receiver
	res, err := k.evmKeeper.CallEVM(ctx, erc20, types.ModuleAddress, contract, true, nil, "transfer", receiver, amount.BigInt())
	if err != nil {
		return err
	}

	// Check unpackedRet execution
	var unpackedRet types.ERC20BoolResponse
	if len(res.Ret) == 0 {
		// if the token does not return a value, check for the transfer event in logs
		if err := validateTransferEventExists(res.Logs, contract); err != nil {
			return err
		}
	} else {
		if err := erc20.UnpackIntoInterface(&unpackedRet, "transfer", res.Ret); err != nil {
			return err
		}
		if !unpackedRet.Value {
			return sdkerrors.Wrap(errortypes.ErrLogic, "failed to execute unescrow tokens from user")
		}
	}

	// Check expected Receiver balance after transfer execution
	balanceTokenAfter := k.BalanceOf(ctx, erc20, contract, receiver)
	if balanceTokenAfter == nil {
		return sdkerrors.Wrap(types.ErrEVMCall, "failed to retrieve balance")
	}

	exp := big.NewInt(0).Add(balanceToken, amount.BigInt())

	if r := balanceTokenAfter.Cmp(exp); r != 0 {
		return sdkerrors.Wrapf(
			types.ErrBalanceInvariance,
			"invalid token balance - expected: %v, actual: %v", exp, balanceTokenAfter,
		)
	}

	// Burn escrowed Coins
	err = k.bankKeeper.BurnCoins(ctx, types.ModuleName, coins)
	if err != nil {
		return sdkerrors.Wrap(err, "failed to burn coins")
	}

	return nil
}

// RegisterERC20 implements the gRPC MsgServer interface. Any account can permissionlessly
// register a native ERC20 contract to map to a Cosmos Coin.
func (k *Keeper) RegisterERC20(goCtx context.Context, req *types.MsgRegisterERC20) (*types.MsgRegisterERC20Response, error) {
	ctx := sdk.UnwrapSDKContext(goCtx)

	params := k.GetParams(ctx)

	if !params.PermissionlessRegistration {
		if err := k.validateAuthority(req.Signer); err != nil {
			return nil, err
		}
	}

	// Check if the conversion is globally enabled
	if !k.IsERC20Enabled(ctx) {
		return nil, types.ErrERC20Disabled.Wrap("registration is currently disabled by governance")
	}

	for _, addr := range req.Erc20Addresses {
		if !common.IsHexAddress(addr) {
			return nil, errortypes.ErrInvalidAddress.Wrapf("invalid ERC20 contract address: %s", addr)
		}

		pair, err := k.registerERC20(ctx, common.HexToAddress(addr))
		if err != nil {
			return nil, err
		}

		ctx.EventManager().EmitEvent(
			sdk.NewEvent(
				types.EventTypeRegisterERC20,
				sdk.NewAttribute(types.AttributeKeyCosmosCoin, pair.Denom),
				sdk.NewAttribute(types.AttributeKeyERC20Token, pair.Erc20Address),
			),
		)
	}

	return &types.MsgRegisterERC20Response{}, nil
}

func (k Keeper) registerERC20(
	ctx sdk.Context,
	contract common.Address,
) (*types.TokenPair, error) {
	// Check if ERC20 is already registered
	if k.IsERC20Registered(ctx, contract) {
		return nil, errorsmod.Wrapf(
			types.ErrTokenPairAlreadyExists, "token ERC20 contract already registered: %s", contract.String(),
		)
	}

	metadata, err := k.CreateCoinMetadata(ctx, contract)
	if err != nil {
		return nil, errorsmod.Wrap(
			err, "failed to create wrapped coin denom metadata for ERC20",
		)
	}

	pair := types.NewTokenPair(contract, metadata.Name, types.OWNER_EXTERNAL)
	err = k.SetToken(ctx, pair)
	if err != nil {
		return nil, err
	}
	return &pair, nil
}

// DeleteTokenPair removes a token pair.
func (k Keeper) DeleteTokenPair(ctx sdk.Context, tokenPair types.TokenPair) {
	id := tokenPair.GetID()
	k.deleteTokenPair(ctx, id)
	k.deleteERC20Map(ctx, tokenPair.GetERC20Contract())
	k.deleteDenomMap(ctx, tokenPair.Denom)
	k.deleteAllowances(ctx, tokenPair.GetERC20Contract())
}
