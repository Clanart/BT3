### Title
Naive hostname-substring heuristic lets an attacker-controlled remote/proxy be trusted as a "GitHub Enterprise" host, triggering GitHub sign-in prompts and credential handling for a malicious server - (File: `app/src/lib/api.ts`, `app/src/lib/trampoline/trampoline-credential-helper.ts`)

### Summary
`isGitHubHost` in `app/src/lib/api.ts` classifies an arbitrary URL as a genuine GitHub/GHE host using a hostname *substring* regex (`/(^|\.)(github)\./`) before ever attempting the network-based verification (checking for `x-github-request-id`). Any attacker who owns a subdomain like `github.evilcorp.com` (fully attacker-controlled — no relationship to GitHub required) will pass this check and be classified `true`, bypassing the "trust but verify" HEAD request entirely.

This function feeds directly into `getEndpointKind` in `app/src/lib/trampoline/trampoline-credential-helper.ts`, the credential helper used for every git HTTP(S) operation (clone, fetch, push, submodule updates, LFS). Just like `OracleRef` assumed a backup oracle would use the "same normalizer" as the primary Chainlink oracle without validating that assumption, Desktop's credential/host-classification logic assumes any host whose name merely *contains* the substring `github.` behaves like — and can be trusted as — a real GitHub Enterprise endpoint, without cryptographic or authoritative verification.

This regex only requires the literal label `github` to appear at the start of the hostname or immediately after a dot, followed by another dot. It says nothing about the *registrable domain*. `github.evilcorp.com`, `foo.github.evilcorp.com`, or `github.attacker-infra.net` are ordinary subdomains that any attacker who controls a domain can create — no compromise of GitHub, DNS, or TLS is required.

The result feeds `getEndpointKind` in the credential trampoline handler: [2](#0-1) 

Note the same weak-trust pattern occurs redundantly one step earlier for a *different* reason: an attacker-controlled HTTP server can also simply answer any credential probe with a `WWW-Authenticate: Basic realm="GitHub"` header, which `getEndpointKind` treats as sufficient proof of being a GitHub host:
```
for (const [k, v] of cred.entries()) {

```
Both paths — the hostname-substring heuristic and the self-reported `WWW-Authenticate` realm — are attacker-controlled data being used as the sole trust signal, with no cross-check against a scaling/normalization-equivalent invariant that a real GHE deployment would actually satisfy (valid TLS chain issued for the domain is not enough — GitHub's identity is never actually asserted cryptographically here).

Once `endpointKind` is `'enterprise'`, `getCredential` treats the host as first-party: [3](#0-2) 
- If no account exists yet for that (fake) endpoint, Desktop calls `ui.promptForGitHubSignIn(endpoint)`, presenting the user with what appears to be a legitimate "sign in to GitHub Enterprise" flow for the attacker's domain.
- Crucially, `storeCredential`/`eraseCredential` also gate on the same `getEndpointKind !== 'generic'` check, so this classification isn't cosmetic — it changes how Desktop manages secrets for that host end-to-end, deviating from the behavior a user/administrator would expect for an unverified third-party server.

This host can be reached by the trampoline purely as a side effect of git operations Desktop performs automatically and without extra user steps: cloning a repository whose `.gitmodules` references a submodule hosted at `https://github.evilcorp.com/...`, or an LFS `.lfsconfig`/remote pointing there. Both are attacker-controlled artifacts inside a cloned/fetched repository, matching the in-scope threat model (attacker controls a cloned/fetched repository / a git remote or proxy response).

### Impact Explanation
Once an account is created against the fake "enterprise" endpoint (via `beginEnterpriseSignIn`/`setEndpoint` in `app/src/lib/stores/sign-in-store.ts`, which likewise performs no `isGitHubHost`-style corroboration beyond basic URL syntax validation), that account's token becomes a first-class stored credential keyed to the attacker's origin. `findGitHubTrampolineAccount` in `app/src/lib/trampoline/find-account.ts` will then automatically fill this token for *any* future git operation whose URL origin matches the attacker's host — silently, with no further prompt: [4](#0-3) 

This is a credential-exfiltration primitive: a user who is led (via a plausible-looking, Desktop-endorsed "GitHub Enterprise" sign-in prompt) to authenticate against `github.evilcorp.com` will have that account's OAuth token repeatedly and automatically transmitted to the attacker's server on subsequent git operations, exactly the kind of "credential/token exfiltration" and "unauthorized OAuth or account binding" outcome called out as in-scope.

### Likelihood Explanation
Likelihood is moderate: registering a subdomain such as `github.<attacker-domain>` requires no special privilege and is fully within attacker control. Reaching the vulnerable code path requires the user to open/clone a repository containing a submodule or LFS config pointing at the attacker host and then complete one sign-in prompt — a normal, expected interaction flow (not an "unnatural" or out-of-band step), since Desktop's own UI vouches for the host as an enterprise GitHub instance due to the flawed classification. I was not able to fully trace `trampoline-ui-helper.ts`'s `promptForGitHubSignIn` implementation to confirm exactly what host information is surfaced to the user in the dialog (the grep only found its declaration/usage sites, not the full dialog copy), so the precise wording/warning shown to the user in that specific prompt is unverified and would need further review in a live Devin session.

### Recommendation
- Remove or replace the hostname-substring heuristic in `isGitHubHost` (`/(^|\.)(github)\./`) with a check against a maintained allowlist of exact GitHub-owned domains/suffixes, or make host classification depend solely on the cryptographically-checkable `x-github-request-id` network verification (already implemented later in the function) rather than a substring pre-check that bypasses it.
- Stop trusting the self-reported `WWW-Authenticate: realm="GitHub"` header as sufficient proof; at minimum require it in conjunction with the network verification, not as an independent early-return.
- When `beginEnterpriseSignIn`/credential-helper prompts are triggered for a host that was classified solely by heuristic (not by an exact `.ghe.com`/`api.github.com` match or verified `x-github-request-id`), surface this uncertainty to the user in the sign-in dialog instead of presenting it identically to a verified enterprise host.

### Proof of Concept
1. Attacker registers `github.evilcorp.com` and stands up an HTTPS server there (any valid cert, e.g., via a public CA for that subdomain — no relation to GitHub needed).
2. Attacker publishes a public repository containing a `.gitmodules` entry: `url = https://github.evilcorp.com/foo/bar.git`.
3. Victim clones/fetches this repository in GitHub Desktop and Desktop performs (or the user triggers) a submodule update, causing git to invoke the credential trampoline for `https://github.evilcorp.com`.
4. `getEndpointKind` reaches the fallback branch, calls `isGitHubHost('https://github.evilcorp.com')`, which matches `/(^|\.)(github)\./` on hostname `github.evilcorp.com` and returns `true` without ever issuing the verification HEAD request.
5. `getCredential` treats the endpoint as `'enterprise'`; finding no existing account, it calls `ui.promptForGitHubSignIn('https://github.evilcorp.com')`.
6. Victim, seeing what Desktop presents as a legitimate GitHub Enterprise sign-in prompt, completes authentication against the attacker's server.
7. The resulting `Account` is now matched by `findGitHubTrampolineAccount` (`app/src/lib/trampoline/find-account.ts:20-29`) for any future git request whose origin is `https://github.evilcorp.com`, so the victim's token is repeatedly sent to the attacker-controlled server on subsequent fetch/push/submodule operations without further prompts.

/**
 * Attempts to determine whether or not the url belongs to a GitHub host.
 *
 * This is a best-effort attempt and may return `undefined` if encountering
 * an error making the discovery request
 */
export async function isGitHubHost(url: string) {
  const { hostname } = new window.URL(url)

  const endpoint =
    hostname === 'github.com' || hostname === 'api.github.com'
      ? getDotComAPIEndpoint()
      : getEnterpriseAPIURL(url)

  if (isDotCom(endpoint) || isGHE(endpoint)) {
    return true
  }

  if (isKnownThirdPartyHost(hostname)) {
    return false
  }

  // github.example.com,
  if (/(^|\.)(github)\./.test(hostname)) {
    return true
  }

/** Implementation of the 'get' git credential helper command */
async function getCredential(cred: Credential, store: Store, token: string) {
  const ghCred = await getGitHubCredential(cred, store)

  if (ghCred) {
    return ghCred
  }

  const endpointKind = await getEndpointKind(cred, store)
  const accounts = await store.getAll()

  const endpoint = `${getCredentialUrl(cred)}`
  const apiEndpoint = getAPIEndpoint(endpoint)

  // If it appears as if the endpoint is a GitHub host and we don't have an
  // account for that endpoint then we should prompt the user to sign in.
  if (
    endpointKind !== 'generic' &&
    !accounts.some(a => a.endpoint === apiEndpoint)
  ) {
    if (getIsBackgroundTaskEnvironment(token)) {
      debug('background task environment, skipping prompt')
      return undefined
    }

    const account = await ui.promptForGitHubSignIn(endpoint)

    if (!account) {
      setHasRejectedCredentialsForEndpoint(token, endpoint)
    }

    return credWithAccount(cred, account)
  }

  // GitHub.com/GHE creds are only stored internally
  if (endpointKind !== 'generic') {
    return undefined
  }

  return useExternalCredentialHelper()
    ? getExternalCredential(cred, token)
    : getGenericCredential(cred, token)
}

const getEndpointKind = async (cred: Credential, store: Store) => {
  const credentialUrl = getCredentialUrl(cred)
  const endpoint = `${credentialUrl}`

  if (isGist(endpoint)) {
    return 'generic'
  }

  if (isDotCom(endpoint)) {
    return 'github.com'
  }

  if (isGHE(endpoint)) {
    return 'ghe.com'
  }

  // When Git attempts to authenticate with a host it captures any
  // WWW-Authenticate headers and forwards them to the credential helper. We
  // use them as a happy-path to determine if the host is a GitHub host without
  // having to resort to making a request ourselves.
  for (const [k, v] of cred.entries()) {
    if (k.startsWith('wwwauth[')) {
      if (v.includes('realm="GitHub"')) {
        return 'enterprise'
      } else if (/realm="(GitLab|Gitea|Atlassian Bitbucket)"/.test(v)) {
        return 'generic'
      }
    }
  }

  const existingAccount = await findGitHubTrampolineAccount(store, endpoint)
  if (existingAccount) {
    return isDotCom(existingAccount.endpoint) ? 'github.com' : 'enterprise'
  }

  // All GitHub hosts use HTTPS, so if the protocol is not HTTPS we can
  // assume that this is not a GitHub host.
  if (credentialUrl.protocol !== 'https:') {
    return 'generic'
  }

  return (await isGitHubHost(endpoint)) ? 'enterprise' : 'generic'
}

export async function findGitHubTrampolineAccount(
  accountsStore: AccountsStore,
  remoteUrl: string
): Promise<Account | undefined> {
  const accounts = await accountsStore.getAll()
  const parsedUrl = new URL(remoteUrl)
  return accounts.find(
    a => new URL(getHTMLURL(a.endpoint)).origin === parsedUrl.origin
  )
}
