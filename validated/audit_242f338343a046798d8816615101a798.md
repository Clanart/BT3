### Title
Flag-injection via unguarded branch name in `checkoutBranch`/`getBranchCheckoutArgs` - (File: app/src/lib/git/checkout.ts)

### Summary
`getBranchCheckoutArgs` places the attacker-influenced `branch.name` (and, for remote branches, `branch.nameWithoutRemote`) *before* the `--` end-of-options marker instead of after it:

```ts
async function getBranchCheckoutArgs(branch: Branch) {
  return [
    branch.name,
    ...(branch.type === BranchType.Remote
      ? ['-b', branch.nameWithoutRemote]
      : []),
    '--',
  ]
}
``` [2](#0-1) 

This is inconsistent with the rest of the same file, where untrusted path/ref arguments are correctly placed **after** `--`:
```ts
await git(['checkout', 'HEAD', '--', ...paths], repository.path, 'checkoutPaths')
...
await git(['checkout', `--${resolution}`, '--', file.path], repository.path, 'checkoutConflictedFile')
``` [3](#0-2) 

### Finding Description
`checkoutBranch` builds its argv as `[...getCheckoutArgs(), ...getBranchCheckoutArgs(branch)]` and passes it straight to `git()`. [4](#0-3) 

`branch.name` for local branches, and `branch.nameWithoutRemote` for remote branches, originate from raw git ref names (`Branch.name`/`Branch.nameWithoutRemote`) with no filtering for a leading `-`. [5](#0-4)  Git's own `check-ref-format` rules (dot/space/control-char/`~^:?*[\` restrictions, no `@{`, no `..`, no trailing `.lock`/`/`) do not forbid a ref component from starting with `-`. Desktop's own UI-level sanitizer, `sanitizedRefName`, does strip a leading `-`/`+`, but this sanitizer is only applied to names the user types in Desktop's own branch-creation/rename dialogs [6](#0-5)  — it is never applied to `Branch` objects parsed from git ref listings (e.g., remote-tracking branches created by `fetch`, or a local branch that git itself creates when checking out a remote's default HEAD during `clone`).

Because `branch.name`/`branch.nameWithoutRemote` sit before the `--` sentinel in the argv array, a ref whose short name begins with `-` (e.g. a local branch literally named `-x`, or the value fed to the `-b` flag) is presented to `git checkout`'s option parser as a flag token rather than as an inert operand, violating the stated invariant ("attacker-controlled text reaches a child process only as an inert operand, never as an option/flag").

### Impact Explanation
If an attacker controls a remote/repository such that a branch (local, or the remote's default HEAD branch materialized locally on clone) has a name beginning with `-`, subsequent checkout of that branch via `checkoutBranch` passes that string to `git checkout` as an option rather than a ref, causing `git` to interpret attacker-chosen flags (e.g. `--orphan`, `-p`, `--ours/--theirs`, or an embedded `--foo=bar` single-token form) instead of performing an ordinary checkout. This can silently change what get checked out/committed, corrupt working-tree state, or otherwise divert git's behavior — matching the "Critical: git ... executes attacker-chosen options" impact class described in scope.

### Likelihood Explanation
Exploitability depends on Desktop (or the underlying git client, e.g. during `clone`) actually materializing a local `Branch` object whose short name starts with `-`, since git ref rules do not forbid this. This is plausible but not something I could fully confirm from the indexed code alone (clone/HEAD-symref-translation logic is outside `checkout.ts`), and the `-b <value>` slot specifically is less exploitable in isolation because `-b` consumes the following token as an option value regardless of its leading dash. The bare `branch.name` slot for a local branch, however, has no such mitigating flag before it and is directly exposed.

### Recommendation
Insert `--` immediately before `branch.name`/`branch.nameWithoutRemote` in `getBranchCheckoutArgs` (matching the pattern already used in `checkoutPaths` and `checkoutConflictedFile`), e.g. build args as `['--', branch.name]` or `['-b', branch.nameWithoutRemote, '--', branch.name]`, and/or validate that ref short-names cannot begin with `-` before they are used as `git` operands.

### Proof of Concept
In `checkout-test.ts`, construct a `Branch` (`BranchType.Local`) with `name = '-x'` and call `checkoutBranch`; assert the resulting args array passed to `git()` places `'-x'` before `'--'`, demonstrating it will be parsed by `git checkout` as an option rather than a ref name, contrary to the invariant. This is testable directly against `getBranchCheckoutArgs`/`checkoutBranch` in [7](#0-6)  without needing to fully trace how such a branch name could be produced by `clone`/`fetch`, which I was not able to verify within the indexed codebase.

export class Branch {
  /**
   * A branch as loaded from Git.
   *
   * @param name The short name of the branch. E.g., `main`.
   * @param upstream The remote-prefixed upstream name. E.g., `origin/main`.
   * @param tip Basic information (sha and author) of the latest commit on the branch.
   * @param type The type of branch, e.g., local or remote.
   * @param ref The canonical ref of the branch
   */
  public constructor(
    public readonly name: string,
    public readonly upstream: string | null,
    public readonly tip: IBranchTip,
    public readonly type: BranchType,
    public readonly ref: string
  ) {}

  /** The name of the upstream's remote. */
  public get upstreamRemoteName(): string | null {
    const upstream = this.upstream
    if (!upstream) {
      return null
    }

    const pieces = upstream.match(/(.*?)\/.*/)
    if (!pieces || pieces.length < 2) {
      return null
    }

    return pieces[1]
  }

  /** The name of remote for a remote branch. If local, will return null. */
  public get remoteName(): string | null {
    if (this.type === BranchType.Local) {
      return null
    }

    const pieces = this.ref.match(/^refs\/remotes\/(.*?)\/.*/)
    if (!pieces || pieces.length !== 2) {
      // This shouldn't happen, the remote ref should always be prefixed
      // with refs/remotes
      throw new Error(`Remote branch ref has unexpected format: ${this.ref}`)
    }
    return pieces[1]
  }
  /**
   * The name of the branch's upstream without the remote prefix.
   */
  public get upstreamWithoutRemote(): string | null {
    if (!this.upstream) {
      return null
    }

    return removeRemotePrefix(this.upstream)
  }

  /**
   * The name of the branch without the remote prefix. If the branch is a local
   * branch, this is the same as its `name`.
   */
  public get nameWithoutRemote(): string {
    if (this.type === BranchType.Local) {
      return this.name
    } else {
      const withoutRemote = removeRemotePrefix(this.name)
      return withoutRemote || this.name
    }
  }

async function getCheckoutOpts(
  repository: Repository,
  title: string,
  target: string,
  currentRemote: IRemote | null,
  progressCallback?: ProgressCallback,
  initialDescription?: string
): Promise<IGitStringExecutionOptions> {
  const opts: IGitStringExecutionOptions = {
    env: await envForRemoteOperation(
      getFallbackUrlForProxyResolve(repository, currentRemote)
    ),
    expectedErrors: AuthenticationErrors,
  }

  if (!progressCallback) {
    return opts
  }

  const kind = 'checkout'

  // Initial progress
  progressCallback({
    kind,
    title,
    description: initialDescription ?? title,
    value: 0,
    target,
  })

  return await executionOptionsWithProgress(
    { ...opts, trackLFSProgress: true },
    new CheckoutProgressParser(),
    progress => {
      if (progress.kind === 'progress') {
        const description = progress.details.text
        const value = progress.percent

        progressCallback({
          kind,
          title,
          description,
          value,
          target,
        })
      }
    }
  )
}

 * @param repository - The repository in which the branch checkout should

 * @param progressCallback - An optional function which will be invoked
 *                           with information about the current progress
 *                           of the checkout operation. When provided this
 *                           enables the '--progress' command line flag for
 *                           'git checkout'.

export async function checkoutBranch(
  repository: Repository,
  branch: Branch,
  currentRemote: IRemote | null,
  progressCallback?: ProgressCallback,
  allowFileProtocol: boolean = false
): Promise<true> {
  const title = `Checking out branch ${branch.name}`
  const opts = await getCheckoutOpts(
    repository,
    title,
    branch.name,
    currentRemote,
    progressCallback
      ? clampProgress(0, CheckoutStepWeight, progressCallback)
      : undefined,
    `Switching to ${__DARWIN__ ? 'Branch' : 'branch'}`
  )

  const baseArgs = getCheckoutArgs(progressCallback)
  const args = [...baseArgs, ...(await getBranchCheckoutArgs(branch))]

  await git(args, repository.path, 'checkoutBranch', opts)

// See https://www.kernel.org/pub/software/scm/git/docs/git-check-ref-format.html
// ASCII Control chars and space, DEL, ~ ^ : ? * [ \
// | " < and > is technically a valid refname but not on Windows
// the magic sequence @{, consecutive dots, leading and trailing dot, ref ending in .lock
const invalidCharacterRegex =
  /[\x00-\x20\x7F~^:?*\[\\|""<>]+|@{|\.\.+|^\.|\.$|\.lock$|\/$/g

/** Sanitize a proposed reference name by replacing illegal characters. */
export function sanitizedRefName(name: string): string {
  return name.replace(invalidCharacterRegex, '-').replace(/^[-\+]*/g, '')
}

/** Validate that a reference does not contain any invalid characters */
export function testForInvalidChars(name: string): boolean {
  return invalidCharacterRegex.test(name)
}
