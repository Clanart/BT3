### Title
Wasmd precompile `execute`/`executeBatch` skip the CW-pointer authorization check for non-delegatecall invocations - (File: precompiles/wasmd/wasmd.go)

### Summary
The `wasmd` precompile enforces that a contract acting as an intermediary in an `execute`/`execute_batch` call must be the officially registered ERC20/ERC721/ERC1155 CW pointer for the target CosmWasm contract it is executing against. In the current implementation this check is gated on `ctx.EVMPrecompileCalledFromDelegateCall()`, a strictly narrower condition than the one used in every earlier (legacy) version of the same file, which gated the check on `caller.Cmp(callingContract) != 0`. This narrowing removes the pointer-identity check for call paths that reach the precompile as a non-delegatecall, indirect invocation.

### Finding Description
The pointer-authorization guard exists to stop an arbitrary, unaudited contract from impersonating a legitimate CW20/CW721/CW1155 pointer and issuing CW execute messages against a contract it does not own/represent, while the identity used for the operation (`senderAddr`) is resolved from the EVM `caller` address's Sei association [1](#0-0) .

In the legacy code paths (`precompiles/wasmd/legacy/v552/wasmd.go`, `v555/wasmd.go`, etc.), this guard fires whenever `caller` (the immediate EVM message sender into the precompile) differs from `callingContract` (the contract context executing the call) — i.e., for any call that is not a direct EOA-to-precompile invocation: [2](#0-1) 

In the current production code, this same guard has been rewritten to only trigger when the call was specifically a delegatecall: [3](#0-2) 

The `isFromDelegateCall` flag driving `ctx.EVMPrecompileCalledFromDelegateCall()` is set purely from the opcode used to reach the precompile [4](#0-3) , and the legitimate pointer contracts (e.g. `CW20ERC20Pointer.sol`) do reach the precompile via `delegatecall`, so the intended flow still triggers the check [5](#0-4) . However, any other indirect call path that is not a delegatecall (e.g., a plain `CALL` made by an intermediary contract, which is exactly the scenario the legacy `caller != callingContract` condition was designed to also cover) now bypasses the "is not a pointer of" verification entirely, since the condition is false.

This mirrors the Budibase bug class: an authorization check that is supposed to gate access to a caller-specified resource identifier (here, the target CW contract address passed as `contractAddrStr`) is only enforced for one specific request shape (delegatecall) and silently skipped for a different, still-reachable request shape (plain call), allowing the per-resource restriction to be bypassed.

### Impact Explanation
If exploitable end-to-end, an attacker-deployed intermediary contract could reach `wasmd.execute`/`execute_batch` through a non-delegatecall path and issue arbitrary `MsgExecuteContract` calls against any CosmWasm contract identifier it supplies, without being verified as the registered pointer for that contract — undermining the pointer-authorization model the wasmd precompile relies on to keep CW20/CW721/CW1155 pointer semantics trustworthy for end users interacting through pointer contracts. Depending on downstream CW contract permission models this could enable unauthorized token operations (transfer/burn/mint messages) reachable from a public EVM transaction, which would constitute unauthorized transfer via a pointer/precompile path.

### Likelihood Explanation
Medium/uncertain. I was not able to fully trace, within the available search budget, exactly how `caller` and `callingContract` are populated by the go-ethereum interpreter for the specific case of a plain `CALL` performed by an intermediary contract that is itself invoked indirectly (vs. the top-level EOA-invoked case where `caller == callingContract`). Confirming full exploitability requires verifying the precise interpreter code path that sets these two parameters for nested `CALL` scenarios (as opposed to `DELEGATECALL`), which I could not fully load in this session. The structural regression — narrowing `caller != callingContract` to `isFromDelegateCall` only — is clearly established in the code and represents a real weakening of the access-control condition compared to every legacy version of the same file.

### Recommendation
Restore the broader condition (`caller.Cmp(callingContract) != 0`, or equivalent "this precompile invocation did not originate directly from an EOA/top-level call") in `precompiles/wasmd/wasmd.go`'s `execute` and `executeBatch` functions, in addition to (not instead of) the delegatecall-specific check, so that any intermediary-contract call path — delegatecall or plain call — is required to prove pointer registration for the target CW contract before being allowed to execute.

### Proof of Concept
Not able to construct a concrete, verified end-to-end PoC transaction within this session, because confirming the exact `caller`/`callingContract` values for a non-delegatecall, contract-mediated invocation of the wasmd precompile requires tracing the go-ethereum `EVMInterpreter`/`Call` dispatch code that is not fully covered by the current search results. This should be validated directly against `precompiles/wasmd/wasmd.go`'s `execute`/`executeBatch` and the EVM call-dispatch code that determines `caller`, `callingContract`, and `isFromDelegateCall` before treating this as confirmed-exploitable.

func (d DynamicGasPrecompile) RunAndCalculateGas(evm *vm.EVM, caller common.Address, callingContract common.Address, input []byte, suppliedGas uint64, value *big.Int, hooks *tracing.Hooks, readOnly bool, isFromDelegateCall bool) (ret []byte, remainingGas uint64, err error) {
	operation := fmt.Sprintf("%s_unknown", d.name)
	defer func() {
		HandlePrecompileError(err, evm, operation)
		if err != nil {
			fmt.Printf("precompile %s encountered error: %v\n", d.name, err)
			err = vm.ErrExecutionReverted
		}
	}()
	ctxer := state.GetDBImpl(evm.StateDB)
	if ctxer == nil {
		return nil, 0, errors.New("cannot get context from EVM")
	}
	// Resolve the target method from the 4-byte selector only. The argument
	// payload is intentionally NOT decoded yet: ABI decoding of attacker-
	// controlled calldata can cost far more than len(input) (a single string can
	// be referenced by many array/tuple slots), so it must be paid for out of the
	// gas the caller supplied. The static-precompile path charges RequiredGas in
	// vm.RunPrecompiledContract before running; that step is skipped for
	// dynamic-gas precompiles, so we apply the equivalent charge here.
	methodID, err := ExtractMethodID(input)
	if err != nil {
		return nil, 0, err
	}
	method, err := d.MethodById(methodID)
	if err != nil {
		return nil, 0, err
	}
	operation = method.Name

	ctx := ctxer.Ctx()
	// Install the gas meter derived from the supplied EVM gas, then charge for
	// decoding the calldata BEFORE decoding it. A call that cannot afford the
	// decode is rejected here, before the parse/allocation work is performed.
	// chargeDecodeGas scopes the out-of-gas recovery to just these charges, so an
	// executor that later exhausts its gas keeps its normal (propagating)
	// out-of-gas semantics.
	gasLimit := d.executor.EVMKeeper().GetCosmosGasLimitFromEVMGas(ctx.WithGasMeter(sdk.NewInfiniteGasMeterWithMultiplier(ctx)), suppliedGas)
	ctx = ctx.WithGasMeter(sdk.NewGasMeterWithMultiplier(ctx, gasLimit))
	if err = d.chargeDecodeGas(ctx, method, input); err != nil {
		return nil, 0, err
	}

	args, err := method.Inputs.Unpack(input[4:])
	if err != nil {
		return nil, 0, err
	}
	em := ctx.EventManager()
	ctx = ctx.WithEventManager(sdk.NewEventManager())
	ctx = ctx.WithEVMPrecompileCalledFromDelegateCall(isFromDelegateCall)
	ret, remainingGas, err = d.executor.Execute(ctx, method, caller, callingContract, args, value, readOnly, evm, suppliedGas, hooks)
	if err != nil {
		return ret, remainingGas, err
	}
	events := ctx.EventManager().Events()
	if len(events) > 0 {
		em.EmitEvents(ctx.EventManager().Events())
	}
	return ret, remainingGas, err
}
