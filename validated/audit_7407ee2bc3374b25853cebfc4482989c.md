## Analog Found: Loose Substring-Based Host Check in `isGitHubHost`

### Title
Insufficient GitHub Host Validation via Substring Regex Enables Attacker-Controlled Remote to Be Misclassified as a Trusted GitHub Enterprise Endpoint - (File: `app/src/lib/api.ts`)

### Summary
The external report's broken invariant is: *a security decision is made by checking whether an attacker-controlled string merely contains an allowed substring/host, instead of strictly comparing the parsed URL host*. The same pattern exists in GitHub Desktop's `isGitHubHost()` function, which is used by the git credential-helper trampoline to decide whether an arbitrary git remote should be treated as a trusted GitHub/GitHub Enterprise host.

### Finding Description
`isGitHubHost` performs a best-effort check to classify a hostname as GitHub-owned: [1](#0-0) 

The relevant line is:
```js
// github.example.com,
if (/(^|\.)(github)\./.test(hostname)) {
  return true
}
```
This regex only requires the literal label `github` to appear as a hostname component preceded by either the start of the string or a dot, and followed by a dot. Any attacker who registers a domain and creates a subdomain literally named `github` — e.g. `github.attacker-evil.com` — satisfies `(^|\.)(github)\.` trivially (it matches at position 0: `github.attacker-evil.com`), causing `isGitHubHost()` to return `true` for a completely attacker-owned host. This mirrors the QR report's flaw exactly: a "contains-the-magic-token" check standing in for a real host/origin comparison, bypassable by simply embedding the token as a labeled component of an attacker-chosen domain.

This function feeds directly into `getEndpointKind()` in the trampoline credential helper, which is invoked by Desktop's embedded git credential helper for every git remote operation (clone/fetch/push): [2](#0-1) 

When the protocol is HTTPS and no existing account/`WWW-Authenticate` realm hint is available, `isGitHubHost(endpoint)` is the deciding check, and returning `true` makes Desktop treat the remote as `'enterprise'`:

```js
return (await isGitHubHost(endpoint)) ? 'enterprise' : 'generic'
```

That classification changes downstream behavior in `getCredential`: [3](#0-2) 

Because `endpointKind !== 'generic'` and no account exists for the attacker's endpoint, Desktop calls `ui.promptForGitHubSignIn(endpoint)` — the real "Sign in to GitHub Enterprise" OAuth flow — for a host the user has no reason to trust is GitHub-owned, instead of falling back to the generic credential store/prompt path that a non-GitHub remote should get.

### Impact Explanation
An attacker who controls a git remote (e.g. via a malicious clone URL, a forked/replaced remote, or a proxy) hosted at a domain such as `github.<attacker-domain>` can force GitHub Desktop to:
- Misclassify the remote as `'enterprise'` instead of `'generic'`, bypassing the intended generic-credential-helper path (`setGenericCredential`/`getGenericCredential`).
- Trigger Desktop's native "Sign in to GitHub Enterprise" OAuth UI (`promptForGitHubSignIn` → `beginEnterpriseSignIn`/`setSignInEndpoint`) against an attacker-controlled endpoint, lending the attacker's domain false legitimacy inside Desktop's own trusted-looking authentication flow.

Note: `findGitHubTrampolineAccount` in `app/src/lib/trampoline/find-account.ts` performs a strict origin equality check when looking up *existing* stored accounts, so already-signed-in GitHub/GHE tokens are not leaked to the attacker host through this specific path — that guard limits the blast radius to UI-trust spoofing / phishing-flow triggering rather than direct token exfiltration.

### Likelihood Explanation
High reachability, low attacker cost: registering a subdomain literally named `github` under any domain the attacker owns is trivial, and the check is reached automatically any time Desktop's git credential helper processes a remote with an HTTPS URL that isn't already recognized as `github.com`/`*.ghe.com` or a known third-party host (`isKnownThirdPartyHost`) — i.e., on ordinary clone/fetch/push against a crafted remote.

### Recommendation
Replace the substring regex with strict, anchored hostname comparison, e.g. requiring the hostname to equal `github.<enterprise-domain>` as a full label match against a known/allow-listed enterprise domain, or better, remove the heuristic regex entirely and rely solely on the authoritative signals already present in the function (`isDotCom`, `isGHE`, existing account match, `WWW-Authenticate: realm="GitHub"`, or the `/meta` endpoint probe with `x-github-request-id`), mirroring the QR scanner fix's approach of parsing the URL and doing an exact host comparison rather than a substring/contains check.

### Proof of Concept
1. Attacker sets up an HTTPS git server at `https://github.attacker-evil.com/some/repo.git` (or any domain where a subdomain component is exactly `github`).
2. Victim adds/clones this remote in GitHub Desktop.
3. During the credential-helper flow, `getEndpointKind` calls `isGitHubHost('https://github.attacker-evil.com')`.
4. `hostname = 'github.attacker-evil.com'` matches `/(^|\.)(github)\./` at the start of the string, so `isGitHubHost` returns `true`.
5. `getEndpointKind` returns `'enterprise'` instead of `'generic'`.
6. Since no account matches this endpoint, `getCredential` calls `ui.promptForGitHubSignIn('https://github.attacker-evil.com')`, surfacing Desktop's native GitHub Enterprise sign-in dialog for the attacker's domain. [4](#0-3) [5](#0-4) [6](#0-5)

```typescript
/**
 * Attempts to determine whether or not the url belongs to a GitHub host.
 *
 * This is a best-effort attempt and may return `undefined` if encountering
 * an error making the discovery request
 */
export async function isGitHubHost(url: string) {
  const { hostname } = new window.URL(url)

  const endpoint =
    hostname === 'github.com' || hostname === 'api.github.com'
      ? getDotComAPIEndpoint()
      : getEnterpriseAPIURL(url)

  if (isDotCom(endpoint) || isGHE(endpoint)) {
    return true
  }

  if (isKnownThirdPartyHost(hostname)) {
    return false
  }

  // github.example.com,
  if (/(^|\.)(github)\./.test(hostname)) {
    return true
  }
```

```typescript
/** Implementation of the 'get' git credential helper command */
async function getCredential(cred: Credential, store: Store, token: string) {
  const ghCred = await getGitHubCredential(cred, store)

  if (ghCred) {
    return ghCred
  }

  const endpointKind = await getEndpointKind(cred, store)
  const accounts = await store.getAll()

  const endpoint = `${getCredentialUrl(cred)}`
  const apiEndpoint = getAPIEndpoint(endpoint)

  // If it appears as if the endpoint is a GitHub host and we don't have an
  // account for that endpoint then we should prompt the user to sign in.
  if (
    endpointKind !== 'generic' &&
    !accounts.some(a => a.endpoint === apiEndpoint)
  ) {
    if (getIsBackgroundTaskEnvironment(token)) {
      debug('background task environment, skipping prompt')
      return undefined
    }

    const account = await ui.promptForGitHubSignIn(endpoint)

    if (!account) {
      setHasRejectedCredentialsForEndpoint(token, endpoint)
    }

    return credWithAccount(cred, account)
  }

  // GitHub.com/GHE creds are only stored internally
  if (endpointKind !== 'generic') {
    return undefined
  }
```

```typescript
const getEndpointKind = async (cred: Credential, store: Store) => {
  const credentialUrl = getCredentialUrl(cred)
  const endpoint = `${credentialUrl}`

  if (isGist(endpoint)) {
    return 'generic'
  }

  if (isDotCom(endpoint)) {
    return 'github.com'
  }

  if (isGHE(endpoint)) {
    return 'ghe.com'
  }

  // When Git attempts to authenticate with a host it captures any
  // WWW-Authenticate headers and forwards them to the credential helper. We
  // use them as a happy-path to determine if the host is a GitHub host without
  // having to resort to making a request ourselves.
  for (const [k, v] of cred.entries()) {
    if (k.startsWith('wwwauth[')) {
      if (v.includes('realm="GitHub"')) {
        return 'enterprise'
      } else if (/realm="(GitLab|Gitea|Atlassian Bitbucket)"/.test(v)) {
        return 'generic'
      }
    }
  }

  const existingAccount = await findGitHubTrampolineAccount(store, endpoint)
  if (existingAccount) {
    return isDotCom(existingAccount.endpoint) ? 'github.com' : 'enterprise'
  }

  // All GitHub hosts use HTTPS, so if the protocol is not HTTPS we can
  // assume that this is not a GitHub host.
  if (credentialUrl.protocol !== 'https:') {
    return 'generic'
  }

  return (await isGitHubHost(endpoint)) ? 'enterprise' : 'generic'
}
```
