## Analysis

**Core broken invariant from the report:** a value with unbounded/large range is silently mapped into a fixed-capacity namespace (100 versions per 1,000,000-slot collection) with no check that the mapping stays inside the entity it's meant to represent, so distinct logical entities collide/alias into the same slot.

**Local analog:** `pallet-bandwidth` derives its per-app storage key by *truncating* an attacker-supplied, variable-length byte string down to a fixed 32-byte `AppKey`, with no check that the caller-supplied identifier is actually ≤32 bytes or otherwise bound to a specific app. Two different `app` byte-strings that share the same first 32 bytes collapse to the identical storage key — exactly the "distinct entities aliasing into one bucket" failure mode from the report.

### Title
Unvalidated truncation of purchaser-supplied `app` bytes lets an attacker alias into another app's bandwidth ledger - (File: `modules/pallets/bandwidth/src/lib.rs`)

### Summary
`AppKey` is a `BoundedVec<u8, ConstU32<32>>` [1](#0-0)  and the pallet derives it from the purchase message's `app` field via `AppKey::truncate_from(msg.app)` with no upstream check that `msg.app` is exactly (or at most) 32 bytes long [2](#0-1) . `msg.app` originates from the ABI-decoded `PurchaseMessage` sent by a permissionless caller of `BandwidthManager.purchase()` on the source chain, and `truncate_from` silently drops any bytes past index 32 instead of rejecting oversized input.

### Finding Description
`Allowance` storage is keyed by `(app_chain: StateMachine, app: AppKey)` [3](#0-2) . The only place `AppKey` is constructed from attacker-controlled data is `on_accept`, where `msg.app` (an arbitrary-length byte string decoded from the purchase body) is truncated to 32 bytes without a length assertion:

```rust
let key = AppKey::truncate_from(msg.app);
let expires_at = Self::push_subscription(&msg.chain, &key, tier, bytes, duration);
``` [2](#0-1) 

Because `truncate_from` keeps only the first 32 bytes, any two `app` byte-strings that agree on their first 32 bytes but differ afterward (`victimApp32Bytes ++ garbage` vs. `victimApp32Bytes`) resolve to the exact same `AppKey`, hence the exact same `Allowance::<T>` row and the exact same 1024-entry FIFO list [4](#0-3) .

`purchase()` on `BandwidthManager.sol` is a public, permissionless entrypoint (any account can call it after paying the tier price) — the pallet only checks that `request.from` matches the registered manager contract, never that `msg.app` belongs to the caller [5](#0-4) . There is no ownership or provenance check tying `app` to `msg.sender`; it is a free-form payload field, so an attacker can pick any `app` value, including one crafted to collide with a legitimate app's 32-byte key once truncated.

`push_subscription` evicts the **oldest** entry once the target `(chain, app)` list is at the 1024 cap, emitting `SubscriptionEvicted` [6](#0-5) . An attacker who repeatedly buys the cheapest tier using a crafted `app` that collides with a target's `AppKey` can force-push entries onto the victim's list, evicting the victim's real, already-paid-for subscriptions before their natural expiry — the eviction event correctly reports the loss but does nothing to prevent it.

### Impact Explanation
This is a loss of a paid-for on-chain resource (bandwidth allowance) belonging to a legitimate app, caused entirely by an unprivileged third party abusing a public purchase entrypoint. The victim app paid real fee-token value for bandwidth that becomes unusable early because of unrelated attacker purchases sharing a truncation-colliding identifier. It also breaks the intended `(chain, app)` isolation the ledger design relies on ("Keyed by `app_chain`... so a payer chain can sponsor an app that lives elsewhere" [7](#0-6) ) — the isolation guarantee silently fails whenever two `app` identifiers share a 32-byte prefix.

### Likelihood Explanation
High: `purchase()` is intentionally open to any caller, the attacker only needs to know (or guess/observe on-chain) a victim's `AppKey` bytes and append arbitrary trailing bytes to the app field before submitting a normal purchase — no relayer, prover, or privileged role is required, and the ABI-encoded `app` field imposes no length limit before it reaches `AppKey::truncate_from`.

### Recommendation
Reject purchase messages where `msg.app.len() > 32` instead of silently truncating (return `Error::InvalidPurchaseBody`), and/or require the manager contract to normalize/validate `app` to a fixed, unambiguous encoding (e.g., always exactly 32 bytes, left- or right-padded per a documented convention) before dispatch, so no two distinct logical apps can ever be represented by colliding byte strings.

### Proof of Concept
1. Identify a victim app's registered 32-byte `AppKey` (e.g., its EVM address right-padded to 32 bytes), call it `V`.
2. From any account, call `BandwidthManager.purchase()` on the source chain with `app = V || <arbitrary extra bytes>` and the cheapest tier/month.
3. The dispatched `PurchaseMessage.app` decodes to `V || extra`; `pallet-bandwidth::on_accept` computes `AppKey::truncate_from(msg.app) == V`, identical to the victim's real key.
4. Repeat the purchase until the victim's `Allowance::<T>::get(app_chain, V)` list reaches 1024 entries; each further attacker purchase evicts the oldest (potentially the victim's genuine, still-unexpired) subscription via `push_subscription`, emitting `SubscriptionEvicted` for bytes the victim actually paid for and expected to still have available.

		fn push_subscription(
			app_chain: &StateMachine,
			app: &AppKey,
			tier: TierIndex,
			bytes: BandwidthBytes,
			duration_secs: u64,
		) -> u64 {
			let now = <T as pallet_ismp::Config>::TimestampProvider::now().as_secs();
			let expires_at = now.saturating_add(duration_secs);
			let new_sub =
				Subscription { tier, remaining_bytes: bytes, expires_at, purchased_at: now };

			let evicted = Allowance::<T>::mutate(app_chain, app, |list| {
				let evicted = if list.len() == MAX_SUBSCRIPTIONS as usize {
					Some(list.remove(0))
				} else {
					None
				};
				// Capacity is now guaranteed; try_push can't fail.
				let _ = list.try_push(new_sub);
				evicted
			});

			if let Some(old) = evicted {
				Self::deposit_event(Event::SubscriptionEvicted {
					app_chain: *app_chain,
					app: app.clone(),
					tier: old.tier,
					lost_bytes: old.remaining_bytes,
				});
			}

			expires_at
		}
