The reported issue is specific to the Magnetar Solidity contract's `burst()` function, which loops over sub-`_action` calls, allows per-action `allowFailure`, and accumulates `msg.value` in the contract's persistent ETH balance — leftover ETH can sit in the contract after a failed action and be swept by any caller.

Chia's execution model has no analogous persistent-balance/partial-failure pattern to map this onto: coin spends inside a spend bundle are atomic at the block-validation level — either the entire bundle (all coin spends) succeeds and is committed, or it is rejected entirely; there is no "continue to next sub-action, leaving unclaimed value in a shared contract balance" semantics like a Solidity `.call{value}()` loop with `allowFailure`. Value conservation is enforced globally per spend bundle via CLVM condition processing (`CREATE_COIN` outputs must be assigned explicitly out of consumed coins), so there's no mechanism for "leftover" value to accumulate in a stateful contract account that a later, unrelated party could then spend, as seen in mempool/batch processing [1](#0-0)  and clawback batch spending [2](#0-1) , both of which fully account for spends without any partial/no-op ETH-like leftover state.
