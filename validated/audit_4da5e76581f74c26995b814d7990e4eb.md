## Analysis

The report's core "broken invariant" is: **an attacker-controlled string is passed unchecked into a sensitive operation (a swap) instead of being validated against a trust boundary (an oracle price).** The closest analog in GitHub Desktop's local codebase is not slippage — it's the equivalent broken invariant for a Git client: **a URL originating from a clicked deep link is passed unchecked into `git clone`, and Git itself will happily execute the `ext::` "protocol" as an arbitrary local command instead of treating it as an untrusted network location.**

### Title
Remote Code Execution via unrestricted `ext::` transport in deep-link-triggered `git clone` - (File: `app/src/lib/git/clone.ts`)

### Summary
GitHub Desktop registers a custom URL protocol (`x-github-client://`, `github-mac://`, etc.) that any web page or message can invoke. `parseAppURL` extracts the `openrepo` path segment verbatim as a "remote repository location" and forwards it, unsanitized with respect to *scheme*, all the way to `git clone`. Git's `ext::` transport treats the remainder of the URL as a shell command to execute, and Desktop never restricts allowed protocols (no `GIT_ALLOW_PROTOCOL`, no `protocol.*.allow` denylist) before invoking `clone()`.

### Finding Description
`parseAppURL` builds an `open-repository-from-url` action directly from the URL path component, validating only the `branch`/`pr` query parameters for illegal ref characters — it does **not** validate that `url` looks like an `https://`/`ssh://`/`git://` remote: [1](#0-0) 

This action is routed to `openRepositoryFromUrl` → `openOrCloneRepository`, which, when no existing local repository matches, opens the Clone dialog pre-filled with the attacker-supplied `url`: [2](#0-1) 

When the user clicks "Clone" in that pre-filled dialog, `cloneImpl` calls `dispatcher.clone(url, path, ...)`: [3](#0-2) 

That eventually reaches `clone()` in `app/src/lib/git/clone.ts`, which only validates that the **destination path** isn't a "sensitive location" (`isClonePathSensitive`) — there is no check whatsoever on the **source URL's scheme**: [4](#0-3) [5](#0-4) 

Git's `ext::` remote helper (and `fd::`) is a documented Git feature that runs an arbitrary shell command in place of contacting a remote (e.g. `ext::sh -c "touch /tmp/pwned"`). Since Git 2.11, protocols like `ext`, `file`, `ssh`, etc. are governed by `protocol.<name>.allow`, whose default is `user` — meaning they **are allowed for user-initiated, top-level invocations** like the one Desktop performs here (`git clone -- <url> <path>`), and are only blocked for *recursive* fetches (e.g. submodules) unless explicitly permitted. Desktop's `envForRemoteOperation`/`clone()` never sets `GIT_ALLOW_PROTOCOL` or `-c protocol.ext.allow=never` to close this off, confirmed by the absence of any such configuration anywhere in the codebase.

The `--` separator used in `clone.ts` (`args.push('--', url, path)`) protects against **flag injection** (a URL starting with `-`), but it does nothing to stop Git from interpreting the `ext::` scheme, because that interpretation happens inside Git's transport layer, not the option parser.

### Impact Explanation
An attacker who gets a victim to click a single link (e.g. embedded in a webpage, email, or GitHub-hosted content that renders as a clickable `x-github-client://openrepo/ext::...` URI) can achieve **arbitrary command execution** on the victim's machine with the privileges of the Desktop process, once the victim confirms the pre-filled Clone dialog. This is full RCE — the strongest possible impact for an unprivileged, remote link-click primitive, matching the "link/deep link" and "code execution" criteria in the Valid Impact list.

### Likelihood Explanation
Likelihood is high once discovered: the protocol handler is registered automatically on every Desktop install (`setAsDefaultProtocolClient`), requires only a single click plus one dialog confirmation (an expected, in-product action, not an "unnatural" step, since "Open in Desktop" links are meant to pre-fill and clone), and no part of the pipeline (`parseAppURL`, `openOrCloneRepository`, `clone.ts`) inspects the URL scheme. The only mitigating factor is that the victim must click "Clone" in the pre-filled dialog, which is normal UX for this feature rather than an unusual step.

### Recommendation
Before calling `clone()`/`git` with an externally-supplied URL (from `parseAppURL`, CLI `--cli-clone`, or any deep link), enforce an allowlist of accepted schemes (`https:`, `http:`, `ssh:`, `git:`) and reject everything else (`ext::`, `fd::`, `file://` unless explicitly intended, etc.), mirroring what `parseRemote`/`remote-parsing.ts` already does for well-formed GitHub remotes. Additionally, set `GIT_ALLOW_PROTOCOL=http:https:ssh:git` (or `-c protocol.ext.allow=never -c protocol.fd.allow=never`) in `envForRemoteOperation` for all clone/fetch/push invocations as defense in depth.

### Proof of Concept
1. Register/observe that Desktop is the default handler for `x-github-client://`.
2. Craft a link such as:
   `x-github-client://openrepo/ext::sh%20-c%20"touch%20/tmp/pwned"`
3. Host this link on a web page or send it via any message; victim clicks it.
4. `parseAppURL` parses `open-repository-from-url` with `url = "ext::sh -c \"touch /tmp/pwned\""`, unchanged by any validation. [6](#0-5) 
5. Desktop opens the Clone dialog pre-filled with this "URL"; victim clicks "Clone".
6. `clone()` executes `git ... clone --recursive -- "ext::sh -c \"touch /tmp/pwned\"" <path>`, and Git's `ext::` transport runs the embedded shell command, achieving code execution. [7](#0-6) 

**Confidence note:** I could not execute Desktop live to confirm exact URL-encoding/parsing edge cases for the `ext::` payload through Node's `URL.parse`, nor confirm the exact default `protocol.*.allow` behavior for the specific bundled Git version pinned by `dugite` in this build. These would need to be validated in a live Desktop session (recommend a Devin session with sandbox access to reproduce end-to-end) before treating this as a fully confirmed exploit rather than a strong code-level analog.

/**
 * Check whether a resolved clone path targets a sensitive location that
 * should never be used as a clone destination. This is a backstop against
 * path traversal attacks where a crafted URL tricks the UI into deriving
 * a clone path outside the intended base directory.
 */
function isClonePathSensitive(unresolvedClonePath: string): boolean {
  const clonePath = Path.resolve(unresolvedClonePath).toLowerCase()
  const home = Path.resolve(homedir()).toLowerCase()

  if (clonePath === home) {
    return true
  }

  const sensitiveLocations = [
    Path.join(home, '.ssh'),
    Path.join(home, '.gnupg'),
    Path.join(home, '.config'),
    Path.join(home, '.config', 'git'),
    Path.join(home, '.gitconfig'),
  ]

  if (__WIN32__) {
    const appData = process.env.APPDATA
    if (appData) {
      sensitiveLocations.push(appData.toLowerCase())
      sensitiveLocations.push(Path.join(appData, 'gnupg').toLowerCase())
    }
  }

  for (const sensitive of sensitiveLocations) {
    if (clonePath === sensitive || clonePath.startsWith(sensitive + Path.sep)) {
      return true
    }
  }

  return false
}

export async function clone(
  url: string,
  path: string,
  options: CloneOptions,
  progressCallback?: (progress: ICloneProgress) => void
): Promise<void> {
  if (isClonePathSensitive(path)) {
    throw new Error(
      `The clone destination "${path}" targets a sensitive system location. ` +
        'Cloning into this directory is not allowed.'
    )
  }

  const env = {
    ...(await envForRemoteOperation(url)),
    GIT_CLONE_PROTECTION_ACTIVE: 'false',
  }

  const defaultBranch = options.defaultBranch ?? (await getDefaultBranch())

  const args = [
    '-c',
    `init.defaultBranch=${defaultBranch}`,
    'clone',
    '--recursive',
  ]

  let opts: IGitStringExecutionOptions = { env }

  if (progressCallback) {
    args.push('--progress')

    const title = `Cloning into ${path}`
    const kind = 'clone'

    opts = await executionOptionsWithProgress(
      { ...opts, trackLFSProgress: true },
      new CloneProgressParser(),
      progress => {
        const description =
          progress.kind === 'progress' ? progress.details.text : progress.text
        const value = progress.percent

        progressCallback({ kind, title, description, value })
      }
    )

    // Initial progress
    progressCallback({ kind, title, value: 0 })
  }

  if (options.branch) {
    args.push('-b', options.branch)
  }

  args.push('--', url, path)

  await git(args, __dirname, 'clone', opts)
}
