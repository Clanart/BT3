### Title
Unbounded, ungated per-authority signature recovery loop over EIP-7702 `AuthList` in the EVM ante pipeline runs under an infinite gas meter - ([File: x/evm/ante/preprocess.go], [File: app/ante/evm_checktx.go], [File: app/ante/evm_delivertx.go])

### Summary
The CVE describes a class of bug where an API is invoked in an unbounded loop with no cost accounting, leading to severe hangs/crashes. Sei-chain's EIP-7702 (`SetCodeTx`) ante-handling reproduces this pattern: every authorization entry in a transaction's `AuthList` is iterated and cryptographically verified (ECDSA recovery + Keccak256 + RLP encoding) plus state-read/write work, while the surrounding context uses an **infinite gas meter**, so none of this work is metered or charged.

### Finding Description
In the standard EVM ante path, `EVMPreprocessDecorator.AnteHandle` first swaps in an infinite gas meter and then walks every authorization in the tx's `AuthList`: [1](#0-0) [2](#0-1) 

Each iteration calls `helpers.AuthorityToPreAssociate`, which performs a full ECDSA signature recovery (`RecoverAddressesFromAuthorization` — RLP-encode, Keccak256, and public-key recovery) plus multiple keeper state reads, and, if it passes, opens a `ctx.CacheContext()` and performs a full `AssociateAddresses` (balance-migration) write: [3](#0-2) [4](#0-3) 

The legacyabci counterpart (`AssociateAuthorizationAuthorities`) does the identical unbounded loop and is invoked from **both** `EvmCheckTxAnte` (mempool admission, run by every node on every gossiped transaction) and `EvmDeliverTxAnte` (block execution), again under an infinite gas meter: [5](#0-4) [6](#0-5) [7](#0-6) 

Because the loop runs before the EVM's own per-authorization gas accounting (which only happens later, inside state-transition execution) and while the Cosmos SDK gas meter is infinite, an attacker can craft a single `SetCodeTx` carrying a large `AuthList` (bounded only by the maximum transaction/mempool byte size, not by any explicit `AuthList` length check I could find in this codebase) and force every node's `CheckTx` and `DeliverTx` ante processing to perform hundreds of expensive ECDSA recoveries and KV read/write cycles per transaction, entirely free of gas cost. I was unable to locate any explicit cap on `AuthList` length in stateless validation (`EvmStatelessChecks`) within the indexed code, so the only limiting factor appears to be the generic tx-size/mempool byte limit, not a bound tailored to this loop's cost.

### Impact Explanation
Since `EvmCheckTxAnte` runs this loop on **every node that receives the transaction via gossip**, not just the proposer, an attacker submitting (and re-submitting with bumped nonce/fee) such transactions can impose disproportionate CPU cost across the network for negligible gas expenditure, with no corresponding fee charged for the recovery work performed before the tx is even accepted into a block. In the worst case this degrades CheckTx/DeliverTx throughput broadly, which can translate into block-processing delays; this maps to the "block delay" impact category, though I could not confirm from the available code an unbounded (not merely large but bounded-by-block-gas) worst case, since block-level DeliverTx work is still ultimately capped by the tx's own EVM gas limit for the rest of execution — only this specific pre-association loop escapes metering.

### Likelihood Explanation
Reachable by any unprivileged public RPC client: constructing a `SetCodeTx` with many authorization entries requires only valid signatures the attacker generates themselves (authorities need not be real accounts with meaningful state — `AuthorityToPreAssociate` performs the recovery and several checks before rejecting invalid ones), and submitting it via the standard EVM JSON-RPC transaction submission path. No privileged access or special configuration is needed.

### Recommendation
Charge Cosmos SDK gas (or an explicit CPU/complexity limit) for each `AuthList` entry processed in `associateAuthorizationAuthorities`/`AssociateAuthorizationAuthorities` before performing the ECDSA recovery, or cap the maximum number of authorizations processed during ante pre-association independent of the generic tx-size limit, so a single transaction cannot impose unbounded ante-time cryptographic and I/O cost on receiving nodes.

### Proof of Concept
Conceptual PoC (based on code reachability, not independently executed): craft an EIP-7702 `SetCodeTx` whose `AuthList` contains the maximum number of authorization entries permitted by the mempool's raw tx-size limit (each entry ~100+ bytes), sign it, and submit it repeatedly via the public EVM JSON-RPC endpoint (`eth_sendRawTransaction`). Because `EvmCheckTxAnte`/`EvmDeliverTxAnte` (and the giga/V2 `EVMPreprocessDecorator` path) iterate the full `AuthList` under an infinite gas meter before any of the recovery cost is charged, each node's CheckTx handling of this single transaction performs hundreds of full ECDSA recoveries and state reads that are otherwise gas-free — repeatable at negligible cost to the attacker (or free if the tx is invalid/dropped after CheckTx, since the fee is never charged in that case).

func (p *EVMPreprocessDecorator) associateAuthorizationAuthorities(ctx sdk.Context, msg *evmtypes.MsgEVMTransaction, associateHelper *helpers.AssociationHelper) {
	txData, err := evmtypes.UnpackTxData(msg.Data)
	if err != nil {
		return
	}
	setCodeTx, ok := txData.(*ethtx.SetCodeTx)
	if !ok {
		// Only SetCode (EIP-7702) transactions carry authorizations.
		return
	}
	ethTx := ethtypes.NewTx(setCodeTx.AsEthereumData())
	for _, auth := range ethTx.SetCodeAuthorizations() {
		// Only pre-associate authorities whose authorization the EVM will actually apply
		// (matching chain id, nonce, and account state). This prevents replaying a
		// publicly-visible authorization a user signed for another chain to force-associate
		// them, which the EVM would skip but which still recovers a valid authority.
		evmAddr, seiAddr, pubkey, ok := helpers.AuthorityToPreAssociate(ctx, p.evmKeeper, auth)
		if !ok {
			continue
		}
		cacheCtx, write := ctx.CacheContext()
		if err := associateHelper.AssociateAddresses(cacheCtx, seiAddr, evmAddr, pubkey, false); err == nil {
			write()
		}
	}

func RecoverAddressesFromAuthorization(auth ethtypes.SetCodeAuthorization) (common.Address, sdk.AccAddress, cryptotypes.PubKey, error) {
	var buf bytes.Buffer
	buf.WriteByte(eip7702MagicPrefix)
	if err := rlp.Encode(&buf, []any{auth.ChainID, auth.Address, auth.Nonce}); err != nil {
		return common.Address{}, sdk.AccAddress{}, nil, err
	}
	sigHash := crypto.Keccak256Hash(buf.Bytes())
	v := new(big.Int).SetUint64(uint64(auth.V) + 27)
	return GetAddresses(v, auth.R.ToBig(), auth.S.ToBig(), sigHash)

func AuthorityToPreAssociate(ctx sdk.Context, k AuthorizationStateReader, auth ethtypes.SetCodeAuthorization) (common.Address, sdk.AccAddress, cryptotypes.PubKey, bool) {
	// Chain ID must be null or match the local chain.
	if !auth.ChainID.IsZero() && auth.ChainID.CmpBig(k.ChainID(ctx)) != 0 {
		return common.Address{}, nil, nil, false
	}
	// Nonce must not overflow (EIP-2681).
	if auth.Nonce+1 < auth.Nonce {
		return common.Address{}, nil, nil, false
	}
	evmAddr, seiAddr, pubkey, err := RecoverAddressesFromAuthorization(auth)
	if err != nil {
		return common.Address{}, nil, nil, false
	}
	// Cross-check against go-ethereum's authoritative recovery so we only ever act on the
	// exact address SetCode would target during execution.
	if authAddr, aerr := auth.Authority(); aerr != nil || authAddr != evmAddr {
		return common.Address{}, nil, nil, false
	}
	// Authority must have no code, or only an existing delegation designator.
	if code := k.GetCode(ctx, evmAddr); len(code) != 0 {
		if _, ok := ethtypes.ParseDelegation(code); !ok {
			return common.Address{}, nil, nil, false
		}
	}
	// Authority account nonce must match the authorization nonce.
	if k.GetNonce(ctx, evmAddr) != auth.Nonce {
		return common.Address{}, nil, nil, false
	}
	// Already-associated authorities need no pre-association (and cannot be re-mapped).
	if _, associated := k.GetEVMAddress(ctx, seiAddr); associated {
		return common.Address{}, nil, nil, false
	}
	return evmAddr, seiAddr, pubkey, true

func AssociateAuthorizationAuthorities(ctx sdk.Context, ek *evmkeeper.Keeper, etx *ethtypes.Transaction) {
	auths := etx.SetCodeAuthorizations()
	if len(auths) == 0 {
		return
	}

			continue
		}
		cacheCtx, write := ctx.CacheContext()
		if err := associateHelper.AssociateAddresses(cacheCtx, seiAddr, evmAddr, pubkey, false); err == nil {
			write()
		}
	}
