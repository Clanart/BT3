### Title
Unbounded, unmetered `ProgramCache` iteration over all-time deployed programs enables cheap chain-wide compute-time DoS - ([File: program-runtime/src/loaded_programs.rs])

### Summary
The global `ProgramCache::index` (`IndexImplementation::V1 { entries: HashMap<Pubkey, Vec<Arc<ProgramCacheEntry>>>, .. }`) keeps one top-level `HashMap` entry per every distinct program `Pubkey` that has ever been deployed on the chain. Routines that run on essentially every slot/rerooting — `ProgramCache::prune` (`runtime/src/bank.rs` `prune_program_cache`, called from bank freezing/rerooting) and `remove_programs_with_no_entries` — iterate over the *entire* `entries` map every time, with cost proportional to the total number of distinct program keys ever inserted, not to anything the current transaction batch touched. ### Finding Description
Deploying a BPF Loader v3 (`bpf_loader_upgradeable`) program is an unprivileged, permissionless action that only costs the rent-exempt balance for the program/programdata accounts plus normal transaction fees — a fixed, one-time, per-deployment cost that does not scale with the *global* number of distinct programs that have ever existed on the chain.

Once deployed (even if later closed), the program's `Pubkey` remains as a top-level key in `ProgramCache`'s `entries: HashMap<Pubkey, Vec<Arc<ProgramCacheEntry>>>` (see `IndexImplementation::V1`). Nothing removes a key unless its `second_level` vector becomes fully empty via `remove_programs_with_no_entries`, and that pruning is itself just another full-map scan: [3](#0-2) 

`ProgramCache::prune` is invoked from `Bank::prune_program_cache`, which is wired into the bank freezing / rerooting path that runs on essentially every processed block, independent of which programs that specific block's transactions actually referenced: [4](#0-3) 

`prune` walks `entries.values_mut()` — i.e., every distinct program `Pubkey` ever recorded, across the whole map — doing per-entry `fork_graph.relationship(...)` lookups, filter/collect/reverse work per second-level vector, and (when a new environment is supplied for an epoch boundary) an additional environment-matching pass over every version of every program: [5](#0-4) 

This is structurally identical to the reported bug class: a small, fixed, permissionless cost (rewards-plan creation fee / program deployment rent) lets an attacker permanently inflate a persistent, validator-global collection, and *every future* execution of an unrelated, unmetered maintenance routine (`BeginBlocker` iterating rewards plans / `prune` iterating `ProgramCache::entries`) pays for that inflation — with no compute-unit charge attributed to the attacker at the time the maintenance work executes. The number of loaded/verified/JIT-compiled `Loaded` executables is bounded by `sort_and_unload`/`evict_using_random_selection` (which target a percentage of `MAX_LOADED_ENTRIES_COUNT`-style caps and only iterate the flattened, currently-loaded set), but the outer `entries` `HashMap` key-space itself is not capped and is exactly what `prune`/`remove_programs_with_no_entries` walk in full on (near-)every slot.

### Impact Explanation
Because `prune` runs off the critical path of normal per-transaction compute metering (there is no `ComputeMeter` involved in bank-freeze/rerooting bookkeeping), its cost is entirely unpriced from the perspective of the attacker who caused the map to grow. An attacker who deploys a very large number of distinct, minimal programs (each only paying the rent-exempt minimum for a near-empty ELF, which is comparatively cheap) permanently increases the size of `entries` for the lifetime of the validator process (short of a full restart), degrading `prune`'s (and `remove_programs_with_no_entries`'s) per-slot latency for the whole cluster on every subsequent block — a persistent, slot-by-slot processing-time tax analogous to the rewards-plan `BeginBlock` iteration in the reported bug, ultimately threatening liveness/slot-processing-time guarantees if scaled far enough.

### Likelihood Explanation
Program deployment via `bpf_loader_upgradeable` is fully permissionless and requires no special privileges — any funded account can deploy programs repeatedly. The per-program cost is a one-time rent deposit sized to a minimal ELF, which is materially cheaper than the ongoing, cumulative CPU cost imposed on `prune`/`remove_programs_with_no_entries` across all future slots, mirroring the "high likelihood, low relative attack cost vs. compounding validator cost" characterization in the source report. However, whether this reaches practical chain-halt severity depends on how large `entries` must grow before `prune`'s per-slot latency becomes cluster-impacting, which was not empirically measured here — this is an architectural underpricing finding, not a benchmarked chain-halt PoC.

### Recommendation
- Bound the lifetime size of `ProgramCache::entries` (e.g., evict/garbage-collect top-level keys whose programs have been closed/unloaded for a sufficiently long time, not just when `second_level` is literally empty), rather than letting it grow unboundedly with the total historical count of distinct deployed program pubkeys.
- Charge program-deployment fees (or ongoing rent) in a way that scales with the incremental burden placed on `ProgramCache` bookkeeping (analogous to `ctx.GasMeter().ConsumeGas(BaseGasFeeForNewPlan*len(existing))` in the source recommendation), or otherwise cap the number of distinct program identities that can be cheaply created.
- Ensure `prune`/`remove_programs_with_no_entries` complexity does not scale with all-time distinct program count by using an auxiliary index of only "active"/"prunable" entries so that the hot per-slot rerooting path is not proportional to unbounded historical state.

### Proof of Concept
No executable PoC was produced in this analysis. The finding is derived by static code-path tracing: repeatedly submitting `bpf_loader_upgradeable` deploy transactions for distinct minimal-size programs (analogous to the "create many low-cost Rewards Plans" loop in the source report) would grow `ProgramCache::entries` without bound, and each subsequent call to `Bank::prune_program_cache` → `ProgramCache::prune` → `remove_programs_with_no_entries` would incur cost linear in that grown map on every slot/rerooting, matching the reported bug's shape (cheap unbounded state creation → unmetered linear iteration in a routine that runs on virtually every block). Confirming the actual wall-clock/CU impact at scale would require running this attack against a live validator, which was not performed here.

        /// so all loads for a given program key are serialized.

    pub fn prune(
        &mut self,
        new_root_slot: Slot,
        new_environment: Option<ProgramRuntimeEnvironment>,
        fork_graph: &FG,
    ) {
        match &mut self.index {
            IndexImplementation::V1 { entries, .. } => {
                for second_level in entries.values_mut() {
                    // Remove entries un/re/deployed on orphan forks
                    let mut first_ancestor_found = false;
                    let mut first_ancestor_env = None;
                    *second_level = second_level
                        .iter()
                        .rev()
                        .filter(|entry| {
                            let relation =
                                fork_graph.relationship(entry.deployment_slot, new_root_slot);
                            if entry.deployment_slot >= new_root_slot {
                                matches!(relation, BlockRelation::Equal | BlockRelation::Descendant)
                            } else if matches!(relation, BlockRelation::Ancestor)
                                || entry.deployment_slot <= self.latest_root_slot
                            {
                                if !first_ancestor_found {
                                    first_ancestor_found = true;
                                    first_ancestor_env = entry.program.get_environment();
                                    return true;
                                }
                                // Do not prune the entry if the runtime environment of the entry is
                                // different than the entry that was previously found (stored in
                                // first_ancestor_env). Different environment indicates that this entry
                                // might belong to an older epoch that had a different environment (e.g.
                                // different feature set). Once the root moves to the new/current epoch,
                                // the entry will get pruned. But, until then the entry might still be
                                // getting used by an older slot.
                                if let Some(entry_env) = entry.program.get_environment()
                                    && let Some(env) = first_ancestor_env
                                    && entry_env != env
                                {
                                    return true;
                                }
                                self.stats.prunes_orphan.fetch_add(1, Ordering::Relaxed);
                                false
                            } else {
                                self.stats.prunes_orphan.fetch_add(1, Ordering::Relaxed);
                                false
                            }
                        })
                        .cloned()
                        .collect();
                    second_level.reverse();
                    // Remove or adjust entries with outdated environment of previous feature set
                    if let Some(new_environment) = new_environment.as_ref() {
                        let retain_flags = (0..second_level.len())
                            .map(|index_in_second_level| {
                                let entry = second_level.get(index_in_second_level).unwrap();
                                if Self::matches_environment(entry, new_environment) {
                                    return true;
                                }
                                // second_level is sorted by deployment_slot first,
                                // thus if the neighbors have a different deployment_slot
                                // then no other entry with the same deployment_slot exists.
                                let prev_entry = index_in_second_level
                                    .checked_sub(1)
                                    .and_then(|idx| second_level.get(idx));
                                let next_entry = index_in_second_level
                                    .checked_add(1)
                                    .and_then(|idx| second_level.get(idx));
                                let other_entry_with_same_deployment_slot_exists = prev_entry
                                    .map(|e| e.deployment_slot)
                                    == Some(entry.deployment_slot)
                                    || next_entry.map(|e| e.deployment_slot)
                                        == Some(entry.deployment_slot);
                                if other_entry_with_same_deployment_slot_exists {
                                    self.stats
                                        .prunes_environment
                                        .fetch_add(1, Ordering::Relaxed);
                                    return false;
                                } else if let Some(unloaded_entry) = entry.to_unloaded_in_env(
                                    ProgramRuntimeEnvironment::clone(new_environment),
                                ) && let Some(entry) =
                                    second_level.get_mut(index_in_second_level)
                                {
                                    *entry = Arc::new(unloaded_entry);
                                }
                                true
                            })
                            .collect::<Vec<bool>>();
                        let mut index_in_second_level = 0;
                        second_level.retain(|_entry| {
                            let retain_flag = *retain_flags.get(index_in_second_level).unwrap();
                            index_in_second_level = index_in_second_level.saturating_add(1);
                            retain_flag
                        });
                    }
                }

    fn remove_programs_with_no_entries(&mut self) {
        match &mut self.index {
            IndexImplementation::V1 { entries, .. } => {
                let num_programs_before_removal = entries.len();
                entries.retain(|_key, second_level| !second_level.is_empty());
                if entries.len() < num_programs_before_removal {
                    self.stats.empty_entries.fetch_add(
                        num_programs_before_removal.saturating_sub(entries.len()) as u64,
                        Ordering::Relaxed,
                    );
                }
            }
        }
    }
