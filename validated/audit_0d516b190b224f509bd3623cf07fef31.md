Based on my research, `updateRemoteUrl` is called automatically (without user prompting) every time a repository is selected, via `_selectRepositoryRefreshTasks` → `repositoryWithRefreshedGitHubRepository` → `updateRemoteUrl`. This runs silently in the background using data returned by the GitHub API, and matches the "underlying asset change causes stale/incorrect cached state to drive a state-changing action" pattern from the report.

### Title
Automatic remote URL rewrite from GitHub API response silently redirects future push/fetch operations - (File: app/src/lib/stores/updates/update-remote-url.ts)

### Summary
Every time a GitHub-associated repository is opened in Desktop, `repositoryWithRefreshedGitHubRepository` refetches the repository object from the GitHub API and, if the API's `clone_url` no longer matches the locally cached `gitHubRepository.cloneURL`, silently rewrites the local git remote (`origin`) to the new URL, without any user confirmation.

### Finding Description
`_selectRepositoryRefreshTasks` unconditionally calls `repositoryWithRefreshedGitHubRepository(repository)` on every repository selection [1](#0-0) . That function fetches the repository's current state from the API using the cached `owner`/`name` association, and if a GitHub repository association already exists, calls `updateRemoteUrl(gitStore, repository.gitHubRepository, apiRepo)` before persisting the fresh API data [2](#0-1) .

`updateRemoteUrl` compares the *previously cached* `gitHubRepository.cloneURL` (the "cached asset value") against the current local remote and the *new* API-provided `clone_url`. If the protocol matches and the local remote still equals the old cached clone URL but no longer equals the new API value, it calls `gitStore.setRemoteURL(...)` and rewrites `origin` to the new URL automatically [3](#0-2) . This is precisely a "cached price"-style value (`gitHubRepository.cloneURL`) being used to authorize a state-changing action after the underlying resource (the repo's identity/location on GitHub) has changed — mirroring the report's core defect of relying on a stale cached reference instead of re-validating against a trust anchor.

Critically, the matching used throughout (`matchGitHubRepository`, `urlMatchesRemote`) is purely string-based on hostname/owner/name, not on GitHub's stable numeric repository ID [4](#0-3) . The API repository object itself is fetched again from `api.fetchRepository(owner, name)` using the previously-cached owner/name, and the API response is trusted wholesale to be "the same repository, possibly moved" with no verification that the returned repository's `id` matches the originally-associated repository's `id` [5](#0-4) .

### Impact Explanation
If a GitHub repository the user has cloned/associated with Desktop is renamed or transferred to a different owner/location on GitHub (a legitimate GitHub API-level event, not requiring any local/physical access, admin rights, or leaked credentials), the very next time the user opens that repository in Desktop, the app will automatically and silently repoint their local `origin` remote to whatever `clone_url` the GitHub API now returns for that (owner, name) pair — without ever verifying that the underlying repository identity (via the stable numeric repo ID) is preserved. Because the endpoint stays on the same host (github.com), stored credentials remain valid for the new destination, so the user's subsequent `git push` operations will silently be sent to a different (potentially attacker-controlled) repository without any prompt, dialog, or confirmation. This is a case of "silent corruption of what the user commits or pushes" driven entirely by trusting an externally-controlled API object (`apiRepo.clone_url`) to override the locally configured remote.

### Likelihood Explanation
Medium. It requires only that the (owner, name) pair the app is tracking end up resolving, via the GitHub API, to a different underlying repository object than the one the user originally added — something that can happen through repository renames/transfers already reachable through the normal GitHub API flows this code exercises, with zero user interaction or explicit consent required to trigger the automatic remote rewrite in Desktop.

### Recommendation
Do not use the cached `clone_url` string comparison alone as the trust anchor for auto-rewriting `origin`. Before calling `gitStore.setRemoteURL`, verify that the API-returned repository's stable id (`GitHubRepository.dbID`/GitHub's numeric repo id) matches the id already associated with the local `Repository`/`GitHubRepository` record. If the id differs, treat it as an association mismatch and require explicit user confirmation before touching the local git remote — comparable to the original report's recommendation to reset/re-validate all cached references after the underlying asset's identity changes, rather than assuming continuity.

### Proof of Concept
1. User clones `https://github.com/alice/project` in Desktop; Desktop stores `gitHubRepository.cloneURL = https://github.com/alice/project` and associates `origin` remote to it.
2. Alice deletes/renames her account or transfers repository ownership such that `alice/project` now resolves (via GitHub's API, following its owner/name based lookup) to a different repository, e.g. one now controlled by a different party at the same `owner/name` path or via a legitimate GitHub-tracked rename/transfer to an unexpected destination `mallory/project-fork`.
3. User reopens the repository in Desktop. `_selectRepositoryRefreshTasks` → `repositoryWithRefreshedGitHubRepository` fetches the API repository for the cached `owner`/`name`, receiving a new `clone_url` pointing at `mallory/project-fork` [6](#0-5) .
4. `updateRemoteUrl` sees the local remote still equals the old cached `cloneURL`, protocols match, and the new URL differs, so it silently calls `gitStore.setRemoteURL('origin', newUrl)` [7](#0-6) .
5. The user, unaware of the change, runs `git push` from Desktop; their code is pushed to `mallory/project-fork` instead of the repository they believe they are working with.

export async function updateRemoteUrl(
  gitStore: GitStore,
  gitHubRepository: GitHubRepository,
  apiRepo: IAPIRepository
): Promise<void> {
  // I'm not sure when these early exit conditions would be met. But when they are
  // we don't have enough information to continue so exit early!
  if (gitStore.defaultRemote === null) {
    return
  }

  const remoteUrl = gitStore.defaultRemote.url
  const updatedRemoteUrl = apiRepo.clone_url
  const urlsMatch = urlMatchesRemote(updatedRemoteUrl, gitStore.defaultRemote)

  // Verify that protocol hasn't changed. If it has we don't want
  // to alter the protocol in case they are relying on a specific one.
  // If protocol is null that implies the url is a ssh url
  // of the format git@github.com:octocat/Hello-World.git, which
  // can't be parsed by URL.parse. In this case we assume the user
  // manually configured their remote to use this format and we don't
  // want to change what they've done just to be safe
  const parsedRemoteUrl = URL.parse(remoteUrl)
  const parsedUpdatedRemoteUrl = URL.parse(updatedRemoteUrl)
  const protocolsMatch =
    parsedRemoteUrl.protocol !== null &&
    parsedUpdatedRemoteUrl.protocol !== null &&
    parsedRemoteUrl.protocol === parsedUpdatedRemoteUrl.protocol

  // Check if the default remote url has been manually changed from the
  // clone url retrieved from the GitHub API previously
  const remoteUrlUnchanged =
    gitStore.defaultRemote &&
    urlMatchesRemote(gitHubRepository.cloneURL, gitStore.defaultRemote)

  if (protocolsMatch && remoteUrlUnchanged && !urlsMatch) {
    await gitStore.setRemoteURL(gitStore.defaultRemote.name, updatedRemoteUrl)
  }
}

export function urlMatchesRemote(url: string | null, remote: IRemote): boolean {
  if (url == null) {
    return false
  }

  const cloneUrl = parseRemote(url)
  const remoteUrl = parseRemote(remote.url)

  if (remoteUrl == null || cloneUrl == null) {
    return false
  }

  if (!caseInsensitiveEquals(remoteUrl.hostname, cloneUrl.hostname)) {
    return false
  }

  if (remoteUrl.owner == null || cloneUrl.owner == null) {
    return false
  }

  if (remoteUrl.name == null || cloneUrl.name == null) {
    return false
  }

  return (
    caseInsensitiveEquals(remoteUrl.owner, cloneUrl.owner) &&
    caseInsensitiveEquals(remoteUrl.name, cloneUrl.name)
  )
}
