### Title
Transaction weight/fee computed before the OP_RETURN `data` output is accounted for, underpaying fees — (File: networks/bitcoin/src/wallet/send.rs)

### Summary
Analogous to the Timeswap `collect()` bug — where `transferFees` consumed `long0Fees/long1Fees/shortFees` before they were computed (always zero) — `SignableTransaction::new` computes the transaction's weight, vbytes, and `needed_fee` from an incomplete output set. The OP_RETURN `data` output is appended to `tx_outs` (lines 194-202) but `calculate_weight_vbytes` is only ever called with `payments` (lines 204, 225-226), never including the data output. The fee decision therefore uses a stale/partial value, just as `transferFees` used not-yet-computed fee values.

### Finding Description
`SignableTransaction::new` builds `tx_outs` in three stages: payments, then the OP_RETURN output (up to 80 bytes of caller-supplied `data`), then optionally change:

```rust
// networks/bitcoin/src/wallet/send.rs:194-202
if let Some(data) = data {
  tx_outs.push(TxOut {
    value: Amount::ZERO,
    script_pubkey: ScriptBuf::new_op_return(...)
  })
}

// line 204 - data output is NOT included in the weight estimate
let (mut weight, vbytes) = Self::calculate_weight_vbytes(tx_ins.len(), payments, None);
let mut needed_fee = fee_per_vbyte * vbytes;

// lines 224-235 - change calculation also uses payments only
let (weight_with_change, vbytes_with_change) =
  Self::calculate_weight_vbytes(tx_ins.len(), payments, Some(&change));
let fee_with_change = fee_per_vbyte * vbytes_with_change;
```

`calculate_weight_vbytes` (lines 62-127) constructs a mock `Transaction` whose outputs are `payments` plus optionally `change` — the OP_RETURN output is never represented. Consequences:

1. `needed_fee` and `fee_with_change` are underestimated by `fee_per_vbyte * size_of(OP_RETURN output)` (roughly `10 + data.len()` bytes, up to ~90 bytes ≈ 23 vbytes).
2. When change is used, the change amount is `input_sat - payment_sat - fee_with_change`, so the *actual* paid fee (`sum(inputs) - sum(outputs)`) equals the underestimated `fee_with_change`, not the requested `fee_per_vbyte` rate on the true size.
3. The minimum-relay-fee gate at line 211 uses the underestimated `needed_fee`/`vbytes`, so a transaction can pass this check while its true fee rate falls below `DEFAULT_MIN_RELAY_TX_FEE`.

### Impact Explanation
Any caller supplying `data` produces a signed transaction paying a lower effective fee rate than `fee_per_vbyte` requested, and potentially below the Bitcoin minimum relay fee. Since this library produces the threshold-signed transaction for moving wallet funds, an underpriced transaction may be rejected by relay/mempool policy, leaving the outputs unspendable via this transaction until a replacement is negotiated — the protocol believes it funded a proper fee (it "burned" the change accordingly) while the network sees an underpriced TX. This mirrors the finding's inconsistent-state impact: state committed based on values computed from incomplete data.

### Likelihood Explanation
Reachable by any caller of `SignableTransaction::new` passing non-`None` `data` (a public parameter); no privileged position required. Triggers deterministically whenever `data` is present, most severely with `fee_per_vbyte` near the minimum and data near the 80-byte cap, where the ~23-vbyte shortfall can push the real rate below relay minimums.

### Recommendation
Include the OP_RETURN output in the mock transaction inside `calculate_weight_vbytes` (pass the fully-built `tx_outs` or add the data output's size to the estimate), computing both the no-change and with-change weights after all fixed outputs are known — i.e., compute the weight only after the complete output set is determined, mirroring the fix of moving `transferFees` after fee calculation.

### Proof of Concept
- `networks/bitcoin/src/wallet/send.rs:194-204`: data output pushed to `tx_outs`, then `calculate_weight_vbytes(tx_ins.len(), payments, None)` — `payments` excludes the OP_RETURN.
- `networks/bitcoin/src/wallet/send.rs:225-227`: `fee_with_change` derived from `payments` + `change` only.
- `networks/bitcoin/src/wallet/send.rs:228-233`: change absorbs the shortfall (`input_sat - payment_sat - fee_with_change`), locking the underestimation into the real fee.
- `networks/bitcoin/src/wallet/send.rs:89-93`: the mock TX outputs are built solely from `payments`, confirming the data output is uncounted.
