### Title
`bank` precompile `send`/`MainRewarder`-style bypass: EVM `send()` calls `BankKeeper.SendCoins` directly, skipping `SendEnabled` and `BlockedAddr` checks enforced at the Cosmos message layer - ([File: precompiles/bank/legacy/v610/bank.go])

### Summary
The Cosmos-SDK bank message-handling path (`BankCoinTransferrer.TransferCoins`, used by `x/bank` `MsgSend` and by the wasmd `BankCoinTransferrer`) explicitly checks `IsSendEnabledCoins` and `BlockedAddr` before calling the low-level `SendCoins` primitive. The EVM `bank` precompile's `send()` executor, however, calls `p.bankKeeper.SendCoins(...)` directly, bypassing both checks entirely — mirroring the reported bug class where a protection (`whenNotPaused`) is enforced at one entry point (`LMPVault.claimRewards`) but not at the lower-level primitive (`MainRewarder.getReward`) reachable through another path.

### Finding Description
`BankCoinTransferrer.TransferCoins` in `sei-wasmd/x/wasm/keeper/keeper.go` is the guarded transfer path: it calls `c.keeper.IsSendEnabledCoins(ctx, amount...)` and `c.keeper.BlockedAddr(toAddr)` before invoking `c.keeper.SendCoins`. [1](#0-0) 

The bank module documents `BlockedAddr`/`SendEnabled` as invariant-preserving guards that any client-facing path must respect, warning that if blocked module accounts receive funds outside these rules the chain "invariants are likely to be broken and could result in a halted network." [2](#0-1) 

The lower-level `BaseSendKeeper.SendCoins` primitive itself performs **no** `SendEnabled` or `BlockedAddr` check — it only calls `SendCoinsWithoutAccCreation` and creates the recipient account if missing. [3](#0-2) 

The EVM bank precompile's `send()` executor calls `p.bankKeeper.SendCoins(ctx, senderSeiAddr, receiverSeiAddr, sdk.NewCoins(...))` directly — never routing through `TransferCoins`/`IsSendEnabledCoins`/`BlockedAddr` — and this pattern is repeated across every legacy precompile version examined (v552, v555, v580, v600, v610). [4](#0-3) [5](#0-4) 

A `grep` across `precompiles/bank/**` for `IsSendEnabledCoins` and `BlockedAddr` returns zero matches, confirming none of the precompile executors perform these checks anywhere in the `send` code path.

### Impact Explanation
If a denom's `SendEnabled` param is turned off (e.g., during an incident, a governance-directed freeze of a compromised/exploited token, or a denom explicitly disabled to halt transfers) or if a destination address is on the bank module's `blockedAddrs` list (module accounts, reserved EVM-coinbase-style addresses, etc.), a user can still move funds for that denom by calling the ERC20-native-pointer contract's `transfer`, which dispatches into the `bank` precompile's `send()` and reaches `SendCoins` directly — completely bypassing the `SendEnabled`/`BlockedAddr` gate that the Cosmos-native `MsgSend` path enforces. This can be used to move funds to a module account that bank invariants assume is unreachable (potentially breaking accounting invariants that other modules rely on, as the bank spec itself warns), or to transfer a denom that governance has explicitly disabled from being sent, defeating the intended freeze.

### Likelihood Explanation
Any unprivileged EVM transaction sender that has an ERC20 native pointer registered for a Sei denom (a standard, publicly reachable path since anyone can register a pointer for any bank denom with metadata) can trigger this by calling `transfer`/`send` through the pointer, which routes to the `bank` precompile's `send()` method — no special privileges are required, and the check-bypass is deterministic and always reachable whenever `SendEnabled=false` or the recipient is blocked.

### Recommendation
Route the `bank` precompile's `send`/`sendNative` executors through the same guarded transfer function used by `x/bank` `MsgSend` (i.e., call `IsSendEnabledCoins` and `BlockedAddr` — or invoke `BankCoinTransferrer.TransferCoins`/the bank `MsgServer.Send` path as the `v610` `send()` for native-pointer-triggered sends already appears to do via `bankMsgServer.Send`) — instead of calling `bankKeeper.SendCoins` directly, for every precompile version that still calls `SendCoins` unguarded.

### Proof of Concept
1. Governance (or an authorized process) sets `SendEnabled=false` for denom `foo` via `x/bank` params, or a recipient address is present in `blockedAddrs`.
2. Attempt `MsgSend` of `foo` to that recipient via the native Cosmos tx path — it fails with `ErrSendDisabled`/`ErrUnauthorized` because `BankCoinTransferrer.TransferCoins` checks `IsSendEnabledCoins`/`BlockedAddr` before calling `SendCoins`. [1](#0-0) 
3. Register/obtain the ERC20 native pointer for `foo`, then call the pointer contract's `transfer(recipient, amount)`; this reaches the `bank` precompile's `send()` executor, which calls `p.bankKeeper.SendCoins(...)` with no `IsSendEnabledCoins`/`BlockedAddr` check, and the transfer succeeds despite the disabled/blocked state. [5](#0-4)

// TransferCoins transfers coins from source to destination account when coin send was enabled for them and the recipient
// is not in the blocked address list.
func (c BankCoinTransferrer) TransferCoins(parentCtx sdk.Context, fromAddr sdk.AccAddress, toAddr sdk.AccAddress, amount sdk.Coins) error {
	em := sdk.NewEventManager()
	ctx := parentCtx.WithEventManager(em)
	if err := c.keeper.IsSendEnabledCoins(ctx, amount...); err != nil {
		return err
	}
	if c.keeper.BlockedAddr(toAddr) {
		return sdkerrors.Wrapf(sdkerrors.ErrUnauthorized, "%s is not allowed to receive funds", toAddr.String())
	}

	sdkerr := c.keeper.SendCoins(ctx, fromAddr, toAddr, amount)
	if sdkerr != nil {
		return sdkerr
	}

## Blocklisting Addresses

The `x/bank` module accepts a map of addresses that are considered blocklisted
from directly and explicitly receiving funds through means such as `MsgSend` and
`MsgMultiSend` and direct API calls like `SendCoinsFromModuleToAccount`.

Typically, these addresses are module accounts. If these addresses receive funds
outside the expected rules of the state machine, invariants are likely to be
broken and could result in a halted network.

By providing the `x/bank` module with a blocklisted set of addresses, an error occurs for the operation if a user or client attempts to directly or indirectly send funds to a blocklisted account, for example, by using [IBC](http://docs.cosmos.network/master/ibc/).

func (k BaseSendKeeper) SendCoins(ctx sdk.Context, fromAddr sdk.AccAddress, toAddr sdk.AccAddress, amt sdk.Coins) error {
	if err := k.SendCoinsWithoutAccCreation(ctx, fromAddr, toAddr, amt); err != nil {

	}

	// Create account if recipient does not exist.
	//
	// NOTE: This should ultimately be removed in favor a more flexible approach

	if !accExists {
		defer func() {
			recordNewAccounts(ctx.Context(), 1)
		}()
		k.ak.SetAccount(ctx, k.ak.NewAccountWithAddress(ctx, toAddr))
	}

	return nil
}

func (p PrecompileExecutor) send(ctx sdk.Context, caller common.Address, method *abi.Method, args []interface{}, value *big.Int, readOnly bool) ([]byte, uint64, error) {
	if readOnly {
		return nil, 0, errors.New("cannot call send from staticcall")
	}
	if err := pcommon.ValidateNonPayable(value); err != nil {
		return nil, 0, err
	}

	if err := pcommon.ValidateArgsLength(args, 4); err != nil {
		return nil, 0, err
	}
	denom := args[2].(string)
	if denom == "" {
		return nil, 0, errors.New("invalid denom")
	}
	pointer, _, exists := p.evmKeeper.GetERC20NativePointer(ctx, denom)
	if !exists || pointer.Cmp(caller) != 0 {
		return nil, 0, fmt.Errorf("only pointer %s can send %s but got %s", pointer.Hex(), denom, caller.Hex())
	}
	amount := args[3].(*big.Int)
	if amount.Cmp(utils.Big0) == 0 {
		// short circuit
		bz, err := method.Outputs.Pack(true)
		return bz, pcommon.GetRemainingGas(ctx, p.evmKeeper), err
	}
	senderSeiAddr, err := p.accAddressFromArg(ctx, args[0])
	if err != nil {
		return nil, 0, err
	}
	receiverSeiAddr, err := p.accAddressFromArg(ctx, args[1])
	if err != nil {
		return nil, 0, err
	}

	msg := &banktypes.MsgSend{
		FromAddress: senderSeiAddr.String(),
		ToAddress:   receiverSeiAddr.String(),
		Amount:      sdk.NewCoins(sdk.NewCoin(denom, sdk.NewIntFromBigInt(amount))),
	}

	err = msg.ValidateBasic()
	if err != nil {
		return nil, 0, err
	}

	if _, err = p.bankMsgServer.Send(sdk.WrapSDKContext(ctx), msg); err != nil {
		return nil, 0, err
	}

	bz, err := method.Outputs.Pack(true)
	return bz, pcommon.GetRemainingGas(ctx, p.evmKeeper), err
}
