### Title
Symlinked `.gitignore` causes silent write-outside-repo when using "Ignore file" - (File: `app/src/lib/git/gitignore.ts`)

### Summary
`appendIgnoreRule`/`appendIgnoreFile` operate on the repository's `.gitignore` using plain `fs` read/write calls that transparently follow symlinks. Git tracks symlinks as regular blobs, so a malicious repository can ship a `.gitignore` entry that is a symlink pointing to an arbitrary path outside the repository working tree. When the victim uses the "Ignore file" context-menu action, Desktop reads through the symlink, appends the escaped file pattern, and writes the result back through the same symlink — silently modifying a file the user never intended to touch, entirely outside the repository.

### Finding Description
`readGitIgnoreAtRoot` computes `ignorePath = Path.join(repository.path, '.gitignore')` and reads it with `FS.readFile`, which resolves symlinks by default: [1](#0-0) 

`saveGitIgnore` writes the new contents back to the same path using `writeFile` from `fs/promises`, which likewise follows symlinks rather than replacing the link itself: [2](#0-1) 

`appendIgnoreRule` chains these two operations together — read current contents, append the new pattern, format, and save — with no check anywhere that `.gitignore` is a regular file rather than a symlink: [3](#0-2) 

`appendIgnoreFile` (the handler invoked by the "Ignore file" context-menu action) only escapes special gitignore characters in the path before delegating to `appendIgnoreRule`; it performs no validation of the `.gitignore` file type/location: [4](#0-3) 

Because Git supports and clones tracked symlinks (subject to `core.symlinks`, which defaults to enabled on macOS/Linux and is also honorable on Windows with the right privilege/config), an attacker can craft a repository whose `.gitignore` is a symlink to an out-of-tree file (e.g., another project's config file, a dotfile in the user's home directory, or any writable path reachable by the OS user). Nothing in Desktop's clone/ignore-file pipeline checks the link target or refuses to follow it, unlike other parts of the codebase (e.g., `resolveWithin` in `app/src/lib/path.ts`) that explicitly use `realpath` to confine paths under a root before performing filesystem operations — no equivalent guard exists for `.gitignore` handling.

### Impact Explanation
Following the symlink means the append operation writes attacker-influenced text (the escaped path of whichever file the victim right-clicked and chose "Ignore file" on) into a file entirely outside the repository, at a location fully chosen by the attacker via the symlink target. This is a silent, unexpected file write outside the intended repository directory, matching the "file write ... outside the repo" impact category. Depending on the target file (e.g., a shell rc file, another repo's config, or an application config file the OS user can write to), this could corrupt configuration or, in some cases, be leveraged for further attack chains if the target file is later interpreted/executed.

### Likelihood Explanation
Exploitation requires only: (1) the victim clones/fetches an attacker-controlled repository containing a `.gitignore` symlink, and (2) the victim performs the ordinary Desktop action of right-clicking a changed file and selecting "Ignore file" (or "Ignore file extension"/similar) from the Changes list context menu, which is a normal, expected workflow — not an "unnatural" step. Cloning a repository from an untrusted source and interacting with its Changes panel are both within the intended attacker-controlled-repository threat model in scope. The victim does not need to inspect `.gitignore` themselves for the corruption to occur, since the write happens transparently.

### Recommendation
Before reading or writing the root `.gitignore`, verify with `fs.lstat` (or `fs.promises.lstat`) that the path is not a symlink (or that the symlink resolves to a path within the repository root, similar to the existing `resolveWithin`/`realpath` pattern in `app/src/lib/path.ts`). If a symlink pointing outside the repo tree is detected, `appendIgnoreRule`/`readGitIgnoreAtRoot`/`saveGitIgnore` should fail closed (reject/throw or surface an error to the user) rather than transparently following the link.

### Proof of Concept
1. Create a repository where `.gitignore` is committed as a symlink pointing to an out-of-tree file, e.g. on a POSIX system:
   ```
   ln -s /tmp/victim-file.txt .gitignore
   git add .gitignore
   git commit -m "malicious gitignore symlink"
   ```
2. Ensure `/tmp/victim-file.txt` exists with known content on the victim machine (or point the symlink at any writable file the victim already has, such as a dotfile).
3. Victim clones this repository with GitHub Desktop (with symlink support enabled, the default on macOS/Linux).
4. Victim modifies/adds a file in the working directory so it appears in the Changes list, right-clicks it, and selects "Ignore file" from the context menu, triggering `appendIgnoreFile` → `appendIgnoreRule`.
5. Diff `/tmp/victim-file.txt` before and after step 4 — it will contain the appended, escaped ignore pattern for the file the victim ignored, despite the victim never intending to touch `/tmp/victim-file.txt`.

```typescript
export async function readGitIgnoreAtRoot(
  repository: Repository
): Promise<string | null> {
  const ignorePath = Path.join(repository.path, '.gitignore')

  return new Promise<string | null>((resolve, reject) => {
    FS.readFile(ignorePath, 'utf8', (err, data) => {
      if (err) {
        if (err.code === 'ENOENT') {
          resolve(null)
        } else {
          reject(err)
        }
      } else {
        resolve(data)
      }
    })
  })
}
```

```typescript
export async function saveGitIgnore(
  repository: Repository,
  text: string
): Promise<void> {
  const ignorePath = Path.join(repository.path, '.gitignore')

  if (text === '') {
    return new Promise<void>((resolve, reject) => {
      FS.unlink(ignorePath, err => {
        if (err) {
          reject(err)
        } else {
          resolve()
        }
      })
    })
  }

  const fileContents = await formatGitIgnoreContents(text, repository)
  await writeFile(ignorePath, fileContents)
}
```

```typescript
export async function appendIgnoreRule(
  repository: Repository,
  patterns: string | string[]
): Promise<void> {
  const text = (await readGitIgnoreAtRoot(repository)) || ''

  const currentContents = await formatGitIgnoreContents(text, repository)

  const newPatternText =
    patterns instanceof Array ? patterns.join('\n') : patterns
  const newText = await formatGitIgnoreContents(
    `${currentContents}${newPatternText}`,
    repository
  )

  await saveGitIgnore(repository, newText)
}
```

```typescript
export async function appendIgnoreFile(
  repository: Repository,
  filePath: string | string[]
): Promise<void> {
  if (filePath instanceof Array) {
    const escapedFilePaths = filePath.map(path =>
      escapeGitSpecialCharacters(path)
    )

    return appendIgnoreRule(repository, escapedFilePaths)
  }

  const escapedFilePath = escapeGitSpecialCharacters(filePath)
  return appendIgnoreRule(repository, escapedFilePath)
}
```
