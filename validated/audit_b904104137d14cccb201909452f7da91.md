Based on the investigation, the strongest analog to the M-3 pattern (an invariant/safety check performed *before* a state-mutating value-moving action instead of atomically with or after it, so the action itself can violate the checked invariant) is in the **gasless module**'s lend/swap flow.

### Title
Gasless lending funds can be lost when swap-repayment invariant is validated against stale state before the value-moving lend transaction executes - (File: kaiax/gasless/impl/tx_pool.go, kaiax/gasless/impl/builder.go, work/builder/bundle.go)

### Summary
The `GaslessModule` validates that a swap will be able to repay a lent gas amount (`checkBalanceForSwap`, `VerifyExecutable`) using a snapshot of chain state (token balance, allowance, and router exchange rate via `GetAmountIn`) *before* the node-funded `LendTx` (real KAIA value transfer to the sender) and the user's `swapForGas` transaction are bundled and executed. The bundle mechanism (`work/builder/bundle.go`) only enforces *ordering* between transactions (`TargetTxHash`/`TargetRequired`), not that the lend and the repaying swap succeed atomically as a single unit.

### Finding Description
`GaslessModule.checkBalanceForSwap` validates several conditions using the tx-pool's current state snapshot: [1](#0-0) 
This includes a live on-chain price query (`routerContract.GetAmountIn`) and current allowance/balance, all evaluated at validation time. [2](#0-1) 

`VerifyExecutable` (used both for tx-pool admission and for the `auction_submitBid`/gasless RPC pre-check) similarly validates repay amount correctness (`SP4`) against arguments decoded once, not re-verified atomically against the state at the moment the bundle actually executes: [3](#0-2) 

The resulting bundle for block building places the `LendTxGenerator` (a real KAIA transfer from the node to the sender) ahead of the `approveTx`/`swapTx`: [4](#0-3) 

`Bundle` (`work/builder/bundle.go`) has no field or mechanism that ties the success of one included transaction to another — it only tracks `TargetTxHash` and `TargetRequired` for *placement*, not all-or-nothing execution: [5](#0-4) 

Because the check that "the swap can and will repay what was lent" is performed once, before the lend transaction is placed into the block, and the bundle format provides no atomic linkage guaranteeing the lend only takes effect if the swap actually succeeds and repays, a state change between the check and execution (e.g., a race with another transaction altering the router's exchange rate, the token allowance, or the token balance) can cause the `LendTx` to unconditionally transfer KAIA to the sender while the subsequent `swapForGas` call reverts or under-repays.

### Impact Explanation
If the lend executes but the repay-bearing swap fails/underperforms, the module's lending node suffers a direct, unrecoverable loss of KAIA funds. This is a concrete value-movement / fee-delegation-style loss reachable by any unprivileged gasless-transaction submitter who can influence timing or exploit the gap between admission-time state and execution-time state (e.g., by front-running the router price or draining/reducing token allowance/balance right before block inclusion).

### Likelihood Explanation
The check-then-act gap is inherent in the design: `checkBalanceForSwap`/`VerifyExecutable` are re-run at various points (pool admission, `IsReady`), but nothing in `work/builder/bundle.go` enforces atomic success linkage between the `LendTx` and the `swapTx` at actual execution time in the block. Any state-changing event between the last check and inclusion (which can span a full block period) opens the window. This does not require special privileges — an ordinary user submitting a gasless swap, potentially timed against normal price movement or another of their own transactions, can trigger it.

### Recommendation
Ensure the lend and swap are atomically linked so that if the swap does not execute successfully and does not actually repay the exact expected amount, the lend value transfer is reverted or never finalized — e.g., re-validate `VerifyExecutable`'s conditions (price, allowance, balance, repay amount) immediately at execution time within the same atomic unit as the `LendTx`, or restructure the lending so repayment verification happens as part of a single transaction/precompile call rather than as two independently-executing bundled transactions.

### Proof of Concept
Not independently reproducible from static analysis alone — this requires constructing a gasless approve/swap pair, submitting it so it clears `checkBalanceForSwap`/`VerifyExecutable` at admission, then altering router liquidity, token allowance, or token balance before the bundle is included in a block, and observing that `LendTx` still transfers KAIA while `swapForGas` fails to fully repay. I could not verify within the available tool budget whether any additional runtime safeguard (e.g., a revert-linking mechanism elsewhere in the block-building pipeline not covered by `work/builder/bundle.go`) mitigates this; this should be confirmed by inspecting `GetLendTxGenerator`'s implementation and the full block-assembly path in `work/` package, which I was unable to fully read given remaining tool calls.

// VerifyExecutable checks if the given transactions form a valid gasless transaction
// It returns an error explaining why the transaction is not executable if it's not,
// and a boolean indicating whether the transaction is executable
func (g *GaslessModule) VerifyExecutable(approveTxOrNil, swapTx *types.Transaction) error {
	// Sx.
	swapArgs, ok := decodeSwapTx(swapTx, g.signer)
	if !ok {
		return ErrDecodeSwapTx
	}
	if !g.isSwapTx(swapArgs) {
		return ErrSwapTxInvalid
	}

	// Conditions involving ApproveTx
	if approveTxOrNil != nil {
		// Ax.
		approveArgs, ok := decodeApproveTx(approveTxOrNil, g.signer)
		if !ok {
			return ErrDecodeApproveTx
		}
		if !g.isApproveTx(approveArgs) {
			return ErrApproveTxInvalid
		}
		// AP1.
		if approveArgs.Sender != swapArgs.Sender {
			return ErrDifferentSenders
		}
		// SP1.
		if approveArgs.Token != swapArgs.Token {
			return fmt.Errorf("%w: approve token %s, swap token %s", ErrDifferentTokens, approveArgs.Token.Hex(), swapArgs.Token.Hex())
		}
		// SP2.
		if approveArgs.Amount.Cmp(swapArgs.AmountIn) < 0 {
			return fmt.Errorf("%w: approve amount %s, required amount %s", ErrInsufficientApproveAmount, approveArgs.Amount.String(), swapArgs.AmountIn.String())
		}
		// SP3.
		if approveTxOrNil.Nonce()+1 != swapTx.Nonce() {
			return fmt.Errorf("%w: approve nonce %d, swap nonce %d (expected %d)", ErrNonSequentialNonce, approveTxOrNil.Nonce(), swapTx.Nonce(), approveTxOrNil.Nonce()+1)
		}
		if nonce := g.getCurrentStateNonce(approveArgs.Sender); nonce != approveTxOrNil.Nonce() {
			return fmt.Errorf("%w: approve nonce %d, current nonce %d", ErrApproveNonceNotCurrent, approveTxOrNil.Nonce(), nonce)
		}
	} else {
		// SP3.
		if nonce := g.getCurrentStateNonce(swapArgs.Sender); nonce != swapTx.Nonce() {
			return fmt.Errorf("%w: swap nonce %d, current nonce %d", ErrSwapNonceNotCurrent, swapTx.Nonce(), nonce)
		}
	}

	// SP4.
	if swapArgs.AmountRepay.Cmp(repayAmount(approveTxOrNil, swapTx)) != 0 {
		return fmt.Errorf("%w: got %s, expected %s", ErrIncorrectRepayAmount, swapArgs.AmountRepay.String(), repayAmount(approveTxOrNil, swapTx).String())
	}

	return nil
}

func (g *GaslessModule) ExtractTxBundles(txs []*types.Transaction, prevBundles []*builder.Bundle) []*builder.Bundle {
	// there are only at most two gasless transactions in pending for a sender
	bundles := []*builder.Bundle{}
	approveTxs := map[common.Address]*types.Transaction{}
	targetTxHash := common.Hash{}
	for _, tx := range txs {
		addr, err := types.Sender(g.signer, tx)
		if err != nil {
			continue
		}
		if g.IsApproveTx(tx) {
			approveTxs[addr] = tx
		} else if g.IsSwapTx(tx) && g.IsExecutable(approveTxs[addr], tx) {
			bundleTxs := builder.NewTxOrGenList(g.GetLendTxGenerator(approveTxs[addr], tx))
			if approveTxs[addr] != nil {
				bundleTxs = append(bundleTxs, builder.NewTxOrGenFromTx(approveTxs[addr]))
			}
			bundleTxs = append(bundleTxs, builder.NewTxOrGenFromTx(tx))

			b := builder.NewBundle(
				bundleTxs,
				targetTxHash,
				false,
			)

			targetTxHash = tx.Hash()

			isConflict := false
			for _, prev := range append(prevBundles, bundles...) {
				if prev.IsConflict(b) {
					isConflict = true
					break
				}
			}
			if isConflict {
				// Gasless transactions will just fail even if they aren't bundled.
				continue
			}
			bundles = append(bundles, b)
		} else {
			targetTxHash = tx.Hash()
		}
	}
	return bundles
}

type Bundle struct {
	// each element can be either *types.Transaction, or TxGenerator
	BundleTxs []*TxOrGen

	// BundleTxs is placed AFTER the target tx. If empty hash, it is placed at the very front.
	TargetTxHash common.Hash

	// TargetRequired is true if the bundle must be executed after the target tx
	// and only if the target tx is successfully executed.
	TargetRequired bool

	// lookup map for O(1) membership checks (lazy initialized)
	txLookup map[common.Hash]int
}

func NewBundle(txs []*TxOrGen, targetTxHash common.Hash, targetRequired bool) *Bundle {
	b := &Bundle{
		BundleTxs:      txs,
		TargetTxHash:   targetTxHash,
		TargetRequired: targetRequired,
	}
	b.buildLookup()
	return b
}
