### Title
`create_payout_txhandler`'s `operator_xonly_pk` OP_RETURN is uncommitted by `user_sig` (SinglePlusAnyoneCanPay), allowing any withdrawer to attribute bridge reimbursement to an arbitrary operator - ([File: core/src/builder/transaction/operator_reimburse.rs])

### Summary
`user_sig` is required to use `SIGHASH_SINGLE|ANYONECANPAY`, which commits only to input 0 and output 0 (the user payout output) of the Payout transaction, never to output 2 (the OP_RETURN carrying `operator_xonly_pk`). Because `create_payout_txhandler` takes `operator_xonly_pk` as an unauthenticated caller-supplied argument and `Verifier::update_finalized_payouts` blindly parses whatever bytes sit in that OP_RETURN as the "payer" operator, any party who already possesses `(input_utxo, output_txout, user_sig)` — including the withdrawing user themselves, who legitimately obtains this triple to submit to Citrea's `withdraw` and to the aggregator — can build and broadcast a self-funded Payout tx naming an arbitrary registered operator as the fronting operator, causing that operator's automation to later claim the deposit's escrowed BTC via the Reimburse transaction for a payout it never funded.

### Finding Description
Binding claimed: `operator_xonly_pk` recorded for withdrawal index `i` (in `update_payout_txs_and_payer_operator_xonly_pk`, read from the confirmed Payout tx's OP_RETURN by `update_finalized_payouts`) == the party whose funds actually paid output 0 of that Payout tx.

Code path:
1. `parse_withdrawal_sig_params` enforces `TapSighashType::SinglePlusAnyoneCanPay` on `user_sig` [1](#0-0) .
2. `create_payout_txhandler` builds the Payout tx with input 0 = withdrawal UTXO (key-spend), output 0 = user payout, output 1 = anchor, output 2 = OP_RETURN(`operator_xonly_pk`), then places `user_sig` into input 0's witness — `operator_xonly_pk` is a plain function parameter, never derived from or checked against the signer of `user_sig` [2](#0-1) .
3. `Operator::withdraw` calls `create_payout_txhandler` with `self.signer.xonly_public_key` and verifies `user_sig` against the sighash of that specific tx [3](#0-2)  — but `SIGHASH_SINGLE|ANYONECANPAY` semantics mean the signature never commits to output 2 (OP_RETURN) or output 1 (anchor), so swapping `operator_xonly_pk` for any other value still produces a valid signature over the same sighash.
4. On-chain, `Verifier::update_finalized_payouts` scans the confirmed Payout tx, extracts the OP_RETURN bytes, and parses them into `operator_xonly_pk` with no cross-check against who actually supplied the extra funding inputs of the transaction [4](#0-3) , then persists this mapping via `update_payout_txs_and_payer_operator_xonly_pk`.
5. `PayoutCheckerTask::run_once` on the named operator's own node queries `get_first_unhandled_payout_by_operator_xonly_pk(self.operator.signer.xonly_public_key)` and, on match, calls `handle_finalized_payout` [5](#0-4) .
6. `Operator::handle_finalized_payout` unconditionally builds `KickoffData { operator_xonly_pk: self.signer.xonly_public_key, ... }` and drives the kickoff/Reimburse flow using that operator's own pre-signed N-of-N sigs — there is no verification that this operator's wallet actually supplied the funding inputs of the underlying Payout tx [6](#0-5) .
7. `create_reimburse_txhandler` ultimately spends the deposit's `DepositInMove` (escrowed bridge_amount) output and pays it to the named operator's `operator_reimbursement_address` [7](#0-6) .

Exploit flow: The attacker is the withdrawing user (or anyone who intercepts the handoff). They already legitimately possess `(input_utxo, output_txout, user_sig)` because they must supply exactly this triple to Citrea's `withdraw`/the aggregator's `Withdraw` gRPC. They construct their own Payout transaction: input 0 = the withdrawal UTXO + `user_sig` witness (unchanged, still valid), plus attacker-supplied funding inputs (their own wallet) to cover `output_txout.value` and fees, output 0 = `output_txout` (their own withdrawal payout — legitimate), output 1 = anchor, output 2 = OP_RETURN containing an arbitrary registered operator's `xonly_pk` instead of the operator who was actually handed the off-chain triple. They sign the extra inputs themselves and broadcast. Because `user_sig`'s SIGHASH_SINGLE|ANYONECANPAY commitment never touches output 2, this transaction is fully valid and confirms. `update_finalized_payouts` then records the named (unrelated) operator as the payer for this withdrawal, and that operator's automated flow claims the deposit's escrowed reimbursement it never funded.

Existing guards do not catch this: `SECP.verify_schnorr` in `Operator::withdraw` only proves the user authorized *this specific tx shape at index 0/output 0* — it says nothing about output 2. `update_finalized_payouts` has no additional authentication of the OP_RETURN payload against a registered signer set or against the source of the tx's other inputs.

### Impact Explanation
This breaks the "operator reimbursed for a payout it never funded" binding explicitly listed as Critical. The deposit's escrowed `DepositInMove` bridge_amount BTC (real bridge collateral) is paid out via the Reimburse transaction to whichever registered operator's `xonly_pk` bytes the attacker chose to place in the OP_RETURN, independent of which party's wallet actually funded the withdrawal's output. This is repeatable for every withdrawal the attacker (as withdrawer) initiates, and can target any currently-registered operator's `xonly_pk` (which are public), consuming that operator's kickoff/round connector and causing bridge escrow to be disbursed to a party unconnected to the actual funding of that specific payout, corrupting the protocol's payer-attribution invariant across arbitrary deposits/operators.

### Likelihood Explanation
No privileged access is required. The attacker only needs to be a normal user who deposits, calls Citrea's `withdraw`, and produces the mandatory `SinglePlusAnyoneCanPay` signature over their own withdrawal — data that is already in their possession by protocol design. They only need enough BTC to fund the payout's output amount plus fees (the same amount they will receive back at output 0, since it's their own withdrawal), and knowledge of any registered operator's public `xonly_pk` (public information). No collusion, key compromise, or majority hashrate is needed; this is directly reachable and reproducible with a plain `cargo test` invoking `create_payout_txhandler` with a legitimately-signed triple and a mismatched `operator_xonly_pk`.

### Recommendation
Bind `operator_xonly_pk` to something the user's signature (or an equally authenticated channel) actually commits to — e.g., require the user to sign (or the Citrea contract to commit) the intended operator identity as part of the withdrawal request, use `SIGHASH_ALL` (or `SIGHASH_ALL|ANYONECANPAY`, still covering all outputs) instead of `SIGHASH_SINGLE|ANYONECANPAY` for the OP_RETURN-bearing output, or otherwise have `update_finalized_payouts`/`handle_finalized_payout` cross-check that the operator named in the OP_RETURN is the one whose wallet actually supplied the additional funding inputs (e.g., by requiring the extra inputs to be spendable only by that operator's known collateral/reimbursement key).

```rust
#[test]
fn poc_operator_xonly_pk_not_committed_by_single_anyonecanpay_sig() {
    // 1. Build input_utxo/output_txout and sign with the withdrawing user's key
    //    using SinglePlusAnyoneCanPay, exactly as generate_withdrawal_transaction_and_signature does.
    let (input_utxo, output_txout, user_sig) = /* legitimately generated triple */;

    // 2. Build Payout tx naming the "intended" operator A.
    let tx_a = create_payout_txhandler(
        input_utxo.clone(), output_txout.clone(), operator_a_xonly_pk, user_sig, network,
    ).unwrap();

    // 3. Build a second Payout tx with the SAME triple but an unrelated operator B.
    let tx_b = create_payout_txhandler(
        input_utxo, output_txout, operator_b_xonly_pk, user_sig, network,
    ).unwrap();

    // Assert: both tx_a and tx_b's input-0 witness passes SECP.verify_schnorr against
    // user_xonly_pk (i.e. tx_b is just as valid as tx_a despite naming a different operator),
    // proving operator_xonly_pk is uncommitted by user_sig.
    let sighash_a = tx_a.calculate_sighash_txin(0, user_sig.sighash_type).unwrap();
    let sighash_b = tx_b.calculate_sighash_txin(0, user_sig.sighash_type).unwrap();
    assert_eq!(sighash_a, sighash_b); // <-- proves OP_RETURN change doesn't affect sighash
    SECP.verify_schnorr(&user_sig.signature, &Message::from_digest(*sighash_b.as_byte_array()), &user_xonly_pk).unwrap();

    // 4. Confirm OP_RETURN parsing in update_finalized_payouts would record operator_b_xonly_pk
    //    for this withdrawal, matching the binding violation: payer recorded (B) != actual funder (attacker/user).
}
```
This demonstrates, with no mainnet and no live Citrea, that `operator_xonly_pk` in `create_payout_txhandler` is entirely uncommitted by `user_sig`, and thus can be freely reassigned by anyone possessing a valid `(input_utxo, output_txout, user_sig)` triple, breaking the caller-authority/attribution binding relied on by `update_finalized_payouts` and downstream reimbursement.

```rust
pub fn create_payout_txhandler(
    input_utxo: UTXO,
    output_txout: TxOut,
    operator_xonly_pk: XOnlyPublicKey,
    user_sig: taproot::Signature,
    _network: bitcoin::Network,
) -> Result<TxHandler<Signed>, BridgeError> {
    let txin = SpendableTxIn::new_partial(input_utxo.outpoint, input_utxo.txout);

    let output_txout = UnspentTxOut::from_partial(output_txout.clone());

    let op_return_txout = op_return_txout(PushBytesBuf::from(operator_xonly_pk.serialize()));

    let mut txhandler = TxHandlerBuilder::new(TransactionType::Payout)
        .with_version(NON_STANDARD_V3)
        .add_input(
            NormalSignatureKind::NotStored,
            txin,
            SpendPath::KeySpend,
            DEFAULT_SEQUENCE,
        )
        .add_output(output_txout)
        .add_output(UnspentTxOut::from_partial(anchor_output(
            NON_EPHEMERAL_ANCHOR_AMOUNT,
        )))
        .add_output(UnspentTxOut::from_partial(op_return_txout))
        .finalize();
    txhandler.set_p2tr_key_spend_witness(&user_sig, 0)?;
    txhandler.promote()
}
```
