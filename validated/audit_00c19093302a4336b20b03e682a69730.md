### Title
Spoofed `WWW-Authenticate: realm="GitHub"` header from an untrusted git remote forces a GitHub-Enterprise sign-in prompt bound to the attacker's host - (File: `app/src/lib/trampoline/trampoline-credential-helper.ts`)

### Summary

### Finding Description
`getEndpointKind` is used by GitHub Desktop's git credential helper trampoline to decide how to treat a remote host during authentication. Before doing any real verification of the remote, it inspects the `wwwauth[...]` credential fields that Git forwards from the server's `WWW-Authenticate` response header, and short-circuits based on the `realm` value: [2](#0-1) 

If the attacker-controlled remote returns `WWW-Authenticate: Basic realm="GitHub"`, the function immediately returns `'enterprise'` — without falling through to the actual authenticated check `isGitHubHost(endpoint)`, which would otherwise make a real API request to verify the host is genuinely a GitHub Enterprise Server [3](#0-2) .

That classification is then used in `getCredential`: since the endpoint is not in the accounts store, Desktop calls `ui.promptForGitHubSignIn(endpoint)` [4](#0-3) .

`promptForGitHubSignIn` inspects the hostname; since it is not `github.com`, it invokes `beginEnterpriseSignIn` and `setSignInEndpoint(origin)` **using the attacker's own origin** as the Enterprise sign-in target, then shows the standard sign-in popup: [5](#0-4) .

This means the “realm” value from an untrusted server response fully controls which sign-in flow (and which target origin) the user is shown, bypassing the intended verification step (`isGitHubHost`) that would otherwise make a genuine API call to confirm the server is actually GitHub-compatible.

### Impact Explanation
A malicious or compromised git server can trigger this simply by responding to Git's authentication probe with a crafted `WWW-Authenticate` header claiming `realm="GitHub"`. This causes GitHub Desktop to present the user with what looks like a legitimate "Sign in to GitHub Enterprise" dialog, but the underlying sign-in endpoint (`origin`) is set to the attacker's host. If the user completes basic authentication in that flow, their entered credentials/PAT would be transmitted to the attacker-controlled endpoint rather than a legitimate GitHub Enterprise Server, resulting in credential theft. This qualifies under the program's valid impact category of "credential/token exfiltration" caused by an attacker-controlled git remote response.

### Likelihood Explanation
Exploitation requires only that the attacker control the git remote/proxy response (in-scope) and the user attempt a normal clone/fetch/push against that remote — no admin rights, malware, or unnatural steps are required beyond the user completing the resulting sign-in prompt, which is the *expected* flow for authenticating against an unfamiliar GHE-like host. The condition is a simple one-line header value the attacker fully controls, which is a low bar to trigger.

### Recommendation
Do not let a self-reported `WWW-Authenticate: realm="GitHub"` header alone elevate an unknown host to `'enterprise'` status and drive an Enterprise sign-in flow that binds to that host's origin. At minimum, require it to be corroborated by the actual `isGitHubHost(endpoint)` API-based check (or an explicit user confirmation showing the real hostname) before initiating `beginEnterpriseSignIn`/`setSignInEndpoint` against an unverified origin.

### Proof of Concept
1. Stand up a git-over-HTTPS server that, when Git requests credentials, responds with `WWW-Authenticate: Basic realm="GitHub"`.
2. In GitHub Desktop, clone or add this remote and initiate a fetch/push that requires authentication.
3. Observe that `getEndpointKind` returns `'enterprise'` purely from the spoofed header [6](#0-5) , and Desktop shows an "Sign in to GitHub Enterprise" dialog with `setSignInEndpoint(origin)` pointed at the attacker's server [7](#0-6) .
4. If a user completes basic-auth sign-in in that dialog, their credentials are sent to the attacker-controlled server.

**Caveat / uncertainty:** I was unable to fully trace, within the available tool budget, exactly which network call `beginEnterpriseSignIn`/`SignInStore` performs when basic-auth credentials are submitted in this flow (e.g., whether it always calls a `/user` or OAuth endpoint at the attacker origin, or whether there is additional origin validation further down in `sign-in-store.ts`/`app-store.ts`). Confirming the exact credential-submission request is recommended before treating this as fully verified end-to-end.

const getEndpointKind = async (cred: Credential, store: Store) => {
  const credentialUrl = getCredentialUrl(cred)
  const endpoint = `${credentialUrl}`

  if (isGist(endpoint)) {
    return 'generic'
  }

  if (isDotCom(endpoint)) {
    return 'github.com'
  }

  if (isGHE(endpoint)) {
    return 'ghe.com'
  }

  // When Git attempts to authenticate with a host it captures any
  // WWW-Authenticate headers and forwards them to the credential helper. We
  // use them as a happy-path to determine if the host is a GitHub host without
  // having to resort to making a request ourselves.
  for (const [k, v] of cred.entries()) {
    if (k.startsWith('wwwauth[')) {
      if (v.includes('realm="GitHub"')) {
        return 'enterprise'
      } else if (/realm="(GitLab|Gitea|Atlassian Bitbucket)"/.test(v)) {
        return 'generic'
      }
    }
  }

  const existingAccount = await findGitHubTrampolineAccount(store, endpoint)
  if (existingAccount) {
    return isDotCom(existingAccount.endpoint) ? 'github.com' : 'enterprise'
  }

  // All GitHub hosts use HTTPS, so if the protocol is not HTTPS we can
  // assume that this is not a GitHub host.
  if (credentialUrl.protocol !== 'https:') {
    return 'generic'
  }

  return (await isGitHubHost(endpoint)) ? 'enterprise' : 'generic'
}

  public promptForGitHubSignIn(endpoint: string): Promise<Account | undefined> {
    return new Promise<Account | undefined>(async resolve => {
      const cb = (result: SignInResult) => {
        resolve(result.kind === 'success' ? result.account : undefined)
        this.dispatcher.closePopup(PopupType.SignIn)
      }

      const { hostname, origin } = new URL(endpoint)
      if (hostname === 'github.com') {
        this.dispatcher.beginDotComSignIn(cb)
      } else {
        this.dispatcher.beginEnterpriseSignIn(cb)
        await this.dispatcher.setSignInEndpoint(origin)
      }

      this.dispatcher.showPopup({
        type: PopupType.SignIn,
        isCredentialHelperSignIn: true,
        credentialHelperUrl: endpoint,
      })
