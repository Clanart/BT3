### Title
Unbounded buffer indexing in CLVM canonical-encoding check causes attacker-triggered `IndexError` during mempool admission - (File: `chia/full_node/mempool_manager.py`)

### Summary
`is_atom_canonical()` / `is_clvm_canonical()` in `chia/full_node/mempool_manager.py` parse an attacker-supplied CLVM byte buffer (a spend bundle's puzzle reveal / solution) without validating that the multi-byte atom length prefix actually stays within the buffer bounds before indexing into it. This mirrors the CVE-2023-0798 bug class: a length/size field taken from crafted input is used to walk a buffer without a bounds check, producing an out-of-range read on crafted input.

### Finding Description
`is_atom_canonical(clvm_buffer, offset)` determines the length-prefix size (`prefix_len`, up to 5 extra bytes) from the leading byte, then loops: [1](#0-0) 
reading `clvm_buffer[offset]` for each of the `prefix_len` iterations without ever checking whether `offset` is still less than `len(clvm_buffer)`. `is_clvm_canonical()`, its only caller, likewise advances `offset` and re-indexes `clvm_buffer[offset]` on each loop iteration with no bounds check against the buffer length until after the atom is consumed: [2](#0-1) 

By contrast, other buffer-walking parsers reachable from network/mempool input in this codebase (e.g. `skip_bytes`, `skip_list` in `chia/full_node/full_block_utils.py`) explicitly check remaining buffer length before indexing and raise a `ValueError` with a descriptive message: [3](#0-2) 
`is_atom_canonical`/`is_clvm_canonical` lack this defensive pattern. A crafted puzzle reveal or solution byte string that ends exactly at (or truncates) a multi-byte atom length-prefix header — analogous to a crafted TIFF whose crop parameters run past the actual image buffer in the `tiffcrop.c:3400` CVE — causes Python bytes indexing (`clvm_buffer[offset]`) to raise an unhandled `IndexError` once `offset >= len(clvm_buffer)`.

### Impact Explanation
This function is invoked during mempool admission of untrusted, attacker-controlled spend bundle CLVM buffers (part of the `pre_validate_spendbundle()` canonical-serialization check path documented in `.cursor/context/clvm-execution.md`). An uncaught `IndexError` raised mid-parse during spend bundle admission is a crash triggered purely by a single submitted spend bundle, i.e. a spend-triggered exception in mempool/transaction-processing code — the strongest reachable impact category listed in scope (transaction-processing halt) for this bug class, without requiring a malicious peer, node, or any privileged access.

### Likelihood Explanation
Likelihood is bounded by uncertainty over exactly how far up the call stack this exception is caught (whether `pre_validate_spendbundle()` or its caller wraps this specific parsing call in a broad `try/except`). If uncaught at the point where per-spend-bundle validation happens (as is typical for exceptions raised inside worker/thread-pool tasks), it can fail that validation task or propagate unexpectedly; if a general exception handler exists further up, impact is limited to a failed/rejected spend bundle rather than a broader halt. This uncertainty could not be fully resolved with the available context/tool budget.

### Recommendation
Add explicit remaining-length checks in `is_atom_canonical()` before each `clvm_buffer[offset]` access (mirroring the `skip_bytes`/`skip_list` pattern in `full_block_utils.py`), returning a definitive non-canonical/invalid result (or raising a caught, well-defined validation error) instead of allowing Python to raise an `IndexError` on truncated/crafted length-prefix headers. Add a Mempool test with a CLVM buffer whose multi-byte atom length prefix runs past the end of the buffer.

### Proof of Concept
Craft a CLVM buffer that ends immediately after a byte announcing a multi-byte atom length prefix, e.g. `bytes([0b11111100])` (5-byte length-prefix marker, `0xFC`) with no following bytes, and pass it to `is_clvm_canonical()`:
```python
from chia.full_node.mempool_manager import is_clvm_canonical
is_clvm_canonical(bytes([0xFC]))  # raises IndexError instead of returning False
```
Embedding such a buffer as a coin spend's puzzle reveal or solution in a submitted `SpendBundle` reaches this code path during mempool admission's canonical-serialization check.

def skip_bytes(buf: memoryview) -> memoryview:
    if len(buf) < 4:
        raise ValueError(f"byte length prefix requires 4 bytes, remaining buffer {len(buf)}")
    n = int.from_bytes(buf[:4], "big", signed=False)
    buf = buf[4:]
    if n > len(buf):
        raise ValueError(f"byte length {n} exceeds remaining buffer {len(buf)}")
    return buf[n:]
