## Analog Found [1](#0-0) 

### Title
Trusted `safe.directory` Git config entries are never revoked when a repository is removed, allowing permanent ownership-check bypass for a reused path - (File: `app/src/lib/git/config.ts`)

### Summary
When GitHub Desktop detects a repository with "dubious ownership" (owned by a different user than the current process), it shows a "Trust Repository" prompt. Accepting it calls `addSafeDirectory`, which permanently appends the path to the **global** `git config --global safe.directory` list [2](#0-1) . This call is exercised from `AddExistingRepository.onTrustDirectory` and `MissingRepository.onTrustDirectory` [3](#0-2) [4](#0-3) . There is no corresponding `removeSafeDirectory`/revoke path anywhere in the codebase — a grep across the repo shows only `addSafeDirectory` usages and no removal counterpart. When a repository is later removed from Desktop, `RepositoriesStore.removeRepository` only deletes the DB record and clears push tags; it never touches the `safe.directory` config [5](#0-4) , and `AppStore._removeRepository` likewise only moves the folder to trash and removes the DB entry [6](#0-5) .

### Finding Description
This is the same missing-revocation pattern as the Palmera `removeWholeTree` bug: a "trust"/permission grant (`disableSafeLeadRoles` for the root safe vs. `safe.directory` trust for a repo path) is established for an entity, but the corresponding disable/removal step is skipped when that entity is torn down. Here, the trust grant is a Git ownership bypass recorded in the **global**, machine-wide gitconfig, keyed only by filesystem path — not by repository identity, commit, or owner fingerprint. Once granted via `addSafeDirectory`, `getRepositoryType` will always return `{ kind: 'regular' }` for that path instead of `{ kind: 'unsafe' }` [7](#0-6) , permanently suppressing the "appears to be owned by another user... may automatically execute files" warning shown in `add-existing-repository.tsx` and `missing-repository.tsx`.

Because the grant is never revoked on repository removal (or on path relocation/deletion), the trust binding outlives the repository object it was created for. On a shared machine, or any path an attacker can later repopulate (temp directories, shared mount points, network shares, path reused after deletion), an attacker who once had the path flagged "unsafe" and had a legitimate user click "Trust Repository" can — after the user removes/deletes that repository in Desktop — recreate a malicious Git repository at the exact same path. Git will no longer perform the ownership check for that path, and Desktop's `getRepositoryType`/`AddExistingRepository`/`MissingRepository` flows will silently treat it as a normal, safe repository.

### Impact Explanation
Git's `safe.directory` ownership check exists specifically to stop automatic execution of repository-controlled content (hooks, `core.fsmonitor`, filters, `include.path` directives, etc.) when the repo is not verifiably owned by the current user. A permanently-stuck trust grant defeats this protection for that path indefinitely, re-enabling the exact "may automatically execute files in the repository" scenario the warning dialog itself describes, whenever an attacker regains control of a previously-trusted path.

### Likelihood Explanation
Requires: (1) a shared or multi-tenant environment (common for CI runners, shared dev boxes, `/tmp`, mapped/shared drives), (2) a legitimate one-time "Trust Repository" click by a user on a path not owned by them, and (3) later removal of that repository in Desktop without the path itself being scrubbed of the global config entry. Given `addSafeDirectory` is a one-way, path-keyed operation with no lifecycle tie to the Desktop repository record, this can occur without any unusual or unnatural user action beyond the normal add/trust/remove workflow.

### Recommendation
Call a new `removeSafeDirectory(path)` (using the existing `removeGlobalConfigValue`/`--unset-all` machinery already present for other config values [8](#0-7) ) whenever a repository is removed via `RepositoriesStore.removeRepository` or relocated away from a previously-trusted unsafe path, so the `safe.directory` grant does not outlive the repository it was created to unblock.

### Proof of Concept
1. On a shared machine, place a directory `D` owned by attacker; a Git repo lives there.
2. Victim opens `D` in Desktop via "Add Existing Repository"; Desktop reports it "unsafe" (`getRepositoryType` returns `kind: 'unsafe'`) [9](#0-8) .
3. Victim clicks "Trust Repository" → `onTrustDirectory` → `addSafeDirectory(D)` permanently adds `D` to the victim's global `safe.directory` list [3](#0-2) .
4. Victim later removes the repository from Desktop (`_removeRepository`) — no config cleanup occurs [6](#0-5) .
5. Attacker deletes and recreates a new malicious Git repository at the same path `D` (e.g., with a malicious `core.hooksPath`/hook script).
6. Victim re-adds/rescans `D` in Desktop; `getRepositoryType` returns `kind: 'regular'` (ownership check bypassed by the stale `safe.directory` entry), no warning is shown, and Desktop/Git operate on the attacker-controlled repository as trusted.

/**
 * Adds a path to the `safe.directories` configuration variable if it's not
 * already present. Adding a path to `safe.directory` will cause Git to ignore
 * if the path is owner by a different user than the current.
 */
export async function addSafeDirectory(path: string) {
  // UNC-paths on Windows need to be prefixed with `%(prefix)/`, see
  // https://github.com/git-for-windows/git/commit/e394a16023cbb62784e380f70ad8a833fb960d68
  if (__WIN32__ && path[0] === '/') {
    path = `%(prefix)/${path}`
  }

  await addGlobalConfigValueIfMissing('safe.directory', path)
}

/**
 * Remove config value by name
 *
 * @param path The path to execute the `git` command in. If null
 *             we'll use the global configuration (i.e. --global)
 *             and execute the Git call from the same location that
 *             GitHub Desktop is installed in.
 */
async function removeConfigValueInPath(
  name: string,
  path: string | null,
  env?: {
    HOME: string
  }
): Promise<void> {
  const options = env ? { env } : undefined

  const flags = ['config']

  if (!path) {
    flags.push('--global')
  }

  flags.push('--unset-all', name)

  await git(flags, path || __dirname, 'removeConfigValueInPath', options)
}

export async function getRepositoryType(path: string): Promise<RepositoryType> {
  if (!(await directoryExists(path))) {
    return { kind: 'missing' }
  }

  try {
    const result = await git(
      ['rev-parse', '--is-bare-repository', '--show-cdup', '--git-dir'],
      path,
      'getRepositoryType',
      { successExitCodes: new Set([0, 128]) }
    )

    if (result.exitCode === 0) {
      // Bare repositories will not include gitdir so we handle that separately
      if (result.stdout.startsWith('true\n')) {
        return { kind: 'bare' }
      }

      // --is-bare-repository and --show-cdup each produce a single line but
      // --git-dir could theoretically contain newlines so we parse the known
      // fields first and treat the remainder as the git dir. We use [\s\S]*
      // instead of .* for the git dir capture group because .* doesn't match
      // newlines whereas [\s\S]* matches any character including newlines.
      const match = result.stdout.match(/^(true|false)\n(.*)\n([\s\S]*)\n$/)

      if (match) {
        const [, isBare, cdup, gitDir] = match

        return isBare === 'true'
          ? { kind: 'bare' }
          : {
              kind: 'regular',
              topLevelWorkingDirectory: resolve(path, cdup),
              gitDir: resolve(path, gitDir),
            }
      }
    }

    const unsafeMatch =
      /fatal: detected dubious ownership in repository at '(.+)'/.exec(
        result.stderr
      )
    if (unsafeMatch) {
      return { kind: 'unsafe', path: unsafeMatch[1] }
    }

    return { kind: 'missing' }
