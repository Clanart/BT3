### Title
Unsynchronized concurrent mutation of shared `MemNode.hash` cache between a live `Tree` and its `Copy()` diverges query proofs/AppHash - (File: sei-db/state_db/sc/memiavl/tree.go)

### Summary
`Tree.Copy()` hands out a snapshot that shares its `MemNode` objects by reference with the live tree, and gives the copy its own, independent `*sync.RWMutex`. [1](#0-0)  `RootHash()` and `GetProof()` take the write lock *of the tree instance they are called on* specifically because `Node.Hash()`/`SafeHash()` lazily fills `MemNode.hash` in place, and the code explicitly documents that this in-place mutation must be serialized to avoid an earlier race (Immunefi 83246/STO-601). [2](#0-1) [3](#0-2)  That per-instance lock, however, only protects a single `Tree` struct's own mutex; a `Copy()`'d tree gets a *different* mutex while still pointing at the same underlying `MemNode` objects. [4](#0-3)  The repository's own test explicitly documents this as an open, unresolved hole. [5](#0-4) 

### Finding Description
This is a direct structural analog of CVE-2016-2069: a shared in-memory data structure (there, a CPU paging structure; here, the `MemNode.hash` cache reachable from `Tree.root`) is mutated by two independent execution contexts (there, two CPUs; here, the live `Tree` goroutine and a `Copy()`'d `Tree` goroutine) without a lock that actually covers both, because each context believes it holds sufficient synchronization (a paging-structure lock / this tree's own `mtx`) while the other context is a distinct entity operating on the same underlying memory.

Concretely:
- `Tree.Copy()`/`copyNoLock()` snapshots `t.root`'s reachable `MemNode`s and freezes them at `cowVersion` so that subsequent `Set`/`Remove` clone-on-write instead of mutating in place — but this only protects the node's *content* fields (key/value/children), not the `hash` field, which is filled lazily and in place by `Hash()`/`SafeHash()` outside of `setRecursive`/`removeRecursive`. [6](#0-5) 
- `RootHash()` and `GetProof()` on the *live* tree acquire `t.mtx` (the live tree's mutex) and then mutate `MemNode.hash` in place via `SafeHash()`/`Node.Hash()`. [7](#0-6) [8](#0-7) 
- `RootHash()`/`GetProof()`/`Get()` on the *copy* acquire `newTree.mtx` (a brand-new, independent mutex created in `copyNoLock`) and mutate the very same shared `MemNode.hash` fields, since the copy holds the same node pointers. [9](#0-8) 
- Because the two mutexes never synchronize with each other, concurrent calls from the live tree and the copy race on the same memory location (`MemNode.hash`), which is a classic unsynchronized-write data race — exactly the CVE-2016-2069 pattern of "access to a [shared] structure by a different [execution context]."

The maintainers' own test, `TestCopyReadRaceWithLiveCommits`, names this exact scenario ("the cross-copy hole that the per-tree write lock does not close ... one lock away from the fix for it") and reproduces it by driving `leased.RootHash()`/`leased.Get()`/`leased.GetProof()` on a `Copy()` concurrently with `tree.ApplyChangeSet`/`tree.SaveVersion(true)` on the live tree. [10](#0-9)  The comment states the practical trigger is the production trace-snapshot path: `SnapshotSCStore` hands `EndBlock` a `DB.Copy()` after `ApplyChangeSets` has released `db.mtx`, so the copy can share nodes stamped at `version+1` that the freeze floor leaves mutable relative to further commits. [11](#0-10) 

`CommitStore.Copy()` — the production entry point wired to `types.Committer.Copy()` and used for `GetProof`/`Get`/`Iterator` on a snapshot — is documented to be "an O(1) memiavl snapshot; COW nodes are shared with the live store," confirming the sharing described above is exactly what happens in the running node, not just in a synthetic test. [12](#0-11)  `CommitStore.GetProof` reaches straight into the per-tree `GetProof`. [13](#0-12) 

### Impact Explanation
A public RPC client can request an ABCI `Query` with `Prove: true` (or any read routed through `GetProof`/`RootHash` on a store `Copy()`) at the same time consensus is committing new blocks on the live tree. Under this race:
- The lazily filled `MemNode.hash` field can be torn or read/written non-atomically from two goroutines with no shared lock, corrupting the cached internal hash.
- A corrupted internal hash can propagate into a subsequently-computed root hash (`AppHash`) if the corrupted node is later reused/serialized, or it can produce a stale/incorrect membership/non-membership proof returned to the RPC client.
- Because different nodes' scheduling of concurrent readers/writers is non-deterministic, one node can derive a different `AppHash` from another for the same block, which is a permanent chain-split risk — the exact class of impact this task accepts ("permanent chain split").

This is squarely a memory-safety/race-condition bug class matching CVE-2016-2069, reachable from ordinary RPC query traffic without any special privilege, and affecting the correctness of committed/queryable chain state.

### Likelihood Explanation
Likelihood is high in terms of reachability (any RPC client issuing `abci_query` with `prove=true`, or any consumer of `Copy()`-based snapshot proofs, races with ordinary block commits, both of which happen continuously on a running node) but the actual data corruption is probabilistic — it depends on `go`'s memory model exposing a torn read/write on the `hash` field, which is difficult to trigger deterministically without `-race` instrumentation, though it is confirmed to be a genuine, currently-open data race by the project's own test comments describing it as unresolved ("one lock away from the fix for it"). [5](#0-4) 

### Recommendation
Make hash-cache mutation safe across `Copy()` boundaries, not just within a single `Tree` instance. Options:
1. Share a single `mtx` (or a coarser lock covering both the live tree and any live copies) between a `Tree` and every `Copy()` derived from it until the copy is closed, so `RootHash`/`GetProof`/`Hash()` on either side serialize against each other.
2. Alternatively, eagerly compute and freeze `MemNode.hash` for every reachable node at `Copy()` time (extending what `copyNoLock` already does for `cowVersion`), so no lazy fill can occur after the copy is handed out — this removes the need for cross-instance locking entirely, since frozen nodes would never have their `hash` field written again.
3. Add `-race`-covered CI gating on `TestCopyReadRaceWithLiveCommits` (already present) to actually fail the build until the fix lands, since the current test only fails under `-race` and it's unclear the project runs it that way in CI.

### Proof of Concept
The existing repository test `TestCopyReadRaceWithLiveCommits` in `sei-db/state_db/sc/memiavl/tree_race_test.go` is a working PoC: run `go test -race -run TestCopyReadRaceWithLiveCommits ./sei-db/state_db/sc/memiavl/...`. It drives `tree.Copy()`, then concurrently calls `leased.RootHash()/Get()/GetProof()` on the copy while the live `tree` keeps calling `ApplyChangeSet`+`SaveVersion(true)` (which internally calls `RootHash`). [14](#0-13)  Under `-race`, this reproduces the unsynchronized concurrent access to shared `MemNode.hash` fields between the live tree and its copy.

func (t *Tree) Copy() *Tree {
	t.mtx.Lock()
	defer t.mtx.Unlock()
	return t.copyNoLock()
}

// copyNoLock is Copy without acquiring t.mtx; the caller must already hold the
// write lock.
func (t *Tree) copyNoLock() *Tree {
	// Hash every reachable node now, while we hold the write lock. Otherwise the
	// copy's reader fills MemNode.hash in place on nodes the live tree also
	// holds, and the two trees have separate mutexes to serialize with.
	_ = t.rootHashNoLock()

	if _, ok := t.root.(*MemNode); ok {
		// Freeze the shared MemNodes against in-place mutation. The floor is the
		// highest version present in the tree, not t.version: Set and Remove
		// stamp nodes at t.version+1, so between a changeset and SaveVersion the
		// tree holds nodes a t.version floor would leave mutable.
		t.cowVersion = t.maxNodeVersion()
	}

	newTree := *t
	newTree.mtx = &sync.RWMutex{}
	// The copy is read-only and must not share the live tree's background-write
	// plumbing: Close would otherwise close the live tree's pendingChanges.
	newTree.pendingChanges = nil
	newTree.pendingWg = &sync.WaitGroup{}
	if newTree.snapshot != nil {
		newTree.snapshot.Acquire()
	}
	return &newTree
}

// RootHash updates the hashes and return the current root hash,
// it clones the persisted node's bytes, so the returned bytes is safe to retain.
//
// It takes the write lock (not RLock) because Hash() lazily populates
// MemNode.hash in place on the live nodes. Two goroutines mutating that
// shared cache under a read lock — e.g. a commit's RootHash racing a
// latest-height proof query's GetProof — is a data race that can serialize
// a stale internal hash into the store root and diverge the AppHash
// (Immunefi 83246 / STO-601). Callers that already hold t.mtx must use
// rootHashNoLock instead.
func (t *Tree) RootHash() []byte {
	t.mtx.Lock()
	defer t.mtx.Unlock()
	return t.rootHashNoLock()
}

// rootHashNoLock is RootHash without acquiring t.mtx; the caller must already
// hold the write lock.
func (t *Tree) rootHashNoLock() []byte {
	if t.root == nil {
		return emptyHash
	}
	return t.root.SafeHash()
}

// GetProof takes a key for creating existence or absence proof and returns the
// appropriate merkle.Proof. Since this must be called after querying for the value, this function should never error
// Thus, it will panic on error rather than returning it
//
// It takes the write lock for the whole proof build because the traversal
// reads sibling node hashes via Node.Hash(), which lazily populates
// MemNode.hash in place. Holding the write lock serializes that mutation
// against a concurrent commit's RootHash and against Set/Remove, closing the
// AppHash-divergence race (Immunefi 83246 / STO-601). Internally it uses the
// *NoLock helpers to avoid recursively re-acquiring t.mtx.
func (t *Tree) GetProof(key []byte) *ics23.CommitmentProof {
	t.mtx.Lock()
	defer t.mtx.Unlock()
	return t.getProofNoLock(key)
}

// TestCopyReadRaceWithLiveCommits covers the cross-copy hole that the per-tree
// write lock does not close. RootHash and the proof builders take the write lock
// because MemNode.Hash fills the hash cache in place (Immunefi 83246), but Copy
// gives each tree its own mutex, so a copy and the tree it came from serialize
// against nothing. Reading a copy whose nodes the live tree is still free to
// mutate is the same unsynchronized access, one lock away from the fix for it.
//
// This is the trace-snapshot path: SnapshotSCStore hands EndBlock a DB.Copy, and
// ApplyChangeSets has already released db.mtx by then, so the copy can share
// nodes stamped at version+1 that the old cowVersion = t.version floor left
// mutable. Its consequence is a wrong trace or proof rather than a bad snapshot
// file, which is why it is separate from the writer test below.
func TestCopyReadRaceWithLiveCommits(t *testing.T) {
	const (
		rounds           = 4
		blocksPerRound   = 20
		keysPerChangeSet = 200
	)

	tree := seedTree(t, copyTestSeedKeys)

	for round := 0; round < rounds; round++ {
		// Copy mid-version, where DB.Copy lands between ApplyChangeSets and Commit.
		tree.ApplyChangeSet(changeSet(round*53, keysPerChangeSet, fmt.Sprintf("pre%02d", round)))
		leased := tree.Copy()

		var wg sync.WaitGroup
		wg.Add(1)
		go func() {
			defer wg.Done()
			for i := 0; i < blocksPerRound; i++ {
				_ = leased.RootHash()
				_ = leased.Get([]byte(fmt.Sprintf("key%08d", i)))
				_ = leased.GetProof([]byte(fmt.Sprintf("key%08d", i)))
			}
		}()

		_, _, err := tree.SaveVersion(true)
		require.NoError(t, err)
		for block := 0; block < blocksPerRound; block++ {
			tree.ApplyChangeSet(changeSet(block*17, keysPerChangeSet, fmt.Sprintf("r%02db%02d", round, block)))
			_, _, err := tree.SaveVersion(true)
			require.NoError(t, err)
		}
		wg.Wait()
	}
}

	}

func (cs *CommitStore) GetProof(store string, key []byte) (*ics23.CommitmentProof, error) {
	if store == "" {
		return nil, fmt.Errorf("store name cannot be empty")
	}
	if key == nil {
		return nil, fmt.Errorf("key cannot be nil")
	}

	childStore := cs.GetChildStoreByName(store)
	if childStore == nil {
		return nil, nil
	}

	return childStore.GetProof(key), nil
}
