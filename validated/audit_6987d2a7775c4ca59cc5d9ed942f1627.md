### Title
Unauthenticated tx-sender JSON-RPC `send_tx` Allows Arbitrary Transaction Injection and Operator Wallet Drain via CPFP Fee-Payer Creation — (`File: crates/clementine-tx-sender/src/jsonrpc/server.rs`)

---

### Summary

The standalone `clementine-tx-sender` JSON-RPC server exposes `send_tx` (and `send_citrea_tx`) over plain HTTP with **no authentication of any kind**. The server explicitly supports binding to `0.0.0.0`, making it reachable by any network peer. Any attacker who can reach the port can inject arbitrary transactions into the tx-sender broadcast queue with a caller-controlled `FeePayingType`. When `FeePayingType::CPFP` is chosen, the tx-sender automatically calls `create_fee_payer_utxo`, which calls `fund_raw_transaction` and `send_raw_transaction` on the operator's Bitcoin Core wallet, spending real BTC from the operator's wallet for each injected entry. Repeated injection drains the operator's wallet, preventing fee-bumping of legitimate bridge transactions and causing liveness failures that expose operator collateral to slashing.

---

### Finding Description

**Root cause — no authentication on the JSON-RPC server**

`start_jsonrpc_server` in `crates/clementine-tx-sender/src/jsonrpc/server.rs` builds a plain `jsonrpsee` HTTP server with no middleware, no token check, no IP allowlist, and no TLS:

```rust
// crates/clementine-tx-sender/src/jsonrpc/server.rs:46-50
let server: Server = ServerBuilder::default()
    .max_request_body_size(MAX_JSONRPC_REQUEST_BODY_SIZE)
    .build(bind_addr)
    .await
    .map_err(|e| BridgeError::Eyre(e.into()))?;
```

The `send_tx` handler immediately calls `insert_try_to_send` with all caller-supplied fields — including `fee_paying_type`, `cancel_outpoints`, `cancel_txids`, `activate_txids`, and `activate_outpoints` — without any identity check:

```rust
// crates/clementine-tx-sender/src/jsonrpc/server.rs:58-88
module.register_async_method("send_tx", |params, client, _| async move {
    let req: InsertTryToSendParams = params.one().map_err(jsonrpc_err)?;
    ...
    let try_to_send_id = client
        .insert_try_to_send(&mut dbtx, req.tx_metadata, &signed_tx,
            req.fee_paying_type, req.rbf_signing_info,
            &req.cancel_outpoints, &req.cancel_txids,
            &req.activate_txids, &req.activate_outpoints)
        .await.map_err(jsonrpc_err)?;
```

This is in direct contrast to the gRPC servers for verifier and operator, which enforce mTLS with the `OnlyAggregatorAndSelf` interceptor. The tx-sender JSON-RPC has no equivalent guard.

**Network exposure is a supported, documented configuration**

`TxSenderConfig::from_env` explicitly accepts `0.0.0.0` as a valid bind address:

```rust
// crates/clementine-tx-sender/src/config.rs:201-208

    return Err(BridgeError::EnvVarMalformed(...));

```

The Docker Compose files and `.env.example` confirm this is a production-facing option.

**CPFP injection drains the operator's Bitcoin wallet**

When the attacker injects a transaction with `FeePayingType::CPFP` and a P2A anchor output (`51024e73`), the tx-sender's loop calls `send_cpfp_tx`. Because no fee-payer UTXOs exist for the freshly injected entry, it falls through to `create_fee_payer_utxo`:

```rust
// crates/clementine-tx-sender/src/cpfp.rs:195-254
let fee_payer_tx = Transaction { ... output: vec![TxOut { value: new_fee_payer_amount,
    script_pubkey: self.signer.address().script_pubkey() }] };
let funded_fee_payer_tx = self.rpc.fund_raw_transaction(&fee_payer_bytes, ...).await...;
let signed_fee_payer_tx = self.rpc.sign_raw_transaction_with_wallet(...).await...;
self.rpc.send_raw_transaction(&signed_fee_payer_tx).await...;
self.db.save_fee_payer_tx(dbtx, bumped_id, ...).await...;
```

`fund_raw_transaction` selects UTXOs from the Bitcoin Core wallet and `send_raw_transaction` broadcasts the fee-payer transaction, permanently spending wallet funds. The fee-payer UTXO is then linked to the injected `try_to_send_id` in the database and is not reused for legitimate bridge transactions. Each injected CPFP entry causes one wallet spend. The attacker can repeat this in a tight loop.

**cancel_txids can suppress legitimate bridge transactions**

The attacker can also inject a valid self-funded transaction (spending their own UTXOs) with `cancel_txids` set to the txids of queued bridge transactions (e.g., a pending challenge or payout). If the attacker's transaction confirms, the tx-sender marks those bridge txids as cancelled and stops broadcasting them.

---

### Impact Explanation

| Impact | Mechanism |
|---|---|
| **Operator wallet drain** | Each CPFP-injected entry triggers `create_fee_payer_utxo` → `fund_raw_transaction` + `send_raw_transaction`, spending real BTC from the operator's Bitcoin Core wallet. |
| **Fee-payer UTXO exhaustion** | Drained wallet prevents the tx-sender from fee-bumping legitimate bridge transactions (kickoff, challenge, payout, reimbursement). |
| **Liveness failure / slashable exposure** | If challenge or assert-timeout transactions cannot be fee-bumped and miss their on-chain windows, the operator loses collateral. |
| **Queue cancellation** | Attacker-controlled `cancel_txids` can suppress queued bridge transactions once the attacker's own transaction confirms. |

---

### Likelihood Explanation

- The server explicitly supports `0.0.0.0` binding; any deployment that exposes the tx-sender port (e.g., in a Docker network or cloud VM) is immediately reachable.
- No credentials, certificates, or prior knowledge of bridge state are required — a single HTTP POST suffices.
- The attack is trivially scriptable and can be sustained indefinitely.

---

### Recommendation

1. **Add authentication to the JSON-RPC server.** At minimum, require a shared secret (Bearer token or HTTP Basic Auth) validated in a request middleware before any method dispatch. Ideally, restrict the bind address to `127.0.0.1` by default and document that `0.0.0.0` requires a firewall rule.
2. **Restrict `FeePayingType` accepted via the external RPC.** The JSON-RPC endpoint should not accept `CPFP` from external callers, or should require the caller to pre-fund the fee-payer UTXO themselves.
3. **Validate `cancel_txids` / `cancel_outpoints`** against a whitelist of known bridge transaction IDs before persisting them.

    async fn create_fee_payer_utxo(
        &self,
        bumped_id: u32,
        dbtx: Option<&mut TxSenderTransaction>,
        tx: &Transaction,
        fee_rate: FeeRateKvb,
        total_fee_payer_amount: Amount,
        fee_payer_utxos_len: usize,
    ) -> Result<()> {
        tracing::debug!(
            "Creating fee payer UTXO for txid {} with bump id {}",
            &tx.compute_txid().to_string(),
            bumped_id
        );
        let required_fee = Self::calculate_required_fee(
            tx.weight(),
            fee_payer_utxos_len + 1,
            fee_rate,
            FeePayingType::CPFP,
        )?;

        // Aggressively add 2x required fee to the total amount to account for sudden spikes
        // We won't actually use 2x fees, but the fee payer utxo will hold that much amount so that while fee payer utxo gets mined
        // if fees increase the utxo should still be sufficient to fund the tx with high probability
        // leftover fees will get sent back to wallet with a change output in fn create_child_tx
        let new_total_fee_needed = required_fee
            .checked_mul(2)
            .and_then(|fee| fee.checked_add(MIN_TAPROOT_AMOUNT));
        if new_total_fee_needed.is_none() {
            return Err(eyre!("Total fee needed is too large, required fee: {}, total fee payer amount: {}, fee rate: {}", required_fee, total_fee_payer_amount, fee_rate).into());
        }
        let new_fee_payer_amount =
            new_total_fee_needed.and_then(|fee| fee.checked_sub(total_fee_payer_amount));

        let new_fee_payer_amount = match new_fee_payer_amount {
            Some(fee) => fee,
            // if underflow, no new fee payer utxo is needed, log it anyway in case its a bug
            None => {
                tracing::debug!("create_fee_payer_utxo was called but no new fee payer utxo is needed for tx: {:?}, required fee: {}, total fee payer amount: {}, current fee rate: {}", tx, required_fee, total_fee_payer_amount, fee_rate);
                return Ok(());
            }
        };

        tracing::debug!(
            "Creating fee payer UTXO with amount {} ({} sat/kvB)",
            new_fee_payer_amount,
            fee_rate
        );

        let fee_payer_tx = Transaction {
            version: Version::TWO,
            lock_time: LockTime::ZERO,
            input: vec![],
            output: vec![TxOut {
                value: new_fee_payer_amount,
                script_pubkey: self.signer.address().script_pubkey(),
            }],
        };

        let fee_payer_bytes = crate::serialize_tx_for_fund_raw(&fee_payer_tx);

        let funded_fee_payer_tx = self
            .rpc
            .fund_raw_transaction(
                &fee_payer_bytes,
                Some(&FundRawTransactionOptions {
                    add_inputs: Some(true),
                    // for cpfp txs, the speed of tx inclusion is not that important, so we can not use unsafe utxos and wait for them to become safe. Also all cpfp fee payer tx's are safe (all wallet owned inputs), so wallet can already chain them
                    include_unsafe: Some(self.include_unsafe),
                    change_address: None,
                    change_position: None,
                    change_type: None,
                    include_watching: None,
                    lock_unspents: None,
                    fee_rate: Some(Amount::from_sat(fee_rate.to_sat_per_kvb())),
                    subtract_fee_from_outputs: None,
                    replaceable: Some(true),
                    conf_target: None,
                    estimate_mode: None,
                }),
                None,
            )
            .await
            .wrap_err("Failed to fund cpfp fee payer tx")?
            .hex;

        let signed_fee_payer_tx: Transaction = bitcoin::consensus::deserialize(
            &self
                .rpc
                .sign_raw_transaction_with_wallet(&funded_fee_payer_tx, None, None)
                .await
                .wrap_err("Failed to sign funded tx through bitcoin RPC")?
                .hex,
        )
        .wrap_err("Failed to deserialize signed tx")?;

        let outpoint_vout = signed_fee_payer_tx
            .output
            .iter()
            .position(|o| {
                o.value == new_fee_payer_amount
                    && o.script_pubkey == self.signer.address().script_pubkey()
            })
            .ok_or(eyre!("Failed to find outpoint vout"))?;

        self.rpc
            .send_raw_transaction(&signed_fee_payer_tx)
            .await
            .wrap_err("Failed to send signed fee payer tx")?;

        self.db
            .save_fee_payer_tx(
                dbtx,
                bumped_id,
                signed_fee_payer_tx.compute_txid(),
                outpoint_vout as u32,
                new_fee_payer_amount,
                None,
            )
            .await
            .map_to_eyre()?;

        Ok(())

    #[allow(clippy::too_many_arguments)]
    pub async fn insert_try_to_send(
        &self,
        dbtx: &mut crate::TxSenderTransaction,
        tx_metadata: Option<TxMetadata>,
        signed_tx: &Transaction,
        fee_paying_type: FeePayingType,
        rbf_signing_info: Option<RbfSigningInfo>,
        cancel_outpoints: &[OutPoint],
        cancel_txids: &[Txid],
        activate_txids: &[ActivatedWithTxid],
        activate_outpoints: &[ActivatedWithOutpoint],
    ) -> Result<u32, BridgeError> {
        let txid = signed_tx.compute_txid();

        // do not add duplicate transactions to the txsender
        let tx_exists = self
            .db
            .check_if_tx_exists_on_txsender(Some(dbtx), txid)
            .await?;
        if let Some(try_to_send_id) = tx_exists {
            return Ok(try_to_send_id);
        }

        tracing::info!(
            "Added tx {} with txid {} to the queue",
            tx_metadata
                .as_ref()
                .map(|data| format!("{:?}", data.tx_type))
                .unwrap_or("N/A".to_string()),
            txid
        );
