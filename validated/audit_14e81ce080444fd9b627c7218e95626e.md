### Title
Underpriced PDA derivation CPU in `translate_signers` CPI signer path (flat `invoke_units` charged regardless of `signers_seeds` count/length) - (File: program-runtime/src/cpi.rs)

### Summary
`translate_signers` performs up to `MAX_SIGNERS` calls to `Pubkey::create_program_address` (each hashing up to `MAX_SEEDS` seeds of up to `MAX_SEED_LEN` bytes) on every `invoke`/`invoke_signed` CPI, but this work is never separately metered. The CPI compute charge is a single flat `invoke_units` (946 CU) applied once in `cpi_common`, so the real SHA256/PDA-derivation cost scales with attacker-chosen `signers_seeds_len`/seed sizes while the bill does not.

### Finding Description
`cpi_common` in `program-runtime/src/cpi.rs` charges compute for a CPI as follows: [1](#0-0) 
The only compute consumption before/around `translate_signers` is the fixed `invoke_context.get_execution_cost().invoke_units` (`DEFAULT_INVOCATION_COST = 946`), charged once per CPI call regardless of `signers_seeds_len`: [2](#0-1) [3](#0-2) 

`translate_signers` then loops over up to `MAX_SIGNERS` signer seed sets, and for each set translates up to `MAX_SEEDS` seed slices and calls `Pubkey::create_program_address(&seeds_bytes, program_id)` — a real SHA256-based PDA derivation: [4](#0-3) 

No per-signer or per-seed-byte compute is consumed inside this loop. Contrast this with the *direct* syscalls `sol_create_program_address` / `sol_try_find_program_address`, which explicitly charge `create_program_address_units` (1500 CU) **per invocation** of `Pubkey::create_program_address`, including in the bump-seed search loop: [5](#0-4) [6](#0-5) 

So the same underlying operation — `Pubkey::create_program_address` — is metered per call when invoked directly via `sol_create_program_address`, but is metered **zero times** (only the flat `invoke_units`) when the identical work is performed inside `translate_signers` for CPI signer derivation. An attacker-controlled program can supply `signers_seeds_addr`/`signers_seeds_len` pointing at up to `MAX_SIGNERS` seed sets, each with up to `MAX_SEEDS` seeds up to `MAX_SEED_LEN` bytes, on every `invoke_signed` call. Cap enforcement exists only for correctness/bounding (`CpiError::TooManySigners`, `InstructionError::MaxSeedLengthExceeded`) — not for billing — so the maximum permitted combination is reachable while the CU cost stays fixed at `invoke_units`.

### Impact Explanation
This is a compute-metering soundness gap: real CPU cost of PDA derivation in the CPI signer path (bounded by `MAX_SIGNERS × MAX_SEEDS × MAX_SEED_LEN` bytes hashed per CPI, repeatable at every nesting level up to `MAX_INSTRUCTION_STACK_DEPTH`) is not reflected in the CU price, which is a fixed `invoke_units` per call. A program that maximizes `signers_seeds` on every CPI (and nests CPIs) can make the validator perform materially more hashing work per consumed compute unit than an equivalent program using minimal or no signer seeds, degrading the node's real per-CU throughput below the value assumed by the compute-unit pricing model. This matches the "materially underpriced compute" / COST_UPPER_BOUND category in the audit scope.

### Likelihood Explanation
Fully attacker-controlled and requires no privileges beyond deploying and invoking one's own program: the attacker only needs to place seed data in their own account/CPI account-info buffers and call `invoke_signed` with the maximum permitted seed configuration, repeatable across nested CPIs within the same transaction. No special validator/leader/staked access, no mocked paths, and no dependence on other clients — purely a transaction the attacker submits themselves. It is fully reproducible with a unit test that varies signer/seed counts and measures wall time vs. billed CU.

### Recommendation
Meter the PDA-derivation work performed in `translate_signers` the same way `create_program_address_units` is charged for the direct syscall: consume `create_program_address_units` (or a cost scaled by number of seeds/bytes) for each `Pubkey::create_program_address` call made inside the `signer_seeds` map in `translate_signers`, before or as part of computing the derived address, so the flat `invoke_units` no longer masks the O(signers × seeds × seed_len) hashing cost.

### Proof of Concept
Rust unit test plan (extending the existing `test_translate_signers` test in `program-runtime/src/cpi.rs`):
```rust
#[test]
fn test_translate_signers_cost_scaling() {
    // Baseline: 1 signer, 1 short seed.
    let start = Instant::now();
    let invoke_context = build_mock_invoke_context(/* 1 signer, seed len = 1 */);
    let before_cu = invoke_context.compute_meter.remaining();
    let _ = translate_signers(&program_id, vm_addr, 1, &invoke_context).unwrap();
    let after_cu_small = invoke_context.compute_meter.remaining();
    let elapsed_small = start.elapsed();

    // Attacker-maximal: MAX_SIGNERS signer sets, each with MAX_SEEDS seeds of MAX_SEED_LEN bytes.
    let start = Instant::now();
    let invoke_context = build_mock_invoke_context(/* MAX_SIGNERS x MAX_SEEDS x MAX_SEED_LEN */);
    let before_cu = invoke_context.compute_meter.remaining();
    let _ = translate_signers(&program_id, vm_addr, MAX_SIGNERS as u64, &invoke_context).unwrap();
    let after_cu_max = invoke_context.compute_meter.remaining();
    let elapsed_max = start.elapsed();

    let cu_consumed_small = before_cu - after_cu_small;
    let cu_consumed_max = before_cu - after_cu_max;

    // Bug: CU consumed by translate_signers itself is 0 (or identical) in both cases,
    // while actual wall-clock work (elapsed_max >> elapsed_small) scales with seed data.
    assert_eq!(cu_consumed_small, cu_consumed_max, "translate_signers charges no CU for PDA derivation");
    assert!(elapsed_max.as_nanos() > elapsed_small.as_nanos() * 10,
        "real CPU cost scales with signer/seed count but billed CU does not");
}
```
Expected result confirming the finding: `cu_consumed_small == cu_consumed_max == 0` (no CU charged inside `translate_signers`) while `elapsed_max` is substantially larger than `elapsed_small`, demonstrating COST_UPPER_BOUND violation — real CPU cost is decoupled from billed compute units for the CPI signer-derivation path.

pub fn translate_signers(
    program_id: &Pubkey,
    signers_seeds_addr: u64,
    signers_seeds_len: u64,
    invoke_context: &InvokeContext,
) -> Result<Vec<Pubkey>, Error> {
    let check_aligned = invoke_context.get_check_aligned();
    let memory_mapping = invoke_context.memory_contexts.memory_mapping()?;
    if signers_seeds_len > 0 {
        let signers_seeds = translate_slice::<VmSlice<VmSlice<u8>>>(
            memory_mapping,
            signers_seeds_addr,
            signers_seeds_len,
            check_aligned,
        )?;
        if signers_seeds.len() > MAX_SIGNERS {
            return Err(Box::new(CpiError::TooManySigners));
        }
        Ok(signers_seeds
            .iter()
            .map(|signer_seeds| {
                let untranslated_seeds = translate_slice::<VmSlice<u8>>(
                    memory_mapping,
                    signer_seeds.ptr(),
                    signer_seeds.len(),
                    check_aligned,
                )?;
                if untranslated_seeds.len() > MAX_SEEDS {
                    return Err(Box::new(InstructionError::MaxSeedLengthExceeded) as Error);
                }
                let seeds_bytes = untranslated_seeds
                    .iter()
                    .map(|untranslated_seed| {
                        translate_vm_slice(untranslated_seed, memory_mapping, check_aligned)
                    })
                    .collect::<Result<Vec<_>, Error>>()?;
                Pubkey::create_program_address(&seeds_bytes, program_id)
                    .map_err(|err| Box::new(CpiError::BadSeeds(err)) as Error)
            })
            .collect::<Result<Vec<_>, Error>>()?)
    } else {
        Ok(vec![])
    }
}
