### Title
PedPoP accepts identity encryption keys, exposing encrypted secret shares publicly - (File: crypto/dkg/pedpop/src/encryption.rs)

### Summary

PedPoP registers each participant’s advertised encryption key without rejecting the group identity or requiring proof that the key corresponds to a usable ECDH secret. If a participant advertises the identity point, encryption derives the shared point `key * identity`, which is always identity and therefore reproducible by anyone who knows the public DKG context. Any observer of the resulting `EncryptedMessage` can reconstruct the ChaCha20 key and recover the encrypted `SecretShare`. [1](#0-0) [2](#0-1) [3](#0-2) 

### Finding Description

`EncryptionKeyMessage::read` deserializes `enc_key` with `C::read_G`, which enforces only a valid canonical group encoding; it does not reject identity or prove possession of a corresponding private key. [4](#0-3) [5](#0-4) 

`Decryption::register` then stores that unvalidated point for the participant. [2](#0-1) 

When an honest participant encrypts a share to that participant, `encrypt` computes `ecdh(key, to)`, where `key` is a fresh nonzero scalar and `to` is the registered public key. [6](#0-5) [3](#0-2) 

If `to` is identity, group multiplication produces identity regardless of `key`. [7](#0-6) 

The cipher key is derived solely from the public `context` and the serialized ECDH point, and the IV is fixed. Consequently, an attacker can recreate the cipher using the publicly known identity encoding and decrypt the message without knowing any private key. [8](#0-7) 

The commitments proof-of-knowledge does not repair this boundary because `challenge` binds the participant, nonce, and commitment encodings, while `EncryptionKeyMessage::read` appends `enc_key` separately after the commitments message. [9](#0-8) [10](#0-9) [4](#0-3) 

### Impact Explanation

An observer can recover the plaintext `SecretShare` encrypted for a participant that registered an identity encryption key. [11](#0-10) [12](#0-11) 

That plaintext is the secret-share representation consumed by `calculate_share`, so public recovery constitutes threshold key-share recovery rather than merely disclosure of nonsecret protocol metadata. [11](#0-10) [13](#0-12) 

For a `t = 1` parameter set, the recovered share is sufficient for the underlying threshold secret represented by that participant’s share. For larger thresholds, the attack still leaks a private threshold share that was intended to be confidential to its recipient. [14](#0-13) [15](#0-14) 

### Likelihood Explanation

A participant can reach this path by supplying an otherwise parseable `EncryptionKeyMessage` whose trailing `enc_key` encodes the group identity. [4](#0-3) 

The recipient-side state accepts the registration before any encryption-key validity or proof-of-possession check. [2](#0-1) [16](#0-15) 

The exploit does not require malformed encodings, noncanonical scalars, unsafe code, or control over the RNG; it requires only control of the advertised encryption-key field and visibility of the encrypted share message. [5](#0-4) [17](#0-16) 

### Recommendation

Reject the identity element when registering or deserializing `enc_key`, preferably as part of a protocol-level validity check in `EncryptionKeyMessage::read` or `Decryption::register`. [4](#0-3) [2](#0-1) 

Additionally, bind `enc_key` to the same participant-authenticated commitments transcript, or require a proof of possession for the registered encryption key before accepting shares encrypted to it. [9](#0-8) [18](#0-17) 

A regression test should register an identity `enc_key`, encrypt a nonzero `SecretShare` to it, and assert that registration or share generation rejects the key before `EncryptedMessage` is emitted. [19](#0-18) [12](#0-11)

```rust
let mut transcript = RecommendedTranscript::new(b"DKG Encryption v0.2");
transcript.append_message(b"context", context);
transcript.domain_separate(b"encryption_key");
transcript.append_message(b"shared_key", C::G::identity().to_bytes());

let mut key = Cc20Key::default();
let challenge = transcript.challenge(b"key");
key.copy_from_slice(&challenge[..32]);

let mut iv = Cc20Iv::default();
iv.copy_from_slice(b"DKG IV v0.2\0");

let mut cipher = ChaCha20::new(&key, &iv);
cipher.apply_keystream(encrypted_secret_share.as_mut());
```

The PoC obtains `encrypted_secret_share` by observing an `EncryptedMessage<C, SecretShare<C::F>>` produced after the target participant registers `enc_key = C::G::identity()`. The derivation works because `ecdh(key, identity)` is always `identity`, so the transcript’s `shared_key` field is publicly computable and does not depend on any secret. [1](#0-0) [12](#0-11)

```rust
fn cipher<C: Ciphersuite>(context: [u8; 32], ecdh: &Zeroizing<C::G>) -> ChaCha20 {
  // Ideally, we'd box this transcript with ZAlloc, yet that's only possible on nightly
  // TODO: https://github.com/serai-dex/serai/issues/151
  let mut transcript = RecommendedTranscript::new(b"DKG Encryption v0.2");
  transcript.append_message(b"context", context);

  transcript.domain_separate(b"encryption_key");

  let mut ecdh = ecdh.to_bytes();
  transcript.append_message(b"shared_key", ecdh.as_ref());
  ecdh.as_mut().zeroize();

  let zeroize = |buf: &mut [u8]| buf.zeroize();

  let mut key = Cc20Key::default();
  let mut challenge = transcript.challenge(b"key");
  key.copy_from_slice(&challenge[.. 32]);
  zeroize(challenge.as_mut());

  // Since the key is single-use, it doesn't matter what we use for the IV
  // The issue is key + IV reuse. If we never reuse the key, we can't have the opportunity to
  // reuse a nonce
  // Use a static IV in acknowledgement of this
  let mut iv = Cc20Iv::default();
  // The \0 is to satisfy the length requirement (12), not to be null terminated
  iv.copy_from_slice(b"DKG IV v0.2\0");
```

```rust
  /// Read a canonical point from something implementing std::io::Read.
  ///
  /// The provided implementation is safe so long as `GroupEncoding::to_bytes` always returns a
  /// canonical serialization.
  #[cfg(any(feature = "alloc", feature = "std"))]
  #[allow(non_snake_case)]
  fn read_G<R: Read>(reader: &mut R) -> io::Result<Self::G> {
    let mut encoding = <Self::G as GroupEncoding>::Repr::default();
    reader.read_exact(encoding.as_mut())?;

    let point = Option::<Self::G>::from(Self::G::from_bytes(&encoding))
      .ok_or_else(|| io::Error::other("invalid point"))?;
    if point.to_bytes().as_ref() != encoding.as_ref() {
      Err(io::Error::other("non-canonical point"))?;
    }
    Ok(point)
```

```rust
impl<C: Ciphersuite> ReadWrite for Commitments<C> {
  fn read<R: Read>(reader: &mut R, params: ThresholdParams) -> io::Result<Self> {
    let mut commitments = Vec::with_capacity(params.t().into());
    let mut cached_msg = vec![];

    #[allow(non_snake_case)]
    let mut read_G = || -> io::Result<C::G> {
      let mut buf = <C::G as GroupEncoding>::Repr::default();
      reader.read_exact(buf.as_mut())?;
      let point = C::read_G(&mut buf.as_ref())?;
      cached_msg.extend(buf.as_ref());
      Ok(point)
    };

    for _ in 0 .. params.t() {
      commitments.push(read_G()?);
    }

    Ok(Commitments { commitments, cached_msg, sig: SchnorrSignature::read(reader)? })
```
