### Title
Cached FROST preprocess is reused across signing invocations, enabling nonce reuse and private key share recovery - (File: coordinator/src/tributary/signing_protocol.rs)

### Summary
The Omni X incident's bug class is *stale state consumed after an operation that logically invalidates it* — the liquidation path judged against an old `vars` snapshot taken before a reentrant callback mutated the real state. The Serai analog lives in `SigningProtocol::preprocess_internal`/`share_internal`: a FROST preprocess (which deterministically fixes the signer's nonces via a seeded `ChaCha20Rng`) is stored in `CachedPreprocesses` keyed only by `context`, and is *never deleted or invalidated* after `machine.sign()` consumes it. Every subsequent call to `share_internal` for the same context regenerates the identical nonces and produces another signature share — classic FROST nonce reuse, which leaks the private key share.

### Finding Description
`preprocess_internal` writes `CachedPreprocesses::set(txn, &self.context, &cache)` once and thereafter always reloads that same seed (`CachedPreprocesses::get(...).unwrap()`) to reconstruct the machine via `AlgorithmSignMachine::from_cache`. There is no `remove`, no "consumed" flag, and no per-sign-attempt nonce: the cache persists for the life of the context [1](#0-0) .

In `crypto/frost`, `from_cache` → `seeded_preprocess` feeds the seed to `ChaCha20Rng::from_seed` and derives `nonces` and `commitments` deterministically — so two machines built from the same cached seed hold the same `d, e` nonces [2](#0-1) . The library itself documents the consequence: "A preprocess MUST only be used once. Reuse will enable third-party recovery of your private key share" [3](#0-2) .

The stale-state reuse is triggered because `share_internal` (and transitively `DkgConfirmer::share` and `DkgConfirmer::complete`) calls `preprocess_internal` fresh each time, then consumes the machine in `machine.sign(preprocesses, msg)` [4](#0-3) . `DkgConfirmer::share` emits a share for an attacker-influenced `preprocesses` map (each entry parsed via `read_preprocess` from untrusted tributary transaction bytes), and `DkgConfirmer::complete` *re-runs the entire `share_internal`* with a potentially different `preprocesses` map and/or different `key_pair` (hence different `msg` from `set_keys_message`) before completing [5](#0-4) . Two `sign()` executions under context `(b"DkgConfirmer", attempt)` therefore reuse `d, e` while the binding factor `rho` (bound to msg and the preprocess set) differs — exactly the Omni X shape: a decision/signing step executed against a state snapshot the protocol assumed was fresh.

### Impact Explanation
FROST share `s_i = d_i + (e_i * rho_i) + (lambda_i * share_i * c)`. If a signer emits two shares with the same `d_i, e_i` but different `(rho, msg/signing set)` — or the same nonces under different challenges — the two public shares form a linear system solvable for `share_i`. An attacker who supplies preprocesses (untrusted bytes through `read_preprocess`) and observes the broadcast shares recovers the validator's MuSig/Schnorrkel secret share; combined with threshold-many compromised shares, the Tributary's substrate key is recoverable, enabling forgery of `set_keys` confirmations and arbitrary signatures. This is secret-key leakage reachable from public inputs — Critical/High severity per the scope rules.

### Likelihood Explanation
The reuse is deterministic, not probabilistic: any code path that calls `share()`/`complete()` more than once per `attempt` context reuses nonces. `complete()` unconditionally re-invokes `share_internal`, so even a single honest share-then-complete flow performs two `sign()` executions on identical nonces; whether the second share is broadcast depends on call-site wiring, but any retry, reboot re-execution, or adversarially induced second `share()` call (distinct preprocess set or `key_pair`) produces a second *published* share under reused nonces. Attacker prerequisites are only the ability to submit preprocess bytes and observe shares — both unprivileged.

### Recommendation
Consume-once semantics for `CachedPreprocesses`: after `share_internal` successfully runs `machine.sign()`, `CachedPreprocesses::remove(txn, &self.context)` (or mark the context consumed) inside the same DB transaction that records the emitted share, so restarts cannot regenerate the nonces. Additionally, bind the cache key to the exact signing instance (e.g., include a hash of `msg` and the preprocess-set commitments in `context`) so that a different message/set cannot ever be signed with the same seed. `DkgConfirmer::complete` should reuse the machine produced by `share` rather than regenerating it from cache.

### Proof of Concept
1. Validators run a DKG confirmer round for `attempt = k`. `DkgConfirmer::share(preprocesses_A, key_pair_A)` → `preprocess_internal` loads seed `S` from `CachedPreprocesses[(b"DkgConfirmer", k)]`, derives nonces `(d, e)`, signs `msg_A` under set `A`, and broadcasts `s_1`.
2. Trigger a second sign under the same context — e.g., `complete(preprocesses_B, key_pair_B, shares)` or a retried `share` — with a different preprocess map or key pair. `share_internal` reloads the untouched seed `S`, regenerates identical `(d, e)`, and computes `s_2 = d + e·rho_2 + lambda·x·c_2`.
3. With `s_1`, `s_2`, known `rho_1, rho_2` (recomputable from public preprocesses/messages), and known `lambda, c`, solve the two-equation system for the signer's secret share `x`. Repeating against `t` validators recovers the threshold key.

  fn share_internal(
    &mut self,
    participants: &[<Ristretto as Ciphersuite>::G],
    mut serialized_preprocesses: HashMap<Participant, Vec<u8>>,
    msg: &[u8],
  ) -> Result<(AlgorithmSignatureMachine<Ristretto, Schnorrkel>, [u8; 32]), Participant> {
    let machine = self.preprocess_internal(participants).0;

    let mut participants = serialized_preprocesses.keys().copied().collect::<Vec<_>>();
    participants.sort();
    let mut preprocesses = HashMap::new();
    for participant in participants {
      preprocesses.insert(
        participant,
        machine
          .read_preprocess(&mut serialized_preprocesses.remove(&participant).unwrap().as_slice())
          .map_err(|_| participant)?,
      );
    }

    let (machine, share) = machine.sign(preprocesses, msg).map_err(|e| match e {
      FrostError::InternalError(e) => unreachable!("FrostError::InternalError {e}"),
      FrostError::InvalidParticipant(_, _) |
      FrostError::InvalidSigningSet(_) |
      FrostError::InvalidParticipantQuantity(_, _) |
      FrostError::DuplicatedParticipant(_) |
      FrostError::MissingParticipant(_) => unreachable!("{e:?}"),
      FrostError::InvalidPreprocess(p) | FrostError::InvalidShare(p) => p,
    })?;

    Ok((machine, share.serialize().try_into().unwrap()))

  fn seeded_preprocess(
    self,
    seed: CachedPreprocess,
  ) -> (AlgorithmSignMachine<C, A>, Preprocess<C, A::Addendum>) {
    let mut params = self.params;

    let mut rng = ChaCha20Rng::from_seed(*seed.0);
    let (nonces, commitments) = Commitments::new::<_>(
      &mut rng,
      params.keys.original_secret_share(),
      &params.algorithm.nonces(),
    );
    let addendum = params.algorithm.preprocess_addendum(&mut rng, &params.keys);

    let preprocess = Preprocess { commitments, addendum };

    // Also obtain entropy to randomly sort the included participants if we need to identify blame
    let mut blame_entropy = [0; 32];
    rng.fill_bytes(&mut blame_entropy);
    (
      AlgorithmSignMachine { params, seed, nonces, preprocess: preprocess.clone(), blame_entropy },
      preprocess,
    )
  }
