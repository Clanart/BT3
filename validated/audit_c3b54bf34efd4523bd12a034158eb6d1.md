### Title
Searcher can revert their own winning auction bid by front-running with a self-nonce-bump, allowing bid reneging and griefing the block proposer's fee revenue - ([File: kaiax/auction/impl/bid_pool.go])

### Summary
The Kaia `kaiax/auction` module (KIP-249) implements a priority-auction mechanism where an off-chain `Auctioneer` selects a winning `Bid` and the block-producing CN executes it on-chain via `AuctionEntryPoint.call(auctionTx)`. Like the `Symmetrical` liquidation flow (where `LibMuon.verifyPartyAUpnl` binds a Muon signature to `AccountStorage.layout().partyANonces[partyA]` at execution time), Kaia's `AuctionTx` struct carries a `Nonce` field tied to the searcher's on-chain nonce in the `AuctionEntryPoint` contract (`getNoncesAndDeposits`, `UseNonce` event), which is intended to be validated at call time (`return auctionTx.nonce == nonces(auctionTx.sender)` in the reference mock) [1](#0-0) . The searcher's `EIP-712` signature over the bid (including `Nonce`) is fixed at bid-submission time [2](#0-1) , but the block-builder-side `BidPool.validateBid` never re-checks that nonce against the current on-chain state before the bid is admitted or included in a bundle [3](#0-2) .

### Finding Description
The exploit path mirrors H-7 exactly: a party who is bound by a nonce-checked signature can invalidate that signature by permissionlessly incrementing their own on-chain nonce before the dependent transaction executes.

1. A searcher submits `auction_submitBid` with `BidData.Nonce` set to their current on-chain nonce and signs the `EIP-712` digest that embeds this nonce (`EncodeData` includes `b.Nonce`) [2](#0-1) .
2. `BidPool.AddBid` → `validateBid` accepts the bid based on block-number range, positive bid amount, size limits, and signature validity — it performs no on-chain-nonce freshness check against the searcher's current state nonce [3](#0-2) .
3. At block-building time, `AuctionModule.ExtractTxBundles` turns the winning bid into a mandatory (`TargetRequired: true`) bundle tied to the target transaction and the worker executes it via `GetBidTxGenerator` → `AuctionEntryPoint.call(auctionTx)` [4](#0-3) .
4. Because a searcher (an ordinary, unprivileged transaction sender) can submit any self-transaction (e.g., a trivial value transfer to themselves) that increments their own account nonce at any time before the bid's execution, they can invalidate the previously auctioneer-approved bid's nonce match at the very last moment — exactly analogous to PartyA calling `requestToClosePosition`/`requestToCancelCloseRequest` or a dust allocate/deallocate to bump `partyANonces[partyA]` and break `LibMuon.verifyPartyAUpnl`.
5. When the CN then submits the bid transaction into the block, the on-chain nonce check inside `AuctionEntryPoint.call` fails and the call reverts, so `_verifyInputIntegrity`-style checks fail and no funds are collected from the searcher.

### Impact Explanation
This lets a searcher who won an auction slot renege on their commitment at will, after the auctioneer has already picked them as the winner and after other competing bids may have been displaced (`senderHasDifferentWinner`/`bidTargetMap` replacement logic only keeps the single best bid per target per block) [5](#0-4) . Consequences:
- The block proposer loses the expected bid revenue for that block/target transaction, since the reverted call transfers no value.
- Because the bundle is marked `TargetRequired: true`, its failure interacts with `shouldDiscardBundle` logic during block assembly [6](#0-5) , and other bidders who were rejected in favor of the (now-reneging) winning bid receive no execution either, so the searcher effectively vetoes the auction outcome for that block.
- Because the searcher can repeat this every block for which they win (self-transactions incrementing nonce are cheap), this is a repeatable, low-cost griefing/last-look mechanism that undermines KIP-249 auction integrity and fee-revenue guarantees — structurally the same class of bug as H-7 (front-runnable, off-chain-approved value tied to an on-chain nonce that any account fully controls).

### Likelihood Explanation
High. No special privileges are needed: any searcher who has already been selected as an auction winner can send an ordinary self-transaction to bump their nonce. Kaia's own `state_transition.go` `preCheck()` nonce validation (`stNonce == txNonce`) is what a normal transaction relies on, and the searcher fully controls their own nonce sequence [7](#0-6) . The `BidPool` never re-validates the nonce against fresh state before or during block building, so there is no mitigation against this timing race short of the auctioneer re-checking nonces immediately before each block (which the code does not appear to do, based on `validateBid`).

### Recommendation
- Re-validate `bid.Nonce` against the searcher's live on-chain nonce as close as possible to inclusion time (e.g., immediately before/at `ExtractTxBundles`/worker execution), and drop stale bids rather than letting them revert on-chain.
- Consider requiring searchers to lock/escrow the bid amount or post a bond at bid-submission time so that reneging via nonce-bump has an economic cost, similar to recommending review of "malicious users attempting to increment the nonce in order to block certain actions" from the original report.
- Alternatively, decouple the auction settlement from the searcher's regular account nonce (e.g., a dedicated auction-nonce/commitment counter that only the `AuctionEntryPoint` contract can increment) so ordinary transactions cannot interfere with bid validity.

### Proof of Concept
Not independently executable from the indexed context — the production `AuctionEntryPoint` contract logic that performs the on-chain `nonce == nonces(sender)` check is not included in this repository (only referenced via `IAuctionEntryPoint` bindings and a mock with the check commented out) [1](#0-0) . Conceptually:
1. Searcher submits a winning bid with `Nonce = N` (current on-chain nonce) via `auction_submitBid`.
2. `BidPool.AddBid`/`validateBid` accepts and stores it as the block's winner for the target tx [5](#0-4) .
3. Before the target block is built, the searcher sends any self-transaction with nonce `N`, advancing their state nonce to `N+1`.
4. When the CN builds the block and calls `AuctionEntryPoint.call(auctionTx)` with the stale `Nonce = N`, the contract's nonce check fails and the call reverts, letting the searcher escape the bid without penalty.

Because the real `AuctionEntryPoint.sol` source and its exact revert/refund semantics are not present in the indexed codebase (only the mock and generated bindings), the precise on-chain gas-accounting consequences for the block proposer could not be fully verified here; a Devin session with full repository/contract access would be needed to confirm the exact production contract logic.

func (bp *BidPool) insertBid(bid *auction.Bid) error {
	bp.bidMu.Lock()
	defer bp.bidMu.Unlock()

	var (
		blockNumber  = bid.BlockNumber
		targetTxHash = bid.TargetTxHash
		sender       = bid.Sender
	)

	// Re-check bidWinnerMap here — two concurrent bids can pass validateBid together.
	if _, ok := bp.bidMap[bid.Hash()]; ok {
		return auction.ErrBidAlreadyExists
	}
	if bp.senderHasDifferentWinner(bid) {
		return auction.ErrBidSenderExists
	}

	// If same block number, same target tx hash exists, replace it if it's better
	if existingBid, ok := bp.bidTargetMap[blockNumber][targetTxHash]; ok {
		// FCFS if the bid is the same.
		if existingBid.Bid.Cmp(bid.Bid) >= 0 {
			return auction.ErrLowBid
		}

		logger.Trace("Replace bid", "old", existingBid.Hash(), "new", bid.Hash())
		delete(bp.bidMap, existingBid.Hash())
		delete(bp.bidWinnerMap[blockNumber], existingBid.Sender)
	} else {
		if int64(len(bp.bidMap)) >= bp.maxBidPoolSize {
			logger.Info("Bid pool is full", "maxBidPoolSize", bp.maxBidPoolSize, "bid", bid.Hash())
			return auction.ErrBidPoolFull
		}
	}

	hash := bid.Hash()

	bp.initializeBidMap(blockNumber)

	bp.bidMap[hash] = bid
	bp.bidTargetMap[blockNumber][targetTxHash] = bid
	bp.bidWinnerMap[blockNumber][sender] = hash

	numBidsGauge.Update(int64(len(bp.bidMap)))

	logger.Trace("Add bid", "bid", hash)

	return nil
}

func (bp *BidPool) validateBid(bid *auction.Bid) error {
	blockNumber := bid.BlockNumber

	bp.bidMu.RLock()

	// Check if the auction tx is already in the pool.
	if _, ok := bp.bidMap[bid.Hash()]; ok {
		bp.bidMu.RUnlock()
		return auction.ErrBidAlreadyExists
	}

	// 1. The `bid.Sender` must not be in the winner list of the same block number if the new bid isn't equal to the previous bid.
	if bp.senderHasDifferentWinner(bid) {
		bp.bidMu.RUnlock()
		return auction.ErrBidSenderExists
	}
	bp.bidMu.RUnlock()

	curBlock := bp.Chain.CurrentBlock()
	if curBlock == nil {
		return auction.ErrBlockNotFound
	}

	// 2. The `bid.BlockNumber` must be in range of `[currentBlockNumber + 1, currentBlockNumber + allowFutureBlock]`.
	curNum := curBlock.NumberU64()
	if blockNumber <= curNum || blockNumber > curNum+allowFutureBlock {
		return auction.ErrInvalidBlockNumber
	}

	// 3. The `bid.Bid` must be greater than 0.
	if bid.Bid.Sign() <= 0 {
		return auction.ErrZeroBid
	}

	// 4. The data size must be less than the maximum limit.
	if uint64(len(bid.Data)) > BidTxMaxDataSize {
		return auction.ErrExceedMaxDataSize
	}

	// 5. The gas limit must be less than the maximum limit.
	if bid.CallGasLimit > BidTxMaxCallGasLimit {
		return auction.ErrExceedMaxCallGasLimit
	}

	// 6. The `bid.SearcherSig` and `bid.AuctioneerSig` must be valid.
	if err := bp.validateBidSigs(bid); err != nil {
		return err
	}

	return nil
}

func (a *AuctionModule) ExtractTxBundles(txs []*types.Transaction, prevBundles []*builder.Bundle) []*builder.Bundle {
	bundles := []*builder.Bundle{}
	curBlock := a.Chain.CurrentBlock()
	if curBlock == nil || atomic.LoadUint32(&a.bidPool.running) == 0 {
		return bundles
	}

	miningBlock := curBlock.NumberU64() + 1
	bidTargetMap := a.bidPool.GetTargetTxMap(miningBlock)
	if len(bidTargetMap) == 0 {
		return bundles
	}

	for _, tx := range txs {
		txHash := tx.Hash()
		bid, ok := bidTargetMap[txHash]
		if !ok {
			continue
		}
		b := builder.NewBundle(
			builder.NewTxOrGenList(a.GetBidTxGenerator(tx, bid)),
			txHash,
			true,
		)

		isConflict := false
		for _, prev := range append(prevBundles, bundles...) {
			if prev.IsConflict(b) {
				isConflict = true
				break
			}
		}
		if isConflict {
			continue
		}
		bundles = append(bundles, b)
	}

	return bundles
}
