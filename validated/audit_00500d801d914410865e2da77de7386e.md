## Finding

### Title
Attacker-controlled `WWW-Authenticate` realm spoofing causes GitHub Desktop to misclassify a malicious remote as a GitHub host and trigger the GitHub sign-in flow - (File: `app/src/lib/trampoline/trampoline-credential-helper.ts`)

### Summary
The credential-helper trampoline that backs GitHub Desktop's `git credential helper` implementation decides whether a remote "appears to be a GitHub host" partly by trusting the `WWW-Authenticate` header value that the **remote server itself returns**. Because that header is fully attacker-controlled when the remote is a malicious or compromised git server, an attacker can make Desktop classify their host as `'enterprise'` and drive the app into the GitHub Enterprise sign-in path for a host the user never intended to authenticate against.

### Finding Description
When Git needs credentials for an HTTPS remote it invokes Desktop's credential helper (`createCredentialHelperTrampolineHandler`), passing along any `wwwauth[]` fields captured from the server's HTTP response. `getEndpointKind` uses these fields as a "happy path" to decide the endpoint kind without an independent check: [1](#0-0) 

```
  // When Git attempts to authenticate with a host it captures any
  // WWW-Authenticate headers and forwards them to the credential helper. We
  // use them as a happy-path to determine if the host is a GitHub host without
  // having to resort to making a request ourselves.
  for (const [k, v] of cred.entries()) {
    if (k.startsWith('wwwauth[')) {
      if (v.includes('realm="GitHub"')) {
        return 'enterprise'
      } else if (/realm="(GitLab|Gitea|Atlassian Bitbucket)"/.test(v)) {
        return 'generic'
      }
    }
  }
```

This value originates entirely from the HTTP response of the remote being contacted, and that remote is exactly the attacker-controlled asset the report's threat model describes (a git remote/proxy response). Any server responding to an HTTPS git request with `WWW-Authenticate: Basic realm="GitHub"` will be classified as `'enterprise'` regardless of its actual hostname.

That classification then feeds `getCredential`: [2](#0-1) 

```
async function getCredential(cred: Credential, store: Store, token: string) {
  const ghCred = await getGitHubCredential(cred, store)
  if (ghCred) { return ghCred }
  const endpointKind = await getEndpointKind(cred, store)
  const accounts = await store.getAll()
  const endpoint = `${getCredentialUrl(cred)}`
  const apiEndpoint = getAPIEndpoint(endpoint)
  if (
    endpointKind !== 'generic' &&
    !accounts.some(a => a.endpoint === apiEndpoint)
  ) {
    ...
    const account = await ui.promptForGitHubSignIn(endpoint)
    ...
    return credWithAccount(cred, account)
  }
  ...
}
```

Because `endpointKind` is `'enterprise'` (not `'generic'`) and the user has no stored account matching the attacker's `apiEndpoint`, Desktop skips the "generic git credential" prompt entirely and instead invokes `ui.promptForGitHubSignIn(endpoint)` — the GitHub/GHE sign-in UI — for a host that is not actually GitHub, purely because the remote lied about its `realm`. Unlike the legitimate GitHub-host checks that precede it (`isDotCom`, `isGHE`, or an existing stored account matched by `findGitHubTrampolineAccount`, which compares `origin` exactly), this branch has no cryptographic or DNS/host verification at all — it is driven solely by a string the attacker's server chose to send.

The invariant that is broken is: "Desktop should only offer the GitHub/GHE-branded sign-in and credential flow for hosts it can independently verify are GitHub-owned." The `wwwauth[]` shortcut breaks that invariant because trust is derived from attacker-supplied data instead of a verified property of the host (e.g. an actual `/api/v3` probe via `isGitHubHost`, which is only reached in the `else` branch when no `wwwauth` header is present).

### Impact Explanation
This lets a malicious or compromised git remote (added by the user, or reached via a redirect, proxy, or MITM'd clone/fetch URL) cause GitHub Desktop to present a "Sign in to GitHub Enterprise" affordance for the attacker's own host. This can be used as a phishing/spoofing primitive: the user is led to believe they are performing a legitimate GitHub Enterprise authentication against a host they are actively working with, when in fact the classification was forged. Depending on what `promptForGitHubSignIn` does for a non-GitHub endpoint (device-flow OAuth or PAT entry against `endpoint`), this can result in the user's GitHub PAT/OAuth token or device-flow authorization being issued to/entered against an attacker-controlled endpoint — i.e., credential exfiltration or unauthorized OAuth binding, which matches the reported valid-impact class. I was not able to fully verify the exact UI/network behavior of `promptForGitHubSignIn` (in `app/src/lib/trampoline/trampoline-ui-helper.ts`) within the available investigation, so the precise mechanics of what is submitted to the attacker's endpoint during that flow are not fully confirmed.

### Likelihood Explanation
No local access, admin rights, or prior malware is required — only that the user's Desktop client performs a fetch/clone/push against a repository whose remote is controlled by (or proxied/MITM'd by) an attacker, and that the server sends a crafted `WWW-Authenticate` header on a 401 response. This is a normal HTTP response an attacker fully controls, requiring no unusual interaction from the user beyond a routine git operation against that remote. The existing guards (`isDotCom`, `isGHE`, exact-origin account matching) do not protect this code path because the `wwwauth[]` check is evaluated first and returns early, before any of the "generic" fallback or real hostname probing (`isGitHubHost`) can run.

### Recommendation
Do not trust the `realm=` value from `WWW-Authenticate` headers as sufficient evidence that a host is GitHub/GHE. At minimum, corroborate it with an independent signal (e.g., only honor the `wwwauth` hint if the endpoint's hostname was already known/allow-listed, or always fall through to the existing `isGitHubHost(endpoint)` network probe rather than short-circuiting on `enterprise` classification). Ensure the sign-in prompt (`promptForGitHubSignIn`) clearly and unambiguously displays the true destination host so a user can identify a spoofed GitHub Enterprise prompt before entering credentials or approving an OAuth flow.

### Proof of Concept
1. Attacker sets up an HTTPS git server (or a MITM/proxy in front of one) at `https://evil.example.com/legit-repo.git`.
2. Victim adds this as a remote in GitHub Desktop and performs a `fetch`/`pull`/`push` (`app/src/lib/git/fetch.ts`, `pull.ts`, `push.ts` all route through `git()` → `withTrampolineEnv` → the credential helper).
3. When git requests credentials, the attacker's server responds to the initial unauthenticated request with `401` and header `WWW-Authenticate: Basic realm="GitHub"`.
4. Git forwards this as a `wwwauth[0]=Basic realm="GitHub"` field to Desktop's credential helper via stdin.
5. `getEndpointKind` (`app/src/lib/trampoline/trampoline-credential-helper.ts:153-165`) matches `realm="GitHub"` and returns `'enterprise'` for `evil.example.com`.
6. `getCredential` finds no stored account for `evil.example.com`'s API endpoint and calls `ui.promptForGitHubSignIn('https://evil.example.com')`, surfacing GitHub Desktop's branded GitHub Enterprise sign-in flow for the attacker's host.

```typescript
/** Implementation of the 'get' git credential helper command */
async function getCredential(cred: Credential, store: Store, token: string) {
  const ghCred = await getGitHubCredential(cred, store)

  if (ghCred) {
    return ghCred
  }

  const endpointKind = await getEndpointKind(cred, store)
  const accounts = await store.getAll()

  const endpoint = `${getCredentialUrl(cred)}`
  const apiEndpoint = getAPIEndpoint(endpoint)

  // If it appears as if the endpoint is a GitHub host and we don't have an
  // account for that endpoint then we should prompt the user to sign in.
  if (
    endpointKind !== 'generic' &&
    !accounts.some(a => a.endpoint === apiEndpoint)
  ) {
    if (getIsBackgroundTaskEnvironment(token)) {
      debug('background task environment, skipping prompt')
      return undefined
    }

    const account = await ui.promptForGitHubSignIn(endpoint)

    if (!account) {
      setHasRejectedCredentialsForEndpoint(token, endpoint)
    }

    return credWithAccount(cred, account)
  }
```
