### Title
Auction bid pool capacity can be griefed by cost-free sybil bids, blocking legitimate competitive bids from being included - (File: `kaiax/auction/impl/bid_pool.go`)

### Summary
The `BidPool.insertBid` function enforces only a global `maxBidPoolSize` cap with no minimum economic cost or liveness/eviction logic analogous to the CLOB order-book bug: once the pool is full, any new distinct-target bid is rejected outright with `ErrBidPoolFull` rather than displacing the least competitive entry, and there is no balance/stake requirement to admit a bid.

### Finding Description
`BidPool.insertBid` accepts a bid into `bidMap`/`bidTargetMap`/`bidWinnerMap` as long as: the bid hash is unique, the sender does not already have a different winning bid for that block, and (for non-replacement inserts) `len(bidMap) < maxBidPoolSize` [2](#0-1) . `validateBid` only checks signature format/validity, block-number window (`curNum+1` to `curNum+allowFutureBlock`), positive bid amount, data size, and gas limit — it never checks that the sender has funds to cover the bid [1](#0-0) . Because `bidWinnerMap` keys uniqueness by `(blockNumber, sender)`, an attacker can trivially generate many disposable EOA keys (which cost nothing but a signature computation) and submit distinct bids each targeting a different, even non-existent, `TargetTxHash` for the allowed future block window. Since `validateBid`/`insertBid` never checks whether `TargetTxHash` corresponds to a real pending transaction, and there is no cost to mint a fresh keypair per bid, an attacker can flood `bidMap` up to `maxBidPoolSize` entries essentially for free.

Once `len(bidMap) >= maxBidPoolSize`, any legitimate searcher's non-replacement bid for a genuinely pending transaction is rejected with `ErrBidPoolFull` [3](#0-2) . Unlike the CLOB book, there is no eviction of the "worst" (lowest) bid to make room for a better one — the pool simply refuses new distinct-target bids. Bids are only purged when the target block is processed via `PostInsertBlock` → `removeOldBids` [4](#0-3) [5](#0-4) , meaning the attacker's junk entries occupy slots for the entire lifetime of the target block window (up to `allowFutureBlock = 2` blocks) before being cleared, and the attacker can immediately re-flood for the next block window at negligible cost.

### Impact Explanation
This blocks legitimate searchers/bidders from competing in the block auction for any block during the flood window, since `AddBid` for their real target transaction fails with `ErrBidPoolFull`. This can result in: (a) denial of legitimate MEV/auction participation, effectively letting the attacker or nobody win the auction for a given block, (b) loss of auction revenue that should have gone to the protocol/auctioneer via `bid.Bid` payment settlement, and (c) potential self-favoring by the attacker who — since they control all filled slots — can ensure their own (possibly minimal) bid is the only one contesting a target, capturing MEV that should have gone to a higher legitimate bid.

### Likelihood Explanation
High likelihood: the attack requires no capital (bid admission has no balance check), only cheap key generation and EIP-712 signature production, both doable locally without any on-chain transaction. `maxBidPoolSize` is a fixed, network-wide constant reachable by any RPC caller submitting bids via the `SubmitBid` API path in `kaiax/auction/impl/api.go`, making this trivially and repeatedly exploitable by any external, unprivileged auction bidder.

### Recommendation
Introduce an eviction policy that removes the lowest-value bid(s) when the pool is full and a higher bid arrives (mirroring competitive replacement already done for same-target bids), and/or require a minimal balance/stake check or bonded per-sender rate limiting at bid-admission time so that sybil bid flooding carries real economic cost. Additionally, consider validating that `TargetTxHash` corresponds to an actually pending transaction before admitting the bid into the pool.

### Proof of Concept
1. Attacker generates `maxBidPoolSize` distinct throwaway keypairs (free, off-chain).
2. For each key, attacker crafts a valid `auction.Bid` with a unique but arbitrary `TargetTxHash` (does not need to correspond to a real transaction) and `BlockNumber = currentBlock+1`, signs it with valid EIP-712 `SearcherSig`, and obtains/forges a valid `AuctioneerSig` if required (or targets one they control if signature requirements allow), then submits via the bid-gossip/API path.
3. Each bid passes `validateBid` (unique hash, no balance check, valid block window, positive bid amount, valid sigs) and is inserted via `insertBid`, incrementing `len(bidMap)` until it equals `maxBidPoolSize` [2](#0-1) .
4. A legitimate searcher then submits a competitive bid targeting a real pending transaction for the same block; `insertBid` hits the `len(bp.bidMap) >= bp.maxBidPoolSize` branch and returns `ErrBidPoolFull`, rejecting the legitimate bid [3](#0-2) .
5. The block is produced without the legitimate bidder's participation; the pool is only cleared for that block number after `PostInsertBlock` processes it [4](#0-3) , after which the attacker can repeat the flood for the next block.

// removeOldBids removes the old bids for the given block number.
func (bp *BidPool) removeOldBids(num uint64, txHashMap map[common.Hash]struct{}) {
	bp.bidMu.Lock()
	defer bp.bidMu.Unlock()

	// Remove the old bids.
	for bn := range bp.bidWinnerMap {
		if bn > num {
			continue
		}

		for _, bh := range bp.bidWinnerMap[bn] {
			delete(bp.bidMap, bh)
		}
		delete(bp.bidTargetMap, bn)
		delete(bp.bidWinnerMap, bn)
	}

	// Remove the bid which target tx is in the txHashMap.
	toBlock := num + allowFutureBlock
	for blockNum := num + 1; blockNum <= toBlock; blockNum++ {
		targetMap := bp.bidTargetMap[blockNum]
		if targetMap == nil {
			continue
		}

		// Collect bids to remove first to avoid modifying map during iteration
		var bidsToRemove []*auction.Bid
		for _, bid := range targetMap {
			if _, ok := txHashMap[bid.TargetTxHash]; ok {
				bidsToRemove = append(bidsToRemove, bid)
			}
		}

		// Remove collected bids
		for _, bid := range bidsToRemove {
			delete(targetMap, bid.TargetTxHash)
			delete(bp.bidWinnerMap[blockNum], bid.Sender)
			delete(bp.bidMap, bid.Hash())
		}
	}

	numBidsGauge.Update(int64(len(bp.bidMap)))
}

func (bp *BidPool) insertBid(bid *auction.Bid) error {
	bp.bidMu.Lock()
	defer bp.bidMu.Unlock()

	var (
		blockNumber  = bid.BlockNumber
		targetTxHash = bid.TargetTxHash
		sender       = bid.Sender
	)

	// Re-check bidWinnerMap here — two concurrent bids can pass validateBid together.
	if _, ok := bp.bidMap[bid.Hash()]; ok {
		return auction.ErrBidAlreadyExists
	}
	if bp.senderHasDifferentWinner(bid) {
		return auction.ErrBidSenderExists
	}

	// If same block number, same target tx hash exists, replace it if it's better
	if existingBid, ok := bp.bidTargetMap[blockNumber][targetTxHash]; ok {
		// FCFS if the bid is the same.
		if existingBid.Bid.Cmp(bid.Bid) >= 0 {
			return auction.ErrLowBid
		}

		logger.Trace("Replace bid", "old", existingBid.Hash(), "new", bid.Hash())
		delete(bp.bidMap, existingBid.Hash())
		delete(bp.bidWinnerMap[blockNumber], existingBid.Sender)
	} else {
		if int64(len(bp.bidMap)) >= bp.maxBidPoolSize {
			logger.Info("Bid pool is full", "maxBidPoolSize", bp.maxBidPoolSize, "bid", bid.Hash())
			return auction.ErrBidPoolFull
		}
	}

	hash := bid.Hash()

	bp.initializeBidMap(blockNumber)

	bp.bidMap[hash] = bid
	bp.bidTargetMap[blockNumber][targetTxHash] = bid
	bp.bidWinnerMap[blockNumber][sender] = hash

	numBidsGauge.Update(int64(len(bp.bidMap)))

	logger.Trace("Add bid", "bid", hash)

	return nil
}

func (bp *BidPool) validateBid(bid *auction.Bid) error {
	blockNumber := bid.BlockNumber

	bp.bidMu.RLock()

	// Check if the auction tx is already in the pool.
	if _, ok := bp.bidMap[bid.Hash()]; ok {
		bp.bidMu.RUnlock()
		return auction.ErrBidAlreadyExists
	}

	// 1. The `bid.Sender` must not be in the winner list of the same block number if the new bid isn't equal to the previous bid.
	if bp.senderHasDifferentWinner(bid) {
		bp.bidMu.RUnlock()
		return auction.ErrBidSenderExists
	}
	bp.bidMu.RUnlock()

	curBlock := bp.Chain.CurrentBlock()
	if curBlock == nil {
		return auction.ErrBlockNotFound
	}

	// 2. The `bid.BlockNumber` must be in range of `[currentBlockNumber + 1, currentBlockNumber + allowFutureBlock]`.
	curNum := curBlock.NumberU64()
	if blockNumber <= curNum || blockNumber > curNum+allowFutureBlock {
		return auction.ErrInvalidBlockNumber
	}

	// 3. The `bid.Bid` must be greater than 0.
	if bid.Bid.Sign() <= 0 {
		return auction.ErrZeroBid
	}

	// 4. The data size must be less than the maximum limit.
	if uint64(len(bid.Data)) > BidTxMaxDataSize {
		return auction.ErrExceedMaxDataSize
	}

	// 5. The gas limit must be less than the maximum limit.
	if bid.CallGasLimit > BidTxMaxCallGasLimit {
		return auction.ErrExceedMaxCallGasLimit
	}

	// 6. The `bid.SearcherSig` and `bid.AuctioneerSig` must be valid.
	if err := bp.validateBidSigs(bid); err != nil {
		return err
	}

	return nil
}
