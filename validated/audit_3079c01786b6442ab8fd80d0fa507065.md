### Title
Nil-pointer dereference crash in `PubkeyBytesToSeiPubKey` on malformed pubkey bytes - ([File: utils/helpers/address.go])

### Summary
`PubkeyBytesToSeiPubKey` discards the error returned by `btcec.ParsePubKey` and unconditionally calls `SerializeCompressed()` on the (possibly nil) result, mirroring the CVE-2023-25742 bug class where a malformed/wrong-type key is fed into a parser whose result is used without validating success, crashing the caller.

### Finding Description
`PubkeyBytesToSeiPubKey` is:
```go
func PubkeyBytesToSeiPubKey(pub []byte) secp256k1.PubKey {
	pubkeyObj, _ := btcec.ParsePubKey(pub)
	return secp256k1.PubKey{Key: pubkeyObj.SerializeCompressed()}
}
``` [1](#0-0) 
If `btcec.ParsePubKey(pub)` fails (e.g., `pub` is not a valid point on the secp256k1 curve, wrong length, or otherwise malformed), `pubkeyObj` is `nil` and the error is silently dropped, so the subsequent `pubkeyObj.SerializeCompressed()` call dereferences a nil pointer and panics.

This helper is called from `GetAddressesFromPubkeyBytes`:
```go
func GetAddressesFromPubkeyBytes(pubkey []byte) (common.Address, sdk.AccAddress, cryptotypes.PubKey, error) {
	evmAddr, err := PubkeyToEVMAddress(pubkey)
	...
	seiPubkey := PubkeyBytesToSeiPubKey(pubkey)
	...
}
``` [2](#0-1) 

The two production entry points that feed `pub` into this path are:
1. `GetAddresses` → `RecoverPubkey` (ECDSA recovery via `crypto.Ecrecover`), used by the `addr` precompile's `associate` method and by the EVM ante-handler tx/authorization recovery paths. `crypto.Ecrecover` only ever returns valid curve points on success, so this path is not exploitable.
2. `associatePublicKey` in the `addr` precompile (and all its legacy versions), which decodes an attacker-supplied hex string and already validates it with `btcec.ParsePubKey` before re-serializing and calling `GetAddressesFromPubkeyBytes` with the *already-validated* uncompressed bytes: [3](#0-2) 

Because both current call sites happen to pre-validate the bytes before they reach `PubkeyBytesToSeiPubKey`, the nil-pointer panic is not reachable from either currently-wired precompile or ante-handler entry point in this snapshot of the code. The bug is nonetheless a real, unguarded landmine identical in class to CVE-2023-25742 (unchecked/mismatched key parse result used downstream causing a crash): any future caller (or any legacy/precompile variant not covered in this scan) that passes attacker-controlled bytes to `GetAddressesFromPubkeyBytes`/`PubkeyBytesToSeiPubKey` without pre-validating via `ParsePubKey` will crash the node process handling that transaction.

### Impact Explanation
If reached with malformed input, this causes an unrecovered Go nil-pointer panic. Depending on where the panic occurs (inside a precompile call during `DeliverTx`/`CheckTx`), this could crash the EVM/precompile execution path, which in Cosmos SDK applications is normally caught by a top-level `recover()` in the baseapp, converting it into a failed tx rather than a full node crash — but any call path that invokes this helper outside of ABCI's protected message handling (e.g. RPC helper functions or unprotected goroutines) could crash a public RPC node. Given all identified current call sites pre-validate the input, the concretely provable impact in-scope today is limited/unproven rather than a fund-loss or chain-halt bug.

### Likelihood Explanation
Low under the current call graph, since both reachable production callers (`associate` via `Ecrecover` and `associatePublicKey` via pre-validated `btcec.ParsePubKey`) guard against malformed keys before invoking the vulnerable helper. The unguarded error-discard itself, however, is a latent defect that would become High severity the moment any new or legacy caller passes unvalidated bytes into `GetAddressesFromPubkeyBytes`.

### Recommendation
Change `PubkeyBytesToSeiPubKey` to return an error and propagate it to all callers:
```go
func PubkeyBytesToSeiPubKey(pub []byte) (secp256k1.PubKey, error) {
	pubkeyObj, err := btcec.ParsePubKey(pub)
	if err != nil {
		return secp256k1.PubKey{}, err
	}
	return secp256k1.PubKey{Key: pubkeyObj.SerializeCompressed()}, nil
}
```
and update `GetAddressesFromPubkeyBytes` to check and return that error, eliminating the possibility of a nil dereference regardless of future call sites.

### Proof of Concept
Not concretely exploitable via any currently-wired production entry point found in this scan (`associate`/`associatePublicKey` both pre-validate the pubkey bytes before reaching `PubkeyBytesToSeiPubKey`). A direct unit-level PoC:
```go
func TestPubkeyBytesToSeiPubKey_Panic(t *testing.T) {
    // Any byte sequence that fails btcec.ParsePubKey, e.g. all-zero or wrong length.
    bad := make([]byte, 65)
    bad[0] = 0x04 // pass PubkeyToEVMAddress's prefix check but not on-curve
    _, _, _, err := helpers.GetAddressesFromPubkeyBytes(bad) // panics instead of returning err
}
