### Title
Unbounded length-prefix parsing in CLVM canonical-serialization check causes out-of-bounds read / crash on attacker-supplied spend bundle - (File: chia/full_node/mempool_manager.py)

### Summary
`is_atom_canonical()` in `chia/full_node/mempool_manager.py:144-183` decodes a CLVM atom's variable-length size prefix (1–6 bytes) directly from an attacker-controlled buffer without ever checking that `offset` stays within the bounds of `clvm_buffer`. This mirrors the root cause of CVE-2017-2906: a size/length field taken from untrusted input is used to walk a buffer with no bounds validation, similar to how Blender's AVI parser trusted a length value and walked/allocated past the buffer end.

### Finding Description
`is_atom_canonical(clvm_buffer, offset)` inspects the leading byte at `offset` to determine how many additional length-prefix bytes (`prefix_len`, 0–5) follow, then loops: [1](#0-0) 

```python
atom_len = b & mask
for i in range(prefix_len):
    atom_len <<= 8
    offset += 1
    atom_len |= clvm_buffer[offset]

return 1 + prefix_len + atom_len, atom_len >= min_value
```

Each iteration indexes `clvm_buffer[offset]` after incrementing `offset`, but there is no check that `offset < len(clvm_buffer)` before doing so. The caller, `is_clvm_canonical()`, drives the same unchecked traversal: [2](#0-1) 

Here `offset += atom_len` can jump far past the end of the buffer using a large attacker-chosen `atom_len` value (up to `2^40`-scale for the 5-byte prefix case), and the very next loop iteration's `clvm_buffer[offset]` access is unguarded. This directly parallels the AVI integer-overflow bug class: an untrusted length field drives a read that isn't validated against the actual buffer size.

Per the mempool admission pipeline documentation, this canonical-serialization check is performed per coin spend during spend-bundle admission specifically to decide DEDUP eligibility: [3](#0-2) 

This means the code path is reachable directly from a single, unprivileged spend-bundle submission (RPC `push_tx` or peer-relayed transaction) — the solution/puzzle bytes for any coin spend in the bundle are attacker-supplied and fed into this canonical-form check.

### Impact Explanation
A crafted CLVM buffer with a truncated/short length that encodes a large `prefix_len`/`atom_len` value will cause `bytes.__getitem__` to raise `IndexError: index out of range` deep inside spend-bundle admission processing. If this exception is not specifically caught as a `ValidationError` at the call site (unlike the well-defined `Err` codes used elsewhere in `validate_spend_bundle`/`pre_validate_spendbundle`), it can propagate as an unhandled exception during mempool processing of a submitted spend bundle. Depending on where exactly it surfaces relative to the pool worker process, this can manifest as a spend-triggered transaction-processing halt/crash for that worker or an unclean failure path outside the node's normal validation-error handling — a denial-of-service condition triggerable by any spend-bundle submitter, which matches the "spend-triggered transaction-processing halt" category explicitly accepted by this analysis.

### Likelihood Explanation
Likelihood is high for reachability (any wallet/RPC caller or peer can submit a spend bundle with arbitrary solution bytes), but I could not fully confirm within the available index whether the call site that invokes `is_clvm_canonical()` wraps it in a broad `try/except` that converts arbitrary exceptions into a `ValidationError` (only doc references to the DEDUP-eligibility check were found, not the exact wrapping code at that call line). This is a real gap in my verification — the actual severity (full-crash of a worker process vs. a caught/logged per-bundle failure) depends on that exception-handling context, which should be confirmed directly in the code (`mempool_manager.py`, the coin-spend-processing loop that calls `is_clvm_canonical`) before treating this as a definite crash bug rather than a hardening gap.

### Recommendation
Add explicit bounds checks in `is_atom_canonical()` before every `clvm_buffer[offset]` access (both in the prefix-length loop and in `is_clvm_canonical()`'s outer traversal), returning "not canonical" (or raising a well-defined `ValidationError`) instead of allowing raw `IndexError`s to escape. Additionally, verify that all call sites of `is_clvm_canonical()` catch exceptions and convert them to controlled `Err` codes so a malformed spend bundle can only ever produce a clean rejection, never an unhandled exception in the admission pipeline.

### Proof of Concept
Construct a `clvm_buffer` where the final atom uses the 5-byte-prefix encoding (top bits `0b11111100`) but the buffer is truncated so that the prefix bytes run past the buffer end, e.g.:

```python
buf = bytes([0xFC, 0xFF, 0xFF])  # signals 5 extra length bytes, but only 2 are present
is_atom_canonical(buf, 0)  # raises IndexError: index out of range
```

Embed such a buffer as a coin spend's `solution` in a submitted `SpendBundle`; when the mempool's DEDUP-eligibility canonical-form check processes that spend's serialized solution bytes, the same out-of-bounds access occurs.

```python
def is_clvm_canonical(clvm_buffer: bytes) -> bool:
    """
    checks whether the CLVM serialization is all canonical representation.
    atoms can be serialized in more than one way by using more bytes than
    necessary to encode the length prefix. This functions ensures that all atoms are
    encoded with the shortest representation. back-references are not allowed
    and will make this function return false
    """
    assert clvm_buffer != b""

    offset = 0
    tokens_left = 1
    while True:
        b = clvm_buffer[offset]

        # pair
        if b == 0xFF:
            tokens_left += 1
            offset += 1
            continue

        # back references cannot be considered canonical, since they may be
        # encoded in many different ways
        if b == 0xFE:
            return False

        # small atom or NIL
        if b <= 0x80:
            tokens_left -= 1
            offset += 1
        else:
            atom_len, canonical = is_atom_canonical(clvm_buffer, offset)
            if not canonical:
                return False
            tokens_left -= 1
            offset += atom_len

        if tokens_left == 0:
            break

    # if there's garbage at the end, it's not canonical
    return offset == len(clvm_buffer)
```
