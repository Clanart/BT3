### Title
PedPoP accepts the identity point as a participant's encryption key, making every secret share sent to that participant publicly decryptable - (File: crypto/dkg/pedpop/src/encryption.rs)

### Summary
`EncryptionKeyMessage::read` deserializes the per-participant ECDH encryption key with `Ciphersuite::read_G`, which enforces only canonical encoding — not non-identity. The FROST-facing `Curve::read_G` explicitly rejects identity, but PedPoP does not use it here and `Decryption::register` performs no validation of `enc_key`. A participant who registers the identity point as their encryption key causes every ECDH shared secret for messages addressed to them to equal the identity point, so the ChaCha20 keystream is derivable by anyone. This is the direct analog of "weak sanitization lets an attacker supply a 'file' (point) of a type that should have been rejected."

### Finding Description
- `EncryptionKeyMessage::read` reads `enc_key` via `C::read_G` (`encryption.rs:57-59`), which only checks canonicality (`ciphersuite/src/lib.rs:91-101`). The identity encoding is valid and canonical for Ristretto/Ed25519/Ed448/secp256k1.
- `Curve::read_G` (`frost/src/curve/mod.rs:125-131`) rejects identity, showing the codebase intends this check, but PedPoP uses the raw `Ciphersuite` version.
- `Decryption::register` inserts `msg.enc_key` unconditionally (`encryption.rs:351-362`).
- Senders encrypt shares to participant `P` with `encrypt(...)` → `ecdh(key, to)` = `to * key` (`encryption.rs:95-97, 154`). If `to` (i.e., `enc_key_P`) is the identity, the shared point is identity regardless of the ephemeral scalar.
- `cipher` derives the ChaCha20 key solely from `context` and the shared point's encoding (`encryption.rs:101-133`), so the keystream for a zero shared secret is fully computable by any observer of the authenticated channel.
- No other check catches this: the DKG PoK (`challenge` in `pedpop/src/lib.rs:86-94`) covers the commitments, not the encryption key, and `verify_r1` (`lib.rs:300-338`) never inspects `enc_key`.

### Impact Explanation
Every `EncryptedMessage` addressed to the malicious participant — i.e., all `n-1` secret shares `f_i(P)` — is encrypted under a publicly known key. Any party observing the DKG transcript (which is required to be authenticated, not confidential, for the commitments; the shares are only protected by this ECDH layer) recovers participant `P`'s full interpolated secret share `sum_i f_i(P)`. That is concrete key-share recovery from public inputs only, weakening the effective threshold of the resulting `ThresholdKeys`: an adversary needs only `t-1` further shares instead of `t`, and the victim participant cannot detect it.

### Likelihood Explanation
Any DKG participant can do this deterministically at protocol start by broadcasting a syntactically valid commitments message whose trailing `enc_key` field is the canonical identity encoding. No collusion, no hash grinding, no special positioning is required; the bytes pass every check in `read`/`register`/`verify_r1`.

### Recommendation
Reject the identity point when reading/registering encryption keys: use `Curve::read_G`-equivalent logic (or an explicit `enc_key.is_identity()` check) in `EncryptionKeyMessage::read` and in `EncryptedMessage::read`/`Decryption::register`, and add a regression test registering an identity `enc_key`. Consider also binding `enc_key` into the commitments PoK transcript so key substitution is attributable.

### Proof of Concept
```rust
// Attacker (participant P) builds their round-1 message manually:
// valid Commitments<C> + sig, but enc_key = identity.
let mut msg = commitments.serialize();           // t points + Schnorr sig
msg.extend(<Ristretto as Ciphersuite>::G::identity().to_bytes()); // 32 zero bytes

// Honest participant Q:
let ekm = EncryptionKeyMessage::<Ristretto, Commitments<Ristretto>>::read(
    &mut msg.as_slice(), params).unwrap();        // succeeds; enc_key = identity
machine.register(P, ekm);                          // accepted, no identity check

// Q encrypts share to P:
//   ecdh(ephemeral, identity) = identity
//   cipher(context, identity) -> keystream K known to everyone
// Observer recomputes K = ChaCha20::new(H("DKG Encryption v0.2" || context ||
//   "encryption_key" || identity_encoding), "DKG IV v0.2\0") and XORs the
// ciphertext, recovering P's secret share in plaintext.
```
All steps use only public transcripts plus attacker-chosen bytes; the deserialization path that should reject the identity "type" accepts it.
