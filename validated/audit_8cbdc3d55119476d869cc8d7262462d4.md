### Title
Universal, path-scoped `safe.directory` trust exception outlives repository identity, letting a later attacker-controlled directory silently bypass Git's ownership check - (File: `app/src/lib/git/config.ts`)

### Summary
GitHub Desktop's "Trust Repository" flow calls `addSafeDirectory()`, which permanently adds the file-system **path** to the global Git config key `safe.directory` [1](#0-0) . This mirrors the LUKSO finding exactly: a permission ("trust this directory, skip the dubious-ownership check") is stored under a **universal key** (the bare path) instead of being scoped to the identity of the content that earned the trust (e.g. the repository's remote URL, its `.git` object identity, or its current owner). Once granted, Desktop never revokes or re-scopes this trust — there is no `removeSafeDirectory` call anywhere in the codebase.

### Finding Description
`getRepositoryType()` detects Git's "dubious ownership" error and returns `{ kind: 'unsafe', path }` [2](#0-1) . The UI (`AddExistingRepository` and `MissingRepository`) offers a "Trust Repository" button that calls `addSafeDirectory(path)`, which just does `git config --global --add safe.directory <path>` [3](#0-2) [4](#0-3) [5](#0-4) .

Git's `safe.directory` mechanism trusts a **path**, not a repository's content or identity. Once a path is in the global `safe.directory` list, Git skips the ownership check for whatever is at that path forever, regardless of who owns it later. Desktop:
- Never removes an entry when a repository is deleted from Desktop's tracked list (`repositories-store.ts` has no corresponding cleanup) — confirmed no `removeSafeDirectory`/cleanup call exists anywhere in the codebase.
- Never re-validates that the directory still holds the same repository/remote before reusing the trust.
- Allows a missing repository to be relocated ("Locate…") or a new repository to be cloned/added at the same path later, silently inheriting the old trust grant with no new prompt.

This is the exact "universal data key" anti-pattern from the report: the trust decision ("this owner/content is safe") is keyed on something reusable and outlives the specific object it was granted for, so a subsequent, attacker-controlled object at that same key inherits privileges it never earned.

### Impact Explanation
`safe.directory` exists specifically to stop execution of untrusted repository content (hooks, `core.fsmonitor`, `.git/config` includes, sparse-checkout, etc.) when directory ownership is "dubious" (e.g., a shared/multi-user machine, a mounted network share, a container volume, or a directory an attacker with local write access populated). Once a directory has been trusted via Desktop, an attacker who later gains control of that same path (e.g. a shared workstation, a re-mounted network drive, a directory recreated by a different OS user, or a directory reused by "Clone Again"/"Locate…" after the original repo was removed) gets ownership-check bypass for free — Desktop/Git will operate on the attacker's repository content as if it were still the originally-trusted one, enabling execution of malicious git hooks/config and potential file writes/reads outside expectations, without any new warning to the user.

### Likelihood Explanation
Requires: (1) a Desktop user to have trusted at least one directory once (a common flow on shared machines, VMs, network shares, or after moving repos), and (2) that same path later being repopulated by an untrusted party or a different owner (shared machine reuse, network-share remount, container/dev-environment reuse, or Desktop's own "Clone Again"/"Locate…" pointing at a stale path). This is plausible in enterprise/shared-machine and CI/dev-container scenarios that GitHub Desktop explicitly targets with the safe-directory feature (see changelog entries for "Trust repositories on network shares"). It requires no local malware, no admin rights, and no unnatural user action beyond normal repository management (remove/relocate/re-clone) — the same "unfounded trust" caveat the LUKSO judge flagged applies here too, keeping this a solid Medium-class rug-pull-style finding rather than High.

### Recommendation
Scope trust to repository identity, not path:
- When adding a safe-directory exception, also record identity data at the moment of trust (e.g., initial remote URL and/or the SHA of the initial commit / `.git` object) in Desktop's own repositories DB.
- Before relying on an existing `safe.directory` entry, Desktop should re-verify the directory still corresponds to the same tracked repository (compare remote URL / initial commit) and re-prompt if it changed.
- On `removeRepository`/when a repository becomes `missing` and the user chooses not to relocate it to the same content, remove the corresponding `safe.directory` entry (`git config --global --unset safe.directory <path>`).
- Consider using ownership + content fingerprint checks rather than a bare path as the trust key, analogous to hashing the permission with an owner-specific value as recommended in the source report.

### Proof of Concept
1. On a shared machine (or VM/container image reused across users), User A adds an existing repository at `/shared/repo` owned by User A; Git reports dubious ownership; User A clicks "Trust Repository" → `addSafeDirectory('/shared/repo')` runs, adding the path to `~/.gitconfig` (or the global config of whichever profile Desktop runs under) [5](#0-4) .
2. User A later removes the repository from Desktop (or the directory is deleted) but the `safe.directory` entry is never cleaned up (no such call exists in the codebase).
3. An attacker (a different local user on the same shared machine, or whoever remounts the network share) recreates `/shared/repo` with a malicious `.git` directory (malicious hooks, `core.fsmonitor`, or `include.path` directives) owned by a different UID.
4. When the path is revisited — whether by Desktop's "Locate…"/"Clone Again" flow on the `MissingRepository` screen [6](#0-5)  pointing back at the same path, or by any other Desktop user on the shared machine adding `/shared/repo` again — `getRepositoryType()` still returns `regular` (not `unsafe`) because `safe.directory` still lists that path, so Git skips the ownership check entirely [7](#0-6) , and Desktop proceeds to run Git operations against the attacker's repository content without any new warning.

/**
 * Adds a path to the `safe.directories` configuration variable if it's not
 * already present. Adding a path to `safe.directory` will cause Git to ignore
 * if the path is owner by a different user than the current.
 */
export async function addSafeDirectory(path: string) {
  // UNC-paths on Windows need to be prefixed with `%(prefix)/`, see
  // https://github.com/git-for-windows/git/commit/e394a16023cbb62784e380f70ad8a833fb960d68
  if (__WIN32__ && path[0] === '/') {
    path = `%(prefix)/${path}`
  }

  await addGlobalConfigValueIfMissing('safe.directory', path)
}

export async function getRepositoryType(path: string): Promise<RepositoryType> {
  if (!(await directoryExists(path))) {
    return { kind: 'missing' }
  }

  try {
    const result = await git(
      ['rev-parse', '--is-bare-repository', '--show-cdup', '--git-dir'],
      path,
      'getRepositoryType',
      { successExitCodes: new Set([0, 128]) }
    )

    if (result.exitCode === 0) {
      // Bare repositories will not include gitdir so we handle that separately
      if (result.stdout.startsWith('true\n')) {
        return { kind: 'bare' }
      }

      // --is-bare-repository and --show-cdup each produce a single line but
      // --git-dir could theoretically contain newlines so we parse the known
      // fields first and treat the remainder as the git dir. We use [\s\S]*
      // instead of .* for the git dir capture group because .* doesn't match
      // newlines whereas [\s\S]* matches any character including newlines.
      const match = result.stdout.match(/^(true|false)\n(.*)\n([\s\S]*)\n$/)

      if (match) {
        const [, isBare, cdup, gitDir] = match

        return isBare === 'true'
          ? { kind: 'bare' }
          : {
              kind: 'regular',
              topLevelWorkingDirectory: resolve(path, cdup),
              gitDir: resolve(path, gitDir),
            }
      }
    }

    const unsafeMatch =
      /fatal: detected dubious ownership in repository at '(.+)'/.exec(
        result.stderr
      )
    if (unsafeMatch) {
      return { kind: 'unsafe', path: unsafeMatch[1] }
    }

    return { kind: 'missing' }
