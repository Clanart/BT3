### Title
Governance-settable `KIP71.GasTarget = 0` causes division-by-zero panic in `NextMagmaBlockBaseFee`, crashing every node - ([File: params/kip71_config.go])

### Summary
`KIP71Config.NextMagmaBlockBaseFee` divides by the governance parameter `GasTarget` without checking for zero, unlike the adjacent `BaseFeeDenominator` divisor which has an explicit zero-guard. Since `Kip71GasTarget`'s `FormatChecker` is a `noopFormatChecker` that accepts any `uint64` including `0`, a governance vote setting `GasTarget=0` will cause every node computing/verifying the next block's base fee to panic with a Go `runtime error: integer divide by zero`, once any block has non-zero gas used.

### Finding Description
`NextMagmaBlockBaseFee` computes the fluctuation of the base fee using `gasTarget := kc.GasTarget` as a divisor in both the "gas used > target" and "gas used < target" branches: [3](#0-2) 

Note that `BaseFeeDenominator` (used a few lines earlier) is explicitly protected: `if kc.BaseFeeDenominator == 0 { baseFeeDenominator = 64 }` at [4](#0-3) , but no such guard exists for `gasTarget`.

If `gasTarget == 0` and `parentGasUsed > 0` (true for essentially every real block), the code takes the "gasUsed > gasTarget" branch and executes `x.Div(x, new(big.Int).SetUint64(gasTarget))` at [5](#0-4) , i.e. `big.Int.Div(x, 0)`, which panics in Go's `math/big` package (`division by zero`) rather than returning an error.

`GasTarget` is a normal governance-votable parameter (`kip71.gastarget`), defined with `Canonicalizer: uint64Canonicalizer, FormatChecker: noopFormatChecker` — i.e., no validation preventing zero — at [1](#0-0) . Contrast this with the sibling parameter `Kip71BaseFeeDenominator`, whose `FormatChecker` explicitly requires `v != 0` [2](#0-1) . The header-vote consistency checker `checkConsistency` in `headergov` also does not perform any extra validation for `gov.Kip71GasTarget`, only for `Kip71LowerBoundBaseFee`/`Kip71UpperBoundBaseFee` (compared against each other) [6](#0-5) .

`NextMagmaBlockBaseFee` is called from `VerifyMagmaHeader`, which is executed by every node validating any block header after the Magma hardfork [7](#0-6) , and also from public-RPC-facing code such as `feehistory.go`'s `processBlock` [8](#0-7) .

### Impact Explanation
A single successful governance vote setting `kip71.gastarget` to `0` (canonicalization/format-checking accepts it, per the `noopFormatChecker`) becomes active at the next epoch. From that point, as soon as any block with nonzero `GasUsed` is processed, every full node (proposer, validators, and any RPC/full node computing `NextMagmaBlockBaseFee` or serving `eth_feeHistory`) will panic and crash. This is a chain-halting, network-wide Denial of Service: consensus cannot proceed because header validation itself panics, matching the "acceptance of an invalid transaction or block" / "state divergence" impact category via an unrecoverable crash instead of a graceful rejection.

### Likelihood Explanation
Reaching this bug requires a successful governance vote to set `GasTarget = 0`, which is a higher bar than a fully permissionless single transaction, but it is squarely in the explicitly in-scope "governance parameters" category, and — critically — there is no validation anywhere in the vote/format-checking pipeline that rejects the value `0` for `GasTarget`, unlike the sibling parameter `BaseFeeDenominator`. This asymmetry strongly suggests a missing safeguard (an oversight relative to the already-fixed `BaseFeeDenominator` case) rather than an intentional design decision, making it a realistic misconfiguration/malicious-governance path to a full network crash.

### Recommendation
Add a zero-guard for `gasTarget` in `NextMagmaBlockBaseFee` analogous to the existing `BaseFeeDenominator` guard (e.g., fall back to a safe default or treat `gasTarget == 0` as `parentGasUsed == gasTarget` never satisfied and use a fixed floor), and/or add a `FormatChecker` for `Kip71GasTarget` in `kaiax/gov/param.go` that rejects `0`, mirroring `Kip71BaseFeeDenominator`'s `v != 0` check.

### Proof of Concept
1. Submit/pass a governance vote for `kip71.gastarget = 0` (format-checker in `kaiax/gov/param.go` accepts any `uint64`, including `0`, via `noopFormatChecker`).
2. Wait for the vote to take effect at the next epoch boundary so `KIP71Config.GasTarget == 0`.
3. Any subsequent block with `GasUsed > 0` (virtually guaranteed) causes `NextMagmaBlockBaseFee` to hit the branch `parentGasUsed > gasTarget` (since `parentGasUsed > 0 = gasTarget`), executing `x.Div(x, new(big.Int).SetUint64(0))`, which panics with `runtime error: integer divide by zero` in every node calling `VerifyMagmaHeader`/`NextMagmaBlockBaseFee` (header validation, block building, and `eth_feeHistory` RPC), crashing the network. This can be reproduced directly by unit-testing `KIP71Config.NextMagmaBlockBaseFee` with `GasTarget: 0` and `parentHeaderGasUsed > 0`, as in the existing test harness at [9](#0-8)  (which currently only tests `gasTarget=30000000`, never `0`).

func (kc *KIP71Config) VerifyMagmaHeader(headerBaseFee *big.Int, parentHeaderNumber *big.Int, parentHeaderBaseFee *big.Int, parentHeaderGasUsed uint64) error {
	if headerBaseFee == nil {
		return fmt.Errorf("header is missing baseFee")
	}
	// Verify the baseFee is correct based on the parent header.
	expectedBaseFee := kc.NextMagmaBlockBaseFee(parentHeaderNumber, parentHeaderBaseFee, parentHeaderGasUsed)
	if headerBaseFee.Cmp(expectedBaseFee) != 0 {
		return fmt.Errorf("invalid baseFee: have %s, want %s, parentBaseFee %s, parentGasUsed %d",
			headerBaseFee, expectedBaseFee, parentHeaderBaseFee, parentHeaderGasUsed)
	}
	return nil
}
