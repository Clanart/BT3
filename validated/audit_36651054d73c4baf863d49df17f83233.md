### Title
EVM WebSocket plane (`:8546`) entirely omits per-IP rate-limit admission control enforced on the HTTP plane - (File: evmrpc/server.go)

### Summary
The Ocelot CVE bypasses IP allow/block enforcement because the WebSocket-upgrade branch of the pipeline (`MapWhen`) never wires in `SecurityMiddleware`. Sei-chain's EVM JSON-RPC has the analogous structural split: HTTP (`:8545`) and WebSocket (`:8546`) are built from two independent config/handler paths, and only the HTTP path constructs and wires a per-IP admission gate (`ratelimiter.Gate`). The WebSocket path never builds or attaches an equivalent gate, so the per-IP admission control that the HTTP plane enforces does not exist at all for WS clients.

### Finding Description
`NewEVMHTTPServer` builds a `ratelimiter.Gate` from `config.RateLimiterConfig()` when `config.RateLimitingEnabled` is set, stores it on `httpConfig.rateLimitGate`, and `HTTPServer.EnableRPC` wires it into the handler chain via `newRateLimitMiddleware(...)`, which is documented as the second stage of the HTTP middleware stack: `jwt → requestSizeLimiter → rateLimitMiddleware → seiLegacyHTTPGate → gzip → vhost → cors → rpc.Server`. [1](#0-0) [2](#0-1) 

By contrast, `NewEVMWebSocketServer` builds a `WsConfig` and never constructs or assigns any `ratelimiter.Gate` at all. [3](#0-2) 

Structurally, `WsConfig` doesn't even carry a `rateLimitGate` field, unlike `HTTPConfig` which explicitly has one (`rateLimitGate *ratelimiter.Gate`). [4](#0-3) 

Consistent with that, `HTTPServer.EnableWS` never calls `newRateLimitMiddleware`, and `NewWSHandlerStack` only wraps the raw websocket handler with an optional JWT handler and `NewWSConnectionHandler` — the per-IP `rateLimitMiddleware` layer present on the HTTP stack (`NewHTTPHandlerStack`) is simply absent from the WS stack. [5](#0-4) [6](#0-5) 

The `rateLimitMiddleware.ServeHTTP` on the HTTP path is exactly the layer responsible for admitting/rejecting requests per source IP based on `ip_rate_limit_rps`/`ip_rate_limit_burst`/`rate_limiting_enabled`. [7](#0-6) 

The config documentation frames `rate_limiting_enabled` as "the master switch for the rate-limit admission middleware on the EVM HTTP plane (:8545)" — the WS plane (:8546) is not mentioned as being covered by this switch at all. [8](#0-7) 

The WS plane does have some independent protections (byte-budget via `SetWSConcurrentRequestBytes`/`readLimit`, and `SetWSAdmissionTimeout`), but these bound per-connection/global byte and wait-time budgets — they are not a per-source-IP token-bucket admission control equivalent to what HTTP enforces. [9](#0-8) 

### Impact Explanation
Any unprivileged client can connect over `eth_subscribe`/JSON-RPC WebSocket (`:8546`) and send an unbounded rate of requests (subscriptions, `eth_call`s, batched RPCs, etc.) from a single or many source IPs without ever passing through the per-IP token-bucket admission gate that would throttle or reject an equivalent flood on the HTTP plane. This is precisely the same class of bug as the CVE: a security-relevant admission control that is enforced on the primary HTTP pipeline branch is silently absent from the WebSocket-upgrade branch. On a default-configuration public EVM RPC node (`rate_limiting_enabled = true`, `ip_rate_limit_rps`/`burst` set) the WS listener still admits requests from a single IP with no throttling ceiling, which can be used to exhaust worker-pool/DB-semaphore resources shared with the HTTP plane (`GetGlobalWorkerPool()`, `dbReadSemaphore`) and starve or crash the node process for other RPC users, a public-RPC-node crash/DoS through purely a public JSON-RPC endpoint with no privileged access needed.

### Likelihood Explanation
High. `NewEVMWebSocketServer` unconditionally starts the WS handler without ever constructing a `ratelimiter.Gate`, regardless of the operator's `rate_limiting_enabled`/`ip_rate_limit_rps` settings — there is no configuration flag that can enable it because `WsConfig` has no such field to populate. Every node running the default WS endpoint (`:8546`) is affected the moment WS is enabled, and the trigger requires nothing more than opening a WebSocket connection and sending a normal (or high-volume) JSON-RPC payload — well within reach of any public, unprivileged client.

### Recommendation
Add a `rateLimitGate *ratelimiter.Gate` field to `WsConfig` (mirroring `HTTPConfig`), construct it in `NewEVMWebSocketServer` the same way `NewEVMHTTPServer` does (from `config.RateLimiterConfig()`/`config.RateLimitingEnabled`), and wrap the WS handler in an equivalent per-IP admission middleware (either reusing `rateLimitMiddleware` adapted for the WS upgrade request, or gating admission at `wsConnection` read time) inside `HTTPServer.EnableWS`/`NewWSHandlerStack`, so the WS plane enforces the same `ip_rate_limit_rps`/`ip_rate_limit_burst` policy the HTTP plane does.

### Proof of Concept
1. Start a `seid` node with default EVM config: `rate_limiting_enabled = true`, `ip_rate_limit_rps = <low value>`, `ip_rate_limit_burst = <small>` on `:8545`, and WS enabled on `:8546`.
2. Confirm HTTP throttling: repeatedly POST JSON-RPC requests to `:8545` from one IP; observe HTTP 429 once the bucket is exhausted (via `rateLimitMiddleware.ServeHTTP`, `evmrpc/rate_limit_middleware.go:27-71`).
3. Open a WebSocket connection to `:8546` from the same IP and send the same volume/rate of JSON-RPC requests (e.g., repeated `eth_call`/`eth_subscribe`).
4. Observe no HTTP 429/rejection equivalent occurs for the WS connection regardless of volume, because `NewEVMWebSocketServer` (`evmrpc/server.go:344-354`) never builds or attaches a `ratelimiter.Gate`, and `HTTPServer.EnableWS`/`NewWSHandlerStack` (`evmrpc/rpcstack.go:390-422`, `444-462`) never invoke `newRateLimitMiddleware` — the per-IP admission control that gates the HTTP plane is structurally unreachable from the WS plane.

```go
// EnableWS turns on JSON-RPC over WebSocket on the server.
func (h *HTTPServer) EnableWS(apis []rpc.API, config WsConfig) error {
	h.mu.Lock()
	defer h.mu.Unlock()

	if h.wsAllowed() {
		return fmt.Errorf("JSON-RPC over WebSocket is already enabled")
	}
	// Create RPC server and handler.
	srv := rpc.NewServer()
	srv.SetBatchLimits(config.batchItemLimit, config.batchResponseSizeLimit)
	readLimit := effectiveMaxRequestBodyBytes(config.readLimit)
	srv.SetReadLimits(readLimit)
	// maxConcurrentRequestBytes is passed through raw; rpc.Server.recomputeWSConcurrentBudget
	// raises it to readLimit when smaller, matching
	// newRequestSizeLimiter's max(budget, maxBody) rule on the HTTP protocol.
	srv.SetWSConcurrentRequestBytes(config.maxConcurrentRequestBytes)
	srv.SetWSAdmissionTimeout(config.wsAdmissionTimeout)
	srv.SetWSAdmissionEventHook(func(reason string) {
		// Hook carries no request context, and the fork's own connCtx is context.Background() too.
		recordWSAdmissionRejected(context.Background(), reason)
	})
	logger.Info("Registering apis for evm websocket")
	if err := RegisterApis(apis, config.Modules, srv); err != nil {
		return err
	}
	h.WsConfig = config
	h.wsHandler.Store(&rpcHandler{
		Handler: NewWSHandlerStack(srv.WebsocketHandler(config.Origins), config.JwtSecret),
		server:  srv,
	})
	return nil
}
```

```go
// NewHTTPHandlerStack returns wrapped http-related handlers.
func NewHTTPHandlerStack(srv http.Handler, cors []string, vhosts []string, JwtSecret []byte) http.Handler {
	// Wrap the CORS-handler within a host-handler
	handler := newCorsHandler(srv, cors)
	handler = newVHostHandler(vhosts, handler)
	if len(JwtSecret) != 0 {
		handler = newJWTHandler(JwtSecret, handler)
	}
	return NewGzipHandler(handler)
}

// NewWSHandlerStack returns a wrapped ws-related handler.
func NewWSHandlerStack(srv http.Handler, JwtSecret []byte) http.Handler {
	handler := srv
	if len(JwtSecret) != 0 {
		handler = newJWTHandler(JwtSecret, handler)
	}
	return NewWSConnectionHandler(handler)
}
```

```go
func newRateLimitMiddleware(inner http.Handler, gate *ratelimiter.Gate) http.Handler {
	if gate == nil {
		return inner
	}
	return &rateLimitMiddleware{inner: inner, gate: gate}
}

func (m *rateLimitMiddleware) ServeHTTP(w http.ResponseWriter, r *http.Request) {
	if isRateLimitExemptHTTPRequest(r) {
		m.inner.ServeHTTP(w, r)
		return
	}

	ip := m.gate.Registry().IPFromHTTPRequest(r)
	body, err := readBoundedBody(r.Body, m.gate.MaxBodyBytes())
	if err != nil {
		if isRequestBodyTooLarge(err) {
			m.rejectAdmission(r.Context(), w, ip, rejectReasonOversize, http.StatusRequestEntityTooLarge, "request body too large")
			return
		}
		if errors.Is(err, errBudgetExhausted) {
			// Server-side capacity event; outer limiter already owns the response.
			return
		}
		if errors.Is(err, errSlowBody) {
			// Client-caused stall: still charge the per-IP bucket.
			m.gate.ChargeAdmissionRejection(r.Context(), ip)
			return
		}
		m.rejectAdmission(r.Context(), w, ip, rejectReasonReadError, http.StatusBadRequest, "bad request")
		return
	}
	r.Body = io.NopCloser(bytes.NewReader(body))
```
