### Title
Arbitrary Directory Creation and File Write via `foldername` Parameter in DataLayer `add_missing_files` RPC - ([File: chia/data_layer/data_layer_rpc_api.py])

### Summary
The DataLayer RPC endpoint `add_missing_files` accepts an unvalidated `foldername` parameter directly from a local RPC caller and passes it through to file-system write operations that create arbitrary directories and write DataLayer tree files, mirroring the Streambert `perform-scheduled-backup` handler flaw where a caller-supplied path is used for `mkdir`/`writeFileSync` without confinement to an authorized directory.

### Finding Description
`DataLayerRpcApi.add_missing_files` reads `foldername` straight from the request dict and constructs a `Path` from it with no validation that it resides under the service's authorized `server_files_location`: [1](#0-0) 

That value is forwarded unchanged into `DataLayer.add_missing_files`, which uses it as `server_files_location` for every generation being written: [2](#0-1) 

The actual filesystem operations occur in `write_files_for_root`, which calls `filename_full_tree.parent.mkdir(parents=True, exist_ok=True)` and then opens files under that caller-controlled directory for writing (`wb`/`xb` mode), creating the target directory tree and writing DataLayer tree content (derived from local `DataStore` data) into it: [3](#0-2) 

Because `foldername` is a plain string turned into a `Path` with no check that it is confined to `server_files_location` (or any allow-listed directory), an absolute path or `../` traversal value causes `mkdir(parents=True, exist_ok=True)` to create arbitrary directories anywhere the DataLayer process has write access, and the subsequent `open(..., "wb"/"xb")` calls to write DataLayer-tree JSON/binary content into attacker-chosen locations — the same bug class as the CVE: an RPC/IPC handler trusting a caller-supplied path for `mkdir`/write operations without confining it to an authorized backup/output directory.

### Impact Explanation
A local RPC caller able to invoke the DataLayer RPC (e.g., a Data Layer client application, or any local process with RPC access) can force the DataLayer service to create directories and write files at attacker-chosen filesystem paths outside its intended `server_files_location` sandbox. This can be used to plant files in locations that are later trusted/executed/loaded by other parts of the system, or to create directories that break other services' assumptions, satisfying the "unauthorized coin movement/state divergence"-adjacent goal only weakly — the more direct impact here is uncontrolled filesystem writes from an under-scoped local RPC handler, consistent with the reported bug class (arbitrary directory creation and file manipulation via an unvalidated path parameter).

### Likelihood Explanation
Any client with access to the DataLayer RPC (which, per the scope, includes "local RPC caller") can trigger this with a single call supplying a crafted `foldername`; no additional preconditions, races, or privileged access to other subsystems are required beyond having DataLayer RPC access.

### Recommendation
Validate `foldername` in `DataLayerRpcApi.add_missing_files` (and in `DataLayer.add_missing_files` / `write_files_for_root`) by resolving it and confirming it is contained within an allow-listed base directory (e.g., `server_files_location`) before use, rejecting absolute paths or `..` traversal components that escape that base, analogous to the fix applied to Streambert's backup path handling.

### Proof of Concept
1. Start `chia data_layer` with RPC enabled.
2. Call the `add_missing_files` RPC with:
```json
{
  "ids": ["<valid store id hex>"],
  "foldername": "/tmp/attacker_controlled_dir"
}
```
3. Observe that `chia/data_layer/data_layer_rpc_api.py`'s `add_missing_files` passes this path unchecked to `DataLayer.add_missing_files`, which calls `write_files_for_root` with `foldername` as `server_files_location`, causing `mkdir(parents=True, exist_ok=True)` to create `/tmp/attacker_controlled_dir` and write `<store_id>-<node_hash>-full-...-v1.0.dat` / `...-delta-...` files into it — a directory and files outside the DataLayer's intended `server_files_location`, with no path confinement check performed anywhere in the call chain (`chia/data_layer/data_layer_rpc_api.py:401-417`, `chia/data_layer/data_layer.py:843-867`, `chia/data_layer/download_data.py:69-105`).

    async def add_missing_files(self, request: dict[str, Any]) -> EndpointResult:
        """
        complete the data server files.
        """
        if "ids" in request:
            store_ids = request["ids"]
            ids_bytes = [bytes32.from_hexstr(id) for id in store_ids]
        else:
            subscriptions: list[Subscription] = await self.service.get_subscriptions()
            ids_bytes = [subscription.store_id for subscription in subscriptions]
        overwrite = request.get("overwrite", False)
        foldername: Path | None = None
        if "foldername" in request:
            foldername = Path(request["foldername"])
        for store_id in ids_bytes:
            await self.service.add_missing_files(store_id, overwrite, foldername)
        return {}

    async def add_missing_files(self, store_id: bytes32, overwrite: bool, foldername: Path | None) -> None:
        root = await self.data_store.get_tree_root(store_id=store_id)
        latest_generation = root.generation
        full_tree_first_publish_generation = max(0, latest_generation - self.maximum_full_file_count + 1)
        singleton_record = (
            await self.wallet_rpc.dl_latest_singleton(DLLatestSingleton(launcher_id=store_id, only_confirmed=True))
        ).singleton
        if singleton_record is None:
            self.log.error(f"No singleton record found for: {store_id}")
            return
        max_generation = min(singleton_record.generation, root.generation)
        server_files_location = foldername if foldername is not None else self.server_files_location
        files = []
        for generation in range(1, max_generation + 1):
            root = await self.data_store.get_tree_root(store_id=store_id, generation=generation)
            res = await write_files_for_root(
                self.data_store,
                store_id,
                root,
                server_files_location,
                full_tree_first_publish_generation,
                overwrite,
                self.group_files_by_store,
            )
            files.append(res.diff_tree.name)

async def write_files_for_root(
    data_store: DataStore,
    store_id: bytes32,
    root: Root,
    foldername: Path,
    full_tree_first_publish_generation: int,
    overwrite: bool = False,
    group_by_store: bool = False,
) -> WriteFilesResult:
    if root.node_hash is not None:
        node_hash = root.node_hash
    else:
        node_hash = bytes32.zeros  # todo change

    filename_full_tree = get_full_tree_filename_path(foldername, store_id, node_hash, root.generation, group_by_store)
    filename_diff_tree = get_delta_filename_path(foldername, store_id, node_hash, root.generation, group_by_store)
    filename_full_tree.parent.mkdir(parents=True, exist_ok=True)

    written = False
    mode: Literal["wb", "xb"] = "wb" if overwrite else "xb"

    written_full_file = False
    if root.generation >= full_tree_first_publish_generation:
        try:
            with open(filename_full_tree, mode) as writer:
                await data_store.write_tree_to_file(root, node_hash, store_id, False, writer)
            written = True
            written_full_file = True
        except FileExistsError:
            pass

    try:
        with open(filename_diff_tree, mode) as writer:
            await data_store.write_tree_to_file(root, node_hash, store_id, True, writer)
        written = True
    except FileExistsError:
        pass
