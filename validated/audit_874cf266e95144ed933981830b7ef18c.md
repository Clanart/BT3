### Title
Identity public keys enable universally forged Schnorr signatures - ([File: crypto/schnorr/src/lib.rs](crypto/schnorr/src/lib.rs))

### Summary
`SchnorrSignature::verify` accepts the identity point as a public key and evaluates `R + cA - sG = 0` without rejecting either an identity `A` or identity `R`. Because `SchnorrSignature::read` deserializes `R` through `Ciphersuite::read_G`, which enforces canonicity but does not reject identity, untrusted bytes can encode `(R = identity, s = 0)` and verify for any challenge when `A = identity`. [1](#0-0) [2](#0-1) [3](#0-2) 

### Finding Description
`SchnorrSignature::read` accepts every canonical point encoding, including the group identity, as `R`. [1](#0-0)  `Ciphersuite::read_G` only checks `from_bytes` success and serialization round-tripping; unlike `frost::Curve::read_G`, it does not reject `is_identity()`. [3](#0-2) [4](#0-3) 

Verification constructs the equation `R + cA - sG = 0`. [5](#0-4)  If `A` and `R` are both identity and `s = 0`, all three terms are zero, so the equation holds for every possible challenge `c`. [6](#0-5) 

This is analogous to accepting a registration whose required identifying member is unavailable: the verifier proceeds with an invalid/degenerate key instead of rejecting the unsupported identity case before applying the signature equation. [2](#0-1) 

### Impact Explanation
An unprivileged party can produce a byte string that deserializes successfully and is accepted as a valid Schnorr signature for the identity public key, regardless of the challenge or message-derived value supplied by the caller. [1](#0-0) [6](#0-5) 

Any caller that accepts an attacker-controlled or deserialized public key without separately rejecting identity can therefore accept a forged signature. [3](#0-2) 

### Likelihood Explanation
The attack requires the verifier to evaluate a signature against the identity public key, which is a degenerate key that should normally be rejected during key handling. [3](#0-2)  However, the in-scope deserialization path explicitly permits canonical identity points, and the verifier itself performs no defensive identity check, so protocols relying on the primitive’s documented strictness are exposed. [7](#0-6) [6](#0-5) 

### Recommendation
Reject identity public keys in `SchnorrSignature::verify` and `SchnorrSignature::batch_verify`, returning `false` or queueing a statement guaranteed to fail before evaluating the equation. [8](#0-7)  Also reject identity `R` during `SchnorrSignature::read`, matching the stricter behavior already implemented by `frost::Curve::read_G`. [1](#0-0) [4](#0-3) 

### Proof of Concept
```rust
// For any C: Ciphersuite and arbitrary challenge:
let forged = SchnorrSignature::<C> {
  R: C::G::identity(),
  s: C::F::ZERO,
};

assert!(forged.verify(C::G::identity(), challenge));
```

The serialized equivalent is `identity.to_bytes() || zero_scalar.to_repr()`, which `SchnorrSignature::read` accepts because `C::read_G` does not reject identity. [1](#0-0) [3](#0-2)  Verification succeeds because `identity + c * identity - 0 * generator = identity`. [2](#0-1)

/// These are intended to be strict. It is generic over Ciphersuite which is for PrimeGroups,
/// and mandates canonical encodings in its read function.
///
/// RFC 8032 has an alternative verification formula, 8R = 8s - 8cX, which is intended to handle
/// torsioned nonces/public keys. Due to this library's strict requirements, such signatures will
/// not be verifiable with this library.
#[allow(non_snake_case)]
#[derive(Clone, Copy, PartialEq, Eq, Debug, Zeroize)]
pub struct SchnorrSignature<C: Ciphersuite> {
  pub R: C::G,
  pub s: C::F,
}

impl<C: Ciphersuite> SchnorrSignature<C> {
  /// Read a SchnorrSignature from something implementing Read.
  pub fn read<R: Read>(reader: &mut R) -> io::Result<Self> {
    Ok(SchnorrSignature { R: C::read_G(reader)?, s: C::read_F(reader)? })
  }

  /// Return the series of pairs whose products sum to zero for a valid signature.
  /// This is intended to be used with a multiexp.
  pub fn batch_statements(&self, public_key: C::G, challenge: C::F) -> [(C::F, C::G); 3] {
    // s = r + ca
    // sG == R + cA
    // R + cA - sG == 0
    [
      // R
      (C::F::ONE, self.R),
      // cA
      (challenge, public_key),
      // -sG
      (-self.s, C::generator()),
    ]
  }

  /// Verify a Schnorr signature for the given key with the specified challenge.
  ///
  /// This challenge must be properly crafted, which means being binding to the public key, nonce,
  /// and any message. Failure to do so will let a malicious adversary to forge signatures for
  /// different keys/messages.
  #[must_use]
  pub fn verify(&self, public_key: C::G, challenge: C::F) -> bool {
    multiexp_vartime(&self.batch_statements(public_key, challenge)).is_identity().into()
  }

  ///
  /// This challenge must be properly crafted, which means being binding to the public key, nonce,
  /// and any message. Failure to do so will let a malicious adversary to forge signatures for

    rng: &mut R,
    batch: &mut BatchVerifier<I, C::G>,
    id: I,
    public_key: C::G,
    challenge: C::F,

  fn read_G<R: Read>(reader: &mut R) -> io::Result<Self::G> {
    let mut encoding = <Self::G as GroupEncoding>::Repr::default();
    reader.read_exact(encoding.as_mut())?;

    let point = Option::<Self::G>::from(Self::G::from_bytes(&encoding))
      .ok_or_else(|| io::Error::other("invalid point"))?;
    if point.to_bytes().as_ref() != encoding.as_ref() {
      Err(io::Error::other("non-canonical point"))?;
    }
    Ok(point)
