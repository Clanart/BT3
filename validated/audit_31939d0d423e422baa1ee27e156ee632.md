### Title
`SignableTransaction::new` computes weight, vbytes, fee, and size checks over `payments` only, omitting the OP_RETURN output it appends — the reported `needed_fee` understates the fee the constructed transaction actually requires - (File: networks/bitcoin/src/wallet/send.rs)

### Summary
`SignableTransaction::new` pushes an OP_RETURN `TxOut` into `tx_outs` (lines 194–202) but then calls `Self::calculate_weight_vbytes(tx_ins.len(), payments, None)` (line 204) and `Self::calculate_weight_vbytes(tx_ins.len(), payments, Some(&change))` (lines 225–226), passing the `payments` slice rather than `tx_outs`. `calculate_weight_vbytes` builds its template transaction's `output` vector solely from `payments` plus the optional change script (lines 85–99). The actual `Transaction` stored in the returned `SignableTransaction` contains `tx_outs`, which includes the OP_RETURN output. This is the same bug class as the referenced finding: a query/estimation routine (`needed_fee`, the `TooLowFee` and `TooLargeTransaction` checks) is computed over a different transaction than the one actually built and signed.

### Finding Description
- `tx_outs` gains an extra `TxOut` for `data` at `send.rs:194-202`.
- `weight`, `vbytes`, and `needed_fee` are derived from `payments` only at `send.rs:204` and `send.rs:206`; the change-aware recomputation at `send.rs:225-227` has the same omission.
- `needed_fee` is exposed via `needed_fee()` (`send.rs:133-135`) and documented as "the fee necessary for this transaction to achieve the fee rate specified at construction," while `fee()` (`send.rs:138-141`) returns the true fee `sum(inputs) - sum(outputs)`.
- With a change output, `change_value = input_sat - payment_sat - fee_with_change` (`send.rs:228-230`), so the actual fee paid equals the underestimated `fee_with_change` — the transaction pays `fee_per_vbyte` over a vsize that excludes up to an 80-byte OP_RETURN output (~91 vbytes, ~364 weight units of base size).
- `TooLowFee` (`send.rs:211`) compares against `DEFAULT_MIN_RELAY_TX_FEE * vbytes / 1000` using the underestimated `vbytes`, so a transaction that actually falls below the minimum relay fee is accepted.
- `TooLargeTransaction` (`send.rs:241`) checks the underestimated `weight` instead of the real transaction weight.

### Impact Explanation
An unprivileged caller supplies `data` (a public input to `SignableTransaction::new`, allowed up to 80 bytes at `send.rs:171-173`). The resulting signed transaction pays a lower fee rate than requested, and can fall below `DEFAULT_MIN_RELAY_TX_FEE` while passing the `TooLowFee` guard, meaning it will not propagate — the inputs are locked in a non-relayable transaction until re-signed with a corrected fee. The `needed_fee` accessor also reports a value lower than what the transaction requires, so any upstream budgeting logic (the same role `maxWithdraw` plays in the original report) systematically underestimates whenever `data` is set.

### Likelihood Explanation
The divergence is deterministic whenever `data.is_some()`: the OP_RETURN output is always appended to `tx_outs` and never included in the weight template. The magnitude is bounded by the 80-byte data limit (~91 vbytes), so the impact is an underpaid/possibly non-relayable transaction rather than loss of funds — Medium.

### Recommendation
Pass the full `tx_outs` (or append the OP_RETURN `TxOut` inside `calculate_weight_vbytes`) when computing `weight`, `vbytes`, `fee_with_change`, the `TooLowFee` bound, and the `TooLargeTransaction` check, so every estimate reflects the exact transaction stored in `SignableTransaction.tx`.

### Proof of Concept
In `networks/bitcoin/src/wallet/send.rs`:

```rust
// line 194-202: OP_RETURN output added to the real outputs
if let Some(data) = data {
  tx_outs.push(TxOut {
    value: Amount::ZERO,
    script_pubkey: ScriptBuf::new_op_return(...),
  })
}

// line 204: template tx built from `payments` only — OP_RETURN excluded
let (mut weight, vbytes) = Self::calculate_weight_vbytes(tx_ins.len(), payments, None);
let mut needed_fee = fee_per_vbyte * vbytes;
```

`calculate_weight_vbytes` (lines 85–99) constructs `tx.output` from `payments` plus optional change only. Consequently `tx.weight()` on the real `Transaction` (line 246–251, which uses `tx_outs`) exceeds the `weight` used for `needed_fee`, the min-fee check at line 211, and the `MAX_STANDARD_TX_WEIGHT` check at line 241, by the serialized size of the OP_RETURN output — and with a change output, the actually-paid fee (`fee()`, lines 138–141) equals that understated `fee_with_change`.
