### Title
Ed448 accepts torsion points, enabling forged Schnorr signatures and DLEq proofs - (File: crypto/ed448/src/point.rs)

### Summary
`Point::is_torsion_free` computes `(-P) + P`, which is the identity for every point, so it always returns true. [1](#0-0)  `Point::from_bytes` therefore accepts any on-curve Ed448 point that is not negative-zero, including non-prime-order torsion points such as `(0, -1)`. [2](#0-1)  `Ciphersuite::read_G` adds only a canonical re-encoding check and does not repair the missing subgroup-membership check. [3](#0-2) 

### Finding Description
The Ed448 implementation is exposed as a `PrimeGroup` and claims to reject torsion, yet its subgroup filter is vacuous. [4](#0-3) [1](#0-0)  Untrusted bytes passed to `Ed448::read_G` can consequently decode to a point with a nonzero order-2 component instead of an element of the prime-order subgroup. [5](#0-4) 

This violates the assumption behind Schnorr and DLEq verification. Schnorr verifies `R + cA - sG = 0`, and DLEq verification reconstructs each nonce as `sG_i - cP_i`. [6](#0-5) [7](#0-6)  If an accepted point has an additional order-2 component `T`, the torsion component cancels whenever the challenge is odd, allowing an attacker to grind the nonce/challenge and produce an accepted proof or signature for `xG + T`, which is not the scalar multiplication of `G` by `x`. [8](#0-7) 

### Impact Explanation
An unauthenticated party can submit byte-encoded Ed448 points that the library contract says must be prime-order elements but which actually contain a torsion component. [9](#0-8)  With roughly two attempts for an order-2 point, the attacker can create a Schnorr signature or DLEq proof accepted for a malformed public point whose full-group discrete logarithm is unknown and which is not a valid Ed448 prime-group key. [10](#0-9) [11](#0-10)  This is an integrity failure in verification of untrusted public inputs and can admit a false discrete-log equality or malformed-key signature in downstream protocols consuming `DLEqProof::read`, `SchnorrSignature::read`, or `Ed448::read_G`. [12](#0-11) [13](#0-12) 

### Likelihood Explanation
The attack requires only public bytes and selecting a point with an order-2 component. After choosing the nonce, the challenge has approximately a one-in-two chance of being odd, so a practical forger can retry nonce generation until the torsion component cancels. [6](#0-5)  The prerequisite is that the application accepts an attacker-supplied Ed448 public point or proof through the exposed read/verify APIs; no malformed scalar encoding is needed because the point decoder itself performs the defective check. [5](#0-4) 

### Recommendation
Replace `is_torsion_free` with a genuine prime-subgroup membership check that multiplies the candidate by the subgroup order and requires the identity, rather than evaluating `-P + P`. [14](#0-13)  Add regression tests that deserialize each nonzero Ed448 torsion point, including the order-2 point encoded as `x = 0, y = -1`, and assert rejection by `GroupEncoding::from_bytes` and `Ed448::read_G`. [15](#0-14)  Until corrected, Ed448 inputs should not be trusted as `PrimeGroup` elements. [16](#0-15) 

### Proof of Concept
Let `T = (0, -1)` be the canonical Ed448 order-2 point, encoded as `y = p - 1` with the sign bit clear. `Ed448::read_G` accepts it because `is_torsion_free` always evaluates to true. [14](#0-13) 

For a malformed public key `A_bad = xG + T`, choose a nonce `r`, set `R_bad = rG + T`, compute the Schnorr challenge `c = H(R_bad, A_bad, m)`, and emit `s = r + cx`. When `c` is odd, verification computes `R_bad + cA_bad - sG = T + cT = 0`, so the malformed-key signature verifies despite `A_bad` not being a scalar multiple of `G`. [17](#0-16) 

The same construction forges a DLEq assertion: submit points `(xG_1, xG_2 + T)` and choose candidate nonces `(rG_1, rG_2 + T)` until the transcript challenge `c` is odd. Emitting `s = r + cx` makes the verifier reconstruct the second nonce as `sG_2 - c(xG_2 + T) = rG_2 + T`, causing the false equality proof to pass. [18](#0-17)

    ((*self * (Scalar::ZERO - Scalar::ONE)) + self).is_identity()

impl GroupEncoding for Point {
  type Repr = <FieldElement as PrimeField>::Repr;

  fn from_bytes(bytes: &Self::Repr) -> CtOption<Self> {
    // Extract and clear the sign bit
    let sign = Choice::from(bytes[56] >> 7);
    let mut bytes = *bytes;
    let mut_ref: &mut [u8] = bytes.as_mut();
    mut_ref[56] &= !(1 << 7);

    // Parse y, recover x
    FieldElement::from_repr(bytes).and_then(|y| {
      recover_x(y).and_then(|mut x| {
        x.conditional_negate(x.is_odd().ct_eq(&!sign));
        let not_negative_zero = !(x.is_zero() & sign);
        let point = Point { x, y, z: FieldElement::ONE };
        CtOption::new(point, not_negative_zero & point.is_torsion_free())
      })

  pub fn verify<T: Transcript>(
    &self,
    transcript: &mut T,
    generators: &[G],
    points: &[G],

    if generators.len() != points.len() {
      Err(DLEqError::InvalidProof)?;
