### Title
`ThresholdKeys::read` accepts structurally inconsistent key material, letting attacker-supplied bytes be treated as a trusted DKG product (type-confusion analog of CVE-2020-1899's "S" type code) - (File: crypto/dkg/src/lib.rs)

### Summary
CVE-2020-1899 was a deserialization bug where a type tag caused attacker bytes to be interpreted as a trusted internal object (`StringData`) without validation. The direct analog in Serai is `ThresholdKeys::<C>::read`: it reassembles a `ThresholdKeys` — a structure that downstream code treats as the authenticated output of a PedPoP DKG — purely from attacker-controlled bytes, without verifying any of the internal consistency invariants the DKG guarantees. In particular, the `secret_share` is never checked against `verification_shares[i]`, and the `verification_shares` are never checked to lie on a common polynomial.

### Finding Description
`ThresholdKeys::read` parses a curve-ID header, `t/n/i`, an interpolation tag (`0` = `Constant`, `1` = `Lagrange`), one scalar (`secret_share`), and `n` points (`verification_shares`), then calls `ThresholdKeys::new` [1](#0-0) . `ThresholdKeys::new` only enforces parameter sanity (`t <= n`, `i <= n`, `t == n` for `Constant`) and computes `group_key` as the interpolated sum of `verification_shares[1..=t]` — it never verifies `secret_share * G == verification_shares[i]` nor that the shares are consistent with any polynomial [2](#0-1) .

An unprivileged party that can feed bytes to `ThresholdKeys::read` (an accepted untrusted sink) can therefore fabricate a complete, "valid" threshold key: choose a known secret `x`, set `verification_shares[j] = x_j * G` for known `x_j` interpolating to `x`, and set `secret_share = x_i`. The resulting `group_key` equals `x * G` — a key whose discrete logarithm the attacker fully knows — while `view()`, `sign`, and offset/scalar machinery all operate normally on it. The interpolation tag byte even gives the attacker two alternative interpretations (`Constant` coefficient list vs `Lagrange`) of the same blob, mirroring the "S" type-code confusion.

### Impact Explanation
Any consumer that loads keys via `ThresholdKeys::read` and then derives addresses or signs will operate under an attacker-chosen group key. Concretely: funds sent to `p2tr_script_buf(group_key)`/`register_offset`-derived outputs are spendable only by the attacker (funds reported received that are not spendable by the honest group), and FROST `SignMachine`s built on `keys.view(included)` will produce fully valid threshold signatures for a key the attacker controls — signing for an unintended key while appearing correct.

### Likelihood Explanation
Reachable wherever serialized `ThresholdKeys` can be supplied or corrupted by an outside party (key-import/restore paths, injected storage, or any transport feeding `read`). It requires no collusion, no protocol participation, and no knowledge of honest shares — the blob is fully self-consistent by construction.

### Recommendation
In `ThresholdKeys::new` (so both `read` and DKG output paths benefit), verify `C::generator() * secret_share == verification_shares[&params.i()]`. Optionally, for small `n`, additionally verify the shares lie on a consistent degree-`t-1` polynomial (reconstruct and compare). Reject deserialization otherwise.

### Proof of Concept
```rust
// Secp256k1 ciphersuite; attacker knows x.
let x = Secp256k1::random_nonzero_F(&mut rng);
let mut blob = vec![];
blob.extend((Secp256k1::ID.len() as u32).to_le_bytes());
blob.extend(Secp256k1::ID);
blob.extend(1u16.to_le_bytes());           // t = 1
blob.extend(1u16.to_le_bytes());           // n = 1
blob.extend(1u16.to_le_bytes());           // i = 1
blob.push(1);                              // Interpolation::Lagrange
blob.extend(x.to_repr().as_ref());         // secret_share = x
blob.extend((Secp256k1::generator() * x).to_bytes().as_ref()); // vshare[1]
let keys = ThresholdKeys::<Secp256k1>::read(&mut blob.as_slice()).unwrap();
assert_eq!(keys.group_key(), Secp256k1::generator() * x); // attacker-known key
// keys.sign(...) now produces valid FROST signatures under x*G.
```

  pub fn new(
    params: ThresholdParams,
    interpolation: Interpolation<C::F>,
    secret_share: Zeroizing<C::F>,
    verification_shares: HashMap<Participant, C::G>,
  ) -> Result<ThresholdKeys<C>, DkgError> {
    if verification_shares.len() != usize::from(params.n()) {
      Err(DkgError::IncorrectAmountOfVerificationShares {
        n: params.n(),
        shares: verification_shares.len(),
      })?;
    }
    for participant in verification_shares.keys().copied() {
      if u16::from(participant) > params.n() {
        Err(DkgError::InvalidParticipant { n: params.n(), participant })?;
      }
    }

    match &interpolation {
      Interpolation::Constant(_) => {
        if params.t() != params.n() {
          Err(DkgError::InapplicableInterpolation("constant interpolation for keys where t != n"))?;
        }
      }
      Interpolation::Lagrange => {}
    }

    let t = (1 ..= params.t()).map(Participant).collect::<Vec<_>>();
    let group_key =
      t.iter().map(|i| verification_shares[i] * interpolation.interpolation_factor(*i, &t)).sum();

    Ok(ThresholdKeys {
      core: Arc::new(Zeroizing::new(ThresholdCore {
        params,
        interpolation,
        secret_share,
        group_key,
        verification_shares,
      })),
      scalar: C::F::ONE,
      offset: C::F::ZERO,
    })
  }

  pub fn read<R: io::Read>(reader: &mut R) -> io::Result<ThresholdKeys<C>> {
    {
      let different = || io::Error::other("deserializing ThresholdKeys for another curve");

      let mut id_len = [0; 4];
      reader.read_exact(&mut id_len)?;
      if u32::try_from(C::ID.len()).unwrap().to_le_bytes() != id_len {
        Err(different())?;
      }

      let mut id = vec![0; C::ID.len()];
      reader.read_exact(&mut id)?;
      if id != C::ID {
        Err(different())?;
      }
    }

    let (t, n, i) = {
      let mut read_u16 = || -> io::Result<u16> {
        let mut value = [0; 2];
        reader.read_exact(&mut value)?;
        Ok(u16::from_le_bytes(value))
      };
      (
        read_u16()?,
        read_u16()?,
        Participant::new(read_u16()?).ok_or(io::Error::other("invalid participant index"))?,
      )
    };

    let mut interpolation = [0];
    reader.read_exact(&mut interpolation)?;
    let interpolation = match interpolation[0] {
      0 => Interpolation::Constant({
        let mut res = Vec::with_capacity(usize::from(n));
        for _ in 0 .. n {
          res.push(C::read_F(reader)?);
        }
        res
      }),
      1 => Interpolation::Lagrange,
      _ => Err(io::Error::other("invalid interpolation method"))?,
    };

    let secret_share = Zeroizing::new(C::read_F(reader)?);

    let mut verification_shares = HashMap::new();
    for l in (1 ..= n).map(Participant) {
      verification_shares.insert(l, <C as Ciphersuite>::read_G(reader)?);
    }

    ThresholdKeys::new(
      ThresholdParams::new(t, n, i).map_err(io::Error::other)?,
      interpolation,
      secret_share,
      verification_shares,
    )
    .map_err(io::Error::other)
  }
