Unauthenticated blame adjudication lets an accuser frame an honest DKG sender for an encrypted share never addressed to them - (File: crypto/dkg/pedpop/src/encryption.rs)

### Summary
The ZooKeeper CVE is a missing-permission-check disclosure: `getACL()` returns security-sensitive data without verifying the requester is authorized for it. The Serai analog is in PedPoP's blame protocol: the per-message proof-of-possession (`pop`) and the `EncryptionKeyProof` DLEq never bind the *intended recipient* of an `EncryptedMessage`, and `BlameMachine::blame`/`AdditionalBlameMachine::blame` accept arbitrary accuser-supplied `msg` bytes. Any party who observes an encrypted share addressed to someone else can submit it as an accusation, produce a valid DLEq for their own encryption key, and get the honest sender adjudicated at fault.

### Finding Description
`encrypt` signs a Schnorr PoP over `pop_challenge::<C>(context, pub_nonce, pub_key, from, msg)` — it binds the sender (`from`) and ciphertext but **not the recipient** [1](#0-0) . In `decrypt_with_proof`, the accuser's supplied `EncryptionKeyProof` is verified as a DLEq proving `proof.key = enc_key[decryptor] * msg.key`, i.e., only that the accuser knows *some* ECDH key for the message — every registered participant can produce this for *any* `msg.key` since they know their own private `enc_key` [2](#0-1) .

`blame_internal` then attributes fault purely from the decryption result: valid PoP + valid DLEq + undecryptable/non-scalar plaintext → `sender` is blamed [3](#0-2) . The security dependency is entirely external: the docstring admits the message "must have been authenticated as actually having come from the sender in question," but nothing authenticates that the message was *addressed to the accuser* [4](#0-3) .

In the processor, `CoordinatorMessage::VerifyBlame` parses `share` bytes supplied in the accusation itself and feeds them to `AdditionalBlameMachine::new(...).blame(...)` — no lookup of the originally relayed share, no binding between `(accuser, accused)` and the recorded message [5](#0-4) .

### Impact Explanation
Any participant (or even a non-participant via `AdditionalBlameMachine::new`, which explicitly supports non-members [6](#0-5) ) who observes the publicly relayed share map can take sender Alice's valid `EncryptedMessage` meant for Dana, attach their own valid `EncryptionKeyProof`, and submit `blame(Alice, attacker, alice_to_dana_msg, attacker_proof)`. The PoP verifies (Alice's message is well-formed), the DLEq verifies (attacker's key is honestly derived), decryption under the attacker's ECDH key yields garbage, `C::F::from_repr` fails, and Alice is returned as the faulty party → `ProcessorMessage::Blame { participant: accused }`. As the code notes, reaching this path means "*someone* is getting fatally slashed" [7](#0-6) . An honest validator is slashed and the DKG aborted — a concrete unauthorized action enabled by a missing authorization check on the blame query, mirroring getACL's unauthenticated disclosure.

### Likelihood Explanation
Medium. Encrypted shares are relayed/broadcast through the coordinator (`ProcessorMessage::Shares`), so observing another pair's ciphertext is realistic. The attack requires only public inputs — one intercepted `EncryptedMessage` plus a locally computed ECDH point and DLEq — and deterministically produces a false-blame verdict since garbage plaintext parses as a scalar with negligible probability. The attacker burns their own accusation slot but inflicts a fatal slash on the victim.

### Recommendation
Bind the intended recipient into `pop_challenge` (e.g., `transcript.append_message(b"to", to.to_bytes())` at encryption and verification time), or equivalently have `blame_internal` verify the accuser's `EncryptionKeyProof` against the *recipient index registered at share-relay time* and reject messages whose PoP/context doesn't commit to `(from, to)`. In `VerifyBlame`, authenticate `share` against the recorded transcript of the accused→accuser message rather than trusting accusation-supplied bytes.

### Proof of Concept
1. Run PedPoP with n ≥ 3; sender `ONE` produces shares to `TWO` and `THREE`. `THREE` (or an observer) keeps `secret_shares[ONE][TWO]`.
2. `THREE` computes `key = ecdh(enc_key_3, msg.key)` and `EncryptionKeyProof { key, dleq: DLEqProof::prove(...,[G, msg.key], &enc_key_3) }` — this verifies in `decrypt_with_proof` since it only checks `key == enc_key_3 * msg.key`.
3. Call `AdditionalBlameMachine::new(context, n, commitment_msgs).blame(ONE, THREE, msg_to_TWO, Some(proof))`.
4. PoP verifies (bound to `from`=ONE), DLEq verifies, `cipher(context, wrong_key)` produces garbage, `from_repr` fails → returns `ONE`. Honest `ONE` is blamed.

  /// Create an AdditionalBlameMachine capable of evaluating Blame regardless of if the caller was
  /// a member in the DKG protocol.
  ///
  /// Takes in the parameters for the DKG protocol and all of the participant's commitment
  /// messages.
  ///
  /// This constructor assumes the full validity of the commitment messages. They must be fully
  /// authenticated as having come from the supposed party and verified as valid. Usage of invalid
  /// commitments is considered undefined behavior, and may cause everything from inaccurate blame
  /// to panics.
  pub fn new(
    context: [u8; 32],
    n: u16,
    mut commitment_msgs: HashMap<Participant, EncryptionKeyMessage<C, Commitments<C>>>,
  ) -> Result<Self, PedPoPError<C>> {
    let mut commitments = HashMap::new();
    let mut encryption = Decryption::new(context);
    for i in 1 ..= n {
      let i = Participant::new(i).unwrap();
      let Some(msg) = commitment_msgs.remove(&i) else { Err(PedPoPError::MissingParticipant(i))? };
      commitments.insert(i, encryption.register(i, msg).commitments);
    }
    Ok(AdditionalBlameMachine(BlameMachine { commitments, encryption, result: None }))
  }
