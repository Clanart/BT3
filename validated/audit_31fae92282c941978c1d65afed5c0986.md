### Title
Attacker-controlled Lagrange parameters in `ThresholdKeys::read` cause quadratic CPU exhaustion - (File: `crypto/dkg/src/lib.rs`)

### Summary
`ThresholdKeys::read` accepts serialized `t` and `n` values, reads `n` verification shares, and invokes `ThresholdKeys::new`. [1](#0-0) [2](#0-1)  For Lagrange interpolation, `ThresholdKeys::new` computes the group key by evaluating an interpolation factor for every participant from `1` through `t`, while each factor evaluation iterates over all `t` participants. [3](#0-2) [4](#0-3)  Setting `t = n = 65535` therefore turns an approximately 2 MiB canonical key encoding into roughly 4.29 billion scalar multiplications, along with 65,535 field inversions and scalar-to-point multiplications.

### Finding Description
The serialized format places attacker-controlled `t`, `n`, and `i` fields immediately after the curve identifier, and an interpolation byte of `1` selects `Interpolation::Lagrange`. [1](#0-0) [5](#0-4)  The reader then consumes one scalar and `n` group encodings before passing the decoded parameters to `ThresholdKeys::new`. [6](#0-5) [7](#0-6) 

`ThresholdKeys::new` constructs an `included` list containing every participant `1..=t` and calls `interpolation_factor` once for each entry while deriving `group_key`. [3](#0-2)  The Lagrange branch evaluates a product and denominator by looping over every participant in `included`, excluding only the current participant. [8](#0-7) [9](#0-8)  It then inverts the denominator and multiplies it by the numerator. [10](#0-9)  Consequently, deriving the group key costs `O(t²)` scalar field operations before the constructor returns.

### Impact Explanation
A party able to submit bytes to `ThresholdKeys::read` can force deserialization to spend CPU time quadratic in the encoded participant count without relying on malformed points, non-canonical scalars, or invalid participant indexes. [11](#0-10) [2](#0-1)  The constructor only requires the expected number of shares, participant identifiers bounded by `n`, and an applicable interpolation mode before reaching the quadratic group-key computation. [12](#0-11) [13](#0-12) 

At the protocol’s `u16` limit, `t = n = 65535` produces approximately `65535 * 65534` scalar multiplications in the interpolation numerator and denominator, plus one inversion and point multiplication for each participant. [14](#0-13) [3](#0-2)  This can stall or effectively deny service to a caller processing attacker-supplied threshold-key material.

### Likelihood Explanation
The trigger is deterministic and fully controlled by serialized fields: choose Lagrange interpolation, set both `t` and `n` to `65535`, choose participant `1`, and encode `65535` canonical points. [15](#0-14) [16](#0-15)  Repeatedly encoding the generator point is sufficient because the expensive computation happens before any check that the supplied secret share corresponds to those verification shares. [17](#0-16) 

### Recommendation
Enforce a deployment-appropriate maximum participant count before allocating vectors, decoding shares, or constructing `ThresholdKeys`. [15](#0-14)  Replace the per-participant `O(t)` Lagrange evaluation with an `O(t)` or `O(t log t)` method using precomputed products and batch inversion, or otherwise separate the expensive group-key derivation from untrusted deserialization. [18](#0-17) [3](#0-2)

use frost::{

fn main() {
  let mut bytes = Vec::new();

  // Curve identifier.
  bytes.extend_from_slice(
    &(u32::try_from(<Ristretto as Ciphersuite>::ID.len()).unwrap()).to_le_bytes(),
  );
  bytes.extend_from_slice(<Ristretto as Ciphersuite>::ID);

  // t = n = u16::MAX; i = 1.
  bytes.extend_from_slice(&u16::MAX.to_le_bytes());
  bytes.extend_from_slice(&u16::MAX.to_le_bytes());
  bytes.extend_from_slice(&1u16.to_le_bytes());

  // Select Lagrange interpolation.
  bytes.push(1);

  // Secret-share scalar.
  bytes.extend_from_slice(
    <<Ristretto as Ciphersuite>::F as Field>::ONE.to_repr().as_ref(),
  );

  // Canonical verification shares. Reusing the generator is sufficient.
  let point = <Ristretto as Ciphersuite>::generator().to_bytes();
  for _ in 0 ..= u16::MAX {
    bytes.extend_from_slice(point.as_ref());
  }

  // ThresholdKeys::new performs roughly 4.29 billion scalar multiplications
  // while deriving the group key.
  let keys = ThresholdKeys::<Ristretto>::read(&mut bytes.as_slice()).unwrap();
  std::hint::black_box(keys);
}

    match self {
