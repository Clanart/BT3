## Analysis

The Biconomy bug's core pattern: a public function lets an attacker append entries onto **another party's** list keyed by that party's identity, which is later drained/iterated by the victim, and the attacker can grief that process because the list has no cap on who may write to it.

The closest local analog is in `pallet-bandwidth`. The `Allowance` storage is a `StorageDoubleMap<StateMachine, AppKey, SubscriptionList>` where `SubscriptionList` is a `BoundedVec` capped at 1024 entries with FIFO eviction on overflow [1](#0-0) . Any address on any registered source chain can call `BandwidthManager.purchase()` and freely choose the target `app` and `chain` arguments — these are **not** derived from `msg.sender`, they're attacker-supplied fields describing who gets credited [2](#0-1) . On the pallet side, `on_accept` decodes `msg.chain`/`msg.app` straight out of the wire message and calls `push_subscription` against that `(chain, app)` key with no ownership check [3](#0-2) .

`push_subscription` evicts the oldest live subscription once the list hits the 1024 cap, emitting `SubscriptionEvicted` with `lost_bytes` — bytes the original payer purchased but will never get to consume [4](#0-3) . Since `purchase()` lets anyone target any `(chain, app)` pair, an attacker can repeatedly call `purchase()` against the cheapest configured tier (`tier` price is a global mapping, any caller pays the same nominal fee) with a victim's `app`/`chain` as the target, filling the FIFO queue until it evicts the victim's legitimately-paid, unexpired subscriptions — a direct loss of the funds the victim already spent. This is the same broken invariant as the NFT report: attacker-controlled writes into a victim-keyed bounded resource that the victim relies on, causing loss for the victim through griefing rather than gas-DoS (here it's eviction instead of unbounded iteration, because the list is capped, but the outcome — victim's paid-for resource destroyed by an unrelated caller — is the same class of bug).

I traced other IntentGatewayV2/`IntentsBase` withdrawal-loop paths (`_withdraw` iterating `body.tokens`) but those token lists come from the order itself (fixed by the original order placer, not attacker-appendable), so they don't reproduce the "push to someone else's list" primitive — I rejected that candidate.

### Title
Anyone can grief another app's prepaid bandwidth by evicting its subscriptions via `BandwidthManager.purchase()` - (File: `modules/pallets/bandwidth/src/lib.rs`, `evm/src/apps/BandwidthManager.sol`)

### Summary
`BandwidthManager.purchase()` on EVM lets any caller specify an arbitrary target `app` and `chain`, not tied to `msg.sender`. `pallet-bandwidth::on_accept` trusts these fields and pushes a new `Subscription` onto the `(app_chain, app)` FIFO list, evicting the oldest entry once the bounded list (`MAX_SUBSCRIPTIONS = 1024`) is full. An attacker can flood a victim app's bucket with minimal-tier purchases to evict the victim's real, unexpired, already-paid-for subscriptions.

### Finding Description
`Allowance` is a `StorageDoubleMap<StateMachine, AppKey, SubscriptionList>` [1](#0-0) . The comment explicitly states the design intent — "any deployment can sponsor any app on any chain" — so `purchase()` intentionally allows a payer that is unrelated to the app being credited [5](#0-4) . But this same openness means there is no check that the caller is a legitimate sponsor rather than a griefer: `purchase()` takes `app` and `chain` as plain calldata parameters [6](#0-5) , and `on_accept` builds the storage key straight from the decoded message with no allowlist/authorization on the `(chain, app)` target [7](#0-6) .

`push_subscription` unconditionally evicts index 0 (oldest) once the list is at cap and appends the new entry [8](#0-7) . Because the FIFO is drained/evicted strictly in insertion order, an attacker can push enough cheap subscriptions (paying only the lowest configured tier price) to shift the queue until the victim's legitimately purchased subscriptions fall off the front — before the victim's app ever consumed that bandwidth.

### Impact Explanation
This is a direct loss of funds: the victim already paid the fee token to credit its `(chain, app)` bandwidth bucket, and an unrelated third party can force those specific subscriptions to be evicted (`SubscriptionEvicted { lost_bytes }`) before they're consumed, at a cost the attacker controls by choosing the cheapest tier. Once evicted, the bytes are irrecoverably lost — there's no user-level compensation path other than the admin `force_credit` escape hatch. This matches the bounty's "loss of funds" and "logic attacks" categories, and does not require a malicious relayer, prover, or admin — only a normal unprivileged caller of the public `purchase()` entrypoint.

### Likelihood Explanation
Likelihood is moderate: the attacker needs to submit enough purchase transactions to advance the FIFO past the victim's existing entries (up to ~1024 pushes to fully cycle a full queue), each paying the cheapest tier price, which is a bounded, calculable cost. For apps with only a few live subscriptions the number of evicting purchases needed is small (just enough to reach the cap plus one push per victim entry to evict). No special access or timing is required, and the entrypoint (`purchase()` / on-chain `onAccept`) is always open.

### Recommendation
Restrict who may credit a given `(chain, app)` bucket — e.g., require the purchase message's payer/sender to match the `app` being credited unless explicitly sponsoring via an authorized allowlist, or track subscriptions per `(chain, app, payer)` so a griefer's cheap subscriptions can't evict another payer's legitimate ones. Alternatively, evict FIFO only within the entries contributed by the same payer/session, or increase `MAX_SUBSCRIPTIONS` combined with a per-payer sub-cap so no single unrelated caller can dominate a shared queue.

### Proof of Concept
1. Victim calls `BandwidthManager.purchase(app=V, tier=T_high, months=1, chain=C)`; pallet credits a `Subscription` at the front of `Allowance[C][V]` (list length 1 of 1024).
2. Attacker repeatedly calls `purchase(app=V, tier=T_cheap, months=1, chain=C)` — same target `app`/`chain`, attacker pays only `T_cheap` price each time — 1024 times, filling `Allowance[C][V]` to the cap.
3. On the attacker's 1024th call, `push_subscription` evicts the oldest entry, which is the victim's paid subscription, emitting `SubscriptionEvicted { app_chain: C, app: V, tier: T_high, lost_bytes: <victim's remaining bytes> }` [9](#0-8) .
4. Victim's bandwidth is gone despite never being consumed via `try_consume`; victim must repurchase to restore service, while the attacker paid only cheap-tier fees to force the loss.

		/// Append a fresh subscription with a fixed expiry. If the list
		/// is already at `MaxSubscriptions`, evict the oldest entry and
		/// emit [`Event::SubscriptionEvicted`] so the lost bytes are
		/// auditable. Returns the new subscription's `expires_at`.
		fn push_subscription(
			app_chain: &StateMachine,
			app: &AppKey,
			tier: TierIndex,
			bytes: BandwidthBytes,
			duration_secs: u64,
		) -> u64 {
			let now = <T as pallet_ismp::Config>::TimestampProvider::now().as_secs();
			let expires_at = now.saturating_add(duration_secs);
			let new_sub =
				Subscription { tier, remaining_bytes: bytes, expires_at, purchased_at: now };

			let evicted = Allowance::<T>::mutate(app_chain, app, |list| {
				let evicted = if list.len() == MAX_SUBSCRIPTIONS as usize {
					Some(list.remove(0))
				} else {
					None
				};
				// Capacity is now guaranteed; try_push can't fail.
				let _ = list.try_push(new_sub);
				evicted
			});

			if let Some(old) = evicted {
				Self::deposit_event(Event::SubscriptionEvicted {
					app_chain: *app_chain,
					app: app.clone(),
					tier: old.tier,
					lost_bytes: old.remaining_bytes,
				});
			}

			expires_at
		}

	impl<T: Config> IsmpModule for Pallet<T> {
		fn on_accept(&self, request: PostRequest) -> Result<Weight, anyhow::Error> {
			let manager = BandwidthManager::<T>::get(&request.source).ok_or_else(|| {
				anyhow::anyhow!(format!("no bandwidth manager registered for {:?}", request.source))
			})?;

			if request.from != manager.0.to_vec() {
				return Err(anyhow::anyhow!(format!(
					"purchase from unauthorised sender on {:?}: expected {:x?}, got {:x?}",
					request.source, manager.0, request.from
				)));
			}

			let msg = PurchaseMessage::try_from(request.body.as_slice())?;
			let tier = TierIndex::try_from(msg.tier)
				.map_err(|_| anyhow::anyhow!(format!("unknown tier discriminant {}", msg.tier)))?;
			let cfg = Tiers::<T>::get(tier)
				.ok_or_else(|| anyhow::anyhow!(format!("tier {:?} is not configured", tier)))?;

			let bytes = cfg.bytes.saturating_mul(msg.months as u128);
			let duration = cfg.duration_secs.saturating_mul(msg.months as u64);

			let key = AppKey::truncate_from(msg.app);
			let expires_at = Self::push_subscription(&msg.chain, &key, tier, bytes, duration);

			Self::deposit_event(Event::BandwidthCredited {
				app_chain: msg.chain,
				app: key,
				paid_from: request.source,
				tier,
				bytes,
				expires_at,
			});

			Ok(Weight::zero())
		}

    function purchase(bytes calldata app, uint256 tier, uint256 months, bytes calldata chain)
        external
        returns (bytes32 commitment)
    {
        if (app.length == 0 || chain.length == 0 || months == 0) revert InvalidPurchase();
        uint256 price18d = tierPrice[tier];
        if (price18d == 0) revert UnknownTier();

        uint256 total18d = price18d * months;
        address feeToken = IDispatcher(_host).feeToken();
        uint8 dec = IERC20Metadata(feeToken).decimals();
        uint256 scale = 10 ** (18 - dec);
        if (total18d % scale != 0) revert PriceNotRepresentable();
        uint256 amount = total18d / scale;

        IERC20(feeToken).safeTransferFrom(msg.sender, address(this), amount);

        BandwidthPurchaseMsg memory body = BandwidthPurchaseMsg({
            app: app,
            tier: tier,
            months: months,
            chain: chain
        });

        commitment = IDispatcher(_host).dispatch(
            DispatchPost({
                dest: IDispatcher(_host).hyperbridge(),
                to: PALLET_BANDWIDTH_MODULE_ID,
                body: abi.encode(body),
                timeout: 0,
                fee: 0,
                payer: address(this)
            })
        );
