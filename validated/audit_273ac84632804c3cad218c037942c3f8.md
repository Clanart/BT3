### Title
Coinbase outputs scanned and reported as spendable before maturity, allowing any miner to inject temporarily-unspendable funds into the wallet - ([File: networks/bitcoin/src/wallet/mod.rs])

### Summary
The bug class in the external report is "a forced external interaction the user cannot refuse or skip permanently blocks a later action" (a blacklisted USDC transfer reverting inside `unstakeGns` prevents unstaking). In Serai, the reachable analog is `Scanner::scan_block` in `networks/bitcoin/src/wallet/mod.rs`: it scans `block.txdata` including `txdata[0]` (the coinbase), and any output whose `script_pubkey` matches a registered script is returned as a `ReceivedOutput` indistinguishable from a normal spendable output. Coinbase outputs are unspendable for 100 blocks, so the wallet reports funds as received which `SignableTransaction` will happily try to spend — producing a transaction the network rejects (`bad-txns-premature-spend-of-coinbase`).

### Finding Description
`scan_transaction` matches only `output.script_pubkey` against `self.scripts` and pushes a `ReceivedOutput` carrying the outpoint `OutPoint::new(tx.compute_txid(), vout)` [1](#0-0) . `scan_block` iterates over **all** of `block.txdata`, including index 0, the coinbase [2](#0-1) . There is no check that the containing transaction is a coinbase (`tx.is_coinbase()`) nor any depth/maturity tracking on `ReceivedOutput` — the struct stores only `offset`, `output`, and `outpoint` [3](#0-2) . Downstream, `SignableTransaction::new` treats every `ReceivedOutput` as an immediately spendable input with no maturity validation [4](#0-3) . The only mitigation is a code comment telling integrators to do "a post-processing pass" or scan `block.txdata[1 ..]` — a trap an integrator using the obvious API (`scan_block`) hits silently.

Any Bitcoin miner is an unprivileged party who can cause this: when mining a block, they set the coinbase `script_pubkey` to the threshold set's P2TR script (publicly derivable from chain activity). The scanner then reports the output as received and spendable while consensus forbids spending it for 100 blocks.

### Impact Explanation
Funds are reported received that are not spendable — an accepted impact class. Concretely: a processor indexing deposits via `scan_block` will record the coinbase output as a valid deposit to the threshold wallet, and any `SignableTransaction` built over it (e.g., an automatic consolidation or withdrawal batch that consumes all scanned outputs) will produce a transaction that consensus rejects. Worse, if coin-selection lumps the immature output in with legitimate mature UTXOs, the entire multi-input transaction fails — mirroring the report's "one bad transfer blocks the whole harvest/unstake": one poisoned UTXO makes the whole spend invalid. The lockup is temporary (100 blocks), so no permanent loss, but a miner can re-trigger it every 100 blocks for sustained disruption at the cost of only the coinbase subsidy they would have received anyway (they pay it to the Serai address instead of their own — they still "keep" it once it matures under Serai's key, so effectively they permanently donate the subsidy; however on regtest-like or pool-payout flows the cost profile differs). The reliable impact is funds-counted-but-unspendable plus spend-blocking for ~100 blocks per injection.

### Likelihood Explanation
Low-to-moderate. It requires a miner to win a block and deliberately direct the coinbase output (their own subsidy) to the threshold address — an act with real cost (the subsidy is locked to Serai's key permanently after maturity, permanently *increasing* Serai's balance, but doing so via a vector that transiently poisons coin selection). The window of unusable funds is bounded (~100 blocks). Additionally, the code comment partially documents the caveat, so an integrator who reads the docs may avoid it; an integrator using `scan_block` naturally will not. The existence of the exact accepted impact ("funds reported received that are not spendable") and the trivially reachable path (public input: a Bitcoin transaction an unprivileged miner causes to exist) keep this at Medium severity.

### Recommendation
- In `scan_block`, skip the coinbase transaction by default (`for tx in &block.txdata[1 ..]`), or mark each returned `ReceivedOutput` with maturity metadata (e.g., `coinbase: bool` / `block_height`) so spend paths can enforce the 100-block rule.
- Alternatively, have `SignableTransaction::new` reject or defer inputs flagged as immature, so a poisoned UTXO cannot invalidate an otherwise-valid batch spend — the direct analogue of the report's "claim pattern" recommendation (isolate the failing component instead of aborting the whole operation).

### Proof of Concept
```
Setup: threshold key K, tweak_keys applied, Scanner::new(K_tweaked) registered.

Attacker (a miner):
1. Mines block B. Sets coinbase output[0].script_pubkey = p2tr_script_buf(K_tweaked) (value = block subsidy + fees).
2. Serai-side processor calls scanner.scan_block(&B).
   - scan_block iterates block.txdata (mod.rs:223), including txdata[0].
   - scan_transaction matches output.script_pubkey in self.scripts (mod.rs:205)
   - Returns ReceivedOutput { offset: ZERO, outpoint: (coinbase_txid, 0) } — identical in type
     to a normal deposit.
3. Processor records it as received funds / feeds it into SignableTransaction::new
   along with other mature inputs (send.rs:150+).
4. The resulting signed transaction spends a coinbase at depth < 100 →
   consensus rejection: bad-txns-premature-spend-of-coinbase.
   The entire transaction (including all legitimate inputs) fails to relay/confirm,
   and the balance sheet has counted the subsidy as spendable when it is not.
```

Note: the test suite itself mines the deposit *via* the coinbase (`generatetoaddress` in `send_and_get_output`) and then mines 100 blocks to maturity before scanning [5](#0-4)  — demonstrating that the scanner does ingest coinbase outputs and that the maturity workaround is entirely the caller's responsibility.

  pub fn scan_transaction(&self, tx: &Transaction) -> Vec<ReceivedOutput> {
    let mut res = Vec::new();
    for (vout, output) in tx.output.iter().enumerate() {
      // If the vout index exceeds 2**32, stop scanning outputs
      let Ok(vout) = u32::try_from(vout) else { break };

      if let Some(offset) = self.scripts.get(&output.script_pubkey) {
        res.push(ReceivedOutput {
          offset: *offset,
          output: output.clone(),
          outpoint: OutPoint::new(tx.compute_txid(), vout),
        });
      }
    }
    res
  }

  ///
  /// This will also scan the coinbase transaction which is bound by maturity. If received outputs
  /// must be immediately spendable, a post-processing pass is needed to remove those outputs.
  /// Alternatively, scan_transaction can be called on `block.txdata[1 ..]`.
  pub fn scan_block(&self, block: &Block) -> Vec<ReceivedOutput> {
    let mut res = Vec::new();
    for tx in &block.txdata {
      res.extend(self.scan_transaction(tx));
    }
    res
  }

async fn send_and_get_output(rpc: &Rpc, scanner: &Scanner, key: ProjectivePoint) -> ReceivedOutput {
  let block_number = rpc.get_latest_block_number().await.unwrap() + 1;

  rpc
    .rpc_call::<Vec<String>>(
      "generatetoaddress",
      serde_json::json!([
        1,
        Address::from_script(&p2tr_script_buf(key).unwrap(), Network::Regtest).unwrap()
      ]),
    )
    .await
    .unwrap();

  // Mine until maturity
  rpc
    .rpc_call::<Vec<String>>(
      "generatetoaddress",
      serde_json::json!([100, Address::p2sh(Script::new(), Network::Regtest).unwrap()]),
    )
    .await
    .unwrap();

  let block = rpc.get_block(&rpc.get_block_hash(block_number).await.unwrap()).await.unwrap();

  let mut outputs = scanner.scan_block(&block);
  assert_eq!(outputs, scanner.scan_transaction(&block.txdata[0]));

  assert_eq!(outputs.len(), 1);
  assert_eq!(outputs[0].outpoint(), &OutPoint::new(block.txdata[0].compute_txid(), 0));
  assert_eq!(outputs[0].value(), block.txdata[0].output[0].value.to_sat());

  assert_eq!(
    ReceivedOutput::read::<&[u8]>(&mut outputs[0].serialize().as_ref()).unwrap(),
    outputs[0]
  );

  outputs.swap_remove(0)
