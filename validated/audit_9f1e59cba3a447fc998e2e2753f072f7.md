### Title
Silent, unconfirmed remote-URL rewrite driven by attacker-influenced GitHub API `clone_url` - (File: `app/src/lib/stores/updates/update-remote-url.ts`)

### Summary
`updateRemoteUrl()` compares the locally configured git remote against the `clone_url` returned by the GitHub API for the repository's associated `GitHubRepository`, and — if a set of heuristic checks pass — silently calls `gitStore.setRemoteURL()` to rewrite the user's `origin` remote to whatever URL the API/object supplies, with no user confirmation. [1](#0-0) 

### Finding Description
`updateRemoteUrl` takes a `GitHubRepository` (the previously cached, locally stored representation of the API object) and a fresh `apiRepo: IAPIRepository` (a live response from the GitHub/GHES API). It computes:
- `updatedRemoteUrl = apiRepo.clone_url` — directly attacker/server-influenced value coming from the API response.
- `remoteUrlUnchanged` — true if the *current* git remote still matches the *previously cached* `gitHubRepository.cloneURL`.
- `protocolsMatch` — true if the URL scheme (http/ssh) of the old and new remote are the same.

If `protocolsMatch && remoteUrlUnchanged && !urlsMatch`, the code calls `gitStore.setRemoteURL(gitStore.defaultRemote.name, updatedRemoteUrl)`, which directly executes `git remote set-url <name> <url>` against the working repository with no user prompt or confirmation dialog. [2](#0-1) [3](#0-2) [4](#0-3) 

The trust boundary being crossed: `apiRepo.clone_url` originates from a GitHub API response for a repository object that the app treats as authoritative simply because the hostname/owner/name still parse-match the locally cached value. This value is controlled by whoever can influence the API's returned `clone_url` for that repository record — e.g., a GHES/enterprise server operator, a network position capable of tampering with API responses to that host (particularly relevant for GHE/GHES endpoints where the "GitHub API object" is the exact attacker-controlled entity called out as in-scope), or scenarios where the API returns a `clone_url` that still satisfies `urlMatchesRemote` structurally (same owner/name/hostname parse) but differs from the literal string on disk (`!urlsMatch`), e.g. through embedded credentials, different subdomain formatting, or a redirect to a different physical host that nonetheless parses to the same owner/name pattern. The existing "safety" checks — `protocolsMatch` and `remoteUrlUnchanged` — only validate *structural* similarity via `urlMatchesRemote()` (hostname/owner/name string compare), not that the byte-for-byte destination is safe; they do not stop the credential/target substitution because they were designed to prevent *unnecessary* churn (e.g., re-syncing after a rename), not to validate authenticity of the new destination. [5](#0-4) 

Once the remote is silently rewritten, all subsequent `git fetch`/`git push` operations, and the trampoline credential-helper's `getCredential`/`storeCredential` flow (which looks up credentials keyed by the resulting remote/credential URL), operate against the new host. [6](#0-5) 

### Impact Explanation
If the attacker-influenced `apiRepo.clone_url` points at a different physical endpoint (e.g. a spoofed GHES host, or an internal DNS/host that still parses to the same "owner/name" shape), Desktop will silently reconfigure the user's git remote to point there — with no dialog, unlike the analogous "Upstream remote already exists" flow, which does prompt the user before altering upstream remotes. [7](#0-6) 
Consequences:
- Future `git push` from the user is silently redirected, corrupting the destination of what the user believes they are pushing/sharing.
- Future `git fetch`/`clone` operations pull content from the attacker-controlled destination into the user's local repository.
- Because the credential helper resolves credentials per-host/per-endpoint, a redirected remote can also cause credentials to be looked up/sent to a different host than the user intended, depending on how `getCredentialUrl`/`getEndpointKind` classify the new URL. [8](#0-7) 

### Likelihood Explanation
This code path runs automatically as part of routine repository/API refresh (it is invoked from `app-store.ts`, which fetches API repo details in the background), not behind any explicit user action. No local access, admin rights, or pre-existing malware is required — only the ability to influence the `clone_url` field of the API repository object for a repo the victim has already added to Desktop (e.g., controlling a GHES instance, or a MITM/compromised-DNS position against an enterprise API endpoint, both of which are the "GitHub API object" attacker primitive named as in-scope). The `urlMatchesRemote` structural check is comparably loose (owner/name/hostname string parse only) and does not perform any cryptographic or identity verification of the new destination.

### Recommendation
- Require explicit user confirmation before silently rewriting an existing remote URL sourced from an API response, mirroring the existing `UpstreamAlreadyExists` confirmation dialog pattern. [9](#0-8) 
- Tighten `urlMatchesRemote`/`remoteUrlUnchanged` checks to compare the literal resolved host (post-redirect) rather than only the parsed owner/name/hostname triplet, and reject silent updates when the new `clone_url` host differs from the previously trusted endpoint's host.
- Consider gating this auto-update behind the same endpoint trust anchor used for account/API endpoint verification, rather than trusting any `IAPIRepository.clone_url` at face value.

### Proof of Concept
1. Victim adds/clones a repository hosted on a GitHub Enterprise Server instance (or any instance an attacker can influence responses for) and it becomes a `GitHubRepository` tracked by Desktop, with `origin` set to the current, expected clone URL.
2. Attacker arranges for the API response describing that repository (e.g., via compromised/malicious GHES instance, or a MITM position on that API endpoint) to return a `clone_url` that:
   - keeps the same `owner`/`name`/`hostname` as parsed by `parseRemote` (so `urlMatchesRemote` still returns true against the cached `GitHubRepository.cloneURL`), and
   - keeps the same URL scheme (so `protocolsMatch` is true), but
   - differs in literal string content from the current `origin` URL (so `urlsMatch` is false) — e.g. embeds different credentials, or resolves through a different literal host string that still parses identically.
3. On the next background repository refresh, `updateRemoteUrl(gitStore, gitHubRepository, apiRepo)` is invoked with the attacker-influenced `apiRepo`, all three conditions (`protocolsMatch && remoteUrlUnchanged && !urlsMatch`) are satisfied, and `gitStore.setRemoteURL(...)` silently runs `git remote set-url origin <attacker-supplied-url>` with no dialog or user notice. [10](#0-9) 
4. The victim's next `git fetch`/`git push` from Desktop now targets the attacker-controlled destination.

Note: I was unable to trace the exact call site in `app-store.ts` where `updateRemoteUrl` is scheduled (e.g. whether it's on every repo refresh, on API rate-limit refresh, or only after specific rename/transfer webhooks), because the file is very large and the index did not surface the specific call-site line numbers within the iteration budget. A Devin session with full file access would be needed to confirm the exact trigger cadence and any additional gating not visible here.

export async function updateRemoteUrl(
  gitStore: GitStore,
  gitHubRepository: GitHubRepository,
  apiRepo: IAPIRepository
): Promise<void> {
  // I'm not sure when these early exit conditions would be met. But when they are
  // we don't have enough information to continue so exit early!
  if (gitStore.defaultRemote === null) {
    return
  }

  const remoteUrl = gitStore.defaultRemote.url
  const updatedRemoteUrl = apiRepo.clone_url
  const urlsMatch = urlMatchesRemote(updatedRemoteUrl, gitStore.defaultRemote)

  // Verify that protocol hasn't changed. If it has we don't want
  // to alter the protocol in case they are relying on a specific one.
  // If protocol is null that implies the url is a ssh url
  // of the format git@github.com:octocat/Hello-World.git, which
  // can't be parsed by URL.parse. In this case we assume the user
  // manually configured their remote to use this format and we don't
  // want to change what they've done just to be safe
  const parsedRemoteUrl = URL.parse(remoteUrl)
  const parsedUpdatedRemoteUrl = URL.parse(updatedRemoteUrl)
  const protocolsMatch =
    parsedRemoteUrl.protocol !== null &&
    parsedUpdatedRemoteUrl.protocol !== null &&
    parsedRemoteUrl.protocol === parsedUpdatedRemoteUrl.protocol

  // Check if the default remote url has been manually changed from the
  // clone url retrieved from the GitHub API previously
  const remoteUrlUnchanged =
    gitStore.defaultRemote &&
    urlMatchesRemote(gitHubRepository.cloneURL, gitStore.defaultRemote)

  if (protocolsMatch && remoteUrlUnchanged && !urlsMatch) {
    await gitStore.setRemoteURL(gitStore.defaultRemote.name, updatedRemoteUrl)
  }
}

export function urlMatchesRemote(url: string | null, remote: IRemote): boolean {
  if (url == null) {
    return false
  }

  const cloneUrl = parseRemote(url)
  const remoteUrl = parseRemote(remote.url)

  if (remoteUrl == null || cloneUrl == null) {
    return false
  }

  if (!caseInsensitiveEquals(remoteUrl.hostname, cloneUrl.hostname)) {
    return false
  }

  if (remoteUrl.owner == null || cloneUrl.owner == null) {
    return false
  }

  if (remoteUrl.name == null || cloneUrl.name == null) {
    return false
  }

  return (
    caseInsensitiveEquals(remoteUrl.owner, cloneUrl.owner) &&
    caseInsensitiveEquals(remoteUrl.name, cloneUrl.name)
  )
}

/** Implementation of the 'get' git credential helper command */
async function getCredential(cred: Credential, store: Store, token: string) {
  const ghCred = await getGitHubCredential(cred, store)

  if (ghCred) {
    return ghCred
  }

  const endpointKind = await getEndpointKind(cred, store)
  const accounts = await store.getAll()

  const endpoint = `${getCredentialUrl(cred)}`
  const apiEndpoint = getAPIEndpoint(endpoint)

  // If it appears as if the endpoint is a GitHub host and we don't have an
  // account for that endpoint then we should prompt the user to sign in.
  if (
    endpointKind !== 'generic' &&
    !accounts.some(a => a.endpoint === apiEndpoint)
  ) {
    if (getIsBackgroundTaskEnvironment(token)) {
      debug('background task environment, skipping prompt')
      return undefined
    }

    const account = await ui.promptForGitHubSignIn(endpoint)

    if (!account) {
      setHasRejectedCredentialsForEndpoint(token, endpoint)
    }

    return credWithAccount(cred, account)
  }

  // GitHub.com/GHE creds are only stored internally
  if (endpointKind !== 'generic') {
    return undefined
  }

  return useExternalCredentialHelper()
    ? getExternalCredential(cred, token)
    : getGenericCredential(cred, token)
}

/**
 * The dialog shown when a repository is a fork but its upstream remote doesn't
 * point to the parent repository.
 */
export class UpstreamAlreadyExists extends React.Component<IUpstreamAlreadyExistsProps> {
  public render() {
    const name = this.props.repository.name
    const gitHubRepository = forceUnwrap(
      'A repository must have a GitHub repository to add an upstream remote',
      this.props.repository.gitHubRepository
    )
    const parent = forceUnwrap(
      'A repository must have a parent repository to add an upstream remote',
      gitHubRepository.parent
    )
    const parentName = parent.fullName
    const existingURL = this.props.existingRemote.url
    const replacementURL = parent.cloneURL
    return (
      <Dialog
        title={
          __DARWIN__ ? 'Upstream Already Exists' : 'Upstream already exists'
        }
        onDismissed={this.props.onDismissed}
        onSubmit={this.onUpdate}
        type="warning"
      >
        <DialogContent>
          <p>
            The repository <Ref>{name}</Ref> is a fork of{' '}
            <Ref>{parentName}</Ref>, but its <Ref>{UpstreamRemoteName}</Ref>{' '}

              Current: <Ref>{existingURL}</Ref>
            </li>
            <li>

    )
  }
