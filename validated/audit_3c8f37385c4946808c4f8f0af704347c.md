### Title
Unbounded dust UTXOs to the multisig address are reported as spendable funds, forcing fee-burning or unconstructable transactions - (File: networks/bitcoin/src/wallet/mod.rs + networks/bitcoin/src/wallet/send.rs)

### Summary
The Bitcoin `Scanner` reports every output paying to a registered `script_pubkey` as a `ReceivedOutput`, with no minimum-value filter, while `SignableTransaction::new` applies the `DUST` check only to payments, never to inputs. An unprivileged attacker can therefore flood a Serai multisig address with dust-valued UTXOs. Each such input must either be spent — costing more in fees than its value — or carried as an unreclaimable balance; and enough of them push any consolidation transaction over `MAX_STANDARD_TX_WEIGHT`, making `SignableTransaction::new` return `TooLargeTransaction` and the funds unspendable through the library.

### Finding Description
`Scanner::scan_transaction` in `networks/bitcoin/src/wallet/mod.rs` (lines 199-214) matches outputs purely on `script_pubkey` via `self.scripts.get(&output.script_pubkey)` and emits a `ReceivedOutput` for any value, including 1-sat dust. There is no value check anywhere in `ReceivedOutput::read` (lines 122-134) or the scanner.

In `SignableTransaction::new` (`networks/bitcoin/src/wallet/send.rs`):
- The `DUST` (546 sat) bound is enforced only on `payments` (lines 165-169); the `inputs` vector is summed and spent unconditionally (lines 175-185).
- A Taproot key-spend input costs ~57.5 vB. At any fee rate ≥ ~10 sat/vB, spending a dust output costs more than its 546-sat value; spending a 1-sat output is pure loss. `fee()` (lines 138-141) silently absorbs this: `sum(inputs) - sum(outputs)`.
- The weight check `weight > MAX_STANDARD_TX_WEIGHT` (lines 241-243) means an attacker who deposits enough dust (~600+ small UTXOs) to the group address makes it impossible to construct a transaction spending the full UTXO set — the library has no input-selection/`skip` mechanism and `multisig()` (lines 273-285) requires one `AlgorithmMachine` per input with matching offsets.

The intended mitigation in the referenced class — a `min_delegation_amount` ensuring every entry contributes meaningfully — is exactly what is missing here: there is no minimum received-output value below which the scanner ignores or the signer can safely refuse an output.

### Impact Explanation
An unprivileged third party (anyone who knows the multisig's `p2tr` script, which is public on-chain) can:
1. Cause the scanner to report funds as "received" that cannot be spent without net loss — satisfying "funds reported received that are not spendable."
2. By depositing enough dust, make the entire UTXO set unspendable in a single `SignableTransaction` (weight cap), permanently burning dust value into fees or forcing consolidation attempts to fail with `TooLargeTransaction`.

This is the direct analog of filling a bounded capacity with fake/dust entries to deny service to legitimate users.

### Likelihood Explanation
Requires only standard Bitcoin transactions to a publicly known address — no validator status, no collusion, no secret material. Cost to the attacker is the dust itself (~546 sat per output minimum for relay-standard outputs), which is cheap relative to denying a threshold multisig the ability to cleanly spend its balance. Reachability is fully public via `scan_transaction`/`scan_block` → `SignableTransaction::new` → `TransactionMachine`.

Severity: **Medium** — DoS/economic griefing of the multisig's spend path, no key or signature compromise.

### Recommendation
- Enforce a minimum output value (e.g., `DUST` or a configurable floor above the marginal spend cost at reasonable fee rates) in `Scanner::scan_transaction`/`ReceivedOutput`, so dust is never registered as a spendable received output.
- Alternatively/additionally, allow `SignableTransaction::new` to select a subset of inputs (skip uneconomical ones) and surface per-input marginal fee cost so callers can exclude dust without failing the whole spend.

### Proof of Concept
```rust
// Networks/bitcoin analog of "fill the list with dust delegators":
// 1. Attacker crafts txs paying dust to the multisig's p2tr script_pubkey.
let dust_tx = Transaction {
    // ... one output of 546 sats (or less) to `p2tr_script_buf(group_key)`
    ..Default::default()
};
// 2. Scanner accepts it unconditionally — no minimum-value check.
let received: Vec<ReceivedOutput> = scanner.scan_transaction(&dust_tx);
assert_eq!(received.len(), 1);          // dust is registered as spendable
assert_eq!(received[0].value(), 546);   // marginal spend cost > value at ~10 sat/vB

// 3. Repeat ~600+ times; then attempting to spend the full set:
let res = SignableTransaction::new(all_received, &payments, change, None, fee_per_vbyte);
// Each input adds ~57.5 vB witness+input weight; total exceeds
// MAX_STANDARD_TX_WEIGHT -> Err(TransactionError::TooLargeTransaction).
// SignableTransaction provides no way to drop uneconomical inputs.
```
