### Title
NFT metadata-updater `prepend_value` type confusion crashes wallet sync/RPC on malicious "-24" metadata update - ([File: chia/wallet/nft_wallet/nft_puzzle_utils.py])

### Summary
`prepend_value()` in `chia/wallet/nft_wallet/nft_puzzle_utils.py` assumes that any existing metadata value is either the CLVM-empty-atom sentinel (`b""`) or a Python `list`, and unconditionally calls `.insert()` on it without checking its actual type. This is structurally the same class of bug as CVE-2026-9334: a value coming from untrusted, attacker-controlled data (an on-chain NFT metadata key/value pair) is treated as a specific container type without verifying that type first, leading to a crash when the assumption is violated. [1](#0-0) 

### Finding Description
`nft_program_to_metadata()` converts the on-chain metadata CLVM program into a Python `dict[bytes, Any]` by calling `.as_python()` on each value with no type normalization: [2](#0-1) 

Depending on the metadata key, `as_python()` can yield either a plain `bytes` atom (e.g., keys like `"h"`/data_hash, `"mh"`, `"lh"`, `"sn"`, `"st"` which are minted as single atoms — see `nft_mint_nft` building `metadata_list` with atoms such as `request.hash`, `edition_number`, etc.) or a `bytes`-encoded list for URI fields: [3](#0-2) 

`prepend_value()` is then called from `update_metadata()` when a "-24" metadata-update condition is executed against an existing NFT coin:
```
def prepend_value(key: bytes, value: Program, metadata: dict[bytes, Any]) -> None:
    if value != Program.to(0):
        if metadata[key] == b"":
            metadata[key] = [value.as_python()]
        else:
            metadata[key].insert(0, value.as_python())
``` [1](#0-0) 

The `else` branch calls `.insert(0, ...)`, a `list`-only method, on `metadata[key]` without checking whether that value is actually a `list`. If the targeted key currently holds a non-empty `bytes` atom (the normal representation for keys like `"h"`, `"mh"`, `"lh"`, `"sn"`, `"st"`), `metadata[key].insert(...)` raises `AttributeError: 'bytes' object has no attribute 'insert'`. This mirrors the root cause pattern in the CVE: dereferencing/operating on a value under an unchecked type assumption derived from attacker-influenced input.

`update_metadata()` (the puzzle-level function, not the wallet RPC-level method) is invoked whenever a wallet processes the metadata resulting from an on-chain `-24` condition, via `get_metadata_and_phs`, which is called from:
- `NFTWallet.puzzle_solution_received()`, triggered automatically for every coin the wallet syncs that uncurries as an NFT and is relevant to the wallet. [4](#0-3) 
- `WalletStateManager.manual_nft_search()`, reachable via the `nft_get_info` RPC for an arbitrary attacker-supplied coin id. [5](#0-4) [6](#0-5) 

The exact body of `get_metadata_and_phs` (which calls `update_metadata`) was not fully retrievable within the tool-call budget; the call sites and the vulnerable `prepend_value`/`update_metadata` pair were confirmed directly, but the precise line range of `get_metadata_and_phs` itself is unverified — this should be double-checked in a follow-up session.

### Impact Explanation
A coin-spend author (any party who owns/controls an NFT's inner puzzle, or a counterparty in an NFT offer/transfer) can craft a spend that emits a `(-24 NFT_METADATA_UPDATER (key . value))` condition targeting a metadata key that is currently a scalar atom (e.g., `"h"`, `"mh"`, `"lh"`, `"sn"`, `"st"`) instead of a URI-list key. Any wallet that syncs this coin (because it is relevant to that wallet, e.g., it is the new owner, or was queried via `nft_get_info`) will crash inside `prepend_value` while trying to derive the updated NFT metadata during normal coin-processing/sync. This is a spend-triggered halt of NFT coin processing for any wallet that observes the malicious spend, which matches the "spend-triggered transaction-processing halt" impact category.

### Likelihood Explanation
Any user who owns or receives an NFT, or crafts an offer/transfer involving one, can trigger the vulnerable code path without special privileges — no consensus/mempool changes are required, only a spend that a wallet later syncs. This is directly reachable by an ordinary wallet/NFT counterparty and does not require malicious peer/node/farmer behavior.

### Recommendation
In `prepend_value()`, explicitly verify that `metadata[key]` is a `list` before calling `.insert()`; if it is not a list (or not the `b""` sentinel), either raise a well-defined, caught exception or convert/replace the value into a list first. Wrap `get_metadata_and_phs`/`update_metadata` processing in `puzzle_solution_received` and `manual_nft_search` with exception handling so that a malformed or adversarial metadata update cannot abort wallet sync or the RPC call outright.

### Proof of Concept
1. Mint an NFT with `edition_number` (`"sn"`) as a plain atom (default minting behavior via `nft_mint_nft`). [3](#0-2) 
2. Spend the NFT coin with a solution containing a metadata-updater condition `[-24, NFT_METADATA_UPDATER, (b"sn" . <nonzero atom>)]` targeting the `"sn"` key instead of a URI key.
3. Any wallet syncing this spend (the new owner, or an RPC caller invoking `nft_get_info`/`manual_nft_search` on this coin id) will call `update_metadata` → `nft_program_to_metadata` → `prepend_value`, where `metadata[b"sn"]` is a non-empty `bytes` atom, and `metadata[key].insert(0, ...)` raises `AttributeError`, aborting the wallet's coin-processing/RPC call. def nft_program_to_metadata(program: Program) -> dict[bytes, Any]:
    """
    Convert a program to a metadata dict
    :param program: Chialisp program contains the metadata
    :return: Metadata dict
    """
    metadata = {}
    for kv_pair in program.as_iter():
        metadata[kv_pair.first().as_atom()] = kv_pair.rest().as_python()
    return metadata
```

    """
    Prepend a value to a list in the metadata
    :param key: Key of the field
    :param value: Value want to add
    :param metadata: Metadata
    :return:
    """
    if value != Program.to(0):
        if metadata[key] == b"":
            metadata[key] = [value.as_python()]
        else:

def update_metadata(metadata: Program, update_condition: Program) -> Program:
    """
    Apply conditions of metadata updater to the previous metadata
    :param metadata: Previous metadata
    :param update_condition: Update metadata conditions
    :return: Updated metadata
    """
    new_metadata: dict[bytes, Any] = nft_program_to_metadata(metadata)
    uri: Program = update_condition.rest().rest().first()
    prepend_value(uri.first().as_python(), uri.rest(), new_metadata)
    return metadata_to_program(new_metadata)
