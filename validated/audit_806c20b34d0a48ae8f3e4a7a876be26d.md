### Title
DataLayer mirror-URL Server-Side Request Forgery via unauthenticated on-chain mirror announcements - (File: `chia/data_layer/data_layer.py`)

### Summary
Any wallet holder can broadcast a standard-puzzle spend to the DataLayer mirror puzzle (`create_mirror_puzzle()`) that announces an arbitrary `launcher_id` (store id) together with an arbitrary list of URLs, without owning or having any relationship to that store. Every full node running the DataLayer service that tracks that `launcher_id` (as an owner or as a subscriber) picks up the announced URL through `DataLayerWallet.coin_added` and, on its periodic sync loop, unconditionally fetches it with `aiohttp` in `http_download()`. There is no allow-list, DNS-resolution check, or private/loopback/link-local address filtering before the outbound request is made, producing a Server-Side Request Forgery analogous to the reported automad `FileController::import` `importUrl` SSRF (CVE-2023-7037).

### Finding Description
Mirror creation is implemented as a plain coin spend to `create_mirror_puzzle()` carrying `launcher_id` and `urls` in memos/solution, with no proof that the spender owns or is associated with the target singleton [1](#0-0) .

When such a coin is seen on chain, `DataLayerWallet.coin_added` matches on the mirror puzzle hash alone and, if the referenced `launcher_id` is a tracked launcher, stores the announced URLs as a `Mirror` record — again with no ownership/authorization check other than a cosmetic `ours` flag used only for UI purposes: [2](#0-1) 

The `DataLayer` service periodically calls `update_subscriptions_from_wallet()`, which pulls every mirror URL for a store id from the wallet and inserts them into the local `subscriptions` table used for fetch attempts: [3](#0-2) 

This is invoked unconditionally as the first step of `update_subscription()`, which is itself scheduled for every tracked/owned/subscribed store in `periodically_manage_data()`: [4](#0-3) 

`fetch_and_validate()` then iterates the (randomly shuffled) server list and, for stores without a plugin downloader configured, calls `download_file()` → `http_download()`: [5](#0-4) [6](#0-5) 

`http_download()` performs a raw `aiohttp` GET to `server_info.url + "/" + filename` with no destination validation whatsoever (no SSRF protections such as blocking loopback/link-local/private ranges, no restriction to https, no DNS-rebinding mitigation): [7](#0-6) 

The module's own documentation acknowledges mirror/plugin URLs are untrusted external inputs, but the mitigation implemented is limited to validating the *downloaded data* against the wallet-advertised Merkle root — not to validating the *destination* of the outbound HTTP request itself: [8](#0-7) 

### Impact Explanation
Any unprivileged wallet user (or DataLayer client) can force any node that runs the DataLayer service and is currently tracking a given store (its own stores are auto-pseudo-subscribed, and any user can also explicitly `subscribe` to a foreign store) into performing outbound HTTP GET requests to attacker-chosen URLs, including internal/private-network addresses, cloud metadata endpoints (e.g. `169.254.169.254`), or other hosts reachable only from the victim's network. Because the request path and query segment (`filename`) is partially attacker-influenced deltas naming, this can also be leveraged for internal service probing/port-scanning, or for pivoting into internal infrastructure from an operator's DataLayer host. This is a real, spend-triggered SSRF against any node that has DataLayer enabled, which matches the reachable-impact bar for "medium/high" per the rules (unauthorized server-side action triggered by an unprivileged submission).

### Likelihood Explanation
Likelihood is high: creating the malicious mirror coin only requires a standard, unprivileged coin spend (any wallet with dust XCH can build the spend to `create_mirror_puzzle()` with attacker-controlled `launcher_id`/`urls` memos), and the victim behavior (periodic sync fetch) is fully automatic once the store id is tracked — no interaction from the store owner is required beyond having their store synced by nodes running DataLayer.

### Recommendation
- Enforce a strict SSRF-safe HTTP client for `http_download()` / `download_file()`: resolve the hostname before connecting and reject loopback, link-local, private, multicast, and metadata-service address ranges (with re-validation to prevent DNS rebinding, e.g. pinning the resolved IP for the connection).
- Consider requiring an explicit user opt-in / allow-list for mirror URLs pulled from chain (`update_subscriptions_from_wallet`) instead of automatically trusting any mirror coin matching the puzzle hash for a tracked launcher id.
- Restrict mirror creation validation so a `Mirror` record is only honored when it can be tied to the singleton owner's authorized transactions, or otherwise clearly labeled as untrusted and require explicit operator approval before it is used for automatic fetches.

### Proof of Concept
1. Attacker wallet spends any coin to `create_mirror_puzzle()`'s puzzle hash with solution/memo `[launcher_id_of_victim_store, "http://169.254.169.254/latest/meta-data/", ...]` per `chia/data_layer/data_layer_wallet.py:700-703` (`create_new_mirror` construction).
2. The transaction confirms on chain.
3. Any node running the DataLayer service that tracks `launcher_id_of_victim_store` (owner or subscriber) observes the mirror coin in `DataLayerWallet.coin_added` (`chia/data_layer/data_layer_wallet.py:775-800`) and stores the attacker URL as a `Mirror`.
4. On the next `periodically_manage_data()` cycle, `update_subscription()` calls `update_subscriptions_from_wallet()` (`chia/data_layer/data_layer.py:979-985`), inserting the attacker URL into the subscriptions table.
5. `fetch_and_validate()` selects that server and calls `download_file()` → `http_download()` (`chia/data_layer/download_data.py:298-320`), causing the victim node to issue an outbound HTTP GET to the attacker-controlled/internal URL.

```python
async def http_download(
    target_filename_path: Path,
    filename: str,
    proxy_url: str | None,
    server_info: ServerInfo,
    timeout: aiohttp.ClientTimeout,
    log: logging.Logger,
    max_delta_file_size: int,
) -> None:
    """
    Download a file from a server using aiohttp.
    Raises exceptions on errors
    """
    async with aiohttp.ClientSession() as session:
        headers = {"accept-encoding": "gzip"}
        async with session.get(
            server_info.url + "/" + filename,
            headers=headers,
            timeout=timeout,
            proxy=proxy_url,
        ) as resp:
            resp.raise_for_status()
            size = int(resp.headers.get("content-length", 0))
```
