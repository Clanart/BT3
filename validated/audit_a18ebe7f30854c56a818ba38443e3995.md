### Title
Malicious git remote can spoof `WWW-Authenticate: realm="GitHub"` to force an unsolicited GitHub Enterprise sign-in bound to an attacker-controlled endpoint - ([File: app/src/lib/trampoline/trampoline-credential-helper.ts])

### Summary
The credential-helper trampoline decides whether a remote host should be treated as a GitHub/GitHub-Enterprise endpoint (and therefore auto-launch a GitHub sign-in dialog) partly by trusting the `wwwauth[]` credential fields, which are populated verbatim from the HTTP `WWW-Authenticate` response header of the remote server. A remote that is fully attacker-controlled can set this header to `realm="GitHub"` and get classified as `'enterprise'`, causing Desktop to open a "Sign in to GitHub Enterprise" flow bound to the attacker's own host without the user ever electing to add or trust that host as a GitHub Enterprise server.

### Finding Description
Similar to the `MuteAmplifier.rescueTokens` bug — which trusted an internal accounting value (`_totalWeightFee0`) instead of verifying the real on-chain state before acting — `getEndpointKind` in [1](#0-0)  trusts a value that is entirely supplied by the untrusted remote (the `WWW-Authenticate` header, surfaced to Desktop by Git as `wwwauth[]` fields) as a stand‑in for "this host is a real GitHub Enterprise host," without any independent verification (e.g., hitting `/api/v3/meta` or checking a known GHE signature):

```
for (const [k, v] of cred.entries()) {
    if (k.startsWith('wwwauth[')) {
      if (v.includes('realm="GitHub"')) {
        return 'enterprise'
      } else if (/realm="(GitLab|Gitea|Atlassian Bitbucket)"/.test(v)) {
        return 'generic'
      }
    }
  }
```

This classification feeds directly into `getCredential`, which — for any endpoint classified as non-`'generic'` that has no matching stored account — automatically calls `ui.promptForGitHubSignIn(endpoint)`: [2](#0-1) 

`promptForGitHubSignIn` then unconditionally begins a GitHub Enterprise sign-in flow scoped to the attacker's own `origin` (derived straight from the credential URL) whenever the hostname isn't literally `github.com`: [3](#0-2) 

```
const { hostname, origin } = new URL(endpoint)
if (hostname === 'github.com') {
  this.dispatcher.beginDotComSignIn(cb)
} else {
  this.dispatcher.beginEnterpriseSignIn(cb)
  await this.dispatcher.setSignInEndpoint(origin)
}
```

Nothing here validates that `origin` (attacker's server) is a legitimate GitHub Enterprise instance beyond what the credential-helper protocol already reported. The only signal used to distinguish "generic git host" from "trust this as a GitHub endpoint and offer OAuth/token sign-in" is a header value the remote server fully controls.

Unlike the `lpToken`/`muteToken` invariant in the `MuteAmplifier` case, which is protected by a balance check against actual contract state, this classification has no analogous cross-check against actual GitHub/GHE identity (e.g., contacting `/api/v3/meta`, checking a TLS cert pinned to a known enterprise, or requiring the user to have manually added the host as an Enterprise account).

### Impact Explanation
An attacker who controls a git server that a user fetches/clones/pushes from (a very low bar — this covers any malicious remote URL a user is lured into using, unrelated to whether the repo content itself is malicious) can:
1. Respond to Git's HTTP credential negotiation with `WWW-Authenticate: Basic realm="GitHub"`.
2. Cause Desktop's credential-helper trampoline to classify the attacker's host as `'enterprise'`.
3. Auto-trigger an unsolicited "Sign in to GitHub Enterprise" dialog scoped to the attacker's domain.

This matches the "unauthorized OAuth or account binding" impact category: the user is nudged into completing an OAuth/token sign-in flow they did not request, tied to a host they may not recognize as untrusted, potentially leading to credential/token exposure to, or account binding against, an attacker-controlled endpoint.

### Likelihood Explanation
Setting an HTTP response header is a trivial, purely server-side action requiring no special privileges or user interaction beyond the user already configuring/using the malicious remote (which is within the stated "attacker controls a git remote/proxy response" threat model). The only user action needed is a normal `fetch`/`clone`/`push` that triggers a credential request, which is completely ordinary git usage and not an "unnatural" step.

### Recommendation
Do not rely solely on the self-reported `WWW-Authenticate` realm to classify a host as GitHub/GitHub Enterprise. At minimum:
- Require an explicit, user-confirmed trust action before auto-launching a GitHub sign-in flow for a host that isn't already a known/added GitHub account endpoint.
- Independently verify GHE identity (e.g., probe `/api/v3/meta` and validate the response) before trusting the `wwwauth` hint, instead of trusting the header value outright.
- At minimum, surface the actual endpoint URL prominently before beginning any browser-based sign-in so users can recognize spoofed enterprise hosts.

### Proof of Concept
1. Stand up a git-over-HTTP server (e.g., `git http-backend`) on `evil.example.com` that, on any unauthenticated request, responds with `401` and header `WWW-Authenticate: Basic realm="GitHub"`.
2. In GitHub Desktop, add `https://evil.example.com/foo/bar.git` as a remote (or clone it) and perform a `fetch`.
3. Git invokes Desktop's credential helper (`get`), which populates `wwwauth[0]=Basic realm="GitHub"` from the header per [4](#0-3) .
4. `getEndpointKind` returns `'enterprise'`; since no account exists for `evil.example.com`, `getCredential` calls `ui.promptForGitHubSignIn('https://evil.example.com')` [5](#0-4) .
5. Desktop opens a "Sign in to GitHub Enterprise" dialog bound to `evil.example.com`, initiating a real OAuth/browser sign-in flow the user did not request against a host they may believe is a benign generic git server [6](#0-5) .

/** Implementation of the 'get' git credential helper command */
async function getCredential(cred: Credential, store: Store, token: string) {
  const ghCred = await getGitHubCredential(cred, store)

  if (ghCred) {
    return ghCred
  }

  const endpointKind = await getEndpointKind(cred, store)
  const accounts = await store.getAll()

  const endpoint = `${getCredentialUrl(cred)}`
  const apiEndpoint = getAPIEndpoint(endpoint)

  // If it appears as if the endpoint is a GitHub host and we don't have an
  // account for that endpoint then we should prompt the user to sign in.
  if (
    endpointKind !== 'generic' &&
    !accounts.some(a => a.endpoint === apiEndpoint)
  ) {
    if (getIsBackgroundTaskEnvironment(token)) {
      debug('background task environment, skipping prompt')
      return undefined
    }

    const account = await ui.promptForGitHubSignIn(endpoint)

    if (!account) {
      setHasRejectedCredentialsForEndpoint(token, endpoint)
    }

    return credWithAccount(cred, account)
  }

const getEndpointKind = async (cred: Credential, store: Store) => {
  const credentialUrl = getCredentialUrl(cred)
  const endpoint = `${credentialUrl}`

  if (isGist(endpoint)) {
    return 'generic'
  }

  if (isDotCom(endpoint)) {
    return 'github.com'
  }

  if (isGHE(endpoint)) {
    return 'ghe.com'
  }

  // When Git attempts to authenticate with a host it captures any
  // WWW-Authenticate headers and forwards them to the credential helper. We
  // use them as a happy-path to determine if the host is a GitHub host without
  // having to resort to making a request ourselves.
  for (const [k, v] of cred.entries()) {
    if (k.startsWith('wwwauth[')) {
      if (v.includes('realm="GitHub"')) {
        return 'enterprise'
      } else if (/realm="(GitLab|Gitea|Atlassian Bitbucket)"/.test(v)) {
        return 'generic'
      }
    }
  }

  public promptForGitHubSignIn(endpoint: string): Promise<Account | undefined> {
    return new Promise<Account | undefined>(async resolve => {
      const cb = (result: SignInResult) => {
        resolve(result.kind === 'success' ? result.account : undefined)
        this.dispatcher.closePopup(PopupType.SignIn)
      }

      const { hostname, origin } = new URL(endpoint)
      if (hostname === 'github.com') {
        this.dispatcher.beginDotComSignIn(cb)
      } else {
        this.dispatcher.beginEnterpriseSignIn(cb)
        await this.dispatcher.setSignInEndpoint(origin)
      }

      this.dispatcher.showPopup({
        type: PopupType.SignIn,
        isCredentialHelperSignIn: true,
        credentialHelperUrl: endpoint,
      })
    }).catch(e => {
      log.error(`Could not prompt for GitHub sign in`, e)
      return undefined
    })
  }
