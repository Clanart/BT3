### Title
Instantaneous (non time-weighted) forfeiture check in `_calExpireForfeit` lets users cancel a cooldown right before claiming to avoid all reward forfeiture - ([File: VLMGP.sol], [File: rewards/vlMGPBaseRewarder.sol])

### Summary
`vlMGPBaseRewarder._calExpireForfeit` computes the forfeited share of accrued rewards using `VLMGP.getRewardablePercentWAD(_account)` evaluated only at the moment `getReward`/`getRewards` is called, not integrated over the accrual period. Because `cancelUnlock` is instant, free, and does not trigger a reward settlement, a user can leave a large cooldown slot open for an extended reward-accrual window (earning full-balance rewards the whole time) and then call `cancelUnlock` immediately before claiming, forcing `getRewardablePercentWAD` back to `1e18` and paying zero forfeiture on rewards that accrued while a large fraction of their stake was nominally "in cooldown".

### Finding Description
- `VLMGP.getUserTotalLocked` (VLMGP.sol:125-129) computes `fullyInLock` as `stakingInfo` amount minus **all** `amountInCoolDown` across slots, and `getRewardablePercentWAD` (VLMGP.sol:193-218) derives the forfeitable percent from this instantaneous split of locked vs. cooling-down balance. [1](#0-0) [2](#0-1) 
- `startUnlock` opens a cooldown slot, but first calls `multiclaimFor` so the reward-accrual window (`userRewardPerTokenPaid`) is reset to the pre-cooldown, fair state. [3](#0-2) 
- `cancelUnlock` zeroes `slot.amountInCoolDown` and reduces `totalAmountInCoolDown` — instantly and at zero cost — but critically does **not** call `multiclaimFor`/settle rewards, so no forfeiture is ever assessed against the time actually spent in cooldown. [4](#0-3) 
- In `vlMGPBaseRewarder`, `_sendReward`/`_calExpireForfeit` compute the forfeit using the **current** `getRewardablePercentWAD` applied to the entire reward amount accumulated since the last update, rather than a time-weighted average of the percent over the accrual window: `uint256 rewardablePercentWAD = vlMGP.getRewardablePercentWAD(_account); uint256 rewardableAmount = _amount * rewardablePercentWAD / 1e18;`. [5](#0-4) 
- Exploit flow: `startUnlock(largeAmount)` (resets accrual baseline at 100% fair state) → hold the cooldown open while rewards accrue at the full (undiminished) `balanceOf` rate in `vlMGPBaseRewarder` (VLMGP.sol:145-148 style `stakingInfo`, unaffected by cooldown) → `cancelUnlock(slot)` immediately before claiming (instant, zero penalty, no reward settlement) → `multiclaim`/`getReward` now evaluates `getRewardablePercentWAD == 1e18`, so `_calExpireForfeit` returns `forfeitAmount = 0` for the entire accrued reward, even though a large portion of the stake was nominally "in cooldown" (i.e., partially forfeitable) for most of the accrual period.
- No existing guard (`nonReentrant`, `whenNotPaused`, index update) prevents this because `cancelUnlock` intentionally allows reverting a cooldown at any time, and the forfeiture math was never designed to account for time spent in a since-cancelled slot.

### Impact Explanation
This breaks the conservation invariant that forfeiture should track sustained lock/unlock behavior: the "cooldown" mechanic is supposed to discount rewards proportional to how "unlocked" a user's stake has been, but its enforcement point is a spot check that is trivially reset. Any staker can systematically avoid all reward forfeiture regardless of how much of their historical accrual period they spent in cooldown, simply by ensuring the last action before every `getReward`/`multiclaim` call is `cancelUnlock`. Forfeited amounts are supposed to be redistributed to the broader pool via `_queueNewRewardsWithoutTransfer` (VLMGP.sol reward path), so systemic avoidance of forfeiture reduces the yield redistributed to honest stakers and lets the manipulating user permanently capture more than their entitled, forfeiture-adjusted share — a theft of unclaimed/redistributable yield (Immunefi: theft of unclaimed yield).

### Likelihood Explanation
- Fully permissionless: only requires holding vlMGP (any staked amount) and calling public/external `startUnlock`, `cancelUnlock`, and the standard `multiclaim`/`getReward` path — no privileged role needed.
- `cancelUnlock` has no cooldown-elapsed requirement beyond being "in cooldown" and carries zero penalty, so it can be invoked at will right before any claim transaction.
- Fully repeatable: the pattern (`startUnlock` → wait/accrue → `cancelUnlock` → `claim`) can be repeated indefinitely by any staker, and requires no special capital beyond the vlMGP the user already holds/wants to eventually unlock.
- The only friction is intentional user discipline (remembering to cancel before claiming), which is trivial to encode in a bot/script.

### Recommendation
Do not compute forfeiture using only the instantaneous `getRewardablePercentWAD` at claim time. Either:
1. Settle/checkpoint rewards (call `_updateFor`/apply forfeiture) on every state transition that changes cooldown status (`startUnlock`, `cancelUnlock`, `unlock`), so forfeiture is assessed against the percent that was actually in effect during each sub-interval, not just the value at final claim time; or
2. Track a time-weighted average of `getRewardablePercentWAD` across the reward-accrual interval (similar to a checkpointed reward-per-share model) and apply forfeiture against that integrated value instead of the spot value.
At minimum, `cancelUnlock` should trigger a reward settlement (as `startUnlock`/`unlock` already do via `multiclaimFor`) so that any accrued rewards up to that point are settled against the (correctly discounted) percent that was in effect while the cooldown was open, before the state is reset to 100% locked.

### Proof of Concept
Foundry test plan:
1. Deploy `VLMGP`, `MasterMagpie`, and `vlMGPBaseRewarder` with a reward token; set `coolDownInSecs` to a realistic value (e.g., 7 days).
2. `attacker` locks a large amount of MGP via `VLMGP.lock`.
3. Assert `vlMGP.getRewardablePercentWAD(attacker) == 1e18`.
4. `attacker` calls `startUnlock(largeAmount)` (e.g., 90% of stake). Assert `getRewardablePercentWAD(attacker)` drops well below `1e18`.
5. Fast-forward time close to `coolDownInSecs` (e.g., 90% elapsed) and have `queueNewRewards`/`queueMGP` inject rewards into `vlMGPBaseRewarder` so `attacker` accrues `earned(attacker, token)` over this window.
6. `attacker` calls `cancelUnlock(slot)`. Assert `getRewardablePercentWAD(attacker) == 1e18` again, immediately, at zero gas/economic cost beyond the transaction fee.
7. `attacker` calls `MasterMagpie.multiclaimFor`/`vlMGPBaseRewarder.getReward`. Assert `forfeitAmount == 0` and `toSend == earned(attacker, token)` in full, despite having spent ~90% of the accrual window with 90% of stake nominally in cooldown.
8. Compare against a control staker who holds the same cooldown open and claims *without* canceling first — assert that control staker's claim triggers a nonzero `forfeitAmount` via `_calExpireForfeit`, proving the attacker fully evaded the intended forfeiture by timing `cancelUnlock` before the claim.

    function getRewardablePercentWAD(address _user) override public view returns(uint256 percent) {
        uint256 fullyInLock = getUserTotalLocked(_user);
        uint256 inCoolDown = getUserAmountInCoolDown(_user);
        uint256 userTotalVlmgp = fullyInLock + inCoolDown;
        if (userTotalVlmgp == 0)
            return 0;
        percent = fullyInLock * 1e18 / userTotalVlmgp;

        uint256 timeNow = block.timestamp;
        UserUnlocking[] storage userUnlocking = userUnlockings[_user];

        for (uint256 i; i < userUnlocking.length; i++) {
            if (userUnlocking[i].amountInCoolDown > 0) {
                if (block.timestamp > userUnlocking[i].endTime) {// fully unlocked 
                    percent += userUnlocking[i].amountInCoolDown * 1e18 * (userUnlocking[i].endTime - userUnlocking[i].startTime)
                        / userTotalVlmgp / (timeNow - userUnlocking[i].startTime);
                }
                else {// still in cool down 
                    percent += userUnlocking[i].amountInCoolDown * 1e18 / userTotalVlmgp;
                }

            }
        }

        return percent;
    }

    function _calExpireForfeit(address _account, uint256 _amount) internal view returns (uint256) {
        uint256 rewardablePercentWAD = vlMGP.getRewardablePercentWAD(_account);
        uint256 rewardableAmount = _amount * rewardablePercentWAD / 1e18;
        if (rewardableAmount > _amount)
            revert InvalidRewardableAmount();

        uint256 forfeitAmount = _amount - rewardableAmount;
        
        if (forfeitAmount < (_amount / 1000)) {  // if forfeitAmount is smaller than 0.1% ignore to save gas fee
            forfeitAmount = 0;
            rewardableAmount = _amount;
        }

        return forfeitAmount;
    }
