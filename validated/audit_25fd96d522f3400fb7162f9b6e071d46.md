### Title
Identity encryption key exposes a participant’s threshold key share - ([File: crypto/dkg/pedpop/src/encryption.rs](crypto/dkg/pedpop/src/encryption.rs))

### Summary
PedPoP accepts the group identity as a participant’s encryption public key. When that key is registered, every honest sender derives the ECDH point `ephemeral_private * identity`, which is always identity. The resulting ChaCha20 key is therefore publicly computable, allowing anyone who observes the encrypted secret-share messages to recover all shares sent to that participant and sum them into the participant’s threshold key share.

### Finding Description
`EncryptionKeyMessage::read` deserializes `enc_key` through `C::read_G` but does not reject the identity point. [1](#0-0)  The generic `read_G` implementation validates canonical encoding but does not reject identity. [2](#0-1)  During registration, the supplied point is inserted directly into the recipient-key map without an additional validity or proof-of-possession check. [3](#0-2) 

When a sender encrypts a share, it computes `msg.key * ephemeral_private`, or equivalently `ephemeral_private * recipient_enc_key`. [4](#0-3)  If `recipient_enc_key` is identity, the ECDH result is always identity. [5](#0-4)  The cipher key is derived solely from the public context and this ECDH point. [6](#0-5) 

The recipient sums every decrypted scalar share to form its final secret share. [7](#0-6)  Consequently, a passive observer who derives the public identity ECDH key can decrypt every share sent to the malicious participant and recover that participant’s final share.

### Impact Explanation
An attacker can cause the public recovery of a threshold key share without knowing any participant’s secret. The attacker registers the identity encoding as their encryption key. All shares addressed to them are encrypted under a publicly known stream-cipher key. Reconstructing the participant’s key share reduces the threshold security margin and can become key recovery if the attacker obtains the remaining threshold shares through compromise or a separate protocol weakness.

### Likelihood Explanation
The attack requires the attacker to participate in a DKG round and supply a malformed, but accepted, registration message. Honest participants accept the identity point because deserialization checks only point validity and canonical form. The attacker can retain the corresponding zero private key and decrypt normally, so the malformed registration does not prevent protocol completion or reliably identify malicious behavior.

### Recommendation
Reject identity points when deserializing or registering `EncryptionKeyMessage::enc_key`. Preferably require the encryption public key to be non-identity and bound to the participant and commitments with a proof of possession. The check should also be applied defensively before ECDH in `encrypt`, so an invalid key cannot produce a deterministic public shared secret.

### Proof of Concept
```rust
// Malicious participant p chooses the identity as its encryption public key
// and retains private scalar zero.
let malicious_enc_key = C::G::identity();
let malicious_enc_secret = Zeroizing::new(C::F::ZERO);

// EncryptionKeyMessage::read accepts this because C::read_G only checks
// that the point is valid and canonical.
let registration = EncryptionKeyMessage::<C, Commitments<C>> {
  msg: valid_commitments,
  enc_key: malicious_enc_key,
};

// For each honest sender s, encryption computes:
//
//   shared = ephemeral_private_s * malicious_enc_key
//          = ephemeral_private_s * identity
//          = identity
//
// The public context and identity point therefore fully determine the
// ChaCha20 stream used to encrypt `SecretShare`.
let public_shared_key = C::G::identity();
let mut observer_cipher = cipher::<C>(public_context, &Zeroizing::new(public_shared_key));

// For every EncryptedMessage sent to p, the observer applies the keystream
// to the ciphertext and parses the resulting scalar representation.
let share_i = C::F::from_repr(decrypted_bytes).unwrap();

// After collecting every sender's message to p, sum the decrypted shares.
let recovered_p_share = sum(share_i);
assert_eq!(C::generator() * recovered_p_share, verification_shares[p]);
```

  fn read_G<R: Read>(reader: &mut R) -> io::Result<Self::G> {
    let mut encoding = <Self::G as GroupEncoding>::Repr::default();
