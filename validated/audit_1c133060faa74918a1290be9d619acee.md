### Title
Unauthorized minting of native bank coins via permissionlessly-registered malicious ERC20 in ConvertERC20 - (File: x/erc20/keeper/msg_server.go)

### Summary
When `permissionless_registration` is enabled, any unprivileged EVM account can register an arbitrary, self-deployed ERC20 contract as a "native ERC20" token pair, then call `ConvertERC20` to mint real, spendable native Cosmos bank coins backed by nothing, because the module's escrow-verification logic only checks the malicious contract's own self-reported storage rather than any externally-verifiable value.

### Finding Description
`RegisterERC20` allows a non-governance signer to register any ERC20 contract address as long as `params.PermissionlessRegistration` is true [1](#0-0) . The registration itself performs no validation of the contract's `transfer`/`balanceOf` correctness — it only creates coin metadata and stores the pair as `OWNER_EXTERNAL` (`IsNativeERC20`) [3](#0-2) [2](#0-1) .

`ConvertERC20` for a native-ERC20 pair calls `convertERC20IntoCoinsForNativeToken`, which:
1. Reads `balanceToken` = `BalanceOf(moduleAddress)` on the (attacker-controlled) contract.
2. Calls `transfer(ModuleAddress, msg.Amount)` on that same contract via `CallEVMWithData` [4](#0-3) .
3. Re-reads `balanceTokenAfter` = `BalanceOf(moduleAddress)` on the same contract and checks it increased by exactly `msg.Amount` [5](#0-4) .
4. Based solely on that self-referential check passing, it mints `msg.Amount` of *real* native bank coins and sends them to the receiver [6](#0-5) .

Because steps 1–3 only query and compare state inside the attacker's own contract, a malicious contract can trivially satisfy the invariant (e.g., simply increment an internal mapping for any caller's "transfer" call with no real backing, no real total-supply constraint, no real prior balance requirement). The module then mints unbacked native coins 1:1 with fake ERC20 balances. Since `pair.Denom` becomes a normal bank denom usable everywhere in the chain (transfers, staking, precompiles, IBC), the attacker converts these fabricated coins into real spendable value or bridges them out via IBC before anyone notices, since `ConvertCoinNativeERC20`'s corresponding check is equally self-referential to the same malicious contract [7](#0-6) .

This is conceptually the same bug class as the Mover finding: a security invariant ("only escrow the amount actually received/backed") is enforced by trusting a value that the untrusted, attacker-supplied external contract fully controls, rather than an independent, module-owned source of truth.

### Impact Explanation
This allows an unprivileged attacker to mint unlimited native Cosmos SDK bank coins (any denom name chosen at registration) with no real backing, i.e., unauthorized minting / irreversible accounting corruption of spendable user value, which is explicitly in the Critical allowed-impact list. Because the resulting coin is a genuine bank-module coin, the attacker can spend, stake, or IBC-transfer it like real value, diluting/breaking any pool, market, or other holders' balances denominated in that "native ERC20" backed coin, and potentially draining counter-value from any Instance that assumes registered ERC20/coin pairs are 1:1 backed.

### Likelihood Explanation
Requires only `permissionless_registration = true`, which is an explicit, tested, non-privileged production configuration in this codebase (test case "ok - non-governance, permissionless true" in `test_proposals.go`) [8](#0-7) , i.e., not a privileged/governance-only assumption. Any account can deploy a trivial Solidity contract and call `MsgRegisterERC20` followed by `MsgConvertERC20`, both of which are ordinary user-signed transactions.

### Recommendation
For native-ERC20 conversions, do not rely purely on the untrusted contract's self-reported balance delta as proof of value transfer. Options:
- Require a real balance/supply consistency check that cannot be gamed by the token's own code (e.g., verify against a trusted oracle of `totalSupply` invariants over time, or restrict escrow accounting to standard, audited/verified ERC20 bytecode).
- Alternatively, disable minting privileges for `permissionless_registration`-registered pairs by default, or require an initial bonding/verification period before allowing `ConvertERC20` to mint bank coins, closing the "self-referential trust" gap identified above.

### Proof of Concept
1. Deploy a minimal malicious ERC20 contract whose `transfer(address to, uint256 amount)` simply does `balances[to] += amount; return true;` for any caller, with no real supply cap and `balanceOf` reading from the same mapping.
2. With `permissionless_registration = true`, submit `MsgRegisterERC20{Erc20Addresses: [maliciousContract]}` as a non-governance signer — succeeds per `RegisterERC20` logic [1](#0-0) .
3. Submit `MsgConvertERC20{ContractAddress: maliciousContract, Amount: 1_000_000, Sender: attacker, Receiver: attacker}`.
4. `convertERC20IntoCoinsForNativeToken` calls the malicious `transfer(ModuleAddress, 1_000_000)`, observes `balanceTokenAfter - balanceToken == 1_000_000` (trivially true because the contract just wrote that value), and mints 1,000,000 real native bank coins of `pair.Denom` to the attacker's receiver address [9](#0-8) .
5. Attacker now holds real, spendable bank coins backed by nothing, repeatable for arbitrary amounts.

// RegisterERC20 creates a Cosmos coin and registers the token pair between the
// coin and the ERC20
func (k Keeper) registerERC20(
	ctx sdk.Context,
	contract common.Address,
) (*types.TokenPair, error) {
	// Check if ERC20 is already registered
	if k.IsERC20Registered(ctx, contract) {
		return nil, errorsmod.Wrapf(
			types.ErrTokenPairAlreadyExists, "token ERC20 contract already registered: %s", contract.String(),
		)
	}

	metadata, err := k.CreateCoinMetadata(ctx, contract)
	if err != nil {
		return nil, errorsmod.Wrap(
			err, "failed to create wrapped coin denom metadata for ERC20",
		)
	}

	pair := types.NewTokenPair(contract, metadata.Name, types.OWNER_EXTERNAL)
	err = k.SetToken(ctx, pair)
	if err != nil {
		return nil, err
	}
	return &pair, nil
}
