### Title
Tokenfactory denom allow-list guardrail can be bypassed by any code path that calls `BaseSendKeeper.SendCoins` directly instead of going through `MsgServer.Send`/`MultiSend` - ([File: sei-cosmos/x/bank/keeper/msg_server.go])

### Summary
The `IsInDenomAllowList` guardrail that enforces tokenfactory denom allow-lists is implemented as an ad-hoc check inserted only inside `msgServer.Send` and `msgServer.MultiSend`, not inside the underlying `BaseSendKeeper.SendCoins`/`InputOutputCoins` primitives that actually move balances. This mirrors the CVE's root cause: a security guardrail that inspects only one specific "key"/entry point and misses functionally-equivalent alternate paths that achieve the same effect (moving the restricted coins) without passing through the checked gate.

### Finding Description
`IsInDenomAllowList` is documented to gate transfers of tokenfactory-restricted denoms: "the address is allowed to send the coins only if it is in the allow list" [1](#0-0) . It is invoked only from the two Cosmos SDK message handlers: [2](#0-1) [3](#0-2) 

However, the coin-moving primitive `SendCoins` itself contains no such check, and is exported as part of the `SendKeeper` interface used throughout the codebase (bank precompile legacy versions, authz `SendAuthorization.Accept`, other modules) [4](#0-3) .

Concretely, several legacy EVM bank precompile executors (still present in the binary as historical/legacy implementations selected by chain-upgrade height) call `p.bankKeeper.SendCoins(...)` directly rather than routing through `p.bankMsgServer.Send(...)`: [5](#0-4) [6](#0-5) 

Compare this with the current (non-legacy) precompile, which correctly routes through the msg server and therefore inherits the allow-list check: [7](#0-6) 

Because `SendCoins` is a generic exported keeper method (not gated), any caller that invokes it directly — bank precompile legacy executors, `x/authz` `SendAuthorization` grants (which the bank keeper documents can be delegated to other accounts, see the tokenfactory README on authz-shared admin capabilities [8](#0-7) ), or any future/other module importing `SendKeeper` — moves tokenfactory-restricted coins without ever consulting `GetDenomAllowList`/`IsInDenomAllowList`. This is the direct analog of the reported bug class: a guardrail that recognizes only the "canonical" access form (`MsgSend`/`MsgMultiSend`) and fails to recognize equivalent alternate access forms (direct `SendCoins` calls) that achieve the identical semantic effect.

### Impact Explanation
Tokenfactory denom allow-lists are a security control that denom admins configure specifically to restrict which addresses may hold/transfer a given asset (e.g., compliance-restricted or permissioned tokens) [9](#0-8) . Bypassing it lets a non-allow-listed address receive or send restricted tokenfactory coins via the EVM legacy bank precompile path, defeating the guardrail the denom creator relied on. Depending on how the restricted denom is used (e.g., as a compliance gate for a regulated asset), this constitutes an unauthorized transfer of restricted funds through the precompile surface, which the analog rules classify as fund-loss/permission-bypass impact.

### Likelihood Explanation
This requires only calling the EVM bank precompile's legacy `send` entry point (`precompiles/bank/legacy/v562|v580/bank.go`) while the EVM pointer for the target tokenfactory denom is set as the precompile caller (a precondition already satisfied for normal ERC20-pointer usage of any tokenfactory denom) — i.e., a normal ERC20-pointer-mediated transfer of a tokenfactory denom that has an allow list configured. No special privileges are required; any EVM transaction sender interacting with an ERC20 pointer for an allow-listed tokenfactory denom, on a chain height where the legacy precompile version is selected, can trigger it.

### Recommendation
Move the `IsInDenomAllowList` (and `BlockedAddr`) enforcement into `BaseSendKeeper.SendCoins`/`InputOutputCoins` themselves (or into a single choke point that all send paths funnel through), rather than duplicating the check only in the two SDK message-server handlers. Alternatively, audit and update every legacy precompile executor and any other direct caller of `SendCoins` to explicitly perform the allow-list check before transferring tokenfactory-prefixed denoms.

### Proof of Concept
1. Denom admin creates a tokenfactory denom `factory/<admin>/restricted` and sets a `DenomAllowList` containing only address `A` via `SetDenomAllowList` (exposed through `MsgCreateDenom`/allow-list update flow, see `x/tokenfactory/keeper/createdenom_test.go`) [10](#0-9) .
2. Register an ERC20 native pointer for `factory/<admin>/restricted` (standard pointer flow), so `GetERC20NativePointer` resolves it.
3. Have address `B` (NOT in the allow list) call the pointer contract's `transfer`/`send`, which invokes the EVM bank precompile's `send(...)` method.
4. At a chain height mapped to the legacy precompile implementation (`precompiles/bank/legacy/v562` or `v580`), the executor calls `p.bankKeeper.SendCoins(ctx, senderSeiAddr, receiverSeiAddr, ...)` directly [11](#0-10) , which never calls `IsInDenomAllowList`, so the transfer succeeds despite `B` (sender or receiver) not being on the allow list — confirming the guardrail bypass. Contrast with `msgServer.Send`, which would have rejected the same transfer with `ErrUnauthorized` [12](#0-11) .

// IsInDenomAllowList checks if the given address is allowed to send the given coins.
// The check is performed only fot token factory denoms. For each token factory denom,
// it checks if there is allow list for the given denom. If there is no allow list,
// the address is allowed to send the coins. If there is an allow list, the address is
// allowed to send the coins only if it is in the allow list.
func (k BaseSendKeeper) IsInDenomAllowList(ctx sdk.Context, addr sdk.AccAddress, coins sdk.Coins, cache map[string]AllowedAddresses) bool {
	for _, coin := range coins {
		// Skip if denom does not contain the token factory prefix
		if !strings.HasPrefix(coin.Denom, TokenFactoryPrefix) {
			continue
		}

		allowedAddresses := k.getAllowedAddresses(ctx, cache, coin.Denom)
		// skip if there is no allow list for the denom
		if len(allowedAddresses.set) == 0 {
			continue
		}

		if !allowedAddresses.contains(addr) {
			return false
		}
	}
	return true
}

func (k msgServer) Send(goCtx context.Context, msg *types.MsgSend) (*types.MsgSendResponse, error) {
	ctx := sdk.UnwrapSDKContext(goCtx)

	if err := k.IsSendEnabledCoins(ctx, msg.Amount...); err != nil {
		return nil, err
	}

	from, err := sdk.AccAddressFromBech32(msg.FromAddress)
	if err != nil {
		return nil, err
	}
	to, err := sdk.AccAddressFromBech32(msg.ToAddress)
	if err != nil {
		return nil, err
	}

	allowListCache := make(map[string]AllowedAddresses)
	if !k.IsInDenomAllowList(ctx, from, msg.Amount, allowListCache) {
		return nil, sdkerrors.Wrapf(sdkerrors.ErrUnauthorized, "%s is not allowed to send funds", msg.FromAddress)
	}

	if k.BlockedAddr(to) || !k.IsInDenomAllowList(ctx, to, msg.Amount, allowListCache) {
		return nil, sdkerrors.Wrapf(sdkerrors.ErrUnauthorized, "%s is not allowed to receive funds", msg.ToAddress)
	}

	err = k.SendCoins(ctx, from, to, msg.Amount)
	if err != nil {
		return nil, err
	}

		}
	}

	err := k.InputOutputCoins(ctx, msg.Inputs, msg.Outputs)
	if err != nil {
		return nil, err
	}

func (p PrecompileExecutor) send(ctx sdk.Context, caller common.Address, method *abi.Method, args []interface{}, value *big.Int, readOnly bool) ([]byte, error) {
	if readOnly {
		return nil, errors.New("cannot call send from staticcall")
	}
	if err := pcommon.ValidateNonPayable(value); err != nil {
		return nil, err
	}

	if err := pcommon.ValidateArgsLength(args, 4); err != nil {
		return nil, err
	}
	denom := args[2].(string)
	if denom == "" {
		return nil, errors.New("invalid denom")
	}
	pointer, _, exists := p.evmKeeper.GetERC20NativePointer(ctx, denom)
	if !exists || pointer.Cmp(caller) != 0 {
		return nil, fmt.Errorf("only pointer %s can send %s but got %s", pointer.Hex(), denom, caller.Hex())
	}
	amount := args[3].(*big.Int)
	if amount.Cmp(utils.Big0) == 0 {
		// short circuit
		return method.Outputs.Pack(true)
	}
	senderSeiAddr, err := p.accAddressFromArg(ctx, args[0])
	if err != nil {
		return nil, err
	}
	receiverSeiAddr, err := p.accAddressFromArg(ctx, args[1])
	if err != nil {
		return nil, err
	}

	if err := p.bankKeeper.SendCoins(ctx, senderSeiAddr, receiverSeiAddr, sdk.NewCoins(sdk.NewCoin(denom, sdk.NewIntFromBigInt(amount)))); err != nil {
		return nil, err
	}

	return method.Outputs.Pack(true)
}

func (p PrecompileExecutor) send(ctx sdk.Context, caller common.Address, method *abi.Method, args []interface{}, value *big.Int, readOnly bool) ([]byte, uint64, error) {
	if readOnly {
		return nil, 0, errors.New("cannot call send from staticcall")
	}
	if err := pcommon.ValidateNonPayable(value); err != nil {
		return nil, 0, err
	}

	if err := pcommon.ValidateArgsLength(args, 4); err != nil {
		return nil, 0, err
	}
	denom := args[2].(string)
	if denom == "" {
		return nil, 0, errors.New("invalid denom")
	}
	pointer, _, exists := p.evmKeeper.GetERC20NativePointer(ctx, denom)
	if !exists || pointer.Cmp(caller) != 0 {
		return nil, 0, fmt.Errorf("only pointer %s can send %s but got %s", pointer.Hex(), denom, caller.Hex())
	}
	amount := args[3].(*big.Int)
	if amount.Cmp(utils.Big0) == 0 {
		// short circuit
		bz, err := method.Outputs.Pack(true)
		return bz, pcommon.GetRemainingGas(ctx, p.evmKeeper), err
	}
	senderSeiAddr, err := p.accAddressFromArg(ctx, args[0])
	if err != nil {
		return nil, 0, err
	}
	receiverSeiAddr, err := p.accAddressFromArg(ctx, args[1])
	if err != nil {
		return nil, 0, err
	}

	msg := &banktypes.MsgSend{
		FromAddress: senderSeiAddr.String(),
		ToAddress:   receiverSeiAddr.String(),
		Amount:      sdk.NewCoins(sdk.NewCoin(denom, sdk.NewIntFromBigInt(amount))),
	}

	err = msg.ValidateBasic()
	if err != nil {
		return nil, 0, err
	}

	if _, err = p.bankMsgServer.Send(sdk.WrapSDKContext(ctx), msg); err != nil {
		return nil, 0, err
	}

	bz, err := method.Outputs.Pack(true)
	return bz, pcommon.GetRemainingGas(ctx, p.evmKeeper), err
}
