### Title
Scanner reports arbitrarily small/dust outputs as received funds, letting anyone force unspendable inputs onto the wallet - ([File: networks/bitcoin/src/wallet/mod.rs])

### Summary
Analogous to the GaugeController bug — where `distributeRewards()` commits accounting state (`periodState.distributed += amount`) without any corresponding transfer being enforced at call time — Serai's `Scanner::scan_transaction` credits every output paying to a registered script as a `ReceivedOutput` with no minimum-value or spendability check. An unprivileged party can send dust-valued (or zero-economical-value) outputs to Serai's P2TR script, causing the wallet to report funds as received that cost more to spend than they are worth, permanently burdening the input set and fee budget — a griefing/DOS analog reachable purely by sending Bitcoin transactions.

### Finding Description
`Scanner::scan_transaction` at `networks/bitcoin/src/wallet/mod.rs:199-214` matches only on `output.script_pubkey` and pushes a `ReceivedOutput` for every match, regardless of `output.value`. There is no dust floor on *received* outputs: `DUST` (546 sat) is only enforced on *payments* Serai creates in `SignableTransaction::new` (`send.rs:165-169`), never on scanned inputs.

Each `ReceivedOutput` becomes one Taproot input in `SignableTransaction::new` (`send.rs:150-256`), and each input requires an independent `AlgorithmMachine<Secp256k1, Schnorr>` signature (`send.rs:275-285`) and adds a full input + 64-byte witness to the weight in `calculate_weight_vbytes` (`send.rs:62-127`). An attacker therefore:

1. Obtains the (public) external/branch/forward scripts for the group key — `p2tr_script_buf(key)` and the offsets registered in `processor/src/networks/bitcoin.rs:314-347` are deterministic and publicly computable.
2. Broadcasts transactions paying e.g. 1–546 sat to those scripts. Nothing in `scan_transaction` or `get_outputs` (`processor/src/networks/bitcoin.rs:686-740`) rejects them.
3. Each such UTXO is reported as received. Spending it costs ~57.5+ vbytes of input+witness at the prevailing fee rate plus an entire FROST signing round share — exceeding its value — so the funds are effectively not spendable, yet they inflate `needed_fee`, can push `weight` over `MAX_STANDARD_TX_WEIGHT` (`send.rs:241`) making `SignableTransaction::new` fail entirely, and force `NotEnoughFunds`/`TooLargeTransaction` errors (`send.rs:215-243`), denying service to legitimate withdrawals until inputs are manually curated.

This mirrors the report's core flaw: state (here the set of credited UTXOs / accounting of "received" funds) is updated purely by matching attacker-controlled data, with no check that the credited amount justifies the resource commitment it triggers.

### Impact Explanation
Funds are reported received that are not economically spendable (each dust input's spend cost ≥ its value), and accumulation of attacker-created outputs can make `SignableTransaction::new` fail via `TooLargeTransaction`/`NotEnoughFunds`, a DOS on the wallet's ability to construct spend transactions. Medium severity: requires attacker to spend dust amounts, impact is griefing and forced manual UTXO handling rather than theft.

### Likelihood Explanation
Fully reachable by any unprivileged party: the only requirement is sending a Bitcoin transaction paying to a publicly derivable script. No validator status, no leaked keys, no collusion needed.

### Recommendation
Enforce a minimum value on scanned outputs: in `Scanner::scan_transaction` (or in `get_outputs` in `processor/src/networks/bitcoin.rs`), drop outputs below an economically-spendable threshold (a multiple of `DUST` calibrated to the fee rate), or mark them so `SignableTransaction::new` can exclude them from the input set. This restores the invariant the report recommends — the credited amount must carry the backing value needed to justify the committed state.

  pub fn scan_transaction(&self, tx: &Transaction) -> Vec<ReceivedOutput> {
    let mut res = Vec::new();
    for (vout, output) in tx.output.iter().enumerate() {
      // If the vout index exceeds 2**32, stop scanning outputs
      let Ok(vout) = u32::try_from(vout) else { break };

      if let Some(offset) = self.scripts.get(&output.script_pubkey) {
        res.push(ReceivedOutput {
          offset: *offset,
          output: output.clone(),
          outpoint: OutPoint::new(tx.compute_txid(), vout),
        });
      }
    }
    res
  }
