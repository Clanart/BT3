### Title
Identity public keys enable universal Schnorr signature forgery - ([File: crypto/schnorr/src/lib.rs](crypto/schnorr/src/lib.rs))

### Summary
`SchnorrSignature::verify` does not reject the identity point as a public key. Its verification equation reduces to `R - sG = 0` for an identity public key because the `challenge * public_key` term is always identity, allowing anyone to construct a universally valid signature for an arbitrary challenge.

### Finding Description
`SchnorrSignature::read` parses `R` with `C::read_G`, which checks canonical encoding but does not reject identity points. [1](#0-0) [2](#0-1)  Verification queues `R + challenge * public_key - sG` and accepts it when the sum is identity, without requiring `public_key` to be non-identity. [3](#0-2) 

For `public_key = identity`, the equation becomes `R - sG = 0`. An attacker can therefore choose `s = 1` and `R = G`, or equivalently any scalar `s` with `R = sG`, and the signature verifies regardless of the challenge.

### Impact Explanation
Any protocol accepting an identity-encoded public key and relying on `SchnorrSignature::verify` for authorization accepts signatures that require no private key. The forged signature works for every challenge and every message because the challenge is multiplied by the identity point.

This is reachable through public signature bytes and an attacker-controlled or attacker-registered identity public key. The signature decoder also accepts an identity nonce because `C::read_G` performs canonical-point validation only. [1](#0-0) [2](#0-1) 

### Likelihood Explanation
The attack requires the verifier to treat the identity point as a valid public key. The in-scope deserialization and verification APIs do not enforce that restriction themselves, so callers can reach the vulnerable condition when attacker-supplied keys are admitted without a separate non-identity check.

### Recommendation
Reject identity public keys in `SchnorrSignature::verify` and `batch_statements` users before queueing verification. Prefer also rejecting identity `R` in `SchnorrSignature::read` or adding a strict signature-validation path that checks both `R` and the public key are canonical, non-identity group elements.

### Proof of Concept
For any `C: Ciphersuite` and arbitrary challenge `c`:

```rust
// crypto/schnorr/src/lib.rs
let forged = SchnorrSignature::<C> {
    R: C::generator(),
    s: C::F::ONE,
};

assert!(forged.verify(C::G::identity(), c));
```

Verification computes:

```text
R + c * public_key - sG
= G + c * identity - G
= identity
```

The identity result is accepted by `multiexp_vartime(...).is_identity()`. [3](#0-2)

  fn read_G<R: Read>(reader: &mut R) -> io::Result<Self::G> {
    let mut encoding = <Self::G as GroupEncoding>::Repr::default();
    reader.read_exact(encoding.as_mut())?;
