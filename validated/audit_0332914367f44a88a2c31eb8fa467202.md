### Title
Payout `OP_RETURN` operator attribution is not covered by the user's `SIGHASH_SINGLE|ANYONECANPAY` signature, allowing anyone to misattribute a fronted withdrawal to an operator who never paid it - ([File: core/src/builder/transaction/operator_reimburse.rs])

### Summary
The `payout_tx` that fronts a Citrea withdrawal on Bitcoin is signed by the user with `SIGHASH_SINGLE|ANYONECANPAY`. This sighash type only commits to input 0 and the output at the same index (output 0, the user's payout). The second output (anchor) and third output (`OP_RETURN` naming the operator's x-only pubkey) are *not* covered by the signature. Since verifiers later read this uncommitted `OP_RETURN` field from the confirmed chain to decide which operator gets credited (and eventually reimbursed) for the withdrawal, anyone who observes the user's signature (e.g., in the mempool once any operator broadcasts it) can rewrite the operator attribution and cause a completely different, honest operator to be credited with a payout it never funded.

### Finding Description
`create_payout_txhandler` builds the payout tx with the user's dust input (`SpendPath::KeySpend`) and three outputs: the user payout, an anchor, and an `OP_RETURN` carrying `operator_xonly_pk`: [1](#0-0) 

The user's signature is a `taproot::Signature` verified against sighash of input 0 with `in_signature.sighash_type`, and the code explicitly documents/relies on `SinglePlusAnyoneCanPay`: [2](#0-1) 

This is corroborated elsewhere in the codebase, where the tx-sender explicitly notes that outputs after the signed one can be freely modified/reordered without breaking the `SinglePlusAnyoneCanPay` signature: [3](#0-2) 

`SIGHASH_SINGLE|ANYONECANPAY` commits only to: (a) the signed input's outpoint/script/value, and (b) the single output at the same output index as the input (index 0, the user payout). It does **not** commit to any other output, including the `OP_RETURN` output that names the fronting operator, nor to any other transaction inputs. Consequently, once the operator's `withdraw()` flow funds and broadcasts this transaction (visible unconfirmed in the mempool), any third party can:
1. Extract the (input, user signature, output0) triple from the mempool transaction.
2. Build an alternate transaction reusing that exact signed input/output-0 pair, funding the remaining value with their own UTXOs (permitted because `ANYONECANPAY` doesn't commit to other inputs), and substituting the `OP_RETURN` output with an arbitrary x-only pubkey — including that of an *unrelated, honest* operator.
3. Get this alternate transaction confirmed instead (via a higher fee), since nothing on-chain ties output index 2 to the original broadcaster.

Verifiers subsequently derive `payout_payer_operator_xonly_pk` purely from this uncommitted `OP_RETURN`: [4](#0-3) 

This value is persisted and later used to select which operator's `PayoutCheckerTask` treats the payout as "its own unhandled payout" to reimburse: [5](#0-4) [6](#0-5) 

And the operator's own reimbursement flow trusts this same field to authorize itself to build/send its kickoff and claim the `MoveToVault` deposit UTXO as reimbursement: [7](#0-6) 

Verifiers also use the same untrusted field to decide whether a kickoff is "malicious" (i.e., whether the operator sending the kickoff actually matches the payout): [8](#0-7) 

Because none of these checks re-verify who actually supplied the extra funding input(s) that pay for the withdrawal (that information is simply absent from the signed part of the tx), the equality the protocol needs — `payout_payer_operator_xonly_pk == the party whose BTC actually left their wallet to fund the payout` — can be broken by any unprivileged party who can see the mempool.

### Impact Explanation
This breaks the "operator credited versus the party that paid" binding directly. A malicious actor (needing no operator, verifier, or other privileged role) can front a withdrawal with their own minimal funds while tagging an arbitrary, otherwise-honest operator's x-only pubkey in the `OP_RETURN`. That honest operator's automation (`PayoutCheckerTask` → `handle_finalized_payout` → kickoff/reimburse flow) will then treat the payout as its own and proceed to claim reimbursement from the `MoveToVault` deposit UTXO for a withdrawal it never funded — i.e., "an operator reimbursed for a payout it never funded." Symmetrically, the operator who did originally intend to front the withdrawal (had their signed pre-image visible in the mempool) may find their attribution stolen and their transaction supplanted, potentially leaving no operator correctly credited and no path to reimbursement for the entity that would otherwise fund and claim it correctly — matching "an honest operator permanently unable to be reimbursed." Both fall under the Critical impact tier defined in scope.

### Likelihood Explanation
The prerequisite exploit primitive (`SIGHASH_SINGLE|ANYONECANPAY` leaving the `OP_RETURN` output unsigned) is a design/implementation property visible in the shipped code and is explicitly acknowledged in a code comment about output reordering safety, indicating awareness of malleability but not of this specific attribution-forgery consequence. The only requirement to trigger the attack is observing an operator's unconfirmed payout transaction in the mempool — a purely public, unprivileged capability — and constructing/broadcasting a replacement with a higher fee. No verifier, operator, or other privileged role is required by the attacker.

### Recommendation
Bind the operator attribution to the user's signature by including the `OP_RETURN` operator pubkey (and ideally all outputs and the anchor) under the same signed digest, e.g., by switching to `SIGHASH_ALL` for the user's payout-input signature, or otherwise cryptographically committing the operator's identity within the input the user actually signs (for example, having the user's off-chain authorization message itself commit to the destination operator's pubkey and verifying that binding independently on-chain/at the verifier layer, rather than trusting an unauthenticated `OP_RETURN`).

### Proof of Concept
1. Operator O constructs and broadcasts `payout_tx` for withdrawal `W` via `Operator::withdraw`, using the pre-obtained `SinglePlusAnyoneCanPay` user signature over `(in_outpoint, output0)`; see `create_payout_txhandler`/`withdraw` [9](#0-8) .
2. The unconfirmed transaction is visible in the mempool, exposing `in_outpoint`, `in_signature`, and `output0` (unchanged, user payout).
3. Attacker A builds `payout_tx'` reusing the identical signed input and output0 (so the user's signature verification still succeeds), funds the remaining value with A's own UTXO(s) (allowed under `ANYONECANPAY`), and sets the `OP_RETURN` output to name victim operator V's x-only pubkey instead of O's.
4. A broadcasts `payout_tx'` with a higher fee so it confirms instead of O's original tx.
5. Verifiers process the confirmed block via `update_finalized_payouts`, parse the `OP_RETURN`, and store `payout_payer_operator_xonly_pk = V` [4](#0-3) .
6. Operator V's `PayoutCheckerTask::run_once` picks this up via `get_first_unhandled_payout_by_operator_xonly_pk` and proceeds through `handle_finalized_payout` to build a kickoff and eventually claim the `MoveToVault` deposit output as reimbursement [6](#0-5) [10](#0-9) , despite never having funded the withdrawal to the user.

pub fn create_reimburse_txhandler(
    move_txhandler: &TxHandler,
    round_txhandler: &TxHandler,
    kickoff_txhandler: &TxHandler,
    kickoff_idx: usize,
    paramset: &'static ProtocolParamset,
    operator_reimbursement_address: &bitcoin::Address,
) -> Result<TxHandler, BridgeError> {
    let builder = TxHandlerBuilder::new(TransactionType::Reimburse)
        .with_version(NON_STANDARD_V3)
        .add_input(
            NormalSignatureKind::Reimburse1,
            move_txhandler.get_spendable_output(UtxoVout::DepositInMove)?,
            builder::script::SpendPath::ScriptSpend(0),
            DEFAULT_SEQUENCE,
        )
        .add_input(
            NormalSignatureKind::Reimburse2,
            kickoff_txhandler.get_spendable_output(UtxoVout::ReimburseInKickoff)?,
            builder::script::SpendPath::ScriptSpend(0),
            DEFAULT_SEQUENCE,
        )
        .add_input(
            NormalSignatureKind::OperatorSighashDefault,
            round_txhandler.get_spendable_output(UtxoVout::ReimburseInRound(
                kickoff_idx,
                paramset.num_kickoffs_per_round,
            ))?,
            builder::script::SpendPath::KeySpend,
            DEFAULT_SEQUENCE,
        );

    Ok(builder
        .add_output(UnspentTxOut::from_partial(TxOut {
            value: move_txhandler
                .get_spendable_output(UtxoVout::DepositInMove)?
                .get_prevout()
                .value,
            script_pubkey: operator_reimbursement_address.script_pubkey(),
        }))
        .add_output(UnspentTxOut::from_partial(
            builder::transaction::anchor_output(paramset.anchor_amount()),
        ))
        .finalize())

pub fn create_payout_txhandler(
    input_utxo: UTXO,
    output_txout: TxOut,
    operator_xonly_pk: XOnlyPublicKey,
    user_sig: taproot::Signature,
    _network: bitcoin::Network,
) -> Result<TxHandler<Signed>, BridgeError> {
    let txin = SpendableTxIn::new_partial(input_utxo.outpoint, input_utxo.txout);

    let output_txout = UnspentTxOut::from_partial(output_txout.clone());

    let op_return_txout = op_return_txout(PushBytesBuf::from(operator_xonly_pk.serialize()));

    let mut txhandler = TxHandlerBuilder::new(TransactionType::Payout)
        .with_version(NON_STANDARD_V3)
        .add_input(
            NormalSignatureKind::NotStored,
            txin,
            SpendPath::KeySpend,
            DEFAULT_SEQUENCE,
        )
        .add_output(output_txout)
        .add_output(UnspentTxOut::from_partial(anchor_output(
            NON_EPHEMERAL_ANCHOR_AMOUNT,
        )))
        .add_output(UnspentTxOut::from_partial(op_return_txout))
        .finalize();
    txhandler.set_p2tr_key_spend_witness(&user_sig, 0)?;
    txhandler.promote()
}

    pub async fn get_first_unhandled_payout_by_operator_xonly_pk(
        &self,
        tx: Option<DatabaseTransaction<'_>>,
        operator_xonly_pk: XOnlyPublicKey,
    ) -> Result<Option<(u32, Txid, BlockHash)>, BridgeError> {
        let query = sqlx::query_as::<_, (i32, Option<TxidDB>, Option<BlockHashDB>)>(
            "SELECT w.idx, w.move_to_vault_txid, w.payout_tx_blockhash
             FROM withdrawals w
             WHERE w.payout_txid IS NOT NULL
                AND w.is_payout_handled = FALSE
                AND w.payout_payer_operator_xonly_pk = $1
                ORDER BY w.idx ASC
             LIMIT 1",
        )
        .bind(XOnlyPublicKeyDB(operator_xonly_pk));

        let results = execute_query_with_tx!(self.connection, tx, query, fetch_optional)?;

        results
            .map(|(citrea_idx, move_to_vault_txid, payout_tx_blockhash)| {
                Ok((
                    u32::try_from(citrea_idx).wrap_err("Failed to convert citrea index to u32")?,
                    move_to_vault_txid
                        .expect("move_to_vault_txid Must be Some")
                        .0,
                    payout_tx_blockhash
                        .expect("payout_tx_blockhash Must be Some")
                        .0,
                ))
            })
            .transpose()
    }
