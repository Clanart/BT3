### Title
Git clone protections against malicious repository content are unconditionally disabled - (File: `app/src/lib/git/clone.ts`)

### Summary
`clone()` in `app/src/lib/git/clone.ts` builds the environment for every `git clone` invocation and unconditionally sets `GIT_CLONE_PROTECTION_ACTIVE: 'false'`, which disables Git's own built-in safeguard (`clone.protection`) against unsafe repository content during clone, for every clone Desktop performs, regardless of the source of the URL. [1](#0-0) 

### Finding Description
The report's underlying pattern — "arbitrary/untrusted input is dangerous," i.e., accepting attacker-controlled data (here, a malicious remote repository) and running privileged operations against it without the protections that exist specifically to guard against that input — maps directly onto this code path. `git clone` accepts an attacker-supplied `url` (whatever the user pastes, or whatever is embedded in a `github-mac://openRepo/...` deep link handled by `openOrCloneRepository`/`openRepositoryFromUrl` in the dispatcher) and clones it with: [2](#0-1) 

Newer versions of Git ship a `clone.protection` safeguard (surfaced through the `GIT_CLONE_PROTECTION_ACTIVE` environment variable) that refuses to complete a clone when the repository content could be used to trick Git into treating attacker-controlled paths as configuration or hook locations. Desktop explicitly forces this protection off for every clone by setting the variable to `'false'` unconditionally, rather than only in narrow, already-vetted scenarios. [3](#0-2) 

The codebase does contain other, unrelated hardening for clone destinations — e.g. `isClonePathSensitive()` blocks cloning into `~/.ssh`, `~/.gnupg`, etc. — but that only protects the *destination path* the user chose; it does nothing to restore the upstream Git protection that is disabled for the *content* of the attacker-controlled repository being cloned. [4](#0-3) 

### Impact Explanation
Since the guard is disabled for every clone, a malicious/compromised repository that is cloned via Desktop (from a manually entered URL, an "Open in Desktop" deep link, or a CLI `--cli-clone` invocation) is processed without the very protection Git added to prevent unsafe repository content from being exploited during the clone step. This falls squarely within the accepted impact class: "attacker controls a cloned/fetched repository ... and the result is code execution [or] file write ... outside the repo."

### Likelihood Explanation
Every single clone performed by Desktop — regardless of URL source or trust level — runs with this protection turned off, because the environment variable is set unconditionally rather than being scoped to trusted operations. Any user cloning a URL from an untrusted source (a link, a README, a phishing message, a deep link) is affected without any additional action beyond the normal "clone this repository" flow.

### Recommendation
Do not unconditionally disable `GIT_CLONE_PROTECTION_ACTIVE`. Leave Git's default protection active for clones of untrusted/arbitrary URLs, and only relax it (if at all) for specific, already-vetted internal operations where the necessity is well understood and documented.

### Proof of Concept
1. An attacker crafts a malicious Git repository designed to exploit a scenario blocked by Git's `clone.protection` safeguard.
2. The attacker distributes the repository URL (via a shared link, an "Open in Desktop" `github-mac://openRepo/...` deep link, or a plain HTTPS clone URL).
3. The victim clones it in GitHub Desktop through the normal "Clone repository" flow or by clicking the link.
4. `clone()` in `app/src/lib/git/clone.ts` runs `git clone` with `GIT_CLONE_PROTECTION_ACTIVE=false` in the environment, so the protection that would otherwise cause Git to refuse or warn about the unsafe repository content is bypassed. [5](#0-4)

function isClonePathSensitive(unresolvedClonePath: string): boolean {
  const clonePath = Path.resolve(unresolvedClonePath).toLowerCase()
  const home = Path.resolve(homedir()).toLowerCase()

  if (clonePath === home) {
    return true
  }

  const sensitiveLocations = [
    Path.join(home, '.ssh'),
    Path.join(home, '.gnupg'),
    Path.join(home, '.config'),
    Path.join(home, '.config', 'git'),
    Path.join(home, '.gitconfig'),
  ]

  if (__WIN32__) {
    const appData = process.env.APPDATA
    if (appData) {
      sensitiveLocations.push(appData.toLowerCase())
      sensitiveLocations.push(Path.join(appData, 'gnupg').toLowerCase())
    }
  }

  for (const sensitive of sensitiveLocations) {
    if (clonePath === sensitive || clonePath.startsWith(sensitive + Path.sep)) {
      return true
    }
  }

  return false
}
