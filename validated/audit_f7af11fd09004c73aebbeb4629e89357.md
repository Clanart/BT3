### Title
Identity `key` in `EncryptedMessage` bypasses the proof-of-possession, letting any party forge a valid blame proof that fatally slashes an honest DKG participant - (File: crypto/dkg/pedpop/src/encryption.rs)

### Summary
CVE-2022-43404 is a validation-bypass bug class: a crafted object reaches code paths whose safety checks were designed for "real" constructors, so a degenerate input slips past the sandbox. In Serai's PedPoP encryption layer, the per-message key `EncryptedMessage::key` is read with `Ciphersuite::read_G`, which enforces canonicality but does **not** reject the identity point (unlike `Curve::read_G` in `crypto/frost/src/curve/mod.rs`, which does). The identity key makes the Schnorr proof-of-possession trivially satisfiable and makes the ECDH shared key the publicly-known identity point, completely defeating the anti-framing mechanism the PoP exists to provide.

### Finding Description
`EncryptedMessage::read` accepts arbitrary untrusted bytes, including `key`, with no identity check: [1](#0-0) 

`Ciphersuite::read_G` only checks canonicality, not identity: [2](#0-1) 

The PoP is meant to stop exactly this framing attack (only someone knowing the discrete log of the per-message key may claim it): [3](#0-2) 

Verification is `s·G == R + c·key`. With `key = identity`, the term `c·key` vanishes, so any `s` with `R = s·G` satisfies it — no discrete log needed: [4](#0-3) 

Decryption derives the cipher from `ecdh = msg.key · enc_priv`; with `msg.key = identity` the shared secret is `identity`, whose transcript-derived ChaCha20 key is computable by anyone: [5](#0-4) [6](#0-5) 

In `KeyMachine::calculate_share`, a crafted `EncryptedMessage { key: identity, pop: (R = sG, s), msg: garbage }` attributed to an honest `from` passes the PoP batch check, decrypts to an invalid share, and produces a valid `EncryptionKeyProof` (the DLEq `identity = x·identity` holds for the accuser's real `enc_key`), so `PedPoPError::InvalidShare { participant: honest_l, blame: Some(...) }` is emitted and third-party `blame` verification confirms the honest sender as faulty: [7](#0-6) 

### Impact Explanation
Any participant (or anyone able to route a message into `calculate_share`/`VerifyBlame`) can frame an honest DKG participant as having sent an invalid secret share. The resulting `EncryptionKeyProof` is genuinely valid, so the blame check in `Decryption::decrypt_with_proof` passes and the honest party is condemned — in Serai's deployment this is a fatal slash. This is precisely the attack the code comments say the PoP prevents ("Eve could observe Alice encrypt to Bob with key X, then send Bob a message also claiming to use X"), with identity replacing the co-opted key to remove even the requirement of observing a prior ciphertext. Medium severity: requires participation in a DKG round and yields wrongful slashing rather than key recovery.

### Likelihood Explanation
Fully deterministic and reachable by an unprivileged party: the crafted `EncryptedMessage` is built entirely from public operations (`s·G`, `identity`, arbitrary ciphertext bytes). No collusion, no hash grinding, no race.

### Recommendation
Reject the identity point when reading `key` in `EncryptedMessage::read` (and `enc_key` in `EncryptionKeyMessage::read` for defense-in-depth), e.g. by adding an identity check to the PedPoP read paths equivalent to `Curve::read_G`, or by rejecting identity inside `encrypt`/`decrypt`/`decrypt_with_proof` before computing the ECDH.

  fn read_G<R: Read>(reader: &mut R) -> io::Result<Self::G> {
    let mut encoding = <Self::G as GroupEncoding>::Repr::default();
    reader.read_exact(encoding.as_mut())?;

    let point = Option::<Self::G>::from(Self::G::from_bytes(&encoding))
      .ok_or_else(|| io::Error::other("invalid point"))?;
    if point.to_bytes().as_ref() != encoding.as_ref() {
      Err(io::Error::other("non-canonical point"))?;
    }
    Ok(point)
