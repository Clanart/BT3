## Title
Reverted transaction bundles leave orphaned live-pruning marks that later delete live trie nodes, causing state divergence - ([File: storage/statedb/trie.go])

### Summary
When Kaia's live-pruning is enabled, every trie mutation (`insert`/`delete`) calls `Trie.markPrunableNode`, which caches the *old* node hash into an in-memory map `t.pruningMarksCache` on the `Trie` object itself [1](#0-0) . This cache is flushed into the database as permanent `PruningMark` records inside `Trie.CommitExt` via `commitPruningMarks` [2](#0-1) , and those marks are later consumed by `pruneTrieNodeLoop`/`PruneTrieNodes`, which unconditionally deletes the corresponding trie nodes from disk [3](#0-2) [4](#0-3) .

The block-building bundle path (`Task.commitBundleTransaction`) executes a bundle's transactions directly against the live block-building `StateDB`/trie, and on any failure it "restores" the pre-bundle state by copying a saved `StateDB` snapshot back over the live one (`env.state.Set(lastSnapshot)`) [5](#0-4) . This is the same rollback pattern the referenced CVE (ALPINE-CVE-2022-42310, Xenstore orphaned nodes on failed transactions) exploits: on error, cleanup does not fully undo everything the failed operation created — here, the trie-level pruning marks recorded by `markPrunableNode` are not part of the journal-based `Snapshot`/`RevertToSnapshot` mechanism and are not rolled back by `env.state.Set(...)`. The existing test `makeTestTxBundleLivePruningScenario` explicitly documents and asserts this exact defect: *"State db will be broken because nodes marked as pruning during executing the bundle will be left in state db even though the bundle will be reverted"* [6](#0-5) .

### Finding Description
Live pruning marks are staged per-trie-mutation in `t.pruningMarksCache`, keyed only by node hash, and are unconditionally merged into the persistent pruning-mark set the next time *any* `Trie.CommitExt` runs — not necessarily the same transaction/trie instance that generated them, since the underlying `*Database` (`t.db`) is shared across all state tries derived from the same `StateCache` [7](#0-6) .

When a bundle transaction inside `commitBundleTransaction` mutates account/storage tries (deleting/replacing nodes and calling `markPrunableNode` for the old nodes it replaces) and then fails (nonce error, insufficient balance, VM revert, time-limit, etc.), the code only restores the `StateDB`'s object-level state via `env.state.Set(lastSnapshot)`; it never discards the pruning marks that the failed transaction's trie edits already cached in `t.pruningMarksCache` [8](#0-7) . Because `pruningMarksCache` lives on the `Trie`/`Database` object rather than on the per-transaction journal (`blockchain/state/journal.go`), it survives the "rollback" of `env.state`.

Those marks reference nodes that are actually still live in the trie (since the mutation that "orphaned" them was reverted and the old value is still current), but on the next successful `Commit`/`writeStateTrie` → `commitPruningMarks` → `pruneTrieNodeLoop` cycle, `PruneTrieNodes` will physically delete those still-referenced trie nodes from the persistent state-trie DB [9](#0-8) [4](#0-3) . This is the direct inverse-but-analogous failure mode to CVE-2022-42310: an aborted/failed transaction leaves behind bookkeeping ("orphaned" pruning marks / cleanup entries) that becomes permanent once a later, unrelated transaction commits — corrupting the persisted state trie.

### Impact Explanation
Once such nodes are deleted from the persistent trie database, any node that later needs to resolve that hash (to serve an `eth_getProof`, sync a light client, replay/re-execute historical state, or simply restart and re-open the trie at that root) will hit a `MissingNodeError` [10](#0-9) , or — in the archive/full-sync context where multiple nodes independently mark-and-prune based on their own local bundle execution history — different validators can end up with divergent sets of retained trie nodes for the same logical state, since bundle failure/timeout behavior (`params.BlockGenerationTimeLimit`, gas exhaustion, VM revert order) is not guaranteed to be byte-for-byte identical across nodes. This directly matches the "state divergence between honest nodes" and "acceptance of invalid transaction/state" impact classes: nodes with live pruning enabled can silently lose parts of their canonical state trie that are still required, breaking proof serving, historical re-execution, and potentially causing consensus-irrelevant-but-service-critical corruption of RPC-facing state data.

### Likelihood Explanation
Live pruning is an operator-configurable feature (`WritePruningEnabled`, `LivePruningRetention`) enabled on full/CN nodes that are not archive nodes [9](#0-8) . The trigger requires only that transaction bundling be in use (a standard kaiax `TxBundlingModule` block-building path) and that at least one bundled transaction inside a block-building attempt fails after having performed trie mutations (e.g., nonce-too-high, insufficient balance, VM revert, or the block-generation time limit being hit mid-bundle) — all of which are exactly the scenarios already exercised by `testTxBundleRevertScenario` and `testTxBundleTimeOutScenario` in the existing test suite [11](#0-10) [12](#0-11) . An unprivileged bundle submitter (auction bidder / MEV-style bundle sender) can deliberately craft a bundle whose later transaction is designed to fail after earlier trie-mutating transactions have executed, directly reaching this code path from a submitted bundle — no privileged or node-internal access is required. The bug is also already known/reproduced internally, as shown by the dedicated `makeTestTxBundleLivePruningScenario(true)` test asserting an error is currently expected [6](#0-5) , confirming the defect is real and reachable, not merely theoretical.

### Recommendation
Tie the lifetime of `pruningMarksCache` entries to the same rollback boundary as the rest of the transaction/bundle state:
- Snapshot and restore `t.pruningMarksCache` (or clear it) whenever a bundle/transaction's trie-level changes are discarded in `commitBundleTransaction`'s `restoreEnv`, or
- Defer emitting pruning marks until `StateDB.Commit` succeeds for the specific block, and discard any marks accumulated by trie operations that belong to a reverted bundle before the next `CommitExt` call, or
- Make pruning-mark caching journal-aware, i.e., record marks in the same journal used by `Snapshot`/`RevertToSnapshot` (`blockchain/state/journal.go`) so they get undone by `RevertToSnapshot`/`env.state.Set` automatically.

### Proof of Concept
The existing repository test already demonstrates the corrupted-state outcome end-to-end:
1. Enable live pruning: `bcdata.db.WritePruningEnabled()`.
2. Build a bundle where `tx0` mutates storage/account tries and `tx1` is designed to fail with `nonceTooHigh` so the whole bundle is reverted via `commitBundleTransaction`'s `restoreEnv`.
3. Observe (as the test itself asserts) that `bcdata.GenABlockWithTransactionsWithBundle(...)` returns an error / broken state — see `makeTestTxBundleLivePruningScenario(true)` comment: *"State db will be broken because nodes marked as pruning during executing the bundle will be left in state db even though the bundle will be reverted."* [6](#0-5)

// Mark the node for later pruning by writing PruningMark to database.
func (t *Trie) markPrunableNode(n node) {
	// Mark nodes only if both conditions are met:
	// - t.pruning: database has pruning enabled, i.e. nodes are stored with ExtHash
	// - t.PruningBlockNumber: requested pruning through state.New -> OpenTrie -> NewTrie.
	if !t.pruning || t.PruningBlockNumber == 0 {
		return
	}

	if hn, ok := n.(hashNode); ok {
		// If a node exists as a hashNode, it means the node is either:
		// (1) lives in database but yet to be resolved - subject to pruning,
		// (2) collapsed by Hash or Commit - may or may not be in database, add the mark anyway.
		t.pruningMarksCache[common.BytesToExtHash(hn)] = t.PruningBlockNumber
	} else if hn, _ := n.cache(); hn != nil {
		// If node.flags.hash is nonempty, it means the node is either:
		// (1) loaded from database - subject to pruning,
		// (2) went through hasher by Hash or Commit - may or may not be in database, add the mark anyway.
		t.pruningMarksCache[common.BytesToExtHash(hn)] = t.PruningBlockNumber
	}
}

// commitPruningMarks writes all the pruning marks
func (t *Trie) commitPruningMarks() {
	if len(t.pruningMarksCache) > 0 {
		t.db.lock.Lock()
		for hash, blockNum := range t.pruningMarksCache {
			t.db.insertPruningMark(hash, blockNum)
		}
		t.db.lock.Unlock()

		t.pruningMarksCache = make(map[common.ExtHash]uint64)
	}
}

func (bc *BlockChain) pruneTrieNodeLoop() {
	// ReadPruningMarks(1, limit) is very slow because it iterates over the most of MiscDB.
	// ReadPruningMarks(start, limit) is much faster because it only iterates a small range.
	startNum := uint64(1)

	bc.wg.Go(func() {
		for {
			select {
			case num := <-bc.chPrune:
				if num <= bc.cacheConfig.LivePruningRetention {
					continue
				}
				limit := num - bc.cacheConfig.LivePruningRetention // Prune [1, latest - retention]

				startTime := time.Now()
				marks := bc.db.ReadPruningMarks(startNum, limit+1)
				bc.db.PruneTrieNodes(marks)
				bc.db.DeletePruningMarks(marks)
				bc.db.WriteLastPrunedBlockNumber(limit)

				logger.Info("Pruned trie nodes", "number", num, "start", startNum, "limit", limit,
					"count", len(marks), "elapsed", time.Since(startTime))

				startNum = limit + 1
			case <-bc.quit:
				return
			}
		}
	})
}

// PruneTrieNodes deletes the trie nodes according to the provided set of pruning marks.
func (dbm *databaseManager) PruneTrieNodes(marks []PruningMark) {
	batch := dbm.NewBatch(StateTrieDB)
	defer batch.Release()
	for _, mark := range marks {
		if err := batch.Delete(TrieNodeKey(mark.Hash)); err != nil {
			logger.Crit("Failed to prune trie node", "err", err)
		}
		if _, err := WriteBatchesOverThreshold(batch); err != nil {
			logger.Crit("Failed to prune trie node", "err", err)
		}
	}
	if err := batch.Write(); err != nil {
		logger.Crit("Failed to batch prune trie node", "err", err)
	}
}

func (env *Task) commitBundleTransaction(bundle *builder.Bundle, bc BlockChain, nodeAddr common.Address, vmConfig *vm.Config) (error, *types.Transaction, []*types.Log) {
	lastSnapshot := env.state.Copy()
	gasUsedSnapshot := env.header.GasUsed
	blobGasUsedSnapshot := env.header.BlobGasUsed
	blobsSnapshot := env.blobs
	tcountSnapshot := env.tcount
	txs := []*types.Transaction{}
	receipts := []*types.Receipt{}
	logs := []*types.Log{}

	markAllTxUnexecutable := func() {
		for _, txOrGen := range bundle.BundleTxs {
			if txOrGen.IsConcreteTx() {
				tx, _ := txOrGen.GetTx(0)
				tx.MarkUnexecutable(true)
			}
		}
	}

	restoreEnv := func() {
		env.state.Set(lastSnapshot)
		env.header.GasUsed = gasUsedSnapshot
		env.tcount = tcountSnapshot
		// blob related env are restored to the snapshot
		env.header.BlobGasUsed = blobGasUsedSnapshot
		env.blobs = blobsSnapshot
	}

	var totalTxSize uint64 = 0
	for _, txOrGen := range bundle.BundleTxs {
		tx, err := txOrGen.GetTx(env.state.GetNonce(nodeAddr))
		if err != nil {
			logger.Error("TxGenerator error", "error", err)
			markAllTxUnexecutable()
			restoreEnv()
			return kerrors.ErrTxGeneration, nil, nil
		}

		env.state.SetTxContext(tx.Hash(), common.Hash{}, env.tcount)
		receipt, _, err := bc.ApplyTransaction(env.config, &nodeAddr, env.state, env.header, tx, &env.header.GasUsed, vmConfig)
		// Bundled tx will be rejected with any receipt.Status other than success.
		// There may be cases where a revert occurs within the EVM, which could result in an attack on a tx sender in an already executed bundle.
		if err != nil || receipt.Status != types.ReceiptStatusSuccessful {
			if err != vm.ErrInsufficientBalance && err != vm.ErrTotalTimeLimitReached {
				markAllTxUnexecutable()
			}
			receiptStatus := ""
			if receipt != nil {
				receiptStatus = strconv.FormatUint(uint64(receipt.Status), 10)
			}
			logger.Warn("ApplyTransaction error, restoring env",
				"blockNum", env.header.Number.String(), "txHash", tx.Hash().String(),
				"error", err, "receiptStatus", receiptStatus,
			)
			restoreEnv()
			if err == nil {
				err = kerrors.ErrRevertedBundleByVmErr
			}
			return err, tx, nil
		}
