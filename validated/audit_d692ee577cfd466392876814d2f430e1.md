### Title
Scanner reports immature coinbase outputs as spendable ReceivedOutputs, enabling signature over an invalid transaction - ([File: networks/bitcoin/src/wallet/mod.rs])

### Summary
In the OpenQ report, `claimTiered` snapshots `fundingTotals` at claim time, letting a claimant inflate the recorded prize pool with a deposit that is reclaimable immediately afterward — funds are counted as real at the snapshot even though they are not durably spendable. The analog in `bitcoin-serai` is `Scanner::scan_block`, which indiscriminately scans `block.txdata` including `block.txdata[0]` (the coinbase). Coinbase outputs are unspendable for 100 blocks, yet `scan_block` wraps them in `ReceivedOutput` with no maturity/height metadata, and `SignableTransaction::new` / `SignableTransaction::multisig` will treat them as ordinary spendable inputs and drive the FROST `TransactionMachine` to sign a transaction the network will reject.

### Finding Description
`Scanner::scan_block` iterates all transactions, including the coinbase, and `scan_transaction` produces a `ReceivedOutput` purely from `script_pubkey` matching — no check on whether the output is a coinbase output or how many confirmations it has. [1](#0-0) [2](#0-1) 

`ReceivedOutput` carries only `offset`, `output`, and `outpoint` — there is no field recording that the output came from a coinbase, so maturity cannot be enforced downstream. [3](#0-2) 

`SignableTransaction::new` sums `input.output.value` as available funds with no maturity distinction, and `multisig` only verifies the prevout's `script_pubkey` matches the offset key — it never checks spendability. [4](#0-3) [5](#0-4) 

`TransactionSignMachine::sign` then produces signature shares committing to all inputs via `Prevouts::All`, burning FROST preprocesses/nonces on a transaction that cannot be broadcast until maturity. [6](#0-5) 

### Impact Explanation
Funds are reported received that are not spendable — the accepted impact criterion. Concretely: an accounting layer built on `scan_block` credits an immature coinbase output; a `SignableTransaction` including it either (a) produces a signed transaction that is invalid on the network until 100 confirmations (a consensus rule, not policy — `BIP-34`/`COINBASE_MATURITY`), wasting the one-shot FROST signing session, or (b) miscounts available balance toward `input_sat`, letting immature funds satisfy `NotEnoughFunds` checks. The fee/commitment binding (`Prevouts::All`) means the signed artifact is fully determined yet unbroadcastable.

### Likelihood Explanation
Reachable by an unprivileged party: any miner (an untrusted consensus participant, not a Serai validator) can craft a coinbase paying to the threshold key's tweaked P2TR script — a plain on-chain "transaction they send" per the reachability rules. No key material, collusion, or malicious node is needed; the scanner accepts any block fed to it. The library acknowledges the hazard only in a doc comment ("a post-processing pass is needed"), but `ReceivedOutput` exposes no API to distinguish coinbase outputs, so there is no way for a caller scanning a block to perform that pass without re-deriving coinbase status themselves — the information is discarded at scan time.

### Recommendation
Mark coinbase origin on `ReceivedOutput` (e.g., an `is_coinbase` flag set when `tx.is_coinbase()` in `scan_transaction`/`scan_block`), or exclude `block.txdata[0]` inside `scan_block` rather than relying on callers, and reject coinbase-sourced inputs in `SignableTransaction::new` unless an explicit confirmation-depth check is provided.

### Proof of Concept
1. Miner M mines a block whose coinbase (`block.txdata[0]`) has an output paying `p2tr_script_buf(tweaked_group_key)` for 5 BTC.
2. Serai scanner calls `Scanner::scan_block(&block)`; it returns a `ReceivedOutput` for `(coinbase_txid, vout)` indistinguishable from a normal output.
3. The wallet calls `SignableTransaction::new(vec![received], payments, change, None, fee)`; `input_sat = 5 BTC` passes `NotEnoughFunds`.
4. `multisig(&keys)` succeeds since the script_pubkey check passes; `TransactionMachine::preprocess`/`sign`/`complete` produce a fully-signed transaction spending the coinbase.
5. Broadcasting fails consensus validation (`bad-txns-premature-spend-of-coinbase`); the FROST preprocess session is consumed and the reported 5 BTC cannot actually fund the payment.

```rust
  pub fn scan_transaction(&self, tx: &Transaction) -> Vec<ReceivedOutput> {
    let mut res = Vec::new();
    for (vout, output) in tx.output.iter().enumerate() {
      // If the vout index exceeds 2**32, stop scanning outputs
      let Ok(vout) = u32::try_from(vout) else { break };

      if let Some(offset) = self.scripts.get(&output.script_pubkey) {
        res.push(ReceivedOutput {
          offset: *offset,
          output: output.clone(),
          outpoint: OutPoint::new(tx.compute_txid(), vout),
        });
      }
    }
    res
  }
```

```rust
  pub fn multisig(self, keys: &ThresholdKeys<Secp256k1>) -> Option<TransactionMachine> {
    let mut sigs = vec![];
    for i in 0 .. self.tx.input.len() {
      let offset = keys.clone().offset(self.offsets[i]);
      if p2tr_script_buf(offset.group_key())? != self.prevouts[i].script_pubkey {
        None?;
      }

      sigs.push(AlgorithmMachine::new(Schnorr::new(), keys.clone().offset(self.offsets[i])));
    }

    Some(TransactionMachine { tx: self, sigs })
  }
```
