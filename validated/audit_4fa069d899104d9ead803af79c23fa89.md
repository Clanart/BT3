### Title
Unauthenticated OP_RETURN payer attribution lets any withdrawer credit an arbitrary victim operator for a payout it never funded - (File: `core/src/verifier.rs`)

### Summary
`update_finalized_payouts` derives `payout_payer_operator_xonly_pk` solely by parsing the OP_RETURN output of whatever transaction is found on-chain spending the registered `withdrawal_utxo`, with no check that the spender/funder of that transaction is the named operator. Since the payout input's `SinglePlusAnyoneCanPay` signature never commits to the OP_RETURN output, the withdrawer (who controls the committed input UTXO's key) can self-broadcast a payout-shaped transaction naming any operator's `xonly_pk`, causing that operator's own `PayoutCheckerTask` automation to believe it fronted the withdrawal and to proceed to kickoff/reimbursement, pulling real BTC out of the bridge's collateral for a payout it never made.

### Finding Description
The broken binding is:
`withdrawals.payout_payer_operator_xonly_pk == xonly-pubkey of the party whose BTC actually funded the payout output`

Trace:
1. The payout transaction's only cryptographic input constraint is the user's `SinglePlusAnyoneCanPay` Schnorr signature over `input_outpoint` (the withdrawal UTXO the withdrawer nominates via Citrea `withdraw`), verified in `Operator::withdraw` at `core/src/operator.rs:630-637` and enforced/normalized in `parse_withdrawal_sig_params` (`core/src/rpc/parser/operator.rs:161-203`). `SinglePlusAnyoneCanPay` only commits the spent input and the output at the *same index* (output 0, the user's payout output); it does **not** commit outputs 1 (anchor) or 2 (OP_RETURN) [1](#0-0) .
2. `create_payout_txhandler` places the operator's xonly pubkey in a plain OP_RETURN with no cryptographic binding to the signer or to a registered operator set [2](#0-1) .
3. Because the withdrawer already possesses a valid signature over their own committed input and output (it's their own key, and `SinglePlusAnyoneCanPay` permits adding/altering other inputs and outputs), they can build and broadcast their own transaction — funding the payout output entirely from their own wallet — with an arbitrary OP_RETURN naming a victim operator, entirely bypassing the operator's gRPC `withdraw`/`internal_withdraw` endpoints (`core/src/rpc/operator.rs:168-258`) and its profitability/verification checks.
4. `update_finalized_payouts` scans confirmed blocks for any transaction spending the registered `withdrawal_utxo` (via `get_payout_txs_for_withdrawal_utxos`), parses the first OP_RETURN blindly, and writes it as `payout_payer_operator_xonly_pk` with no check that this operator actually contributed funds [3](#0-2) .
5. `PayoutCheckerTask::run_once` on the *victim* operator's own node polls `get_first_unhandled_payout_by_operator_xonly_pk` keyed on its own `signer.xonly_public_key` [4](#0-3) , finds the spoofed payout, and unconditionally calls `Operator::handle_finalized_payout`, which allocates a kickoff connector and begins the kickoff→reimburse flow (`core/src/operator.rs:839-885`), eventually broadcasting `Reimburse` transactions that pay the (uninvolved) operator from the round/collateral graph.
6. The only later consistency check, `Verifier::is_kickoff_malicious`, merely re-checks that the OP_RETURN pubkey equals the kickoff's own `operator_xonly_pk` [5](#0-4)  — it trivially passes here because the victim operator is honestly using its own key, which is exactly the (spoofed) key the attacker wrote into the OP_RETURN. Nothing in this path validates that the named operator's own funds paid for the withdrawal output.

### Impact Explanation
This lets an unprivileged withdrawer, at the cost of paying the withdrawal amount to themselves (i.e. essentially free, since the funds return to their own designated output), trigger a real bridge reimbursement payout to an uninvolved operator, draining collateral/round funds via the `Reimburse` transaction for a payout the credited operator never funded. This matches the listed Critical category "an operator reimbursed for a payout it never funded." It is repeatable per withdrawal/deposit (every Citrea `withdraw` call creates a new attackable `withdrawal_id`/UTXO), and the victim operator can be any operator of the attacker's choosing, so blast radius spans the full operator set.

### Likelihood Explanation
Preconditions are minimal and match the stated unprivileged attacker capabilities exactly: the attacker only needs to (1) deposit and call Citrea `withdraw` to register a `withdrawal_id`/UTXO under their own key, (2) sign a `SinglePlusAnyoneCanPay` Schnorr signature over their own committed input/output (which they can do since they hold the key), and (3) construct/broadcast a standard Bitcoin transaction with a custom OP_RETURN, paying normal fees. No interaction with operators, verifiers, or the aggregator gRPC surface is required, and no privileged key material is needed.

### Recommendation
Do not attribute payer identity purely from an unauthenticated OP_RETURN. Require the operator to co-sign or otherwise cryptographically commit to being the funder (e.g., have the operator's key participate in the payout transaction's witness/signature, or require the additional funding inputs to be provably contributed by the claimed operator, such as via a script path enforcing operator's pubkey on a change/funding input) before crediting `payout_payer_operator_xonly_pk`; alternatively, restrict which operator identities are eligible for attribution to the operator that actually broadcast via the authenticated `withdraw`/`internal_withdraw` RPC flow.

pub fn create_payout_txhandler(
    input_utxo: UTXO,
    output_txout: TxOut,
    operator_xonly_pk: XOnlyPublicKey,
    user_sig: taproot::Signature,
    _network: bitcoin::Network,
) -> Result<TxHandler<Signed>, BridgeError> {
    let txin = SpendableTxIn::new_partial(input_utxo.outpoint, input_utxo.txout);

    let output_txout = UnspentTxOut::from_partial(output_txout.clone());

    let op_return_txout = op_return_txout(PushBytesBuf::from(operator_xonly_pk.serialize()));

    let mut txhandler = TxHandlerBuilder::new(TransactionType::Payout)
        .with_version(NON_STANDARD_V3)
        .add_input(
            NormalSignatureKind::NotStored,
            txin,
            SpendPath::KeySpend,
            DEFAULT_SEQUENCE,
        )
        .add_output(output_txout)
        .add_output(UnspentTxOut::from_partial(anchor_output(
            NON_EPHEMERAL_ANCHOR_AMOUNT,
        )))
        .add_output(UnspentTxOut::from_partial(op_return_txout))
        .finalize();
    txhandler.set_p2tr_key_spend_witness(&user_sig, 0)?;
    txhandler.promote()
}
