## Title
Permanent, path-bound `safe.directory` trust grant is never revoked when repository ownership later changes - (File: `app/src/lib/git/config.ts`)

### Summary
The Solidity report's broken invariant is: a privilege (`owner`) is granted to an actor (`deployer`) during setup and is never transferred/revoked to the intended, permanently-responsible party (`admin`), so the wrong principal retains control indefinitely. The equivalent broken invariant in GitHub Desktop is in the "unsafe repository" trust flow: when a user encounters a directory Git considers unsafe (owned by a different user than the current OS user), Desktop lets them grant a permanent exception by calling `addSafeDirectory`, which appends the path to the global `safe.directory` git config [1](#0-0) . That grant is keyed purely on a filesystem path string, is written to `~/.gitconfig` forever, and is never re-validated against the identity/ownership that justified it in the first place, nor revoked when the path is later reused by a different actor.

### Finding Description
`getRepositoryType` detects "dubious ownership" via Git's own `fatal: detected dubious ownership` check and surfaces it as `{ kind: 'unsafe', path }` [2](#0-1) . The UI (`AddExistingRepository` and `MissingRepository`) presents an "add an exception for this directory" action; clicking it calls `addSafeDirectory(repositoryUnsafePath)` once, and the path is added permanently to the global config [3](#0-2) [4](#0-3) .

`addSafeDirectory`/`addGlobalConfigValueIfMissing` never records *who* owned the directory at the time of consent, and there is no code path anywhere in the repository that later removes a path from `safe.directory` when a repository is deleted, relocated, or recreated at that same path by someone else [5](#0-4) . Because Git's `safe.directory` matching is purely by path (not by owner SID/UID at grant time), once a path is trusted it stays trusted for the lifetime of the user's Git config, regardless of who subsequently controls that path on disk.

This is analogous to the reported bug: the "owner" of the trust decision (the deployer who signed off on ownership when it was `deployer`-owned) is never re-checked or transferred when the underlying resource (the path) changes hands to a new principal. Just like `usdxlToken` silently continues answering to `deployer` instead of `admin`, a previously-trusted path silently continues answering to whoever currently occupies it, not the original owner the user vetted.

### Impact Explanation
On any multi-user machine, CI runner, or shared temp-directory environment, an attacker who can create a directory at a path that a Desktop user previously trusted (e.g. a shared clone destination, `/tmp/...` path, network share, or a path from a prior job in a shared CI worker) inherits full trust without the user ever being prompted again. Git repository-local config and hooks executed by "unsafe" repos are exactly what the `safe.directory` mechanism is designed to gate, because they can lead to arbitrary code execution when Desktop/Git operate on that repository (e.g. via `core.fsmonitor`, `core.hooksPath`, filters, or credential helpers defined in-repo). Silently re-granting that protection bypass to a new, attacker-controlled owner is a real code-execution primitive achievable purely by an attacker who controls a path/remote artifact the victim previously interacted with, matching the required "unprivileged" attacker model.

### Likelihood Explanation
Likelihood is elevated on shared or ephemeral-path workflows (CI machines, lab/shared computers, network drives, restored VM snapshots, or simply re-cloning into a previously-used directory after deleting it) — situations GitHub Desktop explicitly supports (clone destination selection, "Clone Again", "Relocate"). The user only has to have trusted a directory once; every future actor who acquires that same path benefits, with no re-prompt and no expiry.

### Recommendation
- Scope the trust grant to the specific ownership/identity validated at consent time rather than the bare path, or re-verify ownership each time `getRepositoryType`/Git evaluates `safe.directory` and prompt again if the owner has changed since the exception was granted.
- Provide a way to revoke a previously granted `safe.directory` exception when a Desktop-tracked repository at that path is removed/relocated (mirroring `_relocateRepository`'s handling of the `unsafe` case at `app/src/lib/stores/app-store.ts:8194-8204`), instead of leaving a stale global exception behind indefinitely.
- Consider recording exceptions in a Desktop-owned store keyed by path *and* a fingerprint of the repository (e.g. first commit hash) so the same path recreated with different content doesn't silently inherit prior trust.

### Proof of Concept
1. On a shared machine (or CI runner reused across jobs), Desktop user A clones/creates a repo at `C:\shared\proj` and later hits the "unsafe" warning (e.g., ownership temporarily changed by a backup/restore tool) and clicks "Trust Repository", triggering `addSafeDirectory('C:\shared\proj')` [4](#0-3) .
2. This appends `C:\shared\proj` to the user's global `~/.gitconfig` `[safe] directory` list permanently [1](#0-0) .
3. Later, the directory is deleted (e.g., a cleanup script) and attacker B, sharing the same machine/account/CI cache, creates a brand-new malicious Git repository at the exact same path `C:\shared\proj`, containing malicious repo-local config/hooks.
4. When user A (or a subsequent CI job under the same account) opens/clones into that path again, `getRepositoryType` no longer reports `unsafe` because the path is already in `safe.directory` — Git and Desktop treat attacker B's repository as fully trusted, executing whatever repo-local trust-gated behavior Git's unsafe-repository protection was designed to block, without any new prompt to the user.

/**
 * Adds a path to the `safe.directories` configuration variable if it's not
 * already present. Adding a path to `safe.directory` will cause Git to ignore
 * if the path is owner by a different user than the current.
 */
export async function addSafeDirectory(path: string) {
  // UNC-paths on Windows need to be prefixed with `%(prefix)/`, see
  // https://github.com/git-for-windows/git/commit/e394a16023cbb62784e380f70ad8a833fb960d68
  if (__WIN32__ && path[0] === '/') {
    path = `%(prefix)/${path}`
  }

  await addGlobalConfigValueIfMissing('safe.directory', path)
}

/** Set the global config value by name. */
export async function addGlobalConfigValueIfMissing(
  name: string,
  value: string
): Promise<void> {
  const { stdout, exitCode } = await git(
    ['config', '--global', '-z', '--get-all', name, value],
    __dirname,
    'addGlobalConfigValue',
    { successExitCodes: new Set([0, 1]) }
  )

  if (exitCode === 1 || !stdout.split('\0').includes(value)) {
    await addGlobalConfigValue(name, value)
  }
}
