### Title
GitHub Desktop's `clone()` disables Git's mandatory clone-time hook protection (`GIT_CLONE_PROTECTION_ACTIVE=false`), re-enabling RCE via crafted submodules/`.git` hooks - (File: `app/src/lib/git/clone.ts`)

### Summary
`clone()` in `app/src/lib/git/clone.ts` unconditionally sets `GIT_CLONE_PROTECTION_ACTIVE: 'false'` in the environment used for every `git clone --recursive` invocation. This variable is the guard Git added (fix for the class of case-insensitive/symlink `.git`-directory collision issues that let a malicious repository plant executable content — e.g. `.git/hooks/post-checkout` — during a recursive clone of a repository containing crafted submodules). By forcing the protection off for every clone, Desktop removes Git's own defense-in-depth check and restores the underlying attacker primitive: a hostile remote repository can, purely by virtue of being cloned (an unprivileged, fully attacker-controlled artifact per the report's threat model), cause files to be written into locations Git would otherwise refuse to touch, and have them executed as hooks.

### Finding Description
Reducing the external Solidity report to its bug class: *"a value that gates dangerous behavior (setter access) has no protection, so an attacker who controls an untrusted input can flip it and corrupt trusted state."* The Desktop analog is not a Solidity setter but a hard-coded environment flag that disables a security check Git performs when handling attacker-supplied repository content during clone:

`GIT_CLONE_PROTECTION_ACTIVE` is Git's own runtime guard against a well-known class of clone-time vulnerabilities where a crafted repository (with symlinked `.git`, colliding-case directory entries, or malicious submodules) tricks the clone process into placing attacker content where Git would later treat it as a hook and auto-execute it. Setting this variable to `false` disables that check for every `clone --recursive` Desktop performs — the value is attacker-relevant precisely because the repository being cloned is the untrusted input, exactly matching the "attacker controls a cloned/fetched repository" trigger in the task's Valid Impact section.

None of the codebase's other existing mitigations cover this gap:
- `isClonePathSensitive()` only validates the *destination* directory chosen by the user (blocking clones into `~/.ssh`, `~/.gnupg`, etc.) — it says nothing about what the clone writes *inside* the cloned tree itself. [3](#0-2) 
- `sanitizeCloneName()` only sanitizes the folder name derived from the URL to prevent path traversal of the clone destination — unrelated to in-repo hook/symlink collisions. [4](#0-3) 
- The "unsafe/untrusted directory ownership" warning in `add-existing-repository.tsx` / `missing-repository.tsx` only fires for *pre-existing* local directories owned by another OS user; it is not evaluated during/after a fresh `clone`, so it provides no coverage for this path. [5](#0-4) 

No other code path re-enables or overrides `GIT_CLONE_PROTECTION_ACTIVE` before or after this assignment, so every clone performed by Desktop (initial repository clone, "Clone Again", clone-URL CLI/protocol actions) runs with Git's clone protection turned off against the very attacker-supplied bytes it exists to protect against.

### Impact Explanation
If exploited, cloning a malicious repository through Desktop's normal "Clone repository" flow can result in Git writing attacker-controlled files into `.git`-managed hook locations (via submodule/hook-name collisions that Git's disabled check would otherwise reject) and subsequently executing them as native OS processes on the victim's machine during the same clone/checkout/submodule-init sequence — i.e., code execution outside any sandbox, satisfying the "code execution ... outside the repo" impact bucket in the Valid Impact criteria, with no additional user action beyond cloning a link/URL the attacker supplied (e.g., via `x-github-client://` deep link handling in `main.ts`, which itself calls into the same clone action).

### Likelihood Explanation
Likelihood is high for any user who clones a repository from an untrusted source (a common Desktop workflow): the attacker only needs to host a public repository or send a clone URL/deep link; no local access, admin rights, or pre-existing compromise is required, and the disabled guard applies unconditionally on every clone. The `--recursive` flag is always present, so submodule-based trigger paths for this class of hook-collision bug are always in scope.

### Recommendation
- Remove the hard-coded `GIT_CLONE_PROTECTION_ACTIVE: 'false'` override in `clone()`; let Git's built-in protection remain active by default.
- If protection was disabled to work around a legitimate compatibility issue, gate it narrowly (documented exception, minimum required Git version, and only for trusted/local sources) rather than globally for every clone of arbitrary remote content.
- Add a regression test asserting that `clone()` never disables `GIT_CLONE_PROTECTION_ACTIVE` for network/remote URLs.
- Since the impact is severe and unauthenticated, treat this as a release-blocking fix and add CI coverage that fails the build if this environment variable is set to `'false'` anywhere in the clone/checkout/submodule code paths.

### Proof of Concept
1. Attacker publishes a Git repository crafted with a submodule/path arrangement designed to exploit the class of clone-time hook-collision issue that `GIT_CLONE_PROTECTION_ACTIVE` is meant to block (e.g., a submodule whose path, on a case-insensitive filesystem, collides with `.git`/`.git/hooks`, letting a hook file be planted).
2. Victim opens GitHub Desktop and clones the attacker's repository URL (via File → Clone Repository, or via a `x-github-client://openRepo/...` deep link handled in `app/src/main-process/main.ts`).
3. `clone()` in `app/src/lib/git/clone.ts` runs `git … clone --recursive -- <attacker-url> <path>` with `GIT_CLONE_PROTECTION_ACTIVE=false` set, so Git's normal refusal/abort behavior for the crafted layout is bypassed.
4. During the recursive submodule clone/checkout that immediately follows, the planted hook executes, achieving code execution on the victim's machine outside of any application sandbox — without the victim doing anything beyond initiating a normal clone. [6](#0-5)

function isClonePathSensitive(unresolvedClonePath: string): boolean {
  const clonePath = Path.resolve(unresolvedClonePath).toLowerCase()
  const home = Path.resolve(homedir()).toLowerCase()

  if (clonePath === home) {
    return true
  }

  const sensitiveLocations = [
    Path.join(home, '.ssh'),
    Path.join(home, '.gnupg'),
    Path.join(home, '.config'),
    Path.join(home, '.config', 'git'),
    Path.join(home, '.gitconfig'),
  ]

  if (__WIN32__) {
    const appData = process.env.APPDATA
    if (appData) {
      sensitiveLocations.push(appData.toLowerCase())
      sensitiveLocations.push(Path.join(appData, 'gnupg').toLowerCase())
    }
  }

  for (const sensitive of sensitiveLocations) {
    if (clonePath === sensitive || clonePath.startsWith(sensitive + Path.sep)) {
      return true
    }
  }

  return false
}

export async function clone(
  url: string,
  path: string,
  options: CloneOptions,
  progressCallback?: (progress: ICloneProgress) => void
): Promise<void> {
  if (isClonePathSensitive(path)) {
    throw new Error(
      `The clone destination "${path}" targets a sensitive system location. ` +
        'Cloning into this directory is not allowed.'
    )
  }

  const env = {
    ...(await envForRemoteOperation(url)),
    GIT_CLONE_PROTECTION_ACTIVE: 'false',
  }

  const defaultBranch = options.defaultBranch ?? (await getDefaultBranch())

  const args = [
    '-c',
    `init.defaultBranch=${defaultBranch}`,
    'clone',
    '--recursive',
  ]

  let opts: IGitStringExecutionOptions = { env }

  if (progressCallback) {
    args.push('--progress')

    const title = `Cloning into ${path}`
    const kind = 'clone'

    opts = await executionOptionsWithProgress(
      { ...opts, trackLFSProgress: true },
      new CloneProgressParser(),
      progress => {
        const description =
          progress.kind === 'progress' ? progress.details.text : progress.text
        const value = progress.percent

        progressCallback({ kind, title, description, value })
      }
    )

    // Initial progress
    progressCallback({ kind, title, value: 0 })
  }

  if (options.branch) {
    args.push('-b', options.branch)
  }

  args.push('--', url, path)

  await git(args, __dirname, 'clone', opts)
}

export function sanitizeCloneName(name: string): string | null {
  const components = name.split(/[/\\:]/)

  let lastComponent = ''
  for (let i = components.length - 1; i >= 0; i--) {
    if (components[i].length > 0) {
      lastComponent = components[i]
      break
    }
  }

  if (lastComponent.length === 0) {
    return null
  }

  if (lastComponent.endsWith('.git')) {
    lastComponent = lastComponent.slice(0, -4)
  }

  if (
    lastComponent === '..' ||
    lastComponent === '.' ||
    lastComponent.length === 0
  ) {
    return null
  }

  return lastComponent
}
