### Title
Flash-deposit reward sniping in `BaseRewardPool.earned` due to live `balanceOf` combined with un-timed `queueNewRewards` accounting - ([File: rewards/BaseRewardPool.sol])

### Summary
`BaseRewardPool.balanceOf` always reads the *current* live stake from `MasterMagpie.stakingInfo` rather than a balance snapshot taken at the time rewards accrued [1](#0-0) . Because reward distribution (`queueNewRewards`) bumps `rewardPerTokenStored` instantly and proportionally to the *current* `totalStaked()`, rather than accruing over elapsed time, an attacker can deposit, force a harvest, and withdraw in a single transaction to capture a full pro-rata share of a reward event they were staked for zero blocks.

### Finding Description
`earned()` is computed as `balanceOf(_account) * (rewardPerToken - userRewardPerTokenPaid) / decimals + userRewards` [2](#0-1) . `balanceOf` is not a stored/snapshotted value; it is fetched live via `IMasterMagpie(operator).stakingInfo(stakingToken, _account)` [3](#0-2) , which reflects `MasterMagpie.userInfo[stakingToken][_account].amount`, the value that is mutated on every `deposit`/`withdraw` call.

In `MasterMagpie._deposit`, `_harvestBaseRewarder` (which triggers `updateReward`/`_updateFor`, snapshotting `userRewardPerTokenPaid` at the pre-deposit reward-per-token value using the pre-deposit balance) is invoked *before* `user.amount` is incremented [4](#0-3) . Symmetrically, in `_withdraw`/`_harvestAndUnstake`, `_harvestBaseRewarder` (which reads the *current* balance via `balanceOf`) runs before `user.amount` is decremented [5](#0-4) .

`queueNewRewards` (callable by any registered manager, e.g. `WombatStaking`, and triggered permissionlessly by anyone calling `WombatPoolHelperV2.harvest()` → `WombatStaking.harvest`) increases `rewardPerTokenStored` immediately in proportion to `totalStaked()` at call time, with no notion of "how long a staker has held their balance" [6](#0-5)  and `rewards/BaseRewardPoolV2.sol:290-314`. Since `totalStaked()` is simply `IERC20(stakingToken).balanceOf(operator)` at call time, a stake deposited moments earlier in the same transaction is already counted in the denominator, and — via the live `balanceOf` read at withdraw-time — also counted fully in the numerator of `earned()`.

Sequence:
1. `MasterMagpie.deposit(stakingToken, amount)` — attacker's receipt tokens are transferred into the pool; `_harvestBaseRewarder` snapshots `userRewardPerTokenPaid` at the old (pre-harvest) `rewardPerTokenStored`; `user.amount` becomes the new (large) balance.
2. Any account permissionlessly triggers `WombatStaking.harvest(lpToken)`(via `WombatPoolHelperV2.harvest()`), which calls `_toMasterWomAndSendReward` → `_sendRewards` → `queueNewRewards` on the `BaseRewardPool`, bumping `rewardPerTokenStored` using a `totalStaked()` that already includes the attacker's newly deposited balance [7](#0-6)  and [8](#0-7) .
3. `MasterMagpie.withdraw(stakingToken, amount)` — `_harvestBaseRewarder`/`getReward` computes `earned()` using the attacker's **full deposited balance** (still present since it's read before decrement) against the entire reward-per-token delta just injected, then pays it out via `_sendReward`.

No existing check (no cooldown, no minimum holding period, no time-weighted accrual, no `nonReentrant`-style protection against this pattern) prevents this, because `nonReentrant`/`whenNotPaused` guard against reentrancy/pausing, not against same-block deposit→harvest→withdraw sequencing.

### Impact Explanation
This is a direct theft of unclaimed yield: the attacker extracts a reward share proportional to a stake that was never actually staked during the period the harvested WOM/bonus rewards accrued in the underlying `MasterWombat` pool, diluting and stealing from genuine long-term stakers. This matches the Immunefi impact class "theft of unclaimed yield" and constitutes a real economic loss to other pool participants, repeatable every time a harvest can be triggered.

### Likelihood Explanation
The attacker needs no special privileges — only ownership of the pool's `depositToken`/LP and the ability to deploy a simple helper contract to bundle `deposit → triggerHarvest (permissionless) → withdraw` into one transaction. Since `WombatStaking.harvest`/`WombatPoolHelperV2.harvest()` is callable by anyone, the attacker fully controls timing and can repeat this against every subsequent harvest event, scaling profit with capital deposited (larger deposit → larger share of `totalStaked()` → larger share of the harvested reward), making it highly feasible and repeatable.

### Recommendation
Decouple reward eligibility from instantaneous live balance by either (a) requiring a minimum staking duration/cooldown before a deposit is eligible for a given `queueNewRewards` round, (b) checkpointing `balanceOf` per reward-round rather than reading it live at `earned()`-time, or (c) accruing rewards on a time-weighted (per-second) basis and only crediting deposits with the amount of time actually staked (as in a Synthetix-style `rewardRate * timeElapsed` design instead of instantaneous `rewardPerTokenStored` bumps proportional to current `totalStaked()`).

### Proof of Concept
Foundry test plan:
1. Deploy `MasterMagpie`, `BaseRewardPool` (or `BaseRewardPoolV2`), a mock `WombatStaking`/manager that can call `queueNewRewards`, and a `depositToken`/receipt token.
2. Seed an existing long-term staker (`staker1`) who deposits and lets time pass, simulating real accrual in `MasterWombat`.
3. Deploy an `AttackerHelper` contract that in a single external call: `MasterMagpie.deposit(stakingToken, amount)` → `manager.queueNewRewards(rewardAmount, rewardToken)` (simulating `WombatStaking.harvest` triggering a reward injection) → `MasterMagpie.withdraw(stakingToken, amount)`.
4. Fund `AttackerHelper` with `depositToken` and reward tokens for the manager to queue.
5. Call `AttackerHelper.attack(amount, rewardAmount)`.
6. Assert: attacker's `depositToken` balance after the transaction is greater than before minus gas (net profit in reward token), and `BaseRewardPool.earned(attacker, rewardToken)` was nonzero and paid out despite `attacker` having zero elapsed blocks/time staked; also assert `staker1`'s expected share of the same reward event was diluted below what it would have been absent the attacker's flash stake.

        updatePool(_stakingToken);

        UserInfo storage user = userInfo[_stakingToken][_account];

        if (!_isVlMgp && user.available < _amount)
            revert WithdrawAmountExceedsStaked();
        else if(user.amount < _amount && _isVlMgp)
            revert UnlockAmountExceedsLocked();
        
        _harvestMGP(_stakingToken, _account);
        _harvestBaseRewarder(_stakingToken, _account);

        user.amount = user.amount - _amount;
        
        if(!_isVlMgp)
            user.available = user.available - _amount;
        user.rewardDebt = (user.amount * tokenToPoolInfo[_stakingToken].accMGPPerShare) / 1e12;
    }

    function _sendRewards(
        address _lpToken,
        address _rewardToken,
        address _rewarder,
        uint256 _amount
    ) internal {
        if (_amount == 0) return;
        uint256 originalRewardAmount = _amount;

        if (!isPoolFeeFree[_lpToken]) {
            for (uint256 i = 0; i < feeInfos.length; i++) {
                Fees storage feeInfo = feeInfos[i];

                if (feeInfo.isActive) {
                    address rewardToken = _rewardToken;
                    uint256 feeAmount = (originalRewardAmount * feeInfo.value) / DENOMINATOR;
                    _amount -= feeAmount;
                    uint256 feeTosend = feeAmount;

                    if (feeInfo.isMWOM && rewardToken == wom) {
                        if (smartWomConverter != address(0)) {
                            IERC20(wom).safeApprove(smartWomConverter, feeAmount);
                            uint256 beforeBalnce = IMWom(mWom).balanceOf(address(this));
                            IConverter(smartWomConverter).smartConvert(feeAmount, 0);
                            rewardToken = mWom;
                            feeTosend = IMWom(mWom).balanceOf(address(this)) - beforeBalnce;
                        } else {
                            IERC20(wom).safeApprove(mWom, feeAmount);
                            uint256 beforeBalnce = IMWom(mWom).balanceOf(address(this));
                            IMWom(mWom).deposit(feeAmount);
                            rewardToken = mWom;
                            feeTosend = IMWom(mWom).balanceOf(address(this)) - beforeBalnce;
                        }
                    }

                    if (!feeInfo.isAddress) {
                        IERC20(rewardToken).safeApprove(feeInfo.to, 0);
                        IERC20(rewardToken).safeApprove(feeInfo.to, feeTosend);
                        IBaseRewardPool(feeInfo.to).queueNewRewards(feeTosend, rewardToken);
                    } else {
                        IERC20(rewardToken).safeTransfer(feeInfo.to, feeTosend);
                        emit RewardPaidTo(feeInfo.to, rewardToken, feeTosend);
                    }
                }
            }
        }

        IERC20(_rewardToken).safeApprove(_rewarder, 0);
        IERC20(_rewardToken).safeApprove(_rewarder, _amount);
        IBaseRewardPool(_rewarder).queueNewRewards(_amount, _rewardToken);
    }
