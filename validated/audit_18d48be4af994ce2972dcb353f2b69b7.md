**Reasoning:**

The premise that no registered egroup covers `{sBTC-collateral, sBTC-debt}` without STX is factually incorrect for this codebase. In the mainnet initialization proposal, Egroup 2 is registered with exactly that combination and no STX dependency: [1](#0-0) 

`v0-egroup`'s `resolve`/`find` mechanism looks up a registered mask that is a **superset** of the target position mask via `subset`, which checks `(is-eq sub (bit-and sub super))`: [2](#0-1) [3](#0-2) 

Since Egroup 2's `MASK` is `2^2 + 2^66` (sBTC-collateral + sBTC-debt exactly), and the future-mask after removing STX collateral is exactly that same value, `subset target target` trivially holds and `find` returns immediately, so `get-egroup future-mask` in `collateral-remove` succeeds and does **not** abort: [4](#0-3) 

Beyond this factual refutation, the underlying premise (a DAO-registered egroup set that fails to cover a valid position-mask combination) is explicitly out of scope per the rules, since correctness of the egroup registry configuration and its superset coverage is asserted to be verified off-chain before DAO approval, and any gap would stem from an incomplete/incorrect DAO registry update rather than a bug in `is-healthy-with-mask` or `get-egroup` resolution logic themselves.

```text
(define-private (find-superset (target uint) (masks (list 128 uint)))
  (let ((init { target: target, result: none })

(define-private (iter-find-superset (mask uint) (acc {target: uint, result: (optional uint)}))
  (let ((res (get result acc)))
    (if (is-some res)
        ;; Already found a match - return early
        acc
        ;; Check if this mask matches
        (let ((target (get target acc)))
          (if (subset target mask)
              ;; Match found - return egroup ID
              (let ((id (unwrap-panic (map-get? reverse mask))))
                (merge acc { result: (some (buff-to-uint-be id)) }))
              ;; Not a match - skip
              acc)))))
```
