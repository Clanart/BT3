### Title
Auction `SubmitBid` submits target transaction to the mempool/network before validating Auctioneer/Searcher authorization - ([File: kaiax/auction/impl/api.go])

### Summary
`AuctionAPI.SubmitBid` decodes and broadcasts the caller-supplied `targetTxRaw` into the transaction pool via `api.a.Backend.SendTx(ctx, targetTx)` **before** the bid's `SearcherSig`/`AuctioneerSig` are checked in `bidPool.AddBid` → `validateBid` → `validateBidSigs`. This mirrors the reported bug class: a side-effecting network/state operation is performed prior to the authorization check that is supposed to gate it.

### Finding Description
`auction_submitBid` is registered as a private (`Public: false`) namespace RPC method, but it is documented and used as the entry point through which the `Auctioneer` — the only entity that is supposed to be trusted to submit auction bids per KIP-249 — pushes bids to the CN [1](#0-0) . The handler performs the following, in order:

1. Decode `bidInput.TargetTxRaw` into a `types.Transaction` and verify only that its hash matches `bidInput.TargetTxHash`.
2. Call `api.a.Backend.SendTx(ctx, targetTx)`, which injects the transaction into the node's live transaction pool (and, from there, standard tx-pool broadcast/propagation and future block-inclusion machinery run against it).
3. Only afterward, construct the `Bid` from the same request and call `bidPool.AddBid(bid)`, which performs `validateBid`/`validateBidSigs` — the searcher-signature and (critically) **Auctioneer**-signature checks that establish whether the caller was actually entitled to submit an auction bid at all. [2](#0-1) 

The authorization for this endpoint's whole raison d'être (only the legitimate Auctioneer's requests should drive auction bookkeeping/state such as `bidWinnerMap`, `bidTargetMap`, gas-limit computation, and the `newBidCh` signal consumed to build bid transactions for the block) is enforced in `validateBidSigs`, which recovers and compares the searcher and auctioneer signer addresses only inside `AddBid`, after `SendTx` has already fired: [3](#0-2) 

Because step 2 happens unconditionally regardless of whether step 3 later fails (invalid searcher sig, invalid or forged auctioneer sig, stale/duplicate bid, bid pool full, etc.), any caller who can reach this RPC method can force the node to decode arbitrary transaction bytes and commit them to the tx pool state (going through `validateTx`, sender-signature recovery, nonce/balance bookkeeping, and subsequent tx-pool broadcast to peers) purely by attaching a syntactically valid but never-actually-checked bid payload. The `AddBid` call and its authorization gate are entirely decoupled from and subsequent to the `SendTx` side effect — exactly the "perform work first, authorize later" pattern in the reported advisory.

### Impact Explanation
- The auction subsystem's core invariant — that bid-triggered actions originate only from the authenticated `Auctioneer` — is bypassed for the transaction-submission side effect: `SendTx` executes unconditionally before `AddBid`'s signature checks run, so an unauthorized caller can drive tx-pool admission logic (including underpriced/replacement/eviction bookkeeping, `pool.all`, `pool.queue`/`pool.pending` mutation, and network propagation to peers) attached to a `auction_submitBid` call that will ultimately be rejected as an invalid bid.
- This allows an unauthorized caller to use the auction-only RPC surface as an unrestricted transaction-injection primitive that is supposed to be gated behind the Auctioneer's signature, undermining the access-control model documented for this module (`Public: false`, Auctioneer-only bidding) and enabling unauthorized state mutation of the tx pool (and consequent gossip/mempool churn) regardless of whether the accompanying bid is legitimate.
- Because bid validation ultimately still runs (and correctly rejects invalid signatures for the *bid itself*), no direct fund theft or auction-settlement forgery is demonstrated here; the primary confirmed effect is unauthorized triggering of tx-pool/network side effects ahead of the authorization gate that was specifically designed to prevent non-Auctioneer parties from driving this code path.

### Likelihood Explanation
`auction_submitBid` only requires reachability to the CN's private RPC namespace and a well-formed (self-consistently hashed) raw transaction plus arbitrary junk bid/signature fields — no valid Auctioneer or Searcher signature is needed to trigger the `SendTx` call, since that call precedes all signature verification. Any caller who can invoke this API can reliably trigger the issue on every call.

### Recommendation
Reorder `SubmitBid` so that `bidPool.AddBid` (and therefore `validateBid`/`validateBidSigs`, which authenticate the Auctioneer and Searcher) runs and succeeds **before** `api.a.Backend.SendTx` is invoked, ensuring the target transaction is only submitted to the pool once the accompanying bid has been proven to originate from the authorized Auctioneer.

### Proof of Concept
1. Craft any well-formed, independently-valid signed transaction `T` (its own sender signature can be legitimate/arbitrary — it does not need to relate to the auction at all) and RLP-encode it as `targetTxRaw`; set `targetTxHash = T.Hash()`.
2. Set `searcherSig`/`auctioneerSig` to any syntactically-correctly-sized but incorrect signatures (65 bytes of garbage), and any bid fields.
3. Call `auction_submitBid` with this payload against a CN exposing the `auction` namespace.
4. Observe: `SendTx` is invoked and `T` is admitted to the transaction pool (subject only to normal tx-pool rules on `T` itself) at [4](#0-3) , even though the subsequent `AddBid` call fails with `ErrInvalidSearcherSig`/`ErrInvalidAuctioneerSig` from `validateBidSigs` [5](#0-4) . The caller never had to prove Auctioneer authorization to cause the tx-pool side effect.

func (api *AuctionAPI) SubmitBid(ctx context.Context, bidInput BidInput) RPCOutput {
	numBidRequestCounter.Inc(1)
	if api.a.IsDisabled() {
		return makeRPCOutput(EMPTY_HASH, auction.ErrAuctionDisabled)
	}

	//  1. directly send target transaction
	targetTx, errTxDecode := toTx(bidInput.TargetTxRaw)
	if errTxDecode != nil {
		return makeRPCOutput(EMPTY_HASH, errTxDecode)
	}
	if targetTx.Hash() != bidInput.TargetTxHash {
		return makeRPCOutput(EMPTY_HASH, auction.ErrInvalidTargetTxHash)
	}
	errTargetTxSend := api.a.Backend.SendTx(ctx, targetTx)
	// ignore known transaction related errors against target tx validation
	if errTargetTxSend != nil && !(strings.HasPrefix(errTargetTxSend.Error(), "known transaction:") || errors.Is(errTargetTxSend, gasless_impl.ErrUnableToAddKnownBundleTx)) {
		return makeRPCOutput(EMPTY_HASH, errTargetTxSend)
	}

	// 2. add bid
	bid := ToBid(bidInput)
	bidHash, errValidateBid := api.a.bidPool.AddBid(bid)
	return makeRPCOutput(bidHash, errValidateBid)
}

func (bp *BidPool) validateBid(bid *auction.Bid) error {
	blockNumber := bid.BlockNumber

	bp.bidMu.RLock()

	// Check if the auction tx is already in the pool.
	if _, ok := bp.bidMap[bid.Hash()]; ok {
		bp.bidMu.RUnlock()
		return auction.ErrBidAlreadyExists
	}

	// 1. The `bid.Sender` must not be in the winner list of the same block number if the new bid isn't equal to the previous bid.
	if bp.senderHasDifferentWinner(bid) {
		bp.bidMu.RUnlock()
		return auction.ErrBidSenderExists
	}
	bp.bidMu.RUnlock()

	curBlock := bp.Chain.CurrentBlock()
	if curBlock == nil {
		return auction.ErrBlockNotFound
	}

	// 2. The `bid.BlockNumber` must be in range of `[currentBlockNumber + 1, currentBlockNumber + allowFutureBlock]`.
	curNum := curBlock.NumberU64()
	if blockNumber <= curNum || blockNumber > curNum+allowFutureBlock {
		return auction.ErrInvalidBlockNumber
	}

	// 3. The `bid.Bid` must be greater than 0.
	if bid.Bid.Sign() <= 0 {
		return auction.ErrZeroBid
	}

	// 4. The data size must be less than the maximum limit.
	if uint64(len(bid.Data)) > BidTxMaxDataSize {
		return auction.ErrExceedMaxDataSize
	}

	// 5. The gas limit must be less than the maximum limit.
	if bid.CallGasLimit > BidTxMaxCallGasLimit {
		return auction.ErrExceedMaxCallGasLimit
	}

	// 6. The `bid.SearcherSig` and `bid.AuctioneerSig` must be valid.
	if err := bp.validateBidSigs(bid); err != nil {
		return err
	}

	return nil
}

func (bp *BidPool) validateBidSigs(bid *auction.Bid) error {
	bp.auctionInfoMu.RLock()
	defer bp.auctionInfoMu.RUnlock()

	if bid.SearcherSig == nil || len(bid.SearcherSig) != crypto.SignatureLength {
		return auction.ErrInvalidSearcherSig
	}
	if bid.AuctioneerSig == nil || len(bid.AuctioneerSig) != crypto.SignatureLength {
		return auction.ErrInvalidAuctioneerSig
	}

	// Verify the EIP712 signature.
	if err := bid.ValidateSearcherSig(bp.ChainConfig.ChainID, bp.auctionEntryPoint, bp.auctionEntryPointVersion); err != nil {
		return err
	}

	// Verify the auctioneer signature.
	if err := bid.ValidateAuctioneerSig(bp.auctioneer); err != nil {
		return err
	}

	return nil
}
