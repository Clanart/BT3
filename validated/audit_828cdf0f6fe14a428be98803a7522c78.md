### Title
Missing recipient binding in DKG encrypted-share PoP enables capture-replay of an honest sender's share, wrongfully blaming/slashing them - (File: crypto/dkg/pedpop/src/encryption.rs)

### Summary
Analogous to the capture-replay authentication bypass class (CWE-294), the proof-of-possession on `EncryptedMessage` authenticates the *sender* and message bytes but never binds the *intended recipient* (the `to` encryption public key). A ciphertext an honest participant produced for one recipient therefore verifies as a valid "message from that sender" in any other recipient/decryptor context — including third-party blame adjudication — causing an innocent party to be identified as faulty.

### Finding Description
In `encrypt`, the per-message key is ECDH'd against the recipient's registered encryption key (`ecdh(&key, to)`), and a Schnorr PoP is produced over `pop_challenge(context, pub_nonce, pub_key, from, msg)`. The challenge transcript appends `context`, `nonce`, `key`, `sender`, and `message` — but not the recipient's encryption public key `to`. [1](#0-0) 

`Decryption::decrypt_with_proof` (used by `BlameMachine::blame` and `AdditionalBlameMachine::blame`) verifies `msg.pop` with only `from` as identity, then checks the accuser-supplied `EncryptionKeyProof` DLEq against `enc_keys[decryptor]` and decrypts. The PoP check therefore passes for a message the sender legitimately produced — but for a *different* recipient. [2](#0-1) 

Crucially, the DKG wire format makes all encrypted shares public: each participant publishes a `Commitments`-wrapped map of `EncryptedMessage`s for every participant (Serai's processor puts these in `DkgShares` transactions on the tributary). Any observer can thus capture the exact `EncryptedMessage` Alice produced for Bob. Since `AdditionalBlameMachine::new` is explicitly designed so "the caller" need not be a DKG member and `blame(sender, recipient, msg, proof)` takes the message as attacker-supplied bytes [3](#0-2) , an accuser can submit `(sender=Alice, recipient=Carol, msg=Alice→Bob ciphertext, proof=Carol's honest ECDH proof)`. The PoP verifies (sender=Alice, message bytes match), the DLEq verifies (Carol's real enc key), and decryption yields garbage → `blame_internal` returns `sender`, marking Alice faulty. [4](#0-3) 

The same gap exists in the live decryption path: `pop_challenge` in `Encryption::decrypt` also omits `to`, so a replayed ciphertext is indistinguishable from a genuinely addressed one. [5](#0-4) 

### Impact Explanation
An unprivileged party who can observe the public DKG transcript (all encrypted shares are broadcast) can replay any honest participant's share ciphertext under a blame accusation naming themselves (or a colluding/forced recipient) as decryptor. Because the plaintext under the wrong recipient's ECDH key is garbage, `blame_internal` deterministically attributes fault to the honest sender. In the Serai protocol this produces a `ProcessorMessage::Blame { participant: accused }` — a fatal slashing of an honest validator — and aborts the DKG. This is an authentication bypass by capture-replay: an authenticated artifact accepted outside the context (recipient) it was produced for, with a security-critical verdict derived from it. Severity: Medium–High (deterministic wrongful slash + liveness abort; does not leak key shares directly since garbage plaintext is revealed, not the real share).

### Likelihood Explanation
Reachable with public inputs only: the attacker needs the broadcast `EncryptedMessage` bytes (public), must produce a valid `EncryptionKeyProof` for their own enc key (they can, per `Encryption::decrypt`), and invoke blame — which `AdditionalBlameMachine::new` explicitly supports for non-participants. The code documents that the `msg` "must have been authenticated as actually having come from the sender in question" — a replayed share *was* authenticated as from the sender; the undocumented gap is that it was never bound to the recipient the accusation concerns. Exploitation requires a DKG to be in progress and triggers an abort, so it cannot be repeated silently, but a single execution suffices to slash an honest party.

### Recommendation
Bind the recipient's encryption public key into the PoP: append `to` (the `C::G` registered encryption key) to `pop_challenge`'s transcript, and pass the expected recipient key at verification sites (`Encryption::encrypt`/`decrypt`, `Decryption::decrypt_with_proof`). This makes an `EncryptedMessage` valid solely for the (sender, recipient) pair it was created for, eliminating cross-recipient replay.

### Proof of Concept
1. Participants run `KeyGenMachine::generate_coefficients` → `generate_secret_shares`; Alice's `EncryptedMessage` to Bob, `m_AB`, is published.
2. Carol (or any observer) captures `m_AB`. Carol generates `EncryptionKeyProof { key: ecdh(enc_key_C, m_AB.key), dleq: DLEqProof::prove(encryption_key_transcript(context), [G, m_AB.key], enc_key_C) }` — valid since she knows `enc_key_C`.
3. Call `AdditionalBlameMachine::new(context, n, commitment_msgs).blame(Alice, Carol, m_AB, Some(proof))`.
4. `pop.verify(m_AB.key, pop_challenge(context, m_AB.pop.R, m_AB.key, Alice, m_AB.msg))` passes (PoP never referenced `to`); the DLEq verifies against `enc_keys[Carol]`; decrypted share fails `from_repr`/share verification → returns `Alice`. Honest Alice is blamed; the protocol aborts and Alice is slashed despite having sent a perfectly valid share to Bob.

fn pop_challenge<C: Ciphersuite>(
  context: [u8; 32],
  nonce: C::G,
  key: C::G,
  sender: Participant,
  msg: &[u8],
) -> C::F {
  let mut transcript = RecommendedTranscript::new(b"DKG Encryption Key Proof of Possession v0.2");
  transcript.append_message(b"context", context);

  transcript.domain_separate(b"proof_of_possession");

  transcript.append_message(b"nonce", nonce.to_bytes());
  transcript.append_message(b"key", key.to_bytes());
  // This is sufficient to prevent the attack this is meant to stop
  transcript.append_message(b"sender", sender.to_bytes());
  // This, as written above, doesn't hurt
  transcript.append_message(b"message", msg);
  // While this is a PoK and a PoP, it's called a PoP here since the important part is its owner
  // Elsewhere, where we use the term PoK, the important part is that it isn't some inverse, with
  // an unknown to anyone discrete log, breaking the system
  C::hash_to_F(b"DKG-encryption-proof_of_possession", &transcript.challenge(b"schnorr"))
}

  pub(crate) fn decrypt_with_proof<E: Encryptable>(
    &self,
    from: Participant,
    decryptor: Participant,
    mut msg: EncryptedMessage<C, E>,
    // There's no encryption key proof if the accusation is of an invalid signature
    proof: Option<EncryptionKeyProof<C>>,
  ) -> Result<Zeroizing<E>, DecryptionError> {
    if !msg.pop.verify(
      msg.key,
      pop_challenge::<C>(self.context, msg.pop.R, msg.key, from, msg.msg.deref().as_ref()),
    ) {
      Err(DecryptionError::InvalidSignature)?;
    }

    if let Some(proof) = proof {
      // Verify this is the decryption key for this message
      proof
        .dleq
        .verify(
          &mut encryption_key_transcript(self.context),
          &[C::generator(), msg.key],
          &[self.enc_keys[&decryptor], *proof.key],
        )
        .map_err(|_| DecryptionError::InvalidProof)?;

      cipher::<C>(self.context, &proof.key).apply_keystream(msg.msg.as_mut().as_mut());
      Ok(msg.msg)
    } else {
      Err(DecryptionError::InvalidProof)
    }
  }

  fn blame_internal(
    &self,
    sender: Participant,
    recipient: Participant,
    msg: EncryptedMessage<C, SecretShare<C::F>>,
    proof: Option<EncryptionKeyProof<C>>,
  ) -> Participant {
    let share_bytes = match self.encryption.decrypt_with_proof(sender, recipient, msg, proof) {
      Ok(share_bytes) => share_bytes,
      // If there's an invalid signature, the sender did not send a properly formed message
      Err(DecryptionError::InvalidSignature) => return sender,
      // Decryption will fail if the provided ECDH key wasn't correct for the given message
      Err(DecryptionError::InvalidProof) => return recipient,
    };

    let Some(share) = Option::<C::F>::from(C::F::from_repr(share_bytes.0)) else {
      // If this isn't a valid scalar, the sender is faulty
      return sender;
    };

    // If this isn't a valid share, the sender is faulty
    if !bool::from(
      multiexp_vartime(&share_verification_statements::<C>(
        recipient,
        &self.commitments[&sender],
        Zeroizing::new(share),
      ))
      .is_identity(),
    ) {
      return sender;
    }

    // The share was canonical and valid
    recipient
  }

impl<C: Ciphersuite> AdditionalBlameMachine<C> {
  /// Create an AdditionalBlameMachine capable of evaluating Blame regardless of if the caller was
  /// a member in the DKG protocol.
  ///
  /// Takes in the parameters for the DKG protocol and all of the participant's commitment
  /// messages.
  ///
  /// This constructor assumes the full validity of the commitment messages. They must be fully
  /// authenticated as having come from the supposed party and verified as valid. Usage of invalid
  /// commitments is considered undefined behavior, and may cause everything from inaccurate blame
  /// to panics.
  pub fn new(
    context: [u8; 32],
    n: u16,
    mut commitment_msgs: HashMap<Participant, EncryptionKeyMessage<C, Commitments<C>>>,
  ) -> Result<Self, PedPoPError<C>> {
    let mut commitments = HashMap::new();
    let mut encryption = Decryption::new(context);
    for i in 1 ..= n {
      let i = Participant::new(i).unwrap();
      let Some(msg) = commitment_msgs.remove(&i) else { Err(PedPoPError::MissingParticipant(i))? };
      commitments.insert(i, encryption.register(i, msg).commitments);
    }
    Ok(AdditionalBlameMachine(BlameMachine { commitments, encryption, result: None }))
  }

  /// Given an accusation of fault, determine the faulty party (either the sender, who sent an
  /// invalid secret share, or the receiver, who claimed a valid secret share was invalid).
  ///
  /// The message should be a copy of the encrypted secret share from the accused sender to the
  /// accusing recipient. This message must have been authenticated as actually having come from
  /// the sender in question.
  ///
  /// This will process the same blame statement multiple times, always identifying blame. It is
  /// the caller's job to ensure they're unique in order to prevent multiple instances of blame
  /// over a single incident.
  pub fn blame(
    &self,
    sender: Participant,
    recipient: Participant,
    msg: EncryptedMessage<C, SecretShare<C::F>>,
    proof: Option<EncryptionKeyProof<C>>,
  ) -> Participant {
    self.0.blame_internal(sender, recipient, msg, proof)
  }
