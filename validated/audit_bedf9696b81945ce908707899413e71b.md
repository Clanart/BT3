### Title
Unbounded HTTP request body read in NewRelic/Datadog RPC middleware bypasses `MaxRequestContentLength` - ([File: networks/rpc/http_newrelic.go])

### Summary
When APM tracing is enabled (`NEWRELIC_APP_NAME`/`NEWRELIC_LICENSE` or `DD_TRACE_ENABLED`), every JSON-RPC HTTP request is first routed through `getRPCRequests`, which reads the entire request body into memory with `io.ReadAll(r.Body)` with no size bound at all, before the normal `MaxRequestContentLength` enforcement (`validateRequest` + `io.LimitReader`) ever runs on the same body. This is directly analogous to the Django ASGI bug where the body-size guard (`DATA_UPLOAD_MAX_MEMORY_SIZE`) is bypassed because the framework buffers/loads the body into memory before the length check is meaningfully applied.

### Finding Description
The Kaia JSON-RPC HTTP server enforces a maximum request size (`common.MaxRequestContentLength`, default 512 KiB) in two places on the "normal" path:
- `validateRequest` rejects requests whose declared `Content-Length` exceeds the limit [1](#0-0) 
- `newHTTPServerConn` wraps `r.Body` in `io.LimitReader(r.Body, common.MaxRequestContentLength)` so that even if `Content-Length` is missing/wrong, actual bytes read are capped [2](#0-1) 

However, when either NewRelic or Datadog tracing is enabled, `NewHTTPServer`/`NewFastHTTPServer` wrap the handler chain with `newNewRelicHTTPHandler`/`newDatadogHTTPHandler`, which run **before** the inner `Server.ServeHTTP` (and thus before `validateRequest`/`io.LimitReader` execute) [3](#0-2) . Both wrappers immediately call `getRPCRequests(r)` to extract the RPC method name for tracing/logging purposes [4](#0-3) [5](#0-4) .

`getRPCRequests` reads the full body with no size limit whatsoever: [6](#0-5) 

Because this read happens unconditionally and unbounded, regardless of what `Content-Length` claims (missing, understated, or simply larger than the configured cap), the entire attacker-controlled body is buffered in memory before any size check is applied — the size check in `validateRequest` only fires afterward inside the wrapped `handler.ServeHTTP(dupW, r)` call, by which point the damage (full in-memory buffering) is already done.

### Impact Explanation
Any unauthenticated remote caller of the public JSON-RPC HTTP endpoint can send an arbitrarily large POST body (limited only by available memory/network bandwidth, not by `MaxRequestContentLength`) whenever the node operator has enabled NewRelic or Datadog APM tracing. This defeats the intended `DATA_UPLOAD_MAX_MEMORY_SIZE`-equivalent protection (`MaxRequestContentLength`) and can be used to exhaust node memory, causing degraded RPC availability or crashes (CWE-770, Allocation of Resources Without Limits), impacting a node's ability to serve legitimate transaction submissions/reads.

### Likelihood Explanation
Likelihood is high for nodes running with APM tracing enabled (a supported, documented operational configuration, not a malicious-operator scenario) since the bypass requires zero authentication or special permissions — any public RPC caller can trigger it with a single oversized POST request. On nodes without NewRelic/Datadog enabled, this specific path is not reachable, but the underlying pattern (calling `getRPCRequests`'s unbounded `io.ReadAll` ahead of the size-checked path) is a structural bug in the code regardless of feature flag.

### Recommendation
Enforce the `MaxRequestContentLength` cap (e.g., via `io.LimitReader` or an explicit `http.MaxBytesReader`) inside `getRPCRequests` before calling `io.ReadAll`, so the APM tracing wrappers never buffer more than the configured limit regardless of `Content-Length` header correctness. Alternatively, move `validateRequest`'s size check to run before the tracing wrappers touch the body.

### Proof of Concept
1. Start a Kaia node with `NEWRELIC_APP_NAME`/`NEWRELIC_LICENSE` (or `DD_TRACE_ENABLED=true`) set, exposing the JSON-RPC HTTP endpoint publicly.
2. Send a POST request to the RPC endpoint with either no `Content-Length` (chunked transfer-encoding) or a small/absent declared length but a very large actual body (e.g., several GB of JSON padding).
3. `newNewRelicHTTPHandler`/`newDatadogHTTPHandler` call `getRPCRequests(r)` which executes `io.ReadAll(r.Body)`, buffering the entire multi-GB payload in memory before `validateRequest`'s `Content-Length` check or `newHTTPServerConn`'s `io.LimitReader` ever executes.
4. Repeating this with concurrent requests exhausts node memory, causing degraded service or a crash — despite `MaxRequestContentLength` being configured to a small value (default 512 KiB).

func NewHTTPServer(cors []string, vhosts []string, timeouts HTTPTimeouts, srv http.Handler) *http.Server {
	timeouts = sanitizeTimeouts(timeouts)
	// Wrap the CORS-handler within a host-handler
	handler := newCorsHandler(srv, cors)
	handler = newVHostHandler(vhosts, handler)
	handler = http.TimeoutHandler(handler, timeouts.ExecutionTimeout, "timeout")

	// If os environment variables for NewRelic exist, register the NewRelicHTTPHandler
	nrApp := newNewRelicApp()
	if nrApp != nil {
		handler = newNewRelicHTTPHandler(nrApp, handler)
	}

	// If os environment variables for Datadog exist, register the NewDatadogHTTPHandler
	ddTracer := newDatadogTracer()
	if ddTracer != nil {
		handler = newDatadogHTTPHandler(ddTracer, handler)
	}

	return &http.Server{
		Handler:      handler,
		ReadTimeout:  timeouts.ReadTimeout,
		WriteTimeout: timeouts.WriteTimeout,
		IdleTimeout:  timeouts.IdleTimeout,
	}
}

func validateRequest(r *http.Request) (int, error) {
	if r.Method == http.MethodPut || r.Method == http.MethodDelete {
		return http.StatusMethodNotAllowed, errors.New("method not allowed")
	}
	if r.ContentLength > int64(common.MaxRequestContentLength) {
		err := fmt.Errorf("content length too large (%d>%d)", r.ContentLength, int64(common.MaxRequestContentLength))
		return http.StatusRequestEntityTooLarge, err
	}

func getRPCRequests(r *http.Request) ([]*jsonrpcMessage, bool, error) {
	reqBody, err := io.ReadAll(r.Body)
	if err != nil {
		logger.Error("cannot read a request body", "err", err)
		return nil, false, err
	}

	r.Body = io.NopCloser(bytes.NewReader(reqBody))
	conn := &httpServerConn{Reader: io.NopCloser(bytes.NewReader(reqBody)), Writer: bytes.NewBufferString(""), r: r}

	codec := NewCodec(conn)

	defer codec.close()

	return codec.readBatch()
}
