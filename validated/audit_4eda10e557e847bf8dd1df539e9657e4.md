### Title
Out-of-bounds slice panic in `consoleLog.decode` via negative offset from truncated `big.Int.Int64()` conversion - (File: blockchain/vm/contracts.go)

### Summary
The `CONSOLE_LOG` precompiled contract's parameter decoder computes string/bytes offsets by truncating a 256-bit big integer to `int64` and then to Go's native `int`, without validating that the resulting value is non-negative. A crafted `StringTy`/`BytesTy` offset word can produce a negative `start`, which bypasses the existing length checks and causes a Go slice expression with a negative index, triggering an unrecoverable runtime panic.

### Finding Description
`consoleLog.decode` is reached from `consoleLog.Run`, which is invoked whenever any address calls the `CONSOLE_LOG` precompiled contract during EVM execution [1](#0-0) . For `StringTy` and `BytesTy` arguments, the function extracts a 32-byte offset word from the calldata and converts it via `big.NewInt(0).SetBytes(...).Int64()` into a Go `int`: [2](#0-1) 

`big.Int.Int64()` is documented to return an undefined/truncated result when the value does not fit in an `int64`. Because the offset word is fully attacker-controlled (up to 32 bytes / 256 bits), an attacker can choose a value whose low 64 bits, interpreted as signed, are negative (e.g. any value with bit 63 set, such as `0xFFFFFFFFFFFFFFFF...`). This makes `start` negative.

The subsequent bounds check `if len(params) < start+registerSize` uses ordinary integer comparison: when `start` is a large negative number, `start+registerSize` is also negative, and `len(params) (non-negative) < negative-number` is always false, so the check is bypassed. Execution then reaches `params[start : start+registerSize]` with a negative `start`, which is not a valid Go slice bound and causes an immediate runtime panic (`slice bounds out of range`) rather than a benign error return. The identical pattern exists in the `BytesTy` branch [3](#0-2) .

This mirrors the CVE-2018-7455 bug class: a parser trusts an attacker-supplied length/offset field without validating its sign/range before using it to index a buffer, leading to an out-of-bounds access from malformed input.

### Impact Explanation
`CONSOLE_LOG` is registered as a reachable precompiled contract in the EVM's precompile table, invoked through the normal `RunPrecompiledContract`/interpreter call path [4](#0-3) . Any unprivileged externally-owned account can trigger this code path simply by sending a transaction (or having a contract make a call) to the `CONSOLE_LOG` address with a crafted calldata payload matching one of the entries in `common.ConsoleLogSignatures` that contains a `string`/`bytes` parameter. I was unable to fully confirm, within the available context, whether a higher layer (e.g. state transition or block processing) wraps EVM execution in a `recover()` that would contain this panic; no `recover()` calls were found within `blockchain/vm/evm.go` or `blockchain/vm/interpreter.go` in the areas inspected. If the panic is not recovered before it unwinds out of transaction/block processing, this becomes a node-crashing denial-of-service reachable by any transaction sender, which fits the required "Medium" severity threshold for a reachable, transaction-triggered DoS.

### Likelihood Explanation
High/likely: exploitation requires only crafting a single transaction's calldata to call the `CONSOLE_LOG` precompile with an out-of-range offset word — no special privileges, staking, or governance access needed, and no dependency on network timing or races.

### Recommendation
Validate that `start` (and `size`) are within `[0, len(params)]` immediately after computing them from `Int64()`, and reject the input as malformed instead of proceeding — e.g., check `start < 0 || size < 0` and also guard against integer overflow in `start+size+registerSize` (currently additive overflow of `int` is also unchecked) before performing any slicing operation, for both the `StringTy` and `BytesTy` branches in `consoleLog.decode` [5](#0-4) .

### Proof of Concept
1. Identify (or pick) a selector in `common.ConsoleLogSignatures` whose type list contains `common.StringTy` or `common.BytesTy`.
2. Build calldata: 4-byte selector + register words, where the offset word for the string/bytes argument encodes a 32-byte big-endian value whose low 8 bytes have the top bit set (e.g. `0xFFFFFFFFFFFFFFFF80` pattern truncated appropriately so `Int64()` yields a negative `int64`).
3. Submit a transaction that calls the `CONSOLE_LOG` precompile address with this calldata (directly, or via a contract that forwards the call).
4. During EVM execution, `consoleLog.decode` computes a negative `start`, bypasses the `len(params) < start+registerSize` check, and executes `params[start : start+registerSize]`, causing a Go runtime panic (`slice bounds out of range`) inside transaction execution [6](#0-5) .
