### Title
Unregistered-chain fallback to `address(this)` in `instance()` lets a forged source chain pass escrow authentication - ([File: evm/tron/contracts/apps/IntentGatewayV2.sol])

### Summary
The Tron variant of `IntentGatewayV2` resolves peer-gateway addresses with a silent fallback to `address(this)` instead of reverting on an unregistered chain, unlike the EVM/mainline implementation. Because escrow-redemption messages are authenticated by comparing the inbound `request.from` against this `instance()` lookup, a message arriving from *any* state machine that has never been registered as a peer is treated as authentic as long as its `from` field equals this same fixed address — which is trivially satisfiable given that `IntentGatewayV2` deployments are explicitly designed to share the same address across chains via deterministic CREATE2.

### Finding Description
`instance()` in the Tron contract is: [1](#0-0) 

```solidity
function instance(bytes calldata stateMachineId) public view returns (address) {
    address gateway = _instances[keccak256(stateMachineId)];
    return gateway == address(0) ? address(this) : gateway;
}
```

`authenticate()` uses this lookup as the sole authorization gate for privileged escrow operations: [2](#0-1) 

```solidity
function authenticate(PostRequest calldata request) internal view {
    if (request.from.length != 20) revert InvalidInput();
    address module = address(bytes20(request.from));
    // IntentGateway only accepts incoming assets from itself or known instances
    if (instance(request.source) != module) revert Unauthorized();
}
```

And `onAccept()` calls `authenticate()` directly for `RedeemEscrow`/`RefundEscrow`, which release escrowed funds: [3](#0-2) 

For any `stateMachineId` that has never had a `NewDeployment` recorded, `_instances[keccak256(stateMachineId)]` is the zero-initialized default, so `instance()` returns `address(this)` — the gateway's own address — instead of reverting. This directly contradicts the design intent documented in the sibling (mainline EVM) implementation, whose `initialize()` comment states: *"`_instance` reverts with `UnknownInstance` for any chain not registered here or later via `onAccept` governance"*, and whose deployments are explicitly bound to `address(this)` and are **identical across chains under deterministic CREATE2**: [4](#0-3) 

Combining these two facts: since `IntentGatewayV2` is deployed at the same address on every chain via CREATE2, an attacker who deploys any contract (or the same bytecode) at that identical address on a chain that Hyperbridge has *not yet registered as a peer* for this gateway can dispatch a POST request whose `from` field is naturally `address(this)`. On the Tron gateway, `authenticate(request)` will compute `instance(request.source) == address(this)` (the fallback) and `module == address(this)` (the attacker's contract address, identical by CREATE2) — the equality holds, and the message is treated as coming from a legitimate registered peer.

This is the same broken-invariant class as the external report: a guard meant to be "authenticate only against explicitly registered/trusted counterparts" instead falls back to an always-true condition ("== self") for the unregistered/default case, silently authorizing calls that should be rejected.

### Impact Explanation
`RedeemEscrow` and `RefundEscrow` messages that pass `authenticate()` call `_withdraw`/`withdraw`, which releases ERC-20/native tokens held in escrow to an attacker-chosen beneficiary: [5](#0-4) 

An attacker satisfying the forged-source condition can drain any outstanding escrow balances tracked in `_orders[commitment][token]` for arbitrary commitments, since `withdraw()` only checks that `_orders[body.commitment][token] != 0`, not that the commitment corresponds to a legitimately-filled or cancelled order from a real peer. This is unauthorized transaction execution and direct loss of escrowed user/solver funds — matching the bounty's "stealing or loss of funds" and "false proof/state acceptance" categories, since the Host-level consensus/state proof only attests that *some* message was included in *some* unregistered chain's state, not that the module dispatching it is the real gateway.

### Likelihood Explanation
Exploitation requires only: (1) Hyperbridge relaying a message from a chain that is technically connected/provable via ISMP consensus but has not yet had `NewDeployment` executed for this specific gateway (a normal, expected pre-registration state during rollout to new chains), and (2) the attacker controlling a contract at the CREATE2-predicted `address(this)` on that chain — achievable by deploying the known `IntentGatewayV2` bytecode (or any minimal contract) there before the real deployment/registration happens, or by targeting any state machine ISMP already trusts but that this application has not onboarded. No malicious relayer, prover, or admin action is needed — it is an unprivileged attacker exploiting the default-mapping-value confusion.

### Recommendation
Change `instance()` in `evm/tron/contracts/apps/IntentGatewayV2.sol` to revert (e.g., `revert UnknownInstance()`) when `_instances[keccak256(stateMachineId)] == address(0)`, mirroring the mainline `_instance()` behavior in `IntentsBase.sol`/`evm/src/apps/IntentGatewayV2.sol`. Never treat an unregistered peer as implicitly equal to `address(this)`.

### Proof of Concept
1. Identify a state machine ID `X` for which the Tron `IntentGatewayV2` has no `NewDeployment` entry (`_instances[keccak256(X)] == address(0)`).
2. Deploy (or reuse) a contract at the CREATE2-predicted address of `IntentGatewayV2` on chain `X`, exploiting the documented deterministic-address deployment scheme.
3. From that contract, dispatch an ISMP POST request to the Tron gateway with `source = X`, `from = address(this)` (the shared gateway address), `body = RedeemEscrow || abi.encode(WithdrawalRequest{commitment: <victim commitment>, tokens: <victim's escrowed tokens>, beneficiary: <attacker>})`.
4. Once relayed and proven at the ISMP Host layer (a legitimate state proof from chain `X`, since ISMP itself doesn't validate application-level peer identity), `onAccept()` invokes `authenticate()`, which calls `instance(X)`, returns `address(this)` (fallback), matches `module == address(this)`, and passes.
5. `withdraw()` executes, transferring the victim's escrowed tokens to the attacker's beneficiary address.

    /**
     * @notice Withdraws the escrowed tokens for a request body.
     * @dev This function is marked as internal.
     * @param body The request body containing commitment, tokens, and beneficiary.
     * @param isRefund Whether this is a refund (true) or a successful fill (false).
     */
    function withdraw(WithdrawalRequest memory body, bool isRefund) internal {
        address beneficiary = address(uint160(uint256(body.beneficiary)));
        _filled[body.commitment] = beneficiary;

        // redeem escrowed tokens
        uint256 len = body.tokens.length;
        for (uint256 i; i < len;) {
            address token = address(uint160(uint256(body.tokens[i].token)));
            uint256 amount = body.tokens[i].amount;
            if (_orders[body.commitment][token] == 0) revert UnknownOrder();

            if (token == address(0)) {
                (bool sent,) = beneficiary.call{value: amount}("");
                if (!sent) revert InsufficientNativeToken();
            } else {
                (bool success,) = token.call(abi.encodeWithSelector(IERC20.transfer.selector, beneficiary, amount));
                if (!success) revert TransferFailed();
            }

            _orders[body.commitment][token] -= amount;
            unchecked {
                ++i;
            }
        }

        // redeem tx fees
        uint256 fees = _orders[body.commitment][TRANSACTION_FEES];
        if (fees > 0) {
            address feeToken = IDispatcher(host()).feeToken();
            (bool success,) = feeToken.call(abi.encodeWithSelector(IERC20.transfer.selector, beneficiary, fees));
            if (!success) revert TransferFailed();
            delete _orders[body.commitment][TRANSACTION_FEES];
        }

        if (isRefund) {
            emit EscrowRefunded({commitment: body.commitment});
        } else {
            emit EscrowReleased({commitment: body.commitment});
        }
    }
