Based on my investigation, I found a concrete analog in `pallet-consensus-incentives`.

### Title
First-ever consensus reward on a state machine pays for its entire pre-registration height span - ([File: modules/pallets/consensus-incentives/src/impls.rs])

### Summary
`store_latest_commitment_height` initializes `PreviousStateMachineHeight` from `LatestStateMachineHeight::<T>::get(id).unwrap_or_default()` [1](#0-0)  — so the very first time a state machine is updated, the "previous" height recorded is `0`, regardless of what height that chain's client was actually initialized at (chains typically bootstrap at a nonzero height). `calculate_reward` in the consensus-incentives pallet uses this value as the fallback baseline for a state machine's first-ever payout: `let baseline = LastRewardedHeight::<T>::get(state_machine_id).unwrap_or(previous_height);` where `previous_height` itself falls back to `0` via `previous_commitment_height(...).unwrap_or_default()` [2](#0-1) . This is structurally the same defect class as the OTLM `stake()` bug: a "last checkpoint" value that is not properly seeded on first use, defaulting to `0`/genesis instead of the caller's actual starting point.

### Finding Description
`process_message` computes `reward = calculate_reward(&state_machine_id, block_cost)` and pays it unconditionally from the treasury to whichever relayer's message triggers the `StateMachineUpdated` event [3](#0-2) . `calculate_reward` is:
```
let latest_height = host.latest_commitment_height(...)
let previous_height = host.previous_commitment_height(...).unwrap_or_default();
let baseline = LastRewardedHeight::<T>::get(state_machine_id).unwrap_or(previous_height);
let blocks = latest_height.saturating_sub(baseline);
let reward = blocks * block_cost;
```
`LastRewardedHeight` is `None` until the pallet pays out at least once for that `state_machine_id` [4](#0-3) . On the very first reward for a newly-added state machine (e.g. right after `update_cost_per_block` is called by governance to enable incentives for a chain that has already been running / already has an advanced consensus client), `previous_commitment_height` will be whatever `PreviousStateMachineHeight` holds — and per `store_latest_commitment_height`, that value only reflects the height stored the *previous time an update was recorded on this pallet instance*, defaulting to `0` if the state machine had never previously called `store_latest_commitment_height`. If a state machine's client is bootstrapped directly at a high starting height (common for parachains/rollups whose consensus client is initialized mid-flight rather than from genesis), the first `StateMachineUpdated` event after incentives are turned on computes `blocks = latest_height - 0 = latest_height`, and the relayer is paid `block_cost * latest_height` from the treasury for a span of blocks nobody actually relayed incrementally — potentially the chain's entire height history.

This mirrors exactly the sherlock bug's root cause: a per-entity "last-processed" checkpoint defaulting to zero on the entity's first appearance, rather than being seeded to its actual starting reference point (there, `epoch - 1`; here, the state machine's initialization height).

### Impact Explanation
This causes an unbounded, one-time treasury drain: `T::Currency::transfer(&Treasury, &relayer_account, block_cost * latest_height, ...)` [5](#0-4) . Since `block_cost` and `state_machine_id` are governance-configured but the relayer account and the trigger message are attacker-controlled (any relayer submitting a valid consensus message can trigger `process_message`), an attacker relaying the first-ever incentivized update for a freshly onboarded high-height chain can extract funds vastly exceeding the actual relaying cost being subsidized. This is a fund-loss / incorrect-beneficiary-amount bug against the live treasury, not merely a gas/DoS issue.

### Likelihood Explanation
Likelihood depends on operational sequencing: it requires governance to call `update_cost_per_block` for a state machine whose consensus client was already initialized at (or has already advanced to) a nonzero height before that call, and for `LastRewardedHeight`/`PreviousStateMachineHeight` to not have been previously populated for that `state_machine_id`. This is plausible during onboarding of a new chain to incentives, or when incentives are re-enabled for a state machine after `remove_incentives` was called (which does not clear `LastRewardedHeight`, but a *brand-new* `state_machine_id` — e.g., after a consensus-state-id change — would have neither watermark set). I could not fully verify from the available code whether `PreviousStateMachineHeight` is guaranteed to be populated to a realistic nonzero baseline at consensus-client initialization time elsewhere in the codebase (e.g., in `pallet-ismp`'s client add flow); this would need confirmation via a Devin session with full repository access, since the wiki-index search did not surface the exact call site that seeds a new consensus client's initial height into `PreviousStateMachineHeight`/`LatestStateMachineHeight`.

### Recommendation
When enabling incentives for a state machine whose `LastRewardedHeight` is `None`, do not fall back to `previous_commitment_height` (which can be `0` for a never-before-rewarded chain). Instead, seed the baseline to `latest_commitment_height` at the time incentives are first configured (i.e., `update_cost_per_block`), or explicitly initialize `LastRewardedHeight` for the state machine in that same call, so the first payable reward only covers blocks moved after incentives are turned on — mirroring the confirmed OTLM fix pattern of seeding the checkpoint to "current position minus nothing owed yet" rather than defaulting to zero.

### Proof of Concept
1. Governance never previously called `update_cost_per_block` or received any `StateMachineUpdated` reward for `state_machine_id = X` (fresh consensus client, or one initialized off-chain at height `H_init >> 0`).
2. `LatestStateMachineHeight` / `PreviousStateMachineHeight` for `X` have never been touched by `store_latest_commitment_height`, so `previous_commitment_height(X)` returns `None` → `unwrap_or_default()` = `0` [6](#0-5) .
3. Governance calls `update_cost_per_block(X, block_cost)` to enable incentives.
4. Any relayer submits a normal consensus update message advancing `X` to `latest_height = H_init` (or higher). This fires `StateMachineUpdated { state_machine_id: X, latest_height }`.
5. `on_executed` → `process_message` → `calculate_reward`: `baseline = LastRewardedHeight::get(X).unwrap_or(previous_height=0)` → `blocks = latest_height - 0 = latest_height` → `reward = latest_height * block_cost`, paid entirely to that relayer from the treasury in one shot [7](#0-6) , then `LastRewardedHeight` is finally set to `latest_height` [8](#0-7) .

```rust
	fn store_latest_commitment_height(&self, height: StateMachineHeight) -> Result<(), Error> {
		let previous_height = LatestStateMachineHeight::<T>::get(height.id).unwrap_or_default();
		PreviousStateMachineHeight::<T>::insert(height.id, previous_height);
		LatestStateMachineHeight::<T>::insert(height.id, height.height);
		Ok(())
	}
```

```rust
	fn process_message(
		state_machine_height: StateMachineHeight,
		state_machine_id: StateMachineId,
		relayer_account: T::AccountId,
	) -> Result<(), Error<T>> {
		if let Some(block_cost) = StateMachinesCostPerBlock::<T>::get(state_machine_id) {
			let reward = Self::calculate_reward(&state_machine_id, block_cost)?;

			if reward.is_zero() {
				return Ok(());
			}

			T::Currency::transfer(
				&T::TreasuryAccount::get().into_account_truncating(),
				&relayer_account,
				reward,
				Preservation::Expendable,
			)
			.map_err(|_| Error::<T>::RewardTransferFailed)?;

			Self::deposit_event(Event::<T>::RelayerRewarded {
				relayer: relayer_account.clone(),
				amount: reward,
				state_machine_height,
			});

			T::ReputationAsset::mint_into(&relayer_account, reward.saturated_into())
				.map_err(|_| Error::<T>::ReputationMintFailed)?;

			LastRewardedHeight::<T>::mutate(state_machine_id, |watermark| {
				*watermark = Some(watermark.unwrap_or_default().max(state_machine_height.height));
			});
		}
		Ok(())
	}
```
