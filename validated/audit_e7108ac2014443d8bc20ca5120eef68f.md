## Analog Found

### Title
CosmWasm ERC721 transfer-payload precompile only builds unsafe `transferFrom` calldata, forcing CW⇄EVM NFT bridges to move ERC721 pointer tokens without receiver checks - (File: x/evm/client/wasm/query.go)

### Summary
The Sei EVM/Wasm bridge exposes a precompile query, `erc721_transfer_payload`, that CosmWasm contracts use to build calldata for moving an ERC721 token that is wrapped/pointed by a CW721 contract. The handler for this query, `HandleERC721TransferPayload`, unconditionally packs the ABI selector for the *unsafe* `transferFrom(address,address,uint256)` method rather than any `safeTransferFrom` variant, and the wasm bindings (`SeiEVMQuery`) expose no safe-transfer equivalent at all.

### Finding Description
`HandleERC721TransferPayload` resolves the EVM addresses associated with the sender/recipient Sei addresses and packs the `transferFrom` selector via the CW721/ERC721 ABI: [1](#0-0) 

This is the only ERC721-transfer payload builder surfaced through the wasm query bindings — there is no `ERC721SafeTransferPayload` (or similarly named) request type in the `SeiEVMQuery` struct, only `ERC721TransferPayload`: [2](#0-1) 

A CosmWasm contract that needs to move a pointer-wrapped ERC721 token on behalf of a user (for example, the `transfer_nft` handler of a CW721 wrapper contract) is therefore forced to build its EVM delegatecall using this unsafe `transferFrom` payload, as demonstrated in the example CW721 contract: [3](#0-2) 

The same unsafe pattern is mirrored on the EVM side: the generated `CW721ERC721Pointer.sol` contract only implements/overrides `transferFrom` for actually forwarding the token move to the underlying CW721 contract via `transfer_nft`; there is no override of `safeTransferFrom` that performs the same forwarding with an `onERC721Received` check on the real recipient: [4](#0-3) 

Because the recipient of a CW721↔EVM NFT transfer is derived purely from address association (`GetEVMAddress`) rather than any capability check, if the resolved EVM address happens to be a contract that does not implement `onERC721Received` (e.g., a smart-contract wallet, multisig, or unrelated contract that merely has an address association), the token is transferred there anyway with no revert and no recovery path through this bridge.

### Impact Explanation
An NFT moved through this CW721→ERC721 bridge path can become permanently stuck at a contract address that cannot handle ERC721 tokens, since the bridge/precompile gives wasm contract authors no way to perform a safe transfer, and the EVM-side pointer's own `transferFrom` override does not perform receiver validation either. This is a permanent loss/freezing of a specific NFT asset, reachable by any ordinary user or CosmWasm contract author who triggers a CW⇄EVM NFT transfer to an address whose associated EVM address is an incompatible contract.

### Likelihood Explanation
Medium likelihood: it requires the recipient's Sei↔EVM address association to resolve to a contract without `onERC721Received` support. This is plausible in practice since address associations on Sei can point to arbitrary deployed contracts, and the transfer path offers no alternative safe method for wasm-side integrators to protect end users, unlike the equivalent ERC20 flow (which has no receiver-capability constraint to begin with).

### Recommendation
Add a safe-transfer variant to the wasm binding surface (e.g., `ERC721SafeTransferPayload`) that packs `safeTransferFrom`, and have `HandleERC721TransferPayload`-consumers (including the example/production CW721↔ERC721 bridge contracts) use it. Additionally, override `safeTransferFrom` in `CW721ERC721Pointer.sol` to route through `_execute`/`transfer_nft` with an explicit receiver check on `to`, consistent with the unsafe `transferFrom` override.

### Proof of Concept
1. Associate a Sei address with the EVM address of a plain contract that does not implement `IERC721Receiver` (e.g., a vault, timelock, or arbitrary contract with no `onERC721Received`).
2. From a CosmWasm CW721 wrapper contract (as in `example/cosmwasm/cw721/src/contract.rs`'s `transfer_nft`), call `transfer_nft` targeting that Sei address as recipient.
3. The contract queries `erc721_transfer_payload`, which encodes `transferFrom(owner, resolvedEvmAddr, tokenId)` and executes it via `DelegateCallEvm`.
4. The transfer succeeds since `transferFrom` performs no receiver check; the NFT is now owned by a contract with no way to move it back out, permanently locking the asset.

func (h *EVMQueryHandler) HandleERC721TransferPayload(ctx sdk.Context, from string, recipient string, tokenId string) ([]byte, error) {
	abi, err := cw721.Cw721MetaData.GetAbi()
	if err != nil {
		return nil, err
	}
	fromEvmAddr, found := h.k.GetEVMAddress(ctx, sdk.MustAccAddressFromBech32(from))
	if !found {
		return nil, types.NewAssociationMissingErr(from)
	}
	toEvmAddr, found := h.k.GetEVMAddress(ctx, sdk.MustAccAddressFromBech32(recipient))
	if !found {
		return nil, types.NewAssociationMissingErr(recipient)
	}
	t, ok := sdk.NewIntFromString(tokenId)
	if !ok {
		return nil, errors.New("invalid token ID for ERC721, must be a big Int")
	}
	bz, err := abi.Pack("transferFrom", fromEvmAddr, toEvmAddr, t.BigInt())
	if err != nil {
		return nil, err
	}
	res := bindings.ERCPayloadResponse{EncodedPayload: base64.StdEncoding.EncodeToString(bz)}
	return json.Marshal(res)
}

fn transfer_nft(
    deps: DepsMut<EvmQueryWrapper>,
    info: &MessageInfo,
    recipient: &str,
    token_id: &str,
) -> Result<Response<EvmMsg>, ContractError> {
    deps.api.addr_validate(recipient)?;

    let erc_addr = ERC721_ADDRESS.load(deps.storage)?;

    let querier = EvmQuerier::new(&deps.querier);
    let owner = querier.erc721_owner(info.sender.to_string(), erc_addr.to_string(), token_id.to_string())?.owner;
    let payload = querier.erc721_transfer_payload(owner, recipient.to_string(), token_id.to_string())?;
    let msg = EvmMsg::DelegateCallEvm { to: erc_addr, data: payload.encoded_payload };
    let res = Response::new().add_message(msg);

    Ok(res)
}

    // Transactions
    function transferFrom(address from, address to, uint256 tokenId) public override {
        if (to == address(0)) {
            revert ERC721InvalidReceiver(address(0));
        }
        require(from == ownerOf(tokenId), "`from` must be the owner");
        string memory recipient = _formatPayload("recipient", _doubleQuotes(AddrPrecompile.getSeiAddr(to)));
        string memory tId = _formatPayload("token_id", _doubleQuotes(Strings.toString(tokenId)));
        string memory req = _curlyBrace(_formatPayload("transfer_nft", _curlyBrace(_join(recipient, tId, ","))));
        _execute(bytes(req));
    }
