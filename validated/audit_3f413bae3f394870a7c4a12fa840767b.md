### Title
DataLayer HTTP server reads and returns delta/full-tree files without checking for symlinks, allowing arbitrary local file disclosure - (File: chia/data_layer/data_layer_server.py)

### Summary
`DataLayerServer.file_handler` and `DataLayerServer.folder_handler` build a filesystem path under `server_dir` from a client-supplied filename, validate only that the *string* matches the DataLayer filename grammar, and then directly `open()` and stream back whatever is at that path. Neither handler checks whether the resolved path is a symlink or whether it stays inside `server_files_location`. This mirrors the DBD::File CVE pattern exactly: `complete_table_name` in the CVE builds an absolute path without verifying it isn't a symlink to an untrusted location, letting callers read/write files outside the intended data directory. The same missing-symlink-check happens in `chia/data_layer/data_layer_server.py`.

### Finding Description
`file_handler` and `folder_handler` are the routes registered for the DataLayer HTTP static-file server: [1](#0-0) 

Both handlers validate only the filename's *format* via `is_filename_valid()` (hex store id/hash, `-delta-`/`-full-`, generation, version suffix) and then join it onto `self.server_dir` and open it for reading: [2](#0-1) 

`is_filename_valid()` only re-derives the expected filename string from its component hex fields and compares strings — it performs no filesystem check at all, so it cannot detect that the on-disk entry at that path is a symlink: [3](#0-2) 

Per the module's own design notes, DataLayer treats mirror/plugin-served content as untrusted input that must be re-verified, and explicitly flags file path/name validation as a hotspot that "must stay strict," while also noting the static server "assumes files are already written under `server_files_location` by the service or plugin" and does direct synchronous reads: [4](#0-3) 

If any entry inside `server_files_location` (or the grouped-by-store subdirectory keyed by `tree_id`) is replaced with a symlink pointing outside that directory — whether by a compromised/misbehaving downloader plugin, a race during subscription file management, or local filesystem access by another process sharing the DataLayer service directory — a subsequent HTTP GET to `/{filename}` or `/{tree_id}/{filename}` will silently follow that symlink and return the target file's contents to the requester with a `Content-Disposition: attachment` header, exactly as if it were a legitimate DataLayer delta/full-tree file.

### Impact Explanation
Any local or remote HTTP client of the DataLayer file server (this endpoint is what mirrors/other DataLayer nodes fetch delta/full files from) can retrieve arbitrary files reachable by the DataLayer process's file permissions once a symlink is planted in the server directory — e.g. SSL private keys, wallet DB, or other config/secret files under the DataLayer service's root path — without any additional authorization check, since `file_handler`/`folder_handler` perform no ownership/symlink validation before reading and streaming file contents.

### Likelihood Explanation
The likelihood of an attacker planting the symlink is the main uncertainty (marked below), but the missing safety check itself is concrete and directly analogous to the reported CVE: `is_filename_valid()` is a pure string check, and neither `file_handler` nor `folder_handler` calls `Path.is_symlink()`, `os.path.realpath()`, or otherwise confirms the resolved file stays within `server_dir` before opening it. Given that DataLayer's own design doc treats plugin/mirror-written files as untrusted and flags this exact area ("file path/name validation must stay strict") as fragile, this is a real, currently-unenforced invariant gap in the reachable HTTP file-serving path, not a hypothetical.

### Recommendation
Before opening any requested file in `file_handler`/`folder_handler`, resolve the path with `Path.resolve()` and verify it is still contained within `self.server_dir` (and its immediate `tree_id` subdirectory for the folder handler), and reject the request if `Path.is_symlink()` is true for the target or any path component. Apply the same symlink/containment check anywhere DataLayer or its plugins write files into `server_files_location` (e.g. `write_files_for_root`, `http_download`, and the S3 plugin's `get_path_for_filename`/`download`) so a symlink can never be substituted for a real delta/full-tree file.

### Proof of Concept
1. Obtain the ability to write one file into the DataLayer server's `server_files_location` directory (e.g. via a compromised/malicious downloader plugin that is expected to only write validated delta/full files, or via any other process sharing that directory).
2. Instead of writing real tree-file bytes, create a symlink at a validly-named path, e.g.:
   `ln -s /home/user/.chia/mainnet/config/ssl/wallet/private_wallet.key <server_files_location>/<store_id>-<node_hash>-full-<generation>-v1.0.dat`
3. Send `GET http://<datalayer-host>:<port>/<store_id>-<node_hash>-full-<generation>-v1.0.dat` to the DataLayer HTTP server.
4. `file_handler` passes `is_filename_valid()` (it is only checking the string format) and `open(file_path, "rb")` follows the symlink, returning the private key file's contents in the HTTP response body.

**Uncertainty:** I could not fully verify within the indexed code how easily an untrusted party can place an arbitrary symlink into `server_files_location` in this codebase version (e.g., whether S3-plugin `download_file`/`http_download` could ever be tricked into creating a symlink rather than writing bytes, or whether the grouped-by-store directory creation path has a TOCTOU window). The core defect — `file_handler`/`folder_handler` never check for symlinks before reading — is confirmed directly from source; the exact write-side vector for planting the symlink needs further confirmation via a live Devin session with full repo access.

```python
    async def file_handler(self, request: web.Request) -> web.Response:
        filename = request.match_info["filename"]
        if not is_filename_valid(filename):
            raise Exception("Invalid file format requested.")
        file_path = self.server_dir.joinpath(filename)
        with open(file_path, "rb") as reader:
            content = reader.read()
        response = web.Response(
            content_type="application/octet-stream",
            headers={"Content-Disposition": f"attachment;filename={filename}"},
            body=content,
        )
        return response

    async def folder_handler(self, request: web.Request) -> web.Response:
        tree_id = request.match_info["tree_id"]
        filename = request.match_info["filename"]
        if not is_filename_valid(tree_id + "-" + filename):
            raise Exception("Invalid file format requested.")
        file_path = self.server_dir.joinpath(tree_id).joinpath(filename)
        with open(file_path, "rb") as reader:
            content = reader.read()
        response = web.Response(
            content_type="application/octet-stream",
            headers={"Content-Disposition": f"attachment;filename={filename}"},
            body=content,
        )
        return response
```

```python
def is_filename_valid(filename: str, group_by_store: bool = False) -> bool:
    if group_by_store:
        if filename.count("/") != 1:
            return False
        filename = filename.replace("/", "-")

    split = filename.split("-")

    try:
        raw_store_id, raw_node_hash, file_type, raw_generation, raw_version, *rest = split
        store_id = bytes32(bytes.fromhex(raw_store_id))
        node_hash = bytes32(bytes.fromhex(raw_node_hash))
        generation = int(raw_generation)
    except ValueError:
        return False

    if len(rest) > 0:
        return False

    # TODO: versions should probably be centrally defined
    if raw_version != "v1.0.dat":
        return False

    if file_type not in {"delta", "full"}:
        return False

    generate_file_func = get_delta_filename if file_type == "delta" else get_full_tree_filename
    reformatted = generate_file_func(
        store_id=store_id, node_hash=node_hash, generation=generation, group_by_store=False
    )

    return reformatted == filename

```
