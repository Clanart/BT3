## Title
Spoofable `WWW-Authenticate` realm header lets a malicious git remote force GitHub Desktop's trusted "Sign in" / OAuth flow against an unverified attacker host — (`File: app/src/lib/trampoline/trampoline-credential-helper.ts`)

## Summary
The Solana report's root cause is identity conflation: a single signer is implicitly trusted to fulfill multiple distinct roles (`caller`, token owner, and `payer`), so the program accepts an entity for a role it was never actually verified for. The same *class* of bug — trusting an unverified value as if it had passed a stronger identity check — exists in GitHub Desktop's git credential-helper trampoline: a git server's self-reported `WWW-Authenticate` header is trusted as proof that a host is a genuine "GitHub Enterprise" endpoint, without ever running the app's real GitHub-host verification (`isGitHubHost`), and that misclassification is enough to trigger Desktop's official sign-in UI and OAuth authorization flow against the attacker's own server.

## Finding Description
When git needs credentials for an HTTPS remote, it invokes Desktop's credential helper trampoline. `getEndpointKind` decides whether the target looks like a GitHub host: [1](#0-0) 

Critically, if none of the fast paths (`isGist`, `isDotCom`, `isGHE`, an existing matching account) apply, the code inspects the `wwwauth[...]` credential fields — which are populated verbatim from the HTTP `WWW-Authenticate` response header that git received from the *remote server itself* — and if it contains `realm="GitHub"`, unconditionally classifies the host as `'enterprise'`:
```
for (const [k, v] of cred.entries()) {
  if (k.startsWith('wwwauth[')) {
    if (v.includes('realm="GitHub"')) {
      return 'enterprise'
    }
    ...
```
This header is fully attacker-controlled: any git remote (or MITM/compromised proxy in front of one) the user has added can answer a 401 with `WWW-Authenticate: Basic realm="GitHub"` for any hostname whatsoever.

Once classified `'enterprise'` with no matching stored account, `getCredential` calls: [2](#0-1) 

`ui.promptForGitHubSignIn(endpoint)` immediately drives the *real* sign-in flow using the attacker's raw origin, with no host verification step in between: [3](#0-2) 

That flow calls `dispatcher.setSignInEndpoint(origin)` → `AppStore._setSignInEndpoint` → `SignInStore.setEndpoint`, whose only validation is `validateURL`, which merely checks that the string is a syntactically valid `https://` URL — it does **not** verify the host is an actual GitHub Enterprise instance: [4](#0-3) [5](#0-4) 

This is the exact same codebase that *does* have a robust GitHub-host verification routine — `isGitHubHost`, which performs a real `/meta` HEAD request and checks for the `x-github-request-id` response header — but that routine is used elsewhere (e.g. in `getEndpointKind`'s fallback branch) and is never invoked to confirm the wwwauth-classified host before the sign-in/OAuth UI is shown: [6](#0-5) 

The user is then shown Desktop's legitimate "Sign in" dialog (labelled as a credential-helper prompt for the attacker's URL) and, if they click "Sign in using your browser," Desktop opens the OAuth authorize URL directly at the attacker's host using Desktop's real OAuth client id: [7](#0-6) 

The resulting "account" (login/token entirely defined by the attacker's server responses to `requestOAuthToken`/`fetchUser`) is accepted and persisted into the `AccountsStore` as an authenticated GitHub Enterprise account bound to that endpoint: [8](#0-7) 

## Impact Explanation
This is an unauthorized OAuth/account-binding class issue: an attacker who merely controls a git remote (or a network position that can answer git's HTTPS request with a crafted 401 response) can force GitHub Desktop's own trusted chrome — the official "Sign in" dialog and OAuth authorize redirect — to run against arbitrary attacker infrastructure without Desktop ever verifying the host is real GitHub. The attacker's server fully controls the OAuth-authorize page content (since it's their own domain), and can capture whatever credentials/forms a user submits there, or complete the flow to bind a bogus "authenticated" account into Desktop's `AccountsStore` under that endpoint, corrupting the user's list of trusted GitHub accounts and confusing later per-endpoint token/account lookups. This satisfies the "unauthorized OAuth or account binding" impact category from a git remote/proxy response the attacker controls, with no local access, admin rights, or social engineering beyond adding/using a malicious remote (a normal Desktop workflow).

## Likelihood Explanation
Triggering requires only that the user add or fetch/clone from an attacker-supplied remote URL over HTTPS with no cached credential/account for that host — an entirely ordinary Desktop action. The attacker fully controls the server side of that connection, so crafting the `WWW-Authenticate: realm="GitHub"` response is trivial. No race conditions, no privilege escalation, no pre-existing compromise needed; the only "guard" (`isGitHubHost`'s `/meta` verification) exists in the codebase but is bypassed by this particular detection branch.

## Recommendation
Do not trust the `wwwauth[...]` realm string alone to classify a host as GitHub/enterprise. Before promoting a host to `'enterprise'` (and before invoking `promptForGitHubSignIn`/starting an OAuth flow), require the existing `isGitHubHost` verification (real `/meta` request check) to succeed, and surface a clear warning/confirmation showing the actual hostname when Desktop is about to run a sign-in flow that was auto-triggered by a git credential request rather than by explicit user action in Preferences.

## Proof of Concept
1. Attacker stands up an HTTPS git server at `https://evil.example.com/foo.git` (self-signed cert acceptable to the user, or use a valid cert on a domain they own).
2. Victim adds this URL as a remote in a GitHub Desktop repository and performs a fetch/push.
3. Git issues an HTTPS request; attacker's server responds `401` with header `WWW-Authenticate: Basic realm="GitHub"`.
4. Desktop's `desktop` credential helper is invoked by git; `getGitHubCredential` finds no matching account, `getEndpointKind` sees the spoofed `wwwauth[...]` value and returns `'enterprise'` (`app/src/lib/trampoline/trampoline-credential-helper.ts:157-165`).
5. `getCredential` calls `ui.promptForGitHubSignIn('https://evil.example.com')`, which immediately calls `dispatcher.setSignInEndpoint(origin)` → `SignInStore.setEndpoint`, which only validates that the URL is `https://` (`enterprise-validate-url.ts`) — no check that `evil.example.com` is a real GitHub host.
6. Desktop shows its official "Sign in" dialog referencing `evil.example.com` and offers "Sign in using your browser."
7. Clicking it opens `https://evil.example.com/login/oauth/authorize?client_id=...` in the system browser — content fully controlled by the attacker — and if the flow is "completed" (attacker redirects back to `x-github-client://oauth?code=...&state=...`), Desktop calls `requestOAuthToken`/`fetchUser` against the attacker's server and stores the returned bogus account as an authenticated account bound to `evil.example.com` in the `AccountsStore`.

const getEndpointKind = async (cred: Credential, store: Store) => {
  const credentialUrl = getCredentialUrl(cred)
  const endpoint = `${credentialUrl}`

  if (isGist(endpoint)) {
    return 'generic'
  }

  if (isDotCom(endpoint)) {
    return 'github.com'
  }

  if (isGHE(endpoint)) {
    return 'ghe.com'
  }

  // When Git attempts to authenticate with a host it captures any
  // WWW-Authenticate headers and forwards them to the credential helper. We
  // use them as a happy-path to determine if the host is a GitHub host without
  // having to resort to making a request ourselves.
  for (const [k, v] of cred.entries()) {
    if (k.startsWith('wwwauth[')) {
      if (v.includes('realm="GitHub"')) {
        return 'enterprise'
      } else if (/realm="(GitLab|Gitea|Atlassian Bitbucket)"/.test(v)) {
        return 'generic'
      }
    }
  }

  const existingAccount = await findGitHubTrampolineAccount(store, endpoint)
  if (existingAccount) {
    return isDotCom(existingAccount.endpoint) ? 'github.com' : 'enterprise'
  }

  // All GitHub hosts use HTTPS, so if the protocol is not HTTPS we can
  // assume that this is not a GitHub host.
  if (credentialUrl.protocol !== 'https:') {
    return 'generic'
  }

  return (await isGitHubHost(endpoint)) ? 'enterprise' : 'generic'
}

export function validateURL(address: string): string {
  // ensure user has specified text and not just whitespace
  // we will interact with this server so we can be fairly
  // relaxed here about what we accept for the server name
  const trimmed = address.trim()
  if (trimmed.length === 0) {
    const error = new Error('Unknown address')
    error.name = InvalidURLErrorName
    throw error
  }

  let url = URL.parse(trimmed)
  if (!url.host) {
    // E.g., if they user entered 'ghe.io', let's assume they're using https.
    address = `https://${trimmed}`
    url = URL.parse(address)
  }

  if (!url.protocol) {
    const error = new Error('Invalid URL')
    error.name = InvalidURLErrorName
    throw error
  }

  if (url.protocol !== 'https:') {
    const error = new Error('Invalid protocol')
    error.name = InvalidProtocolErrorName
    throw error
  }

  return address
}

  public async setEndpoint(url: string): Promise<void> {
    const currentState = this.state

    if (
      currentState?.kind !== SignInStep.EndpointEntry &&
      currentState?.kind !== SignInStep.ExistingAccountWarning
    ) {
      const stepText = currentState ? currentState.kind : 'null'
      return fatalError(
        `Sign in step '${stepText}' not compatible with endpoint entry`
      )
    }

    /**
     * If the user enters a github.com url in the GitHub Enterprise sign-in
     * flow we'll redirect them to the GitHub.com sign-in flow.
     */
    if (/^(?:https:\/\/)?(?:api\.)?github\.com($|\/)/.test(url)) {
      this.beginDotComSignIn(currentState.resultCallback)
      return
    }

    this.setState({ ...currentState, loading: true })

    let validUrl: string
    try {
      validUrl = validateURL(url)
    } catch (e) {
      let error = e
      if (e.name === InvalidURLErrorName) {
        error = new Error(
          `The GitHub Enterprise instance address doesn't appear to be a valid URL. We're expecting something like https://example.ghe.com.`
        )
      } else if (e.name === InvalidProtocolErrorName) {
        error = new Error(
          'Unsupported protocol. Only https is supported when authenticating with GitHub Enterprise instances.'
        )
      }

      this.setState({ ...currentState, loading: false, error })
      return
    }

    const endpoint = getEnterpriseAPIURL(validUrl)

    const existingAccount = this.accounts.find(x => x.endpoint === endpoint)

    if (existingAccount) {
      this.setState({
        kind: SignInStep.ExistingAccountWarning,
        endpoint,
        existingAccount,
        error: null,
        loading: false,
        resultCallback: currentState.resultCallback,
      })
    } else {
      this.setState({
        kind: SignInStep.Authentication,
        endpoint,
        error: null,
        loading: false,
        resultCallback: currentState.resultCallback,
      })
    }
  }

/**
 * Attempts to determine whether or not the url belongs to a GitHub host.
 *
 * This is a best-effort attempt and may return `undefined` if encountering
 * an error making the discovery request
 */
export async function isGitHubHost(url: string) {
  const { hostname } = new window.URL(url)

  const endpoint =
    hostname === 'github.com' || hostname === 'api.github.com'
      ? getDotComAPIEndpoint()
      : getEnterpriseAPIURL(url)

  if (isDotCom(endpoint) || isGHE(endpoint)) {
    return true
  }

  if (isKnownThirdPartyHost(hostname)) {
    return false
  }

  // github.example.com,
  if (/(^|\.)(github)\./.test(hostname)) {
    return true
  }

  // bitbucket.example.com, etc
  if (/(^|\.)(bitbucket|gitlab)\./.test(hostname)) {
    return false
  }

  if (getEndpointVersion(endpoint) !== null) {
    return true
  }

  // Add a unique identifier to the URL to make sure our certificate error
  // supression only catches this request
  const metaUrl = `${endpoint}/meta?ghd=${crypto.randomUUID()}`

  const ac = new AbortController()
  const timeoutId = setTimeout(() => ac.abort(), 2000)
  suppressCertificateErrorFor(metaUrl)
  try {
    const response = await fetch(metaUrl, {
      headers: { 'user-agent': getUserAgent() },
      signal: ac.signal,
      credentials: 'omit',
      method: 'HEAD',
      redirect: 'error',
    })

    tryUpdateEndpointVersionFromResponse(endpoint, response)

    return response.headers.has('x-github-request-id')
  } catch (e) {
    log.debug(`isGitHubHost: failed with endpoint ${endpoint}`, e)
    return undefined
  } finally {
    clearTimeout(timeoutId)
    clearCertificateErrorSuppressionFor(metaUrl)
  }
}
