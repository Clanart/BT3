## Finding



### Title
Spoofed `WWW-Authenticate` header from any git remote triggers unverified GitHub Enterprise sign-in/OAuth binding - (File: `app/src/lib/trampoline/trampoline-credential-helper.ts`)

### Summary
Whenever GitHub Desktop performs any Git network operation (`clone`, `fetch`, `push`, `pull`, submodule update, LFS, etc.), it configures Git to use its own credential helper via the trampoline mechanism, which is invoked for **every** remote host, not just github.com [1](#0-0) . The `getEndpointKind` function that classifies a remote host as `github.com`, `enterprise`, or `generic` contains an explicit shortcut that trusts the `wwwauth[]` value (derived from the remote server's `WWW-Authenticate` response header, which is fully attacker-controlled) as proof the host is a GitHub Enterprise server, bypassing the more rigorous `isGitHubHost` network check [2](#0-1) .

### Finding Description
`getEndpointKind` is invoked for every `get` credential request made by Git, keyed only off information the connected server supplies: the URL/host/protocol and any `WWW-Authenticate` headers Git captured and forwarded [3](#0-2) . If the attacker-controlled remote returns a 401 response with a header such as `WWW-Authenticate: Basic realm="GitHub"`, the function immediately classifies the host as `'enterprise'` — a decision explicitly documented as a "happy path" to *avoid* making a verifying network request [4](#0-3) .

Once classified as `enterprise` (or `github.com`), `getCredential` checks whether an existing account already matches that host; if not, it calls `ui.promptForGitHubSignIn(endpoint)` [5](#0-4) . That helper then drives Desktop's real Enterprise sign-in flow — `beginEnterpriseSignIn` + `setSignInEndpoint(origin)` — using the attacker's own host as the OAuth/API endpoint, and shows the native `SignIn` popup [6](#0-5) . `setEndpoint` only performs syntactic/connectivity validation of the URL (must be `https`), not verification that it is genuinely a GitHub-compatible server [7](#0-6) . Continuing then opens the browser at `getOAuthAuthorizationURL(endpoint, csrfToken)` — i.e., navigates to an OAuth authorize URL on the **attacker's own domain** — and on completion exchanges the returned code for a token against that same attacker-controlled endpoint, ultimately binding a new Account entry keyed to the attacker's host [8](#0-7) .

Existing guards do not stop this path: `findGitHubTrampolineAccount`'s origin-matching check [9](#0-8)  only protects already-existing accounts from being sent to the wrong origin; it does nothing to prevent a brand-new, attacker-hosted "Enterprise account" from being created and OAuth-bound by simply spoofing a response header, since `getEndpointKind`'s realm check bypasses the `isGitHubHost` verification that would normally be used for unknown hosts.

### Impact Explanation
This lets any git remote server (or a repository configured with a malicious `.gitmodules` submodule URL, or a redirect/proxy response) unilaterally trigger Desktop's trusted, first-party "Sign in to your GitHub Enterprise" UI and OAuth flow pointed at itself, without the user ever manually choosing "Add Enterprise Account." A user who believes they are simply re-authenticating to access a private repository can be walked through Desktop's native sign-in chrome into completing OAuth against attacker infrastructure, resulting in an account binding to an attacker-controlled endpoint and, if the attacker mimics the OAuth token exchange responses, storage of that binding as a legitimate Desktop account. This matches the "unauthorized OAuth or account binding" impact category, driven by an attacker-controlled git/proxy response, without requiring local access, malware, or leaked credentials.

### Likelihood Explanation
Triggering this only requires the victim to perform a routine Git operation (fetch/clone/push/submodule update/LFS) against a server the attacker controls or can respond as (including via a malicious submodule pointing at an attacker host, encountered automatically during clone/checkout), and to have the credential helper invoked at all — which happens whenever no cached generic/GitHub credential exists for that host. No unusual user steps beyond completing what looks like a normal GitHub sign-in are required.

### Recommendation
Remove the `wwwauth[]` "happy path" shortcut in `getEndpointKind`, or require it to be corroborated by the existing `isGitHubHost(endpoint)` network verification (checking response headers like `x-github-request-id` from the endpoint directly) before ever classifying an unknown host as `'enterprise'` and invoking `promptForGitHubSignIn`.

### Proof of Concept
1. Set up a plain HTTPS server (e.g. `evil.example.com`) that responds to any Git HTTP smart protocol request with `401 Unauthorized` and header `WWW-Authenticate: Basic realm="GitHub"`.
2. In GitHub Desktop, clone/add `https://evil.example.com/foo.git` as a remote (or reference it via a submodule in a repo the victim clones) and perform a `fetch`.
3. Git invokes Desktop's credential helper trampoline; `getEndpointKind` sees the spoofed header and returns `'enterprise'` [10](#0-9) .
4. Since no account matches `evil.example.com`, Desktop calls `ui.promptForGitHubSignIn('https://evil.example.com')`, opening the native "Sign in to your GitHub Enterprise" dialog bound to that host [11](#0-10) .
5. If the user proceeds, Desktop opens the browser to the OAuth authorize URL on `evil.example.com` and, upon completion, exchanges the code for a token against that same host, creating an Account bound to attacker infrastructure [12](#0-11) .

const getEndpointKind = async (cred: Credential, store: Store) => {
  const credentialUrl = getCredentialUrl(cred)
  const endpoint = `${credentialUrl}`

  if (isGist(endpoint)) {
    return 'generic'
  }

  if (isDotCom(endpoint)) {
    return 'github.com'
  }

  if (isGHE(endpoint)) {
    return 'ghe.com'
  }

  // When Git attempts to authenticate with a host it captures any
  // WWW-Authenticate headers and forwards them to the credential helper. We
  // use them as a happy-path to determine if the host is a GitHub host without
  // having to resort to making a request ourselves.
  for (const [k, v] of cred.entries()) {
    if (k.startsWith('wwwauth[')) {
      if (v.includes('realm="GitHub"')) {
        return 'enterprise'
      } else if (/realm="(GitLab|Gitea|Atlassian Bitbucket)"/.test(v)) {
        return 'generic'
      }
    }
  }

  const existingAccount = await findGitHubTrampolineAccount(store, endpoint)
  if (existingAccount) {
    return isDotCom(existingAccount.endpoint) ? 'github.com' : 'enterprise'
  }

  // All GitHub hosts use HTTPS, so if the protocol is not HTTPS we can
  // assume that this is not a GitHub host.
  if (credentialUrl.protocol !== 'https:') {
    return 'generic'
  }

  return (await isGitHubHost(endpoint)) ? 'enterprise' : 'generic'

export async function findGitHubTrampolineAccount(
  accountsStore: AccountsStore,
  remoteUrl: string

  const accounts = await accountsStore.getAll()
  const parsedUrl = new URL(remoteUrl)
  return accounts.find(
    a => new URL(getHTMLURL(a.endpoint)).origin === parsedUrl.origin
  )
