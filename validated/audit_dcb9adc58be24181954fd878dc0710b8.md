### Title
Yield Theft via Just‑In‑Time Staking Around Permissionless `harvest()` — (File: `wombat/WombatStaking.sol`)

### Summary
`WombatStaking.harvest()` is a permissionless function that pulls accrued WOM rewards from Wombat's `MasterWombat` and pushes them into `BaseRewardPool`/`BaseRewardPoolV2` via `queueNewRewards`, which immediately converts the lump-sum reward into a permanent increase of `rewardPerTokenStored` divided by the pool's **current** `totalStaked()`. Because reward accounting is not time-weighted, any unprivileged wallet can inflate `totalStaked()` immediately before calling `harvest()`, capture an outsized share of rewards that accrued to long-term stakers before the attacker ever staked, then withdraw — permanently diluting/stealing unclaimed yield from existing stakers.

### Finding Description
`BaseRewardPool`/`BaseRewardPoolV2._provisionReward` distributes a reward lump sum proportionally to `totalStaked()` measured **at the instant the reward is provisioned**, with no streaming/time-weighting: [1](#0-0) 

`totalStaked()` for a pool is simply `IERC20(stakingToken).balanceOf(operator)` (the receipt-token balance held by `MasterMagpie`), a spot value that any staker can change instantly by depositing/withdrawing: [2](#0-1) 

`WombatStaking.harvest()` is callable by any address (only gated by `_onlyActivePool`, not `onlyOwner`) and triggers `_toMasterWomAndSendReward`, which ultimately calls `queueNewRewards` on the pool's rewarder using the pool's current `totalStaked()`: [3](#0-2) [4](#0-3) 

While `WombatStaking.deposit()` is careful to call `_toMasterWomAndSendReward` **before** minting the new receipt tokens (so a depositor's own atomic deposit-triggered harvest excludes their new stake), this only prevents self-dilution within a single `deposit()` call: [5](#0-4) 

Nothing prevents an attacker from staking receipt tokens through the pool helper's `depositFor`/`depositLP` in one transaction, and then — once that stake is registered in `MasterMagpie` (inflating `totalStaked()`) — separately invoking the public `harvest()` in a subsequent transaction (or the same block) to trigger `queueNewRewards` while the attacker's inflated balance is counted: [6](#0-5) 

`earned()`/`_earned()` computes a user's share purely from `balanceOf(account) * (rewardPerToken() - userRewardPerTokenPaid[account])`, with `userRewardPerTokenPaid` only set the moment they deposit — meaning any balance staked before a `harvest()` call captures its full proportional share of that harvest's rewards regardless of how briefly it was staked: [7](#0-6) 

The attacker can then immediately withdraw via `WombatPoolHelperV2.withdraw()`/`WombatStaking.withdraw()`, exiting with a disproportionate share of rewards that had accrued to genuine long-term stakers before the attacker's brief presence in the pool.

### Impact Explanation
This allows a wallet with sufficient (or flash-loanable) capital in the underlying deposit token to repeatedly siphon a share of already-accrued, unclaimed WOM yield away from legitimate long-term stakers of a given pool, without contributing meaningful staking duration. This constitutes theft of unclaimed yield from other users, satisfying the "theft or permanent freezing of unclaimed yield" impact bar. The magnitude scales with pool TVL and the size of pending un-harvested rewards at the time of the attack.

### Likelihood Explanation
`harvest()` requires no privileged role and can be called by anyone once a pool is active (`_onlyActivePool` only checks pool status, not caller identity). Any user can call `PoolHelper.depositFor`/`depositLP` to stake a large receipt-token balance and then call `harvest()` shortly after. The main constraint is acquiring/holding the underlying deposit token for a short window (potentially via flash loan of the base asset, then swap/deposit into the Wombat pool to mint LP/receipt tokens), which is a common and low-cost pattern for JIT-style reward sniping in DeFi.

### Recommendation
Convert `BaseRewardPool`/`BaseRewardPoolV2` reward accounting to a time-weighted/streaming model (accrue `rewardRate` over `lastUpdateTime` rather than lump-sum dividing by spot `totalStaked()`), or introduce a minimum staking duration / cool-down before a newly deposited balance becomes eligible to receive freshly harvested rewards, mirroring protections against JIT liquidity attacks in other yield-distribution designs.

### Proof of Concept
1. Attacker monitors a Wombat pool integrated into Magpie with sizeable pending, un-harvested WOM rewards in `MasterWombat`.
2. Attacker calls `WombatPoolHelperV2.depositFor()`/`depositLP()` with a large amount of the underlying/LP token, registering a large stake in `MasterMagpie` for that pool (`rewards/BaseRewardPoolV2.sol:126-128` — `totalStaked()` now includes attacker's balance).
3. Attacker (or anyone) calls `WombatStaking.harvest(_lpToken)` (`wombat/WombatStaking.sol:329-335`), which pulls the accrued WOM and calls `queueNewRewards`, computing `rewardPerTokenStored` using the now-inflated `totalStaked()` (`rewards/BaseRewardPoolV2.sol:301-311`).
4. Attacker calls `getReward`/`multiclaim` to collect their proportional share of the just-harvested reward, then immediately withdraws their stake via `WombatPoolHelperV2.withdraw()`.
5. Net effect: attacker captures reward proportional to their large, briefly-held balance, extracted from the pool's yield that should have accrued to long-term stakers.

    function _provisionReward(uint256 _amountReward, address _rewardToken) internal {
        IERC20(_rewardToken).safeTransferFrom(
            msg.sender,
            address(this),
            _amountReward
        );
        Reward storage rewardInfo = rewards[_rewardToken];
        rewardInfo.historicalRewards =
            rewardInfo.historicalRewards +
            _amountReward;

        if (totalStaked() == 0) {
            rewardInfo.queuedRewards += _amountReward;
        } else {
            if (rewardInfo.queuedRewards > 0) {
                _amountReward += rewardInfo.queuedRewards;
                rewardInfo.queuedRewards = 0;
            }
            rewardInfo.rewardPerTokenStored =
                rewardInfo.rewardPerTokenStored +
                (_amountReward * 10**stakingTokenDecimals) /
                totalStaked();
        }
        emit RewardAdded(_amountReward, _rewardToken);
