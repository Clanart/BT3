### Title
Tokenfactory admin can retroactively allow-list a denom and permanently freeze ERC20-pointer-wrapped balances - (File: `x/tokenfactory/keeper/msg_server.go`)

### Summary
`NativeSeiTokensERC20` (the native-token ERC20 pointer contract) implements every `transfer`/`transferFrom` via `_update`, which calls the `bank` precompile's `send` [1](#0-0) . The precompile validates that only the registered pointer address may call `send` for a denom, then executes a real `MsgSend`/`SendCoins` on the underlying tokenfactory denom [2](#0-1) . `SendCoins` enforces `IsSendEnabledCoins`/`IsInDenomAllowList`, which for `factory/...` denoms rejects any sender/receiver not present in the denom's `AllowList` [3](#0-2) . The tokenfactory admin can change this allow list at any time via `MsgUpdateDenom`, which calls `bankKeeper.SetDenomAllowList` unconditionally with no restriction preventing removal of existing holders [4](#0-3) .

### Finding Description
Analogous to the RocketPool rETH deposit-delay bug (where a parameter the bridge did not control could later be changed by an external admin to break previously-safe transfers), the tokenfactory admin — a role reachable by any unprivileged token creator/denom admin who is not the underlying pointer's users — controls a parameter (`AllowList`) that is completely external to the ERC20 pointer contract's logic but that the pointer's `transfer`/`transferFrom` implicitly depend on succeeding. At denom-creation time there may be no allow list (or a permissive one) and users freely wrap the tokenfactory denom into `NativeSeiTokensERC20`, building ERC20 balances that other DeFi contracts (AMMs, lending markets, escrow) come to rely on. The admin can later call `MsgUpdateDenom` with an `AllowList` that excludes some or all existing balance holders [5](#0-4) . From that block forward, every `transfer`/`transferFrom` call on the ERC20 pointer for an excluded holder reverts inside `SendCoins`, because `IsInDenomAllowList` rejects the sender [6](#0-5) , even though the ERC20 `balanceOf` (which reads directly from the bank module, not from an internal ledger) still shows the pre-existing balance [7](#0-6) . This produces a permanent mismatch: the ERC20 pointer shows a nonzero balance that can never be moved, exactly mirroring rETH's DoS where balances existed but every mutating call reverted due to an externally-changeable delay/lock condition.

### Impact Explanation
Any protocol integrating with a tokenfactory-backed ERC20 pointer (lending markets accepting it as collateral, AMMs holding it in pools, vaults, bridges) is exposed to permanent fund freezing the moment the denom admin narrows the allow list. Because the pointer's `balanceOf`/`totalSupply` continue to reflect on-chain bank balances while `transfer` reverts, funds become irretrievable for any excluded address, satisfying the "permanent freezing of funds" bar for this scan.

### Likelihood Explanation
The tokenfactory admin (denom creator or delegated admin via `MsgChangeAdmin`) is an ordinary, unprivileged on-chain actor able to submit `MsgUpdateDenom` at will; no governance or validator collusion is required. Any dApp or user that treats a tokenfactory-native ERC20 pointer as behaving like a standard immutable ERC20 (no third-party admin control) is at risk the first time such an admin changes the allow list, which requires only a single transaction.

### Recommendation
Consider one or more of: (1) preventing `MsgUpdateDenom`/`SetDenomAllowList` from removing addresses that currently hold a nonzero balance of the denom (or requiring a delay/notice period), (2) having `NativeSeiTokensERC20`/other pointer contracts surface allow-list status via a view function so integrators can detect at-risk denoms before accepting them, or (3) excluding allow-listed tokenfactory denoms from being eligible for native ERC20 pointer creation, since pointer semantics implicitly promise unrestricted internal transferability.

### Proof of Concept
1. Attacker/admin creates a tokenfactory denom `factory/admin/X` with no allow list, or an initial permissive allow list.
2. User A registers/uses the native ERC20 pointer for `factory/admin/X` (`NativeSeiTokensERC20`) and receives/holds a wrapped balance via `BankPrecompile.send` calls that succeed (no allow list restriction yet).
3. Denom admin submits `MsgUpdateDenom` with `AllowList{Addresses: [admin_only]}`, excluding User A [8](#0-7) .
4. User A calls `pointer.transfer(...)`; `_update` invokes `BankPrecompile.send(from, to, denom, value)` [1](#0-0) , which reaches `SendCoins`→`IsInDenomAllowList`, which now returns `false` for User A and the call reverts [9](#0-8) .
5. `pointer.balanceOf(userA)` still reports the pre-existing balance (it queries `BankPrecompile.balance`) [7](#0-6) , but User A can never move or redeem it — funds are permanently frozen.

func (p PrecompileExecutor) send(ctx sdk.Context, caller common.Address, method *abi.Method, args []interface{}, value *big.Int, readOnly bool) ([]byte, uint64, error) {
	if readOnly {
		return nil, 0, errors.New("cannot call send from staticcall")
	}
	if err := pcommon.ValidateNonPayable(value); err != nil {
		return nil, 0, err
	}

	if err := pcommon.ValidateArgsLength(args, 4); err != nil {
		return nil, 0, err
	}
	denom := args[2].(string)
	if denom == "" {
		return nil, 0, errors.New("invalid denom")
	}
	pointer, _, exists := p.evmKeeper.GetERC20NativePointer(ctx, denom)
	if !exists || pointer.Cmp(caller) != 0 {
		return nil, 0, fmt.Errorf("only pointer %s can send %s but got %s", pointer.Hex(), denom, caller.Hex())
	}
	amount := args[3].(*big.Int)
	if amount.Cmp(utils.Big0) == 0 {
		// short circuit
		bz, err := method.Outputs.Pack(true)
		return bz, pcommon.GetRemainingGas(ctx, p.evmKeeper), err
	}
	senderSeiAddr, err := p.accAddressFromArg(ctx, args[0])
	if err != nil {
		return nil, 0, err
	}
	receiverSeiAddr, err := p.accAddressFromArg(ctx, args[1])
	if err != nil {
		return nil, 0, err
	}

	msg := &banktypes.MsgSend{
		FromAddress: senderSeiAddr.String(),
		ToAddress:   receiverSeiAddr.String(),
		Amount:      sdk.NewCoins(sdk.NewCoin(denom, sdk.NewIntFromBigInt(amount))),
	}

	err = msg.ValidateBasic()
	if err != nil {
		return nil, 0, err
	}

	if _, err = p.bankMsgServer.Send(sdk.WrapSDKContext(ctx), msg); err != nil {
		return nil, 0, err
	}

func (k BaseSendKeeper) GetDenomAllowList(ctx sdk.Context, denom string) types.AllowList {
	store := ctx.KVStore(k.storeKey)
	store = prefix.NewStore(store, types.DenomAllowListKey(denom))

	bz := store.Get([]byte(denom))
	if bz == nil {
		return types.AllowList{}
	}

	var allowList types.AllowList
	k.cdc.MustUnmarshal(bz, &allowList)

	return allowList
}

// IsInDenomAllowList checks if the given address is allowed to send the given coins.
// The check is performed only fot token factory denoms. For each token factory denom,
// it checks if there is allow list for the given denom. If there is no allow list,
// the address is allowed to send the coins. If there is an allow list, the address is
// allowed to send the coins only if it is in the allow list.
func (k BaseSendKeeper) IsInDenomAllowList(ctx sdk.Context, addr sdk.AccAddress, coins sdk.Coins, cache map[string]AllowedAddresses) bool {
	for _, coin := range coins {
		// Skip if denom does not contain the token factory prefix
		if !strings.HasPrefix(coin.Denom, TokenFactoryPrefix) {
			continue
		}

		allowedAddresses := k.getAllowedAddresses(ctx, cache, coin.Denom)
		// skip if there is no allow list for the denom
		if len(allowedAddresses.set) == 0 {
			continue
		}

		if !allowedAddresses.contains(addr) {
			return false
		}
	}
	return true
}

func (server msgServer) UpdateDenom(goCtx context.Context, msg *types.MsgUpdateDenom) (*types.MsgUpdateDenomResponse, error) {
	ctx := sdk.UnwrapSDKContext(goCtx)

	denom, err := server.validateUpdateDenom(ctx, msg)
	if err != nil {
		return nil, err
	}

	authorityMetadata, err := server.GetAuthorityMetadata(ctx, denom)
	if err != nil {
		return nil, err
	}

	if msg.Sender != authorityMetadata.GetAdmin() {
		return nil, types.ErrUnauthorized
	}

	updateDenomEvent := sdk.NewEvent(
		types.TypeMsgUpdateDenom,
		sdk.NewAttribute(types.AttributeCreator, msg.Sender),
		sdk.NewAttribute(types.AttributeUpdatedTokenDenom, denom),
	)

	if msg.AllowList != nil {
		server.bankKeeper.SetDenomAllowList(ctx, denom, *msg.AllowList)
		updateDenomEvent = updateDenomEvent.AppendAttributes(
			sdk.NewAttribute(types.AttributeAllowList, strings.Join(msg.AllowList.Addresses, ",")),
		)
	}

	ctx.EventManager().EmitEvents(sdk.Events{
		updateDenomEvent,
	})

	return &types.MsgUpdateDenomResponse{}, nil
}
