### Title
Forfeiture bypass via `VLMGP.cancelUnlock` self-front-running `queueMGP` - ([File: VLMGP.sol], [File: rewards/vlMGPBaseRewarder.sol])

### Summary
`vlMGPBaseRewarder.queueMGP`/`_sendReward` compute forfeiture strictly from the *instantaneous* value of `VLMGP.getRewardablePercentWAD(account)` at the moment MGP is distributed, rather than from the cooldown state that existed while the MGP was accruing. Because `cancelUnlock` is a fee-free, cooldown-free, non-reentrant-guarded action that instantly restores a user's "fully locked" percentage to 100%, any user with a cooldown slot can call `cancelUnlock` immediately before triggering a MasterMagpie claim to erase all forfeiture on MGP that accrued while they were partially in cooldown, then call `startUnlock` again afterwards to resume exiting.

### Finding Description
`VLMGP.getRewardablePercentWAD` computes the rewardable share purely from current state: `getUserTotalLocked` (fully-locked balance) vs. `getUserAmountInCoolDown` (in each `UserUnlocking` slot), see [1](#0-0) . `cancelUnlock` simply zeroes `slot.amountInCoolDown` and decrements `totalAmountInCoolDown`, with no fee, no reentrancy guard beyond `whenNotPaused`, and no interaction with MasterMagpie: [2](#0-1) . Since `getUserTotalLocked` is derived as `stakingInfo(amount) - getUserAmountInCoolDown(user)` [3](#0-2) , zeroing the cooldown slot instantly restores 100% "fully locked" status without any waiting period or penalty.

`vlMGPBaseRewarder.queueMGP` (called from `MasterMagpie._sendMGPForVlMGPPool` during harvest/claim) and `_sendReward` both call `_calExpireForfeit`, which reads `vlMGP.getRewardablePercentWAD(_account)` at call time to determine how much of the freshly emitted MGP is forfeited into the shared reward pool vs. paid to the user: [4](#0-3)  and [5](#0-4) . Because the percentage is not checkpointed or time-weighted against the actual accrual period (only the currently-open cooldown slot's own elapsed-time-weighting is applied, and that resets to zero exposure once `amountInCoolDown` is zeroed), a user can:
1. `lock` MGP, accrue MGP emissions in MasterMagpie via `accMGPPerShare`.
2. `startUnlock(partialAmount)`, opening a cooldown slot that would normally cause partial forfeiture on any subsequently harvested MGP (per `getRewardablePercentWAD`).
3. Call `cancelUnlock(_slotIndex)` right before calling `MasterMagpie.claim`/`multiclaimFor` (own transaction ordering, no external front-running needed since the attacker controls both calls).
4. `queueMGP` now sees `getRewardablePercentWAD == 100%`, so `forfeitAmount == 0` and the full pending MGP is paid to the attacker.
5. Call `startUnlock` again to resume the exit process, at zero cost beyond restarting the cooldown timer.

No existing modifier prevents this: `cancelUnlock` only has `whenNotPaused` and index/cooldown-state checks (`_checkIdexInBoundary`, `_checkInCoolDown`), and `queueMGP`/`_sendReward` have no defense against state manipulated in the same or an immediately preceding transaction.

### Impact Explanation
This defeats the core economic purpose of the vlMGP forfeiture mechanism, which exists to socialize a penalty from users in the process of exiting into the reward pool for users who remain fully locked. An attacker can costlessly toggle in/out of "in cooldown" state around every harvest event, permanently avoiding forfeiture on their share of freshly minted MGP that would otherwise be redistributed as yield to other, genuinely-committed vlMGP lockers. This is a direct theft of yield that should be forfeited to other lockers (Immunefi class: theft of unclaimed yield).

### Likelihood Explanation
Feasibility is high: no special privileges are required, only standard user functions (`lock`, `startUnlock`, `cancelUnlock`, MasterMagpie's `claim`/`multiclaimFor`). No front-running race against another party is even necessary since the attacker sequences their own transactions (or does it atomically via a helper contract). The only "cost" is restarting the cooldown timer on `startUnlock`, which is not a real cost to a user who wasn't planning to complete the unlock imminently. The attack is fully repeatable at every harvest/claim event.

### Recommendation
Compute forfeiture based on the cooldown state that existed while MGP was accruing rather than the state at claim time — e.g., checkpoint `getRewardablePercentWAD` per-block or on every balance-affecting event and use a time-weighted average since the last harvest, or accrue forfeiture obligations incrementally instead of instantaneously. Alternatively, disallow `cancelUnlock` from taking effect until after a cooldown of its own, or force a harvest/settlement (`_calExpireForfeit` snapshot) at the moment `startUnlock`/`cancelUnlock` is called so that forfeiture already accrued cannot be erased retroactively.

### Proof of Concept
Foundry test plan:
1. Deploy `VLMGP`, `MasterMagpie`, `vlMGPBaseRewarder` with MGP token, set up pool for vlMGP.
2. User A locks MGP, MasterMagpie accrues MGP emissions to User A via `accMGPPerShare` over several blocks.
3. Baseline run: User A calls `startUnlock(partialAmount)`, waits, then calls `MasterMagpie.claim`/`multiclaimFor` which routes through `_sendMGPForVlMGPPool -> queueMGP`. Record `forfeitAmount` emitted in `MGPHarvested`/`ForfeitRewardAdded` and `rewardableAmount` transferred to receiver.
4. Exploit run: Reset state identically (same lock/emission history/cooldown start), but immediately before calling `claim`, call `VLMGP.cancelUnlock(_slotIndex)`. Then call `claim`.
5. Assert: in the exploit run, `forfeitAmount == 0` and `rewardableAmount == full pending MGP`, whereas baseline run has `forfeitAmount > 0` for an otherwise identical accrual/cooldown history — confirming the forfeiture is fully and costlessly bypassed.
6. Optionally show User A can call `startUnlock` again post-claim to resume the exit with no lasting penalty, demonstrating repeatability.

    function getRewardablePercentWAD(address _user) override public view returns(uint256 percent) {
        uint256 fullyInLock = getUserTotalLocked(_user);
        uint256 inCoolDown = getUserAmountInCoolDown(_user);
        uint256 userTotalVlmgp = fullyInLock + inCoolDown;
        if (userTotalVlmgp == 0)
            return 0;
        percent = fullyInLock * 1e18 / userTotalVlmgp;

        uint256 timeNow = block.timestamp;
        UserUnlocking[] storage userUnlocking = userUnlockings[_user];

        for (uint256 i; i < userUnlocking.length; i++) {
            if (userUnlocking[i].amountInCoolDown > 0) {
                if (block.timestamp > userUnlocking[i].endTime) {// fully unlocked 
                    percent += userUnlocking[i].amountInCoolDown * 1e18 * (userUnlocking[i].endTime - userUnlocking[i].startTime)
                        / userTotalVlmgp / (timeNow - userUnlocking[i].startTime);
                }
                else {// still in cool down 
                    percent += userUnlocking[i].amountInCoolDown * 1e18 / userTotalVlmgp;
                }

            }
        }

        return percent;
    }

    function _calExpireForfeit(address _account, uint256 _amount) internal view returns (uint256) {
        uint256 rewardablePercentWAD = vlMGP.getRewardablePercentWAD(_account);
        uint256 rewardableAmount = _amount * rewardablePercentWAD / 1e18;
        if (rewardableAmount > _amount)
            revert InvalidRewardableAmount();

        uint256 forfeitAmount = _amount - rewardableAmount;
        
        if (forfeitAmount < (_amount / 1000)) {  // if forfeitAmount is smaller than 0.1% ignore to save gas fee
            forfeitAmount = 0;
            rewardableAmount = _amount;
        }

        return forfeitAmount;
    }
