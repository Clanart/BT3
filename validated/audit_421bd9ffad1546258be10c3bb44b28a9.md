### Title
`SignableTransaction` trusts the attacker-controlled `ReceivedOutput.output.value`, letting a forged claimed prevout value burn real funds as fees - ([File: networks/bitcoin/src/wallet/send.rs](networks/bitcoin/src/wallet/send.rs))

### Summary
The reported Allo bug class is "contract honors a caller-supplied `_amount` without checking it against the funds actually provided." In Serai's Bitcoin wallet, `ReceivedOutput` deserializes a `TxOut` (including `value`) and an `OutPoint` entirely from attacker-supplied bytes in `ReceivedOutput::read` (`networks/bitcoin/src/wallet/mod.rs:122-134`). `SignableTransaction::new` then computes the available input balance, the change amount, and the implicit fee purely from these claimed values (`send.rs:175`, `send.rs:224-235`), and `SignableTransaction::multisig` authenticates each prevout only by comparing `script_pubkey` — it never verifies the `outpoint` exists on chain or that the claimed `value` equals the real UTXO value (`send.rs:273-281`). The resulting signature commits to the claimed values via `Prevouts::All` (`send.rs:373-389`), while Bitcoin consensus computes the fee from the *real* prevout value.

### Finding Description
An unprivileged party who can feed serialized bytes into `ReceivedOutput::read` (a listed untrusted-bytes sink) can craft a `ReceivedOutput` referencing a real multisig-controlled UTXO but with a tampered `output.value`:

- **Deflated value**: claiming `value` lower than the real UTXO makes `input_sat` smaller, shrinking or eliminating the change output (`send.rs:228-234`). The transaction is still consensus-valid (Taproot signatures commit to the *claimed* value in the sighash, while consensus fee = real input − outputs), so the difference between the real UTXO value and the signed outputs is paid as an excess miner fee — a direct, unrecoverable loss of multisig funds to whoever mines the block.
- **Inflated value**: claiming `value` higher than real fabricates a change output worth more than exists; the signed transaction is invalid and can never confirm, yet the system has signed it and may treat the phantom change/balance as received-but-unspendable funds.

The only integrity check performed on a prevout is the `script_pubkey` equality check in `multisig` (`send.rs:277`), which says nothing about the `value` or the `outpoint`'s existence.

### Impact Explanation
A forged `ReceivedOutput` causes the FROST threshold to sign a transaction that either destroys real funds as excess fees (deflated value, real signature-valid theft of multisig balance) or records funds that are not actually spendable (inflated value). This is the Serai analog of paying 0 while declaring arbitrary `_amount`: the claimed amount is never reconciled against the actual value locked at the outpoint.

### Likelihood Explanation
`ReceivedOutput::read` is a public deserialization API explicitly exposed to untrusted bytes; any component that accepts serialized outputs from peers/coordinators rather than purely from its own `Scanner` is reachable. No threshold collusion or validator misbehavior is required — a single forged byte stream drives the signing machine.

### Recommendation
Bind `ReceivedOutput` to verified chain data: in `SignableTransaction::multisig`/`new`, confirm each `outpoint` resolves on chain and that the claimed `TxOut` (value and script) matches the confirmed UTXO before signing, or only construct `SignableTransaction`s from `Scanner`-produced outputs and reject externally supplied `ReceivedOutput`s at trust boundaries.

### Proof of Concept
```rust
// Real UTXO: 100_000 sats controlled by the multisig key, confirmed on chain.
let real: TxOut = /* from Scanner */;
let mut forged = real.clone();
forged.value = Amount::from_sat(10_000); // deflate the claimed value

let bytes = ReceivedOutput { offset, output: forged, outpoint: real_outpoint }.serialize();
let input = ReceivedOutput::read(&mut bytes.as_slice()).unwrap(); // accepted blindly

// payments: 9_000 sats; change script provided
let stx = SignableTransaction::new(vec![input], &payments, Some(change), None, fee).unwrap();
// change = 10_000 - 9_000 - fee ≈ ~500; multisig signs over Prevouts::All(claimed 10_000)
// On chain: real fee = 100_000 - ~9_500 ≈ 90_500 sats burned to miners.
// `multisig` accepts it because only script_pubkey is checked (send.rs:277).
```
