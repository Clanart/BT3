### Title
Permissionless native-denom pointer registration lets attackers spoof legitimate token metadata (name/symbol/decimals) via tokenfactory `SetDenomMetadata` - ([File: precompiles/pointer/pointer.go])

### Summary
The `pointer` precompile's `AddNative` handler creates an ERC20 pointer contract for *any* bank denom that has metadata, taking the `name`, `symbol`, and `decimals` fields directly from `x/bank` `DenomMetadata` without verifying that this metadata is unique or accurately tied to the underlying denom's identity. `x/tokenfactory` allows any account to permissionlessly create a denom and then, as its self-appointed "admin," freely set that denom's `DenomMetadata` via `MsgSetDenomMetadata`, including choosing a `Name`, `Symbol`, and `DenomUnits` (which control `decimals`) that mimic a well-known asset (e.g. "usei", "USDC"), while the actual `Base` denom remains the attacker's unique `factory/{creator}/{subdenom}` string.

### Finding Description
`AddNative` in the pointer precompile [1](#0-0)  fetches `bankKeeper.GetDenomMetaData(ctx, token)` and uses `metadata.Name`, `metadata.Symbol`, and the largest `DenomUnit.Exponent`/alias to derive the pointer's `decimals`, `name`, and `symbol`, then calls `UpsertERCNativePointer` to deploy/point an ERC20 contract for that denom [2](#0-1) . Anyone can trigger `AddNative` via the public precompile (permissionless, callable by any EVM transaction sender).

The denom metadata itself is not tied to a canonical whitelist: `x/tokenfactory` lets any account create a denom via `CreateDenom` (`factory/{creator}/{subdenom}`) [3](#0-2) , and that creator becomes the denom's "admin" who can subsequently call `MsgSetDenomMetadata` to overwrite the bank `DenomMetadata` for their `Base` denom with an arbitrary `Name`, `Symbol`, `Display`, and `DenomUnits` [4](#0-3) . The only validations performed are `Metadata.Validate()` (structural checks on denom-unit ordering/format) [5](#0-4)  and that the sender is the admin of `Metadata.Base` — there is no check that `Name`/`Symbol`/alias values are unique or don't collide with another asset's identifying strings. A test in the tokenfactory keeper even demonstrates setting `Display: "usei"` and a denom unit named `"usei"` with `Exponent: 6` for an attacker-owned factory denom [6](#0-5) .

Combining these two permissionless paths: an attacker can (1) create a tokenfactory denom, (2) set its metadata to impersonate a well-known token's name/symbol/decimals, then (3) call the pointer precompile's `addNativePointer` to deploy an ERC20 contract whose `name()`, `symbol()`, and `decimals()` are indistinguishable from a legitimate asset's pointer, backed by a completely different (and worthless) underlying denom.

### Impact Explanation
Downstream consumers of ERC20 pointer contracts (DEX front-ends, wallets, other smart contracts) that identify a token by its `name()`/`symbol()`/`decimals()` metadata rather than by its unique contract address can be tricked into treating the fake pointer as the genuine wrapped asset. This can lead to users approving/swapping/holding the spoofed token believing it to be the real one, resulting in fund loss for victims who transact against the impostor contract. This mirrors the class of risk described in the reference report: absence of restrictions on what asset properties can be registered into a trust-sensitive registry (there, collateral type; here, token identity metadata) allows an attacker-controlled asset to masquerade as, or corrupt the intended ordering/trust assumptions of, a legitimate one.

### Likelihood Explanation
Both preconditions are reachable by any unprivileged account with no special permission: `x/tokenfactory` denom creation and metadata-setting are open to any account, and the `AddNativePointer` precompile call is a standard EVM transaction with no admin gating (the `RegisterPointerDisabled` param only gates the separate CW->ERC `MsgRegisterPointer` path [7](#0-6) , not `AddNative`). The attack requires only routine transactions and gas fees, making likelihood high, though actual fund loss further depends on victims/integrators trusting name/symbol over contract address.

### Recommendation
When registering a native pointer, restrict or flag the `name`/`symbol`/decimal-unit alias values to prevent collision with the canonical denom name (e.g. `usei`) or other already-registered pointer metadata, or require that pointer creation for tokenfactory denoms surface the full `Base` denom (which is guaranteed unique) prominently instead of a spoofable `Name`/`Symbol`, and/or maintain a governance-curated allow-list before permitting arbitrary denom metadata to be used verbatim by `AddNative`.

### Proof of Concept
1. Attacker calls `MsgCreateDenom` to create `factory/<attacker>/fakeusei`.
2. Attacker calls `MsgSetDenomMetadata` with `Base: "factory/<attacker>/fakeusei"`, `Name: "Sei"`, `Symbol: "usei"`, `DenomUnits: [{Denom: base, Exponent: 0}, {Denom: "usei", Exponent: 6, Aliases: ["Sei"]}]` (structurally valid per `Metadata.Validate()`, as shown feasible in the existing test) [6](#0-5) .
3. Attacker calls the pointer precompile's `addNativePointer("factory/<attacker>/fakeusei")`; `AddNative` reads the spoofed metadata and deploys an ERC20 pointer whose `name()`/`symbol()`/`decimals()` mirror genuine "usei" [1](#0-0) .
4. Any integrator identifying the asset by symbol/name (rather than contract address) can be misled into interacting with the fake token, resulting in fund loss.

Note: I was unable to fully verify within the tool budget whether `DeconstructDenom` in `x/tokenfactory/types/denoms.go` enforces any additional constraint tying `Name`/`Symbol`/`DenomUnits` content back to the `subdenom` string (only its call sites were located, not its full body), so there is some residual uncertainty about whether additional implicit constraints reduce the spoofing surface. A Devin session with full file access could confirm this definitively.

```go
			}
```

```go
func (server msgServer) SetDenomMetadata(goCtx context.Context, msg *types.MsgSetDenomMetadata) (*types.MsgSetDenomMetadataResponse, error) {
	ctx := sdk.UnwrapSDKContext(goCtx)

	// Defense in depth validation of metadata
	err := msg.Metadata.Validate()
	if err != nil {
		return nil, err
	}

	authorityMetadata, err := server.GetAuthorityMetadata(ctx, msg.Metadata.Base)
	if err != nil {
		return nil, err
	}

	if msg.Sender != authorityMetadata.GetAdmin() {
		return nil, types.ErrUnauthorized
	}

	server.bankKeeper.SetDenomMetaData(ctx, msg.Metadata)

	ctx.EventManager().EmitEvents(sdk.Events{
		sdk.NewEvent(
			types.TypeMsgSetDenomMetadata,
			sdk.NewAttribute(types.AttributeDenom, msg.Metadata.Base),
			sdk.NewAttribute(types.AttributeDenomMetadata, msg.Metadata.String()),
		),
	})

	return &types.MsgSetDenomMetadataResponse{}, nil
```

```go
func (m Metadata) Validate() error {
	if strings.TrimSpace(m.Name) == "" {
		return errors.New("name field cannot be blank")
	}

	if strings.TrimSpace(m.Symbol) == "" {
		return errors.New("symbol field cannot be blank")
	}

	if err := sdk.ValidateDenom(m.Base); err != nil {
		return fmt.Errorf("invalid metadata base denom: %w", err)
	}

	if err := sdk.ValidateDenom(m.Display); err != nil {
		return fmt.Errorf("invalid metadata display denom: %w", err)
	}

	var (
		hasDisplay      bool
		currentExponent uint32 // check that the exponents are increasing
	)

	seenUnits := make(map[string]bool)

	for i, denomUnit := range m.DenomUnits {
		// The first denomination unit MUST be the base
		if i == 0 {
			// validate denomination and exponent
			if denomUnit.Denom != m.Base {
				return fmt.Errorf("metadata's first denomination unit must be the one with base denom '%s'", m.Base)
			}
			if denomUnit.Exponent != 0 {
				return fmt.Errorf("the exponent for base denomination unit %s must be 0", m.Base)
			}
		} else if currentExponent >= denomUnit.Exponent {
			return errors.New("denom units should be sorted asc by exponent")
		}

		currentExponent = denomUnit.Exponent

		if seenUnits[denomUnit.Denom] {
			return fmt.Errorf("duplicate denomination unit %s", denomUnit.Denom)
		}

		if denomUnit.Denom == m.Display {
			hasDisplay = true
		}

		if err := denomUnit.Validate(); err != nil {
			return err
		}

		seenUnits[denomUnit.Denom] = true
	}

	if !hasDisplay {
		return fmt.Errorf("metadata must contain a denomination unit with display denom '%s'", m.Display)
	}

	return nil
}
```
