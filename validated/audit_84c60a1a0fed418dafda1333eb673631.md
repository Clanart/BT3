### Title
DNS Rebinding Protection on EVM JSON-RPC Surface Is Defeated by Default `Vhosts: ["*"]` Configuration - ([File: evmrpc/server.go])

### Summary

### Finding Description
Sei's EVM JSON-RPC HTTP server implements a `virtualHostHandler` specifically designed to prevent DNS rebinding attacks by validating the `Host` header against an allowlist [1](#0-0) . This handler is wired into the HTTP middleware stack via `NewHTTPHandlerStack` [2](#0-1) , and its correctness is validated by `TestVhosts` [3](#0-2) .

However, `NewEVMHTTPServer` — the function that actually constructs the production HTTP RPC server — hardcodes the `Vhosts` field to `[]string{"*"}`: [4](#0-3) 

Looking at `virtualHostHandler.ServeHTTP`, when `"*"` is present in the vhost map, every non-IP hostname is unconditionally accepted [5](#0-4) . This means the DNS-rebinding mitigation that the codebase explicitly built and tested is a no-op in the actual node binary — there is no configuration knob exposed to node operators to set a strict allowlist; the wildcard is compiled in.

Compounding this, the EVM RPC/WS HTTP server binds by default to all interfaces via the `LocalAddress` constant `"0.0.0.0"` [6](#0-5) [7](#0-6) , and the WebSocket server similarly binds broadly [8](#0-7) . This is precisely the pattern the referenced advisory describes: an HTTP service reachable on all interfaces with no effective host validation, permitting DNS rebinding to defeat the browser's same-origin policy.

This is functionally identical to the reported bug class: the codebase already "recognizes the threat model" (it wrote `virtualHostHandler` specifically to stop DNS rebinding, mirroring go-ethereum's upstream fix) but the deployed default configuration silently disables the protection.

### Impact Explanation
Once a victim (e.g., a node operator, RPC-node administrator, or any user with a browser that can reach the RPC port on `localhost`/private network) visits an attacker-controlled page during a DNS-rebinding attack, the attacker's JavaScript is treated as same-origin by the rebound hostname and can freely call the EVM JSON-RPC surface exposed on the node — since `Vhosts=["*"]` accepts any `Host` header. Reachable methods include account/state queries (`eth_getBalance`, `eth_call`, `debug_trace*`, `sei_getSeiAddress`/association endpoints, `txpool_*`), enabling confidential data disclosure about the node operator's accounts, and pending transaction visibility, from what the operator otherwise assumed was a network/browser-isolated internal endpoint. If the node additionally exposes any hosted-key signing path (e.g. via `SendAPI.signTransaction`, which resolves from `getTestKeyring` [9](#0-8) , gated to non-live/test configurations), a rebinding attacker could also trigger unauthorized signing/broadcast of transactions from node-hosted keys, resulting in fund loss on such deployments.

### Likelihood Explanation
Exploitation requires no privileged position: it is a standard browser-based DNS rebinding attack requiring only that the victim's browser can reach the node's RPC port (default listen `0.0.0.0`) and that the victim visits an attacker page. Given the compiled-in `Vhosts: []string{"*"}`, there is no operator action that restores the intended protection — the mitigation is dead code in the production path, making this reliably exploitable against any Sei EVM RPC node reachable from a victim's LAN/localhost context.

### Recommendation
- Make `Vhosts` configurable in `evmrpc/config` (analogous to `CORSOrigins`/`WSOrigins`) defaulting to `["localhost", "127.0.0.1"]` rather than hardcoding `"*"` in `NewEVMHTTPServer`.
- Do not rely on `0.0.0.0` bind semantics as an access-control boundary; document that operators exposing the RPC beyond loopback must set an explicit vhost allowlist.
- Apply the same allowlist requirement to the WebSocket origin/host configuration path.

### Proof of Concept
1. Run a Sei node with default `app.toml`/EVM RPC config (as produced by `NewEVMHTTPServer`), which binds the HTTP JSON-RPC server to `0.0.0.0:<HTTPPort>` with `Vhosts: []string{"*"}`.
2. Confirm via `TestVhosts`-style request that any `Host` header is accepted: `curl -H "Host: attacker.example" http://<node-ip>:<port> -d '{"jsonrpc":"2.0","id":1,"method":"eth_chainId","params":[]}'` returns a valid response instead of the `403 invalid host specified` that `virtualHostHandler` would otherwise return for a non-allowlisted host [10](#0-9) .
3. In a real DNS-rebinding scenario, host attacker-controlled JavaScript that first resolves `attacker.example` to attacker infrastructure, then rebinds DNS to the victim-reachable Sei node IP; the victim browser's same-origin JS can then `fetch("http://attacker.example:<port>", {method:"POST", body: '{"jsonrpc":"2.0","id":1,"method":"eth_getBalance","params":["0x...","latest"]}'})` and read the response, because `Vhosts=["*"]` accepts the attacker's rebinding hostname.

func NewHTTPHandlerStack(srv http.Handler, cors []string, vhosts []string, JwtSecret []byte) http.Handler {

// virtualHostHandler is a handler which validates the Host-header of incoming requests.
// Using virtual hosts can help prevent DNS rebinding attacks, where a 'random' domain name points to
// the service ip address (but without CORS headers). By verifying the targeted virtual host, we can
// ensure that it's a destination that the node operator has defined.
type virtualHostHandler struct {
	vhosts map[string]struct{}
	next   http.Handler
}

func newVHostHandler(vhosts []string, next http.Handler) http.Handler {
	vhostMap := make(map[string]struct{})
	for _, allowedHost := range vhosts {
		vhostMap[strings.ToLower(allowedHost)] = struct{}{}
	}
	return &virtualHostHandler{vhostMap, next}
}

// ServeHTTP serves JSON-RPC requests over HTTP, implements http.Handler
func (h *virtualHostHandler) ServeHTTP(w http.ResponseWriter, r *http.Request) {
	// if r.Host is not set, we can continue serving since a browser would set the Host header
	if r.Host == "" {
		h.next.ServeHTTP(w, r)
		return
	}
	host, _, err := net.SplitHostPort(r.Host)
	if err != nil {
		// Either invalid (too many colons) or no port specified
		host = r.Host
	}
	if ipAddr := net.ParseIP(host); ipAddr != nil {
		// It's an IP address, we can serve that
		h.next.ServeHTTP(w, r)
		return
	}
	// Not an IP address, but a hostname. Need to validate
	if _, exist := h.vhosts["*"]; exist {
		h.next.ServeHTTP(w, r)
		return
	}
	if _, exist := h.vhosts[host]; exist {
		h.next.ServeHTTP(w, r)
		return
	}
	http.Error(w, "invalid host specified", http.StatusForbidden)
}

func TestVhosts(t *testing.T) {
