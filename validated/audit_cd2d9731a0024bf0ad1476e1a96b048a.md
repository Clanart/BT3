### Title
Unhandled `ValueError` in condition parsing crashes wallet coin-processing on malformed puzzle output - (File: `chia/consensus/condition_tools.py`)

### Summary
`chia/consensus/condition_tools.py`'s `parse_sexp_to_condition()` builds a `ConditionWithArgs` by calling `ConditionOpcode(op)` on the first byte of a condition emitted by a puzzle's CLVM output, and its caller `conditions_for_solution()` only catches `Program.EvalError`, not the `ValueError` that `ConditionOpcode(op)` raises for any byte value that is not one of the defined opcodes. This is the same bug class as GHSA-846p-jg2w-w324: untrusted, well-formed-but-not-well-typed data (a "valid" CLVM output that isn't a recognized condition opcode) triggers an unhandled exception during parsing, before any consensus-level validation happens.

### Finding Description
`parse_sexp_to_condition()` does: [1](#0-0) 
`op = first[0].atom` is taken directly from puzzle output and passed straight into `ConditionOpcode(op)`. If `op` is any single byte not defined in the `ConditionOpcode` enum [2](#0-1) , the Python `enum.Enum.__call__` raises a plain `ValueError`, not a `ConsensusError`.

The only caller that runs this on attacker-influenced input while catching exceptions, `conditions_for_solution()`, guards solely against `Program.EvalError`: [3](#0-2) 

This function is used by `match_clawback_puzzle()` in the wallet's clawback driver to inspect the conditions produced by running an *inner puzzle/solution pair taken from an incoming coin spend*, before any legitimacy check of that puzzle's semantics is performed: [4](#0-3) 

Only the `ClawbackMetadata.from_bytes(...)` call inside the loop is wrapped in `try/except Exception`; the `conditions_for_solution(...)` call itself, which is where the unguarded `ValueError` would be raised, sits outside any exception handler in this function.

### Impact Explanation
`match_clawback_puzzle` is invoked by the wallet during coin-received/puzzle-matching processing for coins whose puzzle curries to the P2 puzzle mod used inside the clawback merkle structure. An attacker who sends a coin to a victim wallet with such a puzzle, but whose solution runs to output a condition list containing a condition opcode byte outside the defined `ConditionOpcode` range (e.g. an unused byte value), will cause `ConditionOpcode(op)` to raise an uncaught `ValueError`. Because this call sits outside the `try/except Exception` in `match_clawback_puzzle`, the exception propagates out of the puzzle-matching path used during wallet coin processing, which can crash or halt the wallet's transaction/coin-processing loop — a spend-triggered DoS analogous to the go-tuf `checkType` panic, reachable purely by an unprivileged counterparty crafting a coin/solution the victim wallet will later attempt to interpret.

### Likelihood Explanation
Likelihood is limited by the specificity of the trigger: the attacker must construct a puzzle that matches the clawback P2 mod hash so that `match_clawback_puzzle` is invoked, and a solution that CLVM-executes to output at least one condition whose leading opcode byte is not in `ConditionOpcode`. Both are fully attacker-controlled (puzzle and solution are provided by whoever creates/sends the coin), and no signature or special privilege is required — this is reachable by any wallet user or offer/clawback counterparty transacting with the victim.

### Recommendation
Wrap the `ConditionOpcode(op)` conversion in `parse_sexp_to_condition()` to raise `ConsensusError(Err.INVALID_CONDITION, ...)` on `ValueError` (mirroring the handling already done for a missing/oversized opcode atom), or broaden the `except` clause in `conditions_for_solution()` to catch `ValueError` in addition to `Program.EvalError`. Additionally, wrap the `conditions_for_solution(...)` call inside `match_clawback_puzzle()` in the same `try/except Exception` that already guards the metadata-parsing logic, so that malformed/unexpected puzzle output cannot escape as an unhandled exception during wallet coin processing.

### Proof of Concept
1. Construct a coin whose puzzle curries to `P2_CURRIED_PUZZLE_MOD` (matching the shape `match_clawback_puzzle` looks for) but whose inner puzzle/solution, when run via `conditions_for_solution`, outputs a condition list `((99 ...))` where `99` is not a defined `ConditionOpcode` value.
2. Send this coin to a victim wallet that has clawback support enabled.
3. When the wallet processes the incoming coin and calls `match_clawback_puzzle(unknown_puzzle, inner_puzzle, inner_solution)`, `conditions_for_solution` → `parse_sexp_to_conditions` → `parse_sexp_to_condition` executes `ConditionOpcode(bytes([99]))`, raising an uncaught `ValueError` that propagates out of `match_clawback_puzzle`, halting/crashing the wallet's coin-processing task.

Note: I was unable to fully trace the exact call site inside `chia/wallet/wallet_state_manager.py` that invokes `match_clawback_puzzle` (32 references to "clawback" were found there, but I ran out of tool iterations before reading the specific dispatch code that confirms it runs unguarded on every incoming coin). This should be verified before treating the wallet-crash impact as fully confirmed at that call site.

def parse_sexp_to_condition(sexp: Program) -> ConditionWithArgs:
    """
    Takes a ChiaLisp sexp and returns a ConditionWithArgs.
    Raises an ConsensusError if it fails.
    """
    first = sexp.pair
    if first is None:
        raise ConsensusError(Err.INVALID_CONDITION, ["first is None"])
    op = first[0].atom
    if op is None or len(op) != 1:
        raise ConsensusError(Err.INVALID_CONDITION, ["invalid op"])

    # since the ConditionWithArgs only has atoms as the args, we can't parse
    # hints and memos with this function. We just exit the loop if we encounter
    # a pair instead of an atom
    vars: list[bytes] = []
    for arg in Program(first[1]).as_iter():
        a = arg.atom
        if a is None:
            break
        vars.append(a)
        # no condition (currently) has more than 3 arguments. Additional
        # arguments are allowed but ignored
        if len(vars) > 3:
            break

    return ConditionWithArgs(ConditionOpcode(op), vars)

def conditions_for_solution(
    puzzle_reveal: Program | SerializedProgram, solution: Program | SerializedProgram, max_cost: int
) -> list[ConditionWithArgs]:
    # get the standard script for a puzzle hash and feed in the solution
    try:
        _cost, r = run_with_cost(puzzle_reveal, max_cost, solution)

        raise ConsensusError(Err.SEXP_ERROR, [str(e)]) from e

def match_clawback_puzzle(
    unknown_puzzle: UnknownPuzzle,
    inner_puzzle: Program | SerializedProgram,
    inner_solution: Program | SerializedProgram,
) -> ClawbackMetadata | None:
    # Check if the inner puzzle is a P2 puzzle
    if MOD != unknown_puzzle.mod:
        return None
    if not isinstance(inner_puzzle, SerializedProgram):
        inner_puzzle = inner_puzzle.to_serialized()
    if not isinstance(inner_solution, SerializedProgram):
        inner_solution = inner_solution.to_serialized()
    # Fetch Remark condition
    conditions = conditions_for_solution(
        inner_puzzle,
        inner_solution,
        DEFAULT_CONSTANTS.MAX_BLOCK_COST_CLVM // 8,
    )
    metadata: ClawbackMetadata | None = None
    new_puzhash: set[bytes32] = set()
    if conditions is not None:
        for condition in conditions:
            if (
                condition.opcode == ConditionOpcode.REMARK
                and len(condition.vars) == 2
                and int.from_bytes(condition.vars[0], "big") == RemarkDataType.CLAWBACK
            ):
                try:
                    metadata = ClawbackMetadata.from_bytes(VersionedBlob.from_bytes(condition.vars[1]).blob)
                except Exception:
                    # Invalid Clawback metadata
                    log.error(f"Invalid Clawback metadata {condition.vars[1].hex()}")
                    return None
