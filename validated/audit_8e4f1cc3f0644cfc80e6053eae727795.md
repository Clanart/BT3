### Title
Unbounded length-prefix read in `is_atom_canonical()` causes an unhandled `IndexError` on a crafted spend-bundle solution/puzzle-reveal, halting spend-bundle processing - (File: chia/full_node/mempool_manager.py)

### Summary
`is_atom_canonical()`, used by `is_clvm_canonical()` in `chia/full_node/mempool_manager.py`, decodes CLVM atom length-prefix bytes from a caller-supplied buffer without ever verifying that the number of continuation bytes it reads (`prefix_len`, up to 5) actually exist in the buffer. This is the same bug class as CVE-2018-8796 (rdesktop `process_bitmap_updates()`): a length/tag byte is read and used to drive further byte reads without checking the read stays within the buffer.

### Finding Description
`is_atom_canonical()`: [1](#0-0) 
reads `b = clvm_buffer[offset]`, determines a `prefix_len` (0–5) from the high bits of `b`, and then loops `prefix_len` times doing `offset += 1; atom_len |= clvm_buffer[offset]` with no bounds check that `offset < len(clvm_buffer)`. If the buffer ends right after a multi-byte length-prefix tag (e.g. a trailing `0xFC` byte, which signals "5 more continuation bytes follow"), the loop indexes past the end of `clvm_buffer` and Python raises an uncaught `IndexError`.

`is_clvm_canonical()` calls `is_atom_canonical()` on every non-pair, non-small atom encountered while walking the buffer: [2](#0-1) 

This function is invoked unconditionally, for every coin spend in every submitted spend bundle, in `MempoolManager.validate_spend_bundle()`: [3](#0-2) 
i.e. `is_clvm_canonical(bytes(coin_spend.puzzle_reveal))` and `is_clvm_canonical(bytes(coin_spend.solution))` run on attacker-controlled bytes as part of ordinary mempool admission, reachable by any unprivileged spend-bundle submitter (`add_spend_bundle()` → `validate_spend_bundle()`), with no try/except around the call: [4](#0-3) 

Unlike the rdesktop OOB read (native memory read → segfault), Python bounds-checks list/bytes indexing, so the practical effect is a raised `IndexError` rather than memory corruption — but the analog holds at the bug-class level: a length/tag byte drives further unchecked reads on untrusted input reachable pre-validation.

### Impact Explanation
Because the call site in `validate_spend_bundle()` has no exception handling around the `is_clvm_canonical()` calls, the `IndexError` propagates up through `add_spend_bundle()`. Whether this crashes the whole full node process, only kills the asyncio task handling that specific transaction, or is caught by a more generic exception handler further up the call stack (e.g., in the API/RPC message-processing layer) could not be conclusively determined from the code visible in this pass — no outer `try/except` was found within `mempool_manager.py` itself. If uncaught anywhere in the stack, this is at minimum a spend-triggered halt of processing for that transaction/connection, and potentially a broader denial-of-service if it escapes the per-task exception boundary of the full node's message dispatcher.

### Likelihood Explanation
High reachability: the crafted bytes only need to appear as a coin spend's `puzzle_reveal` or `solution` inside a spend bundle submitted via the normal transaction-propagation/RPC path — no privileged access, valid signature bypass, or special network position is required to trigger the parsing bug itself (though the bundle would presumably still need to reach `validate_spend_bundle()`, i.e. pass earlier CLVM/signature validation gates not fully traced here).

### Recommendation
Add explicit bounds checks in `is_atom_canonical()` before dereferencing `clvm_buffer[offset]` in the continuation-byte loop (and before the initial `clvm_buffer[offset]` read in `is_clvm_canonical()`'s loop), raising a clean `ValueError`/returning "not canonical" instead of relying on Python's `IndexError`. Wrap the call sites in `validate_spend_bundle()` (or the canonical-check functions themselves) to treat any parsing failure as `Err.INVALID_COIN_SOLUTION` rather than letting an exception propagate.

### Proof of Concept
Construct a `solution` (or `puzzle_reveal`) buffer whose last byte is a multi-byte atom length-prefix tag with no following continuation bytes, e.g.:
```python
from chia.full_node.mempool_manager import is_clvm_canonical

# 0xFC = "1 + 8*5 bits length prefix" tag requiring 5 more bytes that are absent
buf = bytes.fromhex("fc")
is_clvm_canonical(buf)   # raises IndexError instead of returning False
```
Embedding such a buffer as a `CoinSpend.solution` (with a syntactically-valid enough prefix, e.g. `b"\xff\xff" + b"\xfc"`, so it is reached as a genuine atom during the `is_clvm_canonical` walk) and submitting it as part of a `SpendBundle` drives execution into `validate_spend_bundle()`'s canonical check at line 723, raising the unhandled `IndexError`.

**Uncertainty**: I could not fully trace the exception-handling boundary above `add_spend_bundle()` (e.g., in the full-node API/RPC transaction-intake code) within the available index to confirm whether the `IndexError` is caught generically somewhere and merely logged, or whether it truly disrupts request/task processing. This should be verified directly against `chia/full_node/full_node.py` / `full_node_api.py` transaction-intake handlers before treating this as more than a locally-scoped exception.

def is_atom_canonical(clvm_buffer: bytes, offset: int) -> tuple[int, bool]:
    b = clvm_buffer[offset]
    if (b & 0b11000000) == 0b10000000:
        # 6 bits length prefix
        mask = 0b00111111
        prefix_len = 0
        min_value = 1
    elif (b & 0b11100000) == 0b11000000:
        # 5 + 8 bits length prefix
        mask = 0b00011111
        prefix_len = 1
        min_value = 1 << 6
    elif (b & 0b11110000) == 0b11100000:
        # 4 + 8 + 8 bits length prefix
        mask = 0b00001111
        prefix_len = 2
        min_value = 1 << (5 + 8)
    elif (b & 0b11111000) == 0b11110000:
        # 3 + 8 + 8 + 8 bits length prefix
        mask = 0b00000111
        prefix_len = 3
        min_value = 1 << (4 + 8 + 8)
    elif (b & 0b11111100) == 0b11111000:
        # 2 + 8 + 8 + 8 + 8 bits length prefix
        mask = 0b00000011
        prefix_len = 4
        min_value = 1 << (3 + 8 + 8 + 8)
    elif (b & 0b11111110) == 0b11111100:
        # 1 + 8 + 8 + 8 + 8 + 8 bits length prefix
        mask = 0b00000001
        prefix_len = 5
        min_value = 1 << (2 + 8 + 8 + 8 + 8)

    atom_len = b & mask
    for i in range(prefix_len):
        atom_len <<= 8
        offset += 1
        atom_len |= clvm_buffer[offset]

    return 1 + prefix_len + atom_len, atom_len >= min_value
```

def is_clvm_canonical(clvm_buffer: bytes) -> bool:
    """
    checks whether the CLVM serialization is all canonical representation.
    atoms can be serialized in more than one way by using more bytes than
    necessary to encode the length prefix. This functions ensures that all atoms are
    encoded with the shortest representation. back-references are not allowed
    and will make this function return false
    """
    assert clvm_buffer != b""

    offset = 0
    tokens_left = 1
    while True:
        b = clvm_buffer[offset]

        # pair
        if b == 0xFF:
            tokens_left += 1
            offset += 1
            continue

        # back references cannot be considered canonical, since they may be
        # encoded in many different ways
        if b == 0xFE:
            return False

        # small atom or NIL
        if b <= 0x80:
            tokens_left -= 1
            offset += 1
        else:
            atom_len, canonical = is_atom_canonical(clvm_buffer, offset)
            if not canonical:
                return False
            tokens_left -= 1
            offset += atom_len

        if tokens_left == 0:
            break

    # if there's garbage at the end, it's not canonical
    return offset == len(clvm_buffer)
```

    async def add_spend_bundle(
        self,
        new_spend: SpendBundle,
        conds: SpendBundleConditions,
        spend_name: bytes32,
        first_added_height: uint32,
        get_coin_records: Callable[[Collection[bytes32]], Awaitable[list[CoinRecord]]] | None = None,
        get_unspent_lineage_info_for_puzzle_hash: Callable[[bytes32], Awaitable[UnspentLineageInfo | None]]
        | None = None,
    ) -> SpendBundleAddInfo:
        """
        Validates and adds to mempool a new_spend with the given
        SpendBundleConditions, and spend_name, and the current mempool. The mempool
        should be locked during this call (blockchain lock). If there are mempool
        conflicts, the conflicting spends might be removed (if the new spend is
        a superset of the previous). Otherwise, the new spend might be
        added to the potential pool.

        Args:
            new_spend: spend bundle to validate and add
            conds: SpendBundleConditions resulting from running the clvm in the spend bundle's coin spends
            spend_name: hash of the spend bundle data, passed in as an optimization

        Returns:
            Optional[uint64]: cost of the entire transaction, None iff status is FAILED
            MempoolInclusionStatus:  SUCCESS (should add to pool), FAILED (cannot add), and PENDING (can add later)
            list[MempoolRemoveInfo]: conflicting mempool items which were removed, if no Err
            Optional[Err]: Err is set iff status is FAILED
        """

        # Skip if already added
        existing_item = self.mempool.get_item_by_id(spend_name)
        if existing_item is not None:
            return SpendBundleAddInfo(existing_item.cost, MempoolInclusionStatus.SUCCESS, [], None)

        if get_coin_records is None:
            get_coin_records = self.get_coin_records

        if get_unspent_lineage_info_for_puzzle_hash is None:
            get_unspent_lineage_info_for_puzzle_hash = self.get_unspent_lineage_info_for_puzzle_hash

        err, item, remove_items = await self.validate_spend_bundle(
            new_spend,
            conds,
            spend_name,
            first_added_height,
            get_coin_records,
            get_unspent_lineage_info_for_puzzle_hash,
        )
        if err is None:
            # No error, immediately add to mempool, after removing conflicting TXs.
            assert item is not None
            conflict = self.mempool.remove_from_pool(remove_items, MempoolRemoveReason.CONFLICT)
            info = self.mempool.add_to_pool(item)
            if info.error is not None:
                return SpendBundleAddInfo(item.cost, MempoolInclusionStatus.FAILED, [], info.error)
            return SpendBundleAddInfo(item.cost, MempoolInclusionStatus.SUCCESS, [*info.removals, conflict], None)
        elif err is Err.MEMPOOL_CONFLICT and item is not None:
            # The transaction has a conflict with another item in the
            # mempool, put it aside and re-try it later
            self._conflict_cache.add(item)
            return SpendBundleAddInfo(item.cost, MempoolInclusionStatus.PENDING, [], err)
        elif item is not None:
            # The transasction has a height assertion and is not yet valid.
            # remember it to try it again later
            self._pending_cache.add(item)
            return SpendBundleAddInfo(item.cost, MempoolInclusionStatus.PENDING, [], err)
        else:
            # Cannot add to the mempool or pending pool.
            return SpendBundleAddInfo(None, MempoolInclusionStatus.FAILED, [], err)
