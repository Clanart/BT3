### Title
`TransferToBtcWallet` Allows Operator to Spend Unprotected `ReimburseInRound` UTXOs, Permanently Locking Vault BTC - (`core/src/operator.rs`)

### Summary

`get_all_collateral_outpoints` only enumerates `CollateralInRound` and `CollateralInReadyToReimburse` outputs as protected UTXOs. The `ReimburseInRound` outputs in every round tx pay to the **identical** key-path-only taproot script as the collateral, yet are absent from the protection map. The `TransferToBtcWallet` RPC therefore passes both the script-pubkey check and the collateral check for these outputs, allowing the operator to inadvertently sweep them to their wallet. Once spent, the `Reimburse` transaction — which requires `ReimburseInRound` as its third input — can never be broadcast, permanently locking the vault BTC and forfeiting the operator's fronted bridge amount.

### Finding Description

`create_round_txhandler` creates `num_kickoffs_per_round` reimburse connector outputs with an empty script list and the operator's xonly key as the internal key:

```rust
// Create reimburse utxos
for _ in 0..paramset.num_kickoffs_per_round {
    builder = builder.add_output(UnspentTxOut::from_scripts(
        paramset.default_utxo_amount(),
        vec![],
        Some(operator_xonly_pk),
        paramset.network,
    ));
}
``` [1](#0-0) 

This produces the same `script_pubkey` as `self.operator.signer.address` (key-path taproot, no merkle root). The `TransferToBtcWallet` RPC handler rejects any outpoint whose `script_pubkey` does not match that address:

```rust
if txout.script_pubkey != self.operator.signer.address.script_pubkey() {
    return Err(Status::invalid_argument(...));
}
``` [2](#0-1) 

After passing that check, `transfer_outpoints_to_wallet` consults `get_all_collateral_outpoints` to block collateral UTXOs: [3](#0-2) 

`get_all_collateral_outpoints` inserts only `CollateralInRound` and `CollateralInReadyToReimburse` for every round — it never inserts any `ReimburseInRound` vout: [4](#0-3) 

The `Reimburse` transaction requires `ReimburseInRound` as its third input (key-spend, `OperatorSighashDefault`): [5](#0-4) 

These connectors live in the **next** round tx (the round tx created from `CollateralInReadyToReimburse` of the current round), as explicitly noted in `create_txhandlers`: [6](#0-5) 

Once the next round tx is on-chain, every `ReimburseInRound` output at that txid is spendable by the operator's key and is invisible to the collateral guard.

### Impact Explanation

If the operator calls `TransferToBtcWallet` with a `ReimburseInRound` outpoint (e.g., while consolidating UTXOs):

1. The UTXO is swept to the operator's wallet — the bridge amount (`bridge_amount`, e.g. 10 BTC) is moved out of the protocol UTXO set.
2. The `Reimburse` tx can never be broadcast; the `DepositInMove` UTXO (vault BTC) is permanently locked until security-council emergency-stop intervention.
3. The operator forfeits the BTC they fronted for the payout, with no recovery path short of a protocol-level emergency action.

This satisfies the allowed-impact gate: **permanent lock of bridged BTC** and **loss of reimbursement outputs**.

### Likelihood Explanation

The `TransferToBtcWallet` RPC is explicitly documented as a UTXO-management tool for operators. An operator consolidating UTXOs after the next round tx lands on-chain would see multiple outputs at the operator's taproot address and could inadvertently include a `ReimburseInRound` vout. The RPC gives no warning that these outputs are protocol-critical. Likelihood is **low-medium** (requires operator error, but the RPC is designed for exactly this kind of UTXO management).

### Recommendation

Extend `get_all_collateral_outpoints` to also enumerate all `ReimburseInRound` outpoints for every round tx, mirroring the existing loop that enumerates `CollateralInRound` and `CollateralInReadyToReimburse`:

```rust
for kickoff_idx in 0..paramset.num_kickoffs_per_round {
    let reimburse_outpoint = OutPoint {
        txid: *round_tx.get_txid(),
        vout: UtxoVout::ReimburseInRound(kickoff_idx, paramset.num_kickoffs_per_round).get_vout(),
    };
    outpoints.insert(reimburse_outpoint, (round_idx, TransactionType::Round));
}
```

This ensures `transfer_outpoints_to_wallet` rejects any attempt to sweep a reimburse connector, matching the protection already in place for collateral outputs. [7](#0-6) 

### Proof of Concept

1. Operator fronts a payout for withdrawal index `W` (bridge amount = 10 BTC).
2. Operator sends `KickoffTx` for round `N`, kickoff index `K`.
3. Operator sends `ChallengeTimeoutTx` (no challenge).
4. Operator sends `ReadyToReimburseTx` for round `N`.
5. Operator sends round tx `N+1` (which contains `ReimburseInRound(K, num_kickoffs_per_round)` at a deterministic vout paying to `operator_xonly_pk` key-path taproot).
6. Operator calls `TransferToBtcWallet` with `OutPoint { txid: round_N+1_txid, vout: ReimburseInRound(K, ...).get_vout() }`.
7. RPC passes: script_pubkey matches operator address ✓; outpoint not in `get_all_collateral_outpoints` ✓.
8. `transfer_outpoints_to_wallet` signs and broadcasts the sweep tx.
9. `ReimburseInRound` UTXO is now spent; `Reimburse` tx construction fails at input 3.
10. `DepositInMove` UTXO (10 BTC vault) is permanently locked; operator loses 10 BTC fronted funds.

```rust
    /// Gets all collateral outpoints for the operator.
    /// Returns a map of outpoint to the round index it belongs to.
    async fn get_all_collateral_outpoints(
        &self,
    ) -> Result<HashMap<OutPoint, (RoundIndex, TransactionType)>, BridgeError> {
        let mut outpoints = HashMap::new();
        outpoints.insert(
            self.collateral_funding_outpoint,
            (RoundIndex::Collateral, TransactionType::Round),
        );

        // Fetch operator kickoff winternitz public keys to build round txs
        let operator_winternitz_public_keys = self
            .db
            .get_operator_kickoff_winternitz_public_keys(None, self.signer.xonly_public_key)
            .await?;
        let kickoff_wpks = KickoffWinternitzKeys::new(
            operator_winternitz_public_keys,
            self.config.protocol_paramset().num_kickoffs_per_round,
            self.config.protocol_paramset().num_round_txs,
        )?;
        let operator_data = self.data();

        let mut prev_ready_to_reimburse: Option<TxHandler> = None;

        // Collect collateral outpoints for each round
        for round_idx in RoundIndex::iter_rounds(self.config.protocol_paramset().num_round_txs) {
            let txhandlers = create_round_txhandlers(
                self.config.protocol_paramset(),
                round_idx,
                &operator_data,
                &kickoff_wpks,
                prev_ready_to_reimburse.as_ref(),
            )?;

            let round_tx = txhandlers
                .iter()
                .find(|txhandler| txhandler.get_transaction_type() == TransactionType::Round)
                .ok_or(eyre::eyre!("Round tx not found in txhandlers"))?;
            let collateral_outpoint = OutPoint {
                txid: *round_tx.get_txid(),
                vout: UtxoVout::CollateralInRound.get_vout(),
            };
            outpoints.insert(collateral_outpoint, (round_idx, TransactionType::Round));

            let ready_to_reimburse_tx = txhandlers
                .iter()
                .find(|txhandler| {
                    txhandler.get_transaction_type() == TransactionType::ReadyToReimburse
                })
                .ok_or(eyre::eyre!("Ready to reimburse tx not found in txhandlers"))?;
            let ready_to_reimburse_collateral_outpoint = OutPoint {
                txid: *ready_to_reimburse_tx.get_txid(),
                vout: UtxoVout::CollateralInReadyToReimburse.get_vout(),
            };
            outpoints.insert(
                ready_to_reimburse_collateral_outpoint,
                (round_idx, TransactionType::ReadyToReimburse),
            );
            prev_ready_to_reimburse = Some(ready_to_reimburse_tx.clone());
        }

        Ok(outpoints)
    }
