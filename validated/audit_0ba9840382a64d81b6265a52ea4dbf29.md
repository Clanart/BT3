### Title
Symlink-following file write in `writeGitAttributes` allows repo content to redirect writes outside the selected repository directory - (`app/src/ui/add-repository/git-attributes.ts`)

### Summary
`writeGitAttributes` builds `TARGET_PATH = join(path, '.gitattributes')` and calls `fs.promises.writeFile(fullPath, contents)` with no `lstat`/symlink check. [1](#0-0) 
Node's `writeFile` opens the path following symlinks by default (no `O_NOFOLLOW`), so if `.gitattributes` inside the target directory is a symlink, the write lands wherever the symlink points, not inside the repository.

### Finding Description
The only production caller is `CreateRepository.createRepository` in `app/src/ui/add-repository/create-repository.tsx`, which guards the call with an existence check: [2](#0-1) 
`pathExists` is implemented with `fs.promises.access`, which also follows symlinks: [3](#0-2) 

Because both the guard (`pathExists`) and the sink (`writeFile`) resolve symlinks the same way, the guard is effective at blocking overwrite of an *existing* target reached through a symlink — if the attacker's symlink points to a file that already exists, `pathExists` returns `true` and `writeGitAttributes` is never invoked. This means the exact scenario proposed in the proof idea ("place a symlink to a sensitive *existing* file, confirm its contents get overwritten") is prevented by the existing check in the real call path, per Review Path step 4.

However, the guard does **not** cover a dangling symlink: if `.gitattributes` in the attacker-controlled directory is a symlink pointing to a path that does not yet exist (e.g. outside the repo, such as a parent directory or a location the user has write access to but did not intend to touch), `pathExists`/`access` returns `false` for the broken link, the `!gitAttributesExists` branch is taken, and `writeGitAttributes` creates/writes the git-attributes boilerplate at the symlink's target path — outside the selected repository directory.

### Impact Explanation
This breaks the invariant that repository-creation writes stay inside the selected directory. An attacker who controls the contents of a folder the victim later chooses to "Create Repository" over can plant a dangling `.gitattributes` symlink to cause GitHub Desktop to create/write an attacker-chosen file at an arbitrary filesystem location the user has permissions to write to. This matches the "file write... outside the repo" category in Valid Impact, though the achievable effect is limited to writing fixed, non-attacker-controlled content (`* text=auto` boilerplate) to a new file at an attacker-chosen path, not corrupting the contents of a pre-existing file (that specific stronger case is blocked by the `pathExists` guard in the real call site).

### Likelihood Explanation
Requires the victim to run "Create Repository" over a folder whose contents are attacker-controlled and already contain a dangling symlink named `.gitattributes` — a plausible but non-default workflow (this happens if a user extracts or clones untrusted content into a folder and then chooses "create repository" on it rather than using normal clone). Symlink creation is unprivileged on Unix-like systems.

### Recommendation
In `writeGitAttributes`, use `open`/`writeFile` with the `wx`... actually recommend checking `lstat` on `fullPath` first and refusing to write (or removing the symlink) if it is a symlink, rather than relying on a follow-symlink existence check performed by the caller. Consistently `lstat` (not `access`/`stat`) both in the caller's existence check and before writing, so dangling or pointing symlinks inside the target directory are detected and rejected before any write occurs.

### Proof of Concept
1. On a Unix-like system, create folder `victim-repo/` and inside it: `ln -s /tmp/outside-target.txt victim-repo/.gitattributes` (target `/tmp/outside-target.txt` does not exist yet).
2. In GitHub Desktop, choose "Create Repository" and select `victim-repo/` as the path.
3. `create-repository.tsx` calls `pathExists(join(fullPath, '.gitattributes'))`; since the symlink is dangling, this resolves to `false`. [4](#0-3) 
4. `writeGitAttributes(fullPath)` is invoked, and `fs.promises.writeFile` follows the symlink, creating `/tmp/outside-target.txt` with the git-attributes boilerplate content — a file outside `victim-repo/`. [1](#0-0)

```typescript
import { access } from 'fs/promises'
import constant from 'lodash/constant'

/**
 * Returns a value indicating whether or not the provided path exists (as in
 * whether it's visible to the current process or not).
 */
export const pathExists = (path: string) =>
  access(path).then(constant(true), constant(false))
```
