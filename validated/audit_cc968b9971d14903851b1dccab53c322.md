### Title
Stale-content overwrite in Copilot conflict resolution write path silently discards in-progress user edits - ([File: app/src/lib/stores/app-store.ts])

### Summary
This is a genuine analog to the report's broken invariant: data captured at one point in time (an earlier "height"/state) is later reused as if it still matches the "current" state, without re-validating that the two are consistent. In the Cosmos report, `LastCommitInfo` (latest state) was used to build a proof for a query at a specific historical height. In GitHub Desktop's Copilot conflict-resolution feature, the file content read from disk at the start of a (potentially multi-minute) AI resolution turn (`ctx.rawContent`) is spliced with the model's hunk output and later written back to disk based on a staleness check that only detects *full* resolution, not *any* intervening edit.

### Finding Description
`gatherConflictResolutionContext` → `buildConflictContext` reads each conflicted file's content once via `readFile`, captured in `IFileConflictContext.rawContent` [1](#0-0) . This snapshot is sent to the model, and after the model responds, `reassembleResolutions` splices the model's per-hunk `resolvedContent` into `ctx.rawContent` — the content read minutes earlier — to produce the full file text: [2](#0-1) .

The Copilot turn can run for a long time — the app itself tracks buckets up to 120+ seconds (`copilotConflictResolutionOver120sCount`) [3](#0-2) , and multi-file/chunked resolution can take even longer since chunks run with bounded concurrency across a 600s-per-turn timeout [4](#0-3) . After the model returns, the result is shown in a dialog and file writes are explicitly deferred until the user clicks "Continue Merge" [5](#0-4) , adding further arbitrary delay controlled by the user reviewing the summary.

When the user confirms, `_applyCopilotConflictResolutions` writes `resolution.resolvedContent` (derived from the *stale* `rawContent` snapshot) straight to `absolutePath`, gated only by this check:

```
const onDiskFile = state.changesState.workingDirectory.files.find(f => f.path === resolution.path)
if (onDiskFile !== undefined && isConflictedFileStatus(onDiskFile.status) && !hasUnresolvedConflicts(onDiskFile.status)) {
  continue
}
await writeFile(absolutePath, resolution.resolvedContent, 'utf8')
``` [6](#0-5) 

This guard only skips the write when the file has become *fully* resolved externally (no remaining `<<<<<<<`/`=======`/`>>>>>>>` markers). It does not compare the current on-disk content against `ctx.rawContent`/the byte content the resolution was computed from. Any edit made to the conflicted file during the resolution window that leaves at least one conflict marker in place — e.g., the user manually fixes one hunk in an external editor but a second hunk in the same file is untouched, or the user adds/removes surrounding code — is silently discarded when Copilot's write overwrites the file with content reconstructed from the older snapshot.

This mirrors the report's exact broken invariant: a value from an earlier point in time (`LastCommitInfo` / `rawContent`) is treated as authoritative for "now" (`req.Height` / the file's current on-disk state) without verifying consistency, and no re-read/re-diff/hash check exists to catch drift.

### Impact Explanation
The result is silent corruption of what the user commits: intervening manual edits to a still-conflicted file are overwritten by content reconstructed from a stale snapshot, without any warning, diff, or confirmation that content changed underneath the resolution. Because the write happens automatically on "Continue Merge" and is staged with `git add` immediately after [7](#0-6) , the discarded work can be committed and pushed before the user notices, matching the "silent corruption of what the user commits or pushes" impact category.

### Likelihood Explanation
This requires only normal usage: starting Copilot conflict resolution (which can run for tens of seconds to several minutes across multiple files/chunks) and editing a conflicted file (without fully removing all markers) while the resolution is in flight or while reviewing the result dialog before clicking "Continue Merge." No admin rights, malware, or unusual steps are needed — a user working in a code editor alongside Desktop during a long-running AI resolution is a natural workflow.

### Recommendation
Before writing `resolution.resolvedContent`, re-read the file's current on-disk content (or compare a hash/snapshot captured at context-gathering time) and diff it against `ctx.rawContent`. If the current content differs from what the resolution was computed against, refuse to overwrite and instead surface the conflict to the user (e.g., flag it in the result dialog as "changed outside Desktop, please resolve manually") rather than relying solely on `hasUnresolvedConflicts` full-resolution detection.

### Proof of Concept
1. Have a repo with a merge conflict in `foo.ts` containing two conflict hunks.
2. Click "Resolve with Copilot"; the app reads `foo.ts` into `rawContent` and sends it to the model.
3. While the model is still processing (or while the result dialog is open, before clicking "Continue Merge"), open `foo.ts` in an external editor and manually resolve the *first* hunk only, leaving the second hunk's markers intact, then save.
4. Click "Continue Merge" in Desktop.
5. `_applyCopilotConflictResolutions` sees `foo.ts` still has unresolved conflict markers (`hasUnresolvedConflicts` is true), so it does not skip the write; it overwrites `foo.ts` with `reassembleResolvedFile(rawContent, ...)` built from the pre-edit snapshot, discarding the user's manual fix to the first hunk without any warning.

export function reassembleResolutions(
  rawResolutions: ReadonlyArray<IRawFileResolution>,
  fileContexts: ReadonlyArray<IFileConflictContext>
): ReadonlyArray<IFileResolution> {
  const contextByPath = new Map(fileContexts.map(f => [f.path, f]))

  return rawResolutions.map(raw => {
    // Delete-vs-modify resolutions carry an action, not hunk content.
    // Pass through without reassembly — the resolution is applied as a
    // ManualConflictResolution, not a file write.
    if (raw.action !== undefined) {
      return {
        path: raw.path,
        resolvedContent: '',
        reasoning: raw.reasoning,
        deleteConflictAction: raw.action,
      }
    }

    const ctx = contextByPath.get(raw.path)
    if (ctx?.rawContent === undefined) {
      throw new CopilotValidationError(
        `Cannot reassemble resolution for "${raw.path}": original file content is unavailable`
      )
    }

    const resolvedContent = reassembleResolvedFile(ctx.rawContent, raw.hunks)
    return {
      path: raw.path,
      resolvedContent,
      reasoning: raw.reasoning,
    }
  })
