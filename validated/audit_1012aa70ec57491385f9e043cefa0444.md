### Title
Funds sent to an EVM cast-address before association become permanently locked once that EVM address is associated to a different owner - (File: `giga/deps/xevm/keeper/address.go`, `utils/helpers/associate.go`)

### Summary
`CanAddressReceive`/`CanAddressSend`-style checks in the EVM keeper treat `sdk.AccAddress(evmAddr[:])` (the "cast address") as spendable only while the corresponding EVM address is unassociated. Anyone can permissionlessly send `usei`/wei to a cast address before its owner ever associates. Once association happens — which any third party can trigger for many EVM addresses via `MsgAssociateContractAddress`/native association — the cast address becomes blocked from sending, and there is no user-facing message that lets the original depositor reclaim the balance left behind; the only recovery path found in the repo is the one-time `MigrateCastAddressBalances` upgrade routine, not something reachable via a normal transaction.

### Finding Description
`CanAddressReceive` returns `false` for a cast address once it is associated with a real Sei address other than itself, and the same association gate is used to determine whether a cast address may act as a sender going forward: [1](#0-0) . `TestSendingToCastAddress` confirms this concretely: coins sent to `castAddr` succeed before association, but after `SetAddressMapping` is called for the underlying EVM address, subsequent sends *from* the cast address (`SendCoinsFromModuleToAccount`, `SendCoins`, `SendCoinsAndWei`) all fail [5](#0-4) .

Association can be triggered any time after the deposit — e.g. by `MsgAssociateContractAddress`, native association flows, or `AssociationHelper.AssociateAddresses`, which is the only code path that migrates the cast address's balance to the newly associated owner: [4](#0-3) . That helper only runs during the specific association transaction for the seiAddr that is being associated to that evmAddr — it does not run, and cannot be invoked by the original depositor, if the association is performed by/for a different chain flow (e.g. contract registration, upgrade-time association, or association initiated by someone other than the depositor) after the deposit was already made. Absent this exact code path executing, funds already sitting at the cast address are permanently unrecoverable by ordinary transaction, mirroring the reported bug where `withdrawFromForkEscrow` can only call the DAO-only `returnTokensToOwner`, leaving escrowed tokens stuck once the DAO swaps the escrow reference out from under already-escrowed users.

The repo's own migration `MigrateCastAddressBalances` — used only during a chain upgrade, not as a user transaction — demonstrates the maintainers are aware cast-address balances can be stranded and require a privileged sweep rather than a general user-callable rescue: [3](#0-2) .

### Impact Explanation
Any `usei` or wei sent to an EVM address's cast address before it is associated is at risk of becoming permanently frozen the moment that association happens through any path other than the exact `AssociateAddresses`/`MigrateBalance` flow for that specific depositor. Because deposits to unassociated cast addresses are a normal, unprivileged occurrence (e.g., third parties funding a not-yet-onboarded EVM account), and association can be completed independently of the depositor's knowledge or consent, this is a fund-freezing bug reachable purely through ordinary transactions.

### Likelihood Explanation
Medium-to-high: sending funds to not-yet-associated EVM addresses is a normal and expected user flow on Sei (funding a new EVM wallet before its first transaction), and association of a given EVM address can be completed by the address owner (or triggered by pointer/contract flows) independent of every party that has sent funds to the cast address in the interim.

### Recommendation
Provide a permissionless, user-callable message (e.g., a `RecoverCastAddressBalance` or similar) that sweeps any residual usei/wei balance held at `sdk.AccAddress(evmAddr[:])` to the currently associated Sei address for that EVM address, callable at any time after association, rather than relying solely on the balance migration performed inline during the association transaction or during a chain upgrade.

### Proof of Concept
1. Without associating `evmAddr`, have any account send `usei` to `castAddr := sdk.AccAddress(evmAddr[:])` — this succeeds because `CanAddressReceive` returns `true` for an unassociated cast address [1](#0-0) .
2. A third party (or the eventual owner via a flow other than the exact `AssociateAddresses` transaction that also runs `MigrateBalance`) associates `evmAddr` to a Sei address, e.g. via `SetAddressMapping`.
3. Attempt to move the balance out of `castAddr` — `SendCoins`/`SendCoinsFromModuleToAccount`/`SendCoinsAndWei` from `castAddr` now fail, as shown in `TestSendingToCastAddress` [6](#0-5) , and no user-facing message exists to redirect the stranded balance to the associated owner outside of the one-time upgrade migration [3](#0-2) .

func (k *Keeper) CanAddressReceive(ctx sdk.Context, addr sdk.AccAddress) bool {
	directCast := common.BytesToAddress(addr) // casting goes both directions since both address formats have 20 bytes
	associatedAddr, isAssociated := k.GetSeiAddress(ctx, directCast)
	// if the associated address is the cast address itself, allow the address to receive (e.g. EVM contract addresses)
	return associatedAddr.Equals(addr) || !isAssociated // this means it's either a cast address that's not associated yet, or not a cast address at all.
}

package migrations

import (
	"github.com/ethereum/go-ethereum/common"
	sdk "github.com/sei-protocol/sei-chain/sei-cosmos/types"
	"github.com/sei-protocol/sei-chain/x/evm/keeper"
)

func MigrateCastAddressBalances(ctx sdk.Context, k *keeper.Keeper) (rerr error) {
	k.IterateSeiAddressMapping(ctx, func(evmAddr common.Address, seiAddr sdk.AccAddress) bool {
		castAddr := sdk.AccAddress(evmAddr[:])
		if balances := k.BankKeeper().SpendableCoins(ctx, castAddr); !balances.IsZero() {
			if err := k.BankKeeper().SendCoins(ctx, castAddr, seiAddr, balances); err != nil {
				logger.Error("error migrating balances from cast to real for address", "address", evmAddr, "err", err)
				rerr = err
				return true
			}
		}
		if wei := k.BankKeeper().GetWeiBalance(ctx, castAddr); !wei.IsZero() {
			if err := k.BankKeeper().SendCoinsAndWei(ctx, castAddr, seiAddr, sdk.ZeroInt(), wei); err != nil {
				logger.Error("error migrating wei from cast to real for address", "address", evmAddr, "err", err)
				rerr = err
				return true
			}
		}
		return false
	})
	return
}

func (p AssociationHelper) AssociateAddresses(ctx sdk.Context, seiAddr sdk.AccAddress, evmAddr common.Address, pubkey cryptotypes.PubKey, migrateUseiOnly bool) error {
	castAddr := sdk.AccAddress(evmAddr[:])
	if !castAddr.Equals(seiAddr) && p.accountKeeper.GetAccount(ctx, seiAddr) == nil {
		castAcc := p.accountKeeper.GetAccount(ctx, castAddr)
		castBaseAcc, ok := castAcc.(*authtypes.BaseAccount)
		if ok && castBaseAcc.GetPubKey() == nil && p.bankKeeper.LockedCoins(ctx, castAddr).IsZero() {
			p.accountKeeper.SetAccount(ctx, authtypes.NewBaseAccount(seiAddr, pubkey, castBaseAcc.GetAccountNumber(), castBaseAcc.GetSequence()))
		}
	}
	p.evmKeeper.SetAddressMapping(ctx, seiAddr, evmAddr)
	acc := p.accountKeeper.GetAccount(ctx, seiAddr)
	if acc == nil {
		acc = p.accountKeeper.NewAccountWithAddress(ctx, seiAddr)
	}
	if acc.GetPubKey() == nil {
		if err := acc.SetPubKey(pubkey); err != nil {
			return err
		}
		p.accountKeeper.SetAccount(ctx, acc)
	}
	return p.MigrateBalance(ctx, evmAddr, seiAddr, migrateUseiOnly)
}

func (p AssociationHelper) MigrateBalance(ctx sdk.Context, evmAddr common.Address, seiAddr sdk.AccAddress, migrateUseiOnly bool) error {
	castAddr := sdk.AccAddress(evmAddr[:])
	if castAddr.Equals(seiAddr) {
		return nil
	}
	var castAddrBalances sdk.Coins
	if migrateUseiOnly {
		castAddrBalances = sdk.Coins{p.bankKeeper.GetBalance(ctx, castAddr, "usei")}
	} else {
		castAddrBalances = p.bankKeeper.SpendableCoins(ctx, castAddr)
	}
	if !castAddrBalances.IsZero() {
		if err := p.bankKeeper.SendCoins(ctx, castAddr, seiAddr, castAddrBalances); err != nil {
			return err
		}
	}
	castAddrWei := p.bankKeeper.GetWeiBalance(ctx, castAddr)
	if !castAddrWei.IsZero() {
		if err := p.bankKeeper.SendCoinsAndWei(ctx, castAddr, seiAddr, sdk.ZeroInt(), castAddrWei); err != nil {
			return err
		}
	}
	if p.bankKeeper.LockedCoins(ctx, castAddr).IsZero() {
		p.accountKeeper.RemoveAccount(ctx, authtypes.NewBaseAccountWithAddress(castAddr))
	}
	return nil
}
