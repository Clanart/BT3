## Title
Spoofed `WWW-Authenticate: realm="GitHub"` header from an untrusted git remote causes Desktop to treat an attacker-controlled host as a trusted GitHub Enterprise endpoint - (File: `app/src/lib/trampoline/trampoline-credential-helper.ts`)

### Summary
`getEndpointKind` classifies a git remote host as `'github.com'`, `'enterprise'`, or `'generic'` in order to decide how to handle credential requests coming from git's credential-helper trampoline. Part of that classification trusts the `wwwauth[...]` fields that git forwards verbatim from the remote server's HTTP `WWW-Authenticate` response header, without any independent verification.

### Finding Description
When git performs HTTP(S) authentication, the target server's `WWW-Authenticate` response header is captured by git and passed to the credential helper as `wwwauth[N]` fields. `getEndpointKind` uses this attacker-supplied value as a "happy path" signal: [1](#0-0) 

If the header contains `realm="GitHub"`, the function immediately returns `'enterprise'` — before ever making an actual request to confirm the host is really a GitHub Enterprise instance (that verification only happens later, via `isGitHubHost(endpoint)`, and only if the wwwauth branch didn't already short-circuit): [2](#0-1) 

Because a completely untrusted remote server controls the content of its own `WWW-Authenticate` header, it can set `realm="GitHub"` and be classified as `'enterprise'` even though `isDotCom`/`isGHE`/`findGitHubTrampolineAccount` all failed to match it.

This classification feeds directly into `getCredential`: [3](#0-2) 

Since the malicious endpoint will not match any stored account's `apiEndpoint`, Desktop calls `ui.promptForGitHubSignIn(endpoint)`, which for a non-`github.com` hostname starts the **Enterprise** sign-in flow and points it at the attacker's own origin: [4](#0-3) 

`dispatcher.setSignInEndpoint(origin)` sets the sign-in target to the attacker's origin, so any subsequent authentication (OAuth authorization request, or basic-auth style enterprise login depending on GHES version) is directed at the attacker-controlled server rather than a host the user ever configured or trusted.

### Impact Explanation
A user does not need to click any link — simply cloning or fetching from a malicious HTTP(S) remote is enough to trigger this. The remote can force Desktop's normal git-credential prompt into becoming a "Sign in to GitHub Enterprise" dialog pointed at the attacker's server. If the user completes that flow (entering a PAT/password, or completing an OAuth authorization believing they are authenticating to a legitimate GitHub Enterprise instance), the credential/authorization exchange happens with the attacker's server, resulting in credential or OAuth-token exfiltration to a host the user never authorized.

### Likelihood Explanation
Exploitation requires no privileged access — only the ability to control the HTTP response of a git remote (self-hosted `http(s)://` remote, or a compromised/typosquatted host), which is exactly the "malicious HTTP server" scenario in scope. The `realm="GitHub"` string is trivial for any HTTP server to add to its `WWW-Authenticate` header. The main mitigating factor is that it requires the user to complete the resulting sign-in dialog (i.e., some user interaction with a dialog that will look identical to the legitimate GHE sign-in prompt they'd normally expect for such a remote).

### Recommendation
Do not trust the `WWW-Authenticate: realm="GitHub"` (or GitLab/Gitea/Bitbucket) heuristic as sufficient proof of host identity for anything beyond a low-stakes UI hint. Before triggering the enterprise sign-in flow or bypassing the generic-credential path, corroborate the header with an actual `isGitHubHost(endpoint)` API probe (the check already present later in the function), or restrict use of the `wwwauth` signal strictly to cases where the endpoint has already been explicitly added as an Enterprise server by the user.

### Proof of Concept
1. Host a git-over-HTTP(S) server at `https://evil.example.com/repo.git` (any git-http-backend implementation) configured to reply to unauthenticated requests with `WWW-Authenticate: Basic realm="GitHub"`.
2. In GitHub Desktop, clone or add `https://evil.example.com/repo.git` as a remote and fetch.
3. Git captures the header and forwards `wwwauth[0]=Basic realm="GitHub"` to the trampoline credential helper.
4. `getEndpointKind` returns `'enterprise'` for `evil.example.com` purely from the spoofed header.
5. `getCredential` calls `ui.promptForGitHubSignIn('https://evil.example.com')`, which invokes `dispatcher.beginEnterpriseSignIn` and `dispatcher.setSignInEndpoint('https://evil.example.com')`, directing the Enterprise sign-in UI at the attacker's origin.

**Note:** I was unable to trace beyond `trampoline-ui-helper.ts` into the exact `dispatcher.beginEnterpriseSignIn`/`SignInStore` implementation (e.g., whether it uses OAuth-only or also basic auth, and what exact network calls are issued to the attacker origin), since those files were not returned by my searches. Confirming the precise data sent to the attacker's server during the resulting sign-in flow would require reading `app/src/lib/stores/sign-in-store.ts` and the `SignIn` popup component directly.

  // When Git attempts to authenticate with a host it captures any
  // WWW-Authenticate headers and forwards them to the credential helper. We
  // use them as a happy-path to determine if the host is a GitHub host without
  // having to resort to making a request ourselves.
  for (const [k, v] of cred.entries()) {
    if (k.startsWith('wwwauth[')) {
      if (v.includes('realm="GitHub"')) {
        return 'enterprise'
      } else if (/realm="(GitLab|Gitea|Atlassian Bitbucket)"/.test(v)) {
        return 'generic'
      }
    }
  }

  public promptForGitHubSignIn(endpoint: string): Promise<Account | undefined> {
    return new Promise<Account | undefined>(async resolve => {
      const cb = (result: SignInResult) => {
        resolve(result.kind === 'success' ? result.account : undefined)
        this.dispatcher.closePopup(PopupType.SignIn)
      }

      const { hostname, origin } = new URL(endpoint)
      if (hostname === 'github.com') {
        this.dispatcher.beginDotComSignIn(cb)
      } else {
        this.dispatcher.beginEnterpriseSignIn(cb)
        await this.dispatcher.setSignInEndpoint(origin)
      }

      this.dispatcher.showPopup({
        type: PopupType.SignIn,
        isCredentialHelperSignIn: true,
        credentialHelperUrl: endpoint,
      })
