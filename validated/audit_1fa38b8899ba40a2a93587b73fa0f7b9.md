## Title
Embedded NUL byte in a text-classified diff can cause `diffFromRawDiffOutput()` to silently discard the leading portion of the diff, hiding attacker-controlled content from the Changes view — ([File: app/src/lib/git/diff.ts])

### Summary
`diffFromRawDiffOutput()` blindly assumes that the only NUL bytes present in `git diff ... -z --patch-with-raw` output are the ones Git uses to separate the raw/numstat preamble from the textual patch body, and that taking the *last* `\0`-delimited fragment (`pieces.at(-1)`) is always equivalent to "the patch text." That assumption breaks when the patch body itself contains a literal NUL byte, which Git can legitimately emit for a file it decides to treat as text. [1](#0-0) 

### Finding Description
`diffFromRawDiffOutput` is the single choke point used by every path that renders a diff from `git diff`/`git log --patch-with-raw -z`:

- `getWorkingDirectoryDiff` [2](#0-1) 
- `getCommitDiff` [3](#0-2) 
- `getBranchMergeBaseDiff` [4](#0-3) 
- `getCommitRangeDiff` [5](#0-4) 
- `buildDiff` (which all of the above funnel into) [6](#0-5) 

All of these pass `-z` to Git specifically so the raw/numstat portion is NUL-terminated instead of newline/quote-encoded. `diffFromRawDiffOutput` then does:

```ts
const result = output.toString('utf-8')
const pieces = result.split('\0')
return parser.parse(forceUnwrap(`Invalid diff output`, pieces.at(-1)))
``` [1](#0-0) 

This implicitly assumes the *patch body itself* never contains a raw NUL byte — only Git's own raw/numstat preamble does. But Git's binary-vs-text decision (whether it emits `Binary files a/x and b/x differ` versus a real unified diff) is a heuristic that only scans a bounded prefix of file content (Git's core `buffer_is_binary`-style check looks for a NUL only within the first ~8000 bytes of a blob), and can also be overridden entirely via `.gitattributes` (`-diff`/`diff=text`). If a NUL byte appears past that scanned prefix, or attributes force text handling, Git will still print a normal textual patch, but that patch's byte stream can legitimately contain a literal `\0` character.

`DiffParser.parse()` only recognizes binary diffs by matching the literal string `Binary files ... differ` in the header [7](#0-6)  — there is no additional guard anywhere in `diffFromRawDiffOutput` or `DiffParser` against NUL bytes appearing inside an otherwise-text patch.

Because `result.split('\0')` treats every NUL in the entire stdout (raw/numstat preamble *and* patch body) as a delimiter, an embedded NUL inside the patch body produces an extra split point. `pieces.at(-1)` then only contains whatever bytes came *after* that last NUL — everything before it (potentially the `diff --git` header, hunk headers, and entire hunks including attacker-appended lines) is silently dropped before `DiffParser.parse()` ever sees it. This is a genuine "wrong value" — `pieces.at(-1)` is not equivalent to "the full patch text" when NUL bytes exist inside the patch content itself.

Crucially, this truncation is purely cosmetic in terms of what Desktop *displays*: it does not change what is actually on disk, staged in the index, or ultimately committed/pushed by `git commit`/`git push`, since those operate on real file content independent of how `buildDiff`/`diffFromRawDiffOutput` renders it for the UI.

### Impact Explanation
An attacker who controls a repository, branch, or fetched content (e.g., a malicious PR branch, or a repo the victim clones) can craft a file that:
1. Git still classifies as text (either by placing the NUL past Git's scanned prefix, or via a `.gitattributes` entry forcing text diffing for that path), and
2. Contains a raw NUL byte positioned so that malicious added/modified lines end up in a `\0`-delimited fragment that is *not* the last one.

When the victim views this diff in the Changes view (working directory diff, commit diff, or branch comparison diff), Desktop will render a truncated/incomplete diff that hides the malicious lines, while the real file content — including the malicious lines — is what actually gets staged and committed/pushed. This matches "silent corruption of what the user commits or pushes" in that the user's mental model of *what they are approving* diverges from what actually enters the commit.

### Likelihood Explanation
Exploitability depends on precisely satisfying Git's binary-detection heuristic (positioning the NUL beyond the scanned prefix) or on the attacker also controlling `.gitattributes` in the same repository to force text diffing — both of which are achievable by an attacker who fully controls the crafted repository/branch being cloned or fetched, which is within the stated threat model (repository content is attacker-controlled, no local/admin access needed). It requires careful byte-offset crafting but no unusual user interaction beyond normal viewing of a diff for a file from that repository.

### Recommendation
Do not rely on "last `\0`-delimited fragment" to isolate the patch body. Instead:
- Locate the boundary between the raw/numstat NUL-terminated preamble and the patch body deterministically (e.g., by parsing the known raw/numstat record count, similar to how `getIndexChanges`/`parseRawLogWithNumstat` count fixed-arity NUL-separated fields), rather than assuming the patch itself is NUL-free.
- Alternatively, detect and reject/flag embedded NUL bytes inside the parsed patch text before rendering (treating such diffs as "binary/unrenderable" rather than allowing `DiffParser.parse()` to silently receive a truncated fragment), and log/alert rather than fail silently via `forceUnwrap`.

### Proof of Concept
1. Craft a text file `evil.txt` where:
   - Bytes 0–8000 are innocuous, valid UTF-8 text (to pass Git's binary-detection heuristic scan window).
   - Immediately after that, insert one raw `0x00` byte.
   - Following the NUL, append the "malicious" lines (e.g., a line that would look suspicious/dangerous if reviewed, or additional file contents) plus trailing benign text.
2. Commit this file to a branch in an attacker-controlled repository, then have the victim fetch/checkout it or diff it against `HEAD` (working directory diff) in GitHub Desktop.
3. Compare:
   - The true `git diff --no-ext-diff --patch-with-raw -z --no-color -- evil.txt` output (run manually in a terminal) — shows the full hunk including the malicious lines before the embedded NUL.
   - The diff rendered by Desktop's Changes view for the same file — since `diffFromRawDiffOutput` takes only `pieces.at(-1)` of `stdout.toString('utf-8').split('\0')`, the rendered hunk is truncated to only the content after the embedded NUL, silently omitting the header/hunk data and malicious lines that appear before it.
4. Confirm that despite the truncated/misleading UI diff, staging and committing the file via Desktop commits the full real file content (including the hidden malicious lines), by inspecting the resulting commit with `git show` from the command line.

export async function getCommitRangeDiff(
  repository: Repository,
  file: FileChange,
  commits: ReadonlyArray<string>,
  hideWhitespaceInDiff: boolean = false,
  useNullTreeSHA: boolean = false
): Promise<IDiff> {
  if (commits.length === 0) {
    throw new Error('No commits to diff...')
  }

  const oldestCommit = useNullTreeSHA ? NullTreeSHA : commits[0]
  const oldestCommitRef = useNullTreeSHA ? NullTreeSHA : `${commits[0]}^`
  const latestCommit = commits.at(-1) ?? '' // can't be undefined since commits.length > 0
  const args = [
    'diff',
    oldestCommitRef,
    latestCommit,
    ...(hideWhitespaceInDiff ? ['-w'] : []),
    '--patch-with-raw',
    '--format=',
    '-z',
    '--no-color',
    '--',
    ensureRelativePath(file.path),
  ]

  if (
    file.status.kind === AppFileStatusKind.Renamed ||
    file.status.kind === AppFileStatusKind.Copied
  ) {
    args.push(ensureRelativePath(file.status.oldPath))
  }

  const result = await git(args, repository.path, 'getCommitsDiff', {
    encoding: 'buffer',
    expectedErrors: new Set([GitError.BadRevision]),
  })

  // This should only happen if the oldest commit does not have a parent (ex:
  // initial commit of a branch) and therefore `SHA^` is not a valid reference.
  // In which case, we will retry with the null tree sha.
  if (result.gitError === GitError.BadRevision && useNullTreeSHA === false) {
    return getCommitRangeDiff(
      repository,
      file,
      commits,
      hideWhitespaceInDiff,
      true
    )
  }

  return buildDiff(result.stdout, repository, file, latestCommit, oldestCommit)
}

export async function getWorkingDirectoryDiff(
  repository: Repository,
  file: WorkingDirectoryFileChange,
  hideWhitespaceInDiff: boolean = false
): Promise<IDiff> {
  // `--no-ext-diff` should be provided wherever we invoke `git diff` so that any
  // diff.external program configured by the user is ignored
  const args = [
    'diff',
    ...(hideWhitespaceInDiff ? ['-w'] : []),
    '--no-ext-diff',
    '--patch-with-raw',
    '-z',
    '--no-color',
  ]
  const successExitCodes = new Set([0])
  const isSubmodule = file.status.submoduleStatus !== undefined

  // For added submodules, we'll use the "default" parameters, which are able
  // to output the submodule commit.
  if (
    !isSubmodule &&
    (file.status.kind === AppFileStatusKind.New ||
      file.status.kind === AppFileStatusKind.Untracked)
  ) {
    // `git diff --no-index` seems to emulate the exit codes from `diff` irrespective of
    // whether you set --exit-code
    //
    // this is the behavior:
    // - 0 if no changes found
    // - 1 if changes found
    // -   and error otherwise
    //
    // citation in source:
    // https://github.com/git/git/blob/1f66975deb8402131fbf7c14330d0c7cdebaeaa2/diff-no-index.c#L300
    successExitCodes.add(1)
    args.push('--no-index', '--', '/dev/null', file.path)
  } else if (file.status.kind === AppFileStatusKind.Renamed) {
    // NB: Technically this is incorrect, the best kind of incorrect.
    // In order to show exactly what will end up in the commit we should
    // perform a diff between the new file and the old file as it appears
    // in HEAD. By diffing against the index we won't show any changes
    // already staged to the renamed file which differs from our other diffs.
    // The closest I got to that was running hash-object and then using
    // git diff <blob> <blob> but that seems a bit excessive.
    args.push('--', ensureRelativePath(file.path))
  } else {
    args.push('HEAD', '--', ensureRelativePath(file.path))
  }

  const { stdout, stderr } = await git(
    args,
    repository.path,
    'getWorkingDirectoryDiff',
    { successExitCodes, encoding: 'buffer' }
  )
  const lineEndingsChange = parseLineEndingsWarning(stderr)

  return buildDiff(stdout, repository, file, 'HEAD', 'HEAD', lineEndingsChange)
}

function diffFromRawDiffOutput(output: Buffer): IRawDiff {
  // for now we just assume the diff is UTF-8, but given we have the raw buffer
  // we can try and convert this into other encodings in the future
  const result = output.toString('utf-8')

  const pieces = result.split('\0')
  const parser = new DiffParser()
  return parser.parse(forceUnwrap(`Invalid diff output`, pieces.at(-1)))
}

async function buildDiff(
  buffer: Buffer,
  repository: Repository,
  file: FileChange,
  newestCommitish: string,
  oldestCommitish: string,
  lineEndingsChange?: LineEndingsChange
): Promise<IDiff> {
  if (file.status.submoduleStatus !== undefined) {
    return buildSubmoduleDiff(
      buffer,
      repository,
      file,
      file.status.submoduleStatus
    )
  }

  if (!isValidBuffer(buffer)) {
    // the buffer's diff is too large to be renderable in the UI
    return { kind: DiffType.Unrenderable }
  }

  const diff = diffFromRawDiffOutput(buffer)

  if (isBufferTooLarge(buffer) || isDiffTooLarge(diff)) {
    // we don't want to render by default
    // but we keep it as an option by
    // passing in text and hunks
    const largeTextDiff: ILargeTextDiff = {
      kind: DiffType.LargeText,
      text: diff.contents,
      hunks: diff.hunks,
      lineEndingsChange,
      maxLineNumber: diff.maxLineNumber,
      hasHiddenBidiChars: diff.hasHiddenBidiChars,
    }

    return largeTextDiff
  }

  return convertDiff(
    repository,
    file,
    diff,
    newestCommitish,
    oldestCommitish,
    lineEndingsChange
  )
}
