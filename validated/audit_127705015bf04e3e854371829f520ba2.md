### Title
Attacker-controlled participant count in `ThresholdKeys::read` causes quadratic CPU exhaustion via Lagrange interpolation - (File: crypto/dkg/src/lib.rs)

### Summary
`ThresholdKeys::read` accepts a serialized `n` (participant count) directly from untrusted input, then calls `ThresholdKeys::new`, which computes the group key by evaluating `interpolation_factor` (a Lagrange product over all `t` participants) once per participant `1..=t`. This makes deserialization O(n²) in field multiplications with attacker-controlled `n` up to 65535, mirroring the CVE-2023-1993 pattern of an input-controlled large loop causing denial of service.

### Finding Description
`ThresholdKeys::read` reads `t`, `n`, and `i` as raw `u16` values from the byte stream [1](#0-0) . It then reads `n` scalars/points and invokes `ThresholdKeys::new` [2](#0-1) . Inside `new`, the group key is computed as `sum(verification_shares[i] * interpolation_factor(*i, &t))` over `i in 1..=t` [3](#0-2) . For `Interpolation::Lagrange`, each `interpolation_factor` call iterates over the full `included` vector performing a numerator multiply, denominator multiply, and a final inversion [4](#0-3) .

With `Interpolation::Lagrange` and `t = n = 65535` (permitted by `ThresholdParams::new`, which only checks `t <= n` [5](#0-4) ), deserialization performs ~65535² ≈ 4.3×10⁹ field multiplications plus 65535 field inversions, all driven by a roughly 4–6 MB input. The CPU work is quadratic in input size — a large amplification factor with no size cap on `n` other than the `u16` range.

### Impact Explanation
Any code path that calls `ThresholdKeys::read` (or `Ciphersuite`-generic equivalents) on bytes influenced by an untrusted party — e.g., recovering keys shared between processors or loaded from coordinator-supplied data — can be forced into a single-threaded computation lasting orders of magnitude longer than proportional to input size. This stalls the affected node's key handling, potentially halting DKG completion, signing, or recovery for the session. Severity is Medium: availability impact only, no secret leakage or forgery.

### Likelihood Explanation
The attack requires only that the attacker can supply or corrupt a serialized `ThresholdKeys` blob (or any protocol object embedding one) with a large `n` and `Interpolation::Lagrange`. The input itself must contain `n` point encodings (~4–6 MB), which is small relative to the ~billions of field operations induced. No valid key material, threshold cooperation, or special position is needed — `read` performs the quadratic work before any cryptographic validation of the shares' correctness.

### Recommendation
Cap `n` (e.g., to a protocol-meaningful maximum such as a few thousand, or the actual validator-set bound) inside `ThresholdKeys::read` before allocating vectors and calling `ThresholdKeys::new`. Alternatively, compute the group key incrementally or bound the total work (e.g., reject if `t * n` exceeds a fixed budget). At minimum, validate `n` against a documented maximum participant count prior to interpolation.

### Proof of Concept
```rust
use std::io::Write;
use ciphersuite::Ciphersuite;
use frost::curve::Ristretto;
use dkg::{ThresholdKeys, Participant};

fn main() {
  // Build a serialized ThresholdKeys blob claiming n = 65535 participants
  let t: u16 = 65535;
  let n: u16 = 65535;
  let i: u16 = 1;

  let mut buf = vec![];
  buf.write_all(&(Ristretto::ID.len() as u32).to_le_bytes()).unwrap();
  buf.write_all(Ristretto::ID).unwrap();
  buf.write_all(&t.to_le_bytes()).unwrap();
  buf.write_all(&n.to_le_bytes()).unwrap();
  buf.write_all(&i.to_le_bytes()).unwrap();
  buf.write_all(&[1u8]).unwrap(); // Interpolation::Lagrange
  // secret_share + n verification shares: any canonical encodings suffice
  let scalar = <Ristretto as Ciphersuite>::F::ONE;
  let point = Ristretto::generator();
  buf.write_all(scalar.to_repr().as_ref()).unwrap();
  for _ in 0 .. n {
    buf.write_all(point.to_bytes().as_ref()).unwrap();
  }

  // ThresholdKeys::read -> ThresholdKeys::new performs ~n^2 = ~4.3e9 field multiplications
  let _ = ThresholdKeys::<Ristretto>::read(&mut buf.as_slice());
}
```
The reader consumes ~4.3 MB of input yet executes billions of field operations in `Interpolation::interpolation_factor` before any validity check on the shares themselves, confirming the asymmetric-work DoS.
