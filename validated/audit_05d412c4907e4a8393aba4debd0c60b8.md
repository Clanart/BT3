### Title
Quadratic CPU exhaustion via attacker-controlled participant count in `ThresholdKeys::read` → `ThresholdKeys::new` Lagrange interpolation - ([File: crypto/dkg/src/lib.rs])

### Summary
`ThresholdKeys::read` deserializes `t` and `n` directly from untrusted bytes (`crypto/dkg/src/lib.rs:591-602`), then calls `ThresholdKeys::new`, which computes `group_key` by evaluating `Interpolation::Lagrange::interpolation_factor` for every participant `1..=t` over an `included` set of size `t` (`crypto/dkg/src/lib.rs:376-378`). Each Lagrange factor is O(t) field multiplications (`crypto/dkg/src/lib.rs:229-247`), so group-key derivation is O(t²) = up to ~4.3×10⁹ field multiplications when `t = n = 65535`, reachable from a single ~4 MB input. This is the Serai analog of the CVE-2023-46871 resource-exhaustion bug class: unbounded/quadratic work driven purely by attacker-supplied serialized data, yielding denial of service.

### Finding Description
`ThresholdKeys::read` reads two `u16` values (`t`, `n`) plus a participant index and then reads `n` scalars (for `Interpolation::Constant`) and `n` verification-share points into a `HashMap` (`crypto/dkg/src/lib.rs:607-623`). It then invokes `ThresholdKeys::new` (`crypto/dkg/src/lib.rs:625-631`). `ThresholdParams::new` accepts any `t <= n <= u16::MAX` (`crypto/dkg/src/lib.rs:166-178`), so an attacker can craft a serialized blob with `t = n = 65535` and `Interpolation::Lagrange`. In `ThresholdKeys::new`, `group_key` is computed as `sum(verification_shares[i] * interpolation_factor(i, &t))` over `i` in `1..=t` (`crypto/dkg/src/lib.rs:376-378`). For Lagrange, `interpolation_factor` iterates over all `included` participants performing a numerator and denominator field multiplication each (`crypto/dkg/src/lib.rs:234-241`), plus an inversion. The result is t × O(t) work — roughly 4.3 billion `F` multiplications and 65535 inversions — triggered by a compact serialized message containing only ~4.2 MB of attacker bytes (65535 × 64 bytes of scalar/point encodings). The same O(|included|²) cost recurs in `ThresholdKeys::view` (`crypto/dkg/src/lib.rs:500-507`) whenever a view is built over a large included set. No length cap, gas bound, or sanity limit on `n` exists anywhere in the read path.

### Impact Explanation
Any system that exposes `ThresholdKeys::read` (or an API that reaches it, e.g., deserializing `ThresholdKeys` from untrusted storage/network bytes) can be driven into effectively infinite CPU burn by a single small input. The amplification factor is severe: ~4 MB of input produces billions of field operations, blocking the thread for an unbounded period. Repeated submissions allow a remote, unauthenticated party to fully deny service to the signing/key-loading path. This matches the CVE's class (resource exhaustion via crafted input → DoS) mapped onto Serai's deserialization shape.

### Likelihood Explanation
Reachability requires only that attacker-controlled bytes reach `ThresholdKeys::read`, which is one of the enumerated untrusted-input sinks. The malicious payload is trivially constructible: curve ID, `t = 0xFFFF`, `n = 0xFFFF`, `i = 1`, interpolation byte `0x01` (Lagrange), one secret-share scalar, then 65535 valid point encodings (e.g., the generator repeated). All validation (`t <= n`, participant indexes, share count) passes, so the quadratic computation is entered unconditionally on every such input.

### Recommendation
Cap `n`/`t` at deserialization time to a protocol-meaningful maximum (e.g., a few hundred), or precompute Lagrange denominators once per signing set so `group_key`/view construction is O(t) instead of O(t²). At minimum, reject `n` values exceeding a documented bound inside `ThresholdKeys::read`/`ThresholdParams::new` before allocating or interpolating.

### Proof of Concept
```rust
use std::io::Write;
use ciphersuite::Ciphersuite;
use dkg::{ThresholdKeys, Participant};

fn poc<C: Ciphersuite>() {
    let mut buf = vec![];
    // curve ID
    buf.write_all(&(C::ID.len() as u32).to_le_bytes()).unwrap();
    buf.write_all(C::ID).unwrap();
    // t = n = u16::MAX, i = 1
    buf.write_all(&u16::MAX.to_le_bytes()).unwrap();
    buf.write_all(&u16::MAX.to_le_bytes()).unwrap();
    buf.write_all(&1u16.to_le_bytes()).unwrap();
    // Interpolation::Lagrange
    buf.push(1);
    // secret share scalar
    buf.write_all(C::F::ONE.to_repr().as_ref()).unwrap();
    // n verification shares (all = generator)
    for _ in 0 .. u16::MAX {
        buf.write_all(C::generator().to_bytes().as_ref()).unwrap();
    }
    // ~4.2 MB input -> O(n^2) ≈ 4.3e9 field multiplications in group_key derivation
    let _ = ThresholdKeys::<C>::read(&mut buf.as_slice()); // CPU hang
}
```
