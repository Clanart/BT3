## Analysis

The external report's core invariant: a low-level `.call()` to an address returns `success = true` even when that address has no contract code (e.g., because the target self-destructed), so "call succeeded" is not a valid signal that any logic actually executed. Any component that treats such a call's success as proof of message delivery — thereby recording a receipt, releasing funds, or deleting retryable state — inherits this flaw.

`EvmHost.sol` contains exactly this inconsistency. `dispatchIncoming(PostRequest ...)` is guarded with an `extcodesize` check before invoking the destination module and before writing the replay-protection receipt, but the three sibling delivery paths — `dispatchIncoming(GetResponse ...)`, `dispatchTimeOut(GetRequestTimeout ...)`, and `dispatchTimeOut(PostRequestTimeout ...)` — perform the low-level `.call()` directly with no such check. [1](#0-0) [2](#0-1) 

The `from`/module address that receives these callbacks is derived directly from whoever called `dispatch()` originally (`abi.encodePacked(_msgSender())`), so it's fully attacker-controlled — a contract can dispatch a GET/POST request and then self-destruct within the same creation transaction (still fully valid under EIP-6780 semantics), leaving `request.from` pointing at an empty address by the time the response/timeout is relayed. [3](#0-2) [4](#0-3) 

### Title
Unguarded low-level calls in `dispatchIncoming(GetResponse)`/`dispatchTimeOut` let calls to non-existent modules be treated as successful delivery, causing false receipt finalization and fee/fund loss - (File: `evm/src/core/EvmHost.sol`)

### Summary
`EvmHost.dispatchIncoming(PostRequest, address)` explicitly checks `extcodesize(destination) == 0` before calling the destination module and before persisting the replay-protection receipt, returning early (allowing retry) if the destination has no code. `dispatchIncoming(GetResponse, address)`, `dispatchTimeOut(GetRequestTimeout, ...)`, and `dispatchTimeOut(PostRequestTimeout, ...)` omit this check entirely: they call `_bytesToAddress(...).call(...)` directly. In Solidity/EVM, a `call` to an address with no code always returns `success = true` with empty returndata, so these three paths treat "no module exists" identically to "module successfully processed the message."

### Finding Description
- In `dispatchIncoming(GetResponse ...)`, the response commitment/receipt is written *before* the call, the call trivially succeeds against a no-code address, and the code proceeds to pay the relayer fee and emit `GetRequestHandled`, permanently finalizing a response that was never actually delivered to any application logic. [5](#0-4) 
- In `dispatchTimeOut(GetRequestTimeout ...)` and `dispatchTimeOut(PostRequestTimeout ...)`, `_requestCommitments[commitment]` is deleted *before* the call. Because the call to a no-code `request.from` also trivially succeeds, the "so that it can be retried" fallback branch (`_requestCommitments[commitment] = meta`) never executes, and the relayer fee refund proceeds even though the module's `onGetTimeout`/`onPostRequestTimeout` handler never ran. [6](#0-5) 
- The destination module address is fully attacker-supplied: it's simply `abi.encodePacked(_msgSender())` captured at dispatch time. [3](#0-2) [4](#0-3) 

An attacker can deploy a throwaway contract whose constructor dispatches a GET or POST request via `IDispatcher(host).dispatch(...)` and then immediately `selfdestruct`s in the very same creation transaction — a case EIP-6780 still permits to fully empty the contract's code. By the time a relayer later submits the response/timeout proof, `request.from`/`response.request.from` has no code, so the guardless `.call()` in these three functions falsely reports success.

### Impact Explanation
This breaks the "one-time receipt handling" invariant: state that should only be finalized on genuine, successful delivery is finalized regardless of whether any module code actually ran. Concretely:
- Relayer fees are paid out (`GetResponse` path) or refunded (`GetRequestTimeout`/`PostRequestTimeout` paths) for deliveries that never reached any application logic — funds move without the corresponding application-level effect ever occurring.
- Because the receipt/commitment is deleted/written unconditionally on the false "success", there is no retry path — unlike the `PostRequest` sibling, which explicitly preserves retryability on failure. Any escrow, refund, or settlement logic that a well-formed module would have executed inside `onGetResponse`/`onGetTimeout`/`onPostRequestTimeout` is permanently skipped with no recovery mechanism.

### Likelihood Explanation
The path requires no relayer, prover, or admin collusion — only an unprivileged actor dispatching a normal request from a self-destructing contract in one transaction, which is a supported and legitimate use of `dispatch()`. The relayer proof-submission steps (`dispatchIncoming`/`dispatchTimeOut`) are otherwise legitimate, honestly-relayed ISMP deliveries; the attacker's contribution is solely constructing the module address so that it has no code by delivery time, and the exact same `extcodesize` mitigation already exists elsewhere in the same file for the `PostRequest` case, confirming this is a known-necessary but inconsistently-applied guard.

### Recommendation
Add the same `extcodesize` check used in `dispatchIncoming(PostRequest, address)` to `dispatchIncoming(GetResponse, address)`, `dispatchTimeOut(GetRequestTimeout, ...)`, and `dispatchTimeOut(PostRequestTimeout, ...)`, returning early (without deleting/writing the replay-protection state or transferring fees) when the destination has zero code size, exactly mirroring lines 794-803.

### Proof of Concept
1. Deploy `AttackerModule`, whose constructor calls `IDispatcher(host).dispatch(DispatchGet{...})` (or `DispatchPost`) and then calls `selfdestruct(payable(msg.sender))` at the end of the same constructor/creation transaction (fully valid under EIP-6780 since creation and destruction occur in the same transaction).
2. `EvmHost.dispatch(...)` records `request.from = abi.encodePacked(address(AttackerModule))` per `evm/src/core/EvmHost.sol` lines 936-948 / 988-1001.
3. Let the request time out (or have a relayer submit a spoof-free but ultimately empty-target response via the real handler/consensus flow).
4. The handler calls `EvmHost.dispatchTimeOut(GetRequestTimeout, ...)` (or `dispatchIncoming(GetResponse, ...)`), which performs `_bytesToAddress(timeout.request.from).call(...)` against `AttackerModule`, now with zero code size.
5. The `.call()` returns `success = true`; `evm/src/core/EvmHost.sol` lines 862-877 proceed to delete the commitment and pay out `meta.fee`, permanently finalizing state for a message that no code ever processed — with no retry path available, unlike the guarded `PostRequest` branch.

    function dispatchIncoming(PostRequest memory request, address relayer) external restrict(_hostParams.handler) {
        address destination = _bytesToAddress(request.to);
        uint256 size;
        assembly {
            size := extcodesize(destination)
        }
        if (size == 0) {
            // instead of reverting the entire batch, early return here.
            return;
        }

        // replay protection
        bytes32 commitment = request.hash();
        _requestReceipts[commitment] = relayer;

        (bool success,) = address(destination)
            .call(abi.encodeWithSelector(IApp.onAccept.selector, IncomingPostRequest(request, relayer)));

        if (!success) {
            // so that it can be retried
            delete _requestReceipts[commitment];
            return;
        }
        emit PostRequestHandled({commitment: commitment, relayer: relayer});
    }

    /**
     * @dev Dispatch an incoming GET response to source module
     * @param response - get response
     */
    function dispatchIncoming(GetResponse memory response, address relayer) external restrict(_hostParams.handler) {
        // replay protection
        bytes32 commitment = response.request.hash();
        _responseReceipts[commitment] = ResponseReceipt({
            relayer: relayer,
            responseCommitment: response.hash()
        });

        (bool success,) = _bytesToAddress(response.request.from)
            .call(abi.encodeWithSelector(IApp.onGetResponse.selector, IncomingGetResponse(response, relayer)));

        if (!success) {
            // so that it can be retried
            delete _responseReceipts[commitment];
            return;
        }

        // reward the relayer fee
        uint256 fee = _requestCommitments[commitment].fee;
        if (fee != 0) {
            IERC20(feeToken()).safeTransfer(relayer, fee);
        }
        emit GetRequestHandled({commitment: commitment, relayer: relayer});
    }
