## Title
GitHub repositories are matched and remote URLs silently rewritten by `owner/name` alone, with no repository identity check, enabling repo‑jacking of a user's `origin`/`upstream` remote - (`File: app/src/lib/repository-matching.ts`, `app/src/lib/stores/updates/update-remote-url.ts`, `app/src/lib/stores/repositories-store.ts`)

## Summary
The External Report's broken invariant is: *a trust-critical destination (recipient address / remote URL) is taken from an object whose identity was never re-validated, so the destination can silently change to something attacker-controlled.* The Desktop analog is `updateRemoteUrl`, which rewrites a repository's `origin` (or `upstream`) remote URL using a freshly-fetched `IAPIRepository` that was looked up **purely by `owner/name` string**, never by the stable repository identifier Desktop already had cached. If the `owner/name` slot on GitHub.com/GHES is later associated with a different (attacker-controlled) repository — e.g. after the original repo is renamed/transferred/deleted and the name is reclaimed ("repo-jacking") — Desktop will fetch that attacker repository's data and use its `clone_url` to overwrite the user's real remote, silently redirecting future `git fetch`/`git push` operations.

## Finding Description
`matchGitHubRepository` in [1](#0-0)  only matches accounts and repositories by comparing the remote's hostname/owner/name — there is no comparison against any stable GitHub repository ID.

This match result flows into `AppStore.repositoryWithRefreshedGitHubRepository`: [2](#0-1) 
which calls `api.fetchRepository(owner, name)` using only the `owner`/`name` pair, then unconditionally passes the returned `apiRepo` into `updateRemoteUrl(gitStore, repository.gitHubRepository, apiRepo)`.

`updateRemoteUrl` itself trusts the API response's `clone_url` and rewrites the local git remote whenever the protocol matches and the previously-cached `cloneURL` still matches the current remote: [3](#0-2) 
Nowhere in this path is there a check that the freshly-fetched repository is *the same repository* Desktop previously associated with this local clone (e.g. by GitHub's numeric repository `id`). The local `GitHubRepository` model even documents that its `dbID` is "no relation to the API ID" [4](#0-3) , and the persisted lookup key is `[ownerID+name]`, not an API-side repository id: [5](#0-4) 

`gitStore.setRemoteURL` then performs the actual mutation via `git remote set-url` with no additional confirmation to the user: [6](#0-5) [7](#0-6) 

## Impact Explanation
If an attacker gains control of the `owner/name` combination that a Desktop user's local repository previously pointed to (a well-known GitHub attack class often called "repo-jacking": renaming/deleting/transferring a repo and re-claiming the freed `owner/name`, or the attacker creating a repo at that path before the legitimate one existed and it later got renamed away), the next background metadata refresh will:
1. Resolve `owner/name` to the attacker's repository via `api.fetchRepository`.
2. Treat the attacker's `clone_url` as authoritative and silently call `git remote set-url` on the user's `origin`, and/or `upstream` via `_convertRepositoryToFork`/`ensureUpstreamRemoteURL` paths that also trust caller-supplied `clone_url` without identity verification (`app/src/lib/stores/app-store.ts:8969-8991`, `app/src/lib/stores/git-store.ts:1321-1356`).
3. Persist the attacker's repository info (`cloneURL`, `htmlURL`) into the local database keyed only by `[ownerID+name]` (`app/src/lib/stores/repositories-store.ts:530-563`).

Subsequent `git fetch`/`git pull`/`git push` operations performed by the user inside Desktop would then silently target the attacker's remote — this can result in the user unknowingly pushing private commits/branches to an attacker-controlled server (credential/code exfiltration) or fetching/merging attacker-supplied history into their local repository (supply-chain corruption of what gets committed/merged), all without any prompt other than the routine "fetching" activity Desktop performs automatically in the background.

## Likelihood Explanation
This does not require local access, admin rights, or prior malware — it only requires the attacker to control a GitHub API object (a repository at a specific `owner/name`) that a victim's Desktop happens to still associate with a stale local clone, which is a realistic and externally-documented scenario after repository renames/deletions/ownership transfers. The refresh path (`repositoryWithRefreshedGitHubRepository`) runs as part of Desktop's normal background repository refresh, not a distinct or unnatural user action, so the corrupted state is reached silently.

## Recommendation
Before trusting a freshly-fetched `IAPIRepository`/`clone_url` to rewrite a remote or overwrite cached `GitHubRepository` metadata, verify it refers to the *same* repository the user previously associated locally — e.g. compare GitHub's numeric repository `id` (already available on `IAPIRepository`) against a persisted `apiID` for the cached `GitHubRepository`, and refuse to silently update the remote (instead warn/prompt the user) when the `id` changes for a given `owner/name`. Apply the same identity check anywhere else `clone_url`/`ssh_url` from an API repository object is used to mutate an existing remote (`updateRemoteUrl`, `_convertRepositoryToFork`, `ensureUpstreamRemoteURL`).

## Proof of Concept
1. Victim has a Desktop-tracked repository whose `origin` and cached `GitHubRepository.cloneURL` point to `https://github.com/alice/project`.
2. `alice/project` is deleted or renamed on GitHub; attacker immediately creates a new repository at `https://github.com/alice/project` with `clone_url` pointing to their own server/fork.
3. Desktop's periodic `repositoryWithRefreshedGitHubRepository` runs: `matchGitHubRepository` matches on `owner=alice, name=project` (`app/src/lib/repository-matching.ts:29-46`), `api.fetchRepository('alice','project')` returns the attacker's repository object, and since the previously cached `cloneURL` for `alice/project` still equals the current remote URL (`remoteUrlUnchanged` is true) and protocols match, `updateRemoteUrl` calls `gitStore.setRemoteURL('origin', attackerCloneUrl)` (`app/src/lib/stores/updates/update-remote-url.ts:42-44`).
4. The victim's `origin` remote is now silently pointed at the attacker's repository with no dialog or confirmation; the next push in Desktop sends the victim's commits there.

export function matchGitHubRepository(
  accounts: ReadonlyArray<Account>,
  remote: string
): IMatchedGitHubRepository | null {
  for (const account of accounts) {
    const htmlURL = getHTMLURL(account.endpoint)
    const { hostname } = URL.parse(htmlURL)
    const parsedRemote = parseRemote(remote)

    if (parsedRemote !== null && hostname !== null) {
      if (parsedRemote.hostname.toLowerCase() === hostname.toLowerCase()) {
        return { name: parsedRemote.name, owner: parsedRemote.owner, account }
      }
    }
  }

  return null
}

  private async repositoryWithRefreshedGitHubRepository(
    repository: Repository
  ): Promise<Repository> {
    const repoStore = this.repositoriesStore
    const match = await this.matchGitHubRepository(repository)

    // TODO: We currently never clear GitHub repository associations (see
    // https://github.com/desktop/desktop/issues/1144). So we can bail early at
    // this point.
    if (!match) {
      return repository
    }

    const { account, owner, name } = match
    const { endpoint } = account
    const api = API.fromAccount(account)
    const apiRepo = await api.fetchRepository(owner, name)

    if (apiRepo === null) {
      // If the request fails, we want to preserve the existing GitHub
      // repository info. But if we didn't have a GitHub repository already or
      // the endpoint changed, the skeleton repository is better than nothing.
      if (endpoint !== repository.gitHubRepository?.endpoint) {
        const ghRepo = await repoStore.upsertGitHubRepositoryFromMatch(match)
        return repoStore.setGitHubRepository(repository, ghRepo)
      }

      return repository
    }

    if (repository.gitHubRepository) {
      const gitStore = this.gitStoreCache.get(repository)
      await updateRemoteUrl(gitStore, repository.gitHubRepository, apiRepo)
    }

    const ghRepo = await repoStore.upsertGitHubRepository(endpoint, apiRepo)
    const freshRepo = await repoStore.setGitHubRepository(repository, ghRepo)

    await this.refreshBranchProtectionState(freshRepo)
    return freshRepo
  }

import { IAPIRepository } from '../../api'
import { GitStore } from '../git-store'
import { urlMatchesRemote } from '../../repository-matching'
import * as URL from 'url'
import { GitHubRepository } from '../../../models/github-repository'

export async function updateRemoteUrl(
  gitStore: GitStore,
  gitHubRepository: GitHubRepository,
  apiRepo: IAPIRepository
): Promise<void> {
  // I'm not sure when these early exit conditions would be met. But when they are
  // we don't have enough information to continue so exit early!
  if (gitStore.defaultRemote === null) {
    return
  }

  const remoteUrl = gitStore.defaultRemote.url
  const updatedRemoteUrl = apiRepo.clone_url
  const urlsMatch = urlMatchesRemote(updatedRemoteUrl, gitStore.defaultRemote)

  // Verify that protocol hasn't changed. If it has we don't want
  // to alter the protocol in case they are relying on a specific one.
  // If protocol is null that implies the url is a ssh url
  // of the format git@github.com:octocat/Hello-World.git, which
  // can't be parsed by URL.parse. In this case we assume the user
  // manually configured their remote to use this format and we don't
  // want to change what they've done just to be safe
  const parsedRemoteUrl = URL.parse(remoteUrl)
  const parsedUpdatedRemoteUrl = URL.parse(updatedRemoteUrl)
  const protocolsMatch =
    parsedRemoteUrl.protocol !== null &&
    parsedUpdatedRemoteUrl.protocol !== null &&
    parsedRemoteUrl.protocol === parsedUpdatedRemoteUrl.protocol

  // Check if the default remote url has been manually changed from the
  // clone url retrieved from the GitHub API previously
  const remoteUrlUnchanged =
    gitStore.defaultRemote &&
    urlMatchesRemote(gitHubRepository.cloneURL, gitStore.defaultRemote)

  if (protocolsMatch && remoteUrlUnchanged && !urlsMatch) {
    await gitStore.setRemoteURL(gitStore.defaultRemote.name, updatedRemoteUrl)
  }
}
