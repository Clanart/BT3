### Title
Governance-settable `GasTarget = 0` causes division-by-zero panic in `KIP71Config.NextMagmaBlockBaseFee` - ([File: params/kip71_config.go])

### Summary
`KIP71Config.NextMagmaBlockBaseFee` computes the next block's base fee (KIP-71/Magma dynamic gas pricing) using `GasTarget` as a divisor. Unlike `BaseFeeDenominator`, which has an explicit `!= 0` guard both in the governance parameter validator and in the function itself, `GasTarget` has no such guard anywhere, so a governance vote setting `governance.kip71.gastarget` to `0` causes every node computing the next base fee to divide by zero, panicking during block header verification/production.

### Finding Description
`NextMagmaBlockBaseFee` reads `gasTarget := kc.GasTarget` and uses it as a divisor in both the "gas used > target" and "gas used < target" branches: [1](#0-0) [2](#0-1) 

For `BaseFeeDenominator`, the code explicitly protects against a zero value by falling back to `64`: [3](#0-2) 

No equivalent protection exists for `GasTarget`. If `GasTarget == 0` and `parentGasUsed > 0` (true for essentially any block with transactions), the code takes the `parentGasUsed > gasTarget` branch and executes `x.Div(x, new(big.Int).SetUint64(gasTarget))` with a zero divisor, which panics in Go's `math/big.Int.Div` ("division by zero"): [4](#0-3) 

Critically, the governance parameter validator for `Kip71GasTarget` uses `noopFormatChecker`, i.e. it performs **no validation at all**, in stark contrast to `Kip71BaseFeeDenominator`, which rejects `0`: [5](#0-4) 

This means the governing node (or governance council under `governance` mode) can vote/set `Kip71GasTarget = 0` through the normal governance parameter update mechanism, and this value will be accepted and later applied on-chain without any sanity check.

### Impact Explanation
`NextMagmaBlockBaseFee` is consensus-critical: it is used both to compute the base fee a block producer must put in the next header and to verify that an incoming header's `BaseFee` matches the expected value (`VerifyMagmaHeader` calls it internally). It is invoked from block validation (`blockchain/block_validator.go`), block assembly (`work/worker.go`), the tx pool, and gas price oracle/fee history code (`node/cn/gasprice/*`). Once `GasTarget` becomes `0` after a governance parameter change takes effect, every node attempting to build or validate the very next Magma block with any nonzero gas usage will panic in this function. Because block production and block validation happen on every honest node, this results in a full network halt (all nodes crash/panic simultaneously) rather than an isolated node issue — a denial-of-service against the entire chain, which is a valid consensus-affecting impact.

### Likelihood Explanation
Likelihood depends on whether `Kip71GasTarget` can actually be set to `0` through the reachable governance flow (single governing node signalling a header vote, or council governance depending on `GovernanceMode`). Since the parameter validator (`noopFormatChecker`) imposes no restriction, any entity with governance-voting rights (which, depending on `GovernanceMode: single`, could be a single governing node) can set this value; the very next block after the parameter takes effect and includes any gas usage will trigger the panic. This is a straightforward, always-triggering bug once the parameter is set to zero — no timing races or edge conditions are needed beyond `parentGasUsed > 0`.

### Recommendation
Add an explicit zero-guard for `GasTarget` mirroring the existing `BaseFeeDenominator` fallback, e.g.:
```go
gasTarget := kc.GasTarget
if gasTarget == 0 {
    gasTarget = params.DefaultGasTarget // or another safe fallback
}
```
Additionally, update the `Kip71GasTarget` entry in `kaiax/gov/param.go` to use a `FormatChecker` that rejects `0` (consistent with `Kip71BaseFeeDenominator`), so that the invalid value can never be accepted by the governance parameter-set validation layer in the first place.

### Proof of Concept
1. Via governance (assuming `GovernanceMode: single`, matching the sample config seen in `kaiax/gov/headergov/README.md`), the governing node votes to set `governance.kip71.gastarget = 0`. This vote passes parameter validation because `Kip71GasTarget`'s `FormatChecker` is `noopFormatChecker` (`kaiax/gov/param.go:324-334`).
2. Once the new parameter set becomes effective at block `N`, any block at or after `N` that uses any gas (`parentGasUsed > 0`) enters the `parentGasUsed > gasTarget` branch of `NextMagmaBlockBaseFee` (`params/kip71_config.go:92-109`) since `gasTarget == 0`.
3. The line `y := x.Div(x, new(big.Int).SetUint64(gasTarget))` at `params/kip71_config.go:102` divides by zero, causing `math/big` to panic.
4. This function is called from block production (`work/worker.go`) and block/header validation (`blockchain/block_validator.go`), so every node attempting to produce or validate block `N+1` panics — halting the chain network-wide.
