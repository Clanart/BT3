### Title
Race condition in gasless module's duplicate-bundle-tx guard due to write performed under a read lock - ([File: kaiax/gasless/impl/tx_pool.go])

### Summary
`GaslessModule.PreAddTx`, the transaction-pool admission hook for gasless (KIP-247) transactions, acquires `g.knownTxsMu.RLock()` (a *read* lock) and then, while still holding only that read lock, calls `g.knownTxs.add(tx, TxStatusQueue)`, which mutates the underlying `knownTxs` map. Every other accessor of the same map (`IsReady`, `PreReset`, `PostReset`) correctly takes the *write* lock (`g.knownTxsMu.Lock()`) before mutating it. Because Go's `sync.RWMutex` only provides mutual exclusion when all participants respect the read/write discipline, a writer that mistakenly enters under `RLock()` defeats the protection: a concurrent reader that is also legitimately holding `RLock()` (allowed to run in parallel with another `RLock()` holder) can be racing with this in-place map mutation.

### Finding Description
`PreAddTx` is the single "already known / quota" gate that is supposed to guarantee a gasless bundle transaction (`GaslessApproveTx` or `GaslessSwapTx`) is admitted to the pool at most once within `KnownTxTimeout`, and that the number of queued bundle transactions never exceeds `GetMaxBundleTxsInQueue()`: [1](#0-0) 

The read lock only serializes with other readers, not with itself acting as a writer. Meanwhile, `knownTxs.add` performs unsynchronized map writes (insert, or in-place mutation of `status`/`addedTime`/`promotedTime`) and also updates gauges by iterating the map: [2](#0-1) 

The correctly-guarded call sites, `IsReady`, `PreReset`, and `PostReset`, all take the exclusive `Lock()`: [3](#0-2) [4](#0-3) 

Because `PreAddTx` uses `RLock()` instead of `Lock()`, it is possible for the write inside `PreAddTx` to interleave with any other holder of `RLock()` performing reads over the same map (e.g., a future or existing read-only accessor, or two overlapping `PreAddTx` executions that the RWMutex fails to serialize against each other because both believe they only need a shared/read lock). Concurrent unsynchronized read/write access to a Go map is undefined behavior: it can silently corrupt internal map state (lost or duplicated entries) or crash the process with a `fatal error: concurrent map read and map write`.

If the map's bookkeeping is corrupted rather than crashing outright, the entry that is supposed to prevent re-admission of an already-known/queued bundle transaction (the `knownTx` lookup in `PreAddTx`'s `ErrUnableToAddKnownBundleTx` check) can be lost, effectively defeating the single-admission guarantee the module relies on, and the `numQueue()`/`GetMaxBundleTxsInQueue()` quota check can undercount or overcount, letting bundle tx admission bypass its intended limit.

### Impact Explanation
This is directly analogous to the reported bug class: an in-memory (rather than database) "row lock" that is supposed to serialize check-then-write logic and guarantee at-most-once admission is not actually held in exclusive mode during the write, defeating the intended mutual exclusion. Any attacker able to race gasless approve/swap submissions against the node's pool (a capability available to any unprivileged, gasless-eligible sender or any public-RPC caller submitting transactions concurrently) can potentially corrupt the `knownTxs` tracking structure, causing loss of the deduplication guarantee for gasless bundle transactions and/or a node crash (`fatal error: concurrent map read and map write`), impacting availability of the gasless subsystem and potentially block-building on affected nodes.

### Likelihood Explanation
Exploitability requires winning a data race, so likelihood depends on how frequently `PreAddTx` and any other reader of `g.knownTxs` actually run concurrently under `RLock()`. In the current call chain, `PreAddTx` is invoked from `TxPool.add()` while the pool-wide mutex `pool.mu` is held (see `blockchain/tx_pool.go`), which serializes calls originating strictly through the tx pool. This reduces — but, given the mismatched lock discipline, does not by design guarantee — safety against any other holder of `knownTxsMu.RLock()`. The mismatch between "write while holding only a read lock" versus the correct "write requires the write lock" pattern used everywhere else in the same file is itself concrete, reviewable evidence of a bug regardless of the exact current set of concurrent callers; any future addition of a read-only accessor of `g.knownTxs` (e.g. a debug/metrics API) taking `RLock()` would immediately create the race window.

### Recommendation
Change `PreAddTx` to acquire the exclusive write lock (`g.knownTxsMu.Lock()`/`defer g.knownTxsMu.Unlock()`) instead of `RLock()`, matching the locking discipline already used by `IsReady`, `PreReset`, and `PostReset`. Audit all other accessors of `g.knownTxs` (present and future) to ensure any code path that mutates the map — directly or via `knownTxs.add`/`delete`/`addKnownTx` — always holds the write lock, and only pure lookups use `RLock()`.

### Proof of Concept
Not applicable as a standalone runnable PoC given the ask-only nature of this review; the finding is established directly from the source: `PreAddTx` calls the mutating method `knownTxs.add` while holding `knownTxsMu.RLock()` [1](#0-0) , whereas every other mutator of the same map (`IsReady`, `PreReset`, `PostReset`) correctly uses `knownTxsMu.Lock()` [3](#0-2) [4](#0-3) . Running the module under `go test -race` with concurrent submission of gasless approve/swap transactions (mirroring the `tests/race_test.go` style already present in the repo) against any additional/future concurrent reader of `g.knownTxs` would be expected to surface this as a detected data race.

func (g *GaslessModule) PreAddTx(tx *types.Transaction, local bool) error {
	g.knownTxsMu.RLock()
	defer g.knownTxsMu.RUnlock()

	if knownTx, ok := g.knownTxs.get(tx.Hash()); ok && knownTx.elapsedPromotedOrAddedTime() < KnownTxTimeout {
		return ErrUnableToAddKnownBundleTx
	}

	if g.IsBundleTx(tx) {
		if uint(g.knownTxs.numQueue()) >= g.GetMaxBundleTxsInQueue() {
			return ErrBundleTxQueueFull
		}
		g.knownTxs.add(tx, TxStatusQueue)
	}
	return nil
}

func (g *GaslessModule) PreReset(oldHead, newHead *types.Header) []common.Hash {
	g.knownTxsMu.Lock()
	defer g.knownTxsMu.Unlock()

	drops := make([]common.Hash, 0)

	for hash, knownTx := range *g.knownTxs {
		// remove pending timed out tx from tx pool

			drops = append(drops, hash)

		}

		if knownTx.elapsedPromotedOrAddedTime() >= KnownTxTimeout {
			g.knownTxs.delete(hash)
		}
	}

	return drops
}

func (k knownTxs) add(tx *types.Transaction, status int) {
	if tx == nil {
		return
	}

	if ktx, ok := k.get(tx.Hash()); ok {
		ktx.status = status
	} else {
		k[tx.Hash()] = &knownTx{
			tx:           tx,
			addedTime:    time.Time{},
			promotedTime: time.Time{},
			status:       status,
		}
	}

	if status == TxStatusQueue {
		k[tx.Hash()].startAddedTimeIfZero()
	} else if status == TxStatusPending {
		k[tx.Hash()].startPromotedTimeIfZero()
	}

	updateMetrics(&k)
}
