### Title
Reachable assertion in `Decryption::register` allows a DKG participant to panic the process via a second encryption-key registration - (File: crypto/dkg/pedpop/src/encryption.rs)

### Summary
CVE-2024-24430 is a reachable `assert` in `mme_ue_find_by_imsi` that crashes Open5GS on a crafted NAS packet. The Serai analog is the `assert!` in `Decryption::register`, which panics if a `Participant` registers an encryption key twice. A PedPoP participant who transmits a second `EncryptionKeyMessage` (or replays their first) reaches this assertion and aborts the DKG process.

### Finding Description
`EncryptionKeyMessage::read` parses a per-participant broadcast containing an arbitrary `enc_key` point [1](#0-0) . Each received registration is passed to `Encryption::register`, which forwards to `Decryption::register` [2](#0-1) . That function enforces uniqueness with a hard `assert!` rather than returning an error:

```rust
assert!(
  !self.enc_keys.contains_key(&participant),
  "Re-registering encryption key for a participant"
);
``` [3](#0-2) 

The crate's own documentation acknowledges this input is adversary-controlled and outside the library's deduplication control: "If any participant sends multiple sets of commitments, they are faulty and should be presumed malicious. As this library does not handle networking, it is unable to detect if any participant is so faulty." [4](#0-3) . Unlike every other malformed-input path in this module (`read_G`, `read_F`, PoP verification), which return `io::Error`/`DecryptionError`, this case panics unconditionally. (The same pattern — indexing `self.enc_keys[&participant]` / `self.enc_keys[&decryptor]` — would also panic on lookup of an unregistered index at lines 388 and 466.)

### Impact Explanation
An unprivileged DKG participant sends two `EncryptionKeyMessage`s (e.g., by replaying or equivocating on the authenticated broadcast channel). On processing the second one, the honest node's key-generation process panics instead of cleanly rejecting the faulty participant, killing the DKG/session-setup task — a denial of service matching the CVE's "reachable assertion → process termination" class. No private input, timing side channel, or cryptographic break is required; only a duplicated public message.

### Likelihood Explanation
Likelihood is bounded by deployment behavior: the panic only fires if the caller's networking layer forwards a second registration for the same `Participant` into `register`. The library itself admits it cannot deduplicate broadcast messages [4](#0-3) , and I could not fully verify (within the search budget) whether `pedpop`'s key-generation machine gates `Encryption::register` behind prior deduplication. If it does not, any malicious or simply buggy participant can trigger this at will during every DKG round; if it does, the assert is reachable only on caller misuse, which would downgrade it.

### Recommendation
Replace the `assert!` in `Decryption::register` with a fallible check returning a `DecryptionError`/`io::Error` (e.g., "duplicate encryption key registration"), propagating through `Encryption::register` so callers can blame and exclude the faulty participant. Similarly, replace the `HashMap` indexing at `encryption.rs:388` and `encryption.rs:466` with `.get()` + error, so an unregistered `decryptor`/`participant` index cannot panic blame or encryption paths.

### Proof of Concept
1. Two or more nodes run a PedPoP DKG via `crypto/dkg/pedpop`.
2. Attacker participant broadcasts a valid `EncryptionKeyMessage` (parses fine via `EncryptionKeyMessage::read`, `enc_key` = any non-identity point).
3. Attacker broadcasts a second `EncryptionKeyMessage` under the same `Participant` index (replay or equivocation).
4. The victim calls `Encryption::register(participant, msg)` → `Decryption::register` → `enc_keys.contains_key(&participant)` is true → `assert!` fires → panic, aborting the victim's DKG.

Minimal trigger (conceptual):
```rust
let mut dec = Decryption::<Ristretto>::new(context);
dec.register(p, msg.clone());        // ok
dec.register(p, msg);                // panic: "Re-registering encryption key for a participant"
```
