### Title
`updateRemoteUrl` silently repoints a tracked repository's `origin` remote based on an unauthenticated `clone_url` field from the GitHub API - (File: `app/src/lib/stores/updates/update-remote-url.ts`)

### Summary
`PaymentSettler::setStablecoin`'s broken invariant is: a single trusted, shared piece of state (the stablecoin address) gets swapped out unilaterally, while other in-flight/derived state (payouts, burns) still assumes the *old* value, and no validation ties the change back to user intent for the specific transaction being processed. The GitHub Desktop analog is `updateRemoteUrl` in [1](#0-0) , which automatically rewrites the local git `origin` remote URL to whatever `clone_url` the GitHub API currently reports for that repository — a value entirely controlled by the remote GitHub repository/owner, not the local user.

### Finding Description
`repositoryWithRefreshedGitHubRepository` in `app-store.ts` periodically re-fetches the repository object from the GitHub API and calls `updateRemoteUrl(gitStore, repository.gitHubRepository, apiRepo)`: [2](#0-1) 

Inside `updateRemoteUrl`, the only checks performed before silently calling `gitStore.setRemoteURL` are:
1. the URL protocol (http/https/ssh) hasn't changed, and
2. the *previous* API-reported `cloneURL` still matches the locally configured remote (i.e. the user hasn't manually customized the remote away from what Desktop last saw). [3](#0-2) 

Neither check validates *where* the new URL points relative to the user's original intent beyond protocol — it only compares against the previously cached, API-supplied value, which is itself attacker-influenced. `urlMatchesRemote`/`urlsMatch` (used for the "unchanged" check) only compare hostname/owner/name structurally, not authenticity or ownership continuity [4](#0-3) .

Because `clone_url` is a field returned by the GitHub API for a specific `owner/name` repository object, an attacker who controls that repository's metadata (e.g., the original repo owner renames/transfers the repository, or the repository is deleted and someone else re-registers the same `owner/name` after Desktop's DB still has a stale but matching cached `cloneURL`) can cause the value fetched during a routine background refresh to differ from what the user configured, and Desktop will call `gitStore.setRemoteURL(gitStore.defaultRemote.name, updatedRemoteUrl)` with **no user confirmation or diff dialog** [5](#0-4) .

This is triggered automatically as part of routine account/repository refresh flows (e.g. `refreshSelectedRepositoryAfterAccountChange`), not requiring the user to take any unusual action: [6](#0-5) 

Existing guards do not stop this path because:
- The "protocol match" check only restricts scheme (https vs ssh), not host/owner/repo.
- The "remote unchanged" check is based on comparing against Desktop's own previously-cached API value — which was itself populated from an earlier, possibly attacker-controlled API response — not against a value the user explicitly authorized.
- There is no user-visible prompt or diff before `setRemoteURL` executes; it happens silently as a side effect of a background repository info refresh.

### Impact Explanation
If the local `origin` remote is silently repointed to an attacker-influenced URL, all subsequent `git push`/`git fetch` operations performed by Desktop for that repository target the new remote transparently. This can result in: developers pushing (and thus disclosing) commits/code to a repository they don't intend to, or fetching/basing further work on an attacker-supplied history, without any visible warning that the remote changed. This matches the "silent corruption of what the user commits or pushes" impact bucket in the Valid Impact criteria, and the trigger is a "GitHub API object" (the repository's `clone_url` field) under attacker influence — the exact primitive class called out in scope.

### Likelihood Explanation
Likelihood is Low-Medium: it requires a specific sequence — the tracked repository's `owner/name` must resolve on GitHub.com to a `clone_url` that differs from the locally configured remote while satisfying the "previously matched" precondition. This typically occurs via legitimate repository renames/transfers, but the same code path fires unconditionally on any legitimate-looking API response with a changed `clone_url`, so an attacker with control of the repository object (e.g. compromised maintainer account, or claiming a name freed by a rename/deletion) can trigger it without any additional local access, admin rights, or social engineering step from the victim beyond having previously added the repository in Desktop.

### Recommendation
Do not auto-apply remote URL changes silently. At minimum, prompt the user with an explicit confirmation dialog showing old vs. new remote URL before calling `gitStore.setRemoteURL`, and/or require that the change only be applied when it corresponds to a same-owner rename confirmed via a stable identifier (e.g. the GitHub repository's immutable numeric ID) rather than trusting `clone_url` on its own.

### Proof of Concept
1. User adds `https://github.com/victim-org/example` as a tracked repository in Desktop; Desktop caches `gitHubRepository.cloneURL = https://github.com/victim-org/example`.
2. Attacker gains the ability to make the GitHub API return a different `clone_url` for that same tracked `owner/name` entry (e.g., through a repository transfer/rename chain, or reclaiming a freed repository name matching Desktop's stored mapping) such that `apiRepo.clone_url` now resolves to `https://github.com/attacker/example`.
3. On the next background refresh (`repositoryWithRefreshedGitHubRepository` → `updateRemoteUrl`), since protocols match and the old cached `cloneURL` still matches the locally configured `origin` remote, Desktop calls:
```ts
await gitStore.setRemoteURL(gitStore.defaultRemote.name, updatedRemoteUrl) // -> attacker/example
``` [7](#0-6) 
4. The user's next push/fetch in Desktop silently targets `attacker/example` instead of `victim-org/example`, with no dialog shown to the user.

export async function updateRemoteUrl(
  gitStore: GitStore,
  gitHubRepository: GitHubRepository,
  apiRepo: IAPIRepository
): Promise<void> {
  // I'm not sure when these early exit conditions would be met. But when they are
  // we don't have enough information to continue so exit early!
  if (gitStore.defaultRemote === null) {
    return
  }

  const remoteUrl = gitStore.defaultRemote.url
  const updatedRemoteUrl = apiRepo.clone_url
  const urlsMatch = urlMatchesRemote(updatedRemoteUrl, gitStore.defaultRemote)

  // Verify that protocol hasn't changed. If it has we don't want
  // to alter the protocol in case they are relying on a specific one.
  // If protocol is null that implies the url is a ssh url
  // of the format git@github.com:octocat/Hello-World.git, which
  // can't be parsed by URL.parse. In this case we assume the user
  // manually configured their remote to use this format and we don't
  // want to change what they've done just to be safe
  const parsedRemoteUrl = URL.parse(remoteUrl)
  const parsedUpdatedRemoteUrl = URL.parse(updatedRemoteUrl)
  const protocolsMatch =
    parsedRemoteUrl.protocol !== null &&
    parsedUpdatedRemoteUrl.protocol !== null &&
    parsedRemoteUrl.protocol === parsedUpdatedRemoteUrl.protocol

  // Check if the default remote url has been manually changed from the
  // clone url retrieved from the GitHub API previously
  const remoteUrlUnchanged =
    gitStore.defaultRemote &&
    urlMatchesRemote(gitHubRepository.cloneURL, gitStore.defaultRemote)

  if (protocolsMatch && remoteUrlUnchanged && !urlsMatch) {
    await gitStore.setRemoteURL(gitStore.defaultRemote.name, updatedRemoteUrl)
  }

export function urlMatchesRemote(url: string | null, remote: IRemote): boolean {
  if (url == null) {
    return false
  }

  const cloneUrl = parseRemote(url)
  const remoteUrl = parseRemote(remote.url)

  if (remoteUrl == null || cloneUrl == null) {
    return false
  }

  if (!caseInsensitiveEquals(remoteUrl.hostname, cloneUrl.hostname)) {
    return false
  }

  if (remoteUrl.owner == null || cloneUrl.owner == null) {
    return false
  }

  if (remoteUrl.name == null || cloneUrl.name == null) {
    return false
  }

  return (
    caseInsensitiveEquals(remoteUrl.owner, cloneUrl.owner) &&
    caseInsensitiveEquals(remoteUrl.name, cloneUrl.name)
  )
}
