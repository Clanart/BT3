## Analysis

The seed report's core invariant: **an on-chain price consumer must not trust a Chainlink `latestRoundData()` answer as "current" during an L2 sequencer outage, even when a naive `updatedAt`-based staleness check passes**, because on sequencer-based rollups the price feed freezes while the sequencer is down and the guard only catches staleness that exceeds the configured max age — not staleness caused by sequencer unavailability.

The direct local analog is `SimplexPaymaster`, deployed across multiple sequencer-based L2 rollups (Arbitrum, Optimism, Base per the chain list in `tesseract/consensus/beefy/tests/mainnet_rotation.rs`), which consumes Chainlink `AggregatorV3Interface.latestRoundData()` directly and only checks answer positivity and a `maxOracleAge` timestamp bound — with no L2 sequencer-uptime check at all.

### Title
Missing L2 sequencer-uptime check in `SimplexPaymaster` oracle pricing allows stale-price exploitation during rollup sequencer downtime - (File: `evm/src/utils/SimplexPaymaster.sol`)

### Summary
`SimplexPaymaster._getOraclePrice` prices ERC-20 gas payments using Chainlink `latestRoundData()`, guarded only by an `answer > 0` check and a `maxOracleAge` timestamp bound [1](#0-0) . This mirrors exactly the flaw in the seed report's `PriceTierVesting`: no verification that the L2 sequencer was live when the feed was last updated, so a frozen (but not yet "stale" by timestamp) price can be consumed to compute gas costs on sequencer-based L2 deployments of this contract.

### Finding Description
`_tokenPrice` and `swapAndDeposit` both derive USD conversion rates purely from `_getOraclePrice`, which pulls `answer` and `updatedAt` from the configured Chainlink feed and reverts only if the answer is non-positive or `block.timestamp - updatedAt > maxOracleAge` [2](#0-1) . `maxOracleAge` is governance-configurable up to 7 days [3](#0-2) , and stablecoin feeds on some chains are documented to have 24h heartbeats, per the deploy script comment [4](#0-3) .

Chainlink price feeds on sequencer-based L2s (Arbitrum, Optimism, Base — all present in this repo's deployment target list [5](#0-4) ) rely on the sequencer to relay off-chain reports on-chain. When the sequencer is down, the feed's `updatedAt` simply stops advancing while the real market price keeps moving. As long as the outage duration is shorter than the configured `maxOracleAge` (which can be tuned as high as 24h–7d for some feeds), `_getOraclePrice` will happily return the frozen price as valid — there is no dedicated check against a sequencer-uptime feed (e.g., Chainlink's `L2SequencerUptimeFeed`), unlike the recommendation flagged in the seed report.

This is directly reachable by any unprivileged account: `_fetchDetails`/`_validatePaymasterUserOp` is invoked on every ERC-4337 UserOp that uses this paymaster [6](#0-5) , with no gating beyond token registration/activity checks.

### Impact Explanation
During (or immediately after) a sequencer outage, the native/USD or token/USD price used to compute `tokenPrice` can diverge materially from the true market rate while still passing the `maxOracleAge` gate. An attacker who can still get transactions included on the L2 during/after an outage (e.g. via L1 forced-inclusion on Arbitrum/Optimism, or simply once the sequencer resumes but before the feed catches up) can submit UserOps priced against the frozen rate:
- If the native asset appreciated relative to the token during the outage, users are charged too few tokens per unit of gas, draining the paymaster's EntryPoint deposit/treasury balance faster than intended (fund loss to the protocol).
- The same stale-price primitive also affects `swapAndDeposit`'s `amountOutMin` computation [7](#0-6) , which is treasury-gated but still derives its slippage floor from the same unguarded oracle call, so a stale price during a sequencer incident can still push an unfavorable swap through within the nominal slippage bound.

This matches the bounty's "stealing or loss of funds" / "logic attack" category via wrong-amount computation, without requiring any malicious relayer, prover, or admin.

### Likelihood Explanation
Sequencer outages on Arbitrum/Optimism/Base have occurred in production before and are a documented, non-hypothetical risk class (this is precisely why Chainlink publishes and recommends L2 Sequencer Uptime Feeds for these networks). Given `maxOracleAge` can be configured up to 24h/7d in this contract, the exploit window is realistic and does not require any adversarial infrastructure compromise — only normal L2 operational risk plus a permissionless UserOp submission.

### Recommendation
For every L2 deployment of `SimplexPaymaster` that runs on a sequencer-based rollup, integrate the corresponding Chainlink `L2SequencerUptimeFeed` (or equivalent) and revert `_getOraclePrice` if the sequencer is reported down, or is up for less than a configured grace period after recovery — mirroring the standard Chainlink L2 data feed integration guidance referenced in the seed report.

### Proof of Concept
1. Governance configures `maxOracleAge` at the top end of its allowed range (e.g. close to `MAX_ORACLE_AGE = 7 days`) for a token feed with an infrequent heartbeat, or a shorter but still multi-hour heartbeat legitimately used for a slow-moving stablecoin feed [3](#0-2) .
2. The Arbitrum (or Optimism/Base) sequencer experiences an outage. The `nativeOracle`/`tokenOracle` feed's `updatedAt` freezes at the last pre-outage report while the true native-asset/USD market rate drops or rises materially during the outage.
3. Because `block.timestamp - updatedAt` is still `<= maxOracleAge`, `_getOraclePrice` returns the stale answer without reverting [1](#0-0) .
4. An attacker submits a UserOp (via L1 forced-inclusion or shortly after sequencer resumption, before a new round is posted) that is validated/priced through `_fetchDetails` → `_tokenPrice` → `_getOraclePrice` using the frozen rate [8](#0-7) , paying gas in the target ERC-20 at a rate favorable to the attacker relative to the true market price, draining paymaster funds over repeated executions.

    function _fetchDetails(
        PackedUserOperation calldata userOp,
        bytes32 /* userOpHash */
    ) internal view override returns (uint256 validationData, IERC20 token, uint256 tokenPrice) {
        bytes calldata data = userOp.paymasterData();
        if (data.length < 21) revert InvalidPaymasterData(data.length);

        uint8 mode = uint8(data[0]);
        if (mode > 0x01) revert InvalidMode(mode);

        address tokenAddr = address(bytes20(data[1:21]));

        TokenConfig memory cfg = tokenConfigs[tokenAddr];
        if (address(cfg.tokenOracle) == address(0)) revert TokenNotRegistered(tokenAddr);
        if (!cfg.active) revert TokenNotActive(tokenAddr);

        tokenPrice = _tokenPrice(cfg);
        token = IERC20(tokenAddr);
        validationData = 0; // no time-range restriction
    }

    /// @dev Parse and execute the EIP-2612 permit from paymasterData.
    ///      Layout: mode(1) + token(20) + permitAmount(32) + deadline(32) + v(1) + r(32) + s(32) = 150 bytes
    function _executePermit(PackedUserOperation calldata userOp) internal {
        bytes calldata data = userOp.paymasterData();
        if (data.length != 150) revert InvalidPaymasterData(data.length);

        address tokenAddr = address(bytes20(data[1:21]));
        uint256 permitAmount = uint256(bytes32(data[21:53]));
        uint256 deadline = uint256(bytes32(data[53:85]));
        uint8 v = uint8(data[85]);
        bytes32 r = bytes32(data[86:118]);
        bytes32 s = bytes32(data[118:150]);

        address owner = userOp.sender;

        try IERC20Permit(tokenAddr).permit(owner, address(this), permitAmount, deadline, v, r, s) {
            emit PermitExecuted(tokenAddr, owner, permitAmount);
        } catch {
            revert PermitFailed(tokenAddr);
        }
    }

    // ── Pricing ──────────────────────────────────────────────────────

    function _tokenPrice(TokenConfig memory cfg) internal view returns (uint256) {
        uint256 nativeUsd = _getOraclePrice(nativeOracle, nativeOracleDecimals);
        uint256 tokenUsd = _getOraclePrice(cfg.tokenOracle, cfg.tokenOracleDecimals);

        return (nativeUsd * (10 ** cfg.tokenDecimals) * (10_000 + markupBps)) / (tokenUsd * 10_000);
    }

    /// @dev Fetch a Chainlink price normalized to 8 decimals.
    ///      Reverts on stale or non-positive answers.
    function _getOraclePrice(AggregatorV3Interface oracle, uint8 oracleDecimals) internal view returns (uint256) {
        (, int256 answer, , uint256 updatedAt, ) = oracle.latestRoundData();

        if (answer <= 0) revert InvalidOraclePrice(address(oracle), answer);
        if (block.timestamp - updatedAt > maxOracleAge) {
            revert StaleOraclePrice(address(oracle), updatedAt);
        }

        if (oracleDecimals < 8) {
            return uint256(answer) * (10 ** (8 - oracleDecimals));
        } else if (oracleDecimals > 8) {
            return uint256(answer) / (10 ** (oracleDecimals - 8));
        }
        return uint256(answer);
    }
