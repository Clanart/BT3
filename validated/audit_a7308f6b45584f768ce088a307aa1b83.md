### Title
Cross-transaction instruction/origin contamination: data and presumed_origin from one Bitcoin transaction are applied to outputs scanned from earlier transactions in the same block - (File: processor/src/networks/bitcoin.rs)

### Summary
`Bitcoin::get_outputs` accumulates all scanned Serai outputs for an entire block into a single `outputs` vector, then — for every transaction that yields at least one scanned output *or* follows any transaction that did — computes a single `presumed_origin` (from `tx.input[0]`'s spent output) and a single `data` payload (from `extract_serai_data(tx)`), and stamps them onto **every output accumulated so far**, including outputs that came from *other, earlier transactions*. An attacker who mines/relays a crafted transaction in the same block as a victim's deposit can overwrite the victim output's `data` (the InInstruction) and `presumed_origin` after the fact.

### Finding Description
In `get_outputs`, `outputs` is declared once outside the per-transaction loop and never cleared per transaction:

```rust
let mut outputs = vec![];
for tx in &block.txdata[1 ..] {
  for output in scanner.scan_transaction(tx) { ... outputs.push(output); }
  if outputs.is_empty() { continue; }
  let presumed_origin = { let input = &tx.input[0]; ... };
  let data = Self::extract_serai_data(tx);
  for output in &mut outputs {   // ALL accumulated outputs, not just this tx's
    if output.kind == OutputType::External { output.data.clone_from(&data); }
    output.presumed_origin.clone_from(&presumed_origin);
  }
}
``` [1](#0-0) 

Two compounding flaws:

1. `if outputs.is_empty() { continue }` tests the block-wide accumulator, not the outputs from *this* transaction. A transaction contributing zero Serai outputs still triggers the stamping pass as long as any earlier transaction contributed one.
2. `for output in &mut outputs` iterates every output collected so far, so `data` and `presumed_origin` extracted from the current transaction are written onto outputs belonging to unrelated earlier transactions.

`extract_serai_data` returns attacker-controlled bytes: the last push of the first OP_RETURN output, or `witness[len-2]` of the first input whose trailing witness item is a script matching `OP_SHA256 <hash> OP_EQUALVERIFY` (`segwit_data_pattern`), truncated to `MAX_DATA_LEN`. [2](#0-1)  `presumed_origin` is derived from whatever output the transaction's first input spends. [3](#0-2) 

Downstream, `output.data()` is parsed via `instruction_from_output` into an `InInstruction`/`RefundableInInstruction`, which drives `PlanFromScanning` decisions including `Refund(output, refund_to)` and transfer instructions crediting Serai accounts. [4](#0-3)  The spec documents that the InInstruction is taken from the transaction's OP_RETURN and `origin` from its first input — assuming they're bound to the transaction paying Serai, which this code fails to enforce. [5](#0-4) 

### Impact Explanation
An unprivileged attacker sends a Bitcoin transaction that (a) appears in a confirmed block *after* a victim's deposit transaction to a Serai External address, and (b) carries a crafted OP_RETURN payload (or P2WSH witness-embedded message) decoding to an `InInstruction` of the attacker's choosing — e.g., a `transfer` crediting the attacker's Serai account, or an instruction with a `refund_to` pointing at an attacker-controlled Bitcoin address. Because the stamping loop rewrites `data`/`presumed_origin` on all accumulated outputs, the victim's already-scanned output is re-labeled with the attacker's instruction. Serai then processes the victim's real BTC deposit as the attacker's instruction: the attacker is minted funds they never deposited, or the victim's output is "refunded" to the attacker's address. This is theft of deposit attribution / funds reported received under a forged instruction, reachable purely by publishing attacker-crafted transactions on-chain.

### Likelihood Explanation
The attacker only needs their transaction mined in the same block after the victim's deposit (or in any position, since any later victim tx would restamp). No key material, no threshold collusion, and no node compromise is required — ordering within a block is achievable via normal mempool/fees, and a zero-confirmation race isn't needed since scanning is per-block. The attacker tx doesn't even need to pay Serai; a `continue` is only hit when *no* output has been accumulated yet.

### Recommendation
Scope the metadata stamping to the outputs of the current transaction only:

```rust
for tx in &block.txdata[1 ..] {
  let scanned = scanner.scan_transaction(tx);
  if scanned.is_empty() { continue; }
  let presumed_origin = ...;
  let data = Self::extract_serai_data(tx);
  for output in scanned { /* set data/presumed_origin on this tx's outputs */ outputs.push(output); }
}
```
Additionally, consider binding `data` per-output (e.g., only to the output(s) matching the declared InInstruction structure) rather than broadcasting one payload to all External outputs of a transaction, and document/verify the intended behavior when multiple OP_RETURN outputs exist.

### Proof of Concept
1. Victim broadcasts `tx_v` paying the Serai External address, with a legitimate OP_RETURN InInstruction `D_v` (e.g., transfer to victim's Serai account). It is mined as `block.txdata[k]`.
2. Attacker broadcasts `tx_a` (any inputs they own, first input spending an attacker address) with OP_RETURN output encoding `D_a` = `Shorthand::transfer(None, attacker_serai_addr)` or a `RefundableInInstruction` with attacker `refund_to`. It is mined as `block.txdata[k+1]` (or any later position).
3. `get_outputs(block, key)`: at `tx_v`, victim output is pushed with `data = D_v`. At `tx_a`, `outputs` is non-empty, so `data = extract_serai_data(tx_a) = D_a` is computed and `output.data.clone_from(&D_a)` overwrites the victim output's instruction; `presumed_origin` is overwritten to the attacker's address.
4. `instruction_from_output` parses `D_a` for the victim's output; the scheduler produces a plan crediting/refunding the attacker for BTC the victim sent.

  fn extract_serai_data(tx: &Transaction) -> Vec<u8> {
    // check outputs
    let mut data = (|| {
      for output in &tx.output {
        if output.script_pubkey.is_op_return() {
          match output.script_pubkey.instructions_minimal().last() {
            Some(Ok(Instruction::PushBytes(data))) => return data.as_bytes().to_vec(),
            _ => continue,
          }
        }
      }
      vec![]
    })();

    // check inputs
    if data.is_empty() {
      for input in &tx.input {
        let witness = input.witness.to_vec();
        // expected witness at least has to have 2 items, msg and the redeem script.
        if witness.len() >= 2 {
          let redeem_script = ScriptBuf::from_bytes(witness.last().unwrap().clone());
          if Self::segwit_data_pattern(&redeem_script) == Some(true) {
            data.clone_from(&witness[witness.len() - 2]); // len() - 1 is the redeem_script
            break;
          }
        }
      }
    }

    data.truncate(MAX_DATA_LEN.try_into().unwrap());
    data
  }

  async fn get_outputs(&self, block: &Self::Block, key: ProjectivePoint) -> Vec<Output> {
    let (scanner, _, kinds) = scanner(key);

    let mut outputs = vec![];
    // Skip the coinbase transaction which is burdened by maturity
    for tx in &block.txdata[1 ..] {
      for output in scanner.scan_transaction(tx) {
        let offset_repr = output.offset().to_repr();
        let offset_repr_ref: &[u8] = offset_repr.as_ref();
        let kind = kinds[offset_repr_ref];

        let output = Output { kind, presumed_origin: None, output, data: vec![] };
        assert_eq!(output.tx_id(), tx.id());
        outputs.push(output);
      }

      if outputs.is_empty() {
        continue;
      }

      // populate the outputs with the origin and data
      let presumed_origin = {
        // This may identify the P2WSH output *embedding the InInstruction* as the origin, which
        // would be a bit trickier to spend that a traditional output...
        // There's no risk of the InInstruction going missing as it'd already be on-chain though
        // We *could* parse out the script *without the InInstruction prefix* and declare that the
        // origin
        // TODO
        let spent_output = {
          let input = &tx.input[0];
          let mut spent_tx = input.previous_output.txid.as_raw_hash().to_byte_array();
          spent_tx.reverse();
          let mut tx;
          while {
            tx = self.rpc.get_transaction(&spent_tx).await;
            tx.is_err()
          } {
            log::error!("couldn't get transaction from bitcoin node: {tx:?}");
            sleep(Duration::from_secs(5)).await;

          tx.unwrap().output.swap_remove(usize::try_from(input.previous_output.vout).unwrap())
        };
        Address::new(spent_output.script_pubkey)
      };
      let data = Self::extract_serai_data(tx);
      for output in &mut outputs {
        if output.kind == OutputType::External {
          output.data.clone_from(&data);
        }
        output.presumed_origin.clone_from(&presumed_origin);
      }
    }

    outputs
  }
