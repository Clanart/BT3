### Title
Concurrent map write / data race in Gasless module's `knownTxs` under `RLock` in `PreAddTx` - ([File: kaiax/gasless/impl/tx_pool.go])

### Summary
`GaslessModule.PreAddTx` takes a **read** lock (`knownTxsMu.RLock()`) but then performs an in-place **write** to the shared `knownTxs` map via `g.knownTxs.add(tx, TxStatusQueue)`. Because `sync.RWMutex.RLock()` permits multiple concurrent holders, any two unprivileged callers submitting transactions concurrently (e.g. via `eth_sendRawTransaction`/`AddRemotes`) can execute `PreAddTx` in parallel and both end up writing to the same Go map without mutual exclusion — an unsynchronized concurrent map write. This mirrors the bug class in CVE-2025-37926 (ksmbd `ksmbd_session_rpc_open`/`__session_rpc_close`): a shared, mutable per-request resource is opened/mutated on one code path while readers/other mutators race it because the wrong (or no) exclusive lock is used.

### Finding Description
`PreAddTx` is registered as a `kaiax.TxPoolModule` hook invoked from `blockchain/tx_pool.go` whenever a new transaction is submitted to the pool (local or remote, i.e., reachable directly from public RPC transaction submission). [1](#0-0) 

The lock discipline is:
- `PreAddTx` — `knownTxsMu.RLock()` (read lock) but calls `g.knownTxs.add(...)` (mutates map)
- `IsReady` — `knownTxsMu.Lock()` (write lock), also calls `g.knownTxs.add(...)`
- `PreReset` / `PostReset` — `knownTxsMu.Lock()` (write lock), call `g.knownTxs.delete(...)` / `add(...)` [2](#0-1) [3](#0-2) 

`knownTxs` is a plain Go map type (`map[common.Hash]*knownTx`), and `add`/`delete` mutate that map directly (insert new key, update metrics, etc.) with no internal synchronization of their own — they rely entirely on the caller holding `knownTxsMu` correctly: [4](#0-3) [5](#0-4) 

Since `PreAddTx` only takes `RLock()`, two goroutines processing two different transactions concurrently (both hitting the `g.IsBundleTx(tx)` branch) can simultaneously execute `k[tx.Hash()] = &knownTx{...}` on the same underlying map — this is a classic unsynchronized concurrent write to a Go map, which will panic with "fatal error: concurrent map writes" (crashing the node) or, in the read+write concurrent case, "concurrent map read and map write" if `IsReady`/`PreReset` (which correctly take `Lock()`) run at the same time as a mis-synchronized `PreAddTx`.

### Impact Explanation
A crash of `fatal error: concurrent map writes/read` in Go is unrecoverable via `recover()` — it terminates the process. Because `PreAddTx` runs on every transaction admitted to the pool and the vulnerable path is reached whenever gasless "bundle" transactions (approve/swap) are submitted concurrently by an unprivileged sender, an attacker can trigger this race deterministically by submitting concurrent gasless-bundle transactions from multiple senders/goroutines through the public RPC endpoint. This is a remotely triggerable denial-of-service against every full/consensus node running the gasless module, causing state divergence risk (nodes crashing at different times) and network-wide liveness impact — comparable in severity to the referenced UAF crash primitive, though the underlying primitive here is a Go map race rather than a memory-safety UAF.

### Likelihood Explanation
High: gasless transactions are user-submitted via standard `eth_sendRawTransaction` and pooled the same way as ordinary transactions; the trigger only requires two or more requests processed concurrently by the tx-pool worker(s) (no special privileges, no consensus state needed). Because `AddRemotes`/RPC handling naturally processes multiple submitted transactions concurrently, the race window is realistically hit under moderate transaction load or by an attacker deliberately flooding gasless bundle txs from multiple connections.

### Recommendation
Change `PreAddTx` to take the exclusive lock (`knownTxsMu.Lock()`/`defer Unlock()`) instead of `RLock()`, matching the write it performs, consistent with `IsReady`, `PreReset`, and `PostReset`. Audit all other call sites of `knownTxsMu` to ensure every mutating access to `knownTxs` (or its constituent `*knownTx` fields) is guarded by the write lock, and that no method mutates shared state while holding only a read lock.

### Proof of Concept
1. Start a node with the gasless module enabled (`GaslessConfig` set, allowed tokens/swap router configured).
2. Craft two distinct valid gasless "bundle" transactions (`approve`/`swap` per `IsBundleTx`) from two different signer accounts.
3. Submit both concurrently via `eth_sendRawTransaction` (or call `TxPool.AddRemotes` with both) from two goroutines/connections so that both invocations of `GaslessModule.PreAddTx` execute in parallel and both reach `g.knownTxs.add(tx, TxStatusQueue)` (i.e. `knownTxs.get()` for both misses, or both take the metrics-update path) at effectively the same time.
4. Because both hold only `RLock()`, the concurrent writes to the underlying `knownTxs` map race; running the node with `-race` reproduces `DATA RACE` immediately, and under sufficient concurrency, production builds crash with `fatal error: concurrent map writes`. [1](#0-0)

func (g *GaslessModule) PreAddTx(tx *types.Transaction, local bool) error {
	g.knownTxsMu.RLock()
	defer g.knownTxsMu.RUnlock()

	if knownTx, ok := g.knownTxs.get(tx.Hash()); ok && knownTx.elapsedPromotedOrAddedTime() < KnownTxTimeout {
		return ErrUnableToAddKnownBundleTx
	}

	if g.IsBundleTx(tx) {
		if uint(g.knownTxs.numQueue()) >= g.GetMaxBundleTxsInQueue() {
			return ErrBundleTxQueueFull
		}
		g.knownTxs.add(tx, TxStatusQueue)
	}
	return nil
}

// Check promotion condition and enforce pending pool flow control.
func (g *GaslessModule) IsReady(txs map[uint64]*types.Transaction, next uint64, ready types.Transactions) bool {
	g.knownTxsMu.Lock()
	defer g.knownTxsMu.Unlock()

	tx, ok := txs[next]
	if !ok {
		return false
	}

	if !g.isReady(txs, next, ready) {
		return false
	}

	if g.IsBundleTx(tx) {
		// If prev tx is bundle tx, there's no need to check the knownTxs limit because it has been checked in the previous `IsReady()` execution.
		isPrevTxBundleTx := len(ready) != 0 && g.IsBundleTx(ready[len(ready)-1])
		if isPrevTxBundleTx {
			g.knownTxs.add(tx, TxStatusPending)
			return true
		}

		maxBundleTxsInPending := g.GetMaxBundleTxsInPending()
		if maxBundleTxsInPending != math.MaxUint64 {
			numExecutable := uint(g.knownTxs.numExecutable())

			numSeqTxs := uint(1)
			for i := next + 1; i < next+uint64(len(txs)); i++ {
				if tx, ok := txs[i]; ok && g.IsBundleTx(tx) {
					numSeqTxs++
				} else {
					break
				}
			}

			// false if there is possibility of exceeding max bundle tx num
			if numExecutable+numSeqTxs > maxBundleTxsInPending {
				logger.Trace("Not promoting a tx because of exceeding max bundle tx num", "tx", tx.Hash().String(), "numExecutable", numExecutable, "maxBundleTxsInPending", maxBundleTxsInPending)
				return false
			}
		}

		g.knownTxs.add(tx, TxStatusPending)
	}

	return true
}

// PreReset removes timed out tx from the tx pool and knownTxs.
func (g *GaslessModule) PreReset(oldHead, newHead *types.Header) []common.Hash {
	g.knownTxsMu.Lock()
	defer g.knownTxsMu.Unlock()

	drops := make([]common.Hash, 0)

	for hash, knownTx := range *g.knownTxs {
		// remove pending timed out tx from tx pool
		if knownTx.status == TxStatusPending && knownTx.elapsedPromotedTime() >= PendingTimeout {
			drops = append(drops, hash)
		}
		// remove queue timed out tx from tx pool
		if knownTx.status == TxStatusQueue && knownTx.elapsedAddedTime() >= QueueTimeout {
			drops = append(drops, hash)
		}
		// remove known timed out tx from knownTxs
		if knownTx.elapsedPromotedOrAddedTime() >= KnownTxTimeout {
			g.knownTxs.delete(hash)
		}
	}

	return drops
}

type knownTxs map[common.Hash]*knownTx

func (k knownTxs) add(tx *types.Transaction, status int) {
	if tx == nil {
		return
	}

	if ktx, ok := k.get(tx.Hash()); ok {
		ktx.status = status
	} else {
		k[tx.Hash()] = &knownTx{
			tx:           tx,
			addedTime:    time.Time{},
			promotedTime: time.Time{},
			status:       status,
		}
	}

	if status == TxStatusQueue {
		k[tx.Hash()].startAddedTimeIfZero()
	} else if status == TxStatusPending {
		k[tx.Hash()].startPromotedTimeIfZero()
	}

	updateMetrics(&k)
}
