## Finding

### Title
Unbounded loop in `object::root_owner()` allows gas-exhaustion DoS of code-object publish/upgrade and lazy module self-init — (File: `aptos-move/framework/aptos-framework/sources/object.move`)

### Summary
The external report's root cause is a state invariant that is updated in one direction (incremented) but never re-validated/bounded on the other, letting a legitimate but adversarial state accumulate until it breaks a protected operation for everyone. The Aptos-native analog is in `object::root_owner()`, used by the code-object publish/upgrade path (`code::publish_package`) and by the lazy module self-init gate (`init::assert_may_self_initialize`): unlike its sibling ownership-walking functions, it has no nesting/cycle bound, so a cyclic object-ownership chain (which `object::transfer`/`transfer_raw` permits to be created) turns every future call into an unbounded loop.

### Finding Description
`object::root_owner()` walks the ownership chain upward with no depth limit: [1](#0-0) 

Compare this to the two other ownership-chain walkers in the same module, `owns` and `verify_ungated_and_descendant`, which both explicitly bound the walk with `MAXIMUM_OBJECT_NESTING` and abort with `EMAXIMUM_NESTING` once exceeded: [2](#0-1) [3](#0-2) 

`object::transfer_raw` lets an object be transferred to any destination address, including an address derived from the object itself, and the module's own test explicitly demonstrates that a *self-owned* object can be created in a single transfer (the second attempt is what hits the nesting bound, not the first): [4](#0-3) 

`root_owner()` is exactly the primitive relied on by the code-publish path for lazy module initialization. In `code::publish_package`, for object-hosted packages with the `LAZY_MODULE_INITIALIZATION` feature enabled, the root owner is computed and recorded per module on every (re)publish/upgrade: [5](#0-4) 

And `init::assert_may_self_initialize`, the gate that `internal_maybe_initialize` (used by `init::internal_maybe_initialize`, the compiler-generated lazy self-init entry point) calls before minting a signer for an object-hosted module, also calls `root_owner()` directly: [6](#0-5) 

Because `root_owner()` has no cycle guard, if the object hosting a published/deployed package (or any ancestor in its `.owner` chain) is ever put into a self-referential or cyclic ownership state, every subsequent call to `root_owner()` on that address loops until the transaction runs out of gas:
- Any attempt to republish/upgrade that code object while `LAZY_MODULE_INITIALIZATION` is enabled fails (out-of-gas) inside `code::publish_package`, because it unconditionally computes `root_owner()` for object addresses before recording `deploy_owner`.
- Any attempt to lazily self-initialize a module at that address via `init::internal_maybe_initialize` fails the same way inside `assert_may_self_initialize`.

This is a code-safety invariant break: `code.move`/`init.move` assume `root_owner()` always terminates and returns a comparable owner value, but `object.move` does not actually guarantee termination for objects whose ownership chain is (or becomes) cyclic — a state `object::transfer`/`transfer_raw` itself permits to be created.

### Impact Explanation
Once a cyclic ownership state exists on the object hosting a package, the object's code becomes permanently un-upgradable and un-freezable-via-normal-flow whenever `LAZY_MODULE_INITIALIZATION` is active, and any module relying on `init::internal_maybe_initialize` for its startup logic can never complete initialization — a persistent denial of service on the object-code-deployment publish/upgrade path and on module self-init, both explicitly in-scope "publish-path and code-safety impacts." Direct-owner-gated actions (`object_code_deployment::upgrade`, `code::freeze_code_object`, which check `object::is_owner` rather than `root_owner`) are unaffected, which narrows — but does not eliminate — the blast radius to the lazy-init/record-deploy-owner code path.

### Likelihood Explanation
Creating a self-owned or cyclic object is a single permissionless call to `object::transfer`/`transfer_call` (demonstrated by the module's own `test_cyclic_ownership_transfer_should_fail`), requiring only that `allow_ungated_transfer` is set on the object (the default). The remaining precondition — that the affected object also hosts a published package and that `LAZY_MODULE_INITIALIZATION` is enabled — limits it to that feature's scope, but the primitive bug (`root_owner()` lacking the same bound as `owns`/`verify_ungated_and_descendant`) is a straightforward, low-effort trigger once that feature is live.

### Recommendation
Bound `root_owner()`'s walk with the same `MAXIMUM_OBJECT_NESTING` guard used in `owns` and `verify_ungated_and_descendant`, aborting with `EMAXIMUM_NESTING` (or a dedicated error) instead of looping unboundedly, so that `code::publish_package` and `init::assert_may_self_initialize` fail fast and predictably rather than exhausting gas on cyclic ownership states.

### Proof of Concept
1. Deploy a package to an object address `O` via `object_code_deployment::publish` with `LAZY_MODULE_INITIALIZATION` enabled.
2. As `O`'s owner, call `object::transfer_call(owner, O, O)` — per `test_cyclic_ownership_transfer_should_fail`'s first transfer, this succeeds and sets `O.owner == O` (self-cycle), since `verify_ungated_and_descendant` trivially passes when `owner == current_address` before the loop starts.
3. Attempt `object_code_deployment::upgrade(...)` (or any entry function whose module calls `init::internal_maybe_initialize`) targeting `O`. Both paths call `object::address_to_object::<ObjectCore>(O).root_owner()`, which loops forever (`is_object(O)` is always true and `owner()` never changes), consuming all gas and aborting the transaction — permanently blocking upgrade/self-init for `O`.

    /// object between the two allows for ungated transfers. Note, this is limited to a depth of 8

    fun verify_ungated_and_descendant(owner: address, destination: address) {
        let current_address = destination;
        assert!(
            exists<ObjectCore>(current_address),
            error::not_found(EOBJECT_DOES_NOT_EXIST),
        );

        let object = borrow_global<ObjectCore>(current_address);
        assert!(
            object.allow_ungated_transfer,
            error::permission_denied(ENO_UNGATED_TRANSFERS),
        );

        let current_address = object.owner;
        let count = 0;
        while (owner != current_address) {
            count += 1;
            assert!(count < MAXIMUM_OBJECT_NESTING, error::out_of_range(EMAXIMUM_NESTING));
            // At this point, the first object exists and so the more likely case is that the
            // object's owner is not an object. So we return a more sensible error.

            assert!(

                error::permission_denied(ENO_UNGATED_TRANSFERS),

        };

    /// Return true if the provided address has indirect or direct ownership of the provided object.
    ///
    /// Note: intentionally not using `self` as first argument, as a.owns(b) syntax would be ambiguous.
    public fun owns<T: key>(object: Object<T>, owner: address): bool {
        let current_address = object.object_address();

        assert!(
            exists<ObjectCore>(current_address),
            error::not_found(EOBJECT_DOES_NOT_EXIST),
        );

        if (current_address == owner) {
            return true
        };

        let object = borrow_global<ObjectCore>(current_address);
        let current_address = object.owner;

        let count = 0;
        while (owner != current_address) {
            count += 1;
            assert!(count < MAXIMUM_OBJECT_NESTING, error::out_of_range(EMAXIMUM_NESTING));
            if (!exists<ObjectCore>(current_address)) {
                return false
            };

            let object = borrow_global<ObjectCore>(current_address);
            current_address = object.owner;
        };
        true
    }

    /// Returns the root owner of an object. As objects support nested ownership, it can be useful
    /// to determine the identity of the starting point of ownership.
    public fun root_owner<T: key>(self: Object<T>): address {
        let obj_owner = self.owner();
        while (is_object(obj_owner)) {
            obj_owner = address_to_object<ObjectCore>(obj_owner).owner();
        };
        obj_owner
    }
