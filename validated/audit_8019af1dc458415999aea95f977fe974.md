### Title
Unbounded index access in mempool canonical-CLVM check causes an unhandled `IndexError` on attacker-crafted spend-bundle bytes - (File: chia/full_node/mempool_manager.py)

### Summary
`is_clvm_canonical()` and `is_atom_canonical()` in `chia/full_node/mempool_manager.py` walk a CLVM-serialized buffer (`puzzle_reveal` / `solution` bytes taken directly from an attacker-submitted `SpendBundle`) using raw `bytes` indexing (`clvm_buffer[offset]`) with no bounds check before each access. [1](#0-0)  This is directly analogous to the CVE-2017-12122 bug class: a parser trusts an attacker-supplied length/tag byte to decide how many more bytes to consume, without validating that those bytes exist in the buffer, leading to an out-of-bounds read.

### Finding Description
`is_atom_canonical()` reads `clvm_buffer[offset]` and, based on the top bits of that byte, computes a `prefix_len` (0–5) and then loops `prefix_len` times incrementing `offset` and reading `clvm_buffer[offset]` again — with no check that `offset` stays within `len(clvm_buffer)`. [2](#0-1) 

`is_clvm_canonical()` calls this in a loop as well, advancing `offset` past pair markers (`0xFF`) and atoms, again with no bounds check between reads. [1](#0-0)  A trivial one-byte buffer such as `b"\xff"` (a pair marker with nothing following) causes the loop to try to read `clvm_buffer[1]` on a length-1 buffer, raising an unhandled `IndexError`.

This function is invoked directly on the raw bytes of every coin spend's `puzzle_reveal` and `solution` inside `MempoolManager.validate_spend_bundle()`: [3](#0-2) 
`validate_spend_bundle()` is called from `MempoolManager.add_spend_bundle()`, which is reached by any unprivileged spend-bundle submitter through the normal mempool admission path (`new_transaction`/`respond_transaction` protocol handling and RPC `push_tx`). [4](#0-3) 

Because `is_clvm_canonical`/`is_atom_canonical` raise a raw `IndexError` rather than a handled `ValueError`/`AssertionError` that upstream code expects, this exception is not part of the deliberate control-flow (`Err.INVALID_COIN_SOLUTION` path) and propagates as an unexpected exception out of `validate_spend_bundle()`/`add_spend_bundle()`.

### Impact Explanation
An unprivileged party can submit a `SpendBundle` whose `puzzle_reveal` or `solution` bytes are non-canonical CLVM encodings engineered so that a length-prefix byte claims more trailing bytes than remain in the buffer (or ends immediately after a `0xFF` pair marker). This is reachable purely by submitting a transaction — no mining, farming, or peer-level privilege is required. If the resulting `IndexError` is not caught by a generic exception handler somewhere higher in the mempool/RPC call stack, it will propagate as an unexpected error during spend-bundle admission, which is a spend-triggered transaction-processing disruption for the node handling that bundle (the task/handler processing `add_spend_bundle` fails ungracefully rather than cleanly rejecting the bundle with `Err.INVALID_COIN_SOLUTION`).

### Likelihood Explanation
High reachability: any coin spend with a puzzle_reveal or solution byte sequence is passed unmodified into `is_clvm_canonical()` before any other structural validation of the raw bytes' extent. Because CLVM allows attacker-fully-controlled puzzle_reveal/solution byte content (the bundle need not even be a valid/spendable puzzle for this function to execute, since it runs before signature/coin validity checks reject it), constructing a short/truncated non-canonical atom encoding is trivial and requires no special resources.

Confidence caveat: I was unable to fully trace, within the available context, every call site up the stack (i.e., whether `full_node.py`'s `respond_transaction`/`new_transaction` handlers or the RPC `push_tx` wrapper wrap this call in a blanket `try/except Exception`, which would downgrade this from a crash to a harmless logged error). If such a generic exception handler exists, the practical impact is reduced to a benign rejection rather than a processing halt.

### Recommendation
Add explicit bounds checks in `is_atom_canonical()` and `is_clvm_canonical()` before every `clvm_buffer[offset]` access (both for the initial tag byte and for each of the `prefix_len` continuation bytes), raising a well-defined, already-handled error (e.g. `ValueError`) instead of allowing a raw `IndexError`/`AssertionError` to escape. This should mirror the bounds-checking style already used elsewhere in the codebase, e.g. `skip_bytes()`/`skip_list()` in `chia/full_node/full_block_utils.py`, which explicitly check `len(buf)` before indexing. [5](#0-4)

def is_atom_canonical(clvm_buffer: bytes, offset: int) -> tuple[int, bool]:
    b = clvm_buffer[offset]
    if (b & 0b11000000) == 0b10000000:
        # 6 bits length prefix
        mask = 0b00111111
        prefix_len = 0
        min_value = 1
    elif (b & 0b11100000) == 0b11000000:
        # 5 + 8 bits length prefix
        mask = 0b00011111
        prefix_len = 1
        min_value = 1 << 6
    elif (b & 0b11110000) == 0b11100000:
        # 4 + 8 + 8 bits length prefix
        mask = 0b00001111
        prefix_len = 2
        min_value = 1 << (5 + 8)
    elif (b & 0b11111000) == 0b11110000:
        # 3 + 8 + 8 + 8 bits length prefix
        mask = 0b00000111
        prefix_len = 3
        min_value = 1 << (4 + 8 + 8)
    elif (b & 0b11111100) == 0b11111000:
        # 2 + 8 + 8 + 8 + 8 bits length prefix
        mask = 0b00000011
        prefix_len = 4
        min_value = 1 << (3 + 8 + 8 + 8)
    elif (b & 0b11111110) == 0b11111100:
        # 1 + 8 + 8 + 8 + 8 + 8 bits length prefix
        mask = 0b00000001
        prefix_len = 5
        min_value = 1 << (2 + 8 + 8 + 8 + 8)

    atom_len = b & mask
    for i in range(prefix_len):
        atom_len <<= 8
        offset += 1
        atom_len |= clvm_buffer[offset]

    return 1 + prefix_len + atom_len, atom_len >= min_value
```

def is_clvm_canonical(clvm_buffer: bytes) -> bool:
    """
    checks whether the CLVM serialization is all canonical representation.
    atoms can be serialized in more than one way by using more bytes than
    necessary to encode the length prefix. This functions ensures that all atoms are
    encoded with the shortest representation. back-references are not allowed
    and will make this function return false
    """
    assert clvm_buffer != b""

    offset = 0
    tokens_left = 1
    while True:
        b = clvm_buffer[offset]

        # pair
        if b == 0xFF:
            tokens_left += 1
            offset += 1
            continue

        # back references cannot be considered canonical, since they may be
        # encoded in many different ways
        if b == 0xFE:
            return False

        # small atom or NIL
        if b <= 0x80:
            tokens_left -= 1
            offset += 1
        else:
            atom_len, canonical = is_atom_canonical(clvm_buffer, offset)
            if not canonical:
                return False
            tokens_left -= 1
            offset += atom_len

        if tokens_left == 0:
            break

    # if there's garbage at the end, it's not canonical
    return offset == len(clvm_buffer)
```

def skip_list(buf: memoryview, skip_item: Callable[[memoryview], memoryview]) -> memoryview:
    if len(buf) < 4:
        raise ValueError(f"list count prefix requires 4 bytes, remaining buffer {len(buf)}")
    n = int.from_bytes(buf[:4], "big", signed=False)
    buf = buf[4:]
    if n > len(buf):
        raise ValueError(f"list count {n} exceeds remaining buffer {len(buf)}")
    for _ in range(n):
        buf = skip_item(buf)
    return buf


def skip_bytes(buf: memoryview) -> memoryview:
    if len(buf) < 4:
        raise ValueError(f"byte length prefix requires 4 bytes, remaining buffer {len(buf)}")
    n = int.from_bytes(buf[:4], "big", signed=False)
    buf = buf[4:]
    if n > len(buf):
        raise ValueError(f"byte length {n} exceeds remaining buffer {len(buf)}")
    return buf[n:]
