### Title
Unenforced `_paused` flag in IntentsBase allows fills/settlements to proceed after gateway is halted - (File: evm/src/apps/intentsv2/IntentsBase.sol)

### Summary
`IntentsBase` (the shared base for the IntentGateway v2 across both `evm/src/apps/IntentGatewayV2.sol` and `evm/tron/contracts/apps/IntentGatewayV2.sol`) declares a `_paused` boolean state variable, explicitly commented as "Appended last to preserve existing storage slots," which is the standard signature of an emergency-pause switch retrofitted onto an existing upgradeable contract. No function in the intents code path reads `_paused`. `placeOrder`, `fillOrder` (`_fillSameChain`/`_fillCrossChain`), `select`, `cancelOrder` (`_cancelSameChain`/`_cancelFromSource`/`_cancelFromDest`), `onAccept`'s `withdraw`, and `onGetResponse` all execute unconditionally regardless of `_paused`'s value.

### Finding Description
This mirrors the SecondSwap defect precisely: a boolean settability/availability flag (`sellable` there, `_paused` here) is written to storage and clearly intended to gate a class of actions, but the completion/settlement function(s) never check it. In SecondSwap, `listVesting` checked `sellable` but `completePurchase` did not. Here, `_paused` exists as dedicated storage (appended at the end of the layout to preserve slots across an upgrade — strongly implying it is set by an admin-facing setter elsewhere, e.g. through `ParamsUpdate`/governance or a dedicated pause function not present in this file but expected to be wired in), yet none of the public entrypoints in `IntentGatewayV2.sol` or the shared logic in `IntentsBase.sol`/`IntrinsicIntents.sol`/`ExtrinsicIntents.sol` consult it before moving escrowed funds.

Concretely: `fillOrder` performs its expiry/duplicate/solver-selection/array-length checks but no pause check before delegating to `_fillSameChain` (which transfers user's escrowed input tokens to the solver and output tokens to the beneficiary) or `_fillCrossChain` (which dispatches a cross-chain `RedeemEscrow` message). Likewise `onAccept` → `withdraw` in `IntentsBase.sol` unconditionally transfers escrowed tokens to whatever beneficiary is decoded from the incoming ISMP message, and `cancelOrder`'s three routes unconditionally release or refund escrow — none check `_paused`.

### Impact Explanation
If the gateway is intended to be pausable (the storage slot exists for exactly this purpose) but the check is missing, an operator's attempt to halt the protocol in response to a discovered incident (e.g., a bad oracle price, a compromised solver, a bug in fill/withdraw logic, or a need to freeze funds during an upgrade) would have no effect on fund movement. Users and solvers could continue to place, fill, and settle orders — including draining escrowed funds via `fillOrder`/`withdraw` — exactly during the window the flag was meant to stop such actions. This is a false-safety-state acceptance: the system believes it is paused (state says so) but the execution path treats it as live, which can result in fund loss during an active incident response window.

### Likelihood Explanation
The condition is triggered purely by normal invocation of already-public, unprivileged entrypoints (`fillOrder`, `cancelOrder`, `onAccept`/`onGetResponse` via relayer delivery) — no malicious peer, relayer, or admin action is required beyond the fact that pause was set at all. Given the variable exists in every deployment of `IntentGatewayV2` (both the primary EVM and the Tron variant since they share `IntentsBase`), and given it was deliberately appended to preserve storage layout (a strong signal of intended-but-incomplete pause wiring), this is a realistic and directly exploitable oversight rather than a hypothetical scenario.

### Recommendation
Add a `whenNotPaused` modifier (checking `_paused`) to `placeOrder`, `fillOrder`, `cancelOrder`, `select`, and to the settlement entrypoints `onAccept`/`onGetResponse` (or at minimum to `withdraw`), consistent with how `EvmHost.sol`'s `notFrozen` modifier gates dispatch when the host is frozen. Ensure the setter for `_paused` is present, access-controlled, and unit-tested to confirm it actually blocks fund movement end-to-end.

### Proof of Concept
1. Assume an admin setter for `_paused` exists (or is added) and sets `_paused = true` on `IntentGatewayV2` in response to an incident.
2. A user calls `placeOrder` — succeeds, escrowing tokens, because no function checks `_paused`.
3. A solver calls `fillOrder` on the same or a different order — succeeds; `_fillSameChain`/`_fillCrossChain` transfer escrowed tokens to the solver and beneficiary, because `_paused` is never read.
4. For cross-chain orders, the destination-side `onAccept` still calls `withdraw`, releasing escrow to the beneficiary, and `cancelOrder`'s three code paths still refund/settle escrow.
5. Result: the pause flag has zero effect on any fund-moving contract function, defeating its purpose entirely.

Note: I could not locate the setter function for `_paused` in the indexed portion of the codebase (only the declaration and the surrounding contract are visible), so I cannot confirm whether a setter is already deployed elsewhere or is planned for a future upgrade — this should be verified directly in a full checkout of `evm/src/apps/intentsv2/` and any admin/governance modules that reference `IntentsBase` storage.

    function fillOrder(Order calldata order, FillOptions calldata options) public payable nonReentrant {
        if (order.deadline < _blockNumber()) revert Expired();
        bytes32 commitment = keccak256(abi.encode(order));

        address hostAddr = host();
        bytes32 currentChain = keccak256(IDispatcher(hostAddr).host());
        bytes32 orderSource = keccak256(order.source);
        bytes32 orderDest = keccak256(order.destination);
        bool isSameChain = orderSource == orderDest;

        if (isSameChain && orderSource != currentChain) revert WrongChain();
        if (!isSameChain && orderDest != currentChain) revert WrongChain();

        if (_filled[commitment] != address(0)) revert Filled();

        if (_params.solverSelection) {
            bytes32 storedSelectionHash;
            assembly {
                storedSelectionHash := tload(commitment)
            }

            bytes32 expectedSelectionHash = keccak256(abi.encode(msg.sender, order.session));
            if (storedSelectionHash != expectedSelectionHash) revert Unauthorized();
        }

        uint256 outputsLen = order.output.assets.length;
        if (options.outputs.length != outputsLen) revert InvalidInput();
        if (order.inputs.length != outputsLen) revert InvalidInput();

        if (isSameChain) {
            _fillSameChain(order, options, commitment);
        } else {
            _fillCrossChain(order, options, commitment);
        }

        if (_params.priceOracle != address(0)) {
            IIntentPriceOracle(_params.priceOracle)
                .recordSpread(commitment, order.source, order.inputs, options.outputs);
        }
    }

    function _fillSameChain(Order calldata order, FillOptions calldata options, bytes32 commitment) internal {
        uint256 outputsLen = order.output.assets.length;

        _filled[commitment] = msg.sender;

        uint256 msgValue = msg.value;
        address beneficiary = address(uint160(uint256(order.output.beneficiary)));
        bool isFullyFilled = true;

        TokenInfo[] memory escrowedInputs = new TokenInfo[](outputsLen);
        TokenInfo[] memory outputFills = new TokenInfo[](outputsLen);

        for (uint256 i; i < outputsLen; i++) {
            bytes32 outputToken = order.output.assets[i].token;
            if (options.outputs[i].token != outputToken) revert InvalidInput();

            address token = address(uint160(uint256(outputToken)));
            uint256 totalRequired = order.output.assets[i].amount;
            uint256 solverAmount = options.outputs[i].amount;

            uint256 alreadyFilled = _partialFills[commitment][outputToken];
            uint256 remaining = totalRequired - alreadyFilled;
            if (remaining == 0 || solverAmount == 0) {
                if (solverAmount == 0 && remaining > 0) isFullyFilled = false;
                continue;
            }
            uint256 fillAmount;

            uint256 beneficiaryShare = 0;
            uint256 protocolShare = 0;
            if (alreadyFilled == 0 && solverAmount > totalRequired) {
                fillAmount = totalRequired;
                uint256 dust = solverAmount - totalRequired;
                if (order.output.call.length > 0) {
                    protocolShare = dust;
                } else {
                    protocolShare = (dust * _params.surplusShareBps) / 10_000;
                    beneficiaryShare = dust - protocolShare;
                }
            } else {
                fillAmount = solverAmount > remaining ? remaining : solverAmount;
            }

            uint256 amountFilled = alreadyFilled + fillAmount;
            _partialFills[commitment][outputToken] = amountFilled;
            uint256 beneficiaryTotal = fillAmount + beneficiaryShare;

            if (token == address(0)) {
                if (msgValue < beneficiaryTotal + protocolShare) revert InsufficientNativeToken();
                msgValue -= (beneficiaryTotal + protocolShare);
                (bool sent,) = beneficiary.call{value: beneficiaryTotal}("");
                if (!sent) revert InsufficientNativeToken();
            } else {
                IERC20(token).safeTransferFrom(msg.sender, beneficiary, beneficiaryTotal);
                if (protocolShare > 0) {
                    IERC20(token).safeTransferFrom(msg.sender, address(this), protocolShare);
                }
            }

            if (totalRequired > amountFilled) isFullyFilled = false;
            if (protocolShare > 0) emit DustCollected(token, protocolShare);

            uint256 escrowedAmount;
            if (amountFilled == totalRequired) {
                escrowedAmount = _orders[commitment][address(uint160(uint256(order.inputs[i].token)))];
            } else {
                escrowedAmount = (order.inputs[i].amount * fillAmount) / totalRequired;
            }
            escrowedInputs[i] = TokenInfo({token: order.inputs[i].token, amount: escrowedAmount});
            outputFills[i] = TokenInfo({token: outputToken, amount: fillAmount});
        }

        // Orders carrying output calldata must be filled completely in a single fill.
        // The attached call is only executed on a full fill, so a partial fill would
        // leave the intended side effect unexecuted while releasing proportional escrow.
        if (order.output.call.length > 0 && !isFullyFilled) revert PartialFillNotAllowed();

        WithdrawalRequest memory body = WithdrawalRequest({
            commitment: commitment, tokens: escrowedInputs, beneficiary: bytes32(uint256(uint160(msg.sender)))
        });
        _withdraw(body, false, isFullyFilled);

        if (isFullyFilled) {
            _execute(order, outputsLen);
            emit OrderFilled({commitment: commitment, filler: msg.sender, outputs: outputFills, inputs: escrowedInputs});
        } else {
            delete _filled[commitment];
            emit PartialFill({commitment: commitment, filler: msg.sender, outputs: outputFills, inputs: escrowedInputs});
        }

        // Refund any unspent native tokens to the solver.
        if (msgValue > 0) {
            (bool sent,) = msg.sender.call{value: msgValue}("");
            if (!sent) revert InsufficientNativeToken();
        }
    }
