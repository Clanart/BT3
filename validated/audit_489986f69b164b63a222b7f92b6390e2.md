### Title
Argument injection via unsanitized PR head ref name passed to `git branch` without `--` separator - (File: `app/src/lib/git/branch.ts`)

### Summary
`createBranch()` builds git CLI arguments from two values — a branch name and a start point — and passes them straight to the `git` executable without a `--` separator to terminate option parsing. In the pull-request checkout flow, the start point is derived from `pullRequest.head.ref`, a field taken verbatim from the GitHub API response for a PR. An attacker who opens a pull request from a fork controls this string. Unlike other call sites in the codebase (`clone.ts`, `repository-scaffolding.ts` test helpers) that explicitly insert `--` before user-controlled path/URL arguments to stop dashed values being parsed as git options, `createBranch()` has no equivalent guard, and no code path sanitizes or bounds-checks `headRefName` before it is concatenated into the git argument list.

### Finding Description
The flow is:
1. `Dispatcher.openPullRequestFromUrl()` calls `appStore._checkoutPullRequest()` with `pullRequest.head.ref` taken directly from the GitHub API `IAPIPullRequest` object. [1](#0-0) 

2. `_findPullRequestBranch()` builds `remoteRef = \`${remote.name}/${headRefName}\`` with no validation of `headRefName`'s content, then passes it as the `startPoint` argument to `_createBranch()`. [2](#0-1) 

3. `_createBranch()` → `gitStore.createBranch()` → `createBranch()` (git wrapper) builds:
```ts
const args = startPoint !== null ? ['branch', name, startPoint] : ['branch', name]
await git(args, repository.path, 'createBranch')
```
with no `--` separator before `startPoint`. [3](#0-2) 

Compare this to `clone()` in the same package, which explicitly defends against argument injection by inserting `--` before the attacker-controlled URL:
```ts
args.push('--', url, path)
``` [4](#0-3) 

The `sanitize-ref-name.ts` helper (`testForInvalidChars`/`sanitizedRefName`) exists elsewhere in the codebase and is used to validate `branch` values coming from `parseAppURL` deep links, but it is not applied to `headRefName` in the PR-checkout code path. [5](#0-4) [6](#0-5) 

This mirrors the report's underlying invariant: a value taken from an attacker-influenced external source (a "signature"/ref field) is used in a security-relevant operation without checking that it falls within an expected, safe value range/format before being consumed by a lower-level parser — here, git's own CLI argument parser instead of the `secp256k1` curve validator.

### Impact Explanation
If `git branch` (or the underlying `check_refname_format`) can be made to treat a leading-dash `startPoint` as an option rather than a ref (this is the exact class of bug historically fixed for git remote URLs in CVE-2017-1000117), a forked-repo PR author could smuggle git CLI options into the `branch` invocation run by Desktop's main process. Depending on which git options are reachable this way, outcomes range from unexpected local repository state corruption to more severe local file writes, since Desktop already treats similarly-shaped inputs (`clone` URL, worktree path) as untrusted enough to warrant an explicit `--` guard.

### Likelihood Explanation
Reaching this code path only requires a victim to click "Open in Desktop" / open a PR that was created from a fork the attacker controls (via `x-github-client://openrepo/...?pr=NNN` deep link or the in-app "View on GitHub"/checkout PR button), which is a normal, low-friction Desktop workflow — not something requiring local access, admin rights, or social engineering beyond "open this normal-looking PR link," which is explicitly in-scope per the task's valid-impact criteria (attacker controls a GitHub API object).

### Recommendation
Add a `--` separator before `startPoint` (and `name`) in `createBranch()` in `app/src/lib/git/branch.ts`, consistent with `clone.ts`:
```ts
const args = startPoint !== null
  ? ['branch', '--', name, startPoint]
  : ['branch', '--', name]
```
Additionally, validate/sanitize `headRefName` (e.g., with `testForInvalidChars`/`sanitizedRefName` from `sanitize-ref-name.ts`) before it is used to construct `remoteRef` in `_findPullRequestBranch()` in `app/src/lib/stores/app-store.ts`, rejecting or normalizing ref names that don't conform to a safe, expected git ref-name shape.

### Proof of Concept
1. Attacker forks a public repository and creates a branch whose ref name begins with a git-option-like prefix (e.g., a branch that git accepts locally but that Desktop will not further sanitize), then opens a pull request from that fork.
2. Attacker sends the victim a deep link such as `x-github-client://openrepo/https://github.com/<owner>/<repo>?pr=<num>`, or the victim clicks "Open in Desktop" on the PR page.
3. Desktop calls `dispatchURLAction` → `openRepositoryFromUrl` → `openPullRequestFromUrl` → `appStore._checkoutPullRequest(..., pullRequest.head.ref)`. [7](#0-6) 
4. `_findPullRequestBranch` builds `remoteRef` from the unsanitized `headRefName` and passes it into `_createBranch(repository, 'pr/${prNumber}', remoteRef, false)`. [8](#0-7) 
5. `createBranch()` executes `git branch pr/<num> <remoteRef>` with no `--` separator, so a `remoteRef` value shaped like a git option is parsed by git as a flag instead of a plain ref argument. [9](#0-8) 

Note: I was unable to fully verify, purely from the indexed source, whether the currently bundled git binary (`dugite`) rejects all dash-prefixed ref names at the `check_refname_format` layer before `git branch` processes them as options — that would need to be confirmed by actually invoking `git branch <name> -- <crafted-ref>` against the exact bundled git version to determine the concrete exploitable option surface. The structural gap (missing `--` guard, unlike sibling call sites) is confirmed directly from source.

export async function createBranch(
  repository: Repository,
  name: string,
  startPoint: string | null,
  noTrack?: boolean
): Promise<void> {
  const args =
    startPoint !== null ? ['branch', name, startPoint] : ['branch', name]

  // if we're branching directly from a remote branch, we don't want to track it
  // tracking it will make the rest of desktop think we want to push to that
  // remote branch's upstream (which would likely be the upstream of the fork)
  if (noTrack) {
    args.push('--no-track')
  }

  await git(args, repository.path, 'createBranch')
}

// See https://www.kernel.org/pub/software/scm/git/docs/git-check-ref-format.html
// ASCII Control chars and space, DEL, ~ ^ : ? * [ \
// | " < and > is technically a valid refname but not on Windows
// the magic sequence @{, consecutive dots, leading and trailing dot, ref ending in .lock
const invalidCharacterRegex =
  /[\x00-\x20\x7F~^:?*\[\\|""<>]+|@{|\.\.+|^\.|\.$|\.lock$|\/$/g

/** Sanitize a proposed reference name by replacing illegal characters. */
export function sanitizedRefName(name: string): string {
  return name.replace(invalidCharacterRegex, '-').replace(/^[-\+]*/g, '')
}

/** Validate that a reference does not contain any invalid characters */
export function testForInvalidChars(name: string): boolean {
  return invalidCharacterRegex.test(name)
}
