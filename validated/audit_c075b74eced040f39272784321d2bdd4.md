### Title
Unstaked peers can be evicted from the CRDS/peer table by cheap, self-signed fake `ContactInfo` flooding, bypassing the `keep`-list protection meant to preserve full-node reachability - ([File: gossip/src/crds.rs])

### Summary
The historical finding described unauthenticated peers being added to a node's peer list without limit or discrimination, letting an attacker flood the table with fake IPs and starve honest peers. Agave already caps the CRDS table size and trims by stake [1](#0-0) , but the trim's protected (`keep`) set only covers entrypoints, the local pubkey, and `known_validators` (staked epoch validators) — it does not protect ordinary unstaked full/RPC nodes, which are exactly what the original report asked to preserve.

### Finding Description
`generate_new_gossip_requests` calls `trim_crds_table(CRDS_UNIQUE_PUBKEY_CAPACITY, stakes)` on every gossip round [1](#0-0) . `trim_crds_table` builds its `keep` set from `entrypoints`, `self.id()`, and `known_validators` only: [2](#0-1) . Everything else — including legitimate but unstaked full nodes / RPC nodes — is eligible for eviction.

`Crds::drop` (called from `Crds::trim`) evicts the lowest-stake pubkeys not in `keep`; when stakes are unavailable it falls back to random eviction, and even when stakes are known, all zero-stake pubkeys (attacker-created throwaway keys and legitimate unstaked full nodes alike) sort identically at the bottom of the eviction order: [3](#0-2) .

Crucially, insertion into the CRDS table via push messages does not require any ping/pong liveness check on the declared IP. `CrdsGossipPush::process_push_message` inserts any `CrdsValue` that passes the wallclock window and the standard signature check, with no address-verification gate: [4](#0-3) . The `verify_gossip_addr`/`PingCache` mechanism only gates whether the value is subsequently *retained for forwarding* (`should_retain_crds_value` for `EgressPush`/`EgressPullResponse`), not whether it is accepted into the local table in the first place: [5](#0-4) [6](#0-5) .

Because a `ContactInfo` is self-signed by the sender's own keypair, an attacker can generate an unlimited number of fresh, validly-signed `CrdsValue::ContactInfo` entries with arbitrary declared gossip IPs at negligible cost (no stake, no valid peer relationship required) and push them into any node's gossip listener.

### Impact Explanation
Each such push forces a real Ed25519 signature verification and a CRDS insert/possible-trim cycle on the receiving node [7](#0-6) . Once the table exceeds `CRDS_UNIQUE_PUBKEY_CAPACITY` (`should_trim`, 10% overshoot margin) [8](#0-7) , `drop()` evicts lowest/zero-stake entries — a set that includes both the attacker's disposable fake entries and legitimate unstaked full/RPC nodes, since only `known_validators` (staked) and entrypoints are protected. This reproduces the exact failure mode the original report asked to fix ("keep validators and full nodes in the peer list ... so that network discovery can reasonably be expected to function"): sustained low-cost flooding degrades gossip-based discoverability of legitimate non-validator nodes network-wide as the churn propagates via push/pull, and continuously consumes CPU on signature verification and table churn on every gossip node receiving the flood — a remote, unauthenticated resource-exhaustion/degradation vector, not requiring any privileged or trusted role.

### Likelihood Explanation
High for the resource-consumption/churn effect: generating self-signed `ContactInfo` values is computationally trivial (one keypair + one signature per fake node) and the gossip protocol accepts any signed value from any UDP sender without prior authentication or stake. The overall table-size DoS is bounded by `CRDS_UNIQUE_PUBKEY_CAPACITY`, so this is a moderate-severity degradation/eviction issue rather than unbounded memory exhaustion — but it directly bypasses the specific mitigation ("hard limit on peer list size" + "keep validators and full nodes") that was supposed to fully close this class of issue.

### Recommendation
Extend the `keep` set used by `trim_crds_table`/`Crds::drop` beyond `known_validators` to also protect long-lived, previously-ping-verified full/RPC nodes (e.g., nodes with a confirmed `PingCache` pong, or a minimum observed uptime/age), and/or require a successful ping/pong round-trip before a `ContactInfo` is durably inserted into the CRDS table rather than only gating forwarding. Consider rate-limiting the number of *distinct new pubkeys* accepted from a single origin/IP within a time window to raise the cost of generating disposable identities.

### Proof of Concept
1. Attacker runs a minimal gossip client that repeatedly: generates a fresh `Keypair`, builds a `ContactInfo` with an arbitrary (even non-existent) gossip IP, wraps it in a self-signed `CrdsValue`, and sends it as a `Protocol::PushMessage` to a target node's gossip socket.
2. Target's `handle_batch_push_messages` → `Gossip::process_push_message` → `CrdsGossipPush::process_push_message` verifies the (self-consistent) signature and inserts the value [7](#0-6) ; no ping/pong of the declared IP is required.
3. Once `CRDS_UNIQUE_PUBKEY_CAPACITY` is exceeded, `trim_crds_table` runs `Crds::drop`, which evicts zero-stake entries without distinguishing attacker throwaway pubkeys from genuine unstaked full/RPC nodes not in `known_validators`/`entrypoints` [3](#0-2) .
4. Repeating this at a steady low rate keeps the CRDS table churning, continuously evicting legitimate unstaked nodes' `ContactInfo` and consuming victim CPU on signature verification, reproducing the discovery-degradation impact described in the original report.

// If the CRDS value is an unstaked contact-info, verifies if
// it has responded to ping on its gossip socket address.
// Returns false if the CRDS value should be discarded.
#[must_use]
fn verify_gossip_addr<R: Rng + CryptoRng>(
    rng: &mut R,
    keypair: &Keypair,
    value: &CrdsValue,
    socket_addr_space: &SocketAddrSpace,
    ping_cache: &Mutex<PingCache>,
    pings: &mut Vec<(SocketAddr, Ping)>,
) -> bool {
    let (pubkey, addr) = match value.data() {
        CrdsData::ContactInfo(node) => (node.pubkey(), node.gossip()),
        _ => return true, // If not a contact-info, nothing to verify.
    };
    // Invalid addresses are not verifiable.
    let Some(addr) = addr.filter(|addr| socket_addr_space.check(addr)) else {
        return false;
    };
    let (out, ping) = {
        let node = (*pubkey, addr);
        let mut ping_cache = ping_cache.lock().unwrap();
        ping_cache.check(rng, keypair, Instant::now(), node)
    };
    if let Some(ping) = ping {
        pings.push((addr, ping));
    }
    out
}

    fn drop(
        &mut self,
        size: usize,
        keep: &HashSet<Pubkey>,
        stakes: &HashMap<Pubkey, u64>,
        now: u64,
    ) -> usize {
        if stakes.values().all(|&stake| stake == 0) {
            // Stakes are unavailable, evict amount above cap
            return self.drop_random(size, keep, now);
        }
        let mut keys: Vec<_> = self
            .records
            .keys()
            .map(|k| (stakes.get(k).copied().unwrap_or_default(), *k))
            .collect();
        if size < keys.len() {
            keys.select_nth_unstable(size);
        }
        let keys: Vec<_> = keys
            .into_iter()
            .take(size)
            .map(|(_, k)| k)
            .filter(|k| !keep.contains(k))
            .flat_map(|k| &self.records[&k])
            .map(|k| self.table.get_index(*k).unwrap().0.clone())
            .collect();
        for key in &keys {
            self.remove(key, now);
        }
        keys.len()
    }

    pub(crate) fn process_push_message(
        &self,
        crds: &RwLock<Crds>,
        messages: Vec<(/*from:*/ Pubkey, Vec<CrdsValue>)>,
        now: u64,
    ) -> HashSet<Pubkey> {
        let mut received_cache = self.received_cache.lock().unwrap();
        let mut crds = crds.write().unwrap();
        let wallclock_window = self.wallclock_window(now);
        let mut origins = HashSet::new();
        for (from, values) in messages {
            self.num_total.fetch_add(values.len(), Ordering::Relaxed);
            for value in values {
                if !wallclock_window.contains(&value.wallclock()) {
                    continue;
                }
                let origin = value.pubkey();
                match crds.insert(value, now, GossipRoute::PushMessage(&from)) {
                    Ok(()) => {
                        received_cache.record(origin, from, /*num_dups:*/ 0);
                        origins.insert(origin);
                    }
                    Err(CrdsError::DuplicatePush(num_dups)) => {
                        received_cache.record(origin, from, usize::from(num_dups));
                        self.num_old.fetch_add(1, Ordering::Relaxed);
                    }
                    Err(CrdsError::InsertFailed) => {
                        received_cache.record(origin, from, /*num_dups:*/ usize::MAX);
                        self.num_old.fetch_add(1, Ordering::Relaxed);
                    }
                }
            }
        }
        origins
    }
