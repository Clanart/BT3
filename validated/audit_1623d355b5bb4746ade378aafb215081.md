### Title
Duplicate `ReceivedOutput` inputs can be double-counted and signed - ([File: networks/bitcoin/src/wallet/send.rs](networks/bitcoin/src/wallet/send.rs))

### Summary
`SignableTransaction::new` accepts duplicate `ReceivedOutput` values and counts each duplicate toward the available input value, while creating a separate Bitcoin input for every entry [1](#0-0) . Because `ReceivedOutput::read` performs no deduplication or uniqueness enforcement, untrusted serialized wallet data can supply the same outpoint repeatedly [2](#0-1) .

### Finding Description
The constructor sums every supplied `ReceivedOutput`, copies every supplied outpoint into `tx.input`, and stores every supplied `TxOut` as a prevout without checking whether two entries identify the same UTXO [1](#0-0) . The duplicate entries therefore inflate `input_sat`, allowing the payment and fee checks to succeed against a balance that exists only once on-chain [3](#0-2) . During multisig construction, each duplicated input is checked independently against its declared offset and script, so duplicates still pass and produce one signing machine per repeated outpoint [4](#0-3) . `TransactionSignMachine::sign` then signs a sighash for every duplicated input, producing signatures over a transaction Bitcoin consensus will reject for spending the same prevout more than once [5](#0-4) .

### Impact Explanation
An attacker able to provide serialized `ReceivedOutput` entries can cause a wallet flow to accept and threshold-sign an unintended invalid transaction whose declared input total exceeds the wallet's unique spendable UTXO set [1](#0-0) . This can bypass the constructor's `NotEnoughFunds` check and cause downstream callers to treat a payment as funded and signed even though Bitcoin will reject it [6](#0-5) .

### Likelihood Explanation
The precondition is limited to callers that accept attacker-controlled or otherwise duplicated `ReceivedOutput` encodings, but `ReceivedOutput::read` explicitly exposes deserialization and `SignableTransaction::new` exposes construction from a caller-provided vector [2](#0-1) . Exploitation requires no key compromise or malformed curve point; duplicating one valid serialized output is sufficient [7](#0-6) .

### Recommendation
Deduplicate inputs by `OutPoint` before summing funds or constructing `tx.input`, and reject duplicate outpoints rather than silently retaining both entries [1](#0-0) . The uniqueness check should also be enforced before the `input_sat` accounting so duplicated entries cannot influence `NotEnoughFunds`, fee, or change calculations [8](#0-7) .

  /// Create a multisig machine for this transaction.
  ///
  /// Returns None if the wrong keys are used.
  pub fn multisig(self, keys: &ThresholdKeys<Secp256k1>) -> Option<TransactionMachine> {
    let mut sigs = vec![];
    for i in 0 .. self.tx.input.len() {
      let offset = keys.clone().offset(self.offsets[i]);
      if p2tr_script_buf(offset.group_key())? != self.prevouts[i].script_pubkey {
        None?;
      }

      sigs.push(AlgorithmMachine::new(Schnorr::new(), keys.clone().offset(self.offsets[i])));
    }

    Some(TransactionMachine { tx: self, sigs })
  }

  pub fn read<R: Read>(r: &mut R) -> io::Result<ReceivedOutput> {
    let offset = Secp256k1::read_F(r)?;
    let output;
    let outpoint;
    {
      let mut buf_r = BufReader::with_capacity(0, r);
      output =
        TxOut::consensus_decode(&mut buf_r).map_err(|_| io::Error::other("invalid TxOut"))?;
      outpoint =
        OutPoint::consensus_decode(&mut buf_r).map_err(|_| io::Error::other("invalid OutPoint"))?;
    }
    Ok(ReceivedOutput { offset, output, outpoint })
  }
