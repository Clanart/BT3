## Title
Amending a commit silently trusts attacker-controlled `Co-Authored-By` trailers, letting a malicious commit spoof a co-author identity into the victim's future commits - (File: `app/src/lib/stores/git-store.ts`)

### Summary
The reported bug is a "beneficiary confusion" pattern: an attacker supplies a small amount of untrusted, attacker-controlled input (a payment) that is silently merged into a victim's pre-existing state (credit balance) and later used to produce an outcome the victim never consented to (a low-value NFT). The closest verifiable analog in this GitHub Desktop codebase is `GitStore.restoreCoAuthorsFromCommit()` / `loadCommitAndCoAuthors()`, which parses `Co-Authored-By` trailers straight out of an arbitrary commit's message (a commit that may originate from a cloned/fetched/cherry-picked repository controlled by an attacker) and, without any validation or user confirmation, folds the parsed name/email into the app's persistent co-author list used for the user's *next* commits.

### Finding Description
When a user chooses to amend a commit, `GitStore.prepareToAmendCommit()` calls `restoreCoAuthorsFromCommit()` [1](#0-0) , which in turn calls `loadCommitAndCoAuthors()`. That method takes the commit's summary/body, formats it, and runs `git interpret-trailers --parse` over it to extract `Co-Authored-By` trailers [2](#0-1) .

For each trailer found, the raw trailer value (an arbitrary attacker-controlled string coming from the commit object itself) is parsed with `GitAuthor.parse()`: [3](#0-2) 

This regex-based parse imposes no validation on the resulting `name`/`email` beyond splitting on `<...>` - any attacker-chosen string is accepted verbatim. The resulting `{name, email}` pair is then pushed into `newAuthors`/co-authors state with `kind: 'known'` and no verification against the current signed-in account or the repository's contributor list: [4](#0-3) 

Once added to `this.coAuthors`, this author list is silently reused as trailers on the *victim's own subsequent commits* via `formatCommitMessage` → `mergeTrailers` [5](#0-4) [6](#0-5) .

The broken invariant: a `Co-Authored-By` trailer is treated as trusted, user-approved metadata (like the victim's credit balance in the report), but it is actually attacker-controlled data embedded in any commit the user interacts with - including a commit fetched from a remote, cherry-picked from a PR branch, or applied via patch. There is no step in `restoreCoAuthorsFromCommit`/`loadCommitAndCoAuthors` that confirms the extracted co-author corresponds to someone the user actually intended to credit; it's applied automatically as soon as the user amends any such commit, exactly as the credit-balance in the Juicebox report was silently applied to mint an NFT the beneficiary never explicitly authorized.

### Impact Explanation
An attacker who controls a commit that the victim later amends (e.g., a PR branch commit cherry-picked into the victim's branch, or a commit merged from a compromised/malicious remote) can inject a crafted `Co-Authored-By: <arbitrary name> <arbitrary email>` trailer. When the victim amends that commit in Desktop, the attacker's chosen identity becomes part of the victim's persisted co-author list and is silently stamped onto the victim's *own, unrelated* future commits pushed upstream - without any prompt, diff review, or confirmation dialog surfacing that this identity was pulled from someone else's commit. This is a silent corruption of what the user commits and pushes: it can be used to falsely attribute authorship/credit to an unrelated third party (reputation/spoofing), or to smuggle an attacker-chosen email address into the victim's public commit history under their name.

### Likelihood Explanation
Amending commits from a shared/fetched history (cherry-picks, PR branches, rebasing onto commits from collaborators) is a normal, everyday GitHub Desktop workflow, so the trigger condition (amend a commit containing an attacker-crafted trailer) is easily reachable without unusual user steps. The code path is unconditional - as long as `repository.gitHubRepository` is set, `loadCommitAndCoAuthors` runs and blindly trusts whatever trailer text is present.

### Recommendation
- Only restore co-authors from a commit if the commit was authored/committed by the current user (or otherwise already exists in local unpushed history under the user's control) - not from arbitrary fetched/cherry-picked commits.
- Validate `GitAuthor.parse()` output against a stricter format and consider surfacing the extracted co-author for explicit user confirmation instead of silently re-adding it to the persistent co-author list.
- Add a confirmation UI step in `restoreCoAuthorsFromCommit`/`loadCommitAndCoAuthors` that shows exactly which name/email is being restored so a user can catch a spoofed identity before it propagates into their own future commits.

### Proof of Concept
1. Attacker crafts a commit (e.g., on a branch of a repository the victim will fetch/clone, or in a PR the victim cherry-picks) whose message includes `Co-Authored-By: Trusted Maintainer <spoof@attacker.example>`.
2. Victim cherry-picks or otherwise brings this commit into their local branch, then opens Desktop and chooses "Amend commit" on it.
3. `GitStore.prepareToAmendCommit()` → `restoreCoAuthorsFromCommit()` → `loadCommitAndCoAuthors()` runs, extracting the trailer via `GitAuthor.parse()` [7](#0-6)  and adding `{ name: 'Trusted Maintainer', email: 'spoof@attacker.example' }` to `this.coAuthors` with no validation [4](#0-3) .
4. Victim later makes an unrelated commit; Desktop's `formatCommitMessage`/`mergeTrailers` silently appends the spoofed `Co-Authored-By` trailer to that new, unrelated commit before it is pushed, corrupting the victim's public commit metadata.

Note: I was unable to fully trace every UI entry point that calls `prepareToAmendCommit` (e.g., whether "Undo commit" also triggers it) within the available iterations, so the exact set of user-facing flows that can trigger this beyond "Amend commit" is not fully confirmed from local code alone.

  private async loadCommitAndCoAuthors(commit: Commit) {
    const repository = this.repository

    // git-interpret-trailers is really only made for working
    // with full commit messages so let's start with that
    const message = await formatCommitMessage(repository, {
      summary: commit.summary,
      description: commit.body,
    })

    // Next we extract any co-authored-by trailers we
    // can find. We use interpret-trailers for this
    const foundTrailers = await parseTrailers(repository, message)
    const coAuthorTrailers = foundTrailers.filter(isCoAuthoredByTrailer)

    // This is the happy path, nothing more for us to do
    if (coAuthorTrailers.length === 0) {
      this._commitMessage = {
        summary: commit.summary,
        description: commit.body,
        timestamp: Date.now(),
      }

      return
    }

export class GitAuthor {
  public static parse(nameAddr: string): GitAuthor | null {
    const m = nameAddr.match(/^(.*?)\s+<(.*?)>/)
    return m === null ? null : new GitAuthor(m[1], m[2])
  }

export async function formatCommitMessage(
  repository: Repository,
  context: ICommitContext
) {
  const { summary, description, trailers } = context

  // Git always trim whitespace at the end of commit messages
  // so we concatenate the summary with the description, ensuring
  // that they're separated by two newlines. If we don't have a
  // description or if it consists solely of whitespace that'll
  // all get trimmed away and replaced with a single newline (since
  // all commit messages needs to end with a newline for git
  // interpret-trailers to work)
  const message = `${summary}\n\n${description || ''}\n`.replace(/\s+$/, '\n')

  return trailers !== undefined && trailers.length > 0
    ? mergeTrailers(repository, message, trailers)
    : message
}

export async function mergeTrailers(
  repository: Repository,
  commitMessage: string,
  trailers: ReadonlyArray<ITrailer>,
  unfold: boolean = false
) {
  const args = ['interpret-trailers']

  // See https://github.com/git/git/blob/ebf3c04b262aa/Documentation/git-interpret-trailers.txt#L129-L132
  args.push('--no-divider')

  if (unfold) {
    args.push('--unfold')
  }

  for (const trailer of trailers) {
    args.push('--trailer', `${trailer.token}=${trailer.value}`)
  }

  const result = await git(args, repository.path, 'mergeTrailers', {
    stdin: commitMessage,
  })

  return result.stdout
}
