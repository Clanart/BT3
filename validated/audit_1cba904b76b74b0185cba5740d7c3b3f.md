### Title
`SimplexPaymaster` prices ERC-20 gas payments off a stale-tolerant Chainlink oracle with no deviation check, letting any user extract value from the paymaster treasury - ([File: evm/src/utils/SimplexPaymaster.sol])

### Summary
`SimplexPaymaster` is a "fully onchain, permissionless" ERC-4337 paymaster that lets any user pay gas in a registered ERC-20 (e.g. USDC/USDT) using a Chainlink `token/USD` and `native/USD` price pair [1](#0-0) . The conversion rate `_tokenPrice()` is computed purely from `_getOraclePrice()`, which only rejects a non-positive answer or an answer older than `maxOracleAge` — it performs no deviation/sanity check against the true market price [2](#0-1) . This is exactly the class of bug in the referenced report: relying on an oracle whose staleness/deviation tolerance can diverge materially from the true asset price causes an unfair, one-sided fund transfer at settlement time.

### Finding Description
`_tokenPrice()` is used in `_fetchDetails()` on every UserOp validation to set `tokenPrice`, which `PaymasterERC20` then uses to compute `erc20Cost = weiCost * tokenPrice / 1e18` and pull from the sender [3](#0-2) . The oracle staleness bound `maxOracleAge` is governance-configurable up to a hard cap of `MAX_ORACLE_AGE = 7 days`, and the contract's own comments acknowledge stablecoin heartbeats of up to 24h on Base/Ethereum [4](#0-3) [5](#0-4) . Chainlink feeds only push a new round when either the heartbeat elapses or price moves past the deviation threshold (e.g. 0.5–2% for major pairs), so between updates the onchain `nativeUsd`/`tokenUsd` values used by `_tokenPrice()` can lag the true market price by that full deviation band without tripping `StaleOraclePrice`.

Because the paymaster is explicitly permissionless (no allowlist, no relayer/governance gate on submitting a UserOp), any ordinary user can:
1. Watch the native asset (e.g. ETH/BNB) price move up materially in the open market while the onchain oracle round has not yet updated (still within heartbeat and under the deviation threshold).
2. Submit a UserOp with `paymasterData` referencing a registered stablecoin, paying `erc20Cost` computed from the stale, lower `nativeUsd` value.
3. Consume real, currently-priced native gas from the paymaster's EntryPoint deposit while only reimbursing the contract in stablecoin at the outdated (cheaper) exchange rate.

This directly drains value from the paymaster/treasury on every such trade — the same "user unfairly gains/loses funds due to oracle staleness/deviation" root cause as the referenced stETH/ETH report, just inverted (the protocol, not the user, is the one exposed). No malicious relayer, governance actor, or leaked key is required — only a normal unprivileged UserOp submitter reacting to public price data. The `swapAndDeposit()` function has the same weakness (oracle price plus a slippage-bps cushion), but that path is treasury-gated, so it is not itself independently attacker-reachable.

### Impact Explanation
Every stale-oracle window is a window in which unprivileged users can extract free/discounted gas from the paymaster's EntryPoint deposit, funded by governance/treasury deposits. Repeated exploitation during volatile markets constitutes a direct, ongoing loss of funds for the protocol without requiring any privileged actor, matching the "loss of funds" and "logic attack" categories in scope.

### Likelihood Explanation
The oracle staleness window is a normal, expected operating condition (not a compromise) — Chainlink feeds routinely sit for up to their heartbeat/deviation window between updates, and `maxOracleAge` is explicitly allowed up to 7 days by the contract's own bound. Any user with a public price feed (e.g. a CEX price) can detect the divergence and time a UserOp submission; this needs no special access, node compromise, or governance action, making exploitation realistically low-effort during normal price volatility.

### Recommendation
- Add an explicit price-deviation guard in `_getOraclePrice()`/`_tokenPrice()` (e.g., compare against a secondary reference or bound the max allowed price move since a recorded reference), not just a staleness check.
- Tighten the effective `maxOracleAge` default/cap far below `MAX_ORACLE_AGE = 7 days`, and consider using more responsive USD-denominated feeds (as the original report recommends) rather than pairs with wide deviation thresholds.
- Consider charging with a conservative markup that also absorbs oracle staleness risk, or use a TWAP/median-of-multiple-sources approach for the gas-cost conversion rather than a single spot Chainlink round.

### Proof of Concept
1. Governance configures `maxOracleAge = 86400` (24h, within the allowed `MAX_ORACLE_AGE`), matching realistic Base/Ethereum stablecoin heartbeats as called out in the contract comments [4](#0-3) .
2. Native asset price rises 5% on the open market shortly after the last Chainlink round, but the oracle round hasn't refreshed yet (still under both its heartbeat and deviation threshold, and well under `maxOracleAge`).
3. An unprivileged user constructs and submits a UserOp with `paymasterData` mode `0x01` referencing a registered stablecoin; `_fetchDetails()`/`_tokenPrice()` compute `tokenPrice` from the stale, lower `nativeUsd` [6](#0-5) .
4. `PaymasterERC20` charges the sender in stablecoin using this stale rate while the EntryPoint pays out real, current-priced native gas from the paymaster's deposit — a ~5% value transfer from the paymaster treasury to the user, repeatable every time a similar stale window occurs, with no code path currently rejecting it (`_getOraclePrice` only checks `answer <= 0` and elapsed time) [7](#0-6) .

    /// @dev Returns the token to charge and its price relative to native gas.
    ///
    ///      PaymasterERC20 computes `erc20Cost = weiCost * tokenPrice / 1e18`,
    ///      so tokenPrice must be token base units per wei, scaled by 1e18:
    ///        tokenPrice = (nativeUsd * 10^tokenDecimals) / tokenUsd
    ///      e.g. BNB at $600, USDC at $1 with 6 decimals: 0.001 BNB (1e15 wei)
    ///      should cost 0.60 USDC (600000 units), giving tokenPrice = 6e8, which
    ///      is exactly (600e8 * 1e6) / 1e8. Markup is applied on top.
    function _fetchDetails(
        PackedUserOperation calldata userOp,
        bytes32 /* userOpHash */
    ) internal view override returns (uint256 validationData, IERC20 token, uint256 tokenPrice) {
        bytes calldata data = userOp.paymasterData();
        if (data.length < 21) revert InvalidPaymasterData(data.length);

        uint8 mode = uint8(data[0]);
        if (mode > 0x01) revert InvalidMode(mode);

        address tokenAddr = address(bytes20(data[1:21]));

        TokenConfig memory cfg = tokenConfigs[tokenAddr];
        if (address(cfg.tokenOracle) == address(0)) revert TokenNotRegistered(tokenAddr);
        if (!cfg.active) revert TokenNotActive(tokenAddr);

        tokenPrice = _tokenPrice(cfg);
        token = IERC20(tokenAddr);
        validationData = 0; // no time-range restriction
    }

    function _tokenPrice(TokenConfig memory cfg) internal view returns (uint256) {
        uint256 nativeUsd = _getOraclePrice(nativeOracle, nativeOracleDecimals);
        uint256 tokenUsd = _getOraclePrice(cfg.tokenOracle, cfg.tokenOracleDecimals);

        return (nativeUsd * (10 ** cfg.tokenDecimals) * (10_000 + markupBps)) / (tokenUsd * 10_000);
    }

    /// @dev Fetch a Chainlink price normalized to 8 decimals.
    ///      Reverts on stale or non-positive answers.
    function _getOraclePrice(AggregatorV3Interface oracle, uint8 oracleDecimals) internal view returns (uint256) {
        (, int256 answer, , uint256 updatedAt, ) = oracle.latestRoundData();

        if (answer <= 0) revert InvalidOraclePrice(address(oracle), answer);
        if (block.timestamp - updatedAt > maxOracleAge) {
            revert StaleOraclePrice(address(oracle), updatedAt);
        }

        if (oracleDecimals < 8) {
            return uint256(answer) * (10 ** (8 - oracleDecimals));
        } else if (oracleDecimals > 8) {
            return uint256(answer) / (10 ** (oracleDecimals - 8));
        }
        return uint256(answer);
    }
