### Title
Unauthenticated DKG ciphertexts are decrypted before PoP verification, exposing an ECDH oracle - (File: crypto/dkg/pedpop/src/encryption.rs)

### Summary
`Encryption::decrypt` computes the ECDH shared key, decrypts the attacker-controlled `EncryptedMessage`, and returns both plaintext and an `EncryptionKeyProof` before the per-message proof-of-possession is verified. `KeyMachine::calculate_share` then parses the decrypted share before running the deferred batch verification, so a malformed unauthenticated ciphertext can return early with a serialized ECDH proof. This maps the reported oracle/output-buffer class onto Serai’s PedPoP decryption path.

### Finding Description
`Encryption::decrypt` queues `msg.pop` for batch verification, but immediately computes `key = ecdh(self.enc_key, msg.key)` and applies the ChaCha20 keystream to the supplied message bytes before constructing and returning `EncryptionKeyProof { key, dleq }` [1](#0-0) . The caller then attempts `C::F::from_repr` on that decrypted output before `batch.verify_with_vartime_blame()` has authenticated the PoP [2](#0-1) . If the decrypted bytes are non-canonical, `calculate_share` returns `PedPoPError::InvalidShare` containing `Some(blame)` even though the PoP may be invalid [3](#0-2) . The processor serializes that blame into `ProcessorMessage::InvalidShare`, making the derived ECDH point available as protocol output [4](#0-3) .

The PoP exists specifically to prevent an attacker from reusing another message’s ephemeral encryption key and thereby causing a blame proof to reveal that message’s ECDH output [5](#0-4) . However, because scalar decoding occurs before the queued PoP verification, the early-error path bypasses that protection [6](#0-5) .

### Impact Explanation
An attacker can submit an `EncryptedMessage` whose `key` field is copied from another ciphertext but whose encrypted share bytes are chosen independently. Without knowing the ephemeral scalar, the attacker cannot create a valid PoP, yet the victim still computes `victim_enc_key * copied_key`, decrypts the supplied bytes, and produces a DLEQ proof for that ECDH result [7](#0-6) . When the result decodes to a non-canonical scalar, the early error exposes the proof before the invalid PoP is evaluated [3](#0-2) .

The disclosed `EncryptionKeyProof.key` is the exact ECDH point used by `cipher` to derive the ChaCha20 key [8](#0-7) . Possession of that point lets the attacker decrypt any ciphertext that uses the copied ephemeral key and the victim’s registered encryption key, including an observed honest DKG secret-share ciphertext. This can recover a secret share and undermine the confidentiality boundary that per-message keys are intended to preserve.

### Likelihood Explanation
The attack requires the attacker to feed a syntactically valid but unauthenticated `EncryptedMessage` to `calculate_share` and obtain the resulting invalid-share/blame output. No discrete logarithm or valid PoP is required for the copied key because the ECDH and ciphertext decryption happen before authentication. A uniformly chosen 32-byte payload has a substantial probability of decoding to a non-canonical scalar for common fields such as Ristretto/ed25519, so the early return can be reached without a negligible-probability event. Once the ECDH point is revealed, decryption of ciphertexts protected by that same key is deterministic and offline.

### Recommendation
Verify `msg.pop` synchronously before computing ECDH, mutating the ciphertext buffer, or constructing `EncryptionKeyProof`. Do not rely on the outer batch verifier for authorization of this decryption oracle. If batching is retained for the normal path, the scalar-decode branch must not return blame until batch verification has completed and confirmed the PoP; currently blame must be withheld when `BatchId::Decryption` fails. As defense in depth, derive or return the blame proof only after all authentication checks have succeeded.

### Proof of Concept
Let the victim’s registered encryption key be \(B=bG\), and let an observed honest ciphertext use ephemeral key \(X=xG\), so its shared ECDH point is \(bX\). The attacker constructs:

```text
EncryptedMessage {
  key = X,                         // copied from the target ciphertext
  pop = arbitrary encoding,        // invalid; x is unknown
  msg = attacker-chosen bytes C',  // expected to decrypt to a non-canonical scalar
}
```

`EncryptedMessage::read` accepts the attacker-controlled key, signature, and message fields [9](#0-8) . During `calculate_share`, `Encryption::decrypt` computes:

```text
K = bX
plaintext = C' XOR ChaCha20(H(context, K))
proof   = (K, DLEq(G, X, B, K))
```

before the invalid `pop` is verified [1](#0-0) . If `plaintext` is non-canonical, `calculate_share` returns `InvalidShare { blame: Some(proof) }` before the batch verifier reports the PoP failure [3](#0-2) . The processor serializes that proof into the externally propagated `InvalidShare` message [10](#0-9) . The attacker extracts `K = bX` from the proof and decrypts the original ciphertext carrying `key = X`, recovering the honest secret-share plaintext protected by that ECDH key.

fn cipher<C: Ciphersuite>(context: [u8; 32], ecdh: &Zeroizing<C::G>) -> ChaCha20 {
  // Ideally, we'd box this transcript with ZAlloc, yet that's only possible on nightly
  // TODO: https://github.com/serai-dex/serai/issues/151
  let mut transcript = RecommendedTranscript::new(b"DKG Encryption v0.2");
  transcript.append_message(b"context", context);

  transcript.domain_separate(b"encryption_key");

  let mut ecdh = ecdh.to_bytes();
  transcript.append_message(b"shared_key", ecdh.as_ref());
  ecdh.as_mut().zeroize();

  let zeroize = |buf: &mut [u8]| buf.zeroize();

  let mut key = Cc20Key::default();
  let mut challenge = transcript.challenge(b"key");
  key.copy_from_slice(&challenge[.. 32]);
  zeroize(challenge.as_mut());

  // Since the key is single-use, it doesn't matter what we use for the IV
  // The issue is key + IV reuse. If we never reuse the key, we can't have the opportunity to
  // reuse a nonce
  // Use a static IV in acknowledgement of this
  let mut iv = Cc20Iv::default();
  // The \0 is to satisfy the length requirement (12), not to be null terminated
  iv.copy_from_slice(b"DKG IV v0.2\0");

  // ChaCha20 has the same commentary as the transcript regarding ZAlloc
  // TODO: https://github.com/serai-dex/serai/issues/151
  let res = ChaCha20::new(&key, &iv);
  zeroize(key.as_mut());
  res
