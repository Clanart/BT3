### Title
Payout attribution is derived solely from an unauthenticated OP_RETURN on whichever tx spends the withdrawal UTXO, letting anyone front a withdrawal and frame an arbitrary operator for reimbursement - ([File: core/src/verifier.rs])

### Summary
`update_finalized_payouts` attributes a withdrawal's `payout_payer_operator_xonly_pk` purely by parsing the OP_RETURN of whatever transaction happens to spend the `withdrawal_utxo` outpoint on-chain, with no check that the named operator actually authored, signed, or funded that transaction. Because the withdrawal input is signed with `SIGHASH_SINGLE | SIGHASH_ANYONECANPAY`, any third party who observes the (publicly committed on Citrea) `input_signature`/`input_outpoint`/`output_script_pubkey`/`output_amount` can construct their own transaction that reuses that signature, funds output 0 themselves, and appends an arbitrary OP_RETURN naming any registered operator as the "fronting" operator.

### Finding Description
The broken binding is: `withdrawals.payout_payer_operator_xonly_pk == operator that actually fronted output_amount for withdrawal idx`.

`create_payout_txhandler` signs the withdrawal input with `KeySpend`/`SinglePlusAnyoneCanPay` and only commits to input 0 and output 0 [1](#0-0) . `Operator::withdraw` funds the real payout amount by adding its own inputs via `fund_raw_transaction(..., add_inputs: Some(true), ...)`, confirming that the design intentionally allows extra inputs/outputs beyond index 0/0 to be appended after the withdrawal owner signs [2](#0-1) . The withdrawal signature therefore does not bind the OP_RETURN operator pubkey, the fee, or any other output — those are entirely at the mercy of whoever assembles the final broadcast transaction.

`Verifier::update_finalized_payouts` looks up "the" payout transaction for a withdrawal index purely via `get_payout_txs_for_withdrawal_utxos`, which joins on `withdrawal_utxo_txid`/`vout` regardless of which party built or signed the spending transaction [3](#0-2) . It then parses the first OP_RETURN it finds in that transaction and stores it as `operator_xonly_pk` with no further validation [4](#0-3) .

Downstream, `PayoutCheckerTask::run_once` blindly trusts this DB attribution: it queries `get_first_unhandled_payout_by_operator_xonly_pk` for the operator's own key and, if it finds an entry, automatically drives `handle_finalized_payout` to send a kickoff and begin the reimbursement process [5](#0-4) . `validate_payer_is_operator` only checks that the stored `payer_xonly_pk` equals the operator's own key, never that the operator itself broadcast or funded the transaction [6](#0-5) .

Exploit flow: an unprivileged attacker reads the public Citrea withdrawal request (which contains `input_signature`, `input_outpoint`, `output_script_pubkey`, `output_amount`) for withdrawal i, before any operator or the aggregator's optimistic-payout flow broadcasts a spending transaction. The attacker builds a transaction: input 0 = the same signed dust withdrawal UTXO, plus their own funding input(s) to cover `output_amount`, output 0 = the same fixed payout (correctly paying the real withdrawer), and an appended OP_RETURN naming an arbitrary real operator X's xonly pubkey. The attacker broadcasts and gets this mined before the legitimate operator's `create_payout_txhandler` tx or the aggregator's `create_optimistic_payout_txhandler` tx (which also spends this same input 0, per `core/src/rpc/aggregator.rs:1112-1118`). Once confirmed, `update_finalized_payouts` records operator X as the payer, and operator X's own `PayoutCheckerTask` will autonomously kick off the reimbursement flow for a payout it never made.

Existing guards fail because: `SECP.verify_schnorr` at the aggregator/operator only validates that input 0 + output 0 were signed by the withdrawal owner, not that the whole broadcast transaction (its remaining outputs, including OP_RETURN) was authored by any specific operator; `is_utxo_spent` checks only stop the legitimate flow from proceeding once raced out, they don't prevent the race; and no code path ties `payout_payer_operator_xonly_pk` back to a signature or action performed by that operator.

### Impact Explanation
An operator that never fronted a withdrawal can be credited as the payer and will autonomously drive its own kickoff/reimburse process, receiving real BTC from round/reimbursement collateral for a payout it never made — matching "an operator reimbursed for a payout it never funded" (Critical). Simultaneously, the legitimate operator-payout (`create_payout_txhandler`) or verifier-signed optimistic-payout (`create_optimistic_payout_txhandler`) paths become permanently unconfirmable for that withdrawal because the shared withdrawal UTXO input is already spent, which can leave the corresponding deposit's move-to-vault funds unreachable through the intended paths going forward. This is repeatable per withdrawal, and the attacker only needs to front the withdrawal's face value (which the real withdrawer still receives correctly) to frame any real, currently-active operator.

### Likelihood Explanation
The attacker needs no privileged role: withdrawal parameters are public via Citrea, `SIGHASH_SINGLE|ANYONECANPAY` is the documented, intentional signing scheme (to let a funder add inputs), and winning the race only requires normal fee-bumping/mempool competition against the legitimate operator or the aggregator's multi-round-trip optimistic-payout signing ceremony (which requires collecting nonces/partial sigs from all participating verifiers and is inherently slower). Attacker cost is roughly the withdrawal's face value in BTC (recovered indirectly since the payout still correctly reaches the intended withdrawer) plus fees to win the race — the attack is repeatable across withdrawals and operators, with no cost blocking factor besides needing to fund `output_amount`.

### Recommendation
Do not derive `payout_payer_operator_xonly_pk` solely from an OP_RETURN scraped out of whichever transaction happens to spend the withdrawal UTXO. Require the reimbursement flow to bind the payout transaction to a specific operator via a signature/commitment that operator itself produces (e.g., have `Operator::withdraw` register the exact txid it intends to broadcast with the verifiers/aggregator beforehand, and have `update_finalized_payouts`/`PayoutCheckerTask` only accept attribution if it matches a pre-registered, operator-signed commitment) rather than trusting an unauthenticated OP_RETURN discovered post-hoc on chain.

### Proof of Concept
In a `cargo test` mirroring `deposit_and_withdraw_e2e.rs`'s withdrawal setup:
1. Run a deposit and register a withdrawal (`get_new_withdrawal_utxo_and_register_to_citrea`), obtaining `withdrawal_utxo`, `payout_txout`, `sig` (`SinglePlusAnyoneCanPay`).
2. Do NOT call the honest operator's `withdraw` or the aggregator's `optimistic_payout` yet.
3. As the "attacker," construct a transaction spending `withdrawal_utxo` (input 0, reusing `sig`) plus an attacker-funded extra input covering `payout_txout.value`, output 0 = `payout_txout` unchanged, and an appended OP_RETURN containing an arbitrary registered operator X's xonly pubkey (not the honest operator's). Broadcast and mine it.
4. Assert the honest operator's subsequent `withdraw` call, and the aggregator's `optimistic_payout` call, both fail because `is_utxo_spent(withdrawal_utxo)` is now true.
5. Mine enough blocks for finality and drive `handle_finalized_block`/`update_finalized_payouts`; assert via `db.get_payout_info_from_move_txid` that `payout_payer_operator_xonly_pk == operator X` even though operator X never broadcast or signed anything.
6. Assert that operator X's `PayoutCheckerTask::run_once` (or equivalent) subsequently finds this as an unhandled payout via `get_first_unhandled_payout_by_operator_xonly_pk` and proceeds to `handle_finalized_payout`, demonstrating it will attempt reimbursement for a payout it never funded.

pub fn create_payout_txhandler(
    input_utxo: UTXO,
    output_txout: TxOut,
    operator_xonly_pk: XOnlyPublicKey,
    user_sig: taproot::Signature,
    _network: bitcoin::Network,
) -> Result<TxHandler<Signed>, BridgeError> {
    let txin = SpendableTxIn::new_partial(input_utxo.outpoint, input_utxo.txout);

    let output_txout = UnspentTxOut::from_partial(output_txout.clone());

    let op_return_txout = op_return_txout(PushBytesBuf::from(operator_xonly_pk.serialize()));

    let mut txhandler = TxHandlerBuilder::new(TransactionType::Payout)
        .with_version(NON_STANDARD_V3)
        .add_input(
            NormalSignatureKind::NotStored,
            txin,
            SpendPath::KeySpend,
            DEFAULT_SEQUENCE,
        )
        .add_output(output_txout)
        .add_output(UnspentTxOut::from_partial(anchor_output(
            NON_EPHEMERAL_ANCHOR_AMOUNT,
        )))
        .add_output(UnspentTxOut::from_partial(op_return_txout))
        .finalize();
    txhandler.set_p2tr_key_spend_witness(&user_sig, 0)?;
    txhandler.promote()
}

    async fn validate_payer_is_operator(
        &self,
        dbtx: Option<DatabaseTransaction<'_>>,
        deposit_id: u32,
    ) -> Result<(BlockHash, Txid), BridgeError> {
        let (payer_xonly_pk, payout_blockhash, kickoff_txid) = self
            .db
            .get_payer_xonly_pk_blockhash_and_kickoff_txid_from_deposit_id(dbtx, deposit_id)
            .await?;

        tracing::info!(
            "Payer xonly pk and kickoff txid found for the requested deposit, payer xonly pk: {:?}, kickoff txid: {:?}",
            payer_xonly_pk,
            kickoff_txid
        );

        // first check if the payer is the operator, and the kickoff is handled
        // by the PayoutCheckerTask, meaning kickoff_txid is set
        let (payout_blockhash, kickoff_txid) = match (
            payer_xonly_pk,
            payout_blockhash,
            kickoff_txid,
        ) {
            (Some(payer_xonly_pk), Some(payout_blockhash), Some(kickoff_txid)) => {
                if payer_xonly_pk != self.signer.xonly_public_key {
                    return Err(eyre::eyre!(
                        "Payer is not own operator for deposit, payer xonly pk: {:?}, operator xonly pk: {:?}",
                        payer_xonly_pk,
                        self.signer.xonly_public_key
                    )
                    .into());
                }
                (payout_blockhash, kickoff_txid)
            }
            _ => {
                return Err(eyre::eyre!(
                    "Payer info not found for deposit, payout blockhash: {:?}, kickoff txid: {:?}",
                    payout_blockhash,
                    kickoff_txid
                )
                .into());
            }
        };

    /// Returns the withdrawal indexes and their spending txid for the given
    /// block id.
    pub async fn get_payout_txs_for_withdrawal_utxos(
        &self,
        tx: Option<DatabaseTransaction<'_>>,
        block_id: u32,
    ) -> Result<Vec<(u32, Txid)>, BridgeError> {
        let query = sqlx::query_as::<_, (i32, TxidDB)>(
            "SELECT w.idx, bsu.spending_txid
             FROM withdrawals w
             JOIN bitcoin_syncer_spent_utxos bsu
                ON bsu.txid = w.withdrawal_utxo_txid
                AND bsu.vout = w.withdrawal_utxo_vout
             WHERE bsu.block_id = $1",
        )
        .bind(i32::try_from(block_id).wrap_err("Failed to convert block id to i32")?);

        let results = execute_query_with_tx!(self.connection, tx, query, fetch_all)?;

        results
            .into_iter()
            .map(|(idx, txid)| {
                Ok((
                    u32::try_from(idx).wrap_err("Failed to convert withdrawal index to u32")?,
                    txid.0,
                ))
            })
            .collect()
    }
