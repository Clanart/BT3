## Title
`updateRemoteUrl` silently rewrites a repository's `origin` remote from an unauthenticated GitHub API field, redirecting future fetch/push to an attacker-controlled host - (File: `app/src/lib/stores/updates/update-remote-url.ts`)

### Summary
The C4 report's broken invariant is: a permissioned, externally-fed value (`TwapOracle`'s price) is trusted and silently applied to a critical downstream computation with no validation that the update reflects reality. The Desktop analog is `updateRemoteUrl`, which trusts the `clone_url` field of a `GitHub API` repository object and silently rewrites the local `git remote` origin URL for a tracked repository whenever the app refreshes GitHub repository metadata, with only a superficial "protocol matches" check and no verification that the new URL still points at the expected GitHub/GHES host.

### Finding Description
`updateRemoteUrl` is invoked from `repositoryWithRefreshedGitHubRepository`, which is called on every `_fetch`/`_fetchRemote` and on the push flow via `withRefreshedGitHubRepository`: [1](#0-0) [2](#0-1) 

The refresh calls `api.fetchRepository(owner, name)` against the account's endpoint (which can be `GitHub.com` or an arbitrary configured GitHub Enterprise Server) and feeds the returned object straight into `updateRemoteUrl`: [3](#0-2) 

The only guard is:
- `protocolsMatch` — compares `URL.parse(...).protocol` (e.g. `https:` vs `https:`), which is satisfied by *any* HTTPS host, not just the original GitHub host.
- `remoteUrlUnchanged` — true whenever the user hasn't manually edited the remote (the common case).
- `!urlsMatch` — true whenever the new `clone_url` differs from the current remote.

If all three hold, Desktop calls `gitStore.setRemoteURL(...)`, which runs `git remote set-url origin <apiRepo.clone_url>` unconditionally: [4](#0-3) [5](#0-4) 

There is no check that the new host's origin matches the account's expected GitHub host (e.g. `github.com` or the configured GHES origin) — only that the *protocol* is unchanged. This is the exact analog of the oracle bug: a value from an untrusted/attacker-influenced external source (a "GitHub API object", explicitly listed in the Valid Impact category) is trusted and silently applied to a security-relevant piece of state (the git remote that all subsequent fetch/push operations use), with the only "sanity check" being weak and unrelated to authenticity (protocol string equality, analogous to the oracle's naive TWAP averaging without freshness/sanity bounds).

Separately, the credential trampoline does bind account credentials to the *actual request host* rather than the stored `GitHubRepository` record (`findGitHubTrampolineAccount` matches `parsedUrl.origin` against `account.endpoint`'s HTML origin): [6](#0-5) 

so the GitHub OAuth token itself is not automatically sent to the attacker's host. The residual, still-valid impact is silent corruption of the destination of the user's git operations, not direct token exfiltration.

### Impact Explanation
A compromised or malicious GHES instance (or any server acting as the account's configured API endpoint) can return a repository object whose `clone_url` points to an attacker-controlled HTTPS host. The next time Desktop fetches or pushes for that repository, it will:
1. Silently rewrite `origin` to the attacker's URL with no user prompt or confirmation dialog.
2. Immediately fetch from / push to that attacker-controlled remote using the newly rewritten URL, since the refresh happens inline before `performFetch`/`performPush` executes.

This is "silent corruption of what the user commits or pushes" as defined in scope: the user's source code is transparently exfiltrated to (via push) or replaced with attacker content from (via fetch) a host the user never approved, while the UI still shows the repository as the original GitHub project.

### Likelihood Explanation
This requires the attacker to control the response of the account's configured API endpoint for a specific repository lookup (i.e., a malicious/compromised GHES instance, or an on-path party able to tamper with that specific unauthenticated HTTPS response before TLS termination at the API host is trusted implicitly by the app's model). This is a realistic threat for users of self-hosted/enterprise GitHub instances where the operator or a network-adjacent attacker can influence API responses, and requires no local access, no prior malware, and no unnatural user interaction — it fires automatically on ordinary fetch/push.

### Recommendation
In `updateRemoteUrl`, validate that the new `clone_url`'s hostname/origin matches the expected GitHub host for the account's endpoint (i.e., `getHTMLURL(account.endpoint)` origin) before calling `setRemoteURL`, in addition to the existing protocol check. If the new URL's host differs from the expected host, require explicit user confirmation (similar to how SSH host-key changes are confirmed) rather than silently rewriting the remote.

### Proof of Concept
1. Configure a GitHub Enterprise account whose API endpoint is attacker-influenced (e.g., compromised GHES, or a party able to tamper with the specific `repos/{owner}/{name}` response).
2. Attacker's server returns a repository object identical to the real one except `clone_url: "https://evil.example.com/owner/repo.git"`.
3. User performs an ordinary `fetch` or `push` in Desktop on a repository whose current `origin` still matches the previously stored `gitHubRepository.cloneURL` (the default, unmodified case).
4. `repositoryWithRefreshedGitHubRepository` → `updateRemoteUrl` (`app/src/lib/stores/updates/update-remote-url.ts:42-44`) evaluates `protocolsMatch && remoteUrlUnchanged && !urlsMatch` as true and calls `gitStore.setRemoteURL('origin', 'https://evil.example.com/owner/repo.git')` with no user prompt.
5. The in-flight fetch/push proceeds against the new origin, silently sending the user's push to, or pulling content from, `evil.example.com`.

  private async repositoryWithRefreshedGitHubRepository(
    repository: Repository
  ): Promise<Repository> {
    const repoStore = this.repositoriesStore
    const match = await this.matchGitHubRepository(repository)

    // TODO: We currently never clear GitHub repository associations (see
    // https://github.com/desktop/desktop/issues/1144). So we can bail early at
    // this point.
    if (!match) {
      return repository
    }

    const { account, owner, name } = match
    const { endpoint } = account
    const api = API.fromAccount(account)
    const apiRepo = await api.fetchRepository(owner, name)

    if (apiRepo === null) {
      // If the request fails, we want to preserve the existing GitHub
      // repository info. But if we didn't have a GitHub repository already or
      // the endpoint changed, the skeleton repository is better than nothing.
      if (endpoint !== repository.gitHubRepository?.endpoint) {
        const ghRepo = await repoStore.upsertGitHubRepositoryFromMatch(match)
        return repoStore.setGitHubRepository(repository, ghRepo)
      }

      return repository
    }

    if (repository.gitHubRepository) {
      const gitStore = this.gitStoreCache.get(repository)
      await updateRemoteUrl(gitStore, repository.gitHubRepository, apiRepo)
    }

    const ghRepo = await repoStore.upsertGitHubRepository(endpoint, apiRepo)
    const freshRepo = await repoStore.setGitHubRepository(repository, ghRepo)

    await this.refreshBranchProtectionState(freshRepo)
    return freshRepo

import { IAPIRepository } from '../../api'
import { GitStore } from '../git-store'
import { urlMatchesRemote } from '../../repository-matching'
import * as URL from 'url'
import { GitHubRepository } from '../../../models/github-repository'

export async function updateRemoteUrl(
  gitStore: GitStore,
  gitHubRepository: GitHubRepository,
  apiRepo: IAPIRepository
): Promise<void> {
  // I'm not sure when these early exit conditions would be met. But when they are
  // we don't have enough information to continue so exit early!
  if (gitStore.defaultRemote === null) {
    return
  }

  const remoteUrl = gitStore.defaultRemote.url
  const updatedRemoteUrl = apiRepo.clone_url
  const urlsMatch = urlMatchesRemote(updatedRemoteUrl, gitStore.defaultRemote)

  // Verify that protocol hasn't changed. If it has we don't want
  // to alter the protocol in case they are relying on a specific one.
  // If protocol is null that implies the url is a ssh url
  // of the format git@github.com:octocat/Hello-World.git, which
  // can't be parsed by URL.parse. In this case we assume the user
  // manually configured their remote to use this format and we don't
  // want to change what they've done just to be safe
  const parsedRemoteUrl = URL.parse(remoteUrl)
  const parsedUpdatedRemoteUrl = URL.parse(updatedRemoteUrl)
  const protocolsMatch =
    parsedRemoteUrl.protocol !== null &&
    parsedUpdatedRemoteUrl.protocol !== null &&
    parsedRemoteUrl.protocol === parsedUpdatedRemoteUrl.protocol

  // Check if the default remote url has been manually changed from the
  // clone url retrieved from the GitHub API previously
  const remoteUrlUnchanged =
    gitStore.defaultRemote &&
    urlMatchesRemote(gitHubRepository.cloneURL, gitStore.defaultRemote)

  if (protocolsMatch && remoteUrlUnchanged && !urlsMatch) {
    await gitStore.setRemoteURL(gitStore.defaultRemote.name, updatedRemoteUrl)
  }
}

export async function findGitHubTrampolineAccount(
  accountsStore: AccountsStore,
  remoteUrl: string
): Promise<Account | undefined> {
  const accounts = await accountsStore.getAll()
  const parsedUrl = new URL(remoteUrl)
  return accounts.find(
    a => new URL(getHTMLURL(a.endpoint)).origin === parsedUrl.origin
  )
}
