### Title
DataLayer mirror-URL SSRF via unvalidated on-chain wallet-published URLs - (File: chia/data_layer/download_data.py)

### Summary
Chia's Data Layer lets any wallet holder publish an arbitrary list of URLs on-chain via a "mirror" coin for a given DataLayer store (`create_new_mirror`). Any DataLayer node that is subscribed to (tracking) that store will later read those attacker-controlled URLs from the chain and use them as server endpoints to make outbound HTTP requests, with no validation of scheme, host, or destination (localhost, RFC1918 ranges, or cloud metadata IPs are all accepted).

### Finding Description
A mirror coin's URL list is fully attacker-controlled and requires no special privilege beyond spending a coin: `DataLayerWallet.create_new_mirror` encodes `launcher_id` and arbitrary `urls` bytes directly into coin memos with no validation. [1](#0-0) 

When any peer observes a mirror coin for a launcher_id it is tracking, it decodes and stores those URLs verbatim into its local `mirrors` table, with the only filter being a non-empty check: [2](#0-1) 

The DataLayer service periodically pulls these wallet-sourced mirror URLs and writes them into its local subscription list for the store, again with no URL/scheme/host validation: [3](#0-2) [4](#0-3) 

These subscription URLs are later selected as "available servers" and used to fetch delta/root files over HTTP, again without any restriction on the destination: [5](#0-4) [6](#0-5) 

Additionally, the same mirror URL is also passed unmodified to any configured downloader plugin's `/download` endpoint and to `get_downloader`'s `/handle_download` endpoint as JSON body content, further widening exposure to attacker-supplied string data being relayed to another local/plugin HTTP service: [7](#0-6) [8](#0-7) 

No code path in this flow enforces an allow-list, blocks loopback/link-local/private ranges, or requires HTTPS — the equivalent of the reported Vexa webhook SSRF bug class (attacker sets an arbitrary destination URL that a trusted backend service will later connect to).

### Impact Explanation
Any Chia user who can create a mirror coin for any DataLayer store id (public store ids are used by DataLayer clients tracking that dataset) can force every DataLayer node subscribed to that store to perform outbound HTTP POST/GET requests to a URL of the attacker's choosing. This can be used to:
- Probe or attack internal services and the node operator's local network from the vantage point of the DataLayer host.
- Target cloud metadata endpoints (e.g. `http://169.254.169.254/...`) to attempt credential exfiltration if the DataLayer service runs in a cloud VM.
- Target `localhost`/loopback services exposed only to the local machine (other RPC ports, admin panels, plugin services).

This satisfies the Medium-severity SSRF class described in the analog report; it is reachable by any Data Layer client/wallet owner without requiring compromise of a peer or the node operator's own machine.

### Likelihood Explanation
Likelihood is high for any operator running DataLayer with subscriptions/mirrors enabled and tracking a store id whose mirror coins can be created by an untrusted third party (the whole point of the mirror mechanism is to let arbitrary participants advertise URLs for stores they don't own). The attack requires only the ability to spend a small coin to create a mirror entry with `create_new_mirror` — no elevated permissions, no compromised keys, and no interaction beyond farming a normal transaction.

### Recommendation
- Validate and restrict mirror/server/downloader URLs before making outbound requests: enforce an allow-listed scheme (https only), resolve and reject connections to private/loopback/link-local/multicast IP ranges and cloud metadata addresses, and consider DNS-rebinding protections (re-validate resolved IP just before connecting, e.g. via a custom `aiohttp` resolver/connector).
- Optionally require explicit operator opt-in per mirror URL/host before the service auto-fetches from it, rather than trusting any URL sourced from on-chain wallet mirror data.
- Apply the same validation uniformly to `data_store.update_subscriptions_from_wallet`, `download_file`/`http_download`, `get_downloader`, and `get_uploaders`, since they all consume attacker-influenced URLs.

### Proof of Concept
1. Attacker creates (or already knows) the `launcher_id`/store id of a DataLayer store that a victim node subscribes to (mirrors are a general on-chain publishing mechanism, not limited to store owners).
2. Attacker calls the wallet RPC `dl_new_mirror` (or `DataLayerWallet.create_new_mirror`) with `urls=["http://169.254.169.254/latest/meta-data/iam/security-credentials/", ...]` for that `launcher_id`, spending a small amount plus fee. [9](#0-8) 
3. Once the transaction confirms, any victim DataLayer node tracking that launcher_id ingests the mirror coin via `DataLayerWallet.coin_added` and persists the attacker URL. [2](#0-1) 
4. On the victim's next `periodically_manage_data` cycle, `update_subscriptions_from_wallet` copies the URL into the local subscriptions table, and `fetch_and_validate`/`download_file`/`http_download` issue an outbound HTTP request to the attacker-chosen destination. [3](#0-2) [6](#0-5) 

Note: I was unable to view the exact body of `http_download()` in `chia/data_layer/download_data.py` beyond line 187 (index truncation), so I cannot confirm from source whether it performs any additional low-level socket/IP filtering before connecting; based on all reachable code (`data_layer.py`, `data_store.py`, `data_layer_wallet.py`) there is no such filtering anywhere in the URL-selection or request-construction path. A Devin session with full file access would be needed to double-check `http_download`'s exact implementation if further confirmation is required.

```python
    async def get_downloader(self, store_id: bytes32, url: str) -> PluginRemote | None:
        request_json = {"store_id": store_id.hex(), "url": url}
        for d in self.downloaders:
            async with aiohttp.ClientSession() as session:
                try:
                    async with session.post(
                        d.url + "/handle_download",
                        json=request_json,
                        headers=d.headers,
                        timeout=self.client_timeout,
                    ) as response:
                        res_json = await response.json()
                        if res_json["handle_download"]:
                            return d
                except Exception as e:
                    self.log.error(f"get_downloader could not get response: {type(e).__name__}: {e}")
        return None
```

```python
    async def update_subscriptions_from_wallet(self, store_id: bytes32, new_urls: list[str]) -> None:
        async with self.db_wrapper.writer() as writer:
            cursor = await writer.execute(
                "SELECT * FROM subscriptions WHERE from_wallet == 1 AND tree_id == :tree_id",
                {
                    "tree_id": store_id,
                },
            )
            old_urls = [row["url"] async for row in cursor]
            cursor = await writer.execute(
                "SELECT * FROM subscriptions WHERE from_wallet == 0 AND tree_id == :tree_id",
                {
                    "tree_id": store_id,
                },
            )
            from_subscriptions_urls = {row["url"] async for row in cursor}
            additions = {url for url in new_urls if url not in old_urls}
            removals = [url for url in old_urls if url not in new_urls]
            for url in removals:
                await writer.execute(
                    "DELETE FROM subscriptions WHERE url == :url AND tree_id == :tree_id",
                    {
                        "url": url,
                        "tree_id": store_id,
                    },
                )
            for url in additions:
                if url not in from_subscriptions_urls:
                    await writer.execute(
                        "INSERT INTO subscriptions(tree_id, url, ignore_till, num_consecutive_failures, from_wallet) "
                        "VALUES (:tree_id, :url, 0, 0, 1)",
                        {
                            "tree_id": store_id,
                            "url": url,
                        },
                    )
```

```python
async def download_file(
    data_store: DataStore,
    target_filename_path: Path,
    store_id: bytes32,
    root_hash: bytes32,
    generation: int,
    server_info: ServerInfo,
    proxy_url: str | None,
    downloader: PluginRemote | None,
    timeout: aiohttp.ClientTimeout,
    client_foldername: Path,
    timestamp: int,
    log: logging.Logger,
    grouped_by_store: bool,
    group_downloaded_files_by_store: bool,
    max_delta_file_size: int,
) -> bool:
    if target_filename_path.exists():
        return True
    filename = get_delta_filename(store_id, root_hash, generation, grouped_by_store)

    if downloader is None:
        # use http downloader - this raises on any error
        try:
            await http_download(
                target_filename_path, filename, proxy_url, server_info, timeout, log, max_delta_file_size
            )
        except (asyncio.TimeoutError, aiohttp.ClientError, MaxDeltaFileSizeExceededError):
            new_server_info = await data_store.server_misses_file(store_id, server_info, timestamp)
            log.info(
                f"Failed to download {filename} from {new_server_info.url}."
                f"Miss {new_server_info.num_consecutive_failures}."
            )
            log.info(f"Next attempt from {new_server_info.url} in {new_server_info.ignore_till - timestamp}s.")
            return False
        return True
```

```python
    async def dl_new_mirror(
        self,
        request: DLNewMirror,
        action_scope: WalletActionScope,
        extra_conditions: tuple[Condition, ...] = tuple(),
    ) -> DLNewMirrorResponse:
        """Add a new on chain message for a specific singleton"""
        if self.service.wallet_state_manager is None:
            raise ValueError("The wallet service is not currently initialized")

        dl_wallet = await self.service.wallet_state_manager.get_dl_wallet()
        async with self.service.wallet_state_manager.lock:
            await dl_wallet.create_new_mirror(
                request.launcher_id,
                request.amount,
                Mirror.encode_urls(request.urls),
                action_scope,
                fee=request.fee,
                extra_conditions=extra_conditions,
            )

        # tx_endpoint will take care of default values here
        return DLNewMirrorResponse(unsigned_transactions=[], transactions=[])
```
