### Title
Quadratic/unbounded-time offer cancellation-coin computation from attacker-controlled offer data - ([File: chia/wallet/trading/offer.py])

### Summary
`Offer.get_cancellation_coins()` builds coin-dependency and announcement maps from the coin spends inside an untrusted offer file, then repeatedly rescans all remaining dependencies/announcements to find which coins can be dropped. This is the closest analog in this codebase to the libtasn1 report's bug class: a small, attacker-supplied, structurally-legal input (many elements/announcements) driving the parser/processor into disproportionately expensive repeated re-scans, causing a slow-down or hang on the victim's machine.

### Finding Description
`get_cancellation_coins()` [1](#0-0)  iterates over every non-ephemeral coin spend in an offer, decodes its `CREATE_COIN_ANNOUNCEMENT`/`ASSERT_COIN_ANNOUNCEMENT` conditions (fully attacker-controlled content inside a wallet-supplied offer file), and builds `dependencies`/`announcements` maps keyed by coin id. It then enters a `while True:` loop that calls `detect_dependent_coin()` and, for every coin removed in a round, does an inner `while True:` loop that scans **all remaining `dependencies.items()`** to find which other coins reference the just-removed coin's announcements via `set(deps) & set(removed_announcements)`.

Because each outer round can remove at most one "provider" coin, and each removal triggers a fresh O(n) (or worse, since `set(deps) & set(removed_announcements)` and the union bookkeeping are not cheap for large per-coin announcement lists) scan of the remaining structure, an offer with many coins chained together through announcement dependencies can drive this function toward O(n²) or worse in the number of coin spends/announcements. This is called from `TradeManager.cancel_pending_offers()` [2](#0-1)  whenever a user (maker or the wallet processing a taken offer) cancels a trade, and it runs entirely in Python, unbounded by CLVM cost metering (the CLVM execution itself is metered via `run_with_cost(spend.puzzle_reveal, INFINITE_COST, spend.solution)`, but the post-processing dependency-resolution loop is not cost-limited at all).

This differs from the well-protected mempool/CLVM path: `is_clvm_canonical()` is a single linear scan [3](#0-2) , and `pre_validate_spendbundle()`/`validate_spend_bundle()` enforce strict cost, atom/pair, and wall-clock duration limits [4](#0-3) . The offer-cancellation-coin computation in the wallet has no equivalent CLVM-cost or wall-clock guard.

### Impact Explanation
An offer counterparty (or anyone who gets a victim wallet to load/accept/cancel a crafted offer) can construct an offer bundle containing many coin spends whose puzzles emit chained `CREATE_COIN_ANNOUNCEMENT`/`ASSERT_COIN_ANNOUNCEMENT` conditions, forcing `get_cancellation_coins()` into disproportionately expensive repeated set-scans. Because this runs synchronously inside the wallet's `TradeManager.cancel_pending_offers()` flow, it can stall wallet trade-cancellation processing for the affected wallet — a spend/offer-triggered transaction-processing halt local to the wallet, matching the CVE's "inefficient decoding of specific data leading to a DoS" bug class, though scoped to the wallet-side offer/trade path rather than full-node consensus.

### Likelihood Explanation
Medium: constructing such an offer requires only the ability to craft arbitrary CLVM puzzles/solutions that emit many coin/puzzle announcements (something any wallet user or CAT/NFT developer can already do), and getting the victim to accept/cancel that offer through the standard trade flow. No privileged node or peer access is needed — only a spend bundle/offer file, matching the "unprivileged offer counterparty" reachability requirement.

### Recommendation
Bound `get_cancellation_coins()`'s work relative to the number of coin spends/announcements in the offer (e.g., cap total announcements considered, or rewrite the dependency-resolution loop to use amortized union-find/graph-traversal instead of repeated full re-scans of `dependencies`/`announcements`), and add either a hard iteration/announcement-count cap or a wall-clock timeout around this computation in `TradeManager.cancel_pending_offers()` and any other caller that processes untrusted offer bytes before this stage.

### Proof of Concept
Not independently verified with a runnable reproduction in this session (index-based read-only investigation only, no execution environment). Conceptually: construct an `Offer` whose bundle contains N coin spends, each creating a `CREATE_COIN_ANNOUNCEMENT` and asserting the announcement of the "next" coin in a long chain (as done deliberately but at small scale in `TradeManager.cancel_pending_offers()`'s own use of `CreateCoinAnnouncement`/`AssertCoinAnnouncement` chaining [5](#0-4) ). Load this offer and call `trade_manager.cancel_pending_offers([trade_id], ...)`, which invokes `Offer.from_bytes(trade.offer).get_cancellation_coins()` [6](#0-5) ; measure wall-clock time growth as N increases to confirm super-linear scaling.

    def get_cancellation_coins(self) -> list[Coin]:
        # First, we're going to gather:
        dependencies: dict[bytes32, list[bytes32]] = {}  # all of the hashes that each coin depends on
        announcements: dict[bytes32, list[bytes32]] = {}  # all of the hashes of the announcement that each coin makes
        coin_names: list[bytes32] = []  # The names of all the coins
        additions = self.additions()
        for spend in [cs for cs in self._bundle.coin_spends if cs.coin not in additions]:
            name = bytes32(spend.coin.name())
            coin_names.append(name)
            dependencies[name] = []
            announcements[name] = []
            conditions: Program = run_with_cost(spend.puzzle_reveal, INFINITE_COST, spend.solution)[1]
            for condition in conditions.as_iter():
                if condition.first() == 60:  # create coin announcement
                    announcements[name].append(
                        AssertCoinAnnouncement(asserted_id=name, asserted_msg=condition.at("rf").as_python()).msg_calc
                    )
                elif condition.first() == 61:  # assert coin announcement
                    dependencies[name].append(bytes32(condition.at("rf").as_python()))

        # We now enter a loop that is attempting to express the following logic:
        # "If I am depending on another coin in the same bundle, you may as well cancel that coin instead of me"
        # By the end of the loop, we should have filtered down the list of coin_names to include only those that will
        # cancel everything else
        while True:
            removed = detect_dependent_coin(coin_names, dependencies, announcements)
            if removed is None:
                break
            removed_coin, provider = removed
            removed_announcements: list[bytes32] = announcements[removed_coin]
            remove_these_keys: list[bytes32] = [removed_coin]
            while True:
                for coin, deps in dependencies.items():
                    if set(deps) & set(removed_announcements) and coin != provider:
                        remove_these_keys.append(coin)
                removed_announcements = []
                for coin in remove_these_keys:
                    dependencies.pop(coin)
                    removed_announcements.extend(announcements.pop(coin))
                coin_names = [n for n in coin_names if n not in remove_these_keys]
                if removed_announcements == []:
                    break
                else:
                    remove_these_keys = []

        return [cs.coin for cs in self._bundle.coin_spends if cs.coin.name() in coin_names]

def is_clvm_canonical(clvm_buffer: bytes) -> bool:
    """
    checks whether the CLVM serialization is all canonical representation.
    atoms can be serialized in more than one way by using more bytes than
    necessary to encode the length prefix. This functions ensures that all atoms are
    encoded with the shortest representation. back-references are not allowed
    and will make this function return false
    """
    assert clvm_buffer != b""

    offset = 0
    tokens_left = 1
    while True:
        b = clvm_buffer[offset]

        # pair
        if b == 0xFF:
            tokens_left += 1
            offset += 1
            continue

        # back references cannot be considered canonical, since they may be
        # encoded in many different ways
        if b == 0xFE:
            return False

        # small atom or NIL
        if b <= 0x80:
            tokens_left -= 1
            offset += 1
        else:
            atom_len, canonical = is_atom_canonical(clvm_buffer, offset)
            if not canonical:
                return False
            tokens_left -= 1
            offset += atom_len

        if tokens_left == 0:
            break

    # if there's garbage at the end, it's not canonical
    return offset == len(clvm_buffer)
