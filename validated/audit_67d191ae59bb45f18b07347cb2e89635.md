### Title
Cached FROST preprocess never invalidated, enabling deterministic nonce reuse across `share` and `complete` invocations - ([File: coordinator/src/tributary/signing_protocol.rs])

### Summary
`SigningProtocol::preprocess_internal` stores a `CachedPreprocess` in the DB keyed by `(b"DkgConfirmer", attempt)` and regenerates the *same* signing machine — hence the same FROST nonces — on every call, because the cache entry is only written when absent (`if CachedPreprocesses::get(...).is_none()`) and is never deleted after `sign` consumes it. `DkgConfirmer::share` and `DkgConfirmer::complete` each invoke `share_internal`, which calls `preprocess_internal` again; the library contract (`SignMachine::from_cache`: "the preprocess must be deleted so it's never reused") is violated. This is the Serai analog of CVE-2021-47318: a resource that must be quiesced/invalidated before reuse (here, a one-shot nonce seed) remains reachable to later readers, so a second logical "tick" operates on state that was already consumed.

### Finding Description
In `crypto/frost/src/sign.rs`, `AlgorithmSignMachine` derives its nonces deterministically from `self.seed` via `seeded_preprocess` (invoked by `from_cache`). Two calls to `preprocess_internal` with the same context therefore produce machines with identical nonce pairs `[base, actual]` (sign.rs:386-396 shows the actual nonce is `base + rho * actual` where `rho` is the binding factor).

The reuse path:

1. `DkgConfirmer::share(preprocesses, key_pair)` → `share_internal` → `preprocess_internal` → machine built from cached seed → `machine.sign(preprocesses, msg)` emits share `s₁ = k + e₁·λ·x` where `msg = set_keys_message(set, removed, key_pair)` and `k = base + ρ·actual`.
2. `DkgConfirmer::complete(preprocesses', key_pair', shares)` → `share_internal` again (line 322) → the *same* cached seed → `machine.sign(preprocesses', msg')` emits share `s₂`.

The cached seed is still present because `preprocess_internal` never clears `CachedPreprocesses` after `from_cache` — unlike the kernel fix's `synchronize_rcu()` guarantee that no reader can touch cleared state, nothing here enforces single-use. If the preprocess set is identical across the two calls but the message differs (a different `key_pair`, or a call ordering where `share` and `complete` observe distinct finalization inputs), the binding factors `ρ` and nonce commitments `R` are identical, so `k₁ = k₂` while `e₁ ≠ e₂`. Then `s₁ - s₂ = λ·x·(e₁ - e₂)` directly recovers the validator's MuSig secret share `λ·x` — no cryptanalysis required.

This is precisely the failure mode the file's own header (lines 25-54) worries about ("unsafe to reuse nonces across signing sessions"), and its mitigation relies on BFT ordering of inputs — yet `share` and `complete` are two *different* public entry points both signing under one context, and `complete` re-signs fresh attacker-supplied preprocesses/`key_pair` rather than reusing the share it already produced, so the BFT argument does not cover inputs that differ between the two entry points for the same attempt.

### Impact Explanation
Recovery of a validator's private MuSig share (`λ·x`) from two published signature shares on the public tributary. That share is the root-of-trust validator key used to confirm DKG results on Substrate; recovering it lets the holder forge confirmation signature shares and breaks the threshold assumption for the set. Classified as High: permanent key compromise material from publicly emitted data.

### Likelihood Explanation
Reachable whenever `share` and `complete` are invoked for the same `(b"DkgConfirmer", attempt)` context with differing `msg` or differing preprocess sets — the preprocess map and `key_pair` bytes are supplied by on-chain/tributary data that validators submit, i.e., public inputs an unprivileged party causes to be signed. No collusion threshold or broken BFT is required; only that the two calls see non-identical sign inputs, which the protocol permits since `complete` accepts its own `preprocesses`/`key_pair` arguments and unconditionally re-signs (`.expect("trying to complete a machine which failed to preprocess")` at line 322-323).

### Recommendation
Treat the cached preprocess as single-use per the `SignMachine::from_cache` contract: delete `CachedPreprocesses[context]` (or mark it consumed) inside `preprocess_internal` immediately after `from_cache`, and make `DkgConfirmer::complete` reuse the signature machine/share produced by `share` (persisted keyed by a hash of `preprocesses || key_pair`) rather than re-executing `share_internal` with fresh inputs. If re-execution is unavoidable, verify the reconstructed machine's preprocess equals the one already published on-chain (the header's own TODO at line 50-51) and refuse to emit a second share for divergent inputs.

### Proof of Concept
```rust
// Two calls under the same context reuse the same seed and hence the same nonces.
// Call 1 (share):
let s1 = confirmer.share(preprocesses.clone(), &key_pair_a)?;   // emits share s1
// Call 2 (complete) — attacker-prompted path re-signs with a different key_pair:
let sig = confirmer.complete(preprocesses, &key_pair_b, shares)?; // internally emits s2
// If preprocesses are identical, rho and R are identical -> k1 == k2.
// s1 - s2 = lambda*x*(e1 - e2)  =>  x = (s1 - s2) / (lambda*(e1 - e2))
```

Where `share_internal` → `preprocess_internal` → `CachedPreprocesses::get(txn, &("DkgConfirmer", attempt))` returns the identical `[u8; 32]` seed on both calls since it is only set once and never removed (signing_protocol.rs:123-145), and `sign` computes `actual = base + rho·actual` deterministically from that seed (sign.rs:386-396).
