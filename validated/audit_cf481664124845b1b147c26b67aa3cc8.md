## Title
Fee-on-transfer/deflationary LP tokens cause over-minted receipt tokens in `WombatStaking.depositLP` — (File: `wombat/WombatStaking.sol`)

### Summary
`WombatStaking.depositLP` transfers `_lpAmount` of the Wombat pool's LP token from the caller and then mints exactly `_lpAmount` of receipt tokens and stakes exactly `_lpAmount` to the master Wombat contract, without verifying how much was actually received. This mirrors the reported Gravity Bridge bug: the code trusts the `_amount` parameter instead of measuring the real balance delta from `transferFrom`.

### Finding Description
In `deposit()`, the contract correctly measures the actually-received LP amount by taking a balance snapshot before and after depositing into the Wombat pool: [1](#0-0) 

However, `depositLP()` does not follow this pattern. It transfers `_lpAmount` via `safeTransferFrom`, then immediately uses the caller-supplied `_lpAmount` (not an actual balance-diff) both to stake into `masterWombat` and to mint receipt tokens 1:1: [2](#0-1) 

If `poolInfo.lpAddress` (the Wombat Asset/LP token) ever has a fee-on-transfer, rebasing, or otherwise non-standard transfer behavior — a class of token that the very next function in the same contract (`deposit`) is explicitly defensive against — the amount actually received and staked by `WombatStaking` would be less than `_lpAmount`, while the caller (via `IMintableERC20(poolInfo.receiptToken).mint(msg.sender, _lpAmount)`) still receives receipt tokens as if the full `_lpAmount` had been custodied.

### Impact Explanation
Receipt tokens (minted 1:1 in `depositLP`) are the internal accounting unit redeemable through `WombatPoolHelper`/`WombatPoolHelperV2` and burned via `burnReceiptToken` on withdrawal. If receipt token supply outstrips the actual LP tokens staked in `masterWombat`, later users attempting to withdraw their legitimate share would find insufficient underlying LP balance, i.e. protocol insolvency for that pool — some users would be unable to redeem, effectively enabling early depositors of such a token to over-mint claims against the shared pool of staked assets custodied by `WombatStaking`.

### Likelihood Explanation
This path is reachable by any unprivileged wallet: a user calls `WombatPoolHelper.depositLP` / `WombatPoolHelperV2.depositLP`, which is a pool helper (an "active" pool helper per the `_onlyActivePoolHelper` modifier, not an admin-only path) that forwards to `WombatStaking.depositLP`. Likelihood depends on whether any registered pool's `lpAddress` (a Wombat Asset token) can exhibit fee-on-transfer/deflationary behavior — same caveat as the original Gravity finding, which was still rated high severity because the accounting logic itself is unconditionally wrong for that token class.

### Recommendation
Apply the same before/after balance-diff pattern already used in `deposit()` and `withdraw()` to `depositLP()`: measure `poolInfo.lpAddress` balance before and after the `safeTransferFrom`, and use that delta (not the caller-supplied `_lpAmount`) for both `_toMasterWomAndSendReward` and the receipt token mint amount and event.

### Proof of Concept
1. Register a pool where `lpAddress` is (or is later swapped for/behaves as) a fee-on-transfer token.
2. A user calls `depositLP(_lpAddress, 1000, _for)` through the corresponding pool helper.
3. `safeTransferFrom` moves only 990 tokens to `WombatStaking` due to the transfer fee, but `_toMasterWomAndSendReward` is called with `1000` and `IMintableERC20(poolInfo.receiptToken).mint(msg.sender, 1000)` mints 1000 receipt tokens.
4. Repeated across depositors, minted receipt token supply exceeds actual LP custodied/staked, and later withdrawals via `WombatStaking.withdraw` cannot be fully honored for all receipt-token holders. [2](#0-1)

    function depositLP(
        address _lpAddress,
        uint256 _lpAmount,
        address _for
    ) nonReentrant whenNotPaused _onlyActivePoolHelper(_lpAddress) external {
        // Get information of the Pool of the token
        Pool storage poolInfo = pools[_lpAddress];

        // Transfer lp to this contract and stake it to wombat
        IERC20(poolInfo.lpAddress).safeTransferFrom(_for, address(this), _lpAmount);

        _toMasterWomAndSendReward(_lpAddress, _lpAmount, true); // triggers harvest from wombat exchange
        IMintableERC20(poolInfo.receiptToken).mint(msg.sender, _lpAmount);

        emit NewLPDeposit(_for, poolInfo.lpAddress, _lpAmount, poolInfo.receiptToken, _lpAmount);
    }
