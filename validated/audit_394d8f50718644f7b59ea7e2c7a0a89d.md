### Title
`Scanner::scan_block` reports immature coinbase outputs as spendable funds - (File: networks/bitcoin/src/wallet/mod.rs)

### Summary
`Scanner::scan_block` iterates `block.txdata` including `block.txdata[0]` (the coinbase transaction) and returns `ReceivedOutput`s for it. Coinbase outputs are unspendable for 100 blocks (COINBASE_MATURITY). Nothing in `ReceivedOutput`, `scan_transaction`, or `SignableTransaction::new`/`multisig` checks whether the referenced outpoint is an immature coinbase output, so Serai will accept the output as received balance and construct/sign a transaction that consensus rejects — the analog of accepting a revoked certificate because a validity condition was never checked.

### Finding Description
`Scanner::scan` matches only `output.script_pubkey` against registered scripts: [1](#0-0) 

`scan_block` feeds the coinbase transaction through the same path: [2](#0-1) 

The resulting `ReceivedOutput` carries only `offset`, `output`, `outpoint` — no coinbase/maturity flag: [3](#0-2) 

`SignableTransaction::new` sums `input.output.value` and treats every input as spendable, and `multisig` only verifies the offset/script_pubkey correspondence: [4](#0-3) [5](#0-4) 

The doc comment on `scan_block` acknowledges the caveat ("bound by maturity... a post-processing pass is needed"), but no code enforces it and `scan_transaction` — the public single-tx entry point — performs no coinbase check either. A non-coinbase-aware caller gets structurally valid, signed transactions that are consensus-invalid.

### Impact Explanation
An unprivileged miner can pay the Serai multisig address in a coinbase output. `scan_block` reports the funds as received; Serai then produces a fully-signed spend transaction that any node rejects (`bad-txns-coinbase` / immature coinbase). If this input is mixed with real inputs in `SignableTransaction::new`, the entire transaction is unbroadcastable, stalling the payout and the other inputs. Funds are reported received that are not (yet) spendable, matching the acceptance criterion.

### Likelihood Explanation
Any miner can include a payment to the Serai Taproot script in their coinbase — no privilege required. It triggers whenever a scanner block-scan result is used without the manual post-processing the comment prescribes.

### Recommendation
Track coinbase status on `ReceivedOutput` (or reject coinbase inputs in `SignableTransaction::new`/`multisig` unless maturity is proven), and have `scan_block` either skip `txdata[0]` or annotate outputs so callers cannot silently spend immature coins.

### Proof of Concept
A miner crafts a block whose `txdata[0]` has an output paying `p2tr_script_buf(key)` for the Serai group key. `Scanner::new(key).scan_block(&block)` returns a `ReceivedOutput` for it. `SignableTransaction::new(vec![ro], &payments, None, None, fee)` succeeds and `multisig(&tweak_keys(keys))` builds a `TransactionMachine`; the signed transaction spending the coinbase outpoint is rejected by all Bitcoin nodes until 100 confirmations elapse.

```rust
  pub fn scan_transaction(&self, tx: &Transaction) -> Vec<ReceivedOutput> {
    let mut res = Vec::new();
    for (vout, output) in tx.output.iter().enumerate() {
      // If the vout index exceeds 2**32, stop scanning outputs
      let Ok(vout) = u32::try_from(vout) else { break };

      if let Some(offset) = self.scripts.get(&output.script_pubkey) {
        res.push(ReceivedOutput {
          offset: *offset,
          output: output.clone(),
          outpoint: OutPoint::new(tx.compute_txid(), vout),
        });
      }
    }
    res
  }
```

```rust
    let mut res = Vec::new();
    for tx in &block.txdata {
      res.extend(self.scan_transaction(tx));
    }
    res
  }
```
