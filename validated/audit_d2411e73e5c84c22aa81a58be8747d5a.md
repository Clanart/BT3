### Title
Payout OP_RETURN operator-attribution is unauthenticated, allowing anyone to frame a victim operator as the fronting payer - ([File: core/src/builder/transaction/operator_reimburse.rs])

### Summary
`create_payout_txhandler` builds the `payout_tx` that spends a user's withdrawal UTXO with a key-spend witness and attaches a plain, unauthenticated `OP_RETURN` output carrying an `operator_xonly_pk` used purely to attribute "who fronted this withdrawal" for later reimbursement. [1](#0-0)  The withdrawal input is signed by the user off-chain with a `SinglePlusAnyoneCanPay` sighash (only input 0 / output 0 committed), which is explicitly designed to let a third party add extra funding inputs. [2](#0-1)  Since the OP_RETURN payload is not covered by any signature at all, any party who can observe the withdrawal request (registered publicly via `safeWithdraw` on the Citrea bridge contract) can construct and broadcast their own version of `payout_tx`, fund the output difference themselves, and put an arbitrary victim operator's x-only pubkey into the OP_RETURN.

### Finding Description
The payout transaction has exactly one authenticated input (the withdrawal UTXO, signed by the user with `SinglePlusAnyoneCanPay`) and a completely free-form `OP_RETURN` output whose sole purpose is downstream attribution: [3](#0-2) 

Verifiers scan the chain for payout transactions and parse this `OP_RETURN` to determine `payout_payer_operator_xonly_pk`, storing it in the `withdrawals` table with no verification that the named operator actually supplied the funds: [4](#0-3) [5](#0-4) 

The victim operator's own automation (`PayoutCheckerTask`) then picks up "its" unhandled payout purely by matching `payout_payer_operator_xonly_pk` against its own key, and automatically starts the reimbursement/kickoff process: [6](#0-5) [7](#0-6) 

Because the `SinglePlusAnyoneCanPay` sighash only commits to the single withdrawal input and its corresponding output, an attacker (unprivileged, no verifier/operator/watchtower role needed) can:
1. Observe a pending withdrawal's `input_outpoint`, `input_signature`, `output_script_pubkey`, and `output_amount` — these are published on-chain by the user/aggregator via the Citrea `safeWithdraw` call (readable by anyone) and are also the exact fields carried in `WithdrawParams`. [8](#0-7) 
2. Construct their own `payout_tx` using `create_payout_txhandler` logic, adding their own funding UTXO(s) (permitted by ANYONECANPAY) to cover the output amount, and set the `OP_RETURN` to an arbitrary **victim** operator's `xonly_pk` instead of their own.
3. Broadcast it directly to Bitcoin, bypassing every operator/aggregator gRPC endpoint and any of the `is_profitable`/verification-signature checks in `Operator::withdraw`. [9](#0-8) 

This breaks the intended binding: **the operator credited (attributed as payer in the DB) must equal the party that actually paid**. Before the attack: no payer is credited (payout unfulfilled). After the attacker's transaction: the victim operator is credited as payer even though the attacker funded the payout.

### Impact Explanation
Once the victim operator is falsely recorded as the payer, its own automation (`PayoutCheckerTask` → `handle_finalized_payout` → kickoff/asserts) is triggered for a withdrawal it never fronted with its own capital. [10](#0-9)  This forces the victim operator into an uninitiated kickoff cycle (spending its own kickoff/collateral connectors, going through the challenge/assert machinery) for a payout event outside its control and timing, and ultimately routes the deposit's move-to-vault reimbursement to the framed operator's `operator_reimbursement_address` regardless of who actually paid the user. [11](#0-10)  This matches the Critical impact category "an operator reimbursed for a payout it never funded," and can additionally expose the framed operator to challenge/disprove risk it did not choose to enter, at a time and with commitments (e.g., payout blockhash committed via WOTS in the kickoff) it did not select — a misattributed custody/reimbursement event triggered entirely by an unauthenticated third party.

### Likelihood Explanation
The attack requires no privileged role: withdrawal parameters (outpoint, signature, output script/amount) become public once registered on Citrea via `safeWithdraw`, and Bitcoin transaction construction/broadcast is permissionless. The only "cost" to the attacker is funding the payout output themselves (which they must do anyway to make the forged attribution transaction valid and confirmed), and there is no on-chain or off-chain check tying the `OP_RETURN` payload to the party who actually supplied the extra input value. This makes the likelihood high whenever an attacker is willing to front a withdrawal's BTC value in order to grief/frame a specific operator.

### Recommendation
Bind operator attribution cryptographically instead of relying on unauthenticated OP_RETURN data: e.g., require the operator's signature to authorize the specific payout transaction/attribution (so the payer's own key must sign the commitment of "I fronted this withdrawal"), or otherwise verify at DB-ingestion time that the additional funding UTXOs in the payout transaction actually originate from wallets attributable to the named `operator_xonly_pk` before recording `payout_payer_operator_xonly_pk` and triggering automated reimbursement flows.

### Proof of Concept
1. A user requests a withdrawal and calls `safeWithdraw` on the Citrea bridge contract, revealing `input_outpoint`, `input_signature` (SinglePlusAnyoneCanPay), `output_script_pubkey`, and `output_amount` on-chain/publicly.
2. Attacker builds a transaction identical in shape to `create_payout_txhandler`'s output (input 0 = withdrawal UTXO with the observed signature; output 0 = the user's payout output) but adds their own additional input(s) to cover `output_amount` and sets the `OP_RETURN` payload to `victim_operator_xonly_pk` instead of their own key. [1](#0-0) 
3. Attacker broadcasts this transaction to Bitcoin; it confirms because the only signature check is on input 0 (valid, from the user), and ANYONECANPAY permits arbitrary extra inputs/outputs.
4. Verifiers' block sync parses the OP_RETURN and records `payout_payer_operator_xonly_pk = victim_operator_xonly_pk` in the `withdrawals` table. [4](#0-3) 
5. Victim operator's `PayoutCheckerTask` finds this "unhandled payout" under its own key and automatically starts the kickoff/reimbursement flow for a payment it never made. [6](#0-5)

pub fn create_reimburse_txhandler(
    move_txhandler: &TxHandler,
    round_txhandler: &TxHandler,
    kickoff_txhandler: &TxHandler,
    kickoff_idx: usize,
    paramset: &'static ProtocolParamset,
    operator_reimbursement_address: &bitcoin::Address,
) -> Result<TxHandler, BridgeError> {
    let builder = TxHandlerBuilder::new(TransactionType::Reimburse)
        .with_version(NON_STANDARD_V3)
        .add_input(
            NormalSignatureKind::Reimburse1,
            move_txhandler.get_spendable_output(UtxoVout::DepositInMove)?,
            builder::script::SpendPath::ScriptSpend(0),
            DEFAULT_SEQUENCE,
        )
        .add_input(
            NormalSignatureKind::Reimburse2,
            kickoff_txhandler.get_spendable_output(UtxoVout::ReimburseInKickoff)?,
            builder::script::SpendPath::ScriptSpend(0),
            DEFAULT_SEQUENCE,
        )
        .add_input(
            NormalSignatureKind::OperatorSighashDefault,
            round_txhandler.get_spendable_output(UtxoVout::ReimburseInRound(
                kickoff_idx,
                paramset.num_kickoffs_per_round,
            ))?,
            builder::script::SpendPath::KeySpend,
            DEFAULT_SEQUENCE,
        );

    Ok(builder
        .add_output(UnspentTxOut::from_partial(TxOut {
            value: move_txhandler
                .get_spendable_output(UtxoVout::DepositInMove)?
                .get_prevout()
                .value,
            script_pubkey: operator_reimbursement_address.script_pubkey(),
        }))
        .add_output(UnspentTxOut::from_partial(
            builder::transaction::anchor_output(paramset.anchor_amount()),
        ))
        .finalize())
}

/// Creates a [`TxHandler`] for the `payout_tx`.
///
/// This transaction is sent by the operator to front a peg-out, after which operator will send a kickoff transaction to get reimbursed.
///
/// # Inputs
/// 1. UTXO: User's withdrawal input (committed in Citrea side, with the signature given to operators off-chain)
///
/// # Outputs
/// 1. User payout output
/// 2. OP_RETURN output (with operators x-only pubkey that fronts the peg-out)
///
/// # Arguments
/// * `input_utxo` - The input UTXO for the payout, committed in Citrea side, with the signature given to operators off-chain.
/// * `output_txout` - The output TxOut for the user payout.
/// * `operator_xonly_pk` - The operator's x-only public key that fronts the peg-out.
/// * `user_sig` - The user's signature for the payout, given to operators off-chain.
/// * `network` - The Bitcoin network.
///
/// # Returns
/// A [`TxHandler`] for the payout transaction, or a [`BridgeError`] if construction fails.
pub fn create_payout_txhandler(
    input_utxo: UTXO,
    output_txout: TxOut,
    operator_xonly_pk: XOnlyPublicKey,
    user_sig: taproot::Signature,
    _network: bitcoin::Network,
) -> Result<TxHandler<Signed>, BridgeError> {
    let txin = SpendableTxIn::new_partial(input_utxo.outpoint, input_utxo.txout);

    let output_txout = UnspentTxOut::from_partial(output_txout.clone());

    let op_return_txout = op_return_txout(PushBytesBuf::from(operator_xonly_pk.serialize()));

    let mut txhandler = TxHandlerBuilder::new(TransactionType::Payout)
        .with_version(NON_STANDARD_V3)
        .add_input(
            NormalSignatureKind::NotStored,
            txin,
            SpendPath::KeySpend,
            DEFAULT_SEQUENCE,
        )
        .add_output(output_txout)
        .add_output(UnspentTxOut::from_partial(anchor_output(
            NON_EPHEMERAL_ANCHOR_AMOUNT,
        )))
        .add_output(UnspentTxOut::from_partial(op_return_txout))
        .finalize();
    txhandler.set_p2tr_key_spend_witness(&user_sig, 0)?;
    txhandler.promote()
}

    /// Sets the given payout txs' txid and operator index for the given index.
    pub async fn update_payout_txs_and_payer_operator_xonly_pk(
        &self,
        tx: Option<DatabaseTransaction<'_>>,
        payout_txs_and_payer_operator_xonly_pk: Vec<(
            u32,
            Txid,
            Option<XOnlyPublicKey>,
            bitcoin::BlockHash,
        )>,
    ) -> Result<(), BridgeError> {
        if payout_txs_and_payer_operator_xonly_pk.is_empty() {
            return Ok(());
        }
        // Convert all values first, propagating any errors
        let converted_values: Result<Vec<_>, BridgeError> = payout_txs_and_payer_operator_xonly_pk
            .iter()
            .map(|(idx, txid, operator_xonly_pk, block_hash)| {
                Ok((
                    i32::try_from(*idx).wrap_err("Failed to convert payout index to i32")?,
                    TxidDB(*txid),
                    operator_xonly_pk.map(XOnlyPublicKeyDB),
                    BlockHashDB(*block_hash),
                ))
            })
            .collect();
        let converted_values = converted_values?;

        let mut query_builder = QueryBuilder::new(
            "UPDATE withdrawals AS w SET
                payout_txid = c.payout_txid,
                payout_payer_operator_xonly_pk = c.payout_payer_operator_xonly_pk,
                payout_tx_blockhash = c.payout_tx_blockhash
                FROM (",
        );

        query_builder.push_values(
            converted_values.into_iter(),
            |mut b, (idx, txid, operator_xonly_pk, block_hash)| {
                b.push_bind(idx)
                    .push_bind(txid)
                    .push_bind(operator_xonly_pk)
                    .push_bind(block_hash);
            },
        );

        query_builder
            .push(") AS c(idx, payout_txid, payout_payer_operator_xonly_pk, payout_tx_blockhash) WHERE w.idx = c.idx");

        let query = query_builder.build();
        execute_query_with_tx!(self.connection, tx, query, execute)?;

        Ok(())
    }
