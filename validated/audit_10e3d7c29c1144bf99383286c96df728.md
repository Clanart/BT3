### Title
Unrestricted `CallDispatcher.dispatch()` allows theft of any residual/uncollected token balance left in the shared execution sandbox - ([File: evm/src/utils/CallDispatcher.sol])

### Summary
The external report's core issue is a user-specified "hook" contract that is invoked by the protocol with no restriction on target, calldata, or custody boundary. Hyperbridge's `IntentGatewayV2` (and `HyperFungibleToken`/`WrappedHyperFungibleToken`) implement the exact same pattern via `CallDispatcher`: user-supplied `Call[]` arrays (`order.predispatch.call`, `order.output.call`) are executed by a single, permissionless, un-access-controlled contract that transiently custodies real bridged/escrowed funds. [1](#0-0) 

### Finding Description
`CallDispatcher.dispatch(bytes memory encoded)` is `external` with **no caller restriction whatsoever** — any address, not just `IntentGatewayV2` or `HyperFungibleToken`, can invoke it directly and force it to execute an arbitrary `Call[]` from its own context: [1](#0-0) 

`CallDispatcher` is documented as a shared, chain-wide singleton reused by multiple protocols (`IntentGatewayV2` predispatch/postdispatch, `HyperFungibleToken`, `WrappedHyperFungibleToken`): [2](#0-1) 

During `IntentGatewayV2`'s postdispatch flow, `_execute()` runs the user-supplied `order.output.call` through this shared dispatcher, then sweeps back only the tokens explicitly listed in `order.output.assets` (`outputsLen` loop): [3](#0-2) 

Because `order.output.call` is fully attacker-controlled arbitrary calldata (multi-hop swaps, protocol interactions, referral/reward claims, fee-on-transfer tokens, slippage residue, etc.), it can easily cause the `CallDispatcher` to end up holding tokens that are **not** part of `order.output.assets` — e.g. a bonus/reward token from a DEX call, or dust in a token not enumerated by the order. That residual balance is never swept by `_execute()` (which only iterates `order.output.assets`), and it sits in the CallDispatcher's storage/balance indefinitely.

Because `dispatch()` has zero access control, **any unrelated third party** can later call `CallDispatcher.dispatch()` directly with a `Call[]` that transfers this stranded token/ETH balance to themselves — the same primitive the flagged order used to place it there, but now usable by anyone against a shared contract that also custodies funds belonging to unrelated in-flight orders and other protocols (HyperFungibleToken teleports) using the same dispatcher instance.

This differs from the discarded "gas griefing" class: it is not a DoS against relayers/solvers, it is **unauthorized extraction of bridged/escrowed value from a shared custody contract with no beneficiary check**, i.e., a fund-loss primitive against the "assets must move exactly once and only to the rightful beneficiary" invariant.

### Impact Explanation
Any value left in `CallDispatcher` — whether from slippage, unexpected swap outputs, reward tokens, or a race where a sweep transaction has partially executed — is permanently exposed to anyone. Because the contract is shared across `IntentGatewayV2` and the HyperFungibleToken family, funds belonging to unrelated users/protocols using the same dispatcher address can be drained by a party who has nothing to do with the order that generated the residue. This is a direct violation of the "bridged assets... must move exactly once and only to the rightful beneficiary and amount" pivot.

### Likelihood Explanation
No privileged actor, relayer, prover, or governance action is required — a fully permissionless attacker can (1) craft an order whose `output.call`/`predispatch.call` deliberately leaves an un-enumerated token balance in the dispatcher (e.g., routing through a token not declared in `order.output.assets`), then (2) call `CallDispatcher.dispatch()` themselves to sweep it out. The only friction is that the attacker must engineer their own order to produce the stranded balance, but since `order.output.call` is entirely attacker-authored, this is straightforward and repeatable.

### Recommendation
- Restrict `CallDispatcher.dispatch()` to a whitelisted set of authorized callers (e.g., `onlyIntentGateway`/`onlyHyperApp` style access control), or deploy per-caller/per-order ephemeral dispatcher instances instead of a shared singleton.
- After executing arbitrary calldata, sweep *all* token/ETH balances the dispatcher could plausibly receive, not just the tokens enumerated in `order.output.assets`, or require the calldata's expected output tokens to be declared and enforced.
- Consider adding a reentrancy/ownership guard so that `dispatch()` can only be triggered as part of the same transaction that funded the dispatcher, closing the exposure window entirely.

### Proof of Concept
1. Attacker calls `placeOrder` (or acts as solver in `fillOrder`) with `order.output.call` encoding a `Call[]` that swaps the delivered output token through a path yielding a small amount of a *different* ERC20 (e.g., a DEX reward/referral token) not present in `order.output.assets`. [4](#0-3) 
2. `_execute()` sweeps only the tokens present in `order.output.assets`; the reward token remains in `CallDispatcher`.
3. Attacker (or anyone) calls `CallDispatcher.dispatch()` directly — no access control exists — with a `Call[]` transferring the stranded reward-token balance to their own address. [1](#0-0) 
4. Funds that should have remained protocol dust (or been returned/accounted for) are extracted by an unrelated, unauthorized party from a contract shared with other users' in-flight orders and other Hyperbridge apps.

```text
    function dispatch(bytes memory encoded) external {
        Call[] memory calls = abi.decode(encoded, (Call[]));
        uint256 callsLen = calls.length;
        for (uint256 i = 0; i < callsLen; ++i) {
            Call memory call = calls[i];
            uint32 size;
            address to = call.to;
            assembly {
                size := extcodesize(to)
            }

            if (size == 0) {
                revert NotContract(to);
            }

            (bool success, bytes memory result) = to.call{value: call.value}(call.data);
            if (!success) revert CallFailed(to, result);
        }
    }
```

```text
Both contracts support optional calldata execution on the destination chain via the `CallDispatcher`. By passing a non-empty `data` field in `SendParams`, the sender can trigger arbitrary contract calls on the destination chain immediately after tokens are minted or unlocked. This enables composable cross-chain workflows like transfer-and-swap (e.g., bridge USDC then swap to WETH via UniswapV2), transfer-and-stake, or transfer-and-deposit into a lending protocol — all in a single cross-chain operation.

The `data` field is an ABI-encoded `Call[]` array, where each `Call` specifies a target contract, a native value to forward, and the calldata to execute. On the destination chain, the HFT contract mints or unlocks tokens to the `to` address, then forwards the entire `data` payload to the `CallDispatcher`, which executes each call sequentially. If the calls need to spend the bridged tokens (e.g., approve then swap), set `to` to the `CallDispatcher` address so tokens are delivered directly to it.

For code examples, see the [HyperFungibleToken](/developers/evm/hyper-fungible-token/hyper-fungible-token#calldata-execution) and [WrappedHyperFungibleToken](/developers/evm/hyper-fungible-token/wrapped-hyper-fungible-token#calldata-execution) pages.

### Security

The `CallDispatcher` executes calls in its own context (not via `delegatecall`), so the HFT contract's storage is never at risk. If any call in the array reverts, the entire `onAccept` handler reverts — including the token mint/unlock. The request can then be retried by any relayer until the timeout expires. If no successful execution occurs before the timeout, the request times out and the sender is eligible for a refund on the source chain. Token approvals in the `Call[]` should use exact amounts rather than unlimited allowances, since the dispatcher contract holds tokens temporarily during execution.

Existing `CallDispatcher` deployments are listed on the [contract addresses](/developers/evm/contract-addresses/mainnet) page.
```

```text
    function _execute(Order calldata order, uint256 outputsLen) internal {
        if (order.output.call.length == 0) return;

        address dispatcher = _params.dispatcher;
        ICallDispatcher(dispatcher).dispatch(order.output.call);

        Call[] memory sweepCalls = new Call[](outputsLen);
        uint256 sweepCount = 0;

        for (uint256 i; i < outputsLen;) {
            address token = address(uint160(uint256(order.output.assets[i].token)));

            if (token == address(0)) {
                uint256 balance = dispatcher.balance;
                if (balance > 0) {
                    sweepCalls[sweepCount] = Call({to: address(this), value: balance, data: ""});
                    sweepCount++;
                    emit DustCollected(token, balance);
                }
            } else {
                uint256 balance = IERC20(token).balanceOf(dispatcher);
                if (balance > 0) {
                    sweepCalls[sweepCount] = Call({
                        to: token,
                        value: 0,
                        data: abi.encodeWithSelector(IERC20.transfer.selector, address(this), balance)
                    });
                    sweepCount++;
                    emit DustCollected(token, balance);
                }
            }

            unchecked {
                ++i;
            }
        }
```
