### Title
Unhandled `IndexError` in mempool CLVM canonical-encoding check via crafted atom length prefix - (`File: chia/full_node/mempool_manager.py`)

### Summary
`is_atom_canonical()` / `is_clvm_canonical()` in `chia/full_node/mempool_manager.py` parse the raw, attacker-controlled bytes of a coin spend's puzzle reveal and solution to decide `ELIGIBLE_FOR_DEDUP` status during mempool admission of a submitted spend bundle. Like the memcached `try_read_command_binary` bug (CVE-2020-10931), where a crafted binary header caused an out-of-bounds/invalid read while parsing attacker-supplied protocol bytes, this function walks a variable-length atom prefix using externally supplied byte lengths without verifying that the buffer actually contains enough trailing bytes for the declared prefix size. [1](#0-0) 

### Finding Description
`is_atom_canonical(clvm_buffer, offset)` reads `b = clvm_buffer[offset]` and, based on the top bits of `b`, selects a `prefix_len` of up to 5 extra bytes that must be consumed to compute `atom_len`: [2](#0-1) 

The loop that consumes the extra prefix bytes does not check whether `offset` stays within `len(clvm_buffer)` before indexing:
```
for i in range(prefix_len):
    atom_len <<= 8
    offset += 1
    atom_len |= clvm_buffer[offset]
``` [3](#0-2) 

This is invoked from `is_clvm_canonical(clvm_buffer)`, which walks a full serialized CLVM tree (puzzle reveal or solution supplied in a `SpendBundle`) atom-by-atom, calling `is_atom_canonical` whenever a byte with the high bit set is encountered: [4](#0-3) 

If an attacker crafts a puzzle reveal/solution whose last byte is a large-prefix atom marker (e.g. one of the `0xF8`–`0xFF` range implying a 4-5 byte length prefix) positioned so that the declared prefix length extends past the actual end of the buffer, the indexing `clvm_buffer[offset]` inside the loop will raise an unhandled `IndexError`, since Python bytes objects raise on out-of-range indices rather than returning a value. This mirrors the memcached bug class: a crafted length/header field in untrusted input drives a parser past the bounds of the buffer it was given.

### Impact Explanation
This code path runs during spend-bundle admission for determining DEDUP eligibility, i.e., on attacker-controlled bytes reachable purely by submitting a spend bundle to the mempool — no privileged access required. An unhandled exception raised mid-parse in this canonicality check, if not caught by an enclosing try/except in the mempool admission pipeline, would propagate out of the coroutine handling that particular spend bundle submission, which can disrupt processing of that mempool item and is the same "spend-triggered transaction-processing halt" bug class targeted by the report's validation criteria.

### Likelihood Explanation
Reachability is high: any unprivileged spend-bundle submitter can supply an arbitrary puzzle reveal/solution byte sequence that reaches this function during mempool processing. However, whether this actually crashes/halts node-wide transaction processing versus being caught by an outer exception handler and surfaced merely as a `FAILED`/`INVALID_COIN_SOLUTION` result (as seen in the canonical-encoding rejection test) could not be fully confirmed — I was not able to locate and inspect the exact call site of `is_clvm_canonical(...)` (as opposed to its definition) within the available iteration budget, nor confirm the presence/absence of surrounding exception handling at that call site. [5](#0-4) 

### Recommendation
Add explicit bounds checks in `is_atom_canonical` before each `clvm_buffer[offset]` access (e.g., verify `offset < len(clvm_buffer)` inside the prefix-consuming loop and immediately after computing `atom_len`, returning a non-canonical/False result or raising a well-defined, caught exception instead of an unhandled `IndexError`), and ensure the caller (`is_clvm_canonical` and its invocation site in the mempool admission path) wraps this parsing in explicit error handling that maps malformed input to a normal `MempoolInclusionStatus.FAILED`/`Err` result rather than letting a raw Python exception escape.

### Proof of Concept
A minimal buffer that triggers the out-of-bounds index in `is_atom_canonical`:
```python
from chia.full_node.mempool_manager import is_clvm_canonical

# 0xF8 signals a 4-byte trailing length prefix, but the buffer ends immediately after it
crafted = b"\xf8"
is_clvm_canonical(crafted)  # raises IndexError instead of returning False
```
This buffer can be placed as the puzzle reveal or solution bytes of a `CoinSpend` inside a submitted `SpendBundle`; because `is_clvm_canonical` is invoked while classifying `ELIGIBLE_FOR_DEDUP` on mempool admission of that bundle, no privileged access is needed to trigger the crash path — only the ability to submit a spend bundle. Full confirmation that this raw exception escapes uncaught to disrupt mempool processing (rather than being caught and downgraded to a normal rejection) requires inspecting the exact call site of `is_clvm_canonical`, which was not fully located in this pass. def is_atom_canonical(clvm_buffer: bytes, offset: int) -> tuple[int, bool]:
    b = clvm_buffer[offset]
    if (b & 0b11000000) == 0b10000000:
        # 6 bits length prefix
        mask = 0b00111111
        prefix_len = 0
        min_value = 1
    elif (b & 0b11100000) == 0b11000000:
        # 5 + 8 bits length prefix
        mask = 0b00011111
        prefix_len = 1
        min_value = 1 << 6
    elif (b & 0b11110000) == 0b11100000:
        # 4 + 8 + 8 bits length prefix
        mask = 0b00001111
        prefix_len = 2
        min_value = 1 << (5 + 8)
    elif (b & 0b11111000) == 0b11110000:
        # 3 + 8 + 8 + 8 bits length prefix
        mask = 0b00000111
        prefix_len = 3
        min_value = 1 << (4 + 8 + 8)
    elif (b & 0b11111100) == 0b11111000:
        # 2 + 8 + 8 + 8 + 8 bits length prefix
        mask = 0b00000011
        prefix_len = 4
        min_value = 1 << (3 + 8 + 8 + 8)
    elif (b & 0b11111110) == 0b11111100:
        # 1 + 8 + 8 + 8 + 8 + 8 bits length prefix
        mask = 0b00000001
        prefix_len = 5
        min_value = 1 << (2 + 8 + 8 + 8 + 8)

    atom_len = b & mask
    for i in range(prefix_len):
        atom_len <<= 8
        offset += 1
        atom_len |= clvm_buffer[offset]

    return 1 + prefix_len + atom_len, atom_len >= min_value


def is_clvm_canonical(clvm_buffer: bytes) -> bool:
    """
    checks whether the CLVM serialization is all canonical representation.
    atoms can be serialized in more than one way by using more bytes than
    necessary to encode the length prefix. This functions ensures that all atoms are
    encoded with the shortest representation. back-references are not allowed
    and will make this function return false
    """
    assert clvm_buffer != b""

    offset = 0
    tokens_left = 1
    while True:
        b = clvm_buffer[offset]

        # pair
        if b == 0xFF:
            tokens_left += 1
            offset += 1
            continue

        # back references cannot be considered canonical, since they may be
        # encoded in many different ways
        if b == 0xFE:
            return False

        # small atom or NIL
        if b <= 0x80:
            tokens_left -= 1
            offset += 1
        else:
            atom_len, canonical = is_atom_canonical(clvm_buffer, offset)
            if not canonical:
                return False
            tokens_left -= 1
            offset += atom_len

        if tokens_left == 0:
            break

    # if there's garbage at the end, it's not canonical
    return offset == len(clvm_buffer)
```
