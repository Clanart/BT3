## Analysis Summary

The LamboVEthRouter bug is about a contract that accepts ETH via `receive()` and refunds "most" of it but leaves small rounding/dust residues permanently stuck with no sweep mechanism. I searched Hyperbridge's EVM contracts for the same class of bug (a contract that can accumulate value with no way to retrieve it) and found something structurally worse: `CallDispatcher` — the shared, untrusted-call-forwarding contract used by `IntentGatewayV2`'s predispatch/postdispatch flows — not only lacks a sweep function, its only fund-moving function (`dispatch`) has **zero access control**, turning any stranded balance into a theft vector rather than merely a lock.

### Title
Unswept predispatch-asset dust in the shared `CallDispatcher` is stealable via its unauthenticated `dispatch()` - (File: `evm/src/utils/CallDispatcher.sol`)

### Summary
`IntentGatewayV2.placeOrder`'s predispatch flow sends `order.predispatch.assets` (which may be a *different* token/ETH than `order.inputs`, e.g. ETH swapped into DAI) to the shared `CallDispatcher`, executes arbitrary swap calldata, then sweeps back only the tokens listed in `order.inputs`. Any leftover balance of a predispatch asset that is not itself one of the `order.inputs` tokens is never swept and remains stranded in `CallDispatcher`. Because `CallDispatcher.dispatch()` has no caller restriction whatsoever, any unprivileged address can call it directly with an arbitrary `Call[]` to move that stranded balance — ETH or ERC20 — to any destination, including themselves.

### Finding Description
In `IntentGatewayV2.sol`, the predispatch path is:
1. Transfer `order.predispatch.assets` (e.g. native ETH) to the dispatcher: [1](#0-0) 
2. Execute arbitrary swap calldata: [2](#0-1) 
3. Build sweep calls **strictly over `order.inputs`**, not over `order.predispatch.assets`: [3](#0-2) 

The docs confirm predispatch assets and order inputs are intentionally different tokens (e.g. "a user sends ETH which the CallDispatcher swaps to DAI on Uniswap, and the resulting DAI is escrowed as the order input") [4](#0-3) . If `order.inputs` does not include the native/ERC20 type used as the predispatch asset (e.g. inputs = `[DAI]` only, not `address(0)`), any ETH left over in the dispatcher after an imperfect/partial swap (slippage, router refund behavior, or crafted calldata) is invisible to the sweep loop and is never collected as dust nor moved back to the gateway.

That stranded balance then sits in `CallDispatcher`, whose only fund-moving entry point is completely public: [5](#0-4) 

`dispatch()` has no `onlyGateway`/`onlyHost` modifier — any address can supply a `Call[]` with `to = attacker-controlled contract` and `value = <stranded balance>`, draining it in a single transaction. The only check is that `to` has code (`extcodesize > 0`), which a trivial attacker contract with a payable fallback satisfies.

### Impact Explanation
This is a direct loss-of-funds / unauthorized-execution path: an unprivileged attacker can drain ETH or ERC-20 dust that legitimately belongs to prior order users (as leftover from their predispatch swap) out of the shared `CallDispatcher`, to an address of the attacker's choosing. Unlike the original LamboVEthRouter report (funds merely irretrievable), here the funds are actively stealable by any caller, with no relayer, prover, admin, or governance actor required — matching the "stealing or loss of funds" and "unauthorized transaction or execution" criteria of the bounty gate.

### Likelihood Explanation
Requires only: (1) a `placeOrder` predispatch flow whose swap calldata doesn't perfectly consume the predispatch asset and where `order.inputs` doesn't happen to include that asset's token type, and (2) any observer to notice the resulting non-zero balance on the well-known `CallDispatcher` address and call `dispatch()` directly. Both are realistic in a live intent-fulfillment system where predispatch calldata routes through external DEXes subject to slippage/partial fills, and `CallDispatcher` is a single shared, publicly-known contract address reused across all orders and apps registered with the same dispatcher.

### Recommendation
- Add caller restriction to `CallDispatcher.dispatch()` (e.g., only the registered `IntentGatewayV2`/host, or per-call an authorized invoker), so that even if a balance is stranded, third parties cannot redirect it.
- In the predispatch sweep logic, sweep the *full* set of tokens present in `order.predispatch.assets` (not only `order.inputs`) back to the gateway, and emit `DustCollected` for any non-input-matching leftovers, mirroring the treatment already given to `order.output` dust in `_execute`.
- Alternatively/additionally, add a governance-gated sweep function on `CallDispatcher` itself, consistent with the `SweepDust` mechanism already implemented for `IntentGatewayV2`.

### Proof of Concept
1. User places an order with `predispatch.assets = [{token: address(0), amount: 1 ether}]` and `predispatch.call` that swaps ETH→DAI via a router, but only spends 0.9 ETH due to slippage protection, leaving 0.1 ETH sitting in `CallDispatcher`.
2. `order.inputs = [{token: DAI, amount: X}]` — no native-token entry, so the sweep loop (`evm/src/apps/IntentGatewayV2.sol:232-256`) only sweeps DAI balance back to the gateway; the 0.1 ETH residue in `CallDispatcher` is never touched.
3. Attacker deploys a trivial contract `Sink` with a payable fallback, then calls:
   `CallDispatcher.dispatch(abi.encode([Call({to: address(Sink), value: 0.1 ether, data: ""})]))`
   directly (no permission check exists), draining the stranded ETH to `Sink`. [6](#0-5) [7](#0-6)

```text
### Predispatch

The `predispatch` field in `Order` contains calldata to execute *before* escrowing inputs. The predispatch assets specified in `DispatchInfo.assets` are transferred to the `CallDispatcher`, the encoded calls are executed, and the resulting tokens are transferred back to the gateway for escrow. This enables swap-then-escrow patterns — for example, a user sends ETH which the `CallDispatcher` swaps to DAI on Uniswap, and the resulting DAI is escrowed as the order input.
```

```text
    receive() external payable {}

    /**
     *  @dev reverts if the target is not a contract or if any of the calls reverts.
     */
    function dispatch(bytes memory encoded) external {
        Call[] memory calls = abi.decode(encoded, (Call[]));
        uint256 callsLen = calls.length;
        for (uint256 i = 0; i < callsLen; ++i) {
            Call memory call = calls[i];
            uint32 size;
            address to = call.to;
            assembly {
                size := extcodesize(to)
            }

            if (size == 0) {
                revert NotContract(to);
            }

            (bool success, bytes memory result) = to.call{value: call.value}(call.data);
            if (!success) revert CallFailed(to, result);
        }
    }
```
