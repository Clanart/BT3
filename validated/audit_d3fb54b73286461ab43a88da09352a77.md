### Title
Unchecked type assertion on arbitrary CosmWasm contract query results causes unrecovered panic in pointer precompile's `AddCW20`/`AddCW721`/`AddCW1155` handlers - ([File: precompiles/pointer/pointer.go])

### Summary
The current `pointer` precompile's `AddCW20`, `AddCW721`, and `AddCW1155` handlers query an arbitrary, caller-supplied CosmWasm contract address and then perform unchecked Go type assertions (`formattedRes["name"].(string)`, `formattedRes["symbol"].(string)`) on the JSON response, without validating that the target contract is actually of the expected type/family (CW20/CW721/CW1155). Unlike the netfilter `xt_nat` bug where a target handler assumed IP-family conntrack state existed regardless of the family it was instantiated for, here the pointer precompile assumes any bech32-addressable wasm contract will answer `token_info`/`contract_info` queries with `name`/`symbol` string fields, and panics when that assumption doesn't hold.

### Finding Description
`AddCW20` (and the near-identical `AddCW721`/`AddCW1155`) accept any string-decodable bech32 address as `cwAddr`, without checking that the address is actually a CW20/CW721/CW1155 contract: [1](#0-0) 

The handler queries the contract with a fixed query (`{"token_info":{}}` for CW20, `{"contract_info":{}}` for CW721/CW1155) via `QuerySmartSafe`, unmarshals the raw response into a `map[string]interface{}`, and then performs unchecked type assertions:
```go
name := formattedRes["name"].(string)
symbol := formattedRes["symbol"].(string)
``` [2](#0-1) [3](#0-2) [4](#0-3) 

If the queried wasm contract is *any* contract that happens to respond successfully to those generic query shapes (e.g., a contract that implements `token_info`/`contract_info` for an unrelated purpose, or a contract deliberately crafted by an attacker to return `{"name": 123}` or `{"symbol": null}` or to omit these keys entirely), the type assertion on a non-string (or nil, when the key is absent) value panics.

Critically, `pointer.PrecompileExecutor.Execute` has **no `recover()` wrapper**, unlike other precompiles in this codebase that explicitly guard against this exact class of bug. For comparison, `addr`, `slashing`, and `solo` precompiles all wrap their `Execute` methods with a panic-recovering `defer`: [5](#0-4) [6](#0-5) [7](#0-6) 

The pointer precompile's `Execute` has no such guard: [8](#0-7) 

Nor does the outer `DynamicGasPrecompile.RunAndCalculateGas` (which wraps `Execute`) recover from generic panics — its `defer` only calls `HandlePrecompileError` on a returned `err`, which is never populated for a panic that unwinds past it: [9](#0-8) 

Note the project's own integration tests explicitly assert that precompile failures must never surface as an unrecovered Go panic, treating any observed panic as "a consensus-relevant unhandled error path" — this is exactly the invariant this bug violates: [10](#0-9) 

### Impact Explanation
This matches the CVE's root cause pattern: a target/handler dereferences (here, type-asserts) state that is only guaranteed to exist for the type/family it expects, but is reachable and invocable for other, unvalidated types. Any unprivileged EVM caller can invoke `pointer.addCW20Pointer(cwAddr)` (or the CW721/CW1155 equivalents) against a contract address they do not control the type of. If a Go panic escapes unrecovered through the precompile's static-precompiled-contract call path (`vm.RunPrecompiledContract`), it propagates out of the EVM interpreter and up through `ApplyMessage`/`DeliverTx`, which is not designed to gracefully recover application-level panics originating deep in precompile execution outside the anticipated OOG-panic path (the codebase's `SetUpContextDecorator` only recovers `sdk.ErrorOutOfGas`, re-panicking anything else). This can crash/halt the validator or full node processing that transaction, which the rules classify as a validator halt / block delay — a High-severity, consensus-relevant impact.

### Likelihood Explanation
Likelihood is high: any account can deploy a trivial CosmWasm contract that responds to `token_info`/`contract_info` queries with non-string or missing `name`/`symbol` fields, then call `addCW20Pointer`/`addCW721Pointer`/`addCW1155Pointer` against it through a standard EVM transaction. No special privileges, precompile allowlisting, or governance action is required — this is a straightforward, single-transaction trigger from a public RPC client interacting with the `pointer` precompile at `0x100b`.

### Recommendation
- Wrap `pointer.PrecompileExecutor.Execute` (and the `AddCW20`/`AddCW721`/`AddCW1155` handlers) in the same `defer recover()` pattern already used by `addr`, `slashing`, and `solo` precompiles, converting any panic into a returned `execution reverted` error.
- Additionally (defense in depth, matching the CVE's own fix direction of validating the "family" before trusting type-specific state), validate the JSON response shape explicitly — e.g., use `formattedRes["name"], ok := formattedRes["name"].(string); if !ok { return error }` — rather than relying on unchecked type assertions for attacker-influenced wasm query results across all three pointer-family handlers (CW20/CW721/CW1155) and their legacy versions under `precompiles/pointer/legacy/**`.

### Proof of Concept
1. As any funded account, instantiate a minimal CosmWasm contract whose `token_info` query handler (or `contract_info`, for the CW721/CW1155 path) returns valid JSON but with a non-string or absent `name`/`symbol` field, e.g. `{"name": 12345, "decimals": 0, "total_supply": "0"}`.
2. From an EVM account, call `pointer.addCW20Pointer(<contract_bech32_address>)` on precompile `0x000000000000000000000000000000000000100b`.
3. Execution reaches `PrecompileExecutor.AddCW20`, successfully unmarshals the JSON, then executes `name := formattedRes["name"].(string)`, which panics because the underlying value is a `float64`, not a `string`.
4. Because neither `Execute` nor `RunAndCalculateGas` recovers from this panic, it propagates out of the precompile call and out of the EVM interpreter's call stack for that transaction, crashing/halting processing of that transaction on every node applying it (in contrast to the intended, tested behavior of surfacing `execution reverted` without ever panicking, as codified in `integration_test/precompile_tests/utils/precompileUtils.ts`).

func (d DynamicGasPrecompile) RunAndCalculateGas(evm *vm.EVM, caller common.Address, callingContract common.Address, input []byte, suppliedGas uint64, value *big.Int, hooks *tracing.Hooks, readOnly bool, isFromDelegateCall bool) (ret []byte, remainingGas uint64, err error) {
	operation := fmt.Sprintf("%s_unknown", d.name)
	defer func() {
		HandlePrecompileError(err, evm, operation)
		if err != nil {
			fmt.Printf("precompile %s encountered error: %v\n", d.name, err)
			err = vm.ErrExecutionReverted
		}
	}()
	ctxer := state.GetDBImpl(evm.StateDB)
	if ctxer == nil {
		return nil, 0, errors.New("cannot get context from EVM")
	}
	// Resolve the target method from the 4-byte selector only. The argument
	// payload is intentionally NOT decoded yet: ABI decoding of attacker-
	// controlled calldata can cost far more than len(input) (a single string can
	// be referenced by many array/tuple slots), so it must be paid for out of the
	// gas the caller supplied. The static-precompile path charges RequiredGas in
	// vm.RunPrecompiledContract before running; that step is skipped for
	// dynamic-gas precompiles, so we apply the equivalent charge here.
	methodID, err := ExtractMethodID(input)
	if err != nil {
		return nil, 0, err
	}
	method, err := d.MethodById(methodID)
	if err != nil {
		return nil, 0, err
	}
	operation = method.Name

	ctx := ctxer.Ctx()
	// Install the gas meter derived from the supplied EVM gas, then charge for
	// decoding the calldata BEFORE decoding it. A call that cannot afford the
	// decode is rejected here, before the parse/allocation work is performed.
	// chargeDecodeGas scopes the out-of-gas recovery to just these charges, so an
	// executor that later exhausts its gas keeps its normal (propagating)
	// out-of-gas semantics.
	gasLimit := d.executor.EVMKeeper().GetCosmosGasLimitFromEVMGas(ctx.WithGasMeter(sdk.NewInfiniteGasMeterWithMultiplier(ctx)), suppliedGas)
	ctx = ctx.WithGasMeter(sdk.NewGasMeterWithMultiplier(ctx, gasLimit))
	if err = d.chargeDecodeGas(ctx, method, input); err != nil {
		return nil, 0, err
	}

	args, err := method.Inputs.Unpack(input[4:])
	if err != nil {
		return nil, 0, err
	}
	em := ctx.EventManager()
	ctx = ctx.WithEventManager(sdk.NewEventManager())
	ctx = ctx.WithEVMPrecompileCalledFromDelegateCall(isFromDelegateCall)
	ret, remainingGas, err = d.executor.Execute(ctx, method, caller, callingContract, args, value, readOnly, evm, suppliedGas, hooks)
	if err != nil {
		return ret, remainingGas, err
	}
	events := ctx.EventManager().Events()
	if len(events) > 0 {
		em.EmitEvents(ctx.EventManager().Events())
	}
	return ret, remainingGas, err
}

/**
 * The load-bearing legacy assertion: a precompile that runs out of gas mid-execution
 * must surface as a plain EVM "execution reverted" in traces — never as a Go panic
 * (a "panic occurred" trace would mean a consensus-relevant unhandled error path).
 */
export async function expectTraceRevertedNotPanicked(txHash: string): Promise<void> {
    const trace = await traceTransaction(txHash);
    const error = trace.error ?? '';
    expect(error, `trace of ${txHash} must carry an error`).to.not.equal('');
    expect(error, 'precompile failure must not surface as a panic').to.not.include('panic');
    expect(error, 'precompile failure must trace as an execution revert').to.include(
        'execution reverted',
    );
}
