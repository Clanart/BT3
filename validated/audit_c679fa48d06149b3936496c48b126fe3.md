### Title
Attacker-controlled `WWW-Authenticate` realm spoofing triggers GitHub Enterprise sign-in flow against attacker's host, enabling credential exfiltration - (File: app/src/lib/trampoline/trampoline-credential-helper.ts)

### Summary
GitHub Desktop's Git credential helper trampoline classifies an unknown remote host as GitHub Enterprise (`'enterprise'`) using a heuristic derived from response headers Git forwards to the helper, without ever validating that the host is actually GitHub-compatible. A malicious server acting as a `git remote` (or an HTTP/HTTPS proxy/MITM) can trivially satisfy this heuristic and cause Desktop to launch its full Enterprise "Sign in" popup pointed at the attacker's `origin`, prompting the user to authenticate as if to a genuine GHES instance.

### Finding Description
In `getEndpointKind`, when neither `isDotCom` nor `isGHE` match the credential's URL, Desktop inspects the `wwwauth[]` credential fields (which are populated directly from the `WWW-Authenticate` header the remote server sent, via `parseCredential`) and classifies the endpoint as `'enterprise'` purely because the header text contains `realm="GitHub"`: [1](#0-0) 

This classification decision is the "version"-style branch equivalent to the Conic Finance `interfaceVersion_` bug: it decides which handling code path is exercised (`'github.com' | 'ghe.com' | 'enterprise' | 'generic'`), and it is derived from **untrusted, attacker-supplied input** — an HTTP response header from the remote/proxy the user is fetching/pushing to — rather than any cryptographic or DNS-based verification of the host's authenticity.

If `getEndpointKind` returns `'enterprise'` and no existing account matches the endpoint, `getCredential` immediately prompts a full GitHub sign-in flow instead of the generic credential dialog: [2](#0-1) 

`promptForGitHubSignIn` then treats the attacker's `origin` as a legitimate GHES base URL and starts the enterprise OAuth/sign-in flow against it: [3](#0-2) 

The `getEndpointKind` fallback path also performs an actual network probe (`isGitHubHost`) which similarly trusts response headers (`x-github-request-id`) and a `/meta` endpoint response from the attacker's own server to decide trust: [4](#0-3) 

None of these checks validate a certificate chain tied to a known GitHub/GHES identity, a pinned domain suffix, or any out-of-band trust anchor — they rely entirely on content the remote server chooses to send back.

### Impact Explanation
An attacker who controls a git remote endpoint (e.g., a malicious `http(s)://` remote a victim is instructed/lured to clone/fetch/push to, or a MITM/corporate-proxy-like intermediary) can respond to Git's credential probe with a crafted `WWW-Authenticate: realm="GitHub"` header (or otherwise satisfy `isGitHubHost`'s header checks). This causes Desktop to display its trusted "Sign in to GitHub Enterprise" dialog pointed at the attacker's server. A user who completes this flow believing it is a legitimate GHES/OAuth login can have their credentials or OAuth authorization code sent to the attacker's server, since Desktop is now directing the entire sign-in exchange (`dispatcher.setSignInEndpoint(origin)` / `beginEnterpriseSignIn`) at attacker infrastructure. This matches the "unauthorized OAuth/account binding" and "credential/token exfiltration" impact classes, driven purely by an attacker-controlled remote/proxy response — no local access, malware, or leaked credentials required.

### Likelihood Explanation
Likelihood is moderate: it requires the victim to interact with a malicious/compromised git remote (clone, fetch, or push) that answers the credential probe with a crafted header, and then to proceed through the resulting sign-in popup. Both conditions are within the normal, expected user workflow of adding/using a new remote in Desktop — no unusual steps are needed from the user beyond what they would already do to use a new Git host. Because the header value is used verbatim from the remote's own response with only a `.includes('realm="GitHub"')` substring check, spoofing is trivial for an attacker running or intercepting the HTTP endpoint.

### Recommendation
Do not derive trust ("enterprise"/"GitHub host") classification from content controlled by the remote server (`WWW-Authenticate` header substrings, `/meta` response headers). Only treat a host as GitHub Enterprise if it is an endpoint the user has explicitly registered/signed into before (i.e., rely solely on `findGitHubTrampolineAccount`/known accounts), or require a stronger, harder-to-spoof signal (e.g., valid GHES manifest signed/verified through the account-setup flow) before offering the Enterprise sign-in popup. At minimum, surface a clear warning naming the actual host/origin being signed into before invoking `beginEnterpriseSignIn`, so users aren't misled into authenticating against unfamiliar infrastructure based solely on heuristics.

### Proof of Concept
1. Attacker stands up an HTTP server at `https://evil.example.com/some-repo.git` (or MITMs an HTTP proxy for a corporate remote).
2. Victim adds this URL as a remote in GitHub Desktop and performs a fetch/push; Git invokes the credential helper.
3. The attacker's server responds to the unauthenticated request with `WWW-Authenticate: Basic realm="GitHub"` (or any header substring matching `/realm="GitHub"/`).
4. `parseCredential` captures this as `wwwauth[0]=...realm="GitHub"...` and passes it to `getEndpointKind`, which returns `'enterprise'` at line 159 of `trampoline-credential-helper.ts`. [5](#0-4) 
5. Since no account exists for `evil.example.com`, `getCredential` calls `ui.promptForGitHubSignIn('https://evil.example.com')`.
6. Desktop's UI opens the standard "Sign in to GitHub Enterprise" dialog with `setSignInEndpoint('https://evil.example.com')`, and the user, trusting the familiar dialog, completes authentication against the attacker's server.

/** Implementation of the 'get' git credential helper command */
async function getCredential(cred: Credential, store: Store, token: string) {
  const ghCred = await getGitHubCredential(cred, store)

  if (ghCred) {
    return ghCred
  }

  const endpointKind = await getEndpointKind(cred, store)
  const accounts = await store.getAll()

  const endpoint = `${getCredentialUrl(cred)}`
  const apiEndpoint = getAPIEndpoint(endpoint)

  // If it appears as if the endpoint is a GitHub host and we don't have an
  // account for that endpoint then we should prompt the user to sign in.
  if (
    endpointKind !== 'generic' &&
    !accounts.some(a => a.endpoint === apiEndpoint)
  ) {
    if (getIsBackgroundTaskEnvironment(token)) {
      debug('background task environment, skipping prompt')
      return undefined
    }

    const account = await ui.promptForGitHubSignIn(endpoint)

    if (!account) {
      setHasRejectedCredentialsForEndpoint(token, endpoint)
    }

    return credWithAccount(cred, account)
  }

/**
 * Attempts to determine whether or not the url belongs to a GitHub host.
 *
 * This is a best-effort attempt and may return `undefined` if encountering
 * an error making the discovery request
 */
export async function isGitHubHost(url: string) {
  const { hostname } = new window.URL(url)

  const endpoint =
    hostname === 'github.com' || hostname === 'api.github.com'
      ? getDotComAPIEndpoint()
      : getEnterpriseAPIURL(url)

  if (isDotCom(endpoint) || isGHE(endpoint)) {
    return true
  }

  if (isKnownThirdPartyHost(hostname)) {
    return false
  }

  // github.example.com,
  if (/(^|\.)(github)\./.test(hostname)) {
    return true
  }

  // bitbucket.example.com, etc
  if (/(^|\.)(bitbucket|gitlab)\./.test(hostname)) {
    return false
  }

  if (getEndpointVersion(endpoint) !== null) {
    return true
  }

  // Add a unique identifier to the URL to make sure our certificate error
  // supression only catches this request
  const metaUrl = `${endpoint}/meta?ghd=${crypto.randomUUID()}`

  const ac = new AbortController()
  const timeoutId = setTimeout(() => ac.abort(), 2000)
  suppressCertificateErrorFor(metaUrl)
  try {
    const response = await fetch(metaUrl, {
      headers: { 'user-agent': getUserAgent() },
      signal: ac.signal,
      credentials: 'omit',
      method: 'HEAD',
      redirect: 'error',
    })

    tryUpdateEndpointVersionFromResponse(endpoint, response)

    return response.headers.has('x-github-request-id')
  } catch (e) {
    log.debug(`isGitHubHost: failed with endpoint ${endpoint}`, e)
    return undefined
  } finally {
    clearTimeout(timeoutId)
    clearCertificateErrorSuppressionFor(metaUrl)
  }
}
