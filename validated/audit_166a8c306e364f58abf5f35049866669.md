### Title
Uncontrolled Recursion in `PuzzleWithRestrictions.from_memo` when parsing attacker-crafted custody/PlotNFT memos - ([File: chia/wallet/puzzles/custody/custody_architecture.py])

### Summary
`PuzzleWithRestrictions.from_memo()` recursively reconstructs a MofN custody tree from a CREATE_COIN memo blob without any depth bound, mirroring the Apache Commons Lang `ClassUtils.getClass()` bug class (CWE-674, GHSA-j288-q9x7-2f5v): unbounded recursion driven by attacker-controlled input length/nesting can exhaust the Python call stack and raise an unhandled `RecursionError`, crashing the process that parses it.

### Finding Description
`PuzzleWithRestrictions.from_memo()` in `chia/wallet/puzzles/custody/custody_architecture.py` parses a `Program` memo and, whenever the memo indicates `further_branching` (i.e. the puzzle is a `MofN`), recursively calls itself for every member listed in `MofNHint.member_memos`: [1](#0-0) 

Each member's memo may itself encode another `MofN`, so the recursion depth is bounded only by how deeply the memo `Program` is nested — a value entirely controlled by whoever creates the coin (the memo is emitted verbatim inside a `CREATE_COIN` condition of a spend). Related methods `unknown_puzzles` and `fill_in_unknown_puzzles` on the same class perform equivalent unbounded recursion over the `MofN` member tree: [2](#0-1) 

This is reachable from a completely passive/legitimate flow: `PlotNFT.get_next_from_coin_spend()` in `chia/pools/plotnft_drivers.py` calls `PuzzleWithRestrictions.from_memo(singleton_create_coin.memo_blob.rest())` while syncing a plotnft singleton whose memo could not be resolved by any faster path, and this is invoked from `chia/wallet/plotnft_wallet/plotnft_wallet.py` during normal pool-wallet coin-state sync: [3](#0-2) 

Unlike CLVM execution, which is naturally rate-limited by cost accounting, this parsing happens entirely in pure Python *after* the CLVM has already run, so there is no cost-based ceiling on how many `from_memo` recursive calls occur — only the size of the memo blob (limited indirectly by the generator/spend size limits, but still large enough on mainnet to build thousands of nested MofN levels well beyond Python's default recursion limit of ~1000).

Contrast this with `chia/types/blockchain_format/tree_hash.py`, where the same category of tree traversal was deliberately rewritten as an explicit stack-based loop specifically "so we don't have to worry about blowing out the python stack" — showing the codebase is otherwise aware of and mitigates this exact bug class, but the custody/PlotNFT memo parser was not likewise hardened.

### Impact Explanation
An attacker who creates a plotnft (or generic `PuzzleWithRestrictions`-based custody) singleton coin with a maliciously deep `MofN` memo structure can cause any wallet that later syncs and attempts to interpret that coin's memo (e.g. a pool-wallet client tracking plotnft state transitions) to hit Python's recursion limit and raise `RecursionError`, which is an uncaught exception in this code path (only `ValueError` is caught around `from_memo` in `plotnft_drivers.py`). This halts the wallet's coin-processing/sync task for anyone who encounters the coin, matching the "spend-triggered transaction-processing halt" impact criterion. Because plotnft coins are broadly visible to pool wallet clients monitoring pool state, this can be triggered without any interaction from the victim beyond normal chain sync.

### Likelihood Explanation
Medium. Exploitation requires crafting and getting a coin spend (creating the malicious memo) accepted on-chain — no special privileges are needed to create such a coin, and CREATE_COIN memos are essentially free-form data (subject to CLVM cost of building the memo program, which is cheap relative to the depth needed to exceed Python's default recursion limit). The victim's wallet must subsequently process that specific coin via the PlotNFT/pool-wallet sync path (`get_next_from_coin_spend`) which is only invoked in certain unresolved-memo situations, somewhat limiting automatic universal exposure, but it is a standard code path triggered by ordinary sync logic, not by any privileged or attacker-controlled network position.

### Recommendation
Convert `PuzzleWithRestrictions.from_memo`, `unknown_puzzles`, and `fill_in_unknown_puzzles` to iterative (stack/queue-based) traversal, or impose an explicit maximum recursion/nesting depth (rejecting memos that exceed it with a normal `ValueError` rather than letting Python's interpreter raise `RecursionError`). Ensure all callers (e.g. `plotnft_drivers.py`) also catch `RecursionError` defensively as a stop-gap while the traversal is being converted to non-recursive form.

### Proof of Concept
1. Construct a `Program` memo of the form used by `PuzzleWithRestrictions.memo()`, where the puzzle field recursively nests `MofN` hints many thousands of levels deep (each level being an `m=1` `MofNHint` wrapping a single member whose memo is itself another such nested `MofN` memo).
2. Embed this memo as the memo of a `CREATE_COIN` condition in a plotnft/custody-architecture singleton spend and get it accepted into a block (this is ordinary user-controlled data, not consensus-restricted).
3. Have any wallet call `PlotNFT.get_next_from_coin_spend()` (or otherwise call `PuzzleWithRestrictions.from_memo()`) on that coin's spend, e.g. via normal PlotNFT wallet sync in `chia/wallet/plotnft_wallet/plotnft_wallet.py`.
4. Observe `RecursionError` propagate out of `from_memo`'s self-recursive call chain, which is not caught by the surrounding `except ValueError` in `chia/pools/plotnft_drivers.py`, terminating/erroring the wallet's coin-processing task.

    @classmethod
    def from_memo(cls, memo: Program) -> PuzzleWithRestrictions:
        if memo.atom is not None or memo.first() != Program.to(cls.spec_namespace):
            raise ValueError("Attempting to parse a memo that does not belong to this spec")
        nonce = memo.at("rf")
        restriction_hints_prog = memo.at("rrf")
        further_branching_prog = memo.at("rrrf")
        puzzle_hint_prog = memo.at("rrrrf")
        additional_memos = memo.at("rrrrrf") if memo.at("rrrrr").atom is None else None
        restriction_hints = [RestrictionHint.from_program(hint) for hint in restriction_hints_prog.as_iter()]
        further_branching = further_branching_prog != Program.to(None)
        if further_branching:
            m_of_n_hint = MofNHint.from_program(puzzle_hint_prog)
            puzzle: MIPSComponent = MofN(
                m=m_of_n_hint.m, members=[PuzzleWithRestrictions.from_memo(memo) for memo in m_of_n_hint.member_memos]
            )
        else:
            puzzle_hint = MemberHint.from_program(puzzle_hint_prog)
            puzzle = UnknownMember(puzzle_hint)

        return PuzzleWithRestrictions(
            nonce=nonce.as_int(),
            restrictions=[UnknownRestriction(hint) for hint in restriction_hints],
            puzzle=puzzle,
            additional_memos=additional_memos,
        )
