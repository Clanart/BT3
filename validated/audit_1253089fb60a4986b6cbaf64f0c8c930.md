### Title
Missing binding between payout transaction output value/script and withdrawal amount enables reimbursement without funding the withdrawer - (File: circuits-lib/src/bridge_circuit/mod.rs)

### Summary
`bridge_circuit` never inspects any `TxOut.value`/`script_pubkey` of the payout transaction to confirm the withdrawer was actually paid the registered withdrawal amount. It only checks that the OP_RETURN-derived `operator_xonlypk` is folded into `deposit_constant`, and that one specific *input* of the payout transaction spends `(user_wd_outpoint, vout)`. Since neither check inspects any output paid to the withdrawer, an operator can construct a payout transaction that satisfies both checks while paying the withdrawer nothing (or dust), and still get a valid journal hash that anchors a Reimburse claim.

### Finding Description
The binding that should hold is: `value_and_script(output paid to withdrawer in payout_spv.transaction) == withdrawal_amount/script registered for (user_wd_outpoint, vout)`. Tracing `bridge_circuit` (mod.rs lines 137-245):

- `verify_storage_proofs` returns `(user_wd_outpoint, vout, move_txid)` from Citrea storage proofs [1](#0-0) . These values are only a txid/vout, no amount or script is retrieved anywhere in `verify_storage_proofs` [2](#0-1) .
- The circuit asserts that `input[payout_input_index].previous_output` of the payout transaction equals `(user_wd_outpoint, vout)` — i.e. that the payout tx *spends* this outpoint as an input, not that it *pays* anything to the withdrawer [3](#0-2) .
- `get_first_op_return_output` picks the first OP_RETURN output of the payout tx and is used solely to extract `operator_xonlypk` via `parse_op_return_data`, which then feeds `deposit_constant` [4](#0-3) .
- Nowhere in `bridge_circuit`, `deposit_constant`, or `journal_hash` is any `TxOut.value` or `script_pubkey` of `input.payout_spv.transaction.output` compared to a withdrawal amount or a withdrawer-owned script [5](#0-4) .

The only content check on outputs anywhere in the file targets watchtower challenge transactions, not the payout transaction [6](#0-5) .

Because the equality the question posits (`operator_xonlypk` matches) is orthogonal to "withdrawer received the withdrawal amount," an operator can build a payout transaction that: (1) has a correct OP_RETURN with its own `operator_xonlypk`, (2) spends `(user_wd_outpoint, vout)` at `payout_input_index` (satisfying the two asserts), and (3) sends the real value elsewhere (to itself, to fees, or to a zero-value/dust output), while any additional OP_RETURN or non-OP_RETURN outputs carrying the "real" payment semantics are never inspected for value. `get_first_op_return_output`'s "pick the first OP_RETURN" behavior is a contributing but secondary factor: since no output value check exists at all, even a single well-formed OP_RETURN plus a zero-value withdrawer output is sufficient — the multi-OP_RETURN framing only shows one way an attacker/operator can add noise without affecting the (already absent) verification.

None of the listed guards (`Verifier::is_deposit_valid`, `Operator::is_profitable`, `SECP.verify_schnorr`, `only_aggregator_and_self`, `Verifier::is_kickoff_malicious`, `SPV::verify`, `lc_proof_verifier`, `total_work_and_watchtower_flags`) check payout output value either; `SPV::verify` only proves the transaction's inclusion in the claimed chain, and `verify_storage_proofs` only proves the registered outpoint/vout, not an amount.

### Impact Explanation
This is a Critical-class issue matching "an operator reimbursed for a payout it never funded." If the circuit's journal (which becomes the on-chain-verifiable commitment used to justify the Reimburse transaction) can be produced without any value actually reaching the withdrawer, a malicious operator can claim reimbursement for withdrawal amounts it never fronted. Because `bridge_circuit` is the trust anchor used to compute the journal for every payout across every withdrawal and every operator, this is repeatable per withdrawal and is not confined to a single deposit — it scales to the entire withdrawal/reimbursement flow.

### Likelihood Explanation
Preconditions: a withdrawal must be registered on Citrea with `(user_wd_outpoint, vout)`, which is attacker/operator-controllable input to `withdraw()`. The attacker needs to be the operator processing that withdrawal (an operator role is required to trigger the Reimburse flow built on this journal), and must be able to spend the UTXO at `(user_wd_outpoint, vout)` as an input in their payout transaction (this is generally satisfiable, as this outpoint is simply required to be referenced, not proven to belong to anyone specific inside the circuit) and craft a valid OP_RETURN with its own xonlypk. Cost is limited to standard Bitcoin transaction fees; no majority hashrate, key compromise, or TLS interception is required. This is feasible with only the capabilities explicitly granted to the unprivileged attacker/operator role described.

### Recommendation
Add an explicit equality check in `bridge_circuit` between an output of `input.payout_spv.transaction` and the registered withdrawal amount/destination script (both of which should be retrieved from the Bridge contract's storage proof alongside `(user_wd_outpoint, vout)`), e.g. verify that some `TxOut` in the payout transaction has `script_pubkey == withdrawer_script` and `value >= withdrawal_amount`. This binding must be enforced inside `bridge_circuit` itself, not left to off-circuit assumptions, since the circuit's journal is the trust anchor for reimbursement.

pub fn total_work_and_watchtower_flags(
    circuit_input: &BridgeCircuitInput,
    work_only_image_id: &[u8; 32],
) -> (TotalWork, ChallengeSendingWatchtowers) {
    let watchtower_challenge_set = verify_watchtower_challenges(circuit_input);

    let mut valid_watchtower_challenge_commitments: Vec<WatchTowerChallengeTxCommitment> = vec![];

    for outputs in watchtower_challenge_set.challenge_outputs {
        let compressed_g16_proof: [u8; 128];
        let total_work: [u8; 16];

        match outputs.as_slice() {
            // Single OP_RETURN output with 144 bytes
            [op_return_output, ..] if op_return_output.script_pubkey.is_op_return() => {
                // If the first output is OP_RETURN, we expect a single output with 144 bytes
                let Some(Ok(whole_output)) = parse_op_return_data(&op_return_output.script_pubkey)
                    .map(TryInto::<[u8; 144]>::try_into)
                else {
                    continue;
                };
                compressed_g16_proof = whole_output[0..128]
                    .try_into()
                    .expect("Cannot fail: slicing 128 bytes from 144-byte array");
                total_work = whole_output[128..144]
                    .try_into()
                    .expect("Cannot fail: slicing 16 bytes from 144-byte array");
            }
            // Otherwise, we expect three outputs:
            // 1. [out1, out2, out3] where out1 and out2 are P2TR outputs
            //    and out3 is an OP_RETURN output with 80 bytes
            [out1, out2, out3, ..]
                if out1.script_pubkey.is_p2tr()
                    && out2.script_pubkey.is_p2tr()
                    && out3.script_pubkey.is_op_return() =>
            {
                let first_output: [u8; 32] = out1.script_pubkey.to_bytes()[2..]
                    .try_into()
                    .expect("Cannot fail: slicing 32 bytes from P2TR output");
                let second_output: [u8; 32] = out2.script_pubkey.to_bytes()[2..]
                    .try_into()
                    .expect("Cannot fail: slicing 32 bytes from P2TR output");

                let Some(Ok(third_output)) =
                    parse_op_return_data(&out3.script_pubkey).map(TryInto::<[u8; 80]>::try_into)
                else {
                    continue;
                };

                compressed_g16_proof =
                    [&first_output[..], &second_output[..], &third_output[0..64]]
                        .concat()
                        .try_into()
                        .expect("Cannot fail: concatenating and converting to 128-byte array");

                // Borsh deserialization of the final 16 bytes is functionally redundant in this context,
                // as it does not alter the byte content. It is retained here for consistency and defensive safety.
                total_work = borsh::from_slice(&third_output[64..])
                    .expect("Cannot fail: deserializing 16 bytes from 16-byte slice");
            }
            _ => continue,
        }

        let commitment = WatchTowerChallengeTxCommitment {
            compressed_g16_proof,
            total_work,
        };

        valid_watchtower_challenge_commitments.push(commitment);
    }

    valid_watchtower_challenge_commitments.sort_by(|a, b| b.total_work.cmp(&a.total_work));

    let mut total_work_result = [0u8; 16];

    for commitment in valid_watchtower_challenge_commitments {
        if convert_to_groth16_and_verify(
            &commitment.compressed_g16_proof,
            commitment.total_work,
            work_only_image_id,
            circuit_input.hcp.genesis_state_hash,
        ) {
            total_work_result = commitment.total_work;
            break;
        }
    }

    (
        TotalWork(total_work_result),
        ChallengeSendingWatchtowers(watchtower_challenge_set.challenge_senders),
    )
}

pub fn deposit_constant(
    operator_xonlypk: [u8; 32],
    watchtower_challenge_connector_start_idx: u32,
    watchtower_pubkeys: &[[u8; 32]],
    move_txid: [u8; 32],
    round_txid: [u8; 32],
    kickoff_round_vout: u32,
    genesis_state_hash: [u8; 32],
) -> DepositConstant {
    // pubkeys are 32 bytes long
    let pubkey_concat = watchtower_pubkeys
        .iter()
        .flat_map(|pubkey| pubkey.to_vec())
        .collect::<Vec<u8>>();

    let watchtower_pubkeys_digest: [u8; 32] = Sha256::digest(&pubkey_concat).into();

    let pre_deposit_constant = [
        &move_txid,
        &watchtower_pubkeys_digest,
        &operator_xonlypk,
        &watchtower_challenge_connector_start_idx.to_be_bytes()[..],
        &round_txid,
        &kickoff_round_vout.to_be_bytes()[..],
        &genesis_state_hash,
    ]
    .concat();

    DepositConstant(Sha256::digest(&pre_deposit_constant).into())
}

pub fn journal_hash(
    payout_tx_blockhash: PayoutTxBlockhash,
    latest_blockhash: LatestBlockhash,
    challenge_sending_watchtowers: ChallengeSendingWatchtowers,
    deposit_constant: DepositConstant,
) -> blake3::Hash {
    let concatenated_data = [
        payout_tx_blockhash.0,
        latest_blockhash.0,
        challenge_sending_watchtowers.0,
    ]
    .concat();

    let binding = blake3::hash(&concatenated_data);
    let hash_bytes = binding.as_bytes();

    let concat_journal = [deposit_constant.0, *hash_bytes].concat();

    blake3::hash(&concat_journal)
}

pub fn verify_storage_proofs(
    storage_proof: &StorageProof,
    state_root: [u8; 32],
) -> (WithdrawalOutpointTxid, u32, MoveTxid) {
    let utxo_storage_proof: EIP1186StorageProof =
        serde_json::from_str(&storage_proof.storage_proof_utxo)
            .expect("Failed to deserialize UTXO storage proof");

    let vout_storage_proof: EIP1186StorageProof =
        serde_json::from_str(&storage_proof.storage_proof_vout)
            .expect("Failed to deserialize vout storage proof");

    let deposit_storage_proof: EIP1186StorageProof =
        serde_json::from_str(&storage_proof.storage_proof_deposit_txid)
            .expect("Failed to deserialize deposit storage proof");

    let storage_address: U256 = {
        let mut keccak = Keccak256::new();
        keccak.update(UTXOS_STORAGE_INDEX);
        let hash = keccak.finalize();
        U256::from_be_bytes(
            <[u8; 32]>::try_from(&hash[..]).expect("Hash slice has incorrect length"),
        )
    };

    let storage_key_utxo: alloy_primitives::Uint<256, 4> =
        storage_address + U256::from(storage_proof.index * 2);

    let storage_key_vout: alloy_primitives::Uint<256, 4> =
        storage_address + U256::from(storage_proof.index * 2 + 1);

    let storage_address_deposit: U256 = {
        let mut keccak = Keccak256::new();
        keccak.update(DEPOSIT_STORAGE_INDEX);
        let hash = keccak.finalize();
        U256::from_be_bytes(
            <[u8; 32]>::try_from(&hash[..]).expect("Hash slice has incorrect length"),
        )
    };

    let deposit_storage_key: alloy_primitives::Uint<256, 4> =
        storage_address_deposit + U256::from(storage_proof.index);

    let deposit_storage_key_bytes = deposit_storage_key.to_be_bytes::<32>();

    if deposit_storage_key_bytes != deposit_storage_proof.key.as_b256().0 {
        panic!(
            "Invalid deposit storage key. left: {:?} right: {:?}",
            deposit_storage_key_bytes,
            deposit_storage_proof.key.as_b256().0
        );
    }

    if storage_key_utxo.to_be_bytes() != utxo_storage_proof.key.as_b256().0 {
        panic!(
            "Invalid withdrawal UTXO storage key. left: {:?} right: {:?}",
            storage_key_utxo.to_be_bytes::<32>(),
            utxo_storage_proof.key.as_b256().0
        );
    }

    if storage_key_vout.to_be_bytes() != vout_storage_proof.key.as_b256().0 {
        panic!(
            "Invalid withdrawal vout storage key. left: {:?} right: {:?}",
            storage_key_vout.to_be_bytes::<32>(),
            vout_storage_proof.key.as_b256().0
        );
    }

    storage_verify(&utxo_storage_proof, state_root);

    storage_verify(&deposit_storage_proof, state_root);

    storage_verify(&vout_storage_proof, state_root);

    let buf: [u8; 32] = vout_storage_proof.value.to_be_bytes();

    // ENDIANNESS SHOULD BE CHECKED THIS FIELD IS 4 BYTES in the contract
    let vout = u32::from_le_bytes(
        buf[28..32]
            .try_into()
            .expect("Vout value conversion failed"),
    );

    let wd_outpoint = WithdrawalOutpointTxid(utxo_storage_proof.value.to_be_bytes());

    let move_txid = MoveTxid(deposit_storage_proof.value.to_be_bytes());

    (wd_outpoint, vout, move_txid)
}
