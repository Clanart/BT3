### Title
Missing App Proxy Request Freshness/Replay Check Allows Indefinite Reuse of Signed Proxy Requests - (File: `lib/shopify_app/controller_concerns/app_proxy_verification.rb`)

### Summary
`ShopifyApp::AppProxyVerification` verifies the HMAC signature of Shopify App Proxy requests but never validates the `timestamp` query parameter against the current time. Any GET request whose query string (including the `signature`) has ever been valid remains permanently acceptable, regardless of age, mirroring the "stale data accepted" bug class described in the report (failure to verify freshness of an otherwise cryptographically-valid input).

### Finding Description
`verify_proxy_request` only checks whether the HMAC signature matches the query string: [1](#0-0) 

The `timestamp` parameter is present in the signed payload (it is part of `query_hash_without_signature` used to compute the HMAC), but the code never reads or compares it to `Time.now`/`request.query_string` freshness. This is confirmed by the test suite, where a signature computed for `timestamp=1466106083` (year 2016) is asserted valid without any date-based rejection: [2](#0-1) 

Because App Proxy requests are delivered as signed GET URLs (query string, not headers or POST body), they are inherently more prone to leaking through browser history, server access logs, `Referer` headers, shared links, or intermediary proxy logs than a webhook POST payload. Once such a URL is obtained by any party, it remains a permanently valid, "fresh-looking" signed request to the app proxy endpoint, since there is no expiry enforcement analogous to the Chainlink `updatedAt`/heartbeat check recommended in the report.

### Impact Explanation
An attacker who obtains a previously valid App Proxy URL (via logs, browser history, shared/forwarded links, or any partial network exposure) can replay it indefinitely to any app proxy-protected endpoint, since the concern only re-validates the HMAC and never checks the `timestamp` for staleness. This is the accepted-forged/stale-signed-request pattern the rules call out — the request is not actually "forged" cryptographically, but it should have expired and is not rejected, so the app treats old requests as trustworthy shop-context requests indefinitely.

### Likelihood Explanation
Exploitation requires the attacker to have obtained a valid app-proxy URL/signature at some point (e.g., via log access, shared/cached links, or a leaking intermediary), so it is not exploitable by a purely anonymous requester with no prior access. This constrains likelihood compared to a full authentication bypass, but the absence of any timestamp/freshness check is a concrete, verifiable gap in the implementation as it stands, matching the report's underlying bug class.

### Recommendation
In `query_string_valid?`/`verify_proxy_request`, after confirming the HMAC is valid, parse the `timestamp` parameter and reject the request if `Time.now.to_i - timestamp.to_i` exceeds a defined freshness window (e.g., a few minutes), similar to Shopify's own guidance for App Proxy and OAuth `state`/`timestamp` validation, and consistent with the report's "verify price freshness" recommendation (compare a timestamp field against `block.timestamp`/`Time.now` against a defined heartbeat/tolerance).

### Proof of Concept
1. Capture (via logs, browser history, or a shared link) a previously valid app proxy request URL such as:
`GET /app_proxy/basic?shop=some-random-store.myshopify.com&path_prefix=%2Fapps%2Fmy-app&timestamp=1466106083&signature=f5cd7233558b1c50102a6f33c0b63ad1e1072a2fc126cb58d4500f75223cefcd`
2. Replay this exact URL at any later time (as demonstrated by the passing test using a 2016 timestamp): [2](#0-1) 
3. The request is accepted (`assert_response :ok`) with no check that the `timestamp` is current, confirming the missing freshness validation in `lib/shopify_app/controller_concerns/app_proxy_verification.rb`.

```ruby
    def verify_proxy_request
      head(:forbidden) unless query_string_valid?(request.query_string)
    end

    private

    def query_string_valid?(query_string)
      query_hash = Rack::Utils.parse_query(query_string)

      signature = query_hash.delete("signature")
      return false if signature.nil?

      ActiveSupport::SecurityUtils.secure_compare(
        calculated_signature(query_hash),
        signature,
      )
    end
```
