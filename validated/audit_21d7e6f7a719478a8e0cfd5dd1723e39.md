Confirmed: the withdrawal input is a 550-sat dust UTXO belonging to the aggregator/user key [1](#0-0) , signed only with `SinglePlusAnyoneCanPay`, which under BIP-341/BIP-118 rules commits **only** to input 0 and output 0 (the user payout) [2](#0-1) . The anchor output and the OP_RETURN output that names the operator to be credited are outside the signed message and can be freely rewritten by anyone who observes the signature/witness, as long as they supply their own additional inputs to fund the real payout value (`add_inputs: true`, RBF-enabled) [3](#0-2) [4](#0-3) . The verifier side blindly trusts whatever 32 bytes end up in the confirmed transaction's OP_RETURN as the "party that fronted the payout" [5](#0-4) , and this attribution is then used verbatim to decide who is allowed to run the reimbursement/kickoff flow for that deposit [6](#0-5)  and to judge kickoff maliciousness [7](#0-6) .

### Title
Payout OP_RETURN operator attribution is unauthenticated, letting an unprivileged party permanently orphan a withdrawal's reimbursement path - (File: core/src/builder/transaction/operator_reimburse.rs)

### Summary
The payout transaction that fronts a Citrea withdrawal uses `SIGHASH_SINGLE|ANYONECANPAY` on its only signed input, so the OP_RETURN output that records "which operator fronted this payout" is completely unsigned and freely rewritable by any third party who can see the pending transaction and add their own funding inputs.

### Finding Description
`create_payout_txhandler` builds a payout transaction with: input 0 = the withdrawal dust UTXO (spent with `SpendPath::KeySpend` and a user-supplied `SinglePlusAnyoneCanPay` signature), output 0 = the user's payout, output 1 = anchor, output 2 = OP_RETURN with the fronting operator's x-only pubkey [8](#0-7) . `SIGHASH_SINGLE|ANYONECANPAY` on input 0 commits only to input 0 and output 0; the parser explicitly enforces this sighash type [9](#0-8) , and `Operator::withdraw` verifies the signature only against `sighash_txin(0, …)` for that input [10](#0-9) .

The operator broadcasts this tx after funding it with its own bitcoind wallet via `fund_raw_transaction`, explicitly using RBF (`replaceable` left default/RBF-enabled, comment "send payout tx using RBF") [11](#0-10) . Because outputs 1 and 2 (and any additional inputs) are not covered by the user's signature, any party that observes the unconfirmed transaction in the mempool can construct and broadcast a replacement (BIP-125 RBF) transaction that:
- reuses input 0 and output 0 unchanged (so the withdrawal is still correctly paid, the operator's original signature check is satisfied vacuously by anyone),
- supplies its own funding inputs (signed by itself, satisfying "ANYONECANPAY"),
- sets an arbitrary 32-byte value (a garbage/unregistered pubkey, or another operator's pubkey) in the OP_RETURN,
- pays a higher fee to win the replacement race.

When this transaction confirms, the Verifier's block-sync logic extracts the OP_RETURN bytes and stores them verbatim as `payout_payer_operator_xonly_pk`, with no check that this value corresponds to any actual registered operator or to the party that funded the transaction [5](#0-4) [12](#0-11) . This value later gates the entire reimbursement flow: `validate_payer_is_operator` requires `payer_xonly_pk == self.signer.xonly_public_key` before an operator will even attempt kickoff/reimburse transactions [13](#0-12) , and `is_kickoff_malicious` treats any mismatch or missing key as proof of maliciousness [7](#0-6) .

If the OP_RETURN ends up containing a value that matches no real operator (a plausible outcome — any 32-byte string has roughly even odds of parsing as a valid x-only pubkey, and there is no on-chain check it belongs to a registered operator), no operator will ever pass `validate_payer_is_operator`/`is_kickoff_malicious` for that withdrawal's move-to-vault deposit, because the `get_payout_info_from_move_txid` result for that deposit is fixed once `payout_txid`/`payout_tx_blockhash` are non-null [14](#0-13) . The corresponding move-to-vault deposit UTXO can then never be spent through the normal Reimburse flow, which requires this attribution check to succeed.

### Impact Explanation
This breaks the binding "the operator credited versus the party that actually paid": attribution of who fronted a withdrawal is decided solely by unsigned, freely rewritable transaction data. An unprivileged party (no operator, verifier, or other privileged role required) can win an RBF race against a legitimate operator's in-flight payout and rewrite the credited identity to an arbitrary/garbage value. Because the deposit's associated move-to-vault UTXO can only be released through the reimbursement path that depends on this attribution matching a real, registered operator, mis-attribution permanently forecloses the normal reimbursement/spend path for that deposit's vault UTXO — matching the Critical impact category "a vault UTXO permanently frozen." No compromise of any key, node, or role is required; only observing a broadcast, unconfirmed transaction and outbidding its fee.

### Likelihood Explanation
Exploitability requires only: (1) visibility into the mempool for the operator's pending payout transaction (trivial for any network participant, or even more directly if the attacker is the withdrawing user themselves, since they already know the signature they handed to the operator off-chain), and (2) willingness to front the withdrawal amount plus a competitive fee via RBF. No cryptographic secrets, operator credentials, or privileged roles are needed to perform the replacement itself — the attacker only needs enough BTC to cover the payout amount and fee. This makes the attack straightforward to attempt whenever a withdrawal is being processed, though the attacker's fronted BTC is real financial exposure to them, not just a resource-exhaustion play.

### Recommendation
Bind the operator-attribution output to the same signature that authorizes the spend, e.g., require the off-chain user signature to use a sighash type (or an additional signed input/output) that commits to the OP_RETURN output as well (SIGHASH_ALL or SIGHASH_SINGLE indexed appropriately if multiple outputs must be covered), or otherwise cryptographically bind the fronting operator's identity to the transaction before broadcast so it cannot be altered by a competing replacement. Additionally, validate on the verifier side that the parsed OP_RETURN pubkey corresponds to a currently registered operator before persisting it as `payout_payer_operator_xonly_pk`, and provide an explicit recovery/re-attribution path (beyond only the privileged security-council replacement-deposit flow) for withdrawals whose payout confirmed with an unattributable OP_RETURN.

### Proof of Concept
1. Operator A receives the user's `SinglePlusAnyoneCanPay` signature over input 0/output 0 and broadcasts a payout transaction funded from its own wallet with `fund_raw_transaction`/RBF as in `Operator::withdraw` [15](#0-14) .
2. Before it confirms, an unprivileged observer extracts input 0's witness/signature from the mempool transaction.
3. The observer constructs a new transaction spending the same dust UTXO with the same output 0 (so the user is paid correctly and the SIGHASH_SINGLE constraint is satisfied), adds its own funding inputs (self-signed) to cover the payout amount, sets the OP_RETURN to an arbitrary/garbage 32-byte value, and broadcasts with a higher fee to replace Operator A's transaction via RBF.
4. Once confirmed, `update_finalized_payouts` records this garbage value as `payout_payer_operator_xonly_pk` for the withdrawal [16](#0-15) .
5. No registered operator's `xonly_public_key` will ever equal this stored value, so `validate_payer_is_operator` permanently fails for this deposit [13](#0-12) , and the corresponding move-to-vault UTXO can never proceed through the standard Reimburse transaction flow.

pub fn create_payout_txhandler(
    input_utxo: UTXO,
    output_txout: TxOut,
    operator_xonly_pk: XOnlyPublicKey,
    user_sig: taproot::Signature,
    _network: bitcoin::Network,
) -> Result<TxHandler<Signed>, BridgeError> {
    let txin = SpendableTxIn::new_partial(input_utxo.outpoint, input_utxo.txout);

    let output_txout = UnspentTxOut::from_partial(output_txout.clone());

    let op_return_txout = op_return_txout(PushBytesBuf::from(operator_xonly_pk.serialize()));

    let mut txhandler = TxHandlerBuilder::new(TransactionType::Payout)
        .with_version(NON_STANDARD_V3)
        .add_input(
            NormalSignatureKind::NotStored,
            txin,
            SpendPath::KeySpend,
            DEFAULT_SEQUENCE,
        )
        .add_output(output_txout)
        .add_output(UnspentTxOut::from_partial(anchor_output(
            NON_EPHEMERAL_ANCHOR_AMOUNT,
        )))
        .add_output(UnspentTxOut::from_partial(op_return_txout))
        .finalize();
    txhandler.set_p2tr_key_spend_witness(&user_sig, 0)?;
    txhandler.promote()
}

    /// Sets the given payout txs' txid and operator index for the given index.
    pub async fn update_payout_txs_and_payer_operator_xonly_pk(
        &self,
        tx: Option<DatabaseTransaction<'_>>,
        payout_txs_and_payer_operator_xonly_pk: Vec<(
            u32,
            Txid,
            Option<XOnlyPublicKey>,
            bitcoin::BlockHash,
        )>,
    ) -> Result<(), BridgeError> {
        if payout_txs_and_payer_operator_xonly_pk.is_empty() {
            return Ok(());
        }
        // Convert all values first, propagating any errors
        let converted_values: Result<Vec<_>, BridgeError> = payout_txs_and_payer_operator_xonly_pk
            .iter()
            .map(|(idx, txid, operator_xonly_pk, block_hash)| {
                Ok((
                    i32::try_from(*idx).wrap_err("Failed to convert payout index to i32")?,
                    TxidDB(*txid),
                    operator_xonly_pk.map(XOnlyPublicKeyDB),
                    BlockHashDB(*block_hash),
                ))
            })
            .collect();
        let converted_values = converted_values?;

        let mut query_builder = QueryBuilder::new(
            "UPDATE withdrawals AS w SET
                payout_txid = c.payout_txid,
                payout_payer_operator_xonly_pk = c.payout_payer_operator_xonly_pk,
                payout_tx_blockhash = c.payout_tx_blockhash
                FROM (",
        );

        query_builder.push_values(
            converted_values.into_iter(),
            |mut b, (idx, txid, operator_xonly_pk, block_hash)| {
                b.push_bind(idx)
                    .push_bind(txid)
                    .push_bind(operator_xonly_pk)
                    .push_bind(block_hash);
            },
        );

        query_builder
            .push(") AS c(idx, payout_txid, payout_payer_operator_xonly_pk, payout_tx_blockhash) WHERE w.idx = c.idx");

        let query = query_builder.build();
        execute_query_with_tx!(self.connection, tx, query, execute)?;

        Ok(())
    }
