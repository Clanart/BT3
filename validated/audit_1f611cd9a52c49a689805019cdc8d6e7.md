### Title

PedPoP accepts the identity encryption key, making encrypted secret shares publicly decryptable - ([File: crypto/dkg/pedpop/src/encryption.rs](crypto/dkg/pedpop/src/encryption.rs))

### Summary

`EncryptionKeyMessage::read` accepts any canonical point as a participant’s encryption key, including the identity point, and `SecretShareMachine::verify_r1` registers it without validating that it is non-identity or proving possession of a corresponding secret key. [1](#0-0) [2](#0-1)  Any share encrypted to that participant then derives its ECDH point as `k * identity = identity`, so anyone who knows the public DKG context can derive the ChaCha20 keystream and recover the plaintext secret share. [3](#0-2) [4](#0-3) 

### Finding Description

`EncryptionKeyMessage` contains the PedPoP commitments plus a separate `enc_key`. [5](#0-4)  During deserialization, only the embedded `Commitments` object and `enc_key`’s point encoding are validated. [1](#0-0)  The commitments proof challenge binds the context, sender participant ID, nonce, and serialized commitments, but not `enc_key`. [6](#0-5)  Consequently, an attacker can take a valid commitment message and replace its trailing `enc_key` encoding with the canonical identity encoding without invalidating the commitments proof. [7](#0-6) [8](#0-7) 

`verify_r1` passes the parsed message to `Encryption::register`, which stores the supplied key without rejecting identity or requiring a proof of possession. [9](#0-8) [10](#0-9)  Later, `encrypt` computes `ecdh(key, victim_enc_key)`, and `ecdh` performs a direct point multiplication. [11](#0-10) [12](#0-11)  If `victim_enc_key` is identity, the ECDH output is identity for every per-message private key, causing the cipher to be deterministically derived from only the public context and the public identity encoding. [13](#0-12) 

### Impact Explanation

This is a confidentiality/authentication bypass on PedPoP’s encryption-key registration path: the commitments signature authenticates only the polynomial commitments, while the independently supplied encryption key is neither bound to that proof nor checked for a usable discrete logarithm. [6](#0-5) [10](#0-9)  An observer who obtains the encrypted DKG share messages can derive the shared ChaCha20 key from `context` and the public identity point, XOR the keystream with `SecretShare<F>` ciphertext, and recover canonical secret-share bytes. [13](#0-12) [14](#0-13)  If the attacker collects threshold-many plaintext shares addressed to participants advertising identity encryption keys, they can interpolate the underlying group secret and defeat the threshold-key protection. [15](#0-14) 

### Likelihood Explanation

Exploitation requires the attacker to supply or influence one participant’s `EncryptionKeyMessage` and observe encrypted shares addressed to that participant. PedPoP explicitly encrypts shares and describes the commitment and share messages as requiring authenticated, but not necessarily confidential, channels, so possession of ciphertexts is within the reachable public-input model. [16](#0-15) [17](#0-16)  The identity point is canonical, so `C::read_G` accepts it because `read_G` rejects only invalid or non-canonical encodings, not identity. [18](#0-17) 

### Recommendation

Reject identity and other unusable encryption keys when registering an `EncryptionKeyMessage`, and bind `enc_key` into an authenticated proof before accepting it. A minimal fix is to add a Schnorr proof of possession over the encryption key, with the challenge binding the context, participant ID, encryption key, and serialized commitments, and verify it in `verify_r1` alongside the existing commitments PoK. [2](#0-1)  At minimum, reject `enc_key.is_identity()` before `Decryption::register` stores it. [10](#0-9) 

### Proof of Concept

For participant `victim`, construct or modify an `EncryptionKeyMessage` whose commitments are valid but whose trailing `enc_key` is `C::G::identity()`. The commitments signature remains valid because `challenge` commits only `context`, `participant`, `nonce`, and the commitments bytes, while `EncryptionKeyMessage::write` appends `enc_key` afterward. [6](#0-5) [7](#0-6)

impl<F: Zeroize + PrimeField> Interpolation<F> {
  /// The interpolation factor for this participant, within this signing set.
  fn interpolation_factor(&self, i: Participant, included: &[Participant]) -> F {
    match self {
      Interpolation::Constant(c) => c[usize::from(u16::from(i) - 1)],
      Interpolation::Lagrange => {
        let i_f = F::from(u64::from(u16::from(i)));

        let mut num = F::ONE;
        let mut denom = F::ONE;
        for l in included {
          if i == *l {
            continue;
          }

          let share = F::from(u64::from(u16::from(*l)));
          num *= share;
          denom *= share - i_f;
        }

        // Safe as this will only be 0 if we're part of the above loop
        // (which we have an if case to avoid)
        num * denom.invert().unwrap()
      }

  /// Read a canonical point from something implementing std::io::Read.
  ///
  /// The provided implementation is safe so long as `GroupEncoding::to_bytes` always returns a
  /// canonical serialization.
  #[cfg(any(feature = "alloc", feature = "std"))]
  #[allow(non_snake_case)]
  fn read_G<R: Read>(reader: &mut R) -> io::Result<Self::G> {
    let mut encoding = <Self::G as GroupEncoding>::Repr::default();
    reader.read_exact(encoding.as_mut())?;

    let point = Option::<Self::G>::from(Self::G::from_bytes(&encoding))
      .ok_or_else(|| io::Error::other("invalid point"))?;
    if point.to_bytes().as_ref() != encoding.as_ref() {
      Err(io::Error::other("non-canonical point"))?;
    }
    Ok(point)
