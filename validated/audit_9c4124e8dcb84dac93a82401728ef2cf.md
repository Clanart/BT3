Based on my research, the strongest analog to the Kibana authorization-bypass pattern is `KeychainServer.get_keychain_for_request()`, which selects which on-disk keychain namespace to operate on purely from a client-supplied `kc_user`/`kc_service` field, with no check that the requester is entitled to that namespace.

### Title
Authorization Bypass Through User-Controlled `kc_user`/`kc_service` Key in Chia Daemon KeychainServer Leading to Cross-Namespace Key Access - (File: `chia/daemon/keychain_server.py`)

### Summary
Every keychain RPC command handled by `KeychainServer` resolves its target `Keychain` instance via `get_keychain_for_request()`, which reads the `kc_user`/`kc_service` fields directly out of the untyped request dict and uses them as a lookup/creation key into `_alt_keychains` [1](#0-0) . There is no validation binding these fields to the identity of the connected client — any daemon-connected caller can specify an arbitrary `kc_user`/`kc_service` pair and the server will either look up or lazily instantiate a `Keychain(user=user, service=service)` for that pair and operate on it [2](#0-1) .

### Finding Description
`KeychainServer` maintains a `_default_keychain` plus a dictionary of `_alt_keychains` keyed by `user + service` strings supplied by the caller [3](#0-2) . Every privileged handler — `add_key`, `check_keys`, `delete_all_keys`, `delete_key_by_fingerprint`, `get_all_private_keys`, `get_first_private_key`, `get_key_for_fingerprint`, and the streamable `run_request` path (`get_key`, `get_keys`, `get_public_key`, `get_public_keys`, `set_label`, `delete_label`) — calls `self.get_keychain_for_request(request)` and trusts the resulting keychain as the correct scope for the operation [4](#0-3) .

This is directly analogous to the Kibana bug class (CWE-639, Authorization Bypass Through User-Controlled Key): a client-supplied identifier ("space" in Kibana, `kc_user`/`kc_service` here) is used to select a resource/authorization boundary without validating that the caller is actually a party of that boundary. `KeychainProxy.format_request()` on the legitimate client side only injects `kc_user`/`kc_service` when the proxy itself was constructed with those values [5](#0-4) , but nothing on the server enforces that a raw daemon-connected client cannot simply set different values than the ones its own service would use. The daemon's only gate is mutual TLS with a locally-issued private cert [6](#0-5) ; once a process (wallet, farmer, plotter, any local script holding daemon certs) is connected, it is treated as fully trusted for arbitrary `kc_user`/`kc_service` selection, allowing it to read, add, or delete keys/labels in a keychain namespace that was never meant to be its own (e.g., a different service's or a different logical user's keychain on a multi-user install).

### Impact Explanation
Because `get_key`, `get_keys`, `get_first_private_key`, and `get_all_private_keys` return private key material (mnemonic-reconstructable entropy) once decoded by `KeychainProxy` [7](#0-6) , a caller that can freely choose `kc_user`/`kc_service` can retrieve private keys belonging to a different logical keychain namespace than the one it should be restricted to, and `delete_all_keys`/`delete_key_by_fingerprint` let it destroy that namespace's keys as well [8](#0-7) . This maps to unauthorized cross-boundary disclosure and mutation of sensitive wallet key material, i.e. an authorization bypass with a direct path to key theft or destructive key deletion — a high-impact primitive if any local process with daemon access is not fully trusted with all keychain namespaces on the machine.

### Likelihood Explanation
Exploitation requires only an existing daemon TLS connection (which any locally co-installed chia service, plugin, or script that has been provisioned with the daemon's private certs already has) and the ability to set two string fields in a JSON RPC payload — no cryptographic bypass or race condition needed. The main mitigating factor is that daemon access itself is already a high-trust boundary (single-machine mutual TLS), so this is most impactful in scenarios where multiple `kc_user`/`kc_service` partitions are expected to represent separate trust domains on the same host (e.g., multi-instance/multi-user chia deployments), which the code explicitly supports via `_alt_keychains`.

### Recommendation
Do not let `kc_user`/`kc_service` be freely client-chosen for privileged keychain commands. Either (a) bind the keychain namespace to the server-side identity of the registered service/connection rather than trusting client-supplied `kc_user`/`kc_service` fields, or (b) maintain an explicit allowlist of `kc_user`/`kc_service` pairs a given connection is authorized to request, validated in `get_keychain_for_request()` before any lookup/creation of an alternate `Keychain` occurs.

### Proof of Concept
1. Start `chia_daemon` normally so `KeychainServer._default_keychain` is populated with the primary user's keys.
2. From any process holding valid daemon client certs (e.g., any locally installed chia service), send a `get_keys` (or `get_first_private_key`/`get_all_private_keys`) daemon RPC with a crafted payload: `{"command": "get_keys", "data": {"include_secrets": true, "kc_user": "user-chia-1.8-other", "kc_service": "chia-other-service"}}`.
3. `get_keychain_for_request()` treats this as a different namespace than the default, creates/looks up `Keychain(user="user-chia-1.8-other", service="chia-other-service")` in `_alt_keychains`, and `run_request()` executes `GetKeysRequest.run(keychain)` against that namespace [9](#0-8) , returning private key data for a keychain the caller never authenticated against.
4. Repeat with `delete_all_keys` using the same crafted `kc_user`/`kc_service` to demonstrate destructive cross-namespace access [10](#0-9) .

**Note on confidence**: I could not fully verify from the index whether `chia/daemon/server.py`'s connection/registration logic ties a connecting websocket's allowed `kc_user`/`kc_service` to any server-side identity check before forwarding to `KeychainServer.handle_command()` — grep found only 3 references in that file but I was not able to read the surrounding authorization logic before running out of tool iterations. If `server.py` does perform such binding, this finding would need to be downgraded or invalidated; I recommend a background agent verify `chia/daemon/server.py`'s handling of keychain commands (search for `keychain_commands` and where `KeychainServer.handle_command` is invoked) before treating this as fully confirmed.

@dataclass
class KeychainServer:
    """
    Implements a remote keychain service for clients to perform key operations on
    """

    _default_keychain: Keychain = field(default_factory=Keychain)
    _alt_keychains: dict[str, Keychain] = field(default_factory=dict)

    def get_keychain_for_request(self, request: dict[str, Any]) -> Keychain:
        """
        Keychain instances can have user and service strings associated with them.
        The keychain backends ultimately point to the same data stores, but the user
        and service strings are used to partition those data stores. We attempt to
        maintain a mapping of user/service pairs to their corresponding Keychain.
        """
        user = request.get("kc_user", self._default_keychain.user)
        service = request.get("kc_service", self._default_keychain.service)
        if user == self._default_keychain.user and service == self._default_keychain.service:
            keychain = self._default_keychain
        else:
            key = (user or "unnamed") + (service or "")
            if key in self._alt_keychains:
                keychain = self._alt_keychains[key]
            else:
                keychain = Keychain(user=user, service=service)
                self._alt_keychains[key] = keychain
        return keychain

    async def add_key(self, request: dict[str, Any]) -> dict[str, Any]:
        if self.get_keychain_for_request(request).is_keyring_locked():
            return {"success": False, "error": KEYCHAIN_ERR_LOCKED}

        mnemonic_or_pk = request.get("mnemonic_or_pk", None)
        label = request.get("label", None)
        private = request.get("private", True)

        if mnemonic_or_pk is None:
            return {
                "success": False,
                "error": KEYCHAIN_ERR_MALFORMED_REQUEST,
                "error_details": {"message": "missing key information"},
            }

        try:
            key = self.get_keychain_for_request(request).add_key(mnemonic_or_pk, label, private)
        except KeyError as e:
            return {
                "success": False,
                "error": KEYCHAIN_ERR_KEYERROR,
                "error_details": {"message": f"The word '{e.args[0]}' is incorrect.'", "word": e.args[0]},
            }
        except ValueError as e:
            log.exception(e)
            return {
                "success": False,
                "error": str(e),
            }

        if isinstance(key, PrivateKey):
            fingerprint = key.get_g1().get_fingerprint()
        else:
            fingerprint = key.get_fingerprint()

        return {"success": True, "fingerprint": fingerprint}

    async def check_keys(self, request: dict[str, Any]) -> dict[str, Any]:
        if self.get_keychain_for_request(request).is_keyring_locked():
            return {"success": False, "error": KEYCHAIN_ERR_LOCKED}

        root_path = request.get("root_path", None)
        if root_path is None:
            return {
                "success": False,
                "error": KEYCHAIN_ERR_MALFORMED_REQUEST,
                "error_details": {"message": "missing root_path"},
            }

        check_keys(Path(root_path))

        return {"success": True}

    async def delete_all_keys(self, request: dict[str, Any]) -> dict[str, Any]:
        if self.get_keychain_for_request(request).is_keyring_locked():
            return {"success": False, "error": KEYCHAIN_ERR_LOCKED}

        self.get_keychain_for_request(request).delete_all_keys()

        return {"success": True}

    async def delete_key_by_fingerprint(self, request: dict[str, Any]) -> dict[str, Any]:
        if self.get_keychain_for_request(request).is_keyring_locked():
            return {"success": False, "error": KEYCHAIN_ERR_LOCKED}

        fingerprint = request.get("fingerprint", None)
        if fingerprint is None:
            return {
                "success": False,
                "error": KEYCHAIN_ERR_MALFORMED_REQUEST,
                "error_details": {"message": "missing fingerprint"},
            }

        self.get_keychain_for_request(request).delete_key_by_fingerprint(fingerprint)

        return {"success": True}

    async def run_request(self, request_dict: dict[str, Any], request_type: type[Any]) -> dict[str, Any]:
        keychain = self.get_keychain_for_request(request_dict)
        if keychain.is_keyring_locked():
            return {"success": False, "error": KEYCHAIN_ERR_LOCKED}

        try:
            request = request_type.from_json_dict(request_dict)
        except Exception as e:
            return {
                "success": False,
                "error": KEYCHAIN_ERR_MALFORMED_REQUEST,
                "error_details": {"message": str(e)},
            }

        try:
            return {"success": True, **request.run(keychain).to_json_dict()}
        except KeychainFingerprintNotFound as e:
            return {
                "success": False,
                "error": KEYCHAIN_ERR_KEY_NOT_FOUND,
                "error_details": {"fingerprint": e.fingerprint},
            }
        except KeychainException as e:
            return {
                "success": False,
                "error": KEYCHAIN_ERR_MALFORMED_REQUEST,
                "error_details": {"message": str(e)},
            }

    async def get_all_private_keys(self, request: dict[str, Any]) -> dict[str, Any]:
        all_keys: list[dict[str, Any]] = []
        if self.get_keychain_for_request(request).is_keyring_locked():
            return {"success": False, "error": KEYCHAIN_ERR_LOCKED}

        private_keys = self.get_keychain_for_request(request).get_all_private_keys()
        for sk, entropy in private_keys:
            all_keys.append({"pk": bytes(sk.get_g1()).hex(), "entropy": entropy.hex()})

        return {"success": True, "private_keys": all_keys}

    def format_request(self, command: str, data: dict[str, Any]) -> WsRpcMessage:
        """
        Overrides DaemonProxy.format_request() to add keychain-specific RPC params
        """
        if data is None:
            data = {}

        if self.keychain_user or self.keychain_service:

            data["kc_service"] = self.keychain_service

        Forwards to Keychain.get_first_private_key()

        if self.use_local_keychain():
