### Title
Gasless-swap price validation uses live AMM spot price with no TWAP/oracle, and KIP-249 auction bids let searchers guarantee an atomic back-run — enabling classic sandwich extraction of GaslessSwapTx users (analog of code-423n4 H-08) - (File: `kaiax/gasless/impl/tx_pool.go`, `kaiax/auction/impl/builder.go`)

### Summary
The Kaia gasless-transaction module (`kaiax/gasless`) validates `GaslessSwapTx` solely against the *current* spot price of the underlying AMM pool (`GaslessSwapRouter.GetAmountIn`, backed by Uniswap-V2-style reserve math), and the user's `minAmountOut`/`amountIn` bound is fixed off-chain at signing time with no TWAP protection. Kaia's native auction module (KIP-249) additionally gives any unprivileged bidder a protocol-guaranteed way to have a transaction executed immediately after a specific target transaction hash. Combined, a searcher can (1) front-run the pending `GaslessSwapTx` with an ordinary transaction that shifts the pool's reserves, and (2) use a KIP-249 bid targeting the `GaslessSwapTx` hash to atomically back-run it, extracting the price-impact/slippage exactly as in the rETH sandwich described in the external report — except here the "victim" is every gasless-swap user and the adjacency is guaranteed by the auction rather than probabilistic gas bidding.

### Finding Description
`GaslessModule.checkBalanceForSwap` enforces:
- `minAmountOut >= amountRepay`
- `amountIn >= gsr.getAmountIn(token, minAmountOut)` where `getAmountIn` is a live view call into `GaslessSwapRouter` [1](#0-0) 

`GetAmountIn`/`GetAmountOut` on the router and its underlying Uniswap V2 router are pure reserve-ratio computations (`x*y=k` spot price), not TWAP-based: [2](#0-1) [3](#0-2) 

The user (or the gasless SDK) computes `amountIn`/`minAmountOut` off-chain using the spot price at signing time, exactly the way the original rETH `stake()`/`unstake()` computed `minOut` from the current spot price with a fixed slippage bound. There is no mechanism to keep this bound tied to the price actually realized at inclusion time.

Kaia's auction module (KIP-249) is designed to let a bidder submit a bid targeting a specific pending transaction hash; `ExtractTxBundles` guarantees that bid's generated transaction is placed immediately after the target transaction in the mined block: [4](#0-3) 

The block-building filter (`FilterTxs`) explicitly recognizes and special-cases gasless transactions so they are not dropped near the auction's early deadline, keeping `GaslessSwapTx` visible and biddable as an auction target up to block construction: [5](#0-4) 

Because a `GaslessSwapTx`'s swap parameters (`token`, `amountIn`, `minAmountOut`, `amountRepay`) are visible in the mempool/RPC before inclusion (also exposed via `debug_isGaslessTx`), a searcher can:
1. Submit an ordinary transaction ahead of the target (via normal fee/priority ordering) that trades against the same DEX pool used by `GaslessSwapRouter` to push the pool price against the pending swap.
2. Submit a KIP-249 bid whose target is the `GaslessSwapTx` hash, guaranteeing their reversing (back-run) trade executes atomically right after it in the same block regardless of gas-price competition.

Since the router only requires `amountIn >= getAmountIn(minAmountOut)` computed from the (now front-run-distorted) reserves and only enforces `minAmountOut >= amountRepay`, the swap still succeeds (it does not revert), but it executes at a manipulated price. The `SwappedForGas` event's `finalUserAmount` (the residual sent to the user after repaying gas and commission) is directly reduced by the sandwich, transferring value from the gasless user to the searcher — the same value-extraction mechanic as the rETH sandwich (H-08), just relocated from a derivative-staking flow to Kaia's native gasless-swap flow, and made deterministic instead of probabilistic thanks to the KIP-249 bid's guaranteed adjacency.

### Impact Explanation
This allows any unprivileged auction bidder / transaction sender to systematically extract value from gasless-swap users' token-to-KAIA conversions, reducing the amount of KAIA users receive after gas repayment, without requiring any privileged role, validator collusion, or protocol bug beyond normal transaction submission and legitimate use of the KIP-249 bidding API. This is a direct, repeatable unauthorized value transfer from ordinary users to searchers, satisfying the "unauthorized value movement" bar.

### Likelihood Explanation
Likelihood is high wherever the whitelisted DEX pool backing a gasless-swap token has shallow liquidity relative to typical swap sizes (the exact precondition in the original finding). The auction module is a first-class, documented, public feature (KIP-249) explicitly built to let searchers guarantee post-target execution, and gasless swap transactions are visible pre-inclusion and explicitly exempted from early-deadline filtering, making them easy, persistent targets. No special privileges, timing races beyond normal bid submission, or validator complicity are required.

### Recommendation
- Bind `GaslessSwapTx` price validation and/or the on-chain `swapForGas` execution to a manipulation-resistant price reference (e.g., a TWAP oracle or a router-level maximum price-impact check against reserves sampled over multiple blocks) rather than the instantaneous reserve ratio.
- Consider disallowing a KIP-249 auction bid from targeting a `GaslessSwapTx` hash, or require the gasless router to re-validate `minAmountOut` against a stricter, deadline-scoped price bound at execution time so that pool manipulation within the same block cannot move the realized price beyond the user's true intended slippage.
- Shorten the effective exposure window of gasless swap parameters (e.g., recompute/re-sign `minAmountOut` closer to inclusion, or use commit-reveal to hide swap parameters until execution).

### Proof of Concept
1. Attacker monitors the mempool/RPC (`debug_isGaslessTx`, or plain tx inspection) for a pending `GaslessSwapTx(token, amountIn, minAmountOut, amountRepay, deadline)` targeting `GaslessSwapRouter.swapForGas`.
2. Attacker computes the pool reserves for `token/WKAIA` backing that router (Uniswap-V2-style AMM) and determines a front-run trade size that pushes the price down just enough that the victim's swap, though still passing `amountIn >= getAmountIn(minAmountOut)` and `minAmountOut >= amountRepay`, yields a much smaller residual for the user.
3. Attacker submits: (a) a plain swap transaction to shift reserves before the target block is built, and (b) a signed KIP-249 bid whose `TargetTxHash` equals the `GaslessSwapTx` hash, so that the bidder's reversing trade is guaranteed to execute immediately after the gasless swap in the same block via `AuctionModule.ExtractTxBundles`.
4. When the block is produced, order is: [attacker front-run] → ... → [LendTxGenerator, GaslessApproveTx?, GaslessSwapTx] → [attacker bid back-run]. The gasless swap executes at the manipulated price, still satisfying its on-chain checks, but `finalUserAmount` in the `SwappedForGas` event is reduced by the extracted amount, which flows to the attacker on the back-run.

func (a *AuctionModule) ExtractTxBundles(txs []*types.Transaction, prevBundles []*builder.Bundle) []*builder.Bundle {
	bundles := []*builder.Bundle{}
	curBlock := a.Chain.CurrentBlock()
	if curBlock == nil || atomic.LoadUint32(&a.bidPool.running) == 0 {
		return bundles
	}

	miningBlock := curBlock.NumberU64() + 1
	bidTargetMap := a.bidPool.GetTargetTxMap(miningBlock)
	if len(bidTargetMap) == 0 {
		return bundles
	}

	for _, tx := range txs {
		txHash := tx.Hash()
		bid, ok := bidTargetMap[txHash]
		if !ok {
			continue
		}
		b := builder.NewBundle(
			builder.NewTxOrGenList(a.GetBidTxGenerator(tx, bid)),
			txHash,
			true,
		)

		isConflict := false
		for _, prev := range append(prevBundles, bundles...) {
			if prev.IsConflict(b) {
				isConflict = true
				break
			}
		}
		if isConflict {
			continue
		}
		bundles = append(bundles, b)
	}

	return bundles
}

func (a *AuctionModule) FilterTxs(txs map[common.Address]types.Transactions) {
	if atomic.LoadUint32(&a.bidPool.running) == 0 {
		return
	}

	curBlock := a.Chain.CurrentBlock()
	if curBlock == nil {
		return
	}

	targetTxHashMap := a.bidPool.getTargetTxHashMap(curBlock.NumberU64() + 1)
	edOffset := a.AuctionConfig.EDOffset

	now := time.Now()
	deadline := now.Add(-edOffset)
	// filter txs that are after the auction early deadline
	for addr, list := range txs {
		for i, tx := range list {
			if tx.Time().After(deadline) && !a.isGaslessTx(tx) {
				// if the tx is a target tx, skip it
				if _, ok := targetTxHashMap[tx.Hash()]; ok {
					continue
				}

				if i == 0 {
					// if first transaction exceeds deadline, remove the address
					delete(txs, addr)
				} else {
					// keep only transactions before the deadline
					txs[addr] = list[:i]
				}
				break
			}
		}
	}

	edOffsetGauge.Update(int64(edOffset))
}
