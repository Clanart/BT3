### Title
Out-of-range blame recipient causes a reachable panic in `AdditionalBlameMachine::blame` - ([File: crypto/dkg/pedpop/src/encryption.rs](crypto/dkg/pedpop/src/encryption.rs))

### Summary
`AdditionalBlameMachine::blame` accepts arbitrary nonzero `Participant` values but never checks that the accused sender or accusing recipient belongs to the `1 ..= n` DKG set. After an attacker's encrypted message passes its proof-of-possession check, `decrypt_with_proof` indexes `self.enc_keys[&decryptor]`; `enc_keys` only contains `1 ..= n`, so a nonzero out-of-range recipient causes an unhandled `HashMap` indexing panic.

### Finding Description
`Participant::new` only rejects zero, so callers can construct participants greater than the protocol's `n`. [1](#0-0)  `AdditionalBlameMachine::new` populates `Decryption::enc_keys` exclusively for participants `1 ..= n`. [2](#0-1)  The public `blame` method forwards the supplied `sender` and `recipient` to `blame_internal` without validating either against that map. [3](#0-2)  `blame_internal` then calls `decrypt_with_proof`, which verifies the message proof-of-possession and, when `proof` is `Some`, evaluates `self.enc_keys[&decryptor]` to build the DLEq points. [4](#0-3) [5](#0-4) 

The crash is reachable from public serialized inputs: `EncryptedMessage::read` accepts an arbitrary encoded key, Schnorr proof-of-possession, and ciphertext. [6](#0-5)  An attacker can choose an encryption-key scalar and produce a valid Schnorr signature over the ciphertext using the public `pop_challenge` transcript structure. `EncryptionKeyProof::read` only needs to deserialize syntactically valid point/scalar encodings because the out-of-bounds map access occurs while constructing the DLEq verification arguments, before proof validity can reject it. [7](#0-6) [8](#0-7) 

### Impact Explanation
This is a remote denial of service analogous to the reported crash class. A single blame evaluation naming a nonzero but out-of-range recipient aborts the calling thread or process through a panic. In a deployment that evaluates blame proofs on behalf of the DKG, this prevents blame processing and can halt the node component responsible for completing key generation.

### Likelihood Explanation
The attacker only needs to supply:

1. A syntactically valid `EncryptedMessage` whose proof-of-possession verifies.
2. Any syntactically valid `EncryptionKeyProof` encoding.
3. A recipient such as `Participant::new(n + 1)`.

No private key, collusion, malformed curve point, or privileged operation is required. The encrypted share does not need to decrypt to a valid scalar, and the supplied DLEq proof does not need to verify because the panic occurs before either check can complete.

### Recommendation
Validate `sender` and `recipient` in `AdditionalBlameMachine::blame` / `blame_internal` before calling `decrypt_with_proof`. Return a deterministic error or classify the caller-supplied accusation as invalid when either participant is absent from `commitments` / `enc_keys`. Avoid indexing untrusted participant IDs with `map[&participant]`; use `map.get(&participant)` and handle `None`.

### Proof of Concept
```rust
// C: the negotiated ciphersuite; n is the registered participant count.
let sender = Participant::new(1).unwrap();
let invalid_recipient = Participant::new(n + 1).unwrap();

// Build a valid EncryptedMessage encoding:
// key = x * G
// pop = SchnorrSignature::sign(x, r, pop_challenge(context, rG, key, sender, msg))
// msg = arbitrary SecretShare-sized bytes.
let encoded_msg = concat(key.to_bytes(), pop.serialize(), arbitrary_msg_bytes);
let msg = EncryptedMessage::<C, SecretShare<C::F>>::read(
    &mut encoded_msg.as_slice(),
    params,
).unwrap();

// Any canonically encoded point plus two canonical scalars reaches the panic.
let encoded_proof = concat(point.to_bytes(), c.to_repr(), s.to_repr());
let proof = EncryptionKeyProof::<C>::read(&mut encoded_proof.as_slice()).unwrap();

// `enc_keys` contains only 1..=n, so this indexes a missing key and panics.
machine.blame(sender, invalid_recipient, msg, Some(proof));
```
