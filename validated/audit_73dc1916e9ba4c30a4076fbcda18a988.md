Looking at the report's core pattern — a verification function that trusts a *cheaply spoofable, attacker-influenced runtime signal* to select which trust/validation branch to take, and never falls back to a safe/independent check once that signal fires — I found a structurally identical bug in GitHub Desktop's git credential helper.

### Title
Attacker-Controlled `WWW-Authenticate` Header Spoofs GitHub-Host Classification in Trampoline Credential Helper - (File: `app/src/lib/trampoline/trampoline-credential-helper.ts`)

### Summary
`getEndpointKind()` in the trampoline credential helper decides whether a git remote is GitHub.com/Enterprise ("github.com"/"enterprise"/"ghe.com") or a generic host by inspecting a `WWW-Authenticate` header value (`wwwauth[...]`) that Git forwards verbatim from the remote server's HTTP response. Just as the FactCheckExchange bug trusted `isContract()` — a runtime, spoofable property — as the sole signal for which signature-verification path to take, this function trusts an unauthenticated, attacker-controlled string (`realm="GitHub"`) as the sole signal for classifying an arbitrary remote as a GitHub host, short-circuiting before any independent verification.

### Finding Description
`getEndpointKind()` [1](#0-0)  runs a series of checks in order: `isGist`, `isDotCom`, `isGHE`, and then — before falling back to the network-verified `isGitHubHost()` discovery request — a header-based "happy path": [2](#0-1) 

The comment itself concedes the trust assumption: *"We use them as a happy-path to determine if the host is a GitHub host without having to resort to making a request ourselves."* The `wwwauth[...]` values originate from the HTTP `WWW-Authenticate` response header sent by whatever server the user is cloning/fetching/pushing to — this is server-controlled content with no cryptographic binding to the actual identity of the host, exactly analogous to how `EXTCODESIZE`/`isContract` is a runtime property that EIP-7702 lets an EOA spoof.

Because this check runs *before* the independent, network-verified `isGitHubHost()` fallback [3](#0-2)  and *before* the protocol/https gate is even relevant to it, any git server (a malicious clone/fetch target, or a MITM/malicious proxy in the git transport path) can unilaterally force classification to `'enterprise'` merely by returning `WWW-Authenticate: realm="GitHub"` on its 401 challenge — no valid GitHub API responses, no TLS cert requirements beyond what git itself already accepted, nothing else needed.

This classification is consumed by `getCredential()` [4](#0-3) , `storeCredential()` [5](#0-4) , and `eraseCredential()` [6](#0-5) . In all three, once `endpointKind !== 'generic'`, Desktop takes the "this is a GitHub identity" branch and never falls back to the generic username/password credential mechanism (external GCM or Desktop's own generic-git-auth store) — mirroring the report's "does not fall back to ECDSA.recover(), causing legitimate ... signatures to be rejected" failure mode, except here it's "does not fall back to normal generic credential handling for a non-GitHub host."

### Impact Explanation
The exact corrupted value is the `endpointKind` classification returned by `getEndpointKind()` for an arbitrary, attacker-chosen remote URL. Once spoofed to `'enterprise'`:
- `storeCredential`/`eraseCredential` silently no-op instead of persisting/erasing the user's entered credential for that (actually generic, non-GitHub) host — a silent corruption of what credential state Desktop maintains for that remote.
- `getCredential()`, finding no existing Account bound to that spoofed endpoint, calls `ui.promptForGitHubSignIn(endpoint)` [7](#0-6) , surfacing a GitHub/GitHub-Enterprise sign-in flow scoped to the attacker's hostname instead of the generic-auth prompt the user would normally expect for an unknown git host. This misdirects the account-binding/OAuth flow toward a host that was never independently verified as a genuine GitHub endpoint.

No existing guard stops this: the header check runs unconditionally and prior to the one check (`isGitHubHost`) that actually performs network verification with certificate/response validation.

### Likelihood Explanation
Any repository the user clones, fetches, or pushes to is a reachable trigger point — the attacker only needs to control the HTTP(S) server (or a proxy/MITM position already accepted for that git operation) and needs no privileged access, no local file system access, and no prior compromise. This satisfies the "attacker controls...a git remote/proxy response" criterion in the valid-impact list. The only precondition is that Git performs an HTTP auth challenge round-trip against that remote (a normal occurrence for any HTTP(S) remote requiring auth), which the credential helper protocol then forwards to Desktop.

### Recommendation
Do not trust `WWW-Authenticate` realm strings as a standalone signal for GitHub-host classification. At minimum:
- Require the `isGitHubHost()` network-verified check (or an equivalent independently-verifiable signal, e.g., matching a previously-established Account's exact endpoint) before treating an unknown host as GitHub/Enterprise.
- If the header-based fast path is kept for performance, treat it only as a *hint* to skip to the `isGitHubHost()` discovery request, not as a terminal classification.

### Proof of Concept
1. Stand up an HTTP(S) server (`evil.example.com`) that responds to Git's credential probe with `HTTP/1.1 401 Unauthorized` and header `WWW-Authenticate: Basic realm="GitHub"`.
2. In GitHub Desktop, clone/fetch `https://evil.example.com/some/repo.git`.
3. Git forwards the captured header to Desktop's trampoline credential helper as a `wwwauth[...]` field in the `get` credential command's stdin.
4. `getEndpointKind()` matches `realm="GitHub"` and returns `'enterprise'` for `evil.example.com` without ever calling `isGitHubHost()`.
5. Observe that `getCredential()` skips the generic credential path entirely and instead invokes `ui.promptForGitHubSignIn('https://evil.example.com')`, and that a subsequent `store`/`erase` credential command for this host is silently dropped instead of being persisted/removed via the generic credential mechanism.

async function getCredential(cred: Credential, store: Store, token: string) {
  const ghCred = await getGitHubCredential(cred, store)

  if (ghCred) {
    return ghCred
  }

  const endpointKind = await getEndpointKind(cred, store)
  const accounts = await store.getAll()

  const endpoint = `${getCredentialUrl(cred)}`
  const apiEndpoint = getAPIEndpoint(endpoint)

  // If it appears as if the endpoint is a GitHub host and we don't have an
  // account for that endpoint then we should prompt the user to sign in.
  if (
    endpointKind !== 'generic' &&
    !accounts.some(a => a.endpoint === apiEndpoint)
  ) {
    if (getIsBackgroundTaskEnvironment(token)) {
      debug('background task environment, skipping prompt')
      return undefined
    }

    const account = await ui.promptForGitHubSignIn(endpoint)

    if (!account) {
      setHasRejectedCredentialsForEndpoint(token, endpoint)
    }

    return credWithAccount(cred, account)
  }

  // GitHub.com/GHE creds are only stored internally
  if (endpointKind !== 'generic') {
    return undefined
  }

  return useExternalCredentialHelper()
    ? getExternalCredential(cred, token)
    : getGenericCredential(cred, token)
}

const getEndpointKind = async (cred: Credential, store: Store) => {
  const credentialUrl = getCredentialUrl(cred)
  const endpoint = `${credentialUrl}`

  if (isGist(endpoint)) {
    return 'generic'
  }

  if (isDotCom(endpoint)) {
    return 'github.com'
  }

  if (isGHE(endpoint)) {
    return 'ghe.com'
  }

  // When Git attempts to authenticate with a host it captures any
  // WWW-Authenticate headers and forwards them to the credential helper. We
  // use them as a happy-path to determine if the host is a GitHub host without
  // having to resort to making a request ourselves.
  for (const [k, v] of cred.entries()) {
    if (k.startsWith('wwwauth[')) {
      if (v.includes('realm="GitHub"')) {
        return 'enterprise'
      } else if (/realm="(GitLab|Gitea|Atlassian Bitbucket)"/.test(v)) {
        return 'generic'
      }
    }
  }

  const existingAccount = await findGitHubTrampolineAccount(store, endpoint)
  if (existingAccount) {
    return isDotCom(existingAccount.endpoint) ? 'github.com' : 'enterprise'
  }

  // All GitHub hosts use HTTPS, so if the protocol is not HTTPS we can
  // assume that this is not a GitHub host.
  if (credentialUrl.protocol !== 'https:') {
    return 'generic'
  }

  return (await isGitHubHost(endpoint)) ? 'enterprise' : 'generic'
}

async function storeCredential(cred: Credential, store: Store, token: string) {
  if ((await getEndpointKind(cred, store)) !== 'generic') {
    return
  }

  return useExternalCredentialHelper()
    ? storeExternalCredential(cred, token)
    : setGenericCredential(
        urlWithoutCredentials(getCredentialUrl(cred)),
        forceUnwrap(`credential missing username`, cred.get('username')),
        forceUnwrap(`credential missing password`, cred.get('password'))
      )
}
