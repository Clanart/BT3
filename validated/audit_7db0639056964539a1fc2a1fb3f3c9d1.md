## Analysis

The MetaSwap bug is fundamentally about **implicit trust flowing to a downstream component (an "adapter") that has no way to verify who is actually invoking it, while that component carries a valuable secret (token approval)**. The closest analog in this GitHub Desktop codebase is not the credential-helper's URL matching (which is scoped by strict origin comparison and therefore *is* a working guard), but the **trampoline TCP server used for askpass/credential-helper requests, combined with the git-hooks interception mechanism**.

### Broken invariant

Desktop's `git()`/`spawnGit()` wrapper injects two secrets into every Git subprocess's environment: `DESKTOP_PORT` and `DESKTOP_TRAMPOLINE_TOKEN` [1](#0-0) . These are the *only* credentials the trampoline server checks before honoring a request. The desktop-trampoline C client simply forwards `DESKTOP_TRAMPOLINE_TOKEN` (read from env) over a plain TCP socket to `127.0.0.1:$DESKTOP_PORT` [2](#0-1) , and the server-side parser accepts any client that supplies a valid-looking `DESKTOP_TRAMPOLINE_TOKEN` [3](#0-2) . There is no check that the connecting process is the actual `desktop-trampoline` binary invoked by Git's own askpass/credential-helper machinery — knowledge of the token is treated as sufficient proof of identity, exactly like MetaSwap's approval being usable by *any* code that gets DELEGATECALLed.

Separately, Desktop has a "hooks proxy" feature that lets **repository-controlled executables** (hooks discovered via `getRepoHooks`, sourced from `core.hooksPath` or `.git/hooks` inside the cloned/fetched repo) run as real child processes of Git during operations like commit/checkout, routed through a `process-proxy` [4](#0-3) [5](#0-4) . Crucially, `withHooksEnv` and `withTrampolineEnv` are composed for the *same* `git()` invocation — `withHooksEnv(hooksEnv => withTrampolineEnv(...))` [6](#0-5)  — so the `DESKTOP_PORT`/`DESKTOP_TRAMPOLINE_TOKEN` env vars set for that Git process are present in the same environment block that Git will use to spawn its hooks. Since Node's child processes inherit environment by default unless explicitly stripped, a hook binary shipped inside an attacker-controlled repository (e.g. `post-checkout`, `pre-commit`) can read `DESKTOP_PORT` / `DESKTOP_TRAMPOLINE_TOKEN` straight out of its own `process.env` and speak the trampoline protocol itself.

### Why existing guards don't stop it

Once a malicious hook connects to the trampoline server with the leaked token and issues a `CREDENTIALHELPER get` command for `url=https://github.com`, the handler in `getGitHubCredential` looks the account up purely by URL origin and returns the account's token unconditionally, with no verification that the request came from Git's real credential subsystem rather than from an arbitrary hook process running inside the repo: [7](#0-6) 

`createCredentialHelperTrampolineHandler` will format and return this credential to whoever asked, without any UI prompt or reconfirmation, because the design assumes the caller is always the trusted `desktop-trampoline` executable that Git itself launched via `GIT_ASKPASS`/`credential.helper`: [8](#0-7) 

The trampoline server's only authentication factor — the token — is exactly the value that gets exposed to the untrusted hook process by ordinary environment inheritance, so the "approval" (in MetaSwap terms) leaks to the "adapter" (the hook) without any additional step.

### Summary
Git operations spawned by Desktop carry two trust secrets, `DESKTOP_PORT` and `DESKTOP_TRAMPOLINE_TOKEN`, used solely to authenticate requests to Desktop's in-process trampoline TCP server, which answers askpass/credential-helper requests with the user's stored GitHub token. The same environment used to launch Git also gets composed with the hooks-interception environment for the identical `git()` call, meaning a malicious executable hook inside a cloned/fetched repository runs as a child of that Git process and inherits those secrets. Because the trampoline server trusts any holder of a valid token, not just the real `desktop-trampoline` client, the hook can directly request and receive the signed-in GitHub account's token.

### Finding Description
`withTrampolineEnv` injects `DESKTOP_PORT`/`DESKTOP_TRAMPOLINE_TOKEN` into the Git process environment for every `git()`/`spawnGit()` call [1](#0-0) , and this happens inside `withHooksEnv(hooksEnv => withTrampolineEnv(...))` in the core `git()` function, so both hook-execution and trampoline environments are merged into one process env [6](#0-5) . The hooks-proxy feature runs hooks found in the target repository as real subprocesses of that same Git invocation [4](#0-3) [5](#0-4) . The trampoline server (both the C client and the Node-side parser) authenticates purely on possession of the token string, not on process identity [2](#0-1) [3](#0-2) . The credential-helper handler resolves and returns the GitHub account token for a matching origin with no additional verification [7](#0-6) .

### Impact Explanation
A successful request yields the victim's GitHub personal token/OAuth credential (`account.token`), which can be used to impersonate the user against the GitHub API — reading private repositories, pushing code, or performing any action the token is scoped for. This maps directly to the "credential/token exfiltration" impact category.

### Likelihood Explanation
The primitive required — an attacker-controlled repository containing an executable hook (or a `core.hooksPath` pointing at attacker content) that gets cloned/fetched and then triggers a hook-eligible operation (e.g., commit, checkout) — is within the stated threat model (attacker controls a cloned/fetched repository). I was not able to fully confirm from the indexed code which specific Desktop operations pass `interceptHooks: true` by default versus only exposing it as an opt-in preference, which affects how easily the hook-execution path is reached in practice; this should be verified against the call sites of `git()`/`spawnGit()` that pass `interceptHooks`.

### Recommendation
Scope the trampoline TCP server's trust to the specific Git subprocess it was spawned for (e.g., a per-invocation nonce tied to process ancestry, or a Unix domain socket/named pipe with an access-controlled path only known to the direct trampoline binary), and ensure hook/filter subprocess environments used to run untrusted, repository-supplied executables never inherit `DESKTOP_PORT`/`DESKTOP_TRAMPOLINE_TOKEN` (strip them explicitly from the hook-proxy environment rather than relying on them not being read by malicious code).

### Proof of Concept
Not independently verified end-to-end due to tool/time constraints; conceptually: clone/fetch a repository containing an executable `post-checkout` hook whose only logic is: read `process.env.DESKTOP_PORT`/`DESKTOP_TRAMPOLINE_TOKEN`, connect to `127.0.0.1:$DESKTOP_PORT`, send `DESKTOP_TRAMPOLINE_IDENTIFIER=CREDENTIALHELPER`, `DESKTOP_TRAMPOLINE_TOKEN=<token>`, argv `["get"]`, stdin `url=https://github.com\n`, and read back the `username=`/`password=` response containing the account token.

    return 1;

export async function withHooksEnv<T>(
  fn: (env: Record<string, string | undefined> | undefined) => Promise<T>,
  path: string,
  opts: IGitExecutionOptions | undefined
): Promise<T> {
  if (!opts?.interceptHooks || !getHooksEnvEnabled()) {
    return fn(opts?.env)
  }

  const hooks = await Array.fromAsync(getRepoHooks(path, opts.interceptHooks))

  if (hooks.length === 0) {
    return fn(opts?.env)
  }

  const ext = __WIN32__ ? '.exe' : ''
  const processProxyPath = join(__dirname, `process-proxy${ext}`)

  const token = crypto.randomUUID()
  const tmpHooksDir = await mkdtemp(join(tmpdir(), 'desktop-git-hooks-'))
  const hooksProxy = createHooksProxy(
    cwd =>
      memoizedGetShellEnv(
        getGitHookEnvShell(),
        cwd,
        // We always cache environment per token (i.e. per operation, e.g commit, apply, etc)
        // but we can optionally cache it over multiple operations in the same repository if the user
        // has enabled that setting.
        getCacheHooksEnv() ? 'global' : token
      ),
    tmpHooksDir,
    opts?.onHookProgress,
    opts?.onHookFailure
  )

  const server = createProxyProcessServer(
    conn =>
      hooksProxy(conn).catch(err => {
        log.error(`hooks proxy failed:`, err)
        conn.exit(1).catch(() => {})
      }),
    { validateConnection: async receivedToken => receivedToken === token }
  )
  const port = await new Promise<number>(resolve => {
    server.listen(0, '127.0.0.1', () =>
      resolve((server.address() as AddressInfo).port)
    )
  })
  try {
    for (const hook of hooks) {
      await cp(processProxyPath, join(tmpHooksDir, `${hook}${ext}`))
    }

    const existingGitEnvConfig =
      opts?.env?.['GIT_CONFIG_PARAMETERS'] ??
      process.env['GIT_CONFIG_PARAMETERS'] ??
      ''

    const gitEnvConfigPrefix =
      existingGitEnvConfig.length > 0 ? `${existingGitEnvConfig} ` : ''

    return await fn({
      // TODO: Do we need to escape tmpHooksDir? Could it possibly include a single quote?
      // probably not?
      GIT_CONFIG_PARAMETERS: `${gitEnvConfigPrefix}'core.hooksPath=${tmpHooksDir}'`,
      PROCESS_PROXY_PORT: `${port}`,
      PROCESS_PROXY_TOKEN: token,
    })

export async function* getRepoHooks(path: string, filter?: string[]) {
  const hooksPath = await getConfigValue(path, 'core.hooksPath')
    .catch(() => getHooksPath(path))
    .then(p => resolve(path, p))

  const files = await readdir(hooksPath, { withFileTypes: true })
    .then(entries => entries.filter(x => x.isFile()))
    .catch(() => [])

  const matchAll = filter?.includes('*')

  for (const file of files) {
    const hookName = basename(file.name, '.exe')

    if (matchAll || filter?.includes(hookName) === false) {
      continue
    }

    if (!knownHooks.includes(hookName)) {
      continue
    }

    if (__WIN32__) {
      // On Windows we have to assume that any valid hook name is executable
      // because the executable bit is not used there. Git looks for a shebang
      // but that seems expensive to check here :shrug:
      yield hookName
    } else if (await isExecutable(join(file.parentPath, file.name))) {
      yield hookName
    }
  }
