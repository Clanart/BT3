## Analysis

The report describes a bug class where independent unit failures in a loop (`Vault.sol`'s plugin deposit/withdraw) cause an all-or-nothing revert instead of isolating just the failing unit. The closest reachable analog in the Kaia codebase is in block-building bundle incorporation, which underlies both the `gasless` and `auction` (KIP-249) settlement modules.

`ExtractBundlesAndIncorporate` collects bundles from all registered `TxBundlingModule`s (gasless and auction) and then calls `IncorporateBundleTx` once for the entire, combined bundle list [1](#0-0) . `IncorporateBundleTx` loops over every bundle and calls `incorporate` sequentially, but if incorporation of any single bundle fails (its `TargetTxHash` is not found in the transaction list), it immediately returns `nil, err` for the *entire* function call [2](#0-1) [3](#0-2) . Back in `ExtractBundlesAndIncorporate`, that single error causes **all** bundles — from every module and every sender — to be discarded, and the function falls back to `flattenedTxs, nil` (no bundles at all) [4](#0-3) .

Since gasless and auction bundles are unrelated to each other (different senders, independent settlement flows for KIP-247 gasless swaps and KIP-249 auction bids), one bundle's target-tx-not-found condition (e.g., because its target got evicted or reordered) silences every other unrelated, otherwise-valid bundle for that block, denying legitimate settlement to unrelated users — directly mirroring the "one plugin's failure blocks the rest" bug class.

### Title
One bundle's incorporation failure discards all unrelated gasless/auction bundles for the block - ([File: work/builder/builder.go])

### Summary
`ExtractBundlesAndIncorporate` builds a combined list of bundles from all `TxBundlingModule`s (currently `gasless` and `auction`) and incorporates them via a single call to `IncorporateBundleTx`. If incorporation of any one bundle fails, the function discards every bundle for the block, not just the failing one.

### Finding Description
`IncorporateBundleTx` iterates all bundles and calls `incorporate` for each; the first `incorporate` failure (its `TargetTxHash` not found among `txs`) causes the loop to `return nil, err` immediately [2](#0-1) . This is analogous to the reported Vault.sol pattern where a `for` loop over independent plugins reverts the whole operation on the first plugin failure instead of continuing with the others.

`ExtractBundlesAndIncorporate` calls `IncorporateBundleTx` once with the combined `bundles` slice gathered from *all* `TxBundlingModule`s (gasless module, auction module) [5](#0-4) . On any single incorporation error, it returns `flattenedTxs, nil` — i.e., zero bundles for the whole block [4](#0-3) . The gasless and auction modules are registered together into this shared bundling pipeline [6](#0-5) , so a bundle produced by one module (e.g., an auction bid bundle) failing to find its target can wipe out an unrelated bundle produced by the other module (e.g., a different user's gasless swap bundle) in the same block, even though that second bundle was independently valid.

### Impact Explanation
This is a liveness/fairness issue for value-settlement flows rather than a fund-theft bug: legitimate gasless swap settlements and auction winner bid executions can be silently dropped from block construction because of an unrelated bundle's target-hash mismatch, denying users their expected transaction inclusion/settlement for that block. Since auction settlement (KIP-249) and gasless lending/repayment (KIP-247) both rely on this shared bundling code path, an unrelated bundle failure degrades the guaranteed execution ordering promised by these mechanisms.

### Likelihood Explanation
Reachable purely through normal transaction/bid submission: any transaction pool state change (eviction, reordering, replacement) that invalidates one bundle's `TargetTxHash` before `IncorporateBundleTx` runs is sufficient — no privileged access is required, and both gasless swap senders and auction bidders/searchers are unprivileged transaction submitters.

### Recommendation
Change `IncorporateBundleTx`/`ExtractBundlesAndIncorporate` to skip (and log/drop) only the bundle whose incorporation fails, continuing to incorporate the remaining independent bundles rather than discarding the entire bundle set on the first failure.

### Proof of Concept
1. Submit two independent, valid bundle-eligible transaction sets in the same block-building window: e.g., a gasless approve+swap pair from sender A, and an auction bid targeting an unrelated transaction from sender B.
2. Arrange for the auction bid's `TargetTxHash` to no longer be present in the flattened `arrayTxs` at incorporation time (e.g., the target tx was already popped/evicted or reordered out by `coordinateTargetTxHash`/pool eviction).
3. `IncorporateBundleTx` fails on the auction bundle and returns `nil, ErrFailedToIncorporateBundle` [7](#0-6) .
4. `ExtractBundlesAndIncorporate` catches this error and returns zero bundles for the block [4](#0-3) , causing sender A's otherwise-valid gasless bundle to also be dropped, even though it had nothing to do with the auction bundle's failure.

// IncorporateBundleTx incorporates bundle transactions into the transaction list.
// Caller must ensure that there is no conflict between bundles.
func IncorporateBundleTx(txs []*types.Transaction, bundles []*Bundle) ([]*TxOrGen, error) {
	ret := make([]*TxOrGen, len(txs))
	for i, tx := range txs {
		ret[i] = NewTxOrGenFromTx(tx)
	}

	for _, bundle := range bundles {
		var err error
		ret, err = incorporate(ret, bundle)
		if err != nil {
			return nil, err
		}
	}
	return ret, nil
}

func incorporate(txs []*TxOrGen, bundle *Bundle) ([]*TxOrGen, error) {
	ret := make([]*TxOrGen, 0, len(txs)+len(bundle.BundleTxs))
	targetFound := false

	// 1. place bundle at the beginning
	if bundle.TargetTxHash == (common.Hash{}) {
		ret = append(ret, bundle.BundleTxs...)
		targetFound = true
	}

	// 2. place bundle after TargetTxHash
	for _, txOrGen := range txs {
		// if tx-in-bundle, the tx will be appended when target is found.
		if bundle.Has(txOrGen) {
			continue
		}
		ret = append(ret, txOrGen)
		if txOrGen.Id == bundle.TargetTxHash {
			targetFound = true
			ret = append(ret, bundle.BundleTxs...)
		}
	}

	if !targetFound {
		return nil, ErrFailedToIncorporateBundle
	}

	return ret, nil
}

func ExtractBundlesAndIncorporate(arrayTxs []*types.Transaction, txBundlingModules []TxBundlingModule) ([]*TxOrGen, []*Bundle) {
	// Detect bundles and add them to bundles
	bundles := []*Bundle{}
	flattenedTxs := []*TxOrGen{}
	if txBundlingModules == nil {
		for _, tx := range arrayTxs {
			flattenedTxs = append(flattenedTxs, NewTxOrGenFromTx(tx))
		}
		return flattenedTxs, nil
	}

	for _, txBundlingModule := range txBundlingModules {
		newBundles := txBundlingModule.ExtractTxBundles(arrayTxs, bundles)
		for _, newBundle := range newBundles {
			isConflict := false
			// Check for conflicts with all previous bundles
			for _, prevBundle := range bundles {
				isConflict = prevBundle.IsConflict(newBundle)
				if isConflict {
					break
				}
			}
			// Not allowing empty bundles
			if !isConflict && len(newBundle.BundleTxs) > 0 {
				bundles = append(bundles, newBundle)
			}
		}
	}

	// Coordinate target tx hash of bundles. It assumes the Gasless and Auction modules only currently.
	// This reordering does not break the execution result.
	// For example, if bundle reordering breaks the nonce ordering, the execution result will be different.
	bundles = coordinateTargetTxHash(bundles)

	incorporatedTxs, err := IncorporateBundleTx(arrayTxs, bundles)
	if err != nil {
		return flattenedTxs, nil
	}

	return incorporatedTxs, bundles
