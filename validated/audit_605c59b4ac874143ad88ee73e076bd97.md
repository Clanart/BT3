### Title
Serialized `ReceivedOutput` offset is trusted without re-binding to `script_pubkey`, letting attacker-supplied bytes re-attribute an output to a different group key - (networks/bitcoin/src/wallet/mod.rs)

### Summary

The PostgreSQL flaw class: a secondary operation reuses the basic parameters of a session while silently dropping the security-relevant ones, so a different security context is applied than was negotiated. In Serai, `ReceivedOutput` is the local record proving "this UTXO is spendable by `group_key + offset·G`". Its `offset` is the security-relevant parameter linking the on-chain `script_pubkey` to the key the threshold group must sign with. `ReceivedOutput::read` deserializes `offset` and `output` (the `TxOut` carrying `script_pubkey`) as independent fields and never checks that `script_pubkey == P2TR(scanner_key + offset·G)`. Downstream, `Output::key()` reconstructs the owning key as `scriptKey - offset·G`, so any tampered offset silently re-attributes the output to a different key.

### Finding Description

- `ReceivedOutput` stores `{ offset: Scalar, output: TxOut, outpoint }` with no binding between them: [1](#0-0) 
- `ReceivedOutput::read` reads `offset` via `Secp256k1::read_F` and the `TxOut`/`OutPoint` via consensus decoding, then returns them verbatim — no consistency check that `output.script_pubkey` equals `p2tr_script_buf(key + offset·G)`: [2](#0-1) 
- The owning key is *derived* from the pair rather than stored: `key() = XOnly(script_pubkey) - offset·G`. A forged `(offset', script)` pair yields `key' = scriptKey - offset'·G`, an arbitrary shifted point: [3](#0-2) 
- `Output::read` (the same untrusted-byte path) wraps `ReceivedOutput::read` directly: [4](#0-3) 
- The `Scanner` itself only produces correct `offset`/`script_pubkey` pairs by construction (`scripts: HashMap<ScriptBuf, Scalar>` is keyed on the script), so the invariant is enforced at scan time but is *dropped* at serialization/read time — exactly the shape of the advisory: the reconnect path (`read`) keeps the basic params (`TxOut`) but drops the security binding (offset ↔ script): [5](#0-4) 
- When signing, `SignableTransaction::multisig` applies `output.offset()` to the threshold keys (`keys.offset(offset)`), so a tampered offset steers which key the signers produce a signature for.

### Impact Explanation

An unprivileged party who can feed `ReceivedOutput::read` / `Output::read` bytes (the prompt's in-scope untrusted-byte sinks, e.g. relayed/scanned output records) can:

1. **Misattribute funds**: craft `(offset', script)` such that `scriptKey - offset'·G` equals a *different* registered multisig key `K2`. `output.key()` returns `K2`, so the processor records a received output under `K2` that is actually locked to `K1`'s script path — funds reported received under a key that cannot spend them, or credited to the wrong multisig.
2. **Cause unspendable/"burned" outputs**: any `offset'` not matching the true registered offset produces a signature under `group + offset'·G` which fails verification against the on-chain key, so the credited funds can never actually be moved.
3. **Evade duplicate-output handling**: because `key()` is recomputed from the forged pair, the same on-chain outpoint can be presented under multiple derived keys, confusing the `seen` de-duplication logic that keys on `output.id()`/key attribution.

This is `Medium`/`High` impact: it is a direct analogue of CVE-2020-25694 — the security context (the key↔offset binding) is silently replaced by attacker-supplied data on the secondary path.

### Likelihood Explanation

Requires an attacker to get malicious serialized `ReceivedOutput`/`Output` bytes consumed by a processor — plausible wherever these records transit authenticated-but-not-authoritative channels or shared storage rather than being produced purely by the local `Scanner`. It does not require threshold collusion, malicious validators, or key material — only the ability to supply untrusted bytes to the listed `read` functions. The invariant violation is deterministic once bytes are accepted: `key()` has no way to detect the forgery because the script is not re-derived from `key + offset·G`.

### Recommendation

- In `Output::key()` / when consuming a deserialized `ReceivedOutput`, recompute `p2tr_script_buf(key() + offset·G)` and assert it equals `output.script_pubkey`; reject the record otherwise. Alternatively store the derived key at scan time and verify on `read`.
- Treat `ReceivedOutput` as a claim, not a proof: re-run `Scanner::scan_transaction`-style matching against the registered key set before crediting/spending.
- Make `Output::read` re-validate `kind`/`presumed_origin`/`offset` consistency rather than trusting all three serialized fields independently.

### Proof of Concept

1. Let the honest scan produce `out = Scanner::scan_transaction(tx)` with `out.offset() = o` and `script = P2TR(K + o·G)`, where `K` is the multisig key.
2. Attacker crafts bytes: `offset' = o + d` for `d ≠ 0`, keeping `script` and `outpoint` unchanged, serialized per `ReceivedOutput::write` (`offset.to_bytes() ‖ TxOut ‖ OutPoint`).
3. Feed to `Output::read` → `ReceivedOutput::read`. `read` succeeds (no binding check).
4. `output.key()` returns `(K + o·G) - (o+d)·G = K - d·G`. Choose `d` so `K - d·G` equals another registered/expected key `K2` (e.g., a sibling offset `K + o_2·G` gives `d = o - o_2`, known public offsets like `hash_to_F(KEY_DST, "branch"|"change"|"forward")` from `processor/src/networks/bitcoin.rs:333-344` are computable by anyone).
5. Result: the processor attributes the outpoint to `K2`. Signing for it uses `keys.offset(o + d)`, producing a signature under `K + d·G` that the on-chain key `K + o·G` rejects — funds are reported received (under `K2`) yet are unspendable, a concrete integrity violation reachable purely through untrusted deserialization.

  /// Scan a transaction.
  pub fn scan_transaction(&self, tx: &Transaction) -> Vec<ReceivedOutput> {
    let mut res = Vec::new();
    for (vout, output) in tx.output.iter().enumerate() {
      // If the vout index exceeds 2**32, stop scanning outputs
      let Ok(vout) = u32::try_from(vout) else { break };

      if let Some(offset) = self.scripts.get(&output.script_pubkey) {
        res.push(ReceivedOutput {
          offset: *offset,
          output: output.clone(),
          outpoint: OutPoint::new(tx.compute_txid(), vout),
        });
      }
    }
    res
  }
