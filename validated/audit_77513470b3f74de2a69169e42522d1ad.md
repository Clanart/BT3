### Title
Unprivileged front-running of `multiclaimFor` forces victims' vlMGP-pool MGP through `queueMGP` at an attacker-chosen timestamp, maximizing forfeiture and redistributing yield to other stakers - ([File: rewards/vlMGPBaseRewarder.sol])

### Summary
`MasterMagpie.multiclaimFor` is a public, unpermissioned function that lets anyone force-claim any account's accrued rewards, including the vlMGP pool's MGP emissions, which are routed to `vlMGPBaseRewarder.queueMGP`. Because `queueMGP`'s forfeiture calculation (`_calExpireForfeit`) reads `vlMGP.getRewardablePercentWAD(_account)` at the *call time* rather than at accrual time, an attacker can time (front-run) the forced claim to a moment when the victim's rewardable percentage is low, permanently converting a larger share of the victim's accrued MGP into "forfeited" rewards that get folded pro-rata into `rewardPerTokenStored` for current vlMGP stakers.

### Finding Description
`multiclaimFor` has no access control beyond `whenNotPaused` and simply calls `_multiClaim(_stakingTokens, _account, _account, _rewardTokens)` for an arbitrary `_account` chosen by the caller [1](#0-0) . Inside `_multiClaim`, any pending MGP for the `vlmgp` staking token is accumulated into `vlMGPPoolAmount` and routed via `_sendMGPForVlMGPPool(_user, _receiver, vlMGPPoolAmount)` [2](#0-1) , which internally calls `vlMGPBaseRewarder.queueMGP`.

`queueMGP` computes the forfeit amount strictly as a function of the account's *current* `getRewardablePercentWAD`: [3](#0-2) 

```

    ...
    uint256 forfeitAmount = _calExpireForfeit(_account, _amount);
    uint256 rewardableAmount = _amount - forfeitAmount;
    if (forfeitAmount > 0)
        _queueNewRewardsWithoutTransfer(forfeitAmount, address(vlMGP.MGP()));
    if (rewardableAmount > 0) {
        IERC20(vlMGP.MGP()).safeTransfer(_receiver, rewardableAmount);
        ...
```

`_calExpireForfeit` pulls the live `rewardablePercentWAD` at the moment of the call: [4](#0-3) 

Because this value is read at the transaction's timestamp rather than snapshotted when the reward was originally accrued, and because `multiclaimFor` lets *any* address trigger this claim on the victim's behalf at a time the attacker chooses, an attacker can wait for or engineer a moment when the victim's `rewardablePercentWAD` dips (e.g., immediately after a partial unlock event before the value climbs back toward full maturity) and immediately call `multiclaimFor([vlmgp], [[]], victim)`. This locks in a larger `forfeitAmount` than the victim would have incurred by self-claiming at a more favorable time (e.g., at full lock maturity). The forfeited MGP is not burned or refunded to the victim — it is folded into `rewardPerTokenStored` via `_queueNewRewardsWithoutTransfer`, redistributing it pro-rata to whoever currently holds a vlMGP stake in the rewarder, including the attacker if the attacker also stakes vlMGP [5](#0-4) .

Crucially, once `queueMGP` executes, `unClaimedMgp[_stakingToken][_user]` is zeroed and `user.rewardDebt` is updated in `_multiClaim` [6](#0-5) , making the forfeiture permanent and non-recoverable by the victim — there is no retroactive credit if the victim's rewardable percent later improves.

No existing modifier prevents this: `multiclaimFor` only checks `whenNotPaused`; `queueMGP` is `onlyManager` (called internally by `MasterMagpie`, which is a registered manager) and `nonReentrant`, neither of which restricts *who* can trigger the claim or *when*.

### Impact Explanation
This is a theft/permanent-loss-of-unclaimed-yield vector: the victim permanently loses MGP that would have been available to them had they controlled the timing of their own claim, and that value is redistributed to other current vlMGP stakers (potentially including the attacker, if the attacker also stakes vlMGP). This matches the "theft or permanent freezing of unclaimed yield" Immunefi impact class. The magnitude of loss scales with the victim's accrued unclaimed MGP in the vlMGP pool and the delta in `rewardablePercentWAD` between the forced-claim moment and the victim's optimal self-claim moment.

### Likelihood Explanation
- No privileged role is required; `multiclaimFor` is fully public.
- The attacker needs no capital or token holdings to trigger the call against the victim (only gas), though to *capture* redistributed value directly the attacker would need an existing vlMGP stake (which they can acquire cheaply/permissionlessly by locking MGP, and the proof idea explicitly assumes this).
- The attack is repeatable against any victim with unclaimed vlMGP-pool MGP whenever their `rewardablePercentWAD` is temporarily below their eventual/maximum value, and can be automated to front-run/monitor mempool state or be triggered right after events that cause temporary dips.
- Full confirmation of the exact conditions under which `getRewardablePercentWAD` dips (e.g., tied to `VLMGP.sol`'s unlock/lock-maturity schedule) could not be independently verified in this pass since `VLMGP.sol`'s `getRewardablePercentWAD` implementation was not retrieved; the analysis above relies on the documented behavior in `_calExpireForfeit`/`calExpireForfeit` and the premise stated in the question. This should be verified against `VLMGP.sol` directly.

### Recommendation
Do not let arbitrary third parties force a claim that permanently locks in a forfeiture based on a value (`rewardablePercentWAD`) the victim does not control the timing of. Options:
- Restrict `multiclaimFor` (or specifically the vlMGP-pool branch) to only be callable by the account itself, an approved operator, or the compounder, removing the fully-permissionless "claim for anyone" path for pools subject to `queueMGP` forfeiture logic.
- Alternatively, snapshot/lock in `rewardablePercentWAD` at accrual time per unit of MGP rather than at claim time, so forced-claim timing cannot change the forfeiture ratio.
- Add a mechanism so that when a claim is forced by a third party, the victim's realized `rewardablePercentWAD` cannot be worse than their historical maximum since last claim.

### Proof of Concept
Foundry test plan:
1. Deploy `MasterMagpie`, `VLMGP`, and `vlMGPBaseRewarder`, register the `vlmgp` pool.
2. Set up two users: `victim` and `attacker`, both lock MGP into `vlmgp` at different maturities such that `attacker`'s `rewardablePercentWAD` stays high while `victim`'s temporarily dips (e.g., right after a partial relock/unlock event) before climbing to 100% at full maturity.
3. Let MGP emissions accrue to both users' vlMGP-pool positions via `MasterMagpie.updatePool`/time warps.
4. Baseline: warp to when `victim.getRewardablePercentWAD == 1e18` (full maturity) and have `victim` self-claim via `multiclaimSpec([vlmgp], [[]])`; record `victimBaselineReceived`.
5. Reset state (or run as a separate branch with the same starting conditions): warp to the moment `victim`'s `rewardablePercentWAD` is at its lowest dip, and have `attacker` call `multiclaimFor([vlmgp], [[]], victim)` with `attacker` holding no MGP of their own beyond their existing vlMGP stake.
6. Assert:
   - `victim`'s net MGP received from the forced claim (`victimForcedReceived`) is strictly less than `victimBaselineReceived`.
   - `vlMGPBaseRewarder.rewards[MGP].rewardPerTokenStored` increased by the forfeited amount divided by `totalStaked()`.
   - `attacker`'s `userRewards[MGP][attacker]` (via `earned(attacker, MGP)`) increases as a result of the forced claim, purely from holding vlMGP stake at the time of the forced call, without attacker performing any self-claim action.
   - `unClaimedMgp[vlmgp][victim]` is zeroed and cannot be reclaimed later even if `victim`'s `rewardablePercentWAD` later returns to 100%.

```text
    function queueMGP(uint256 _amount, address _account, address _receiver) override external onlyManager nonReentrant returns (bool) {
        IERC20(vlMGP.MGP()).safeTransferFrom(msg.sender, address(this), _amount);
        
        uint256 forfeitAmount = _calExpireForfeit(_account, _amount);
        uint256 rewardableAmount = _amount - forfeitAmount;
        
        if (forfeitAmount > 0)
            _queueNewRewardsWithoutTransfer(forfeitAmount, address(vlMGP.MGP()));

        if (rewardableAmount > 0) {
            IERC20(vlMGP.MGP()).safeTransfer(_receiver, rewardableAmount);
            emit MGPHarvested(_account, rewardableAmount, forfeitAmount);
        }

        return true;
    }
```

```text
    function _queueNewRewardsWithoutTransfer(uint256 _amountReward, address _rewardToken) internal
    {
        Reward storage rewardInfo = rewards[_rewardToken];
        rewardInfo.historicalRewards = rewardInfo.historicalRewards + _amountReward;
        if (totalStaked() == 0) {
            rewardInfo.queuedRewards += _amountReward;

            if (rewardInfo.queuedRewards > 0) {
                _amountReward += rewardInfo.queuedRewards;
                rewardInfo.queuedRewards = 0;

                rewardInfo.rewardPerTokenStored +

    }
```

```text
    function _calExpireForfeit(address _account, uint256 _amount) internal view returns (uint256) {
        uint256 rewardablePercentWAD = vlMGP.getRewardablePercentWAD(_account);
        uint256 rewardableAmount = _amount * rewardablePercentWAD / 1e18;
        if (rewardableAmount > _amount)
            revert InvalidRewardableAmount();

        uint256 forfeitAmount = _amount - rewardableAmount;
        
        if (forfeitAmount < (_amount / 1000)) {  // if forfeitAmount is smaller than 0.1% ignore to save gas fee
            forfeitAmount = 0;
            rewardableAmount = _amount;
        }

        return forfeitAmount;
    }
```
