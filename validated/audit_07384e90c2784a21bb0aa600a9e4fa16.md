### Title
Uncontrolled recursion in `AccountKeyRoleBased.DecodeRLP` allows unbounded stack growth from a single crafted transaction - ([File: blockchain/types/accountkey/account_key_role_based.go])

### Summary
`NewAccountKey` places no restriction on nesting: an `AccountKeyTypeRoleBased` key can legally contain another `AccountKeyTypeRoleBased` key as one of its elements at the raw RLP-decoding layer. `AccountKeyRoleBased.DecodeRLP` recursively calls `rlp.DecodeBytes` on each role's serialized key blob, which for a nested `RoleBased` entry re-enters `AccountKeyRoleBased.DecodeRLP` again. The only defense against nested composite keys (`kerrors.ErrNestedCompositeType`, enforced in `AccountKeyRoleBased.CheckInstallable`/`CheckUpdatable`) runs **after** decoding completes, so the recursive decode itself is unguarded.

### Finding Description
- `AccountKeyRoleBased.DecodeRLP` ( [1](#0-0) ) decodes a `[][]byte`, then for each byte-slice entry calls `rlp.DecodeBytes(b, &serializer)` where `serializer` is an `AccountKeySerializer`.
- `AccountKeySerializer.DecodeRLP` ( [2](#0-1) ) reads a `keyType`, calls `NewAccountKey(keyType)` and then `s.Decode(serializer.key)`.
- `NewAccountKey` ( [3](#0-2) ) happily instantiates `AccountKeyTypeRoleBased` again for any nested entry, with no depth check, so `s.Decode(serializer.key)` re-invokes `AccountKeyRoleBased.DecodeRLP`, creating recursion: `DecodeRLP → rlp.DecodeBytes → AccountKeySerializer.DecodeRLP → NewAccountKey → s.Decode → DecodeRLP → ...`
- The only rejection of nested "composite" keys is `IsCompositeType()`/`ErrNestedCompositeType`, checked in `CheckInstallable`/`CheckUpdatable` ( [4](#0-3) ) — these run only **after** the whole structure has already been fully RLP-decoded (e.g., in tx pool validation / state transition), so the check cannot prevent the recursive decode from happening first.
- This decode path is reached whenever a raw transaction is parsed: e.g. `SendRawTransaction`/`SendRawTransactions` in the public RPC ( [5](#0-4) ) calls `rlp.DecodeBytes(encodedTx, tx)`, which for `TxTypeAccountUpdate`/`TxTypeFeeDelegatedAccountUpdate*` dispatches to `TxInternalDataSerializer.DecodeRLP` ( [6](#0-5) ) → the corresponding tx's `fromSerializable`, which calls `rlp.DecodeBytes(serialized.Key/KeyData, serializer)` on the `AccountKeySerializer` (e.g. [7](#0-6) , [8](#0-7) ). It is also reachable via `KaiaAPI.DecodeAccountKey` ( [9](#0-8) ), which decodes attacker-supplied bytes with no validation at all.
- Because there is no explicit recursion-depth limit, an attacker only needs to make an RLP payload deep enough (bounded only by the 32 KB tx-size limit, `MaxTxDataSize`, or the unbounded input to `DecodeAccountKey`) to drive the decode into thousands of nested calls, each spanning multiple Go stack frames (`DecodeRLP` → reflect-based `decoder`/`makeDecoder` chain → `rlp.DecodeBytes` → `Stream.Decode`). Go grows goroutine stacks dynamically but aborts the whole process with an unrecoverable `runtime: goroutine stack exceeds ... - fatal error: stack overflow` once the maximum stack size is hit; this cannot be caught by `recover()`, so it crashes the node process. This mirrors the CVE-2020-22885 bug class: recursion depth unbounded by an external input causes stack exhaustion during a scanning/decoding phase.

### Impact Explanation
Any unprivileged transaction sender (or any public RPC caller, since `DecodeAccountKey` needs no signature at all) can craft an `AccountUpdate`/`FeeDelegatedAccountUpdate*`-type payload, or a raw `AccountKeySerializer` blob, containing deeply self-nested `AccountKeyTypeRoleBased` entries. Submitting it via `eth_sendRawTransaction`/`kaia_sendRawTransaction`, `kaia_sendRawTransactions`, or `kaia_decodeAccountKey` forces the receiving node (including any full node, RPC node, or block producer decoding the block containing such a transaction) to recursively decode the structure, crashing the process with a fatal, unrecoverable stack-overflow error. This is a remote, unauthenticated denial-of-service against any Kaia node that processes the transaction (mempool ingestion, RPC endpoint, or block execution), matching the severity class of the underlying CVE (network-reachable DoS via uncontrolled recursion).

### Likelihood Explanation
High likelihood: no special privileges, staking, or governance access is required — a plain `AccountUpdate` transaction (or even an unsigned `kaia_decodeAccountKey` RPC call) suffices, and the nesting depth achievable within the transaction-size limit is large enough (each nesting adds only a handful of RLP overhead bytes within a ~32 KB payload) to exceed typical Go stack-growth limits before any validation logic (`CheckInstallable`/`ErrNestedCompositeType`) executes.

### Recommendation
Enforce a strict recursion-depth (or explicit "no nested RoleBased" check) directly inside `AccountKeySerializer.DecodeRLP` / `AccountKeyRoleBased.DecodeRLP` (rather than only after decode completes in `CheckInstallable`), rejecting any `AccountKeyTypeRoleBased` value found while already decoding within a `RoleBased` context. Apply the same guard, unconditionally, to `KaiaAPI.DecodeAccountKey` and `KaiaAPI.EncodeAccountKey`, since these currently perform no depth/composite-type validation before or during decode.

### Proof of Concept
Conceptually (cannot be executed here, but the flow is directly derivable from the code):
1. Build an `AccountKeySerializer` for `AccountKeyTypeRoleBased` whose single "key" is itself an RLP-encoded `AccountKeySerializer` of type `AccountKeyTypeRoleBased`, and repeat this nesting N times (N large enough, e.g. thousands, while total payload stays under `MaxTxDataSize`/32 KB, or unlimited if targeting `kaia_decodeAccountKey` directly which has no size cap).
2. Wrap the innermost with a legitimate account key.
3. Either:
   - Embed the resulting `KeyData`/`Key` bytes in a `TxTypeAccountUpdate` (or `TxTypeFeeDelegatedAccountUpdate*`) transaction and submit via `kaia_sendRawTransaction`, or
   - Call `kaia_decodeAccountKey` directly with the crafted bytes.
4. On the receiving node, `rlp.DecodeBytes` recurses through `AccountKeyRoleBased.DecodeRLP` → `AccountKeySerializer.DecodeRLP` → `NewAccountKey` → repeat, N times, before any `CheckInstallable`/`ErrNestedCompositeType` validation is reached, exhausting the goroutine stack and crashing the node process with a fatal runtime error.

func (a *AccountKeyRoleBased) DecodeRLP(s *rlp.Stream) error {
	enc := [][]byte{}
	if err := s.Decode(&enc); err != nil {
		return err
	}

	keys := make([]AccountKey, len(enc))
	for i, b := range enc {
		serializer := NewAccountKeySerializer()
		if err := rlp.DecodeBytes(b, &serializer); err != nil {
			return err
		}
		keys[i] = serializer.key
	}

	*a = (AccountKeyRoleBased)(keys)

	return nil
}

func (a *AccountKeyRoleBased) CheckInstallable(currentBlockNumber uint64) error {
	// A zero-role key is not allowed.
	if len(*a) == 0 {
		return kerrors.ErrZeroLength
	}
	// Do not allow undefined roles.
	if len(*a) > (int)(RoleLast) {
		return kerrors.ErrLengthTooLong
	}
	for i := 0; i < len(*a); i++ {
		// A composite key is not allowed.
		if (*a)[i].IsCompositeType() {
			return kerrors.ErrNestedCompositeType
		}
		// If any key in the role cannot be initialized, return an error.
		if err := (*a)[i].CheckInstallable(currentBlockNumber); err != nil {
			return err
		}
	}
	return nil
}

func (s *KaiaTransactionAPI) SendRawTransactions(ctx context.Context, inputs []hexutil.Bytes) ([]common.Hash, error) {
	hash := []common.Hash{}
	errs := []error{}

	if len(inputs) == 0 {
		hash = append(hash, common.Hash{})
		return hash, errors.New("Empty input")
	}

	for i, input := range inputs {
		if len(input) == 0 {
			hash = append(hash, common.Hash{})
			errs = append(errs, fmt.Errorf("Index %d: empty input", i))
			break
		}
		// Allow naked Ethereum tx types

			hash = append(hash, common.Hash{})
			errs = append(errs, fmt.Errorf("Index %d: %w", i, err))

func (serializer *TxInternalDataSerializer) DecodeRLP(s *rlp.Stream) error {
	if err := s.Decode(&serializer.txType); err != nil {
		// fallback to the original transaction decoding.
		txd := newEmptyTxInternalDataLegacy()
		if err := s.Decode(txd); err != nil {
			return err
		}
		serializer.txType = TxTypeLegacyTransaction
		serializer.tx = txd
		return nil
	}

	if serializer.txType == EthereumTxTypeEnvelope {
		var ethType TxType
		if err := s.Decode(&ethType); err != nil {
			return err
		}
		serializer.txType = serializer.txType<<8 | ethType
	}

	var err error
	serializer.tx, err = NewTxInternalData(serializer.txType)
	if err != nil {
		return err
	}

	return s.Decode(serializer.tx)
}
