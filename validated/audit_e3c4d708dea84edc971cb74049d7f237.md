### Title
Copilot conflict resolution splices unbounded, unverified LLM output into files with no deviation/sanity check against the original conflicting content - (File: `app/src/lib/copilot-conflict-resolution.ts`)

### Summary
The external report's core defect is a broken invariant: an oracle value crossing a trust boundary (an LST exchange rate) is consumed and acted upon by the protocol without any check that it stays within an expected deviation from a reference (market price / expected growth), so an attacker-influenced value can flow straight into asset transfers. The structurally equivalent invariant in GitHub Desktop is in the Copilot-based merge/rebase/cherry-pick conflict resolution feature: content taken from a conflicting branch/PR (which is fully attacker-controlled when merging a fork or reviewing an incoming branch) is fed to an LLM, and the LLM's `resolvedContent` for each hunk is spliced back into the file and staged with **no deviation/sanity check** against the original `ours`/`theirs`/`base` content — only shape/format checks are performed.

### Finding Description
`parseCopilotConflictResolution` in `app/src/lib/copilot-conflict-resolution.ts` (lines 379-463) validates only that each hunk's `resolvedContent` is a string and does not still contain literal `<<<<<<<`/`=======` conflict markers: [1](#0-0) 

`validateResolutionPaths` (lines 473-521) only checks that the returned file paths match the expected conflicted files and that the *number* of hunks per file matches the *number* of conflicts detected in that file — it never inspects the hunk *content*: [2](#0-1) 

`reassembleResolvedFile` (lines 549-599) then blindly splices whatever string the model returned in place of each conflict marker block, with no length cap, no similarity/diff check against the `ours`/`theirs` hunk content, and no verification that the replacement is actually related to the two sides being merged: [3](#0-2) 

Finally, `_applyCopilotConflictResolutions` in `app/src/lib/stores/app-store.ts` writes this content straight to disk and `git add`s it once the user clicks "Continue Merge": [4](#0-3) 

The conflicting hunk content itself — which originates from the "theirs" side of a merge, i.e., a branch, fork, or pull request the user did not author — is placed directly into the LLM prompt (per the system prompt's own description of its inputs): [5](#0-4) 

Because the only guardrails are "right shape JSON," "right file paths," "right hunk count," and "no literal conflict markers," an attacker who crafts a conflicting branch/PR with an embedded prompt-injection payload (e.g. a code comment instructing the model to "also replace the following unrelated function with this implementation" or to exfiltrate/insert arbitrary code while resolving the conflict) can cause the model's `resolvedContent` to contain content that has nothing to do with the actual conflicting lines. `reassembleResolvedFile` will happily splice this into the file, and the app will write and stage it without ever comparing it back against the two original sides or bounding its size/shape. This is the direct analogue of the missing on-chain deviation check: a value crossing a trust boundary (LLM output derived from attacker-supplied repo content) is acted upon (written to disk, staged for commit) without validating it stays within any expected bound relative to the known-good reference values (the original `ours`/`theirs`/`base` hunk text).

### Impact Explanation
If successful, this results in silent corruption of what the user commits and, if they push without close inspection, what they push — one of the explicitly valid impact categories (silent corruption of what the user commits or pushes). The user is shown a reasoning/summary text and a resolution dialog, but nothing in the validated pipeline guarantees the displayed reasoning text matches the actual spliced content, and there is no automated check preventing wildly divergent injected code from being accepted as a "hunk resolution." A user who trusts the Copilot resolution and clicks "Continue Merge" — the intended supported workflow — can unknowingly commit attacker-influenced code.

### Likelihood Explanation
Exploitation requires: (1) the attacker's branch/PR to be involved in a merge/rebase/cherry-pick that produces textual conflicts, (2) the victim to use the Copilot conflict-resolution feature (an explicit, but increasingly promoted, opt-in path per the changelog), and (3) a working prompt-injection payload against whatever underlying model is used, which is inherently probabilistic and model-dependent. This makes the likelihood moderate-to-low compared to a deterministic financial exploit, but it satisfies the required attacker primitive (content in a cloned/fetched/merged repository is attacker-controlled) without requiring local access, admin rights, prior malware, or leaked credentials.

### Recommendation
Add a bounded "deviation check" analogous to the oracle mitigations proposed in the source report:
- Reject or flag any `resolvedContent` whose diff against the union of `ours`/`theirs`/`base` hunk content exceeds a reasonable similarity/size threshold (e.g., using a line-level diff to ensure the resolution is drawn from the two conflicting sides plus minor edits, not wholesale unrelated content).
- Enforce a maximum length ratio between `resolvedContent` and the larger of the two original hunk sides.
- Surface a real diff (original hunk vs. proposed resolution) in the review UI rather than only reasoning text, so a human review step can catch injected content before staging.
- Consider stripping/neutralizing instructive text inside conflict hunks before constructing the prompt, to reduce susceptibility to prompt injection from repository content.

export function validateResolutionPaths(
  resolutions: ReadonlyArray<IRawFileResolution>,
  expectedFiles: ReadonlyArray<IFileConflictContext>
): void {
  const expectedPaths = new Set(expectedFiles.map(f => f.path))
  const expectedHunkCounts = new Map(
    expectedFiles.map(f => [f.path, f.hunks.length])
  )
  const returnedPaths = new Set(resolutions.map(r => r.path))

  for (const path of returnedPaths) {
    if (!expectedPaths.has(path)) {
      throw new CopilotValidationError(
        `Copilot returned resolution for unexpected file: ${path}`
      )
    }
  }

  if (returnedPaths.size !== resolutions.length) {
    throw new CopilotValidationError(
      'Copilot returned duplicate file paths in resolutions'
    )
  }

  const missingPaths: Array<string> = []
  for (const path of expectedPaths) {
    if (!returnedPaths.has(path)) {
      missingPaths.push(path)
    }
  }
  if (missingPaths.length > 0) {
    throw new CopilotValidationError(
      `Copilot did not return resolutions for: ${missingPaths.join(', ')}`
    )
  }

  for (const resolution of resolutions) {
    // Delete-vs-modify resolutions use action instead of hunks — skip count check
    if (resolution.action !== undefined) {
      continue
    }
    const expectedCount = expectedHunkCounts.get(resolution.path) ?? 0
    if (resolution.hunks.length !== expectedCount) {
      throw new CopilotValidationError(
        `Copilot returned ${resolution.hunks.length} hunk(s) for "${resolution.path}" but expected ${expectedCount}`
      )
    }
  }
}

export function reassembleResolvedFile(
  rawContent: string,
  hunkResolutions: ReadonlyArray<IHunkResolution>
): string {
  const eol = rawContent.includes('\r\n') ? '\r\n' : '\n'
  const lines = rawContent.split(/\r?\n/)
  const resultLines: Array<string> = []
  let hunkIndex = 0
  let i = 0

  while (i < lines.length) {
    if (reassemblyOursMarker.test(lines[i])) {
      // Look ahead to verify this is a well-formed conflict block:
      // must have a ======= separator and a >>>>>>> closing marker.
      let hasSeparator = false
      let closingIndex = -1
      for (let j = i + 1; j < lines.length; j++) {
        if (reassemblySeparatorMarker.test(lines[j])) {
          hasSeparator = true
        } else if (reassemblyTheirsMarker.test(lines[j])) {
          closingIndex = j
          break
        }
      }

      if (!hasSeparator || closingIndex === -1) {
        // Malformed marker — copy through as regular content
        resultLines.push(lines[i])
        i++
        continue
      }

      // Skip through the entire conflict marker block
      i = closingIndex + 1

      // Splice in the resolved content for this hunk
      if (hunkIndex < hunkResolutions.length) {
        const resolved = hunkResolutions[hunkIndex].resolvedContent
        if (resolved.length > 0) {
          resultLines.push(...resolved.split(/\r?\n/))
        }
      }
      hunkIndex++
    } else {
      resultLines.push(lines[i])
      i++
    }
  }

  return resultLines.join(eol)
}
