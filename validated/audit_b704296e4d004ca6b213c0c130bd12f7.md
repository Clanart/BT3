## Title
Duplicate/replayed `VoteAggregate` inflates accumulated stake without deduplication in `AggregateAccumulator::add_aggregate` - ([File: votor/src/aggregate_accumulator.rs])

## Summary
`AggregateAccumulator::add_aggregate`, used by the consensus vote pool to accumulate BLS vote aggregates toward notarization/finalization certificate thresholds, unconditionally adds the incoming aggregate's stake to the running total without checking whether the ranks it represents have already been counted. This mirrors the reported Solidity bug class exactly: a signature/vote from an already-counted signer is counted again toward a threshold, because the counter increments unconditionally instead of checking a "already seen" set before incrementing.

## Finding Description
`AggregateAccumulator::add_aggregate` in `votor/src/aggregate_accumulator.rs`: [1](#0-0) 

```rust
pub fn add_aggregate(
    &mut self,
    aggregate: &VoteAggregate,
) -> Result<u64, AggregateAccumulatorError> {
    self.signature
        .aggregate_with(std::iter::once(aggregate.signature()))
        .map_err(AggregateAccumulatorError::SignatureAggregationFailed)?;
    self.ranks |= aggregate.ranks();
    self.stake = self.stake.saturating_add(aggregate.stake().get());
    Ok(self.stake)
}
```

`self.ranks |= aggregate.ranks()` is an idempotent bitwise-OR — the bitmap correctly stays deduplicated. However, `self.stake` is *unconditionally* incremented by `aggregate.stake()`, with no check for whether the incoming ranks overlap ranks already present in `self.ranks`. This is in stark contrast to the sibling method `add_own_vote_message` in the same file, which explicitly guards against double counting: [2](#0-1) 


`add_own_vote_message` proves the codebase authors are aware duplicates must be checked before incrementing stake — but the same discipline was not applied to `add_aggregate`, the path used for *externally received* vote batches, which is the higher-risk input surface.

This accumulator directly drives certificate-threshold decisions in `VotePool::add_pool_vote` (`votor/src/consensus_pool/vote_pool.rs`), which is fed by `PoolVote::External` aggregates coming from the network (via `bls-sigverify`): [3](#0-2)

If the same underlying `VoteAggregate` (same rank set / same signer stake) is delivered to `add_pool_vote` a second time — e.g. via gossip retransmission, redundant delivery paths, or simply a validator resending its own already-broadcast vote batch — `add_aggregate` is called twice with overlapping `ranks()`. The bitmap stays correct (OR is idempotent) but `self.stake` is credited twice for the same real stake. Nothing downstream of `add_aggregate` (neither the accumulator nor `try_build_base2_cert`/`try_build_base3_cert`) recomputes stake from `self.ranks.count_ones()` mapped through the rank→stake table before comparing to `cert_type.threshold()` — it trusts the incrementally-accumulated `self.stake` value.

This is precisely the C-01 bug class: a validated, individually-legitimate signature/vote is replayed and counted an extra time toward a threshold because the accumulator increments a counter unconditionally instead of checking whether the contributing identity (here: rank/bit position) was already counted before adding its weight.

## Impact Explanation
This affects the local validator's decision of whether a supermajority (notarize/finalize/skip) threshold has been reached for Alpenglow consensus certificates. If the perceived `self.stake` crosses the required fraction earlier than the real, unique-signer stake actually does (due to double-counted duplicate aggregates), the victim validator can:
- Falsely conclude a slot is notarized/finalized and emit `VotorEvent`s (vote/finalize) based on insufficient real backing stake, corrupting its local view of consensus state (false acceptance).
- This is a false-execution/false-acceptance class bug (a corrupted `stake` value driving threshold comparisons) directly in the runtime's consensus certificate-construction logic, matching the "false execution/rooting/acceptance" impact category. It does not require a malicious validator — ordinary duplicate delivery of a validator's own legitimately-signed vote (redundant gossip paths, retransmission) is sufficient to trigger double counting, since no assumption about a malicious peer/validator is needed for the underlying primitive (only that the same valid vote artifact reaches the accumulator twice).

Note: any certificate broadcast externally is subject to independent re-verification by `bls-cert-verify::verify_certificate` on other nodes, which recomputes stake purely from the certificate's bitmap (using `iter_ones`, which is inherently deduplicated) — so a certificate with an inflated internally-tracked `self.stake` but a bitmap that doesn't actually meet the threshold would likely be rejected by peers when independently re-verified. The primary confirmed impact is therefore on the *local* threshold-crossing decision inside this validator's own vote pool (used to decide when a certificate is even attempted, and to drive local `VotorEvent`s), rather than a guaranteed cross-network certificate forgery.

## Likelihood Explanation
Likelihood is High: duplicate delivery of the same vote/aggregate is a routine occurrence in a gossip-based, redundant-path network (retransmission, multiple relayers, node restarts causing rebroadcast), and no adversarial coordination or leaked keys are required — it only takes an aggregate whose ranks were already counted being routed to `add_aggregate` a second time.

## Recommendation
In `AggregateAccumulator::add_aggregate`, check for overlap between `aggregate.ranks()` and the already-accumulated `self.ranks` before crediting new stake (analogous to the `Duplicate` check already implemented in `add_own_vote_message`), e.g. reject/no-op on any overlapping rank, or only add stake for ranks that are newly set by the OR operation (compute `let newly_set = !self.ranks.clone() & aggregate.ranks()` before updating `self.ranks`, and only sum stake for the newly-set ranks — this requires per-rank stake lookup rather than a single aggregate-level `stake()` field). Alternatively, always recompute `self.stake` from `self.ranks.iter_ones()` via the rank→stake map immediately before every threshold comparison in `try_build_base2_cert`/`try_build_base3_cert`, rather than trusting the incrementally accumulated field.

## Proof of Concept
1. Construct a `VoteAggregate` `A` for validator rank `5` with stake `S` (a single, honestly and individually signature-verified vote).
2. Deliver `A` to `VotePool::add_pool_vote` as `PoolVote::External(A)` — `AggregateAccumulator::add_aggregate` sets `self.ranks[5] = true`, `self.stake += S`.
3. Deliver the *same* `A` (or any other `VoteAggregate` whose rank set overlaps rank `5`) to `add_pool_vote` again (simulating gossip retransmission/duplicate delivery) — `add_aggregate` runs again: `self.ranks |= A.ranks()` is a no-op (rank 5 already set), but `self.stake += S` executes again, so `self.stake` is now `2S` even though only one unique validator (real weight `S`) has actually voted.
4. If `2S / total_stake` now crosses `cert_type.threshold()` while the true unique stake `S / total_stake` does not, `try_build_base2_cert` returns `Some(Certificate)` and the local vote pool treats the slot as reaching threshold, even though only one real validator's stake actually backs it.     pub fn add_aggregate(
```rust
        &mut self,
        aggregate: &VoteAggregate,
    ) -> Result<u64, AggregateAccumulatorError> {
        self.signature
            .aggregate_with(std::iter::once(aggregate.signature()))
            .map_err(AggregateAccumulatorError::SignatureAggregationFailed)?;
        self.ranks |= aggregate.ranks();
        self.stake = self.stake.saturating_add(aggregate.stake().get());
        Ok(self.stake)
    }

    /// Accumulate own vote message into the accumulator.
    ///
    /// Due to nodes restarting or failover, etc. it is possible to get duplicates.
    pub fn add_own_vote_message(
        &mut self,
        msg: &VoteMessage,
    ) -> Result<u64, AggregateAccumulatorError> {
        let mut signature = self.signature;
        signature
            .aggregate_with(std::iter::once(&msg.signature))
            .map_err(AggregateAccumulatorError::SignatureAggregationFailed)?;
        if self.ranks.replace(msg.rank as usize, true) {
            return Err(AggregateAccumulatorError::Duplicate);
        }
        self.signature = signature;
        self.stake = self.stake.saturating_add(msg.stake.get());
        Ok(self.stake)
    }

    /// Builds a base2 [`Certificate`] if its threshold is met.
    pub fn try_build_base2_cert(
        &self,
        cert_type: CertificateType,
        total_stake: NonZero<u64>,
    ) -> Result<Option<Certificate>, AggregateAccumulatorError> {
        let observed_fraction = Fraction::new(self.stake, total_stake);
        if observed_fraction < cert_type.threshold() {
            return Ok(None);
        }
        let mut ranks = self.ranks.clone();
        let new_len = ranks.last_one().map_or(0, |i| i.saturating_add(1));
        ranks.resize(new_len, false);
        let bitmap = encode_base2(&ranks).map_err(AggregateAccumulatorError::EncodingFailed)?;
        let signature = BLSSignature::from(self.signature);
        Ok(Some(Certificate {
            cert_type,
            signature,
            bitmap,
        }))
    }
```
