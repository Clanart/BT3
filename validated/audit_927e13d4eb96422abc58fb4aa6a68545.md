## Analysis: SSRF analog found in Chia DataLayer mirror/subscription mechanism

### Title
Unauthenticated attacker can force victim's DataLayer service into semi-blind SSRF via arbitrary mirror URLs - (File: `chia/data_layer/download_data.py`, `chia/data_layer/data_layer.py`, `chia/data_layer/data_layer_wallet.py`)

### Summary
`DataLayer` mirror coins let anyone publish an arbitrary URL on-chain, associated with any DataLayer store id (launcher id). Any node that subscribes to / owns that store will periodically pick up the attacker-controlled URL from wallet state and issue outbound HTTP requests to it via `aiohttp`, with no restriction on scheme, host, or port — mirroring the semi-blind SSRF pattern in the reported DNN advisory (attacker cannot see the full response, but can trigger arbitrary GET requests against internal/external hosts).

### Finding Description
A mirror coin is created by spending funds to `create_mirror_puzzle()` and embedding a `launcher_id` plus a list of URL bytes in the `CREATE_COIN` memo field: [1](#0-0) . The puzzle hash `MIRROR_PUZZLE_HASH` is fixed/public, and `get_mirror_info()` parses ANY coin creation matching that puzzle hash to extract `launcher_id` and URLs from the memos, with no ownership check tying the spender to the `launcher_id` being referenced: [2](#0-1) .

Because `launcher_id` is attacker-supplied and requires no proof of ownership or relation to the store, any unprivileged spend-bundle submitter can create a mirror coin (using only their own funds/fee) that points at a victim's arbitrary or well-known store id, with a URL of the attacker's choosing (e.g., an internal metadata endpoint, an internal admin service, or an arbitrary external target). The RPC/CLI path (`dl_new_mirror`, `add_mirror`) exists purely as convenience for legitimate use, but the underlying chain state accepts any `CREATE_COIN` with the mirror puzzle hash and memo layout: [3](#0-2) .

Once such a mirror coin is confirmed on chain, any node's `DataLayer` service that is subscribed to (or owns) that `store_id` retrieves the mirror URLs through `update_subscriptions_from_wallet()` and stores them as `ServerInfo` entries: [4](#0-3) .

During the periodic sync loop, `fetch_and_validate()` iterates these attacker-controlled `server_info.url` values and calls `insert_from_delta_file()`/`download_file()`, which — when no downloader plugin is configured — falls through to `http_download()`: [5](#0-4) .

`http_download()` performs an unrestricted `aiohttp.ClientSession().get(server_info.url + "/" + filename, ...)` request using the attacker-supplied base URL with no allow-listing, no scheme restriction, and no blocking of private/internal address ranges: [6](#0-5) .

Additionally, `get_downloader()` (used for plugin-based downloads) POSTs the attacker-supplied URL to configured downloader plugins, and `download_file()` also forwards the raw URL in a JSON payload to plugin services: [7](#0-6) [8](#0-7) .

The `.cursor/context/data-layer.md` documentation explicitly flags this as a known trust boundary: "Plugin and mirror URLs are external trust inputs... file path/name validation must stay strict" — but there is no equivalent statement or code enforcing that the destination host/IP of the mirror URL itself is restricted: [9](#0-8) .

### Impact Explanation
This lets an unauthenticated (from the victim's perspective) attacker who can only submit a spend bundle cause a victim's DataLayer service to issue outbound HTTP GET (and, for plugin configurations, POST) requests to arbitrary attacker-chosen destinations, including internal-network or loopback addresses reachable from the victim host. While the attacker cannot read the full response body (the DataLayer service treats the response as delta-file bytes and only logs size/failure/timeout information), the differing behavior on success/failure/timeout/content-length constitutes the same "semi-blind SSRF" impact class described in the DNN advisory: internal network reconnaissance and the ability to reach services normally firewalled from external access. This is reachable purely through the on-chain mirror-coin mechanism, satisfying the "unauthorized coin movement is not required" bar — this is a spend-triggered request forgery against any node that syncs the referenced store.

### Likelihood Explanation
Likelihood is moderate-to-high for nodes that run DataLayer with subscriptions/ownership of public stores, since creating a mirror coin only requires a small amount of XCH and a public `launcher_id` (store ids are typically public/known for shared datasets). No cooperation from the victim beyond normal DataLayer sync operation (`periodically_manage_data()` → `update_subscription()` → `fetch_and_validate()`) is required.

### Recommendation
Validate/allow-list mirror and downloader URLs before dereferencing them in `http_download()`, `get_downloader()`, and `download_file()` — e.g., reject non-HTTP(S) schemes, resolve and block RFC1918/loopback/link-local addresses, and/or require explicit user opt-in per mirror URL/domain rather than automatically trusting anything published on-chain for a subscribed store.

### Proof of Concept
1. Attacker calls `dl_new_mirror`/`add_mirror` (or crafts an equivalent spend bundle directly) targeting `launcher_id = <victim's public store id>` with `urls=["http://169.254.169.254/latest/meta-data/", "http://internal-admin.local:8443/"]` and a minimal `amount`/`fee`.
2. The spend bundle is broadcast and confirmed; the resulting coin matches `create_mirror_puzzle().get_tree_hash()` and encodes the attacker's URL via memos, per `get_mirror_info()`.
3. A victim node subscribed to/owning that `store_id` runs its periodic `update_subscription()` → `fetch_and_validate()` cycle, picks up the malicious URL as a `ServerInfo`, and calls `http_download()`, causing the victim process to send an outbound GET to the attacker-chosen internal/external URL.
4. Observable side effects (connection success vs. `ClientConnectorError`, timing, HTTP status differences logged by the service) allow the attacker to infer information about the victim's internal network reachability.

def get_mirror_info(
    parent_puzzle: Program | SerializedProgram, parent_solution: Program | SerializedProgram
) -> tuple[bytes32, list[bytes]]:
    assert type(parent_puzzle) is type(parent_solution)
    _, conditions = run_with_cost(parent_puzzle, INFINITE_COST, parent_solution)
    for condition in conditions.as_iter():
        if (
            condition.first().as_python() == ConditionOpcode.CREATE_COIN
            and condition.at("rf").as_python() == create_mirror_puzzle().get_tree_hash()
        ):
            memos: list[bytes] = condition.at("rrrf").as_python()
            launcher_id = bytes32(memos[0])
            return launcher_id, [url for url in memos[1:]]
    raise ValueError("The provided puzzle and solution do not create a mirror coin")
```

    async def get_downloader(self, store_id: bytes32, url: str) -> PluginRemote | None:
        request_json = {"store_id": store_id.hex(), "url": url}
        for d in self.downloaders:
            async with aiohttp.ClientSession() as session:
                try:
                    async with session.post(
                        d.url + "/handle_download",
                        json=request_json,
                        headers=d.headers,
                        timeout=self.client_timeout,
                    ) as response:
                        res_json = await response.json()
                        if res_json["handle_download"]:
                            return d
                except Exception as e:
                    self.log.error(f"get_downloader could not get response: {type(e).__name__}: {e}")
        return None

async def download_file(
    data_store: DataStore,
    target_filename_path: Path,
    store_id: bytes32,
    root_hash: bytes32,
    generation: int,
    server_info: ServerInfo,
    proxy_url: str | None,
    downloader: PluginRemote | None,
    timeout: aiohttp.ClientTimeout,
    client_foldername: Path,
    timestamp: int,
    log: logging.Logger,
    grouped_by_store: bool,
    group_downloaded_files_by_store: bool,
    max_delta_file_size: int,
) -> bool:
    if target_filename_path.exists():
        return True
    filename = get_delta_filename(store_id, root_hash, generation, grouped_by_store)

    if downloader is None:
        # use http downloader - this raises on any error
        try:
            await http_download(
                target_filename_path, filename, proxy_url, server_info, timeout, log, max_delta_file_size
            )
        except (asyncio.TimeoutError, aiohttp.ClientError, MaxDeltaFileSizeExceededError):
            new_server_info = await data_store.server_misses_file(store_id, server_info, timestamp)
            log.info(
                f"Failed to download {filename} from {new_server_info.url}."
                f"Miss {new_server_info.num_consecutive_failures}."
            )
            log.info(f"Next attempt from {new_server_info.url} in {new_server_info.ignore_till - timestamp}s.")
            return False
        return True

    log.info(f"Using downloader {downloader} for store {store_id.hex()}.")
    request_json = {
        "url": server_info.url,
        "client_folder": str(client_foldername),
        "filename": filename,
        "group_files_by_store": group_downloaded_files_by_store,
        "max_delta_file_size": max_delta_file_size,
    }
    try:
        async with aiohttp.ClientSession() as session:
            async with session.post(
                downloader.url + "/download",
                json=request_json,
                headers=downloader.headers,
                timeout=timeout,
            ) as response:
                res_json = await response.json()
                assert isinstance(res_json["downloaded"], bool)
                return res_json["downloaded"]
    except (asyncio.TimeoutError, aiohttp.ClientError) as e:
        log.error(f"download_file could not get response from plugin {downloader}: {type(e).__name__}: {e}")
        return False

async def http_download(
    target_filename_path: Path,
    filename: str,
    proxy_url: str | None,
    server_info: ServerInfo,
    timeout: aiohttp.ClientTimeout,
    log: logging.Logger,
    max_delta_file_size: int,
) -> None:
    """
    Download a file from a server using aiohttp.
    Raises exceptions on errors
    """
    async with aiohttp.ClientSession() as session:
        headers = {"accept-encoding": "gzip"}
        async with session.get(
            server_info.url + "/" + filename,
            headers=headers,
            timeout=timeout,
            proxy=proxy_url,
        ) as resp:
            resp.raise_for_status()
            size = int(resp.headers.get("content-length", 0))
            max_delta_file_size_bytes = max_delta_file_size * 1024 * 1024
            if size > max_delta_file_size_bytes:
                raise MaxDeltaFileSizeExceededError(f"Maximum delta file size exceeded: {max_delta_file_size} MiB.")
            log.debug(f"Downloading delta file {filename}. Size {size} bytes.")
```
