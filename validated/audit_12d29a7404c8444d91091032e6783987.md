## Title
Argument/option injection into `git remote add` via attacker-controlled PR head clone URL - (File: `app/src/lib/git/remote.ts`)

### Summary
`addRemote()` builds a `git remote add <name> <url>` invocation without the `--` end-of-options terminator that is used consistently everywhere else in this codebase (`clone.ts`, `submodule.ts`, `checkout.ts`'s `checkoutPaths`/`checkoutConflictedFile`). Because `<url>` originates from a GitHub API object (`pullRequest.head.repo.clone_url` / `pullRequest.head.gitHubRepository.cloneURL`) that Desktop does not validate as a well-formed `https://`/`ssh://`/`git://` URL before passing it to git, a value that begins with `-` will be parsed by git as an option to `remote add` instead of a positional URL argument.

### Finding Description
`addRemote` is defined as: [1](#0-0) 

Compare this to every other place in the codebase that builds argv for git with untrusted, externally-sourced strings — they all insert `--` before positional path/URL arguments to stop option parsing: [2](#0-1) [3](#0-2) [4](#0-3) 

`addRemote` is the one code path handling a network-object-derived string that omits this guard.

This function is reached from the pull-request checkout flow, where `headCloneUrl` comes directly from a GitHub API response (`pullRequest.head.repo.clone_url` for the "Open PR from browser" deep-link flow, or `pullRequest.head.gitHubRepository.cloneURL` for the in-app PR list): [5](#0-4) [6](#0-5) [7](#0-6) 

The same unsanitized-URL pattern is also used by `ensureUpstreamRemoteURL`: [8](#0-7) 

For GitHub.com, repository owner/name segments are constrained enough that `clone_url` can't practically start with `-`. However, Desktop also talks to GitHub Enterprise instances and (per `getEndpointKind`) any host that presents itself as GitHub via `WWW-Authenticate` headers or an API response: [9](#0-8) 
An attacker controlling (or MITM-ing/spoofing) a GHE-style API endpoint, or a git proxy that returns crafted repository metadata, can supply an arbitrary `clone_url` string, including one beginning with `-`. That string is never parsed as a URL nor rejected before being spliced into `git remote add`.

### Impact Explanation
`git remote add` accepts options such as `-f` (fetch immediately after adding), `-t <branch>`, `-m <master>`, `--mirror=fetch|push`, `--tags`/`--no-tags`. If the "URL" positional argument is instead consumed as one of these flags/values, the remote can be created with attacker-chosen fetch/push mirror semantics or trigger an immediate, unexpected fetch. This falls squarely into "silent corruption of what the user commits or pushes" — a maliciously configured remote (e.g., `--mirror=push`) changes how subsequent Desktop-initiated pushes to that remote behave without the user being aware, and an injected `-f` forces immediate outbound network activity as a side effect of what the user believes is just "adding a remote." This is directly analogous to the reported LamboWin issue's core theme: an attacker-influenced external input silently subverts an invariant (`profit > 0` there; "argument is a URL, not a flag" here) that the calling code implicitly, but not explicitly, assumes holds.

### Likelihood Explanation
Exploitation requires the attacker to control the git-hosting API endpoint's response for a fork's `clone_url` (a compromised/malicious GHE server, or a network-level responder impersonating one, consistent with the allowed "git remote/proxy response" attacker model). It does not require local access, admin rights, or social engineering beyond the user having added/authenticated against that endpoint and viewing/opening a PR from a fork on it — an otherwise ordinary Desktop workflow (`checkoutPullRequest` / "Open in Desktop" PR deep link).

### Recommendation
- Add a `--` terminator in `addRemote` before the `name`/`url` positional arguments, matching the pattern already used in `clone.ts`, `submodule.ts`, and `checkout.ts`:
```ts
await git(['remote', 'add', '--', name, url], repository.path, 'addRemote')
```
- Additionally validate that `url` parses as one of the git-supported remote URL schemes (mirroring the validation already done for clone destinations in `clone.ts`'s `isClonePathSensitive`) before it is ever handed to `addRemote`/`setRemoteURL`, rejecting values that don't match an expected URL grammar (particularly ones starting with `-`).

### Proof of Concept
1. Configure Desktop against a GitHub Enterprise-style endpoint whose API/proxy is attacker-controlled (or intercept/spoof its response).
2. Have the attacker-controlled API return a fork pull request whose `head.repo.clone_url` (or the corresponding fork `cloneURL` field) is set to a string beginning with `-`, e.g. `--mirror=push` or `-f`.
3. The victim opens that PR in Desktop (via the in-app PR list or the "Open PR in Desktop" deep link), triggering `_checkoutPullRequest` → `_findPullRequestBranch` → `addRemote(repository, forkRemoteName, headCloneUrl)`: [10](#0-9) 
4. `git(['remote', 'add', name, headCloneUrl], ...)` executes with `headCloneUrl` parsed as an option instead of a URL because no `--` separates it from possible flags, silently altering the remote's configured behavior (e.g., forcing an immediate fetch or configuring it as a mirror remote) instead of failing safely.

const getEndpointKind = async (cred: Credential, store: Store) => {
  const credentialUrl = getCredentialUrl(cred)
  const endpoint = `${credentialUrl}`

  if (isGist(endpoint)) {
    return 'generic'
  }

  if (isDotCom(endpoint)) {
    return 'github.com'
  }

  if (isGHE(endpoint)) {
    return 'ghe.com'
  }

  // When Git attempts to authenticate with a host it captures any
  // WWW-Authenticate headers and forwards them to the credential helper. We
  // use them as a happy-path to determine if the host is a GitHub host without
  // having to resort to making a request ourselves.
  for (const [k, v] of cred.entries()) {
    if (k.startsWith('wwwauth[')) {
      if (v.includes('realm="GitHub"')) {
        return 'enterprise'
      } else if (/realm="(GitLab|Gitea|Atlassian Bitbucket)"/.test(v)) {
        return 'generic'
      }
    }
  }

  const existingAccount = await findGitHubTrampolineAccount(store, endpoint)
  if (existingAccount) {
    return isDotCom(existingAccount.endpoint) ? 'github.com' : 'enterprise'
  }

  // All GitHub hosts use HTTPS, so if the protocol is not HTTPS we can
  // assume that this is not a GitHub host.
  if (credentialUrl.protocol !== 'https:') {
    return 'generic'
  }

  return (await isGitHubHost(endpoint)) ? 'enterprise' : 'generic'
}
