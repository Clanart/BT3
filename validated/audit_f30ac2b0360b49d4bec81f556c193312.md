### Title
One-Sided `output_amount` Bound in `sign_optimistic_payout` Allows Bridge Vault UTXO to Be Permanently Burned as Miner Fees — (`File: core/src/verifier.rs`)

---

### Summary

`sign_optimistic_payout` enforces only an **upper** bound on `output_amount`. Any value from `0` to `bridge_amount - NON_EPHEMERAL_ANCHOR_AMOUNT` passes validation. Because the optimistic payout transaction has no change output and no fee-payer input, the entire gap between the bridge vault UTXO value and the user's payout is consumed as Bitcoin miner fees — permanently destroying bridged BTC.

---

### Finding Description

In `core/src/verifier.rs`, the only guard on `output_amount` is:

```rust
if output_amount
    > self.config.protocol_paramset().bridge_amount - NON_EPHEMERAL_ANCHOR_AMOUNT
{
    return Err(...)
}
``` [1](#0-0) 

This mirrors the original bug exactly: the check is `<` / `>` (one-sided) rather than `==`. Any `output_amount` strictly below the ceiling silently passes.

`create_optimistic_payout_txhandler` then builds a fixed transaction with no change output:

| # | Role | Value |
|---|------|-------|
| Input 0 | User withdrawal UTXO | `input_amount` (dust) |
| Input 1 | Bridge vault (MoveToVaultTx) | `bridge_amount` |
| Output 0 | User payout | `output_amount` |
| Output 1 | Non-ephemeral anchor | `NON_EPHEMERAL_ANCHOR_AMOUNT` | [2](#0-1) 

Implicit miner fee = `input_amount + bridge_amount − output_amount − NON_EPHEMERAL_ANCHOR_AMOUNT`.

When `output_amount = 0`, essentially the entire `bridge_amount` is burned as fees. There is no `fund_raw_transaction` call, no change output, and no second validation step after the verifiers sign.

The test suite confirms the intended value is `bridge_amount - NON_EPHEMERAL_ANCHOR_AMOUNT`, yet the code never enforces this lower bound: [3](#0-2) 

---

### Impact Explanation

The bridge vault UTXO is a bridge-controlled UTXO holding the user's deposited BTC. If the transaction is broadcast with an under-specified `output_amount`, that UTXO is **permanently spent** with the excess going to miners — satisfying the "permanent loss of bridge-controlled UTXOs / bridged BTC" criterion in the Allowed Impact Gate.

---

### Likelihood Explanation

**Low** — mirrors the original report's likelihood assessment. Requires one of:

1. **User mistake**: the user (or the software constructing the withdrawal request) supplies a wrong `output_amount` (e.g., off-by-one in satoshi conversion, stale fee estimate, or unit confusion).
2. **Aggregator misconfiguration**: `aggregator_verification_address` is absent from config, so the verification-signature gate is skipped entirely, and any caller with mTLS access to the verifier endpoint can supply an arbitrary `output_amount`. [4](#0-3) 

When the verification address **is** configured, the aggregator's ECDSA signature covers `output_amount`, so a malicious aggregator would be required — a privileged assumption. However, the code-level invariant is still broken: verifiers have no independent floor check and will sign whatever the aggregator presents.

---

### Recommendation

Replace the one-sided inequality with strict equality (preferred, matching the protocol's fixed-denomination design):

```rust
if output_amount != self.config.protocol_paramset().bridge_amount - NON_EPHEMERAL_ANCHOR_AMOUNT {
    return Err(eyre::eyre!(
        "Output amount must equal bridge_amount - anchor: expected {}, got {}",
        self.config.protocol_paramset().bridge_amount - NON_EPHEMERAL_ANCHOR_AMOUNT,
        output_amount
    ).into());
}
```

If variable payout amounts are intentionally supported in the future, add an explicit lower bound (e.g., dust limit) and document the fee-burning risk.

---

### Proof of Concept

1. User deposits `bridge_amount` (e.g., 1 BTC) → `MoveToVaultTx` output 0 holds `bridge_amount`.
2. User initiates an optimistic withdrawal, but the client software computes `output_amount = 0` (e.g., due to a unit-conversion bug converting satoshis to BTC).
3. Aggregator (or any mTLS-authenticated caller when `aggregator_verification_address` is unset) calls `sign_optimistic_payout` with `output_amount = 0`.
4. Verifier executes the check: `0 > bridge_amount - NON_EPHEMERAL_ANCHOR_AMOUNT` → **false** → no error returned.
5. Verifier signs the sighash for the optimistic payout transaction.
6. Transaction is broadcast: inputs total ≈ `bridge_amount`, outputs total = `NON_EPHEMERAL_ANCHOR_AMOUNT`, miner fee ≈ `bridge_amount − NON_EPHEMERAL_ANCHOR_AMOUNT` ≈ **1 BTC burned**.
7. The bridge vault UTXO is permanently spent; the user receives nothing; the BTC is unrecoverable. [1](#0-0) [5](#0-4)
