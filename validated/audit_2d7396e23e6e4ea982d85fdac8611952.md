### Title
Uncaught TypeError in `CommitMentionLinkFilter.getRefFromComparePath` on single-SHA compare links crashes markdown rendering - (File: app/src/lib/markdown-filters/commit-mention-link-filter.ts)

### Summary
`CommitMentionLinkFilter.getRefFromComparePath` splits the `compare/<range>` URL path segment on `'...'` and unconditionally accesses `shas[1]`, assuming a two-element range. When the range contains no `'...'` separator, `shas` has only one element and `shas[1]` is `undefined`, so calling `.indexOf('/')` on it throws a `TypeError`. This is the same bug class as the txverifier issue: an array/slice is indexed without checking that the expected element actually exists, and length was only checked for being "too large" (`> 2`) but never "too small" (`< 2`).

### Finding Description
`getRefFromComparePath` matches URL paths of the form `compare/<range>` (built from the `comparePath` regexp `^compare\/(?<range>.+)$`) and only rejects ranges with more than two SHAs: [2](#0-1) 

If `range` has zero occurrences of `'...'` (e.g. `range = "6fd7945"`), `range.split('...')` returns a single-element array, so `shas.length === 1`, which passes the `shas.length > 2` guard. The code then unconditionally dereferences `shas[1]` (`undefined`), throwing `TypeError: Cannot read properties of undefined (reading 'indexOf')`.

This method is reachable from `filter()`, which is invoked by `commitMentionUrl` matches — a regex that already accepts `compare/<7-40 hex chars>` (a single SHA, no `...`) as a valid mention URL: [3](#0-2) 

So any anchor `<a href="https://github.com/OWNER/REPO/compare/abcdef1">https://github.com/OWNER/REPO/compare/abcdef1</a>` (self-referential href/text, matching `commitMentionUrl`) inside PR bodies, issue/PR comments, or commit messages rendered by `SandboxedMarkdown` will trigger the crash.

### Impact Explanation
`applyFilters` in `sandboxed-markdown.tsx` iterates node filters and calls `await nodeFilter.filter(node)` without any try/catch around the call: [4](#0-3) 

An uncaught exception here rejects the `applyFilters` promise, aborting the whole filter pipeline mid-iteration for that markdown document. This means any commit-mention or compare link filter, plus every filter queued after `CommitMentionLinkFilter` (e.g. `VideoTagFilter`, `VideoLinkFilter`), silently fails to apply for the rest of that markdown render — a rendering-integrity failure triggered purely by data pulled from GitHub (PR/issue/commit body content), i.e. attacker-controlled content an unprivileged user can post.

### Likelihood Explanation
High likelihood of accidental/attacker triggering: any GitHub user can post a PR description, PR/issue comment, or commit message containing a plain link like `https://github.com/OWNER/REPO/compare/<7-40-hex-sha>` (which GitHub's own UI auto-links the same way single-commit links are auto-linked), and as soon as a Desktop user views that content through `SandboxedMarkdown` (PR view, commit view, etc.), the crash path is hit. No special privileges, local access, or unusual user interaction are required beyond normal viewing of GitHub-sourced content.

### Recommendation
Guard against a range with fewer than two SHAs (`shas.length !== 2`, not just `> 2`) in `getRefFromComparePath`, returning `null` when there's no `...` separator, matching the `numberFromGroup`/defensive style used elsewhere in the codebase (e.g. `diff-parser.ts`'s explicit checks before indexing regex groups). Additionally, wrap the `await nodeFilter.filter(node)` call in `sandboxed-markdown.tsx`'s `applyFilters` in a try/catch so a single malformed filter input cannot abort the entire remaining filter pipeline.

### Proof of Concept
1. Render markdown content (e.g., a PR description) through `SandboxedMarkdown` with `repository` set, containing:
   `<a href="https://github.com/OWNER/REPO/compare/abcdef1">https://github.com/OWNER/REPO/compare/abcdef1</a>`
   (or simply the raw autolinked text `https://github.com/OWNER/REPO/compare/abcdef1`, which `marked` will convert into a matching self-referential anchor).
2. `commitMentionUrl` regex matches (`compare/abcdef1` satisfies `(commit|pull|compare)/([0-9a-f]{7,40})`).
3. `filter()` → `getRefFromComparePath('compare/abcdef1')` → `range = 'abcdef1'` → `shas = ['abcdef1']` → `shas.length > 2` is false → `shas[1].indexOf('/')` throws `TypeError: Cannot read properties of undefined (reading 'indexOf')`.
4. The exception propagates out of `applyFilters` in `sandboxed-markdown.tsx`, aborting the remaining filter pipeline for that render.
