### Title
Duplicate UTXOs are counted as separate spendable funds - (File: networks/bitcoin/src/wallet/send.rs)

### Summary
`SignableTransaction::new` treats every supplied `ReceivedOutput` as a distinct coin and sums their values without rejecting duplicate `OutPoint`s. [1](#0-0) 

The resulting transaction can therefore contain the same previous output multiple times, while its accounting and sighash `prevouts` treat the duplicated coin as additional value. [2](#0-1) 

### Finding Description
`ReceivedOutput` identifies a coin by its `outpoint`, but `ReceivedOutput::read` only deserializes the offset, `TxOut`, and `OutPoint`; uniqueness is necessarily left to consumers. [3](#0-2) 

`SignableTransaction::new` calculates `input_sat` by summing every entry in `inputs` and constructs one `TxIn` for each entry without checking whether multiple entries reference the same `previous_output`. [4](#0-3) 

The duplicated entries are then stored in parallel `offsets` and `prevouts` vectors. [5](#0-4) [6](#0-5) 

`multisig` only verifies that each offset produces the script in the corresponding `prevout`; it does not detect two positions referencing the same UTXO. [7](#0-6) 

Each duplicated input subsequently receives its own Taproot sighash and signature, producing a transaction that Bitcoin consensus rejects because a transaction cannot spend the same outpoint twice. [8](#0-7) [9](#0-8) 

This is the same invariant failure as the reported NFT issue: an externally supplied item identifier can be counted repeatedly even though the identifier refers to only one spendable asset. [10](#0-9) 

### Impact Explanation
An input list containing two serialized copies of one 10,000-satoshi UTXO is accounted as 20,000 satoshis, allowing construction of a payment that exceeds the real coin's value. [4](#0-3) 

The threshold signing path can successfully sign the malformed transaction because it validates each offset/script pairing independently, not the uniqueness of the spent outpoints. [11](#0-10) 

The output remains unspent because the duplicate-input transaction is invalid, while the wallet/signing pipeline has already accepted the inflated accounting and generated signatures for an unintended transaction. [12](#0-11) [13](#0-12) 

### Likelihood Explanation
The issue is reachable when untrusted serialized `ReceivedOutput`s are passed through `ReceivedOutput::read` and then supplied to `SignableTransaction::new`, since neither stage rejects duplicate outpoints. [14](#0-13) [15](#0-14) 

Outputs produced by one call to `Scanner::scan_transaction` have distinct `vout` values, but replayed scan results, merged output lists, or externally supplied serialized outputs can introduce the same outpoint more than once. [16](#0-15) 

### Recommendation
Add a `HashSet<OutPoint>` or equivalent duplicate check in `SignableTransaction::new` before summing `inputs` or constructing `tx_ins`, and return a new `TransactionError::DuplicateInput` when an outpoint repeats. [17](#0-16) 

Consumers that merge scanned and deserialized `ReceivedOutput`s should also key their coin database by the consensus `OutPoint`, rather than treating each returned or decoded `ReceivedOutput` as a new asset. [10](#0-9) [14](#0-13) 

### Proof of Concept

```rust
use bitcoin_serai::{
  bitcoin::{
    absolute::LockTime,
    hashes::Hash,
    transaction::Version,
    Amount, OutPoint, ScriptBuf, Sequence, Transaction, TxIn, TxOut, Witness,
  },
  wallet::{p2tr_script_buf, Scanner, SignableTransaction, TransactionError},
};
use k256::{elliptic_curve::group::Group, ProjectivePoint};

#[test]
fn same_utxo_is_counted_twice() {
  let mut key = ProjectivePoint::GENERATOR;
  let script = loop {
    if let Some(script) = p2tr_script_buf(key) {
      break script;
    }
    key += ProjectivePoint::GENERATOR;
  };

  let scanner = Scanner::new(key).unwrap();

  let funding_tx = Transaction {
    version: Version(2),
    lock_time: LockTime::ZERO,
    input: vec![TxIn {
      previous_output: OutPoint::default(),
      script_sig: ScriptBuf::new(),
      sequence: Sequence::MAX,
      witness: Witness::new(),
    }],
    output: vec![TxOut {
      value: Amount::from_sat(10_000),
      script_pubkey: script.clone(),
    }],
  };

  let outputs = scanner.scan_transaction(&funding_tx);
  assert_eq!(outputs.len(), 1);
  let utxo = outputs[0].clone();

  let payment = (script, 15_000);

  // One coin cannot pay 15,000 sats.
  assert!(matches!(
    SignableTransaction::new(
      vec![utxo.clone()],
      &[payment.clone()],
      None,
      None,
      1,
    ),
    Err(TransactionError::NotEnoughFunds { .. })
  ));

  // Counting the same coin twice makes the payment pass the balance check.
  let duplicated = SignableTransaction::new(
    vec![utxo.clone(), utxo],
    &[payment],
    None,
    None,
    1,
  )
  .unwrap();

  // Both consensus inputs reference the same UTXO.
  assert_eq!(duplicated.transaction().input.len(), 2);
  assert_eq!(
    duplicated.transaction().input[0].previous_output,
    duplicated.transaction().input[1].previous_output,
  );
}
```
