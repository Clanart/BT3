## Title
Malformed `git diff --raw --numstat` entry from an attacker-controlled repository throws and discards the entire changed-files batch for a multi-commit selection - (File: `app/src/lib/git/log.ts`)

### Summary
`parseRawLogWithNumstat` in `app/src/lib/git/log.ts` decodes `git log`/`git diff --raw --numstat -z` output for a *set* of changed files in one commit or one commit-range selection using `forceUnwrap`, which throws on any unexpected token. [1](#0-0)  This mirrors the report's "atomicity failure" pattern: one anomalous entry in a decoded batch aborts processing of every other (valid) entry in that same batch, with the caller only learning "an error occurred" rather than which file/commit was at fault.

### Finding Description
`getChangedFiles` and `getCommitRangeChangedFiles` both run a single `git` invocation covering potentially many files, and hand the raw `-z`-delimited stdout to `parseRawLogWithNumstat`, which loops through every raw/numstat line and pushes a `CommittedFileChange` per file. [2](#0-1) [3](#0-2) 

Inside the loop, several fields are extracted with `forceUnwrap('...', value)`, which throws a hard `Error` the moment a field is `undefined` or doesn't match the expected shape: [4](#0-3) 

Because `stdout.split('\0')` is a flat, single pass over the whole raw+numstat output for *all* files in the commit/range, a single crafted entry (e.g., a raw-status line whose mode/status token doesn't match `:mode mode blob blob status`, or a numstat line that doesn't match `/^(\d+|-)\t(\d+|-)\t/`) causes `forceUnwrap` to throw immediately, unwinding the entire function before any of the remaining files are appended to `files`. The whole batch — not just the offending file — is lost, exactly as in the reported `aggregate3`/`onCronTrigger` pattern where one bad item halts an otherwise-independent set of items.

The data this function parses is not app-generated: it is derived from the attacker-controlled repository's commit history (file paths, modes, statuses) once the user clones/fetches/checks out a hostile repo, satisfying the "attacker controls a cloned/fetched repository" primitive in the report's valid-impact list.

### Impact Explanation
This is availability/UX-degrading rather than memory-unsafe: no code execution or credential exfiltration results. When the throw propagates out of `getChangedFiles`/`getCommitRangeChangedFiles`, the caller (`AppStore._loadChangedFilesForCurrentSelection`) never populates `changesetData` for the selection, so a single anomalous filename/mode in one commit silently blanks the entire "Changed Files" list and diff view for that commit or commit range — for every legitimate file in that same commit — with no per-file indication of which entry caused the failure. Given the report's own framing ("no funds at risk... delayed [work]... total silence about which entry caused the failure"), the Desktop analog is a comparable "whole-batch item loss / opaque failure" rather than a memory-safety or RCE bug.

### Likelihood Explanation
Reaching this requires only that the user open history/select commits in a repository that contains at least one commit with an unusual raw-diff entry (e.g., unusual mode bits, a status token outside `AMDRC` and their `R100`/`C100` percent variants, or a numstat line whose byte-counts field doesn't match the expected regex due to binary/edge-case entries). Crafting such a commit is possible with low-level plumbing (`git hash-object` / `update-index` / packing) without needing local access to the victim machine — the victim simply clones or fetches the repo and clicks through commit history in Desktop's UI, which is a normal, expected user action rather than an "unprompted unnatural step."

### Recommendation
Make `parseRawLogWithNumstat` resilient per-entry instead of failing the whole call:
- Replace the hard `forceUnwrap` throws inside the loop with skip-and-log behavior: if a raw-status line or numstat line doesn't match the expected shape, emit a warning/log entry and `continue` to the next token instead of throwing.
- Return the successfully parsed subset of `files`/`linesAdded`/`linesDeleted` even when some entries were skipped, and surface a non-fatal indicator (e.g., a `hasParseWarnings` flag) to the UI so the user knows the changed-files list may be incomplete for that commit, rather than silently showing nothing.
- Apply the same tolerant-parsing pattern to `createLogParser`/`createForEachRefParser` in `app/src/lib/git/git-delimiter-parser.ts`, since they use the same all-or-nothing field-splitting approach for `git log`/`for-each-ref` output. [5](#0-4) [6](#0-5) 

### Proof of Concept
1. Craft a malicious repository containing a normal commit `A` (with several ordinary file changes) and, within the same commit, one entry engineered via low-level plumbing so that its raw diff line's mode/status token does not match `/^:mode mode blob blob status$/`-like expectations that `mapStatus`/`forceUnwrap` assume (e.g. an out-of-spec status code appended after the trailing tab-separated fields, or a numstat line missing its two leading numeric/`-` fields).
2. Publish/host the repo and have the victim clone it in GitHub Desktop, then select commit `A` (or a range including it) in the History view.
3. `AppStore._loadChangedFilesForCurrentSelection` calls `getChangedFiles`/`getCommitRangeChangedFiles`, which invoke `parseRawLogWithNumstat` on the full `--raw --numstat -z` output for commit `A`. [7](#0-6) 
4. When the loop reaches the crafted entry, `forceUnwrap` throws (e.g., "Invalid numstat line" or "Missing path"), unwinding before the remaining legitimate files in commit `A` are added to `files`. [8](#0-7) 
5. Observed result: the Changed Files pane / diff for commit `A` fails to populate at all (no files shown, or a generic operation-failure state depending on how `performFailableOperation` swallows the rejection), even though most files in that commit were valid — demonstrating the single-bad-entry-halts-whole-batch pattern with no indication of which file was responsible.

export async function getChangedFiles(
  repository: Repository,
  sha: string
): Promise<IChangesetData> {
  // opt-in for rename detection (-M) and copies detection (-C)
  // this is equivalent to the user configuring 'diff.renames' to 'copies'
  // NOTE: order here matters - doing -M before -C means copies aren't detected
  const args = [
    'log',
    sha,
    '-C',
    '-M',
    '-m',
    '-1',
    '--no-show-signature',
    '--first-parent',
    '--raw',
    '--format=format:',
    '--numstat',
    '-z',
    '--',
  ]

  const { stdout } = await git(args, repository.path, 'getChangesFiles')
  return parseRawLogWithNumstat(stdout, sha, `${sha}^`)
}

export function parseRawLogWithNumstat(
  stdout: string,
  sha: string,
  parentCommitish: string
) {
  const files = new Array<CommittedFileChange>()
  let linesAdded = 0
  let linesDeleted = 0
  let numStatCount = 0
  const lines = stdout.split('\0')

  for (let i = 0; i < lines.length - 1; i++) {
    const line = lines[i]
    if (line.startsWith(':')) {
      const lineComponents = line.split(' ')
      const srcMode = forceUnwrap(
        'Invalid log output (srcMode)',
        lineComponents[0]?.replace(':', '')
      )
      const dstMode = forceUnwrap(
        'Invalid log output (dstMode)',
        lineComponents[1]
      )
      const status = forceUnwrap(
        'Invalid log output (status)',
        lineComponents.at(-1)
      )
      const oldPath = /^R|C/.test(status)
        ? forceUnwrap('Missing old path', lines.at(++i))
        : undefined

      const path = forceUnwrap('Missing path', lines.at(++i))

      files.push(
        new CommittedFileChange(
          path,
          mapStatus(status, oldPath, srcMode, dstMode),
          sha,
          parentCommitish
        )
      )
    } else {
      const match = /^(\d+|-)\t(\d+|-)\t/.exec(line)
      const [, added, deleted] = forceUnwrap('Invalid numstat line', match)
      linesAdded += added === '-' ? 0 : parseInt(added, 10)
      linesDeleted += deleted === '-' ? 0 : parseInt(deleted, 10)

      // If this entry denotes a rename or copy the old and new paths are on
      // two separate fields (separated by \0). Otherwise they're on the same
      // line as the added and deleted lines.
      if (isCopyOrRename(files[numStatCount].status)) {
        i += 2
      }
      numStatCount++
    }
  }

  return { files, linesAdded, linesDeleted }

export async function getCommitRangeChangedFiles(
  repository: Repository,
  shas: ReadonlyArray<string>,
  useNullTreeSHA: boolean = false
): Promise<IChangesetData> {
  if (shas.length === 0) {
    throw new Error('No commits to diff...')
  }

  const oldestCommitRef = useNullTreeSHA ? NullTreeSHA : `${shas[0]}^`
  const latestCommitRef = shas.at(-1) ?? '' // can't be undefined since shas.length > 0
  const baseArgs = [
    'diff',
    oldestCommitRef,
    latestCommitRef,
    '-C',
    '-M',
    '-z',
    '--raw',
    '--numstat',
    '--',
  ]

  const { stdout, gitError } = await git(
    baseArgs,
    repository.path,
    'getCommitRangeChangedFiles',
    {
      expectedErrors: new Set([GitError.BadRevision]),
    }
  )

  // This should only happen if the oldest commit does not have a parent (ex:
  // initial commit of a branch) and therefore `SHA^` is not a valid reference.
  // In which case, we will retry with the null tree sha.
  if (gitError === GitError.BadRevision && useNullTreeSHA === false) {
    const useNullTreeSHA = true
    return getCommitRangeChangedFiles(repository, shas, useNullTreeSHA)
  }

  return parseRawLogWithNumstat(stdout, latestCommitRef, oldestCommitRef)

export function createLogParser<T extends Record<string, string>>(fields: T) {
  const keys: Array<keyof T> = Object.keys(fields)
  const format = Object.values(fields).join('%x00')
  const formatArgs = ['-z', `--format=${format}`]

  const parse = <V extends string | Buffer>(value: V) => {
    const records = (
      Buffer.isBuffer(value) ? splitBuffer(value, '\0') : value.split('\0')
    ) as V[]
    const entries = []

    for (let i = 0; i < records.length - keys.length; i += keys.length) {
      const entry = {} as { [K in keyof T]: V }
      keys.forEach((key, ix) => (entry[key] = records[i + ix]))
      entries.push(entry)
    }

    return entries
  }

  return { formatArgs, parse }
}

export function createForEachRefParser<T extends Record<string, string>>(
  fields: T
) {
  const keys: Array<keyof T> = Object.keys(fields)
  const format = Object.values(fields).join('%00')
  const formatArgs = [`--format=%00${format}%00`]

  const parse = (value: string) => {
    const records = value.split('\0')
    const entries = new Array<{ [K in keyof T]: string }>()

    let entry
    let consumed = 0

    // start at 1 to avoid 0 modulo X problem. The first record is guaranteed
    // to be empty anyway (due to %00 at the start of --format)
    for (let i = 1; i < records.length - 1; i++) {
      if (i % (keys.length + 1) === 0) {
        if (records[i] !== '\n') {
          throw new Error('Expected newline')
        }
        continue
      }

      entry = entry ?? ({} as { [K in keyof T]: string })
      const key = keys[consumed % keys.length]
      entry[key] = records[i]
      consumed++

      if (consumed % keys.length === 0) {
        entries.push(entry)
        entry = undefined
      }
    }

    return entries
  }

  return { formatArgs, parse }
}
