### Title
Unlocked concurrent read/write of `deliverTxTask.Status` in the OCC scheduler causes non-deterministic re-execution decisions - (File: `giga/deps/tasks/scheduler.go`, `sei-cosmos/tasks/scheduler.go`)

### Summary
The Sei OCC parallel-execution scheduler protects each `deliverTxTask`'s mutable fields with a per-task `mx sync.RWMutex`, but several hot paths that run concurrently across worker goroutines read and write `task.Status` (and derived dependency state) directly, bypassing that mutex. This is the same bug class as CVE-2024-40986: a field that is meant to be guarded by a lock is checked/updated from a concurrent execution context without acquiring it first, producing a data race whose outcome is non-deterministic.

### Finding Description
`deliverTxTask` declares a lock intended to guard its status: [1](#0-0) 

`validateAll` fans work out across one goroutine per task, each of which can transition its own task's status and also (via `shouldRerun`/`dependenciesValidated`) read the status of *other* tasks that are concurrently being validated/updated in sibling goroutines of the same `wg`: [2](#0-1) 

Inside `shouldRerun`, the field is read directly as `task.Status` (not through the `mx` lock), and — for tasks in `statusWaiting` — the dependency check inspects the `.Status` of other tasks that another goroutine may be writing at the same time via `SetStatus`: [3](#0-2) 

`findFirstNonValidated`, used to decide the synchronous fallback slice and iteration termination, also walks `s.allTasks` and reads `t.Status` without any lock: [4](#0-3) 

Execution itself is also fanned out across goroutines that mutate each task concurrently: [5](#0-4) 

The identical pattern exists in the non-Giga OCC scheduler used for the standard (Cosmos) tx path: [6](#0-5) [7](#0-6) 

Because `Status` is read outside of `mx` while being concurrently written elsewhere (mirroring xdma's unlocked read of `stop_request` while another context under the vchan lock could mutate it), the Go memory model gives no guarantee the reading goroutine observes a consistent/up-to-date value. A stale read of `statusValidated`/`statusExecuted`/`statusAborted` can cause the scheduler to skip a required re-execution of a task whose dependency actually invalidated it (or vice versa, cause spurious re-execution), because `shouldRerun` and `findFirstNonValidated` make control-flow decisions purely from an unsynchronized field read.

### Impact Explanation
The OCC scheduler decides which transactions must be re-executed against the finally-accepted prefix and which are accepted as-is; results are then written into the multi-version store via `WriteLatestToStore` and become the block's committed state. A race that causes `shouldRerun`/`findFirstNonValidated` to observe a stale `Status` can lead a validator to accept a transaction result computed against an invalid/overwritten source state (i.e., skip a required re-run) instead of the deterministic sequential result, or vice versa. Since this is a data race, different validators (or even the same validator across re-runs, e.g. during state sync replay) can non-deterministically reach different execution outcomes for the same block, producing divergent AppHashes — a permanent chain split. It could also manifest as accepting an unvalidated (stale) execution result, allowing incorrect balances/state to be committed (fund loss / incorrect accounting) for the affected transactions in that block.

### Likelihood Explanation
This code runs on every block whenever OCC parallel execution is used with `ConcurrencyWorkers()`/`OCCWorkers` > 1 and there is more than one transaction — which is the default, always-reachable execution path for ordinary users submitting Cosmos or EVM (via Giga OCC) transactions; no special privileges or crafted messages beyond normal tx conflicts are needed to trigger concurrent validation of dependent tasks. The race window depends on Go's scheduler timing and the presence of actual read/write conflicts among concurrently-submitted transactions, which is common under load, making this a realistically triggerable, not purely theoretical, race under `-race`-detectable conditions.

### Recommendation
Guard every access to `deliverTxTask.Status` (reads and writes) with the existing `mx` mutex — introduce `GetStatus()`/`SetStatus()` accessor methods that take `mx.RLock()`/`mx.Lock()` respectively, and replace all direct `task.Status`/`t.Status` field accesses in `shouldRerun`, `findFirstNonValidated`, `allValidated`, and any other cross-goroutine reader in both `giga/deps/tasks/scheduler.go` and `sei-cosmos/tasks/scheduler.go` with these accessors. Add a `go test -race` regression test that runs `ProcessAll` with intentionally conflicting transactions across many iterations to catch the race deterministically, analogous to the existing `tree_race_test.go` regression tests already used to close the STO-601 memiavl hash race.

### Proof of Concept
1. Construct a block of transactions such that transaction B depends on (conflicts with) transaction A's write set, and run it through `ProcessAll` with `ConcurrencyWorkers()`/`OCCWorkers` set to at least 2 so that A and B's validations run in separate goroutines inside `validateAll`.
2. Run the block-processing path repeatedly under `go test -race` (or equivalently, add a fuzz/stress harness that calls `ProcessAll` thousands of times with the same conflicting entry set from multiple goroutines) — `go test -race` will flag the concurrent unsynchronized access to `task.Status` between the goroutine executing A's `SetStatus` transition and the goroutine evaluating B's `dependenciesValidated(s.allTasksMap, task.Dependencies)` / `findFirstNonValidated`.
3. Because the outcome of the race determines whether B is marked `statusWaiting`/rerun or accepted immediately, repeated runs of the same input can be shown to occasionally accept B's stale (pre-A) execution result instead of rerunning it, demonstrating non-deterministic acceptance of conflicting state — the same class of consequence as the kernel bug's use of a racily-read flag to make an incorrect control decision.

func (s *scheduler) shouldRerun(task *deliverTxTask) bool {
	switch task.Status {

	case statusAborted, statusPending:
		return true

	// validated tasks can become unvalidated if an earlier re-run task now conflicts
	case statusExecuted, statusValidated:
		// With the current scheduler, we won't actually get to this step if a previous task has already been determined to be invalid,
		// since we choose to fail fast and mark the subsequent tasks as invalid as well.
		// TODO: in a future async scheduler that no longer exhaustively validates in order, we may need to carefully handle the `valid=true` with conflicts case
		if valid, conflicts, conflictKeys := s.findConflicts(task); !valid {
			s.invalidateTask(task)
			task.AppendDependencies(conflicts)
			s.conflictKeyMu.Lock()
			for _, k := range conflictKeys {
				s.conflictKeyCounts[k]++
			}
			s.conflictKeyMu.Unlock()

			// if the conflicts are now validated, then rerun this task
			if dependenciesValidated(s.allTasksMap, task.Dependencies) {
				return true
			} else {
				// otherwise, wait for completion
				task.SetStatus(statusWaiting)
				return false
			}
		} else if len(conflicts) == 0 {
			// mark as validated, which will avoid re-validating unless a lower-index re-validates
			task.SetStatus(statusValidated)
			return false
		}
		// conflicts and valid, so it'll validate next time
		return false

	case statusWaiting:
		// if conflicts are done, then this task is ready to run again
		return dependenciesValidated(s.allTasksMap, task.Dependencies)
	}
	panic("unexpected status: " + task.Status)
}

func (s *scheduler) validateAll(ctx sdk.Context, tasks []*deliverTxTask) ([]*deliverTxTask, error) {
	ctx, span := s.traceSpan(ctx, "SchedulerValidateAll", nil)
	defer span.End()

	var mx sync.Mutex
	var res []*deliverTxTask

	startIdx, anyLeft := s.findFirstNonValidated()

	if !anyLeft {
		return nil, nil
	}

	wg := &sync.WaitGroup{}
	for i := startIdx; i < len(tasks); i++ {
		wg.Add(1)
		t := tasks[i]
		s.DoValidate(func() {
			defer wg.Done()
			if !s.validateTask(ctx, t) {
				mx.Lock()
				defer mx.Unlock()
				t.Reset()
				t.Increment()
				// update max incarnation for scheduler
				if t.Incarnation > s.maxIncarnation {
					s.maxIncarnation = t.Incarnation
				}
				res = append(res, t)
			}
		})
	}
	wg.Wait()

	return res, nil
}

func (s *scheduler) executeAll(ctx sdk.Context, tasks []*deliverTxTask) error {
	if len(tasks) == 0 {
		return nil
	}
	ctx, span := s.traceSpan(ctx, "SchedulerExecuteAll", nil)
	span.SetAttributes(attribute.Bool("synchronous", s.synchronous))
	defer span.End()

	// validationWg waits for all validations to complete
	// validations happen in separate goroutines in order to wait on previous index
	wg := &sync.WaitGroup{}
	wg.Add(len(tasks))

	for _, task := range tasks {
		t := task
		s.DoExecute(func() {
			s.prepareAndRunTask(wg, ctx, t)
		})
	}

	wg.Wait()

	return nil

func (s *scheduler) findConflicts(task *deliverTxTask) (bool, []int, []string) {
	var conflicts []int
	conflictKeys := make([]string, 0, len(s.multiVersionStores))
	uniq := make(map[int]struct{})
	valid := true
	for storeKey, mv := range s.multiVersionStores {
		ok, mvConflicts, mvKeys := mv.ValidateTransactionStateWithKeys(task.AbsoluteIndex)
		for _, c := range mvConflicts {
			if _, ok := uniq[c]; !ok {
				conflicts = append(conflicts, c)
				uniq[c] = struct{}{}
			}
		}
		for _, k := range mvKeys {
			conflictKeys = append(conflictKeys, storeKey.Name()+"/"+k)
		}
		// any non-ok value makes valid false
		valid = valid && ok
	}
	sort.Ints(conflicts)
	return valid, conflicts, conflictKeys
}

func (s *scheduler) ProcessAll(ctx sdk.Context, reqs []*sdk.DeliverTxEntry) ([]types.ResponseDeliverTx, error) {
	startTime := time.Now()
	var iterations int
	// initialize mutli-version stores if they haven't been initialized yet
	s.tryInitMultiVersionStore(ctx)
	tasks, tasksMap := toTasks(reqs)
	s.allTasks = tasks
	s.allTasksMap = tasksMap
	s.conflictKeyCounts = make(map[string]int)
	s.executeCh = make(chan func(), len(tasks))
	s.validateCh = make(chan func(), len(tasks))
	defer s.emitMetrics(ctx.Context())

	// default to number of tasks if workers is negative or 0 by this point
	workers := s.workers
	if s.workers < 1 || len(tasks) < s.workers {
		workers = len(tasks)
	}

	workerCtx, cancel := context.WithCancel(ctx.Context())
	defer cancel()

	// execution tasks are limited by workers
	start(workerCtx, s.executeCh, workers)

	// validation tasks uses length of tasks to avoid blocking on validation
	start(workerCtx, s.validateCh, len(tasks))

	toExecute := tasks
	for !allValidated(tasks) {
		// if the max incarnation >= x, we should revert to synchronous
		if iterations >= maximumIterations {
			// process synchronously
			s.synchronous = true
			startIdx, anyLeft := s.findFirstNonValidated()
			if !anyLeft {
				break
			}
			toExecute = tasks[startIdx:]
		}

		// execute sets statuses of tasks to either executed or aborted
		if err := s.executeAll(ctx, toExecute); err != nil {
			return nil, err
		}

		// validate returns any that should be re-executed
		// note this processes ALL tasks, not just those recently executed
		var err error
		toExecute, err = s.validateAll(ctx, tasks)
		if err != nil {
			return nil, err
		}
		// these are retries which apply to metrics
		s.metrics.retries += len(toExecute)
		iterations++
	}

	for _, mv := range s.multiVersionStores {
		mv.WriteLatestToStore()
	}
	s.metrics.maxIncarnation = s.maxIncarnation

	if s.metrics.retries > 0 && len(s.conflictKeyCounts) > 0 {
		encoded := make(map[string]int, len(s.conflictKeyCounts))
		for k, v := range s.conflictKeyCounts {
			storeName, rawKey, _ := strings.Cut(k, "/")
			var encodedKey string
			if rawKey == "globalAccountNumber" {
				encodedKey = storeName + "/" + rawKey
			} else {
				encodedKey = storeName + "/" + hex.EncodeToString([]byte(rawKey))
			}
			encoded[encodedKey] = v
		}
		logger.Info("occ scheduler key conflicts", "height", ctx.BlockHeight(), "counts", encoded)
	}

	logger.Info("occ scheduler", "height", ctx.BlockHeight(), "txs", len(tasks), "latency_ms", time.Since(startTime).Milliseconds(), "retries", s.metrics.retries, "maxIncarnation", s.maxIncarnation, "iterations", iterations, "sync", s.synchronous, "workers", s.workers)

	return s.collectResponses(tasks), nil
}
