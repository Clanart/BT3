### Title
Unvalidated `ReceivedOutput` bytes can represent nonexistent or unspendable Bitcoin UTXOs - ([File: networks/bitcoin/src/wallet/mod.rs](https://github.com/Kirstentat/serai--020/blob/main/networks/bitcoin/src/wallet/mod.rs#L120-L134))

### Summary
`ReceivedOutput::read` deserializes an offset, `TxOut`, and `OutPoint` without verifying that the outpoint exists, that the referenced output has the claimed value or script, or that the offset was produced by a `Scanner`. [1](#0-0)  A caller that accepts serialized `ReceivedOutput`s from an untrusted source can therefore treat fabricated bytes as received funds. [2](#0-1) 

### Finding Description
`ReceivedOutput` consists of a scalar offset, a claimed previous output, and a claimed outpoint. [3](#0-2)  Its reader only parses those three fields, returning a struct for any syntactically valid encoding. [1](#0-0) 

Legitimate outputs are normally produced by `Scanner::scan_transaction`, which recognizes a previously registered `script_pubkey` and records the real transaction ID and output index. [4](#0-3)  Deserialization bypasses that scanner path, so the returned object does not carry the same assurance of chain existence or ownership. [1](#0-0) 

`SignableTransaction::new` then trusts the decoded `output.value`, `output.script_pubkey`, `outpoint`, and `offset` when constructing the transaction inputs and prevout commitments. [5](#0-4) [6](#0-5)  `multisig` checks only that `keys.offset(offset).group_key()` maps to the supplied previous-output script; it does not check that the supplied `OutPoint` resolves to that `TxOut` on chain. [7](#0-6) 

### Impact Explanation
An attacker can provide a serialized `ReceivedOutput` containing a script controlled by the threshold key but a fabricated transaction ID, output index, or amount. [8](#0-7)  The application can consequently account for funds as received even though no corresponding UTXO exists or the claimed UTXO cannot be spent. [5](#0-4) 

If that fabricated object is later used to build a transaction, the threshold participants may sign a transaction whose input is nonexistent or whose committed prevout does not match the actual chain data. [6](#0-5)  The resulting transaction will be rejected by Bitcoin consensus despite the wallet API accepting the attacker-supplied “received” output. [9](#0-8) 

### Likelihood Explanation
The issue is reachable wherever untrusted serialized `ReceivedOutput` data is accepted through the public `ReceivedOutput::read` API rather than obtained directly from `Scanner::scan_transaction` or `Scanner::scan_block`. [1](#0-0) [10](#0-9) 

Exploitation does not require forging a signature, compromising a validator, or controlling a Bitcoin peer; the attacker only needs to supply bytes that decode successfully. [1](#0-0)  The likelihood is limited by the need for an integrator to persist or accept attacker-controlled `ReceivedOutput`s as inputs, so this is a Medium severity analog rather than a direct remote consensus failure. [2](#0-1) 

### Recommendation
Do not expose `ReceivedOutput::read` as a source of authoritative UTXO evidence, or require callers to revalidate deserialized outputs against chain data before accounting for or spending them. [8](#0-7)  At minimum, verify the referenced outpoint exists, has the claimed value and `script_pubkey`, is mature when applicable, and that the decoded offset maps through the expected group key to that `script_pubkey`. [10](#0-9) [7](#0-6) 

A safer API would bind the output to scanner evidence, such as the containing transaction ID plus output index, and reconstruct the `TxOut` from trusted chain data rather than accepting the attacker’s `TxOut` bytes directly. [1](#0-0) 

### Proof of Concept
The following conceptual input demonstrates the missing semantic validation; the exact point and transaction encodings must use the target’s canonical secp256k1 and Bitcoin consensus encodings. [11](#0-10) [1](#0-0) 

```rust
// Fabricated bytes supplied by an untrusted peer:
//   offset       = Scalar::ZERO encoding
//   output       = TxOut {
//                    value: 1_000_000_000,
//                    script_pubkey: <script controlled by the wallet key>,
//                  }
//   outpoint     = OutPoint {
//                    txid: <nonexistent transaction>,
//                    vout: 0,
//                  }
let received = ReceivedOutput::read(&mut fabricated_bytes.as_slice()).unwrap();
```

`received` is accepted even though its `outpoint` does not reference the encoded `TxOut` on chain. [1](#0-0)  Passing it to `SignableTransaction::new` causes the fabricated value and outpoint to be used as an input and as a prevout committed by the Taproot sighash. [5](#0-4) [9](#0-8)

  /// Scan a transaction.
  pub fn scan_transaction(&self, tx: &Transaction) -> Vec<ReceivedOutput> {
    let mut res = Vec::new();
    for (vout, output) in tx.output.iter().enumerate() {
      // If the vout index exceeds 2**32, stop scanning outputs
      let Ok(vout) = u32::try_from(vout) else { break };

      if let Some(offset) = self.scripts.get(&output.script_pubkey) {
        res.push(ReceivedOutput {
          offset: *offset,
          output: output.clone(),
          outpoint: OutPoint::new(tx.compute_txid(), vout),
        });
      }
    }
    res
  }

  /// Scan a block.
  ///
  /// This will also scan the coinbase transaction which is bound by maturity. If received outputs
  /// must be immediately spendable, a post-processing pass is needed to remove those outputs.
  /// Alternatively, scan_transaction can be called on `block.txdata[1 ..]`.
  pub fn scan_block(&self, block: &Block) -> Vec<ReceivedOutput> {
    let mut res = Vec::new();
    for tx in &block.txdata {
      res.extend(self.scan_transaction(tx));
    }
    res
  }

  /// Read a canonical scalar from something implementing std::io::Read.
  #[cfg(any(feature = "alloc", feature = "std"))]
  #[allow(non_snake_case)]
  fn read_F<R: Read>(reader: &mut R) -> io::Result<Self::F> {
    let mut encoding = <Self::F as PrimeField>::Repr::default();
    reader.read_exact(encoding.as_mut())?;

    // ff mandates this is canonical
    let res = Option::<Self::F>::from(Self::F::from_repr(encoding))
      .ok_or_else(|| io::Error::other("non-canonical scalar"));
    encoding.as_mut().zeroize();
    res
  }

  /// Read a canonical point from something implementing std::io::Read.
  ///
  /// The provided implementation is safe so long as `GroupEncoding::to_bytes` always returns a
  /// canonical serialization.
  #[cfg(any(feature = "alloc", feature = "std"))]
  #[allow(non_snake_case)]
  fn read_G<R: Read>(reader: &mut R) -> io::Result<Self::G> {
    let mut encoding = <Self::G as GroupEncoding>::Repr::default();
    reader.read_exact(encoding.as_mut())?;

    let point = Option::<Self::G>::from(Self::G::from_bytes(&encoding))
      .ok_or_else(|| io::Error::other("invalid point"))?;
    if point.to_bytes().as_ref() != encoding.as_ref() {
      Err(io::Error::other("non-canonical point"))?;
    }
    Ok(point)
  }
