### Title
Authenticated SSRF in Chia DataLayer mirror sync: unvalidated mirror/subscription URLs cause the local node to make outbound HTTP requests to attacker-chosen hosts - (File: chia/data_layer/download_data.py)

### Summary
Chia's DataLayer service maintains a table of "mirror" URLs for each store, sourced from on-chain mirror coins created by any wallet via `dl_new_mirror` (a normal, unprivileged spend). The local `DataLayer` service periodically syncs these URLs (`update_subscriptions_from_wallet` / `update_subscription`) and issues raw outbound HTTP `GET` requests to them (`http_download`) with no host/scheme/IP allow-listing, matching the "unvalidated job template URI leads to SSRF" bug class in the reference advisory (Gravitino JobManager).

### Finding Description
Any Chia wallet user can create a mirror coin for a launcher/store id by calling the `dl_new_mirror` wallet RPC with attacker-controlled `urls`: [1](#0-0) 
This spends XCH to create a coin with puzzle hash `create_mirror_puzzle()` whose memo encodes the launcher id and URL list: [2](#0-1) 
When this coin is seen on chain, `DataLayerWallet.coin_added` decodes and stores the URLs without any validation of scheme or destination: [3](#0-2) 

Any node running the DataLayer service that is subscribed to (or owns) that store id periodically calls `update_subscriptions_from_wallet`, which pulls these mirror URLs from the wallet DB and merges them into the local subscription table with no filtering: [4](#0-3) [5](#0-4) 

`fetch_and_validate()` then iterates these server URLs and calls `insert_from_delta_file()` → `download_file()` → `http_download()`, which performs a bare `aiohttp` `GET` to `server_info.url + "/" + filename` with no scheme/host/IP validation (no blocking of `http://` to internal ranges, no DNS-rebinding protection, no cloud-metadata IP denylist): [6](#0-5) [7](#0-6) 

The `.cursor/context/data-layer.md` notes explicitly flag mirror/plugin URLs as untrusted external inputs, but the download path only validates the *content* returned (against the wallet-advertised root), not the *destination* being requested: [8](#0-7) 

Similarly, `get_downloader()` and `get_uploaders()` POST requests to plugin URLs (config-controlled, not attacker-controlled) are a separate, lower-risk path and out of scope here.

### Impact Explanation
A single unprivileged spend (creating a mirror coin with a fee) lets an attacker cause any node that syncs that DataLayer store — including nodes owning/subscribing to a targeted store — to issue outbound HTTP requests to arbitrary hosts/ports it chooses, e.g. `http://169.254.169.254/latest/meta-data/...` (cloud metadata) or internal-only services (`http://127.0.0.1:<port>/...`, RPC ports, internal admin panels). Response bytes are written to a local delta file and only rejected afterward if the tree hash validation in `insert_into_data_store_from_file` fails; before that check, the attacker still gets a probe (connect timing, banning behavior, `ClientResponseError` messages) revealing reachability, open ports, and possibly partial content leakage into the log/local error path. This satisfies the CVSS 6.5 bug class (server makes unauthenticated-destination HTTP requests based on attacker-supplied URI, no PR beyond normal wallet ownership) and is reachable purely through wallet/DataLayer RPC actions available to any user running the service.

### Likelihood Explanation
High likelihood of triggering the request: creating a mirror coin is a standard, unprivileged wallet operation requiring only a fee, and any DataLayer node that owns or subscribes to the targeted store id will automatically sync and fetch from the new mirror URL during its normal periodic sync loop (`periodically_manage_data` → `update_subscription` → `fetch_and_validate`). No special timing or race condition is needed; it happens on the next sync cycle.

### Recommendation
- Validate mirror/subscription URLs before storing/using them: enforce scheme allow-list (https only), reject `localhost`/loopback/link-local/private/cloud-metadata IP ranges, and resolve DNS to re-check the resolved IP prior to connecting (to avoid DNS rebinding).
- Consider requiring an explicit local opt-in (allow-list of trusted mirror domains) rather than automatically dialing out to any URL published in a mirror coin by any peer.
- Apply the same validation to plugin/downloader/uploader URLs used in `get_downloader`/`get_uploaders`/`get_plugin_info`.

### Proof of Concept
1. Attacker (any wallet holder) runs:
   `dl_new_mirror(launcher_id=<victim's store id>, amount=1, urls=["http://169.254.169.254/latest/meta-data/iam/security-credentials/"], fee=<fee>, push=True)`
2. The mirror coin confirms on-chain; the victim node's `DataLayerWallet.coin_added` records the mirror row for `launcher_id`.
3. If the victim node owns or is subscribed to `launcher_id`, its `DataLayer.periodically_manage_data()` loop calls `update_subscriptions_from_wallet(launcher_id)`, adding the malicious URL to the subscriptions table, then `fetch_and_validate(launcher_id)` uses it as a `server_info.url` and calls `http_download()`, issuing `GET http://169.254.169.254/latest/meta-data/.../<delta-filename>` from the victim's server/host network context.

```python
    async def update_subscriptions_from_wallet(self, store_id: bytes32, new_urls: list[str]) -> None:
        async with self.db_wrapper.writer() as writer:
            cursor = await writer.execute(
                "SELECT * FROM subscriptions WHERE from_wallet == 1 AND tree_id == :tree_id",
                {
                    "tree_id": store_id,
                },
            )
            old_urls = [row["url"] async for row in cursor]
            cursor = await writer.execute(
                "SELECT * FROM subscriptions WHERE from_wallet == 0 AND tree_id == :tree_id",
                {
                    "tree_id": store_id,
                },
            )
            from_subscriptions_urls = {row["url"] async for row in cursor}
            additions = {url for url in new_urls if url not in old_urls}
            removals = [url for url in old_urls if url not in new_urls]
            for url in removals:
                await writer.execute(
                    "DELETE FROM subscriptions WHERE url == :url AND tree_id == :tree_id",
                    {
                        "url": url,
                        "tree_id": store_id,
                    },
                )
            for url in additions:
                if url not in from_subscriptions_urls:
                    await writer.execute(
                        "INSERT INTO subscriptions(tree_id, url, ignore_till, num_consecutive_failures, from_wallet) "
                        "VALUES (:tree_id, :url, 0, 0, 1)",
                        {
                            "tree_id": store_id,
                            "url": url,
                        },
                    )
```

```python
async def http_download(
    target_filename_path: Path,
    filename: str,
    proxy_url: str | None,
    server_info: ServerInfo,
    timeout: aiohttp.ClientTimeout,
    log: logging.Logger,
    max_delta_file_size: int,
) -> None:
    """
    Download a file from a server using aiohttp.
    Raises exceptions on errors
    """
    async with aiohttp.ClientSession() as session:
        headers = {"accept-encoding": "gzip"}
        async with session.get(
            server_info.url + "/" + filename,
            headers=headers,
            timeout=timeout,
            proxy=proxy_url,
        ) as resp:
            resp.raise_for_status()
            size = int(resp.headers.get("content-length", 0))
            max_delta_file_size_bytes = max_delta_file_size * 1024 * 1024
            if size > max_delta_file_size_bytes:
                raise MaxDeltaFileSizeExceededError(f"Maximum delta file size exceeded: {max_delta_file_size} MiB.")
            log.debug(f"Downloading delta file {filename}. Size {size} bytes.")
```
