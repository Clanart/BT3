## Analysis

The KIP-247 Gasless module gates a critical, value-bearing decision — whether the block proposer is allowed to front real KAIA gas to an unpaid user — on a spot-price read from an on-chain AMM (`GaslessSwapRouter.getAmountIn`, backed by a Uniswap V2-style pair), with no time-weighting or manipulation resistance. This is architecturally the same bug class as the Curve TWAP report: a price feed derived purely from the *current* reserves of a low-liquidity pool that the caller (or anyone acting in the same block) can move before the value-transfer step executes.

### Title
Gasless swap admission relies on manipulable spot-price read from `GaslessSwapRouter`/underlying AMM reserves, letting an attacker under-collateralize the proposer's gas loan - (File: kaiax/gasless/impl/tx_pool.go)

### Summary
`GaslessModule.checkBalanceForSwap` in `kaiax/gasless/impl/tx_pool.go` is the sole on-node economic check that a gasless `SwapForGas` transaction can actually repay the KAIA that the block proposer is about to lend it via `GetLendTxGenerator`/`MakeLendTx` [1](#0-0) . It validates `tx.amountIn >= gsr.getAmountIn(minAmountOut)` by making a live `eth_call` into the `GaslessSwapRouter` contract [2](#0-1) , which internally queries the underlying whitelisted DEX (Uniswap-V2-style factory/router, per `GetDEXInfo`) for its current reserves — a pure spot price with no TWAP or manipulation resistance [3](#0-2) . Because this check is evaluated against whatever state is current when the node validates/promotes the tx (tx-pool time), and the pair's reserves can be freely moved by any party swapping against the same pool in an adjacent or bundled transaction before the gasless bundle actually executes, the "required amountIn" figure the node computes is not a durable/committed value — exactly the manipulation vector described in the reference report (deposit/withdraw against a low-liquidity pool to move `get_dy`-equivalent output).

### Finding Description
The gasless flow works as follows: the block proposer (an unprivileged block-builder acting on `kaiax/gasless`) prepends a `LendTxGenerator` transaction that sends the user real KAIA out of the proposer's own balance [4](#0-3) , then bundles `[Lend, Approve?, Swap]` atomically via `ExtractTxBundles` [5](#0-4) . Whether a given `SwapForGas` call is even considered valid/admissible for this lending flow is decided by `checkBalanceForSwap`, which trusts a single, unauthenticated view call to `GaslessSwapRouter.getAmountIn(token, minAmountOut)` [2](#0-1) . That router function derives the exchange rate from the live reserves of the configured DEX pair for the token (per `dexAddress`/`getDEXInfo`), i.e. a spot price, not a manipulation-resistant oracle [6](#0-5) . Nothing in the module ties this admissibility check to the exact state the transaction will ultimately execute against, nor requires any minimum liquidity/TWAP for the underlying pair — it is identical in structure to the reported Curve-pool spot/cumulative-balance manipulation: an attacker who can move the pair's reserves (e.g., a swap against the same pool, or repeated deposit/withdraw if the pair supports it) can transiently depress the amount-in required by `getAmountIn`, causing the node to certify `amountIn` as sufficient collateral for the proposer's KAIA loan when, judged against a fair/typical price, it is not.

### Impact Explanation
If the required `amountIn` figure used for admission is manipulated downward, a malicious sender can get their `SwapForGas` bundled and lent real KAIA by the proposer (`LendTxGenerator`/`MakeLendTx`) while supplying less ERC-20 collateral than the token is actually worth. Since `swapForGas`'s actual on-chain execution also reads the (attacker-controllable) pool at execution time, the same manipulation that fooled the tx-pool-level admission check can be re-applied at execution time to make the resulting `amountOut` appear to satisfy `minAmountOut`/`amountRepay`, letting the attacker walk away with KAIA financed by the proposer for tokens that are not genuinely worth that much (fee/fee-delegation/gasless settlement theft, directly at the expense of the block proposer who fronted the KAIA). Because the router itself is only "whitelisted" (an allowed token/DEX pair set up by governance/owner) but the reserve balances of that pair are freely movable by any unprivileged trader, this is squarely a public-RPC/tx-sender-reachable value-theft path against the gasless module, matching the accepted class of "gasless or auction settlement theft."

### Likelihood Explanation
Exploitability depends heavily on the liquidity depth of the specific token/DEX pair an operator whitelists for gasless swaps; against a shallow pool (directly analogous to the ~$27k Curve pool in the original report) the reserve balance can be moved cheaply within one block via ordinary swap transactions from the same attacker, and the gasless bundle's approve+swap sequence is itself atomic and attacker-controlled, so the attacker fully controls transaction ordering intent (subject to the proposer/bundler actually including their manipulating tx first). This is a realistic, single-block, single-sender-reachable manipulation requiring no validator/node compromise — only a thinly-liquidity-backed whitelisted gasless token, which is an operational/governance choice rather than a hard protocol guarantee.

### Recommendation
- Do not rely on a live spot-price view call (`getAmountIn`) from `GaslessSwapRouter`/underlying DEX reserves as the sole gate for how much KAIA a proposer lends; require a TWAP, external price oracle, or a minimum-liquidity/deviation-from-oracle check before treating `amountIn` as sufficient.
- Re-validate the swap's actual economics at execution time against the same trusted price source used for admission (not just re-reading the same manipulable reserves), or bound the maximum single-block price impact allowed on the whitelisted pair.
- Consider requiring gasless-whitelisted tokens to only pair with pools that meet a minimum TVL/liquidity threshold enforced on-chain, and/or cap `LendAmount` independent of the attacker-supplied `minAmountOut`/`amountIn` figures.

### Proof of Concept
1. Governance/owner whitelists a token `T` for gasless swaps whose only liquidity is a shallow `T/WKAIA` Uniswap-V2-style pair registered via `GaslessSwapRouter.dexAddress`/`getDEXInfo` [6](#0-5) .
2. Attacker, in the block they intend to submit their gasless bundle, first executes an ordinary swap against the `T/WKAIA` pool to skew reserves so that `getAmountIn(T, minAmountOut)` returns an artificially low value.
3. Attacker submits `ApproveTx` + `SwapForGas(T, amountIn=<the manipulated low value>, minAmountOut, amountRepay, deadline)`; `checkBalanceForSwap` reads the now-skewed `getAmountIn` and passes the "insufficient amountIn" check that would otherwise reject the tx [2](#0-1) .
4. The gasless bundling logic (`ExtractTxBundles`) prepends `GetLendTxGenerator`'s lend transaction, and the proposer's KAIA is sent to the attacker before the swap even executes [4](#0-3) .
5. When `SwapForGas` executes on-chain against the still-skewed (or attacker-re-skewed) pool, it reports a passing `amountOut`/`amountRepay`, and the attacker keeps the proposer-funded KAIA while having deposited `T` tokens worth materially less than the loan, at the block proposer's expense.

Note: I was not able to locate the Solidity source of `GaslessSwapRouter.sol` itself in the indexed codebase (only its Go bindings/ABI were available), so the exact internal pricing formula (e.g., whether it calls `UniswapV2Library.getAmountIn` directly on raw `getReserves()`) could not be directly confirmed line-by-line — this is inferred from the ABI/ABI-bound method signatures and the whitelisted-DEX architecture described in `kaiax/gasless/impl/getter.go`. If you need to confirm the exact on-chain pricing formula, a Devin session with full repository access would be needed to inspect the Solidity sources.

// L1. LendTx.type = 0x7802 (TxTypeEthereumDynamicFee)
// L2. LendTx.from = proposer
// L3. LendTx.to = SwapTx.from
// L4. LendTx.value = LendAmount(approveTxOrNil, swapTx)
func (g *GaslessModule) GetLendTxGenerator(approveTxOrNil, swapTx *types.Transaction) *builder.TxOrGen {
	var src []byte
	if approveTxOrNil != nil {
		src = append(src, approveTxOrNil.Hash().Bytes()...)
	}
	src = append(src, swapTx.Hash().Bytes()...)
	bundleHash := crypto.Keccak256Hash(src)

	gen := func(nonce uint64) (*types.Transaction, error) {
		var (
			chainId = g.InitOpts.ChainConfig.ChainID
			signer  = types.LatestSignerForChainID(chainId)
			key     = g.InitOpts.NodeKey
		)

		to, err := types.Sender(signer, swapTx)
		if err != nil {
			return nil, err
		}

		tx, err := types.NewTransactionWithMap(types.TxTypeEthereumDynamicFee, map[types.TxValueKeyType]interface{}{
			types.TxValueKeyNonce:      nonce,
			types.TxValueKeyTo:         &to,
			types.TxValueKeyAmount:     lendAmount(approveTxOrNil, swapTx),
			types.TxValueKeyData:       common.Hex2Bytes("0x"),
			types.TxValueKeyGasLimit:   params.TxGas,
			types.TxValueKeyGasFeeCap:  swapTx.GasFeeCap(),
			types.TxValueKeyGasTipCap:  swapTx.GasTipCap(),
			types.TxValueKeyAccessList: types.AccessList{},
			types.TxValueKeyChainID:    chainId,
		})
		if err != nil {
			return nil, err
		}

		err = tx.Sign(signer, key)
		return tx, err
	}

	return builder.NewTxOrGenFromGen(gen, bundleHash)
}

func (g *GaslessModule) ExtractTxBundles(txs []*types.Transaction, prevBundles []*builder.Bundle) []*builder.Bundle {
	// there are only at most two gasless transactions in pending for a sender
	bundles := []*builder.Bundle{}
	approveTxs := map[common.Address]*types.Transaction{}
	targetTxHash := common.Hash{}
	for _, tx := range txs {
		addr, err := types.Sender(g.signer, tx)
		if err != nil {
			continue
		}
		if g.IsApproveTx(tx) {
			approveTxs[addr] = tx
		} else if g.IsSwapTx(tx) && g.IsExecutable(approveTxs[addr], tx) {
			bundleTxs := builder.NewTxOrGenList(g.GetLendTxGenerator(approveTxs[addr], tx))
			if approveTxs[addr] != nil {
				bundleTxs = append(bundleTxs, builder.NewTxOrGenFromTx(approveTxs[addr]))
			}
			bundleTxs = append(bundleTxs, builder.NewTxOrGenFromTx(tx))

			b := builder.NewBundle(
				bundleTxs,
				targetTxHash,
				false,
			)

			targetTxHash = tx.Hash()

			isConflict := false
			for _, prev := range append(prevBundles, bundles...) {
				if prev.IsConflict(b) {
					isConflict = true
					break
				}
			}
			if isConflict {
				// Gasless transactions will just fail even if they aren't bundled.
				continue
			}
			bundles = append(bundles, b)
		} else {
			targetTxHash = tx.Hash()
		}
	}
	return bundles
}
