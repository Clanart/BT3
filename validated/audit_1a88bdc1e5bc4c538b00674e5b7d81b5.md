### Title
`SignableTransaction::new` burns all inputs to fees when only `data` is provided — (`networks/bitcoin/src/wallet/send.rs`)

### Summary
The referenced bug is a payable `mint()` that accepts `amount == 0`, taking the user's ETH while minting nothing — a missing zero-value guard on a value-taking entry point. The Serai analog lives in `SignableTransaction::new`: when `payments` is empty and `change` is `None` but `data` is `Some`, the function constructs a transaction whose only output is a **zero-value OP_RETURN**, so the entire input value silently becomes miner fees. The `NoOutputs` guard explicitly exempts this case, and there is no check that any value-carrying output exists.

### Finding Description
In `networks/bitcoin/src/wallet/send.rs`, the "no outputs" validation only fires when all three of `payments`, `change`, and `data` are absent:

- `if payments.is_empty() && change.is_none() && data.is_none() { Err(TransactionError::NoOutputs)?; }` [1](#0-0) 
- The dust check rejects `amount < DUST` per payment, so a *value-bearing* output of 0 is impossible — but a data-only transaction bypasses the notion of a payment entirely [2](#0-1) 
- The OP_RETURN output is pushed with `value: Amount::ZERO` [3](#0-2) 
- The solvency check is `input_sat < payment_sat + needed_fee` — with `payment_sat == 0`, any input covering `needed_fee` passes [4](#0-3) 
- The change block only adds an output if `change` is `Some` [5](#0-4) 

Result: `SignableTransaction::new(inputs, &[], None, Some(data), fee)` succeeds and yields a TX with `input - 0 - OP_RETURN` — `fee() == sum(inputs)`, i.e. the whole UTXO value is paid to miners while the caller receives nothing spendable. This mirrors the audit report exactly: the entry point takes funds, the "thing" the caller wants (an output they control) is skipped because the count is zero, and no zero-amount/zero-beneficiary guard stops it. The test suite even codifies the hole: `assert!(SignableTransaction::new(inputs.clone(), &[], None, Some(vec![]), FEE).is_ok())` [6](#0-5) 

The FROST `multisig`/sign path then faithfully signs this transaction — the signature is valid, the funds are irrecoverably consumed as fees, and `Eventuality` completion only checks the outputs match what was signed.

### Impact Explanation
Any caller that constructs a transaction intending only to embed data (or that empties its `payments` list through upstream filtering — e.g., all payments dropped) loses the entire input value to miners instead of getting an error. For a threshold multisig wallet, this converts custodied funds into fees with a validly signed, consensus-legal transaction — identical in effect to "user paid ETH, received zero NFTs."

### Likelihood Explanation
`processor/src/networks/bitcoin.rs` currently invokes `BSignableTransaction::new` with `data: None`, so the deployed processor doesn't hit it directly [7](#0-6) . However, `SignableTransaction::new` is a public API of `bitcoin_serai::wallet` taking `data` as a caller-controlled argument, and the natural invocation "send a data-carrying TX" triggers total loss rather than a `NoOutputs`-style error. Reachable by any consumer of the library; Medium.

### Recommendation
Treat a data-only transaction the same as an empty one, or require that at least one non-OP_RETURN output exists:

- Change the guard to `Err(TransactionError::NoOutputs)` when `payments.is_empty() && change.is_none()`, regardless of `data`; or
- After building `tx_outs`, verify at least one output has `value >= DUST` (the existing `tx_outs.is_empty()` check at [8](#0-7)  only catches a fully empty vector, which `data` alone already prevents).

### Proof of Concept
```rust
// networks/bitcoin/tests/wallet.rs — with `inputs` = one funded ReceivedOutput
let tx = SignableTransaction::new(
  inputs.clone(),
  &[],                    // zero payments — the "amount == 0" analog
  None,                   // no change
  Some(b"data".to_vec()), // any data (even empty) bypasses NoOutputs
  FEE,
).unwrap();

// tx has exactly one output: OP_RETURN with value 0
assert_eq!(tx.fee(), inputs[0].value()); // entire input value paid as fee
```
The transaction is constructible, signable via `tx.multisig(&keys)`/`sign`, and broadcastable — the signer receives no spendable output while all input funds are destroyed as fees.
