### Title
Spoofable `WWW-Authenticate` header lets a malicious git remote bypass GitHub-host verification and trigger an unauthorized Enterprise sign-in/credential flow - (`app/src/lib/trampoline/trampoline-credential-helper.ts`)

### Summary
The Lybra bug let an attacker manipulate a raw, unverified value (`balanceOf` on the pair) that a security check trusted instead of a properly-verified oracle price, bypassing an "is this claimable" gate. The Desktop analog is structurally identical: `getEndpointKind()` in the trampoline credential helper trusts a raw, attacker-suppliable value — the `WWW-Authenticate` header echoed back by *any* HTTP git remote — as a "happy path" proof that a host is a genuine GitHub/GHE server, instead of relying on the properly verified check (`isGitHubHost()`, which requires the response to carry `x-github-request-id`, a header only GitHub's real infrastructure can add). A malicious or MITM'd git server can therefore forge this header to make Desktop misclassify it as `'enterprise'`, which changes the credential/authentication path Desktop takes for that host.

### Finding Description
When Git needs credentials for an HTTPS remote, it invokes Desktop's credential helper trampoline, which calls `getCredential()` → `getEndpointKind()`: [1](#0-0) 

The classification order is:
1. Known GitHub.com/GHE.com/Gist patterns (`isDotCom`, `isGHE`, `isGist`) — safe, since they're static domain allow-lists.
2. **`wwwauth[]` entries from the credential protocol** — these are `WWW-Authenticate` header values that Git captured from the HTTP response of the very server being classified and forwarded verbatim to the credential helper:
```
for (const [k, v] of cred.entries()) {
  if (k.startsWith('wwwauth[')) {
    if (v.includes('realm="GitHub"')) {
      return 'enterprise'
    } ...
```
3. Only if none of the above match does Desktop fall back to the actual verified check, `isGitHubHost()`, which performs a real HTTPS request to `/meta` and requires the `x-github-request-id` response header — a header that only genuine GitHub/GHE infrastructure can produce: [2](#0-1) 

Because step 2 is checked *before* the cryptographically-grounded step 3, and the value is fully attacker-controlled (any HTTP(S) server the user's git client talks to can return `WWW-Authenticate: realm="GitHub"` on a 401), an attacker who controls a git remote or a proxy sitting on the path to it can force `getEndpointKind()` to return `'enterprise'` for a host that is not GitHub at all — completely bypassing the legitimate verification path that exists specifically to prevent this kind of spoofing.

This misclassification changes the control flow in `getCredential()`: [3](#0-2) 
Since `endpointKind !== 'generic'` and no existing account matches the spoofed endpoint, Desktop calls `ui.promptForGitHubSignIn(endpoint)`, which starts a GitHub Enterprise sign-in flow scoped to the **attacker's own endpoint**: [4](#0-3) 
and `SignInStore.setEndpoint()` will happily proceed to the authentication step for that attacker-chosen origin: [5](#0-4) 

### Impact Explanation
- The corrupted value is the **trust classification of a remote host** (`endpointKind`), which is supposed to be derived only from a verified request (`isGitHubHost`) but can instead be forced via a forged, attacker-supplied header.
- The practical effect is that Desktop's credential-helper logic silently treats an attacker's server as a legitimate "GitHub Enterprise" endpoint, generating an unsolicited GitHub Enterprise sign-in/OAuth prompt scoped to that attacker endpoint during what looks like a routine `fetch`/`push`/`pull` operation, rather than routing to the generic-credential/external-helper path a non-GitHub host should take.
- If the user completes that sign-in (believing it's part of the normal auth flow for the repository they're working with), a real `Account` (with a live GitHub token) ends up bound to the attacker-controlled endpoint in `AccountsStore`, and subsequent git operations to that same origin will have that account's credentials attached automatically via `findGitHubTrampolineAccount`'s origin match — i.e., the token gets sent to the attacker's server on future contact. This matches "unauthorized OAuth/account binding" and "credential exfiltration" categories.
- Existing guardrail (`isGitHubHost`'s certificate/`x-github-request-id` check) exists precisely to prevent exactly this kind of spoofing, but it's never reached because the `wwwauth[]` shortcut returns first.

### Likelihood Explanation
Any git server the app talks to (a malicious remote the user adds/clones, a compromised mirror, or a network MITM/proxy for an HTTP git remote) can trivially add a `WWW-Authenticate: realm="GitHub"` header to a 401 response — no special privileges, no local access, and no dependency on any existing credential are required. The trigger is a normal git network operation (clone/fetch/push), something users perform constantly, not an unnatural manual step.

### Recommendation
Do not treat the `wwwauth[]` realm value as sufficient evidence of a GitHub/Enterprise host. Either drop this shortcut entirely and always fall back to the verified `isGitHubHost()` check (which validates via a real request and the `x-github-request-id` header), or only use the `wwwauth[]` hint to skip straight to running `isGitHubHost()` sooner — never to directly return `'enterprise'`.

### Proof of Concept
1. Attacker stands up an HTTP git remote (or sits on-path as a proxy for one) and configures it to answer any request Desktop makes (e.g. the initial ref-advertisement request during `git fetch`) with `401` and header `WWW-Authenticate: Basic realm="GitHub"`.
2. User adds/clones this remote in GitHub Desktop and performs a fetch/pull/push.
3. Git captures the `WWW-Authenticate` header and forwards it to Desktop's credential helper as `wwwauth[0]=Basic realm="GitHub"`.
4. `getEndpointKind()` in `app/src/lib/trampoline/trampoline-credential-helper.ts` matches `realm="GitHub"` and returns `'enterprise'` without ever calling `isGitHubHost()`.
5. Since no account exists for that endpoint, `getCredential()` invokes `ui.promptForGitHubSignIn(attackerEndpoint)`, opening a GitHub Enterprise sign-in flow scoped to the attacker's origin instead of treating it as a generic git host.

/** Implementation of the 'get' git credential helper command */
async function getCredential(cred: Credential, store: Store, token: string) {
  const ghCred = await getGitHubCredential(cred, store)

  if (ghCred) {
    return ghCred
  }

  const endpointKind = await getEndpointKind(cred, store)
  const accounts = await store.getAll()

  const endpoint = `${getCredentialUrl(cred)}`
  const apiEndpoint = getAPIEndpoint(endpoint)

  // If it appears as if the endpoint is a GitHub host and we don't have an
  // account for that endpoint then we should prompt the user to sign in.
  if (
    endpointKind !== 'generic' &&
    !accounts.some(a => a.endpoint === apiEndpoint)
  ) {
    if (getIsBackgroundTaskEnvironment(token)) {
      debug('background task environment, skipping prompt')
      return undefined
    }

    const account = await ui.promptForGitHubSignIn(endpoint)

    if (!account) {
      setHasRejectedCredentialsForEndpoint(token, endpoint)
    }

    return credWithAccount(cred, account)
  }

  // GitHub.com/GHE creds are only stored internally
  if (endpointKind !== 'generic') {
    return undefined
  }

  return useExternalCredentialHelper()
    ? getExternalCredential(cred, token)
    : getGenericCredential(cred, token)
}

const getEndpointKind = async (cred: Credential, store: Store) => {
  const credentialUrl = getCredentialUrl(cred)
  const endpoint = `${credentialUrl}`

  if (isGist(endpoint)) {
    return 'generic'
  }

  if (isDotCom(endpoint)) {
    return 'github.com'
  }

  if (isGHE(endpoint)) {
    return 'ghe.com'
  }

  // When Git attempts to authenticate with a host it captures any
  // WWW-Authenticate headers and forwards them to the credential helper. We
  // use them as a happy-path to determine if the host is a GitHub host without
  // having to resort to making a request ourselves.
  for (const [k, v] of cred.entries()) {
    if (k.startsWith('wwwauth[')) {
      if (v.includes('realm="GitHub"')) {
        return 'enterprise'
      } else if (/realm="(GitLab|Gitea|Atlassian Bitbucket)"/.test(v)) {
        return 'generic'
      }
    }
  }

  const existingAccount = await findGitHubTrampolineAccount(store, endpoint)
  if (existingAccount) {
    return isDotCom(existingAccount.endpoint) ? 'github.com' : 'enterprise'
  }

  // All GitHub hosts use HTTPS, so if the protocol is not HTTPS we can
  // assume that this is not a GitHub host.
  if (credentialUrl.protocol !== 'https:') {
    return 'generic'
  }

  return (await isGitHubHost(endpoint)) ? 'enterprise' : 'generic'
}

  public promptForGitHubSignIn(endpoint: string): Promise<Account | undefined> {
    return new Promise<Account | undefined>(async resolve => {
      const cb = (result: SignInResult) => {
        resolve(result.kind === 'success' ? result.account : undefined)
        this.dispatcher.closePopup(PopupType.SignIn)
      }

      const { hostname, origin } = new URL(endpoint)
      if (hostname === 'github.com') {
        this.dispatcher.beginDotComSignIn(cb)
      } else {
        this.dispatcher.beginEnterpriseSignIn(cb)
        await this.dispatcher.setSignInEndpoint(origin)
      }

      this.dispatcher.showPopup({
        type: PopupType.SignIn,
        isCredentialHelperSignIn: true,
        credentialHelperUrl: endpoint,
      })
    }).catch(e => {
      log.error(`Could not prompt for GitHub sign in`, e)
      return undefined
    })
  }

  public async setEndpoint(url: string): Promise<void> {
    const currentState = this.state

    if (
      currentState?.kind !== SignInStep.EndpointEntry &&
      currentState?.kind !== SignInStep.ExistingAccountWarning
    ) {
      const stepText = currentState ? currentState.kind : 'null'
      return fatalError(
        `Sign in step '${stepText}' not compatible with endpoint entry`
      )
    }

    /**
     * If the user enters a github.com url in the GitHub Enterprise sign-in
     * flow we'll redirect them to the GitHub.com sign-in flow.
     */
    if (/^(?:https:\/\/)?(?:api\.)?github\.com($|\/)/.test(url)) {
      this.beginDotComSignIn(currentState.resultCallback)
      return
    }

    this.setState({ ...currentState, loading: true })

    let validUrl: string
    try {
      validUrl = validateURL(url)
    } catch (e) {
      let error = e
      if (e.name === InvalidURLErrorName) {
        error = new Error(
          `The GitHub Enterprise instance address doesn't appear to be a valid URL. We're expecting something like https://example.ghe.com.`
        )
      } else if (e.name === InvalidProtocolErrorName) {
        error = new Error(
          'Unsupported protocol. Only https is supported when authenticating with GitHub Enterprise instances.'
        )
      }

      this.setState({ ...currentState, loading: false, error })
      return
    }

    const endpoint = getEnterpriseAPIURL(validUrl)

    const existingAccount = this.accounts.find(x => x.endpoint === endpoint)

    if (existingAccount) {
      this.setState({
        kind: SignInStep.ExistingAccountWarning,
        endpoint,
        existingAccount,
        error: null,
        loading: false,
        resultCallback: currentState.resultCallback,
      })
    } else {
      this.setState({
        kind: SignInStep.Authentication,
        endpoint,
        error: null,
        loading: false,
        resultCallback: currentState.resultCallback,
      })
    }
  }
