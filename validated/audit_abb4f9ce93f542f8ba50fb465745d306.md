## Analog Found

### Title
Reward-per-share rounds to zero via temporary inflation of `totalStaked()`, permanently freezing harvested yield - (File: rewards/BaseRewardPool.sol)

### Summary
`BaseRewardPool` (and its clone `BaseRewardPoolV2`) tracks pool rewards using a per-share accumulator (`rewardPerTokenStored`) that is updated by dividing an incoming reward amount by `totalStaked()`. Unlike a real reserve, `totalStaked()` is simply `IERC20(stakingToken).balanceOf(operator)` — the live balance of `MasterMagpie`, which any unprivileged wallet can inflate for free by depositing and withdrawing the pool's staking token in the same transaction (no cooldown, no fee for ordinary LP staking-token pools). If a reward is queued while this balance is inflated, the division rounds to zero, and the reward tokens that were physically transferred into the contract become permanently unaccounted for and unclaimable by any user — the same class of bug as the reported Portfolio.sol issue, where an inflated denominator causes a division to round to zero and decouples a real token movement from the internal per-unit accounting.

### Finding Description
`_provisionReward` in `BaseRewardPool.sol` computes: [1](#0-0) 

The critical lines are:
```
if (this.totalStaked() == 0) {
    rewardInfo.queuedRewards += _amountReward;
} else {
    ...
    rewardInfo.rewardPerTokenStored += (_amountReward * 10**stakingDecimals()) / this.totalStaked();

``` [2](#0-1) 

`totalStaked()` is defined as `IERC20(stakingToken).balanceOf(operator)` where `operator` is `MasterMagpie`. This is not a siloed, monotonic "reserve" tied to reward accounting — it is the live, freely-mutable token balance of the whole contract, exactly analogous to `iteration.liquidity` in the Portfolio.sol report being a freely-inflatable divisor. Any wallet can call `MasterMagpie.deposit`/`withdraw` (unprivileged, no lock, `nonReentrant` only) to move the staking token balance up and back down within the same block/transaction: [3](#0-2) 

`donateRewards` on `BaseRewardPool` is fully public and unprivileged: [4](#0-3) 

and the same rounding is reachable through the normal harvest path (`queueNewRewards`, called by managers such as `WombatStaking`/pool helpers whenever WOM/bribe rewards are harvested): [5](#0-4) 

If `totalStaked()` is temporarily driven to a very large number (e.g., via a flash-loaned or otherwise briefly-held large amount of the staking token deposited into `MasterMagpie`) at the moment a reward is queued (either the attacker's own `donateRewards` call, or by front-running/sandwiching a legitimate harvest that calls `queueNewRewards`), `(_amountReward * 10**stakingDecimals) / totalStaked()` rounds to zero. Since `totalStaked() != 0`, the `queuedRewards` fallback (meant to preserve rewards when there are no stakers) is never triggered, so the reward amount is silently dropped from `rewardPerTokenStored` while `historicalRewards` still increases and the actual reward tokens sit in the contract with no code path crediting them to any staker's `userRewards`.

### Impact Explanation
Reward tokens (WOM, MGP, or bribe tokens) that are physically transferred into `BaseRewardPool`/`BaseRewardPoolV2` via `queueNewRewards`/`donateRewards` become permanently stuck: they are not reflected in `rewardPerTokenStored`, there is no sweep/recovery mechanism in the contract, and future `queueNewRewards` calls only add to the accumulator prospectively — they cannot retroactively recover the lost slice. This is a permanent freezing of unclaimed yield for every staker of the affected pool, triggerable entirely from an unprivileged wallet.

### Likelihood Explanation
The staking-token deposit/withdraw path is completely free of locks or fees for ordinary LP pools registered in `MasterMagpie`, and reversible within one transaction, so the only real cost to the attacker is briefly sourcing a large amount of the staking token (e.g., via flash loan of the underlying deposit token routed through `WombatStaking.deposit`/`depositLP`, or of the receipt token itself if a market exists) plus gas. Since harvest calls (`WombatPoolHelper.harvest()` → `WombatStaking.harvest` → `queueNewRewards`) are public and their timing is predictable/triggerable, an attacker can reliably sandwich a legitimate reward-queuing transaction to zero out that epoch's reward distribution for a target pool.

### Recommendation
Do not use a freely mutable external balance (`IERC20(stakingToken).balanceOf(operator)`) as the divisor for reward-per-share accounting. Track an internal, monotonically-consistent "shares" ledger (e.g., a running `totalStaked` state variable updated only inside `_deposit`/`_withdraw`, not derived from `balanceOf`), and/or fall back to the `queuedRewards` mechanism whenever the computed `rewardPerTokenStored` delta would be zero due to rounding (not just when `totalStaked() == 0`), so that incoming rewards are never silently lost regardless of the instantaneous stake size.

### Proof of Concept
1. Attacker obtains (e.g., via flash loan) a very large amount of a pool's `stakingToken` (the Wombat receipt token for that pool).
2. Attacker calls `MasterMagpie.deposit(stakingToken, hugeAmount)` [6](#0-5) , inflating `IERC20(stakingToken).balanceOf(MasterMagpie)` to a very large value, which is what `BaseRewardPool.totalStaked()` returns [7](#0-6) .
3. In the same transaction, attacker triggers (or is naturally in front of) a `queueNewRewards`/`donateRewards` call carrying real reward tokens; the division `(_amountReward * 10**stakingDecimals) / totalStaked()` rounds to zero [8](#0-7) , so `rewardPerTokenStored` is unchanged while the reward tokens remain in the contract.
4. Attacker calls `MasterMagpie.withdraw(stakingToken, hugeAmount)` [9](#0-8)  to retrieve their flash-loaned tokens, repaying the loan.
5. The reward tokens transferred in step 3 are now permanently unclaimable by any existing or future staker of that pool, since `rewardPerTokenStored` never reflects them and no recovery path exists.

    function _provisionReward(uint256 _amountReward, address _rewardToken) internal {
        IERC20(_rewardToken).safeTransferFrom(
            msg.sender,
            address(this),
            _amountReward
        );
        Reward storage rewardInfo = rewards[_rewardToken];
        rewardInfo.historicalRewards =
            rewardInfo.historicalRewards +
            _amountReward;
        if (this.totalStaked() == 0) {
            rewardInfo.queuedRewards += _amountReward;
        } else {
            if (rewardInfo.queuedRewards > 0) {
                _amountReward += rewardInfo.queuedRewards;
                rewardInfo.queuedRewards = 0;
            }
            rewardInfo.rewardPerTokenStored =
                rewardInfo.rewardPerTokenStored +
                (_amountReward * 10**stakingDecimals()) /
                this.totalStaked();
        }
        emit RewardAdded(_amountReward, _rewardToken);
```
