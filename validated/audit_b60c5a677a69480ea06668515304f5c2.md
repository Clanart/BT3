### Title
Payout `OP_RETURN` operator attribution is not bound by the user's withdrawal signature, allowing an operator to be reimbursed for a payout it never funded - ([File: core/src/builder/transaction/operator_reimburse.rs])

### Summary

### Finding Description
The Clementine payout transaction is authorized by the withdrawing user with a signature that is expected to use the `SIGHASH_SINGLE | ANYONECANPAY` sighash type, as documented explicitly in `Operator::withdraw`: [1](#0-0) 

This sighash type only commits the user's signed input to the output at the *same index* (index 0, the payout output to the withdrawer) and does **not** commit to any other input or output of the transaction. `create_payout_txhandler` builds the transaction with exactly this structure: input 0 is the user-authorized UTXO, output 0 is the payout, and a later, *unsigned-by-the-user* output 2 is an `OP_RETURN` embedding whichever `operator_xonly_pk` the transaction *builder* chooses: [2](#0-1) 

Because `ANYONECANPAY` exempts all other inputs from the signature and `SIGHASH_SINGLE` only binds output 0, any party that can observe the signed input/output-0 pair (e.g., in the mempool, or via any legitimate service attempt) can re-assemble an entirely different transaction: reusing the identical user-signed input and output 0 (which the signature actually enforces), adding their own funding input(s) to cover the payout value (paid with their own BTC), and substituting **any operator's `xonly_pk`** into the `OP_RETURN` output — with no cryptographic tie to whoever actually supplied the funding input.

Downstream, this forged attribution is trusted verbatim. `Verifier::update_finalized_payouts` parses the confirmed payout transaction's `OP_RETURN` and stores whatever `operator_xonly_pk` it contains as `payout_payer_operator_xonly_pk`, without any check that this key corresponds to the party that actually funded the payout: [3](#0-2) 

The operator automation (`PayoutCheckerTask`) then looks up unhandled payouts strictly by this stored `operator_xonly_pk`: [4](#0-3) 

and `Operator::handle_finalized_payout`/`validate_payer_is_operator` proceed to claim reimbursement (kickoff → reimburse flow from the move-to-vault UTXO) purely based on this attribution, again with no check against the actual source of the payout funds: [5](#0-4) [6](#0-5) 

This same unauthenticated `OP_RETURN` value is also what the bridge circuit relies on as ground truth for `operator_xonlypk` when computing the deposit constant used to authorize on-chain reimbursement claims, so there is no additional cryptographic check anywhere in the pipeline that ties the credited operator to the party that actually funded the withdrawal: [7](#0-6) 

This is structurally the same class of bug as the referenced `Vault.redeem`/`syncFeeCheckpoint` report: a value/state binding (there, `highWaterMark` vs. actual share price; here, "party that funded the payout" vs. "party credited for reimbursement") is updated/derived through one code path (`OP_RETURN` construction) that is not actually constrained by the authorization mechanism (the user's `SIGHASH_SINGLE|ANYONECANPAY` signature) that is supposed to make it trustworthy.

### Impact Explanation
An unprivileged party (anyone who observes a broadcast/pending payout transaction, since inputs signed with `ANYONECANPAY` are mempool-visible and freely re-composable) can front the exact same withdrawal payout using their own funds while embedding an arbitrary operator's `xonly_pk` — including an honest, uninvolved operator's key — into the `OP_RETURN` output of the transaction that ultimately confirms. Once confirmed, that named operator's own automation (`PayoutCheckerTask`) will treat the payout as its own and proceed through the normal kickoff/reimburse flow, resulting in that operator being reimbursed the full bridge amount for a peg-out it never funded. This matches the Critical impact category "an operator reimbursed for a payout it never funded," since the binding `credited_operator == funding_party` is broken by an attacker who supplies no privileged role, only observation of the mempool and their own BTC to front the same payout output.

### Likelihood Explanation
The precondition is only that the user's payout-authorizing signature (`SIGHASH_SINGLE|ANYONECANPAY`) and the withdrawal details become visible before the intended operator's transaction confirms, which is inherent to how such transactions must be broadcast to the Bitcoin mempool to be mined. No verifier, operator, aggregator, or other privileged role is required by the attacker; any unprivileged Bitcoin participant capable of constructing and funding an alternative transaction with the reused input/output-0 pair can carry out the attack.

### Recommendation
Bind the `OP_RETURN` operator attribution to the same signature commitment that authorizes the payout, e.g., by having the user's signature use `SIGHASH_ALL` (or a sighash type that commits to all outputs) once the true operator has been fixed, or by having the intended operator co-sign/commit to their own `xonly_pk` as part of the authorized payout structure, so that only the operator who is cryptographically bound to a given payout construction can be credited for it. Alternatively, require the verifier's `update_finalized_payouts` logic to independently validate that the funding inputs of the confirmed payout transaction are attributable to the operator named in its `OP_RETURN` output before recording `payout_payer_operator_xonly_pk`.

### Proof of Concept
1. User signs a payout authorization with `SIGHASH_SINGLE | ANYONECANPAY` over input 0 (the dust/withdrawal UTXO) and output 0 (the payout to their address), as required by `Operator::withdraw` (`core/src/operator.rs:614-637`).
2. Honest operator A begins constructing/broadcasting the payout transaction via `create_payout_txhandler`, funding it with A's own additional inputs and embedding A's `xonly_pk` in the `OP_RETURN` output (`core/src/builder/transaction/operator_reimburse.rs:407-436`).
3. Attacker observes the pending transaction (or independently reconstructs it from the same off-chain signature), builds a competing transaction reusing the identical signed input 0 and output 0 (both enforced by the `SIGHASH_SINGLE|ANYONECANPAY` signature), but adds their own funding input(s) to cover output 0's value and substitutes victim operator B's `xonly_pk` into the `OP_RETURN` output.
4. Attacker's transaction confirms instead of (or before) operator A's.
5. `Verifier::update_finalized_payouts` parses the confirmed transaction and records `payout_payer_operator_xonly_pk = B` (`core/src/verifier.rs:2312-2335`).
6. Operator B's own `PayoutCheckerTask`, seeing an unhandled payout matching its key (`core/src/database/verifier.rs:282-313`), automatically drives `handle_finalized_payout` and claims reimbursement from the deposit's move-to-vault UTXO (`core/src/operator.rs:839-916`), even though B never funded the payout — the funds were fronted by the attacker.

    async fn validate_payer_is_operator(
        &self,
        dbtx: Option<DatabaseTransaction<'_>>,
        deposit_id: u32,
    ) -> Result<(BlockHash, Txid), BridgeError> {
        let (payer_xonly_pk, payout_blockhash, kickoff_txid) = self
            .db
            .get_payer_xonly_pk_blockhash_and_kickoff_txid_from_deposit_id(dbtx, deposit_id)
            .await?;

        tracing::info!(
            "Payer xonly pk and kickoff txid found for the requested deposit, payer xonly pk: {:?}, kickoff txid: {:?}",
            payer_xonly_pk,
            kickoff_txid
        );

        // first check if the payer is the operator, and the kickoff is handled
        // by the PayoutCheckerTask, meaning kickoff_txid is set
        let (payout_blockhash, kickoff_txid) = match (
            payer_xonly_pk,
            payout_blockhash,
            kickoff_txid,
        ) {
            (Some(payer_xonly_pk), Some(payout_blockhash), Some(kickoff_txid)) => {
                if payer_xonly_pk != self.signer.xonly_public_key {
                    return Err(eyre::eyre!(
                        "Payer is not own operator for deposit, payer xonly pk: {:?}, operator xonly pk: {:?}",
                        payer_xonly_pk,
                        self.signer.xonly_public_key
                    )
                    .into());
                }
                (payout_blockhash, kickoff_txid)
            }
            _ => {
                return Err(eyre::eyre!(
                    "Payer info not found for deposit, payout blockhash: {:?}, kickoff txid: {:?}",
                    payout_blockhash,
                    kickoff_txid
                )
                .into());
            }
        };

        tracing::info!(
            "Payer xonly pk, payout blockhash and kickoff txid found and valid for own operator for the requested deposit id: {}, payer xonly pk: {:?}, payout blockhash: {:?}, kickoff txid: {:?}",
            deposit_id,
            payer_xonly_pk,
            payout_blockhash,
            kickoff_txid
        );

        Ok((payout_blockhash, kickoff_txid))
    }

pub fn create_payout_txhandler(
    input_utxo: UTXO,
    output_txout: TxOut,
    operator_xonly_pk: XOnlyPublicKey,
    user_sig: taproot::Signature,
    _network: bitcoin::Network,
) -> Result<TxHandler<Signed>, BridgeError> {
    let txin = SpendableTxIn::new_partial(input_utxo.outpoint, input_utxo.txout);

    let output_txout = UnspentTxOut::from_partial(output_txout.clone());

    let op_return_txout = op_return_txout(PushBytesBuf::from(operator_xonly_pk.serialize()));

    let mut txhandler = TxHandlerBuilder::new(TransactionType::Payout)
        .with_version(NON_STANDARD_V3)
        .add_input(
            NormalSignatureKind::NotStored,
            txin,
            SpendPath::KeySpend,
            DEFAULT_SEQUENCE,
        )
        .add_output(output_txout)
        .add_output(UnspentTxOut::from_partial(anchor_output(
            NON_EPHEMERAL_ANCHOR_AMOUNT,
        )))
        .add_output(UnspentTxOut::from_partial(op_return_txout))
        .finalize();
    txhandler.set_p2tr_key_spend_witness(&user_sig, 0)?;
    txhandler.promote()
}

    pub async fn get_first_unhandled_payout_by_operator_xonly_pk(
        &self,
        tx: Option<DatabaseTransaction<'_>>,
        operator_xonly_pk: XOnlyPublicKey,
    ) -> Result<Option<(u32, Txid, BlockHash)>, BridgeError> {
        let query = sqlx::query_as::<_, (i32, Option<TxidDB>, Option<BlockHashDB>)>(
            "SELECT w.idx, w.move_to_vault_txid, w.payout_tx_blockhash
             FROM withdrawals w
             WHERE w.payout_txid IS NOT NULL
                AND w.is_payout_handled = FALSE
                AND w.payout_payer_operator_xonly_pk = $1
                ORDER BY w.idx ASC
             LIMIT 1",
        )
        .bind(XOnlyPublicKeyDB(operator_xonly_pk));

        let results = execute_query_with_tx!(self.connection, tx, query, fetch_optional)?;

        results
            .map(|(citrea_idx, move_to_vault_txid, payout_tx_blockhash)| {
                Ok((
                    u32::try_from(citrea_idx).wrap_err("Failed to convert citrea index to u32")?,
                    move_to_vault_txid
                        .expect("move_to_vault_txid Must be Some")
                        .0,
                    payout_tx_blockhash
                        .expect("payout_tx_blockhash Must be Some")
                        .0,
                ))
            })
            .transpose()
    }

fn host_deposit_constant(
    input: &BridgeCircuitInput,
) -> Result<DepositConstant, BridgeCircuitHostParamsError> {
    let first_op_return_output = get_first_op_return_output(&input.payout_spv.transaction)
        .ok_or(BridgeCircuitHostParamsError::InvalidOperatorPubkey)?;

    let deposit_storage_proof: EIP1186StorageProof =
        serde_json::from_str(&input.sp.storage_proof_deposit_txid).map_err(|e| {
            BridgeCircuitHostParamsError::StorageProofDeserializationError(e.to_string())
        })?;

    let round_txid = input.kickoff_tx.input[0]
        .previous_output
        .txid
        .to_byte_array();

    let kickoff_round_vout = input.kickoff_tx.input[0].previous_output.vout;

    let operator_xonlypk: [u8; 32] = parse_op_return_data(&first_op_return_output.script_pubkey)
        .ok_or(BridgeCircuitHostParamsError::InvalidOperatorPubkey)?
        .try_into()
        .map_err(|_| BridgeCircuitHostParamsError::InvalidOperatorPubkey)?;

    let deposit_value_bytes: [u8; 32] = deposit_storage_proof.value.to_be_bytes::<32>();

    Ok(deposit_constant(
        operator_xonlypk,
        input.watchtower_challenge_connector_start_idx,
        &input.all_tweaked_watchtower_pubkeys,
        deposit_value_bytes,
        round_txid,
        kickoff_round_vout,
        input.hcp.genesis_state_hash,
    ))
}
