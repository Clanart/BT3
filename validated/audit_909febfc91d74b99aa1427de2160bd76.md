### Title
`ReceivedOutput::read` accepts untrusted bytes without verifying the offset actually derives the output's `script_pubkey` — inconsistent-object / missing ownership-binding check analogous to unauthenticated IDOR - (File: networks/bitcoin/src/wallet/mod.rs)

### Summary
The reference bug class is a resource fetched by an attacker-supplied identifier (`flow_id`, `file_name`) where the "ownership check" — verifying the resource belongs to the requester — is missing on one code path while enforced on all sibling paths. In `bitcoin-serai`, the same shape exists: the *construction* path (`Scanner::scan_transaction`) proves each returned `ReceivedOutput` pays to `key + offset·G` by looking the `script_pubkey` up in `self.scripts`, but the *deserialization* path (`ReceivedOutput::read`) accepts `offset`, `output`, and `outpoint` verbatim with no consistency check at all. Any consumer that reconstructs a `ReceivedOutput` from untrusted bytes gets an object claiming wallet ownership of an output the wallet cannot spend.

### Finding Description
`Scanner::scan_transaction` only emits a `ReceivedOutput` when `output.script_pubkey` is present in `self.scripts`, i.e., when the offset provably derives the output's Taproot key (`mod.rs:199-214`). `ReceivedOutput::read` (`mod.rs:122-134`) deserializes the same three fields with no key available and no verification that `p2tr_script_buf(key + GENERATOR * offset) == output.script_pubkey`. This is the direct analog of `download_image` lacking `Depends(get_flow)`: the enforcement point exists on one path and is absent on the other.

Downstream, `send`/`SignableTransaction` machinery consumes `received.offset()` to derive the signing key for that input. If `offset` does not correspond to `output.script_pubkey`, the produced Schnorr signature is valid for a *different* key, so the input is unspendable — while the wallet/integrator has already accounted it as received funds (`value()` returns the full output amount).

### Impact Explanation
Funds reported received that are not spendable — an accepted impact class. An attacker who can feed crafted bytes to `ReceivedOutput::read` (the prompt's accepted reachability surface) can make a consumer credit an outpoint paying to an arbitrary script (including the attacker's own key) as a wallet-owned, spendable output of `offset`. The wallet then includes this phantom input in spends; the transaction is either invalid on-chain (wasting the real inputs' fees / halting burns) or the accounting layer overstates spendable balance. This mirrors the IDOR's cross-tenant leak: a bare identifier (outpoint) is honored without proving ownership.

### Likelihood Explanation
Medium-to-low reachability: it requires a path where serialized `ReceivedOutput`s cross a trust boundary (e.g., service-to-service queue messages, coordinator-supplied data) rather than being produced locally by `scan_block`. Within the stated scope rules, untrusted bytes into `ReceivedOutput::read` qualify as reachable, but I could not fully confirm in the indexed code how widely `read` is used on externally sourced data versus purely local caching — that determines whether this is High or Medium.

### Recommendation
Either store the base `key` alongside and have `read` take the `Scanner`/key and re-derive `p2tr_script_buf(key + offset·G)` to compare against `output.script_pubkey` (rejecting mismatches), or document `read` as trusted-only and have every consumer that ingests external `ReceivedOutput`s re-scan the referenced transaction via `scan_transaction` before crediting funds.

let attacker_offset = Scalar::ONE;
let foreign_txout = TxOut {

    script_pubkey: ScriptBuf::new_p2tr_tweaked(/* attacker's key */),

let foreign_outpoint = OutPoint::new(attacker_txid, 0);

let mut buf = vec![];
buf.extend(attacker_offset.to_bytes());
buf.extend(serialize(&foreign_txout));
buf.extend(serialize(&foreign_outpoint));

// Accepted with no ownership/consistency check (mod.rs:122-134)
let ro = ReceivedOutput::read(&mut &buf[..]).unwrap();
assert_eq!(ro.value(), 100_000); // credited as wallet funds
// Any spend using ro.offset() signs with key+1·G, which does not
// control foreign_txout.script_pubkey -> unspendable input.

  /// Read a ReceivedOutput from a generic satisfying Read.
  #[cfg(feature = "std")]
  pub fn read<R: Read>(r: &mut R) -> io::Result<ReceivedOutput> {
    let offset = Secp256k1::read_F(r)?;
    let output;
    let outpoint;
    {
      let mut buf_r = BufReader::with_capacity(0, r);
      output =
        TxOut::consensus_decode(&mut buf_r).map_err(|_| io::Error::other("invalid TxOut"))?;
      outpoint =
        OutPoint::consensus_decode(&mut buf_r).map_err(|_| io::Error::other("invalid OutPoint"))?;
    }
    Ok(ReceivedOutput { offset, output, outpoint })
  }

  /// Scan a transaction.
  pub fn scan_transaction(&self, tx: &Transaction) -> Vec<ReceivedOutput> {
    let mut res = Vec::new();
    for (vout, output) in tx.output.iter().enumerate() {
      // If the vout index exceeds 2**32, stop scanning outputs
      let Ok(vout) = u32::try_from(vout) else { break };

      if let Some(offset) = self.scripts.get(&output.script_pubkey) {
        res.push(ReceivedOutput {
          offset: *offset,
          output: output.clone(),
          outpoint: OutPoint::new(tx.compute_txid(), vout),
        });
      }
    }
    res
  }
