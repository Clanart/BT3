### Title
Attacker-controlled `WWW-Authenticate` realm header forces GitHub Enterprise sign-in prompt for an arbitrary remote, enabling account-binding/OAuth phishing - ([File: app/src/lib/trampoline/trampoline-credential-helper.ts])

### Summary
`getEndpointKind` in the Git credential-helper trampoline classifies an unknown remote as a GitHub Enterprise host solely by inspecting the `wwwauth[...]` fields that Git forwards from the remote server's HTTP `WWW-Authenticate` response header, without any independent verification of the host. A malicious or compromised Git server (added as a remote, or reached via a proxy/redirect) can set `WWW-Authenticate: Basic realm="GitHub"` and cause GitHub Desktop to treat it as a legitimate GitHub Enterprise endpoint, triggering `promptForGitHubSignIn` and a full Enterprise OAuth sign-in flow bound to the attacker's host.

### Finding Description
When Git needs credentials for an HTTPS remote, it invokes the configured credential helper (`GIT_CONFIG_PARAMETERS` set by Desktop, see `withTrampolineEnv` in `app/src/lib/trampoline/trampoline-environment.ts:143`), which routes to `createCredentialHelperTrampolineHandler` → `getCredential` → `getEndpointKind`.

`getEndpointKind` uses a chain of heuristics to decide whether a remote is `'github.com'`, `'ghe.com'`, `'enterprise'`, or `'generic'`: [1](#0-0) 

This block trusts the `wwwauth[...]` credential fields — which originate from the remote server's `WWW-Authenticate` response header, an attacker-controlled value when the attacker operates (or has compromised, or proxies) the Git remote — and unconditionally returns `'enterprise'` if the realm string contains `GitHub`, with **no network verification** (unlike the fallback path a few lines below that actually calls `isGitHubHost(endpoint)` to make a real HTTP request to confirm GitHubness): [2](#0-1) 

Once classified as `'enterprise'`/`'github.com'` (i.e. not `'generic'`) and no existing account matches the endpoint, `getCredential` unconditionally invokes the GitHub sign-in UI for that attacker-controlled endpoint: [3](#0-2) 

`promptForGitHubSignIn` then starts a real Enterprise sign-in flow scoped to that origin, and calls `dispatcher.setSignInEndpoint(origin)` before showing the sign-in popup — i.e., Desktop's legitimate GitHub sign-in dialog is bound to the attacker's endpoint: [4](#0-3) 

The broken invariant is the same class as the report's seed bug: a security-relevant value (`endpointKind`, driving whether the "trusted GitHub sign-in" path is taken) is derived from mutable, externally-supplied input (`wwwauth[...]`) without validation, and that value is then used to drive a privileged action (initiating an OAuth/enterprise sign-in flow and, on success, persisting an `Account` keyed by the attacker's endpoint in `AccountsStore`) that the rest of the code assumes only happens for genuine GitHub hosts.

### Impact Explanation
This is exploitable purely by an attacker who controls the Git remote/proxy response (in-scope per the impact list: "a git remote/proxy response"). By spoofing `WWW-Authenticate: ... realm="GitHub"` on any HTTPS 401 challenge, the attacker causes Desktop's native "Sign in to GitHub Enterprise" dialog to appear for their arbitrary hostname. Because this is Desktop's own trusted-looking sign-in UI (not a webpage the user must judge for phishing signs), a user who completes it will bind a GitHub account/token to the attacker's endpoint in the `AccountsStore`, and Desktop will subsequently trust and auto-send that account's stored credentials for any future request matching that endpoint's origin (see `findGitHubTrampolineAccount`, which matches purely by URL origin). This falls under "unauthorized OAuth or account binding," an explicitly in-scope impact.

### Likelihood Explanation
Requires only that the victim add/clone/fetch from an attacker-controlled or attacker-proxied HTTPS remote and encounter an HTTP auth challenge — no local access, no malware, no leaked credentials, and no unusual user steps beyond normal Git usage. The `wwwauth[...]` values are populated directly from server response headers by Git itself and passed to the credential helper verbatim, so nothing in the existing code path validates or challenges this header before trusting it as a `'GitHub'` realm classification.

### Recommendation
Do not trust the `WWW-Authenticate` realm string alone to classify a host as GitHub/Enterprise. Require the same network-based verification (`isGitHubHost`) used in the fallback path before ever short-circuiting to `'enterprise'`/`'github.com'`, or at minimum require a successful `isGitHubHost` check (which validates via `x-github-request-id`/`/meta` probing) in addition to the header hint before invoking `promptForGitHubSignIn`.

### Proof of Concept
1. Stand up a Git-smart-HTTP server (or MITM proxy) at `https://evil.example.com/repo.git` that responds to unauthenticated requests with `401` and header `WWW-Authenticate: Basic realm="GitHub"`.
2. In GitHub Desktop, clone or fetch from `https://evil.example.com/repo.git` without a pre-existing account for that endpoint.
3. Git invokes the credential helper; `getEndpointKind` (`app/src/lib/trampoline/trampoline-credential-helper.ts:153-165`) reads the `wwwauth[...]` field, matches `realm="GitHub"`, and returns `'enterprise'` without any verification.
4. `getCredential` (`trampoline-credential-helper.ts:107-125`) finds no matching account for `evil.example.com` and calls `ui.promptForGitHubSignIn('https://evil.example.com')`.
5. `promptForGitHubSignIn` (`trampoline-ui-helper.ts:80-99`) opens Desktop's native GitHub Enterprise sign-in dialog scoped to `evil.example.com`; if the user completes it, an `Account` bound to the attacker's endpoint is persisted and will be used for future credential lookups against that origin.

  // When Git attempts to authenticate with a host it captures any
  // WWW-Authenticate headers and forwards them to the credential helper. We
  // use them as a happy-path to determine if the host is a GitHub host without
  // having to resort to making a request ourselves.
  for (const [k, v] of cred.entries()) {
    if (k.startsWith('wwwauth[')) {
      if (v.includes('realm="GitHub"')) {
        return 'enterprise'
      } else if (/realm="(GitLab|Gitea|Atlassian Bitbucket)"/.test(v)) {
        return 'generic'
      }
    }
  }

  public promptForGitHubSignIn(endpoint: string): Promise<Account | undefined> {
    return new Promise<Account | undefined>(async resolve => {
      const cb = (result: SignInResult) => {
        resolve(result.kind === 'success' ? result.account : undefined)
        this.dispatcher.closePopup(PopupType.SignIn)
      }

      const { hostname, origin } = new URL(endpoint)
      if (hostname === 'github.com') {
        this.dispatcher.beginDotComSignIn(cb)
      } else {
        this.dispatcher.beginEnterpriseSignIn(cb)
        await this.dispatcher.setSignInEndpoint(origin)
      }

      this.dispatcher.showPopup({
        type: PopupType.SignIn,
        isCredentialHelperSignIn: true,
        credentialHelperUrl: endpoint,
      })
