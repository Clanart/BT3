### Title
Aggregate Schnorr signature verification bypass via weight-transcript not binding the nonces (forgery by choosing `R_0` to cancel the batch equation) - ([File: crypto/schnorr/src/aggregate.rs](https://github.com/blackvul/serai--002/blob/master/crypto/schnorr/src/aggregate.rs))

### Summary
`SchnorrAggregate::verify` batch-checks `Σ z_i·R_i + Σ z_i·c_i·A_i − s·G = 0`, where each weight `z_i` is derived from a transcript that commits only to the ordered challenges — never to the public keys, the nonces `R_i`, or the aggregate scalar `s`. An unprivileged attacker can therefore compute all `z_i` publicly, pick arbitrary `s` and `R_1..R_{n-1}`, and solve for `R_0` so the equation holds for signatures they never produced, forging an aggregate signature over keys they do not control.

### Finding Description
Verification builds weights by appending only `challenge` messages to a `DigestTranscript` and calling `weight()` per index. Neither the per-signature nonce `Rs[i]` nor the key is fed into the transcript:

```rust
// crypto/schnorr/src/aggregate.rs
let mut digest = DigestTranscript::<C::H>::new(dst);
digest.domain_separate(b"signatures");
for (_, challenge) in keys_and_challenges {
  digest.append_message(b"challenge", challenge.to_repr());
}
...
for (i, (key, challenge)) in keys_and_challenges.iter().enumerate() {
  let z = weight(&mut digest);
  pairs.push((z, self.Rs[i]));
  pairs.push((z * challenge, *key));
}
pairs.push((-self.s, C::generator()));
multiexp_vartime(&pairs).is_identity()
``` [1](#0-0) 

Because `z_0` does not depend on `R_0`, an attacker holding public `(A_i, c_i)` pairs can compute `z_i` themselves and set

```
R_0 = (s·G − z_0·c_0·A_0 − Σ_{i≥1} z_i·(R_i + c_i·A_i)) · z_0^{-1}
```

for any `s`, `R_{i≥1}` of their choosing. The multiexp then sums to identity even though no component equation `R_i + c_i·A_i − s_i·G = 0` needs to hold. `s` is attacker-controlled input — it is never checked to equal `Σ z_i s_i` (the real `s_i` values are not available at verify time, so the binding *must* come from hashing the `R_i`/`A_i` into the weights, which is absent). By contrast, `BatchVerifier`/`multiexp` only randomize the pairing; here the weights themselves are the sole anti-forgery mechanism and they leave one full degree of freedom per signature to the attacker.

### Impact Explanation
Any consumer that accepts an attacker-supplied aggregate via `SchnorrAggregate::read`/`verify` will accept a forged aggregate attesting to `n` Schnorr signatures under victim public keys. This is a direct signature-verification bypass — the analog of CVE-2019-0631's "security feature bypass" class: the integrity check that should gate acceptance of untrusted bytes is satisfied by adversarial construction. Severity High: forgery is deterministic, requires no secret material, and works for any `n ≥ 1` (for `n = 1`, `R_0` solves a single equation trivially, forging a lone "aggregated" signature).

### Likelihood Explanation
Reachable by any unprivileged party able to submit `SchnorrAggregate` bytes (e.g., to a verify path) with knowledge of the public keys and challenges — both public inputs. The attack is pure public-key algebra; no threshold collusion, no malicious validator assumptions, and no weak RNG needed. The only precondition is an integrator routing untrusted aggregates into `verify` with a known `dst`.

### Recommendation
Bind the nonces and keys into the weight transcript: before deriving each `z_i`, append `self.Rs[i]` (e.g., `digest.append_message(b"R", self.Rs[i].to_bytes())`) and `key` to the digest, so weights are unpredictable functions of the full statement. Equivalently, follow the half-aggregation scheme's requirement that each `R_i` be committed inside the aggregation transcript. Also consider committing `s` into the digest. Note `SchnorrAggregator::aggregate`/`complete` must be updated in lockstep so honest aggregation remains consistent with the new transcript.

### Proof of Concept
```rust
// Attacker knows public keys A_i and challenges c_i for n statements.
// 1) Reconstruct weights z_i locally:
let mut digest = DigestTranscript::<C::H>::new(dst);
digest.domain_separate(b"signatures");
for (_, c) in keys_and_challenges { digest.append_message(b"challenge", c.to_repr()); }
let zs: Vec<F> = (0..n).map(|_| weight(&mut digest)).collect();

// 2) Choose arbitrary s and R_1..R_{n-1}; solve for R_0:
let mut acc = C::generator() * s;
for i in 1..n { acc -= (Rs[i] * zs[i]) + (A[i] * (zs[i] * c[i])); }
acc -= A[0] * (zs[0] * c[0]);
let R0 = acc * zs[0].invert().unwrap();

// 3) SchnorrAggregate { Rs: [R0, ...], s } passes verify():
//    Σ z_i·R_i + Σ z_i·c_i·A_i − s·G = identity by construction.
```

  pub fn verify(&self, dst: &'static [u8], keys_and_challenges: &[(C::G, C::F)]) -> bool {
    if self.Rs.len() != keys_and_challenges.len() {
      return false;
    }

    let mut digest = DigestTranscript::<C::H>::new(dst);
    digest.domain_separate(b"signatures");
    for (_, challenge) in keys_and_challenges {
      digest.append_message(b"challenge", challenge.to_repr());
    }

    let mut pairs = Vec::with_capacity((2 * keys_and_challenges.len()) + 1);
    for (i, (key, challenge)) in keys_and_challenges.iter().enumerate() {
      let z = weight(&mut digest);
      pairs.push((z, self.Rs[i]));
      pairs.push((z * challenge, *key));
    }
    pairs.push((-self.s, C::generator()));
    multiexp_vartime(&pairs).is_identity().into()
  }
