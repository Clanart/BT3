### Title
Missing replay protection in App Proxy signature verification allows indefinite reuse of captured signed requests - ([File: lib/shopify_app/controller_concerns/app_proxy_verification.rb](lib/shopify_app/controller_concerns/app_proxy_verification.rb))

### Summary
`ShopifyApp::AppProxyVerification#query_string_valid?` only checks that the HMAC-SHA256 `signature` query parameter matches the recomputed signature of the remaining query parameters. It never validates the `timestamp` parameter for staleness or tracks previously-seen signatures/nonces, so any captured valid App Proxy request URL remains permanently valid and can be replayed by an unrelated party at any time in the future.

### Finding Description
The `AppProxyVerification` concern is the mixin Shopify recommends (and the generator installs, see `lib/generators/shopify_app/app_proxy_controller/templates/app_proxy_controller.rb`) for authenticating storefront-to-app requests forwarded through Shopify's App Proxy feature: [1](#0-0) 

`verify_proxy_request` only calls `query_string_valid?`, which strips the `signature` param, recomputes the HMAC over the sorted remaining params (which include `shop`, `path_prefix`, and `timestamp`), and does a constant-time comparison. This is exactly the same class of weakness described in the reference report: the signed payload authenticates only the content of the request, not its uniqueness or freshness — there is no dedicated structure (nonce, used-signature set) and no enforcement that `timestamp` is recent, so the signature by itself does not prevent replay.

App Proxy requests forwarded by Shopify legitimately include storefront/session-derived query parameters such as `logged_in_customer_id` when a customer is logged into the storefront, and can include other request-specific parameters supplied by the storefront (form field values, etc.) that the app trusts because the signature is valid. Since the signature has no expiry or single-use enforcement, any request URL/query string an attacker manages to observe (via browser history, shared/public devices, proxies, analytics/CDN/server logs, Referer leakage, screen recording, etc.) remains a permanently valid, Shopify-authenticated request that can be resubmitted by anyone, at any time, from anywhere.

### Impact Explanation
An attacker who obtains a previously issued, validly-signed App Proxy query string can replay it against the app indefinitely. Because the app's only trust anchor for identifying the storefront customer or request context in App Proxy flows is this signature check, replay allows:
- Cross-user impersonation of the original logged-in customer identified by `logged_in_customer_id` in the replayed query.
- Repetition of any state-changing action encoded in the query parameters that the App Proxy controller performs on valid signature (e.g., form submissions, review creation, order lookups) with no time-window or single-use restriction.

This matches the "accepted forged signed request" / cross-user access impact category, since the app has no mechanism to reject a stale-but-cryptographically-valid signed request.

### Likelihood Explanation
Exploitation only requires an unprivileged attacker to obtain one previously valid signed App Proxy URL (no secret key, no privileged Shopify Partner/API access needed). Query strings containing signatures are commonly leaked through browser history/autocomplete, shared/public computers, third-party analytics or logging middleware, proxy/CDN access logs, or Referer headers on outbound links from the proxied page — all realistic, low-effort leakage vectors for an unauthenticated attacker.

### Recommendation
Add replay protection to `ShopifyApp::AppProxyVerification`:
- Reject requests where `timestamp` is older than a small allowed skew (e.g., a few minutes) similar to how OAuth callback freshness is expected to be checked.
- Optionally track consumed signatures (or a nonce) in a short-lived store (cache/Redis) keyed by signature+timestamp so a given signed request can only be accepted once within its validity window.
- Document this expectation for consumers of the concern, since the generated `app_proxy_controller.rb` relies on this mixin as its sole authentication mechanism.

### Proof of Concept
1. A merchant's storefront makes a legitimate App Proxy request, e.g.:
   `GET /apps/my-app/reviews?shop=some-store.myshopify.com&path_prefix=%2Fapps%2Fmy-app&timestamp=1466106083&logged_in_customer_id=12345&signature=<valid-hmac>`
2. This full URL (with valid signature) is captured by an attacker (e.g. via a browser history dump, a leaked server log, or a Referer header on an outbound link).
3. At any later time, the attacker replays the exact same URL to the app's `AppProxyVerification`-protected controller.
4. `query_string_valid?` in `app_proxy_verification.rb` (lines 17-27) recomputes the same HMAC over the same unchanged parameters and returns `true`, because there is no timestamp expiry check or single-use nonce tracking — the request is processed as if it were the original customer's fresh request, regardless of how much time has passed since the original request or whether the customer session it referenced is still valid. # frozen_string_literal: true

module ShopifyApp
  module AppProxyVerification
    extend ActiveSupport::Concern
    included do
      skip_before_action :verify_authenticity_token, raise: false
      before_action :verify_proxy_request
    end

    def verify_proxy_request
      head(:forbidden) unless query_string_valid?(request.query_string)
    end

    private

    def query_string_valid?(query_string)
      query_hash = Rack::Utils.parse_query(query_string)

      signature = query_hash.delete("signature")
      return false if signature.nil?

      ActiveSupport::SecurityUtils.secure_compare(
        calculated_signature(query_hash),
        signature,
      )
    end

    def calculated_signature(query_hash_without_signature)
      sorted_params = query_hash_without_signature.collect { |k, v| "#{k}=#{Array(v).join(",")}" }.sort.join

      OpenSSL::HMAC.hexdigest(
        OpenSSL::Digest.new("sha256"),
        ShopifyApp.configuration.secret,
        sorted_params,
      )
    end
  end
end
