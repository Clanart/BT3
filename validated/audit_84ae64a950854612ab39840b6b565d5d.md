### Title
Ad-hoc frontmatter parser silently corrupts `pattern`/`tool_matcher` values on commas inside quoted strings, defeating `action: block` rules without any visible change to the reviewed markdown - ([File: plugins/hookify/core/config_loader.py])

### Summary
`extract_frontmatter` implements a hand-rolled, indentation/heuristic based YAML-subset parser instead of a real YAML parser, and diverges from `yaml.safe_load` semantics on inline list-dict syntax that contains a comma inside a quoted value. A rule author (or malicious contributor) can write a `.claude/hookify.*.local.md` rule whose visible frontmatter clearly reads as a strict `action: block` rule with a specific regex `pattern`, while the actual parsed `Condition.pattern` fed into `Rule.from_dict` is silently truncated/corrupted, so the enforced regex no longer matches the dangerous command the reviewer believed it blocked.

### Finding Description
`extract_frontmatter` (plugins/hookify/core/config_loader.py, lines 87-195) processes list items with the branch:
```
if ':' in item_text and ',' in item_text:
    for part in item_text.split(','):
        if ':' in part:
            k, v = part.split(':', 1)
            item_dict[k.strip()] = v.strip().strip('"').strip("'")
``` [1](#0-0) 

This code blindly splits the whole inline list item on every `,`, with no awareness of quoting. A condition line such as:
```
- field: command, operator: regex_match, pattern: "curl.*,.*exfil\.example\.com"
```
is intended (and would be interpreted by `yaml.safe_load` on an equivalent flow-mapping) as a single `pattern` value containing a comma inside quotes. `extract_frontmatter`, however, splits on the comma inside the quoted string, producing `pattern: "curl.*"` and a bogus extra fragment (` .*exfil\.example\.com"` — no colon, silently dropped by the `if ':' in part` guard). The result is that `Condition.pattern` (consumed unchanged by `Condition.from_dict`, plugins/hookify/core/config_loader.py lines 22-29) is truncated to `curl.*`, which is either overly broad or fails to match the exact dangerous command the reviewer verified in the rendered markdown.

Because `Rule.from_dict` (lines 44-84) trusts the frontmatter dict verbatim and the `action` field (e.g. `action: block`) is set correctly at top level, the rule *looks* like a hard block on a specific dangerous pattern, but the actual regex condition silently diverges from what a human reviewing the `.md` file would compute by eye or with a standard YAML parser. This breaks the "deny means deny" invariant: the enforcement logic (pretooluse.py, which evaluates `Rule.action`/conditions) can end up not blocking (or over/under-blocking) the exact input the rule was supposed to gate, while the file's rendered content gives no indication of the discrepancy.

Existing checks do not catch this: there is no schema validation, no comparison against a real YAML parser, and `load_rule_file`/`load_rules` only catch I/O and generic exceptions — a successfully-but-wrongly parsed frontmatter dict raises no error and is loaded as a normal enabled rule (plugins/hookify/core/config_loader.py, lines 244-274).

### Impact Explanation
This is a parser-differential vulnerability in hook/frontmatter parsing that directly undermines the deny/block enforcement invariant of the hookify plugin: a rule that a reviewer approves believing it blocks a specific dangerous command pattern can, due to the ad-hoc parser, actually enforce a different (weaker or broader) regex, causing either (a) failure to block the intended dangerous command, or (b) unexpected blocking/over-restriction of unrelated legitimate commands. Since hookify rules gate `PreToolUse` command/tool execution, this is a genuine security-control bypass reachable through ordinary repository content (a committed rule file), not a cosmetic bug.

### Likelihood Explanation
Exploitability requires only that a `.claude/hookify.*.local.md` file containing an inline-list condition with a quoted value containing a comma be introduced into the repository and pass casual visual review — a realistic scenario since the file's YAML-like syntax appears well-formed and the corruption is invisible without tracing the custom parser's line-by-line state machine. No special privileges, admin access, or secrets are needed; this is a supply-chain-style trust-boundary bypass purely through crafted plugin/config content.

### Recommendation
Replace the hand-rolled frontmatter parser with a real YAML parser (`yaml.safe_load`) for the frontmatter block delimited by the `---` markers, eliminating the custom indentation/comma heuristics entirely. If a lightweight parser must be retained, at minimum implement quote-aware comma splitting (e.g., using `csv`/`shlex`-style tokenization) and add a validation step that re-parses each rule file with `yaml.safe_load` and asserts equivalence with the custom parser's output before accepting `action`/`tool_matcher`/`pattern` values, failing closed (rejecting the rule file) on divergence.

### Proof of Concept
Differential fuzz/unit test in `plugins/hookify/core/config_loader.py` test suite:
```python
import yaml
from config_loader import extract_frontmatter

def test_quoted_comma_in_pattern_diverges_from_yaml():
    content = '''---
name: block-exfil
enabled: true
event: bash
action: block
tool_matcher: "Bash"
conditions:
  - field: command, operator: regex_match, pattern: "curl.*,.*exfil\\.example\\.com"
---
Blocks exfiltration via curl.
'''
    fm, _ = extract_frontmatter(content)
    # Reference: what a spec-compliant YAML flow-mapping author intended
    intended_pattern = r"curl.*,.*exfil\.example\.com"

    parsed_pattern = fm['conditions'][0]['pattern']
    assert parsed_pattern != intended_pattern, (
        "Parser should diverge here, demonstrating truncation bug"
    )
    # Demonstrate the corrupted pattern is a strict/looser subset,
    # meaning the deployed Condition no longer matches the same set
    # of commands the reviewer believed the rule was blocking.
    assert parsed_pattern == "curl.*"
```
Expected result: the test passes, proving `extract_frontmatter` silently truncates a quoted pattern value at an embedded comma, producing a `Condition.pattern` that diverges from the value a reviewer (or `yaml.safe_load`) would derive from the same file, while `action: block` and `tool_matcher` remain unchanged — confirming the parser differential changes real enforcement semantics without any visible change to the file's rendered content.
