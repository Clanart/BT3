Confirmed: `RegisterPointer` in `x/evm/keeper/msg_server.go` never checks that `msg.ErcAddress` (or the config passed for ERC721/ERC1155) actually resolves to a real, deployed contract of the claimed type before instantiating an "unowned" pointer resource for it. This matches the report's bug class: a permissionless message creates a resource keyed by an attacker-chosen ID with no ownership check, permanently squatting that ID for legitimate use later.

### Title
Permissionless `MsgRegisterPointer` lets any account pre-squat CW pointer slots for arbitrary/non-existent ERC contracts, blocking legitimate pointer registration - ([File: x/evm/keeper/msg_server.go])

### Summary
`RegisterPointer` (`x/evm/keeper/msg_server.go:247-324`) instantiates a CosmWasm pointer contract keyed only by `msg.ErcAddress` and `msg.PointerType`, with no check that the address is actually a deployed contract implementing the corresponding ERC interface. `ValidateBasic` for `MsgRegisterPointer` (`x/evm/types/message_register_pointer.go:47-58`) only verifies the string is a well-formed hex address, not that it is a real contract. Any sender can call this message for any hex address, deploying and permanently binding a pointer to `types.ModuleName`'s pointer registry (`SetCW20ERC20Pointer`/`SetCW721ERC721Pointer`/`SetCW1155ERC1155Pointer`).

### Finding Description
`msgServer.RegisterPointer` [1](#0-0)  only guards against a pointer already existing at or above the module's current version:
```go
if exists && existingVersion >= currentVersion {
    return nil, fmt.Errorf("pointer %s already registered at version %d", existingPointer.String(), existingVersion)
}
```
It never validates that `msg.ErcAddress` is an EVM contract, let alone that it implements the correct ERC20/ERC721/ERC1155 interface. It then unconditionally instantiates a CW pointer contract for that address via `server.wasmKeeper.Instantiate` and records the mapping permanently in the on-chain pointer registry [2](#0-1) .

`MsgRegisterPointer.ValidateBasic` [3](#0-2)  only checks `common.IsHexAddress`, so any syntactically valid address — including one nobody has deployed a contract at yet, or one that will later hold an unrelated legitimate ERC20/721/1155 token — can be registered right now by anyone.

This is directly analogous to the UFO `COMMAND_RESULTS` bug: a state-mutating handler creates a persistent, keyed resource (`get_or_create_session` ↔ `Instantiate`+`Set*Pointer`) driven entirely by an attacker-supplied identifier (`constellation_task_id` ↔ `ErcAddress`), with no ownership/existence check tying the resource to the entity it is meant to represent. In UFO this let an attacker squat a session ID the real owner needed; here it lets an attacker squat the pointer slot for an address before (or instead of) the legitimate contract owner registers it.

Once squatted at `currentVersion`, the version-gate `exists && existingVersion >= currentVersion` permanently blocks any future correct re-registration attempt for that same `ErcAddress` unless a chain upgrade bumps `CurrentVersion` for that pointer type or governance intervenes — the token owner (or dApp relying on that pointer) is denied the ability to get a correct pointer contract deployed for their token.

Confirmatory tests such as `TestRegisterPointer` [4](#0-3)  pass an arbitrary `pointee` address that is never checked to be a contract — the mock keeper accepts it as-is, demonstrating the missing validation is exercised in the normal code path, not merely a test artifact.

### Impact Explanation
- Denial of service for token/pointer interoperability: an attacker can front-run or pre-register pointer slots for arbitrary EVM addresses (including precomputed CREATE/CREATE2 addresses of tokens about to be deployed), causing the eventual legitimate `RegisterPointer` call for that same address to fail permanently with "pointer already registered at version %d" once occupied at the max known version.
- This breaks the interoperability guarantee the pointer system exists to provide (per the module's own documentation) between CosmWasm and EVM token representations, denying legitimate holders/dApps a correctly bound pointer for their token — a functional/availability denial matching the "unauthorized/blocked pointer" impact criteria for a Medium-severity issue, not a fund-loss bug.
- Additionally, since the wasm `Instantiate` calls are unconditional and paid for by attacker gas, an attacker can also spam many junk pointer contracts (unbounded distinct `ErcAddress` values), inflating on-chain wasm contract/storage state — an availability/resource-exhaustion vector similar to UFO's "exhaust memory with phantom sessions."

### Likelihood Explanation
High reachability: `MsgRegisterPointer` is a standard, permissionless Cosmos message reachable by any funded account (also exposed via CLI `register-cw-pointer`, see `x/evm/client/cli/native_tx.go:60-87`). No special privilege, precompile access, or contract deployment is required beyond paying the tx fee — an attacker only needs to guess or predict a target `ErcAddress` (trivial for CREATE2-style deterministic deployments, or for well-known token addresses being migrated/bridged).

### Recommendation
Add an existence/type check before instantiating a pointer: verify `msg.ErcAddress` has deployed EVM code (`GetCode`/`GetCodeSize`) and, ideally, that it implements the claimed ERC interface (e.g., via a static call/interface probe), mirroring the CW20/CW721 pointer precompile checks that reject non-contract addresses (`addCW20Pointer rejects a valid sei address that is not a contract`, see `integration_test/precompile_tests/precompiles/pointer.spec.ts:121-126`). Consider also rate-limiting or requiring a bond/fee proportional to potential squatting abuse, and allow re-registration by the actual token owner/deployer even if a version-current pointer already exists but was created for a non-existent contract.

### Proof of Concept
1. Attacker calls `seid tx evm register-cw-pointer ERC20 0xDEADBEEF...` (an address with no deployed code, or a precomputed CREATE2 address for a token the victim intends to deploy next).
2. `RegisterPointer` passes `exists=false`, skips any contract-existence check, and calls `wasmKeeper.Instantiate` to create a CW20 pointer bound to that address, then persists it via `SetCW20ERC20Pointer` at `erc20.CurrentVersion`.
3. Victim later deploys their real ERC20 token at that same address (if CREATE2-predicted) or attempts `RegisterPointer` for their genuinely deployed token at that address.
4. The call now hits `exists && existingVersion >= currentVersion` and returns `"pointer %s already registered at version %d"`, permanently denying the legitimate owner a correct pointer for their token.

func (server msgServer) RegisterPointer(goCtx context.Context, msg *types.MsgRegisterPointer) (*types.MsgRegisterPointerResponse, error) {
	ctx := sdk.UnwrapSDKContext(goCtx)
	if server.GetRegisterPointerDisabled(ctx) {
		return nil, fmt.Errorf("registering CW->ERC pointers has been disabled")
	}
	var existingPointer sdk.AccAddress
	var existingVersion uint16
	var currentVersion uint16
	var exists bool
	switch msg.PointerType {
	case types.PointerType_ERC20:
		currentVersion = erc20.CurrentVersion
		existingPointer, existingVersion, exists = server.GetCW20ERC20Pointer(ctx, common.HexToAddress(msg.ErcAddress))
	case types.PointerType_ERC721:
		currentVersion = erc721.CurrentVersion
		existingPointer, existingVersion, exists = server.GetCW721ERC721Pointer(ctx, common.HexToAddress(msg.ErcAddress))
	case types.PointerType_ERC1155:
		currentVersion = erc1155.CurrentVersion
		existingPointer, existingVersion, exists = server.GetCW1155ERC1155Pointer(ctx, common.HexToAddress(msg.ErcAddress))
	default:
		panic("unknown pointer type")
	}
	if exists && existingVersion >= currentVersion {
		return nil, fmt.Errorf("pointer %s already registered at version %d", existingPointer.String(), existingVersion)
	}

func (msg *MsgRegisterPointer) ValidateBasic() error {
	_, err := sdk.AccAddressFromBech32(msg.Sender)
	if err != nil {
		return sdkerrors.Wrapf(sdkerrors.ErrInvalidAddress, "Invalid sender address (%s)", err)
	}

	if !common.IsHexAddress(msg.ErcAddress) {
		return sdkerrors.ErrInvalidAddress
	}

	return nil
}
