### Title
Corrupted lazy MessageSet extensions are silently replaced with default instances instead of failing the parse - ([File: java/core/src/main/java/com/google/protobuf/LazyFieldLite.java])

### Summary
The BC-Java CVE-2026-59643 bug class is: a security-relevant validation check (OpenPGP inline-signature policy check) fails internally, but the failure is swallowed, so the caller believes the operation succeeded and treats untrusted data as if it had been validated. The Protobuf analog is in `LazyFieldLite.ensureInitialized()` (Java full/lite runtime, MessageSet-lazy-extension path): when the delayed bytes for a nested/extension message fail to parse (`InvalidProtocolBufferException`), the exception is caught, the field is silently replaced with the default instance, and `corrupted` is set, but **nothing propagates this failure to the top-level `parseFrom`/`mergeFrom` call**. The overall parse reports success even though an attacker-controlled sub-message failed validation.

### Finding Description
`LazyFieldLite` stores serialized bytes for an extension field and defers parsing until first access (`getValue()`/`ensureInitialized()`): [1](#0-0) 

If `defaultInstance.getParserForType().parseFrom(delayedBytes, extensionRegistry)` throws `InvalidProtocolBufferException` (malformed/attacker-supplied bytes), the code does:
```
this.corrupted = true;
this.value = defaultInstance;
this.memoizedBytes = ByteString.EMPTY;
```
No exception is rethrown, nothing is logged, and the comment in the source explicitly documents this: "Nothing is logged and no exceptions are thrown. Clients will be unaware that this proto was invalid." [2](#0-1) 

The same silent-swallow pattern recurs in `mergeFrom(CodedInputStream, ExtensionRegistryLite)` and `mergeValueAndBytes` in the same file: [3](#0-2) 

This field is populated during regular deserialization of `MessageSet`-style extensions via `MessageReflection.mergeMessage` when `extensionRegistry.lazyExtensionEnabled()` is true and the field is an extension: [4](#0-3) 

The invariant that should hold (and that the failed check exists to enforce) is: "a message's `ParseFrom`/`MergeFrom` call must fail (throw/return false) if any wire-format-valid outer message contains an inner length-delimited sub-message that itself is not parseable/valid protobuf." Here, that invariant is broken for lazily-deferred MessageSet extension fields: the outer `parseFrom` returns successfully, and the corruption is only exposed later, if and when application code happens to call `getValue()`/`getExtension()` on that particular field — and even then, in the older `LazyFieldLite`/legacy lazy-MessageSet path, the accessor simply returns the default instance rather than raising an error.

Notably, protobuf's own test suite documents and locks in this exact silent-swallow behavior as intended for the legacy path: `testLoadCorruptedLazyField_getsReplacedWithEmptyMessage` explicitly asserts that accessing a corrupted lazy MessageSet extension "gets replaced with the default empty message" with no exception, for the (default/legacy) lazy extension mode: [5](#0-4) 

By contrast, the newer `InternalLazyField` class (added later, per its 2026 copyright header) explicitly documents this as a known problem being fixed, and throws `InvalidProtocolBufferException`/`InvalidProtobufRuntimeException` on corrupted access instead of silently substituting a default value: [6](#0-5)  — this parallels how BC-Java's fix for CVE-2026-59643 made a previously-ignored failure surface as an actual error.

### Impact Explanation
An application parsing a message containing a `MessageSet`-style extension with lazy extension parsing enabled will see `ParseFrom`/`MergeFrom` succeed even if the bytes for a specific extension are corrupted/malformed. If the application logic branches on `hasExtension()` (which does not force parsing) or eventually calls `getExtension()`, it will silently receive the type's *default instance* rather than an error — data that never existed. Depending on how the application uses that extension (e.g., authorization data, feature flags, business-logic values embedded as extensions), this integrity failure can cause security-relevant fields to be silently treated as "empty/default" instead of failing closed. This mirrors the BC-Java issue: a validation failure that should cause the whole operation to be rejected is instead absorbed, and the caller has no signal that anything was wrong.

### Likelihood Explanation
The path is reachable by an ordinary client sending a bounded, attacker-controlled Protobuf payload through the standard `Message.parseFrom`/`Builder.mergeFrom` public API, provided the schema uses (legacy) extensions/MessageSet semantics and the registry has lazy extension parsing enabled (the historical default behavior for `ExtensionRegistry`/MessageSet-style extensions, as reflected in `MessageReflection.mergeMessage`). No privileged access, malicious schema, or forged MiniTable is needed — only a single malformed length-delimited extension payload embedded in an otherwise well-formed outer message.

### Recommendation
Make `LazyFieldLite.ensureInitialized()` (and the analogous `mergeFrom`/`mergeValueAndBytes` swallow sites) propagate the `InvalidProtocolBufferException` to the caller instead of silently substituting the default instance, consistent with the already-corrected behavior in `InternalLazyField.ensureInitialized()`. At minimum, document and audit all call sites relying on lazy MessageSet extension parsing to ensure they cannot silently treat corrupted extension data as "absent/default" without any error signal reaching the top-level parse result.

### Proof of Concept
Conceptual repro path (cannot execute in this environment, but traceable in source):
1. Build a `RawMessageSet` with one `Item` whose `type_id` matches a registered extension, but whose `message` bytes are deliberately invalid protobuf for that extension type (as done in `LazilyParsedMessageSetTest.CORRUPTED_MESSAGE_PAYLOAD`).
2. Call `TestMessageSet.parseFrom(inputData, extensionRegistry)` with lazy extension mode enabled — this call succeeds (no exception), per `MessageReflection.mergeMessage`'s lazy-field path.
3. Call `messageSet.getExtension(TestMessageSetExtension1.messageSetExtension)` — instead of surfacing the corruption, it returns `TestMessageSetExtension1.getDefaultInstance()`, exactly as asserted by `testLoadCorruptedLazyField_getsReplacedWithEmptyMessage`: [7](#0-6) 

This demonstrates the outer parse "succeeding" while an attacker-controlled, invalid sub-message is silently discarded and replaced with a default value — the direct analog of "policy/validation failures silently ignored."

  /** Might lazily parse the bytes that were previously passed in. Is thread-safe. */
  protected void ensureInitialized(MessageLite defaultInstance) {
    if (value != null) {
      return;
    }
    synchronized (this) {
      if (value != null) {
        return;
      }
      try {
        if (delayedBytes != null) {
          // The extensionRegistry shouldn't be null here since we have delayedBytes.
          MessageLite parsedValue =
              defaultInstance.getParserForType().parseFrom(delayedBytes, extensionRegistry);
          this.value = parsedValue;
          this.memoizedBytes = delayedBytes;
        } else {
          this.value = defaultInstance;
          this.memoizedBytes = ByteString.EMPTY;
        }
      } catch (InvalidProtocolBufferException e) {
        // Nothing is logged and no exceptions are thrown. Clients will be unaware that this proto
        // was invalid.
        this.corrupted = true;
        this.value = defaultInstance;
        this.memoizedBytes = ByteString.EMPTY;
      }
    }
  }

  /**
   * Guarantees that `this.value` is non-null or throws.
   *
   * @throws InvalidProtocolBufferException If `bytes` cannot be parsed.
   */
  private void ensureInitialized() throws InvalidProtocolBufferException {
    if (value != null) {
      return;
    }

    synchronized (this) {
      if (corrupted) {
        throw new InvalidProtocolBufferException("Repeat access to corrupted lazy field");
      }
      try {
        // `bytes` is guaranteed to be non-null since `value` was null.
        CodedInputStream input = bytes.newCodedInput();
        input.enableAliasing(/* enabled= */ true);
        // When lazyExtensionEnabled() returns true, it means all extensions including MessageSet's
        // will be fully parsed. When it returns false, it basically implies this can only be a
        // MessageSet extension, and we should fall back to the old behavior of silently returning
        // the default instance on corrupted extensions i.e. a full parse.
        value =
            extensionRegistry.lazyExtensionEnabled()
                ? defaultInstance.getParserForType().parsePartialFrom(input, extensionRegistry)
                : defaultInstance.getParserForType().parseFrom(input, extensionRegistry);
        input.checkLastTagWas(0);
      } catch (InvalidProtocolBufferException e) {
        corrupted = true;
        throw e;
      }
