### Title
`Scanner::scan_transaction` classifies outputs by `script_pubkey` alone, letting any external sender forge "internal" Change/Branch/Forwarded outputs - ([File: networks/bitcoin/src/wallet/mod.rs](networks/bitcoin/src/wallet/mod.rs))

### Summary
`Scanner` maps every registered offset to a P2TR `script_pubkey` and `scan_transaction` reports any on-chain output paying to that script as a `ReceivedOutput` carrying that offset, with no check that the output was actually produced by the protocol. Downstream, the offset fully determines the `OutputType` classification (`External`/`Branch`/`Change`/`Forwarded`). Because the internal offsets are deterministic public values (`hash_to_F(b"Serai Bitcoin Output Offset", "branch"/"change"/"forward")`), any unprivileged party can compute the internal addresses and send Bitcoin that is misclassified as a reserved internal category — the exact analog of inserting a "finalized" category at the bulk-insert boundary to bypass the gated transition.

### Finding Description
`Scanner::register_offset` inserts `script -> offset` into `self.scripts` for every registered offset, including the internally-reserved change/branch/forward offsets. [1](#0-0)  `scan_transaction` then emits a `ReceivedOutput` for *any* transaction output whose `script_pubkey` matches — matching on the script alone, with no provenance check. [2](#0-1) 

The kind byte is derived purely from the offset: the processor builds `kinds: HashMap<offset_repr, OutputType>` where `External` is only `Scalar::ZERO`, and `Branch`/`Change`/`Forwarded` map to `Secp256k1::hash_to_F(KEY_DST, ...)` constants. [3](#0-2)  `get_outputs` then does `let kind = kinds[offset_repr_ref]` and only applies deposit handling (`presumed_origin`, `data` extraction via `extract_serai_data`) when `kind == OutputType::External`. [4](#0-3) 

Nothing gates the reserved categories to outputs the protocol itself created — exactly like `agentBulkInsertLegacyUsers` storing `category: 45/47` without checking it is a legitimate "source" category. The offsets are public constants derived from a fixed DST, so the internal P2TR scripts are computable by anyone who knows the group key.

### Impact Explanation
An unprivileged attacker sends a normal Bitcoin transaction paying to the internal change, branch, or forwarder address. The scanner reports it as a `ReceivedOutput` with the reserved offset; the processor classifies it `Change`/`Branch`/`Forwarded` instead of `External`, permanently skipping the external-deposit path (no `presumed_origin`, no `data` extraction — `output.data` is only populated for `External`). [5](#0-4)  The attacker's payment is then consumed by internal flows that assume only the protocol can produce such outputs: a forged `Branch` output is treated as a key-rotation input, and forged `Change`/`Forwarded` outputs enter the spendable UTXO set without the data/Origin checks external deposits undergo — corrupting the processor's output accounting and allowing attacker-controlled outputs to ride internal-only code paths. This mirrors the original finding where a finalized category bypassed the V3 `_electVestingUpdate` burn gate.

### Likelihood Explanation
Reachable by any party able to send a Bitcoin transaction — no validator status, key material, or collusion required. The group key is public; the offset derivation (`hash_to_F(KEY_DST, b"change")` etc.) and `p2tr_script_buf` construction are deterministic and public. The only cost is the BTC sent (which can be dust-sized, though the value lands in the multisig's control).

### Recommendation
Do not classify outputs by `script_pubkey`/offset alone. Either:
- Require that `Branch`/`Change`/`Forwarded` outputs appear in transactions whose inputs are already controlled by the known key set (protocol-authored transactions), or carry an on-chain marker binding them to an internal action, before assigning the reserved `OutputType`; or
- Explicitly whitelist only `Scalar::ZERO`/expected offsets at the `scan_transaction` boundary for externally-sourced transactions, rejecting or reclassifying outputs matching reserved scripts that lack protocol provenance — the analog of rejecting categories 45/47 at `agentBulkInsertLegacyUsers`.

### Proof of Concept
Conceptual reproduction:

```rust
// The protocol's internal offsets are public constants
let change_offset = Secp256k1::hash_to_F(b"Serai Bitcoin Output Offset", b"change");
// Attacker computes the internal change address for the public group key
let change_addr = p2tr_script_buf(key + (ProjectivePoint::GENERATOR * change_offset)).unwrap();

// Attacker broadcasts a transaction paying change_addr (no protocol involvement)
let attacker_tx = Transaction {
  // ... pays to `change_addr`
};

// Scanner misclassifies the external payment as an internal Change output
let outputs = scanner(key).0.scan_transaction(&attacker_tx);
assert_eq!(outputs.len(), 1);
assert_eq!(outputs[0].offset(), change_offset); // claimed as internal, not Scalar::ZERO

// processor::get_outputs maps it to OutputType::Change and skips
// presumed_origin/data population reserved for External outputs,
// so the forged deposit enters internal-only handling uninspected.
```

The `scanner()` helper already acknowledges the fragility of offset-derived classification ("Always construct the full scanner in order to ensure there's no collisions"), but collision-checking does not stop an external sender from paying to a reserved script — only provenance validation does.   pub fn register_offset(&mut self, mut offset: Scalar) -> Option<Scalar> {
    // This loop will terminate as soon as an even point is found, with any point having a ~50%
    // chance of being even
    // That means this should terminate within a very small amount of iterations
    loop {
      match p2tr_script_buf(self.key + (ProjectivePoint::GENERATOR * offset)) {
        Some(script) => {
          if self.scripts.contains_key(&script) {
            None?;
          }
          self.scripts.insert(script, offset);
          return Some(offset);
        }
        None => offset += Scalar::ONE,
      }
    }
  }

  pub fn scan_transaction(&self, tx: &Transaction) -> Vec<ReceivedOutput> {
    let mut res = Vec::new();
    for (vout, output) in tx.output.iter().enumerate() {
      // If the vout index exceeds 2**32, stop scanning outputs
      let Ok(vout) = u32::try_from(vout) else { break };

      if let Some(offset) = self.scripts.get(&output.script_pubkey) {
        res.push(ReceivedOutput {
          offset: *offset,
          output: output.clone(),
          outpoint: OutPoint::new(tx.compute_txid(), vout),
        });
      }
    }
    res
  }

// Always construct the full scanner in order to ensure there's no collisions
fn scanner(
  key: ProjectivePoint,
) -> (Scanner, HashMap<OutputType, Scalar>, HashMap<Vec<u8>, OutputType>) {
  let mut scanner = Scanner::new(key).unwrap();
  let mut offsets = HashMap::from([(OutputType::External, Scalar::ZERO)]);

  let zero = Scalar::ZERO.to_repr();
  let zero_ref: &[u8] = zero.as_ref();
  let mut kinds = HashMap::from([(zero_ref.to_vec(), OutputType::External)]);

  let mut register = |kind, offset| {
    let offset = scanner.register_offset(offset).expect("offset collision");
    offsets.insert(kind, offset);

    let offset = offset.to_repr();
    let offset_ref: &[u8] = offset.as_ref();
    kinds.insert(offset_ref.to_vec(), kind);
  };

  register(
    OutputType::Branch,
    *BRANCH_OFFSET.get_or_init(|| Secp256k1::hash_to_F(KEY_DST, b"branch")),
  );
  register(
    OutputType::Change,
    *CHANGE_OFFSET.get_or_init(|| Secp256k1::hash_to_F(KEY_DST, b"change")),
  );
  register(
    OutputType::Forwarded,
    *FORWARD_OFFSET.get_or_init(|| Secp256k1::hash_to_F(KEY_DST, b"forward")),
  );

  (scanner, offsets, kinds)
}
