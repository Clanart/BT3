## Analog Found: `getResolutionDiff` hardcodes git stage `:2`/`:3` as "ours"/"theirs" without correcting for rebase's swapped meaning

### Title
Conflict-resolution diff preview mislabels "Current"/"Incoming" content during rebase due to hardcoded stage-index assumption - (File: `app/src/lib/git/diff.ts`)

### Summary
Just as `CurveTricryptoOracle` hardcoded `tokens[2]` as "always WETH" regardless of actual pool composition, `getResolutionDiff` in `app/src/lib/git/diff.ts` hardcodes stage `:2` as "ours" and `:3` as "theirs" unconditionally, even though the function's own docstring states this mapping is inverted during a rebase.

### Finding Description
`getResolutionDiff` translates a caller-supplied `stage: 'ours' | 'theirs'` directly into git index stage numbers: [1](#0-0) 

Its own documentation explicitly warns that this mapping is not universally valid: [2](#0-1) 

"`ours` = stage 2 (HEAD at merge time), `theirs` = stage 3 ... Note that during a rebase, git swaps these — the upstream branch is 'ours' and the rebased commit is 'theirs'. **The caller is responsible for mapping user-facing labels to the correct git side.**"

This is structurally identical to the Curve bug: a fixed positional assumption (`tokens[2] == WETH`, `:2 == ours`) that silently breaks when the underlying structure/context differs (a non-standard tricrypto pool ordering vs. a rebase operation), and nothing in the code enforces the correction — it is pushed onto the caller as an unchecked assumption.

Reviewing the consumers of this stage-mode API — `copilot-resolution-helpers.ts` (which derives the "Current"/"Incoming" labels and icons shown in the resolution UI) and the `ManualConflictResolution` model used to actually apply the resolution — none of them carry or check any "is this a rebase" flag: [3](#0-2) [4](#0-3) 

Note that `ManualConflictResolution` values are passed straight through to `git checkout --ours`/`--theirs` in `checkoutConflictedFile`, which is git's own flag-based mechanism and *is* correctly rebase-aware internally: [5](#0-4) 

But the newer Copilot-assisted resolution flow bypasses that git-native correction by reading raw index stages (`:2`/`:3`) directly for the *diff preview* shown to the user, per the hardcoded mapping in `getResolutionDiff`. If the preview labeled "Current" is actually built from `:2` while during a rebase `:2` is really the upstream/target branch's content (not the user's own commit being replayed), the diff the user reviews under the label "Current" would show the *incoming* content and vice versa.

### Impact Explanation
If a user is resolving conflicts during a rebase using the Copilot conflict-resolution dialog, the diff preview under "Current"/"Incoming" can show the swapped side's content. A user who reviews the (mislabeled) diff and picks what they believe is "keep my current work" could actually be selecting to discard their own changes and keep the upstream content, or vice versa. Because `stageManualConflictResolution` (`app/src/lib/git/stage.ts`) stages exactly whichever side git resolves via `--ours`/`--theirs`, this results in **silent corruption of what the user commits** during the rebase — the committed/pushed content differs from what the user believed they were choosing, with no error or warning surfaced.

### Likelihood Explanation
This requires no attacker action beyond an ordinary rebase-with-conflicts scenario, which is a common workflow. The bug is purely internal logic (hardcoded stage mapping) rather than externally injected data, so it is not a maliciously-triggered vulnerability in the classic sense, but it matches the same bug class as the report: a hardcoded positional/index assumption that silently diverges from the real underlying structure (pool token order → rebase stage semantics), producing incorrect values used downstream without any guard.

### Recommendation
`getResolutionDiff` (and its callers) should accept an explicit `isRebase` (or equivalent operation-kind) parameter and invert the `:2`/`:3` mapping accordingly, matching the same correction git itself performs internally for `checkout --ours/--theirs`. Alternatively, avoid raw stage numbers entirely and resolve content via `git show :ours:<path>` semantics equivalent, or explicitly test and label the diff preview using the same branch-name mapping (`ourBranch`/`theirBranch`) already computed in `getOursTheirsLabels`, ensuring labels and diff content stay consistent regardless of operation type.

### Proof of Concept
Not independently reproduced end-to-end in this session (would require exercising the Copilot conflict-resolution dialog mid-rebase and confirming the UI wiring never sets a rebase-aware flag before calling `getResolutionDiff`). What is confirmed from the code is:
1. `getResolutionDiff`'s stage mapping is a fixed `'ours' → ':2'`, `'theirs' → ':3'` with no parameter to invert it.
2. Its own doc comment states this mapping is wrong during rebase and delegates responsibility to the caller.
3. The reviewed caller-side helper (`copilot-resolution-helpers.ts`) and the `ManualConflictResolution` model carry no operation-kind context to perform that correction.

I was not able to fully trace every call site (e.g., `app/src/lib/copilot-conflict-context.ts`, `app/src/lib/stores/app-store.ts`) within the available iterations to confirm whether a rebase-aware correction exists elsewhere in the wiring; this should be verified in a full session before treating the impact as fully confirmed.

export type CopilotFileResolutionChoice = 'copilot' | 'ours' | 'theirs'

/** Label and icon for each resolution choice. */
export const resolutionChoices = {
  copilot: { label: 'Copilot', icon: octicons.copilot },
  ours: { label: 'Current', icon: octicons.chevronLeft },
  theirs: { label: 'Incoming', icon: octicons.chevronRight },
} as const

/**
 * Derive the resolution choice for a file from the manual resolutions map.
 * Defaults to 'copilot' when no manual override is set.
 */
export function getResolutionChoiceForFile(
  path: string,
  manualResolutions: Map<string, ManualConflictResolution>
): CopilotFileResolutionChoice {
  const manual = manualResolutions.get(path)
  if (manual === ManualConflictResolution.ours) {
    return 'ours'
  }
  if (manual === ManualConflictResolution.theirs) {
    return 'theirs'
  }
  return 'copilot'
}
