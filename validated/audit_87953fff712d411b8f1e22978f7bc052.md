### Title
Unhandled exception / crafted-buffer crash in `is_clvm_canonical()` CLVM canonicality scanner reachable from any submitted spend bundle - (File: `chia/full_node/mempool_manager.py`)

### Summary
`is_clvm_canonical()` and its helper `is_atom_canonical()` scan an attacker-supplied `puzzle_reveal`/`solution` buffer byte-by-byte with no bounds checking against the buffer length before indexing, analogous to the ncurses `next_char`/`comp_scan.c` unbounded-scan bug class (CVE-2017-13728), where malformed/truncated input drives the scanner past valid input without a termination/bounds guard.

### Finding Description
`is_clvm_canonical()` is invoked directly on attacker-controlled bytes for every coin spend in a submitted `SpendBundle`: [1](#0-0) 

The scan loop increments `offset` based on length-prefix bytes read from the buffer itself, with no check that `offset` (or the read positions inside `is_atom_canonical`) stay within `len(clvm_buffer)`: [2](#0-1) [3](#0-2) 

A crafted buffer (e.g., a truncated/malformed atom length-prefix, or a long run of `0xFF` "pair" markers followed by a truncated tail) causes `clvm_buffer[offset]` or the prefix-byte reads inside `is_atom_canonical` to index past the end of the buffer, raising an uncaught `IndexError`. This call happens inside `MempoolManager.validate_spend_bundle()`, invoked via `add_spend_bundle()` from `FullNode.add_transaction()` while the node holds `self.blockchain.priority_mutex`: [4](#0-3) 

Unlike `pre_validate_spendbundle()` a few lines above (which is wrapped in `try/except ValueError`/`ValidationError`), this call site has no exception handling around `add_spend_bundle()`.

### Impact Explanation
An unhandled exception raised while the blockchain's `priority_mutex` is held risks leaving the mutex/async task in an inconsistent state and propagates as an unhandled task exception in the full node's WebSocket/RPC transaction-processing path. Any unprivileged party who can submit a spend bundle (via RPC `push_tx` or the transaction-protocol handler) can trigger this by simply crafting a `puzzle_reveal` or `solution` with a malformed CLVM atom length prefix or unbalanced `0xFF` pair markers. This matches the "spend-triggered transaction-processing halt" impact category: repeated submissions can degrade or crash transaction admission for the node.

### Likelihood Explanation
High likelihood of reachability: `is_clvm_canonical()` is called unconditionally on every coin spend's `puzzle_reveal` and `solution` bytes during ordinary mempool admission, with no upstream sanitization that guarantees a self-consistent CLVM buffer. Constructing an atom whose declared length prefix exceeds the remaining buffer bytes is trivial and requires no signature, no wallet participation, and no privileged access — just a spend bundle submitted to a full node.

### Recommendation
Add explicit bounds checks in `is_atom_canonical()` and `is_clvm_canonical()` before every buffer index/slice (verify `offset`, `offset + prefix_len`, and computed `atom_len` stay within `len(clvm_buffer)`), returning `False` (or raising a well-defined, caught exception) instead of allowing `IndexError` to propagate. Additionally, wrap the `add_spend_bundle()` call in `FullNode.add_transaction()` in the same defensive `try/except Exception` pattern already used around `pre_validate_spendbundle()`, so any unexpected parsing exception fails the transaction gracefully instead of propagating as an unhandled exception while holding `priority_mutex`.

### Proof of Concept
1. Construct a `puzzle_reveal` (or `solution`) buffer starting with a size-prefix byte indicating a multi-byte atom-length prefix (e.g., `0xF8`) but truncate the buffer before all declared prefix bytes are present — e.g. `bytes([0xF8])` (declares 4 additional length bytes but supplies none).
2. Submit a `SpendBundle` containing a `CoinSpend` with this `puzzle_reveal`/`solution` via the full node's transaction RPC/protocol path (`push_tx` or peer `SendTransaction`).
3. When `FullNode.add_transaction()` calls `mempool_manager.add_spend_bundle()` → `validate_spend_bundle()` → `is_clvm_canonical(bytes(coin_spend.puzzle_reveal))`, the helper `is_atom_canonical()` reads `clvm_buffer[offset]` for `prefix_len` iterations beyond the 1-byte buffer, raising `IndexError: index out of range`, uncaught in this call path (contrast with the `try/except` wrapping only `pre_validate_spendbundle()` a few lines earlier at `chia/full_node/full_node.py:3064-3078`). def is_atom_canonical(clvm_buffer: bytes, offset: int) -> tuple[int, bool]:
```python
    b = clvm_buffer[offset]
    if (b & 0b11000000) == 0b10000000:
        # 6 bits length prefix
        mask = 0b00111111
        prefix_len = 0
        min_value = 1
    elif (b & 0b11100000) == 0b11000000:
        # 5 + 8 bits length prefix
        mask = 0b00011111
        prefix_len = 1
        min_value = 1 << 6
    elif (b & 0b11110000) == 0b11100000:
        # 4 + 8 + 8 bits length prefix
        mask = 0b00001111
        prefix_len = 2
        min_value = 1 << (5 + 8)
    elif (b & 0b11111000) == 0b11110000:
        # 3 + 8 + 8 + 8 bits length prefix
        mask = 0b00000111
        prefix_len = 3
        min_value = 1 << (4 + 8 + 8)
    elif (b & 0b11111100) == 0b11111000:
        # 2 + 8 + 8 + 8 + 8 bits length prefix
        mask = 0b00000011
        prefix_len = 4
        min_value = 1 << (3 + 8 + 8 + 8)
    elif (b & 0b11111110) == 0b11111100:
        # 1 + 8 + 8 + 8 + 8 + 8 bits length prefix
        mask = 0b00000001
        prefix_len = 5
        min_value = 1 << (2 + 8 + 8 + 8 + 8)

    atom_len = b & mask
    for i in range(prefix_len):
        atom_len <<= 8
        offset += 1
        atom_len |= clvm_buffer[offset]

    return 1 + prefix_len + atom_len, atom_len >= min_value
```
