### Title
Integer division by zero in KIP-71 (Magma) base fee calculation when `kip71.gastarget` governance parameter is set to 0 - (File: `params/kip71_config.go`)

### Summary
`KIP71Config.NextMagmaBlockBaseFee` divides by the governance-controlled `GasTarget` parameter without checking it for zero, unlike the sibling `BaseFeeDenominator` parameter which is explicitly special-cased. If `GasTarget` is set to `0` via governance vote, every node computing the next block's base fee (which happens for every Magma-enabled block, on every full node, during header verification) will panic on integer division by zero, analogous to the `AllToAll`/`split_count` bug pattern in the reported TensorFlow advisory.

### Finding Description
`NextMagmaBlockBaseFee` reads `gasTarget := kc.GasTarget` directly from the governance parameter set and uses it as a divisor in two branches: [4](#0-3) [5](#0-4) 

Notice that `BaseFeeDenominator` is defended against zero:
```go
var baseFeeDenominator *big.Int
if kc.BaseFeeDenominator == 0 {
    // To avoid panic, set the fluctuation range small
    baseFeeDenominator = new(big.Int).SetUint64(64)
} else {
    baseFeeDenominator = new(big.Int).SetUint64(kc.BaseFeeDenominator)
}
``` [6](#0-5) 

But `gasTarget := kc.GasTarget` has no equivalent guard, and it is used as `x.Div(x, new(big.Int).SetUint64(gasTarget))` in both the "usage above target" and "usage below target" branches.

The governance parameter `kip71.gastarget` is validated on the header-governance vote path via `Params[Kip71GasTarget].FormatChecker`, which is set to `noopFormatChecker` (always returns `true`), in contrast to `Kip71BaseFeeDenominator`'s `FormatChecker` which explicitly rejects `0`: [7](#0-6) 

This means a governance vote (`kip71.gastarget = 0`), once it is the majority/governing vote and takes effect at an epoch boundary, is accepted as a valid parameter value with no rejection anywhere in the validation pipeline (`TestVerifyVote` in the test suite only checks bounds for `LowerBoundBaseFee`/`UpperBoundBaseFee`, not `GasTarget`). [8](#0-7) 

Once `GasTarget == 0` is in effect for a Magma-enabled block, any subsequent block's base fee calculation (as long as `parentGasUsed != 0`, which is essentially guaranteed for any block with transactions) executes `parentGasUsed - gasTarget` (nonzero) and then `x.Div(x, big.NewInt(0))`, which panics in Go's `big.Int.Div`.

### Impact Explanation
`NextMagmaBlockBaseFee` is called on the consensus-critical path during header verification (`VerifyMagmaHeader`) by every full node/validator processing every Magma-fork block, as well as by RPC/gas-price-oracle code paths (`node/cn/gasprice/feehistory.go`). A panic here on all nodes simultaneously is a chain-halting denial of service — every node attempting to validate or build a new block after the malicious parameter takes effect crashes, which is a severe availability impact affecting the "block assembly" and "state transition and gas/burn accounting" categories in scope. Because governance parameter votes are recorded on-chain in block headers, an attacker only needs the vote to become the governing/effective governance value (via the existing governance vote mechanism), which subsequently causes divergence/crash deterministically for all nodes computing the base fee — not a mere resource-only bug, but complete chain halt.

### Likelihood Explanation
The likelihood depends on the governance mode of the network. Under `GovernanceMode: "single"` (default per this repo's config), a single governing node can directly set `kip71.gastarget = 0` and have it take effect, making this trivially triggerable. Under multi-signer/ballot governance, it requires a validator/governance quorum to accept the parameter, but the validation code performs no bounds/nonzero check to reject such a proposal at any layer (`NewVoteData`, `VerifyVote`, or `ChainConfigValue`/`FormatChecker`), so nothing in-protocol prevents it.

### Recommendation
Add a zero-check for `GasTarget` in `NextMagmaBlockBaseFee` (mirroring the existing `BaseFeeDenominator == 0` fallback), and/or change `Kip71GasTarget`'s `FormatChecker` in `kaiax/gov/param.go` to reject `v == 0`, consistent with `Kip71BaseFeeDenominator`.

### Proof of Concept
1. Under `GovernanceMode: single`, submit a governance vote/gov data setting `kip71.gastarget = 0` (accepted because `Kip71GasTarget.FormatChecker` is `noopFormatChecker`, see `kaiax/gov/param.go` lines 324-334).
2. Once this becomes the effective `ParamSet` at the next epoch/Magma block, any block whose `parentGasUsed != 0` (i.e., any block that consumed gas) is submitted.
3. `NextMagmaBlockBaseFee` executes `gasUsedDelta := new(big.Int).SetUint64(parentGasUsed - gasTarget)` (nonzero), followed by `y := x.Div(x, new(big.Int).SetUint64(gasTarget))` with `gasTarget = 0`, which panics with "division by zero" in `math/big`.
4. Every node processing/verifying this header via `VerifyMagmaHeader` (and gas price oracle code) panics, halting the chain.

	} else {
		baseFeeDenominator = new(big.Int).SetUint64(kc.BaseFeeDenominator)
	}
	gasTarget := kc.GasTarget
	upperGasLimit := kc.MaxBlockGasUsedForBaseFee

	// check the case of upper/lowerBoundBaseFee is updated by governance mechanism
	parentBaseFee := parentHeaderBaseFee
	if parentBaseFee.Cmp(upperBoundBaseFee) >= 0 {
		parentBaseFee = upperBoundBaseFee
	} else if parentBaseFee.Cmp(lowerBoundBaseFee) <= 0 {
		parentBaseFee = lowerBoundBaseFee
	}

	// upper gas limit cut off the impulse of used gas to upper bound
	parentGasUsed := min(parentHeaderGasUsed, upperGasLimit)
	if parentGasUsed == gasTarget {
		return makeEvenByFloor(parentBaseFee)
	} else if parentGasUsed > gasTarget {
		// shortcut. If parentBaseFee is already reached upperbound, do not calculate.
		if parentBaseFee.Cmp(upperBoundBaseFee) == 0 {
			return makeEvenByFloor(upperBoundBaseFee)
		}
		// If the parent block used more gas than its target,
		// the baseFee of the next block should increase.
		// baseFeeDelta = max(1, parentBaseFee * (parentGasUsed - gasTarget) / gasTarget / baseFeeDenominator)
		gasUsedDelta := new(big.Int).SetUint64(parentGasUsed - gasTarget)
		x := new(big.Int).Mul(parentBaseFee, gasUsedDelta)
		y := x.Div(x, new(big.Int).SetUint64(gasTarget))
		baseFeeDelta := math.BigMax(x.Div(y, baseFeeDenominator), common.Big1)

		nextBaseFee := x.Add(parentBaseFee, baseFeeDelta)
		if nextBaseFee.Cmp(upperBoundBaseFee) > 0 {
			return makeEvenByFloor(upperBoundBaseFee)
		}
		return makeEvenByFloor(nextBaseFee)
	} else {
		// shortcut. If parentBaseFee is already reached lower bound, do not calculate.
		if parentBaseFee.Cmp(lowerBoundBaseFee) == 0 {
			return makeEvenByFloor(lowerBoundBaseFee)
		}
		// Otherwise if the parent block used less gas than its target,
		// the baseFee of the next block should decrease.
		// baseFeeDelta = parentBaseFee * (gasTarget - parentGasUsed) / gasTarget / baseFeeDenominator
		gasUsedDelta := new(big.Int).SetUint64(gasTarget - parentGasUsed)
		x := new(big.Int).Mul(parentBaseFee, gasUsedDelta)
		y := x.Div(x, new(big.Int).SetUint64(gasTarget))
		baseFeeDelta := x.Div(y, baseFeeDenominator)

		nextBaseFee := x.Sub(parentBaseFee, baseFeeDelta)
		if nextBaseFee.Cmp(lowerBoundBaseFee) < 0 {
			return makeEvenByFloor(lowerBoundBaseFee)
		}
		return makeEvenByFloor(nextBaseFee)
