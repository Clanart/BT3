### Title
Removing a state machine from `HostParams.stateMachines` does not revoke trust — `latestStateMachineHeight` stays nonzero, so its state commitments keep being accepted - (File: evm/src/core/EvmHost.sol, evm/src/core/HandlerV2.sol)

### Summary
This is the local analog of the Hats "toggle address" bug: governance treats the `stateMachines` whitelist inside `HostParams` as the "toggle" that turns trust in a counter-chain on or off, but the actual runtime gate used to admit new remote state (`_latestStateMachineHeight[id] != 0`) is a separate piece of storage that is only ever set forward and is never cleared when a state machine is removed from the whitelist. Exactly like the Hats hat defaulting back to its stale local `status` after the toggle contract is swapped, a "removed" state machine here keeps its stale nonzero height and continues to be treated as trusted by the code path that actually decides whether new consensus/state updates are accepted.

### Finding Description
`updateHostParamsInternal` in [1](#0-0)  only ever *adds* entries to `_latestStateMachineHeight`:

```solidity
for (uint256 i = 0; i < stateMachinesLen; ++i) {
    if (_latestStateMachineHeight[params.stateMachines[i]] == 0) {
        _latestStateMachineHeight[params.stateMachines[i]] = 1;
    }
}
```

There is no corresponding loop that deletes/zeroes `_latestStateMachineHeight[id]` for a state machine that existed in the *previous* `_hostParams.stateMachines` but is absent from the *new* `params.stateMachines`. The array itself (`_hostParams.stateMachines`) is simply overwritten: [2](#0-1) .

Crucially, the array is never consulted again at runtime. The actual gate that decides whether a newly-verified intermediate state for a given `stateMachineId` gets persisted is in `HandlerV2.handleConsensus`:

```solidity
uint256 latestHeight = host.latestStateMachineHeight(intermediate.stateMachineId);
if (latestHeight != 0 && intermediate.height > latestHeight) {
    host.storeStateMachineCommitment(stateMachineHeight, intermediate.commitment);
}
``` [3](#0-2) 

This check only inspects the per-id height mapping — it never checks whether `intermediate.stateMachineId` is a member of the *current* `HostParams.stateMachines` array. `handleConsensus` itself is a public, unauthenticated entrypoint (gated only by `notFrozen(host)`), so any relayer can invoke it with a real consensus proof at any time.

The result: once a state machine's height mapping has been initialized (nonzero), removing that state machine ID from `HostParams.stateMachines` via `updateHostParams` (the hostManager/governance "toggle") has no effect on whether its future state commitments continue to be accepted. The whitelist array is cosmetic; the real source of truth (`_latestStateMachineHeight`) never resyncs with it, exactly the "toggle changed, but the checked value defaults to stale local storage" pattern in the Hats report.

### Impact Explanation
This breaks the "state commitments must never let false/untrusted remote state become trusted" invariant. Governance may remove a state machine from the whitelist specifically because it should no longer be trusted (e.g., a chain whose consensus was compromised, deprecated, or is being sunset). Because `_latestStateMachineHeight` is never cleared, the handler will keep accepting and storing new `StateCommitment`s for that "revoked" chain, which then feed directly into `stateMachineCommitment()`-based verification of incoming POST requests, GET responses, and timeouts across `HandlerV2` (`handlePostRequests`, `handleGetResponses`, timeout handlers). This allows continued processing of cross-chain messages from a state machine that operators explicitly intended to cut off — a false-state-acceptance / unauthorized-execution condition that can lead to funds movement or execution based on state the protocol no longer considers trustworthy.

### Likelihood Explanation
No malicious peer, relayer, or governance compromise is required. It only takes: (1) a normal, legitimate governance action removing a state machine ID from `params.stateMachines` (expected admin behavior, not an attack), and (2) any ordinary, unprivileged relayer subsequently calling the fully public `handleConsensus`/`handlePostRequests` with a genuine proof for that now-"removed" chain. Both are routine, expected operations, making the stale-trust window trivially reachable whenever a state machine is ever removed after being active.

### Recommendation
When computing the new `HostParams` in `updateHostParamsInternal`, diff the previous `_hostParams.stateMachines` against the incoming `params.stateMachines` and explicitly `delete _latestStateMachineHeight[id]` (and ideally purge/mark stored commitments as untrusted) for any state machine ID that is being removed, mirroring the recommended Hats fix of syncing state before switching the source of truth. Alternatively, gate `handleConsensus`'s admission of new commitments on active membership in `_hostParams.stateMachines`, not merely `latestStateMachineHeight != 0`.

### Proof of Concept
1. Governance calls `updateHostParams` with `stateMachines = [X]`. `_latestStateMachineHeight[X]` becomes `1` (per `evm/src/core/EvmHost.sol:641-643`).
2. Over time, legitimate consensus proofs advance `_latestStateMachineHeight[X]` to some height `H`.
3. Governance decides chain `X` should no longer be trusted and calls `updateHostParams` with `stateMachines = []` (or any list excluding `X`). `_hostParams.stateMachines` no longer contains `X`, but `_latestStateMachineHeight[X]` remains `H` (untouched by `evm/src/core/EvmHost.sol:581-645`).
4. Any relayer calls `HandlerV2.handleConsensus(host, proof)` with a valid consensus proof containing a new `IntermediateState` for `X` at height `H+1`.
5. In `evm/src/core/HandlerV2.sol:158-163`, `host.latestStateMachineHeight(X)` returns `H` (nonzero), `H+1 > H` is true, so `host.storeStateMachineCommitment` is called — the new commitment for the "removed" chain `X` is stored and becomes usable to validate incoming requests/responses/timeouts, despite governance's explicit removal of `X` from the trusted `stateMachines` list.

        // check the params to prevent the host from getting bricked.
        if (

            revert InvalidHostManager();

            // otherwise cannot process new datagrams
            revert InvalidHandler();
        }

            revert InvalidConsensusClient();

        // otherwise cannot process new cross-chain governance requests
