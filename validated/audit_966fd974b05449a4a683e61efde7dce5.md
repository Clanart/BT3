### Title
BNB sent directly to WombatStaking via `receive()` is permanently locked - (wombat/WombatStaking.sol)

### Summary
`WombatStaking` implements a bare `receive() external payable {}` function that lets any wallet send native BNB directly into the contract, but there is no function anywhere in the contract that allows this BNB to be withdrawn or swept out again. This is the same bug class as the referenced BathBuddy finding: a contract that accepts ETH/BNB but has no corresponding release mechanism, resulting in permanently locked funds.

### Finding Description
`WombatStaking.sol` defines an open, unrestricted `receive()` function: [1](#0-0) 

Any externally owned account can call `address(wombatStaking).call{value: x}("")` and the BNB will be accepted unconditionally.

The only place in the contract that ever moves native BNB out again is inside `vote()`, where BNB bribe rewards returned by `voter.vote()` are immediately forwarded to the WBNB contract to be wrapped: [2](#0-1) 

That flow is self-contained: it only forwards the exact `rewardAmount` value that `voter.vote()` reported as a bribe, and `vote()` can only be triggered by the `bribeManager`. It performs no check of, and has no path to move, the contract's actual native BNB balance (`address(this).balance`). There is no `emergencyWithdraw`, `rescueETH`, `withdrawNative`, or similar sweep function in `WombatStaking.sol` — unlike the reward-side `MultiRewarderPerSec` mock, which explicitly implements an `emergencyWithdraw()` that forwards `address(this).balance` back to the owner: [3](#0-2) 

`WombatStaking.sol` has no analogous function, and none of `deposit`, `depositLP`, `withdraw`, `harvest`, `convertWOM`, or `convertAllWom` touch native BNB balances. As a result, any BNB an ordinary wallet sends to the contract's `receive()` — whether by mistake, by interacting with a UI that miscalculates `msg.value`, or simply by directly calling the payable fallback — becomes permanently stuck with no code path capable of extracting it.

### Impact Explanation
Any BNB that lands in the contract outside of the narrow `vote()`-triggered bribe-wrapping flow is unrecoverable forever. This is a permanent freezing of funds, reachable by any unprivileged wallet without needing governance or admin cooperation, since sending value to a payable `receive()` requires no special permission.

### Likelihood Explanation
Likelihood is moderate: nothing in the normal user flow of `WombatPoolHelper`/`WombatPoolHelperV2` deliberately sends raw BNB to `WombatStaking` (those helpers wrap native BNB into WBNB themselves before calling `deposit`), so accidental/direct transfers are the main vector. However, because the function is `payable` and unguarded, it is trivially triggerable by any wallet, and once triggered the loss is permanent and irreversible.

### Recommendation
Either remove the `receive()` function from `WombatStaking.sol` entirely if the contract is not meant to hold native BNB balances outside of the `vote()` bribe-wrap step, or add an owner-only sweep/rescue function (mirroring `MultiRewarderPerSec.emergencyWithdraw()`) that forwards `address(this).balance` to a safe recipient, ensuring any accidentally received BNB is not permanently locked.

### Proof of Concept
1. Any wallet calls `address(wombatStaking).call{value: 1 ether}("")`.
2. `receive()` accepts the BNB unconditionally: [1](#0-0) 
3. No function in `WombatStaking.sol` reads or transfers `address(this).balance` outside of the bribe-specific amount computed inside `vote()`, which is gated to the exact bribe reward amount and callable only by `bribeManager`: [4](#0-3) 
4. The 1 BNB sent in step 1 remains in the contract permanently, with no owner or user function capable of retrieving it.
