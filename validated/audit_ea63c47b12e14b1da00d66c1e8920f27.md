## Title
Missing destination-chain binding in `handlePostRequestTimeouts`/`handleGetRequestTimeouts` allows wrongful timeout/refund using a non-membership proof from an unrelated (but legitimately tracked) state machine — ([File: evm/src/core/HandlerV2.sol])

### Summary
`HandlerV2.handlePostRequestTimeouts` never checks that the state machine whose non-membership proof is supplied (`message.height.stateMachineId`) is actually the request's declared `dest`. Because a single `EvmHost` tracks state commitments for many whitelisted state machines simultaneously, an unprivileged caller can prove "non-membership" of a request's receipt in an *unrelated* chain's trie (where the receipt trivially never exists, since the request was never sent there) instead of the real destination's trie, and force `dispatchTimeOut` to fire even though the request was actually delivered and processed on its real destination.

### Finding Description
`Message.hash()` computes a commitment purely from the request's fields (`source, dest, nonce, from, to, timeoutTimestamp, body`) via `keccak256(abi.encode(req))`: [1](#0-0) 

In `handlePostRequestTimeouts`, the flow is:
1. Fetch `state = host.stateMachineCommitment(message.height)` for whatever `stateMachineId` the caller puts in `message.height`.
2. Check `meta = host.requestCommitments(request.hash())` — this only requires that the exact same request struct (including its real `dest`) was previously dispatched on *this* host.
3. Verify non-membership of `REQUEST_RECEIPTS_STORAGE_PREFIX + requestCommitment` in `state.stateRoot`.
4. Call `host.dispatchTimeOut(...)`. [2](#0-1) 

Nowhere in this function is `request.dest` compared against `message.height.stateMachineId` (or the returned `state`'s identity). `EvmHost` stores state commitments per `(stateMachineId, height)` for *every* state machine configured in `_hostParams.stateMachines`, not just the request's actual destination: [3](#0-2) [4](#0-3) 

By contrast, the Substrate ISMP timeout handler explicitly enforces this binding — `dest_chain != timeout_proof.height.id.state_id` must be rejected unless proxying is explicitly allowed: [5](#0-4) 

This asymmetry means the EVM handler is missing the destination-binding check that the Substrate implementation has. An attacker can:
1. Legitimately dispatch a `PostRequest` with `dest = D1` on a source `EvmHost`, populating `_requestCommitments[hash]` via `dispatch()`: [6](#0-5) 
2. Wait until the request's `timeoutTimestamp` has passed relative to *any* other whitelisted state machine `D2`'s tracked timestamp (trivial, since absolute unix timestamps only grow).
3. Submit `handlePostRequestTimeouts` with `message.height = {stateMachineId: D2, height: h}` and a genuine non-membership proof against `D2`'s real, legitimately-updated state root — which will essentially always succeed because the request (destined for `D1`) was never delivered to `D2`, so its receipt key is guaranteed absent from `D2`'s trie.
4. This satisfies every check in the handler and triggers `host.dispatchTimeOut(...)`, which deletes the commitment, invokes the source app's `onPostRequestTimeout` callback (often refunding/unlocking escrowed value to the original sender), and refunds the relayer fee — regardless of whether the request was actually delivered and successfully processed on `D1`: [7](#0-6) 

### Impact Explanation
If an application's `onPostRequestTimeout` callback performs an asset refund/unlock (the standard pattern for bridged-asset apps), and the original request was in fact successfully delivered to and processed on the real destination `D1` (e.g. funds already minted/unlocked to the recipient there), then triggering this bogus timeout via an unrelated chain `D2`'s proof causes a second, unauthorized release of funds on the source chain. This is a direct double-settlement / double-spend of escrowed value, plus an unauthorized relayer-fee refund, matching the bounty's "stealing or loss of funds", "replay/double-claim/double-settlement", and "false proof/state acceptance" categories. Any permissionless caller can trigger `handlePostRequestTimeouts`.

### Likelihood Explanation
`handlePostRequestTimeouts` is explicitly permissionless ("Access: Permissionless (can be called by anyone)"), and any host with more than one whitelisted destination state machine (the typical multi-chain deployment) provides the second, unrelated chain needed for this proof. No hash collision or forged proof is required — only a genuine non-membership proof against a legitimate but wrong chain's state root, which is straightforward for an attacker to obtain via public RPC/indexer access.

### Recommendation
Add an explicit check in `HandlerV2.handlePostRequestTimeouts` (and the analogous `handleGetRequestTimeouts`) that `message.height.stateMachineId` equals the `dest` state machine id encoded in each `request` (mirroring the Substrate `timeout.rs` check `dest_chain != timeout_proof.height.id.state_id`), rejecting the batch (or per-item, if batching by destination is required) when they don't match, unless an equivalent explicit proxy-allowance mechanism is intentionally supported and validated on the EVM side as well.

### Proof of Concept
1. Deploy an `EvmHost` H configured with two whitelisted state machines `D1` and `D2` (via `_hostParams.stateMachines`), both with periodically updated consensus/state commitments.
2. From an app, call `H.dispatch(DispatchPost{dest: D1, timeout: T, ...})`; this stores `_requestCommitments[hash] = {payer, fee}` on `H`.
3. Wait until `D2`'s latest tracked `state.timestamp` on `H` exceeds `T` (independent of whether `D1` ever processed the request).
4. Construct a genuine non-membership proof of `REQUEST_RECEIPTS_STORAGE_PREFIX || hash` against `D2`'s real trusted state root at some proven height (trivially satisfiable since this request was never sent to `D2`).
5. Call `Handler.handlePostRequestTimeouts(H, PostRequestTimeoutMessage{timeouts: [request], height: {stateMachineId: D2, height: h}, proof})`.
6. Observe the call succeeds and `H.dispatchTimeOut` fires `onPostRequestTimeout` and refunds the relayer fee, even though the request's actual destination is `D1` and no proof about `D1`'s trie was ever supplied — assert this should have reverted with something like `InvalidMessageDestination`/`RequestProxyProhibited` but does not.

    function handlePostRequestTimeouts(IHost host, PostRequestTimeoutMessage calldata message)
        external
        notFrozen(host)
    {
        uint256 delay = block.timestamp - host.stateMachineCommitmentUpdateTime(message.height);
        uint256 challengePeriod = host.challengePeriod();
        if (challengePeriod != 0 && challengePeriod > delay) revert ChallengePeriodNotElapsed();

        // fetch the state commitment
        StateCommitment memory state = host.stateMachineCommitment(message.height);
        if (state.stateRoot == bytes32(0)) revert StateCommitmentNotFound();
        uint256 timeoutsLength = message.timeouts.length;

        for (uint256 i = 0; i < timeoutsLength; ++i) {
            PostRequest memory request = message.timeouts[i];
            // timed-out?
            if (request.timeout() > state.timestamp) revert MessageNotTimedOut();

            // known request? also serves as source check
            bytes32 requestCommitment = request.hash();
            FeeMetadata memory meta = host.requestCommitments(requestCommitment);
            if (meta.sender == address(0)) revert UnknownMessage();

            bytes[] memory keys = new bytes[](1);
            keys[0] = bytes.concat(REQUEST_RECEIPTS_STORAGE_PREFIX, requestCommitment);

            // verify state trie non-membership proofs
            PolkadotTrie.StorageValue memory entry = PolkadotTrie.VerifyProof(state.stateRoot, message.proof, keys)[0];
            if (entry.value.length != 0) revert InvalidProof();

            host.dispatchTimeOut(PostRequestTimeout(request, _msgSender()), meta, requestCommitment);
        }
    }

    function dispatchTimeOut(
        PostRequestTimeout memory timeout,
        FeeMetadata memory meta,
        bytes32 commitment
    ) external restrict(_hostParams.handler) {
        // replay protection
        delete _requestCommitments[commitment];
        (bool success,) = _bytesToAddress(timeout.request.from)
            .call(abi.encodeWithSelector(IApp.onPostRequestTimeout.selector, timeout));

        if (!success) {
            // so that it can be retried
            _requestCommitments[commitment] = meta;
            return;
        }

        if (meta.fee != 0) {
            // refund relayer fee
            IERC20(feeToken()).safeTransfer(meta.sender, meta.fee);
        }
        emit PostRequestTimeoutHandled({commitment: commitment, dest: string(timeout.request.dest)});
    }

        if (msg.value > 0) {

            );

            IERC20(feeToken()).safeTransferFrom(_msgSender(), address(this), post.fee);
        }

        // adjust the timeout
        uint64 timeoutTimestamp = post.timeout == 0 ? 0 : uint64(block.timestamp) + uint64(post.timeout);
        PostRequest memory request = PostRequest({
            source: host(),
            dest: post.dest,
            nonce: uint64(_nextNonce()),
            from: abi.encodePacked(_msgSender()),
            to: post.to,
            timeoutTimestamp: timeoutTimestamp,
            body: post.body
        });
