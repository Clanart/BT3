### Title
`CallDispatcher.dispatch()` has no caller authentication, allowing anyone to drain funds transiently held by the shared dispatcher used for Intent Gateway predispatch/postdispatch swaps - (File: `evm/src/utils/CallDispatcher.sol`)

### Summary
The external report's core broken invariant is: a component that temporarily custodies value mid-flow (`BunniHub`/`BunniHook` between pre-hook and post-hook) is reachable by an outside party (the "fulfiller") through a callback that has no guard against interjecting on that in-flight balance. The Hyperbridge analog is `IntentGatewayV2`'s shared `CallDispatcher`: it is the single, protocol-wide intermediary that custodies user/solver assets during `placeOrder` predispatch and `fillOrder` postdispatch flows, yet its `dispatch()` entrypoint is completely unauthenticated — any address can call it directly to move whatever balance the dispatcher currently holds.

### Finding Description
`IntentGatewayV2.placeOrder` and `IntentsBase._execute` treat `_params.dispatcher` (a `CallDispatcher` instance) as a trusted, gateway-only intermediary for composable swap-then-escrow (predispatch) and fill-then-act (postdispatch) flows: [1](#0-0) 

Assets are transferred into the dispatcher, `dispatch(order.predispatch.call)` runs the caller-supplied calldata, and the resulting balance is swept back with a second `dispatch(...)` call: [2](#0-1) 

The same pattern is used for postdispatch calldata after a cross-chain/same-chain fill, and the code explicitly acknowledges residual balances can be left on the dispatcher ("any residual token balances left on the dispatcher are swept back to this contract"): [3](#0-2) 

However, `CallDispatcher.dispatch()` itself performs no caller check whatsoever — it only validates that each call target has code: [4](#0-3) 

There is no `onlyOwner`, `onlyGateway`, or any `msg.sender` restriction. The contract also has an open `receive()` function that accepts native token from anyone. Because the gateway's whole predispatch/postdispatch design assumes the dispatcher is only ever driven by the gateway's own sequential calls, any balance that is transiently or residually held by the dispatcher (in-flight predispatch assets, fee-on-transfer/rounding dust, ETH sent directly to `receive()`, or any leftover ERC-20 balance from a partially-swept order) can be seized by an unprivileged third party simply by calling `dispatch()` directly with a `Call[]` that transfers the dispatcher's current balance to themselves. This is the exact bug-class match to the Bunni report: an entity with no special privilege can interject on a shared component's transiently-held funds because the component's execution surface lacks an access-control invariant that the rest of the protocol implicitly relies on.

### Impact Explanation
This is a direct fund-loss vector matching "stealing or loss of funds" and "unauthorized transaction or execution": any externally-observable balance (native or ERC-20) sitting in the single, protocol-wide `CallDispatcher` — which is used by every `placeOrder`/`fillOrder` call across the entire gateway for predispatch/postdispatch composability — can be extracted by any unprivileged caller, not just the affected order's user or solver. Given the dispatcher is shared across all orders and both fee-on-transfer/rounding dust and native ETH deposits are explicitly anticipated by the code, an attacker does not need a malicious relayer, prover, or admin — a bare EOA calling `dispatch()` is sufficient.

### Likelihood Explanation
High. `CallDispatcher.dispatch()` is a public, no-modifier function; exploitation requires only observing (or causing) any nonzero balance on the dispatcher and submitting a single transaction. The `receive()` function alone guarantees an always-available drain target for any ETH sent to that address (accidentally or otherwise), and the gateway's own dust/residual-balance handling in `_execute`/`placeOrder` confirms nonzero balances are a normal, expected occurrence, not just a hypothetical edge case.

### Recommendation
Restrict `CallDispatcher.dispatch()` to the registered gateway(s) only, e.g. by storing an authorized caller (the `IntentGatewayV2` proxy address) at deployment and enforcing `if (msg.sender != gateway) revert Unauthorized();` at the top of `dispatch()`. Alternatively, make the dispatcher instance-scoped per call (deploy an ephemeral dispatcher or use a transient-storage-gated single-use authorization set immediately before invoking `dispatch` and cleared immediately after) so no window exists where an external, unauthenticated party can act on funds intended only for the gateway's own composed calls.

### Proof of Concept
1. Gateway `_params.dispatcher` points to a single shared `CallDispatcher` instance used by all `placeOrder`/`fillOrder` predispatch/postdispatch flows.
2. Any user sends native ETH directly to the dispatcher's address (it has a public `receive()`), or a `placeOrder`/`fillOrder` predispatch/postdispatch execution leaves residual ERC-20 dust in the dispatcher (acknowledged in `IntentsBase._execute`'s doc comment).
3. An attacker, with no relationship to any order, calls:
   ```solidity
   Call[] memory calls = new Call[](1);
   calls[0] = Call({to: address(attackerToken or address(this)), value: dispatcherBalance, data: abi.encodeWithSelector(IERC20.transfer.selector, attacker, dispatcherBalance)});
   CallDispatcher(dispatcher).dispatch(abi.encode(calls));
   ```
4. Since `dispatch()` performs no caller check, this call succeeds and the attacker (`msg.sender` of the outer call, `to` of the inner call) receives the dispatcher's balance, which was intended for the gateway's own sweep-back logic (`DustCollected` accounting) or a legitimate order's escrow crediting.     /**
     * @dev Executes arbitrary calldata attached to an order's output via the CallDispatcher.
     * After dispatching the calls, any residual token balances left on the dispatcher
     * are swept back to this contract and accounted for as protocol dust.
     *
     * This enables composable order fulfillment — solvers can route through DEXes,
     * lending protocols, or other DeFi primitives as part of filling an order.
     *
     * @param order The order containing the output calldata to execute.
     * @param outputsLen The number of output assets to sweep after execution.
     */
    function _execute(Order calldata order, uint256 outputsLen) internal {
        if (order.output.call.length == 0) return;

        address dispatcher = _params.dispatcher;
        ICallDispatcher(dispatcher).dispatch(order.output.call);

        Call[] memory sweepCalls = new Call[](outputsLen);
        uint256 sweepCount = 0;

        for (uint256 i; i < outputsLen;) {
            address token = address(uint160(uint256(order.output.assets[i].token)));

            if (token == address(0)) {
                uint256 balance = dispatcher.balance;
                if (balance > 0) {
                    sweepCalls[sweepCount] = Call({to: address(this), value: balance, data: ""});
                    sweepCount++;
                    emit DustCollected(token, balance);
                }
            } else {
                uint256 balance = IERC20(token).balanceOf(dispatcher);
                if (balance > 0) {
                    sweepCalls[sweepCount] = Call({
                        to: token,
                        value: 0,
                        data: abi.encodeWithSelector(IERC20.transfer.selector, address(this), balance)
                    });
                    sweepCount++;
                    emit DustCollected(token, balance);
                }
            }

            unchecked {
                ++i;
            }
        }

        if (sweepCount > 0) {
            Call[] memory finalCalls = new Call[](sweepCount);
            for (uint256 i; i < sweepCount;) {
                finalCalls[i] = sweepCalls[i];
                unchecked {
                    ++i;
                }
            }
            ICallDispatcher(dispatcher).dispatch(abi.encode(finalCalls));
        }
    }

    receive() external payable {}

    /**
     *  @dev reverts if the target is not a contract or if any of the calls reverts.
     */
    function dispatch(bytes memory encoded) external {
        Call[] memory calls = abi.decode(encoded, (Call[]));
        uint256 callsLen = calls.length;
        for (uint256 i = 0; i < callsLen; ++i) {
            Call memory call = calls[i];
            uint32 size;
            address to = call.to;
            assembly {
                size := extcodesize(to)
            }

            if (size == 0) {
                revert NotContract(to);
            }

            (bool success, bytes memory result) = to.call{value: call.value}(call.data);
            if (!success) revert CallFailed(to, result);
        }
    }
}
