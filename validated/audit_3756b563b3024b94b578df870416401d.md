### Title
Coinbase outputs are scanned and treated as immediately spendable, producing unbroadcastable spends that lock multisig funds - (File: networks/bitcoin/src/wallet/mod.rs)

### Summary
The Bitcoin `Scanner` indexes every transaction in a block — including the coinbase — purely by `script_pubkey`, with no maturity check. The processor feeds these outputs directly into `SignableTransaction` construction and FROST signing, so a miner who directs a coinbase output to a Serai multisig script causes the processor to sign a transaction spending an immature coinbase output. That transaction is consensus-invalid for 100 blocks, so the emitted plan can never be executed and the multisig's scheduling pipeline stalls on an unspendable input — the same "funds reported present but locked/inaccessible" outcome as the Starkware incident.

### Finding Description
`Scanner::scan_block` iterates `block.txdata` unconditionally (`networks/bitcoin/src/wallet/mod.rs:221-227`), and `scan_transaction` matches any output whose `script_pubkey` is in `self.scripts` (`mod.rs:199-214`). The doc comment itself admits the defect: "This will also scan the coinbase transaction which is bound by maturity. If received outputs must be immediately spendable, a post-processing pass is needed to remove those outputs." No such pass exists downstream:

- `processor/src/multisigs/scanner.rs:562-567` pushes every output returned by `network.get_outputs(&block, key)` (i.e., the `Scanner`) into `outputs` as long as it exceeds `N::DUST`, with no coinbase/maturity check.
- Those outputs are saved and emitted in `ScannerEvent::Block` (`scanner.rs:697-704`) and converted into `Plan`s in `processor/src/multisigs/mod.rs:565-601`.
- `Bitcoin::make_signable_transaction` (`processor/src/networks/bitcoin.rs:446-452`) feeds `input.output.clone()` (the `ReceivedOutput`, whose `outpoint` may reference a coinbase txid) directly into `BSignableTransaction::new`, which is then threshold-signed via `tx.multisig(&keys[&i])` (see `tests/wallet.rs:89-98` for the signing shape).

Bitcoin consensus (BIP-30/rule: coinbase outputs mature after 100 confirmations) rejects any transaction spending a coinbase output younger than 100 blocks. `BSignableTransaction::new` performs only local fee/dust/size checks — nothing inspects whether the prevout is a coinbase or its age.

### Impact Explanation
The multisig signs and commits to a `Plan`/`Batch` whose transaction the Bitcoin network will permanently reject until maturity — and the plan machinery has no re-selection path for the poisoned input (it was already consumed into `plan.inputs`/`output_set` at `mod.rs:624-631`). The scheduler is blocked on an output it believes is spendable, mirroring the Starkware incident's "funds locked, access lost" outcome: reported balance exists but cannot move. Repeated coinbase deposits (every block found by a mining pool paying to the multisig script) keep injecting immature inputs, amplifying the stall into an effective DoS of the forwarding/refund pipeline for that key.

### Likelihood Explanation
Reachable by an unprivileged party using only public inputs — a Bitcoin transaction they cause to exist. Any miner (including small/regtest-difficulty miners, or a pool directing the coinbase) can set the coinbase output's `script_pubkey` to Serai's published P2TR multisig script. No collusion, key material, or validator compromise is required. Exploitation requires the attacker to mine a block, which bounds frequency but not feasibility; any coinbase payout to the multisig — even accidental — triggers it.

### Recommendation
In `Scanner::scan_block` (or the `get_outputs` implementation in `processor/src/networks/bitcoin.rs`), skip `block.txdata[0]` when `tx.is_coinbase()`, or annotate `ReceivedOutput` with a maturity flag and have `make_signable_transaction` exclude immature coinbase prevouts until `block_number - coinbase_height >= 100`. At minimum, call `scan_transaction` on `block.txdata[1..]` per the code's own documentation.

### Proof of Concept
```rust
// A miner crafts a block whose coinbase pays the multisig script.
let coinbase = Transaction {
  version: Version(2),
  lock_time: LockTime::ZERO,
  input: vec![TxIn {
    previous_output: OutPoint::null(), // coinbase
    script_sig: /* arbitrary */,
    sequence: Sequence::MAX,
    witness: Witness::default(),
  }],
  output: vec![TxOut {
    value: Amount::from_sat(50_0000_0000),
    script_pubkey: p2tr_script_buf(group_key).unwrap(), // Serai multisig script
  }],
};

// Scanner::scan_block reports the coinbase output as a ReceivedOutput
// (wallet/mod.rs:221-227 does not skip txdata[0]).
let outputs = scanner.scan_block(&block_with(coinbase));
assert_eq!(outputs.len(), 1); // reported "received"

// Processor path (scanner.rs:562-567, mod.rs:565-601) turns it into a Plan input,
// and make_signable_transaction (bitcoin.rs:446-452) builds/signs a spend of it.
// Broadcasting that spend fails consensus validation:
//   "bad-txns-premature-spend-of-coinbase" for 100 blocks.
// The plan is committed with an unspendable input -> scheduler stall / locked funds.
```
