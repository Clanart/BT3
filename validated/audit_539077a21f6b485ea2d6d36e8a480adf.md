Based on my investigation, I found a concrete Desktop analog: a validation gap in the deep-link "open repository from URL" flow that mirrors the report's core bug class — a boundary/validation check that exists elsewhere in the codebase but is not applied on the actual attacker-reachable path.

### Title
Branch name from deep link bypasses git-ref option-injection guard - (File: `app/src/lib/sanitize-ref-name.ts`, `app/src/lib/parse-app-url.ts`)

### Summary
`fastUpgradePenguin()`'s bug was a missing invariant check (`underMaxLevel`) on one code path while an equivalent, correct path (`upgradePenguin()`) enforced it. The Desktop analog is the same shape: `testForInvalidChars()` — the guard used to validate a branch name coming from an untrusted `x-github-client://openRepo/...?branch=` deep link — is missing a check that a sibling function in the same file (`sanitizedRefName()`) does perform.

### Finding Description
`app/src/lib/parse-app-url.ts` validates the `branch` query parameter of an "open repository from URL" deep link using `testForInvalidChars()`: [1](#0-0) 

`testForInvalidChars()` and `sanitizedRefName()` share the same `invalidCharacterRegex`, but only `sanitizedRefName()` additionally strips a leading run of `-`/`+` characters: [2](#0-1) 

`testForInvalidChars` has no equivalent check — a branch value beginning with `-` (e.g. `--upload-pack=/tmp/evil`, `-force`, or other flag-like strings) is **not** rejected by the regex, because `-` is not in the invalid-character class. This branch string then flows, unsanitized for a leading dash, into `Dispatcher.openBranchNameFromUrl()` and ultimately `checkoutLocalBranch()`: [3](#0-2) 

The same untrusted URL also drives a fetch beforehand (`this.appStore._fetch(repository, FetchType.UserInitiatedTask)`), so an attacker-controlled remote is already fully involved in this flow, satisfying the "attacker controls a git remote/proxy response" impact category.

### Impact Explanation
If the branch string reaches a `git` invocation as a bare positional argument (rather than being passed after a `--` separator or being validated to reject leading dashes), a value like `--upload-pack=/path/to/evil-script` or `-c core.fsmonitor=...` can be interpreted by `git` as an option instead of a ref name — a classic git argument-injection primitive that can lead to arbitrary command execution in the context of the user who clicked the link, entirely through a crafted deep link (`x-github-client://openRepo/<url>?branch=<payload>`) with no local access, no admin rights and no pre-existing malware, matching the report's "silent corruption via a missing cap" pattern but for command-line arguments instead of a numeric level.

### Likelihood Explanation
The trigger requires only that the user click an attacker-supplied `x-github-client://` link (or an "Open in Desktop" HTML link, which Desktop registers as a protocol handler for). `parseAppURL` is the sole gatekeeper for this untrusted input, and it uses the weaker of the two available sanitization functions in the same file, so the omission is a real, reachable gap rather than a theoretical one. I could not fully trace, given the tool budget available, whether the eventual `git` invocation in `checkoutLocalBranch` passes the branch name after a `--` separator (which would neutralize the flag-injection risk) — this is the key remaining uncertainty and should be verified directly in `dispatcher.ts`/`checkout.ts` before treating this as fully exploitable.

### Recommendation
Apply the same leading-dash stripping/rejection used in `sanitizedRefName()` to `testForInvalidChars()` (or call `sanitizedRefName` and compare) before accepting a `branch` parameter from `parseAppURL`, and confirm all git invocations that consume attacker-influenced ref/branch strings pass them after a `--` positional-argument separator.

### Proof of Concept
1. Attacker hosts a page with a link: `x-github-client://openRepo/https://github.com/attacker/repo?branch=--upload-pack=/tmp/payload.sh`.
2. Victim, with Desktop installed and registered as the protocol handler, clicks the link.
3. `parseAppURL` accepts the branch value because `testForInvalidChars` does not flag a leading `-`.
4. `Dispatcher.openBranchNameFromUrl` clones/fetches the attacker repo, then calls `checkoutLocalBranch` with the unsanitized string, potentially passing it as a `git` argument that `git` parses as an option.

Note: I could not conclusively verify the exact `git` argument construction inside `checkoutLocalBranch` within the available tool budget — this should be confirmed with a Devin session that can read the full `dispatcher.ts`/`checkout.ts` implementation before treating this as confirmed-exploitable rather than a validation-gap finding.

// See https://www.kernel.org/pub/software/scm/git/docs/git-check-ref-format.html
// ASCII Control chars and space, DEL, ~ ^ : ? * [ \
// | " < and > is technically a valid refname but not on Windows
// the magic sequence @{, consecutive dots, leading and trailing dot, ref ending in .lock
const invalidCharacterRegex =
  /[\x00-\x20\x7F~^:?*\[\\|""<>]+|@{|\.\.+|^\.|\.$|\.lock$|\/$/g

/** Sanitize a proposed reference name by replacing illegal characters. */
export function sanitizedRefName(name: string): string {
  return name.replace(invalidCharacterRegex, '-').replace(/^[-\+]*/g, '')
}

/** Validate that a reference does not contain any invalid characters */
export function testForInvalidChars(name: string): boolean {
  return invalidCharacterRegex.test(name)
}

  private async openBranchNameFromUrl(
    url: string,
    branchName: string
  ): Promise<Repository | null> {
    const repository = await this.openOrCloneRepository(url)

    if (repository === null) {
      return null
    }

    // ensure a fresh clone repository has it's in-memory state
    // up-to-date before performing the "Clone in Desktop" steps
    await this.appStore._refreshRepository(repository)

    // if the repo has a remote, fetch before switching branches to ensure
    // the checkout will be successful. This operation could be a no-op.
    await this.appStore._fetch(repository, FetchType.UserInitiatedTask)

    await this.checkoutLocalBranch(repository, branchName)

    return repository
  }
