## Analysis

This matches the reported bug class: a mutable token/asset identity parameter is changed in place while the system's persisted state (locked/held balances) still assumes the *previous* identity's accounting shape, breaking withdrawal.

### Title
Unsolicited CR-CAT coin silently converts a plain CAT wallet, permanently stranding pre-existing CAT balance - (`chia/wallet/cat_wallet/cat_wallet.py`, `chia/wallet/vc_wallet/cr_cat_wallet.py`)

### Summary
`CATWallet.identify()` runs automatically during wallet sync for any coin hinted to the user's own puzzle hash. If that coin is CR-CAT-wrapped and its tail hash matches an existing plain `CATWallet` the user already holds a balance in, the code irreversibly converts that wallet in place into a `CRCATWallet` via `CRCATWallet.convert_to_cr()`, without migrating or reconciling the coin records that were stored under the old plain-CAT accounting model.

### Finding Description
`CATWallet.identify()` detects an incoming coin whose puzzle reveal is CR-CAT-wrapped (`wallet_type = CRCATWallet`), and if an existing plain CAT wallet has the same `limitations_program_hash` (tail hash), it calls: [1](#0-0) 

`CRCATWallet.convert_to_cr()` mutates the wallet-info record and swaps the in-memory wallet object for that same wallet id, from `CATWallet` to `CRCATWallet`, without touching any previously stored `WalletCoinRecord`s: [2](#0-1) 

After conversion, every balance/spend path on that wallet id goes through `CRCATWallet` logic, which strictly requires `coin_type` to be `CRCAT`/`CRCAT_PENDING` and requires `CRCATMetadata` to be present: [3](#0-2) 

`get_confirmed_balance()` and `get_pending_approval_balance()` call `coin_record_to_crcat()` on every unspent record for the wallet: [4](#0-3) 

Pre-existing plain CAT coins were stored by the original `CATWallet` with `CoinType.NORMAL`/no CR metadata (added via `puzzle_solution_received`/`add_lineage`, not `add_crcat_coin`), so `coin_record_to_crcat()` raises `ValueError("Attempting to spend a non-CRCAT coin...")` or fails to parse `CRCATMetadata` for these records. The old balance is neither spendable as a plain CAT anymore (the wallet object is now a `CRCATWallet`, whose legacy spend paths are explicitly disabled, e.g. `puzzle_for_pk = None`, `get_new_cat_puzzle_hash` raises `NotImplementedError`) nor spendable as a CR-CAT (it lacks the CR layer, lineage, and VC-authorization data CR-CAT spends require).

This is the same bug class as the report: an externally/attacker-triggerable change to the effective "token"/asset configuration for an existing balance, made without reconciling the funds already accounted for under the prior configuration, resulting in funds becoming stuck until (in the original report) the owner reverts the token, and here — there is no reversion path at all, since `convert_to_cr` is one-directional and has no analog "convert back."

### Impact Explanation
Any party who can get a coin accepted into the mempool that is hinted at the victim's own puzzle hash (e.g. sent within a normal-looking transaction, an offer settlement coin, or a tiny "dust" CR-CAT coin of the same tail hash) can force this conversion on sync. This silently disrupts the victim's ability to spend their pre-existing CAT balance for that asset — a spend-triggered halt on that wallet's normal transaction processing, matching the "Medium" severity class described in the report (locked funds become unwithdrawable until intervention, and here there's no intervention path since the conversion is one-way).

### Likelihood Explanation
Likelihood is moderate: it requires the attacker (or even an unrelated third party's normal transaction, e.g. within an offer, or a well-known/malicious CAT with authorized-provider layers) to send a CR-CAT-wrapped coin of a tail hash the victim already holds, hinted to the victim's puzzle hash. This does not require any elevated privilege — a standard unprivileged wallet user constructing and broadcasting a spend bundle is sufficient, and the victim's own wallet-sync logic performs the disruptive conversion automatically and silently (only logging a websocket event).

### Recommendation
`CATWallet.identify()` should not perform an automatic, one-way, in-place wallet-type conversion (`CRCATWallet.convert_to_cr` / `RCATWallet.convert_to_revocable`) triggered by an unsolicited incoming coin. At minimum, existing `CoinType.NORMAL` records for the wallet id being converted must be reconciled or migrated (or the conversion should be blocked/require explicit user confirmation) before the wallet's spend/balance logic switches to the CR-CAT/RCAT code path, and a safe reversal path should exist. The post-audit precedent — removing the analogous "update stake token" functionality entirely — is directly applicable: disallow automatic CAT→CR-CAT/RCAT type conversion based purely on tail-hash coincidence from unauthenticated network coin states.

### Proof of Concept
1. Victim wallet holds balance in a plain `CATWallet` for tail hash `T` (asset id `T`).
2. Attacker (or any unrelated actor) constructs and broadcasts a spend bundle creating a CR-CAT-layered coin with tail hash `T`, whose inner puzzle/hint resolves to the victim's own puzzle hash (trivial to arrange since hints are attacker-controlled memo data attached to any output).
3. Victim's `WalletStateManager` syncs this new coin; `CATWallet.identify()` detects the CR-CAT wrapping and matching tail hash, and calls `CRCATWallet.convert_to_cr(found_cat_wallet, ...)` (`chia/wallet/cat_wallet/cat_wallet.py:522-528`), replacing the wallet object for that wallet id.
4. Victim's previously-confirmed plain-CAT `WalletCoinRecord`s for that wallet id remain in the coin store with `CoinType.NORMAL` and no `CRCATMetadata`.
5. Any subsequent call to `get_confirmed_balance()`/spend generation on that wallet id invokes `coin_record_to_crcat()` on those records and raises `ValueError` ("Attempting to spend a non-CRCAT coin"/"Error parsing CRCAT metadata"), permanently blocking access to the pre-existing balance through the now-CRCAT-typed wallet.

    @classmethod
    async def convert_to_cr(
        cls,
        cat_wallet: CATWallet,
        authorized_providers: list[bytes32],
        proofs_checker: ProofsChecker,
    ) -> None:
        replace_self = cls()
        replace_self.standard_wallet = cat_wallet.standard_wallet
        replace_self.log = logging.getLogger(cat_wallet.get_name())
        replace_self.log.info(f"Converting CAT wallet {cat_wallet.id()} to CR-CAT wallet")
        replace_self.wallet_state_manager = cat_wallet.wallet_state_manager
        replace_self.info = CRCATInfo(
            cat_wallet.cat_info.limitations_program_hash, None, authorized_providers, proofs_checker
        )
        await cat_wallet.wallet_state_manager.user_store.update_wallet(
            WalletInfo(
                cat_wallet.id(), cat_wallet.get_name(), uint8(WalletType.CRCAT.value), bytes(replace_self.info).hex()
            )
        )
        updated_wallet_info = await cat_wallet.wallet_state_manager.user_store.get_wallet_by_id(cat_wallet.id())
        assert updated_wallet_info is not None
        replace_self.wallet_info = updated_wallet_info
        replace_self.tail_hash = replace_self.info.limitations_program_hash

        cat_wallet.wallet_state_manager.wallets[cat_wallet.id()] = replace_self

    async def get_confirmed_balance(self, record_list: set[WalletCoinRecord] | None = None) -> uint128:
        if record_list is None:
            record_list = await self.wallet_state_manager.coin_store.get_unspent_coins_for_wallet(
                self.id(), CoinType.CRCAT
            )
        amount: uint128 = uint128(0)
        for record in record_list:
            crcat: CRCAT = self.coin_record_to_crcat(record)
            if not crcat.lineage_proof.is_none():
                amount = uint128(amount + record.coin.amount)

        self.log.info(f"Confirmed balance for cat wallet {self.id()} is {amount}")
        return uint128(amount)

    @staticmethod
    def get_metadata_from_record(coin_record: WalletCoinRecord) -> CRCATMetadata:
        metadata: MetadataTypes = coin_record.parsed_metadata()
        assert isinstance(metadata, CRCATMetadata)
        return metadata

    def coin_record_to_crcat(self, coin_record: WalletCoinRecord) -> CRCAT:
        if coin_record.coin_type not in {CoinType.CRCAT, CoinType.CRCAT_PENDING}:  # pragma: no cover
            raise ValueError(f"Attempting to spend a non-CRCAT coin: {coin_record.coin.name().hex()}")
        if coin_record.metadata is None:  # pragma: no cover
            raise ValueError(f"Attempting to spend a CRCAT coin without metadata: {coin_record.coin.name().hex()}")
        try:
            metadata: CRCATMetadata = CRCATWallet.get_metadata_from_record(coin_record)
            crcat: CRCAT = CRCAT(
                coin_record.coin,
                self.info.limitations_program_hash,
                metadata.lineage_proof,
                self.info.authorized_providers,
                self.info.proofs_checker.as_program(),
                (
                    construct_pending_approval_state(
                        metadata.inner_puzzle_hash, uint64(coin_record.coin.amount)
                    ).get_tree_hash()
                    if coin_record.coin_type == CoinType.CRCAT_PENDING
                    else metadata.inner_puzzle_hash
                ),
            )
            return crcat
        except Exception as e:  # pragma: no cover
            raise ValueError(f"Error parsing CRCAT metadata: {e}")
