## Title
`onPostRequestTimeout` gated by `whenNotPaused` blocks user refunds of already-burned tokens while owner-paused, mirroring the Cap "cannot repay on paused asset" bug class - (File: `sdk/packages/core/contracts/apps/HyperFungibleToken.sol`)

### Summary
`HyperFungibleToken`, `HyperFungibleTokenUpgradeable`, `WrappedHyperFungibleToken`, and `WrappedHyperFungibleTokenUpgradeable` all gate `onPostRequestTimeout` — the callback that refunds a user's already-burned/locked tokens when a cross-chain transfer times out — with the same `whenNotPaused` modifier used to gate outbound `send()`. Pausing is meant to stop *new* outbound transfers, but it also blocks the refund of funds that were already removed from circulation by a prior `send()`, exactly the same broken-invariant class as the Cap M-4 report where a pause meant to block new borrows/mints also blocked legitimate repay/liquidation.

### Finding Description
- `send()` burns the caller's tokens immediately and dispatches a POST request; the tokens only exist again if either `onAccept` mints them on the destination or `onPostRequestTimeout` re-mints them to the sender on timeout: [1](#0-0) 
- `onPostRequestTimeout` — the sole recovery path for a user whose transfer timed out — is declared `whenNotPaused`: [2](#0-1) 
- The same pattern repeats in the upgradeable and wrapped variants: [3](#0-2) [4](#0-3) [5](#0-4) 
- The host's timeout dispatcher calls this callback via a low-level `.call`, and only retries later if it reverts — it does not treat a revert as fatal, but it also does not bypass or route around the pause: [6](#0-5) 

Because of the shared `whenNotPaused` guard, once the app owner pauses the contract (e.g., for an incident response on the *outbound* leg), every user with a message currently in flight loses the only mechanism that returns their burned tokens: `onPostRequestTimeout` reverts, `EvmHost.dispatchTimeOut` catches the failed call and re-persists `_requestCommitments[commitment]` for retry, but the retry will keep failing for as long as the contract stays paused. This is structurally identical to the Cap bug: a pause flag intended to stop *new* risk-taking (borrow/mint, `send`) incidentally disables the *recovery/settlement* path (repay/liquidate, `onPostRequestTimeout`) that must always be available to return value already committed to a user.

### Impact Explanation
While the contract is paused, users whose cross-chain sends have timed out cannot recover their burned tokens. This is a direct "loss/lock of funds" condition on production bridge-app contracts (`HyperFungibleToken*`, `WrappedHyperFungibleToken*`) shipped as part of the SDK. Since `onAccept` (destination-side mint) is also `whenNotPaused`, a message that times out during a pause window can never be minted on the destination either, so the value is entirely trapped between chains for the duration of the pause — the same "cannot recover funds" impact class recognized as valid in the seed report.

### Likelihood Explanation
No malicious relayer, prover, or governance compromise is required. The condition only requires the ordinary, sanctioned use of `pause()`/`unpause()` by the contract owner (e.g. during a routine incident response) combined with any in-flight message that times out during that window — an entirely realistic, non-adversarial operational scenario, matching the "internal pre-condition: an asset is paused" pattern from the seed report.

### Recommendation
Remove the `whenNotPaused` modifier from `onPostRequestTimeout` (and consider whether `onGetTimeout`-style refund/settlement callbacks in other apps have the same issue) so that pausing only blocks new outbound `send()`/`onAccept` mint flows, never the return of previously escrowed/burned value to its rightful owner — mirroring the Cap fix that permits repay to proceed independent of the pause flag.

### Proof of Concept
```solidity
// 1. Owner pauses the token app for maintenance/incident response.
hft.pause();

// 2. A user's earlier send() that has not yet been delivered times out.
//    The host retries the timeout callback:
vm.prank(address(host));
(bool success, ) = address(hft).call(
    abi.encodeWithSelector(
        hft.onPostRequestTimeout.selector,
        timedOutRequest
    )
);
assertFalse(success); // reverts due to whenNotPaused -> tokens stay burned, unrecoverable while paused

// 3. Even after owner unpauses, if pause is prolonged, user funds remain
//    inaccessible on both source (burned) and destination (never minted)
//    chains for the entire pause window.

    function onPostRequestTimeout(PostRequestTimeout calldata incoming) external override onlyHost whenNotPaused {
        HyperFungibleToken.Message memory message = abi.decode(incoming.request.body, (HyperFungibleToken.Message));
        address refundee = _toAddr(message.from);

        if (_isWeth) {
            // Try a native-ETH push first; if the refundee cannot accept native value
            // (e.g. the caller used the ERC-20 deposit path in `send()` from a
            // non-payable contract), re-wrap the withdrawn ETH and deliver the
            // underlying WETH as an ERC-20 transfer so the timeout still settles and
            // funds are not permanently locked.
            IWETH(_underlying).withdraw(message.amount);
            (bool sent,) = refundee.call{value: message.amount}("");
            if (!sent) {
                IWETH(_underlying).deposit{value: message.amount}();
                IERC20(_underlying).safeTransfer(refundee, message.amount);
            }
        } else {
            IERC20(_underlying).safeTransfer(refundee, message.amount);
        }

        emit Refunded({to: refundee, amount: message.amount});
    }

    function dispatchTimeOut(
        PostRequestTimeout memory timeout,
        FeeMetadata memory meta,
        bytes32 commitment
    ) external restrict(_hostParams.handler) {
        // replay protection
        delete _requestCommitments[commitment];
        (bool success,) = _bytesToAddress(timeout.request.from)
            .call(abi.encodeWithSelector(IApp.onPostRequestTimeout.selector, timeout));

        if (!success) {
            // so that it can be retried
            _requestCommitments[commitment] = meta;
            return;
        }

        if (meta.fee != 0) {
            // refund relayer fee
            IERC20(feeToken()).safeTransfer(meta.sender, meta.fee);
        }
        emit PostRequestTimeoutHandled({commitment: commitment, dest: string(timeout.request.dest)});
    }
