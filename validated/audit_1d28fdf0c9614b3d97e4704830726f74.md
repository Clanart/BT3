### Title
Trusting an attacker-controlled `WWW-Authenticate` header to classify a remote as "GitHub Enterprise" bypasses real host verification - (File: `app/src/lib/trampoline/trampoline-credential-helper.ts`)

### Summary
`getEndpointKind()` in the Git credential-helper trampoline decides whether a remote host should be treated as a trusted GitHub/GHE endpoint. One of its signals is the `wwwauth[]` credential field, which Git populates directly from the HTTP `WWW-Authenticate` response header sent by the remote server during authentication. Any git server the user clones/fetches/pushes to (i.e. an attacker-controlled remote or a MITM/compromised proxy) fully controls this header, yet Desktop treats `realm="GitHub"` in it as sufficient proof of being an "enterprise" GitHub host, without performing the same network-based verification (`isGitHubHost`) it does in the fallback path. This is directly analogous to the Pyth report: an externally supplied, attacker-influenced value (`conf`/`realm`) is used to make a trust decision without validating it against a real, independent check.

### Finding Description
`getEndpointKind` classifies a credential request's endpoint before deciding how to source credentials for it: [1](#0-0) 

The `wwwauth[...]` keys originate from Git's HTTP credential protocol, which forwards any `WWW-Authenticate` header value returned by the remote server for a 401 response, unauthenticated and unvalidated by Desktop itself, straight into the credential map that `createCredentialHelperTrampolineHandler` parses: [2](#0-1) 

Unlike the legitimate fallback path a few lines below, which performs an actual network probe (`isGitHubHost`, hitting `/meta` and checking for the `x-github-request-id` response header) to determine if a host is really GitHub-controlled: [3](#0-2) 

the `wwwauth[]` branch short-circuits that check purely on a substring match of attacker-supplied text (`v.includes('realm="GitHub"')`). Nothing about the HTTP header proves the host is actually GitHub-affiliated — it is just text chosen by the server operator.

Once classified as `'enterprise'`, `getCredential()` uses this classification to decide whether to trigger the "Sign in to GitHub Enterprise" UI flow for a host that has no existing account: [4](#0-3) 

which calls into `promptForGitHubSignIn`, presenting the user with GitHub Desktop's native Enterprise sign-in UI and OAuth/PAT flow, seeded with the attacker's endpoint URL, even though the "trust" that this is a genuine GitHub Enterprise instance was derived from a header the attacker fully controls: [5](#0-4) 

While `findGitHubTrampolineAccount` (used to auto-fill credentials for *already signed-in* accounts) does correctly match by exact `origin`, preventing outright token leakage to the wrong host, the initial trust classification itself is the broken invariant: Desktop accepts an unvalidated, attacker-supplied signal (`realm="GitHub"`) as equivalent to verified proof of a GitHub-affiliated host, exactly the same "missing confidence/validation check on an untrusted external value" pattern as the Pyth report.

### Impact Explanation
This corrupts the endpoint-trust decision Desktop makes when handling Git authentication for a URL supplied by the user (any generic git remote). A malicious or compromised HTTP git server can:
1. Respond to Git's authentication probe with `WWW-Authenticate: Basic realm="GitHub"`.
2. Cause Desktop to classify the host as `'enterprise'` without ever performing the real `/meta` verification that would normally distinguish it from an actual GitHub Enterprise server.
3. Trigger Desktop's native "Sign in to GitHub Enterprise" popup/OAuth flow bound to the attacker's endpoint, lending the attacker's server false legitimacy in the eyes of the user and steering the account-binding UX toward an untrusted host — an unauthorized/attacker-influenced account-binding path that would not have been reached had Desktop performed its normal host verification.

### Likelihood Explanation
Low-to-moderate: it requires the user to add/clone a remote pointing at a server the attacker controls (or a MITM'd/compromised legitimate-looking git host) and go through Git's HTTP authentication flow against it, but requires no elevated privileges, no prior compromise of the user's machine, and no unnatural user steps beyond adding/using a hostile remote — one of the explicitly in-scope attacker primitives (a git remote/proxy response).

### Recommendation
Do not treat the `wwwauth[]` realm string as sufficient proof of a GitHub-affiliated host. Either:
- Remove the `wwwauth[]` "happy path" short-circuit entirely and always fall back to the network-verified `isGitHubHost()` check, or
- Require the `wwwauth[]` signal to be corroborated by the same `isGitHubHost()` verification (e.g., use it only as a hint to skip caching/short-circuit an *additional* verification request, never as the sole basis for the trust decision) before invoking `promptForGitHubSignIn`.

### Proof of Concept
1. Stand up a plain HTTP(S) git server (e.g. a simple `git-http-backend` wrapper) that, on receiving an unauthenticated request, returns `401` with header `WWW-Authenticate: Basic realm="GitHub"`.
2. In GitHub Desktop, clone/add this server's repository as a remote and perform a fetch/push that requires authentication.
3. Observe that `getEndpointKind` in `app/src/lib/trampoline/trampoline-credential-helper.ts` returns `'enterprise'` for this host purely from the spoofed header (no `isGitHubHost` network check occurs), and that Desktop surfaces the "Sign in to GitHub Enterprise" flow (`trampolineUIHelper.promptForGitHubSignIn`) for the attacker's endpoint, treating it as a legitimate GitHub Enterprise server based solely on attacker-controlled data.

/** Implementation of the 'get' git credential helper command */
async function getCredential(cred: Credential, store: Store, token: string) {
  const ghCred = await getGitHubCredential(cred, store)

  if (ghCred) {
    return ghCred
  }

  const endpointKind = await getEndpointKind(cred, store)
  const accounts = await store.getAll()

  const endpoint = `${getCredentialUrl(cred)}`
  const apiEndpoint = getAPIEndpoint(endpoint)

  // If it appears as if the endpoint is a GitHub host and we don't have an
  // account for that endpoint then we should prompt the user to sign in.
  if (
    endpointKind !== 'generic' &&
    !accounts.some(a => a.endpoint === apiEndpoint)
  ) {
    if (getIsBackgroundTaskEnvironment(token)) {
      debug('background task environment, skipping prompt')
      return undefined
    }

    const account = await ui.promptForGitHubSignIn(endpoint)

    if (!account) {
      setHasRejectedCredentialsForEndpoint(token, endpoint)
    }

    return credWithAccount(cred, account)
  }

  // GitHub.com/GHE creds are only stored internally
  if (endpointKind !== 'generic') {
    return undefined
  }

  return useExternalCredentialHelper()
    ? getExternalCredential(cred, token)
    : getGenericCredential(cred, token)
}

const getEndpointKind = async (cred: Credential, store: Store) => {
  const credentialUrl = getCredentialUrl(cred)
  const endpoint = `${credentialUrl}`

  if (isGist(endpoint)) {
    return 'generic'
  }

  if (isDotCom(endpoint)) {
    return 'github.com'
  }

  if (isGHE(endpoint)) {
    return 'ghe.com'
  }

  // When Git attempts to authenticate with a host it captures any
  // WWW-Authenticate headers and forwards them to the credential helper. We
  // use them as a happy-path to determine if the host is a GitHub host without
  // having to resort to making a request ourselves.
  for (const [k, v] of cred.entries()) {
    if (k.startsWith('wwwauth[')) {
      if (v.includes('realm="GitHub"')) {
        return 'enterprise'
      } else if (/realm="(GitLab|Gitea|Atlassian Bitbucket)"/.test(v)) {
        return 'generic'
      }
    }
  }

/**
 * Attempts to determine whether or not the url belongs to a GitHub host.
 *
 * This is a best-effort attempt and may return `undefined` if encountering
 * an error making the discovery request
 */
export async function isGitHubHost(url: string) {
  const { hostname } = new window.URL(url)

  const endpoint =
    hostname === 'github.com' || hostname === 'api.github.com'
      ? getDotComAPIEndpoint()
      : getEnterpriseAPIURL(url)

  if (isDotCom(endpoint) || isGHE(endpoint)) {
    return true
  }

  if (isKnownThirdPartyHost(hostname)) {
    return false
  }

  // github.example.com,
  if (/(^|\.)(github)\./.test(hostname)) {
    return true
  }

  // bitbucket.example.com, etc
  if (/(^|\.)(bitbucket|gitlab)\./.test(hostname)) {
    return false
  }

  if (getEndpointVersion(endpoint) !== null) {
    return true
  }

  // Add a unique identifier to the URL to make sure our certificate error
  // supression only catches this request
  const metaUrl = `${endpoint}/meta?ghd=${crypto.randomUUID()}`

  const ac = new AbortController()
  const timeoutId = setTimeout(() => ac.abort(), 2000)
  suppressCertificateErrorFor(metaUrl)
  try {
    const response = await fetch(metaUrl, {
      headers: { 'user-agent': getUserAgent() },
      signal: ac.signal,
      credentials: 'omit',
      method: 'HEAD',
      redirect: 'error',
    })

    tryUpdateEndpointVersionFromResponse(endpoint, response)

    return response.headers.has('x-github-request-id')
  } catch (e) {
    log.debug(`isGitHubHost: failed with endpoint ${endpoint}`, e)
    return undefined
  } finally {
    clearTimeout(timeoutId)
    clearCertificateErrorSuppressionFor(metaUrl)
  }
}

  public promptForGitHubSignIn(endpoint: string): Promise<Account | undefined> {
    return new Promise<Account | undefined>(async resolve => {
      const cb = (result: SignInResult) => {
        resolve(result.kind === 'success' ? result.account : undefined)
        this.dispatcher.closePopup(PopupType.SignIn)
      }

      const { hostname, origin } = new URL(endpoint)
      if (hostname === 'github.com') {
        this.dispatcher.beginDotComSignIn(cb)
      } else {
        this.dispatcher.beginEnterpriseSignIn(cb)
        await this.dispatcher.setSignInEndpoint(origin)
      }

      this.dispatcher.showPopup({
        type: PopupType.SignIn,
        isCredentialHelperSignIn: true,
        credentialHelperUrl: endpoint,
      })
    }).catch(e => {
      log.error(`Could not prompt for GitHub sign in`, e)
      return undefined
    })
  }
