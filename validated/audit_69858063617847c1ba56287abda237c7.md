### Title
Lazy extension field silently replaces attacker-controlled corrupt bytes with default instance on first access, permanently discarding data with no error surfaced to caller - (File: java/core/src/main/java/com/google/protobuf/LazyFieldLite.java)

### Summary
The Turnstile report's failed invariant is: an operation that is validated by a "lenient" check at one layer (application layer accepts any non-zero address) silently produces a permanently broken/incomplete result once a stricter, deferred check (consensus layer account-existence) is applied, and the caller of the lenient layer receives a success signal with no way to detect or recover the loss. `LazyFieldLite` in the Java runtime exhibits the same structural pattern: attacker-controlled bytes for an extension/lazy message field pass the outer, lenient wire-format check (a well-formed length-delimited field) at parse time, but the deferred, stricter check — actually parsing those bytes as the declared submessage type — is not performed until first access (`ensureInitialized`/`mergeFrom`). If that deferred parse fails, the field's true value is permanently and silently discarded and replaced by the default instance, while the outer `parseFrom`/`mergeFrom` call that consumed the client's bytes already returned success.

### Finding Description
`LazyFieldLite` defers parsing of a message-typed field's serialized bytes (`delayedBytes`) until the value is first accessed via `getValue()`/`ensureInitialized()`, or until another `LazyFieldLite` is merged into it via `mergeFrom(CodedInputStream, ExtensionRegistryLite)` or `mergeValueAndBytes`.

At the point the outer message is parsed (`MessageLite.parseFrom`, a supported public parse API), the wire-format check performed on a lazy field is only that the field is a well-formed length-delimited byte blob; the bytes are stored as `delayedBytes` and the parse of the *enclosing* message returns success without ever validating that those bytes decode into a valid instance of the target message type: [1](#0-0) 

The stricter check — actually decoding `delayedBytes` against the target `MessageLite` parser — only happens lazily, in `ensureInitialized`: [2](#0-1) 

If that deferred decode throws `InvalidProtocolBufferException`, the code sets `this.value = defaultInstance` and `this.corrupted = true`, but — per the comment at lines 489-490 — "Nothing is logged and no exceptions are thrown. Clients will be unaware that this proto was invalid." The same silent-discard pattern recurs in `mergeFrom(CodedInputStream, ExtensionRegistryLite)` (lines 360-365) and in `mergeValueAndBytes` (lines 368-377), both of which swallow `InvalidProtocolBufferException` without signaling failure to the caller of the outer `mergeFrom`/`build()` call.

This mirrors the external report's root cause exactly: a value (an address / a byte blob) that satisfies a shallow, permissive check at the entry point (non-zero address / well-formed length-delimited bytes) is accepted and reported as successful, while a deeper, authoritative check (account-existence on the consensus layer / actual message decode against the target schema) silently fails later, and by the time that failure is discovered, the "true" data is already gone and unrecoverable — the caller has no signal that anything went wrong.

### Impact Explanation
Any consuming application that relies on `LazyFieldLite`-backed extension or message fields (used internally for extensions/`MessageSet` and for other message-typed fields with lazy-parsing enabled) can silently lose the true contents of a field that was sent by a legitimate, ordinary client through a supported public parse API (`parseFrom`/`mergeFrom`). The outer parse operation reports success (no exception), `IsInitialized`/required-field checks on the outer message are unaffected because the field is present as far as has-bits/oneof-case tracking is concerned, but the actual submessage is silently replaced by the type's default instance. Because there is no exception, no log message, and no public API to query `corrupted` (the flag is package-private), the consuming application cannot detect that this happened, and once the corrupted `LazyFieldLite` is merged/serialized further, the original bytes are permanently gone (see `toByteString()`, which returns `memoizedBytes = ByteString.EMPTY` after corruption, and `mergeValue`, which will merge in the corrupted default value into the aggregate result). This is a data-integrity issue with correctness/availability implications for the application (silent field-level data loss), not a memory-safety bug.

### Likelihood Explanation
This requires a message that has a `LazyFieldLite`-typed field/extension (i.e. lazy parsing enabled via `ExtensionRegistryLite.lazyExtensionEnabled()` or a lazy message field), and the sub-message bytes provided by a client must be malformed relative to the target sub-message schema while still being a valid length-delimited byte string at the outer wire-format level — an easy, purely-client-controlled condition to construct (e.g. bytes that don't decode as the expected submessage type, or a submessage missing wire-format well-formedness within its own bounds). No privileged access, hostile schema, or non-standard API usage is required; this occurs through the ordinary public `parseFrom`/`mergeFrom` binary-parsing surface with bounded input.

### Recommendation
- Do not silently discard the corrupted value: either propagate the parse failure to the caller of the outer `parseFrom`/`mergeFrom` (fail the whole parse operation, consistent with how non-lazy submessage parse failures propagate), or expose `isCorrupted()`/an equivalent signal through a public API so callers can detect and react to field-level parse failures.
- At minimum, log the swallowed `InvalidProtocolBufferException` (as is already done in `MessageLite.LogInitializationErrorMessage()` for the required-fields case) so silent data loss is observable and diagnosable in production.
- Audit other locations that swallow `InvalidProtocolBufferException` without signaling failure (`LazyFieldLite.mergeFrom`, `LazyFieldLite.mergeValueAndBytes`, `InternalLazyField.ensureInitialized`) for the same silent-success/data-loss pattern.

### Proof of Concept
1. Construct (as an ordinary client) a serialized message containing an extension/lazy-message field whose length-delimited payload is *not* a valid encoding of the declared extension message type (e.g., truncated/garbage bytes inside a validly-tagged, validly-length-prefixed field).
2. Call the public parsing API, e.g. `Foo.parseFrom(bytes, extensionRegistry)` where `extensionRegistry.lazyExtensionEnabled()` is true for that extension. The call returns successfully; no exception is thrown, matching `LazyFieldLite`'s constructor path (`java/core/src/main/java/com/google/protobuf/LazyFieldLite.java:100-114`).
3. On the returned message, call `getExtension(...)` (which triggers `LazyFieldLite.getValue()` → `ensureInitialized`, `java/core/src/main/java/com/google/protobuf/LazyFieldLite.java:468-496`). The decode of `delayedBytes` fails internally with `InvalidProtocolBufferException`, which is caught; the accessor instead returns the extension's *default instance*, with no exception surfaced and no log emitted (comment at lines 489-490).
4. Serialize the message again (`toByteString()`): the field's original attacker bytes have already been replaced (`memoizedBytes = ByteString.EMPTY`), so the true payload is unrecoverable, while every step of the process (initial parse, extension access, re-serialization) reported success to the caller.

  /** Might lazily parse the bytes that were previously passed in. Is thread-safe. */
  protected void ensureInitialized(MessageLite defaultInstance) {
    if (value != null) {
      return;
    }
    synchronized (this) {
      if (value != null) {
        return;
      }
      try {
        if (delayedBytes != null) {
          // The extensionRegistry shouldn't be null here since we have delayedBytes.
          MessageLite parsedValue =
              defaultInstance.getParserForType().parseFrom(delayedBytes, extensionRegistry);
          this.value = parsedValue;
          this.memoizedBytes = delayedBytes;
        } else {
          this.value = defaultInstance;
          this.memoizedBytes = ByteString.EMPTY;
        }
      } catch (InvalidProtocolBufferException e) {
        // Nothing is logged and no exceptions are thrown. Clients will be unaware that this proto
        // was invalid.
        this.corrupted = true;
        this.value = defaultInstance;
        this.memoizedBytes = ByteString.EMPTY;
      }
    }
  }
