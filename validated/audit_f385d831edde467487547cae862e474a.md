### Title
Identity/Torsion-Weak ECDH Key Accepted in PedPoP Encrypted Messages Enables Keystream Reuse and Share Recovery - ([File: crypto/dkg/pedpop/src/encryption.rs](crypto/dkg/pedpop/src/encryption.rs))

### Summary
CVE-2021-36047 is an improper-input-validation flaw where a crafted file is parsed without sufficient validation, yielding attacker-controlled state. The analog in Serai is the PedPoP DKG encryption layer: both `EncryptionKeyMessage::read` (the registered per-participant encryption key) and `EncryptedMessage::read` (the per-message ephemeral key) parse group elements via `Ciphersuite::read_G`, which enforces canonical encoding and (for the dalek/ed448 wrappers) subgroup membership, but does **not** reject the identity point. FROST's own `Curve::read_G` rejects identity for exactly this reason, but PedPoP uses the raw `Ciphersuite` implementation instead. An attacker-controlled identity point makes the ECDH shared secret the identity — a publicly known value — collapsing the per-message encryption scheme onto a single, attacker-known, reused ChaCha20 keystream.

### Finding Description
`EncryptedMessage` reads its ephemeral `key` with `C::read_G` (the `Ciphersuite` trait), which only checks canonicality, not identity [1](#0-0) . The same is true for the long-lived `enc_key` registered per participant [2](#0-1)  and stored without any validation in `Decryption::register` [3](#0-2) . By contrast, the FROST `Curve` trait's `read_G` explicitly rejects identity [4](#0-3) , so this defense exists in the codebase but was not applied on the PedPoP path.

The ECDH is `ecdh(private, public) = public * private` [5](#0-4) , fed into `cipher()` which derives a ChaCha20 key and uses a **fixed static IV** `"DKG IV v0.2\0"`, justified by the comment "If we never reuse the key, we can't have the opportunity to reuse a nonce" [6](#0-5) . The code itself states the invariant: "Each ecdh must be distinct. Reuse of an ecdh for multiple ciphers will cause the messages to be leaked" [7](#0-6) .

Two attack shapes:

1. **Registered `enc_key = identity`**: a participant registers an `EncryptionKeyMessage` whose `enc_key` is the identity. Every `encrypt()` to that participant computes `ecdh(key, identity) = identity` [8](#0-7) . All ciphertexts to that participant reuse the identical keystream derived from the publicly known identity encoding — so (a) any observer of a ciphertext can decrypt it (the "shared" key is not secret), and (b) the blame machinery's guarantee that revealing one message's `EncryptionKeyProof` doesn't affect other messages is destroyed, since every message shares the same ECDH key [9](#0-8) .

2. **Per-message `key = identity`**: `EncryptedMessage::read` accepts `key = identity`. The attached PoP is a Schnorr signature over `key`, and a signature under the identity public key is trivially forgeable (private key `0`), so the proof-of-possession check provides no barrier [10](#0-9) . The victim's `decrypt` then derives `ecdh(self.enc_key, identity) = identity`, decrypting with a key anyone can recompute [11](#0-10) .

The poisoned inputs flow through the exact surfaces the rules enumerate: `EncryptionKeyMessage::read` / `Commitments::read` via `generate_secret_shares` [12](#0-11) , and `EncryptedMessage::read` via `calculate_share` [13](#0-12) .

### Impact Explanation
Secret-share confidentiality is the security property this encryption layer exists to provide. With an identity `enc_key`, every secret share encrypted to the malicious participant is protected by a keystream derived from the identity point — recoverable by any passive observer who knows `context` (a public value) — and all such ciphertexts share one keystream, so `C_i XOR C_j = P_i XOR P_j`. Additionally, a single published `EncryptionKeyProof` (the blame mechanism designed to reveal exactly one message) silently decrypts *every* message ever sent to that participant. The end result is exposure of threshold secret-share plaintext and collapse of the blame isolation the protocol documents in `spec/cryptography/Distributed Key Generation.md` — key-share recovery for any party able to observe the authenticated channel ciphertexts or a blame statement.

### Likelihood Explanation
The trigger is a single crafted 32-byte identity encoding in a `Commitments`/`EncryptionKeyMessage` broadcast or an `EncryptedMessage` — the "crafted file" of the original CVE mapped to Serai's real shape. No threshold collusion, no broken BFT, and no key leakage is required; the code performs no identity rejection anywhere on this path (`Ciphersuite::read_G` returns identity happily, and `register` does an unconditional HashMap insert). The share-verification step does not mitigate it, because the attack doesn't need a *valid* share to leak — the ciphertexts are already decryptable.

### Recommendation
Reject the identity point when parsing any group element used for ECDH or PoP in PedPoP: use `Curve`-style `read_G` semantics (canonicality + `is_identity()` rejection) inside `EncryptionKeyMessage::read`, `EncryptedMessage::read`, `Commitments::read`, `EncryptionKeyProof::read`, and `GeneratorProof::read`, or add explicit `is_identity` checks in `Decryption::register` and `decrypt`/`decrypt_with_proof`. This mirrors the existing defense in `frost::Curve::read_G`.

  pub fn calculate_share<R: RngCore + CryptoRng>(

    rng: &mut R,

  ) -> Result<BlameMachine<C>, PedPoPError<C>> {
    validate_map(

      self.params.i(),

    let mut batch = BatchVerifier::new(shares.len());
    let mut blames = HashMap::new();
    for (l, share_bytes) in shares.drain() {

        rng,
        BatchId::Share(l),

      );
