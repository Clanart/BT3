## Title
Withdrawal-UTXO owner can reuse their own `SIGHASH_SINGLE|ANYONECANPAY` signature to mine a conflicting payout with a garbage/missing OP_RETURN, causing `is_kickoff_malicious` to challenge the honest, paying operator - (File: core/src/verifier.rs)

## Summary
The withdrawal UTXO spent by the payout transaction is the withdrawing user's own UTXO, signed with `TapSighashType::SinglePlusAnyoneCanPay` [1](#0-0) . That sighash flag pins only input 0 and output 0 of the transaction, leaving every other output (including the operator-identifying OP_RETURN) and every other input unconstrained [2](#0-1) . Because the withdrawer (an unprivileged attacker) owns the private key for that UTXO, they can independently construct and get mined a competing spend of the same outpoint that keeps output 0 (their payout) intact but supplies a malformed/absent OP_RETURN, which `update_finalized_payouts` will resolve to `operator_xonly_pk = None`, causing `is_kickoff_malicious` to always return `true` for the honest operator's later kickoff.

## Finding Description
Binding claimed to hold: `operator_credited_in_db (operator_xonly_pk_opt from update_finalized_payouts) == operator_that_actually_funded_the_payout (kickoff_data.operator_xonly_pk in handle_finalized_payout)`.

Trace:
1. The withdrawing user calls `Operator::withdraw`/`internal_withdraw`/aggregator `withdraw`, supplying `in_outpoint` (the withdrawal UTXO, which is the user's own dust UTXO, spendable with the user's own key) and `in_signature` [3](#0-2) . `parse_withdrawal_sig_params` enforces the signature's sighash type must be `SinglePlusAnyoneCanPay` [4](#0-3) .
2. The operator builds `create_payout_txhandler`, which spends this same input via `SpendPath::KeySpend` and appends an OP_RETURN with the operator's own xonly pubkey as output 2 [2](#0-1) . `SinglePlusAnyoneCanPay` only commits to output index 0 and input index 0 - it does not commit to the OP_RETURN output or to any operator-funded fee inputs the operator adds via `fund_raw_transaction`.
3. Because the attacker (the withdrawer) holds the private key spending that UTXO, they can sign and broadcast an alternative transaction spending the *same* outpoint, keeping output 0 identical (so their own payout is unaffected/preserved) but omitting the OP_RETURN or filling it with garbage bytes, and get this transaction confirmed instead of (or in a race with) the operator's transaction (e.g. via higher fee/RBF, since sequence/fee is unconstrained by ANYONECANPAY).
4. Verifiers track whichever transaction actually spends the withdrawal outpoint via the bitcoin syncer and record its txid as the payout, then in `update_finalized_payouts` parse the OP_RETURN of that block-confirmed tx: `parse_op_return_data(...).and_then(|bytes| XOnlyPublicKey::from_slice(bytes).ok())` [5](#0-4) . A garbage or missing OP_RETURN makes `operator_xonly_pk = None`, which is explicitly documented as tolerated ("optimistic payout" or "operator constructed the payout tx wrong") and stored as NULL [6](#0-5) .
5. Meanwhile the honest operator, believing it fronted the payout (because it saw its own broadcast succeed, or via `PayoutCheckerTask`/`handle_finalized_payout`), commits the payout blockhash via WOTS in its kickoff.
6. When verifiers process `CheckIfKickoffMalicious`, `is_kickoff_malicious` looks up payout info by move txid, and unconditionally returns `true` when `operator_xonly_pk_opt` is `None`: `let Some(operator_xonly_pk) = operator_xonly_pk_opt else { ... return Ok(true); }` [7](#0-6) .
7. `handle_kickoff` then queues/sends a `Challenge` transaction against the honest operator's kickoff [8](#0-7) , burning the honest operator's collateral even though it genuinely funded the withdrawal (or at least attempted to, and committed the correct blockhash).

Why existing guards fail: `Verifier::is_deposit_valid`, `SECP.verify_schnorr`, and the sighash-type enforcement in `parse_withdrawal_sig_params` only check that the *given* signature is valid for `SinglePlusAnyoneCanPay` - they do nothing to prevent that same signature (or any equally valid alternate signature the attacker can produce with their own key) from being reused in a different transaction with different non-pinned outputs. There is no on-chain commitment tying the confirmed spend of the withdrawal UTXO to the specific operator that is supposed to be credited; the credit is derived purely from parsing whatever OP_RETURN happens to be in whichever transaction wins the race to spend that UTXO.

## Impact Explanation
This burns the honest operator's collateral (Challenge tx execution) even though the operator did not act maliciously - it is the classification in `update_finalized_payouts`/`is_kickoff_malicious` that is wrong due to attacker-controlled OP_RETURN malleability on an unauthenticated (ANYONECANPAY/SINGLE) input. This matches the Critical category "an honest operator's collateral burned." The attack is repeatable per-withdrawal: any user withdrawing through the bridge can grief the specific operator servicing their withdrawal by racing a self-crafted transaction with a garbage OP_RETURN against the operator's payout broadcast. Blast radius is bounded to one operator's kickoff/collateral per exploited withdrawal, but is repeatable across all withdrawals and operators since every withdrawal UTXO is user-owned and every payout signature uses the same permissive sighash flag.

## Likelihood Explanation
- Preconditions: attacker must be the withdrawing user themselves (an unprivileged actor with a legitimate deposit and citrea withdrawal), controlling the private key of the "withdrawal UTXO" - this is guaranteed by the protocol design (the withdrawal UTXO is always the user's own dust UTXO).
- Attacker cost: one on-chain transaction fee (arbitrarily small dust UTXO amount plus fee to win the mining race, e.g., via RBF or by broadcasting first with a competitive fee).
- Feasibility: no cryptographic break needed - only reuse of a validly obtained/self-created Schnorr signature under `SinglePlusAnyoneCanPay`, which is explicitly the required sighash type for this flow. High feasibility, fully repeatable per withdrawal/operator pairing.

## Recommendation
Do not rely solely on `SinglePlusAnyoneCanPay` for the withdrawal UTXO signature when the OP_RETURN payer-identification output must be trusted; either (a) require `SIGHASH_ALL` (or otherwise commit to all outputs including the OP_RETURN) for the user's payout signature, or (b) stop crediting/discrediting operators purely from parsing an unauthenticated OP_RETURN of whichever transaction happens to spend the outpoint - instead have verifiers/operators independently and cryptographically confirm which operator's kickoff (and its committed hash) corresponds to the actual on-chain payout before ever concluding `operator_xonly_pk = None` implies maliciousness, e.g., only treat a payout as "no operator" (optimistic payout) if it structurally matches the known optimistic-payout tx template, otherwise treat unparseable OP_RETUENs on a non-optimistic-payout-shaped tx as inconclusive rather than automatically malicious.

#[allow(clippy::result_large_err)]
pub fn parse_withdrawal_sig_params(
    params: WithdrawParams,
) -> Result<(u32, taproot::Signature, OutPoint, ScriptBuf, Amount), Status> {
    let mut input_signature =
        taproot::Signature::from_slice(&params.input_signature).map_err(|e| {
            Status::invalid_argument(format!("Can't convert input to taproot Signature - {e}"))
        })?;

    // If the Taproot sighash type is Default (no explicit type attached; i.e. a 64-byte
    // signature without a sighash flag), normalize it to SinglePlusAnyoneCanPay.
    // Prior to v0.5 this was Clementine's implicit behavior; we retain it here for
    // backwards compatibility when a 64-byte signature is provided.
    if input_signature.sighash_type == TapSighashType::Default {
        tracing::warn!(
            "Input signature for withdrawal {} has sighash type default, setting to SinglePlusAnyoneCanPay", params.withdrawal_id,
        );
        input_signature.sighash_type = TapSighashType::SinglePlusAnyoneCanPay;
    }

    // enforce sighash type here
    if input_signature.sighash_type != TapSighashType::SinglePlusAnyoneCanPay {
        return Err(Status::invalid_argument(format!(
            "Input signature has wrong sighash type, SinglePlusAnyoneCanPay expected, got {}",
            input_signature.sighash_type
        )));
    }

pub fn create_payout_txhandler(
    input_utxo: UTXO,
    output_txout: TxOut,
    operator_xonly_pk: XOnlyPublicKey,
    user_sig: taproot::Signature,
    _network: bitcoin::Network,
) -> Result<TxHandler<Signed>, BridgeError> {
    let txin = SpendableTxIn::new_partial(input_utxo.outpoint, input_utxo.txout);

    let output_txout = UnspentTxOut::from_partial(output_txout.clone());

    let op_return_txout = op_return_txout(PushBytesBuf::from(operator_xonly_pk.serialize()));

    let mut txhandler = TxHandlerBuilder::new(TransactionType::Payout)
        .with_version(NON_STANDARD_V3)
        .add_input(
            NormalSignatureKind::NotStored,
            txin,
            SpendPath::KeySpend,
            DEFAULT_SEQUENCE,
        )
        .add_output(output_txout)
        .add_output(UnspentTxOut::from_partial(anchor_output(
            NON_EPHEMERAL_ANCHOR_AMOUNT,
        )))
        .add_output(UnspentTxOut::from_partial(op_return_txout))
        .finalize();
    txhandler.set_p2tr_key_spend_witness(&user_sig, 0)?;
    txhandler.promote()
}

    /// Checks if the kickoff is malicious and sends the appropriate txs if it is.
    /// Returns true if the kickoff is malicious.
    /// Sends a challenge tx if the kickoff is first malicious one in the current round, and the network is not mainnet or testnet4.
    pub async fn handle_kickoff<'a>(
        &'a self,
        dbtx: DatabaseTransaction<'a>,
        kickoff_witness: Witness,
        mut deposit_data: DepositData,
        kickoff_data: KickoffData,
        challenged_before: bool,
    ) -> Result<bool, BridgeError> {
        let is_malicious = self
            .is_kickoff_malicious(kickoff_witness, &mut deposit_data, kickoff_data, dbtx)
            .await?;

        let deposit_outpoint = deposit_data.get_deposit_outpoint();

        let (_signed_txs, tx_metadata, challenge_tx) = self
            .get_signed_txs_for_kickoff(dbtx, kickoff_data, deposit_data)
            .await?;

        if is_malicious {
            tracing::warn!(
                "Malicious {} detected. {} Challenge tx: {} for deposit {}",
                kickoff_data,
                match challenged_before {
                    false => "This is the first malicious kickoff in the current round.",
                    true => "This is not the first malicious kickoff in the current round.",
                },
                bitcoin::consensus::encode::serialize_hex(&challenge_tx),
                deposit_outpoint
            );
            // do not automatically send challenge txs on mainnet or testnet4
            if !challenged_before
                && !matches!(
                    self.config.protocol_paramset().network,
                    bitcoin::Network::Bitcoin | bitcoin::Network::Testnet4
                )
            {
                #[cfg(feature = "automation")]
                self.tx_sender
                    .add_tx_to_queue(
                        dbtx,
                        TransactionType::Challenge,
                        &challenge_tx,
                        &[],
                        Some(tx_metadata),
                        self.config.protocol_paramset(),
                        None,
                    )
                    .await?;
            }
