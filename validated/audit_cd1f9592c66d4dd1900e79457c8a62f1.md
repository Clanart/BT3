### Title
Unvalidated GitHub PR fork `clone_url` passed directly to `git remote add` / `git fetch` enables argument and transport-scheme injection - ([File: app/src/lib/stores/app-store.ts])

### Summary
When a user opens a pull request that originates from a fork, GitHub Desktop takes the fork's `clone_url` — a value returned by the GitHub API and therefore fully controlled by whoever created the fork/PR — and feeds it unchecked into `git remote add` and subsequently `git fetch`. Neither the URL scheme (`https`/`ssh`/`git`) nor a leading-dash "flag-like" value is validated before this untrusted string reaches the git command line, unlike the report's central complaint about EIP-4337: a value from an untrusted/attacker-influenced source is consumed by a critical validation/state-transition path without the mandated checks.

### Finding Description
`_findPullRequestBranch()` in [1](#0-0)  receives `headCloneUrl` from `_checkoutPullRequest()`, which in turn receives it straight from the GitHub API object `pullRequest.head.repo.clone_url` in `openPullRequestFromUrl()`: [2](#0-1) . If no existing remote matches, this raw string is handed to `addRemote()`:

```
await git(['remote', 'add', name, url], repository.path, 'addRemote')
``` [3](#0-2) 

This call does not insert a `--` separator before the positional `name`/`url` arguments (contrast with `app/src/lib/git/clone.ts`, which explicitly does `args.push('--', url, path)` at [4](#0-3)  as a hardening measure). Because `addRemote` lacks the same `--` guard, a `clone_url` value that begins with a dash (e.g. `-o`, `--foo`) can be interpreted by `git remote add` as an option rather than a URL argument. More significantly, there is no restriction anywhere in the reviewed remote/fetch/environment code (`app/src/lib/git/environment.ts`, `app/src/lib/git/fetch.ts`, `app/src/lib/git/remote.ts`) on the URL **scheme**: no `GIT_ALLOW_PROTOCOL` allowlist, no `-c protocol.<transport>.allow=never` hardening, and no reuse of the existing `parseRemote()` allowlist (which only recognizes `https`/`ssh`/`git` shapes, see [5](#0-4) ) is applied to `headCloneUrl` before it is used to add a remote and immediately fetched via `_fetchRemote()` at [6](#0-5) .

Existing guards in the codebase (`resolveWithin`/`isAbsolute` checks in `dispatcher.ts` for `filepath`, `sanitizeCloneName` and `isClonePathSensitive` for clone destinations, `testForInvalidChars` for branch names, and the `--` separator in `clone.ts`) demonstrate the project is aware of and defends against argument-injection and path-traversal in other flows, but the fork PR checkout path (`addRemote` + `_fetchRemote`) was not brought under the same discipline.

### Impact Explanation
`git`'s transport-helper mechanism (`ext::`, `fd::`) can execute arbitrary shell commands when a remote URL uses those schemes and the relevant `protocol.*.allow` policy is not set to `never`/`user`. A PR author who controls the head repository's advertised `clone_url` (via the GitHub API response consumed by Desktop, not the git protocol itself) can cause the victim's Desktop client — merely by having them open the "View on GitHub"/"Checkout PR" flow for that PR — to add a remote and fetch from an attacker-chosen URL. If Desktop's git installation and configuration do not block the `ext::` transport, this results in command execution outside the git sandbox on the victim's machine; at minimum it allows argument-injection style manipulation of `git remote add`/`git fetch` behavior. This matches the "unprivileged... attacker controls ... a GitHub API object... result is code execution" impact criterion.

### Likelihood Explanation
Exploitation requires only that the attacker create a fork and a pull request whose head repository's `clone_url` is attacker-influenced, and that the victim use Desktop's normal "checkout this PR" / "Open PR from Desktop" feature — no local access, no elevated privileges, and no unnatural steps beyond viewing/checking out a PR, which is standard Desktop usage.

### Recommendation
- Validate `headCloneUrl` (and any other API-derived clone/remote URL) against the same allowlisted protocol/shape used by `parseRemote()` before calling `addRemote()` or fetching from it; reject anything that isn't `https://`, `ssh://`/`git@`, or `git://` GitHub-shaped URLs.
- Reject values that start with `-` to avoid option/argument injection, and add a `--` separator before positional URL arguments in `addRemote()`, mirroring the pattern already used in `clone.ts`.
- Explicitly set `GIT_ALLOW_PROTOCOL` (or `-c protocol.ext.allow=never -c protocol.fd.allow=never`) in `envForRemoteOperation`/`envForRemoteOperation` for all remote-touching git invocations, not just submodules.

### Proof of Concept
1. Attacker forks a target repository and opens a pull request; through control of their fork's metadata/API responses the head repository's `clone_url` field is `-oProxyCommand=...` (or, if the app is later run against a compromised/mocked API relay, `ext::sh -c 'touch /tmp/pwned'`).
2. Victim uses "Open PR from Desktop" / clicks the PR / uses `openPullRequestFromUrl()` in [7](#0-6) .
3. `_checkoutPullRequest` → `_findPullRequestBranch` executes `addRemote(repository, forkRemoteName, headCloneUrl)` [8](#0-7) , which runs `git remote add <name> <attacker-controlled url>` with no `--` separator and no scheme allowlist [3](#0-2) .
4. The remote is then fetched via `_fetchRemote` [6](#0-5) , causing git to connect using whatever scheme/arguments were injected, without a protocol allowlist enforced by Desktop.

  private async openPullRequestFromUrl(
    url: string,
    pr: string
  ): Promise<RepositoryWithGitHubRepository | null> {
    const pullRequest = await this.appStore.fetchPullRequest(url, pr)

    if (pullRequest === null) {
      return null
    }

    // Find the repository where the PR is created in Desktop.
    let repository: Repository | null =
      this.getRepositoryFromPullRequest(pullRequest)

    if (repository !== null) {
      await this.selectRepository(repository)
    } else {
      repository = await this.openOrCloneRepository(url)
    }

    if (repository === null) {
      log.warn(
        `Open Repository from URL failed, did not find or clone repository: ${url}`
      )
      return null
    }
    if (!isRepositoryWithGitHubRepository(repository)) {
      log.warn(
        `Received a non-GitHub repository when opening repository from URL: ${url}`
      )
      return null
    }

    // ensure a fresh clone repository has it's in-memory state
    // up-to-date before performing the "Clone in Desktop" steps
    await this.appStore._refreshRepository(repository)

    if (pullRequest.head.repo === null) {
      return null
    }

    await this.appStore._checkoutPullRequest(
      repository,
      pullRequest.number,
      pullRequest.head.repo.owner.login,
      pullRequest.head.repo.clone_url,
      pullRequest.head.ref
    )

    return repository
  }
