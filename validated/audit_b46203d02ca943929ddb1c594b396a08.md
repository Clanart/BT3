### Title
Missing `--no-ext-diff` on commit/history/branch-compare diff paths allows attacker-controlled `.gitattributes` diff drivers to run during rendering - (File: app/src/lib/git/diff.ts)

### Summary
`app/src/lib/git/diff.ts` contains multiple `git diff`/`git log -p` invocations that render diffs to the user. Two of them (`getWorkingDirectoryDiff`, `getResolutionDiff`) explicitly pass `--no-ext-diff` with a comment stating the invariant: *"`--no-ext-diff` should be provided wherever we invoke `git diff` so that any diff.external program configured by the user is ignored"* [1](#0-0) . Three other exported diff functions — `getCommitDiff`, `getBranchMergeBaseDiff`, and `getCommitRangeDiff` — violate this stated invariant and omit the flag [2](#0-1) [3](#0-2) [4](#0-3) .

### Finding Description
The bug-class parallel to the ERC777 report is: a value the app trusts for a security/UX-relevant decision (here, the rendered diff text/hunks) is computed via a two-step process where control can be handed to an untrusted, externally-influenced program in between, and the app has no guard against that in some code paths even though it explicitly guards against it in others.

Git's diff machinery supports per-path diff drivers configured through `.gitattributes` (`path diff=<driver>`) combined with a `diff.<driver>.command`/`diff.<driver>.textconv` entry in git config. When git computes a diff for a path matching such an attribute and a matching driver command is configured, it invokes that external program to produce the diff/text content instead of git's internal diff engine — i.e., "control" over what the "before"/"after" content looks like is handed to that external command. Desktop's own code acknowledges this risk and neutralizes it with `--no-ext-diff` in `getWorkingDirectoryDiff` [5](#0-4)  and `getResolutionDiff` [6](#0-5) , but not in the commit-history diff path (`getCommitDiff`, used by `git log -1 -p`) [7](#0-6) , the branch-merge-base ("compare branches") diff path (`getBranchMergeBaseDiff`) [8](#0-7) , or the commit-range diff path (`getCommitRangeDiff`) [9](#0-8) .

These functions are exercised in `app-store.ts` when a user browses commit history, views a stash, or compares branches — i.e., paths that are commonly hit right after cloning or fetching an untrusted repository, exactly the "attacker controls a cloned/fetched repository" primitive called out in the task's valid-impact list. The corrupted value here is the diff content/hunks (`IDiff`) handed back to the renderer and used to drive the UI (and, in `getBranchMergeBaseChangedFiles`, the numstat-derived changeset data used elsewhere for change summaries).

### Impact Explanation
If the user (or their environment/profile) already has a `diff.<driver>.command` or `diff.<driver>.textconv` configured (a common pattern for users of tools such as `difftastic`, `delta`, image/binary diff helpers, etc.), a malicious repository can ship a `.gitattributes` file that maps its tracked paths to that driver name. When the victim opens the commit view, browses history, or uses "compare branches" for that repository in Desktop, the affected code paths will invoke `git log -p` / `git diff --merge-base` without `--no-ext-diff`, causing git to shell out to the externally configured command against attacker-chosen file paths/content. Depending on the sophistication of the configured external tool, this can range from unexpected process execution with attacker-influenced arguments to full command injection if the external tool is not hardened — and at minimum it silently substitutes git's internal, trustworthy diff computation with output from a third-party program the app never intended to invoke in that flow, which can misrepresent what changed (silent corruption of the diff shown to the user).

### Likelihood Explanation
Exploitation still requires the victim to already have some `diff.<driver>` entry configured in their global/user gitconfig; a repository's own `.git/config` is not cloned, so the attacker cannot inject the driver's command by themselves — only the attribute-to-driver-name mapping via the tracked `.gitattributes`. This somewhat lowers the likelihood versus a fully self-contained exploit, but it is a realistic setup for developers using popular external diff/pretty-print tools, and the fact that Desktop's own code explicitly documents and enforces this exact mitigation in two of five diff-producing functions shows the developers consider the scenario in-scope; the omission in the other three is an inconsistency/regression rather than a deliberate design choice.

### Recommendation
Add `--no-ext-diff` to the `git` arguments built in `getCommitDiff`, `getBranchMergeBaseDiff`, and `getCommitRangeDiff` in `app/src/lib/git/diff.ts`, matching the existing pattern and comment used in `getWorkingDirectoryDiff`/`getResolutionDiff`. Also audit `getBranchMergeBaseChangedFiles` and `getCommitRangeChangedFiles` (raw `--numstat`/`--raw` diffs) for the same flag, since numstat generation can still invoke `textconv` filters for byte-count computation.

### Proof of Concept
Not independently executed (no filesystem/terminal access in this session); the following steps would need to be verified by a Devin agent with repo access:
1. In a test environment, configure `git config --global diff.mydriver.command "/tmp/poc-diff.sh"` where `poc-diff.sh` is a script that logs/executes when invoked with the file paths it receives.
2. Create a malicious repository containing a `.gitattributes` with `*.txt diff=mydriver` and at least one commit modifying a `.txt` file.
3. Clone this repository into GitHub Desktop and open the "History" tab, or use "Compare branches", triggering `getCommitDiff`/`getBranchMergeBaseDiff`.
4. Confirm `poc-diff.sh` executes as part of rendering the diff (e.g., via log file written by the script), demonstrating that `diff.external` is honored in these code paths, unlike in `getWorkingDirectoryDiff`/`getResolutionDiff` where the same script does not execute due to `--no-ext-diff`.

export async function getCommitDiff(
  repository: Repository,
  file: FileChange,
  commitish: string,
  hideWhitespaceInDiff: boolean = false
): Promise<IDiff> {
  const args = [
    'log',
    commitish,
    ...(hideWhitespaceInDiff ? ['-w'] : []),
    '-m',
    '-1',
    '--first-parent',
    '--patch-with-raw',
    '--format=',
    '-z',
    '--no-color',
    '--',
    ensureRelativePath(file.path),
  ]

  if (
    file.status.kind === AppFileStatusKind.Renamed ||
    file.status.kind === AppFileStatusKind.Copied
  ) {
    args.push(ensureRelativePath(file.status.oldPath))
  }

  const { stdout } = await git(args, repository.path, 'getCommitDiff', {
    encoding: 'buffer',
  })

  return buildDiff(stdout, repository, file, commitish, commitish)
}

export async function getCommitRangeDiff(
  repository: Repository,
  file: FileChange,
  commits: ReadonlyArray<string>,
  hideWhitespaceInDiff: boolean = false,
  useNullTreeSHA: boolean = false
): Promise<IDiff> {
  if (commits.length === 0) {
    throw new Error('No commits to diff...')
  }

  const oldestCommit = useNullTreeSHA ? NullTreeSHA : commits[0]
  const oldestCommitRef = useNullTreeSHA ? NullTreeSHA : `${commits[0]}^`
  const latestCommit = commits.at(-1) ?? '' // can't be undefined since commits.length > 0
  const args = [
    'diff',
    oldestCommitRef,
    latestCommit,
    ...(hideWhitespaceInDiff ? ['-w'] : []),
    '--patch-with-raw',
    '--format=',
    '-z',
    '--no-color',
    '--',
    ensureRelativePath(file.path),
  ]

  if (
    file.status.kind === AppFileStatusKind.Renamed ||
    file.status.kind === AppFileStatusKind.Copied
  ) {
    args.push(ensureRelativePath(file.status.oldPath))
  }

  const result = await git(args, repository.path, 'getCommitsDiff', {
    encoding: 'buffer',
    expectedErrors: new Set([GitError.BadRevision]),
  })

  // This should only happen if the oldest commit does not have a parent (ex:
  // initial commit of a branch) and therefore `SHA^` is not a valid reference.
  // In which case, we will retry with the null tree sha.
  if (result.gitError === GitError.BadRevision && useNullTreeSHA === false) {
    return getCommitRangeDiff(
      repository,
      file,
      commits,
      hideWhitespaceInDiff,
      true
    )
  }

  return buildDiff(result.stdout, repository, file, latestCommit, oldestCommit)
}
