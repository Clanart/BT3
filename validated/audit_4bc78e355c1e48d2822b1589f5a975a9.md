### Title
Unauthenticated OP_RETURN in Payout tx lets an attacker reassign operator reimbursement credit via a signature-preserving double-spend - (File: `core/src/verifier.rs`, `core/src/task/payout_checker.rs`)

### Summary
The `Payout` transaction's only cryptographic signature (the withdrawing user's `SinglePlusAnyoneCanPay`+`Single` signature) commits only to input 0 and output 0; the anchor (output 1) and OP_RETURN operator-attribution output (output 2) are completely unsigned and freely replaceable by anyone who observes the broadcast transaction. Since `Verifier::update_finalized_payouts` derives `payout_payer_operator_xonly_pk` purely from whatever bytes happen to be in the OP_RETURN of the tx that is actually mined, an attacker can race a double-spend of the same withdrawal input with a forged OP_RETURN naming any operator `Q`, causing `Q`'s `PayoutCheckerTask` to run `handle_finalized_payout` and eventually claim reimbursement for a withdrawal `Q` never funded.

### Finding Description
**Binding claimed to hold:** `payout_payer_operator_xonly_pk(withdrawal i) == xonly_pk(operator whose funds paid the user for withdrawal i)`.

**Root cause:** `create_payout_txhandler` builds the Payout tx with three outputs — user payout (0), anchor (1), OP_RETURN with operator pubkey (2) — but only signs output 0 via the user's key with a `SinglePlusAnyoneCanPay` signature [1](#0-0) . The sighash type is enforced server-side, confirming that the signature commits only to the current input and the output at the same index (output 0) [2](#0-1) . `Operator::withdraw` verifies exactly this restricted sighash [3](#0-2) .

Later, `Verifier::update_finalized_payouts` scans the confirmed block for whichever transaction actually spent the withdrawal UTXO, and blindly parses whatever OP_RETURN output is present to determine `operator_xonly_pk`, storing it as the sole attribution record [4](#0-3) . No signature or commitment ties this OP_RETURN byte string to the operator that actually funded/broadcast the transaction.

`PayoutCheckerTask::run_once` for operator `Q` then queries `get_first_unhandled_payout_by_operator_xonly_pk` filtered only by this unauthenticated column [5](#0-4) , and if a match is found calls `Operator::handle_finalized_payout`, which fetches `Q`'s pre-signed, unused kickoff connector for that deposit and proceeds to kickoff [6](#0-5) . Because every operator pre-signs kickoff connectors for every deposit during the deposit ceremony (not just the "real" fronting operator) [7](#0-6) , `Q` already possesses a valid signed kickoff path and needs no cooperation from anyone to consume it.

The only sanity check that touches this attribution, `Verifier::is_kickoff_malicious`, merely compares the (equally unauthenticated) DB-stored `operator_xonly_pk` against the kickoff's `operator_xonly_pk` [8](#0-7)  — it does not verify that the credited operator actually constructed or funded the payout transaction, so a self-consistent forged attribution passes this check trivially.

**Attack:** The attacker observes O's broadcast Payout transaction (input0 witness + output0 are public in the mempool). The attacker constructs a new transaction spending the same input0 with the same witness (valid under `SinglePlusAnyoneCanPay`+`Single`, since only input0/output0 are committed), reuses output0 verbatim, but appends an attacker-funded fee input (allowed by `AnyoneCanPay`) and a new OP_RETURN naming a distinct real operator `Q`. The attacker gets this transaction mined instead of O's (e.g., via higher fee/RBF), causing the withdrawal row's `payout_payer_operator_xonly_pk` to be recorded as `Q`, letting `Q` be credited and eventually reimbursed for a payout it never funded.

### Impact Explanation
This directly matches the Critical category "an operator reimbursed for a payout it never funded": `Q`'s `PayoutCheckerTask` will proceed through `handle_finalized_payout` → kickoff → (absent a dispute) `Reimburse`, drawing bridge-collateral funds for a withdrawal it never paid. The blast radius spans every deposit/withdrawal and every operator pair, since the attribution mechanism (unsigned OP_RETURN) is identical across the system, and the attack is repeatable per withdrawal race window.

### Likelihood Explanation
The attacker needs no privileged role — only the ability to observe a broadcast/mempool transaction and to construct/broadcast a competing double-spend with a higher fee, which is standard Bitcoin capability. The cost is limited to the fee needed to win the mining race. Because the Payout transaction's signature explicitly authorizes exactly this kind of malleability (`SinglePlusAnyoneCanPay`+`Single` leaves outputs 1 and 2 unauthenticated), the precondition is met by design in every payout, making this readily exploitable whenever an attacker is monitoring the mempool for Payout transactions.

### Recommendation
Bind the OP_RETURN operator attribution to the same signature that authorizes the withdrawal, e.g., by requiring the sighash type to cover all outputs (`TapSighashType::All` or `AllPlusAnyoneCanPay`) so the user's signature also commits to the OP_RETURN content, or by having verifiers additionally require an operator-signed commitment (separate from the freely-malleable OP_RETURN) proving that the specific operator constructed/authorized that exact payout transaction before crediting it in `update_finalized_payouts`.

Plan:
1. Set up two operators `O` and `Q` and one deposit/withdrawal as in existing e2e tests (`core/src/test/deposit_and_withdraw_e2e.rs`).
2. Have `O` call `withdraw` normally to produce and broadcast `payout_tx_O` (do not mine it yet).
3. Extract `payout_tx_O`'s input0 witness and output0; construct `payout_tx_attacker` with the same input0/output0, an attacker-funded extra input (AnyoneCanPay), and an OP_RETURN containing `Q`'s xonly pubkey.
4. Broadcast `payout_tx_attacker` with a higher fee so it replaces/wins over `payout_tx_O` in the mempool, then mine to finality.
5. Run `Q`'s `PayoutCheckerTask::run_once` and assert it returns `Ok(true)`, that `get_payout_info_from_move_txid` for the deposit's move txid returns `Q`'s xonly pubkey, and that `handle_finalized_payout` succeeded for `Q` — demonstrating `payout_payer_operator_xonly_pk == Q` while `Q` funded nothing (assert the mined tx's extra input belongs to the attacker, not `Q` or `O`).

pub fn create_payout_txhandler(
    input_utxo: UTXO,
    output_txout: TxOut,
    operator_xonly_pk: XOnlyPublicKey,
    user_sig: taproot::Signature,
    _network: bitcoin::Network,
) -> Result<TxHandler<Signed>, BridgeError> {
    let txin = SpendableTxIn::new_partial(input_utxo.outpoint, input_utxo.txout);

    let output_txout = UnspentTxOut::from_partial(output_txout.clone());

    let op_return_txout = op_return_txout(PushBytesBuf::from(operator_xonly_pk.serialize()));

    let mut txhandler = TxHandlerBuilder::new(TransactionType::Payout)
        .with_version(NON_STANDARD_V3)
        .add_input(
            NormalSignatureKind::NotStored,
            txin,
            SpendPath::KeySpend,
            DEFAULT_SEQUENCE,
        )
        .add_output(output_txout)
        .add_output(UnspentTxOut::from_partial(anchor_output(
            NON_EPHEMERAL_ANCHOR_AMOUNT,
        )))
        .add_output(UnspentTxOut::from_partial(op_return_txout))
        .finalize();
    txhandler.set_p2tr_key_spend_witness(&user_sig, 0)?;
    txhandler.promote()
}

    pub async fn get_first_unhandled_payout_by_operator_xonly_pk(
        &self,
        tx: Option<DatabaseTransaction<'_>>,
        operator_xonly_pk: XOnlyPublicKey,
    ) -> Result<Option<(u32, Txid, BlockHash)>, BridgeError> {
        let query = sqlx::query_as::<_, (i32, Option<TxidDB>, Option<BlockHashDB>)>(
            "SELECT w.idx, w.move_to_vault_txid, w.payout_tx_blockhash
             FROM withdrawals w
             WHERE w.payout_txid IS NOT NULL
                AND w.is_payout_handled = FALSE
                AND w.payout_payer_operator_xonly_pk = $1
                ORDER BY w.idx ASC
             LIMIT 1",
        )
        .bind(XOnlyPublicKeyDB(operator_xonly_pk));

        let results = execute_query_with_tx!(self.connection, tx, query, fetch_optional)?;

        results
            .map(|(citrea_idx, move_to_vault_txid, payout_tx_blockhash)| {
                Ok((
                    u32::try_from(citrea_idx).wrap_err("Failed to convert citrea index to u32")?,
                    move_to_vault_txid
                        .expect("move_to_vault_txid Must be Some")
                        .0,
                    payout_tx_blockhash
                        .expect("payout_tx_blockhash Must be Some")
                        .0,
                ))
            })
            .transpose()
    }
