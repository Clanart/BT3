## Title
`aptos move verify-package` claims to verify on-chain bytecode but never fetches or compares it, only metadata/source fields - ([File: aptos-move/cli/src/commands.rs])

### Summary
The `VerifyPackage` CLI command is documented as "Downloads a package and verifies the bytecode... verifies the bytecode matches a local compilation of the Move code." In practice, it never downloads or compares the actual on-chain compiled module bytes (`.mv` bytecode). It creates the `CachedPackageRegistry` with `with_bytecode = false` and calls `CachedPackageMetadata::verify()`, which only compares `PackageMetadata` fields (`name`, `deps`, `modules` (name/source/source_map/extension), `manifest`, `upgrade_policy`, `extension`, `source_digest`). None of these fields are cryptographically or structurally tied on-chain to the actual bytecode blobs that were published via `code::publish_package_txn`.

### Finding Description
`code::publish_package(owner, pack: PackageMetadata, code: vector<vector<u8>>)` in [1](#0-0)  accepts `PackageMetadata` and `code` (module bytecode blobs) as two independent, unrelated parameters. There is no on-chain assertion that the `source_digest`, `source`, or `source_map` fields inside `PackageMetadata` actually correspond to the bytecode in `code`. The Move module only performs upgrade-policy, dependency, and module-name-set checks (`check_dependencies`, `check_upgradability`, `check_coexistence`) — it never hashes or otherwise validates that the submitted bytecode matches the claimed metadata/source, as seen in [2](#0-1) .

Given this on-chain design, source-level verification is meant to happen off-chain via the CLI's `verify-package` command, whose doc comment explicitly promises: "Downloads a package and verifies the bytecode... Downloads the package from onchain and verifies the bytecode matches a local compilation of the Move code" — [3](#0-2) .

However, the implementation:
1. Creates the registry with `with_bytecode = false`, so no actual `.mv` bytecode is ever fetched from chain: [4](#0-3) .
2. Calls `package.verify(&compiled_metadata)` which only diffs `PackageMetadata` struct fields (name, deps, modules, manifest, upgrade_policy, extension, source_digest) — it contains no comparison of compiled bytecode bytes at all: [5](#0-4) .

Separately, `DownloadPackage` does support fetching real bytecode via `registry.get_bytecode(module)` when `--bytecode` is passed [6](#0-5) , proving the capability to fetch and compare bytecode exists in the codebase, but `VerifyPackage` deliberately doesn't use it (`with_bytecode: false`, and no code path comparing `pack.extract_code()` against fetched bytecode).

The `ModuleMetadata.source` field, which is the closest thing to a bytecode-linked artifact in the compared struct, is documented as optional and can be empty ("Source text, gzipped String. Empty if not provided" — [7](#0-6) ), and `source_digest` is only a hash over the source `.move` files (per the doc comment on `PackageMetadata`), not over the compiled bytecode.

### Impact Explanation
Because the on-chain `code::publish_package` never links metadata (including `source_digest`) to the actual published bytecode, and the off-chain "bytecode verifier" tool (`aptos move verify-package`) never fetches or diffs real bytecode, an attacker (or a compromised/malicious publisher) can publish a package where the claimed metadata/source corresponds to benign code while the actual bytecode bundle executed on-chain is different/malicious. Anyone relying on `aptos move verify-package` to gain assurance that "what's published matches what I see as source" (a standard trust flow for depending on or auditing third-party packages before adding them as a dependency, before calling into them, or before treating them as safe) gets a false positive: the command reports "Successfully verified source of package" while having done nothing to check the actual bytecode. This directly matches the Publish Pivot: "Mismatch between verified bytes, package metadata, dependency declarations, and committed module bytes." Given that dependency verification and package auditing are a standard part of ecosystem trust for third-party Move packages (and this tool is explicitly marketed as bytecode verification), the practical impact is high: false assurance of code safety for any consumer trusting the CLI's stated behavior.

### Likelihood Explanation
This is a straightforward implementation bug (feature-not-implemented) reachable by any user who runs `aptos move verify-package`, with no privileged access required to trigger the misleading result — a publisher only needs to submit a `PackageMetadata`/`code` pair where the metadata does not match the actual bytecode. This is trivially possible since `code::publish_package_txn` takes both as independent BCS-serialized arguments with no on-chain cross-check. Likelihood of a user unknowingly relying on this broken guarantee is realistic since the CLI presents it as the standard mechanism to verify on-chain packages against source.

### Recommendation
Fix `VerifyPackage::execute` to:
1. Fetch on-chain bytecode (`with_bytecode: true` when creating `CachedPackageRegistry`, or otherwise call `registry.get_bytecode` for every module).
2. Compare the fetched on-chain bytecode byte-for-byte (or by hash) against `pack.extract_code()` from the locally built package, for every module in the package.
3. Fail verification if any module's bytecode differs, independent of whether the metadata fields (source, source_digest, manifest) happen to match.
Alternatively, update the documentation/UX to make clear that `verify-package` only checks metadata consistency and does not verify bytecode equivalence, to avoid users relying on a false security guarantee — though this weakens the command's usefulness for its stated purpose and is not a substitute for fixing the actual bytecode check.

### Proof of Concept
1. Compile a legitimate package `P` locally with source files `S` and build `metadata_v1` (with `source_digest_v1` over `S`), and legitimate bytecode `code_v1`.
2. Craft a second, malicious bytecode bundle `code_evil` (e.g., containing a backdoored function) but reuse `metadata_v1` (same `source_digest_v1`, same `modules` field including the same gzipped `source`) unchanged.
3. Publish on-chain: call `code::publish_package_txn(signer, bcs::to_bytes(&metadata_v1), code_evil)`. Nothing in `code::publish_package` (see [8](#0-7) ) checks that `code_evil` bytecode corresponds to `metadata_v1`'s claimed source/digest — the transaction succeeds as long as module names in `code_evil` match `expected_modules` derived from the metadata.
4. Run `aptos move verify-package --account <addr>` against the local source `S` that produces `metadata_v1`. Because `VerifyPackage::execute` fetches only metadata (`with_bytecode: false`, [4](#0-3) ) and `CachedPackageMetadata::verify` only diffs metadata struct fields ( [5](#0-4) ), all fields match (`metadata_v1 == metadata_v1`), and the command prints `"Successfully verified source of package"` even though the actually executing on-chain bytecode (`code_evil`) is entirely different and unrelated to the verified source.

(Note: I was unable to fully trace the byte-level layout of `BuiltPackage::extract_metadata`/`extract_code` in `aptos-move/framework/src/built_package.rs` due to index truncation of that file's content, but the CLI command flow and the `CachedPackageMetadata::verify` implementation are both directly confirmed in the excerpts above, which is sufficient to establish the root cause: `verify-package` does not fetch or compare bytecode despite its documented purpose.)

    public fun publish_package(owner: &signer, pack: PackageMetadata, code: vector<vector<u8>>) acquires PackageRegistry {
        // Disallow incompatible upgrade mode. Governance can decide later if this should be reconsidered.
        assert!(
            pack.upgrade_policy.policy > upgrade_policy_arbitrary().policy,
            error::invalid_argument(EINCOMPATIBLE_POLICY_DISABLED),
        );

        let addr = signer::address_of(owner);
        if (!exists<PackageRegistry>(addr)) {
            move_to(owner, PackageRegistry { packages: vector::empty() })
        };

        // Checks for valid dependencies to other packages
        let allowed_deps = check_dependencies(addr, &pack);

        // Check package against conflicts
        // To avoid prover compiler error on spec
        // the package need to be an immutable variable
        let module_names = get_module_names(&pack);

        // Record, per module in this package, the object's transitive root owner at (re)publish, so
        // lazy self-init can detect a later transfer of the object or an ancestor since that module
        // was published (see `init::internal_maybe_initialize`). Objects only; feature-gated.
        if (features::is_lazy_module_initialization_enabled() && object::is_object(addr)) {
            let owner = object::address_to_object<object::ObjectCore>(addr).root_owner();
            module_names.for_each_ref(|name| {
                init::record_deploy_owner(addr, *name.bytes(), owner);
            });
        };
        let package_immutable = &borrow_global<PackageRegistry>(addr).packages;
        let len = package_immutable.length();
        let index = len;
        let upgrade_number = 0;
        package_immutable.enumerate_ref(|i, old| {
            let old: &PackageMetadata = old;
            if (old.name == pack.name) {
                upgrade_number = old.upgrade_number + 1;
                check_upgradability(old, &pack, &module_names);
                index = i;
            } else {
                check_coexistence(old, &module_names)
            };
        });

        // Assign the upgrade counter.
        pack.upgrade_number = upgrade_number;

        let packages = &mut borrow_global_mut<PackageRegistry>(addr).packages;
        // Update registry
        let policy = pack.upgrade_policy;
        if (index < len) {
            pack.modules.for_each_ref(|m| {
                let m: &ModuleMetadata = m;
                init::reset_initialized(addr, *m.name.bytes());
            });
            *packages.borrow_mut(index) = pack
        } else {
            packages.push_back(pack)
        };

        event::emit(PublishPackage {
            code_address: addr,
            is_upgrade: upgrade_number > 0
        });

        // Request publish
        if (features::code_dependency_check_enabled())
            request_publish_with_allowed_deps(addr, module_names, allowed_deps, code, policy.policy)
        else
        // The new `request_publish_with_allowed_deps` has not yet rolled out, so call downwards
        // compatible code.
            request_publish(addr, module_names, code, policy.policy)
    }

    pub fn verify(&self, package_metadata: &PackageMetadata) -> anyhow::Result<()> {
        let self_metadata = self.metadata;

        if self_metadata.name != package_metadata.name {
            bail!(
                "Package name doesn't match {} : {}",
                package_metadata.name,
                self_metadata.name
            )
        } else if self_metadata.deps != package_metadata.deps {
            bail!(
                "Dependencies don't match {:?} : {:?}",
                package_metadata.deps,
                self_metadata.deps
            )
        } else if self_metadata.modules != package_metadata.modules {
            bail!(
                "Modules don't match {:?} : {:?}",
                package_metadata.modules,
                self_metadata.modules
            )
        } else if self_metadata.manifest != package_metadata.manifest {
            bail!(
                "Manifest doesn't match {:?} : {:?}",
                package_metadata.manifest,
                self_metadata.manifest
            )
        } else if self_metadata.upgrade_policy != package_metadata.upgrade_policy {
            bail!(
                "Upgrade policy doesn't match {:?} : {:?}",
                package_metadata.upgrade_policy,
                self_metadata.upgrade_policy
            )
        } else if self_metadata.extension != package_metadata.extension {
            bail!(
                "Extensions doesn't match {:?} : {:?}",
                package_metadata.extension,
                self_metadata.extension
            )
        } else if self_metadata.source_digest != package_metadata.source_digest {
            bail!(
                "Source digests doesn't match {:?} : {:?}",
                package_metadata.source_digest,
                self_metadata.source_digest
            )
        }

        Ok(())
    }
