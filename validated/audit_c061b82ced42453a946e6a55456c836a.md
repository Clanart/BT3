### Title
Payout OP_RETURN operator attribution is not authenticated, allowing anyone to frame an operator into an unfunded reimbursement claim - ([File: core/src/verifier.rs])

### Summary
`update_finalized_payouts` derives `withdrawals.payout_payer_operator_xonly_pk` purely from a parsed OP_RETURN push in the mined payout transaction [1](#0-0) , and `create_payout_txhandler` signs the withdrawal input with `SIGHASH_SINGLE|ANYONECANPAY`, which never authenticates that OP_RETURN output or any other inputs of the final broadcast transaction [2](#0-1) . Because the withdrawal UTXO is owned and signed by the withdrawing user (the "attacker" in this threat model), that user can construct and broadcast the completed payout transaction themselves — funding output 0 however they like and writing an arbitrary registered operator's x-only pubkey into the OP_RETURN — without any operator ever being involved.

### Finding Description
The claimed binding is: `withdrawals.payout_payer_operator_xonly_pk == xonly_pk of the operator whose wallet actually funded the payout output`. Tracing the code shows this binding is never enforced.

- `Operator::withdraw` (core/src/operator.rs:560-675) is only the *convenience path* an honest operator uses: it calls `fund_raw_transaction` to add its own inputs, verifies the user's signature with `SECP.verify_schnorr` [3](#0-2) , and includes `operator_xonly_pk` in the OP_RETURN via `create_payout_txhandler` [4](#0-3) . Nothing about this path is enforced on-chain.
- The withdrawal-UTXO signature uses `SinglePlusAnyoneCanPay` (`txhandler.set_p2tr_key_spend_witness`), which by BIP-341/BIP-118 semantics commits only to the *single* corresponding output (output 0, the user payout) and the *single* signed input. It leaves every other input and output — including the OP_RETURN operator-attribution output — completely unconstrained. Anyone possessing that signature (trivially the withdrawing user themselves, since they own the private key of the withdrawal UTXO they registered via Citrea `withdraw()`) can assemble and broadcast a different, valid transaction: same signed input/output-0, arbitrary additional funding inputs (their own), and an OP_RETURN containing any 32 bytes, including a real, uninvolved operator's x-only pubkey, or no OP_RETURN at all.
- When this transaction confirms, `update_finalized_payouts` in `core/src/verifier.rs` (2283-2353) scans the mined block, extracts the first OP_RETURN via `get_first_op_return_output`/`parse_op_return_data`, and if it parses as a valid x-only pubkey, stores it verbatim as `payout_payer_operator_xonly_pk` for that withdrawal index via `update_payout_txs_and_payer_operator_xonly_pk` [5](#0-4)  — with **no check that this pubkey corresponds to whoever actually funded/broadcast the transaction**.
- Downstream, `PayoutCheckerTask::run_once` fetches "the first unhandled payout" filtered by the victim operator's own xonly pubkey (`get_first_unhandled_payout_by_operator_xonly_pk`) [6](#0-5)  and unconditionally calls `Operator::handle_finalized_payout`, which starts the kickoff/reimbursement flow for a withdrawal that operator never funded.
- The only defense against a fraudulent attribution is `Verifier::is_kickoff_malicious` (core/src/verifier.rs:1859-1915), which checks (a) the OP_RETURN pubkey equals `kickoff_data.operator_xonly_pk`, and (b) the committed payout blockhash in the kickoff witness matches the real on-chain payout blockhash. Both checks trivially pass in this attack because the attacker wrote the real victim operator's own pubkey into the OP_RETURN and the payout tx really did confirm at that blockhash — the check never verifies that the operator (its wallet, its signature, its funding inputs) actually participated in creating the payout.
- `create_reimburse_txhandler`'s bridge-value-releasing inputs (`Reimburse1`/`Reimburse2` — N-of-N signatures over the `MoveToVaultTx` deposit output and the kickoff's `ReimburseInKickoff` output) are presigned once at deposit time per (deposit, operator, round, kickoff index) [7](#0-6)  and are entirely independent of whether that operator ever broadcast a valid payout — they only require the kickoff to go unchallenged. Since `is_kickoff_malicious` does not detect the forged attribution, the framed operator's kickoff is never challenged, and the presigned `Reimburse` tx will eventually spend the deposit's `MoveToVaultTx` output, releasing `bridge_amount` BTC from the vault to the framed/unwitting operator, for a payout that operator never funded.

Existing guards that were checked and do **not** close this gap: `SECP.verify_schnorr` (only authenticates output 0/input 0, not the OP_RETURN), `Verifier::is_kickoff_malicious` (checks pubkey equality and blockhash consistency, not actual funding provenance), `verify_storage_proofs`/`SPV::verify`/`lc_proof_verifier` in the bridge circuit (these only prove the payout tx exists and its outpoint matches the Citrea withdrawal outpoint — they read and re-trust the very same forgeable OP_RETURN via `get_first_op_return_output`/`parse_op_return_data` in `circuits-lib/src/bridge_circuit/mod.rs:206-229`), and `Operator::is_profitable` (only enforced client-side inside the operator's own optional `withdraw()` RPC path, never enforced on-chain or during `update_finalized_payouts`).

### Impact Explanation
This directly matches the Critical category "BTC leaving a move-to-vault UTXO without a matching fronted withdrawal, an operator reimbursed for a payout it never funded." An unprivileged withdrawing user, without ever calling any operator's `Withdraw`/`InternalWithdraw` gRPC, can self-fund (or minimally fund) their own payout transaction, insert an arbitrary honest operator's x-only pubkey into the mandatory OP_RETURN, and cause that operator's automation to be credited with, and eventually reimbursed for, a withdrawal it never paid for. This releases `bridge_amount` real BTC from the deposit's `MoveToVaultTx` output through the presigned `Reimburse` transaction chain, breaking the bridge's fundamental value-conservation invariant (every reimbursement must correspond to a payout genuinely fronted by the reimbursed operator). The attack is repeatable per withdrawal and can target any currently active/registered operator; it does not require verifier, operator, aggregator, or Citrea privileges, and it bypasses the operator's own `is_profitable` gate entirely because the attacker never uses the operator's RPC path at all.

### Likelihood Explanation
Preconditions: attacker must register a normal Citrea withdrawal (own the withdrawal UTXO key, standard user capability), sign the payout input with `SinglePlusAnyoneCanPay` (they hold the key, so trivial), self-fund the rest of the transaction with any additional inputs (their own BTC, cost bounded by fees + whatever output value they choose), and pick any target operator's known/public x-only pubkey for the OP_RETURN (operator pubkeys are public protocol data). No mainnet, no live Citrea, and no cooperation from any privileged party is required — this is fully reproducible in a regtest/unit-test environment using `create_payout_txhandler` directly with a forged/omitted OP_RETURN and asserting the resulting stored attribution. Given the low attacker cost (just broadcasting a Bitcoin transaction) and complete lack of an authenticity check on the OP_RETURN, this is highly feasible and repeatable across every deposit/withdrawal and every operator in the system.

### Recommendation
Bind the OP_RETURN operator attribution to the actual payout funder cryptographically, not just by reading an unauthenticated data push:
- Require the operator to prove control of the funding inputs (e.g., require a signature over the full payout transaction — including the OP_RETURN output — from the operator's known xonly pubkey, and verify that signature during `update_finalized_payouts` before trusting the OP_RETURN value), or
- Have `is_kickoff_malicious` additionally verify that at least one of the payout transaction's other inputs' `script_pubkey`/spend corresponds to the claimed operator's registered address/key (i.e., verify actual fund provenance), or
- Redesign the withdrawal-authorization signature to cover the entire transaction (e.g. `SIGHASH_ALL` variant with an operator co-signature over the OP_RETURN) so the OP_RETURN cannot be substituted without operator consent.

pub fn create_reimburse_txhandler(
    move_txhandler: &TxHandler,
    round_txhandler: &TxHandler,
    kickoff_txhandler: &TxHandler,
    kickoff_idx: usize,
    paramset: &'static ProtocolParamset,
    operator_reimbursement_address: &bitcoin::Address,
) -> Result<TxHandler, BridgeError> {
    let builder = TxHandlerBuilder::new(TransactionType::Reimburse)
        .with_version(NON_STANDARD_V3)
        .add_input(
            NormalSignatureKind::Reimburse1,
            move_txhandler.get_spendable_output(UtxoVout::DepositInMove)?,
            builder::script::SpendPath::ScriptSpend(0),
            DEFAULT_SEQUENCE,
        )
        .add_input(
            NormalSignatureKind::Reimburse2,
            kickoff_txhandler.get_spendable_output(UtxoVout::ReimburseInKickoff)?,
            builder::script::SpendPath::ScriptSpend(0),
            DEFAULT_SEQUENCE,
        )
        .add_input(
            NormalSignatureKind::OperatorSighashDefault,
            round_txhandler.get_spendable_output(UtxoVout::ReimburseInRound(
                kickoff_idx,
                paramset.num_kickoffs_per_round,
            ))?,
            builder::script::SpendPath::KeySpend,
            DEFAULT_SEQUENCE,
        );

    Ok(builder
        .add_output(UnspentTxOut::from_partial(TxOut {
            value: move_txhandler
                .get_spendable_output(UtxoVout::DepositInMove)?
                .get_prevout()
                .value,
            script_pubkey: operator_reimbursement_address.script_pubkey(),
        }))
        .add_output(UnspentTxOut::from_partial(
            builder::transaction::anchor_output(paramset.anchor_amount()),
        ))
        .finalize())
}

pub fn create_payout_txhandler(
    input_utxo: UTXO,
    output_txout: TxOut,
    operator_xonly_pk: XOnlyPublicKey,
    user_sig: taproot::Signature,
    _network: bitcoin::Network,
) -> Result<TxHandler<Signed>, BridgeError> {
    let txin = SpendableTxIn::new_partial(input_utxo.outpoint, input_utxo.txout);

    let output_txout = UnspentTxOut::from_partial(output_txout.clone());

    let op_return_txout = op_return_txout(PushBytesBuf::from(operator_xonly_pk.serialize()));

    let mut txhandler = TxHandlerBuilder::new(TransactionType::Payout)
        .with_version(NON_STANDARD_V3)
        .add_input(
            NormalSignatureKind::NotStored,
            txin,
            SpendPath::KeySpend,
            DEFAULT_SEQUENCE,
        )
        .add_output(output_txout)
        .add_output(UnspentTxOut::from_partial(anchor_output(
            NON_EPHEMERAL_ANCHOR_AMOUNT,
        )))
        .add_output(UnspentTxOut::from_partial(op_return_txout))
        .finalize();
    txhandler.set_p2tr_key_spend_witness(&user_sig, 0)?;
    txhandler.promote()
}

    /// Sets the given payout txs' txid and operator index for the given index.
    pub async fn update_payout_txs_and_payer_operator_xonly_pk(
        &self,
        tx: Option<DatabaseTransaction<'_>>,
        payout_txs_and_payer_operator_xonly_pk: Vec<(
            u32,
            Txid,
            Option<XOnlyPublicKey>,
            bitcoin::BlockHash,
        )>,
    ) -> Result<(), BridgeError> {
        if payout_txs_and_payer_operator_xonly_pk.is_empty() {
            return Ok(());
        }
        // Convert all values first, propagating any errors
        let converted_values: Result<Vec<_>, BridgeError> = payout_txs_and_payer_operator_xonly_pk
            .iter()
            .map(|(idx, txid, operator_xonly_pk, block_hash)| {
                Ok((
                    i32::try_from(*idx).wrap_err("Failed to convert payout index to i32")?,
                    TxidDB(*txid),
                    operator_xonly_pk.map(XOnlyPublicKeyDB),
                    BlockHashDB(*block_hash),
                ))
            })
            .collect();
        let converted_values = converted_values?;

        let mut query_builder = QueryBuilder::new(
            "UPDATE withdrawals AS w SET
                payout_txid = c.payout_txid,
                payout_payer_operator_xonly_pk = c.payout_payer_operator_xonly_pk,
                payout_tx_blockhash = c.payout_tx_blockhash
                FROM (",
        );

        query_builder.push_values(
            converted_values.into_iter(),
            |mut b, (idx, txid, operator_xonly_pk, block_hash)| {
                b.push_bind(idx)
                    .push_bind(txid)
                    .push_bind(operator_xonly_pk)
                    .push_bind(block_hash);
            },
        );

        query_builder
            .push(") AS c(idx, payout_txid, payout_payer_operator_xonly_pk, payout_tx_blockhash) WHERE w.idx = c.idx");

        let query = query_builder.build();
        execute_query_with_tx!(self.connection, tx, query, execute)?;

        Ok(())
    }
