## Analysis

The external report's core pattern — a privileged/user-supplied address parameter that is never checked against `address(0)`, leading to funds being irrecoverably locked/lost — has a direct analog in the IntentGateway V2 escrow-release path.

### Title
Missing zero-address check on native-token escrow release lets user/solver-controlled `beneficiary` permanently burn escrowed native funds - ([File: evm/src/apps/intentsv2/IntentsBase.sol])

### Summary
`IntentsBase._withdraw`, the function that releases escrowed order funds to a beneficiary on both the `RedeemEscrow` (fill) and `RefundEscrow` (cancel/refund) code paths, decodes `beneficiary` from a `bytes32` order field and never validates it against `address(0)` before moving native-token escrow. [1](#0-0) 

### Finding Description
`_withdraw` computes `address beneficiary = address(uint160(uint256(body.beneficiary)))` and then, for each escrowed token, either does a low-level native `.call{value: amount}("")` to `beneficiary` or an ERC20 `safeTransfer`. [2](#0-1) 

There is an asymmetry here: OpenZeppelin's ERC20 `transfer`/`safeTransfer` reverts on a zero-address recipient, so the ERC20 branch is implicitly protected. The native-token branch (`token == address(0)`) is not — a raw `.call{value: amount}("")` to `address(0)` succeeds and permanently burns the funds, since `address(0)` has no code and no owner. [3](#0-2) 

`beneficiary` on the `RefundEscrow` path is `order.user`, a `bytes32` field fully controlled by whoever constructs the order at `placeOrder` time (no code path I found in the base contracts rejects `order.user == bytes32(0)`). On the `RedeemEscrow` path, `beneficiary` is `msg.sender` recorded at fill time in `_fillCrossChain`/`_fillSameChain`, which cannot naturally be zero, so the exploitable path is via `order.user`. [4](#0-3) 

The identical missing-check pattern also exists in the standalone (non-abstract) `withdraw` implementation used on the Tron deployment, confirming this is a structural gap rather than a one-off oversight. [5](#0-4) 

### Impact Explanation
This falls squarely under "loss of funds" in the accepted impact list: native-token escrow that should be refunded/released to a user is instead sent to `address(0)` and permanently destroyed, with no revert, no error, and no recovery path — the escrow accounting (`_orders[commitment][token] -= amount`) is decremented as if the transfer succeeded. [6](#0-5) 

### Likelihood Explanation
Reachable without any privileged role, relayer collusion, or malformed proof: any user who constructs an order (or a client/SDK misconfiguration that leaves `order.user` at its zero-value default) with `user = bytes32(0)` and pays in native token can trigger this on refund/cancel. It requires no admin, no governance actor, and no compromised infrastructure — matching the report's "accidentally left blank input address" bug class exactly, but manifesting as fund destruction rather than a lock.

### Recommendation
In `IntentsBase._withdraw` (and its Tron counterpart), add a check that `beneficiary != address(0)` before performing either the native-token `.call` or the ERC20 `safeTransfer`, and revert (e.g., with a new `InvalidBeneficiary` error) rather than silently succeeding. Additionally, validate `order.user != bytes32(0)` at order-placement/dispatch time so malformed orders cannot enter escrow in the first place.

### Proof of Concept
1. User calls `placeOrder` with `order.user = bytes32(0)` and native-token inputs escrowed (`token == address(0)`).
2. After the deadline, anyone (or the user themself) triggers cancellation (`_cancelFromDest`/`_cancelFromSource`), which dispatches a `RefundEscrow` message with `beneficiary: order.user` (i.e., `bytes32(0)`). [7](#0-6) 
3. On the source chain, `onAccept` authenticates the source module and calls `_withdraw(body, true, true)`. [8](#0-7) 
4. `_withdraw` computes `beneficiary = address(0)`, and for the native-token entry executes `address(0).call{value: amount}("")`, which succeeds trivially — escrowed native funds are burned instead of returned to the rightful owner. [9](#0-8)

    function _withdraw(WithdrawalRequest memory body, bool isRefund, bool finalize) internal {
        address beneficiary = address(uint160(uint256(body.beneficiary)));
        if (finalize) _filled[body.commitment] = beneficiary;

        uint256 len = body.tokens.length;
        for (uint256 i; i < len; i++) {
            address token = address(uint160(uint256(body.tokens[i].token)));
            uint256 amount = body.tokens[i].amount;
            if (amount == 0) continue;

            uint256 escrowed = _orders[body.commitment][token];
            if (escrowed == 0) revert UnknownOrder();

            _orders[body.commitment][token] = escrowed - amount;
            if (token == address(0)) {
                (bool sent,) = beneficiary.call{value: amount}("");
                if (!sent) revert InsufficientNativeToken();
            } else {
                IERC20(token).safeTransfer(beneficiary, amount);
            }
        }

    function _cancelFromDest(Order calldata order, CancelOptions calldata options, bytes32 commitment) internal {
        if (order.deadline >= _blockNumber()) {
            if (order.user != bytes32(uint256(uint160(msg.sender)))) revert Unauthorized();
        }

        _filled[commitment] = address(uint160(uint256(order.user)));

        bytes memory body = bytes.concat(
            bytes1(uint8(RequestKind.RefundEscrow)),
            abi.encode(WithdrawalRequest({commitment: commitment, tokens: order.inputs, beneficiary: order.user}))
        );

        DispatchPost memory request = DispatchPost({
            dest: order.source,
            to: abi.encodePacked(_instance(order.source)),
            body: body,
            timeout: 0,
            fee: options.relayerFee,
            payer: msg.sender
        });

        address beneficiary = address(uint160(uint256(body.beneficiary)));
        _filled[body.commitment] = beneficiary;

        // redeem escrowed tokens
        uint256 len = body.tokens.length;
        for (uint256 i; i < len;) {
            address token = address(uint160(uint256(body.tokens[i].token)));
            uint256 amount = body.tokens[i].amount;

            if (token == address(0)) {
                (bool sent,) = beneficiary.call{value: amount}("");
                if (!sent) revert InsufficientNativeToken();
            } else {
                (bool success,) = token.call(abi.encodeWithSelector(IERC20.transfer.selector, beneficiary, amount));
                if (!success) revert TransferFailed();
            }

                ++i;
            }
        }
