### Title
Permissionless `donateRewards` combined with live-balance `totalStaked()` allows flash-stake reward sniping / unfair reward-per-token dilution - ([File: rewards/BaseRewardPool.sol])

### Summary
`BaseRewardPool.donateRewards()` (and the equivalent in `BaseRewardPoolV2.sol` / `vlMGPBaseRewarder.sol`) is callable by **any address**, with the only precondition being that the reward token is already registered. It funnels straight into `_provisionReward`, which recalculates the global `rewardPerTokenStored` accumulator using the **instantaneous** result of `totalStaked()` — a value that is simply the live token balance held by `MasterMagpie` (`stakingToken.balanceOf(operator)`), fully controllable by depositing/withdrawing in the same block. This mirrors the USDs root cause: a global per-token accounting value gets recomputed from a balance that an ordinary caller can move immediately before/after the recalculation, letting them extract value that legitimate long-term stakers should have received. ### Finding Description
`rewardPerTokenStored` is Magpie's analog of Sperax's `rebasingCreditsPerToken` — a single global ratio used to compute every account's `earned()` balance: [3](#0-2) 

It is only updated in `_provisionReward`, and the increment is `(_amountReward * 10**decimals) / totalStaked()`, where `totalStaked()` reads the live receipt-token balance held by `MasterMagpie`: [4](#0-3) 

`totalStaked()` is not a snapshot — it changes the moment anyone calls `MasterMagpie.deposit`/`withdraw`, which have no cooldown, no time-lock, and are freely composable in the same transaction: [5](#0-4) [6](#0-5) 

Because `donateRewards` has no access control beyond `isRewardToken[_rewardToken]` (already true for the pool's primary reward token from construction), any wallet can atomically:
1. Deposit a large amount of the pool's staking/receipt token into `MasterMagpie` (inflating `totalStaked()`), which sets the attacker's own `userRewardPerTokenPaid` to the *pre-donation* `rewardPerToken`.
2. Call `donateRewards()` themselves (or simply time the call to land right after someone else's donation/queueNewRewards), so the newly added `rewardPerTokenStored` increment is computed while the attacker's inflated stake is part of the denominator.
3. Immediately withdraw, which triggers `_harvestBaseRewarder`/`getReward`, paying the attacker a share of the just-donated reward proportional to their momentary (flash) stake — even though they held that stake for a single block/transaction.

This lets the attacker capture a disproportionate share of rewards that honest, long-term stakers should receive, directly diluting/misappropriating unclaimed yield. The reverse manipulation (withdrawing right before triggering `donateRewards`) shrinks the denominator and can be used to grief the increment applied for that round, again distorting fair proportional distribution the accounting is supposed to guarantee.

### Impact Explanation
This is a direct theft of unclaimed yield from legitimate stakers: an attacker with no real economic exposure to the pool (holding the staking/receipt token for only the duration of one transaction) can siphon reward tokens that should accrue to genuine, time-weighted stakers. Because `donateRewards` is unauthenticated, this requires no privileged role and is reachable purely by an ordinary wallet interacting with `MasterMagpie` and `BaseRewardPool`.

### Likelihood Explanation
`donateRewards()` has no access control and no minimum-hold/cooldown mechanism exists in `MasterMagpie.deposit`/`withdraw`, so the attack is executable in a single atomic transaction (or via a same-block deposit → donate → withdraw sequence) using only capital the attacker can source (e.g., large receipt-token holdings or capital borrowed against the LP/receipt token). No governance, oracle, or admin interaction is required.

### Recommendation
- Restrict `donateRewards` (and any reward-provisioning entry point) so `rewardPerTokenStored` updates use a time-weighted or snapshotted `totalStaked()` rather than the instantaneous balance, or add a minimum stake-duration/checkpoint before a deposit counts toward reward-per-token calculations.
- Alternatively, require `donateRewards` to be `onlyManager`-gated like `queueNewRewards`, and add reentrancy/same-block guards preventing deposit-then-withdraw within the same transaction/block for reward-earning purposes.

### Proof of Concept
1. Attacker observes (or triggers) a call to `donateRewards(amountReward, rewardToken)` on a `BaseRewardPool`.
2. In the same transaction: `MasterMagpie.deposit(stakingToken, largeAmount)` → `BaseRewardPool.donateRewards(amountReward, rewardToken)` → `MasterMagpie.withdraw(stakingToken, largeAmount)`.
3. During `withdraw`, `_harvestAndUnstake` → `_harvestBaseRewarder` calls `getReward`, which computes `earned()` using the now-updated `rewardPerTokenStored` and pays the attacker a share of `amountReward` proportional to `largeAmount / totalStaked()` at donation time, despite holding the stake for only the single transaction.     function _provisionReward(uint256 _amountReward, address _rewardToken) internal {
        IERC20(_rewardToken).safeTransferFrom(
            msg.sender,
            address(this),
            _amountReward
        );
        Reward storage rewardInfo = rewards[_rewardToken];
        rewardInfo.historicalRewards =
            rewardInfo.historicalRewards +
            _amountReward;
        if (this.totalStaked() == 0) {
            rewardInfo.queuedRewards += _amountReward;
        } else {
            if (rewardInfo.queuedRewards > 0) {
                _amountReward += rewardInfo.queuedRewards;
                rewardInfo.queuedRewards = 0;
            }
            rewardInfo.rewardPerTokenStored =
                rewardInfo.rewardPerTokenStored +
                (_amountReward * 10**stakingDecimals()) /
                this.totalStaked();
        }
        emit RewardAdded(_amountReward, _rewardToken);
    }

    function _harvestAndUnstake(address _stakingToken, address _account, uint256 _amount, bool _isVlMgp) internal {
        updatePool(_stakingToken);

        UserInfo storage user = userInfo[_stakingToken][_account];

        if (!_isVlMgp && user.available < _amount)
            revert WithdrawAmountExceedsStaked();
        else if(user.amount < _amount && _isVlMgp)
            revert UnlockAmountExceedsLocked();
        
        _harvestMGP(_stakingToken, _account);
        _harvestBaseRewarder(_stakingToken, _account);
