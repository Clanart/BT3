### Title
Untrusted `ReceivedOutput` bytes accepted without binding the offset, script_pubkey, or outpoint to the scanner key — fabricated/unspendable outputs reported as received funds - (File: networks/bitcoin/src/wallet/mod.rs)

### Summary
`ReceivedOutput::read` deserializes an HDKD scalar `offset`, a `TxOut`, and an `OutPoint` directly from untrusted bytes and performs zero validation: it never checks that `output.script_pubkey` is a registered script for the scanner's key under `offset`, nor that the output is even a Serai-payable P2TR output. Analogous to the `tomato` `/api/exec` sink that executes unvalidated input, this is an unvalidated-input sink where attacker-controlled bytes are interpreted as a "received, spendable output" directive by downstream wallet/signing code. [1](#0-0) 

### Finding Description
`Scanner::scan_transaction` constructs `ReceivedOutput` only after matching `output.script_pubkey` against `self.scripts`, so outputs discovered on-chain are correctly bound to an offset (script → offset map). [2](#0-1)  However, `ReceivedOutput::read` — the deserialization path used when outputs arrive as untrusted bytes — skips this binding entirely. It reads `offset` via `Secp256k1::read_F` and then `TxOut`/`OutPoint` via `consensus_decode`, accepting any combination. [1](#0-0) 

Two distinct injections result:

1. **Unspendable output reported as received.** Attacker supplies a `ReceivedOutput` whose `TxOut` pays to an arbitrary (attacker-controlled or garbage) `script_pubkey`, paired with any offset and a fabricated `OutPoint`. Nothing verifies `p2tr_script_buf(key + G*offset) == output.script_pubkey`, which is the exact relation `register_offset`/`scan_transaction` enforce on the honest path. [3](#0-2) 
2. **Wrong offset for a real output.** Attacker supplies a real on-chain `TxOut`/`OutPoint` paying to the group key, but with a different `offset`. The wallet will attempt to spend it under `key + offset`, producing an invalid BIP-340 signature path — funds effectively burned/reported but not spendable.

This is exacerbated by `register_offset`'s documented surjectivity (offsets incremented until even, collisions return `None`), meaning offset/script binding is already non-bijective on the honest path and cannot be re-derived by the reader. [4](#0-3) 

### Impact Explanation
Any downstream code that consumes deserialized `ReceivedOutput`s as inputs to a spend plan or balance accounting treats attacker bytes as ground truth. Consequences: (a) funds reported received that are not spendable — a fabricated or mis-offset output inflates apparent received value and can enter a spend plan, causing signing of a transaction that spends a nonexistent/unspendable input or fails outright; (b) an attacker can inject outputs paying to themselves as if they were Serai-owned, corrupting the input set the threshold group signs over.

### Likelihood Explanation
Reachability requires attacker-controlled bytes reaching `ReceivedOutput::read` (listed in scope as an intended untrusted-input surface). The scan path is safe; the vulnerability is confined to the `read` path, so likelihood hinges on whether deserialized (rather than freshly scanned) outputs flow into spend decisions. Since `ReceivedOutput` exposes `serialize`/`read` as its persistence/transport format, any peer- or storage-supplied blob is a viable injection vector.

### Recommendation
Add a verification step: `ReceivedOutput::read` should take the scanner's base `key` (or the `Scanner` itself) and reject outputs where `output.script_pubkey != p2tr_script_buf(key + G*offset)` or where the offset isn't a registered script. Alternatively, re-verify every deserialized `ReceivedOutput` against `Scanner::scripts` before use in plan construction, and treat the outpoint's on-chain existence as unverified until confirmed by scan.

### Proof of Concept
```rust
// Attacker crafts bytes: offset = 1, TxOut paying to attacker's own script,
// arbitrary outpoint
let offset = Scalar::ONE;
let evil_output = TxOut {
  value: Amount::from_sat(100_000),
  script_pubkey: attacker_p2tr_script, // pays to attacker, not Serai
};
let fake_outpoint = OutPoint::new(real_txid, 0);

let mut buf = offset.to_bytes().to_vec();
buf.extend(serialize(&evil_output));
buf.extend(serialize(&fake_outpoint));

// Accepted unconditionally: no binding of offset -> script_pubkey -> key
let injected = ReceivedOutput::read(&mut buf.as_slice()).unwrap();
// Downstream code now treats `injected` as a received, spendable output.
```

    let offset = Secp256k1::read_F(r)?;
    let output;

  pub fn register_offset(&mut self, mut offset: Scalar) -> Option<Scalar> {
    // This loop will terminate as soon as an even point is found, with any point having a ~50%
    // chance of being even
    // That means this should terminate within a very small amount of iterations
    loop {
      match p2tr_script_buf(self.key + (ProjectivePoint::GENERATOR * offset)) {
        Some(script) => {
          if self.scripts.contains_key(&script) {
            None?;
          }
          self.scripts.insert(script, offset);
          return Some(offset);
        }
        None => offset += Scalar::ONE,
      }
    }
  }
