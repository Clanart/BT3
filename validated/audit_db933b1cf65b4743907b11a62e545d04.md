## Title
Unhandled `IndexError`/`UnboundLocalError` in `is_atom_canonical()` on truncated CLVM atom header — potential mempool-validation crash from a submitted spend bundle (`chia/full_node/mempool_manager.py`)

### Summary
`is_atom_canonical()` decodes a CLVM atom's variable-length size prefix (1–6 bytes) directly by indexing raw `bytes` at an unchecked `offset`, with no bound check against `len(clvm_buffer)`, mirroring the class of bug in CVE-2019-14370 (`Exiv2::MrwImage::readMetadata()`), where a hand-written length-prefixed metadata parser reads past the end of the buffer.

### Finding Description
`is_atom_canonical(clvm_buffer, offset)` reads `b = clvm_buffer[offset]` and, based on the top bits of `b`, decides how many extra prefix bytes (`prefix_len`, up to 5) encode the atom length. It then loops `prefix_len` times, incrementing `offset` and indexing `clvm_buffer[offset]` again with no check that `offset < len(clvm_buffer)`: [1](#0-0) 

This function is invoked from `is_clvm_canonical()`, the second, independent hand-rolled CLVM-format walker used purely to decide canonicality (not the Rust deserializer): [2](#0-1) 

`is_clvm_canonical()` is called directly on raw `puzzle_reveal`/`solution` bytes from every coin spend in a submitted spend bundle, inside `MempoolManager.validate_spend_bundle()`: [3](#0-2) 

This runs on the async blockchain-lock-holding admission path (`validate_spend_bundle`), not inside the sandboxed process-pool CLVM execution (`pre_validate_spendbundle` → `validate_clvm_and_signature` [Rust]) that already validated the buffer parses as CLVM.

The theoretical risk is that if this Python-level walker's atom-length categorization can diverge from the Rust CLVM deserializer's rules (e.g., through an edge case at the boundary between prefix-length categories, or by reaching a byte such as `0xFE`/`0xFF` in a state this function doesn't expect), `offset` could be advanced past the true end of `clvm_buffer`, causing `clvm_buffer[offset]` to raise `IndexError` — or, for a byte value that satisfies none of the `elif` branches, an `UnboundLocalError` on the undefined `mask`/`prefix_len` variable. Note: because Python `bytes` indexing is bounds-checked, this manifests as an unhandled exception rather than a C-style memory-safety violation reading adjacent heap memory as in the original Exiv2 CVE.

### Impact Explanation
I could **not** find a byte sequence that both (a) parses successfully as valid CLVM under the same byte-format rules used by `chia_rs`'s Rust deserializer (a prerequisite for `is_clvm_canonical` to even be reached with that buffer, since `validate_clvm_and_signature` runs first and would reject any buffer that isn't valid, in-bounds CLVM) and (b) causes `is_atom_canonical`'s independent bit-pattern decoding to run past the buffer end. The bit masks used in `is_atom_canonical` (`0b10xxxxxx`, `0b110xxxxx`, `0b1110xxxx`, `0b11110xxx`, `0b111110xx`, `0b1111110x`) mirror the standard CLVM atom-length prefix format, so for any buffer that is already a validly-parsed CLVM program, the same prefix-length decoding should stay in bounds by construction. I was not able to construct or confirm a concrete divergent case (e.g., involving the `0xFE` back-reference byte, which `is_clvm_canonical` special-cases *before* calling `is_atom_canonical`, so `is_atom_canonical` should never see it through that call path).

Given this uncertainty, I cannot confirm a reachable, concrete out-of-bounds/DoS trigger through this function for the required threat model (single unprivileged spend-bundle submitter). The impact of an unhandled exception here, if triggered, would only be a possible crash of the coroutine handling `add_spend_bundle`/`validate_spend_bundle` (a processing-halt-style DoS), not any of the required "concrete unsigned/unauthorized coin movement, supply inflation, forged asset identity, offer-theft, coin-set divergence, or invalid spend/block acceptance" outcomes.

### Likelihood Explanation
Low-to-unproven. The function is only reached with buffers that already passed the Rust CLVM validator (`validate_clvm_and_signature`) in `pre_validate_spendbundle()`, which structurally prevents most malformed/truncated atom headers from ever reaching `is_clvm_canonical`/`is_atom_canonical`. No test in `chia/_tests/core/mempool/test_mempool_manager.py` (e.g. `test_atom_canonical`, `test_atom_not_canonical`, `test_clvm_not_canonical`, `test_mempool_requires_canonical_clvm`) demonstrates an out-of-bounds or exception case — all covered non-canonical cases are still within-bounds encodings that merely use more bytes than necessary.

### Recommendation
As defense-in-depth, add explicit bounds checks in `is_atom_canonical()` before each `clvm_buffer[offset]` access in the prefix-decoding loop (mirroring the bounds checks already present in the analogous `full_block_utils.py` `skip_bytes`/`skip_list` helpers, which raise `ValueError` with descriptive messages instead of relying on implicit Python `IndexError`s), and add an explicit `else: raise ValueError(...)` branch to the `if/elif` chain in case no mask/prefix_len pattern matches (covering `0xFE`/`0xFF` inputs defensively) rather than leaving `mask`/`prefix_len`/`min_value` potentially unbound.

### Proof of Concept
I was unable to construct a concrete proof-of-concept spend-bundle byte sequence that reaches `is_atom_canonical` with a truncated/out-of-range offset while still passing the prior Rust CLVM validation gate. This finding is reported with that caveat explicitly noted — I recommend a follow-up focused specifically on fuzzing `is_atom_canonical`/`is_clvm_canonical` against every byte sequence accepted by `chia_rs`'s CLVM deserializer (including back-reference-enabled generator encodings and any not-yet-covered edge bytes) to determine definitively whether a divergence exists.

def is_atom_canonical(clvm_buffer: bytes, offset: int) -> tuple[int, bool]:
    b = clvm_buffer[offset]
    if (b & 0b11000000) == 0b10000000:
        # 6 bits length prefix
        mask = 0b00111111
        prefix_len = 0
        min_value = 1
    elif (b & 0b11100000) == 0b11000000:
        # 5 + 8 bits length prefix
        mask = 0b00011111
        prefix_len = 1
        min_value = 1 << 6
    elif (b & 0b11110000) == 0b11100000:
        # 4 + 8 + 8 bits length prefix
        mask = 0b00001111
        prefix_len = 2
        min_value = 1 << (5 + 8)
    elif (b & 0b11111000) == 0b11110000:
        # 3 + 8 + 8 + 8 bits length prefix
        mask = 0b00000111
        prefix_len = 3
        min_value = 1 << (4 + 8 + 8)
    elif (b & 0b11111100) == 0b11111000:
        # 2 + 8 + 8 + 8 + 8 bits length prefix
        mask = 0b00000011
        prefix_len = 4
        min_value = 1 << (3 + 8 + 8 + 8)
    elif (b & 0b11111110) == 0b11111100:
        # 1 + 8 + 8 + 8 + 8 + 8 bits length prefix
        mask = 0b00000001
        prefix_len = 5
        min_value = 1 << (2 + 8 + 8 + 8 + 8)

    atom_len = b & mask
    for i in range(prefix_len):
        atom_len <<= 8
        offset += 1
        atom_len |= clvm_buffer[offset]

    return 1 + prefix_len + atom_len, atom_len >= min_value
```

def is_clvm_canonical(clvm_buffer: bytes) -> bool:
    """
    checks whether the CLVM serialization is all canonical representation.
    atoms can be serialized in more than one way by using more bytes than
    necessary to encode the length prefix. This functions ensures that all atoms are
    encoded with the shortest representation. back-references are not allowed
    and will make this function return false
    """
    assert clvm_buffer != b""

    offset = 0
    tokens_left = 1
    while True:
        b = clvm_buffer[offset]

        # pair
        if b == 0xFF:
            tokens_left += 1
            offset += 1
            continue

        # back references cannot be considered canonical, since they may be
        # encoded in many different ways
        if b == 0xFE:
            return False

        # small atom or NIL
        if b <= 0x80:
            tokens_left -= 1
            offset += 1
        else:
            atom_len, canonical = is_atom_canonical(clvm_buffer, offset)
            if not canonical:
                return False
            tokens_left -= 1
            offset += atom_len

        if tokens_left == 0:
            break

    # if there's garbage at the end, it's not canonical
    return offset == len(clvm_buffer)
```
