### Title
Unauthenticated `OP_RETURN` operator attribution lets anyone attribute a fronted payout to an operator who never funded it - (File: `core/src/verifier.rs`)

### Summary
The `payout_tx`'s claim of "which operator fronted this withdrawal" is derived purely from an unsigned `OP_RETURN` push in the broadcast Bitcoin transaction, with no cryptographic binding to the actual funding inputs of that transaction. Because the withdrawal input is signed by the user with `SinglePlusAnyoneCanPay`, *any* party can construct and broadcast a valid payout transaction (adding their own funding inputs) and place an arbitrary operator's x-only pubkey in the `OP_RETURN` output. The verifier's chain-scan (`update_finalized_payouts`) blindly records that pubkey as `payout_payer_operator_xonly_pk`, and each operator's own `PayoutCheckerTask` polls for "my unhandled payouts" by that column and automatically drives the kickoff/reimbursement flow for it.

### Finding Description
In `create_payout_txhandler` (`core/src/builder/transaction/operator_reimburse.rs:407-436`), the payout transaction's only authenticated component is the withdrawal input, signed by the user with `TapSighashType::SinglePlusAnyoneCanPay`: [1](#0-0) 

The `SinglePlusAnyoneCanPay` sighash type by design only commits to the single input+output pair; anyone possessing the signature (obtained via the `Withdraw`/`InternalWithdraw` gRPC parameters, or observable off-chain) can add other inputs/outputs freely, including an arbitrary `op_return_txout` containing any operator's x-only pubkey: [2](#0-1) 

When the verifier processes a finalized block, `update_finalized_payouts` extracts the operator attribution solely by parsing this unauthenticated `OP_RETURN` byte string — no signature, no linkage to whoever actually supplied the extra funding inputs of the transaction: [3](#0-2) 

This is persisted verbatim to the DB via `update_payout_txs_and_payer_operator_xonly_pk`: [4](#0-3) 

Every operator's background automation (`PayoutCheckerTask`) then queries `get_first_unhandled_payout_by_operator_xonly_pk` filtered by its *own* xonly pubkey, and if it finds an entry, automatically drives `handle_finalized_payout` → kickoff → eventual `Reimburse` tx, crediting itself with reimbursement for a withdrawal it never actually funded: [5](#0-4) [6](#0-5) 

The only consistency check performed later (`is_kickoff_malicious` in `core/src/verifier.rs`, and the equality check in `send_asserts` in `core/src/operator.rs`) merely re-confirms that the `payout_payer_operator_xonly_pk` column equals the pubkey of whoever sends the kickoff — it never verifies that the credited operator's own funds were actually spent in the payout transaction: [7](#0-6) [8](#0-7) 

**Binding broken:** the protocol's intended invariant is `party attributed as payer == party whose funds funded the payout output`. Because the attribution byte string in `OP_RETURN` is not signed by, or otherwise bound to, the party supplying the extra transaction inputs, an unprivileged party who fronts the withdrawal can write in an arbitrary operator's pubkey, breaking `credited operator == party that paid`.

### Impact Explanation
This maps to the Critical impact category "an operator reimbursed for a payout it never funded." An attacker (any observer who can obtain the user's `SinglePlusAnyoneCanPay` withdrawal signature and construct/broadcast the payout transaction with their own funding, e.g. a competing operator, a griefer, or a user's own delegate) can front a withdrawal themselves while stamping a *different*, legitimate operator's x-only pubkey into the `OP_RETURN`. That legitimate operator's own automation (`PayoutCheckerTask`) will then autonomously pursue the kickoff and reimbursement flow and extract the deposited BTC from the vault via the `Reimburse` transaction — money it never fronted to the user. This is a direct custody-binding break: the vaulted BTC leaves via reimbursement to an operator with no corresponding fronted withdrawal by that operator.

### Likelihood Explanation
The withdrawal input signature is `SinglePlusAnyoneCanPay` by design specifically to let any funder complete the payout transaction — this is intentional flexibility for operators, but nothing restricts who can exercise it or what they write to the unauthenticated `OP_RETURN` field. No verifier/operator/aggregator privilege is required to broadcast a valid payout transaction once the withdrawal signature is known (it is handed to operators off-chain per the code comments, and is also passed through public gRPC parameters/CLI in `WithdrawParams`); reachability by an unprivileged party is plausible and does not require compromising any keys or roles.

### Recommendation
Bind the `OP_RETURN` operator attribution cryptographically to the operator who is actually claiming reimbursement, e.g., by requiring the reimbursing operator to co-sign the payout transaction with the input they fund (rather than relying on unauthenticated `OP_RETURN` data), or by verifying on-chain that the credited operator's own UTXO(s) funded the payout output's value before recording `payout_payer_operator_xonly_pk`. Alternatively, require the operator to additionally sign a commitment (e.g., via Winternitz/kickoff pre-commit) proving they supplied the funding inputs, and reject the finalized-payout DB write if that proof is absent or mismatched.

### Proof of Concept
1. Attacker (any party, not an operator) obtains withdrawal id `W`'s `input_signature` (`SinglePlusAnyoneCanPay`) either from the Citrea request or from operators' shared off-chain channel.
2. Attacker builds a payout transaction using `create_payout_txhandler`-equivalent structure: withdrawal input + user output + anchor + `OP_RETURN` containing Operator B's (a legitimate, honest operator's) x-only pubkey — funding the transaction fee/output with the attacker's own wallet, not Operator B's.
3. Attacker broadcasts and confirms this transaction.
4. Verifier's `update_finalized_payouts` (`core/src/verifier.rs:2283-2353`) parses the `OP_RETURN`, extracts Operator B's pubkey, and writes `payout_payer_operator_xonly_pk = B` into `withdrawals` via `update_payout_txs_and_payer_operator_xonly_pk`.
5. Operator B's `PayoutCheckerTask` (`core/src/task/payout_checker.rs:39-111`) polls `get_first_unhandled_payout_by_operator_xonly_pk(B)`, finds the unhandled payout, and calls `handle_finalized_payout`, subsequently sending Round/Kickoff/ReadyToReimburse/Reimburse transactions.
6. Operator B receives the `Reimburse` output (the full deposited bridge amount) from the vault, despite never having spent funds to front withdrawal `W` — the attacker's funds (not B's) paid the user.

/// 2. OP_RETURN output (with operators x-only pubkey that fronts the peg-out)
///
/// # Arguments
/// * `input_utxo` - The input UTXO for the payout, committed in Citrea side, with the signature given to operators off-chain.
/// * `output_txout` - The output TxOut for the user payout.
/// * `operator_xonly_pk` - The operator's x-only public key that fronts the peg-out.
/// * `user_sig` - The user's signature for the payout, given to operators off-chain.
/// * `network` - The Bitcoin network.
///
/// # Returns
/// A [`TxHandler`] for the payout transaction, or a [`BridgeError`] if construction fails.
pub fn create_payout_txhandler(
    input_utxo: UTXO,
    output_txout: TxOut,
    operator_xonly_pk: XOnlyPublicKey,
    user_sig: taproot::Signature,
    _network: bitcoin::Network,
) -> Result<TxHandler<Signed>, BridgeError> {
    let txin = SpendableTxIn::new_partial(input_utxo.outpoint, input_utxo.txout);

    let output_txout = UnspentTxOut::from_partial(output_txout.clone());

    let op_return_txout = op_return_txout(PushBytesBuf::from(operator_xonly_pk.serialize()));

    let mut txhandler = TxHandlerBuilder::new(TransactionType::Payout)
        .with_version(NON_STANDARD_V3)
        .add_input(
            NormalSignatureKind::NotStored,
            txin,
            SpendPath::KeySpend,
            DEFAULT_SEQUENCE,
        )
        .add_output(output_txout)
        .add_output(UnspentTxOut::from_partial(anchor_output(
            NON_EPHEMERAL_ANCHOR_AMOUNT,
        )))
        .add_output(UnspentTxOut::from_partial(op_return_txout))
        .finalize();
    txhandler.set_p2tr_key_spend_witness(&user_sig, 0)?;
    txhandler.promote()
}

    /// Sets the given payout txs' txid and operator index for the given index.
    pub async fn update_payout_txs_and_payer_operator_xonly_pk(
        &self,
        tx: Option<DatabaseTransaction<'_>>,
        payout_txs_and_payer_operator_xonly_pk: Vec<(
            u32,
            Txid,
            Option<XOnlyPublicKey>,
            bitcoin::BlockHash,
        )>,
    ) -> Result<(), BridgeError> {
        if payout_txs_and_payer_operator_xonly_pk.is_empty() {
            return Ok(());
        }
        // Convert all values first, propagating any errors
        let converted_values: Result<Vec<_>, BridgeError> = payout_txs_and_payer_operator_xonly_pk
            .iter()
            .map(|(idx, txid, operator_xonly_pk, block_hash)| {
                Ok((
                    i32::try_from(*idx).wrap_err("Failed to convert payout index to i32")?,
                    TxidDB(*txid),
                    operator_xonly_pk.map(XOnlyPublicKeyDB),
                    BlockHashDB(*block_hash),
                ))
            })
            .collect();
        let converted_values = converted_values?;

        let mut query_builder = QueryBuilder::new(
            "UPDATE withdrawals AS w SET
                payout_txid = c.payout_txid,
                payout_payer_operator_xonly_pk = c.payout_payer_operator_xonly_pk,
                payout_tx_blockhash = c.payout_tx_blockhash
                FROM (",
        );

        query_builder.push_values(
            converted_values.into_iter(),
            |mut b, (idx, txid, operator_xonly_pk, block_hash)| {
                b.push_bind(idx)
                    .push_bind(txid)
                    .push_bind(operator_xonly_pk)
                    .push_bind(block_hash);
            },
        );

        query_builder
            .push(") AS c(idx, payout_txid, payout_payer_operator_xonly_pk, payout_tx_blockhash) WHERE w.idx = c.idx");

        let query = query_builder.build();
        execute_query_with_tx!(self.connection, tx, query, execute)?;

        Ok(())
    }

    pub async fn get_first_unhandled_payout_by_operator_xonly_pk(
        &self,
        tx: Option<DatabaseTransaction<'_>>,

            "SELECT w.idx, w.move_to_vault_txid, w.payout_tx_blockhash

             WHERE w.payout_txid IS NOT NULL
                AND w.is_payout_handled = FALSE
                AND w.payout_payer_operator_xonly_pk = $1

                    move_to_vault_txid
                        .expect("move_to_vault_txid Must be Some")
                        .0,
                    payout_tx_blockhash
                        .expect("payout_tx_blockhash Must be Some")
                        .0,
