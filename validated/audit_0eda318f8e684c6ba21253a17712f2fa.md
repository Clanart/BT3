## Title
GitHub Desktop force-disables Git's built-in clone protection against malicious submodules (CVE-2024-32002 class) - (`app/src/lib/git/clone.ts`)

### Summary
`app/src/lib/git/clone.ts` unconditionally sets `GIT_CLONE_PROTECTION_ACTIVE: 'false'` in the environment for every `git clone --recursive` invocation, regardless of the trustworthiness of the remote. This environment variable is the mechanism Git added to guard against a class of RCE vulnerabilities (the 2024 clone/submodule symlink and case-insensitive-filesystem hook-execution attacks, e.g. CVE-2024-32002/32004/32020/32021) where a maliciously crafted repository with nested submodules can smuggle a hook (or other executable content) into `.git/` during a recursive clone and have it execute automatically. By forcing this protection off on every clone, Desktop reintroduces the exact vulnerability class Git's upstream fix was designed to prevent, for any repository cloned or opened via Desktop's "Clone" or "Open in Desktop" flows.

### Finding Description
The `clone()` function builds a hardened env object but deliberately turns off Git's clone protection: [1](#0-0) 

```
const env = {
    ...(await envForRemoteOperation(url)),
    GIT_CLONE_PROTECTION_ACTIVE: 'false',
}
...
const args = [
    '-c',
    `init.defaultBranch=${defaultBranch}`,
    'clone',
    '--recursive',
]
```

This is invoked for every clone Desktop performs, including clones initiated from an attacker-controlled URL (e.g. via the `x-github-client://openRepo/...` deep link or `--cli-clone`), and the `--recursive` flag means nested submodules are fetched and checked out automatically: [2](#0-1) [3](#0-2) 

The only local mitigation present in this file is `isClonePathSensitive()`, which validates the *top-level destination directory* the user is cloning into (blocking clones into `~/.ssh`, `~/.gnupg`, the home directory root, etc.): [4](#0-3) 

That check does nothing to prevent malicious content *inside* the cloned repository tree — e.g., crafted submodules, symlinked `.git` entries, or case-insensitive path collisions designed to overwrite hook files — from being written and executed as part of the recursive clone/checkout process. `GIT_CLONE_PROTECTION_ACTIVE` is precisely the mechanism Git itself added to detect and reject that class of malicious repository content, and Desktop disables it outright rather than only in cases where it's provably safe to do so (e.g., trusted, already-verified local paths).

This mirrors the structure of the reported bug: a security-relevant check (`maxFundDur`) is bypassed whenever another condition is active (`maxLoanDur` set); here, Git's clone-time symlink/hook protection is bypassed unconditionally for every single clone Desktop performs, leaving the corrupted invariant "a recursively cloned repository cannot execute code as part of the clone" broken.

### Impact Explanation
An attacker who controls a Git remote (a public repo the victim is enticed to open/clone via a GitHub URL, a deep link, or a malicious fork) can craft nested submodules/symlinks that Git's clone protection would normally reject. Because Desktop explicitly disables that protection, cloning such a repository through Desktop's UI, the `x-github-client://openRepo/` handler, or the `--cli-clone` CLI flag can result in arbitrary file writes outside the intended checkout (e.g., overwriting `.git/hooks/*`) and subsequent code execution on the victim's machine — satisfying the "attacker controls a cloned/fetched repository... resulting in code execution" impact criterion.

### Likelihood Explanation
Every clone performed by Desktop passes through this exact code path with the protection forced off, and `--recursive` is always requested, so no unusual user action beyond "clone/open this repository in Desktop" (a completely normal, expected workflow) is required. The only gate is Git's own client-side vulnerability status for the relevant CVEs, but Desktop's explicit override removes that defense-in-depth regardless of the bundled Git version's patch level.

### Recommendation
Remove the unconditional `GIT_CLONE_PROTECTION_ACTIVE: 'false'` override in `clone()` so Git's built-in clone-time protections remain active for all recursive clones. If this override was added to work around a specific, narrow compatibility issue, scope it precisely (e.g., only for verified local/trusted sources) rather than disabling it globally for every remote clone.

### Proof of Concept
1. Host a malicious Git repository containing a submodule configuration crafted to exploit the symlink/case-insensitive-collision clone vulnerability (as described in the Git advisories fixed by `GIT_CLONE_PROTECTION_ACTIVE`), targeting `.git/hooks/post-checkout` (or an equivalent hook) for overwrite.
2. Get the victim to clone or "Open in Desktop" the repository, e.g. via a link like `x-github-client://openRepo/https://github.com/attacker/evil-repo` (handled in `app/src/lib/parse-app-url.ts` and `app/src/ui/dispatcher/dispatcher.ts`'s `openOrCloneRepository`), or by pasting the URL into Desktop's clone dialog.
3. Desktop calls `clone()` in `app/src/lib/git/clone.ts` with `--recursive` and `GIT_CLONE_PROTECTION_ACTIVE=false`, disabling Git's protection against the crafted submodule.
4. The malicious hook is written and subsequently executed by Git during the recursive clone/checkout, achieving code execution on the victim's machine outside the bounds of the intended repository checkout.

```typescript
function isClonePathSensitive(unresolvedClonePath: string): boolean {
  const clonePath = Path.resolve(unresolvedClonePath).toLowerCase()
  const home = Path.resolve(homedir()).toLowerCase()

  if (clonePath === home) {
    return true
  }

  const sensitiveLocations = [
    Path.join(home, '.ssh'),
    Path.join(home, '.gnupg'),
    Path.join(home, '.config'),
    Path.join(home, '.config', 'git'),
    Path.join(home, '.gitconfig'),
  ]

  if (__WIN32__) {
    const appData = process.env.APPDATA
    if (appData) {
      sensitiveLocations.push(appData.toLowerCase())
      sensitiveLocations.push(Path.join(appData, 'gnupg').toLowerCase())
    }
  }

  for (const sensitive of sensitiveLocations) {
    if (clonePath === sensitive || clonePath.startsWith(sensitive + Path.sep)) {
      return true
    }
  }

  return false
}
```
