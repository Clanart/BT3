### Title
Unbounded attacker-controlled loop count in `SchnorrAggregate::read` enables denial of service - (File: crypto/schnorr/src/aggregate.rs)

### Summary
`SchnorrAggregate::read` deserializes a Schnorr aggregate signature from an untrusted byte stream. It reads a 4-byte little-endian length prefix and then iterates that many times calling `C::read_G(reader)` — a count the attacker fully controls (up to 4,294,967,295). This is a direct analog of CVE-2017-9093 (crafted input → resource-exhaustion DoS): a tiny crafted message forces an effectively unbounded amount of point-decompression work and vector growth. [1](#0-0) 

### Finding Description
The deserializer at `crypto/schnorr/src/aggregate.rs:77-88` does:

```rust
let mut len = [0; 4];
reader.read_exact(&mut len)?;
let mut Rs = vec![];
for _ in 0 .. u32::from_le_bytes(len) {
  Rs.push(C::read_G(reader)?);
}
```

There is no cap on `len`. An attacker sets `len = 0xFFFFFFFF`. Two distinct DoS consequences follow:

1. **Long-running loop.** If the reader yields data (or is a reader that synthesizes data, e.g., in a fuzzed/protocol-driven parse of a stream), `read_G` performs a full `from_bytes` decompression plus a canonicality re-encoding check per iteration (`crypto/ciphersuite/src/lib.rs:91-100`), burning ~4 billion group operations on one thread.
2. **Memory exhaustion on a live stream.** In a network protocol where peer messages are read from a socket, each iteration `push`es a 32-byte point into `Rs`; if the peer streams data slowly enough, `Rs` grows to ~128 GiB before any error, exhausting memory — a classic "alloc/loop driven by untrusted length" DoS, same class as the CVE (attacker-crafted input controls loop/resource usage).

Even if the stream is short, the loop still performs one decompression per supplied byte-quad until `read_exact` fails — the point is that nothing bounds the count before the allocation/parsing work begins, and each iteration is comparatively expensive (point decompression). The analogous reachable surface: `SchnorrAggregate::read` is a `read_*` API that consumes untrusted bytes, squarely in the permitted threat model.

### Impact Explanation
An unprivileged party who can feed bytes to `SchnorrAggregate::read` (or to any integrator that deserializes peer-supplied aggregate signatures) can hang the parsing thread for an effectively unbounded duration or drive it to OOM, denying service to the verifying node. No key material, valid signature, or protocol position is required — the length field alone triggers it. This matches the "denial of service via crafted input" impact of the reference CVE.

### Likelihood Explanation
The trigger requires only control of 4 length bytes at the head of a `SchnorrAggregate` encoding — a trivially reachable input for any peer or any data path that calls this `read` on external data. The loop bound is never validated against remaining input size, available memory, or a sane maximum (real aggregates have at most a few hundred signers). Likelihood of trigger: high wherever deserialization occurs; severity: medium (availability only, no secret/funds impact).

### Recommendation
Bound `len` before iterating — e.g., reject `len` greater than a protocol maximum (such as the validator set size or a hard cap like 65536), and/or check that `len * <C::G as GroupEncoding>::Repr::default().as_ref().len()` does not exceed the remaining input length when the reader supports `io::Seek`/`BufRead::fill_buf`. Alternatively stream-verify against the declared count without pre-growing `Rs`.

### Proof of Concept
```rust
use ciphersuite::Ciphersuite;
use schnorr::aggregate::SchnorrAggregate;
use std::io::Cursor;

// A crafted "signature" claiming to contain ~4.3 billion R values,
// followed by as much junk data as the attacker can supply.
let mut buf = u32::MAX.to_le_bytes().to_vec();
buf.extend(vec![0u8; 1 << 20]); // 1 MiB of zeros; more is better for the attacker

let mut cursor = Cursor::new(buf);
// On Ed25519, each zero-block may or may not decode; regardless, the loop
// iterates len times performing read_G decompression work per iteration,
// or grows Rs until OOM on a live stream.
let _ = SchnorrAggregate::<dalek_ff_group::Ed25519>::read(&mut cursor);
// Expectation: unbounded loop / memory growth proportional to attacker input,
// with no bound enforced before the work begins.
```
