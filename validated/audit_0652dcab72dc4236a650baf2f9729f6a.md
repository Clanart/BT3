## Analog Found

### Title
Unrecoverable panic (node crash) from unchecked offset conversion in `consoleLog.decode` - (File: blockchain/vm/contracts.go)

### Summary
The `consoleLog` precompiled contract (Kaia's Hardhat-style `console.log` support) decodes ABI-style dynamic parameters (`string`/`bytes`) from attacker-controlled EVM calldata. It converts a 256-bit, fully attacker-controlled offset word into a Go `int` via `big.Int.Int64()`, whose behavior is explicitly undefined for values that don't fit in an `int64`. A crafted offset can turn into a negative `int`, defeating the subsequent bounds checks and causing a Go runtime slice-bounds panic when the value is used to index into the `params` byte slice. This mirrors the NetHack "Call" command bug class: illegal, malformed input to a command/decode routine overruns expected bounds and crashes the process, rather than being safely rejected.

### Finding Description
`consoleLog.decode` processes the calldata following the 4-byte selector for the `console.log` precompile: [1](#0-0) 

For `StringTy` (and identically for `BytesTy`): [2](#0-1) 

The offset word `params[pos:pos+32]` is fully attacker-supplied (it is EVM calldata), and is converted with:
```go
start := int(big.NewInt(0).SetBytes(params[pos : pos+registerSize]).Int64())
```
`math/big`'s `Int64()` documents: "If x cannot be represented in an int64, the result is undefined." For a 256-bit value that does not fit in an `int64` (e.g., all-`0xff` bytes), the returned `int64` can be negative. This negative `start` is then used directly in:
```go
if len(params) < start+registerSize { ... }          // negative+32 still negative -> check passes
size := ...Int64()... params[start : start+registerSize]  // negative slice index -> panic
```
Because `start` is negative, `start+registerSize` is still negative in typical two's-complement arithmetic, so the guard `len(params) < start+registerSize` (comparing a positive length to a negative number) never triggers, and the following slice expression `params[start : start+registerSize]` panics with "slice bounds out of range [:-N]". The same unsafe conversion/pattern exists for both the `StringTy` and `BytesTy` branches.

This function is called from `toLogString`, which is called from `Run`, the entry point invoked whenever any contract executes a `CALL`/`STATICCALL` to the `console.log` precompiled address: [3](#0-2) 

Because `Run` performs no `recover()`, a panic here propagates up through EVM execution during normal transaction/state-transition processing. Unlike a normal EVM error (which reverts just the call), a Go runtime panic that is not recovered anywhere in the block-processing goroutine will crash the node process — matching the "process crash" impact category of CVE-2023-24809 (A:H, C:N, I:N).

### Impact Explanation
Any address (an unprivileged transaction sender or contract deployer) can trigger this by deploying/calling a trivial contract that performs a `CALL` (or by directly targeting the well-known `console.log` address from a transaction, if callable directly) with calldata containing a recognized selector from `common.ConsoleLogSignatures` followed by a crafted 32-byte "offset" word that does not fit in an `int64`. This causes an unrecovered Go panic during EVM execution reachable from a single submitted transaction, resulting in denial of service (node crash) — a Medium/High-severity availability issue, consistent with the referenced CVE's CVSS profile (local/low-complexity, no privileges beyond sending a transaction, availability impact only).

### Likelihood Explanation
High likelihood of triggering the panic path: the attacker fully controls the calldata bytes decoded by `consoleLog.decode`, needs only a valid selector present in `common.ConsoleLogSignatures` for a type that includes `StringTy` or `BytesTy`, and a single out-of-range 32-byte word. No special permissions, staking, governance, or validator access are required — it is reachable purely through normal contract execution paths available to any transaction sender.

### Recommendation
Replace the unchecked `big.Int.Int64()` conversions in `consoleLog.decode` (for both `StringTy` and `BytesTy`) with safe bounds validation before converting to `int`, e.g., check `bigOffset.IsInt64()` and that the resulting value is non-negative and within `len(params)` before using it to index/slice, mirroring the safe pattern already used in `accounts/abi/unpack.go`'s `lengthPrefixPointsTo` (which validates `BitLen()` and compares against output length prior to conversion). Additionally, consider wrapping precompile execution (or at minimum the `consoleLog.Run`) in a `recover()` to prevent a single malformed input from crashing the whole node.

### Proof of Concept
1. Craft calldata: 4-byte selector matching an entry in `common.ConsoleLogSignatures` whose type list contains at least one `string` or `bytes` parameter.
2. Set the corresponding "offset" word (the 32 bytes at `params[pos:pos+32]`) to a value that does not fit into an `int64`, e.g. `0xFFFFFFFFFFFFFFFFFFFFFFFFFFFFFFFFFFFFFFFFFFFFFFFFFFFFFFFFFFFFFFFF`.
3. Deploy/execute a contract that performs `CALL`/`STATICCALL` to the `console.log` precompile address with this calldata (or send it directly if the node exposes that address as callable via a transaction).
4. During EVM execution, `consoleLog.decode` computes a negative `start`, the bounds check `len(params) < start+registerSize` fails to catch it, and `params[start:start+registerSize]` triggers a Go runtime "slice bounds out of range" panic, which is unrecovered and crashes the node process handling the transaction/block.

```go
// Hardhat console.log accepts format string, however we don't support it.
// Instead, we just join all the parameters with a space.
func (c *consoleLog) toLogString(input []byte) (string, error) {
	if len(input) < 4 {
		return "", errors.New("input too short")
	}
	selector := binary.BigEndian.Uint32(input[:4])
	params := input[4:]

	types, ok := common.ConsoleLogSignatures[selector]
	if !ok {
		return "", errors.New("unknown selector")
	}
	decoded, err := c.decode(params, types)
	if err != nil {
		return "", err
	}

	return strings.Join(decoded, " "), nil
```
