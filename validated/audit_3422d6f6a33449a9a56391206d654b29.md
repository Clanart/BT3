Confirmed: `EvmHost.dispatch(DispatchPost)` never refunds excess ETH after the internal swap.

### Title
Native-fee `dispatch()`/`dispatchWithFeeToken` path permanently strands overpaid ETH in `EvmHost` instead of refunding the caller - (File: `evm/src/core/EvmHost.sol`)

### Summary
`EvmHost.dispatch(DispatchPost)` and `dispatch(DispatchGet)` accept `msg.value` and, when non-zero, call `swapETHForExactTokens{value: msg.value}(post.fee, path, address(this), block.timestamp)` on the configured Uniswap V2 router. [1](#0-0)  `swapETHForExactTokens` only spends the ETH needed to obtain exactly `post.fee` output tokens and refunds the unused portion of `msg.value` to whoever called the router — which is `EvmHost` itself (`address(this)` is only the token recipient, not the ETH refund recipient; the router refunds to `msg.sender` of the swap call). Nothing in `dispatch()` forwards that refund back to `_msgSender()`, and there is no leftover-ETH sweep in this function. [2](#0-1) 

### Finding Description
This mirrors the report's core broken invariant: an on-chain AMM interaction is used to size a payment (`quote()` off-chain estimate → `msg.value` sent on-chain), and the actual on-chain execution price can differ from the estimate the caller used. The docs explicitly acknowledge `HyperApp.quote()` (which uses `getAmountsIn`) is "vulnerable to sandwich attacks" and must only be used off-chain for estimation. [3](#0-2)  Any caller that sizes `msg.value` from that quote (with a safety buffer, since exact quotes are stale/manipulable by the time the tx lands) will nearly always overpay by some margin.

Whereas the analogous `fundRequest()` function explicitly documents this behavior as intentional ("these funds will be seen as a donation to the hyperbridge protocol") for over-payment on an already-delivered request [4](#0-3) , `dispatch(DispatchPost)`/`dispatch(DispatchGet)` carry no such disclosure and no such intent — they are the primary, everyday call path for native-fee dispatches, used directly by `HyperFungibleToken`/`WrappedHyperFungibleToken` and any third-party `HyperApp` integrator following the docs' own example (`IDispatcher(host()).dispatch{value: msg.value}(getRequest)`). [5](#0-4)  Every overpayment silently accumulates as ETH stuck in the `EvmHost` contract with no accounting, no event, and no withdrawal path for the original payer.

The existing "safety net" — reverting when `msg.value` is insufficient — only protects against underpayment; it does nothing for the (far more common in practice) overpayment case, since callers must add slippage buffer to survive sandwich/price-movement risk on the very swap the docs warn about.

### Impact Explanation
This is a real, unprivileged fund-loss path: any user or integrating contract dispatching with native token payment loses the ETH difference between their sent `msg.value` and the exact amount the router consumes, with no recovery mechanism. Given price volatility and the sandwich risk on `getAmountsIn`-based quoting (as the docs themselves warn), buffers are unavoidable, meaning the loss is structural and recurring, not an edge case. Funds accumulate in the host contract with no earmarked recipient, effectively a permanent loss to end users (though ultimately recoverable only by host governance).

### Likelihood Explanation
High. `dispatch()` with native payment is a primary, documented, first-class entry point (not an edge case), and off-chain quoting for the exact amount to send is inherently imprecise/manipulable, so nearly every native-token dispatch will overpay by some non-zero amount.

### Recommendation
After the `swapETHForExactTokens` call, compute and refund any leftover `address(this).balance` delta (or read the swap's returned `amounts[0]` to know exact ETH spent) back to `_msgSender()` before finishing `dispatch()`. Apply the same fix to `dispatch(DispatchGet)` and any other native-fee swap call sites in `EvmHost.sol`.

### Proof of Concept
1. Caller estimates `nativeCost` via `HyperApp.quote(post)` off-chain, adds a buffer for slippage (unavoidable since quoting on-chain in the same tx is explicitly discouraged per docs), and calls `IDispatcher(host).dispatch{value: nativeCost}(post)`.
2. Inside `dispatch()`, `swapETHForExactTokens{value: msg.value}(post.fee, path, address(this), block.timestamp)` spends only enough ETH to obtain `post.fee` fee tokens; the router refunds the unspent ETH to `EvmHost` (the caller of the router). [6](#0-5) 
3. `dispatch()` proceeds to build/emit the request without ever moving that refunded ETH back to `_msgSender()`. [7](#0-6) 
4. The overpaid ETH remains locked in `EvmHost`'s balance indefinitely, with no user-facing accounting or reclaim path — repeatable on every native-fee dispatch across every integrator.

    function dispatch(DispatchPost memory post) external payable notFrozen returns (bytes32 commitment) {
        if (msg.value > 0) {
            address[] memory path = new address[](2);
            address uniswapV2 = _hostParams.uniswapV2;
            path[0] = IUniswapV2Router02(uniswapV2).WETH();
            path[1] = feeToken();
            IUniswapV2Router02(uniswapV2).swapETHForExactTokens{value: msg.value}(
                post.fee, path, address(this), block.timestamp
            );
        } else if (post.fee > 0) {
            IERC20(feeToken()).safeTransferFrom(_msgSender(), address(this), post.fee);
        }

        // adjust the timeout
        uint64 timeoutTimestamp = post.timeout == 0 ? 0 : uint64(block.timestamp) + uint64(post.timeout);
        PostRequest memory request = PostRequest({
            source: host(),
            dest: post.dest,
            nonce: uint64(_nextNonce()),
            from: abi.encodePacked(_msgSender()),
            to: post.to,
            timeoutTimestamp: timeoutTimestamp,
            body: post.body
        });

        // make the commitment
        commitment = request.hash();
        _requestCommitments[commitment] = FeeMetadata({sender: post.payer, fee: post.fee});
        emit PostRequestEvent({
            source: string(request.source),
            dest: string(request.dest),
            from: _msgSender(),
            to: abi.encodePacked(request.to),
            nonce: request.nonce,
            timeoutTimestamp: request.timeoutTimestamp,
            body: request.body,
            fee: post.fee
        });
    }

### Native Token Payment

For native token payments, dispatch directly and let the Host handle the Uniswap swap:

```solidity lineNumbers title="MyApp.sol" icon="solidity"
contract MyApp is HyperApp {
    function readRemoteStateWithNative(
        bytes memory dest,
        bytes[] memory keys
    ) public payable returns (bytes32) {
        bytes memory context = abi.encode(msg.sender, block.timestamp);
        
        DispatchGet memory getRequest = DispatchGet({
            dest: dest,
            height: 0,
            keys: keys,
            timeout: 3600,
            fee: 0,
            context: context
        });
        
        // User must send enough native tokens to cover fees
        // The Host will swap native -> feeToken via Uniswap
        return IDispatcher(host()).dispatch{value: msg.value}(getRequest);
    }
}
```
