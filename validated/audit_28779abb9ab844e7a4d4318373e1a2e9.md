Confirmed. `pallet_ismp::Pallet::handle_unsigned` is a fully permissionless unsigned extrinsic accepting an arbitrary attacker-ordered `Vec<Message>` [1](#0-0) , whose ordering is preserved straight through `execute` into the `FeeHandler::on_executed` call [2](#0-1) . `pallet-consensus-incentives` derives the sole reward payee from `messages.get(0)` only, then pays that one account for every `StateMachineUpdated` event produced anywhere in the whole batch [3](#0-2) .

### Title
Consensus-incentive reward misattribution via attacker-controlled message batch ordering - (File: modules/pallets/consensus-incentives/src/impls.rs)

### Summary
`pallet-consensus-incentives::on_executed` identifies "the relayer" for an entire batch of ISMP messages by decoding the signer of only the **first** message in the batch, then pays that single account the treasury reward for **every** state-machine height advance produced by the whole batch — including advances caused by other, independently-signed consensus messages later in the same batch. Because `handle_unsigned` is a permissionless, unsigned extrinsic that lets anyone submit an arbitrary `Vec<Message>` in any order, any address can front the batch with a cheap/self-authored valid consensus message and append someone else's valid, not-yet-applied consensus proof, capturing the reward the second submitter earned.

### Finding Description
`pallet_ismp::Pallet::handle_unsigned` accepts `messages: Vec<Message>` from an unsigned origin (`ensure_none`) and forwards it unmodified, in submitter-chosen order, to `Pallet::<T>::execute` [1](#0-0) . `execute` processes every message via `handle_incoming_message`, collects `MessageWithWeight` in the same order, aggregates all resulting `Event`s, and calls `T::FeeHandler::on_executed(messages_with_weights, events)` once for the whole batch [2](#0-1) .

`pallet-consensus-incentives` is wired as a `FeeHandler`. Its `on_executed` implementation:

```rust
let maybe_relayer_account = messages.get(0).and_then(|first_message| {
    if let Message::Consensus(consensus_msg) = &first_message.message {
        ...recover sr25519 pubkey from consensus_msg.signer over keccak256(consensus_proof)...
    } else { None }
});
if let Some(relayer_account) = maybe_relayer_account {
    // collapse ALL StateMachineUpdated events in the batch to one highest height per state machine
    for (state_machine_id, latest_height) in highest_per_state_machine {
        let _ = Self::process_message(state_machine_height, state_machine_id, relayer_account.clone().into());
    }
}
``` [4](#0-3) 

`process_message`/`calculate_reward` then transfers `(latest_height − baseline) × cost_per_block` from the treasury to `relayer_account` for **each** state machine that advanced anywhere in the batch [5](#0-4) .

The existing code comment only defends against a narrower bug — multiple `StateMachineUpdated` events for the *same* chain within one batch being double-paid — by collapsing to the highest height per chain. It does **not** address that `messages.get(0)` is the sole source of the payee identity: nothing ties a given `StateMachineUpdated` event to the specific `Message::Consensus` that produced it, or to the signer of that specific message. Any consensus message can trigger a `StateMachineUpdated` event for a state machine unrelated to `messages[0]`'s target — e.g., a batch `[consensus_msg_A_signed_by_attacker_for_chain_X, consensus_msg_B_signed_by_victim_for_chain_Y]` pays the attacker for chain Y's advance, which the victim actually proved.

Because `handle_unsigned` is validated purely by `validate_unsigned` checking proof validity (not origin) [6](#0-5) , and consensus messages are unsigned-extrinsic payloads carrying their own embedded relayer signature rather than being bound to the submitting account, any network participant who observes a valid, not-yet-applied consensus proof (e.g., in the transaction pool, or a proof they can independently reconstruct/replay before it lands) can wrap it together with a trivial self-signed consensus message as position 0 and submit the combined batch themselves, diverting the reward.

### Impact Explanation
This directly causes unauthorized redirection of treasury funds intended for the account whose consensus proof actually produced the state-machine advance — the reward is paid to an unrelated address the attacker controls instead of the rightful payee. This is a "wrong beneficiary" fund-theft primitive matching the bounty's stealing/loss-of-funds and logic-attack categories: the treasury pays out correctly-sized rewards, but to the wrong recipient, at the true submitter's expense, on every batch containing more than one distinct consensus-message signer.

### Likelihood Explanation
`handle_unsigned` is explicitly documented and implemented as permissionless — "anyone" can submit valid ISMP message batches for free [7](#0-6) . No signed origin, staking, or allowlist gates batch composition or ordering. An attacker only needs (a) any valid consensus message they can legitimately author/sign (even trivial, e.g., a rotation/messaging proof for a low-cost chain they also monitor), and (b) visibility into another party's valid, unapplied consensus proof before it is included (mempool observation or independent reconstruction) to front-run its inclusion by wrapping it into their own batch as a later element. This requires no privileged access, no relayer/prover compromise, and no admin action — an ordinary unprivileged network participant can execute it.

### Recommendation
Attribute each `StateMachineUpdated` reward to the signer of the specific `Message::Consensus` that produced it, not to `messages.get(0)`. Concretely, iterate `messages` alongside `events`, recover the signer per `Message::Consensus` entry, and only credit the state machine(s) that message's own processing actually advanced (e.g., by correlating message index/position with the event stream returned per-message from `handle_incoming_message`, rather than flattening all events before attribution).

### Proof of Concept
1. Attacker holds a valid signed BEEFY/consensus proof `M_a` for state machine `X` that they are entitled to submit (however trivial — even a proof that advances `X` by the minimum amount).
2. Attacker observes (via mempool or independent construction) a second valid, unapplied consensus proof `M_v`, signed by victim `V`, that advances a high-value state machine `Y` by a large block span.
3. Attacker submits `Ismp::handle_unsigned(messages = [M_a, M_v])` as an unsigned extrinsic.
4. `execute` processes both messages successfully (assuming both proofs verify), producing `StateMachineUpdated` events for both `X` and `Y` [8](#0-7) .
5. `pallet-consensus-incentives::on_executed` recovers the relayer only from `messages[0] = M_a` (the attacker), then pays the attacker the treasury reward for **both** `X`'s and `Y`'s block-span advance, including the reward that should have gone to `V` for `M_v` [3](#0-2) .
6. Victim `V`'s equivalent submission of `M_v` alone (or as `messages[0]` in a future batch) fails to earn any reward, since `Y`'s height has already advanced and `LastRewardedHeight` watermark has moved — the reward has already been drained to the attacker.

	pub fn execute(messages: Vec<Message>) -> Result<Vec<events::Event>, Error<T>> {
		let host = Pallet::<T>::default();

		let message_results = messages
			.iter()
			.map(|msg| handle_incoming_message(&host, msg.clone()))
			.collect::<Result<Vec<_>, _>>()
			.map_err(|err| {
				log::debug!(target: "ismp", "Handling Error {:#?}", err);
				Pallet::<T>::deposit_event(Event::<T>::Errors { errors: vec![err.into()] });
				Error::<T>::InvalidMessage
			})?;

		let messages_with_weights = message_results
			.iter()
			.zip(messages)
			.map(|(result, message)| MessageWithWeight { message, weight: result.weight() })
			.collect::<Vec<_>>();

		let events = message_results
			.into_iter()
			// check that requests will be successfully dispatched
			// so we can not be spammed with failing txs
			.map(|result| match result {
				MessageResult::Request { events, .. } |
				MessageResult::Response { events, .. } |
				MessageResult::Timeout { events, .. } => events,
				MessageResult::ConsensusMessage(events) => events.into_iter().map(Ok).collect(),
				MessageResult::FrozenClient(_) => vec![],
			})
			.flatten()
			.collect::<Result<Vec<_>, _>>()
			.map_err(|err| {
				log::debug!(target: "ismp", "Handling Error {:#?}", err);
				Pallet::<T>::deposit_event(Event::<T>::Errors { errors: vec![err.into()] });
				Error::<T>::InvalidMessage
			})?;

		T::FeeHandler::on_executed(messages_with_weights, events.clone())
			.map_err(|_| Error::<T>::ErrorChargingFee)?;

		for event in events.clone() {
			// deposit any relevant events
			Pallet::<T>::deposit_event(event.into());
		}

		Ok(events)
	}

	fn process_message(
		state_machine_height: StateMachineHeight,
		state_machine_id: StateMachineId,
		relayer_account: T::AccountId,
	) -> Result<(), Error<T>> {
		if let Some(block_cost) = StateMachinesCostPerBlock::<T>::get(state_machine_id) {
			let reward = Self::calculate_reward(&state_machine_id, block_cost)?;

			if reward.is_zero() {
				return Ok(());
			}

			T::Currency::transfer(
				&T::TreasuryAccount::get().into_account_truncating(),
				&relayer_account,
				reward,
				Preservation::Expendable,
			)
			.map_err(|_| Error::<T>::RewardTransferFailed)?;

			Self::deposit_event(Event::<T>::RelayerRewarded {
				relayer: relayer_account.clone(),
				amount: reward,
				state_machine_height,
			});

			T::ReputationAsset::mint_into(&relayer_account, reward.saturated_into())
				.map_err(|_| Error::<T>::ReputationMintFailed)?;

			LastRewardedHeight::<T>::mutate(state_machine_id, |watermark| {
				*watermark = Some(watermark.unwrap_or_default().max(state_machine_height.height));
			});
		}
		Ok(())
	}

	/// Calculate the reward for a message based on the state machine id
	fn calculate_reward(
		state_machine_id: &StateMachineId,
		block_cost: <T as pallet_ismp::Config>::Balance,
	) -> Result<<T as pallet_ismp::Config>::Balance, Error<T>> {
		let host = <T::IsmpHost>::default();
		let latest_height = host
			.latest_commitment_height(state_machine_id.clone())
			.map_err(|_| Error::<T>::CouldNotGetStateMachineHeight)?;
		let previous_height =
			host.previous_commitment_height(state_machine_id.clone()).unwrap_or_default();

		// Use the rewarded watermark as the baseline and fall back to the previous height until
		// the first reward is recorded for this chain. The watermark only moves forward, so a
		// height that is rolled back and later resubmitted is not paid for a second time.
		let baseline = LastRewardedHeight::<T>::get(state_machine_id).unwrap_or(previous_height);

		let blocks = latest_height.saturating_sub(baseline);

		let blocks_as_balance: <T as pallet_ismp::Config>::Balance = blocks.saturated_into();
		let reward = blocks_as_balance.saturating_mul(block_cost);

		Ok(reward)
	}

	fn on_executed(
		messages: Vec<MessageWithWeight>,
		events: Vec<IsmpEvent>,
	) -> DispatchResultWithPostInfo {
		let maybe_relayer_account = messages.get(0).and_then(|first_message| {
			if let Message::Consensus(consensus_msg) = &first_message.message {
				let data = sp_io::hashing::keccak_256(&consensus_msg.consensus_proof);
				Signature::decode(&mut &consensus_msg.signer[..])
					.ok()
					.and_then(|sig| sig.verify_and_get_sr25519_pubkey(&data, None).ok())
					.map(|pub_key| pub_key.into())
			} else {
				None::<[u8; 32]>
			}
		});

		if let Some(relayer_account) = maybe_relayer_account {
			// When a batch contains multiple `StateMachineUpdated` events for the
			// same `state_machine_id` (sequential consensus updates for the same
			// chain), `calculate_reward` reads the same persisted
			// `(latest_commitment_height, previous_commitment_height)` pair on
			// every iteration and pays the same block-span reward N times.
			// Collapse the per-state-machine event stream to the single highest
			// `latest_height` so each state machine receives one reward per
			// batch, sized by the actual span of its commitment advance.
			let mut highest_per_state_machine: BTreeMap<StateMachineId, u64> = BTreeMap::new();
			for event in events {
				if let IsmpEvent::StateMachineUpdated(update) = event {
					highest_per_state_machine
						.entry(update.state_machine_id)
						.and_modify(|h| {
							if update.latest_height > *h {
								*h = update.latest_height;
							}
						})
						.or_insert(update.latest_height);
				}
			}

			for (state_machine_id, latest_height) in highest_per_state_machine {
				let state_machine_height =
					StateMachineHeight { id: state_machine_id.clone(), height: latest_height };

				let _ = Self::process_message(
					state_machine_height,
					state_machine_id,
					relayer_account.clone().into(),
				);
			}
		}
