### Title
`PayoutCheckerTask` Permanently Halts on First Failing Payout, Blocking All Subsequent Operator Reimbursements — (`File: core/src/task/payout_checker.rs`)

---

### Summary

`PayoutCheckerTask::run_once()` always dequeues the **lowest-index** unhandled payout and propagates any processing error directly to the caller. Because the task is not wrapped with any error-recovery combinator, a single transient or permanent failure on the head-of-queue payout terminates the task loop permanently. Every subsequent payout — regardless of its own validity — is then blocked, preventing the operator from ever initiating kickoff transactions to reclaim BTC already fronted.

---

### Finding Description

`PayoutCheckerTask` is the sole automated mechanism by which an operator converts an on-chain payout observation into a kickoff transaction for reimbursement.

**Step 1 — Always picks the same head entry.**
`get_first_unhandled_payout_by_operator_xonly_pk` issues:

```sql
SELECT w.idx, w.move_to_vault_txid, w.payout_tx_blockhash
FROM withdrawals w
WHERE w.payout_txid IS NOT NULL
  AND w.is_payout_handled = FALSE
  AND w.payout_payer_operator_xonly_pk = $1
ORDER BY w.idx ASC
LIMIT 1
``` [1](#0-0) 

Every invocation of `run_once()` will return the same row until `mark_payout_handled` is called on it.

**Step 2 — Multiple hard-error paths before `mark_payout_handled`.**

Inside `run_once()`, the following calls all propagate `Err` via `?` before the payout is ever marked handled:

- `get_deposit_data_with_move_tx` returns `None` → explicit `Err` return at line 67.
- `handle_finalized_payout` → internally calls `get_unused_and_signed_kickoff_connector`, which returns `None` → `BridgeError::DatabaseError(RowNotFound)`.
- `get_block_info_from_hash` → `ok_or_eyre("Couldn't find payout blockhash in bitcoin sync")` if the Bitcoin syncer has not yet indexed the block.
- `fetch_validate_and_store_lcp` → any Citrea RPC failure. [2](#0-1) 

**Step 3 — No error recovery wrapper.**

The task is started as:

```rust
PayoutCheckerTask::new(self.operator.db.clone(), self.operator.clone())
    .with_delay(PAYOUT_CHECKER_POLL_DELAY)
``` [3](#0-2) 

`PayoutCheckerTask` does **not** implement `RecoverableTask` and is **not** wrapped with `into_buffered_errors`. Compare with `TxSenderTask` and `MessageConsumerTask`, which both use `into_buffered_errors(N, ...)` for resilience. [4](#0-3) 

**Step 4 — Error propagates through `WithDelay` → `CancelableTask` → `CancelableLoop` and terminates the loop.**

`CancelableLoop::run_once()` returns `Err(e)` on any inner error, which causes the spawned `JoinHandle` to complete with an error. `BackgroundTaskManager` marks the task as `NotRunning` and does **not** restart it. [5](#0-4) 

The result is structurally identical to the VUSD bug: a single stuck head-of-queue entry permanently blocks all entries behind it, and the stuck entry is never cleared.

---

### Impact Explanation

Once `PayoutCheckerTask` terminates:

1. The operator cannot automatically initiate kickoff transactions for **any** payout, including ones that would succeed.
2. The operator has already spent BTC to front the withdrawal (the payout transaction is on-chain).
3. If the operator does not manually intervene before the protocol's challenge/reimbursement window expires, the operator loses the ability to claim reimbursement via the kickoff → reimburse path.
4. The operator's collateral UTXO remains locked and the fronted BTC is unrecoverable through the normal protocol flow.

This is a liveness failure with direct material fund impact on operator collateral and fronted BTC.

---

### Likelihood Explanation

Several realistic, non-adversarial conditions trigger the failure:

- **Race condition**: The Bitcoin syncer may not have indexed the payout block by the time `PayoutCheckerTask` first runs. `get_block_info_from_hash` returns `None`, producing a permanent task halt from what is a transient state.
- **Citrea RPC unavailability**: `fetch_validate_and_store_lcp` fails on any Citrea node hiccup.
- **Exhausted kickoff connectors**: If `get_unused_and_signed_kickoff_connector` returns `None` for the head payout (e.g., all connectors for that deposit are used), the task halts permanently, blocking all other deposits' payouts.

No privileged access or malicious deployment is required; normal operational conditions are sufficient.

---

### Recommendation

1. **Implement `RecoverableTask` for `PayoutCheckerTask`** and wrap it with `into_buffered_errors(N, ...)` so transient errors are retried before the task terminates, consistent with `TxSenderTask` and `MessageConsumerTask`.

2. **Skip permanently-stuck payouts** rather than halting: if a payout fails processing after N retries, log a critical alert and advance to the next entry (analogous to the "skip blacklisted users" mitigation in the original report). A separate dead-letter queue or admin RPC can surface stuck entries for manual resolution.

3. **Add automatic task restart** in `BackgroundTaskManager` for critical tasks like `PayoutChecker`, or at minimum ensure the operator process restarts on task failure.

---

### Proof of Concept

1. Operator fronts withdrawal index 0 (payout tx on-chain, recorded in `withdrawals` table with `is_payout_handled = FALSE`).
2. `PayoutCheckerTask` starts. `get_first_unhandled_payout_by_operator_xonly_pk` returns index 0.
3. `get_block_info_from_hash` returns `None` (Bitcoin syncer race) → `run_once()` returns `Err("Couldn't find payout blockhash in bitcoin sync")`.
4. Error propagates: `WithDelay::run_once()` → `?` → `CancelableTask::run_once()` → `CancelableLoop::run_once()` returns `Err` → task loop exits.
5. `BackgroundTaskManager` marks `TaskVariant::PayoutChecker` as `NotRunning`.
6. Operator fronts withdrawal index 1. `PayoutCheckerTask` is not running. Kickoff for index 1 is never initiated.
7. Challenge window for index 1 expires. Operator cannot recover fronted BTC. [6](#0-5) [7](#0-6) [3](#0-2)

    async fn run_once(&mut self) -> Result<Self::Output, BridgeError> {
        let mut dbtx = self.db.begin_transaction().await?;
        let unhandled_payout = self
            .db
            .get_first_unhandled_payout_by_operator_xonly_pk(
                Some(&mut dbtx),
                self.operator.signer.xonly_public_key,
            )
            .await?;

        if unhandled_payout.is_none() {
            return Ok(false);
        }

        let (citrea_idx, move_to_vault_txid, payout_tx_blockhash) =
            unhandled_payout.expect("Must be Some");

        tracing::info!(
            "Unhandled payout found for withdrawal {}, move_txid: {}",
            citrea_idx,
            move_to_vault_txid
        );

        let deposit_data = self
            .db
            .get_deposit_data_with_move_tx(Some(&mut dbtx), move_to_vault_txid)
            .await?;
        if deposit_data.is_none() {
            return Err(eyre::eyre!("Fronted withdrawal for move tx {move_to_vault_txid} found, but the signatures for the deposit are not found in the db.").into());
        }

        let deposit_data = deposit_data.expect("Must be Some");

        let kickoff_txid = self
            .operator
            .handle_finalized_payout(
                &mut dbtx,
                deposit_data.get_deposit_outpoint(),
                payout_tx_blockhash,
            )
            .await?;

        // fetch and save the LCP for if we get challenged and need to provide proof of payout later
        let (_, payout_block_height) = self
            .operator
            .db
            .get_block_info_from_hash(Some(&mut dbtx), payout_tx_blockhash)
            .await?
            .ok_or_eyre("Couldn't find payout blockhash in bitcoin sync")?;

        let _ = self
            .operator
            .citrea_client
            .fetch_validate_and_store_lcp(
                payout_block_height as u64,
                citrea_idx,
                &self.operator.db,
                Some(&mut dbtx),
                self.operator.config.protocol_paramset(),
            )
            .await?;

        #[cfg(feature = "automation")]
        self.operator.end_round(&mut dbtx).await?;

        self.db
            .mark_payout_handled(Some(&mut dbtx), citrea_idx, kickoff_txid)
            .await?;

        dbtx.commit().await?;

        Ok(true)
    }

#[async_trait]
impl<T: Task + Sized> Task for CancelableLoop<T> {
    type Output = ();
    const VARIANT: TaskVariant = T::VARIANT;

    async fn run_once(&mut self) -> Result<Self::Output, BridgeError> {
        loop {
            match self.inner.run_once().await {
                Ok(CancelableResult::Running(_)) => {
                    tokio::task::yield_now().await;
                    continue;
                }
                Ok(CancelableResult::Cancelled) => return Ok(()),
                Err(e) => return Err(e),
            }
        }
    }
