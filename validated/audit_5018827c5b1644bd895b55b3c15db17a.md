### Title
Host-scoped (not path-scoped) generic git credential storage lets an attacker-hosted repo path on a trusted multi-tenant git host silently receive/overwrite stored PAT credentials - (File: app/src/lib/trampoline/trampoline-environment.ts, app/src/lib/generic-git-auth.ts)

### Summary
The Desktop generic-git-credential helper builds the storage/lookup key for a host's stored username/password (PAT) using `getCredentialUrl()`, which falls back to `${protocol}://${host}/${path}` where `path` is only populated if Git sends it. Git only sends the `path` field to credential helpers when `credential.useHttpPath` is enabled, which Desktop never sets. As a result, in Desktop's default configuration the credential key collapses to the **host only** (e.g. `https://git.example.com/`), not the specific repository path the user originally authenticated against.

### Finding Description
`getCredentialUrl` in `trampoline-environment.ts` constructs the URL git credential helpers key off of: `${protocol}://${user}${host}/${path}` [4](#0-3) . Since `cred.get('path')` defaults to an empty string whenever git doesn't forward the path (the default, since Desktop never configures `credential.useHttpPath=true`), every repository under the same host resolves to the identical `endpoint` string.

That `endpoint` is then used directly as the storage/lookup key in `generic-git-auth.ts`: `setGenericUsername`/`getGenericUsername` key off `genericGitAuth/username/<endpoint>` in `localStorage`, and `setGenericPassword`/`getGenericPassword` key the OS keychain entry off `getKeyForEndpoint(endpoint)` + username [5](#0-4) . Because `endpoint` is host-wide, these are effectively **one slot per host**, shared across every repository/path on that host.

The `storeCredential` handler in `trampoline-credential-helper.ts` is invoked automatically by Git's credential-helper `store` command after *any* successful HTTPS authentication and unconditionally calls `setGenericCredential(...)`, which overwrites the previously stored username and password for that host with whatever username/password were just used [3](#0-2) [6](#0-5) . There is no check that the new credential belongs to the same logical repository, project, or even the same user as the one already stored — mirroring the original report's pattern where a second unguarded write (`allowed[this][virtualExchangeAddress] = ...`) silently clobbers a prior legitimate value with no invariant check.

On the read side, `getGenericCredential`/`findGenericTrampolineAccount` looks up the stored password purely by `(host-endpoint, username)` [7](#0-6) , with no verification that the *path* Git is currently authenticating against is the same repository the credential was originally issued for.

### Impact Explanation
This is exploitable against any multi-tenant Git host that the user has previously authenticated to with a generic (non-GitHub) credential — self-hosted GitLab/Gitea/Bitbucket instances with open or org-wide project creation, or corporate git servers where any employee/contractor can create a new project path. An attacker who can get the victim to clone/add/fetch a repository they control at a *different path on the same host* benefits two ways:
1. **Credential exfiltration**: When Desktop authenticates to the attacker's repo path, it transparently supplies the victim's previously stored PAT/password for that host (since lookup is host-scoped, not path-scoped) — the attacker, controlling the server responding to that HTTPS Basic-Auth request, directly captures the credential.
2. **Silent corruption/account confusion**: If the attacker's remote URL embeds a different username (e.g., `https://attacker@git.example.com/evil.git`), a successful auth flow triggers `storeCredential`, silently overwriting the victim's stored username/password for the *entire host* with the attacker's supplied values — so subsequent operations against the victim's real, legitimate repositories on that host will use the wrong (attacker-influenced) credential, corrupting what identity is used for future pushes/fetches without any user-visible warning.

### Likelihood Explanation
Requires no local access, no malware, no leaked credentials, and no unnatural user steps beyond the normal "clone/add someone else's repo URL" action that GitHub Desktop explicitly supports (`Clone Repository` dialog with a raw URL, or adding a submodule/remote). The only precondition is that the victim already has a generic (non-GitHub.com/GHE) stored credential for a shared/multi-tenant host, which is a common real-world setup for enterprises using self-hosted Git.

### Recommendation
Scope generic git credential storage/lookup by full repository path (not just host) whenever Git provides one, and enable `credential.useHttpPath=true` for hosts that are known/likely multi-tenant, or at minimum bind the stored credential to the exact remote URL (protocol+host+path) that was used the first time it was entered/prompted, rejecting silent overwrite from a different username/path without explicit user confirmation.

### Proof of Concept
1. Victim adds a private repo `https://git.example.com/team/private-repo.git` in Desktop and enters/saves generic credentials (username `alice`, PAT `xxxx`) when prompted.
2. Because Desktop never sets `credential.useHttpPath`, the stored key becomes `genericGitAuth/username/https://git.example.com/` and keychain entry `GitHub - https://git.example.com/` / `alice`, with no path component [4](#0-3) .
3. Attacker (who has an account and can create a project on the same `git.example.com`, e.g. a public GitLab instance or shared internal server) sends the victim a clone URL `https://git.example.com/attacker/evil.git`.
4. Victim clones the attacker's repo in Desktop. When Git's credential-helper `get` runs for host `git.example.com`, `findGenericTrampolineAccount`/`getGenericPassword` returns the stored `alice`/`xxxx` PAT because the lookup key only encodes the host [7](#0-6) , and Desktop sends it to the attacker's endpoint, which the attacker fully controls and logs.

export const getCredentialUrl = (cred: Map<string, string>) => {
  const u = cred.get('url')
  if (u) {
    return new URL(u)
  }

  const protocol = cred.get('protocol') ?? ''
  const username = cred.get('username')
  const user = username ? `${encodeURIComponent(username)}@` : ''
  const host = cred.get('host') ?? ''
  const path = cred.get('path') ?? ''

  return new URL(`${protocol}://${user}${host}/${path}`)
}

import { getKeyForEndpoint } from './auth'
import { TokenStore } from './stores/token-store'

export const genericGitAuthUsernameKeyPrefix = 'genericGitAuth/username/'

function getKeyForUsername(endpoint: string): string {
  return `${genericGitAuthUsernameKeyPrefix}${endpoint}`
}

/** Get the username for the host. */
export function getGenericUsername(endpoint: string): string | null {
  const key = getKeyForUsername(endpoint)
  return localStorage.getItem(key)
}

/** Set the username for the host. */
export function setGenericUsername(endpoint: string, username: string) {
  const key = getKeyForUsername(endpoint)
  return localStorage.setItem(key, username)
}

/** Set the password for the username and host. */
export function setGenericPassword(
  endpoint: string,
  username: string,
  password: string
): Promise<void> {
  const key = getKeyForEndpoint(endpoint)
  return TokenStore.setItem(key, username, password)
}

export function setGenericCredential(
  endpoint: string,
  username: string,
  password: string
) {
  setGenericUsername(endpoint, username)
  return setGenericPassword(endpoint, username, password)
}

/** Get the password for the given username and host. */
export const getGenericPassword = (endpoint: string, username: string) =>
  TokenStore.getItem(getKeyForEndpoint(endpoint), username)

/** Delete a generic credential */
export function deleteGenericCredential(endpoint: string, username: string) {
  localStorage.removeItem(getKeyForUsername(endpoint))
  return TokenStore.deleteItem(getKeyForEndpoint(endpoint), username)
}

async function storeCredential(cred: Credential, store: Store, token: string) {
  if ((await getEndpointKind(cred, store)) !== 'generic') {
    return
  }

  return useExternalCredentialHelper()
    ? storeExternalCredential(cred, token)

export async function findGenericTrampolineAccount(
  trampolineToken: string,
  remoteUrl: string
) {
  const parsedUrl = new URL(remoteUrl)
  const endpoint = urlWithoutCredentials(remoteUrl)

  const login =
    parsedUrl.username === ''
      ? getGenericUsername(endpoint)
      : parsedUrl.username

  if (!login) {
    return undefined
  }

  const token = await memoizedGetGenericPassword(
    trampolineToken,
    endpoint,
    login
  )

  if (!token) {
    // We have a username but no password, that warrants a warning
    log.warn(`credential: generic password for ${remoteUrl} missing`)
    return undefined
  }

  return { login, endpoint, token }
