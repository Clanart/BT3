### Title
Command injection via unsanitized directory path in Windows shell-launch spawn calls - (File: app/src/lib/shells/win32.ts)

### Summary
GitHub Desktop's "Open in Shell" / "Open in Git Bash" / "Open in Cygwin" / etc. features on Windows build a shell command line by string-interpolating a filesystem `path` directly into arguments passed to Node's `child_process.spawn` with `shell: true`. This is the same broken invariant as the reported `npm-git-publish` bug: untrusted string data is formatted into a command line that is then handed to a shell interpreter (`cmd.exe`) instead of being passed as a properly escaped, discrete argument.

### Finding Description
`launch()` in [1](#0-0)  builds shell-specific argument strings by directly embedding `path` inside double/single quotes, e.g. for Git Bash:
```
return spawn(gitBashPath, [`--cd="${path}"`], { shell: true, cwd: path })
```
and for Cygwin:
```
return spawn(cygwinPath, [`/bin/sh -lc 'cd "$(cygpath "${path}")"; exec bash'`], { shell: true, cwd: path })
```
Because `shell: true` is set, Node.js re-assembles the whole command line and runs it through `cmd.exe /d /s /c`, meaning any shell metacharacters embedded in `path` (`"`, `&`, `%`, `` ` ``, `'`, `(`, `)`, `|`) are interpreted by the shell rather than treated as literal path text. The same pattern repeats for `Hyper`, `Alacritty`, `Warp`, `Cygwin`, and `GitBash` at [2](#0-1) .

The only place in the codebase that sanitizes a repository directory name is `sanitizedRepositoryName()`, which strips non-word characters when Desktop derives the **initial clone directory name** from a repository's display name: [3](#0-2) . This sanitization is not applied to every path that can end up as `repository.path`:
- Local repository paths reported by git (e.g. submodule working directories inside a cloned repository, or worktree directories) are not passed through `sanitizedRepositoryName`.
- Windows permits filesystem-legal characters that are shell metacharacters (`&`, `%`, `'`, `` ` ``, `(`, `)`, `;` are all valid in NTFS filenames), so a directory name containing these characters can exist on disk without any OS-level restriction.

The context menu action "Open in Shell" simply forwards `repository.path` to the shell-launch code without any additional validation: [4](#0-3) , and `launchShell` dispatches directly to the platform-specific `launch()` shown above: [5](#0-4) .

### Impact Explanation
If a victim opens a cloned/fetched repository whose on-disk path (or a submodule/worktree path within it) contains shell metacharacters, and later uses Desktop's built-in "Open in [Shell]" feature (Git Bash, Cygwin, Hyper, Alacritty, or Warp) on Windows, arbitrary commands can execute in the context of the Desktop user — a straight remote-code-execution primitive analogous to the reported `npm-git-publish` issue, where a user-supplied string is spliced into a shell command instead of being passed as a safe argument.

### Likelihood Explanation
The exploitation requires the victim to explicitly invoke "Open in Shell" on the affected repository/worktree, which is a normal, expected Desktop action rather than an "unnatural user step." The attacker only needs to influence a path component that ends up on disk unsanitized (e.g., via a crafted submodule path in a repository the victim clones) — no local access, admin rights, or pre-existing malware is required. This lowers likelihood somewhat compared to a fully automatic trigger, but it remains within a normal user workflow for a git client.

### Recommendation
- Never rely on `shell: true` when any part of the command line is derived from user- or repository-controlled data. Use `spawn(cmd, args)` without a shell, or pass the target directory only via the `cwd` option (already done in most cases) instead of re-embedding it into a quoted string argument.
- If a shell wrapper is unavoidable (e.g., invoking `cygpath`), use the existing escaping utilities in `app/src/lib/hooks/shell-escape.ts` (`bashEscape`, `cmdEscape`, `powershellEscape`) — currently used elsewhere in the codebase — to sanitize `path` before interpolation. See [6](#0-5)  for the existing pattern that should be reused in `win32.ts`.
- Apply consistent path sanitization/validation for all repository, submodule, and worktree paths, not just the initial clone directory name in `sanitizedRepositoryName()`.

### Proof of Concept
1. Attacker publishes a repository containing a submodule whose path in `.gitmodules` is set to a name containing shell metacharacters valid on NTFS, e.g. `foo"&calc.exe&"bar` (or an equivalent payload targeting `cmd.exe`/`cygpath` quoting).
2. Victim clones/fetches the repository with GitHub Desktop on Windows; git creates the submodule directory using that literal name.
3. Victim selects the submodule/repository in Desktop's repository list and chooses "Open in Git Bash" (or Cygwin/Hyper/Alacritty/Warp).
4. `launch()` in `app/src/lib/shells/win32.ts` builds `--cd="${path}"` (or the Cygwin `/bin/sh -lc '...'` string) with the malicious path and runs it via `spawn(..., { shell: true })`, causing `cmd.exe` to execute the injected command.

```typescript
/** Launch the given shell at the path. */
export async function launchShell(
  shell: AnyFoundShell,
  path: string,
  onError: (error: Error) => void
): Promise<void> {
  // We have to manually cast the wider `Shell` type into the platform-specific
  // type. This is less than ideal, but maybe the best we can do without
  // platform-specific build targets.
  const exists = await pathExists(shell.path)
  if (!exists) {
    const label = __DARWIN__ ? 'Settings' : 'Options'
    throw new ShellError(
      `Could not find executable for '${shell.shell}' at path '${shell.path}'.  Please open ${label} and select an available shell.`
    )
  }

  let cp: ChildProcess | null = null

  if (__DARWIN__) {
    cp = Darwin.launch(shell as FoundShell<Darwin.Shell>, path)
  } else if (__WIN32__) {
    cp = Win32.launch(shell as FoundShell<Win32.Shell>, path)
  } else if (__LINUX__) {
    cp = Linux.launch(shell as FoundShell<Linux.Shell>, path)
  }
```

```typescript
const bashEscape = (arg: string) =>
  arg
    .replace(/[\0\u0008\u001B\u009B]/gu, '')
    .replace(/\r(?!\n)/gu, '')
    .replace(/'/gu, "'\\''")

const shQuoteCommand = (
  escapeFn: (arg: string) => string,
  cmd: string,
  ...args: string[]
) => [cmd, ...args].map(a => `'${escapeFn(a)}'`).join(' ')

export const bash: Shell = {
  args: ['-ilc'],
  quoteCommand: shQuoteCommand.bind(null, bashEscape),
}

const cmdEscape = (arg: string) =>
  arg

    .replace(/([%&<>^|])/gu, '"^$1"')
```
