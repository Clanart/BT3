### Title
Untyped wallet message-signing modes produce signatures indistinguishable from on-chain `AGG_SIG_ME` authorization, enabling off-chain signature reuse for unauthorized coin spends - (File: `chia/wallet/util/signing.py`)

### Summary
The wallet's `sign_message_by_address`/`sign_message_by_id` RPCs support "unsafe" signing modes (`BLS_MESSAGE_AUGMENTATION_UTF8_INPUT`/`BLS_MESSAGE_AUGMENTATION_HEX_INPUT`) that sign raw, unprefixed bytes with the coin owner's real spend-authorizing key (the synthetic secret key), with no domain separation from the on-chain `AGG_SIG_ME` condition message format. This is the same bug class as the Meson report: an untyped/legacy message format that is ambiguous between two different signing contexts (an off-chain "prove ownership"/login message vs. an on-chain fund-authorizing signature) allows a signature obtained for one purpose to be replayed for the other.

### Finding Description
`chia.wallet.util.signing.sign_message()` supports several `SigningMode` values [1](#0-0) . For the CHIP-0002 modes, the signed payload is domain-separated via a tree-hash of `(CHIP_0002_SIGN_MESSAGE_PREFIX, message)` [2](#0-1) . However, for `BLS_MESSAGE_AUGMENTATION_UTF8_INPUT` and `BLS_MESSAGE_AUGMENTATION_HEX_INPUT`, the signed payload is the **raw caller-supplied bytes with no prefix or domain separator at all** [3](#0-2) .

Which mode is used is selected by the caller via the `is_hex`/`safe_mode` flags on the RPC request, and `safe_mode=False` explicitly selects one of the unprefixed raw modes [4](#0-3) . The RPC handler signs using the wallet's actual `synthetic_secret_key` for the target address/NFT/DID — the same key that authorizes `AGG_SIG_ME` spend conditions on-chain [5](#0-4) .

On the consensus side, the message that must be signed to satisfy an `AGG_SIG_ME` condition for a coin is `msg + coin.name() + AGG_SIG_ME_ADDITIONAL_DATA`, computed by `make_aggsig_final_message()` [6](#0-5)  and consumed identically by `pkm_pairs()`/`pkm_pairs_for_conditions_dict()` during mempool/block validation [7](#0-6) [8](#0-7) .

Because the raw signing modes apply no prefix, if a caller (a malicious website/dApp driving the local wallet RPC, or a CLI/RPC script) requests a "message signature" where the "message" string is chosen to be exactly `msg_bytes || coin_id || AGG_SIG_ME_ADDITIONAL_DATA` for a coin the victim owns, the wallet will happily produce a `G2Element` signature that is byte-for-byte a valid `AGG_SIG_ME` signature for that coin. `coin.name()` and `AGG_SIG_ME_ADDITIONAL_DATA` are both public/derivable by an attacker ahead of time, so the "message" to request can be fully precomputed. The resulting signature can then be attached to a spend bundle containing an `(AGG_SIG_ME pubkey msg)` condition for that exact coin, and it will pass signature verification identically to a legitimately authorized spend.

### Impact Explanation
This allows unauthorized/unsigned coin movement: a victim who is convinced to sign an apparently harmless "message" (e.g., for a dApp login flow) using the unsafe/raw signing mode can unknowingly produce a valid on-chain spend authorization for one of their own coins. An attacker who knows the target coin (parent id, puzzle hash, amount → coin id) can pre-construct the exact "message" to request, then use the resulting signature to build and broadcast a spend bundle that moves the victim's coin, e.g. to an attacker-controlled address, without any separate on-chain authorization from the victim.

### Likelihood Explanation
Exploitation requires social-engineering a wallet user (or a compromised/malicious local application with RPC access) into signing a specific opaque hex message using the non-default `safe_mode=False` option — the default (`safe_mode=True`) uses the safely-prefixed CHIP-0002 mode, so a user relying on wallet-CLI/GUI defaults is not automatically exposed. However, nothing in the RPC surface enforces that only trusted, benign callers can request `safe_mode=False`; any dApp or script capable of calling the local wallet RPC (which is a documented, supported interaction pattern for message signing/login flows) can request it, and the message to request is fully attacker-computable in advance from public coin data.

### Recommendation
Remove or heavily restrict the unprefixed raw signing modes (`BLS_MESSAGE_AUGMENTATION_UTF8_INPUT`/`BLS_MESSAGE_AUGMENTATION_HEX_INPUT`), or at minimum always prepend a fixed, unambiguous domain-separation tag (as CHIP-0002 already does) before signing any message via the wallet's message-signing RPCs, so that no valid off-chain "signed message" byte sequence can ever collide with the on-chain `AGG_SIG_ME`/`AGG_SIG_*` message format (`msg + addendum + additional_data`). Long term, formally document and enforce that every message format ever signed by a wallet key (on-chain conditions, CHIP-0002 messages, legacy `chia keys sign`-style raw signing) is injectively distinguishable, and consider rejecting `sign_message` requests whose raw payload ends with any of the known `AGG_SIG_*_ADDITIONAL_DATA` suffixes, mirroring the existing `AGG_SIG_UNSAFE` restriction in `pkm_pairs_for_conditions_dict()` [9](#0-8) .

### Proof of Concept
1. Attacker identifies a victim's coin `C` they wish to steal (public: `parent_coin_info`, `puzzle_hash`, `amount` → `coin_id = C.name()`), and knows the network's `AGG_SIG_ME_ADDITIONAL_DATA`.
2. Attacker chooses an arbitrary `msg` (e.g. `b""`) and computes `hex_message = (msg + coin_id + AGG_SIG_ME_ADDITIONAL_DATA).hex()`.
3. Attacker lures the victim (via a dApp/website driving the local wallet RPC, or a malicious script) into calling `sign_message_by_address` with `message=hex_message, is_hex=True, safe_mode=False`, which maps to `SigningMode.BLS_MESSAGE_AUGMENTATION_HEX_INPUT` [10](#0-9)  and signs the raw bytes with the coin owner's synthetic key with no prefix [11](#0-10) .
4. The returned `signature` is byte-identical to a valid `AGG_SIG_ME` authorization for condition `(AGG_SIG_ME pubkey msg)` on coin `C`, per `make_aggsig_final_message` [12](#0-11) .
5. Attacker crafts a `CoinSpend` for `C` with a solution containing `(AGG_SIG_ME pubkey msg)` (plus any `CREATE_COIN` to their own address) and submits a `SpendBundle` using the harvested signature; mempool/consensus validation via `pkm_pairs`/`pkm_pairs_for_conditions_dict` accepts it as properly authorized.

```python
def sign_message(secret_key: PrivateKey, message: str, mode: SigningMode) -> SignMessageResponse:
    public_key = secret_key.get_g1()
    if mode == SigningMode.CHIP_0002_HEX_INPUT:
        hex_message: bytes = Program.to((CHIP_0002_SIGN_MESSAGE_PREFIX, bytes.fromhex(message))).get_tree_hash()
    elif mode == SigningMode.BLS_MESSAGE_AUGMENTATION_UTF8_INPUT:
        hex_message = bytes(message, "utf-8")
    elif mode == SigningMode.BLS_MESSAGE_AUGMENTATION_HEX_INPUT:
        hex_message = bytes.fromhex(message)
    else:
        hex_message = Program.to((CHIP_0002_SIGN_MESSAGE_PREFIX, message)).get_tree_hash()
    return SignMessageResponse(
        pubkey=public_key,
        signature=AugSchemeMPL.sign(secret_key, hex_message),
    )
```

```python
def signing_mode_enum(request: SignMessageByAddress | SignMessageByID) -> SigningMode:
    if request.is_hex and request.safe_mode:
        return SigningMode.CHIP_0002_HEX_INPUT
    elif not request.is_hex and not request.safe_mode:
        return SigningMode.BLS_MESSAGE_AUGMENTATION_UTF8_INPUT
    elif request.is_hex and not request.safe_mode:
        return SigningMode.BLS_MESSAGE_AUGMENTATION_HEX_INPUT

    return SigningMode.CHIP_0002
```

```python
def make_aggsig_final_message(
    opcode: ConditionOpcode,
    msg: bytes,
    spend_conditions: Coin | SpendConditions,
    agg_sig_additional_data: dict[ConditionOpcode, bytes],
) -> bytes:
    if isinstance(spend_conditions, Coin):
        coin = spend_conditions
    elif isinstance(spend_conditions, SpendConditions):
        coin = Coin(spend_conditions.parent_id, spend_conditions.puzzle_hash, uint64(spend_conditions.coin_amount))
    else:
        raise ValueError(f"Expected Coin or Spend, got {type(spend_conditions)}")  # pragma: no cover

    COIN_TO_ADDENDUM_F_LOOKUP: dict[ConditionOpcode, Callable[[Coin], bytes]] = {
        ConditionOpcode.AGG_SIG_PARENT: lambda coin: coin.parent_coin_info,
        ConditionOpcode.AGG_SIG_PUZZLE: lambda coin: coin.puzzle_hash,
        ConditionOpcode.AGG_SIG_AMOUNT: lambda coin: int_to_bytes(coin.amount),
        ConditionOpcode.AGG_SIG_PUZZLE_AMOUNT: lambda coin: coin.puzzle_hash + int_to_bytes(coin.amount),
        ConditionOpcode.AGG_SIG_PARENT_AMOUNT: lambda coin: coin.parent_coin_info + int_to_bytes(coin.amount),
        ConditionOpcode.AGG_SIG_PARENT_PUZZLE: lambda coin: coin.parent_coin_info + coin.puzzle_hash,
        ConditionOpcode.AGG_SIG_ME: lambda coin: coin.name(),
    }
    addendum = COIN_TO_ADDENDUM_F_LOOKUP[opcode](coin)
    return msg + addendum + agg_sig_additional_data[opcode]
```

```python
def pkm_pairs(conditions: SpendBundleConditions, additional_data: bytes) -> tuple[list[G1Element], list[bytes]]:
    ret: tuple[list[G1Element], list[bytes]] = ([], [])

    data = agg_sig_additional_data(additional_data)

    for pk, msg in conditions.agg_sig_unsafe:
        ret[0].append(pk)
        ret[1].append(msg)

    for spend in conditions.spends:
        condition_items_pairs = [
            (ConditionOpcode.AGG_SIG_PARENT, spend.agg_sig_parent),
            (ConditionOpcode.AGG_SIG_PUZZLE, spend.agg_sig_puzzle),
            (ConditionOpcode.AGG_SIG_AMOUNT, spend.agg_sig_amount),
            (ConditionOpcode.AGG_SIG_PUZZLE_AMOUNT, spend.agg_sig_puzzle_amount),
            (ConditionOpcode.AGG_SIG_PARENT_AMOUNT, spend.agg_sig_parent_amount),
            (ConditionOpcode.AGG_SIG_PARENT_PUZZLE, spend.agg_sig_parent_puzzle),
            (ConditionOpcode.AGG_SIG_ME, spend.agg_sig_me),
        ]
        for condition, items in condition_items_pairs:
            for pk, msg in items:
                ret[0].append(pk)
                ret[1].append(make_aggsig_final_message(condition, msg, spend, data))

    return ret
```

```python
def pkm_pairs_for_conditions_dict(
    conditions_dict: dict[ConditionOpcode, list[ConditionWithArgs]],
    coin: Coin,
    additional_data: bytes,
) -> list[tuple[G1Element, bytes]]:
    ret: list[tuple[G1Element, bytes]] = []

    data = agg_sig_additional_data(additional_data)

    for cwa in conditions_dict.get(ConditionOpcode.AGG_SIG_UNSAFE, []):
        validate_cwa(cwa)
        for disallowed in data.values():
            if cwa.vars[1].endswith(disallowed):
                raise ConsensusError(Err.INVALID_CONDITION)
        ret.append((G1Element.from_bytes(cwa.vars[0]), cwa.vars[1]))

    for opcode in [
        ConditionOpcode.AGG_SIG_PARENT,
        ConditionOpcode.AGG_SIG_PUZZLE,
        ConditionOpcode.AGG_SIG_AMOUNT,
        ConditionOpcode.AGG_SIG_PUZZLE_AMOUNT,
        ConditionOpcode.AGG_SIG_PARENT_AMOUNT,
        ConditionOpcode.AGG_SIG_PARENT_PUZZLE,
        ConditionOpcode.AGG_SIG_ME,
    ]:
        for cwa in conditions_dict.get(opcode, []):
            validate_cwa(cwa)
            ret.append((G1Element.from_bytes(cwa.vars[0]), make_aggsig_final_message(opcode, cwa.vars[1], coin, data)))
```
