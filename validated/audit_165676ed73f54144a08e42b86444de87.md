### Title
CosmWasm contract fund transfers bypass tokenfactory `DenomAllowList` ACL enforced only on `bank.MsgSend`/`MsgMultiSend` - (File: sei-wasmd/x/wasm/keeper/keeper.go)

### Summary
The tokenfactory module lets a denom admin restrict transfers of a `factory/...` denom to an allow-listed set of addresses via `SetDenomAllowList`. This restriction is enforced by `BaseSendKeeper.IsInDenomAllowList`, but that check is only invoked from the `x/bank` message-server handlers `Send` and `MultiSend`. It is not part of the underlying `SendCoins`/`InputOutputCoins` keeper methods. The CosmWasm integration (`sei-wasmd`) moves coins associated with contract instantiate/execute calls (and other bank-msg dispatch paths) through `BankCoinTransferrer.TransferCoins`, which calls the bank keeper's `SendCoins` directly and only checks `IsSendEnabledCoins` and `BlockedAddr` — never `IsInDenomAllowList`. This mirrors the NATS bug class: an authorization check ("ACL") is enforced on one entry surface (`MsgSend`) but silently skipped on another reachable surface (CosmWasm-driven transfers) that ultimately moves the exact same funds.

### Finding Description
`IsInDenomAllowList` is the sole gate that enforces tokenfactory admin-configured allow lists on `factory/<creator>/<subdenom>` transfers: [1](#0-0) 

It is called explicitly inside the bank `MsgServer.Send` and `MultiSend` handlers before invoking `SendCoins`: [2](#0-1) [3](#0-2) 

However, `SendCoins` itself does not perform this check — it is bolted on only at the message-handler layer, not inside the shared transfer primitive. The wasm module's `BankCoinTransferrer`, used to move coins on behalf of CosmWasm contract operations, calls `keeper.SendCoins` directly and only re-implements `IsSendEnabledCoins`/`BlockedAddr`, omitting the allow-list check entirely: [4](#0-3) 

As a result, any code path that transfers coins through this transferrer (e.g., funds attached to `MsgInstantiateContract`/`MsgExecuteContract`, or `BankMsg` dispatch that is routed through this transferrer rather than through the bank `MsgServer`) can move `factory/...` tokens in or out of addresses that a denom admin has explicitly excluded from the `DenomAllowList`, exactly as MQTT clients in the NATS advisory bypassed ACLs enforced only on the standard NATS subject path.

### Impact Explanation
Tokenfactory admins rely on `DenomAllowList` to restrict transfer of sensitive or regulated `factory/...` denoms (e.g., permissioned/whitelisted tokens) to specific addresses. If CosmWasm contract fund movement bypasses this control, any CosmWasm user or contract can move restricted tokenfactory tokens to/from addresses that were never authorized, defeating the admin's access control and enabling unauthorized transfer of restricted assets. This is a fund-control/authorization-bypass impact (unauthorized transfer), matching the CWE-863 (Incorrect Authorization) class of the referenced advisory.

### Likelihood Explanation
Reachable by any account that can submit `MsgInstantiateContract`/`MsgExecuteContract` with funds denominated in an allow-list-restricted `factory/...` denom, or by any contract logic that moves such funds via the wasm bank-transfer plumbing — no special privilege required beyond holding/being sent the restricted token. The bypass requires no crafted exploit beyond routing the transfer through the CosmWasm fund-transfer path instead of `bank.MsgSend`.

### Recommendation
Move the `IsInDenomAllowList` enforcement into the shared `SendCoins`/`InputOutputCoins` keeper functions (or into every code path that ultimately performs the ledger transfer, including `BankCoinTransferrer.TransferCoins`) so that the ACL is enforced uniformly regardless of entry point, rather than being duplicated ad hoc in the `MsgServer.Send`/`MultiSend` handlers only.

### Proof of Concept
Conceptual PoC (not independently executed, based on code-path analysis):
1. Tokenfactory admin creates `factory/<admin>/restricted` and sets `DenomAllowList{Addresses: [admin]}` via `SetDenomAllowList`, so only `admin` may hold/transfer it.
2. A non-admin account that (legitimately or via a prior transfer that itself used the bank `MsgSend` path) holds some of `factory/<admin>/restricted` submits `MsgInstantiateContract` or `MsgExecuteContract` attaching those coins as `funds`, or interacts with a contract that internally moves the coins using the wasm bank-transfer mechanism backed by `BankCoinTransferrer`.
3. Because `TransferCoins` never calls `IsInDenomAllowList`, the transfer succeeds and moves the restricted denom to/from the contract address, even though that address is not in the `DenomAllowList`, whereas the same transfer attempted via `bank.MsgSend` would be rejected with `"... is not allowed to send/receive funds"`.

Note: I was not able to fully trace every wasm dispatch path (e.g., whether `BankMsg::Send` submessages emitted by a contract are routed through this `BankCoinTransferrer` versus through the full `baseapp` message router, which would re-invoke the bank `MsgServer` and thus the allow-list check) due to remaining tool-call budget; the confirmed bypass is for coin transfers that use `BankCoinTransferrer.TransferCoins` directly (e.g., funds accompanying instantiate/execute). Further verification of the exact set of wasm dispatch paths using this transferrer versus the full message router would benefit from a full Devin session with repository access.

// IsInDenomAllowList checks if the given address is allowed to send the given coins.
// The check is performed only fot token factory denoms. For each token factory denom,
// it checks if there is allow list for the given denom. If there is no allow list,
// the address is allowed to send the coins. If there is an allow list, the address is
// allowed to send the coins only if it is in the allow list.
func (k BaseSendKeeper) IsInDenomAllowList(ctx sdk.Context, addr sdk.AccAddress, coins sdk.Coins, cache map[string]AllowedAddresses) bool {
	for _, coin := range coins {
		// Skip if denom does not contain the token factory prefix
		if !strings.HasPrefix(coin.Denom, TokenFactoryPrefix) {
			continue
		}

		allowedAddresses := k.getAllowedAddresses(ctx, cache, coin.Denom)
		// skip if there is no allow list for the denom
		if len(allowedAddresses.set) == 0 {
			continue
		}

		if !allowedAddresses.contains(addr) {
			return false
		}
	}
	return true
}

func (k msgServer) Send(goCtx context.Context, msg *types.MsgSend) (*types.MsgSendResponse, error) {
	ctx := sdk.UnwrapSDKContext(goCtx)

	if err := k.IsSendEnabledCoins(ctx, msg.Amount...); err != nil {
		return nil, err
	}

	from, err := sdk.AccAddressFromBech32(msg.FromAddress)
	if err != nil {
		return nil, err
	}
	to, err := sdk.AccAddressFromBech32(msg.ToAddress)
	if err != nil {
		return nil, err
	}

	allowListCache := make(map[string]AllowedAddresses)
	if !k.IsInDenomAllowList(ctx, from, msg.Amount, allowListCache) {
		return nil, sdkerrors.Wrapf(sdkerrors.ErrUnauthorized, "%s is not allowed to send funds", msg.FromAddress)
	}

	if k.BlockedAddr(to) || !k.IsInDenomAllowList(ctx, to, msg.Amount, allowListCache) {
		return nil, sdkerrors.Wrapf(sdkerrors.ErrUnauthorized, "%s is not allowed to receive funds", msg.ToAddress)
	}

func (k msgServer) MultiSend(goCtx context.Context, msg *types.MsgMultiSend) (*types.MsgMultiSendResponse, error) {
	ctx := sdk.UnwrapSDKContext(goCtx)
	denomToAllowListCache := make(map[string]AllowedAddresses)
	// NOTE: totalIn == totalOut should already have been checked
	for _, in := range msg.Inputs {
		if err := k.IsSendEnabledCoins(ctx, in.Coins...); err != nil {
			return nil, err
		}
		accAddr := sdk.MustAccAddressFromBech32(in.Address)
		if !k.IsInDenomAllowList(ctx, accAddr, in.Coins, denomToAllowListCache) {
			return nil, sdkerrors.Wrapf(sdkerrors.ErrUnauthorized, "%s is not allowed to send funds", accAddr)
		}

			return nil, sdkerrors.Wrapf(sdkerrors.ErrUnauthorized, "%s is not allowed to receive funds", out.Address)
		}
	}

	err := k.InputOutputCoins(ctx, msg.Inputs, msg.Outputs)
	if err != nil {
		return nil, err

// BankCoinTransferrer replicates the cosmos-sdk behaviour as in
// https://github.com/cosmos/cosmos-sdk/blob/v0.41.4/x/bank/keeper/msg_server.go#L26
type BankCoinTransferrer struct {
	keeper types.BankKeeper
}

func NewBankCoinTransferrer(keeper types.BankKeeper) BankCoinTransferrer {
	return BankCoinTransferrer{
		keeper: keeper,
	}
}

// TransferCoins transfers coins from source to destination account when coin send was enabled for them and the recipient
// is not in the blocked address list.
func (c BankCoinTransferrer) TransferCoins(parentCtx sdk.Context, fromAddr sdk.AccAddress, toAddr sdk.AccAddress, amount sdk.Coins) error {
	em := sdk.NewEventManager()
	ctx := parentCtx.WithEventManager(em)
	if err := c.keeper.IsSendEnabledCoins(ctx, amount...); err != nil {
		return err
	}
	if c.keeper.BlockedAddr(toAddr) {
		return sdkerrors.Wrapf(sdkerrors.ErrUnauthorized, "%s is not allowed to receive funds", toAddr.String())
	}

	sdkerr := c.keeper.SendCoins(ctx, fromAddr, toAddr, amount)
	if sdkerr != nil {
		return sdkerr
	}
	for _, e := range em.Events() {
		if e.Type == sdk.EventTypeMessage { // skip messages as we talk to the keeper directly
			continue
		}
		parentCtx.EventManager().EmitEvent(e)
	}
	return nil
}
