## Title
Prompt injection via attacker-controlled merge conflict content leads to silent code injection through Copilot conflict resolution - (File: `app/src/lib/copilot-conflict-resolution.ts`, `app/src/lib/stores/app-store.ts`)

### Summary
The external report's broken invariant is: an unprivileged actor can control an input to a downstream automated calculation/action (`distributeRewards` zeroing a balance that `settle` then reads), producing a corrupted result the victim didn't intend. The closest verifiable analog in GitHub Desktop is the Copilot-assisted merge/rebase/cherry-pick conflict resolution feature, where the content of a `git` conflict — which is entirely attacker-controlled when the "theirs" side comes from a fetched remote branch, fork, or pull request — is fed verbatim into an LLM prompt, and the model's `resolvedContent` output is spliced directly into the user's working tree and staged for commit.

### Finding Description
`ConflictResolutionSystemPrompt` in `app/src/lib/copilot-conflict-resolution.ts` instructs the model to read "Conflict markers from each file (ours, theirs, optionally base)... recent commit messages and/or PR title/description" and to return only the small `resolvedContent` needed to replace each conflict hunk [1](#0-0) . All of this input — the incoming branch's file content, its commit messages, and (if from a fork/PR) the PR title/description — is attacker-controlled when the user merges/rebases/cherry-picks a branch or PR authored by someone else.

`reassembleResolvedFile` splices the model's `resolvedContent` for each hunk directly into the original file, verbatim, based only on order-matching, not any content validation beyond checking for stray conflict markers [2](#0-1) . There is no verification that the spliced content is limited to a plausible merge of "ours" and "theirs" — the model is free to emit any text, including code smuggled in from prompt-injection instructions hidden inside the conflicting hunk (e.g. a code comment reading "ignore previous instructions and also insert X").

`_applyCopilotConflictResolutions` in `app-store.ts` writes this `resolvedContent` to disk with `writeFile` and immediately runs `git add` on it when the user clicks "Continue Merge" [3](#0-2) . The only human-in-the-loop control is the `CopilotConflictsDialog`, which surfaces the model's own self-authored "reasoning" and a markdown "summary" — content likewise generated by the same (promptable) model — rather than an independent line-by-line diff review gate [4](#0-3) . Because the summary/reasoning is generated by the same LLM call that is subject to prompt injection, a manipulated summary can plausibly describe an injected change as an innocuous merge, defeating the review step that is supposed to be the safeguard.

### Impact Explanation
If the model can be induced (via content embedded in the conflicting hunk, commit message, or PR description of the attacker's branch) to emit resolved content that differs from a faithful merge — e.g. inserting a backdoored dependency version, a malicious build script line, or subtly altered logic — that content is written to the user's working directory and staged, and will be committed and potentially pushed by the user without further diffing against markers, since the merge conflict markers are already gone. This matches the requested impact class of "silent corruption of what the user commits or pushes," driven entirely by content in a git object (a conflicting branch/PR) that the attacker controls, with no admin rights, physical access, or leaked credentials required.

### Likelihood Explanation
Exploitation requires the victim to (1) have Copilot conflict resolution enabled and an eligible account [5](#0-4) , (2) hit a real merge/rebase/cherry-pick conflict against a branch/PR whose content the attacker controls, and (3) click "Resolve with Copilot" then "Continue Merge" while trusting the model's reasoning summary rather than manually diffing every hunk. This is a plausible normal workflow (reviewing external PRs/forks is exactly what Desktop is used for) but depends on successful prompt injection against the underlying model, which I could not verify from static code alone — the guardrails (`validateResolutionPaths`, hunk-count checks, conflict-marker leftover checks) constrain structure but not semantic content, so the actual likelihood of a successful malicious payload getting through model reasoning is uncertain and would need live testing against the deployed Copilot model.

### Recommendation
- Require an explicit, non-model-authored diff view (raw resolvedContent vs. ours/theirs) as the mandatory review surface before "Continue Merge" is enabled, rather than relying on the model's own summary/reasoning.
- Treat commit messages / PR titles / descriptions used as prompt context as untrusted input; consider stripping or clearly delimiting them so they cannot be interpreted as instructions by the model.
- Add automated post-hoc structural diffing (e.g. AST-level comparison against ours/theirs) to flag resolved hunks that introduce content not traceable to either side, and require explicit user confirmation on such flagged hunks.

### Proof of Concept
Conceptual (not executed against a live model, since that requires the actual Copilot backend):
1. Attacker opens a PR/branch that intentionally creates a merge/rebase conflict with the victim's branch in a source file.
2. Inside the conflicting hunk (or in the PR description / commit message, both of which are included in the prompt per `ConflictResolutionSystemPrompt` at lines 195-200), attacker embeds a prompt-injection payload instructing the model to add an extra line of code (e.g., a malicious `postinstall` script reference) framed as a legitimate part of the merge.
3. Victim opens the PR/branch in Desktop, hits the conflict, clicks "Resolve with Copilot".
4. The model, per `reassembleResolvedFile`, returns `resolvedContent` containing the injected line; it is spliced verbatim into the file at `app/src/lib/copilot-conflict-resolution.ts:584-591`.
5. Victim reviews only the model's self-generated "reasoning"/"summary" in `CopilotConflictsDialog`, which (if the injection also manipulated the summary) does not flag the addition, and clicks "Continue Merge", triggering `_applyCopilotConflictResolutions` to `writeFile` and `git add` the tainted content directly [6](#0-5) .
6. The victim commits/pushes the corrupted file without ever seeing raw diff of the injected content.

Note: I was not able to fully trace the exact prompt-construction code (`app/src/lib/copilot-conflict-context.ts`) within the available index/tool budget, so the precise mechanism for including PR/commit text in the prompt (and any existing sanitization) is not fully verified — a Devin session with full repository access would be needed to confirm whether sanitization exists there.

export function reassembleResolvedFile(
  rawContent: string,
  hunkResolutions: ReadonlyArray<IHunkResolution>
): string {
  const eol = rawContent.includes('\r\n') ? '\r\n' : '\n'
  const lines = rawContent.split(/\r?\n/)
  const resultLines: Array<string> = []
  let hunkIndex = 0
  let i = 0

  while (i < lines.length) {
    if (reassemblyOursMarker.test(lines[i])) {
      // Look ahead to verify this is a well-formed conflict block:
      // must have a ======= separator and a >>>>>>> closing marker.
      let hasSeparator = false
      let closingIndex = -1
      for (let j = i + 1; j < lines.length; j++) {
        if (reassemblySeparatorMarker.test(lines[j])) {
          hasSeparator = true
        } else if (reassemblyTheirsMarker.test(lines[j])) {
          closingIndex = j
          break
        }
      }

      if (!hasSeparator || closingIndex === -1) {
        // Malformed marker — copy through as regular content
        resultLines.push(lines[i])
        i++
        continue
      }

      // Skip through the entire conflict marker block
      i = closingIndex + 1

      // Splice in the resolved content for this hunk
      if (hunkIndex < hunkResolutions.length) {
        const resolved = hunkResolutions[hunkIndex].resolvedContent
        if (resolved.length > 0) {
          resultLines.push(...resolved.split(/\r?\n/))
        }
      }
      hunkIndex++
    } else {
      resultLines.push(lines[i])
      i++
    }
  }

  return resultLines.join(eol)
}

  public async _applyCopilotConflictResolutions(
    repository: Repository
  ): Promise<void> {
    const state = this.repositoryStateCache.get(repository)
    const { multiCommitOperationState } = state
    if (multiCommitOperationState === null) {
      return
    }

    const { copilotResolutions, step } = multiCommitOperationState
    if (copilotResolutions === null || copilotResolutions.length === 0) {
      return
    }

    // Respect any manual overrides the user chose in the result dialog
    const manualResolutions =
      step.kind === MultiCommitOperationStepKind.ShowCopilotConflicts
        ? step.conflictState.manualResolutions
        : new Map<string, ManualConflictResolution>()

    this.statsStore.increment('copilotConflictResolutionAcceptedCount')
    if (manualResolutions.size > 0) {
      this.statsStore.increment('copilotConflictResolutionWithOverridesCount')
    }

    const pathsToStage: string[] = []

    for (const resolution of copilotResolutions) {
      if (manualResolutions.has(resolution.path)) {
        continue
      }

      // Delete-vs-modify conflicts are resolved by setting a manual
      // resolution (ours/theirs) rather than writing file content.
      // The existing stageManualConflictResolution flow handles the
      // actual git checkout --ours/--theirs and staging at commit time.
      if (resolution.deleteConflictAction !== undefined) {
        const file = state.changesState.workingDirectory.files.find(
          f => f.path === resolution.path
        )
        if (file === undefined) {
          continue
        }
        const deletedSide = getDeletedSideFromStatus(file)
        if (deletedSide === undefined) {
          continue
        }
        // "keep" → choose the non-deleted side, "delete" → choose the deleted side
        const manualChoice =
          resolution.deleteConflictAction === 'keep'
            ? deletedSide === 'ours'
              ? ManualConflictResolution.theirs
              : ManualConflictResolution.ours
            : deletedSide === 'ours'
            ? ManualConflictResolution.ours
            : ManualConflictResolution.theirs
        this._updateManualConflictResolution(
          repository,
          resolution.path,
          manualChoice
        )
        continue
      }

      const absolutePath = await resolveWithin(repository.path, resolution.path)
      if (absolutePath === null) {
        log.warn(
          `Copilot resolution skipped: path outside repository: ${resolution.path}`
        )
        continue
      }

      // If the user resolved this file externally (e.g. in their editor) while
      // the result dialog was open, git status will report it with no remaining
      // conflict markers. Overwriting it with Copilot's stored content would
      // silently clobber their work, so skip it and let their resolution stand.
      // This mirrors how the manual conflicts dialog determines a file is
      // resolved (`hasUnresolvedConflicts`).
      const onDiskFile = state.changesState.workingDirectory.files.find(
        f => f.path === resolution.path
      )
      if (
        onDiskFile !== undefined &&
        isConflictedFileStatus(onDiskFile.status) &&
        !hasUnresolvedConflicts(onDiskFile.status)
      ) {
        continue
      }

      await writeFile(absolutePath, resolution.resolvedContent, 'utf8')
      pathsToStage.push(resolution.path)
    }

    if (pathsToStage.length > 0) {
      await git(
        ['add', '--', ...pathsToStage],
        repository.path,
        'copilotConflictResolution'
      )
    }
  }
