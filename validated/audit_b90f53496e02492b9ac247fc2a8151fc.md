### Title
Missing timestamp/freshness validation allows indefinite replay of signed App Proxy requests - ([File: lib/shopify_app/controller_concerns/app_proxy_verification.rb])

### Summary
`ShopifyApp::AppProxyVerification#query_string_valid?` verifies only that the HMAC `signature` parameter matches the recomputed signature over the remaining query params, but it never checks the `timestamp` parameter for staleness or freshness. [1](#0-0)  This is the same bug class as the reported issue: a value that is supposed to encode "validity within a maturity/time window" (`optionsRenewedTimeStamp` in the report, `timestamp` here) is present in the data but never validated against the current time, so a signed artifact that should logically be treated as expired continues to be accepted as valid.

### Finding Description
`verify_proxy_request` calls `query_string_valid?(request.query_string)` before every app-proxy action. [2](#0-1)  That method only removes `signature` from the query hash, recomputes the HMAC over the sorted remaining params (which include `timestamp`), and compares the signature — no comparison of `timestamp` to `Time.now` is performed anywhere in the concern. [3](#0-2)  Because HMAC verification alone doesn't expire, any full app-proxy URL (including the `signature` and `timestamp` query params) that is ever observed — via browser history, referrer headers, server/proxy logs, shared links, or a compromised intermediary — remains a permanently valid, replayable request as far as this library is concerned. This mirrors the audited bug class: a maturity/expiry timestamp field exists in the protected data but is not checked, so downstream logic treats stale/expired data as current, granting benefits/access it should not.

### Impact Explanation
An attacker who obtains a previously-issued, legitimately-signed app-proxy query string (this is possible since app-proxy URLs are visible to end users' browsers, appear in HTTP Referer headers, and may leak through logs/history/CDNs) can replay that exact query string to the app's proxy endpoint at any time in the future and have it accepted as an authentic, current Shopify-signed request. This is a concrete "accepted forged/replayed signed request" — the app has no way to distinguish a fresh request from a years-old captured one, enabling unauthorized re-triggering of any app-proxy action gated solely by `ShopifyApp::AppProxyVerification`.

### Likelihood Explanation
Likelihood is moderate-to-high in real deployments: app proxy URLs are rendered into storefront pages and are trivially exposed to any visitor of the shop (view-source, network tab, Referer leakage to third-party resources loaded by the proxied page), and Rails' default query-string based routing means the entire signed string is easy to capture and resend with `curl`. No additional secrets or privileged access are required — this is exploitable by an anonymous actor who merely observed one valid request.

### Recommendation
Add a required, bounded freshness check on the `timestamp` query parameter inside `query_string_valid?` (or `verify_proxy_request`), rejecting requests whose `timestamp` is missing or is not within an acceptable window (e.g., a few minutes) of `Time.now.to_i`, in addition to the existing HMAC comparison.

### Proof of Concept
1. A legitimate app-proxy request is issued by Shopify with a valid `signature` and `timestamp=1466106083`, e.g.:
   `GET /app_proxy/basic?shop=some-store.myshopify.com&path_prefix=%2Fapps%2Fmy-app&timestamp=1466106083&signature=f5cd7233558b1c50102a6f33c0b63ad1e1072a2fc126cb58d4500f75223cefcd`
2. This exact URL/query-string is captured (e.g., from browser history or a proxy log) long after `1466106083` (2016) has passed.
3. Replaying the identical request today still returns `200 OK` because `query_string_valid?` only checks the HMAC, as shown by the existing test asserting this exact stale query string is valid. [4](#0-3)

```ruby
    def query_string_valid?(query_string)
      query_hash = Rack::Utils.parse_query(query_string)

      signature = query_hash.delete("signature")
      return false if signature.nil?

      ActiveSupport::SecurityUtils.secure_compare(
        calculated_signature(query_hash),
        signature,
      )
    end

    def calculated_signature(query_hash_without_signature)
      sorted_params = query_hash_without_signature.collect { |k, v| "#{k}=#{Array(v).join(",")}" }.sort.join

      OpenSSL::HMAC.hexdigest(
        OpenSSL::Digest.new("sha256"),
        ShopifyApp.configuration.secret,
        sorted_params,
      )
    end
```
