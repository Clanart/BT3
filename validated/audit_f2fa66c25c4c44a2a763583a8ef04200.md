### Title
Division by zero in `KIP71Config.NextMagmaBlockBaseFee` when governance parameter `kip71.gastarget` is set to 0 - (File: `params/kip71_config.go`)

### Summary
`params/kip71_config.go`'s `NextMagmaBlockBaseFee` divides by the governance-controlled `GasTarget` value without checking for zero, unlike the sibling `BaseFeeDenominator` field which explicitly guards against a zero value. The `Kip71GasTarget` governance parameter has `FormatChecker: noopFormatChecker` in `kaiax/gov/param.go`, meaning it accepts any `uint64` including `0`, so this value is fully attacker/governance controllable via on-chain contract governance (`GovParam.setParam`/`setParamIn`), analogous to TFLite's `Split` operator dividing by an attacker-supplied `num_splits` of 0.

Note the explicit comment "To avoid panic" for `BaseFeeDenominator == 0`, showing the developers were aware of and specifically fixed the zero-division risk for that field — but `gasTarget` (used identically in both the `parentGasUsed > gasTarget` and `parentGasUsed < gasTarget` branches) has no equivalent guard.

`GasTarget` comes directly from the `kip71.gastarget` governance parameter, whose validator performs no bounds checking: [2](#0-1) 

Compare this to `Kip71BaseFeeDenominator`, which explicitly rejects zero: [3](#0-2) 

This parameter can be updated on-chain through contract governance's `GovParam.setParam`/`setParamIn`, which is reachable by submitting an ordinary transaction (subject to owner/GC permissions defined by the `GovParam` contract) as demonstrated in the test harness: [4](#0-3) 

Go's `math/big.Int.Div` panics with "division by zero" when the divisor is zero (there is no software check equivalent to Solidity's `require`). `math.Big.Int` panics unrecoverably unless caught by a `recover()`, which is not present around this call path.

### Impact Explanation
`NextMagmaBlockBaseFee` is called for every block after the Magma hard fork, both when a node computes/verifies the next block's base fee (`VerifyMagmaHeader`) during block assembly and header verification, and is on the hot path for consensus. If `GasTarget` is set to `0` and the parent block used any nonzero amount of gas (`parentGasUsed != 0`, which is virtually every real block), the node will panic while computing the header's expected base fee. This is a chain-halting, deterministic panic hit by every honest node processing the block — a Denial-of-Service against the entire network's block production and header validation, not merely a single node crash. Because it affects all nodes identically (deterministic input), this is not a state-divergence bug but a total-network liveness failure (chain halt), which is a high-severity impact for a governance parameter that is nominally intended only to tune fee elasticity, not to be a chain-halting foot-gun.

### Likelihood Explanation
The likelihood depends on whether the `GovParam` contract's `setParam`/`setParamIn` can be invoked by a party with limited privileges (e.g., a governing-council member acting maliciously or misconfiguring) — contract governance is explicitly listed as in-scope ("governance parameters") and reachable via ordinary transactions, as shown by the test harness. There is no on-chain or off-chain validation preventing `kip71.gastarget` from being set to `0`, unlike the sibling `BaseFeeDenominator` parameter, which has an explicit `v != 0` `FormatChecker`. This asymmetry strongly suggests the missing check is unintentional (an oversight) rather than a deliberately-permitted value, increasing the likelihood that this is an exploitable/triggerable defect once a governance/contract-governance actor with param-setting rights sets `GasTarget = 0`.

### Recommendation
Add a zero-guard for `GasTarget` in `NextMagmaBlockBaseFee`, mirroring the existing `BaseFeeDenominator` zero-check (e.g., fallback to the default value `params.DefaultGasTarget` or treat `0` as "no adjustment"/reject the value). Additionally, add a `FormatChecker` for `Kip71GasTarget` in `kaiax/gov/param.go` that rejects `0` (and validates `GasTarget <= MaxBlockGasUsedForBaseFee`), consistent with the validation already applied to `Kip71BaseFeeDenominator`.

### Proof of Concept
1. Via contract governance (`GovParam.setParam("kip71.gastarget", true, <8-byte big-endian 0>, activationBlock)`), or via header governance vote, set `kip71.gastarget = 0`, effective at some future block `N`.
2. At block `N`, any block with `parentGasUsed > 0` (essentially guaranteed) triggers:
   - `parentGasUsed > gasTarget` (since `gasTarget == 0`)
   - `y := x.Div(x, new(big.Int).SetUint64(gasTarget))` divides by `big.NewInt(0)`
3. This call occurs both when the proposer computes the next block's base fee for header assembly and when every peer node verifies the header via `VerifyMagmaHeader`, at: [5](#0-4) 
4. `big.Int.Div` by zero panics ("division by zero") on every node, halting block production/validation network-wide.

func (kc *KIP71Config) VerifyMagmaHeader(headerBaseFee *big.Int, parentHeaderNumber *big.Int, parentHeaderBaseFee *big.Int, parentHeaderGasUsed uint64) error {
	if headerBaseFee == nil {
		return fmt.Errorf("header is missing baseFee")
	}
	// Verify the baseFee is correct based on the parent header.
	expectedBaseFee := kc.NextMagmaBlockBaseFee(parentHeaderNumber, parentHeaderBaseFee, parentHeaderGasUsed)
	if headerBaseFee.Cmp(expectedBaseFee) != 0 {
		return fmt.Errorf("invalid baseFee: have %s, want %s, parentBaseFee %s, parentGasUsed %d",
			headerBaseFee, expectedBaseFee, parentHeaderBaseFee, parentHeaderGasUsed)
	}
	return nil
}
