### Title
Credential-helper misclassifies attacker-controlled hostnames containing "github." as first-party GitHub endpoints, risking token exposure via a crafted remote/proxy - (File: app/src/lib/trampoline/trampoline-credential-helper.ts)

### Summary
GitHub Desktop's credential trampoline decides whether a Git remote is a "real" GitHub endpoint (in which case Desktop supplies the stored OAuth token) purely from string/regex heuristics run against the *credential URL that Git itself reports back to the trampoline*. A remote whose hostname merely contains the substring `github.` anywhere as a label (e.g. `github.attacker.example`) is classified as `'enterprise'`, causing later stages of the credential lookup to attempt to resolve/prompt for a GitHub account rather than falling into the generic-credential path immediately.

### Finding Description
`getEndpointKind` in [1](#0-0)  classifies the credential-fill request as `'github.com'`, `'ghe.com'`, `'enterprise'`, or `'generic'` using, in order: `isDotCom`/`isGHE` exact-domain checks, a `WWW-Authenticate` header heuristic, an existing-account lookup, and finally the regex test `/(^|\.)(github)\./.test(hostname)` inherited from `isGitHubHost` in [2](#0-1)  before it ever reaches the network-verified `fetch(...).headers.has('x-github-request-id')` check.

The broken invariant: the string `github.` appearing as a hostname label is treated as strong evidence of "this is a legitimate GitHub Enterprise Server," yet an attacker fully controls DNS/hostnames for any domain they own (e.g. `git.github.corp-phish.com` does not match, but `github.corp-phish.com` or `sub.github.attacker.io` does, since the regex only requires a `github` label bounded by dots). A user who is redirected by a crafted invite link, a malicious fork's `.gitmodules` submodule URL (attacker-controlled repository content, per the allowed threat model), or a manipulated corporate/PAC proxy response (`resolveGitProxy`/`parsePACString`, [3](#0-2)  and [4](#0-3) ) that reroutes traffic to such a host will have Desktop treat the interaction as `'enterprise'` rather than `'generic'`.

Being classified as `'enterprise'` matters because it routes into the "endpointKind !== 'generic'" branch of `getCredential` at [5](#0-4) , which either (a) silently returns `undefined` if an account already exists for a *different* GitHub endpoint (since `accounts.some(a => a.endpoint === apiEndpoint)` is false for the fake endpoint) — surfacing `ui.promptForGitHubSignIn(endpoint)` — enticing the user to sign in to what they believe is a legitimate GitHub host, potentially completing an OAuth/device flow against the attacker's proxy/host — or (b) if a matching `existingAccount` was found via `findGitHubTrampolineAccount` (which matches purely on origin string equality after DNS/host spoofing or a compromised corporate proxy MITM), causes `getGitHubCredential` to supply the user's real GitHub token directly to that host's git operation via `credWithAccount`.

Existing guards do not stop this path: `isDotCom`/`isGHE` are exact-match and correctly reject spoofed hosts, but the fallback regex explicitly widens the match to any label containing `github.`, and this heuristic is evaluated for classification purposes *before* the authoritative network check (`isGitHubHost`) is reached for hosts that don't match any of the fast-path heuristics — and even the network check itself only validates a `meta` endpoint response header, which is not a strong proof of identity against an active on-path proxy or DNS-controlling attacker.

### Impact Explanation
If successfully triggered, this can result in unauthorized OAuth/account binding prompts against an attacker-controlled endpoint, or in the worst case, exfiltration of the user's real GitHub token/credential to a non-GitHub host, since the credential trampoline's `get` command formats and returns the token to whatever process (ultimately libcurl) is talking to the spoofed host. This matches the "credential/token exfiltration" and "unauthorized OAuth or account binding" categories from the valid impact list.

### Likelihood Explanation
Exploitation requires the attacker to get Desktop to attempt a Git HTTPS operation against a hostname they control that contains a `github.` label (via a malicious remote URL, a submodule URL in a cloned/forked repository, or a manipulated PAC/proxy response) and for the victim to have (or create) a stored GitHub account whose *credential lookup* happens to align, or to be willing to complete a sign-in prompt believing it's legitimate GitHub. This requires some user interaction (adding/cloning an untrusted repo with a crafted submodule/remote) but no local access, admin rights, or prior malware, and the trigger is fully attacker-controlled repository/URL content, which is in-scope per the task's valid-impact criteria.

### Recommendation
Do not use the loose `/(^|\.)(github)\./` substring/label heuristic as a basis for treating a host as first-party/enterprise before the network-verified check succeeds; require the authoritative `isGitHubHost()` HTTP verification (or an explicit user-approved enterprise-account binding) to succeed before ever considering supplying stored account credentials, and fail closed (treat as `'generic'`) for any host that isn't an exact match against a known/added enterprise endpoint.

### Proof of Concept
1. Attacker publishes a public repository containing a `.gitmodules` entry (or a remote instructs a fetch/clone against) `https://github.attacker.io/victim-org/private-repo.git`.
2. Victim, who already has a GitHub.com or GHE account configured in Desktop, opens/clones the repository, and Desktop performs a submodule update/fetch against `github.attacker.io`.
3. Git invokes the trampoline credential helper `get` command with `host=github.attacker.io`; `getEndpointKind` evaluates `isDotCom`/`isGHE` (both false), the `wwwauth` heuristic (attacker can supply `WWW-Authenticate: realm="GitHub"` from their own server to force `'enterprise'` immediately, skipping even the regex/network path), then returns `'enterprise'`.
4. `getCredential` reaches the `ui.promptForGitHubSignIn(endpoint)` branch (or, if an account object's origin happens to coincide due to a MITM/DNS-spoofed proxy scenario, the direct `credWithAccount` branch), leading either to a spoofed sign-in prompt or direct credential disclosure to the attacker-controlled host.

**Note on confidence**: This analysis is based on static review of the classification/heuristic code paths; I was not able to execute the trampoline end-to-end (no filesystem/terminal access) to confirm the exact conditions under which `findGitHubTrampolineAccount`'s origin match would actually succeed against a spoofed host in a live proxy/MITM scenario, so the "direct credential disclosure" sub-case should be verified by a Devin session with full repo/runtime access before treating it as fully confirmed; the sign-in-prompt spoofing sub-case is directly supported by the cited code.

/** Implementation of the 'get' git credential helper command */
async function getCredential(cred: Credential, store: Store, token: string) {
  const ghCred = await getGitHubCredential(cred, store)

  if (ghCred) {
    return ghCred
  }

  const endpointKind = await getEndpointKind(cred, store)
  const accounts = await store.getAll()

  const endpoint = `${getCredentialUrl(cred)}`
  const apiEndpoint = getAPIEndpoint(endpoint)

  // If it appears as if the endpoint is a GitHub host and we don't have an
  // account for that endpoint then we should prompt the user to sign in.
  if (
    endpointKind !== 'generic' &&
    !accounts.some(a => a.endpoint === apiEndpoint)
  ) {
    if (getIsBackgroundTaskEnvironment(token)) {
      debug('background task environment, skipping prompt')
      return undefined
    }

    const account = await ui.promptForGitHubSignIn(endpoint)

    if (!account) {
      setHasRejectedCredentialsForEndpoint(token, endpoint)
    }

    return credWithAccount(cred, account)
  }

  // GitHub.com/GHE creds are only stored internally
  if (endpointKind !== 'generic') {
    return undefined
  }

  return useExternalCredentialHelper()
    ? getExternalCredential(cred, token)
    : getGenericCredential(cred, token)
}

const getEndpointKind = async (cred: Credential, store: Store) => {
  const credentialUrl = getCredentialUrl(cred)
  const endpoint = `${credentialUrl}`

  if (isGist(endpoint)) {
    return 'generic'
  }

  if (isDotCom(endpoint)) {
    return 'github.com'
  }

  if (isGHE(endpoint)) {
    return 'ghe.com'
  }

  // When Git attempts to authenticate with a host it captures any
  // WWW-Authenticate headers and forwards them to the credential helper. We
  // use them as a happy-path to determine if the host is a GitHub host without
  // having to resort to making a request ourselves.
  for (const [k, v] of cred.entries()) {
    if (k.startsWith('wwwauth[')) {
      if (v.includes('realm="GitHub"')) {
        return 'enterprise'
      } else if (/realm="(GitLab|Gitea|Atlassian Bitbucket)"/.test(v)) {
        return 'generic'
      }
    }
  }

  const existingAccount = await findGitHubTrampolineAccount(store, endpoint)
  if (existingAccount) {
    return isDotCom(existingAccount.endpoint) ? 'github.com' : 'enterprise'
  }

  // All GitHub hosts use HTTPS, so if the protocol is not HTTPS we can
  // assume that this is not a GitHub host.
  if (credentialUrl.protocol !== 'https:') {
    return 'generic'
  }

  return (await isGitHubHost(endpoint)) ? 'enterprise' : 'generic'
}

/**
 * Attempts to determine whether or not the url belongs to a GitHub host.
 *
 * This is a best-effort attempt and may return `undefined` if encountering
 * an error making the discovery request
 */
export async function isGitHubHost(url: string) {
  const { hostname } = new window.URL(url)

  const endpoint =
    hostname === 'github.com' || hostname === 'api.github.com'
      ? getDotComAPIEndpoint()
      : getEnterpriseAPIURL(url)

  if (isDotCom(endpoint) || isGHE(endpoint)) {
    return true
  }

  if (isKnownThirdPartyHost(hostname)) {
    return false
  }

  // github.example.com,
  if (/(^|\.)(github)\./.test(hostname)) {
    return true
  }

import { resolveProxy } from '../ui/main-process-proxy'
import { parsePACString } from './parse-pac-string'

export async function resolveGitProxy(
  url: string
): Promise<string | undefined> {
  // resolveProxy doesn't throw an error (at least not in the
  // current Electron version) but it could in the future and
  // it's also possible that the IPC layer could throw an
  // error (if the URL we're given is null or undefined despite
  // our best type efforts for example).
  // Better safe than sorry.
  const pacString = await resolveProxy(url).catch(err => {
    log.error(`Failed resolving proxy for '${url}'`, err)
    return 'DIRECT'
  })

  const proxies = parsePACString(pacString)

  if (proxies === null) {
    return undefined
  }

  for (const proxy of proxies) {
    // On Windows GitHub Desktop relies on the `schannel` `http.sslBackend` to
    // be used in order to support things like self-signed certificates.
    // Unfortunately it doesn't support https proxies so we'll exclude those
    // here. Luckily for us https proxies are really rare. On macOS we use
    // the OpenSSL ssl backend which does support https proxies.
    //
    // See
    // https://github.com/jeroen/curl/issues/186#issuecomment-494560890
    // "The Schannel backend doesn't support HTTPS proxy"
    if (__WIN32__ && proxy.startsWith('https://')) {
      log.warn('ignoring https proxy, not supported in cURL/schannel')
    } else {
      return proxy
    }
  }

  return undefined
}

export function parsePACString(pacString: string): Array<string> | null {
  // Happy path, this will be the case for the vast majority of users
  if (pacString === 'DIRECT') {
    return null
  }

  const specs = pacString.trim().split(/\s*;\s*/)
  const urls = new Array<string>()

  for (const spec of specs) {
    // No point in continuing after we get a DIRECT since we
    // have no way of implementing a fallback logic in cURL/Git
    if (spec.match(/^direct/i)) {
      break
    }

    const [protocol, endpoint] = spec.split(/\s+/, 2)

    if (endpoint !== undefined) {
      const url = urlFromProtocolAndEndpoint(protocol, endpoint)

      if (url !== null) {
        urls.push(url)
      } else {
        log.warn(`Skipping proxy spec: ${spec}`)
      }
    }
  }

  return urls.length > 0 ? urls : null
}
