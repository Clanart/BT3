### Title
Unbounded, unrepaid proposer-funded `LendTx` in the gasless module enables value extraction from the block proposer — ([File: kaiax/gasless/impl/getter.go], [File: kaiax/gasless/impl/tx_pool.go], [File: kaiax/gasless/config.go])

### Summary
The ECG report shows that `SimplePSM`/`ProfitManager` mint/burn credit tokens without going through `RateLimitedMinter`'s value-based safety cap, letting an unprivileged actor create outsized, immediately-usable voting power with no economic lock-up. The analogous weak point in Kaia is the `kaiax/gasless` module: the block proposer unconditionally transfers native KAIA to a swap-tx sender via `GetLendTxGenerator`/`MakeLendTx`, with **no value-based rate limiter** — the only defense is a transaction-count cap (`MaxBundleTxsInPending`/`MaxBundleTxsInQueue`), not a cap on the aggregate KAIA value lent per block/epoch, and the lent amount is repaid only if the bundled `SwapTx` succeeds on-chain.

### Finding Description
`GetLendTxGenerator` (aka `MakeLendTx`) builds an unconditional native-token transfer from the proposer's own key to the gasless sender, sized by `lendAmount(approveTxOrNil, swapTx)` which is derived from the attacker-supplied `swapTx.Fee()` (gas limit × attacker-chosen `GasFeeCap`/`GasTipCap`) [1](#0-0) . The bundle is `[LendTx, ApproveTx?, SwapTx]`, produced per pending sender in `ExtractTxBundles` [2](#0-1) .

The only throttling mechanism that exists is a **count** limit on how many gasless bundles can be pending/queued (`MaxBundleTxsInPending`, `MaxBundleTxsInQueue`, default 100/200, or unlimited if configured negative) — there is no limit on the *aggregate value* lent by the proposer, unlike `RateLimitedMinter`'s `hardCap`/buffer semantics that bound value flow regardless of transaction count [3](#0-2) .

Crucially, the balance/executability checks (`checkBalanceForSwap`, `VerifyExecutable`) are only evaluated against a snapshot state at tx-pool admission/promotion time (`g.Chain`/`g.getCurrentStateNonce`, DEX router's `GetAmountIn` at that moment) [4](#0-3) . Nothing re-verifies that the swap will still be economically valid (e.g. `minAmountOut`/`amountRepay` still satisfiable) at the moment the bundle is actually executed in the block. Because `LendTx` is a plain value transfer (it cannot itself fail as long as the proposer has balance) while `SwapTx`'s on-chain repayment logic can revert (price movement, sandwiching, DEX liquidity change, or an approve front-run) between the pool-time check and block-execution time, the proposer's KAIA can be spent (as the lent value, and/or consumed as gas by the reverted `SwapTx`) without the compensating repayment happening — value that is not recouped and not capped by any rate limiter.

This is structurally the same class of bug as the ECG finding: an unprivileged, ordinary transaction sender exploits a code path (`PSM.mint` / here, `gasless.SwapForGas` submission) that a rate-limiting mechanism should but does not bound, extracting unbounded value from a systemically important balance sheet (protocol solvency in ECG; proposer's own KAIA balance / gas-sponsorship pool in Kaia) using only a count-based instead of value-based safety limit.

### Impact Explanation
An attacker who can construct gasless approve/swap transaction pairs that are admissible at tx-pool-check time but whose swap fails or is manipulated to fail at execution time can repeatedly force the block proposer to lend KAIA that is never repaid, directly extracting value from the proposer with no capital cost. Because the module bounds only transaction count and not lent value, a single validator's rewardbase/nodekey balance can be drained across a block by chaining up to `MaxBundleTxsInPending` bundles with maximal `GasFeeCap`/gas-limit-derived lend amounts, causing direct fund loss to the proposer (a form of unauthorized value movement) and potential denial of gasless-service continuity for that CN, since insufficient balance stops sponsorship.

### Likelihood Explanation
Reachable by any public RPC caller who can craft a `GaslessApproveTx`/`GaslessSwapTx` pair — no special privileges, staking, or governance access required. The count-based `MaxBundleTxsInPending`/`InQueue` limits reduce, but do not eliminate, the attack surface since they only bound *how many* bundles run per block/epoch, not how much value each can extract, and the value per bundle is directly proportional to attacker-chosen gas parameters and swap amounts.

### Recommendation
Introduce a value-based (not merely count-based) rate limiter for the aggregate KAIA lent by `GetLendTxGenerator` per block/epoch, analogous to `RateLimitedMinter`'s `hardCap`/buffer, and re-verify swap executability/slippage bounds at the point of `LendTx` inclusion (not only at pool admission), so that lent value cannot exceed what can be safely repaid within the same atomic bundle.

### Proof of Concept
Not independently executable from the indexed contents alone (execution/repayment bytecode of the `GaslessSwapRouter` and its `swapForGas` repay logic were not fully retrievable via the index). Conceptually: (1) submit `GaslessApproveTx` + `GaslessSwapTx` with `minAmountOut`/`amountRepay` set tightly to the current DEX price at submission time; (2) have another transaction move the DEX pool price (or simply let normal market movement occur) between tx-pool promotion and block execution; (3) the bundled `LendTx` unconditionally transfers KAIA to the sender per `lendAmount()`, while the `SwapTx` reverts on-chain due to slippage, leaving the proposer's lent KAIA unrepaid; (4) repeat up to `MaxBundleTxsInPending` times per block to scale the extraction. Full confirmation requires access to `GaslessSwapRouter`'s Solidity source and the exact block-building revert semantics for partially-failing bundles, which were not available in the indexed context — a Devin session with full repo/file access would be needed to construct and run a concrete forge/hardhat PoC.

// L1. LendTx.type = 0x7802 (TxTypeEthereumDynamicFee)
// L2. LendTx.from = proposer
// L3. LendTx.to = SwapTx.from
// L4. LendTx.value = LendAmount(approveTxOrNil, swapTx)
func (g *GaslessModule) GetLendTxGenerator(approveTxOrNil, swapTx *types.Transaction) *builder.TxOrGen {
	var src []byte
	if approveTxOrNil != nil {
		src = append(src, approveTxOrNil.Hash().Bytes()...)
	}
	src = append(src, swapTx.Hash().Bytes()...)
	bundleHash := crypto.Keccak256Hash(src)

	gen := func(nonce uint64) (*types.Transaction, error) {
		var (
			chainId = g.InitOpts.ChainConfig.ChainID
			signer  = types.LatestSignerForChainID(chainId)
			key     = g.InitOpts.NodeKey
		)

		to, err := types.Sender(signer, swapTx)
		if err != nil {
			return nil, err
		}

		tx, err := types.NewTransactionWithMap(types.TxTypeEthereumDynamicFee, map[types.TxValueKeyType]interface{}{
			types.TxValueKeyNonce:      nonce,
			types.TxValueKeyTo:         &to,
			types.TxValueKeyAmount:     lendAmount(approveTxOrNil, swapTx),
			types.TxValueKeyData:       common.Hex2Bytes("0x"),
			types.TxValueKeyGasLimit:   params.TxGas,
			types.TxValueKeyGasFeeCap:  swapTx.GasFeeCap(),
			types.TxValueKeyGasTipCap:  swapTx.GasTipCap(),
			types.TxValueKeyAccessList: types.AccessList{},
			types.TxValueKeyChainID:    chainId,
		})
		if err != nil {
			return nil, err
		}

		err = tx.Sign(signer, key)
		return tx, err
	}

	return builder.NewTxOrGenFromGen(gen, bundleHash)

func (g *GaslessModule) ExtractTxBundles(txs []*types.Transaction, prevBundles []*builder.Bundle) []*builder.Bundle {
	// there are only at most two gasless transactions in pending for a sender
	bundles := []*builder.Bundle{}
	approveTxs := map[common.Address]*types.Transaction{}
	targetTxHash := common.Hash{}
	for _, tx := range txs {
		addr, err := types.Sender(g.signer, tx)
		if err != nil {
			continue
		}
		if g.IsApproveTx(tx) {
			approveTxs[addr] = tx
		} else if g.IsSwapTx(tx) && g.IsExecutable(approveTxs[addr], tx) {
			bundleTxs := builder.NewTxOrGenList(g.GetLendTxGenerator(approveTxs[addr], tx))
			if approveTxs[addr] != nil {
				bundleTxs = append(bundleTxs, builder.NewTxOrGenFromTx(approveTxs[addr]))
			}
			bundleTxs = append(bundleTxs, builder.NewTxOrGenFromTx(tx))

			b := builder.NewBundle(
				bundleTxs,
				targetTxHash,
				false,
			)

			targetTxHash = tx.Hash()

			isConflict := false
			for _, prev := range append(prevBundles, bundles...) {
				if prev.IsConflict(b) {
					isConflict = true
					break
				}
			}
			if isConflict {
				// Gasless transactions will just fail even if they aren't bundled.
				continue
			}
			bundles = append(bundles, b)
		} else {
			targetTxHash = tx.Hash()
		}
	}
	return bundles
}

	token := swapArgs.Token

	g.gaslessInfoMu.RLock()
	swapRouter := g.swapRouter
	g.gaslessInfoMu.RUnlock()

	// tx.minAmountOut >= tx.amountRepay
	minAmountOut := swapArgs.MinAmountOut
	amountRepay := swapArgs.AmountRepay
	if minAmountOut.Cmp(amountRepay) < 0 {
		return fmt.Errorf("insufficient minAmountOut: minAmountOut=%s, amountRepay=%s", minAmountOut.String(), amountRepay.String())
	}

	if g.GaslessConfig.ShouldCheckSenderCode() {
		if g.getCurrentHasCode(swapArgs.Sender) {

			return err
		}
