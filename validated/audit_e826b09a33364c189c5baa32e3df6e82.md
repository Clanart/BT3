### Title
`associatePublicKey` precompile permits force-associating and migrating another account's funds using only a public key, with no proof of private-key ownership - (File: precompiles/addr/addr.go)

### Summary
The external report describes an MFA-critical operation (`TOTP disable`/`backup-codes` regeneration) that is authorized by a weaker factor (password alone) than the operation's sensitivity requires, letting anyone who merely knows the password perform an irreversible security-state change without proving possession of the second factor. The `addr` precompile's `Associate` function requires the caller to supply a valid ECDSA signature (v, r, s) over a custom message, which cryptographically proves possession of the private key before the Sei⇄EVM address mapping (and any associated balance migration) is created. Its sibling entry point, `AssociatePubKey`, however, accepts a bare public key with **no signature and no proof of key ownership** and performs the exact same address-binding and fund-migration logic.

### Finding Description
`PrecompileExecutor.Execute` routes calls to `associate()` (proof-of-key via ECDSA signature recovery) or `associatePublicKey()` depending on the selector, and both funnel into the same state-mutating helper: [1](#0-0) 

`associate()` derives `evmAddr`/`seiAddr` only after recovering the signer's pubkey from a valid signature over `customMessage`: [2](#0-1) 

`associatePublicKey()`, in contrast, takes an arbitrary raw compressed public-key hex string supplied as a plain call argument — it never checks that the caller/tx signer actually controls the corresponding private key: [3](#0-2) 

Both paths converge on `associateAddresses`, which only checks that the derived `seiAddr` is not already associated, then unconditionally calls `AssociateAddresses`: [4](#0-3) 

`AssociateAddresses`/`MigrateBalance` in `utils/helpers/associate.go` performs real, consensus-visible state changes: it sets the permanent EVM↔Sei address mapping, sets the account's public key if unset, and **sweeps all spendable coins and wei balance from the cast address to the newly bound Sei address**: [5](#0-4) 

Because `associatePublicKey` never validates a signature, `Execute`'s `caller`/`callingContract` parameters are unused for this path (they are discarded via `_ common.Address` in the function signature), and the precompile is callable by any account: [6](#0-5) 

Compressed secp256k1 public keys are not secret — they are publicly recoverable from any prior Cosmos-signed transaction from the target account (included in `tx.auth_info.signer_infos`) or from any EVM transaction (via ECDSA recovery) the victim has ever broadcast. Consequently, any third party who has observed a single signed transaction from a not-yet-associated victim account can call `associatePublicKey` with that public key and force-trigger the association and fund-migration flow for the victim, at a time of the attacker's choosing, without any authorization from the victim and without the victim ever consenting to or being aware of the specific call.

### Impact Explanation
This is a real integrity break of the "second factor" guarantee: the `Associate`/`AssociateTx` design in the ante handler (`app/ante/evm_checktx.go: HandleAssociateTx`) and the `associate()` precompile method both intentionally require a signature as proof-of-key-possession before mutating the address mapping and moving funds — this is the analog of TOTP/second-factor verification. `associatePublicKey` bypasses that proof entirely, permitting a "one-factor" (mere possession of a public value) trigger of the same fund-moving and identity-binding operation that is elsewhere treated as security-critical enough to require cryptographic proof. An attacker can force premature/unauthorized association and cast-address balance migration for any victim, causing unintended and non-reversible state transitions (mapping creation, forced account pubkey binding, involuntary migration of the victim's cast-address balance) outside the victim's control or timing, and — as the code comments elsewhere warn regarding EIP-7702/`SetCode` interactions — mutable direct-cast mappings created without proper checks can conflict with staking/distribution state built under the original cast identity. Because the derived `evmAddr`/`seiAddr` pair is mathematically self-consistent (both come from the same public key), no fund destination changes — the practical damage is unauthorized/irreversible state mutation and forced balance migration performed without the victim's authorization, at a time chosen by an attacker, which is the direct structural analog to "disable MFA using only the password."

### Likelihood Explanation
Trivially reachable: any external EVM caller can invoke the `AssociatePubKey` selector on the `addr` precompile with only a public-key argument extracted from any previously observed transaction of the target — no special privilege, no node access, and no interaction with the victim is required.

### Recommendation
Require `associatePublicKey` to prove key ownership equivalently to `associate()` — e.g., require a signature (over a domain-separated message including the caller/nonce) from the supplied public key, or restrict the entry point so it can only be invoked by the EVM/Cosmos signer whose recovered pubkey matches the supplied one, before invoking `associateAddresses`/`MigrateBalance`.

### Proof of Concept
1. Observe any transaction broadcast by an unassociated victim Sei account (Cosmos tx `signer_infos` or EVM tx signature) and extract the victim's compressed secp256k1 public key.
2. As an unrelated attacker account, call the `addr` precompile's `associatePublicKey(pubKeyHex)` (selector `AssociatePubKey`) with the extracted public key.
3. `associatePublicKey` in `precompiles/addr/addr.go:205-236` derives the victim's `evmAddr`/`seiAddr` from the raw pubkey with no signature check, and `associateAddresses` (`precompiles/addr/addr.go:239-255`) proceeds to call `AssociateAddresses`, which force-creates the mapping and migrates all of the victim's cast-address balance (`utils/helpers/associate.go:34-83`), all without the victim submitting or authorizing this transaction.

func (p PrecompileExecutor) associatePublicKey(ctx sdk.Context, method *abi.Method, args []interface{}, value *big.Int) (ret []byte, remainingGas uint64, err error) {
	if err := pcommon.ValidateNonPayable(value); err != nil {
		return nil, 0, err
	}

	if err := pcommon.ValidateArgsLength(args, 1); err != nil {
		return nil, 0, err
	}

	// Takes a single argument, a compressed pubkey in hex format, excluding the '0x'
	pubKeyHex := args[0].(string)

	pubKeyBytes, err := hex.DecodeString(pubKeyHex)
	if err != nil {
		return nil, 0, err
	}

	// Parse the compressed public key
	pubKey, err := btcec.ParsePubKey(pubKeyBytes)
	if err != nil {
		return nil, 0, err
	}

	// Convert to uncompressed public key
	uncompressedPubKey := pubKey.SerializeUncompressed()

	evmAddr, seiAddr, pubkey, err := helpers.GetAddressesFromPubkeyBytes(uncompressedPubKey)
	if err != nil {
		return nil, 0, err
	}

	return p.associateAddresses(ctx, method, evmAddr, seiAddr, pubkey)

func (p PrecompileExecutor) associateAddresses(ctx sdk.Context, method *abi.Method, evmAddr common.Address, seiAddr sdk.AccAddress, pubkey cryptotypes.PubKey) (ret []byte, remainingGas uint64, err error) {
	// Check that address is not already associated
	_, found := p.evmKeeper.GetEVMAddress(ctx, seiAddr)
	if found {
		return nil, 0, fmt.Errorf("address %s is already associated with evm address %s", seiAddr, evmAddr)
	}

	// Associate Addresses:
	associationHelper := helpers.NewAssociationHelper(p.evmKeeper, p.bankKeeper, p.accountKeeper)
	err = associationHelper.AssociateAddresses(ctx, seiAddr, evmAddr, pubkey, false)
	if err != nil {
		return nil, 0, err
	}

	ret, err = method.Outputs.Pack(seiAddr.String(), evmAddr)
	return ret, pcommon.GetRemainingGas(ctx, p.evmKeeper), err
}

func (p AssociationHelper) AssociateAddresses(ctx sdk.Context, seiAddr sdk.AccAddress, evmAddr common.Address, pubkey cryptotypes.PubKey, migrateUseiOnly bool) error {
	castAddr := sdk.AccAddress(evmAddr[:])
	if !castAddr.Equals(seiAddr) && p.accountKeeper.GetAccount(ctx, seiAddr) == nil {
		castAcc := p.accountKeeper.GetAccount(ctx, castAddr)
		castBaseAcc, ok := castAcc.(*authtypes.BaseAccount)
		if ok && castBaseAcc.GetPubKey() == nil && p.bankKeeper.LockedCoins(ctx, castAddr).IsZero() {
			p.accountKeeper.SetAccount(ctx, authtypes.NewBaseAccount(seiAddr, pubkey, castBaseAcc.GetAccountNumber(), castBaseAcc.GetSequence()))
		}
	}
	p.evmKeeper.SetAddressMapping(ctx, seiAddr, evmAddr)
	acc := p.accountKeeper.GetAccount(ctx, seiAddr)
	if acc == nil {
		acc = p.accountKeeper.NewAccountWithAddress(ctx, seiAddr)
	}
	if acc.GetPubKey() == nil {
		if err := acc.SetPubKey(pubkey); err != nil {
			return err
		}
		p.accountKeeper.SetAccount(ctx, acc)
	}
	return p.MigrateBalance(ctx, evmAddr, seiAddr, migrateUseiOnly)
}

func (p AssociationHelper) MigrateBalance(ctx sdk.Context, evmAddr common.Address, seiAddr sdk.AccAddress, migrateUseiOnly bool) error {
	castAddr := sdk.AccAddress(evmAddr[:])
	if castAddr.Equals(seiAddr) {
		return nil
	}
	var castAddrBalances sdk.Coins
	if migrateUseiOnly {
		castAddrBalances = sdk.Coins{p.bankKeeper.GetBalance(ctx, castAddr, "usei")}
	} else {
		castAddrBalances = p.bankKeeper.SpendableCoins(ctx, castAddr)
	}
	if !castAddrBalances.IsZero() {
		if err := p.bankKeeper.SendCoins(ctx, castAddr, seiAddr, castAddrBalances); err != nil {
			return err
		}
	}
	castAddrWei := p.bankKeeper.GetWeiBalance(ctx, castAddr)
	if !castAddrWei.IsZero() {
		if err := p.bankKeeper.SendCoinsAndWei(ctx, castAddr, seiAddr, sdk.ZeroInt(), castAddrWei); err != nil {
			return err
		}
	}
	if p.bankKeeper.LockedCoins(ctx, castAddr).IsZero() {
		p.accountKeeper.RemoveAccount(ctx, authtypes.NewBaseAccountWithAddress(castAddr))
	}
	return nil
}
