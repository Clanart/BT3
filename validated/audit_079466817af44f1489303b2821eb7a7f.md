### Title
Permissionless `WombatStaking.harvest()` + unrestricted `MasterMagpie.deposit`/`withdraw` allow flash-stake sandwiching of reward distribution to steal yield from long-term LPs - (File: wombat/WombatStaking.sol, rewards/BaseRewardPoolV2.sol, rewards/MasterMagpie.sol)

### Summary
The Hyperdrive report describes an attack pattern where an economic state update (a checkpoint that mutates shared pool reserves) is applied atomically and pro-rata against whatever position sizes exist *at that instant*, letting an attacker sandwich the update by inflating their position right before it and closing right after. The same structural weakness exists in the Magpie reward-distribution pipeline: `WombatStaking.harvest()` is a **permissionless** function that pushes newly harvested WOM/bonus rewards into `BaseRewardPoolV2.queueNewRewards`, which instantly divides the reward by `totalStaked()` at that exact block to compute `rewardPerTokenStored`. Because `MasterMagpie.deposit`/`withdraw` for the pool's staking (receipt) token are unrestricted, ordinary calls with no cooldown or vesting, an attacker can inflate their staked balance immediately before triggering (or waiting for) `harvest()`, capture a pro-rata share of the newly queued reward, and withdraw again in the same or next transaction — diluting and stealing yield that should have accrued to genuine long-term liquidity providers.

### Finding Description
`WombatStaking.harvest(address _lpToken)` has no caller restriction beyond `whenNotPaused` and `_onlyActivePool`, so any wallet can trigger it: [1](#0-0) 

It calls `_toMasterWomAndSendReward`, which harvests WOM (and bonus tokens) from Wombat and forwards them via `_sendRewards` to `IBaseRewardPool(_rewarder).queueNewRewards(...)`: [2](#0-1) [3](#0-2) 

`queueNewRewards` → `_provisionReward` in `BaseRewardPoolV2` instantly folds the incoming reward into `rewardPerTokenStored` using the *current* `totalStaked()` as denominator, with no time-weighting, vesting, or minimum holding period: [4](#0-3) 

Meanwhile, `MasterMagpie.deposit(_stakingToken, _amount)` and `withdraw(_stakingToken, _amount)` are plain, unrestricted external entry points (no lock, no pool-helper-only gate) that any holder of the pool's receipt/staking token can call directly: [5](#0-4) 

`_deposit`/`_withdraw` immediately settle a user's `userRewardPerTokenPaid` (via `_harvestBaseRewarder`) at the pre-jump `rewardPerTokenStored`, then update `user.amount`, so any stake added right before the reward-per-token jump earns the full jump proportional to that stake, and can be withdrawn immediately afterward: [6](#0-5) 

This mirrors the report's root cause: a shared pro-rata accounting variable (`bondReserves`/`shareReserves` in Hyperdrive, `rewardPerTokenStored`/`totalStaked()` here) is updated atomically at a triggerable event (`checkpoint()` / `harvest()`), and the update's payout is computed using instantaneous balances rather than time-weighted ones — enabling a temporary, flash-sized position to capture a disproportionate share of value at the expense of positions that were genuinely at risk/staked the whole period.

### Impact Explanation
An attacker who can obtain a large temporary balance of the pool's receipt/staking token (e.g., by flash-borrowing the underlying Wombat LP, minting the receipt via `WombatStaking.deposit`, then calling `MasterMagpie.deposit`) can:
1. Call/await `WombatStaking.harvest(_lpToken)` while holding an inflated stake,
2. Immediately `MasterMagpie.withdraw` and claim their pro-rata share of the freshly queued WOM/bonus rewards via `getReward`/`_harvestBaseRewarder`,
3. Unwind the flash position.

This directly steals unclaimed yield that would otherwise accrue entirely to genuine, longer-term LPs who were staked for the full accrual period, diluting `rewardPerTokenStored` gains attributable to their real capital-at-risk. This satisfies the "theft ... of unclaimed yield" impact category since real depositors' rightful share of harvested rewards is diverted to a transient, capital-light attacker position.

### Likelihood Explanation
`harvest()` is unauthenticated and can be called by anyone at a time of the attacker's choosing (or immediately after observing a pending harvest in the mempool), and `deposit`/`withdraw` on `MasterMagpie` have no cooldown, minimum duration, or anti-flash-loan protection for standard LP staking-token pools (unlike `VLMGP`/`mWomSV`, which do enforce cooldowns). The main constraint is availability of a flash-loanable source of the underlying Wombat LP token and reward-token liquidity size being large enough to make the attack profitable net of any harvest/deposit fees, which is realistic for larger, actively-farmed Wombat pools.

### Recommendation
Introduce time-weighting or a minimum staking duration before a deposit is eligible for a share of a given reward distribution (e.g., snapshot-based or checkpointed reward eligibility, similar to a "reward epoch" boundary that ignores balance changes within the same block/transaction as `queueNewRewards`), and/or restrict `harvest()` triggering combined with deposit/withdraw to prevent same-transaction or same-block sandwiching (e.g., disallow withdraw in the same block as a deposit, or defer reward eligibility to the next accrual period for newly deposited balances).

### Proof of Concept
Conceptual PoC (requires flash-loan access to the underlying Wombat LP for the targeted pool):
1. Flash-borrow Wombat LP for `_lpToken`.
2. Call `WombatPoolHelper.depositLP` (or `WombatStaking.deposit`) to mint receipt/staking tokens, then `MasterMagpie.deposit(stakingToken, hugeAmount)` directly (bypassing the pool helper is possible since `deposit` has no pool-helper restriction).
3. Call `WombatStaking.harvest(_lpToken)` (permissionless), which pushes accumulated WOM/bonus rewards through `queueNewRewards` → `_provisionReward`, spiking `rewardPerTokenStored` using `totalStaked()` inflated by the attacker's flash deposit.
4. Call `MasterMagpie.withdraw(stakingToken, hugeAmount)`, which internally calls `_harvestBaseRewarder`/`getReward`, paying the attacker their pro-rata share of the just-queued reward.
5. Unwind: burn receipt token, withdraw LP from `WombatStaking`, repay the flash loan, keep the skimmed reward.

Note: I could not fully verify within the indexed context whether `_onlyPoolHelper` or another modifier restricts direct calls to `MasterMagpie.deposit`/`withdraw` for standard (non-vlMGP) staking tokens beyond `whenNotPaused`/`nonReentrant`, nor confirm the exact flash-loan availability for each Wombat LP; a Devin session with full repository and on-chain-fork access would be needed to execute and confirm profitability of the concrete PoC end-to-end.

    function _provisionReward(uint256 _amountReward, address _rewardToken) internal {
        IERC20(_rewardToken).safeTransferFrom(
            msg.sender,
            address(this),
            _amountReward
        );
        Reward storage rewardInfo = rewards[_rewardToken];
        rewardInfo.historicalRewards =
            rewardInfo.historicalRewards +
            _amountReward;

        if (totalStaked() == 0) {
            rewardInfo.queuedRewards += _amountReward;
        } else {
            if (rewardInfo.queuedRewards > 0) {
                _amountReward += rewardInfo.queuedRewards;
                rewardInfo.queuedRewards = 0;
            }
            rewardInfo.rewardPerTokenStored =
                rewardInfo.rewardPerTokenStored +
                (_amountReward * 10**stakingTokenDecimals) /
                totalStaked();
        }
        emit RewardAdded(_amountReward, _rewardToken);

    /// @notice internal function to deal with deposit staking token
    function _deposit(address _stakingToken, address _account, uint256 _amount, bool _isVlmgp) internal {
        updatePool(_stakingToken);

        PoolInfo storage pool = tokenToPoolInfo[_stakingToken];
        UserInfo storage user = userInfo[_stakingToken][_account];

        if (user.amount > 0) {
            _harvestMGP(_stakingToken, _account);
        }
        _harvestBaseRewarder(_stakingToken, _account);

        user.amount = user.amount + _amount;
        if (!_isVlmgp) {
            user.available = user.available + _amount;
            IERC20(pool.stakingToken).safeTransferFrom(address(msg.sender), address(this), _amount);
        }
        user.rewardDebt = (user.amount * pool.accMGPPerShare) / 1e12;

        if (_amount > 0)
            if (!_isVlmgp)
                emit Deposit(_account, _stakingToken, _amount);
            else
                emit DepositNotAvailable(_account, _stakingToken, _amount);
    }

    /// @notice internal function to deal with withdraw staking token
    function _withdraw(address _stakingToken, address _account, uint256 _amount, bool _isVlMgp) internal {
        _harvestAndUnstake(_stakingToken, _account, _amount, _isVlMgp);

        if (!_isVlMgp)
            IERC20(tokenToPoolInfo[_stakingToken].stakingToken).safeTransfer(address(msg.sender), _amount);
        emit Withdraw(_account, _stakingToken, _amount);
    }

    function _harvestAndUnstake(address _stakingToken, address _account, uint256 _amount, bool _isVlMgp) internal {
        updatePool(_stakingToken);

        UserInfo storage user = userInfo[_stakingToken][_account];

        if (!_isVlMgp && user.available < _amount)
            revert WithdrawAmountExceedsStaked();
        else if(user.amount < _amount && _isVlMgp)
            revert UnlockAmountExceedsLocked();
        
        _harvestMGP(_stakingToken, _account);
        _harvestBaseRewarder(_stakingToken, _account);

        user.amount = user.amount - _amount;
        
        if(!_isVlMgp)
            user.available = user.available - _amount;
        user.rewardDebt = (user.amount * tokenToPoolInfo[_stakingToken].accMGPPerShare) / 1e12;
    }
