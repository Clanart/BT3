### Title
Java `TextFormat` default string printer omits control-character escaping, allowing raw terminal-escape-sequence injection into `DebugString`/`toString()` output - (File: `java/core/src/main/java/com/google/protobuf/TextFormat.java`)

### Summary
The BusyBox CVE-2017-16544 root cause is that `add_match` in `libbb/lineedit.c` forwarded attacker-controlled filenames to the terminal without stripping/escaping control bytes, letting arbitrary ANSI/VT escape sequences reach the terminal renderer. The transferable invariant is: *any string value that will be rendered to a text sink (including a terminal) must have all control bytes (and especially ESC, 0x1B) escaped before being emitted verbatim.* In this Protobuf checkout, the Java `TextFormat.Printer` STRING-printing path has exactly this gap: when the printer is configured (or defaults) to non-UTF8 escaping mode, it escapes only `"`, `\`, and `\n`, leaving every other C0 control character — including ESC (0x1B), CR, BEL, backspace, vertical tab, form feed — completely unescaped in the emitted text. A caller that logs or prints `TextFormat.printToString(message)` / `message.toString()` to a terminal, and whose message contains an attacker-controlled `string` field (parsed from an untrusted binary/ProtoJSON payload), will forward raw escape sequences straight to the terminal, mirroring the BusyBox flaw.

### Finding Description
`TextFormat.Printer.printFieldValue` handles the `STRING` case as: [1](#0-0) 

```java
case STRING:
  generator.print("\"");
  generator.print(
      escapeNonAscii
          ? TextFormatEscaper.escapeText((String) value)
          : escapeDoubleQuotesAndBackslashes((String) value).replace("\n", "\\n"));
  generator.print("\"");
  break;
```

Only the `escapeNonAscii == true` branch calls `TextFormatEscaper.escapeText`, which fully escapes all C0 control bytes (0x00–0x1F) and DEL (0x7F) as octal sequences: [2](#0-1) 

The `escapeNonAscii == false` branch — reached via `escapeDoubleQuotesAndBackslashes(...).replace("\n", "\\n")` — only neutralizes double quotes, backslashes, and literal `\n`. It does **not** touch ESC (0x1B), CR (0x0D), BEL (0x07), backspace, tab, vertical tab, or form feed. Any of these bytes present in a parsed `string` field value pass through into the printed TextFormat output byte-for-byte.

This is a genuine internal inconsistency, not an intentional format choice: the C++ implementation's default field printer (`TextFormat::FastFieldValuePrinter::PrintString`) and the "hardened" printer both escape *every* control byte via `ContainsCharactersToCEscape`/`absl::CEscape` or `HardenedPrintString`: [3](#0-2) [4](#0-3) 

and upb's C encoder (`_upb_HardenedPrintString`) enforces the identical invariant that any byte `< 32` "definitely needs escape": [5](#0-4) 

So the C++/upb backends never let a raw control byte reach the output stream regardless of mode, while the Java backend's non-UTF8-escaping branch does — this is the "missing safety invariant" that transfers from the BusyBox analog: unsanitized attacker bytes reaching a text/terminal sink.

### Impact Explanation
An ordinary client can supply a `string` field value (via a supported public parse API, e.g. `Message.parseFrom(bytes)` or ProtoJSON parsing) containing arbitrary bytes, including ESC (0x1B) sequences (CSI/OSC escape codes). If the consuming Java application later calls `message.toString()`, `TextFormat.printToString(message)`, or logs the message via a logger that writes to a terminal/TTY (a common debugging/operational pattern), those raw escape sequences are written to the terminal unescaped. Depending on the terminal emulator, this can move the cursor, overwrite visible content, hide/spoof text, or in vulnerable/legacy terminal emulators trigger more serious effects (e.g., title-bar/clipboard manipulation via OSC 52, or query-response sequences that echo data back into the input stream) — the same class of impact described in the BusyBox report (terminal escape-sequence execution from unsanitized attacker strings). This does not achieve memory corruption or RCE within Protobuf itself; the impact is confined to terminal-rendering integrity/spoofing in the consuming application, contingent on that application printing untrusted parsed message content to a terminal.

### Likelihood Explanation
Likelihood is moderate: it requires (1) the application to print/log a full message via `toString()`/`TextFormat.printToString` to a terminal, and (2) the printer to be operating in the non-UTF8-escaping mode (`escapeNonAscii == false`), which per the code's own escaping design is a legacy/default path in Java's TextFormat implementation. This is a very common debugging pattern (`System.out.println(message)`, default `toString()` on a proto), so the reachable surface is realistic, but the actual security impact depends entirely on how/where the consuming application renders the output. I was unable to confirm within the available iterations the exact default value of the `escapeNonAscii` flag as configured by `TextFormat.printer()` / `Message.toString()` in this checkout (the setter and default-initialization code were not fully retrieved before the tool budget was exhausted); this should be verified directly in the repository before treating the default path as confirmed.

### Recommendation
Make the non-UTF8-escaping STRING branch in `TextFormat.printFieldValue` escape all C0 control characters (0x00–0x1F) and DEL (0x7F), not just `"`, `\`, and `\n` — mirroring `TextFormatEscaper.escapeText`'s and the C++/upb backends' full control-byte escaping — so that both escaping modes uphold the same "no raw control bytes in emitted text" invariant.

### Proof of Concept
1. Construct any proto message with a `string` field, e.g. `optional_string`.
2. Set its value via the public binary parse API to a value containing an embedded ESC sequence, e.g. bytes for `"\u001b[31mFAKE ERROR\u001b[0m"` (CSI red-text sequence), delivered as a length-delimited string field in a binary-encoded message and parsed with `MyProto.parseFrom(bytes)`.
3. Call `message.toString()` (or `TextFormat.printer().printToString(message)` with default settings) and write the result to a terminal (e.g., `System.out.println`).
4. Compare against `TextFormatEscaper.escapeText` behavior: in the `escapeNonAscii=true` path the ESC byte (0x1B) would be rendered as `\033`; in the default/non-UTF8 path demonstrated here, it is emitted as the raw 0x1B byte, causing the terminal to interpret/render the injected escape sequence instead of printing literal text — reproducing the BusyBox-class "unsanitized escape sequence reaches terminal" condition.

  private static final String[] REPLACEMENT_CHARS;

  static {
    REPLACEMENT_CHARS = new String[128];
    for (int i = 0; i <= 0x1f; i++) {
      REPLACEMENT_CHARS[i] = String.format("\\%03o", i);
    }
    REPLACEMENT_CHARS[0x7f] = "\\177";
    REPLACEMENT_CHARS['\"'] = "\\\"";
    REPLACEMENT_CHARS['\''] = "\\\'";
    REPLACEMENT_CHARS['\\'] = "\\\\";
    REPLACEMENT_CHARS['\t'] = "\\t";
    REPLACEMENT_CHARS['\b'] = "\\b";
    REPLACEMENT_CHARS['\n'] = "\\n";
    REPLACEMENT_CHARS['\r'] = "\\r";
    REPLACEMENT_CHARS['\f'] = "\\f";
    REPLACEMENT_CHARS[0x07] = "\\a";
    REPLACEMENT_CHARS[0x0b] = "\\v";
  }

  /** Like {@link #escapeBytes(ByteString)}, but escapes a text string. */
  static String escapeText(String input) {
    int len = input.length();
    StringBuilder builder = null;
    int last = 0;
    for (int i = 0; i < len; i++) {
      char c = input.charAt(i);
      // If there are any characters outside of ASCII range (> 127) we eagerly convert to UTF and
      // escape on those bytes (including quotes as well). Note that escaping to UTF8 bytes instead
      // of \\u sequences is itself somewhat nonsensical, but JavaProto has behaved this way for a
      // long time, and changing the behavior would be disruptive.
      if (c > 127) {
        return escapeBytes(input.getBytes(StandardCharsets.UTF_8));
      }
      String replacement = REPLACEMENT_CHARS[c];
      if (replacement == null) {
        continue;
      }
      if (builder == null) {
        builder = new StringBuilder(len + 16);
      }
      if (last < i) {
        builder.append(input, last, i);
      }
      builder.append(replacement);
      last = i + 1;
    }
    // If builder is null, we made it through the entire input without needing any escaping,
    // so we can return the original string verbatim with zero allocations.
    if (builder == null) {
      return input;
    }
    if (last < len) {
      builder.append(input, last, len);
    }
    return builder.toString();
  }

void TextFormat::Printer::HardenedPrintString(
    absl::string_view src, TextFormat::BaseTextGenerator* generator) {
  // Print as UTF-8, while guarding against any invalid UTF-8 in the string
  // field.
  //
  // If in the future we have a guaranteed invariant that invalid UTF-8 will
  // never be present, we could avoid the UTF-8 check here.

  generator->PrintLiteral("\"");
  while (!src.empty()) {
    size_t n = SkipPassthroughBytes(src);
    if (n != 0) {
      generator->PrintString(src.substr(0, n));
      src.remove_prefix(n);
      if (src.empty()) break;
    }

    // If repeated calls to CEscape() and PrintString() are expensive, we could
    // consider batching them, at the cost of some complexity.
    generator->PrintString(absl::CEscape(src.substr(0, 1)));
    src.remove_prefix(1);
  }
  generator->PrintLiteral("\"");
}

bool ContainsCharactersToCEscape(absl::string_view val) {
  bool needs_escape = false;
  for (unsigned char c : val) {
    needs_escape |=
        ((c < 32) | (c > 126) | (c == '"') | (c == '\'') | (c == '\\'));
  }
  return needs_escape;
}

}  // namespace

void TextFormat::FastFieldValuePrinter::PrintString(
    const std::string& val, BaseTextGenerator* generator) const {
  generator->PrintLiteral("\"");
  if (!val.empty()) {
    if (ABSL_PREDICT_FALSE(ContainsCharactersToCEscape(val))) {
      generator->PrintString(absl::CEscape(val));
    } else {
      generator->PrintString(val);
    }
  }
  generator->PrintLiteral("\"");
}

// Returns true if `ch` needs to be escaped in TextFormat, independent of any
// UTF-8 validity issues.
UPB_INLINE bool UPB_PRIVATE(_upb_DefinitelyNeedsEscape)(unsigned char ch) {
  if (ch < 32) return true;
  switch (ch) {
    case '\"':
    case '\'':
    case '\\':
    case 127:
      return true;
  }
  return false;
}

UPB_INLINE bool UPB_PRIVATE(_upb_AsciiIsPrint)(unsigned char ch) {
  return ch >= 32 && ch < 127;
}

// Returns true if this is a high byte that requires UTF-8 validation.  If the
// UTF-8 validation fails, we must escape the byte.
UPB_INLINE bool UPB_PRIVATE(_upb_NeedsUtf8Validation)(unsigned char ch) {
  return ch > 127;
}

// Returns the number of bytes in the prefix of `val` that do not need escaping.
// This is like utf8_range::SpanStructurallyValid(), except that it also
// terminates at any ASCII char that needs to be escaped in TextFormat (any char
// that has `DefinitelyNeedsEscape(ch) == true`).
//
// If we could get a variant of utf8_range::SpanStructurallyValid() that could
// terminate on any of these chars, that might be more efficient, but it would
// be much more complicated to modify that heavily SIMD code.
UPB_INLINE size_t UPB_PRIVATE(_SkipPassthroughBytes)(const char* ptr,
                                                     size_t size) {
  for (size_t i = 0; i < size; i++) {
    unsigned char uc = ptr[i];
    if (UPB_PRIVATE(_upb_DefinitelyNeedsEscape)(uc)) return i;
    if (UPB_PRIVATE(_upb_NeedsUtf8Validation)(uc)) {
      // Find the end of this region of consecutive high bytes, so that we only
      // give high bytes to the UTF-8 checker.  This avoids needing to perform
      // a second scan of the ASCII characters looking for characters that
      // need escaping.
      //
      // We assume that high bytes are less frequent than plain, printable ASCII
      // bytes, so we accept the double-scan of high bytes.
      size_t end = i + 1;
      for (; end < size; end++) {
        if (!UPB_PRIVATE(_upb_NeedsUtf8Validation)(ptr[end])) break;
      }
      size_t n = end - i;
      size_t ok = utf8_range_ValidPrefix(ptr + i, n);
      if (ok != n) return i + ok;
      i += ok - 1;
    }
  }
  return size;
}

UPB_INLINE void UPB_PRIVATE(_upb_HardenedPrintString)(txtenc* e,
