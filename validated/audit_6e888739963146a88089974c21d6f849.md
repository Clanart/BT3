### Title
Gasless swap admission uses `getAmountIn` from mutable pool reserves at check time, permitting sandwich manipulation of the actual on-chain exchange rate between mempool admission and block-inclusion execution - (File: kaiax/gasless/impl/tx_pool.go)

### Summary
The LAURA report describes a pair-balance manipulation: an attacker uses flash-loaned funds to distort a Uniswap V2 pair's live reserves so that a subsequent operation computed off the *current* (manipulated) reserves produces a favorable/incorrect result, letting the attacker drain the pair. The reachable analog in this repo is `kaiax`'s gasless-transaction (KIP-247) admission logic, which similarly derives a critical economic bound (`requiredAmountIn`) from the DEX pair's live reserves at validation time via `GaslessSwapRouter.GetAmountIn`, and that value is used only to gate mempool promotion, not to bind execution.

### Finding Description
`checkBalanceForSwap` in `kaiax/gasless/impl/tx_pool.go` computes the minimum acceptable `amountIn` for a gasless swap by querying the router's `GetAmountIn(token, minAmountOut)` against the chain's current head state: [1](#0-0) 

This `GetAmountIn` call reads the underlying DEX pair's reserves (`getReserves`) at the time of the check, exactly the state variable that the LAURA-style attack manipulates (via flash loans, `swapExactTokensForTokensSupportingFeeOnTransferTokens`, `addLiquidity`, then draining) within a single atomic transaction/bundle: [2](#0-1) 

Because this check happens purely at tx-pool admission/promotion time (`isSwapTxReady` → `IsExecutable` → `VerifyExecutable`, and separately `checkBalanceForSwap` in `GetCheckBalance`), and the same sender can craft an unprivileged transaction bundle where a preceding transaction manipulates the target token's pair reserves in the same block before the gasless swap is executed, the actual repay/swap-amount bound enforced by the router contract at execution time can be computed against reserves that differ from those seen at admission time: [3](#0-2) [4](#0-3) 

The bundling logic (`ExtractTxBundles`) places `[LendTxGenerator, ApproveTx?, SwapTx]` as a fixed unit, but nothing prevents an attacker-controlled prior transaction elsewhere in the same block (or a preceding transaction from the same sender within a bundle-adjacent position) from moving the pair reserves that the `GetAmountIn`-based sanity check assumed were valid: [5](#0-4) 

Because gasless swap fee-repayment (`amountRepay`) is denominated in KAIA lent by the block proposer (`LendTxGenerator`), and the sender's actual token-to-repay conversion happens via `swapForGas` at execution time against whatever reserves exist then, a reserve manipulation between admission-time `GetAmountIn` evaluation and actual execution can cause the proposer-funded gas loan (`amountRepay`) to not be fully recovered, or cause the swap to execute at a manipulated (attacker-favorable) rate, effectively reproducing the "compute critical invariant from live, attacker-influenced AMM reserves" root cause from the report.

### Impact Explanation
If the on-chain `GaslessSwapRouter.swapForGas` contract does not independently and atomically re-verify against post-manipulation reserves (which we cannot confirm since only the ABI/Go bindings for this contract are indexed, not its Solidity source), an attacker can:
- Get a gasless swap tx admitted/promoted using a stale, favorable `GetAmountIn` result,
- Manipulate the underlying DEX pair reserves for the target token immediately before the bundle executes in the same block,
- Cause the proposer-funded `amountRepay` (lent KAIA) to be under-collected, or extract value from the pool/proposer-lending mechanism.

This falls under fee/gasless settlement theft or reward/fee-delegation abuse, reachable purely by a gasless-transaction sender (unprivileged), matching the allowed analog categories.

### Likelihood Explanation
Medium. The `BalanceCheckLevelSwapAmount` check is a mempool heuristic, not an execution-time guarantee, and is configurable/optional (`ShouldCheckSwapAmount`), so misconfigured or default-node deployments only partially mitigate this. Actual exploitability depends on validation logic inside the (non-indexed) `GaslessSwapRouter.sol` contract itself, which could not be directly confirmed in the codebase provided — this is a genuine gap in verification, not a confirmed absence of protection.

### Recommendation
- Ensure `GaslessSwapRouter.swapForGas` (Solidity contract, not present in the indexed Go-bindings-only codebase) atomically recomputes and enforces `amountIn`/`amountRepay` bounds against reserves observed within the same execution context, not relying on any off-chain precomputed value.
9- In `kaiax/gasless/impl/tx_pool.go`, treat `checkBalanceForSwap`'s `GetAmountIn`-based check strictly as a DoS/spam filter and never as a security guarantee, and document this explicitly.
- Consider re-validating swap admission against reserves read from the exact state the block builder will use immediately prior to bundle execution, reducing the TOCTOU window, or reject bundles where the target pair's reserves changed materially between admission and inclusion.

### Proof of Concept
Could not be fully constructed: the exploit's feasibility hinges on the internal logic of `GaslessSwapRouter.swapForGas` (Solidity contract), whose source is not present in the indexed portion of this repository — only its ABI/Go bindings (`contracts/bindings/kip247/GaslessSwapRouter.go`) were available. Due to index size limits, some file contents (e.g. the actual `GaslessSwapRouter.sol` and any KIP-247 system-contract Solidity sources) may not be available to Ask; a full Devin session with complete repository access would be needed to inspect the contract's execution-time checks and confirm whether the TOCTOU window described above is actually exploitable end-to-end.

	return func(tx *types.Transaction) error {
		if approveArgs, ok := decodeApproveTx(tx, g.signer); ok {
			return g.checkBalanceForApprove(approveArgs)

		if swapArgs, ok := decodeSwapTx(tx, g.signer); ok {
			return g.checkBalanceForSwap(swapArgs, tx.Nonce())
		}
		return errors.New("not a gasless transaction") // should not happen because IsModuleTx is called before GetCheckBalance
	}
}

// VerifyExecutable checks if the given transactions form a valid gasless transaction
// It returns an error explaining why the transaction is not executable if it's not,
// and a boolean indicating whether the transaction is executable
func (g *GaslessModule) VerifyExecutable(approveTxOrNil, swapTx *types.Transaction) error {
	// Sx.
	swapArgs, ok := decodeSwapTx(swapTx, g.signer)
	if !ok {
		return ErrDecodeSwapTx
	}
	if !g.isSwapTx(swapArgs) {
		return ErrSwapTxInvalid
	}

	// Conditions involving ApproveTx
	if approveTxOrNil != nil {
		// Ax.
		approveArgs, ok := decodeApproveTx(approveTxOrNil, g.signer)
		if !ok {
			return ErrDecodeApproveTx
		}
		if !g.isApproveTx(approveArgs) {
			return ErrApproveTxInvalid
		}
		// AP1.
		if approveArgs.Sender != swapArgs.Sender {
			return ErrDifferentSenders
		}
		// SP1.
		if approveArgs.Token != swapArgs.Token {
			return fmt.Errorf("%w: approve token %s, swap token %s", ErrDifferentTokens, approveArgs.Token.Hex(), swapArgs.Token.Hex())
		}
		// SP2.
		if approveArgs.Amount.Cmp(swapArgs.AmountIn) < 0 {
			return fmt.Errorf("%w: approve amount %s, required amount %s", ErrInsufficientApproveAmount, approveArgs.Amount.String(), swapArgs.AmountIn.String())
		}
		// SP3.
		if approveTxOrNil.Nonce()+1 != swapTx.Nonce() {
			return fmt.Errorf("%w: approve nonce %d, swap nonce %d (expected %d)", ErrNonSequentialNonce, approveTxOrNil.Nonce(), swapTx.Nonce(), approveTxOrNil.Nonce()+1)
		}
		if nonce := g.getCurrentStateNonce(approveArgs.Sender); nonce != approveTxOrNil.Nonce() {
			return fmt.Errorf("%w: approve nonce %d, current nonce %d", ErrApproveNonceNotCurrent, approveTxOrNil.Nonce(), nonce)
		}
	} else {
		// SP3.
		if nonce := g.getCurrentStateNonce(swapArgs.Sender); nonce != swapTx.Nonce() {
			return fmt.Errorf("%w: swap nonce %d, current nonce %d", ErrSwapNonceNotCurrent, swapTx.Nonce(), nonce)
		}
	}

	// SP4.
	if swapArgs.AmountRepay.Cmp(repayAmount(approveTxOrNil, swapTx)) != 0 {
		return fmt.Errorf("%w: got %s, expected %s", ErrIncorrectRepayAmount, swapArgs.AmountRepay.String(), repayAmount(approveTxOrNil, swapTx).String())
	}

	return nil
}

func (g *GaslessModule) ExtractTxBundles(txs []*types.Transaction, prevBundles []*builder.Bundle) []*builder.Bundle {
	// there are only at most two gasless transactions in pending for a sender
	bundles := []*builder.Bundle{}
	approveTxs := map[common.Address]*types.Transaction{}
	targetTxHash := common.Hash{}
	for _, tx := range txs {
		addr, err := types.Sender(g.signer, tx)
		if err != nil {
			continue
		}
		if g.IsApproveTx(tx) {
			approveTxs[addr] = tx
		} else if g.IsSwapTx(tx) && g.IsExecutable(approveTxs[addr], tx) {
			bundleTxs := builder.NewTxOrGenList(g.GetLendTxGenerator(approveTxs[addr], tx))
			if approveTxs[addr] != nil {
				bundleTxs = append(bundleTxs, builder.NewTxOrGenFromTx(approveTxs[addr]))
			}
			bundleTxs = append(bundleTxs, builder.NewTxOrGenFromTx(tx))

			b := builder.NewBundle(
				bundleTxs,
				targetTxHash,
				false,
			)

			targetTxHash = tx.Hash()

			isConflict := false
			for _, prev := range append(prevBundles, bundles...) {
				if prev.IsConflict(b) {
					isConflict = true
					break
				}
			}
			if isConflict {
				// Gasless transactions will just fail even if they aren't bundled.
				continue
			}
			bundles = append(bundles, b)
		} else {
			targetTxHash = tx.Hash()
		}
	}
	return bundles
}
