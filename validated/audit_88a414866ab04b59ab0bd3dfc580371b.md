### Title
Untrusted `ReceivedOutput` deserialization can report arbitrary unspendable Bitcoin funds - ([File: networks/bitcoin/src/wallet/mod.rs](networks/bitcoin/src/wallet/mod.rs))

### Summary
`ReceivedOutput::read` accepts an attacker-supplied scalar offset, `TxOut`, and `OutPoint` without proving that the output exists on-chain or corresponds to the scanner key for which the offset was registered. A forged serialized `ReceivedOutput` can therefore cause downstream balance/accounting code to report arbitrary Bitcoin as received even though the output is not controlled by, or spendable through, the expected threshold key.

### Finding Description
`ReceivedOutput::read` deserializes three independent fields: a secp256k1 scalar, a consensus-decoded `TxOut`, and a consensus-decoded `OutPoint`. The only validations are canonical scalar decoding and syntactic Bitcoin consensus decoding. [1](#0-0) 

The resulting object directly exposes the attacker-selected `TxOut` value through `ReceivedOutput::value()`. [2](#0-1) 

No check ties the `offset` to a previously registered `Scanner`, validates that `output.script_pubkey` is the expected tweaked key, or proves that `outpoint` identifies a real confirmed UTXO. [3](#0-2) 

The later signing path does independently reject an output whose script does not equal the threshold key tweaked by the claimed offset, so the forged object is not necessarily convertible into a valid spend. [4](#0-3) 

### Impact Explanation
An unprivileged party who can supply bytes to `ReceivedOutput::read` can claim an arbitrary `TxOut` value and arbitrary transaction outpoint as a received output. [3](#0-2) 

If the caller treats a successfully deserialized `ReceivedOutput` as a scanned receipt, it can report funds as received even though Serai cannot spend them with the intended threshold key. [5](#0-4) 

This matches the concrete impact class of “funds reported received that are not spendable”; it is not remote code execution, and exploitation requires a production path that feeds attacker-controlled serialization to this API.

### Likelihood Explanation
The byte format is public and fixed: a canonical secp256k1 scalar followed by Bitcoin consensus `TxOut` and `OutPoint` encodings. [6](#0-5) 

An attacker does not need to solve a discrete logarithm or forge a proof because deserialization performs no cryptographic or blockchain-backed consistency check. [3](#0-2) 

Likelihood is bounded by whether the serialized representation is exposed to untrusted storage, messages, backups, or peer input rather than being exclusively generated internally by `Scanner::scan_transaction`. [7](#0-6) 

### Recommendation
Treat `ReceivedOutput::read` as a parser for an untrusted claim, not as proof of ownership. After deserialization, verify the `OutPoint` against the Bitcoin blockchain and verify `output.script_pubkey` against the expected scanner-derived script for the claimed offset.

At a minimum, bind the expected base key or scanner identity to the serialized form and reject records whose `offset` does not derive the observed Taproot output. The existing signing-time comparison in `SignableTransaction::multisig` should be moved into, or duplicated during, ingestion/accounting so invalid claims cannot first be counted as received funds. [8](#0-7) 

### Proof of Concept
Conceptually, the forged byte string is:

```text
received_output :=
    secp256k1_scalar(1)
  || consensus_txout(value = arbitrary_amount,
                     script_pubkey = arbitrary_script)
  || consensus_outpoint(txid = arbitrary_hash,
                        vout = arbitrary_index)
```

`Secp256k1::read_F` accepts the canonical encoding of `1`, while `TxOut::consensus_decode` and `OutPoint::consensus_decode` accept syntactically valid attacker-chosen objects. [3](#0-2) 

For example, a caller can encode:

```rust
// Pseudocode over bitcoin consensus encoding.
let mut bytes = Vec::new();

// Canonical secp256k1 scalar 1.
bytes.extend([0; 31]);
bytes.push(1);

// TxOut: arbitrary satoshi value and arbitrary script_pubkey.
bytes.extend(21_000_000_000u64.to_le_bytes()); // value
bytes.push(0);                                  // empty script is syntactically valid

// OutPoint: arbitrary txid and vout.
bytes.extend([0x11; 32]);
bytes.extend(0u32.to_le_bytes());

let forged = bitcoin_serai::wallet::ReceivedOutput::read(&mut bytes.as_slice()).unwrap();
assert_eq!(forged.value(), 21_000_000_000);
```

The parser returns a `ReceivedOutput` despite the empty script not being a scanner-generated Taproot output and the outpoint not being proven to exist. [1](#0-0)

  /// Read a ReceivedOutput from a generic satisfying Read.
  #[cfg(feature = "std")]
  pub fn read<R: Read>(r: &mut R) -> io::Result<ReceivedOutput> {
    let offset = Secp256k1::read_F(r)?;
    let output;
    let outpoint;
    {
      let mut buf_r = BufReader::with_capacity(0, r);
      output =
        TxOut::consensus_decode(&mut buf_r).map_err(|_| io::Error::other("invalid TxOut"))?;
      outpoint =
        OutPoint::consensus_decode(&mut buf_r).map_err(|_| io::Error::other("invalid OutPoint"))?;
    }
    Ok(ReceivedOutput { offset, output, outpoint })
  }
