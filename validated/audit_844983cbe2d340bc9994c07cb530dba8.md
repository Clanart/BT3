Found a solid local analog: in `HyperbridgeLzEndpoint.sol`, the `Pausable` "stop switch" is applied to some entry points but not to `retryPayload`, which performs the same privileged action (delivering an inbound message to an OApp) as the paused `onAccept` path.

### Title
`HyperbridgeLzEndpoint.retryPayload()` bypasses the `whenNotPaused` guard, defeating the pause stop-switch - (File: sdk/packages/lz-endpoint/contracts/HyperbridgeLzEndpoint.sol)

### Summary
`HyperbridgeLzEndpoint` inherits OpenZeppelin `Pausable` and gates the two message-delivery entry points, `send()` and `onAccept()`, with `whenNotPaused` so the owner can halt "all cross-chain operations (send and receive)" as documented. However `retryPayload()`, which performs the exact same privileged action — calling `lzReceive` on a destination OApp — has no `whenNotPaused` modifier at all, so pausing the contract does not stop it.

### Finding Description
`pause()`/`unpause()` are documented to pause "all cross-chain operations (send and receive)": [1](#0-0) 

`send()` and `onAccept()` both correctly enforce `whenNotPaused`: [2](#0-1) [3](#0-2) 

`retryPayload()` is the recovery path that "mirrors {onAccept}'s direct call to the OApp" and is explicitly "permissionless: anyone may push a stuck payload through", yet it is declared without `whenNotPaused`: [4](#0-3) 

This is the same bug class as the report's `isClosed()` always returning `false`: a guard (`Pausable`'s `_paused` state / `whenNotPaused` modifier) exists, is wired into some of the state-mutating checks, but the check is simply never consulted on one of the functions that performs the exact same gated action. The pause is therefore not an actual stop-switch — it only stops new inbound deliveries via `onAccept` and new outbound sends via `send()`, but any already-stored failed payload can still be forced through by anyone at any time, including while the contract is paused.

### Impact Explanation
An owner pausing the endpoint (e.g., in response to a detected issue with a specific OApp's `lzReceive`, a bug requiring a freeze while a fix/upgrade is prepared, or any other operational reason to halt processing) cannot actually stop delivery of already-queued payloads. Since `retryPayload` is permissionless, any external caller can continue to trigger `lzReceive` execution on arbitrary receiver OApps for previously stored payloads while the protocol is supposedly frozen — directly contradicting the pause invariant and enabling unauthorized execution during a period the operator explicitly intended to halt. This can cause unintended state changes/fund movement in downstream OApps (e.g., completion of a cross-chain transfer) at a time the operator was relying on the pause to prevent exactly that.

### Likelihood Explanation
High: the condition requires no privileged actor, no relayer/prover compromise, and no malformed proof — merely (1) any prior inbound message whose `lzReceive` reverted (a normal, expected occurrence per the code's own comments about retry/recovery), and (2) the owner calling `pause()`. Both are ordinary operational states already anticipated by the contract's design; the missing modifier is a straightforward oversight.

### Recommendation
Add the `whenNotPaused` modifier to `retryPayload()` (and audit `clear`, `skip`, `nilify`, `burn` for the same intended scope, deciding case-by-case whether recovery bookkeeping-only actions should remain available while paused, but any function that calls into `lzReceive` should be paused consistently with `send`/`onAccept`):
```solidity
function retryPayload(
    address receiver,
    Origin calldata origin,
    bytes32 guid,
    bytes calldata message
) external payable whenNotPaused {
```

### Proof of Concept
1. OApp `X`'s `lzReceive` reverts once (e.g. transient failure) during `onAccept`, so `_inboundPayloadHashes[X][srcEid][sender][nonce]` is populated per `onAccept`'s catch block [5](#0-4) .
2. Owner calls `pause()` intending to halt all cross-chain delivery, e.g. because a vulnerability in `X.lzReceive` was discovered.
3. Any address calls `retryPayload(X, origin, guid, message)` with the matching stored hash; because the function carries no `whenNotPaused` modifier, the call succeeds and `ILayerZeroReceiver(X).lzReceive(...)` executes despite the pause [6](#0-5) .
4. The pause has no effect on this delivery path, contradicting the documented guarantee that pausing halts "all cross-chain operations."

```text
    /**
     * @notice Retries an inbound delivery whose OApp `lzReceive` previously reverted in {onAccept}.
     * @dev Mirrors {onAccept}'s direct call to the OApp (the adapter is the caller, so the OApp's
     * `onlyEndpoint` check still passes). Permissionless: anyone may push a stuck payload through
     * once it is executable again. On success the stored payload hash is cleared; if delivery
     * reverts again the whole call reverts and the payload remains recoverable.
     * @param receiver The destination OApp
     * @param origin The (srcEid, sender, nonce) of the stored payload
     * @param guid The original message guid
     * @param message The original message payload (must match the stored hash)
     */
    function retryPayload(
        address receiver,
        Origin calldata origin,
        bytes32 guid,
        bytes calldata message
    ) external payable {
        bytes32 stored = _inboundPayloadHashes[receiver][origin.srcEid][origin.sender][origin.nonce];
        if (stored == bytes32(0) || stored == NIL_PAYLOAD_HASH || stored != keccak256(abi.encode(guid, message))) {
            revert InvalidPayloadHash();
        }

        // Clear first; if the retry reverts, this deletion rolls back with the rest of the tx and
        // the payload remains recoverable.
        delete _inboundPayloadHashes[receiver][origin.srcEid][origin.sender][origin.nonce];

        ILayerZeroReceiver(receiver).lzReceive{value: msg.value}(origin, guid, message, msg.sender, "");
        emit InboundPayloadResolved(receiver, origin.srcEid, origin.sender, origin.nonce);
    }
```
