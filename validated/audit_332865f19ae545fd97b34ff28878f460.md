## Analysis Summary

The Django CVE is a DoS caused by processing attacker-controlled strings without adequate length bounds before expensive parsing work (CWE-130/CWE-770). Searching the chia codebase for an equivalent pattern — an entry point reachable by an unprivileged wallet/RPC caller that removes or bypasses an existing length safeguard before parsing untrusted string data — leads to the offer bech32 decoding path.

### Title
Offer bech32 decoding removes the length cap, allowing unbounded-size untrusted input to be parsed - (File: `chia/wallet/trading/offer.py`)

### Summary
`bech32_decode()` in `chia/util/bech32m.py` enforces a `max_length` guard (default 90) specifically to bound the amount of work spent validating/decoding a bech32 string before any checksum or data-conversion work is performed. `Offer.from_bech32()` explicitly discards this protection by calling `bech32_decode(offer_bech32, max_length=len(offer_bech32))`, meaning the length check can never reject an oversized input. [1](#0-0) [2](#0-1) 

### Finding Description
`bech32_decode()` validates every character of the input (`ord(x)` range check, case check, `CHARSET.find(x)` lookups) and computes a checksum over the full data before returning, and this cost scales with input length. The function signature caps this cost via `max_length: int = 90`, which is appropriate for addresses/HRPs. [1](#0-0) 

`Offer.from_bech32()`, however, passes `max_length=len(offer_bech32)`, i.e., the cap is always satisfied regardless of how large the supplied string is, effectively disabling the guard for offer inputs: [2](#0-1) 

This code path is reachable by an unprivileged actor through several attacker-controlled entry points:
- `TakeOffer.parsed_offer` decodes `self.offer` (a raw string from the RPC/CLI caller or an offer counterparty's shared offer blob) via `Offer.from_bech32`. [3](#0-2) 
- The wallet CLI `take_offer` command reads the offer text directly from a file or hex/bech32 blob supplied by the counterparty and calls `Offer.from_bech32(offer_hex)`. [4](#0-3) 

After the (unbounded) decode, the code proceeds to `convertbits()` (another O(n) pass) and then attempts decompression/`WalletSpendBundle.from_bytes` parsing on the resulting buffer, all scaling with the attacker-chosen size: [5](#0-4) 

Because the length guard that exists specifically to bound this parsing cost is neutralized for the offer path, a single crafted "offer" string of attacker-chosen size (megabytes to gigabytes) forces the receiving wallet/RPC process to spend CPU and memory proportional to that size purely to determine the input is invalid, before any real puzzle/asset validation occurs.

### Impact Explanation
An offer counterparty or local wallet RPC caller can supply an arbitrarily large string to `take_offer`, `check_offer_validity`, or offer-summary RPCs. This causes disproportionate CPU/memory consumption on the wallet process handling the offer, which can stall or degrade transaction processing for that wallet — a spend/action-triggered resource exhaustion analogous to the Django `get_supported_language_variant()` DoS class (CWE-770: missing resource-consumption limits on attacker-controlled string length).

### Likelihood Explanation
Reachability is straightforward: any party who can hand a wallet user or its RPC an "offer" string (a normal, expected interaction in the offers/trades flow) can substitute an oversized string instead of a legitimate offer. No privileged access, signature, or on-chain action is required to trigger the parsing cost — only that the target voluntarily loads/checks the untrusted offer text, which is the default expected user/RPC workflow for offers.

### Recommendation
Restore a bounded `max_length` in `Offer.from_bech32()` (e.g., a generous but fixed ceiling based on realistic maximum offer/spend-bundle size) instead of `len(offer_bech32)`, and reject oversized offer strings before performing checksum/conversion/decompression work. Apply an early raw-length check on the input string prior to calling `bech32_decode` for defense in depth.

### Proof of Concept
1. Construct a very large ASCII string of valid bech32 charset characters (e.g., several hundred MB) with an `offer1...` prefix (checksum need not even be correct if length rejection is the goal, but for full-cost demonstration compute a valid checksum over a large payload).
2. Submit this string as `TakeOffer.offer` to the wallet RPC `take_offer` endpoint, or pass it as the offer argument to the `chia wallet take_offer` CLI command, or to `check_offer_validity`/`get_offer_summary`.
3. Observe that `Offer.from_bech32()` invokes `bech32_decode(offer_bech32, max_length=len(offer_bech32))`, which never trips the length guard, and the wallet process spends CPU/memory proportional to the full attacker-chosen size performing charset validation, checksum computation, and `convertbits` before failing (or succeeding) — demonstrating the missing resource bound relative to the intended 90-character cap in `bech32_decode`. def bech32_decode(bech: str, max_length: int = 90) -> tuple[str | None, list[int] | None]:
```python
    """Validate a Bech32 string, and determine HRP and data."""
    bech = bech.strip()
    if (any(ord(x) < 33 or ord(x) > 126 for x in bech)) or (bech.lower() != bech and bech.upper() != bech):
        return (None, None)
    bech = bech.lower()
    pos = bech.rfind("1")
    if pos < 1 or pos + 7 > len(bech) or len(bech) > max_length:
        return (None, None)
    if not all(x in CHARSET for x in bech[pos + 1 :]):
        return (None, None)
    hrp = bech[:pos]
    data = [CHARSET.find(x) for x in bech[pos + 1 :]]
    if not bech32_verify_checksum(hrp, data):
        return (None, None)
    return hrp, data[:-6]
```

```python
    def to_bech32(self, prefix: str = "offer", compression_version: int | None = None) -> str:
        offer_bytes = self.compress(version=compression_version)
        encoded = bech32_encode(prefix, convertbits(list(offer_bytes), 8, 5))
        return encoded

    @classmethod
    def from_bech32(cls, offer_bech32: str) -> Offer:
        _hrpgot, data = bech32_decode(offer_bech32, max_length=len(offer_bech32))
        if data is None:
            raise ValueError("Invalid Offer")
        decoded = convertbits(list(data), 5, 8, False)
```
