### Title
`.gitignore` pattern over-matching due to unescaped backslash in `escapeGitSpecialCharacters` - ([File: app/src/lib/git/gitignore.ts])

### Summary
`escapeGitSpecialCharacters` only escapes the characters `[`, `]`, `!`, `*`, `#`, `?`, but never escapes a literal backslash (`\`) that may already be present in a file name. [1](#0-0)  Since gitignore/`fnmatch` treats `\` as its own escape character, a pre-existing backslash in the file name combines with the backslash that `escapeGitSpecialCharacters` inserts before an adjacent metacharacter, turning `\\<meta>` into "escaped backslash + unescaped wildcard" instead of "escaped backslash + escaped literal metacharacter."

### Finding Description
`appendIgnoreFile` is the function invoked when a user chooses "Ignore file" on an untracked file in Desktop's Changes list. [2](#0-1)  It calls `escapeGitSpecialCharacters(filePath)` on the raw file name and writes the "escaped" string as a literal gitignore rule via `appendIgnoreRule` → `saveGitIgnore`. [3](#0-2) 

The escaping regex is:
```
const specialCharacters = /[\[\]!\*\#\?]/g
```
which prepends a `\` only to `[`, `]`, `!`, `*`, `#`, `?`, leaving any backslash already present in the name untouched. [1](#0-0) 

Backslash is a legal filename character on Linux/macOS (only `/` and NUL are forbidden). If a repository provides (or a build/checkout leaves behind) an untracked file whose name contains a literal `\` immediately followed by one of `*`, `?`, `[`, `]`, the escaping breaks:

- Original bytes: `...\` `*` `...`
- After `escapeGitSpecialCharacters`: `...\` `\*` `...` = `...\\*...`
- Git's wildmatch parses `\\` as an escaped backslash (matches a literal `\`), leaving the following `*` **unescaped**, so it is now interpreted as a real wildcard glob token instead of the literal asterisk from the file name.

This is confirmed by the project's own unit test, which shows the escaper faithfully preserves pre-existing backslashes unmodified next to newly-escaped metacharacters. [4](#0-3)  In that particular test the adjacent character happens to be `!`, which is only special as the very first pattern character in gitignore, so no visible breakage occurs there — but the same code path with `*`, `?`, `[`, or `]` (which are always special, regardless of position) does break, because the wildcard/character-class semantics are still active in that position.

### Impact Explanation
The resulting `.gitignore` rule no longer represents a literal match of the single file the user intended to ignore. For a file such as `foo\*bar`, the emitted pattern becomes `foo\\*bar`, which git interprets as "literal `foo\`, then any sequence of characters, then `bar`" — over-matching many unrelated sibling files with names like `foo\anythingbar`. Because this happens automatically and silently after a completely ordinary "Ignore file" UI action, it can cause other legitimate, unrelated files in the working directory to be unintentionally excluded from `git add`/status/commit, i.e., silent corruption of what the user commits or pushes, which is a listed valid impact.

### Likelihood Explanation
The trigger requires only that the untracked file's name (which can originate from attacker-supplied repository content, e.g. a file dropped by a build step defined in a malicious repo, or delivered inside a cloned repo) contain a backslash immediately preceding `*`, `?`, `[`, or `]`, and that the victim performs the normal "Ignore file" action in the Desktop UI. This is a single ordinary user interaction, not an unnatural step, and no elevated privileges are needed. The character combination needed is unusual but plausible for an attacker who controls file names in a repository the user clones (Linux/macOS only, since Windows disallows backslash in file names).

### Recommendation
Escape backslash characters first (before escaping the other metacharacters) in `escapeGitSpecialCharacters`, e.g. extend the regex to include `\\` and ensure it is processed before/along with the other special characters so a literal backslash in the original name is always emitted as `\\` and cannot merge with the following inserted escape sequence. For example:
```js
const specialCharacters = /[\\\[\]!\*\#\?]/g
return pattern.replace(specialCharacters, match => '\\' + match)
```
This guarantees any pre-existing backslash is itself escaped, so the following metacharacter's own added backslash cannot be consumed by it.

### Proof of Concept
1. In a test repository, create an untracked file literally named `foo\*bar` (on Linux/macOS this is a valid filename containing a real backslash and asterisk byte).
2. In GitHub Desktop, select this file in the Changes list and choose "Ignore file", which invokes `appendIgnoreFile`. [2](#0-1) 
3. Inspect the generated `.gitignore` — it will contain `foo\\*bar` instead of a properly escaped literal `foo\\\*bar`.
4. Create a second, unrelated file `foo\anythingbar` in the same directory and run `git check-ignore -v foo\\anythingbar`. Git reports it as ignored, confirming that the pattern over-matches beyond the single file the user intended to ignore.

```typescript
/** Add the given pattern or patterns to the root gitignore file */
export async function appendIgnoreRule(
  repository: Repository,
  patterns: string | string[]
): Promise<void> {
  const text = (await readGitIgnoreAtRoot(repository)) || ''

  const currentContents = await formatGitIgnoreContents(text, repository)

  const newPatternText =
    patterns instanceof Array ? patterns.join('\n') : patterns
  const newText = await formatGitIgnoreContents(
    `${currentContents}${newPatternText}`,
    repository
  )

  await saveGitIgnore(repository, newText)
}
```

```typescript
export async function appendIgnoreFile(
  repository: Repository,

  if (filePath instanceof Array) {
    const escapedFilePaths = filePath.map(path =>
      escapeGitSpecialCharacters(path)
    )

    return appendIgnoreRule(repository, escapedFilePaths)
  }

  const escapedFilePath = escapeGitSpecialCharacters(filePath)
  return appendIgnoreRule(repository, escapedFilePath)
}
```

```typescript
/** Escapes a string from special characters used in a gitignore file */
export function escapeGitSpecialCharacters(pattern: string): string {
  const specialCharacters = /[\[\]!\*\#\?]/g

  return pattern.replaceAll(specialCharacters, match => {
    return '\\' + match
  })
}
```
