### Title
`updateRemoteUrl` rewrites the local git remote to an attacker-influenced GitHub API `clone_url` without validating the hostname, silently hijacking future push/fetch targets - (File: `app/src/lib/stores/updates/update-remote-url.ts`)

### Summary
When Desktop refreshes a repository's GitHub metadata, it fetches `apiRepo.clone_url` from the GitHub API and, under certain conditions, automatically calls `git remote set-url` to point the local `origin` remote at that URL [1](#0-0) . The only checks performed are that the URL scheme (`https`/`ssh`) is unchanged and that the *current* remote still matches the previously cached clone URL [2](#0-1) . There is no check that the new `clone_url`'s hostname/owner matches the account's expected endpoint or the repository's original host, so a crafted or manipulated API repository object can redirect the user's local remote to an arbitrary server.

### Finding Description
`repositoryWithRefreshedGitHubRepository` in `app-store.ts` fetches the repository object from the GitHub API on the configured account/endpoint and, if the repository already has an associated `gitHubRepository`, passes the fetched object straight into `updateRemoteUrl` [3](#0-2) .

Inside `updateRemoteUrl`, the logic is:
1. Compare `apiRepo.clone_url` (`updatedRemoteUrl`) to the current remote URL via `urlMatchesRemote` (hostname+owner+name comparison) to compute `urlsMatch` [4](#0-3) .
2. Only compare the URL *protocol* (`https:` vs `ssh:` style) between old and new URLs, not the hostname [5](#0-4) .
3. Check that the *current* remote still matches the previously cached `gitHubRepository.cloneURL` (i.e., the user hasn't manually pointed origin elsewhere) [6](#0-5) .
4. If protocols match, the remote is "unchanged" from the last known clone URL, and the new URL differs, it silently calls `gitStore.setRemoteURL(...)` to rewrite `origin` to the brand-new `apiRepo.clone_url` [7](#0-6) .

Nowhere in this path is the new URL's **hostname** validated against the account's known GitHub endpoint (`getHTMLURL(account.endpoint)`), unlike `matchGitHubRepository`, which does enforce a hostname allowlist when initially associating a repo [8](#0-7) . `urlMatchesRemote` is only used to detect *whether URLs differ*, not to constrain what host the new URL may point to [9](#0-8) . This mirrors the report's broken invariant: one part of the system (the cached `RabbitHoleReceipt`/here, the trusted account endpoint) is assumed to be the sole source of truth, but a mutable, externally-supplied value (`apiRepo.clone_url`) is trusted and propagated into a security-relevant local git operation with no host allowlist. The comment in `performPush` even acknowledges this fragility of keeping remote URL/name in sync across the app [10](#0-9) .

### Impact Explanation
If the GitHub API repository object served to Desktop contains an attacker-influenced `clone_url` (e.g., a spoofed/compromised GitHub Enterprise instance, a proxy/MITM on the API path, or any GitHub API response inconsistency), Desktop will silently rewrite the local `origin` remote via `git remote set-url` to that URL. All subsequent `git push`/`git fetch` operations for that repository will silently target the attacker's server instead of the legitimate one, which is exactly the "silent corruption of what the user commits/pushes" impact class: credentials configured for git operations (via credential helpers) may be sent to the attacker's endpoint, and future pushes leak code/history to it, all without any user-visible confirmation dialog.

### Likelihood Explanation
This code path runs automatically as part of routine background repository refresh/push flow (`_push` → `withRefreshedGitHubRepository` → `repositoryWithRefreshedGitHubRepository` → `updateRemoteUrl`) [11](#0-10) [12](#0-11) , meaning it requires no unusual user action — a user simply pushing to a repository triggers a refresh that can silently rewrite their remote. The check that guards it (`remoteUrlUnchanged` and `protocolsMatch`) validates consistency of the *local* state but performs no cross-check against the trusted account endpoint's hostname, so the only barrier to exploitation is the integrity of the value returned by `api.fetchRepository`.

### Recommendation
In `updateRemoteUrl`, before calling `gitStore.setRemoteURL`, validate that the new `updatedRemoteUrl`'s hostname matches the hostname of the account's known API endpoint (the same check already performed by `matchGitHubRepository`), rejecting/ignoring updates whose target host differs from the expected GitHub/GHE host. Consider also surfacing a user-facing confirmation before silently rewriting a configured git remote.

### Proof of Concept
1. User has a repository configured with `origin` pointing at `https://github.com/acme/widgets` and a matching `gitHubRepository.cloneURL`.
2. Desktop calls `repositoryWithRefreshedGitHubRepository`, which calls `api.fetchRepository('acme', 'widgets')` against the account's endpoint [13](#0-12) .
3. Suppose the returned `apiRepo.clone_url` is manipulated/spoofed to `https://evil.example.com/acme/widgets` (same scheme, different host).
4. `updateRemoteUrl` computes `protocolsMatch = true` (both `https:`), `remoteUrlUnchanged = true` (current remote matches the last cached clone URL), and `urlsMatch = false` (hostnames differ) [14](#0-13) .
5. The condition `protocolsMatch && remoteUrlUnchanged && !urlsMatch` is true, so `gitStore.setRemoteURL('origin', 'https://evil.example.com/acme/widgets')` executes, silently repointing the user's `origin` remote [7](#0-6) .
6. The existing unit test confirms this exact behavior: changing `clone_url` on the API repository object results in the local git remote URL being updated to match, with no hostname check performed [15](#0-14) .

export async function updateRemoteUrl(
  gitStore: GitStore,
  gitHubRepository: GitHubRepository,
  apiRepo: IAPIRepository
): Promise<void> {
  // I'm not sure when these early exit conditions would be met. But when they are
  // we don't have enough information to continue so exit early!
  if (gitStore.defaultRemote === null) {
    return
  }

  const remoteUrl = gitStore.defaultRemote.url
  const updatedRemoteUrl = apiRepo.clone_url
  const urlsMatch = urlMatchesRemote(updatedRemoteUrl, gitStore.defaultRemote)

  // Verify that protocol hasn't changed. If it has we don't want
  // to alter the protocol in case they are relying on a specific one.
  // If protocol is null that implies the url is a ssh url
  // of the format git@github.com:octocat/Hello-World.git, which
  // can't be parsed by URL.parse. In this case we assume the user
  // manually configured their remote to use this format and we don't
  // want to change what they've done just to be safe
  const parsedRemoteUrl = URL.parse(remoteUrl)
  const parsedUpdatedRemoteUrl = URL.parse(updatedRemoteUrl)
  const protocolsMatch =
    parsedRemoteUrl.protocol !== null &&
    parsedUpdatedRemoteUrl.protocol !== null &&
    parsedRemoteUrl.protocol === parsedUpdatedRemoteUrl.protocol

  // Check if the default remote url has been manually changed from the
  // clone url retrieved from the GitHub API previously
  const remoteUrlUnchanged =
    gitStore.defaultRemote &&
    urlMatchesRemote(gitHubRepository.cloneURL, gitStore.defaultRemote)

  if (protocolsMatch && remoteUrlUnchanged && !urlsMatch) {
    await gitStore.setRemoteURL(gitStore.defaultRemote.name, updatedRemoteUrl)
  }

  private async repositoryWithRefreshedGitHubRepository(
    repository: Repository
  ): Promise<Repository> {
    const repoStore = this.repositoriesStore
    const match = await this.matchGitHubRepository(repository)

    // TODO: We currently never clear GitHub repository associations (see
    // https://github.com/desktop/desktop/issues/1144). So we can bail early at
    // this point.
    if (!match) {
      return repository
    }

    const { account, owner, name } = match
    const { endpoint } = account
    const api = API.fromAccount(account)
    const apiRepo = await api.fetchRepository(owner, name)

    if (apiRepo === null) {
      // If the request fails, we want to preserve the existing GitHub
      // repository info. But if we didn't have a GitHub repository already or
      // the endpoint changed, the skeleton repository is better than nothing.
      if (endpoint !== repository.gitHubRepository?.endpoint) {
        const ghRepo = await repoStore.upsertGitHubRepositoryFromMatch(match)
        return repoStore.setGitHubRepository(repository, ghRepo)
      }

      return repository
    }

    if (repository.gitHubRepository) {
      const gitStore = this.gitStoreCache.get(repository)
      await updateRemoteUrl(gitStore, repository.gitHubRepository, apiRepo)
    }

export function matchGitHubRepository(
  accounts: ReadonlyArray<Account>,
  remote: string
): IMatchedGitHubRepository | null {
  for (const account of accounts) {
    const htmlURL = getHTMLURL(account.endpoint)
    const { hostname } = URL.parse(htmlURL)
    const parsedRemote = parseRemote(remote)

    if (parsedRemote !== null && hostname !== null) {
      if (parsedRemote.hostname.toLowerCase() === hostname.toLowerCase()) {
        return { name: parsedRemote.name, owner: parsedRemote.owner, account }
      }
    }
  }

  return null
}

export function urlMatchesRemote(url: string | null, remote: IRemote): boolean {
  if (url == null) {
    return false
  }

  const cloneUrl = parseRemote(url)
  const remoteUrl = parseRemote(remote.url)

  if (remoteUrl == null || cloneUrl == null) {
    return false
  }

  if (!caseInsensitiveEquals(remoteUrl.hostname, cloneUrl.hostname)) {
    return false
  }

  if (remoteUrl.owner == null || cloneUrl.owner == null) {
    return false
  }

  if (remoteUrl.name == null || cloneUrl.name == null) {
    return false
  }

  return (
    caseInsensitiveEquals(remoteUrl.owner, cloneUrl.owner) &&
    caseInsensitiveEquals(remoteUrl.name, cloneUrl.name)
  )
}
