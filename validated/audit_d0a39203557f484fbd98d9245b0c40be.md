### Title
`SIGHASH_SINGLE | ANYONECANPAY` on Challenge Transaction Leaves `challenger_evm_address` OP_RETURN Uncommitted, Enabling Front-Running to Steal Citrea Reimbursement — (`core/src/builder/transaction/challenge.rs`, `core/src/builder/transaction/deposit_signature_owner.rs`)

---

### Summary

The Challenge transaction's sole input is pre-signed by the operator with `TapSighashType::SinglePlusAnyoneCanPay`. Under Bitcoin's sighash rules, `SIGHASH_SINGLE | ANYONECANPAY` commits only to the input being signed and the output at the **same index** (output 0, the operator reimbursement). Output 1 — the `OP_RETURN` carrying the `challenger_evm_address` that determines who receives the Citrea-side collateral reimbursement — is **not covered** by the signature. Any observer can take the pre-signed input, substitute their own EVM address in the OP_RETURN, add their own funding inputs (permitted by `ANYONECANPAY`), and broadcast with a higher fee, redirecting the Citrea reimbursement to themselves.

---

### Finding Description

**Sighash assignment for the Challenge input:** [1](#0-0) 

```rust
Challenge => Ok(OperatorSharedDeposit(SinglePlusAnyoneCanPay)),
```

`OperatorSharedDeposit` means the operator signs this input during deposit setup and shares the signature with verifiers. The sighash type is `TapSighashType::SinglePlusAnyoneCanPay`.

**Challenge transaction structure:** [2](#0-1) 

```
Input  0: KickoffTx Challenge UTXO  ← signed with SIGHASH_SINGLE | ANYONECANPAY
Output 0: operator_challenge_amount → operator_reimbursement_address  ← COMMITTED (same index as input)
Output 1: OP_RETURN(challenger_evm_address)                           ← NOT COMMITTED
```

**What `SIGHASH_SINGLE | ANYONECANPAY` covers** (confirmed by the in-repo sighash implementation): [3](#0-2) 

When `sighash == TapSighashType::Single`, only `tx.output[input_index]` (output 0) is hashed. All other outputs, including the OP_RETURN at output 1, are excluded from the digest.

**The OP_RETURN is the reimbursement designator:** [4](#0-3) 

The `challenger_evm_address` embedded in output 1 is the on-chain record used by the Citrea bridge contract to identify who should receive the operator's Citrea-locked collateral if the challenge is proven correct (operator is malicious).

**The Challenge UTXO script allows anyone to add inputs** (ANYONECANPAY): [5](#0-4) 

The Challenge UTXO holds only `default_utxo_amount()` (dust), while output 0 pays `operator_challenge_amount` (200 000 000 sat in the reference config). The challenger must add their own funding inputs. Because the sighash is `ANYONECANPAY`, any third party can also add their own inputs to the same pre-signed input, making the attack trivially executable.

---

### Impact Explanation

A mempool observer can:

1. See the verifier's challenge transaction in the Bitcoin mempool.
2. Extract the pre-signed Challenge UTXO input (operator's `SIGHASH_SINGLE | ANYONECANPAY` signature remains valid regardless of what output 1 contains).
3. Replace output 1 with an OP_RETURN encoding their own EVM address.
4. Add their own funding inputs (permitted by `ANYONECANPAY`) to cover `operator_challenge_amount`.
5. Broadcast with a higher fee rate.

Result: the attacker's transaction is mined first. The Citrea bridge contract reads the OP_RETURN from the on-chain challenge transaction and reimburses the **attacker's** EVM address from the operator's Citrea collateral. The legitimate verifier's transaction is rejected (UTXO already spent) and receives nothing.

The verifier who performed the work of detecting a malicious kickoff loses their entire Citrea-side reimbursement. If this attack is reliably executable, rational verifiers will stop challenging, removing the economic enforcement layer that keeps operators honest and directly threatening bridge liveness.

---

### Likelihood Explanation

- The attack requires only mempool monitoring and constructing a standard Bitcoin transaction — no special cryptographic capability.
- The pre-signed operator signature is publicly visible in the mempool.
- Bitcoin's `SIGHASH_SINGLE | ANYONECANPAY` is specifically designed to allow exactly this kind of output substitution; no consensus rule prevents it.
- The attacker profits by the full Citrea reimbursement amount minus the `operator_challenge_amount` they pay, making it economically attractive whenever the Citrea collateral exceeds the challenge fee.

---

### Recommendation

Change the sighash type for the Challenge input from `SinglePlusAnyoneCanPay` to `TapSighashType::Default` (or `All`). This commits the signature to **all outputs**, including the OP_RETURN at output 1, making it impossible to substitute the `challenger_evm_address` without invalidating the operator's pre-signature.

The trade-off is that the challenger can no longer add arbitrary funding inputs after the fact. Instead, the challenge transaction must be fully constructed (with the correct funding inputs and change outputs) before the operator signs it during deposit setup, or the funding mechanism must be redesigned (e.g., the Challenge UTXO itself must carry the full `operator_challenge_amount`, funded at kickoff time by the operator).

Alternatively, the `challenger_evm_address` could be committed into the Challenge UTXO's Taproot script itself (as a script path condition), so that any spend of that UTXO on-chain cryptographically binds the EVM address regardless of sighash type.

---

### Proof of Concept

```
Deposit setup:
  Operator pre-signs Challenge tx:
    Input 0:  kickoff_txid:Challenge_vout  (SIGHASH_SINGLE | ANYONECANPAY)
    Output 0: 200_000_000 sat → operator_reimburse_addr   ← covered by sig
    Output 1: OP_RETURN(verifier_A_evm_addr)              ← NOT covered

Verifier A detects malicious kickoff, broadcasts the pre-signed tx.

Attacker observes mempool, constructs:
    Input 0:  kickoff_txid:Challenge_vout  (same pre-signed witness, still valid)
    Input 1:  attacker_utxo (funds the 200_000_000 sat output)
    Output 0: 200_000_000 sat → operator_reimburse_addr   ← sig still valid
    Output 1: OP_RETURN(attacker_evm_addr)                ← substituted

Attacker broadcasts with fee_rate > Verifier A's fee_rate.
Attacker's tx mines first.
Citrea contract reads OP_RETURN → reimburses attacker_evm_addr.
Verifier A's tx is rejected (UTXO spent). Verifier A receives nothing.

/// 2. OP_RETURN output (containing EVM address of the challenger, for reimbursement if the challenge is correct)
///
/// # Arguments
///
/// * `kickoff_txhandler` - The kickoff transaction handler that the challenge belongs to.
/// * `operator_reimbursement_address` - The address to reimburse the operator to cover their costs.
/// * `challenger_evm_address` - The EVM address of the challenger, for reimbursement if the challenge is correct.
/// * `paramset` - Protocol parameter set.
///
/// # Returns
///
/// A [`TxHandler`] for the challenge transaction, or a [`BridgeError`] if construction fails.
pub fn create_challenge_txhandler(
    kickoff_txhandler: &TxHandler,
    operator_reimbursement_address: &bitcoin::Address,
    challenger_evm_address: Option<EVMAddress>,
    paramset: &'static ProtocolParamset,
) -> Result<TxHandler, BridgeError> {
    let mut builder = TxHandlerBuilder::new(TransactionType::Challenge)
        .with_version(NON_STANDARD_V3)
        .add_input(
            NormalSignatureKind::Challenge,
            kickoff_txhandler.get_spendable_output(UtxoVout::Challenge)?,
            SpendPath::ScriptSpend(0),
            DEFAULT_SEQUENCE,
        )
        .add_output(UnspentTxOut::from_partial(TxOut {
            value: paramset.operator_challenge_amount,
            script_pubkey: operator_reimbursement_address.script_pubkey(),
        }));

    if let Some(challenger_evm_address) = challenger_evm_address {
        builder = builder.add_output(UnspentTxOut::from_partial(op_return_txout(
            challenger_evm_address.0,
        )));
    }

    Ok(builder.finalize())
