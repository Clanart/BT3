### Title
Payout OP_RETURN operator attribution is unauthenticated, letting an unprivileged withdrawer self-fund a payout and frame/credit an arbitrary operator for reimbursement - ([File: core/src/builder/transaction/operator_reimburse.rs])

### Summary
`create_payout_txhandler` writes an arbitrary caller-chosen `operator_xonly_pk` into output 2's OP_RETURN, and `Verifier::update_finalized_payouts` blindly trusts that OP_RETURN as the "fronting operator" without checking who actually supplied the transaction's value. Because the only cryptographically bound part of the payout tx is the withdrawer's own dust input signed with `SinglePlusAnyoneCanPay`, the withdrawer (an unprivileged attacker) can fully self-fund the payout, broadcast it directly to Bitcoin without any operator's involvement, and stamp any operator's pubkey on it.

### Finding Description
The claimed binding is: `withdrawals.payout_payer_operator_xonly_pk` (set in `Verifier::update_finalized_payouts`) == the operator who actually supplied the BTC value paid out at output 0 of the payout tx.

`create_payout_txhandler` builds the payout tx with a single key-spend input (the Citrea-registered `withdrawal_utxo`) and places the OP_RETURN with `operator_xonly_pk.serialize()` unconditionally at output index 2, with no linkage to the input's actual funding source: [1](#0-0) 

The user's signature over the input uses `TapSighashType::SinglePlusAnyoneCanPay`, verified in `Operator::withdraw`: [2](#0-1) 

`SIGHASH_SINGLE|ANYONECANPAY` only commits input 0 and output 0 (the user's own payout output). Nothing constrains which additional inputs (funding) or which OP_RETURN pubkey (output 2) get added — whoever completes/funds the transaction (normally an operator via `fund_raw_transaction`, but there is no on-chain enforcement of this) can pick any value there: [3](#0-2) 

Because the withdrawer created and holds this exact signature themselves (they are the one calling `withdraw`/registering the `withdrawal_utxo` on Citrea, and in the test helper the dust UTXO is a plain key they control), an unprivileged attacker can add their own extra input(s) to cover the entire payout amount, add any operator's xonly pubkey to the OP_RETURN, and broadcast the whole payout transaction directly to Bitcoin — with zero operator RPC interaction.

Once finalized, `Verifier::update_finalized_payouts` parses only the first OP_RETURN output and stores that pubkey as the payer with no further validation: [4](#0-3) [5](#0-4) 

The framed operator's own automation then picks this up as its own unhandled payout purely by pubkey match: [6](#0-5) 

and calls `Operator::handle_finalized_payout`, which builds and signs a kickoff transaction to claim reimbursement of `bridge_amount` from the deposit's move-to-vault via the N-of-N presigned transaction graph — with no check that this operator's wallet/TxSender actually broadcast the forged payout tx: [7](#0-6) 

Separately, `Verifier::is_kickoff_malicious` compares a later kickoff's `operator_xonly_pk` against the DB-recorded payer: [8](#0-7) 
If the attacker's forged, self-funded transaction wins the race to spend the registered `withdrawal_utxo` (a single UTXO can only be spent once) with a different operator's pubkey than the one who was genuinely about to front the withdrawal, the honest operator's later kickoff is flagged malicious, exposing it to challenge and collateral loss, and it can never be reimbursed for the withdrawal it genuinely intended to front.

None of the existing guards close this gap: `Operator::withdraw`/`sign_optimistic_payout` only validate that `input_outpoint == withdrawal_utxo` and that the user's signature is valid — they do not run when the attacker bypasses the RPC and broadcasts directly; `is_kickoff_malicious` only compares pubkeys already corrupted by the forged OP_RETURN; there is no check anywhere that the entity named in the OP_RETURN is the one who supplied the additional funding inputs.

### Impact Explanation
This directly matches the Critical bullet "an operator reimbursed for a payout it never funded" / "BTC leaving a move-to-vault UTXO without a matching fronted withdrawal": the attacker can force release of the deposit's escrowed `bridge_amount` to any operator of their choosing who did nothing, purely by choosing the OP_RETURN bytes on a self-funded transaction. It can also produce "an honest operator's collateral burned" / "an honest operator permanently unable to be reimbursed" if the attacker's forged tx wins the race against a legitimately fronting operator's payout tx for the same `withdrawal_utxo`, since the DB will misattribute the payer and `is_kickoff_malicious` will flag the honest operator's real kickoff. This is repeatable for every withdrawal the attacker themselves initiates, against any operator whose xonly pubkey is public (all registered operators' pubkeys are public protocol data), across all deposits.

### Likelihood Explanation
The attacker only needs standard unprivileged capabilities explicitly granted in scope: call `withdraw` on the Citrea Bridge contract, choose the withdrawal UTXO bytes, produce their own Schnorr signature/sighash flag, construct an OP_RETURN, and broadcast a Bitcoin transaction. No operator, verifier, or aggregator interaction is required at all — the attack completely bypasses gRPC. Cost is limited to Bitcoin fees plus funding their own payout output (which they'd pay anyway as the legitimate withdrawer), so it is cheap and fully repeatable per withdrawal.

### Recommendation
Do not trust the OP_RETURN pubkey as proof of funding. Either (a) require the fronting operator to co-sign the payout transaction (e.g., via an additional signature or a distinguishing script path bound to the operator's key) so that `operator_xonly_pk` is cryptographically tied to an input/output the operator actually controls, or (b) have `update_finalized_payouts`/`handle_finalized_payout` cross-check that the operator's own `TxSender`/wallet actually broadcast the specific payout tx txid (e.g., match against a locally recorded "sent payout tx" table keyed by operator, not just parse untrusted OP_RETURN bytes from chain data).

### Proof of Concept
Add a `cargo test` (outside the excluded test dirs is not required for reporting, but the demonstration plan is):
1. Build a `withdrawal_utxo` UTXO owned by a test "withdrawer" keypair (attacker), matching `generate_withdrawal_utxo` pattern.
2. Sign it with `TapSighashType::SinglePlusAnyoneCanPay` for output 0 = withdrawer's own receiving output.
3. Using `create_payout_txhandler`, construct the payout tx but add an attacker-funded extra input (via `fund_raw_transaction`-equivalent) instead of any operator's, and set `operator_xonly_pk` to victim operator X's pubkey (never involved in the RPC flow).
4. Broadcast this transaction directly (no `internal_withdraw`/`Withdraw` RPC call to any operator).
5. Mine to finality; call `Verifier::update_finalized_payouts` (or run the finalized-block handler) and assert: `get_payout_info_from_move_txid` returns `payout_payer_operator_xonly_pk == Some(X)`.
6. Assert operator X never received a `Withdraw`/`InternalWithdraw` RPC call and never signed/broadcast this transaction, proving the two sides of the binding (`payout_payer_operator_xonly_pk` vs. "party that funded output 0") diverge — the DB attributes fronting to X purely from attacker-controlled OP_RETURN bytes on a self-funded transaction.

pub fn create_payout_txhandler(
    input_utxo: UTXO,
    output_txout: TxOut,
    operator_xonly_pk: XOnlyPublicKey,
    user_sig: taproot::Signature,
    _network: bitcoin::Network,
) -> Result<TxHandler<Signed>, BridgeError> {
    let txin = SpendableTxIn::new_partial(input_utxo.outpoint, input_utxo.txout);

    let output_txout = UnspentTxOut::from_partial(output_txout.clone());

    let op_return_txout = op_return_txout(PushBytesBuf::from(operator_xonly_pk.serialize()));

    let mut txhandler = TxHandlerBuilder::new(TransactionType::Payout)
        .with_version(NON_STANDARD_V3)
        .add_input(
            NormalSignatureKind::NotStored,
            txin,
            SpendPath::KeySpend,
            DEFAULT_SEQUENCE,
        )
        .add_output(output_txout)
        .add_output(UnspentTxOut::from_partial(anchor_output(
            NON_EPHEMERAL_ANCHOR_AMOUNT,
        )))
        .add_output(UnspentTxOut::from_partial(op_return_txout))
        .finalize();
    txhandler.set_p2tr_key_spend_witness(&user_sig, 0)?;
    txhandler.promote()
}

    /// Sets the given payout txs' txid and operator index for the given index.
    pub async fn update_payout_txs_and_payer_operator_xonly_pk(
        &self,
        tx: Option<DatabaseTransaction<'_>>,
        payout_txs_and_payer_operator_xonly_pk: Vec<(
            u32,
            Txid,
            Option<XOnlyPublicKey>,
            bitcoin::BlockHash,
        )>,
    ) -> Result<(), BridgeError> {
        if payout_txs_and_payer_operator_xonly_pk.is_empty() {
            return Ok(());
        }
        // Convert all values first, propagating any errors
        let converted_values: Result<Vec<_>, BridgeError> = payout_txs_and_payer_operator_xonly_pk
            .iter()
            .map(|(idx, txid, operator_xonly_pk, block_hash)| {
                Ok((
                    i32::try_from(*idx).wrap_err("Failed to convert payout index to i32")?,
                    TxidDB(*txid),
                    operator_xonly_pk.map(XOnlyPublicKeyDB),
                    BlockHashDB(*block_hash),
                ))
            })
            .collect();
        let converted_values = converted_values?;

        let mut query_builder = QueryBuilder::new(
            "UPDATE withdrawals AS w SET
                payout_txid = c.payout_txid,
                payout_payer_operator_xonly_pk = c.payout_payer_operator_xonly_pk,
                payout_tx_blockhash = c.payout_tx_blockhash
                FROM (",
        );

        query_builder.push_values(
            converted_values.into_iter(),
            |mut b, (idx, txid, operator_xonly_pk, block_hash)| {
                b.push_bind(idx)
                    .push_bind(txid)
                    .push_bind(operator_xonly_pk)
                    .push_bind(block_hash);
            },
        );

        query_builder
            .push(") AS c(idx, payout_txid, payout_payer_operator_xonly_pk, payout_tx_blockhash) WHERE w.idx = c.idx");

        let query = query_builder.build();
        execute_query_with_tx!(self.connection, tx, query, execute)?;

        Ok(())
    }
