### Title
Reward-Dilution Front-Run: Attacker can `vote()` immediately before `harvestSinglePool` to steal a pro-rata share of already-accrued bribes without having voted during the accrual period - (File: wombat/WombatBribeManager.sol)

### Summary
`WombatBribeManager.harvestSinglePool` pulls the entire Wombat bribe (accrued over the whole epoch based on a gauge's historical votes) and distributes it as one lump sum into `BribeRewardPool.rewardPerTokenStored`, using the pool's *current* `totalSupply` at the moment of harvest. Because `WombatBribeManager.vote()` immediately updates `pool.totalVoteInVlmgp` and calls `BribeRewardPool.stakeFor`, an attacker can front-run any `harvestSinglePool`/`castVotes` transaction with a large `vote()` call and capture a full pro-rata share of the freshly harvested bribe despite having contributed zero votes during the period the bribe accrued.

### Finding Description
`harvestSinglePool` sends a zero-delta vote array to `wombatStaking.vote()` [1](#0-0) , which calls `voter.vote()` on the external Wombat voter (harvesting the pool's full accumulated bribe regardless of the zero delta) and then forwards the entire harvested amount to the pool's rewarder via `queueNewRewards` [2](#0-1) .

`queueNewRewards` → `_provisionReward` immediately mixes the whole reward into `rewardPerTokenStored` using the pool's *current* `totalStaked()` (i.e., `BribeRewardPool.totalSupply`) at that exact block, with no time-weighting: `rewardPerTokenStored += amountReward * 1e_decimals / totalStaked()` [3](#0-2) .

`WombatBribeManager.vote()` is fully permissionless and, for a positive delta, immediately increases `pool.totalVoteInVlmgp` and calls `IBribeRewardPool(pool.rewarder).stakeFor(msg.sender, delta)` [4](#0-3) . `stakeFor` runs the `updateRewards` modifier (which checkpoints the caller's `userRewardPerTokenPaid` at the **pre-harvest** rate using the caller's **old** balance) before increasing `totalSupply` and the caller's balance [5](#0-4) [6](#0-5) .

Exploit flow:
1. Attacker observes a pending `harvestSinglePool`/`castVotes` transaction (or public bribe accrual on Wombat) in the mempool.
2. Attacker calls `vote()` with a large positive delta on the target pool in the same block, before the harvest transaction executes, raising `totalVoteInVlmgp`/`totalSupply` and getting their `userRewardPerTokenPaid` checkpointed at the pre-harvest rate.
3. The harvest transaction executes, pulling the whole epoch's bribe from Wombat and diluting it across the now-inflated `totalSupply`, i.e. across the attacker's freshly-added stake too.
4. Attacker calls `claimBribe`, earning `delta * (newRate - oldRate) / 1e_decimals` — a full pro-rata share of a reward period during which they held zero vote weight.
5. Attacker can then `unvote`/withdraw their delta with no lock-up, retaining principal.

Existing controls do not prevent this: there is no time-weighting, no minimum holding period before earning newly queued rewards, and `vote()`/`harvestSinglePool` have no reentrancy or ordering protection against this specific interaction.

### Impact Explanation
This results in a redistribution of already-accrued, unclaimed bribe yield away from legitimate long-term voters (e.g., "voter A" who voted for the whole accrual period) toward an attacker who injects capital for a single block. This matches the Immunefi "theft of unclaimed yield" impact class — it is a real, quantifiable economic loss to existing voters, proportional to `attacker_delta / new_totalSupply * harvested_bribe`.

### Likelihood Explanation
- Requires the attacker to hold and lock MGP as vlMGP to have votable balance for `vote()` — this is a normal token acquisition, not a privileged capability.
- Requires front-running/same-block ordering against a public, permissionless `harvestSinglePool`/`castVotes` call — feasible via standard MEV techniques (mempool monitoring + higher gas, or via a searcher/builder relationship) on any chain without strict private mempools.
- Fully repeatable every time a pool's bribe is harvested with meaningful `totalSupply`/reward ratio, since `vote`/`unvote` have no cooldown.
- Capital-at-risk is only the vlMGP a user already needs to lock to vote, which is returned after `unvote`; the only "cost" is the temporary allocation and any opportunity cost, making the attack close to risk-free relative to the extracted share of the bribe.

### Recommendation
Time-weight bribe distribution instead of applying the entire lump-sum reward to the instantaneous `totalSupply`. Options: (1) checkpoint each user's stake duration and only allow earning of rewards accrued after their stake timestamp (e.g., a per-epoch snapshot model rather than continuous accPerShare-on-lump-sum), (2) impose a minimum lock/holding period between `vote()` and eligibility for rewards from a subsequent harvest in the same pool, or (3) have `WombatBribeManager` snapshot `totalVoteInVlmgp`/`totalSupply` at the start of the Wombat epoch being harvested (matching what Wombat's voter itself used to compute the bribe) rather than reading the live, most-recently-mutated `totalSupply` at `queueNewRewards` time.

### Proof of Concept
Foundry test outline:
1. Deploy `WombatBribeManager`, `WombatStaking`, `BribeRewardPool`, and mock `IWombatVoter`/`IWombatBribe` that return a fixed large pending bribe amount for the target pool regardless of vote delta.
2. Voter A locks vlMGP and calls `vote()` with delta `D_A` on pool `P`, and waits (simulating an epoch of real participation).
3. Advance a block; construct attacker's transaction: lock vlMGP, then in the same block call `vote()` with a large delta `D_attacker >> D_A` on pool `P`.
4. In the following transaction (same block), call `harvestSinglePool([P])`, which triggers `wombatStaking.vote` → mock `voter.vote` returning the large pending bribe → `queueNewRewards` on `P`'s `BribeRewardPool`.
5. Attacker calls `claimBribe([P])` and asserts `attacker_reward / D_attacker` (per-unit share) approximates `harvested_bribe / (D_A + D_attacker)`, i.e., the attacker earns a full instantaneous share despite zero elapsed voting time, and `attacker_reward` exceeds any reasonable time-weighted allocation (e.g., compare against `attacker_reward` if `D_attacker` had been staked for the entire accrual epoch).
6. Attacker then calls `unvote(P)` and confirms full principal `D_attacker` is returned, demonstrating capital-free extraction of yield diluted from Voter A.

        uint256 length = _lps.length;
        int256[] memory votes = new int256[](length);
        address[] memory rewarders = new address[](length);

            Pool storage pool = poolInfos[lp];

    function _provisionReward(uint256 _amountReward, address _rewardToken) internal {
        IERC20(_rewardToken).safeTransferFrom(
            msg.sender,
            address(this),
            _amountReward
        );
        Reward storage rewardInfo = rewards[_rewardToken];
        rewardInfo.historicalRewards =
            rewardInfo.historicalRewards +
            _amountReward;

        if (totalStaked() == 0) {
            rewardInfo.queuedRewards += _amountReward;
        } else {
            if (rewardInfo.queuedRewards > 0) {
                _amountReward += rewardInfo.queuedRewards;
                rewardInfo.queuedRewards = 0;
            }
            rewardInfo.rewardPerTokenStored =
                rewardInfo.rewardPerTokenStored +
                (_amountReward * 10**stakingTokenDecimals) /
                totalStaked();
        }
        emit RewardAdded(_amountReward, _rewardToken);
