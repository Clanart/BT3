### Title
Permissionless `purchase()` lets anyone credit unlimited unwanted bandwidth subscriptions to a victim app, evicting its paid, unconsumed allowance via FIFO cap eviction - ([File: modules/pallets/bandwidth/src/lib.rs])

### Summary
`BandwidthManager.purchase()` on EVM lets **any caller** pay for a tier and specify an arbitrary `app` and `chain` (the credited `(app_chain, app)` pair) with zero consent from the app owner. The resulting ISMP message is accepted by `pallet-bandwidth::on_accept` and unconditionally appended to that app's FIFO subscription list via `push_subscription`. That list is capped at `MAX_SUBSCRIPTIONS = 1024`; once full, `push_subscription` unconditionally evicts `list[0]` — the **oldest** entry — regardless of whether it is expired or still fully funded. This is the same broken invariant as the Ammplify M-3 report: an unrestricted "recipient" parameter lets an attacker add unwanted state to someone else's capped quota without consent, and the FIFO/shared-cap eviction policy then destroys the victim's legitimate, already-paid-for state.

### Finding Description
- `BandwidthManager.sol::purchase(bytes app, uint256 tier, uint256 months, bytes chain)` is a fully public function; `app` and `chain` are attacker-supplied and never checked against `msg.sender`. [1](#0-0) 
- On the Hyperbridge side, `Pallet::on_accept` only validates that the request came from the registered `BandwidthManager` contract for the source chain — it does not validate any relationship between the purchaser and the `app`/`chain` (`app_chain`) being credited. [2](#0-1) 
- `push_subscription` appends to the `(app_chain, app)` FIFO list capped at `MAX_SUBSCRIPTIONS` (1024). When full, it evicts index `0` unconditionally — there is no check for expiry, ownership, or value; it evicts strictly by insertion order. [3](#0-2) [4](#0-3) 
- The design intentionally allows any payer to sponsor bandwidth for any `(chain, app)` (the "Sponsorship" feature), which is precisely the unrestricted-recipient pattern from the seed report: assets are added to someone else's account/quota without their consent. [5](#0-4) 
- The eviction test confirms the mechanic: pushing past the cap always evicts the oldest entry, independent of whether it's spent, valuable, or fresh. [6](#0-5) 

Attack path: an attacker repeatedly calls `purchase(app = victim_app, tier = cheapest_configured_tier, months = 1, chain = victim_app_chain)`. Each call is a self-funded but fully permissionless credit to the victim's `(app_chain, app)` FIFO queue. Once the victim's queue is pushed to length 1024 (which requires far fewer additional attacker purchases than 1024 if the victim's app already carries a natural backlog of unconsumed, low-traffic subscriptions — the docs themselves acknowledge multi-entry queues are the normal state for low-throughput apps, e.g. "years of headroom"), the next credited purchase evicts the victim's oldest subscription. If that subscription is the victim's own genuine, unconsumed, still-valid purchase (not yet expired, not yet drained by the gate), it is destroyed and emitted as `SubscriptionEvicted`, permanently losing the bytes the victim paid real fee-token for. No existing guard stops this: `is_purchase_message`/`on_accept` only check the *manager contract's* identity, never the app owner's; the gate's expiry sweep (`try_consume`) only prunes lazily on read/drain, it never protects push-time eviction from clobbering non-expired entries.

### Impact Explanation
This breaks the "bridged assets... must move exactly once and only to the rightful beneficiary" and "loss of funds" bounty categories: a victim app's pre-paid bandwidth allowance (real fee-token value, e.g. up to $1000/8MB tiers) can be permanently destroyed by an attacker who never obtained consent to touch the victim's queue, and the destruction is irreversible (evicted subscriptions are gone, only an audit event remains). Additionally, once the victim's usable subscriptions are exhausted/evicted, the app is effectively DoS'd: `BandwidthGate::try_consume` will reject its ISMP dispatches with `NoAllowance`/`Insufficient`, blocking the app's core cross-chain functionality — mirroring the Maker/Taker DoS in the seed report.

### Likelihood Explanation
This requires only an unprivileged EVM account with fee-token balance calling the public `purchase()` function — no relayer, prover, admin, or governance actor is involved, and no malformed proof is needed (it's a plain, valid purchase message). The cost scales with the number of attacker purchases needed to push the victim's queue to the 1024 cap and beyond; this is cheapest against apps that already carry a natural backlog of unconsumed entries (acknowledged as a normal, expected state in the protocol's own documentation), making the attack economically realistic for a griefer targeting a specific high-value app rather than a universal zero-cost attack.

### Recommendation
- Require the credited `app` to opt in (e.g., a registered/consented sponsor allowlist per app), or restrict unsolicited third-party sponsorship to a separate, non-evicting bucket.
- Change `push_subscription`'s eviction policy to prefer evicting expired entries first (the pallet already computes `now` and sweeps expired entries elsewhere); only fall back to oldest-live eviction when no expired entry exists, and consider rejecting the push (or refunding/erroring) rather than silently destroying a live, unexpired, valuable subscription.
- Emit a pre-eviction check that reverts (or requires an explicit governance/force path) when the entry to be evicted is not yet expired, so unconsented purchases cannot destroy value the victim has already paid for.

### Proof of Concept
1. Governance configures `TierOne` with a small `bytes`/`duration_secs` and the manager sets a low `tierPrice[1]`.
2. Victim app `V` on `chain=EVM-8453` has purchased several tiers over time and has not yet drained them (its `Allowance[(EVM-8453, V)]` list has, say, 20 unexpired entries — a state the docs treat as normal for low-traffic apps).
3. Attacker calls `BandwidthManager.purchase(app = V, tier = 1, months = 1, chain = "EVM-8453")` repeatedly (self-funded with the cheapest tier) until `Allowance::<T>::get(EVM-8453, V).len() == 1024` and one more.
4. On the `(1024+1)`-th credit, `push_subscription` evicts `list[0]` — V's oldest, still-valid, previously paid-for subscription — emitting `SubscriptionEvicted { app_chain: EVM-8453, app: V, tier, lost_bytes }`.
5. V's paid-for bytes are permanently lost with no consent or recourse; repeating the attack against V's next-oldest entries continues to destroy V's allowance and can drive V into `GateError::NoAllowance`, DoS'ing its cross-chain dispatches. [7](#0-6)

        external

        if (app.length == 0 || chain.length == 0 || months == 0) revert InvalidPurchase();
        uint256 price18d = tierPrice[tier];

        uint256 total18d = price18d * months;
        address feeToken = IDispatcher(_host).feeToken();
        uint8 dec = IERC20Metadata(feeToken).decimals();
        uint256 scale = 10 ** (18 - dec);
        if (total18d % scale != 0) revert PriceNotRepresentable();
        uint256 amount = total18d / scale;

        IERC20(feeToken).safeTransferFrom(msg.sender, address(this), amount);

        BandwidthPurchaseMsg memory body = BandwidthPurchaseMsg({
            app: app,
            tier: tier,
            months: months,
            chain: chain
        });

		/// Append a fresh subscription with a fixed expiry. If the list
		/// is already at `MaxSubscriptions`, evict the oldest entry and
		/// emit [`Event::SubscriptionEvicted`] so the lost bytes are
		/// auditable. Returns the new subscription's `expires_at`.
		fn push_subscription(
			app_chain: &StateMachine,
			app: &AppKey,
			tier: TierIndex,
			bytes: BandwidthBytes,
			duration_secs: u64,
		) -> u64 {
			let now = <T as pallet_ismp::Config>::TimestampProvider::now().as_secs();
			let expires_at = now.saturating_add(duration_secs);
			let new_sub =
				Subscription { tier, remaining_bytes: bytes, expires_at, purchased_at: now };

			let evicted = Allowance::<T>::mutate(app_chain, app, |list| {
				let evicted = if list.len() == MAX_SUBSCRIPTIONS as usize {
					Some(list.remove(0))
				} else {
					None
				};
				// Capacity is now guaranteed; try_push can't fail.
				let _ = list.try_push(new_sub);
				evicted
			});

			if let Some(old) = evicted {
				Self::deposit_event(Event::SubscriptionEvicted {
					app_chain: *app_chain,
					app: app.clone(),
					tier: old.tier,
					lost_bytes: old.remaining_bytes,
				});
			}

			expires_at
		}

			let manager = BandwidthManager::<T>::get(&request.source).ok_or_else(|| {
				anyhow::anyhow!(format!("no bandwidth manager registered for {:?}", request.source))
			})?;

			let tier = TierIndex::try_from(msg.tier)
				.map_err(|_| anyhow::anyhow!(format!("unknown tier discriminant {}", msg.tier)))?;
			let cfg = Tiers::<T>::get(tier)
				.ok_or_else(|| anyhow::anyhow!(format!("tier {:?} is not configured", tier)))?;

			let bytes = cfg.bytes.saturating_mul(msg.months as u128);
			let duration = cfg.duration_secs.saturating_mul(msg.months as u64);

				app_chain: msg.chain,
				app: key,

				tier,

			});

## Sponsorship

The purchase message carries its own `chain` (the _credit chain_) which is **independent of the source chain** that sent the message. This means a buyer on Ethereum can credit an app on Base by dispatching a purchase whose payload sets `chain = "EVM-8453"`.

The pallet keys allowance storage by `(app_chain, app)` taken from the message body, not by `request.source`. The event `BandwidthCredited` carries both — `app_chain` (where the credit lands) and `paid_from` (where the payment came from) — so the cross-chain payer is auditable.

This is what makes the system multi-tenant friendly: a treasury on a single chain can sponsor bandwidth for an app deployed across many chains, without having to deploy `BandwidthManager` on each chain the app lives on.

/// The 1024-sub cap evicts the oldest entry. force_credit reuses the
/// same push path as purchase, so this also covers the purchase cap.
#[test]
fn subscription_cap_evicts_oldest() {
	new_test_ext().execute_with(|| {
		jump_to(T0);
		let cap = MAX_SUBSCRIPTIONS as u128;

		// Fill the list to exactly the cap. `bytes` encodes the index
		// so we can prove which one got evicted.
		for i in 0..cap {
			Bandwidth::force_credit(
				RuntimeOrigin::root(),
				ForceCreditParams {
					app_chain: APP_CHAIN,
					app: app_key(),
					tier: TIER1,
					bytes: i + 1,
					duration_secs: MONTH_SECS,
				},
			)
			.unwrap();
		}
		assert_eq!(sub_count(APP_CHAIN), cap as usize);
		assert_eq!(sub_at(APP_CHAIN, 0).unwrap().remaining_bytes, 1, "oldest is index 1");

		// One more push: evicts the oldest, appends the new one.
		Bandwidth::force_credit(
			RuntimeOrigin::root(),
			ForceCreditParams {
				app_chain: APP_CHAIN,
				app: app_key(),
				tier: TIER1,
				bytes: cap + 1,
				duration_secs: MONTH_SECS,
			},
		)
		.unwrap();

		assert_eq!(sub_count(APP_CHAIN), cap as usize, "still capped");
		assert_eq!(
			sub_at(APP_CHAIN, 0).unwrap().remaining_bytes,
			2,
			"former second-oldest is now front",
		);
		assert_eq!(
			sub_at(APP_CHAIN, (cap - 1) as usize).unwrap().remaining_bytes,
			cap + 1,
			"new sub is at the back",
		);
	});
}
