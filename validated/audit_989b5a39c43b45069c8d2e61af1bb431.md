### Title
An oracle-vote-slashing validator can evade `SlashFraction` penalties by becoming unbonded or jailed before the end of the slash window - (File: `x/oracle/keeper/slash.go`)

### Summary
`x/oracle/keeper/slash.go`'s `SlashAndResetCounters` only applies the oracle-voting slash/jail if the offending validator is currently `IsBonded() && !IsJailed()` at the moment the `SlashWindow` closes, but it unconditionally deletes the accumulated `VotePenaltyCounter` for every validator regardless of whether the slash was applied. [1](#0-0) [2](#0-1) 

### Finding Description
`EndBlocker` invokes `SlashAndResetCounters` at the last block of every `SlashWindow`: [3](#0-2) 

`SlashAndResetCounters` walks every validator's `VotePenaltyCounter`, computes `validVoteRate`, and only slashes/jails when `validator.IsBonded() && !validator.IsJailed()`: [4](#0-3) 

Crucially, whether or not the `if` branch executes, the function unconditionally calls `k.DeleteVotePenaltyCounter(ctx, operator)` for that validator, wiping its accumulated miss/abstain/success history clean: [5](#0-4) 

This mirrors the EigenLayer report's root cause exactly: an actor whose slashable state is transiently reduced/removed at the precise moment the slashing calculation runs escapes the penalty entirely, and the accounting is reset so no residual claim survives to be applied later. Here, a validator who has accumulated a bad oracle voting record for an entire `SlashWindow` can, right before (or in the same block as) the window's last block, submit an ordinary `MsgUndelegate` (fully self-undelegating, causing the validator to drop out of the bonded set) or otherwise become jailed (e.g. via downtime), so that at the time `SlashAndResetCounters` runs, `IsBonded()` is false or `IsJailed()` is true. The `SlashFraction`/jail penalty for bad oracle voting is skipped, and the `VotePenaltyCounter` is deleted anyway — permanently erasing the evidence of misbehavior. The validator can then re-bond / unjail with a clean slate and never pay the oracle slashing penalty that its behavior earned.

This is confirmed directly by the module's own test cases, which show that both an `Unbonded` validator (Case 3) and a `Jailed` validator (Case 4) with an otherwise slashable `VotePenaltyCounter` retain their full token amount and are never slashed: [6](#0-5) 

### Impact Explanation
A validator can deliberately and cheaply defeat the oracle-module's slashing/accountability mechanism using only standard, permissionless staking transactions (`MsgUndelegate`/`MsgUnjail`) reachable by any staker/validator, avoiding the `SlashFraction` token penalty that governance/protocol design intends to impose for repeated bad or missing oracle votes. Because the penalty counter is deleted unconditionally, there is no later "catch-up" slash when the validator re-bonds, resulting in permanent loss of the intended penalty (economic security guarantee) for the oracle module. This is a fund/penalty-evasion issue, not merely cosmetic, since it directly undermines the oracle's price-feed integrity incentive structure.

### Likelihood Explanation
The trigger requires only a single, ordinary, unprivileged transaction (self-undelegation or accepting a downtime jail) timed near the end of a `SlashWindow`/`VotePeriod`, both of which are on-chain, publicly queryable parameters (`SlashWindow`, `VotePeriod`), making the timing trivially predictable. No governance action, malicious peer/node behavior, or special privilege is required — any validator who anticipates being penalized can perform this to escape the penalty.

### Recommendation
When a validator is skipped for oracle-vote slashing because it is unbonded/unbonding or jailed, retain (rather than delete) its `VotePenaltyCounter`/violation record, or apply the slash retroactively against the validator's tokens/unbonding delegations (similar to how `x/slashing`'s downtime slash correctly reduces historical unbonding/redelegation entries) instead of unconditionally clearing accumulated penalty state in `SlashAndResetCounters`.

### Proof of Concept
1. Validator `V` votes maliciously/misses oracle votes for most of a `SlashWindow`, accumulating a `VotePenaltyCounter` whose `validVoteRate` is below `MinValidPerWindow` (as constructed in `TestSlashAndResetMissCounters` Case 2).
2. Shortly before the last block of the `SlashWindow`, `V` submits `MsgUndelegate` to fully unbond (or is jailed via downtime), so `staking.EndBlocker` transitions `V`'s status away from `Bonded` / marks it `Jailed`.
3. At the last block of the `SlashWindow`, `oracle.EndBlocker` → `SlashAndResetCounters` runs; the `if validator.IsBonded() && !validator.IsJailed()` check fails for `V`, so no `Slash`/`Jail` call occurs, exactly as demonstrated in Cases 3 and 4 of `slash_test.go`.
4. `k.DeleteVotePenaltyCounter(ctx, operator)` still executes for `V`, erasing all record of the bad-voting history.
5. `V` later re-bonds (waits out unbonding, or submits `MsgUnjail`) with a completely clean `VotePenaltyCounter` and without ever having paid `SlashFraction`, despite having behaved exactly as badly as a validator that would otherwise be slashed.

// SlashAndResetCounters do slash any operator who over criteria & clear all operators miss counter to zero
func (k Keeper) SlashAndResetCounters(ctx sdk.Context) {
	height := ctx.BlockHeight()
	distributionHeight := height - sdk.ValidatorUpdateDelay - 1

	minValidPerWindow := k.MinValidPerWindow(ctx)
	slashFraction := k.SlashFraction(ctx)
	powerReduction := k.StakingKeeper.PowerReduction(ctx)

	k.IterateVotePenaltyCounters(ctx, func(operator sdk.ValAddress, votePenaltyCounter types.VotePenaltyCounter) bool {
		// Calculate valid vote rate; (totalVotes - (MissCounter + AbstainCounter))/totalVotes
		// this accounts for changes in vote period within a window, and will take the overall success rate
		// as opposed to the one expected based on the number of vote period expected based on the ending slash window or vote period
		totalVotes := votePenaltyCounter.SuccessCount + votePenaltyCounter.AbstainCount + votePenaltyCounter.MissCount
		if totalVotes == 0 {
			logger.Error("zero votes in penalty counter, this should never happen")
			return false
		}
		validVoteRate := sdk.NewDecFromInt(
			sdk.NewInt(int64(votePenaltyCounter.SuccessCount))). //nolint:gosec
			QuoInt64(int64(totalVotes))                          //nolint:gosec

		// Penalize the validator whose the valid vote rate is smaller than min threshold
		if validVoteRate.LT(minValidPerWindow) {
			validator := k.StakingKeeper.Validator(ctx, operator)
			if validator.IsBonded() && !validator.IsJailed() {
				consAddr, err := validator.GetConsAddr()
				if err != nil {
					panic(err)
				}

				k.StakingKeeper.Slash(
					ctx, consAddr,
					distributionHeight, validator.GetConsensusPower(powerReduction), slashFraction,
				)
				k.StakingKeeper.Jail(ctx, consAddr)
				oracleKeeperMetrics.validatorSlashedTotal.Add(ctx.Context(), 1, otelmetric.WithAttributes(attribute.String("validator", consAddr.String()), attribute.String("type", "oracle")))
			}
		}

		ctx.EventManager().EmitEvent(
			sdk.NewEvent(types.EventTypeEndSlashWindow,
				sdk.NewAttribute(types.AttributeKeyOperator, operator.String()),
				sdk.NewAttribute(types.AttributeKeyMissCount, strconv.FormatUint(votePenaltyCounter.MissCount, 10)),
				sdk.NewAttribute(types.AttributeKeyAbstainCount, strconv.FormatUint(votePenaltyCounter.AbstainCount, 10)),
				sdk.NewAttribute(types.AttributeKeySuccessCount, strconv.FormatUint(votePenaltyCounter.SuccessCount, 10)),
			),
		)

		k.DeleteVotePenaltyCounter(ctx, operator)
		return false
	})

func EndBlocker(ctx sdk.Context, k keeper.Keeper) {
	start := time.Now()
	defer func() {
		oracleMetrics.endBlockerDuration.Record(ctx.Context(), time.Since(start).Seconds())
	}()

	params := k.GetParams(ctx)
	// Do slash who did miss voting over threshold and
	// reset miss counters of all validators at the last block of slash window
	if utils.IsPeriodLastBlock(ctx, params.SlashWindow) {
		k.SlashAndResetCounters(ctx)
		// Compare vote targets and actives and remove excess feeds
		k.RemoveExcessFeeds(ctx)
	}
