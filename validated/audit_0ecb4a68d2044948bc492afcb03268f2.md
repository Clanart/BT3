### Title
Empty aggregate bypasses Schnorr signature verification - (File: crypto/schnorr/src/aggregate.rs)

### Summary
`SchnorrAggregate::verify` accepts an aggregate containing zero nonces when the caller supplies zero key/challenge pairs. With `s = 0`, the verification equation reduces to the identity and returns true without authenticating any public key. [1](#0-0) 

### Finding Description
`SchnorrAggregate::read` permits the encoded nonce list length to be zero and then reads `s` from attacker-controlled bytes. [2](#0-1) 

During verification, an empty `keys_and_challenges` slice satisfies the length check for empty `Rs`, adds no randomized signature statements, and leaves only the pair `(-s, G)`. [1](#0-0) 

Setting `s = 0` makes `multiexp_vartime` evaluate `0 * G`, which is the identity, so verification succeeds despite there being no key, nonce, or message challenge to authenticate. [3](#0-2) 

### Impact Explanation
An unprivileged party can submit the serialized aggregate encoding `0` nonce commitments followed by the canonical zero scalar. Any verifier that invokes `SchnorrAggregate::read` and then `verify` with an empty `keys_and_challenges` set will accept the bytes as a valid aggregate signature, even though no signer authenticated anything. [2](#0-1) [1](#0-0) 

### Likelihood Explanation
The attack is deterministic and requires no private key, valid nonce, or signature-share possession. Its prerequisite is a verification path that permits an empty aggregate/key set; the public parser and verifier do not reject that condition. [2](#0-1) [4](#0-3) 

### Recommendation
Reject empty aggregate signatures in `SchnorrAggregate::verify`, either by requiring `!self.Rs.is_empty()` or requiring `!keys_and_challenges.is_empty()` before evaluating the multiexponentiation. [1](#0-0) 

### Proof of Concept
For a ciphersuite `C`, the encoded form is four little-endian zero bytes followed by the canonical encoding of scalar zero:

```rust
let mut encoded = 0u32.to_le_bytes().to_vec();
encoded.extend(C::F::ZERO.to_repr().as_ref());

let signature = SchnorrAggregate::<C>::read(&mut encoded.as_slice()).unwrap();
assert!(signature.verify(b"example-dst", &[]));
```

The read succeeds because the declared `Rs` length is zero and zero is a canonical scalar. [2](#0-1)  Verification succeeds because the sole statement is `0 * G`, which is the identity. [3](#0-2)
