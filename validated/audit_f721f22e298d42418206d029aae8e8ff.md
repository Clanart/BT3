### Title
Out-of-bounds read (unbounded index access) in `is_atom_canonical`/`is_clvm_canonical` reachable from any submitted spend bundle - (File: `chia/full_node/mempool_manager.py`)

### Summary
CVE-2017-17912 is a heap buffer over-read caused by a length-prefix-driven comparison (`LocaleNCompare`) walking past the end of an allocated buffer while parsing an untrusted TIFF field. The chia-blockchain analog is `is_atom_canonical()` / `is_clvm_canonical()` in `chia/full_node/mempool_manager.py`, which parses attacker-controlled CLVM byte buffers (`coin_spend.puzzle_reveal` and `coin_spend.solution`) using a length-prefix scheme, indexing directly into the buffer (`clvm_buffer[offset]`) without ever checking `offset` against `len(clvm_buffer)`.

### Finding Description
`is_atom_canonical()` reads the length-prefix byte at `clvm_buffer[offset]` and, depending on the top bits, walks forward `prefix_len` additional bytes (`clvm_buffer[offset]` in the loop at lines 177-181 of `chia/full_node/mempool_manager.py`), then returns `1 + prefix_len + atom_len` as the number of bytes "consumed" — all without validating that these offsets are within bounds of `clvm_buffer`. [1](#0-0) 

`is_clvm_canonical()` calls this in a loop, advancing `offset` by the (unchecked) returned `atom_len`, and dereferences `clvm_buffer[offset]` again on the next iteration (line 199) with no bound check either. [2](#0-1) 

This is invoked directly on attacker-supplied bytes during mempool admission of every spend bundle: [3](#0-2) 

If a crafted `puzzle_reveal` or `solution` encodes a length prefix (e.g. `0xC0`+, `0xE0`+, `0xF0`+, `0xF8`+, `0xFC`+ lead bytes) whose prefix bytes or resulting `atom_len` extend past the actual end of the buffer, `is_atom_canonical` will attempt to read `clvm_buffer[offset]` at an out-of-bounds index. In CPython, indexing a `bytes` object out of range raises `IndexError`, which is an *unhandled* exception at this call site (not caught by any `try/except`), rather than continuing gracefully as `ValueError`/`AssertionError` paths elsewhere in the file do (compare with `chia/full_node/full_block_utils.py`'s `skip_bytes`/`skip_list`, which explicitly bound-check length prefixes before slicing, at `chia/full_node/full_block_utils.py:15-34`). [4](#0-3) 

### Impact Explanation
An unprivileged network peer/wallet user can submit a spend bundle with a truncated, malformed length-prefix atom as the puzzle reveal or solution. `validate_spend_bundle()` calls `is_clvm_canonical()` unconditionally for every coin spend before any other validation, so this code path is reached for any submitted spend bundle, not just DEDUP-eligible ones. A crafted buffer that has a non-canonical atom whose length-prefix bytes point past the buffer boundary will cause `is_atom_canonical` to index out of range, raising an unhandled `IndexError` inside `validate_spend_bundle`. Since this runs inside the full node's mempool-admission code path (holding the blockchain lock per the docstring), an uncaught exception here can propagate up and crash/disrupt mempool processing for the node handling the spend bundle — a spend-triggered transaction-processing halt, which matches the "Validate" criteria of this analog search.

### Likelihood Explanation
High likelihood of triggering the crash: any unprivileged party who can submit a spend bundle (via RPC or over the wallet/full-node protocol) fully controls the bytes of `puzzle_reveal` and `solution`. Constructing a length-prefix byte (e.g. `0xFC`) with insufficient trailing bytes, or an `atom_len` computed from those bytes that exceeds the remaining buffer length, is a simple, deterministic, low-cost operation requiring no cryptographic material or special privilege.

### Recommendation
Add explicit bounds checks in `is_atom_canonical` and `is_clvm_canonical` before every `clvm_buffer[offset]` access, mirroring the pattern used in `chia/full_node/full_block_utils.py` (`skip_bytes`, `skip_list`), which validates remaining buffer length against the declared length before indexing/slicing, and raises a caught/handled `ValueError` instead of letting an `IndexError` propagate. At minimum, wrap the call sites in `validate_spend_bundle` in the try/except that translates any parsing failure (including `IndexError`) into `Err.INVALID_COIN_SOLUTION`.

### Proof of Concept
1. Construct a `CoinSpend` with a `solution` (or `puzzle_reveal`) whose bytes are, e.g., `b"\xfc"` (a lead byte in the `0b11111100` bucket implying a 5-byte trailing length prefix) followed by fewer than 5 bytes, e.g. `b"\xfc\x00"`.
2. Submit a `SpendBundle` containing this `CoinSpend` to a full node's mempool (e.g. via `push_tx` RPC or protocol message).
3. `MempoolManager.validate_spend_bundle()` calls `is_clvm_canonical(bytes(coin_spend.solution))` at `chia/full_node/mempool_manager.py:723-726`, which calls `is_atom_canonical(clvm_buffer, 0)`.
4. Inside `is_atom_canonical`, the loop `for i in range(prefix_len): ... offset += 1; atom_len |= clvm_buffer[offset]` (lines 177-181) attempts to read `clvm_buffer[1]` through `clvm_buffer[5]`, but the buffer is only 2 bytes long, raising `IndexError: index out of range` unhandled at this call site.

```python
def is_atom_canonical(clvm_buffer: bytes, offset: int) -> tuple[int, bool]:
    b = clvm_buffer[offset]
    if (b & 0b11000000) == 0b10000000:
        # 6 bits length prefix
        mask = 0b00111111
        prefix_len = 0
        min_value = 1
    elif (b & 0b11100000) == 0b11000000:
        # 5 + 8 bits length prefix
        mask = 0b00011111
        prefix_len = 1
        min_value = 1 << 6
    elif (b & 0b11110000) == 0b11100000:
        # 4 + 8 + 8 bits length prefix
        mask = 0b00001111
        prefix_len = 2
        min_value = 1 << (5 + 8)
    elif (b & 0b11111000) == 0b11110000:
        # 3 + 8 + 8 + 8 bits length prefix
        mask = 0b00000111
        prefix_len = 3
        min_value = 1 << (4 + 8 + 8)
    elif (b & 0b11111100) == 0b11111000:
        # 2 + 8 + 8 + 8 + 8 bits length prefix
        mask = 0b00000011
        prefix_len = 4
        min_value = 1 << (3 + 8 + 8 + 8)
    elif (b & 0b11111110) == 0b11111100:
        # 1 + 8 + 8 + 8 + 8 + 8 bits length prefix
        mask = 0b00000001
        prefix_len = 5
        min_value = 1 << (2 + 8 + 8 + 8 + 8)

    atom_len = b & mask
    for i in range(prefix_len):
        atom_len <<= 8
        offset += 1
        atom_len |= clvm_buffer[offset]

    return 1 + prefix_len + atom_len, atom_len >= min_value
```

```python
def skip_list(buf: memoryview, skip_item: Callable[[memoryview], memoryview]) -> memoryview:
    if len(buf) < 4:
        raise ValueError(f"list count prefix requires 4 bytes, remaining buffer {len(buf)}")
    n = int.from_bytes(buf[:4], "big", signed=False)
    buf = buf[4:]
    if n > len(buf):
        raise ValueError(f"list count {n} exceeds remaining buffer {len(buf)}")
    for _ in range(n):
        buf = skip_item(buf)
    return buf


def skip_bytes(buf: memoryview) -> memoryview:
    if len(buf) < 4:
        raise ValueError(f"byte length prefix requires 4 bytes, remaining buffer {len(buf)}")
    n = int.from_bytes(buf[:4], "big", signed=False)
    buf = buf[4:]
    if n > len(buf):
        raise ValueError(f"byte length {n} exceeds remaining buffer {len(buf)}")
    return buf[n:]
```
