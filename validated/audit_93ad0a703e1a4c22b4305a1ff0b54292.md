### Title
DataLayer Subscription/Mirror URLs Are Fetched Without Any Host or DNS Validation, Enabling SSRF to Internal Network/Metadata Endpoints - (File: chia/data_layer/download_data.py)

### Summary
The DataLayer service accepts arbitrary mirror/subscription URLs — supplied either directly via the `/subscribe` RPC or indirectly via on-chain `DLNewMirror` coins created by any store owner — and later fetches those URLs with `aiohttp` from the local node process with **zero** hostname/IP validation. Unlike the referenced TypeBot bug (which at least checked literal IPs/blocked-hostname strings before the DNS-bypass flaw), this codebase performs **no** validation at all: no scheme allow-list, no blocked-hostname list, no literal-IP check, and certainly no DNS resolution check. Any DataLayer participant (an unprivileged "Data Layer client") can therefore cause a peer's node to issue outbound HTTP requests to attacker-chosen hosts, including loopback, cloud metadata (`169.254.169.254`), and RFC1918 private ranges.

### Finding Description
`DataLayerRpcApi.subscribe()` accepts a raw list of URL strings from the RPC caller and passes them straight through to `DataLayer.subscribe()`: [1](#0-0) 

`DataLayer.subscribe()` only strips trailing slashes — it performs no scheme/host validation before persisting the URL as a `ServerInfo`: [2](#0-1) 

Separately, mirror URLs published on-chain by any store owner via `add_mirror`/`DLNewMirror` are pulled by every subscriber's own node during the periodic management loop and merged into that subscriber's local subscription table with no filtering: [3](#0-2) [4](#0-3) 

Those URLs are then used automatically by the background sync loop (`update_subscription` → `fetch_and_validate` → `insert_from_delta_file` → `download_file` → `http_download`) without any host check: [5](#0-4) [6](#0-5) 

`http_download` builds the request URL directly from `server_info.url` and issues an `aiohttp` GET with no host/IP allow-list, no `is_localhost`/`is_in_network` check, and no DNS-resolution-based validation: [7](#0-6) 

The repository does contain helper functions capable of detecting localhost/private targets (`is_localhost`, `is_in_network`, `resolve`) used elsewhere for peer-connection trust decisions, but none of them are applied to DataLayer subscription/mirror URLs: [8](#0-7) 

Existing tests explicitly exercise subscriptions pointed at `http://127.0.0.1/8000`, confirming the code path accepts loopback URLs without complaint: [9](#0-8) 

### Impact Explanation
Any DataLayer participant — including a store's counterparty who simply creates a mirror coin (`add_mirror`, a normal, unprivileged spend) or a local RPC caller invoking `/subscribe` — can force the victim's DataLayer node process to issue outbound HTTP GET requests to attacker-controlled or attacker-chosen internal targets. Because `update_subscriptions_from_wallet` autonomously syncs mirror URLs from chain state and the management loop periodically re-fetches, this is not a one-off local misconfiguration but an automatically triggered outbound request from the victim's own infrastructure, reachable purely through normal DataLayer/offer usage. This can be used to probe or interact with internal services, cloud metadata endpoints, or other hosts on the private network that the victim's DataLayer node can reach, and the response size/behavior differences are observable via server-failure/backoff bookkeeping (`server_misses_file`), giving a blind but real SSRF oracle.

### Likelihood Explanation
High. No special privilege is required — a store owner only needs to publish a mirror coin (a standard wallet spend any user can perform) or any local caller only needs to hit the `/subscribe` DataLayer RPC endpoint with a crafted URL. The vulnerable fetch path (`http_download`) runs unconditionally as part of the normal DataLayer sync loop with no opt-out, and there is no validation logic anywhere in the code to bypass — it is simply absent.

### Recommendation
Before persisting or fetching any subscription/mirror URL, resolve the hostname and validate the resulting IP against loopback/link-local/RFC1918/metadata ranges (reusing `chia/util/network.py`'s `resolve`, `is_localhost`, and `is_in_network` helpers), re-validating at fetch time (not just at subscribe time) to avoid DNS-rebinding-style bypasses, and reject or require explicit opt-in configuration for private-network mirror URLs, both for direct `/subscribe` RPC input and for URLs synced automatically from on-chain mirror coins in `update_subscriptions_from_wallet`.

### Proof of Concept
1. Attacker (Alice) owns a DataLayer store and calls `dl_new_mirror` (wallet RPC, standard unprivileged spend) with `urls=["http://169.254.169.254/latest/meta-data/"]`, confirming the mirror coin on-chain.
2. Victim (Bob) subscribes to Alice's store via `/subscribe` (a normal, expected DataLayer workflow for consuming shared data stores).
3. Bob's DataLayer service management loop calls `update_subscriptions_from_wallet` → `DataStore.update_subscriptions_from_wallet`, pulling Alice's mirror URL into Bob's local subscription table with `from_wallet=1`, no validation performed: [10](#0-9)  and [11](#0-10) .
4. The next `fetch_and_validate` cycle picks this server, and `http_download` performs `session.get("http://169.254.169.254/latest/meta-data/" + "/" + filename, ...)` from Bob's node with no host check: [12](#0-11) .
5. Bob's node has now issued an unauthenticated, attacker-directed outbound HTTP request to a private/metadata address, purely as a side effect of subscribing to Alice's store — demonstrating the SSRF.

```python
async def http_download(
    target_filename_path: Path,
    filename: str,
    proxy_url: str | None,
    server_info: ServerInfo,
    timeout: aiohttp.ClientTimeout,
    log: logging.Logger,
    max_delta_file_size: int,
) -> None:
    """
    Download a file from a server using aiohttp.
    Raises exceptions on errors
    """
    async with aiohttp.ClientSession() as session:
        headers = {"accept-encoding": "gzip"}
        async with session.get(
            server_info.url + "/" + filename,
            headers=headers,
            timeout=timeout,
            proxy=proxy_url,
        ) as resp:
            resp.raise_for_status()
            size = int(resp.headers.get("content-length", 0))
            max_delta_file_size_bytes = max_delta_file_size * 1024 * 1024
            if size > max_delta_file_size_bytes:
                raise MaxDeltaFileSizeExceededError(f"Maximum delta file size exceeded: {max_delta_file_size} MiB.")
            log.debug(f"Downloading delta file {filename}. Size {size} bytes.")
```

```python
async def resolve(host: str, *, prefer_ipv6: bool = False) -> IPAddress:
    try:
        return IPAddress.create(host)
    except ValueError:
        pass
    addrset = await asyncio.get_event_loop().getaddrinfo(host, None)
    # The list returned by getaddrinfo is never empty, an exception is thrown or data is returned.
    ips_v4 = []
    ips_v6 = []
    for family, _, _, _, ip_port in addrset:
        if family not in {socket.AF_INET, socket.AF_INET6}:
            continue  # pragma: no cover
        host_ip = ip_port[0]
        assert isinstance(host_ip, str)
        ip = IPAddress.create(host_ip)
        if family == socket.AF_INET:
            ips_v4.append(ip)
        else:
            ips_v6.append(ip)
    preferred, alternative = (ips_v6, ips_v4) if prefer_ipv6 else (ips_v4, ips_v6)
    if len(preferred) > 0:
        return preferred[0]
    elif len(alternative) > 0:
        return alternative[0]
    else:
        raise ValueError(f"failed to resolve {host} into an IP address")
```
