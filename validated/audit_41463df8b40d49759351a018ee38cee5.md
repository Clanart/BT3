### Title
`ThresholdKeys::read` installs fully attacker-controlled key material: the group key is derived from supplied verification shares with no check that `secret_share` is consistent, so imported keys can be a single-party key known to the attacker - ([File: crypto/dkg/src/lib.rs](https://github.com/serai-dex/serai))

### Summary
Analogous to the GitLab report where a project import blindly trusted a privileged `template: true` flag and silently installed attacker-controlled services into every subsequently created project, `ThresholdKeys::read`/`ThresholdKeys::new` blindly trust serialized key material. The deserializer accepts an arbitrary `secret_share`, arbitrary `verification_shares`, and arbitrary `t`/`n`/`i`, then derives the group key purely by interpolating the first `t` attacker-supplied verification shares — never verifying that `G * secret_share == verification_shares[i]` or that the shares lie on any common polynomial. A crafted blob therefore yields a `ThresholdKeys` whose `group_key()` is an attacker-known single-party key, while the importer believes it holds a threshold key.

### Finding Description

`ThresholdKeys::read` parses `t`, `n`, `i`, an interpolation method, a `secret_share`, and `n` verification shares, then calls `ThresholdKeys::new`. [1](#0-0) 

`ThresholdKeys::new` checks only cardinality (`shares.len() == n`), participant bounds, and `t == n` for `Constant` interpolation. It then computes the group key as the Lagrange/Constant interpolation of `verification_shares[1..=t]`: [2](#0-1) 

```rust
let t = (1 ..= params.t()).map(Participant).collect::<Vec<_>>();
let group_key =
  t.iter().map(|i| verification_shares[i] * interpolation.interpolation_factor(*i, &t)).sum();
```

There is no verification that the deserialized `secret_share` is the evaluation of the polynomial committed to by `verification_shares` at index `i`, i.e. no `G * secret_share == verification_shares[i]` check anywhere in `new`, `read`, or `view`. [3](#0-2) 

Because `Constant` interpolation is also accepted (it just requires `t == n`), the attacker has full freedom over every coefficient: they can pick a secret `x`, set all verification shares so interpolation yields `G * x` as `group_key`, and set the victim's `secret_share` to anything. The resulting object is internally consistent to every consumer (`group_key()`, `view()`, `write`/`serialize` round-trip through `GeneratedKeysDb::read_keys`/`save_keys` in `processor/src/key_gen.rs` [4](#0-3) ), yet the "threshold key" is a single-party key whose discrete log `x` the attacker knows.

### Impact Explanation
Any flow that feeds untrusted bytes into `ThresholdKeys::read` — key backup/restore, key import, peer-supplied key blobs — produces a `ThresholdKeys` that every downstream consumer treats as authoritative:

- `group_key()` feeds `N::tweak_keys` and is what bitcoin-serai's `Scanner` derives deposit addresses/scan keys from, so funds "received" under this key are spendable only by the attacker (analogous to GitLab exfiltrating all project data to attacker infrastructure).
- Even absent theft, `secret_share` not matching `verification_shares[i]` makes every FROST `sign_share` the victim produces fail `complete`'s aggregate verification while other participants' shares (per the attacker's injected verification shares) remain valid — a silent, blame-misattributing integrity failure. [5](#0-4) 

### Likelihood Explanation
Reachability is conditional: the in-scope rules treat untrusted bytes reaching `ThresholdKeys::read` as a valid input class (e.g. an import/restore path, exactly like GitLab's project-import entry point). The primitive itself is deterministic and requires no collusion, malformed peer behavior, or leaked secrets — only a crafted serialized blob. Where an integrator only ever obtains keys from an in-process PedPoP `KeyMachine`, the impact degrades to a footgun; the crate exposes `read`/`new` as public API with no documentation of the missing consistency invariant, so misuse is plausible.

### Recommendation
In `ThresholdKeys::new`, verify `C::generator() * secret_share == verification_shares[&params.i()]` and reject otherwise. Ideally also verify that the verification shares are pairwise-consistent on a degree-`t-1` polynomial (check interpolation of every size-`t` subset yields the same `group_key`, or require a commitment format that binds them), mirroring the fix for the GitLab bug (reject privileged/inconsistent fields on import rather than trusting them).

### Proof of Concept
```rust
// Attacker crafts a blob accepted by ThresholdKeys::<C>::read whose group_key
// has a known discrete log, while the victim's secret_share is unrelated.
let x = C::random_nonzero_F(&mut rng);          // attacker-known group secret
let n = 3u16; let t = 2u16; let i = 1u16;

// Pick interpolation-consistent verification shares for a polynomial p with p(0) = x
// (e.g. choose p(1), p(2) randomly, commitments = G*p(l)); set secret_share = garbage.
let mut blob = vec![];
blob.extend(u32::try_from(C::ID.len()).unwrap().to_le_bytes());
blob.extend(C::ID);
blob.extend(t.to_le_bytes()); blob.extend(n.to_le_bytes()); blob.extend(i.to_le_bytes());
blob.push(1);                                  // Interpolation::Lagrange
blob.extend(garbage_share.to_repr().as_ref()); // victim's "secret_share" (unchecked)
for share_commit in &attacker_commitments {    // G*p(1)..=G*p(n) chosen so sum => G*x
  blob.extend(share_commit.to_bytes().as_ref());
}

let keys = ThresholdKeys::<C>::read(&mut blob.as_slice()).unwrap();
// keys.group_key() == G*x: attacker knows x, victim believes a threshold key exists.
// keys.original_secret_share() == garbage_share: no error is raised anywhere.
```

Caveat: this assumes the integrator's threat model includes importing `ThresholdKeys` from untrusted bytes (the scenario the scan rules place in scope); if deserialization only ever consumes self-produced DKG output, severity drops accordingly.

  pub fn read<R: io::Read>(reader: &mut R) -> io::Result<ThresholdKeys<C>> {
    {
      let different = || io::Error::other("deserializing ThresholdKeys for another curve");

      let mut id_len = [0; 4];
      reader.read_exact(&mut id_len)?;
      if u32::try_from(C::ID.len()).unwrap().to_le_bytes() != id_len {
        Err(different())?;
      }

      let mut id = vec![0; C::ID.len()];
      reader.read_exact(&mut id)?;
      if id != C::ID {
        Err(different())?;
      }
    }

    let (t, n, i) = {
      let mut read_u16 = || -> io::Result<u16> {
        let mut value = [0; 2];
        reader.read_exact(&mut value)?;
        Ok(u16::from_le_bytes(value))
      };
      (
        read_u16()?,
        read_u16()?,
        Participant::new(read_u16()?).ok_or(io::Error::other("invalid participant index"))?,
      )
    };

    let mut interpolation = [0];
    reader.read_exact(&mut interpolation)?;
    let interpolation = match interpolation[0] {
      0 => Interpolation::Constant({
        let mut res = Vec::with_capacity(usize::from(n));
        for _ in 0 .. n {
          res.push(C::read_F(reader)?);
        }
        res
      }),
      1 => Interpolation::Lagrange,
      _ => Err(io::Error::other("invalid interpolation method"))?,
    };

    let secret_share = Zeroizing::new(C::read_F(reader)?);

    let mut verification_shares = HashMap::new();
    for l in (1 ..= n).map(Participant) {
      verification_shares.insert(l, <C as Ciphersuite>::read_G(reader)?);
    }

    ThresholdKeys::new(
      ThresholdParams::new(t, n, i).map_err(io::Error::other)?,
      interpolation,
      secret_share,
      verification_shares,
    )
    .map_err(io::Error::other)
  }

impl GeneratedKeysDb {
  #[allow(clippy::type_complexity)]
  fn read_keys<N: Network>(
    getter: &impl Get,
    key: &[u8],
  ) -> Option<(Vec<u8>, (Vec<ThresholdKeys<Ristretto>>, Vec<ThresholdKeys<N::Curve>>))> {
    let keys_vec = getter.get(key)?;
    let mut keys_ref: &[u8] = keys_vec.as_ref();

    let mut substrate_keys = vec![];
    let mut network_keys = vec![];
    while !keys_ref.is_empty() {
      substrate_keys.push(ThresholdKeys::read(&mut keys_ref).unwrap());
      let mut these_network_keys = ThresholdKeys::read(&mut keys_ref).unwrap();
      N::tweak_keys(&mut these_network_keys);
      network_keys.push(these_network_keys);
    }
    Some((keys_vec, (substrate_keys, network_keys)))
  }

  fn save_keys<N: Network>(
    txn: &mut impl DbTxn,
    id: &KeyGenId,
    substrate_keys: &[ThresholdKeys<Ristretto>],
    network_keys: &[ThresholdKeys<N::Curve>],
  ) {
    let mut keys = Zeroizing::new(vec![]);

      keys.extend(substrate_keys.serialize().as_slice());
      keys.extend(network_keys.serialize().as_slice());

      Self::key(
        &id.session,
        &substrate_keys[0].group_key().to_bytes(),
        network_keys[0].group_key().to_bytes().as_ref(),
      ),
      keys,
    );
  }
