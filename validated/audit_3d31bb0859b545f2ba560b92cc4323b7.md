Based on my research, I found a strong Agave analog to the stableswap "disjoint invariant" bug pattern, though I was unable to fully verify one downstream function (`calculate_rewards`) due to tool budget exhaustion. I present my findings with explicit caveats about what remains unverified.

### Title
Reward calculation mixes full stake-delegation set with VAT-truncated vote-account snapshot, breaking the reward invariant - (File: `runtime/src/bank.rs`)

### Summary
Similar to the stableswap bug where the invariant `D`/`S` was computed using only the "ask"/"offer" tokens instead of all `n_coins` tokens in the pool — silently ignoring part of the state that should be included — Agave's epoch-reward pipeline computes rewards using **two data sets of different completeness**: the full set of stake delegations (`stake_delegations`, covering every staker in the network) and a **VAT-truncated** vote-accounts snapshot (`filtered_distribution_vote_accounts`, capped to `MAX_ALPENGLOW_VOTE_ACCOUNTS` and a minimum-balance floor). These two sets are then combined in `calculate_rewards`, creating the same "disjoint computation" pattern: one dimension of the calculation (stakers) reflects the complete universe, while the other dimension (vote-account/validator commission and state data) only reflects a subset.

### Finding Description
`compute_new_epoch_caches_and_rewards` first calculates activated stake for **all** delegations via `stakes.calculate_activated_stake`, producing `unfiltered_distribution_vote_accounts` (the complete vote-accounts universe) and `stake_delegations` (the complete staker universe): [1](#0-0) 

It then derives a VAT-truncated subset by capping the vote accounts to `MAX_ALPENGLOW_VOTE_ACCOUNTS` and applying `minimum_vote_account_balance_for_vat()`: [2](#0-1) 

`get_cached_vote_accounts` is built from this **filtered** snapshot, but `calculate_rewards` is invoked with the **full, unfiltered** `stake_delegations`: [3](#0-2) 

Separately, when the new `EpochStakes` is constructed at an epoch boundary, `total_stake` (used pervasively downstream as the consensus-threshold denominator) is computed only over whichever vote-account map is passed in — the VAT-filtered one on Alpenglow/migration epochs: [4](#0-3) [5](#0-4) 

This `total_stake`/`vote_accounts()` value is then consumed as the ground truth for critical unprivileged-facing consensus computations, e.g. optimistic confirmation: [6](#0-5) 

and duplicate-confirmed/supermajority-root calculations: [7](#0-6) [8](#0-7) 

The structural parallel to the stableswap bug: `n_coins` (analogous to the count of all stakers/validators) stays correct, but the actual sum/invariant computation (`S`, `D` — analogous to `cached_vote_accounts`/`total_stake`) is derived from a truncated subset, while a sibling computation (`stake_delegations`, analogous to the pool's true reserve of all tokens) still reflects the full set. Any staker whose delegated vote account falls outside the VAT-filtered set (lowest-staked validators beyond `MAX_ALPENGLOW_VOTE_ACCOUNTS`, or below `minimum_vote_account_balance_for_vat`) is present in `stake_delegations` but absent from `cached_vote_accounts`/`filtered_distribution_vote_accounts`.

### Impact Explanation
If `calculate_rewards` (not fully inspectable in this session) looks up each delegation's vote account inside `cached_vote_accounts` to obtain commission/vote-state data, delegations pointing at excluded vote accounts would either be skipped (stakers silently lose earned rewards — fund loss) or fall back to a default/incorrect commission value (miscalculated rewards — false execution of the reward invariant). Independently, since `EpochStakes.total_stake()` is reduced by the same filtering, every downstream stake-weighted consensus check (optimistic confirmation, duplicate-confirmed threshold, supermajority root, switch/vote thresholds) operates against an artificially shrunk denominator that excludes an entire tail of validators — a structural deviation from the "count every token/validator" invariant that the switch/threshold checks are designed to preserve.

### Likelihood Explanation
This path triggers automatically at every Alpenglow/migration epoch boundary for any network with more validators than `MAX_ALPENGLOW_VOTE_ACCOUNTS`, or where some validators fall under `minimum_vote_account_balance_for_vat()` — no attacker action is required, only having a below-cutoff amount of stake, which is a realistic, permissionless network condition.

### Recommendation
Ensure `calculate_rewards` sources vote-account state for **every** delegation in `stake_delegations` from the complete (unfiltered) vote-accounts map rather than the VAT-truncated one, or explicitly define and test the fallback behavior for delegations to excluded vote accounts so no reward silently disappears. Separately, audit whether `total_stake`/`vote_accounts()` truncation via VAT filtering is intended to also reduce the denominator used by unrelated consensus thresholds (optimistic confirmation, duplicate-confirmed, supermajority root) or whether those should continue to use the full, unfiltered stake distribution.

### Proof of Concept
Conceptual: caveat — I could not read the body of `calculate_rewards` or `clone_and_filter_for_vat`/`maybe_burn_vat_from_staked_accounts` in this session (tool budget exhausted), so I cannot show the exact line where a filtered-out vote account causes a reward-lookup miss. The test `test_alpenglow_reward_epoch_delegated_stakes_account_is_bounded` confirms the truncation behavior exists and is deterministic (excludes the lowest-staked validator once `num_validators > MAX_ALPENGLOW_VOTE_ACCOUNTS`): [9](#0-8) 
A concrete PoC would require instrumenting `calculate_rewards` to confirm whether a staker delegated to the excluded (`filtered_vote_pubkey`) validator receives correct/any reward, and whether `total_stake` used in `check_vote_stake_threshold`/`supermajority_root` reflects the reduced VAT-filtered set versus the true network-wide stake in a mixed fork-choice scenario.

**Caveat on confidence**: This finding is a strong structural analog (partial-set invariant vs. full-set invariant, mirroring the reported bug class) but is **not fully confirmed end-to-end** — I recommend a Devin session with full file access to trace `calculate_rewards`, `clone_and_filter_for_vat`, and `maybe_burn_vat_from_staked_accounts` to confirm the exact reward-loss or consensus-denominator mechanics before treating this as a fully validated vulnerability.

    fn parse_epoch_vote_accounts(
        epoch_vote_accounts: &VoteAccountsHashMap,
        leader_schedule_epoch: Epoch,
    ) -> (u64, NodeIdToVoteAccounts, EpochAuthorizedVoters) {
        let mut node_id_to_vote_accounts: NodeIdToVoteAccounts = HashMap::new();
        let mut epoch_authorized_voters: EpochAuthorizedVoters = HashMap::new();
        let mut total_stake: u64 = 0;

        for (key, (stake, account)) in epoch_vote_accounts.iter() {
            total_stake += *stake;

            if *stake == 0 {
                continue;
            }

            let vote_state = account.vote_state_view();

            if let Some(authorized_voter) = vote_state.get_authorized_voter(leader_schedule_epoch) {
                let node_vote_accounts = node_id_to_vote_accounts
                    .entry(*vote_state.node_pubkey())
                    .or_default();

                node_vote_accounts.total_stake += stake;
                node_vote_accounts.vote_accounts.push(*key);

                epoch_authorized_voters.insert(*key, *authorized_voter);
            }
        }

        (
            total_stake,
            node_id_to_vote_accounts,
            epoch_authorized_voters,
        )
    }

fn supermajority_root(roots: &[(Slot, u64)], total_epoch_stake: u64) -> Option<Slot> {
    if roots.is_empty() {
        return None;
    }

    // Find latest root
    let mut total = 0;
    let mut prev_root = roots[0].0;
    for (root, stake) in roots.iter() {
        assert!(*root <= prev_root);
        total += stake;
        if total as f64 / total_epoch_stake as f64 > VOTE_THRESHOLD_SIZE {
            return Some(*root);
        }
        prev_root = *root;
    }

    None
}
