## Finding [1](#0-0) [2](#0-1) 

### Title
Forced-ETH balance manipulation of `swapExactTokensForETH` output accounting - (File: `evm/src/utils/uniswapv2/UniV4UniswapV2Wrapper.sol`)

### Summary
The `UniV4UniswapV2Wrapper` contract is Hyperbridge's local analog of "an attacker forcing value into a contract via SELFDESTRUCT/forced transfer to corrupt accounting that assumes only expected inflows occurred." The developers explicitly hardened one function, `swapETHForExactTokens`, against exactly this bug class, but its sibling, `swapExactTokensForETH`, uses the same unguarded balance-delta pattern the report warns about.

### Finding Description
In `swapETHForExactTokens`, the code snapshots the wrapper's own balance *before* the swap and explicitly documents why: [3](#0-2) 

```solidity
// Snapshot standing balance (excluding inbound msg.value) so the refund is the swap-call delta only,
// immune to any ETH that lands on the wrapper from outside the router (e.g., selfdestruct, coinbase).
uint256 balanceBefore = address(this).balance - msg.value;
...
uint256 refundETH = address(this).balance - balanceBefore;
```

This is the same class of bug described in the external report: a contract whose accounting relies on `address(this).balance` deltas can be corrupted by a third party forcibly pushing ETH into it via `SELFDESTRUCT` (or coinbase rewards), which bypasses `receive()`/`fallback()` and cannot be blocked.

`swapExactTokensForETH`, however, measures the *output recipient's* balance delta with no equivalent protection: [4](#0-3) 

```solidity
uint256 balanceBefore = to.balance;

IUniversalRouter(_params.universalRouter).execute(
    abi.encodePacked(bytes1(uint8(Commands.V4_SWAP))), inputs, deadline
);

amounts = new uint256[](2);
amounts[0] = amountIn;
amounts[1] = to.balance - balanceBefore;
```

Any ETH that lands on `to` between the snapshot and the `execute()` call — via a `SELFDESTRUCT` beneficiary transfer, a plain external send, or coinbase payment if `to` happens to be a miner/validator address — is indistinguishable from swap proceeds and gets counted into `amounts[1]`. This is exactly the "forced value transfer corrupts balance-diff accounting" primitive the external report describes, just applied to an arbitrary caller-supplied `to` address instead of `address(this)`.

### Impact Explanation
`amounts[1]` is the reported "actual output received" for a token→ETH swap performed by this wrapper, which stands in for `IUniswapV2Router02.swapExactTokensForETH` in Hyperbridge's intent-fulfillment fee/settlement flow (per the doc comment in `placeOrder`: "collects them in the protocol fee token — swapping from native token via Uniswap V2 if necessary"). If this reported amount feeds into on-chain settlement accounting (fee computed from swap output, dust/received bookkeeping, or order-fill validation), an attacker who controls `to` (e.g., a solver filling their own order, or the caller specifying the recipient) can inflate the reported swap output without the router actually having produced that value, corrupting the exact-once/exact-amount custody invariant the bridge relies on.

### Likelihood Explanation
The precondition is only that the attacker be the caller of `swapExactTokensForETH` (or control the `to` parameter) and be willing to burn their own ETH via a self-destructing helper contract targeting `to` in the same transaction window — no relayer, prover, admin, or governance compromise is required. This is a plain unprivileged-caller path, matching the "unprivileged attacker" requirement, though I was not able to trace the exact downstream call-site that consumes `amounts[1]` within the available iterations, so the magnitude of on-chain fund impact (vs. a purely informational return value) could not be fully confirmed from the indexed code.

### Recommendation
Apply the same fix already used in `swapETHForExactTokens`: snapshot and compare `address(this).balance`/`to.balance` in a way that cannot be polluted by unrelated inbound transfers, or better, have the Universal Router return the actual settled amount directly instead of inferring it via balance deltas on an externally-controlled address.

### Proof of Concept
1. Attacker calls `swapExactTokensForETH(amountIn, amountOutMin, path, to, deadline)` where `to` is an address they control.
2. In the same transaction (or immediately before, front-run in a single composed tx via a helper contract), the attacker deploys and triggers a contract that executes `SELFDESTRUCT(to)` sending `X` extra wei to `to`.
3. `balanceBefore = to.balance` is captured after the forced donation already landed (if before `execute`) or the donation lands between the snapshot and `execute` if properly sequenced (e.g., via a hook/callback inside the router's execution path that the attacker also controls).
4. `amounts[1] = to.balance - balanceBefore` now includes `X` wei that did not come from the actual swap.
5. If any downstream contract (fee computation, dust accounting, order settlement) trusts this `amounts[1]` value as the genuine swap output, the attacker extracts value beyond what the swap actually produced.

Because I could not confirm the exact downstream consumer of `amounts[1]` within the remaining tool budget, treat the settlement-impact severity as unconfirmed pending a trace of all callers of `UniV4UniswapV2Wrapper.swapExactTokensForETH`.

    function swapETHForExactTokens(uint256 amountOut, address[] calldata path, address recipient, uint256 deadline)
        external
        payable
        returns (uint256[] memory amounts)
    {
        PoolKey memory poolKey = _createPoolKey(path[1]);

        bytes[] memory params = new bytes[](3);
        params[0] = abi.encode(poolKey, true, uint128(amountOut), uint128(msg.value), bytes(""));
        params[1] = abi.encode(poolKey.currency0, uint256(0), false);
        params[2] = abi.encode(poolKey.currency1, recipient, amountOut);

        bytes[] memory inputs = new bytes[](1);
        inputs[0] = abi.encode(
            abi.encodePacked(uint8(Actions.SWAP_EXACT_OUT_SINGLE), uint8(Actions.SETTLE), uint8(Actions.TAKE)), params
        );

        // Snapshot standing balance (excluding inbound msg.value) so the refund is the swap-call delta only,
        // immune to any ETH that lands on the wrapper from outside the router (e.g., selfdestruct, coinbase).
        uint256 balanceBefore = address(this).balance - msg.value;

        IUniversalRouter(_params.universalRouter).execute{value: msg.value}(
            abi.encodePacked(bytes1(uint8(Commands.V4_SWAP))), inputs, deadline
        );

        uint256 refundETH = address(this).balance - balanceBefore;

        if (refundETH > 0) {
            (bool success,) = msg.sender.call{value: refundETH}("");
            require(success, "ETH refund failed");
        }

        amounts = new uint256[](2);
        amounts[0] = msg.value - refundETH;
        amounts[1] = amountOut;
    }

    function swapExactTokensForETH(
        uint256 amountIn,
        uint256 amountOutMin,
        address[] calldata path,
        address to,
        uint256 deadline
    ) external returns (uint256[] memory amounts) {
        address token = path[0];
        PoolKey memory poolKey = _createPoolKey(token);

        // Stage the tokens on the router so SETTLE can pay them from its own balance.
        IERC20(token).safeTransferFrom(msg.sender, address(this), amountIn);
        IERC20(token).safeTransfer(_params.universalRouter, amountIn);

        bytes[] memory params = new bytes[](3);
        // token (currency1) -> ETH (currency0), so zeroForOne is false.
        params[0] = abi.encode(poolKey, false, uint128(amountIn), uint128(amountOutMin), bytes(""));
        params[1] = abi.encode(poolKey.currency1, uint256(0), false);
        params[2] = abi.encode(poolKey.currency0, to, uint256(0));

        bytes[] memory inputs = new bytes[](1);
        inputs[0] = abi.encode(
            abi.encodePacked(uint8(Actions.SWAP_EXACT_IN_SINGLE), uint8(Actions.SETTLE), uint8(Actions.TAKE)), params
        );

        uint256 balanceBefore = to.balance;

        IUniversalRouter(_params.universalRouter).execute(
            abi.encodePacked(bytes1(uint8(Commands.V4_SWAP))), inputs, deadline
        );

        amounts = new uint256[](2);
        amounts[0] = amountIn;
        amounts[1] = to.balance - balanceBefore;
    }
