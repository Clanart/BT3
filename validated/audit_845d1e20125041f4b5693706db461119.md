### Title
`translate_signers` performs uncharged `Pubkey::create_program_address` (SHA256) work during CPI, allowing materially underpriced compute via `invoke_signed` - ([File: program-runtime/src/cpi.rs])

### Summary
`cpi_common` charges only a flat `invoke_units` cost (946 CU by default) for the entire CPI dispatch, and this flat charge is consumed *before* `translate_signers` is invoked to derive PDAs from the caller-supplied `signers_seeds`. Unlike the direct `sol_create_program_address`/`sol_try_find_program_address` syscalls, which explicitly charge `create_program_address_units` (1500 CU) per `Pubkey::create_program_address` call, `translate_signers` performs up to `MAX_SIGNERS` (16) SHA256-based `Pubkey::create_program_address` derivations, each over up to `MAX_SEEDS` seeds, without consuming any additional compute units for that work.

### Finding Description
In `cpi_common`, the CU charge for a CPI invocation is taken once, up front, as a flat amount: [1](#0-0) 

Specifically:
```
let amount = invoke_context.get_execution_cost().invoke_units;
invoke_context.compute_meter.consume_checked(amount)?;
...
let signers = translate_signers(caller_program_id, signers_seeds_addr, signers_seeds_len, invoke_context)?;
```
`translate_signers` then loops over up to `MAX_SIGNERS` (16) signer-seed sets and, for each, translates up to `MAX_SEEDS` seeds and calls `Pubkey::create_program_address(&seeds_bytes, program_id)`, which internally performs a SHA256 hash over the concatenated seed bytes plus a domain marker: [2](#0-1) 

No `compute_meter.consume_checked` call exists anywhere in `translate_signers` for this SHA256 work, contrary to the syscall entrypoints for the same primitive. `SyscallCreateProgramAddress` and `SyscallTryFindProgramAddress`, which are the syscalls a program would call directly (not via CPI signing), explicitly charge `create_program_address_units` (1500 CU) per invocation before performing the same `Pubkey::create_program_address` call: [3](#0-2) 

So the same underlying cryptographic operation (`Pubkey::create_program_address`, SHA256-based derivation) is priced at 1500 CU when reached via the dedicated syscall, but is free (beyond the single flat `invoke_units` charge for the whole CPI) when reached via `invoke_signed`'s `signers_seeds` argument, no matter how many signers (up to 16) or how many/how-long seeds (up to `MAX_SEEDS` each) are supplied. `MAX_SIGNERS` is fixed at 16 and enforced only as a count-cap, not as a compute-cost multiplier: [4](#0-3) 

### Impact Explanation
A malicious but valid unprivileged program can call `invoke_signed` with 16 signer-seed sets, each set containing multiple seeds, causing 16 SHA256-based PDA derivations per CPI call while the runtime only charges one flat `invoke_units` (946 CU) for the whole CPI. Equivalent explicit derivation via `sol_create_program_address` would cost 16 × 1500 = 24,000 CU. By repeating `invoke_signed` calls (bounded only by `compute_unit_limit` / `invoke_units`, i.e. up to ~1400 CPI calls per transaction at default MAX_COMPUTE_UNIT_LIMIT), an attacker can amplify actual wall-clock CPU work (SHA256 hashing) relative to the CU cost charged, compared to the intended per-derivation pricing model used elsewhere in the codebase. This is a compute-cost-model / underpricing issue (materially underpriced compute), which degrades validator performance under adversarial but otherwise valid programs, consistent with the "CPU exhaustion / underpriced compute" bounty category.

### Likelihood Explanation
This requires no privileged access: any user can deploy an sBPF program and invoke `invoke_signed`/`invoke_signed_unchecked` with attacker-controlled `signers_seeds` (up to `MAX_SIGNERS`=16, each with up to `MAX_SEEDS`=16 seeds of up to `MAX_SEED_LEN` bytes). This is directly reachable through the standard CPI invocation path used by essentially all Solana programs, so it is fully feasible and repeatable within a single transaction and across transactions.

### Recommendation
Charge `create_program_address_units` (or an equivalent per-derivation cost) inside `translate_signers` once per signer-seed set actually processed (i.e., per call to `Pubkey::create_program_address`), in addition to the flat `invoke_units` charge in `cpi_common`, mirroring the cost model already applied in `SyscallCreateProgramAddress`/`SyscallTryFindProgramAddress`.

```rust
pub fn translate_signers(
    program_id: &Pubkey,
    signers_seeds_addr: u64,
    signers_seeds_len: u64,
    invoke_context: &InvokeContext,
) -> Result<Vec<Pubkey>, Error> {
    let check_aligned = invoke_context.get_check_aligned();
    let memory_mapping = invoke_context.memory_contexts.memory_mapping()?;
    if signers_seeds_len > 0 {
        let signers_seeds = translate_slice::<VmSlice<VmSlice<u8>>>(
            memory_mapping,
            signers_seeds_addr,
            signers_seeds_len,
            check_aligned,
        )?;
        if signers_seeds.len() > MAX_SIGNERS {
            return Err(Box::new(CpiError::TooManySigners));
        }
        Ok(signers_seeds
            .iter()
            .map(|signer_seeds| {
                let untranslated_seeds = translate_slice::<VmSlice<u8>>(
                    memory_mapping,
                    signer_seeds.ptr(),
                    signer_seeds.len(),
                    check_aligned,
                )?;
                if untranslated_seeds.len() > MAX_SEEDS {
                    return Err(Box::new(InstructionError::MaxSeedLengthExceeded) as Error);
                }
                let seeds_bytes = untranslated_seeds
                    .iter()
                    .map(|untranslated_seed| {
                        translate_vm_slice(untranslated_seed, memory_mapping, check_aligned)
                    })
                    .collect::<Result<Vec<_>, Error>>()?;
                Pubkey::create_program_address(&seeds_bytes, program_id)
                    .map_err(|err| Box::new(CpiError::BadSeeds(err)) as Error)
            })
            .collect::<Result<Vec<_>, Error>>()?)
    } else {
        Ok(vec![])
    }
}
```
