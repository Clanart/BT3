### Title
`SinglePlusAnyoneCanPay` sighash on payout transactions lets any unprivileged party rewrite the OP_RETURN operator-attribution after the fact, permanently orphaning the deposit's reimbursement path - (File: `core/src/operator.rs`, `core/src/builder/transaction/operator_reimburse.rs`, `core/src/verifier.rs`)

### Summary
The equality that must hold is: `payout_payer_operator_xonly_pk stored for a withdrawal == the party whose funds actually fronted the payout`. Because the user's authorization for the `payout_tx` is signed with `SIGHASH_SINGLE | SIGHASH_ANYONECANPAY`, that signature only commits to input #0 and output #0 of the transaction — it does **not** commit to the OP_RETURN output that records which operator is to be credited/reimbursed. Any party that observes a broadcast/mempool payout transaction can extract this reusable signature and rebroadcast a competing, fee-bumped transaction with the identical user input/output but an arbitrary (or no) operator attribution in the OP_RETURN, while funding the payout itself. Once such a transaction confirms, `update_finalized_payouts` blindly records whatever OP_RETURN pubkey is present (or `NULL`), and the reimbursement query is keyed by exact match on that pubkey. If the confirmed pubkey does not belong to any registered operator, no operator's `PayoutCheckerTask` will ever pick this payout up, so the deposit can never be reimbursed — the money that funded the withdrawal is unrecoverable and the deposit's move-to-vault UTXO can never legitimately be spent.

### Finding Description
The user's authorization to spend the withdrawal UTXO for a payout is verified with the `SinglePlusAnyoneCanPay` sighash flag: [1](#0-0) 

`SinglePlusAnyoneCanPay` means the produced sighash — and hence the signature — is invariant to every input beyond index 0 and every output beyond index 0. The OP_RETURN output that records `operator_xonly_pk` is built into the same transaction at construction time: [2](#0-1) 

Because this OP_RETURN output is *not* index 0, it is completely outside what the user's signature commits to. The same is true for the optimistic-payout path, which documents the identical requirement: [3](#0-2) 

Once a payout transaction (with any OP_RETURN content) confirms on Bitcoin, the verifier trusts whatever is present in that output to attribute the payout to an operator: [4](#0-3) 

That value is persisted verbatim and later used as an exact-match lookup key for the honest operator's own reimbursement task: [5](#0-4) [6](#0-5) 

No code path validates that the OP_RETURN pubkey (a) belongs to a registered operator, or (b) corresponds to whoever actually supplied the funding inputs of the mined transaction. Since the user's witness signature is public as soon as the transaction is broadcast (mempool-visible), any unprivileged party can:
1. Observe an honest operator's broadcast `payout_tx` (input #0 = withdrawal UTXO, output #0 = the user's payout, both fixed by the SIGHASH_SINGLE|ANYONECANPAY-covered signature).
2. Copy that witness signature into a newly constructed transaction with the *same* input #0 and output #0, but supply their own funding input(s)/change and their own (or an arbitrary/garbage) OP_RETURN pubkey.
3. Broadcast with a higher fee via RBF so it displaces the honest operator's transaction.

The resulting confirmed transaction still pays the user correctly (output #0 is fixed), so users are not harmed directly, but the operator-attribution binding is now controlled by whoever won the fee race rather than being cryptographically tied to who is authorized to be reimbursed.

### Impact Explanation
This breaks the custody/attribution equality directly: the party recorded as the payer (`payout_payer_operator_xonly_pk`) need not be a registered protocol operator at all. If the confirmed OP_RETURN pubkey does not match any registered operator's key (e.g., because an attacker inserted an arbitrary key or no valid pubkey), `get_first_unhandled_payout_by_operator_xonly_pk` will never surface this withdrawal to any operator's `PayoutCheckerTask`, and the reimbursement flow (`create_reimburse_txhandler`, spending the move-to-vault UTXO) can never be triggered by anyone. This permanently strands the corresponding move-to-vault UTXO: the withdrawal already happened, but the collateral that should compensate whoever funded it becomes unclaimable forever. This matches the Critical impact category "a vault UTXO permanently frozen."

### Likelihood Explanation
Exploitation requires no privileged role (no verifier/operator/aggregator/watchtower credentials) — only mempool visibility (public) and enough BTC to win a fee race for a single withdrawal amount, which is inherent to the attack, not a precondition of insider access. The attacker's own capital is spent, but the disruption (a permanently orphaned reimbursement path) is disproportionate and deterministic once the malicious transaction confirms instead of the honest one, so the likelihood is directly tied to mempool competitiveness rather than any privileged precondition.

### Recommendation
Do not use `SIGHASH_SINGLE | SIGHASH_ANYONECANPAY` for the payout input when the transaction also carries an attribution-critical output (OP_RETURN operator pubkey). Either:
- Use `SIGHASH_ALL` (or `SIGHASH_SINGLE` without `ANYONECANPAY`, still covering the number/order of outputs) for the user's payout signature so the OP_RETURN attribution is committed to by the same signature, or
- Move the operator attribution into data the user signature already covers (e.g., embed it in the covered output rather than a separate OP_RETURN), or
- Validate, at `update_finalized_payouts` time, that the OP_RETURN pubkey belongs to a registered operator and additionally verify (via the transaction's other inputs) that the funding actually originates from that operator's known collateral/wallet before trusting the attribution.

### Proof of Concept
1. Operator O broadcasts `payout_tx_O`: input #0 = withdrawal dust UTXO (signed by user with `SinglePlusAnyoneCanPay`), output #0 = user payout (amount X to address A), output #1 = anchor, output #2 = OP_RETURN(O's xonly pubkey), funded/paid by O's own additional inputs.
2. Attacker M observes `payout_tx_O` in the mempool and extracts the witness signature on input #0.
3. M builds `payout_tx_M` with: input #0 = same withdrawal UTXO, witness = the copied signature (still valid, since it only commits input #0/output #0), output #0 = identical to O's (amount X to address A) — required for signature validity — output #1 = anchor, output #2 = OP_RETURN(M's pubkey or garbage bytes), plus M's own funding input(s) covering amount X and a higher fee.
4. M broadcasts `payout_tx_M` with higher fee; it replaces `payout_tx_O` in mempool/confirms first.
5. `update_finalized_payouts` (`core/src/verifier.rs:2283-2353`) records `payout_payer_operator_xonly_pk` = M's pubkey (or `NULL` if garbage/absent).
6. No registered operator's `get_first_unhandled_payout_by_operator_xonly_pk` query ever matches this value, so `reimburse_tx` is never constructed for this deposit; the move-to-vault UTXO remains permanently unspendable through the intended reimbursement path.

pub fn create_payout_txhandler(
    input_utxo: UTXO,
    output_txout: TxOut,
    operator_xonly_pk: XOnlyPublicKey,
    user_sig: taproot::Signature,
    _network: bitcoin::Network,
) -> Result<TxHandler<Signed>, BridgeError> {
    let txin = SpendableTxIn::new_partial(input_utxo.outpoint, input_utxo.txout);

    let output_txout = UnspentTxOut::from_partial(output_txout.clone());

    let op_return_txout = op_return_txout(PushBytesBuf::from(operator_xonly_pk.serialize()));

    let mut txhandler = TxHandlerBuilder::new(TransactionType::Payout)
        .with_version(NON_STANDARD_V3)
        .add_input(
            NormalSignatureKind::NotStored,
            txin,
            SpendPath::KeySpend,
            DEFAULT_SEQUENCE,
        )
        .add_output(output_txout)
        .add_output(UnspentTxOut::from_partial(anchor_output(
            NON_EPHEMERAL_ANCHOR_AMOUNT,
        )))
        .add_output(UnspentTxOut::from_partial(op_return_txout))
        .finalize();
    txhandler.set_p2tr_key_spend_witness(&user_sig, 0)?;
    txhandler.promote()
}

    pub async fn get_first_unhandled_payout_by_operator_xonly_pk(
        &self,
        tx: Option<DatabaseTransaction<'_>>,
        operator_xonly_pk: XOnlyPublicKey,
    ) -> Result<Option<(u32, Txid, BlockHash)>, BridgeError> {
        let query = sqlx::query_as::<_, (i32, Option<TxidDB>, Option<BlockHashDB>)>(
            "SELECT w.idx, w.move_to_vault_txid, w.payout_tx_blockhash
             FROM withdrawals w
             WHERE w.payout_txid IS NOT NULL
                AND w.is_payout_handled = FALSE
                AND w.payout_payer_operator_xonly_pk = $1
                ORDER BY w.idx ASC
             LIMIT 1",
        )
        .bind(XOnlyPublicKeyDB(operator_xonly_pk));

        let results = execute_query_with_tx!(self.connection, tx, query, fetch_optional)?;

        results
            .map(|(citrea_idx, move_to_vault_txid, payout_tx_blockhash)| {
                Ok((
                    u32::try_from(citrea_idx).wrap_err("Failed to convert citrea index to u32")?,
                    move_to_vault_txid
                        .expect("move_to_vault_txid Must be Some")
                        .0,
                    payout_tx_blockhash
                        .expect("payout_tx_blockhash Must be Some")
                        .0,
                ))
            })
            .transpose()
    }
