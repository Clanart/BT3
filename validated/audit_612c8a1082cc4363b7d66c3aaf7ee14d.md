### Title
Citrea Light Client Prover RPC Unavailability Blocks Operator Assert Flow, Causing Collateral Slashing — (`core/src/operator.rs`, `core/src/citrea.rs`, `core/src/task/payout_checker.rs`)

### Summary

The operator's `send_asserts` function has a hard, single-point dependency on the Citrea light client prover RPC (`get_light_client_proof_by_l1_height`) with no fallback. If the prover endpoint is unavailable during the assert window, the operator cannot post assert transactions. After `assert_timeout_timelock` blocks elapse, anyone can broadcast pre-signed `AssertTimeout` transactions that burn the operator's collateral (the `BurnConnector` UTXO in the round transaction).

### Finding Description

**Step 1 — LCP is fetched at assert time with no fallback.**

`send_asserts` in `core/src/operator.rs` calls `fetch_validate_and_store_lcp`, which in turn calls the single configured `light_client_prover_client`:

```rust
// core/src/operator.rs ~1315
let lcp_receipt = self
    .citrea_client
    .fetch_validate_and_store_lcp(
        payout_block_height as u64,
        deposit_idx as u32,
        &self.db,
        Some(&mut dbtx),
        self.config.protocol_paramset(),
    )
    .await?;          // ← propagates error; no fallback
```

Inside `fetch_validate_and_store_lcp` (`core/src/citrea.rs`), the DB is checked first; if the LCP was never persisted, it calls:

```rust
// core/src/citrea.rs ~503
let proof_result = self
    .light_client_prover_client
    .get_light_client_proof_by_l1_height(l1_height)
    .await
    .wrap_err("Failed to get light client proof")?;
```

There is exactly one `light_client_prover_client` (configured via `CITREA_LIGHT_CLIENT_PROVER_URL`), no secondary URL, no cached fallback, and no circuit-breaker. If the endpoint is unreachable or returns an error, the `?` propagates all the way up through `send_asserts`, which returns an error.

**Step 2 — The LCP is supposed to be pre-cached by `PayoutCheckerTask`, but the save is not atomic with the kickoff.**

`PayoutCheckerTask::run_once` (`core/src/task/payout_checker.rs`) calls `handle_finalized_payout` first (which queues the kickoff to the tx-sender), then calls `fetch_validate_and_store_lcp`:

```rust
// core/src/task/payout_checker.rs ~72-99
let kickoff_txid = self.operator
    .handle_finalized_payout(&mut dbtx, ...).await?;   // kickoff queued

let _ = self.operator.citrea_client
    .fetch_validate_and_store_lcp(...).await?;          // ← if this fails …

// … dbtx.commit() is never reached; payout stays "unhandled"
```

If `fetch_validate_and_store_lcp` fails, the database transaction is rolled back, so the LCP is **not** persisted. The payout remains "unhandled" and the task retries on the next poll. However, the kickoff transaction may already have been broadcast to Bitcoin via the tx-sender's independent queue. On the next retry, `handle_finalized_payout` is called again against a DB that has not recorded the first kickoff, potentially queuing a duplicate.

**Step 3 — State machine does not automatically re-trigger the assert duty.**

`send_operator_asserts_if_ready` in `core/src/states/kickoff.rs` dispatches `Duty::SendOperatorAsserts` and wraps the call in `capture_error`, which logs the failure and continues without re-scheduling:

```rust
// core/src/states/kickoff.rs ~276-300
async fn send_operator_asserts_if_ready(&mut self, context: &mut StateContext<T>) {
    context.capture_error(async |context| {
        if self.challenged && … {
            context.dispatch_duty(Duty::SendOperatorAsserts { … }).await?;
        }
        Ok::<(), BridgeError>(())
    }).await;
}
```

Once all preconditions are satisfied (all watchtower challenge UTXOs spent, latest blockhash committed), no further state-machine events re-trigger this function. A single failed `send_asserts` call due to LCP unavailability is therefore not automatically retried.

**Step 4 — Collateral is burned after `assert_timeout_timelock` blocks.**

`AssertTimeout` transactions are pre-signed by the N-of-N committee and can be broadcast by anyone after `assert_timeout_timelock` (576 blocks ≈ 4 days on testnet4 config). Each `AssertTimeout` spends the corresponding `Assert` UTXO and the `BurnConnector` UTXO from the round transaction, permanently destroying the operator's collateral.

```rust
// core/src/builder/transaction/operator_collateral.rs ~179-203
TxHandlerBuilder::new(TransactionType::AssertTimeout(idx))
    .add_input(…, kickoff_txhandler.get_spendable_output(UtxoVout::Assert(idx))?, …,
               Sequence::from_height(paramset.assert_timeout_timelock))
    .add_input(…, round_txhandler.get_spendable_output(UtxoVout::CollateralInRound)?, …)
```

### Impact Explanation

If the Citrea light client prover endpoint is unavailable for the duration of the assert window after a challenge is issued, the operator cannot generate or broadcast assert transactions. Pre-signed `AssertTimeout` transactions then burn the operator's `CollateralInRound` UTXO. This is a direct, irreversible loss of operator collateral — a material fund impact within the allowed impact gate ("slashable exposure of operator collateral").

### Likelihood Explanation

The Citrea light client prover is a single configured HTTP endpoint with no fallback URL, no circuit-breaker, and no alternative data source. Any extended outage of that service (network partition, infrastructure failure, or deliberate blocking) lasting longer than `assert_timeout_timelock` blocks after a challenge is issued is sufficient to trigger the slash. The `PayoutCheckerTask` attempts to pre-cache the LCP, but this cache write is not atomic with the kickoff broadcast, so a window exists where the kickoff is on-chain but the LCP is not yet persisted.

### Recommendation

1. **Pre-cache the LCP atomically with the kickoff.** Ensure `fetch_validate_and_store_lcp` succeeds and the LCP is committed to the DB **before** the kickoff transaction is queued to the tx-sender. If the LCP cannot be fetched, do not send the kickoff.

2. **Implement retry logic in the assert duty.** If `send_asserts` fails due to an RPC error, the state machine should schedule a retry (e.g., on the next block event) rather than silently dropping the duty.

3. **Support a fallback LCP source.** Allow configuration of one or more secondary `light_client_prover_url` endpoints. If the primary fails, attempt the secondary before propagating the error.

4. **Decouple the assert from the live RPC call.** Once the LCP is persisted in the DB (which `fetch_validate_and_store_lcp` already supports via `get_lcp_for_assert`), `send_asserts` should never need to call the live prover endpoint. Enforce this by making the DB-cached path the only path in `send_asserts` and failing loudly at kickoff time if the LCP cannot be pre-fetched.

### Proof of Concept

1. Operator fronts a withdrawal and `PayoutCheckerTask` detects the finalized payout.
2. `handle_finalized_payout` queues the kickoff transaction to the tx-sender; the kickoff is broadcast to Bitcoin.
3. The Citrea light client prover endpoint becomes unavailable (infrastructure failure or deliberate block).
4. `fetch_validate_and_store_lcp` in `PayoutCheckerTask` fails; `dbtx` is rolled back; the LCP is **not** persisted; the payout remains "unhandled".
5. A challenger sends the `Challenge` transaction, spending the challenge UTXO.
6. The state machine transitions to `challenged` and calls `send_operator_asserts_if_ready`.
7. `send_asserts` calls `fetch_validate_and_store_lcp`; the DB has no cached LCP; the live RPC call fails; `send_asserts` returns an error.
8. `capture_error` logs the failure; no retry is scheduled.
9. After `assert_timeout_timelock` (576 blocks ≈ 4 days) elapses, any party broadcasts the pre-signed `AssertTimeout` transactions.
10. The operator's `CollateralInRound` UTXO is permanently burned. [1](#0-0) [2](#0-1) [3](#0-2) [4](#0-3) [5](#0-4) [6](#0-5) [7](#0-6)

pub fn create_assert_timeout_txhandlers(
    kickoff_txhandler: &TxHandler,
    round_txhandler: &TxHandler,
    num_asserts: usize,
    paramset: &'static ProtocolParamset,
) -> Result<Vec<TxHandler>, BridgeError> {
    let mut txhandlers = Vec::new();
    for idx in 0..num_asserts {
        txhandlers.push(
            TxHandlerBuilder::new(TransactionType::AssertTimeout(idx))
                .with_version(NON_STANDARD_V3)
                .add_input(
                    (NumberedSignatureKind::AssertTimeout1, idx as i32),
                    kickoff_txhandler.get_spendable_output(UtxoVout::Assert(idx))?,
                    SpendPath::ScriptSpend(0),
                    Sequence::from_height(paramset.assert_timeout_timelock),
                )
                .add_input(
                    (NumberedSignatureKind::AssertTimeout2, idx as i32),
                    kickoff_txhandler.get_spendable_output(UtxoVout::KickoffFinalizer)?,
                    SpendPath::ScriptSpend(0),
                    DEFAULT_SEQUENCE,
                )
                .add_input(
                    (NumberedSignatureKind::AssertTimeout3, idx as i32),
                    round_txhandler.get_spendable_output(UtxoVout::CollateralInRound)?,
                    SpendPath::KeySpend,
                    DEFAULT_SEQUENCE,
                )
                .add_output(UnspentTxOut::from_partial(
                    builder::transaction::anchor_output(paramset.anchor_amount()),
                ))
                .finalize(),
        );
    }
    Ok(txhandlers)
