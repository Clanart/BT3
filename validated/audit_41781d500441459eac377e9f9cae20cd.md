### Title
Forged `ReceivedOutput` records let untrusted bytes create unspendable credited funds - (File: networks/bitcoin/src/wallet/mod.rs)

### Summary
`ReceivedOutput::read` deserializes an arbitrary scalar offset, `TxOut`, and `OutPoint` into a type that downstream transaction construction treats as an authenticated, spendable UTXO. [1](#0-0) [2](#0-1) 

### Finding Description
`Scanner::scan_transaction` normally creates `ReceivedOutput` only after observing a transaction output whose `script_pubkey` matches a registered key offset. [3](#0-2)  `ReceivedOutput::read` bypasses that provenance and accepts independent bytes for `offset`, `output`, and `outpoint`, without binding them to a scanner, a confirmed transaction, or an existing UTXO. [2](#0-1) 

`SignableTransaction::new` then trusts `input.outpoint` and `input.output` as the transaction input and prevout data, while `SignableTransaction::multisig` only checks that `key + offset * G` maps to the serialized output’s `script_pubkey`. [4](#0-3) [5](#0-4)  Consequently, an attacker can choose a valid wallet-controlled script, pair it with a nonexistent or spent outpoint, and obtain a syntactically valid `ReceivedOutput` that the wallet will sign for even though the input cannot be spent. [6](#0-5) 

### Impact Explanation
An application which accepts serialized `ReceivedOutput` values can report or account for funds that are not spendable, and the threshold wallet can complete signatures for a Bitcoin transaction that consensus rejects because the referenced prevout is fake, spent, or otherwise unavailable. [2](#0-1) [7](#0-6) 

### Likelihood Explanation
The attack requires only the ability to submit bytes to `ReceivedOutput::read`; no validator privileges, key material, malformed cryptography, or consensus violation by honest nodes is needed. [2](#0-1)  The attacker must know a wallet-controlled `script_pubkey`, which is publicly observable from prior transactions or derivable when the deposit offset is known. [8](#0-7) 

### Recommendation
Treat serialized `ReceivedOutput` as untrusted input rather than scanner output. Re-derive the record through `Scanner` and verify the outpoint exists, is unspent, has the claimed value and script, and is mature before passing it to `SignableTransaction::new`. [9](#0-8)  If persistence is required, authenticate the serialized record and store enough provenance to bind the offset, transaction ID, vout, value, script, and confirmation state. [1](#0-0) 

### Proof of Concept
```rust
// Let wallet_script be p2tr_script_buf(tweaked_group_key).unwrap()
// and offset be the corresponding Scalar::ZERO/registered offset.

let forged_output = TxOut {
  value: Amount::from_sat(100_000),
  script_pubkey: wallet_script,
};

// An arbitrary outpoint which does not exist or is already spent.
let forged_outpoint = OutPoint::new(Txid::all_zeros(), 0);

// ReceivedOutput::read consumes exactly:
// scalar || consensus(TxOut) || consensus(OutPoint).
let mut bytes = offset.to_bytes().to_vec();
bytes.extend(serialize(&forged_output));
bytes.extend(serialize(&forged_outpoint));

let forged = ReceivedOutput::read(&mut bytes.as_slice()).unwrap();

// This succeeds because the script matches key + offset * G.
let tx = SignableTransaction::new(
  vec![forged],
  &[(payment_script, 50_000)],
  None,
  None,
  1,
).unwrap();

let machine = tx.multisig(&tweaked_keys).unwrap();
// FROST signing then produces witnesses for a transaction spending the fake outpoint.
```

The deserializer accepts this record, `multisig` accepts the key/script relationship, and signing commits to `Prevouts::All` containing the forged `TxOut`; the resulting transaction still cannot spend the nonexistent prevout. [5](#0-4) [6](#0-5)

  pub fn read<R: Read>(r: &mut R) -> io::Result<ReceivedOutput> {
    let offset = Secp256k1::read_F(r)?;
    let output;
    let outpoint;
    {
      let mut buf_r = BufReader::with_capacity(0, r);
      output =
        TxOut::consensus_decode(&mut buf_r).map_err(|_| io::Error::other("invalid TxOut"))?;
      outpoint =

    }

  /// Scan a transaction.
  pub fn scan_transaction(&self, tx: &Transaction) -> Vec<ReceivedOutput> {
    let mut res = Vec::new();
    for (vout, output) in tx.output.iter().enumerate() {
      // If the vout index exceeds 2**32, stop scanning outputs
      let Ok(vout) = u32::try_from(vout) else { break };

      if let Some(offset) = self.scripts.get(&output.script_pubkey) {
        res.push(ReceivedOutput {
          offset: *offset,
          output: output.clone(),
          outpoint: OutPoint::new(tx.compute_txid(), vout),
        });
      }
    }
    res
  }

  /// Scan a block.
  ///
  /// This will also scan the coinbase transaction which is bound by maturity. If received outputs
  /// must be immediately spendable, a post-processing pass is needed to remove those outputs.
  /// Alternatively, scan_transaction can be called on `block.txdata[1 ..]`.
  pub fn scan_block(&self, block: &Block) -> Vec<ReceivedOutput> {
    let mut res = Vec::new();
    for tx in &block.txdata {
      res.extend(self.scan_transaction(tx));
    }
    res
  }
