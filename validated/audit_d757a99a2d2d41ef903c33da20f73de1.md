### Title
`ChangeAdmin` in the tokenfactory module allows irreversible, single-step admin transfer with no confirmation - (File: `x/tokenfactory/keeper/msg_server.go`)

### Summary
The tokenfactory module's `MsgChangeAdmin` handler reassigns the admin of a token-factory denom to `msg.NewAdmin` in a single atomic step, with no two-step confirmation or acceptance flow, mirroring the reported `transferOwnership()` bug class (single-call, irreversible ownership change).

### Finding Description
`ChangeAdmin` in `x/tokenfactory/keeper/msg_server.go` validates only that the sender is the current admin and that the new admin differs from the current one, then immediately calls `server.setAdmin(ctx, msg.Denom, msg.NewAdmin)`: [1](#0-0) 

`setAdmin` overwrites the `DenomAuthorityMetadata.Admin` field directly with no ability for the new admin to accept or reject the transfer, and no rollback path: [2](#0-1) 

This is reachable by any unprivileged account that created a tokenfactory denom (the admin of `factory/{creator}/{subdenom}`) via a plain `MsgChangeAdmin` transaction — exactly the same "unprivileged transaction sender" attack surface as the reported EVM `Vault.transferOwnership()`. Existing tests confirm the admin can even be set to an empty string, permanently relinquishing admin rights with no way to reverse it: `TestAdminMsgs`/`TestChangeAdminDenom` in `x/tokenfactory/keeper/admins_test.go` (lines 59-67, 80-90).

### Impact Explanation
If the denom admin makes a typo in `new_admin`, transfers to an address they no longer control, or accidentally sets it to an empty/unreachable address, all future `Mint`, `Burn`, `SetDenomMetadata`, and further `ChangeAdmin` calls for that denom are permanently locked out — the admin capability for that denom is irrecoverably frozen, with no on-chain recovery mechanism.

### Likelihood Explanation
Likelihood is low-to-moderate: it requires operator error (typo, wrong address, or premature/careless admin rotation) rather than an attacker exploiting a flaw against a victim, and it only affects denoms the erring party itself administers. This mirrors the original report's characterization as an operational/UX safety gap rather than an externally exploitable attack, which caps this at Medium severity.

### Recommendation
Implement a two-step admin transfer for `MsgChangeAdmin`: store a `PendingAdmin` on `DenomAuthorityMetadata` when `ChangeAdmin` is called, and require a follow-up `MsgAcceptAdmin` (or similar) signed by the pending admin before the transfer takes effect, so a typo or mistaken transfer can be caught before it becomes irreversible.

### Proof of Concept
1. Account A creates a tokenfactory denom via `MsgCreateDenom`, becoming its admin (`CreateDenom` in `x/tokenfactory/keeper/createdenom.go`, lines 40-42).
2. Account A submits `MsgChangeAdmin{Sender: A, Denom: denom, NewAdmin: <typo'd or unintended address>}`.
3. `msgServer.ChangeAdmin` immediately sets the new admin with no confirmation step, as shown above.
4. Account A can no longer `Mint`/`Burn`/`SetDenomMetadata`/`ChangeAdmin` for that denom; if the new admin address was mistyped or is unreachable, control over the denom's admin functions is permanently lost, matching the behavior exercised in `TestAdminMsgs` (`x/tokenfactory/keeper/admins_test.go`, lines 38-67).

func (server msgServer) ChangeAdmin(goCtx context.Context, msg *types.MsgChangeAdmin) (*types.MsgChangeAdminResponse, error) {
	ctx := sdk.UnwrapSDKContext(goCtx)

	authorityMetadata, err := server.GetAuthorityMetadata(ctx, msg.Denom)
	if err != nil {
		return nil, err
	}

	if msg.Sender != authorityMetadata.GetAdmin() {
		return nil, types.ErrUnauthorized
	}

	// Validate new admin we change to should be different from current admin
	if msg.NewAdmin == authorityMetadata.GetAdmin() {
		return nil, types.ErrAdminAlreadyExists
	}

	err = server.setAdmin(ctx, msg.Denom, msg.NewAdmin)
	if err != nil {
		return nil, err
	}
	ctx.EventManager().EmitEvents(sdk.Events{
		sdk.NewEvent(
			types.TypeMsgChangeAdmin,
			sdk.NewAttribute(types.AttributeDenom, msg.GetDenom()),
			sdk.NewAttribute(types.AttributeNewAdmin, msg.NewAdmin),
		),
	})

	return &types.MsgChangeAdminResponse{}, nil
}

func (k Keeper) setAdmin(ctx sdk.Context, denom string, admin string) error {
	metadata, err := k.GetAuthorityMetadata(ctx, denom)
	if err != nil {
		return err
	}

	metadata.Admin = admin

	return k.setAuthorityMetadata(ctx, denom, metadata)
