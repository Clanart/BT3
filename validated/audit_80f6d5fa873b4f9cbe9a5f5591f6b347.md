## Title
`pallet-consensus-incentives` freezes `LastRewardedHeight` watermark when a chain's incentive is disabled, letting the next relayer sweep an inflated backlog reward at re-enablement - (File: `modules/pallets/consensus-incentives/src/impls.rs`)

## Summary

### Finding Description
The external report's core broken invariant is: an accounting index (`epoch[asset]`) is only advanced inside a branch gated by a condition (`totalShares != 0`); when that condition is false, the index silently goes stale, and a later state-dependent value (`mint epoch`/`expire epoch`) computed off that stale index grants far more value than the elapsed real time warrants.

Hyperbridge's `pallet-consensus-incentives` has the same shape. `process_message` only executes its body — including the `LastRewardedHeight` watermark update — when `StateMachinesCostPerBlock::<T>::get(state_machine_id)` is `Some`: [1](#0-0) 

If a state machine's cost-per-block is removed via `remove_incentives` (or was never set), `on_executed` still runs and consensus updates for that chain keep landing (via normal `pallet-ismp` consensus message processing, unrelated to this pallet), advancing `latest_commitment_height` on the `IsmpHost`. But because the `if let Some(block_cost) = ...` guard short-circuits, `LastRewardedHeight` is **never touched** while the incentive is off — exactly analogous to `distribute()` skipping `epoch[_tigAsset]` updates while `totalShares[_tigAsset] == 0`. [2](#0-1) 

When governance re-enables the incentive with `update_cost_per_block`, `calculate_reward` computes: [3](#0-2) 

`baseline = LastRewardedHeight::get(...).unwrap_or(previous_height)` — the stale, pre-disablement watermark — while `latest_height` reflects the chain's current (already-advanced) tip. `blocks = latest_height.saturating_sub(baseline)` therefore spans the *entire* disabled period plus any watermark drift, and `reward = blocks * block_cost` (at the *new*, possibly much higher, cost-per-block rate) is paid in full to whichever relayer happens to deliver the very next `ConsensusMessage` after re-enablement.

### Impact Explanation
This is a fund-loss/logic-attack vector on the treasury: any permissionless relayer (per the pallet's own documentation, submitting `ConsensusMessage`s is fully permissionless) can watch `StateMachinesCostPerBlock` and `LastRewardedHeight` on-chain, and as soon as governance re-enables incentives for a paused/never-funded chain, race to be the first to submit a consensus update. That single relayer collects a reward sized to the *entire* backlog of blocks accumulated since the last time the watermark moved — a payout the pallet's own comment ("Rewards only ever cover the span above this watermark, so a height that is revisited after a rollback is not paid for twice") does not intend to allow for a *disabled* period, only for legitimate rollbacks. The treasury pays out an amount disconnected from the actual single delivery performed, i.e., wrong-amount/unauthorized-scale fund transfer to whichever relayer wins the race — directly matching the bounty's "logic attacks" / "transaction manipulation" / "wrong beneficiary or amount" categories.

### Likelihood Explanation
Triggering requires governance to disable (`remove_incentives`) and later re-enable (`update_cost_per_block`) incentives for a state machine — a realistic, foreseeable operational sequence (e.g., pausing a misbehaving/expensive chain's rewards, or a chain simply never having incentives configured until later). No malicious relayer, prover, or admin collusion is needed: the exploiting party is any ordinary, unprivileged relayer racing to submit the next signed `ConsensusMessage`, which is exactly the permissionless action the protocol is designed to reward. This is directly analogous in mechanism and triggerability to the original `distribute()`/`totalShares == 0` finding.

### Recommendation
Update `LastRewardedHeight` to the current `latest_commitment_height` whenever incentives are disabled (in `remove_incentives`) or whenever `process_message` is skipped because `StateMachinesCostPerBlock` is `None`, so that re-enabling incentives only rewards blocks produced *after* re-enablement, not the entire disabled backlog. Alternatively, snapshot and persist the watermark at the moment `remove_incentives` is called, and re-baseline it to the height current at `update_cost_per_block` time rather than letting `calculate_reward` silently span the gap.

### Proof of Concept
1. Governance calls `update_cost_per_block(chain_X, cost=1)` — a relayer submits a consensus update to height 1000; `LastRewardedHeight[chain_X] = 1000` is set and rewarded.
2. Governance calls `remove_incentives(chain_X)` (`StateMachinesCostPerBlock[chain_X]` removed).
3. Over time, chain_X's consensus continues to be relayed and finalized on Hyperbridge via `pallet-ismp` (unrelated to this pallet's reward gating), advancing `latest_commitment_height(chain_X)` to, say, 100000, while `LastRewardedHeight[chain_X]` stays frozen at `1000` because `process_message`'s `if let Some(block_cost) = ...` guard is never entered.
4. Governance calls `update_cost_per_block(chain_X, cost=1_000_000)` to resume incentives (e.g., after negotiating a new rate).
5. Any relayer submits the next `ConsensusMessage` for chain_X. `calculate_reward` computes `blocks = 100000 - 1000 = 99000`, `reward = 99000 * 1_000_000`, all paid from the treasury to that single relayer — far beyond what a single delivered message should earn, and disconnected from the intended "watermark" semantics documented at [4](#0-3) .

	fn process_message(
		state_machine_height: StateMachineHeight,
		state_machine_id: StateMachineId,
		relayer_account: T::AccountId,
	) -> Result<(), Error<T>> {
		if let Some(block_cost) = StateMachinesCostPerBlock::<T>::get(state_machine_id) {
			let reward = Self::calculate_reward(&state_machine_id, block_cost)?;

			if reward.is_zero() {
				return Ok(());
			}

			T::Currency::transfer(
				&T::TreasuryAccount::get().into_account_truncating(),
				&relayer_account,
				reward,
				Preservation::Expendable,
			)
			.map_err(|_| Error::<T>::RewardTransferFailed)?;

			Self::deposit_event(Event::<T>::RelayerRewarded {
				relayer: relayer_account.clone(),
				amount: reward,
				state_machine_height,
			});

			T::ReputationAsset::mint_into(&relayer_account, reward.saturated_into())
				.map_err(|_| Error::<T>::ReputationMintFailed)?;

			LastRewardedHeight::<T>::mutate(state_machine_id, |watermark| {
				*watermark = Some(watermark.unwrap_or_default().max(state_machine_height.height));
			});
		}
		Ok(())
	}

	/// Calculate the reward for a message based on the state machine id
	fn calculate_reward(
		state_machine_id: &StateMachineId,
		block_cost: <T as pallet_ismp::Config>::Balance,
	) -> Result<<T as pallet_ismp::Config>::Balance, Error<T>> {
		let host = <T::IsmpHost>::default();
		let latest_height = host
			.latest_commitment_height(state_machine_id.clone())
			.map_err(|_| Error::<T>::CouldNotGetStateMachineHeight)?;
		let previous_height =
			host.previous_commitment_height(state_machine_id.clone()).unwrap_or_default();

		// Use the rewarded watermark as the baseline and fall back to the previous height until
		// the first reward is recorded for this chain. The watermark only moves forward, so a
		// height that is rolled back and later resubmitted is not paid for a second time.
		let baseline = LastRewardedHeight::<T>::get(state_machine_id).unwrap_or(previous_height);

		let blocks = latest_height.saturating_sub(baseline);

		let blocks_as_balance: <T as pallet_ismp::Config>::Balance = blocks.saturated_into();
		let reward = blocks_as_balance.saturating_mul(block_cost);

		Ok(reward)
	}
