### Title
Unauthenticated dust deposits to scanned `script_pubkey`s are reported as spendable inputs, inflating `needed_fee` and permanently breaking `SignableTransaction` construction - ([File: networks/bitcoin/src/wallet/mod.rs](networks/bitcoin/src/wallet/mod.rs))

### Summary
The bug class in the external report is a permissionless micro-deposit that corrupts shared accounting (pair reserves via `transfer` + `sync`) so a later state transition (`addLiquidityETH`) fails. The Serai analog lives in the Bitcoin wallet scanner: `Scanner::scan_transaction` credits any output paying to a registered `script_pubkey` as a `ReceivedOutput`, with no value floor and no provenance check. Any unprivileged party can send transactions to the multisig's External/Branch/Change/Forwarded P2TR scripts, and every such output becomes a spend input candidate. When those outputs are consumed by `SignableTransaction::new`, each one deterministically raises `needed_fee` and transaction weight, until construction fails with `NotEnoughFunds` or `TooLargeTransaction` — mirroring the `INSUFFICIENT_LIQUIDITY` abort in the report.

### Finding Description
`Scanner` keys purely on `script_pubkey`. In `scan_transaction`, any output whose `script_pubkey` is in `self.scripts` is pushed as a `ReceivedOutput` regardless of value, sender, or intent — there is no `DUST` floor, no check the output was created by the protocol, and no way to distinguish a 1-sat griefing output from a real deposit [1](#0-0) . The scripts an attacker must hit are all public: the base key script is registered in `Scanner::new`, and Branch/Change/Forwarded offsets are deterministically derived via `hash_to_F(KEY_DST, …)` and registered into the same map [2](#0-1) .

On the spend side, `SignableTransaction::new` sums all provided inputs, computes `needed_fee = fee_per_vbyte * vbytes` where `vbytes` grows linearly in `inputs.len()`, and rejects with `NotEnoughFunds` if `input_sat < payment_sat + needed_fee`, or with `TooLargeTransaction` once weight exceeds `MAX_STANDARD_TX_WEIGHT` [3](#0-2) . The caller-visible failure modes are exactly analogous to `addLiquidityETH` reverting: the transaction simply cannot be constructed. The processor wrapper treats `TooLargeTransaction` as a `panic!` ("despite limiting inputs/outputs"), turning injected outputs into a hard failure rather than a graceful skip [4](#0-3) .

Additionally, `get_outputs` classifies attacker-sent outputs by offset kind (`kinds[offset_repr]`), so dust sent to the Branch or Change script is misreported as protocol-internal `OutputType::Branch`/`Change` rather than `External`, corrupting the scheduler's bookkeeping [5](#0-4) .

### Impact Explanation
An unprivileged attacker, spending only ordinary Bitcoin transaction fees, can (a) inflate `needed_fee` for every plan consuming the polluted output set, (b) push input count/weight past `MAX_STANDARD_TX_WEIGHT` causing `TooLargeTransaction` (a panic in the processor path — a liveness failure), and (c) cause misclassification of fake deposits as Change/Branch outputs, i.e., funds reported received under a kind they were never created as. This is a DoS of the withdrawal/signing path and an accounting-integrity violation, reachable purely with public Bitcoin transactions — the same reachability class as the reported `transfer` + `sync` attack.

### Likelihood Explanation
The scripts are deterministic and publicly derivable; no keys, validator status, or collusion is required. The attack costs the attacker real fees, but each dust input (~546 sats) forces ~57+ vB of witness/input weight the honest side must pay for or fail on, and the scanner provides no mechanism to reject these outputs before they enter the input set.

### Recommendation
- In `Scanner::scan_transaction` (or in `get_outputs`), apply a minimum-value / spendability filter (e.g., ignore outputs below `DUST` or below `DUST + per-input fee cost`) before emitting a `ReceivedOutput`.
- Have `SignableTransaction::new` enforce a per-input value sanity bound or accept an explicit input cap, and drop/queue uneconomical inputs instead of failing construction.
- Treat `TooLargeTransaction` as a recoverable signal to select a subset of inputs rather than a panic, and verify `kind` attribution only for outputs the protocol itself created (e.g., match expected change by plan, not just by offset script).

### Proof of Concept
1. Derive the multisig's External/Change/Branch P2TR scripts (`p2tr_script_buf(key + G*offset)` with the well-known `KEY_DST` offsets).
2. Broadcast transactions paying the minimum relayable amount to those scripts; `scanner.scan_transaction` returns them as `ReceivedOutput`s indistinguishable from real deposits.
3. Feed the full scanned set into `SignableTransaction::new`: `needed_fee` grows per injected input; once aggregate weight exceeds `MAX_STANDARD_TX_WEIGHT`, construction returns `TooLargeTransaction`, which the processor escalates to `panic!` — the signing path halts exactly as `addLiquidityETH` reverted in the report.

  pub fn scan_transaction(&self, tx: &Transaction) -> Vec<ReceivedOutput> {
    let mut res = Vec::new();
    for (vout, output) in tx.output.iter().enumerate() {
      // If the vout index exceeds 2**32, stop scanning outputs
      let Ok(vout) = u32::try_from(vout) else { break };

      if let Some(offset) = self.scripts.get(&output.script_pubkey) {
        res.push(ReceivedOutput {
          offset: *offset,
          output: output.clone(),
          outpoint: OutPoint::new(tx.compute_txid(), vout),
        });
      }
    }
    res
  }

// Always construct the full scanner in order to ensure there's no collisions
fn scanner(
  key: ProjectivePoint,
) -> (Scanner, HashMap<OutputType, Scalar>, HashMap<Vec<u8>, OutputType>) {
  let mut scanner = Scanner::new(key).unwrap();
  let mut offsets = HashMap::from([(OutputType::External, Scalar::ZERO)]);

  let zero = Scalar::ZERO.to_repr();
  let zero_ref: &[u8] = zero.as_ref();
  let mut kinds = HashMap::from([(zero_ref.to_vec(), OutputType::External)]);

  let mut register = |kind, offset| {
    let offset = scanner.register_offset(offset).expect("offset collision");
    offsets.insert(kind, offset);

    let offset = offset.to_repr();
    let offset_ref: &[u8] = offset.as_ref();
    kinds.insert(offset_ref.to_vec(), kind);
  };

  register(
    OutputType::Branch,
    *BRANCH_OFFSET.get_or_init(|| Secp256k1::hash_to_F(KEY_DST, b"branch")),
  );
  register(
    OutputType::Change,
    *CHANGE_OFFSET.get_or_init(|| Secp256k1::hash_to_F(KEY_DST, b"change")),
  );
  register(
    OutputType::Forwarded,
    *FORWARD_OFFSET.get_or_init(|| Secp256k1::hash_to_F(KEY_DST, b"forward")),
  );

  (scanner, offsets, kinds)
}
