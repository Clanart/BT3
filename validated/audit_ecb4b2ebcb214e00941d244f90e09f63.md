### Title
Divide-by-zero panic in KIP-71 base fee calculation via unchecked `kip71.gastarget` governance vote - (File: `params/kip71_config.go`)

### Summary
`NextMagmaBlockBaseFee` in `params/kip71_config.go` divides by `gasTarget` without checking it for zero, while the governance parameter `Kip71GasTarget` that feeds this value has no format validation preventing a zero value.

### Finding Description
`NextMagmaBlockBaseFee` computes the fluctuation of the KIP-71 base fee using `gasTarget := kc.GasTarget` and, in both the "gas used above target" and "gas used below target" branches, divides by it directly: [1](#0-0) [2](#0-1) 

Unlike `BaseFeeDenominator`, which has an explicit zero-fallback guard (`if kc.BaseFeeDenominator == 0 { ... set to 64 ... }`), `GasTarget` has no such guard: [3](#0-2) 

The governance parameter definition for `Kip71GasTarget` uses `noopFormatChecker`, meaning any `uint64` value including `0` is accepted, in contrast to `Kip71BaseFeeDenominator`, which explicitly rejects zero (`v != 0`): [4](#0-3) 

The header-vote consistency checker (`checkConsistency`) also performs no additional validation for `gov.Kip71GasTarget`; it is bucketed with parameters that "pass as long as it passes the format checks in `NewVoteData()`", which is the no-op checker above: [5](#0-4) 

Consequently, a governance vote setting `kip71.gastarget = 0` will be accepted by both the format checker and the consistency checker. Once this value is adopted into `ParamSet.GasTarget` and propagated via `ToKip71Config()`: [6](#0-5) 

any subsequent call to `NextMagmaBlockBaseFee` with `parentGasUsed != gasTarget` (i.e., essentially any block with nonzero gas usage, since `gasTarget == 0` guarantees `parentGasUsed > gasTarget` unless the parent block used exactly zero gas) enters the "gas used above target" branch and executes `y := x.Div(x, new(big.Int).SetUint64(gasTarget))` with a zero divisor. Go's `big.Int.Div` panics with "division by zero" in this case, since the fast-path shortcuts (`parentBaseFee == upperBoundBaseFee`) will not always apply.

This function is on the critical block-processing path — it is invoked both when the block validator verifies a header's `BaseFee` (`VerifyMagmaHeader`) and when the gas price oracle computes `nextBaseFee` for `eth_feeHistory` (`node/cn/gasprice/feehistory.go`): [7](#0-6) [8](#0-7) 

### Impact Explanation
A panic in `NextMagmaBlockBaseFee` reached from block header verification or fee-history/RPC processing would crash the node process (unless caught by a deferred recover somewhere higher up the call stack, which was not confirmed to exist for this specific path). Because this parameter, once accepted by governance, takes effect network-wide and is applied identically by every honest node evaluating the same header/parent state, all nodes computing the base fee for the affected block would panic simultaneously, resulting in a chain-wide denial of service / halt condition — one of the explicitly in-scope impacts (state divergence/chain halt via acceptance/processing of an invalid parameter state).

### Likelihood Explanation
Reaching this bug requires a successful governance vote to set `kip71.gastarget` to `0`. In `GovernanceMode: "single"`, only the designated governing node can cast an effective vote; in ballot mode, sufficient validator votes are required. This is not reachable directly from an arbitrary unprivileged transaction, but "governance parameters" is explicitly listed as an in-scope reachable path in the analog rules. Given the complete absence of a format check (`noopFormatChecker`) for `Kip71GasTarget` — in clear contrast to the explicit `v != 0` check that exists for the structurally similar `Kip71BaseFeeDenominator` parameter — this looks like a genuine oversight rather than an intentional design choice, making it plausible that a single flawed or malicious governance proposal (from a compromised or malicious governing node) could trigger a network-wide crash.

### Recommendation
Add a zero-value guard for `GasTarget` analogous to the existing `BaseFeeDenominator` guard in `NextMagmaBlockBaseFee` (e.g., treat `0` as invalid/fallback to a safe default), and/or add a `FormatChecker` for `Kip71GasTarget` in `kaiax/gov/param.go` that rejects `0`, consistent with `Kip71BaseFeeDenominator`.

### Proof of Concept
1. Governance vote submitted (as governing node in single mode) to set `kip71.gastarget` to `0`. This passes `NewVoteData` (canonicalizer accepts any `uint64`; `noopFormatChecker` always returns true) and `checkConsistency` (no special-case check for `Kip71GasTarget`).
2. Once the vote is finalized and reflected in `ParamSet.GasTarget = 0`, the next block header (or any block with `GasUsed > 0`) triggers, on every node:
   - Block validation: `VerifyMagmaHeader` → `NextMagmaBlockBaseFee(parentNumber, parentBaseFee, parentGasUsed)` with `parentGasUsed > 0 = gasTarget`.
   - Inside `NextMagmaBlockBaseFee`, code enters the `parentGasUsed > gasTarget` branch and executes `y := x.Div(x, new(big.Int).SetUint64(gasTarget))` with `gasTarget = 0`.
3. `big.Int.Div` panics on division by zero, crashing every node that evaluates this header — a synchronized network-wide denial of service.

func (kc *KIP71Config) VerifyMagmaHeader(headerBaseFee *big.Int, parentHeaderNumber *big.Int, parentHeaderBaseFee *big.Int, parentHeaderGasUsed uint64) error {
	if headerBaseFee == nil {
		return fmt.Errorf("header is missing baseFee")
	}
	// Verify the baseFee is correct based on the parent header.
	expectedBaseFee := kc.NextMagmaBlockBaseFee(parentHeaderNumber, parentHeaderBaseFee, parentHeaderGasUsed)
	if headerBaseFee.Cmp(expectedBaseFee) != 0 {
		return fmt.Errorf("invalid baseFee: have %s, want %s, parentBaseFee %s, parentGasUsed %d",
			headerBaseFee, expectedBaseFee, parentHeaderBaseFee, parentHeaderGasUsed)
	}
	return nil
}
