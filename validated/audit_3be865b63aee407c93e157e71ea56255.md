### Title
PedPoP DKG accepts the identity point as an encryption key, making all secret shares sent to that participant publicly decryptable - (File: crypto/dkg/pedpop/src/encryption.rs)

### Summary
`EncryptionKeyMessage::read` accepts any canonical point as `enc_key` with no check that it is non-identity, and `Decryption::register` stores it verbatim. When a peer registers the identity point as their encryption key, the ECDH in `encrypt` produces `key * identity = identity`, a publicly known shared secret. The ChaCha20 keystream derived from it is computable by any observer, so every `EncryptedMessage` addressed to that participant — which carries FROST/PedPoP secret shares — decrypts for everyone. This is a direct analog of CVE-2025-45767's "weak key accepted by the decryption/encryption path" bug class: an untrusted key of zero cryptographic strength is accepted where a contributory/non-trivial public key is required.

### Finding Description
`EncryptionKeyMessage::read` deserializes `enc_key` with only `C::read_G`, which checks canonical encoding but not non-identity [1](#0-0) [2](#0-1) . `Decryption::register` inserts it without any validity check [3](#0-2) . `Encryption::encrypt` then uses it as the ECDH public key: `ecdh(private, public) = public * private` [4](#0-3) , called with `to = self.decryption.enc_keys[&participant]` [5](#0-4) , and the resulting point feeds `cipher` as `shared_key` [6](#0-5) . With `to = identity`, the shared point is the identity for every message regardless of the ephemeral scalar, so `transcript.challenge(b"key")` is a deterministic, publicly computable ChaCha20 key (fixed IV `"DKG IV v0.2\0"`) [7](#0-6) . The per-message Schnorr PoP proves only knowledge of the ephemeral key's discrete log — it does not bind the recipient's `enc_key` — so the attacker's ciphertext passes all checks in `verify_r1`/`decrypt` [8](#0-7) . No PoP exists on `enc_key` at all: `EncryptionKeyMessage` is just `{ msg, enc_key }`.

### Impact Explanation
Any participant who registers `enc_key = identity` causes every honest participant to encrypt their PedPoP secret share for that participant under a public key. The share bytes (a scalar of the victim dealer's polynomial evaluated at the attacker's index) are recoverable by anyone observing the wire. Combined with the attacker's own legitimately-received shares and public commitments, recovery of `t` shares of a dealer polynomial reconstructs that dealer's contribution; more importantly, each share sent to the malicious participant leaks the honest dealer's evaluation at the attacker's index, and shares are what `ThresholdKeys`/FROST signing ultimately relies on — this is key share material leakage reachable purely from bytes fed to `EncryptionKeyMessage::read`.

### Likelihood Explanation
A DKG participant submits a commitment message containing an identity `enc_key` (32 zero-ish bytes for the curve's canonical identity encoding). No honest participant rejects it because no identity check exists anywhere in `register`, `encrypt`, `verify_r1`, or `AdditionalBlameMachine::new` [9](#0-8) . The resulting shares remain valid (the attacker can still decrypt honestly and produce valid `calculate_share` output), so the protocol completes while the attacker-indexed evaluations are public.

### Recommendation
Reject identity (and ideally any non-prime-order/torsion-adjacent point where applicable) in `Decryption::register` or in `EncryptionKeyMessage::read`, e.g., `if bool::from(msg.enc_key.is_identity()) { Err(...) }`. Optionally require a Schnorr PoP on `enc_key` bound to the participant and context so the key is provably known/non-trivial.

fn cipher<C: Ciphersuite>(context: [u8; 32], ecdh: &Zeroizing<C::G>) -> ChaCha20 {
  // Ideally, we'd box this transcript with ZAlloc, yet that's only possible on nightly
  // TODO: https://github.com/serai-dex/serai/issues/151
  let mut transcript = RecommendedTranscript::new(b"DKG Encryption v0.2");
  transcript.append_message(b"context", context);

  transcript.domain_separate(b"encryption_key");

  let mut ecdh = ecdh.to_bytes();
  transcript.append_message(b"shared_key", ecdh.as_ref());
  ecdh.as_mut().zeroize();

  let zeroize = |buf: &mut [u8]| buf.zeroize();

  let mut key = Cc20Key::default();
  let mut challenge = transcript.challenge(b"key");
  key.copy_from_slice(&challenge[.. 32]);
  zeroize(challenge.as_mut());

  // Since the key is single-use, it doesn't matter what we use for the IV
  // The issue is key + IV reuse. If we never reuse the key, we can't have the opportunity to
  // reuse a nonce
  // Use a static IV in acknowledgement of this
  let mut iv = Cc20Iv::default();
  // The \0 is to satisfy the length requirement (12), not to be null terminated
  iv.copy_from_slice(b"DKG IV v0.2\0");

  // ChaCha20 has the same commentary as the transcript regarding ZAlloc
  // TODO: https://github.com/serai-dex/serai/issues/151
  let res = ChaCha20::new(&key, &iv);
  zeroize(key.as_mut());
  res
}

  fn read_G<R: Read>(reader: &mut R) -> io::Result<Self::G> {
    let mut encoding = <Self::G as GroupEncoding>::Repr::default();
    reader.read_exact(encoding.as_mut())?;
