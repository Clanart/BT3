### Title
Front-running reward harvest via instant, non-time-weighted `BaseRewardPool` distribution allows theft of accrued yield - (File: `rewards/BaseRewardPool.sol`)

### Summary
`BaseRewardPool` distributes newly harvested reward tokens (WOM, bonus tokens, MGP) to stakers by instantly bumping `rewardPerTokenStored` in proportion to the *current* `totalStaked()` at the moment `queueNewRewards`/`donateRewards` is called, rather than accruing rewards continuously over time as they are earned. Because `harvest()` on `WombatStaking`/`WombatPoolHelper` is permissionlessly callable by any wallet, and depositing/withdrawing into `MasterMagpie` has no cooldown or time-weighting, an ordinary user can front-run a pending harvest by depositing a large stake immediately before it executes, then withdraw immediately after, capturing a disproportionate share of rewards that accrued to long-term stakers over the preceding harvest interval.

### Finding Description
`BaseRewardPool._provisionReward` updates the global `rewardPerTokenStored` all at once when new rewards arrive: [1](#0-0) 

This is the same class of flaw as the referenced report: reward accounting that lumps a period's worth of rewards into a single, discrete update based on a stake snapshot taken at distribution time, rather than continuously vesting rewards over the time they were actually earned by each staker. In the original report, the discrete update was caused by an admin freeze; here it is caused by the protocol's own reward design—`queueNewRewards`/`donateRewards` push all newly harvested rewards into `rewardPerTokenStored` in one step, weighted only by whoever is staked *at that instant*: [2](#0-1) [3](#0-2) 

The harvest that triggers this distribution is unprivileged and callable by anyone: [4](#0-3) [5](#0-4) 

which internally calls `_toMasterWomAndSendReward` → `_sendRewards` → `IBaseRewardPool(_rewarder).queueNewRewards(...)`: [6](#0-5) [7](#0-6) 

Deposit/withdraw into `MasterMagpie` (via `depositFor`/`withdrawFor` called from `WombatPoolHelper`) has no minimum holding period, no vesting, and no penalty for immediate withdrawal: [8](#0-7) [9](#0-8) 

An attacker can therefore:
1. Monitor the mempool/Wombat exchange for accrued, unharvested WOM rewards for a given LP pool (visible off-chain or by simulating `harvest()`).
2. Front-run the pending `harvest()` call (or call it themselves right after depositing) by depositing a large LP amount via `WombatPoolHelperV2.deposit`/`depositLP`, which calls `MasterMagpie.depositFor`.
3. The harvest fires, and `_provisionReward` distributes the whole accrued reward batch proportional to `totalStaked()`, which now includes the attacker's large just-added stake.
4. The attacker immediately calls `withdraw`, which harvests the base rewarder (`_harvestBaseRewarder`/`getReward`) and returns their principal, capturing a share of rewards disproportionate to the time they were actually staked.

This is functionally the same underlying class as the External Report: value that should accrue only to stakers who were exposed to risk/time is instead captured near-instantly by an attacker who briefly parks capital right before a lump-sum reward release event.

### Impact Explanation
This allows theft of yield that rightfully belongs to long-term LP stakers. Depending on the size of the harvested reward batch relative to existing `totalStaked()`, and the attacker's available capital, this could redirect the majority of a harvest's WOM/bonus-token rewards to the attacker, permanently diluting rewards for honest long-term stakers (theft of unclaimed yield).

### Likelihood Explanation
`harvest()` is a fully permissionless, unprivileged-wallet-reachable function, and deposit/withdraw into `MasterMagpie` via `WombatPoolHelper` have no cooldown, lockup, or anti-flash-loan protection. Any wallet with enough capital (including flash-loaned LP/deposit tokens, if the deposit token is flash-loanable) can execute this in a single transaction or across two adjacent transactions, without needing any privileged role. Reward harvest events are periodic (triggered by any user or automated keeper), making the opportunity recurring and predictable.

### Recommendation
Convert `BaseRewardPool` to a time-weighted/continuous accrual model (e.g., `rewardRate` + `lastUpdateTime`, as already used in `WomUp.sol`) instead of instantaneous lump-sum distribution based on `totalStaked()` at harvest time, so that rewards accrue proportionally to the time and amount actually staked. Alternatively, introduce a minimum staking duration or a harvest-triggered snapshot mechanism that excludes stakes deposited very close to (or after) reward accrual, and/or apply a deposit/withdraw cooldown to prevent same-block or near-instant stake-then-withdraw sandwiching of reward distributions.

### Proof of Concept
1. Wombat exchange accrues, say, 1,000 WOM in pending rewards for a pool with `totalStaked() = 1,000` (existing long-term stakers).
2. Attacker observes the pending harvest (or triggers it themselves) and, in the preceding transaction, calls `WombatPoolHelperV2.deposit`/`depositLP` to deposit 9,000 LP tokens, growing `totalStaked()` to 10,000.
3. `WombatStaking.harvest(lpToken)` is called (permissionless): `_toMasterWomAndSendReward` → `_sendRewards` → `BaseRewardPool.queueNewRewards(1000, WOM)` → `_provisionReward` sets `rewardPerTokenStored += 1000 * 1e18 / 10000` — the attacker's 9,000 share now claims 90% of the 1,000 WOM (900 WOM) instead of the honest stakers' fair share.
4. Attacker immediately calls `WombatPoolHelperV2.withdraw` to unstake the 9,000 LP and simultaneously harvest their ~900 WOM reward via `_harvestBaseRewarder`/`getReward` in `MasterMagpie._harvestAndUnstake`.
5. Attacker walks away with ~900 WOM captured from a single harvest event with only momentary capital exposure, while original 1,000-LP stakers who bore the full time/risk only receive ~100 WOM. [1](#0-0) [5](#0-4) [10](#0-9)

    function _provisionReward(uint256 _amountReward, address _rewardToken) internal {
        IERC20(_rewardToken).safeTransferFrom(
            msg.sender,
            address(this),
            _amountReward
        );
        Reward storage rewardInfo = rewards[_rewardToken];
        rewardInfo.historicalRewards =
            rewardInfo.historicalRewards +
            _amountReward;
        if (this.totalStaked() == 0) {
            rewardInfo.queuedRewards += _amountReward;
        } else {
            if (rewardInfo.queuedRewards > 0) {
                _amountReward += rewardInfo.queuedRewards;
                rewardInfo.queuedRewards = 0;
            }
            rewardInfo.rewardPerTokenStored =
                rewardInfo.rewardPerTokenStored +
                (_amountReward * 10**stakingDecimals()) /
                this.totalStaked();
        }

    /// @notice Send rewards to the rewarders
    /// @param _rewardToken the address of the reward token to send
    /// @param _rewarder the rewarder that will get the rewards
    /// @param _amount the initial amount of rewards after harvest

    function _sendRewards(
        address _lpToken,
        address _rewardToken,
        address _rewarder,
        uint256 _amount
    ) internal {
        if (_amount == 0) return;
        uint256 originalRewardAmount = _amount;

        if (!isPoolFeeFree[_lpToken]) {
            for (uint256 i = 0; i < feeInfos.length; i++) {
                Fees storage feeInfo = feeInfos[i];

                if (feeInfo.isActive) {
                    address rewardToken = _rewardToken;
                    uint256 feeAmount = (originalRewardAmount * feeInfo.value) / DENOMINATOR;
                    _amount -= feeAmount;
                    uint256 feeTosend = feeAmount;

                    if (feeInfo.isMWOM && rewardToken == wom) {
                        if (smartWomConverter != address(0)) {
                            IERC20(wom).safeApprove(smartWomConverter, feeAmount);
                            uint256 beforeBalnce = IMWom(mWom).balanceOf(address(this));
                            IConverter(smartWomConverter).smartConvert(feeAmount, 0);
                            rewardToken = mWom;
                            feeTosend = IMWom(mWom).balanceOf(address(this)) - beforeBalnce;
                        } else {
                            IERC20(wom).safeApprove(mWom, feeAmount);
                            uint256 beforeBalnce = IMWom(mWom).balanceOf(address(this));
                            IMWom(mWom).deposit(feeAmount);
                            rewardToken = mWom;
                            feeTosend = IMWom(mWom).balanceOf(address(this)) - beforeBalnce;
                        }
                    }

                    if (!feeInfo.isAddress) {
                        IERC20(rewardToken).safeApprove(feeInfo.to, 0);
                        IERC20(rewardToken).safeApprove(feeInfo.to, feeTosend);
                        IBaseRewardPool(feeInfo.to).queueNewRewards(feeTosend, rewardToken);
                    } else {
                        IERC20(rewardToken).safeTransfer(feeInfo.to, feeTosend);
                        emit RewardPaidTo(feeInfo.to, rewardToken, feeTosend);
                    }
                }
            }
        }

        IERC20(_rewardToken).safeApprove(_rewarder, 0);
        IERC20(_rewardToken).safeApprove(_rewarder, _amount);
        IBaseRewardPool(_rewarder).queueNewRewards(_amount, _rewardToken);
    }

    function _harvestAndUnstake(address _stakingToken, address _account, uint256 _amount, bool _isVlMgp) internal {
        updatePool(_stakingToken);

        UserInfo storage user = userInfo[_stakingToken][_account];

        if (!_isVlMgp && user.available < _amount)
            revert WithdrawAmountExceedsStaked();
        else if(user.amount < _amount && _isVlMgp)
            revert UnlockAmountExceedsLocked();
        
        _harvestMGP(_stakingToken, _account);
        _harvestBaseRewarder(_stakingToken, _account);

        user.amount = user.amount - _amount;
        
        if(!_isVlMgp)
            user.available = user.available - _amount;
        user.rewardDebt = (user.amount * tokenToPoolInfo[_stakingToken].accMGPPerShare) / 1e12;
    }
