Based on my investigation, I found a plausible analog: the gasless swap flow's price-check gap between mempool admission and actual block execution.

### Title
Gasless swap price check uses stale AMM state, allowing swap slippage/repay mismatch to cause proposer fund loss - (File: kaiax/gasless/impl/tx_pool.go)

### Summary
The gasless module validates that `AmountIn >= gsr.getAmountIn(minAmountOut)` only at mempool admission time using the current chain-head AMM reserves [1](#0-0) . This check is a one-time admission filter, not re-verified atomically against the actual reserves at the moment the bundle (`LendTx` + `ApproveTx` + `SwapTx`) is executed inside a block. The block-building flow prepends a `LendTx` that unconditionally transfers KAIA value to the user before the `SwapTx` runs [2](#0-1) , and the README confirms the gas fee is fronted by the proposer via `LendTx`, to be repaid by the user's swap [3](#0-2) .

### Finding Description
This mirrors the Platypus root cause: a price/ratio value is computed and checked against one state (mempool's view of AMM reserves), but the actual value transfer (LendTx to the user) happens unconditionally and irreversibly, while the compensating leg (`SwapForGas`, which is expected to repay `AmountRepay` to the proposer) is evaluated against reserves that can have moved by execution time (through other pool activity or MEV/front-running within the same or intervening blocks) [4](#0-3) . Because `LendTx` and `SwapTx` are separate, independently-executed transactions bundled together (not a single atomic call), a reverted or under-delivering `SwapTx` does not claw back the value already sent by `LendTx`. The `checkBalanceForSwap` price/amount check is only performed once at tx-pool admission [5](#0-4) , not re-validated at inclusion time immediately before block assembly, creating a time-of-check/time-of-use (TOCTOU) gap analogous to Platypus's failure to account for price divergence between two states during an exchange.

### Impact Explanation
If the AMM price/reserves diverge between mempool admission and actual bundle execution (e.g., due to prior transactions within the same block shifting the pool, or a delay between validation and inclusion), the proposer's `LendTx` payment is irrevocably sent to the user, but the subsequent `SwapTx` may yield less than expected or revert, meaning the proposer does not recover the lent gas fee. This is a direct unauthorized value loss vector for block proposers (fee-delegation counterparty), matching the "Medium" severity/"unauthorized value movement" criteria.

### Likelihood Explanation
Reachable by any unprivileged gasless-swap sender: a user (or colluding party) can craft/observe transactions that shift the DEX pool price between the sender's tx-pool submission and the proposer's block-building/execution step, or intentionally construct swap parameters near the margin of `minAmountOut`/`amountRepay` so that legitimate price movement (which the module does not re-check atomically) causes the `SwapTx` to under-deliver relative to the `LendTx` already paid out. This requires no special privilege beyond submitting ordinary transactions, but does require some timing/market conditions to be exploitable reliably.

### Recommendation
Re-validate the AMM-derived `getAmountIn`/expected swap output against the state immediately preceding `SwapTx` execution within the same block-building pass (not only at admission), and/or make `LendTx` and `SwapTx` execution atomic (e.g., revert `LendTx`'s effect if `SwapTx` fails or under-delivers), so that a stale price snapshot cannot lead to an irreversible one-sided payment by the proposer.

### Proof of Concept
Not independently reproducible from the indexed code alone — the exact conditions require crafting a sequence of DEX trades that move `UniswapV2` pool reserves between the moment `checkBalanceForSwap` is evaluated in the tx pool (using `routerContract.GetAmountIn`, see [1](#0-0) ) and the moment the bundled `LendTx`+`SwapTx` sequence is actually executed in a block, then observing that `SwapForGas` under-delivers relative to `AmountRepay` while `LendTx` has already unconditionally paid the user. This would need to be verified against the full `GaslessSwapRouter.sol` source (not available in the indexed context, only Go bindings/bytecode were found) to confirm whether `swapForGas` reverts fully on slippage failure or partially settles — this is a gap in my analysis that a Devin session with full repository access could resolve by examining `contracts/kip247/GaslessSwapRouter.sol` (not present in the index) directly.

func (g *GaslessModule) ExtractTxBundles(txs []*types.Transaction, prevBundles []*builder.Bundle) []*builder.Bundle {
	// there are only at most two gasless transactions in pending for a sender
	bundles := []*builder.Bundle{}
	approveTxs := map[common.Address]*types.Transaction{}
	targetTxHash := common.Hash{}
	for _, tx := range txs {
		addr, err := types.Sender(g.signer, tx)
		if err != nil {
			continue
		}
		if g.IsApproveTx(tx) {
			approveTxs[addr] = tx
		} else if g.IsSwapTx(tx) && g.IsExecutable(approveTxs[addr], tx) {
			bundleTxs := builder.NewTxOrGenList(g.GetLendTxGenerator(approveTxs[addr], tx))
			if approveTxs[addr] != nil {
				bundleTxs = append(bundleTxs, builder.NewTxOrGenFromTx(approveTxs[addr]))
			}
			bundleTxs = append(bundleTxs, builder.NewTxOrGenFromTx(tx))

			b := builder.NewBundle(
				bundleTxs,
				targetTxHash,
				false,
			)

			targetTxHash = tx.Hash()

			isConflict := false
			for _, prev := range append(prevBundles, bundles...) {
				if prev.IsConflict(b) {
					isConflict = true
					break
				}
			}
			if isConflict {
				// Gasless transactions will just fail even if they aren't bundled.
				continue
			}
			bundles = append(bundles, b)
		} else {
			targetTxHash = tx.Hash()
		}
	}
	return bundles
}

func repayAmount(approveTxOrNil, swapTx *types.Transaction) *big.Int {
	// R1 = LendTx.Fee() = SwapTx.GasPrice() * TxGas
	r1 := new(big.Int).Mul(swapTx.GasPrice(), new(big.Int).SetUint64(params.TxGas))

	// RepayAmount = R1 + R2 + R3
	return new(big.Int).Add(r1, lendAmount(approveTxOrNil, swapTx))
}
