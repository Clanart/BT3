### Title
Vote-capacity check is permanently bypassed for `delegatedPool`, allowing unbacked votes to be cast - ([File: wombat/WombatBribeManager.sol])

### Summary
In `vote()`, when `msg.sender == delegatedPool`, the block that updates `userTotalVotedInVlmgp[msg.sender]` and `totalVlMgpInVote` is skipped entirely. Since the subsequent invariant check (`userTotalVotedInVlmgp[msg.sender] > getUserVotable(msg.sender)`) reads the very same mapping that was just skipped, `userTotalVotedInVlmgp[delegatedPool]` never increases above `0`, so the check can never revert for `delegatedPool` regardless of how many votes it casts on behalf of its depositors.

### Finding Description
`vote()` at [1](#0-0)  processes per-pool deltas and always increments `pool.totalVoteInVlmgp` (line 197/201) and calls `IBribeRewardPool(pool.rewarder).stakeFor` regardless of caller. Then:

```solidity
if (msg.sender != delegatedPool) {
    ... update userTotalVotedInVlmgp[msg.sender] and totalVlMgpInVote ...
}
if (userTotalVotedInVlmgp[msg.sender] > getUserVotable(msg.sender))
    revert NotEnoughVote();
``` [2](#0-1) 

Because the update is guarded by `msg.sender != delegatedPool`, whenever `delegatedPool` itself calls `vote()`, `userTotalVotedInVlmgp[delegatedPool]` is never written and stays `0` forever (barring any other writer). The final check therefore evaluates `0 > getUserVotable(delegatedPool)`, which is always `false`. This is not merely "checked once at the aggregate level" as one might assume by design intent — it is never checked at all for calls coming from `delegatedPool`. There is no other code path in this contract that enforces that the sum of votes routed through `delegatedPool` stays within `getUserVotable(delegatedPool)` (i.e., `IVLMGP(vlMGP).getUserTotalLocked(delegatedPool)`).

Consequently, if `DelegateVoteRewardPool` (the `delegatedPool` contract) allows any unprivileged user to deposit/stake and then internally calls `WombatBribeManager.vote()` as `msg.sender == delegatedPool` without itself independently enforcing that its aggregate outgoing vote never exceeds its own real vlMGP backing, depositors can drive `pool.totalVoteInVlmgp` for arbitrary pools upward with no ceiling tied to actual locked MGP. This also desynchronizes `totalVlMgpInVote` (never incremented for delegatedPool votes) from the sum of all `pool.totalVoteInVlmgp` entries, which is used in `castVotes()` to compute `targetVote = targetVoteInLMGP * totalVotes() / totalVlMgpInVote` [3](#0-2) , causing pools voted through `delegatedPool` to receive disproportionately more real Wombat votes than their true backing warrants.

I was unable to inspect `DelegateVoteRewardPool.sol` in this session (not indexed/found in this repo scope), so I cannot confirm whether that contract independently re-implements the missing bound (e.g., checking its callers' stakes against its own `getUserVotable(delegatedPool)` before calling `vote()`). Based solely on `WombatBribeManager.sol`, the bound is structurally absent for the delegatedPool code path — the skip condition removes the only enforcement mechanism that exists in this contract, and no substitute check is present here.

### Impact Explanation
If `DelegateVoteRewardPool` does not itself cap total delegated votes to its own real vlMGP lock, unprivileged depositors staking through it can cause the protocol to cast Wombat governance votes for LP pools that are not actually backed by locked MGP, i.e., aggregate votes can exceed `IVLMGP(vlMGP).totalLocked()`. This is a governance-voting-result manipulation impact (accepted impact class) and can also mis-distribute bribe rewards proportional to inflated `pool.totalVoteInVlmgp`, causing rightful voters to receive diluted bribe yield — a form of yield theft/dilution.

### Likelihood Explanation
This requires `delegatedPool` to be set (an owner action, out of scope as "malicious admin," but the precondition explicitly states it is a "live DelegateVoteRewardPool contract" — a legitimate, expected protocol configuration, not an admin attack). Given that configuration, any unprivileged user can trigger the issue simply by staking into `DelegateVoteRewardPool`'s public entrypoint, with no special capital requirements beyond the deposit itself, and the bug is deterministic and repeatable on every vote cast. However, since the actual exploitability hinges on whether `DelegateVoteRewardPool` (a contract not available for review in this session) has its own equivalent bound, I cannot confirm with certainty that the missing check in `WombatBribeManager` is not compensated elsewhere.

### Recommendation
Do not skip the mapping update for `delegatedPool`; instead, track `userTotalVotedInVlmgp[delegatedPool]` normally, or replace the bypass with an explicit accounting mechanism where `DelegateVoteRewardPool` reports/enforces the total real vlMGP backing of the depositors it aggregates before calling `vote()`. At minimum, ensure `totalVlMgpInVote` is always incremented/decremented consistently regardless of caller, and that the `NotEnoughVote` check is enforced against the true aggregate backing (e.g., `IVLMGP(vlMGP).getUserTotalLocked(delegatedPool)`) rather than a mapping value that is permanently frozen at zero for that address.

### Proof of Concept
Foundry test plan:
1. Deploy `WombatBribeManager`, `VLMGP` mock, and `DelegateVoteRewardPool` (or a minimal mock implementing its external stake entrypoint that calls `WombatBribeManager.vote()` as itself).
2. Set `delegatedPool` via `setDelegatedPool` to this contract; add an active pool via `addPool`.
3. Ensure `IVLMGP(vlMGP).getUserTotalLocked(delegatedPool) == 0` (delegatedPool itself has no locked MGP).
4. Have `delegatedPool` call `vote()` with a large positive delta on behalf of a simulated depositor.
5. Assert the call does **not** revert with `NotEnoughVote` despite `getUserVotable(delegatedPool) == 0`, and that `poolInfos[lp].totalVoteInVlmgp` increased by the delta while `totalVlMgpInVote` remains unchanged — proving `pool.totalVoteInVlmgp` summed across pools now exceeds `totalVlMgpInVote`, and both exceed any real vlMGP backing (`IVLMGP(vlMGP).totalLocked()`), confirming the invariant violation.

    function vote(address[] calldata _lps, int256[] calldata _deltas) override public {
        if (_lps.length != _deltas.length)
            revert LengthMismatch();

        uint256 length = _lps.length;
        int256 totalUserVote;

        for (uint256 i; i < length; i++) {
            Pool storage pool = poolInfos[_lps[i]];
            if (!pool.isActive)
                revert PoolNotActive();
            int256 delta = _deltas[i];
            totalUserVote += delta;
            if (delta != 0) {
                if (delta > 0) {
                    pool.totalVoteInVlmgp += uint256(delta);
                    userVotedForPoolInVlmgp[msg.sender][pool.poolAddress] += uint256(delta);
                    IBribeRewardPool(pool.rewarder).stakeFor(msg.sender, uint256(delta));
                } else {
                    pool.totalVoteInVlmgp -= uint256(-delta);
                    userVotedForPoolInVlmgp[msg.sender][pool.poolAddress] -= uint256(-delta);
                    IBribeRewardPool(pool.rewarder).withdrawFor(msg.sender, uint256(-delta), false);
                }
            }
        }

        if (msg.sender != delegatedPool) {
            if (totalUserVote > 0) {
                userTotalVotedInVlmgp[msg.sender] += uint256(totalUserVote);
                totalVlMgpInVote += uint256(totalUserVote);
            } else {
                userTotalVotedInVlmgp[msg.sender] -= uint256(-totalUserVote);
                totalVlMgpInVote -= uint256(-totalUserVote);
            }
        }

        if (userTotalVotedInVlmgp[msg.sender] > getUserVotable(msg.sender))
            revert NotEnoughVote();
    }
