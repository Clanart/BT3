### Title
SSRF in Data Layer mirror-fetch: unvalidated on-chain mirror URLs trigger server-side HTTP GET to arbitrary hosts - (File: chia/data_layer/download_data.py)

### Summary
Any wallet user can publish an on-chain "mirror" coin advertising arbitrary URLs for a Data Layer store via `dl_new_mirror`/`create_new_mirror`. Any peer that subscribes to that store id will pull the mirror URL list from the wallet and have its Data Layer service issue raw HTTP GET requests to those URLs, with no hostname/IP validation, mirroring the Sydent SSRF bug class (server makes outbound HTTP requests to attacker-chosen targets with no blacklisting of internal addresses).

### Finding Description
`DataLayerWallet.create_new_mirror` lets any wallet holder create a mirror coin whose memos encode a list of arbitrary URL strings tied to a `launcher_id` (store id), with no validation of the URL contents: [1](#0-0) 

These mirrors are retrievable by any node tracking that singleton via `dl_get_mirrors`, and `DataLayer.update_subscriptions_from_wallet` copies the raw URL strings (only `rstrip("/")` is applied — no scheme/host/IP checks) into the local subscription's server list: [2](#0-1) 

When a peer subscribes to (or syncs) that store, `DataLayer.fetch_and_validate` picks a server from that list and calls `insert_from_delta_file`, which calls `download_file`, which — when no plugin `downloader` is configured — calls `http_download`, issuing an `aiohttp` GET directly against `server_info.url + "/" + filename` with no validation that the host is not loopback, link-local, RFC1918, or other internal/metadata address: [3](#0-2) [4](#0-3) [5](#0-4) 

Tests confirm loopback/arbitrary-host mirror URLs are accepted verbatim with the only guard being a non-empty check: [6](#0-5)  and the RPC/service-layer only rejects an empty list, not disallowed hosts: [7](#0-6) .

This is the direct analog of GHSA-9jhm-8m8c-c3f4: a remote, unprivileged party supplies a URL that gets fetched by another party's server-side HTTP client with no IP/hostname allow/deny-listing, enabling internal network reconnaissance/port scanning from the fetching node's vantage point.

### Impact Explanation
An attacker publishing a mirror coin for a store id (or for a store that a victim already subscribes to) can point mirror URLs at internal-only hosts/ports (e.g., `http://127.0.0.1:<port>`, `http://169.254.169.254/...`, RFC1918 addresses) on the machine or network running the victim's Data Layer service. Because `http_download` performs a real GET and distinguishes connection errors from successful/HTTP-error responses (via `resp.raise_for_status()`, `ClientConnectorError` vs. other exceptions, and content-length/size logging), a remote attacker can perform internal port enumeration and probe for reachable internal HTTP services from any node that syncs the malicious store — the same "Medium" SSRF impact described in the advisory (no credential exfiltration or header control, but genuine SSRF/port-scanning capability). This is reachable purely via a normal `dl_new_mirror` wallet transaction and does not require any privileged or malicious-peer access — it's a standard Data Layer client feature abused by design gap.

### Likelihood Explanation
High likelihood of reachability: publishing a mirror is a documented, unauthenticated wallet operation available to anyone who can construct a spend to the mirror puzzle (`create_new_mirror`/`dl_new_mirror` RPC), and any node subscribing to (or already following) that store's DataLayer singleton will automatically attempt to fetch from all advertised mirror URLs during normal sync (`update_subscription`/`fetch_and_validate`), with no operator interaction required beyond subscribing to a public store id.

### Recommendation
Validate and restrict mirror URLs before they are stored/used for fetching: enforce an allowed scheme list (http/https only), resolve and reject requests to loopback, link-local (169.254.0.0/16 including cloud metadata IP), RFC1918 private ranges, and other non-routable/internal addresses (both at mirror-creation and, more importantly, immediately before each outbound request in `http_download`/`download_file`), and consider re-resolving DNS per connection attempt to avoid TOCTOU/DNS-rebinding bypasses of an allowlist.

### Proof of Concept
1. Attacker creates a Data Layer store or targets an existing store id that a victim tracks.
2. Attacker calls `dl_new_mirror` (via `chia data add_mirror` / `DataLayerRpcApi.add_mirror` or `DLNewMirror` wallet RPC) with `urls=["http://127.0.0.1:22", "http://169.254.169.254/latest/meta-data/"]`, as demonstrated feasible by the test helper accepting arbitrary loopback URLs: [6](#0-5) .
3. Victim's Data Layer node subscribes to / is already tracking the store id and periodically calls `update_subscriptions_from_wallet` then `fetch_and_validate`, which iterates `servers_info` and calls `insert_from_delta_file` → `download_file` → `http_download`, issuing `session.get(server_info.url + "/" + filename, ...)` directly to the attacker-chosen internal URL: [8](#0-7) .
4. By observing whether the fetch fails with `ClientConnectorError` (closed port) vs. proceeds to `resp.raise_for_status()`/content-length handling (open/listening port), the attacker infers the internal service's reachability/state on the victim's network — completing the SSRF/port-scan primitive.

async def download_file(
    data_store: DataStore,
    target_filename_path: Path,
    store_id: bytes32,
    root_hash: bytes32,
    generation: int,
    server_info: ServerInfo,
    proxy_url: str | None,
    downloader: PluginRemote | None,
    timeout: aiohttp.ClientTimeout,
    client_foldername: Path,
    timestamp: int,
    log: logging.Logger,
    grouped_by_store: bool,
    group_downloaded_files_by_store: bool,
    max_delta_file_size: int,
) -> bool:
    if target_filename_path.exists():
        return True
    filename = get_delta_filename(store_id, root_hash, generation, grouped_by_store)

    if downloader is None:
        # use http downloader - this raises on any error
        try:
            await http_download(
                target_filename_path, filename, proxy_url, server_info, timeout, log, max_delta_file_size
            )
        except (asyncio.TimeoutError, aiohttp.ClientError, MaxDeltaFileSizeExceededError):
            new_server_info = await data_store.server_misses_file(store_id, server_info, timestamp)
            log.info(
                f"Failed to download {filename} from {new_server_info.url}."
                f"Miss {new_server_info.num_consecutive_failures}."
            )
            log.info(f"Next attempt from {new_server_info.url} in {new_server_info.ignore_till - timestamp}s.")
            return False
        return True

async def http_download(
    target_filename_path: Path,
    filename: str,
    proxy_url: str | None,
    server_info: ServerInfo,
    timeout: aiohttp.ClientTimeout,
    log: logging.Logger,
    max_delta_file_size: int,
) -> None:
    """
    Download a file from a server using aiohttp.
    Raises exceptions on errors
    """
    async with aiohttp.ClientSession() as session:
        headers = {"accept-encoding": "gzip"}
        async with session.get(
            server_info.url + "/" + filename,
            headers=headers,
            timeout=timeout,
            proxy=proxy_url,
        ) as resp:
            resp.raise_for_status()
            size = int(resp.headers.get("content-length", 0))
            max_delta_file_size_bytes = max_delta_file_size * 1024 * 1024
            if size > max_delta_file_size_bytes:
                raise MaxDeltaFileSizeExceededError(f"Maximum delta file size exceeded: {max_delta_file_size} MiB.")
            log.debug(f"Downloading delta file {filename}. Size {size} bytes.")
            progress_byte = 0
