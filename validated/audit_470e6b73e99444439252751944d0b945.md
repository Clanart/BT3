### Title
Untrusted `offset`/`TxOut` in `ReceivedOutput::read` lets an attacker declare outputs spendable by no multisig, crediting unspendable funds - (File: `networks/bitcoin/src/wallet/mod.rs`)

### Summary
Analogous to the auction report — where a trusted setter installs an unvalidated dependency (`nft`) that later silently breaks the mint path — `ReceivedOutput::read` and `Output::read` accept attacker-controlled bytes declaring which scalar `offset` and which `script_pubkey` define an output, with no consistency check between them. The output is then credited as received funds, while `Output::key()` derives a "multisig key" (`script_key - G*offset`) that need not correspond to any real `ThresholdKeys`, so the deposited BTC can never be signed for.

### Finding Description
`ReceivedOutput::read` reads a free-form `Scalar` offset, a `TxOut`, and an `OutPoint` directly from the reader with no validation that the offset actually derives the `script_pubkey` from some known group key [1](#0-0) . `Output::read` wraps this plus an arbitrary `OutputType`, `presumed_origin`, and `data` [2](#0-1) .

When consumed, `Output::key()` reconstructs the purported owner key by subtracting `GENERATOR * offset` from the x-only key in the script [3](#0-2) . For `OutputType::External` outputs, `instruction_from_output` credits `output.balance()` into an `InInstructionWithBalance` without ever checking that `output.key()` matches an existing multisig [4](#0-3) . A `key()` check exists only in the `RotationStep::ForwardFromExisting` branch [5](#0-4) .

Later, `SignableTransaction::multisig` is the only place the offset/script binding is enforced: `p2tr_script_buf(offset.group_key()) != self.prevouts[i].script_pubkey` returns `None` [6](#0-5) , and `attempt_sign` turns that `None` into a panic [7](#0-6) . So the bad input sails through scanning/crediting and only fails — via panic — at spend time.

### Impact Explanation
A crafted serialized `Output`/`ReceivedOutput` pairing a real-looking `TxOut`/`OutPoint` with an `offset` that does not satisfy `p2tr_script_buf(base_key + G*offset) == script_pubkey` for any active multisig causes Serai to report the output as received: balance is computed from `output.value()` and converted into an InInstruction, minting the corresponding Serai-side asset. The underlying BTC is unspendable — no `ThresholdKeys` exists for `output.key()` — and signing attempts panic (`"used the wrong keys"`, `assert!(script.is_p2tr())`). This is funds reported received that are not spendable, plus an induced halt of the signing pipeline. Directly mirrors the report's "users pay, receive nothing" shape: deposits are honored while the BTC can never be recovered.

### Likelihood Explanation
Medium. Exploitation requires reaching a path where these bytes are deserialized and trusted (a `read` sink), not merely sending an on-chain transaction — `Scanner::scan_transaction` itself always produces consistent offset/script pairs [8](#0-7) . The code contains no defense: no post-read check that `output.key()` is a registered multisig key, and the only consistency check lives at signing time where it panics rather than rejects the input.

### Recommendation
After `Output::read`/`ReceivedOutput::read`, recompute the expected `script_pubkey` for the claimed `key() + G*offset` and reject mismatches; equivalently, require `output.key()` to equal a known multisig key before crediting an `External` output in `instruction_from_output`/`scanner_event_to_multisig_event`. Treat a failed `multisig()` as a rejectable `NetworkError` rather than `.expect("used the wrong keys")`.

### Proof of Concept
Conceptual:

```rust

// kind = External, output = ReceivedOutput { offset: malicious_offset,

// where p2tr(P) - G*malicious_offset != any registered multisig key.

// instr.balance = 1 BTC -> Serai mints against unspendable BTC
// Later: signable.multisig(&keys) -> None -> attempt_sign panics
```

```rust
fn instruction_from_output<N: Network>(
  output: &N::Output,
) -> (Option<ExternalAddress>, Option<InInstructionWithBalance>) {
  assert_eq!(output.kind(), OutputType::External);

  let presumed_origin = output.presumed_origin().map(|address| {
    ExternalAddress::new(
      address
        .try_into()
        .map_err(|_| ())
        .expect("presumed origin couldn't be converted to a Vec<u8>"),
    )
    .expect("presumed origin exceeded address limits")
  });

  let mut data = output.data();
  let max_data_len = usize::try_from(MAX_DATA_LEN).unwrap();
  if data.len() > max_data_len {
    error!(
      "data in output {} exceeded MAX_DATA_LEN ({MAX_DATA_LEN}): {}. skipping",
      hex::encode(output.id()),
      data.len(),
    );
    return (presumed_origin, None);
  }

  let shorthand = match Shorthand::decode(&mut data) {
    Ok(shorthand) => shorthand,
    Err(e) => {
      info!("data in output {} wasn't valid shorthand: {e:?}", hex::encode(output.id()));
      return (presumed_origin, None);
    }
  };
  let instruction = match RefundableInInstruction::try_from(shorthand) {
    Ok(instruction) => instruction,
    Err(e) => {
      info!(
        "shorthand in output {} wasn't convertible to a RefundableInInstruction: {e:?}",
        hex::encode(output.id())
      );
      return (presumed_origin, None);
    }
  };

  let mut balance = output.balance();
  // Deduct twice the cost to aggregate to prevent economic attacks by malicious miners against
  // other users
  balance.amount.0 -= 2 * N::COST_TO_AGGREGATE;

  (
    instruction.origin.or(presumed_origin),
    Some(InInstructionWithBalance { instruction: instruction.instruction, balance }),
  )
```

```rust
  pub fn multisig(self, keys: &ThresholdKeys<Secp256k1>) -> Option<TransactionMachine> {
    let mut sigs = vec![];
```
