### Title
Unhandled `IndexError`/`AssertionError` in CLVM canonical-encoding check causes mempool DoS - ([File: chia/full_node/mempool_manager.py])

### Summary
`is_clvm_canonical()` and its helper `is_atom_canonical()` in `chia/full_node/mempool_manager.py` parse a raw, attacker-supplied CLVM-serialized byte buffer (a spend's solution bytes, used to decide DEDUP eligibility) with no bounds checking on the crafted length prefix, and with a bare `assert` on the empty-buffer case. This mirrors the reported `images` npm bug class: unexpected/edge-case input values reach an `assert`/unchecked-index path instead of being validated, crashing the process instead of failing gracefully. [1](#0-0) 

### Finding Description
`is_clvm_canonical(clvm_buffer)` begins with a bare `assert clvm_buffer != b""` rather than returning `False` for malformed input: [2](#0-1) 

It then walks the buffer byte-by-byte, and for any atom byte it calls `is_atom_canonical(clvm_buffer, offset)`, which reads the length-prefix bytes and computes `atom_len` purely from attacker-controlled prefix bits, without ever checking that `offset + prefix_len` or the resulting `atom_len` stay within `len(clvm_buffer)`: [3](#0-2) 

Back in `is_clvm_canonical`, the returned `atom_len` is added directly to `offset` with no validation, and the loop continues reading `clvm_buffer[offset]` on the next iteration: [4](#0-3) 

A crafted length-prefix byte sequence that declares an atom length larger than the number of bytes actually remaining in the buffer causes `offset` to advance past `len(clvm_buffer)`. The subsequent `b = clvm_buffer[offset]` at the top of the loop then raises an uncaught `IndexError` instead of the function returning `False` as its contract (a boolean canonicality check) implies. This is functionally identical to the reported CVE: a size/length value taken directly from attacker input is used to index/compute without validating it against the actual buffer bounds, producing an unhandled runtime error (assert-class crash) instead of controlled rejection.

The context documentation confirms this function is exercised on spend/solution byte data to gate DEDUP-eligible mempool processing, i.e. it runs on attacker-supplied bytes originating from an ordinary submitted spend bundle, not from any privileged or already-fully-validated source: [5](#0-4) 

### Impact Explanation
If this parsing path is invoked on raw solution bytes during mempool admission (as its purpose — gating DEDUP eligibility — implies), a single unprivileged spend-bundle submitter can supply a solution whose serialized bytes contain a malformed/oversized length prefix. This throws an unhandled `IndexError` (or hits the bare `assert` on other malformed shapes) inside mempool-manager processing rather than a clean rejection (`Err`), which can abort/crash the processing task or worker handling that spend bundle — a spend-triggered transaction-processing halt / DoS, matching CWE-241/CWE-400 exactly as in the reported advisory.

### Likelihood Explanation
Reaching this requires only submitting a spend bundle with a coin spend whose `solution` bytes are attacker-crafted with an invalid/oversized CLVM atom length-prefix — something any wallet user, offer counterparty, or mempool submitter can construct without needing any signature bypass (the solution bytes themselves don't need to satisfy the puzzle to be run through this canonical-encoding check, only to reach the DEDUP-eligibility gate). No special network position or privileged key is required.

### Recommendation
Add explicit bounds checks in both `is_atom_canonical()` and `is_clvm_canonical()`: verify that `offset + prefix_len < len(clvm_buffer)` before reading prefix bytes, and that `offset + atom_len <= len(clvm_buffer)` before advancing `offset`, returning `False` on violation instead of raising. Replace the bare `assert clvm_buffer != b""` with an explicit `if clvm_buffer == b"": return False` (or raise a caught/expected exception type) so malformed input is a normal “not canonical” result rather than an unhandled crash.

### Proof of Concept
Using the buffer-construction helper already present in the test suite (`serialized_atom_overflow`), an analogous crafted buffer can be built directly against `is_clvm_canonical`/`is_atom_canonical`: build a buffer whose first byte declares a multi-byte length prefix (e.g. `0xC0`-class prefix) but is followed by fewer bytes than the declared `atom_len`, e.g.:
```python
from chia.full_node.mempool_manager import is_clvm_canonical
# 0xC0 | high-byte, low-byte declare atom_len far larger than remaining buffer
buf = bytes([0xC0, 0xFF, 0x01])  # declares an atom far longer than available bytes
is_clvm_canonical(buf)  # raises IndexError instead of returning False
```
This demonstrates the same bug class as the `images` advisory: a size value taken from untrusted input is used to advance an offset/length without bounds validation, producing an unhandled crash instead of a safe boolean result. [6](#0-5)

def is_atom_canonical(clvm_buffer: bytes, offset: int) -> tuple[int, bool]:
    b = clvm_buffer[offset]
    if (b & 0b11000000) == 0b10000000:
        # 6 bits length prefix
        mask = 0b00111111
        prefix_len = 0
        min_value = 1
    elif (b & 0b11100000) == 0b11000000:
        # 5 + 8 bits length prefix
        mask = 0b00011111
        prefix_len = 1
        min_value = 1 << 6
    elif (b & 0b11110000) == 0b11100000:
        # 4 + 8 + 8 bits length prefix
        mask = 0b00001111
        prefix_len = 2
        min_value = 1 << (5 + 8)
    elif (b & 0b11111000) == 0b11110000:
        # 3 + 8 + 8 + 8 bits length prefix
        mask = 0b00000111
        prefix_len = 3
        min_value = 1 << (4 + 8 + 8)
    elif (b & 0b11111100) == 0b11111000:
        # 2 + 8 + 8 + 8 + 8 bits length prefix
        mask = 0b00000011
        prefix_len = 4
        min_value = 1 << (3 + 8 + 8 + 8)
    elif (b & 0b11111110) == 0b11111100:
        # 1 + 8 + 8 + 8 + 8 + 8 bits length prefix
        mask = 0b00000001
        prefix_len = 5
        min_value = 1 << (2 + 8 + 8 + 8 + 8)

    atom_len = b & mask
    for i in range(prefix_len):
        atom_len <<= 8
        offset += 1
        atom_len |= clvm_buffer[offset]

    return 1 + prefix_len + atom_len, atom_len >= min_value


def is_clvm_canonical(clvm_buffer: bytes) -> bool:
    """
    checks whether the CLVM serialization is all canonical representation.
    atoms can be serialized in more than one way by using more bytes than
    necessary to encode the length prefix. This functions ensures that all atoms are
    encoded with the shortest representation. back-references are not allowed
    and will make this function return false
    """
    assert clvm_buffer != b""

    offset = 0
    tokens_left = 1
    while True:
        b = clvm_buffer[offset]

        # pair
        if b == 0xFF:
            tokens_left += 1
            offset += 1
            continue

        # back references cannot be considered canonical, since they may be
        # encoded in many different ways
        if b == 0xFE:
            return False

        # small atom or NIL
        if b <= 0x80:
            tokens_left -= 1
            offset += 1
        else:
            atom_len, canonical = is_atom_canonical(clvm_buffer, offset)
            if not canonical:
                return False
            tokens_left -= 1
            offset += atom_len

        if tokens_left == 0:
            break

    # if there's garbage at the end, it's not canonical
    return offset == len(clvm_buffer)

## Canonical serialization

**Location**: `mempool_manager.py:185`

### `is_clvm_canonical(clvm_buffer)`

Checks that a CLVM program uses shortest-form atom encoding:

- No unnecessary length prefix bytes
- No back-references (`0xFE` byte)
- No trailing garbage

### When enforced

Required for DEDUP-eligible spends. Without canonical form, identical
solutions could have different serializations, breaking dedup.

### `is_atom_canonical(clvm_buffer, offset)`

Validates a single atom's length prefix encoding. The CLVM format uses
variable-length prefixes (1-6 bytes) based on atom size. Each prefix
length has a minimum atom size threshold.
