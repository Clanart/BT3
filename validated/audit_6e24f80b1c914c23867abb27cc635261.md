### Title
`transfer_outpoints_to_wallet` Fails to Block `ReimburseInRound` UTXOs, Enabling Permanent Lock of Bridged BTC — (`File: core/src/operator.rs`)

---

### Summary

`transfer_outpoints_to_wallet` (exposed via the `TransferToBtcWallet` gRPC endpoint) guards only against transferring collateral outpoints. It does not guard against transferring `ReimburseInRound` UTXOs, which sit at the same plain operator taproot address and are required as a key-spend input in the `reimburse_tx`. Spending a `ReimburseInRound` connector via this function invalidates the only pre-signed path that spends the `DepositInMove` UTXO, permanently locking the bridged BTC.

---

### Finding Description

`transfer_outpoints_to_wallet` performs two checks before signing and broadcasting:

1. **Script-pubkey check** (in the RPC handler): the outpoint's `script_pubkey` must equal the operator's plain taproot address (xonly key, no merkle root).
2. **Collateral blocklist check**: `get_all_collateral_outpoints` is called and any match causes an early return error. [1](#0-0) [2](#0-1) 

`get_all_collateral_outpoints` populates the blocklist with three categories of outpoints: the initial `collateral_funding_outpoint`, `CollateralInRound` (vout 0 of each round tx), and `CollateralInReadyToReimburse` (vout 0 of each ready-to-reimburse tx). [3](#0-2) 

`ReimburseInRound` UTXOs are created in `create_round_txhandler` with **no scripts** and `Some(operator_xonly_pk)` as the internal key — identical script-pubkey to the collateral: [4](#0-3) 

Because `ReimburseInRound` outpoints are never inserted into the blocklist, they pass both checks and can be signed and broadcast by `transfer_outpoints_to_wallet`.

The `reimburse_tx` requires three inputs:

1. `DepositInMove` — the bridge vault UTXO holding the deposited BTC (script-spend, nofn-signed)
2. `ReimburseInKickoff` — kickoff connector (script-spend, nofn-signed)
3. `ReimburseInRound` — round connector (**key-spend, operator-signed**) [5](#0-4) 

If `ReimburseInRound` is spent via `TransferToBtcWallet`, the pre-signed `reimburse_tx` becomes invalid (double-spend of input 3). No alternative spending path exists for `DepositInMove`, so the bridged BTC is permanently locked.

---

### Impact Explanation

The `DepositInMove` UTXO contains `bridge_amount` of BTC. The only pre-signed transaction that spends it is `reimburse_tx`. Consuming the `ReimburseInRound` connector via `TransferToBtcWallet` destroys the connector for a trivial `default_utxo_amount` while permanently locking the full `bridge_amount` in the move-to-vault UTXO. This is a permanent, irreversible loss of bridged BTC. [6](#0-5) 

---

### Likelihood Explanation

`TransferToBtcWallet` is accessible to both the operator itself and the aggregator (any non-`Internal`-prefixed method is allowed for both `our_cert` and `aggregator_cert`): [7](#0-6) 

The operator may call this RPC to sweep dust UTXOs from their taproot address. Because `ReimburseInRound` UTXOs are indistinguishable from ordinary operator-owned UTXOs by address alone, an operator sweeping their address after a round could inadvertently include an active reimburse connector. The aggregator, which is also permitted to call this endpoint, represents an additional trust boundary. The function's own documentation advertises collateral protection but is silent on reimburse connectors, creating a false sense of safety. [8](#0-7) 

---

### Recommendation

Extend `get_all_collateral_outpoints` (or create a parallel `get_all_protected_outpoints`) to also enumerate all `ReimburseInRound` outpoints for every round. Add them to the blocklist checked inside `transfer_outpoints_to_wallet`, mirroring the existing collateral protection:

```rust
// For each round tx, also block ReimburseInRound UTXOs
for kickoff_idx in 0..paramset.num_kickoffs_per_round {
    let reimburse_outpoint = OutPoint {
        txid: *round_tx.get_txid(),
        vout: UtxoVout::ReimburseInRound(kickoff_idx, paramset.num_kickoffs_per_round).get_vout(),
    };
    outpoints.insert(reimburse_outpoint, (round_idx, TransactionType::Round));
}
``` [9](#0-8) 

---

### Proof of Concept

1. Operator completes a payout and sends a kickoff tx for deposit `D`. The round tx for round `R` is on-chain. `ReimburseInRound(k, R)` is unspent and at the operator's plain taproot address.
2. Operator (or aggregator) calls `TransferToBtcWallet` with outpoint `(round_tx_R_txid, ReimburseInRound(k).get_vout())`.
3. RPC handler: `txout.script_pubkey == operator.signer.address.script_pubkey()` → **passes**.
4. `get_all_collateral_outpoints` returns only `CollateralInRound` and `CollateralInReadyToReimburse` entries; `ReimburseInRound` is absent → **passes**.
5. `transfer_outpoints_to_wallet` signs and broadcasts a transaction spending `ReimburseInRound(k, R)` to the operator's wallet.
6. The pre-signed `reimburse_tx` for deposit `D` now references a spent input and can never be broadcast.
7. `DepositInMove` for deposit `D` (containing `bridge_amount` BTC) is permanently unspendable. [10](#0-9) [11](#0-10)

    /// Gets all collateral outpoints for the operator.
    /// Returns a map of outpoint to the round index it belongs to.
    async fn get_all_collateral_outpoints(
        &self,
    ) -> Result<HashMap<OutPoint, (RoundIndex, TransactionType)>, BridgeError> {
        let mut outpoints = HashMap::new();
        outpoints.insert(
            self.collateral_funding_outpoint,
            (RoundIndex::Collateral, TransactionType::Round),
        );

        // Fetch operator kickoff winternitz public keys to build round txs
        let operator_winternitz_public_keys = self
            .db
            .get_operator_kickoff_winternitz_public_keys(None, self.signer.xonly_public_key)
            .await?;
        let kickoff_wpks = KickoffWinternitzKeys::new(
            operator_winternitz_public_keys,
            self.config.protocol_paramset().num_kickoffs_per_round,
            self.config.protocol_paramset().num_round_txs,
        )?;
        let operator_data = self.data();

        let mut prev_ready_to_reimburse: Option<TxHandler> = None;

        // Collect collateral outpoints for each round
        for round_idx in RoundIndex::iter_rounds(self.config.protocol_paramset().num_round_txs) {
            let txhandlers = create_round_txhandlers(
                self.config.protocol_paramset(),
                round_idx,
                &operator_data,
                &kickoff_wpks,
                prev_ready_to_reimburse.as_ref(),
            )?;

            let round_tx = txhandlers
                .iter()
                .find(|txhandler| txhandler.get_transaction_type() == TransactionType::Round)
                .ok_or(eyre::eyre!("Round tx not found in txhandlers"))?;
            let collateral_outpoint = OutPoint {
                txid: *round_tx.get_txid(),
                vout: UtxoVout::CollateralInRound.get_vout(),
            };
            outpoints.insert(collateral_outpoint, (round_idx, TransactionType::Round));

            let ready_to_reimburse_tx = txhandlers
                .iter()
                .find(|txhandler| {
                    txhandler.get_transaction_type() == TransactionType::ReadyToReimburse
                })
                .ok_or(eyre::eyre!("Ready to reimburse tx not found in txhandlers"))?;
            let ready_to_reimburse_collateral_outpoint = OutPoint {
                txid: *ready_to_reimburse_tx.get_txid(),
                vout: UtxoVout::CollateralInReadyToReimburse.get_vout(),
            };
            outpoints.insert(
                ready_to_reimburse_collateral_outpoint,
                (round_idx, TransactionType::ReadyToReimburse),
            );
            prev_ready_to_reimburse = Some(ready_to_reimburse_tx.clone());
        }

        Ok(outpoints)
    }
