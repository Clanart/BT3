### Title
Stale AMM-price admission check in gasless swap validation allows execution-time value divergence between lent gas and actual repayment - (File: kaiax/gasless/impl/tx_pool.go)

### Summary
The gasless module lends a user gas funds via a `LendTx` and expects exact repayment inside the same bundle's `GaslessSwapTx`, with the required `amountRepay` fixed and verified only against the AMM's *current* quoted price at admission/build time, not at execution time.

### Finding Description
`checkBalanceForSwap` computes the token amount the user must swap by calling `routerContract.GetAmountIn(nil, token, minAmountOut)` against the live state of the DEX pool at the moment of tx-pool admission [1](#0-0) . The `amountRepay` the sender commits to in the `GaslessSwapTx` (verified in `VerifyExecutable`/`repayAmount`) is a fixed KAIA amount derived purely from the two transactions' gas price × gas limit, independent of the AMM's exchange rate [2](#0-1) . The bundle is built as `[LendTxGenerator, GaslessApproveTx, GaslessSwapTx]`, where `LendTxGenerator` unconditionally transfers `lendAmount` (the KAIA the proposer fronts) to the sender before the swap executes [3](#0-2) [4](#0-3) .

This mirrors the `USDMPegRecovery` root cause: an internal, mempool/build-time-computed quantity (`requiredAmountIn`, analogous to internally tracked LP balances) is priced against a live AMM curve that can move between the moment it's checked/quoted and the moment it's actually consumed on-chain (analogous to a CRV trade occurring between deposit and withdrawal). Because `checkBalanceForSwap`'s `GetAmountIn` result is only used as an admission filter and is not re-validated atomically with lending, any price movement of the underlying token/KAIA pair between admission and inclusion (e.g., caused by another transaction touching the same pool in the same block, or the proposer batching multiple bundles) can make the swap's actual on-chain output diverge from what was assumed lendable/repayable at check time.

### Impact Explanation
If the swap under-delivers relative to the fixed `amountRepay` obligation baked into the bundle (because the AMM price moved unfavorably after the stale `GetAmountIn` check but before execution), the `GaslessSwapRouter.swapForGas`'s own `minAmountOut`/repay enforcement will revert the swap transaction — but the `LendTxGenerator` transfer of KAIA to the sender is a separate transaction in the same bundle and, depending on bundle atomicity guarantees, its success is not strictly coupled to the swap's success outside of `IsConflict` bundle exclusion logic. This creates a state-divergence/fund-loss risk where the proposer's lent KAIA is not fully recovered if the swap reverts or partially executes against a stale price assumption, directly paralleling the reported bug's "real balances not matching tracked/expected balances" failure mode.

### Likelihood Explanation
Reachable by any unprivileged user simply submitting a legitimate-looking `GaslessApproveTx`/`GaslessSwapTx` pair through the public RPC/tx pool; a third party (or the same sender via another transaction) can move the referenced DEX pool's price between the tx-pool's `checkBalanceForSwap` admission check and the actual block-building/execution, since admission-time state and inclusion-time state are not guaranteed identical across the mempool-to-block pipeline.

### Recommendation
Do not rely on a point-in-time `GetAmountIn` view call for admission; instead ensure the bundle-building and execution path re-validates the AMM quote atomically immediately before constructing/broadcasting the `LendTx`+`SwapTx` bundle, and make the `LendTx` transfer strictly conditional on (or reversible with) the `SwapTx`'s successful repayment within the same atomic bundle, so a stale-price swap failure cannot separate the lent amount from a guaranteed repayment.

### Proof of Concept
Not independently reproducible from the indexed code alone (the on-chain `GaslessSwapRouter.sol` source implementing `swapForGas`'s internal repay/refund logic and the block-builder's exact bundle atomicity guarantees were not available in the index — only Go bindings were found). This should be verified with a full Devin session having complete repository access to confirm whether `LendTxGenerator`'s transfer and the `GaslessSwapTx` execution are enforced as a single atomic unit at the block-building layer, and to trace whether a reverted/underfilled swap can leave the proposer's lent KAIA unrecovered.

// L1. LendTx.type = 0x7802 (TxTypeEthereumDynamicFee)
// L2. LendTx.from = proposer
// L3. LendTx.to = SwapTx.from
// L4. LendTx.value = LendAmount(approveTxOrNil, swapTx)
func (g *GaslessModule) GetLendTxGenerator(approveTxOrNil, swapTx *types.Transaction) *builder.TxOrGen {
	var src []byte
	if approveTxOrNil != nil {
		src = append(src, approveTxOrNil.Hash().Bytes()...)
	}
	src = append(src, swapTx.Hash().Bytes()...)
	bundleHash := crypto.Keccak256Hash(src)

	gen := func(nonce uint64) (*types.Transaction, error) {
		var (
			chainId = g.InitOpts.ChainConfig.ChainID
			signer  = types.LatestSignerForChainID(chainId)
			key     = g.InitOpts.NodeKey
		)

		to, err := types.Sender(signer, swapTx)
		if err != nil {
			return nil, err
		}

		tx, err := types.NewTransactionWithMap(types.TxTypeEthereumDynamicFee, map[types.TxValueKeyType]interface{}{
			types.TxValueKeyNonce:      nonce,
			types.TxValueKeyTo:         &to,
			types.TxValueKeyAmount:     lendAmount(approveTxOrNil, swapTx),
			types.TxValueKeyData:       common.Hex2Bytes("0x"),
			types.TxValueKeyGasLimit:   params.TxGas,
			types.TxValueKeyGasFeeCap:  swapTx.GasFeeCap(),
			types.TxValueKeyGasTipCap:  swapTx.GasTipCap(),
			types.TxValueKeyAccessList: types.AccessList{},
			types.TxValueKeyChainID:    chainId,
		})
		if err != nil {
			return nil, err
		}

		err = tx.Sign(signer, key)
		return tx, err
	}

	return builder.NewTxOrGenFromGen(gen, bundleHash)
}

func lendAmount(approveTxOrNil, swapTx *types.Transaction) *big.Int {
	r := new(big.Int)

	// R2 = ApproveTx.Fee() if exists
	if approveTxOrNil != nil {
		r.Add(r, approveTxOrNil.Fee())
	}

	// R3 = SwapTx.Fee()
	r.Add(r, swapTx.Fee())

	// LendAmount = R2 + R3
	return r
}

func repayAmount(approveTxOrNil, swapTx *types.Transaction) *big.Int {
	// R1 = LendTx.Fee() = SwapTx.GasPrice() * TxGas
	r1 := new(big.Int).Mul(swapTx.GasPrice(), new(big.Int).SetUint64(params.TxGas))

	// RepayAmount = R1 + R2 + R3
	return new(big.Int).Add(r1, lendAmount(approveTxOrNil, swapTx))
}

### Block building rules

Upon detection of GaslessTxs, the following logics are executed:

- Per sender, if exists, GaslessApproveTx is relocated before GaslessSwapTx.
- LendTxGenerator is prepended before GaslessApproveTx.
- A new bundle is generated which contain either `[LendTxGenerator, GaslessApproveTx, GaslessSwapTx]` or `[LendTxGenerator, GaslessSwapTx]`
- If the bundle has conflict with any previous bundles, it is excluded from the returned bundle list.
