### Title
`ThresholdKeys::read` trusts the serialized participant count and allocates attacker-controlled memory before validating input - ([File: crypto/dkg/src/lib.rs](crypto/dkg/src/lib.rs))

### Summary
`ThresholdKeys::read` deserializes an attacker-controlled `n`, then immediately allocates a vector with capacity `n` when the interpolation byte selects constant interpolation. [1](#0-0) 

### Finding Description
The parser reads `t`, `n`, and `i` directly from the input stream, without first constructing or validating `ThresholdParams`. [2](#0-1)  If the next byte is `0`, it executes `Vec::with_capacity(usize::from(n))` before reading any scalar bytes or checking whether `n` is valid. [3](#0-2)  Only after the interpolation coefficients, secret share, and all `n` verification shares are processed does `ThresholdParams::new(t, n, i)` reject malformed parameters. [4](#0-3) 

Because `n` is a `u16`, a truncated message can cause an allocation proportional to `65_535` scalar elements while supplying only the serialized header. [5](#0-4) 

### Impact Explanation
An unprivileged party able to submit bytes to `ThresholdKeys::read` can force disproportionate memory consumption with a very small input. Repeated malformed messages can exhaust memory or induce allocator failure, denying service to the process performing deserialization. [6](#0-5) 

This is analogous to the advisory's DDoS class: a small, attacker-controlled metadata field causes the implementation to commit substantially more work or resources than the input itself required. [1](#0-0) 

### Likelihood Explanation
`ThresholdKeys::read` is a public deserialization API intended to consume generic `io::Read` input, and no external length limit is enforced inside the function. [7](#0-6)  The malicious encoding does not need to contain the promised scalar or point encodings; the allocation occurs before the first scalar is read. [3](#0-2) 

Exploitation requires an application to deserialize attacker-controlled `ThresholdKeys`; it does not by itself affect applications that only deserialize trusted local key material. [8](#0-7) 

### Recommendation
Validate `t`, `n`, and `i` with `ThresholdParams::new` before allocating the coefficient vector. [2](#0-1)  Avoid preallocating from the serialized count, or impose a protocol-specific maximum before calling `Vec::with_capacity`. [3](#0-2)  Streaming values into an initially empty vector still does not prevent allocation amplification on 32-bit targets, so parameter validation and an explicit maximum should occur before any allocation. [3](#0-2) 

### Proof of Concept
The following truncated input reaches the `Constant` interpolation branch, requests capacity for all `65_535` participants, and then fails on EOF while trying to read the first scalar:

```rust
use std::io::Cursor;

use ciphersuite::Ciphersuite;
use dalek_ff_group::Ristretto;
use dkg::ThresholdKeys;

let mut bytes = Vec::new();
bytes.extend_from_slice(
  &u32::try_from(Ristretto::ID.len()).unwrap().to_le_bytes(),
);
bytes.extend_from_slice(Ristretto::ID);

// t = 1, n = u16::MAX, i = 1
bytes.extend_from_slice(&1u16.to_le_bytes());
bytes.extend_from_slice(&u16::MAX.to_le_bytes());
bytes.extend_from_slice(&1u16.to_le_bytes());

// Interpolation::Constant; no serialized coefficients follow.
bytes.push(0);

let mut cursor = Cursor::new(bytes);
let result = ThresholdKeys::<Ristretto>::read(&mut cursor);
assert!(result.is_err());
```

The decisive behavior is at `crypto/dkg/src/lib.rs:608`, where `Vec::with_capacity(usize::from(n))` allocates for the attacker-declared participant count before the loop attempts to read the corresponding scalar encodings. [3](#0-2)

  /// Read keys from a type satisfying `std::io::Read`.
  pub fn read<R: io::Read>(reader: &mut R) -> io::Result<ThresholdKeys<C>> {
    {
      let different = || io::Error::other("deserializing ThresholdKeys for another curve");

      let mut id_len = [0; 4];
      reader.read_exact(&mut id_len)?;
      if u32::try_from(C::ID.len()).unwrap().to_le_bytes() != id_len {
        Err(different())?;
      }

      let mut id = vec![0; C::ID.len()];
      reader.read_exact(&mut id)?;
      if id != C::ID {
        Err(different())?;
      }
    }

    let (t, n, i) = {
      let mut read_u16 = || -> io::Result<u16> {
        let mut value = [0; 2];
        reader.read_exact(&mut value)?;
        Ok(u16::from_le_bytes(value))
      };
      (
        read_u16()?,
        read_u16()?,
        Participant::new(read_u16()?).ok_or(io::Error::other("invalid participant index"))?,
      )
    };

    let mut interpolation = [0];
    reader.read_exact(&mut interpolation)?;
    let interpolation = match interpolation[0] {
      0 => Interpolation::Constant({
        let mut res = Vec::with_capacity(usize::from(n));
        for _ in 0 .. n {
          res.push(C::read_F(reader)?);
        }
        res
      }),
      1 => Interpolation::Lagrange,
      _ => Err(io::Error::other("invalid interpolation method"))?,
    };

    let secret_share = Zeroizing::new(C::read_F(reader)?);

    let mut verification_shares = HashMap::new();
    for l in (1 ..= n).map(Participant) {
      verification_shares.insert(l, <C as Ciphersuite>::read_G(reader)?);
    }

    ThresholdKeys::new(
      ThresholdParams::new(t, n, i).map_err(io::Error::other)?,
      interpolation,
      secret_share,
      verification_shares,
    )
    .map_err(io::Error::other)
  }
