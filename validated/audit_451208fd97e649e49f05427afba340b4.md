### Title
`BaseRewardPool`/`BaseRewardPoolV2.totalStaked()` relies on raw ERC20 balance instead of internal accounting, letting any wallet dilute reward math via direct token donation - (File: `rewards/BaseRewardPool.sol`, `rewards/BaseRewardPoolV2.sol`)

### Summary
`BaseRewardPool` and `BaseRewardPoolV2` compute `totalStaked()` as the raw `stakingToken.balanceOf(operator)` (MasterMagpie) rather than from internally tracked, per-user deposit accounting. Because `MasterMagpie` deposits are supposed to be the only path that increases this balance, but a plain unprivileged ERC20 `transfer()` to the `MasterMagpie` contract also increases it, an ordinary wallet can inflate `totalStaked()` without ever calling `deposit()`. This mirrors the InitCore `M-05` pattern: collateral/stake accounting is derived from an externally-observable balance instead of internal bookkeeping, so a plain token donation manipulates protocol accounting that should only change through the gated deposit path.

### Finding Description
`totalStaked()` in both `BaseRewardPool.sol` and `BaseRewardPoolV2.sol` is defined as: [1](#0-0) [2](#0-1) 

This value is the divisor used in `_provisionReward` to compute the global `rewardPerTokenStored` whenever new rewards are queued/donated: [3](#0-2) 

`donateRewards` is a permissionless entry point that triggers `_provisionReward` (and thus a `rewardPerTokenStored` update using `totalStaked()`), while `stakingToken` for a given `BaseRewardPool` is a normal, freely transferable ERC20 (e.g. a Wombat receipt token or LP token minted by `WombatStaking`) held by `MasterMagpie` at address `operator`: [4](#0-3) 

Since `stakingToken.balanceOf(operator)` counts every token physically sitting in the `MasterMagpie` contract — not just tokens that went through `MasterMagpie.deposit`/`depositFor` and were credited to a `UserInfo.amount` — any unprivileged wallet can call `stakingToken.transfer(masterMagpieAddress, amount)` directly. This inflates `totalStaked()` without crediting any user's `UserInfo.amount` in `MasterMagpie`: [5](#0-4) 

Unlike per-user rewards (`balanceOf(_account)` in `BaseRewardPool`, which correctly reads `IMasterMagpie.stakingInfo` — internal accounting), the pool-wide `totalStaked()` denominator has no equivalent internal-accounting safeguard: [6](#0-5) 

This is directly analogous to the `M-05` root cause: `InitCore`/`PosManager` compute collateral value from `IBaseWrapLp(wLps[i]).balanceOfLp(ids[i][j])` (a raw external balance) instead of tracked internal deposits, letting anyone donate tokens directly to a position's underlying LP and change protocol accounting outside the gated `collateralizeWLp` path. Here, `totalStaked()` similarly reads a raw external balance (`stakingToken.balanceOf(operator)`) instead of the sum of `UserInfo.amount` tracked internally by `MasterMagpie`.

### Impact Explanation
Because `rewardPerTokenStored += (_amountReward * 10**decimals) / totalStaked()` uses the manipulated (larger) `totalStaked()`, every subsequent reward distribution computes a **permanently lower** reward-per-token rate. The donated tokens are never withdrawable/attributable to any user (they are not registered in any `UserInfo`), so the inflation of the denominator is permanent unless the donator repeats withdrawal logic that doesn't exist for them. This permanently and irreversibly reduces the yield legitimately-staked users can earn from that pool going forward — a permanent freezing/reduction of unclaimed yield for all current and future stakers of that `BaseRewardPool`. This can be triggered by any wallet holding (or able to acquire) the relevant `stakingToken`, with no privileged role required.

### Likelihood Explanation
High reachability: the attack requires only a standard ERC20 `transfer()` call to the publicly known `MasterMagpie` address using a `stakingToken` that is a normal transferable token (Wombat receipt tokens, LP tokens, etc.), which any wallet can hold. No special permissions, timing, or protocol state are needed — it works as long as a `BaseRewardPool`/`BaseRewardPoolV2` for that staking token exists and rewards are/will be distributed through `queueNewRewards`/`donateRewards`.

### Recommendation
Do not derive `totalStaked()` from `IERC20(stakingToken).balanceOf(operator)`. Instead, track and expose the true internally-accounted total (e.g., a `totalSupply`/`totalStaked` counter incremented/decremented only inside `MasterMagpie._deposit`/`_withdraw`, mirroring the pattern already used by `mWomSV`/`VLMGP`, or have `BaseRewardPool` maintain its own `totalSupply` updated exclusively via `stakeFor`/`withdrawFor` calls from the `onlyMasterMagpie` modifier), so that direct token transfers to the contract cannot influence reward-per-token math.

### Proof of Concept
1. Identify a live `BaseRewardPool` (or `BaseRewardPoolV2`) instance and its `stakingToken` (e.g., a Wombat receipt token minted by `WombatStaking.deposit`), whose `operator` is `MasterMagpie`.
2. Attacker wallet acquires some of that `stakingToken` (e.g., by depositing a small amount normally, or otherwise obtaining it on the open market).
3. Attacker calls `stakingToken.transfer(masterMagpieAddress, largeAmount)` directly — bypassing `MasterMagpie.deposit`/`depositFor` entirely, so no `UserInfo.amount` is updated for anyone.
4. `BaseRewardPool.totalStaked()` (`IERC20(stakingToken).balanceOf(operator)`, at `rewards/BaseRewardPool.sol:126-128`) now returns the inflated balance.
5. Next time `queueNewRewards`/`donateRewards` (`rewards/BaseRewardPool.sol:297-318`) is called to distribute rewards, `rewardPerTokenStored` is computed with the artificially large `totalStaked()` denominator, permanently lowering the reward rate credited to all legitimate stakers of that pool, while the donated tokens remain stuck in `MasterMagpie` un-attributed to any staker.

    function _provisionReward(uint256 _amountReward, address _rewardToken) internal {
        IERC20(_rewardToken).safeTransferFrom(
            msg.sender,
            address(this),
            _amountReward
        );
        Reward storage rewardInfo = rewards[_rewardToken];
        rewardInfo.historicalRewards =
            rewardInfo.historicalRewards +
            _amountReward;
        if (this.totalStaked() == 0) {
            rewardInfo.queuedRewards += _amountReward;
        } else {
            if (rewardInfo.queuedRewards > 0) {
                _amountReward += rewardInfo.queuedRewards;
                rewardInfo.queuedRewards = 0;
            }
            rewardInfo.rewardPerTokenStored =
                rewardInfo.rewardPerTokenStored +
                (_amountReward * 10**stakingDecimals()) /
                this.totalStaked();
        }
