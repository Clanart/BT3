### Title
Quadratic Lagrange interpolation in `ThresholdKeys::read` enables CPU exhaustion - (File: crypto/dkg/src/lib.rs)

### Summary
`ThresholdKeys::read` accepts attacker-controlled `t`, `n`, and Lagrange interpolation parameters without imposing a practical bound before constructing the key. [1](#0-0)  During `ThresholdKeys::new`, the group key is computed by evaluating `interpolation_factor` once for each of the `t` participants. [2](#0-1)  Each Lagrange evaluation iterates over the complete `t`-element participant list and performs a field inversion. [3](#0-2) 

### Finding Description
The deserializer reads `t`, `n`, and `i` directly from untrusted input and permits `t == n == u16::MAX`. [4](#0-3)  Selecting interpolation byte `1` avoids the `n` scalar encodings used by constant interpolation, so the input only needs one scalar and `n` group encodings. [5](#0-4) 

`ThresholdKeys::new` then creates participants `1..=t` and calls `interpolation_factor` for every participant. [2](#0-1)  Because each Lagrange factor scans all `t` participants, construction requires `O(t²)` scalar operations and `O(t)` field inversions. [3](#0-2) 

### Impact Explanation
A roughly 4 MB serialized `ThresholdKeys` object can request `t = n = 65,535`, causing approximately 4.3 billion inner-loop iterations and 65,535 field inversions before `read` returns. This can monopolize CPU and make the calling signing/key-management service unavailable; repeated requests increase the exhaustion. The attacker does not need a meaningful secret share because the constructor does not verify that `secret_share` corresponds to `verification_shares[i]` before performing the expensive group-key computation. [6](#0-5) 

### Likelihood Explanation
The vulnerable path is directly reachable through the public `ThresholdKeys::read` API with only canonical scalar and point encodings. [7](#0-6)  Canonical zero scalars are accepted by `read_F`, and repeated valid group-element encodings are accepted by `read_G`. [8](#0-7)  Exploitability therefore depends on whether an application parses attacker-supplied threshold-key blobs, backups, synchronization data, or recovery payloads using this API.

### Recommendation
Validate `ThresholdParams` immediately after reading `t`, `n`, and `i`, before reading interpolation data or constructing `ThresholdKeys`. Impose an application-level maximum participant count and reject `t == n == 65,535` unless explicitly supported. More fundamentally, replace the per-participant quadratic Lagrange evaluation with a batch interpolation algorithm, or defer expensive key construction until the input has been fully authenticated.

### Proof of Concept

use ciphersuite::{Ciphersuite, group::GroupEncoding};
use dalek_ff_group::Ristretto;
use dkg::ThresholdKeys;

let mut input = Vec::new();

// Curve identifier.
input.extend_from_slice(&(Ristretto::ID.len() as u32).to_le_bytes());
input.extend_from_slice(Ristretto::ID);

// t = n = u16::MAX, participant i = 1.
input.extend_from_slice(&u16::MAX.to_le_bytes());
input.extend_from_slice(&u16::MAX.to_le_bytes());
input.extend_from_slice(&1u16.to_le_bytes());

// Interpolation::Lagrange.
input.push(1);

// Canonical zero Ristretto scalar for secret_share.
input.extend_from_slice(&[0u8; 32]);

// n canonical verification-share encodings; values may repeat.
let generator = Ristretto::generator().to_bytes();
for _ in 0..u16::MAX {
    input.extend_from_slice(generator.as_ref());
}

// Triggers O(65,535²) Lagrange work inside ThresholdKeys::new.
let _ = ThresholdKeys::<Ristretto>::read(&mut input.as_slice());

impl<C: Ciphersuite> ThresholdKeys<C> {
  /// Create a new set of ThresholdKeys.
  pub fn new(
    params: ThresholdParams,
    interpolation: Interpolation<C::F>,
    secret_share: Zeroizing<C::F>,
    verification_shares: HashMap<Participant, C::G>,
  ) -> Result<ThresholdKeys<C>, DkgError> {
    if verification_shares.len() != usize::from(params.n()) {
      Err(DkgError::IncorrectAmountOfVerificationShares {
        n: params.n(),
        shares: verification_shares.len(),
      })?;
    }
    for participant in verification_shares.keys().copied() {
      if u16::from(participant) > params.n() {
        Err(DkgError::InvalidParticipant { n: params.n(), participant })?;
      }
    }

    match &interpolation {
      Interpolation::Constant(_) => {
        if params.t() != params.n() {
          Err(DkgError::InapplicableInterpolation("constant interpolation for keys where t != n"))?;
        }
      }
      Interpolation::Lagrange => {}
    }

    let t = (1 ..= params.t()).map(Participant).collect::<Vec<_>>();
    let group_key =
      t.iter().map(|i| verification_shares[i] * interpolation.interpolation_factor(*i, &t)).sum();

    Ok(ThresholdKeys {
      core: Arc::new(Zeroizing::new(ThresholdCore {
        params,
        interpolation,
        secret_share,
        group_key,
        verification_shares,
      })),
      scalar: C::F::ONE,
      offset: C::F::ZERO,
    })
