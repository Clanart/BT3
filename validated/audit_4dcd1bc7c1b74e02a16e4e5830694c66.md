## Analysis

The whitepaper-discrepancy report's underlying pattern is: **state that should be evaluated/finalized at one canonical moment is instead evaluated relative to inconsistent snapshots, letting a state that has already been superseded be treated as still valid** (e.g. balances snapshotted "whenever the first reveal happens" instead of atomically at period start, or "median accepted" instead of a proper re-vote). The strongest local analog in Hyperbridge is a **stale-state-commitment double-payment** in the GET-request fee lifecycle on `EvmHost.sol`: the fee record for a GET request is never cleared once a `GetResponse` is delivered, so a later timeout message anchored to an *older, already-canonical* state commitment (one whose non-membership window predates the response) can still fire and pay the fee a second time.

### Root cause

`EvmHost.dispatchIncoming(GetResponse ...)` pays the relayer fee out of `_requestCommitments[commitment]` but never deletes that entry: [1](#0-0) 

Compare this to the sibling function `dispatchTimeOut(GetRequestTimeout ...)`, which *does* delete `_requestCommitments[commitment]` for replay protection before paying out a refund: [2](#0-1) 

`HandlerV2.handleGetRequestTimeouts` gates the timeout purely on: (1) `request.timeout() > state.timestamp` being false for the *chosen* `message.height` (any previously-stored height, not necessarily the latest), (2) `requestCommitments(commitment).sender != 0` (never cleared by the response path above), and (3) a non-membership proof of the response receipt at that same, arbitrary height: [3](#0-2) 

`stateMachineCommitment(height)` retains state commitments for *every* previously verified height indefinitely (not just the latest) unless a fisherman explicitly vetoes it: [4](#0-3) 

### The exploit path

1. A relayer legitimately delivers a `GetResponse` for a GET request; `dispatchIncoming(GetResponse,...)` pays the fee to that relayer but leaves `_requestCommitments[commitment]` (sender + fee) intact.
2. The response's non-membership record only appears in the destination/coprocessor trie *at or after* the height where it was actually written. Any earlier height that Hyperbridge/EvmHost had already durably committed — and whose embedded `state.timestamp` already exceeds the GET request's `timeout` — still satisfies `handleGetRequestTimeouts`'s non-membership check (the response simply didn't exist yet at that earlier height).
3. Anyone (permissionless) submits `handleGetRequestTimeouts` using that older height's proof. All checks pass: challenge period elapsed (it's an old height), `timeout` already exceeded relative to that height's timestamp, `meta.sender != 0` (never cleared), and the non-membership proof verifies against that legitimately-stored older root.
4. `dispatchTimeOut` refunds `meta.fee` to `meta.sender` — a second payout of the exact same fee that was already paid to the relayer in step 1.

No malicious relayer, prover, or admin is required — only ordinary permissionless callers using publicly obtainable state proofs against commitments the protocol itself already finalized.

## Impact

This is a direct double-payment/loss-of-funds bug: the protocol's fee token balance is drained by paying the same GET-request fee twice (once to the delivering relayer, once as a timeout refund to the original payer), for every GET request whose response lands later than some already-canonical, pre-response state height. This matches the bounty's "stealing or loss of funds" / "double-claim" categories exactly, and requires no privileged actor.

## Recommendation

`EvmHost.dispatchIncoming(GetResponse memory response, address relayer)` should `delete _requestCommitments[commitment]` (mirroring the pattern in `dispatchTimeOut`) immediately after — or in place of — reading `meta.fee`, so that any subsequent `handleGetRequestTimeouts` call for the same commitment fails the `meta.sender == address(0)` (`UnknownMessage`) check, regardless of which historical height's proof is supplied.

## Proof of Concept

1. Dispatch a `GetRequest` from `EvmHost` A to destination B via Hyperbridge with a short `timeout` and non-zero `fee`.
2. Let a relayer deliver the `GetResponse` normally: `handleGetResponses` → `dispatchIncoming(GetResponse,...)` pays `fee` to the relayer; `_requestCommitments[commitment]` remains set with the original `sender`/`fee`.
3. Identify (via public RPC/state queries) an earlier state-machine height `H1` that Hyperbridge/EvmHost already committed *before* the response's inclusion, whose `StateCommitment.timestamp` already exceeds the request's `timeout`.
4. Construct a `PolkadotTrie` non-membership proof for `RESPONSE_RECEIPTS_STORAGE_PREFIX || commitment` against `H1`'s stored root (valid, since the response hadn't landed yet at that height).
5. Call `handleGetRequestTimeouts` with `message.height = H1` and this proof. All checks pass (`MessageNotTimedOut` not triggered, `UnknownMessage` not triggered, `InvalidProof` not triggered) → `dispatchTimeOut` refunds `meta.fee` to `meta.sender`, duplicating the payout already made in step 2.

    function dispatchIncoming(GetResponse memory response, address relayer) external restrict(_hostParams.handler) {
        // replay protection
        bytes32 commitment = response.request.hash();
        _responseReceipts[commitment] = ResponseReceipt({
            relayer: relayer,
            responseCommitment: response.hash()
        });

        (bool success,) = _bytesToAddress(response.request.from)
            .call(abi.encodeWithSelector(IApp.onGetResponse.selector, IncomingGetResponse(response, relayer)));

        if (!success) {
            // so that it can be retried
            delete _responseReceipts[commitment];
            return;
        }

        // reward the relayer fee
        uint256 fee = _requestCommitments[commitment].fee;
        if (fee != 0) {
            IERC20(feeToken()).safeTransfer(relayer, fee);
        }
        emit GetRequestHandled({commitment: commitment, relayer: relayer});
    }

    function handleGetRequestTimeouts(IHost host, GetTimeoutMessage calldata message) external notFrozen(host) {
        uint256 delay = block.timestamp - host.stateMachineCommitmentUpdateTime(message.height);
        uint256 challengePeriod = host.challengePeriod();
        if (challengePeriod != 0 && challengePeriod > delay) revert ChallengePeriodNotElapsed();

        // fetch the state commitment
        StateCommitment memory state = host.stateMachineCommitment(message.height);
        if (state.stateRoot == bytes32(0)) revert StateCommitmentNotFound();
        uint256 timeoutsLength = message.timeouts.length;

        for (uint256 i = 0; i < timeoutsLength; ++i) {
            GetRequest memory request = message.timeouts[i];
            // timed-out?
            if (request.timeout() > state.timestamp) revert MessageNotTimedOut();

            bytes32 commitment = request.hash();
            FeeMetadata memory meta = host.requestCommitments(commitment);
            if (meta.sender == address(0)) revert UnknownMessage();

            bytes[] memory keys = new bytes[](1);
            keys[0] = bytes.concat(RESPONSE_RECEIPTS_STORAGE_PREFIX, commitment);

            // verify state trie non-membership proofs
            PolkadotTrie.StorageValue memory entry = PolkadotTrie.VerifyProof(state.stateRoot, message.proof, keys)[0];
            if (entry.value.length != 0) revert InvalidProof();

            host.dispatchTimeOut(GetRequestTimeout(request, _msgSender()), meta, commitment);
        }
    }
