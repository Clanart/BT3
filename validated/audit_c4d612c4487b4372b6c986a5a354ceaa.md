### Title
`SchnorrAggregate::verify` derives aggregation weights without binding the nonces, allowing forged aggregate signatures - (File: crypto/schnorr/src/aggregate.rs)

### Summary
The bug-class hint is a publicly manipulable input feeding a persistent computed rate. The analog in Serai is `SchnorrAggregate::verify`: the per-signature aggregation weights `z_i` are derived solely from the caller-supplied challenges, and never bind the attacker-controlled `Rs` (or the public keys). Because a prover can predict every `z_i` before choosing `Rs`, they can solve the verification equation for the final nonce and produce a `SchnorrAggregate` that verifies for arbitrary public keys and challenges without any valid underlying signature.

### Finding Description
In `crypto/schnorr/src/aggregate.rs`, `verify` builds a `DigestTranscript` from the DST and appends only each `challenge`:

```rust
let mut digest = DigestTranscript::<C::H>::new(dst);
digest.domain_separate(b"signatures");
for (_, challenge) in keys_and_challenges {
  digest.append_message(b"challenge", challenge.to_repr());
}
``` [1](#0-0) 

It then computes `z = weight(&mut digest)` per index and checks `Σ z_i·R_i + Σ z_i·c_i·A_i − s·G == 0`:

```rust
for (i, (key, challenge)) in keys_and_challenges.iter().enumerate() {
  let z = weight(&mut digest);
  pairs.push((z, self.Rs[i]));
  pairs.push((z * challenge, *key));
}
pairs.push((-self.s, C::generator()));
multiexp_vartime(&pairs).is_identity().into()
``` [2](#0-1) 

The stated purpose of `weight` is "a unbiased scalar weight to use on a signature in order to prevent malleability" [3](#0-2) . For half-aggregation (eprint 2021/350), the coefficient must bind the statement being verified — the aggregate key / nonce list — so the prover cannot select nonces after learning the weights. Here the weight transcript contains only `challenge` values; `self.Rs` and the public keys are never appended. Since `DigestTranscript::challenge` is deterministic given prior transcript state [4](#0-3) , every `z_i` is a public function of the inputs the verifier already supplies.

The single multiexp is also the entire check: there is no per-signature `s_i` — the verifier only sees `Rs` and one scalar `s` from `SchnorrAggregate::read`, which reads `u32` count then `Rs` then `s` from untrusted bytes [5](#0-4) .

### Impact Explanation
An unprivileged party can craft a `SchnorrAggregate` (via `SchnorrAggregate::read` of arbitrary bytes) that passes `verify` for any `keys_and_challenges` set, i.e., a forged aggregate signature attesting to signatures under keys the attacker does not control. Anywhere aggregate Schnorr verification is used to authorize actions (the same machinery backs Tributary's Tendermint commit aggregation via `SchnorrAggregator`/`DigestTranscript` patterns), a forged aggregate equates to accepting statements never signed.

### Likelihood Explanation
Fully deterministic and reachable by any party able to submit serialized aggregate bytes to a verifier: the attacker needs only the public keys and challenges (both public), computes `z_i` locally using the same `weight` function, picks arbitrary `R_1..R_{n-1}` and `s`, and solves for `R_n = z_n^{-1}(s·G − Σ_{i<n} z_i(R_i + c_i·A_i) − z_n·c_n·A_n)`. No secret knowledge, no minority-of-hash-power, and no honest signer participation is required — verification is a single linear relation over publicly predictable scalars.

### Recommendation
Bind the full verification context into the weight transcript before deriving any `z_i`: append each public key and each nonce commitment (e.g., `digest.append_message(b"key", key.to_bytes())` and `digest.append_message(b"R", R.to_bytes())` inside a first pass over `keys_and_challenges`/`self.Rs`), matching the `L = H(pk_1..pk_n)` commitment used by half-aggregation, so weights cannot be known before `Rs` are fixed.

### Proof of Concept
Given target `(A_i, c_i)` pairs and a `dst`:

1. Build `DigestTranscript::<C::H>::new(dst)`, `domain_separate(b"signatures")`, append all `c_i` exactly as `verify` does.
2. Compute each `z_i` by calling `weight(&mut digest)` in order (replicating aggregate.rs lines 22–65).
3. Choose arbitrary nonzero scalar `s` and random points `R_1..R_{n-1}`.
4. Compute `R_n = (z_n^{-1})·(s·G − Σ_{i<n} z_i·(R_i + c_i·A_i) − z_n·c_n·A_n)` where the point ops are done in the group and `z_n^{-1}` is the scalar inverse.
5. Serialize `SchnorrAggregate { Rs: [R_1..R_n], s }`.

Verification computes `Σ z_i·R_i + Σ z_i·c_i·A_i − s·G`; substituting `R_n` makes the sum the identity, so `verify` returns `true` for a signature set that never existed. The same construction works for any choice of `Rs` order/values since no `R` ever enters the weight transcript.
