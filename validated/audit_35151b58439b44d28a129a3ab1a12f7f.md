### Title
DataLayer mirror URLs and downloader/uploader plugin URLs enable SSRF via attacker-controlled on-chain data - (File: chia/data_layer/data_layer.py)

### Summary
Chia's DataLayer subsystem stores arbitrary attacker-supplied URL strings on-chain (via mirror coins) and locally (via `subscribe`), then automatically dereferences those URLs with outbound HTTP requests from the DataLayer service (`aiohttp.ClientSession`) with no destination validation. This mirrors the reported Casdoor "Webhook URL Handler" SSRF pattern (CWE-918): a user-controlled URL field is later fetched server-side, letting an attacker point any DataLayer node at internal/private network endpoints.

### Finding Description
Any wallet holder can create a "mirror" for a DataLayer store by calling `dl_new_mirror`, which creates a coin whose puzzle memos embed arbitrary URL strings supplied by the caller: [1](#0-0) 

These URLs are stored on-chain in the coin's `CREATE_COIN` memo and are decoded by any peer that observes the mirror coin, with no scheme/host/IP validation: [2](#0-1) 

Any DataLayer node that is subscribed to (or owns) the referenced store id will later pull these URLs from the wallet and treat them as download servers: [3](#0-2) 

The DataLayer sync loop (`fetch_and_validate` / `update_subscription`) then performs outbound HTTP requests to these attacker-chosen URLs via `download_file`/`http_download` with no allow-listing of hosts, no blocking of loopback/link-local/private ranges, and no scheme restriction beyond what `aiohttp` itself does: [4](#0-3) [5](#0-4) 

Separately, `get_downloader`/`get_uploaders` also POST attacker-influenced data to plugin URLs configured by the operator's `downloaders`/`uploaders` list, and `subscribe`/`add_mirror` RPCs accept raw URL strings without validation: [6](#0-5) [7](#0-6) [8](#0-7) 

There is no code path that validates the mirror/server URL against a denylist of private, loopback, or link-local addresses (e.g., `169.254.169.254` cloud metadata, `127.0.0.1`, internal RFC1918 ranges) before the DataLayer service issues the request.

### Impact Explanation
Because mirror URLs are propagated on-chain and consumed automatically by any subscribing DataLayer node's background sync loop (`periodically_manage_data` → `update_subscription` → `fetch_and_validate`), a malicious DataLayer participant (an unprivileged wallet user who can spend a small amount to create a mirror coin) can force every other node subscribed to a shared store to issue outbound HTTP GET/POST requests to attacker-chosen internal addresses. This can be used to:
- probe/interact with internal network services and cloud metadata endpoints reachable only from the victim's node (SSRF),
- trigger requests to third-party hosts for reflection/DoS amplification.

This matches CWE-918 in the source advisory and is reachable by the "Data Layer client" / on-chain participant category permitted by the scope rules. It does not directly cause coin-set divergence, forged assets, or unauthorized spends; the impact is confined to SSRF-style outbound requests, consistent with the Medium severity of the original advisory.

### Likelihood Explanation
Likelihood is moderate-to-high for anyone participating in shared DataLayer stores: creating a mirror coin only requires a normal wallet spend (`dl_new_mirror`), and any node subscribed to that store id will automatically fetch the URLs during its periodic subscription-management loop without operator interaction. No special privileges beyond normal wallet/DataLayer usage are required.

### Recommendation
- Validate and sanitize URLs before use in `DataLayerWallet.create_new_mirror`/`add_mirror`, `subscribe`, `update_subscriptions_from_wallet`, and before use in `download_file`/`http_download`/`get_downloader`/`get_uploaders`.
- Reject or require explicit opt-in for URLs resolving to loopback, link-local, multicast, or private/internal address ranges (RFC1918, RFC3927, cloud metadata IPs) unless explicitly whitelisted by the node operator.
- Enforce an allow-list/deny-list configuration option for mirror/server hosts, and consider requiring HTTPS with certificate validation for mirror fetches (similar to the existing mainnet HTTPS-only pool URL enforcement pattern).
- Add DNS-rebinding protection (resolve then re-check IP immediately before connecting) since `aiohttp` follows redirects and re-resolves hosts.

### Proof of Concept
1. Attacker (an unprivileged wallet holder) calls `dl_new_mirror` for a store id that a victim DataLayer node subscribes to, with `urls=["http://169.254.169.254/latest/meta-data/"]` (or an internal RFC1918 address of a target service): [9](#0-8) 
2. The mirror coin is confirmed on-chain; any node's `DataLayerWallet.coin_added` observes it and records the URL: [10](#0-9) 
3. The victim's DataLayer background loop (`periodically_manage_data` → `update_subscription`) calls `update_subscriptions_from_wallet` then `fetch_and_validate`, which iterates the attacker's URL as a `ServerInfo` and issues an outbound HTTP request to it via `download_file`/`http_download`, with no validation of the destination: [11](#0-10) [12](#0-11) 

Note: I could not fully inspect the internal implementation of `http_download` itself (only its call site and signature were available via the index), so I cannot fully confirm whether any partial destination filtering exists inside that specific function. If further verification is needed on that exact function body, a full-repository session (not limited by index size) would be required to confirm.

```python
def get_mirror_info(
    parent_puzzle: Program | SerializedProgram, parent_solution: Program | SerializedProgram
) -> tuple[bytes32, list[bytes]]:
    assert type(parent_puzzle) is type(parent_solution)
    _, conditions = run_with_cost(parent_puzzle, INFINITE_COST, parent_solution)
    for condition in conditions.as_iter():
        if (
            condition.first().as_python() == ConditionOpcode.CREATE_COIN
            and condition.at("rf").as_python() == create_mirror_puzzle().get_tree_hash()
        ):
            memos: list[bytes] = condition.at("rrrf").as_python()
            launcher_id = bytes32(memos[0])
            return launcher_id, [url for url in memos[1:]]
    raise ValueError("The provided puzzle and solution do not create a mirror coin")
```

```python
    async def get_downloader(self, store_id: bytes32, url: str) -> PluginRemote | None:
        request_json = {"store_id": store_id.hex(), "url": url}
        for d in self.downloaders:
            async with aiohttp.ClientSession() as session:
                try:
                    async with session.post(
                        d.url + "/handle_download",
                        json=request_json,
                        headers=d.headers,
                        timeout=self.client_timeout,
                    ) as response:
                        res_json = await response.json()
                        if res_json["handle_download"]:
                            return d
                except Exception as e:
                    self.log.error(f"get_downloader could not get response: {type(e).__name__}: {e}")
        return None
```

```python
async def download_file(
    data_store: DataStore,
    target_filename_path: Path,
    store_id: bytes32,
    root_hash: bytes32,
    generation: int,
    server_info: ServerInfo,
    proxy_url: str | None,
    downloader: PluginRemote | None,
    timeout: aiohttp.ClientTimeout,
    client_foldername: Path,
    timestamp: int,
    log: logging.Logger,
    grouped_by_store: bool,
    group_downloaded_files_by_store: bool,
    max_delta_file_size: int,
) -> bool:
    if target_filename_path.exists():
        return True
    filename = get_delta_filename(store_id, root_hash, generation, grouped_by_store)

    if downloader is None:
        # use http downloader - this raises on any error
        try:
            await http_download(
                target_filename_path, filename, proxy_url, server_info, timeout, log, max_delta_file_size
            )
        except (asyncio.TimeoutError, aiohttp.ClientError, MaxDeltaFileSizeExceededError):
            new_server_info = await data_store.server_misses_file(store_id, server_info, timestamp)
            log.info(
                f"Failed to download {filename} from {new_server_info.url}."
                f"Miss {new_server_info.num_consecutive_failures}."
            )
            log.info(f"Next attempt from {new_server_info.url} in {new_server_info.ignore_till - timestamp}s.")
            return False
        return True

    log.info(f"Using downloader {downloader} for store {store_id.hex()}.")
    request_json = {
        "url": server_info.url,
        "client_folder": str(client_foldername),
        "filename": filename,
        "group_files_by_store": group_downloaded_files_by_store,
        "max_delta_file_size": max_delta_file_size,
    }
    try:
        async with aiohttp.ClientSession() as session:
            async with session.post(
                downloader.url + "/download",
                json=request_json,
                headers=downloader.headers,
                timeout=timeout,
            ) as response:
                res_json = await response.json()
                assert isinstance(res_json["downloaded"], bool)
                return res_json["downloaded"]
    except (asyncio.TimeoutError, aiohttp.ClientError) as e:
        log.error(f"download_file could not get response from plugin {downloader}: {type(e).__name__}: {e}")
        return False
```

```python
        self,
```
