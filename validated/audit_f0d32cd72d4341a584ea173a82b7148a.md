### Title
Unbounded Python recursion in offer/puzzle-driver matching allows a malicious offer to crash a wallet (`chia/wallet/outer_puzzles.py`, `chia/wallet/trading/offer.py`)

### Summary
`Offer.from_bech32()` / `Offer.from_spend_bundle()` and `Offer._get_offered_coins()` call `match_puzzle()` on every coin's puzzle reveal in an untrusted offer file before any CLVM cost metering is applied. `match_puzzle()` dispatches to outer-puzzle drivers (`CATOuterPuzzle`, `SingletonOuterPuzzle`, `OwnershipOuterPuzzle`, `MetadataOuterPuzzle`, `CROuterPuzzle`) whose `match()`/`get_inner_puzzle()`/`get_inner_solution()` methods recursively call themselves through the `also` chain for each nested puzzle layer, with no depth limit, similar in spirit to TDengine's unbounded UDF nested-query crash.

### Finding Description
`match_puzzle()` in [1](#0-0)  iterates the `driver_lookup` and invokes each driver's `match()` on an `UnknownPuzzle`. Each outer-puzzle driver's `match`, `get_inner_puzzle`, and `get_inner_solution` recurse into `self._match(...)`, `self._get_inner_puzzle(...)`, or `self._get_inner_solution(...)` whenever the constructed `PuzzleInfo` has an `also` layer, e.g. in `CATOuterPuzzle`: [2](#0-1) , `OwnershipOuterPuzzle`: [3](#0-2) , `MetadataOuterPuzzle`: [4](#0-3) , and `CROuterPuzzle`: [5](#0-4) . `UnknownPuzzle._uncurry_result`/`.mod`/`.curried_args` themselves rely on `uncurry_puzzle()`/`Program.uncurry()`, which is Python-recursion-free per layer but the *outer-puzzle driver chain itself* has no bound on the number of `also` layers it will traverse.

This is directly exercised by `Offer._get_offered_coins()`, which is called from offer construction/parsing paths and runs `match_puzzle`, `get_inner_puzzle`, and `get_inner_solution` on every coin spend in the offer bundle before any signature or full CLVM cost-metered execution occurs: [6](#0-5) . `Offer.from_spend_bundle()` similarly calls `match_puzzle` on every `coin_spend.puzzle_reveal` while reconstructing an offer from a spend bundle: [7](#0-6) .

A malicious offer counterparty can construct a puzzle reveal with hundreds/thousands of nested outer-puzzle layers (CAT-in-CAT-in-CAT, or CR/ownership/metadata layers wrapped many times), each layer parsed as a fresh `also` in `PuzzleInfo`. Because Python's default recursion limit (1000) is not raised or checked anywhere in the codebase (`sys.setrecursionlimit`/`RecursionError` handling do not appear anywhere), sufficiently deep nesting causes a `RecursionError` deep inside the wallet process, which is not caught by any of these driver methods, when a wallet user merely inspects or attempts to process the offer — not necessarily accepts/signs it. This happens outside the CLVM cost-metered execution path, so `MAX_BLOCK_COST_CLVM`/`max_tx_clvm_cost` protections do not apply.

### Impact Explanation
This is a spend-triggered/offer-triggered halt of wallet transaction processing: an unhandled `RecursionError` propagating from offer-parsing code can crash the wallet RPC worker/thread handling the request, denying service to that wallet (Medium severity, matches the CVSS profile of the TDengine crash-on-nested-input bug: Availability impact only, no confidentiality/integrity impact, low attack complexity, no privileges required to send an offer file to a counterparty).

### Likelihood Explanation
Likelihood is moderate: an attacker only needs to author an offer file (a JSON/bech32-encoded spend bundle) with many nested outer-puzzle layers and share it with a victim wallet user (e.g., via a trade website, chat, or NFT marketplace flow) — no on-chain broadcast, signature validity, or mempool acceptance is required, since the vulnerable code runs during local offer parsing before any consensus-level validation.

### Recommendation
- Add an explicit maximum nesting depth (or iterative rewrite) for `match_puzzle`/`get_inner_puzzle`/`get_inner_solution` traversal across `chia/wallet/outer_puzzles.py` and all outer-puzzle driver implementations (`CATOuterPuzzle`, `SingletonOuterPuzzle`, `OwnershipOuterPuzzle`, `MetadataOuterPuzzle`, `CROuterPuzzle`).
- Reject/short-circuit offers whose puzzle reveals exceed a sane layer count before calling `Offer._get_offered_coins()` or `Offer.from_spend_bundle()`.
- Catch `RecursionError` at the offer-parsing entry points (`Offer.from_bech32`, `Offer.from_spend_bundle`, trade manager offer-summary RPC handlers) and convert it into a normal validation error instead of crashing the process.

### Proof of Concept
Conceptual PoC (not executed, given ask-only/read-only access):
1. Build an inner puzzle `P0` (e.g. `1` — accept-anything).
2. Repeatedly wrap it N times (N ≈ 2000) alternating `construct_cat_puzzle(CAT_MOD, tail, Pi)` and/or CR/ownership/metadata layer curries, each layer matched by a corresponding outer-puzzle driver in `driver_lookup`.
3. Create a coin spend using the final wrapped puzzle `PN` as `puzzle_reveal`, with a solution shaped so each layer's `also` matches successfully to keep recursing.
4. Package this coin spend into a `WalletSpendBundle` and build an `Offer` via `Offer.from_spend_bundle()` (or serialize/deserialize via `Offer.from_bech32`) and send it to a victim.
5. Victim wallet calls into `Offer._get_offered_coins()`/`match_puzzle()` while inspecting/summarizing the offer, triggering deep Python recursion through `CATOuterPuzzle.match`/`get_inner_puzzle`/`get_inner_solution` (and other drivers) until `RecursionError` is raised, crashing the wallet request handler.

Note: I was unable to fully verify the exact wallet RPC entry point (`get_offer_summary` in `chia/wallet/trade_manager.py` / `chia/wallet/wallet_rpc_api.py`) that a user calls before deciding to accept an offer, due to tool-call limits reached before reading those files. This should be confirmed by a Devin agent with full file access to establish the precise reachable RPC surface (e.g., whether `get_offer_summary` is invoked automatically on offer receipt in GUI/CLI flows, strengthening the "unprivileged offer counterparty" reachability claim).

    def _get_offered_coins(self) -> dict[bytes32 | None, list[Coin]]:
        offered_coins: dict[bytes32 | None, list[Coin]] = {}

        cost_left = INFINITE_COST
        for parent_spend in self._bundle.coin_spends:
            coins_for_this_spend: list[Coin] = []

            parent_puzzle: UnknownPuzzle = UnknownPuzzle(known_program=parent_spend.puzzle_reveal)
            parent_solution = Program.from_serialized(parent_spend.solution)
            additions: list[Coin] = self._additions[parent_spend.coin]

            puzzle_driver = match_puzzle(parent_puzzle)
            if puzzle_driver is not None:
                asset_id = create_asset_id(puzzle_driver)
                inner_puzzle: Program | None = get_inner_puzzle(puzzle_driver, parent_puzzle, parent_solution)
                inner_solution: Program | None = get_inner_solution(puzzle_driver, parent_solution)
                assert inner_puzzle is not None and inner_solution is not None

                # We're going to look at the conditions created by the inner puzzle
                puzzle_cost, conditions = inner_puzzle.run_with_cost(cost_left, inner_solution)
                assert cost_left >= puzzle_cost
                cost_left -= puzzle_cost
                expected_num_matches: int = 0
                offered_amounts: list[int] = []
                for condition in conditions.as_iter():
                    if condition.first() == 51 and condition.rest().first() == OFFER_MOD_HASH:
                        expected_num_matches += 1
                        offered_amounts.append(condition.rest().rest().first().as_int())

                # Start by filtering additions that match the amount
                matching_spend_additions = [a for a in additions if a.amount in offered_amounts]

                if len(matching_spend_additions) == expected_num_matches:
                    coins_for_this_spend.extend(matching_spend_additions)
                # We didn't quite get there so now lets narrow it down by puzzle hash
                else:
                    # If we narrowed down too much, we can't trust the amounts so start over with all additions
                    if len(matching_spend_additions) < expected_num_matches:
                        matching_spend_additions = additions
                    matching_spend_additions = [
                        a
                        for a in matching_spend_additions
                        if a.puzzle_hash == construct_puzzle(puzzle_driver, OFFER_MOD).get_tree_hash()
                    ]
                    if len(matching_spend_additions) == expected_num_matches:
                        coins_for_this_spend.extend(matching_spend_additions)
                    else:
                        raise ValueError("Could not properly guess offered coins from parent spend")
            else:
                # It's much easier if the asset is bare XCH
                asset_id = None
                coins_for_this_spend.extend([a for a in additions if a.puzzle_hash == OFFER_MOD_HASH])

            # We only care about unspent coins
            coins_for_this_spend = [c for c in coins_for_this_spend if c not in self._bundle.removals()]

            if coins_for_this_spend != []:
                offered_coins.setdefault(asset_id, [])
                offered_coins[asset_id].extend(coins_for_this_spend)
        return offered_coins

    @classmethod
    def from_spend_bundle(cls, bundle: WalletSpendBundle) -> Offer:
        # Because of the `to_spend_bundle` method, we need to parse the dummy CoinSpends as `requested_payments`
        requested_payments: dict[bytes32 | None, list[NotarizedPayment]] = {}
        driver_dict: dict[bytes32, PuzzleInfo] = {}
        leftover_coin_spends: list[CoinSpend] = []
        for coin_spend in bundle.coin_spends:
            driver = match_puzzle(UnknownPuzzle(known_program=coin_spend.puzzle_reveal))
            if driver is not None:
                asset_id = create_asset_id(driver)
                assert asset_id is not None
                driver_dict[asset_id] = driver
            else:
                asset_id = None
            if coin_spend.coin.parent_coin_info == bytes32.zeros:
                notarized_payments: list[NotarizedPayment] = []
                for payment_group in Program.from_serialized(coin_spend.solution).as_iter():
                    nonce = bytes32(payment_group.first().as_atom())
                    payment_args_list = payment_group.rest().as_iter()
                    notarized_payments.extend(
                        [NotarizedPayment.from_condition_and_nonce(condition, nonce) for condition in payment_args_list]
                    )

                requested_payments[asset_id] = notarized_payments
            else:
                leftover_coin_spends.append(coin_spend)

        return cls(
            requested_payments, WalletSpendBundle(leftover_coin_spends, bundle.aggregated_signature), driver_dict
        )
