### Title
Lossy UTF-8 decoding of diff buffers silently corrupts committed content during partial-line staging - ([File: app/src/lib/git/diff.ts])

### Summary
`diffFromRawDiffOutput` unconditionally decodes the raw diff `Buffer` returned by `git diff`/`git log --patch-with-raw` as UTF-8, discarding the original byte stream. That decoded, potentially-lossy string is then used verbatim by `formatPatch`/`formatPatchToDiscardChanges` to build the patch that is fed to `git apply --cached`, meaning any byte sequence that isn't valid UTF-8 in the touched file is permanently replaced before being written into the git index/working tree.

### Finding Description
Desktop retrieves diffs as raw buffers (`encoding: 'buffer'`) from `git diff`/`git log`: [1](#0-0) 

The raw buffer is then decoded assuming UTF-8, with an explicit comment acknowledging this is a known simplification: [2](#0-1) 

`Buffer.toString('utf-8')` is lossy for any byte sequence that is not valid UTF-8 (e.g., files encoded in Shift-JIS, GBK, Latin-1, or any text file containing byte sequences that only coincidentally aren't flagged as "binary" by Git's heuristic) — invalid sequences are silently replaced with the U+FFFD replacement character, and the original bytes cannot be recovered from the resulting string.

The decoded, already-corrupted `line.text` values are stored as hunk lines and later re-emitted verbatim when constructing a partial-commit patch — including for **context lines and lines the user did not even select**: [3](#0-2) 

That patch string is passed as `stdin` to `git apply --cached`, so whatever bytes are in `line.text` (now containing replacement characters instead of the true bytes) become the bytes written into the git index/object database: [4](#0-3) 

The same lossy path is used by `discardChangesFromSelection`, which rewrites the *working directory* file via `git apply` from the same corrupted `line.text`: [5](#0-4) [6](#0-5) 

Only the fully-binary case (detected by Git's own "Binary files differ" marker, handled in `diff-parser.ts`) is excluded from this path; a text file containing occasional non-UTF-8 byte sequences (common with legacy encodings, or a file crafted specifically to contain invalid UTF-8 continuation bytes) is treated as "text" by Git and flows through the lossy decode/re-encode round trip.

### Impact Explanation
This breaks the invariant that Desktop's partial-commit/discard feature only touches the lines the user explicitly selects and leaves everything else byte-for-byte identical. Because the *entire* buffer is decoded through a single lossy UTF-8 pass before any line is written back out, unselected context lines and untouched regions of the file can also be corrupted (bytes replaced with U+FFFD) once any partial stage or partial discard operation on that file is performed. This is a silent corruption of what the user commits/pushes: the object written to the index and eventually pushed to a remote will not match either the file the user saw on disk or the diff they thought they were selectively applying, and there is no warning shown to the user (no encoding-mismatch banner, no confirmation) — only the pre-existing, unrelated `parseLineEndingsWarning` covers CRLF/LF changes, not encoding.

### Likelihood Explanation
Requires only that the attacker-influenced repository (cloned/fetched) contain a text file using a non-UTF-8 encoding or embedding invalid UTF-8 byte sequences that Git does not classify as binary, and that the victim performs a partial-line stage or partial discard through Desktop's normal UI on that file — an ordinary workflow, not a contrived one. No elevated privileges, local access, or social engineering beyond "user works with a file from the cloned repo" is needed.

### Recommendation
Preserve the original bytes end-to-end for partial-patch operations instead of decoding the whole diff to a JS string: either detect the file's actual encoding (or preserve raw byte ranges per hunk/line) and reconstruct patches from the original buffer offsets, or explicitly detect invalid UTF-8 in `diffFromRawDiffOutput`/`isDiffTooLarge` and fall back to disabling partial-line staging (treat as `Unrenderable`/binary-like) for such files, surfacing a clear warning to the user rather than silently applying a lossy re-encoded patch.

### Proof of Concept
1. Attacker publishes a repository containing `notes.txt` encoded in Shift-JIS (valid non-UTF-8 bytes that Git still treats as text, not binary).
2. Victim clones the repo in GitHub Desktop, edits `notes.txt`, and uses the "select lines to stage" UI to stage only a subset of the changed lines.
3. `getWorkingDirectoryDiff` reads the raw diff buffer, and `diffFromRawDiffOutput` decodes it via `Buffer.toString('utf-8')` [2](#0-1) , replacing the Shift-JIS byte sequences with U+FFFD in `line.text` for every line, including unselected context lines.
4. `formatPatch` reproduces these corrupted `line.text` values verbatim for context/unselected lines [7](#0-6) , and `applyPatchToIndex` applies this patch to the index via `git apply --cached` [4](#0-3) .
5. The resulting staged/committed blob differs from the original file bytes even in regions the victim never touched, and Desktop shows no warning — the corrupted content can be pushed as-is.

```typescript
function diffFromRawDiffOutput(output: Buffer): IRawDiff {
  // for now we just assume the diff is UTF-8, but given we have the raw buffer
  // we can try and convert this into other encodings in the future
```

```typescript
export function formatPatchToDiscardChanges(
  filePath: string,
  diff: ITextDiff,
  selection: DiffSelection
): string | null {
  let patch = ''

  diff.hunks.forEach((hunk, hunkIndex) => {
    let hunkBuf = ''

    let oldCount = 0
    let newCount = 0

    let anyAdditionsOrDeletions = false

    hunk.lines.forEach((line, lineIndex) => {
      const absoluteIndex = hunk.unifiedDiffStart + lineIndex

      // We write our own hunk headers
      if (line.type === DiffLineType.Hunk) {
        return
      }

      // Context lines can always be let through, they will
      // never appear for new files.
      if (line.type === DiffLineType.Context) {
        hunkBuf += `${line.text}\n`
        oldCount++
        newCount++
      } else if (selection.isSelected(absoluteIndex)) {
        // Reverse the change (if it was an added line, treat it as removed and vice versa).
        if (line.type === DiffLineType.Add) {
          hunkBuf += `-${line.text.substring(1)}\n`
          newCount++
        } else if (line.type === DiffLineType.Delete) {
          hunkBuf += `+${line.text.substring(1)}\n`
          oldCount++
        } else {
          assertNever(line.type, `Unsupported line type ${line.type}`)
        }

        anyAdditionsOrDeletions = true
      } else {
        if (line.type === DiffLineType.Add) {
          // An unselected added line will stay in the file after discarding the changes,
          // so we just print it untouched on the diff.
          oldCount++
          newCount++
          hunkBuf += ` ${line.text.substring(1)}\n`
        } else if (line.type === DiffLineType.Delete) {
          // An unselected removed line has no impact on this patch since it's not
          // found on the current working copy of the file, so we can ignore it.
          return
        } else {
          // Guarantee that we've covered all the line types.
          assertNever(line.type, `Unsupported line type ${line.type}`)
        }
      }

      if (line.noTrailingNewLine) {
        hunkBuf += '\\ No newline at end of file\n'
      }
    })
```

```typescript
export async function discardChangesFromSelection(
  repository: Repository,
  filePath: string,
  diff: ITextDiff,
  selection: DiffSelection
) {
  const patch = formatPatchToDiscardChanges(filePath, diff, selection)

  if (patch === null) {
    // When the patch is null we don't need to apply it since it will be a noop.
    return
  }

  const args = ['apply', '--unidiff-zero', '--whitespace=nowarn', '-']

  await git(args, repository.path, 'discardChangesFromSelection', {
    stdin: patch,
  })
}
```
