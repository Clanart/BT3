### Title
Unmetered `Pubkey::create_program_address` calls in `translate_signers` during CPI (`invoke_signed`) allow underpriced compute for PDA re-derivation - ([File: program-runtime/src/cpi.rs])

### Summary
`translate_signers` (called from `cpi_common` on every `invoke_signed`) invokes `Pubkey::create_program_address` directly, once per signer-seeds entry, without charging `create_program_address_units`. This is inconsistent with the dedicated `sol_create_program_address`/`sol_try_find_program_address` syscalls, which explicitly charge `create_program_address_units` per call via `invoke_context.compute_meter.consume_checked(cost)`.

### Finding Description
In `program-runtime/src/cpi.rs`, `translate_signers` iterates over up to `MAX_SIGNERS` signer-seed groups (each with up to `MAX_SEEDS` seeds) and calls `Pubkey::create_program_address(&seeds_bytes, program_id)` directly for each one: [1](#0-0) 

This function is invoked from `cpi_common`, the shared entry point for `SyscallInvokeSignedRust`/`SyscallInvokeSignedC`: [2](#0-1) 

`cpi_common` only ever charges the flat `invoke_units` cost via `consume_checked(amount)` before calling `translate_signers` - there is no additional charge proportional to the number of signers or the cost of the PDA derivations performed inside `translate_signers`.

By contrast, the standalone `SyscallCreateProgramAddress` and `SyscallTryFindProgramAddress` syscalls explicitly charge `create_program_address_units` for every `Pubkey::create_program_address` invocation, including retries in the `try_find` loop: [3](#0-2) [4](#0-3) 

`Pubkey::create_program_address` performs a SHA256 hash over the concatenated seed bytes plus the program ID and PDA marker, so this is genuine CPU work, not a trivial computation. An attacker-controlled program can supply `signers_seeds_len` up to `MAX_SIGNERS`, each with up to `MAX_SEEDS` seeds of maximal length, on every `invoke_signed` call, causing `MAX_SIGNERS` SHA256-based PDA derivations to occur inside `translate_signers` while only the flat `invoke_units` cost is charged for the whole CPI. This is a real compute-cost accounting gap: the cost model correctly bills `create_program_address_units` when the seed-derivation logic is reached via the explicit syscalls, but bills nothing extra for the same logic when reached via CPI signer translation.

### Impact Explanation
This is a compute-unit underpricing issue: the actual CPU cost of hashing (SHA256 over up to `MAX_SIGNERS * MAX_SEEDS` maximal seeds per CPI call) is not reflected in the CU charged, degrading the CU-to-CPU-time invariant that Agave's cost model relies on (`COST_UPPER_BOUND`). This falls into the "materially underpriced compute" bounty category rather than memory safety or privilege escalation.

### Likelihood Explanation
This is trivially reachable by any unprivileged program: it only requires calling `invoke_signed` with the maximum number of signer-seed groups and maximal seed lengths on every CPI, which is fully within an attacker's control (no special privileges, no validator/leader control needed). It is deterministic and repeatable on every invocation.

### Recommendation
Charge `create_program_address_units` for each PDA derivation performed inside `translate_signers` (i.e., once per signer-seeds entry, mirroring the charge already applied in `SyscallCreateProgramAddress`), before or as part of the loop in `program-runtime/src/cpi.rs`'s `translate_signers`, so the CPI-triggered PDA derivation cost is accounted for identically to the standalone syscalls.

### Proof of Concept
Add a unit test in `program-runtime/src/cpi.rs` alongside `test_translate_signers` that:
1. Sets `invoke_context.compute_meter` to a known remaining budget.
2. Calls `translate_signers` with `MAX_SIGNERS` signer-seed groups, each containing `MAX_SEEDS` seeds of `MAX_SEED_LEN` bytes.
3. Reads `invoke_context.compute_meter.remaining()` afterward and asserts the consumed CU equals (or includes) `create_program_address_units * MAX_SIGNERS` — the assertion will fail, showing zero CU was charged for the `MAX_SIGNERS` SHA256-based derivations, in contrast to an equivalent test calling `SyscallCreateProgramAddress::rust` `MAX_SIGNERS` times, which does charge `create_program_address_units` each time (as shown in `test_create_program_address`/`test_find_program_address`).
