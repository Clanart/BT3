### Title
Silent, unconfirmed rewrite of the trusted `origin` remote URL from a GitHub API response - (File: `app/src/lib/stores/updates/update-remote-url.ts`)

### Summary
GitHub Desktop periodically re-resolves a local repository's associated GitHub repository by re-parsing the *current* `origin` remote URL, querying `GET /repos/{owner}/{name}` again, and — if the API's `clone_url` differs from what Desktop last saw — silently rewriting the local Git remote to the new URL via `gitStore.setRemoteURL()`. This mirrors the report's core invariant break: a value the rest of the app treats as durable/"final" (the trusted push/fetch destination) is actually derived from state that is fully controlled by a third party (here, GitHub API data reflecting an owner's repo rename/transfer) and can silently mutate without the same explicit user gate (e.g., `cancel()`/confirmation) that governs comparable state changes elsewhere in the app.

### Finding Description
- `repositoryWithRefreshedGitHubRepository` re-derives the owner/name to query from the repository's *current* remote URL every refresh cycle, not from a stable repository ID: [1](#0-0) [2](#0-1) 

- It then fetches the repository afresh from the API and unconditionally calls `updateRemoteUrl` with the freshly returned `IAPIFullRepository`: [3](#0-2) 

- `updateRemoteUrl` compares the new `clone_url` to the previously-known GitHub `cloneURL` and, if the protocol scheme matches and the local remote had not manually diverged from what Desktop last knew, it silently calls `gitStore.setRemoteURL(...)` — with no user prompt, confirmation dialog, or ownership/host-pinning check beyond a protocol string comparison: [4](#0-3) 

- This is invoked from ordinary, frequent, non-privileged flows such as fetch/push/pull refresh paths (`withRefreshedGitHubRepository`, `_fetch`, `performPush` → `_refreshRepository`), meaning it runs automatically in the background: [5](#0-4) [6](#0-5) 

**Why existing guards don't stop the path:** The only checks in `updateRemoteUrl` are (1) protocol equality between old/new URL and (2) that the local remote's URL still equals the last-known `cloneURL` (i.e., the user hasn't manually repointed it). Neither check validates that the new `clone_url` still belongs to the same repository identity/owner the user originally trusted — it only guards against Desktop clobbering a manual user edit, not against the GitHub-reported destination changing entirely (e.g., after a repository rename/transfer performed by whoever currently has admin rights on that specific repository — not the Desktop user, and not requiring any local/physical access to the victim's machine).

### Impact Explanation
If the repository owner (potentially a compromised or malicious collaborator with admin rights on that GitHub repo — an entity outside the victim's control, satisfying the "attacker controls a GitHub API object" criterion) renames or transfers the repository, GitHub's API will return a different `clone_url` on the next background refresh. Desktop will then silently repoint the user's `origin` remote to that new location without any prompt. Consequences:
- Silent corruption of the destination for the user's future `git push` operations — commits/branches the user believes are going to the original repository are instead sent to a different remote path/owner, potentially exposing private code or diverting contributions.
- Because this happens transparently during routine fetch/push/refresh, the user has no natural opportunity to notice or object, unlike explicit actions such as "Clone Again" that surface a URL to the user.

### Likelihood Explanation
Low-to-moderate. It requires an actor with legitimate write/admin access to the specific GitHub repository the user has cloned (not access to the user's machine, not stolen credentials, not social engineering of the Desktop user) to rename or transfer that repository — a normal, permitted GitHub action. Given Desktop's default periodic/background refresh behavior on fetch/push, this condition, once true, is triggered automatically and silently, similar to how the Nouns DAO bug requires an admin config change (`GRACE_PERIOD`) that is rare but plausible and, once it occurs, automatically flips previously-final application state without further user consent.

### Recommendation
Do not silently rewrite the local remote based on API data. When `updateRemoteUrl` detects a `clone_url` change relative to the previously-known GitHub repository, surface a confirmation prompt/banner (similar to the existing publish/relocate flows) showing the old and new remote URLs and requiring explicit user approval before calling `setRemoteURL`. Additionally, validate that the new `clone_url`'s owner/name still resolves to the same GitHub repository ID (`node_id`/numeric `id`) previously associated with the local `GitHubRepository`, rather than relying solely on protocol/URL string comparisons.

### Proof of Concept
1. User clones `https://github.com/victim-owner/project` and works normally; Desktop stores `GitHubRepository.cloneURL` accordingly (see `repositories-store.ts` upsert logic referenced above).
2. The GitHub repository's current owner (who has legitimate admin rights on that repo, not on the victim's machine) renames or transfers the repository, so `GET /repos/victim-owner/project` at GitHub now returns `clone_url: https://github.com/attacker-owner/project-renamed`.
3. On the user's next background fetch/push (`performFetch` → `withRefreshedGitHubRepository` → `repositoryWithRefreshedGitHubRepository`), Desktop re-parses the current `origin` URL, queries the API, and calls:
   `updateRemoteUrl(gitStore, oldGitHubRepository, { clone_url: 'https://github.com/attacker-owner/project-renamed', ... })`
4. Because the protocol matches and the local remote URL still equals the old known `cloneURL`, `updateRemoteUrl` silently executes `gitStore.setRemoteURL('origin', 'https://github.com/attacker-owner/project-renamed')` — confirmed by the passing test case "updates the repository's remote url when the github url changes": [7](#0-6) 
5. The user's subsequent `git push` now targets `attacker-owner/project-renamed` with no prompt or notification.

/** Try to use the list of users and a remote URL to guess a GitHub repository. */
export function matchGitHubRepository(
  accounts: ReadonlyArray<Account>,
  remote: string
): IMatchedGitHubRepository | null {
  for (const account of accounts) {
    const htmlURL = getHTMLURL(account.endpoint)
    const { hostname } = URL.parse(htmlURL)
    const parsedRemote = parseRemote(remote)

    if (parsedRemote !== null && hostname !== null) {
      if (parsedRemote.hostname.toLowerCase() === hostname.toLowerCase()) {
        return { name: parsedRemote.name, owner: parsedRemote.owner, account }
      }
    }
  }

  return null
}

import { IAPIRepository } from '../../api'
import { GitStore } from '../git-store'
import { urlMatchesRemote } from '../../repository-matching'
import * as URL from 'url'
import { GitHubRepository } from '../../../models/github-repository'

export async function updateRemoteUrl(
  gitStore: GitStore,
  gitHubRepository: GitHubRepository,
  apiRepo: IAPIRepository
): Promise<void> {
  // I'm not sure when these early exit conditions would be met. But when they are
  // we don't have enough information to continue so exit early!
  if (gitStore.defaultRemote === null) {
    return
  }

  const remoteUrl = gitStore.defaultRemote.url
  const updatedRemoteUrl = apiRepo.clone_url
  const urlsMatch = urlMatchesRemote(updatedRemoteUrl, gitStore.defaultRemote)

  // Verify that protocol hasn't changed. If it has we don't want
  // to alter the protocol in case they are relying on a specific one.
  // If protocol is null that implies the url is a ssh url
  // of the format git@github.com:octocat/Hello-World.git, which
  // can't be parsed by URL.parse. In this case we assume the user
  // manually configured their remote to use this format and we don't
  // want to change what they've done just to be safe
  const parsedRemoteUrl = URL.parse(remoteUrl)
  const parsedUpdatedRemoteUrl = URL.parse(updatedRemoteUrl)
  const protocolsMatch =
    parsedRemoteUrl.protocol !== null &&
    parsedUpdatedRemoteUrl.protocol !== null &&
    parsedRemoteUrl.protocol === parsedUpdatedRemoteUrl.protocol

  // Check if the default remote url has been manually changed from the
  // clone url retrieved from the GitHub API previously
  const remoteUrlUnchanged =
    gitStore.defaultRemote &&
    urlMatchesRemote(gitHubRepository.cloneURL, gitStore.defaultRemote)

  if (protocolsMatch && remoteUrlUnchanged && !urlsMatch) {
    await gitStore.setRemoteURL(gitStore.defaultRemote.name, updatedRemoteUrl)
  }
}
