### Title
Unauthenticated hang via quadratic Lagrange interpolation triggered by crafted `ThresholdKeys` bytes - ([File: crypto/dkg/src/lib.rs])

### Summary
The external report (CVE-2018-2565) describes a denial of service: an attacker with network access can cause a hang or repeatable crash of the server. The analog in Serai is an attacker-controlled input that drives `ThresholdKeys::new` into a resource-exhausting computation: computing the group key performs `t` independent Lagrange interpolation-factor evaluations, each `O(t)`, giving `O(t²)` field operations with `t` taken directly from untrusted serialized bytes in `ThresholdKeys::read`.

### Finding Description
`ThresholdKeys::read` parses `t`, `n`, `i`, the interpolation method, the secret share, and `n` verification-share points entirely from an untrusted reader. `t` and `n` are `u16` values supplied by the sender, bounded only by `t <= n <= 65535` via `ThresholdParams::new`.

`ThresholdKeys::read` then calls `ThresholdKeys::new`, which derives the group key as:

```rust
let t = (1 ..= params.t()).map(Participant).collect::<Vec<_>>();
let group_key =
  t.iter().map(|i| verification_shares[i] * interpolation.interpolation_factor(*i, &t)).sum();
```
(crypto/dkg/src/lib.rs:376-378)

`interpolation_factor` for `Interpolation::Lagrange` iterates over every entry of `included` (length `t`) performing field multiplications and a final inversion:

```rust
for l in included {
  if i == *l { continue; }
  let share = F::from(u64::from(u16::from(*l)));
  num *= share;
  denom *= share - i_f;
}
num * denom.invert().unwrap()
```
(crypto/dkg/src/lib.rs:229-247)

Total work is therefore `t²` field multiplications plus `t` field inversions. With `t = n = 65535` — both fully attacker-chosen — that is ~4.3·10⁹ field multiplications and 65535 inversions per single call to `read`, an effective hang of the calling thread, matching the "hang or frequently repeatable crash" DoS class of the CVE.

The same unbounded `n` also drives `ThresholdKeys::read` to allocate and deserialize `n` group elements (`Vec::with_capacity(n)` / `HashMap` of `n` points, plus `n` scalars for `Interpolation::Constant`), and later `view()`/`sign()` cost scales with the same attacker-chosen set size.

### Impact Explanation
Any component that deserializes `ThresholdKeys` from a peer-, network-, or disk-supplied buffer (`ThresholdKeys::read`, `ThresholdKeys::deserialize`) can be made to burn CPU for an unbounded, attacker-controlled amount of time on a single small input (~4 MB). Repeated submissions produce a repeatable denial of service of the signing/DKG host — the exact impact class (loss of availability) described in the CVE. No secret material is required; the `t`/`n` fields and verification-share bytes are all public inputs under the attacker's control.

### Likelihood Explanation
Reachability requires only that attacker-influenced bytes reach `ThresholdKeys::read`, which is an explicitly exposed untrusted-input sink. The payload is trivially constructible: header with `t = n = 0xFFFF`, `i = 1`, interpolation tag `1` (Lagrange), followed by `n` valid point encodings and a scalar. All validation (`t <= n`, participant indexes `1..=n`, deduplicated implicit set `1..=t`) passes, so the `O(t²)` loop is always executed. No timing, privilege, or cooperation constraints exist.

### Recommendation
Impose a documented upper bound on `t`/`n` in `ThresholdKeys::read`/`ThresholdKeys::new` (e.g. a few hundred participants, well above any realistic multisig), or derive the group key once during DKG and store it rather than recomputing an `O(t²)` Lagrange aggregation on every deserialization. At minimum, compute the group key lazily/asynchronously so malformed parameter sets cannot synchronously stall the caller.

### Proof of Concept
```rust
use std::io::Cursor;
use ciphersuite::Ciphersuite;
use dkg::ThresholdKeys;
// Any in-scope Ciphersuite, e.g. Ristretto:
// use ciphersuite::Ristretto as C;

fn poc() {
  let n: u16 = u16::MAX; // 65535, attacker chosen
  let mut buf = vec![];
  // C::ID header matching ThresholdKeys::write
  buf.extend_from_slice(&(C::ID.len() as u32).to_le_bytes());
  buf.extend_from_slice(C::ID);
  buf.extend_from_slice(&n.to_le_bytes());        // t = 65535
  buf.extend_from_slice(&n.to_le_bytes());        // n = 65535
  buf.extend_from_slice(&1u16.to_le_bytes());     // i = 1
  buf.push(1);                                    // Interpolation::Lagrange
  buf.extend_from_slice(C::F::ONE.to_repr().as_ref()); // secret_share
  for _ in 0 .. n {                                // n verification shares
    buf.extend_from_slice(C::generator().to_bytes().as_ref());
  }
  // Triggers ~4.3e9 field muls + 65535 inversions inside ThresholdKeys::new
  let _ = ThresholdKeys::<C>::read(&mut Cursor::new(buf));
}
```
