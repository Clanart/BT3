### Title
Loss of MGP Emissions When Pool `lpSupply == 0` in `MasterMagpie.updatePool()` - (File: `rewards/MasterMagpie.sol`)

### Summary
`MasterMagpie.updatePool()` skips reward accrual entirely whenever a pool's staked supply is zero, silently discarding the MGP emissions that should have accrued for that time window, exactly mirroring the reported `LiquidityGauge._checkpoint()` bug class where a zero-total-supply division/branch causes rewards to be dropped instead of preserved for later distribution.

### Finding Description
`updatePool()` computes the pool's staked supply via `_calLpSupply()` and, if it is zero, advances `lastRewardTimestamp` and returns without ever computing `mgpReward` or updating `accMGPPerShare`: [1](#0-0) 

Compare this to `BaseRewardPool._provisionReward()`, which correctly handles the analogous zero-supply case for bonus-reward tokens by *queuing* the reward (`rewardInfo.queuedRewards += _amountReward`) so it can be distributed to the next depositor instead of being lost: [2](#0-1) 

`MasterMagpie.updatePool()` has no such queuing mechanism for MGP. When `lpSupply == 0`, the elapsed time `multiplier = block.timestamp - pool.lastRewardTimestamp` is discarded by resetting `pool.lastRewardTimestamp = block.timestamp` without ever computing `mgpReward = (multiplier * mgpPerSec * pool.allocPoint) / totalAllocPoint`. Because `MGP` is a fixed, pre-minted ERC20 supply held by the protocol (minted once in the constructor, not minted lazily per emission): [3](#0-2) 

the MGP tokens that were nominally "reserved" for the zero-supply period are never credited to `accMGPPerShare` for any past or future staker, and there is no admin-recovery/sweep function anywhere in `MasterMagpie.sol` to reclaim them. The `mgpPerSec` emission rate keeps ticking based on wall-clock time regardless of whether anyone is staked, so any elapsed period with `lpSupply == 0` results in permanently unaccounted-for MGP sitting in the contract, unreachable by any user.

This state is trivially reachable by ordinary unprivileged actions:
1. A pool manager calls `add()` to register a new pool; `lastRewardTimestamp` is set to the current/start timestamp, but the pool has `lpSupply == 0` until the first depositor arrives — any time elapsed before the first `deposit()` call is lost. [4](#0-3) 
2. Any ordinary user can also cause this window to reappear organically by withdrawing 100% of a pool's stake, driving `lpSupply` to 0 until another user deposits again — the emission during that gap is unrecoverable. [5](#0-4) 

### Impact Explanation
This causes permanent, protocol-wide loss of unclaimed MGP yield. Emissions that should have accrued to stakers (or to a future depositor via a queuing mechanism, as is correctly implemented for bonus rewards in `BaseRewardPool`) are simply skipped and become permanently stranded in the contract with no code path to reclaim or redistribute them. This matches the "theft or permanent freezing of unclaimed yield" impact category.

### Likelihood Explanation
High likelihood: any newly created pool naturally has `lpSupply == 0` until its first depositor, and any pool can return to `lpSupply == 0` any time all stakers withdraw — both are routine, unprivileged occurrences that require no special conditions or malicious actors.

### Recommendation
Mirror the queuing pattern already used in `BaseRewardPool._provisionReward()`: when `lpSupply == 0` in `updatePool()`, accumulate the un-distributed `mgpReward` (or the unelapsed emission) into a per-pool "queued" accumulator that gets folded into `accMGPPerShare` once the pool has nonzero `lpSupply` again, instead of discarding it via `pool.lastRewardTimestamp = block.timestamp; return;`.

### Proof of Concept
1. Owner/pool manager calls `add(_allocPoint, _stakingToken, ...)` to register a new pool at time `T0`; `lastRewardTimestamp = T0`.
2. No user deposits for `N` seconds (`lpSupply == 0` the whole time).
3. At `T0 + N`, the first user calls `deposit()`, which triggers `updatePool()` → `_calLpSupply() == 0` (balance not yet transferred in) → the function sets `lastRewardTimestamp = T0 + N` and returns, never computing the `mgpReward` for the `N`-second window.
4. The `N * mgpPerSec * allocPoint / totalAllocPoint` MGP that was allocated to this pool for that period is now permanently unaccounted for — it is never added to `accMGPPerShare`, so no past or future staker can ever claim it, and there is no admin function to recover it.

```text
    function updatePool(address _stakingToken) public whenNotPaused {
        PoolInfo storage pool = tokenToPoolInfo[_stakingToken];
        if (block.timestamp <= pool.lastRewardTimestamp || totalAllocPoint == 0) {
            return;
        }
        uint256 lpSupply = _calLpSupply(_stakingToken);
        if (lpSupply == 0) {
            pool.lastRewardTimestamp = block.timestamp;
            return;
        }        
        uint256 multiplier = block.timestamp - pool.lastRewardTimestamp;
        uint256 mgpReward = (multiplier * mgpPerSec * pool.allocPoint) / totalAllocPoint;
        
        pool.accMGPPerShare = pool.accMGPPerShare + ((mgpReward * 1e12) / lpSupply);
        pool.lastRewardTimestamp = block.timestamp;

        emit UpdatePool(
            _stakingToken,
            pool.lastRewardTimestamp,
            lpSupply,
            pool.accMGPPerShare
        );
    }    
```

```text
    function _provisionReward(uint256 _amountReward, address _rewardToken) internal {
        IERC20(_rewardToken).safeTransferFrom(
            msg.sender,
            address(this),
            _amountReward
        );
        Reward storage rewardInfo = rewards[_rewardToken];
        rewardInfo.historicalRewards =
            rewardInfo.historicalRewards +
            _amountReward;
        if (this.totalStaked() == 0) {
            rewardInfo.queuedRewards += _amountReward;
        } else {
            if (rewardInfo.queuedRewards > 0) {
                _amountReward += rewardInfo.queuedRewards;
                rewardInfo.queuedRewards = 0;
            }
            rewardInfo.rewardPerTokenStored =
                rewardInfo.rewardPerTokenStored +
                (_amountReward * 10**stakingDecimals()) /
                this.totalStaked();
        }
        emit RewardAdded(_amountReward, _rewardToken);
```
