## Analysis

The Derby bug's core pattern — a reward/settlement value computed in aggregate over a batch/period gets attributed incorrectly once the underlying attribution assumption breaks (blacklisted protocol ≠ predictable price) — maps to a concrete misattribution flaw in Hyperbridge's consensus relayer incentive accounting, where reward attribution for an entire batch of independently-verified state updates is collapsed onto a single signer regardless of which message actually produced each result.

### Title
Consensus relayer rewards for an entire batch are attributed only to the first message's signer, allowing reward misattribution to the wrong beneficiary - (File: `modules/pallets/consensus-incentives/src/impls.rs`)

### Summary
`pallet-consensus-incentives` implements `FeeHandler::on_executed`, which is invoked by `pallet-ismp::execute` after processing a batch of ISMP `Message`s submitted through the permissionless, unsigned `handle_unsigned` extrinsic. The relayer account credited for **all** `StateMachineUpdated` events produced by the batch is derived solely from `messages.get(0)` — the signer of the *first* message in the batch — even when the batch contains multiple independent `ConsensusMessage`s for different state machines, each carrying its own distinct signer.

### Finding Description
`handle_unsigned` accepts an arbitrary `Vec<Message>` from anyone (`ensure_none(origin)`), executes them all, and forwards the resulting events to `T::FeeHandler::on_executed`: [1](#0-0) [2](#0-1) 

Inside `on_executed`, the relayer identity is extracted only from `messages[0]`: [3](#0-2) 

The function then iterates over *every* `StateMachineUpdated` event in the whole batch (built from `events`, not scoped per-message), computes `highest_per_state_machine`, and pays `calculate_reward` for each `state_machine_id` found — crediting all of it to the single relayer recovered from `messages[0]`: [4](#0-3) 

`calculate_reward` itself is well-guarded against height rollbacks via the `LastRewardedHeight` watermark (confirmed by `reward_covers_only_unpaid_heights_after_rollback`), so the bug is not in the per-state-machine amount calculation — it is in **who** the aggregate reward is paid to. Since `Message::Consensus.signer` is a per-message field (a signature over that message's own `consensus_proof`, verified independently), each `ConsensusMessage` in a batch can carry a *different* legitimate signer/account. `verify_consensus` authorizes messages independently of the outer `signer` field, so nothing stops a batch from containing several validly-signed `ConsensusMessage`s from different signers for different `state_machine_id`s. `on_executed` nevertheless pays every state machine's reward to whichever signer happened to occupy index 0.

### Impact Explanation
This is a wrong-beneficiary / fund-misallocation bug in the treasury-funded relayer incentive pipeline: `T::Currency::transfer(&TreasuryAccount, &relayer_account, reward, ...)` moves treasury funds to an account that may not correspond to the signer who actually attested to a given state machine's update. Any batch containing more than one `ConsensusMessage` with distinct signers routes 100% of the combined reward (and the accompanying `ReputationAsset` mint) to the index-0 signer, while other signers whose messages produced real `StateMachineUpdated` events for other chains receive nothing for that batch. This is a direct violation of "reward payouts move exactly once and only to the rightful beneficiary."

### Likelihood Explanation
Batching multiple independently-signed `ConsensusMessage`s in a single `handle_unsigned` call requires no special privilege — it is a permissionless, unsigned extrinsic (`ensure_none`), and nothing in `handle_unsigned`, `execute`, or `on_executed` restricts a batch to messages signed by a single account. Any actor able to construct or relay two or more valid consensus proofs (their own plus any other publicly-available, not-yet-committed proof) can trigger this misattribution without needing admin/governance rights, a compromised relayer, or a race condition — only the ordinary act of submitting a multi-message batch.

### Recommendation
Attribute each `StateMachineUpdated` event to the signer of the specific `ConsensusMessage` that produced it (pair events with their originating message index during `execute`/`MessageResult::ConsensusMessage` construction) rather than defaulting the whole batch's rewards to `messages[0]`'s signer.

### Proof of Concept
1. Relayer A holds a valid signing key and observes a valid, publicly verifiable `ConsensusMessage` M2 (proof + signer signature) for state machine B that has not yet been committed on Hyperbridge (e.g., it is still pending in the network / not yet included).
2. Relayer A constructs their own minimal `ConsensusMessage` M1 for a cheap/low-`StateMachinesCostPerBlock` chain A, which they can validly sign themselves.
3. Relayer A submits `handle_unsigned([M1, M2])` in a single unsigned extrinsic.
4. `execute` processes both messages, producing `StateMachineUpdated` events for both state machine A and B.
5. `on_executed` recovers the relayer identity only from `messages[0]` (M1's signer = Relayer A) and pays the combined reward for **both** state machine A and state machine B's advance to Relayer A's account — even though Relayer A's signature never attested to state machine B's update.

	pub fn execute(messages: Vec<Message>) -> Result<Vec<events::Event>, Error<T>> {
		let host = Pallet::<T>::default();

		let message_results = messages
			.iter()
			.map(|msg| handle_incoming_message(&host, msg.clone()))
			.collect::<Result<Vec<_>, _>>()
			.map_err(|err| {
				log::debug!(target: "ismp", "Handling Error {:#?}", err);
				Pallet::<T>::deposit_event(Event::<T>::Errors { errors: vec![err.into()] });
				Error::<T>::InvalidMessage
			})?;

		let messages_with_weights = message_results
			.iter()
			.zip(messages)
			.map(|(result, message)| MessageWithWeight { message, weight: result.weight() })
			.collect::<Vec<_>>();

		let events = message_results
			.into_iter()
			// check that requests will be successfully dispatched
			// so we can not be spammed with failing txs
			.map(|result| match result {
				MessageResult::Request { events, .. } |
				MessageResult::Response { events, .. } |
				MessageResult::Timeout { events, .. } => events,
				MessageResult::ConsensusMessage(events) => events.into_iter().map(Ok).collect(),
				MessageResult::FrozenClient(_) => vec![],
			})
			.flatten()
			.collect::<Result<Vec<_>, _>>()
			.map_err(|err| {
				log::debug!(target: "ismp", "Handling Error {:#?}", err);
				Pallet::<T>::deposit_event(Event::<T>::Errors { errors: vec![err.into()] });
				Error::<T>::InvalidMessage
			})?;

		T::FeeHandler::on_executed(messages_with_weights, events.clone())
			.map_err(|_| Error::<T>::ErrorChargingFee)?;

	fn on_executed(
		messages: Vec<MessageWithWeight>,
		events: Vec<IsmpEvent>,
	) -> DispatchResultWithPostInfo {
		let maybe_relayer_account = messages.get(0).and_then(|first_message| {
			if let Message::Consensus(consensus_msg) = &first_message.message {
				let data = sp_io::hashing::keccak_256(&consensus_msg.consensus_proof);
				Signature::decode(&mut &consensus_msg.signer[..])
					.ok()
					.and_then(|sig| sig.verify_and_get_sr25519_pubkey(&data, None).ok())
					.map(|pub_key| pub_key.into())
			} else {
				None::<[u8; 32]>
			}
		});

		if let Some(relayer_account) = maybe_relayer_account {
			// When a batch contains multiple `StateMachineUpdated` events for the
			// same `state_machine_id` (sequential consensus updates for the same
			// chain), `calculate_reward` reads the same persisted
			// `(latest_commitment_height, previous_commitment_height)` pair on
			// every iteration and pays the same block-span reward N times.
			// Collapse the per-state-machine event stream to the single highest
			// `latest_height` so each state machine receives one reward per
			// batch, sized by the actual span of its commitment advance.
			let mut highest_per_state_machine: BTreeMap<StateMachineId, u64> = BTreeMap::new();
			for event in events {
				if let IsmpEvent::StateMachineUpdated(update) = event {
					highest_per_state_machine
						.entry(update.state_machine_id)
						.and_modify(|h| {
							if update.latest_height > *h {
								*h = update.latest_height;
							}
						})
						.or_insert(update.latest_height);
				}
			}
