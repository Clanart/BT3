### Title
Unauthenticated JSON-RPC `send_citrea_tx` Allows Any Network Peer to Inject Arbitrary DA Payloads and Drain tx-sender Bitcoin UTXOs — (`crates/clementine-tx-sender/src/jsonrpc/server.rs`)

---

### Summary

The `start_jsonrpc_server` function builds a plain HTTP JSON-RPC server with `ServerBuilder::default()` and attaches zero authentication middleware. The `send_citrea_tx` method is registered with no credential check. Any caller that can reach the port — including any host on the network when `TX_SENDER_JSONRPC_BIND=0.0.0.0`, which the code explicitly permits — can inject arbitrary `CitreaTxRequest` payloads (`BatchProof`, `BatchProofMethodId`, `SequencerCommitment`) into `tx_sender_citrea_raw_tx_queue`. The tx-sender's background loop then autonomously funds, signs, and broadcasts commit + reveal Bitcoin transactions for those rows, spending the tx-sender's own Bitcoin wallet UTXOs.

---

### Finding Description

**Unauthenticated server construction:**

`start_jsonrpc_server` uses `ServerBuilder::default()` with no middleware, no token, no mTLS, and no IP allowlist beyond the bind address itself. [1](#0-0) 

The `send_citrea_tx` handler immediately deserializes the caller-supplied `InsertCitreaRawTxParams` and forwards it to `TxSenderClient::send_citrea_tx` with no identity check: [2](#0-1) 

**Explicit `0.0.0.0` support with no auth:**

The config layer explicitly accepts `0.0.0.0` as a valid bind address: [3](#0-2) 

When `TX_SENDER_JSONRPC_BIND` is unset the default is `127.0.0.1`, but the code makes `0.0.0.0` a first-class supported value with no compensating authentication requirement. Any deployment that sets `0.0.0.0` (e.g., containerized environments where the tx-sender is a sidecar reachable from other pods) exposes the port to the network with no credentials required.

**Downstream fund spend:**

`TxSenderClient::send_citrea_tx` writes the attacker-controlled body directly into `tx_sender_citrea_raw_tx_queue`: [4](#0-3) 

The background `sync_citrea_txs` loop picks up every row with a null `commit_outpoint`, calls `fund_raw_transaction` (selecting UTXOs from the tx-sender's Bitcoin Core wallet), signs, and broadcasts a commit transaction on Bitcoin: [5](#0-4) [6](#0-5) 

It then creates and broadcasts a reveal transaction spending that commit UTXO. Both transactions pay miner fees from the tx-sender's wallet. The attacker pays nothing.

**Contrast with gRPC actors:**

Every gRPC actor (verifier, operator, aggregator) is protected by mTLS + the `OnlyAggregatorAndSelf` interceptor: [7](#0-6) 

The JSON-RPC tx-sender server has no equivalent protection.

---

### Impact Explanation

- **tx-sender-managed Bitcoin balance drained**: Each attacker-injected row causes the tx-sender to spend wallet UTXOs for commit + reveal fees. The JSON-RPC body size limit is 50 MB; an attacker can submit many large `BatchProof` payloads in rapid succession, exhausting the tx-sender's Bitcoin balance. [8](#0-7) 

- **Bridge liveness broken**: Once the tx-sender's Bitcoin wallet is depleted, it can no longer fund legitimate bridge transactions (challenge txs, payout txs, reimbursement txs), halting the bridge.
- **Unauthorized privileged action**: Arbitrary `BatchProofMethodId` and `SequencerCommitment` payloads are broadcast on Bitcoin under the tx-sender's identity, polluting the DA layer with attacker-controlled data.

---

### Likelihood Explanation

Likelihood is **conditional on bind address**. With `TX_SENDER_JSONRPC_BIND=0.0.0.0` (explicitly supported, no auth required by code), any network peer can exploit this with a single HTTP POST. With `127.0.0.1` (the default), the attacker must be a local process on the same host — still reachable via SSRF from a co-located service or a compromised container sharing the network namespace. The code contains no authentication layer at all, so there is no defense-in-depth regardless of bind address.

---

### Recommendation

1. **Add shared-secret or token authentication** to the JSON-RPC server. `jsonrpsee`'s `ServerBuilder` supports custom middleware layers; add an HTTP `Authorization` header check before dispatching any method.
2. **Reject `0.0.0.0` binding unless authentication is configured**, or remove `0.0.0.0` as a valid option entirely.
3. **Rate-limit and cap** the number of pending rows per `insertion_id` to bound the worst-case fee drain even if authentication is bypassed.

---

    pub async fn send_citrea_tx(&self, request: CitreaTxRequest) -> Result<i64, eyre::Report> {
        use crate::citrea::data_serialization::DataOnDa;
        use crate::citrea::MAX_CHUNK_SIZE;

        let mut dbtx = self.db.begin_transaction().await?;

        let insertion_id = match request {
            CitreaTxRequest::BatchProof { bytes, chunk_size } => {
                // Hash the original proof bytes so the same proof dedupes even if callers
                // retry it with a different chunk_size or as a non-chunked Complete body.
                let full_body_hash = crate::citrea::calculate_sha256(&bytes);
                let mut chunk_size = chunk_size.unwrap_or(MAX_CHUNK_SIZE);
                if chunk_size == 0 {
                    chunk_size = MAX_CHUNK_SIZE;
                }
                if chunk_size > MAX_CHUNK_SIZE {
                    chunk_size = MAX_CHUNK_SIZE;
                }
                let chunk_size = chunk_size as usize;

                if bytes.len() <= chunk_size {
                    let data = DataOnDa::Complete(bytes);
                    let blob = borsh::to_vec(&data).expect("zk::Proof serialize must not fail");
                    self.db
                        .insert_citrea_raw_tx_single_with_hash(
                            &mut dbtx,
                            TransactionKind::Complete,
                            &blob,
                            &full_body_hash,
                        )
                        .await?
                } else {
                    let chunks: Vec<Vec<u8>> = bytes
                        .chunks(chunk_size)
                        .map(|chunk| {
                            borsh::to_vec(&DataOnDa::Chunk(chunk.to_vec()))
                                .expect("zk::Proof serialize must not fail")
                        })
                        .collect();
                    self.db
                        .insert_citrea_raw_tx_chunks(&mut dbtx, &chunks, &full_body_hash)
                        .await?
                }
            }
            CitreaTxRequest::BatchProofMethodId(body) => {
                if body.len() as u32 > MAX_CHUNK_SIZE {
                    return Err(eyre!(
                        "Citrea BatchProofMethodId DA payload body too large; max {} bytes",
                        MAX_CHUNK_SIZE,
                    ));
                }
                self.db
                    .insert_citrea_raw_tx_single(
                        &mut dbtx,
                        TransactionKind::BatchProofMethodId,
                        &body,
                    )
                    .await?
            }
            CitreaTxRequest::SequencerCommitment(body) => {
                if body.len() as u32 > MAX_CHUNK_SIZE {
                    return Err(eyre!(
                        "Citrea SequencerCommitment DA payload body too large; max {} bytes",
                        MAX_CHUNK_SIZE,
                    ));
                }
                self.db
                    .insert_citrea_raw_tx_single(
                        &mut dbtx,
                        TransactionKind::SequencerCommitment,
                        &body,
                    )
                    .await?
            }
        };

        self.db.commit_transaction(dbtx).await?;
        Ok(insertion_id)

    #[allow(clippy::result_large_err)]
    fn call(&mut self, req: Request<()>) -> Result<Request<()>, Status> {

            Interceptors::OnlyAggregatorAndSelf {

            } => only_aggregator_and_self(req, our_cert, aggregator_cert),
            Interceptors::Noop => Ok(req),
        }
    }
}

#[allow(clippy::result_large_err)]
fn only_aggregator_and_self(
    req: Request<()>,
    our_cert: &CertificateDer<'static>,
    aggregator_cert: &CertificateDer<'static>,
) -> Result<Request<()>, Status> {
    let Some(peer_certs) = req.peer_certs() else {
        if cfg!(test) {
            // Test mode, we don't need to verify peer certificates
            return Ok(req);
        } else {
            // If we're not in test mode, we need to check peer certificates
            return Err(Status::unauthenticated(
                "Failed to verify peer certificate, is TLS enabled?",
            ));
        }
    };

    // IMPORTANT: Only check the leaf (end-entity) certificate, which is always the first
    // certificate in the chain. The leaf is the only certificate whose private key the peer
    // proved possession of during the TLS handshake. Checking anywhere else in the chain
    // would allow identity spoofing: an attacker could include a pinned cert as an
    // intermediate in their chain without possessing its private key.
    let Some(leaf_cert) = peer_certs.first() else {
        return Err(Status::unauthenticated("Peer certificate chain is empty"));
    };

    if is_internal(&req) {
        if leaf_cert == our_cert {
            Ok(req)
        } else {
            Err(Status::unauthenticated(
                "Unauthorized call to internal method (not self)",
            ))
        }
    } else if leaf_cert == aggregator_cert || leaf_cert == our_cert {
        Ok(req)
    } else {
        Err(Status::unauthenticated(
            "Unauthorized call to method (not aggregator or self)",
        ))
    }
