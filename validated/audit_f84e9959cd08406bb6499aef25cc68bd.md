### Title
Daemon keychain response logging leaks raw private-key entropy in plaintext due to an incomplete redaction allowlist - ([File: chia/daemon/server.py])

### Summary
The Discourse advisory describes a redaction/authorization gap: a field containing a raw SMTP password was not included in the set of fields that get masked before being shown through a lower-privileged audit/history view, so a non-staff actor could read the plaintext secret. `chia/daemon/server.py` has the analogous bug class: `redact_sensitive_data()` is a substring-based allowlist (`"pass"`, `"key"`, `"secret"`, `"mnemonic"`) used to scrub keychain-related daemon websocket traffic before it is written to the daemon's debug log. The `entropy` field returned by several keychain RPC commands — the raw seed bytes from which the full 24-word mnemonic and private key can be deterministically reconstructed — does not match any of these substrings and is therefore never redacted.

### Finding Description
`redact_sensitive_data()` recursively walks a dict and redacts any key whose name contains `"pass"`, `"key"`, `"secret"`, or `"mnemonic"` (case-insensitive): [1](#0-0) 

This function is exercised by `test_message_logging_redaction`, which only verifies redaction for fields such as `password`, `private_key`, `secret_value`, `mnemonic`, `passphrase`, `api_key`, and `seed_mnemonic`: [2](#0-1) 

However, the `KeychainServer` command handlers `get_all_private_keys`, `get_first_private_key`, and `get_key_for_fingerprint` all return the seed material under the key name `entropy` (not `key`, `secret`, or `mnemonic`): [3](#0-2) [4](#0-3) 

`entropy` is the literal seed used by `KeychainProxy` to reconstruct the mnemonic and private key on the client side (`mnemonic_to_seed` → `AugSchemeMPL.key_gen`), i.e. it is fully equivalent to possessing the private key/mnemonic itself: [5](#0-4) [6](#0-5) 

Because `"entropy"` contains none of the redaction trigger substrings, any daemon websocket traffic carrying this field — command responses to `get_all_private_keys`, `get_first_private_key`, `get_key_for_fingerprint`, and remote `add_key`/`add_private_key` roundtrips that echo derived key data — is logged to the daemon's debug log (`chia.daemon.server`) in cleartext instead of being masked like every other private-key-bearing field.

### Impact Explanation
Any process or user with read access to the daemon's log output (support diagnostics bundles, log shipping/aggregation, crash reports, or simply a lower-trust local account that can read log files but was never granted keyring/daemon TLS cert access) can recover the full seed entropy for every key in the keychain once DEBUG-level daemon logging has been enabled and any of the affected keychain RPC commands has been invoked. Because `entropy` deterministically reconstructs the mnemonic and hence the master private key (`bytes_to_mnemonic` → `mnemonic_to_seed` → `AugSchemeMPL.key_gen`), this is a complete compromise of the wallet's spending authority — equivalent to leaking the master private key/mnemonic itself, which is the class of impact the redaction mechanism was explicitly built to prevent (as shown by the coverage of `mnemonic`, `password`, `secret_value`, `api_key`, etc. in the existing test). This maps directly to unauthorized/unsigned coin movement, since anyone obtaining the entropy can sign and broadcast spends for every coin controlled by the derived keys.

### Likelihood Explanation
The logging path is only active when the daemon logger is at `DEBUG` level and the relevant keychain commands are invoked (`get_all_private_keys`, `get_first_private_key`, `get_key_for_fingerprint`, or the local `add_key`/`add_private_key` flow), which happens routinely during normal wallet startup/login (`KeychainProxy` calls these to unlock and select keys) and during support/diagnostic sessions where DEBUG logging is commonly enabled. No special privilege beyond local daemon access is required to trigger the logging (any already-connected local RPC/daemon client, e.g. wallet service startup, invokes these calls as part of normal operation), and the disclosure only requires read access to the resulting log file — a materially lower bar than the mutual-TLS daemon certificate normally required to talk to the keychain directly.

### Recommendation
Expand `redact_sensitive_data()`'s trigger set (or switch to an explicit denylist of exact field names: `entropy`, `pk`/`sk` pairs used with entropy, `private_key`, `seed`, etc.) so that `entropy` and any other field capable of reconstructing key material is always masked before being passed to `dict_to_json_str()` for logging, regardless of substring matching against `"pass"/"key"/"secret"/"mnemonic"`. Add a regression test (extending `test_message_logging_redaction`) that specifically covers `entropy` and the exact response shapes produced by `get_all_private_keys`, `get_first_private_key`, and `get_key_for_fingerprint`.

### Proof of Concept
1. Start the chia daemon with debug-level logging enabled for `chia.daemon.server` (e.g. via config log level).
2. Connect a local client to the daemon websocket and add a key or log in with an existing key so that `WalletNode`/`KeychainProxy` issues a `get_key_for_fingerprint` or `get_all_private_keys` daemon command (this happens automatically during normal wallet startup, see `chia/daemon/keychain_proxy.py:254-289,343-397`).
3. Inspect the daemon debug log: unlike `password`, `mnemonic`, `secret_value`, or `api_key` fields (redacted per `test_message_logging_redaction`), the `entropy` field in the `get_key_for_fingerprint`/`get_all_private_keys` response payload appears in cleartext hex, e.g. `{"success": true, "pk": "<hex>", "entropy": "<hex>"}` (see `chia/daemon/keychain_server.py:317-326,343-365`).
4. From the leaked `entropy` hex, reconstruct the mnemonic and private key exactly as `KeychainProxy.get_all_private_keys`/`get_key_for_fingerprint` do (`bytes_to_mnemonic` → `mnemonic_to_seed` → `AugSchemeMPL.key_gen`), yielding full spend authority over the associated wallet.

```python
def redact_sensitive_data(obj: Any, redaction_triggers: Collection[str] = ("pass", "key", "secret", "mnemonic")) -> Any:
    """Recursively redact sensitive data from nested dictionaries."""
    if isinstance(obj, dict):
        return {
            key: "***<redacted>***"
            if any(trigger.casefold() in key.casefold() for trigger in redaction_triggers)
            else redact_sensitive_data(value, redaction_triggers)
            for key, value in obj.items()
        }
    else:
        return obj
```

```python
    async def get_all_private_keys(self, request: dict[str, Any]) -> dict[str, Any]:
        all_keys: list[dict[str, Any]] = []
        if self.get_keychain_for_request(request).is_keyring_locked():
            return {"success": False, "error": KEYCHAIN_ERR_LOCKED}

        private_keys = self.get_keychain_for_request(request).get_all_private_keys()
        for sk, entropy in private_keys:
            all_keys.append({"pk": bytes(sk.get_g1()).hex(), "entropy": entropy.hex()})

        return {"success": True, "private_keys": all_keys}
```

```python
    async def get_key_for_fingerprint(self, request: dict[str, Any]) -> dict[str, Any]:
        keychain = self.get_keychain_for_request(request)
        if keychain.is_keyring_locked():
            return {"success": False, "error": KEYCHAIN_ERR_LOCKED}

        private = request.get("private", True)
        keys = keychain.get_keys(include_secrets=private)
        if len(keys) == 0:
            return {"success": False, "error": KEYCHAIN_ERR_NO_KEYS}

        try:
            if request["fingerprint"] is None:
                key_data = keys[0]
            else:
                key_data = keychain.get_key(request["fingerprint"], include_secrets=private)
        except KeychainFingerprintNotFound:
            return {"success": False, "error": KEYCHAIN_ERR_KEY_NOT_FOUND}

        return {
            "success": True,
            "pk": bytes(key_data.public_key).hex(),
            "entropy": key_data.entropy.hex() if private else None,
        }
```

```python
    async def get_all_private_keys(self) -> list[tuple[PrivateKey, bytes]]:
        """
        Forwards to Keychain.get_all_private_keys()
        """
        keys: list[tuple[PrivateKey, bytes]] = []
        if self.use_local_keychain():
            keys = self.keychain.get_all_private_keys()
        else:
            response, success = await self.get_response_for_request("get_all_private_keys", {})
            if success:
                private_keys = response["data"].get("private_keys", None)
                if private_keys is None:
                    err = f"Missing private_keys in {response.get('command')} response"
                    self.log.error(f"{err}")
                    raise KeychainMalformedResponse(f"{err}")
                else:
                    for key_dict in private_keys:
                        pk = key_dict.get("pk", None)
                        ent_str = key_dict.get("entropy", None)
                        if pk is None or ent_str is None:
                            err = f"Missing pk and/or ent in {response.get('command')} response"
                            self.log.error(f"{err}")
                            continue  # We'll skip the incomplete key entry
                        ent = bytes.fromhex(ent_str)
                        mnemonic = bytes_to_mnemonic(ent)
                        seed = mnemonic_to_seed(mnemonic)
                        key = AugSchemeMPL.key_gen(seed)
                        if bytes(key.get_g1()).hex() == pk:
                            keys.append((key, ent))
                        else:
                            err = "G1Elements don't match"
                            self.log.error(f"{err}")
            else:
                self.handle_error(response)

        return keys
```
