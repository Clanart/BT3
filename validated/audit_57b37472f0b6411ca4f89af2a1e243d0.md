### Title
Attacker-controlled zero-slippage buyback in `_bullMGP` allows flash-loan price manipulation of the BUSD→MGP swap to inflate `mgpAmountToLock` - ([File: wombat/ArbWomUp2.sol])

### Summary
`ArbWomUp2.incentiveDeposit(_amount, _minMGPRec, true)` lets the caller set `_minMGPRec` freely (including `0`), and the fixed BUSD reward computed from the WOM deposit tier schedule is then swapped for MGP at the AMM's instantaneous spot price with no oracle or TWAP check. An attacker can flash-loan to shift the BUSD/MGP pool reserves immediately before the call, causing `ROUTER.swapExactTokensForTokens` to return an inflated `amounts[1]`, which is then multiplied by the bull bonus and locked into `vlMGP` on the attacker's behalf.

### Finding Description
`getRewardAmount` computes `rewardToSend` purely from `userWOMDeposited`/`rewardTier`/`rewardMultiplier`, entirely independent of MGP market price: [1](#0-0) 

`incentiveDeposit` passes the caller-supplied `_minMGPRec` straight through to `_bullMGP`, with no internal floor, oracle check, or TWAP guard: [2](#0-1) 

`_bullMGP` executes the swap using only that attacker-controlled minimum and the router's current spot reserves, then locks `amounts[1] * (DENOMINATOR + bullBonusRatio) / DENOMINATOR` MGP into `vlMGP` for the caller: [3](#0-2) 

Because `_minMGPRec` can be `0`, the swap has no slippage protection. An attacker can, within one atomic transaction:
1. Flash-loan BUSD/MGP and swap on `ROUTER` to depress the MGP price (increase MGP reserve relative to BUSD) in the exact pool `ArbWomUp2` uses.
2. Call `incentiveDeposit(_amount, 0, true)` — the fixed BUSD reward is swapped at the manipulated depressed price, yielding an inflated `amounts[1]`, further amplified by `bullBonusRatio`, and locked to the attacker in `vlMGP`.
3. Reverse the manipulation swap and repay the flash loan.

`nonReentrant`/`whenNotPaused` do not prevent this because it is not reentrancy — it is intra-transaction price manipulation of a spot-priced swap with disabled slippage protection, all driven by the attacker's own transaction ordering.

### Impact Explanation
The MGP locked into `vlMGP` for the attacker exceeds what the fixed BUSD reward is fairly worth at the pool's true (unmanipulated) price. This is a direct extraction of value from the AMM pool's liquidity/reserves routed through the protocol's reward-buyback mechanism, resulting in theft of unclaimed MGP yield beyond the attacker's genuine tier-based entitlement — matching the "theft of unclaimed yield" impact class.

### Likelihood Explanation
Requires only: (a) a deployed/real BUSD-MGP AMM pair reachable via `ROUTER`, (b) flash-loan capital (freely available on most chains for common tokens), and (c) the ability to call `incentiveDeposit` with `_minMGPRec = 0` and `_bullMode = true`, which any unprivileged holder of WOM can do after a normal deposit. The attack is repeatable each time the contract holds BUSD reward balance and is composed entirely of public/permissionless calls executable by an EOA-deployed contract in one transaction.

### Recommendation
Do not accept a caller-supplied `_minMGPRec` for a reward buyback executed on behalf of the protocol. Instead, compute the minimum acceptable output internally from a manipulation-resistant price source (e.g., TWAP oracle or a bounded deviation check against a recent on-chain price), and/or split large buybacks, and add a maximum allowed price-impact/slippage tolerance enforced by the contract itself rather than trusting the caller's input.

### Proof of Concept
Foundry fork test outline:
1. Fork BSC at a block where the real BUSD/MGP pair on `ROUTER` has known reserves; deploy/point `ArbWomUp2` at that pair via `setup`.
2. Have the attacker contract flash-loan BUSD (or MGP) and execute a large `swapExactTokensForTokens` on the same pair to depress MGP price.
3. In the same transaction, call `incentiveDeposit(_amount, 0, true)` with a WOM balance sized to trigger a meaningful `rewardToSend`.
4. Reverse the initial swap to restore pool price and repay the flash loan.
5. Assert `mgpAmountToLock` (read from the `VLMGPRewarded` event or `vlMGP` position) exceeds `fairPriceMGP = rewardToSend / trueSpotPrice * (DENOMINATOR + bullBonusRatio) / DENOMINATOR` computed from reserves before manipulation, demonstrating extraction beyond fair entitlement.

        } else {
            IERC20(busd).transfer(msg.sender, rewardToSend);
            emit BUSDRewarded(msg.sender, rewardToSend);
        }
    }

    function getRewardAmount(uint256 _amount, address _account) external view returns (uint256) {
        if (_amount == 0 || rewardMultiplier.length == 0) return 0;
        uint256 accumulated = _amount + userWOMDeposited[_account];

        uint256 rewardAmount = 0;
        uint256 i = 1;
        while (i < rewardTier.length && accumulated > rewardTier[i]) {
            rewardAmount +=
                (rewardTier[i] - rewardTier[i - 1]) *
                rewardMultiplier[i - 1];
            i++;
        }
        rewardAmount += (accumulated - rewardTier[i - 1]) * rewardMultiplier[i - 1];

        uint256 busdReward = (rewardAmount / DENOMINATOR) - this.calDoubledCounted(_account);
        uint256 busdleft = IERC20(busd).balanceOf(address(this));

        return busdReward > busdleft ? busdleft : busdReward;
    }

    function _bullMGP(uint256 _busdAmount, uint256 _minRec, address _account) internal {
        IERC20(busd).safeApprove(address(ROUTER), _busdAmount);
        
        address[] memory path = new address[](2);
        path[0] = busd;
        path[1] = mgp;
        uint256[] memory amounts = ROUTER.swapExactTokensForTokens(
            _busdAmount,
            _minRec,
            path,
            address(this),
            block.timestamp
        );

        uint256 mgpAmountToLcok = amounts[1] * (DENOMINATOR + bullBonusRatio) / DENOMINATOR; // get bull mode bonus
        IERC20(mgp).approve(address(vlMGP), mgpAmountToLcok);
        vlMGP.lockFor(mgpAmountToLcok, _account);

        emit VLMGPRewarded(_account, _busdAmount, mgpAmountToLcok);
    }
