## Finding [1](#0-0) 

### Title
Git's local-clone/submodule protection is explicitly disabled during recursive clone of an attacker-controlled URL — ([File: app/src/lib/git/clone.ts])

### Summary
Just as the TeaVaultAmbient report centers on an *unvalidated address parameter* (the swap router) being trusted for a sensitive operation, GitHub Desktop's clone pipeline takes an **attacker-influenced URL/repository** (reachable via the `x-github-client://openRepo/<url>` deep link, the `github clone <url>` CLI entry point, or the "Clone repository" generic-URL flow) and feeds it into `git clone --recursive` while **explicitly turning off a Git-provided safety mechanism**: `GIT_CLONE_PROTECTION_ACTIVE: 'false'`. [2](#0-1) [3](#0-2) [4](#0-3) 

### Finding Description
`clone()` in `app/src/lib/git/clone.ts` builds the environment for the `git clone` invocation and unconditionally sets `GIT_CLONE_PROTECTION_ACTIVE: 'false'` before running `clone --recursive -- <url> <path>`: [1](#0-0) 

`GIT_CLONE_PROTECTION_ACTIVE` is the flag Git itself uses to decide whether the "outer" invocation's anti-abuse checks for local/submodule clones are active (the checks added to stop a malicious repository from using symlinked `.git` contents, hardlinks, or crafted submodule URLs to make Git read/write files outside the intended destination during a recursive clone). Desktop hard-codes this to `'false'` for **every** clone, regardless of whether the URL originates from a trusted "Clone GitHub repository" flow or from a completely untrusted source such as:
- an `x-github-client://openRepo/<url>` deep link parsed by `parseAppURL`, which validates only `branch`/`pr` shape and passes the raw `url` straight through [5](#0-4) 
- `dispatcher.openOrCloneRepository(url)`, which forwards that URL directly into the Clone Repository popup/clone call with no allow-listing of protocol or host [4](#0-3) 

Because `--recursive` is always passed, any submodules declared inside the attacker-supplied repository are cloned automatically, and it is precisely in that submodule-recursion path that Git's protection (which Desktop disables) is designed to matter. The `filepath` parameter of the same deep-link action *is* validated against path traversal via `isAbsolute` + `resolveWithin` [6](#0-5)  — showing the developers were aware of and guarded against attacker-controlled-path escapes in this exact code path, but the far more consequential `GIT_CLONE_PROTECTION_ACTIVE=false` override on the clone/submodule-recursion path has no equivalent guard.

The `isClonePathSensitive` check in the same file only restricts the *destination* directory (home, `.ssh`, `.gnupg`, etc.) chosen by the local user — it does nothing to constrain what a malicious *remote repository's submodules* can do once protection is disabled during the recursive clone. [7](#0-6) 

### Impact Explanation
This mirrors the report's broken invariant: a caller-supplied, attacker-influenced identifier (swap router address ↔ clone URL/repository) is handed to a sensitive operation whose built-in safety check exists specifically to stop the untrusted party from abusing it, and that check is turned off. Here, disabling `GIT_CLONE_PROTECTION_ACTIVE` during a `--recursive` clone of an attacker-controlled remote (or its submodules) can allow a malicious repository to make Git write or follow paths outside the intended clone directory during submodule setup — i.e., file write/read outside the repo, satisfying the "Valid Impact" criteria (attacker controls a cloned/fetched repository resulting in file write or read outside the repo).

### Likelihood Explanation
The path is reachable without any local/physical access or prior compromise: a victim simply has to click an `x-github-client://openRepo/...` link (or use "Clone repository" / `github clone <url>`) pointing at a repository the attacker controls, exactly the "attacker controls a cloned/fetched repository ... or a link the user clicks" scenario called out as in-scope. No admin rights or pre-existing malware are required, and the disabling of the protection flag is unconditional in code, not situational.

### Recommendation
- Do not unconditionally set `GIT_CLONE_PROTECTION_ACTIVE: 'false'`; only relax it where genuinely necessary and re-enable/leave default protection active for the recursive submodule phase of untrusted clones.
- Apply an allow-list/validation layer to clone URLs originating from deep links and CLI arguments (scheme allow-list such as `https`/`ssh` only, reject `ext::`/`fd::` and similar Git transport helpers) before they ever reach `clone()`.
- Extend the existing `resolveWithin`/`isAbsolute` pattern already used for the `filepath` parameter to the submodule-recursion path as well, since the developers already recognize that attacker-controlled paths from this same action need containment.

### Proof of Concept
1. Attacker hosts a public repository containing a `.gitmodules` file (or nested submodule config) crafted to abuse local-clone/symlink handling that Git's `GIT_CLONE_PROTECTION_ACTIVE` check would normally block.
2. Attacker sends the victim a link: `x-github-client://openRepo/<attacker-repo-url>`.
3. Victim clicks the link; `parseAppURL` accepts it as `open-repository-from-url` and `openOrCloneRepository` opens the Clone dialog / triggers `_clone` with the attacker URL. [5](#0-4) [4](#0-3) 
4. `clone()` runs `git -c init.defaultBranch=... clone --recursive -- <attacker-url> <path>` with `GIT_CLONE_PROTECTION_ACTIVE=false` in the environment, disabling Git's own submodule/local-clone protections for the entire operation, including submodule recursion. [1](#0-0) [8](#0-7) 

Verifying exactly which write/read primitive the disabled check would have blocked requires reproducing the crafted-submodule scenario in a live Git binary of the version bundled with Desktop (dugite/embedded Git version), which was not accessible in this read-only review — this should be validated with an actual PoC repository against the exact Git version Desktop ships.

function isClonePathSensitive(unresolvedClonePath: string): boolean {
  const clonePath = Path.resolve(unresolvedClonePath).toLowerCase()
  const home = Path.resolve(homedir()).toLowerCase()

  if (clonePath === home) {
    return true
  }

  const sensitiveLocations = [
    Path.join(home, '.ssh'),
    Path.join(home, '.gnupg'),
    Path.join(home, '.config'),
    Path.join(home, '.config', 'git'),
    Path.join(home, '.gitconfig'),
  ]

  if (__WIN32__) {
    const appData = process.env.APPDATA
    if (appData) {
      sensitiveLocations.push(appData.toLowerCase())
      sensitiveLocations.push(Path.join(appData, 'gnupg').toLowerCase())
    }
  }

  for (const sensitive of sensitiveLocations) {
    if (clonePath === sensitive || clonePath.startsWith(sensitive + Path.sep)) {
      return true
    }
  }

  return false
}

export function parseAppURL(url: string): URLActionType {
  const parsedURL = URL.parse(url, true)
  const hostname = parsedURL.hostname
  const unknown: IUnknownAction = { name: 'unknown', url }
  if (!hostname) {
    return unknown
  }

  const query = parsedURL.query

  const actionName = hostname.toLowerCase()
  if (actionName === 'oauth') {
    const code = getQueryStringValue(query, 'code')
    const state = getQueryStringValue(query, 'state')
    if (code != null && state != null) {
      return { name: 'oauth', code, state }
    } else {
      return unknown
    }
  }

  // we require something resembling a URL first
  // - bail out if it's not defined
  // - bail out if you only have `/`
  const pathName = parsedURL.pathname
  if (!pathName || pathName.length <= 1) {
    return unknown
  }

  // Trim the trailing / from the URL
  const parsedPath = pathName.substring(1)

  if (actionName === 'openrepo') {
    const pr = getQueryStringValue(query, 'pr')
    const branch = getQueryStringValue(query, 'branch')
    const filepath = getQueryStringValue(query, 'filepath')

    if (pr != null) {
      if (!/^\d+$/.test(pr)) {
        return unknown
      }

      // we also expect the branch for a forked PR to be a given ref format
      if (branch != null && !/^pr\/\d+$/.test(branch)) {
        return unknown
      }
    }

    if (branch != null && testForInvalidChars(branch)) {
      return unknown
    }

    return {
      name: 'open-repository-from-url',
      url: parsedPath,
      branch,
      pr,
      filepath,
    }
  }
