### Title
Minimum relay fee threshold under-enforced due to sat/kWU constant treated as sat/kvB — (`networks/bitcoin/src/wallet/send.rs`)

### Summary

The external report describes a unit-scaling bug: a value expressed in one unit (lamports) is compared against a threshold expressed in another (SOL), producing a factor-of-10 error. The same bug class appears in `SignableTransaction::new`, where `bitcoin::policy::DEFAULT_MIN_RELAY_TX_FEE` — defined by rust-bitcoin (v0.32, `Cargo.toml` line 27) in satoshi per kilo-weight-unit — is treated as satoshi per kilo-vbyte and divided by `1000` against `vbytes`, making the enforced minimum several times smaller than intended.

### Finding Description

In `SignableTransaction::new`, after computing the transaction's `vbytes`, the constructor rejects fee rates below the network relay minimum:

```rust
// bitcoin::policy::DEFAULT_MIN_RELAY_TX_FEE is in sats/kilo-vbyte
if needed_fee < ((u64::from(bitcoin::policy::DEFAULT_MIN_RELAY_TX_FEE) * vbytes) / 1000) {
  Err(TransactionError::TooLowFee)?;
}
``` [1](#0-0) 

`bitcoin::policy::DEFAULT_MIN_RELAY_TX_FEE` in rust-bitcoin 0.32 is `100`, expressed in satoshi per kilo-weight-unit (sat/kWU), matching the crate's `FeeRate` unit convention (`bitcoin::policy::get_virtual_tx_size`, used just above, works in weight units). The correct minimum fee for a transaction is therefore `DEFAULT_MIN_RELAY_TX_FEE * weight / 1000`, i.e. roughly `100 * 4 * vbytes / 1000 = 0.4 sat/vbyte` (and Bitcoin Core's actual relay minimum is 250 sat/kWU = 1 sat/vbyte). The code instead computes `100 * vbytes / 1000 = 0.1 sat/vbyte` — a factor of 4 below what the constant implies, and a factor of 10 below the real Core relay policy, the same "missing zero" class as the external report.

### Impact Explanation

A `SignableTransaction` constructed with `fee_per_vbyte` in the gap (e.g. 0.1–1 sat/vbyte, or any value whose resulting `needed_fee` clears `vbytes/10` but is below the true relay minimum) is accepted by `SignableTransaction::new`, proceeds through `sign` (which produces a valid BIP-340 signature over the sighash), and produces a fully signed transaction that the Bitcoin peer-to-peer network will refuse to relay and miners will not include. Funds consumed by that transaction are effectively burned-until-RBF'd: Serai's Bitcoin integration signs spends that cannot propagate, so outputs appear spent-planned but never confirm, stalling the multisig wallet.

### Likelihood Explanation

`fee_per_vbyte` is a public caller-supplied parameter of `SignableTransaction::new` (`send.rs` line 155), so any consumer of the library can trigger this with no privilege. The flawed threshold is also purely arithmetic on the public input `fee_per_vbyte * vbytes`, so it always under-enforces; the only reason it isn't hit constantly is that upstream callers currently supply ≥1 sat/vbyte (e.g. `median_fee` floors at 1). Any low-fee-regime call path — or an attacker who can influence the fee input toward a value below the true minimum — produces an unrelayable signed transaction.

### Recommendation

Compute the minimum in the constant's actual units, using `weight` rather than `vbytes`:

```rust
if needed_fee < ((u64::from(bitcoin::policy::DEFAULT_MIN_RELAY_TX_FEE) * weight) / 1000) {
  Err(TransactionError::TooLowFee)?;
}
```

Preferably compare via `bitcoin::FeeRate` (`FeeRate::from_sat_per_kwu(DEFAULT_MIN_RELAY_TX_FEE) * weight`) so unit conversions are handled by the library rather than hand-rolled divisors, and consider checking against Core's effective 250 sat/kWU (1 sat/vbyte) relay floor rather than the stale constant.

### Proof of Concept

```rust
// A P2TR-in/P2TR-out transaction with 1 input, 1 payment, no change is ~155 vbytes.
// SignableTransaction::new checks:
//   needed_fee < (100 * vbytes) / 1000  ->  needed_fee < ~15 sats
// So fee_per_vbyte = 1 (155 sats) passes, yet a 155-vbyte tx needs
//   100 sat/kWU * ~620 wu / 1000 = 62 sats minimum by the constant's own units,
// and 155 sats (1 sat/vbyte) under real Core relay policy it still barely meets;
// but fee_per_vbyte such that needed_fee is e.g. 20–60 sats passes this check
// while being below the network relay floor.
let tx = SignableTransaction::new(
    vec![output],                       // ReceivedOutput from Scanner
    &[(p2tr_script_buf(key).unwrap(), 10_000)],
    None,                               // no change
    None,
    1,                                  // 1 sat/vbyte on the margin cases below
).unwrap();
// For constructions where vbytes makes 100*vbytes/1000 < true minimum,
// sign(&keys, &tx) yields a transaction send_raw_transaction will reject
// with "min relay fee not met".
```

The divergence is deterministic: the check at `send.rs:211` divides a sat/kWU constant by 1000 while multiplying by vbytes, so any `fee_per_vbyte * vbytes` between `vbytes/10` and `weight/10` produces a signed-but-unrelayable transaction.
