### Title
`SignableTransaction::new()` omits `OP_RETURN` data from transaction weight and fee calculations - (File: `networks/bitcoin/src/wallet/send.rs`)

### Summary

`SignableTransaction::new()` accepts an attacker/public-input-controlled `data` field and adds it as a zero-value `OP_RETURN` output, but calls `calculate_weight_vbytes()` with only `payments` and optional `change`. The resulting `weight`, `vbytes`, `needed_fee`, minimum-relay-fee check, and maximum-standard-weight check are computed for a smaller transaction than the one actually signed and broadcast. This is analogous to the referenced bug class: an economically relevant formula omits one component of the quantity it claims to price, producing an incorrect reported value.

### Finding Description

`SignableTransaction::new()` constructs `tx_outs`, appends the optional `OP_RETURN` output when `data` is supplied, but then calculates `(weight, vbytes)` using `calculate_weight_vbytes(tx_ins.len(), payments, None)`, whose signature has no `data` parameter and whose synthetic transaction contains only payment outputs and optional change [1](#0-0) . `calculate_weight_vbytes()` serializes a model transaction and returns `tx.weight()` plus the policy virtual size [2](#0-1) [3](#0-2) .

The same omission occurs when change is included: `fee_with_change` is calculated from a transaction containing payments and change, but not the already-appended `OP_RETURN` output [4](#0-3) . The final `SignableTransaction` nevertheless contains the real `tx_outs`, including the `OP_RETURN` [5](#0-4) .

### Impact Explanation

An unprivileged caller who can cause a Bitcoin transaction containing `data` to be signed can make Serai sign a transaction whose effective fee rate is lower than `fee_per_vbyte` requested. The absolute fee remains `input_sat - payment_sat - change`, but the transaction is larger than the size used to derive that fee.

At boundary conditions this can produce a transaction that fails Bitcoin's minimum relay feerate despite passing Serai's `TooLowFee` check, or exceeds `MAX_STANDARD_TX_WEIGHT` despite passing Serai's `TooLargeTransaction` check [6](#0-5) [7](#0-6) . The result is a signed transaction that may not relay or confirm as required, disrupting withdrawals/payments that depend on the caller-supplied `data`.

### Likelihood Explanation

The bug is deterministic whenever `data.is_some()`. The omitted size is approximately the serialized `OP_RETURN` output: 8 bytes of value, compact-size script length, `OP_RETURN`, push opcode/length, and up to 80 bytes of payload. Because `data` is a direct public input to `SignableTransaction::new()`, no cryptographic assumption, validator compromise, or protocol violation is required. Impact is bounded by transaction relay/confirmation failure rather than direct theft, so this is best classified as Medium rather than High.

### Recommendation

Include the exact `OP_RETURN` script in the transaction model used for sizing. Prefer refactoring `calculate_weight_vbytes()` to accept the final candidate `Vec<TxOut>` or an explicit `data: Option<&PushBytesBuf>`/`ScriptBuf`, so fee and weight calculations cannot diverge from `tx_outs`. Recompute the minimum relay fee and `MAX_STANDARD_TX_WEIGHT` against the transaction that will actually be signed.

### Proof of Concept

A crate-local test can demonstrate the mismatch without network access:

```rust
// networks/bitcoin/src/wallet/send.rs tests or crate-visible test
use bitcoin::{
  transaction::Version,
  absolute::LockTime,
  script::ScriptBuf,
  transaction::Transaction,
  OutPoint, Sequence, TxIn, TxOut, Amount, Witness,
};

// Build the transaction the same way SignableTransaction::new() does.
let data = vec![0xaa; 80];
let mut tx_outs = vec![TxOut {
  value: Amount::from_sat(10_000),
  script_pubkey: ScriptBuf::new(),
}];
tx_outs.push(TxOut {
  value: Amount::ZERO,
  script_pubkey: ScriptBuf::new_op_return(
    bitcoin::script::PushBytesBuf::try_from(data).unwrap(),
  ),
});

let actual = Transaction {
  version: Version(2),
  lock_time: LockTime::ZERO,
  input: vec![TxIn {
    previous_output: OutPoint::default(),
    script_sig: ScriptBuf::new(),
    sequence: Sequence::MAX,
    witness: Witness::from_slice(&[vec![0; 64]]),
  }],
  output: tx_outs,
};

// calculate_weight_vbytes(...) is called with only `payments`, so its model omits
// the OP_RETURN output.
let (model_weight, model_vbytes) =
  SignableTransaction::calculate_weight_vbytes(1, &payments, None);

assert!(actual.weight().to_wu() > model_weight);
assert!(actual.vsize() as u64 > model_vbytes);
```

The signed transaction returned by `TransactionSignatureMachine::complete()` uses the real transaction containing `tx_outs`, while `needed_fee` remains derived from the smaller model [8](#0-7) .
