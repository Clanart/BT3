Based on my investigation, I found a reachable type-confusion analog: unchecked Go type assertions on untrusted CosmWasm query response data in the pointer precompile.

### Title
Unrecovered type-assertion panic on attacker-controlled CW20/CW721/CW1155 query response crashes the calling node - ([File: precompiles/pointer/pointer.go])

### Summary
The pointer precompile's `AddCW20`, `AddCW721`, and `AddCW1155` handlers decode the pointee CosmWasm contract's own `token_info`/`contract_info` smart-query JSON response into a generic `map[string]interface{}` and then perform unchecked Go type assertions `formattedRes["name"].(string)` and `formattedRes["symbol"].(string)` on fields whose type and presence are fully controlled by the queried contract, not validated beforehand.

### Finding Description
Any user can deploy a CosmWasm contract implementing `token_info`/`contract_info` queries that returns a JSON value where `name` or `symbol` is absent, `null`, a number, boolean, or nested object instead of a string. `json.Unmarshal` into `map[string]interface{}` succeeds regardless (missing key yields `nil`, or a JSON number decodes to `float64`), so `formattedRes["name"].(string)` performs a raw, non-`, ok` type assertion, which panics on mismatch: [1](#0-0) [2](#0-1) [3](#0-2) 

This is reachable via the public EVM entry point `addCW20Pointer`/`addCW721Pointer`/`addCW1155Pointer` on the pointer precompile at `0x000000000000000000000000000000000000100b`, invoked through `Execute`: [4](#0-3) 

The precompile is a `DynamicGasPrecompile`. Its `RunAndCalculateGas` wrapper does have a `defer`/`recover`, but it is scoped to converting **gas-meter** panics into reverts only — the `precompiles_test.go` explicitly documents and tests that non-gas panics must propagate rather than be masked: [5](#0-4) 

A propagating (non-gas) Go panic inside EVM execution is not a normal `revert` — it unwinds past the state-transition/ante-handler call stack. Whether this halts only the single node processing that transaction (crash of a public RPC node executing an `eth_call`/simulate path) or a validator during `DeliverTx` depends on whether an outer `recover()` exists further up the Cosmos SDK / baseapp call chain; my search did not find any recover in the pointer precompile call path itself, only the gas-scoped one in the common dynamic-gas wrapper.

### Impact Explanation
If uncaught by any higher-level recover, this constitutes a crash of any node (including default-configuration public RPC/full nodes performing `eth_call`, `eth_estimateGas`, or transaction simulation against the malicious contract, and potentially validators during block execution/consensus if the message is included in a block), satisfying the "crash of default-configuration RPC nodes" / "block delay" / "validator halt" impact classes in this bug's class.

### Likelihood Explanation
Trivial and fully within reach of an unprivileged CosmWasm contract deployer: deploy any contract that answers `token_info`/`contract_info` with a non-string `name` or `symbol` (or omits them), then call `addCW20Pointer`/`addCW721Pointer`/`addCW1155Pointer` with that contract's address from any EVM account. No special privileges, races, or preconditions are required.

### Recommendation
Replace the raw type assertions with the comma-ok form and reject the pointer-creation request with an error (not a panic) when `name`/`symbol` are missing or not strings, mirroring the safe handling already used elsewhere (e.g., `result, ok := decoded[key]` pattern used in the JSON precompile). Apply the fix uniformly across `precompiles/pointer/pointer.go` and all legacy versions (`precompiles/pointer/legacy/v552`, `v555`, `v562`, `v614`, etc.) that contain the same pattern.

### Proof of Concept
1. Deploy a CosmWasm contract whose `{"token_info":{}}` (or `{"contract_info":{}}`) query handler returns `{"name": 12345, "symbol": null}` (or omits the fields).
2. From any EVM account, call `addCW20Pointer(contractAddr)` (or `addCW721Pointer`/`addCW1155Pointer`) on precompile `0x000000000000000000000000000000000000100b`.
3. Execution reaches `formattedRes["name"].(string)` at `precompiles/pointer/pointer.go:154` (or the CW721/CW1155 equivalents), which panics because the underlying value is not a `string`.
4. The panic is not recovered by the dynamic-gas precompile wrapper (which only recovers gas-meter panics), propagating up the call stack and crashing the executing node/RPC process handling that transaction or simulation.

	require.Nil(t, err)
	newAbi, err := abi.JSON(bytes.NewReader(abiBz))
	require.Nil(t, err)
	input, err := newAbi.Pack("decimals")
	require.Nil(t, err)

	precompile := common.NewDynamicGasPrecompile(newAbi, &MockDynamicGasPrecompileExecutor{panicWith: "boom", evmKeeper: k}, ethcommon.Address{}, "test")

	// Ample gas so the decode charges pass and the (panicking) executor runs.
	require.PanicsWithValue(t, "boom", func() {

	})
}
