### Title
Free PDA derivation via `translate_signers` — CPI signer-seed hashing bypasses `create_program_address_units` metering - ([File: program-runtime/src/cpi.rs])

### Summary
`cpi_common` charges a single flat `invoke_units` amount for the entire CPI call and then calls `translate_signers`, which performs up to `MAX_SIGNERS` (16) `Pubkey::create_program_address` (SHA256-based) derivations per CPI with zero additional compute-unit charge. This is inconsistent with the dedicated `sol_create_program_address`/`sol_try_find_program_address` syscalls, which explicitly charge `create_program_address_units` (1500 CU by default) for the identical hashing operation.

### Finding Description
`cpi_common` (program-runtime/src/cpi.rs:773-808) consumes only the flat `invoke_units` cost once at the top of the function: [1](#0-0) 

It then calls `translate_signers` to build the PDA signer list from the syscall's `signers_seeds_addr`/`signers_seeds_len` arguments: [2](#0-1) 

`translate_signers` bounds the number of signer-seed groups to `MAX_SIGNERS` (16) and the seeds per group to `MAX_SEEDS`, then for **each** signer performs a `Pubkey::create_program_address` call — the same SHA256-based PDA-derivation primitive exposed by the `sol_create_program_address` syscall — but never touches `invoke_context.compute_meter`: [3](#0-2) 

Compare this to the standalone syscall implementation, which explicitly charges `create_program_address_units` (1500 CU) *before* doing the identical `Pubkey::create_program_address` work: [4](#0-3) 

So the same expensive operation is priced at 1500 CU per call in one code path (`sol_create_program_address`) but is completely free (0 CU marginal cost beyond the flat `invoke_units` charge) when performed via CPI signer seeds in `translate_signers`. `MAX_SIGNERS` is defined as 16: [5](#0-4) 

An attacker program can invoke `sol_invoke_signed`/`invoke_signed` with 16 signer-seed arrays (each up to `MAX_SEEDS` short seeds) on every CPI call. Each such call would, if metered consistently with the standalone syscall, cost roughly `16 * 1500 = 24,000` CU just for PDA derivation, but instead it is absorbed into the single flat `invoke_units` charge (on the order of ~1000 CU, per `DEFAULT_INVOCATION_COST` in `execution_budget.rs`). This lets a program perform many more PDA derivations per compute-unit budget than intended, and because CPI calls can be looped, the aggregate real (hashing) work per instruction is not upper-bounded by the compute units charged.

This is distinct from, and not addressed by, the various byte-based CPI charges that do exist elsewhere in `cpi_common`/`translate_accounts_common`/`translate_instruction_c` (e.g. `cpi_bytes_per_unit`-based charges for account data, account metas, and account-info arrays) — those only price memory-copy work, not the seed-hashing (`create_program_address`) work done in `translate_signers`.

### Impact Explanation
This is a materially underpriced compute path: an unprivileged attacker program can perform CPU-expensive SHA256-based PDA derivations essentially for free by routing them through CPI signer seeds instead of the metered `sol_create_program_address` syscall. Repeated CPI invocations (each within `MAX_CALL_DEPTH`/`max_instruction_trace_length` limits, but that's per-instruction, and the loop can be at the top level of a single instruction) can accumulate substantial uncharged hashing work within a fixed compute-unit budget, causing excess validator wall-clock work per compute unit charged — a DoS-adjacent, compute-metering-integrity bug, matching Agave's "materially underpriced compute" bounty category.

### Likelihood Explanation
Fully reachable by an unprivileged attacker: deploy an SBF program that loops `invoke_signed`/`sol_invoke_signed` calls, each carrying `MAX_SIGNERS` (16) signer-seed groups with `MAX_SEEDS` short seed arrays. No special privileges, staked validators, or specific preconditions besides deploying and invoking one's own program are required. This is deterministic and fully repeatable in the SBF sandbox.

### Recommendation
Charge `create_program_address_units` (or an equivalent metered cost) in `translate_signers` for each `Pubkey::create_program_address` invocation performed while resolving CPI signer seeds, mirroring the metering already applied in `SyscallCreateProgramAddress`/`SyscallTryFindProgramAddress`. This should be applied per signer entry before or after the `create_program_address` call, consuming the compute meter via `invoke_context.compute_meter.consume_checked(...)`, and should fail with `ComputationalBudgetExceeded` if the caller runs out of CU, consistent with the standalone syscall's behavior.

### Proof of Concept
Add a unit test in `program-runtime/src/cpi.rs` test module (near `test_translate_accounts_rust`) that mocks an `InvokeContext` with a small compute-unit budget, then calls `translate_signers` with `MAX_SIGNERS` (16) signer-seed groups, and asserts that the compute meter is decremented by an amount consistent with `create_program_address_units * num_signers` — currently this assertion would fail because `translate_signers` charges 0.

```rust
#[test]
fn test_translate_signers_underpriced_pda_derivation() {
    // Set up a mock InvokeContext with a compute budget of e.g. 100 CU
    // (far less than 16 * create_program_address_units == 24_000 CU).
    mock_invoke_context!(invoke_context, transaction_context, b"ix data", transaction_accounts, 0, &[]);
    invoke_context.compute_meter.mock_set_remaining(100);

    let program_id = Pubkey::new_unique();
    // Build signers_seeds memory region encoding MAX_SIGNERS (16) valid,
    // create_program_address-able seed groups pointing at VM memory.
    // ... construct memory_mapping with 16 SolSignerSeeds entries ...

    let result = translate_signers(&program_id, signers_seeds_addr, 16, &invoke_context);

    // Expected (after fix): should fail with ComputationalBudgetExceeded
    // because 16 * create_program_address_units (1500) = 24_000 CU > 100 CU remaining.
    assert!(result.is_err());
    // Actual (current behavior, bug): translate_signers succeeds and the
    // compute meter still shows ~100 CU remaining, proving 16 PDA
    // derivations were performed for free.
    assert_eq!(invoke_context.compute_meter.get_remaining(), 100);
}
```

This test would currently pass with `compute_meter` unchanged (proving the free hashing), and after applying the recommended fix (charging `create_program_address_units` per signer) the call should instead return a `ComputationalBudgetExceeded` error given an insufficient CU budget, matching the behavior of `SyscallCreateProgramAddress`/`SyscallTryFindProgramAddress` in `syscalls/src/lib.rs`.

```rust
pub fn translate_signers(
    program_id: &Pubkey,
    signers_seeds_addr: u64,
    signers_seeds_len: u64,
    invoke_context: &InvokeContext,
) -> Result<Vec<Pubkey>, Error> {
    let check_aligned = invoke_context.get_check_aligned();
    let memory_mapping = invoke_context.memory_contexts.memory_mapping()?;
    if signers_seeds_len > 0 {
        let signers_seeds = translate_slice::<VmSlice<VmSlice<u8>>>(
            memory_mapping,
            signers_seeds_addr,
            signers_seeds_len,
            check_aligned,
        )?;
        if signers_seeds.len() > MAX_SIGNERS {
            return Err(Box::new(CpiError::TooManySigners));
        }
        Ok(signers_seeds
            .iter()
            .map(|signer_seeds| {
                let untranslated_seeds = translate_slice::<VmSlice<u8>>(
                    memory_mapping,
                    signer_seeds.ptr(),
                    signer_seeds.len(),
                    check_aligned,
                )?;
                if untranslated_seeds.len() > MAX_SEEDS {
                    return Err(Box::new(InstructionError::MaxSeedLengthExceeded) as Error);
                }
                let seeds_bytes = untranslated_seeds
                    .iter()
                    .map(|untranslated_seed| {
                        translate_vm_slice(untranslated_seed, memory_mapping, check_aligned)
                    })
                    .collect::<Result<Vec<_>, Error>>()?;
                Pubkey::create_program_address(&seeds_bytes, program_id)
                    .map_err(|err| Box::new(CpiError::BadSeeds(err)) as Error)
            })
            .collect::<Result<Vec<_>, Error>>()?)
    } else {
        Ok(vec![])
    }
}
```
