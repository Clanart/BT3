### Title
Coinbase outputs are reported as spendable, enabling invalid withdrawal transactions - ([File: networks/bitcoin/src/wallet/mod.rs](networks/bitcoin/src/wallet/mod.rs))

### Summary
`Scanner::scan_block` scans every transaction in a block, including the coinbase transaction, and converts matching outputs into `ReceivedOutput` values without checking coinbase maturity. A miner can therefore cause Serai's Bitcoin wallet layer to report funds as received before consensus permits them to be spent. If that output is supplied to `SignableTransaction::new`, Serai constructs and signs a transaction that Bitcoin nodes will reject until the coinbase matures, delaying or preventing withdrawals.

### Finding Description
`Scanner::scan_block` iterates over `block.txdata` from index 0 and passes every transaction to `scan_transaction` [1](#0-0) . `scan_transaction` treats any output whose `script_pubkey` is registered as a `ReceivedOutput`, without checking whether its containing transaction is a coinbase [2](#0-1) . The function's own documentation acknowledges that the coinbase is scanned even though it is bound by maturity [3](#0-2) .

`SignableTransaction::new` accepts attacker-provided `ReceivedOutput`s and converts each recorded outpoint directly into a transaction input [4](#0-3) . No coinbase-confirmation check is performed before the transaction is returned for signing [5](#0-4) . The signing path then computes a Taproot sighash for every supplied previous output and produces signatures for the invalid spend [6](#0-5) .

### Impact Explanation
A miner who directs a coinbase output to a watched Serai address can make the scanner report a balance that is not currently spendable. If that output is selected for a withdrawal or consolidation transaction, the resulting transaction is cryptographically valid but consensus-invalid until maturity. Broadcast failure can therefore stall the intended withdrawal and poison automated input selection with a temporarily unusable UTXO.

### Likelihood Explanation
The attacker must produce a Bitcoin block paying the watched script, so exploitation is not available to an arbitrary transaction sender at negligible cost. It requires no validator key, private state, malformed encoding, or protocol violation, however; the miner uses ordinary public transaction data. The affected path is explicitly exposed by the public `scan_block` API.

### Recommendation
Do not return coinbase outputs from `Scanner::scan_block`, or include enough metadata in `ReceivedOutput` for callers to enforce the required maturity. At a minimum, skip `block.txdata[0]` in `scan_block`; additionally reject coinbase outpoints in `SignableTransaction::new` unless the caller supplies confirmation height proving maturity.

### Proof of Concept
1. Create a `Scanner` for an even Taproot key and register the desired offset.
2. Mine a block whose coinbase transaction pays that scanner's `p2tr_script_buf` address.
3. Call `scanner.scan_block(&block)`.
4. The returned `ReceivedOutput` has the coinbase transaction ID and vout despite lacking the required confirmations.
5. Pass that `ReceivedOutput` to `SignableTransaction::new` with any valid payment and fee.
6. Call `multisig`, `preprocess`, `sign`, and `complete`; Serai produces a signed transaction spending the immature coinbase.
7. Bitcoin broadcast/validation rejects the transaction because the coinbase input is immature.
