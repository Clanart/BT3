### Title
Payout attribution is self-declared via an unsigned OP_RETURN, letting anyone frame a different operator as reimbursable for a payout it never funded - (File: `core/src/verifier.rs`)

### Summary
The protocol credits an operator for having "fronted" a peg-out purely by parsing an unsigned `OP_RETURN` output of the payout transaction on-chain, with no cryptographic binding between that embedded x-only pubkey and whoever actually funded/broadcast the payout. This breaks the equality *operator credited == party that paid*, mirroring the Axelar bug class where an action recorded on one side (burn) is not actually bound to what happened on the other side (successful destination execution) — here, "who is credited with reimbursement" is not bound to "who actually paid."

### Finding Description
When constructing a payout transaction, the operator xonly pubkey that will later be credited for the withdrawal is written into a plain `OP_RETURN` output that carries no signature or commitment tying it to the transaction's actual funder: [1](#0-0) 

The user's signature (`user_sig`) only authorizes spending of the withdrawal input to the specific payout output (key-spend of input 0); it says nothing about the `OP_RETURN` output's contents, so any party capable of constructing this transaction (the withdrawal input's signature is delivered "off-chain" and the output amount/address are attacker-known from the Citrea withdrawal request) can insert an arbitrary operator's xonly pubkey there instead of their own.

When the chain syncer later processes the block, it reads the attribution straight from this OP_RETURN with no additional check that the embedded pubkey corresponds to who actually paid the fees/funded the transaction: [2](#0-1) 

This self-declared value is persisted directly into the `withdrawals` table: [3](#0-2) 

Each operator's own `PayoutCheckerTask` then picks up any withdrawal row where `payout_payer_operator_xonly_pk` equals its own key, and automatically drives the reimbursement flow (`handle_finalized_payout`), fetching the light-client proof and eventually enabling the kickoff/reimburse transaction sequence, purely because the OP_RETURN said so: [4](#0-3) [5](#0-4) 

The malicious-kickoff check (`is_kickoff_malicious`) only verifies that the kickoff's `operator_xonly_pk` matches the `payout_payer_operator_xonly_pk` stored from the OP_RETURN — it never verifies that this operator was the one who economically funded the payout to the user: [6](#0-5) 

Thus the binding that should hold — *operator credited with a payout == operator who fronted the BTC to the user* — is broken. Anyone can construct and broadcast the withdrawal-spending transaction (paying the user with their own funds, or via funds not attributable to the framed operator) while stamping a victim operator's pubkey into the OP_RETURN. That victim operator's own automation (`PayoutCheckerTask`) will then treat the payout as "its own" unhandled payout and proceed to claim reimbursement from the vault (`MoveToVault`/`Reimburse` flow), even though it never funded anything.

### Impact Explanation
This matches the Critical impact category "an operator reimbursed for a payout it never funded." The operator whose pubkey is falsely stamped is nudged (or, under `#[cfg(feature = "automation")]`, automatically driven) to spend real kickoff/round transactions and ultimately withdraw funds from the shared vault (`Reimburse` output in `core/src/builder/transaction/operator_reimburse.rs:341-385`) for a peg-out someone else paid — improperly transferring vault BTC to an operator without a matching fronted withdrawal. Conversely, the operator who actually paid the user has no recorded attribution and can never claim reimbursement for that deposit, permanently losing the fronted funds ("an honest operator permanently unable to be reimbursed").

### Likelihood Explanation
The withdrawal input UTXO's spending authorization (the user's signature) is described as being handed to operators "off-chain," and the amount/output address of a pending Citrea withdrawal request are observable on Citrea. No proof-of-funding or signature is required over the OP_RETURN field, so constructing a payout transaction with an arbitrary operator's pubkey requires no privileged access beyond the withdrawal signature that operators normally receive — this is reachable by any actor able to obtain or intercept that off-chain signature and broadcast a transaction, without needing verifier/operator private keys.

### Recommendation
Bind payout attribution cryptographically to the actual funder instead of trusting an unsigned OP_RETURN: require the payout transaction's funding input(s)/CPFP anchor spend to be signed by (or otherwise provably controlled by) the operator whose pubkey is recorded, or have the operator co-sign a commitment (e.g., via a Taproot script path keyed to the operator, or a MuSig2 partial signature covering the OP_RETURN data) before `update_finalized_payouts` attributes the payout to that operator. Reject/flag payouts whose OP_RETURN attribution cannot be corroborated by a signature from the claimed operator's key.

### Proof of Concept
1. Observe (or receive off-chain, as normal operator would) the user's `in_signature`/`in_outpoint`/`out_script_pubkey`/`out_amount` for a pending Citrea withdrawal.
2. Build the payout transaction as in `create_payout_txhandler` (`core/src/builder/transaction/operator_reimburse.rs:407-435`), using the legitimate signature/output but substituting a different, victim operator's `operator_xonly_pk` in the `op_return_txout`.
3. Broadcast the transaction; it confirms because the only signature check is on the key-spend input (user's authorization), not on the OP_RETURN.
4. The chain syncer's `update_finalized_payouts` (`core/src/verifier.rs:2312-2343`) parses the OP_RETURN and records `payout_payer_operator_xonly_pk` = victim operator.
5. Victim operator's `PayoutCheckerTask` (`core/src/task/payout_checker.rs:39-79`) picks this up as an unhandled payout under its own key and proceeds through `handle_finalized_payout`, eventually enabling a `Kickoff`/`Reimburse` transaction that pays the victim operator from the shared vault — for a withdrawal it never funded — while the real funder has no recorded claim to reimbursement.

pub fn create_payout_txhandler(
    input_utxo: UTXO,
    output_txout: TxOut,
    operator_xonly_pk: XOnlyPublicKey,
    user_sig: taproot::Signature,
    _network: bitcoin::Network,
) -> Result<TxHandler<Signed>, BridgeError> {
    let txin = SpendableTxIn::new_partial(input_utxo.outpoint, input_utxo.txout);

    let output_txout = UnspentTxOut::from_partial(output_txout.clone());

    let op_return_txout = op_return_txout(PushBytesBuf::from(operator_xonly_pk.serialize()));

    let mut txhandler = TxHandlerBuilder::new(TransactionType::Payout)
        .with_version(NON_STANDARD_V3)
        .add_input(
            NormalSignatureKind::NotStored,
            txin,
            SpendPath::KeySpend,
            DEFAULT_SEQUENCE,
        )
        .add_output(output_txout)
        .add_output(UnspentTxOut::from_partial(anchor_output(
            NON_EPHEMERAL_ANCHOR_AMOUNT,
        )))
        .add_output(UnspentTxOut::from_partial(op_return_txout))
        .finalize();
    txhandler.set_p2tr_key_spend_witness(&user_sig, 0)?;
    txhandler.promote()

    /// Sets the given payout txs' txid and operator index for the given index.
    pub async fn update_payout_txs_and_payer_operator_xonly_pk(
        &self,
        tx: Option<DatabaseTransaction<'_>>,
        payout_txs_and_payer_operator_xonly_pk: Vec<(
            u32,
            Txid,
            Option<XOnlyPublicKey>,
            bitcoin::BlockHash,
        )>,
    ) -> Result<(), BridgeError> {
        if payout_txs_and_payer_operator_xonly_pk.is_empty() {
            return Ok(());
        }
        // Convert all values first, propagating any errors
        let converted_values: Result<Vec<_>, BridgeError> = payout_txs_and_payer_operator_xonly_pk
            .iter()
            .map(|(idx, txid, operator_xonly_pk, block_hash)| {
                Ok((
                    i32::try_from(*idx).wrap_err("Failed to convert payout index to i32")?,
                    TxidDB(*txid),
                    operator_xonly_pk.map(XOnlyPublicKeyDB),
                    BlockHashDB(*block_hash),
                ))
            })
            .collect();
        let converted_values = converted_values?;

        let mut query_builder = QueryBuilder::new(
            "UPDATE withdrawals AS w SET
                payout_txid = c.payout_txid,
                payout_payer_operator_xonly_pk = c.payout_payer_operator_xonly_pk,
                payout_tx_blockhash = c.payout_tx_blockhash
                FROM (",
        );

        query_builder.push_values(
            converted_values.into_iter(),
            |mut b, (idx, txid, operator_xonly_pk, block_hash)| {
                b.push_bind(idx)
                    .push_bind(txid)
                    .push_bind(operator_xonly_pk)
                    .push_bind(block_hash);
            },
        );

        query_builder
            .push(") AS c(idx, payout_txid, payout_payer_operator_xonly_pk, payout_tx_blockhash) WHERE w.idx = c.idx");

        let query = query_builder.build();
        execute_query_with_tx!(self.connection, tx, query, execute)?;

        Ok(())
    }

    /// For a deposit_id checks that the payer for that deposit is the operator, and the payout blockhash and kickoff txid are set.
    async fn validate_payer_is_operator(
        &self,
        dbtx: Option<DatabaseTransaction<'_>>,
        deposit_id: u32,
    ) -> Result<(BlockHash, Txid), BridgeError> {
        let (payer_xonly_pk, payout_blockhash, kickoff_txid) = self
            .db
            .get_payer_xonly_pk_blockhash_and_kickoff_txid_from_deposit_id(dbtx, deposit_id)
            .await?;

        tracing::info!(
            "Payer xonly pk and kickoff txid found for the requested deposit, payer xonly pk: {:?}, kickoff txid: {:?}",
            payer_xonly_pk,
            kickoff_txid
        );

        // first check if the payer is the operator, and the kickoff is handled
        // by the PayoutCheckerTask, meaning kickoff_txid is set
        let (payout_blockhash, kickoff_txid) = match (
            payer_xonly_pk,
            payout_blockhash,
            kickoff_txid,
        ) {
            (Some(payer_xonly_pk), Some(payout_blockhash), Some(kickoff_txid)) => {
                if payer_xonly_pk != self.signer.xonly_public_key {
                    return Err(eyre::eyre!(
                        "Payer is not own operator for deposit, payer xonly pk: {:?}, operator xonly pk: {:?}",
                        payer_xonly_pk,
                        self.signer.xonly_public_key
                    )
                    .into());
                }
                (payout_blockhash, kickoff_txid)
            }
            _ => {
                return Err(eyre::eyre!(
                    "Payer info not found for deposit, payout blockhash: {:?}, kickoff txid: {:?}",
                    payout_blockhash,
                    kickoff_txid
                )
                .into());
            }
        };

        tracing::info!(
            "Payer xonly pk, payout blockhash and kickoff txid found and valid for own operator for the requested deposit id: {}, payer xonly pk: {:?}, payout blockhash: {:?}, kickoff txid: {:?}",
            deposit_id,
            payer_xonly_pk,
            payout_blockhash,
            kickoff_txid
        );

        Ok((payout_blockhash, kickoff_txid))
    }
