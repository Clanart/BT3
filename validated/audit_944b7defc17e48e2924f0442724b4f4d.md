### Title
Spoofed `WWW-Authenticate` realm from a malicious git remote misclassifies host as a trusted GitHub Enterprise endpoint, triggering an unrequested OAuth sign-in flow to an attacker-controlled origin - (File: app/src/lib/trampoline/trampoline-credential-helper.ts)

### Summary
The DeFi report's broken invariant is that a callback-supplied value (attacker-controlled during the callback) is trusted to decide how much should be repaid/settled, without independent verification, letting the attacker corrupt the settlement outcome. The closest verifiable Desktop analog is `getEndpointKind` in the credential-helper trampoline: it classifies a remote as a GitHub/Enterprise host based on the `WWW-Authenticate` header value that git forwards from the *remote HTTP server's response* — attacker-controlled input arriving via a callback path (the credential-helper protocol) — without any independent verification (e.g. querying `/meta` or checking a known cert/host list) before that classification drives security-relevant UI/OAuth behavior.

### Finding Description
`getEndpointKind` in [1](#0-0)  decides whether a credential request is for `'github.com'`, `'enterprise'`, or `'generic'`. Part of that decision is based purely on the `wwwauth[]` credential fields: [2](#0-1) 

These `wwwauth[...]` values originate from the `WWW-Authenticate` HTTP response header sent by the remote git server, which git's credential protocol forwards verbatim to the configured credential helper (Desktop's trampoline, via `credential.helper=desktop`, see [3](#0-2) ). A fully attacker-controlled HTTPS remote (or a proxy/MITM able to answer the initial unauthenticated request) can simply respond with `WWW-Authenticate: Basic realm="GitHub"` to force `getEndpointKind` to return `'enterprise'` for a host that is not a real GitHub Enterprise instance.

That classification feeds directly into `getCredential`: [4](#0-3) 

Because `endpointKind !== 'generic'` and no account exists for the attacker's arbitrary `apiEndpoint`, Desktop calls `ui.promptForGitHubSignIn(endpoint)`, which — for any non-`github.com` host — invokes `beginEnterpriseSignIn` and then `setSignInEndpoint(origin)` where `origin` is the attacker's own host: [5](#0-4) 

`SignInStore.setEndpoint` only performs syntactic/protocol validation (`https://`), never verifying that the host is an actual GitHub Enterprise API (no reachability/`meta` check is done at this stage): [6](#0-5) 

This means an unprivileged, remote, attacker-controlled git host can — purely by sending a crafted `WWW-Authenticate` header during a normal `git fetch`/`clone`/`push` — cause Desktop's own trusted "Sign in to GitHub Enterprise" UI flow (and subsequent browser-based OAuth authorization request) to be initiated against a host of the attacker's choosing, without the user ever typing that URL into the Enterprise sign-in box.

### Impact Explanation
If a user has such a remote configured (or is lured to add/fetch from one), an ordinary `git fetch`/`clone` operation that returns a 401 with a spoofed `WWW-Authenticate: realm="GitHub"` header causes Desktop to legitimize the attacker's host as a "GitHub Enterprise" endpoint and open the standard, trusted-looking sign-in/browser-authentication flow pointed at that host. This is a confused-deputy condition: Desktop's own credential/sign-in UI (which users are trained to trust because Desktop initiated it, not a link they clicked) is used to funnel the user toward providing credentials or completing OAuth against an attacker-controlled origin, and any OAuth code returned is exchanged via `requestOAuthToken(endpoint, action.code)` against that same attacker-controlled `endpoint`. Depending on what shared secrets/parameters the enterprise OAuth exchange call sends (I was not able to fully verify from the index whether a static client secret is included in `requestOAuthToken`/`api.ts`, and note this as an open question requiring a full read of `app/src/lib/api.ts`), this could exfiltrate OAuth material to the attacker or otherwise deceive the user into supplying credentials to a spoofed but Desktop-legitimized flow.

### Likelihood Explanation
The trigger requires only an unprivileged attacker who controls (or can respond as) an HTTPS git remote/proxy that the user's Desktop performs an authenticated git operation against — no local access, no prior malware, and no leaked credentials are needed. The only "unnatural" step is the user clicking through the Desktop-presented sign-in prompt, which is materially different from typical social engineering because the prompt is generated and hosted entirely inside GitHub Desktop's own trusted UI, not an external link.

### Recommendation
Do not derive trust-affecting endpoint classification (`'enterprise'`) solely from an unauthenticated, remote-controlled `WWW-Authenticate` header. Before offering a GitHub Enterprise sign-in/OAuth flow, independently verify the candidate host (e.g., via a GitHub Enterprise `/meta` endpoint check, matching against previously verified/known enterprise endpoints, or requiring explicit, out-of-band user confirmation naming the exact host) before initiating `promptForGitHubSignIn` / `setSignInEndpoint`.

### Proof of Concept
1. Set up a malicious HTTPS git server (or MITM proxy) that serves a valid-looking git-http-backend but responds to the initial unauthenticated request with `HTTP/1.1 401` and header `WWW-Authenticate: Basic realm="GitHub"`.
2. In GitHub Desktop, add this URL as a remote for a repository and perform `git fetch` (this can be done by simply cloning an attacker-supplied remote URL).
3. Git invokes the `desktop` credential helper trampoline with the `wwwauth[]` field containing `realm="GitHub"`.
4. `getEndpointKind` returns `'enterprise'` for the attacker's arbitrary host [7](#0-6) .
5. Since no existing account matches the attacker's `apiEndpoint`, Desktop calls `ui.promptForGitHubSignIn(endpoint)` [8](#0-7) , which opens the "Sign in to GitHub Enterprise" dialog scoped to the attacker's host [5](#0-4) , with no reachability/authenticity check performed on that host by `setEndpoint` [9](#0-8) .

/** Implementation of the 'get' git credential helper command */
async function getCredential(cred: Credential, store: Store, token: string) {
  const ghCred = await getGitHubCredential(cred, store)

  if (ghCred) {
    return ghCred
  }

  const endpointKind = await getEndpointKind(cred, store)
  const accounts = await store.getAll()

  const endpoint = `${getCredentialUrl(cred)}`
  const apiEndpoint = getAPIEndpoint(endpoint)

  // If it appears as if the endpoint is a GitHub host and we don't have an
  // account for that endpoint then we should prompt the user to sign in.
  if (
    endpointKind !== 'generic' &&
    !accounts.some(a => a.endpoint === apiEndpoint)
  ) {
    if (getIsBackgroundTaskEnvironment(token)) {
      debug('background task environment, skipping prompt')
      return undefined
    }

    const account = await ui.promptForGitHubSignIn(endpoint)

    if (!account) {
      setHasRejectedCredentialsForEndpoint(token, endpoint)
    }

    return credWithAccount(cred, account)
  }

const getEndpointKind = async (cred: Credential, store: Store) => {
  const credentialUrl = getCredentialUrl(cred)
  const endpoint = `${credentialUrl}`

  if (isGist(endpoint)) {
    return 'generic'
  }

  if (isDotCom(endpoint)) {
    return 'github.com'
  }

  if (isGHE(endpoint)) {
    return 'ghe.com'
  }

  // When Git attempts to authenticate with a host it captures any
  // WWW-Authenticate headers and forwards them to the credential helper. We
  // use them as a happy-path to determine if the host is a GitHub host without
  // having to resort to making a request ourselves.
  for (const [k, v] of cred.entries()) {
    if (k.startsWith('wwwauth[')) {
      if (v.includes('realm="GitHub"')) {
        return 'enterprise'
      } else if (/realm="(GitLab|Gitea|Atlassian Bitbucket)"/.test(v)) {
        return 'generic'
      }
    }
  }

  const existingAccount = await findGitHubTrampolineAccount(store, endpoint)
  if (existingAccount) {
    return isDotCom(existingAccount.endpoint) ? 'github.com' : 'enterprise'
  }

  // All GitHub hosts use HTTPS, so if the protocol is not HTTPS we can
  // assume that this is not a GitHub host.
  if (credentialUrl.protocol !== 'https:') {
    return 'generic'
  }

  return (await isGitHubHost(endpoint)) ? 'enterprise' : 'generic'

  public promptForGitHubSignIn(endpoint: string): Promise<Account | undefined> {
    return new Promise<Account | undefined>(async resolve => {
      const cb = (result: SignInResult) => {
        resolve(result.kind === 'success' ? result.account : undefined)
        this.dispatcher.closePopup(PopupType.SignIn)
      }

      const { hostname, origin } = new URL(endpoint)
      if (hostname === 'github.com') {
        this.dispatcher.beginDotComSignIn(cb)
      } else {
        this.dispatcher.beginEnterpriseSignIn(cb)
        await this.dispatcher.setSignInEndpoint(origin)
      }

      this.dispatcher.showPopup({
        type: PopupType.SignIn,
        isCredentialHelperSignIn: true,
        credentialHelperUrl: endpoint,
      })
    }).catch(e => {
      log.error(`Could not prompt for GitHub sign in`, e)
      return undefined
    })
  }

  public async setEndpoint(url: string): Promise<void> {
    const currentState = this.state

    if (
      currentState?.kind !== SignInStep.EndpointEntry &&
      currentState?.kind !== SignInStep.ExistingAccountWarning
    ) {
      const stepText = currentState ? currentState.kind : 'null'
      return fatalError(
        `Sign in step '${stepText}' not compatible with endpoint entry`
      )
    }

    /**
     * If the user enters a github.com url in the GitHub Enterprise sign-in
     * flow we'll redirect them to the GitHub.com sign-in flow.
     */
    if (/^(?:https:\/\/)?(?:api\.)?github\.com($|\/)/.test(url)) {
      this.beginDotComSignIn(currentState.resultCallback)
      return
    }

    this.setState({ ...currentState, loading: true })

    let validUrl: string
    try {
      validUrl = validateURL(url)
    } catch (e) {
      let error = e
      if (e.name === InvalidURLErrorName) {
        error = new Error(
          `The GitHub Enterprise instance address doesn't appear to be a valid URL. We're expecting something like https://example.ghe.com.`
        )
      } else if (e.name === InvalidProtocolErrorName) {
        error = new Error(
          'Unsupported protocol. Only https is supported when authenticating with GitHub Enterprise instances.'
        )
      }

      this.setState({ ...currentState, loading: false, error })
      return
    }

    const endpoint = getEnterpriseAPIURL(validUrl)

    const existingAccount = this.accounts.find(x => x.endpoint === endpoint)

    if (existingAccount) {
      this.setState({
        kind: SignInStep.ExistingAccountWarning,
        endpoint,
        existingAccount,
        error: null,
        loading: false,
        resultCallback: currentState.resultCallback,
      })
    } else {

        kind: SignInStep.Authentication,
        endpoint,
        error: null,
