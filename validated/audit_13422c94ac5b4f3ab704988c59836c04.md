### Title
Unrestricted 1:1 `mWOM.deposit()` minting enables flash-loan arbitrage that drains the WOM/mWOM pool - (File: wombat/mWOM.sol)

### Summary
`mWOM.sol` exposes a public `deposit()` function that mints mWOM at a fixed, unconditional 1:1 rate against WOM, with no check on the prevailing WOM/mWOM market price and no per-transaction cap. Whenever the WOM/mWOM AMM pool (`womMWomPool`, referenced throughout `SmartWomConvert.sol`) trades mWOM above parity, any wallet can mint mWOM at the guaranteed 1:1 rate and immediately dump it into that pool for more than 1 WOM per mWOM, extracting the premium directly from the pool's WOM reserves. This is the same bug class as the Fei `BondingCurve` report: a fixed/discounted minting rate combined with an on-chain sale venue creates a risk-free, flash-loanable arbitrage that can be scaled to drain protocol-owned/LP liquidity in a single transaction.

### Finding Description
`mWOM.deposit()` calls the internal `_convert()` path with `_doConvert = false`, which unconditionally mints `_amount` mWOM to the caller for `_amount` WOM transferred in, with no reference to market price: [1](#0-0) [2](#0-1) 

The protocol's own `SmartWomConvert` contract acknowledges that the 1:1 mint rate is only safe when the market ratio is at/above a threshold — it computes `currentRatio()` (the AMM price of mWOM in WOM terms via `womMWomPool`) and, only when that ratio falls *below* `buybackThreshold`, forces a portion of the conversion through the AMM instead of the 1:1 mint: [3](#0-2) 

However, this protection lives entirely in `SmartWomConvert`, and only guards the low-price direction. It is not enforced by `mWOM.sol` itself, whose `deposit()`/`convert()` functions are directly and permissionlessly callable by any wallet, bypassing `SmartWomConvert` altogether: [4](#0-3) 

When the market price of mWOM on `womMWomPool` rises above 1:1 WOM (e.g., due to demand for locking exposure via `mWomSV`/vlMGP-style mechanics), a fixed 1:1 mint is strictly better than buying mWOM on the AMM. Nothing stops a wallet from:
1. Minting mWOM 1:1 via `mWOM.deposit()`.
2. Immediately swapping that mWOM for WOM on `womMWomPool` (via the Wombat router used elsewhere in `SmartWomConvert.sol`, e.g. `IWombatRouter.swapExactTokensForTokens`) at the elevated price.
3. Pocketing the difference, extracted from the pool's WOM reserves.

Because `deposit()` has no size limit, this arbitrage can be scaled with a WOM flash loan to the full depth of the pool's price deviation in a single transaction, exactly mirroring the Fei report's flash-loan-amplified `BondingCurve` drain.

### Impact Explanation
Each time the WOM/mWOM pool price deviates above parity, an attacker can extract real WOM value from that pool's liquidity in one atomic, flash-loanable transaction, directly transferring value from LPs/protocol-owned liquidity in `womMWomPool` to the attacker and collapsing the mWOM peg abruptly rather than through gradual, bounded arbitrage. This is a direct theft of pooled funds and causes acute price volatility for all mWOM holders and stakers relying on the peg.

### Likelihood Explanation
Likelihood is high: `mWOM.deposit()` has no access control beyond `whenNotPaused`, no rate/size limiting, and no price-band check, so any premium on `womMWomPool` — however transient — is immediately and fully exploitable by any wallet, and the attack is trivially sized via flash loan to maximize extraction with no capital risk.

### Recommendation
Enforce the same price-band protection inside `mWOM.sol` itself (not only in the optional `SmartWomConvert` wrapper): check the current `womMWomPool` ratio before allowing 1:1 minting, cap the amount mintable at 1:1 per block/transaction, or route all conversions exclusively through `SmartWomConvert`'s threshold-aware logic by restricting `mWOM.deposit()`/`convert()` to be callable only by the vetted helper contract.

### Proof of Concept
1. Attacker observes `womMWomPool` pricing mWOM above 1 WOM (via `SmartWomConvert.currentRatio()` logic reused directly against the router).
2. Attacker flash-borrows a large amount of WOM.
3. Attacker calls `mWOM.deposit(amount)` [1](#0-0)  minting `amount` mWOM 1:1, no price check performed.
4. Attacker swaps the minted mWOM back into WOM through `womMWomPool` at the elevated market rate, receiving more WOM than deposited.
5. Attacker repays the flash loan and keeps the difference, having drained WOM from the pool's reserves and crashed the mWOM price.

    function smartConvert(uint256 _amountIn, uint256 _mode) external returns (uint256 obtainedmWomAmount) {
        if (_amountIn == 0) revert MustNoBeZero();

        uint256 convertRatio = DENOMINATOR;
        uint256 mWomToWom = currentRatio();

        if (mWomToWom < buybackThreshold) {
            uint256 maxSwap = maxSwapAmount();
            uint256 amountToSwap = _amountIn > maxSwap ? maxSwap : _amountIn;
            uint256 convertAmount = _amountIn - amountToSwap;
            convertRatio = convertAmount * DENOMINATOR / _amountIn;
        }

        return _convertFor(_amountIn, convertRatio, _amountIn, msg.sender, _mode);
    }
