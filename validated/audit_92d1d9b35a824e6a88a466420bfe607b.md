### Title
`ThresholdKeys::read` accepts inconsistent, attacker-crafted key material yielding a group key whose full private key the attacker knows - (File: crypto/dkg/src/lib.rs)

### Summary
Analogous to the Any23 YAMLExtractor RCE (untrusted input deserialized into dangerous object state), Serai deserializes `ThresholdKeys` from raw bytes without ever verifying that the `secret_share` is consistent with `verification_shares[i]`, nor that a `Constant` interpolation's coefficients are consistent with the shares. A fully attacker-crafted blob deserializes into valid-looking threshold keys whose group key's discrete logarithm the attacker knows.

### Finding Description
`ThresholdKeys::read` (crypto/dkg/src/lib.rs:574-632) reads `t`, `n`, `i`, the interpolation blob, `secret_share`, and `n` verification shares purely from the input stream, then calls `ThresholdKeys::new`. `ThresholdKeys::new` (crypto/dkg/src/lib.rs:349-378) only checks:

- `verification_shares.len() == n` and participant indices `<= n` (lines 355-365)
- for `Interpolation::Constant`, `t == n` (lines 367-372)
- computes `group_key` as the interpolation over `verification_shares[1..=t]` (lines 376-378)

It never checks `secret_share * C::generator() == verification_shares[i]` — there is no binding between the deserialized secret share and the verification-share map. For `Interpolation::Constant`, the coefficient vector is also never validated against the shares (e.g., `interpolate(coeffs, i) * G` vs share points). Every scalar and point is canonical (via `C::read_F`/`C::read_G`, crypto/ciphersuite/src/lib.rs:74-101), so encoding checks pass.

An attacker supplies bytes where they chose scalars `y_1..y_n` and set `verification_shares[l] = g*y_l`, `secret_share = y_i`. Deserialization succeeds, `group_key` interpolates to `g*f(0)` where the attacker knows `f(0)`, and `view()`/`original_verification_share` all behave consistently for the victim — the shares are internally coherent, just entirely attacker-constructed. The victim then operates (FROST sign, `ThresholdView`, processor spend path) believing the group key is a genuine threshold key, while the attacker holds the complete private key.

### Impact Explanation
Any key recovery / unintended-signing outcome follows directly: the attacker knows the full discrete log of `group_key`, so any funds locked to it (Bitcoin outputs, Ethereum key, etc.) are fully spendable by the attacker alone, and any signature produced "under" these keys corresponds to a key the attacker controls. This is not a malformed-encoding rejection miss; it is silent acceptance of semantically inconsistent key material, mirroring the Any23 class where deserializing untrusted content produces a dangerously constructed object.

### Likelihood Explanation
Reachability requires an attacker to supply the serialized `ThresholdKeys` blob (e.g., a crafted backup/import file or any pipeline feeding untrusted bytes to `ThresholdKeys::read`, which the scope rules enumerate as a reachable surface). If keys are only ever loaded from self-generated local files, likelihood drops; where restoration/import paths accept external data, it is a deterministic, zero-cost attack — no brute force, no collusion needed.

### Recommendation
In `ThresholdKeys::new` (and transitively `read`), verify `secret_share * C::generator() == verification_shares[&params.i()]`, and for `Interpolation::Constant` verify the coefficient-derived share points equal the verification shares for all `1..=n`. Optionally authenticate the serialization (e.g., MAC over the blob or compare a stored group-key digest) so externally supplied key files cannot substitute attacker-controlled material.

buf.extend(y1.to_repr().as_ref()); // secret_share for participant 1
for y in [y1, y2, y3] {

}

let keys = ThresholdKeys::<C>::read(&mut buf.as_slice()).unwrap();
// Succeeds: no check binds secret_share to verification_shares[Participant(1)]

// so the "threshold" key is a single-party key fully known to the attacker.

  pub fn new(
    params: ThresholdParams,
    interpolation: Interpolation<C::F>,
    secret_share: Zeroizing<C::F>,
    verification_shares: HashMap<Participant, C::G>,
  ) -> Result<ThresholdKeys<C>, DkgError> {
    if verification_shares.len() != usize::from(params.n()) {
      Err(DkgError::IncorrectAmountOfVerificationShares {
        n: params.n(),
        shares: verification_shares.len(),
      })?;
    }
    for participant in verification_shares.keys().copied() {
      if u16::from(participant) > params.n() {
        Err(DkgError::InvalidParticipant { n: params.n(), participant })?;
      }
    }

    match &interpolation {
      Interpolation::Constant(_) => {
        if params.t() != params.n() {
          Err(DkgError::InapplicableInterpolation("constant interpolation for keys where t != n"))?;
        }
      }
      Interpolation::Lagrange => {}
    }

    let t = (1 ..= params.t()).map(Participant).collect::<Vec<_>>();
    let group_key =
      t.iter().map(|i| verification_shares[i] * interpolation.interpolation_factor(*i, &t)).sum();

    Ok(ThresholdKeys {
      core: Arc::new(Zeroizing::new(ThresholdCore {
        params,
        interpolation,
        secret_share,
        group_key,
        verification_shares,
      })),
      scalar: C::F::ONE,
      offset: C::F::ZERO,
    })

  pub fn read<R: io::Read>(reader: &mut R) -> io::Result<ThresholdKeys<C>> {
    {
      let different = || io::Error::other("deserializing ThresholdKeys for another curve");

      let mut id_len = [0; 4];
      reader.read_exact(&mut id_len)?;
      if u32::try_from(C::ID.len()).unwrap().to_le_bytes() != id_len {
        Err(different())?;
      }

      let mut id = vec![0; C::ID.len()];
      reader.read_exact(&mut id)?;
      if id != C::ID {
        Err(different())?;
      }
    }

    let (t, n, i) = {
      let mut read_u16 = || -> io::Result<u16> {
        let mut value = [0; 2];
        reader.read_exact(&mut value)?;
        Ok(u16::from_le_bytes(value))
      };
      (
        read_u16()?,
        read_u16()?,
        Participant::new(read_u16()?).ok_or(io::Error::other("invalid participant index"))?,
      )
    };

    let mut interpolation = [0];
    reader.read_exact(&mut interpolation)?;
    let interpolation = match interpolation[0] {
      0 => Interpolation::Constant({
        let mut res = Vec::with_capacity(usize::from(n));
        for _ in 0 .. n {
          res.push(C::read_F(reader)?);
        }
        res
      }),
      1 => Interpolation::Lagrange,
      _ => Err(io::Error::other("invalid interpolation method"))?,
    };

    let secret_share = Zeroizing::new(C::read_F(reader)?);

    let mut verification_shares = HashMap::new();
    for l in (1 ..= n).map(Participant) {
      verification_shares.insert(l, <C as Ciphersuite>::read_G(reader)?);
    }

    ThresholdKeys::new(
      ThresholdParams::new(t, n, i).map_err(io::Error::other)?,
      interpolation,
      secret_share,
      verification_shares,
    )
    .map_err(io::Error::other)
  }

  fn read_F<R: Read>(reader: &mut R) -> io::Result<Self::F> {
    let mut encoding = <Self::F as PrimeField>::Repr::default();
    reader.read_exact(encoding.as_mut())?;

    // ff mandates this is canonical
    let res = Option::<Self::F>::from(Self::F::from_repr(encoding))
      .ok_or_else(|| io::Error::other("non-canonical scalar"));
    encoding.as_mut().zeroize();
    res
  }

  /// Read a canonical point from something implementing std::io::Read.
  ///
  /// The provided implementation is safe so long as `GroupEncoding::to_bytes` always returns a
  /// canonical serialization.
  #[cfg(any(feature = "alloc", feature = "std"))]
  #[allow(non_snake_case)]
  fn read_G<R: Read>(reader: &mut R) -> io::Result<Self::G> {
    let mut encoding = <Self::G as GroupEncoding>::Repr::default();
    reader.read_exact(encoding.as_mut())?;

    let point = Option::<Self::G>::from(Self::G::from_bytes(&encoding))
      .ok_or_else(|| io::Error::other("invalid point"))?;
    if point.to_bytes().as_ref() != encoding.as_ref() {
      Err(io::Error::other("non-canonical point"))?;
    }
    Ok(point)
  }
