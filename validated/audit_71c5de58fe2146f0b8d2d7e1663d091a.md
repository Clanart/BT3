### Title
Sandwiching of WOM Bonus-Reward Harvests via Instant `rewardPerTokenStored` Update in `BaseRewardPool`/`BaseRewardPoolV2` - ([File: rewards/BaseRewardPool.sol], [File: wombat/WombatStaking.sol])

### Summary
The Wombat bonus-reward accounting used by `MasterMagpie`/`BaseRewardPool` shares the exact bug class described in the external report: a lump-sum reward credit (`_provisionReward`) is applied instantaneously and pro-rata over the *current* `totalStaked()`, with no vesting/streaming and no minimum holding period. Because `WombatStaking.harvest(address _lpToken)` is a public, unprivileged, permissionless function [1](#0-0) , and `MasterMagpie.deposit`/`withdraw` are also permissionless with no cooldown [2](#0-1) , any ordinary wallet can execute the full "deposit → trigger harvest → withdraw" sandwich in a single atomic transaction (not even requiring front-running someone else's mempool tx), stealing a share of freshly harvested WOM/bonus rewards intended for long-term LPs.

### Finding Description
`WombatStaking._sendRewards()`/`_toMasterWomAndSendReward()` calls `IBaseRewardPool.queueNewRewards()` whenever WOM (and bonus tokens) are harvested from Wombat Exchange, whether triggered by a deposit, a withdrawal, or the public `harvest()` function [1](#0-0) [3](#0-2) [4](#0-3) .

`queueNewRewards()` in `BaseRewardPool`/`BaseRewardPoolV2` immediately folds the entire reward amount into `rewardPerTokenStored`, dividing by the pool's *current* `totalStaked()` at that instant: [5](#0-4) 

`totalStaked()` and `balanceOf()` read live balances from `MasterMagpie`, meaning any stake added just before this call immediately participates in the division: [6](#0-5) 

`earned()` then computes a user's owed reward purely from `balanceOf(_account) * (rewardPerToken - userRewardPerTokenPaid)`, with no time-weighting or streaming over a duration: [7](#0-6) 

Because `MasterMagpie.deposit()` and `withdraw()` are unprivileged, unrestricted, and immediately effective (no lock/cooldown, only `whenNotPaused nonReentrant`), and because `_deposit`/`_harvestAndUnstake` call `updatePool` + `_harvestBaseRewarder` synchronously around a user's staked `amount`, an attacker can:
1. Call `MasterMagpie.deposit(stakingToken, largeAmount)` (or via a Wombat pool helper's `depositLP`).
2. In the same transaction, call `WombatStaking.harvest(_lpToken)` (public, no access control) to force `_toMasterWomAndSendReward` → `_sendRewards` → `queueNewRewards`, instantly inflating `rewardPerTokenStored` based on the now-inflated `totalStaked()` that includes the attacker's fresh deposit.
3. Call `MasterMagpie.withdraw(stakingToken, largeAmount)` to exit, having already accrued/claimed a pro-rata share of the harvested WOM/bonus rewards via `_harvestBaseRewarder`/`getReward()`.

This mirrors the reported MultipliVault bug precisely: a predictable, instantaneously-applied balance/yield update with no delay mechanism, exploitable by depositing right before and withdrawing right after the update. Unlike the vault case, this analog is even more severe because the "yield update" trigger (`harvest()`) is itself callable by the attacker with no need to front-run anyone else's pending transaction.

### Impact Explanation
Legitimate long-term Wombat LP stakers have their WOM/bonus-token rewards diluted every time an attacker sandwiches a harvest, resulting in direct theft of unclaimed yield from honest depositors to the attacker — falling under "theft or permanent freezing of unclaimed yield."

### Likelihood Explanation
High. The attack requires no privileged role, no oracle manipulation, and no governance action — an ordinary wallet with sufficient capital can atomically call `deposit` → `harvest` → `withdraw` in one transaction. It is only bounded by gas costs and any withdrawal/redemption fees the deployment configuration may impose (none were found enforced at the `MasterMagpie`/`BaseRewardPool` level in this code).

### Recommendation
Introduce reward streaming (e.g., time-weighted `rewardRate` distributed over a duration, as in Synthetix-style `StakingRewards`) instead of instantaneous `rewardPerTokenStored` credit, and/or enforce a minimum staking duration before a deposit becomes eligible to accrue newly queued rewards in `BaseRewardPool`/`BaseRewardPoolV2`/`vlMGPBaseRewarder`.

### Proof of Concept
1. Attacker calls `MasterMagpie.deposit(stakingToken, X)` for a Wombat LP pool with a large `X`, minted via `WombatPoolHelper.depositLP` if needed [8](#0-7) .
2. Attacker (or anyone) calls `WombatStaking.harvest(_lpToken)`, which pulls accrued WOM from Wombat's `MasterWombat` and calls `_sendRewards` → `queueNewRewards`, crediting `rewardPerTokenStored` based on `totalStaked()` that now includes the attacker's stake [9](#0-8) [5](#0-4) .
3. Attacker calls `MasterMagpie.withdraw(stakingToken, X)`, which internally calls `_harvestBaseRewarder` and effectively realizes `earned()` for the attacker's account based on the now-inflated `rewardPerTokenStored` [10](#0-9) [7](#0-6) .
4. Attacker calls `getReward`/`multiclaim` to withdraw the pro-rata WOM/bonus reward, having held the position only for the duration of one transaction.

    function _sendRewards(
        address _lpToken,
        address _rewardToken,
        address _rewarder,
        uint256 _amount
    ) internal {
        if (_amount == 0) return;
        uint256 originalRewardAmount = _amount;

        if (!isPoolFeeFree[_lpToken]) {
            for (uint256 i = 0; i < feeInfos.length; i++) {
                Fees storage feeInfo = feeInfos[i];

                if (feeInfo.isActive) {
                    address rewardToken = _rewardToken;
                    uint256 feeAmount = (originalRewardAmount * feeInfo.value) / DENOMINATOR;
                    _amount -= feeAmount;
                    uint256 feeTosend = feeAmount;

                    if (feeInfo.isMWOM && rewardToken == wom) {
                        if (smartWomConverter != address(0)) {
                            IERC20(wom).safeApprove(smartWomConverter, feeAmount);
                            uint256 beforeBalnce = IMWom(mWom).balanceOf(address(this));
                            IConverter(smartWomConverter).smartConvert(feeAmount, 0);
                            rewardToken = mWom;
                            feeTosend = IMWom(mWom).balanceOf(address(this)) - beforeBalnce;
                        } else {
                            IERC20(wom).safeApprove(mWom, feeAmount);
                            uint256 beforeBalnce = IMWom(mWom).balanceOf(address(this));
                            IMWom(mWom).deposit(feeAmount);
                            rewardToken = mWom;
                            feeTosend = IMWom(mWom).balanceOf(address(this)) - beforeBalnce;
                        }
                    }

                    if (!feeInfo.isAddress) {
                        IERC20(rewardToken).safeApprove(feeInfo.to, 0);
                        IERC20(rewardToken).safeApprove(feeInfo.to, feeTosend);
                        IBaseRewardPool(feeInfo.to).queueNewRewards(feeTosend, rewardToken);
                    } else {
                        IERC20(rewardToken).safeTransfer(feeInfo.to, feeTosend);
                        emit RewardPaidTo(feeInfo.to, rewardToken, feeTosend);
                    }
                }
            }
        }

        IERC20(_rewardToken).safeApprove(_rewarder, 0);
        IERC20(_rewardToken).safeApprove(_rewarder, _amount);
        IBaseRewardPool(_rewarder).queueNewRewards(_amount, _rewardToken);
    }

        updatePool(_stakingToken);

        UserInfo storage user = userInfo[_stakingToken][_account];

        if (!_isVlMgp && user.available < _amount)
            revert WithdrawAmountExceedsStaked();
        else if(user.amount < _amount && _isVlMgp)
            revert UnlockAmountExceedsLocked();
        
        _harvestMGP(_stakingToken, _account);
        _harvestBaseRewarder(_stakingToken, _account);

        user.amount = user.amount - _amount;

            user.available = user.available - _amount;
        user.rewardDebt = (user.amount * tokenToPoolInfo[_stakingToken].accMGPPerShare) / 1e12;
    }

    function _provisionReward(uint256 _amountReward, address _rewardToken) internal {
        IERC20(_rewardToken).safeTransferFrom(
            msg.sender,
            address(this),
            _amountReward
        );
        Reward storage rewardInfo = rewards[_rewardToken];
        rewardInfo.historicalRewards =
            rewardInfo.historicalRewards +
            _amountReward;
        if (this.totalStaked() == 0) {
            rewardInfo.queuedRewards += _amountReward;
        } else {
            if (rewardInfo.queuedRewards > 0) {
                _amountReward += rewardInfo.queuedRewards;
                rewardInfo.queuedRewards = 0;
            }
            rewardInfo.rewardPerTokenStored =
                rewardInfo.rewardPerTokenStored +
                (_amountReward * 10**stakingDecimals()) /
                this.totalStaked();
        }
        emit RewardAdded(_amountReward, _rewardToken);
