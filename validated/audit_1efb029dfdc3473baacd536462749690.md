### Title
No timestamp/freshness check on signed App Proxy requests permits indefinite replay of leaked proxy URLs - (File: `lib/shopify_app/controller_concerns/app_proxy_verification.rb`)

### Summary
`ShopifyApp::AppProxyVerification#query_string_valid?` verifies only that the HMAC signature over the query string matches the shared secret, but it never checks the `timestamp` parameter that Shopify includes in every signed app-proxy request for freshness/staleness.

### Finding Description
The concern's `verify_proxy_request` calls `query_string_valid?`, which recomputes the HMAC over all query params (including `timestamp`) and compares it to the `signature` param using a secure compare: [1](#0-0) 

The signature computation folds `timestamp` into the signed payload, but nothing in `query_string_valid?` or `verify_proxy_request` ever inspects `timestamp` to reject requests whose signed timestamp is old: [2](#0-1) 

This is structurally the same root cause as the referenced report: a signed/verifiable value is trusted without checking that it is still "live" — the oracle report checks HMAC/round data but not sequencer liveness/staleness; here the code checks HMAC validity but not the staleness of the signed `timestamp`. Once a valid signed app-proxy URL (with its `signature` and `timestamp`) is observed — e.g. leaked via browser history, shared links, referrer headers, server logs, or a `Referer` header on an outbound request from the proxied page — it remains permanently valid and can be replayed by anyone, indefinitely, from any origin, since the concern never enforces recency.

The accompanying test suite confirms only signature correctness is exercised, never expiry: [3](#0-2) 

### Impact Explanation
An attacker who obtains a previously-valid, Shopify-signed app-proxy URL (query string containing `shop`, `path_prefix`, `timestamp`, `signature`) can replay it against the app's app-proxy endpoint at any point in the future — hours, days, or years later — and the request will still be accepted as authentic, because `query_string_valid?` only checks signature correctness, not `timestamp` recency. Any controller relying solely on `ShopifyApp::AppProxyVerification` for authorization of shop-scoped app-proxy actions (which is the concern's intended and documented use) will process this stale/replayed request as if it were a fresh, legitimate call from Shopify/the merchant's storefront, enabling accepted-forged-request-style abuse (e.g., replaying a proxy action outside its intended time window) without any additional authentication.

### Likelihood Explanation
Exploitation requires only capturing one previously valid signed app-proxy query string (a passive network/log/referrer leak is enough) — no secret key knowledge or additional cryptographic break is needed, since the concern by design never checks `timestamp` staleness. This makes the missing check a persistent gap rather than a theoretical one.

### Recommendation
Add an explicit staleness check on the `timestamp` query parameter in `query_string_valid?`/`verify_proxy_request`, rejecting requests whose `timestamp` is older than a reasonable grace window (mirroring how `LoginProtection`/`TokenExchange` already enforce `check_session_expiry_date` for sessions): [4](#0-3) 

### Proof of Concept
1. Observe a legitimately-issued app-proxy request URL, e.g. `GET /apps/my-app?shop=some-store.myshopify.com&path_prefix=%2Fapps%2Fmy-app&timestamp=1466106083&signature=<valid-sig>` (captured from logs, browser history, or a `Referer` header).
2. At any later time, replay the exact same query string to the app's app-proxy controller.
3. `verify_proxy_request` → `query_string_valid?` recomputes the same HMAC (since all params, including `timestamp`, are unchanged) and it matches `signature`, so the request passes verification and the controller action executes, despite the request being arbitrarily old. [1](#0-0)

```ruby
      head(:forbidden) unless query_string_valid?(request.query_string)

    def query_string_valid?(query_string)
      query_hash = Rack::Utils.parse_query(query_string)

      signature = query_hash.delete("signature")
      return false if signature.nil?

      ActiveSupport::SecurityUtils.secure_compare(
        calculated_signature(query_hash),
        signature,
      )
    end
```

```ruby
    def calculated_signature(query_hash_without_signature)
      sorted_params = query_hash_without_signature.collect { |k, v| "#{k}=#{Array(v).join(",")}" }.sort.join

      OpenSSL::HMAC.hexdigest(
        OpenSSL::Digest.new("sha256"),
        ShopifyApp.configuration.secret,
        sorted_params,
      )
    end
```
