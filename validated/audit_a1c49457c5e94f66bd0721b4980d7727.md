### Title
Open redirect in `redirect_to_app`/`decoded_host`/`deduced_phishing_attack?` via unsanitized backslash/control-character host authority bypassing myshopify domain check - ([File: app/controllers/shopify_app/callback_controller.rb])

### Summary
`CallbackController#decoded_host` decodes the attacker-controlled `host` param via `ShopifyAPI::Auth.embedded_app_url` and parses it with plain Ruby `URI()`, then `deduced_phishing_attack?` runs `ShopifyApp::Utils.sanitize_shop_domain` against that parsed host to decide whether to trust the resulting redirect. Unlike the sibling method `EmbeddedApp#safe_embedded_app_url`, which explicitly rejects unsafe authority strings (control characters, backslashes, or `@` in the authority) via `unsafe_embedded_host?` before calling `sanitize_shop_domain`, `decoded_host`/`deduced_phishing_attack?` in `callback_controller.rb` perform no such pre-filtering.

### Finding Description
`redirect_to_app` builds the post-auth redirect target from two attacker-influenced inputs and gates it with `deduced_phishing_attack?`: [1](#0-0) 

`decoded_host` decodes `params[:host]` directly with no character/format sanitization: [2](#0-1) 

`deduced_phishing_attack?` parses that decoded value with plain `URI()` (not `Addressable::URI`) and only then calls `ShopifyApp::Utils.sanitize_shop_domain`: [3](#0-2) 

Compare this to the equivalent, but hardened, logic used elsewhere in the gem for the same "decode host param, then verify it's trusted" operation: [4](#0-3) 

`safe_embedded_app_url` explicitly rejects hosts containing control characters (`<= 0x20`, `0x7f`), backslashes, or userinfo (`@`) via `unsafe_embedded_host?`/`unsafe_embedded_host_characters?`/`embedded_host_authority` before ever calling `sanitize_shop_domain`. This is a defense against known browser-vs-parser normalization discrepancies (e.g., backslashes being treated as path/host separators by browsers but not by Ruby's URI/Addressable parsers, and userinfo `@` tricks like `trusted.myshopify.com@evil.com`). `callback_controller.rb`'s `decoded_host`/`deduced_phishing_attack?` path has no equivalent guard — it relies solely on `sanitize_shop_domain`'s own Addressable-based host/domain comparison, and even that only sees whatever `URI()` (stdlib) extracts as `.host`, which can differ from what a browser would ultimately navigate to for malformed authority strings containing backslashes or control characters.

Additionally, note the `fully_formed_url?` branch: if `return_to` (session-based, normally constrained to a relative path by `RedirectSafely.make_safe(params[:return_to], "/")` in `sessions_controller.rb#copy_return_to_param_to_session` and by `return_to_url` in `login_protection.rb`, both of which only ever store relative paths derived from `request.path`) somehow became a fully-formed absolute URL, `redirect_to = return_to` would bypass the `decoded_host`-based check entirely, since `deduced_phishing_attack?` only inspects `decoded_host`, never the chosen `redirect_to` value. I could not find a reachable code path in this repo where `session[:return_to]` is set to an attacker-supplied absolute URL — `RedirectSafely.make_safe` (external gem, not present in this repo's source) is relied upon to strip scheme/`//`-prefixed values, and the test suite confirms `"//example.com"` is normalized to `/`. This portion of the concern could not be fully verified because `RedirectSafely`'s implementation is not part of this codebase, but no in-repo caller was found that stores an unsanitized absolute `return_to` in the session.

### Impact Explanation
If a crafted `host` value decodes to an authority string that `sanitize_shop_domain`/stdlib `URI()` parse as trusted (e.g. matching `myshopify.com`) but that a real browser would resolve to an attacker-controlled origin (via backslash-as-slash normalization, userinfo tricks, or control-character truncation), `deduced_phishing_attack?` returns `false`, and `redirect_to_app` issues `redirect_to(redirect_to, allow_other_host: true)` to that attacker origin. Because this redirect fires immediately after OAuth completion — with the fresh Shopify session cookie and `host` value newly persisted — landing on an attacker-controlled origin embedded in the flow can be leveraged to exfiltrate the session/host context, matching the "open redirect leading to token/session exfiltration" impact class.

### Likelihood Explanation
Exploitability depends entirely on finding an authority string where stdlib `URI()`/`Addressable::URI` (used internally by `sanitize_shop_domain`) and a real browser disagree on the effective host — this is the same bug class the maintainers already patched in `EmbeddedApp#unsafe_embedded_host?`, meaning it is a known, previously-fixed class of parser/browser normalization mismatch, but has not been mirrored to `CallbackController`. This requires no privileged access: the attacker only needs to complete or trigger the standard OAuth callback with a crafted base64 `host` param, which is fully attacker-controlled and unauthenticated at this stage. I was unable to construct or verify a concrete byte sequence that both (a) satisfies `sanitize_shop_domain`'s trusted-domain check and (b) is browser-normalized to an attacker host, since that requires testing exact behavior of `ShopifyAPI::Auth.embedded_app_url` (external `shopify_api` gem, not in this repo) and real browser URL-parsing behavior, which are outside this repo's indexed content.

### Recommendation
Apply the same authority-sanitization guard used in `lib/shopify_app/controller_concerns/embedded_app.rb` (`unsafe_embedded_host?`, `unsafe_embedded_host_characters?`, `embedded_host_authority`) to `CallbackController#decoded_host`/`deduced_phishing_attack?` before calling `sanitize_shop_domain`, and parse with `Addressable::URI` instead of stdlib `URI()` for consistency with the rest of the codebase's host-trust logic. Also make `deduced_phishing_attack?` validate the actual chosen `redirect_to` value (or explicitly re-validate `return_to`'s host when `fully_formed_url?` is true) rather than only checking `decoded_host`, so the fully-formed-URL branch cannot bypass the trust check.

### Proof of Concept
Could not be fully constructed/verified against this repo alone: reproducing the parser-vs-browser mismatch requires the external `shopify_api` gem's `ShopifyAPI::Auth.embedded_app_url` decoding behavior and real-browser URL normalization semantics, neither of which are present in this codebase's index. A concrete regression/property test to add (mirroring the existing `embedded_app.rb` unsafe-host test suite) would be:

```ruby
# test/controllers/callback_controller_test.rb
[
  "trusted-shop.myshopify.com\\@evil.com",
  "trusted-shop.myshopify.com%5c@evil.com",
  "trusted-shop.myshopify.com\u0000@evil.com",
].each do |crafted_authority|
  test "callback does not redirect off-domain for crafted host authority (#{crafted_authority})" do
    host_param = Base64.strict_encode64(crafted_authority)
    mock_oauth
    get :callback, params: @callback_params.merge(host: host_param)
    assert_redirected_to ShopifyApp.configuration.root_url
  end
end
```
This test currently has no equivalent in `test/controllers/callback_controller_test.rb` (only fully-formed/relative `return_to` cases and legitimate `host` values are tested), which is itself evidence that the callback path lacks the same authority-fuzzing coverage that `test/shopify_app/controller_concerns` (for `EmbeddedApp`) has.

    def safe_embedded_app_url(host)
      decoded_host = Base64.decode64(host.to_s)
      return if deduced_phishing_attack?(decoded_host)

      ShopifyAPI::Auth.embedded_app_url(Base64.strict_encode64(decoded_host))
    end

    def deduced_phishing_attack?(decoded_host)
      sanitized_host = ShopifyApp::Utils.sanitize_shop_domain(decoded_host) unless unsafe_embedded_host?(decoded_host)
      if sanitized_host.nil?
        message = "Host param for redirect to embed app in admin is not from a trusted domain, " \
          "redirecting to root as this is likely a phishing attack."
        ShopifyApp::Logger.info(message)
      end
      sanitized_host.nil?
    end

    def unsafe_embedded_host?(decoded_host)
      return true if decoded_host.empty? || !decoded_host.valid_encoding?
      return true if unsafe_embedded_host_characters?(decoded_host)

      embedded_host_authority(decoded_host).include?("@")
    end

    def unsafe_embedded_host_characters?(decoded_host)
      decoded_host.each_char.any? do |character|
        character_code = character.ord
        character_code <= 0x20 || character_code == 0x7f || character == "\\"
      end
    end

    def embedded_host_authority(decoded_host)
      decoded_host.sub(%r{\Ahttps?://}i, "").split(%r{[/?#]}, 2).first.to_s
    end
