Found a concrete analog in the Data Layer's mirror/download subsystem: subscription server URLs (which may embed HTTP basic-auth credentials, e.g. `https://user:pass@host/path`, as used with wolfi-style repository URLs in the apko report) are printed verbatim into log output on every download attempt, success, and failure path.

### Title
Exposure of HTTP basic-auth credentials embedded in Data Layer mirror/server URLs in log output - (File: chia/data_layer/download_data.py)

### Summary
The Data Layer client downloads store delta/full files from mirror server URLs (`ServerInfo.url`) that are stored via `subscribe()`/mirror-add flows and can contain embedded HTTP basic-auth credentials (`https://user:pass@host/...`). These URLs are interpolated directly into f-strings passed to `log.info`/`log.debug`/`log.warning` without any parsing or redaction, identical in root cause to the apko advisory: raw string URL values are logged without ever being parsed/sanitized as a `URL` object.

### Finding Description
`http_download` in [1](#0-0)  builds the request target as `server_info.url + "/" + filename` and, on progress, logs `f"Downloading delta file {filename}. {progress_percentage} of {size} bytes."`—but more importantly, its caller `download_file` logs the raw URL on failure: [2](#0-1) 
Additional call sites embed the same unredacted URL string in info/warning logs during normal operation and error handling in `DataLayer.fetch_and_validate`: [3](#0-2) [4](#0-3) 
None of these sites parse the URL (e.g., with `urllib.parse.urlsplit`) to strip the userinfo component before logging, matching the exact bug class in the apko advisory (`%s`/f-string formatting a URL, or never parsing a string URL at all, so credentials pass through into log output unredacted).

### Impact Explanation
If a Data Layer operator configures a mirror/server URL containing HTTP basic-auth credentials (a supported and common pattern for privately hosted delta/full file servers), those credentials are written in plaintext to the Data Layer log at INFO/WARNING/DEBUG levels on every sync attempt, success, and failure — including in CI/automation logs, which is exactly the scenario the referenced advisory calls out as the primary impact. This is a confidentiality-only issue (CWE-522/532): it does not directly enable unauthorized coin movement, but it does allow leakage of credentials that gate access to the DataLayer server, potentially letting an attacker overwrite or poison mirrored store content that other Data Layer clients then trust and merge.

### Likelihood Explanation
Any user or operator running a Data Layer node with debug/info logging enabled and using authenticated mirror URLs will trigger this on every normal sync cycle (`fetch_and_validate` runs periodically per subscribed store), and on every download failure. No attacker interaction is needed — it's a byproduct of legitimate configuration and normal operation, making it highly likely to occur whenever authenticated URLs are used.

### Recommendation
Before logging any `ServerInfo.url` (or downloader/uploader `PluginRemote.url`), parse it with `urllib.parse.urlsplit`/`urlparse` and reconstruct a redacted form (replacing `username`/`password` with `***`) prior to string interpolation in all `log.*` calls in `chia/data_layer/download_data.py` and `chia/data_layer/data_layer.py`. Add a shared `redact_url()` helper and route every credential-bearing URL through it prior to logging, mirroring the fix pattern in the referenced apko commit.

### Proof of Concept
1. Configure a Data Layer subscription/mirror with a URL containing embedded basic-auth credentials, e.g. `https://user:secretpass@mirror.example.com/path`, via `DataStore.subscribe()` [5](#0-4) .
2. Run the Data Layer service with `log_level: debug` or `info`.
3. Trigger a sync (`fetch_and_validate`) or a transient download failure (e.g., mirror briefly unreachable).
4. Observe the plaintext credentials appear in the log lines emitted at [6](#0-5)  and [3](#0-2) , e.g. `Downloading files ... Server used: https://user:secretpass@mirror.example.com.`

async def http_download(
    target_filename_path: Path,
    filename: str,
    proxy_url: str | None,
    server_info: ServerInfo,
    timeout: aiohttp.ClientTimeout,
    log: logging.Logger,
    max_delta_file_size: int,
) -> None:
    """
    Download a file from a server using aiohttp.
    Raises exceptions on errors
    """
    async with aiohttp.ClientSession() as session:
        headers = {"accept-encoding": "gzip"}
        async with session.get(
            server_info.url + "/" + filename,
            headers=headers,
            timeout=timeout,
            proxy=proxy_url,
        ) as resp:
            resp.raise_for_status()
            size = int(resp.headers.get("content-length", 0))
            max_delta_file_size_bytes = max_delta_file_size * 1024 * 1024
            if size > max_delta_file_size_bytes:
                raise MaxDeltaFileSizeExceededError(f"Maximum delta file size exceeded: {max_delta_file_size} MiB.")
            log.debug(f"Downloading delta file {filename}. Size {size} bytes.")
