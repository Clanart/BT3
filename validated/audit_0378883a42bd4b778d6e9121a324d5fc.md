### Title
`WombatBribeManager.removePool` fails to deactivate or reset the removed pool's vote accounting, permanently corrupting `totalVlMgpInVote` and diluting governance vote weight for all other pools - ([File: wombat/WombatBribeManager.sol])

### Summary
This is an analog of the "SettlementSignatureVerifier's `required_validators` is not updated"-class bug: an admin performs a normal, legitimate configuration change in one place (removing a pool from the bribe manager's active pool list) but a dependent piece of state (`poolInfos[_lp].isActive`, `totalVoteInVlmgp`, `totalVlMgpInVote`) is never synchronized/reset. The resulting desynchronization is then exploitable through completely ordinary, unprivileged user transactions (`vote()`), causing a permanent and irreversible corruption of the vote-weighting denominator used for all pools.

### Finding Description
`WombatBribeManager.removePool` only removes the pool address from the `pools` array; it never touches `poolInfos[_lp]`: [1](#0-0) 

Critically, it does not set `poolInfos[_lp].isActive = false`, nor does it subtract the pool's outstanding `totalVoteInVlmgp` from the global `totalVlMgpInVote` counter, nor zero out `userVotedForPoolInVlmgp` for users who had voted for that pool.

The `vote()` function's only gating check is `pool.isActive`, not membership of the LP in the `pools` array: [2](#0-1) 

Because `isActive` is never flipped to `false` by `removePool`, any unprivileged wallet can continue to call `vote()` targeting the removed pool's address indefinitely. This increases `pool.totalVoteInVlmgp` and the global `totalVlMgpInVote`: [3](#0-2) 

However, `castVotes()` only iterates over the `pools` array (which no longer contains the removed LP), so the votes accumulated against the removed pool are never forwarded to the actual Wombat voter contract: [4](#0-3) 

Yet `totalVlMgpInVote` (inflated by votes for the orphaned/removed pool) remains the denominator used to compute `targetVote` for every *still-active* pool:

```
targetVote = targetVoteInLMGP * totalVotes() / totalVlMgpInVote;
``` [5](#0-4) 

Since this inflated denominator can never be corrected (there is no admin path to zero out the orphaned pool's contribution — `removePool` doesn't do it, and there is no separate function to purge `poolInfos[_lp].totalVoteInVlmgp` from `totalVlMgpInVote`), every vote placed on a removed pool by any ordinary wallet permanently and irreversibly reduces the effective vote weight distributed to all legitimate, currently active pools in every subsequent `castVotes()` call.

### Impact Explanation
This causes a permanent governance voting result manipulation: the real on-chain vote allocation towards Wombat pools (which determines bribe/emission distribution) is systematically diluted below what vlMGP holders actually intend, because an ever-growing pool of "phantom" votes is siphoned into a decommissioned pool address that will never be cast. This corruption is irreversible via any exposed function and grows every time an unprivileged wallet calls `vote()` against the stale pool address.

### Likelihood Explanation
The trigger requires only a normal, expected admin action (`removePool`, which is a routine housekeeping operation, not a malicious/privileged misuse) followed by ordinary unprivileged wallets calling the public `vote()` function with the now-orphaned LP address — which remains fully known and valid since it is never removed from `poolInfos`. No special access or timing is required, making this straightforward to trigger by any user once a pool has been removed.

### Recommendation
When removing a pool in `removePool`, also: set `poolInfos[_lp].isActive = false` to block further `vote()` calls against it, and subtract the pool's outstanding `totalVoteInVlmgp` from `totalVlMgpInVote` (while providing a mechanism to return/settle already-voted user balances, e.g., forcing an implicit `unvote` for all voters before removal, or excluding inactive pools' vote weight from the `castVotes` denominator).

### Proof of Concept
1. Admin calls `addPool(lpA, rewarderA, "PoolA")`.
2. Users vote for `lpA` via `vote()`, contributing to `totalVlMgpInVote` and `poolInfos[lpA].totalVoteInVlmgp`.
3. Admin calls `removePool(indexOfLpA)` — `lpA` is removed from the `pools` array but `poolInfos[lpA].isActive` remains `true`.
4. Any unprivileged wallet calls `vote([lpA], [positiveDelta])` — this succeeds because `pool.isActive` is still `true`, further inflating `totalVlMgpInVote`.
5. `castVotes()` is called: since `lpA` is not in the `pools` array, its votes are never forwarded to `wombatStaking.vote(...)`, but `totalVlMgpInVote` still includes `lpA`'s accumulated vote weight, permanently shrinking `targetVote` computed for all other active pools.
