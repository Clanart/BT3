### Title
DataLayer mirror coins allow unauthenticated attacker-controlled URLs to trigger outbound HTTP requests against arbitrary third-party targets (mirror-based SSRF/DDoS amplification) - ([File: chia/data_layer/data_layer_wallet.py])

### Summary
Chia's DataLayer "mirror" mechanism lets any wallet publish a set of arbitrary URLs on-chain, associated with any DataLayer store (`launcher_id`), for the cost of a standard coin spend. Any full node running the DataLayer service that is subscribed to (or owns) that store id will periodically read those mirror URLs from the chain and automatically issue outbound HTTP requests to them, with no validation of scheme, host, or ownership. This mirrors the CVE-2021-22696 Apache CXF pattern, where an attacker-supplied, unvalidated URI parameter caused the server to make outbound network requests, enabling a DDoS/SSRF amplification vector against arbitrary third parties.

### Finding Description
`DataLayerWallet.create_new_mirror()` builds a `CREATE_COIN` condition whose memo is `[launcher_id, *urls]`, taking `launcher_id` and `urls` directly from the RPC caller with no check that the caller owns, controls, or is otherwise authorized for that `launcher_id`, and no validation of the URL contents: [1](#0-0) 

This is exposed via the wallet RPC `dl_new_mirror` endpoint, reachable by any wallet client with funds to pay the coin amount/fee: [2](#0-1) 

Once mined, the mirror coin's memos are parsed back into `(launcher_id, urls)` by `get_mirror_info()` with no filtering: [3](#0-2) 

Any DataLayer service that has subscribed to (or owns) that `launcher_id` periodically calls `update_subscriptions_from_wallet()`, which fetches **all** mirrors registered for that store id from chain and merges their URLs into the local subscription/server list without any per-mirror authorization or ownership check: [4](#0-3) 

The periodic sync loop (`periodically_manage_data()` → `update_subscription()` → `fetch_and_validate()`) then iterates these server URLs and performs outbound HTTP GET requests via `http_download()`: [5](#0-4) [6](#0-5) 

There is no restriction on the URL's scheme or destination (e.g., internal network addresses, arbitrary external hosts), and the request is issued automatically and repeatedly (once per `manage_data_interval`, by default every node subscribed to that store) as long as the local generation lags the chain-published generation, which an attacker can also force by pushing new roots or simply keeping mirrors registered indefinitely.

### Impact Explanation
Because mirror registration is permissionless (any XCH holder can register a mirror for any existing store id) and mirror URLs are trusted enough to be dialed automatically by every subscribing DataLayer node, an attacker can:
- Register a malicious/victim URL as a mirror for a popular, widely-subscribed DataLayer store, causing many independent nodes to repeatedly send outbound HTTP requests to the attacker-chosen target — a distributed DDoS amplification against an arbitrary third party (CWE-400).
- Direct requests at internal/local network addresses reachable from node operators' networks, a potential SSRF vector (CWE-918), since the code performs no host/scheme allow-listing before dialing `server_info.url + "/" + filename`.

This satisfies the "spend-triggered transaction-processing halt" bucket loosely, but more precisely maps to a reachable resource-consumption/amplification vector triggered by a single on-chain spend from an unprivileged wallet holder, matching the DDoS bug class of the source CVE.

### Likelihood Explanation
Likelihood is high for any store id that already has active subscribers/mirrors: creating a mirror coin only requires a standard coin spend with a small `amount` and `fee`, no special permission, and no relationship to the store owner. The sync loop runs unconditionally on an interval (`manage_data_interval`) for every subscribed/owned store, so the malicious URL will be dialed repeatedly and automatically without any user interaction beyond the initial subscription that already existed for the legitimate store.

### Recommendation
- Validate mirror URLs at registration and/or consumption time (scheme allow-list such as `https` only, reject private/loopback/link-local addresses, enforce max URL count/length).
- Consider gating which mirrors are trusted per store (e.g., only mirrors created by the store owner's known keys, or requiring mirrors to be explicitly approved by the subscriber) rather than treating any on-chain mirror registration as automatically fetchable.
- Rate-limit/backoff outbound requests per destination host in addition to per-`ServerInfo`, and consider circuit-breaking hosts that repeatedly fail or resolve to private network ranges.

### Proof of Concept
1. Attacker identifies a DataLayer `launcher_id` that many nodes are subscribed to/track (store ids are public on-chain).
2. Attacker calls `dl_new_mirror` RPC (`chia/wallet/wallet_rpc_api.py:3255-3274`) with `launcher_id` set to that store id and `urls=["http://victim.example.com/heavy-resource"]`, paying only the coin amount + fee.
3. Once confirmed, every DataLayer node subscribed to that store id calls `update_subscriptions_from_wallet()` (`chia/data_layer/data_layer.py:979-985`), pulling the attacker's URL into its local server list.
4. On each `manage_data_interval` cycle, `fetch_and_validate()`/`download_file()`/`http_download()` (`chia/data_layer/data_layer.py:642-666`, `chia/data_layer/download_data.py:298-324`) issues an HTTP GET to `http://victim.example.com/heavy-resource` from every such node, repeatedly, with no ownership or destination validation — producing distributed outbound traffic against the attacker-chosen victim.

def get_mirror_info(
    parent_puzzle: Program | SerializedProgram, parent_solution: Program | SerializedProgram
) -> tuple[bytes32, list[bytes]]:
    assert type(parent_puzzle) is type(parent_solution)
    _, conditions = run_with_cost(parent_puzzle, INFINITE_COST, parent_solution)
    for condition in conditions.as_iter():
        if (
            condition.first().as_python() == ConditionOpcode.CREATE_COIN
            and condition.at("rf").as_python() == create_mirror_puzzle().get_tree_hash()
        ):
            memos: list[bytes] = condition.at("rrrf").as_python()
            launcher_id = bytes32(memos[0])
            return launcher_id, [url for url in memos[1:]]
    raise ValueError("The provided puzzle and solution do not create a mirror coin")

async def http_download(
    target_filename_path: Path,
    filename: str,
    proxy_url: str | None,
    server_info: ServerInfo,
    timeout: aiohttp.ClientTimeout,
    log: logging.Logger,
    max_delta_file_size: int,
) -> None:
    """
    Download a file from a server using aiohttp.
    Raises exceptions on errors
    """
    async with aiohttp.ClientSession() as session:
        headers = {"accept-encoding": "gzip"}
        async with session.get(
            server_info.url + "/" + filename,
            headers=headers,
            timeout=timeout,
            proxy=proxy_url,
        ) as resp:
            resp.raise_for_status()
            size = int(resp.headers.get("content-length", 0))
            max_delta_file_size_bytes = max_delta_file_size * 1024 * 1024
            if size > max_delta_file_size_bytes:
                raise MaxDeltaFileSizeExceededError(f"Maximum delta file size exceeded: {max_delta_file_size} MiB.")
            log.debug(f"Downloading delta file {filename}. Size {size} bytes.")
