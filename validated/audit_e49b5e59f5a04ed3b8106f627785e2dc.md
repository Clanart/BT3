## Analysis

The Connext report's core invariant break is: **a single external failure/omission in a batched, all-or-nothing flow lets state become permanently inconsistent, and no code path revalidates against what has already happened.** The local Hyperbridge analog isn't in `propagate`-style loops (those are already deliberately fail-safe, see `EvmHost.dispatchIncoming`), but in the **GetRequest fee lifecycle**, where the "already resolved" check that timeout processing depends on is missing.

`EvmHost.dispatchIncoming(GetResponse, ...)` pays the relayer the request's fee on successful delivery but never clears the fee-bearing `_requestCommitments[commitment]` entry: [1](#0-0) 

Compare this to the sibling timeout path, `dispatchTimeOut(GetRequestTimeout, ...)`, which *does* delete `_requestCommitments[commitment]` and pays the fee back to `meta.sender`: [2](#0-1) 

`HandlerV2.handleGetRequestTimeouts` gates timeout dispatch only on (a) a non-membership proof at an arbitrary previously-committed height, and (b) `requestCommitments(commitment).sender != address(0)` — it never checks `host.responseReceipts(commitment)` to confirm a response hasn't already been delivered: [3](#0-2) 

By contrast, `handleGetResponses` does perform the analogous duplicate check against `responseReceipts` before delivering a response: [4](#0-3) 

### Title
Double payment of GetRequest relayer fee via stale non-membership timeout proof - (File: `evm/src/core/EvmHost.sol`, `evm/src/core/HandlerV2.sol`)

### Summary
`EvmHost.dispatchIncoming(GetResponse, ...)` pays the relayer fee out of `_requestCommitments[commitment]` on successful response delivery but does not delete that entry. `HandlerV2.handleGetRequestTimeouts` only checks that `requestCommitments(commitment).sender != address(0)` and a non-membership proof at *some* previously-committed height — it never checks whether a response was already delivered (`host.responseReceipts(commitment)`). Because Hyperbridge retains historical state commitments for earlier heights, an attacker can submit a perfectly valid non-membership proof from a height that predates the (later, legitimately delivered) response, causing the same fee to be paid twice: once to the relayer at delivery time, once refunded to `meta.sender` at "timeout" time.

### Finding Description
The request-fee state machine has two terminal transitions sharing the same guard variable, `_requestCommitments[commitment]`:
1. Response delivered → `dispatchIncoming(GetResponse)` pays `meta.fee` to the relayer, but leaves `_requestCommitments[commitment]` untouched.
2. Timeout proven → `dispatchTimeOut(GetRequestTimeout)` refunds `meta.fee` to `meta.sender` and clears `_requestCommitments[commitment]`.

Since path 1 never clears the guard, path 2 remains reachable for the same commitment even after a response has already landed, as long as an attacker can produce a non-membership proof for the response-receipt storage key at *any* height where that receipt genuinely did not yet exist — which is trivially true for any height before the response was actually delivered. `handleGetRequestTimeouts` only verifies `request.timeout() > state.timestamp` (i.e., that the request's timeout has passed relative to the proven height) and does not compare against the current time or check whether a response has since arrived via `host.responseReceipts(commitment)`.

### Impact Explanation
This is a direct double-claim/double-settlement of the same fee: once as relayer payment, once as sender refund, both drawn from the Host's fee-token balance. This matches "stealing or loss of funds" / "replay/double-claim/double-settlement" in the bounty scope — value is extracted beyond what was ever escrowed for that single request.

### Likelihood Explanation
Both `handleGetResponses` and `handleGetRequestTimeouts` are permissionless entry points callable by anyone holding a valid proof; no malicious relayer, prover, or admin is required — an attacker can self-relay the response (or wait for a legitimate relayer to do so) and then separately submit an old, honestly-obtained non-membership proof for the timeout. The proof itself is truthful (the response really was absent at that historical height), so it passes verification; the flaw is purely in the missing cross-check between the two mutually exclusive resolution paths.

### Recommendation
In `dispatchIncoming(GetResponse, ...)`, delete `_requestCommitments[commitment]` after successful delivery (mirroring the deletion already done in the timeout paths). Additionally, `handleGetRequestTimeouts` (and `dispatchTimeOut`) should assert `host.responseReceipts(commitment).relayer == address(0)` before processing a timeout, so a delivered response permanently forecloses the timeout/refund path for that commitment.

### Proof of Concept
1. User dispatches a `GetRequest` on the source chain via `EvmHost.dispatch(DispatchGet)`, escrowing `fee` in `_requestCommitments[commitment]`.
2. Destination chain answers; a relayer submits `HandlerV2.handleGetResponses` on the source chain. This calls `EvmHost.dispatchIncoming(GetResponse, relayer)`, which pays `fee` to `relayer` and leaves `_requestCommitments[commitment]` intact [5](#0-4) .
3. Attacker (can be the same relayer, or anyone) obtains/constructs a non-membership proof for the response-receipt key at a height on the destination state machine that predates the actual response (any height between request dispatch and eventual response satisfies "receipt absent" honestly, and can also satisfy `request.timeout() > state.timestamp` reversed, i.e. `state.timestamp >= request.timeout()`, if the destination chain's block time already passed the request's timeout deadline before the response was included).
4. Attacker submits `HandlerV2.handleGetRequestTimeouts` with that proof. Checks pass: state commitment exists, timeout condition satisfied, `meta.sender != address(0)` (never cleared), non-membership proof verifies. `host.dispatchTimeOut(...)` executes, refunding `fee` again to `meta.sender` and deleting `_requestCommitments[commitment]`.
5. Net effect: `fee` has now been paid out twice from the Host's fee-token reserves for a single escrowed request.

    function dispatchIncoming(GetResponse memory response, address relayer) external restrict(_hostParams.handler) {
        // replay protection
        bytes32 commitment = response.request.hash();
        _responseReceipts[commitment] = ResponseReceipt({
            relayer: relayer,
            responseCommitment: response.hash()
        });

        (bool success,) = _bytesToAddress(response.request.from)
            .call(abi.encodeWithSelector(IApp.onGetResponse.selector, IncomingGetResponse(response, relayer)));

        if (!success) {
            // so that it can be retried
            delete _responseReceipts[commitment];
            return;
        }

        // reward the relayer fee
        uint256 fee = _requestCommitments[commitment].fee;
        if (fee != 0) {
            IERC20(feeToken()).safeTransfer(relayer, fee);
        }
        emit GetRequestHandled({commitment: commitment, relayer: relayer});
    }

    function dispatchTimeOut(
        GetRequestTimeout memory timeout,
        FeeMetadata memory meta,
        bytes32 commitment
    ) external restrict(_hostParams.handler) {
        // replay protection
        delete _requestCommitments[commitment];
        (bool success,) = _bytesToAddress(timeout.request.from)
            .call(abi.encodeWithSelector(IApp.onGetTimeout.selector, timeout));

        if (!success) {
            // so that it can be retried
            _requestCommitments[commitment] = meta;
            return;
        }

        if (meta.fee != 0) {
            // refund relayer fee
            IERC20(feeToken()).safeTransfer(meta.sender, meta.fee);
        }
        emit GetRequestTimeoutHandled({commitment: commitment, dest: string(timeout.request.dest)});
    }

    function handleGetRequestTimeouts(IHost host, GetTimeoutMessage calldata message) external notFrozen(host) {
        uint256 delay = block.timestamp - host.stateMachineCommitmentUpdateTime(message.height);
        uint256 challengePeriod = host.challengePeriod();
        if (challengePeriod != 0 && challengePeriod > delay) revert ChallengePeriodNotElapsed();

        // fetch the state commitment
        StateCommitment memory state = host.stateMachineCommitment(message.height);
        if (state.stateRoot == bytes32(0)) revert StateCommitmentNotFound();
        uint256 timeoutsLength = message.timeouts.length;

        for (uint256 i = 0; i < timeoutsLength; ++i) {
            GetRequest memory request = message.timeouts[i];
            // timed-out?
            if (request.timeout() > state.timestamp) revert MessageNotTimedOut();

            bytes32 commitment = request.hash();
            FeeMetadata memory meta = host.requestCommitments(commitment);
            if (meta.sender == address(0)) revert UnknownMessage();

            bytes[] memory keys = new bytes[](1);
            keys[0] = bytes.concat(RESPONSE_RECEIPTS_STORAGE_PREFIX, commitment);

            // verify state trie non-membership proofs
            PolkadotTrie.StorageValue memory entry = PolkadotTrie.VerifyProof(state.stateRoot, message.proof, keys)[0];
            if (entry.value.length != 0) revert InvalidProof();

            host.dispatchTimeOut(GetRequestTimeout(request, _msgSender()), meta, commitment);
        }
    }
