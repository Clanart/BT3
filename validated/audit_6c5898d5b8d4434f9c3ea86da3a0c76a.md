### Title
Permissionless `donateRewards` lets a flash-loaned staker steal queued reward backlog via `totalStaked()` timing - (File: rewards/BaseRewardPool.sol)

### Summary
`donateRewards(uint256 _amountReward, address _rewardToken)` is unauthenticated and forwards to `_provisionReward`, which only releases `rewards[token].queuedRewards` into `rewardPerTokenStored` when `totalStaked() != 0` [1](#0-0) . `totalStaked()` reads `IERC20(stakingToken).balanceOf(operator)` live at call time [2](#0-1) , so an attacker can flash-loan the staking token, deposit it into `MasterMagpie` to inflate their own share of `totalStaked()`, trigger `donateRewards` to flush the queued backlog against that inflated stake, harvest their proportional (inflated) share on withdrawal, and repay the flash loan — all atomically.

### Finding Description
- `donateRewards` has no access control beyond `isRewardToken[_rewardToken]` check, and calls `_provisionReward` [3](#0-2) .
- `_provisionReward` computes: if `totalStaked() == 0`, add to `queuedRewards` (backlog); otherwise, fold any existing `queuedRewards` into `_amountReward` and increase `rewardPerTokenStored` by `_amountReward * 10**decimals / totalStaked()` [4](#0-3) .
- `totalStaked()` and `balanceOf(account)` both derive from `MasterMagpie`'s live state: `IERC20(stakingToken).balanceOf(operator)` and `IMasterMagpie(operator).stakingInfo(stakingToken, account)` respectively [5](#0-4) .
- `MasterMagpie.deposit`/`withdraw` have no cooldown or lock — both are only `whenNotPaused nonReentrant`, so stake and unstake can be composed atomically in one transaction [6](#0-5) .
- `_deposit` and `_harvestAndUnstake` (called from `_withdraw`) both invoke `_harvestBaseRewarder` for the account's current stake before adjusting `user.amount`, meaning a stake made just before `donateRewards` is fully counted in `totalStaked()` at flush time, and is still fully counted when the harvest occurs on the subsequent same-block withdrawal [7](#0-6) .

Exploit flow:
1. Attacker flash-loans a large amount of `stakingToken`.
2. Attacker calls `MasterMagpie.deposit(stakingToken, largeAmount)`, inflating `operator`'s token balance (i.e., `totalStaked()`) and their own `stakingInfo(...).staked`.
3. Attacker calls `donateRewards(1, _rewardToken)` (or any small `_amountReward`). Since `totalStaked() != 0` now, the entire pre-existing `queuedRewards` backlog is folded in and `rewardPerTokenStored` is incremented using the attacker-inflated `totalStaked()` as denominator.
4. Attacker calls `MasterMagpie.withdraw(...)`, which harvests the base rewarder before decrementing stake — crediting the attacker `earned()` proportional to their (still large) `balanceOf` times the just-applied `rewardPerTokenStored` delta, capturing a disproportionate share of the flushed backlog.
5. Attacker repays the flash loan in the same transaction, netting a profit funded by rewards that should have accrued to genuine long-term stakers.

No existing modifier (`onlyManager`, `onlyMasterMagpie`, `nonReentrant`) protects `donateRewards`/`_provisionReward` against this timing manipulation, since `donateRewards` intentionally has no manager restriction and the reward math trusts the instantaneous `totalStaked()`/`balanceOf()` values without any time-weighting or snapshotting.

### Impact Explanation
This breaks the invariant that a queued reward backlog should be distributed among the stakers who actually earned it over time, not a stake set assembled and dissolved within a single transaction. The attacker can direct a disproportionate (and with a large enough flash loan, close to the full) share of the accumulated `queuedRewards` to themselves at zero real capital cost, which is a direct theft of unclaimed yield from legitimate stakers — matching "High - Theft of unclaimed yield."

### Likelihood Explanation
The precondition is simply that `rewards[token].queuedRewards > 0` (i.e., rewards accumulated while `totalStaked() == 0`, or accrued in a low-participation window) and that a flash loan of the staking token is obtainable, which is generally trivial for common tokens. `donateRewards` is fully permissionless and callable by any address, and `MasterMagpie.deposit`/`withdraw` have no timelock, so the whole sequence is atomically composable and repeatable whenever a backlog exists.

### Recommendation
- Snapshot/checkpoint `totalStaked()` and reward accrual using a time-weighted mechanism (e.g., accrue rewards continuously per-second like `accMGPPerShare` in `MasterMagpie.updatePool`, rather than releasing a lump backlog against instantaneous stake).
- Alternatively, restrict `donateRewards`/`queueNewRewards` to only flush `queuedRewards` gradually (streaming) rather than instantly against current `totalStaked()`, or require `updatePool`-style block/time deltas so flash-stakers cannot capture a full period's backlog in one block.
- Consider adding a minimum staking duration or block-delay before a stake counts toward `totalStaked()` for reward-flush purposes.

### Proof of Concept
Foundry test plan:
1. Deploy `MasterMagpie`, `BaseRewardPool` for a mock staking token and reward token; register a legitimate staker who deposits a modest amount.
2. Force `totalStaked() == 0` momentarily is not required — instead, directly build up `queuedRewards` by calling `queueNewRewards`/`donateRewards` while `totalStaked() == 0` (before any stake exists), producing a nonzero `rewards[token].queuedRewards`.
3. Have a legitimate staker deposit (small amount) so pool has some real stake.
4. Simulate an attacker contract that in one transaction:
   - Flash-loans a large amount of the staking token.
   - Calls `MasterMagpie.deposit(stakingToken, largeAmount)`.
   - Calls `donateRewards(1, rewardToken)`.
   - Calls `MasterMagpie.withdraw(stakingToken, largeAmount)`.
   - Repays the flash loan.
5. Assert: attacker's reward-token balance increased (net of the 1-wei donation) while legitimate staker's `earned()` is far below the proportional share they should have received had `totalStaked()` reflected only genuine stakers; assert `balanceOf(attacker)` (via `stakingInfo`) returns to pre-attack value while reward tokens were already distributed based on the transient inflated balance.

    function _provisionReward(uint256 _amountReward, address _rewardToken) internal {
        IERC20(_rewardToken).safeTransferFrom(
            msg.sender,
            address(this),
            _amountReward
        );
        Reward storage rewardInfo = rewards[_rewardToken];
        rewardInfo.historicalRewards =
            rewardInfo.historicalRewards +
            _amountReward;
        if (this.totalStaked() == 0) {
            rewardInfo.queuedRewards += _amountReward;
        } else {
            if (rewardInfo.queuedRewards > 0) {
                _amountReward += rewardInfo.queuedRewards;
                rewardInfo.queuedRewards = 0;
            }
            rewardInfo.rewardPerTokenStored =
                rewardInfo.rewardPerTokenStored +
                (_amountReward * 10**stakingDecimals()) /
                this.totalStaked();
        }

    function _withdraw(address _stakingToken, address _account, uint256 _amount, bool _isVlMgp) internal {
        _harvestAndUnstake(_stakingToken, _account, _amount, _isVlMgp);

        if (!_isVlMgp)
            IERC20(tokenToPoolInfo[_stakingToken].stakingToken).safeTransfer(address(msg.sender), _amount);
        emit Withdraw(_account, _stakingToken, _amount);
    }

    function _harvestAndUnstake(address _stakingToken, address _account, uint256 _amount, bool _isVlMgp) internal {
        updatePool(_stakingToken);

        UserInfo storage user = userInfo[_stakingToken][_account];

        if (!_isVlMgp && user.available < _amount)
            revert WithdrawAmountExceedsStaked();
        else if(user.amount < _amount && _isVlMgp)
            revert UnlockAmountExceedsLocked();
        
        _harvestMGP(_stakingToken, _account);
        _harvestBaseRewarder(_stakingToken, _account);

        user.amount = user.amount - _amount;
        
        if(!_isVlMgp)
            user.available = user.available - _amount;
        user.rewardDebt = (user.amount * tokenToPoolInfo[_stakingToken].accMGPPerShare) / 1e12;
    }
