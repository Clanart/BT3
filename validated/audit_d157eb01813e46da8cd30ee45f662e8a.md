### Title
Governance can set `Kip71GasTarget` to `0`, causing a division-by-zero panic in `NextMagmaBlockBaseFee` during block processing - (File: `params/kip71_config.go`)

### Summary
The `Kip71GasTarget` governance parameter is registered with a `noopFormatChecker`, meaning any `uint64` value — including `0` — is accepted as valid. Unlike `Kip71BaseFeeDenominator`, which is defended against a zero value both by its `FormatChecker` and by a runtime guard inside `NextMagmaBlockBaseFee`, `GasTarget` has no such protection anywhere in the pipeline. If `GasTarget` is voted to `0` and becomes effective, any block whose parent used more than zero gas will make `NextMagmaBlockBaseFee` divide a `big.Int` by zero, panicking every honest node that processes that block.

### Finding Description
`Kip71GasTarget` is defined with `Canonicalizer: uint64Canonicalizer` and `FormatChecker: noopFormatChecker` — the no-op checker accepts every value: [1](#0-0) 

By contrast, its sibling parameter `Kip71BaseFeeDenominator` explicitly rejects `0`: [2](#0-1) 

The vote-consistency check in `headerGovModule.checkConsistency` does not add any extra validation for `Kip71GasTarget` either — it simply falls into the pass-through case: [3](#0-2) 

Once a `GasTarget = 0` vote is finalized, `ParamSet.ToKip71Config()` propagates it unchanged into `KIP71Config.GasTarget`: [4](#0-3) 

`NextMagmaBlockBaseFee` guards `BaseFeeDenominator == 0` (falling back to 64) but does **not** guard `GasTarget == 0`: [5](#0-4) 

With `gasTarget = 0` and any `parentGasUsed > 0`, execution enters the "gas used above target" branch and performs `x.Div(x, new(big.Int).SetUint64(gasTarget))`, i.e., division by zero: [6](#0-5) 

`(*big.Int).Div` panics on a zero divisor, so every node computing the next base fee for that block — which happens during ordinary header verification/block building on all full nodes — panics.

### Impact Explanation
This function is called on the hot path of block validation and building via `VerifyMagmaHeader`/`NextMagmaBlockBaseFee`, used pervasively (e.g., by the block processor, gas price oracle, `feehistory.go`). A single governance vote setting `Kip71GasTarget = 0` that becomes canonical would cause all honest nodes to panic identically once a block with nonzero gas usage is processed, effectively halting the chain — a Kip71/KIP-71 base fee (EIP-1559-style) consensus-critical parameter accepting an invalid value with no safety fallback (unlike the sibling `BaseFeeDenominator`).

### Likelihood Explanation
Requires a governance vote (via `header.Vote`, cast by council members/proposer, or via the `GovParam` contract) to set `Kip71GasTarget` to `0`. This mirrors exactly the reported bug class: a state variable/parameter documented/expected to be constrained (here, must be `> 0` to be usable as a divisor) has no format/range validation anywhere in the setter/voting pipeline, so a single mistaken or malicious governance transaction is sufficient to introduce the invalid value — same class of issue as `Game.sol#setNegativeRewardThreshold` accepting values it must not accept.

### Recommendation
Add a `FormatChecker` to `Kip71GasTarget` in `kaiax/gov/param.go` requiring `v > 0`, mirroring the check already used for `Kip71BaseFeeDenominator` and `IstanbulCommitteeSize`. Additionally, add a defensive `GasTarget == 0` fallback inside `NextMagmaBlockBaseFee` in `params/kip71_config.go`, consistent with the existing `BaseFeeDenominator == 0` fallback, so that even a pre-existing invalid config cannot crash the node.

### Proof of Concept
1. Governance council votes `Kip71GasTarget = 0` (accepted because `FormatChecker` is `noopFormatChecker`, and `checkConsistency` in `kaiax/gov/headergov/impl/header.go` performs no extra check for this parameter).
2. Once the vote is finalized and the epoch takes effect, `ParamSet.GasTarget = 0` is used to build `KIP71Config` via `ToKip71Config()`.
3. Any subsequent block with `parentHeaderGasUsed > 0` triggers `NextMagmaBlockBaseFee`, which executes `gasUsedDelta := parentGasUsed - gasTarget` (nonzero) then `y := x.Div(x, new(big.Int).SetUint64(gasTarget))` with `gasTarget = 0`.
4. `(*big.Int).Div` panics with "division by zero", crashing every node that verifies or builds this block, halting the chain.
