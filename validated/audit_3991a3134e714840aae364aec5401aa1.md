### Title
Attacker can rewrite `payout_payer_operator_xonly_pk` attribution by front-running the payout tx's unsigned inputs/outputs, crediting reimbursement to an arbitrary operator - (File: `core/src/builder/transaction/operator_reimburse.rs`)

### Summary
`create_payout_txhandler` signs the payout transaction's input 0 with `SinglePlusAnyoneCanPay`, which only commits to input 0 and output 0; the funding input(s) and the OP_RETURN output (holding the fronting operator's xonly pubkey) are left unsigned. `Verifier::update_finalized_payouts` attributes a withdrawal to whichever operator xonly pubkey appears in the OP_RETURN of the first transaction seen spending the withdrawal UTXO, with no check that this pubkey belongs to whoever actually funded the payout. An unprivileged attacker can therefore mine a variant transaction first, funding it with their own extra input, and stamp any operator's public xonly pubkey (learned via `Aggregator::fetch_operator_keys`, a public RPC) into the OP_RETURN.

### Finding Description
The claimed binding is: `payout_payer_operator_xonly_pk[withdrawal_idx] == xonly_pk of the operator whose funds actually paid withdrawal_idx`.

`create_payout_txhandler` builds the payout tx with input 0 = withdrawal UTXO (`SpendPath::KeySpend`), output 0 = user payout, output 1 = anchor, output 2 = OP_RETURN carrying `operator_xonly_pk.serialize()`, and signs input 0 with the caller-provided sighash type: [1](#0-0) 

`calculate_pubkey_spend_sighash` shows that for `SinglePlusAnyoneCanPay` the prevouts used are `Prevouts::One(txin_index, ...)`, i.e. the signature only commits to input 0 and (by BIP-341 SIGHASH_SINGLE semantics) output 0: [2](#0-1) 

The test helper `sign_withdrawal_output` confirms this exact signing pattern used by the real withdrawal flow (dust UTXO input 0, output 0, sighash `SinglePlusAnyoneCanPay`): [3](#0-2) 

Because this signature does not cover any additional inputs or the anchor/OP_RETURN outputs, anyone possessing the tuple (`withdrawal outpoint`, `output0 script/amount`, `signature`) — which is broadcast on Citrea (`WithdrawParams`) and observable — can construct their own transaction spending the *same* input 0, add a second, attacker-funded input, and freely choose outputs 1/2, including the OP_RETURN xonly pubkey.

On the verifier side, attribution is derived purely from whichever transaction first spends the withdrawal outpoint, matched only by `(txid, vout)`, with no signature/funder check: [4](#0-3) 

`update_finalized_payouts` then parses the OP_RETURN of that mined transaction and writes it verbatim as `payout_payer_operator_xonly_pk`: [5](#0-4) [6](#0-5) 

On the operator side, `PayoutCheckerTask::run_once` queries unhandled payouts filtered strictly by `self.operator.signer.xonly_public_key` matching this DB column, and if a match is found, unconditionally proceeds to `handle_finalized_payout` (kickoff creation, reimbursement flow) for a deposit this operator never actually withdrew for: [7](#0-6) [8](#0-7) 

The verifier-side sanity check `is_kickoff_malicious` only compares the operator xonly pk *committed in the kickoff* against the (already-poisoned) DB value and checks the payout blockhash matches the (already-poisoned) DB value — both trivially pass since they are being compared against the same corrupted row, not against the actual funder of the payout: [9](#0-8) 

No code path anywhere validates that the OP_RETURN pubkey corresponds to the entity that actually supplied the funding input(s) of the payout transaction. The `Operator::withdraw` gRPC call is never consulted by this flow at all — attribution is 100% determined by on-chain OP_RETURN content of whichever transaction wins the outpoint race.

### Impact Explanation
This directly matches the Critical category "an operator reimbursed for a payout it never funded." An attacker who funds the withdrawal (using their own BTC, since only output 0 to the user is bound by the user's signature) can name any real operator's public xonly pubkey in the OP_RETURN. That named operator's `PayoutCheckerTask` (if automation is enabled) will autonomously treat this as its own unhandled payout, and drive the kickoff/round/reimburse flow to completion, ultimately spending the move-to-vault deposit output to the named operator's reimbursement address — even though that operator never called `withdraw` and never funded the payout. The blast radius is per-withdrawal and repeatable across every deposit/withdrawal cycle and against any operator whose xonly pubkey is public (all operators' keys are public via `Aggregator::fetch_operator_keys`). This decouples the bridge's fundamental "pay once, reimburse once, to the right payer" invariant, letting an attacker arbitrarily redirect the reimbursement credit for a withdrawal to any operator of their choosing.

### Likelihood Explanation
Preconditions: attacker must be able to observe or predict the honest payout's `(withdrawal_outpoint, output0, user_sig)` before it confirms (these are visible in mempool, or the attacker can independently front the withdrawal itself as the "fronting" party using data available from Citrea's withdraw call), and must win the race to have their variant transaction mined first (fee-bump / block inclusion race, standard mempool tactics). Attacker cost: the withdrawal amount + fees (they are effectively paying the user out of pocket) plus normal BTC transaction fees; no verifier/operator/aggregator privilege, collateral, or key material is required. This is feasible on regtest/testnet for a `cargo test` proof and works against any deployment configuration where a payout tx's OP_RETURN is trusted without independently verifying the funder identity. It is repeatable for every withdrawal.

### Recommendation
Do not derive payer attribution solely from an unauthenticated OP_RETURN in whichever transaction spends the withdrawal outpoint first. Either (a) sign the operator's OP_RETURN commitment with `SIGHASH_ALL`/`SIGHASH_DEFAULT` so all outputs (including the OP_RETURN) and all inputs are covered by a single non-malleable signature from the actual fronting operator, or (b) bind attribution cryptographically to the operator, e.g. require the operator to additionally sign (with their own key, verified via `SECP.verify_schnorr`) a commitment over the full payout txid before `update_finalized_payouts` accepts the OP_RETURN pubkey, or (c) require that the funding input(s) beyond input 0 be provably controlled by the operator whose pubkey appears in the OP_RETURN (e.g., verify a script/signature tying the extra inputs to that operator's registered address) before recording `payout_payer_operator_xonly_pk`.

### Proof of Concept
`cargo test` plan (regtest, no mainnet, no live Citrea, using `MockCitreaClient`):
1. Run a standard deposit + `withdraw` flow to obtain the honest payout tx components: `withdrawal_utxo`, `output_txout`, `user_sig` (SinglePlusAnyoneCanPay), as done in `full_flow.rs`/`deposit_and_withdraw_e2e.rs` helpers.
2. Build the honest `create_payout_txhandler(input_utxo, output_txout, operator0_xonly_pk, user_sig, network)` but do NOT broadcast it.
3. As "attacker", build a variant transaction manually: same input 0 (`input_utxo.outpoint`) with the copied witness from step 2 (reusing `user_sig`), add a second attacker-funded input (e.g. from a locally controlled UTXO) to cover fees/amount, keep output 0 identical (payout to user, required by SIGHASH_SINGLE), and set the OP_RETURN (output 2) to `operator1_xonly_pk` (a second, real registered operator, distinct from operator0).
4. Verify the variant transaction is valid: `SECP.verify_schnorr` on `payout_txhandler.calculate_sighash_txin(0, SinglePlusAnyoneCanPay)` still succeeds against `user_sig` and `user_xonly_pk` because inputs/outputs beyond index 0 are unconstrained.
5. Broadcast and mine the attacker's variant first; run block sync so `Verifier::update_finalized_payouts` processes it.
6. Assert `db.get_payout_info_from_move_txid(...).0 == Some(operator1_xonly_pk)` (i.e., `payout_payer_operator_xonly_pk == operator1_xonly_pk`), NOT `operator0_xonly_pk` — this is the equality that should have matched the actual funder (operator0/attacker) but instead matches the falsely attributed operator1.
7. Run `PayoutCheckerTask::run_once` for `operator1` and assert it returns `Ok(true)` and calls `handle_finalized_payout`, proceeding to kickoff/reimbursement — despite `operator1` never having called `Operator::withdraw` for this withdrawal index, confirming the ATTRIBUTION binding is broken.

pub fn create_payout_txhandler(
    input_utxo: UTXO,
    output_txout: TxOut,
    operator_xonly_pk: XOnlyPublicKey,
    user_sig: taproot::Signature,
    _network: bitcoin::Network,
) -> Result<TxHandler<Signed>, BridgeError> {
    let txin = SpendableTxIn::new_partial(input_utxo.outpoint, input_utxo.txout);

    let output_txout = UnspentTxOut::from_partial(output_txout.clone());

    let op_return_txout = op_return_txout(PushBytesBuf::from(operator_xonly_pk.serialize()));

    let mut txhandler = TxHandlerBuilder::new(TransactionType::Payout)
        .with_version(NON_STANDARD_V3)
        .add_input(
            NormalSignatureKind::NotStored,
            txin,
            SpendPath::KeySpend,
            DEFAULT_SEQUENCE,
        )
        .add_output(output_txout)
        .add_output(UnspentTxOut::from_partial(anchor_output(
            NON_EPHEMERAL_ANCHOR_AMOUNT,
        )))
        .add_output(UnspentTxOut::from_partial(op_return_txout))
        .finalize();
    txhandler.set_p2tr_key_spend_witness(&user_sig, 0)?;
    txhandler.promote()
}

fn sign_withdrawal_output(
    config: &BridgeConfig,
    dust_utxo: &UTXO,
    withdrawal_address: &bitcoin::Address,
    withdrawal_amount: bitcoin::Amount,
) -> (bitcoin::TxOut, taproot::Signature) {
    let signer = Actor::new(config.secret_key, config.protocol_paramset().network);
    let txin = builder::transaction::input::SpendableTxIn::new(
        dust_utxo.outpoint,
        dust_utxo.txout.clone(),
        vec![],
        None,
    );
    let txout = bitcoin::TxOut {
        value: withdrawal_amount,
        script_pubkey: withdrawal_address.script_pubkey(),
    };
    let unspent_txout = builder::transaction::output::UnspentTxOut::from_partial(txout.clone());

    let tx = builder::transaction::TxHandlerBuilder::new(TransactionType::Payout)
        .with_version(NON_STANDARD_V3)
        .add_input(
            NormalSignatureKind::NotStored,
            txin,
            SpendPath::KeySpend,
            builder::transaction::DEFAULT_SEQUENCE,
        )
        .add_output(unspent_txout.clone())
        .finalize();

    let sighash = tx
        .calculate_sighash_txin(0, sighash::TapSighashType::SinglePlusAnyoneCanPay)
        .expect("Failed to calculate sighash");

    let sig = signer
        .sign_with_tweak_data(sighash, builder::sighash::TapTweakData::KeyPath(None), None)
        .expect("Failed to sign");

    let sig = taproot::Signature {
        signature: sig,
        sighash_type: sighash::TapSighashType::SinglePlusAnyoneCanPay,
    };

    (txout, sig)
}
