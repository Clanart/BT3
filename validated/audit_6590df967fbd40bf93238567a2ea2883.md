### Title
`ReceivedOutput::read` accepts a scalar offset inconsistent with the output's `script_pubkey`, letting forged outputs be attributed to a Serai key as spendable funds - ([File: networks/bitcoin/src/wallet/mod.rs](networks/bitcoin/src/wallet/mod.rs))

### Summary
`ReceivedOutput` pairs a `Scalar` offset with a Bitcoin `TxOut`/`OutPoint`. Its only invariant — that `output.script_pubkey` equals `p2tr(key + G * offset)` for the scanning key — is established by construction in `Scanner::scan_transaction`, but `ReceivedOutput::read` deserializes all three fields from untrusted bytes with no consistency check. An attacker who can feed crafted bytes into `ReceivedOutput::read` (e.g., a serialized `Output` consumed by the processor) can cause an arbitrary on-chain output to be reported as received by, and spendable under, a Serai multisig key, when it is not.

### Finding Description
`ReceivedOutput::read` reads `offset` via `Secp256k1::read_F`, then consensus-decodes an arbitrary `TxOut` and `OutPoint`, returning the triple verbatim: [1](#0-0) 

There is no parameter for the expected base key and no verification that `output.script_pubkey == p2tr_script_buf(key + GENERATOR * offset)`. Contrast with the honest construction path, where the offset is only attached because the script matched a registered script: [2](#0-1) 

The inconsistency is masked downstream: `Output::key()` derives the attributed key by *subtracting* `GENERATOR * offset` from whatever key is embedded in `script_pubkey`, so any attacker-chosen pair `(key_in_script, offset)` yields a self-consistent "key" rather than being rejected: [3](#0-2) 

`Output::read` then wraps the forged `ReceivedOutput` with an attacker-chosen `OutputType` and `data`, again without checking the offset/script relationship or that the output was ever produced by `Scanner::scan_transaction`: [4](#0-3) 

This is the same bug class as the Syncope advisory: structured input fields are accepted and trusted without validating the semantic constraint that binds them together (there, text fields flowed to rendering unescaped; here, an offset/script_pubkey/outpoint triple flows to the scheduler unbound to the actual scanned key).

### Impact Explanation
A forged `ReceivedOutput` reports funds as received that are not spendable by the multisig. When such an output reaches the scheduler/signing path, `SignableTransaction::new` treats it as a real input: it sums `input.output.value` into `input_sat` and builds a `TxIn` for the attacker-chosen `outpoint` [5](#0-4) . The multisig then produces a signature for `key + offset` that does not correspond to the output's actual locking script (or spends an outpoint not controlled by Serai at all). Consequences:

- Outputs are credited to the multisig balance that can never be spent — corrupted accounting and plans that permanently fail or stall while they reference the forged input.
- By choosing `offset` adversarially, `Output::key()` can attribute an output to a *different* key than the one that actually owns the script, causing cross-key misattribution in the processor.

### Likelihood Explanation
Reachability requires untrusted bytes reaching `ReceivedOutput::read`/`Output::read`, which the in-scope surface explicitly covers. The crafted encoding is trivial: a canonical 32-byte scalar plus consensus-valid `TxOut`/`OutPoint` encodings — no cryptographic hardness stands between the attacker and a consistent-looking forgery, since the consistency check simply does not exist. Severity is bounded to Medium: the primitive yields misaccounting and unspendable-fund reporting rather than direct key recovery, and exploiting it still requires a channel that feeds attacker-controlled serialized outputs into a processor.

### Recommendation
Bind the offset to the script at deserialization time. Either:

- Store the expected base key alongside the serialized form and have `ReceivedOutput::read`/`Output::read` verify `p2tr_script_buf(key + GENERATOR * offset) == output.script_pubkey` (rejecting on `None`/mismatch), or
- Deserialize only the `TxOut`/`OutPoint` and re-derive the offset by running `Scanner::scan_transaction`-equivalent lookup against the registered `scripts` map, so the offset can never be attacker-supplied independently of the script.

Add a regression test that serializes a legitimate `ReceivedOutput`, mutates the `offset` field, and asserts `read` returns an error.

### Proof of Concept
```rust
// networks/bitcoin — demonstrates the missing binding check
use bitcoin_serai::{wallet::{ReceivedOutput, Scanner, p2tr_script_buf}, bitcoin::{TxOut, OutPoint, Amount, ScriptBuf, Txid, hashes::Hash}};
use ciphersuite_kp256::Secp256k1;
use ciphersuite::{group::ff::Field, Ciphersuite};
use k256::{ProjectivePoint, Scalar};

let mut rng = rand_core::OsRng;
// Honest setup: a key and a real received output paying to it
let key = ProjectivePoint::GENERATOR * Scalar::random(&mut rng);
let mut scanner = Scanner::new(key).unwrap();
let offset = scanner.register_offset(Scalar::random(&mut rng)).unwrap();
let real_script = p2tr_script_buf(key + ProjectivePoint::GENERATOR * offset).unwrap();

// Attacker crafts a ReceivedOutput: real script_pubkey (so the entry looks
// like funds to this key) but a WRONG offset — or conversely a script paying
// to an unrelated key with an offset chosen so Output::key() still returns
// the multisig key.
let forged_offset = Scalar::random(&mut rng); // != offset
let forged = ReceivedOutput {
    offset: forged_offset,
    output: TxOut { value: Amount::from_sat(100_000), script_pubkey: real_script.clone() },
    outpoint: OutPoint { txid: Txid::all_zeros(), vout: 0 },
};

// Round-trips cleanly: no consistency check rejects it
let bytes = forged.serialize();
let decoded = ReceivedOutput::read(&mut bytes.as_slice()).unwrap();
assert_eq!(decoded, forged); // accepted despite offset/script mismatch

// Downstream, Output::key() happily returns `key`, so the output is
// attributed to the multisig — yet signing with `forged_offset` produces a
// key that does NOT match real_script, making the "received" funds
// unspendable.
```
(Note: struct fields are private; equivalent effect is obtained by hand-serializing `offset || TxOut || outpoint` bytes, which `ReceivedOutput::read` accepts identically.)

    let offset = Secp256k1::read_F(r)?;
    let output;

      outpoint =

    }

  }

  /// Scan a transaction.
  pub fn scan_transaction(&self, tx: &Transaction) -> Vec<ReceivedOutput> {
    let mut res = Vec::new();
    for (vout, output) in tx.output.iter().enumerate() {
      // If the vout index exceeds 2**32, stop scanning outputs
      let Ok(vout) = u32::try_from(vout) else { break };

      if let Some(offset) = self.scripts.get(&output.script_pubkey) {
        res.push(ReceivedOutput {
          offset: *offset,
          output: output.clone(),
          outpoint: OutPoint::new(tx.compute_txid(), vout),
        });
      }
    }
    res
  }
