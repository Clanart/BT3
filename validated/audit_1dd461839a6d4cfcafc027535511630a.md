### Title
Bridge circuit journal/Groth16 public input never binds the payout amount fronted to the withdrawer - (File: circuits-lib/src/bridge_circuit/mod.rs)

### Summary
The bridge circuit only verifies that `payout_spv.transaction.input[payout_input_index].previous_output` matches the withdrawal outpoint identified by the storage proof, but it never inspects any `TxOut::value` of `payout_spv.transaction` to confirm the operator actually paid the withdrawer the owed amount. Consequently `host_journal_hash`/`calculate_groth16_public_input` — built solely from `payout_tx_block_hash`, `latest_block_hash`, `challenge_sending_watchtowers`, and `deposit_constant` — are identical whether the payout transaction fully pays the user or pays them a negligible/zero amount.

### Finding Description
Binding claimed: `Groth16 public input committed == f(amount fronted to withdrawer)`. Trace shows this does not hold.

`bridge_circuit` in `circuits-lib/src/bridge_circuit/mod.rs` performs these checks on the payout transaction:
- SPV inclusion check [1](#0-0) 
- storage-proof-derived withdrawal outpoint/vout must equal `payout_spv.transaction.input[payout_input_index].previous_output` (identity of which withdrawal request is being fulfilled) [2](#0-1) 
- `deposit_constant` computed from `operator_xonlypk`, watchtower connector index, tweaked watchtower pubkeys, `move_txid`, `round_txid`, `kickoff_round_vout`, `genesis_state_hash` [3](#0-2) 
- final `journal_hash` combines only `payout_tx_blockhash`, `latest_blockhash`, `challenge_sending_watchtowers`, `deposit_constant` [4](#0-3) 

None of these four committed values, nor any intermediate check, reads any `TxOut::value` from `payout_spv.transaction`'s outputs (only the OP_RETURN script and the spent input's `previous_output` are inspected). The host mirrors this exactly in `SuccinctBridgeCircuitPublicInputs::new`/`host_journal_hash` and `host_deposit_constant` [5](#0-4) , and the BitVM-facing `BridgeCircuitBitvmInputs::calculate_groth16_public_input`/`verify_bridge_circuit` operate purely on the same four fields [6](#0-5) .

`verify_storage_proofs` in `circuits-lib/src/bridge_circuit/storage_proof.rs` only returns `(withdrawal_outpoint_txid, vout, move_txid)` — the outpoint identity, never a value/amount field [7](#0-6) .

Exploit flow: an operator (attacker with respect to this binding, since the question's actor model allows anyone shaping the payout tx bytes) constructs a payout transaction that correctly spends the required `previous_output` (satisfying the identity check) but sends a dust/zero-value output to the user instead of the full withdrawal amount, keeping the rest for itself/fees. Because no check anywhere in `bridge_circuit`, `SuccinctBridgeCircuitPublicInputs`, or `BridgeCircuitBitvmInputs` reads the paid-out `TxOut::value`, the resulting journal hash and Groth16 public input are bit-for-bit identical to those of a transaction that paid the full amount, given identical block/watchtower/deposit_constant context. `verify_bridge_circuit`/BitVM2 disprove scripts can therefore never distinguish the two cases — there is no assertion path in the circuit that a challenger/verifier can invoke to prove the amount was wrong, because the amount was never part of the computation being proved.

### Impact Explanation
This allows "an operator reimbursed for a payout it never funded" (or funded only partially) — a Critical-category impact per the audit's impact list. The operator can claim full reimbursement from the bridge for a withdrawal it paid little or nothing for, and this is repeatable across every withdrawal/deposit the operator processes, since the missing check is structural (in the shared `bridge_circuit`/`journal_hash` logic used for all payouts), not tied to one deposit.

### Likelihood Explanation
No privileged access is required beyond being the operator who constructs and broadcasts its own payout transaction on Bitcoin — which is standard operator behavior in this protocol. The only "cost" is normal Bitcoin transaction fees; the attacker does not need to spend the withdrawal amount itself, which is exactly the exploit's benefit. Preconditions are simply: a legitimate withdrawal request exists (so `withdrawal_utxo`/storage proof are valid) and the operator crafts the payout output(s) to underpay. This is deployment-configuration independent (mainnet, testnet4, signet, regtest all share the same `bridge_circuit`/`journal_hash` code path).

### Recommendation
Bind the actual amount paid to the withdrawer into the committed public input. Concretely, extract the `TxOut::value` of the output that pays the withdrawal address in `payout_spv.transaction` (at a well-defined, storage-proof-verified index/script), compare it against the withdrawal amount recorded in the Citrea storage proof (or fold it into `deposit_constant`/a new committed field), and panic/fail if they do not match before computing `journal_hash`. This must be mirrored in `host_deposit_constant`/`SuccinctBridgeCircuitPublicInputs::new` and in the BitVM Winternitz-committed values so the on-chain disprove scripts can detect a mismatch.

/// Calculates the deposit constant from bridge circuit input.
///
/// # Arguments
///
/// * `input` - The bridge circuit input containing deposit information
///
/// # Returns
///
/// Returns a `Result` containing the `DepositConstant` or an error.
///
/// # Errors
///
/// This function will return an error if:
/// - Transaction output is missing
/// - Storage proof deserialization fails
/// - Operator public key parsing fails
/// - Round transaction ID validation fails
fn host_deposit_constant(
    input: &BridgeCircuitInput,
) -> Result<DepositConstant, BridgeCircuitHostParamsError> {
    let first_op_return_output = get_first_op_return_output(&input.payout_spv.transaction)
        .ok_or(BridgeCircuitHostParamsError::InvalidOperatorPubkey)?;

    let deposit_storage_proof: EIP1186StorageProof =
        serde_json::from_str(&input.sp.storage_proof_deposit_txid).map_err(|e| {
            BridgeCircuitHostParamsError::StorageProofDeserializationError(e.to_string())
        })?;

    let round_txid = input.kickoff_tx.input[0]
        .previous_output
        .txid
        .to_byte_array();

    let kickoff_round_vout = input.kickoff_tx.input[0].previous_output.vout;

    let operator_xonlypk: [u8; 32] = parse_op_return_data(&first_op_return_output.script_pubkey)
        .ok_or(BridgeCircuitHostParamsError::InvalidOperatorPubkey)?
        .try_into()
        .map_err(|_| BridgeCircuitHostParamsError::InvalidOperatorPubkey)?;

    let deposit_value_bytes: [u8; 32] = deposit_storage_proof.value.to_be_bytes::<32>();

    Ok(deposit_constant(
        operator_xonlypk,
        input.watchtower_challenge_connector_start_idx,
        &input.all_tweaked_watchtower_pubkeys,
        deposit_value_bytes,
        round_txid,
        kickoff_round_vout,
        input.hcp.genesis_state_hash,
    ))
}

    pub fn calculate_groth16_public_input(&self) -> blake3::Hash {
        let concatenated_data = [
            self.payout_tx_block_hash,
            self.latest_block_hash,
            self.challenge_sending_watchtowers,
        ]
        .concat();
        let x = blake3::hash(&concatenated_data);
        let hash_bytes = x.as_bytes();

        let concat_journal = [self.deposit_constant, *hash_bytes].concat();

        let journal_hash = blake3::hash(&concat_journal);

        let hash_bytes = journal_hash.as_bytes();

        let concat_input = [self.combined_method_id, *hash_bytes].concat();

        blake3::hash(&concat_input)
    }

    /// Verifies a bridge circuit Groth16 proof.
    ///
    /// This method verifies that a given Groth16 proof is valid for this bridge circuit
    /// by computing the expected public input and verifying the proof against it.
    ///
    /// # Arguments
    ///
    /// * `proof` - The Groth16 proof to verify
    ///
    /// # Returns
    ///
    /// Returns a `Result` containing `true` if the proof is valid, or an error if verification fails.
    ///
    /// # Errors
    ///
    /// This function will return an error if:
    /// - Proof verification fails
    /// - Public input calculation fails
    /// - Verifying key retrieval fails
    pub fn verify_bridge_circuit(
        &self,
        proof: ark_groth16::Proof<Bn254>,
    ) -> Result<bool, BridgeCircuitHostParamsError> {
        let mut hasher = blake3::Hasher::new();
        hasher.update(&self.payout_tx_block_hash);
        hasher.update(&self.latest_block_hash);
        hasher.update(&self.challenge_sending_watchtowers);
        let x = hasher.finalize();
        let x_bytes: [u8; 32] = x.into();

        let mut hasher = blake3::Hasher::new();
        hasher.update(&self.deposit_constant);
        hasher.update(&x_bytes);
        let y = hasher.finalize();
        let y_bytes: [u8; 32] = y.into();

        let mut hasher = blake3::Hasher::new();
        hasher.update(&self.combined_method_id);
        hasher.update(&y_bytes);
        let public_output = hasher.finalize();

        let public_output_bytes: [u8; 32] = public_output.into();
        let public_input_scalar =
            ark_bn254::Fr::from_be_bytes_mod_order(&public_output_bytes[0..31]);

        let ark_vk = get_ark_verifying_key_prod();
        let ark_pvk = ark_groth16::prepare_verifying_key(&ark_vk);

        ark_groth16::Groth16::<ark_bn254::Bn254>::verify_proof(
            &ark_pvk,
            &proof,
            &[public_input_scalar],
        )
        .map_err(|_| BridgeCircuitHostParamsError::ProofVerificationFailed)
    }

pub fn verify_storage_proofs(
    storage_proof: &StorageProof,
    state_root: [u8; 32],
) -> (WithdrawalOutpointTxid, u32, MoveTxid) {
    let utxo_storage_proof: EIP1186StorageProof =
        serde_json::from_str(&storage_proof.storage_proof_utxo)
            .expect("Failed to deserialize UTXO storage proof");

    let vout_storage_proof: EIP1186StorageProof =
        serde_json::from_str(&storage_proof.storage_proof_vout)
            .expect("Failed to deserialize vout storage proof");

    let deposit_storage_proof: EIP1186StorageProof =
        serde_json::from_str(&storage_proof.storage_proof_deposit_txid)
            .expect("Failed to deserialize deposit storage proof");

    let storage_address: U256 = {
        let mut keccak = Keccak256::new();
        keccak.update(UTXOS_STORAGE_INDEX);
        let hash = keccak.finalize();
        U256::from_be_bytes(
            <[u8; 32]>::try_from(&hash[..]).expect("Hash slice has incorrect length"),
        )
    };

    let storage_key_utxo: alloy_primitives::Uint<256, 4> =
        storage_address + U256::from(storage_proof.index * 2);

    let storage_key_vout: alloy_primitives::Uint<256, 4> =
        storage_address + U256::from(storage_proof.index * 2 + 1);

    let storage_address_deposit: U256 = {
        let mut keccak = Keccak256::new();
        keccak.update(DEPOSIT_STORAGE_INDEX);
        let hash = keccak.finalize();
        U256::from_be_bytes(
            <[u8; 32]>::try_from(&hash[..]).expect("Hash slice has incorrect length"),
        )
    };

    let deposit_storage_key: alloy_primitives::Uint<256, 4> =
        storage_address_deposit + U256::from(storage_proof.index);

    let deposit_storage_key_bytes = deposit_storage_key.to_be_bytes::<32>();

    if deposit_storage_key_bytes != deposit_storage_proof.key.as_b256().0 {
        panic!(
            "Invalid deposit storage key. left: {:?} right: {:?}",
            deposit_storage_key_bytes,
            deposit_storage_proof.key.as_b256().0
        );
    }

    if storage_key_utxo.to_be_bytes() != utxo_storage_proof.key.as_b256().0 {
        panic!(
            "Invalid withdrawal UTXO storage key. left: {:?} right: {:?}",
            storage_key_utxo.to_be_bytes::<32>(),
            utxo_storage_proof.key.as_b256().0
        );
    }

    if storage_key_vout.to_be_bytes() != vout_storage_proof.key.as_b256().0 {
        panic!(
            "Invalid withdrawal vout storage key. left: {:?} right: {:?}",
            storage_key_vout.to_be_bytes::<32>(),
            vout_storage_proof.key.as_b256().0
        );
    }

    storage_verify(&utxo_storage_proof, state_root);

    storage_verify(&deposit_storage_proof, state_root);

    storage_verify(&vout_storage_proof, state_root);

    let buf: [u8; 32] = vout_storage_proof.value.to_be_bytes();

    // ENDIANNESS SHOULD BE CHECKED THIS FIELD IS 4 BYTES in the contract
    let vout = u32::from_le_bytes(
        buf[28..32]
            .try_into()
            .expect("Vout value conversion failed"),
    );

    let wd_outpoint = WithdrawalOutpointTxid(utxo_storage_proof.value.to_be_bytes());

    let move_txid = MoveTxid(deposit_storage_proof.value.to_be_bytes());

    (wd_outpoint, vout, move_txid)
}
