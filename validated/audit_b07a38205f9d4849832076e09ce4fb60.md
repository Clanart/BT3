### Title
Silent, unvalidated rewrite of the local git remote URL from GitHub API repository data - (File: `app/src/lib/stores/updates/update-remote-url.ts`)

### Summary
`updateRemoteUrl()` automatically rewrites a repository's local `origin` remote to whatever URL a GitHub API response reports as the repository's `clone_url`, without ever checking that the new URL still points to the same host as the one the user originally configured. The only guards are that the *protocol* stays the same and that the *previous* remote still matched the *previously cached* clone URL. Nothing verifies that the *new* target host is the same as the *old* one, so a malicious or compromised API endpoint (e.g. a rogue/compromised GitHub Enterprise Server, which is an explicitly in-scope "GitHub API object" attacker) can redirect the user's `origin` to an attacker-controlled server, silently.

### Finding Description
`updateRemoteUrl()` is invoked with `apiRepo`, an `IAPIRepository`/`IAPIFullRepository` object obtained from the GitHub API, and decides whether to call `gitStore.setRemoteURL()`: [1](#0-0) 

The checks performed are:
- `protocolsMatch` — only compares the URL scheme (http/https/ssh), not the host.
- `remoteUrlUnchanged` — verifies the *current* remote still matches the *previously known* `gitHubRepository.cloneURL` (i.e. the user hasn't manually customized the remote), via `urlMatchesRemote`, which does compare hostname/owner/name: [2](#0-1) 
- `urlsMatch` — only used to confirm the new URL is actually *different* from the current one.

Crucially, there is no check that `updatedRemoteUrl` (`apiRepo.clone_url`, the *new* target) shares the same hostname as the *old* remote/cached `gitHubRepository.cloneURL`. As long as the cached `GitHubRepository` record for that repo still reflects the old (unmodified) remote, and the API subsequently returns a `clone_url` on a completely different host, Desktop will call `setRemoteURL()` and rewrite `origin` to that new, arbitrary host: [3](#0-2) [4](#0-3) 

This is functionally the same broken invariant as the `OmoAgent.setPositionManager` bug: a critical reference (`positionManager` / the git remote's target host) is updated in-place based on an externally supplied value, with no validation that the new value is compatible with everything that already depends on the old one (deposited positions / the user's trust that `origin` points to the repo they added).

The consequence compounds with the credential trampoline's account-matching logic, which resolves GitHub credentials purely by *origin* comparison against the remote URL: [5](#0-4) [6](#0-5) 

If the attacker-controlled `clone_url` host happens to coincide with any endpoint the victim has an account for, git operations against the rewritten remote will be issued with that account's token attached — none of this requires the user to notice or approve the remote change, since `updateRemoteUrl` is called silently as part of repository refresh flows.

### Impact Explanation
A repository whose GitHub-side metadata is controlled by an attacker (a malicious or compromised GitHub Enterprise Server the victim has added as an account, or an attacker-owned/renamed repository on that instance) can cause Desktop to silently repoint the victim's local `origin` remote to an arbitrary host. Because the change happens transparently in the background (no dialog, no diff shown to the user), the user's next `git push`/`git fetch` (all subsequent commits) is silently redirected to the attacker's endpoint — this is exactly the "silent corruption of what the user commits or pushes" impact class, and can additionally leak credentials to the wrong host if the trampoline's origin-based account match resolves in the attacker's favor.

### Likelihood Explanation
This requires the victim to have added an account for a GitHub Enterprise Server the attacker controls (or has compromised), and to have a repository from that server open in Desktop while the API subsequently serves a `clone_url` pointing elsewhere. This is a realistic but non-trivial precondition (medium likelihood, mirroring the original report's medium/medium rating) — it does not require local access, admin rights, or pre-existing malware, only a hostile/compromised API endpoint the user already trusted for authentication.

### Recommendation
In `updateRemoteUrl()`, validate that `updatedRemoteUrl`'s hostname matches the hostname of the *current* remote (or the account's configured endpoint) before calling `gitStore.setRemoteURL()`. If the hostname differs, treat it the same way a manual remote/host mismatch is already handled elsewhere (e.g., surface a confirmation dialog similar to `UpstreamAlreadyExists`) instead of silently rewriting the remote.

### Proof of Concept
1. Victim adds a GitHub Enterprise account for `ghe.evil-controlled.example` and clones a repository from it, creating `origin` pointing at `https://ghe.evil-controlled.example/org/repo.git`.
2. Attacker (who administers/compromised that GHES instance) later serves an API response for that same repository id where `clone_url` is `https://attacker.example/whatever/repo.git`.
3. Desktop's background refresh calls `updateRemoteUrl(gitStore, gitHubRepository, apiRepo)`; since the current remote still equals the cached `gitHubRepository.cloneURL` (`remoteUrlUnchanged` is true) and the protocol is unchanged (`https`), and `urlsMatch` is false, the guard in `app/src/lib/stores/updates/update-remote-url.ts:42-44` passes and `gitStore.setRemoteURL('origin', 'https://attacker.example/whatever/repo.git')` is invoked.
4. `origin` is silently rewritten; all subsequent pushes/fetches by the victim go to `attacker.example`, and if that host is matched by an account's origin in `findGitHubTrampolineAccount`, that account's token is sent along with the request.

export async function updateRemoteUrl(
  gitStore: GitStore,
  gitHubRepository: GitHubRepository,
  apiRepo: IAPIRepository
): Promise<void> {
  // I'm not sure when these early exit conditions would be met. But when they are
  // we don't have enough information to continue so exit early!
  if (gitStore.defaultRemote === null) {
    return
  }

  const remoteUrl = gitStore.defaultRemote.url
  const updatedRemoteUrl = apiRepo.clone_url
  const urlsMatch = urlMatchesRemote(updatedRemoteUrl, gitStore.defaultRemote)

  // Verify that protocol hasn't changed. If it has we don't want
  // to alter the protocol in case they are relying on a specific one.
  // If protocol is null that implies the url is a ssh url
  // of the format git@github.com:octocat/Hello-World.git, which
  // can't be parsed by URL.parse. In this case we assume the user
  // manually configured their remote to use this format and we don't
  // want to change what they've done just to be safe
  const parsedRemoteUrl = URL.parse(remoteUrl)
  const parsedUpdatedRemoteUrl = URL.parse(updatedRemoteUrl)
  const protocolsMatch =
    parsedRemoteUrl.protocol !== null &&
    parsedUpdatedRemoteUrl.protocol !== null &&
    parsedRemoteUrl.protocol === parsedUpdatedRemoteUrl.protocol

  // Check if the default remote url has been manually changed from the
  // clone url retrieved from the GitHub API previously
  const remoteUrlUnchanged =
    gitStore.defaultRemote &&
    urlMatchesRemote(gitHubRepository.cloneURL, gitStore.defaultRemote)

  if (protocolsMatch && remoteUrlUnchanged && !urlsMatch) {
    await gitStore.setRemoteURL(gitStore.defaultRemote.name, updatedRemoteUrl)
  }
}

export function urlMatchesRemote(url: string | null, remote: IRemote): boolean {
  if (url == null) {
    return false
  }

  const cloneUrl = parseRemote(url)
  const remoteUrl = parseRemote(remote.url)

  if (remoteUrl == null || cloneUrl == null) {
    return false
  }

  if (!caseInsensitiveEquals(remoteUrl.hostname, cloneUrl.hostname)) {
    return false
  }

  if (remoteUrl.owner == null || cloneUrl.owner == null) {
    return false
  }

  if (remoteUrl.name == null || cloneUrl.name == null) {
    return false
  }

  return (
    caseInsensitiveEquals(remoteUrl.owner, cloneUrl.owner) &&
    caseInsensitiveEquals(remoteUrl.name, cloneUrl.name)
  )
}

export async function findGitHubTrampolineAccount(
  accountsStore: AccountsStore,
  remoteUrl: string
): Promise<Account | undefined> {
  const accounts = await accountsStore.getAll()
  const parsedUrl = new URL(remoteUrl)
  return accounts.find(
    a => new URL(getHTMLURL(a.endpoint)).origin === parsedUrl.origin
  )
}
