## Analog Found

### Title
Permissionless `harvest()` triggers protocol-owned WOM→mWOM swap at live pool price, enabling flashloan sandwich attacks - (File: `wombat/WombatStaking.sol`)

### Summary
`WombatStaking.harvest()` is callable by anyone and internally routes newly harvested WOM reward fees into `SmartWomConvert.smartConvert()`, which reads the current `womMWomPool` price on-chain and immediately executes a real swap of protocol-held WOM funds at that price with no attacker-supplied minimum-output check beyond a coarse aggregate assertion. This mirrors the reported `MochiTreasuryV0.veCRVlock()` sandwich pattern: a permissionless trigger that forces the protocol itself to trade against a manipulable AMM price using its own funds.

### Finding Description
`harvest(_lpToken)` has no privileged-caller restriction — it is `external`, gated only by `whenNotPaused` and `_onlyActivePool(_lpToken)` (a pool-validity check, not an access-control check): [1](#0-0) 

`harvest()` calls `_toMasterWomAndSendReward`, which computes the WOM rewards received from `MasterWombat` and forwards them to `_sendRewards`: [2](#0-1) 

Inside `_sendRewards`, when a fee is flagged `isMWOM` and the reward token is WOM, the contract calls `smartWomConverter.smartConvert(feeAmount, 0)` using WOM that is already sitting in the `WombatStaking` contract (protocol/staker funds, not funds supplied by the caller): [3](#0-2) 

`smartConvert` reads the *live* pool price via `currentRatio()` (a `getAmountOut` call against `womMWomPool`) and, if the price is below `buybackThreshold`, computes a swap size and executes an actual `swapExactTokensForTokens` against the router with `0` as the router-level minimum-output parameter: [4](#0-3) [5](#0-4) 

The only slippage check afterward is `convertAmount + amountRec < _minRec`, where `_minRec` is set to `_amountIn` inside `smartConvert` (i.e., it only guards against getting fewer mWOM units than WOM units deposited overall) — it does not protect the swap leg itself from being executed at an attacker-manipulated price: [6](#0-5) [7](#0-6) 

### Impact Explanation
An attacker can flashloan-manipulate the `womMWomPool` price immediately before calling the permissionless `harvest()` (or by waiting for/front-running any user's `harvest()`/deposit/withdraw call that triggers `_toMasterWomAndSendReward`), forcing the protocol's own WOM reward fees to be swapped into mWOM at an unfavorable, attacker-controlled price, then reversing the pool price in the same transaction — a classic sandwich extracting value directly from protocol-held funds. This directly reduces the value of rewards ultimately distributed to WOM stakers/rewarders, i.e. theft of protocol/user yield funds, matching the accepted impact class (theft of unclaimed yield / protocol insolvency vector).

### Likelihood Explanation
`harvest()` is unauthenticated and can be called by any wallet at any time the target pool is active, and the WOM→mWOM swap path is only gated by a price threshold check that itself reads from the same manipulable pool — an attacker fully controls when the swap condition triggers and at what price it executes, making this practically reachable from an ordinary wallet with a flashloan.

### Recommendation
Add slippage protection to the swap leg in `SmartWomConvert._convertFor`/`smartConvert` (e.g., require a caller/keeper-supplied minimum output for the actual router swap rather than `0`), and/or restrict when `harvest()`-triggered fee conversion executes the swap (e.g., use a TWAP-based price check instead of an instantaneous `getAmountOut`, or defer/batch conversions under access control) to prevent single-block price manipulation from being profitable.

### Proof of Concept
1. Attacker flashloans WOM/mWOM and swaps in `womMWomPool` to push `currentRatio()` below `buybackThreshold` (9000/10000).
2. Attacker calls `WombatStaking.harvest(_lpToken)` (permissionless), which routes accumulated WOM fees through `_sendRewards` → `SmartWomConvert.smartConvert(feeAmount, 0)`.
3. `smartConvert` sees the depressed ratio, computes `maxSwapAmount()` from pool cash/liability, and swaps protocol WOM into mWOM via the router at the manipulated (unfavorable) price with `0` minimum output on the router call.
4. Attacker reverses their initial swap in the same transaction to restore the pool price and repay the flashloan, pocketing the difference extracted from the protocol's WOM fee balance.

    function smartConvert(uint256 _amountIn, uint256 _mode) external returns (uint256 obtainedmWomAmount) {
        if (_amountIn == 0) revert MustNoBeZero();

        uint256 convertRatio = DENOMINATOR;
        uint256 mWomToWom = currentRatio();

        if (mWomToWom < buybackThreshold) {
            uint256 maxSwap = maxSwapAmount();
            uint256 amountToSwap = _amountIn > maxSwap ? maxSwap : _amountIn;
            uint256 convertAmount = _amountIn - amountToSwap;
            convertRatio = convertAmount * DENOMINATOR / _amountIn;
        }

        return _convertFor(_amountIn, convertRatio, _amountIn, msg.sender, _mode);
    }
