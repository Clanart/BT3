### Title
Unauthenticated `InternalSendTx` reachable with `client_verification=false`, allowing attacker to inject arbitrary transactions into the aggregator's fee-bumping wallet queue - (File: `core/src/rpc/aggregator.rs`, `core/src/rpc/interceptors.rs`, `core/src/servers.rs`)

### Summary
`AggregatorServer::internal_send_tx` is gated only by the `only_aggregator_and_self` interceptor's `is_internal` check, but that interceptor is only installed when `config.client_verification == true`; otherwise `create_grpc_server` installs `Interceptors::Noop`, which performs no authentication at all. Any unauthenticated caller reaching the aggregator's public gRPC port can then call `InternalSendTx` and get an arbitrary attacker-supplied transaction inserted into the aggregator's `tx_sender` queue, which for `FeePayingType::RBF` will fund/sign the tx using the tx-sender's own Bitcoin Core wallet via `fund_raw_transaction`/`psbtbumpfee`.

### Finding Description
The intended binding is: `internal_send_tx reachability == is_internal(req) && leaf_cert == our_cert` (i.e., only the aggregator itself, authenticated via mTLS, should reach this RPC). This binding is enforced in `only_aggregator_and_self` in `core/src/rpc/interceptors.rs` [1](#0-0) , but that function is only wired in when `config.client_verification` is `true`; when it is `false`, `create_grpc_server` in `core/src/servers.rs` installs `Interceptors::Noop`, which returns `Ok(req)` unconditionally with no certificate check whatsoever [2](#0-1) .

With `Noop` active, `ClementineAggregatorServer::internal_send_tx` in `core/src/rpc/aggregator.rs` directly deserializes an attacker-supplied `raw_tx` and calls `self.tx_sender.insert_try_to_send(...)` with the requested `fee_type` (e.g. `RBF`), with no signer/authorization checks in the handler body itself [3](#0-2) . The generated gRPC dispatch confirms the call reaches `internal_send_tx` directly from the wire with no additional gating [4](#0-3) .

Once queued with `FeePayingType::RBF`, `TxSender::send_rbf_tx` will fund the transaction using the node wallet's `fund_raw_transaction`/`psbtbumpfee` RPCs if the tx is not yet fully funded, meaning wallet-controlled UTXOs (the same wallet funding CPFP/RBF for Challenge/Disprove/Reimburse) can be selected as inputs into an attacker-chosen transaction [5](#0-4) .

Existing guards fail here because `only_aggregator_and_self`/`is_internal` are the only mechanism restricting `Internal*`-prefixed RPCs, and they are completely absent under the `Noop` interceptor path, which is a real, reachable, documented deployment configuration (`client_verification=false`).

### Impact Explanation
An attacker with no credentials can cause the aggregator's tx-sender wallet to co-mingle its UTXO set with an attacker-chosen transaction. If the wallet's coin selection during RBF funding consumes or conflicts with UTXOs otherwise available/reserved for fee-bumping a deadline-bound protocol transaction (Challenge, Disprove, ChallengeNACK, Reimburse), that legitimate transaction can fail to confirm in time, matching the Critical impact category "an honest operator's collateral burned via Challenge/Disprove/ChallengeNACK." At minimum, this is a High-severity "unauthenticated state-changing/broadcasting call," since any anonymous caller can force the aggregator to broadcast transactions of their choosing. The attack is repeatable across every polling interval of the tx-sender and does not require a specific deposit or operator - it degrades the shared fee-bumping wallet used across the whole protocol.

### Likelihood Explanation
The precondition is that the aggregator is deployed with `client_verification=false` (a real config flag consumed in `create_grpc_server`/`create_aggregator_grpc_server`) [6](#0-5) ; under that configuration no certificate, key, or council/operator/verifier privilege is required - only network reachability to the aggregator's public gRPC port. The attacker only needs enough BTC to shape a conflicting transaction's fee and inputs (which they are documented as capable of: broadcasting Bitcoin transactions, choosing outpoints/signatures/scripts). Feasibility is high and the call is trivially repeatable.

### Recommendation
Do not rely solely on the `Interceptors` TLS-cert gate for authorization of `Internal*` RPCs. Enforce the "internal-only" restriction unconditionally inside the RPC handler itself (e.g., require a valid internal auth token/mTLS peer identity check inside `internal_send_tx`, independent of the `client_verification` toggle), or refuse to start the aggregator gRPC service with `client_verification=false` unless it is bound to a loopback/Unix-socket-only listener. At minimum, treat `client_verification=false` combined with a TCP-exposed aggregator server as a hard misconfiguration and reject `Internal*` calls in that mode regardless of interceptor result.

pub async fn create_aggregator_grpc_server(
    config: BridgeConfig,
) -> Result<(std::net::SocketAddr, oneshot::Sender<()>), BridgeError> {
    let addr: std::net::SocketAddr = format!("{}:{}", config.host, config.port)
        .parse()
        .wrap_err("Failed to parse address")?;
    let aggregator_server = AggregatorServer::new(config.clone()).await?;
    aggregator_server.start_background_tasks().await?;

    let svc = ClementineAggregatorServer::new(aggregator_server)
        .max_encoding_message_size(config.grpc.max_message_size)
        .max_decoding_message_size(config.grpc.max_message_size);

    if config.client_verification {
        tracing::warn!("Client verification is enabled on aggregator gRPC server",);
    }

    let (server_addr, shutdown_tx) =
        create_grpc_server(addr.into(), svc, "Aggregator", &config).await?;

    match server_addr {
        ServerAddr::Tcp(socket_addr) => Ok((socket_addr, shutdown_tx)),
        _ => Err(BridgeError::ConfigError("Expected TCP address".into())),
    }
}

            Err(Status::unimplemented("Automation is not enabled"))

            let fee_type = send_tx_req.fee_type();

                .try_into()?;
            tracing::warn!(
                "Internal send tx rpc called with feetype: {:?}, tx hex: {}",
                fee_type,
                bitcoin::consensus::encode::serialize_hex(&signed_tx)
            );

            let mut dbtx = self.db.begin_transaction().await?;
            self.tx_sender
                .insert_try_to_send(
                    &mut dbtx,
                    None,
                    &signed_tx,
                    fee_type.try_into()?,
                    None,
                    &[],
                    &[],
                    &[],
                    &[],
                )
                .await
                .map_to_status()?;
            dbtx.commit()
                .await
                .map_err(|e| Status::internal(format!("Failed to commit db transaction: {e}")))?;
            Ok(Response::new(Empty {}))
        }
