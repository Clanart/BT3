### Title
Secret key shares leak via derived `Debug` on `ThresholdKeys`/`ThresholdCore` when constant interpolation is in use - (File: crypto/dkg/src/lib.rs)

### Summary
The NATS bug class is "secret material supplied at setup is emitted, unredacted, on an output surface any observer can read" (`argv` → `/debug/vars`). Serai's analog lives in `crypto/dkg`: `ThresholdKeys` derives `Debug`, and the manual `fmt::Debug` for its inner `ThresholdCore` deliberately redacts `secret_share` via `finish_non_exhaustive`, but still prints `interpolation` — which for `Interpolation::Constant(Vec<F>)` contains every participant's secret share scalar. Any call site that formats these keys (error paths, logs, `format!("{e:?}")` wrappers such as the borsh deserializer at `crypto/dkg/src/lib.rs:206`) discloses the full secret sharing.

### Finding Description
`Interpolation` derives `Debug` and its `Constant` variant is a `Vec<F>` of per-participant constant coefficients, where `interpolation_factor` returns `c[i - 1]` verbatim — i.e., the vector literally is the list of secret shares (`crypto/dkg/src/lib.rs:211-249`). `ThresholdCore`'s `fmt::Debug` prints `self.interpolation` while only omitting `secret_share` (`crypto/dkg/src/lib.rs:266-276`). `ThresholdKeys` then derives `Debug` (`crypto/dkg/src/lib.rs:291`), forwarding to `ThresholdCore` through `Arc<Zeroizing<...>>` (`Zeroizing`'s `Debug` delegates to the inner value). The redaction intent is clear — `SecretShare`, `SecretShareMachine`, `KeyMachine`, and `Encryption` in `crypto/dkg/pedpop` all carefully omit secret fields — so including `interpolation` here is an inconsistency, not a design choice.

### Impact Explanation
Because `Interpolation::Constant` requires `t == n` (`ThresholdKeys::new` rejects it otherwise, `crypto/dkg/src/lib.rs:367-372`), the leaked `Vec<F>` is the complete set of shares for a full-threshold key. Anyone who obtains the debug representation — a log line, an error message embedding `{keys:?}` or the `DkgError` it produces — can recover the entire group private key by summing the coefficients, then forge arbitrary FROST/Bitcoin signatures or steal all funds under that key. This is key share recovery reachable through an unredacted output channel, the direct analog of credentials reaching `/debug/vars` readers.

### Likelihood Explanation
Medium. `Constant` interpolation is only used for `t == n` configurations (e.g., dealer-produced/recovered keys), so exposure requires both that configuration and a formatting call site. But `Debug` impls exist precisely to be printed in logs and errors, the type is `pub` and returned across the entire `crypto/dkg` API surface, and downstream code already interpolates errors via `format!("{e:?}")`. No malicious participant, collusion, or leaked key is needed — only read access to the same observability surface, exactly as in the NATS report.

### Recommendation
Do not print the `interpolation` field in `ThresholdCore::fmt::Debug` — replace `.field("interpolation", &self.interpolation)` with a variant tag only (e.g., `.field("interpolation", &matches!(self.interpolation, Interpolation::Constant(_)))`), or drop it entirely. Alternatively implement a manual `Debug` for `Interpolation` that omits the `Constant` payload, mirroring `SecretShare`'s redacting `Debug` in `crypto/dkg/pedpop/src/lib.rs:242-246`. Also consider a manual `Debug` for `ThresholdKeys` that omits `scalar`/`offset` (ephemeral tweaks applied to the share), matching the redaction discipline used throughout `pedpop`.

### Proof of Concept
```rust
// Any ThresholdKeys built with constant interpolation (requires t == n):
let keys = ThresholdKeys::<Ristretto>::new(
  ThresholdParams::new(n, n, Participant(1)).unwrap(),
  Interpolation::Constant(shares.clone()), // shares = Vec<F>, one scalar per participant
  our_share,
  verification_shares,
).unwrap();

// The derived Debug on ThresholdKeys -> ThresholdCore prints `interpolation`,
// which for the Constant variant is the raw share vector:
let leak = format!("{keys:?}");
// `leak` now contains every participant's secret share scalar in plaintext.
// Summing/reconstructing yields the group private key:
//   secret = sum_i shares[i]  (since interpolation_factor(i) = shares[i-1])
```
By contrast, `original_secret_share()` and `SecretShare`'s `Debug` are deliberately redacted (`crypto/dkg/src/lib.rs:450`, `crypto/dkg/pedpop/src/lib.rs:242`), confirming `interpolation`'s inclusion is an oversight.
