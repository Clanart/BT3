The report describes CVE-2026-40612 in `jq`: `jv_contains` recurses into nested JSON structures with no depth limit, and because the value was built programmatically with `reduce` (bypassing the parser's depth cap of 10000), the C stack overflows. The failed invariant is: *a value that was constructed to be logically arbitrarily deep, but which never went through the bounded recursive-descent parser, is walked by a separate recursive function that has no depth check of its own.*

I looked for the same pattern in this checkout — a place where protobuf's own recursion-depth check (the ~100-level limit enforced by `CodedInputStream`/`ParseContext`/`ArrayDecoders` during binary decode) can be bypassed because a nested structure is *not* decoded through the normal message-recursion path, and a *different* internal recursive function then walks it with no depth counter of its own. [1](#0-0)  confirms binary parsing tracks and caps recursion depth (default 100) specifically to prevent stack overflow from malicious/corrupt messages, and [2](#0-1)  shows this depth counter is decremented for every embedded message/group during `_InternalParse`. However, `google.protobuf.Any`'s `value` field is just an opaque `bytes` field at the wire-parsing level, so an attacker can nest `Any` payloads inside `Any` payloads (each nested `Any` serialized into the outer `Any`'s `value` bytes) without ever incrementing that recursion counter — the outer parse just copies bytes. [3](#0-2)  demonstrates this is a supported, expected usage pattern (`Any` packed inside `Any`).

`MessageDifferencer::Compare`, when it encounters an `Any`-typed message, unpacks both sides and *recursively calls itself* on the unpacked payload: [4](#0-3)  — `UnpackAny` then does a fresh `ParsePartialFromString` on the inner bytes: [5](#0-4) . Each `Compare(m1, m2, ...)` → `UnpackAny` → `Compare(...)` cycle is a native C++ stack frame, and there is no depth counter anywhere in `message_differencer.cc`/`.h` bounding how many times this Any-unwrap-and-recurse cycle can occur — confirmed by the grep across `src/google/protobuf/util/*.cc` finding no `recursion_budget`/`max_depth`/`depth_` tracking in that file. Since each level's Any-nesting is invisible to the binary/JSON parser's depth limit (it's just bytes-in-bytes), an attacker can encode a chain of thousands of nested `Any(value=Any(value=Any(...)))` — each parses trivially within the standard bytes-field depth of 1-2, while the *logical* Any-chain depth is unbounded by the wire recursion limit.

### Title
Unbounded native recursion in `MessageDifferencer::Compare` via chained `google.protobuf.Any` unwrapping - (File: `src/google/protobuf/util/message_differencer.cc`)

### Summary
`MessageDifferencer::Compare` automatically unpacks `google.protobuf.Any` payloads and recurses into them (`Compare(*data1, *data2, unpacked_any + 1, parent_fields)`), calling `UnpackAny` -> `ParsePartialFromString` at each level. This Any-unwrap loop has no depth limit of its own and is decoupled from the wire-format recursion limit that bounds normal embedded-message nesting, because each `Any.value` is an opaque `bytes` field to the outer parser.

### Finding Description
Binary/JSON parsing in protobuf enforces a recursion depth limit (default 100) for actual embedded message/group nesting [6](#0-5) . But `Any.value` is just a `bytes` field, so a chain of `Any` messages, each wrapping the serialized bytes of the next `Any`, parses as a shallow structure (constant depth per level) regardless of how many `Any` levels are chained — exactly analogous to jq's `reduce`-built structure bypassing the JSON parser's depth cap. When application code calls `MessageDifferencer::Equals`/`Compare` on such a message (a supported public API, e.g. for diffing/deduplicating protobuf messages received from clients), `Compare` detects `google.protobuf.Any` by full name and unconditionally recurses: [4](#0-3) . `UnpackAny` parses the next level's bytes and returns a new `Message`, which is compared by calling `Compare` again — with no counter or limit checked anywhere in this call chain [7](#0-6) .

### Impact Explanation
A crafted but individually-small/bounded protobuf message containing a sufficiently long chain of nested `Any` wrappers, when compared via `MessageDifferencer` (a common utility used in testing frameworks, caching/dedup layers, and application logic that treats two attacker-influenced messages), drives unbounded native C++ stack recursion, exhausting the stack and crashing the process (denial of service), matching the VA:H/others-none impact profile of the jq analog.

### Likelihood Explanation
Exploitability requires only that a consuming application call `MessageDifferencer::Equals`/`Compare`/`Compare` on an attacker-influenced message containing chained `Any` fields — a normal, supported usage of a public protobuf utility, with no privileged access, hostile schema, or malicious peer needed. The bypass of the standard recursion-limit protection is intrinsic to how `Any.value` is represented as opaque bytes rather than a typed submessage at parse time.

### Recommendation
Add an explicit, tracked recursion/Any-unwrap depth limit inside `MessageDifferencer::Compare`'s Any-expansion path (e.g., cap `unpacked_any`, which is already threaded through the calls, and treat exceeding it as "cannot expand, compare as opaque bytes" rather than recursing further), independent of and in addition to the standard message wire-recursion limit.

### Proof of Concept
Construct `N` (e.g. 100,000) nested `google.protobuf.Any` messages: `any_0.value = serialize(any_1)`, `any_1.value = serialize(any_2)`, ..., where each `any_i` has `type_url` set to `"type.googleapis.com/google.protobuf.Any"` except the innermost, which wraps a trivial concrete message. Each individual `ParsePartialFromString` call only sees a depth-1 `Any` message (the wire-level recursion limit is never touched). Call `google::protobuf::util::MessageDifferencer::Equals(any_0, any_0_copy)` (or any comparator API) on the two resulting top-level `Any` messages — the differencer recurses through `Compare` -> `UnpackAny` -> `Compare` `N` times with no bound, and a sufficiently large `N` exhausts the C++ call stack.

bool MessageDifferencer::UnpackAnyField::UnpackAny(
    const Message& any, std::unique_ptr<Message>* data) {
  const Reflection* reflection = any.GetReflection();
  const FieldDescriptor* type_url_field;
  const FieldDescriptor* value_field;
  if (!internal::GetAnyFieldDescriptors(any, &type_url_field, &value_field)) {
    return false;
  }
  const std::string& type_url = reflection->GetString(any, type_url_field);
  std::string full_type_name;
  if (!internal::ParseAnyTypeUrl(type_url, &full_type_name)) {
    return false;
  }

  const Descriptor* desc =
      any.GetDescriptor()->file()->pool()->FindMessageTypeByName(
          full_type_name);
  if (desc == nullptr) {
    return false;
  }

  if (dynamic_message_factory_ == nullptr) {
    dynamic_message_factory_ = std::make_unique<DynamicMessageFactory>();
  }
  data->reset(dynamic_message_factory_->GetPrototype(desc)->New());
  std::string serialized_value = reflection->GetString(any, value_field);
  if (!(*data)->ParsePartialFromString(serialized_value)) {
    ABSL_DLOG(ERROR) << "Failed to parse value for " << full_type_name;
    return false;
  }
  return true;
}
