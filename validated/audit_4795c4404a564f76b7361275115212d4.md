### Title
Forged `ReceivedOutput` records allow unspendable deposits to be reported and signed - (File: `networks/bitcoin/src/wallet/mod.rs`)

### Summary
`ReceivedOutput::read` accepts a caller-supplied offset, `TxOut`, and `OutPoint` without proving that the referenced UTXO exists, has the claimed value, or actually pays to the claimed script. [1](#0-0)  An unprivileged peer can therefore serialize an output with a victim-controlled script but a fake or mismatched outpoint, causing it to be accepted as spendable input. [1](#0-0) 

### Finding Description
The scanner establishes ownership by matching a transaction output’s `script_pubkey` to a registered script and deriving the real outpoint from the scanned transaction. [2](#0-1)  The deserialization path bypasses that scan entirely and directly trusts all three fields needed to claim ownership: the scalar offset, the advertised prevout, and the outpoint. [3](#0-2) 

`SignableTransaction::new` then uses the claimed `outpoint` as a transaction input and the claimed `TxOut` as the prevout whose value and script are committed to the Taproot sighash. [4](#0-3) [5](#0-4)  `SignableTransaction::multisig` validates only that the supplied prevout script equals `p2tr_script_buf(group_key + offset * G)`, not that the referenced blockchain output contains that script or amount. [6](#0-5) 

Consequently, bytes such as `Scalar::ZERO || TxOut { value: large_amount, script_pubkey: victim_script } || fake_outpoint` deserialize successfully and pass Serai’s ownership check while referencing no spendable victim UTXO. [3](#0-2) [6](#0-5) 

### Impact Explanation
An application that accepts serialized `ReceivedOutput` values from an untrusted source can credit an attacker for funds which do not exist or are not spendable by the threshold key. [3](#0-2)  The signer can be driven through the full signing flow because the forged prevout script matches the derived key, while the resulting transaction is rejected by Bitcoin consensus or cannot authorize the real outpoint. [7](#0-6) 

The impact is false deposit reporting and potentially accepting worthless records in exchange for assets or services; it does not directly expose the threshold private key. [6](#0-5) 

### Likelihood Explanation
The attack requires only control over serialized input supplied to `ReceivedOutput::read`, since canonical scalar and Bitcoin consensus decoding impose no ownership or UTXO-authenticity condition. [3](#0-2)  It is preventable when the application only stores outputs produced locally by `Scanner::scan_transaction` over authenticated blockchain data, but the public deserialization API provides no such provenance enforcement. [2](#0-1) 

### Recommendation
Do not expose `ReceivedOutput::read` as an authority-producing deserialization API for untrusted data. [1](#0-0)  Require reconstructed outputs to be produced by `Scanner` from an authenticated block or transaction, or extend the parsing API to take the expected base key and validate `p2tr_script_buf(key + offset * G) == output.script_pubkey`. [8](#0-7) [6](#0-5)  Separately verify the outpoint against a trusted UTXO source and require the actual `TxOut` to equal the claimed prevout before treating the record as a received balance. [7](#0-6) 

### Proof of Concept
The following sequence exercises the untrusted-input path and shows that Serai validates the forged prevout script without validating the referenced UTXO. [3](#0-2) [6](#0-5) 

```rust
// networks/bitcoin/src/wallet/mod.rs
// P is the victim's spendable group key and victim_script is its P2TR output.
let victim_script = p2tr_script_buf(victim_group_key).unwrap();

// Attacker-controlled serialized ReceivedOutput.
let forged = ReceivedOutput {
    offset: Scalar::ZERO,
    output: TxOut {
        value: Amount::from_sat(1_000_000),
        script_pubkey: victim_script,
    },
    // Nonexistent, or an outpoint whose real TxOut has a different script/value.
    outpoint: fake_outpoint,
};

// Accepted by ReceivedOutput::read when supplied as serialized bytes.
let parsed = ReceivedOutput::read(&mut forged.serialize().as_slice()).unwrap();

// networks/bitcoin/src/wallet/send.rs
// The forged value is used for funding/fee calculations.
let signable =
  SignableTransaction::new(vec![parsed], &payments, None, None, fee_rate).unwrap();

// This succeeds because only the fake prevout's script is compared with
// p2tr_script_buf(victim_group_key + ZERO * G).
let machine = signable.multisig(&victim_threshold_keys).unwrap();
```

Signing that machine produces a transaction committing to the attacker-supplied prevout value and script, but Bitcoin will not accept it as a spend of the fake or mismatched outpoint. [7](#0-6) [9](#0-8)
