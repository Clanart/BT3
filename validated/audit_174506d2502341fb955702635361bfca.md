### Title
Uncontrolled Recursion in Nested `AccountKeyRoleBased` RLP Decoding Allows Remote DoS via Crafted Transaction - (File: `blockchain/types/accountkey/account_key_role_based.go`)

### Summary
The Kaia analog of the `golang.org/x/net/http/httpguts` recursion bug (GHSA-h86h-8ppg-mxmh / CVE-2021-31525) is present in the `AccountKey` RLP decoder chain. An unprivileged transaction sender can craft an `AccountUpdate`/`FeeDelegatedAccountUpdate`-type transaction whose `AccountKey` payload is a deeply, self-referentially nested `AccountKeyRoleBased` structure. Decoding that payload recurses through `AccountKeyRoleBased.DecodeRLP` → `AccountKeySerializer.DecodeRLP` → `NewAccountKey` → `AccountKeyRoleBased.DecodeRLP` with no depth limit, before any of the "no nested RoleBased" validation logic ever runs. This is reachable purely by submitting raw transaction bytes (e.g., via `eth_sendRawTransaction`/`klay_sendRawTransaction` or gossip), causing unbounded call-stack growth and a process panic/crash — the same bug class as the httpguts advisory (attacker-controlled input drives uncontrolled recursion leading to a DoS panic).

### Finding Description
`AccountKeyRoleBased.DecodeRLP` decodes a list of opaque byte strings and, for every element, independently RLP-decodes an `AccountKeySerializer`: [1](#0-0) 

`AccountKeySerializer.DecodeRLP` reads the key type and then dispatches to `NewAccountKey`, decoding the inner key generically: [2](#0-1) 

`NewAccountKey` allows the inner key type to again be `AccountKeyTypeRoleBased`: [3](#0-2) 

so a `RoleBased` key can contain another `RoleBased` key as one of its role entries, and that one can contain another, and so on — the decode path is fully recursive with no depth counter, no maximum-nesting check, and no distinct byte-string overhead requirement that would meaningfully bound recursion depth relative to input size.

The only defense against "nested RoleBased" keys is a *post-decode* semantic check, `CheckInstallable`, which explicitly rejects composite (nested) keys — but this check runs only after the recursive `DecodeRLP` has already fully unwound: [4](#0-3) 

This is corroborated by the existing test `TestAccountUpdateRoleBasedKeyNested`, which shows nested `RoleBased` keys are only rejected at the tx-pool/execution validation stage (`kerrors.ErrNestedCompositeType`), i.e., strictly after decoding has already succeeded: [5](#0-4) 

The transaction-level decode path that triggers this recursion is fully attacker-reachable: `Transaction.DecodeRLP`/`UnmarshalBinary` decode arbitrary submitted bytes into a `TxInternalDataSerializer`, which then dispatches into type-specific `DecodeRLP` implementations such as `TxInternalDataFeeDelegatedAccountUpdate.DecodeRLP`, which in turn decodes the embedded `AccountKey` via the recursive chain above — all before any size/gas/pool validation occurs: [6](#0-5) [7](#0-6) 

Because nesting only costs a few bytes of RLP list/byte-string overhead per level (a `keyType` byte plus small list headers), an attacker can encode very deep nesting relative to payload size, and the transaction size cap (`blockchain.MaxTxDataSize`) is enforced by the tx pool only *after* the transaction (and therefore its `AccountKey`) has already been fully RLP-decoded — the decode-time recursion happens unconditionally regardless of whether the resulting tx is later rejected for size or `ErrNestedCompositeType`.

### Impact Explanation
Deeply nested `AccountKeyRoleBased` payloads drive unbounded recursive calls through `DecodeRLP`/`NewAccountKey`/`AccountKeySerializer.DecodeRLP`. In Go, exceeding the max goroutine stack triggers an unrecoverable `fatal error: stack overflow`, which cannot be caught by `recover()` and crashes the entire node process. Any Kaia node that decodes such a transaction — a full node processing gossiped transactions, a node's public RPC endpoint handling `sendRawTransaction`, or a node validating a block containing such a transaction — can be crashed. This is a network-wide denial-of-service vector: a single malicious transaction, submitted once, can be relayed to and crash every honest node that decodes it, which is a Medium/High severity availability impact consistent with the referenced advisory's CVSS profile (`AC:H/... /A:H`).

### Likelihood Explanation
The path is reachable by any unprivileged actor who can submit a transaction: no special privileges, prior account setup beyond a funded sender is not even strictly required to trigger the decode (decode happens before nonce/balance/signature checks in many entry points, and even where a valid sender/signature is required, an attacker fully controls that). Constructing the crafted nested RLP payload requires no cryptographic material for the nested keys themselves (they only need to look structurally like `AccountKeyRoleBased` to be recursively decoded) and no complex preconditions.

### Recommendation
Enforce an explicit recursion/nesting depth limit while decoding `AccountKeyRoleBased` (and generally in `AccountKeySerializer.DecodeRLP`), rejecting any encoding whose nesting exceeds a small constant (e.g., 1, matching the existing "no nested composite type" invariant) *during decode*, not only during later `CheckInstallable`/`CheckUpdatable` validation. Alternatively, track and bound decode depth via an explicit counter/context threaded through `rlp.Stream`, or reject `AccountKeyTypeRoleBased` as an invalid child type at the point where a role-key element is decoded within `AccountKeyRoleBased.DecodeRLP`, before recursing further.

### Proof of Concept
1. Construct `k0 = RLP([keyTypeRoleBased, RLP([k])])` recursively, where the base case is any leaf `AccountKeyLegacy`/`AccountKeyPublic` serializer, and each level wraps the previous one as the sole role entry of a new `AccountKeyRoleBased`, e.g.:
   - `leaf = rlp.EncodeToBytes(NewAccountKeySerializerWithAccountKey(NewAccountKeyLegacy()))`
   - for `i := 0; i < N; i++ { role = NewAccountKeyRoleBasedWithValues([]AccountKey{ /* wrap previous serialized bytes */ }) }`
   - Repeat until `N` is large enough (tens of thousands of levels) while total encoded size stays within the RPC's accepted body size.
2. Wrap the resulting `AccountKeySerializer` bytes as the `Key` field of a `TxInternalDataFeeDelegatedAccountUpdate` (or `AccountUpdate`) transaction, RLP-encode the full transaction.
3. Submit the raw transaction bytes to a node's public RPC (`eth_sendRawTransaction`/`klay_sendRawTransaction`) or via p2p transaction gossip.
4. Observe that `Transaction.DecodeRLP` → `TxInternalDataFeeDelegatedAccountUpdate.DecodeRLP` → `AccountKeySerializer.DecodeRLP` → `AccountKeyRoleBased.DecodeRLP` recurse `N` times before any size or `ErrNestedCompositeType` check is reached, and with sufficiently large `N` the target node crashes with `fatal error: stack overflow`.

func (a *AccountKeyRoleBased) DecodeRLP(s *rlp.Stream) error {
	enc := [][]byte{}
	if err := s.Decode(&enc); err != nil {
		return err
	}

	keys := make([]AccountKey, len(enc))
	for i, b := range enc {
		serializer := NewAccountKeySerializer()
		if err := rlp.DecodeBytes(b, &serializer); err != nil {
			return err
		}
		keys[i] = serializer.key
	}

	*a = (AccountKeyRoleBased)(keys)

	return nil
}

func (a *AccountKeyRoleBased) CheckInstallable(currentBlockNumber uint64) error {
	// A zero-role key is not allowed.
	if len(*a) == 0 {
		return kerrors.ErrZeroLength
	}
	// Do not allow undefined roles.
	if len(*a) > (int)(RoleLast) {
		return kerrors.ErrLengthTooLong
	}
	for i := 0; i < len(*a); i++ {
		// A composite key is not allowed.
		if (*a)[i].IsCompositeType() {
			return kerrors.ErrNestedCompositeType
		}
		// If any key in the role cannot be initialized, return an error.
		if err := (*a)[i].CheckInstallable(currentBlockNumber); err != nil {
			return err
		}
	}
	return nil
}

// DecodeRLP implements rlp.Decoder
func (tx *Transaction) DecodeRLP(s *rlp.Stream) error {
	serializer := newTxInternalDataSerializer()
	if err := s.Decode(serializer); err != nil {
		return err
	}

	if !SanityCheckSignatures(serializer.tx.RawSignatureValues(), serializer.tx.Type()) {
		return ErrInvalidSig
	}

	size := calculateTxSize(serializer.tx)
	tx.setDecoded(serializer.tx, int(size))

	return nil
}

// UnmarshalBinary decodes the canonical encoding of transactions.
// It supports legacy RLP transactions and EIP2718 typed transactions.
func (tx *Transaction) UnmarshalBinary(b []byte) error {
	newTx := &Transaction{}
	if err := rlp.DecodeBytes(b, newTx); err != nil {
		return err
	}

	tx.setDecoded(newTx.data, len(b))
	return nil
}
