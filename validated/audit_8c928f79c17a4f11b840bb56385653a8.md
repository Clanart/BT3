### Title
`ReceivedOutput::read` accepts arbitrary `TxOut`/`OutPoint`/offset bytes without binding them to the scanner-registered Taproot script, letting untrusted bytes construct "received" outputs that are not spendable by the Serai key - (File: networks/bitcoin/src/wallet/mod.rs)

### Summary
The XQUIC issue is improper validation of a frame/field in a context where it is not permitted (STREAM frames accepted inside Initial/Handshake packets), enabling protocol manipulation. The Serai analog lives in `bitcoin_serai::wallet::ReceivedOutput`: the `Scanner` only ever produces outputs whose `script_pubkey` equals `p2tr(key + offset * G)` for a registered offset, but `ReceivedOutput::read` — an explicitly in-scope untrusted-bytes entry point — reconstructs the same type from raw bytes with zero semantic validation. It accepts any `TxOut` (any `script_pubkey`, any `value`), any `OutPoint`, and any scalar `offset`, decoupled entirely from the invariants `Scanner::scan_transaction` enforces.

### Finding Description
`Scanner::new`/`register_offset`/`scan_transaction` guarantee that a `ReceivedOutput` corresponds to a P2TR script solvable by `key + offset * G`:
`networks/bitcoin/src/wallet/mod.rs:162-214`.

`ReceivedOutput::read` performs no such check: [1](#0-0) 

It decodes:
- `offset`: any canonical scalar via `Secp256k1::read_F`,
- `output`: any consensus-decodable `TxOut` — no `is_p2tr()` check, no `value <= MAX_MONEY` check, and critically no check that `output.script_pubkey == p2tr_script_buf(key + GENERATOR * offset)` for any plausible key,
- `outpoint`: any `OutPoint`, including non-existent txids.

The type's own contract (doc: "A spendable output") is therefore violated at deserialization: the `offset` field only makes the output spendable when the script commits to `key + offset·G`, which `read` never verifies. Downstream code assumes the invariant — e.g., `Output::key()` in `processor/src/networks/bitcoin.rs:112-122` asserts `script.is_p2tr()` and derives the spend key as `x_only_script_key − offset·G`, and `SignableTransaction::new` in `networks/bitcoin/src/wallet/send.rs` treats every `ReceivedOutput` as a spendable Taproot input contributing `value` to the balance/fee computation (`send.rs:139-141`).

### Impact Explanation
An unprivileged party who can feed bytes to `ReceivedOutput::read` (e.g., a forged/malicious serialized output crossing a trust boundary) obtains funds-reported-received that are not spendable:

- A `TxOut` paying to an attacker-controlled P2PKH/P2WPKH/foreign script is accepted as a received output; the wallet's balance accounting inflates by the attacker-chosen `value`, and any transaction built with it is unspendable/invalid on-chain.
- A P2TR output with a mismatched `offset` produces a "received" output whose derived spend key doesn't match the script — unspendable, yet counted.
- A non-P2TR `script_pubkey` reaches `Output::key()`, which `assert!`s `is_p2tr()` — a panic/DoS on deserialization-driven input.

This is a direct analog of CVE-2026-6328: a structure accepted by a parser in a context where its contents don't satisfy the protocol state machine's requirements, yielding protocol manipulation (corrupt balance accounting, stuck/invalid spend plans, or crashes).

### Likelihood Explanation
Reachability requires attacker-influenced bytes reaching `ReceivedOutput::read`. The type is a serialization boundary (`serialize`/`read` round-trip is exercised in tests at `networks/bitcoin/tests/wallet.rs:73-75`), and it is embedded inside `Output::read` (`processor/src/networks/bitcoin.rs:145-166`), which is used to move scanned outputs between components. Any path where serialized outputs are relayed, stored, or re-parsed from data an external party influenced exposes this. The crafted input is trivial to produce: `offset || consensus_encode(TxOut) || consensus_encode(OutPoint)` with arbitrary fields — no cryptography needed. Impact is bounded to balance corruption/DoS rather than theft of correctly-registered outputs, since a real spend still requires the threshold signature over a valid Taproot input — hence Medium, matching the source advisory's severity.

### Recommendation
In `ReceivedOutput::read` (`networks/bitcoin/src/wallet/mod.rs:122`), enforce the type's invariants on untrusted bytes:

1. Require `output.script_pubkey.is_p2tr()` (v1 key-path Taproot) before accepting.
2. Derive the x-only key from the decoded script, reconstruct `key_even` (as `Output::key()` does), and reject if the implied internal key `key_even − offset·G` is not well-formed — or better, require the caller to supply the expected base key and verify `script_pubkey == p2tr_script_buf(key + GENERATOR·offset)`.
3. Reject `output.value` greater than `Amount::MAX_MONEY` and dust-below-threshold values consistent with `SignableTransaction`'s policy.
4. Prefer returning `Err` over the downstream `assert!`/`expect`/`unwrap` panic paths in `Output::key()`.

### Proof of Concept
```rust
use bitcoin::{
  absolute::LockTime, consensus::Encodable, script::ScriptBuf, transaction::Version,
  Amount, OutPoint, Transaction, TxIn, TxOut, Txid,
};
use bitcoin_serai::wallet::ReceivedOutput;
use frost::curve::Secp256k1;
use ciphersuite::Ciphersuite;
use k256::Scalar;

fn main() {
  // Attacker-controlled bytes: a P2PKH script paying the *attacker*, claimed as
  // a Serai-received output with an arbitrary offset and outpoint.
  let attacker_script = ScriptBuf::new_p2pkh(&bitcoin::PubkeyHash::all_zeros());

  let fake = TxOut { value: Amount::from_sat(21_000_000), script_pubkey: attacker_script };
  let fake_outpoint = OutPoint { txid: Txid::all_zeros(), vout: 0 };

  let mut bytes = vec![];
  bytes.extend(Scalar::ZERO.to_bytes());                       // offset
  fake.consensus_encode(&mut bytes).unwrap();                  // arbitrary TxOut
  fake_outpoint.consensus_encode(&mut bytes).unwrap();         // arbitrary OutPoint

  // Accepted: no is_p2tr / offset-binding / value checks
  let output = ReceivedOutput::read(&mut bytes.as_slice()).unwrap();
  assert_eq!(output.value(), 21_000_000);       // balance credited
  // Not spendable: script_pubkey is not P2TR and never committed to key + offset*G.
  // Downstream Output::key() then panics on `assert!(script.is_p2tr())`.
}
```

  pub fn read<R: Read>(r: &mut R) -> io::Result<ReceivedOutput> {
    let offset = Secp256k1::read_F(r)?;
    let output;
    let outpoint;
    {
      let mut buf_r = BufReader::with_capacity(0, r);
      output =
        TxOut::consensus_decode(&mut buf_r).map_err(|_| io::Error::other("invalid TxOut"))?;
      outpoint =
        OutPoint::consensus_decode(&mut buf_r).map_err(|_| io::Error::other("invalid OutPoint"))?;
    }
    Ok(ReceivedOutput { offset, output, outpoint })
  }
