### Title
Attacker-substituted RBF payout tx with missing OP_RETURN causes `Verifier::is_kickoff_malicious` to falsely convict an honest operator, burning its collateral - ([File: core/src/verifier.rs])

### Summary
The user's payout signature uses `TapSighashType::SinglePlusAnyoneCanPay`, which commits only to input 0 and output 0 of the payout transaction. Because the honest operator's payout tx is broadcast as an RBF-signaling transaction, any unprivileged network observer can construct a fee-bumping replacement that reuses the exact signed input/output (so the user is still correctly paid) while dropping or corrupting the OP_RETURN operator-attribution output, causing `Verifier::update_finalized_payouts` to record `operator_xonly_pk = None` for that withdrawal. When the honest operator later sends its kickoff, `Verifier::is_kickoff_malicious` treats the missing OP_RETURN pubkey as automatically malicious, triggering a Challenge and, because the operator cannot produce valid asserts without the recorded operator pubkey, an eventual Disprove that burns the operator's collateral.

### Finding Description
Binding claimed: `is_kickoff_malicious(kickoff) == true` should equal `operator actually deviated from protocol (sent no/invalid payout)`. This binding is broken because the malicious verdict is derived purely from the DB-recorded `operator_xonly_pk_opt` for the confirmed payout tx [1](#0-0) , and that value is attacker-controllable.

Root cause and path:
1. The operator's `withdraw()` builds a `Payout` tx with input 0 = withdrawal UTXO (user-signed `SinglePlusAnyoneCanPay`), output 0 = user payout, and output 2 = OP_RETURN with the operator's x-only pubkey [2](#0-1) . It is broadcast via `fund_raw_transaction`/RBF, explicitly noted as RBF-enabled [3](#0-2) .
2. Because the sighash is `SinglePlusAnyoneCanPay`, only input 0 and output 0 are committed to; any other input/output (fee inputs, anchor, OP_RETURN) can be freely altered by anyone holding the broadcast tx, which is public in the mempool. The codebase's own RBF helper acknowledges this fragility by pinning the change output position specifically "so that SinglePlusAnyoneCanPay signatures stay valid" [4](#0-3) .
3. An attacker builds a competing, higher-fee transaction reusing the identical signed input 0 and output 0, but with a different or missing OP_RETURN, and gets it confirmed instead of/ahead of the honest operator's original broadcast (standard RBF replacement, requiring only a fee bump - no bridge stake).
4. `update_finalized_payouts` scans the confirmed spender of the withdrawal UTXO, and if the OP_RETURN is missing/unparsable, sets `operator_xonly_pk = None` in the `withdrawals` table [5](#0-4) .
5. When the honest operator later sends its kickoff for that same withdrawal, `Verifier::is_kickoff_malicious` looks up payout info by move txid, finds `operator_xonly_pk_opt = None`, and immediately returns `true` ("assuming malicious") [6](#0-5) .
6. `handle_kickoff` then queues a Challenge tx against the operator's kickoff [7](#0-6) .
7. Because the payout DB entry lacks the operator pubkey, the operator's own `send_asserts` path errors out (`payout_op_xonly_pk_opt.ok_or_eyre(...)`) [8](#0-7) , so the honest operator cannot complete the BitVM assert chain that would let it avoid Disprove, leading to collateral being burned via the Disprove path [9](#0-8) .

Existing guards do not catch this: `is_kickoff_malicious` only compares the OP_RETURN-derived pubkey and the committed payout blockhash [10](#0-9) ; it never cross-checks that the confirmed payout's txid/output actually matches what the honest operator itself broadcast, nor tolerates a `None` caused by third-party malleation of unsigned fields.

### Impact Explanation
The honest operator's round collateral (burn connector) is spent via Disprove despite the operator having correctly funded the user's withdrawal payout (output 0 is unchanged and still pays the user in full). This is a Critical impact per the "honest operator's collateral burned" category. The attack is repeatable per withdrawal/operator: any in-flight, unconfirmed operator payout is vulnerable, so it scales across all deposits/operators that use the standard `withdraw()` (non-optimistic) payout path.

### Likelihood Explanation
Preconditions: an operator has an unconfirmed RBF payout tx for a withdrawal. The attacker only needs to observe the mempool (public), and pay Bitcoin transaction fees to construct and get mined a higher-fee replacement reusing the signed input/output 0. No bridge stake, no privileged role, and no key compromise are required — only unprivileged mempool observation and fee payment, consistent with the described attacker capabilities. The RBF-enabled nature of the operator's own payout broadcast makes fee-based replacement straightforward under standard Bitcoin Core RBF policy.

### Recommendation
Do not treat a `None` operator pubkey (missing/unparsable OP_RETURN) as unconditional proof of malice. Instead, cross-validate against additional operator-committed data (e.g., require the kickoff-committed payout data to reference the exact payout txid rather than relying solely on OP_RETURN parsing), or bind the OP_RETURN output into the same sighash committed by the user (e.g., require `AllPlusAnyoneCanPay`/covering all outputs, or use SIGHASH_ALL for that input) so third parties cannot alter it without invalidating the user's signature. At minimum, allow honest operators to prove their payout was the first-seen/legitimately intended one and not automatically slash on ambiguous DB state caused by unrelated third-party transaction substitution.

### Proof of Concept
`cargo test` plan (end-to-end, regtest, no mainnet/live Citrea):
1. Set up deposit + withdrawal e2e harness (reuse `core/src/test/deposit_and_withdraw_e2e.rs` scaffolding) with one honest operator.
2. Trigger a withdrawal so the operator broadcasts its RBF-enabled `Payout` tx (input 0 = withdrawal UTXO, output 0 = user payout, OP_RETURN = operator xonly pk) but do not mine it yet.
3. As "attacker," fetch the mempool tx, construct a replacement transaction reusing input 0 and output 0 verbatim (preserving the valid `SinglePlusAnyoneCanPay` signature), add an attacker-funded fee input, and drop/corrupt the OP_RETURN output; broadcast with higher fee, then mine it so it confirms instead of the operator's original.
4. Assert `Database::get_payout_info_from_move_txid` returns `operator_xonly_pk_opt == None` for this withdrawal, confirming the substitution succeeded and the user still received the payout (output 0 unchanged).
5. Have the honest operator send its kickoff for this withdrawal/deposit as normal.
6. Assert that `Verifier::handle_kickoff` returns `is_malicious == true` and that a Challenge tx is queued/mined for the honest operator's kickoff (assert on `UtxoVout::Challenge` outpoint being spent).
7. Continue the flow to Disprove/DisproveTimeout and assert that the round's `CollateralInRound` (burn connector) UTXO is ultimately spent by Disprove despite the operator never deviating from protocol, proving the SLASHING TRUTH binding (`challengeable/disprovable ⇔ actual deviation`) is violated.

pub fn create_payout_txhandler(
    input_utxo: UTXO,
    output_txout: TxOut,
    operator_xonly_pk: XOnlyPublicKey,
    user_sig: taproot::Signature,
    _network: bitcoin::Network,
) -> Result<TxHandler<Signed>, BridgeError> {
    let txin = SpendableTxIn::new_partial(input_utxo.outpoint, input_utxo.txout);

    let output_txout = UnspentTxOut::from_partial(output_txout.clone());

    let op_return_txout = op_return_txout(PushBytesBuf::from(operator_xonly_pk.serialize()));

    let mut txhandler = TxHandlerBuilder::new(TransactionType::Payout)
        .with_version(NON_STANDARD_V3)
        .add_input(
            NormalSignatureKind::NotStored,
            txin,
            SpendPath::KeySpend,
            DEFAULT_SEQUENCE,
        )
        .add_output(output_txout)
        .add_output(UnspentTxOut::from_partial(anchor_output(
            NON_EPHEMERAL_ANCHOR_AMOUNT,
        )))
        .add_output(UnspentTxOut::from_partial(op_return_txout))
        .finalize();
    txhandler.set_p2tr_key_spend_witness(&user_sig, 0)?;
    txhandler.promote()
}

/// Creates a [`TxHandler`] for the `disprove_tx`.
///
/// This transaction is sent by N-of-N to penalize a malicious operator by burning their collateral (burn connector).
/// This is done either with the additional disprove script created by BitVM, in case the public inputs of the bridge proof the operator
/// sent are not correct/do not match previous data, or if the Groth16 verification of the proof is incorrect using BitVM disprove scripts.
///
/// # Inputs
/// 1. KickoffTx: Disprove utxo
/// 2. RoundTx: BurnConnector utxo
///
/// # Outputs
/// 1. Anchor output for CPFP
///
/// # Arguments
///
/// * `kickoff_txhandler` - The kickoff transaction handler the disprove belongs to.
/// * `round_txhandler` - The round transaction handler to the current round the kickoff belongs to.
///
/// # Returns
///
/// A [`TxHandler`] for the disprove transaction, or a [`BridgeError`] if construction fails.
pub fn create_disprove_txhandler(
    kickoff_txhandler: &TxHandler,
    round_txhandler: &TxHandler,
) -> Result<TxHandler, BridgeError> {
    Ok(TxHandlerBuilder::new(TransactionType::Disprove)
        .with_version(Version::TWO)
        .add_input(
            NormalSignatureKind::NoSignature,
            kickoff_txhandler.get_spendable_output(UtxoVout::Disprove)?,
            SpendPath::Unknown,
            DEFAULT_SEQUENCE,
        )
        .add_input(
            NormalSignatureKind::Disprove2,
            round_txhandler.get_spendable_output(UtxoVout::CollateralInRound)?,
            SpendPath::KeySpend,
            DEFAULT_SEQUENCE,
        )
        .add_output(UnspentTxOut::from_partial(
            builder::transaction::non_ephemeral_anchor_output(), // must be non-ephemeral, because tx is v2
        ))
        .finalize())
}
