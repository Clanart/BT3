## Title
Spoofed `WWW-Authenticate` header from a malicious/MITM git remote silently triggers an unauthorized "Sign in to GitHub Enterprise" account-binding flow - (File: `app/src/lib/trampoline/trampoline-credential-helper.ts`)

## Summary
This is the closest Desktop analog to the Astaria bug class: **a state-classification decision is derived from data the attacker fully controls, and the code that consumes that classification doesn't independently verify it before taking a trust-elevating action** (in Astaria: trusting that an auction had been "settled" without verifying cleanup; in Desktop: trusting a forged `WWW-Authenticate` realm string to decide a host is a "GitHub" host worth an automatic sign-in prompt).

## Finding Description
Every git operation Desktop performs (clone/fetch/pull/push) routes through the credential-helper trampoline, which is installed unconditionally for all git invocations via `withTrampolineEnv`/`git()`: [1](#0-0) 

When git needs credentials for a remote (including a remote the user just cloned/fetched from, which can be **any attacker-controlled host**), Desktop's `createCredentialHelperTrampolineHandler` is invoked and calls `getCredential` → `getEndpointKind`: [2](#0-1) 

Note the classification logic: if the host doesn't match `github.com`/`*.ghe.com` patterns, Desktop inspects the `wwwauth[...]` credential fields — which are populated directly from the **HTTP `WWW-Authenticate` response header sent by the remote server** — and if it contains `realm="GitHub"`, the endpoint is classified as `'enterprise'`.

That classification then drives `getCredential`: [3](#0-2) 

If no existing `Account` matches the (attacker) host, Desktop does **not** treat this as "unknown/generic" and back off — instead it calls `ui.promptForGitHubSignIn(endpoint)`, which invokes `dispatcher.beginEnterpriseSignIn` / `setSignInEndpoint` and opens the native "Sign in to GitHub Enterprise" `PopupType.SignIn` dialog scoped to the attacker's endpoint: [4](#0-3) 

The broken invariant: **the decision to present a GitHub-branded, credential-collecting sign-in surface — and to potentially create/bind a new `Account` for that endpoint — is driven entirely by a response header that the remote server (attacker-controlled clone URL, or any network position that can MITM/proxy the git HTTP request) fully controls.** There is no cross-check against a real GitHub/GHE handshake (e.g., hitting `/api/v3/meta` or checking a known-good certificate/response body) before eliciting sign-in.

## Impact Explanation
An attacker who controls a git remote (e.g., publishes a malicious repository and lures the user into cloning/adding it) or who can inject/tamper with an HTTP response in the request path of any git operation Desktop performs, can cause Desktop to autonomously classify their arbitrary host as a "GitHub Enterprise" endpoint and pop the trusted native sign-in UI for it — an action the user never explicitly requested (they only tried to sync a repository). This satisfies "unauthorized OAuth or account binding": the resulting account, if the user proceeds, gets silently added to Desktop's `AccountsStore` bound to the attacker's endpoint, and per `findGitHubTrampolineAccount`'s origin-matching, that stored token/credential would subsequently be auto-supplied by Desktop to any future git operation against that same origin without further prompting: [5](#0-4) 

This is materially different from a user-initiated "Add Enterprise Account" flow: it is triggered passively as a side effect of an ordinary fetch/clone against a host the user did not intend to authenticate against, using nothing but a spoofable header.

## Likelihood Explanation
Triggering this requires only that the attacker control the HTTP response to a credential-challenged git request — trivially achievable by hosting the remote themselves (`http://attacker.example/repo.git` returning `401 WWW-Authenticate: Basic realm="GitHub"`), no local access, no malware, no leaked credentials, and no unnatural user steps beyond the ordinary "clone/add this repository" action that Desktop is designed to support.

## Recommendation
Do not classify an endpoint as `'enterprise'` (or any GitHub-trusted kind) based solely on the `wwwauth[...]` realm string reflected from the remote's own response. Require independent verification (e.g., a successful call to the candidate host's `/api/v3/meta`, or matching against a previously verified/user-confirmed GHE endpoint) before invoking `promptForGitHubSignIn`, and clearly label the sign-in dialog with the literal, unmodified host being contacted so it cannot be mistaken for github.com/an already-trusted enterprise instance.

## Proof of Concept
1. Attacker hosts `https://attacker.example/evil.git` and configures the server to respond to unauthenticated Smart HTTP requests with `401` and header `WWW-Authenticate: Basic realm="GitHub"`.
2. Victim, using GitHub Desktop, clones/adds/fetches `https://attacker.example/evil.git` (normal user action, e.g., via a link they were sent or a "Clone repository" URL).
3. Git invokes Desktop's `credential.helper=desktop`; `getEndpointKind` reads the forwarded `wwwauth[...]` field, sees `realm="GitHub"`, returns `'enterprise'` (`app/src/lib/trampoline/trampoline-credential-helper.ts:137-166`).
4. `getCredential` finds no existing account for `attacker.example` and calls `ui.promptForGitHubSignIn('https://attacker.example')`, which opens the native "Sign in to GitHub Enterprise" popup pointed at the attacker's server (`app/src/lib/trampoline/trampoline-ui-helper.ts:80-104`).
5. If the user completes sign-in (e.g., pastes a PAT believing it's a normal Desktop prompt), the resulting `Account` is bound to `attacker.example` and will be auto-supplied by Desktop for any future git operation against that origin.

/** Implementation of the 'get' git credential helper command */
async function getCredential(cred: Credential, store: Store, token: string) {
  const ghCred = await getGitHubCredential(cred, store)

  if (ghCred) {
    return ghCred
  }

  const endpointKind = await getEndpointKind(cred, store)
  const accounts = await store.getAll()

  const endpoint = `${getCredentialUrl(cred)}`
  const apiEndpoint = getAPIEndpoint(endpoint)

  // If it appears as if the endpoint is a GitHub host and we don't have an
  // account for that endpoint then we should prompt the user to sign in.
  if (
    endpointKind !== 'generic' &&
    !accounts.some(a => a.endpoint === apiEndpoint)
  ) {
    if (getIsBackgroundTaskEnvironment(token)) {
      debug('background task environment, skipping prompt')
      return undefined
    }

    const account = await ui.promptForGitHubSignIn(endpoint)

    if (!account) {
      setHasRejectedCredentialsForEndpoint(token, endpoint)
    }

    return credWithAccount(cred, account)
  }

const getEndpointKind = async (cred: Credential, store: Store) => {
  const credentialUrl = getCredentialUrl(cred)
  const endpoint = `${credentialUrl}`

  if (isGist(endpoint)) {
    return 'generic'
  }

  if (isDotCom(endpoint)) {
    return 'github.com'
  }

  if (isGHE(endpoint)) {
    return 'ghe.com'
  }

  // When Git attempts to authenticate with a host it captures any
  // WWW-Authenticate headers and forwards them to the credential helper. We
  // use them as a happy-path to determine if the host is a GitHub host without
  // having to resort to making a request ourselves.
  for (const [k, v] of cred.entries()) {
    if (k.startsWith('wwwauth[')) {
      if (v.includes('realm="GitHub"')) {
        return 'enterprise'
      } else if (/realm="(GitLab|Gitea|Atlassian Bitbucket)"/.test(v)) {
        return 'generic'
      }
    }
  }

  public promptForGitHubSignIn(endpoint: string): Promise<Account | undefined> {
    return new Promise<Account | undefined>(async resolve => {
      const cb = (result: SignInResult) => {
        resolve(result.kind === 'success' ? result.account : undefined)
        this.dispatcher.closePopup(PopupType.SignIn)
      }

      const { hostname, origin } = new URL(endpoint)
      if (hostname === 'github.com') {
        this.dispatcher.beginDotComSignIn(cb)
      } else {
        this.dispatcher.beginEnterpriseSignIn(cb)
        await this.dispatcher.setSignInEndpoint(origin)
      }

      this.dispatcher.showPopup({
        type: PopupType.SignIn,
        isCredentialHelperSignIn: true,
        credentialHelperUrl: endpoint,
      })
    }).catch(e => {
      log.error(`Could not prompt for GitHub sign in`, e)
      return undefined
    })
  }

export async function findGitHubTrampolineAccount(
  accountsStore: AccountsStore,
  remoteUrl: string
): Promise<Account | undefined> {
  const accounts = await accountsStore.getAll()
  const parsedUrl = new URL(remoteUrl)
  return accounts.find(
    a => new URL(getHTMLURL(a.endpoint)).origin === parsedUrl.origin
  )
}
