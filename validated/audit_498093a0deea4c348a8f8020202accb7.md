### Title
DataLayer mirror URLs are untrusted, attacker-controlled inputs that cause the service to make outbound HTTP requests (SSRF via on-chain mirror memo injection) - (File: `chia/data_layer/download_data.py`, `chia/data_layer/data_layer_wallet.py`, `chia/data_layer/data_layer.py`)

### Summary
`DataLayerWallet.create_new_mirror` lets a wallet create a coin using `create_mirror_puzzle()` whose puzzle hash is fixed and public, with an arbitrary list of `urls` embedded in the coin's memo [1](#0-0) . Any unprivileged spend-bundle submitter can construct their own `CREATE_COIN` output to this same well-known mirror puzzle hash with an arbitrary `launcher_id` and arbitrary URL memos — there is no signature or ownership check tying the mirror to the store owner. When a peer's wallet observes this coin, `DataLayerWallet.coin_added` decodes the memo and records the mirror as long as the `launcher_id` is a locally tracked store, without validating or restricting the URL values [2](#0-1) .

### Finding Description
Once a malicious mirror record is stored, `DataLayer.fetch_and_validate()` reads `servers_info` for a store id via `self.data_store.get_available_servers_for_store(...)`, shuffles them, and for each iterates calling `insert_from_delta_file(...)` with `server_info=server_info` sourced directly from the attacker-controlled mirror URL [3](#0-2) . Inside `download_data.py`, `download_file()` calls `http_download()` when no plugin downloader claims the URL, and `http_download()` performs an unrestricted `aiohttp` GET to `server_info.url + "/" + filename` with no scheme allow-list, no DNS/IP restriction, and no blocking of loopback/link-local/internal addresses [4](#0-3) . This is the classic SSRF pattern from the CraftQL advisory: a value fully controlled by an untrusted party (here, an on-chain memo any spend-bundle submitter can set) is used directly as a server-side outbound request target, with the running DataLayer/full node process acting as the requesting agent.

Additionally, `DataLayer.get_downloader()` similarly POSTs a JSON payload containing the attacker-supplied `url` to each configured downloader plugin endpoint before falling back to `http_download` [5](#0-4) , meaning the malicious URL string is passed to plugin trust boundaries as well.

The `.cursor/context/data-layer.md` documentation for this module explicitly acknowledges this trust boundary weakness: "Plugin and mirror URLs are external trust inputs... file path/name validation must stay strict" and "Do not treat mirror URLs, plugins, or static file names as trusted data sources" [6](#0-5) [7](#0-6) , confirming that mirror URL trust is a known-sensitive area but the code performs no scheme/host restriction before issuing the HTTP request.

### Impact Explanation
Any node running the DataLayer service and subscribed to (or owning) a store can be coerced into making an outbound HTTP GET request to an arbitrary attacker-chosen URL, purely by an unprivileged party broadcasting a spend that creates a coin with the mirror puzzle hash and a crafted memo. This enables:
- Probing/attacking internal network services or cloud metadata endpoints (e.g., `http://169.254.169.254/...`) reachable from the machine running the DataLayer service.
- Using the DataLayer node as an open-ended HTTP request proxy against third parties, since the URL and constructed filename path are attacker-influenced.
- Resource exhaustion / driving repeated outbound connections to attacker infrastructure by many nodes tracking the same store.

Because the mirror record is picked up automatically by any peer syncing the affected store id, the blast radius extends to every DataLayer node subscribed to that store, not just the mirror creator's own node.

### Likelihood Explanation
Likelihood is high given reachability: creating the malicious mirror coin only requires a standard spend bundle with a `CREATE_COIN` condition to the known `create_mirror_puzzle()` hash and a memo of `[launcher_id, url, ...]` — no special privileges, ownership of the store, or wallet-level authorization are required for the on-chain artifact to be recorded and later acted upon by `fetch_and_validate()`.

### Recommendation
- In `chia/data_layer/download_data.py::http_download` and `chia/data_layer/data_layer.py::get_downloader`, validate mirror URLs before making outbound requests: restrict schemes (e.g., only `http`/`https` or scoped `s3`), resolve and reject private/loopback/link-local/multicast IP ranges, and enforce an allow-list or explicit opt-in policy for mirror hosts.
- In `DataLayerWallet.coin_added` (`chia/data_layer/data_layer_wallet.py`), consider adding basic sanity/format checks on decoded mirror URLs before persisting them via `dl_store.add_mirror`, and/or exposing configuration to require manual approval of new mirror servers rather than auto-trusting any on-chain memo.
- Ensure the `ours` mirror-ownership flag (already tracked) can be used to gate which mirrors are auto-fetched from versus which require explicit operator consent.

### Proof of Concept
1. Attacker learns/observes the `launcher_id` of a DataLayer store that victim nodes subscribe to.
2. Attacker submits a standard spend bundle creating a coin with puzzle hash `create_mirror_puzzle().get_tree_hash()` and memo `[launcher_id, b"http://169.254.169.254/latest/meta-data/", ...]` — mirroring the shape produced by `create_new_mirror` [1](#0-0) .
3. Once confirmed, any victim `DataLayerWallet.coin_added` for a peer tracking that `launcher_id` records the malicious URL as a mirror [2](#0-1) .
4. During the victim's next `periodically_manage_data()`/`update_subscription()` cycle, `fetch_and_validate()` selects this server and calls `insert_from_delta_file` → `download_file` → `http_download`, causing the victim's DataLayer process to issue an HTTP GET to the attacker-chosen internal/arbitrary URL [3](#0-2) [4](#0-3) .

```python
    async def get_downloader(self, store_id: bytes32, url: str) -> PluginRemote | None:
        request_json = {"store_id": store_id.hex(), "url": url}
        for d in self.downloaders:
            async with aiohttp.ClientSession() as session:
                try:
                    async with session.post(
                        d.url + "/handle_download",
                        json=request_json,
                        headers=d.headers,
                        timeout=self.client_timeout,
                    ) as response:
                        res_json = await response.json()
                        if res_json["handle_download"]:
                            return d
                except Exception as e:
                    self.log.error(f"get_downloader could not get response: {type(e).__name__}: {e}")
        return None
```

```python
async def http_download(
    target_filename_path: Path,
    filename: str,
    proxy_url: str | None,
    server_info: ServerInfo,
    timeout: aiohttp.ClientTimeout,
    log: logging.Logger,
    max_delta_file_size: int,
) -> None:
    """
    Download a file from a server using aiohttp.
    Raises exceptions on errors
    """
    async with aiohttp.ClientSession() as session:
        headers = {"accept-encoding": "gzip"}
        async with session.get(
            server_info.url + "/" + filename,
            headers=headers,
            timeout=timeout,
            proxy=proxy_url,
        ) as resp:
            resp.raise_for_status()
            size = int(resp.headers.get("content-length", 0))
            max_delta_file_size_bytes = max_delta_file_size * 1024 * 1024
            if size > max_delta_file_size_bytes:
                raise MaxDeltaFileSizeExceededError(f"Maximum delta file size exceeded: {max_delta_file_size} MiB.")
            log.debug(f"Downloading delta file {filename}. Size {size} bytes.")
```
