### Title
`Scanner::scan_block` reports coinbase outputs as received without enforcing the 100-block maturity rule - ([File: networks/bitcoin/src/wallet/mod.rs](networks/bitcoin/src/wallet/mod.rs))

### Summary
The bug class in the external report is "redeem spends/credits a position whose maturity was never checked." The Serai analog is Bitcoin coinbase maturity: a coinbase output is a "received" UTXO that cannot actually be spent until 100 confirmations. `Scanner::scan_block` in `networks/bitcoin/src/wallet/mod.rs` iterates `block.txdata` including `txdata[0]` (the coinbase transaction) and returns matching outputs as `ReceivedOutput`s with no maturity check or flag, while `scan_transaction` itself has no notion of coinbase-vs-regular at all.

### Finding Description
`scan_block` calls `scan_transaction` over every transaction in the block, starting with index 0 (the coinbase): [1](#0-0) 

`scan_transaction` matches purely on `script_pubkey` membership in `self.scripts` and wraps any match into a `ReceivedOutput`: [2](#0-1) 

The only mitigation is a doc comment stating a "post-processing pass is needed" — the function itself performs no check, and `ReceivedOutput` carries no field distinguishing an immature coinbase output from a spendable one. Contrast with the maturity-aware handling elsewhere: `processor/src/networks/bitcoin.rs` explicitly skips `block.txdata[1 ..]`'s leading coinbase with the comment "Skip the coinbase transaction which is burdened by maturity", and the Monero scanner explicitly filters via `outputs.not_additionally_locked()` for miner transactions with extended timelocks. The public `Scanner` API in `networks/bitcoin` offers a correctness-preserving path only if the caller reads the doc comment; the API itself happily reports the unspendable output.

### Impact Explanation
Any downstream consumer using `scan_block` (the natural "scan a block for our outputs" entry point — it is the API exercised in `networks/bitcoin/tests/wallet.rs`) receives a `ReceivedOutput` that is consensus-unspendable for 100 blocks. If such an output is fed into wallet/planning logic, a transaction spending it will be constructed and signed but rejected by the network, or worse, accounted as available balance while it is not. This matches the accepted impact class "funds reported received that are not spendable."

### Likelihood Explanation
The trigger is externally reachable: a miner can pay the Serai multisig script directly from a coinbase output (no permission needed; the script is a plain P2TR anyone can pay to). Whether damage materializes depends on a consumer calling `scan_block` rather than skipping `txdata[0]` — the doc comment warns, but nothing enforces it, and the API design makes the unsafe path the obvious one.

### Recommendation
Exclude the coinbase transaction inside `scan_block` (iterate `block.txdata[1 ..]`), or tag `ReceivedOutput`/return value so immature coinbase outputs cannot be conflated with spendable ones. If scanning coinbase outputs is genuinely desired, gate them behind an explicit maturity/confirmations parameter rather than a doc comment.

### Proof of Concept
In `networks/bitcoin/tests/wallet.rs`, `send_and_get_output` already demonstrates the path: a block is generated whose coinbase (`block.txdata[0]`) pays `p2tr_script_buf(key)`, and `scanner.scan_block(&block)` returns that coinbase output as a `ReceivedOutput` — `assert_eq!(outputs, scanner.scan_transaction(&block.txdata[0]))` confirms the coinbase match is reported. The test then mines 100 blocks afterward only to make it spendable, showing the reported output was immature at scan time.

  pub fn scan_transaction(&self, tx: &Transaction) -> Vec<ReceivedOutput> {
    let mut res = Vec::new();
    for (vout, output) in tx.output.iter().enumerate() {
      // If the vout index exceeds 2**32, stop scanning outputs
      let Ok(vout) = u32::try_from(vout) else { break };

      if let Some(offset) = self.scripts.get(&output.script_pubkey) {
        res.push(ReceivedOutput {
          offset: *offset,
          output: output.clone(),
          outpoint: OutPoint::new(tx.compute_txid(), vout),
        });
      }
    }
    res
