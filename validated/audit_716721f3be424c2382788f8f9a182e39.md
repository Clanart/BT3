### Title
`FinalizeState` block-processing pipeline aborts the entire chain on a single module failure instead of failing safely - ([File: blockchain/state_processor.go])

### Summary
`StateProcessor.FinalizeState` iterates over all registered `BlockStateModule`s (reward, staking, valset, gasless, supply, gov, …) and returns immediately, aborting the whole block, the instant any single module returns an error. One of those modules (`kaiax/staking`) resolves `StakingInfo` via a single, fixed-gas, on-chain multicall to `AddressBook`/`AddressBookV2`/`CLRegistry`. If that read ever reverts or runs out of gas, the failure propagates all the way up and halts block finalization for every node on the network — the same "single external dependency failure breaks the entire critical operation" pattern flagged in the `RootManager.propagate` finding, except here the blast radius is the whole chain rather than one bridge connector.

### Finding Description
`StateProcessor.FinalizeState` runs the following loop with no isolation between modules: [1](#0-0) 

```go
for _, module := range p.blockStateModules {
    if err := module.FinalizeState(header, statedb, txs, receipts); err != nil {
        return nil, err
    }
}
```

Any single module error aborts the entire `FinalizeState` call, and by extension `Process()`: [2](#0-1) 

One of the registered modules is `RewardModule.FinalizeState`, which calls `GetDeferredReward` → `StakingModule.GetStakingInfo`: [3](#0-2) 

`GetStakingInfo` ultimately calls `getFromState`, which performs a single EVM call into the `MultiCallContract` (a fixed `gasLimit := uint64(1e8)` read call) to fetch `AddressBook`/`AddressBookV2` and, after Prague, `CLRegistry` data in one shot: [4](#0-3) 

If this call reverts or runs out of gas — e.g. because the AddressBook/CLRegistry state has grown unbounded (many registered CN staking contracts / CL pools, which any staker can register through ordinary permissionless registration flows) or the multicall's internal iteration exceeds the fixed 1e8 gas budget — `getFromState` returns `ErrAddressBookCall`/`ErrCLRegistryCall`/`ErrMultiCallCall`: [5](#0-4) 

This error is not handled defensively anywhere in the chain: it propagates from `getFromState` → `GetStakingInfo` → `RewardModule.FinalizeState` → `StateProcessor.FinalizeState` → `Process()`, causing every honest node to fail to finalize the block. Because this is deterministic state-dependent behavior, all honest nodes fail identically and simultaneously — the network-wide equivalent of Connext's messaging network breaking down when one AMB call reverts.

### Impact Explanation
Unlike `RootManager.propagate`, where a bridge failure only stalls cross-chain root propagation for the affected route, a failure surfaced through `StateProcessor.FinalizeState` stalls **block finalization for the entire Kaia network** — no blocks can be finalized/validated by any node until the underlying condition (e.g., AddressBook/CLRegistry state size) is manually remediated via a hard fork or governance/emergency intervention. This is a consensus-liveness-halting condition triggered by ordinary state growth rather than malicious governance/admin action, matching the "state transition and gas/burn accounting" and "acceptance of an invalid transaction or block" (in this case, rejection of *all* blocks) categories in scope.

### Likelihood Explanation
The condition requires the `MultiCallContract`'s fixed 1e8 gas budget to be exceeded, or the underlying `AddressBook`/`AddressBookV2`/`CLRegistry` read to revert. Since CN staking contract registration and CL pool registration are reachable by ordinary stakers under the permissionless model (no privileged governance action required), an attacker/staker who registers enough entries could push the multicall's gas usage toward the fixed budget over time, eventually tripping this fail-hard path. This requires accumulating many registrations rather than a single transaction, making likelihood moderate rather than trivial, but the lack of any fail-safe/degradation path makes the eventual impact severe once triggered.

### Recommendation
Do not let a single `BlockStateModule.FinalizeState` (or the underlying `StakingModule.GetStakingInfo` / `MultiCallContractCaller` read) failure unconditionally abort the entire block pipeline:
- Increase/parameterize the multicall gas budget relative to actual AddressBook/CLRegistry size, or paginate the multicall so it cannot exceed a fixed gas ceiling as the registry grows.
- Distinguish between "no data" (empty/uninstalled) and "call failed" states, and consider a bounded, monitored, fail-open fallback (e.g., reuse of the last successfully computed `StakingInfo`) for the reward-distribution path, analogous to the try/catch fail-safe recommended for `RootManager.propagate`, so that one module's error does not halt the entire chain's block finalization.

### Proof of Concept
1. Under the permissionless fork, repeatedly submit ordinary CN-staking-contract / CL-pool registration transactions (available to any sufficiently staked account, no admin role required) until the number of entries returned by `AddressBook`/`AddressBookV2`/`CLRegistry` is large enough that `MultiCallContractCaller`'s fixed `gasLimit = 1e8` read call in `blockchain/system/multicall.go` (`CallContract`) can no longer complete within budget.
2. On the next block, `StakingModule.getFromState` (`kaiax/staking/impl/getter.go`) receives an out-of-gas/revert error from the multicall and returns `ErrAddressBookCall`/`ErrCLRegistryCall`.
3. `RewardModule.FinalizeState` (`kaiax/reward/impl/blockstate.go`) propagates this error unchanged.
4. `StateProcessor.FinalizeState` (`blockchain/state_processor.go`) aborts with the same error for every node attempting to process/validate that block, halting block finalization network-wide until the registry size is reduced or the gas budget is patched via a hard fork.

func (r *RewardModule) FinalizeState(header *types.Header, state *state.StateDB, txs []*types.Transaction, receipts []*types.Receipt) error {
	if r.GovModule.GetParamSet(header.Number.Uint64()).ProposerPolicy == uint64(istanbul.WeightedRandom) && common.EmptyHash(header.Root) {
		qualified, err := r.ValsetModule.GetQualifiedValidators(header.Number.Uint64())
		if err != nil {
			return err
		}
		useRewardAddress := valset.NewAddressSet(qualified).Contains(r.NodeAddress)

		if rewardAddr := r.GetRewardAddress(header.Number.Uint64(), r.NodeAddress); useRewardAddress && rewardAddr != (common.Address{}) {
			header.Rewardbase = rewardAddr
			logger.Trace("Use reward address for nodeValidator", "header.Number", header.Number.Uint64(), "nodeAddress", r.NodeAddress, "rewardbase", header.Rewardbase)
		} else {
			logger.Trace("No reward address for nodeValidator. Use node's rewardbase.", "header.Number", header.Number.Uint64(), "nodeAddress", r.NodeAddress, "rewardbase", header.Rewardbase)
		}
	}

	spec, err := r.GetDeferredReward(header, txs, receipts)
	if err != nil {
		return err
	}

// CallContract injects a multicall contract code into the state and executes the call.
func (caller *ContractCallerForMultiCall) CallContract(ctx context.Context, call kaia.CallMsg, blockNumber *big.Int) ([]byte, error) {
	gasPrice := big.NewInt(0) // execute call regardless of the balance of the sender
	gasLimit := uint64(1e8)   // enough gas limit to execute multicall contract functions
	intrinsicGas := uint64(0) // read operation doesn't require intrinsicGas

	// call.From: zero address will be assigned if nothing is specified
	// call.To: the target contract address will be assigned by `BoundContract`
	// call.Value: nil value is acceptable for `types.NewMessage`
	// call.Data: a proper value will be assigned by `BoundContract`
	// No need to handle access list here

	// Set the code of the multicall contract
	err := caller.state.SetCode(MultiCallAddr, MultiCallCode)
	if err != nil {
		return nil, err
	}

	msg := types.NewMessage(call.From, call.To, caller.state.GetNonce(call.From),
		call.Value, gasLimit, gasPrice, nil, nil, nil, call.Data, false, intrinsicGas, nil, nil, nil, nil, nil)

	blockContext := blockchain.NewEVMBlockContext(caller.header, caller.chain, nil)
	txContext := blockchain.NewEVMTxContext(msg, caller.header, caller.chain.Config())
	txContext.GasPrice = gasPrice                                                                // set gasPrice again if baseFee is assigned
	evm := vm.NewEVM(blockContext, txContext, caller.state, caller.chain.Config(), &vm.Config{}) // no additional vm config required

	result, err := blockchain.ApplyMessage(evm, msg)
	return result.Return(), err
}
