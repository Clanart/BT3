### Title
Unhandled `IndexError` in `is_atom_canonical` on a truncated CLVM length-prefix crashes mempool spend-bundle validation - (File: chia/full_node/mempool_manager.py)

### Summary
`is_clvm_canonical()` is invoked directly on attacker-supplied `coin_spend.puzzle_reveal` and `coin_spend.solution` bytes for every coin spend inside a submitted `SpendBundle`, as part of ordinary mempool admission (`validate_spend_bundle`). It delegates multi-byte atom length-prefix decoding to `is_atom_canonical()`, which reads the trailing prefix bytes without ever checking that `offset` stays within the buffer bounds, analogous to the unchecked-length/overflow read pattern in CVE-2007-3798's BGP TLV parsing.

### Finding Description
`is_atom_canonical` determines, from the top bits of `clvm_buffer[offset]`, how many additional prefix bytes (`prefix_len`, 0–5) encode the atom's length, then loops to read them: [1](#0-0) 

The loop `for i in range(prefix_len): ... offset += 1; atom_len |= clvm_buffer[offset]` never verifies that `offset` is still `< len(clvm_buffer)` before indexing. If the buffer ends exactly at (or before) the position implied by the length-prefix encoding — e.g. a single-byte buffer `b"\xc0"`, whose top bits `0b110xxxxx` declare `prefix_len = 1` — the very next index access `clvm_buffer[1]` is out of range and Python raises an uncaught `IndexError`.

`is_clvm_canonical` calls into `is_atom_canonical` for any byte `b` in the range `0x81`–`0xFD` encountered while scanning the CLVM buffer: [2](#0-1) 

This function is called unconditionally, per coin spend, directly on the raw bytes of both the puzzle reveal and the solution supplied in the `SpendBundle`, during normal mempool admission: [3](#0-2) 

`validate_spend_bundle` is called from `add_spend_bundle`, which has no `try/except` around the call and lets any exception propagate: [4](#0-3) 

Because a crafted, truncated multi-byte atom-length prefix can be placed as the final bytes of `puzzle_reveal` or `solution` in an otherwise-valid-looking `CoinSpend`, an unprivileged remote peer or RPC caller submitting a `SpendBundle` can force `is_atom_canonical` to index past the end of the buffer, raising `IndexError` inside `validate_spend_bundle`/`add_spend_bundle`.

### Impact Explanation
An uncaught `IndexError` raised deep inside the mempool admission pipeline, on the code path executed for every incoming `SpendBundle`, is a spend-triggered fault in transaction processing. Depending on where `add_spend_bundle` is awaited by the full node's mempool/RPC handling code, this can abort the enclosing task or handler for that submission, and if the exception is not defensively caught at every call site, it can disrupt the mempool manager's ability to keep processing subsequent spend bundles — a denial-of-service condition triggerable by a single unprivileged spend-bundle submitter, without needing a valid signature, funds, or any state change.

### Likelihood Explanation
The trigger only requires constructing a `CoinSpend` whose `puzzle_reveal` or `solution` byte string ends immediately after a multi-byte atom-length-prefix marker (e.g. a trailing `0xC0` byte, or `0xE0`, `0xF0`, `0xF8`, `0xFC` followed by fewer bytes than required). This requires no cryptographic material, no coin ownership, and no special privileges — any party able to submit a spend bundle (over RPC or gossip) can reach `is_clvm_canonical` with arbitrary bytes before signature/coin-ownership checks fully gate the request. This makes the likelihood high for a party willing to submit malformed data.

### Recommendation
Add explicit bounds checks in `is_atom_canonical` before each `clvm_buffer[offset]` access in the prefix-reading loop (and before the initial `clvm_buffer[offset]` read), raising a well-defined, caught error (e.g. returning `atom_len, False` or raising a handled `ValueError`) instead of allowing an `IndexError` to propagate. Additionally, wrap the `is_clvm_canonical` calls in `validate_spend_bundle` in a try/except that treats any parsing failure as `Err.INVALID_COIN_SOLUTION`, matching how the rest of the function already handles non-canonical encodings.

### Proof of Concept
```python
from chia.full_node.mempool_manager import is_clvm_canonical

# 0xC0 = 0b11000000 -> declares a 5+8-bit length prefix (prefix_len = 1),
# but the buffer contains no further bytes for the prefix.
truncated_atom_prefix = b"\xc0"

is_clvm_canonical(truncated_atom_prefix)
# raises: IndexError: index out of range
```
Embedding such a truncated tail as the final bytes of a `CoinSpend.puzzle_reveal` or `CoinSpend.solution` and submitting the enclosing `SpendBundle` through normal mempool submission reaches `is_clvm_canonical` inside `validate_spend_bundle` (`chia/full_node/mempool_manager.py:723-725`) before any exception handling, raising the same uncaught `IndexError`.

```python
def is_atom_canonical(clvm_buffer: bytes, offset: int) -> tuple[int, bool]:
    b = clvm_buffer[offset]
    if (b & 0b11000000) == 0b10000000:
        # 6 bits length prefix
        mask = 0b00111111
        prefix_len = 0
        min_value = 1
    elif (b & 0b11100000) == 0b11000000:
        # 5 + 8 bits length prefix
        mask = 0b00011111
        prefix_len = 1
        min_value = 1 << 6
    elif (b & 0b11110000) == 0b11100000:
        # 4 + 8 + 8 bits length prefix
        mask = 0b00001111
        prefix_len = 2
        min_value = 1 << (5 + 8)
    elif (b & 0b11111000) == 0b11110000:
        # 3 + 8 + 8 + 8 bits length prefix
        mask = 0b00000111
        prefix_len = 3
        min_value = 1 << (4 + 8 + 8)
    elif (b & 0b11111100) == 0b11111000:
        # 2 + 8 + 8 + 8 + 8 bits length prefix
        mask = 0b00000011
        prefix_len = 4
        min_value = 1 << (3 + 8 + 8 + 8)
    elif (b & 0b11111110) == 0b11111100:
        # 1 + 8 + 8 + 8 + 8 + 8 bits length prefix
        mask = 0b00000001
        prefix_len = 5
        min_value = 1 << (2 + 8 + 8 + 8 + 8)

    atom_len = b & mask
    for i in range(prefix_len):
        atom_len <<= 8
        offset += 1
        atom_len |= clvm_buffer[offset]

    return 1 + prefix_len + atom_len, atom_len >= min_value
```
