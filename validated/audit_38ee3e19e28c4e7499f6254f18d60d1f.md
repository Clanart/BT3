### Title
Unbounded-recursion JSON decode of ChainDataAnchoring tx payload causes node-crashing stack overflow - ([File: blockchain/types/anchoring_data.go])

### Summary
`DecodeAnchoringDataToJSON` in `blockchain/types/anchoring_data.go` decodes the `AnchoringJSONDataType` (type `128`) payload of a `TxTypeChainDataAnchoring` / `TxTypeFeeDelegatedChainDataAnchoring` / `...WithRatio` transaction via `json.Unmarshal(anchoringData.Data, &v)` into an unconstrained `map[string]interface{}`, with no maximum nesting-depth check [1](#0-0) . This mirrors the HAPI FHIR bug class: a JSON parser with no bound on array/object nesting depth, invoked recursively until the call stack is exhausted.

### Finding Description
Any account can submit a `TxTypeChainDataAnchoring` transaction whose `AnchoredData` payload is RLP-encoded as `AnchoringData{Type: AnchoringJSONDataType, Data: <arbitrary JSON bytes>}` [2](#0-1) . The `Data` field is fully attacker-controlled and is never validated at tx admission time — `TxInternalDataChainDataAnchoring.Validate` is a no-op (`return nil`) [3](#0-2) , and `Execute` simply increments the nonce without inspecting the payload [4](#0-3) .

Once the transaction is pending or mined, any RPC caller that fetches it (e.g. `eth_getTransactionByHash`, `klay_getTransactionByHash`, block/receipt queries that embed the tx, `debug` tracing outputs) triggers JSON serialization of the transaction via `TxInternalDataChainDataAnchoring.MarshalJSON()` and `MakeRPCOutput()`, both of which call `DecodeAnchoringDataToJSON(t.Payload)` [5](#0-4) . The same pattern exists for the fee-delegated variants [6](#0-5)  and the fee-delegated-with-ratio variant [7](#0-6) .

`json.Unmarshal` into `interface{}`/`map[string]interface{}` in Go recurses once per nesting level of arrays/objects (e.g. `[[[[[...]]]]]` or `{"a":{"a":{"a":...}}}`) with no depth limit enforced by `encoding/json` or by this code. A sufficiently deep but syntactically valid JSON document (tens of thousands of nesting levels, easily fit within normal payload/gas limits) will exhaust the goroutine stack, causing a Go runtime fatal error (`runtime: goroutine stack exceeds ... limit`), which — unlike a panic — cannot be recovered and crashes the entire node process, not just the handling goroutine.

### Impact Explanation
Any RPC client that reads back a maliciously crafted chain-data-anchoring transaction (a very common operation — wallets/explorers/dApps call `getTransactionByHash`/`getBlockByNumber` on every tx) crashes the serving node process outright. Because this is a full process crash (not an isolated goroutine panic), it takes down all RPC service and node operation, a denial-of-service against any public-RPC node, gasless relayer, or fee-delegation counterparty that queries the mempool/chain for this transaction. Reaching this path requires only submitting one ordinary, low-cost transaction type available to any unprivileged sender.

### Likelihood Explanation
High. `TxTypeChainDataAnchoring` is a standard, publicly available Kaia transaction type; no special privilege, staking, or governance access is required to submit it. Local/self anchoring tx submission may be gated by `AllowLocalAnchorTx` in some tx-pool configurations [8](#0-7) , but the transaction can still reach the chain via `AddRemote` (as shown in the pool test) and via other origination paths (e.g. relayed from peers), after which any RPC read of it triggers the vulnerable code deterministically.

### Recommendation
Enforce a maximum JSON nesting depth before/while decoding attacker-controlled anchoring payloads in `DecodeAnchoringDataToJSON` (e.g. use a `json.Decoder` with a depth counter, or pre-scan the byte stream and reject inputs exceeding a safe depth such as 32–64 levels) and reject `AnchoringJSONDataType` payloads that exceed that bound before calling `json.Unmarshal`. Apply the same guard to any other RPC-facing JSON decoding into unconstrained interfaces.

### Proof of Concept
1. Construct a payload `nested = strings.Repeat("[", 100000) + strings.Repeat("]", 100000)` (or `{"a":` × N).
2. Build `AnchoringData{Type: AnchoringJSONDataType, Data: []byte(nested)}` and RLP-encode it: `payload, _ := rlp.EncodeToBytes(anchoringData)`.
3. Craft and sign a `TxTypeChainDataAnchoring` transaction with `TxValueKeyAnchoredData: payload` (as in `genAnchorTx` [9](#0-8) ) and submit it via `AddRemote`/`eth_sendRawTransaction`.
4. Once the tx is pending or included, call `eth_getTransactionByHash` (or any endpoint returning the tx) against the node.
5. The node's goroutine handling the RPC call invokes `MarshalJSON`/`MakeRPCOutput` → `DecodeAnchoringDataToJSON` → `json.Unmarshal`, recursing 100000 levels deep and crashing the process with a Go runtime stack-overflow fatal error.

func genAnchorTx(nonce uint64) *types.Transaction {
	key, _ := crypto.HexToECDSA("45a915e4d060149eb4365960e6a7a45f334393093061116b197e3240065ff2d8")
	from := crypto.PubkeyToAddress(key.PublicKey)

	gasLimit := uint64(1000000)
	gasPrice := big.NewInt(1)

	data := []byte{0x11, 0x22}
	values := map[types.TxValueKeyType]interface{}{
		types.TxValueKeyNonce:        nonce,
		types.TxValueKeyFrom:         from,
		types.TxValueKeyGasLimit:     gasLimit,
		types.TxValueKeyGasPrice:     gasPrice,
		types.TxValueKeyAnchoredData: data,
	}

	tx, _ := types.NewTransactionWithMap(types.TxTypeChainDataAnchoring, values)

	signer := types.MakeSigner(params.TestChainConfig, big.NewInt(2))
	tx.Sign(signer, key)

	return tx
