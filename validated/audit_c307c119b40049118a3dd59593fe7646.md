### Title
`WombatBribeManager.unvote` cannot be called for inactive pools, permanently freezing users' voted vlMGP - (File: wombat/WombatBribeManager.sol)

### Summary
`WombatBribeManager.unvote` is documented as the escape hatch that lets a user pull their vlMGP-backed vote out of a pool that has been deactivated ("This makes it so that deleting a pool, or changing a rewarder doesn't block users from withdrawing"), but the function's guard condition does the opposite: it reverts unless the pool `isActive`. Combined with the fact that `vote()` also reverts on inactive pools, a user who has voted for a pool that is later deactivated has no path to withdraw/unvote their locked vlMGP stake from that pool's `IBribeRewardPool`.

### Finding Description
`unvote` is meant to be usable specifically when a pool is no longer active, per its own docstring: [1](#0-0) 

```solidity
/// @notice Unvote from an inactive pool. This makes it so that deleting a pool, or changing a rewarder doesn't block users from withdrawing
function unvote(address _lp) public {
    Pool storage pool = poolInfos[_lp];
    uint256 currentVote = userVotedForPoolInVlmgp[msg.sender][pool.poolAddress];
    if(!pool.isActive)
        revert PoolNotActive();
    ...
```

The comment states the purpose is to let users unvote from an *inactive* pool, yet the guard `if(!pool.isActive) revert PoolNotActive();` requires the opposite — the pool must still be active for the call to succeed. This is the exact bug class described in the external report: the wrapper/guard function's state check does not match the states in which the underlying operation is actually supposed to be permitted, so users lose access to an action they should have.

This is compounded by `vote()`, the only other function that can move a user's stake out of a pool's `IBribeRewardPool` (via `withdrawFor` when `delta < 0`), which also unconditionally reverts for inactive pools: [2](#0-1) 

```solidity
for (uint256 i; i < length; i++) {
    Pool storage pool = poolInfos[_lps[i]];
    if (!pool.isActive)
        revert PoolNotActive();
    int256 delta = _deltas[i];
    ...
```

Since both the general `vote()` path and the dedicated `unvote()` escape hatch require `pool.isActive == true`, once a pool is deactivated there is no user-callable function in `WombatBribeManager` that can reduce `userVotedForPoolInVlmgp[msg.sender][pool.poolAddress]` or trigger `IBribeRewardPool(pool.rewarder).withdrawFor(...)` for that pool.

### Impact Explanation
A user's vlMGP voting weight allocated to a pool is tracked in `userVotedForPoolInVlmgp` and mirrored as a stake inside that pool's `IBribeRewardPool` via `stakeFor`. If the pool is later marked inactive (e.g., the underlying Wombat pool/rewarder is deprecated or swapped, a routine and expected lifecycle event, not an attack), the affected user's vlMGP allocation becomes permanently non-withdrawable through any contract path: `unvote` reverts due to the inverted `isActive` check, and `vote` reverts for the same reason. This locks the user's voting-power stake (and correspondingly blocks their ability to reallocate/unlock their vlMGP for other votes or to claim it back), constituting a permanent freeze of user funds/voting rights tied to that pool.

### Likelihood Explanation
Pool deactivation is a normal, expected part of the protocol's pool-management lifecycle (pools get deprecated/replaced over time as is common in Wombat-style bribe managers), not a rare or adversarial event. Any ordinary user who has voted for a pool that is subsequently deactivated is affected automatically the next time they try to unvote or adjust their vote — no special preconditions or privileged actions are required.

### Recommendation
Invert the guard in `unvote` so that it succeeds precisely when the pool is inactive (or at minimum does not block unvoting for inactive pools), consistent with its docstring, e.g.:

```solidity
function unvote(address _lp) public {
    Pool storage pool = poolInfos[_lp];
    uint256 currentVote = userVotedForPoolInVlmgp[msg.sender][pool.poolAddress];
    // allow unvoting regardless of active status; withdrawing must always be possible
    ...
}
```

Additionally, allow `vote()` to process negative deltas (withdrawals) for inactive pools instead of reverting outright, so reducing/removing a vote is never blocked by pool deactivation.

### Proof of Concept
1. User calls `vote([lpA], [1000e18])`, which calls `IBribeRewardPool(pool.rewarder).stakeFor(user, 1000e18)` and sets `userVotedForPoolInVlmgp[user][lpA] = 1000e18` — see [3](#0-2) .
2. The pool for `lpA` is later deactivated (`poolInfos[lpA].isActive = false`) as part of normal pool management.
3. User calls `unvote(lpA)` to withdraw their vote — reverts with `PoolNotActive()` because of the check at [4](#0-3) .
4. User calls `vote([lpA], [-1000e18])` to reduce the vote instead — also reverts with `PoolNotActive()` at [5](#0-4) .
5. The user's 1000e18 vlMGP vote allocation and its mirrored stake in `IBribeRewardPool(lpA.rewarder)` remain permanently locked, with no user-callable function able to release it.
