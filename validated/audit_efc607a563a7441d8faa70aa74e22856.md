### Title
`ThresholdKeys::read` accepts self-inconsistent keys — secret share and verification shares are never validated against each other or against the group key - (File: crypto/dkg/src/lib.rs)

### Summary
Analogous to CVE-2019-19729 (bson-objectid returning early when user input claims `_bsontype == ObjectID`, letting malformed objects bypass all validation), `ThresholdKeys::read` deserializes a `ThresholdKeys` object whose internal fields are mutually inconsistent: the `secret_share` is never checked against `verification_shares[i]`, and the verification shares are never checked to be consistent evaluations of a single polynomial / aggregation. The bytes merely need to *claim* the right curve ID and well-formed params — the `_bsontype` marker analog — to be accepted as a valid, usable set of threshold keys. The result is a `ThresholdKeys` value that serializes/parses cleanly and reports an arbitrary attacker-chosen `group_key()`, yet cannot actually sign for that key.

### Finding Description
`ThresholdKeys::read` reads `t`, `n`, `i`, the interpolation discriminant and coefficients, the `secret_share`, and `n` verification shares entirely from the input buffer, then passes them to `ThresholdKeys::new`. [1](#0-0) 

`ThresholdKeys::new` validates only:
- `verification_shares.len() == n`,
- participant indices ≤ `n`,
- `Constant` interpolation only when `t == n`,

and then derives `group_key` as the interpolation of `verification_shares[1..=t]`. [2](#0-1) 

It never performs the fundamental consistency checks:
1. `C::generator() * secret_share == verification_shares[i]` — the holder's own secret share is never bound to the claimed verification share.
2. The `verification_shares` are never checked to form a coherent sharing (e.g., that every size-`t` subset interpolates to the same group key). `group_key` is computed from *only* participants `1..=t`, so shares `t+1..=n` are entirely unbound; an attacker can place arbitrary points there — including points with known discrete logs — and the object still "validates".

This is exactly the bson-objectid shape: the deserializer trusts the object's claimed type/structure and skips semantic validation, so bytes in "arbitrary form" are accepted as a valid key object.

### Impact Explanation
Reachability is explicitly in scope (`ThresholdKeys::read` on untrusted bytes), and the type is stored/loaded by the processor (`read_keys` in `processor/src/key_gen.rs`). Two concrete consequences:

- **Unspendable "received" funds.** A crafted blob yields keys whose `group_key()` equals an arbitrary point (e.g., a victim multisig's real group key, or a key whose secret no one knows). If such keys are adopted for a session, deposits reported against the resulting `external_address`/scanner key are received but can never be signed for: `view()` interpolates the bogus `secret_share`/`verification_shares` independently, so every signing attempt fails `verify` in `AlgorithmSignatureMachine::complete` (or `recover_key` fails its `generator * res == group_key` check). [3](#0-2) 
- **Forged share-verification entries.** Because `verification_shares` for indices `> t` are never bound into `group_key`, an attacker can set `verification_shares[j] = k·G` for a known `k`, making `verify_share` accept shares of a scalar the attacker chose — corrupting blame attribution and share validation without any honest participation.

### Likelihood Explanation
The corruption requires attacker-controlled bytes reaching `ThresholdKeys::read`. Within Serai's own model this is a documented sink for untrusted input, and the processor round-trips serialized keys through its DB (`read_keys`/`save_keys`), where a tampered or substituted blob is accepted without integrity protection. Severity is Medium: exploitation requires a write/substitution path to the serialized keys, but the cryptographic damage (permanently unspendable multisig funds, mis-attributed verification shares) is high once crossed.

### Recommendation
In `ThresholdKeys::new` (which `read` already funnels through), add semantic validation:
- Assert `C::generator() * secret_share == verification_shares[&params.i()]`.
- For `Interpolation::Lagrange`, verify consistency of `verification_shares` beyond participants `1..=t` — e.g., check that at least one other size-`t` subset interpolates to the same `group_key`, or require a proof/registration bound to the DKG session rather than trusting deserialized shares.
- Optionally authenticate stored serialized keys (MAC/versioned envelope) so `read` cannot be fed substitute blobs.

### Proof of Concept
```rust
// Attacker crafts bytes for Secp256k1/Ristretto keys with t = n = 2 (Constant
// interpolation permitted). group_key is derived ONLY from verification_shares
// [1..=t], so we interpolate arbitrary points to hit a target group key G.
let id = C::ID;
let mut buf = vec![];
buf.extend((id.len() as u32).to_le_bytes());
buf.extend(id);
buf.extend(2u16.to_le_bytes()); // t
buf.extend(2u16.to_le_bytes()); // n
buf.extend(1u16.to_le_bytes()); // i = participant 1
buf.push(0);                    // Interpolation::Constant
buf.extend(C::F::ONE.to_repr().as_ref());   // coeff[0]
buf.extend(C::F::ONE.to_repr().as_ref());   // coeff[1]
buf.extend(attacker_secret.to_repr().as_ref()); // secret_share: never checked!

// Constant interpolation factors are c[i-1] = 1 for all participants,
// so group_key = V1 + V2. Choose V1 = k*G (known DL, forgeable share),
// V2 = G_victim - V1. read() succeeds; group_key() == G_victim.
let v1 = C::generator() * attacker_known_scalar;
let v2 = victim_group_key - v1;
buf.extend(v1.to_bytes().as_ref());
buf.extend(v2.to_bytes().as_ref());

let keys = ThresholdKeys::<C>::read(&mut buf.as_slice()).unwrap();
assert_eq!(keys.group_key(), victim_group_key); // claims the victim's key
// Yet generator * secret_share != verification_shares[1] — object is
// semantically invalid; any funds at group_key are unspendable by this holder,
// and verification_shares[2] was attacker-chosen with no binding to the group key.
```

This passes `read` and `ThresholdKeys::new` today because neither checks `generator * secret_share == verification_shares[i]` nor binds `verification_shares[t+1..=n]` into the derived group key — the direct analog of bson-objectid accepting any object bearing a `_bsontype` marker.

Note: I verified the missing consistency checks directly in `crypto/dkg/src/lib.rs` (`ThresholdKeys::new` ~349-391, `read` ~573-631, `view` ~463-533). I did not fully confirm an end-to-end remote byte-delivery path into `read` beyond the DB load in `processor/src/key_gen.rs` (`GeneratedKeysDb::read_keys`), so the Likelihood rating assumes such a path exists per the scope's listing of `ThresholdKeys::read` as an untrusted-input sink.

  pub fn new(
    params: ThresholdParams,
    interpolation: Interpolation<C::F>,
    secret_share: Zeroizing<C::F>,
    verification_shares: HashMap<Participant, C::G>,
  ) -> Result<ThresholdKeys<C>, DkgError> {
    if verification_shares.len() != usize::from(params.n()) {
      Err(DkgError::IncorrectAmountOfVerificationShares {
        n: params.n(),
        shares: verification_shares.len(),
      })?;
    }
    for participant in verification_shares.keys().copied() {
      if u16::from(participant) > params.n() {
        Err(DkgError::InvalidParticipant { n: params.n(), participant })?;
      }
    }

    match &interpolation {
      Interpolation::Constant(_) => {
        if params.t() != params.n() {
          Err(DkgError::InapplicableInterpolation("constant interpolation for keys where t != n"))?;
        }
      }
      Interpolation::Lagrange => {}
    }

    let t = (1 ..= params.t()).map(Participant).collect::<Vec<_>>();
    let group_key =
      t.iter().map(|i| verification_shares[i] * interpolation.interpolation_factor(*i, &t)).sum();

    Ok(ThresholdKeys {
      core: Arc::new(Zeroizing::new(ThresholdCore {
        params,
        interpolation,
        secret_share,
        group_key,
        verification_shares,
      })),
      scalar: C::F::ONE,
      offset: C::F::ZERO,
    })
  }

  pub fn view(&self, mut included: Vec<Participant>) -> Result<ThresholdView<C>, DkgError> {
    if (included.len() < self.params().t.into()) ||
      (usize::from(self.params().n()) < included.len())
    {
      Err(DkgError::IncorrectAmountOfParticipants {
        t: self.params().t,
        n: self.params().n,
        amount: included.len(),
      })?;
    }
    included.sort();
    {
      let mut found = included[0] == self.params().i();
      for i in 1 .. included.len() {
        if included[i - 1] == included[i] {
          Err(DkgError::DuplicatedParticipant(included[i]))?;
        }
        found |= included[i] == self.params().i();
      }
      if !found {
        Err(DkgError::NotParticipating)?;
      }
    }
    {
      let last = *included.last().unwrap();
      if u16::from(last) > self.params().n() {
        Err(DkgError::InvalidParticipant { n: self.params().n(), participant: last })?;
      }
    }

    // The interpolation occurs multiplicatively, letting us scale by the scalar now
    let secret_share_scaled = Zeroizing::new(self.scalar * self.original_secret_share().deref());
    let mut secret_share = Zeroizing::new(
      self.core.interpolation.interpolation_factor(self.params().i(), &included) *
        secret_share_scaled.deref(),
    );

    let mut verification_shares = HashMap::with_capacity(included.len());
    for i in &included {
      let verification_share = self.core.verification_shares[i];
      let verification_share = verification_share *
        self.scalar *
        self.core.interpolation.interpolation_factor(*i, &included);
      verification_shares.insert(*i, verification_share);
    }

    /*
      The offset is included by adding it to the participant with the lowest ID.

      This is done after interpolating to ensure, regardless of the method of interpolation, that
      the method of interpolation does not scale the offset. For Lagrange interpolation, we could
      add the offset to every key share before interpolating, yet for Constant interpolation, we
      _have_ to add it as we do here (which also works even when we intend to perform Lagrange
      interpolation).
    */
    if included[0] == self.params().i() {
      *secret_share += self.offset;
    }
    *verification_shares.get_mut(&included[0]).unwrap() += C::generator() * self.offset;

    Ok(ThresholdView {
      interpolation: self.core.interpolation.clone(),
      scalar: self.scalar,
      offset: self.offset,
      group_key: self.group_key(),
      secret_share,
      original_verification_shares: self.core.verification_shares.clone(),
      verification_shares,
      included,
    })
  }

  /// Read keys from a type satisfying `std::io::Read`.
  pub fn read<R: io::Read>(reader: &mut R) -> io::Result<ThresholdKeys<C>> {
    {
      let different = || io::Error::other("deserializing ThresholdKeys for another curve");

      let mut id_len = [0; 4];
      reader.read_exact(&mut id_len)?;
      if u32::try_from(C::ID.len()).unwrap().to_le_bytes() != id_len {
        Err(different())?;
      }

      let mut id = vec![0; C::ID.len()];
      reader.read_exact(&mut id)?;
      if id != C::ID {
        Err(different())?;
      }
    }

    let (t, n, i) = {
      let mut read_u16 = || -> io::Result<u16> {
        let mut value = [0; 2];
        reader.read_exact(&mut value)?;
        Ok(u16::from_le_bytes(value))
      };
      (
        read_u16()?,
        read_u16()?,
        Participant::new(read_u16()?).ok_or(io::Error::other("invalid participant index"))?,
      )
    };

    let mut interpolation = [0];
    reader.read_exact(&mut interpolation)?;
    let interpolation = match interpolation[0] {
      0 => Interpolation::Constant({
        let mut res = Vec::with_capacity(usize::from(n));
        for _ in 0 .. n {
          res.push(C::read_F(reader)?);
        }
        res
      }),
      1 => Interpolation::Lagrange,
      _ => Err(io::Error::other("invalid interpolation method"))?,
    };

    let secret_share = Zeroizing::new(C::read_F(reader)?);

    let mut verification_shares = HashMap::new();
    for l in (1 ..= n).map(Participant) {
      verification_shares.insert(l, <C as Ciphersuite>::read_G(reader)?);
    }

    ThresholdKeys::new(
      ThresholdParams::new(t, n, i).map_err(io::Error::other)?,
      interpolation,
      secret_share,
      verification_shares,
    )
    .map_err(io::Error::other)
