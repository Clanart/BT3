### Title
`RegisterPointerDisabled` governance flag is not enforced by the `pointer` precompile, allowing CW→ERC pointer creation to bypass the disable switch - (File: `precompiles/pointer/pointer.go`)

### Summary
The EVM module exposes a governance-controlled param, `RegisterPointerDisabled`, meant to globally disable the creation of new CW→ERC pointer contracts. The `MsgServer.RegisterPointer` path correctly checks this flag and rejects requests when it is set. However, the `pointer` precompile (`addNativePointer`, `addCW20Pointer`, `addCW721Pointer`, `addCW1155Pointer`), which is a second, EVM-reachable code path that creates/upserts the exact same pointer contracts, never checks `RegisterPointerDisabled`. This mirrors the reported Vault bug pattern: a privileged "disable" flag is checked on one code path but not on another functionally-equivalent path that reaches the same sensitive state transition.

### Finding Description
`x/evm/keeper/msg_server.go`'s `RegisterPointer` explicitly gates pointer creation on the governance param: [1](#0-0) 

This param is set to `true` via a chain upgrade migration, intended to permanently turn off further pointer registration/creation: [2](#0-1) 

and is exercised/tested only against the `RegisterPointer` message path: [3](#0-2) 

However, the `pointer` precompile at address `0x100b` provides an independent, EVM-transaction-reachable surface (`AddNative`, `AddCW20`, `AddCW721`, `AddCW1155`) that calls the same underlying `UpsertERCNativePointer` / `UpsertERCCW20Pointer` / `UpsertERCCW721Pointer` / `UpsertERCCW1155Pointer` keeper functions to create or upgrade pointer contracts — but it never calls `GetRegisterPointerDisabled` or otherwise checks the param: [4](#0-3) [5](#0-4) [6](#0-5) 

The shared keeper function that both entry points ultimately call is `UpsertERCPointer`, along with its type-specific wrappers: [7](#0-6) [8](#0-7) 

None of `UpsertERCPointer`, `UpsertERCNativePointer`, `UpsertERCCW20Pointer`, `UpsertERCCW721Pointer`, or `UpsertERCCW1155Pointer` enforce `RegisterPointerDisabled` themselves — the check exists solely as a guard clause at the top of `msg_server.go`'s `RegisterPointer`, not in the shared keeper logic. This is architecturally the same class of bug as the Vault report: the "disabled" flag is checked in one caller but the sensitive underlying operation is reachable through a second caller that omits the check.

### Impact Explanation
Once governance disables pointer registration (as it has been permanently set via the v18 module migration `MigrateDisableRegisterPointer`), the intent is that no new CW→ERC pointer contracts can be created/upgraded on-chain. Any EVM transaction sender can still call the `pointer` precompile at `0x100b` to create pointers for native denoms, CW20, CW721, or CW1155 contracts, completely bypassing the governance-enforced disable switch. This undermines a deliberate on-chain policy decision (likely made to freeze the pointer registry, e.g. ahead of a broader pointer/bridge redesign) and could let users create pointer contracts governance intended to block — a governance/permission bypass on a security-relevant migration switch.

### Likelihood Explanation
High likelihood of exploitability given the required conditions (which are already true in production, since migration 18 sets `RegisterPointerDisabled = true`): the precompile is public, requires no special permissions, and is reachable by any account submitting a normal EVM transaction. The bug requires no race condition or edge case — it is a straightforward missing-check.

### Recommendation
Add a `RegisterPointerDisabled` check (via `p.evmKeeper.GetRegisterPointerDisabled(ctx)` or equivalent) at the start of `PrecompileExecutor.Execute` in `precompiles/pointer/pointer.go`, or push the check down into the shared `UpsertERCPointer` keeper function in `x/evm/keeper/pointer_upgrade.go` so both entry points (`MsgServer.RegisterPointer` and the `pointer` precompile) consistently honor the governance flag.

### Proof of Concept
1. Governance/upgrade sets `RegisterPointerDisabled = true` (already the case on production chains per `x/evm/migrations/disable_register_pointer.go`, registered in migration 18 in `x/evm/module.go`).
2. Any account submits an EVM transaction calling `IPointer(0x100b).addCW20Pointer(cwAddr)` (or `addNativePointer`/`addCW721Pointer`/`addCW1155Pointer`).
3. `PrecompileExecutor.AddCW20` executes without any `RegisterPointerDisabled` check and calls `p.evmKeeper.UpsertERCCW20Pointer`, successfully deploying/upgrading a pointer contract — despite governance having disabled pointer registration via `MsgRegisterPointer`.

func (p PrecompileExecutor) AddNative(ctx sdk.Context, method *ethabi.Method, caller common.Address, args []interface{}, value *big.Int, evm *vm.EVM, hooks *tracing.Hooks) (ret []byte, remainingGas uint64, err error) {
	if err := pcommon.ValidateNonPayable(value); err != nil {
		return nil, 0, err
	}
	if err := pcommon.ValidateArgsLength(args, 1); err != nil {
		return nil, 0, err
	}
	token := args[0].(string)
	metadata, metadataExists := p.bankKeeper.GetDenomMetaData(ctx, token)
	if !metadataExists {
		return nil, 0, fmt.Errorf("denom %s does not have metadata stored and thus can only have its pointer set through gov proposal", token)
	}
	name := metadata.Name
	symbol := metadata.Symbol
	var decimals uint8
	for _, denomUnit := range metadata.DenomUnits {
		if denomUnit.Exponent > uint32(decimals) && denomUnit.Exponent <= math.MaxUint8 {
			decimals = uint8(denomUnit.Exponent)
			name = denomUnit.Denom
			symbol = denomUnit.Denom
			if len(denomUnit.Aliases) > 0 {
				name = denomUnit.Aliases[0]
			}
		}
	}
	contractAddr, err := p.evmKeeper.UpsertERCNativePointer(ctx, evm, token, utils.ERCMetadata{Name: name, Symbol: symbol, Decimals: decimals})
	if err != nil {
		return nil, 0, err
	}

	ret, err = method.Outputs.Pack(contractAddr)
	remainingGas = pcommon.GetRemainingGas(ctx, p.evmKeeper)
	return
}

func (k *Keeper) UpsertERCPointer(
	ctx sdk.Context, evm *vm.EVM, typ string, args []interface{}, getter PointerGetter, setter PointerSetter,
) (contractAddr common.Address, err error) {
	pointee := args[0].(string)
	evmModuleAddress := k.GetEVMAddressOrDefault(ctx, k.AccountKeeper().GetModuleAddress(types.ModuleName))

	var bin []byte
	bin, err = artifacts.GetParsedABI(typ).Pack("", args...)
	if err != nil {
		panic(err)
	}
	bin = append(artifacts.GetBin(typ), bin...)
	// GetDeploymentCode / Create take EVM snapshots that Freeze() Multistore layers.
	// Exists-lookup and commits must use the live unfrozen top (sdb.Ctx): cachekv
	// forbids writing a frozen layer, and same-tx readers that skip frozen-empty
	// parents would miss those writes. The precompile Prepare `ctx` is that top at
	// Prepare time, but is frozen once this Upsert snapshots. Always attach the
	// caller's gas meter (finite precompile meter in deliver) — sdb.Ctx() alone
	// carries the infinite EVM meter.
	sdb := state.GetDBImpl(evm.StateDB)
	liveCtx := func() sdk.Context {
		if sdb == nil {
			return ctx
		}
		return sdb.Ctx().WithGasMeter(ctx.GasMeter())
	}
	existingAddr, _, exists := getter(liveCtx(), pointee)
	suppliedGas := k.getEvmGasLimitFromCtx(ctx)
	var remainingGas uint64
	if exists {
		var ret []byte
		contractAddr = existingAddr
		ret, remainingGas, err = evm.GetDeploymentCode(evmModuleAddress, bin, suppliedGas, utils.Big0, existingAddr)
		if err != nil {
			return
		}
		// Only write on success: a failed GetDeploymentCode can leave ret as nil or
		// revert data, which must not clobber live pointer bytecode (even transiently).
		writeCtx := liveCtx()
		k.SetCode(writeCtx, contractAddr, ret)
		if sdb != nil {
			sdb.RefreshCodeCache(contractAddr, ret)
		}
	} else {
		_, contractAddr, remainingGas, err = evm.Create(evmModuleAddress, bin, suppliedGas, uint256.NewInt(0))
	}
	if err != nil {
		return
	}
	ctx.GasMeter().ConsumeGas(k.GetCosmosGasLimitFromEVMGas(ctx, suppliedGas-remainingGas), "ERC pointer deployment")
	if err = setter(liveCtx(), pointee, contractAddr); err != nil {
		return
	}
	ctx.EventManager().EmitEvent(sdk.NewEvent(
		types.EventTypePointerRegistered, sdk.NewAttribute(types.AttributeKeyPointerType, typ),
		sdk.NewAttribute(types.AttributeKeyPointerAddress, contractAddr.Hex()), sdk.NewAttribute(types.AttributeKeyPointee, pointee)))
	return
}
