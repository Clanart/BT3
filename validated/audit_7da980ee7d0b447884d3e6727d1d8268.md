### Title
Auction bid pool accepts bids without verifying searcher's on-chain deposit balance, enabling settlement-time DoS - (File: kaiax/auction/impl/bid_pool.go)

### Summary
`BidPool.validateBid()` — the function that decides whether a submitted `auction_submitBid` bid becomes an accepted, block-reserving "winner" bid — never checks the searcher's deposited balance in the `AuctionEntryPoint` contract before admitting the bid. This mirrors the JOJO `requestWithdraw()` bug class: a state-affecting commitment (reserving a winner slot for a block/sender, and later scheduling on-chain execution of the bid) is accepted purely on signature and format checks, with no verification that the underlying value (the searcher's deposit) actually exists to back it.

### Finding Description
`validateBid` performs six checks: duplicate bid, existing-winner conflict, block-number window, `bid.Bid > 0`, data-size limit, gas-limit limit, and searcher/auctioneer signatures. [1](#0-0) 

None of these checks query the searcher's deposit balance held in the `AuctionEntryPoint` system contract, even though such a view function exists and is exposed precisely for this purpose: [2](#0-1) 

Once `validateBid` passes, `AddBid` inserts the bid into `bidMap`/`bidTargetMap`/`bidWinnerMap`, marking the sender as the block's winner for that target tx: [3](#0-2) 

The winner-slot mechanic then blocks other bids from the same sender for that block unless they are identical, via `senderHasDifferentWinner`: [4](#0-3) 

Because deposit is never checked at admission time, a searcher can submit a validly signed, high bid value with zero or insufficient on-chain deposit. The bid pool will accept it, reserve the winner slot for that block, and the block-building pipeline will generate the corresponding bundle for it (per README's block-building rules) since a bid found in the pool is unconditionally converted into a bundle: [5](#0-4) 

At actual execution time, `AuctionEntryPoint.call()` is expected to take the bid from the searcher's deposit before executing the searcher's call (per the KIP-249 mock's commented-out intended flow: "Take bid first" then execute): [6](#0-5) 

If the deposit is insufficient, that on-chain call will revert/fail, but the bid pool has already reserved that sender's winner slot for the block and already excluded legitimate bidder attempts to overwrite it via `ErrBidSenderExists`. This produces a class of value-desync/DoS identical in structure to the JOJO report: an unprivileged, low-cost transaction (an RPC bid submission with signatures but no real backing funds) reserves a resource/commitment slot that is never validated against actual balance, and the mismatch is discovered only at settlement time — causing failed or reverted on-chain auction execution and blocking the slot from legitimate searchers.

### Impact Explanation
An attacker (any entity able to obtain a validly signed searcher bid and forward it to `auction_submitBid` — note the auctioneer signs, but a searcher/attacker still fully controls submission and can use a stale/never-funded deposit, or drain their deposit after obtaining an auctioneer signature but before the target block) can repeatedly occupy winner slots for target blocks without possessing sufficient deposit. This:
- Causes `AuctionEntryPoint.call()` execution to fail/revert at block-building/settlement time, wasting the reserved bundle slot.
- Blocks other legitimate bids for the same sender/block due to `ErrBidSenderExists`, denying honest searchers/auction outcomes for that block (auction settlement DoS).
- Creates a divergence between the bid pool's view of "who owns this block's auction slot" and the true on-chain economic backing, analogous to the off-chain/on-chain desynchronization described in the source report.

This satisfies "acceptance of an invalid transaction" — the bid pool's admission logic (a pre-inclusion validation gate analogous to `requestWithdraw`) accepts a bid it should reject given no balance backing, and the state divergence causes failed settlement.

### Likelihood Explanation
The `auction_submitBid` RPC endpoint is reachable by any external caller who can obtain a valid searcher signature and (as per current design) an auctioneer signature: [7](#0-6) 
Deposits are checked nowhere in the Go module (`bid_pool.go` or `api.go`), and this is a per-bid, single-transaction/single-RPC-call reachable path with no privileged role required beyond obtaining the auctioneer co-signature (which the KIP-249 protocol design already assumes is obtainable by any legitimate searcher going through the off-chain auction flow, exactly as the JOJO scenario assumed a legitimate trader interacting with the off-chain matching engine).

### Recommendation
Add a deposit-balance check to `validateBid` (or as a `GetCheckBalance`-style hook similar to the gasless module's design) that calls `AuctionEntryPoint.getNoncesAndDeposits([bid.Sender])` and rejects bids whose declared `bid.Bid` (plus expected gas cost) exceeds the searcher's current on-chain deposit, mirroring how `checkBalanceForApprove`/`checkBalanceForSwap` validate the gasless module's transactions before promotion: [8](#0-7) 

### Proof of Concept
1. Attacker obtains a valid `Bid` (with correct `SearcherSig` and a valid `AuctioneerSig`, per current KIP-249 flow) declaring `bid.Bid = X` for `blockNumber = N`, while their actual `AuctionEntryPoint` deposit is `0` (or less than `X`).
2. Attacker calls `auction_submitBid` with this bid; `AddBid` → `validateBid` passes all six checks (none check deposit) and the bid is inserted, reserving the winner slot for `(N, attacker)` in `bidWinnerMap`. [1](#0-0) 
3. Any subsequent, differing bid from the same sender for block `N` is rejected with `ErrBidSenderExists`, blocking legitimate use of that slot. [4](#0-3) 
4. At block `N`, the block-building pipeline generates the bundle for this bid and forwards it for execution; `AuctionEntryPoint.call()` (KIP-249) attempts to take the bid from the attacker's deposit and fails/reverts due to insufficient deposit, wasting the reserved slot and causing the intended searcher call to not execute — an on-chain settlement DoS with no funds ever at risk for the attacker.

// AddBid adds a bid to the bid pool.
// Required mutex is locked in each function.
func (bp *BidPool) AddBid(bid *auction.Bid) (common.Hash, error) {
	if atomic.LoadUint32(&bp.running) == 0 {
		return common.Hash{}, auction.ErrAuctionPaused
	}

	if err := bp.validateBid(bid); err != nil {
		return common.Hash{}, err
	}

	if err := bp.insertBid(bid); err != nil {
		return common.Hash{}, err
	}

	gasLimit, err := bp.getBidTxGasLimit(bid)
	if err != nil {
		return common.Hash{}, err
	}
	bid.SetGasLimit(gasLimit)

	bp.newBidCh <- bid

	return bid.Hash(), nil
}

// senderHasDifferentWinner reports whether a different bid from the same sender
// already exists in the winner list for this block. Caller must hold bidMu.
func (bp *BidPool) senderHasDifferentWinner(bid *auction.Bid) bool {
	hash, ok := bp.bidWinnerMap[bid.BlockNumber][bid.Sender]
	if !ok {
		return false
	}
	return !bid.Equals(bp.bidMap[hash])
}

func (bp *BidPool) validateBid(bid *auction.Bid) error {
	blockNumber := bid.BlockNumber

	bp.bidMu.RLock()

	// Check if the auction tx is already in the pool.
	if _, ok := bp.bidMap[bid.Hash()]; ok {
		bp.bidMu.RUnlock()
		return auction.ErrBidAlreadyExists
	}

	// 1. The `bid.Sender` must not be in the winner list of the same block number if the new bid isn't equal to the previous bid.
	if bp.senderHasDifferentWinner(bid) {
		bp.bidMu.RUnlock()
		return auction.ErrBidSenderExists
	}
	bp.bidMu.RUnlock()

	curBlock := bp.Chain.CurrentBlock()
	if curBlock == nil {
		return auction.ErrBlockNotFound
	}

	// 2. The `bid.BlockNumber` must be in range of `[currentBlockNumber + 1, currentBlockNumber + allowFutureBlock]`.
	curNum := curBlock.NumberU64()
	if blockNumber <= curNum || blockNumber > curNum+allowFutureBlock {
		return auction.ErrInvalidBlockNumber
	}

	// 3. The `bid.Bid` must be greater than 0.
	if bid.Bid.Sign() <= 0 {
		return auction.ErrZeroBid
	}

	// 4. The data size must be less than the maximum limit.
	if uint64(len(bid.Data)) > BidTxMaxDataSize {
		return auction.ErrExceedMaxDataSize
	}

	// 5. The gas limit must be less than the maximum limit.
	if bid.CallGasLimit > BidTxMaxCallGasLimit {
		return auction.ErrExceedMaxCallGasLimit
	}

	// 6. The `bid.SearcherSig` and `bid.AuctioneerSig` must be valid.
	if err := bp.validateBidSigs(bid); err != nil {
		return err
	}

	return nil
}

// GetNoncesAndDeposits is a free data retrieval call binding the contract method 0x0339ed37.
//
// Solidity: function getNoncesAndDeposits(address[] searchers) view returns(uint256[] nonces_, uint256[] deposits_)
func (_IAuctionEntryPoint *IAuctionEntryPointCaller) GetNoncesAndDeposits(opts *bind.CallOpts, searchers []common.Address) (struct {
	Nonces   []*big.Int
	Deposits []*big.Int
}, error) {
	var out []interface{}
	err := _IAuctionEntryPoint.contract.Call(opts, &out, "getNoncesAndDeposits", searchers)

	outstruct := new(struct {
		Nonces   []*big.Int
		Deposits []*big.Int
	})
	if err != nil {
		return *outstruct, err
	}

	outstruct.Nonces = *abi.ConvertType(out[0], new([]*big.Int)).(*[]*big.Int)
	outstruct.Deposits = *abi.ConvertType(out[1], new([]*big.Int)).(*[]*big.Int)

	return *outstruct, err

}

func (api *AuctionAPI) SubmitBid(ctx context.Context, bidInput BidInput) RPCOutput {
	numBidRequestCounter.Inc(1)
	if api.a.IsDisabled() {
		return makeRPCOutput(EMPTY_HASH, auction.ErrAuctionDisabled)
	}

	//  1. directly send target transaction
	targetTx, errTxDecode := toTx(bidInput.TargetTxRaw)
	if errTxDecode != nil {
		return makeRPCOutput(EMPTY_HASH, errTxDecode)
	}
	if targetTx.Hash() != bidInput.TargetTxHash {
		return makeRPCOutput(EMPTY_HASH, auction.ErrInvalidTargetTxHash)
	}
	errTargetTxSend := api.a.Backend.SendTx(ctx, targetTx)
	// ignore known transaction related errors against target tx validation
	if errTargetTxSend != nil && !(strings.HasPrefix(errTargetTxSend.Error(), "known transaction:") || errors.Is(errTargetTxSend, gasless_impl.ErrUnableToAddKnownBundleTx)) {
		return makeRPCOutput(EMPTY_HASH, errTargetTxSend)
	}

	// 2. add bid
	bid := ToBid(bidInput)
	bidHash, errValidateBid := api.a.bidPool.AddBid(bid)
	return makeRPCOutput(bidHash, errValidateBid)

	}
}
