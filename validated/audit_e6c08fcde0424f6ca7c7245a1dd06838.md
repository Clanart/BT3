### Title
Stale `isActive` flag after `removePool()` allows unprivileged users to vote into phantom pools, permanently diluting `totalVlMgpInVote` and corrupting `castVotes()` proportional allocation - (File: wombat/WombatBribeManager.sol)

### Summary
`removePool()` only removes a pool's address from the `pools` array but never clears `poolInfos[_lp].isActive`, leaving the mapping entry "active" forever. Any unprivileged user can then call `vote()` on that removed pool address, which passes the `isActive` check, increases `pool.totalVoteInVlmgp` and the global `totalVlMgpInVote`, but is never reconciled because `castVotes()` only iterates the `pools` array, permanently inflating the denominator used to compute every remaining active pool's `targetVote`.

### Finding Description
`removePool()` swaps the last element into `_index` and pops the array, but does not touch `poolInfos[_lp]`: [1](#0-0) 

`vote()` only checks `poolInfos[_lps[i]].isActive`, which remains `true` for a removed pool, so the call succeeds and mutates state exactly as for any live pool - incrementing `pool.totalVoteInVlmgp`, `userVotedForPoolInVlmgp`, and (when caller isn't `delegatedPool`) `userTotalVotedInVlmgp` and the global `totalVlMgpInVote`: [2](#0-1) 

`castVotes()` computes each active pool's on-chain target using `totalVlMgpInVote` as the shared denominator, but it only loops over `pools.length`, i.e., pools still present in the array: [3](#0-2) 

Because the phantom pool's `totalVoteInVlmgp` contributed to `totalVlMgpInVote` but is never included in the `_pools`/`votes`/`rewarders` arrays passed to `wombatStaking.vote()`, that portion of `totalVlMgpInVote` has no corresponding on-chain vote allocation. Every remaining active pool's `targetVote = targetVoteInLMGP * totalVotes() / totalVlMgpInVote` is computed with an inflated denominator, permanently under-allocating veWOM votes to all real pools relative to what locked MGP holders are entitled to.

There is no mechanism to remove the phantom entry: `unvote()` explicitly requires `pool.isActive == true` to proceed, so it works fine on the stale entry, but nothing forces or triggers this cleanup, and since it can be re-populated by any voter after being unvoted, the pool remains a permanent phantom sink as long as `poolInfos[_lp].isActive` stays true (it is never set to false anywhere in the contract, since `removePool` never does it and no other function does).

### Impact Explanation
This is a governance/voting-result manipulation and permanent value-dilution bug (Immunefi "Governance voting result manipulation" / permanent yield-dilution class). Once a pool is removed from `pools`, any voter directing MGP votes at it permanently reduces the effective veWOM allocation given to all genuinely active pools, because the accounting denominator (`totalVlMgpInVote`) no longer matches the votes actually forwarded through `wombatStaking.vote()`. This corrupts reward/bribe distribution proportionality for all users voting on real pools, not just the attacker, and the corruption is permanent (no code path clears the stale `isActive` flag or removes the phantom's contribution from `totalVlMgpInVote`).

### Likelihood Explanation
Requires only a normal, non-malicious governance action (`removePool`) which is a routine pool-management operation, not an abuse of privilege — the resulting stale state is a straightforward consequence of the code's design. After that, any unprivileged locked-MGP holder can trigger the corruption at zero extra cost by simply calling `vote()` targeting the address of the removed pool, which they can discover from prior `AddPool` events or on-chain history. It is fully repeatable by any number of users and requires no capital beyond an existing vlMGP lock.

### Recommendation
Have `removePool()` also set `poolInfos[_lp].isActive = false` before removing it from the `pools` array, and/or have `castVotes()` reconcile/zero out `totalVoteInVlmgp` for any pool being deactivated (subtracting its contribution from `totalVlMgpInVote`) so stale entries can never accept new votes or continue diluting the shared denominator.

### Proof of Concept
Foundry test plan:
1. Deploy `WombatBribeManager` with two pools A and B via `addPool`, lock MGP for two users (attacker and victim).
2. Attacker votes for pool A: `vote([A], [+100e18])`.
3. Owner calls `removePool(indexOfA)` to remove A from `pools` (index-swap-and-pop) — confirm `isPoolActive(A)` still returns `true`.
4. Attacker votes again for pool A (still passes `isActive` check): `vote([A], [+50e18])`; assert `poolInfos[A].totalVoteInVlmgp` and `totalVlMgpInVote` increase.
5. Victim votes for pool B: `vote([B], [+100e18])`.
6. Call `castVotes(false)`; assert `_pools`/`votes` arrays passed to `wombatStaking.vote()` never include A, and compute expected `targetVote` for B using the actual, uninflated `totalVlMgpInVote` (excluding A's 150e18) vs. the contract's actual (inflated) computation — assert B receives a strictly smaller `targetVote` than it should, demonstrating permanent dilution caused entirely by the unreachable phantom pool A.

        if (_lps.length != _deltas.length)
            revert LengthMismatch();

        uint256 length = _lps.length;
        int256 totalUserVote;

        for (uint256 i; i < length; i++) {
            Pool storage pool = poolInfos[_lps[i]];
            if (!pool.isActive)
                revert PoolNotActive();
            int256 delta = _deltas[i];
            totalUserVote += delta;
            if (delta != 0) {
                if (delta > 0) {
                    pool.totalVoteInVlmgp += uint256(delta);
                    userVotedForPoolInVlmgp[msg.sender][pool.poolAddress] += uint256(delta);
                    IBribeRewardPool(pool.rewarder).stakeFor(msg.sender, uint256(delta));
                } else {
                    pool.totalVoteInVlmgp -= uint256(-delta);
                    userVotedForPoolInVlmgp[msg.sender][pool.poolAddress] -= uint256(-delta);
                    IBribeRewardPool(pool.rewarder).withdrawFor(msg.sender, uint256(-delta), false);
                }
            }
        }

        if (msg.sender != delegatedPool) {
            if (totalUserVote > 0) {
                userTotalVotedInVlmgp[msg.sender] += uint256(totalUserVote);

                totalVlMgpInVote -= uint256(-totalUserVote);
            }
        }

        if (userTotalVotedInVlmgp[msg.sender] > getUserVotable(msg.sender))
            revert NotEnoughVote();
    }
