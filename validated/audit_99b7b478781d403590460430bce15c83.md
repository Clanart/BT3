### Title
Missing Recency Check on Shopify App Proxy Signed Requests Enables Indefinite Replay - ([File: lib/shopify_app/controller_concerns/app_proxy_verification.rb])

### Summary
`ShopifyApp::AppProxyVerification#query_string_valid?` validates only the HMAC signature of an app-proxy request and never checks the `timestamp` query parameter for staleness, so a captured, validly-signed app-proxy request can be replayed at any point in the future and will still be accepted as authentic.

### Finding Description
The `AppProxyVerification` concern is used to authenticate requests forwarded by Shopify's App Proxy to the app's backend. `verify_proxy_request` calls `query_string_valid?`, which recomputes the HMAC over the query string (including the `timestamp` parameter as signed data) and compares it to the supplied `signature` using `ActiveSupport::SecurityUtils.secure_compare`: [1](#0-0) 

The `timestamp` value is only used as one of many fields folded into the HMAC input via `calculated_signature` — it is never read back out and compared against the current time to reject stale requests. Once a valid `shop`, `path_prefix`, `timestamp`, and `signature` combination is observed (e.g., via server logs, browser history/referrer leakage, proxy/CDN logs, or a network intermediary), that exact query string remains permanently valid and can be replayed against the app's proxy endpoints indefinitely, because the signature check alone will always pass regardless of how old the `timestamp` is.

This mirrors the reported bug class: data (here, a signed request) is accepted purely on the basis of an integrity check (HMAC) without any accompanying recency/freshness check, allowing stale/captured authorization material to be reused as if it were fresh.

### Impact Explanation
An attacker who obtains one previously-valid, Shopify-signed app-proxy request URL (no privileged access required — it can be leaked via logs, Referer headers, browser history sync, shared links, etc.) can replay that exact request against the app's app-proxy-protected endpoints at any later time. Depending on what the app-proxy route does (order/customer lookups, cart mutations, or other shop-scoped actions), this enables unauthorized cross-time reuse of a merchant/customer-scoped signed request, effectively bypassing the intended one-time/short-lived nature of proxy authentication.

### Likelihood Explanation
Exploitation requires an attacker to first capture one legitimately signed app-proxy query string. This is plausible via common leak channels (referrer leakage to third-party resources loaded by the proxied page, access/CDN logs, browser history synchronization, or shared bookmarks), and once captured, replay requires no cryptographic effort — the same URL is reusable forever since the concern never enforces a validity window on `timestamp`.

### Recommendation
In `query_string_valid?` (or a new before_action), after signature verification succeeds, parse `query_hash["timestamp"]`, and reject the request if it falls outside a small acceptable window (e.g., a few minutes) relative to the current time, similar to Shopify's own webhook/OAuth timestamp handling. Return `head(:forbidden)` for both invalid signatures and stale timestamps.

### Proof of Concept
1. Trigger a legitimate Shopify App Proxy request to the app (e.g., a merchant visits `https://shop.myshopify.com/apps/my-app?...&timestamp=T&signature=S`).
2. Capture the full query string from server access logs, a referrer header on an outbound request from the proxied page, or browser history.
3. At any later time T' (minutes, hours, or days after T), replay the exact same query string against the app's app-proxy route.
4. `AppProxyVerification#query_string_valid?` recomputes the HMAC over the unchanged query parameters (including the old `timestamp`) and it matches `signature`, so the request is accepted as valid even though it is stale — demonstrating the absence of a recency check as described in `lib/shopify_app/controller_concerns/app_proxy_verification.rb:11-37`.

```ruby
    def verify_proxy_request
      head(:forbidden) unless query_string_valid?(request.query_string)
    end

    private

    def query_string_valid?(query_string)
      query_hash = Rack::Utils.parse_query(query_string)

      signature = query_hash.delete("signature")
      return false if signature.nil?

      ActiveSupport::SecurityUtils.secure_compare(
        calculated_signature(query_hash),
        signature,
      )
    end

    def calculated_signature(query_hash_without_signature)
      sorted_params = query_hash_without_signature.collect { |k, v| "#{k}=#{Array(v).join(",")}" }.sort.join

      OpenSSL::HMAC.hexdigest(
        OpenSSL::Digest.new("sha256"),
        ShopifyApp.configuration.secret,
        sorted_params,
      )
    end
```
