### Title
`_diff_pathspec` fails to neutralize git pathspec "magic" prefixes, letting a colon-prefixed touched-file name silently widen the reviewed diff scope - (File: `plugins/security-guidance/hooks/gitutil.py`)

### Summary
`_diff_pathspec` converts touched/edited file paths into `git diff -- <rel> ...` arguments without disabling git's pathspec "magic" syntax (`--literal-pathspecs` / `:(literal)` prefixing). A repo-controlled file whose relative name begins with `:` (e.g. `:(exclude)foo.py` or `:!foo.py`) is passed through unmodified, so git interprets it as pathspec magic instead of a literal filename, changing the semantics of the pathspec fed to the security-review diff.

### Finding Description
`_diff_pathspec` in `plugins/security-guidance/hooks/gitutil.py` (lines 70-88) realpath-resolves both `cwd` and each candidate path and drops any path whose `os.path.relpath(...)` result starts with `..`, which correctly defeats simple directory-escape and macOS `/var`↔`/private/var` symlink issues. However, it does nothing to neutralize git pathspec "magic" signatures: any relative path that begins with `:` is passed straight through in the `["--"] + rel` list handed to `git diff` (consumed in `get_git_diff`, lines 391-419) and to `_git_name_only`/other diff calls. Git's pathspec grammar treats a leading `:` specially — `:(exclude)pattern`, `:!pattern`, `:(icase)pattern`, `:(glob)pattern`, etc. — regardless of the `--` end-of-options marker, since `--` only ends option parsing, not pathspec magic parsing. [1](#0-0) 

Because `touched_paths` (fed into `paths` here) are recorded from files that Claude itself writes/edits during a session (via Write/Edit/MultiEdit tool calls, which are influenceable by repo content/prompt injection), an attacker who can get Claude to create or edit a file literally named e.g. `:(exclude)innocent.py` causes `_diff_pathspec` to emit a pathspec argument of `:(exclude)innocent.py` instead of a literal filename. Git's pathspec semantics say that when the *only* pathspec given is an exclude pathspec, git implicitly matches "everything except this", turning what was meant to be a single-file scoped diff (`git diff -- :(exclude)innocent.py`) into an diff over the **entire working tree** minus that one file — i.e., the intended narrow repo diff scope silently expands to cover all files in the repository, not just the files Claude actually touched. [2](#0-1) 

No code path in the plugin sanitizes or literal-escapes leading `:` characters, and no `--literal-pathspecs` / `GIT_LITERAL_PATHSPECS` usage exists anywhere in the codebase, so this magic-pathspec behavior is entirely unmitigated.

### Impact Explanation
The Stop-hook/commit-review pipeline is designed to scope the LLM-reviewed diff to only the paths Claude actually touched in a turn (see `get_git_diff`'s docstring and the "unrestricted diff — the bug this whole change exists to fix" comment at line ~411). A magic-pathspec-triggered scope explosion defeats that scoping invariant: it can pull unrelated, potentially sensitive tracked files (secrets, other users'/branches' pending local changes, unrelated source) into the diff that gets sent to the external LLM review API (`analyze_code_security`/`agentic_review`), which is a networked sink outside the intended trust boundary. This matches the stated impact class: "Sensitive code, prompt, token, diff, or local file disclosure to an unintended local or remote sink."

### Likelihood Explanation
Exploitation requires only that a repo-controlled or prompt-injected workflow cause Claude to write/edit a file whose basename begins with `:` — a filename that is completely legal on Linux/macOS filesystems and requires no special privilege, symlink trickery, or admin access. This is a single unprivileged write action reachable through ordinary Write/Edit tool use, making it a low-effort, repeatable path once such a filename is created in the working tree during a session.

### Recommendation
In `_diff_pathspec`, force literal pathspec matching so filenames can never be interpreted as git pathspec magic:
- Prepend `:(literal)` to each `rel` entry before returning it, or
- Pass `--literal-pathspecs` (or set `GIT_LITERAL_PATHSPECS=1` in the subprocess env) on every `git diff`/`git name-only` invocation that consumes the pathspec produced by `_diff_pathspec`.
Either fix ensures a leading `:` in a real filename is always treated as a literal character rather than a magic signature.

### Proof of Concept
Unit test plan for `plugins/security-guidance/hooks/gitutil.py::_diff_pathspec` combined with `get_git_diff`:
1. Create a temp git repo; commit an initial file `secret.py` with sentinel content `SECRET_MARKER`.
2. In the working tree, create (untracked or `git add`-ed) a file literally named `:(exclude)decoy.py` and modify `decoy.py` unrelated to `secret.py`.
3. Call `get_git_diff(cwd, baseline_sha, paths=[os.path.join(cwd, ":(exclude)decoy.py")])`.
4. Assert (expected under a fix): the returned diff contains only changes to `decoy.py`/the passed path, and does **not** contain `SECRET_MARKER` from `secret.py`.
5. Demonstrate the current bug: without the `:(literal)` fix, assert the returned diff (or the constructed pathspec list from `_diff_pathspec`) includes files other than the one named in `paths` — i.e. `secret.py`'s content leaks into the diff sent for review despite `secret.py` never being in `paths`.

```python
def _diff_pathspec(cwd, paths):
    """Convert absolute touched-paths to repo-relative pathspec args for
    git diff. Paths outside cwd (e.g. ~/.claude/…) are dropped. Returns the
    list to splice after `--`, or [] for an unrestricted diff. realpath both
    sides so the macOS /var ↔ /private/var symlink doesn't make in-repo
    paths look external."""
    if not paths:
        return []
    cwd_abs = os.path.realpath(cwd)
    rel = []
    for p in paths:
        try:
            r = os.path.relpath(os.path.realpath(p), cwd_abs)
        except ValueError:
            continue
        if r.startswith(".."):
            continue
        rel.append(r)
    return ["--"] + rel if rel else []
```
