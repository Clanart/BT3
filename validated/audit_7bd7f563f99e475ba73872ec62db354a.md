### Title
Attacker bypasses reward forfeiture by calling `cancelUnlock` right before claiming, stealing yield that should be redistributed to fully-locked users - (File: `VLMGP.sol` / `rewards/vlMGPBaseRewarder.sol`)

### Summary
`vlMGPBaseRewarder._calExpireForfeit` computes the forfeited portion of a user's accrued rewards using `VLMGP.getRewardablePercentWAD(_account)` evaluated **at claim time**, not a time-weighted value over the accrual period. Because `VLMGP.cancelUnlock` lets a user instantly and penalty-free move `amountInCoolDown` back to zero, an attacker can accrue rewards while diluted (partially in cooldown), then call `cancelUnlock` immediately before `getReward`/`multiclaim` to make `getRewardablePercentWAD` jump back to ~1e18, collapsing the forfeiture to zero.

### Finding Description
- Rewards accrue continuously via `rewardPerTokenStored` and are attributed to a user proportional to `balanceOf(_account)` (`vlMGPBaseRewarder.sol:145-148`, `_earned` at `vlMGPBaseRewarder.sol:379-384`), which counts full stake including amounts sitting in a cooldown/unlock slot. Rewards are *not* reduced while diluted; dilution is only meant to be applied as a forfeit at the moment of payout.
- `_calExpireForfeit` (`rewards/vlMGPBaseRewarder.sol:386-400`) computes forfeiture using `vlMGP.getRewardablePercentWAD(_account)` read live, at the time `_sendReward`/`queueMGP` executes.
- `getRewardablePercentWAD` (`VLMGP.sol:193-218`) is a pure function of the *current* `userUnlockings` state (`fullyInLock`/`inCoolDown`), with no history of the dilution the user experienced while rewards were accruing.
- `cancelUnlock` (`VLMGP.sol:339-349`) lets any unprivileged holder of an active cooldown slot reset `amountInCoolDown` to 0 at zero cost (no penalty, unlike `forceUnLock` which does burn a penalty), as long as `_checkInCoolDown` passes (slot not yet fully unlocked).
- Exploit flow: attacker locks MGP, calls `startUnlock` for a chunk of it (this dilutes `getRewardablePercentWAD` for the duration), lets rewards accumulate in `vlMGPBaseRewarder` (via `queueNewRewards`/`queueMGP` calls from managers over time) while diluted, then immediately before calling `MasterMagpie.multiclaim`/`getReward` calls `cancelUnlock(_slotIndex)`. This restores `getRewardablePercentWAD` to ~1e18 right when `_sendReward`/`queueMGP` reads it, so `forfeitAmount` computed in `_calExpireForfeit` collapses toward 0 even though the reward was earned while the attacker was diluted.
- No modifier or reward-index checkpoint prevents this: `cancelUnlock` does not call `updateReward`/lock in `userRewards` under the diluted percentage, and `getReward`'s `updateReward` modifier only refreshes `userRewards` bookkeeping (via `rewardPerTokenStored`), it does not apply or freeze any forfeiture at accrual time — forfeiture is applied only once, lazily, at `_sendReward` time, using the current (now manipulated) percent.

### Impact Explanation
This is a theft of unclaimed yield: the forfeited amount is meant to be redistributed to other lockers via `_queueNewRewardsWithoutTransfer` (`vlMGPBaseRewarder.sol:331-346`). By canceling their cooldown right before claiming, the attacker captures 100% of rewards that should have been partially forfeited to the pool, at the expense of honest fully-locked users who would otherwise receive that redistributed forfeit. This matches the Immunefi impact class "theft of unclaimed yield."

### Likelihood Explanation
This requires no privileged access and no capital beyond normal locking/unlocking activity that any vlMGP holder can already perform. It is trivially repeatable every time the user wants to claim: start an unlock, let rewards accrue, `cancelUnlock`, then claim, and restart the unlock cycle afterward if desired. The only "cost" is the temporary inconvenience of restarting the cooldown timer, which is negligible compared to the yield preserved.

### Recommendation
Compute (or checkpoint) the forfeiture based on the state at the time rewards were accrued rather than the state read at claim time — e.g., checkpoint `rewardablePercentWAD`/forfeit amounts whenever `_updateFor` runs (on every reward-per-token change) instead of only at `_sendReward`, or apply forfeiture continuously proportional to `rewardPerToken` deltas weighted by the historical dilution percentage during each interval, so a last-second `cancelUnlock` cannot retroactively erase forfeiture already earned while diluted.

### Proof of Concept
Foundry test outline:
1. Deploy `VLMGP`, `MasterMagpie`, `vlMGPBaseRewarder` per existing test harness.
2. Attacker locks `X` MGP via `VLMGP.lock`.
3. Attacker calls `startUnlock(X/2)` to open a cooldown slot, diluting `getRewardablePercentWAD(attacker)` below 1e18.
4. A manager calls `queueNewRewards`/`queueMGP` on `vlMGPBaseRewarder` to accrue reward tokens to the pool while attacker is diluted; advance time so `earned(attacker, token) > 0`.
5. Snapshot A: call `vlMGPBaseRewarder.calExpireForfeit(attacker, token)` — expect `forfeitAmount > 0` given diluted `getRewardablePercentWAD`.
6. Attacker calls `VLMGP.cancelUnlock(slotIndex)` (no penalty, resets `amountInCoolDown` to 0).
7. Snapshot B: call `calExpireForfeit(attacker, token)` again with the same `userRewards` balance — assert `forfeitAmount` collapses to (near) 0 despite the reward having accrued while diluted.
8. Attacker calls `MasterMagpie.multiclaim`/`getReward` and receives the full reward with no forfeiture, confirming the yield that should have been redistributed to other lockers was captured instead. [1](#0-0) [2](#0-1) [3](#0-2) [4](#0-3)

    function getRewardablePercentWAD(address _user) override public view returns(uint256 percent) {
        uint256 fullyInLock = getUserTotalLocked(_user);
        uint256 inCoolDown = getUserAmountInCoolDown(_user);
        uint256 userTotalVlmgp = fullyInLock + inCoolDown;
        if (userTotalVlmgp == 0)
            return 0;
        percent = fullyInLock * 1e18 / userTotalVlmgp;

        uint256 timeNow = block.timestamp;
        UserUnlocking[] storage userUnlocking = userUnlockings[_user];

        for (uint256 i; i < userUnlocking.length; i++) {
            if (userUnlocking[i].amountInCoolDown > 0) {
                if (block.timestamp > userUnlocking[i].endTime) {// fully unlocked 
                    percent += userUnlocking[i].amountInCoolDown * 1e18 * (userUnlocking[i].endTime - userUnlocking[i].startTime)
                        / userTotalVlmgp / (timeNow - userUnlocking[i].startTime);
                }
                else {// still in cool down 
                    percent += userUnlocking[i].amountInCoolDown * 1e18 / userTotalVlmgp;
                }

            }
        }

        return percent;
    }

    function _sendReward(address _rewardToken, address _account, address _receiver) internal {
        uint256 forfeitAmount = _calExpireForfeit(_account, userRewards[_rewardToken][_account]);
        uint256 toSend = userRewards[_rewardToken][_account] - forfeitAmount;


        userRewards[_rewardToken][_account] = 0;
            
        if (toSend > 0) {
            IERC20(_rewardToken).safeTransfer(_receiver, toSend);
            emit RewardPaid(_account, _receiver, toSend, _rewardToken);
        }

        if(forfeitAmount > 0)
            _queueNewRewardsWithoutTransfer(forfeitAmount, _rewardToken);
    }

    function _earned(address _account, address _rewardToken, uint256 _userVlmgpShare) internal view returns (uint256) {
        return ((_userVlmgpShare *
                (rewardPerToken(_rewardToken) -
                    userRewardPerTokenPaid[_rewardToken][_account])) /
                10**vlMGPDecimal) + userRewards[_rewardToken][_account];
    }

    function _calExpireForfeit(address _account, uint256 _amount) internal view returns (uint256) {
        uint256 rewardablePercentWAD = vlMGP.getRewardablePercentWAD(_account);
        uint256 rewardableAmount = _amount * rewardablePercentWAD / 1e18;
        if (rewardableAmount > _amount)
            revert InvalidRewardableAmount();

        uint256 forfeitAmount = _amount - rewardableAmount;
        
        if (forfeitAmount < (_amount / 1000)) {  // if forfeitAmount is smaller than 0.1% ignore to save gas fee
            forfeitAmount = 0;
            rewardableAmount = _amount;
        }

        return forfeitAmount;
    }
