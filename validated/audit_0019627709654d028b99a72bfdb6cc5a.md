### Title
Payout attribution (OP_RETURN operator pubkey) is not covered by the user's withdrawal signature, allowing an unprivileged party to fund a withdrawal while crediting an arbitrary operator for reimbursement - (File: core/src/builder/transaction/operator_reimburse.rs)

### Summary
The `KarmaAirdrop`-style bug class ("a signed message can be replayed/repurposed outside the party's control because the signature does not commit to everything that matters") has a direct analog in Clementine's payout flow. The user's withdrawal authorization is a Taproot Schnorr signature with sighash type `SinglePlusAnyoneCanPay`, enforced in `parse_withdrawal_sig_params` [1](#0-0) . `SIGHASH_SINGLE|ANYONECANPAY` commits **only** to input 0 and the output at the same index (the user's payout output). It does **not** commit to the other outputs of `create_payout_txhandler` — specifically the anchor output and the `OP_RETURN` output that records which operator "fronts" the withdrawal [2](#0-1) . Because that OP_RETURN value (`operator_xonly_pk`) is the field later used by the automated payout tracker to decide which operator gets to claim reimbursement [3](#0-2) , an unprivileged party who obtains the user's signature can build and fund an alternate payout transaction, substitute an arbitrary operator's public key into the OP_RETURN, and fund it entirely themselves — decoupling "who actually paid" from "who is credited as having paid."

### Finding Description
`Operator::withdraw` verifies the user's signature only against the sighash of `payout_txhandler` input 0 with the signature's declared sighash type [4](#0-3) . `create_payout_txhandler` builds:
- output 0: user payout (covered by SIGHASH_SINGLE)
- output 1: anchor (NOT covered)
- output 2: `OP_RETURN` containing `operator_xonly_pk`, i.e. "the operator that fronts the peg-out" (NOT covered) [5](#0-4) 

Because `SinglePlusAnyoneCanPay` only binds input 0 + output 0, and `ANYONECANPAY` allows arbitrary additional inputs to be attached (this is exactly how the intended flow funds the transaction, via `fund_raw_transaction`/RBF with `add_inputs: true` [6](#0-5) ), any party in possession of the raw signature can:
1. Build a functionally-identical payout transaction (same input 0, same signature, same user output).
2. Replace the OP_RETURN's `operator_xonly_pk` with an arbitrary, attacker-chosen (or colluding) operator's public key — a value never signed by the user.
3. Fund the whole transaction with their own UTXOs (not the credited operator's funds), and pay the fee.
4. Broadcast/confirm it before the legitimate operator's own funded transaction confirms (the same double-spend race as the airdrop report's mempool-observation front-run).

Since the withdrawal signature is off-chain, per-doc, "given to operators off-chain" and also visible in the mempool once any operator submits it, this signature is not secret to a single actor — multiple parties can build competing spends of the same input.

Downstream, the withdrawal/reimbursement pipeline attributes the fronted payout strictly by the `operator_xonly_pk` recovered from the confirmed payout transaction (as evidenced by `get_first_unhandled_payout_by_operator_xonly_pk` keyed per-operator, feeding `handle_finalized_payout` → `mark_payout_handled` → round advancement) [7](#0-6) . There is no check anywhere in this path that the operator whose xonly_pk appears in the OP_RETURN actually supplied the transaction's funding inputs. This breaks the binding: `operator credited via OP_RETURN == party that actually fronted the withdrawal from its own funds`.

### Impact Explanation
This directly matches the Critical category "an operator reimbursed for a payout it never funded." An attacker (or a party colluding with a target operator) can front a legitimate Citrea withdrawal entirely with their own BTC while writing a different, real operator's `xonly_pk` into the payout transaction's OP_RETURN. The automated per-operator task (`PayoutCheckerTask`) will detect this as "our unhandled payout," call `handle_finalized_payout`, mark it handled, and advance that operator's round toward the `Reimburse` transaction, which pays the deposited bridge amount back to that operator's reimbursement address [8](#0-7) . That operator thus receives bridge collateral for a withdrawal it never economically fronted — value is extracted from the vault without a matching expenditure by the credited party, and consumes that operator's kickoff slot for a payout unrelated to its own funds.

### Likelihood Explanation
The precondition — knowledge of a valid `SinglePlusAnyoneCanPay` user signature for a pending withdrawal — is met by design: every registered operator already receives this signature off-chain via the withdrawal request, and it is also publicly visible the moment any operator broadcasts a payout attempt to the Bitcoin mempool. No verifier/aggregator/operator role or key compromise is required by the attacker to construct the substitute transaction; only the ability to fund a Bitcoin transaction and win a fee-based race (RBF/CPFP), which is an unprivileged, standard on-chain capability.

### Recommendation
Bind the OP_RETURN operator-attribution output (and ideally the anchor output) into the user-signed message, or otherwise cryptographically tie "who is credited" to "who funded the transaction." Options:
- Change the withdrawal authorization scheme so the signed sighash covers all outputs relevant to reimbursement attribution (e.g., use `SIGHASH_ALL|ANYONECANPAY` is not sufficient either since operator still needs to add funding inputs freely; instead have the operator additionally co-sign/commit to their own identity, or require the OP_RETURN operator pubkey to match an operator-controlled input/output that IS covered by a signature the operator itself produces).
- Alternatively, verify off-chain/on-chain that the party credited in the OP_RETURN actually supplied the transaction's non-anyone-can-pay funding inputs (e.g., require one input controlled by `operator_xonly_pk` in the transaction and check it during `handle_finalized_payout`/attribution parsing) before allowing that operator's automation to advance to reimbursement.

### Proof of Concept
1. Operator O is a registered operator with public `xonly_pk_O`; a withdrawal W (Citrea `withdrawal_id`) becomes available with a `SinglePlusAnyoneCanPay` user signature `sig_U` over `input_outpoint`/`output_script_pubkey`/`output_amount` (verifiable via `parse_withdrawal_sig_params` + `Operator::withdraw`) [9](#0-8) .
2. Attacker A (not O, unprivileged) obtains `sig_U` (from Citrea's withdrawal event data shared with all operators, or by observing operator O's payout tx once broadcast to the Bitcoin mempool).
3. A constructs a payout transaction with `create_payout_txhandler`-equivalent structure: input 0 = `input_outpoint` witnessed with `sig_U`; output 0 = the user's `output_script_pubkey`/`output_amount` (unchanged, since covered by the signature); output 1 = anchor; output 2 = `OP_RETURN` containing `xonly_pk_O` (operator O's key, not A's) [2](#0-1) .
4. A adds its own funding input(s) to cover fees/output amount (permitted since sighash is `ANYONECANPAY`), and broadcasts with a competitive fee, confirming before or in place of O's own transaction.
5. Operator O's `PayoutCheckerTask` scans the chain, finds the confirmed payout with `xonly_pk_O` in the OP_RETURN, treats it as its own fronted payout via `get_first_unhandled_payout_by_operator_xonly_pk`, and proceeds through `handle_finalized_payout` → `mark_payout_handled` → round advancement toward the `Reimburse` transaction, ultimately paying O the bridge's deposited amount [7](#0-6) [10](#0-9) , even though O never funded this specific withdrawal.

#[allow(clippy::result_large_err)]
pub fn parse_withdrawal_sig_params(
    params: WithdrawParams,
) -> Result<(u32, taproot::Signature, OutPoint, ScriptBuf, Amount), Status> {
    let mut input_signature =
        taproot::Signature::from_slice(&params.input_signature).map_err(|e| {
            Status::invalid_argument(format!("Can't convert input to taproot Signature - {e}"))
        })?;

    // If the Taproot sighash type is Default (no explicit type attached; i.e. a 64-byte
    // signature without a sighash flag), normalize it to SinglePlusAnyoneCanPay.
    // Prior to v0.5 this was Clementine's implicit behavior; we retain it here for
    // backwards compatibility when a 64-byte signature is provided.
    if input_signature.sighash_type == TapSighashType::Default {
        tracing::warn!(
            "Input signature for withdrawal {} has sighash type default, setting to SinglePlusAnyoneCanPay", params.withdrawal_id,
        );
        input_signature.sighash_type = TapSighashType::SinglePlusAnyoneCanPay;
    }

    // enforce sighash type here
    if input_signature.sighash_type != TapSighashType::SinglePlusAnyoneCanPay {
        return Err(Status::invalid_argument(format!(
            "Input signature has wrong sighash type, SinglePlusAnyoneCanPay expected, got {}",
            input_signature.sighash_type
        )));
    }

    let input_outpoint: OutPoint = params
        .input_outpoint
        .ok_or_else(error::input_ended_prematurely)?
        .try_into()?;

    let users_intent_script_pubkey = ScriptBuf::from_bytes(params.output_script_pubkey);

    Ok((
        params.withdrawal_id,
        input_signature,
        input_outpoint,
        users_intent_script_pubkey,
        Amount::from_sat(params.output_amount),
    ))
}

/// Creates a [`TxHandler`] for the `reimburse_tx`.
///
/// This transaction is sent by the operator if no challenge was sent, or a challenge was sent but no disprove was sent, to reimburse the operator for their payout.
///
/// # Inputs
/// 1. MoveToVaultTx: Utxo containing the deposit
/// 2. KickoffTx: Reimburse connector utxo in the kickoff
/// 3. RoundTx: Reimburse connector utxo in the round (for the given kickoff index)
///
/// # Outputs
/// 1. Reimbursement output to the operator
/// 2. Anchor output for CPFP
///
/// # Arguments
/// * `move_txhandler` - The move-to-vault transaction handler for the deposit.
/// * `round_txhandler` - The round transaction handler for the round.
/// * `kickoff_txhandler` - The kickoff transaction handler for the kickoff.
/// * `kickoff_idx` - The kickoff index of the operator's kickoff.
/// * `paramset` - Protocol parameter set.
/// * `operator_reimbursement_address` - The address to reimburse the operator.
///
/// # Returns
/// A [`TxHandler`] for the reimburse transaction, or a [`BridgeError`] if construction fails.
pub fn create_reimburse_txhandler(
    move_txhandler: &TxHandler,
    round_txhandler: &TxHandler,
    kickoff_txhandler: &TxHandler,
    kickoff_idx: usize,
    paramset: &'static ProtocolParamset,
    operator_reimbursement_address: &bitcoin::Address,
) -> Result<TxHandler, BridgeError> {
    let builder = TxHandlerBuilder::new(TransactionType::Reimburse)
        .with_version(NON_STANDARD_V3)
        .add_input(
            NormalSignatureKind::Reimburse1,
            move_txhandler.get_spendable_output(UtxoVout::DepositInMove)?,
            builder::script::SpendPath::ScriptSpend(0),
            DEFAULT_SEQUENCE,
        )
        .add_input(
            NormalSignatureKind::Reimburse2,
            kickoff_txhandler.get_spendable_output(UtxoVout::ReimburseInKickoff)?,
            builder::script::SpendPath::ScriptSpend(0),
            DEFAULT_SEQUENCE,
        )
        .add_input(
            NormalSignatureKind::OperatorSighashDefault,
            round_txhandler.get_spendable_output(UtxoVout::ReimburseInRound(
                kickoff_idx,
                paramset.num_kickoffs_per_round,
            ))?,
            builder::script::SpendPath::KeySpend,
            DEFAULT_SEQUENCE,
        );

    Ok(builder
        .add_output(UnspentTxOut::from_partial(TxOut {
            value: move_txhandler
                .get_spendable_output(UtxoVout::DepositInMove)?
                .get_prevout()
                .value,
            script_pubkey: operator_reimbursement_address.script_pubkey(),
        }))
        .add_output(UnspentTxOut::from_partial(
            builder::transaction::anchor_output(paramset.anchor_amount()),
        ))
        .finalize())

/// Creates a [`TxHandler`] for the `payout_tx`.
///
/// This transaction is sent by the operator to front a peg-out, after which operator will send a kickoff transaction to get reimbursed.
///
/// # Inputs
/// 1. UTXO: User's withdrawal input (committed in Citrea side, with the signature given to operators off-chain)
///
/// # Outputs
/// 1. User payout output
/// 2. OP_RETURN output (with operators x-only pubkey that fronts the peg-out)
///
/// # Arguments
/// * `input_utxo` - The input UTXO for the payout, committed in Citrea side, with the signature given to operators off-chain.
/// * `output_txout` - The output TxOut for the user payout.
/// * `operator_xonly_pk` - The operator's x-only public key that fronts the peg-out.
/// * `user_sig` - The user's signature for the payout, given to operators off-chain.
/// * `network` - The Bitcoin network.
///
/// # Returns
/// A [`TxHandler`] for the payout transaction, or a [`BridgeError`] if construction fails.
pub fn create_payout_txhandler(
    input_utxo: UTXO,
    output_txout: TxOut,
    operator_xonly_pk: XOnlyPublicKey,
    user_sig: taproot::Signature,
    _network: bitcoin::Network,
) -> Result<TxHandler<Signed>, BridgeError> {
    let txin = SpendableTxIn::new_partial(input_utxo.outpoint, input_utxo.txout);

    let output_txout = UnspentTxOut::from_partial(output_txout.clone());

    let op_return_txout = op_return_txout(PushBytesBuf::from(operator_xonly_pk.serialize()));

    let mut txhandler = TxHandlerBuilder::new(TransactionType::Payout)
        .with_version(NON_STANDARD_V3)
        .add_input(
            NormalSignatureKind::NotStored,
            txin,
            SpendPath::KeySpend,
            DEFAULT_SEQUENCE,
        )
        .add_output(output_txout)
        .add_output(UnspentTxOut::from_partial(anchor_output(
            NON_EPHEMERAL_ANCHOR_AMOUNT,
        )))
        .add_output(UnspentTxOut::from_partial(op_return_txout))
        .finalize();
    txhandler.set_p2tr_key_spend_witness(&user_sig, 0)?;
    txhandler.promote()
}

            citrea_idx,
            move_to_vault_txid

            .await?;
        if deposit_data.is_none() {
            return Err(eyre::eyre!("Fronted withdrawal for move tx {move_to_vault_txid} found, but the signatures for the deposit are not found in the db.").into());
        }

        let deposit_data = deposit_data.expect("Must be Some");

        let kickoff_txid = self
            .operator
            .handle_finalized_payout(
                &mut dbtx,
                deposit_data.get_deposit_outpoint(),
                payout_tx_blockhash,
            )
            .await?;

        // fetch and save the LCP for if we get challenged and need to provide proof of payout later
        let (_, payout_block_height) = self
            .operator
            .db
            .get_block_info_from_hash(Some(&mut dbtx), payout_tx_blockhash)
            .await?
            .ok_or_eyre("Couldn't find payout blockhash in bitcoin sync")?;

        let _ = self
            .operator
            .citrea_client
            .fetch_validate_and_store_lcp(
                payout_block_height as u64,
                citrea_idx,
                &self.operator.db,
                Some(&mut dbtx),
                self.operator.config.protocol_paramset(),
            )
            .await?;

        #[cfg(feature = "automation")]
        self.operator.end_round(&mut dbtx).await?;

        self.db
            .mark_payout_handled(Some(&mut dbtx), citrea_idx, kickoff_txid)
            .await?;
