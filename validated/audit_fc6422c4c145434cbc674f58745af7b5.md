### Title
Total-byte diff budget in `cap_diff_for_prompt` lets attacker-padded decoy files silently omit the dangerous file from the review prompt - (File: `plugins/security-guidance/hooks/review_api.py`)

### Summary
`cap_diff_for_prompt` allocates the shared `DIFF_TOTAL_BYTES` budget to files strictly in list order with no risk-awareness, and once the running total is exhausted it fully replaces the remaining files' diff content with a generic `"[omitted by security-guidance: total diff byte cap reached]"` placeholder [1](#0-0) . An attacker who authors a normal PR/diff can place several large, order-earlier "decoy" source files ahead of the actual dangerous change so their combined size consumes the whole `DIFF_TOTAL_BYTES` cap, causing the truly dangerous file's diff to never reach the review model.

### Finding Description
`cap_diff_for_prompt` iterates `files` in the order it receives them and greedily fills a shared `DIFF_TOTAL_BYTES` (400,000-byte, env-overridable) budget per file, first applying the per-file `DIFF_PER_FILE_BYTES` (80,000-byte) cap, then subtracting from `room = DIFF_TOTAL_BYTES - total` [2](#0-1) . Once `room <= 0`, the function does not truncate — it drops the entire file's content and substitutes a placeholder string, giving the reviewer zero visibility into that file's actual diff.

This function is called directly to build the Stage-1 investigate prompt via `build_investigate_prompt`, which passes `diff_files` straight into `cap_diff_for_prompt` with no risk-based reordering at that call site [3](#0-2) . The analogous single-shot path (`_cap_files_for_prompt` in `llm.py`, sharing the same caps) has identical greedy, order-dependent behavior [4](#0-3) .

The only place that reorders files by security relevance is `_prioritize_diff_files`, and it is gated on **file count**, not byte size — it only runs when `len(diff_files) > cap` (e.g. `MAX_DIFF_FILES`) [5](#0-4) . For a diff with a small number of files (below that count threshold) but where some files are individually large, no risk-based reordering happens before `cap_diff_for_prompt` runs, so the file order is simply whatever `parse_diff_into_files` produced from the raw `git diff` output (effectively pathname order) [6](#0-5) .

Exploit flow: an attacker submits a diff containing e.g. 5 lexically-earlier files, each padded to ~80,000 bytes of `+` lines (within the per-file cap so they aren't individually truncated), totaling ~400,000 bytes — exactly `DIFF_TOTAL_BYTES`. The genuinely dangerous file, sorted after them, has `room <= 0` by the time `cap_diff_for_prompt` reaches it and is replaced entirely with the omission placeholder before being sent to the reviewer. The Stop-hook / commit-review code paths that call this treat the omission as a successful "reviewed" pass and report no vulnerabilities for that turn, even though the dangerous file's actual diff content was never seen by the model.

Existing guards do not stop this: the file-count-based `_prioritize_diff_files` only engages above `MAX_DIFF_FILES` files, and does not consider per-file byte size or overall byte budget; `cap_diff_for_prompt`/`_cap_files_for_prompt` have no fairness or per-file minimum guarantee, and no re-sort by risk score before applying the byte budget.

### Impact Explanation
This is a logic-level bypass of a required security guard: dangerous code changes can be smuggled past the LLM security review by surrounding them with decoy padding files earlier in diff order, causing `cap_diff_for_prompt` to drop the dangerous file's content from the prompt while the review pipeline still completes and reports a (false) clean result. This matches "Logic-level service disruption caused by bypassing a required guard" — the required guard here is the mandatory diff-content review that gates Stop/commit/push hooks.

### Likelihood Explanation
Feasible with attacker control limited to ordinary repository content (no special privileges): the attacker only needs to control the diff/commit contents of files they are already contributing (e.g. in a shared workspace, a PR-style flow, or any automation that feeds untrusted diffs into this pipeline). Padding files to a known byte size is trivial and repeatable; the byte caps (`DIFF_PER_FILE_BYTES`, `DIFF_TOTAL_BYTES`) are fixed, discoverable constants (also overridable via well-known env vars), making the exact padding size to trigger omission straightforward to compute.

### Recommendation
Make the byte-budget allocation in `cap_diff_for_prompt` risk-aware and order-independent: (1) always run `_prioritize_diff_files`-style risk scoring before byte-capping, not only when file count exceeds a threshold; (2) guarantee every file at least a minimum byte allowance (e.g. proportional share or a fixed floor) before greedily filling with earlier files' overflow, so no file is fully omitted purely due to ordering; (3) emit a `diff_truncated`/`diff_omitted` telemetry signal that hooks can use to fail closed (block or flag) rather than silently pass when omission occurred; (4) consider capping per-file bytes tighter relative to total so a small number of files cannot exhaust the whole budget.

### Proof of Concept
Unit test in `review_api.py` test suite:
1. Construct `diff_files = [("aaa1.py", "+" * 80000), ("aaa2.py", "+"*80000), ("aaa3.py", "+"*80000), ("aaa4.py", "+"*80000), ("aaa5.py", "+"*80000), ("zzz_target.py", "+os.system(user_input)  # dangerous")]`.
2. Call `capped, dropped = cap_diff_for_prompt(diff_files)`.
3. Assert that `capped[-1][1]` for `"zzz_target.py"` equals `"[omitted by security-guidance: total diff byte cap reached]"` and does NOT contain `"os.system(user_input)"`.
4. Assert `dropped > 0` and that the dangerous marker string is absent from the concatenated `diff_text` built by `build_investigate_prompt(["zzz_target.py"], diff_files)`.
Expected (failing) assertion demonstrating the bug: the dangerous file's content is present and correctly anchored in the built prompt regardless of decoy file ordering/size — currently it is not, proving the invariant "prompt assembly must not let untrusted repo content suppress review of dangerous changes" is violated.

```python
DIFF_PER_FILE_BYTES = int(os.environ.get("DIFF_PER_FILE_BYTES", "80000"))
DIFF_TOTAL_BYTES = int(os.environ.get("DIFF_TOTAL_BYTES", "400000"))


def cap_diff_for_prompt(
    files: list[tuple[str, str]],
) -> tuple[list[tuple[str, str]], int]:
    """Cap per-file and total diff bytes; return (capped_files, bytes_dropped).

    Truncation markers are written inside the content so the reviewer
    knows the file is incomplete.
    """
    out: list[tuple[str, str]] = []
    dropped = 0
    total = 0
    for fp, content in files:
        if len(content) > DIFF_PER_FILE_BYTES:
            dropped += len(content) - DIFF_PER_FILE_BYTES
            content = (
                content[:DIFF_PER_FILE_BYTES]
                + "\n... [truncated by security-guidance: file exceeds per-file byte cap]"
            )
        room = DIFF_TOTAL_BYTES - total
        if room <= 0:
            dropped += len(content)
            out.append(
                (fp, "[omitted by security-guidance: total diff byte cap reached]")
            )
            continue
        if len(content) > room:
            dropped += len(content) - room
            content = (
                content[:room]
                + "\n... [truncated by security-guidance: total diff byte cap reached]"
            )
        total += len(content)
        out.append((fp, content))
    return out, dropped
```

```python
def build_investigate_prompt(
    touched_paths: list[str],
    diff_files: list[tuple[str, str]],
    *,
    context_note: str = "",
) -> str:
    capped, _ = cap_diff_for_prompt(diff_files)
    diff_text = "\n\n".join(
        f"=== DIFF: {fp} ===\n{content}" for fp, content in capped
    )
    return (
        "Review this change for security vulnerabilities.\n\n"
        "Changed files (you may Read these and any other file in the repo):\n"
        + "\n".join(f"  - {p}" for p in touched_paths[:50])
        + context_note
        + "\n\nUnified diff (only + lines are new):\n\n"
        + diff_text
        + extensibility.guidance_block()
        + "\n\nInvestigate per the method in your instructions, then return "
        "the findings list."
    )
```

```python
def _prioritize_diff_files(diff_files, cap):
    """When `diff_files` exceeds `cap`, return the top-`cap` by security
    relevance plus the count dropped. Otherwise return (diff_files, 0).

    Score = (risk_tokens_in_path, not_low_priority, added_lines). The
    added-lines proxy is `content.count('\\n+')` which counts diff additions
    cheaply without re-parsing hunks. This is a heuristic, not a guarantee —
    the goal is to review the likely-dangerous subset of an over-cap diff
    instead of reviewing nothing. Diffs that exceed the cap are typically
    large multi-file scaffolds, and the cross-file source→sink vulnerabilities
    in them concentrate in a handful of api/client/route files.
    """
    if len(diff_files) <= cap:
        return diff_files, 0

    def _score(item):
        fp, content = item
        low = fp.lower()
        # Prepend "/" so leading-slash patterns in _LOW_PRIORITY_PATH_TOKENS
        # match top-level dirs (git diff paths are repo-root-relative, e.g.
        # `migrations/001.py` not `/migrations/001.py`). Same trick as
        # _is_reviewable_source.
        low_slashed = "/" + low
        risk = sum(1 for t in _SECURITY_RISK_PATH_TOKENS if t in low)
        low_prio = (
            fp.endswith(_LOW_PRIORITY_SUFFIXES)
            or any(t in low_slashed for t in _LOW_PRIORITY_PATH_TOKENS)
        )
        # added_lines: count('\n+') over-counts by including '+++' header and
        # any literal '+' at line start in context, but it's a consistent
        # ordinal across files in the same diff which is all we need.
        added = content.count("\n+")
        return (risk, not low_prio, added)

    ranked = sorted(diff_files, key=_score, reverse=True)
    return ranked[:cap], len(diff_files) - cap
```

```python
def parse_diff_into_files(diff_output):
    """
    Parse unified diff output into a list of (file_path, diff_content) tuples.
    Only includes files with source code extensions.
    """
    if not diff_output or not diff_output.strip():
        return []

    files = []
    file_diffs = diff_output.split("diff --git ")

    for file_diff in file_diffs:
        if not file_diff.strip():
            continue

        # Extract filename from first line: "a/path/to/file b/path/to/file"
        lines = file_diff.split('\n')
        header_match = re.match(r'^a/(.+?) b/(.+)$', lines[0])
        if not header_match:
            continue

        file_path = header_match.group(2) or header_match.group(1) or ''

        # Filter to source code files only
        if not _is_reviewable_source(file_path):
            continue

        # Extract the diff content (from first @@ onwards)
        diff_lines = []
        in_hunks = False
        for line in lines[1:]:
            if line.startswith('@@'):
                in_hunks = True
            if in_hunks:
                diff_lines.append(line)

        if diff_lines:
            files.append((file_path, '\n'.join(diff_lines)))

    return files
```
