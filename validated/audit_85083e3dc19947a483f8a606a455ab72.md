### Title
Data Layer mirror URLs are fetched via unauthenticated HTTP without SSRF protection - (File: `chia/data_layer/download_data.py`)

### Summary
Chia's Data Layer subsystem lets any wallet user register a "mirror" URL for a store by submitting an on-chain mirror coin (via the `dl_new_mirror`/mirror-creation wallet RPC, confirmed present in `chia/wallet/wallet_rpc_client.pyi` and implemented in `chia/data_layer/data_layer_wallet.py`/`chia/data_layer/dl_wallet_store.py`). Any Data Layer client that subscribes to that store later reads the mirror's `ServerInfo.url` and issues an unauthenticated HTTP GET to `server_info.url + "/" + filename` in `http_download()` [1](#0-0) , with no validation that the host is not localhost, a link-local/cloud-metadata address, or another internal service. This mirrors the reported bug class (SSRF via unvalidated URL fetch from an untrusted/attacker-influenced source) but here the untrusted URL originates from an on-chain, attacker-controlled coin rather than an MCP OAuth discovery response.

### Finding Description
`download_file()` and `http_download()` in `chia/data_layer/download_data.py` build the request target directly from `server_info.url`, which is derived from `ServerInfo` records tied to Data Layer mirror coins [2](#0-1) . The only validation applied is to the *filename* component (`is_filename_valid()` and the store/root-hash-derived filename), not to the *host/URL* itself [3](#0-2) . The actual network call is a plain `aiohttp.ClientSession().get(server_info.url + "/" + filename, ...)` [4](#0-3) , and the downloader-plugin path similarly POSTs `server_info.url` as a JSON field to a downloader without validating it [5](#0-4) .

Mirror URLs are populated from on-chain mirror coins that any wallet holder can create for a given store id, with the URL stored as coin memo data (mirror creation surfaced through `dl_new_mirror` per `chia/wallet/wallet_rpc_client.pyi` and implemented in `chia/data_layer/data_layer_wallet.py` / `chia/data_layer/dl_wallet_store.py`, confirmed to reference `mirror`/`MirrorInfo` constructs extensively). I was not able to fully read the mirror-creation code path within the available iterations to confirm whether any URL-format or host restriction exists there; based on the code I did review, no restriction exists at the point of consumption (`download_data.py`), which is the concrete, reachable sink.

### Impact Explanation
Any unprivileged wallet user who can afford the fee for a mirror-coin spend can register a URL like `http://169.254.169.254/`, `http://127.0.0.1:<internal-port>/`, or an internal-network address as a Data Layer mirror for a store. Other Data Layer clients (peers who subscribe to/track that store) will automatically attempt to fetch delta/full-tree files from that URL via `http_download()`, causing their local Data Layer service to issue outbound requests to attacker-chosen internal/loopback/link-local targets — a classic SSRF impact (probing internal services, hitting cloud metadata endpoints, port-scanning internal networks from the victim's node). This does not directly forge coins or drain funds, but it is a concrete confidentiality/network-boundary violation reachable purely from an on-chain, attacker-authored coin, satisfying the "Medium/High" SSRF bug class from the external report.

### Likelihood Explanation
Creating a mirror coin with an arbitrary URL is a standard, documented Data Layer feature available to any wallet user, requiring no special privilege beyond a spendable coin and fee. Any other node subscribing to the same store (which is the entire purpose of mirrors — to help peers find that store's data) will be induced to fetch from the attacker's URL during normal sync operation, without any operator interaction or malicious-peer requirement.

### Recommendation
Validate mirror/server URLs before use in `download_data.py`: reject or block URLs resolving to loopback, link-local, private, and other non-routable/internal address ranges (and enforce scheme allow-listing, e.g., https-only) before issuing `session.get()`/`session.post()` calls in `http_download()` and `download_file()`. Apply the same validation at mirror-registration time in the DL wallet (`data_layer_wallet.py`) so invalid mirrors are rejected/flagged before being persisted and consumed by peers, consistent with the MCP security advisory's recommended mitigation of URL/host validation before making outbound requests to server-supplied endpoints.

### Proof of Concept
1. Attacker wallet user creates (or has) a Data Layer store and calls the mirror-creation RPC (`dl_new_mirror`) with `url="http://169.254.169.254/latest/meta-data/"` (or any internal target) and pushes the resulting spend bundle to the mempool — this is a normal, low-cost, unprivileged wallet action.
2. Once confirmed, any other Data Layer client subscribed to that store id will, during its normal `insert_from_delta_file`/sync flow, resolve this mirror as a `ServerInfo` and call `download_file()` → `http_download()` [6](#0-5) [1](#0-0) .
3. The victim's node issues an outbound HTTP GET to the attacker-chosen internal/loopback URL with no host validation, completing the SSRF.

def is_filename_valid(filename: str, group_by_store: bool = False) -> bool:
    if group_by_store:
        if filename.count("/") != 1:
            return False
        filename = filename.replace("/", "-")

    split = filename.split("-")

    try:
        raw_store_id, raw_node_hash, file_type, raw_generation, raw_version, *rest = split
        store_id = bytes32(bytes.fromhex(raw_store_id))
        node_hash = bytes32(bytes.fromhex(raw_node_hash))
        generation = int(raw_generation)
    except ValueError:
        return False

    if len(rest) > 0:
        return False

    # TODO: versions should probably be centrally defined
    if raw_version != "v1.0.dat":
        return False

    if file_type not in {"delta", "full"}:
        return False

    generate_file_func = get_delta_filename if file_type == "delta" else get_full_tree_filename
    reformatted = generate_file_func(
        store_id=store_id, node_hash=node_hash, generation=generation, group_by_store=False
    )

    return reformatted == filename
```

async def download_file(
    data_store: DataStore,
    target_filename_path: Path,
    store_id: bytes32,
    root_hash: bytes32,
    generation: int,
    server_info: ServerInfo,
    proxy_url: str | None,
    downloader: PluginRemote | None,
    timeout: aiohttp.ClientTimeout,
    client_foldername: Path,
    timestamp: int,
    log: logging.Logger,
    grouped_by_store: bool,
    group_downloaded_files_by_store: bool,
    max_delta_file_size: int,
) -> bool:
    if target_filename_path.exists():
        return True
    filename = get_delta_filename(store_id, root_hash, generation, grouped_by_store)

    if downloader is None:
        # use http downloader - this raises on any error
        try:
            await http_download(
                target_filename_path, filename, proxy_url, server_info, timeout, log, max_delta_file_size
            )
        except (asyncio.TimeoutError, aiohttp.ClientError, MaxDeltaFileSizeExceededError):
            new_server_info = await data_store.server_misses_file(store_id, server_info, timestamp)
            log.info(
                f"Failed to download {filename} from {new_server_info.url}."
                f"Miss {new_server_info.num_consecutive_failures}."
            )
            log.info(f"Next attempt from {new_server_info.url} in {new_server_info.ignore_till - timestamp}s.")
            return False
        return True
```

async def http_download(
    target_filename_path: Path,
    filename: str,
    proxy_url: str | None,
    server_info: ServerInfo,
    timeout: aiohttp.ClientTimeout,
    log: logging.Logger,
    max_delta_file_size: int,
) -> None:
    """
    Download a file from a server using aiohttp.
    Raises exceptions on errors
    """
    async with aiohttp.ClientSession() as session:
        headers = {"accept-encoding": "gzip"}
        async with session.get(
            server_info.url + "/" + filename,
            headers=headers,
            timeout=timeout,
            proxy=proxy_url,
        ) as resp:
            resp.raise_for_status()
