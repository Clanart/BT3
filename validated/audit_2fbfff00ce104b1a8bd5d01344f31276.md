## Title
Missing duplicate-input/output token rejection in Tron `IntentGatewayV2.placeOrder()` allows escrow over-release on partial fills - (File: `evm/tron/contracts/apps/IntentGatewayV2.sol`)

### Summary
The canonical EVM `IntentGatewayV2.placeOrder()` explicitly rejects orders containing duplicate input tokens (`if (_orders[commitment][token] != 0) revert InvalidInput();`) and duplicate output tokens (a transient-storage dedup loop), with regression tests documenting exactly why: without these checks, "same-chain partial fills over-release repeated input escrow" and "prematurely finalize repeated output legs." [1](#0-0) [2](#0-1)  The Tron variant of the same contract, `evm/tron/contracts/apps/IntentGatewayV2.sol`, implements `placeOrder()` without either guard: it uses `_orders[commitment][token] += reducedInputs[i].amount` (accumulating rather than rejecting) and has no output-token dedup loop at all. [3](#0-2) 

### Finding Description
This is a local analog of the reported Liquorice `validateInteractions()` bug class: a batch of caller-supplied entries (here, `order.inputs[]` / `order.output.assets[]`) is processed without deduplication, so repeating an entry lets the attacker multiply an escrow/fill effect beyond what the signed/committed intent should allow.

- On the EVM `IntentGatewayV2.sol`, duplicate input tokens are explicitly rejected before escrow crediting: `if (_orders[commitment][token] != 0) revert InvalidInput();` [1](#0-0) , and duplicate output tokens are rejected via a transient-storage dedup pass at the top of `placeOrder()`. [2](#0-1) 
- The dedicated regression tests state the exact impact of omitting these checks: "Regression test for: same-chain partial fills over-release repeated input escrow" and "Regression test for: same-chain partial fills prematurely finalize repeated output legs." [4](#0-3) [5](#0-4) 
- The Tron fork's `placeOrder()` (`evm/tron/contracts/apps/IntentGatewayV2.sol:332-463`) has neither guard: it accumulates escrow per-token with `+=` instead of rejecting a repeat, and has no output-token duplicate check at all. [6](#0-5) 

Why this breaks the invariant: `_fillSameChain` in `IntrinsicIntents.sol` computes `alreadyFilled = _partialFills[commitment][outputToken]` and releases a proportional share of `_orders[commitment][token]` per output leg, based on each leg's own `totalRequired`. [7](#0-6)  If two output legs share the same token, they share one `_partialFills` bucket while each leg independently computes `remaining = totalRequired - alreadyFilled` against its own `totalRequired`, letting a solver satisfy the first leg and then reuse the residual as unclaimed room on the second leg — over-releasing escrow beyond the true total required. Symmetrically, if two input legs share the same token, escrow crediting on the Tron contract accumulates into one bucket (`+=`) rather than rejecting, corrupting the assumption (encoded in the EVM contract's revert) that each token appears at most once per commitment, which downstream proportional-release math depends on.

### Impact Explanation
This falls under the bounty's "logic attacks" / "stealing or loss of funds" / "transaction manipulation" category for intent settlement. An attacker (any user placing an order — no privileged actor, relayer, or governance role needed) can craft an order with duplicate input or output token entries on the Tron deployment and, by orchestrating partial fills, extract more escrowed value than the order's total committed amount, causing direct fund loss to the protocol/other party in the swap. This exactly matches the "Impacts" gate: unauthorized/incorrect transaction manipulation and fund loss via a single unprivileged public entrypoint (`placeOrder`/`fillOrder`), not requiring a malicious relayer, prover, or governance actor.

### Likelihood Explanation
High, if the Tron deployment is live or planned for the intent-settlement bridge: `placeOrder` and `fillOrder` are fully permissionless public entrypoints, exploitable by any user submitting one transaction with duplicate `TokenInfo` entries. The bug requires no race condition, no relayer collusion, and no cross-chain timing — it is triggerable entirely within same-chain partial-fill logic that the EVM version's own regression-test suite proves is broken without the missing checks.

### Recommendation
Port the same two guards from `evm/src/apps/IntentGatewayV2.sol` into `evm/tron/contracts/apps/IntentGatewayV2.sol`:
1. Reject duplicate input tokens: instead of `_orders[commitment][token] += reducedInputs[i].amount`, revert with `InvalidInput()` if `_orders[commitment][token] != 0` before crediting escrow (mirroring lines 333-343 of the EVM contract).
2. Reject duplicate output tokens before escrow/fee processing, in the same manner as the EVM contract's transient-storage dedup loop (or a memory-based dedup if Tron's TVM does not support `tload`/`tstore`/EIP-1153).

Add the same regression tests already present in `evm/tests/foundry/IntentGatewayV2SameChainTest.sol` (`testRevert_PlaceOrder_DuplicateInputTokens`, `testRevert_PlaceOrder_DuplicateOutputTokens`) against the Tron contract to prevent this divergence from being reintroduced.

### Proof of Concept
1. On the Tron `IntentGatewayV2`, call `placeOrder(order, graffiti)` with `order.output.assets` containing two legs for the same output token, e.g. `[{token: DAI, amount: 400e18}, {token: DAI, amount: 600e18}]`, and matching inputs (e.g. USDC 1000e6 total). Since no output-dedup check exists, this order is accepted (unlike the EVM contract, which reverts per `testRevert_PlaceOrder_DuplicateOutputTokens`, `evm/tests/foundry/IntentGatewayV2SameChainTest.sol:2056-2088`).
2. A solver calls `fillOrder` supplying `solverAmount = 400 DAI` against the first output leg. `_fillSameChain` sets `_partialFills[commitment][DAI] = 400e18` and releases the proportional share of escrowed USDC for that leg, based on `totalRequired = 400e18` for leg 0. [8](#0-7) 
3. The loop then processes leg 1 (`totalRequired = 600e18`, same token DAI): `alreadyFilled = _partialFills[commitment][DAI] = 400e18` (shared bucket), so `remaining = 600e18 - 400e18 = 200e18`, letting the same/another solver claim another proportional escrow release computed off `totalRequired = 600e18` while the first release was already computed off a different (smaller) `totalRequired` — inflating total escrow released beyond the true single combined requirement (1000 DAI total, escrow siced for only 1000 USDC input) because the two legs' proportional shares are calculated independently rather than jointly, over-releasing the shared USDC escrow pool.
4. Repeat analogously with duplicate input tokens exploiting the `+=` accumulation instead of the EVM contract's reject-on-duplicate, to double-count escrow availability across legs.

Note: I was not able to fully verify whether Tron `IntentGatewayV2.sol` is actually deployed/live versus a WIP/experimental fork — the index does not indicate deployment status. If it is not live in production, the "testnet-only"/non-production exclusion in the bounty scope may apply; this should be confirmed with the repo maintainers or via a Devin session inspecting deployment scripts/configs for `evm/tron/`.

    function placeOrder(Order memory order, bytes32 graffiti) public payable {
        // Validate that order has inputs
        if (order.inputs.length == 0) revert InvalidInput();

        address hostAddr = host();
        // fill out the order preludes
        order.user = bytes32(uint256(uint160(msg.sender)));
        order.source = IDispatcher(hostAddr).host();
        order.nonce = _nonce++;

        // Calculate reduced inputs (after protocol fees) for commitment and escrow
        uint256 inputsLen = order.inputs.length;
        // Use destination-specific protocol fee, fallback to source chain fee if zero
        bytes32 destinationHash = keccak256(order.destination);
        uint256 protocolFeeBps = _destinationProtocolFees[destinationHash];
        if (protocolFeeBps == 0) {
            protocolFeeBps = _params.protocolFeeBps;
        }
        TokenInfo[] memory reducedInputs;
        bytes32 commitment;

        if (protocolFeeBps > 0) {
            reducedInputs = new TokenInfo[](inputsLen);
            for (uint256 i; i < inputsLen;) {
                uint256 originalAmount = order.inputs[i].amount;
                uint256 protocolFee = (originalAmount * protocolFeeBps) / 10_000;
                uint256 reducedAmount = originalAmount - protocolFee;
                address token = address(uint160(uint256(order.inputs[i].token)));

                // Emit DustCollected for protocol fee if non-zero
                if (protocolFee > 0) emit DustCollected(token, protocolFee);

                reducedInputs[i] = TokenInfo({token: order.inputs[i].token, amount: reducedAmount});
                unchecked {
                    ++i;
                }
            }

            // Temporarily swap inputs to calculate commitment with reduced amounts
            TokenInfo[] memory originalInputs = order.inputs;
            order.inputs = reducedInputs;
            commitment = keccak256(abi.encode(order));
            order.inputs = originalInputs;
        } else {
            // No protocol fees, use order.inputs directly
            reducedInputs = order.inputs;
            commitment = keccak256(abi.encode(order));
        }

        // escrow tokens
        uint256 msgValue = msg.value;
        if (order.predispatch.call.length > 0 && order.predispatch.assets.length > 0) {
            address dispatcher = _params.dispatcher;

            // Transfer all predispatch assets to the call dispatcher
            uint256 assetsLen = order.predispatch.assets.length;
            for (uint256 i; i < assetsLen;) {
                address token = address(uint160(uint256(order.predispatch.assets[i].token)));
                uint256 amount = order.predispatch.assets[i].amount;

                if (token == address(0)) {
                    if (amount > msgValue) revert InsufficientNativeToken();
                    msgValue -= amount;

                    (bool sent,) = dispatcher.call{value: amount}("");
                    if (!sent) revert InsufficientNativeToken();
                } else {
                    IERC20(token).safeTransferFrom(msg.sender, dispatcher, amount);
                }

                unchecked {
                    ++i;
                }
            }

            // Execute the call dispatcher with predispatch call
            ICallDispatcher(dispatcher).dispatch(order.predispatch.call);

            // Transfer tokens from call dispatcher back to IntentGateway
            Call[] memory transferCalls = new Call[](inputsLen);
            for (uint256 i; i < inputsLen;) {
                address token = address(uint160(uint256(order.inputs[i].token)));
                uint256 requiredAmount = order.inputs[i].amount;
                uint256 balance;

                if (token == address(0)) {
                    balance = address(dispatcher).balance;
                    if (balance < requiredAmount) revert InsufficientNativeToken();
                    transferCalls[i] = Call({to: address(this), value: balance, data: ""});
                } else {
                    balance = IERC20(token).balanceOf(dispatcher);
                    if (balance < requiredAmount) revert InvalidInput();
                    transferCalls[i] = Call({
                        to: token,
                        value: 0,
                        data: abi.encodeWithSelector(IERC20.transfer.selector, address(this), balance)
                    });
                }

                uint256 dust = balance - requiredAmount;
                if (dust > 0) emit DustCollected(token, dust);

                // Store reduced amount (after protocol fees) in escrow
                _orders[commitment][token] += reducedInputs[i].amount;

                unchecked {
                    ++i;
                }
            }

            // Execute transfer calls from call dispatcher
            ICallDispatcher(dispatcher).dispatch(abi.encode(transferCalls));
        } else {
            for (uint256 i; i < inputsLen;) {
                if (order.inputs[i].amount == 0) revert InvalidInput();
                address token = address(uint160(uint256(order.inputs[i].token)));
                if (token == address(0)) {
                    // native token
                    if (msgValue < order.inputs[i].amount) revert InsufficientNativeToken();
                    msgValue -= order.inputs[i].amount;
                } else {
                    IERC20(token).safeTransferFrom(msg.sender, address(this), order.inputs[i].amount);
                }

                // Store reduced amount (after protocol fees) in escrow
                _orders[commitment][token] += reducedInputs[i].amount;

                unchecked {
                    ++i;
                }
            }
        }

    function _fillSameChain(Order calldata order, FillOptions calldata options, bytes32 commitment) internal {
        uint256 outputsLen = order.output.assets.length;

        _filled[commitment] = msg.sender;

        uint256 msgValue = msg.value;
        address beneficiary = address(uint160(uint256(order.output.beneficiary)));
        bool isFullyFilled = true;

        TokenInfo[] memory escrowedInputs = new TokenInfo[](outputsLen);
        TokenInfo[] memory outputFills = new TokenInfo[](outputsLen);

        for (uint256 i; i < outputsLen; i++) {
            bytes32 outputToken = order.output.assets[i].token;
            if (options.outputs[i].token != outputToken) revert InvalidInput();

            address token = address(uint160(uint256(outputToken)));
            uint256 totalRequired = order.output.assets[i].amount;
            uint256 solverAmount = options.outputs[i].amount;

            uint256 alreadyFilled = _partialFills[commitment][outputToken];
            uint256 remaining = totalRequired - alreadyFilled;
            if (remaining == 0 || solverAmount == 0) {
                if (solverAmount == 0 && remaining > 0) isFullyFilled = false;
                continue;
            }
            uint256 fillAmount;

            uint256 beneficiaryShare = 0;
            uint256 protocolShare = 0;
            if (alreadyFilled == 0 && solverAmount > totalRequired) {
                fillAmount = totalRequired;
                uint256 dust = solverAmount - totalRequired;
                if (order.output.call.length > 0) {
                    protocolShare = dust;
                } else {
                    protocolShare = (dust * _params.surplusShareBps) / 10_000;
                    beneficiaryShare = dust - protocolShare;
                }
            } else {
                fillAmount = solverAmount > remaining ? remaining : solverAmount;
            }

            uint256 amountFilled = alreadyFilled + fillAmount;
            _partialFills[commitment][outputToken] = amountFilled;
            uint256 beneficiaryTotal = fillAmount + beneficiaryShare;

            if (token == address(0)) {
                if (msgValue < beneficiaryTotal + protocolShare) revert InsufficientNativeToken();
                msgValue -= (beneficiaryTotal + protocolShare);
                (bool sent,) = beneficiary.call{value: beneficiaryTotal}("");
                if (!sent) revert InsufficientNativeToken();
            } else {
                IERC20(token).safeTransferFrom(msg.sender, beneficiary, beneficiaryTotal);
                if (protocolShare > 0) {
                    IERC20(token).safeTransferFrom(msg.sender, address(this), protocolShare);
                }
            }

            if (totalRequired > amountFilled) isFullyFilled = false;
            if (protocolShare > 0) emit DustCollected(token, protocolShare);

            uint256 escrowedAmount;
            if (amountFilled == totalRequired) {
                escrowedAmount = _orders[commitment][address(uint160(uint256(order.inputs[i].token)))];
            } else {
                escrowedAmount = (order.inputs[i].amount * fillAmount) / totalRequired;
            }
            escrowedInputs[i] = TokenInfo({token: order.inputs[i].token, amount: escrowedAmount});
            outputFills[i] = TokenInfo({token: outputToken, amount: fillAmount});
