### Title
Unvalidated pool-info HTTP redirect permits persistent credential-bearing pool requests to be hijacked to an attacker-chosen host - (File: `chia/farmer/farmer.py`)

### Summary
`Farmer._pool_get_pool_info()` accepts any HTTP 301/308 redirect target returned for the `GET /pool_info` request and persists it as the farmer's new `pool_url`, without validating that the redirect target's host/domain matches the originally configured pool. That mutated `pool_url` is then used for all subsequent credential-bearing pool requests (`/auth`, `/farmer`, `/partial`), causing signed authentication material to be sent to the attacker-controlled endpoint from then on. This mirrors CVE-2026-85528's bug class: an auto-configuration/redirect step that changes the effective endpoint without validating it, causing reusable credentials to be transmitted to an attacker-chosen host.

### Finding Description
`_pool_get_pool_info()` compares the final response URL to the expected `/pool_info` endpoint and, if it differs and the full redirect chain consisted only of `301`/`308` responses, returns that URL as `new_pool_url` with no check that it shares the same scheme/host as the configured pool: [1](#0-0) 

`update_pool_state()` then unconditionally writes this attacker-influenced value into the persisted `PoolingShareState.pool_url`, which is used by `self.pool_config` for the remainder of the farmer's lifetime (until the next periodic `/pool_info` fetch, one hour later): [2](#0-1) 

`_url_for_endpoint()` builds every subsequent pool endpoint URL directly from `pool_config.pool_url`: [3](#0-2) 

Once `pool_url` is redirected, `_pool_get_auth()` sends a BLS signature over `(timestamp, launcher_id, target_puzzle_hash)` signed with the farmer's authentication key to that host: [4](#0-3) 

and `FarmerAPI.new_proof_of_space()` POSTs `/partial` (containing the aggregate signature over harvester proof-of-space data plus the current pool auth token) to `self.farmer._url_for_endpoint(pool_state_dict["pool_config"], "partial")`: [5](#0-4) 

No comparison is made between the original pool host and the redirect target host, so a single successful permanent-redirect response (which the existing test suite explicitly validates is accepted, see `valid_response_with_301_redirect`/`valid_response_with_308_redirect` cases) is sufficient to durably repoint all future credential-bearing pool traffic: [6](#0-5) 

### Impact Explanation
This lets an attacker who can produce a single valid HTTPS 301/308 response for the configured pool's `/pool_info` endpoint (e.g. a compromised/rotated pool CDN edge, a stale DNS record now pointed at attacker infrastructure, or a pool operator turned malicious) capture the farmer's authentication signatures and partial-share submissions going forward. Because the auth signature is scoped to `(timestamp, launcher_id, target_puzzle_hash)` and reusable within its validity window against the legitimate pool API, an attacker who intercepts it can replay it to the real pool to act with the farmer's pooling privileges (e.g., trigger `PUT /farmer` payout-instruction changes), redirecting farming rewards or otherwise impersonating the farmer's pool session. This is a credential-redirection issue reachable purely through the pool-participant flow, matching the CVE's bug class.

### Likelihood Explanation
Exploitation requires the attacker to control (or intercept/redirect) the pool's HTTPS endpoint long enough to serve one valid 301/308 response — a moderate-complexity, plausible scenario for cloud-hosted pool infrastructure (matches CVSS AC:H). No wallet-key compromise or node-level privilege is required; a pool participant simply relies on the farmer's normal hourly `update_pool_state()` cycle.

### Recommendation
Validate that any accepted `new_pool_url` shares the same scheme and host (or is on an explicit allow-list) as the originally configured `pool_url` before persisting it in `update_pool_state()`; alternatively, require explicit user/operator confirmation before changing the stored pool endpoint, and never automatically redirect credential-bearing requests (`/auth`, `/farmer`, `/partial`) to a host different from the one the operator configured.

### Proof of Concept
1. Farmer configures `pool_url = https://pool.example.com` in `PoolingShareState`.
2. Attacker gains control of `pool.example.com` (DNS takeover, compromised CDN edge, or is the legitimate-but-now-malicious pool operator) and configures `GET /pool_info` to respond with `308 Permanent Redirect` to `https://evil.attacker.com/pool_info`.
3. On the next `update_pool_state()` cycle, `_pool_get_pool_info()` accepts the redirect (`all(r.status in {301, 308} ...)` passes) and returns `new_pool_url = "https://evil.attacker.com"`.
4. `update_pool_state()` persists this into `PoolingShareState.pool_url` at chia/farmer/farmer.py:704-710.
5. All subsequent `_pool_get_auth()` and `/partial` submissions (`chia/farmer/farmer_api.py:388-398`) are sent to `https://evil.attacker.com`, delivering the farmer's authentication signature and partial-share aggregate signatures to the attacker, who can replay the auth signature against the real pool within its validity window.

    async def _pool_get_pool_info(self, pool_config: PoolingShareState) -> GetPoolInfoResult | None:
        response, client_response = await make_pool_protocol_request(
            self=self,
            pool_config=pool_config,
            method="GET",
            endpoint_name="pool_info",
            request=None,
            response_type=pool_protocol.GetPoolInfoResponse,
        )
        if client_response is None:
            return None
        new_pool_url: str | None = None
        response_url_str = f"{client_response.url}"
        if (
            response_url_str != self._url_for_endpoint(pool_config, "pool_info")
            and len(client_response.history) > 0
            and all(r.status in {301, 308} for r in client_response.history)
        ):
            new_pool_url = response_url_str.replace("/pool_info", "")
            new_pool_url = new_pool_url.replace(f"/v{pool_config.version}", "")

        if isinstance(response, pool_protocol.GetPoolInfoResponse):
            return GetPoolInfoResult(pool_info=response, new_pool_url=new_pool_url)
        else:
            return None
