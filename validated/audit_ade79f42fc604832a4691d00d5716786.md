### Title
`donateRewards` rounds reward increment to zero, permanently stranding donated reward tokens in the pool - (File: rewards/BaseRewardPool.sol)

### Summary
`donateRewards(uint256 _amountReward, address _rewardToken)` has no access control beyond `isRewardToken[_rewardToken]`, so any unprivileged caller can call it directly with an arbitrary registered reward token and amount. It forwards the call to `_provisionReward`, which pulls the tokens in via `safeTransferFrom`, unconditionally increments `rewardInfo.historicalRewards`, but only increases `rewardInfo.rewardPerTokenStored` by `(_amountReward * 10**stakingDecimals()) / this.totalStaked()` — an integer division that truncates to zero whenever `_amountReward * 10**stakingDecimals() < totalStaked()`.

### Finding Description
`donateRewards` in [1](#0-0)  is externally callable by anyone as long as `_rewardToken` is already registered (`isRewardToken[_rewardToken]` true); it does not require `onlyManager`, `onlyMasterMagpie`, or any other privileged role.

The core accounting happens in `_provisionReward`: [2](#0-1) 

Key issue: when `this.totalStaked() != 0`, the code enters the `else` branch and computes:
```
rewardInfo.rewardPerTokenStored += (_amountReward * 10**stakingDecimals()) / this.totalStaked();
```
Unlike the `totalStaked() == 0` branch (which stores the entire donated amount in `queuedRewards` to be applied later), this branch does **not** carry forward any remainder or fully-rounded-to-zero amount. If `_amountReward * 10**stakingDecimals()` is smaller than `totalStaked()` — which is trivially achievable given a staking token with 18 decimals (e.g., a Wombat LP/receipt token) and `totalStaked()` far above `1e18` — the division truncates to `0`, meaning `rewardPerTokenStored` is left completely unchanged.

Despite that, the function has already:
1. Pulled `_amountReward` of `_rewardToken` into the contract via `safeTransferFrom` (so `IERC20(_rewardToken).balanceOf(address(this))` increases).
2. Incremented `rewardInfo.historicalRewards` by the full `_amountReward`.

Because `rewardPerTokenStored` never changed, `earned()` (which reads `rewardPerToken(_rewardToken)` — i.e., `rewards[_rewardToken].rewardPerTokenStored` — see [3](#0-2) ) for every staker returns exactly the same value as before the donation. No staker's claimable balance increases by the donated amount. The tokens sit in the contract balance forever, with `historicalRewards` reporting a higher figure than what is actually distributable, and no mechanism (no `queuedRewards` carry-over in this branch, no rescue function) exists to recover or later apply that stranded amount.

### Impact Explanation
Every call to `donateRewards` (or `queueNewRewards`, which shares `_provisionReward`) with an amount small enough relative to `totalStaked()` results in reward tokens being permanently locked in the `BaseRewardPool` contract, unclaimable by any current or future staker, while `historicalRewards` silently diverges from the real distributable balance. This breaks the stated invariant "every reward token that enters the pool must become claimable by some staker" and matches the "High – Permanent freezing of unclaimed yield" impact class, since the affected tokens are stuck with no code path to ever credit them to `rewardPerTokenStored`.

### Likelihood Explanation
The precondition is simple and realistic: an 18-decimal staking receipt token (as used by Wombat-integrated pools in this protocol) with `totalStaked()` on the order of `>1e18` — a normal state for any pool with modest deposits. Any unprivileged holder of a registered reward token can trigger this with a single transaction and an amount as small as 1 wei, with no special capital requirements, and it is fully repeatable (each sub-threshold donation call independently truncates to zero and strands its full amount).

### Recommendation
Track and carry forward the rounding remainder analogous to the `queuedRewards` mechanism in the `totalStaked() == 0` branch: when `(_amountReward * 10**stakingDecimals()) / totalStaked()` truncates to zero (or has a non-zero remainder), retain the un-applied portion in `rewardInfo.queuedRewards` so it is combined with the next `_provisionReward` call instead of being silently dropped while still being pulled into the contract and counted in `historicalRewards`.

### Proof of Concept
Hardhat/Foundry test plan:
1. Deploy `BaseRewardPool` with an 18-decimal staking token and register a reward token (also 18-decimal) via `queueNewRewards` (as `onlyManager`) once, so `isRewardToken[rewardToken] == true`.
2. Have users stake so `totalStaked()` (via `MasterMagpie`/mocked `stakingInfo`) is, e.g., `1000e18`.
3. Mint 1 wei of `rewardToken` to an unprivileged attacker EOA; approve the pool.
4. Call `donateRewards(1, rewardToken)` from the attacker.
5. Assert:
   - `IERC20(rewardToken).balanceOf(pool)` increased by 1.
   - `rewards[rewardToken].historicalRewards` increased by 1.
   - `rewards[rewardToken].rewardPerTokenStored` unchanged (`(1 * 1e18) / 1000e18 == 0`).
   - `earned(anyStaker, rewardToken)` unchanged before/after the donation, proving the 1 wei is unclaimable by any staker and permanently stranded in contract balance.

```text
    function _provisionReward(uint256 _amountReward, address _rewardToken) internal {
        IERC20(_rewardToken).safeTransferFrom(
            msg.sender,
            address(this),
            _amountReward
        );
        Reward storage rewardInfo = rewards[_rewardToken];
        rewardInfo.historicalRewards =
            rewardInfo.historicalRewards +
            _amountReward;
        if (this.totalStaked() == 0) {
            rewardInfo.queuedRewards += _amountReward;
        } else {
            if (rewardInfo.queuedRewards > 0) {
                _amountReward += rewardInfo.queuedRewards;
                rewardInfo.queuedRewards = 0;
            }
            rewardInfo.rewardPerTokenStored =
                rewardInfo.rewardPerTokenStored +
                (_amountReward * 10**stakingDecimals()) /
                this.totalStaked();
        }
        emit RewardAdded(_amountReward, _rewardToken);
    }
```
