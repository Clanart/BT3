### Title
Stale infinite ERC20 approvals to a rotated Gasless SwapRouter remain exploitable after router update - ([File: kaiax/gasless/impl/getter.go])

### Summary
The Kaia gasless module (KIP-247) requires users to grant an **unlimited (`MaxUint256`) ERC20 approval** to the whitelisted `SwapRouter` contract in order to participate in gasless swaps. The `swapRouter` address is not a constant — it is mutable module state (`g.swapRouter common.Address`) that is refreshed every block via `PostInsertBlock` → `updateAddresses`. If the swap router address is ever rotated (e.g., due to a system-contract/registry upgrade or governance change), users who previously executed a `GaslessApproveTx` retain an infinite ERC20 allowance on the *old* router address. That old router contract remains fully authorized to pull the user's entire token balance via `transferFrom`, exactly mirroring PoolTogether's "old yield source still has infinite approval" issue.

### Finding Description
`IsApproveTx`/`isApproveTx` enforces that a valid gasless approve transaction must set the allowance to exactly `MaxUint256` for the current `swapRouter`: [1](#0-0) 

The module tracks `swapRouter` as protected, mutable in-memory state guarded by `gaslessInfoMu`, populated during block processing rather than fixed at genesis: [2](#0-1) [3](#0-2) 

Swap execution (`checkBalanceForSwap`) simply checks `token.allowance(sender, swapRouter) >= amountIn` for the *current* router at execution time — there is no mechanism anywhere in the module, in the on-chain `GaslessSwapRouter` contract bindings, or in the transition logic to revoke/zero-out allowances previously granted to a router address that is no longer the active `swapRouter`: [4](#0-3) 

Because the protocol design (rule A4) *mandates* infinite approval rather than a bounded, per-swap approval, every gasless user who has ever interacted with the system holds a standing `MaxUint256` allowance on whatever router address was active at the time. If the `swapRouter` address is later changed at the system-contract/registry level (an admin/governance action reachable through normal protocol parameter transitions, not requiring any malicious peer or validator), the old router address keeps full spending rights over every user's approved token balance indefinitely, with no expiry or automatic revocation path.

### Impact Explanation
If the old (deprecated) `SwapRouter` contract is later found to contain a bug, is upgraded to a malicious implementation (if proxy-based), or its private key/owner is otherwise compromised, an attacker could call `transferFrom` directly against any ERC20 token contract using the stale infinite allowance to drain the full token balance of every user who ever performed a gasless approve — without needing any further authorization from those users. This is a direct unauthorized value-movement vector reachable purely from a public transaction (`transferFrom` call), consistent with the required "concrete unauthorized value movement" impact bar.

### Likelihood Explanation
Likelihood depends on (a) the `swapRouter` address actually being rotated during the system's lifetime (an expected governance/registry operation, not a rare edge case, since KIP-247 anticipates router upgrades) and (b) the old router later becoming unsafe (bug, compromised admin key on an upgradeable router, or the address being reused for unrelated code). Given infinite approval is the mandatory approval pattern (not opt-in), the exposure accumulates with every user of the gasless feature over time, making this a realistic Medium/High-severity latent risk rather than a purely theoretical one — matching the original finding's classification (Medium).

### Recommendation
- When the `swapRouter` address changes (in `updateAddresses`/registry transition), emit an on-chain or off-chain mechanism instructing/forcing revocation of allowances on the outgoing router, or
- Redesign the approve flow to avoid `MaxUint256` blanket approvals in favor of per-swap, bounded approvals (approve exactly `amountIn` per `GaslessSwapTx`), eliminating standing infinite allowances entirely, or
- If infinite approval must be retained for gas efficiency, maintain a "deprecated routers" list and have new router deployments include a migration step that revokes allowance on the prior router as part of the rotation transaction.

### Proof of Concept
1. Router `R1` is set as `swapRouter`; users `U1...Un` each submit a `GaslessApproveTx` granting `token.approve(R1, MaxUint256)` as required by rule A4 in `isApproveTx` [5](#0-4) .
2. Governance/registry rotates the active swap router to `R2`; `updateAddresses` updates `g.swapRouter` to `R2` on the next block [3](#0-2) .
3. `R1` is later found vulnerable or its owner key is compromised (if upgradeable).
4. An attacker (or a compromised `R1` logic) calls `token.transferFrom(Ui, attacker, balanceOf(Ui))` for every `Ui`, succeeding because `allowance(Ui, R1) == MaxUint256` was never revoked — no additional signature from `Ui` is required.

**Uncertainty note:** the exact implementation of `updateAddresses` (i.e., the precise system-contract/registry read path that assigns `g.swapRouter`) was not fully retrieved from the index within the available searches; its existence and mutability is confirmed via the `GaslessModule` struct field and its invocation from `PostInsertBlock`, but a background Devin session should read `kaiax/gasless/impl/getter.go`'s `updateAddresses` function in full to confirm the exact trigger/authorization path for router rotation.

// IsApproveTx checks following conditions:
// A1. tx.to is a whitelisted ERC20 token.
// A2. tx.data is `approve(spender, amount)`.
// A3. spender is a whitelisted SwapRouter contract.
// A4. amount is MaxUint.
func (g *GaslessModule) IsApproveTx(tx *types.Transaction) bool {
	args, ok := decodeApproveTx(tx, g.signer)
	return ok && g.isApproveTx(args)
}

func (g *GaslessModule) isApproveTx(args *ApproveArgs) bool {
	g.gaslessInfoMu.RLock()
	defer g.gaslessInfoMu.RUnlock()

	return g.allowedTokens[args.Token] && // A1
		g.swapRouter == args.Spender && // A3
		args.Amount.Cmp(abi.MaxUint256) == 0 // A4
}

func (g *GaslessModule) PostInsertBlock(block *types.Block) error {
	currentState, err := g.Chain.StateAt(block.Header().Root)
	if err != nil {
		return err
	}
	g.setCurrentState(currentState)
	return g.updateAddresses(block.Header())
}
