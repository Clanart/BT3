### Title
Pointer precompile mints spoofed ERC20/ERC721 token identities from unsanitized CW20/CW721/tokenfactory metadata, enabling homograph-style token impersonation - (File: precompiles/pointer/pointer.go)

### Summary
The pointer precompile's `AddCW20`, `AddCW721`, `AddCW1155`, and `AddNative` handlers copy the `name`/`symbol` fields verbatim from an attacker-chosen CosmWasm contract's `token_info`/`contract_info` query response (or from bank denom metadata) and bake them into the constructor of a newly-deployed EVM pointer contract, with no validation, sanitization, or Unicode normalization of the strings. [1](#0-0) [2](#0-1)  Because any address can permissionlessly deploy a CW20/CW721 contract with arbitrary `name`/`symbol` metadata and then call `addCW20Pointer`/`addCW721Pointer` for it, an attacker can register a pointer whose ERC20/ERC721 `name()`/`symbol()` visually mimics ("homograph") a well-known legitimate token (e.g. using Unicode homoglyphs of "USDC"/"USDT" or an exact string match to a token that has no pointer yet), tricking wallets, explorers, and integrators that key off the human-readable name/symbol rather than the contract address into treating the fake pointer as the genuine asset.

### Finding Description
The pointer precompile (`0x000000000000000000000000000000000000100b`) is reachable from any EVM caller. `AddCW20` fetches `token_info` from the target CW20 contract and directly uses the returned `name`/`symbol` (attacker-fully-controlled since the attacker deployed that CW20 contract) to construct the ERC20 pointer via `UpsertERCCW20Pointer`: [3](#0-2)  The same pattern applies to `AddCW721`/`AddCW1155` (using `contract_info`) [4](#0-3)  and to `AddNative`, which uses bank denom metadata `Name`/`Symbol`, which for tokenfactory denoms is fully attacker-supplied via `MsgSetDenomMetadata` or defaults to the denom string itself. [5](#0-4) 

There is no check that:
1. The `name`/`symbol` strings are restricted to a safe character set (e.g., no confusable Unicode homoglyphs, zero-width characters, or bidi-control characters).
2. The `name`/`symbol` do not already collide with (or are confusably similar to) a token that already has a registered pointer or is otherwise "well known".

Since the pointer registration itself is permissionless — any caller can invoke `addCW20Pointer`/`addCW721Pointer`/`addNativePointer` for any CW20/CW721 address or tokenfactory denom they choose — an attacker's flow is:
1. Deploy a CW20 contract (or create a tokenfactory denom) with `name`/`symbol` crafted to be visually indistinguishable from a legitimate, high-value token's, using homoglyphs (e.g. Cyrillic "Ѕ"/"а" vs Latin "S"/"a", or other confusable Unicode code points) or an identical raw string.
2. Call `addCW20Pointer(cwAddr)` on the pointer precompile, causing the EVM to deploy a real ERC20 pointer contract whose `name()`/`symbol()` return the attacker's spoofed strings.
3. Distribute/list this pointer contract address to users, wallets, or integrations, or use it in a DEX pair, presenting it as the legitimate token because its displayed name/symbol match.

This is the direct sei-chain analog of the Keycloak IDN homograph bug: instead of tricking an admin into believing a registered identity/user is the one they already trust, the attacker tricks a chain user, wallet, or downstream contract into believing a spoofed pointer token is the trusted asset they already know, purely based on unsanitized display-name matching.

### Impact Explanation
Users, wallets, and integrators commonly identify ERC20/ERC721 tokens by `name()`/`symbol()` in absence of careful address verification. A spoofed pointer contract with a homograph/identical name and symbol to a legitimate, valuable token can cause users to approve, transfer, or swap against the fake pointer believing it is genuine, resulting in direct fund loss (sending value to or interacting with a worthless/malicious contract while believing it is the real asset). This matches the "unauthorized transfer via precompile or pointer" / "concrete fund loss" impact criteria, since the pointer contract is a first-class on-chain artifact created and endorsed by the core pointer precompile infrastructure.

### Likelihood Explanation
The precondition is trivial and fully permissionless: anyone can deploy a CW20/CW721 contract (or a tokenfactory denom) with any UTF-8 metadata string and then call the pointer precompile to mint a pointer contract exposing it. No governance, admin, or fee gate exists beyond ordinary transaction gas, and the constructors of `AddCW20`/`AddCW721`/`AddNative` never reject unusual characters or check against existing legitimate pointers' names/symbols. [3](#0-2) [5](#0-4) 

### Recommendation
- Sanitize/normalize `name` and `symbol` strings pulled from CW20/CW721/CW1155 `token_info`/`contract_info` and from bank denom metadata before using them in pointer contract constructors: restrict to a known-safe character set (e.g. ASCII alphanumerics and a small punctuation allowlist), reject zero-width/bidi-control/confusable Unicode ranges, or apply Unicode confusable-skeleton normalization (similar to UTS #39) and reject collisions against skeletons of already-pointed tokens.
- Consider exposing the underlying CW20/tokenfactory address prominently (already done via `Cw721Address`/similar fields) and encourage wallets/integrators to key off address rather than name/symbol, but this does not eliminate the on-chain spoofing risk, so input sanitization at pointer-creation time is the primary mitigation.

### Proof of Concept
1. Deploy a CW20 contract (e.g. via `x/wasm` `MsgInstantiateContract`) with `token_info` returning `name: "USDС"` (using Cyrillic "С" instead of Latin "C") and `symbol: "USDC"` — indistinguishable from real USDC in most fonts/UIs.
2. Call the pointer precompile's `addCW20Pointer(cwAddr)` from any EVM account; per `AddCW20` in [6](#0-5) , this deploys a real ERC20 pointer contract whose `name()`/`symbol()` return the spoofed strings, with no rejection.
3. Present the new pointer contract address to users/integrators as "USDC"; a user comparing displayed name/symbol (not address) cannot distinguish it from the legitimate USDC pointer, and may approve/transfer funds to the fake token contract, resulting in fund loss.

func (p PrecompileExecutor) AddNative(ctx sdk.Context, method *ethabi.Method, caller common.Address, args []interface{}, value *big.Int, evm *vm.EVM, hooks *tracing.Hooks) (ret []byte, remainingGas uint64, err error) {
	if err := pcommon.ValidateNonPayable(value); err != nil {
		return nil, 0, err
	}
	if err := pcommon.ValidateArgsLength(args, 1); err != nil {
		return nil, 0, err
	}
	token := args[0].(string)
	metadata, metadataExists := p.bankKeeper.GetDenomMetaData(ctx, token)
	if !metadataExists {
		return nil, 0, fmt.Errorf("denom %s does not have metadata stored and thus can only have its pointer set through gov proposal", token)
	}
	name := metadata.Name
	symbol := metadata.Symbol
	var decimals uint8
	for _, denomUnit := range metadata.DenomUnits {
		if denomUnit.Exponent > uint32(decimals) && denomUnit.Exponent <= math.MaxUint8 {
			decimals = uint8(denomUnit.Exponent)
			name = denomUnit.Denom
			symbol = denomUnit.Denom
			if len(denomUnit.Aliases) > 0 {
				name = denomUnit.Aliases[0]
			}
		}
	}
	contractAddr, err := p.evmKeeper.UpsertERCNativePointer(ctx, evm, token, utils.ERCMetadata{Name: name, Symbol: symbol, Decimals: decimals})
	if err != nil {
		return nil, 0, err
	}

	ret, err = method.Outputs.Pack(contractAddr)
	remainingGas = pcommon.GetRemainingGas(ctx, p.evmKeeper)
	return

func (p PrecompileExecutor) AddCW20(ctx sdk.Context, method *ethabi.Method, caller common.Address, args []interface{}, value *big.Int, evm *vm.EVM, hooks *tracing.Hooks) (ret []byte, remainingGas uint64, err error) {
	if err := pcommon.ValidateNonPayable(value); err != nil {
		return nil, 0, err
	}
	if err := pcommon.ValidateArgsLength(args, 1); err != nil {
		return nil, 0, err
	}
	cwAddr := args[0].(string)
	cwAddress, err := sdk.AccAddressFromBech32(cwAddr)
	if err != nil {
		return nil, 0, err
	}
	res, err := p.wasmdKeeper.QuerySmartSafe(ctx, cwAddress, []byte("{\"token_info\":{}}"))
	if err != nil {
		return nil, 0, err
	}
	formattedRes := map[string]interface{}{}
	if err := json.Unmarshal(res, &formattedRes); err != nil {
		return nil, 0, err
	}
	name := formattedRes["name"].(string)
	symbol := formattedRes["symbol"].(string)
	contractAddr, err := p.evmKeeper.UpsertERCCW20Pointer(ctx, evm, cwAddr, utils.ERCMetadata{Name: name, Symbol: symbol})
	if err != nil {
		return nil, 0, err
	}

	ret, err = method.Outputs.Pack(contractAddr)
	remainingGas = pcommon.GetRemainingGas(ctx, p.evmKeeper)
	return
}
