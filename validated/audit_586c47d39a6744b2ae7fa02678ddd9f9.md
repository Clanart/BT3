### Title
Improper Input Validation via Silent Corruption Handling in `LazyFieldLite` - (File: `java/core/src/main/java/com/google/protobuf/LazyFieldLite.java`)

### Summary
The Apache CXF advisory describes a caching layer (the STS) that fails to re-validate a SAML token once it is cached, so an invalid token is treated as valid. The closest transferable analog in this checkout is Protobuf Java Lite's `LazyFieldLite`, which caches the *result* of parsing an attacker-controlled, length-delimited embedded message (used for `[lazy=true]` fields and MessageSet extensions). When the embedded bytes fail to parse, `LazyFieldLite` does not propagate the failure or mark the field in any caller-visible way — it silently substitutes and *caches* the default instance, so every subsequent read of that field reports "valid, empty" data instead of the fact that validation failed [1](#0-0) .

### Finding Description
`LazyFieldLite.ensureInitialized(MessageLite defaultInstance)` lazily parses `delayedBytes` (attacker-controlled bytes from the wire) the first time the field is accessed [2](#0-1) . If parsing throws `InvalidProtocolBufferException`, the catch block sets `corrupted = true` but then unconditionally caches `value = defaultInstance` and `memoizedBytes = ByteString.EMPTY`, and the exception is swallowed — the comment explicitly documents this: "Nothing is logged and no exceptions are thrown. Clients will be unaware that this proto was invalid." [3](#0-2) 

The `corrupted` flag is only exposed via the package-private `isCorrupted()` accessor [4](#0-3) , which is not reachable from the public `getValue()`/`getValue(MessageLite)` API that ordinary generated-code getters and `equals()`/`toByteString()` use [5](#0-4) . Because `value`/`memoizedBytes` are memoized once set, this substitution is permanent for the life of the object — i.e., the "invalid input was cached as valid" pattern that CVE-2014-0034 describes for STS/SAML.

Notably, the newer sibling class `InternalLazyField` recognizes this exact class of bug and, in its new code path, converts the swallowed exception into a thrown `InvalidProtobufRuntimeException` when `extensionRegistry.lazyExtensionEnabled()` is true [6](#0-5) , but explicitly preserves the "old behavior: silently return the default instance" for compatibility [7](#0-6) . `LazyFieldLite` (still the implementation backing Lite-runtime extensions and MessageSet fields) has no such opt-in and always takes the silent path.

### Impact Explanation
An ordinary client calling the public `parseFrom`/`mergeFrom` API on a Lite message containing a `[lazy=true]` message field or a MessageSet-style extension can supply an outer message that parses "successfully" while an inner, attacker-controlled sub-message is corrupt/malformed. Any application logic that reads that field via the normal getter (`getValue()`) observes a default/empty instance with no indication that the bytes were invalid — indistinguishable from a legitimately-absent field. Applications that make security- or business-relevant decisions based on presence/content of such a lazily-parsed field (e.g., an authorization or metadata extension) would silently treat attacker-supplied garbage as "field absent/default," mirroring the CXF flaw where an invalid token was accepted because the validation failure was not surfaced once the value was cached.

### Likelihood Explanation
Reachable via fully public, documented Protobuf-Lite APIs (`parseFrom`, extension getters) with a schema that legitimately uses `lazy = true` fields or MessageSet extensions — no privileged access or hostile schema required, only attacker control over the bytes of one embedded sub-message within an otherwise well-formed, bounded input. The bug is deterministic and confirmed directly in source, not inferred from a crash or sanitizer signal.

### Recommendation
Either (a) propagate corruption to callers of `LazyFieldLite.getValue()`/`getValue(MessageLite)` by throwing (mirroring `InternalLazyField`'s new `lazyExtensionEnabled()` path) instead of silently caching `defaultInstance`, or (b) expose `isCorrupted()` publicly so consuming code can detect and reject messages containing corrupted lazy fields, and document that reflection-based/generated getters must check it before trusting a lazily-parsed field's "default" value.

### Proof of Concept
Construct an outer Lite message that carries a `[lazy=true]` field (or MessageSet extension) whose length-delimited payload has a valid varint length but bytes that are not a valid encoding of the target message type (e.g., a random/truncated byte sequence of that length). Parsing the outer message via the public `parseFrom` succeeds with no exception (the corrupt bytes are stored in `delayedBytes`, unparsed). Calling the generated getter for that field triggers `ensureInitialized`, which catches the resulting `InvalidProtocolBufferException` internally and returns the default instance from then on [8](#0-7) ; there is no public signal that the original bytes were invalid, and repeated calls to `getValue()`/`equals()` consistently report the cached default instance as if it were legitimate.

  /** Might lazily parse the bytes that were previously passed in. Is thread-safe. */
  protected void ensureInitialized(MessageLite defaultInstance) {
    if (value != null) {
      return;
    }
    synchronized (this) {
      if (value != null) {
        return;
      }
      try {
        if (delayedBytes != null) {
          // The extensionRegistry shouldn't be null here since we have delayedBytes.
          MessageLite parsedValue =
              defaultInstance.getParserForType().parseFrom(delayedBytes, extensionRegistry);
          this.value = parsedValue;
          this.memoizedBytes = delayedBytes;
        } else {
          this.value = defaultInstance;
          this.memoizedBytes = ByteString.EMPTY;
        }
      } catch (InvalidProtocolBufferException e) {
        // Nothing is logged and no exceptions are thrown. Clients will be unaware that this proto
        // was invalid.
        this.corrupted = true;
        this.value = defaultInstance;
        this.memoizedBytes = ByteString.EMPTY;
      }
    }
  }
