### Title
Tokenfactory denom allow-list access control is enforced only in the `MsgSend`/`MsgMultiSend` handlers, not in the underlying `SendKeeper` methods, allowing bypass via any direct caller of `SendCoins`/`InputOutputCoins` - (File: sei-cosmos/x/bank/keeper/send.go)

### Summary
The tokenfactory "denom allow list" is bank's per-denom transfer restriction feature (an issuer can restrict `factory/...` denoms to only be sent/received by a whitelisted set of addresses). This access-control check is only enforced at the outer `MsgServer.Send` / `MsgServer.MultiSend` layer, not inside the lower-level `BaseSendKeeper` transfer primitives that many other subsystems (precompiles, CosmWasm bindings, other keepers) call directly. This is structurally the same bug class as GHSA-6h67-934r-82g7: an access-control check ("who may access/transfer this field/denom") is implemented as a wrapper around one entry point instead of inside the shared data-mutation function, so any other caller of the underlying primitive silently bypasses the restriction.

### Finding Description
`BaseSendKeeper.IsInDenomAllowList` is the sole gate that enforces the tokenfactory denom allow-list restriction [1](#0-0)  (duplicated in the giga xbank deps copy as well). It is invoked explicitly in the bank `MsgServer.Send` and `MsgServer.MultiSend` handlers before calling the transfer primitives: [2](#0-1)  and [3](#0-2) .

However, the actual transfer logic lives in `BaseSendKeeper.SendCoins`, `SendCoinsWithoutAccCreation`, `sendCoinsWithoutAccCreation`, and `InputOutputCoins`, none of which call `IsInDenomAllowList` themselves: [4](#0-3) . These methods are exposed on the public `SendKeeper` interface [5](#0-4)  and are the standard integration point used by every other module/precompile/CosmWasm binding that needs to move coins (e.g. EVM bank precompile transfers, CW bank bindings, IBC transfer handlers, tokenfactory mint/burn-adjacent flows, module-to-account payouts, etc.).

Because the allow-list check is bolted onto the `MsgSend`/`MsgMultiSend` RPC handlers rather than into the shared `SendCoins`/`InputOutputCoins` primitives, any code path that reaches the bank keeper's transfer methods without going through those two specific message handlers completely bypasses the field-level (denom-level) access control — mirroring the strapi-plugin-protected-populate flaw where the field-security check lived in one wrapper and could be sidestepped by any other call path into the underlying populate logic.

### Impact Explanation
If a tokenfactory denom owner has configured a restricted allow-list (e.g. to comply with regulatory/compliance requirements or to gate a permissioned asset), any caller that invokes `SendCoins`/`InputOutputCoins` directly — such as the EVM bank precompile, CosmWasm bank bindings, or any other module keeper that performs a bank transfer on behalf of a user/contract — can move the restricted denom to/from addresses that are not on the allow-list, defeating the intended access control. This is an unauthorized-transfer-style bypass of an on-chain enforced restriction (fund movement in violation of issuer-configured denom controls), which matches the "unauthorized transfer" impact class.

### Likelihood Explanation
High likelihood of reachability: `SendCoins` and `InputOutputCoins` are the canonical, most widely used bank transfer primitives in the codebase and are called from many entry points besides `MsgSend`/`MsgMultiSend` (precompiles, wasm bindings, other keepers). Any of these callers moving a `factory/`-prefixed denom will silently skip the allow-list enforcement, since the check is not embedded in the shared primitive.

### Recommendation
Move the `IsInDenomAllowList` check (and blocked-address check) into the shared `BaseSendKeeper.SendCoins`/`sendCoinsWithoutAccCreation`/`InputOutputCoins` implementations so that the restriction is enforced regardless of caller, rather than relying on each individual message handler to remember to call it. Alternatively, audit every non-`MsgSend`/`MsgMultiSend` caller of these primitives (precompiles, wasm bindings, keepers) and explicitly add the allow-list check there.

### Proof of Concept
Not independently confirmed against a specific precompile/wasm-binding call site in this pass due to tool-call limits — the analysis is based on the confirmed fact that `IsInDenomAllowList` is called only in `sei-cosmos/x/bank/keeper/msg_server.go` (`Send`, `MultiSend`) and is absent from `SendCoins`/`SendCoinsWithoutAccCreation`/`InputOutputCoins` in `sei-cosmos/x/bank/keeper/send.go`. A concrete PoC would require identifying a reachable EVM precompile or CosmWasm binding that calls `BankKeeper.SendCoins`/`InputOutputCoins` directly with a restricted tokenfactory denom and demonstrating the transfer succeeds despite the sender/recipient not being on the denom's allow-list — this should be verified with full repository access (e.g., a Devin session) since the index used here does not guarantee full coverage of every precompile/binding call site.

// InputOutputCoins performs multi-send functionality. It accepts a series of
// inputs that correspond to a series of outputs. It returns an error if the
// inputs and outputs don't lineup or if any single transfer of tokens fails.
func (k BaseSendKeeper) InputOutputCoins(ctx sdk.Context, inputs []types.Input, outputs []types.Output) error {
	// Safety check ensuring that when sending coins the keeper must maintain the
	// Check supply invariant and validity of Coins.
	if err := types.ValidateInputsOutputs(inputs, outputs); err != nil {
		return err
	}
	for _, in := range inputs {
		inAddress, err := sdk.AccAddressFromBech32(in.Address)
		if err != nil {
			return err
		}

		err = k.SubUnlockedCoins(ctx, inAddress, in.Coins, true)
		if err != nil {
			return err
		}

		ctx.EventManager().EmitEvent(
			sdk.NewEvent(
				sdk.EventTypeMessage,
				sdk.NewAttribute(types.AttributeKeySender, in.Address),
			),
		)
	}

	for _, out := range outputs {
		outAddress, err := sdk.AccAddressFromBech32(out.Address)
		if err != nil {
			return err
		}
		err = k.AddCoins(ctx, outAddress, out.Coins, true)
		if err != nil {
			return err
		}

		ctx.EventManager().EmitEvent(
			sdk.NewEvent(
				types.EventTypeTransfer,
				sdk.NewAttribute(types.AttributeKeyRecipient, out.Address),
				sdk.NewAttribute(sdk.AttributeKeyAmount, out.Coins.String()),
			),
		)

		// Create account if recipient does not exist.
		//
		// NOTE: This should ultimately be removed in favor a more flexible approach
		// such as delegated fee messages.
		accExists := k.ak.HasAccount(ctx, outAddress)
		if !accExists {
			defer func() {
				recordNewAccounts(ctx.Context(), 1)
			}()
			k.ak.SetAccount(ctx, k.ak.NewAccountWithAddress(ctx, outAddress))
		}
	}

	return nil
}

	if !accExists {
		defer func() {

		}()
		k.ak.SetAccount(ctx, k.ak.NewAccountWithAddress(ctx, toAddr))

// recordNewAccounts dual-emits the legacy new-account counter and its OTel
// counterpart (bank_new_account). Runs from consensus-critical send paths, so
// a telemetry fault here must not panic into the caller.
func recordNewAccounts(ctx context.Context, count int64) {
	if count <= 0 {
		return
	}
	defer func() {
		if e := recover(); e != nil {
			fmt.Fprintf(os.Stderr, "telemetry panic: %v\n%s", e, debug.Stack())
		}
	}()
	// TODO(PLT-353): remove once bank_new_account verified
	telemetry.IncrCounter(float32(count), "new", "account")
	bankMetrics.newAccount.Add(ctx, count)
}

func (k BaseSendKeeper) sendCoinsWithoutAccCreation(ctx sdk.Context, fromAddr sdk.AccAddress, toAddr sdk.AccAddress, amt sdk.Coins, checkNeg bool) error {

		return err
	}

	if err != nil {
		return err

			sdk.NewAttribute(types.AttributeKeyRecipient, toAddr.String()),

		),
		sdk.NewEvent(
			sdk.EventTypeMessage,
			sdk.NewAttribute(types.AttributeKeySender, fromAddr.String()),
		),
	})

	return nil
}

	store := ctx.KVStore(k.storeKey)
	store = prefix.NewStore(store, types.DenomAllowListKey(denom))

	bz := store.Get([]byte(denom))
	if bz == nil {
		return types.AllowList{}

	var allowList types.AllowList
	k.cdc.MustUnmarshal(bz, &allowList)

	return allowList
}

func (k msgServer) Send(goCtx context.Context, msg *types.MsgSend) (*types.MsgSendResponse, error) {
	ctx := sdk.UnwrapSDKContext(goCtx)

	if err := k.IsSendEnabledCoins(ctx, msg.Amount...); err != nil {
		return nil, err
	}

	from, err := sdk.AccAddressFromBech32(msg.FromAddress)
	if err != nil {
		return nil, err
	}
	to, err := sdk.AccAddressFromBech32(msg.ToAddress)
	if err != nil {
		return nil, err
	}

	allowListCache := make(map[string]AllowedAddresses)
	if !k.IsInDenomAllowList(ctx, from, msg.Amount, allowListCache) {
		return nil, sdkerrors.Wrapf(sdkerrors.ErrUnauthorized, "%s is not allowed to send funds", msg.FromAddress)
	}

	if k.BlockedAddr(to) || !k.IsInDenomAllowList(ctx, to, msg.Amount, allowListCache) {
		return nil, sdkerrors.Wrapf(sdkerrors.ErrUnauthorized, "%s is not allowed to receive funds", msg.ToAddress)
	}

	err = k.SendCoins(ctx, from, to, msg.Amount)
	if err != nil {
		return nil, err
	}

func (k msgServer) MultiSend(goCtx context.Context, msg *types.MsgMultiSend) (*types.MsgMultiSendResponse, error) {
	ctx := sdk.UnwrapSDKContext(goCtx)
	denomToAllowListCache := make(map[string]AllowedAddresses)
	// NOTE: totalIn == totalOut should already have been checked
	for _, in := range msg.Inputs {
		if err := k.IsSendEnabledCoins(ctx, in.Coins...); err != nil {
			return nil, err
		}
		accAddr := sdk.MustAccAddressFromBech32(in.Address)
		if !k.IsInDenomAllowList(ctx, accAddr, in.Coins, denomToAllowListCache) {
			return nil, sdkerrors.Wrapf(sdkerrors.ErrUnauthorized, "%s is not allowed to send funds", accAddr)
		}
	}

	for _, out := range msg.Outputs {
		accAddr := sdk.MustAccAddressFromBech32(out.Address)

		if k.BlockedAddr(accAddr) || !k.IsInDenomAllowList(ctx, accAddr, out.Coins, denomToAllowListCache) {
			return nil, sdkerrors.Wrapf(sdkerrors.ErrUnauthorized, "%s is not allowed to receive funds", out.Address)
		}
	}

	err := k.InputOutputCoins(ctx, msg.Inputs, msg.Outputs)
	if err != nil {
		return nil, err
	}
