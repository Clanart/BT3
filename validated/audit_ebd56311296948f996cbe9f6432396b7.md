### Title
Unspendable Bitcoin payment scripts are accepted as transaction recipients - ([File: `networks/bitcoin/src/wallet/send.rs`](networks/bitcoin/src/wallet/send.rs))

### Summary
`SignableTransaction::new` accepts payment destinations as arbitrary `ScriptBuf` values and only validates each payment amount against the dust threshold before embedding the script directly into a transaction output. [1](#0-0) 

### Finding Description
The payment parameter is `&[(ScriptBuf, u64)]`, so callers can supply any consensus-encodable output script rather than a constrained address type. [2](#0-1)  The only per-payment validation checks `amount < DUST`; it never checks that `script_pubkey` is a recognized, spendable output type or rejects provably unspendable scripts such as `OP_RETURN`. [3](#0-2)  The supplied script is copied verbatim into the transaction output list. [4](#0-3) 

### Impact Explanation
A request specifying an `OP_RETURN` script or a malformed witness output can produce a valid `SignableTransaction`, causing the threshold wallet to sign a transaction whose payment is irrecoverably burned. [5](#0-4)  This is the Bitcoin-wallet analogue of minting to address zero: value is transferred successfully on-chain, but no private key or valid spend path exists for the recipient output. [4](#0-3) 

### Likelihood Explanation
Any caller capable of supplying the public payment list can trigger this by providing an above-dust amount and an unspendable script; no control of validators, peers, keys, or private state is required. [6](#0-5) 

### Recommendation
Reject empty, provably unspendable, malformed, and otherwise unsupported payment scripts in `SignableTransaction::new`, and accept a validated Bitcoin address representation instead of raw `ScriptBuf` where possible. [1](#0-0)  At minimum, reject `script_pubkey.is_op_return()` for value-bearing payments and validate witness version/program length and P2TR point validity before creating outputs. [4](#0-3) 

### Proof of Concept
```rust
use bitcoin::{
  script::{Builder, PushBytesBuf},
  opcodes::all::OP_RETURN,
};
use bitcoin_serai::wallet::{ReceivedOutput, SignableTransaction};

// `input` is a spendable ReceivedOutput worth at least `amount + fee`.
let input: ReceivedOutput = /* scanner output */;

let burn_script = Builder::new()
  .push_opcode(OP_RETURN)
  .push_slice(PushBytesBuf::try_from(b"burn".to_vec()).unwrap())
  .into_script();

// This succeeds because only the payment amount is validated.
let signable = SignableTransaction::new(
  vec![input],
  &[(burn_script, 10_000)],
  None,
  None,
  1,
).unwrap();

// The resulting transaction contains a positive-value OP_RETURN output.
assert!(signable.transaction().output[0].value.to_sat() >= 10_000);
assert!(signable.transaction().output[0].script_pubkey.is_op_return());
```
