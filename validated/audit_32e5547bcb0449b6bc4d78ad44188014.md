### Title
Server-Side Request Forgery via unauthenticated DataLayer mirror URLs - (File: `chia/data_layer/download_data.py`)

### Summary
Chia's DataLayer subsystem lets any wallet holder publish arbitrary "mirror" URLs on-chain for a store via a simple coin spend, with no scheme/host validation. Any DataLayer client that subscribes to that store will have its own node automatically make outbound HTTP requests to those attacker-chosen URLs when syncing, mirroring the class of bug in the Recurly `Resource#find` SSRF (CVE-2017-0905): server-side code performs outbound requests to a URL taken from untrusted, remotely supplied input.

### Finding Description
A mirror coin is created by spending to `create_mirror_puzzle()` with memos `[launcher_id, *urls]` — this can be done by anyone with funds, no special permission required: [1](#0-0) [2](#0-1) 

When any DataLayer node observes such a mirror coin for a launcher/store it is tracking, it parses the raw memo bytes directly into `Mirror.urls` with no validation of scheme or destination: [3](#0-2) 

Those mirror URLs are then merged into the local subscription's `servers_info` list: [4](#0-3) 

The `fetch_and_validate` sync loop selects one of these attacker-controlled `server_info.url` values and passes it to `insert_from_delta_file` → `download_file` → `http_download`, which performs an unrestricted `aiohttp` GET directly against the URL: [5](#0-4) [6](#0-5) 

There is no allow-list, no restriction on scheme (`http`/`https` only would still allow SSRF against internal hosts), no restriction on target IP ranges (loopback, link-local, RFC1918, cloud metadata endpoints like `169.254.169.254`), and no DNS-rebinding protection. The only validation performed anywhere in this path is on the URL *list emptiness* (`add_mirror` requires non-empty urls) and later on the *response* (max delta file size), not on the destination itself: [7](#0-6) 

This mirrors exactly the SSRF bug class in the report: a remote/untrusted party supplies a URL (via `Resource#find`/here via an on-chain mirror memo) that is then fetched by the victim's server-side process, with no destination validation.

### Impact Explanation
Any user who can afford a small coin spend can publish a store with malicious mirror URLs (e.g. `http://169.254.169.254/latest/meta-data/iam/security-credentials/`, `http://127.0.0.1:<internal-port>/`, or other internal-only endpoints reachable from the DataLayer host). Any other DataLayer operator who subscribes to (or otherwise tracks/syncs) that store will have their node automatically issue outbound HTTP requests to attacker-chosen destinations as part of normal sync (`fetch_and_validate`), with node-controlled headers and following the response back into disk (subject to the `max_delta_file_size` guard, then treated as delta-file content and parsed). This can be used to:
- Probe/attack internal network services and cloud metadata endpoints reachable from the operator's DataLayer node, potentially exfiltrating cloud credentials.
- Cause the node to make requests to a wide range of arbitrary internal or external targets, which combined with the plugin `downloader` POST call (`get_downloader`) also forwards a `server_info.url` field into third-party plugin services.

This is a real network-reachable SSRF triggerable purely by an unprivileged "Data Layer client" subscribing to a store controlled by any other user, matching the report's "unprivileged...Data Layer client" reachability class.

### Likelihood Explanation
Likelihood is high given normal DataLayer operation: subscribing to a store and syncing it is a core, expected user action, and the mirror-URL feature is explicitly designed to let store owners publish alternate download servers. No special crafting of spend-bundle internals beyond a standard coin spend with the mirror puzzle is needed, and the mirror URL is never validated for scheme or destination anywhere in the flow shown.

### Recommendation
- Validate and restrict mirror URLs before they are stored/used: enforce `http(s)` scheme only, and resolve/deny requests to private, loopback, link-local, and cloud-metadata IP ranges (defense against DNS rebinding as well, e.g. by validating the resolved IP at connection time, not just the hostname).
- Apply this validation both when a mirror is recorded from chain data (`DataLayerWallet.coin_added` / `get_mirror_info`) and again immediately before use in `http_download` / `download_file` / `get_downloader`, since the DB-stored mirror list could otherwise still contain unsafe values from before validation was added.
- Consider requiring explicit user opt-in/allow-listing of external mirror servers per store rather than automatically trusting any URL discovered on-chain.

### Proof of Concept
1. Attacker creates a DataLayer store and publishes a mirror coin with `urls=["http://169.254.169.254/latest/meta-data/"]` via the standard `dl_new_mirror` / `add_mirror` RPC flow (`chia/data_layer/data_layer_rpc_api.py:add_mirror` → `DataLayer.add_mirror` → `dl_new_mirror`).
2. Victim runs a DataLayer node and subscribes to / tracks the attacker's store (normal operator workflow, e.g. via `DLTrackNew`/subscribe).
3. Victim's node observes the mirror coin in `DataLayerWallet.coin_added`, decodes the URL with no validation, and stores it as an available server (`chia/data_layer/data_layer.py:979-985`).
4. On the next sync cycle, `DataLayer.fetch_and_validate` selects this URL and `http_download` (`chia/data_layer/download_data.py:298-320`) issues `GET http://169.254.169.254/latest/meta-data/<filename>` from the victim's node, potentially leaking cloud instance metadata/credentials or probing internal services, entirely driven by attacker-controlled on-chain data.

def create_mirror_puzzle() -> Program:
    return P2_PARENT.curry(Program.to(1))


MIRROR_PUZZLE_HASH = create_mirror_puzzle().get_tree_hash()


def get_mirror_info(
    parent_puzzle: Program | SerializedProgram, parent_solution: Program | SerializedProgram
) -> tuple[bytes32, list[bytes]]:
    assert type(parent_puzzle) is type(parent_solution)
    _, conditions = run_with_cost(parent_puzzle, INFINITE_COST, parent_solution)
    for condition in conditions.as_iter():
        if (
            condition.first().as_python() == ConditionOpcode.CREATE_COIN
            and condition.at("rf").as_python() == create_mirror_puzzle().get_tree_hash()
        ):
            memos: list[bytes] = condition.at("rrrf").as_python()
            launcher_id = bytes32(memos[0])
            return launcher_id, [url for url in memos[1:]]

async def http_download(
    target_filename_path: Path,
    filename: str,
    proxy_url: str | None,
    server_info: ServerInfo,
    timeout: aiohttp.ClientTimeout,
    log: logging.Logger,
    max_delta_file_size: int,
) -> None:
    """
    Download a file from a server using aiohttp.
    Raises exceptions on errors
    """
    async with aiohttp.ClientSession() as session:
        headers = {"accept-encoding": "gzip"}
        async with session.get(
            server_info.url + "/" + filename,
            headers=headers,
            timeout=timeout,
            proxy=proxy_url,
        ) as resp:
            resp.raise_for_status()
