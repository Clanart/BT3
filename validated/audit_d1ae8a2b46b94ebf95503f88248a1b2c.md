### Title
Command Injection via Unescaped Repository Path in Shell Launch Command Strings - ([File: app/src/lib/shells/win32.ts])

### Summary
`extra-ffmpeg`'s flaw was building a shell command string from unsanitized user input and executing it. GitHub Desktop has a structurally identical pattern in its "Open in Shell" feature on Windows: several shell launchers build a command-line string by directly interpolating the repository's local folder path into a template literal and executing it with Node's `child_process.spawn(..., { shell: true })`, which on Windows delegates parsing to `cmd.exe`. The interpolated value is never passed through the project's own shell-escaping utility (`app/src/lib/hooks/shell-escape.ts`), which exists specifically to prevent this class of bug for git hooks but is not reused here.

### Finding Description
`launch()` in [1](#0-0)  constructs command strings for GitBash, Cygwin, Warp, Alacritty, Hyper, and PowerShell by embedding the working-directory `path` directly into a quoted template-literal argument, e.g.:

```ts
case Shell.GitBash:
  return spawn(gitBashPath, [`--cd="${path}"`], { shell: true, cwd: path })
case Shell.Cygwin:
  return spawn(cygwinPath, [`/bin/sh -lc 'cd "$(cygpath "${path}")"; exec bash'`], { shell: true, cwd: path })
case Shell.Warp:
  return spawn(warpPath, [`warp://action/new_tab?path="${path}"`], { shell: true, cwd: path })
``` [2](#0-1) 

Because `shell: true` causes Node to hand the whole reconstructed command line to `cmd.exe /d /s /c`, wrapping `path` in manually-typed double quotes does **not** neutralize `cmd.exe` metacharacters (`&`, `|`, `^`, `%`) that can appear inside an otherwise-quoted argument on the Windows command line — this is the same "insecure command formatting" root cause cited in the original report. Contrast this with `app/src/lib/hooks/shell-escape.ts`, which implements dedicated `cmdEscape`/`powershellEscape` functions precisely because naive quoting is insufficient [3](#0-2) ; that escaping is applied only to the git-hooks proxy path, not to `launch()`.

The `path` value passed to `launch()` originates from `repository.path`, set via `dispatcher.openShell(repository.path)` [4](#0-3)  → `appStore._openShell` → `launchShell` [5](#0-4) . That folder path is derived, at clone time, from `sanitizeCloneName()` [6](#0-5) , which only guards against path traversal (rejects `..`, strips `/`, `\`, `:`) and does **not** strip `cmd.exe` metacharacters such as `&`, `%`, `^`, `(`, `)`, all of which are legal characters in Windows/NTFS filenames.

### Impact Explanation
If a victim clones or opens a repository whose local folder name contains `cmd.exe` metacharacters, then uses "Open in [Shell]" (menu item `open-in-shell`, wired in `build-default-menu.ts` [7](#0-6) ) with GitBash, Cygwin, Warp, or a similarly affected shell configured, the injected metacharacters can terminate the intended argument and chain an attacker-controlled command, achieving arbitrary code execution in the context of the logged-in Desktop user. This satisfies the "attacker controls a cloned/fetched repository ... resulting in code execution" impact class from the program scope.

### Likelihood Explanation
Exploitation requires: (1) the victim clones/opens a repository whose destination folder name contains shell metacharacters, and (2) the victim explicitly invokes "Open in Shell" for that repository with an affected shell selected. Because GitHub.com repository names are restricted to `[A-Za-z0-9_.-]`, the strongest path is the "URL"/generic clone tab or a directly-typed/renamed local folder rather than a GitHub-hosted repo name — I was unable to confirm, within the available index, a deep-link or GitHub API object that lets a remote attacker fully control the destination folder name end-to-end without any local action from the user (e.g., manually renaming the folder or typing a crafted path in the generic clone dialog). This uncertainty reduces confidence that the "attacker fully remote, no unusual user step" bar is met, so likelihood should be treated as moderate rather than confirmed until that path is traced further (ideally with a live/dynamic environment, which is outside what static indexing can confirm).

### Recommendation
- Reuse the existing `quoteCommand`/`cmdEscape`/`powershellEscape` helpers from `app/src/lib/hooks/shell-escape.ts` in every `launch()` implementation in `app/src/lib/shells/win32.ts` (and audit `darwin.ts`/`linux.ts` for the same pattern) instead of ad hoc template-literal quoting.
- Avoid `shell: true` entirely where possible; pass `path` as a discrete array element to `spawn` so Node/Windows quoting is applied consistently instead of manual string building.
- Extend `sanitizeCloneName` (or add a directory-name sanitation step at clone/open time) to strip or reject shell metacharacters in addition to path-traversal characters.

### Proof of Concept
1. Attacker gets a victim to clone (via the "URL" tab or a generic git remote) or otherwise obtain a working directory literally named, e.g., `repo & calc.exe &`. This is not blocked by `sanitizeCloneName`, which only checks for `/ \ : ..` [6](#0-5) .
2. Victim adds this local folder as a repository in Desktop and selects Git Bash (or Cygwin/Warp) as their shell.
3. Victim clicks Repository → "Open in Git Bash" (`open-in-shell` menu item).
4. `launch()` builds `spawn(gitBashPath, ['--cd="repo & calc.exe &"'], { shell: true, ... })` [8](#0-7) ; when `cmd.exe` parses the resulting command line, `&` terminates the `--cd=` argument and starts a new command, executing `calc.exe` (or any attacker payload) with the victim's privileges.

const cmdEscape = (arg: string) =>
  arg
    .replace(/[\0\u0008\r\u001B\u009B]/gu, '')
    .replace(/\n/gu, ' ')
    .replace(/"/gu, '""')
    .replace(/([%&<>^|])/gu, '"^$1"')

export const cmd: Shell = {
  args: ['/d', '/s', '/c'],
  quoteCommand: (cmd, ...args) =>

export function sanitizeCloneName(name: string): string | null {
  const components = name.split(/[/\\:]/)

  let lastComponent = ''
  for (let i = components.length - 1; i >= 0; i--) {
    if (components[i].length > 0) {
      lastComponent = components[i]
      break
    }
  }

  if (lastComponent.length === 0) {
    return null
  }

  if (lastComponent.endsWith('.git')) {
    lastComponent = lastComponent.slice(0, -4)
  }

  if (
    lastComponent === '..' ||
    lastComponent === '.' ||
    lastComponent.length === 0
  ) {
    return null
  }

  return lastComponent
}
