### Title
Governing node can set `governance.unitprice` to an unbounded value, permanently DOSing transaction admission - (File: kaiax/gov/param.go)

### Summary
The `governance.unitprice` governance parameter, which sets the mandatory gas price for all pre-Magma (legacy-priced) transactions, has no upper-bound or sanity check on its value. A governing node (the sole voter in `single` governance mode) can vote this parameter up to `math.MaxUint64`, and every honest node will adopt it as the pool's `gasPrice`. Because transaction admission strictly requires `tx.GasPrice() == pool.gasPrice` (pre-Magma) or `tx.GasPrice() >= pool.gasPrice` (post-Magma), an extreme unit price makes it economically/practically impossible for any account to submit or pay for a transaction, DOSing transaction admission network-wide — directly analogous to the reported "Admin can DOS with fees" pattern.

### Finding Description
`governance.unitprice` is defined with `FormatChecker: noopFormatChecker`, meaning any `uint64` value is accepted without an upper bound, unlike sibling parameters that do enforce bounds (e.g. `GovernanceDeriveShaImpl` requires `v <= 2`, `IstanbulCommitteeSize` requires `v > 0`): [1](#0-0) 

By contrast, KIP-71 base fee bounds at least have a cross-field consistency check (`lowerbound <= upperbound`) enforced in header governance: [2](#0-1) 

No equivalent consistency or magnitude check exists for `GovernanceUnitPrice` in `checkConsistency`: [3](#0-2) 

The resulting `ParamSet.UnitPrice` is fed directly into the transaction pool's required gas price with no additional bound checking: [4](#0-3) 

Transaction validation then strictly enforces this value for legacy-priced transactions (pre-Magma), rejecting any transaction whose `GasPrice()` doesn't exactly match it: [5](#0-4) 

If the governing node votes an astronomically large `unitprice` (e.g., near `2^64-1`), `pool.gasPrice` becomes that value on all nodes. Since `tx.GasPrice()` is capped by practical/economic limits (an account would need `gas * gasPrice` in balance, and gas price itself is transmitted as a real cost), no ordinary account can construct a transaction satisfying `tx.GasPrice() == pool.gasPrice`, so essentially all transaction types — including fee-delegated and fee-delegated-with-ratio transactions, which also rely on this same gas-price equality check pre-Magma — become unadmittable.

### Impact Explanation
This is a chain-wide denial of service on the transaction-admission path. Once the governing node casts a single vote at an epoch boundary, all honest nodes converge on the same extreme `UnitPrice`/`gasPrice`, and legitimate users, fee payers, and fee-delegation counterparties can no longer get any legacy-priced transaction accepted into the pool or block. This blocks ordinary value transfers, contract calls, gasless/fee-delegation flows, and any protocol operation gated by paying the network's minimum gas price — a concrete, unauthorized disruption of the network's core liveness for transaction submission, matching the "Medium/DOS-with-fees" bug class in the report.

### Likelihood Explanation
The action requires control of the governing node (the entity legitimately authorized to vote governance parameters in `single` mode, analogous to the "admin" role in the referenced report). No cryptographic exploit, malicious peer, or consensus bug is needed — it's a single legitimate governance vote that the code fails to bound-check, so the likelihood of this being reachable is high if the governing node key is used incorrectly, is compromised, or is otherwise induced to cast such a vote (accidentally or maliciously). The lack of any sanity ceiling in `param.go` means this is a straightforward path once such a vote is cast and passes the (currently absent) bound validation.

### Recommendation
Add an explicit sanity/format check (`FormatChecker`) for `GovernanceUnitPrice` bounding it to a reasonable maximum (analogous to the existing bound relationship enforced between `Kip71LowerBoundBaseFee` and `Kip71UpperBoundBaseFee`), and/or add a `checkConsistency` case for `gov.GovernanceUnitPrice` in `kaiax/gov/headergov/impl/header.go` that rejects unreasonably large values before they are accepted into governance history.

### Proof of Concept
1. In `single` governance mode, the governing node casts a vote `{name: "governance.unitprice", value: uint64(math.MaxUint64)}` at an epoch block. `NewVoteData`/`VerifyVote` accept it because `GovernanceUnitPrice`'s `FormatChecker` is `noopFormatChecker` and `checkConsistency` has no special-case validation for it (see `kaiax/gov/headergov/impl/header.go` lines 214-219).
2. At the next epoch, `GetParamSet(blockNum).UnitPrice` returns `math.MaxUint64` on every node.
3. `NewTxPool`/pool reset sets `pool.gasPrice = new(big.Int).SetUint64(pset.UnitPrice)` (`blockchain/tx_pool.go` lines 285-299).
4. `validateTx` (pre-Magma path) requires `pool.gasPrice.Cmp(tx.GasPrice()) == 0` (`blockchain/tx_pool.go` lines 875-881); no ordinary sender/fee-payer can supply a transaction with that exact, impossibly large gas price, and all such transactions are rejected with `ErrInvalidUnitPrice`, network-wide.
