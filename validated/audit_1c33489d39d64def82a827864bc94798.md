Confirmed: `is_clvm_canonical()` calls `validate_spend_bundle()` in `chia/full_node/mempool_manager.py` on every coin spend's `puzzle_reveal` and `solution` bytes, and this path is reachable directly from any single submitted spend bundle before it can be added to the mempool.

### Title
Out-of-bounds read in mempool CLVM canonical-encoding checker via crafted spend-bundle solution/puzzle bytes - (File: chia/full_node/mempool_manager.py)

### Summary
`is_atom_canonical()` and `is_clvm_canonical()` in `chia/full_node/mempool_manager.py` walk a raw `bytes` buffer (`clvm_buffer`) representing a coin spend's serialized `puzzle_reveal` or `solution`, indexing into it with an `offset` that is derived from attacker-controlled length-prefix bytes, without ever checking `offset` against `len(clvm_buffer)` before dereferencing it.

### Finding Description
`is_atom_canonical(clvm_buffer, offset)` reads `clvm_buffer[offset]` and then, based on the top bits of that byte, computes `prefix_len` (up to 5) and loops `offset += 1; atom_len |= clvm_buffer[offset]` that many times [1](#0-0) . Nothing here bounds `offset` against the buffer length, so if the multi-byte length-prefix marker (e.g. `0xFC`..`0xFE` range bits) appears near or at the end of the buffer, the subsequent `clvm_buffer[offset]` reads walk past the end of the byte string.

`is_clvm_canonical(clvm_buffer)` calls `is_atom_canonical()` in a loop while scanning a CLVM-serialized program byte-by-byte, and is itself called unconditionally on every coin spend's `puzzle_reveal` and `solution` in `MempoolManager.validate_spend_bundle()`: `if not is_clvm_canonical(bytes(coin_spend.puzzle_reveal)) or not is_clvm_canonical(bytes(coin_spend.solution))` [2](#0-1) [3](#0-2) . This is reached for every spend bundle admitted to the mempool from any submitter (`send_transaction` RPC, `new_transaction` gossip), independent of privilege.

Because `bytes` in CPython raises `IndexError` on out-of-range access rather than reading adjacent heap memory, this is not a true C-style memory-safety OOB read like PDFium's — Python bounds-checks all sequence indexing. The practical effect of a crafted truncated/malformed length prefix at the tail of `puzzle_reveal`/`solution` is an unhandled `IndexError` raised from inside `is_clvm_canonical()`, propagating out of `validate_spend_bundle()`.

### Impact Explanation
If the `IndexError` is not caught anywhere between `is_clvm_canonical()` and the mempool-manager's spend-bundle admission caller, a single crafted spend bundle can throw an unhandled exception during `add_spend_bundle()`/`validate_spend_bundle()`, which is invoked while holding the blockchain lock, potentially interrupting transaction admission for that call and requiring the caller to handle/catch the propagated exception. Whether this actually crashes the full node process or is caught by an outer `try/except` in the RPC/gossip handler is not established from the code visible here — the index only shows `mempool_manager.py` and its unit tests, not the full call chain in `full_node.py`/`full_node_api.py` that invokes `validate_spend_bundle()`, so I cannot confirm with certainty whether an uncaught exception here crashes the node, is logged and dropped, or bans the peer.

### Likelihood Explanation
Constructing the required byte sequence is straightforward for an attacker: a `puzzle_reveal` or `solution` ending in a byte matching one of the multi-byte-length-prefix patterns (`0b11000000`–`0b11111110` top bits) with the prefix's continuation bytes truncated by end-of-buffer would trigger the out-of-range index inside the prefix-parsing loop. Any unprivileged wallet user or spend-bundle submitter can build and submit such a coin spend.

### Recommendation
Add explicit bounds checks in `is_atom_canonical()` before each `clvm_buffer[offset]` access (both the initial read and each prefix-continuation byte), raising a domain-specific, caught exception (e.g., treat as non-canonical / return `False`) rather than allowing `IndexError` to propagate. Ensure `MempoolManager.validate_spend_bundle()` (or callers of `is_clvm_canonical`) wraps the canonical check in a `try/except` that maps any parsing failure to `Err.INVALID_COIN_SOLUTION` instead of letting an exception escape unhandled.

### Proof of Concept
Construct a `CoinSpend` whose `solution` (or `puzzle_reveal`) serialized bytes end with a byte such as `0xC0` (5+8-bit prefix marker, `prefix_len = 1`) as the very last byte of the buffer, so `offset` after `offset += 1` in the `for i in range(prefix_len)` loop of `is_atom_canonical()` points one byte past `len(clvm_buffer)`. Submitting a `SpendBundle` containing this coin spend into `MempoolManager.validate_spend_bundle()` triggers `is_clvm_canonical(bytes(coin_spend.solution))` → `is_atom_canonical()` → `clvm_buffer[offset]` with `offset == len(clvm_buffer)`, raising `IndexError`. This mirrors the reachable-path test in `chia/_tests/core/mempool/test_mempool_manager.py::test_mempool_requires_canonical_clvm`, which already exercises `is_clvm_canonical` against crafted non-canonical hex payloads (e.g. `"ffffc001018080"`) via the same `validate_spend_bundle` admission path [4](#0-3) , though that specific test case does not itself truncate the buffer to trigger the OOB index — it only demonstrates the reachable call path.

def is_atom_canonical(clvm_buffer: bytes, offset: int) -> tuple[int, bool]:
    b = clvm_buffer[offset]
    if (b & 0b11000000) == 0b10000000:
        # 6 bits length prefix
        mask = 0b00111111
        prefix_len = 0
        min_value = 1
    elif (b & 0b11100000) == 0b11000000:
        # 5 + 8 bits length prefix
        mask = 0b00011111
        prefix_len = 1
        min_value = 1 << 6
    elif (b & 0b11110000) == 0b11100000:
        # 4 + 8 + 8 bits length prefix
        mask = 0b00001111
        prefix_len = 2
        min_value = 1 << (5 + 8)
    elif (b & 0b11111000) == 0b11110000:
        # 3 + 8 + 8 + 8 bits length prefix
        mask = 0b00000111
        prefix_len = 3
        min_value = 1 << (4 + 8 + 8)
    elif (b & 0b11111100) == 0b11111000:
        # 2 + 8 + 8 + 8 + 8 bits length prefix
        mask = 0b00000011
        prefix_len = 4
        min_value = 1 << (3 + 8 + 8 + 8)
    elif (b & 0b11111110) == 0b11111100:
        # 1 + 8 + 8 + 8 + 8 + 8 bits length prefix
        mask = 0b00000001
        prefix_len = 5
        min_value = 1 << (2 + 8 + 8 + 8 + 8)

    atom_len = b & mask
    for i in range(prefix_len):
        atom_len <<= 8
        offset += 1
        atom_len |= clvm_buffer[offset]

    return 1 + prefix_len + atom_len, atom_len >= min_value
```

def is_clvm_canonical(clvm_buffer: bytes) -> bool:
    """
    checks whether the CLVM serialization is all canonical representation.
    atoms can be serialized in more than one way by using more bytes than
    necessary to encode the length prefix. This functions ensures that all atoms are
    encoded with the shortest representation. back-references are not allowed
    and will make this function return false
    """
    assert clvm_buffer != b""

    offset = 0
    tokens_left = 1
    while True:
        b = clvm_buffer[offset]

        # pair
        if b == 0xFF:
            tokens_left += 1
            offset += 1
            continue

        # back references cannot be considered canonical, since they may be
        # encoded in many different ways
        if b == 0xFE:
            return False

        # small atom or NIL
        if b <= 0x80:
            tokens_left -= 1
            offset += 1
        else:
            atom_len, canonical = is_atom_canonical(clvm_buffer, offset)
            if not canonical:
                return False
            tokens_left -= 1
            offset += atom_len

        if tokens_left == 0:
            break

    # if there's garbage at the end, it's not canonical
    return offset == len(clvm_buffer)
```
