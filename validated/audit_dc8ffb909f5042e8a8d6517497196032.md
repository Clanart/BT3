### Title
Native value (`msg.value`) sent to non-payable stateful precompiles (staking, distribution, gov, slashing) is permanently locked - ([File: precompiles/staking/staking.go], [File: precompiles/distribution/distribution.go], [File: precompiles/gov/gov.go], [File: precompiles/slashing/slashing.go])

### Summary
The `fundContract.depositNative()` bug class (accepting more native value than the contract logic actually consumes, with no refund/sweep path) has a direct analog in Cosmos EVM's stateful precompiles. The ERC20 precompile explicitly guards against this by rejecting any call carrying `contract.Value() > 0` [1](#0-0) , with a comment explaining *why*: "ERC20 precompiles cannot receive funds because they are not managed by an EOA and will not be possible to recover funds sent to an instance of them." The same guard does not exist on the Staking, Distribution, Gov, or Slashing precompiles.

### Finding Description
All EVM precompile calls go through the standard `vm.Contract` value-transfer semantics: when a caller invokes a precompile with `{value: X}`, the EVM core transfers `X` from the caller to the precompile's address balance before `Run()`/`Execute()` is invoked, exactly as for any normal contract call. `RunNativeAction` / `runNativeAction` then executes the precompile's business logic against the cached SDK context and translates bank-keeper events into StateDB balance deltas via `BalanceHandler.AfterBalanceChange` [2](#0-1) [3](#0-2) .

For the Staking precompile, `Delegate` (and similarly `CreateValidator`, `Undelegate`, `Redelegate`, `CancelUnbondingDelegation`) derives the amount to move exclusively from the ABI-decoded `msg.Amount` argument, and executes the transfer via the Cosmos SDK staking message server against the delegator's existing bank balance — it never reads or consumes `contract.Value()`: [4](#0-3) 

The `Execute` dispatcher for Staking has no check equivalent to ERC20's `ErrCannotReceiveFunds` guard: [5](#0-4) 

The same pattern (no value-rejection guard, and per-method logic keyed off ABI arguments rather than `contract.Value()`) is present in Distribution, Gov, and Slashing precompile `Execute`/`Run` dispatchers: [6](#0-5) 

By contrast, ERC20 explicitly documents and blocks this exact class of bug because the address has no code path to recover value sent to it: [1](#0-0) 

The WERC20 precompile is the only "receiving" precompile with a correct compensating mechanism: its `Deposit` explicitly reads `contract.Value()` and sends the exact same amount back to the caller via `BankKeeper.SendCoins`, guaranteeing the native balance stays with the user [7](#0-6) . Staking/Distribution/Gov/Slashing have no such sweep-back logic.

Consequently, if a caller (EOA or contract) sends a non-zero `value` alongside a call to any non-payable method on these precompiles (e.g. `staking.delegate{value: X}(...)`, `distribution.withdrawDelegatorRewards{value: X}(...)`, `gov.vote{value: X}(...)`), that value is transferred by the EVM value-transfer mechanism to the fixed precompile address (e.g. `0x...0800` for staking), which has no private key, no withdraw/sweep function, and no fallback handling that reclaims or refunds it. The precompile's own logic proceeds independently based on ABI arguments, so the call still "succeeds" from the caller's perspective while the extra native value silently vanishes into the address representing the precompile.

### Impact Explanation
This matches the "Critical permanent freezing/locking/theft of user funds" impact class: any unprivileged EVM user who mistakenly (or is tricked by a malicious front-end/contract into) attaching `msg.value` to a staking/distribution/gov/slashing precompile call loses that value irrecoverably, with no admin, governance, or protocol-level path to reclaim it. Unlike the ERC20 case, which is explicitly hardened, these four precompiles are exposed to the exact bug class described in the external report, and because it is a full loss (not just an "excess" residue as in WETH-style overpayment), the severity is more severe: the *entire* sent value is lost, not merely the delta above an intended `_amount`.

### Likelihood Explanation
Likelihood is elevated because:
- These precompiles are designed to be called directly from Solidity with `payable`-style patterns (staking's own test caller contracts routinely call `delegate{value: ...}` style patterns using `msg.value`, as seen throughout `StakingCaller.sol`/`StakingCallerTwo.sol` test fixtures) [8](#0-7) .
- Any wallet/dApp/aggregator that naively forwards `msg.value` when composing a call to these addresses (a very plausible integration mistake, mirroring exactly the WETH/fundContract overpayment bug class) will silently strand funds.
- No transaction-level or ante-level validation currently rejects non-zero value against non-payable precompile methods for Staking/Distribution/Gov/Slashing.

### Recommendation
Add the same guard used in the ERC20 precompile to Staking, Distribution, Gov, and Slashing `Execute`/dispatcher functions: reject any transaction where `contract.Value().Sign() == 1` for methods that do not explicitly consume the value (i.e., all current methods, since none of them use `contract.Value()`), returning an error such as `ErrCannotReceiveFunds`. Alternatively, if any future payable variant is intended, explicitly reconcile `contract.Value()` against the ABI-decoded amount and refund/no-op any surplus, following the WERC20 `Deposit` pattern of sending the received value straight back to the caller.

### Proof of Concept
1. Deploy or use an existing caller contract (e.g. `StakingCaller.sol`) that calls `staking.STAKING_CONTRACT.delegate(address(this), _validatorAddr, amount)` while simultaneously attaching `msg.value` (e.g., directly via `eth_sendTransaction` to `0x0000000000000000000000000000000000000800` with calldata for `delegate(...)` and a nonzero `value` field, or via a wrapper contract that forwards `msg.value` for an unrelated reason).
2. Observe that the `Delegate` transaction succeeds (delegation is created for `amount` from the delegator's bank balance) — confirmed unaffected by `contract.Value()` per `precompiles/staking/tx.go` lines 142-186.
3. Query the balance associated with the staking precompile's address (bech32-derived from `0x...0800`) after the call — the transferred `value` is credited there with no corresponding sweep-back, and no method exists on the precompile (no `withdraw`, no fallback) to recover it.
4. Repeat against Distribution/Gov/Slashing precompile addresses with any of their transaction methods to confirm the same result.

Note: this analysis is based on the observed absence of the `ErrCannotReceiveFunds`-equivalent guard and absence of `contract.Value()` usage in the Staking/Distribution/Gov/Slashing transaction handlers found via static review; full confirmation of the exact value-transfer-to-bank-mint mechanics at StateDB commit time (i.e., whether the EVM `Transfer` call for a precompile actually results in a real, persisted bank-balance movement at commit, as opposed to being reverted/no-op) would benefit from a live integration test run, which was not available in this review.

func (p Precompile) runNativeAction(evm *vm.EVM, contract *vm.Contract, action NativeAction) (bz []byte, err error) {
	stateDB, ok := evm.StateDB.(*statedb.StateDB)
	if !ok {
		return nil, errors.New(ErrNotRunInEvm)
	}

	// get the stateDB cache ctx
	ctx, err := stateDB.GetCacheContext()
	if err != nil {
		return nil, err
	}

	// take a snapshot of the current state before any changes
	// to be able to revert the changes
	snapshot := stateDB.MultiStoreSnapshot()
	events := ctx.EventManager().Events()

	// add precompileCall entry on the stateDB journal
	// this allows to revert the changes within an evm tx
	if err := stateDB.AddPrecompileFn(snapshot, events); err != nil {
		return nil, err
	}

	// commit the current changes in the cache ctx
	// to get the updated state for the precompile call
	if err := stateDB.CommitWithCacheCtx(); err != nil {
		return nil, err
	}

	initialGas := ctx.GasMeter().GasConsumed()

	defer HandleGasError(ctx, contract, initialGas, &err)()

	// set the default SDK gas configuration to track gas usage
	// we are changing the gas meter type, so it panics gracefully when out of gas
	ctx = ctx.WithGasMeter(storetypes.NewGasMeter(contract.Gas)).
		WithKVGasConfig(p.KvGasConfig).
		WithTransientKVGasConfig(p.TransientKVGasConfig)

	// we need to consume the gas that was already used by the EVM
	ctx.GasMeter().ConsumeGas(initialGas, "creating a new gas meter")

	var balanceHandler *BalanceHandler
	if p.BalanceHandlerFactory != nil {
		balanceHandler = p.BalanceHandlerFactory.NewBalanceHandler()
	}

	if balanceHandler != nil {
		balanceHandler.BeforeBalanceChange(ctx)
	}

	bz, err = action(ctx)
	if err != nil {
		return bz, err
	}

	cost := ctx.GasMeter().GasConsumed() - initialGas

	if !contract.UseGas(cost, nil, tracing.GasChangeCallPrecompiledContract) {
		return nil, vm.ErrOutOfGas
	}

	if balanceHandler != nil {
		if err := balanceHandler.AfterBalanceChange(ctx, stateDB); err != nil {
			return nil, err
		}
	}

func (bh *BalanceHandler) AfterBalanceChange(ctx sdk.Context, stateDB *statedb.StateDB) error {
	events := ctx.EventManager().Events()

	for _, event := range events[bh.prevEventsLen:] {
		switch event.Type {
		case banktypes.EventTypeCoinSpent:
			spenderAddr, err := ParseAddress(event, banktypes.AttributeKeySpender)
			if err != nil {
				return fmt.Errorf("failed to parse spender address from event %q: %w", banktypes.EventTypeCoinSpent, err)
			}
			if bh.bankKeeper.BlockedAddr(spenderAddr) {
				// Bypass blocked addresses
				continue
			}

			amount, err := ParseAmount(event)
			if err != nil {
				return fmt.Errorf("failed to parse amount from event %q: %w", banktypes.EventTypeCoinSpent, err)
			}

			stateDB.SubBalance(common.BytesToAddress(spenderAddr.Bytes()), amount, tracing.BalanceChangeUnspecified)

		case banktypes.EventTypeCoinReceived:
			receiverAddr, err := ParseAddress(event, banktypes.AttributeKeyReceiver)
			if err != nil {
				return fmt.Errorf("failed to parse receiver address from event %q: %w", banktypes.EventTypeCoinReceived, err)
			}
			if bh.bankKeeper.BlockedAddr(receiverAddr) {
				// Bypass blocked addresses
				continue
			}

			amount, err := ParseAmount(event)
			if err != nil {
				return fmt.Errorf("failed to parse amount from event %q: %w", banktypes.EventTypeCoinReceived, err)
			}

			stateDB.AddBalance(common.BytesToAddress(receiverAddr.Bytes()), amount, tracing.BalanceChangeUnspecified)

// Delegate performs a delegation of coins from a delegator to a validator.
func (p *Precompile) Delegate(
	ctx sdk.Context,
	contract *vm.Contract,
	stateDB vm.StateDB,
	method *abi.Method,
	args []interface{},
) ([]byte, error) {
	bondDenom, err := p.stakingKeeper.BondDenom(ctx)
	if err != nil {
		return nil, err
	}
	msg, delegatorHexAddr, err := NewMsgDelegate(args, bondDenom, p.addrCdc)
	if err != nil {
		return nil, err
	}

	p.Logger(ctx).Debug(
		"tx called",
		"method", method.Name,
		"args", fmt.Sprintf(
			"{ delegator_address: %s, validator_address: %s, amount: %s }",
			delegatorHexAddr,
			msg.ValidatorAddress,
			msg.Amount.Amount,
		),
	)

	msgSender := contract.Caller()
	if msgSender != delegatorHexAddr {
		return nil, fmt.Errorf(cmn.ErrRequesterIsNotMsgSender, msgSender.String(), delegatorHexAddr.String())
	}

	// Execute the transaction using the message server
	if _, err = p.stakingMsgServer.Delegate(ctx, msg); err != nil {
		return nil, err
	}

	// Emit the event for the delegate transaction
	if err = p.EmitDelegateEvent(ctx, stateDB, msg, delegatorHexAddr); err != nil {
		return nil, err
	}

	return method.Outputs.Pack(true)
}

func (p Precompile) Deposit(
	ctx sdk.Context,
	contract *vm.Contract,
	stateDB vm.StateDB,
) ([]byte, error) {
	caller := contract.Caller()
	depositedAmount := contract.Value()

	callerAccAddress := sdk.AccAddress(caller.Bytes())
	precompileAccAddr := sdk.AccAddress(p.Address().Bytes())

	// Send the coins back to the sender
	if err := p.BankKeeper.SendCoins(
		ctx,
		precompileAccAddr,
		callerAccAddress,
		sdk.NewCoins(sdk.Coin{
			Denom:  evmtypes.GetEVMCoinExtendedDenom(),
			Amount: math.NewIntFromBigInt(depositedAmount.ToBig()),
		}),
	); err != nil {
		return nil, err
	}

	if err := p.EmitDepositEvent(ctx, stateDB, caller, depositedAmount.ToBig()); err != nil {
		return nil, err
	}

	return nil, nil
}
