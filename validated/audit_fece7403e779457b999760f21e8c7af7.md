### Title
Unbounded External Calls to Gasless Whitelisted Tokens/Router Cause Gas-Griefing DoS on TxPool - ([File: kaiax/gasless/impl/tx_pool.go])

### Summary
The `ERC20Farmable` gas-griefing pattern (unbounded external calls without a gas cap, allowing a malicious/upgraded contract to burn all available gas) has a direct analog in the `kaiax/gasless` module. `GetCheckBalance()` performs external calls into whitelisted ERC20 tokens and the `GaslessSwapRouter` contract with no gas ceiling, and these calls are re-executed synchronously and repeatedly by the transaction pool while holding pool-wide locks.

### Finding Description
`GaslessModule.checkBalanceForApprove` and `checkBalanceForSwap` invoke `tokenContract.BalanceOf`, `tokenContract.Allowance`, and `routerContract.GetAmountIn` on addresses drawn from `g.allowedTokens` / `g.swapRouter`, using `backends.NewBlockchainContractBackend(g.Chain, nil, nil)` with a `nil` `bind.CallOpts`: [1](#0-0) [2](#0-1) 

Unlike the corrected `ERC20Farmable` fix (200,000 gas cap on the external call), `BlockchainContractBackend.callContract` defaults an unset `call.Gas` to `3e8` (300,000,000) — effectively unbounded relative to a normal contract call — with no assembly-level return-bomb guard: [3](#0-2) 

This `GetCheckBalance()` closure is invoked in two hot, lock-held paths of the transaction pool:
1. `TxPool.validateTx`, executed under `pool.mu` for every incoming gasless tx via `addTx`/`add`: [4](#0-3) 
2. `txList.Filter`, executed for every queued transaction of every account on every `promoteExecutables` call (i.e., on every new block / pool reset), under `pool.txMu`: [5](#0-4) 

A token or router contract, once whitelisted for gasless usage and later made malicious (e.g., via an upgradeable proxy pattern), can implement `balanceOf`/`allowance`/`getAmountIn` to consume near the full 3e8 gas allowance on every invocation. Because `Filter` re-evaluates `checkBalance` for every still-queued transaction referencing that token on every block, and `validateTx` re-evaluates it on every new submission, this single malicious contract can force repeated, expensive EVM executions inside pool-wide locks (`pool.mu`, `pool.txMu`), stalling submission and promotion of all transactions pool-wide, not just the malicious sender's own transactions.

### Impact Explanation
This mirrors the reported `ERC20Farmable` gas-griefing class: an external, attacker-controlled contract call without a bounded gas limit is invoked repeatedly from a security-critical hot path (here, the tx pool admission/promotion pipeline instead of a farm claim/exit). Because the check runs under `pool.mu`/`pool.txMu`, sustained high-gas execution can degrade or stall transaction pool throughput for all senders (not only gasless users), and repeatedly delays promotion/inclusion of legitimate gasless and non-gasless transactions competing for the same locks — a liveness/availability impact on a component explicitly in scope (gasless module, txpool admission).

### Likelihood Explanation
Requires only that a token/router contract already whitelisted for gasless transactions (`g.allowedTokens`, `g.swapRouter`) be, or later become (via upgradeable proxy), malicious. No validator or node-operator privilege is needed — an ordinary contract deployer/gasless user interacting with an onboarded token can trigger this by submitting gasless transactions referencing the malicious token, after which the txpool's periodic `Filter`/`validateTx` calls repeatedly re-execute the expensive call.

### Recommendation
Cap the gas supplied to `CallContract` invocations used for gasless balance/allowance/router checks (analogous to the 200,000 gas cap used in the corrected `ERC20Farmable` code), handle failures/out-of-gas as an ordinary check failure rather than propagating unbounded EVM execution, and consider bounding return data size to avoid return-data-bomb amplification, consistent with the referenced Solidity issue (ethereum/solidity#12306).

### Proof of Concept
1. Onboard (or wait for onboarding of) an ERC20 token/`GaslessSwapRouter` implementation behind an upgradeable proxy into `g.allowedTokens`/`g.swapRouter`.
2. Upgrade the implementation so `balanceOf`, `allowance`, or `getAmountIn` contains an expensive/near-infinite-loop computation designed to consume close to the 3e8 gas ceiling set in `BlockchainContractBackend.callContract`.
3. Submit gasless approve/swap transactions referencing this token so they enter the `TxPool` queue.
4. Each subsequent `promoteExecutables`/`reset` cycle (every new block) calls `txList.Filter`, which re-invokes `GetCheckBalance()` → the malicious token's `balanceOf`/`allowance`, burning near-maximal gas under `pool.txMu` for every queued reference, repeatedly degrading pool processing.

func (g *GaslessModule) checkBalanceForApprove(approveArgs *ApproveArgs) error {
	token := approveArgs.Token
	bc := backends.NewBlockchainContractBackend(g.Chain, nil, nil)

	if g.GaslessConfig.ShouldCheckSenderCode() {
		if g.getCurrentHasCode(approveArgs.Sender) {
			return errors.New("sender with code is not allowed")
		}
	}

	if g.GaslessConfig.ShouldCheckToken() {
		tokenContract, err := sc_erc20.NewERC20(token, bc)
		if err != nil {
			return err
		}

		// tx.token.balanceOf(sender) > 0
		tokenBalance, err := tokenContract.BalanceOf(nil, approveArgs.Sender)
		if err != nil {
			return err
		}
		if tokenBalance.Sign() <= 0 {
			return fmt.Errorf("insufficient sender token balance: token=%s, have=%s, want=nonzero", token.Hex(), tokenBalance.String())
		}
	}
	return nil
}

func (g *GaslessModule) checkBalanceForSwap(swapArgs *SwapArgs, swapNonce uint64) error {
	token := swapArgs.Token
	bc := backends.NewBlockchainContractBackend(g.Chain, nil, nil)

	g.gaslessInfoMu.RLock()
	swapRouter := g.swapRouter
	g.gaslessInfoMu.RUnlock()

	// tx.minAmountOut >= tx.amountRepay
	minAmountOut := swapArgs.MinAmountOut
	amountRepay := swapArgs.AmountRepay
	if minAmountOut.Cmp(amountRepay) < 0 {
		return fmt.Errorf("insufficient minAmountOut: minAmountOut=%s, amountRepay=%s", minAmountOut.String(), amountRepay.String())
	}

	if g.GaslessConfig.ShouldCheckSenderCode() {
		if g.getCurrentHasCode(swapArgs.Sender) {
			return errors.New("sender with code is not allowed")
		}
	}

	if g.GaslessConfig.ShouldCheckSwapAmount() {
		// tx.amountIn >= gsr.getAmountIn(minAmountOut)
		routerContract, err := kip247.NewGaslessSwapRouterCaller(swapRouter, bc)
		if err != nil {
			return err
		}
		// Required token amountIn, given the current exchange rate and the declared minAmountOut.
		requiredAmountIn, err := routerContract.GetAmountIn(nil, token, minAmountOut)
		if err != nil {
			return err
		}
		if swapArgs.AmountIn.Cmp(requiredAmountIn) < 0 {
			return fmt.Errorf("insufficient amountIn: have=%s, want=%s", swapArgs.AmountIn.String(), requiredAmountIn.String())
		}
	}
