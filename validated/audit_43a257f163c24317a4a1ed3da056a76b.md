### Title
Data Layer client SSRF via unauthenticated fetch of attacker-published mirror `ServerInfo.url` - (File: `chia/data_layer/download_data.py`)

### Summary
Chia's Data Layer store-sync flow downloads delta/full-tree files by making an HTTP GET request to a server URL taken directly from an on-chain `ServerInfo`/mirror record, with no validation of scheme, host, or destination network. Any wallet holding a coin can publish a mirror server URL on-chain for a Data Layer store; when another DL client subscribes to and syncs that store, its local Data Layer service will issue outbound HTTP requests to the attacker-chosen URL, enabling SSRF against internal/private network endpoints reachable from the victim's host.

### Finding Description
`http_download()` builds the request target directly from `server_info.url` and performs an unauthenticated `aiohttp` GET against it with no allow-listing of scheme or host: [1](#0-0) 

This function is invoked from `download_file()`, which is called for every root hash needed while a Data Layer client syncs a subscribed store, using whichever `server_info` (mirror) is currently selected for that store: [2](#0-1) 

`ServerInfo` objects originate from mirror records that are published on-chain and can be created by any wallet via the "add mirror" flow (`add_mirror`/`get_mirrors`, exposed through `data_layer_rpc_api.py`, `data_layer_wallet.py`, and CLI `data.py`/`data_funcs.py`), and are then discovered and used by other Data Layer nodes when they sync/subscribe to that store. The `url` field is free-form text supplied by whoever creates the mirror coin — the Data Layer client performing the download does not validate it belongs to a legitimate/expected host, nor restrict it from pointing at loopback, link-local, or private RFC1918 addresses.

Because the request is made server-side by the victim's Data Layer node process (not by a browser), any low-privilege actor able to create a mirror coin for a store (an operation reachable by an ordinary wallet holding funds) can cause the victim node to issue outbound requests to internal services, cloud metadata endpoints, or other network-restricted resources.

### Impact Explanation
This matches the reachable actor class permitted by scope ("Data Layer client"): an unprivileged party publishes a malicious mirror URL for a store; when other DL nodes subscribe to and sync the same store, they blindly issue outbound HTTP requests to that URL. This can be leveraged for SSRF against internal infrastructure reachable from the victim host (e.g., cloud metadata service, internal admin panels, other services bound to localhost), potentially leaking credentials or triggering unauthorized actions on internal systems. It does not achieve local arbitrary file read (aiohttp does not resolve `file://` URIs), so the impact is scoped to SSRF rather than the file-disclosure component of the original Snipe-IT report.

### Likelihood Explanation
Likelihood is moderate: any wallet operator can create a mirror record for a Data Layer store cheaply, and any other node that subscribes to that same store for legitimate replication purposes will automatically attempt downloads from the attacker-controlled URL without manual review, since mirror selection/rotation happens automatically as part of routine sync (`insert_from_delta_file` iterates over `server_info` candidates).

### Recommendation
Validate mirror URLs before use: restrict to `http`/`https` schemes, resolve and reject requests to loopback/link-local/private address ranges (unless explicitly configured for testing), and consider requiring operator opt-in/allow-listing of mirror hosts before automatic download, mirroring standard SSRF mitigations (DNS-rebinding-safe host validation, egress network policy for the Data Layer download client).

### Proof of Concept
1. Attacker publishes a Data Layer store and adds a mirror via the standard "add mirror" RPC/CLI flow with `url` set to `http://169.254.169.254/latest/meta-data/` (or an internal service address on the victim's network).
2. Victim configures their Data Layer node to subscribe to the attacker's store, as is normal for consuming shared DL data.
3. During routine sync, the victim's node calls `insert_from_delta_file` → `download_file` → `http_download`, which issues a GET to `server_info.url + "/" + filename`, causing the victim node to make an outbound request to the attacker-chosen internal address. [1](#0-0)

async def download_file(
    data_store: DataStore,
    target_filename_path: Path,
    store_id: bytes32,
    root_hash: bytes32,
    generation: int,
    server_info: ServerInfo,
    proxy_url: str | None,
    downloader: PluginRemote | None,
    timeout: aiohttp.ClientTimeout,
    client_foldername: Path,
    timestamp: int,
    log: logging.Logger,
    grouped_by_store: bool,
    group_downloaded_files_by_store: bool,
    max_delta_file_size: int,
) -> bool:
    if target_filename_path.exists():
        return True
    filename = get_delta_filename(store_id, root_hash, generation, grouped_by_store)

    if downloader is None:
        # use http downloader - this raises on any error
        try:
            await http_download(
                target_filename_path, filename, proxy_url, server_info, timeout, log, max_delta_file_size
            )
        except (asyncio.TimeoutError, aiohttp.ClientError, MaxDeltaFileSizeExceededError):
            new_server_info = await data_store.server_misses_file(store_id, server_info, timestamp)
            log.info(
                f"Failed to download {filename} from {new_server_info.url}."
                f"Miss {new_server_info.num_consecutive_failures}."
            )
            log.info(f"Next attempt from {new_server_info.url} in {new_server_info.ignore_till - timestamp}s.")
            return False
        return True

async def http_download(
    target_filename_path: Path,
    filename: str,
    proxy_url: str | None,
    server_info: ServerInfo,
    timeout: aiohttp.ClientTimeout,
    log: logging.Logger,
    max_delta_file_size: int,
) -> None:
    """
    Download a file from a server using aiohttp.
    Raises exceptions on errors
    """
    async with aiohttp.ClientSession() as session:
        headers = {"accept-encoding": "gzip"}
        async with session.get(
            server_info.url + "/" + filename,
            headers=headers,
            timeout=timeout,
            proxy=proxy_url,
        ) as resp:
            resp.raise_for_status()
