### Title
Aggregate Schnorr signatures are publicly malleable because verification weights omit `R` - ([File: crypto/schnorr/src/aggregate.rs](crypto/schnorr/src/aggregate.rs))

### Summary
`SchnorrAggregate::verify` derives the aggregation weights only from the caller-supplied per-signature challenges, while omitting the aggregate’s `Rs` from that transcript. Because the public nonce commitments are not bound to the weights, anyone who observes a valid aggregate signature can add a chosen multiple of the generator to one `R` and compensate in `s`, producing a distinct aggregate encoding that still verifies for the same signers and challenges.

### Finding Description
The verifier constructs the weight transcript from the domain separator and each challenge, but never appends the corresponding public key or nonce commitment `R_i` to that transcript. [1](#0-0) 

It then verifies:

```text
Σ z_i * R_i + Σ (z_i * c_i) * A_i - s * G = 0
```

where `z_i` is deterministic from only the public challenges. [2](#0-1) 

Given a valid aggregate `((R_0, ..., R_n), s)`, an attacker can recompute `z_0`, choose any scalar `d`, and submit:

```text
R'_0 = R_0 + d * G
s'   = s + z_0 * d
```

All other components remain unchanged. The added terms cancel algebraically:

```text
z_0 * R'_0 - s' * G
= z_0 * (R_0 + dG) - (s + z_0d) * G
= z_0 * R_0 - s * G
```

`SchnorrAggregate::read` accepts attacker-provided `R` values through canonical point decoding, so the modified nonce commitment can be supplied directly as untrusted bytes. [3](#0-2) 

### Impact Explanation
An unprivileged observer can forge a new, valid aggregate-signature representation for an already-signed statement without knowing any private key or nonce. Any protocol that treats the aggregate signature bytes, hash, or encoded `Rs` as a unique authorization artifact can accept attacker-malleated authorization data that was never produced by the signer set. This is an incorrect verifier formula for aggregate Schnorr signatures because the aggregation randomizer does not bind the statement-specific nonce commitments it is meant to prevent from being manipulated. [4](#0-3) 

### Likelihood Explanation
Exploitation requires only a previously valid aggregate signature, the public signer keys/challenges, and public recomputation of the verifier’s deterministic weight. No signing participant, validator, network peer, secret material, or protocol misuse is required. The transformation is deterministic and succeeds whenever the original aggregate verifies and the modified `R'_0` has a canonical group encoding. [5](#0-4) 

### Recommendation
Bind each aggregate nonce commitment—and preferably each corresponding public key—to the weight transcript before deriving `z_i`. For example, append `R_i` and the encoded public key alongside each challenge in both `SchnorrAggregator` and `SchnorrAggregate::verify`, while preserving a consistent order. The aggregator and verifier must derive weights over identical, fully bound transcripts. [1](#0-0) [6](#0-5) 

### Proof of Concept
For an in-scope `Ciphersuite` `C`, let `verify` accept `dst`, `keys_and_challenges`, and a serialized `SchnorrAggregate<C>`:

```rust
// From crypto/schnorr/src/aggregate.rs semantics.
let original = SchnorrAggregate::<C>::read(&mut encoded).unwrap();
assert!(original.verify(dst, &keys_and_challenges));

// Recreate the verifier transcript.
let mut digest = DigestTranscript::<C::H>::new(dst);
digest.domain_separate(b"signatures");
for (_, challenge) in &keys_and_challenges {
    digest.append_message(b"challenge", challenge.to_repr());
}

// Compute the first public aggregation weight.
let z0: C::F = weight::<_, C::F>(&mut digest);

// Choose an arbitrary non-zero scalar.
let d = C::random_nonzero_F(&mut OsRng);

// Malleate the first nonce commitment and compensating scalar.
let mut malleated = original;
malleated.Rs[0] += C::generator() * d;
malleated.s += z0 * d;

// A distinct encoding verifies for the same keys and challenges.
assert_ne!(malleated.serialize(), encoded);
assert!(malleated.verify(dst, &keys_and_challenges));
```

The fields are private outside the crate, so an external executable proof can equivalently parse the encoding, replace the first encoded `R` with `R + dG`, replace `s` with `s + z_0d`, and reserialize the modified aggregate.
