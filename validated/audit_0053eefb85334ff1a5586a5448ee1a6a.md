## Title
Unauthenticated `CallDispatcher.dispatch()` lets anyone drain residual token/ETH balances left by IntentGateway/HFT predispatch and postdispatch flows - ([File: evm/src/utils/CallDispatcher.sol])

### Summary
`CallDispatcher.dispatch()` has no caller restriction whatsoever, and is used as *shared, temporary custody* by `IntentGatewayV2` (predispatch/postdispatch swaps), `IntrinsicIntents`/`ExtrinsicIntents` (`_execute` output-call sweep), and `HyperFungibleToken`/`WrappedHyperFungibleToken` (`onAccept` calldata execution). Every one of these call sites only sweeps back the *specific tokens they expect*, not "whatever the dispatcher currently holds." Any ERC20 balance that ends up on the dispatcher outside those expected token lists (e.g. a predispatch swap whose output token isn't in `order.inputs`, or dust from a reverted/partial flow) is left sitting on a single, permanently shared contract address that **anyone** can call directly to move that balance out — without going through `IntentGatewayV2` or any of its checks. This mirrors the H-1 pattern: value custody is inferred purely from "whatever balance exists on the holding contract," with no binding to who actually deposited it.

### Finding Description
`CallDispatcher.dispatch()`: [1](#0-0) 
has zero access control — any external account can call it and command it to execute arbitrary `Call{to, value, data}` entries, including `IERC20(token).transfer(attacker, amount)` against whatever balance the dispatcher currently holds.

`IntentGatewayV2.placeOrder`'s predispatch phase funds the dispatcher, runs the caller-supplied `order.predispatch.call`, and then sweeps back **only** the tokens listed in `order.inputs`: [2](#0-1) 
Any token balance produced by the arbitrary predispatch call that is *not* included in `order.inputs` (e.g. slippage residue, or an output token that doesn't match what the user listed) is never swept, never emitted as `DustCollected`, and is left sitting on the shared `dispatcher` address. The same unswept-if-not-listed pattern exists in the output-side `_execute()` sweep, which only iterates `order.output.assets`: [3](#0-2) 
and in the Tron/legacy `IntentGatewayV2.sol` variant with the same structure: [4](#0-3) 

Because `_params.dispatcher` is one persistent, address-stable `CallDispatcher` instance shared across all orders and all apps (docs confirm: "the dispatcher contract holds tokens temporarily during execution"), any balance stranded there after a transaction completes is *not* protected by `IntentGatewayV2`'s escrow accounting (`_orders[commitment][token]`) at all — it's simply an ERC20/ETH balance sitting on a public, unauthenticated contract. Since `dispatch()` accepts calls from anyone, an attacker monitoring the dispatcher's balance can immediately call it directly with a `Call` that transfers that stranded balance to themselves, bypassing `IntentGatewayV2` entirely.

### Impact Explanation
This is a direct theft-of-funds primitive: any token value that ends up on the `CallDispatcher` outside of an app's expected sweep list (via slippage in a predispatch/postdispatch swap, a token-list/output mismatch, or any other deviation between what a `Call[]` produces and what the calling app sweeps back) becomes freely takeable by an unprivileged attacker with a single direct call to `dispatch()`. No relayer, prover, admin, or governance compromise is required — the entrypoint is fully public and permissionless by design.

### Likelihood Explanation
`predispatch`/`postdispatch` calldata is explicitly user-supplied and arbitrary (Uniswap swaps, LP unwraps, etc. per the documented use case), so any mismatch between the actual token(s) produced by that calldata and the token(s) listed in `order.inputs`/`order.output.assets` — whether from slippage, a user/integrator mistake, or a deliberately crafted self-order — creates exploitable dust on the dispatcher. Given `dispatch()` requires no permission, exploitation is a single trivial transaction as soon as any such balance exists.

### Recommendation
Restrict `CallDispatcher.dispatch()` to a caller allowlist (only the apps that legitimately use it, e.g. `IntentGatewayV2`, `HyperFungibleToken`), or make dispatcher instances per-call/ephemeral (e.g. deploy a fresh minimal-proxy dispatcher per invocation) so no value can persist between transactions. Additionally, have each app's sweep logic capture the *entire* balance change of the dispatcher (all touched tokens), not just the tokens explicitly listed in the order, and emit `DustCollected` for genuinely unexpected residues so they are swept to the protocol treasury rather than left claimable by any caller.

### Proof of Concept
1. A user (or attacker themselves) calls `IntentGatewayV2.placeOrder` with `predispatch.call` encoding a Uniswap swap from `tokenA` → `tokenB`, sending `tokenA` into the dispatcher, but sets `order.inputs = [{token: tokenA, amount: dust}]` (omitting `tokenB`).
2. `placeOrder`'s predispatch phase executes the swap via `ICallDispatcher(dispatcher).dispatch(order.predispatch.call)` and only sweeps `tokenA` back per `order.inputs`; the resulting `tokenB` balance remains on `dispatcher`. [5](#0-4) 
3. Any attacker directly calls `CallDispatcher.dispatch(abi.encode([Call({to: tokenB, value: 0, data: abi.encodeWithSelector(IERC20.transfer.selector, attacker, IERC20(tokenB).balanceOf(dispatcher))})]))`.
4. Because `dispatch()` has no caller check, the call succeeds and transfers the entire stranded `tokenB` balance to the attacker. [1](#0-0)

    function dispatch(bytes memory encoded) external {
        Call[] memory calls = abi.decode(encoded, (Call[]));
        uint256 callsLen = calls.length;
        for (uint256 i = 0; i < callsLen; ++i) {
            Call memory call = calls[i];
            uint32 size;
            address to = call.to;
            assembly {
                size := extcodesize(to)
            }

            if (size == 0) {
                revert NotContract(to);
            }

            (bool success, bytes memory result) = to.call{value: call.value}(call.data);
            if (!success) revert CallFailed(to, result);
        }
