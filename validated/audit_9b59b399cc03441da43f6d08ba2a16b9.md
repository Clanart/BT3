### Title
Uncontrolled Recursion in `PuzzleWithRestrictions.from_memo()`/`MofN` Memo Parsing Leading to Denial of Service - (File: chia/wallet/puzzles/custody/custody_architecture.py)

### Summary
`PuzzleWithRestrictions.from_memo()` recursively parses an untrusted CLVM `Program` memo into a `MofN` tree of `PuzzleWithRestrictions` objects with no limit on nesting depth. Because `MofN` members can themselves recursively contain `PuzzleWithRestrictions` objects whose `puzzle` field is another `MofN`, an attacker who controls the memo bytes attached to a coin (e.g., a plotNFT or custody-architecture coin's `memo_blob`) can construct a deeply nested `further_branching` memo that causes unbounded Python recursion when a wallet/pool client parses it.

### Finding Description
`from_memo()` at [1](#0-0)  checks `further_branching_prog != Program.to(None)` and, if true, recurses via `PuzzleWithRestrictions.from_memo(memo)` once per member memo inside `MofNHint.from_program()`. There is no depth counter, no recursion limit check, and no bound on the number of `MofN` nesting levels an attacker can encode in the memo `Program`. Each level of nesting only costs a few bytes of CLVM structure to add another (m, [members]) wrapper, so an attacker can cheaply construct a memo with thousands of nested `MofN` levels.

This code path is exercised by `PlotNFT.get_next_from_coin_spend()` at [2](#0-1) , which calls `PuzzleWithRestrictions.from_memo(singleton_create_coin.memo_blob.rest())` on the memo of a coin created by an observed spend — memo content that is entirely controlled by whoever creates that coin (any unprivileged spend-bundle submitter creating a `CREATE_COIN` condition with a crafted memo). Any pool client, wallet, or Data Layer-adjacent tool that walks singleton lineage and calls `from_memo()` on attacker-supplied memo data will recurse into the Python interpreter's call stack proportional to memo nesting depth, exactly matching the CWE-674 "Uncontrolled Recursion" class in the report: no bound on recursion depth for a recursively-structured input, leading to a Python `RecursionError`/native stack exhaustion.

Python normally raises `RecursionError` gracefully at moderate depths, but with sufficiently deep nesting (or if wrapped C-extension frames are involved, e.g. `chia_rs` `Program` operations invoked per recursion level such as `.at()`, `.as_iter()`, `G1Element.from_bytes()`), the process can crash with a native stack overflow rather than a catchable Python exception, terminating the client process — the direct analog to the Elasticsearch node crash described in the report.

### Impact Explanation
A wallet, pool client, or PlotNFT-tracking tool that processes a maliciously crafted coin's memo (via `PuzzleWithRestrictions.from_memo()`, reachable through `PlotNFT.get_next_from_coin_spend()` or any wallet-side custody-architecture sync code) can be crashed or made unresponsive by a single spend that creates a coin with a deeply nested `MofN` memo. This is a Medium-severity availability/DoS issue against wallet/pool-tracking clients that parse observed on-chain memos, consistent with the CVSS 6.5 (AV:N/AC:L/PR:L/UI:N/S:U/C:N/I:N/A:H) profile of the report — no confidentiality/integrity impact, but availability impact to the parsing client/process.

### Likelihood Explanation
Likelihood is high for any client that automatically parses on-chain memo data for custody-architecture/PlotNFT tracking, because: (1) constructing the malicious memo requires only ordinary CLVM list nesting, not any privileged network position; (2) the coin creating the malicious memo can be spent by any user via a standard `CREATE_COIN` condition with a memo; (3) no validation of memo depth exists in `from_memo()` before recursing.

### Recommendation
Add an explicit recursion/nesting depth limit (and/or convert `from_memo()`/`MofNHint.from_program()` to an iterative work-stack implementation, following the pattern already used in `chia/types/blockchain_format/tree_hash.py`'s `sha256_treehash()`) so that parsing an untrusted memo cannot exceed a bounded number of stack frames. Reject memos whose `further_branching` nesting exceeds a sane maximum (e.g., matching realistic `MofN` usage) before recursing.

### Proof of Concept
1. Programmatically build a `Program` memo of the form `(spec_namespace [nonce, [], 1, (m, [<memo>])])` where `<memo>` is itself another such nested structure, repeated N times (e.g., N = 100,000), each wrapping the previous as the sole `MofN` member.
2. Attach this memo as the `memo_blob` on a `CREATE_COIN` condition of a spend bundle submitted by an unprivileged spender (e.g., simulating a PlotNFT pool-transition coin).
3. Have a wallet/pool client observe this coin creation and call `PuzzleWithRestrictions.from_memo(memo)` (directly, or transitively via `PlotNFT.get_next_from_coin_spend()`).
4. Observe that the recursive call chain in `from_memo()` → `MofNHint.from_program()` → `from_memo()` grows linearly with N, exhausting the Python/native call stack and crashing or hanging the parsing process. [1](#0-0) [2](#0-1)

    def from_memo(cls, memo: Program) -> PuzzleWithRestrictions:
        if memo.atom is not None or memo.first() != Program.to(cls.spec_namespace):
            raise ValueError("Attempting to parse a memo that does not belong to this spec")
        nonce = memo.at("rf")
        restriction_hints_prog = memo.at("rrf")
        further_branching_prog = memo.at("rrrf")
        puzzle_hint_prog = memo.at("rrrrf")
        additional_memos = memo.at("rrrrrf") if memo.at("rrrrr").atom is None else None
        restriction_hints = [RestrictionHint.from_program(hint) for hint in restriction_hints_prog.as_iter()]
        further_branching = further_branching_prog != Program.to(None)
        if further_branching:
            m_of_n_hint = MofNHint.from_program(puzzle_hint_prog)
            puzzle: MIPSComponent = MofN(
                m=m_of_n_hint.m, members=[PuzzleWithRestrictions.from_memo(memo) for memo in m_of_n_hint.member_memos]
            )
        else:
            puzzle_hint = MemberHint.from_program(puzzle_hint_prog)
            puzzle = UnknownMember(puzzle_hint)
