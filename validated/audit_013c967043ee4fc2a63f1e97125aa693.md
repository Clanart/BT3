### Title
GaslessSwapRouter's on-chain `getAmountIn` uses manipulable spot AMM reserves as an unprotected price oracle for gasless-swap admission and settlement - ([File: kaiax/gasless/impl/tx_pool.go])

### Summary
The KIP-247 gasless module validates and settles `swapForGas` transactions using a live, un-averaged spot price read from a Uniswap-V2-style DEX pool (`GaslessSwapRouter.getAmountIn` / `getDEXInfo`), exactly the "thin AMM pool used as a price oracle" pattern that Float Protocol was exploited through. An unprivileged gasless-swap sender who can move the reserves of the underlying token/WKAIA pool within the same block can manipulate this spot price to (a) get a `swapForGas` transaction admitted to the tx pool with an artificially favorable required-`amountIn`, and (b) have the on-chain swap execute at the same manipulated rate, extracting excess WKAIA from the pool while the proposer only recovers the fixed, gas-cost-based `amountRepay`.

### Finding Description
`checkBalanceForSwap` computes the "required" token input purely from a live view call into the swap router/DEX: [1](#0-0) 

`GetAmountIn` on `GaslessSwapRouter` is a `view` function that queries a registered per-token DEX (via `getDEXInfo`/`DexAddress`) and returns an amount derived from the pool's current reserves: [2](#0-1) [3](#0-2) 

This is functionally the same as Uniswap V2's `getAmountIn(amountOut, reserveIn, reserveOut)` spot-price formula used elsewhere in the repo's Uniswap bindings, with no TWAP, no minimum-liquidity requirement, and no manipulation resistance: [4](#0-3) 

The gasless flow then unconditionally advances real value to the sender before the swap settles: `ExtractTxBundles` always prepends a `LendTxGenerator`-produced transaction (funded by the block proposer) ahead of the approve/swap pair in the same bundle, and the lend amount/repay amount are fixed formulas based on gas price × gas, not on the actual swap output: [5](#0-4) [6](#0-5) 

Because `amountRepay` is a fixed gas-based figure while the actual swap yield is determined by whatever exchange rate the DEX gives at execution time (`SwappedForGas.FinalUserAmount`), any amount the swap yields above `amountRepay` goes to the user: [7](#0-6) 

An attacker who is also the sender of the gasless swap can, within the same block/bundle window, push the underlying token/WKAIA pool's reserves in their favor (e.g., via a preceding swap in the same low-liquidity pool, analogous to manipulating Float Protocol's thin FLOAT/USDC Uniswap V3 pool) so that:
1. `checkBalanceForSwap`'s `GetAmountIn`-based admission check is satisfied with a smaller-than-fair `amountIn`, and
2. the actual on-chain `swapForGas` execution (immediately following the manipulation, same block) returns disproportionately more WKAIA than the fair-market rate would allow.

The excess value is extracted from the DEX pool's liquidity providers, while the fixed-formula `amountRepay` guarantees the proposer/lender is unaffected — meaning there is no economic check tying the swap's realized rate to a manipulation-resistant reference price, so the attacker profits purely from the shallow-liquidity spot-price read.

### Impact Explanation
This allows unauthorized value extraction from a DEX pool trusted by the gasless protocol as its exchange-rate source, reachable by any account that can submit a `GaslessApproveTx`/`GaslessSwapTx` pair — no privileged role required. Losses scale with the depth of the token's registered DEX pool, mirroring the Float Protocol incident where a thin liquidity oracle enabled a six-figure extraction. This is classified Medium given it requires the attacker to control (or influence) a specific low-liquidity token pool registered in `GaslessSwapRouter`'s DEX registry, limiting blast radius to gasless-supported low-liquidity tokens rather than core protocol funds.

### Likelihood Explanation
Likelihood is moderate: it requires (1) a whitelisted gasless token whose DEX pool has shallow liquidity, and (2) the attacker being able to manipulate that pool's reserves and land both the manipulation and the `swapForGas` bundle atomically in the same block — achievable by a single searcher/sender since gasless bundles are proposer-assembled within one block and the price check has no cooldown, TWAP, or liquidity-depth floor.

### Recommendation
Do not rely on a single-block spot AMM read for both tx-pool admission and settlement guarantees. Introduce a manipulation-resistant reference price (e.g., time-weighted average price over multiple blocks, or a minimum-liquidity/maximum-price-impact bound) in `GaslessSwapRouter.getAmountIn`, and/or make `amountRepay`/settlement validation in `checkBalanceForSwap` and the on-chain swap cross-check against a bounded price-impact threshold rather than trusting the live reserve ratio at check-time and execution-time.

### Proof of Concept
1. Attacker registers/uses a whitelisted gasless token `T` whose DEX pool (per `getDEXInfo(T)`) has shallow `T`/WKAIA liquidity.
2. In the target block, attacker (or an associated account) performs a large swap in that same pool to shift the reserve ratio favorably for `T`→WKAIA conversion.
3. Attacker immediately submits `GaslessApproveTx` + `GaslessSwapTx(token=T, amountIn, minAmountOut, amountRepay, deadline)` where `amountIn`/`minAmountOut` are computed against the manipulated price via `GaslessSwapRouter.GetAmountIn` — satisfying `checkBalanceForSwap`'s `swapArgs.AmountIn >= requiredAmountIn` check (kaiax/gasless/impl/tx_pool.go:128-142).
4. The block builder bundles `[LendTxGenerator, GaslessApproveTx, GaslessSwapTx]` (kaiax/gasless/impl/builder.go:28-72); the proposer's `LendTx` unconditionally funds the sender first.
5. `swapForGas` executes against the still-manipulated pool state in the same block, yielding WKAIA above the fair-market rate; `amountRepay` (fixed, gas-based) is paid back to the lender, and the surplus (`FinalUserAmount`) is kept by the attacker — extracted from the pool's liquidity providers rather than reflecting a fair exchange rate.

**Uncertainty/limitations**: The `GaslessSwapRouter.sol` Solidity source was not available in the indexed codebase (only compiled bytecode/bindings), so the exact internal slippage/repay logic inside `swapForGas` could not be directly read — this analysis relies on the ABI, the `checkBalanceForSwap` Go logic, and the `tests/gasless_test.go` behavioral assertions (e.g., `FinalUserAmount`). A full source review of `GaslessSwapRouter.sol` (likely outside this index due to size limits) would be needed to confirm whether any additional on-chain slippage guard beyond `minAmountOut` exists. Starting a Devin session with full repository access would allow retrieving and auditing that contract source directly.

func (g *GaslessModule) ExtractTxBundles(txs []*types.Transaction, prevBundles []*builder.Bundle) []*builder.Bundle {
	// there are only at most two gasless transactions in pending for a sender
	bundles := []*builder.Bundle{}
	approveTxs := map[common.Address]*types.Transaction{}
	targetTxHash := common.Hash{}
	for _, tx := range txs {
		addr, err := types.Sender(g.signer, tx)
		if err != nil {
			continue
		}
		if g.IsApproveTx(tx) {
			approveTxs[addr] = tx
		} else if g.IsSwapTx(tx) && g.IsExecutable(approveTxs[addr], tx) {
			bundleTxs := builder.NewTxOrGenList(g.GetLendTxGenerator(approveTxs[addr], tx))
			if approveTxs[addr] != nil {
				bundleTxs = append(bundleTxs, builder.NewTxOrGenFromTx(approveTxs[addr]))
			}
			bundleTxs = append(bundleTxs, builder.NewTxOrGenFromTx(tx))

			b := builder.NewBundle(
				bundleTxs,
				targetTxHash,
				false,
			)

			targetTxHash = tx.Hash()

			isConflict := false
			for _, prev := range append(prevBundles, bundles...) {
				if prev.IsConflict(b) {
					isConflict = true
					break
				}
			}
			if isConflict {
				// Gasless transactions will just fail even if they aren't bundled.
				continue
			}
			bundles = append(bundles, b)
		} else {
			targetTxHash = tx.Hash()
		}
	}
	return bundles
}

func lendAmount(approveTxOrNil, swapTx *types.Transaction) *big.Int {
	r := new(big.Int)

	// R2 = ApproveTx.Fee() if exists
	if approveTxOrNil != nil {
		r.Add(r, approveTxOrNil.Fee())
	}

	// R3 = SwapTx.Fee()
	r.Add(r, swapTx.Fee())

	// LendAmount = R2 + R3
	return r
}

func repayAmount(approveTxOrNil, swapTx *types.Transaction) *big.Int {
	// R1 = LendTx.Fee() = SwapTx.GasPrice() * TxGas
	r1 := new(big.Int).Mul(swapTx.GasPrice(), new(big.Int).SetUint64(params.TxGas))

	// RepayAmount = R1 + R2 + R3
	return new(big.Int).Add(r1, lendAmount(approveTxOrNil, swapTx))
}
