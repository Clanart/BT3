### Title
Setting KIP-71 `GasTarget` governance parameter to 0 causes a division-by-zero panic in `NextMagmaBlockBaseFee`, crashing every node (network-wide DoS) - (File: `params/kip71_config.go`)

### Summary
The KIP-71 governance parameter `GasTarget` is validated with a `noopFormatChecker` that never rejects zero, allowing a governing/validator node to vote `GasTarget = 0` into effect. Once active, every subsequent block's base-fee computation in `NextMagmaBlockBaseFee` divides by `gasTarget`, causing an unrecovered `big.Int` division-by-zero panic that crashes all nodes processing the block (proposer, validators, and full/RPC nodes alike).

### Finding Description
The `Kip71GasTarget` parameter definition uses `noopFormatChecker`, which performs no bounds/zero check on the value, unlike its sibling `Kip71BaseFeeDenominator` which explicitly requires `v != 0`: [1](#0-0) 

Votes are accepted as long as `Canonicalizer` succeeds and `FormatChecker(cv)` returns true, so a governance vote setting `Kip71GasTarget=0` passes validation cleanly: [2](#0-1) 

The resulting `ParamSet` is converted into a `KIP71Config` and consumed by `NextMagmaBlockBaseFee`, which computes the next block base fee for every Magma-enabled block: [3](#0-2) 

In `NextMagmaBlockBaseFee`, when `parentGasUsed != gasTarget`, the code performs `x.Div(x, new(big.Int).SetUint64(gasTarget))` on both the "increase" and "decrease" branches. With `gasTarget == 0`, this is a division by zero: [4](#0-3) 

Note that the code explicitly guards `BaseFeeDenominator == 0` ("To avoid panic, set the fluctuation range small") but has no equivalent guard for `GasTarget == 0`: [5](#0-4) 

`NextMagmaBlockBaseFee`/`VerifyMagmaHeader` is invoked during block header validation and assembly for every block once Magma is active, so the panic is deterministic and hit by every honest node (proposer building the block and every validator/full node verifying it): [6](#0-5) 

`big.Int.Div` in Go's standard library panics with "division by zero" when the divisor is zero, and there is no recover() wrapping this governance-parameter-driven consensus path.

### Impact Explanation
This is a complete, network-wide denial of service matching the CVE's "hang or frequently repeatable crash (complete DOS)" impact class: once the malicious `GasTarget=0` vote is enacted, every node that processes a subsequent block (proposer during block assembly and every validator/full node during header verification) panics and crashes. This halts the entire chain, since the same deterministic computation is executed by all nodes — there is no divergence, only total consensus/liveness failure until the software is patched/parameter reverted.

### Likelihood Explanation
The action requires a governance vote, which is restricted to the governing node(s)/validators (a privileged but reachable on-chain actor, analogous to the CVE's `PR:H` "high privileged" attacker), and no additional collusion or off-chain compromise is needed. The vote-acceptance path performs no rejection of zero for `Kip71GasTarget`, so the vote is accepted and enacted through the normal governance flow, making the trigger straightforward once cast.

### Recommendation
Add a non-zero `FormatChecker` for `Kip71GasTarget` (mirroring `Kip71BaseFeeDenominator`'s check), and additionally add a defensive `gasTarget == 0` guard inside `NextMagmaBlockBaseFee` (similar to the existing `BaseFeeDenominator == 0` fallback) so that a zero value cannot reach the division regardless of how it was introduced.

### Proof of Concept
1. A governing/validator node casts a governance vote setting `kip71.gastarget = 0`. `NewVoteData` accepts it because `Kip71GasTarget`'s `FormatChecker` is `noopFormatChecker` (`kaiax/gov/param.go` lines 324-334).
2. The vote is tallied and takes effect at the next epoch, updating the active `ParamSet.GasTarget` to `0`.
3. On the next block after any nonzero `GasUsed`, `NextMagmaBlockBaseFee` is called with `gasTarget = 0`; since `parentGasUsed != 0 != gasTarget`, execution enters either the `parentGasUsed > gasTarget` branch (`params/kip71_config.go` line 100-102) or `else` branch (line 118-120), both performing `x.Div(x, new(big.Int).SetUint64(0))`, which panics.
4. Every node executing block assembly or `VerifyMagmaHeader` for that block panics and crashes, halting the network.

func NewVoteData(voter common.Address, name string, value any) VoteData {
	param, ok := gov.Params[gov.ParamName(name)]
	if !ok {
		param, ok = gov.ValidatorParams[gov.ParamName(name)]
		if !ok {
			logger.Error("Invalid vote name", "name", name)
			return nil
		}
	}

	cv, err := param.Canonicalizer(value)
	if err != nil {
		logger.Error("Canonicalize error", "name", name, "value", value, "err", err)
		return nil
	}

	if !param.FormatChecker(cv) {
		logger.Error("Format check error", "name", name, "value", value)
		return nil
	}

	return &voteData{
		voter: voter,
		name:  gov.ParamName(name),
		value: cv,
	}
}

		return fmt.Errorf("header is missing baseFee")
	}
	// Verify the baseFee is correct based on the parent header.
	expectedBaseFee := kc.NextMagmaBlockBaseFee(parentHeaderNumber, parentHeaderBaseFee, parentHeaderGasUsed)
	if headerBaseFee.Cmp(expectedBaseFee) != 0 {
		return fmt.Errorf("invalid baseFee: have %s, want %s, parentBaseFee %s, parentGasUsed %d",
			headerBaseFee, expectedBaseFee, parentHeaderBaseFee, parentHeaderGasUsed)
	}
	return nil
}
