### Title
Unhandled `UnicodeDecodeError` in NFT metadata URI decoding causes repeated wallet crash on malicious NFT — (File: `chia/wallet/nft_wallet/nft_puzzle_utils.py`)

### Summary
`get_nft_info_from_puzzle()` decodes the on-chain `data_uris`, `meta_uris`, and `license_uris` fields of an NFT's curried metadata using unguarded `str(uri, "utf-8")` calls, with no `try/except` around the decode. Because these byte strings are attacker-controlled CLVM curry parameters (set by whoever mints, updates, or transfers the NFT), any actor can craft an NFT whose metadata contains invalid UTF-8 bytes in these fields, causing every wallet that later loads or displays that NFT to raise an unhandled `UnicodeDecodeError`. This is the same bug class as ALPINE-CVE-2019-10691: a service (the Dovecot auth process there, the Chia wallet/NFT-info pipeline here) crashes when asked to JSON-serialize or process a string field containing invalid UTF-8 supplied by an untrusted party, and the crash is repeatable on demand.

### Finding Description
`get_nft_info_from_puzzle()` uncurries the NFT puzzle and converts the raw byte atoms from `data_uris`/`meta_uris`/`license_uris` directly to Python `str` objects: [1](#0-0) 

Note the contrast with the codebase's own established safe pattern for decoding untrusted, attacker-supplied bytes elsewhere (e.g. CAT memo decoding), which explicitly wraps the decode in `try/except UnicodeError` and falls back to a safe default instead of propagating the exception: [2](#0-1) 

`get_nft_info_from_puzzle` has no equivalent guard. These URI fields originate from the NFT's curried metadata program, which is fully controlled by whoever mints the NFT or (via `metadata_updater_hash`) updates it on-chain — this is the same class of "attacker fully controls the byte content" data source that the memo-decoding code defends against. The function is referenced from both `chia/wallet/wallet_state_manager.py` and `chia/wallet/wallet_rpc_api.py`, indicating it is invoked both automatically as the wallet processes/tracks NFT coin state and via direct RPC calls (e.g., `nft_get_info`/`nft_get_nfts`), though exact call-site line numbers could not be confirmed within the available search budget.

### Impact Explanation
Any wallet (recipient of an offer, DID-linked NFT holder, or a wallet simply tracking/syncing an NFT wallet) that encounters an NFT whose metadata contains an invalid UTF-8 byte sequence in `data_uris`, `meta_uris`, or `license_uris` will hit an unhandled exception when the wallet attempts to build `NFTInfo` for that coin. Because NFT coin state is re-evaluated on every wallet sync/restart and on every RPC call that enumerates NFT info, a single malicious NFT sent to or owned by a wallet can repeatedly and reliably halt NFT-info processing for that wallet, denying legitimate NFT/DID/offer functionality — directly analogous to Dovecot's "repeatedly crash the authentication service" impact.

### Likelihood Explanation
High likelihood: minting an NFT (or crafting an offer that delivers one) with arbitrary byte content in the metadata URI fields requires no special privilege — it is a standard, permissionless wallet operation. No consensus rule constrains these URI byte strings to valid UTF-8, so the invalid sequence reaches the wallet unmodified and is guaranteed to be processed whenever the receiving wallet inspects that NFT.

### Recommendation
Wrap each `str(uri, "utf-8")` call in `get_nft_info_from_puzzle()` in a `try/except UnicodeDecodeError` block (mirroring the pattern already used for CAT memo decoding), falling back to a safe representation (e.g., the raw hex string or an empty placeholder) instead of propagating the exception, so that malformed NFT metadata cannot halt wallet NFT-info processing.

### Proof of Concept
1. Mint an NFT (or construct an offer containing one) whose curried metadata sets `data_uris` (or `meta_uris`/`license_uris`) to a byte string containing an invalid UTF-8 sequence, e.g. `b"\xff\xfe"`.
2. Transfer/deliver this NFT to a victim wallet, or have any wallet begin tracking the coin (e.g., via an accepted offer or DID-associated NFT).
3. When the wallet processes the coin and calls `get_nft_info_from_puzzle()` (during sync or via an RPC call such as `nft_get_info`), the line `str(uri, "utf-8")` raises `UnicodeDecodeError`, which is unhandled and propagates, disrupting NFT info retrieval/processing for that wallet every time the coin/metadata is evaluated.
