### Title
Webhook HMAC verification does not bind the signature to the `X-Shopify-Shop-Domain` header, enabling cross-shop webhook forgery/replay - ([File: lib/shopify_app/controller_concerns/payload_verification.rb])

### Summary
This is analogous to the reported `PortalFacet` flaw: the contract validated that a repayment was *authentic* (a legitimate token transfer) but never validated that the specific token matched the specific debt being repaid, letting an attacker satisfy the wrong obligation. In `shopify_app`, `WebhookVerification`/`PayloadVerification` validates that a webhook body is *authentic* (signed with the app's client secret) but never binds that signature to the specific shop the request claims to be for. The shop identity is taken from the unsigned `X-Shopify-Shop-Domain` header, so a valid HMAC computed for one shop's webhook can be replayed/relabeled against a different shop.

### Finding Description
`hmac_valid?` computes the HMAC purely over `request.raw_post` and compares it against the `X-Shopify-Hmac-Sha256` header, using the app-wide client secret: [1](#0-0) 

`WebhookVerification#verify_request` only checks `hmac_valid?(data)` before allowing the request through; it never inspects or verifies `shop_domain`: [2](#0-1) 

`shop_domain` is read straight from the `X-Shopify-Shop-Domain` request header, which is **not** part of the HMAC-signed payload: [3](#0-2) 

`WebhooksController#receive` forwards the raw body and the full (unsigned) header set to `ShopifyAPI::Webhooks::Registry.process`, which extracts `topic`/`shop` from those headers and dispatches to the app's job handlers: [4](#0-3) 

Generated job handlers then trust that `shop` value to select and mutate a specific tenant's row — e.g. the app-uninstall job destroys the `Shop` record matched by the header-derived domain: [5](#0-4) 

Because the HMAC only proves "this body was signed with the app's client secret" and not "this body+shop pairing is what Shopify sent," any party who can obtain one genuinely-signed webhook delivery (e.g., a merchant who installs the app on their own store and receives real webhooks for their own shop) can resend that exact raw body to the app's public webhook endpoint while substituting an arbitrary `X-Shopify-Shop-Domain` header. The signature check still passes (it never examined the header), so the request is accepted and processed as if it originated from the victim shop.

### Impact Explanation
This directly maps to the report's core defect class — accepting a valid credential/asset without checking it corresponds to the specific target it is meant to satisfy, causing action against the wrong entity. Here it can cause cross-shop state mutation using a webhook payload that legitimately belongs to a different shop, e.g. triggering `app/uninstalled` handling (`shop.destroy`) or shop/customer redact jobs against a victim shop's tenant record using a header value the attacker fully controls. This is a genuine cross-shop/cross-tenant integrity issue reachable by any party (not privileged/dev-only) with access to at least one genuine webhook delivery for their own shop.

### Likelihood Explanation
Requires the attacker to obtain one valid HMAC-signed webhook payload (trivial: install the app on any store they control, which is a standard, unprivileged merchant action) and then send an HTTP POST directly to the app's public webhook URL with a forged shop-domain header — no secret knowledge, no elevated privileges, and no dependency on leaked credentials.

### Recommendation
Bind the verified webhook to a specific shop by incorporating the shop domain into the trust decision — e.g., verify the `X-Shopify-Shop-Domain` header corresponds to a shop with an active install/session before dispatching, or otherwise ensure the topic/shop pairing used for job dispatch is derived from data that is itself covered by the HMAC (per Shopify's guidance, treat headers as untrusted metadata and cross-check against the app's own installed-shop registry before performing destructive actions).

### Proof of Concept
1. Install the target app on an attacker-controlled shop (`attacker.myshopify.com`); trigger a genuine webhook delivery (e.g., `app/uninstalled` has an empty JSON body `{}`), capturing the raw POST body and its `X-Shopify-Hmac-Sha256` header value.
2. Send a new POST to the app's webhook endpoint (e.g. `/webhooks/app_uninstalled`) with:
   - Body: identical to the captured raw body (`{}`)
   - Header `X-Shopify-Hmac-Sha256`: the captured (still valid) HMAC
   - Header `X-Shopify-Shop-Domain`: `victim.myshopify.com`
   - Header `X-Shopify-Topic`: `app/uninstalled`
3. `hmac_valid?` in `lib/shopify_app/controller_concerns/payload_verification.rb` succeeds because the signature only depends on the (unchanged) body.
4. `ShopifyAPI::Webhooks::Registry.process` dispatches to the generated `AppUninstalledJob`, which looks up `Shop.find_by(shopify_domain: "victim.myshopify.com")` and calls `shop.destroy`, deleting the victim shop's local record despite the app never actually being uninstalled from that shop.

    def shopify_hmac
      request.headers["HTTP_X_SHOPIFY_HMAC_SHA256"]
    end

    def hmac_valid?(data)
      secrets = [ShopifyApp.configuration.secret, ShopifyApp.configuration.old_secret].reject(&:blank?)

      secrets.any? do |secret|
        digest = OpenSSL::Digest.new("sha256")
        ActiveSupport::SecurityUtils.secure_compare(
          shopify_hmac,
          Base64.strict_encode64(OpenSSL::HMAC.digest(digest, secret, data)),
        )
      end
    end
```

class AppUninstalledJob < ActiveJob::Base
  extend ShopifyAPI::Webhooks::WebhookHandler

  def self.handle(topic:, shop:, body:, webhook_id:, api_version:)
    perform_later(topic: topic, shop_domain: shop, webhook: body)
  end

  def perform(topic:, shop_domain:, webhook:)
    shop = Shop.find_by(shopify_domain: shop_domain)

    if shop.nil?
      logger.error("#{self.class} failed: cannot find shop with domain '#{shop_domain}'")
      
      raise ActiveRecord::RecordNotFound, "Shop Not Found"
    end

    logger.info("#{self.class} started for shop '#{shop_domain}'")
    shop.destroy
  end
```
