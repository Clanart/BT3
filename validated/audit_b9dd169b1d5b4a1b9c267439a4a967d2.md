### Title
Static (non-dynamic-gas) EVM precompiles charge only linear `RequiredGas` but ABI-decode calldata with `Unpack` before executing, allowing sub-linear-cost/super-linear-cost memory allocation - ([File: precompiles/common/precompiles.go])

### Summary
The `bank`, `distribution`, `gov`, `oracle`, `slashing`, `upgrade`, `authz` and other static precompiles (built on `Precompile.Prepare`/`Precompile.Run` in `precompiles/common/precompiles.go`) accept string-array / tuple-array ABI arguments and unconditionally call `method.Inputs.Unpack(argsBz)` in `Prepare`, but the gas charged for the call (`RequiredGas`) is computed purely as a linear function of `len(input)` before `Unpack` ever runs.

### Finding Description
`Precompile.RequiredGas` ( [1](#0-0) ) delegates to `p.executor.RequiredGas`, which for most static precompiles is `DefaultGasCost`-style — a flat cost plus a per-byte-of-input charge (see the analogous `DefaultGasCost` at [2](#0-1) , and e.g. `bank`'s `RequiredGas` at [3](#0-2) ). go-ethereum's `vm.RunPrecompiledContract` deducts exactly this linear amount before calling `Precompile.Run`.

`Precompile.Run` then calls `Prepare`, which performs the actual ABI decode via `method.Inputs.Unpack(argsBz)` with **no additional gas metering of the decode itself** ( [4](#0-3) ).

This is precisely the bug class in the reported Spring Data Commons advisory: a cheap, length-priced request triggers a decode/binding step whose actual CPU/memory cost is not bounded by that price. The codebase's own comments and tests prove the class is real and already mitigated for the *dynamic-gas* precompile path: `DynamicGasPrecompile.RunAndCalculateGas` explicitly calls `chargeDecodeGas`/`DecodeGasCost` **before** calling `Unpack`, with the comment: "ABI decoding of attacker-controlled calldata can cost far more than len(input) (a single string can be referenced by many array/tuple slots)... The static-precompile path charges RequiredGas in vm.RunPrecompiledContract before running; that step is skipped for dynamic-gas precompiles, so we apply the equivalent charge here." ( [5](#0-4) , mitigation logic at [6](#0-5)  and cost model at [7](#0-6) ).

The comment's own claim — that "the static-precompile path charges RequiredGas... before running" — is true only in the sense that *some* linear gas amount is charged; it is not equivalent to `chargeDecodeGas`, because go-ethereum's ABI `Unpack` for dynamic types (`string[]`, `tuple[]` containing `string`) walks offset-addressed slots, and a single payload can be aliased/referenced from many array or tuple slots, producing string-copy volume that scales with `slots × payload_size` rather than with `len(input)`. This exact amplification is what the test `TestVoteWeightedAliasedOptionsRejectedBeforeUnpack` demonstrates for the (already patched) dynamic-gas `gov.VoteWeighted` method ( [8](#0-7) ), including a crafted "aliased" tuple offset that inflates real Unpack cost while keeping calldata itself compact (~40 KiB) yet decoded copy volume in the tens of megabytes.

Grepping the ABI files shows multiple *static* precompiles expose dynamic array/tuple types (`string[]`/`tuple[]`) reachable through the unmitigated `Precompile.Prepare`/`Run` path: `precompiles/bank/abi.json`, `precompiles/distribution/abi.json`, `precompiles/gov/abi.json` (for its static, non-`VoteWeighted` methods), `precompiles/oracle/abi.json`, `precompiles/slashing/abi.json`, `precompiles/upgrade/abi.json`, `precompiles/authz/abi.json`, and their `legacy/vNN` mirrors. Any EVM method registered through `common.NewPrecompile` (as opposed to `NewDynamicGasPrecompile`) inherits this gap.

### Impact Explanation
An attacker submitting a normal EVM transaction (or `eth_call`) to any of these static precompiles with a crafted calldata payload using aliased offsets in a `string[]`/`tuple[]` argument can force the node to allocate memory disproportionate to the gas paid for the call, well beyond the linear per-byte charge in `RequiredGas`. Because the decode happens synchronously inside block execution / RPC serving, a sufficiently amplified payload can consume excessive heap on the node processing the transaction, causing high GC pressure, latency spikes, or process-level memory exhaustion — a resource-allocation DoS against the executing full node, potentially delaying block production beyond acceptable bounds if amplification is large enough within the calldata size limits imposed by the mempool/tx-size caps.

### Likelihood Explanation
Likelihood is constrained by EVM calldata gas costs and transaction/calldata size limits (larger calldata costs more base EVM gas and is capped by tx size), which bounds how much amplification an attacker can achieve per call — the same constraint the codebase's own comment acknowledges ("Calldata large enough to hit [maxDecodeWalkOps] is infeasible under EVM calldata gas costs"). However, the `gov` test itself demonstrates that ~40 KiB of calldata can already produce tens-of-megabytes of decode-copy volume via aliasing, i.e., meaningful amplification is achievable within realistic calldata sizes, and this can be repeated across many concurrently-processed transactions/precompile calls (e.g. via `eth_call`/`debug_traceCall` swarms against read-only static precompile methods, which cost even less gas) to multiply the effect.

### Recommendation
Apply the same `chargeDecodeGas`/`DecodeGasCost` pre-decode charge used by `DynamicGasPrecompile.RunAndCalculateGas` to the static `Precompile.Prepare`/`Run` path (or migrate string-array/tuple-array-bearing static precompile methods onto the dynamic-gas precompile mechanism) so that `Unpack`'s actual string-copy cost is priced and enforced before decoding, for every precompile ABI that exposes dynamic array/tuple-of-string arguments (bank, distribution, gov static methods, oracle, slashing, upgrade, authz, and their legacy vNN copies).

### Proof of Concept
Follow the pattern already proven for the (patched) dynamic-gas path in `TestVoteWeightedAliasedOptionsRejectedBeforeUnpack` ( [8](#0-7) ) — `craftAliasedVoteWeightedArgs` constructs a `tuple[]` where every element's dynamic-`string` offset points at the *same* trailing payload — but target it at a static precompile method (e.g., a `bank`/`distribution`/`oracle` method with a `string[]`/`tuple[]` argument reachable via `Precompile.Run`/`Prepare`) instead of `gov.VoteWeighted`. Since that path has no `chargeDecodeGas` equivalent, `method.Inputs.Unpack` will run unmetered and allocate the full amplified string-copy volume regardless of the linear `RequiredGas` charge deducted by `vm.RunPrecompiledContract`, confirming the DoS.

Note: I was not able to fully confirm within the available searches exactly which specific static precompile method signature is publicly reachable with a *dynamic, unbounded-length* string-array/tuple-array argument (as opposed to fixed-size arrays) end-to-end from an EVM transaction, since I could not open every ABI/method file for each of the 20+ affected precompile packages and legacy versions in the time available — a Devin session with full file access would be needed to enumerate and confirm the exact vulnerable method(s) and craft a concrete working exploit payload.

func (p Precompile) Prepare(evm *vm.EVM, input []byte) (sdk.Context, *abi.Method, []interface{}, error) {
	ctxer := state.GetDBImpl(evm.StateDB)
	if ctxer == nil {
		return sdk.Context{}, nil, nil, errors.New("cannot get context from EVM")
	}
	methodID, err := ExtractMethodID(input)
	if err != nil {
		return sdk.Context{}, nil, nil, err
	}
	method, err := p.MethodById(methodID)
	if err != nil {
		return sdk.Context{}, nil, nil, err
	}

	argsBz := input[4:]
	args, err := method.Inputs.Unpack(argsBz)
	if err != nil {
		return sdk.Context{}, nil, nil, err
	}

	return ctxer.Ctx(), method, args, nil
}

// chargeDecodeGas charges the (already-installed) gas meter for decoding the
// calldata, before it is decoded: a length-proportional scan cost that also
// bounds the DecodeGasCost scan, then the string-copy surcharge from
// DecodeGasCost. Its out-of-gas / overflow recovery is deliberately scoped to
// just these charges — a call that cannot afford the decode reverts here, while
// an executor that later exhausts its gas keeps its normal propagating
// out-of-gas semantics. Anything other than a gas-meter panic is re-raised.
func (d DynamicGasPrecompile) chargeDecodeGas(ctx sdk.Context, method *abi.Method, input []byte) (err error) {
	defer func() {
		if r := recover(); r != nil {
			switch r.(type) {
			case sdk.ErrorOutOfGas, sdk.ErrorGasOverflow:
				err = fmt.Errorf("%v", r)
			default:
				panic(r)
			}
		}
	}()
	scanCost := DefaultGasCost(input, false)
	ctx.GasMeter().ConsumeGas(scanCost, fmt.Sprintf("%s precompile calldata scan", d.name))
	decodeCost, ok := DecodeGasCost(method.Inputs, input)
	if !ok {
		// Calldata is structurally invalid (Unpack would reject it too); reject
		// now, without attempting the decode.
		return fmt.Errorf("invalid calldata encoding for %s", d.name)
	}
	// DecodeGasCost already includes scanCost; charge only the remaining
	// (string-copy) portion so the decode is priced exactly once.
	ctx.GasMeter().ConsumeGas(decodeCost-scanCost, fmt.Sprintf("%s precompile calldata decode", d.name))
	return nil
}

func DefaultGasCost(input []byte, isTransaction bool) uint64 {

// DecodeGasCost returns the gas to charge for ABI-decoding a dynamic precompile
// call's calldata (the full input, including the 4-byte selector) given the
// method's argument list. ok is false when the calldata is structurally invalid
// (or too deeply nested to price cheaply); the caller should reject such input
// rather than decode it, since the real decoder would reject it too.
//
// The Go ABI decoder's cost is dominated by copying `string` payloads: it
// materializes each string via string(output[begin:end]), and because a single
// string can be referenced by many array/tuple slots, the copied volume can be
// super-linear in len(input) (worst case ~len(input)^2). `bytes` values are
// excluded because the decoder reslices them without copying. The charge is
// therefore a linear pass over the input (DefaultGasCost) plus the string-copy
// volume the decoder would produce, priced at the KV read-per-byte rate.
func DecodeGasCost(args abi.Arguments, input []byte) (uint64, bool) {
	base := DefaultGasCost(input, false)
	if len(input) < 4 {
		return base, true
	}
	strBytes, ok := decodeStringCopyBytes(args, input[4:])
	if !ok {
		return 0, false
	}
	return satAdd(base, satMul(storetypes.KVGasConfig().ReadCostPerByte, strBytes)), true
}

func TestVoteWeightedAliasedOptionsRejectedBeforeUnpack(t *testing.T) {
	testApp := testkeeper.EVMTestApp
	ctx := testApp.NewContext(false, tmtypes.Header{}).WithBlockHeight(2)
	k := &testApp.EvmKeeper

	seiAddr, evmAddr := testkeeper.MockAddressPair()
	k.SetAddressMapping(ctx, seiAddr, evmAddr)

	p, err := gov.NewPrecompile(testApp.GetPrecompileKeepers())
	require.NoError(t, err)
	method := p.ABI.Methods[gov.VoteWeightedMethod]

	// Dimensions chosen so calldata stays small (~40KiB) while decoded copy
	// volume (options*weightBytes) prices above the 12.5M gas cap used in the
	// original reproduction. If Unpack ran, allocation would be only ~8MiB —
	// CI-safe — and the error would be the post-decode max-options message
	// instead.
	const (
		options     = uint64(1024)
		weightBytes = uint64(8192)
		suppliedGas = uint64(12_500_000)
	)
	args := craftAliasedVoteWeightedArgs(options, weightBytes)
	input := append(append([]byte{}, method.ID...), args...)

	decodeGas, ok := pcommon.DecodeGasCost(method.Inputs, input)
	require.True(t, ok)
	require.Greater(t, decodeGas, suppliedGas)

	statedb := state.NewDBImpl(ctx, k, true)
	evm := vm.EVM{StateDB: statedb}
	ret, remaining, runErr := p.RunAndCalculateGas(&evm, evmAddr, evmAddr, input, suppliedGas, big.NewInt(0), nil, false, false)
	require.Nil(t, ret)
	require.Equal(t, uint64(0), remaining)
	require.ErrorIs(t, runErr, vm.ErrExecutionReverted)

	precompileErr := statedb.GetPrecompileError()
	require.NotNil(t, precompileErr)
	require.NotContains(t, precompileErr.Error(), "too many vote options",
		"decode must fail before the post-Unpack max-options check; got %v", precompileErr)
	// chargeDecodeGas recovers sdk.ErrorOutOfGas as fmt.Errorf("%v", r), which
	// stringifies to "{<descriptor>}"; the descriptor names the decode charge.
	require.Contains(t, precompileErr.Error(), "gov precompile calldata decode")

	_, found := testApp.GovKeeper.GetVote(statedb.Ctx(), 1, seiAddr)
	require.False(t, found)
}

func craftAliasedVoteWeightedArgs(k, s uint64) []byte {
	tupleRel := 32 * k
	arrayPayload := make([]byte, 0, int(32*k+64+s))
	for range k {
		arrayPayload = append(arrayPayload, abiWord(tupleRel)...)
	}
	arrayPayload = append(arrayPayload, abiWord(s)...)
	arrayPayload = append(arrayPayload, abiWord(0)...)
	arrayPayload = append(arrayPayload, make([]byte, s)...)

	data := append(abiWord(1), abiWord(64)...)
	data = append(data, abiWord(k)...)
	data = append(data, arrayPayload...)
	return data
}
