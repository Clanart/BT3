### Title
PlotNFT `join_pool` does not force claiming of pending self-custody pool rewards, permanently ceding them to the pool via `forward_pool_reward` - (File: chia/wallet/plotnft_wallet/plotnft_wallet.py, chia/pools/plotnft_drivers.py)

### Summary
`PlotNFT2Wallet.claim_rewards()` is the only spend path that pays farming/pool-reward coins to the plot-owner's own `rewards_claim_puzhash`, and it explicitly rejects operation while the singleton is pooling: `"Cannot claim rewards while pooling. If you're a pool, try forward_pool_rewards"` [1](#0-0) . Once the singleton is pooling, the *only* legal spend of an outstanding p2-singleton reward coin is `forward_pool_reward()`, which unconditionally sends the reward to the pool's puzzle hash rather than to the owner [2](#0-1) . `PlotNFT2Wallet.join_pool()` transitions the singleton into the pooling state without first claiming any outstanding, self-custody-earned rewards for the owner [3](#0-2) .

### Finding Description
Reward coins paid to a PlotNFT's p2-singleton puzzle hash are tracked irrespective of when they were farmed, via `PlotNFTStore.get_pool_rewards()`, which returns all unspent `pool_reward2s` rows for the singleton id with no distinction between "earned while self-custodying" and "earned while pooling" [4](#0-3) .

The spend authority for these reward coins is entirely determined by the *current* state of the singleton at spend time, not by the state in effect when the reward was earned:
- `claim_pool_rewards()` (CLVM-level, in `plotnft_drivers.py`) raises if `self.pooling` is true, i.e. rewards cannot be routed to the owner's `rewards_claim_puzhash` once pooling [1](#0-0) .
- `forward_pool_reward()` raises if not pooling, and when pooling it always creates the pool-routing spend, sending the reward to the pool's puzzle hash [2](#0-1) .

`PlotNFT2Wallet.join_pool()` performs the state transition to pooling by calling `plotnft.join_pool(...)` and pushing the resulting spend bundle, with no call to `claim_rewards()` or check for outstanding unclaimed rewards beforehand [5](#0-4) . The wallet RPC entry point `pw_absorb_rewards` and CLI `claim_cmd` require the owner to proactively call claim before joining; nothing enforces that ordering [6](#0-5) [7](#0-6) .

The repository's own test suite documents this exact outcome. In `test_plotnft_lifecycle`, after farming self-custody rewards and joining a pool, an attempt to `claim_rewards()` fails with `"Cannot claim rewards while pooling..."`, and the test explicitly labels the subsequent step "LOSE REWARDS (while leaving)", showing the previously-earned reward coin can only be swept via `forward_pool_reward()` into the pool's puzzle hash, decreasing the plotnft wallet's balance with no compensating XCH-wallet increase for the owner [8](#0-7) .

This is the same bug class as the referenced Olympus finding: an optional/omittable claim step before a state-changing action (there: `withdraw`; here: `join_pool`) causes rewards the user is entitled to be irreversibly redirected to another party (there: other LP depositors; here: the pool operator).

### Impact Explanation
Any plot-NFT owner who has outstanding, unclaimed self-custody pool rewards and then calls `join_pool` (a normal, expected user action, e.g. to switch pools or start pooling) permanently loses those rewards to the pool's designated payout puzzle hash. There is no code path that returns them to the owner once the singleton enters the pooling state; `claim_rewards()` is hard-disabled for a pooling singleton, and `forward_pool_reward()` unconditionally pays the pool. This is a concrete, spend-triggered redirection of the owner's own farmed XCH to a third party (the pool operator) — a permanent, uncompensated loss of funds for the owner, reachable by a normal wallet action with no attacker interaction required.

### Likelihood Explanation
High likelihood in practice: any owner who accumulates rewards while self-custodying (which is the default/initial state for a new PlotNFT) and then joins a pool without first calling `claim_rewards` will trigger this. Because `join_pool` gives no warning and does not require the caller to have zero pending rewards, this is an easy operational mistake with no attacker required — a plain user-driven loss-of-funds bug.

### Recommendation
`PlotNFT2Wallet.join_pool()` (and the corresponding CLI/RPC entry point) should check for and force-claim any outstanding unclaimed rewards for the plotnft (via `claim_rewards()`) before submitting the join-pool spend, or refuse to join if unclaimed rewards exist and instruct the caller to claim first. Alternatively, `plotnft_wallet.py`'s `join_pool` could batch a `claim_rewards` spend into the same joining transaction so it is atomic with the state transition, preventing any window where rewards become forwardable-only to the pool.

### Proof of Concept
1. Create a PlotNFT and leave it self-custodying; farm several blocks to its `p2_singleton_puzzle_hash` so unclaimed pool-reward coins accumulate (`REWARDS_GAINED`, as constructed in `chia/_tests/wallet/plotnft_wallet/test_plotnft_wallet.py`).
2. Without calling `plotnft_wallet.claim_rewards()`, call `plotnft_wallet.join_pool(pool_config=..., pool_url=..., action_scope=...)` as shown at [5](#0-4) .
3. Attempt `plotnft_wallet.claim_rewards()` again — it now raises `ValueError("Cannot claim rewards while pooling. If you're a pool, try forward_pool_rewards")`, as confirmed at [1](#0-0)  and exercised by the existing test at [9](#0-8) .
4. The only remaining spend path for the still-unclaimed reward coin is `plotnft.forward_pool_reward(pool_reward)`, which the test performs and labels "LOSE REWARDS (while leaving)" — the plotnft wallet's balance decreases by `POOL_REWARD_AMOUNT` with no corresponding payment to the owner's XCH wallet [10](#0-9) .

Note: I was unable to fully trace whether there is any pre-existing safety check elsewhere in the CLI (`chia/cmds/plotnft_funcs.py`) that warns or blocks joining while rewards are outstanding — the `claim_cmd`/`join`-related CLI code available in the index did not show such a check, but a full audit of all CLI join-pool command paths would need a live checkout to be certain no UI-level warning exists.

    async def join_pool(
        self,
        *,
        pool_config: PoolConfig,
        action_scope: WalletActionScope,
        fee: uint64 = uint64(0),
        finish_leaving_fee: uint64 = uint64(0),
        pool_url: str,
        extra_conditions: tuple[Condition, ...] = tuple(),
        plotnft_override: PlotNFT | None = None,
    ) -> None:
        if plotnft_override is None:
            plotnft = await self.get_current_plotnft()
        else:
            plotnft = plotnft_override
        if plotnft.pool_config is not None:
            await self.leave_pool(
                action_scope=action_scope,
                fee=fee,
                finish_leaving_fee=finish_leaving_fee,
                extra_conditions=extra_conditions,
                new_pool_url=pool_url,
                new_pool_config=pool_config,
            )
            return
        elif finish_leaving_fee != uint64(0):
            raise ValueError("A fee to finish leaving was specified but PlotNFT does not need to leave")
        fee_hook = CreateCoinAnnouncement(msg=b"", coin_id=plotnft.coin.name())
        url_remark = Remark(rest=Program.to(pool_url))
        coin_spends = plotnft.join_pool(
            user_config=plotnft.user_config,
            pool_config=pool_config,
            extra_conditions=(*extra_conditions, fee_hook, url_remark),
        )
        if fee > 0:
            await self.xch_wallet.create_tandem_xch_tx(
                fee=fee,
                action_scope=action_scope,
                extra_conditions=(fee_hook.corresponding_assertion(),),
            )

        spend_bundle = WalletSpendBundle(coin_spends, G2Element())

    async def get_pool_rewards(
        self,
        *,
        plotnft_id: bytes32,
        max: int = DEFAULT_POOL_REWARDS_PER_CLAIM,
        include_spent: bool = False,
    ) -> list[PoolReward]:
        async with self.db_wrapper.reader() as conn:
            rows = await conn.execute_fetchall(
                (
                    "SELECT * from pool_reward2s WHERE singleton_id = ?"
                    + (" AND spent_height IS NULL" if not include_spent else "")
                    + " ORDER BY spent_height ASC LIMIT ?"
                ),
                (plotnft_id, max),
            )
            pool_rewards_selected = [
                PoolReward(
                    coin=Coin(
                        parent_coin_info=bytes32(row[1]), puzzle_hash=bytes32(row[2]), amount=uint64.from_bytes(row[3])
                    ),
                    singleton_id=bytes32(row[4]),
                )
                for row in rows
            ]
            return pool_rewards_selected

    async def pw_absorb_rewards(
        self,
        request: PWAbsorbRewards,
        action_scope: WalletActionScope,
        extra_conditions: tuple[Condition, ...] = tuple(),
    ) -> PWAbsorbRewardsResponse:
        """Perform a sweep of the p2_singleton rewards controlled by the pool wallet singleton"""
        wallet = self.service.wallet_state_manager.wallets[request.wallet_id]

        if isinstance(wallet, PoolWallet):
            async with self.service.wallet_state_manager.lock:
                await wallet.claim_pool_rewards(request.fee, request.max_spends_in_tx, action_scope)
                state: PoolWalletInfo = await wallet.get_current_state()
        elif isinstance(wallet, PlotNFT2Wallet):
            await wallet.claim_rewards(action_scope=action_scope, fee=request.fee, extra_conditions=extra_conditions)
            state = await wallet.get_current_state()
        else:
            raise ValueError("`pw_absorb_rewards` called on a non-pooling wallet")
