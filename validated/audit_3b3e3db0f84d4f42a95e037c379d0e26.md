### Title
Unbounded recursive parsing of custody-puzzle memos causes wallet-crashing stack overflow - (File: `chia/wallet/puzzles/custody/custody_architecture.py`)

### Summary
CVE-2020-26800 describes a stack-overflow DoS in Aleth caused by recursively parsing an attacker-supplied `config.json` without a depth bound. The chia-blockchain "custody architecture" (CHIP-0043 M-of-N / restriction) module has an analogous recursive-parsing surface: `PuzzleWithRestrictions.memo()`/`from_memo()` and `MofN`/`MofNHint` build and reconstruct arbitrarily nested member trees, and the underlying `MerkleTree` helper walks these structures with plain Python recursion instead of an iterative algorithm.

### Finding Description
`MofN` wraps a list of `PuzzleWithRestrictions` members, each of which can itself contain another `MofN` (nested multisig-of-multisig), as documented in the project's own architectural notes: *"`from_memo()` must reconstruct unknown members/restrictions, including recursive `MofN`."* [1](#0-0) 

The concrete recursive helpers that walk these structures are Python-recursive, not iterative:
- `MofNMerkleTree._m_of_n_proof()` recurses on `puzzle_hashes`/`spends_to_prove` splits. [2](#0-1) 
- `MofN.__post_init__`, `memo()`, `puzzle()`, and `puzzle_hash()` recurse into nested `PuzzleWithRestrictions`/`MofN` members every time a memo is parsed or a puzzle/hash is derived. [3](#0-2) 
- `MofNHint.from_program()`/`to_program()` reconstruct `member_memos` from an arbitrary on-chain `Program`, and each entry can itself be another serialized `MofNHint`, giving the attacker full control over nesting depth. [4](#0-3) 
- Lower-level `MerkleTree._root()`/`_proof()` are also plainly recursive Python functions rather than iterative, unlike `sha256_treehash()` which the codebase deliberately made iterative "to avoid Python recursion limits on deeply nested CLVM." [5](#0-4) [6](#0-5) 

Because `memo()` is explicitly described as the "on-chain/exported synchronization contract" — i.e., data placed in a coin's memo/hint and later re-parsed by another wallet syncing that coin — an attacker who sends a coin (or constructs an offer/spend) with a maliciously deep nested `MofN`/`PuzzleWithRestrictions` memo can force a victim wallet's parsing code to recurse to attacker-chosen depth. Python's default recursion limit means sufficiently deep nesting raises `RecursionError`, and depending on interpreter state this can also manifest as a native C stack overflow (segfault) rather than a catchable Python exception, crashing the wallet process. The project has already had to work around exactly this class of bug in a related subsystem: `chia_rs.datalayer.RecursionDepthExceededError` is explicitly raised and tested for deeply nested Data Layer merkle graphs, confirming that unbounded recursion over attacker-influenced tree structures is a recognized failure mode in this codebase. [7](#0-6) 

### Impact Explanation
This is a wallet-user/offer-counterparty-reachable denial of service: a crafted memo/hint (analogous to the crafted `config.json`) causes the parsing wallet process to crash via stack exhaustion when syncing a coin or evaluating an offer/custody arrangement, rather than gracefully rejecting malformed input. No coin movement, inflation, or signature bypass results — the impact is limited to process crash/DoS of the victim's wallet, matching the CVSS profile of the source CVE (`AV:L/AC:L/PR:N/UI:R/.../A:H`, no confidentiality/integrity impact).

### Likelihood Explanation
Reasonably likely: the recursive helpers have no explicit depth check anywhere in the reviewed code, and nesting `MofN` inside `MofN` is an intended, documented feature of the custody architecture, so constructing a deeply nested memo requires no protocol violation — only crafting a sufficiently deep `Program` tree and getting the victim to parse it (e.g., via a coin sent to them, or an offer they inspect).

### Recommendation
- Convert `MofNMerkleTree._m_of_n_proof`, `MerkleTree._root`/`_proof`, and the `MofN`/`PuzzleWithRestrictions` memo (de)serialization walk to iterative, explicit-stack implementations (as already done for `sha256_treehash()`).
- Enforce an explicit maximum nesting/member-count bound when parsing `MofNHint`/`RestrictionHint`/`MemberHint` from untrusted `Program` data, rejecting memos that exceed the bound before recursing.
- Add fuzz/unit tests analogous to the existing `test_insert_into_data_store_from_file_line_graph_depth` depth test, targeted at `PuzzleWithRestrictions.from_memo()` and `MofN` reconstruction.

### Proof of Concept
Conceptual (no live environment available): construct a `Program` memo where an `MofNHint`'s `member_memos` contains another serialized `MofNHint`, nested to a depth of several thousand levels, and place it as the memo/hint on a coin sent to a custody-architecture wallet (or embed it in an offer). When the victim wallet syncs the coin and calls `PuzzleWithRestrictions.from_memo()` / builds the corresponding `MofN` tree, the recursive parsing functions cited above recurse once per nesting level, exhausting the Python/C call stack and crashing the wallet process.

**Note on completeness:** the exact `PuzzleWithRestrictions.from_memo()` implementation (deserialization counterpart of `memo()`) was not fully retrievable in this session — only its contract and the `memo()`/`MofN`/`MofNHint` construction side were directly inspected. Confirming the precise absence of a depth guard in `from_memo()` itself would require reading that function's body directly (likely also in `custody_architecture.py`, just past the excerpted range).

@dataclass(kw_only=True, frozen=True)
class MofN:  # Technically matches Puzzle protocol but is a bespoke part of the architecture
    m: int
    members: list[PuzzleWithRestrictions]

    def __post_init__(self) -> None:
        if self.m > self.n:
            raise ValueError("M cannot be greater than N")
        if self.m < 1:
            raise ValueError("M must be greater than 0")
        if len(list(set(self._merkle_tree.nodes))) != len(self._merkle_tree.nodes):
            raise ValueError("Duplicate nodes not currently supported by MofN drivers")

    @property
    def n(self) -> int:
        return len(self.members)

    @property
    def _merkle_tree(self) -> MerkleTree:
        nodes = [member.puzzle_hash(_top_level=False) for member in self.members]
        if self.m > 1:
            return MofNMerkleTree(nodes)
        else:
            return MerkleTree(nodes)

    def solve(self, spends_to_prove: dict[bytes32, ProvenSpend]) -> Program:
        assert len(spends_to_prove) == self.m, "Must prove as many spends as the M value"
        if self.m == self.n:
            return Program.to([[spends_to_prove[node].solution for node in self._merkle_tree.nodes]])
        elif self.m > 1:
            return Program.to([self._merkle_tree.generate_m_of_n_proof(spends_to_prove)])  # type: ignore[attr-defined]
        else:
            only_key = next(iter(spends_to_prove.keys()))
            proven_spend = spends_to_prove[only_key]
            proof = self._merkle_tree.generate_proof(only_key)
            return Program.to([(proof[0], proof[1][0]), proven_spend.puzzle_reveal, proven_spend.solution])

    def memo(self, nonce: int) -> Program:  # pragma: no cover
        raise NotImplementedError("PuzzleWithRestrictions handles MofN memos, this method should not be called")

    def puzzle(self, nonce: int) -> Program:
        if self.m == self.n:
            return NofN_MOD.curry([member.puzzle_reveal(_top_level=False) for member in self.members])
        elif self.m > 1:
            return MofN_MOD.curry(self.m, self._merkle_tree.calculate_root())
        else:
            return OneOfN_MOD.curry(self._merkle_tree.calculate_root())

    def puzzle_hash(self, nonce: int) -> bytes32:
        if self.m == self.n:
            member_hashes = [member.puzzle_hash(_top_level=False) for member in self.members]
            return NofN_MOD.curry(member_hashes).get_tree_hash_precalc(*member_hashes)
        else:
            return self.puzzle(nonce).get_tree_hash()

@pytest.mark.parametrize("depth", [1000, 100_000])
async def test_insert_into_data_store_from_file_line_graph_depth(
    data_store: DataStore,
    store_id: bytes32,
    tmp_path: Path,
    depth: int,
) -> None:
    # Binary "line graph":
    #   1 -> leaf_1, 2
    #   2 -> leaf_2, 3
    #   ...
    #   depth -> leaf_depth, leaf_end
    #
    # This stresses depth/stack handling while staying strictly binary.
    #
    # Node IDs:
    # - internal nodes: 1..depth
    # - per-level leaf nodes: (depth+1)..(2*depth)
    # - final leaf: (2*depth+1)
    internal_first = 1
    internal_last = depth
    leaf_base = internal_last + 1
    leaf_end = (2 * depth) + 1

    edges: list[tuple[int, int]] = []
    for i in range(internal_first, internal_last):
        # Order matters: first edge is left child, second edge is right child.
        edges.append((i, leaf_base + (i - internal_first)))  # unique leaf for this internal node
        edges.append((i, i + 1))  # next internal node

    # last internal points to its leaf and a final leaf
    edges.append((internal_last, leaf_base + (internal_last - internal_first)))
    edges.append((internal_last, leaf_end))

    filename = tmp_path / f"line_graph_depth_{depth}.dat"
    root_hash = create_graph_util(filename, edges)

    with pytest.raises(chia_rs.datalayer.RecursionDepthExceededError):
        await data_store.insert_into_data_store_from_file(store_id, root_hash, filename)
