### Title
Untrusted `ThresholdKeys::read` deserialization never validates the secret share against the verification shares nor rejects identity shares, enabling signing under attacker-controlled key material - (File: crypto/dkg/src/lib.rs)

### Summary
The deserialization-of-untrusted-data class from GHSA-wjvx-jhpj-r54r maps onto `ThresholdKeys::read` / `ThresholdKeys::new`. The deserializer accepts a fully attacker-controlled `(t, n, i, interpolation, secret_share, verification_shares)` tuple and constructs signing-capable keys without ever checking that `secret_share * G == verification_shares[i]`, without rejecting identity verification shares, and without validating `Constant` interpolation length.

### Finding Description
`ThresholdKeys::read` reads `t`, `n`, `i`, an interpolation tag, a raw `secret_share` scalar, and `n` verification-share points via `Ciphersuite::read_G`, then hands them to `ThresholdKeys::new`. [1](#0-0) 

`ThresholdKeys::new` performs only structural checks: `verification_shares.len() == n`, indexes `<= n`, and `t == n` for `Interpolation::Constant`. [2](#0-1)  It then derives `group_key` solely as the interpolated sum of `verification_shares[1..=t]`, and stores the supplied `secret_share` verbatim with no consistency check against `verification_shares[i]`. [3](#0-2) 

Three concrete gaps result:

1. **No secret-share/verification-share binding.** `read` never verifies `C::generator() * secret_share == verification_shares[i]`. The FROST completion path itself acknowledges this: `AlgorithmSignatureMachine::complete` notes the only known way to reach its internal-error state is "to deserialize a semantically invalid FrostKeys." [4](#0-3) 
2. **Identity verification shares are accepted.** `read` uses `Ciphersuite::read_G`, which checks canonical encoding only and admits the identity point. [5](#0-4)  The identity-rejecting variant exists only on `frost::Curve::read_G` and is not used here. [6](#0-5)  An identity verification share satisfies share-verification statements with a zero share contribution.
3. **`Constant` interpolation length is unchecked.** `interpolation_factor` indexes `c[i-1]` for participant `i`, [7](#0-6)  while `ThresholdKeys::new` only requires `t == n`, never `c.len() == n`. A short or oversized coefficient vector deserializes successfully and panics or silently shifts interpolation factors at signing time.

### Impact Explanation
An unprivileged party able to supply serialized `ThresholdKeys` bytes (the documented sink for `ThresholdKeys::read`) produces a semantically invalid but accepted key object. Because `group_key` is derived purely from the attacker-chosen `verification_shares`, the deserializer can build keys whose group key corresponds to a discrete log known to the attacker, while `secret_share` is an arbitrary scalar. Signing with `view()` then interpolates this arbitrary share and emits signature shares under the attacker's key material; the offset is added to `included[0]`'s share and verification share identically, so a fully attacker-fabricated key produces signatures that verify under the attacker-controlled `group_key`. [8](#0-7)  This yields signatures on messages for a key the legitimate operator never agreed to, and identity/short-`Constant` variants yield incorrect verifier formulas and panic-based denial of service. Severity: High if key material can cross a trust boundary (backups, key transport, coordinator-supplied blobs); Medium otherwise.

### Likelihood Explanation
Exploitation requires the attacker's bytes to reach `ThresholdKeys::read`. The rules scope this read path as a valid untrusted-byte sink, and the absence of any self-consistency check means a single malformed blob suffices — no collusion, no leaked keys, and no broken transport assumption is needed. Where key blobs are only ever self-generated, the practical exposure is lower, hence Medium likelihood.

### Recommendation
In `ThresholdKeys::new` (so `read` inherits it):

- Reject identity verification shares (`is_identity()` check per share, matching `Curve::read_G` semantics).
- Verify `C::generator() * secret_share == verification_shares[params.i()]`.
- For `Interpolation::Constant`, require `coefficients.len() == n`.
- Optionally verify the remaining `verification_shares[t+1..=n]` are consistent with the implied polynomial so different signing sets cannot diverge from `group_key`.

### Proof of Concept
```rust
// crypto/dkg: deserialize a crafted ThresholdKeys where the secret share
// does not correspond to the published verification share for i.
let mut bytes = vec![];
bytes.extend((Ristretto::ID.len() as u32).to_le_bytes());
bytes.extend(Ristretto::ID);
bytes.extend(2u16.to_le_bytes()); // t
bytes.extend(3u16.to_le_bytes()); // n
bytes.extend(1u16.to_le_bytes()); // i
bytes.push(1);                    // Interpolation::Lagrange

// attacker-known secret share, NOT matching verification_shares[1]
let evil_share = Scalar::from(7u64);
bytes.extend(evil_share.to_repr());

// verification shares chosen so group_key = attacker-known key
let known_key = Scalar::from(42u64);
// set shares 1..=t to interpolate to known_key*G; share index 3 arbitrary (unchecked, incl. identity)
bytes.extend(Ristretto::generator().to_bytes());           // vs[1] = G (mismatched with evil_share)
bytes.extend((Ristretto::generator() * known_key).to_bytes()); // vs[2]
bytes.extend(EdwardsPoint::identity().to_bytes());          // vs[3]: identity, accepted by read_G

let keys = ThresholdKeys::<Ristretto>::read(&mut bytes.as_slice()).unwrap();
// keys.group_key() is attacker-controlled; keys.original_secret_share() == evil_share
// any sign() call produces shares under this inconsistent material, and
// verification_shares[3] == identity never contributes to group_key (only 1..=t are summed).
```

Two independent defects are demonstrated: `read` succeeds despite `G * evil_share != verification_shares[1]`, and it succeeds despite `verification_shares[3]` being the identity point, which `ThresholdKeys::new` never inspects because `group_key` is computed only from participants `1..=t`.   fn interpolation_factor(&self, i: Participant, included: &[Participant]) -> F {
    match self {
      Interpolation::Constant(c) => c[usize::from(u16::from(i) - 1)],
      Interpolation::Lagrange => {
        let i_f = F::from(u64::from(u16::from(i)));

        let mut num = F::ONE;
        let mut denom = F::ONE;
        for l in included {
          if i == *l {
            continue;
          }

          let share = F::from(u64::from(u16::from(*l)));
          num *= share;
          denom *= share - i_f;
        }

        // Safe as this will only be 0 if we're part of the above loop
        // (which we have an if case to avoid)
        num * denom.invert().unwrap()
      }
    }

    {
      let different = || io::Error::other("deserializing ThresholdKeys for another curve");

      let mut id_len = [0; 4];
      reader.read_exact(&mut id_len)?;
      if u32::try_from(C::ID.len()).unwrap().to_le_bytes() != id_len {
        Err(different())?;
      }

      let mut id = vec![0; C::ID.len()];
      reader.read_exact(&mut id)?;
      if id != C::ID {
        Err(different())?;
      }
    }

    let (t, n, i) = {
      let mut read_u16 = || -> io::Result<u16> {
        let mut value = [0; 2];
        reader.read_exact(&mut value)?;
        Ok(u16::from_le_bytes(value))
      };
      (
        read_u16()?,
        read_u16()?,
        Participant::new(read_u16()?).ok_or(io::Error::other("invalid participant index"))?,
      )
    };

    let mut interpolation = [0];
    reader.read_exact(&mut interpolation)?;
    let interpolation = match interpolation[0] {
      0 => Interpolation::Constant({
        let mut res = Vec::with_capacity(usize::from(n));
        for _ in 0 .. n {
          res.push(C::read_F(reader)?);
        }
        res
      }),
      1 => Interpolation::Lagrange,
      _ => Err(io::Error::other("invalid interpolation method"))?,
    };

    let secret_share = Zeroizing::new(C::read_F(reader)?);

    let mut verification_shares = HashMap::new();

      verification_shares.insert(l, <C as Ciphersuite>::read_G(reader)?);
    }

    ThresholdKeys::new(
      ThresholdParams::new(t, n, i).map_err(io::Error::other)?,
      interpolation,
      secret_share,
      verification_shares,
    )

  fn read_G<R: Read>(reader: &mut R) -> io::Result<Self::G> {
    let mut encoding = <Self::G as GroupEncoding>::Repr::default();
    reader.read_exact(encoding.as_mut())?;

    let point = Option::<Self::G>::from(Self::G::from_bytes(&encoding))
      .ok_or_else(|| io::Error::other("invalid point"))?;
    if point.to_bytes().as_ref() != encoding.as_ref() {
      Err(io::Error::other("non-canonical point"))?;
    }
    Ok(point)
  }
