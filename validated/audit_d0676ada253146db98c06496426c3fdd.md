## Analog Found

### Title
Auction bid pool accepts and selects winning bids without verifying searcher deposit balance, allowing settlement-incapable bids to win the auction slot - ([File: kaiax/auction/impl/bid_pool.go])

### Summary
The Unitas report describes a reserve/liability mismatch: a value used to prove solvency (`Total Reserve`) includes funds that are not actually liquid/available to satisfy the corresponding obligation, so the check "passes" even though the real payout cannot be made. The same class of bug exists in Kaia's KIP-249 auction module: `BidPool.validateBid` decides whether a submitted bid becomes the block's winning auction slot purely from signature/format/price checks, and never verifies that the bidding searcher actually has sufficient deposited balance (the `AuctionEntryPoint`'s `depositVault`/`getNoncesAndDeposits`) to cover the bid it is competing with.

### Finding Description
`BidPool.validateBid` in `kaiax/auction/impl/bid_pool.go` enforces only:
1. bid not already present,
2. sender doesn't already have a different winning bid for the block,
3. block number window,
4. `bid.Bid > 0`,
5. data/gas-limit size caps,
6. searcher/auctioneer signature validity. [1](#0-0) 

There is no step that reads the searcher's actual deposit/collateral from the on-chain `AuctionEntryPoint` contract (`DepositVault()` / `GetNoncesAndDeposits(searchers)`), even though these exact read functions exist in the generated bindings and are clearly meant to represent the "reserve" backing a bid: [2](#0-1) 

Because `insertBid` uses the raw `bid.Bid` value to decide the single winner per `(blockNumber, targetTxHash)` slot (higher bid replaces the previous winner, FCFS on ties) — [3](#0-2) 

— a searcher can submit an arbitrarily high `bid.Bid` value with a valid `searcherSig`/`auctioneerSig` pair while holding zero or insufficient deposit in the `depositVault`. This bid outcompetes and evicts a legitimately-funded competitor's lower bid for the same target transaction slot, exactly as the "reserve" in the Unitas report is counted toward solvency without verifying it is actually redeemable when needed. Only when the proposer later builds and executes the resulting `AuctionTx` (via `GetBidTxGenerator`/`AuctionEntryPointMock.call`, which is `onlyProposer`) does the entry-point contract have any chance of discovering the deposit shortfall — by which point the legitimate bid that should have won the auction slot has already been displaced. [4](#0-3) [5](#0-4) 

### Impact Explanation
This directly maps to the disallowed-impact carve-out that is explicitly accepted by the rules ("auction bidder", "auction settlement theft"). A bid whose backing "reserve" (deposit) is insufficient is treated by the node's off-chain admission logic as fully equivalent to a properly-backed bid, letting it:
- Win/occupy the single auction slot for a target transaction (`bidTargetMap[blockNumber][targetTxHash]`) that would otherwise have gone to a legitimately-funded searcher, denying that searcher's paid settlement and any proposer fee revenue tied to it.
- Consume the proposer's decision to bundle and execute the corresponding `AuctionTx`, which — depending on the deployed `AuctionEntryPoint` contract's exact bid-taking order (the commented-out logic in `AuctionEntryPointMock.call` shows bid-taking happens only after the call executes) — can allow the underlying searcher call to execute using the proposer-included execution slot without the bid actually being collectible, i.e., an "acceptance of an invalid transaction" into the winner selection that should have been rejected at admission time.

### Likelihood Explanation
Any unprivileged auction bidder/searcher who can obtain (or forge cooperation of) a valid `auctioneerSig` for a bid — which the module's own trust model assumes searchers routinely submit via `auction_submitBid` — can exploit this with a single RPC call, since `validateBid` never queries the deposit contract. No special network position, node compromise, or consensus-level access is required.

### Recommendation
In `kaiax/auction/impl/bid_pool.go`'s `validateBid` (or in `insertBid` right before a bid is allowed to replace an existing winner), query the `AuctionEntryPoint`'s `GetNoncesAndDeposits([bid.Sender])` at the current state and reject/deprioritize the bid if `deposit < bid.Bid` (analogous to how `TxPool.validateTx` checks sender/fee-payer balance before admitting a transaction, see `blockchain/tx_pool.go:934-989`). This keeps the "reserve" used to select an auction winner in sync with the searcher's actual settleable balance, mirroring the recommended fix in the original report of excluding non-liquid/non-verified reserve from the solvency check. [6](#0-5) 

### Proof of Concept
1. Searcher A has zero (or 1 wei) balance in the `AuctionEntryPoint.depositVault` for a given `targetTxHash` in block `N+1`.
2. Searcher A obtains a validly-signed bid (`searcherSig`) for a very high `bid.Bid` and gets the auctioneer to co-sign it (`auctioneerSig`) — the auctioneer's off-chain matching service is not required by the protocol to check on-chain deposit before signing, and even if it did, the CN-side `validateBid`/`insertBid` performs no independent verification.
3. Searcher A calls `auction_submitBid` (`kaiax/auction/impl/api.go:118-142`) with this bid.
4. `BidPool.validateBid` accepts it (signature and range checks pass) and `insertBid` makes it the winner for `(N+1, targetTxHash)`, evicting the previous, properly-funded bid from Searcher B (`kaiax/auction/impl/bid_pool.go:294-309`).
5. The proposer for block `N+1` calls `ExtractTxBundles`/`GetBidTxGenerator` and builds the `AuctionTx` bundle for Searcher A's bid instead of Searcher B's (`kaiax/auction/impl/builder.go:31-70`, `kaiax/auction/impl/getter.go:27-70`).
6. Searcher B, despite having sufficient deposit and a lower-but-fundable bid, never gets its `AuctionTx` included for that target — the auction slot and any associated settlement/fee accrual is diverted to a bid the pool never verified could actually be paid.

func (bp *BidPool) validateBid(bid *auction.Bid) error {
	blockNumber := bid.BlockNumber

	bp.bidMu.RLock()

	// Check if the auction tx is already in the pool.
	if _, ok := bp.bidMap[bid.Hash()]; ok {
		bp.bidMu.RUnlock()
		return auction.ErrBidAlreadyExists
	}

	// 1. The `bid.Sender` must not be in the winner list of the same block number if the new bid isn't equal to the previous bid.
	if bp.senderHasDifferentWinner(bid) {
		bp.bidMu.RUnlock()
		return auction.ErrBidSenderExists
	}
	bp.bidMu.RUnlock()

	curBlock := bp.Chain.CurrentBlock()
	if curBlock == nil {
		return auction.ErrBlockNotFound
	}

	// 2. The `bid.BlockNumber` must be in range of `[currentBlockNumber + 1, currentBlockNumber + allowFutureBlock]`.
	curNum := curBlock.NumberU64()
	if blockNumber <= curNum || blockNumber > curNum+allowFutureBlock {
		return auction.ErrInvalidBlockNumber
	}

	// 3. The `bid.Bid` must be greater than 0.
	if bid.Bid.Sign() <= 0 {
		return auction.ErrZeroBid
	}

	// 4. The data size must be less than the maximum limit.
	if uint64(len(bid.Data)) > BidTxMaxDataSize {
		return auction.ErrExceedMaxDataSize
	}

	// 5. The gas limit must be less than the maximum limit.
	if bid.CallGasLimit > BidTxMaxCallGasLimit {
		return auction.ErrExceedMaxCallGasLimit
	}

	// 6. The `bid.SearcherSig` and `bid.AuctioneerSig` must be valid.
	if err := bp.validateBidSigs(bid); err != nil {
		return err
	}

	return nil
}

// Solidity: function getNoncesAndDeposits(address[] searchers) view returns(uint256[] nonces_, uint256[] deposits_)
func (_IAuctionEntryPoint *IAuctionEntryPointCaller) GetNoncesAndDeposits(opts *bind.CallOpts, searchers []common.Address) (struct {
	Nonces   []*big.Int
	Deposits []*big.Int
}, error) {
	var out []interface{}
	err := _IAuctionEntryPoint.contract.Call(opts, &out, "getNoncesAndDeposits", searchers)

	outstruct := new(struct {
		Nonces   []*big.Int
		Deposits []*big.Int
	})
	if err != nil {
		return *outstruct, err
	}

	outstruct.Nonces = *abi.ConvertType(out[0], new([]*big.Int)).(*[]*big.Int)
	outstruct.Deposits = *abi.ConvertType(out[1], new([]*big.Int)).(*[]*big.Int)

	return *outstruct, err

}

func (a *AuctionModule) GetBidTxGenerator(tx *types.Transaction, bid *auction.Bid) *builder.TxOrGen {
	gen := func(nonce uint64) (*types.Transaction, error) {
		var (
			chainId           = a.InitOpts.ChainConfig.ChainID
			signer            = types.LatestSignerForChainID(chainId)
			auctionEntryPoint = a.bidPool.GetAuctionEntryPoint()
			key               = a.InitOpts.NodeKey
		)

		data, err := system.EncodeAuctionCallData(bid, a.bidPool.GetAuctionEntryPointVersion())
		if err != nil {
			return nil, err
		}

		if bid.GetGasLimit() == 0 {
			gasLimit, err := a.bidPool.getBidTxGasLimit(bid)
			if err != nil {
				return nil, err
			}
			bid.SetGasLimit(gasLimit)
		}

		tx, err := types.NewTransactionWithMap(types.TxTypeEthereumDynamicFee, map[types.TxValueKeyType]interface{}{
			types.TxValueKeyNonce:      nonce,
			types.TxValueKeyTo:         &auctionEntryPoint,
			types.TxValueKeyAmount:     common.Big0,
			types.TxValueKeyData:       data,
			types.TxValueKeyGasLimit:   bid.GetGasLimit(),
			types.TxValueKeyGasFeeCap:  tx.GasFeeCap(),
			types.TxValueKeyGasTipCap:  tx.GasTipCap(),
			types.TxValueKeyAccessList: types.AccessList{},
			types.TxValueKeyChainID:    chainId,
		})
		if err != nil {
			return nil, err
		}

		err = tx.Sign(signer, key)

		return tx, err
	}

	return builder.NewTxOrGenFromGen(gen, bid.Hash())
}
