### Title
Clone flow disables Git's built-in clone-time protection against malicious repository content (`GIT_CLONE_PROTECTION_ACTIVE=false`) - (File: `app/src/lib/git/clone.ts`)

### Summary
GitHub Desktop's `clone()` function explicitly disables a security guard that upstream Git ships specifically to stop attacker-controlled repository content from corrupting the local filesystem/state during clone, mirroring the Uniswap pattern of a guarded initialization path whose protection is bypassed, letting attacker-supplied data (a malicious remote repository) win the "first write" and corrupt what the victim ends up trusting.

### Finding Description
`clone()` sets `GIT_CLONE_PROTECTION_ACTIVE: 'false'` in the environment used to invoke `git clone --recursive` on user-supplied URLs: [1](#0-0) . This environment variable is Git's own opt-out for clone-time protections that were added to prevent attacker-controlled repositories (in particular nested/case-confusable submodules or symlinked paths that git receives from a remote) from writing into locations like `.git/hooks` or overwriting sensitive tree entries during a recursive clone/checkout, which can subsequently execute arbitrary code or corrupt the working tree. Desktop's clone path takes the raw `url` from user input or a deep link/clone dialog and passes it straight to `git clone --recursive` with this protection turned off: [2](#0-1) .

Unlike the Uniswap `initialize()` bug — where the missing guard is access control on who may set the price — the Desktop analog is a guard that exists specifically to validate/reject dangerous content coming from an untrusted party (the remote repository author), and it has been deliberately turned off for every clone Desktop performs, including `--recursive` submodule clones where nested repositories are entirely attacker-controlled: [3](#0-2) .

The only other safeguards present in this path are unrelated to this class of attack: `isClonePathSensitive` only blocks a handful of well-known sensitive destination directories chosen by the local user (`~/.ssh`, `~/.gnupg`, etc.), not attacker-supplied content inside the cloned tree itself: [4](#0-3) . Nothing in `clone()` or `updateSubmodulesAfterOperation()` re-enables or substitutes for the disabled clone protection.

### Impact Explanation
If `GIT_CLONE_PROTECTION_ACTIVE=false` disables the same class of protection it was introduced for upstream (guarding against malicious nested submodule/tree entries during `--recursive` clones), an attacker who controls a repository (or a submodule referenced by it) that a Desktop user clones or opens via "Clone" / deep link could have their repository content write outside the intended working directory or into Git's control directories during the clone/submodule-init step, which can lead to code execution or corruption of the resulting local repository — directly matching the allowed impact class ("attacker controls a cloned/fetched repository ... code execution, file write ... outside the repo").

### Likelihood Explanation
Cloning attacker-supplied or attacker-linked repositories (including third-party forks, malicious "helpful" repos shared via URL, or `Open in Desktop` deep links) is a core, unprivileged, everyday Desktop workflow — no elevated privileges, local access, or social engineering beyond "clone this repo" is required, and `--recursive` submodule expansion happens automatically without extra user confirmation: [5](#0-4) .

### Recommendation
- Remove the `GIT_CLONE_PROTECTION_ACTIVE: 'false'` override in `app/src/lib/git/clone.ts` so Desktop benefits from upstream Git's clone-time protections by default.
- If disabling it was intentional to work around a compatibility issue, gate it behind a narrowly scoped, documented condition and add the equivalent protections back at the Desktop layer (e.g., validating submodule paths/case-collisions before `--recursive` init, as also invoked from `updateSubmodulesAfterOperation`).
- Add regression tests analogous to `app/test/unit/git/clone-test.ts` that assert the protection environment variable is not disabled for untrusted clone sources.

### Proof of Concept
1. An attacker publishes a Git repository containing a submodule (or nested tree entries) crafted to exploit the case-insensitive/symlink clone-time issue that `GIT_CLONE_PROTECTION_ACTIVE` guards against (the class of issue fixed in Git's clone-protection hardening).
2. Victim clones the repository through Desktop's `clone-repository` dialog or an `x-github-client://openRepo` deep link, which calls `Dispatcher.clone` → `_clone` → `CloningRepositoriesStore.clone` → `clone()`.
3. `clone()` invokes `git -c init.defaultBranch=... clone --recursive -- <url> <path>` with `GIT_CLONE_PROTECTION_ACTIVE=false` in the environment: [1](#0-0) .
4. Because the protection is disabled, Git does not apply its safeguard against the attacker's crafted submodule/tree layout during the recursive clone, allowing the malicious content to write to a location it should have been blocked from reaching (e.g. inside `.git`), potentially resulting in code execution on next Git invocation or corruption of the cloned repository state.

function isClonePathSensitive(unresolvedClonePath: string): boolean {
  const clonePath = Path.resolve(unresolvedClonePath).toLowerCase()
  const home = Path.resolve(homedir()).toLowerCase()

  if (clonePath === home) {
    return true
  }

  const sensitiveLocations = [
    Path.join(home, '.ssh'),
    Path.join(home, '.gnupg'),
    Path.join(home, '.config'),
    Path.join(home, '.config', 'git'),
    Path.join(home, '.gitconfig'),
  ]

  if (__WIN32__) {
    const appData = process.env.APPDATA
    if (appData) {
      sensitiveLocations.push(appData.toLowerCase())
      sensitiveLocations.push(Path.join(appData, 'gnupg').toLowerCase())
    }
  }

  for (const sensitive of sensitiveLocations) {
    if (clonePath === sensitive || clonePath.startsWith(sensitive + Path.sep)) {
      return true
    }
  }

  return false
}

export async function clone(

  path: string,
  options: CloneOptions,
  progressCallback?: (progress: ICloneProgress) => void

  if (isClonePathSensitive(path)) {
    throw new Error(
      `The clone destination "${path}" targets a sensitive system location. ` +
        'Cloning into this directory is not allowed.'
    )
  }

  const env = {
    ...(await envForRemoteOperation(url)),
    GIT_CLONE_PROTECTION_ACTIVE: 'false',
  }

  const defaultBranch = options.defaultBranch ?? (await getDefaultBranch())

  const args = [
    '-c',
    `init.defaultBranch=${defaultBranch}`,
    'clone',
    '--recursive',
  ]
