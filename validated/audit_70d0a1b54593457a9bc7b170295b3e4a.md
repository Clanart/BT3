### Title
Duplicate `withdrawal_utxo_txid`/`vout` across withdrawal indices lets a single payout tx be joined to two withdrawal rows, letting an operator seize a second deposit's move-to-vault funds as reimbursement without ever paying that withdrawal - (`core/src/database/verifier.rs`)

### Summary
`Database::get_payout_txs_for_withdrawal_utxos` joins `withdrawals` to `bitcoin_syncer_spent_utxos` purely on `(withdrawal_utxo_txid, withdrawal_utxo_vout)` equality, with no uniqueness constraint enforced on those columns in the `withdrawals` table schema. If two withdrawal indices (idx1, idx2) are registered on Citrea with the identical dust `input_outpoint`, one real Bitcoin payout transaction that spends that outpoint gets matched to *both* rows, causing `update_payout_txs_and_payer_operator_xonly_pk` to mark both idx1 and idx2 as "paid" by the same operator even though only idx1's deposit funds were actually paid out. `PayoutCheckerTask` and `Operator::handle_finalized_payout` then run the reimbursement kickoff for idx2 using idx2's *own, still-untouched* deposit outpoint, letting the operator claim reimbursement (and later spend idx2's `MoveToVault` output via `create_reimburse_txhandler`) for a withdrawal it never funded.

### Finding Description
The broken binding: `operator_credited_and_reimbursed_for_withdrawal_i == party_whose_funds_paid_that_payout_counted_exactly_once`. Trace:

1. `withdrawals` table has no unique constraint on `(withdrawal_utxo_txid, withdrawal_utxo_vout)`, only `idx` is primary key: [1](#0-0) .
2. `collect_withdrawal_utxos` on the Citrea client simply enumerates `withdrawalUTXOs(idx)` sequentially with no deduplication of the underlying outpoint across indices, and `update_citrea_deposit_and_withdrawals` writes each idx's utxo verbatim into the `withdrawals` table via `update_withdrawal_utxo_from_citrea_withdrawal`: [2](#0-1) [3](#0-2) .
3. `get_payout_txs_for_withdrawal_utxos` joins on raw `(txid, vout)` equality: if two `withdrawals` rows share the same `withdrawal_utxo_txid`/`vout`, a single row in `bitcoin_syncer_spent_utxos` (i.e. one real spend of that dust outpoint) produces two result rows - one per withdrawal idx: [4](#0-3) .
4. `update_finalized_payouts` takes that result set and, for every `(idx, payout_txid)` pair, extracts the operator xonly pk from the single payout tx's OP_RETURN and calls `update_payout_txs_and_payer_operator_xonly_pk`, writing the same `payout_txid`/`payout_payer_operator_xonly_pk`/`payout_tx_blockhash` into *both* idx rows: [5](#0-4) .
5. `PayoutCheckerTask::run_once` (and every verifier's `is_kickoff_malicious`) reads this per-idx `payout_*` state at face value and cannot distinguish "real payout for idx2" from "same tx aliased onto idx2 by the JOIN bug": [6](#0-5) [7](#0-6) .
6. `handle_finalized_payout` is invoked with `deposit_data.get_deposit_outpoint()` derived from idx2's *own* `move_to_vault_txid` (a distinct deposit from idx1's), and proceeds to allocate a kickoff/round slot and eventually build `create_reimburse_txhandler`, which spends idx2's `MoveToVault` `DepositInMove` output to the operator as "reimbursement": [8](#0-7) [9](#0-8) .

Existing guards fail because every check (`is_kickoff_malicious`, `get_payout_info_from_move_txid`, `get_first_unhandled_payout_by_operator_xonly_pk`) reads from the same DB table that was populated by the faulty join - there is no cross-check that the outpoint spent in the observed payout tx is uniquely owned by exactly one `idx`, and no check that idx2's *specific* `MoveToVault` output was ever an input to any confirmed payout transaction.

### Impact Explanation
An operator ends up credited and eventually reimbursed for withdrawal idx2 while never having paid the corresponding user; idx2's `MoveToVault` deposit UTXO is consumed by the `Reimburse` transaction as payment to the operator instead of to the withdrawing user - this is BTC leaving a move-to-vault UTXO without a matching fronted withdrawal, and an operator reimbursed for a payout it never funded (both listed Critical impacts). The withdrawing user tied to idx2 never receives funds (their withdrawal is marked handled in the DB), and no honest operator will ever attempt a real payout for idx2 since the system already believes it is paid - so the withdrawal request becomes permanently unfulfillable while the backing deposit is drained to the operator. This is repeatable for every additional duplicate `(idx, outpoint)` pair the attacker registers, scaling with the number of withdraw() calls the attacker makes with a reused outpoint, and does not require operator collusion - it triggers via the fully automated `PayoutCheckerTask` and kickoff/reimburse flow.

### Likelihood Explanation
Preconditions: (1) the Citrea Bridge contract must accept `withdraw()` calls that reuse an `input_outpoint` already used by a prior withdrawal index (asserted attacker capability in this exercise, and confirmed there is no repo-side rejection since `collect_withdrawal_utxos`/`update_withdrawal_utxo_from_citrea_withdrawal` never check for existing rows with the same outpoint); (2) at least one operator must front (or the attacker/any operator must cause) a real payout for the first of the duplicated indices, which is routine, low-cost bridge operation (cost: one dust withdrawal registration + normal deposit/withdraw flow, no elevated privileges). Given those, the double-crediting in `get_payout_txs_for_withdrawal_utxos`/`update_finalized_payouts` triggers automatically and deterministically the next time the block syncer processes the block containing the payout tx - no race condition or timing luck required.

### Recommendation
Enforce a database-level and query-level uniqueness guarantee tying a withdrawal UTXO to exactly one `idx`: add a unique constraint on `(withdrawal_utxo_txid, withdrawal_utxo_vout)` in the `withdrawals` table (rejecting/erroring on duplicate registration from Citrea sync), and change `get_payout_txs_for_withdrawal_utxos`/`update_finalized_payouts` to additionally verify that the specific `MoveToVault` `DepositInMove` output belonging to that `idx`'s deposit is one of the actual inputs of the observed payout transaction before marking it paid, rather than relying solely on the dust `withdrawal_utxo` outpoint match.

async fn duplicate_withdrawal_utxo_across_indices_double_credits_payout() {

    let db = Database::new(&config).await.unwrap();
    let mut dbtx = db.begin_transaction().await.unwrap();

    let shared_outpoint = bitcoin::OutPoint { txid: Txid::from_byte_array([0xAA; 32]), vout: 0 };
    let move_txid1 = Txid::from_byte_array([0x01; 32]);
    let move_txid2 = Txid::from_byte_array([0x02; 32]);
    let idx1 = 10u32;
    let idx2 = 11u32;

    // Register two distinct deposits (idx1, idx2), each with its OWN move_to_vault_txid.
    db.upsert_move_to_vault_txid_from_citrea_deposit(Some(&mut dbtx), idx1, &move_txid1).await.unwrap();
    db.upsert_move_to_vault_txid_from_citrea_deposit(Some(&mut dbtx), idx2, &move_txid2).await.unwrap();

    // Attacker calls withdraw() twice on Citrea contract with the SAME input_outpoint for idx1 and idx2.
    let block_id = db.insert_block_info(Some(&mut dbtx), &BlockHash::all_zeros(), &BlockHash::all_zeros(), 0).await.unwrap();
    db.update_withdrawal_utxo_from_citrea_withdrawal(Some(&mut dbtx), idx1, shared_outpoint, block_id).await.unwrap();
    db.update_withdrawal_utxo_from_citrea_withdrawal(Some(&mut dbtx), idx2, shared_outpoint, block_id).await.unwrap();

    // One real Bitcoin payout tx spends the shared dust outpoint (fronting idx1's withdrawal only).
    let payout_txid = Txid::from_byte_array([0xEE; 32]);
    db.insert_txid_to_block(&mut dbtx, block_id, &payout_txid).await.unwrap();
    db.insert_spent_utxo(&mut dbtx, block_id, &payout_txid, &shared_outpoint.txid, shared_outpoint.vout.into()).await.unwrap();

    // BINDING CHECK (before): only idx1's withdrawal should be attributable to payout_txid.
    let joined = db.get_payout_txs_for_withdrawal_utxos(Some(&mut dbtx), block_id).await.unwrap();
    // BUG: this returns BOTH (idx1, payout_txid) and (idx2, payout_txid) for one real spend.
    assert_eq!(joined.len(), 2, "one real payout tx incorrectly matched to two withdrawal indices");
    assert!(joined.iter().any(|(idx, txid)| *idx == idx1 && *txid == payout_txid));
    assert!(joined.iter().any(|(idx, txid)| *idx == idx2 && *txid == payout_txid));

    // update_finalized_payouts equivalent: write payout info for both idx.
    let op_pk = generate_random_xonly_pk();
    db.update_payout_txs_and_payer_operator_xonly_pk(
        Some(&mut dbtx),
        vec![
            (idx1, payout_txid, Some(op_pk), BlockHash::all_zeros()),
            (idx2, payout_txid, Some(op_pk), BlockHash::all_zeros()),
        ],
    ).await.unwrap();

    // BINDING CHECK (after): idx2 is now falsely marked as paid by `op_pk`, even though
    // idx2's own move_to_vault_txid (move_txid2) was never spent to any user.
    let info2 = db.get_payout_info_from_move_txid(Some(&mut dbtx), move_txid2).await.unwrap().unwrap();
    assert_eq!(info2.0, Some(op_pk)); // operator falsely credited for idx2
    assert_eq!(info2.2, payout_txid); // same tx as idx1's real payout

    // get_first_unhandled_payout_by_operator_xonly_pk will now surface idx2 as reimbursable,
    // driving handle_finalized_payout to spend move_txid2's DepositInMove output as
    // "reimbursement" for a withdrawal that was never funded — violating the binding.

        last_withdrawal_idx: Option<u32>,
        to_height: u64,
    ) -> Result<Vec<(u64, OutPoint)>, BridgeError> {
        let mut utxos = vec![];

            Some(idx) => idx + 1,
            None => 0,

                    break;
                }
                Err(e) => return Err(e.into()),
                Ok(_) => {}
            }
            let withdrawal_utxo = withdrawal_utxo.expect("Failed to get withdrawal UTXO");
            let txid = withdrawal_utxo.txId.0;
            let txid =
                Txid::from_slice(txid.as_ref()).wrap_err("Failed to convert txid to Txid")?;
            let vout = withdrawal_utxo.outputId.0;
            let vout = u32::from_le_bytes(vout);
            let utxo = OutPoint { txid, vout };
            utxos.push((start_idx as u64, utxo));
            start_idx += 1;
        }
        Ok(utxos)
    }

    async fn update_finalized_payouts(
        &self,
        dbtx: DatabaseTransaction<'_>,
        block_id: u32,
        block_cache: &block_cache::BlockCache,
    ) -> Result<(), BridgeError> {
        let payout_txids = self
            .db
            .get_payout_txs_for_withdrawal_utxos(Some(dbtx), block_id)
            .await?;

        let block = &block_cache.block;

        let block_hash = block.block_hash();

        let mut payout_txs_and_payer_operator_idx = vec![];
        for (idx, payout_txid) in payout_txids {
            let payout_tx_idx = block_cache.txids.get(&payout_txid);
            if payout_tx_idx.is_none() {
                tracing::error!(
                    "Payout tx not found in block cache: {:?} and in block: {:?}",
                    payout_txid,
                    block_id
                );
                tracing::error!("Block cache: {:?}", block_cache);
                return Err(eyre::eyre!("Payout tx not found in block cache").into());
            }
            let payout_tx_idx = payout_tx_idx.expect("Payout tx not found in block cache");
            let payout_tx = &block.txdata[*payout_tx_idx];
            // Find the first output that contains OP_RETURN
            let circuit_payout_tx = CircuitTransaction::from(payout_tx.clone());
            let op_return_output = get_first_op_return_output(&circuit_payout_tx);

            // If OP_RETURN doesn't exist in any outputs, or the data in OP_RETURN is not a valid xonly_pubkey,
            // operator_xonly_pk will be set to None, and the corresponding column in DB set to NULL.
            // This can happen if optimistic payout is used, or an operator constructs the payout tx wrong.
            let operator_xonly_pk = op_return_output
                .and_then(|output| parse_op_return_data(&output.script_pubkey))
                .and_then(|bytes| XOnlyPublicKey::from_slice(bytes).ok());

            if operator_xonly_pk.is_none() {
                tracing::info!(
                    "No valid operator xonly pk found in payout tx {:?} OP_RETURN. Either it is an optimistic payout or the operator constructed the payout tx wrong",
                    payout_txid
                );
            }

            tracing::info!(
                "A new payout tx detected for withdrawal {}, payout txid: {:?}, operator xonly pk: {:?}",
                idx,
                payout_txid,
                operator_xonly_pk
            );

            payout_txs_and_payer_operator_idx.push((
                idx,
                payout_txid,
                operator_xonly_pk,
                block_hash,
            ));
        }

        self.db
            .update_payout_txs_and_payer_operator_xonly_pk(
                Some(dbtx),
                payout_txs_and_payer_operator_idx,
            )
            .await?;

        Ok(())
    }

    /// Returns the withdrawal indexes and their spending txid for the given

    pub async fn get_payout_txs_for_withdrawal_utxos(
        &self,
        tx: Option<DatabaseTransaction<'_>>,
        block_id: u32,
    ) -> Result<Vec<(u32, Txid)>, BridgeError> {
        let query = sqlx::query_as::<_, (i32, TxidDB)>(
            "SELECT w.idx, bsu.spending_txid
             FROM withdrawals w
             JOIN bitcoin_syncer_spent_utxos bsu
                ON bsu.txid = w.withdrawal_utxo_txid
                AND bsu.vout = w.withdrawal_utxo_vout
             WHERE bsu.block_id = $1",
        )
        .bind(i32::try_from(block_id).wrap_err("Failed to convert block id to i32")?);

        let results = execute_query_with_tx!(self.connection, tx, query, fetch_all)?;

        results
            .into_iter()
            .map(|(idx, txid)| {
                Ok((
                    u32::try_from(idx).wrap_err("Failed to convert withdrawal index to u32")?,
                    txid.0,
                ))
            })
            .collect()

pub fn create_reimburse_txhandler(
    move_txhandler: &TxHandler,
    round_txhandler: &TxHandler,
    kickoff_txhandler: &TxHandler,
    kickoff_idx: usize,
    paramset: &'static ProtocolParamset,
    operator_reimbursement_address: &bitcoin::Address,
) -> Result<TxHandler, BridgeError> {
    let builder = TxHandlerBuilder::new(TransactionType::Reimburse)
        .with_version(NON_STANDARD_V3)
        .add_input(
            NormalSignatureKind::Reimburse1,
            move_txhandler.get_spendable_output(UtxoVout::DepositInMove)?,
            builder::script::SpendPath::ScriptSpend(0),
            DEFAULT_SEQUENCE,
        )
        .add_input(
            NormalSignatureKind::Reimburse2,
            kickoff_txhandler.get_spendable_output(UtxoVout::ReimburseInKickoff)?,
            builder::script::SpendPath::ScriptSpend(0),
            DEFAULT_SEQUENCE,
        )
        .add_input(
            NormalSignatureKind::OperatorSighashDefault,
            round_txhandler.get_spendable_output(UtxoVout::ReimburseInRound(
                kickoff_idx,
                paramset.num_kickoffs_per_round,
            ))?,
            builder::script::SpendPath::KeySpend,
            DEFAULT_SEQUENCE,
        );

    Ok(builder
        .add_output(UnspentTxOut::from_partial(TxOut {
            value: move_txhandler
                .get_spendable_output(UtxoVout::DepositInMove)?
                .get_prevout()
                .value,
            script_pubkey: operator_reimbursement_address.script_pubkey(),
        }))
        .add_output(UnspentTxOut::from_partial(
            builder::transaction::anchor_output(paramset.anchor_amount()),
        ))
