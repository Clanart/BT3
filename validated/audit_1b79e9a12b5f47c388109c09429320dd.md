### Title
`ReceivedOutput` accepts an attacker-claimed scalar offset without binding it to the output's script_pubkey, letting untrusted bytes report unspendable funds as received - (File: networks/bitcoin/src/wallet/mod.rs)

### Summary

`Scanner` tracks deposits by script_pubkey and records the HDKD scalar `offset` needed to re-key the threshold group key for each matched output. `scan_transaction` always produces consistent `(offset, output)` pairs because it derives `offset` from its internal `scripts` map keyed by `output.script_pubkey`. However, `ReceivedOutput` itself carries an attacker-controlled `offset` alongside the `TxOut`, and `ReceivedOutput::read` performs no consistency check between them. This is the same bug class as CVE-2021-20206: an attacker-supplied identifier (here, the scalar "offset" that selects which key an output belongs to) is trusted to name a resource (the spendable key) without being constrained to the set actually derived from the key — analogous to `../` escaping the plugin directory. Untrusted bytes fed to `ReceivedOutput::read` can therefore cause the wallet pipeline to register "received" funds that no key the validator set holds can ever spend.

### Finding Description

`ReceivedOutput` is a `(offset: Scalar, output: TxOut, outpoint: OutPoint)` triple. The only legitimate construction path is `Scanner::scan_transaction`, which looks up `self.scripts.get(&output.script_pubkey)` — guaranteeing `output.script_pubkey == p2tr(key + offset·G)` [1](#0-0) .

`ReceivedOutput::read` deserializes all three fields independently and returns the struct with no verification that `offset` re-keys `Scanner`'s `key` to the output's script [2](#0-1) . There is no method on `ReceivedOutput` that re-derives the expected script (`p2tr_script_buf(key + GENERATOR·offset)`) and compares it to `output.script_pubkey`.

The offset/key relationship is established in `register_offset`, which inserts `p2tr_script_buf(self.key + GENERATOR * offset) → offset` into the script map [3](#0-2) . A mismatched `offset` therefore yields a signature under the wrong tweaked key: the BIP-340 Schnorr signature produced by the FROST signing round over `ThresholdKeys::offset(offset)` [4](#0-3)  will not verify against the output's actual taproot key, and the spend transaction is invalid.

### Impact Explanation

Any component that accepts serialized `ReceivedOutput`s from an untrusted source (network peers, a coordinator feeding scanner results to signers) can be made to record deposits that are not spendable by the threshold group. Concretely:

- Funds reported as received under a derived address are, in reality, locked to an unrelated taproot key (or the offset points at a script-path-spendable key the group doesn't control).
- Downstream code that sums `ReceivedOutput::value()` to compute available balance or construct spends via `TransactionMachine`/send paths will overstate spendable balance and build transactions that can never be validly signed, causing denial of the withdrawal pipeline and accounting divergence between the bitcoin network and the substrate-side mint record.

This satisfies the "funds reported received that are not spendable" acceptance criterion.

### Likelihood Explanation

Reachable by any unprivileged party able to submit serialized `ReceivedOutput` bytes (an explicitly in-scope input per the engagement rules). The attacker needs no collusion and no valid deposit: they craft `offset = arbitrary`, `output` = any `TxOut` (e.g., an output paying to their own address or an unrelated script), and a synthetic `outpoint`. The cost is a single crafted message; exploitation does not require sending a real Bitcoin transaction.

### Recommendation

Bind the offset to the output inside `ReceivedOutput` construction. Either:

1. Store the scanner's base `key` (or the script map) and add a `ReceivedOutput::verify(key)` / construction-time check that recomputes `p2tr_script_buf(key + GENERATOR * offset)` and rejects the output if it differs from `output.script_pubkey`; or
2. Make `ReceivedOutput::read` take the originating `Scanner` (or its key) and perform that check during deserialization, mirroring how `ThresholdKeys::read` validates `C::ID` before accepting bytes [5](#0-4) .

### Proof of Concept

```rust
// Attacker crafts bytes where `offset` does not correspond to `output.script_pubkey`
let mut buf = Vec::new();
// offset = 1 (arbitrary), instead of the offset registered for the script
buf.extend(Scalar::ONE.to_bytes());
// output pays to the attacker's own P2TR key, not key + G*1
buf.extend(serialize(&TxOut { value: Amount::from_sat(100_000).into(), script_pubkey: attacker_script }));
buf.extend(serialize(&OutPoint::new(attacker_txid, 0)));

let received = ReceivedOutput::read(&mut &buf[..]).unwrap();
// `received` is accepted: value 100_000 reported as spendable by the group,
// but signing with keys.offset(Scalar::ONE) produces a signature that fails
// BIP-340 verification against `attacker_script`'s key — funds unspendable.
```

Uncertainty noted: whether `ReceivedOutput::read` is invoked on peer-controlled bytes in the processor depends on code outside the in-scope crates (`processor/src/networks/bitcoin.rs`), but the in-scope API contract itself lacks the binding check.

  pub fn register_offset(&mut self, mut offset: Scalar) -> Option<Scalar> {
    // This loop will terminate as soon as an even point is found, with any point having a ~50%
    // chance of being even
    // That means this should terminate within a very small amount of iterations
    loop {
      match p2tr_script_buf(self.key + (ProjectivePoint::GENERATOR * offset)) {
        Some(script) => {
          if self.scripts.contains_key(&script) {
            None?;
          }
          self.scripts.insert(script, offset);
          return Some(offset);
        }
        None => offset += Scalar::ONE,
      }
    }
  }

  pub fn scan_transaction(&self, tx: &Transaction) -> Vec<ReceivedOutput> {
    let mut res = Vec::new();
    for (vout, output) in tx.output.iter().enumerate() {
      // If the vout index exceeds 2**32, stop scanning outputs
      let Ok(vout) = u32::try_from(vout) else { break };

      if let Some(offset) = self.scripts.get(&output.script_pubkey) {
        res.push(ReceivedOutput {
          offset: *offset,
          output: output.clone(),
          outpoint: OutPoint::new(tx.compute_txid(), vout),
        });
      }
    }
    res
  }
