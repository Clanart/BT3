### Title
Unprivileged tier self-upgrade via `registerCode()` overwriting admin-set tier - (File: rewards/ReferralStorage.sol)

### Summary
`ReferralStorage.registerCode()` unconditionally sets `userInfos[msg.sender].tier = 1` on every call, with no check that the caller already has a `myCode` or a previously admin-configured tier. Any account whose tier was intentionally set below 1 (e.g. tier 0, "no rebate") by the owner via `setReferrerTier()` can call `registerCode()` again with a fresh unused code to silently reset its own tier back to 1, thereby gaining `tiers[1].rewardPercentage` rebates on future `trigger()` calls.

### Finding Description
`registerCode()` only validates that the new code is unclaimed (`codeOwners[_code] != address(0)`), never that the caller doesn't already own a code or has an owner-assigned tier: [1](#0-0) 

Since there is no restriction preventing an account from calling `registerCode()` multiple times with different unused `_code` values, and each call always writes `tier = 1`, any account can override a tier previously set via the owner-only function: [2](#0-1) 

Exploit flow:
1. Owner calls `setReferrerTier(attacker, 0)` to deliberately disqualify `attacker` from rebates (or set a lower non-1 tier).
2. `attacker` (unprivileged) calls `registerCode(newUnusedCode)`. This succeeds because the only guard is on the code's uniqueness, not on the caller's existing state, and unconditionally sets `userInfos[attacker].tier = 1`.
3. A referee calls `useCode(newUnusedCode)`, linking themselves to `attacker` via `myReferer`.
4. `masterMagpie` calls `trigger(referee, amount)`, which reads `userInfos[attacker].tier` (now 1) and pays out `tiers[1].rewardPercentage` to `attacker.rewardAmount`, in violation of the admin's explicit tier-0 assignment: [3](#0-2) 

No modifier, `nonReentrant` guard, or state check in `registerCode()` prevents re-invocation by an account that already registered a code or that has an owner-managed tier, so the owner's `setReferrerTier` intent is trivially bypassable by the account itself.

### Impact Explanation
This lets an unprivileged referrer unlock a paid reward tier that the protocol owner explicitly revoked or limited, resulting in unauthorized accrual of `rewardAmount` (claimable MGP) that the account was not entitled to — a theft of unclaimed yield paid out of the referral reward pool at the expense of legitimate participants/protocol.

### Likelihood Explanation
Trivial and fully repeatable: requires only an EOA, one unused `bytes32` code, and a cooperating (or attacker-controlled) referee address to call `useCode`. No capital, privileged role, or special timing is needed; the attacker can repeat this after any future `setReferrerTier` demotion by simply registering a new code.

### Recommendation
In `registerCode()`, do not overwrite `tier` if the account already has a `UserInfo` entry (`myCode != bytes32(0)`) or already has a non-default tier; only initialize `tier` for genuinely new accounts (e.g., check `if (userInfos[msg.sender].myCode == bytes32(0)) userInfo.tier = 1;`), or remove automatic tier assignment from `registerCode()` entirely and require the owner to call `setReferrerTier()` for all tier assignments.

### Proof of Concept
Foundry test outline:
1. Deploy `ReferralStorage`, initialize, and call `setTier(1, someRewardPct)`.
2. `attacker.registerCode(codeA)` → asserts `userInfos[attacker].tier == 1`.
3. Owner calls `setReferrerTier(attacker, 0)` → assert `userInfos[attacker].tier == 0`.
4. `attacker.registerCode(codeB)` (new unused code) → assert `userInfos[attacker].tier == 1` again (bug reproduced; expected behavior would be tier remains `0` or the call reverts).
5. `referee.useCode(codeB)`, then `masterMagpie.trigger(referee, amount)` → assert `userInfos[attacker].rewardAmount > 0`, demonstrating the attacker received tier-1 rebates despite the owner's tier-0 assignment.

    function registerCode(bytes32 _code) external {
        if (_code == bytes32(0)) revert InvalidCode();
        if (codeOwners[_code] != address(0)) revert CodeOccupied();

        codeOwners[_code] = msg.sender;
        userInfos[msg.sender].myCode = _code;
        userInfos[msg.sender].tier = 1; // tier 1 as default

        emit RegisterCode(msg.sender, _code);
    }

        UserInfo storage refereeInfo = userInfos[_referee];
        address _referer = myReferer[_referee];

        if (_referer == address(0))
            return;

        UserInfo storage refererInfo = userInfos[_referer];
        uint256 tierId = userInfos[_referer].tier;
        uint256 basic = tiers[tierId].rewardPercentage;
        uint256 boostesd = _calBoosted(_referer);

        uint256 refererPercentage = (basic + boostesd) * (DENOMINATOR - sharePercent)  / DENOMINATOR;
        uint256 refereePercentage = (basic + boostesd) *  sharePercent / DENOMINATOR;
        uint256 refererAmount = _amount * refererPercentage / DENOMINATOR;
        uint256 refereeAmount = _amount * refereePercentage / DENOMINATOR;

        refererInfo.rewardAmount += refererAmount;
        refereeInfo.rewardAmount += refereeAmount;

        emit RefererRewardHarvested(_referer, refererAmount);
        emit RefereeRewardHarvested(_referee, refereeAmount);
    }
