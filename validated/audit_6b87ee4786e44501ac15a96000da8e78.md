### Title
Immature coinbase outputs are reported as spendable `ReceivedOutput`s - (File: networks/bitcoin/src/wallet/mod.rs)

### Summary
`Scanner::scan_block` scans every transaction in `block.txdata`, including `block.txdata[0]`, and converts matching coinbase outputs into `ReceivedOutput`s indistinguishable from mature outputs. [1](#0-0) 

This is analogous to allowing a one-second collateral-ratio fall duration: a required delay exists, but the API fails to enforce or encode it before exposing the result as actionable. [2](#0-1) 

### Finding Description
`Scanner::scan_transaction` creates a `ReceivedOutput` solely by matching `output.script_pubkey` against registered scripts, without checking whether the containing transaction is a coinbase or whether its outpoint has matured. [3](#0-2) 

`Scanner::scan_block` then applies this routine to every transaction, including the mandatory coinbase transaction at index zero. [4](#0-3) 

`ReceivedOutput` stores only the scalar offset, `TxOut`, and `OutPoint`; it does not retain transaction type, block height, confirmations, or coinbase status. [5](#0-4) 

`SignableTransaction::new` accepts these `ReceivedOutput`s and turns each supplied `outpoint` directly into a transaction input, with no maturity validation possible at that layer. [6](#0-5) 

### Impact Explanation
A wallet can treat an immature coinbase output as available balance and construct, sign, and attempt to broadcast a transaction spending it before the 100-block coinbase maturity period has elapsed. [1](#0-0) 

The result is funds reported as received and spendable that are not yet spendable under Bitcoin consensus rules, causing transaction construction or broadcast failure and potentially misleading balance accounting. [7](#0-6) 

Because `ReceivedOutput` carries no maturity metadata, callers cannot reliably recover this information after scanning without separately tracking which transaction index produced each output. [5](#0-4) 

### Likelihood Explanation
A miner or mining pool can produce a coinbase output paying to a scanned Taproot script, and normal processing of that block through `scan_block` will expose it identically to a mature payment. [8](#0-7) 

The issue does not require malicious RPC data, compromised keys, or protocol peers; it follows from a valid public Bitcoin block supplied to the block-scanning API. [9](#0-8) 

The likelihood depends on whether downstream code uses `scan_block` for balance selection, but the vulnerable path is directly reachable through the public API. [1](#0-0) 

### Recommendation
Change `Scanner::scan_block` to skip `block.txdata[0]` by default, or return a distinct output type/state that records coinbase maturity and prevents passing the output to `SignableTransaction::new` until it is mature. [1](#0-0) 

If coinbase outputs must remain discoverable, `ReceivedOutput` should encode the minimum spendable height and `SignableTransaction::new` should reject inputs whose recorded spendable height exceeds the current chain height. [5](#0-4) 

### Proof of Concept
A block containing a coinbase output to the scanner’s registered P2TR script is scanned with `Scanner::scan_block`, causing `scan_transaction` to emit a `ReceivedOutput` with `offset`, `output`, and `outpoint`. [8](#0-7) 

The resulting `ReceivedOutput` can be passed to `SignableTransaction::new`, which uses its `outpoint` as a normal transaction input without any coinbase-maturity check. [6](#0-5) 

```rust
let received = scanner.scan_block(&block);
assert_eq!(received.len(), 1);
assert_eq!(received[0].outpoint().txid, block.txdata[0].compute_txid());

// This constructs an input spending the coinbase output immediately.
let signable = SignableTransaction::new(
    received,
    &[(payment_script, payment_amount)],
    None,
    None,
    fee_per_vbyte,
)?;
```

```rust
  /// Scan a transaction.
  pub fn scan_transaction(&self, tx: &Transaction) -> Vec<ReceivedOutput> {
    let mut res = Vec::new();
    for (vout, output) in tx.output.iter().enumerate() {
      // If the vout index exceeds 2**32, stop scanning outputs
      let Ok(vout) = u32::try_from(vout) else { break };

      if let Some(offset) = self.scripts.get(&output.script_pubkey) {
        res.push(ReceivedOutput {
          offset: *offset,
          output: output.clone(),
          outpoint: OutPoint::new(tx.compute_txid(), vout),
        });
      }
    }
    res
  }

  /// Scan a block.
  ///
  /// This will also scan the coinbase transaction which is bound by maturity. If received outputs
  /// must be immediately spendable, a post-processing pass is needed to remove those outputs.
  /// Alternatively, scan_transaction can be called on `block.txdata[1 ..]`.
  pub fn scan_block(&self, block: &Block) -> Vec<ReceivedOutput> {
    let mut res = Vec::new();
    for tx in &block.txdata {
      res.extend(self.scan_transaction(tx));
    }
    res
  }
```
