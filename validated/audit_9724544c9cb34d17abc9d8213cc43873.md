### Title
Governance parameters read from the GovParam contract bypass `FormatChecker` validation applied to header-vote parameters, allowing acceptance of semantically invalid governance values - (File: kaiax/gov/paramset.go)

### Summary
`ParamSet.Set()`, which is used by the contract-governance engine to populate the effective `ParamSet` from values read out of the on-chain `GovParam` contract, only performs a Go type assertion on each value and never calls the parameter's `FormatChecker`. In contrast, the header-vote path (`PartialParamSet.Add()`) explicitly runs both `Canonicalizer` and `FormatChecker` before a vote value is accepted. This is the same "constructor vs. setter validation mismatch" pattern as the referenced Backd finding: two code paths write the same state, but only one path enforces the semantic validation rules.

### Finding Description
`Param.FormatChecker` encodes semantic validity rules for each governance parameter, e.g. `Kip71BaseFeeDenominator` must be non‑zero, `RewardKip82Ratio`/`RewardRatio` percentages must sum to 100, `GovernanceGovernanceMode` must be `"none"` or `"single"`, `IstanbulPolicy`/`GovernanceDeriveShaImpl` must be within a bounded range, etc. [1](#0-0) [2](#0-1) [3](#0-2) 

The header-vote ingestion path enforces these checks before storing a value: [4](#0-3) 

However, `ParamSet.Set()`, which is the function used to populate the `ParamSet` both for defaults and for values decoded from the `GovParam` contract, performs only a type assertion (`ok`) and never invokes `FormatChecker`: [5](#0-4) 

The contract-governance engine calls this unguarded `Set()` directly on values obtained from the contract: [6](#0-5) 

The module's own documentation confirms that only canonicalization failures (wrong type/format) are filtered out, not `FormatChecker` semantic violations: "Some parameters may be invalid (e.g., invalid parameter name or non-canonical value), which will be ignored." [7](#0-6) 

Since `GovParam` is a generic bytes key/value store controlled by contract governance (KIP-81 voting / contract owner), and `setParam`/`setParamIn` do not themselves validate the semantic meaning of `val`, a value can be crafted that decodes to the correct Go type (passing `Canonicalizer`) but violates the `FormatChecker` invariant (e.g., `Kip71BaseFeeDenominator = 0`, or `RewardKip82Ratio = "30/30"`). Because `contractGovModule.GetParamSet` calls `ret.Set(k, v)` instead of an equivalent of `Add()`, this invalid value is accepted into the live `ParamSet` used for block processing. [6](#0-5) 

### Impact Explanation
`ParamSet.ToKip71Config()` feeds `BaseFeeDenominator` directly into the KIP-71 base fee formula used during block assembly/validation. [8](#0-7) 
If `Kip71BaseFeeDenominator` is set to `0` via the GovParam contract path (bypassing the `v != 0` `FormatChecker`), any node computing the next base fee with this parameter set will hit a division by zero, causing a panic/crash during block header validation or block building. This is directly reachable from a normal governance/contract-owner transaction (`setParamIn`/`setParam` on `GovParam`), and results in either a node crash (halting participation) or, if only some nodes apply the contract-governance path while others use defaults/headergov, a state/consensus divergence between honest nodes — both of which qualify as concrete, high-impact effects rather than a purely cosmetic bug.

### Likelihood Explanation
Exploitation requires only a normal transaction to the `GovParam` contract (`setParam`/`setParamIn`) crafted by whoever controls governance mode "single"/contract ownership or a GC member acting through KIP-81 voting — no privileged node/validator access or network-level attack is required. The bug is a straightforward code-path inconsistency (missing `FormatChecker` call) that is trivially reproducible by anyone able to submit a `setParamIn` transaction with an out-of-range value for a parameter whose `Canonicalizer` type matches but whose `FormatChecker` would normally reject it.

### Recommendation
Make `ParamSet.Set()` (or the call site in `contractGovModule.GetParamSet`) enforce the same `FormatChecker` validation that `PartialParamSet.Add()` applies, e.g. by having `GetParamSet` call `Add`-equivalent logic (canonicalize + format-check) on each contract-derived value before calling `Set`, and fall back to the default value (or skip the parameter) when `FormatChecker` fails, consistent with the documented "invalid parameters are ignored" behavior.

### Proof of Concept
1. Deploy/own `GovParam` and enable contract governance (`GovernanceGovParamContract` set, mode enabling contract governance), analogous to the flow in the existing test harness. [9](#0-8) 
2. Call `setParamIn("kip71.basefeedenominator", true, <bytes encoding 0>, <activation>)` on the `GovParam` contract.
3. At the activation block, `contractGovModule.GetParamSet` decodes the stored bytes via `uint64Canonicalizer` to `uint64(0)` (type-valid) and calls `ret.Set(Kip71BaseFeeDenominator, uint64(0))`, which succeeds because `Set()` never checks `FormatChecker`'s `v != 0` rule. [10](#0-9) [2](#0-1) 
4. Subsequent base fee computation using `ParamSet.ToKip71Config().BaseFeeDenominator == 0` will divide by zero during block processing.

func (p PartialParamSet) Add(name string, value any) error {
	param, ok := Params[ParamName(name)]
	if !ok {
		return ErrInvalidParamName
	}

	cv, err := param.Canonicalizer(value)
	if err != nil {
		return err
	}

	if !param.FormatChecker(cv) {
		return ErrInvalidParamValue
	}

	p[ParamName(name)] = cv
	return nil
}

func (c *contractGovModule) GetParamSet(blockNum uint64) gov.ParamSet {
	m, err := c.contractGetAllParamsAt(blockNum)
	if err != nil {
		return *gov.GetDefaultGovernanceParamSet()
	}

	ret := *gov.GetDefaultGovernanceParamSet()
	for k, v := range m {
		err = ret.Set(k, v)
		if err != nil {
			return *gov.GetDefaultGovernanceParamSet()
		}
	}

	return ret
}
