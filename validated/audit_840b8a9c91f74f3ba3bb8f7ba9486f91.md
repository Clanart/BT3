### Title
Bank precompile's `sendNative` bypasses the governance `SendEnabled` pause, unlike `send()` - (File: precompiles/bank/bank.go)

### Summary
The Bank precompile exposes two ways to move `usei`/native coin value from an EVM transaction: `send()` and the payable `sendNative()`. `send()` routes through the Cosmos bank message server, which enforces the governance-controlled `SendEnabled` param (the chain's send-pause mechanism). `sendNative()` instead calls the bank keeper's low-level `SendCoinsAndWei` directly, which never checks `SendEnabled`, letting any EVM caller move `usei` even while sends are paused by governance.

### Finding Description
The `send` method of the Bank precompile builds a `banktypes.MsgSend` and dispatches it through `p.bankMsgServer.Send(...)`: [1](#0-0) 

`bank` module's `MsgServer.Send` enforces the pause by calling `IsSendEnabledCoins` before doing any transfer: [2](#0-1) 

`IsSendEnabledCoins`/`IsSendEnabledCoin` read the governance-settable `SendEnabled`/`DefaultSendEnabled` bank params — the mechanism operators use to pause transfers of a denom: [3](#0-2) 

In contrast, the precompile's `sendNative` (a `payable` function reachable by any EVM transaction that sends native value to the Bank precompile address) skips the message server entirely and calls `p.bankKeeper.SendCoinsAndWei` directly: [4](#0-3) 

`SendCoinsAndWei` only manipulates the wei sub-balance and calls `SendCoinsWithoutAccCreation` for the integer `usei` portion — neither of which calls `IsSendEnabledCoins`: [5](#0-4) 

This same structure (message-server-checked `send()` vs. keeper-direct `sendNative()`) is present identically across every historical precompile version examined (v65, v66, v600, v605, v630, v67), indicating the bypass has persisted through the precompile's evolution rather than being a one-off regression: [6](#0-5) 

### Impact Explanation
`SendEnabled` is the chain's operator/governance-controlled kill-switch for halting transfers of a given denom (e.g., in response to an exploit, compliance action, or incident response). Because `sendNative` never consults it, any unprivileged EVM account can continue transferring native `usei` value through the Bank precompile even after governance disables sends for that denom, completely defeating the pause. This is a fund-movement/authorization-bypass bug reachable by a plain EVM transaction (no privileges needed), analogous to the reported `authRedeem`/`autoRedeem` pause bypass.

### Likelihood Explanation
High: reaching `sendNative` requires nothing more than an ordinary EVM transaction with a non-zero `value` targeting the Bank precompile address (`0x1001`) — the exact same primitive any user already uses for legitimate native transfers via that precompile. No special permissions, contract deployment, or edge-case setup is needed; the bypass triggers on every call whenever `SendEnabled` has been turned off.

### Recommendation
Add an explicit `IsSendEnabledCoins` (or equivalent) check for the base denom in `sendNative` before calling `SendCoinsAndWei`, mirroring the check already performed by the bank message server's `Send` path used by the precompile's `send()` method.

### Proof of Concept
1. Governance/admin sets `SendEnabled` (or `DefaultSendEnabled`) to `false` for `usei` via a bank params update.
2. Call `MsgSend` (or the precompile's `send()`), which correctly reverts with `ErrSendDisabled` — pause works as intended.
3. From any EOA, send an EVM transaction with non-zero `value` to the Bank precompile address invoking `sendNative(toNativeAddress)`.
4. `sendNative` calls `bankKeeper.SendCoinsAndWei` directly; the transfer succeeds and funds move despite `SendEnabled=false`, proving the pause is bypassed.

// IsSendEnabledCoins checks the coins provide and returns an ErrSendDisabled if
// any of the coins are not configured for sending.  Returns nil if sending is enabled
// for all provided coin
func (k BaseSendKeeper) IsSendEnabledCoins(ctx sdk.Context, coins ...sdk.Coin) error {
	for _, coin := range coins {
		if !k.IsSendEnabledCoin(ctx, coin) {
			return sdkerrors.Wrapf(types.ErrSendDisabled, "%s transfers are currently disabled", coin.Denom)
		}
	}
	return nil
}

// IsSendEnabledCoin returns the current SendEnabled status of the provided coin's denom
func (k BaseSendKeeper) IsSendEnabledCoin(ctx sdk.Context, coin sdk.Coin) bool {
	return k.GetParams(ctx).SendEnabledDenom(coin.Denom)
}

func (k BaseSendKeeper) SendCoinsAndWei(ctx sdk.Context, from sdk.AccAddress, to sdk.AccAddress, amt sdk.Int, wei sdk.Int) error {
	if err := k.SubWei(ctx, from, wei); err != nil {
		return err
	}
	if err := k.AddWei(ctx, to, wei); err != nil {
		return err
	}
	ctx.EventManager().EmitEvents(sdk.Events{
		sdk.NewEvent(
			types.EventTypeWeiTransfer,
			sdk.NewAttribute(types.AttributeKeyRecipient, to.String()),
			sdk.NewAttribute(types.AttributeKeySender, from.String()),
			sdk.NewAttribute(sdk.AttributeKeyAmount, wei.String()),
		),
	})
	if amt.GT(sdk.ZeroInt()) {
		return k.SendCoinsWithoutAccCreation(ctx, from, to, sdk.NewCoins(sdk.NewCoin(sdk.MustGetBaseDenom(), amt)))
	}
	return nil
}

		return nil, 0, errors.New("cannot call sendNative from staticcall")
	}
	if ctx.EVMPrecompileCalledFromDelegateCall() {
		return nil, 0, errors.New("cannot delegatecall sendNative")
	}
	if err := pcommon.ValidateArgsLength(args, 1); err != nil {
		return nil, 0, err
	}
	if value == nil || value.Sign() == 0 {
		return nil, 0, errors.New("set `value` field to non-zero to send")
	}

	senderSeiAddr, ok := p.evmKeeper.GetSeiAddress(ctx, caller)
	if !ok {
		return nil, 0, errors.New("invalid addr")
	}

	receiverAddr, ok := (args[0]).(string)
	if !ok || receiverAddr == "" {
		return nil, 0, errors.New("invalid addr")
	}

	receiverSeiAddr, err := sdk.AccAddressFromBech32(receiverAddr)
	if err != nil {
		return nil, 0, err
	}

	usei, wei, err := pcommon.HandlePaymentUseiWei(ctx, p.evmKeeper.GetSeiAddressOrDefault(ctx, p.address), senderSeiAddr, value, p.bankKeeper, p.evmKeeper, hooks, evm.GetDepth())
	if err != nil {
		return nil, 0, err
	}

	if err := p.bankKeeper.SendCoinsAndWei(ctx, senderSeiAddr, receiverSeiAddr, usei, wei); err != nil {
		return nil, 0, err
