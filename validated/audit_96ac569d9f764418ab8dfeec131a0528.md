### Title
Invalid-PoP DKG share messages can force early return of an EncryptionKeyProof, revealing an ECDH key for an attacker-chosen `msg.key` - (File: crypto/dkg/pedpop/src/encryption.rs)

### Summary
`EncryptedMessage` PoP validity is only queued into a batch verifier, while `decrypt` immediately derives the ECDH key, decrypts, and returns an `EncryptionKeyProof` containing that ECDH key and a DLEq for `enc_key * msg.key` [1](#0-0) . In `calculate_share`, a malformed secret-share scalar causes an early `InvalidShare` error with `blame: Some(blame)` before `batch.verify_with_vartime_blame()` can reject the queued invalid PoP [2](#0-1) . An unprivileged DKG participant can set `EncryptedMessage.key` to another participant’s registered encryption public key, use an invalid PoP and non-scalar ciphertext, and still obtain a blame proof revealing the ECDH shared key for that public key.

### Finding Description
The code intends the per-message PoP to prevent an attacker from claiming/reusing someone else’s encryption key, because blame disclosure of `proof.key` would expose the victim’s ECDH output [3](#0-2) . However, `decrypt` calls `msg.pop.batch_verify(...)` only to enqueue the statement, then computes `key = ecdh(&self.enc_key, msg.key)`, decrypts, and constructs `EncryptionKeyProof { key, dleq }` before any batch result is known [4](#0-3) . `calculate_share` then parses the decrypted bytes with `C::F::from_repr`; on invalid scalar it returns `InvalidShare { participant: l, blame: Some(blame.clone()) }` immediately, prior to the batch verification that would flag the bad PoP [5](#0-4) .

### Impact Explanation
A malicious DKG participant can obtain a valid `EncryptionKeyProof` for `ECDH(victim_static_enc_key, attacker_supplied_msg.key)` even though the supplied message has an invalid PoP. By setting `msg.key` to another participant’s registered encryption public key, the revealed `proof.key` equals that participant↔victim ECDH output, enabling decryption/blame material for messages encrypted under that pairing and undermining the side-effect protection described for per-message keys [6](#0-5) [7](#0-6) .

### Likelihood Explanation
The attacker only needs to be a DKG participant able to send an `EncryptedMessage` into `calculate_share`/`read` paths with chosen `key`, `pop`, and ciphertext bytes; no collusion, validator compromise, leaked secret, or invalid curve input is required [8](#0-7) [9](#0-8) . The trigger is deterministic: make the decrypted share bytes non-canonical so the early scalar error fires before the deferred PoP batch check [10](#0-9) .

### Recommendation
Verify the `msg.pop` synchronously before performing ECDH/decryption or before constructing/returning `EncryptionKeyProof`, and ensure no error path can return a blame proof for a message whose PoP has not already passed [4](#0-3) . At minimum, do not attach `blame` to early parse/share errors until after the queued PoP statement has been verified and found valid [11](#0-10) .

### Proof of Concept
In `SecretShareMachine::generate_secret_shares`, the victim registers sender encryption keys and later calls `KeyMachine::calculate_share` with attacker-controlled `shares` [12](#0-11) [13](#0-12) . The attacker submits `EncryptedMessage { key: victim_or_other_registered_enc_pub_key, pop: invalid_signature, msg: bytes_that_decrypt_to_non_scalar }`; `Encryption::decrypt` queues `pop.batch_verify`, then derives `proof.key = self.enc_key * msg.key` and returns the proof regardless [4](#0-3) . Because `calculate_share` returns `InvalidShare` with `Some(blame)` on the non-canonical scalar before `batch.verify_with_vartime_blame()` runs, the caller receives an `EncryptionKeyProof` exposing the ECDH key for the chosen `msg.key` despite the forged/invalid PoP [14](#0-13) .

  pub fn calculate_share<R: RngCore + CryptoRng>(
    mut self,
    rng: &mut R,
    mut shares: HashMap<Participant, EncryptedMessage<C, SecretShare<C::F>>>,
  ) -> Result<BlameMachine<C>, PedPoPError<C>> {
    validate_map(
      &shares,
      &self.params.all_participant_indexes().collect::<Vec<_>>(),
      self.params.i(),
    )?;

    let mut batch = BatchVerifier::new(shares.len());
    let mut blames = HashMap::new();
    for (l, share_bytes) in shares.drain() {
      let (mut share_bytes, blame) =
        self.encryption.decrypt(rng, &mut batch, BatchId::Decryption(l), l, share_bytes);
      let share =
        Zeroizing::new(Option::<C::F>::from(C::F::from_repr(share_bytes.0)).ok_or_else(|| {
          PedPoPError::InvalidShare { participant: l, blame: Some(blame.clone()) }
        })?);
      share_bytes.zeroize();
      *self.secret += share.deref();

      blames.insert(l, blame);
      batch.queue(
        rng,
        BatchId::Share(l),
        share_verification_statements::<C>(self.params.i(), &self.commitments[&l], share),
      );
    }
    batch.verify_with_vartime_blame().map_err(|id| {
      let (l, blame) = match id {
        BatchId::Decryption(l) => (l, None),
        BatchId::Share(l) => (l, Some(blames.remove(&l).unwrap())),
      };
      PedPoPError::InvalidShare { participant: l, blame }
    })?;
