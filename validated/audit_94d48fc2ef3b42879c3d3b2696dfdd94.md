Found a concrete analog. The `kaiax/staking` module caches `minimumStake` once at initialization from the genesis `ChainConfig`, rather than reading the live governance parameter (`reward.minimumstake`) on every call, unlike the reward and valset modules which correctly re-fetch `GetParamSet(blockNum).MinimumStake` per block.

### Title
Staking module caches `minimumStake` from genesis config, ignoring live `reward.minimumstake` governance updates - ([File: kaiax/staking/impl/init.go])

### Summary
`StakingModule.Init` reads `reward.minimumstake` once from the genesis `ChainConfig` and stores it in the module field `s.minimumStake` for the module's lifetime [1](#0-0) . This cached value is later used unconditionally by the public `kaia_getStakingInfo` / `governance_getStakingInfo` RPC API to compute the Gini coefficient and populate the response's minimum-stake-filtered node list [2](#0-1) , regardless of any subsequent governance change to the minimum stake requirement at the queried block number.

### Finding Description
This mirrors the FrankenDAO bug class: a governance-adjustable parameter (`monsterMultiplier` there, `reward.minimumstake` here) is captured into a fixed/cached value at one point in time, and a downstream computation keeps using the stale cached copy instead of re-reading the parameter effective at the relevant point (per-tokenId in FrankenDAO, per-block here).

Other Kaia modules do this correctly: the reward module re-derives `MinimumStake` from `govModule.GetParamSet(header.Number.Uint64())` for every block via `NewRewardConfig` [3](#0-2) , and the valset module's demotion/eligibility logic also calls `GetParamSet(blockNum)` per block to obtain `MinimumStake` (as exercised in `Test_AfterMinimumStakingVotes`) [4](#0-3) . In contrast, the staking module's `s.minimumStake` is set only in `Init()` from `ChainConfig.Governance.Reward.MinimumStake` and is never refreshed from `GovModule.GetParamSet(num)` [5](#0-4) .

The `kaiax/gov/README.md` documents `kaiax/staking: Provides the useGini and minStake for the API`, and lists `reward.minimumstake` as immutable specifically for **Mainnet** configuration, implying it can still be altered via governance (header or contract governance) on non-Mainnet networks (e.g., private chains, Kairos) [6](#0-5) . On such networks, if `reward.minimumstake` is changed post-genesis, the `kaia_getStakingInfo` API's Gini computation and minimum-stake-based node reporting would silently continue to use the original genesis value, causing divergence between the API's reported staking eligibility/Gini data and the actual on-chain consensus-determined eligibility (which correctly uses live governance parameters via valset/reward).

### Impact Explanation
This is a state/reporting divergence bug rather than a fund-theft bug: the RPC API `kaia_getStakingInfo` (public, callable by anyone) would return an incorrect Gini coefficient and stake-eligibility view relative to the actual live governance parameter used by consensus (valset/reward modules). Any external system, monitoring tool, or governance dashboard relying on this API to determine validator eligibility or staking-based Gini weighting would receive stale/incorrect data, potentially leading to incorrect downstream decisions (e.g., mis-reporting which nodes are staking-eligible). It does not directly move funds or affect the consensus block validation, since the actual reward/valset paths use fresh governance values.

### Likelihood Explanation
Medium-low: `reward.minimumstake` is deprecated for header-governance votes after a certain hardfork (`ErrDeprecatedVote` for `RewardMinimumStake` votes) [7](#0-6) , and it is explicitly "immutable" on Mainnet per the module README [6](#0-5) . This limits real-world triggerability primarily to networks where `reward.minimumstake` can still be updated (private/test networks or via contract governance if not deprecated there), reducing likelihood on Mainnet/Kairos but leaving it plausible in other deployments of the Kaia codebase.

### Recommendation
Replace the cached `s.minimumStake` field usage in `stakingAPI.GetStakingInfo` with a live lookup via the governance module (`GovModule.GetParamSet(num).MinimumStake`) at the requested block number, consistent with how `kaiax/reward` and `kaiax/valset` retrieve this parameter, instead of relying on the value captured once during `StakingModule.Init`.

### Proof of Concept
1. Deploy a private Kaia network where `reward.minimumstake` is not yet deprecated (or use contract governance, if permitted, to change it).
2. Genesis sets `reward.minimumstake = 5,000,000`; `StakingModule.Init` caches `s.minimumStake = 5,000,000` [8](#0-7) .
3. Submit a governance vote/transaction to change `reward.minimumstake` to a new value (e.g., `1,000,000`) effective at a later epoch/block.
4. Query `kaia_getStakingInfo` for a block number after the change takes effect: the API still computes Gini and stake-filtered results using the stale `5,000,000` value [9](#0-8) , while the actual consensus-relevant valset/reward computations for the same block correctly use the updated `1,000,000` value, producing a verifiable divergence between the reported staking API data and the true on-chain eligibility.

	InitOpts

	// Genesis configurations
	stakingInterval uint64
	useGiniCoeff    bool
	minimumStake    *big.Int

	stakingInfoCache *lru.ARCCache // cached by sourceNum
	preloadBuffer    *PreloadBuffer
}

func NewStakingModule() *StakingModule {
	cache, _ := lru.NewARC(128)
	return &StakingModule{
		stakingInfoCache: cache,
		preloadBuffer:    NewPreloadBuffer(),
	}
}

func (s *StakingModule) Init(opts *InitOpts) error {
	if opts == nil || opts.ChainConfig == nil || opts.Chain == nil || opts.ChainKv == nil {
		return staking.ErrInitUnexpectedNil
	}
	s.InitOpts = *opts

	if s.ChainConfig.Governance == nil || s.ChainConfig.Governance.Reward == nil {
		return staking.ErrInitUnexpectedNil
	}
	if s.ChainConfig.Governance.Reward.StakingUpdateInterval == 0 {
		return staking.ErrZeroStakingInterval
	}
	s.stakingInterval = s.ChainConfig.Governance.Reward.StakingUpdateInterval
	s.useGiniCoeff = s.ChainConfig.Governance.Reward.UseGiniCoeff
	s.minimumStake = s.ChainConfig.Governance.Reward.MinimumStake

	return nil
}

func (api *stakingAPI) GetStakingInfo(num rpc.BlockNumber) (*staking.StakingInfoResponse, error) {
	if num == rpc.LatestBlockNumber {
		num = rpc.BlockNumber(api.s.Chain.CurrentBlock().NumberU64())
	}

	si, err := api.s.GetStakingInfo(num.Uint64())
	if err != nil {
		return nil, err
	}

	var useGini bool
	// Gini option deprecated since Kore, as All committee members have an equal chance
	if api.s.ChainConfig.IsKoreForkEnabled(new(big.Int).SetUint64(num.Uint64())) {
		useGini = false
	} else {
		useGini = api.s.useGiniCoeff
	}
	// Calculate Gini coefficient regardless of useGini flag
	return si.ToResponse(useGini, api.s.minimumStake.Uint64()), nil
}
