### Title
Trampoline credential-helper token is not bound to the git operation's target host, allowing a malicious repo hook/filter to exfiltrate the user's real GitHub token during clone/fetch - (File: `app/src/lib/trampoline/trampoline-credential-helper.ts`, `app/src/lib/trampoline/trampoline-tokens.ts`)

### Summary
This is a structural analog of the Sablier Permit2 report: a broadly-scoped authorization artifact (there, a Permit2 signature; here, `DESKTOP_TRAMPOLINE_TOKEN`) is valid for *any* use once possessed, because it is not bound to the specific intent it was minted for (there, the target contract/function; here, the specific remote host/URL the git operation was launched against). Any process that can obtain the token can redeem it for an unrelated, more privileged action.

### Finding Description
When Desktop runs a git operation (`clone`, `fetch`, etc.) it calls `withTrampolineEnv`, which mints a bearer token via `withTrampolineToken` and injects it into the child git process environment as `DESKTOP_TRAMPOLINE_TOKEN`, along with `DESKTOP_PORT` for the trampoline TCP server: [1](#0-0) 

`isValidTrampolineToken` only checks *set membership* - it has no notion of which repository, remote, or endpoint the token was issued for: [2](#0-1) 

The trampoline server accepts any connection presenting a valid token and dispatches it to the registered `CredentialHelper`/`AskPass` handler, again without checking that the request corresponds to the git subprocess that owns the token or to the URL that subprocess is actually talking to: [3](#0-2) 

The credential-helper `get` handler resolves credentials purely from the `url`/`host` fields supplied in the request payload - fields that are entirely attacker-controlled if the caller is not the real git process but an impostor using the leaked token/port: [4](#0-3) [5](#0-4) 

If the account for that (attacker-chosen) endpoint already exists in Desktop's account store (e.g. the user's real `github.com` account), `getGitHubCredential` returns the stored OAuth token **silently, with no user prompt**: [6](#0-5) 

Git operations that run attacker-influenced code as a child process (post-checkout/post-merge hooks enabled via `core.hooksPath`/hooks copied from the fetched repo, clean/smudge filters declared in a fetched `.gitattributes`, or submodule build steps triggered by `--recursive`) inherit the full process environment, including `DESKTOP_PORT` and `DESKTOP_TRAMPOLINE_TOKEN`, because `clone.ts` spawns `git clone --recursive` with the trampoline env attached: [7](#0-6) 

The wire protocol used to talk to the trampoline server is a simple, undocumented (but not secret) text protocol implemented by the small C client and parsed by `TrampolineCommandParser` - parameter count, parameters, env-var count, env vars, stdin, terminated by NUL - trivially reproducible from a shell script or any language with a TCP socket: [8](#0-7) 

Nothing in this chain verifies that a `get` request naming `url=https://github.com` was actually issued by *this* git subprocess talking to *this* remote, as opposed to being forged by a sibling process (a hook/filter spawned by the very same git invocation, sharing the same env) that simply wants a different, higher-value credential.

### Impact Explanation
An attacker who controls a cloned/fetched repository (or a submodule pulled in via `--recursive`) can plant a hook or a `.gitattributes` filter that runs during the user's own clone/fetch operation. Because that script inherits `DESKTOP_TRAMPOLINE_TOKEN`/`DESKTOP_PORT`, it can open a raw socket to `127.0.0.1:$DESKTOP_PORT`, emit a forged `CREDENTIALHELPER get` command with `url=https://github.com` (or the user's GHE endpoint), and receive the user's real GitHub personal token/OAuth token back over the loopback socket with no additional prompt, since an account already exists for that endpoint. That token can then be exfiltrated over the network from the hook script. This is credential/token exfiltration entirely outside the scope of the git operation the user actually consented to (cloning an unrelated repository), matching the "credential/token exfiltration" impact bucket.

### Likelihood Explanation
The precondition is only that the victim clones or fetches a repository controlled by the attacker (or one containing an attacker-controlled submodule) with hooks enabled or with a `.gitattributes` filter/clean command configured (Desktop does not sandbox git hooks or filters, and `--recursive` is passed unconditionally on clone). No local access, malware, or leaked credentials are required — the untrusted input is the repository content itself, which is exactly the attacker-controlled-repository primitive called out as valid in scope. The main uncertainty is exact timing/reliability of grabbing the token before the legitimate git subprocess consumes/short-lived-revokes it (`withTrampolineToken` revokes the token once the whole git invocation, including all hooks/filters it spawns, completes) — but since hooks run synchronously as children of that same invocation, the token is live in their environment for the whole operation.

### Recommendation
Scope trampoline tokens (and/or credential-helper requests) to the specific remote URL/host the originating git invocation was started for, and reject `get`/`store`/`erase` requests whose `url`/`host` do not match that pre-registered target. At minimum, require confirmation before releasing GitHub/GHE-authenticated credentials to a `get` request whose host differs from the host recorded when the token was minted for that git operation. Consider also not enabling hook execution / documenting the risk analogous to Sablier's response, since — like the plugin/target-execution flow — the trampoline server cannot always distinguish the "real" git process from an attacker-spawned child sharing its environment.

### Proof of Concept
1. Attacker publishes a public repo containing:
   - `.git/hooks/post-checkout` (or a `.gitattributes` referencing a smudge filter) that reads `DESKTOP_PORT`/`DESKTOP_TRAMPOLINE_TOKEN` from its environment.
2. Victim uses GitHub Desktop, already signed in to `github.com`, and clones the attacker's repository (`clone.ts` invokes `git clone --recursive` with `withTrampolineEnv`, injecting the token/port into the whole process tree).
3. During checkout, the hook fires and, using the inherited env vars, connects to `127.0.0.1:$DESKTOP_PORT` and speaks the trampoline protocol (`0` parameters, `2` environment variables: `DESKTOP_TRAMPOLINE_IDENTIFIER=CREDENTIALHELPER`, `DESKTOP_TRAMPOLINE_TOKEN=<token>`, followed by stdin `get\n`) with credential input `protocol=https\nhost=github.com\n`.
4. `createCredentialHelperTrampolineHandler` → `getCredential` → `getGitHubCredential` finds the victim's stored `github.com` account and returns `username`/`password` (the OAuth token) in the response, which the hook script exfiltrates to an attacker server.

Note: I was not able to execute this end-to-end in the index (no sandbox/terminal access here), so step 3-4 reproduction should be validated by a Devin session with actual repo/terminal access to confirm the exact wire-format bytes accepted by `TrampolineCommandParser` and that hook execution indeed inherits `DESKTOP_PORT`/`DESKTOP_TRAMPOLINE_TOKEN` in this build.

export const getCredentialUrl = (cred: Map<string, string>) => {
  const u = cred.get('url')
  if (u) {
    return new URL(u)
  }

  const protocol = cred.get('protocol') ?? ''
  const username = cred.get('username')
  const user = username ? `${encodeURIComponent(username)}@` : ''
  const host = cred.get('host') ?? ''
  const path = cred.get('path') ?? ''

  return new URL(`${protocol}://${user}${host}/${path}`)
}

async function getCredential(cred: Credential, store: Store, token: string) {
  const ghCred = await getGitHubCredential(cred, store)

  if (ghCred) {
    return ghCred
  }

  const endpointKind = await getEndpointKind(cred, store)
  const accounts = await store.getAll()

  const endpoint = `${getCredentialUrl(cred)}`
  const apiEndpoint = getAPIEndpoint(endpoint)

  // If it appears as if the endpoint is a GitHub host and we don't have an
  // account for that endpoint then we should prompt the user to sign in.
  if (
    endpointKind !== 'generic' &&
    !accounts.some(a => a.endpoint === apiEndpoint)

    if (getIsBackgroundTaskEnvironment(token)) {
      debug('background task environment, skipping prompt')
      return undefined
    }

    const account = await ui.promptForGitHubSignIn(endpoint)

    if (!account) {
      setHasRejectedCredentialsForEndpoint(token, endpoint)
    }

    return credWithAccount(cred, account)
  }

  public processValue(value: string) {
    switch (this.state) {
      case TrampolineCommandParserState.ParameterCount:
        this.parameterCount = parseInt(value)

        if (this.parameterCount > 0) {
          this.state = TrampolineCommandParserState.Parameters
        } else {
          this.state = TrampolineCommandParserState.EnvironmentVariablesCount
        }

        break

      case TrampolineCommandParserState.Parameters:
        this.parameters.push(value)
        if (this.parameters.length === this.parameterCount) {
          this.state = TrampolineCommandParserState.EnvironmentVariablesCount
        }
        break

      case TrampolineCommandParserState.EnvironmentVariablesCount:
        this.environmentVariablesCount = parseInt(value)

        if (this.environmentVariablesCount > 0) {
          this.state = TrampolineCommandParserState.EnvironmentVariables
        } else {
          this.state = TrampolineCommandParserState.Stdin
        }

        break

      case TrampolineCommandParserState.EnvironmentVariables:
        // Split after the first '='
        const match = /([^=]+)=(.*)/.exec(value)

        if (
          match === null ||
          // Length must be 3: the 2 groups + the whole string
          match.length !== 3
        ) {
          throw new Error(`Unexpected environment variable format: ${value}`)
        }

        const variableKey = match[1]
        const variableValue = match[2]

        this.environmentVariables.set(variableKey, variableValue)

        if (this.environmentVariables.size === this.environmentVariablesCount) {
          this.state = TrampolineCommandParserState.Stdin
        }
        break
      case TrampolineCommandParserState.Stdin:
        this.stdin = value
        this.state = TrampolineCommandParserState.Finished
        break
