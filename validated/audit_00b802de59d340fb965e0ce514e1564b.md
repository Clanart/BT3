## Title
Unauthenticated OP_RETURN operator attribution in the payout transaction lets anyone rewrite who gets credited for a fronted withdrawal - ([File: core/src/builder/transaction/operator_reimburse.rs])

### Summary
The bug class in the report ("a value used for accounting is not derived from an authenticated, up-to-date binding before it is consumed") maps to a real attribution gap in Clementine: the operator that gets reimbursed for a withdrawal is decided purely from the `OP_RETURN` payload of the on-chain `payout_tx`, but that payload is never bound to (nor authenticated by) the user's withdrawal signature. `create_payout_txhandler` only Schnorr-signs input 0 of the `payout_tx` with the user-provided `taproot::Signature` [1](#0-0) , and `Operator::withdraw` verifies that signature against the payout sighash before broadcasting [2](#0-1) , but the credited-operator value (`payout_payer_operator_xonly_pk`) is later derived solely by parsing the `OP_RETURN` output of whatever `payout_tx` variant ends up confirmed on-chain [3](#0-2) .

### Finding Description
The custody/attribution binding that must hold is:
`operator credited for reimbursement == operator that actually funded (fronted) the withdrawal`

`update_finalized_payouts` computes the credited operator by scanning the confirmed `payout_tx`'s outputs for an `OP_RETURN` and parsing an x-only pubkey out of it [4](#0-3) . This value is persisted as `payout_payer_operator_xonly_pk` in the `withdrawals` table [5](#0-4)  and is later used, unconditionally, to: (a) decide which operator's `PayoutCheckerTask` picks up the payout for reimbursement via `get_first_unhandled_payout_by_operator_xonly_pk` [6](#0-5) , and (b) decide whether a kickoff is "malicious" by comparing the OP_RETURN-derived pubkey against `kickoff_data.operator_xonly_pk` in `is_kickoff_malicious` [7](#0-6) .

The comment on `create_payout_txhandler` itself documents the intent: "OP_RETURN output (with operator's x-only pubkey that fronts the peg-out)" [8](#0-7) . However, nothing enforces that this OP_RETURN value corresponds to whichever operator actually supplied the funding inputs of `payout_tx`:
- Only the withdrawal input (input 0, using the user's Schnorr key-spend signature) is authenticated. `set_p2tr_key_spend_witness` signs solely that input [9](#0-8) .
- `Operator::withdraw` funds the transaction via `fund_raw_transaction` with `add_inputs: true`, adding wallet inputs and paying fees, and the sighash type required from the user (`SinglePlusAnyoneCanPay`, per the wrap_err message) explicitly authorizes exactly this: additional inputs can be freely added/changed by anyone, and (because it is `SIGHASH_SINGLE`) only the output at the *same index* as the signed input is committed — the third output (`OP_RETURN`) is outside the signed commitment [2](#0-1) [10](#0-9) .
- Because the signature is `SIGHASH_SINGLE|ANYONECANPAY` over input 0 / output 0 only, *any* party (not just the operator who fronted funds) who observes this partially-signed transaction (e.g., in mempool, via RBF replacement, or via CPFP handling in `clementine-tx-sender`) can rebuild a variant of `payout_tx` that keeps the user's signed input/output pair intact but substitutes a different funding operator's OP_RETURN pubkey (or removes/garbles it), and get it mined instead of the original.

### Impact Explanation
If the OP_RETURN attribution can be altered independently of who actually fronted the withdrawal:
- An operator who never funded the payout could have their `xonly_pk` embedded in a substituted `payout_tx`, causing `update_finalized_payouts`/`is_kickoff_malicious` to credit that operator, letting them claim reimbursement (`handle_finalized_payout` → kickoff → `Reimburse` tx) for a withdrawal they did not pay — this is the "operator credited versus party that paid" binding break called out in the rules, and maps to Critical impact (an operator reimbursed for a payout it never funded).
- Conversely, the honest operator that actually paid the withdrawal amount to the user could have their OP_RETURN dropped or swapped, causing `operator_xonly_pk` to resolve to `None` or to a different pubkey; `is_kickoff_malicious` would then treat their subsequent kickoff as malicious and challenge it, or `PayoutCheckerTask`/`handle_finalized_payout` would never find the payout under their own key, leaving the honest operator permanently unable to be reimbursed for the sats they already paid — Critical impact per the stated rubric.

### Likelihood Explanation
Exploitability requires only unprivileged network-level ability to observe a not-yet-confirmed `payout_tx` (whose signed portion is limited to input 0/output 0 due to `SIGHASH_SINGLE|ANYONECANPAY`) and to have it replaced/rebroadcast with a modified OP_RETURN before the original confirms — no verifier/operator/watchtower/aggregator role, no key compromise, and no dependence on any documented configuration deviation is needed. This is a standard mempool/relay-level manipulation enabled directly by the choice of sighash flags in `create_payout_txhandler`.

### Recommendation
Bind the operator-attribution value to the same signature the user already provides, e.g., by covering the OP_RETURN output with a sighash flag that commits to all outputs (or by moving the operator attribution into data that is committed by an N-of-N/verifier-checked path rather than an unauthenticated OP_RETURN), so that `payout_payer_operator_xonly_pk` cannot be altered independently of the authenticated funding operator. Recompute/verify this binding using the same authenticated data at the point it is consumed in `update_finalized_payouts` and `is_kickoff_malicious`, analogous to recomputing a stale accumulator immediately before use rather than trusting an unauthenticated late-bound field.

### Proof of Concept
1. Operator O1 receives a withdrawal request and calls `withdraw()`, producing `payout_tx` with input 0 = user's withdrawal UTXO (signed `SIGHASH_SINGLE|ANYONECANPAY` by the user), output 0 = user payout, output 1 = anchor, output 2 = `OP_RETURN` containing O1's xonly pubkey [1](#0-0) , then funds/broadcasts it via `fund_raw_transaction`/RBF [11](#0-10) .
2. Before finality, an unprivileged party observes the unconfirmed `payout_tx` in the mempool. Because only input 0/output 0 are signature-committed, they construct an alternate transaction reusing the same signed input/output pair but with a different funding input set and a modified `OP_RETURN` (e.g., embedding operator O2's pubkey, or an invalid pubkey), then relays/RBFs it to replace O1's version.
3. Once the substituted transaction confirms, `update_finalized_payouts` parses the OP_RETURN and stores O2 (or `NULL`) as `payout_payer_operator_xonly_pk` in the `withdrawals` table [12](#0-11) .
4. `is_kickoff_malicious` subsequently compares the stored operator pubkey to O1's kickoff and flags it malicious (mismatch), while `get_first_unhandled_payout_by_operator_xonly_pk`/`PayoutCheckerTask` for O2 (or nobody) surfaces the payout for reimbursement instead of O1, who actually funded the withdrawal [7](#0-6) [6](#0-5) .

pub fn create_payout_txhandler(
    input_utxo: UTXO,
    output_txout: TxOut,
    operator_xonly_pk: XOnlyPublicKey,
    user_sig: taproot::Signature,
    _network: bitcoin::Network,
) -> Result<TxHandler<Signed>, BridgeError> {
    let txin = SpendableTxIn::new_partial(input_utxo.outpoint, input_utxo.txout);

    let output_txout = UnspentTxOut::from_partial(output_txout.clone());

    let op_return_txout = op_return_txout(PushBytesBuf::from(operator_xonly_pk.serialize()));

    let mut txhandler = TxHandlerBuilder::new(TransactionType::Payout)
        .with_version(NON_STANDARD_V3)
        .add_input(
            NormalSignatureKind::NotStored,
            txin,
            SpendPath::KeySpend,
            DEFAULT_SEQUENCE,
        )
        .add_output(output_txout)
        .add_output(UnspentTxOut::from_partial(anchor_output(
            NON_EPHEMERAL_ANCHOR_AMOUNT,
        )))
        .add_output(UnspentTxOut::from_partial(op_return_txout))
        .finalize();
    txhandler.set_p2tr_key_spend_witness(&user_sig, 0)?;
    txhandler.promote()

    /// Sets the given payout txs' txid and operator index for the given index.
    pub async fn update_payout_txs_and_payer_operator_xonly_pk(
        &self,
        tx: Option<DatabaseTransaction<'_>>,
        payout_txs_and_payer_operator_xonly_pk: Vec<(
            u32,
            Txid,
            Option<XOnlyPublicKey>,
            bitcoin::BlockHash,
        )>,
    ) -> Result<(), BridgeError> {
        if payout_txs_and_payer_operator_xonly_pk.is_empty() {
            return Ok(());
        }
        // Convert all values first, propagating any errors
        let converted_values: Result<Vec<_>, BridgeError> = payout_txs_and_payer_operator_xonly_pk
            .iter()
            .map(|(idx, txid, operator_xonly_pk, block_hash)| {
                Ok((
                    i32::try_from(*idx).wrap_err("Failed to convert payout index to i32")?,
                    TxidDB(*txid),
                    operator_xonly_pk.map(XOnlyPublicKeyDB),
                    BlockHashDB(*block_hash),
                ))
            })
            .collect();
        let converted_values = converted_values?;

        let mut query_builder = QueryBuilder::new(
            "UPDATE withdrawals AS w SET
                payout_txid = c.payout_txid,
                payout_payer_operator_xonly_pk = c.payout_payer_operator_xonly_pk,
                payout_tx_blockhash = c.payout_tx_blockhash
                FROM (",
        );

        query_builder.push_values(
            converted_values.into_iter(),
            |mut b, (idx, txid, operator_xonly_pk, block_hash)| {
                b.push_bind(idx)
                    .push_bind(txid)
                    .push_bind(operator_xonly_pk)
                    .push_bind(block_hash);
            },
        );

        query_builder
            .push(") AS c(idx, payout_txid, payout_payer_operator_xonly_pk, payout_tx_blockhash) WHERE w.idx = c.idx");

        let query = query_builder.build();
        execute_query_with_tx!(self.connection, tx, query, execute)?;

        Ok(())
    }

    pub async fn get_first_unhandled_payout_by_operator_xonly_pk(
        &self,
        tx: Option<DatabaseTransaction<'_>>,
        operator_xonly_pk: XOnlyPublicKey,
    ) -> Result<Option<(u32, Txid, BlockHash)>, BridgeError> {
        let query = sqlx::query_as::<_, (i32, Option<TxidDB>, Option<BlockHashDB>)>(
            "SELECT w.idx, w.move_to_vault_txid, w.payout_tx_blockhash
             FROM withdrawals w
             WHERE w.payout_txid IS NOT NULL
                AND w.is_payout_handled = FALSE
                AND w.payout_payer_operator_xonly_pk = $1
                ORDER BY w.idx ASC
             LIMIT 1",
        )
        .bind(XOnlyPublicKeyDB(operator_xonly_pk));

        let results = execute_query_with_tx!(self.connection, tx, query, fetch_optional)?;

        results
            .map(|(citrea_idx, move_to_vault_txid, payout_tx_blockhash)| {
                Ok((
                    u32::try_from(citrea_idx).wrap_err("Failed to convert citrea index to u32")?,
                    move_to_vault_txid
                        .expect("move_to_vault_txid Must be Some")
                        .0,
                    payout_tx_blockhash
                        .expect("payout_tx_blockhash Must be Some")
                        .0,
                ))
            })
            .transpose()
    }
