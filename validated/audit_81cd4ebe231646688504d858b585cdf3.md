### Title
Desktop-created stash entries are keyed by mutable branch **name** instead of branch identity, allowing an unrelated/attacker-influenced branch to silently inherit or destroy another branch's stashed changes - (File: `app/src/lib/git/stash.ts`)

### Summary
GitHub Desktop's "stash on current branch" feature encodes the *branch name* into the stash message and looks stashes up purely by that string. There is no binding to the branch's underlying ref/commit lineage or any other unique identifier, so if two different logical branches ever share the same name (before/after deletion and recreation, or because Desktop itself deterministically derives the name from an external, attacker-influenced value), Desktop will retrieve and eventually drop or restore a stash that belongs to a completely different commit history.

### Finding Description
Desktop marks and finds its own stashes solely via a magic string embedding the branch name: [1](#0-0) 

Lookups by branch name have no secondary check against the branch's tip/tree/history: [2](#0-1) 

This lookup is used automatically whenever Desktop creates a new stash for a branch that already has a Desktop-created entry: the previous entry for that *name* is fetched and then unconditionally dropped, with no verification that the entry actually originated from the same underlying branch history: [3](#0-2) 

The current-branch stash shown in the UI is likewise resolved purely by matching the current tip's branch name against the map of Desktop stash entries: [4](#0-3) 

Crucially, branch names checked out via pull-request flows are **not chosen by the user** but derived deterministically by Desktop itself from PR metadata coming from the GitHub API (attacker-influenced when the attacker is a PR author): for fork PRs Desktop creates/reuses a local branch literally named `pr/${prNumber}`: [5](#0-4) 

This flow is reachable directly from a deep link the user clicks, with all PR head data taken from the GitHub API response: [6](#0-5) [7](#0-6) 

Because the local branch name `pr/<N>` is fully determined by the PR number (public, low-entropy, and reusable after a branch of that name is deleted), and because stash association is keyed only on that name string, the same broken invariant as the reported `loanId` issue is present: **an identifier that is not uniquely reserved to one logical object is used as the sole key for a destructive/administrative operation** (dropping or presenting a stash). No guard exists comparing the stash's stored tree/parent SHAs against the current branch's actual lineage before treating it as "belonging" to that branch.

### Impact Explanation
If a user deletes a `pr/<N>` branch that still has an un-popped Desktop stash (e.g., abandoned review), and later opens a *different* PR that happens to reuse the same number `N` (or manually names a branch `pr/N`), Desktop will:
- Present the old, unrelated stash as "the stash for this branch" in the Changes UI, risking the user restoring foreign code from an unrelated fork/commit history into their current work, or
- Silently drop that old stash the next time `createStashAndDropPreviousEntry` runs for a same-named branch, permanently destroying uncommitted work that had no relation to the new branch.

This matches the "silent corruption of what the user commits" impact category: work gets attributed to, merged with, or destroyed under, the wrong branch identity without any error being surfaced to the user.

### Likelihood Explanation
The trigger path (open a PR link → `openPullRequestFromUrl` → `_checkoutPullRequest` → `_findPullRequestBranch`) is reachable purely by the user clicking a link, using only PR data sourced from the GitHub API, with no local access or elevated privileges required. The collision condition (branch-name reuse after deletion, or PR-number reuse) is a normal, foreseeable event in real usage rather than a contrived edge case, and no code path re-validates stash-to-branch ownership beyond the name string, so the guard that would stop this does not exist.

### Recommendation
Bind Desktop stash entries to a stable identity rather than the mutable branch name alone — e.g., include the branch's original tip SHA (already available as the stash's first parent) as part of the match criteria in `getLastDesktopStashEntryForBranch`, and refuse to silently drop or present a stash whose recorded parent is not an ancestor of the branch's current/previous tip. This closes the same class of "identifier reused without reservation" bug described in the external report.

### Proof of Concept
1. On branch `pr/42` (created from a fork PR #42), make uncommitted changes and switch branches with the "stash on current branch" strategy so Desktop creates a stash tagged `!!GitHub_Desktop<pr/42>`. [8](#0-7) 
2. Delete the local `pr/42` branch without popping the stash (the stash entry itself is not tied to the ref and survives branch deletion in git).
3. Open a link/PR whose number is also `42` from a different fork/author; Desktop's deterministic naming recreates a local branch also called `pr/42`. [9](#0-8) 
4. Any subsequent stash-on-branch operation for the new `pr/42` calls `getLastDesktopStashEntryForBranch(repository, branch)`, which matches the old stash purely by name and drops/exposes it as if it belonged to the new, unrelated branch. [10](#0-9)

export async function getLastDesktopStashEntryForBranch(
  repository: Repository,
  branch: Branch | string
) {
  const stash = await getStashes(repository)
  const branchName = typeof branch === 'string' ? branch : branch.name

  // Since stash objects are returned in a LIFO manner, the first
  // entry found is guaranteed to be the last entry created
  return (
    stash.desktopEntries.find(stash => stash.branchName === branchName) || null
  )
}

  private async createStashAndDropPreviousEntry(
    repository: Repository,
    branch: Branch
  ) {
    const entry = await getLastDesktopStashEntryForBranch(repository, branch)
    const gitStore = this.gitStoreCache.get(repository)

    const createdStash = await gitStore.performFailableOperation(() =>
      this.createStashEntry(repository, branch)
    )

    if (createdStash === true && entry !== null) {
      const { stashSha, branchName } = entry
      await gitStore.performFailableOperation(async () => {
        await dropDesktopStashEntry(repository, stashSha)
        log.info(`Dropped stash '${stashSha}' associated with ${branchName}`)
      })
    }

    return createdStash === true
  }

  private async openPullRequestFromUrl(
    url: string,
    pr: string
  ): Promise<RepositoryWithGitHubRepository | null> {
    const pullRequest = await this.appStore.fetchPullRequest(url, pr)

    if (pullRequest === null) {
      return null
    }

    // Find the repository where the PR is created in Desktop.
    let repository: Repository | null =
      this.getRepositoryFromPullRequest(pullRequest)

    if (repository !== null) {
      await this.selectRepository(repository)
    } else {
      repository = await this.openOrCloneRepository(url)
    }

    if (repository === null) {
      log.warn(
        `Open Repository from URL failed, did not find or clone repository: ${url}`
      )
      return null
    }
    if (!isRepositoryWithGitHubRepository(repository)) {
      log.warn(
        `Received a non-GitHub repository when opening repository from URL: ${url}`
      )
      return null
    }

    // ensure a fresh clone repository has it's in-memory state
    // up-to-date before performing the "Clone in Desktop" steps
    await this.appStore._refreshRepository(repository)

    if (pullRequest.head.repo === null) {
      return null
    }

    await this.appStore._checkoutPullRequest(
      repository,
      pullRequest.number,
      pullRequest.head.repo.owner.login,
      pullRequest.head.repo.clone_url,
      pullRequest.head.ref
    )

    return repository
  }
