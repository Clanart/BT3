### Title
`SignableTransaction::new` undercounts vbytes when an OP_RETURN `data` output is present, so the deducted/budgeted fee is computed before the full transaction is known and produces an under-funded transaction — ([File: networks/bitcoin/src/wallet/send.rs])

### Summary
The bug class of the external report — "a fee is deducted/budgeted against a not-yet-final transaction size, so a valid party who funds the exact computed amount cannot complete the action" — maps onto `SignableTransaction::new`. The weight/vbytes used to derive `needed_fee` (and the minimum-relay check) are calculated from `payments` only, but the actual transaction additionally includes an OP_RETURN output whenever `data` is `Some`. A caller who supplies inputs totaling exactly `payment + needed_fee` gets a transaction whose real fee rate is below the requested `fee_per_vbyte` — and potentially below the Bitcoin minimum relay fee — so the signed transaction is not spendable/relayable as constructed.

### Finding Description
In `SignableTransaction::new`, the OP_RETURN output is pushed onto `tx_outs` (send.rs:194-202), but the fee sizing call uses `payments`, not `tx_outs`:

- `let (mut weight, vbytes) = Self::calculate_weight_vbytes(tx_ins.len(), payments, None);` — send.rs:204
- `needed_fee = fee_per_vbyte * vbytes;` — send.rs:206
- The minimum relay check also uses this same undercounted `vbytes` — send.rs:211
- The change path repeats the omission: `calculate_weight_vbytes(tx_ins.len(), payments, Some(&change))` — send.rs:226

Inside `calculate_weight_vbytes`, the dummy transaction's `output` vector is built exclusively from `payments` (send.rs:85-94), so the OP_RETURN output (up to 80 bytes of data plus ~9-11 bytes of output overhead, i.e. roughly 11-91 vbytes) is never included in the fee basis.

The consequence: the fund-sufficiency check `input_sat < payment_sat + needed_fee` (send.rs:215) passes for a caller who funds exactly `payment + needed_fee`, but the final transaction is larger than the one measured. The effective fee rate `fee / actual_vsize` is below `fee_per_vbyte`, and because the minimum-relay check at send.rs:211 used the same underestimated `vbytes`, the transaction can pass all of Serai's checks while being below Bitcoin's `DEFAULT_MIN_RELAY_TX_FEE` once broadcast at its true size.

This mirrors the reported bug: the fee is determined before the transaction is final, so a party who funds the exact computed requirement ends up with a transaction that cannot perform its intended action.

### Impact Explanation
An unprivileged user of the bitcoin-serai wallet API calls `SignableTransaction::new` with `data = Some(...)` and funds the inputs for exactly `payments + needed_fee` (no change address, or change that then fails the `checked_sub`/`DUST` test). The resulting signed transaction underpays relative to the requested rate and may fall under the mempool minimum relay fee at its real vsize, causing `send_raw_transaction` rejection and leaving the funds unmovable until a new transaction is built and re-signed. For the threshold-signed context this is worse: inputs are FROST/MuSig-controlled, so a failed broadcast requires a new signing round — the "valid user who only has a certain amount of funds cannot act" outcome of the original report.

### Likelihood Explanation
Reachable by any caller passing `data` (Inscribenments/metadata path) while choosing a low `fee_per_vbyte` near the minimum relay fee and tight input funding — a realistic configuration for cost-sensitive payouts. Deterministic whenever the omitted OP_RETURN weight pushes the true fee rate below the minimum.

### Recommendation
In `SignableTransaction::new`, pass the fully-populated `tx_outs` (or append the OP_RETURN output inside `calculate_weight_vbytes`) to `calculate_weight_vbytes` so both the no-change and with-change fee estimates account for every output that will actually be serialized. Alternatively, add the OP_RETURN output's size to the estimated vbytes before computing `needed_fee` and the minimum-relay check.

### Proof of Concept
```rust
// networks/bitcoin/tests/wallet.rs style
let data = vec![0u8; 80]; // largest permitted OP_RETURN
// Estimate with data:
let tx = SignableTransaction::new(inputs, &payments, Some(change), Some(data), fee_per_vbyte).unwrap();
// tx.needed_fee() was computed from `payments` only (send.rs:204, 226),
// omitting the OP_RETURN output's ~91 vbytes.
// tx.fee() / tx.actual_vsize < fee_per_vbyte; if fee_per_vbyte was the relay
// minimum, the real fee rate is below DEFAULT_MIN_RELAY_TX_FEE and the TX is
// rejected on broadcast despite passing Serai's internal checks.
```
