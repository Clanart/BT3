### Title
`Scanner::scan_block` reports immature coinbase outputs as spendable inputs - (File: `networks/bitcoin/src/wallet/mod.rs`)

### Summary
`Scanner::scan_block` scans every transaction in a block, including `block.txdata[0]`—the coinbase transaction—without checking coinbase maturity. It converts matching coinbase outputs into ordinary `ReceivedOutput` values, which `SignableTransaction::new` then accepts as spendable inputs.

### Finding Description
`scan_block` iterates over `block.txdata` and calls `scan_transaction` for every transaction, including the coinbase transaction at index `0` [1](#0-0) . `scan_transaction` returns a `ReceivedOutput` for any matching `script_pubkey`, recording the transaction outpoint and output value [2](#0-1) . The comment acknowledges that coinbase outputs are maturity-burdened and require post-processing, but the function itself performs no such filtering [3](#0-2) .

`SignableTransaction::new` treats every supplied `ReceivedOutput` as an available input and validates only aggregate value, fee, dust, and transaction-size constraints [4](#0-3) . It has no field representing the block height or maturity status needed to reject a coinbase input [5](#0-4) .

### Impact Explanation
A caller using `scan_block` directly can treat funds as received and spendable before consensus permits them to be spent. The wallet can then construct and threshold-sign a transaction spending an immature coinbase output. That transaction cannot be accepted by the Bitcoin network until the coinbase matures, so the reported funds are not actually spendable. This is a medium-severity accounting and liveness issue rather than direct theft.

### Likelihood Explanation
Any Bitcoin miner can create a block whose coinbase pays to a scanned Serai Taproot script. Mining is permissionless, although the attacker must successfully produce a block. The vulnerable path is exposed whenever callers use the advertised `scan_block` API rather than manually skipping `block.txdata[0]` [1](#0-0) .

### Recommendation
`scan_block` should skip `block.txdata[0]` by default, or `ReceivedOutput` should carry maturity metadata that prevents `SignableTransaction::new` from accepting the output until the required confirmation depth is reached. If a caller needs to observe immature coinbases for accounting, expose that behavior through an explicitly separate API or output classification.

### Proof of Concept
A miner creates a coinbase transaction paying to a script registered in a `Scanner`. Calling `scanner.scan_block(&block)` returns the coinbase output as a `ReceivedOutput` [6](#0-5) . Passing that value to `SignableTransaction::new` succeeds because the constructor uses `input.output.value` as spendable input value and performs no maturity check [7](#0-6) . `multisig` then creates a transaction-signing machine for the resulting `SignableTransaction` without checking whether the selected outpoint is mature [8](#0-7) .

  /// Scan a transaction.
  pub fn scan_transaction(&self, tx: &Transaction) -> Vec<ReceivedOutput> {
    let mut res = Vec::new();
    for (vout, output) in tx.output.iter().enumerate() {
      // If the vout index exceeds 2**32, stop scanning outputs
      let Ok(vout) = u32::try_from(vout) else { break };

      if let Some(offset) = self.scripts.get(&output.script_pubkey) {
        res.push(ReceivedOutput {
          offset: *offset,
          output: output.clone(),
          outpoint: OutPoint::new(tx.compute_txid(), vout),
        });
      }
