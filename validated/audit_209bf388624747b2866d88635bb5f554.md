### Title
Untrusted `ThresholdKeys::read` input can trigger quadratic Lagrange interpolation and exhaust CPU - (File: `crypto/dkg/src/lib.rs`)

### Summary
`ThresholdKeys::read` accepts attacker-controlled `t`, `n`, and `interpolation` fields before constructing `ThresholdKeys`. [1](#0-0)  For a serialized key with Lagrange interpolation and `t = n = u16::MAX`, `ThresholdKeys::new` computes one interpolation factor for each of the 65,535 initial participants. [2](#0-1)  Each Lagrange interpolation factor loops over every included participant, producing approximately 4.3 billion field operations from an input only a few megabytes in size. [3](#0-2) 

### Finding Description
The deserializer reads `t`, `n`, participant index `i`, and the interpolation variant directly from the input. [1](#0-0)  It then reads `n` verification shares and passes all attacker-controlled parameters to `ThresholdKeys::new`. [4](#0-3) 

`ThresholdParams::new` permits `t == n`, including the maximum `65535`, so long as `i <= n`. [5](#0-4)  `ThresholdKeys::new` calculates the group key by evaluating `interpolation_factor` for participants `1..=t`. [2](#0-1)  For `Interpolation::Lagrange`, every factor iterates over all included participants, so the total work is quadratic in `t`. [3](#0-2) 

### Impact Explanation
A service that deserializes untrusted `ThresholdKeys` can be driven into a long-running, CPU-bound computation with a relatively small serialized object. The attacker-controlled workload is roughly `65535 * 65534` multiplication/subtraction/inversion-dependent Lagrange operations, before the group-element additions and scalar multiplication are performed. [3](#0-2) [2](#0-1) 

This is an availability impact analogous to the referenced vulnerability class: hostile input causes excessive resource consumption and can render the handling thread or process unavailable.

### Likelihood Explanation
Exploitation requires an attacker to supply serialized `ThresholdKeys` to an exposed `ThresholdKeys::read` path. The byte stream does not need valid threshold shares or a meaningful group key; it only needs canonical scalar and point encodings and parameters satisfying `t <= n`. [6](#0-5)  The maximum declared size is only `u16::MAX`, making the trigger simple to construct.

### Recommendation
Enforce a protocol-appropriate maximum `t`/`n` before reading or interpolating coefficients and verification shares. Reject threshold parameters above that bound in `ThresholdKeys::read`, and ideally before allocating or reading `n` group elements. [7](#0-6)  If arbitrary large threshold parameters must remain representable, derive the group key without evaluating independent Lagrange bases, or make construction lazy so deserialization does not perform quadratic work.

### Proof of Concept
Conceptually, construct a serialized `ThresholdKeys` object using:

```text
curve_id_length || curve_id
t = 0xffff
n = 0xffff
i = 0x0001
interpolation = 0x01  // Lagrange
secret_share = canonical zero scalar
verification_shares = canonical generator encoding repeated 65535 times
```

When passed to `ThresholdKeys::<C>::read`, deserialization succeeds to the point of calling `ThresholdKeys::new`; `ThresholdKeys::new` then evaluates 65,535 Lagrange interpolation factors, each scanning 65,535 participants. [4](#0-3) [2](#0-1) 

A minimal Rust-shaped trigger is:

```rust
let mut bytes = Vec::new();

// Use the target curve's serialized ID and canonical encodings.
bytes.extend_from_slice(&(C::ID.len() as u32).to_le_bytes());
bytes.extend_from_slice(C::ID);

bytes.extend_from_slice(&u16::MAX.to_le_bytes()); // t
bytes.extend_from_slice(&u16::MAX.to_le_bytes()); // n
bytes.extend_from_slice(&1u16.to_le_bytes());     // i
bytes.push(1);                                    // Lagrange

bytes.extend_from_slice(C::F::ZERO.to_repr().as_ref());
for _ in 0 .. u16::MAX {
  bytes.extend_from_slice(C::generator().to_bytes().as_ref());
}

let _ = ThresholdKeys::<C>::read(&mut bytes.as_slice());
```

The resulting workload is quadratic in the attacker-selected participant count rather than merely proportional to the input length.
