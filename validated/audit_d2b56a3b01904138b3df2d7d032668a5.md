### Title
Division-by-zero panic in `DelegateVoteRewardPool._updateVote` causes DoS on voting/staking for the delegated pool - ([File: rewards/DelegateVoteRewardPool.sol])

### Summary
`DelegateVoteRewardPool._updateVote()` divides by `totalWeight` without any zero-check. `totalWeight` starts at `0` and is only ever changed via the owner-only `updateWeight` function, so any user-triggered call into `stakeFor`/`withdrawFor` (which both call `_updateVote()`) reverts with a division-by-zero panic whenever `totalWeight == 0`. This is functionally the same bug class as the reported `distributeRewards` issue (missing zero-check on the divisor causing a panic revert / DoS), but it is present here, unguarded, and reachable by ordinary wallets.

### Finding Description
`_updateVote()` computes, for every registered vote pool, `targetVote = (votingWeights[pool] * totalSupply) / totalWeight`: [1](#0-0) 

`totalWeight` is only mutated inside the owner-only `updateWeight` function: [2](#0-1) 

`_updateVote()` is unconditionally invoked from both `stakeFor` and `withdrawFor`, which are the functions the `WombatBribeManager` (the `operator`) calls whenever an ordinary user votes/unvotes with vlMGP for the delegated pool: [3](#0-2) 

The unprivileged entry point is `WombatBribeManager.vote()` (and `unvote()`), which any vlMGP holder can call to route votes into a pool's rewarder (potentially the `delegatedPool`, which is a `DelegateVoteRewardPool`): [4](#0-3) 

If `votePools.length > 0` (i.e., at least one pool has been registered via `updateWeight`) while `totalWeight == 0` — e.g., because the only configured `votingWeights[pool]` were later reduced back to 0, or a pool's weight was set to 0 leaving `totalWeight` at 0 while `votePools` is non-empty — every subsequent `vote()`/`unvote()` call that routes through the delegated pool will divide by zero in `_updateVote()` and revert. Note that by contrast, `MasterMagpie.updatePool()` explicitly guards the analogous `totalAllocPoint == 0` case: [5](#0-4) 

showing the team is aware of and has patched this bug class elsewhere in the codebase, but the same protection is missing in `DelegateVoteRewardPool._updateVote()`.

### Impact Explanation
Once `totalWeight` is `0` while `votePools` is non-empty, every user attempting to stake/withdraw vlMGP votes through the `delegatedPool` (via `WombatBribeManager.vote`/`unvote`) will have their transaction revert. This blocks all users from voting, unvoting, or withdrawing their vote allocation through the delegated pool, effectively freezing their ability to manage voting power and any associated unclaimed bribe rewards tied to that state transition, until the condition is resolved.

### Likelihood Explanation
The condition is reachable through the normal owner workflow of managing `votingWeights` (reducing a weight to 0, or removing weight allocation), which is a plausible, non-malicious operational state, and once triggered, is exploitable purely through ordinary user transactions (`vote`/`unvote`) with no special privileges required to trigger the revert.

### Recommendation
Add an explicit zero check on `totalWeight` in `_updateVote()` (e.g., skip the vote update or treat `targetVote` as `0` when `totalWeight == 0`), mirroring the guard already used in `MasterMagpie.updatePool()` for `totalAllocPoint == 0`.

### Proof of Concept
1. Owner calls `updateWeight(lpA, 100)`, registering `lpA` into `votePools` with `totalWeight = 100`.
2. Owner later calls `updateWeight(lpA, 0)`, which sets `votingWeights[lpA] = 0` and recomputes `totalWeight = totalWeight - 100 + 0 = 0` (per `rewards/DelegateVoteRewardPool.sol:215`), while `lpA` remains in `votePools`.
3. Any user with vlMGP calls `WombatBribeManager.vote()` (or `unvote()`) targeting the delegated pool.
4. This routes into `DelegateVoteRewardPool.stakeFor`/`withdrawFor`, which calls `_updateVote()`.
5. Inside `_updateVote()`, `(votingWeights[pool] * totalSupply) / totalWeight` divides by `totalWeight == 0`, causing a Solidity panic revert, blocking the user's transaction and all subsequent votes/withdrawals through this pool.

        int256[] memory deltas = new int256[](length);

            address pool = votePools[index];
