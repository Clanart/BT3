### Title
Scanner reports immature coinbase outputs as spendable funds - (File: networks/bitcoin/src/wallet/mod.rs)

### Summary
`Scanner::scan_block` scans `block.txdata[0]` — the coinbase transaction — identically to every other transaction and returns its matching outputs as `ReceivedOutput`s. Coinbase outputs are unspendable for 100 blocks (COINBASE_MATURITY), yet nothing in `scan_block`, `scan_transaction`, or `ReceivedOutput` records whether an output came from a coinbase or at what height it was found. A miner who pays to a scanned script pubkey causes the wallet to report funds received that are not actually spendable.

### Finding Description
`scan_transaction` iterates `tx.output`, matches `output.script_pubkey` against registered scripts, and pushes a `ReceivedOutput` containing only `offset`, `output`, and `outpoint` — with no coinbase/maturity metadata (networks/bitcoin/src/wallet/mod.rs:199-214). `scan_block` iterates `&block.txdata` unconditionally, including `txdata[0]` (the coinbase), and merely leaves a comment stating "a post-processing pass is needed" if outputs must be immediately spendable (mod.rs:216-227). There is no `is_coinbase()` check anywhere in `networks/bitcoin/src` — the only maturity-adjacent logic is in the test harness, which mines 100 blocks before spending.

Downstream, `SignableTransaction::new` accepts any `ReceivedOutput` as input (send.rs:150-186) and the signing machines produce a fully signed transaction spending it (send.rs:373-398). Bitcoin consensus rejects any transaction spending a coinbase output younger than 100 blocks, so the produced transaction is invalid regardless of signature validity.

### Impact Explanation
An unprivileged party who mines a block (no special privileges required — any miner, or anyone paying a miner via fees) can include a P2TR output paying a scanned multisig script in their coinbase transaction. `scan_block` reports it as a normally received output. Funds are reported received that are not spendable: any spend built on this input fails consensus validation (`bad-txns-premature-spend-of-coinbase`), and balance accounting overstates immediately available funds. This is the direct analog of the oracle-clamping bug class: an external data source (the block/transaction supply) produces a value outside the valid range (an immature output), and the consumer uses it without checking it against the applicable bound (coinbase maturity).

### Likelihood Explanation
Deterministic for any block containing a coinbase payment to a scanned key. Miners routinely control coinbase outputs, and any mining pool participant or fee-incentivized miner can craft such a payment. The only mitigation is an out-of-scope integrator remembering to post-filter `scan_block` results or call `scan_transaction` on `block.txdata[1 ..]` — the API itself provides no indicator distinguishing coinbase outputs, making correct filtering impossible from the returned `ReceivedOutput` alone (the outpoint's txid can be looked up, but nothing in the type marks it).

### Recommendation
In `Scanner::scan_block` (or `scan_transaction`), skip `txdata[0]` when `tx.is_coinbase()`, or record maturity metadata on `ReceivedOutput` (e.g., a `matures_at: Option<u64>` field populated from the block height) and reject immature inputs in `SignableTransaction::new`. At minimum, `scan_block` should take the block height and only return coinbase outputs once they are at least 100 confirmations deep.

### Proof of Concept
```rust
// Regtest: key is the tweaked multisig key
let scanner = Scanner::new(key).unwrap();
let script = p2tr_script_buf(key).unwrap();

// A miner mines a block paying the multisig via the coinbase
let block = rpc.get_block(&rpc.get_block_hash(height).await.unwrap()).await.unwrap();
assert!(block.txdata[0].is_coinbase());

// scan_block returns the coinbase output with no maturity indication
let outputs = scanner.scan_block(&block);
assert_eq!(outputs.len(), 1);
let received = outputs[0].clone();

// Building a spend succeeds and produces a fully-signed transaction
let signable = SignableTransaction::new(
  vec![received],
  &[(dest_script, 1000)],
  None, None, 1,
).unwrap();
// ... FROST signing completes ...
// Broadcasting fails: bad-txns-premature-spend-of-coinbase
```
The library's own test acknowledges this: `send_and_get_output` in networks/bitcoin/tests/wallet.rs:40-78 mines 100 additional blocks before spending precisely because the scanned coinbase output is otherwise unspendable — confirming `scan_block` itself performs no maturity filtering.
