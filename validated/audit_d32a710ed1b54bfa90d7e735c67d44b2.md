### Title
Attacker can front-run `DelegateVoteRewardPool.harvestAll()` with a self-directed `vote()` to steal a disproportionate share of harvested bribes via reward-index dilution - ([File: rewards/DelegateVoteRewardPool.sol])

### Summary
`harvestAll()` has no access control and can be called by anyone at an attacker-chosen block. An attacker who already holds vlMGP voting power can redirect it into the `delegatedPool` slot (`vote()` → `stakeFor()`), immediately call `harvestAll()` to crystallize bribes that were earned by the pool's pre-existing (long-term) voters, and then `unvote()` to both reclaim their vlMGP and extract a reward slice proportional to their newly-inflated share of `totalSupply`, none of which they earned time-wise.

### Finding Description
`harvestAll()` is `external` with no modifier restricting the caller: [1](#0-0) . It fetches a lump-sum of already-accrued bribe rewards via `IWombatBribeManager(operator).claimAllBribes(address(this))` and passes them to `_manageRewards`.

`_manageRewards` forwards the lump sum to `_queueNewRewardsWithoutTransfer`, which spreads the reward over the **current** `totalSupply` at call time: [2](#0-1) .

An attacker who holds (or controls) vlMGP voting power can call `WombatBribeManager.vote()` targeting the `delegatedPool` entry, which calls `IBribeRewardPool(pool.rewarder).stakeFor(msg.sender, delta)` — i.e. `DelegateVoteRewardPool.stakeFor`: [3](#0-2) . `stakeFor` checkpoints the attacker's `userRewardPerTokenPaid` at the *current* `rewardPerTokenStored` **before** incrementing `totalSupply`/`_balances`: [4](#0-3) .

The attacker then calls `harvestAll()` immediately in the same transaction. Because the reward lump sum (accrued by the pool's pre-existing votes over elapsed time) is now divided by the inflated `totalSupply` that includes the attacker's freshly-added stake, the attacker's checkpoint delta (`new rewardPerTokenStored - old rewardPerTokenStored at stake time`) is nonzero and multiplied by their stake, giving them real earned rewards despite contributing zero time-weighted voting. The attacker then calls `unvote()` → `withdrawFor(attacker, X, true)`, which calls `_getReward` to pay out this reward and removes their stake: [5](#0-4)  and [6](#0-5) .

No existing check prevents this: there is no minimum staking duration, no snapshot of `totalSupply` prior to reward distribution, and `harvestAll()` is not restricted to be called only through the intended `castVotes()` flow (`castVotes()` also invokes it unconditionally at line 293 of `WombatBribeManager.sol`, but nothing stops an attacker from invoking `harvestAll()` directly and out of band). [7](#0-6) 

### Impact Explanation
This is a theft of unclaimed yield: the attacker extracts a share of bribe rewards that were earned by other, long-term voters who kept their vlMGP allocated to `delegatedPool` over time. Each cycle dilutes legitimate holders' `rewardPerTokenStored` accrual and diverts value to the attacker, repeatable every time new bribes are queued/harvested.

### Likelihood Explanation
The attacker needs to already control some vlMGP voting power (not flash-loanable within a single transaction since locking is a stateful action tracked by `VLMGP`), but does **not** need new capital to execute the exploit itself — they can simply redirect their existing locked voting allocation into `delegatedPool` for one block, harvest, and immediately move it back. `vote()`, `harvestAll()`, and `unvote()` are all public/external with no cooldown, so the full sequence can be atomically executed from a single attacker-controlled contract, making it cheap (gas-only) and repeatable every time a nontrivial reward batch is pending.

### Recommendation
- Snapshot `totalSupply` and per-user balances used for reward-index distribution using a mechanism that excludes stakes added in the same block/epoch as the harvest (e.g., checkpoint balances prior to `harvestAll`, or require a minimum holding period before a stake is eligible for a given reward distribution).
- Restrict `harvestAll()` so it can only be invoked as part of `castVotes()` (e.g., `onlyOperator` or a check that `msg.sender == operator`), removing the attacker's ability to choose an arbitrary block to front-run distribution.
- Consider a cooldown between `vote()`-driven stake increases and reward eligibility, or a pull-based accounting model that pro-rates rewards by time-weighted stake rather than instantaneous `totalSupply`.

### Proof of Concept
Foundry test plan:
1. Deploy `WombatBribeManager`, `DelegateVoteRewardPool`, and mock `votePools`/bribe rewarders; set up `delegatedPool` and register it with `addPool`.
2. Have a "long-term voter" lock vlMGP and `vote()` for `delegatedPool` well before any bribes accrue; simulate time passage and a `castVotes()` call that queues bribe rewards into the underlying votePool's `BribeRewardPool`.
3. From an attacker EOA/contract holding a separate vlMGP lock, call `vote([delegatedPool], [+X])` to stake into `DelegateVoteRewardPool`.
4. In the same transaction, call `DelegateVoteRewardPool.harvestAll()` directly (not via `castVotes()`).
5. Immediately call `unvote(delegatedPool)` to withdraw and claim reward.
6. Assert: attacker's claimed reward > 0 despite zero elapsed staking time, and long-term voter's effective `rewardPerTokenStored`-based entitlement is measurably lower than it would have been absent the attacker's flash stake (i.e., total distributed reward to the attacker is disproportionate to a time-weighted entitlement of `0`).

    function _queueNewRewardsWithoutTransfer(
        uint256 _amountReward,
        address _rewardToken
    ) internal {
        if (!isRewardToken[_rewardToken]) {
            rewardTokens.push(_rewardToken);
            isRewardToken[_rewardToken] = true;
        }
        Reward storage rewardInfo = rewards[_rewardToken];
        rewardInfo.historicalRewards =
            rewardInfo.historicalRewards +
            _amountReward;
        if (totalSupply == 0) {
            rewardInfo.queuedRewards += _amountReward;
        } else {
            if (rewardInfo.queuedRewards > 0) {
                _amountReward += rewardInfo.queuedRewards;
                rewardInfo.queuedRewards = 0;
            }
            rewardInfo.rewardPerTokenStored =
                rewardInfo.rewardPerTokenStored +
                (_amountReward * 10 ** this.stakingDecimals()) /
                totalSupply;
        }
        emit RewardAdded(_amountReward, _rewardToken);
    }

        if (_lps.length != _deltas.length)
            revert LengthMismatch();

        uint256 length = _lps.length;
        int256 totalUserVote;

        for (uint256 i; i < length; i++) {
            Pool storage pool = poolInfos[_lps[i]];
            if (!pool.isActive)
                revert PoolNotActive();
            int256 delta = _deltas[i];
            totalUserVote += delta;
            if (delta != 0) {
                if (delta > 0) {
                    pool.totalVoteInVlmgp += uint256(delta);
                    userVotedForPoolInVlmgp[msg.sender][pool.poolAddress] += uint256(delta);
                    IBribeRewardPool(pool.rewarder).stakeFor(msg.sender, uint256(delta));
                } else {
                    pool.totalVoteInVlmgp -= uint256(-delta);
                    userVotedForPoolInVlmgp[msg.sender][pool.poolAddress] -= uint256(-delta);
                    IBribeRewardPool(pool.rewarder).withdrawFor(msg.sender, uint256(-delta), false);
                }
            }
        }

        if (msg.sender != delegatedPool) {
            if (totalUserVote > 0) {
                userTotalVotedInVlmgp[msg.sender] += uint256(totalUserVote);
                totalVlMgpInVote += uint256(totalUserVote);
            } else {
                userTotalVotedInVlmgp[msg.sender] -= uint256(-totalUserVote);
                totalVlMgpInVote -= uint256(-totalUserVote);
            }
        }

        if (userTotalVotedInVlmgp[msg.sender] > getUserVotable(msg.sender))
            revert NotEnoughVote();
    }

    /// @notice Unvote from an inactive pool. This makes it so that deleting a pool, or changing a rewarder doesn't block users from withdrawing
    function unvote(address _lp) public {
        Pool storage pool = poolInfos[_lp];
        uint256 currentVote = userVotedForPoolInVlmgp[msg.sender][pool.poolAddress];
        if(!pool.isActive)
            revert PoolNotActive();
        
        pool.totalVoteInVlmgp -= uint256(currentVote);
        userTotalVotedInVlmgp[msg.sender] -= uint256(currentVote);
        userVotedForPoolInVlmgp[msg.sender][pool.poolAddress] = 0;
        if (msg.sender != delegatedPool) {
            totalVlMgpInVote -= currentVote;
        }
        
        IBribeRewardPool(pool.rewarder).withdrawFor(msg.sender, uint256(currentVote), true);
    }
