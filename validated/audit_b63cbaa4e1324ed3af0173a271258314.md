### Title
Payout OP_RETURN operator attribution is unsigned, allowing reimbursement-credit hijacking via `SinglePlusAnyoneCanPay` signature reuse - (File: core/src/operator.rs, core/src/builder/transaction/operator_reimburse.rs)

### Summary
`HolographOperator.executeJob`'s bug class is "value moves, but the party who should be credited/refunded for that movement is not," due to an unsigned/unchecked linkage between the value transfer and the attribution record. In Clementine, the payout transaction that fronts a withdrawal binds the *paid amount* to the user's output with a `SIGHASH_SINGLE | SIGHASH_ANYONECANPAY` signature, but leaves the `OP_RETURN` output (which records **which operator** should later be reimbursed) completely outside the signed message. That signature — once revealed (e.g. by being broadcast to the Bitcoin mempool by the legitimate operator) — can be reused by anyone to build a competing transaction with the same paid-out amount but an attacker-chosen `OP_RETURN`, hijacking the reimbursement attribution.

### Finding Description
`Operator::withdraw` verifies the user's `in_signature` only against the input and a single corresponding output: [1](#0-0) 

The transaction template itself is built by `create_payout_txhandler`, whose only signed input is `SpendPath::KeySpend` over output index 0 (the user payout), while output index 2 (`op_return_txout`, carrying the fronting operator's x-only pubkey) is appended without being part of the same sighash commitment for `SIGHASH_SINGLE|ANYONECANPAY`: [2](#0-1) 

Because the signature is `SinglePlusAnyoneCanPay` (explicitly required per the error message in `operator.rs`), it commits only to: (a) the single signed input (the dust withdrawal UTXO) and (b) the output at the same index (the user's payout). It does **not** commit to the funding inputs added via `fund_raw_transaction` (which is how the operator actually funds the withdrawal amount) nor to the `OP_RETURN` output that records the operator's identity for reimbursement: [3](#0-2) 

Downstream, the chain-observer (verifier) determines who gets credited for a payout purely by parsing this unsigned `OP_RETURN`: [4](#0-3) 

and persists it as the authoritative payer for reimbursement: [5](#0-4) 

Once an honest operator broadcasts its payout transaction (even before confirmation, as soon as it is relayed on the Bitcoin P2P network / visible in mempools), the full transaction — including the witness signature — becomes public. An unprivileged party can then construct a new transaction that reuses the exact same signed input/output pair (valid under `ANYONECANPAY`), attaches its **own** funding input(s) to cover the actual withdrawal payment, and its own `OP_RETURN` naming an arbitrary x-only pubkey as the "payer operator," then get it mined ahead of (or in place of) the honest operator's transaction via a higher fee.

This breaks the binding **the operator credited == the operator that fronted the payout**, matching the report's "operator loses sent funds it committed" bug class.

### Impact Explanation
Two concrete negative outcomes follow from this attribution hijack, both directly enumerated in the impact taxonomy:
1. If the attacker inserts a pubkey that is not a valid, collateralized operator, the withdrawal is marked handled/paid (the user is satisfied), but `validate_payer_is_operator` / `get_reimbursement_txs` will never find a legitimate kickoff/round pipeline for that fake pubkey — the withdrawal becomes reimbursement-dead: [6](#0-5) . This matches "an honest operator permanently unable to be reimbursed" — the honest operator that intended to front this withdrawal can never do so (the input is already spent) and the pseudo-operator recorded can never legitimately claim reimbursement either.
2. If the attacker instead front-runs with its own registered operator pubkey, it can steal the reimbursement credit that an honest, already-broadcasting operator earned by paying the user, causing that honest operator to lose the BTC it spent funding the payout with no path to recoup it — mirroring the original report's "operator loses sent value with no recovery."

### Likelihood Explanation
Exploitation requires only: (1) observing an in-flight payout transaction on the Bitcoin P2P network/mempool (no privileged role, key, or node access needed — publicly observable data), and (2) constructing/broadcasting a standard, validly-signed Bitcoin transaction reusing the exposed `ANYONECANPAY` signature with a replacement fee-paying input and OP_RETURN. This is a well-known malleability pattern for `SIGHASH_SINGLE|ANYONECANPAY`-signed inputs, and does not require compromising verifiers, operators, or Clementine's own RPC surface at all — it operates purely against the resulting Bitcoin transaction.

### Recommendation
Bind the operator attribution to the signed message so it cannot be substituted after the fact — e.g., commit the fronting operator's x-only pubkey (and/or the `OP_RETURN` output) into the sighash the user signs, or use `SIGHASH_ALL` for a template that is unique per intended operator (requiring a fresh, operator-specific signature from the aggregator/user for each operator attempting to front the payout) instead of a single reusable `SinglePlusAnyoneCanPay` signature that lets fee-paying inputs and attribution outputs be freely swapped by any observer.

### Proof of Concept
Not independently reproduced against a live Clementine deployment (would require constructing a full protocol test harness). Root cause is demonstrated directly by the cited code: `create_payout_txhandler`'s `OP_RETURN` output at index 2 is appended after signature verification of only input 0/output 0 under `SinglePlusAnyoneCanPay` [7](#0-6) , and `Operator::withdraw` verifies exactly that scoped sighash [8](#0-7) , confirming the `OP_RETURN`/funding inputs are unsigned and substitutable by any party who obtains the broadcast transaction.

pub fn create_payout_txhandler(
    input_utxo: UTXO,
    output_txout: TxOut,
    operator_xonly_pk: XOnlyPublicKey,
    user_sig: taproot::Signature,
    _network: bitcoin::Network,
) -> Result<TxHandler<Signed>, BridgeError> {
    let txin = SpendableTxIn::new_partial(input_utxo.outpoint, input_utxo.txout);

    let output_txout = UnspentTxOut::from_partial(output_txout.clone());

    let op_return_txout = op_return_txout(PushBytesBuf::from(operator_xonly_pk.serialize()));

    let mut txhandler = TxHandlerBuilder::new(TransactionType::Payout)
        .with_version(NON_STANDARD_V3)
        .add_input(
            NormalSignatureKind::NotStored,
            txin,
            SpendPath::KeySpend,
            DEFAULT_SEQUENCE,
        )
        .add_output(output_txout)
        .add_output(UnspentTxOut::from_partial(anchor_output(
            NON_EPHEMERAL_ANCHOR_AMOUNT,
        )))
        .add_output(UnspentTxOut::from_partial(op_return_txout))
        .finalize();
    txhandler.set_p2tr_key_spend_witness(&user_sig, 0)?;
    txhandler.promote()
}

    /// Sets the given payout txs' txid and operator index for the given index.
    pub async fn update_payout_txs_and_payer_operator_xonly_pk(
        &self,
        tx: Option<DatabaseTransaction<'_>>,
        payout_txs_and_payer_operator_xonly_pk: Vec<(
            u32,
            Txid,
            Option<XOnlyPublicKey>,
            bitcoin::BlockHash,
        )>,
    ) -> Result<(), BridgeError> {
        if payout_txs_and_payer_operator_xonly_pk.is_empty() {
            return Ok(());
        }
        // Convert all values first, propagating any errors
        let converted_values: Result<Vec<_>, BridgeError> = payout_txs_and_payer_operator_xonly_pk
            .iter()
            .map(|(idx, txid, operator_xonly_pk, block_hash)| {
                Ok((
                    i32::try_from(*idx).wrap_err("Failed to convert payout index to i32")?,
                    TxidDB(*txid),
                    operator_xonly_pk.map(XOnlyPublicKeyDB),
                    BlockHashDB(*block_hash),
                ))
            })
            .collect();
        let converted_values = converted_values?;

        let mut query_builder = QueryBuilder::new(
            "UPDATE withdrawals AS w SET
                payout_txid = c.payout_txid,
                payout_payer_operator_xonly_pk = c.payout_payer_operator_xonly_pk,
                payout_tx_blockhash = c.payout_tx_blockhash
                FROM (",
        );

        query_builder.push_values(
            converted_values.into_iter(),
            |mut b, (idx, txid, operator_xonly_pk, block_hash)| {
                b.push_bind(idx)
                    .push_bind(txid)
                    .push_bind(operator_xonly_pk)
                    .push_bind(block_hash);
            },
        );

        query_builder
            .push(") AS c(idx, payout_txid, payout_payer_operator_xonly_pk, payout_tx_blockhash) WHERE w.idx = c.idx");

        let query = query_builder.build();
        execute_query_with_tx!(self.connection, tx, query, execute)?;

        Ok(())
    }
