### Title
`debug_redact` Field Annotation Is Silently Ignored by ProtoJSON Printing, Allowing Sensitive Fields (e.g., Passwords) to Leak Through Logs That Serialize Messages as JSON - (File: java/util/src/main/java/com/google/protobuf/util/JsonFormat.java, python/google/protobuf/json_format.py)

### Summary
Protobuf provides the `debug_redact` field option specifically to prevent sensitive values (the documented example is literally "sensitive credentials") from appearing in human-readable debug output [1](#0-0) . This invariant is enforced consistently in `TextFormat`/`DebugString` across C++, Java, and other bindings [2](#0-1) [3](#0-2) , but the ProtoJSON printer (`JsonFormat` in Java, `json_format.py` in Python) contains no equivalent check anywhere in its field-printing code path. A consuming application that logs protobuf messages via `JsonFormat.printer().print(message)` (a common practice, e.g., for structured/JSON logging) instead of `TextFormat`/`toString()` will emit fields marked `debug_redact = true` in full, defeating the schema author's explicit redaction intent.

### Finding Description
The `debug_redact` FieldOptions annotation exists precisely to stop credential/PII leakage into logs: its doc comment states "Indicate that the field value should not be printed out when using debug formats, e.g. when the field contains sensitive credentials" [1](#0-0) .

In `TextFormat.Printer` (C++), every field print path funnels through `TryRedactFieldValue`, which checks `GetRedactionState(field)` and substitutes `[REDACTED]` when `redact_debug_string_` is enabled [2](#0-1) . The Java `TextFormat.Printer` has the analogous `shouldRedact` check tied to `field.getRedactionState()` [3](#0-2) , and `Message.DebugString()`/`DebugFormat` wire this in by default via `SetRedactDebugString(true)` [4](#0-3) .

By contrast, searching the entire checkout for any reference to `redact`/`debug_redact`/`GetRedactionState`/`shouldRedact` inside JSON-related printer files (`JsonFormat.java`, `json_format.py`, and the C++ JSON utilities) returns zero matches. The Java `JsonFormat.Printer.printSingleFieldValue` method, which is the code that actually serializes a field's scalar value into the JSON output, contains only type-dispatch logic (INT32, INT64, BOOL, FLOAT, DOUBLE, …) with no redaction branch at all [5](#0-4) . `Printer.appendTo`, the public entry point for `JsonFormat`, likewise has no redaction-related parameter or hook [6](#0-5) .

The failed invariant: "fields annotated `debug_redact = true` must never appear in plaintext in any protobuf-provided debug/human-readable serialization" — an invariant enforced for TextFormat/DebugString but not for ProtoJSON. The attacker-controlled value maps to an ordinary bounded protobuf message (e.g., containing a database password field marked `debug_redact = true`) that a trusted, schema-compliant application constructs and then serializes for logging purposes via the public `JsonFormat`/`json_format` API. There is no size/type/parsing check that could catch this — it is a printer-completeness gap, not a wire-format parsing bug, so it sits squarely in the "missing safety check in a supported public API" category rather than a parser corruption bug.

### Impact Explanation
This mirrors the Yugabyte CVE-2024-0006 pattern exactly at the invariant level: information disclosure of database/user credentials into application logs due to a logging code path that bypasses the intended redaction mechanism [1](#0-0) . Any codebase that has protobuf schemas annotated with `debug_redact = true` for credential fields (the exact scenario the tests in this repo, e.g. `RedactedFields`, model) and that uses `JsonFormat`/`json_format.dumps`/`MessageToJson` for structured logging instead of `TextFormat`/`DebugString` will leak those fields verbatim into logs, files, or downstream log aggregation systems. This is a real confidentiality impact (credential/PII disclosure) reachable purely through supported, documented protobuf APIs with a valid trusted schema — no malicious input or privileged access is required.

### Likelihood Explanation
High likelihood of exposure given the design: `debug_redact` documentation and API naming ("debug formats") do not clearly scope the guarantee to TextFormat only, so developers reasonably expect ProtoJSON output to honor the same annotation, especially since structured JSON logging is now more common than TextFormat logging in many services. The gap is total (not a partial bypass under exotic conditions) — the redaction logic is simply absent from every JSON print/dump function in the tree, in every language binding checked (Java, Python, and no C++ JSON printer redaction references found either).

### Recommendation
Add a `debug_redact` check to the field-value printing path in `JsonFormat.Printer` (Java) — analogous to `TryRedactFieldValue`/`shouldRedact` — invoked wherever `printSingleFieldValue` or the containing per-field print loop iterates `FieldDescriptor`s, substituting a `"[REDACTED]"`-equivalent JSON value when `field.getOptions().getDebugRedact()` (or the message/enum-option-derived sensitivity, per `Descriptors.isOptionSensitive`) is true [7](#0-6) . Apply the equivalent fix to `python/google/protobuf/json_format.py` and any C++ JSON printing utility. At minimum, document prominently that `debug_redact` is TextFormat/DebugString-only and is NOT honored by ProtoJSON, so application authors do not mistakenly rely on it for JSON-based logging.

### Proof of Concept
Given a schema field `string db_password = 1 [debug_redact = true];` (as modeled by `RedactedFields.optional_redacted_string` in the test protos [8](#0-7) ):

1. `TextFormat`/`DebugFormat`: `DebugFormat.multiline().toString(message)` correctly redacts the field, verified by existing tests `messageFormat_debugRedactFieldIsRedacted` [9](#0-8) .
2. `JsonFormat.printer().print(message)` on the same message: since `printSingleFieldValue` and the surrounding field-printing loop in `JsonFormat.java` never consult `FieldDescriptor.getOptions().getDebugRedact()` or `Descriptors.RedactionState`, the plaintext value ("foo"/the password) is emitted directly into the JSON output.

No test in this checkout (`java/util/src/test/java/com/google/protobuf/util/JsonFormatTest.java`) asserts redaction behavior for `JsonFormat`, whereas `DebugFormatTest`/`ProtobufToStringOutputTest` extensively assert redaction for `TextFormat`/`DebugFormat` [10](#0-9) , confirming the redaction test coverage — and by extension the enforced invariant — is absent for the JSON code path.

bool TextFormat::Printer::TryRedactFieldValue(
    const Message& message, const FieldDescriptor* field,
    BaseTextGenerator* generator, bool insert_value_separator) const {
  TextFormat::RedactionState redaction_state =
      DescriptorPool::MemoizeProjection(
          field, [](const FieldDescriptor* field) {
            return TextFormat::GetRedactionState(field);
          });
  if (redaction_state.redact) {
    if (redact_debug_string_) {
      IncrementRedactedFieldCounter();
      if (insert_value_separator) {
        generator->PrintMaybeWithMarker(MarkerToken(), ": ");
      }
      generator->PrintString(kFieldValueReplacement);
      if (insert_value_separator) {
        if (single_line_mode_) {
          generator->PrintLiteral(" ");
        } else {
          generator->PrintLiteral("\n");
        }
      }
      return true;
    }
  }
  return false;
}

    // Lazily calculates the redact state of the field, caching the result.
    RedactionState getRedactionState() {
      RedactionState state = redactionState;
      if (state == null) {
        // If the field is directly marked with debug_redact=true, then it is sensitive.
        synchronized (this) {
          state = redactionState;
          if (state == null) {
            FieldOptions options = getOptions();
            state = RedactionState.of(options.getDebugRedact());
            // Check if the FieldOptions contain any enums that are marked as debug_redact=true,
            // either directly or indirectly via a message option.
            for (Map.Entry<Descriptors.FieldDescriptor, Object> entry :
                options.getAllFields().entrySet()) {
              state =
                  RedactionState.combine(
                      state, isOptionSensitive(entry.getKey(), entry.getValue()));
              if (state.redact) {
                break;
              }
            }
            redactionState = state;
          }
        }
      }
      return state;
    }
