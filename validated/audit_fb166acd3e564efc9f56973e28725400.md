### Title
Premature eviction of shared `PreloadBuffer` entries in `StakingModule` causes state-regeneration failures reachable by unprivileged concurrent RPC calls - ([File: kaiax/staking/impl/preload_buffer.go])

### Summary
The Chrome CVE is a use-after-free caused by destroying a shared object (a browser profile) while another consumer still holds a reference to it. The Kaia analog is a reference-counting bug in `PreloadBuffer`, the in-memory cache that `StakingModule` uses to keep `StakingInfo` for state roots that exist only transiently during state regeneration (reexec). A second, legitimate consumer of a cached entry is never registered as a reference holder, so the first consumer's cleanup can destroy the entry while the second consumer is still relying on it — mirroring "destruction while still referenced" from the original bug class.

### Finding Description
`PreloadBuffer.PreloadFromState` is supposed to register the caller's `refId` against a cached `StakingInfo` entry so the entry survives until every referencing caller releases it: [1](#0-0) 

If the entry for `root` already exists (checked with only an `RLock`), the function returns immediately **without adding the caller's `refId` to `refs`**: [2](#0-1) 

Meanwhile, `FreeRefId` deletes a given `refId` from every entry's `refs` set and deletes the entry entirely once its `refs` set becomes empty: [3](#0-2) 

So if consumer A creates the entry (and is the sole registered ref), and consumer B later calls `PreloadFromState` for the same root while A's regen loop is still running, B takes the "already stored, return nil" fast path and is never recorded as a ref holder. When A finishes and calls `FreePreloadRef` (deferred in the RPC-facing regen routine), the shared entry is deleted even though B still needs it: [4](#0-3) 

This buffer exists specifically because the corresponding trie nodes for these intermediate roots are proactively dereferenced from the in-memory trie cache in the same loop and are not persisted to disk: [5](#0-4) [6](#0-5) 

Once B's entry is prematurely evicted, `GetInfo` returns `nil` and the code falls back to reading the pruned trie root from disk, which will fail because the state was never committed to disk: [7](#0-6) 

The buffer's own doc comment confirms `StakingInfo` derived here feeds directly into consensus-relevant reward computation for post-Kaia `engine.Finalize()`: [8](#0-7) [9](#0-8) 

### Impact Explanation
Any unprivileged public-RPC caller that triggers historical state regeneration (e.g. `debug_traceTransaction`, `debug_traceBlockByNumber`, or historical `eth_getBalance`/`eth_call` requests that go through `stateAtBlock`) allocates its own `refId` and drives the same shared `PreloadBuffer`. By issuing two or more overlapping regen requests that pass through the same historical block range, an attacker can trigger the missing-registration race so that one session's cleanup evicts a cache entry the other session still depends on. The affected `GetStakingInfo` lookup then fails with a missing-trie-node style error instead of succeeding, because the corresponding state was intentionally pruned from the live trie cache and only the (now-deleted) preload buffer held it. Because this exact code path underlies staking info used by reward distribution logic tied to `engine.Finalize()`, the failure mode is a state-computation error that is timing-dependent — the same historical query can succeed or fail depending on unrelated concurrent RPC traffic, which is a state-consistency risk rather than deterministic behavior expected of consensus-adjacent logic.

### Likelihood Explanation
Triggering it only requires the ability to issue standard historical-state RPC calls (`debug_trace*`/archival `eth_*` calls) concurrently — no special privileges, staking, or governance role is needed. Any node that supports historical state queries (typical for archive/full nodes serving public RPC) is reachable this way. The race window is proportional to the duration of the state regen loop, which for a several-block gap can be non-trivial, making concurrent hits achievable by simply firing overlapping requests.

### Recommendation
In `PreloadFromState`, always register the caller's `refId` in the entry's `refs` map, including on the fast path where the entry already exists (acquire the write lock, or promote from read to write lock, before returning), so that reference counting correctly reflects every active consumer of a given cached state root before it can be evicted.

### Proof of Concept
1. Prune historical state trie nodes for a block range (as done in `tests/state_reexec_test.go`) so a state query for those blocks requires `stateAtBlock` reexec.
2. Issue two concurrent RPC calls (e.g. two `debug_traceBlockByNumber` calls, or one archival query overlapping a running `engine.Finalize` regen) that both need `StakingInfo` for the same intermediate historical root within the pruned range.
3. Let request A finish first: its `defer cn.stakingModule.FreePreloadRef(preloadRef)` (`node/cn/state_accessor.go:148`) runs and calls `FreeRefId`, which deletes the shared `preloaded[root]` entry because request B was never registered in `refs` (it hit the early-return path in `PreloadFromState`).
4. Request B subsequently calls `GetInfo(root)` for the same root (via `getFromStateByNumber`) and gets `nil`, falls back to `s.Chain.StateAt(header.Root)`, which fails because the corresponding trie nodes were already dereferenced — producing an error for a state query that should have succeeded, purely due to unrelated concurrent RPC activity.

func (ss *PreloadBuffer) FreeRefId(refId uint64) {
	ss.mu.Lock()
	defer ss.mu.Unlock()

	for root, state := range ss.preloaded {
		delete(state.refs, refId) // delete reference
		if len(state.refs) == 0 { // no more references
			delete(ss.preloaded, root)
		}
	}
}

func (s *StakingModule) PreloadFromState(refId uint64, header *types.Header, statedb *state.StateDB) error {
	ss := s.preloadBuffer
	root := statedb.IntermediateRoot(false)
	// Sanity check
	if header.Root != root {
		return fmt.Errorf("header root mismatch: %s != %s", header.Root, root)
	}

	// Quickly check if the info is already stored.
	ss.mu.RLock()
	_, ok := ss.preloaded[root]
	ss.mu.RUnlock()
	if ok {
		return nil
	}

func (s *StakingModule) getFromStateByNumber(num uint64) (*staking.StakingInfo, error) {
	header := s.Chain.GetHeaderByNumber(num)
	if header == nil {
		return nil, fmt.Errorf("failed to get header for block number %d", num)
	}

	// If found in side state, no bother getting from the state.
	if si := s.preloadBuffer.GetInfo(header.Root); si != nil { // Try side state
		return si, nil
	}

	// Otherwise bring up the state from the database.
	statedb, err := s.Chain.StateAt(header.Root)
	if err != nil {
		return nil, fmt.Errorf("failed to get state for block number %d: %w", num, err)
	}
	return s.getFromState(header, statedb)
