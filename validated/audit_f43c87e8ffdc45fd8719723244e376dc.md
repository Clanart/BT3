### Title
Unchecked u64 sums over attacker-supplied `ReceivedOutput` values overflow in `SignableTransaction::new`/`fee` - (File: networks/bitcoin/src/wallet/send.rs)

### Summary
`SignableTransaction::new` sums `input.output.value.to_sat()` over untrusted `ReceivedOutput`s with plain `u64` addition (`sum::<u64>()`), and later compares `input_sat < payment_sat + needed_fee` — also plain addition. `ReceivedOutput::read` deserializes the `TxOut` (including the full 8-byte `value`) from untrusted bytes with no bound check. Crafted input values can wrap `input_sat`, bypassing the `NotEnoughFunds` check and producing a transaction whose committed prevout/output arithmetic is inconsistent with what `fee()` later computes, causing the multisig to sign a malformed transaction.

### Finding Description
`ReceivedOutput::read` (networks/bitcoin/src/wallet/mod.rs:122-134) consensus-decodes a `TxOut` from a reader, so `output.value` is an arbitrary `u64` chosen by whoever supplies the bytes. These flow into `SignableTransaction::new`:

- `let input_sat = inputs.iter().map(|input| input.output.value.to_sat()).sum::<u64>();` (send.rs:175) — unchecked sum.
- `let payment_sat = payments.iter().map(|payment| payment.1).sum::<u64>();` (send.rs:187) — unchecked sum.
- `if input_sat < (payment_sat + needed_fee)` (send.rs:215) — unchecked `+`.
- `input_sat.checked_sub(payment_sat + fee_with_change)` (send.rs:228) — the inner `payment_sat + fee_with_change` is unchecked.
- `fee()` computes `sum(prevouts) - sum(outputs)` (send.rs:139-140) — unchecked `-`.

In release builds (`overflow-checks` off) wrapping two large crafted input values (e.g., `u64::MAX - k` each) yields a wrapped `input_sat` that is still large enough to pass the `NotEnoughFunds` check, while `payment_sat + fee_with_change` can independently wrap so `checked_sub` produces a nonsensical change `value` pushed as a real `TxOut` (send.rs:230). The resulting `SignableTransaction` is signed via `TransactionSignMachine::sign`, which commits to `Prevouts::All(&self.tx.prevouts)` — the crafted amounts — in the Taproot sighash (send.rs:373-390).

### Impact Explanation
The threshold group signs a transaction whose prevout amounts and/or change output do not correspond to real spendable funds: the signed transaction is unbroadcastable/invalid (negative or inconsistent fee), yet a signature share was produced and aggregated — an unintended message signed by the multisig and a DoS of the signing pipeline. This is the direct analog of the report's "delta computed with unchecked integer arithmetic": sums and differences over untrusted `u64` values are computed without overflow checks, corrupting every downstream invariant (`NotEnoughFunds`, dust/change logic, `fee()`).

### Likelihood Explanation
Reachability requires untrusted bytes into `ReceivedOutput::read` (an explicitly in-scope untrusted-read API) plus enough such inputs to wrap the sum — two outputs suffice, since each can carry `u64::MAX` in the decoded `TxOut`. No on-chain funds are needed; the values are pure serialized bytes. The wrapping path only manifests in release builds (debug panics), which is precisely the deployment mode. Severity is Medium: it yields signing of a malformed transaction rather than fund theft, since the forged amounts cannot confirm on-chain.

### Recommendation
- Bound-check decoded `TxOut::value` in `ReceivedOutput::read` (e.g., reject values above `MAX_MONEY` = 21e14 sats).
- Use `checked_add`/`checked_sum` for `input_sat`, `payment_sat`, `payment_sat + needed_fee`, and `payment_sat + fee_with_change`, returning a `TransactionError` on overflow.
- Use `checked_sub` in `fee()`.
