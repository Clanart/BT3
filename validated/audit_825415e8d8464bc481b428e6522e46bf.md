### Title
Unbounded Python recursion in wallet outer-puzzle driver matching enables stack-overflow DoS via a crafted offer/coin spend - ([File: chia/wallet/outer_puzzles.py])

### Summary
The yasm CVE describes a stack overflow in a recursive expression parser (`parse_expr1`) triggered by attacker-supplied, deeply nested input. Chia's wallet-side outer-puzzle "driver" layer contains an analogous class of bug: `match_puzzle()` and the `get_inner_puzzle()`/`construct()` methods of the CAT, singleton, ownership, metadata, and CR (credential-restricted) outer-puzzle drivers recurse into each other with no depth limit, walking the nested layers of a curried CLVM puzzle reveal supplied by an untrusted counterparty (e.g. inside an `Offer`).

### Finding Description
`match_puzzle()` in [1](#0-0)  iterates the driver table and returns as soon as one driver's `.match()` succeeds. Each outer-puzzle driver's `match()` method, when it recognizes its own curried wrapper, immediately recurses back into the *same* `match_puzzle` function (bound as `self._match`) on the wrapped inner puzzle — for example in `CATOuterPuzzle.match()`: [2](#0-1) 

and identically in `SingletonOuterPuzzle.match()`, `OwnershipOuterPuzzle.match()`, `MetadataOuterPuzzle.match()`, and `CROuterPuzzle.match()`: [3](#0-2) [4](#0-3) 

Because any of these puzzle mods (e.g. `CAT_MOD`) can be trivially curried around another instance of itself an arbitrary number of times using `Program.curry()`, an attacker can build a puzzle reveal with hundreds of nested outer-puzzle layers. Each layer costs at least one Python call frame in `match_puzzle` plus one in the driver's `match()`/`match_cat_puzzle()`/`uncurry_puzzle()` helper, with no cap on nesting depth anywhere in this call chain.

This matching path is reached from wallet code that processes an untrusted counterparty's offer: `Offer._get_offered_coins()` calls `match_puzzle()` on the puzzle reveal of every coin spend in the bundle: [5](#0-4) 

The equivalent debug/inspection helper `uncurry_dump`/`recursive_uncurry_dump` (used e.g. by `debug_spend_bundle`, which wallets/CLI use to inspect spend bundles) has the same unbounded recursive-descent pattern: [6](#0-5) 

This mirrors the code base's own documented awareness of this exact bug class: `sha256_treehash()` was deliberately rewritten as an iterative stack machine specifically "to avoid Python recursion limits on deeply nested CLVM," a fix that was never applied to the outer-puzzle driver matching/inspection code paths: [7](#0-6) 

### Impact Explanation
A wallet user who receives and inspects/accepts a maliciously crafted offer (or any coin spend a counterparty asks them to look at) can trigger a Python `RecursionError` deep inside `match_puzzle`/driver matching. Depending on where the exception propagates, this can abort in-flight offer parsing/acceptance or crash the wallet's spend-bundle inspection/trade-processing code path — a spend/offer-triggered halt of transaction processing for the victim wallet, consistent with the "spend-triggered transaction-processing halt" impact category.

### Likelihood Explanation
Constructing the malicious input requires only standard, unprivileged CLVM tooling: curry `CAT_MOD` (or another outer-puzzle mod) around itself hundreds of times to produce a puzzle reveal, embed it in a `CoinSpend`, and package it as an `Offer` sent to a victim, or as a coin whose spend the victim's wallet later inspects. No special network position, signing key, or trusted role is needed — any offer counterparty or spend-bundle submitter can do this.

### Recommendation
Convert `match_puzzle()` and the recursive `match()`/`get_inner_puzzle()`/`construct()`/`get_inner_solution()` methods of the outer-puzzle drivers (`CATOuterPuzzle`, `SingletonOuterPuzzle`, `OwnershipOuterPuzzle`, `MetadataOuterPuzzle`, `CROuterPuzzle`) and `recursive_uncurry_dump` to an iterative, explicit-stack implementation (mirroring the fix already applied to `sha256_treehash`), or impose a hard maximum outer-puzzle nesting depth and reject/raise a controlled error once exceeded, before recursing further.

### Proof of Concept
1. Build `p0 = CAT_MOD` (or any recognized outer-puzzle mod), then iteratively curry: `p_{i+1} = construct_cat_puzzle(CAT_MOD, tail, p_i)` for i = 0..N (N ≈ 1000, well above Python's default recursion limit).
2. Wrap `p_N` as the puzzle reveal of a `CoinSpend` inside a `WalletSpendBundle`/`Offer`.
3. Send the offer file to a victim wallet, or have the victim call `Offer.summary()`/`Offer._get_offered_coins()` (or `debug_spend_bundle()`) on the bundle.
4. Observe a Python `RecursionError` raised from within `match_puzzle` → `CATOuterPuzzle.match` recursion chain, crashing/aborting the offer-processing call.

def recursive_uncurry_dump(puzzle: Program, layer: int, prefix: str, uncurried_already: UncurriedPuzzle) -> None:
    mod = uncurried_already.mod
    curried_args = uncurried_already.args
    if mod != puzzle:
        print(f"{prefix}- Layer {layer}:")
        print(f"{prefix}  - Mod hash: {mod.get_tree_hash().hex()}")
        for arg in curried_args.as_iter():
            uncurry_dump(arg, prefix=f"{prefix}  ")
        mod2, curried_args2 = mod.uncurry()
        if mod2 != mod:
            recursive_uncurry_dump(mod, layer + 1, prefix, UncurriedPuzzle(mod2, curried_args2))
    else:
        print(f"{prefix}- {bu_disassemble(puzzle)}")


def uncurry_dump(puzzle: Program, prefix: str = "") -> None:
    mod, curried_args = puzzle.uncurry()
    if mod != puzzle:
        print(f"{prefix}- <curried puzzle>")
        prefix = f"{prefix}  "

    recursive_uncurry_dump(puzzle, 1, prefix, UncurriedPuzzle(mod, curried_args))
