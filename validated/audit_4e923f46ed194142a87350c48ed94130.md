### Title
Duplicate/Forged `ReceivedOutput` Inputs Are Counted Multiple Times, Producing Transactions Reporting Unspendable Funds — ([File: networks/bitcoin/src/wallet/send.rs](networks/bitcoin/src/wallet/send.rs))

### Summary
Analogous to `Shelter.withdraw` lacking a `claimed[_token][msg.sender]` check, `SignableTransaction::new` never checks that the `inputs` list contains distinct outpoints, nor does `ReceivedOutput::read` validate that the claimed `TxOut`/`value` corresponds to any real UTXO. Each entry in `inputs` is summed into `input_sat` and mapped into `tx_ins` unconditionally, so the same "claim" (the same output, or a fabricated one) can be counted repeatedly.

### Finding Description
- `ReceivedOutput::read` deserializes `offset`, an arbitrary `TxOut` (including arbitrary `value` and `script_pubkey`), and an arbitrary `OutPoint` from untrusted bytes with no consistency or existence check ([send.rs context; `networks/bitcoin/src/wallet/mod.rs` `ReceivedOutput::read`, mod.rs:122-134]).
- `SignableTransaction::new` computes `input_sat` as a plain sum over all inputs and builds one `TxIn` per entry with no deduplication (`send.rs:175-185`).
- The balance check `input_sat < payment_sat + needed_fee` (send.rs:215) and the change calculation `input_sat - (payment_sat + fee_with_change)` (send.rs:228-230) therefore treat duplicate or fabricated inputs as real spendable balance — the exact same missing-"already claimed" accounting flaw as the Concur shelter.
- `multisig` only verifies `p2tr_script_buf(offset.group_key()) == prevouts[i].script_pubkey` per input (send.rs:276-281). A duplicated *genuine* output (same offset, same script) passes this check in every duplicated slot, so the threshold will sign the malformed transaction.

### Impact Explanation
An attacker feeding crafted bytes to `ReceivedOutput::read` (or a caller passing a scanned output multiple times) causes `SignableTransaction` to credit phantom sats:
- The change output is assigned value backed by no real input, so the wallet reports receiving change funds that are not spendable — the transaction is consensus-invalid (duplicate `txin`s, or prevout amounts that don't match chain state under `Prevouts::All` in `taproot_key_spend_signature_hash`, send.rs:375-390) and can never confirm.
- The honest FROST signing set produces a threshold signature over a permanently unbroadcastable transaction; any downstream accounting that marks the inputs consumed and the change/payments as received is corrupted — funds appear received/spent but the UTXOs are never actually moved, and the wallet's balance view is inflated by attacker-chosen amounts via `Output::balance`/`value()`.

### Likelihood Explanation
Reachable by any party able to supply serialized `ReceivedOutput`s (an explicitly in-scope untrusted-bytes sink). Requires no collusion: honest signers' `multisig` check is per-input script matching only, so duplicates and fabricated values sail through. Concrete impact is bounded to invalid signed transactions and false received-funds reporting rather than direct theft, so severity is Medium.

### Recommendation
- In `SignableTransaction::new`, reject duplicate `outpoint`s (insert into a `HashSet`/BTreeSet and error on collision) before summing `input_sat`.
- Wherever possible, bind `ReceivedOutput` to chain-verified data (derive `output`/`value` from the scanned block rather than trusting decoded bytes), or verify `prevouts[i]` against the referenced transaction before signing.
- Optionally sanity-check `offset`/`script_pubkey` consistency at `ReceivedOutput::read` time when the expected key set is known.

### Proof of Concept
```rust
// output: a genuine ReceivedOutput scanned for the group key (offset ZERO or registered)
let bytes = output.serialize();
let dup1 = ReceivedOutput::read(&mut bytes.as_slice()).unwrap();
let dup2 = ReceivedOutput::read(&mut bytes.as_slice()).unwrap();

// No dedup: input_sat = 2 * output.value(), tx contains the same txin twice
let tx = SignableTransaction::new(
  vec![dup1, dup2],
  &payments,                 // e.g. one payment of output.value()
  Some(change_script),       // change is credited ~output.value() of phantom sats
  None,
  FEE,
).unwrap();
// tx.multisig(&keys) succeeds: each duplicate input's script_pubkey matches the offset key;
// the threshold signs a consensus-invalid transaction whose change output is unspendable.
```
