### Title
SignableTransaction fee/size checks computed on a transaction that omits the OP_RETURN output, so the checks don't take effect on the actual transaction - (File: networks/bitcoin/src/wallet/send.rs)

### Summary
`SignableTransaction::new` pushes the OP_RETURN output into `tx_outs` before computing the transaction's weight/vbytes, but calls `calculate_weight_vbytes(tx_ins.len(), payments, None)` with the raw `payments` list — not `tx_outs`. The fee, minimum-relay-fee, `NotEnoughFunds`, and `MAX_STANDARD_TX_WEIGHT` checks are therefore all evaluated against a transaction that does not contain the OP_RETURN output, exactly mirroring the BondAggregator bug where `minAmountOut_` was checked against `maxPayout` rather than the actual `payout`.

### Finding Description
In `SignableTransaction::new`: [1](#0-0) 

`tx_outs` is built from `payments` and then the OP_RETURN output is appended when `data` is `Some`. However, the weight/vbytes used for `needed_fee`, the `TooLowFee` minimum-relay check, and the `NotEnoughFunds` sufficiency check are computed from `payments` only: [2](#0-1) 

Likewise, when change is considered, `calculate_weight_vbytes(tx_ins.len(), payments, Some(&change))` again omits the OP_RETURN output, and the final `weight > MAX_STANDARD_TX_WEIGHT` check uses the same incomplete measurement: [3](#0-2) 

`calculate_weight_vbytes` builds a mock `Transaction` to measure, and its `output` field only includes what it's passed — the OP_RETURN output present in the real `tx` is never measured: [4](#0-3) 

So the parameter "checked" (vbytes of a payment-only transaction) is a different quantity than the one that actually matters (vbytes of the final transaction including OP_RETURN). The check exists but does not take effect on the real value — the same bug class as `findMarketFor` checking `minAmountOut_ <= maxPayout` while never checking `payouts[i] >= minAmountOut_`.

### Impact Explanation
An unprivileged caller can pass arbitrary `data` (up to 80 bytes) to `SignableTransaction::new`. The resulting transaction carries an OP_RETURN output (~12–90 extra bytes) whose weight was never priced:

- The effective fee rate is `needed_fee / actual_vbytes < fee_per_vbyte`. If `data` is large and `fee_per_vbyte` is near the minimum relay fee, the transaction can fall below `DEFAULT_MIN_RELAY_TX_FEE` even though the `TooLowFee` check passed — producing a signed transaction the network won't propagate.
- `input_sat >= payment_sat + needed_fee` can pass while the inputs cannot actually fund the intended fee rate, so the silently-underpaid difference comes out of change/fee semantics the caller did not request.
- The `MAX_STANDARD_TX_WEIGHT` bound is under-measured, allowing construction of a transaction that is non-standard (unbroadcastable) despite passing validation.

This is the same outcome class as the Bond issue: the validation gives a false guarantee, and the resulting operation fails downstream (wasted fee/signing work, unbroadcastable transaction).

### Likelihood Explanation
`data` is a user-controlled public input to `SignableTransaction::new`; reaching the bug only requires supplying a non-empty `data` with a low `fee_per_vbyte`. No collusion, malicious validator, or leaked key is needed. The discrepancy is bounded (~90 vbytes max), so the practical impact is limited to edge-case transactions near the minimum fee rate or the weight cap — consistent with Medium severity rather than High.

### Recommendation
Compute weight/vbytes over the actual outputs. Change `calculate_weight_vbytes` to take the final `tx_outs` (or take `output: Vec<TxOut>` directly) and call it after the OP_RETURN output is appended — e.g. `Self::calculate_weight_vbytes(tx_ins.len(), &tx_outs)` for the no-change case, and `tx_outs.clone()` plus the candidate change `TxOut` for the with-change case. This ensures `needed_fee`, `TooLowFee`, `NotEnoughFunds`, and `TooLargeTransaction` are checked against the transaction that will actually be signed.

### Proof of Concept
```rust
// networks/bitcoin/src/wallet/send.rs
// In SignableTransaction::new, with `data = Some(vec![0; 80])`:
tx_outs.push(TxOut {
  value: Amount::ZERO,
  script_pubkey: ScriptBuf::new_op_return(PushBytesBuf::try_from(data).unwrap()),
}); // ~90-byte output now in tx_outs

// Fee is priced on `payments` only — the OP_RETURN output is never counted:
let (mut weight, vbytes) = Self::calculate_weight_vbytes(tx_ins.len(), payments, None);
let mut needed_fee = fee_per_vbyte * vbytes; // under-priced by ~90 vbytes * fee_per_vbyte

// Construct a tx with fee_per_vbyte exactly at the min relay rate and data = [0; 80].
// TooLowFee passes, but the real TX's effective fee rate is below the minimum
// relay fee, so the signed transaction will not be accepted to the mempool.
```
