Based on my research, the Union Finance bug's core pattern—a privileged operation (`removeReserves`) that trusts an input value without validating it against the actual state it's supposed to represent—has a direct analog in this fork's AI-assisted merge-conflict resolution feature.

### Title
Unvalidated LLM-generated file content is silently written and staged during AI conflict resolution, allowing attacker-controlled merge input to corrupt committed code - ([File: app/src/lib/stores/app-store.ts])

### Summary
The Copilot conflict-resolution pipeline validates that an LLM response only touches expected file *paths* and produces the expected *hunk count*, but never validates the actual *content* of `resolvedContent` before it is written to disk and staged for commit. Since the LLM prompt is built directly from conflict hunks pulled from the branch being merged/rebased (attacker-influenced content when merging a fetched/untrusted branch or PR), a malicious branch can manipulate the model's output enough to inject unreviewed content into the final file, which the app writes and `git add`s automatically.

### Finding Description
`validateResolutionPaths` in [1](#0-0)  only checks that returned paths match `expectedFiles` and that hunk counts line up — it performs no validation of `resolvedContent` itself beyond rejecting leftover conflict markers (checked separately in `parseCopilotConflictResolution`, [2](#0-1) ).

The conflict context sent to the model is built from the actual file content of the branch being merged, via `buildConflictContext`, [3](#0-2)  — this content, including any adversarial text embedded in the conflicting branch (or referenced commit messages/PR descriptions per the system prompt at [4](#0-3) ), is attacker-influenced whenever the user is merging in a branch/PR they don't fully control.

Once the model returns hunk-count-matching, marker-free content for a legitimate conflicted path, `applyCopilotConflictResolutions` writes it straight to disk and stages it with no further check on the content: [5](#0-4) 

The only invariant enforced is "right file, right hunk count" — exactly analogous to `removeReserves` only checking `totalReserves -= reduceAmount` bookkeping without checking whether that amount is actually backed by reserves. Here, the safeguards check *shape* (path/count) but not *substance* (that the merged content is actually a faithful union of "ours"/"theirs", free of injected code).

The UI defaults to a "Summary" tab that shows AI-authored reasoning text, not a diff; the actual line-level diff only appears if the user manually clicks the "Changes" tab in [6](#0-5) . Clicking "Continue" immediately calls `applyCopilotConflictResolutions` and proceeds with the operation: [7](#0-6) .

### Impact Explanation
An attacker who controls one side of a merge (a malicious branch, fork PR, or crafted commit messages/PR description that get fed into the prompt) can attempt to steer the model into emitting resolved content that differs from a faithful merge — e.g., re-introducing removed security checks, subtly altering logic, or embedding a backdoor — while staying within the expected path/hunk-count envelope so `validateResolutionPaths` passes silently. Since the default dialog view is a prose "Summary" and staging/commit happens automatically on "Continue", this can result in silent corruption of what the user ultimately commits and pushes, without the user reviewing a diff.

### Likelihood Explanation
Requires the user to (a) have Copilot conflict resolution enabled, (b) merge/rebase/cherry-pick a branch or PR the attacker controls or influences, and (c) click "Continue" without switching to the "Changes" tab to inspect the diff. This is a plausible normal workflow (reviewing forked PRs, third-party branches) and doesn't require unnatural user steps beyond the ordinary "accept AI resolution" click that the feature is designed to encourage.

### Recommendation
Do not rely solely on path/hunk-count matching as the safety boundary for LLM-written content. Consider: requiring the user to view the actual diff (not just the summary) before "Continue" is enabled, running a lightweight structural diff between the model's `resolvedContent` and both `ours`/`theirs` sides to flag content that doesn't originate from either side, and/or treating PR titles/descriptions/commit messages as untrusted input with explicit prompt-injection mitigations when they are included in the resolution context (`app/src/lib/copilot-conflict-resolution.ts:195-201`).

### Proof of Concept
Conceptual (no execution environment available for browser/git operations):
1. Attacker creates a PR/branch with a file that conflicts with the target branch, and crafts commit messages/PR description that attempt prompt injection against `ConflictResolutionSystemPrompt`.
2. Victim merges/rebases this branch in Desktop with Copilot conflict resolution enabled.
3. The model resolves the conflict; `validateResolutionPaths` only checks the resolution touches the same conflicted path with the same hunk count — it does not check the resolved text against the two source hunks.
4. Victim reviews the "Summary" tab (default) and clicks "Continue"; `applyCopilotConflictResolutions` writes `resolution.resolvedContent` to disk and stages it (`app/src/lib/stores/app-store.ts:7258-7259`) without further inspection.
5. The operation completes and the file is committed with content the victim never diffed line-by-line.

Note: I was unable to fully trace how commit messages/PR title/body are incorporated into the prompt sent to the model (only the system prompt references them at a high level), so the exact scope of attacker-controllable prompt surface beyond the raw conflict hunks is not fully confirmed from the available index.

export function validateResolutionPaths(
  resolutions: ReadonlyArray<IRawFileResolution>,
  expectedFiles: ReadonlyArray<IFileConflictContext>
): void {
  const expectedPaths = new Set(expectedFiles.map(f => f.path))
  const expectedHunkCounts = new Map(
    expectedFiles.map(f => [f.path, f.hunks.length])
  )
  const returnedPaths = new Set(resolutions.map(r => r.path))

  for (const path of returnedPaths) {
    if (!expectedPaths.has(path)) {
      throw new CopilotValidationError(
        `Copilot returned resolution for unexpected file: ${path}`
      )
    }
  }

  if (returnedPaths.size !== resolutions.length) {
    throw new CopilotValidationError(
      'Copilot returned duplicate file paths in resolutions'
    )
  }

  const missingPaths: Array<string> = []
  for (const path of expectedPaths) {
    if (!returnedPaths.has(path)) {
      missingPaths.push(path)
    }
  }
  if (missingPaths.length > 0) {
    throw new CopilotValidationError(
      `Copilot did not return resolutions for: ${missingPaths.join(', ')}`
    )
  }

  for (const resolution of resolutions) {
    // Delete-vs-modify resolutions use action instead of hunks — skip count check
    if (resolution.action !== undefined) {
      continue
    }
    const expectedCount = expectedHunkCounts.get(resolution.path) ?? 0
    if (resolution.hunks.length !== expectedCount) {
      throw new CopilotValidationError(
        `Copilot returned ${resolution.hunks.length} hunk(s) for "${resolution.path}" but expected ${expectedCount}`
      )
    }
  }
