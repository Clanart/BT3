## Title
SSRF via unrestricted HTTP fetch of attacker-published DataLayer mirror URLs - (File: `chia/data_layer/download_data.py`)

### Summary
DataLayer's file-sync path (`http_download()` in `chia/data_layer/download_data.py`) issues an `aiohttp` GET request to a `ServerInfo.url` without any validation that the URL does not point at `localhost`, link-local/private ranges, or other internal-network endpoints. These URLs are not configured by the local operator — they are read from `Mirror` coins that **any wallet user** can publish on-chain for **any** DataLayer store id via `dl_new_mirror`, and a node that later subscribes to that store id will automatically fetch from every published URL. This lets an unprivileged spend-bundle/wallet-action submitter drive a victim node's outbound HTTP requests to arbitrary internal targets, the same bug class described in the `dssrf` advisory (URL/host "safety" is never actually verified before the request is issued).

### Finding Description
`DataLayer.create_new_mirror()` in `chia/data_layer/data_layer_wallet.py` builds and signs a standard-wallet spend to the mirror puzzle with `memos=[[launcher_id, *(url for url in urls)]]` — note it does **not** check that `launcher_id` (the target store id) is owned by the caller: [1](#0-0) 

The corresponding RPC endpoint `WalletRpcApi.dl_new_mirror()` performs no ownership or URL validation either, so any wallet holder can publish a mirror entry (any string URL, arbitrary count) tagged with someone else's `launcher_id`: [2](#0-1) 

Any other node that decides to track/subscribe to that same store id (a normal, unprivileged DataLayer client action) will ingest those attacker-controlled URLs into its subscription list via `DataLayer.update_subscriptions_from_wallet()`: [3](#0-2) 

During the periodic sync loop, `fetch_and_validate()` shuffles the configured `ServerInfo` list and calls `insert_from_delta_file()` → `download_file()` → `http_download()` for each server without ever inspecting the URL's host/IP: [4](#0-3) 

`http_download()` opens a plain `aiohttp.ClientSession` and issues `session.get(server_info.url + "/" + filename, ...)` with no host allow-list, no rejection of loopback/link-local/private addresses, and no DNS-rebinding protection — it will happily connect to `http://127.0.0.1/...`, `http://169.254.169.254/...`, or any internal service reachable from the DataLayer process: [5](#0-4) 

This mirrors the `dssrf` root cause exactly: a "is this destination safe" check is either absent or effectively bypassed, so a value fully controlled by an external, unprivileged party is used directly as the target of a server-initiated outbound request. Existing tests even show `127.0.0.1` URLs being accepted as normal mirror content with no rejection (`test_mirrors` / `test_server_selection`), confirming there is no host filtering in this path: [6](#0-5) 

### Impact Explanation
A malicious wallet user can force any DataLayer node that subscribes to (or independently tracks) their chosen store id to make outbound HTTP requests to attacker-chosen internal endpoints (localhost services, cloud metadata endpoints, other private-network hosts). This is classic SSRF: it can be used for internal network reconnaissance/port-scanning, hitting unauthenticated local/internal HTTP services (e.g., other local RPC ports, metadata services), or triggering side effects on internal-only endpoints reachable from the DataLayer process. Because responses are parsed/consumed only as delta files (and `is_filename_valid`/proof verification eventually rejects bad content), this analog does not directly yield remote code execution or fund theft, but it does grant an unprivileged on-chain actor a reliable request-forgery primitive against any node that chooses to subscribe to their store.

### Likelihood Explanation
Likelihood is high for any node operator who subscribes to third-party DataLayer stores (a normal, encouraged use case for DataLayer — subscribing to others' published data). Publishing a mirror for an arbitrary `launcher_id` costs only a wallet transaction fee and requires no special privilege or ownership of the targeted store, as shown by the unchecked `create_new_mirror()`/`dl_new_mirror()` path.

### Recommendation
Before issuing any outbound request in `http_download()` (and the plugin `handle_download`/`download` flow), resolve and validate the target host against a deny-list of loopback, link-local, and private/reserved IP ranges (consistent with `chia.util.network.is_localhost`/`is_in_network`), rejecting non-HTTP(S) schemes and re-validating post-redirect destinations. Consider also requiring/allowing operators to configure an explicit allow-list of DataLayer mirror hosts, and revalidate resolved IPs at connect time (not just at URL-parse time) to avoid DNS-rebinding.

### Proof of Concept
1. Attacker (any wallet holder) calls `dl_new_mirror` (or `add_mirror` CLI) with `launcher_id = <victim_store_id>` and `urls = ["http://127.0.0.1:<victim_internal_port>"]`, paying only the transaction fee — no ownership of `victim_store_id` is required (`create_new_mirror` in `chia/data_layer/data_layer_wallet.py:687-703`).
2. Victim node subscribes to `victim_store_id` (a normal DataLayer client operation) and periodically runs `DataLayer.update_subscriptions_from_wallet()` / `periodically_manage_data()`, pulling the attacker's URL into its `Subscription.servers_info`.
3. On the next sync cycle, `fetch_and_validate()` → `insert_from_delta_file()` → `download_file()` → `http_download()` issues `GET http://127.0.0.1:<victim_internal_port>/<filename>` from the victim's own process, exactly as `dssrf`'s `is_url_safe` failed to block requests to `localhost`.

```python
async def http_download(
    target_filename_path: Path,
    filename: str,
    proxy_url: str | None,
    server_info: ServerInfo,
    timeout: aiohttp.ClientTimeout,
    log: logging.Logger,
    max_delta_file_size: int,
) -> None:
    """
    Download a file from a server using aiohttp.
    Raises exceptions on errors
    """
    async with aiohttp.ClientSession() as session:
        headers = {"accept-encoding": "gzip"}
        async with session.get(
            server_info.url + "/" + filename,
            headers=headers,
            timeout=timeout,
            proxy=proxy_url,
        ) as resp:
            resp.raise_for_status()
            size = int(resp.headers.get("content-length", 0))
            max_delta_file_size_bytes = max_delta_file_size * 1024 * 1024
            if size > max_delta_file_size_bytes:
                raise MaxDeltaFileSizeExceededError(f"Maximum delta file size exceeded: {max_delta_file_size} MiB.")
            log.debug(f"Downloading delta file {filename}. Size {size} bytes.")
```
