## Finding: Hardcoded "sensitive location" denylist in `isClonePathSensitive` is an incomplete/stale security backstop

This is a legitimate structural analog to the reported bug. The Compound-style bug was a **hardcoded constant (`blocksPerYear`) that was accurate at write time but became stale as the underlying environment changed**, silently corrupting a security-relevant calculation while the code kept behaving as if the guard/formula were still correct. The Desktop equivalent is the hardcoded, enumerated denylist of "sensitive locations" in `isClonePathSensitive`.

### Title
Hardcoded, incomplete sensitive-path denylist lets crafted clone destinations write into unlisted credential/persistence locations - (File: `app/src/lib/git/clone.ts`)

### Summary
`clone()` derives its destination directory from a repository "name" that is attacker-controlled when the user follows a crafted clone URL or `x-github-client://openRepo` deep link. The only backstop preventing that destination from resolving to a security-sensitive directory is `isClonePathSensitive`, which checks the resolved path against a small, hand-maintained list of paths.

### Finding Description
`isClonePathSensitive` explicitly documents itself as "a backstop against path traversal attacks where a crafted URL tricks the UI into deriving a clone path outside the intended base directory," and enumerates a fixed set of paths to block: [1](#0-0) 

The primary defense, `sanitizeCloneName`, reduces an attacker-supplied repository name down to a single safe path component, e.g. turning `x..\..\..\../.ssh` into `.ssh`: [2](#0-1) 

The clone UI then joins that single sanitized component onto the *existing* base path (`Path.join(Path.dirname(dirPath), safeName)` / `Path.join(dirPath, safeName)`), so an attacker can force the final path component of the destination to be an arbitrary sensitive-looking name (`.ssh`, `.netrc`, `.aws`, `Startup`, etc.) as long as the user's chosen base directory happens to be (or is navigated to) the home directory or another sensitive parent: [3](#0-2) 

`isClonePathSensitive`'s list only covers `~/.ssh`, `~/.gnupg`, `~/.config`, `~/.config/git`, `~/.gitconfig`, and on Windows `%APPDATA%` and `%APPDATA%\gnupg`. It omits a large set of equally sensitive, equally common locations that are just as capable of leaking credentials or achieving code execution:
- `~/.aws/credentials`, `~/.aws/config`
- `~/.netrc` (used by curl/git-credential and other tools)
- `~/.docker/config.json`
- `~/.kube/config`
- `~/.npmrc`, `~/.gem/credentials`, `~/.azure`
- Windows/macOS autorun/persistence directories such as `%APPDATA%\Microsoft\Windows\Start Menu\Programs\Startup` or `~/Library/LaunchAgents`

Exactly like `blocksPerYear = 2102400` being correct for pre-Merge Ethereum but silently wrong afterward, this denylist was correct for the specific threats considered at write time but is a static enumeration that does not track the actual (much larger, evolving) set of sensitive/credential paths present on a real machine. The guard gives the *appearance* of blocking "sensitive location" clones while only covering a narrow subset.

### Impact Explanation
If an attacker can get a victim to clone into a base directory that is, or resolves under, the home directory (a normal, expected user action when following a "Clone with GitHub Desktop" deep link and accepting/adjusting the pre-filled path), a crafted repository name can force the final destination to be an unlisted sensitive path. Since `clone --recursive` fully populates that directory with attacker-chosen file contents, this can overwrite/create files like `~/.netrc` or `~/.aws/credentials` (credential exfiltration/poisoning on subsequent tool use) or drop files into an autorun directory (code execution at next login) — all without the existing guard firing, because the guard only recognizes the small enumerated list.

### Likelihood Explanation
Requires an attacker-supplied clone URL/deep link (no local access, no admin rights, no prior malware) and only the ordinary user action of clicking "Clone" after a URL is opened via GitHub Desktop's own clone/deep-link flow — the exact threat model `isClonePathSensitive`'s own comment says it was built to stop. It fails specifically because it is a hardcoded, non-exhaustive list rather than a general-purpose check (e.g., a curated but broader set, or a check based on "well-known credential-file names" rather than a handful of hardcoded absolute paths).

### Recommendation
Replace or augment the static list in `isClonePathSensitive` with a more systematic and actively maintained set covering common credential stores (`.netrc`, `.aws`, `.docker`, `.kube`, `.npmrc`, `.azure`, `.gem`, etc.) and OS-specific autorun/startup locations, and treat unknown "unlisted but similarly sensitive" dotfile/dot-directory names defensively (e.g., disallow cloning directly into any existing dotfile/dot-directory under the home directory) rather than enumerating an exact allowlist of blocked names.

### Proof of Concept
1. Attacker hosts/crafts a clone URL whose repository name, after Git's `basename`-style parsing and `sanitizeCloneName`, reduces to `.netrc` (or `.aws`, or a Windows Startup-folder-styled component), e.g. `https://evil.example/owner/x..\..\..\..\.netrc.git`.
2. Victim opens the link (or pastes URL into "Clone repository" → URL tab) and accepts the default/derived path, which is a sibling of their chosen base directory (in some flows the base directory defaults to or is navigated to the home directory).
3. `updateUrl` joins the sanitized name onto the base path per [4](#0-3) , producing `~/.netrc` as the clone target.
4. `clone()` calls `isClonePathSensitive(path)`, which does not match `.netrc` against any entry in its hardcoded list [5](#0-4) , so the clone proceeds and populates `~/.netrc` with attacker-controlled content.

/**
 * Check whether a resolved clone path targets a sensitive location that
 * should never be used as a clone destination. This is a backstop against
 * path traversal attacks where a crafted URL tricks the UI into deriving
 * a clone path outside the intended base directory.
 */
function isClonePathSensitive(unresolvedClonePath: string): boolean {
  const clonePath = Path.resolve(unresolvedClonePath).toLowerCase()
  const home = Path.resolve(homedir()).toLowerCase()

  if (clonePath === home) {
    return true
  }

  const sensitiveLocations = [
    Path.join(home, '.ssh'),
    Path.join(home, '.gnupg'),
    Path.join(home, '.config'),
    Path.join(home, '.config', 'git'),
    Path.join(home, '.gitconfig'),
  ]

  if (__WIN32__) {
    const appData = process.env.APPDATA
    if (appData) {
      sensitiveLocations.push(appData.toLowerCase())
      sensitiveLocations.push(Path.join(appData, 'gnupg').toLowerCase())
    }
  }

  for (const sensitive of sensitiveLocations) {
    if (clonePath === sensitive || clonePath.startsWith(sensitive + Path.sep)) {
      return true
    }
  }

  return false
}

export function sanitizeCloneName(name: string): string | null {
  const components = name.split(/[/\\:]/)

  let lastComponent = ''
  for (let i = components.length - 1; i >= 0; i--) {
    if (components[i].length > 0) {
      lastComponent = components[i]
      break
    }
  }

  if (lastComponent.length === 0) {
    return null
  }

  if (lastComponent.endsWith('.git')) {
    lastComponent = lastComponent.slice(0, -4)
  }

  if (
    lastComponent === '..' ||
    lastComponent === '.' ||
    lastComponent.length === 0
  ) {
    return null
  }

  return lastComponent
}
