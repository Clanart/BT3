Untrusted Git remote's `WWW-Authenticate` header can trick Desktop's credential-helper trampoline into treating a non-GitHub host as GitHub Enterprise, forcing a GHE sign-in flow against an attacker-controlled endpoint - (File: `app/src/lib/trampoline/trampoline-credential-helper.ts`)

### Summary
Desktop's credential-helper trampoline classifies a remote endpoint's "kind" (`github.com` / `enterprise` / `generic`) partly based on a `WWW-Authenticate` header value that the *remote Git server itself* supplies during authentication. This is directly analogous to the audited report's broken invariant: an external, attacker-influenceable system (there, Aave's `RewardsController` emission manager; here, an arbitrary git remote/proxy) is allowed to make an authorization/classification decision that the client (there, `AaveV3YieldSource`; here, GitHub Desktop) assumes it fully controls, letting an untrusted party redirect trusted behavior toward itself.

### Finding Description
In `getEndpointKind` [1](#0-0) , when the credential URL doesn't already match `github.com`, `ghe.com`, or an existing gist host, Desktop inspects the `wwwauth[]` fields of the credential map — which are populated directly from the `WWW-Authenticate` HTTP response header sent by the remote server during a Git HTTP authentication challenge — and if the value contains `realm="GitHub"`, unconditionally classifies the endpoint as `'enterprise'`. This is stated explicitly in the comment: "We use them as a happy-path to determine if the host is a GitHub host without having to resort to making a request ourselves."

This classification directly drives `getCredential` [2](#0-1) : if `endpointKind !== 'generic'` and no existing account matches `apiEndpoint`, Desktop calls `ui.promptForGitHubSignIn(endpoint)` [3](#0-2) . That helper, in `trampoline-ui-helper.ts`, begins a full **GitHub Enterprise sign-in flow bound to the attacker-controlled origin** — `dispatcher.beginEnterpriseSignIn(cb)` followed by `dispatcher.setSignInEndpoint(origin)` where `origin` is derived straight from the malicious remote's URL [4](#0-3) .

The only real, network-verified check (`isGitHubHost`, which performs an actual HEAD request and checks for the `x-github-request-id` response header) [5](#0-4)  is bypassed entirely by the `wwwauth[]` "happy path" — it is only reached as a fallback when no `wwwauth[]` header matched. A remote server (or an on-path proxy/MITM of an arbitrary HTTPS/HTTP git remote the user clones or has as a `git remote`) fully controls the `WWW-Authenticate` response header it returns for a 401, so it can trivially set `WWW-Authenticate: Basic realm="GitHub"` to force the `'enterprise'` classification regardless of the actual hostname.

### Impact Explanation
This lets an attacker who controls a git remote (a repository the user clones/fetches, or a proxy sitting in front of one) cause Desktop to initiate an **Enterprise sign-in / account-binding flow pointed at the attacker's own origin**, matching the Valid Impact category "unauthorized OAuth or account binding" resulting from "a git remote/proxy response." The user is shown Desktop's native sign-in dialog (`PopupType.SignIn`, `isCredentialHelperSignIn: true`) with `credentialHelperUrl` set to the attacker's host, and Desktop's own enterprise sign-in endpoint state is silently set to that attacker-controlled origin via `setSignInEndpoint(origin)`. Because this occurs from a legitimate-looking Desktop-native dialog triggered automatically during a normal `git fetch`/`push`/`clone` credential prompt (not a phishing email or fake browser page), a user has no way to distinguish it from a real GHE authentication request, and any credentials or OAuth authorization entered end up delivered to the attacker's endpoint rather than a genuine GitHub host.

### Likelihood Explanation
The trigger requires nothing beyond adding/using a git remote (HTTP(S)) that responds with a 401 and a crafted `WWW-Authenticate: ... realm="GitHub"` header — something entirely within the control of anyone who can stand up a git server or sit on-path for a plain HTTP remote. It does not require the user to click any links, install anything, or have local/admin access; it is triggered purely by Desktop performing a normal Git network operation against a remote whose ownership/administration is by definition untrusted from the client's perspective. The `existingAccount` and `isGitHubHost` fallback checks are only ever reached if the `wwwauth[]` happy-path doesn't fire first, so any attacker sending this header short-circuits the legitimate verification.

### Recommendation
Do not trust the `WWW-Authenticate` realm value from an untrusted remote as sufficient evidence to classify a host as an authoritative GitHub/GHE endpoint for the purpose of initiating a sign-in/account-binding flow. At minimum, corroborate the `wwwauth[]` happy-path with the same server-side verification `isGitHubHost` performs (e.g., checking for `x-github-request-id`) before triggering `promptForGitHubSignIn`, or clearly surface the actual remote hostname/origin to the user before beginning an Enterprise sign-in flow so they can detect a mismatch.

### Proof of Concept
1. Stand up an HTTP(S) git server (or MITM proxy in front of one) at `https://evil.example.com/some/repo.git`.
2. Configure it to respond to unauthenticated Git-over-HTTP requests (`/info/refs?service=git-upload-pack`) with `401 Unauthorized` and header `WWW-Authenticate: Basic realm="GitHub"`.
3. In GitHub Desktop, add this URL as a remote (or clone it) and trigger a fetch/push.
4. Git invokes Desktop's credential-helper trampoline; the helper receives `wwwauth[0]=Basic realm="GitHub"` in its stdin credential map.
5. `getEndpointKind` matches `realm="GitHub"` and returns `'enterprise'` without ever verifying via `isGitHubHost`.
6. Since no existing account endpoint matches `apiEndpoint(evil.example.com)`, `getCredential` calls `ui.promptForGitHubSignIn('https://evil.example.com')`, which calls `dispatcher.beginEnterpriseSignIn` and `dispatcher.setSignInEndpoint('https://evil.example.com')`, presenting Desktop's native GitHub Enterprise sign-in dialog pointed at the attacker's origin.

/** Implementation of the 'get' git credential helper command */
async function getCredential(cred: Credential, store: Store, token: string) {
  const ghCred = await getGitHubCredential(cred, store)

  if (ghCred) {
    return ghCred
  }

  const endpointKind = await getEndpointKind(cred, store)
  const accounts = await store.getAll()

  const endpoint = `${getCredentialUrl(cred)}`
  const apiEndpoint = getAPIEndpoint(endpoint)

  // If it appears as if the endpoint is a GitHub host and we don't have an
  // account for that endpoint then we should prompt the user to sign in.
  if (
    endpointKind !== 'generic' &&
    !accounts.some(a => a.endpoint === apiEndpoint)
  ) {
    if (getIsBackgroundTaskEnvironment(token)) {
      debug('background task environment, skipping prompt')
      return undefined
    }

    const account = await ui.promptForGitHubSignIn(endpoint)

    if (!account) {
      setHasRejectedCredentialsForEndpoint(token, endpoint)
    }

    return credWithAccount(cred, account)
  }

  // GitHub.com/GHE creds are only stored internally
  if (endpointKind !== 'generic') {
    return undefined
  }

  return useExternalCredentialHelper()
    ? getExternalCredential(cred, token)
    : getGenericCredential(cred, token)
}

const getEndpointKind = async (cred: Credential, store: Store) => {
  const credentialUrl = getCredentialUrl(cred)
  const endpoint = `${credentialUrl}`

  if (isGist(endpoint)) {
    return 'generic'
  }

  if (isDotCom(endpoint)) {
    return 'github.com'
  }

  if (isGHE(endpoint)) {
    return 'ghe.com'
  }

  // When Git attempts to authenticate with a host it captures any
  // WWW-Authenticate headers and forwards them to the credential helper. We
  // use them as a happy-path to determine if the host is a GitHub host without
  // having to resort to making a request ourselves.
  for (const [k, v] of cred.entries()) {
    if (k.startsWith('wwwauth[')) {
      if (v.includes('realm="GitHub"')) {
        return 'enterprise'
      } else if (/realm="(GitLab|Gitea|Atlassian Bitbucket)"/.test(v)) {
        return 'generic'
      }
    }
  }

/**
 * Attempts to determine whether or not the url belongs to a GitHub host.
 *
 * This is a best-effort attempt and may return `undefined` if encountering
 * an error making the discovery request
 */
export async function isGitHubHost(url: string) {
  const { hostname } = new window.URL(url)

  const endpoint =
    hostname === 'github.com' || hostname === 'api.github.com'
      ? getDotComAPIEndpoint()
      : getEnterpriseAPIURL(url)

  if (isDotCom(endpoint) || isGHE(endpoint)) {
    return true
  }

  if (isKnownThirdPartyHost(hostname)) {
    return false
  }

  // github.example.com,
  if (/(^|\.)(github)\./.test(hostname)) {
    return true
  }

  // bitbucket.example.com, etc
  if (/(^|\.)(bitbucket|gitlab)\./.test(hostname)) {
    return false
  }

  if (getEndpointVersion(endpoint) !== null) {
    return true
  }

  // Add a unique identifier to the URL to make sure our certificate error
  // supression only catches this request
  const metaUrl = `${endpoint}/meta?ghd=${crypto.randomUUID()}`

  const ac = new AbortController()
  const timeoutId = setTimeout(() => ac.abort(), 2000)
  suppressCertificateErrorFor(metaUrl)
  try {
    const response = await fetch(metaUrl, {
      headers: { 'user-agent': getUserAgent() },
      signal: ac.signal,
      credentials: 'omit',
      method: 'HEAD',
      redirect: 'error',
    })

    tryUpdateEndpointVersionFromResponse(endpoint, response)

    return response.headers.has('x-github-request-id')
  } catch (e) {
    log.debug(`isGitHubHost: failed with endpoint ${endpoint}`, e)
    return undefined
  } finally {
    clearTimeout(timeoutId)
    clearCertificateErrorSuppressionFor(metaUrl)
  }
}
