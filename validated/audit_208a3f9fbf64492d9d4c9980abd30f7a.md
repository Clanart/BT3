### Title
Invalid proof-of-possession ciphertexts can disclose encrypted DKG shares through blame proofs - (File: crypto/dkg/pedpop/src/lib.rs)

### Summary
`KeyMachine::calculate_share` returns an `EncryptionKeyProof` for a malformed `EncryptedMessage` before verifying the message’s queued proof-of-possession signature. An attacker can copy the ephemeral encryption key from another participant’s encrypted share, submit garbage ciphertext under that key, and cause the recipient to produce a blame proof containing the ECDH result needed to decrypt the copied share. [1](#0-0) 

### Finding Description
`EncryptedMessage::read` accepts the attacker-controlled message key, Schnorr proof, and ciphertext without authenticating them. [2](#0-1)  During decryption, the proof-of-possession is only queued into the batch verifier, while the recipient immediately computes `enc_key * msg.key`, decrypts the message, and constructs an `EncryptionKeyProof` for that ECDH point. [3](#0-2)  If the decrypted bytes are not a canonical scalar, `calculate_share` returns `InvalidShare` with that proof before `batch.verify_with_vartime_blame` ever checks the queued proof-of-possession. [1](#0-0) [4](#0-3) 

This bypasses the explicit mitigation documented on `EncryptedMessage`: without the proof-of-possession, an attacker can copy another participant’s message key and induce the recipient to reveal the corresponding ECDH result. [5](#0-4)  The original sender encrypted with `ecdh(message_key, recipient_encryption_key)`, so the disclosed blame proof’s `key` is the same shared point used to derive that message’s ChaCha20 stream. [6](#0-5) 

### Impact Explanation
An encrypted DKG share intended for the victim can be recovered once the generated blame proof is returned or published. [7](#0-6)  `decrypt_with_proof` accepts such a proof and applies `cipher(context, proof.key)` directly to the copied ciphertext after verifying its DLEq proof, so the disclosed point is sufficient for share recovery. [8](#0-7) 

### Likelihood Explanation
A protocol participant capable of submitting a share can mount this attack using only observed encrypted traffic and a malformed message under their own participant index; they do not need to know the copied key’s discrete logarithm or create a valid proof-of-possession. For curves whose scalar encoding space is substantially larger than the scalar modulus, such as Ed448 or Ristretto-family scalar fields, randomly decrypted bytes are non-canonical with high probability, causing the vulnerable early return. [9](#0-8) [10](#0-9) 

### Recommendation
Do not expose an `EncryptionKeyProof` until the associated message proof-of-possession has passed verification. In `calculate_share`, either verify each PoP before decrypting, or defer returning `blame` until the queued `BatchId::Decryption` statement has been checked and shown valid; an invalid-PoP failure should return `InvalidShare { blame: None }` or an equivalent error without an ECDH proof. [11](#0-10) [12](#0-11) 

### Proof of Concept
```rust
// Honest sender A produced this message for recipient B:
//   honest = EncryptedMessage { key: X, pop: pop_A, msg: C_A }
// where C_A encrypts A's secret share under bX.

// Attacker E observes `honest`, then submits its own message to B:
let forged = EncryptedMessage {
  key: honest.key,        // copied X; no discrete logarithm required
  pop: invalid_pop,       // any canonically encoded, invalid Schnorr signature
  msg: arbitrary_bytes,   // fixed-width SecretShare ciphertext
};

// B calls:
machine.calculate_share(rng, map_with_forged_share)

// Execution:
// 1. EncryptedMessage::read accepts forged.
// 2. decrypt queues forged.pop instead of verifying it immediately.
// 3. decrypt computes proof.key = bX and returns EncryptionKeyProof.
// 4. from_repr(decrypted_bytes) fails before batch verification.
// 5. calculate_share returns InvalidShare { blame: Some(proof) }.

// Once `proof` is returned/published:
// cipher(context, proof.key) is the same stream used for C_A.
// Therefore, decrypting C_A reveals A's secret-share bytes.
```

  pub fn read<R: io::Read>(reader: &mut R) -> io::Result<Self> {

  }

  pub fn write<W: io::Write>(&self, writer: &mut W) -> io::Result<()> {
    writer.write_all(self.key.to_bytes().as_ref())?;
    self.dleq.write(writer)
  }

  pub fn serialize(&self) -> Vec<u8> {
    let mut buf = vec![];
    self.write(&mut buf).unwrap();
    buf
