Based on my investigation, I found a real analog to the ReserveLogic bug class — a cumulative-average price oracle that uses an unbounded, ever-decaying-weight formula, allowing a single large-volume "legitimate" fill to permanently poison the oracle used to price subsequent economic settlements.

### Title
`VWAPOracle.recordSpread`/`spread()` — unbounded cumulative average lets a single fill permanently anchor the price used for phantom-order valuation - (File: `evm/src/utils/VWAPOracle.sol`)

### Summary
`VWAPOracle` maintains a running weighted-average "spread" per `(sourceChain, token)`, `spread = weightedSpreadSum / totalVolume`, accumulated forever with no decay, no window, and no cap on a single fill's weight [1](#0-0) . `recordSpread` is restricted to `_intentGateway` (the Simplex-style filler/solver settlement path), and every fill — regardless of size — is folded into the cumulative sum with `weightedSpread = spreadBps * inputAmountNormalized` [2](#0-1) .

### Finding Description
This mirrors the Yieldoor bug's core defect: a state used to price/settle future economic actions is derived from an accumulator that assumes past composition stays representative, but the accumulator can be driven arbitrarily by a single large interaction, and subsequent (unrelated, honest) activity cannot meaningfully correct it because volumes compound additively without any time decay or capping (`data.totalVolume += volume` forever) [3](#0-2) . Once a party pushes one outsized fill through `recordSpread` (a normal, permissionless intent fill through the gateway, not a privileged/relayer/prover action), the lifetime average is permanently shifted toward that fill's spread; every future call to `spread()` — consumed downstream to price real orders via `PhantomSnapshotIntentQuoteStrategy.quoteSnapshot` (`amountOut = netAmountIn * medianPrice / standardAmount`) [4](#0-3)  — inherits that skew. There is no `restrict` on volume size, no windowing (`lastUpdate` is stored but never used to decay or discard old contributions) [5](#0-4) , and no minimum sample count before `spread()` is trusted (a single fill after `init` already returns a live-looking, non-zero-confidence value).

### Impact Explanation
Because the quote strategy directly multiplies user input by this manipulated cumulative spread/price to compute settlement `amountOut`, a permanently skewed average causes systematically wrong-amount settlement for every subsequent order priced off that `(chain, token)` pair — a form of transaction/logic manipulation matching the bounty's "transaction manipulation / logic attacks" class, since the corrupted value (`spread`) directly determines fund movement amounts in the intent-settlement path, not merely an off-chain indexer statistic.

### Likelihood Explanation
The action that poisons state — calling through `_intentGateway`'s normal fill flow, which invokes `recordSpread` — is available to any ordinary filler/solver settling real orders (not a relayer, prover, or privileged admin), and requires no malicious peer collusion, only capital to push one large, self-favorable fill through the gateway once. This satisfies the "unprivileged attacker, public entrypoint" bar; the only limiting factor is capital size to produce a large `inputAmountNormalized`, but there is no cap enforced by the contract itself.

### Recommendation
Replace the unbounded lifetime accumulator with a bounded/windowed VWAP (e.g., ring buffer of recent fills, time-decayed weighting, or a per-fill volume cap relative to trailing average volume) so that a single fill cannot permanently dominate `weightedSpreadSum/totalVolume`, and require a minimum trailing volume/sample count before `spread()` is considered valid for pricing downstream settlements — analogous to fixing `ReserveLogic` by making the index reflect current, not stale/skewed, aggregate state.

### Proof of Concept
1. `VWAPOracle.init` is called with token decimals configured for a pair.
2. Attacker, acting as a filler/solver, executes one legitimate self-fill (or colludes on both legs) through `_intentGateway` with `inputAmountNormalized` many orders of magnitude larger than typical flow and a `spreadBps` favorable to the attacker (e.g., `outputAmountNormalized` slightly below `inputAmountNormalized`, capturing spread), driving `recordSpread` (`evm/src/utils/VWAPOracle.sol:170-216`).
3. `_tokenSpreads[chainHash][token].weightedSpreadSum` and `.totalVolume` are now dominated by this single fill: subsequent small honest fills barely move `spread()` (`evm/src/utils/VWAPOracle.sol:141-147`), as demonstrated by the existing test `testMultipleFills`/`testVWAPCalculation` showing volume-weighted dominance of larger fills [6](#0-5) .
4. All future calls to `PhantomSnapshotIntentQuoteStrategy.quoteSnapshot` for that pair compute `amountOut`/`amountIn` off the skewed `medianPrice`, systematically mis-pricing user settlements in the attacker's favor [7](#0-6) .

Note: I was not able to fully trace every downstream consumer of `VWAPOracle.spread()` (only found the phantom-snapshot quote strategy) or confirm whether any additional bound/sanity check exists further downstream at settlement time that would clamp the effect of a skewed quote — if such a check exists, it would materially reduce the impact and should be verified against the full `IntentGatewayV2`/`IntentsBase` settlement path before treating this as fully exploitable.

    function spread(bytes memory sourceChain, address token) external view returns (int256) {
        bytes32 chainHash = keccak256(sourceChain);
        CumulativeSpreadData memory data = _tokenSpreads[chainHash][token];
        if (data.totalVolume == 0) return 0;

        return data.weightedSpreadSum / int256(data.totalVolume);
    }

	private quoteSnapshot(
		params: QuoteIntentParams,
		protocolFeeBps: bigint,
		snapshot: PhantomOrderPriceSnapshot,
	): PhantomSnapshotQuoteIntentResult {
		if (params.amountIn !== undefined) {
			const netAmountIn = deductProtocolFee(params.amountIn, protocolFeeBps)
			const amountOut = (netAmountIn * snapshot.medianPrice) / snapshot.standardAmount
			if (amountOut <= 0n) {
				throw new InvalidPhantomSnapshotError(snapshot.commitment, "quote rounds down to zero output")
			}
			return this.buildResult("EXACT_INPUT", params.amountIn, amountOut, protocolFeeBps, snapshot)
		}

		if (params.amountOut === undefined) throw new Error("Quote amount is missing after validation")
		const netAmountIn = divCeil(params.amountOut * snapshot.standardAmount, snapshot.medianPrice)
		const amountIn = grossUpForProtocolFee(netAmountIn, protocolFeeBps)
		return this.buildResult("EXACT_OUTPUT", amountIn, params.amountOut, protocolFeeBps, snapshot)
	}
