## Analysis Summary

Reducing the external report to its core invariant: **a "verification"/"preview" function is trusted by downstream code to attest that computed/derived state matches actual on-chain state, but it never actually incorporates the security-critical raw data (there, `lendAssets`; here, actual bytecode) needed to make that guarantee true.**

The strongest Aptos-native analog is in the package-verification tooling: `aptos move verify-package` claims to verify that on-chain bytecode matches a local source tree, but its underlying check never actually compares committed module bytecode.

### Title
`VerifyPackage` reports success without ever comparing on-chain module bytecode to compiled bytecode - (File: aptos-move/cli/src/stored_package.rs)

### Summary
The `aptos move verify-package` CLI command is documented as checking "that on-chain bytecode matches a local source tree" [1](#0-0)  but its implementation only ever compares `PackageMetadata` fields (name, deps, module metadata, manifest, upgrade policy, extension, and a source-file digest) — it never fetches or diffs the actually committed module bytecode.

### Finding Description
`VerifyPackage::execute` builds the local package, then creates a `CachedPackageRegistry` with the bytecode-fetch flag hardcoded to `false`, and finally calls `package.verify(&compiled_metadata)`: [2](#0-1) 

`CachedPackageRegistry::create` only downloads real module bytecode into its internal `bytecode` map when `with_bytecode` is `true`; since `VerifyPackage` always passes `false`, `get_bytecode()` is never populated and never consulted anywhere in the verify flow: [3](#0-2) [4](#0-3) 

`CachedPackageMetadata::verify` then only compares `name`, `deps`, `modules` (metadata: source blob/source map, not code), `manifest`, `upgrade_policy`, `extension`, and `source_digest`: [5](#0-4) 

Crucially, `source_digest` is derived purely from the **Move source files** of the package, not from the compiled bytecode that is actually committed on-chain via `code::publish_package`'s `code: vector<vector<u8>>` argument: [6](#0-5) 

Since the on-chain `PackageMetadata` stored in `PackageRegistry` (name, deps, modules, manifest, policy, source_digest) is entirely attacker-controlled metadata separate from the raw module bytes that were actually verified/loaded by the VM (`request_publish`/`request_publish_with_allowed_deps` take the raw `bundle`/`code` argument independently of the metadata resource) [7](#0-6) , a publisher can submit metadata (including embedded source and a matching source digest) describing one, benign package while the actual bytecode bytes committed to the account/object are a different, malicious module. `aptos move verify-package` will report `"Successfully verified source of package"` in this case because it never inspects the real deployed bytecode.

### Impact Explanation
This breaks the "Mismatch between verified bytes, package metadata, dependency declarations, and committed module bytes" invariant. Third parties (auditors, integrators, users deciding whether to interact with or depend on a package) who run `aptos move verify-package` to confirm that on-chain code matches reviewed/audited source receive a false attestation of integrity. A malicious or compromised package owner (for `compatible`-policy packages, which are explicitly the ones expected to be depended upon and periodically re-verified) can publish arbitrary bytecode while metadata continues to "verify" against a benign source tree, undermining the code-safety guarantee that the tooling is meant to provide for the ecosystem's dependency trust model.

### Likelihood Explanation
High likelihood of triggering the false-positive: any package owner controls both the on-chain `PackageMetadata` and the on-chain module bytecode bytes independently (they are separate arguments to the publish natives), and the CLI's default/only verification path (`with_bytecode = false`) is hardcoded, so there is no way for a user of `verify-package` to opt into real bytecode comparison. No special privilege is required beyond being the package owner performing (or having previously performed) a normal, permissionless publish/upgrade.

### Recommendation
`VerifyPackage::execute` should call `CachedPackageRegistry::create(client, self.account, true)` to fetch actual on-chain bytecode, and `verify()` should additionally compare each module's fetched bytecode against the freshly compiled bytecode (byte-for-byte or via a hash), not merely compare `PackageMetadata` fields. The `source_digest` should not be conflated with a bytecode-integrity guarantee, and documentation should not claim byte-level bytecode verification unless it is actually performed.

### Proof of Concept
1. Attacker authors a benign Move package `P` and publishes it under `compatible` policy via `aptos move publish`, embedding source for `P` in metadata.
2. Attacker (or a subsequent upgrade with the same owner) crafts the on-chain publish transaction's `code: vector<vector<u8>>` bundle to contain different, malicious bytecode while keeping `PackageMetadata` (including the gzipped source, source digest, module names) referencing the original benign source of `P` — permitted because `code::publish_package` never checks that `code` was actually compiled from `pack.manifest`/`pack.modules[].source`, only that module names match `expected_modules` [8](#0-7) .
3. A third party runs `aptos move verify-package --account <attacker> --package-dir <local copy of benign source>`.
4. `VerifyPackage::execute` builds `compiled_metadata` from the benign local source, fetches `PackageMetadata` only (`with_bytecode=false`), and calls `verify()`, which succeeds because all compared metadata fields match the benign source's metadata [9](#0-8) .
5. Command prints `"Successfully verified source of package"` even though the actual deployed bytecode differs entirely from the benign source, giving the third party false assurance of code integrity.

impl CachedPackageRegistry {
    /// Creates a new registry.
    pub async fn create(
        client: Client,
        addr: AccountAddress,
        with_bytecode: bool,
    ) -> anyhow::Result<Self> {
        // Need to use a different type to deserialize JSON
        let inner = client
            .get_account_resource_bcs::<PackageRegistry>(addr, "0x1::code::PackageRegistry")
            .await?
            .into_inner();
        let mut bytecode = BTreeMap::new();
        if with_bytecode {
            for pack in &inner.packages {
                for module in &pack.modules {
                    let bytes = client
                        .get_account_module(addr, &module.name)
                        .await?
                        .into_inner()
                        .bytecode
                        .0;
                    bytecode.insert(module.name.clone(), bytes);
                }
            }
        }
        Ok(Self { inner, bytecode })
    }

    pub fn verify(&self, package_metadata: &PackageMetadata) -> anyhow::Result<()> {
        let self_metadata = self.metadata;

        if self_metadata.name != package_metadata.name {
            bail!(
                "Package name doesn't match {} : {}",
                package_metadata.name,
                self_metadata.name
            )
        } else if self_metadata.deps != package_metadata.deps {
            bail!(
                "Dependencies don't match {:?} : {:?}",
                package_metadata.deps,
                self_metadata.deps
            )
        } else if self_metadata.modules != package_metadata.modules {
            bail!(
                "Modules don't match {:?} : {:?}",
                package_metadata.modules,
                self_metadata.modules
            )
        } else if self_metadata.manifest != package_metadata.manifest {
            bail!(
                "Manifest doesn't match {:?} : {:?}",
                package_metadata.manifest,
                self_metadata.manifest
            )
        } else if self_metadata.upgrade_policy != package_metadata.upgrade_policy {
            bail!(
                "Upgrade policy doesn't match {:?} : {:?}",
                package_metadata.upgrade_policy,
                self_metadata.upgrade_policy
            )
        } else if self_metadata.extension != package_metadata.extension {
            bail!(
                "Extensions doesn't match {:?} : {:?}",
                package_metadata.extension,
                self_metadata.extension
            )
        } else if self_metadata.source_digest != package_metadata.source_digest {
            bail!(
                "Source digests doesn't match {:?} : {:?}",
                package_metadata.source_digest,
                self_metadata.source_digest
            )
        }

        Ok(())
    }
