### Title
Value sent to the `distribution` precompile's non-payable-unchecked `rewards()` view method is permanently stranded - (File: `precompiles/distribution/distribution.go`)

### Summary
The `rewards()` view method of the distribution precompile (address `0x0000000000000000000000000000000000001007`) is dispatched without the `ValidateNonPayable` guard that every other view/transaction method in the same `Execute` switch uses, and without ever calling `HandlePaymentUsei` to refund a caller-supplied `value`. A caller that sends native value together with a `rewards()` call will have that value's usei/wei moved into the precompile's account balance by the EVM's normal value-transfer semantics, and since the precompile module has no mechanism to sweep or return funds sitting on its address, that value is permanently locked, mirroring the `MarginAccount`→`InsuranceFund` stuck-asset issue in the referenced report.

### Finding Description
`PrecompileExecutor.Execute` in `precompiles/distribution/distribution.go` dispatches methods as follows: [1](#0-0) 
Every transaction method (`setWithdrawAddress`, `withdrawDelegationRewards`, `withdrawValidatorCommission`, etc.) either calls `pcommon.ValidateNonPayable(value)` directly, or its inner handler is expected to call `pcommon.HandlePaymentUsei` to refund any accidentally attached value back to the payer: [2](#0-1) [3](#0-2) 

However, `case RewardsMethod: return p.rewards(ctx, method, args)` is dispatched with no `ValidateNonPayable` check and no payment handling at all: [4](#0-3) 

The integration test suite explicitly documents this quirk: [5](#0-4) 

Because the EVM's native value-transfer mechanism moves `usei`/`wei` from the caller into the precompile's backing account (the `AccAddress` associated with `0x...1007`) before/around the precompile `Run`, a value-bearing `rewards()` call succeeds (there is no `ValidateNonPayable` to reject it) but the executor never forwards, credits, or refunds that value to anyone. Unlike the `HandlePaymentUsei` path used elsewhere, which immediately sends the payment coin back to `payer`, this method leaves the coin/wei balance sitting under the precompile's account. There is no admin, governance, or user-facing function anywhere in the distribution precompile (or the underlying `x/distribution` module) that lets funds be swept out of that address — precompile addresses are not addressable through ordinary `MsgSend` flows in the same way a normal account is, and no code path retrieves value parked there.

### Impact Explanation
Any unprivileged EVM caller (contract or EOA) who mistakes `rewards()` for a payable/no-op function, or who is tricked by a malicious frontend/contract into sending value with this call, permanently loses that value: it becomes unspendable and unrecoverable usei/wei, a direct and irreversible loss of user funds with no governance-level sweep function available, unlike the upstream MarginAccount/InsuranceFund case where the report's own mitigating factor (an upgradeable contract that can later add a sweep) does not apply here since precompiles are compiled into the chain binary and adding a sweep requires a full chain upgrade.

### Likelihood Explanation
The call is trivially reachable by any address capable of sending an EVM transaction to `0x0000000000000000000000000000000000001007` with calldata for `rewards(address)` and non-zero `msg.value` — no special privilege, precondition, or association state is required (the `rewards` case runs before any auth checks and is one of the few methods without the non-payable guard). This makes exploitation straightforward, whether accidental (wallet/dApp UX error) or via a malicious contract that forwards user-supplied value into this call.

### Recommendation
Add `pcommon.ValidateNonPayable(value)` to the `RewardsMethod` case in `precompiles/distribution/distribution.go` (and audit all other precompile `Execute` switches for the same omission across `legacy/v552`, `v575`, `v600`, `v614`, etc.), rejecting any `rewards()` call that carries non-zero value instead of silently accepting and stranding it. As defense in depth, consider adding a generic guard in the shared precompile dispatch path (`precompiles/common/precompiles.go`) that automatically refunds unclaimed value for any view-only method that neither validates non-payable nor explicitly handles payment.

### Proof of Concept
1. Deploy or use any EVM account with an associated Sei address holding usei.
2. Call `IDistr(0x0000000000000000000000000000000000001007).rewards{value: X}(anyDelegatorAddress)` for any nonzero `X`.
3. Observe: (a) no revert occurs because `RewardsMethod` skips `ValidateNonPayable`; (b) the value `X` is debited from the caller by normal EVM value-transfer semantics; (c) the executor's `rewards()` handler never calls `bankKeeper.SendCoins` or any equivalent to route the funds back to the caller (see `precompiles/distribution/distribution.go` lines 204-205); (d) the caller's balance is permanently reduced by `X` with no reachable function to recover it.

func ValidateNonPayable(value *big.Int) error {
	if value != nil && value.Sign() != 0 {
		return errors.New("sending funds to a non-payable function")
	}

	return nil
}

func HandlePaymentUsei(ctx sdk.Context, precompileAddr sdk.AccAddress, payer sdk.AccAddress, value *big.Int, bankKeeper utils.BankKeeper, evmKeeper utils.EVMKeeper, hooks *tracing.Hooks, depth int) (sdk.Coin, error) {
	usei, wei := state.SplitUseiWeiAmount(value)
	if !wei.IsZero() {
		return sdk.Coin{}, fmt.Errorf("selected precompile function does not allow payment with non-zero wei remainder: received %s", value)
	}
	coin := sdk.NewCoin(sdk.MustGetBaseDenom(), usei)
	// refund payer because the following precompile logic will debit the payments from payer's account
	// this creates a new event manager to avoid surfacing these as cosmos events
	if err := bankKeeper.SendCoins(ctx.WithEventManager(sdk.NewEventManager()), precompileAddr, payer, sdk.NewCoins(coin)); err != nil {
		return sdk.Coin{}, err
	}
	if hooks != nil {
		newCtx := ctx.WithGasMeter(sdk.NewInfiniteGasMeterWithMultiplier(ctx))
		if hooks.OnEnter != nil {
			hooks.OnEnter(depth+1, byte(vm.CALL), evmKeeper.GetEVMAddressOrDefault(newCtx, precompileAddr), evmKeeper.GetEVMAddressOrDefault(newCtx, payer), []byte{}, GetRemainingGas(newCtx, evmKeeper), value)
		}
		if hooks.OnExit != nil {
			hooks.OnExit(depth+1, []byte{}, 0, nil, false)
		}
	}
	return coin, nil
}
