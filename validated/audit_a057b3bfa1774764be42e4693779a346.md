### Title
Scanner reports unspendable dust outputs as received funds, enabling an unprivileged sender to pollute the wallet's input set and burn value to fees - (File: networks/bitcoin/src/wallet/mod.rs)

### Summary
The external report describes funds being pushed to an unvalidated, attacker-chosen destination, where receiving itself is the dangerous act. The analog in Serai's in-scope code is the mirror image: `Scanner::scan_transaction` accepts *any* on-chain output paying to a registered script as an owned `ReceivedOutput`, with no validation of whether the output can ever be economically spent. An unprivileged party can send dust-value P2TR outputs to the wallet's script, and the wallet will report them as received funds and later accept them as transaction inputs, where each costs more in fee than its face value.

### Finding Description
`Scanner::scan_transaction` matches purely on `output.script_pubkey` and unconditionally pushes a `ReceivedOutput` carrying the output's full `value` for every match — there is no minimum-value check. `ReceivedOutput::value()` then reports this dust as part of the wallet's received balance. Downstream, `SignableTransaction::new` enforces `DUST` (546 sats) only on *payments* (`if *amount < DUST { Err(TransactionError::DustPayment) }`), never on inputs: it sums `input.output.value` into `input_sat` and copies every supplied `ReceivedOutput` into `tx_ins`/`prevouts` unconditionally.

Each added Taproot input costs roughly 57.5 vbytes to spend. At any non-trivial `fee_per_vbyte`, an input worth less than ~a few hundred sats is net-negative: it contributes less to `input_sat` than the marginal fee it adds to `needed_fee`. An attacker who sends a 1–546 sat output to the victim's P2TR address creates a `ReceivedOutput` the scanner reports as received value that can never be spent for net gain — funds received but not spendable — and if the caller includes it (e.g., automatic UTXO consumption), the transaction silently converts the difference into miner fees.

### Impact Explanation
- Reported balance inflation: `Scanner`/`ReceivedOutput` attest to funds the wallet cannot economically claim.
- Fee burn: integrating these outputs into `SignableTransaction` makes the signer produce valid signatures for transactions whose input cost exceeds input value, destroying wallet funds proportional to attacker-spent dust (attacker spends ~546 sats to burn an equivalent-or-greater amount of the victim's fees, repeatedly and cheaply).
- UTXO-set pollution scales linearly with attacker transactions; there is no filtering or eviction path in-scope.

### Likelihood Explanation
Any unprivileged party can reach this path with only public inputs — a Bitcoin transaction they send — matching exactly the allowed reachability model. The only prerequisite is knowledge of the victim's P2TR script, which is public (it appears on-chain as soon as the wallet receives or spends anything, and external/deposit addresses are meant to be shared). No collusion, malicious validator, or leaked key is required. The processor-side code does apply an `N::DUST` filter, but the in-scope wallet `Scanner` is itself a public API that other integrators use directly, and the wallet layer is where the false "received funds" claim originates.

### Recommendation
- Apply a minimum-value filter in `Scanner::scan_transaction` (or at `ReceivedOutput` construction) rejecting outputs below `send::DUST` (or a fee-rate-aware spendability threshold), consistent with how downstream code treats dust payments.
- Additionally, in `SignableTransaction::new`, reject or warn on inputs whose `output.value` is below the marginal fee cost of spending a Taproot input at the requested `fee_per_vbyte` (`fee_per_vbyte * ~58`), so a dust input can never make it into the signed `Prevouts::All` commitment.

### Proof of Concept
Conceptual, against in-scope APIs only:

```rust
// Victim wallet scanner for group key K (external address publicly known)
let mut scanner = Scanner::new(K).unwrap();

// Attacker crafts and broadcasts a tx with an output paying 330 sats
// (< DUST) to p2tr_script_buf(K)
let tx = attacker_tx_with_dust_output_to(K_script, 330);

// Wallet scans it
let outputs = scanner.scan_transaction(&tx);
assert_eq!(outputs.len(), 1);            // reported as received
assert_eq!(outputs[0].value(), 330);     // counted toward balance

// Later, wallet/integrator builds a spend including it
let stx = SignableTransaction::new(
    vec![outputs[0].clone()],            // dust input accepted without check
    &payments,
    Some(change),
    None,
    fee_per_vbyte,                       // e.g. 10 sat/vb
).unwrap();

// The Taproot input adds ~57.5 vb => ~575 sats of fee for a 330-sat input:
// net -245 sats burned to fees, and stx.multisig(keys) will happily produce
// a valid threshold signature committing to it via Prevouts::All.
```

The code paths are: `Scanner::scan_transaction` matching only `script_pubkey` (networks/bitcoin/src/wallet/mod.rs:199-214), `ReceivedOutput::value` reporting the full amount (mod.rs:115-118), and `SignableTransaction::new` dust-checking payments only while unconditionally accepting all supplied inputs (networks/bitcoin/src/wallet/send.rs:165-185).
