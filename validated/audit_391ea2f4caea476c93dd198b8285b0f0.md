### Title
Unauthenticated `x-github-client://openRepo` deep link silently fetches and checks out an attacker-chosen branch in an already-open repository, bypassing the clone-confirmation UI - ([File: app/src/ui/dispatcher/dispatcher.ts])

### Summary
The H1 report exploits a trust boundary mismatch: an action that is supposed to require a confirmed/gated step (email confirmation before store creation) can instead be completed through a second, less-guarded endpoint that only checks for a bearer token, not for the confirmation state. The Desktop analog is the `open-repository-from-url` deep-link action. For a *new* repository this action correctly routes through a confirmation `CloneRepository` popup, but for a repository the user *already has open* (matched only by comparing the GitHub repo's `htmlURL`/parent `htmlURL` to the URL embedded in the link), the code skips any popup, and — if a `branch` parameter is present — automatically fetches and checks out that branch in the user's real, already-open repository, all triggered purely by the user clicking a crafted link.

### Finding Description
`parseAppURL` accepts `x-github-client://openRepo/<url>?branch=<name>` links and only validates the branch string against `testForInvalidChars` (illegal ref characters), not against any policy of trust or user intent: [1](#0-0) 

`Dispatcher.dispatchURLAction` routes `open-repository-from-url` actions directly to `openRepositoryFromUrl`, with no gating step: [2](#0-1) 

`openRepositoryFromUrl` branches on the presence of `branch`, calling `openBranchNameFromUrl`: [3](#0-2) 

`openBranchNameFromUrl` calls `openOrCloneRepository`, then unconditionally fetches and checks out the branch: [4](#0-3) 

The critical branch is inside `openOrCloneRepository`: if an existing repository in the user's repo list matches the URL (via `doesRepositoryMatchUrl`, which only compares `origin`/`upstream` `htmlURL` strings — trivially satisfied by any link pointing at a repo the user already has cloned, e.g. their employer's or a public OSS repo they contribute to), the function *silently selects it and returns* — no `CloneRepository` popup, no user confirmation of any kind: [5](#0-4) [6](#0-5) 

Only for a brand-new repository does the code go through the "confirmation" branch, `showPopup({ type: PopupType.CloneRepository, ... })`, which is the deliberate user-facing gate that exists precisely so a user must consciously approve adding/cloning a repository. That gate is completely bypassed for the "repository already exists" case — exactly analogous to the H1 report where the intended gate (confirmed email) was bypassed by hitting the endpoint that only checked for a valid session/token, not the completed-confirmation state.

Once the existing repo is silently selected, `openBranchNameFromUrl` proceeds without any prompt: it force-fetches the remote and calls `checkoutLocalBranch`, switching the user's working directory to a branch of the attacker's choosing: [7](#0-6) 

### Impact Explanation
An attacker who knows (or guesses, e.g., via a public OSS project) the URL of a repository the victim already has open in Desktop can craft a link such as `x-github-client://openRepo/https://github.com/org/private-repo?branch=malicious-branch` and get the victim to click it (e.g., embedded in a webpage, chat message, or GitHub issue comment referencing "Open in Desktop"). Desktop will, with no dialog and no visible confirmation:
1. Select the victim's existing local checkout of that repository (bringing it to the foreground / making it the active repo in the UI).
2. Force a fetch of the remote.
3. Silently `git checkout` an attacker-named branch.

This can be used to switch the developer's working tree to a branch containing malicious build scripts, pre/post-checkout hooks, or altered source code that will subsequently be built/run by the victim, without a "Clone repository?" or "switch branch?" confirmation ever being shown — a silent corruption of what the user has open and will commit/build/push next. It also discards the mental model that a branch checkout only happens deliberately inside the app.

### Likelihood Explanation
The protocol handler is registered by the packaged app for `x-github-client`, `x-github-desktop-auth`/`x-github-desktop-dev-auth`, and legacy `github-mac`/`github-windows` schemes and is invoked automatically by the OS when a link is clicked, with `handleAppURL`/`open-url`/`--protocol-launcher` wiring in `main.ts`: [8](#0-7) [9](#0-8) 

No user interaction beyond a single link click is required, and the "repository already exists" branch requires no additional confirmation step, making the attack straightforward to trigger for any developer who has the targeted repository already cloned (a very common condition for OSS contributors or employees of an org).

### Recommendation
- Require an explicit confirmation dialog (similar to `PopupType.CloneRepository`) before fetching and checking out a branch supplied via `open-repository-from-url`, even when the repository already exists locally.
- Treat `branch`/`pr`/`filepath` parameters from deep links as untrusted regardless of whether the target repository matches an existing one; surface the target branch name to the user and require an explicit "Switch branch" confirmation rather than performing the checkout automatically.
- Consider stashing/warning about uncommitted changes before an automatic checkout triggered by an external URL.

### Proof of Concept
1. Victim has already cloned `https://github.com/org/repo` in GitHub Desktop.
2. Attacker crafts a link: `x-github-client://openRepo/https://github.com/org/repo?branch=attacker-branch` (where `attacker-branch` exists on the remote, e.g. pushed by attacker if they have push access to a fork/branch, or is any branch name matching `pr/\d+` format tied to a PR).
3. Victim clicks the link (e.g. from a webpage or chat client that renders it, or via "Open in Desktop" flow abuse).
4. OS invokes Desktop via the registered protocol handler → `handleAppURL` → `dispatchURLAction` → `openRepositoryFromUrl` → `openOrCloneRepository` finds the existing repository match and returns it directly (no popup) → `openBranchNameFromUrl` fetches and calls `checkoutLocalBranch`, switching the victim's working directory to `attacker-branch` with zero confirmation dialogs shown.   private doesRepositoryMatchUrl(
    repo: Repository | CloningRepository,
    url: string
  ): repo is RepositoryWithGitHubRepository {
    if (repo instanceof Repository && isRepositoryWithGitHubRepository(repo)) {
      const originRepoUrl = repo.gitHubRepository.htmlURL
      const upstreamRepoUrl = repo.gitHubRepository.parent?.htmlURL ?? null

      if (originRepoUrl !== null && urlsMatch(originRepoUrl, url)) {
        return true
      }

      if (upstreamRepoUrl !== null && urlsMatch(upstreamRepoUrl, url)) {
        return true
      }
    }

    return false
  }

  private async openBranchNameFromUrl(
    url: string,
    branchName: string
  ): Promise<Repository | null> {
    const repository = await this.openOrCloneRepository(url)

    if (repository === null) {
      return null
    }

    // ensure a fresh clone repository has it's in-memory state
    // up-to-date before performing the "Clone in Desktop" steps
    await this.appStore._refreshRepository(repository)

    // if the repo has a remote, fetch before switching branches to ensure
    // the checkout will be successful. This operation could be a no-op.
    await this.appStore._fetch(repository, FetchType.UserInitiatedTask)

    await this.checkoutLocalBranch(repository, branchName)

    return repository
  }

  private async openOrCloneRepository(url: string): Promise<Repository | null> {
    const state = this.appStore.getState()
    const repositories = state.repositories
    const existingRepository = repositories.find(r =>
      this.doesRepositoryMatchUrl(r, url)
    )

    if (existingRepository) {
      return await this.selectRepository(existingRepository)
    }

    return this.appStore._startOpenInDesktop(() => {
      this.changeCloneRepositoriesTab(CloneRepositoryTab.Generic)
      this.showPopup({
        type: PopupType.CloneRepository,
        initialURL: url,
      })
    })
  }
