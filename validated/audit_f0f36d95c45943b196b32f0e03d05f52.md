### Title
Delegating via the staking precompile with an amount below the validator's tokens-per-share exchange rate silently truncates issued shares to zero, permanently locking the delegator's usei with no recoverable stake - (File: `precompiles/staking/staking.go`, `sei-cosmos/x/staking/types/validator.go`, `sei-cosmos/x/staking/keeper/delegation.go`)

### Summary
The staking precompile's `delegate` function converts the EVM `value` field (wei) into a `usei` `Coin` and forwards it as a `MsgDelegate` with no minimum-amount or minimum-shares-issued check. The underlying `Keeper.Delegate` calls `Validator.AddTokensFromDel`, which computes issued shares via `SharesFromTokens` using integer (truncating) division. If the caller delegates a small enough `usei` amount relative to the validator's current `DelegatorShares/Tokens` exchange rate, the computed shares truncate to zero, yet the full `bondAmt` of `usei` is still deducted from the delegator and moved into the bonded/not-bonded pool. This is the same bug class as the reported "mint a position for 0 MgCVG/YSCVG" issue: a positive, non-zero amount is accepted and consumed, but the recipient receives a zero-valued accounting unit in return.

### Finding Description
The EVM-reachable path is:
- `precompiles/staking/staking.go` `delegate()` → `delegateFor()` builds a `stakingtypes.MsgDelegate` from the caller-supplied EVM `value`, only requiring `value.Sign() != 0` [1](#0-0) . There is no check that the resulting delegation will actually issue non-zero shares.
- `msg.ValidateBasic()` and the keeper's `Delegate` (via `directStakingExecutor`) are then invoked [2](#0-1) [3](#0-2) .
- `sei-cosmos/x/staking/keeper/delegation.go` `Delegate()` deducts `bondAmt` from the delegator's account into the bonded/not-bonded pool via `DelegateCoinsFromAccountToModule`, then calls `AddValidatorTokensAndShares` to compute `newShares` [4](#0-3) .
- `AddTokensFromDel` computes `SharesFromTokens(amount)` when the validator already has shares: `v.GetDelegatorShares().MulInt(amt).QuoInt(v.GetTokens())` [5](#0-4) [6](#0-5) . `QuoInt` performs truncating integer division with no minimum-output check.
- Because every successive `AddTokensFromDel` truncates shares downward, a validator's `DelegatorShares` accumulate slightly less than 1:1 with `Tokens` over many delegations, driving the exchange rate below 1 share/usei. Once that ratio is unfavorable enough, a delegator sending a small enough `usei` amount (e.g., 1 usei, or any amount `< Tokens/DelegatorShares`) has `newShares` truncate to exactly zero.
- The keeper does not reject `newShares.IsZero()`; it unconditionally does `delegation.Shares = delegation.Shares.Add(newShares)` and persists the delegation and updated validator state, and the function returns `nil` error to the caller [7](#0-6) .
- The precompile then reports success (`method.Outputs.Pack(true)`) and emits a `Delegate` EVM event [8](#0-7) , giving the caller no on-chain signal that they received nothing in return for their transferred usei.

There is no `MinSelfDelegation`/minimum-delegation amount check enforced in the actual `Delegate` message handling path (`sei-cosmos/x/staking/keeper/msg_server.go` `Delegate()` only validates the validator exists, the denom matches, and forwards to `Keeper.Delegate`) [9](#0-8) , even though the staking spec documentation states this should fail "if the amount delegated is less than the minimum allowed delegation" [10](#0-9)  — that documented invariant is not actually implemented in code.

### Impact Explanation
The delegator's `usei` is irrevocably transferred to the bonded/not-bonded pool module account, but the delegator's `Delegation.Shares` for that validator does not increase (0 shares added). The delegator has no `Shares` corresponding to the transferred tokens and thus no mechanism (`Undelegate`, `BeginRedelegate`) to reclaim the deposited `usei` — it becomes stranded inside the pool, effectively permanently lost to the depositor while being attributed (via `validator.Tokens`) to the validator's total stake/voting power without a matching claim. This is a concrete, permanent loss of user funds reachable purely through a public EVM transaction to the staking precompile (`0x0000000000000000000000000000000000001005`), which satisfies the "concrete fund loss or permanent freezing" criterion.

### Likelihood Explanation
Exploitability requires a validator whose `DelegatorShares/Tokens` ratio has drifted below 1 (or below the specific small delegation amount threshold) through repeated truncation from many small delegations over the validator's lifetime — an organically occurring condition for popular/long-lived validators, not an artificially engineered one. Any user (or the validator itself, to grief a specific victim by pointing them at a manipulated ratio) can trigger the truncation deterministically once the exchange rate crosses the threshold, by sending a `delegate()` call with a small enough `value`. Because the precompile is directly callable by any EVM account with no privileged access required, likelihood is Medium: it depends on validator-specific exchange-rate state but is trivially triggerable by a straightforward transaction once that state exists.

### Recommendation
1. In `Keeper.Delegate` (`sei-cosmos/x/staking/keeper/delegation.go`), reject delegations where `newShares.IsZero()` after `AddValidatorTokensAndShares`, returning an error instead of silently persisting a zero-share delegation.
2. Enforce the documented minimum-delegation-amount invariant in `MsgDelegate` handling (`sei-cosmos/x/staking/keeper/msg_server.go`) as described in `spec/03_messages.md`.
3. Apply the same zero-shares guard in the staking precompile's `delegateFor`/`redelegateFor` paths (`precompiles/staking/staking.go`) before reporting success and emitting the `Delegate` EVM event, so that transactions issuing zero shares revert rather than silently consuming the caller's usei.

### Proof of Concept
Conceptual PoC (cannot be executed without live state, but derivable from the code paths cited above):
1. Identify or engineer a validator `V` whose `DelegatorShares.QuoInt(Tokens)`-equivalent (i.e. `Tokens/DelegatorShares`) exceeds 1 usei per share — achievable naturally over time via many truncated small delegations, since `SharesFromTokens` always rounds down.
2. Call the staking precompile's `delegate(validatorAddr)` at `0x0000000000000000000000000000000000001005` with `value` set to `1 wei-equivalent usei` (i.e., an amount that maps to `usei = 1` after `SplitUseiWeiAmount`), from any EVM account associated with a Sei address holding at least 1 usei.
3. Observe: `HandlePaymentUsei` moves 1 usei from the caller to the staking module payer address, `MsgDelegate` succeeds, `Keeper.Delegate` moves the 1 usei into the bonded pool, but `AddTokensFromDel`→`SharesFromTokens` computes `DelegatorShares * 1 / Tokens`, which truncates to `0` given the validator's ratio.
4. Query the delegator's `Delegation` for validator `V` via the precompile's `delegation()` method: `Shares` is unchanged (or zero if it's a new delegation), while the caller's usei balance has decreased by 1 — the 1 usei is now stranded in the bonded pool with no corresponding claim.

func (p PrecompileExecutor) directStakingExecutor(ctx sdk.Context) stakingMessageExecutor {
	return func(msg sdk.Msg) error {
		switch msg := msg.(type) {
		case *stakingtypes.MsgDelegate:
			_, err := p.stakingKeeper.Delegate(sdk.WrapSDKContext(ctx), msg)
			return err
		case *stakingtypes.MsgBeginRedelegate:
			_, err := p.stakingKeeper.BeginRedelegate(sdk.WrapSDKContext(ctx), msg)
			return err
		case *stakingtypes.MsgUndelegate:
			_, err := p.stakingKeeper.Undelegate(sdk.WrapSDKContext(ctx), msg)
			return err
		default:
			return fmt.Errorf("unsupported staking message %T", msg)
		}
	}
}

// SharesFromTokens returns the shares of a delegation given a bond amount. It
// returns an error if the validator has no tokens.
func (v Validator) SharesFromTokens(amt sdk.Int) (sdk.Dec, error) {
	if v.Tokens.IsZero() {
		return sdk.ZeroDec(), ErrInsufficientShares
	}

	return v.GetDelegatorShares().MulInt(amt).QuoInt(v.GetTokens()), nil
}

// AddTokensFromDel adds tokens to a validator
func (v Validator) AddTokensFromDel(amount sdk.Int) (Validator, sdk.Dec) {
	// calculate the shares to issue
	var issuedShares sdk.Dec
	if v.DelegatorShares.IsZero() {
		// the first delegation to a validator sets the exchange rate to one
		issuedShares = amount.ToDec()
	} else {
		shares, err := v.SharesFromTokens(amount)
		if err != nil {
			panic(err)
		}

		issuedShares = shares
	}

	v.Tokens = v.Tokens.Add(amount)
	v.DelegatorShares = v.DelegatorShares.Add(issuedShares)

	return v, issuedShares
}

// Delegate defines a method for performing a delegation of coins from a delegator to a validator
func (k msgServer) Delegate(goCtx context.Context, msg *types.MsgDelegate) (*types.MsgDelegateResponse, error) {
	ctx := sdk.UnwrapSDKContext(goCtx)
	valAddr, valErr := sdk.ValAddressFromBech32(msg.ValidatorAddress)
	if valErr != nil {
		return nil, valErr
	}

	validator, found := k.GetValidator(ctx, valAddr)
	if !found {
		return nil, types.ErrNoValidatorFound
	}

	delegatorAddress, err := sdk.AccAddressFromBech32(msg.DelegatorAddress)
	if err != nil {
		return nil, err
	}

	bondDenom := k.BondDenom(ctx)
	if msg.Amount.Denom != bondDenom {
		return nil, sdkerrors.Wrapf(
			sdkerrors.ErrInvalidRequest, "invalid coin denomination: got %s, expected %s", msg.Amount.Denom, bondDenom,
		)
	}

	// NOTE: source funds are always unbonded
	newShares, err := k.Keeper.Delegate(ctx, delegatorAddress, msg.Amount.Amount, types.Unbonded, validator, true)
	if err != nil {
		return nil, err
	}
