### Title
Coinbase outputs reported as spendable ReceivedOutputs cause invalid spend transactions - (File: networks/bitcoin/src/wallet/mod.rs)

### Summary
The Tokemak report describes a funds-crediting mismatch: the user's payment (ETH) is converted into a balance owned by the contract, yet the protocol still tries to pull the asset from the user, so `mint` always reverts and the supplied funds are unusable. The Serai analog lives in `Scanner::scan_block` / `scan_transaction`, which report on-chain payments as `ReceivedOutput`s spendable by the multisig. `scan_block` scans `block.txdata` wholesale — including `txdata[0]`, the coinbase — so a coinbase output paying to the vault's P2TR script is reported as a received, spendable output even though consensus rules forbid spending it for 100 blocks.

### Finding Description
`Scanner::scan_transaction` iterates `tx.output` and pushes a `ReceivedOutput` for every output whose `script_pubkey` matches a registered script [1](#0-0) . `scan_block` calls it for every transaction in the block with no coinbase exclusion [2](#0-1) . The doc comment concedes the issue: "This will also scan the coinbase transaction which is bound by maturity. If received outputs must be immediately spendable, a post-processing pass is needed" — but no maturity metadata is recorded on the `ReceivedOutput` (it only carries `offset`, `output`, `outpoint`) [3](#0-2) , so downstream code cannot distinguish an immature coinbase output.

Downstream, `SignableTransaction::new` happily accepts these inputs [4](#0-3) , and `SignableTransaction::multisig`/`TransactionSignMachine::sign` produce FROST-signed transactions spending them [5](#0-4) . Any such transaction is consensus-invalid until maturity (100 blocks), while Serai's confirmation window is far shorter, so the scheduler will commit to a plan that can never broadcast — mirroring the report's "payment accepted, function always reverts" DOS.

### Impact Explanation
Any miner (an unprivileged party crafting a Bitcoin transaction) can set a coinbase output to the Serai vault/branch/forward address. Once scanned past `N::CONFIRMATIONS`, the processor reports the output as received funds; the scheduler then builds a `SignableTransaction` spending it. The signed transaction is rejected by every Bitcoin node for ~100 blocks, stalling the batch/payment plan that includes it — funds reported received that are not spendable, plus a signing-round DOS on whichever plan consumed the poisoned input. The test helper itself demonstrates the flow: it funds via `generatetoaddress`, then must "Mine until maturity" before the output is used [6](#0-5) .

### Likelihood Explanation
Requires a miner (or a party bribing one) to point a coinbase output at a Serai address — costly but permissionless. Exploitation probability is low-to-moderate; the code path is unconditional once such an output exists, since neither `scan_block` nor `ReceivedOutput` records maturity, and the processor's `get_outputs`/scheduler pipeline has no maturity filter in the in-scope code.

### Recommendation
In `scan_block` (and any caller consuming block-level scans), skip `block.txdata[0]` or tag `ReceivedOutput`s derived from coinbase transactions and withhold them from scheduling until maturity (100 confirmations). At minimum, perform the "post-processing pass" the comment requires inside the library rather than delegating it to integrators, so `ReceivedOutput` always denotes an immediately spendable UTXO.

### Proof of Concept
1. A miner mines a block whose coinbase transaction pays to `p2tr_script_buf(vault_key)` (the External script registered with `Scalar::ZERO` in `Scanner::new` [7](#0-6) ).
2. `Scanner::scan_block(&block)` returns a `ReceivedOutput` with `offset == Scalar::ZERO` and `outpoint == (coinbase_txid, vout)` — indistinguishable from a normal deposit.
3. The processor emits `ScannerEvent::Block` with this output; the scheduler calls `SignableTransaction::new(inputs, ...)` including it and the multisig signs the transaction successfully (the offset/parity check in `multisig` passes because the script legitimately matches [8](#0-7) ).
4. Broadcast fails on every node: coinbase inputs are immature until the coinbase is 100 blocks deep. The output is reported as received balance yet cannot be spent, and any plan including it produces a permanently invalid transaction until maturity — or forever if the input is mixed with time-sensitive payments.

Caveat: I could not fully confirm in this pass whether `Bitcoin::get_outputs` in `processor/src/networks/bitcoin.rs` adds its own coinbase/maturity filter before emitting outputs; if it already drops `txdata[0]` outputs or enforces a ≥100-block confirmation delay, the reachable impact collapses to the library-level footgun. The in-scope defect in `bitcoin_serai::wallet::Scanner` itself is confirmed.

  pub fn scan_transaction(&self, tx: &Transaction) -> Vec<ReceivedOutput> {
    let mut res = Vec::new();
    for (vout, output) in tx.output.iter().enumerate() {
      // If the vout index exceeds 2**32, stop scanning outputs
      let Ok(vout) = u32::try_from(vout) else { break };

      if let Some(offset) = self.scripts.get(&output.script_pubkey) {
        res.push(ReceivedOutput {
          offset: *offset,
          output: output.clone(),
          outpoint: OutPoint::new(tx.compute_txid(), vout),
        });
      }
    }
    res
  }

    let mut sigs = vec![];
    for i in 0 .. self.tx.input.len() {
      let offset = keys.clone().offset(self.offsets[i]);
      if p2tr_script_buf(offset.group_key())? != self.prevouts[i].script_pubkey {

async fn send_and_get_output(rpc: &Rpc, scanner: &Scanner, key: ProjectivePoint) -> ReceivedOutput {
  let block_number = rpc.get_latest_block_number().await.unwrap() + 1;

  rpc
    .rpc_call::<Vec<String>>(
      "generatetoaddress",
      serde_json::json!([
        1,
        Address::from_script(&p2tr_script_buf(key).unwrap(), Network::Regtest).unwrap()
      ]),
    )
    .await
    .unwrap();

  // Mine until maturity
  rpc
    .rpc_call::<Vec<String>>(
      "generatetoaddress",
      serde_json::json!([100, Address::p2sh(Script::new(), Network::Regtest).unwrap()]),
    )
    .await
    .unwrap();

  let block = rpc.get_block(&rpc.get_block_hash(block_number).await.unwrap()).await.unwrap();

  let mut outputs = scanner.scan_block(&block);
  assert_eq!(outputs, scanner.scan_transaction(&block.txdata[0]));

  assert_eq!(outputs.len(), 1);
  assert_eq!(outputs[0].outpoint(), &OutPoint::new(block.txdata[0].compute_txid(), 0));
  assert_eq!(outputs[0].value(), block.txdata[0].output[0].value.to_sat());

    outputs[0]
