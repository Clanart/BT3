### Title
Unauthenticated "GitHub host" classification lets an attacker-controlled remote spoof the credential-helper's GitHub sign-in prompt - (File: `app/src/lib/api.ts`)

### Summary
The `AccessControl.sol` bug is caused by treating a narrow, easily-forgeable identifier (`msg.sig`, a 4-byte value) as proof of a privileged role, without verifying its true origin. The same class of bug exists in GitHub Desktop's Git credential trampoline: whether a remote host is "a GitHub instance" (and therefore worthy of Desktop's native "Sign in to GitHub" credential prompt) is decided by a loose, unauthenticated string match on the hostname rather than a cryptographically or authoritatively verified identity, and this hostname is fully attacker-controlled via any git remote/submodule URL.

### Finding Description
`isGitHubHost()` in `app/src/lib/api.ts` classifies a URL as GitHub-owned using a short-circuiting series of heuristics before ever making a network round-trip: [1](#0-0) 

The critical line is:
```
if (/(^|\.)(github)\./.test(hostname)) {
  return true
}
```
This regex matches any hostname where the label `github` appears at the start or after a dot, e.g. `github.attacker-domain.com` or `evil.github.attacker.io` — domains the attacker fully owns and controls. There is no check against a real GitHub Enterprise certificate, DNS ownership, or the `x-github-request-id` verification that the function otherwise performs for unknown hosts (the network probe further below is only reached if this string check fails).

This classification feeds directly into the credential trampoline used for every `git fetch`/`clone`/`push`/submodule operation. `getEndpointKind()` in `app/src/lib/trampoline/trampoline-credential-helper.ts` calls `isGitHubHost()` as a fallback: [2](#0-1) 

When the endpoint is classified as `'enterprise'` (not `'generic'`) and no existing account matches, `getCredential()` automatically triggers Desktop's native "sign in to GitHub" UI for that attacker-controlled host: [3](#0-2) 

This mirrors the auth-collision report precisely: a small, guessable identifier space (`msg.sig` / hostname substring) is used as the sole gate for a privileged action (root authorization / triggering Desktop's trusted GitHub sign-in flow), and an external, attacker-supplied input (a new module's function name / a git remote or submodule URL) can be trivially crafted to collide with the trusted identifier ("ROOT" / "is a GitHub host").

### Impact Explanation
An attacker who controls any git remote that the victim adds, clones, forks, or that appears as a submodule URL (`.gitmodules`, or a URL embedded in a repository the victim clones) can register a domain such as `github.<attacker-domain>.com` and host a Git server there. When Desktop performs any authenticated Git operation against that remote, the trampoline will misclassify the host as an "enterprise" GitHub instance and pop Desktop's native "Sign in to GitHub" dialog — a dialog the user is conditioned to trust because it looks identical to genuine GHE authentication prompts. If the user completes sign-in (PAT entry or OAuth/browser-based flow), the resulting API validation/token exchange requests are sent to the attacker's endpoint (`getEnterpriseAPIURL(endpoint)`), which can capture the submitted personal access token or complete an OAuth binding to the attacker's server, effectively exfiltrating credentials/tokens and creating an unauthorized account binding to an attacker-controlled endpoint.

### Likelihood Explanation
Likelihood is credible but not automatic: the attack requires the victim to add or clone a repository containing a maliciously crafted remote/submodule URL and then to actively complete the resulting sign-in prompt. However, no local access, malware, or leaked credentials are required — only a crafted `.gitmodules` entry or remote URL that the victim's own Desktop instance processes, matching the "attacker controls a cloned/fetched repository or git remote" impact criteria. The prompt appears as part of a normal-looking Git operation (fetch/clone/submodule update), increasing the chance a user treats it as legitimate.

### Recommendation
- Remove or tighten the substring-based `/(^|\.)(github)\./` heuristic in `isGitHubHost()`; classification of "is this a GitHub Enterprise host" should not be based on hostname substrings that an attacker can register.
- Require the network-based verification (the `x-github-request-id` header check already implemented) as the authoritative signal, rather than a bypassable earlier heuristic.
- Before invoking `ui.promptForGitHubSignIn`, surface the exact hostname/endpoint prominently in the dialog so users can distinguish real GHE domains from lookalikes, and consider rate-limiting/confirming when the endpoint was derived from a just-cloned repository's remote/submodule rather than a user-typed value.

### Proof of Concept
1. Attacker registers `github.attacker-c2.example` and stands up a plain HTTP(S) Git server plus a minimal HTTP endpoint that responds to `/api/v3/...` requests (mimicking a GHE API).
2. Attacker publishes a public repository containing a `.gitmodules` entry (or simply asks the victim to clone/add a remote) pointing to `https://github.attacker-c2.example/foo/bar.git`.
3. Victim adds/clones the repository in Desktop and Desktop performs a submodule update or fetch requiring authentication (the malicious server returns a `401`/`WWW-Authenticate` challenge without a `realm="GitLab"`-style third-party marker).
4. `getEndpointKind()` reaches `isGitHubHost('https://github.attacker-c2.example/...')`; the hostname `github.attacker-c2.example` satisfies `/(^|\.)(github)\./`, short-circuiting to `true` → `'enterprise'`.
5. Since no existing account matches `getAPIEndpoint(endpoint)`, `getCredential()` calls `ui.promptForGitHubSignIn(endpoint)`, showing Desktop's native "Sign in to GitHub" dialog for the attacker's endpoint.
6. If the victim enters a PAT or completes the sign-in flow, the resulting HTTP request(s) go to `https://api.github.attacker-c2.example/...`, which is fully controlled by the attacker, capturing the credential.

Note: I was not able to execute this end-to-end in the sandbox (no runtime/git server available); the PoC path is derived directly from the code paths cited above.

/**
 * Attempts to determine whether or not the url belongs to a GitHub host.
 *
 * This is a best-effort attempt and may return `undefined` if encountering
 * an error making the discovery request
 */
export async function isGitHubHost(url: string) {
  const { hostname } = new window.URL(url)

  const endpoint =
    hostname === 'github.com' || hostname === 'api.github.com'
      ? getDotComAPIEndpoint()
      : getEnterpriseAPIURL(url)

  if (isDotCom(endpoint) || isGHE(endpoint)) {
    return true
  }

  if (isKnownThirdPartyHost(hostname)) {
    return false
  }

  // github.example.com,
  if (/(^|\.)(github)\./.test(hostname)) {
    return true
  }

  // bitbucket.example.com, etc
  if (/(^|\.)(bitbucket|gitlab)\./.test(hostname)) {
    return false
  }

  if (getEndpointVersion(endpoint) !== null) {
    return true
  }

/** Implementation of the 'get' git credential helper command */
async function getCredential(cred: Credential, store: Store, token: string) {
  const ghCred = await getGitHubCredential(cred, store)

  if (ghCred) {
    return ghCred
  }

  const endpointKind = await getEndpointKind(cred, store)
  const accounts = await store.getAll()

  const endpoint = `${getCredentialUrl(cred)}`
  const apiEndpoint = getAPIEndpoint(endpoint)

  // If it appears as if the endpoint is a GitHub host and we don't have an
  // account for that endpoint then we should prompt the user to sign in.
  if (
    endpointKind !== 'generic' &&
    !accounts.some(a => a.endpoint === apiEndpoint)
  ) {
    if (getIsBackgroundTaskEnvironment(token)) {
      debug('background task environment, skipping prompt')
      return undefined
    }

    const account = await ui.promptForGitHubSignIn(endpoint)

    if (!account) {
      setHasRejectedCredentialsForEndpoint(token, endpoint)
    }

    return credWithAccount(cred, account)
  }

const getEndpointKind = async (cred: Credential, store: Store) => {
  const credentialUrl = getCredentialUrl(cred)
  const endpoint = `${credentialUrl}`

  if (isGist(endpoint)) {
    return 'generic'
  }

  if (isDotCom(endpoint)) {
    return 'github.com'
  }

  if (isGHE(endpoint)) {
    return 'ghe.com'
  }

  // When Git attempts to authenticate with a host it captures any
  // WWW-Authenticate headers and forwards them to the credential helper. We
  // use them as a happy-path to determine if the host is a GitHub host without
  // having to resort to making a request ourselves.
  for (const [k, v] of cred.entries()) {
    if (k.startsWith('wwwauth[')) {
      if (v.includes('realm="GitHub"')) {
        return 'enterprise'
      } else if (/realm="(GitLab|Gitea|Atlassian Bitbucket)"/.test(v)) {
        return 'generic'
      }
    }
  }

  const existingAccount = await findGitHubTrampolineAccount(store, endpoint)
  if (existingAccount) {
    return isDotCom(existingAccount.endpoint) ? 'github.com' : 'enterprise'
  }

  // All GitHub hosts use HTTPS, so if the protocol is not HTTPS we can
  // assume that this is not a GitHub host.
  if (credentialUrl.protocol !== 'https:') {
    return 'generic'
  }

  return (await isGitHubHost(endpoint)) ? 'enterprise' : 'generic'
}
