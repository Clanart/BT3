### Title
Missing recipient binding in PedPoP blame verification lets any party frame an honest participant — ([File: crypto/dkg/pedpop/src/lib.rs])

### Summary
CVE-2020-8235 is an insecure direct object reference: an object was accessed by reference without checking the accessor was its authorized party. The Serai analog lives in PedPoP's blame machine. `BlameMachine::blame` / `AdditionalBlameMachine::blame` accept an arbitrary `(sender, recipient, msg, proof)` tuple, and `Decryption::decrypt_with_proof` decrypts `msg` under `enc_keys[recipient]` without ever checking that `msg` was actually encrypted *to* that `recipient`. The `EncryptedMessage` PoP binds `context`, `from`, `key`, and the ciphertext — but not the intended recipient, since `encrypt` uses `to` only for the ECDH shared secret and never mixes it into `pop_challenge`. [1](#0-0) [2](#0-1) 

### Finding Description
`blame_internal(sender, recipient, msg, proof)` calls `self.encryption.decrypt_with_proof(sender, recipient, msg, proof)` and then maps outcomes to a faulty party: `InvalidSignature` → sender, `InvalidProof` → recipient, non-canonical or invalid share → sender. [3](#0-2)  The DLEq inside `decrypt_with_proof` only binds `proof.key` to `enc_keys[decryptor]` and `msg.key` — it does not prove the message was destined for `decryptor`. [4](#0-3)  Two reachable framings follow:

1. **Frame any participant as a false accuser.** Call `blame(S, V, msg_S, None)` where `msg_S` is any valid `EncryptedMessage` from `S` (encrypted shares are relayed by the coordinator and are published verbatim inside blame accusations per the DKG spec's blame procedure). `msg.pop` verifies (bound to `from=S`), then `proof == None` returns `InvalidProof`, and `blame_internal` returns `recipient` — i.e., `V` — as faulty, even though `V` never saw, claimed, or accused anything. [5](#0-4) 
2. **Frame an honest sender.** Call `blame(S, attacker, msg_for_V, proof)` where the attacker proves a DLEq against *their own* registered encryption key (`decryptor = attacker`). This is honestly provable — the attacker knows their `enc_key` scalar — decryption yields a wrong-recipient plaintext, `from_repr` or the share-verification multiexp fails, and `blame_internal` returns `sender`, blaming `S` for a share that was correct for `V`. [6](#0-5) 

The exposure is worsened because `AdditionalBlameMachine::new` is explicitly designed so the caller need not be a DKG participant — it requires only `context`, `n`, and the public commitment messages. [7](#0-6)  Downstream, `CoordinatorMessage::VerifyBlame` feeds attacker-supplied `accuser`/`accused`/`share`/`blame` bytes directly into this API. [8](#0-7) 

### Impact Explanation
Each `blame` verdict deterministically names one participant as faulty, and the library's contract is that identifying any fault forces protocol abort. [9](#0-8)  In Serai's deployment the verdict is escalated into `ProcessorMessage::Blame { participant }`, which the coordinator treats as grounds for fatal slashing of the named validator. An attacker can therefore cause an honest, non-participating party to be marked faulty — aborting the key-generation session and mis-attributing the fault — using only publicly observable ciphertexts and a self-generated DLEq proof. This is the exact IDOR shape of CVE-2020-8235: a reference to an object (another recipient's encrypted share) is accepted without verifying the reference's authorizations.

### Likelihood Explanation
Likelihood is moderate. The attacker needs only a validly-signed `EncryptedMessage` from the target sender — obtainable from coordinator-relayed share traffic or previously published blame — plus, for framing #2, a standard Schnorr DLEq over their own key. For framing #1 no proof is needed at all (`proof: None` suffices). The only mitigations are out-of-band: callers are told the message "must have been authenticated as actually having come from the sender in question," but nothing authenticates that it was addressed to `recipient`. [10](#0-9) 

### Recommendation
Bind the intended recipient into the per-message PoP: extend `pop_challenge` (or the ciphertext transcript) to include `to`'s encryption public key / `Participant` index in `encrypt`, and verify it in `decrypt`/`decrypt_with_proof`. Additionally, in `decrypt_with_proof`, treat `proof == None` as unverifiable rather than attributing `InvalidProof` to `recipient`, since an absent proof carries no information about the recipient's honesty.

### Proof of Concept
```rust
// PedPoP DKG, participants 1..=n. Attacker A, victim V, honest sender S.
// A has a copy of msg_S: the EncryptedMessage<SecretShare> S sent to V
// (relayed by coordinator, or copied from a published blame statement).

let machine = AdditionalBlameMachine::<C>::new(
    CONTEXT, params.n(), commitment_msgs /* all public */,
).unwrap();

// Framing 1: no proof at all. decrypt_with_proof takes the `else` branch,
// returns DecryptionError::InvalidProof, blame_internal returns `recipient`.
let faulty = machine.blame(S, V, msg_S.clone(), None);
assert_eq!(faulty, V); // V blamed though V never accused anyone

// Framing 2: A proves a DLEq against THEIR OWN enc key (decryptor = A).
let shared = ecdh::<C>(&a_enc_key, msg_S.key); // A * msg.key, honestly computable
let proof = EncryptionKeyProof {
    key: Zeroizing::new(shared),
    dleq: DLEqProof::prove(&mut rng, &mut encryption_key_transcript(CONTEXT),
                           &[C::generator(), msg_S.key], &a_enc_key),
};
let faulty = machine.blame(S, A, msg_S, Some(proof));
assert_eq!(faulty, S); // S blamed for a correct share meant for V
```
Both calls abort the DKG and name an innocent party as faulty, matching the processor's `VerifyBlame` flow which converts the verdict into `ProcessorMessage::Blame`. [11](#0-10) 

Uncertainty: the severity of the mis-attributed blame depends on coordinator-side slashing policy (out of scope here); within the in-scope crate, the provable defect is an incorrect blame/forged-accusation verdict reachable with public inputs.

fn encrypt<R: RngCore + CryptoRng, C: Ciphersuite, E: Encryptable>(
  rng: &mut R,
  context: [u8; 32],
  from: Participant,
  to: C::G,
  mut msg: Zeroizing<E>,
) -> EncryptedMessage<C, E> {
  /*
  The following code could be used to replace the requirement on an RNG here.
  It's just currently not an issue to require taking in an RNG here.
  let last = self.last_enc_key.to_bytes();
  self.last_enc_key = C::hash_to_F(b"encryption_base", last.as_ref());
  let key = C::hash_to_F(b"encryption_key", last.as_ref());
  last.as_mut().zeroize();
  */

  // Generate a new key for this message, satisfying cipher's requirement of distinct keys per
  // message, and enabling revealing this message without revealing any others
  let key = Zeroizing::new(C::random_nonzero_F(rng));
  cipher::<C>(context, &ecdh::<C>(&key, to)).apply_keystream(msg.as_mut().as_mut());

  let pub_key = C::generator() * key.deref();
  let nonce = Zeroizing::new(C::random_nonzero_F(rng));
  let pub_nonce = C::generator() * nonce.deref();
  EncryptedMessage {
    key: pub_key,
    pop: SchnorrSignature::sign(
      &key,
      nonce,
      pop_challenge::<C>(context, pub_nonce, pub_key, from, msg.deref().as_ref()),
    ),
    msg,
  }
}

  pub(crate) fn decrypt_with_proof<E: Encryptable>(
    &self,
    from: Participant,
    decryptor: Participant,
    mut msg: EncryptedMessage<C, E>,
    // There's no encryption key proof if the accusation is of an invalid signature
    proof: Option<EncryptionKeyProof<C>>,
  ) -> Result<Zeroizing<E>, DecryptionError> {
    if !msg.pop.verify(
      msg.key,
      pop_challenge::<C>(self.context, msg.pop.R, msg.key, from, msg.msg.deref().as_ref()),
    ) {
      Err(DecryptionError::InvalidSignature)?;
    }

    if let Some(proof) = proof {
      // Verify this is the decryption key for this message
      proof
        .dleq
        .verify(
          &mut encryption_key_transcript(self.context),
          &[C::generator(), msg.key],
          &[self.enc_keys[&decryptor], *proof.key],
        )
        .map_err(|_| DecryptionError::InvalidProof)?;

      cipher::<C>(self.context, &proof.key).apply_keystream(msg.msg.as_mut().as_mut());
      Ok(msg.msg)
    } else {
      Err(DecryptionError::InvalidProof)
    }
  }

  fn blame_internal(
    &self,
    sender: Participant,
    recipient: Participant,
    msg: EncryptedMessage<C, SecretShare<C::F>>,
    proof: Option<EncryptionKeyProof<C>>,
  ) -> Participant {
    let share_bytes = match self.encryption.decrypt_with_proof(sender, recipient, msg, proof) {
      Ok(share_bytes) => share_bytes,
      // If there's an invalid signature, the sender did not send a properly formed message
      Err(DecryptionError::InvalidSignature) => return sender,
      // Decryption will fail if the provided ECDH key wasn't correct for the given message
      Err(DecryptionError::InvalidProof) => return recipient,
    };

    let Some(share) = Option::<C::F>::from(C::F::from_repr(share_bytes.0)) else {
      // If this isn't a valid scalar, the sender is faulty
      return sender;
    };

    // If this isn't a valid share, the sender is faulty
    if !bool::from(
      multiexp_vartime(&share_verification_statements::<C>(
        recipient,
        &self.commitments[&sender],
        Zeroizing::new(share),
      ))
      .is_identity(),
    ) {
      return sender;
    }

    // The share was canonical and valid
    recipient
  }

  /// invalid secret share, or the receiver, who claimed a valid secret share was invalid). No
  /// matter which, prevent completion of the machine, forcing an abort of the protocol.
  ///
  /// The message should be a copy of the encrypted secret share from the accused sender to the
  /// accusing recipient. This message must have been authenticated as actually having come from

  /// In order to enable detecting multiple faults, an `AdditionalBlameMachine` is returned, which
  /// can be used to determine further blame. These machines will process the same blame statements
  /// multiple times, always identifying blame. It is the caller's job to ensure they're unique in
  /// order to prevent multiple instances of blame over a single incident.

    self,
    sender: Participant,
    recipient: Participant,
    msg: EncryptedMessage<C, SecretShare<C::F>>,
    proof: Option<EncryptionKeyProof<C>>,
  ) -> (AdditionalBlameMachine<C>, Participant) {

  /// Create an AdditionalBlameMachine capable of evaluating Blame regardless of if the caller was
  /// a member in the DKG protocol.
  ///
  /// Takes in the parameters for the DKG protocol and all of the participant's commitment
  /// messages.
  ///
  /// This constructor assumes the full validity of the commitment messages. They must be fully
  /// authenticated as having come from the supposed party and verified as valid. Usage of invalid
  /// commitments is considered undefined behavior, and may cause everything from inaccurate blame
  /// to panics.
  pub fn new(
    context: [u8; 32],
    n: u16,
    mut commitment_msgs: HashMap<Participant, EncryptionKeyMessage<C, Commitments<C>>>,
  ) -> Result<Self, PedPoPError<C>> {
    let mut commitments = HashMap::new();
    let mut encryption = Decryption::new(context);
    for i in 1 ..= n {
      let i = Participant::new(i).unwrap();
      let Some(msg) = commitment_msgs.remove(&i) else { Err(PedPoPError::MissingParticipant(i))? };
      commitments.insert(i, encryption.register(i, msg).commitments);
    }
    Ok(AdditionalBlameMachine(BlameMachine { commitments, encryption, result: None }))
  }
