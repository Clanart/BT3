### Title
Unbounded connection acceptance on the frozen-rpc-router public EVM JSON-RPC listener - (File: cmd/frozen-rpc-router/main.go)

### Summary
`frozen-rpc-router` is a standalone, publicly-exposed EVM JSON-RPC HTTP proxy (documented use case: `--listen-address 0.0.0.0:8545`, and in the reference docker-compose topology it is bound to a host port, `8553:8545`) [4](#0-3) . Its `http.Server` is started with plain `ListenAndServe()` and has no connection-count cap anywhere in its configuration surface [5](#0-4) .

### Finding Description
`run()` in `cmd/frozen-rpc-router/main.go` builds an `http.Server` with only header/write/idle timeouts and calls `server.ListenAndServe()` directly [5](#0-4) . The Go standard library's `ListenAndServe`/`Serve` accept every incoming TCP connection unconditionally into an unbounded set of goroutines/file descriptors — the same underlying pattern flagged in the http4s-blaze-server advisory (GHSA-xhv5-w9c5-2r2w / CVE-2021-21294), where connections were accepted without any bound at the listener layer.

By contrast, this same codebase already fixes this exact bug class for its primary EVM RPC listener: `evmrpc/rpcstack.go`'s `HTTPServer.Start` wraps the raw `net.Listen` result with `netutil.LimitListener` whenever `maxOpenConns > 0` [1](#0-0) , driven by `MaxOpenConnections` (default 2000, configurable via `evm.max_open_connections`) [2](#0-1) [6](#0-5) , and it is regression-tested by `TestMaxOpenConns` [7](#0-6) . The Tendermint RPC/API servers (`sei-cosmos/server/api/server.go`, `sei-tendermint/internal/rpc/core/env.go`) likewise call `tmrpcserver.Listen(addr, MaxOpenConnections)` which applies the same cap [8](#0-7) [9](#0-8) .

`cmd/frozen-rpc-router/config.go`'s `parseConfig` defines flags for request-body size, batch limits, and write/shutdown timeouts, but exposes no `--max-open-connections` (or equivalent) flag, and `config` has no field capable of bounding accepted connections [10](#0-9) . Each accepted connection additionally triggers `router.proxy`/`callUpstream`, which opens its own outbound HTTP request to a live or frozen upstream node via `r.client.Do(...)` [11](#0-10) , so unbounded inbound acceptance also unboundedly fans out outbound sockets/goroutines toward the validator/archival nodes behind it, compounding the resource exhaustion.

### Impact Explanation
An unprivileged public-RPC client can open a large number of TCP connections to the router's public listener (e.g., without ever sending a complete HTTP request, or via slow/half-open connections) and exhaust the process's file descriptors / goroutines, crashing or hanging the `frozen-rpc-router` process — a default-configuration public RPC endpoint per its own deployment documentation and docker-compose reference topology. This matches the "crash of default-configuration RPC nodes" acceptance bar. It does not directly compromise consensus, funds, or validator nodes (the router only proxies to nodes over their existing RPC surfaces), so the blast radius is limited to availability of this specific gateway component, not the chain itself.

### Likelihood Explanation
High likelihood: no authentication, connection cap, or rate limiting is applied at the accept stage; only request-body size and batch-size limits, applied after a connection is accepted and a request is read, are enforced. A trivial connection-flood or slow-loris-style script against the router's exposed port is sufficient.

### Recommendation
Add a `maxOpenConnections`-style flag to `cmd/frozen-rpc-router/config.go`, and in `run()` obtain the listener via `net.Listen` explicitly, wrap it with `golang.org/x/net/netutil.LimitListener(listener, cfg.maxOpenConnections)` when the limit is positive (mirroring `evmrpc/rpcstack.go`'s pattern), and call `server.Serve(listener)` instead of `server.ListenAndServe()`. Choose a conservative default (e.g., matching `evmrpc/config`'s default of 2000) and document it alongside the existing `--write-timeout`/`--batch-request-limit` flags.

### Proof of Concept
1. Start `frozen-rpc-router` with `--listen-address 0.0.0.0:8545 --live-node <live>` per the documented usage [12](#0-11) .
2. From an external host, open many thousands of raw TCP connections to port 8545 without completing valid HTTP requests (e.g., `for i in $(seq 1 50000); do (exec 3<>/dev/tcp/<router-ip>/8545 &); done` or a small Go/Python fuzzer opening sockets and not writing/reading).
3. Observe the router process's open file descriptor / goroutine count grow unbounded (`lsof -p <pid> | wc -l`), eventually hitting `ulimit -n` and causing `accept: too many open files` errors, refused connections for legitimate clients, or process crash — while `evmrpc`'s equivalent HTTP/WS listeners under the same attack remain bounded due to `SetMaxOpenConns`/`netutil.LimitListener`.

// TestMaxOpenConns verifies that SetMaxOpenConns wraps the listener so that no
// more than the configured number of connections are accepted at once. With a
// cap of 1, a second connection is not served until the first one is closed.
func TestMaxOpenConns(t *testing.T) {
	srv := evmrpc.NewHTTPServer(rpc.DefaultHTTPTimeouts)
	srv.SetMaxOpenConns(1)
	assert.NoError(t, srv.EnableRPC(apis(), evmrpc.HTTPConfig{}))
	assert.NoError(t, srv.SetListenAddr("localhost", 0))
	assert.NoError(t, srv.Start())
	defer srv.Stop()

	addr := srv.ListenAddr()

	// Open the first connection and send only request headers advertising a body
	// that never arrives. The server accepts it (consuming the single slot), and
	// its serving goroutine blocks reading the body, holding the slot open.
	c1, err := net.Dial("tcp", addr)
	assert.NoError(t, err)
	defer func() {
		_ = c1.Close()
	}()
	_, err = c1.Write([]byte("POST / HTTP/1.1\r\nHost: localhost\r\nContent-Type: application/json\r\nContent-Length: 4096\r\n\r\n"))
	assert.NoError(t, err)

	// Give the accepting loop time to accept c1 and consume the slot.
	time.Sleep(200 * time.Millisecond)

	// While c1 holds the only slot, a second connection is not accepted, so a
	// complete request over it receives no response before the read deadline.
	body := `{"jsonrpc":"2.0","id":1,"method":"test_greet","params":[]}`
	req := fmt.Sprintf("POST / HTTP/1.1\r\nHost: localhost\r\nContent-Type: application/json\r\nContent-Length: %d\r\n\r\n%s", len(body), body)
	c2, err := net.DialTimeout("tcp", addr, time.Second)
	assert.NoError(t, err)
	defer func() {
		_ = c2.Close()
	}()
	_, err = c2.Write([]byte(req))
	assert.NoError(t, err)
	assert.NoError(t, c2.SetReadDeadline(time.Now().Add(500*time.Millisecond)))
	buf := make([]byte, 64)
	_, err = c2.Read(buf)
	assert.Error(t, err, "second connection should not be served while the slot is held")

	// Closing c1 frees the slot; c2 is then accepted and served.
	assert.NoError(t, c1.Close())
	assert.NoError(t, c2.SetReadDeadline(time.Now().Add(5*time.Second)))
	n, err := c2.Read(buf)
	assert.NoError(t, err)
	assert.Greater(t, n, 0)
}

		return config{}, errors.New("--max-block-reference-depth must be positive")

		return config{}, errors.New("--batch-request-limit must be positive")

		return config{}, errors.New("--write-timeout must be positive")
	}

		return config{}, errors.New("--shutdown-timeout must be positive")
	}
	return cfg, nil
}

func (r *router) proxy(w http.ResponseWriter, request *http.Request, target *upstream, body []byte) error {
	upstreamRequest, err := r.newUpstreamRequest(request, target, body)
	if err != nil {
		return err
	}
	response, err := r.client.Do(upstreamRequest) //nolint:gosec // upstream URLs come from operator configuration; request data only supplies the proxied path and query.
	if err != nil {
		return err
	}

	copyResponseHeaders(w.Header(), response.Header)
	w.Header().Set(rpcRouteHeader, target.routeName())
	w.WriteHeader(response.StatusCode)
	_, _ = io.Copy(w, response.Body)
	_ = response.Body.Close()
	return nil
}
