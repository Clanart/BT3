### Title
Double `end_round` Call in `PayoutCheckerTask` Corrupts Operator Round State — (File: `core/src/task/payout_checker.rs`)

### Summary

`PayoutCheckerTask::run_once` calls `operator.end_round` unconditionally after `handle_finalized_payout` returns. However, `handle_finalized_payout` already calls `end_round` internally when the current round has no free kickoff connectors. When both code paths execute, the operator's `current_round_index` advances by **two** instead of one, permanently breaking the operator's ability to process future payouts.

### Finding Description

In `core/src/task/payout_checker.rs`, after `handle_finalized_payout` completes, `end_round` is called unconditionally: [1](#0-0) 

Inside `handle_finalized_payout` in `core/src/operator.rs`, `end_round` is called **conditionally** — only when the current round index lags behind the round that holds the next available kickoff connector: [2](#0-1) 

When `current_round_index != round_idx` (i.e., all kickoff connectors in the current round are exhausted and the next available one is in round N+1), the execution path is:

1. `handle_finalized_payout` calls `end_round` → `current_round_index` advances from N → N+1.
2. `payout_checker` calls `end_round` again unconditionally → `current_round_index` advances from N+1 → N+2.

`end_round` has no idempotency guard; it reads the current round index from the DB and advances it every time it is called: [3](#0-2) 

Both calls share the same live database transaction (`&mut dbtx`), so the second call observes the already-updated round index written by the first call and advances it a second time.

### Impact Explanation

After the double advance, `current_round_index` is N+2. The next call to `handle_finalized_payout` invokes `get_unused_and_signed_kickoff_connector`, which returns the next unused connector — still in round N+1 (since only one connector from that round was consumed). The sanity check then fires: [4](#0-3) 

Because `current_round_index` (N+2) is **greater** than `round_idx` (N+1), and `current_round_index.next_round()` (N+3) ≠ N+1, the function returns a hard error. `PayoutCheckerTask` retries but always hits the same corrupted state. The operator is permanently unable to process further payouts, losing all BTC fronted for those withdrawals without any path to reimbursement.

### Likelihood Explanation

The trigger condition — all kickoff connectors in the current round exhausted, forcing a round advance inside `handle_finalized_payout` — is a normal operational event for any active operator. With `num_kickoffs_per_round > 1` (the production configuration), round N+1 retains unused connectors after the first payout from that round, guaranteeing the error on the very next payout attempt. The `automation` feature flag must be enabled, which is the intended production mode.

### Recommendation

Capture the round index **before** calling `handle_finalized_payout` and compare it to the round index **after**. Call `end_round` in `payout_checker` only if `handle_finalized_payout` did **not** already advance the round:

```rust
let round_before = self.db.get_current_round_index(Some(&mut dbtx)).await?;

let kickoff_txid = self.operator
    .handle_finalized_payout(&mut dbtx, deposit_data.get_deposit_outpoint(), payout_tx_blockhash)
    .await?;

#[cfg(feature = "automation")]
{
    let round_after = self.db.get_current_round_index(Some(&mut dbtx)).await?;
    if round_before == round_after {
        self.operator.end_round(&mut dbtx).await?;
    }
}
```

This mirrors the external report's recommendation: save the initial state before the operation and use it as a condition for the post-operation state change.

### Proof of Concept

1. Operator is in round N; all kickoff connectors for the target deposit in round N are marked used.
2. A new payout arrives; `payout_checker` calls `handle_finalized_payout`.
3. `get_unused_and_signed_kickoff_connector` returns connector `(round_idx = N+1, kickoff_idx = 0)`.
4. `current_round_index` (N) ≠ `round_idx` (N+1) → `handle_finalized_payout` calls `end_round` → DB: `current_round_index = N+1`.
5. `handle_finalized_payout` returns `kickoff_txid`.
6. `payout_checker` calls `end_round` unconditionally → DB: `current_round_index = N+2`.
7. Next payout: `get_unused_and_signed_kickoff_connector` returns `(round_idx = N+1, kickoff_idx = 1)` (remaining unused connector in round N+1).
8. `current_round_index` (N+2) ≠ `round_idx` (N+1); sanity check: `(N+2).next_round()` = N+3 ≠ N+1 → `handle_finalized_payout` returns `BridgeError`.
9. `payout_checker` retries indefinitely; operator cannot reimburse any further payout. [5](#0-4) [6](#0-5)

            .await?;

        let kickoff_txid = self
            .operator
            .handle_finalized_payout(

            .ok_or_eyre("Couldn't find payout blockhash in bitcoin sync")?;

        let _ = self

            .await?;

        self.operator.end_round(&mut dbtx).await?;

        self.db
            .mark_payout_handled(Some(&mut dbtx), citrea_idx, kickoff_txid)
            .await?;

        dbtx.commit().await?;

        Ok(true)

    pub async fn handle_finalized_payout<'a>(
        &'a self,
        dbtx: DatabaseTransaction<'a>,
        deposit_outpoint: OutPoint,
        payout_tx_blockhash: BlockHash,
    ) -> Result<bitcoin::Txid, BridgeError> {
        let (deposit_id, deposit_data) = self
            .db
            .get_deposit_data(Some(dbtx), deposit_outpoint)
            .await?
            .ok_or(BridgeError::DatabaseError(sqlx::Error::RowNotFound))?;

        // get unused kickoff connector
        let (round_idx, kickoff_idx) = self
            .db
            .get_unused_and_signed_kickoff_connector(
                Some(dbtx),
                deposit_id,
                self.signer.xonly_public_key,
            )
            .await?
            .ok_or(BridgeError::DatabaseError(sqlx::Error::RowNotFound))?;

        let current_round_index = self.db.get_current_round_index(Some(dbtx)).await?;
        tracing::info!(
            "Operator: Current round index: {}, round idx for kickoff: {}",
            current_round_index,
            round_idx
        );
        #[cfg(feature = "automation")]
        if current_round_index != round_idx {
            // we currently have no free kickoff connectors in the current round, so we need to end round first
            // if current_round_index should only be smaller than round_idx, and should not be smaller by more than 1
            // so sanity check:
            if current_round_index.next_round() != round_idx {
                return Err(eyre::eyre!(
                    "Internal error: Expected the current round ({:?}) to be equal to or 1 less than the round of the first available kickoff for deposit reimbursement ({:?}) for deposit {:?}. If the round is less than the current round, there is an issue with the logic of the fn that gets the first available kickoff. If the round is greater, that means the next round do not have any kickoff connectors available for reimbursement, which should not be possible.",
                    current_round_index, round_idx, deposit_outpoint
                ).into());
            }
            tracing::info!(
                "Operator: Starting next round to be able to get reimbursement for the payout"
            );
            // start the next round to be able to get reimbursement for the payout
            self.end_round(dbtx).await?;
        }

    pub async fn end_round<'a>(
        &'a self,
        mut dbtx: DatabaseTransaction<'a>,
    ) -> Result<(), BridgeError> {
        // get current round index
        let current_round_index = self.db.get_current_round_index(Some(&mut dbtx)).await?;

        let mut activation_prerequisites = Vec::new();

        let operator_winternitz_public_keys = self
            .db
            .get_operator_kickoff_winternitz_public_keys(None, self.signer.xonly_public_key)
            .await?;
        let kickoff_wpks = KickoffWinternitzKeys::new(
            operator_winternitz_public_keys,
            self.config.protocol_paramset().num_kickoffs_per_round,
            self.config.protocol_paramset().num_round_txs,
        )?;

        // if we are at round 0, which is just the collateral, we need to start the first round
        if current_round_index == RoundIndex::Collateral {
            return self.start_first_round(dbtx, kickoff_wpks).await;
        }
