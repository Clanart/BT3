### Title
Non-linear HEAD move (checkout/reset to unrelated commit) causes `compute_v2_review_set` to exclude committed malicious diffs from review - ([File: plugins/security-guidance/hooks/diffstate.py])

### Summary
`compute_v2_review_set` builds `review_set` as the intersection of `dirty_now` (files dirty vs. *current* HEAD, plus files from `head_at_capture..HEAD` only when that range is a linear ancestor chain) and `changed_since` (files that differ in content from the pre-turn `baseline_sha` stash snapshot). When an attacker-controlled agent moves HEAD non-linearly relative to `head_at_capture` (e.g. `git checkout`/`git reset --hard` to an unrelated commit/branch after committing malicious changes there), `_is_ancestor` returns `False`, the `head_at_capture..HEAD` diff is never unioned into `dirty_now`, and a fully-committed (clean working tree) malicious file is dropped from `dirty_now` even though it is present in `changed_since`. The intersection then silently excludes the file from the security review set.

### Finding Description
`compute_v2_review_set` (`plugins/security-guidance/hooks/diffstate.py:353-438`) computes:
```
review_set = (dirty_now & changed_since) if changed_since is not None else dirty_now
``` [1](#0-0) 

`dirty_now` is populated from `git status --porcelain` (current worktree vs. current HEAD) plus, conditionally, the name-only diff of `head_at_capture..HEAD`, but only when `head_at_capture` is an ancestor of `current_head` (a linear history advance) as checked by `_is_ancestor` in `gitutil.py`: [2](#0-1) 

`changed_since` is computed independently as `_git_name_only(repo, baseline_sha)` — a pure content diff between the frozen pre-turn `baseline_sha` (created via `git stash create`, capturing HEAD+dirty state at prompt submission) and the current worktree, which is unaffected by how HEAD got to its current state: [3](#0-2) 

Exploit flow:
1. At turn start, UPS captures `baseline_sha` (stash-create of pre-turn tree) and `head_at_capture` = HEAD at commit A.
2. During its own turn, the attacker-controlled agent checks out/creates an unrelated commit/branch not descended from A (e.g. `git checkout -b evil <unrelated-ref>` or `git reset --hard <other-sha>`), edits a file with malicious code, and commits it there (commit D, not a descendant of A).
3. Working tree is left clean (fully committed) at D. `git status --porcelain` shows nothing dirty, so `tracked_dirty` is empty for the malicious file.
4. `_is_ancestor(repo, A, D)` returns `False` (D is not reachable from A), so the `head_at_capture..HEAD` union branch is skipped — `dirty_now` stays empty for that file.
5. `changed_since = git diff --name-only baseline_sha` still lists the file, because content differs from the pre-turn snapshot regardless of the git history path taken.
6. `review_set = dirty_now ∩ changed_since = ∅` for that file — it is silently dropped from the paths passed to `get_git_diff`, so the Stop-hook review never sees it.

This works because the "linear HEAD advance" ancestor check is a *history* check, not a *content* check, while `changed_since` is purely content-based; the intersection design assumes these two concepts are always congruent, which is false whenever git history is manipulated non-linearly during the turn (an operation well within reach of an unprivileged, repo-embedded agent with normal git access, as documented for agents built per `plugins/plugin-dev/skills/agent-development/SKILL.md`).

### Impact Explanation
A malicious or compromised sub-agent operating within its own turn can commit attacker-controlled code changes via non-linear git operations (checkout/reset to an unrelated ref, commit, then return) such that the automated security-review Stop hook's `review_set` never includes the altered file, even though the file's content genuinely diverges from the pre-turn baseline. This is a silent bypass of the automated security review/commit-review gate — malicious code changes reach the repository (already committed) without ever being scanned, undermining the "deny means deny / secrets-and-diff-integrity" guarantee that the review baseline is not attacker-steerable.

### Likelihood Explanation
Preconditions are modest: an agent needs ordinary git command execution (stash/checkout/commit/reset) during its own turn — capability explicitly expected of repo-embedded coding agents per the SKILL.md tooling model, with no special privilege, admin access, or secrets required. The sequence is deterministic and fully reproducible with plain git commands; no timing race or external dependency is needed beyond controlling the sequence of git operations within one turn.

### Recommendation
Do not gate inclusion of committed-since-capture changes on `_is_ancestor`/linear-history detection. Instead, always compute the union of (a) worktree-dirty files vs. current HEAD and (b) `_git_name_only(repo, head_at_capture)` (a direct content diff between `head_at_capture` and current worktree, independent of ancestry) whenever `head_at_capture` is available, so any content divergence from the turn-start commit is captured regardless of intervening checkout/reset/rebase. Alternatively, drop the ancestry precondition entirely and rely solely on `changed_since` (content diff vs. `baseline_sha`) as the review set, using `dirty_now` only as an additive signal rather than an exclusionary intersection term.

### Proof of Concept
Integration/invariant test in the existing `security_reminder_hook`/`diffstate` test suite:
1. Init a repo with an initial commit; capture `baseline_sha` via `capture_git_baseline(cwd)` and `head_at_capture = _git_rev_parse_head(cwd)` (commit A).
2. Create and check out an unrelated orphan branch (`git checkout --orphan evil` or checkout a commit not descended from A), write malicious content to `evil.py`, `git add -A && git commit -m evil` to create commit D.
3. Call `compute_v2_review_set(cwd, baseline_sha, head_at_capture)`.
4. Assert `_is_ancestor(cwd, head_at_capture, current_head)` is `False` (confirms the vulnerable branch) yet `os.path.join(repo, "evil.py")` (or its repo-relative form) is present in the returned `review_paths`.
5. Expected (correct) behavior: `evil.py` is in `review_set` because its content differs from `baseline_sha`. Observed (buggy) behavior: `review_set` is empty/excludes `evil.py` because `dirty_now` was never unioned with the non-linear commit's changes, demonstrating the review-baseline bypass.

def _is_ancestor(cwd, maybe_ancestor, descendant):
    """True if `maybe_ancestor` is reachable from `descendant` (i.e. HEAD
    moved forward via commit/merge, not sideways via checkout)."""
    try:
        result = subprocess.run(
            [*GIT_CMD, "merge-base", "--is-ancestor", maybe_ancestor, descendant],
            cwd=cwd, capture_output=True, text=True, timeout=5,
        )
        return result.returncode == 0
    except (subprocess.TimeoutExpired, FileNotFoundError, OSError):
        return False
