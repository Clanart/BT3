### Title
Stop-hook review-set intersection collapses to empty after `git commit --amend`, silently skipping LLM security review of committed vulnerabilities - (File: `plugins/security-guidance/hooks/diffstate.py`)

### Summary
`compute_v2_review_set` computes the Stop-hook's file review set as `dirty_now ∩ changed_since`, where `dirty_now` comes from `git status` plus a linear-history check (`_is_ancestor`) against `head_at_capture`, and `changed_since` comes from diffing against `load_baseline_sha`'s stored SHA. A completely ordinary git operation — `git commit --amend` (or any non-linear history rewrite) performed during the same turn — makes `dirty_now` empty while `changed_since` still correctly contains the dangerous file, and because the code intersects rather than falls back, the result is an empty review set that causes the Stop hook to skip review entirely.

### Finding Description
`compute_v2_review_set` in `plugins/security-guidance/hooks/diffstate.py` builds the review set as: [1](#0-0) 

`dirty_now` is `tracked_dirty | new_untracked` from `_git_status_porcelain`, extended only when HEAD "advanced linearly" — i.e. `head_at_capture != current_head and _is_ancestor(repo, head_at_capture, current_head)`: [2](#0-1) 

`changed_since` is derived from `baseline_sha` (populated via `load_baseline_sha`/`save_baseline_sha`), independent of the ancestry check: [3](#0-2) 

Attack flow (fully within an ordinary cloned-repo git workflow, no elevated privilege needed):
1. `UserPromptSubmit` captures `baseline_sha` (via `capture_git_baseline`) and `head_at_capture` (current HEAD) at turn start.
2. During the turn, a dangerous change is made and **committed** (e.g. by the agent, or by the user directing normal git commands).
3. The commit is then amended (`git commit --amend`, or any rebase/reset that rewrites history) — a completely normal, frequent git operation that does not require any special access.
4. After the amend, the working tree is clean, so `tracked_dirty = ∅` and (absent new files) `new_untracked = ∅`, making `dirty_now = ∅`.
5. The amended commit's ancestor is the *original pre-amend parent*, not `head_at_capture` (the pre-amend commit itself), so `_is_ancestor(head_at_capture, current_head)` is `False`. The linear-advance branch that would otherwise fold `head_at_capture..HEAD` into `dirty_now` never executes, so `dirty_now` stays `∅`.
6. `changed_since` (diff against `baseline_sha`) still correctly reports the dangerous file as changed, since its content differs from the pre-turn stash.
7. `review_set = dirty_now & changed_since = ∅ & {dangerous_file} = ∅`, regardless of what `changed_since` contains.
8. `handle_stop_hook` receives `review_paths == []` and calls `_skip(9, ...)`, exiting 0 without ever invoking the LLM security analysis: [4](#0-3) 

The intent of the intersection (documented in the function's own docstring) is to exclude the user's *pre-existing, untouched* WIP from review, not to exclude genuinely new, committed, turn-authored content: [5](#0-4) 

But the empty-set short-circuit means any turn ending with a clean working tree *and* a non-ancestor HEAD relationship to `head_at_capture` (amend, rebase, `commit --fixup`+autosquash, cherry-pick replacing the tip, etc.) unconditionally zeroes the review set even though `changed_since` proves the dangerous file changed relative to `baseline_sha`. No existing guard (workspace scoping, `filter_preexisting_from_diff`, `previous_findings` dedup) runs before this point — the review set is computed and found empty before any diff content is even fetched.

### Impact Explanation
This breaks the stated invariant that "the review set must stay bound to the right repo, baseline, and touched paths": a dangerous, fully committed change is treated as if it doesn't exist for the current turn and never reaches the Haiku vulnerability scan (`analyze_code_security`). Since the security-guidance Stop hook is Claude Code's main automated defense against the agent writing/committing exploitable code (hardcoded secrets, command injection, path traversal, etc.), an attacker (or a compromised/prompt-injected agent turn) can reliably suppress this review using nothing more than a standard `git commit --amend`, letting an unreviewed vulnerable change persist in the repository — matching "Unauthorized file read or write outside the user-approved workspace or target scope" once that unreviewed vulnerability is later exploited (e.g. a path-traversal or injection bug that the reviewer would otherwise have flagged and forced Claude to fix before continuing).

### Likelihood Explanation
High feasibility and full repeatability: no special privileges, leaked credentials, or social engineering are required — only an ordinary `git commit` followed by `git commit --amend` within a single agent turn, which is a common, unremarkable workflow (e.g. "fix the commit message", "squash this into the last commit"). The condition triggers deterministically any time the working tree ends up clean and HEAD is not a fast-forward descendant of `head_at_capture`, which covers amend, rebase, reset+recommit, and cherry-pick-replace flows.

### Recommendation
Change `compute_v2_review_set` to not let history-rewriting operations blind the review set: either (a) fall back to `changed_since` alone (not intersected with a possibly-stale `dirty_now`) whenever HEAD differs from `head_at_capture` regardless of ancestry, unioning in `_git_name_only(repo, head_at_capture)` (comparing the *tips*, not requiring a linear ancestor relationship) so amended/rebased commits are still detected; or (b) union `dirty_now` with the full `changed_since` set instead of intersecting, using the intersection only as an optimization when both sets are non-empty and trusted. At minimum, add a specific check: if `head_at_capture != current_head` and `changed_since` is non-empty while `dirty_now` is empty, treat this as a "history rewritten" case and fall back to reviewing `changed_since` directly rather than silently emitting an empty review set.

### Proof of Concept
Integration test in the plugin's test suite (e.g. alongside existing `compute_v2_review_set` tests):
1. Init a temp git repo, create `app.py` with benign content, `git add && git commit` (initial commit) → this is HEAD/`head_at_capture`.
2. Call `capture_git_baseline(cwd)` to get `baseline_sha` (clean tree ⇒ resolves to HEAD).
3. Write a dangerous change into `app.py` (e.g. `os.system(user_input)`), `git add app.py && git commit -m "wip"`.
4. Run `git commit --amend -m "fix"` (no content change, just history rewrite) to simulate the ordinary amend workflow, leaving the tree clean.
5. Call `compute_v2_review_set(cwd, baseline_sha, head_at_capture, {})`.
6. **Expected (bug present):** `review_paths == []` even though `git diff --name-only baseline_sha` (i.e., `changed_since`) contains `app.py`.
7. **Assertion the fix must satisfy:** `review_paths` contains the absolute path to `app.py`, so the subsequent `handle_stop_hook` call proceeds to `analyze_code_security` instead of hitting `_skip(9, ...)`. [6](#0-5) [7](#0-6)

    dirty_now = tracked_dirty | new_untracked

    diff_base = "HEAD"
    current_head = _git_rev_parse_head(repo)
    if (head_at_capture and current_head and head_at_capture != current_head
            and _is_ancestor(repo, head_at_capture, current_head)):
        dirty_now |= _git_name_only(repo, f"{head_at_capture}..HEAD") or set()
        diff_base = head_at_capture

    # changed_since: tracked files vs the stash baseline (no temp index — the
    # stash never contained untracked files anyway), then union with
    # currently-untracked. The previous `include_untracked=True` arm cost a
    # full `git add -N .` (slow in large repos) per call to surface
    # untracked files in the diff output — but `git diff <stash>` already
    # lists them as "only in worktree" without that, and we have the explicit
    # set from status regardless.
    if baseline_sha:
        changed_since = _git_name_only(repo, baseline_sha)
        if changed_since is not None:
            changed_since |= new_untracked
    else:
        changed_since = None
    # changed_since is None on missing baseline OR on git error (e.g. the
    # dangling stash SHA was pruned). Either way, don't intersect with ∅ —
    # that would silently zero the review set. Fall back to dirty_now.
    review_set = (dirty_now & changed_since) if changed_since is not None else dirty_now
