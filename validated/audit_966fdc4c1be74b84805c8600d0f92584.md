### Title
Insecure Default for `client_verification` Disables mTLS Interceptor, Allowing Any Caller to Invoke Privileged gRPC Methods — (`core/src/config/env.rs`, `core/src/servers.rs`)

---

### Summary

When `CLIENT_VERIFICATION` is absent from the environment, `BridgeConfig::from_env` silently defaults `client_verification` to `false`. This propagates into `create_grpc_server`, which installs the `Noop` interceptor instead of `OnlyAggregatorAndSelf` and omits the `client_ca_root` TLS requirement. The result is that any network-reachable client — without presenting any certificate — can invoke privileged gRPC methods including `internal_end_round`, `internal_finalized_payout`, and `optimistic_payout_sign` on operator and verifier servers.

---

### Finding Description

**Step 1 — Insecure default in `BridgeConfig::from_env`** [1](#0-0) 

```rust
let client_verification =
    read_string_from_env("CLIENT_VERIFICATION").is_ok_and(|s| s == "true" || s == "1");
```

`is_ok_and` returns `false` when the env var is absent. There is no error, no warning, and no fallback to a secure default. The field silently becomes `false`.

**Step 2 — `create_grpc_server` branches on `client_verification`** [2](#0-1) 

When `client_verification == false`:
- TLS is configured **without** `client_ca_root`, so the server does not require or validate any client certificate.
- The interceptor installed is `Noop`, not `OnlyAggregatorAndSelf`.

**Step 3 — `Noop` interceptor passes every request unconditionally** [3](#0-2) 

```rust
Interceptors::Noop => Ok(req),
```

The `only_aggregator_and_self` function — which enforces that internal methods are callable only by `our_cert` and non-internal methods only by `aggregator_cert` or `our_cert` — is never invoked. [4](#0-3) 

**Step 4 — Privileged methods are fully exposed**

With `Noop` active, any caller with TCP access to the gRPC port can invoke:
- `internal_end_round` (operator) — advances round state
- `optimistic_payout_sign` (operator) — signs payout transactions
- `internal_finalized_payout` (verifier) — marks payouts as finalized [5](#0-4) 

The test itself confirms the intended invariant: the aggregator cert must be rejected from calling `internal_end_round`. With `Noop`, this invariant is silently dropped.

---

### Impact Explanation

An attacker with network access to a deployed operator or verifier gRPC port (which is typically exposed for aggregator communication) can:
- Trigger `internal_end_round` to force unauthorized round advancement, disrupting deposit/withdrawal session lifecycle.
- Trigger `optimistic_payout_sign` to obtain operator signatures on payout transactions without holding the aggregator key, potentially enabling unauthorized fund withdrawals.
- Trigger `internal_finalized_payout` on verifiers to corrupt payout finalization state.

This constitutes an authentication bypass granting privileged bridge actions to an unprivileged party, satisfying the allowed impact gate.

---

### Likelihood Explanation

`CLIENT_VERIFICATION` is an optional env var with no required presence. Any deployment that omits it — including fresh deployments following the `.env.example` without explicitly enabling the flag — silently runs with no RPC authentication. The code bug is the insecure-by-default behavior, not merely an operator config mistake: the code should fail closed (require explicit opt-out of verification) rather than fail open.

---

### Recommendation

Change the default to secure-by-default. Either:
1. Treat an absent `CLIENT_VERIFICATION` as `true` (require explicit `CLIENT_VERIFICATION=false` to disable), or
2. Return an error from `BridgeConfig::from_env` if `CLIENT_VERIFICATION` is absent, forcing operators to make an explicit choice.

Additionally, add a startup-time assertion or prominent `tracing::error!` (not just `warn!`) when `client_verification == false` on operator/verifier servers, since the current `warn!` only fires on the aggregator path. [6](#0-5) 

---

### Proof of Concept

1. Start an operator server with `CLIENT_VERIFICATION` unset (or explicitly absent from the environment).
2. Connect from any TLS client (no client certificate needed, since `client_ca_root` is not configured).
3. Call `internal_end_round(Empty {})`.
4. Observe the call succeeds — the `Noop` interceptor passes it through — where it must be rejected with `Status::unauthenticated`.

The existing test at `core/src/test/rpc_auth.rs` already demonstrates the correct behavior under `client_verification=true`; the same test with `client_verification=false` would show the bypass. [7](#0-6)

```rust
fn only_aggregator_and_self(
    req: Request<()>,
    our_cert: &CertificateDer<'static>,
    aggregator_cert: &CertificateDer<'static>,
) -> Result<Request<()>, Status> {
    let Some(peer_certs) = req.peer_certs() else {
        if cfg!(test) {
            // Test mode, we don't need to verify peer certificates
            return Ok(req);
        } else {
            // If we're not in test mode, we need to check peer certificates
            return Err(Status::unauthenticated(
                "Failed to verify peer certificate, is TLS enabled?",
            ));
        }
    };

    // IMPORTANT: Only check the leaf (end-entity) certificate, which is always the first
    // certificate in the chain. The leaf is the only certificate whose private key the peer
    // proved possession of during the TLS handshake. Checking anywhere else in the chain
    // would allow identity spoofing: an attacker could include a pinned cert as an
    // intermediate in their chain without possessing its private key.
    let Some(leaf_cert) = peer_certs.first() else {
        return Err(Status::unauthenticated("Peer certificate chain is empty"));
    };

    if is_internal(&req) {
        if leaf_cert == our_cert {
            Ok(req)
        } else {
            Err(Status::unauthenticated(
                "Unauthorized call to internal method (not self)",
            ))
        }
    } else if leaf_cert == aggregator_cert || leaf_cert == our_cert {
        Ok(req)
    } else {
        Err(Status::unauthenticated(
            "Unauthorized call to method (not aggregator or self)",
        ))
    }
```
