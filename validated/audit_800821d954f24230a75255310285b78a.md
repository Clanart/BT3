### Title

Unauthenticated `ReceivedOutput` deserialization accepts an offset/output pair not authorized for the wallet - (File: `networks/bitcoin/src/wallet/mod.rs`)

### Summary

`ReceivedOutput::read` accepts an attacker-chosen scalar offset, `TxOut`, and `OutPoint` as three independent fields. Unlike `Scanner`, it does not bind the claimed offset to the output’s `script_pubkey`, nor establish that the outpoint belongs to the scanned wallet. Consequently, a forged serialized `ReceivedOutput` can report Bitcoin value controlled by an unrelated script as spendable by the threshold key. [1](#0-0) [2](#0-1) 

### Finding Description

The authentic construction path is `Scanner::scan_transaction`: it looks up `output.script_pubkey` in the registered script map and copies the offset associated with that exact script. This preserves the invariant `script_pubkey == p2tr(base_key + G * offset)`. [3](#0-2) 

`ReceivedOutput::read` has no wallet key context and performs no equivalent check. It accepts any canonical scalar, any consensus-decodable `TxOut`, and any consensus-decodable `OutPoint`, then returns them as a “spendable output.” [4](#0-3) [1](#0-0) 

This is analogous to accepting a normalized identifier without resolving it to the stable identity it claims to represent. Here, the claimed spending identity is the scalar offset, while the authoritative spending condition is the output script. A caller that deserializes attacker-supplied bytes can receive a record whose claimed offset is valid in isolation but does not authorize spending the attached output.

### Impact Explanation

A forged object’s `value()` reports the attacker-selected `TxOut` amount, and `SignableTransaction::new` consumes that amount and outpoint when constructing a spend. [5](#0-4) [6](#0-5) 

If the attacker attaches an output paying their own Taproot key but claims `offset = 0`, the wallet’s accounting path can treat the value as available even though the threshold key cannot spend it. The mismatch is caught only later by `SignableTransaction::multisig`, which compares the deserialized prevout script with `p2tr_script_buf` of the offset group key and returns `None`. [7](#0-6) [8](#0-7) 

This creates funds reported as received/available that are not spendable, and can stall scheduling or signing once the forged output is selected.

### Likelihood Explanation

Exploitation requires an application path that accepts serialized `ReceivedOutput` values rather than obtaining them solely from `Scanner`. That is the exposed purpose of the public `read`/`write` serialization pair. The attacker only needs to supply consensus-valid Bitcoin encodings and a canonical scalar; no private key, validator compromise, malformed curve point, or hash collision is required. [9](#0-8) 

### Recommendation

Do not treat a deserialized `ReceivedOutput` as authenticated scan evidence.

- Add a key-aware validation/deserialization API, such as `ReceivedOutput::read_for_key(reader, base_key)`, that rejects records unless `output.script_pubkey == p2tr_script_buf(base_key + G * offset)`.
- Require consumers to verify the claimed `outpoint` exists on the accepted Bitcoin chain and contains the claimed `TxOut`.
- Prefer storing and re-deriving scan results from authenticated block data rather than accepting standalone serialized `ReceivedOutput` objects from untrusted sources.

### Proof of Concept

```rust
use bitcoin::{
  consensus::serialize,
  Amount, OutPoint, ScriptBuf, TxOut, Txid,
};
use bitcoin::hashes::Hash;
use k256::Scalar;
use serai_bitcoin::wallet::ReceivedOutput;

// A Taproot output paying an attacker-controlled script, with a real or
// attacker-chosen outpoint.
let attacker_output = TxOut {
  value: Amount::from_sat(100_000),
  script_pubkey: attacker_p2tr_script,
};

let attacker_outpoint = OutPoint {
  txid: Txid::from_byte_array([0x42; 32]),
  vout: 0,
};

// The forged record claims the wallet's unoffset key controls the output.
let mut encoded = Vec::new();
encoded.extend(Scalar::ZERO.to_bytes());
encoded.extend(serialize(&attacker_output));
encoded.extend(serialize(&attacker_outpoint));

let forged = ReceivedOutput::read(&mut encoded.as_slice()).unwrap();

// The object reports 100_000 sats as received, even though the wallet offset
// does not correspond to attacker_p2tr_script.
assert_eq!(forged.value(), 100_000);
```

When passed with wallet keys to `SignableTransaction::multisig`, the forged input fails the script check because `p2tr_script_buf(keys.offset(0).group_key())` produces the wallet script, not `attacker_p2tr_script`. [8](#0-7)

  #[cfg(feature = "std")]
  pub fn read<R: Read>(r: &mut R) -> io::Result<ReceivedOutput> {
    let offset = Secp256k1::read_F(r)?;
    let output;
    let outpoint;
    {
      let mut buf_r = BufReader::with_capacity(0, r);
      output =
        TxOut::consensus_decode(&mut buf_r).map_err(|_| io::Error::other("invalid TxOut"))?;
      outpoint =
        OutPoint::consensus_decode(&mut buf_r).map_err(|_| io::Error::other("invalid OutPoint"))?;
    }
    Ok(ReceivedOutput { offset, output, outpoint })
  }

  /// Write a ReceivedOutput to a generic satisfying Write.
  pub fn write<W: Write>(&self, w: &mut W) -> io::Result<()> {
    w.write_all(&self.offset.to_bytes())?;
    w.write_all(&serialize(&self.output))?;
    w.write_all(&serialize(&self.outpoint))
  }
