### Title
DataLayer mirror URLs from unauthenticated on-chain coins enable SSRF via unvalidated HTTP fetch - (File: `chia/data_layer/download_data.py`)

### Summary
Any wallet user can create a "mirror" coin that associates an arbitrary set of URL strings with **any** DataLayer `launcher_id`, including stores they do not own. DataLayer nodes that subscribe to that store pull these attacker-controlled URLs into their local subscription list and later issue outbound HTTP GET requests to them with no validation of scheme (`http`/`https`) or destination host (loopback, link-local, RFC1918, cloud metadata endpoint, etc.). This mirrors the Quill SSRF pattern (CVE-2026-31959): a URL sourced from an untrusted external response is fetched by the client without scheme/host validation.

### Finding Description
A mirror coin is created purely from wallet-controlled memo data — `DataLayerWallet.create_new_mirror()` builds a standard coin spend to `create_mirror_puzzle()` with `memos=[[launcher_id, *urls]]` [1](#0-0) . There is no on-chain or wallet-side check binding the memo `launcher_id` to a singleton actually owned or controlled by the spender — any XCH holder can create a mirror coin naming an arbitrary victim `launcher_id` (store id) and arbitrary URLs, as confirmed by the mirror-parsing helper that simply extracts `launcher_id` and URL list from CREATE_COIN memos [2](#0-1) . This is exposed to any wallet user via the `dl_new_mirror` RPC [3](#0-2)  and CLI `add_mirror`/`dl_new_mirror` [4](#0-3) .

Any DataLayer node subscribed to that `launcher_id` fetches these mirrors via `dl_get_mirrors` and merges the URLs directly into its local subscription server list without filtering scheme or destination: [5](#0-4) 

These server URLs are then consumed by `fetch_and_validate()`/`insert_from_delta_file()` during the periodic sync loop [6](#0-5) , ultimately reaching `http_download()`, which issues an `aiohttp` GET request built by simple string concatenation of the attacker-supplied URL with no scheme/host validation: [7](#0-6) 

Unlike the S3 plugin path, which validates `parse_result.scheme == "s3"` before acting [8](#0-7) , the default HTTP downloader path performs no equivalent validation of scheme or of whether the host resolves to a loopback/link-local/private/multicast address before making the outbound request.

### Impact Explanation
An unprivileged wallet user (Data Layer client) can cause any other DataLayer node that subscribes to a chosen store to issue arbitrary outbound HTTP requests — to internal services, loopback addresses, or cloud metadata endpoints (e.g. `http://169.254.169.254/...`) — from the victim's network position. This can be used to probe or interact with internal infrastructure, potentially exfiltrating credentials or triggering unintended actions on internal HTTP services reachable only from the victim node, matching the SSRF impact class described in the analog advisory (CWE-918/CWE-20).

### Likelihood Explanation
Likelihood is moderate: creating a mirror coin costs only the standard mirror amount + fee and requires no ownership of the target store, and any active DataLayer subscriber to that store id will automatically pick up and attempt to fetch the malicious URLs during its normal periodic sync loop (`periodically_manage_data()` → `update_subscription()` → `fetch_and_validate()`), with no operator interaction required.

### Recommendation
- Validate mirror/subscription URLs before use: enforce an allowed scheme (`https`, and optionally `http` only if explicitly configured), and reject URLs whose host resolves to loopback, link-local, private, or multicast addresses (mirroring the SSRF hardening pattern from GHSA-7q3q-5px6-4c5p).
- Apply this validation both when persisting mirror URLs from wallet data (`update_subscriptions_from_wallet`) and immediately before dispatching the request in `http_download()`.
- Consider requiring operator opt-in/allow-listing for automatically-discovered mirror URLs vs. manually configured ones.

### Proof of Concept
1. Attacker wallet calls `dl_new_mirror` RPC with `launcher_id = <victim_store_id>` (a store the attacker does not own) and `urls=["http://169.254.169.254/latest/meta-data/"]`, paying only the mirror coin amount + fee: [3](#0-2) 
2. The mirror coin is confirmed on chain; any node's `dl_get_mirrors(launcher_id=victim_store_id)` now returns the attacker's URL as a legitimate mirror for that store.
3. A victim DataLayer node subscribed to `victim_store_id` runs its periodic sync, calling `update_subscriptions_from_wallet` which merges the malicious URL into its subscription list unfiltered: [5](#0-4) 
4. On the next `fetch_and_validate()` cycle, `insert_from_delta_file()`/`download_file()` selects this server and calls `http_download()`, which issues `session.get("http://169.254.169.254/latest/meta-data/" + "/" + filename, ...)` from the victim's network context: [9](#0-8)

def get_mirror_info(
    parent_puzzle: Program | SerializedProgram, parent_solution: Program | SerializedProgram
) -> tuple[bytes32, list[bytes]]:
    assert type(parent_puzzle) is type(parent_solution)
    _, conditions = run_with_cost(parent_puzzle, INFINITE_COST, parent_solution)
    for condition in conditions.as_iter():
        if (
            condition.first().as_python() == ConditionOpcode.CREATE_COIN
            and condition.at("rf").as_python() == create_mirror_puzzle().get_tree_hash()
        ):
            memos: list[bytes] = condition.at("rrrf").as_python()
            launcher_id = bytes32(memos[0])
            return launcher_id, [url for url in memos[1:]]

async def http_download(
    target_filename_path: Path,

    proxy_url: str | None,
    server_info: ServerInfo,

    log: logging.Logger,
    max_delta_file_size: int,

    """
    Download a file from a server using aiohttp.
    Raises exceptions on errors
    """
    async with aiohttp.ClientSession() as session:
        headers = {"accept-encoding": "gzip"}
        async with session.get(
