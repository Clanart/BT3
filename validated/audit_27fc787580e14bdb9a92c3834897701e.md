### Title
Malicious remote/proxy can spoof `WWW-Authenticate: realm="GitHub"` to force GitHub Enterprise sign-in flow against an attacker-controlled endpoint - ([File: app/src/lib/trampoline/trampoline-credential-helper.ts])

### Summary
`getEndpointKind()`, used by the Git credential-helper trampoline to decide whether an HTTPS remote is a GitHub host, trusts a self-declared, attacker-controllable HTTP response header (`WWW-Authenticate` with `realm="GitHub"`) as a "happy path" proof of identity, without any cryptographic or independent verification. This mirrors the Hats/HOPR finding: a value is asked whether it belongs to a trusted class (`isHoprNodeManagementModule()` vs. `realm="GitHub"`), and the code trusts the self-declaration to make a security-relevant decision, instead of independently proving membership/identity.

### Finding Description
When Git needs credentials for an HTTPS remote, Desktop's trampoline credential helper calls `getEndpointKind()` to classify the endpoint: [1](#0-0) 

Specifically, it inspects `wwwauth[...]` parameters that Git forwards from the server's `WWW-Authenticate` response header, and if the value contains `realm="GitHub"`, it unconditionally classifies the endpoint as `'enterprise'`: [2](#0-1) 

This header is fully attacker-controlled: any HTTPS server the user's Git process talks to (a malicious remote the user cloned/added, or a MITM/dev proxy sitting on the network path) can respond to the unauthenticated `git-upload-pack`/`git-receive-pack` request with a `401` and `WWW-Authenticate: Basic realm="GitHub"`, exactly like the on-chain module in the report that implements `isHoprNodeManagementModule()`/`isNode()` to falsely claim membership in a trusted category.

Once `getEndpointKind()` returns `'enterprise'` (not `'generic'`), `getCredential()` checks whether the user already has a stored account for that host's computed API endpoint. If not, it invokes `ui.promptForGitHubSignIn(endpoint)`: [3](#0-2) 

`promptForGitHubSignIn()` then drives the real "Sign in to GitHub Enterprise" UI flow, pointing it at the attacker's origin: [4](#0-3) 

This calls `dispatcher.setSignInEndpoint(origin)` and `dispatcher.beginEnterpriseSignIn(cb)` with the attacker-controlled `origin`, launching Desktop's normal GHE OAuth/basic-auth sign-in dialog against a host the user never explicitly told Desktop to trust as "GitHub Enterprise" — the classification came solely from a spoofable header echoed back by the remote itself.

### Impact Explanation
This satisfies "unauthorized OAuth or account binding" and potential credential exfiltration: the sign-in dialog is presented to the user as a legitimate GitHub Enterprise authentication prompt (Desktop's own trusted native UI), but it targets an attacker-chosen origin. If the resulting sign-in succeeds (e.g., basic-auth/PAT entry, or an enterprise instance the attacker actually stands up and serves a convincing login page/API from), the account gets bound into Desktop's `AccountsStore` as a first-class GitHub account for that attacker endpoint. Any credentials or tokens the user submits during that flow go to the attacker's server, and the resulting attacker-controlled account/endpoint is subsequently trusted by other endpoint-classification helpers (`isDotCom`, `isGHE`, `findGitHubTrampolineAccount`) for future operations, similar to how the HOPR issue lets a malicious module falsely satisfy the safety check.

### Likelihood Explanation
The trigger requires only that the user's Git client performs an HTTPS request to a repository/remote controlled or intercepted by the attacker (e.g., the user adds/clones a malicious remote URL, or an on-path proxy responds to the request) — no local access, admin rights, or pre-existing malware is needed. The `realm="GitHub"` string match is trivial to produce from any HTTP server, making this a low-effort, high-reliability spoof of the existing "happy path" check that was explicitly designed to avoid an extra network round trip (`isGitHubHost`).

### Recommendation
Do not treat the `WWW-Authenticate` realm string as authoritative proof that a host is GitHub/GHE. At minimum, require corroboration via an independent signal (e.g., the `isGitHubHost()` meta-endpoint probe that checks for the `x-github-request-id` response header over a request Desktop itself issues) before auto-launching the enterprise sign-in flow, and surface the actual target hostname prominently in the sign-in prompt so users can recognize an unexpected/unfamiliar host before entering credentials.

### Proof of Concept
1. Attacker hosts an HTTPS git server (or sits as a MITM proxy) at `https://evil.example.com/attacker/repo.git`.
2. Victim adds this as a remote or clones it in GitHub Desktop.
3. When Desktop/Git attempts to fetch and receives a 401 challenge, the attacker's server responds with header `WWW-Authenticate: Basic realm="GitHub"`.
4. `getEndpointKind()` in `app/src/lib/trampoline/trampoline-credential-helper.ts` matches this string and returns `'enterprise'` without any further verification: [5](#0-4) 
5. Since the victim has no stored account for `evil.example.com`, `getCredential()` calls `ui.promptForGitHubSignIn('https://evil.example.com')`, which opens Desktop's native "Sign in to GitHub Enterprise" dialog pointed at the attacker's origin: [6](#0-5) 
6. The victim, seeing what looks like Desktop's trusted sign-in UI, enters credentials/PAT which are sent to the attacker-controlled endpoint, and/or an attacker-controlled "account" becomes registered in Desktop's account store as a GitHub Enterprise account.

const getEndpointKind = async (cred: Credential, store: Store) => {
  const credentialUrl = getCredentialUrl(cred)
  const endpoint = `${credentialUrl}`

  if (isGist(endpoint)) {
    return 'generic'
  }

  if (isDotCom(endpoint)) {
    return 'github.com'
  }

  if (isGHE(endpoint)) {
    return 'ghe.com'
  }

  // When Git attempts to authenticate with a host it captures any
  // WWW-Authenticate headers and forwards them to the credential helper. We
  // use them as a happy-path to determine if the host is a GitHub host without
  // having to resort to making a request ourselves.
  for (const [k, v] of cred.entries()) {
    if (k.startsWith('wwwauth[')) {
      if (v.includes('realm="GitHub"')) {
        return 'enterprise'
      } else if (/realm="(GitLab|Gitea|Atlassian Bitbucket)"/.test(v)) {
        return 'generic'
      }
    }
  }

  const existingAccount = await findGitHubTrampolineAccount(store, endpoint)
  if (existingAccount) {
    return isDotCom(existingAccount.endpoint) ? 'github.com' : 'enterprise'
  }

  // All GitHub hosts use HTTPS, so if the protocol is not HTTPS we can
  // assume that this is not a GitHub host.
  if (credentialUrl.protocol !== 'https:') {
    return 'generic'
  }

  return (await isGitHubHost(endpoint)) ? 'enterprise' : 'generic'
}

  public promptForGitHubSignIn(endpoint: string): Promise<Account | undefined> {
    return new Promise<Account | undefined>(async resolve => {
      const cb = (result: SignInResult) => {
        resolve(result.kind === 'success' ? result.account : undefined)
        this.dispatcher.closePopup(PopupType.SignIn)
      }

      const { hostname, origin } = new URL(endpoint)
      if (hostname === 'github.com') {
        this.dispatcher.beginDotComSignIn(cb)
      } else {
        this.dispatcher.beginEnterpriseSignIn(cb)
        await this.dispatcher.setSignInEndpoint(origin)
      }

      this.dispatcher.showPopup({
        type: PopupType.SignIn,
        isCredentialHelperSignIn: true,
        credentialHelperUrl: endpoint,
      })
