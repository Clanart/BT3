### Title
`getEndpointKind()` classifies an arbitrary remote host as GitHub Enterprise based solely on attacker-controlled `WWW-Authenticate` header, bypassing endpoint-identity checks - (File: `app/src/lib/trampoline/trampoline-credential-helper.ts`)

### Summary
The original report's bug class is "an externally supplied parameter is used in an access-control decision without being validated first." The closest verified analog in this GitHub Desktop repository is `getEndpointKind()` in `app/src/lib/trampoline/trampoline-credential-helper.ts`, which decides whether a git remote host should be treated as a GitHub/Enterprise endpoint (an access-control-relevant classification) by trusting a server-supplied HTTP header value rather than validating the host itself.

### Finding Description
When Git needs credentials for an HTTPS request it invokes Desktop's credential helper trampoline with the response's `WWW-Authenticate` headers forwarded as `wwwauth[]` entries in the credential map [1](#0-0) . `getEndpointKind()` inspects these attacker/server-controlled header values and, if any contains `realm="GitHub"`, unconditionally returns `'enterprise'` for that host — with no validation of the actual hostname, TLS identity, or any allow-list [1](#0-0) .

This classification is then used directly as an access-control gate in `getCredential()`: if `endpointKind !== 'generic'` and there's no existing account for that host, Desktop calls `ui.promptForGitHubSignIn(endpoint)`, initiating a GitHub Enterprise sign-in/OAuth flow scoped to the attacker-chosen `endpoint` [2](#0-1) . Because `endpoint` is derived straight from `getCredentialUrl(cred)` — itself built from fields (`url`/`protocol`/`host`/`path`) that ultimately originate from the git remote/HTTP response Git is talking to [3](#0-2)  — any HTTPS host the user's Desktop-managed Git process contacts (including a malicious remote or a redirect target) can inject this header and cause Desktop to treat it as a legitimate GitHub Enterprise endpoint worthy of the sign-in UI, without any check that the host is a real GHE instance (e.g., via `isGitHubHost`/API probe, which is only used as a *fallback*, not as a gate on the header-based path) [4](#0-3) .

This mirrors the reported Solidity bug class precisely: a parameter (`endpointKind`, ultimately derived from an unvalidated header/host value) is consumed by downstream access-control logic (`endpointKind !== 'generic'` branch) without first validating that the underlying identity claim (that the host really is GitHub Enterprise) is legitimate.

### Impact Explanation
An attacker who controls a git remote/HTTP endpoint that the user's Desktop-managed Git client talks to (e.g., a malicious or compromised remote, or a man-in-the-middle/redirect scenario on a fetch/clone) can spoof the `WWW-Authenticate: ... realm="GitHub"` response header to force Desktop's credential trampoline to classify that arbitrary host as `'enterprise'`. This triggers the "sign in to GitHub Enterprise" popup pointed at the attacker's host, tricking the user into an OAuth flow against a host they did not intend to authenticate with. This satisfies the "unauthorized OAuth binding" impact category from an attacker-controlled remote/proxy response.

### Likelihood Explanation
The path is reachable purely by responding to a normal HTTPS Git operation (clone/fetch/push) with a crafted `401 WWW-Authenticate` header — no local access, admin rights, or prior compromise is required; it only requires the user to have added or be interacting with an attacker-controlled or MITM'd remote, which is within the documented threat model (attacker-controlled git remote/proxy response). The header-based classification is the *first* check performed, ahead of the more robust `isGitHubHost()` API probe fallback, so it fires without any secondary verification when the header is present.

### Recommendation
Do not classify a host as `'enterprise'` solely from a self-reported `WWW-Authenticate` realm string. At minimum, require this header-based hint to be corroborated by an actual API probe (the same mechanism already used as the fallback, `isGitHubHost(endpoint)`) before triggering `promptForGitHubSignIn`, or restrict the header-based fast path to hosts already known/trusted (e.g., previously-added GHE accounts) rather than arbitrary new hosts.

### Proof of Concept
1. Set up an HTTPS server the victim's Desktop will contact as a git remote (e.g., `https://evil.example.com/attacker/repo.git`), simulating a malicious or compromised remote/proxy.
2. Configure the server to respond to Git's HTTP auth probe with `401 Unauthorized` and header `WWW-Authenticate: Basic realm="GitHub"`.
3. In GitHub Desktop, clone/fetch this remote. Git invokes the credential helper trampoline, forwarding the header as `wwwauth[]=Basic realm="GitHub"` [1](#0-0) .
4. `getEndpointKind()` returns `'enterprise'` for `evil.example.com` purely from the header match.
5. `getCredential()` sees no existing account for `evil.example.com` and calls `ui.promptForGitHubSignIn('https://evil.example.com')`, popping the "Sign in to GitHub Enterprise" dialog scoped to the attacker's domain [5](#0-4) .

async function getCredential(cred: Credential, store: Store, token: string) {
  const ghCred = await getGitHubCredential(cred, store)

  if (ghCred) {
    return ghCred
  }

  const endpointKind = await getEndpointKind(cred, store)
  const accounts = await store.getAll()

  const endpoint = `${getCredentialUrl(cred)}`
  const apiEndpoint = getAPIEndpoint(endpoint)

  // If it appears as if the endpoint is a GitHub host and we don't have an
  // account for that endpoint then we should prompt the user to sign in.
  if (
    endpointKind !== 'generic' &&
    !accounts.some(a => a.endpoint === apiEndpoint)
  ) {
    if (getIsBackgroundTaskEnvironment(token)) {
      debug('background task environment, skipping prompt')
      return undefined
    }

    const account = await ui.promptForGitHubSignIn(endpoint)

    if (!account) {
      setHasRejectedCredentialsForEndpoint(token, endpoint)
    }

    return credWithAccount(cred, account)
  }

export const getCredentialUrl = (cred: Map<string, string>) => {
  const u = cred.get('url')
  if (u) {
    return new URL(u)
  }

  const protocol = cred.get('protocol') ?? ''
  const username = cred.get('username')
  const user = username ? `${encodeURIComponent(username)}@` : ''
  const host = cred.get('host') ?? ''
  const path = cred.get('path') ?? ''

  return new URL(`${protocol}://${user}${host}/${path}`)
}
