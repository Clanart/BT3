### Title
App Proxy signature verification has no timestamp/replay check, allowing indefinite replay of captured requests - ([File: lib/shopify_app/controller_concerns/app_proxy_verification.rb])

### Summary
The `ShopifyApp::AppProxyVerification` concern validates that an incoming App Proxy request's `signature` query parameter matches an HMAC computed over the other query parameters, but it never checks the `timestamp` parameter (which Shopify includes in every App Proxy request) against the current time, and it keeps no record of previously-seen signatures/nonces. This is the same bug class as the reported `ChainlinkAtlasWrapper.transmit()` issue: a validly-signed message can be reused (retransmitted) indefinitely because nothing enforces "use only once" or "use only within a freshness window."

### Finding Description
`verify_proxy_request` calls `query_string_valid?`, which strips the `signature` param, recomputes an HMAC over the remaining sorted query params using the app secret, and does a `secure_compare` against the supplied signature: [1](#0-0) 

`calculated_signature` includes whatever params are in the query string (Shopify includes `shop`, `path_prefix`, `timestamp`, `logged_in_customer_id`, etc.), but the `timestamp` value is never compared to "now," and there is no persisted set of consumed signatures: [2](#0-1) 

Because App Proxy requests are issued by a storefront visitor's browser to `https://<shop>.myshopify.com/apps/<subpath>` and then forwarded by Shopify to the app with the same signed query string, any unprivileged party who can observe that URL (e.g., via browser devtools/network tab, browser history, a shared link, or logs) can replay it to the app server as many times and as long after the original request as they want, and it will still pass verification. The webhook HMAC verification concern (`lib/shopify_app/controller_concerns/payload_verification.rb` / `webhook_verification.rb`) has the identical gap — no delivery-id/nonce tracking — but is lower severity there since webhook payloads aren't normally exposed to a browser client the way App Proxy query strings are.

### Impact Explanation
This maps to the "accepted forged/old signed request" category: a previously valid, signed request continues to be accepted by the app indefinitely. Depending on what the app's App Proxy endpoint does (e.g., look up or mutate data tied to `shop`/`logged_in_customer_id`), an attacker replaying a captured proxy URL could repeat state-changing actions or access data associated with another customer's session parameters embedded in that URL, without needing any credentials — this is a genuine authentication/freshness weakness in a component reachable by any anonymous storefront visitor.

### Likelihood Explanation
Likelihood is moderate-to-high: App Proxy request URLs (including `signature` and `timestamp`) are directly visible in the requesting browser's network activity, so no privileged access or secret leak is required to obtain a replayable request — only the ability to observe traffic from one's own (or another) storefront session.

### Recommendation
Enforce a freshness window on the `timestamp` query parameter in `query_string_valid?` (reject requests older than e.g. 60–300 seconds), and/or maintain a short-lived cache of consumed signatures to reject duplicates, mirroring the fix pattern used in `ChainlinkAtlasWrapper` PR 184 (monotonically increasing/one-time-use identifiers).

### Proof of Concept
1. Visit a storefront page that triggers a call to the app's App Proxy endpoint (browser issues `GET https://shop.myshopify.com/apps/<subpath>?shop=...&timestamp=...&signature=...`).
2. Capture the fully-qualified forwarded request/query string (observable in devtools).
3. Replay the exact same query string to the app's proxy route at any later time (`query_string_valid?` in `lib/shopify_app/controller_concerns/app_proxy_verification.rb` line 17-27 performs only an HMAC equality check, no timestamp/nonce check) — the request is accepted identically to the original.

    def query_string_valid?(query_string)
      query_hash = Rack::Utils.parse_query(query_string)

      signature = query_hash.delete("signature")
      return false if signature.nil?

      ActiveSupport::SecurityUtils.secure_compare(
        calculated_signature(query_hash),
        signature,
      )
    end
```

    def calculated_signature(query_hash_without_signature)
      sorted_params = query_hash_without_signature.collect { |k, v| "#{k}=#{Array(v).join(",")}" }.sort.join

      OpenSSL::HMAC.hexdigest(
        OpenSSL::Digest.new("sha256"),
        ShopifyApp.configuration.secret,
        sorted_params,
      )
    end
```
