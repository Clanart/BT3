### Title
`ReceivedOutput::read` accepts arbitrary offset/script_pubkey pairs, bypassing the `Scanner` binding check so a deserialized output can be reported spendable under a key that does not control it - (File: networks/bitcoin/src/wallet/mod.rs)

### Summary
The Symfony advisory is an underinclusive gate: a deny/validity check applied to one representation of the input while an equivalent (decoded) representation reaches the consumer unchecked. The same shape exists in bitcoin-serai. The only code that binds a scalar `offset` to the `script_pubkey` it purports to control is `Scanner::scan_transaction`, which looks up `output.script_pubkey` in the `scripts` map populated by `register_offset` (which derives the script from `key + offset·G`). `ReceivedOutput::read` — explicitly a sink for untrusted bytes — deserializes `(offset, output, outpoint)` with no such consistency check, so a forged serialization pairs any offset with any `script_pubkey`.

### Finding Description
`Scanner::register_offset` computes `p2tr_script_buf(self.key + GENERATOR * offset)` and stores `script -> offset`, so `scan_transaction` only ever yields `ReceivedOutput`s whose offset actually derives the output's key [1](#0-0) . `ReceivedOutput::read` reconstructs the same struct from a byte stream — `Secp256k1::read_F` for the offset, then `TxOut::consensus_decode` and `OutPoint::consensus_decode` — and returns it without verifying `output.script_pubkey == p2tr_script_buf(key + offset·G)` [2](#0-1) . `ReceivedOutput` doesn't even store the group key, so the consistency check cannot be re-established downstream. Consumers then trust `output.offset()` as the scalar needed to spend `output`, exactly as the test and wallet flow do when passing `output.offset()` into `SignableTransaction`/multisig signing [3](#0-2) .

### Impact Explanation
A party able to feed crafted bytes into `ReceivedOutput::read` (e.g., a serialized output passed between components or recovered from untrusted storage/input) creates an output the wallet treats as spendable — the Taproot `script_pubkey` is a real registered-looking script — while the claimed `offset` yields a tweaked key `key + offset·G` that is not the key in the script. Signing proceeds with the wrong offset key, producing a BIP-340 signature that cannot satisfy the output's script: the funds are reported received but are not spendable, and any spend attempt produces an invalid transaction. This is precisely the "validated in one form, accepted in another" failure: canonicality of the scalar (`read_F`) is checked, but the semantic offset↔script binding enforced at scan time is absent on the deserialization path.

### Likelihood Explanation
Reachable wherever `ReceivedOutput::read` consumes bytes an unprivileged party influences; the struct's own `serialize`/`read` round-trip is exercised across components [4](#0-3) . Exploitation requires no key material — only control of the serialized tuple. Impact is bounded to an unspendable-output/invalid-signature outcome (no key leakage), consistent with Medium.

### Recommendation
Either store the group key (or the expected script) in `ReceivedOutput` and have `read` verify `output.script_pubkey == p2tr_script_buf(key + GENERATOR * offset)` and the `outpoint`, or provide a `verify(key)`/`revalidate(&Scanner)` method and require it after any deserialization before the output is used for planning/signing.

### Proof of Concept
1. Let `K` be the group key and `s = p2tr_script_buf(K)` a real output script worth `v` sats.
2. Attacker crafts `ReceivedOutput { offset: Scalar::ONE, output: TxOut { script_pubkey: s, value: v }, outpoint: <any> }` — or any `offset` where `K + offset·G ≠ K`.
3. `ReceivedOutput::read` accepts it (offset is canonical; TxOut/OutPoint decode).
4. The multisig signs the spend applying `offset = 1` to its shares; the resulting signature verifies against `K + G`'s x-only key, not `K`, so the input fails script validation — the "received" funds are unspendable via the wallet's own signing path.

  #[cfg(feature = "std")]
  pub fn read<R: Read>(r: &mut R) -> io::Result<ReceivedOutput> {
    let offset = Secp256k1::read_F(r)?;
    let output;
    let outpoint;
    {
      let mut buf_r = BufReader::with_capacity(0, r);
      output =
        TxOut::consensus_decode(&mut buf_r).map_err(|_| io::Error::other("invalid TxOut"))?;
      outpoint =
        OutPoint::consensus_decode(&mut buf_r).map_err(|_| io::Error::other("invalid OutPoint"))?;
    }
    Ok(ReceivedOutput { offset, output, outpoint })
  }

  pub fn register_offset(&mut self, mut offset: Scalar) -> Option<Scalar> {
    // This loop will terminate as soon as an even point is found, with any point having a ~50%
    // chance of being even
    // That means this should terminate within a very small amount of iterations
    loop {
      match p2tr_script_buf(self.key + (ProjectivePoint::GENERATOR * offset)) {
        Some(script) => {
          if self.scripts.contains_key(&script) {
            None?;
          }
          self.scripts.insert(script, offset);
          return Some(offset);
        }
        None => offset += Scalar::ONE,
      }
    }
  }

  /// Scan a transaction.
  pub fn scan_transaction(&self, tx: &Transaction) -> Vec<ReceivedOutput> {
    let mut res = Vec::new();
    for (vout, output) in tx.output.iter().enumerate() {
      // If the vout index exceeds 2**32, stop scanning outputs
      let Ok(vout) = u32::try_from(vout) else { break };

      if let Some(offset) = self.scripts.get(&output.script_pubkey) {
        res.push(ReceivedOutput {
          offset: *offset,
          output: output.clone(),
          outpoint: OutPoint::new(tx.compute_txid(), vout),
        });
      }
    }
