### Title
Broken `\z` extension-exclusion regex lets `.patch`/`.diff` download links be relabeled as innocuous `#N` issue references - (File: `app/src/lib/markdown-filters/issue-link-filter.ts`)

### Summary
`isGitHubIssuePullDiscussionLink()` tries to exclude "custom format" GitHub URLs (e.g. `.patch`, `.diff`, `.zip`) from being treated as plain issue/PR/discussion links, using the regex `/\.[a-z]+\z/`. In JavaScript, `\z` is not a supported regex escape and is parsed as the literal character `z`, not an end-of-string anchor. As a result the check fails to detect almost every real extension (including `.patch` and `.diff`, which contain no `z`), so the exclusion never fires for these URLs.

### Finding Description
`isURlCustomFormat` is computed as: [1](#0-0) 

The intent (per the docstring/example list, which explicitly does not include `.patch`/`.diff` as valid formats) is to reject links that point to a file/data variant of an issue or PR (`.patch`, `.diff`, `.zip`, etc.) rather than the normal HTML page. Because `\z` is treated as a literal `z`, the pattern actually requires a literal `z` character to appear after a run of lowercase letters following a `.` — which `.patch` and `.diff` never satisfy. So `isURlCustomFormat` evaluates to `false` for these URLs, and the exclusion check is silently bypassed: [2](#0-1) 

Execution then falls through to `issueUrl(this.repository).test(anchor.href)`: [3](#0-2) 

That regex is unanchored and its trailing `\b` matches at the boundary between the digit `1` and the following `.` in `.../issues/1.patch`, so it matches successfully with `refNumber="1"`. Combined with the tree-walker `acceptNode` check that only accepts anchors whose `href === innerText`: [4](#0-3) 

an `<a href="https://github.com/owner/repo/issues/1.patch">https://github.com/owner/repo/issues/1.patch</a>` node is accepted, and `filter()` rewrites its visible text to `#1` while leaving the `href` unchanged: [5](#0-4) 

This confirms the reported bypass: the `.patch`/`.diff` exclusion is dead code for these extensions due to the `\z`/literal-`z` mistake.

### Impact Explanation
The visible link text becomes a benign-looking `#1` issue/PR reference while the underlying `href` still points at a raw `.patch`/`.diff` (or other non-`z`-containing extension) endpoint that triggers a file download/diff view rather than the normal issue page navigation the user expects from the rendered text. This is a link-text spoofing / UI-deception issue affecting any markdown rendering path that uses `IssueLinkFilter` (commit messages, PR/issue bodies, comments, etc., wherever markdown filters are applied) with attacker-controlled repository content or API text. However, the destination is still confined to `github.com` (same repo/owner), and it results in a misleading label rather than code execution, credential exfiltration, arbitrary origin navigation, or corruption of what the user commits/pushes — the underlying href is not altered and no additional privilege or trust boundary is crossed beyond the link text presentation.

### Likelihood Explanation
High reachability: the only requirement is that an untrusted markdown source (issue/PR/discussion body, commit message, comment) contain a bare URL like `https://github.com/owner/repo/issues/1.patch`, which markdown auto-linking will turn into an anchor with identical href/innerText — exactly the pattern this filter targets. No special user interaction beyond normal viewing/clicking a link is required to trigger the mislabeling.

### Recommendation
Fix the regex to properly anchor to the end of the string in JavaScript syntax, e.g. `/\.[a-z]+$/` (or `/\.[a-z0-9]+$/` if extensions can include digits), so `.patch`, `.diff`, and other file-format suffixes are correctly excluded from being treated as plain issue/PR/discussion links.

### Proof of Concept
1. Construct markdown/HTML content (e.g., in an issue comment or commit message) containing:
   `<a href="https://github.com/owner/repo/issues/1.patch">https://github.com/owner/repo/issues/1.patch</a>`
   (or simply the bare URL, which the markdown auto-linker converts into this anchor form).
2. Run it through `IssueLinkFilter` for a `GitHubRepository` matching `owner/repo` on `github.com`.
3. Observe:
   - `isURlCustomFormat` (`/\.[a-z]+\z/.test(href)`) returns `false` (no literal `z` present), so the exclusion does not trigger.
   - `issueUrl(repository).test(href)` returns `true` (word boundary matches before the trailing `.patch`).
   - `filter()` rewrites the node's text content from the full `.patch` URL to `#1`, while `href` remains `https://github.com/owner/repo/issues/1.patch`.
4. Compare with a control case using `.gz` (contains `z`) to show the exclusion works correctly there, confirming the bug is specific to the broken `\z` handling.

export function issueUrl(repository: GitHubRepository): RegExp {
  const gitHubURL = getHTMLURL(repository.endpoint)
  return new RegExp(
    escapeRegExp(gitHubURL) +
      '/' +
      /** A regexp that searches for the owner/name pattern in issue href */
      /(?<nameWithOwner>\w+(?:-\w+)*\/[.\w-]+)/.source +
      '/' +
      /(?:issues|pull|discussions)/.source +
      '/' +
      /** A regexp that searches for the number and #anchor of an issue reference */
      /(?<refNumber>\d+)(?<anchor>#[\w-]+)?\b/.source
  )
}

  private isGitHubIssuePullDiscussionLink(anchor: HTMLAnchorElement) {
    const isIssuePullOrDiscussion = /(issue|pull|discussion)/.test(anchor.href)
    if (!isIssuePullOrDiscussion) {
      return false
    }

    const isPullRequestTab = /\d+\/(files|commits|conflicts|checks)/.test(
      anchor.href
    )
    if (isPullRequestTab) {
      return false
    }

    const isURlCustomFormat = /\.[a-z]+\z/.test(anchor.href)
    if (isURlCustomFormat) {
      return false
    }

    return issueUrl(this.repository).test(anchor.href)
  }

  public async filter(node: Node): Promise<ReadonlyArray<Node> | null> {
    const { textContent: text } = node
    if (!isElement(node, 'a') || text === null) {
      return null
    }

    const match = text.match(issueUrl(this.repository))
    if (match === null || match.groups === undefined) {
      return null
    }

    const { refNumber, anchor } = match.groups
    const newNode = node.cloneNode(true)
    newNode.textContent = this.getConsistentIssueReferenceText(
      refNumber,
      anchor
    )

    return [newNode]
  }
