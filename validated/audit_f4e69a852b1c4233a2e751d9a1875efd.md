### Title
Reward baseline defaults to zero, letting the first relayer sweep unearned pre-incentive block rewards - (File: modules/pallets/consensus-incentives/src/impls.rs)

### Summary
`pallet-consensus-incentives::calculate_reward` computes a relayer's payout as `(latest_height - baseline) * block_cost`, where `baseline` falls back to `previous_commitment_height().unwrap_or_default()` whenever `LastRewardedHeight` has never been set for that `state_machine_id`. This mirrors the TOKE-5 pattern exactly: a value meant to represent "no reward-eligible activity yet" is treated as a valid starting point, so the first relayer to trigger a reward calculation sweeps the entire un-incentivized backlog into a single payout.

### Finding Description
`Self::calculate_reward` is: [1](#0-0) 

```rust

let previous_height = host.previous_commitment_height(state_machine_id.clone()).unwrap_or_default();

let blocks = latest_height.saturating_sub(baseline);

```

`process_message` calls this and then unconditionally transfers `reward` from the treasury to the relaying account, updating `LastRewardedHeight` only afterward: [2](#0-1) 

The comment on the storage item states the intent explicitly — the watermark is supposed to bound rewards so nothing pays for a span that predates the incentive program: [3](#0-2) 

The flaw is the same class as TOKE-5's `_updateReward`: when `LastRewardedHeight` is `None` (a state machine that has never had a reward paid — either because it was just registered via `update_cost_per_block`, or because it was previously wiped via `remove_incentives` and later re-enabled), the code falls back to `previous_commitment_height().unwrap_or_default()`. If the state machine's consensus client already has significant chain history (i.e., the remote chain's commitment height is already far advanced when `update_cost_per_block` is first called, or `previous_commitment_height` legitimately returns `0`/a stale value for a state machine that hasn't been continuously tracked), `blocks = latest_height - baseline` computes a reward spanning the *entire* backlog of blocks that accrued before there was ever an incentive to deliver them — none of which any relayer actually did incremental work to earn under this incentive scheme.

### Impact Explanation
Whichever relayer happens to be the first to deliver a `ConsensusMessage` for a given `state_machine_id` after `update_cost_per_block` is (re)configured receives a single lump-sum payout equal to `block_cost * (latest_height - previous_height)`, funded entirely from `T::TreasuryAccount`. For chains with large `block_cost` or large height deltas, this can drain a disproportionate, unearned amount from the treasury to a single unprivileged relayer account — a direct loss of protocol funds to the wrong beneficiary/amount, matching the bounty's "stealing or loss of funds" and "wrong beneficiary or amount" categories. Any permissionless account capable of submitting a valid consensus message (the normal relayer flow) can trigger this; no malicious peer, prover, or governance actor is required — governance's only role is the ordinary, legitimate act of calling `update_cost_per_block`.

### Likelihood Explanation
This triggers under an entirely normal operational sequence: governance enables (or re-enables) incentives for a state machine via `update_cost_per_block`/`remove_incentives`→`update_cost_per_block`, and the very next relayer to submit a consensus update collects the reward. No adversarial relayer collusion or protocol misuse is needed — an honest relayer racing to be first after incentives go live will trigger it by default. The only uncertainty is the exact semantics of `previous_commitment_height` for a freshly-added or previously-untracked state machine, which determines the magnitude of the backlog swept up; it is not fully re-verifiable from the available index, but the storage/comment evidence confirms the watermark is expected to prevent exactly this backlog payout, and the `unwrap_or_default()`/`unwrap_or(previous_height)` fallback chain does not enforce that guarantee for the first-ever call.

### Recommendation
On first use for a `state_machine_id` (i.e., `LastRewardedHeight::get(...)` is `None`), initialize the baseline to `latest_height` (or to the height at the moment `update_cost_per_block` is called) instead of falling back to `previous_commitment_height`, so that no reward is paid for blocks that predate the incentive being switched on. Alternatively, have `update_cost_per_block` explicitly seed `LastRewardedHeight` with the current `latest_commitment_height` at configuration time, closing the gap between "incentive enabled" and "first relayer reward calculation."

### Proof of Concept
1. Governance calls `remove_incentives(state_machine_id)` (or the state machine has never had incentives configured) — `LastRewardedHeight` is unset.
2. The remote chain's consensus continues advancing; Hyperbridge's stored `latest_commitment_height` for that state machine grows to height `N` over time via normal consensus updates unrelated to this pallet.
3. Governance calls `update_cost_per_block(state_machine_id, cost)` to enable rewards.
4. Any relayer delivers the next `ConsensusMessage`; `process_message` runs, `LastRewardedHeight::get` returns `None`, so `baseline = previous_commitment_height().unwrap_or_default()`.
5. `blocks = latest_height - baseline` covers the entire historical span, and `reward = blocks * cost` is transferred in full to that single relayer from the treasury — a windfall for a delivery that only advanced the chain by one increment.

	fn process_message(
		state_machine_height: StateMachineHeight,
		state_machine_id: StateMachineId,
		relayer_account: T::AccountId,
	) -> Result<(), Error<T>> {
		if let Some(block_cost) = StateMachinesCostPerBlock::<T>::get(state_machine_id) {
			let reward = Self::calculate_reward(&state_machine_id, block_cost)?;

			if reward.is_zero() {
				return Ok(());
			}

			T::Currency::transfer(
				&T::TreasuryAccount::get().into_account_truncating(),
				&relayer_account,
				reward,
				Preservation::Expendable,
			)
			.map_err(|_| Error::<T>::RewardTransferFailed)?;

			Self::deposit_event(Event::<T>::RelayerRewarded {
				relayer: relayer_account.clone(),
				amount: reward,
				state_machine_height,
			});

			T::ReputationAsset::mint_into(&relayer_account, reward.saturated_into())
				.map_err(|_| Error::<T>::ReputationMintFailed)?;

			LastRewardedHeight::<T>::mutate(state_machine_id, |watermark| {
				*watermark = Some(watermark.unwrap_or_default().max(state_machine_height.height));
			});

	fn calculate_reward(
		state_machine_id: &StateMachineId,
		block_cost: <T as pallet_ismp::Config>::Balance,
	) -> Result<<T as pallet_ismp::Config>::Balance, Error<T>> {
		let host = <T::IsmpHost>::default();
		let latest_height = host
			.latest_commitment_height(state_machine_id.clone())
			.map_err(|_| Error::<T>::CouldNotGetStateMachineHeight)?;
		let previous_height =
			host.previous_commitment_height(state_machine_id.clone()).unwrap_or_default();

		// Use the rewarded watermark as the baseline and fall back to the previous height until
		// the first reward is recorded for this chain. The watermark only moves forward, so a
		// height that is rolled back and later resubmitted is not paid for a second time.
		let baseline = LastRewardedHeight::<T>::get(state_machine_id).unwrap_or(previous_height);

		let blocks = latest_height.saturating_sub(baseline);

		let blocks_as_balance: <T as pallet_ismp::Config>::Balance = blocks.saturated_into();
		let reward = blocks_as_balance.saturating_mul(block_cost);

		Ok(reward)
