### Title
Consensus-incentive reward for a delayed backlog is paid entirely at the *current* `CostPerBlock`, not the rate(s) that applied while the blocks accrued - ([File: modules/pallets/consensus-incentives/src/impls.rs])

### Summary
`pallet-consensus-incentives::calculate_reward` pays `Reward = (LatestHeight - baseline) * CostPerBlock`, using whatever `CostPerBlock` is *currently* configured for the whole unpaid block span, regardless of how long that span has been accumulating or how many rate changes happened while it was unpaid. This is the same broken invariant as the reported `RewardsMath.sol` bug: a multi-period quantity (blocks accrued across potentially several different `CostPerBlock` regimes) is priced using a single rate applied to the whole span, instead of weighting each sub-period by the rate that actually applied to it.

### Finding Description
`calculate_reward` in [1](#0-0)  computes:

```
baseline = LastRewardedHeight::get(state_machine_id).unwrap_or(previous_height)
blocks   = latest_height.saturating_sub(baseline)
reward   = blocks * block_cost   // block_cost = current StateMachinesCostPerBlock value
```

`block_cost` is read fresh from `StateMachinesCostPerBlock` at call time in `process_message` ( [2](#0-1) ), but `blocks` can span an arbitrarily long, arbitrarily old backlog: `LastRewardedHeight` only advances when a reward is actually claimed ( [3](#0-2) ), and there's no enforced maximum age or size on that backlog, nor any per-height snapshot of the rate that applied when each block was produced. `update_cost_per_block` is a normal, expected admin operation for repricing consensus updates over time ( [4](#0-3) ) — it is not a compromise or malicious act, just ordinary governance/parameter tuning that the system is designed to support routinely (chain congestion changes, treasury budget changes, etc.).

The structural flaw mirrors the reported bug exactly: instead of computing `Σ (blocks_in_period_i * cost_in_period_i)` across however many rate regimes the backlog spans, the pallet applies a single point-in-time rate to the entire accumulated span — exactly the "average TPS over the whole elapsed time" mistake described in the report, just substituting "cost per block" for "TPS" and "unpaid block backlog" for "elapsed epochs."

### Impact Explanation
Any unprivileged relayer can withhold submitting/claiming a mandatory consensus update for one of the tracked state machines (this only requires *not* acting — no compromise of any relayer/prover/admin role is needed), let a large block backlog accumulate at a currently low `CostPerBlock`, and then, once governance raises `CostPerBlock` for an unrelated legitimate reason (fee-market adjustment, inflation, congestion pricing, etc.), submit a single consensus message that fast-forwards `latest_height` across the entire backlog. `calculate_reward` then pays `(entire backlog span) * (new, higher rate)` out of the treasury in one shot via `T::Currency::transfer` ( [5](#0-4) ), producing a payout far larger than the amount the protocol intended to spend incentivizing that backlog (which should have been priced mostly at the old, lower rate). This is a direct, unbounded overpayment of protocol treasury funds to an unprivileged actor, triggered purely by the ordinary combination of (a) delaying a public-entrypoint action and (b) an expected governance rate change — no malicious peer, relayer collusion, or compromised key is required.

### Likelihood Explanation
The precondition (a `CostPerBlock` increase) is a normal governance action the pallet explicitly supports via `update_cost_per_block`, and the attacker action (simply not submitting a consensus proof for a while, then submitting once the rate rises) is fully within the capabilities of any relaying party, requiring no special access. The existing guard (`LastRewardedHeight` watermark) only prevents double-payment for the same span — it does nothing to bound the span's *age* or to split the reward across the rate(s) that actually applied during accrual, so the overpayment path is not mitigated by the current code.

### Recommendation
Track rate changes with effective heights (or timestamps) and compute the reward as a sum over each sub-range using the rate that was in force during that sub-range, analogous to iterating per-epoch rather than applying one rate to the aggregate span. Alternatively, cap the maximum block span rewarded in a single claim and/or snapshot the applicable `CostPerBlock` at the block it was earned (e.g., via a per-height rate ledger) rather than reading the live value at claim time.

### Proof of Concept
1. Governance sets `StateMachinesCostPerBlock[chain] = 1` (low rate).
2. Relayer relays consensus proofs but withholds submitting new ones for `chain`, so `LatestHeight` (or `LastRewardedHeight`) stalls while the remote chain still advances thousands of blocks off-chain (or the relayer simply avoids calling `handle_unsigned` for a long period once one becomes eligible).
3. Governance later raises `StateMachinesCostPerBlock[chain] = 1000` for unrelated reasons (documented, intended admin flow, see `update_cost_per_block` in [4](#0-3) ).
4. Relayer submits a single consensus message that advances `latest_height` by the entire backlog (e.g., 10,000 blocks).
5. `calculate_reward` computes `reward = 10,000 * 1000`, i.e., a payout priced entirely at the new rate even though nearly all of the backlog accrued under the old rate of `1`, resulting in a ~1000x overpayment from `TreasuryAccount` for the same underlying test flow shown in [6](#0-5)  (which only demonstrates the watermark preventing *double*-payment, not the rate-averaging problem).

	/// Calculate the reward for a message based on the state machine id
	fn calculate_reward(
		state_machine_id: &StateMachineId,
		block_cost: <T as pallet_ismp::Config>::Balance,
	) -> Result<<T as pallet_ismp::Config>::Balance, Error<T>> {
		let host = <T::IsmpHost>::default();
		let latest_height = host
			.latest_commitment_height(state_machine_id.clone())
			.map_err(|_| Error::<T>::CouldNotGetStateMachineHeight)?;
		let previous_height =
			host.previous_commitment_height(state_machine_id.clone()).unwrap_or_default();

		// Use the rewarded watermark as the baseline and fall back to the previous height until
		// the first reward is recorded for this chain. The watermark only moves forward, so a
		// height that is rolled back and later resubmitted is not paid for a second time.
		let baseline = LastRewardedHeight::<T>::get(state_machine_id).unwrap_or(previous_height);

		let blocks = latest_height.saturating_sub(baseline);

		let blocks_as_balance: <T as pallet_ismp::Config>::Balance = blocks.saturated_into();
		let reward = blocks_as_balance.saturating_mul(block_cost);

		Ok(reward)
	}

		#[pallet::call_index(0)]

			state_machine_id: StateMachineId,

		) -> DispatchResult {

			StateMachinesCostPerBlock::<T>::mutate(state_machine_id.clone(), |maybe_cost| {

			});

			Self::deposit_event(Event::<T>::StateMachineCostPerBlockUpdated {
				state_machine_id,
				cost_per_block,
			});

			Ok(())
		}

#[test]
fn reward_covers_only_unpaid_heights_after_rollback() {
	let mut ext = new_test_ext();
	ext.execute_with(|| {
		const BLOCK_COST: u128 = 100;
		let host = Ismp::default();
		let state_machine_id = setup_state_machine();
		let treasury_account: AccountId32 = PalletId(*b"treasury").into_account_truncating();

		pallet_consensus_incentives::Pallet::<Test>::update_cost_per_block(
			RuntimeOrigin::root(),
			state_machine_id,
			BLOCK_COST,
		)
		.unwrap();

		let (consensus_message, relayer_account) = setup_host_and_message(&host);
		let message = MessageWithWeight { message: consensus_message, weight: Weight::zero() };
		let updated = |height: u64| {
			vec![IsmpEvent::StateMachineUpdated(StateMachineUpdated {
				state_machine_id,
				latest_height: height,
			})]
		};

		// The chain has already advanced to 1025 and every block up to it has been rewarded once.
		host.store_state_machine_commitment(
			StateMachineHeight { id: state_machine_id, height: 1024 },
			commitment(),
		)
		.unwrap();
		host.store_latest_commitment_height(StateMachineHeight {
			id: state_machine_id,
			height: 1024,
		})
		.unwrap();
		host.store_state_machine_commitment(
			StateMachineHeight { id: state_machine_id, height: 1025 },
			commitment(),
		)
		.unwrap();
		host.store_latest_commitment_height(StateMachineHeight {
			id: state_machine_id,
			height: 1025,
		})
		.unwrap();

		let treasury_before_first = Balances::balance(&treasury_account);
		<pallet_consensus_incentives::Pallet<Test> as FeeHandler>::on_executed(
			vec![message.clone()],
			updated(1025),
		)
		.unwrap();

		assert_eq!(Balances::balance(&treasury_account), treasury_before_first - BLOCK_COST);
		assert_eq!(
			pallet_consensus_incentives::LastRewardedHeight::<Test>::get(state_machine_id),
			Some(1025)
		);

		// The previous-height pointer references an older height whose commitment is no longer
		// retained in the bounded map.
		pallet_ismp::PreviousStateMachineHeight::<Test>::insert(state_machine_id, 1);

		// Deleting the latest commitment rolls the latest height back to that previous pointer.
		host.delete_state_commitment(StateMachineHeight { id: state_machine_id, height: 1025 })
			.unwrap();
		assert_eq!(host.latest_commitment_height(state_machine_id).unwrap(), 1);

		// The next honest consensus update advances to 1030, carrying the stale pointer forward as
		// the new previous height.
		host.store_state_machine_commitment(
			StateMachineHeight { id: state_machine_id, height: 1030 },
			commitment(),
		)
		.unwrap();
		host.store_latest_commitment_height(StateMachineHeight {
			id: state_machine_id,
			height: 1030,
		})
		.unwrap();
		assert_eq!(host.previous_commitment_height(state_machine_id), Some(1));

		let treasury_before_second = Balances::balance(&treasury_account);
		<pallet_consensus_incentives::Pallet<Test> as FeeHandler>::on_executed(
			vec![message],
			updated(1030),
		)
		.unwrap();

		// The real advance is 1025 -> 1030, so only the 5 new blocks are paid rather than the full
		// span back to the previous pointer.
		assert_eq!(Balances::balance(&treasury_account), treasury_before_second - 5 * BLOCK_COST);
		assert_eq!(
			pallet_consensus_incentives::LastRewardedHeight::<Test>::get(state_machine_id),
			Some(1030)
		);
	})
}
