### Title
Arbitrary `clone_url`/deep-link URL passed unvalidated to `git clone`/`git remote add` enables Git remote-helper command execution - (File: `app/src/lib/git/clone.ts`, `app/src/lib/git/remote.ts`)

### Summary
Both the deep-link "Open Repository from URL" flow and the pull-request/upstream remote-wiring flow take a URL string that is either fully attacker-controlled (a `x-github-client://openRepo/<url>` link the victim clicks) or attacker-influenceable (`head.repo.clone_url` / `clone_url` returned from the GitHub API for a forked PR) and pass it straight into `git clone …` or `git remote add …` with no scheme allow-list. Git itself supports "remote helper" URL schemes such as `ext::<command>` (and others) that execute an arbitrary shell command as part of establishing the "remote," so an attacker who controls the URL string controls process execution once Desktop invokes Git with it.

### Finding Description
`parseAppURL` in [1](#0-0)  extracts the `url` segment from an `openRepo` deep link and only validates the optional `pr`, `branch`, and `filepath` query parameters — the `url` itself (`parsedPath`) is returned completely unvalidated (no scheme allow-list, no `parseRemote`/`urlsMatch` check at this layer).

That URL flows to `Dispatcher.openRepositoryFromUrl` → `openOrCloneRepository`, which shows the Clone dialog pre-filled with `initialURL: url` [2](#0-1) . When the user confirms cloning, the URL is handed to `clone()` in [3](#0-2) , which builds `args.push('--', url, path)` and executes `git(args, __dirname, 'clone', opts)`. The only validation performed anywhere in this path is on the destination **path** (`isClonePathSensitive`) — the **URL** itself is never checked against a protocol allow-list.

Similarly, for pull requests from forks, `openPullRequestFromUrl` fetches `pullRequest.head.repo.clone_url` from the GitHub API and calls `_checkoutPullRequest` [4](#0-3) , which eventually calls `addRemote(repository, forkRemoteName, headCloneUrl)` in `_findPullRequestBranch` [5](#0-4) . `addRemote` itself performs no validation of the URL scheme: `await git(['remote', 'add', name, url], repository.path, 'addRemote')` [6](#0-5) .

Git natively supports "remote helper" transports invoked by URL scheme, most notably `ext::<shell-command>`, which Git executes as a subprocess to service the "remote" — this is a well-known real-world Git RCE primitive when an attacker controls a clone/fetch URL and no `protocol.*.allow`/`GIT_ALLOW_PROTOCOL` restriction is in effect. I searched the codebase for any such restriction (`GIT_ALLOW_PROTOCOL`, `protocol.ext`, `protocol.allow`) and found **no matches anywhere in the repository** — Desktop never sets `GIT_ALLOW_PROTOCOL` or `-c protocol.ext.allow=never` when spawning `git`, `withTrampolineEnv`/`git()` in `core.ts` only adds `TERM`, credential-helper, and SSH-related variables [7](#0-6) .

By contrast, the codebase shows the authors are clearly aware of, and defend against, other URL/path-derived attacks in this exact area — `sanitizeCloneName` guards path traversal from URL-derived directory names [8](#0-7) , `isClonePathSensitive` guards sensitive destination directories [9](#0-8) , `--no-ext-diff` is applied to block `diff.external` config injection [10](#0-9) , and `safe.directory`/dubious-ownership handling gates hook execution from untrusted clones [11](#0-10) . None of these mitigations address the URL **scheme** itself, leaving the `ext::` remote-helper class of attack open.

### Impact Explanation
If exploitable, this allows arbitrary command execution on the victim's machine merely by getting them to click an `x-github-client://openRepo/…` link and confirm a clone (or, for the PR path, by getting a maintainer to view/checkout a PR from a fork whose head repository's `clone_url` an attacker fully controls). This is a full renderer/host code-execution primitive originating from a link a user clicks or a GitHub API object populated by an untrusted actor (a fork's `clone_url`), matching the "attacker controls…a GitHub API object, a link or deep link the user clicks…result is code execution" impact class in the report seed.

### Likelihood Explanation
Likelihood depends on whether `clone_url` returned by the GitHub REST API for a fork can ever be a non-`https`/`ssh`/`git` scheme string (GitHub.com normally always returns `https://github.com/...` for `clone_url`, which would make the PR-checkout path low-risk for github.com but potentially more relevant for GitHub Enterprise or custom API endpoints). The deep-link path (`openRepo/<url>`), however, is much more directly attacker-controlled since the entire URL segment comes from an arbitrary link with zero scheme validation in `parseAppURL`. I could not fully verify at what point (if any) `git`/`dugite` on the versions Desktop bundles might already refuse `ext::` by default, or whether the Clone dialog performs additional scheme filtering in a component I did not fully inspect (`clone-repository.tsx`) beyond `resolveCloneInfo`, which only special-cases `.wiki.git` and otherwise passes the raw `url` through [12](#0-11) .

### Recommendation
- Set `GIT_ALLOW_PROTOCOL` (or pass `-c protocol.ext.allow=never -c protocol.fd.allow=never` etc.) whenever Desktop spawns `git` for any operation that takes a user/API-supplied URL (`clone`, `remote add`, `remote set-url`, `fetch`), restricting to `http`, `https`, `ssh`, and `git` only.
- Validate the URL scheme with `parseRemote`/an explicit allow-list at the earliest point it is accepted from an untrusted source: in `parseAppURL` for deep links, in `addRemote`/`ensureUpstreamRemoteURL` for PR/upstream remotes, and in `clone()` before invoking `git`.
- Reject any URL that doesn't match one of the recognized `remoteRegexes` patterns already defined in `remote-parsing.ts` before it reaches a `git` invocation.

### Proof of Concept
Conceptual PoC (not executed):
1. Attacker crafts a link: `x-github-client://openRepo/ext::sh%20-c%20"open%20-a%20Calculator"` (or an equivalent OS command for the victim's platform).
2. Victim clicks the link; Desktop's protocol handler (`handleAppURL`, registered for `x-github-client` in `main.ts`) routes it to `parseAppURL`, which returns `{ name: 'open-repository-from-url', url: 'ext::sh -c "open -a Calculator"' }` with no scheme check.
3. `Dispatcher.openRepositoryFromUrl` → `openOrCloneRepository` opens the Clone dialog pre-populated with this URL.
4. Victim clicks "Clone"; `clone()` runs `git ... clone -- 'ext::sh -c "open -a Calculator"' <path>`, and Git's `ext` remote helper executes the embedded shell command. [13](#0-12) [14](#0-13)

function isClonePathSensitive(unresolvedClonePath: string): boolean {
  const clonePath = Path.resolve(unresolvedClonePath).toLowerCase()
  const home = Path.resolve(homedir()).toLowerCase()

  if (clonePath === home) {
    return true
  }

  const sensitiveLocations = [
    Path.join(home, '.ssh'),
    Path.join(home, '.gnupg'),
    Path.join(home, '.config'),
    Path.join(home, '.config', 'git'),
    Path.join(home, '.gitconfig'),
  ]

  if (__WIN32__) {
    const appData = process.env.APPDATA
    if (appData) {
      sensitiveLocations.push(appData.toLowerCase())
      sensitiveLocations.push(Path.join(appData, 'gnupg').toLowerCase())
    }
  }

  for (const sensitive of sensitiveLocations) {
    if (clonePath === sensitive || clonePath.startsWith(sensitive + Path.sep)) {
      return true
    }
  }

  return false
}

export async function clone(
  url: string,
  path: string,
  options: CloneOptions,
  progressCallback?: (progress: ICloneProgress) => void
): Promise<void> {
  if (isClonePathSensitive(path)) {
    throw new Error(
      `The clone destination "${path}" targets a sensitive system location. ` +
        'Cloning into this directory is not allowed.'
    )
  }

  const env = {
    ...(await envForRemoteOperation(url)),
    GIT_CLONE_PROTECTION_ACTIVE: 'false',
  }

  const defaultBranch = options.defaultBranch ?? (await getDefaultBranch())

  const args = [
    '-c',
    `init.defaultBranch=${defaultBranch}`,
    'clone',
    '--recursive',
  ]

  let opts: IGitStringExecutionOptions = { env }

  if (progressCallback) {
    args.push('--progress')

    const title = `Cloning into ${path}`
    const kind = 'clone'

    opts = await executionOptionsWithProgress(
      { ...opts, trackLFSProgress: true },
      new CloneProgressParser(),
      progress => {
        const description =
          progress.kind === 'progress' ? progress.details.text : progress.text
        const value = progress.percent

        progressCallback({ kind, title, description, value })
      }
    )

    // Initial progress
    progressCallback({ kind, title, value: 0 })
  }

  if (options.branch) {
    args.push('-b', options.branch)
  }

  args.push('--', url, path)

  await git(args, __dirname, 'clone', opts)
}
