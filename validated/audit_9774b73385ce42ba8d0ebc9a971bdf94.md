### Title
Type-tag-blind deserialization of `MsgEVMTransaction.Data` allows an EVM tx to be reinterpreted as an unintended `TxData` variant - ([File: x/evm/types/codec.go])

### Summary
`UnpackTxData` ignores the `google.protobuf.Any.TypeUrl` field entirely and instead determines the concrete `ethtx.TxData` type by sequentially attempting `proto.Unmarshal` against a fixed, hardcoded list of candidate message types (`LegacyTx`, `AccessListTx`, `DynamicFeeTx`, `BlobTx`, `AssociateTx`, `SetCodeTx`), accepting whichever candidate unmarshals without error first. This is the same bug class as the `bson` advisory: the authoritative type indicator is ignored, and an object is deserialized as whatever type the decoder happens to successfully parse it as, rather than the type it was declared/intended to be.

### Finding Description
`codectypes.Any` carries a `TypeUrl` that is supposed to be the single source of truth for what concrete type `Any.Value` should be decoded into; this is exactly how the SDK's proper `interfaceRegistry.UnpackAny` / `legacyInterfaceRegistry.UnpackAny` work — they look up the type strictly by `TypeUrl` before calling `proto.Unmarshal` [1](#0-0) [2](#0-1) .

However `x/evm/types/codec.go`'s `UnpackTxData` (used for `MsgEVMTransaction.Data`) bypasses this entirely when the `Any`'s cached value is not already populated (which is the normal case for a freshly-received wire message before `UnpackInterfaces` runs, or any code path that calls `UnpackTxData` directly on the raw `Any`). It never reads or validates `TypeUrl`; it simply tries `proto.Unmarshal` against six different message schemas in a fixed order and returns the first one that parses without error: [3](#0-2) 

The identical pattern exists in the giga variant: [4](#0-3) 

This function is invoked from many security-relevant call sites, including `MsgEVMTransaction.ValidateBasic`, `AsTransaction`, and `GetAssociateTx` [5](#0-4) , and from the ante-handler preprocessing pipeline that derives the sender address, signature checks, and tx-type gating (`IsTxTypeAllowed`) [6](#0-5) .

Because protobuf wire encoding is schema-agnostic at the byte level (field number + wire type only), a byte string crafted to represent one `ethtx` message type (e.g. `AssociateTx`, which has fundamentally different semantics — no gas/value validation, custom-message signature scheme) can, depending on field-number/wire-type overlap, also successfully `proto.Unmarshal` into an earlier candidate in the hardcoded list (e.g. `LegacyTx`) with different field semantics, silently producing a different `TxData` object than the sender's declared `TypeUrl` intended, all without any error being raised. The declared `TypeUrl` sent on the wire is not checked against the chosen type at all, so there is no cross-check that would catch such a mismatch.

### Impact Explanation
`TxData` selection directly feeds: signature/hash computation and sender-address derivation (`PreprocessUnpacked`), fee and gas computations (`x/evm/ante/fee.go`, `x/evm/ante/gas.go`), and whether the special `AssociateTx` code path (which has different validation and signature-recovery logic, e.g. skips `Validate()` and uses `CustomMessage` hashing instead of standard tx hash) is taken [7](#0-6) [8](#0-7) . A type-confused decode that flips between these code paths could let an attacker bypass tx-type-specific validation (`Validate()` for non-associate txs, `IsTxTypeAllowed` checks) or cause fee/signature computation to diverge from what the signer intended, which maps to fee/refund abuse, signature/sender confusion, or bypassing the EIP-2718 tx-type allow-list — all reachable from a single submitted EVM transaction.

### Likelihood Explanation
This requires an attacker to construct a byte sequence that: (a) is valid enough for the intended `TxData` type to pass whatever front-end acceptance exists, and (b) also decodes cleanly as an earlier candidate type in the hardcoded fallback list with different field semantics, without triggering `proto.Unmarshal` errors (proto3's permissive unknown-field/optional-field handling makes such overlaps plausible, especially between `LegacyTx`/`AccessListTx`/`DynamicFeeTx`/`AssociateTx`, which are likely to share several scalar/bytes field numbers). Constructing a concrete colliding payload requires enumerating the exact field-number layouts of these six generated messages (`x/evm/types/ethtx/tx.pb.go`), which was not fully verified within the scope of this investigation — I was not able to exhaustively check field-number overlaps across all six `ethtx` message definitions to build a working PoC before this session ended. The root-cause pattern (ignoring `TypeUrl`, guessing by trial-unmarshal) is confirmed and is the same bug class as the reported `bson` advisory, but the exploitability into a specific fund-impacting deserialization mismatch needs the field-layout analysis to be completed.

### Recommendation
Make `UnpackTxData` authoritative on `Any.TypeUrl` (matching how `interfaceRegistry.UnpackAny` and `legacyInterfaceRegistry.UnpackAny` already work), decoding only into the single message type indicated by `TypeUrl`, and reject the `Any` if `TypeUrl` does not match any registered `ethtx.TxData` implementation, rather than iterating over candidate types and accepting the first one that parses.

### Proof of Concept
Not constructed — a concrete colliding-bytes PoC requires enumerating the protobuf field-number layout of `LegacyTx`, `AccessListTx`, `DynamicFeeTx`, `BlobTx`, `AssociateTx`, and `SetCodeTx` in `x/evm/types/ethtx/tx.pb.go` to find/construct a byte sequence that parses successfully under two different schemas with materially different semantics; this analysis was not completed within the available investigation scope.

func UnpackTxData(any *codectypes.Any) (ethtx.TxData, error) {
	if any == nil {
		return nil, errors.New("protobuf Any message cannot be nil")
	}

	txData, ok := any.GetCachedValue().(ethtx.TxData)
	if !ok {
		ltx := ethtx.LegacyTx{}
		if proto.Unmarshal(any.Value, &ltx) == nil {
			// value is a legacy tx
			return &ltx, nil
		}
		atx := ethtx.AccessListTx{}
		if proto.Unmarshal(any.Value, &atx) == nil {
			// value is a accesslist tx
			return &atx, nil
		}
		dtx := ethtx.DynamicFeeTx{}
		if proto.Unmarshal(any.Value, &dtx) == nil {
			// value is a dynamic fee tx
			return &dtx, nil
		}
		btx := ethtx.BlobTx{}
		if proto.Unmarshal(any.Value, &btx) == nil {
			// value is a blob tx
			return &btx, nil
		}
		astx := ethtx.AssociateTx{}
		if proto.Unmarshal(any.Value, &astx) == nil {
			// value is an associate tx
			return &astx, nil
		}
		stx := ethtx.SetCodeTx{}
		if proto.Unmarshal(any.Value, &stx) == nil {
			// value is a set code tx
			return &stx, nil
		}
		return nil, fmt.Errorf("cannot unpack Any into TxData %T", any)
	}

	return txData, nil
}

func (msg *MsgEVMTransaction) ValidateBasic() error {
	if msg.Derived != nil && msg.Derived.PubKey == nil {
		return sdkerrors.ErrInvalidPubKey
	}
	txData, err := UnpackTxData(msg.Data)
	if err != nil {
		return err
	}
	if _, ok := txData.(*ethtx.AssociateTx); !ok {
		if err := txData.Validate(); err != nil {
			return err
		}
	}
	amsg, isAssociate := msg.GetAssociateTx()
	if isAssociate {
		if len(amsg.CustomMessage) > MaxAssociateCustomMessageLength {
			return sdkerrors.Wrapf(sdkerrors.ErrTxTooLarge, "custom message can have at most 64 characters")
		}
		return amsg.Validate()
	}
	return nil
}

func (msg *MsgEVMTransaction) AsTransaction() (*ethtypes.Transaction, ethtx.TxData) {
	txData, err := UnpackTxData(msg.Data)
	if err != nil {
		return nil, nil
	}

	return ethtypes.NewTx(txData.AsEthereumData()), txData
}

// UnpackInterfaces implements UnpackInterfacesMesssage.UnpackInterfaces
func (msg *MsgEVMTransaction) UnpackInterfaces(unpacker codectypes.AnyUnpacker) error {
	return unpacker.UnpackAny(msg.Data, new(ethtx.TxData))
}

func (msg *MsgEVMTransaction) IsAssociateTx() bool {
	_, ok := msg.GetAssociateTx()
	return ok
}

func (msg *MsgEVMTransaction) GetAssociateTx() (*ethtx.AssociateTx, bool) {
	txData, err := UnpackTxData(msg.Data)
	if err != nil {
		// should never happen
		panic(err)
	}
	amsg, ok := txData.(*ethtx.AssociateTx)
	return amsg, ok
}

func PreprocessUnpacked(ctx sdk.Context, msgEVMTransaction *evmtypes.MsgEVMTransaction, chainID *big.Int, isBlockTest bool, txData ethtx.TxData) error {
	if msgEVMTransaction.Derived != nil {
		if msgEVMTransaction.Derived.PubKey == nil {
			// this means the message has `Derived` set from the outside, in which case we should reject
			return sdkerrors.ErrInvalidPubKey
		}
		// already preprocessed
		return nil
	}

	if txData == nil {
		// TxData not passed in, unpack it.
		var err error
		txData, err = evmtypes.UnpackTxData(msgEVMTransaction.Data)
		if err != nil {
			return err
		}
	}

	if atx, ok := txData.(*ethtx.AssociateTx); ok {
		V, R, S := atx.GetRawSignatureValues()
		V = new(big.Int).Add(V, utils.Big27)
		// Hash custom message passed in
		customMessageHash := crypto.Keccak256Hash([]byte(atx.CustomMessage))
		evmAddr, seiAddr, pubkey, err := helpers.GetAddresses(V, R, S, customMessageHash)
		if err != nil {
			return err
		}
		msgEVMTransaction.Derived = &derived.Derived{
			SenderEVMAddr: evmAddr,
			SenderSeiAddr: seiAddr,
			PubKey:        &secp256k1.PubKey{Key: pubkey.Bytes()},
			Version:       derived.Cancun,
			IsAssociate:   true,
		}
		return nil
	}

	ethTx := ethtypes.NewTx(txData.AsEthereumData())
	if ethTx.Type() != ethtypes.LegacyTxType {
		chainID = ethTx.ChainId()
	}
	chainCfg := evmtypes.DefaultChainConfig()
	ethCfg := chainCfg.EthereumConfig(chainID)
	version := GetVersion(ctx, ethCfg)
	signer := SignerMap[version](chainID)
	if !IsTxTypeAllowed(version, ethTx.Type()) {
		return ethtypes.ErrInvalidChainId
	}
