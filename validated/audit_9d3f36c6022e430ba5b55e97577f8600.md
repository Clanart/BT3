## Analog Found

### Title
Gasless swap admission and execution rely on manipulable instantaneous DEX reserves instead of a TWAP, allowing price-manipulation to bypass gasless swap collateral checks and extract value from swap-router-connected pools - ([File: kaiax/gasless/impl/tx_pool.go], [File: contracts/bindings/kip247/GaslessSwapRouter.go])

### Summary
The reported bug class is "use of an instantaneous, easily-manipulable on-chain price (`slot0`) instead of a TWAP for a security-relevant decision." The Kaia `kaiax/gasless` module (KIP-247) and its `GaslessSwapRouter` contract exhibit the same pattern: they price a `GaslessSwapTx` using the swap DEX pair's **current/live reserves** (an AMM spot price with no time-weighting or manipulation resistance), and this price is used both to admit the transaction into the pool (fronting proposer-paid gas) and to execute the actual token swap that repays that gas.

### Finding Description
`GaslessModule.checkBalanceForSwap` is the tx-pool admission rule for `GaslessSwapTx`. It calls `GaslessSwapRouter.GetAmountIn(token, minAmountOut)` against the *current* chain state to decide whether `tx.amountIn` is sufficient: [1](#0-0) 

`GetAmountIn` is a view function exposed by `GaslessSwapRouter` that — per its binding signature `getAmountIn(address token, uint256 amountOut) view returns(uint256 amountIn)` — resolves the DEX pair for `token` and computes the amount using the pair's live reserves, i.e., the standard `getAmountIn(amountOut, reserveIn, reserveOut)` AMM formula seen in the bundled `UniswapV2Router02`/`UniswapV2Pair` bindings: [2](#0-1) [3](#0-2) 

This is architecturally identical to reading Uniswap V3 `slot0`: both expose the *most recent* price point of an AMM with no cumulative/TWAP smoothing, and both are trivially shiftable within a single block via a large swap against the same pool.

Because `swapForGas` itself is executed atomically together with the `LendTxGenerator` transaction inside a builder `Bundle` (`ExtractTxBundles`, `commitBundleTransaction`) in the same block, using the *same* (attacker-influenced) state as the admission check: [4](#0-3) [5](#0-4) 

An attacker who also submits ordinary swap transactions against the same underlying DEX pool immediately before their `GaslessApproveTx`/`GaslessSwapTx` in the same block can shift the pair's reserves to their favor, then submit a `GaslessSwapTx` whose `amountIn`/`minAmountOut` pair only satisfies `checkBalanceForSwap`'s `amountIn >= getAmountIn(minAmountOut)` requirement under the manipulated reserves — not under the pool's fair, unmanipulated price. The gasless test suite explicitly demonstrates that this exact check is the sole gate for admitting `GaslessSwapTx` and fronting proposer gas via `LendTxGenerator`: [6](#0-5) 

### Impact Explanation
Because `minAmountOut`/`amountIn` are validated against a manipulable spot price rather than a TWAP or an oracle resistant to single-block manipulation, an attacker can:
- construct a `GaslessSwapTx` that passes admission (`checkBalanceForSwap`) using a temporarily distorted exchange rate, then
- have the proposer front gas via the `LendTxGenerator` bundle, and
- execute `swapForGas` at the same manipulated reserves to extract more output token value from the DEX pool's liquidity than the token's fair market price would allow, while only repaying the block proposer a fixed, gas-cost-based `amountRepay`.

The surplus value is extracted from the swap pool's liquidity providers using Kaia's gasless subsystem (a protocol-level module) as the vehicle, and the proposer-provided gas-lending mechanism is what makes the attack self-funding (attacker doesn't need to hold KAIA for gas). This matches "acceptance of an invalid/underpriced transaction" and "value movement via fee-delegation/gasless abuse" in the accepted-impact list.

### Likelihood Explanation
This requires only unprivileged transaction submission: an attacker submits ordinary swap transactions plus a `GaslessApproveTx`/`GaslessSwapTx` targeting the same block, relying on standard gas-price/ordering incentives (or auction-module bidding) to get favorable ordering. No validator, peer, or governance privilege is required — it is reachable purely through the public transaction pool and gasless swap RPC path, matching the "unprivileged transaction sender / gasless user" persona explicitly in scope.

### Recommendation
- Do not compute `getAmountIn`/`getAmountsOut` for gasless-swap admission or execution purely from the DEX pair's instantaneous `getReserves()`. Use a manipulation-resistant reference (e.g., a TWAP oracle, or bound the allowed price deviation between the admission-time check and execution-time check, or require the swap price to be within a tolerance of an external oracle).
- Alternatively, restrict supported gasless-swap tokens/pools to those with sufficient liquidity/oracle backing, and add a max slippage/deviation bound comparing the pool price at tx-pool admission time vs. a longer-window average.

### Proof of Concept
1. Attacker identifies a `token`↔`WKAIA` pool registered in `GaslessSwapRouter` (`GetDEXInfo`/`DexAddress`) with modest liquidity.
2. In the same block, attacker submits: (a) a large ordinary swap against the pool to skew `getReserves()` favorably, (b) a `GaslessApproveTx`, (c) a `GaslessSwapTx` with `minAmountOut`/`amountIn` chosen to just satisfy `checkBalanceForSwap`'s `amountIn >= GetAmountIn(token, minAmountOut)` check under the skewed reserves — see the exact check at [1](#0-0) .
3. The proposer's block builder bundles `[LendTxGenerator, GaslessApproveTx, GaslessSwapTx]` per `ExtractTxBundles` and executes them atomically at the still-skewed reserves (`commitBundleTransaction`), so `swapForGas` outputs more value than the pool's fair price would allow.
4. Attacker repays only the fixed `amountRepay` (gas-cost-based) to the proposer and keeps the surplus extracted from the pool's liquidity.

func (g *GaslessModule) ExtractTxBundles(txs []*types.Transaction, prevBundles []*builder.Bundle) []*builder.Bundle {
	// there are only at most two gasless transactions in pending for a sender
	bundles := []*builder.Bundle{}
	approveTxs := map[common.Address]*types.Transaction{}
	targetTxHash := common.Hash{}
	for _, tx := range txs {
		addr, err := types.Sender(g.signer, tx)
		if err != nil {
			continue
		}
		if g.IsApproveTx(tx) {
			approveTxs[addr] = tx
		} else if g.IsSwapTx(tx) && g.IsExecutable(approveTxs[addr], tx) {
			bundleTxs := builder.NewTxOrGenList(g.GetLendTxGenerator(approveTxs[addr], tx))
			if approveTxs[addr] != nil {
				bundleTxs = append(bundleTxs, builder.NewTxOrGenFromTx(approveTxs[addr]))
			}
			bundleTxs = append(bundleTxs, builder.NewTxOrGenFromTx(tx))

			b := builder.NewBundle(
				bundleTxs,
				targetTxHash,
				false,
			)

			targetTxHash = tx.Hash()

			isConflict := false
			for _, prev := range append(prevBundles, bundles...) {
				if prev.IsConflict(b) {
					isConflict = true
					break
				}
			}
			if isConflict {
				// Gasless transactions will just fail even if they aren't bundled.
				continue
			}
			bundles = append(bundles, b)
		} else {
			targetTxHash = tx.Hash()
		}
	}
