### Title
Spoofable `WWW-Authenticate` header lets a malicious git remote/proxy bind an attacker-controlled host as a trusted "GitHub Enterprise" sign-in endpoint - (File: `app/src/lib/trampoline/trampoline-credential-helper.ts`)

### Summary
GitHub Desktop's git credential helper classifies an unknown HTTP(S) remote as a genuine GitHub Enterprise host purely on the basis of an HTTP response header (`WWW-Authenticate`) supplied by the remote/proxy itself, with no independent verification. That classification is then used to initiate the Enterprise OAuth sign-in flow against the attacker-chosen origin, exactly the kind of "attacker controls a git remote/proxy response → unauthorized OAuth/account binding" primitive called out as valid impact.

### Finding Description
When git needs credentials for a remote, Desktop's trampoline credential helper decides what "kind" of endpoint it is talking to in `getEndpointKind`: [1](#0-0) 

If none of the fast-path checks (`isGist`, `isDotCom`, `isGHE`) match, it inspects the `wwwauth[...]` header values that git forwarded from the *remote server's own HTTP response* and, if any value contains `realm="GitHub"`, unconditionally treats the host as `'enterprise'` — before ever calling `isGitHubHost` to make an independent determination: [2](#0-1) 

This header is attacker-controlled data: any git remote or any MITM/corporate proxy sitting on the git HTTP(S) path can emit `WWW-Authenticate: realm="GitHub"` for an arbitrary host, e.g. `https://evil.example.com`.

That classification feeds directly into `getCredential`, which — if no existing account matches the endpoint — invokes `ui.promptForGitHubSignIn(endpoint)` using the untrusted endpoint verbatim: [3](#0-2) 

`promptForGitHubSignIn` then binds the Enterprise sign-in flow to that attacker-controlled origin: [4](#0-3) 

Specifically, for any hostname other than exactly `github.com`, it calls `dispatcher.beginEnterpriseSignIn(cb)` and `dispatcher.setSignInEndpoint(origin)` with `origin` derived straight from the spoofed remote URL — no allow-list, no certificate/identity check beyond what the attacker's own server chose to claim in a header.

The broken invariant mirrors the MIMO report's core problem: a piece of state that is supposed to represent a trusted identity/ownership relationship (here, "this host is a legitimate GitHub Enterprise endpoint eligible for OAuth sign-in") is derived from data the counterparty fully controls, rather than from something Desktop independently verifies. Just as MIMO's registry could be told "this address owns this proxy" by an untrusted call path, Desktop's credential helper can be told "this host is GitHub Enterprise" by an untrusted HTTP header.

### Impact Explanation
An attacker who controls a git remote (or intercepts/relays git HTTP traffic via a proxy) can:
- Trigger Desktop's Enterprise sign-in UI/flow (`beginEnterpriseSignIn`, `setSignInEndpoint`) bound to an arbitrary attacker-chosen origin, misrepresenting it to the user as a legitimate GitHub Enterprise instance.
- Because the endpoint used for all subsequent enterprise API/OAuth URL construction (`getHTMLURL(endpoint)`, `getOAuthAuthorizationURL`, `requestOAuthToken`) is taken from this same attacker-controlled value elsewhere in `api.ts`, any credentials or OAuth exchange the user completes as part of that flow are directed at the attacker's server rather than a real GitHub host — matching the "unauthorized OAuth or account binding" / "credential exfiltration" impact classes.
- I was not able to fully trace, within the available context, whether the Enterprise sign-in path used in this specific "credential-helper-initiated" flow uses the browser/device OAuth path (which embeds `ClientID`/`ClientSecret`, see `app/src/lib/api.ts`) or a manual endpoint-entry form requiring further user action; this downstream detail should be verified against `sign-in-store.ts` and `sign-in.tsx` before treating OAuth-secret exfiltration as fully confirmed. The confirmed, exploitable defect is the untrusted-header-driven trust decision itself, which is sufficient to misdirect the sign-in target.

### Likelihood Explanation
This requires only that the user attempt a git operation (fetch/clone/push) against a remote whose server (or an interposed proxy) is attacker-controlled and returns a crafted `WWW-Authenticate: realm="GitHub"` header — no local access, no admin rights, and no prior compromise of the host are needed, satisfying the valid-impact criteria (attacker controls the git remote/proxy response). The header check is a simple substring match with no host validation, so it is trivial to trigger.

### Recommendation
- Do not classify a host as a trusted GitHub/Enterprise endpoint based solely on a `WWW-Authenticate` header value returned by that same untrusted host. At minimum, require this heuristic to be reinforced by `isGitHubHost` verification via an independently-issued API request before returning `'enterprise'`, and/or gate any sign-in prompt behind explicit user confirmation showing the exact host being contacted.
- Ensure any OAuth authorize/token-exchange requests derived from a "credential-helper-initiated" sign-in cannot be pointed at hosts that were classified using unverified, remote-supplied signals.

### Proof of Concept
1. Attacker sets up an HTTPS git remote (or a MITM proxy in front of a legitimate-looking remote) at `https://evil.example.com/some/repo.git`.
2. Attacker configures the server to respond to git's credential probe with header `WWW-Authenticate: realm="GitHub"`.
3. Victim, using GitHub Desktop, adds/fetches this remote. Desktop's credential helper calls `getEndpointKind`, which matches the spoofed header and returns `'enterprise'` (`trampoline-credential-helper.ts:157-163`).
4. Since the victim has no account registered for `evil.example.com`, `getCredential` calls `ui.promptForGitHubSignIn('https://evil.example.com')` (`trampoline-credential-helper.ts:109-124`).
5. `promptForGitHubSignIn` sees hostname !== `github.com` and calls `dispatcher.beginEnterpriseSignIn(cb)` + `dispatcher.setSignInEndpoint('https://evil.example.com')` (`trampoline-ui-helper.ts:90-93`), presenting the victim a GitHub-branded Enterprise sign-in flow bound to the attacker's server.

/** Implementation of the 'get' git credential helper command */
async function getCredential(cred: Credential, store: Store, token: string) {
  const ghCred = await getGitHubCredential(cred, store)

  if (ghCred) {
    return ghCred
  }

  const endpointKind = await getEndpointKind(cred, store)
  const accounts = await store.getAll()

  const endpoint = `${getCredentialUrl(cred)}`
  const apiEndpoint = getAPIEndpoint(endpoint)

  // If it appears as if the endpoint is a GitHub host and we don't have an
  // account for that endpoint then we should prompt the user to sign in.
  if (
    endpointKind !== 'generic' &&
    !accounts.some(a => a.endpoint === apiEndpoint)
  ) {
    if (getIsBackgroundTaskEnvironment(token)) {
      debug('background task environment, skipping prompt')
      return undefined
    }

    const account = await ui.promptForGitHubSignIn(endpoint)

    if (!account) {
      setHasRejectedCredentialsForEndpoint(token, endpoint)
    }

    return credWithAccount(cred, account)
  }

const getEndpointKind = async (cred: Credential, store: Store) => {
  const credentialUrl = getCredentialUrl(cred)
  const endpoint = `${credentialUrl}`

  if (isGist(endpoint)) {
    return 'generic'
  }

  if (isDotCom(endpoint)) {
    return 'github.com'
  }

  if (isGHE(endpoint)) {
    return 'ghe.com'
  }

  // When Git attempts to authenticate with a host it captures any
  // WWW-Authenticate headers and forwards them to the credential helper. We
  // use them as a happy-path to determine if the host is a GitHub host without
  // having to resort to making a request ourselves.
  for (const [k, v] of cred.entries()) {
    if (k.startsWith('wwwauth[')) {
      if (v.includes('realm="GitHub"')) {
        return 'enterprise'
      } else if (/realm="(GitLab|Gitea|Atlassian Bitbucket)"/.test(v)) {
        return 'generic'
      }
    }
  }

  public promptForGitHubSignIn(endpoint: string): Promise<Account | undefined> {
    return new Promise<Account | undefined>(async resolve => {
      const cb = (result: SignInResult) => {
        resolve(result.kind === 'success' ? result.account : undefined)
        this.dispatcher.closePopup(PopupType.SignIn)
      }

      const { hostname, origin } = new URL(endpoint)
      if (hostname === 'github.com') {
        this.dispatcher.beginDotComSignIn(cb)
      } else {
        this.dispatcher.beginEnterpriseSignIn(cb)
        await this.dispatcher.setSignInEndpoint(origin)
      }

      this.dispatcher.showPopup({
        type: PopupType.SignIn,
        isCredentialHelperSignIn: true,
        credentialHelperUrl: endpoint,
      })
    }).catch(e => {
      log.error(`Could not prompt for GitHub sign in`, e)
      return undefined
    })
  }
