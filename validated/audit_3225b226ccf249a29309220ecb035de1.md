### Title
PedPoP DKG accepts identity/invalid encryption keys, letting any observer decrypt secret shares - (File: crypto/dkg/pedpop/src/encryption.rs)

### Summary
Analogous to txAWS accepting TLS connections without verifying the peer's certificate, PedPoP's `EncryptionKeyMessage::read`/`Decryption::register` accept the per-participant ECDH encryption key `enc_key` without validating it is a non-identity, contributor-controlled group element. If a participant registers the identity point (or any point whose discrete log is publicly known) as `enc_key`, the ECDH shared point for every `EncryptedMessage` addressed to them becomes the publicly known identity point, so the ChaCha20 keystream protecting the secret share is computable by any unprivileged eavesdropper.

### Finding Description
- `EncryptionKeyMessage::read` parses `enc_key` with `C::read_G` (the base `Ciphersuite` implementation), which only checks canonical encoding — it does not reject the identity point, unlike `Curve::read_G` in FROST which explicitly errors on identity (`crypto/frost/src/curve/mod.rs:125-130`). [1](#0-0) [2](#0-1) 
- `Decryption::register` inserts `msg.enc_key` with no proof of possession and no validity check. [3](#0-2) 
- `encrypt` computes the shared secret as `ecdh(key, to) = enc_key * msg_key_scalar` and derives the keystream solely from that point plus the public `context`. If `enc_key` is identity, `ecdh` returns identity — a public value — and `cipher(context, identity)` yields a keystream anyone can recompute. [4](#0-3) [5](#0-4) 
- `EncryptedMessage` carries `key = msg_key_scalar * G` and a PoP signature binding the message to `from`, but nothing binds `enc_key` to the recipient or proves anyone knows its discrete log. [6](#0-5) 
- The victim participant still "decrypts" fine (`ecdh = enc_key_priv * msg.key = 0 * k = identity`), so the protocol completes normally while every share sent to that participant is readable by any onlooker.

### Impact Explanation
Each `EncryptedMessage<C, SecretShare<C::F>>` carries `f_j(i)`, sender `j`'s polynomial evaluation for recipient `i`. An eavesdropper who recovers all such ciphertexts addressed to the identity-keyed participant `i` recovers the sum — i.e., participant `i`'s complete FROST secret share — a direct key-share recovery/information-disclosure primitive reachable purely from observing public DKG traffic (and a blame proof would even let third parties confirm correctness). No trust assumption beyond observing the round-2 messages is needed.

### Likelihood Explanation
Requires one DKG participant (or a MitM able to substitute the authenticated round-1 `EncryptionKeyMessage`) to register an identity/low-order `enc_key`. The protocol's own comments note the DKG does not provide an authenticated channel and relies on the caller for message authenticity; the missing key validation is the defect the library itself can and should enforce, matching the txAWS pattern of skipping a verification step the library is responsible for.

### Recommendation
Reject identity (and ideally require a Schnorr proof of possession) for `enc_key` in `EncryptionKeyMessage::read` or `Decryption::register`, mirroring the identity rejection already performed in `Curve::read_G` (`crypto/frost/src/curve/mod.rs:125-130`). Additionally, transcript-bind `enc_key` to the participant index and `context` via a PoK so keys cannot be replayed or substituted.

### Proof of Concept
```rust
// Participant i runs the DKG honestly, except it broadcasts:
let mut msg = encryption.registration(commitments);
msg.enc_key = C::G::identity(); // accepted: C::read_G only checks canonical encoding

// Every honest sender j computes:
//   ecdh = enc_key * msg_key_scalar = identity * k = identity
//   cipher(context, identity) -> ChaCha20 keystream (publicly derivable)

// An eavesdropper observing EncryptedMessage { key, pop, msg } for i:
let shared = C::G::identity(); // known a priori since enc_key was identity
let mut plaintext = ciphertext.msg.clone();
cipher::<C>(context, &Zeroizing::new(shared))
    .apply_keystream(plaintext.as_mut().as_mut());
// plaintext == SecretShare f_j(i); summing over all j yields participant i's
// full ThresholdKeys secret_share.
```

fn cipher<C: Ciphersuite>(context: [u8; 32], ecdh: &Zeroizing<C::G>) -> ChaCha20 {
  // Ideally, we'd box this transcript with ZAlloc, yet that's only possible on nightly
  // TODO: https://github.com/serai-dex/serai/issues/151
  let mut transcript = RecommendedTranscript::new(b"DKG Encryption v0.2");
  transcript.append_message(b"context", context);

  transcript.domain_separate(b"encryption_key");

  let mut ecdh = ecdh.to_bytes();
  transcript.append_message(b"shared_key", ecdh.as_ref());
  ecdh.as_mut().zeroize();

  let zeroize = |buf: &mut [u8]| buf.zeroize();

  let mut key = Cc20Key::default();
  let mut challenge = transcript.challenge(b"key");
  key.copy_from_slice(&challenge[.. 32]);
  zeroize(challenge.as_mut());

  // Since the key is single-use, it doesn't matter what we use for the IV
  // The issue is key + IV reuse. If we never reuse the key, we can't have the opportunity to
  // reuse a nonce
  // Use a static IV in acknowledgement of this
  let mut iv = Cc20Iv::default();
  // The \0 is to satisfy the length requirement (12), not to be null terminated
  iv.copy_from_slice(b"DKG IV v0.2\0");

  // ChaCha20 has the same commentary as the transcript regarding ZAlloc
  // TODO: https://github.com/serai-dex/serai/issues/151
  let res = ChaCha20::new(&key, &iv);
  zeroize(key.as_mut());
  res
