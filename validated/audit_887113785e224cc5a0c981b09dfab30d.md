### Title
Repository-controlled git config can make Desktop's generic credential-helper trampoline store/erase credentials for an arbitrary, attacker-chosen host - ([File: app/src/lib/trampoline/trampoline-credential-helper.ts])

### Summary
GitHub Desktop configures a single, process-wide `credential.helper=desktop` for every git invocation and routes every credential `get`/`store`/`erase` request Git makes during that invocation to `createCredentialHelperTrampolineHandler`. For any host that isn't recognized as a GitHub endpoint, the handler treats the request as "generic" and persists whatever `(host, username, password)` triple Git reports directly into the OS-level generic credential store, with no check that the host is one the user actually intended to authenticate against for the repository being operated on. Because the URL Git reports for a credential request is derived from remote/submodule/`insteadOf` configuration that lives inside the repository the user cloned, a malicious repository can force Desktop to write (or erase) OS-stored credentials for a host of the attacker's choosing.

### Finding Description
`withTrampolineEnv` unconditionally sets, for every git subprocess Desktop spawns: [1](#0-0) 
`GIT_CONFIG_PARAMETERS: ... 'credential.helper=desktop'`, meaning Desktop's credential helper is the sole authority handling every credential request Git makes for the duration of that command - regardless of which host that request is actually for.

The handler for that helper dispatches `get`/`store`/`erase` purely based on the URL embedded in the credential protocol data Git supplies: [2](#0-1) 

`getEndpointKind` classifies a host as `generic` whenever it isn't github.com/GHE/Gist and doesn't match an already-known account or GitHub `WWW-Authenticate` realm: [3](#0-2) 

For `generic` hosts, `storeCredential`/`eraseCredential` call directly into the persistent generic credential store keyed only by the host + username taken from the credential record, with no validation that this host corresponds to the repository's actual configured remote or to anything the user previously trusted: [4](#0-3) 

Git derives the URL/host it reports to the credential helper from whatever remote is being contacted during that invocation - this can come from `.gitmodules` submodule URLs, `url.<base>.insteadOf` rewrites, or LFS endpoint declarations, all of which are ordinary, repository-tracked configuration that ships inside a cloned repo. None of these values are validated by Desktop against the repository's primary remote before the trampoline token/credential-helper session is active for the whole git invocation.

This is the same broken-invariant shape as the RocketStorage report: a single coarse authorization gate ("is this a currently-active trampoline token" / "is this a registered contract") grants full write access to a shared store (`setGenericCredential`/`deleteGenericCredential`, analogous to `addressStorage`/`uIntStorage`) for *any* key (host), instead of scoping writes to the namespace (repository/remote) the caller is actually operating on.

### Impact Explanation
An attacker who controls a cloned/fetched repository can plant a submodule, LFS pointer, or `insteadOf` rewrite that points to an arbitrary host with embedded basic-auth credentials (e.g. `https://user:evilpass@corp-git.internal/x`). When the victim performs a normal Desktop operation (clone, fetch, add existing repository, submodule update) that touches that URL, Git will call the credential helper's `store` command for that host, and Desktop will persist the attacker-chosen `(host, username, password)` into the OS-level generic credential store (keychain / Windows Credential Manager / libsecret) via `setGenericCredential`. If the victim already has legitimate stored credentials for that same host (e.g., a corporate Git server), this silently overwrites them with attacker-controlled values, corrupting the credential material Desktop will offer for subsequent, unrelated operations against that host. The same path also allows the attacker to trigger `erase`, deleting the user's legitimate credential for a host they don't control. This is a genuine credential-store corruption/poisoning primitive triggered purely by content of an attacker-controlled repository.

### Likelihood Explanation
The trampoline credential helper is wired in for every git subprocess Desktop spawns, not just ones initiated against attacker repositories directly - the classification and storage logic apply to any "generic" (non-GitHub) host encountered during that invocation. Any workflow that causes Git to read repository-supplied remote/submodule/`insteadOf` configuration (clone, fetch, submodule update) is sufficient to reach this path; no unusual user interaction beyond adding/cloning the malicious repository is required.

### Recommendation
Scope the generic credential-helper's `store`/`erase` operations to hosts that are actually associated with the repository/remote the current git invocation is operating on (i.e., bind the trampoline session to an allow-list of expected hosts derived from the repository's configured remotes at the time the operation was initiated by the user), rather than trusting any host Git reports during the session. Consider prompting the user before persisting new generic credentials for a host that wasn't part of the explicitly configured remote, mirroring the namespace-scoping recommendation from the original report.

### Proof of Concept
1. Attacker publishes a public repository containing a `.gitmodules` entry (or `url.<host>.insteadOf` local config, delivered via a benign-looking clone URL redirect) such as:
   `https://implanted-user:implanted-pass@victim-internal-host.example/repo.git`
2. Victim adds/clones this repository in GitHub Desktop and Desktop performs a fetch/submodule update, invoking `git` with `credential.helper=desktop` set globally via `withTrampolineEnv` [5](#0-4) .
3. Git contacts `victim-internal-host.example` with the embedded credentials; on success it invokes the credential helper's `store` command for that host.
4. `createCredentialHelperTrampolineHandler` routes this to `storeCredential`, which classifies the host as `generic` (since it doesn't match GitHub/GHE/Gist or any known account) [6](#0-5)  and calls `setGenericCredential(host, 'implanted-user', 'implanted-pass')`, persisting the attacker's chosen credential into the user's OS credential store for `victim-internal-host.example` - overwriting any credential the user previously trusted for that host, with no verification that this host relates to the repository the user actually intended to work with.

const getEndpointKind = async (cred: Credential, store: Store) => {
  const credentialUrl = getCredentialUrl(cred)
  const endpoint = `${credentialUrl}`

  if (isGist(endpoint)) {
    return 'generic'
  }

  if (isDotCom(endpoint)) {
    return 'github.com'
  }

  if (isGHE(endpoint)) {
    return 'ghe.com'
  }

  // When Git attempts to authenticate with a host it captures any
  // WWW-Authenticate headers and forwards them to the credential helper. We
  // use them as a happy-path to determine if the host is a GitHub host without
  // having to resort to making a request ourselves.
  for (const [k, v] of cred.entries()) {
    if (k.startsWith('wwwauth[')) {
      if (v.includes('realm="GitHub"')) {
        return 'enterprise'
      } else if (/realm="(GitLab|Gitea|Atlassian Bitbucket)"/.test(v)) {
        return 'generic'
      }
    }
  }

  const existingAccount = await findGitHubTrampolineAccount(store, endpoint)
  if (existingAccount) {
    return isDotCom(existingAccount.endpoint) ? 'github.com' : 'enterprise'
  }

  // All GitHub hosts use HTTPS, so if the protocol is not HTTPS we can
  // assume that this is not a GitHub host.
  if (credentialUrl.protocol !== 'https:') {
    return 'generic'
  }

  return (await isGitHubHost(endpoint)) ? 'enterprise' : 'generic'
}

/** Implementation of the 'store' git credential helper command */
async function storeCredential(cred: Credential, store: Store, token: string) {
  if ((await getEndpointKind(cred, store)) !== 'generic') {
    return
  }

  return useExternalCredentialHelper()
    ? storeExternalCredential(cred, token)
    : setGenericCredential(
        urlWithoutCredentials(getCredentialUrl(cred)),
        forceUnwrap(`credential missing username`, cred.get('username')),
        forceUnwrap(`credential missing password`, cred.get('password'))
      )
}

const storeExternalCredential = (cred: Credential, token: string) => {
  const path = getTrampolineEnvironmentPath(token)
  return approveCredential(cred, path, getGcmEnv(token))
}

/** Implementation of the 'erase' git credential helper command */
async function eraseCredential(cred: Credential, store: Store, token: string) {
  if ((await getEndpointKind(cred, store)) !== 'generic') {
    return
  }

  return useExternalCredentialHelper()
    ? eraseExternalCredential(cred, token)
    : deleteGenericCredential(
        urlWithoutCredentials(getCredentialUrl(cred)),
        forceUnwrap(`credential missing username`, cred.get('username'))
      )
}
