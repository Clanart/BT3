## Analysis

The reported bug pattern is: a critical value-moving function (`dumpFees`) is gated behind an access-control check whose expected caller never actually calls it with the right calling convention, so the funds move path is unreachable/broken and the corresponding cleanup logic (fee zeroing) has no matching execution — resulting in fund loss.

The closest concrete analog in Hyperbridge is the relayer-fee **cross-chain withdrawal dispatch**, where the Substrate `pallet-ismp-relayer` encodes the withdrawal message body for the EVM `HostManager.onAccept` callback in a format that does not match what `HostManager.onAccept` expects to decode.

### Title
Relayer fee withdrawal body is missing the `OnAcceptActions` selector prefix expected by `HostManager.onAccept`, causing cross-chain withdrawal execution to fail after the fee balance has already been zeroed - (File: `modules/pallets/relayer/src/withdrawal.rs`, `evm/src/core/HostManager.sol`)

### Summary
`Pallet::withdraw` on Hyperbridge dispatches an ISMP POST request to the destination EVM chain's `HostManager` contract to disburse a relayer's accumulated fees. For EVM destinations, the request body is built as the raw ABI encoding of `WithdrawalParams{beneficiary_address, amount, token}` with no leading discriminant byte: [1](#0-0) 

But the receiving `HostManager.onAccept` on the EVM side unconditionally treats the **first byte** of the request body as an `OnAcceptActions` enum selector and only ABI-decodes `WithdrawParams` from `request.body[1:]`: [2](#0-1) 

Because the relayer pallet's encoded body has no selector byte, the callee's byte-0/word-alignment assumptions are wrong: `OnAcceptActions(uint8(request.body[0]))` reads into the first byte of the ABI-encoded struct instead of an actual action tag, and `abi.decode(request.body[1:], (WithdrawParams))` operates on a body shifted by one byte relative to how it was encoded. ABI encoding is word-aligned (32-byte slots with offset pointers for dynamic fields such as `beneficiary_address`), so shifting the buffer by a single byte corrupts every offset/length field, and the decode call will revert in the vast majority of cases.

### Finding Description
The bug is structurally identical to the reported `dumpFees` issue: a fund-moving function exists and is reachable only through a specific caller/format contract that the actual sender does not satisfy, so the call effectively never executes as intended.

- Source of truth for the wire format is `pallet-ismp-host-executive`'s `WithdrawalParams::abi_encode()`, invoked directly with no action tag: [3](#0-2) 
- The consumer `HostManager.onAccept` requires `request.body[0]` to be an `OnAcceptActions` enum (`Withdraw = 0`, `SetHostParam = 1`) before it will even attempt to call `IHostManager(_params.host).withdraw(...)`: [4](#0-3) , [5](#0-4) 

Critically, the pallet zeroes the relayer's `Fees` entry on the source (Hyperbridge) chain **immediately after successfully queuing the dispatch**, not after confirming successful execution on the destination: [6](#0-5) 

The dispatched POST request also carries `timeout: 0` (never times out), so there is no built-in refund/retry path if the `onAccept` execution reverts on delivery: [7](#0-6) 

Documentation for the relayer flow confirms this "fire-and-forget" design — settlement is expected to occur when the request is delivered, with no rollback on the source side: [8](#0-7) 

### Impact Explanation
If the encoding mismatch causes `onAccept` to revert on delivery (the most likely outcome given ABI word-alignment), the relayer's fee balance is already zeroed on Hyperbridge (`Fees::insert(..., U256::zero())`) with no compensating credit, and the withdrawal request has `timeout: 0` (it can be redelivered, but the payload itself is permanently malformed since it's derived deterministically from the same stored proof data) — so the relayer's accrued cross-chain fees for that withdrawal are effectively lost. This falls under "loss of funds" in the accepted impact set, and is not a peer/relayer/prover-trust issue: it is a protocol-level ABI-encoding/decoding contract violation between two components that are both part of core Hyperbridge (pallet ↔ `HostManager`).

### Likelihood Explanation
This path triggers on every relayer withdrawal to an EVM destination chain (`Pallet::withdraw` → `HYPERBRIDGE_MODULE_ID`/`host_manager` dispatch), which is a normal, frequently-used, unprivileged relayer operation (any relayer with accumulated fees can call `withdraw_fees`), not requiring any malicious peer, relayer collusion, or governance action.

### Recommendation
Align the wire format between `Pallet::withdraw`'s EVM body construction and `HostManager.onAccept`'s decode logic: prefix the ABI-encoded `WithdrawalParams` payload with the `OnAcceptActions.Withdraw` selector byte (`0x00`) before dispatch, matching exactly what `HostManager.onAccept` expects (`body[0]` = action, `body[1:]` = ABI-encoded params). Additionally, consider not zeroing `Fees` until a delivery acknowledgment/receipt is confirmed, or add a proper timeout + refund path so a failed destination-side execution does not permanently destroy the relayer's fee credit.

### Proof of Concept
1. A relayer accumulates fees on Hyperbridge and calls `withdraw_fees` targeting an EVM `dest_chain`.
2. `Pallet::withdraw` (in `withdrawal.rs`) builds `body = WithdrawalParams{beneficiary_address, amount, token}.abi_encode()` and dispatches a POST to `params.host_manager` with `timeout: 0`.
3. `Fees` for that relayer/chain pair is immediately zeroed.
4. When the request lands on the EVM chain, `HostManager.onAccept` executes `OnAcceptActions action = OnAcceptActions(uint8(request.body[0]))` against the first byte of the raw ABI-encoded struct (not an actual selector), then attempts `abi.decode(request.body[1:], (WithdrawParams))` on a buffer whose word alignment is off by one byte — this decode reverts for virtually all real payloads (since ABI dynamic-type offsets no longer point to valid slots).
5. The `onAccept` call reverts, the withdrawal never executes on the destination, yet the relayer's `Fees` balance on Hyperbridge was already zeroed in step 3 — the funds are unrecoverable through the normal flow. [9](#0-8) [2](#0-1)

    function onAccept(IncomingPostRequest calldata incoming) external override restrict(_params.host) {
        PostRequest calldata request = incoming.request;
        // Only the Hyperbridge parachain can send requests to this module.
        if (!request.source.equals(IHost(_params.host).hyperbridge())) revert UnauthorizedAction();

        OnAcceptActions action = OnAcceptActions(uint8(request.body[0]));
        if (action == OnAcceptActions.Withdraw) {
            // This is where governance & relayers can withdraw their revenue.
            WithdrawParams memory withdrawParams = abi.decode(request.body[1:], (WithdrawParams));
            IHostManager(_params.host).withdraw(withdrawParams);
        } else if (action == OnAcceptActions.SetHostParam) {
            HostParams memory hostParams = abi.decode(request.body[1:], (HostParams));
            IHostManager(_params.host).updateHostParams(hostParams);
        }
    }
