### Title
Coinbase outputs are reported as spendable before maturity - (File: networks/bitcoin/src/wallet/mod.rs)

### Summary
`Scanner::scan_block` includes the coinbase transaction when reporting `ReceivedOutput`s, even though Bitcoin coinbase outputs cannot be spent for 100 blocks. `SignableTransaction::new` then accepts such an output as an ordinary input without checking coinbase maturity, allowing callers to construct and sign a transaction that consensus will reject. [1](#0-0) [2](#0-1) 

### Finding Description
`scan_block` iterates over every transaction in `block.txdata`, including `block.txdata[0]`; its own comment acknowledges that coinbase outputs remain maturity-bound and require post-processing if immediate spendability is required. [3](#0-2)  `scan_transaction` converts any transaction output whose `script_pubkey` matches a registered scanner script into a `ReceivedOutput`, with no distinction between coinbase and ordinary outputs. [4](#0-3)  `SignableTransaction::new` accepts caller-provided `ReceivedOutput`s, turns their outpoints into transaction inputs, stores their full `TxOut`s as prevouts, and performs no maturity or transaction-type validation. [5](#0-4) [6](#0-5)  During signing, those prevouts are committed through `Prevouts::All`, so the resulting signatures are bound to a transaction Bitcoin nodes cannot accept until the coinbase matures. [7](#0-6) 

### Impact Explanation
An externally produced block containing a coinbase output to a registered scanner address can cause the scanner API to report funds as received even though the output is not spendable. Downstream wallet code can consume that reported output, construct a spend, obtain signatures, and produce a transaction that Bitcoin consensus rejects, causing failed execution and potentially repeated signing/broadcast attempts. This matches the accepted impact of funds being reported received when they are not presently spendable. [1](#0-0) [8](#0-7) 

### Likelihood Explanation
Any miner can create a coinbase output paying a scanned script, and any caller that uses `scan_block` without the documented post-processing pass will receive it as a `ReceivedOutput`. Triggering the issue does not require a malicious validator, private-key access, malformed encodings, or collusion. [9](#0-8)  The likelihood is moderated because the API documentation explicitly warns that immediate-spend consumers must remove coinbase outputs, and the coins become spendable after 100 blocks rather than being permanently lost. [10](#0-9) 

### Recommendation
Change `Scanner::scan_block` to skip `block.txdata[0]`, or return coinbase outputs with an explicit maturity marker that prevents them from being passed to `SignableTransaction::new` until they are spendable. If preserving the current API, `SignableTransaction::new` should reject maturity-bound coinbase `ReceivedOutput`s, which requires carrying the producing transaction’s coinbase status or block height in `ReceivedOutput`. [11](#0-10) [12](#0-11) 

### Proof of Concept
1. Construct a `Scanner` for an even-Y key, causing `Scanner::new` to register the corresponding P2TR script. [13](#0-12) 
2. Submit a block whose coinbase transaction contains an output paying that registered script; `scan_block` scans every `block.txdata` element and `scan_transaction` returns a `ReceivedOutput` for the matching script. [9](#0-8) 
3. Pass that `ReceivedOutput` to `SignableTransaction::new`; it is converted into a `TxIn` and its `TxOut` is stored in `prevouts` without checking that the source was a coinbase. [5](#0-4) [6](#0-5) 
4. Sign and complete the transaction; the code inserts the completed Schnorr witness and returns the transaction even though Bitcoin consensus rejects a spend of an immature coinbase output. [8](#0-7)

  pub fn scan_transaction(&self, tx: &Transaction) -> Vec<ReceivedOutput> {
    let mut res = Vec::new();
    for (vout, output) in tx.output.iter().enumerate() {
      // If the vout index exceeds 2**32, stop scanning outputs
      let Ok(vout) = u32::try_from(vout) else { break };

      if let Some(offset) = self.scripts.get(&output.script_pubkey) {
        res.push(ReceivedOutput {
          offset: *offset,
          output: output.clone(),
          outpoint: OutPoint::new(tx.compute_txid(), vout),
        });
      }
    }
    res
  }

  /// Scan a block.
  ///
  /// This will also scan the coinbase transaction which is bound by maturity. If received outputs
  /// must be immediately spendable, a post-processing pass is needed to remove those outputs.
  /// Alternatively, scan_transaction can be called on `block.txdata[1 ..]`.
  pub fn scan_block(&self, block: &Block) -> Vec<ReceivedOutput> {
    let mut res = Vec::new();
    for tx in &block.txdata {
      res.extend(self.scan_transaction(tx));
    }
    res
  }
