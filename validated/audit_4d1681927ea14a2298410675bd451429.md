### Title
Unix Socket gRPC Server Omits `OnlyAggregatorAndSelf` Interceptor, Allowing Any Co-Located Process to Invoke Internal Bridge Methods — (`core/src/servers.rs`)

### Summary

The `create_grpc_server` function in `core/src/servers.rs` applies the `OnlyAggregatorAndSelf` mTLS interceptor only on the TCP path. The Unix socket path unconditionally registers the raw service with no interceptor, so any local process that can reach the socket file can call every gRPC method — including `InternalEndRound`, `InternalHandleKickoff`, and `InternalWithdraw` — without presenting a certificate.

### Finding Description

`create_grpc_server` branches on `ServerAddr`:

**TCP path** — wraps the service with `InterceptedService::new(service, OnlyAggregatorAndSelf{...})` when `client_verification = true`: [1](#0-0) 

**Unix socket path** — calls `.add_service(service)` directly, with no interceptor at all: [2](#0-1) 

The interceptor `OnlyAggregatorAndSelf` is the sole enforcement point for the two-tier access model:
- Non-`Internal` methods → aggregator cert or self cert only
- `Internal` methods → self cert only [3](#0-2) 

`is_internal` classifies a request by checking whether the `grpc-method` header (injected by `AddMethodMiddlewareLayer`) starts with `"Internal"`: [4](#0-3) 

Because the Unix socket path never installs `InterceptedService`, the `AddMethodMiddlewareLayer` still runs (it is added to the builder on both paths), but the interceptor that reads the header and enforces identity is absent. Every request passes straight through.

The testnet4 production config explicitly enables both `client_verification = true` and `socket_path`: [5](#0-4) 

This means the Unix socket is a live, intended deployment mode, not a test-only path.

### Impact Explanation

Three Internal methods are reachable without any credential:

**`InternalEndRound`** — takes no parameters; calls `operator.end_round()` which advances the operator's round-UTXO chain in the database: [6](#0-5) 

Premature round advancement can leave kickoff UTXOs in an inconsistent state and expose the operator to slashing, because the on-chain round-tx sequence is pre-signed and must match the DB state.

**`InternalHandleKickoff`** — accepts any `Txid`; if found in the DB it calls `verifier.handle_kickoff(...)` with `challenged_before = false`, which can enqueue a `Challenge` transaction to the tx-sender: [7](#0-6) [8](#0-7) 

Sending a spurious challenge transaction burns the challenge UTXO and can disrupt the legitimate challenge/disprove flow.

**`InternalWithdraw`** — skips the `aggregator_verification_address` ECDSA check that the public `withdraw` endpoint enforces: [9](#0-8) [10](#0-9) 

An attacker who also controls a valid withdrawal UTXO signature (e.g., a colluding user) can bypass the aggregator's manual verification gate and force an immediate payout.

### Impact Explanation

| Method | Worst-case outcome |
|---|---|
| `InternalEndRound` | Operator round state desync → operator slashed (collateral loss) |
| `InternalHandleKickoff` | Spurious challenge tx broadcast → challenge UTXO burned, liveness broken |
| `InternalWithdraw` | Aggregator verification gate bypassed → unauthorized payout |

All three outcomes fall within the allowed impact gate: unauthorized state transition in payout/challenge/round flow with material fund impact, and authentication bypass in gRPC/mTLS actor roles.

### Likelihood Explanation

The Unix socket is protected by OS filesystem permissions (same-user access). However:
- The testnet4 Docker deployment runs multiple services in the same container/pod, often as the same OS user.
- Any compromised co-located process (Bitcoin RPC client, DB client, monitoring agent) running as the same user gains full Internal-method access.
- No exploit of the TLS stack is required; a plain gRPC client connecting to the socket path suffices.

### Recommendation

Apply the same `InterceptedService` wrapping to the Unix socket path as is done for TCP:

```rust
#[cfg(unix)]
ServerAddr::Unix(ref socket_path) => {
    // Build intercepted service identically to the TCP path
    let service = InterceptedService::new(
        service,
        if config.client_verification {
            OnlyAggregatorAndSelf { aggregator_cert, our_cert: client_cert }
        } else {
            Noop
        },
    );
    let server_builder = tonic::transport::Server::builder()
        .layer(AddMethodMiddlewareLayer)
        // ...
        .add_service(service);
    // ...
}
```

Alternatively, if the Unix socket is intended to be a trusted local-only channel, document that assumption explicitly and ensure the socket file permissions are set to `0600` and owned by the service account, and that no other process runs as that user.

### Proof of Concept

1. Deploy operator/verifier with `socket_path` set (as in the testnet4 config) and `client_verification = true`.
2. From any process running as the same OS user, connect a plain gRPC client to the Unix socket (no TLS, no certificate).
3. Call `/clementine.ClementineOperator/InternalEndRound` with an empty body.
4. Observe: the operator's round index advances in the database without the corresponding on-chain round transaction having been broadcast, desynchronizing the pre-signed UTXO chain and exposing the operator to slashing.

The root cause is exclusively in `core/src/servers.rs` lines 179–189: the Unix socket branch omits `InterceptedService`, which is the only code path that enforces the `OnlyAggregatorAndSelf` certificate check. [11](#0-10)
