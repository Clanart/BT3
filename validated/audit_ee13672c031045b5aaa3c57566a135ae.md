### Title
Unbounded Python recursion in wallet outer-puzzle driver matching (offer/CAT/NFT layer walk) can crash a wallet processing an attacker-crafted offer or spend bundle - ([File: chia/wallet/outer_puzzles.py])

### Summary
The bug class in CVE-2021-28302 is a stack overflow caused by an *unbounded recursive* tree-walk over attacker-controlled, arbitrarily-nested data (`ixmlNode_free()` recursing over a parsed XML tree). The chia codebase mitigates this exact class in several core spots — `sha256_treehash()`/`tree_hash.py` is explicitly implemented iteratively "so we don't have to worry about blowing out the python stack" [1](#0-0) , and Data Layer proof insertion enforces `chia_rs.datalayer.RecursionDepthExceededError` on deep trees [2](#0-1) . However, the wallet's "outer puzzle" driver-matching chain, used to interpret untrusted puzzle reveals (e.g. when parsing an offer or spend bundle from a counterparty), walks nested puzzle layers with genuine Python recursion and has no depth guard.

### Finding Description
`match_puzzle()` in `chia/wallet/outer_puzzles.py` iterates registered drivers (CAT, Singleton, Metadata, Ownership, CR, Revocation) and calls `driver.match(puzzle)` [3](#0-2) . Each driver's `match()` recurses into `self._match(UnknownPuzzle(known_program=inner_puzzle))` whenever the puzzle matches its layer's mod hash, e.g. in `CATOuterPuzzle.match()` [4](#0-3) , `OwnershipOuterPuzzle.match()` [5](#0-4) , `MetadataOuterPuzzle.match()` [6](#0-5) , `SingletonOuterPuzzle.match()` [7](#0-6) , and `CROuterPuzzle.match()` [8](#0-7) . The recursion depth equals the number of nested outer-puzzle layers in the puzzle reveal; there is no cap. `get_inner_puzzle()` and `get_inner_solution()` on each driver recurse the same way.

This code path is directly reachable from untrusted, attacker-supplied puzzle reveals: `Offer.from_spend_bundle()` calls `match_puzzle(UnknownPuzzle(known_program=coin_spend.puzzle_reveal))` for every coin spend in an incoming offer/spend bundle [9](#0-8) , and `Offer._get_offered_coins()` similarly calls `match_puzzle` while walking a counterparty-supplied bundle to determine the offered coins [10](#0-9) . A malicious counterparty can construct a `puzzle_reveal` consisting of thousands of nested `CAT_MOD` (or ownership/metadata) curry layers — cheap CLVM to construct and cheap to `uncurry()`/match at each level — driving Python recursion depth into the thousands when a wallet parses the offer, well beyond Python's default recursion limit (1000), before any consensus-level cost/complexity bound is even evaluated (this is pre-CLVM-execution parsing logic, not gated by mempool CLVM cost).

### Impact Explanation
If unhandled, deep recursion here raises `RecursionError` in the wallet/RPC process handling `take_offer`/offer-parsing flows; if the call stack is exhausted before Python's own recursion guard triggers (e.g. under constrained C-stack environments or via `ctypes`/other C-extension frames interleaved in the call chain), it can manifest as a hard interpreter crash rather than a catchable exception — a denial-of-service against a wallet or RPC client that merely inspects an untrusted offer/spend bundle from a counterparty. This matches the "spend-triggered transaction-processing halt" impact class called out in the validation criteria, scoped to the wallet's offer-handling and CAT/NFT/VC driver-matching pipeline rather than full-node consensus.

### Likelihood Explanation
Medium. Constructing deeply nested curry layers of a recognized mod (e.g. `CAT_MOD`) is inexpensive and requires no valid signatures or spendable coins to merely trigger the `match_puzzle` walk on a `puzzle_reveal` — the recursive matching logic runs before/independent of full puzzle execution or signature validation. The main uncertainty is whether the offer-acceptance/RPC caller wraps this code in a broad exception handler that would turn a `RecursionError` into a harmless error response rather than a process crash; I could not fully verify this from the indexed portion of `offer.py` and related RPC call sites within available context.

### Recommendation
Convert the recursive driver-matching chain (`match()`, `get_inner_puzzle()`, `get_inner_solution()`, `construct()`, `solve()` across `CATOuterPuzzle`, `SingletonOuterPuzzle`, `MetadataOuterPuzzle`, `OwnershipOuterPuzzle`, `CROuterPuzzle`, and `outer_puzzle.match_puzzle`) into an iterative implementation, or impose an explicit maximum nesting-depth check before recursing, mirroring the design rationale already used in `chia/types/blockchain_format/tree_hash.py`. Additionally, ensure all offer/spend-bundle parsing entry points (`Offer.from_spend_bundle`, `Offer._get_offered_coins`, and any RPC `take_offer`/`get_offer_summary` handlers) catch `RecursionError` and convert it into a normal validation failure rather than allowing it to propagate.

### Proof of Concept
Conceptual PoC (not executed): build a puzzle reveal `P` = `CAT_MOD.curry(tail, CAT_MOD.curry(tail, CAT_MOD.curry(tail, ... , ACS)))` nested N times (N in the low thousands), embed it as a `puzzle_reveal` for a dummy coin spend inside a `WalletSpendBundle`, and pass that bundle to `Offer.from_spend_bundle()` or otherwise trigger `match_puzzle(UnknownPuzzle(known_program=P))`. The `CATOuterPuzzle.match()` → `self._match()` recursion chain [4](#0-3)  will recurse N times, exhausting Python's stack/recursion limit.

@pytest.mark.anyio
@pytest.mark.parametrize("depth", [1000, 100_000])
async def test_insert_into_data_store_from_file_line_graph_depth(
    data_store: DataStore,
    store_id: bytes32,
    tmp_path: Path,
    depth: int,
) -> None:
    # Binary "line graph":
    #   1 -> leaf_1, 2
    #   2 -> leaf_2, 3
    #   ...
    #   depth -> leaf_depth, leaf_end
    #
    # This stresses depth/stack handling while staying strictly binary.
    #
    # Node IDs:
    # - internal nodes: 1..depth
    # - per-level leaf nodes: (depth+1)..(2*depth)
    # - final leaf: (2*depth+1)
    internal_first = 1
    internal_last = depth
    leaf_base = internal_last + 1
    leaf_end = (2 * depth) + 1

    edges: list[tuple[int, int]] = []
    for i in range(internal_first, internal_last):
        # Order matters: first edge is left child, second edge is right child.
        edges.append((i, leaf_base + (i - internal_first)))  # unique leaf for this internal node
        edges.append((i, i + 1))  # next internal node

    # last internal points to its leaf and a final leaf
    edges.append((internal_last, leaf_base + (internal_last - internal_first)))
    edges.append((internal_last, leaf_end))

    filename = tmp_path / f"line_graph_depth_{depth}.dat"
    root_hash = create_graph_util(filename, edges)

    with pytest.raises(chia_rs.datalayer.RecursionDepthExceededError):
        await data_store.insert_into_data_store_from_file(store_id, root_hash, filename)
