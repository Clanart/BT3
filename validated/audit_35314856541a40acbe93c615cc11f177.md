### Title
Path-forwarding proxy in `frozen-rpc-router` forwards the raw, unvalidated request path to backend nodes, allowing a public client to reach unintended endpoints - (File: cmd/frozen-rpc-router/router.go)

### Summary
`frozen-rpc-router` is a public-facing HTTP proxy that sits in front of a live EVM RPC node and any number of "frozen" (historical) nodes, routing JSON-RPC calls to the correct backend by inspecting the JSON-RPC method/params [1](#0-0) . Like the reported class of bug (a front proxy/backend mismatch causing path traversal into unintended Tomcat endpoints), this component's request-forwarding logic does not validate or normalize the inbound HTTP path before relaying it to the chosen backend.

### Finding Description
`ServeHTTP` dispatches purely on `request.Method`: non-POST requests go straight to `r.liveProxy` (a standard `httputil.ReverseProxy`), and POST requests are parsed as JSON-RPC and dispatched to `r.serveSingle`/`r.serveBatch`, which only inspect the JSON-RPC body — the URL path of the incoming request is never checked or restricted to `/` [2](#0-1) .

When a call is finally proxied, `newUpstreamRequest` builds the outbound request by calling `joinedURL(target.endpoint, request.URL)`, which naively concatenates the operator-configured upstream base path with the caller-supplied `incoming.Path` and clears `RawPath`: [3](#0-2) 

Because `router` is used as a raw `http.Handler` (not behind `http.ServeMux`, which is the only thing in the Go standard library that cleans `.`/`..` segments), `request.URL.Path` retains whatever literal path segments the client sent — including `..` sequences or paths pointing at backend routes other than `/`. `joinedURL` performs no cleaning (`path.Clean`) and no validation that the incoming path equals `/`, so an attacker-controlled path is forwarded verbatim to the selected backend (`r.live` or a frozen node), exactly the "front proxy passes an unsanitized path to backend server" pattern described in the external report.

This is functionally analogous to the NGINX/Tomcat misconfiguration in the report: the front-end (`frozen-rpc-router`, playing the NGINX role) does not restrict or normalize the path before relaying to the backend (playing the Tomcat role, i.e. the actual `geth`-style JSON-RPC `HTTPServer` in `evmrpc/rpcstack.go`, which itself registers additional handlers on its mux beyond the root JSON-RPC endpoint via `Node.RegisterHandler`, and gates access to prefixed paths only through simple string-prefix `CheckPath`) [4](#0-3) . If the backend registers any endpoint reachable at a non-root path (anything wired through `h.mux`), a POST body that is valid JSON-RPC together with a manipulated URL path is proxied straight through to that path on the backend, defeating any path-based access control the operator may rely on the router to enforce.

### Impact Explanation
An unprivileged public RPC client can influence which backend endpoint on the live/frozen node handles their request by crafting the HTTP request path, since the router forwards the literal path unchanged. If any operator relies on the router to gate access only to the root JSON-RPC method dispatch (e.g., expecting only `/` to ever be reachable through the front proxy), this allows reaching internal-only paths registered on the backend's HTTP mux that were not meant to be internet-exposed. Depending on what is registered on that mux in a given deployment, this ranges from information disclosure to reaching debug/administrative surfaces — matching the "expose unintended endpoints" impact class of the reference CVE. This does not, however, provide a direct path to fund loss, precompile/pointer bypass, or consensus-affecting impact within the scope rules unless a specific sensitive handler is proven reachable on `h.mux` in this repo, which could not be conclusively confirmed from the code inspected.

### Likelihood Explanation
Likelihood is limited to environments where `frozen-rpc-router` is deployed (per `docker/docker-compose.frozen-rpc-router.yml`) in front of a live node whose EVM RPC HTTP server has more than the root JSON-RPC handler registered on its mux, and where the operator did not add path filtering elsewhere (e.g., an additional reverse proxy). Any unprivileged client reaching the router's listen address (typically `0.0.0.0:8545` per the README example) can attempt this with a normal POST request containing a crafted path.

### Recommendation
In `cmd/frozen-rpc-router/router.go`, reject any request whose `request.URL.Path` is not exactly `/` (mirroring `handleInvalidJSONRPCPaths` used by the Tendermint JSON-RPC server [5](#0-4) ), and additionally clean/validate `incoming.Path` in `joinedURL` (e.g., via `path.Clean` and rejecting `..` segments) before joining it onto the upstream base path, so the router can never forward client-controlled path segments to the backend beyond the intended root JSON-RPC endpoint.

### Proof of Concept
1. Deploy `frozen-rpc-router` per the documented configuration, pointing `--live-node` at a full node whose EVM `HTTPServer` has any handler registered on `h.mux` beyond `/` (e.g., via `Node.RegisterHandler`) [6](#0-5) .
2. Send: `POST http://<router>/<backend-only-path> ` with body `{"jsonrpc":"2.0","id":1,"method":"eth_blockNumber","params":[]}`.
3. Because `ServeHTTP`/`serveSingle` only inspect the body and never check `request.URL.Path`, the request is routed to `r.live` and `joinedURL` forwards the literal `/<backend-only-path>` onto the upstream base URL [7](#0-6) , reaching whatever handler is registered at that path on the backend rather than being confined to the intended root JSON-RPC surface.

func (r *router) ServeHTTP(w http.ResponseWriter, request *http.Request) {
	if request.Method != http.MethodPost {
		r.liveProxy.ServeHTTP(w, request)
		return
	}

	request.Body = http.MaxBytesReader(w, request.Body, r.maxRequestBodySize)
	body, err := io.ReadAll(request.Body)
	if err != nil {
		var maxBytesErr *http.MaxBytesError
		if errors.As(err, &maxBytesErr) {
			http.Error(w, "request body too large", http.StatusRequestEntityTooLarge)
			return
		}
		http.Error(w, "failed to read request body", http.StatusBadRequest)
		return
	}

	trimmed := bytes.TrimSpace(body)
	if len(trimmed) > 0 && trimmed[0] == '[' {
		r.serveBatch(w, request, body)
		return
	}
	r.serveSingle(w, request, body)
}

func (r *router) newUpstreamRequest(request *http.Request, target *upstream, body []byte) (*http.Request, error) {
	endpoint := joinedURL(target.endpoint, request.URL)
	upstreamRequest, err := http.NewRequestWithContext(request.Context(), request.Method, endpoint.String(), bytes.NewReader(body)) //nolint:gosec // endpoint is rooted at an operator-configured upstream URL.
	if err != nil {
		return nil, err
	}
	upstreamRequest.Header = request.Header.Clone()
	removeHopByHopHeaders(upstreamRequest.Header)
	upstreamRequest.Header.Del("Accept-Encoding")
	if host := clientIP(request.RemoteAddr); host != "" {
		prior := upstreamRequest.Header.Get("X-Forwarded-For")
		if prior != "" {
			host = prior + ", " + host
		}
		upstreamRequest.Header.Set("X-Forwarded-For", host)
	}
	return upstreamRequest, nil
}

func joinedURL(base, incoming *url.URL) *url.URL {
	target := *base
	if incoming.Path != "" && incoming.Path != "/" {
		target.Path = strings.TrimRight(base.Path, "/") + "/" + strings.TrimLeft(incoming.Path, "/")
		target.RawPath = ""
	}
	if target.RawQuery == "" {
		target.RawQuery = incoming.RawQuery
	} else if incoming.RawQuery != "" {
		target.RawQuery += "&" + incoming.RawQuery
	}
	return &target
}

func (h *HTTPServer) ServeHTTP(w http.ResponseWriter, r *http.Request) {
	// check if ws request and serve if ws enabled
	ws := h.wsHandler.Load().(*rpcHandler)
	if ws != nil && websocket.IsWebSocketUpgrade(r) {
		if CheckPath(r, h.WsConfig.prefix) {
			ws.ServeHTTP(w, r)
		}
		return
	}

	// if http-rpc is enabled, try to serve request
	rpc := h.httpHandler.Load().(*rpcHandler)
	if rpc != nil {
		// First try to route in the mux.
		// Requests to a path below root are handled by the mux,
		// which has all the handlers registered via Node.RegisterHandler.
		// These are made available when RPC is enabled.
		muxHandler, pattern := h.mux.Handler(r)
		if pattern != "" {
			muxHandler.ServeHTTP(w, r)
			return
		}

		if CheckPath(r, h.HTTPConfig.prefix) {
			rpc.ServeHTTP(w, r)
			return
		}
	}
	w.WriteHeader(http.StatusNotFound)
}

// CheckPath checks whether a given request URL matches a given path prefix.
func CheckPath(r *http.Request, path string) bool {
	// if no prefix has been specified, request URL must be on root
	if path == "" {
		return r.URL.Path == "/"
	}
	// otherwise, check to make sure prefix matches
	return len(r.URL.Path) >= len(path) && r.URL.Path[:len(path)] == path
}

func handleInvalidJSONRPCPaths(next http.HandlerFunc) http.HandlerFunc {
	return func(w http.ResponseWriter, r *http.Request) {
		//  we check whether the path is indeed "/", otherwise return a 404 error
		if r.URL.Path != "/" {
			http.NotFound(w, r)
			return
		}

		next(w, r)
	}
}
