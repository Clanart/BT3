### Title
`debug_redact` field-option redaction is enforced in TextFormat/DebugString but not in ProtoJSON (JsonFormat) output - ([File: java/util/src/main/java/com/google/protobuf/util/JsonFormat.java], [File: src/google/protobuf/json/internal/writer.h])

### Summary
CVE-2018-8042 describes Apache Ambari leaking Hadoop credential-store passwords into agent informational log messages because the logging path had no redaction/masking of sensitive values before they were written to disk. The failed invariant is "sensitive values must never reach an unredacted log/serialization sink even though the underlying data model marks them as sensitive." Protobuf has a first-class mechanism for exactly this class of problem: the `debug_redact` `FieldOptions` annotation, which is honored by `TextFormat`/`Message::DebugString()`/`DebugFormat`, but the same annotation is not consulted by the ProtoJSON code paths (`JsonFormat` in Java, `src/google/protobuf/json/internal/*` in C++). Any consuming application that treats ProtoJSON as its "safe for logs" serialization (a common practice, since JSON is far more frequently logged/dumped than TextFormat) will unintentionally emit `debug_redact`-annotated sensitive fields (passwords, tokens, credentials) in plaintext, defeating the protection the schema author explicitly requested.

### Finding Description
Protobuf's redaction feature is built around `FieldOptions.debug_redact` (`src/google/protobuf/descriptor.proto`), and it is deliberately checked in the printing/debug-string code paths:
- C++: `TextFormat::Printer::TryRedactFieldValue` looks up `field->options().debug_redact()` (via `TextFormat::GetRedactionState`) and substitutes `[REDACTED]` when `redact_debug_string_` is set. This is wired into `Message::DebugString()`/`ShortDebugString()`/`Utf8DebugString()` through `internal::StringifyMessage`, which calls `printer.SetRedactDebugString(true)`. [1](#0-0) [2](#0-1) 
- Java: `TextFormat.Printer.printFieldValue` calls `shouldRedact(field, generator)`, which checks `field.getRedactionState().redact`, and unknown-field paths also propagate a `redact` boolean into `printUnknownFieldValue`/`printUnknownFields`. [3](#0-2) [4](#0-3) 
- `DebugFormat`/`LegacyUnredactedTextFormat` in Java, and `UnredactedDebugFormatForTest` in C++, explicitly document that TextFormat-based `toString()`/`DebugString()` output is "redacted" and safe for debug logging, while un-redacted variants are marked for test-only use. [5](#0-4) [6](#0-5) 

However, `debug_redact` does not appear anywhere in the ProtoJSON printer/parser implementations. A repository-wide search for `debug_redact`/`redact` returns matches only in TextFormat, descriptor/option generated code, and unrelated compiler files — there are zero occurrences in `java/util/src/main/java/com/google/protobuf/util/JsonFormat.java` or in `src/google/protobuf/json/internal/*` (the upb-based JSON writer used by C++/Python/Ruby/PHP bindings). This means `JsonFormat.printer().print(message)` (Java) and the equivalent `MessageToJsonString`/JSON printer paths in C++ will serialize a `debug_redact`-annotated field's real value into JSON, with no `[REDACTED]` substitution, no matter how the schema author configured `debug_redact`.

The attacker-controlled input in the consuming-application scenario is the bounded Protobuf binary/JSON payload the client sends; once parsed into a message with a `debug_redact`-marked sensitive field (e.g., a credential/password field, mirroring the Ambari/Hive/Oozie credential-store password scenario), any application code that logs `JsonFormat.printer().print(message)` for diagnostics — a very common pattern, since JSON is generally preferred over TextFormat for structured/service logs — will write the raw sensitive value to the log, exactly mirroring the CVE-2018-8042 exposure mechanism (sensitive value reaching an informational log sink unredacted), just through the ProtoJSON serializer as the "informational log" writer instead of Ambari Agent's own logger.

### Impact Explanation
This is a disclosure-class issue, matching the severity class of CVE-2018-8042 (High, C:H under CVSS). If an application relies on `debug_redact` as its authoritative mechanism to keep sensitive proto fields (credentials, tokens, PII) out of logs/telemetry, but uses ProtoJSON (a fully supported, documented public serialization API) instead of TextFormat/DebugString for that logging, the "safety" guarantee silently does not apply and the sensitive value is exposed to whatever consumes those logs — the same failure mode and consequence as the Ambari case, where password data reached log aggregation without the developer intending it. Impact is capped at confidentiality disclosure of application-defined sensitive fields (no code execution, no memory corruption), consistent with the "no unbounded/allocation/RCE analog" scope constraint in this exercise.

### Likelihood Explanation
Likelihood is proto-schema/application-dependent rather than automatically exploitable by an anonymous network attacker in isolation — the attacker's role here is limited to supplying a payload that legitimately populates a `debug_redact` field (which is expected, since these are ordinary application fields, e.g. credentials submitted by a client). The actual disclosure trigger is the consuming application's choice to log ProtoJSON output of a message containing such a field, which is a foreseeable and common pattern precisely because protobuf documents `debug_redact` as the general-purpose "safe to log" contract, without scoping that promise to TextFormat only in the ProtoJSON-facing documentation/API surface. This mirrors Ambari's issue: the vulnerable behavior is a documentation/consistency gap between what the redaction feature promises and what it actually covers, not a memory-safety bug.

### Recommendation
- Extend `debug_redact` enforcement to the ProtoJSON printer paths (`JsonFormat` in Java and the upb-based C++/Python/Ruby/PHP JSON writer in `src/google/protobuf/json/internal/`), so that fields annotated `debug_redact = true` are substituted with a redaction marker when printed via `JsonFormat.printer()` / `MessageToJsonString`, at least in a documented "safe" print mode analogous to `DebugFormat`.
- If ProtoJSON is intentionally out of scope for `debug_redact` (e.g., because ProtoJSON must remain round-trippable for wire use, unlike TextFormat's already-lossy redacted mode), this should be explicitly documented next to `debug_redact` in `descriptor.proto` and in `JsonFormat`'s Javadoc/API docs, warning users not to rely on it for JSON-based logging, to prevent the exact class of accidental exposure seen in CVE-2018-8042.

### Proof of Concept
Not independently executed in this environment (index-search only, no build/test harness available). Conceptual reproduction based on confirmed code paths:
1. Define a `.proto` message with a `string password = 1 [debug_redact = true];` (mirrors patterns in `src/google/protobuf/unittest_redaction.proto`). [7](#0-6) 
2. Populate the field from a bounded, otherwise-benign client payload via `Message.parseFrom(bytes)` (trusted schema, ordinary parse API).
3. Call `message.toString()` / `TextFormat.printer().printToString(message)` → observe `[REDACTED]` per `TextFormat.Printer.printFieldValue`'s `shouldRedact` check. [8](#0-7) 
4. Call `JsonFormat.printer().print(message)` on the same message → the code path has no equivalent `debug_redact` check (absent from `JsonFormat.java`), so the JSON output contains the plaintext `password` value — the analog of the password reaching Ambari's informational logs unredacted.

std::string StringifyMessage(const Message& message, Option option,
                             FieldReporterLevel reporter_level) {
  // Indicate all scoped reflection calls are from DebugString function.
  ScopedReflectionMode scope(ReflectionMode::kDebugString);

  TextFormat::Printer printer;
  internal::FieldReporterLevel reporter = reporter_level;
  switch (option) {
    case Option::kShort:
      printer.SetSingleLineMode(true);
      break;
    case Option::kUTF8:
      printer.SetUseUtf8StringEscaping(true);
      break;
    case Option::kNone:
      break;
  }
  printer.SetExpandAny(true);
  printer.SetRedactDebugString(true);
  printer.SetRandomizeDebugString(true);
  printer.SetReportSensitiveFields(reporter);
  std::string result;
  // TODO: Remove this suppression.
  (void)printer.PrintToString(message, &result);

  if (option == Option::kShort) {
    TrimTrailingSpace(result);
  }

  return result;
}

bool TextFormat::Printer::TryRedactFieldValue(
    const Message& message, const FieldDescriptor* field,
    BaseTextGenerator* generator, bool insert_value_separator) const {
  TextFormat::RedactionState redaction_state =
      DescriptorPool::MemoizeProjection(
          field, [](const FieldDescriptor* field) {
            return TextFormat::GetRedactionState(field);
          });
  if (redaction_state.redact) {
    if (redact_debug_string_) {
      IncrementRedactedFieldCounter();
      if (insert_value_separator) {
        generator->PrintMaybeWithMarker(MarkerToken(), ": ");
      }
      generator->PrintString(kFieldValueReplacement);
      if (insert_value_separator) {
        if (single_line_mode_) {
          generator->PrintLiteral(" ");
        } else {
          generator->PrintLiteral("\n");
        }
      }
      return true;
    }
  }
  return false;
}

    // option must be on. 2) The field must be considered "sensitive". A sensitive field can be
    // marked as sensitive via two methods: a) via a direct debug_redact=true annotation on the

    private boolean shouldRedact(final FieldDescriptor field, TextGenerator generator) {
      FieldDescriptor.RedactionState state = field.getRedactionState();
      return enablingSafeDebugFormat && state.redact;

    private static void printUnknownFieldValue(
        final int tag, final Object value, final TextGenerator generator, boolean redact)
        throws IOException {
      switch (WireFormat.getTagWireType(tag)) {
        case WireFormat.WIRETYPE_VARINT:
          generator.print(
              redact
                  ? String.format("UNKNOWN_VARINT %s", REDACTED_MARKER)
                  : unsignedToString((Long) value));
          break;
        case WireFormat.WIRETYPE_FIXED32:
          generator.print(
              redact
                  ? String.format("UNKNOWN_FIXED32 %s", REDACTED_MARKER)
                  : String.format((Locale) null, "0x%08x", (Integer) value));
          break;
        case WireFormat.WIRETYPE_FIXED64:
          generator.print(
              redact
                  ? String.format("UNKNOWN_FIXED64 %s", REDACTED_MARKER)
                  : String.format((Locale) null, "0x%016x", (Long) value));
          break;
        case WireFormat.WIRETYPE_LENGTH_DELIMITED:
          try {
            // Try to parse and print the field as an embedded message
            UnknownFieldSet message = UnknownFieldSet.parseFrom((ByteString) value);
            generator.print("{");
            generator.eol();
            generator.indent();
            printUnknownFields(message, generator, redact);
            generator.outdent();
            generator.print("}");
          } catch (InvalidProtocolBufferException e) {
            // If not parseable as a message, print as a String
            if (redact) {
              generator.print(String.format("UNKNOWN_STRING %s", REDACTED_MARKER));
              break;
            }
            generator.print("\"");
            generator.print(escapeBytes((ByteString) value));
            generator.print("\"");
          }
          break;
        case WireFormat.WIRETYPE_START_GROUP:
          printUnknownFields((UnknownFieldSet) value, generator, redact);
          break;
        default:
          throw new IllegalArgumentException("Bad tag: " + tag);
      }
    }
