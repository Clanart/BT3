### Title
Value-bearing Bitcoin payments can be signed to provably unspendable scripts, burning funds - ([File: networks/bitcoin/src/wallet/send.rs](networks/bitcoin/src/wallet/send.rs))

### Summary
`SignableTransaction::new` accepts caller-controlled `payments: &[(ScriptBuf, u64)]` and enforces only `amount >= DUST`; it never rejects `script_pubkey`s that are provably unspendable, such as `OP_RETURN`. A payment output with `value >= 546` and an `OP_RETURN` script is copied verbatim into the transaction and later signed as a normal spend. The result is a valid consensus transaction whose output can never be spent, permanently burning the attributed BTC. [1](#0-0) [2](#0-1) 

### Finding Description
The Bitcoin wallet builder treats payment destinations as opaque `ScriptBuf`s. It validates input presence, output presence, dust amount for every payment, data length, fee, funds, and weight, but performs no spendability/address validation on `payment.0`. [3](#0-2)  The intended unspendable output is handled separately as a zero-value `data` OP_RETURN output, while the same unspendable script form remains accepted in the value-bearing `payments` path. [4](#0-3)  After construction, `TransactionSignMachine::sign` produces Taproot key-spend signature shares for every input, so the malformed destination becomes part of the signed transaction rather than being rejected. [5](#0-4) 

### Impact Explanation
This is the Serai analog of forwarding value to `address(0)`: an unprivileged party who can influence a withdrawal/burn destination supplies a provably unspendable script instead of a spendable Bitcoin address/script. The network signs a transaction paying real satoshis to that script, where they are unrecoverable. Impact is permanent loss of user/treasury funds from a single signed transaction, without key compromise or threshold misbehavior. [6](#0-5) 

### Likelihood Explanation
Reachability requires control over the destination script passed to `SignableTransaction::new`, which is the untrusted external-address/payment input in the burn/withdrawal flow rather than an internal validator-only secret. The check gap is deterministic: any `ScriptBuf` passes so long as the attached amount clears `DUST`. No race, malformed signature, or cryptographic failure is needed. [7](#0-6) 

### Recommendation
Reject provably unspendable scripts for all value-bearing outputs in `SignableTransaction::new`, e.g. refuse `payment.0.is_provably_unspendable()` / known `OP_RETURN` outputs when `payment.1 != 0`, and keep `OP_RETURN` limited to the separate zero-value `data` output. Prefer validating decoded Bitcoin addresses/templates at the network boundary and only constructing `ScriptBuf` payments from validated spendable destinations. [8](#0-7) 

### Proof of Concept
Conceptual construction against the in-scope wallet API:

```rust
use bitcoin::{Amount, ScriptBuf, script::PushBytesBuf};
use bitcoin_serai::wallet::{SignableTransaction, ReceivedOutput};

// inputs: at least one previously scanned ReceivedOutput with enough value.
let inputs: Vec<ReceivedOutput> = scanned_inputs;

let payments = vec![(
  ScriptBuf::new_op_return(PushBytesBuf::try_from(b"burn".to_vec()).unwrap()),
  546, // passes DUST check
)];

let tx = SignableTransaction::new(
  inputs,
  &payments,
  None,          // no change needed for PoC
  None,          // no separate data output needed
  1,             // fee_per_vbyte chosen to satisfy needed_fee checks
).unwrap();

// tx.transaction().output[0] pays 546 sats to OP_RETURN and is forever unspendable.
let _machine = tx.multisig(&keys).unwrap();
```

`payments` entries are emitted as outputs exactly as supplied, while only `amount < DUST` is rejected. [2](#0-1)

    mut inputs: Vec<ReceivedOutput>,
    payments: &[(ScriptBuf, u64)],
    change: Option<ScriptBuf>,
    data: Option<Vec<u8>>,
    fee_per_vbyte: u64,

    if inputs.is_empty() {
      Err(TransactionError::NoInputs)?;
    }

    if payments.is_empty() && change.is_none() && data.is_none() {
      Err(TransactionError::NoOutputs)?;
    }

    for (_, amount) in payments {
      if *amount < DUST {
        Err(TransactionError::DustPayment)?;
      }
    }

    if data.as_ref().map_or(0, Vec::len) > 80 {
      Err(TransactionError::TooMuchData)?;
    }

    let input_sat = inputs.iter().map(|input| input.output.value.to_sat()).sum::<u64>();
    let offsets = inputs.iter().map(|input| input.offset).collect();
    let tx_ins = inputs
      .iter()
      .map(|input| TxIn {
        previous_output: input.outpoint,
        script_sig: ScriptBuf::new(),
        sequence: Sequence::MAX,
        witness: Witness::new(),
      })
      .collect::<Vec<_>>();

    let payment_sat = payments.iter().map(|payment| payment.1).sum::<u64>();
    let mut tx_outs = payments
      .iter()

      .collect::<Vec<_>>();
