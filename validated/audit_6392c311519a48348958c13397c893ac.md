**Reasoning:**

The claim conflates the rendered display text with the underlying selection mechanism. In `compare-branch-list-item.tsx`, `HighlightText` only affects the *visual* rendering of `branch.name` [1](#0-0) ; it never re-derives which branch is acted upon. The actual branch selection and merge/reset flow in `compare.tsx` operates on the `Branch` object reference passed via `item.branch`/`this.props.branch`, not on any string parsed back from the rendered DOM. For example, `onBranchItemClicked` receives the `Branch` object directly and immediately dispatches `executeCompare` with that object [2](#0-1) , and `onSelectionChanged` similarly stores the `Branch` object itself [3](#0-2) .

Since each list row is bound at render time to a specific `Branch` object (with its real `name` and `tip.sha`), a Unicode-confusable name only affects what a human perceives when reading the list — it cannot cause Desktop to internally conflate `release-1` and `release-2` as data, because the click/keyboard-selection handlers never re-parse the highlighted/rendered string back into a branch identity. The `HighlightText` component itself is a pure, generic text-splitting/highlighting utility with no branch-identity logic [4](#0-3) .

This reduces to a general Unicode homograph/confusable-rendering concern affecting any UI that displays untrusted branch names as text (same as terminal, GitHub.com, or any git tool), not a Desktop-specific flaw that causes silent corruption of what the user commits/merges through a broken security boundary. There is no reachable path here where the wrong `Branch` object gets merged/reset against due to this highlighting code — the user would need to genuinely misread two visually similar list entries, which falls into the excluded "social engineering" / no-broken-boundary category rather than a valid, unprivileged attacker-controlled data-path vulnerability.

```typescript
export const HighlightText: React.FunctionComponent<IHighlightTextProps> = ({
  text,
  highlight,
}) => (
  <span>
    {
      text
        .split('')
        .map((ch, i): [string, boolean] => [ch, highlight.includes(i)])
        .concat([['', false]])
        .reduce(
          (state, [ch, matched], i, arr) => {
            if (matched === state.matched && i < arr.length - 1) {
              state.str += ch
            } else {
              const Component = state.matched ? 'mark' : 'span'
              state.result.push(<Component key={i}>{state.str}</Component>)
              state.str = ch
              state.matched = matched
            }
            return state
          },
          {
            matched: false,
            str: '',
            result: new Array<React.ReactElement<any>>(),
          }
        ).result
    }
  </span>
)
```
