### Title
Missing HTTP Timeout on Alloy Contract Provider Causes Indefinite Hang in Deposit and Withdrawal Processing — (File: `core/src/citrea.rs`)

---

### Summary

`CitreaClient::new()` correctly sets a configurable timeout on both `jsonrpsee` `HttpClient` instances, but the Alloy `RootProvider` used for all EVM contract calls is created via `ProviderBuilder::new().on_http()` with no timeout. A non-responsive Citrea node causes every contract call through this provider to hang indefinitely, permanently blocking the bridge state-machine tasks that drive deposit finalization and withdrawal processing.

---

### Finding Description

In `CitreaClient::new()`, the two `jsonrpsee` clients are built with an explicit timeout:

```rust
// core/src/citrea.rs  lines 397-407
let client = HttpClientBuilder::default()
    .request_timeout(timeout.unwrap_or(Duration::from_secs(60)))
    .build(citrea_rpc_url)…;

let light_client_prover_client = HttpClientBuilder::default()
    .request_timeout(timeout.unwrap_or(Duration::from_secs(60)))
    .build(light_client_prover_url)…;
``` [1](#0-0) 

The Alloy provider, however, is created with no timeout at all:

```rust
// core/src/citrea.rs  lines 382-393
let provider = ProviderBuilder::new()
    .wallet(EthereumWallet::from(key))
    .on_http(citrea_rpc_url.clone());   // ← no reqwest timeout configured
``` [2](#0-1) 

This provider is stored in `contract` and is the transport for every Alloy contract call:

| Method | Call | Bridge Role |
|---|---|---|
| `collect_deposit_move_txids` | `contract.depositTxIds(…).call().await` in a loop | Deposit finalization |
| `collect_withdrawal_utxos` | `contract.withdrawalUTXOs(…).call().await` in a loop | Withdrawal processing |
| `check_nofn_correctness` | `contract.getAggregatedKey().call().await` | Operator/verifier startup |
| `get_logs` (→ `get_replacement_deposit_move_txids`) | `provider.get_logs(&filter).await` in a loop | Deposit replacement tracking | [3](#0-2) [4](#0-3) [5](#0-4) [6](#0-5) 

`on_http()` internally constructs a default `reqwest::Client`, which by default has **no connect or read timeout**. Any `.call().await` or `.get_logs().await` on a non-responsive endpoint will never return.

---

### Impact Explanation

The bridge state-machine automation tasks call `collect_deposit_move_txids` and `collect_withdrawal_utxos` on every synced L1 block to advance deposit and withdrawal state. If the Citrea node stops responding, these async calls block their Tokio task forever. No further deposits can be finalized and no further withdrawals can be initiated from that task. BTC deposited to the bridge UTXO is credited on L1 but cannot be credited on L2 (or vice versa for withdrawals), constituting a liveness failure with material fund impact. Recovery requires an operator to detect the hang and restart the service; there is no self-healing path in the code.

---

### Likelihood Explanation

The Citrea RPC endpoint is an external dependency. Network partitions, node overload, or a targeted DoS against the configured `citrea_rpc_url` are realistic scenarios on mainnet and testnet4. The inconsistency is already present in production code: the `jsonrpsee` path is protected; the Alloy path is not.

---

### Recommendation

Build a `reqwest::Client` with the same configurable timeout and pass it to the provider:

```rust
let reqwest_client = reqwest::ClientBuilder::new()
    .timeout(timeout.unwrap_or(Duration::from_secs(60)))
    .build()
    .wrap_err("Failed to build reqwest client")?;

let provider = ProviderBuilder::new()
    .wallet(EthereumWallet::from(key))
    .on_http_with_client(citrea_rpc_url.clone(), reqwest_client);
```

This mirrors the existing pattern used for the `jsonrpsee` clients and ensures all three HTTP transports share the same configurable timeout.

---

### Proof of Concept

1. Start Clementine with a `citrea_rpc_url` pointing to a host that accepts TCP connections but never sends an HTTP response (e.g., `nc -l 8545` with no output).
2. Trigger a deposit so the bitcoin syncer calls `CitreaClient::collect_deposit_move_txids`.
3. Observe that the state-machine task never returns from `contract.depositTxIds(U256::from(0)).call().await` — the future is pending indefinitely.
4. Confirm that the `jsonrpsee`-backed `get_light_client_proof` call on the same unresponsive host correctly times out after 60 seconds, demonstrating the inconsistency. [7](#0-6)

    async fn get_logs(
        &self,
        filter: Filter,
        from_height: u64,
        to_height: u64,
    ) -> Result<Vec<Log>, BridgeError> {
        let mut logs = vec![];

        let mut from_height = from_height;
        while from_height <= to_height {
            // Block num is 999 because limits are inclusive.
            let to_height = std::cmp::min(from_height + 999, to_height);
            tracing::debug!("Fetching logs from {} to {}", from_height, to_height);

            // Update filter with the new range.
            let filter = filter.clone();
            let filter = filter.from_block(BlockNumberOrTag::Number(from_height));
            let filter = filter.to_block(BlockNumberOrTag::Number(to_height));

            let logs_chunk = self
                .contract
                .provider()
                .get_logs(&filter)
                .await
                .wrap_err("Failed to get logs")?;
            logs.extend(logs_chunk);

            from_height = to_height + 1;
        }

        Ok(logs)
    }

    async fn collect_deposit_move_txids(
        &self,
        last_deposit_idx: Option<u32>,
        to_height: u64,
    ) -> Result<Vec<(u64, Txid)>, BridgeError> {
        let mut move_txids = vec![];

        let mut start_idx = match last_deposit_idx {
            Some(idx) => idx + 1,
            None => 0,
        };

        loop {
            let deposit_txid = self
                .contract
                .depositTxIds(U256::from(start_idx))
                .block(BlockId::Number(BlockNumberOrTag::Number(to_height)))
                .call()
                .await;
            match deposit_txid {
                Err(e) if e.to_string().contains("execution reverted") => {
                    tracing::trace!("Deposit txid not found for index, error: {:?}", e);
                    break;
                }
                Err(e) => return Err(e.into()),
                Ok(_) => {}
            }
            tracing::info!("Deposit txid found for index: {:?}", deposit_txid);

            let deposit_txid = deposit_txid.expect("Failed to get deposit txid");
            let move_txid = Txid::from_slice(deposit_txid._0.as_ref())
                .wrap_err("Failed to convert move txid to Txid")?;
            move_txids.push((start_idx as u64, move_txid));
            start_idx += 1;
        }
        Ok(move_txids)
    }

    async fn collect_withdrawal_utxos(
        &self,
        last_withdrawal_idx: Option<u32>,
        to_height: u64,
    ) -> Result<Vec<(u64, OutPoint)>, BridgeError> {
        let mut utxos = vec![];

        let mut start_idx = match last_withdrawal_idx {
            Some(idx) => idx + 1,
            None => 0,
        };

        loop {
            let withdrawal_utxo = self
                .contract
                .withdrawalUTXOs(U256::from(start_idx))
                .block(BlockId::Number(BlockNumberOrTag::Number(to_height)))
                .call()
                .await;
            match withdrawal_utxo {
                Err(e) if e.to_string().contains("execution reverted") => {
                    tracing::trace!("Withdrawal utxo not found for index, error: {:?}", e);
                    break;
                }
                Err(e) => return Err(e.into()),
                Ok(_) => {}
            }
            let withdrawal_utxo = withdrawal_utxo.expect("Failed to get withdrawal UTXO");
            let txid = withdrawal_utxo.txId.0;
            let txid =
                Txid::from_slice(txid.as_ref()).wrap_err("Failed to convert txid to Txid")?;
            let vout = withdrawal_utxo.outputId.0;
            let vout = u32::from_le_bytes(vout);
            let utxo = OutPoint { txid, vout };
            utxos.push((start_idx as u64, utxo));
            start_idx += 1;
        }
        Ok(utxos)
    }

    async fn check_nofn_correctness(
        &self,
        nofn_xonly_pk: XOnlyPublicKey,
    ) -> Result<(), BridgeError> {
        if std::env::var("DISABLE_NOFN_CHECK").is_ok() {
            return Ok(());
        }

        let contract_nofn_xonly_pk = self
            .contract
            .getAggregatedKey()
            .call()
            .await
            .wrap_err("Failed to get script prefix")?
            ._0;

        let contract_nofn_xonly_pk = XOnlyPublicKey::from_slice(contract_nofn_xonly_pk.as_ref())
            .wrap_err("Failed to convert citrea contract script nofn bytes to xonly pk")?;
        if contract_nofn_xonly_pk != nofn_xonly_pk {
            return Err(eyre::eyre!("Nofn of deposit does not match with citrea contract").into());
        }
        Ok(())
    }
