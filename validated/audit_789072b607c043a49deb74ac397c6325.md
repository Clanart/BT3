The mirror creation path (`create_new_mirror` in `chia/data_layer/data_layer_wallet.py`) never checks ownership of the target `launcher_id`/store, and `http_download` in `chia/data_layer/download_data.py` performs a plain `aiohttp` GET to `server_info.url` with zero host/IP filtering.

### Title
DataLayer mirror URLs are fetched via `http_download`/`fetch_and_validate` without any private-IP/hostname filtering, allowing SSRF against subscriber nodes - (File: chia/data_layer/download_data.py)

### Summary
Any wallet holding a small amount of XCH can publish an on-chain "mirror" entry for **any** DataLayer store (not just stores it owns) whose payload is an arbitrary attacker-controlled URL list. Any other node that subscribes to that store id will, during its normal sync loop, pick that URL from `get_available_servers_for_store` and issue an outbound HTTP GET to it via `http_download`, with no validation that the host is not a loopback/link-local/private/hex-encoded address. This is a direct SSRF analog to the Serendipity `serendipity_url_allowed()` bypass: the code trusts a user-supplied URL as-is before making a server-side request.

### Finding Description
`DataLayerWallet.create_new_mirror()` builds a coin with `memos=[[launcher_id, *urls]]` and never verifies the caller owns or controls `launcher_id`: [1](#0-0) 

The RPC-facing `DataLayer.add_mirror()` only checks the URL list is non-empty — no scheme/host validation at all: [2](#0-1) 

Any node's `update_subscriptions_from_wallet()` pulls these attacker-supplied URLs from the wallet's mirror records with no filtering and hands them to the data store as subscription server URLs: [3](#0-2) 

During periodic sync, `fetch_and_validate()` selects one of these `servers_info` entries and calls `insert_from_delta_file()` → `download_file()`: [4](#0-3) 

`download_file()`, when no plugin `downloader` is configured (the default path for plain HTTP mirrors), calls `http_download()` directly on `server_info.url`: [5](#0-4) 

`http_download()` performs a raw `aiohttp.ClientSession().get(server_info.url + "/" + filename, ...)` with no host resolution/allow-list check whatsoever — no `is_localhost`, `is_private`, or hex/IPv6/decimal-encoding normalization is applied, even though such helpers already exist elsewhere in the codebase (`chia/util/network.py::is_localhost`, `chia/util/ip_address.py::IPAddress.is_private`) but are never invoked here: [6](#0-5) [7](#0-6) 

Because Python's `ipaddress`/DNS resolution and the URL host are attacker chosen, any of the classic SSRF-filter-bypass encodings (decimal/hex/octal IPv4, IPv6-mapped IPv4, `[::ffff:127.0.0.1]`, link-local `169.254.169.254`, etc.) reach the outbound request unmodified since there is no filter to bypass — there is simply no filter present at all.

### Impact Explanation
Any Data Layer client node that subscribes to (or owns/tracks) a store for which an attacker has published a malicious mirror will have its own process issue outbound HTTP requests to attacker-chosen internal addresses (e.g. cloud metadata endpoints, internal admin services, loopback ports on the victim host). Because `create_new_mirror` does not restrict `launcher_id` to stores the caller owns, this is exploitable against any publicly-known store id by any wallet user willing to spend a small mirror-coin amount + fee. Repeated failures only feed into a per-server backoff counter (`server_misses_file`/`received_incorrect_file`), not into any blocking of the destination, so the request is always attempted at least once, and the response is briefly streamed to a local file before delta-file validation discards it on failure — enough to leak response timing/availability and, for services that act on GET, trigger side effects. This satisfies the "Data Layer client" reachable-actor category and produces the SSRF impact analogous to the referenced CVE.

### Likelihood Explanation
High feasibility: publishing a mirror requires only a standard wallet spend (no special permission), the store id can be any existing/public DataLayer store id, and the download path (`http_download`) is the default (no plugin configured) code path used by ordinary DataLayer installs. The vulnerability requires no cooperation from the store owner and no malicious peer/node capability beyond normal wallet + DataLayer RPC use.

### Recommendation
Before dereferencing a mirror/server URL in `http_download()` (and the plugin `handle_download`/`download` POST paths), resolve the hostname and reject the request if the resolved address is private, loopback, link-local, multicast, or otherwise reserved (reusing `chia.util.network.is_localhost` / `chia.util.ip_address.IPAddress.is_private`, applied after DNS resolution and after normalizing hex/octal/decimal IPv4 and IPv6-mapped forms). Additionally, consider validating/restricting the URL scheme (`http`/`https` only) and rejecting non-standard literal encodings at the point mirror URLs are stored (`add_mirror`) as defense in depth, though the authoritative check must happen at fetch time since URLs can also arrive via mirrors created before any client-side policy existed.

### Proof of Concept
1. Attacker wallet calls `dl_new_mirror` RPC (or `chia data add_mirror`) with an arbitrary, existing `store_id` (does not need to be attacker-owned) and `urls=["http://169.254.169.254"]` (or a hex/octal-encoded loopback like `http://0x7f000001/`), paying the mirror amount + fee: [8](#0-7) 
2. Once the mirror coin confirms on-chain, any node that has this store id tracked/subscribed picks it up via `coin_added()` in `DataLayerWallet`, recording it as an available server: [9](#0-8) 
3. On its next sync cycle, the victim node's `fetch_and_validate()` selects this URL and calls `http_download()`, causing the victim process to issue an outbound GET to `http://169.254.169.254/<delta-filename>` (or the hex-encoded loopback target) with no validation, as shown above.

```python
async def http_download(
    target_filename_path: Path,
    filename: str,
    proxy_url: str | None,
    server_info: ServerInfo,
    timeout: aiohttp.ClientTimeout,
    log: logging.Logger,
    max_delta_file_size: int,
) -> None:
    """
    Download a file from a server using aiohttp.
    Raises exceptions on errors
    """
    async with aiohttp.ClientSession() as session:
        headers = {"accept-encoding": "gzip"}
        async with session.get(
            server_info.url + "/" + filename,
            headers=headers,
            timeout=timeout,
            proxy=proxy_url,
        ) as resp:
            resp.raise_for_status()
            size = int(resp.headers.get("content-length", 0))
            max_delta_file_size_bytes = max_delta_file_size * 1024 * 1024
            if size > max_delta_file_size_bytes:
                raise MaxDeltaFileSizeExceededError(f"Maximum delta file size exceeded: {max_delta_file_size} MiB.")
            log.debug(f"Downloading delta file {filename}. Size {size} bytes.")
```
