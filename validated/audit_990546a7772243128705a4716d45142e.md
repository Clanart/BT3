### Title
`translate_signers` performs unmetered `Pubkey::create_program_address` hashing work proportional to MAX_SIGNERS×MAX_SEEDS, charged only the fixed `invoke_units` CPI cost - (File: program-runtime/src/cpi.rs)

### Summary
`cpi_common` charges a single fixed `invoke_units` (946 CU) compute cost before doing any work for a CPI, then calls `translate_signers`, which loops over up to `MAX_SIGNERS` (16) signer-seed sets, each with up to `MAX_SEEDS` seeds, calling `Pubkey::create_program_address` once per signer. [1](#0-0)  Unlike the standalone `sol_create_program_address`/`sol_try_find_program_address` syscalls, which explicitly charge `create_program_address_units` (1500 CU) per hash attempt via `invoke_context.compute_meter.consume_checked(cost)`, the CPI-embedded derivation path in `translate_signers` never consumes any compute for the `create_program_address` calls it performs. [2](#0-1) [3](#0-2) 

### Finding Description
`cpi_common` consumes `invoke_units` once at the top of the function, a fixed cost regardless of the CPI's actual arguments. [4](#0-3)  It then calls `translate_signers(caller_program_id, signers_seeds_addr, signers_seeds_len, invoke_context)`. [5](#0-4) 

Inside `translate_signers`, the function bounds `signers_seeds.len()` to `MAX_SIGNERS` (16) and each signer's `untranslated_seeds.len()` to `MAX_SEEDS`, then for every signer entry calls `Pubkey::create_program_address(&seeds_bytes, program_id)` — a SHA-256-based, on-curve-check hashing operation — with no compute charge for this work at all. [3](#0-2) 

Compare this to the standalone syscalls that expose the exact same primitive: `SyscallCreateProgramAddress` and `SyscallTryFindProgramAddress` both explicitly charge `create_program_address_units` (1500 CU, see `program-runtime/src/execution_budget.rs:211`) via `invoke_context.compute_meter.consume_checked(cost)` before doing the translation and hashing. [6](#0-5)  This demonstrates the codebase's intended pricing model: each `create_program_address` invocation should cost 1500 CU. The CPI signer-derivation path bypasses this pricing model entirely, only charging the fixed `invoke_units` (946 CU) for the whole CPI regardless of whether 0 or 16 signers with up to 16 max-length (32-byte) seeds each are supplied.

An unprivileged attacker can deploy an sBPF program that calls `invoke_signed` repeatedly (up to the nested-invoke/call limits) with the maximum `MAX_SIGNERS` × `MAX_SEEDS` seed arrays each with maximal seed lengths, forcing up to `MAX_SIGNERS` (16) `create_program_address` hash computations per CPI call at effectively zero marginal compute cost, compared to what the same work would cost if done via the direct `sol_create_program_address` syscall (16 × 1500 = 24,000 CU vs. 0 extra CU inside CPI). This is confirmed by the sbf-c test harness `TEST_CAP_SIGNERS`/`TEST_CAP_SEEDS`, which construct exactly the maximal 17-seed / 17-signer boundary cases used to probe `MAX_SIGNERS`/`MAX_SEEDS`. [7](#0-6) 

Existing guards (`MAX_SIGNERS`/`MAX_SEEDS`/`MAX_SEED_LEN` bounds checks) only prevent unbounded growth of the loop size — they cap the worst case at 16×16×32 bytes per CPI call — but they do not charge compute proportional to that capped-but-nonzero work, so the fixed `invoke_units` charge is undersized relative to the real hashing cost incurred.

### Impact Explanation
This is a compute-metering underpricing bug: a fixed-cost CPI (invoke_units) can trigger materially more real CPU work (up to 16 `create_program_address` calls, each involving SHA-256 over up to ~513 bytes of seed data plus an on-curve check) than its charged cost reflects. Repeated in a loop across many CPI calls in one transaction (bounded by `MAX_INSTRUCTION_TRACE_LENGTH` / call-depth limits), this allows a transaction to consume real validator CPU disproportionate to the compute units it's billed for — a "materially underpriced compute" finding matching the scoped invariant that "every syscall/CPI charges compute proportional to real cost."

### Likelihood Explanation
Fully attacker-controlled and requires no special privileges: the attacker only needs to deploy a program invoking `invoke_signed` with crafted `signers_seeds` arrays at the `MAX_SIGNERS`/`MAX_SEEDS` boundary with maximum-length seed byte slices, which is ordinary program bytecode and instruction data. The bug is deterministic and repeatable on every CPI call, and the boundary values (`MAX_SIGNERS = 16` at `program-runtime/src/cpi.rs:62`, `MAX_SEEDS`, `MAX_SEED_LEN`) are compile-time constants so a PoC/benchmark can exercise them precisely. [8](#0-7) 

### Recommendation
Charge `create_program_address_units` (or an equivalent proportional cost) inside `translate_signers` for each `Pubkey::create_program_address` invocation, mirroring what `SyscallCreateProgramAddress::rust` already does, so CPI signer derivation is priced the same as the standalone syscall:
```rust
// in translate_signers, before/around each create_program_address call
let cost = invoke_context.get_execution_cost().create_program_address_units;
invoke_context.compute_meter.consume_checked(cost)?;
```
This should be added per signer entry in the `.map(...)` closure at `program-runtime/src/cpi.rs:649-670` before calling `Pubkey::create_program_address`.

### Proof of Concept

```rust
#[test]
fn test_translate_signers_compute_cost_not_charged() {
    // Build a mock invoke_context with compute_meter set to a small budget,
    // e.g. equal to `invoke_units` only (DEFAULT_INVOCATION_COST = 946).
    // Construct signers_seeds with MAX_SIGNERS (16) entries, each with
    // MAX_SEEDS seeds of MAX_SEED_LEN (32) bytes (crafted to be valid,
    // off-curve derivable seeds).
    // Call translate_signers(...) directly (bypassing cpi_common's single
    // invoke_units charge) and assert:
    let remaining_before = invoke_context.compute_meter.remaining();
    let signers = translate_signers(&program_id, vm_addr, MAX_SIGNERS as u64, &invoke_context).unwrap();
    let remaining_after = invoke_context.compute_meter.remaining();
    // FAILING ASSERTION under current code: remaining_before == remaining_after
    // (no compute consumed for 16 create_program_address calls).
    // EXPECTED (after fix): remaining_before - remaining_after >=
    //     MAX_SIGNERS as u64 * invoke_context.get_execution_cost().create_program_address_units;
    assert!(remaining_before - remaining_after >=
        MAX_SIGNERS as u64 * invoke_context.get_execution_cost().create_program_address_units);
}
```
Additionally, an integration/benchmark test invoking `invoke_signed` in a loop (via the sbf-c `TEST_CAP_SIGNERS`/`TEST_CAP_SEEDS` harness already present) comparing wall-clock time and CU-consumed for 0-signer vs. 16-signer/max-seed invocations would show CU consumption stays flat (`invoke_units` only) while wall-clock time scales with signer/seed count, confirming the underpricing. declare_builtin_function!(
    /// Create a program address
    SyscallCreateProgramAddress,
    fn rust(
        invoke_context: &mut InvokeContext<'_, '_>,
        seeds_addr: u64,
        seeds_len: u64,
        program_id_addr: u64,
        address_addr: u64,
        _arg5: u64,
    ) -> Result<u64, Error> {
        let cost = invoke_context
            .get_execution_cost()
            .create_program_address_units;
        invoke_context.compute_meter.consume_checked(cost)?;

        let check_aligned = invoke_context.get_check_aligned();
        let memory_mapping = invoke_context.memory_contexts.memory_mapping_mut()?;
        let (seeds, program_id) = translate_and_check_program_address_inputs(
            seeds_addr,
            seeds_len,
            program_id_addr,
            memory_mapping,
            check_aligned,
        )?;

        let Ok(new_address) = Pubkey::create_program_address(&seeds, program_id) else {
            return Ok(1);
        };
        translate_mut!(
            memory_mapping,
            check_aligned,
            let address: (&mut [MaybeUninit<u8>]) = map(address_addr, std::mem::size_of::<Pubkey>() as u64)?;
        );
        address.write_copy_of_slice(new_address.as_ref());
        Ok(0)
    }
