### Title
Scanner reports the same output multiple times and `SignableTransaction::new` accepts duplicate inputs, enabling double-counted funds and signing of consensus-invalid transactions - (File: networks/bitcoin/src/wallet/mod.rs)

### Summary
Analogous to `settle()` being callable multiple times with no "already settled" flag (minting the NFT twice), Serai's Bitcoin wallet `Scanner` keeps no record of previously reported outputs, and `SignableTransaction::new` performs no duplicate-input check. An output obtained from one real deposit can be reported and consumed more than once, causing the same funds to be counted multiple times and a transaction spending the same outpoint twice to be signed.

### Finding Description
`Scanner::scan_transaction` iterates `tx.output` and pushes a `ReceivedOutput` for every `script_pubkey` match, with no state recording which outpoints have already been returned. `scan_block` simply concatenates `scan_transaction` over all `block.txdata`. There is no equivalent of an `auction_settled` boolean: rescanning a block, or scanning a transaction that also appears in a scanned block, yields duplicate `ReceivedOutput`s with identical outpoints. The test even exercises both paths on the same coinbase transaction (`scanner.scan_block(&block)` and `scanner.scan_transaction(&block.txdata[0])`), showing overlapping scans are a natural usage pattern. [1](#0-0) [2](#0-1) 

`SignableTransaction::new` then trusts the `inputs` vector completely: it sums `input.output.value` into `input_sat` and builds one `TxIn` per entry with no check that `previous_output` outpoints are distinct. A duplicated `ReceivedOutput` double-counts its value in `input_sat`, so the `NotEnoughFunds` check passes on inflated funds and the change amount is computed from money that exists only once on-chain. [3](#0-2) 

The resulting transaction is signed normally: `TransactionSignMachine::sign` produces a per-input Taproot key-spend signature over `Prevouts::All`, so the duplicated input contributes a duplicate `TxIn`, making the transaction consensus-invalid while still consuming a full threshold signing session. [4](#0-3) 

### Impact Explanation
An unprivileged party who sends a Bitcoin transaction to a registered scanner script controls the `ReceivedOutput`s produced. If that output is surfaced twice by overlapping scans (re-scan after restart, `scan_block` plus an explicit `scan_transaction`, or reorg-driven rescanning), downstream accounting credits the deposit twice — funds reported received that are not backed by distinct UTXOs. If both copies are fed to `SignableTransaction::new`, the multisig signs an unintended transaction (one spending the same outpoint twice), wasting a signing round and producing a permanently unbroadcastable transaction whose fee/change math was derived from phantom input value.

### Likelihood Explanation
The defect requires an output to be scanned twice, which the stateless `Scanner` permits by design — nothing in `scan_transaction` or `scan_block` prevents it, and the library-level deduplication that would catch it (the `panic!("scanned an output multiple times")` seen-tracking) lives in the out-of-scope processor layer, not in the in-scope wallet code. Any integrator relying solely on this library inherits the double-counting. `SignableTransaction::new` similarly has no guard, so a single duplicated `ReceivedOutput` silently corrupts the funded amount.

### Recommendation
Track reported outpoints inside `Scanner` (a `HashSet<OutPoint>` populated by `scan_transaction` and consulted to skip already-reported outputs), mirroring the `auction_settled` flag. Additionally, in `SignableTransaction::new`, reject `inputs` containing duplicate `outpoint` values before computing `input_sat` and building `tx_ins`, e.g. by inserting each `input.outpoint` into a `HashSet` and erroring on reinsertion. This makes the scan→consume pipeline idempotent at the library boundary rather than relying on every caller to deduplicate.

  pub fn scan_transaction(&self, tx: &Transaction) -> Vec<ReceivedOutput> {
    let mut res = Vec::new();
    for (vout, output) in tx.output.iter().enumerate() {
      // If the vout index exceeds 2**32, stop scanning outputs
      let Ok(vout) = u32::try_from(vout) else { break };

      if let Some(offset) = self.scripts.get(&output.script_pubkey) {
        res.push(ReceivedOutput {
          offset: *offset,
          output: output.clone(),
          outpoint: OutPoint::new(tx.compute_txid(), vout),
        });
      }
    }
    res
  }

  /// Scan a block.
  ///
  /// This will also scan the coinbase transaction which is bound by maturity. If received outputs
  /// must be immediately spendable, a post-processing pass is needed to remove those outputs.
  /// Alternatively, scan_transaction can be called on `block.txdata[1 ..]`.
  pub fn scan_block(&self, block: &Block) -> Vec<ReceivedOutput> {
    let mut res = Vec::new();
    for tx in &block.txdata {
      res.extend(self.scan_transaction(tx));
    }
    res
  }
