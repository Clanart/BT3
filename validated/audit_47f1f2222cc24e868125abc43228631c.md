## Title
First-ever `StateMachineUpdated` event for a state machine overpays the relayer reward because `previous_commitment_height` defaults to `0` instead of the state machine's actual starting height - (File: `modules/pallets/consensus-incentives/src/impls.rs`)

## Summary
`pallet-consensus-incentives::calculate_reward` pays a relayer `blocks_as_balance * block_cost` BRIDGE-equivalent for advancing a state machine's light client. `blocks` is computed as `latest_height - baseline`, where `baseline` falls back to `previous_commitment_height`, which itself falls back to `0` when no `PreviousStateMachineHeight` entry exists yet. For any state machine's very first consensus update (or any state machine that is freshly registered with a non-zero `StateMachinesCostPerBlock`), this makes `baseline = 0`, so the relayer is paid for the entire historical height range (`0..latest_height`) instead of just the actual number of new blocks proven. This is the same broken-invariant class as the reported `ERC4626i.claimProtocolFees` bug: an uninitialized "last accounted" watermark defaulting to `0` instead of to the real starting point, inflating an amount-owed calculation on the first claim.

## Finding Description
`calculate_reward` in `modules/pallets/consensus-incentives/src/impls.rs`:

```rust
let previous_height =
    host.previous_commitment_height(state_machine_id.clone()).unwrap_or_default();
let baseline = LastRewardedHeight::<T>::get(state_machine_id).unwrap_or(previous_height);
let blocks = latest_height.saturating_sub(baseline);
let reward = blocks_as_balance.saturating_mul(block_cost);
``` [1](#0-0) 

`previous_commitment_height` reads `PreviousStateMachineHeight::<T>::get(id)`, which is only ever populated inside `store_latest_commitment_height` as a side effect of a *prior* update:
```rust
fn store_latest_commitment_height(&self, height: StateMachineHeight) -> Result<(), Error> {
    let previous_height = LatestStateMachineHeight::<T>::get(height.id).unwrap_or_default();
    PreviousStateMachineHeight::<T>::insert(height.id, previous_height);
    LatestStateMachineHeight::<T>::insert(height.id, height.height);
    Ok(())
}
``` [2](#0-1) [3](#0-2) 

For a state machine that has never had a commitment stored before (freshly onboarded, or the very first accepted consensus proof for it), `LatestStateMachineHeight` and hence `PreviousStateMachineHeight` are both absent, so `previous_commitment_height` returns `None` → `unwrap_or_default()` yields `0`. Combined with `LastRewardedHeight` also being absent (`unwrap_or(previous_height)` → `0`), `baseline = 0` regardless of what height the light client actually started tracking from.

The existing test confirms this is real behavior, not a hypothetical: in `test_incentivize_relayer`, the very first consensus message processed for a brand-new `state_machine_id` yields a reward of `4200` at `block_cost = 100`, i.e. `blocks = 42`, even though this is the *first* update ever processed for that state machine — there is no prior "42 blocks of unrewarded progress" that actually needs paying, the light client height simply started at 42 in the mock setup. [4](#0-3) 

This is structurally identical to the reported bug: a "last accounted" storage value defaults to `0` on first use, and the elapsed/blocks metric is computed against that false floor of `0` rather than the state machine's real initial height, producing a reward many multiples larger than intended and paid straight out of the treasury. [5](#0-4) 

## Impact Explanation
The reward is transferred unconditionally from `T::TreasuryAccount` to the relayer that submitted the qualifying consensus message, with no cap tied to actual new work:
```rust
T::Currency::transfer(
    &T::TreasuryAccount::get().into_account_truncating(),
    &relayer_account,
    reward,
    Preservation::Expendable,
)
``` [6](#0-5) 

Because `blocks` for a freshly onboarded (or never-before-rewarded) state machine equals the *entire* `latest_height`, and `block_cost` is a governance-configured per-block price, the payout scales with however high the light client height already is at onboarding time (which for a long-running external chain can be very large). This is a direct, unbounded loss of treasury funds triggered by ordinary relayer activity — no malicious relayer, prover, or governance actor is required; any relayer that happens to submit the qualifying proof collects the inflated reward.

## Likelihood Explanation
This fires on the ordinary, expected code path — the very first `StateMachineUpdated` event recorded for any state machine that has `StateMachinesCostPerBlock` configured. Every time governance onboards a new state machine (or re-enables cost-per-block accounting for one that has no prior watermark), the first honest relayer to submit a valid consensus proof triggers the overpayment automatically. `on_executed` runs this logic for every consensus message batch without any first-time-guard. [7](#0-6) 

## Recommendation
When neither `LastRewardedHeight` nor a genuine `PreviousStateMachineHeight` exists for a state machine, the baseline should be set to the height at which the state machine was first registered/tracked (or to `latest_height` itself, paying zero on the bootstrap update) rather than to `0`. Concretely, distinguish "no previous height recorded" from "previous height is 0" so `calculate_reward` never treats an untracked chain's entire historical height as newly-delivered blocks.

## Proof of Concept
1. Governance calls `update_cost_per_block(state_machine_id, block_cost)` for a state machine that has an existing, already-advanced light client height `H` (e.g., a beefy/GRANDPA client initialized off-chain at height `H = 1_000_000`), but has no `LastRewardedHeight` or `PreviousStateMachineHeight` entry yet (fresh pallet storage / newly enabled incentive).
2. Any relayer submits the first valid consensus proof advancing the state machine to `H+1`.
3. `on_executed` → `process_message` → `calculate_reward` computes `previous_height = host.previous_commitment_height(...).unwrap_or_default() = 0`, `baseline = 0`, `blocks = (H+1) - 0 = H+1`.
4. The relayer is paid `(H+1) * block_cost` from the treasury for a single proof submission, instead of `1 * block_cost` for the single new block actually delivered — demonstrated at small scale by `test_incentivize_relayer`, which pays `42 * block_cost` on the very first message for a freshly configured state machine. [8](#0-7)

	fn process_message(
		state_machine_height: StateMachineHeight,
		state_machine_id: StateMachineId,
		relayer_account: T::AccountId,
	) -> Result<(), Error<T>> {
		if let Some(block_cost) = StateMachinesCostPerBlock::<T>::get(state_machine_id) {
			let reward = Self::calculate_reward(&state_machine_id, block_cost)?;

			if reward.is_zero() {
				return Ok(());
			}

			T::Currency::transfer(
				&T::TreasuryAccount::get().into_account_truncating(),
				&relayer_account,
				reward,
				Preservation::Expendable,
			)
			.map_err(|_| Error::<T>::RewardTransferFailed)?;

			Self::deposit_event(Event::<T>::RelayerRewarded {
				relayer: relayer_account.clone(),
				amount: reward,
				state_machine_height,
			});

			T::ReputationAsset::mint_into(&relayer_account, reward.saturated_into())
				.map_err(|_| Error::<T>::ReputationMintFailed)?;

			LastRewardedHeight::<T>::mutate(state_machine_id, |watermark| {
				*watermark = Some(watermark.unwrap_or_default().max(state_machine_height.height));
			});
		}
		Ok(())
	}

	fn on_executed(
		messages: Vec<MessageWithWeight>,
		events: Vec<IsmpEvent>,
	) -> DispatchResultWithPostInfo {
		let maybe_relayer_account = messages.get(0).and_then(|first_message| {
			if let Message::Consensus(consensus_msg) = &first_message.message {
				let data = sp_io::hashing::keccak_256(&consensus_msg.consensus_proof);
				Signature::decode(&mut &consensus_msg.signer[..])
					.ok()
					.and_then(|sig| sig.verify_and_get_sr25519_pubkey(&data, None).ok())
					.map(|pub_key| pub_key.into())
			} else {
				None::<[u8; 32]>
			}
		});

		if let Some(relayer_account) = maybe_relayer_account {
			// When a batch contains multiple `StateMachineUpdated` events for the
			// same `state_machine_id` (sequential consensus updates for the same
			// chain), `calculate_reward` reads the same persisted
			// `(latest_commitment_height, previous_commitment_height)` pair on
			// every iteration and pays the same block-span reward N times.
			// Collapse the per-state-machine event stream to the single highest
			// `latest_height` so each state machine receives one reward per
			// batch, sized by the actual span of its commitment advance.
			let mut highest_per_state_machine: BTreeMap<StateMachineId, u64> = BTreeMap::new();
			for event in events {
				if let IsmpEvent::StateMachineUpdated(update) = event {
					highest_per_state_machine
						.entry(update.state_machine_id)
						.and_modify(|h| {
							if update.latest_height > *h {
								*h = update.latest_height;
							}
						})
						.or_insert(update.latest_height);
				}
			}

			for (state_machine_id, latest_height) in highest_per_state_machine {
				let state_machine_height =
					StateMachineHeight { id: state_machine_id.clone(), height: latest_height };

				let _ = Self::process_message(
					state_machine_height,
					state_machine_id,
					relayer_account.clone().into(),
				);
			}
		}

		// Return with actual weight information
		// We use Pays::No to indicate that someone (the message sender) doesn't pay for this
		// operation, though we're using this mechanism to reward relayers rather than charge fees
		Ok(PostDispatchInfo { actual_weight: None, pays_fee: Pays::No })
	}
