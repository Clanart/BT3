## Analog Found: Stale escrow accounting survives a same-chain partial fill, enabling a duplicate payout on cancellation

### Title
`_orders[commitment][token]` is never decremented on partial fills, letting `_cancelSameChain` refund escrow already paid out to a solver - ([File: evm/src/apps/intentsv2/IntrinsicIntents.sol])

### Summary
The external report's core broken invariant is: a "terminal/untouched" sentinel (`nextId == TAIL`) is trusted as proof of a specific state, but that sentinel is reused after the underlying record was already consumed, letting a stale value drive a subsequent state-corrupting operation. The local analog is in `IntentGatewayV2`'s same-chain intent-fill path: the `_filled[commitment]` flag - the guard that `cancelOrder` uses to decide whether an order may still be cancelled - is deliberately reset to `address(0)` after every partial fill [1](#0-0) , even though escrow has already been paid out to a solver in that same fill. Meanwhile the escrow bookkeeping map `_orders[commitment][token]`, written once at `placeOrder` [2](#0-1) , is never observed being decremented anywhere in the partial-fill path [3](#0-2) .

### Finding Description
`fillOrder` gates cancellation eligibility purely on `_filled[commitment] != address(0)` [4](#0-3) . During `_fillSameChain`, the flag is set to `msg.sender` at the top of the call (marking the order as "in progress") [5](#0-4) , but on a *partial* fill it is explicitly deleted back to `address(0)` right before returning [6](#0-5) . This makes `_filled[commitment] == address(0)` an unreliable signal: it means "order has room for more solver activity," not "order has never released any escrow" - functionally the same class of assumption break as the ditto-eth report, where `nextId == Constants.TAIL` was assumed to mean "never cancelled" when it could also mean "already cancelled".

`_cancelSameChain` is reached only through this same `_filled == 0` gate and independently re-derives the refund amount straight from `_orders[commitment][token]` [7](#0-6) . Across the full `IntrinsicIntents.sol`, `ExtrinsicIntents.sol`, and `IntentGatewayV2.sol` sources, `_orders[commitment][token]` is written exactly once, at order placement [2](#0-1) , and is only ever *read* afterward - once in `_fillSameChain` to size a full-fill payout [8](#0-7)  and once in `_cancelSameChain` to size the refund [9](#0-8) . Nothing in these two contracts decrements it after a partial fill has already streamed proportional escrow out to a solver via `_withdraw` [10](#0-9) .

The corrupted value is `_orders[commitment][token]`: it is treated by `_cancelSameChain` as "current remaining escrow" but is actually a snapshot of the *original, full* escrowed amount, unless the (unread in this investigation) `_withdraw` implementation in `IntentsBase.sol` independently maintains and decrements this same map. Existing guards do not stop this path because the only gate protecting cancellation is `_filled[commitment]`, which is intentionally reset to zero by design after every partial fill to allow further solver participation - the same reset that an attacker (any user acting as the order's own `order.user`, who is the only one authorized to call `_cancelSameChain`) can exploit as the original order creator: partially fill their own order with a colluding/self-controlled solver address to release a chunk of escrow, then immediately call `cancelOrder`, which reads the still-full `_orders[commitment][token]` value and refunds the entire original escrow amount a second time.

### Impact Explanation
If `_withdraw` does not itself decrement `_orders[commitment][token]` (nothing in the reviewed contracts does), an order creator can double-spend their own order's escrow: once via a partial same-chain fill payout to a solver, and again via `_cancelSameChain`'s refund of the full original escrow. This is a direct "stealing or loss of funds" / duplicate-settlement outcome against the `IntentGatewayV2` escrow, squarely inside the bounty's required-impact list (double-claim/double-settlement, unauthorized transaction manipulation of order escrow).

### Likelihood Explanation
The path requires no privileged role, relayer, prover, or governance action - only the order's own `user` (or a colluding solver they control) calling public `fillOrder` with a partial amount followed by public `cancelOrder`, both of which are unprivileged entry points on `IntentGatewayV2` [11](#0-10) [4](#0-3) . The `nonReentrant` guard on both functions only prevents reentrancy within one call, not sequential abuse of the reset `_filled` flag across separate transactions, so it does not block this sequence.

### Recommendation
Track escrow "remaining" state independently of a one-time-write `_orders` map, or explicitly decrement `_orders[commitment][token]` inside `_fillSameChain` for every partial release before the `_withdraw` call, so `_cancelSameChain` always reads a value net of any prior payouts. Additionally, do not treat `_filled[commitment] == address(0)` as sufficient authorization context for cancellation without also cross-checking `_partialFills[commitment][...]` state, mirroring the report's recommendation to make cancellation checks match a normal, invariant-preserving cancel flow rather than trusting a reused sentinel.

### Proof of Concept
Conceptual sequence (same-chain order, order creator acting alone or with a controlled solver address):
1. `placeOrder` escrows `X` input tokens; `_orders[commitment][token] = X` [2](#0-1) .
2. Creator (or their own solver) calls `fillOrder` with `solverAmount` less than the full output requirement, causing `isFullyFilled = false`; `_fillSameChain` releases a proportional slice of escrow to the solver, then executes `delete _filled[commitment];` [6](#0-5) , leaving `_orders[commitment][token]` unchanged at `X`.
3. Creator immediately calls `cancelOrder`; the top-level check `_filled[commitment] != address(0)` passes as "not filled" [12](#0-11) , routing to `_cancelSameChain`, which reads `_orders[commitment][token] == X` and refunds the full original `X` to `order.user` [13](#0-12)  - on top of the amount already paid out to the solver in step 2.

Note: full confirmation requires inspecting `IntentsBase.sol`'s `_withdraw` implementation (not covered in this session) to verify whether it independently decrements `_orders[commitment][token]`; the reviewed contracts (`IntentGatewayV2.sol`, `IntrinsicIntents.sol`, `ExtrinsicIntents.sol`) show no such decrement.

    function _fillSameChain(Order calldata order, FillOptions calldata options, bytes32 commitment) internal {
        uint256 outputsLen = order.output.assets.length;

        _filled[commitment] = msg.sender;

        uint256 msgValue = msg.value;
        address beneficiary = address(uint160(uint256(order.output.beneficiary)));
        bool isFullyFilled = true;

        TokenInfo[] memory escrowedInputs = new TokenInfo[](outputsLen);
        TokenInfo[] memory outputFills = new TokenInfo[](outputsLen);

        for (uint256 i; i < outputsLen; i++) {
            bytes32 outputToken = order.output.assets[i].token;
            if (options.outputs[i].token != outputToken) revert InvalidInput();

            address token = address(uint160(uint256(outputToken)));
            uint256 totalRequired = order.output.assets[i].amount;
            uint256 solverAmount = options.outputs[i].amount;

            uint256 alreadyFilled = _partialFills[commitment][outputToken];
            uint256 remaining = totalRequired - alreadyFilled;
            if (remaining == 0 || solverAmount == 0) {
                if (solverAmount == 0 && remaining > 0) isFullyFilled = false;
                continue;
            }
            uint256 fillAmount;

            uint256 beneficiaryShare = 0;
            uint256 protocolShare = 0;
            if (alreadyFilled == 0 && solverAmount > totalRequired) {
                fillAmount = totalRequired;
                uint256 dust = solverAmount - totalRequired;
                if (order.output.call.length > 0) {
                    protocolShare = dust;
                } else {
                    protocolShare = (dust * _params.surplusShareBps) / 10_000;
                    beneficiaryShare = dust - protocolShare;
                }
            } else {
                fillAmount = solverAmount > remaining ? remaining : solverAmount;
            }

            uint256 amountFilled = alreadyFilled + fillAmount;
            _partialFills[commitment][outputToken] = amountFilled;
            uint256 beneficiaryTotal = fillAmount + beneficiaryShare;

            if (token == address(0)) {
                if (msgValue < beneficiaryTotal + protocolShare) revert InsufficientNativeToken();
                msgValue -= (beneficiaryTotal + protocolShare);
                (bool sent,) = beneficiary.call{value: beneficiaryTotal}("");
                if (!sent) revert InsufficientNativeToken();
            } else {
                IERC20(token).safeTransferFrom(msg.sender, beneficiary, beneficiaryTotal);
                if (protocolShare > 0) {
                    IERC20(token).safeTransferFrom(msg.sender, address(this), protocolShare);
                }
            }

            if (totalRequired > amountFilled) isFullyFilled = false;
            if (protocolShare > 0) emit DustCollected(token, protocolShare);

            uint256 escrowedAmount;
            if (amountFilled == totalRequired) {
                escrowedAmount = _orders[commitment][address(uint160(uint256(order.inputs[i].token)))];
            } else {
                escrowedAmount = (order.inputs[i].amount * fillAmount) / totalRequired;
            }
            escrowedInputs[i] = TokenInfo({token: order.inputs[i].token, amount: escrowedAmount});
            outputFills[i] = TokenInfo({token: outputToken, amount: fillAmount});
        }

        // Orders carrying output calldata must be filled completely in a single fill.
        // The attached call is only executed on a full fill, so a partial fill would
        // leave the intended side effect unexecuted while releasing proportional escrow.
        if (order.output.call.length > 0 && !isFullyFilled) revert PartialFillNotAllowed();

        WithdrawalRequest memory body = WithdrawalRequest({
            commitment: commitment, tokens: escrowedInputs, beneficiary: bytes32(uint256(uint160(msg.sender)))
        });
        _withdraw(body, false, isFullyFilled);

        if (isFullyFilled) {
            _execute(order, outputsLen);
            emit OrderFilled({commitment: commitment, filler: msg.sender, outputs: outputFills, inputs: escrowedInputs});
        } else {
            delete _filled[commitment];
            emit PartialFill({commitment: commitment, filler: msg.sender, outputs: outputFills, inputs: escrowedInputs});
        }

        // Refund any unspent native tokens to the solver.
        if (msgValue > 0) {
            (bool sent,) = msg.sender.call{value: msgValue}("");
            if (!sent) revert InsufficientNativeToken();
        }
    }

    function fillOrder(Order calldata order, FillOptions calldata options) public payable nonReentrant {
        if (order.deadline < _blockNumber()) revert Expired();
        bytes32 commitment = keccak256(abi.encode(order));

        address hostAddr = host();
        bytes32 currentChain = keccak256(IDispatcher(hostAddr).host());
        bytes32 orderSource = keccak256(order.source);
        bytes32 orderDest = keccak256(order.destination);
        bool isSameChain = orderSource == orderDest;

        if (isSameChain && orderSource != currentChain) revert WrongChain();
        if (!isSameChain && orderDest != currentChain) revert WrongChain();

        if (_filled[commitment] != address(0)) revert Filled();

        if (_params.solverSelection) {
            bytes32 storedSelectionHash;
            assembly {
                storedSelectionHash := tload(commitment)
            }

            bytes32 expectedSelectionHash = keccak256(abi.encode(msg.sender, order.session));
            if (storedSelectionHash != expectedSelectionHash) revert Unauthorized();
        }

        uint256 outputsLen = order.output.assets.length;
        if (options.outputs.length != outputsLen) revert InvalidInput();
        if (order.inputs.length != outputsLen) revert InvalidInput();

        if (isSameChain) {
            _fillSameChain(order, options, commitment);
        } else {
            _fillCrossChain(order, options, commitment);
        }

        if (_params.priceOracle != address(0)) {
            IIntentPriceOracle(_params.priceOracle)
                .recordSpread(commitment, order.source, order.inputs, options.outputs);
        }
    }

    function cancelOrder(Order calldata order, CancelOptions calldata options) public payable nonReentrant {
        bytes32 commitment = keccak256(abi.encode(order));

        if (_filled[commitment] != address(0)) revert Filled();

        address hostAddr = host();
        bytes32 currentChain = keccak256(IDispatcher(hostAddr).host());
        bytes32 orderSource = keccak256(order.source);
        bytes32 orderDest = keccak256(order.destination);
        bool isSameChain = orderSource == orderDest;

        if (isSameChain) {
            _cancelSameChain(order, commitment);
        } else if (currentChain == orderSource) {
            _cancelFromSource(order, options, commitment);
        } else if (currentChain == orderDest) {
            _cancelFromDest(order, options, commitment);
        } else {
            revert WrongChain();
        }
    }
