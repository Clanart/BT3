## Analog Found: Data Race in `CMessage::composite_fields` Lazy Map Initialization/Access (Python C Extension, Free-Threaded Build)

### Title
Unsynchronized Concurrent Access to `CMessage::composite_fields` Lazy Map Causes Data Race / Undefined Behavior in Free-Threaded Python Protobuf Extension - (File: `python/google/protobuf/pyext/message.cc`)

### Summary
The Juju finding's failed invariant is: a plain, unsynchronized map (`userTokens`) is read, written, and deleted from multiple goroutines concurrently, causing runtime crashes and TOCTOU token reuse. The closest verified analog in this protobuf checkout is the `composite_fields` field of `CMessage` — a lazily-initialized `PyWeakValueMap` (`CompositeFieldsMap`) that caches Python wrapper objects for submessage/repeated/map fields — which is read via `TryGet()` and written via `Get()->TrySet()` in `cmessage::GetFieldValue` and `cmessage::SetCompositeField` with no lock, mutex, or atomic protecting the lazy-allocation and insertion path.

### Finding Description
`CMessage` stores `LazyUniquePtr<CompositeFieldsMap> composite_fields;` [1](#0-0) . `GetFieldValue` first probes the map non-atomically with `TryGet()`, and if the field isn't cached, builds a new container object and stores it via `SetCompositeField`, which calls `self->composite_fields.Get()->TrySet(field, value)` — `Get()` lazily allocates the underlying map object if it doesn't exist yet [2](#0-1) , [3](#0-2) . `ExtensionDict::subscript` follows the identical unsynchronized `Get()`/`TrySet()` pattern for extension fields [4](#0-3) .

Under the classic GIL-protected CPython build this race window is closed because the interpreter serializes bytecode/C-extension execution. However, the codebase now ships an explicit regression test, `testConcurrentGetFieldValueRace`, inside a `FreeThreadingTest` test class, whose docstring states verbatim: *"Reproduces a data race in GetFieldValue due to lazy initialization"* and *"This access triggers GetFieldValue and lazy initialization of the composite_fields map in CMessage"* [5](#0-4) . This confirms the maintainers are aware this exact map is unsafe under the free-threaded (no-GIL) CPython build, and that concurrent attribute access — e.g. two threads simultaneously reading `msg.optional_nested_message` on the same parsed message object — races on the lazy pointer allocation and the underlying `PyWeakValueMap`'s insert/lookup, exactly mirroring Juju's unsynchronized `userTokens[token]` read/write/delete pattern.

### Impact Explanation
Attacker/exposure model: an application parses one bounded Protobuf message via the standard public API (`Message.FromString`/`ParseFromString`) and then, per common server patterns (e.g., request handlers, worker pools), multiple threads read fields (submessages, repeated fields, map fields, extensions) off that single parsed message concurrently. On a free-threaded CPython build this triggers concurrent, unsynchronized mutation of `composite_fields`: two threads can race on the lazy-allocation of the `PyWeakValueMap`, or race on concurrent `TrySet`/`Get` calls into the same map, corrupting the map's internal state. Because this is native C++ code (not Go), the consequence is not merely a controlled runtime panic as in Juju — it is undefined behavior in a C++ container, which can manifest as memory corruption, use-after-free, or a hard crash (segfault) of the host process, and could yield inconsistent/duplicated wrapper objects for the same field (an analog to Juju's "duplicate acceptance" issue, since two threads could each construct and cache distinct Python objects for the same underlying field before either write commits).

### Likelihood Explanation
This is not a hypothetical or forced analog — it is proven by an existing test the maintainers wrote specifically to reproduce the race with a `threading.Barrier` to force worst-case concurrent timing [6](#0-5) . The trigger requires no malicious payload content (any parsed message with a message/repeated/map/extension field suffices) — only ordinary concurrent field access from application threads, which is a realistic pattern for servers holding a shared parsed message across worker threads. The blocking condition is that it is only reachable on CPython's free-threaded (`--disable-gil`/PEP 703) build; on the standard GIL build the race window does not open. Given free-threaded Python is an increasingly adopted (though still experimental) deployment target, this keeps the finding at Medium severity, consistent with the original report's CVSS band.

### Recommendation
Protect the lazy allocation and map mutation of `composite_fields` (and the analogous `child_submessages` `SubMessagesMap`, and `ExtensionDict`'s use of `parent->composite_fields`) with a per-`CMessage` mutex or an atomic compare-and-swap for the lazy pointer, and make `PyWeakValueMap::TrySet`/`Get` internally thread-safe (e.g., via a lock or lock-free structure) whenever the interpreter is built without the GIL. Alternatively, gate lazy cache population behind `Py_BEGIN_CRITICAL_SECTION`/`Py_END_CRITICAL_SECTION` (the CPython 3.13+ per-object locking primitive designed exactly for this free-threading migration pattern).

### Proof of Concept
The existing repository test is itself the minimal reproduction:
```python
# python/google/protobuf/internal/thread_safe_test.py (FreeThreadingTest.testConcurrentGetFieldValueRace)
def AccessFields(msg, barrier):
    barrier.wait()
    _ = msg.optional_nested_message  # triggers GetFieldValue + lazy init of composite_fields

msg = unittest_proto3_pb2.TestAllTypes()
barrier = threading.Barrier(10)
threads = [threading.Thread(target=AccessFields, args=(msg, barrier)) for _ in range(10)]
for t in threads: t.start()
for t in threads: t.join()
```
Run under a `--disable-gil` (free-threaded) CPython build with the C++ (`upb`/`pyext`) implementation, repeated iterations of this pattern race on `self->composite_fields.Get()->TrySet(...)` in `cmessage::GetFieldValue`/`SetCompositeField` [7](#0-6) , which the test's own docstring confirms is a data race, not merely a theoretical one.

**Uncertainty note**: I was unable to fetch the implementation of `LazyUniquePtr::Get()`/`TryGet()` and `PyWeakValueMap::TrySet()`/`Get()` themselves within the available tool budget, so I cannot show the exact non-atomic instruction sequence (e.g., whether `Get()` does a plain `if (!ptr) ptr = new Map()` without CAS). The existence, naming, and docstring of the dedicated `FreeThreadingTest.testConcurrentGetFieldValueRace` test, however, is direct evidence from the maintainers that this exact code path is a known, reproducible race condition.

PyObject* GetFieldValue(CMessage* self,
                        const FieldDescriptor* field_descriptor) {
  if (CMessage::CompositeFieldsMap* fields = self->composite_fields.TryGet();
      fields != nullptr) {
    if (PyObject* value = fields->Get(field_descriptor, nullptr)) {
      return value;
    }
  }

  const Descriptor* message_descriptor =
      (reinterpret_cast<CMessageClass*>(Py_TYPE(self)))->message_descriptor;
  // We might've run into a descriptor pool mismatch.
  // In that case, we can update the field descriptor directly in the case
  // of a direct match.
  if (message_descriptor != self->message->GetDescriptor()) {
    if (message_descriptor->full_name() ==
        self->message->GetDescriptor()->full_name()) {
      message_descriptor = self->message->GetDescriptor();
      field_descriptor =
          message_descriptor->FindFieldByName(field_descriptor->name());
    }
  }

  if (self->message->GetDescriptor() != field_descriptor->containing_type()) {
    PyErr_Format(PyExc_TypeError,
                 "descriptor to field '%s' doesn't apply to '%s' object",
                 std::string(field_descriptor->full_name()).c_str(),
                 Py_TYPE(self)->tp_name);
    return nullptr;
  }

  if (!field_descriptor->is_repeated() &&
      field_descriptor->cpp_type() != FieldDescriptor::CPPTYPE_MESSAGE) {
    return InternalGetScalar(self->message, field_descriptor);
  }

  ContainerBase* py_container = nullptr;
  if (field_descriptor->is_map()) {
    const Descriptor* entry_type = field_descriptor->message_type();
    const FieldDescriptor* value_type = entry_type->map_value();
    if (value_type->cpp_type() == FieldDescriptor::CPPTYPE_MESSAGE) {
      CMessageClass* value_class = message_factory::GetMessageClass(
          GetFactoryForMessage(self), value_type->message_type());
      if (value_class == nullptr) {
        return nullptr;
      }
      py_container =
          NewMessageMapContainer(self, field_descriptor, value_class);
    } else {
      py_container = NewScalarMapContainer(self, field_descriptor);
    }
  } else if (field_descriptor->is_repeated()) {
    if (field_descriptor->cpp_type() == FieldDescriptor::CPPTYPE_MESSAGE) {
      CMessageClass* message_class = message_factory::GetMessageClass(
          GetFactoryForMessage(self), field_descriptor->message_type());
      if (message_class == nullptr) {
        return nullptr;
      }
      py_container = repeated_composite_container::NewContainer(
          self, field_descriptor, message_class);
    } else {
      py_container =
          repeated_scalar_container::NewContainer(self, field_descriptor);
    }
  } else if (field_descriptor->cpp_type() == FieldDescriptor::CPPTYPE_MESSAGE) {
    py_container = InternalGetSubMessage(self, field_descriptor);
  } else {
    PyErr_SetString(PyExc_SystemError, "Should never happen");
  }

  if (py_container == nullptr) {
    return nullptr;
  }
  PyObject* value = py_container->AsPyObject();
  SetCompositeField(self, field_descriptor, value);
  return value;
}

PyObject* subscript(ExtensionDict* self, PyObject* key) {
  const FieldDescriptor* descriptor = cmessage::GetExtensionDescriptor(key);
  if (descriptor == nullptr) {
    return nullptr;
  }
  if (!CheckFieldBelongsToMessage(descriptor, self->parent->message)) {
    return nullptr;
  }

  if (!descriptor->is_repeated() &&
      descriptor->cpp_type() != FieldDescriptor::CPPTYPE_MESSAGE) {
    return cmessage::InternalGetScalar(self->parent->message, descriptor);
  }

  CMessage::CompositeFieldsMap* parent_fields =
      self->parent->composite_fields.Get();
  if (PyObject* value = parent_fields->Get(descriptor, nullptr)) {
    return value;
  }

  if (!descriptor->is_repeated() &&
      descriptor->cpp_type() == FieldDescriptor::CPPTYPE_MESSAGE) {
    // TODO: consider building the class on the fly!
    ContainerBase* sub_message =
        cmessage::InternalGetSubMessage(self->parent, descriptor);
    if (sub_message == nullptr) {
      return nullptr;
    }
    PyObject* value = sub_message->AsPyObject();
    parent_fields->TrySet(descriptor, value);
    return value;
  }

  if (descriptor->is_repeated()) {
    if (descriptor->cpp_type() == FieldDescriptor::CPPTYPE_MESSAGE) {
      // On the fly message class creation is needed to support the following
      // situation:
      // 1- add FileDescriptor to the pool that contains extensions of a message
      //    defined by another proto file. Do not create any message classes.
      // 2- instantiate an extended message, and access the extension using
      //    the field descriptor.
      // 3- the extension submessage fails to be returned, because no class has
      //    been created.
      // It happens when deserializing text proto format, or when enumerating
      // fields of a deserialized message.
      CMessageClass* message_class = message_factory::GetOrCreateMessageClass(
          cmessage::GetFactoryForMessage(self->parent),
          descriptor->message_type());
      ScopedPyObjectPtr message_class_handler(
          reinterpret_cast<PyObject*>(message_class));
      if (message_class == nullptr) {
        return nullptr;
      }
      ContainerBase* py_container = repeated_composite_container::NewContainer(
          self->parent, descriptor, message_class);
      if (py_container == nullptr) {
        return nullptr;
      }
      PyObject* value = py_container->AsPyObject();
      parent_fields->TrySet(descriptor, value);
      return value;
    } else {
      ContainerBase* py_container =
          repeated_scalar_container::NewContainer(self->parent, descriptor);
      if (py_container == nullptr) {
        return nullptr;
      }
      PyObject* value = py_container->AsPyObject();
      parent_fields->TrySet(descriptor, value);
      return value;
    }
  }
  PyErr_SetString(PyExc_ValueError, "control reached unexpected line");
  return nullptr;
}

  def testConcurrentGetFieldValueRace(self):
    """Reproduces a data race in GetFieldValue due to lazy initialization."""

    def AccessFields(msg, barrier) -> None:
      barrier.wait()
      # This access triggers GetFieldValue and lazy initialization
      # of the composite_fields map in CMessage.
      _ = msg.optional_nested_message

    for _ in range(100):
      threads = []
      msg = unittest_proto3_pb2.TestAllTypes()

      # Use a barrier to ensure all threads hit the GetFieldValue call
      # at nearly the same time, maximizing the race window.
      barrier = threading.Barrier(10)

      for _ in range(10):
        thread = threading.Thread(target=AccessFields, args=(msg, barrier))
        threads.append(thread)
        thread.start()

      for thread in threads:
        thread.join()
