### Title
`aptos move verify-package` reports on-chain bytecode as verified while it never compares actual module bytecode against the local compilation — (File: `aptos-move/cli/src/stored_package.rs`)

### Summary
The Aptos publish/upgrade flow accepts a `PackageMetadata` struct and an independent `code: vector<vector<u8>>` blob as two unrelated arguments to `code::publish_package_txn` [1](#0-0) . Nothing on-chain binds the metadata's self-reported `source_digest`/`source` fields to the actual bytecode that gets stored and executed. The only tool that claims to close this gap, `aptos move verify-package`, in fact only re-checks that the locally-recompiled `PackageMetadata` struct equals the on-chain-stored `PackageMetadata` struct field-by-field; it never re-derives or diff-checks the deployed module bytecode itself [2](#0-1) .

### Finding Description
`PackageMetadata` carries only metadata about the code, not the code itself: `name`, `upgrade_policy`, `source_digest`, `manifest`, `modules: vector<ModuleMetadata>` (each with `name`, gzipped `source`, `source_map`), and `deps` [3](#0-2) . The actual compiled bytecode is a completely separate argument (`code`) that is passed straight to the native publish request and never cross-checked against `pack.modules[i].source`/`source_digest` inside `publish_package` [4](#0-3) .

`aptos move verify-package` is documented as verifying "that on-chain bytecode matches a local source tree" [5](#0-4) . Its implementation, however, only builds the package locally to obtain a `PackageMetadata`, fetches the on-chain `PackageMetadata` via `CachedPackageRegistry`, and calls `package.verify(&compiled_metadata)` [6](#0-5) . `StoredPackage::verify` compares `name`, `deps`, `modules` (the `ModuleMetadata` records — source/source_map/name, not bytecode), `manifest`, `upgrade_policy`, `extension`, and `source_digest` between the two metadata objects [2](#0-1) . All of these fields originate from data the original publisher chose to submit at publish time and are stored verbatim in the on-chain `PackageRegistry` resource — none of them is cryptographically derived from, or checked against, the actual `MODULE bytes` deployed to the account/object's code storage.

Because `source_digest` is "constructed by first building the sha256 of each individual source... then sha256 them again" over the *claimed source text*, not over the deployed bytecode [7](#0-6) , a publisher can submit `metadata` whose `source`/`source_digest`/`manifest` correspond to some innocuous, auditable Move source, while submitting a `code` vector containing different (e.g. malicious) compiled bytecode in the same `publish_package_txn` call. `verify-package` will recompute a matching `PackageMetadata` from the honest source, compare it field-by-field to the on-chain metadata, find them equal, and print "Successfully verified source of package" — while the bytecode actually executing at that address is unrelated to, and potentially malicious relative to, what was "verified."

### Impact Explanation
This is a code/publish-safety invariant violation: it breaks the implicit guarantee that "verified" on-chain code corresponds to its claimed, reviewable source. Downstream consumers — dependent packages, auditors, or end users deciding whether to interact with or `deps`-declare a package — rely on `verify-package` as the concrete mechanism to confirm bytecode-to-source correspondence before extending trust, exactly the scenario the CLI doc promises. Since the check never touches actual bytecode, a malicious or compromised publisher can present a false "verified" package while running arbitrary logic, defeating code-safety review for any party who trusts the CLI's verification result. This maps to the required impact category: "Mismatch between verified bytes, package metadata, dependency declarations, and committed module bytes."

### Likelihood Explanation
No privileged access is required — any account that can publish a package (any signer) can supply this mismatch merely by constructing an ordinary `publish_package_txn`/`publish`/`deploy-object` transaction with unrelated `metadata` and `code` payloads; no compatibility, ownership, or upgrade-policy check inspects this relationship [4](#0-3) . The only barrier is that a victim must run `verify-package` and trust its output, which is precisely its intended use case.

### Recommendation
Bind the bytecode to the metadata cryptographically before/at publish time, e.g., have `publish_package`/`request_publish[_with_allowed_deps]` verify that each `ModuleMetadata.source`'s digest, when recompiled by the verifying client, matches a hash computed from the actual bytecode module (not just self-reported `source_digest`), or have `StoredPackage::verify` independently fetch the raw module bytecode from the account's code storage and compare it (e.g., via a bytecode hash) against a hash of the freshly-compiled `BuiltPackage` output, rather than only comparing the two `PackageMetadata` structs.

### Proof of Concept
1. Prepare a legitimate, auditable Move package `A` and compute its `PackageMetadata` (source, source_digest, manifest) via `BuiltPackage::extract_metadata`.
2. Separately compile a malicious package `B` with the same module names/signatures as `A` but different (backdoored) logic; extract only its `code: vector<vector<u8>>`.
3. Submit `code::publish_package_txn(metadata_from_A, code_from_B)` (or via `object_code_deployment::publish`/`upgrade`, which forward directly to `code::publish_package_txn` [8](#0-7) ).
4. Any third party runs `aptos move verify-package --account <addr>` against local source `A`; `StoredPackage::verify` compares the on-chain metadata (from step 3, i.e., `A`'s metadata) to the locally rebuilt metadata of `A`, finds all fields equal, and prints "Successfully verified source of package" [9](#0-8)  — despite the deployed bytecode actually being `B`'s malicious code.

    public fun publish_package(owner: &signer, pack: PackageMetadata, code: vector<vector<u8>>) acquires PackageRegistry {
        // Disallow incompatible upgrade mode. Governance can decide later if this should be reconsidered.
        assert!(
            pack.upgrade_policy.policy > upgrade_policy_arbitrary().policy,
            error::invalid_argument(EINCOMPATIBLE_POLICY_DISABLED),
        );

        let addr = signer::address_of(owner);
        if (!exists<PackageRegistry>(addr)) {
            move_to(owner, PackageRegistry { packages: vector::empty() })
        };

        // Checks for valid dependencies to other packages
        let allowed_deps = check_dependencies(addr, &pack);

        // Check package against conflicts
        // To avoid prover compiler error on spec
        // the package need to be an immutable variable
        let module_names = get_module_names(&pack);

        // Record, per module in this package, the object's transitive root owner at (re)publish, so
        // lazy self-init can detect a later transfer of the object or an ancestor since that module
        // was published (see `init::internal_maybe_initialize`). Objects only; feature-gated.
        if (features::is_lazy_module_initialization_enabled() && object::is_object(addr)) {
            let owner = object::address_to_object<object::ObjectCore>(addr).root_owner();
            module_names.for_each_ref(|name| {
                init::record_deploy_owner(addr, *name.bytes(), owner);
            });
        };
        let package_immutable = &borrow_global<PackageRegistry>(addr).packages;
        let len = package_immutable.length();
        let index = len;
        let upgrade_number = 0;
        package_immutable.enumerate_ref(|i, old| {
            let old: &PackageMetadata = old;
            if (old.name == pack.name) {
                upgrade_number = old.upgrade_number + 1;
                check_upgradability(old, &pack, &module_names);
                index = i;
            } else {
                check_coexistence(old, &module_names)
            };
        });

        // Assign the upgrade counter.
        pack.upgrade_number = upgrade_number;

        let packages = &mut borrow_global_mut<PackageRegistry>(addr).packages;
        // Update registry
        let policy = pack.upgrade_policy;
        if (index < len) {
            pack.modules.for_each_ref(|m| {
                let m: &ModuleMetadata = m;
                init::reset_initialized(addr, *m.name.bytes());
            });
            *packages.borrow_mut(index) = pack
        } else {
            packages.push_back(pack)
        };

        event::emit(PublishPackage {
            code_address: addr,
            is_upgrade: upgrade_number > 0
        });

        // Request publish
        if (features::code_dependency_check_enabled())
            request_publish_with_allowed_deps(addr, module_names, allowed_deps, code, policy.policy)
        else
        // The new `request_publish_with_allowed_deps` has not yet rolled out, so call downwards
        // compatible code.
            request_publish(addr, module_names, code, policy.policy)
    }

    pub fn verify(&self, package_metadata: &PackageMetadata) -> anyhow::Result<()> {
        let self_metadata = self.metadata;

        if self_metadata.name != package_metadata.name {
            bail!(
                "Package name doesn't match {} : {}",
                package_metadata.name,
                self_metadata.name
            )
        } else if self_metadata.deps != package_metadata.deps {
            bail!(
                "Dependencies don't match {:?} : {:?}",
                package_metadata.deps,
                self_metadata.deps
            )
        } else if self_metadata.modules != package_metadata.modules {
            bail!(
                "Modules don't match {:?} : {:?}",
                package_metadata.modules,
                self_metadata.modules
            )
        } else if self_metadata.manifest != package_metadata.manifest {
            bail!(
                "Manifest doesn't match {:?} : {:?}",
                package_metadata.manifest,
                self_metadata.manifest
            )
        } else if self_metadata.upgrade_policy != package_metadata.upgrade_policy {
            bail!(
                "Upgrade policy doesn't match {:?} : {:?}",
                package_metadata.upgrade_policy,
                self_metadata.upgrade_policy
            )
        } else if self_metadata.extension != package_metadata.extension {
            bail!(
                "Extensions doesn't match {:?} : {:?}",
                package_metadata.extension,
                self_metadata.extension
            )
        } else if self_metadata.source_digest != package_metadata.source_digest {
            bail!(
                "Source digests doesn't match {:?} : {:?}",
                package_metadata.source_digest,
                self_metadata.source_digest
            )
        }

        Ok(())
    }

# Publish

Subcommands that publish a Move package to a network. All of them accept the [shared package options](./cli.md#package-options) and [shared transaction options](./cli.md#transaction-options); only the command-specific flags are listed below.

## Picking a publication pattern

Two patterns are supported side by side; pick based on how you want the package's address to behave:

- **Account publishing** (`publish` / `deploy`): the modules live at the **signer's account address**. Simplest pattern. Upgrades happen by re-publishing from the same account. The signer owns upgrade authority and can't transfer it.
- **Code-object publishing** (`deploy-object` / `upgrade-object`): the modules live at a **separate, derived object address**. Upgrade authority is held in a code object and can be transferred. Use this when modules need an address independent of any single account.

For code review and reproducibility, [`verify-package`](#aptos-move-verify-package) checks that on-chain bytecode matches a local source tree.

    async fn execute(self) -> CliTypedResult<&'static str> {
        // First build the package locally to get the package metadata
        let build_options = BuildOptions {
            install_dir: self.move_options.output_dir.clone(),
            bytecode_version: fix_bytecode_version(
                self.move_options.bytecode_version,
                self.move_options.language_version,
            ),
            ..self.included_artifacts.build_options(&self.move_options)?
        };
        let w = self.env.writer();
        let pack = BuiltPackage::build_to(&w, self.move_options.get_package_path()?, build_options)
            .map_err(|e| CliError::MoveCompilationError(format!("{:#}", e)))?;
        let compiled_metadata = pack.extract_metadata()?;

        // Now pull the compiled package
        let client = self.rest_options.client(&self.profile_options)?;
        let registry = CachedPackageRegistry::create(client, self.account, false).await?;
        let package = registry
            .get_package(pack.name())
            .await
            .map_err(|s| CliError::CommandArgumentError(s.to_string()))?;

        // We can't check the arbitrary, because it could change on us
        if package.upgrade_policy() == UpgradePolicy::arbitrary() {
            return Err(CliError::CommandArgumentError(
                "A package with upgrade policy `arbitrary` cannot be downloaded \
                since it is not safe to depend on such packages."
                    .to_owned(),
            ));
        }

        // Verify that the source digest matches
        package.verify(&compiled_metadata)?;

        Ok("Successfully verified source of package")
    }
