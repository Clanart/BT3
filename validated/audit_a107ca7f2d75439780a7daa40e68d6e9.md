## Analysis

Found a valid analog in `VLMGP.sol`. The bug class here is different in mechanics but identical in structure to the report: a `pause()` (owner-triggered circuit breaker, not a malicious admin action, just normal operational risk-mitigation) blocks a user-initiated finalization function (`unlock`/`cancelUnlock`), while a time-dependent formula elsewhere in the protocol keeps running against the user's position, converting the forced delay into a real, permanent loss (forfeited yield) rather than a temporary and reversible one.

### Title
Pausing VLMGP blocks `unlock()`/`cancelUnlock()` while the time-decaying `getRewardablePercentWAD()` forfeiture formula keeps running, causing users to permanently lose reward yield they cannot stop from decaying - (File: VLMGP.sol)

### Summary
`VLMGP.unlock()` and `VLMGP.cancelUnlock()` are gated by `whenNotPaused` [1](#0-0) [2](#0-1) . When the contract is paused, a user whose cooldown has already ended (or is still counting down) cannot call `unlock()` to withdraw their MGP nor `cancelUnlock()` to re-lock it. Meanwhile, `getRewardablePercentWAD()` computes a time-decaying "rewardable" percentage for amounts sitting in a finished cooldown slot, and this percentage keeps shrinking the longer `block.timestamp` grows past `endTime`, independent of whether the contract is paused [3](#0-2) .

### Finding Description
`getRewardablePercentWAD()` is used by `vlMGPBaseRewarder._calExpireForfeit()` to determine how much of a user's pending MGP/bonus reward gets forfeited (sent to other stakers) instead of paid out to the user [4](#0-3) . For a cooldown slot that is already past `endTime` ("fully unlocked" but not yet claimed), the contributed percentage is:

```
percent += amountInCoolDown * 1e18 * (endTime - startTime) / userTotalVlmgp / (timeNow - startTime)
```

As `timeNow` grows, this term monotonically shrinks, so the longer the amount sits unclaimed past `endTime`, the smaller the "rewardable" percentage becomes and the larger the forfeited portion of pending rewards becomes [5](#0-4) .

The only way to move a slot out of this "fully unlocked but idle" state is to call `unlock()` (which also triggers `IMasterMagpie(masterMagpie).multiclaimFor` and resets `slot.amountInCoolDown`) [6](#0-5) . Both `unlock()` and `cancelUnlock()` require `whenNotPaused` [7](#0-6) [2](#0-1) . If the contract owner pauses `VLMGP` (a normal, non-malicious operational action, e.g. in response to an unrelated incident) while a user's cooldown slot has already matured, the user is completely unable to call `unlock()` to stop the decay: they can neither claim the underlying MGP nor cancel the unlock to move the funds back into steady locked state. The decay clock (`timeNow - startTime`) keeps advancing regardless of the pause state, exactly mirroring the original report's pattern of "user-facing action blocked by pause, background accrual continues unaffected by the pause."

Unlike the original UToken case (where the harm is merely continuing to owe interest that could later be repaid), here the harm is irreversible: the forfeited MGP/bonus reward is permanently redistributed to other stakers via `_queueNewRewardsWithoutTransfer` [8](#0-7)  the moment the user is eventually able to claim, so the yield loss cannot be recovered once it has decayed.

### Impact Explanation
The affected user permanently loses pending MGP/bonus reward yield that they earned while locked, with the loss magnitude directly proportional to how long the admin pause lasts while their cooldown slot sits matured. This is a direct, permanent loss of unclaimed yield caused purely by protocol logic reachable through a normal wallet flow (`lock` → `startUnlock` → wait → blocked `unlock`), not by any error or malicious act on the part of the affected user.

### Likelihood Explanation
Requires: (1) a user to have started `startUnlock()` and their cooldown to mature, and (2) the contract to be paused (a legitimate, foreseeable operational event, e.g. incident response) for a meaningful period while that slot is idle. Given `PausableUpgradeable` is a standard operational safety tool expected to be used at some point in the contract's lifetime, and cooldown periods (`coolDownInSecs`) are typically on the order of days-to-weeks, the overlap window is realistic and not a contrived edge case.

### Recommendation
Remove the `whenNotPaused` modifier from `unlock()` and `cancelUnlock()` (mirroring the original report's fix of removing `whenNotPaused` from repay-like exit functions), so that users can always exit a matured or in-progress cooldown slot regardless of pause state. Alternatively, freeze the decay clock used in `getRewardablePercentWAD()` (e.g., track cumulative "paused time" and subtract it from `timeNow - startTime`) so that pause periods do not count against the user's rewardable percentage.

### Proof of Concept
1. User calls `lock()` then `startUnlock(amount)`; a cooldown slot is created with `endTime = block.timestamp + coolDownInSecs` [9](#0-8) .
2. Time passes past `endTime`, the slot is now "fully unlocked" per `getFullyUnlock()` [10](#0-9) , but the user has not yet called `unlock()`.
3. Owner calls `pause()` [11](#0-10) .
4. User attempts `unlock(slotIndex)` or `cancelUnlock(slotIndex)` — both revert due to `whenNotPaused` [7](#0-6) [2](#0-1) .
5. While paused, `block.timestamp` keeps advancing; `getRewardablePercentWAD()`'s decaying term for this slot keeps shrinking each second [12](#0-11) .
6. Once unpaused and the user finally claims rewards (via `getReward`/`getRewards` in `vlMGPBaseRewarder`), `_calExpireForfeit` computes a larger forfeiture than would have applied had the user been able to `unlock()` promptly at `endTime`, and that forfeited MGP is redistributed to other stakers, permanently, via `_queueNewRewardsWithoutTransfer` [8](#0-7) .

    function getRewardablePercentWAD(address _user) override public view returns(uint256 percent) {
        uint256 fullyInLock = getUserTotalLocked(_user);
        uint256 inCoolDown = getUserAmountInCoolDown(_user);
        uint256 userTotalVlmgp = fullyInLock + inCoolDown;
        if (userTotalVlmgp == 0)
            return 0;
        percent = fullyInLock * 1e18 / userTotalVlmgp;

        uint256 timeNow = block.timestamp;
        UserUnlocking[] storage userUnlocking = userUnlockings[_user];

        for (uint256 i; i < userUnlocking.length; i++) {
            if (userUnlocking[i].amountInCoolDown > 0) {
                if (block.timestamp > userUnlocking[i].endTime) {// fully unlocked 
                    percent += userUnlocking[i].amountInCoolDown * 1e18 * (userUnlocking[i].endTime - userUnlocking[i].startTime)
                        / userTotalVlmgp / (timeNow - userUnlocking[i].startTime);
                }
                else {// still in cool down 
                    percent += userUnlocking[i].amountInCoolDown * 1e18 / userTotalVlmgp;
                }

            }
        }

        return percent;
    }

    function _calExpireForfeit(address _account, uint256 _amount) internal view returns (uint256) {
        uint256 rewardablePercentWAD = vlMGP.getRewardablePercentWAD(_account);
        uint256 rewardableAmount = _amount * rewardablePercentWAD / 1e18;
        if (rewardableAmount > _amount)
            revert InvalidRewardableAmount();

        uint256 forfeitAmount = _amount - rewardableAmount;
        
        if (forfeitAmount < (_amount / 1000)) {  // if forfeitAmount is smaller than 0.1% ignore to save gas fee
            forfeitAmount = 0;
            rewardableAmount = _amount;
        }

        return forfeitAmount;
    }
