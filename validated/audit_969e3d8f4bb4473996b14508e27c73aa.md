### Title
Governance-settable `Kip71GasTarget = 0` causes divide-by-zero panic in KIP-71 base fee calculation - (File: params/kip71_config.go)

### Summary
The CVE-2021-33844 bug class is a divide-by-zero crash triggered by unvalidated numeric input reaching a division operation. The Kaia analog is the `reward.kip71.gastarget` governance parameter, which lacks a nonzero-value format check, feeding directly into `math/big.Int.Div` calls in `NextMagmaBlockBaseFee`.

### Finding Description
`NextMagmaBlockBaseFee` computes the next block's base fee using `kc.GasTarget` as a divisor: [1](#0-0) 
and, symmetrically, in the decreasing-base-fee branch: [2](#0-1) 

`gasTarget := kc.GasTarget` is used unguarded as a `big.Int` divisor (`x.Div(x, new(big.Int).SetUint64(gasTarget))` and `x.Div(y, baseFeeDenominator)`). Note that `BaseFeeDenominator` (a sibling KIP-71 parameter) is explicitly protected by a `FormatChecker` requiring `v != 0`: [3](#0-2) 
but `Kip71GasTarget` uses `noopFormatChecker`, allowing any `uint64` value including `0`: [4](#0-3) 

If `GasTarget` is set to `0` via a governance vote, then for any block with `parentGasUsed > 0`, execution enters the `parentGasUsed > gasTarget` branch (since `0` is trivially exceeded), and `new(big.Int).SetUint64(gasTarget)` becomes zero, causing `x.Div(x, gasTarget)` to panic with "division by zero" in Go's `math/big` package. This function is invoked on every block during header verification (`VerifyMagmaHeader`) and next-base-fee suggestion in gas price oracle / fee history code: [5](#0-4) [6](#0-5) 

Since the divisor guard exists for `BaseFeeDenominator` but not `GasTarget`, this is a specific, provable input-validation asymmetry, matching the SoX CVE's bug class of an unguarded division on attacker/operator-influenced input.

### Impact Explanation
A panic in block header processing/verification is a crash of the consensus-critical code path invoked by every full node processing every block after the malicious parameter takes effect. Because `NextMagmaBlockBaseFee` is called from block validation (via `VerifyMagmaHeader`) and RPC-facing gas price oracle logic, a network-wide crash (denial of service across all nodes simultaneously) is possible, which can also manifest as state divergence if only some nodes panic/recover differently, satisfying the "state divergence between honest nodes" acceptance criterion.

### Likelihood Explanation
This requires a governance vote to set `reward.kip71.gastarget` (or genesis config) to `0`, which is within the explicitly allowed "governance parameters" category per the validation rules. It does not require compromising a validator key — a normal governance proposal/vote flow (reachable via governance transactions) is sufficient, and there is no format check preventing the zero value, unlike the adjacent `BaseFeeDenominator` parameter which is explicitly guarded. This asymmetry strongly suggests the zero-check for `GasTarget` was simply omitted, not intentionally allowed.

### Recommendation
Add a `FormatChecker` to `Kip71GasTarget` in `kaiax/gov/param.go` requiring `v != 0`, mirroring the existing check on `Kip71BaseFeeDenominator`. Additionally, add a defensive `if gasTarget == 0 { ... fallback ... }` guard directly in `NextMagmaBlockBaseFee` (`params/kip71_config.go`), analogous to the existing zero-guard for `BaseFeeDenominator`: [7](#0-6) 

### Proof of Concept
1. Submit/pass a governance vote (or configure genesis) setting `reward.kip71.gastarget = 0` on a Magma-enabled chain.
2. Once the parameter takes effect, any subsequent block with `GasUsed > 0` triggers `NextMagmaBlockBaseFee(parentNumber, parentBaseFee, parentGasUsed)` with `gasTarget = 0`.
3. Execution reaches `y := x.Div(x, new(big.Int).SetUint64(gasTarget))` at `params/kip71_config.go:102` with a zero divisor, causing `math/big.Int.Div` to panic ("division by zero"), crashing the node process during header verification or fee-history/gas-price-oracle RPC calls that invoke the same function.

func (kc *KIP71Config) VerifyMagmaHeader(headerBaseFee *big.Int, parentHeaderNumber *big.Int, parentHeaderBaseFee *big.Int, parentHeaderGasUsed uint64) error {
	if headerBaseFee == nil {
		return fmt.Errorf("header is missing baseFee")
	}
	// Verify the baseFee is correct based on the parent header.
	expectedBaseFee := kc.NextMagmaBlockBaseFee(parentHeaderNumber, parentHeaderBaseFee, parentHeaderGasUsed)
	if headerBaseFee.Cmp(expectedBaseFee) != 0 {
		return fmt.Errorf("invalid baseFee: have %s, want %s, parentBaseFee %s, parentGasUsed %d",
			headerBaseFee, expectedBaseFee, parentHeaderBaseFee, parentHeaderGasUsed)
	}
	return nil
}
