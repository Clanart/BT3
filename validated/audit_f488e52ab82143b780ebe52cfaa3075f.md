### Title
Attacker-controlled `security-patterns.yaml`/`.json` regex can bypass `_has_redos_structure` heuristic, causing unbounded ReDoS hang in `check_patterns` with no timeout or logging - ([File: plugins/security-guidance/hooks/extensibility.py])

### Summary
`_validate_pattern` in `extensibility.py` relies on the heuristic `_has_redos_structure` (only two hardcoded `_REDOS_SHAPES` regexes plus a prefix-overlap alternation check) to reject catastrophic-backtracking regexes before caching them in `_user_patterns`. This is a known-incomplete static heuristic (the code comment itself states "Not a proof"), so a regex shape outside those two patterns (e.g. multi-group nested quantifiers, or overlapping alternation not caught by the simple prefix check) passes validation, gets `re.compile`d, and is later executed via `re.search(pattern["regex"], content)` in `check_patterns` (`security_reminder_hook.py`) against unbounded diff/file content with no timeout.

### Finding Description
The flow is: `extensibility.load_for_session` → `_load_user_patterns` (`plugins/security-guidance/hooks/extensibility.py:147-168`) reads `security-patterns.{yaml,json}` from `~/.claude/`, `<cwd>/.claude/`, or `<cwd>/.claude/*.local.*` [1](#0-0) . Each entry is passed to `_validate_pattern`, which gates regex acceptance solely on `_has_redos_structure` [2](#0-1) . That heuristic checks only two nested-quantifier/wildcard shapes and a naive alternation-prefix check [3](#0-2) . It does not cover many classic ReDoS shapes (e.g. `(a+)+b`-style patterns split across more than one group, `(a|ab)*c` variants where overlap isn't a strict prefix relationship, or backreference-based blowups), so a crafted regex can pass this gate. Once accepted, the rule is stored in `_user_patterns` and later matched via `re.search(pattern["regex"], content)` inside `check_patterns` (`security_reminder_hook.py:417-422`) against diff/file content with **no timeout, no length cap on the matched content, and no exception other than a bare `except Exception: pass`** that only catches immediate `re.error`s, not runtime hangs [4](#0-3) . `debug_log` in `_base.py` only writes synchronously at explicit call sites — there is no call before or after the `re.search` in `check_patterns`, so a hang in the regex engine occurs silently with no diagnostic trace and no exit path [5](#0-4) . This stalls the whole hook process (Python's `re` module is not preemptible and has no built-in timeout), so the PostToolUse/Stop hook that gates commit/push review never completes, defeating the "DENY_MEANS_DENY" invariant by fail-open (or effectively fail-hang, blocking the interactive session or timing out the hook infrastructure without ever running the LLM review or emitting a deny decision).

### Impact Explanation
This is a real denial-of-service / fail-open path in the security-guidance hook: a malicious `security-patterns.yaml` committed in a repo (a plausible "ordinary repository content" attack, e.g. via a PR) can hang the hook that is responsible for the commit/push security review and pattern-warning enforcement, with no logged failure and no hard timeout. Practically this can suppress the pattern-check portion of every future Edit/Write/commit review in that project (or degrade to a hung/killed hook process), which is a trust-boundary bypass of the plugin's own "custom regexes are validated ... and skipped if they look ReDoS-prone" claim documented at the top of `extensibility.py` [6](#0-5) .

### Likelihood Explanation
Feasibility depends entirely on whether `_has_redos_structure`'s two-pattern heuristic can be evaded — plausible, since it is explicitly a coarse static heuristic covering only two specific AST shapes, not a general catastrophic-backtracking detector. An attacker needs write access to a file under `.claude/security-patterns.{yaml,yml,json}` in the repository (project or project-local) or the user's home directory — this is achievable via a malicious PR adding such a file, satisfying the "ordinary repository content" precondition. Content large enough to trigger multi-second+ backtracking (tens of KB of near-miss text) is trivially reachable via a diff or edited file. I could not execute code in this environment to empirically confirm a specific bypass payload triggers a multi-second hang; this assessment is based on static analysis of the heuristic's incompleteness, which is explicitly acknowledged by the code's own comments.

### Recommendation
Do not rely purely on static heuristics for ReDoS prevention. Enforce a hard runtime timeout around every user-supplied-regex `re.search` call in `check_patterns` (e.g. via a signal-based alarm on POSIX, a subprocess/worker with a wall-clock timeout, or switching to the `regex` module with a timeout parameter, or the `re2`/`google-re2` engine which has linear-time guarantees and no catastrophic backtracking). Additionally, cap the size of `content` passed to `re.search` for user-supplied regex rules, and add a `debug_log` call immediately before invoking a user regex so a subsequent hang is at least attributable in the log (even though the hang itself would prevent the *next* log line, a "about to run user regex X" pre-log lets an operator diagnose the stall post-mortem via process inspection/`SIGABRT`/watchdog).

### Proof of Concept
Unit/fuzz test plan for `plugins/security-guidance/hooks/extensibility.py` and `security_reminder_hook.check_patterns`:
1. Fuzz a corpus of catastrophic-backtracking regex shapes (classic ReDoS payloads: `(a|a)+$`, `(a+)+$`, `([a-zA-Z]+)*$`, `(a|aa)+b`, patterns with 3+ nested groups) and run each through `_has_redos_structure`; assert that some pass (return `False`) despite being exponential-time.
2. For each pattern that passes the heuristic, call `_validate_pattern({"rule_name": "x", "reminder": "y", "regex": pattern}, source="test")` and confirm it returns a non-`None` rule (i.e., reaches `re.compile`).
3. Construct malicious/near-miss input strings of 10–50KB (e.g., `"a" * 40000 + "!"` for patterns anchored to fail) and time `re.search(pattern, content)` directly; assert wall-clock time exceeds a threshold (e.g., >2s) to demonstrate real backtracking blowup.
4. Integration test: write such a rule into a temp `.claude/security-patterns.yaml`, call `extensibility.load_for_session(cwd)`, then call `check_patterns(file_path, large_diff_content)` and assert it either times out (test should fail/hang without a fix) or, after the fix, returns within a bounded time and logs the abort via `debug_log`.

```python
_REDOS_SHAPES = [
    re.compile(r"\([^()]*[+*][^()]*\)[+*?]"),  # nested quantifier: (a+)*  (a*b)*
    re.compile(r"\(\.\*[^()]*\)[+*]"),         # wildcard group: (.*)*
]
_ALT_UNDER_REP = re.compile(r"\(([^()]*)\|([^()|]*)(?:\|[^()]*)*\)[+*]")


def _has_redos_structure(regex: str) -> bool:
    """Heuristic catastrophic-backtracking check. Not a proof. Catches:
      - nested quantifiers ((a+)*, (a*b)+)
      - wildcard groups under repetition ((.*)*)
      - alternation under repetition where one branch is a prefix of another
        ((a|aa)*, (ab|a)*) — these overlap and explode on non-matching input.
    Does NOT flag non-overlapping alternation ((a|b)*) which is safe."""
    if any(p.search(regex) for p in _REDOS_SHAPES):
        return True
    for m in _ALT_UNDER_REP.finditer(regex):
        branches = [b for b in m.group(0).strip("()*+").split("|") if b]
        for i, a in enumerate(branches):
            for b in branches[i + 1:]:
                # If one branch is a literal prefix of another, the alternation
                # overlaps and the engine backtracks combinatorially.
                if a.startswith(b) or b.startswith(a):
                    return True
    return False
```

```python
def debug_log(message):
    """Append debug message to log file with timestamp."""
    try:
        # Ensure parent dir exists — first hook invocation on a fresh install
        # creates ~/.claude/security/ if it isn't already there. 0700 so other
        # local users can't read review/debug output (only applies on creation).
        try:
            os.makedirs(os.path.dirname(DEBUG_LOG_FILE), mode=0o700, exist_ok=True)
        except OSError:
            pass
        try:
            if os.path.getsize(DEBUG_LOG_FILE) > DEBUG_LOG_MAX_BYTES:
                # os.replace is atomic on POSIX; under a racing fleet the loser
                # gets FileNotFoundError, which is fine — the append below
                # recreates the file.
                os.replace(DEBUG_LOG_FILE, DEBUG_LOG_FILE + ".1")
        except OSError:
            pass
        timestamp = datetime.now().strftime("%Y-%m-%d %H:%M:%S.%f")[:-3]
        # 0600 on creation; existing files keep their mode.
        fd = os.open(DEBUG_LOG_FILE, os.O_WRONLY | os.O_CREAT | os.O_APPEND, 0o600)
        with os.fdopen(fd, "a") as f:
            f.write(f"[{timestamp}] {message}\n")
    except Exception:
        pass
```
