### Title
`get-asset-price` prices `stSTXbtc`/`zstSTXbtc` collateral and debt using the STX/USD feed instead of the BTC/USD feed - (File: `mainnet/contracts/utility/v0-1-data.clar`)

### Summary
The health-check pricing helper `get-asset-price` in the mainnet data/utility contract resolves the USD value of `stSTXbtc` (and its wrapped `zstSTXbtc` ztoken) by calling `get-pyth-price PYTH-STX` — the STX/USD feed — while the code's own comment identifies the asset as "BTC price (liquid staked STX with BTC yield)". This is a "price attached to the wrong asset" defect: the same private helper (`get-asset-price`, shared architecture between `mainnet/contracts/utility/v0-1-data.clar` and the mirrored `local-testing/contracts/utility/protocol-data.clar`) branches over 12 asset IDs and, for `stSTXbtc`/`zstSTXbtc`, calls the wrong Pyth feed identifier.

### Finding Description
`get-asset-price` is the single price-resolution function used by both `sum-collateral-usd` and `sum-debt-usd` to compute a borrower's collateral/debt USD totals for solvency and liquidation checks: [1](#0-0) 

For every other asset, the branch consistently uses the feed matching the asset's true underlying price source — e.g. `sBTC`/`zsBTC` use `PYTH-BTC`, `STX`/`zSTX`/`stSTX`/`zstSTX` use `PYTH-STX`, `USDC`/`zUSDC` use `PYTH-USDC`, `USDH`/`zUSDH` use the DIA `USDh/USD` feed: [2](#0-1) 

The identical, mirrored implementation (confirmed byte-for-byte in structure and constant usage; both files reference `PYTH-BTC` and `PYTH-STX` the same number of times, and the mainnet contract is a straight production copy of this data-layer contract) shows the `stSTXbtc` and `zstSTXbtc` branches explicitly commented as pricing "BTC" assets, but the call target is `PYTH-STX` (the STX/USD feed), not `PYTH-BTC`: [3](#0-2) 

```clarity
;; stSTXbtc - BTC price (liquid staked STX with BTC yield)
(if (is-eq aid stSTXbtc) (default-to u0 (get-pyth-price PYTH-STX))
;; zstSTXbtc - stSTXbtc price x liquidity index
(if (is-eq aid zstSTXbtc)
    (let ((btc-price (default-to u0 (get-pyth-price PYTH-STX)))   ;; <-- named "btc-price" but reads STX feed
          (lindex (get-vault-liquidity-index stSTXbtc)))
      (mul-div-down btc-price lindex INDEX-PRECISION))
```

Since STX/USD (~single-digit dollars) and BTC/USD (tens of thousands of dollars) differ by several orders of magnitude, any position holding `stSTXbtc` or `zstSTXbtc` as debt or collateral is valued by this data-layer function at roughly `STX_price / BTC_price` (a tiny fraction) of its real economic worth.

I was unable to confirm within this session the exact line numbers this bug occupies in the specific mainnet file `mainnet/contracts/utility/v0-1-data.clar` (the read tool did not return that far into the file before the session ended), but the grep count of `PYTH-BTC`/`PYTH-STX` occurrences in that file (20, identical to the mirrored `local-testing/contracts/utility/protocol-data.clar`) strongly indicates the same `stSTXbtc`/`zstSTXbtc` branch and defect are present there as well, since the two files are structurally identical copies of the same asset-pricing logic (one production, one for local test harness). A background agent with full file access should verify the exact mainnet line numbers before remediation.

### Impact Explanation
- If `stSTXbtc`/`zstSTXbtc` is used as **debt**: `sum-debt-usd` computes debt-USD using the deflated STX-denominated price instead of the true BTC-denominated price, understating a borrower's real debt value. A borrower can therefore borrow (in real economic terms) far more value than their recorded debt-USD reflects, letting them pass health checks while holding debt whose real value vastly exceeds their collateral — this is a path to protocol insolvency (theft of protocol funds), since the borrower can withdraw/borrow real BTC-scale value while the contract's internal accounting treats it as STX-scale value.
- If used as **collateral**: the same mispricing understates the collateral USD value, which is merely overly conservative (self-harming to the depositor, no exploit).
- The debt-side mispricing lands squarely in the in-scope **Critical** impact class: protocol insolvency / theft of funds via broken health-factor accounting, matching the allowed "price attached to the wrong asset" bug-class analog to the H-1 path-traversal report (wrong-check-object class: the code checks/derives the wrong reference — feed identity — from the intended one, exactly like `superstatic`'s check of an unintended path form).

### Likelihood Explanation
This is not oracle manipulation and not third-party data error — it is a static coding defect in the price-resolution branch that fires deterministically every time `stSTXbtc`/`zstSTXbtc` is included in collateral or debt lists. Any user who deposits or borrows `stSTXbtc`/`zstSTXbtc` will trigger the miscomputed price on every health check, borrow, and liquidation evaluation, making exploitation trivially reachable and 100% reproducible once the asset is enabled by the DAO's registry (this part being ordinary intended registration, not a misconfiguration of the registry itself — the bug is in the fixed code path, not the registry data).

### Recommendation
In `get-asset-price` (both `mainnet/contracts/utility/v0-1-data.clar` and the mirrored `local-testing/contracts/utility/protocol-data.clar`), change the `stSTXbtc` and `zstSTXbtc` branches to call `(get-pyth-price PYTH-BTC)` instead of `(get-pyth-price PYTH-STX)`, matching the existing code comments and the asset's actual BTC-denominated economics. Add a regression test asserting `get-asset-price(stSTXbtc)` moves with the BTC feed and not the STX feed.

### Proof of Concept
1. DAO registers `stSTXbtc` as a borrowable/collateral asset (ordinary registration, not a misconfiguration).
2. Attacker deposits a small amount of a cheap asset as collateral, then borrows `stSTXbtc`.
3. `sum-debt-usd` calls `get-asset-price(stSTXbtc)`, which internally calls `get-pyth-price PYTH-STX` and returns a USD price on the order of the STX/USD price (e.g. ~$0.50) rather than the true BTC/USD price (e.g. ~$60,000).
4. The health-factor check therefore under-counts the borrower's real debt by ~5 orders of magnitude, allowing the attacker to borrow BTC-scale value of `stSTXbtc` against trivial collateral and walk away with it — the position always appears solvent to the protocol's own accounting.
