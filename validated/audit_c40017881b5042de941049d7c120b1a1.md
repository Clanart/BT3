### Title
Unvalidated NFT metadata-update key causes uncaught `KeyError` when parsing a crafted on-chain metadata-update condition - (File: chia/wallet/nft_wallet/nft_puzzle_utils.py)

### Summary
The CVE analog is a "crafted input causes invalid/unchecked memory access via unvalidated lookup" bug class. In `chia-blockchain`, `update_metadata()` and its helper `prepend_value()` perform a dictionary lookup on a key taken directly from an attacker-controlled ChiaLisp condition without validating that the key exists, which raises an unhandled `KeyError` when a wallet processes a spend containing a crafted metadata-update condition (opcode `-24`).

### Finding Description
`update_metadata()` extracts the current metadata into a dict via `nft_program_to_metadata()`, which only contains keys that are already present in the NFT's on-chain metadata (e.g. `u`, `h`, `mu`, `mh`, `lu`, `lh`, `sn`, `st`). [1](#0-0) 

It then reads an update key/value pair straight from the spend's condition and calls `prepend_value()`: [2](#0-1) 

`prepend_value()` indexes the metadata dict with the attacker-supplied `key` without checking membership first: [3](#0-2) 

If the key encoded in the malicious spend's metadata-update condition is any value not already present in the NFT's metadata dict (e.g. an arbitrary/novel byte-key), `metadata[key]` raises `KeyError`, which is not caught anywhere in this call chain.

This function is invoked from `get_metadata_and_phs()`, which runs the p2 puzzle against the spend's solution and dispatches to `update_metadata()` whenever it observes condition code `-24` (metadata update) in the output: [4](#0-3) 

`get_metadata_and_phs` is called from `chia/wallet/nft_wallet/nft_wallet.py` and `chia/wallet/wallet_state_manager.py` during normal coin-state/puzzle processing of NFT coins — i.e., whenever a wallet observes/syncs a spend of an NFT coin it tracks (including one it just received from a counterparty or an offer). This makes the trigger reachable by any party who can construct or influence a coin spend for an NFT that a victim wallet will process (mint, transfer, or offer settlement), not just a privileged/administrative actor.

### Impact Explanation
An attacker who controls (or influences) an NFT puzzle/solution spend can encode a metadata-update condition (opcode `-24`) whose key is not part of the NFT's existing metadata program. When a victim wallet processes that spend (e.g., syncing NFT state after receiving/transferring the NFT or completing an offer), `update_metadata()` → `prepend_value()` raises an unhandled `KeyError`. Depending on where this exception propagates in the wallet's coin-processing pipeline, this can interrupt NFT/wallet state syncing for that coin, matching the "spend-triggered transaction-processing halt" impact category from a single crafted spend.

### Likelihood Explanation
The trigger only requires crafting a ChiaLisp inner puzzle/solution for an NFT that emits a `-24` condition with a novel key — this is achievable by any user who mints or transfers an NFT (or constructs an offer) with a custom p2/inner puzzle, without needing any special privilege, consensus involvement, or race condition. The complexity is low: it is essentially a one-line puzzle output.

### Recommendation
Validate the key against the current metadata dict (or use `dict.get`/`setdefault` with a defined default) before indexing in `prepend_value()`, and wrap `update_metadata()` calls in `get_metadata_and_phs()` with exception handling that treats unrecognized/malformed metadata-update conditions as no-ops (consistent with how other malformed conditions are already skipped, e.g. `if condition.list_len() < 2: continue`).

### Proof of Concept
1. Craft an NFT inner (p2) puzzle whose solution causes it to output a condition `(-24 <update_puzzle> (<novel_key> . <value>))`, where `<novel_key>` is a byte string not present in the NFT's existing metadata program (e.g., not `u`, `h`, `mu`, `mh`, `lu`, `lh`, `sn`, `st`).
2. Mint or transfer the NFT to a victim wallet, or include it in an offer that the victim wallet will process.
3. When the victim's wallet syncs the coin spend and calls `get_metadata_and_phs()` → `update_metadata()` → `prepend_value()`, the lookup `metadata[key]` in `chia/wallet/nft_wallet/nft_puzzle_utils.py` at [5](#0-4)  raises `KeyError`, since the crafted key was never inserted into `new_metadata` by `nft_program_to_metadata()`.

```python
def nft_program_to_metadata(program: Program) -> dict[bytes, Any]:
    """
    Convert a program to a metadata dict
    :param program: Chialisp program contains the metadata
    :return: Metadata dict
    """
    metadata = {}
    for kv_pair in program.as_iter():
        metadata[kv_pair.first().as_atom()] = kv_pair.rest().as_python()
    return metadata
```

```python
def prepend_value(key: bytes, value: Program, metadata: dict[bytes, Any]) -> None:
    """
    Prepend a value to a list in the metadata
    :param key: Key of the field
    :param value: Value want to add
    :param metadata: Metadata
    :return:
    """
    if value != Program.to(0):
        if metadata[key] == b"":
            metadata[key] = [value.as_python()]
        else:
            metadata[key].insert(0, value.as_python())
```

```python
def update_metadata(metadata: Program, update_condition: Program) -> Program:
```

```python
def get_metadata_and_phs(unft: UncurriedNFT, solution: SerializedProgram) -> tuple[Program, bytes32]:
    conditions = unft.p2_puzzle.run(unft.get_innermost_solution(Program.from_serialized(solution)))
    metadata = unft.metadata
    puzhash_for_derivation: bytes32 | None = None
    for condition in conditions.as_iter():
        if condition.list_len() < 2:
            # invalid condition
            continue
        condition_code = condition.first().as_int()
        log.debug("Checking condition code: %r", condition_code)
        if condition_code == -24:
            # metadata update
            metadata = update_metadata(metadata, condition)
            metadata = Program.to(metadata)
        elif condition_code == 51:
            atom = condition.rest().rest().first().as_int()

            if atom == 1:
                # destination puzhash
                if puzhash_for_derivation is not None:
                    # ignore duplicated create coin conditions
                    continue
                memo = bytes32(condition.at("rrrff").as_atom())
                puzhash_for_derivation = memo
                log.debug("Got back puzhash from solution: %s", puzhash_for_derivation)
    assert puzhash_for_derivation
    return metadata, puzhash_for_derivation
```
