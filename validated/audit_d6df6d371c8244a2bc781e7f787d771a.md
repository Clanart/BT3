## Title
Fee-payment swaps in `EvmHost` use `block.timestamp` as the Uniswap deadline, enabling MEV/sandwich manipulation of protocol fee payments - (`File: evm/src/core/EvmHost.sol`)

### Summary
`EvmHost` exposes three permissionless, `payable` entry points — `dispatch(DispatchPost)`, `dispatch(DispatchGet)`, and `fundRequest` — that let a caller pay the ISMP relayer fee in native token. In all three, when `msg.value > 0` the contract swaps native token for `feeToken()` via `IUniswapV2Router02.swapETHForExactTokens`, passing `block.timestamp` as the `deadline` parameter [1](#0-0) . This is the exact bug class from the external report: a deadline equal to the execution timestamp provides no real expiry, since it is always satisfied whenever the transaction is finally included, no matter how long it sat in the mempool.

### Finding Description
The same unsafe pattern appears in three places in `EvmHost.sol`:

- `dispatch(DispatchPost memory post)`: `swapETHForExactTokens{value: msg.value}(post.fee, path, address(this), block.timestamp)` [2](#0-1) 
- `dispatch(DispatchGet memory get)`: `swapETHForExactTokens{value: msg.value}(get.fee, path, address(this), block.timestamp)` [3](#0-2) 
- `fundRequest(bytes32 commitment, uint256 amount)`: `swapETHForExactTokens{value: msg.value}(amount, path, address(this), block.timestamp)` [4](#0-3) 

All three functions are public, unprivileged entry points (`external payable`, gated only by `notFrozen`) that anyone dispatching an ISMP request or topping up a request's fee can call with native value [5](#0-4) [6](#0-5) [7](#0-6) . Because `swapETHForExactTokens` is an exact-output/maximum-input swap where `amountInMax = msg.value`, an attacker who sandwiches the pending transaction on the local `uniswapV2` pool can push the ETH/feeToken price up right before it executes, forcing the swap to consume a larger share of `msg.value` to obtain the fixed `fee`/`amount` of `feeToken()`. The router's own excess-ETH refund is sent back to `msg.sender` of the router call, which is `EvmHost` itself (`to: address(this)`), not the original caller (`_msgSender()`); none of the three functions forward any refund to the depositor afterward. Consequently, whatever ETH surplus the sandwich attack consumes beyond the depositor's intended slippage buffer is irreversibly retained by the `EvmHost` contract rather than returned to the caller, and there is no deadline safeguard to bound how stale/manipulated a price the swap can execute at.

### Impact Explanation
This maps directly to "transaction manipulation" / "loss of funds" impact: an unprivileged MEV actor can sandwich fee-funding transactions on `dispatch`/`fundRequest`, forcing users who pay the ISMP relayer fee in native token to lose ETH value to a worse execution price, with any consumed surplus becoming unrecoverable once retained by the host contract. Because these functions sit on the hot path for dispatching every POST/GET request and for topping up pending request fees, the exposure recurs on every native-token-funded dispatch, not just an edge case.

### Likelihood Explanation
Likelihood is high for chains with liquid `uniswapV2` fee-token pools: the vulnerable calls are permissionless, occur on ordinary user-facing flows (dispatching a cross-chain message and paying with native token), and require no relayer, prover, or governance compromise — only a searcher/validator observing the pending transaction, exactly the "no context" MEV/sandwich condition the original report describes.

### Recommendation
Do not use `block.timestamp` as the Uniswap deadline. Accept an explicit, caller-supplied `deadline` (and ideally `amountInMax`/slippage bound tighter than raw `msg.value`) in `DispatchPost`, `DispatchGet`, and `fundRequest`, validate it is in the future but bounded, and refund any unused native token back to `_msgSender()` rather than leaving it in `address(this)`.

### Proof of Concept
1. Attacker monitors the mempool for a `dispatch(DispatchPost)`/`dispatch(DispatchGet)`/`fundRequest` call carrying `msg.value > 0`.
2. Attacker front-runs with a large buy of `feeToken()` on the configured `uniswapV2` pool, shifting the ETH/feeToken price.
3. The victim's transaction executes `swapETHForExactTokens{value: msg.value}(fee, path, address(this), block.timestamp)`; since `deadline == block.timestamp` always passes at inclusion time, the swap executes at the manipulated price, consuming more ETH than expected (bounded by `msg.value`) or reverting if `msg.value` is insufficient.
4. Attacker back-runs to restore the pool price and pocket the price-impact profit; any ETH the victim overpaid beyond the router's actual conversion cost is refunded by the router to `address(this)` (the `EvmHost` contract) — not to the victim — and is never returned in code, per the reviewed function bodies [8](#0-7) [9](#0-8) [10](#0-9) .

    function dispatch(DispatchPost memory post) external payable notFrozen returns (bytes32 commitment) {
        if (msg.value > 0) {
            address[] memory path = new address[](2);
            address uniswapV2 = _hostParams.uniswapV2;
            path[0] = IUniswapV2Router02(uniswapV2).WETH();
            path[1] = feeToken();
            IUniswapV2Router02(uniswapV2).swapETHForExactTokens{value: msg.value}(
                post.fee, path, address(this), block.timestamp
            );
        } else if (post.fee > 0) {
            IERC20(feeToken()).safeTransferFrom(_msgSender(), address(this), post.fee);
        }

        // adjust the timeout
        uint64 timeoutTimestamp = post.timeout == 0 ? 0 : uint64(block.timestamp) + uint64(post.timeout);
        PostRequest memory request = PostRequest({
            source: host(),
            dest: post.dest,
            nonce: uint64(_nextNonce()),
            from: abi.encodePacked(_msgSender()),
            to: post.to,
            timeoutTimestamp: timeoutTimestamp,
            body: post.body
        });

        // make the commitment
        commitment = request.hash();
        _requestCommitments[commitment] = FeeMetadata({sender: post.payer, fee: post.fee});
        emit PostRequestEvent({
            source: string(request.source),
            dest: string(request.dest),
            from: _msgSender(),
            to: abi.encodePacked(request.to),
            nonce: request.nonce,
            timeoutTimestamp: request.timeoutTimestamp,
            body: request.body,
            fee: post.fee
        });
    }

    function fundRequest(bytes32 commitment, uint256 amount) external payable notFrozen {
        if (msg.value > 0) {
            address[] memory path = new address[](2);
            address uniswapV2 = _hostParams.uniswapV2;
            path[0] = IUniswapV2Router02(uniswapV2).WETH();
            path[1] = feeToken();
            IUniswapV2Router02(uniswapV2).swapETHForExactTokens{value: msg.value}(
                amount, path, address(this), block.timestamp
            );
        } else {
            IERC20(feeToken()).safeTransferFrom(_msgSender(), address(this), amount);
        }

        FeeMetadata memory metadata = _requestCommitments[commitment];
        if (metadata.sender == address(0)) revert UnknownRequest();

        metadata.fee += amount;
        _requestCommitments[commitment] = metadata;

        emit RequestFunded({commitment: commitment, newFee: metadata.fee});
    }
