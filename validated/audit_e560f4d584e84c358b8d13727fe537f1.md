### Title
Permissionless bandwidth-purchase sponsorship allows griefing eviction of a victim app's paid, unexpired subscriptions - ([File: modules/pallets/bandwidth/src/lib.rs])

### Summary
`pallet-bandwidth` keys a subscription's target `(app_chain, app)` slot by the **buyer-controlled** `chain`/`app` fields inside the purchase message body, not by the identity of the source chain's registered `BandwidthManager` caller or any relationship to the app being credited. Combined with a hard 1024-entry FIFO cap that silently evicts the oldest subscription on overflow, any unprivileged actor holding the cheapest tier's price can spam purchases targeting a victim's `(app_chain, app)` pair and evict the victim's legitimately-purchased, unexpired, higher-value bandwidth entitlement before it is consumed.

### Finding Description
The pallet's design explicitly supports "sponsorship": a purchase dispatched from any registered `BandwidthManager` on any source chain can credit bandwidth to *any* `(app_chain, app)` pair, because the allowance storage is keyed from the message body, not `request.source`: [1](#0-0) 

`on_accept` only authenticates that the *sender* is the registered manager for its own source chain — it performs no check tying `msg.chain`/`msg.app` to the purchaser or to any prior relationship with that app: [2](#0-1) 

Every purchase (or `force_credit`) goes through `push_subscription`, which appends to a `BoundedVec` capped at `MAX_SUBSCRIPTIONS = 1024`; once full, the **oldest** entry — regardless of its remaining bytes or expiry — is silently evicted to make room for the new one: [3](#0-2) [4](#0-3) 

Because `chain`/`app` in `BandwidthPurchaseMsg` are attacker-controlled at purchase time, an attacker can:
1. Determine a victim's `(app_chain, app)` key (public — it is emitted on every `BandwidthCredited`/`BandwidthConsumed` event).
2. Repeatedly call `purchase()` on any registered `BandwidthManager`, targeting the victim's exact `app_chain`/`app`, using the cheapest configured tier (`TierOne`, $50 for 100 KB per the docs) purchased 1024 times.
3. Each of these attacker purchases appends to the front of the victim's queue eviction order; once the victim's `(app_chain, app)` list reaches 1024 entries, the victim's older — potentially much larger and unexpired — subscription(s) are evicted and the paid-for bytes are permanently lost (`Event::SubscriptionEvicted`).

This is the same broken-invariant class as the source report ("an edge case in the min/max-bound accounting path is not considered, causing a mandatory bookkeeping operation to silently fail or destroy already-paid-for value") — here the un-considered edge case is that the FIFO cap and cross-chain sponsorship model let a completely unrelated, unprivileged party permanently destroy another app's already-paid, unconsumed bandwidth entitlement.

### Impact Explanation
This is a direct "loss of funds" / logic-attack impact under the bounty scope: a victim's paid bandwidth entitlement (real economic value, purchased in ERC-20 stablecoin via `BandwidthManager.purchase()`) can be permanently destroyed by an unprivileged third party without needing a malicious relayer, prover, or admin. The victim's app additionally suffers a denial-of-service — the bandwidth gate (`BandwidthGate::try_consume`) will reject inbound message dispatch for that app once its entitlement is wiped, since `NoAllowance`/`Insufficient` reverts consuming apps' requests at the ISMP router level.

### Likelihood Explanation
The attack requires no privileged role, no relayer/prover collusion, and no race condition beyond normal transaction ordering. It costs the attacker `1024 × price(TierOne)` per target (a bounded, attacker-chosen cost — the cheapest available tier), which for a griefing campaign against a specific competitor or targeted app is a realistic and repeatable cost, especially since `app_chain`/`app` values are visible on-chain via emitted events, making target selection trivial.

### Recommendation
- Do not allow a purchase's target `(app_chain, app)` to be fully attacker-controlled and unauthenticated relative to the paying entity; require either (a) the buyer to be the app itself (e.g., `msg.sender`/`from` on the source chain must match `app`), or (b) an explicit opt-in/allow-list from the app being sponsored before third-party credits are accepted into its queue.
- Alternatively, segregate the FIFO list per `(app_chain, app, paid_from)` or per purchase-tier so that low-value spam purchases cannot evict higher-value, unexpired subscriptions bought by (or for) the app through its trusted funding path.
- Consider evicting based on remaining value/expiry-adjusted priority rather than strict insertion order, or reject new pushes rather than silently destroying value once a "trusted" subscription would be evicted before it is at least partially consumed.

### Proof of Concept
1. App `A` on `AppChain` legitimately purchases a `TierFour` subscription (8 MB, months=12) via its `BandwidthManager` — one `BandwidthCredited` event reveals `app_chain = AppChain`, `app = A`.
2. Attacker registers/uses a `BandwidthManager` on any registered source chain (their own funds only) and calls `purchase()` 1024 times with `chain = AppChain`, `app = A`, `tier = TierOne`, `months = 1` (the cheapest tier).
3. Each call reaches `pallet-bandwidth::on_accept` → `push_subscription(&AppChain, &A, TierOne, ...)`, appending to `Allowance::<T>::get(AppChain, A)`.
4. Once the list length hits `MAX_SUBSCRIPTIONS = 1024`, subsequent attacker purchases evict the oldest entry in the queue — eventually evicting App `A`'s legitimate `TierFour` subscription, emitting `SubscriptionEvicted { app_chain: AppChain, app: A, tier: TierFour, lost_bytes: <unused bytes> }`.
5. App `A`'s paid, unexpired 8 MB entitlement is destroyed before use, and its subsequent Hyperbridge dispatches fail the `BandwidthGate` check (`NoAllowance`/`Insufficient`) despite having paid in full.

		/// Append a fresh subscription with a fixed expiry. If the list
		/// is already at `MaxSubscriptions`, evict the oldest entry and
		/// emit [`Event::SubscriptionEvicted`] so the lost bytes are
		/// auditable. Returns the new subscription's `expires_at`.
		fn push_subscription(
			app_chain: &StateMachine,
			app: &AppKey,
			tier: TierIndex,
			bytes: BandwidthBytes,
			duration_secs: u64,
		) -> u64 {
			let now = <T as pallet_ismp::Config>::TimestampProvider::now().as_secs();
			let expires_at = now.saturating_add(duration_secs);
			let new_sub =
				Subscription { tier, remaining_bytes: bytes, expires_at, purchased_at: now };

			let evicted = Allowance::<T>::mutate(app_chain, app, |list| {
				let evicted = if list.len() == MAX_SUBSCRIPTIONS as usize {
					Some(list.remove(0))
				} else {
					None
				};
				// Capacity is now guaranteed; try_push can't fail.
				let _ = list.try_push(new_sub);
				evicted
			});

			if let Some(old) = evicted {
				Self::deposit_event(Event::SubscriptionEvicted {
					app_chain: *app_chain,
					app: app.clone(),
					tier: old.tier,
					lost_bytes: old.remaining_bytes,
				});
			}

			expires_at
		}

		fn on_accept(&self, request: PostRequest) -> Result<Weight, anyhow::Error> {
			let manager = BandwidthManager::<T>::get(&request.source).ok_or_else(|| {
				anyhow::anyhow!(format!("no bandwidth manager registered for {:?}", request.source))
			})?;

			if request.from != manager.0.to_vec() {
				return Err(anyhow::anyhow!(format!(
					"purchase from unauthorised sender on {:?}: expected {:x?}, got {:x?}",
					request.source, manager.0, request.from
				)));
			}

			let msg = PurchaseMessage::try_from(request.body.as_slice())?;
			let tier = TierIndex::try_from(msg.tier)
				.map_err(|_| anyhow::anyhow!(format!("unknown tier discriminant {}", msg.tier)))?;
			let cfg = Tiers::<T>::get(tier)
				.ok_or_else(|| anyhow::anyhow!(format!("tier {:?} is not configured", tier)))?;

			let bytes = cfg.bytes.saturating_mul(msg.months as u128);
			let duration = cfg.duration_secs.saturating_mul(msg.months as u64);

			let key = AppKey::truncate_from(msg.app);
			let expires_at = Self::push_subscription(&msg.chain, &key, tier, bytes, duration);

			Self::deposit_event(Event::BandwidthCredited {
				app_chain: msg.chain,
				app: key,
				paid_from: request.source,
				tier,
				bytes,
				expires_at,
			});

			Ok(Weight::zero())
		}
