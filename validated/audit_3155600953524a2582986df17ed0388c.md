### Title
Deleting a branch silently orphans its GitHub-Desktop stash entry, permanently hiding stashed work from the UI - (File: `app/src/lib/stores/app-store.ts`)

### Summary
The Sherlock report's root cause is that a destructive "burn" operation (`_burn(_from)` in `merge()`) is performed without first preserving/transferring state (accrued-but-unclaimed rewards) that is keyed to the destroyed object, and the system has no other path to reach that state afterward. GitHub Desktop has a structurally identical pattern: Desktop-created stash entries are keyed only by branch name (a string embedded in the stash commit message), and are only ever looked up "by current branch" in the UI and store. When a branch is renamed, Desktop explicitly re-keys the stash to the new name via `moveStashEntry`. But when a branch is deleted, Desktop deletes the branch (and possibly the upstream) without any equivalent re-keying or preservation step for its stash entry.

### Finding Description
`_renameBranch` in `app/src/lib/stores/app-store.ts` explicitly finds `gitStore.desktopStashEntries.get(branch.name)` and calls `moveStashEntry(repository, stashEntry, newName)` to re-associate the stash entry with the branch's new name so it stays reachable: [1](#0-0) 

By contrast, `_deleteBranch` checks out a fallback branch and then permanently deletes the local (and optionally upstream) branch, with no lookup of `gitStore.desktopStashEntries.get(branch.name)` and no call to `moveStashEntry` or any preservation step: [2](#0-1) 

The underlying git stash reflog entry (`refs/stash`) itself is not deleted — `getStashes` still finds it and Desktop still classifies it as a "Desktop entry" via the `!!GitHub_Desktop<branchName>` marker in the commit message: [3](#0-2) [4](#0-3) 

However, the only two ways the app surfaces a stash entry to the user are (1) `currentBranchStashEntry`, which strictly matches the entry map key against the name of the **currently checked-out** branch, and (2) `getLastDesktopStashEntryForBranch(repository, branch)`, which requires a `Branch` object/name that must exist: [5](#0-4) 

Once the branch is deleted, there is no `Branch` with that name anymore, so `currentBranchStashEntry` never matches it (the user is now on a different branch), and nothing in the codebase iterates `desktopStashEntries` by all keys to surface "orphaned" entries to the UI. The `onGitStoreUpdated` handler in `app-store.ts` only ever reads `gitStore.currentBranchStashEntry` to decide what to show/select, reinforcing that only the current branch's entry is ever visible: [6](#0-5) 

The stash blob is not corrupted or lost at the git level, but from the product's perspective the user's uncommitted, stashed changes become unreachable through any Desktop UI path once the source branch is deleted — mirroring the veNFT case where the reward accounting object still technically "exists" (in an already-elapsed epoch) but the burned NFT means there's no code path left to reach it.

### Impact Explanation
A user can lose access, through the GitHub Desktop UI, to uncommitted work they explicitly stashed via Desktop, with no warning presented at branch-deletion time. This is a silent, permanent loss of user data reachable purely through normal use of the app's own delete-branch flow (`app/src/ui/delete-branch/delete-branch-dialog.tsx` triggers `_deleteBranch` with no stash check present in that dialog). While the raw commit object underlying the stash remains in the git object database/reflog until garbage collected, discovering and recovering it requires manual command-line git archaeology (`git fsck --unreachable`, reflog inspection) that ordinary Desktop users are not expected to perform — functionally equivalent to loss for the app's target audience.

### Likelihood Explanation
This triggers on the ordinary, unprivileged, single-user workflow: stash changes on branch A via Desktop, switch away, then delete branch A from the Branches list/dialog. No attacker-controlled repository or remote content is required, and no other guard in `_deleteBranch` checks for an associated stash entry before proceeding — unlike `_renameBranch`, which is the only other adjacent branch-mutating code path that does correctly preserve the stash mapping, making the omission in `_deleteBranch` a clear inconsistency rather than an intentional constraint.

### Recommendation
In `_deleteBranch` (`app/src/lib/stores/app-store.ts`), before/after `deleteLocalBranchAndUpstreamBranch`, look up `gitStore.desktopStashEntries.get(branch.name)` and either (a) move it to the branch being checked out (mirroring `_renameBranch`'s use of `moveStashEntry`), or (b) explicitly warn the user in the delete-branch dialog that stashed changes exist and will become inaccessible, requiring confirmation before proceeding, similar to how `createStashAndDropPreviousEntry` explicitly manages stash lifecycle elsewhere.

### Proof of Concept
1. On branch `feature-a`, make working-directory changes and use Desktop's "Stash changes" (invokes `createDesktopStashEntry`, tagging the stash message with `!!GitHub_Desktop<feature-a>`).
2. Switch to `main`.
3. From the Branches list, delete `feature-a` via the delete-branch dialog (`_deleteBranch`); Desktop checks out `main` (already current) and calls `deleteLocalBranchAndUpstreamBranch`, with no reference anywhere to `feature-a`'s stash entry.
4. Reopen the "Stashed changes" UI: `currentBranchStashEntry` looks up the map by `main`, finds nothing; `feature-a`'s stash entry is never shown again anywhere in Desktop, even though `git log -g refs/stash` (run manually outside Desktop) still shows the entry with message `!!GitHub_Desktop<feature-a>`.

    repository: Repository,
    branch: Branch,
    newName: string
  ): Promise<void> {
    const gitStore = this.gitStoreCache.get(repository)
    await gitStore.performFailableOperation(async () => {
      await renameBranch(repository, branch, newName)

      const stashEntry = gitStore.desktopStashEntries.get(branch.name)

  /** This shouldn't be called directly. See `Dispatcher`. */
  public async _deleteBranch(
    repository: Repository,
    branch: Branch,
    includeUpstream?: boolean,
    toCheckout?: Branch | null
  ): Promise<void> {
    return this.withRefreshedGitHubRepository(repository, async repository => {
      const gitStore = this.gitStoreCache.get(repository)

      // If solely a remote branch, there is no need to checkout a branch.
      if (branch.type === BranchType.Remote) {
        const { remoteName, tip, nameWithoutRemote } = branch
        if (remoteName === null) {
          // This is based on the branches ref. It should not be null for a
          // remote branch
          throw new Error(
            `Could not determine remote name from: ${branch.ref}.`
          )
        }

        const remote =
          gitStore.remotes.find(r => r.name === remoteName) ??
          (await getRemoteURL(repository, remoteName)
            .then(url => (url ? { name: remoteName, url } : undefined))
            .catch(e => log.debug(`Could not get remote URL`, e)))

        if (remote === undefined) {
          throw new Error(`Could not determine remote url from: ${branch.ref}.`)
        }

        await gitStore.performFailableOperation(() =>
          deleteRemoteBranch(repository, remote, nameWithoutRemote)
        )

        // We log the remote branch's sha so that the user can recover it.
        log.info(
          `Deleted branch ${branch.upstreamWithoutRemote} (was ${tip.sha})`
        )

        return this._refreshRepository(repository)
      }

      // If a local branch, user may have the branch to delete checked out and
      // we need to switch to a different branch (default or recent).
      const branchToCheckout =
        toCheckout ?? this.getBranchToCheckoutAfterDelete(branch, repository)

      if (branchToCheckout !== null) {
        await gitStore.performFailableOperation(() =>
          checkoutBranch(repository, branchToCheckout, gitStore.currentRemote)
        )
      }

      await gitStore.performFailableOperation(() => {
        return this.deleteLocalBranchAndUpstreamBranch(
          repository,
          branch,
          includeUpstream
        )
      })

      return this._refreshRepository(repository)
    })
  }

export async function getLastDesktopStashEntryForBranch(
  repository: Repository,
  branch: Branch | string
) {
  const stash = await getStashes(repository)
  const branchName = typeof branch === 'string' ? branch : branch.name

  // Since stash objects are returned in a LIFO manner, the first
  // entry found is guaranteed to be the last entry created
  return (
    stash.desktopEntries.find(stash => stash.branchName === branchName) || null
  )
}
