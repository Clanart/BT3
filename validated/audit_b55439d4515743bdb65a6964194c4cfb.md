## Title
Gossip `CrdsValue` signatures omit a cluster/shred-version identifier, allowing cross-cluster replay of non-`ContactInfo` values (e.g. `RestartLastVotedForkSlots`) - ([File: gossip/src/crds_value.rs])

## Summary
The external report's broken invariant is: a signed message digest omits a chain/domain identifier, so a signature that is valid on one chain is also valid on a different chain sharing the same signer key, enabling replay. The closest verified Agave analog is in the gossip layer: `CrdsValue::new` signs only `wincode::serialize(&data)` with no shred-version (cluster identifier) baked into the signed bytes, and the only place shred-version is enforced (`discard_different_shred_version`) special-cases `ContactInfo` but, for every other `CrdsData` variant, accepts the value merely because *some* record already exists for that pubkey in the local Crds table - it does not check that record's shred-version matches. This mirrors the "no chainId in the signed payload" flaw exactly: the signature itself carries no binding to which cluster/network it was produced for.

## Finding Description
`CrdsValue::new` computes the signature over the raw serialized `CrdsData` only: [1](#0-0) 

Nothing about the destination cluster (shred_version, genesis hash, etc.) is folded into the signed bytes for non-`ContactInfo` variants (e.g. `LowestSlot`, `EpochSlots`, `DuplicateShred`, `SnapshotHashes`, `RestartLastVotedForkSlots`, `RestartHeaviestFork`).

The only gate that is supposed to prevent cross-cluster contamination is `discard_different_shred_version`: [2](#0-1) 

For `CrdsData::ContactInfo` it correctly compares the embedded `shred_version()` against `self_shred_version`. But for every *other* variant, the retain predicate is:
```
_ => crds.get_records(&value.pubkey()).next().is_some(),
```
i.e. it keeps the value as long as the local table already has *any* record (of any shred-version/cluster) for that pubkey — it never re-validates that the value's *signed content* corresponds to the receiver's own cluster, because that information was never part of what was signed in the first place.

## Impact Explanation
A validator identity key is frequently reused by an operator across multiple live clusters (mainnet-beta / testnet / devnet all run by the same operator, or a private/permissioned cluster forked from the same genesis). Because the CRDS signature for values like `RestartLastVotedForkSlots` / `RestartHeaviestFork` (used by the wen-restart tooling to decide cluster restart / heaviest-fork consensus) carries no cluster-binding data, a value legitimately signed and broadcast by a validator on Cluster A can be replayed verbatim into Cluster B's gossip mesh where the same pubkey is a validator, and it will pass signature verification (`CrdsValue::verify_with_cache`, which only checks the ed25519 signature over the unmodified bytes) and pass `discard_different_shred_version` once any prior record for that pubkey exists. This can inject fork/slot data attributed to a legitimate validator that was never intended for that cluster, corrupting restart-consensus/gossip state (false-acceptance of gossip data) — the affected outcome class matches "false execution/rooting/acceptance, consensus halt" from the task's valid-impact list.

## Likelihood Explanation
Exploitation requires only capturing publicly broadcast gossip packets from one cluster (gossip is unauthenticated/public by design — no privileged access needed) and re-broadcasting them into a different cluster whose validator set overlaps in identity keys. This is a plausible, unprivileged network-layer replay (not requiring a malicious validator/leaked key — the signer never has to cooperate) but is contingent on operators reusing keys across clusters and on a value type that isn't otherwise re-validated against fresh live state at consumption time; this conditionality lowers confidence relative to a fully generic exploit.

## Recommendation
Bind a cluster-identifying value (shred_version and/or genesis hash) into the signed byte stream for all `CrdsData` variants, not just `ContactInfo`, e.g. by including `shred_version` in `CrdsValue::signable_data()`/the serialized payload that is actually signed, so a signature produced for one cluster cannot verify against another cluster's context. Additionally, `discard_different_shred_version` should validate the *value's own* claimed shred-version (once it's part of the signed data) rather than inferring correctness from the mere existence of any prior record for the same pubkey.

## Proof of Concept
Conceptual (not executed, no runtime access here):
1. Operator runs identity key `K` on both Cluster A (e.g. testnet) and Cluster B (e.g. mainnet-beta).
2. Attacker passively captures a `PushMessage`/`PullResponse` from Cluster A's public gossip containing a `CrdsValue` with `CrdsData::RestartLastVotedForkSlots` signed by `K`.
3. Attacker rebroadcasts the identical bytes into Cluster B's gossip network.
4. `CrdsValue::verify_with_cache` succeeds (signature is over unmodified bytes) at [3](#0-2) .
5. `discard_different_shred_version` retains the value because `crds.get_records(&K).next().is_some()` is true on Cluster B (K already has records there) at [4](#0-3) , even though the value was produced for Cluster A's context.

Note: I was unable to fully trace how each specific consumer (e.g. the restart/wen-restart logic) uses `RestartLastVotedForkSlots` once accepted into the Crds table, since that code path (`gossip/src/restart_crds_values.rs` and downstream consumers) was only located, not read in depth, due to iteration limits — this affects confidence in the precise severity of the downstream consequence and should be verified further before treating this as conclusively "High" severity.

    pub(crate) fn verify_with_cache(&self, cache: &SigVerifyCache) -> bool {
        if cache.verified_values.contains(&self.hash) {
            return true;
        }
        let pubkey = self.pubkey();
        let signable_data = self.signable_data();
        let message = signable_data.borrow();
        let sig_bytes: [u8; 64] = self.signature.into();
        let signature = ed25519_dalek::Signature::from_bytes(&sig_bytes);
        let verified = match cache.verifying_keys.get(&pubkey) {
            Some(vk) => vk.verify_strict(message, &signature).is_ok(),
            None => {
                let Ok(vk) = ed25519_dalek::VerifyingKey::try_from(pubkey.as_ref()) else {
                    return false;
                };
                if vk.verify_strict(message, &signature).is_err() {
                    return false;
                }
                cache.verifying_keys.insert(pubkey, vk);
                true
            }
        };
        if verified {
            cache.verified_values.insert(self.hash);
        }
        verified
    }

// Discards CrdsValues in PushMessages and PullResponses from nodes with
// different shred-version.
fn discard_different_shred_version(
    msg: &mut Protocol,
    self_shred_version: u16,
    crds: &Crds,
    stats: &GossipStats,
) {
    let (values, skip_shred_version_counter) = match msg {
        Protocol::PullResponse(_, values) => (values, &stats.skip_pull_response_shred_version),
        Protocol::PushMessage(_, values) => (values, &stats.skip_push_message_shred_version),
        // Shred-version on pull-request callers can be checked without a lock
        // on CRDS table and is so verified separately (by
        // check_pull_request_shred_version).
        Protocol::PullRequest(..) => return,
        // No CRDS values in Prune, Ping and Pong messages.
        Protocol::PruneMessage(_, _) | Protocol::PingMessage(_) | Protocol::PongMessage(_) => {
            return;
        }
    };
    let num_values = values.len();
    values.retain(|value| match value.data() {
        CrdsData::ContactInfo(ci) => ci.shred_version() == self_shred_version,
        // for any other CRDS types we check if we store anything already
        // for this pubkey, if we do we allow more values in
        _ => crds.get_records(&value.pubkey()).next().is_some(),
    });
    let num_skipped = num_values - values.len();
    if num_skipped != 0 {
        skip_shred_version_counter.add_relaxed(num_skipped as u64);
    }
}
