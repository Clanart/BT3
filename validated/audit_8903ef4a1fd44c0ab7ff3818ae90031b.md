### Title
Attacker-controlled remote can spoof `WWW-Authenticate: realm="GitHub"` to trigger a GitHub Enterprise sign-in flow bound to a non-GitHub host - (File: `app/src/lib/trampoline/trampoline-credential-helper.ts`)

### Summary
`getEndpointKind` in `app/src/lib/trampoline/trampoline-credential-helper.ts:137-179` classifies a git remote as `'enterprise'` (a "GitHub host") solely by inspecting the `wwwauth[]` credential fields Git forwards from the HTTP response of the remote server, matching the string `realm="GitHub"` with a regex, without any independent verification (e.g. calling `isGitHubHost`, which is only used as a fallback) that the host actually runs GitHub Enterprise software.

### Finding Description
When Git performs an HTTP(S) fetch/clone/push against a remote and receives a `401` with a `WWW-Authenticate` header, Git forwards that as `wwwauth[N]=...` fields to the configured credential helper. `getEndpointKind` reads these fields directly: [1](#0-0) 
If the value contains `realm="GitHub"`, the endpoint is unconditionally trusted as `'enterprise'` — i.e., treated as if it were a genuine GitHub Enterprise Server instance — even though this header is entirely attacker-controlled (it comes from the response of whatever server the user cloned/added as a remote, or a proxy sitting in front of it). This is the same class of bug as the report's root cause: a value (here, "this endpoint is a GitHub host") is trusted and propagated to logic that assumes a specific trusted counterpart, without validating that the actual recipient/target can be trusted to handle it.

Once classified `'enterprise'`, `getCredential` (lines 94-135) checks whether an existing account matches `apiEndpoint`; if none exists it calls `ui.promptForGitHubSignIn(endpoint)`: [2](#0-1) 
`promptForGitHubSignIn` then unconditionally starts the Enterprise sign-in flow against the attacker's origin: [3](#0-2) 
`dispatcher.setSignInEndpoint(origin)` and `beginEnterpriseSignIn` are invoked with `origin` taken directly from the untrusted remote URL. This causes GitHub Desktop to run its GitHub Enterprise Server authentication discovery/OAuth flow against a host the attacker controls, presenting the user a native "Sign in to GitHub Enterprise" dialog for a server that is not actually a GitHub product.

### Impact Explanation
This is a spoofing/trust-confusion primitive: a user who clones or adds a remote pointing at an attacker-controlled HTTP git server (or a malicious proxy in front of one) can cause Desktop to present a legitimate-looking "Sign in to GitHub Enterprise" prompt bound to the attacker's host. Users who then attempt to authenticate (via the standard Enterprise OAuth/device flow that Desktop drives against that origin) may have OAuth authorization codes or the resulting session interactions directed at the attacker's server rather than a genuine GitHub Enterprise deployment, risking credential/token exfiltration for the account the user attempts to sign in with. It also produces a persistent, misleading trust indicator in Desktop's UI (host treated as "GitHub host") for a server that is not one.

### Likelihood Explanation
Moderate. It requires the user to interact with an attacker-supplied remote (clone/add a remote to an attacker-controlled or MITM'd HTTP git server) — within the stated valid-impact scope ("a git remote/proxy response") and does not require local/physical access, admin rights, or pre-existing malware. It does require the user to notice and proceed through the resulting sign-in prompt, so it depends on some user interaction, but no unnatural steps beyond normal Desktop usage (adding a remote, fetching/cloning) are needed to trigger the misclassification itself.

### Recommendation
Do not trust the `WWW-Authenticate` realm string alone to classify a host as GitHub/Enterprise. At minimum, corroborate the realm-based heuristic with `isGitHubHost(endpoint)` (already available and used as the fallback path at line 178) before short-circuiting to `'enterprise'`, or require confirmation via the GitHub Enterprise metadata endpoint before invoking `beginEnterpriseSignIn`/`setSignInEndpoint` with an unverified origin.

### Proof of Concept
1. Stand up an HTTP server that responds to Git's credential probe with `WWW-Authenticate: Basic realm="GitHub"` on a `401`.
2. In GitHub Desktop, clone/add this server as a remote and perform an operation requiring authentication (fetch/push).
3. `getEndpointKind` (`trampoline-credential-helper.ts:157-165`) reads the forwarded `wwwauth[]` header, matches `realm="GitHub"`, and returns `'enterprise'`.
4. async function getCredential(cred: Credential, store: Store, token: string) {
  const ghCred = await getGitHubCredential(cred, store)

  if (ghCred) {
    return ghCred
  }

  const endpointKind = await getEndpointKind(cred, store)
  const accounts = await store.getAll()

  const endpoint = `${getCredentialUrl(cred)}`
  const apiEndpoint = getAPIEndpoint(endpoint)

  // If it appears as if the endpoint is a GitHub host and we don't have an
  // account for that endpoint then we should prompt the user to sign in.
  if (
    endpointKind !== 'generic' &&
    !accounts.some(a => a.endpoint === apiEndpoint)
  ) {
    if (getIsBackgroundTaskEnvironment(token)) {
      debug('background task environment, skipping prompt')
      return undefined
    }

    const account = await ui.promptForGitHubSignIn(endpoint)

    if (!account) {
      setHasRejectedCredentialsForEndpoint(token, endpoint)
    }

    return credWithAccount(cred, account)
  }

  // GitHub.com/GHE creds are only stored internally
  if (endpointKind !== 'generic') {
    return undefined
  }

  return useExternalCredentialHelper()
    ? getExternalCredential(cred, token)
    : getGenericCredential(cred, token)
}

  // When Git attempts to authenticate with a host it captures any
  // WWW-Authenticate headers and forwards them to the credential helper. We
  // use them as a happy-path to determine if the host is a GitHub host without
  // having to resort to making a request ourselves.
  for (const [k, v] of cred.entries()) {
    if (k.startsWith('wwwauth[')) {
      if (v.includes('realm="GitHub"')) {
        return 'enterprise'
      } else if (/realm="(GitLab|Gitea|Atlassian Bitbucket)"/.test(v)) {
        return 'generic'
      }
    }
  }

  public promptForGitHubSignIn(endpoint: string): Promise<Account | undefined> {
    return new Promise<Account | undefined>(async resolve => {
      const cb = (result: SignInResult) => {
        resolve(result.kind === 'success' ? result.account : undefined)
        this.dispatcher.closePopup(PopupType.SignIn)
      }

      const { hostname, origin } = new URL(endpoint)
      if (hostname === 'github.com') {
        this.dispatcher.beginDotComSignIn(cb)
      } else {
        this.dispatcher.beginEnterpriseSignIn(cb)
        await this.dispatcher.setSignInEndpoint(origin)
      }

      this.dispatcher.showPopup({
        type: PopupType.SignIn,
        isCredentialHelperSignIn: true,
        credentialHelperUrl: endpoint,
      })
