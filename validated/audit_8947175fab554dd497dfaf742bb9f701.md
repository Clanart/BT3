### Title
`Scanner::scan_block` reports immature coinbase outputs as spendable funds - ([File: networks/bitcoin/src/wallet/mod.rs])

### Summary
The bug class in the external report is "untracked collateral is counted as freely available balance, so the protocol either treats stuck funds as spendable/profit or loses them." The direct analog in `bitcoin-serai` is `Scanner::scan_block`, which scans **every** transaction in a block — including `block.txdata[0]`, the coinbase — and returns matching outputs as ordinary `ReceivedOutput`s. Coinbase outputs are unspendable for 100 blocks (BIP-30 / consensus maturity rule), so a coinbase payout to a Serai address is "funds reported received that are not spendable": the scanner credits balance that cannot actually be moved, exactly like Aegis counting redeem-destined collateral as available profit.

### Finding Description
`Scanner::scan_block` iterates `block.txdata` with no carve-out for the coinbase (`networks/bitcoin/src/wallet/mod.rs:221-227`):

```rust
pub fn scan_block(&self, block: &Block) -> Vec<ReceivedOutput> {
  let mut res = Vec::new();
  for tx in &block.txdata {
    res.extend(self.scan_transaction(tx));
  }
  res
}
```

The doc comment concedes the issue — "This will also scan the coinbase transaction which is bound by maturity. If received outputs must be immediately spendable, a post-processing pass is needed" — but the API still returns the immature output as a fully-formed `ReceivedOutput` with a valid `offset`/`outpoint` (`scan_transaction`, lines 199-214, matches only `script_pubkey`). Nothing in the type distinguishes a coinbase output from a normal one, so any downstream consumer that feeds the result into `SignableTransaction::new` will construct a transaction spending an immature coinbase, which the network rejects — or worse, if accounting relies on the scanned value, the treasury reports funds that are locked.

A realistic reachable scenario requires no special privilege: any miner can include a coinbase output paying to Serai's P2TR script (the external/change/branch scripts are public and computable from the group key). On scan, Serai credits the deposit to the originating protocol/account (mirroring the `presumed_origin` flow), yet the input cannot be spent for 100 blocks. If Serai's plan-acknowledgement/rotation path treats scanned balance as available — or a spend is attempted and fails — the credited balance is stranded inside the vault's accounting, the same "stuck / miscounted collateral" impact as the Aegis report. Note the downstream processor (`processor/src/networks/bitcoin.rs:686-691`) does skip `txdata[1..]` precisely because of maturity, confirming the hazard is real and that `scan_block`'s default behavior is the unsafe one.

### Impact Explanation
Funds are reported received that are not spendable. Concretely:
- A `ReceivedOutput` for an immature coinbase is indistinguishable from a spendable one; attempting to include it in `SignableTransaction` produces a tx the network rejects, causing failed/dropped sign sessions and liveness loss for the rotate/spend path.
- Any balance/availability computation over `scan_block` results overcounts spendable collateral (the "mistaken for profit/available funds" analog), which can drive minting/accounting decisions against unbacked value for up to 100 blocks.

### Likelihood Explanation
Medium. Triggering requires a miner (or a coinbase payout arrangement, e.g., via a mining pool paying to an arbitrary address, or an attacker who mines even one block on a low-difficulty period) to pay to Serai's script. That is within the reach of an unprivileged party sending Bitcoin transactions. Exploitation does not require defeating signatures — it relies purely on the scanner crediting consensus-immature outputs.

### Recommendation
Skip `block.txdata[0]` inside `scan_block` (matching `scan_transaction` usage on `block.txdata[1..]`), or carry an `is_coinbase`/maturity flag on `ReceivedOutput` so consumers cannot mistake immature coinbase outputs for spendable funds.

### Proof of Concept

// Any miner crafts a block whose coinbase pays to Serai's script:

  // coinbase input ...

  ..

let block = Block { header: .., txdata: vec![coinbase] };

// scan_block returns the output as a normal ReceivedOutput:
let outputs = Scanner::new(serai_key).unwrap().scan_block(&block);

// outputs[0] is immature: spending outpoint (coinbase txid, 0) is invalid

  pub fn scan_transaction(&self, tx: &Transaction) -> Vec<ReceivedOutput> {
    let mut res = Vec::new();
    for (vout, output) in tx.output.iter().enumerate() {
      // If the vout index exceeds 2**32, stop scanning outputs
      let Ok(vout) = u32::try_from(vout) else { break };

      if let Some(offset) = self.scripts.get(&output.script_pubkey) {
        res.push(ReceivedOutput {
          offset: *offset,
          output: output.clone(),
          outpoint: OutPoint::new(tx.compute_txid(), vout),
        });
      }
    }
    res
  }
