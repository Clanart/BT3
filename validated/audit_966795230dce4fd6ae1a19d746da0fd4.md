### Title
Unbounded recursion in wallet outer-puzzle driver matching allows attacker-crafted offer to crash the wallet via Python `RecursionError` - ([File: chia/wallet/outer_puzzles.py], [File: chia/wallet/trading/offer.py])

### Summary
The wallet's outer-puzzle driver framework (`match_puzzle`, `get_inner_puzzle`, `get_inner_solution`, `construct_puzzle`) recursively unwraps nested puzzle layers (CAT, singleton, NFT ownership/metadata, CR-CAT) with no depth limit. An offer file (a `WalletSpendBundle` supplied by an untrusted counterparty, parsed via `Offer.from_bytes`/`from_bech32` before any mempool/CLVM cost accounting) can contain a coin spend whose puzzle reveal is nested arbitrarily deeply (e.g. `CAT(CAT(CAT(...(ACS)...)))`). When the local wallet inspects the offer (`Offer.__init__` → `_get_offered_coins()` → `match_puzzle()`/`get_inner_puzzle()`), each layer triggers another Python-level recursive call, eventually hitting Python's recursion limit and raising `RecursionError`, crashing/aborting the wallet's offer-processing/RPC call. This is directly analogous to the rPGP bug class: parsing (not executing) a deeply nested message/puzzle structure crashes the message-handling code before any cost/resource limits apply.

### Finding Description
`match_puzzle()` in `chia/wallet/outer_puzzles.py` dispatches to per-asset-type driver objects (`CATOuterPuzzle`, `SingletonOuterPuzzle`, `OwnershipOuterPuzzle`, `MetadataOuterPuzzle`, `CROuterPuzzle`), each of which recursively calls `self._match(...)` on the puzzle's inner layer when curried args indicate a further inner puzzle: [1](#0-0) [2](#0-1) [3](#0-2) 

`get_inner_puzzle()`, `get_inner_solution()`, and `construct()` follow the same unbounded recursive pattern, each recursing on `constructor.also()` with no maximum depth: [4](#0-3) [5](#0-4) 

None of these entry points execute the puzzle under CLVM cost accounting first — they simply pattern-match the curried structure of the supplied `Program`/`UnknownPuzzle`. This means an attacker can build a puzzle reveal with many stacked outer layers (each layer adds bounded bytes, e.g. one `CAT_MOD.curry(...)` wrapping another) to reach thousands of nesting levels within a puzzle reveal of moderate size, well before any consensus-level cost limit would reject it.

This structure is reached directly from offer processing: `Offer.__init__` computes `_offered_coins` via `_get_offered_coins()`, which calls `match_puzzle(parent_puzzle)` and `get_inner_puzzle(...)` on every coin spend's puzzle reveal in the bundle: [6](#0-5) 

Because `Offer.from_bytes()`/`Offer.from_bech32()` construct an `Offer` object (triggering `_get_offered_coins()` in `__init__`) purely from attacker-supplied bytes — this is exactly the "offer file" a counterparty sends to be inspected via wallet RPC (`get_offer_summary`, `check_offer_validity`, `respond_to_offer`, notification/take-offer flows) — the recursive puzzle-matching runs before the bundle is ever submitted to the mempool or validated for cost.

### Impact Explanation
A malicious offer counterparty can craft an offer file containing a deeply nested outer-puzzle stack (CAT/singleton/ownership/CR layers) attached to one of the offered/settlement coins. When the victim's wallet parses the offer (e.g., via `get_offer_summary`, viewing an incoming offer, or `take_offer`), the recursive driver-matching code raises an uncaught `RecursionError`, aborting the wallet RPC call / offer-processing pipeline. This matches the "spend-triggered transaction-processing halt" impact category: a wallet user or offer counterparty can remotely halt processing of a legitimately-formed but adversarially deep spend/offer without needing any privileged access, mirroring the rPGP crash-via-deep-nesting bug class.

### Likelihood Explanation
High likelihood of triggerability: constructing a `CoinSpend` with a puzzle reveal wrapped in many outer layers (CAT/singleton/ownership) is a normal driver operation already exposed by `construct_puzzle()`; an attacker with wallet tooling access can trivially call these constructors in a loop to build an arbitrarily deep puzzle, embed it in an offer, and send the resulting `.offer` file to a victim. No signature or on-chain validity is required to trigger the crash, since the recursive matching happens purely during local offer inspection, prior to any mempool submission.

### Recommendation
Add an explicit maximum nesting depth (matching or below Python's safe recursion budget, or convert to an iterative work-list) in `match_puzzle()`, `get_inner_puzzle()`, `get_inner_solution()`, and `construct_puzzle()` in `chia/wallet/outer_puzzles.py` and all `*OuterPuzzle` driver implementations (`cat_outer_puzzle.py`, `singleton_outer_puzzle.py`, `ownership_outer_puzzle.py`, `metadata_outer_puzzle.py`, `cr_outer_puzzle.py`). Reject (return `None`/raise a handled `ValueError`) once the depth limit is exceeded instead of allowing unbounded Python recursion, and ensure `Offer.__init__`/`_get_offered_coins()` catches/handles such rejections gracefully instead of propagating an unhandled `RecursionError`.

### Proof of Concept
Conceptual PoC (not run against the target, since only static analysis tools were available):
1. Build an inner puzzle `ACS = Program.to(1)`.
2. Repeatedly wrap it N times (e.g., N = 2000) using `construct_cat_puzzle(CAT_MOD, tail, inner)` as done in `chia/_tests/wallet/cat_wallet/test_cat_outer_puzzle.py` (which already demonstrates double-nesting: `construct_cat_puzzle(CAT_MOD, tail, cat_puzzle)`), producing a puzzle reveal `deep_cat_puzzle`.
3. Construct a `CoinSpend`/`WalletSpendBundle` using `deep_cat_puzzle` as the puzzle reveal for one coin, matching the structure used to build offer files in `chia/wallet/trading/offer.py`.
4. Serialize this into an offer file and call `Offer.from_bytes(offer_bytes)` (as exercised in `chia/_tests/wallet/test_offer_parsing_performance.py`), or invoke the wallet RPC `get_offer_summary` with the crafted offer.
5. Expect `Offer.__init__` → `_get_offered_coins()` → `match_puzzle()`/`get_inner_puzzle()` to recurse N times, ultimately raising `RecursionError` and aborting the RPC call/offer-processing routine. [7](#0-6)

def test_cat_outer_puzzle() -> None:

    tail = bytes32.zeros
    cat_puzzle: Program = construct_cat_puzzle(CAT_MOD, tail, ACS)
    double_cat_puzzle: Program = construct_cat_puzzle(CAT_MOD, tail, cat_puzzle)

    assert cat_driver.type() == "CAT"
    assert cat_driver["tail"] == tail

    assert inside_cat_driver["tail"] == tail
