## Analysis

The Velodrome bug class is: **a reward/benefit is finalized against a stale snapshot of state (voting weight at `EPOCH_END-1`), while a permissionless, attacker-timed action (`distribute()`, called by anyone, anytime after) determines the state actually used, letting an actor collect the reward without reciprocating**. The local Hyperbridge analog with the same shape is in the **bandwidth-subscription cross-chain purchase flow**.

### The mismatch

`BandwidthManager.purchase()` (EVM side) locks in the buyer's **price** at the moment of the call, using the tier price *currently* stored in the manager contract, and dispatches an ISMP `BandwidthPurchaseMsg { app, tier, months, chain }` with `timeout: 0` (never expires): [1](#0-0) 

The corresponding byte/duration allowance is **not** carried in that message. It is looked up live, on the destination (Hyperbridge), at whatever point in time the message happens to be delivered, from the pallet's *current* `Tiers` storage: [2](#0-1) 

The pallet itself documents that these purchase messages are non-timeouting: "Purchases dispatch with `timeout = 0`. If `on_timeout` ever fires it's an invariant violation, not a noop." [3](#0-2) 

`set_tier` (bytes/duration, pallet-side) and `dispatch_set_tiers` (price, manager-side) are two independent, non-atomic governance calls with no versioning or epoch binding between them: [4](#0-3) 

Delivery of ISMP messages to Hyperbridge is permissionless — anyone (including the buyer themselves) can relay a message whenever they choose, and a first-relayer-wins race is the norm elsewhere in this codebase (e.g. `docs/outbound-request-incentivization.md`). So the buyer fully controls *when* their already-paid-for purchase message actually lands on Hyperbridge.

### Exploit path

1. Buyer calls `purchase()` on the EVM `BandwidthManager` for `TierOne` at today's price (e.g. 100 KB / $50), paying the fee token and getting a `commitment`. This is a normal unprivileged user action.
2. Buyer does **not** relay the message immediately — they hold it (or simply relay it themselves later; relaying requires no special permission and the message never times out).
3. At some later point, governance runs a routine, legitimate `set_tier` update that increases `TierOne`'s `bytes`/`duration_secs` (tier improvements over time are an expected, normal operational action, not an attack on governance's part).
4. Buyer now relays the *already-paid* purchase message. `on_accept` reads `Tiers::<T>::get(TierOne)` — the **new, larger** allowance — and credits the buyer with it, for the price locked in at step 1.

This is exactly the report's pattern: a value (bytes/duration) that should be bound to the moment of payment is instead resolved against live, later, mutable state, and the two legs (price commit vs. allowance credit) are connected only by an attacker-controlled delay in an otherwise permissionless relay step — no malicious relayer, admin, or governance actor is required; governance's tier update is a normal action, and the attacker is just an ordinary buyer who chooses when to submit their own already-signed message.

### Impact

Buyers can systematically under-pay for bandwidth allowances by timing delivery of already-purchased, non-expiring messages to land after any future tier improvement, extracting bandwidth value that was never paid for. This directly violates the pivot: *"Bridged assets, order escrow, refunds, paymaster balances, relayer rewards, and bandwidth balances must move exactly once and only to the rightful beneficiary and amount."* — here bandwidth is credited for the **wrong (later, larger) amount** relative to what was paid.

### Recommendation

Bind the byte/duration terms to the purchase at dispatch time rather than resolving them from live pallet state at delivery time — e.g. include a `tier_version`/snapshot of `(bytes, duration_secs)` (or a price/config hash) in the `BandwidthPurchaseMsg`, and have `on_accept` verify it against the tier config that was active at the message's origin timestamp, rejecting or reconciling mismatches instead of blindly applying whatever `Tiers::<T>::get(tier)` currently holds.     function purchase(bytes calldata app, uint256 tier, uint256 months, bytes calldata chain)
        external
        returns (bytes32 commitment)
    {
        if (app.length == 0 || chain.length == 0 || months == 0) revert InvalidPurchase();
        uint256 price18d = tierPrice[tier];
        if (price18d == 0) revert UnknownTier();

        uint256 total18d = price18d * months;
        address feeToken = IDispatcher(_host).feeToken();
        uint8 dec = IERC20Metadata(feeToken).decimals();
        uint256 scale = 10 ** (18 - dec);
        if (total18d % scale != 0) revert PriceNotRepresentable();
        uint256 amount = total18d / scale;

        IERC20(feeToken).safeTransferFrom(msg.sender, address(this), amount);

        BandwidthPurchaseMsg memory body = BandwidthPurchaseMsg({
            app: app,
            tier: tier,
            months: months,
            chain: chain
        });

        commitment = IDispatcher(_host).dispatch(
            DispatchPost({
                dest: IDispatcher(_host).hyperbridge(),
                to: PALLET_BANDWIDTH_MODULE_ID,
                body: abi.encode(body),
                timeout: 0,
                fee: 0,
                payer: address(this)
            })
        );

			Self::deposit_event(Event::TiersDispatched { target, count, commitment });
			Ok(())

	impl<T: Config> IsmpModule for Pallet<T> {
		fn on_accept(&self, request: PostRequest) -> Result<Weight, anyhow::Error> {
			let manager = BandwidthManager::<T>::get(&request.source).ok_or_else(|| {
				anyhow::anyhow!(format!("no bandwidth manager registered for {:?}", request.source))
			})?;

			if request.from != manager.0.to_vec() {
				return Err(anyhow::anyhow!(format!(
					"purchase from unauthorised sender on {:?}: expected {:x?}, got {:x?}",
					request.source, manager.0, request.from
				)));
			}

			let msg = PurchaseMessage::try_from(request.body.as_slice())?;
			let tier = TierIndex::try_from(msg.tier)
				.map_err(|_| anyhow::anyhow!(format!("unknown tier discriminant {}", msg.tier)))?;
			let cfg = Tiers::<T>::get(tier)
				.ok_or_else(|| anyhow::anyhow!(format!("tier {:?} is not configured", tier)))?;

			let bytes = cfg.bytes.saturating_mul(msg.months as u128);
			let duration = cfg.duration_secs.saturating_mul(msg.months as u64);

			let key = AppKey::truncate_from(msg.app);
			let expires_at = Self::push_subscription(&msg.chain, &key, tier, bytes, duration);

			Self::deposit_event(Event::BandwidthCredited {
				app_chain: msg.chain,
				app: key,
				paid_from: request.source,
				tier,
				bytes,
				expires_at,
			});

			Ok(Weight::zero())
		}
