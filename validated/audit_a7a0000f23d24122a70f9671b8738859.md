### Title
Unanchored `issueUrl` regex in `IssueLinkFilter` allows link-text spoofing that disguises attacker-controlled navigation targets as trusted "#N" issue references - (File: `app/src/lib/markdown-filters/issue-link-filter.ts`)

### Summary
`IssueLinkFilter` rewrites an auto-linked anchor's visible text into a clean `#1234`-style GitHub issue/PR/discussion reference, but it never re-validates or anchors the match against the *start* of the URL. Because the regexp built in `issueUrl()` has no `^` anchor, it matches the trusted `https://github.com/owner/repo/issues/1234` pattern anywhere as a **substring** of a much longer, attacker-controlled URL. An attacker can therefore craft a link whose real destination is an arbitrary external host while the filter still recognizes and "beautifies" it into an innocuous `#1234` label. Since `filter()` only mutates `newNode.textContent` on a `node.cloneNode(true)`, the original (malicious) `href` attribute is preserved unchanged and is exactly what `setupLinkInterceptor` reads and forwards to `onMarkdownLinkClicked` on click.

### Finding Description
The regex factory: [1](#0-0) 

builds a pattern `escapeRegExp(gitHubURL) + '/' + owner/repo + '/' + (issues|pull|discussions) + '/' + number` with **no `^` start anchor and no `$` end anchor**. `RegExp.prototype.test`/`match` will happily match this pattern as a substring anywhere inside a longer string.

The tree walker that selects candidate anchors only requires `href === innerText` and that `isGitHubIssuePullDiscussionLink` (which uses the same unanchored `issueUrl` regex) returns true: [2](#0-1) 

Then `filter()` re-runs the same unanchored regex against `textContent` (which equals `href` for an autolinked anchor), extracts `refNumber`/`anchor` from the matched substring, clones the *original* node (preserving its full, unvalidated `href` attribute), and only replaces the visible text: [3](#0-2) 

Because of this, a bare autolinked URL such as:

```
https://evilsite.example/redirect?to=https://github.com/owner/repo/issues/1234
```

- Is autolinked by `marked` with `href === innerText` equal to the full malicious URL.
- Passes DOMPurify's default sanitize step unchanged, since only the URL scheme (`https:`) is checked, not the host — confirmed by the single, default-config `DOMPurify.sanitize(...)` call with no `ALLOWED_URI_REGEXP` override in `app/src/ui/lib/sandboxed-markdown.tsx`.
- Passes `isGitHubIssuePullDiscussionLink` because `https://github.com/owner/repo/issues/1234` appears as a substring of the full malicious href, and none of the disqualifying checks (`isPullRequestTab`, `isURlCustomFormat`) trigger.
- Is accepted by the tree walker (`href === innerText`).
- Is "beautified" by `filter()` into visible text `#1234`, while the anchor's `href` attribute on the cloned node remains the full attacker URL `https://evilsite.example/redirect?to=...`.

When the user clicks what looks like a same-repo issue reference `#1234`, `setupLinkInterceptor` reads the *actual* DOM `a.href` (the attacker's URL) and forwards it verbatim to `onMarkdownLinkClicked`: [4](#0-3) 

Every consumer of this callback (`pull-request-quick-view.tsx`, `pull-request-comment-like.tsx`, `copilot-conflicts-dialog.tsx`, `release-notes-dialog.tsx`) simply opens the URL in the OS default browser via `dispatcher.openInBrowser(url)` / `shell.openExternal(url)`, e.g.: [5](#0-4) 

with no further host verification. The visually-confirmed destination (`#1234`, an internal-looking issue reference) therefore never matches the actual navigation target (an arbitrary external HTTPS URL).

### Impact Explanation
This is a link-spoofing / phishing-enabling defect: attacker-controlled repository content (issue/PR/comment bodies, Copilot conflict-resolution summaries, or any markdown surface rendered through `SandboxedMarkdown` with a `repository` prop) can present a malicious external link disguised as a trustworthy, same-repository `#N` issue reference. This is more deceptive than an ordinary "text says one thing, href says another" markdown link because Desktop actively strips away the visible URL and replaces it with a stylized, contextual label that implies an internal, safe destination — increasing user confidence to click through to a phishing/malware site opened in the default browser. This can be leveraged for credential-phishing pages that imitate GitHub sign-in flows.

### Likelihood Explanation
Any attacker who can post an issue, PR description, PR/review comment, or discussion (or otherwise supply content rendered through `IssueLinkFilter`, e.g. a Copilot merge-conflict resolution summary consuming untrusted repo content) can trigger this with a single crafted autolinked URL, requiring no special privileges and no unusual victim interaction beyond a normal link click.

### Recommendation
Anchor the `issueUrl` regex to the start (and ideally end) of the string so it cannot match as a substring of a longer URL, e.g. build the pattern with `^` before `escapeRegExp(gitHubURL)` (and consider `$`/`\b` at the very end after the anchor group), and/or explicitly parse `anchor.href` with the `URL` constructor and verify `origin`/`pathname` match the expected repository issue URL exactly, rather than relying on `RegExp.test`/`match` against the raw string.

### Proof of Concept
1. In a repository whose GitHub endpoint is `https://github.com`, create/comment on an issue or PR with body containing only:
   ```
   https://evilsite.example/redirect?to=https://github.com/owner/repo/issues/1234
   ```
2. Open the issue/PR in GitHub Desktop (rendered via `SandboxedMarkdown`/`IssueLinkFilter`).
3. Inspect the rendered anchor before/after `applyFilters()`:
   - Before: `<a href="https://evilsite.example/redirect?to=https://github.com/owner/repo/issues/1234">https://evilsite.example/redirect?to=https://github.com/owner/repo/issues/1234</a>`
   - After: `<a href="https://evilsite.example/redirect?to=https://github.com/owner/repo/issues/1234">#1234 </a>` — the `href` attribute is unchanged, only the visible text changed.
4. Click the displayed `#1234` link; observe `setupLinkInterceptor` invokes `onMarkdownLinkClicked('https://evilsite.example/redirect?to=https://github.com/owner/repo/issues/1234')`, which opens the attacker's site in the default browser instead of the expected GitHub issue page.
