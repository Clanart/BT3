## Finding: Automatic, unconfirmed rewrite of a git remote URL from untrusted GitHub API data

### Title
Silent, unconfirmed rewriting of a repository's git remote URL from GitHub API repository data enables remote hijacking - (File: `app/src/lib/stores/updates/update-remote-url.ts`)

### Summary
This is the closest Desktop analog to the M-3 pattern: a value (`works[tokenId].strategy.royaltyBps`) is mutated by one code path (`setFeeStrategy`/`publish`) without updating a dependent, security-relevant piece of state (`ERC2981` token royalty), so two sources of truth for the same fact silently diverge and one of them is trusted downstream. In Desktop, the analogous broken invariant is: **the local git remote URL, which the user has full control over and which determines where their commits are pushed/fetched, gets silently overwritten based on data returned by the GitHub API for an owner/name pair — without re-verifying that the API-returned repository is actually the same trust anchor the user originally added.**

### Finding Description
`updateRemoteUrl()` [1](#0-0)  automatically calls `gitStore.setRemoteURL(...)` to change the on-disk git `origin` remote whenever:
- the local remote currently matches the *previously cached* `gitHubRepository.cloneURL` from the local DB (`remoteUrlUnchanged`), and
- the protocol of the new API-supplied `clone_url` matches the old remote's protocol, and
- the new API-supplied `clone_url` differs from the current remote URL [2](#0-1) 

This is invoked from `repositoryWithRefreshedGitHubRepository()`, which re-resolves the GitHub repository for an existing local repo purely from parsing the current remote's `owner/name` (via `matchGitHubRepository`) and then calls `api.fetchRepository(owner, name)`: [3](#0-2) . `matchGitHubRepository()` only checks that the remote's hostname matches an account's endpoint and extracts `owner`/`name` from the URL text — it performs no identity check tying the result back to the previously known repository (e.g. no comparison of a stable repo ID): [4](#0-3) .

The invariant that should hold — "the locally configured remote is the same trust anchor the user intentionally added, unless the user explicitly changes it" — is broken because Desktop trusts whatever `owner/name` currently resolves to on GitHub.com and rewrites the local git config to match it, with no user confirmation and no verification that the returned repository is a continuation of the original one (e.g., checking a persistent GitHub repository `id`, not just the URL). Unlike the manual `Repository Settings > Remote` flow, which explicitly asks the user to type/confirm a new URL [5](#0-4) , this automated path changes the remote as a side effect of a background repository refresh.

### Impact Explanation
If a repository is deleted/renamed such that the `owner/name` combination becomes claimable by a different account (a classic "repo-jacking"/reclaimed-namespace scenario), or if the original repository is transferred and an attacker manages to get the same `owner/name` slug to resolve to attacker-controlled content, the next background refresh will silently rewrite the victim's local `origin` remote to point at the attacker's `clone_url`. From then on:
- Subsequent `git push` operations by the user go to the attacker's repository (data/IP exfiltration — “silent corruption of what the user pushes”).
- Subsequent `git fetch`/`pull` operations bring in attacker-controlled commits that the user may believe come from the original trusted repository (“silent corruption of what the user commits”, since local branches can be fast-forwarded from attacker history).

This matches the requested class: attacker controls a GitHub API object (the repository resolved for `owner/name`) and the result is silent corruption of the user's push/pull destination, without any local access, malware, or leaked credentials required.

### Likelihood Explanation
This code path runs automatically as part of Desktop's routine background repository refresh (`repositoryWithRefreshedGitHubRepository`), not on user-initiated action, so it requires no unusual steps from the victim. The trigger condition — `remoteUrlUnchanged` — is the common case (most users never manually edit `origin`), so any repo whose `owner/name` becomes re-resolvable to different content is affected the next time Desktop refreshes it in the background. The existing guards (`protocolsMatch`, `urlsMatch`, `remoteUrlUnchanged`) only check URL *shape* consistency, not repository *identity*, so they do not prevent the hijack.

### Recommendation
Do not silently rewrite the local remote from freshly fetched API data based solely on `owner/name` string matching. Before calling `setRemoteURL`, verify a stable identity signal (e.g., compare the previously stored GitHub repository's persistent `id`/`node_id` against the one now returned by `fetchRepository`) and, if the identity check can't confirm continuity, surface the discrepancy to the user for explicit confirmation (similar to the existing manual "Remote" tab flow in `repository-settings.tsx`) instead of updating `git-store.ts`'s remote automatically.

### Proof of Concept
1. User adds `https://github.com/victim-org/project` as `origin` in Desktop; Desktop stores `gitHubRepository.cloneURL = https://github.com/victim-org/project`.
2. `victim-org/project` is deleted or the org name is released/renamed, and `attacker/project` (or a repo an attacker registers under the reused `victim-org/project` slug) becomes reachable at the same URL path.
3. On the next background refresh, `repositoryWithRefreshedGitHubRepository` calls `matchGitHubRepository` (matches purely on hostname + URL text) then `api.fetchRepository('victim-org', 'project')`, which now returns the attacker's `IAPIRepository` with `clone_url` pointing at the attacker's actual storage location/mirror.
4. `updateRemoteUrl` sees `remoteUrlUnchanged === true` (local remote still matches old cached clone URL), protocols match, `urlsMatch === false`, and calls `gitStore.setRemoteURL('origin', attackerCloneUrl)` — rewriting the user's `.git/config` without any dialog or confirmation. [6](#0-5) 
5. The user's next push/fetch silently targets the attacker's remote. [7](#0-6)

  // Verify that protocol hasn't changed. If it has we don't want
  // to alter the protocol in case they are relying on a specific one.
  // If protocol is null that implies the url is a ssh url
  // of the format git@github.com:octocat/Hello-World.git, which
  // can't be parsed by URL.parse. In this case we assume the user
  // manually configured their remote to use this format and we don't
  // want to change what they've done just to be safe
  const parsedRemoteUrl = URL.parse(remoteUrl)
  const parsedUpdatedRemoteUrl = URL.parse(updatedRemoteUrl)
  const protocolsMatch =
    parsedRemoteUrl.protocol !== null &&
    parsedUpdatedRemoteUrl.protocol !== null &&
    parsedRemoteUrl.protocol === parsedUpdatedRemoteUrl.protocol

  // Check if the default remote url has been manually changed from the
  // clone url retrieved from the GitHub API previously
  const remoteUrlUnchanged =
    gitStore.defaultRemote &&
    urlMatchesRemote(gitHubRepository.cloneURL, gitStore.defaultRemote)

  if (protocolsMatch && remoteUrlUnchanged && !urlsMatch) {
    await gitStore.setRemoteURL(gitStore.defaultRemote.name, updatedRemoteUrl)
  }

  private async repositoryWithRefreshedGitHubRepository(
    repository: Repository
  ): Promise<Repository> {
    const repoStore = this.repositoriesStore
    const match = await this.matchGitHubRepository(repository)

    // TODO: We currently never clear GitHub repository associations (see
    // https://github.com/desktop/desktop/issues/1144). So we can bail early at
    // this point.
    if (!match) {
      return repository
    }

    const { account, owner, name } = match
    const { endpoint } = account
    const api = API.fromAccount(account)
    const apiRepo = await api.fetchRepository(owner, name)

    if (apiRepo === null) {
      // If the request fails, we want to preserve the existing GitHub
      // repository info. But if we didn't have a GitHub repository already or
      // the endpoint changed, the skeleton repository is better than nothing.
      if (endpoint !== repository.gitHubRepository?.endpoint) {
        const ghRepo = await repoStore.upsertGitHubRepositoryFromMatch(match)
        return repoStore.setGitHubRepository(repository, ghRepo)

      return repository
    }

      const gitStore = this.gitStoreCache.get(repository)
      await updateRemoteUrl(gitStore, repository.gitHubRepository, apiRepo)
    }

export function matchGitHubRepository(
  accounts: ReadonlyArray<Account>,
  remote: string
): IMatchedGitHubRepository | null {
  for (const account of accounts) {
    const htmlURL = getHTMLURL(account.endpoint)
    const { hostname } = URL.parse(htmlURL)
    const parsedRemote = parseRemote(remote)

    if (parsedRemote !== null && hostname !== null) {
      if (parsedRemote.hostname.toLowerCase() === hostname.toLowerCase()) {
        return { name: parsedRemote.name, owner: parsedRemote.owner, account }
      }
    }
  }

  return null
}
