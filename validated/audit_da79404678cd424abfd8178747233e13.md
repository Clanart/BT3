### Title
Persistent, unrevocable `safe.directory` trust exceptions let a later-compromised repository path silently regain arbitrary Git-hook execution - (File: `app/src/lib/git/config.ts`)

### Summary
GitHub Desktop lets a user "Trust" a Git repository whose ownership looks suspicious (Git's `dubious ownership` / unsafe-repository protection). Trusting a path calls `addSafeDirectory()`, which permanently appends the path to the **global** `safe.directory` Git config. Desktop exposes no corresponding "untrust"/"revoke" action anywhere in its UI or dispatcher, so once a path is trusted it stays trusted for the lifetime of the user's global `.gitconfig`, regardless of what later happens to the content at that path.

### Finding Description
`addSafeDirectory` writes the trusted path into the global config and never removes it: [1](#0-0) 

This is invoked from the two UI surfaces where Desktop detects an "unsafe" repository owned by a different user — adding an existing repository and reopening a missing/relocated one: [2](#0-1) [3](#0-2) 

A repo-content search for any code path that removes a value from `safe.directory` finds none — `removeConfigValue`/`removeGlobalConfigValue` exist generically for other config keys, but nothing in the codebase ever calls `--unset-all safe.directory <path>`. The only Git-config helper Desktop ships for `safe.directory` is additive (`addGlobalConfigValueIfMissing`): [4](#0-3) 

This exactly mirrors the report's broken invariant: a privileged flag (`isTroveManager`/`isBorrowerOperations`-equivalent — here, "this path is safe to run Git in without ownership checks") is granted once and can never be revoked by the application. Git's own `safe.directory` mechanism exists specifically to stop Git from acting on a repository whose owner isn't trusted, because an untrusted repository can execute code via `core.hooksPath`, `core.fsmonitor`, filters, aliases, etc. defined in its local `.git/config`. Once Desktop tells Git "trust this exact path forever," any future occupant of that exact filesystem path — e.g., a removable/network drive letter or mount point reused by a different, attacker-controlled repository, or a directory that is deleted and recreated by an attacker with write access — inherits the trust with no re-prompt and no way for the user to revoke it from within Desktop.

### Impact Explanation
If the trusted path is later repopulated by attacker-controlled content (a realistic scenario for shared machines, network shares, removable media, or any path reuse after the original repo is removed/relocated), Git will skip the "dubious ownership" check entirely and honor local repository config such as `core.hooksPath`, `core.fsmonitor`, clean/smudge filters, or `core.sshCommand`, resulting in arbitrary command execution the next time Desktop performs any Git operation (fetch, checkout, commit, etc.) against that path — all without the safety prompt the trust mechanism was designed to enforce. This satisfies "code execution via a git remote/cloned-repository path with no local/physical-access prerequisite beyond normal Desktop usage."

### Likelihood Explanation
Exploitation requires only that: (1) a user at some point trusted a path via Desktop's built-in "Trust repository" flow (an expected, common action for legitimate multi-user/shared-drive workflows), and (2) that same path is later reoccupied by different, attacker-influenced content (e.g., re-mounted network share, re-inserted USB drive, directory recreated after deletion). No admin rights, malware, or leaked credentials are needed — the attacker only needs to be able to place a Git repository at a path Desktop previously marked safe. Because Desktop provides no expiration, audit, or revoke UI for `safe.directory` entries, the trust silently persists indefinitely, unlike Git's own CLI users who can manually edit `~/.gitconfig`.

### Recommendation
Add a way to view and revoke Desktop-granted `safe.directory` entries (e.g., a settings panel listing trusted paths with a "Remove" action calling `git config --global --unset-all safe.directory <path>`), and consider re-validating trust (e.g., by prompting again) when a previously-missing/relocated repository is restored at a trusted path, rather than treating path equality as permanent proof of continued trustworthiness.

### Proof of Concept
1. Add an existing repository located on a shared/removable path (e.g. `E:\shared-repo`) that Git flags as unsafe (different owner). Click "Trust repository" in `AddExistingRepository`/`MissingRepository` — Desktop calls `addSafeDirectory('E:\shared-repo')`, permanently adding it to the user's global `.gitconfig`.
2. User later removes the drive/share; the same drive letter/mount point (`E:\shared-repo`) is subsequently reused for a different repository, this time populated by an attacker with a malicious `.git/config` (`core.fsmonitor = calc.exe` or `core.hooksPath` pointing at a malicious hook).
3. User reconnects the drive and reopens/refreshes the repository in Desktop, or Desktop's "Locate…"/auto re-scan finds a repo at the same path.
4. Because `safe.directory` still contains that exact path, Git performs no ownership re-check and Desktop happily runs Git commands against it, executing the attacker's `core.fsmonitor`/hook payload — with no re-prompt, since Desktop has no mechanism to revoke the earlier trust grant.

```typescript
/**
 * Adds a path to the `safe.directories` configuration variable if it's not
 * already present. Adding a path to `safe.directory` will cause Git to ignore
 * if the path is owner by a different user than the current.
 */
export async function addSafeDirectory(path: string) {
  // UNC-paths on Windows need to be prefixed with `%(prefix)/`, see
  // https://github.com/git-for-windows/git/commit/e394a16023cbb62784e380f70ad8a833fb960d68
  if (__WIN32__ && path[0] === '/') {
    path = `%(prefix)/${path}`
  }

  await addGlobalConfigValueIfMissing('safe.directory', path)
}
```

```typescript
/** Set the global config value by name. */
export async function addGlobalConfigValueIfMissing(
  name: string,
  value: string
): Promise<void> {
  const { stdout, exitCode } = await git(
    ['config', '--global', '-z', '--get-all', name, value],
    __dirname,
    'addGlobalConfigValue',
    { successExitCodes: new Set([0, 1]) }
  )

  if (exitCode === 1 || !stdout.split('\0').includes(value)) {
    await addGlobalConfigValue(name, value)
  }
}
```
