Missing recipient binding in `EncryptedMessage` proof-of-possession lets an accuser substitute another recipient's message and frame an honest sender - (File: crypto/dkg/pedpop/src/encryption.rs)

### Summary
The Schnorr proof of possession on every PedPoP `EncryptedMessage` binds the sender identity and the ciphertext, but not the intended recipient. `Decryption::decrypt_with_proof` and `BlameMachine::blame_internal` therefore accept any ciphertext produced by the accused sender as "the message sent to the accusing recipient". An accusing participant can substitute a copy of the sender's message addressed to a *different* participant, supply a self-generated `EncryptionKeyProof` under their own encryption key, and cause `blame` to attribute fault to the innocent sender — an authentication/spoofing bypass of the blame mechanism analogous to replacing another user's note in Zeppelin.

### Finding Description
`pop_challenge` transcript commits `context`, `nonce`, `key`, `sender`, and `message`, but no recipient field exists (`crypto/dkg/pedpop/src/encryption.rs:302-324`). The sender encrypts to a per-participant key via `Encryption::encrypt`, which ECDHs against `decryption.enc_keys[&participant]` (`encryption.rs:460-467`) — the recipient identity only lives in the key agreement, not in the authenticating signature.

During blame evaluation, `blame_internal` calls `decrypt_with_proof(sender, recipient, msg, proof)` (`crypto/dkg/pedpop/src/lib.rs:582-588`). `decrypt_with_proof` verifies the PoP with `from` = the claimed sender only (`encryption.rs:374-379`), then verifies the accuser-supplied `EncryptionKeyProof` DLEq against `self.enc_keys[&decryptor]` where `decryptor` = the claimed recipient (`encryption.rs:381-390`). Because the accuser knows their own encryption private key, they can produce a valid DLEq for *any* `msg.key`, so the proof check is satisfiable for a message that was never encrypted to them. The resulting keystream decrypts to garbage: `C::F::from_repr` fails or `share_verification_statements(recipient, commitments[sender], share)` is non-identity (`lib.rs:590-605`), and in every such path `blame_internal` returns `sender` as the faulty party.

Nothing elsewhere compensates: `Decryption::register` only authenticates the commitment/`enc_key` map (`encryption.rs:351-362`), and `calculate_share`'s `blames` map (`lib.rs:476-499`) just defers to the same `blame` evaluation.

### Impact Explanation
The blame protocol is the accountability mechanism of PedPoP: its entire purpose is to identify whether the sender or receiver of a secret share was faulty. This flaw lets a malicious recipient publish a "proof" that an honest, correctly-behaving sender sent an invalid share. All honest observers running `BlameMachine::blame`/`AdditionalBlameMachine::blame` will deterministically conclude the innocent sender is faulty, aborting the DKG and pinning fault on the wrong party. In a validator set this enables eviction/slashing of honest participants and lets genuinely faulty sends (e.g., shares sent only to some parties) escape correct attribution, breaking the protocol's liveness and accountability guarantees.

### Likelihood Explanation
Any participant in the DKG can perform this. `EncryptedMessage` ciphertexts are explicitly designed to be shared for blame adjudication — `blame` takes "a copy of the encrypted secret share from the accused sender" and `AdditionalBlameMachine` exists so non-participants can evaluate accusations (`lib.rs:611-632`, `649-682`) — so ciphertexts from the accused sender to third parties are obtainable wherever blame is adjudicated. The attack needs no private state beyond the accuser's own encryption key and only public `blame`/`read` APIs. The only prerequisite is access to one `EncryptedMessage` the accused sender produced for another recipient.

### Recommendation
Bind the intended recipient into `pop_challenge` (e.g., `transcript.append_message(b"recipient", to.to_bytes())`), threading the recipient index through `encrypt`, `Encryption::decrypt`, `decrypt_with_proof`, and `blame_internal`. Bump the transcript version. This makes a substituted ciphertext fail the PoP check, and since an invalid PoP blames `sender`, also consider that a relayed-but-foreign message presented by an accuser is accuser fault — at minimum, recipients will no longer be able to present messages never addressed to them.

### Proof of Concept
Participants: honest sender `A`, malicious recipient `B`, third party `C`. `n >= 3`.

1. DKG round 2 executes normally. `A` produces `EncryptedMessage`s `m_B` (for `B`) and `m_C` (for `C`). `m_C` = `encrypt(rng, context, A, enc_keys_A_view[C], share_for_C)` (`encryption.rs:460-467`).
2. `B` obtains `m_C` (blame messages are broadcast/archived for adjudication).
3. `B` calls `blame(sender: A, recipient: B, msg: m_C, proof: Some(p))` where `p = EncryptionKeyProof { key: ecdh(B_enc_priv, m_C.key), dleq: DLEqProof::prove(.., &[G, m_C.key], &B_enc_priv) }` — constructible because `B` knows `B_enc_priv` (`encryption.rs:487-499`).
4. In `decrypt_with_proof`:
   - `m_C.pop.verify(m_C.key, pop_challenge(context, m_C.pop.R, m_C.key, A, m_C.msg))` passes — the PoP is genuinely `A`'s over `m_C` and no recipient is bound (`encryption.rs:374-379`, `302-324`).
   - `p.dleq.verify(encryption_key_transcript(context), [G, m_C.key], [enc_keys[B], p.key])` passes — valid DLEq under `B`'s key (`encryption.rs:381-390`).
   - `cipher(context, p.key)` decrypts `m_C.msg` to garbage (real key is `ecdh(C_enc_priv, m_C.key)`).
5. `blame_internal` hits `C::F::from_repr` failure (overwhelmingly likely) or a non-identity `share_verification_statements(B, commitments[A], garbage)` (`lib.rs:590-605`), returning `A` as faulty.
6. Every honest `BlameMachine`/`AdditionalBlameMachine` deterministically blames honest `A`; the DKG aborts with `A` marked malicious. [1](#0-0) [2](#0-1) [3](#0-2) [4](#0-3) [5](#0-4)

fn pop_challenge<C: Ciphersuite>(
  context: [u8; 32],
  nonce: C::G,
  key: C::G,
  sender: Participant,
  msg: &[u8],
) -> C::F {
  let mut transcript = RecommendedTranscript::new(b"DKG Encryption Key Proof of Possession v0.2");
  transcript.append_message(b"context", context);

  transcript.domain_separate(b"proof_of_possession");

  transcript.append_message(b"nonce", nonce.to_bytes());
  transcript.append_message(b"key", key.to_bytes());
  // This is sufficient to prevent the attack this is meant to stop
  transcript.append_message(b"sender", sender.to_bytes());
  // This, as written above, doesn't hurt
  transcript.append_message(b"message", msg);
  // While this is a PoK and a PoP, it's called a PoP here since the important part is its owner
  // Elsewhere, where we use the term PoK, the important part is that it isn't some inverse, with
  // an unknown to anyone discrete log, breaking the system
  C::hash_to_F(b"DKG-encryption-proof_of_possession", &transcript.challenge(b"schnorr"))
}
