## Title
Stale owner/name-based GitHub repository re-association allows a name-squatted repo to silently redirect Desktop's push/fetch remote — (File: `app/src/lib/stores/updates/update-remote-url.ts`, `app/src/lib/stores/app-store.ts`)

### Summary
The reported WrappedVault bug is a case of an internal "ownership" record (Dahlia shares assigned to a specific address) becoming stale after the externally-visible unit of ownership (the wrapped ERC20 share) is transferred through a path the accounting logic doesn't intercept. The structurally identical defect in GitHub Desktop is that a local `Repository`'s association to a `GitHubRepository` — and consequently its trusted default push/fetch remote URL — is re-resolved using the **mutable** `owner/name` pair parsed out of the local git remote, rather than the GitHub repository's immutable ID. When the real repository behind that `owner/name` is renamed/deleted and re-registered by someone else (a routine "repo-name-squatting" primitive available to any unprivileged GitHub user), Desktop's own background refresh logic will silently rebind the local repository to the new, attacker-controlled GitHub object and, under a specific but reachable condition, rewrite the user's `origin` remote URL to point at it.

### Finding Description
`repositoryWithRefreshedGitHubRepository` re-derives the GitHub identity of a tracked repository purely from the current default remote's URL: [1](#0-0) 

`matchGitHubRepository` extracts only `{ owner, name }` (case-sensitive host, case-insensitive-ish strings) from the remote URL and looks that up via the API: [2](#0-1) 

`api.fetchRepository(owner, name)` (called at `app/src/lib/stores/app-store.ts:4890`) resolves whatever repository currently occupies that `owner/name` slug on the API endpoint — there is no verification that the returned repository's stable ID matches any previously recorded ID for this local `Repository`. Whatever comes back is unconditionally written into the local database and attached to the `Repository` object: [3](#0-2) 

Once that happens, `updateRemoteUrl` is invoked with the (now attacker-supplied) `apiRepo.clone_url`. Its only safety checks are: (1) the protocol didn't change, and (2) the *current* remote URL still textually matches the *previously stored* `gitHubRepository.cloneURL`: [4](#0-3) 

None of these checks validate repository identity — they only compare URL strings. If the attacker's replacement repository's `clone_url` differs from what's on disk (e.g. different casing/host alias that still parses to a different structural match, or simply because the original owner renamed away and the squatter's repo now legitimately differs), `gitStore.setRemoteURL` is called, silently rewriting `origin` to the attacker's URL — the exact "silent corruption of what the user commits or pushes" impact called out as in-scope.

Even short of that specific remote-rewrite branch firing, the broader invariant break is real and reachable on every call to `repositoryWithRefreshedGitHubRepository` (triggered on `_fetch`, `_selectRepositoryRefreshTasks`, account-change refreshes, `withRefreshedGitHubRepository`, etc. — see call sites in `app/src/lib/stores/app-store.ts:2257`, `:4921-4933`, `:8285-8306`): the local repository's `gitHubRepository` (permissions, private/public flag, parent/fork chain, `cloneURL`) gets swapped for the squatter's object with no ID continuity check, exactly mirroring how WrappedVault kept routing "who owns this" state to the wrong principal after a transfer it didn't validate.

### Impact Explanation
This breaks the invariant that a locally-tracked repository's GitHub identity, once established, can only change via an event that actually keeps the same GitHub object (a real rename/transfer the API surfaces as such), not via unrelated third-party registration of a previously-used `owner/name` string. Consequences:
- Silent rewrite of the trusted `origin` remote to an attacker-controlled clone URL, redirecting subsequent `git push`/`fetch` traffic (and, transitively, credentials sent by the trampoline credential helper for that host) to a destination the user never approved.
- Adoption of attacker-controlled `permissions`, `private`, and `parent` metadata for the repository, which downstream features (branch protection checks, PR/fork remote creation in `_findPullRequestBranch`, "Open on GitHub") trust implicitly.

This satisfies the required bar: unprivileged attacker (anyone who can create/rename a public GitHub repo), no local access, no malware, and the effect is silent corruption of what the user pushes/fetches.

### Likelihood Explanation
The precondition — a repository being renamed/deleted and its old `owner/name` becoming available for someone else to claim — is a known, common GitHub occurrence (org renames, personal account renames, abandoned repos), not something requiring elevated privilege. Desktop refreshes this association routinely in the background (every fetch, every repository selection, every account-list change), so the window of opportunity is continuous rather than one-shot. The remote-URL-rewrite branch specifically requires `protocolsMatch && remoteUrlUnchanged && !urlsMatch`, which is a narrower but still realistically reachable combination (e.g., squatter registers the slug on a different case-normalized form, or the endpoint config differs slightly) — the broader identity-swap (permissions/parent/cloneURL metadata) fires unconditionally whenever `apiRepo !== null`.

### Recommendation
Track and validate GitHub repository identity by the stable numeric ID (already stored as `GitHubRepository.dbID`/API `id`) rather than by `owner/name` alone. `repositoryWithRefreshedGitHubRepository` should refuse to silently reassign a `Repository`'s `gitHubRepository` (and especially should refuse to call `updateRemoteUrl`) when the freshly-fetched `apiRepo.id` differs from the previously recorded ID for that slot — in that case, treat it as a repository move/deletion requiring explicit user confirmation rather than an automatic swap.

### Proof of Concept
1. User A tracks `origin = https://github.com/alice/project` in Desktop; Desktop persists `GitHubRepository{ id: 111, owner: alice, name: project, cloneURL: .../alice/project }`.
2. Alice renames her account or the repository (or deletes it), freeing the `alice/project` slug.
3. An attacker creates a new public repository that reclaims the exact same `owner/name` (or a case variant that Desktop's `caseInsensitiveEquals`-based matching still treats as unchanged), giving it a different `clone_url` value structurally.
4. On the next background refresh (`_fetch`, repository selection, or account list refresh), Desktop calls `matchGitHubRepository` → `api.fetchRepository('alice','project')`, which now returns the attacker's repository object [5](#0-4) .
5. `updateRemoteUrl` evaluates `remoteUrlUnchanged` (true, since the stored `cloneURL` still textually matches the on-disk remote) and `urlsMatch` (false, attacker's `clone_url` differs) and calls `gitStore.setRemoteURL('origin', attackerCloneUrl)` [6](#0-5) , silently repointing the user's push/fetch destination without any prompt.

  private async repositoryWithRefreshedGitHubRepository(
    repository: Repository
  ): Promise<Repository> {
    const repoStore = this.repositoriesStore
    const match = await this.matchGitHubRepository(repository)

    // TODO: We currently never clear GitHub repository associations (see
    // https://github.com/desktop/desktop/issues/1144). So we can bail early at
    // this point.
    if (!match) {
      return repository
    }

    const { account, owner, name } = match
    const { endpoint } = account
    const api = API.fromAccount(account)
    const apiRepo = await api.fetchRepository(owner, name)

    if (apiRepo === null) {
      // If the request fails, we want to preserve the existing GitHub
      // repository info. But if we didn't have a GitHub repository already or
      // the endpoint changed, the skeleton repository is better than nothing.
      if (endpoint !== repository.gitHubRepository?.endpoint) {
        const ghRepo = await repoStore.upsertGitHubRepositoryFromMatch(match)
        return repoStore.setGitHubRepository(repository, ghRepo)
      }

      return repository
    }

    if (repository.gitHubRepository) {
      const gitStore = this.gitStoreCache.get(repository)
      await updateRemoteUrl(gitStore, repository.gitHubRepository, apiRepo)
    }

    const ghRepo = await repoStore.upsertGitHubRepository(endpoint, apiRepo)
    const freshRepo = await repoStore.setGitHubRepository(repository, ghRepo)

    await this.refreshBranchProtectionState(freshRepo)
    return freshRepo

/** Try to use the list of users and a remote URL to guess a GitHub repository. */
export function matchGitHubRepository(
  accounts: ReadonlyArray<Account>,
  remote: string
): IMatchedGitHubRepository | null {
  for (const account of accounts) {
    const htmlURL = getHTMLURL(account.endpoint)
    const { hostname } = URL.parse(htmlURL)
    const parsedRemote = parseRemote(remote)

    if (parsedRemote !== null && hostname !== null) {
      if (parsedRemote.hostname.toLowerCase() === hostname.toLowerCase()) {
        return { name: parsedRemote.name, owner: parsedRemote.owner, account }
      }
    }
  }

  return null
}

export async function updateRemoteUrl(
  gitStore: GitStore,
  gitHubRepository: GitHubRepository,
  apiRepo: IAPIRepository
): Promise<void> {
  // I'm not sure when these early exit conditions would be met. But when they are
  // we don't have enough information to continue so exit early!
  if (gitStore.defaultRemote === null) {
    return
  }

  const remoteUrl = gitStore.defaultRemote.url
  const updatedRemoteUrl = apiRepo.clone_url
  const urlsMatch = urlMatchesRemote(updatedRemoteUrl, gitStore.defaultRemote)

  // Verify that protocol hasn't changed. If it has we don't want
  // to alter the protocol in case they are relying on a specific one.
  // If protocol is null that implies the url is a ssh url
  // of the format git@github.com:octocat/Hello-World.git, which
  // can't be parsed by URL.parse. In this case we assume the user
  // manually configured their remote to use this format and we don't
  // want to change what they've done just to be safe
  const parsedRemoteUrl = URL.parse(remoteUrl)
  const parsedUpdatedRemoteUrl = URL.parse(updatedRemoteUrl)
  const protocolsMatch =
    parsedRemoteUrl.protocol !== null &&
    parsedUpdatedRemoteUrl.protocol !== null &&
    parsedRemoteUrl.protocol === parsedUpdatedRemoteUrl.protocol

  // Check if the default remote url has been manually changed from the
  // clone url retrieved from the GitHub API previously
  const remoteUrlUnchanged =
    gitStore.defaultRemote &&
    urlMatchesRemote(gitHubRepository.cloneURL, gitStore.defaultRemote)

  if (protocolsMatch && remoteUrlUnchanged && !urlsMatch) {
    await gitStore.setRemoteURL(gitStore.defaultRemote.name, updatedRemoteUrl)
  }
}
