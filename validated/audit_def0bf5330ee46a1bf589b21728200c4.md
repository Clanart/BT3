### Title
Payout tx malleability under `SinglePlusAnyoneCanPay` + first-OP_RETURN attribution lets an attacker (the withdrawal-UTXO owner) forge operator attribution for withdrawal index i via a decoy-first, real-second double-OP_RETURN transaction - (File: `core/src/verifier.rs`, `circuits-lib/src/bridge_circuit/mod.rs`)

### Summary
The payout transaction's input 0 is signed with `TapSighashType::SinglePlusAnyoneCanPay`, which only commits to input 0 and output 0 [1](#0-0) , so anyone holding the input UTXO's key (the withdrawer, per the granted threat model) can reconstruct the honest operator's broadcast payout tx with extra self-funded inputs and completely different remaining outputs, while output 0 stays byte-identical. Because attribution is derived by `get_first_op_return_output`, which just returns the first `is_op_return()` output with no uniqueness or structural check [2](#0-1) , an attacker can insert a decoy OP_RETURN before the operator's legitimate one and get their malleated, higher-fee variant mined first, corrupting the `withdrawals.payout_payer_operator_xonly_pk` attribution for the honest fronting operator.

### Finding Description
Binding claimed broken: `withdrawals.payout_payer_operator_xonly_pk` (for withdrawal index i) == the xonly pk of the operator whose advanced funds fund output 0 of the mined payout tx for index i.

Path:
1. The withdrawal UTXO and its funding value are registered by whoever calls the Citrea Bridge contract's `withdraw`/`safeWithdraw` (attacker-controlled) and the accompanying `input_signature` must be `SinglePlusAnyoneCanPay`, enforced at parse time [3](#0-2) .
2. `Operator::withdraw` verifies this same-index UTXO and signature, then builds `create_payout_txhandler` with output 0 = user payout, output 1 = anchor, output 2 = OP_RETURN(operator_xonly_pk) [4](#0-3) , and funds/broadcasts it via `fund_raw_transaction`/RBF [5](#0-4) .
3. Because `SinglePlusAnyoneCanPay` only signs input 0 + output 0, the attacker (who controls the private key backing that specific input, per the granted capability to "choose... a Schnorr signature and its sighash flag") can build a variant keeping input 0's signature and output 0 identical, but adding an attacker-funded fee input and replacing outputs 1..n with, e.g., a decoy first OP_RETURN (bogus/garbage bytes) followed by the honest operator's real OP_RETURN, then relay/mine this variant with a higher fee ahead of the operator's original broadcast.
4. `update_finalized_payouts` locates "the" payout tx purely by which tx spent the registered withdrawal outpoint, with no binding to a specific expected txid or output layout [6](#0-5) [7](#0-6) . It then stores whatever `parse_op_return_data`/`XOnlyPublicKey::from_slice` on the FIRST OP_RETURN yields — wrong or `None` — via `update_payout_txs_and_payer_operator_xonly_pk` [8](#0-7) .
5. `is_kickoff_malicious` later compares this corrupted DB value against the honest operator's real kickoff `operator_xonly_pk`; mismatch or `None` unconditionally marks the honest operator's kickoff malicious [9](#0-8) . The same first-OP_RETURN logic is also used by the bridge/BitVM circuit itself to compute `deposit_constant` for disprove/assert verification [10](#0-9) , so the wrong pk propagates into consensus-relevant proof data as well.

No existing guard rejects this: `get_first_op_return_output` performs no count/uniqueness check on OP_RETURN outputs, and no code validates that the mined payout tx matches an operator-committed txid or output template before recording attribution.

### Impact Explanation
The honest operator that genuinely advanced funds for withdrawal index i can be misattributed as `None` or as a different (bogus/attacker-chosen) xonly pk in the `withdrawals` table. Downstream, `is_kickoff_malicious` flags their legitimate kickoff as malicious, and the same corrupted-OP_RETURN-derived key feeds `deposit_constant` in the bridge circuit used for disprove verification — both paths risk the honest operator being challenged/disproved and their collateral burned, or being permanently unable to be reimbursed for a payout they genuinely funded. This is repeatable for any withdrawal where the withdrawer (attacker) can observe the operator's unconfirmed payout tx and outbid it, i.e., any withdrawal processed by any operator, matching the Critical category "an honest operator's collateral burned" / "reimbursement impossibility."

### Likelihood Explanation
Preconditions are the ones granted by the threat model: the attacker is the withdrawer, controls the withdrawal UTXO's key and its `SinglePlusAnyoneCanPay` signature, and can fund an extra input to outbid the operator's fee. No consensus rule limits the number of OP_RETURN outputs in Bitcoin, so constructing the decoy-first/real-second variant is trivial. The only cost is fee-bidding to get the malleated variant mined before the operator's original broadcast, which is a modest, one-time cost per withdrawal and is repeatable across every withdrawal/operator.

### Recommendation
Do not derive payout attribution by scanning for "the first OP_RETURN" in whatever transaction happens to spend the registered withdrawal outpoint. Instead: (a) have the operator's `withdraw` RPC persist the exact payout txid/transaction it constructed and signed, and only accept that specific txid (or a transaction whose output 0 and OP_RETURN content is verified against the operator's own commitment) as authoritative; (b) reject/flag payout transactions containing more than one OP_RETURN output; (c) bind attribution to a signed/committed operator identity rather than trusting arbitrary OP_RETURN bytes that any third party can place ahead of the legitimate one.

pub fn create_payout_txhandler(
    input_utxo: UTXO,
    output_txout: TxOut,
    operator_xonly_pk: XOnlyPublicKey,
    user_sig: taproot::Signature,
    _network: bitcoin::Network,
) -> Result<TxHandler<Signed>, BridgeError> {
    let txin = SpendableTxIn::new_partial(input_utxo.outpoint, input_utxo.txout);

    let output_txout = UnspentTxOut::from_partial(output_txout.clone());

    let op_return_txout = op_return_txout(PushBytesBuf::from(operator_xonly_pk.serialize()));

    let mut txhandler = TxHandlerBuilder::new(TransactionType::Payout)
        .with_version(NON_STANDARD_V3)
        .add_input(
            NormalSignatureKind::NotStored,
            txin,
            SpendPath::KeySpend,
            DEFAULT_SEQUENCE,
        )
        .add_output(output_txout)
        .add_output(UnspentTxOut::from_partial(anchor_output(
            NON_EPHEMERAL_ANCHOR_AMOUNT,
        )))
        .add_output(UnspentTxOut::from_partial(op_return_txout))
        .finalize();
    txhandler.set_p2tr_key_spend_witness(&user_sig, 0)?;
    txhandler.promote()
}

    /// Returns the withdrawal indexes and their spending txid for the given
    /// block id.
    pub async fn get_payout_txs_for_withdrawal_utxos(
        &self,
        tx: Option<DatabaseTransaction<'_>>,
        block_id: u32,
    ) -> Result<Vec<(u32, Txid)>, BridgeError> {
        let query = sqlx::query_as::<_, (i32, TxidDB)>(
            "SELECT w.idx, bsu.spending_txid
             FROM withdrawals w
             JOIN bitcoin_syncer_spent_utxos bsu
                ON bsu.txid = w.withdrawal_utxo_txid
                AND bsu.vout = w.withdrawal_utxo_vout
             WHERE bsu.block_id = $1",
        )
        .bind(i32::try_from(block_id).wrap_err("Failed to convert block id to i32")?);

        let results = execute_query_with_tx!(self.connection, tx, query, fetch_all)?;

        results
            .into_iter()
            .map(|(idx, txid)| {
                Ok((
                    u32::try_from(idx).wrap_err("Failed to convert withdrawal index to u32")?,
                    txid.0,
                ))
            })
            .collect()
    }

    /// Sets the given payout txs' txid and operator index for the given index.
    pub async fn update_payout_txs_and_payer_operator_xonly_pk(
        &self,
        tx: Option<DatabaseTransaction<'_>>,
        payout_txs_and_payer_operator_xonly_pk: Vec<(
            u32,
            Txid,
            Option<XOnlyPublicKey>,
            bitcoin::BlockHash,
        )>,
    ) -> Result<(), BridgeError> {
        if payout_txs_and_payer_operator_xonly_pk.is_empty() {
            return Ok(());
        }
        // Convert all values first, propagating any errors
        let converted_values: Result<Vec<_>, BridgeError> = payout_txs_and_payer_operator_xonly_pk
            .iter()
            .map(|(idx, txid, operator_xonly_pk, block_hash)| {
                Ok((
                    i32::try_from(*idx).wrap_err("Failed to convert payout index to i32")?,
                    TxidDB(*txid),
                    operator_xonly_pk.map(XOnlyPublicKeyDB),
                    BlockHashDB(*block_hash),
                ))
            })
            .collect();
        let converted_values = converted_values?;

        let mut query_builder = QueryBuilder::new(
            "UPDATE withdrawals AS w SET
                payout_txid = c.payout_txid,
                payout_payer_operator_xonly_pk = c.payout_payer_operator_xonly_pk,
                payout_tx_blockhash = c.payout_tx_blockhash
                FROM (",
        );

        query_builder.push_values(
            converted_values.into_iter(),
            |mut b, (idx, txid, operator_xonly_pk, block_hash)| {
                b.push_bind(idx)
                    .push_bind(txid)
                    .push_bind(operator_xonly_pk)
                    .push_bind(block_hash);
            },
        );

        query_builder
            .push(") AS c(idx, payout_txid, payout_payer_operator_xonly_pk, payout_tx_blockhash) WHERE w.idx = c.idx");

        let query = query_builder.build();
        execute_query_with_tx!(self.connection, tx, query, execute)?;

        Ok(())
    }
