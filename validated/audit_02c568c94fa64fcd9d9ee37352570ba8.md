### Title
Unscoped whole-contract balance sweep in `ManualCompound.compound()` allows theft of other users' unclaimed reward tokens - (File: `rewards/ManualCompound.sol`)

### Summary
`ManualCompound.compound()` distributes registered reward tokens to `msg.sender` based on the entire ERC20 balance currently held by the `ManualCompound` contract, rather than the amount actually produced by the caller's own claim in that transaction. Any wallet can call `compound()` and sweep whatever registered-reward-token balance happens to be sitting in the contract at that moment, regardless of whether that balance was generated by the caller's own stake.

### Finding Description
This mirrors the root cause of the referenced Nextcloud report: a bulk/aggregate operation (there, `copyFromStorage` trusting an entire folder's contents; here, `compound()` trusting the entire contract's token balance) is used as a proxy for "what this specific operation is authorized to move," without re-validating that the aggregate actually corresponds to the caller's own entitlement.

In `compound()`: [1](#0-0) 

- `IMasterMagpie(masterMagpie).multiclaimOnBehalf(_lps, _rewards, msg.sender)` claims rewards for the caller's own stakes based on caller-supplied `_lps`/`_rewards` arrays [2](#0-1) .
- The first loop refunds *non-compoundable* tokens explicitly named in `_rewards[i][j]` by reading `IERC20(token).balanceOf(address(this))` and transferring the *entire* balance to `msg.sender`, not just the amount the caller's claim produced [3](#0-2) .
- The second loop, for every *registered* reward token in `rewards`, again reads `receivedBalance = IERC20(_tokenAddress).balanceOf(address(this))` and forwards/locks/converts the whole balance to `msg.sender` [4](#0-3) .

Because these loops use `balanceOf(address(this))` instead of tracking a before/after delta scoped to the current call, any token balance already resting in the contract — from another user's partially-processed compound, dust left after a previous `safeApprove`/convert/lock call, or tokens sent to the contract by any other path — is attributed entirely to whichever address happens to call `compound()` next. There is no check that the balance being swept was actually earned by `msg.sender`. `_lps` can even be supplied as an empty array (skipping any real claim) while the registered-rewards loop (`for (uint256 i; i< rewardTokensLength; i++)`) still executes unconditionally and sweeps whatever balance is present.

### Impact Explanation
This is a direct theft-of-user-funds vector: reward tokens belonging to the protocol/other stakers that transiently sit in `ManualCompound` (e.g., due to reentrancy-safe but non-atomic multi-step reward flows, rounding dust from `convertFor`/`lockFor`/`depositFor`, or race conditions between two calls to `compound()`) can be redirected to an attacker who simply calls `compound()` at the right moment, even with a trivial or empty claim. Meets the "direct theft of user funds" / "theft of unclaimed yield" bar.

### Likelihood Explanation
Reachable directly from any unprivileged wallet by calling the external `compound()` function with attacker-chosen `_lps`/`_rewards` (including empty/minimal claims) — no privileged role required. Exploitability depends on there being a non-zero balance of a compoundable/registered reward token in the contract at call time, which can arise naturally from normal operation (dust, front-running another user's in-flight compound, or reentrant-adjacent call ordering across transactions) rather than requiring any admin misconfiguration.

### Recommendation
Track the amount of each token actually received/claimed within the current `compound()` call (e.g., record `balanceOf(address(this))` immediately before `multiclaimOnBehalf` and use the post-call delta, or have `multiclaimOnBehalf`/the reward pool return exact claimed amounts) instead of reading raw `balanceOf(address(this))`. Ensure any leftover/dust balance is either swept to a protocol-controlled sink or accounted per-user, never opportunistically distributed to whichever wallet calls `compound()` next.

### Proof of Concept
1. Contract `ManualCompound` accumulates a balance of a registered reward token (e.g., dust left from a prior `compound()` call whose `convertFor`/`lockFor` invocation didn't consume the full approved/received amount, or tokens sent by another in-flight transaction).
2. Attacker (unprivileged wallet, possibly with zero stake) calls `compound(_lps, _rewards, _convertRatio, _minRec, _lockMgp)` with `_lps` empty or referencing pools where they hold a trivial/no position.
3. `multiclaimOnBehalf` is invoked but has nothing (or little) to actually distribute to the attacker.
4. The unconditional loop `for (uint256 i; i< rewardTokensLength; i++)` in `rewards/ManualCompound.sol:139-159` reads `IERC20(_tokenAddress).balanceOf(address(this))`, which includes the leftover/other-users' balance, and transfers/locks/converts the *entire* amount to `msg.sender` (the attacker), draining funds that were not earned by the attacker's own claim.

    function compound(address[] calldata _lps, address[][] calldata _rewards, uint256 _convertRatio, uint256 _minRec, bool _lockMgp) external {
        uint256 rewardTokensLength = rewards.length;        
        IMasterMagpie(masterMagpie).multiclaimOnBehalf(_lps, _rewards, msg.sender);
        // send none compoundable reward back to caller
        for(uint256 i; i < _lps.length; i++) {
            uint256 rewardLength = _rewards[i].length;
            if (rewardLength > 0) {
                for (uint j; j < rewardLength; j++) {
                    if (!compoundableRewards[_rewards[i][j]]) {
                        uint256 rewardBalance = IERC20(_rewards[i][j]).balanceOf(address(this));
                        if (rewardBalance > 0)
                            IERC20(_rewards[i][j]).safeTransfer(msg.sender, rewardBalance);
                    }
                }
            }
        }
        for (uint256 i; i< rewardTokensLength; i++) {
            address _tokenAddress = rewards[i].tokenAddress;
            address _helperAddress = rewards[i].tokenHelper;
            address _convertor = rewards[i].convertor;
            address _locker = rewards[i].locker;
            uint256 receivedBalance = IERC20(_tokenAddress).balanceOf(address(this));

            if (receivedBalance > 0) {
                if (_convertor != address(0)) {
                    IERC20(_tokenAddress).safeApprove(_convertor, receivedBalance);
                    IConverter(_convertor).convertFor(receivedBalance, _convertRatio, _minRec, msg.sender, 2);
                } else if (_locker != address(0) && _lockMgp) {
                    IERC20(_tokenAddress).safeApprove(_locker, receivedBalance);
                    ILocker(_locker).lockFor(receivedBalance, msg.sender);                        
                } else if (_helperAddress != address(0)) { 
                    IERC20(_tokenAddress).safeApprove(_helperAddress, receivedBalance);
                    ISimpleHelper(_helperAddress).depositFor(receivedBalance, msg.sender);
                } else {
                    IERC20(_tokenAddress).safeTransfer(msg.sender, receivedBalance);
                }
            }
        }

        emit Compounded(msg.sender, rewardTokensLength, _lockMgp);
    }
