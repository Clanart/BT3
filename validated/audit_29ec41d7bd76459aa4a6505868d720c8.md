## Analysis

The key mechanism is `getEndpointKind` in `trampoline-credential-helper.ts`, used by the git credential-helper trampoline whenever Desktop performs an authenticated HTTP(S) git operation (fetch/push/pull/clone) against *any* remote, including a completely untrusted, attacker-controlled server [1](#0-0) .

When Git needs credentials for a host, it forwards any `WWW-Authenticate` response headers it received from that host to the credential helper as `wwwauth[...]` fields. `getEndpointKind` trusts this attacker-suppliable header at face value: if the header contains `realm="GitHub"`, Desktop immediately classifies the endpoint as `'enterprise'` without any network verification (that check is a fallback only used when the header isn't present) [2](#0-1) .

In `getCredential`, once the endpoint is classified as non-generic (`'enterprise'`) and there is no existing account for that exact endpoint, Desktop calls `ui.promptForGitHubSignIn(endpoint)`, which opens a real Sign-in dialog and starts a genuine Enterprise OAuth/browser sign-in flow, but scoped to the **attacker's URL/origin** rather than to any legitimate GitHub Enterprise host [3](#0-2) [4](#0-3) .

The resulting `Account` returned from that sign-in flow is bound to `endpoint = origin-of-attacker-server` and is then handed back as the git credential (`credWithAccount`), which git will submit as Basic-Auth username/password directly to that attacker server [5](#0-4) .

The dialog does display the raw URL to the user ("Git requesting credentials to access …") [6](#0-5) , so a user must click through an OAuth-in-browser sign-in — but nothing prevents an attacker from operating a look-alike "enterprise" remote host that spoofs the `WWW-Authenticate: … realm="GitHub"` header on any push/fetch, at which point Desktop will offer to bind the user's real GitHub Enterprise/GitHub.com OAuth session to that attacker-controlled endpoint and then transmit the resulting token to it as Basic Auth on every future credential request for that same origin.

### Title
Spoofable `WWW-Authenticate: realm="GitHub"` header from a malicious remote drives unauthorized OAuth account binding and token exfiltration - (File: app/src/lib/trampoline/trampoline-credential-helper.ts)

### Summary
`getEndpointKind()` classifies a git remote as a trusted "enterprise" GitHub host purely by trusting the `WWW-Authenticate` response header value that Git forwards from the remote server, before any network-based verification is attempted. A malicious or compromised HTTPS git remote can set this header, causing Desktop to initiate a real Enterprise sign-in flow scoped to the attacker's host and subsequently to send the resulting OAuth-derived credential back to that attacker's server as Basic-Auth on every future authenticated request to it.

### Finding Description
The credential helper's `getEndpointKind` function determines how Desktop treats an unknown remote host by checking, in order: known GitHub/Gist/GHE endpoints, existing accounts, then the attacker-influenced `wwwauth[...]` headers, and only as a last resort a network probe (`isGitHubHost`) [1](#0-0) . Because the `wwwauth[...]` values come straight from HTTP response headers of the (attacker-controlled) remote, and are checked *before* the network verification fallback, an attacker fully controls this classification for any endpoint not already known to Desktop.

Once classified `'enterprise'`, `getCredential` treats the lack of a stored account for that exact endpoint as a cue to prompt the user to sign in for that endpoint via `ui.promptForGitHubSignIn(endpoint)` [7](#0-6) . This triggers a legitimate GitHub Enterprise OAuth/browser sign-in flow, but with `endpoint` set to the attacker's origin, via `beginEnterpriseSignIn` + `setSignInEndpoint(origin)` [4](#0-3) . Whatever `Account` results is then merged into the credential and handed to git (`credWithAccount`) [5](#0-4) , which git will submit to the attacker's server as the HTTP Basic-Auth password — i.e., the user's OAuth token.

No existing guard closes this path: `findGitHubTrampolineAccount`/`isDotCom`/`isGHE` only protect *already-known* hosts by exact-origin matching [8](#0-7) ; they do nothing to stop a *new*, attacker-chosen origin from being classified as "enterprise" via the spoofed header and consequently having credentials bound and exfiltrated to it.

### Impact Explanation
If the account bound to the attacker's endpoint is a real Enterprise Server credential (device/browser token), the token is subsequently sent to the attacker's server as Basic-Auth on every future authenticated interaction with that endpoint — full credential/token exfiltration to an attacker-controlled host, without the attacker needing any local access, admin rights, or prior malware. This matches the "attacker controls … a git remote/proxy response, and the result is … unauthorized OAuth or account binding, credential/token exfiltration."

### Likelihood Explanation
Requires the victim to interact with a malicious/compromised HTTPS remote (clone/fetch/push) and to click through the resulting sign-in prompt, which does disclose the URL. This reduces but does not eliminate the risk, since users are accustomed to enterprise sign-in flows when accessing corporate/self-hosted git servers, and the URL disclosed may look legitimate (e.g., an internal-looking hostname).

### Recommendation
Do not use the attacker-supplied `WWW-Authenticate` realm string alone to elevate trust for previously-unknown hosts. Require the network-based `isGitHubHost` verification (or equivalent authenticated GitHub Enterprise `/meta` check) for any endpoint that isn't already a stored account before offering to bind an OAuth sign-in to it, and clearly warn users when signing in to a brand-new/unverified enterprise endpoint triggered implicitly by a git operation rather than by explicit user action in Preferences.

### Proof of Concept
1. Attacker sets up an HTTPS git server at `https://ghe-mirror.evil.example/org/repo.git` that, on any unauthenticated request, replies `401` with header `WWW-Authenticate: Basic realm="GitHub"`.
2. Victim adds this remote (e.g., lured via a "mirror"/"backup" remote suggestion, or a crafted README instructing them to `git remote add` and `fetch`) and performs a `fetch`/`push` in Desktop.
3. Git invokes Desktop's credential helper with the `wwwauth[]` header captured from the attacker's response; `getEndpointKind` returns `'enterprise'` due to the `realm="GitHub"` match, bypassing the network probe.
4. Desktop shows a Sign-in dialog ("Git requesting credentials to access `https://ghe-mirror.evil.example`") and, if the user completes the browser OAuth flow (which they may do believing this is their real Enterprise instance, especially if the hostname is convincing), an `Account` is created bound to `endpoint = https://ghe-mirror.evil.example`.
5. The resulting login/token is returned to git as the credential and transmitted via Basic-Auth to the attacker's server, and will continue to be sent to that same origin (`findGitHubTrampolineAccount` origin match) on subsequent operations — exfiltrating the token to the attacker on every future interaction with that endpoint.

Note: I could not fully verify end-to-end whether `beginEnterpriseSignIn`'s OAuth flow allows arbitrary/attacker-chosen origins without additional TLS/connectivity checks in `_setSignInEndpoint` — some validation code (`enterprise-validate-url.ts`) exists for protocol/URL syntax but did not appear to perform host-authenticity verification, this is a further point a background agent should confirm against `app/src/lib/stores/app-store.ts` (`_setSignInEndpoint`) before treating this as fully proven.

/** Implementation of the 'get' git credential helper command */
async function getCredential(cred: Credential, store: Store, token: string) {
  const ghCred = await getGitHubCredential(cred, store)

  if (ghCred) {
    return ghCred
  }

  const endpointKind = await getEndpointKind(cred, store)
  const accounts = await store.getAll()

  const endpoint = `${getCredentialUrl(cred)}`
  const apiEndpoint = getAPIEndpoint(endpoint)

  // If it appears as if the endpoint is a GitHub host and we don't have an
  // account for that endpoint then we should prompt the user to sign in.
  if (
    endpointKind !== 'generic' &&
    !accounts.some(a => a.endpoint === apiEndpoint)
  ) {
    if (getIsBackgroundTaskEnvironment(token)) {
      debug('background task environment, skipping prompt')
      return undefined
    }

    const account = await ui.promptForGitHubSignIn(endpoint)

    if (!account) {
      setHasRejectedCredentialsForEndpoint(token, endpoint)
    }

    return credWithAccount(cred, account)
  }

const getEndpointKind = async (cred: Credential, store: Store) => {
  const credentialUrl = getCredentialUrl(cred)
  const endpoint = `${credentialUrl}`

  if (isGist(endpoint)) {
    return 'generic'
  }

  if (isDotCom(endpoint)) {
    return 'github.com'
  }

  if (isGHE(endpoint)) {
    return 'ghe.com'
  }

  // When Git attempts to authenticate with a host it captures any
  // WWW-Authenticate headers and forwards them to the credential helper. We
  // use them as a happy-path to determine if the host is a GitHub host without
  // having to resort to making a request ourselves.
  for (const [k, v] of cred.entries()) {
    if (k.startsWith('wwwauth[')) {
      if (v.includes('realm="GitHub"')) {
        return 'enterprise'
      } else if (/realm="(GitLab|Gitea|Atlassian Bitbucket)"/.test(v)) {
        return 'generic'
      }
    }
  }

  const existingAccount = await findGitHubTrampolineAccount(store, endpoint)
  if (existingAccount) {
    return isDotCom(existingAccount.endpoint) ? 'github.com' : 'enterprise'
  }

  // All GitHub hosts use HTTPS, so if the protocol is not HTTPS we can
  // assume that this is not a GitHub host.
  if (credentialUrl.protocol !== 'https:') {
    return 'generic'
  }

  return (await isGitHubHost(endpoint)) ? 'enterprise' : 'generic'
}

  public promptForGitHubSignIn(endpoint: string): Promise<Account | undefined> {
    return new Promise<Account | undefined>(async resolve => {
      const cb = (result: SignInResult) => {
        resolve(result.kind === 'success' ? result.account : undefined)
        this.dispatcher.closePopup(PopupType.SignIn)
      }

      const { hostname, origin } = new URL(endpoint)
      if (hostname === 'github.com') {
        this.dispatcher.beginDotComSignIn(cb)
      } else {
        this.dispatcher.beginEnterpriseSignIn(cb)
        await this.dispatcher.setSignInEndpoint(origin)
      }

      this.dispatcher.showPopup({
        type: PopupType.SignIn,
        isCredentialHelperSignIn: true,
        credentialHelperUrl: endpoint,
      })
    }).catch(e => {
      log.error(`Could not prompt for GitHub sign in`, e)
      return undefined
    })
  }

export async function findGitHubTrampolineAccount(
  accountsStore: AccountsStore,
  remoteUrl: string
): Promise<Account | undefined> {
  const accounts = await accountsStore.getAll()
  const parsedUrl = new URL(remoteUrl)
  return accounts.find(
    a => new URL(getHTMLURL(a.endpoint)).origin === parsedUrl.origin
  )
