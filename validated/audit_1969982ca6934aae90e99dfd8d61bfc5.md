Found it: `NativeSeiTokensERC20.sol`, the ERC20 pointer contract that wraps native Sei bank denoms for EVM access, overrides OpenZeppelin's `_update` hook but never checks `to != address(0)` (or `from != address(0)`) before forwarding the transfer to the Bank precompile.

### Title
Missing zero-address validation in `NativeSeiTokensERC20._update` allows permanent loss of native-token pointer balances - (File: `contracts/src/NativeSeiTokensERC20.sol`)

### Summary
`NativeSeiTokensERC20` is the ERC20 pointer contract created by the `AddNative` precompile flow (`x/evm/keeper/pointer_upgrade.go` `UpsertERCNativePointer`, `precompiles/pointer/legacy/*/pointer.go` `AddNative`) that exposes a Cosmos native bank denom as an ERC20 token inside the EVM. It overrides OpenZeppelin ERC20's internal `_update(address from, address to, uint256 value)` hook — the modern equivalent of `_beforeTokenTransfer` — to forward the balance change to the real Sei bank module via the Bank precompile's `send` function, instead of maintaining its own ledger.

### Finding Description
`_update` is called by all of ERC20's public `transfer`/`transferFrom` paths. The override contains no guard against `to == address(0)` (nor `from == address(0)`): [1](#0-0) 

Because OpenZeppelin's base `transfer`/`transferFrom` do validate that the caller-supplied `to` is non-zero in newer OZ versions via `_update`'s caller-side checks in some releases, but this contract's `_update` override completely replaces the storage-mutation logic with a call to `BankPrecompile.send(from, to, denom, value)`. The Bank precompile's `send` implementation (`precompiles/bank/bank.go` `send`, mirrored across all `precompiles/bank/legacy/*/bank.go` versions) resolves `to` into a Sei account address and constructs a `banktypes.MsgSend` to the resolved address: [2](#0-1) 

The Cosmos `bank.MsgSend` handler does not reject the "zero address" concept the way ERC20 does — `common.Address(0)` maps to a valid (if unusual) Sei bech32 address that can receive coins. Unless OpenZeppelin's base ERC20 already reverts on `to == address(0)` before calling `_update` (this depends on the exact OZ version vendored, `require(to != address(0), "ERC20: transfer to the zero address")` lives in the public `transfer`/`transferFrom` wrappers only for OZ 4.x; OZ 5.x moved all checks into `_update` itself and the base implementation does check `to != address(0)` when minting/burning but not for regular transfers where it's assumed the caller already validated), a contract that overrides `_update` and skips the check reproduces exactly the audit finding in `BridgedERC20._beforeTokenTransfer`: no explicit `require(to != address(0))` exists in this override at all.

### Impact Explanation
If a user calls `transfer(address(0), amount)` on the native-pointer ERC20, `BankPrecompile.send` will execute a real `MsgSend` moving native denom coins from the sender's Sei account to the account address corresponding to `common.Address(0)`. Since no known private key or module controls that account, and the EVM `balanceOf` for a zero-address pointer would only be observable via bank state, the transferred coins become permanently unrecoverable — a direct loss of funds for the sender, mirroring the reported `BridgedERC20` issue but backed by real native-token custody rather than a synthetic ERC20 ledger.

### Likelihood Explanation
Any EVM account holding a registered native-token ERC20 pointer balance can trigger this by calling `transfer(address(0), amount)` or `transferFrom(..., address(0), amount)` directly through the public JSON-RPC surface — no special privileges, precompile access, or contract deployment beyond the already-existing pointer are required. This is a single, ordinary EVM transaction.

### Recommendation
Add explicit zero-address checks in `NativeSeiTokensERC20._update` (and in the equivalent CW20/CW721/CW1155 pointer contracts' `transfer`/`transferFrom`, though those already have such checks per `CW20ERC20Pointer.sol` lines 79-96) before invoking `BankPrecompile.send`:
```solidity
function _update(address from, address to, uint256 value) internal override {
    require(to != address(0), "NativeSeiTokensERC20: transfer to the zero address");
    bool success = BankPrecompile.send(from, to, denom, value);
    require(success, "NativeSeiTokensERC20: transfer failed");
    emit Transfer(from, to, value);
}
```

### Proof of Concept
1. Register a native-token ERC20 pointer for any bank denom via the `AddNative` precompile call (as exercised in `precompiles/pointer/pointer_test.go` `TestAddNative`).
2. Fund an EVM account with the underlying denom so its `balanceOf` via the pointer is non-zero (as in `contracts/test/ERC20toNativePointerTest.js`).
3. Call `pointer.transfer(address(0), amount)` from that account.
4. Because `_update` in `contracts/src/NativeSeiTokensERC20.sol:45-49` has no zero-address guard, `BankPrecompile.send` executes `bankMsgServer.Send` moving real coins to the Sei address derived from `common.Address(0)`, and the funds cannot be recovered by the sender. [1](#0-0) [3](#0-2)

func (p PrecompileExecutor) send(ctx sdk.Context, caller common.Address, method *abi.Method, args []interface{}, value *big.Int, readOnly bool) ([]byte, uint64, error) {
	if readOnly {
		return nil, 0, errors.New("cannot call send from staticcall")
	}
	if err := pcommon.ValidateNonPayable(value); err != nil {
		return nil, 0, err
	}

	if err := pcommon.ValidateArgsLength(args, 4); err != nil {
		return nil, 0, err
	}
	denom := args[2].(string)
	if denom == "" {
		return nil, 0, errors.New("invalid denom")
	}
	pointer, _, exists := p.evmKeeper.GetERC20NativePointer(ctx, denom)
	if !exists || pointer.Cmp(caller) != 0 {
		return nil, 0, fmt.Errorf("only pointer %s can send %s but got %s", pointer.Hex(), denom, caller.Hex())
	}
	amount := args[3].(*big.Int)
	if amount.Cmp(utils.Big0) == 0 {
		// short circuit
		bz, err := method.Outputs.Pack(true)
		return bz, pcommon.GetRemainingGas(ctx, p.evmKeeper), err
	}
	senderSeiAddr, err := p.accAddressFromArg(ctx, args[0])
	if err != nil {
		return nil, 0, err
	}
	receiverSeiAddr, err := p.accAddressFromArg(ctx, args[1])
	if err != nil {
		return nil, 0, err
	}

	msg := &banktypes.MsgSend{
		FromAddress: senderSeiAddr.String(),
		ToAddress:   receiverSeiAddr.String(),
		Amount:      sdk.NewCoins(sdk.NewCoin(denom, sdk.NewIntFromBigInt(amount))),
	}

	err = msg.ValidateBasic()
	if err != nil {
		return nil, 0, err
	}

	if _, err = p.bankMsgServer.Send(sdk.WrapSDKContext(ctx), msg); err != nil {
		return nil, 0, err
	}

	bz, err := method.Outputs.Pack(true)
	return bz, pcommon.GetRemainingGas(ctx, p.evmKeeper), err
