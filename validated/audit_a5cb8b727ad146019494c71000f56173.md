### Title
Immature coinbase outputs are returned as spendable received outputs - (File: networks/bitcoin/src/wallet/mod.rs)

### Summary
`Scanner::scan_block` scans every transaction in a block, including the coinbase transaction, and returns matching outputs as `ReceivedOutput`, which is documented as “a spendable output.” Because the wallet does not record the output’s confirmation height or whether its containing transaction is coinbase, `SignableTransaction::new` can subsequently construct and sign a transaction spending a coinbase output before its maturity period. This causes funds to be reported and selected as spendable when consensus rules still prohibit spending them. [1](#0-0) [2](#0-1) 

### Finding Description
`scan_block` iterates over `block.txdata` without skipping `txdata[0]` or checking `Transaction::is_coinbase`. `scan_transaction` then matches solely on `output.script_pubkey` and creates a `ReceivedOutput` containing only the offset, `TxOut`, and outpoint. [3](#0-2) [2](#0-1) 

The code comments explicitly acknowledge that coinbase outputs are maturity-bound and require a post-processing pass, but `ReceivedOutput` carries no maturity metadata that would let callers safely distinguish them after scanning. [1](#0-0) [4](#0-3) 

`SignableTransaction::new` accepts those `ReceivedOutput` values directly, sums their values, and places each recorded outpoint into a transaction input without checking coinbase maturity or confirmation count. [5](#0-4) [6](#0-5) 

### Impact Explanation
A wallet scanning a newly accepted block can include a matching coinbase output in its spendable UTXO set before the required maturity interval. The wallet can then construct and coordinate signatures for a transaction that the network will reject as consensus-invalid. The accepted impact is funds reported as received/spendable when they are not yet spendable; operationally, this can also cause repeated failed transaction construction or broadcast attempts until the output matures. [2](#0-1) [6](#0-5) 

### Likelihood Explanation
The path is reachable through ordinary public block data: any valid miner can direct a coinbase output to the wallet’s P2TR script, and `scan_block` is the public API intended to inspect such blocks. Exploitation requires producing a valid block or targeting a wallet that receives mining rewards, so it is less broadly reachable than an arbitrary transaction input, but it does not require access to wallet keys or internal state. [7](#0-6) [8](#0-7) 

### Recommendation
Make maturity status explicit in the scanning and spending interfaces:

- Either skip `block.txdata[0]` in `scan_block` unless the caller supplies a block height and the coinbase has reached maturity, or return a distinct immature-output type.
- Store enough provenance in `ReceivedOutput`—such as `is_coinbase` and confirmation/block height—to let `SignableTransaction::new` reject immature inputs.
- Add a regression test that scans a block whose coinbase pays the scanner key and verifies that the output cannot be passed to `SignableTransaction::new` before maturity.
- Document `scan_transaction`’s behavior for standalone coinbase transactions, since it lacks block-position context. [2](#0-1) [9](#0-8) 

### Proof of Concept
Source-level reproduction:

1. Construct an even-y Taproot wallet key and initialize `Scanner::new(key)`.
2. Build a block whose `txdata[0]` is a coinbase transaction containing an output with `script_pubkey == p2tr_script_buf(key)`.
3. Call `scanner.scan_block(&block)`.
4. The matching coinbase output is returned as a `ReceivedOutput`, with its outpoint set to `(coinbase_txid, vout)`.
5. Pass that `ReceivedOutput` to `SignableTransaction::new` before the coinbase maturity interval.
6. `SignableTransaction::new` creates a `TxIn` for the coinbase outpoint, and the resulting transaction can be passed through the FROST signing machines despite being consensus-unspendable at that height. [8](#0-7) [6](#0-5) [10](#0-9)

  /// Scan a transaction.
  pub fn scan_transaction(&self, tx: &Transaction) -> Vec<ReceivedOutput> {
    let mut res = Vec::new();
    for (vout, output) in tx.output.iter().enumerate() {
      // If the vout index exceeds 2**32, stop scanning outputs
      let Ok(vout) = u32::try_from(vout) else { break };

      if let Some(offset) = self.scripts.get(&output.script_pubkey) {
        res.push(ReceivedOutput {
          offset: *offset,
          output: output.clone(),
          outpoint: OutPoint::new(tx.compute_txid(), vout),
        });
      }
    }
    res
  }

  /// Scan a block.
  ///
  /// This will also scan the coinbase transaction which is bound by maturity. If received outputs
  /// must be immediately spendable, a post-processing pass is needed to remove those outputs.
  /// Alternatively, scan_transaction can be called on `block.txdata[1 ..]`.
  pub fn scan_block(&self, block: &Block) -> Vec<ReceivedOutput> {
    let mut res = Vec::new();
    for tx in &block.txdata {
      res.extend(self.scan_transaction(tx));
    }
    res
  }
