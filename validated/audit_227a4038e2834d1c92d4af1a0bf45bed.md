### Title
Pre-Randao-fork PREVRANDAO opcode returns the fully known parent block hash, enabling predictable "randomness" for any contract that reads it before the Randao hardfork - (File: `blockchain/evm.go`)

### Summary
`NewEVMBlockContext` sets the `Random` field used by the `PREVRANDAO`/`RANDOM` opcode (0x44) to `header.ParentHash` whenever `header.MixHash` is not yet populated, i.e. for any block before the Randao hardfork activates on a given Kaia chain/network. Any contract deployed by an ordinary, unprivileged transaction sender can call this opcode via `opRandom` and receive a value that is deterministically the hash of the previous block - a value that is public, already finalized, and known before the calling transaction is even submitted or mined. [1](#0-0) [2](#0-1) 

This is functionally the same bug class as the ATM BlindBox report: a contract relies on an opcode/field that is supposed to represent unpredictable randomness, but under a specific (here, pre-hardfork) condition it silently falls back to a fully predictable, previously-committed value (`prevrandao`/`parentHash`) instead of erroring out or refusing to provide a "random" value. A caller can read `blockhash`/`parentHash` off-chain (or via any public RPC call) before submitting a transaction that depends on this value, and pre-compute the "random" outcome exactly as the ATM BlindBox attacker pre-computed `keccak256(block.prevrandao, betId, block.timestamp)`.

### Finding Description
- `NewEVMBlockContext` checks `header.MixHash != nil`; if the header does not yet carry the Randao mix hash (i.e., a block produced before the chain's Randao hardfork/`RandaoCompatibleBlock`), it sets `random = header.ParentHash` instead of a genuinely unpredictable value. [1](#0-0) 
- This `random` value becomes `vm.BlockContext.Random`, which `opRandom` (bound to opcode `PREVRANDAO`/`0x44` via `enable4399`) pushes onto the EVM stack whenever a smart contract executes the `PREVRANDAO`/`RANDOM` opcode. [2](#0-1) [3](#0-2) 
- This behavior is confirmed by the project's own integration test, which explicitly asserts `random == header.ParentHash` for every block prior to the Randao fork number: `if num < forkNum { ... assert.Equal(t, header.ParentHash.Bytes(), random, num) }`. [4](#0-3) 
- Any unprivileged EOA can deploy or call an arbitrary contract that reads `block.prevrandao`, and because the parent block's hash is public (retrievable via any public RPC, e.g. `eth_getBlockByNumber`) before the transaction that consumes it is even created, the "randomness" is fully known to the caller ahead of time. This mirrors the ATM BlindBox report's core weakness: `keccak256(block.prevrandao, ...)` is deterministic and computable by the caller in advance because `block.prevrandao` itself is not a fresh random beacon in this code path — it is a value that was fixed and published one block earlier.

### Impact Explanation
Any DeFi/gaming/lottery/auction contract deployed on a Kaia network segment or private network that has not yet activated the Randao hardfork (or during any window before `RandaoCompatibleBlock`) and which relies on `PREVRANDAO`/`block.prevrandao`/`RANDOM` as its randomness source is trivially exploitable by an ordinary caller in the exact same fashion as the ATM BlindBox exploit: the caller can pre-compute the "random" outcome using the already-known parent block hash and only submit/settle when the outcome favors them, resulting in unauthorized value extraction (e.g., guaranteed lottery/auction wins, gambling payouts) from any contract built on this primitive. This is a core-EVM-semantics issue (affects every contract on the chain during the pre-fork window), not merely an isolated dApp bug, since it is baked into `NewEVMBlockContext`, which every transaction execution path uses.

### Likelihood Explanation
High for any pre-Randao-fork Kaia deployment (mainnet migration window, private/test networks that have not enabled the fork, or genesis configs with `RandaoCompatibleBlock` set far in the future): the attack requires no special privilege — only the ability to read the previous block hash from any public RPC endpoint and to submit a normal transaction, exactly matching the reachable actor classes in scope (unprivileged transaction sender / public RPC caller / contract deployer).

### Recommendation
- Do not present `header.ParentHash` as a value equivalent to genuine RANDAO randomness pre-fork; either revert/disallow the `PREVRANDAO` opcode before the Randao hardfork is active, or clearly document/enforce that `PREVRANDAO` is a non-random placeholder (matching legacy `DIFFICULTY` semantics) so dApp developers cannot mistake it for a secure randomness source.
- Consider making the pre-fork fallback in `NewEVMBlockContext` return a fixed sentinel (e.g., zero) rather than `header.ParentHash`, consistent with how other pre-fork opcodes (e.g., `BASEFEE`, `BLOBBASEFEE`) return `ZeroBaseFee` rather than a derivable, predictable value.
- Audit all in-repo/system contracts and reference implementations (e.g., gasless, auction) to ensure none of them rely on `PREVRANDAO` for security-critical randomness during the pre-Randao-fork period.

### Proof of Concept
1. Deploy any contract on a Kaia chain/network before the Randao hardfork activation block (i.e., `header.MixHash == nil`) that uses the `PREVRANDAO` opcode (`0x44`) for a "random" outcome, e.g., the `random()` sample contract used in the project's own tests. [5](#0-4) 
2. As an ordinary RPC caller, query the current head block header via public RPC to learn `header.ParentHash` (equivalently, `blockhash(block.number-1)`), which will be returned unchanged as `block.prevrandao` in the next block per `NewEVMBlockContext`. [1](#0-0) 
3. Off-chain, compute the exact "random" result that the target contract will observe (e.g., `keccak256(block.prevrandao, ...)` as in the ATM BlindBox pattern) since `block.prevrandao` is already fully determined and public.
4. Submit only the transaction whose predicted outcome is favorable (bet, auction claim, lottery draw, etc.), guaranteeing a win — the same "evaluate before submitting a winning settlement" technique used in the ATM BlindBox exploit, but here rooted in core Kaia EVM block-context construction rather than an application-level fallback.
5. This is confirmed by the project's own assertion in `testRandao_checkKip114`, which shows `random == header.ParentHash` for all pre-fork blocks, proving the value is not a secret at the time contracts read it. [4](#0-3)

func enable4399(jt *JumpTable) {
	jt[PREVRANDAO] = &operation{
		execute:         opRandom,
		constantGas:     GasQuickStep,
		minStack:        minStack(0, 1),
		maxStack:        maxStack(0, 1),
		computationCost: params.RandomComputationCost,
	}
}
