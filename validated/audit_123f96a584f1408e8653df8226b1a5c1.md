### Title
EVM access-list revert corrupts other addresses' slot indices after removing an entry from `transientAccessLists.Slots` - (File: x/evm/state/journal.go)

### Summary
`accessListAddSlotChange.revert` in the EVM `StateDB` shim removes an emptied address's slot map from `transientAccessLists.Slots` by shifting all subsequent elements left (`append(slotsList[:idx], slotsList[idx+1:]...)`), but never updates the `Addresses` index map for every other address whose slot-map position shifted as a result. This is the same bug class as the Union Finance `cancelVouch` swap-and-pop issue: an index-tracked array is mutated by removing an element, and stale/incorrect indices are left behind for the entries whose positions moved.

### Finding Description
The EVM access list is implemented as a map plus parallel slice for gas-metering purposes: [1](#0-0) 

`AddSlotToAccessList` assigns a fresh index equal to `len(al.Slots)` to any address getting its first slot, and stores that index in `al.Addresses[addr]`, then appends the new slot map to `al.Slots`: [2](#0-1) 

Each such addition is journaled via `accessListAddSlotChange{address, slot}` for revert-on-failure semantics: [3](#0-2) 

On revert, if removing a slot leaves an address's slot map empty, the code splices that entry out of the `Slots` slice by shifting everything after `idx` down by one position: [4](#0-3) 

This mutates `s.tempState.transientAccessLists.Slots` in place, changing the slice-index of every entry originally stored at positions `> idx`. However, only `e.address`'s entry in the `Addresses` map is updated (set to `-1`); the `Addresses[addr] = idx'` mapping for every other address whose slot map used to live at a position after `idx` is left pointing to the wrong (now shifted) slot map, exactly mirroring the Union Finance bug where a swap/removal from an indexed array desynchronizes the stored index for elements whose position changed.

### Impact Explanation
After such a revert occurs mid-transaction (e.g., inside a nested `Snapshot`/`RevertToSnapshot` sequence triggered by a reverted inner call, which is routine EVM execution behavior for CALL/CREATE failures, `require`/`revert` in Solidity, or out-of-gas sub-calls), any address whose slot-map index was shifted will have `al.Addresses[addr]` pointing at the wrong `map[common.Hash]struct{}` in `al.Slots`. Subsequent `SlotInAccessList` / `AddSlotToAccessList` calls for that address then read/write into another address's slot set: [5](#0-4) [6](#0-5) 

Because the EIP-2930/EIP-2929 access-list state directly drives whether a storage slot is billed as "cold" (2100 gas) or "warm" (100 gas) in `SLOAD`/`SSTORE` gas metering, corrupting which slots are considered "already accessed" for a given address changes the computed gas cost of a transaction — this can under- or over-charge gas relative to the correct EVM semantics, i.e., a fee/gas-accounting integrity issue reachable purely from an EVM transaction sender crafting a call sequence that triggers a partial revert after establishing multiple addresses in the access list.

### Likelihood Explanation
Triggering the corrupted state requires only standard EVM execution patterns available to any transaction sender: touching several addresses/slots via `AddSlotToAccessList` (through `SLOAD`/`SSTORE`/transaction access-list entries) followed by a sub-call revert that empties an earlier address's slot set while later addresses still hold slots at higher indices in `Slots`. This is a common pattern (e.g., a nested call to a contract that accesses storage and then reverts) and does not require any special privileges — any public EVM JSON-RPC client submitting a contract-call transaction can construct it.

### Recommendation
When splicing an entry out of `transientAccessLists.Slots`, update `Addresses[addr']` for every address whose stored index is greater than the removed `idx` (decrement it by one), the same way `voucherIndexes` should have been fixed in the original Union report. Alternatively, avoid shifting the slice altogether: swap the removed entry with the last element (updating the swapped address's `Addresses` entry to the new index) and truncate, or track slots by address key directly instead of by positional index into a slice.

### Proof of Concept
1. In a single EVM transaction, call `AddSlotToAccessList(addrA, slotA)` then `AddSlotToAccessList(addrB, slotB)` — this assigns `Addresses[addrA]=0`, `Slots=[{slotA}]`; then `Addresses[addrB]=1`, `Slots=[{slotA},{slotB}]`.
2. Take a snapshot, then within a reverted sub-call, remove `slotA` from `addrA`'s only slot (journal revert for `addrA` fires): `idx=0`, `slots` becomes empty, so `Slots = append(Slots[:0], Slots[1:]...)` → `Slots=[{slotB}]`, and `Addresses[addrA] = -1`. Note `Addresses[addrB]` is still `1`, but `Slots` now only has index `0`.
3. Any subsequent `SlotInAccessList(addrB, slotB)` or `AddSlotToAccessList(addrB, ...)` call indexes `al.Slots[1]`, which is now out of bounds or (if more entries exist) points to a completely different address's slot map, corrupting gas-metering state for the remainder of the transaction — verifiable by asserting `Addresses[addrB]` no longer matches `addrB`'s actual position in `Slots` after the revert.

```go
func (s *DBImpl) SlotInAccessList(addr common.Address, slot common.Hash) (addressOk bool, slotOk bool) {
	s.k.PrepareReplayedAddr(s.ctx, addr)
	al := s.getCurrentAccessList()
	idx, addrOk := al.Addresses[addr]
	if addrOk && idx != -1 {
		_, slotOk := al.Slots[idx][slot]
		return addrOk, slotOk
	}
	return addrOk, false
}
```

```go
func (s *DBImpl) AddSlotToAccessList(addr common.Address, slot common.Hash) {
	s.k.PrepareReplayedAddr(s.ctx, addr)
	al := s.getCurrentAccessList()
	idx, addrPresent := al.Addresses[addr]
	if !addrPresent {
		s.AddAddressToAccessList(addr)
	}
	if !addrPresent || idx == -1 {
		// Address not present, or addr present but no slots there
		al.Addresses[addr] = len(al.Slots)
		slotmap := map[common.Hash]struct{}{slot: {}}
		al.Slots = append(al.Slots, slotmap)
		s.journal = append(s.journal, &accessListAddSlotChange{address: addr, slot: slot})
		return
	}
```
