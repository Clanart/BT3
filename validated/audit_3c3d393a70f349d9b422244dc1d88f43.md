### Title
Data Layer mirror URLs are not scheme/host-restricted, allowing an authenticated store owner to trigger SSRF against subscriber nodes - (File: chia/data_layer/download_data.py)

### Summary
Any wallet user who owns a DataLayer store can register arbitrary mirror URLs on-chain via `add_mirror()`, and any other node that subscribes to that store will have its DataLayer service issue outbound HTTP requests to those attacker-chosen URLs with no validation of scheme, host, or destination (e.g., loopback/link-local/internal addresses). This mirrors the Frappe SSRF bug class: a request field controlled by an authenticated user causes the server to make an HTTP call to an arbitrary destination of the user's choosing.

### Finding Description
`DataLayer.add_mirror()` publishes a list of caller-supplied `urls` on-chain for a store the caller owns, with the only check being that the list is non-empty: [1](#0-0) 

Other nodes discover these URLs through `get_mirrors()`/`update_subscriptions_from_wallet()`, which just concatenates all mirror URLs with no filtering: [2](#0-1) 

When a subscribing node's periodic sync runs `fetch_and_validate()`, it picks a server URL from `get_available_servers_for_store()` and calls `insert_from_delta_file()` → `download_file()` → `http_download()`: [3](#0-2) 

`http_download()` performs an unrestricted `aiohttp` GET to `server_info.url + "/" + filename`, with no scheme allowlist (http/https only enforced implicitly by aiohttp) and no check against private/loopback/link-local IP ranges (e.g., `127.0.0.1`, `169.254.169.254`, internal service ports): [4](#0-3) 

The plugin/downloader path (`download.url + "/download"`) is similarly unrestricted: [5](#0-4) 

Because mirror URLs are propagated on-chain (via `dl_new_mirror`/`DLNewMirror` wallet RPC) and consumed automatically by any subscribing DataLayer node's background sync loop (`periodically_manage_data()` → `update_subscription()` → `fetch_and_validate()`), a malicious but ordinary wallet user who owns any DataLayer store can force other participants' DataLayer services to make HTTP requests to attacker-chosen internal or otherwise restricted network endpoints, purely by registering that store as a mirror and having victims subscribe to it (subscription is a normal, low-friction DataLayer client action, e.g. via `chia data subscribe`).

### Impact Explanation
This is a genuine SSRF: the destination of an outbound HTTP request made by a node's DataLayer service is fully attacker-controlled (any owner of any DataLayer store can set it), and consuming nodes are legitimate DataLayer clients acting on public, on-chain mirror data with no reachability restriction. This can be used to probe/attack internal services reachable from a victim's DataLayer node (e.g., other local RPC ports, cloud metadata endpoints, LAN-only management interfaces), and can also be leveraged to keep the victim's HTTP client hanging on slow/malicious endpoints. It does not directly cause consensus divergence, fund loss, or forged assets, so it does not reach the "concrete unsigned coin movement / supply inflation / consensus divergence" bar the validation criteria ask for, but it is a legitimate confidentiality/availability-adjacent SSRF matching the reported bug class in a codebase path reachable by an unprivileged Data Layer client (any store owner + any subscriber).

### Likelihood Explanation
Likelihood is high for triggering the request: publishing a malicious mirror URL requires only owning a store and paying the mirror coin cost, and any node that later subscribes to that store (a routine, expected DataLayer client action) will automatically make the SSRF request during its periodic sync without further user interaction or confirmation.

### Recommendation
Validate and restrict mirror/downloader URLs before use in `add_mirror()`/`update_subscriptions_from_wallet()`/`http_download()`/`download_file()`: enforce an `http(s)` scheme allowlist, resolve and reject requests to loopback, link-local, private, and multicast IP ranges (unless explicitly configured for testing), and consider making outbound mirror fetches opt-in/allowlist-based per operator rather than fully automatic based on untrusted on-chain data.

### Proof of Concept
1. Attacker creates a DataLayer store and calls `add_mirror(store_id, urls=["http://169.254.169.254/latest/meta-data/"], amount, fee)` (or an internal victim-only address such as `http://127.0.0.1:8555/`), publishing this on-chain via `dl_new_mirror`. [1](#0-0) 
2. A victim node subscribes to the attacker's store (`chia data subscribe`), causing `update_subscriptions_from_wallet()` to pull the malicious URL into its subscription list. [6](#0-5) 
3. During the victim's periodic sync cycle, `fetch_and_validate()` selects the malicious URL and calls `http_download()`, which issues an aiohttp GET request to the attacker-chosen internal/loopback address. [4](#0-3)

```python
        mirrors: list[Mirror] = (await self.wallet_rpc.dl_get_mirrors(DLGetMirrors(launcher_id=store_id))).mirrors

    async def update_subscriptions_from_wallet(self, store_id: bytes32) -> None:
        mirrors: list[Mirror] = (await self.wallet_rpc.dl_get_mirrors(DLGetMirrors(launcher_id=store_id))).mirrors
        urls: list[str] = []
        for mirror in mirrors:
            urls += mirror.urls
        urls = [url.rstrip("/") for url in urls]
        await self.data_store.update_subscriptions_from_wallet(store_id, urls)
```

```python
async def http_download(
    target_filename_path: Path,
    filename: str,
    proxy_url: str | None,
    server_info: ServerInfo,
    timeout: aiohttp.ClientTimeout,
    log: logging.Logger,
    max_delta_file_size: int,
) -> None:
    """
    Download a file from a server using aiohttp.
    Raises exceptions on errors
    """
    async with aiohttp.ClientSession() as session:
        headers = {"accept-encoding": "gzip"}
        async with session.get(
            server_info.url + "/" + filename,
            headers=headers,
            timeout=timeout,
            proxy=proxy_url,
        ) as resp:
            resp.raise_for_status()
            size = int(resp.headers.get("content-length", 0))
            max_delta_file_size_bytes = max_delta_file_size * 1024 * 1024
            if size > max_delta_file_size_bytes:
                raise MaxDeltaFileSizeExceededError(f"Maximum delta file size exceeded: {max_delta_file_size} MiB.")
            log.debug(f"Downloading delta file {filename}. Size {size} bytes.")
```
