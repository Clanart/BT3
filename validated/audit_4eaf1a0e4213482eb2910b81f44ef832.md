### Title
Fail-open exception handling in Hookify's PreToolUse hook allows blocking rules to be silently bypassed - (File: plugins/hookify/hooks/pretooluse.py)

### Summary
The ZetaChain report describes a class of bug where a failure in an error-handling/recovery path (the on-chain revert) causes the security guarantee (funds returned) to silently fail, with the system falling back to an unrecoverable "safe-looking" state (`Aborted`) that actually harms the user. The reachable analog in this repo is in the `hookify` plugin, whose entire purpose is to let a project **block** dangerous tool calls (e.g. `rm -rf`, writes to `.env`, etc.) via `PreToolUse` hook rules. When rule loading or rule evaluation throws *any* exception, the hook unconditionally falls back to "allow" (`exit 0`), silently discarding the blocking decision instead of failing closed or informing the user that protection was skipped.

### Finding Description
`plugins/hookify/hooks/pretooluse.py` is registered as the `PreToolUse` hook executor and is responsible for evaluating user-defined `.claude/hookify.*.local.md` rules and returning a `permissionDecision: deny` when a `block` rule matches [1](#0-0) .

The `main()` function wraps the entire load-and-evaluate flow in a broad `try/except Exception`, and in the `finally` block it always calls `sys.exit(0)` regardless of whether an exception occurred: [2](#0-1) 

This means that **any** unhandled exception during rule loading (`load_rules`) or rule evaluation (`RuleEngine.evaluate_rules`) results in the tool call being allowed, with only a `systemMessage` describing the error - there is no `permissionDecision: deny` fallback and no distinction between "no rule matched" and "rule evaluation crashed."

The rule loader itself is a hand-rolled, non-standard YAML frontmatter parser (`extract_frontmatter` in `config_loader.py`), which is fragile string/indentation-based parsing of arbitrary `.claude/hookify.*.local.md` files [3](#0-2) . While `load_rules`/`load_rule_file` catch several exception classes when reading/parsing individual files and skip the bad file [4](#0-3) , the downstream `RuleEngine.evaluate_rules`/`_rule_matches` path (which compiles and applies rule regex patterns via `compile_regex`, and iterates over `rule.conditions`) has no equivalent per-rule error isolation - an exception raised there propagates up to `pretooluse.py`'s single top-level handler, which as shown above defaults to "allow" for the *whole* hook invocation, not just the offending rule.

Because `.claude/hookify.*.local.md` files are ordinary workspace files (git-ignored by convention, per `plugins/hookify/commands/help.md:138`, but not access-controlled), any content that can reach the working directory - a malicious or malformed rule file, a rule with a pathological/invalid regex pattern, unexpected types in `conditions`, etc. - can trigger the fail-open path and cause **all** hookify rules (including unrelated `block` rules protecting against `rm -rf`, secret-file writes, etc.) to be skipped for that tool call.

### Impact Explanation
This directly parallels the ZetaChain bug class: a failure in the "recovery"/"guard" code path (there: the on-chain revert; here: the PreToolUse rule evaluation) silently degrades the security guarantee instead of preserving it or surfacing the failure loudly. In claude-code's threat model, `hookify` is explicitly a user-configured last line of defense against dangerous `Bash`/`Write`/`Edit` operations. A crash in this component - triggerable by ordinary, unprivileged workspace content (a rule file with a broken pattern, unexpected YAML shape, etc.) - causes the intended `block` action to be silently converted into an "allow," letting a dangerous command execute exactly as if no protection existed. This is an approval-bypass condition consistent with the categories explicitly in scope (hook bypass / tool authorization trust boundary).

### Likelihood Explanation
Likelihood is moderate-to-high in practice: hookify rules are user-authored markdown/YAML-like files parsed by a custom, non-robust parser [5](#0-4) , so a single malformed field (e.g., an invalid regex in `pattern`, a `conditions` entry missing expected keys, or a type mismatch introduced accidentally or intentionally) is plausible during real usage or could be deliberately crafted by anyone able to drop a file into `.claude/` (e.g., via a compromised dependency, a suggested rule from an untrusted source, or a subagent/session writing rule files). The fail-open design guarantees that once triggered, the bypass is total and silent (no deny) rather than merely degraded.

### Recommendation
1. In `pretooluse.py`, do not unconditionally default to allow on exception. Distinguish between "hookify itself is broken/misconfigured" (arguably should degrade to allow with a loud warning) and "a specific rule crashed while evaluating a specific tool call" (should not silently discard a `block` decision for other valid rules).
2. Add per-rule exception isolation inside `RuleEngine.evaluate_rules`/`_rule_matches` (mirroring the per-file isolation already done in `load_rules`), so one broken rule cannot suppress evaluation of all other rules.
3. Make failures visible: emit a `systemMessage`/warning to the user or transcript whenever a rule fails to evaluate, rather than only writing to the hook's own error message that may go unnoticed. Consider an explicit "fail-safe" configuration option so security-critical deployments can opt into fail-closed behavior for `block` rules.

### Proof of Concept
1. Create `.claude/hookify.test.local.md` with a rule intended to block `rm -rf`:
```
---
name: block-rm
enabled: true
event: bash
action: block
conditions:
  - field: command
    operator: regex_match
    pattern: "rm\s+-rf"
---
Blocked dangerous rm -rf.
```
2. Modify/introduce a second co-located rule file (or corrupt the same file) with content that produces a value the `RuleEngine`/`Condition` machinery cannot handle safely when compiled/evaluated (e.g., a pattern string that raises `re.error` deep in matching logic reached only from `_rule_matches`, not the file-level try/except in `config_loader.load_rule_file`).
3. Trigger a `Bash` tool call with `rm -rf /tmp/x`.
4. Because `RuleEngine.evaluate_rules`'s exception is caught generically in `pretooluse.py:61-66` and the `finally` block always exits 0 [2](#0-1) , the hook returns `{"systemMessage": "Hookify error: ..."}` with **no** `permissionDecision: deny`, so Claude Code proceeds to execute `rm -rf /tmp/x` even though a matching `block` rule exists.

Note: I was not able to fully trace the exact internal exception surface of `RuleEngine._rule_matches`/condition evaluation (only `evaluate_rules` was directly retrieved), so the precise minimal malformed-rule payload that reaches an unhandled exception in that function is not fully confirmed from the indexed code; a Devin session with full repository access would be needed to enumerate the exact crash-triggering inputs in `rule_engine.py` and `config_loader.Condition`/`Rule` handling.

def main():
    """Main entry point for PreToolUse hook."""
    try:
        # Read input from stdin
        input_data = json.load(sys.stdin)

        # Determine event type for filtering
        # For PreToolUse, we use tool_name to determine "bash" vs "file" event
        tool_name = input_data.get('tool_name', '')

        event = None
        if tool_name == 'Bash':
            event = 'bash'
        elif tool_name in ['Edit', 'Write', 'MultiEdit']:
            event = 'file'

        # Load rules
        rules = load_rules(event=event)

        # Evaluate rules
        engine = RuleEngine()
        result = engine.evaluate_rules(rules, input_data)

        # Always output JSON (even if empty)
        print(json.dumps(result), file=sys.stdout)

def extract_frontmatter(content: str) -> tuple[Dict[str, Any], str]:
    """Extract YAML frontmatter and message body from markdown.

    Returns (frontmatter_dict, message_body).

    Supports multi-line dictionary items in lists by preserving indentation.
    """
    if not content.startswith('---'):
        return {}, content

    # Split on --- markers
    parts = content.split('---', 2)
    if len(parts) < 3:
        return {}, content

    frontmatter_text = parts[1]
    message = parts[2].strip()

    # Simple YAML parser that handles indented list items
    frontmatter = {}
    lines = frontmatter_text.split('\n')

    current_key = None
    current_list = []
    current_dict = {}
    in_list = False
    in_dict_item = False

    for line in lines:
        # Skip empty lines and comments
        stripped = line.strip()
        if not stripped or stripped.startswith('#'):
            continue

        # Check indentation level
        indent = len(line) - len(line.lstrip())

        # Top-level key (no indentation or minimal)
        if indent == 0 and ':' in line and not line.strip().startswith('-'):
            # Save previous list/dict if any
            if in_list and current_key:
                if in_dict_item and current_dict:
                    current_list.append(current_dict)
                    current_dict = {}
                frontmatter[current_key] = current_list
                in_list = False
                in_dict_item = False
                current_list = []

            key, value = line.split(':', 1)
            key = key.strip()
            value = value.strip()

            if not value:
                # Empty value - list or nested structure follows
                current_key = key
                in_list = True
                current_list = []
            else:
                # Simple key-value pair
                value = value.strip('"').strip("'")
                if value.lower() == 'true':
                    value = True
                elif value.lower() == 'false':
                    value = False
                frontmatter[key] = value

        # List item (starts with -)
        elif stripped.startswith('-') and in_list:
            # Save previous dict item if any
            if in_dict_item and current_dict:
                current_list.append(current_dict)
                current_dict = {}

            item_text = stripped[1:].strip()

            # Check if this is an inline dict (key: value on same line)
            if ':' in item_text and ',' in item_text:
                # Inline comma-separated dict: "- field: command, operator: regex_match"
                item_dict = {}
                for part in item_text.split(','):
                    if ':' in part:
                        k, v = part.split(':', 1)
                        item_dict[k.strip()] = v.strip().strip('"').strip("'")
                current_list.append(item_dict)
                in_dict_item = False
            elif ':' in item_text:
                # Start of multi-line dict item: "- field: command"
                in_dict_item = True
                k, v = item_text.split(':', 1)
                current_dict = {k.strip(): v.strip().strip('"').strip("'")}
            else:
                # Simple list item
                current_list.append(item_text.strip('"').strip("'"))
                in_dict_item = False

        # Continuation of dict item (indented under list item)
        elif indent > 2 and in_dict_item and ':' in line:
            # This is a field of the current dict item
            k, v = stripped.split(':', 1)
            current_dict[k.strip()] = v.strip().strip('"').strip("'")

    # Save final list/dict if any
    if in_list and current_key:
        if in_dict_item and current_dict:
            current_list.append(current_dict)
        frontmatter[current_key] = current_list

    return frontmatter, message

def load_rule_file(file_path: str) -> Optional[Rule]:
    """Load a single rule file.

    Returns:
        Rule object or None if file is invalid.
    """
    try:
        with open(file_path, 'r') as f:
            content = f.read()

        frontmatter, message = extract_frontmatter(content)

        if not frontmatter:
            print(f"Warning: {file_path} missing YAML frontmatter (must start with ---)", file=sys.stderr)
            return None

        rule = Rule.from_dict(frontmatter, message)
        return rule

    except (IOError, OSError, PermissionError) as e:
        print(f"Error: Cannot read {file_path}: {e}", file=sys.stderr)
        return None
    except (ValueError, KeyError, AttributeError, TypeError) as e:
        print(f"Error: Malformed rule file {file_path}: {e}", file=sys.stderr)
        return None
    except UnicodeDecodeError as e:
        print(f"Error: Invalid encoding in {file_path}: {e}", file=sys.stderr)
        return None
    except Exception as e:
        print(f"Error: Unexpected error parsing {file_path} ({type(e).__name__}): {e}", file=sys.stderr)
        return None
