### Title
Unvalidated on-chain mirror URLs enable SSRF against DataLayer subscribers - (File: `chia/data_layer/download_data.py`)

### Summary
Any unprivileged spend-bundle submitter can create a "mirror" coin on chain that advertises an arbitrary attacker-chosen URL for any DataLayer store id. Every full/Data-Layer node that is subscribed to that store id will later eagerly issue outbound HTTP(S) requests to that attacker-controlled URL/host with no validation, host allow-listing, or DNS/IP restriction — mirroring the "eager resolution of attacker-controlled network address" bug class described in CVE-2026-77310, but reachable through Chia's on-chain mirror-coin mechanism rather than Java deserialization.

### Finding Description
The mirror puzzle used to publish DataLayer mirror URLs is a fixed, ownerless puzzle: [1](#0-0) 

`get_mirror_info()` extracts the `launcher_id` and URL list purely from the `CREATE_COIN` memo of whatever spend created a coin with this puzzle hash — there is no signature, ownership, or authorization check tying the `launcher_id` to the spender: [2](#0-1) 

Any wallet can build this spend directly (`generate_signed_transaction` with `puzzle_hashes=[create_mirror_puzzle().get_tree_hash()]` and `memos=[[launcher_id, *urls]]`), as done in `create_new_mirror()`: [3](#0-2) 

When any wallet observes a coin with this puzzle hash for a `launcher_id` it is already tracking, it records the attacker-supplied URLs verbatim into `dl_store`: [4](#0-3) 

Those URLs propagate into `DataStore` via `update_subscriptions_from_wallet()`: [5](#0-4) 

and are later selected and connected to without validation in the sync loop's `fetch_and_validate()` / `download_file()` / `http_download()` path, which performs a direct `aiohttp` GET to `server_info.url`: [6](#0-5) 

No check exists anywhere in this chain that the URL/host is a public, non-private, non-loopback, non-link-local address (e.g., no rejection of `http://127.0.0.1/...`, `http://169.254.169.254/...`, internal service ports, etc.) — the existing tests even demonstrate mirrors pointing at `http://127.0.0.1/8000` being accepted and stored without complaint: [7](#0-6) 

The same trust gap applies to the S3 plugin download handler, which resolves `data["url"]` supplied through this same untrusted mirror-coin path: [8](#0-7) 

### Impact Explanation
Any node subscribed to a DataLayer store (a normal, unprivileged Data Layer client action) can be induced to make outbound network connections to attacker-chosen hosts/ports whenever any third party — with no relationship to the store owner — pushes a mirror coin naming that store's `launcher_id`. This enables SSRF: probing/reaching internal-only services, cloud metadata endpoints, or other hosts reachable from the victim's machine, and can be used for internal-host enumeration or to trigger unwanted requests to arbitrary infrastructure from the victim node. This matches the CVSS 5.3 (Medium) impact profile of the referenced CVE (confidentiality-only impact via SSRF, no direct code execution).

### Likelihood Explanation
Creating a mirror coin only requires submitting a standard, unprivileged spend bundle (paying a small mojo amount plus fee) — no special key, no ownership of the target store, and no on-chain authorization tied to the `launcher_id` is required. The store id (`launcher_id`) of a shared DataLayer dataset is normally public/known to its subscribers, making this trivially reachable by anyone wishing to target subscribers of a known DataLayer store.

### Recommendation
- Validate mirror URLs before storing/using them: reject `http(s)` URLs resolving to private, loopback, link-local, or otherwise disallowed IP ranges (equivalent to blocking `InetAddress.isAnyLocalAddress()/isLoopbackAddress()/isSiteLocalAddress()` classes), and re-validate at connection time rather than trusting cached hostnames.
- Consider restricting mirror URL scheme to `https` only and enforcing an allow-list/pinning mechanism, or at minimum resolving DNS once and validating the resolved IP against a deny-list immediately before the `aiohttp` request in `http_download()` and in the S3 plugin's `handle_download`/`download`.
- Optionally require mirror coins to only be actionable for `launcher_id`s the local wallet actually owns/controls, or add stronger provenance requirements before a URL is treated as fetchable.

### Proof of Concept
1. Attacker learns (or guesses) the public `launcher_id` (store id) of a DataLayer store that victim nodes subscribe to.
2. Attacker submits an ordinary spend bundle creating a coin with puzzle hash `create_mirror_puzzle().get_tree_hash()` and memo `[launcher_id, b"http://169.254.169.254/latest/meta-data/"]` (or any internal target), following the same construction as `DataLayerWallet.create_new_mirror()` (`chia/data_layer/data_layer_wallet.py:687-703`).
3. Once confirmed, any victim node subscribed to that `launcher_id` records the mirror via `coin_added()` (`chia/data_layer/data_layer_wallet.py:775-800`), syncs it into `DataStore` via `update_subscriptions_from_wallet()` (`chia/data_layer/data_layer.py:979-985`), and its background sync loop eventually calls `http_download()` (`chia/data_layer/download_data.py:298-320`), issuing an outbound GET to the attacker-chosen host with no destination validation.

```python
def get_mirror_info(
    parent_puzzle: Program | SerializedProgram, parent_solution: Program | SerializedProgram
) -> tuple[bytes32, list[bytes]]:
    assert type(parent_puzzle) is type(parent_solution)
    _, conditions = run_with_cost(parent_puzzle, INFINITE_COST, parent_solution)
    for condition in conditions.as_iter():
        if (
            condition.first().as_python() == ConditionOpcode.CREATE_COIN
            and condition.at("rf").as_python() == create_mirror_puzzle().get_tree_hash()
        ):
            memos: list[bytes] = condition.at("rrrf").as_python()
            launcher_id = bytes32(memos[0])
            return launcher_id, [url for url in memos[1:]]
    raise ValueError("The provided puzzle and solution do not create a mirror coin")
```

```python
                        launcher_id,
                        uint64(coin.amount),
```

```python
    timeout: aiohttp.ClientTimeout,
    log: logging.Logger,
    max_delta_file_size: int,

    """
    Download a file from a server using aiohttp.
    Raises exceptions on errors
    """
    async with aiohttp.ClientSession() as session:
        headers = {"accept-encoding": "gzip"}
        async with session.get(
            server_info.url + "/" + filename,
            headers=headers,
            timeout=timeout,
            proxy=proxy_url,
        ) as resp:
            resp.raise_for_status()
```
