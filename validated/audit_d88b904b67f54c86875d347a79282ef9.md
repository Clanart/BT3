### Title
Missing identity check on DKG encryption keys allows publicly-decryptable secret shares - (File: crypto/dkg/pedpop/src/encryption.rs)

### Summary
Analogous to the reported "validity check missed on consumed data" bug, `EncryptionKeyMessage::read` accepts a peer-supplied `enc_key` via `Ciphersuite::read_G`, which enforces only canonical encoding — not non-identity. FROST's `Curve::read_G` explicitly rejects the identity point for exactly this reason, but the PedPoP encryption layer never performs an equivalent check on `enc_key`, `EncryptedMessage::key`, or `EncryptionKeyProof::key`, all of which are attacker-controlled bytes.

### Finding Description
`EncryptionKeyMessage::read` deserializes `enc_key` with `C::read_G` (`crypto/ciphersuite/src/lib.rs:91-101`), which only checks canonicity. A malicious participant can therefore register `enc_key = identity`. When any honest participant later encrypts a secret share to them, `encrypt()` computes the ECDH shared key as `ecdh(&key, to) = key * enc_key` (`crypto/dkg/pedpop/src/encryption.rs:95-97, 153-154`). With `enc_key = identity`, this yields `identity`, so `cipher()` derives the ChaCha20 keystream from the publicly-known byte encoding of the identity point (`encryption.rs:101-133`).

### Impact Explanation
The secret share intended only for the malicious participant is encrypted under a keystream anyone can recompute — the ChaCha20 key is `H(context || "encryption_key" || identity_encoding)` with a static IV. Any party that observes the `EncryptedMessage` bytes (a relay, coordinator, or processor node shuttling shares between validators, per `processor/src/key_gen.rs:300-304`) can decrypt the share without knowing any secret. This defeats the confidentiality guarantee the ECDH layer exists to provide, and revealed shares can be combined to recover group key material.

### Likelihood Explanation
Any unprivileged DKG participant can submit an identity `enc_key` in their round-1 `EncryptionKeyMessage`; no cryptographic break is needed, only a canonical encoding of the identity point. The vulnerability requires an observer of the ciphertext bytes to exploit, consistent with a Medium rating.

### Recommendation
Reject the identity point when reading externally supplied group elements in the DKG/PedPoP encryption path: after `C::read_G` in `EncryptionKeyMessage::read`, `EncryptedMessage::read`, and `EncryptionKeyProof::read` (`crypto/dkg/pedpop/src/encryption.rs:58, 173, 268`), add `if res.is_identity().into() { Err(...) }`, matching the pattern in `Curve::read_G` (`crypto/frost/src/curve/mod.rs:125-131`).

### Proof of Concept
1. Malicious participant `l` broadcasts `EncryptionKeyMessage { msg: Commitments(..), enc_key: C::G::identity() }`; `read` succeeds.
2. Honest participant calls `generate_secret_shares` → `encryption.encrypt(rng, l, share)` → `ecdh(&key, identity) = identity`.
3. `cipher(context, &identity)` produces a keystream derived only from public values (`context`, `identity.to_bytes()`), so any holder of the serialized `EncryptedMessage` applies the same keystream and recovers `SecretShare<C::F>` in the clear.
