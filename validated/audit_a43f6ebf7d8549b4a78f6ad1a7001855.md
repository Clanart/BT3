### Title
Missing cross-field validation of `LowerBoundBaseFee`/`UpperBoundBaseFee` in contract governance allows base-fee invariant violation - ([File: kaiax/gov/contractgov/impl/getter.go])

### Summary
`kaiax/gov/param.go` defines `Kip71LowerBoundBaseFee` and `Kip71UpperBoundBaseFee` each with a `noopFormatChecker` [1](#0-0) [2](#0-1) , meaning neither parameter is validated against the other when set. The contract-governance path (`kaiax/gov/contractgov/impl/getter.go`) reads all parameters from the on-chain `GovParam` contract and applies them field-by-field via `ret.Set(k, v)` with no cross-parameter consistency check at all [3](#0-2) . This is in contrast to the header-vote governance path, which does perform a `LowerBoundBaseFee <= UpperBoundBaseFee` cross-check in `checkConsistency` [4](#0-3) . The contract-governance path lacks the equivalent safeguard.

### Finding Description
`NextMagmaBlockBaseFee` in `params/kip71_config.go` assumes `LowerBoundBaseFee <= UpperBoundBaseFee` and clamps the parent base fee into that range before computing the next base fee [5](#0-4) . If `LowerBoundBaseFee > UpperBoundBaseFee` (e.g., lower = 100, upper = 50), the clamping logic:
```go
if parentBaseFee.Cmp(upperBoundBaseFee) >= 0 {
    parentBaseFee = upperBoundBaseFee
} else if parentBaseFee.Cmp(lowerBoundBaseFee) <= 0 {
    parentBaseFee = lowerBoundBaseFee
}
```
can clamp `parentBaseFee` down to `upperBoundBaseFee`, a value strictly below `lowerBoundBaseFee`, and then return it directly (e.g., when `parentGasUsed == gasTarget`), producing a next base fee that violates the intended invariant "base fee never falls below `LowerBoundBaseFee`." This invariant is explicitly relied upon elsewhere, e.g. `params/kip71_config_test.go`'s `TestEvenBaseFee` asserts `even.Cmp(lowerBoundBaseFee) >= 0` for every valid config [6](#0-5) , and downstream consumers such as `isRelaxedNetwork` in the gas-price oracle compare live base fees against `pset.LowerBoundBaseFee` assuming it is a true floor [7](#0-6) .

The root cause is that `contractGovModule.GetParamSet` (`kaiax/gov/contractgov/impl/getter.go`, lines 17–32) sets each governance parameter independently from GovParam contract values with only per-field `FormatChecker`s (all `noopFormatChecker` for KIP-71 fields), and never checks `LowerBoundBaseFee <= UpperBoundBaseFee` as a pair, unlike the `checkConsistency` function used for header-vote governance.

### Impact Explanation
Since fee-market parameters (`LowerBoundBaseFee`, `UpperBoundBaseFee`) directly determine every transaction's minimum acceptable gas price and the block's dynamic base fee, breaking their ordering invariant can drive the network's effective base fee below the intended floor. This constitutes fee-mechanism abuse: transactions could be priced/accepted below the governance-intended minimum fee, and downstream fee logic (gas price oracle, `UpperBoundGasPrice`/`LowerBoundGasPrice` in `node/cn/api_backend.go`) that assumes `Lower <= Upper` would behave inconsistently, potentially producing incorrect fee quotes and allowing systematically underpriced transactions across the whole chain.

### Likelihood Explanation
This requires the on-chain `GovParam` contract (post-Kore governance, per KIP-81) to be updated with `LowerBoundBaseFee > UpperBoundBaseFee`. This is a governance-parameter class change explicitly listed as in-scope, and unlike the header-vote path, no code path in `contractgov` rejects such a combination — the bug is a genuine gap in the codebase (missing validation), matching the report's bug class exactly. The barrier to triggering it is whatever access control exists around GovParam contract parameter proposals/updates, which is outside the scope of this repo's Go code (it lives in the separate `kaia-system-contracts` GovParam contract not present in this index).

### Recommendation
Add a cross-field consistency check in the contract-governance ingestion path (`kaiax/gov/contractgov/impl/getter.go`'s `GetParamSet`, or in `gov.ParamSet.Set`/`SetFromMap`) mirroring `checkConsistency`'s `Kip71LowerBoundBaseFee`/`Kip71UpperBoundBaseFee` logic in `kaiax/gov/headergov/impl/header.go`, rejecting or falling back to defaults when `LowerBoundBaseFee > UpperBoundBaseFee` after applying all parameters from the contract.

### Proof of Concept
1. Deploy/update GovParam contract (post-Kore) to set `kip71.lowerboundbasefee = 100000000000` and `kip71.upperboundbasefee = 50000000000` (lower > upper).
2. `contractGovModule.GetParamSet` at the relevant block will accept both values individually (each passes `noopFormatChecker`), producing a `ParamSet` with `LowerBoundBaseFee=100000000000 > UpperBoundBaseFee=50000000000`.
3. `ParamSet.ToKip71Config()` yields a `KIP71Config` with this inverted range [8](#0-7) .
4. Call `NextMagmaBlockBaseFee` with a `parentBaseFee` between the two bounds (e.g., 70000000000) and `parentGasUsed == gasTarget`: the clamp sets `parentBaseFee = upperBoundBaseFee = 50000000000` (since `70e9 >= 50e9`), and the function returns `50000000000`, which is below the configured `LowerBoundBaseFee = 100000000000`, violating the floor invariant asserted by `TestEvenBaseFee`.

func (c *contractGovModule) GetParamSet(blockNum uint64) gov.ParamSet {
	m, err := c.contractGetAllParamsAt(blockNum)
	if err != nil {
		return *gov.GetDefaultGovernanceParamSet()
	}

	ret := *gov.GetDefaultGovernanceParamSet()
	for k, v := range m {
		err = ret.Set(k, v)
		if err != nil {
			return *gov.GetDefaultGovernanceParamSet()
		}
	}

	return ret
}

// isRelaxedNetwork returns true if the current network congestion is low to the point
// paying any tip is unnecessary. It returns true when the head block is after Magma fork
// and the next base fee is at the lower bound.
func (oracle *Oracle) isRelaxedNetwork(header *types.Header) bool {
	pset := oracle.govModule.GetParamSet(header.Number.Uint64() + 1)
	nextBaseFee := pset.ToKip71Config().NextMagmaBlockBaseFee(header.Number, header.BaseFee, header.GasUsed)
	return nextBaseFee.Cmp(big.NewInt(int64(pset.LowerBoundBaseFee))) <= 0
}
