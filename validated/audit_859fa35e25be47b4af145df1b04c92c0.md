## Title
Chialisp-injection via unescaped string concatenation of untrusted CAT sibling data in `Offer.to_valid_spend()` - ([File: chia/wallet/trading/offer.py])

### Summary
`Offer.to_valid_spend()` builds the `siblings`/`sibling_spends`/`sibling_puzzles`/`sibling_solutions` fields for a CAT settlement solve by hex- and text-concatenating attacker-influenceable data (via `disassemble()`) into raw CLVM-source strings, then hands them to a `Solver`, whose `PuzzleInfo/Solver.__getitem__` re-parses those strings with `clvm_tools.binutils.assemble()`. This mirrors the CVE-2026-57456 bug class exactly: content that should be an opaque, escaped data value is instead spliced verbatim into a textual code template that is later parsed/assembled as code, so a value containing the template's own delimiter characters (parentheses/quotes) can break out of its intended slot and inject extra structural elements into what `CATOuterPuzzle.solve()` treats as a trusted list of sibling coins/spends/puzzles/solutions used for the CAT conservation ("ring") check.

### Finding Description
`Offer.to_valid_spend()` constructs the sibling data for a CAT/CR-CAT settlement spend like this: [1](#0-0) 

Each `sibling_solutions`/`sibling_puzzles` entry is produced by `disassemble()` — a textual CLVM-source serializer — applied to `Program`s derived from `coin_to_solution_dict[sibling_coin]`, which itself is built from `NotarizedPayment.as_condition_args()`, and ultimately traces back to a `CreateCoin.memo_blob`, an arbitrary attacker-supplied `Program`: [2](#0-1) 

These strings — `"(" + <hex> + " " + ... + ")"` — are then wrapped as plain Python strings inside a `Solver` dict and passed to `solve_puzzle` (`chia/wallet/trading/offer.py:565-583`). Any consumer of the `Solver` object — here `CATOuterPuzzle.solve()` — accesses these fields via `solver["siblings"]`, `solver["sibling_solutions"]`, etc.: [3](#0-2) 

`Solver.__getitem__` calls `decode_info_value`, which — for any string not equal to `"()"`/`""` and not prefixed with `"0x"` — calls `clvm_tools.binutils.assemble(value)` to re-parse the string as CLVM source: [4](#0-3) 

This is structurally identical to the Vim bug class: a value that should be treated as opaque data (a memo/condition-argument `Program`) is serialized to text (`disassemble`) and concatenated unescaped into a larger textual "program" (the `"(... )"` sibling list), which is later fed back into an interpreter/parser (`assemble()`) that treats it as code/structure rather than as a single opaque token. If `disassemble()`'s textual rendering of an attacker-chosen atom contains unescaped structural characters recognized by the assembler (e.g. extra `)`/`(` or quote characters, or additional whitespace-separated atoms), the resulting parsed s-expression can contain more or different list elements than the constructor intended — i.e., the attacker can inject extra items into (or otherwise corrupt the intended arity/shape of) the `siblings`, `sibling_spends`, `sibling_puzzles`, or `sibling_solutions` lists that `CATOuterPuzzle.solve()` consumes.

Because `CATOuterPuzzle.solve()` uses this ring data (`zip(solver["siblings"].as_iter(), solver["sibling_spends"].as_iter(), solver["sibling_puzzles"].as_iter(), solver["sibling_solutions"].as_iter())`) to build the set of `SpendableCAT` sibling entries used by `unsigned_spend_bundle_for_spendable_cats(CAT_MOD, ...)` — which is precisely the mechanism that establishes the CAT ring used for TAIL/conservation checking — a successful injection here could desynchronize what the wallet believes it is constructing versus what CLVM will actually execute, corrupting the built solution for a CAT ring spend.

### Impact Explanation
If exploitable, this could let a counterparty's offer (a `memo_blob`/condition payload under their control) corrupt the textual reconstruction of sibling coin/puzzle/solution lists used to build the settlement CAT ring solve, potentially causing the wallet to produce a malformed or attacker-steered CAT spend solution (wrong sibling puzzle/solution/coin correlation), risking incorrect ring construction for CAT conservation checks during offer completion — a class of bug (corrupting untrusted-to-trusted text reconstruction of CLVM data) that historically maps to coin-identity/asset-forgery or conservation-check bypass risk in the CAT ring mechanism. This is High-severity by class (matches the analog CVSS profile: local, requires user/wallet action, but leads to code/structure-execution-equivalent corruption), though I could not fully verify within this investigation whether `clvm_tools.binutils.disassemble()` (a third-party dependency, not present/indexed in this repo) actually fails to escape atom content that could contain assembler-significant characters (`(`, `)`, `"`, whitespace) — that escaping behavior is the crux of whether this is truly exploitable, and I was unable to inspect its source in this codebase's index.

### Likelihood Explanation
Reaching this path requires only submitting/accepting a CAT offer (`respond_to_offer`/`to_valid_spend`) containing a crafted `memo_blob` or other condition-argument `Program` whose disassembled text contains characters significant to the CLVM assembler — an action available to any wallet user/offer counterparty with no special privileges, matching the "User Interaction Required, Local" profile of the source CVE. However, whether `disassemble()` actually renders raw/controlled bytes without escaping (the necessary precondition, akin to Vim's unescaped docstring insertion) could not be confirmed here because `clvm_tools` is an external dependency not present in this codebase's searchable index.

### Recommendation
Do not build these `Solver` fields as raw, hand-concatenated CLVM-source text derived from `disassemble()` of attacker-influenceable `Program`s. Instead, construct the sibling lists as native `Program`/CLVM objects (e.g., `Program.to([...])`) and pass them directly (or via a `Solver` value type that is not re-parsed through `assemble()`), eliminating the text round-trip through `disassemble()` → string concatenation → `assemble()`. If a text-based `Solver` API must be retained, ensure any interpolated sub-expression is individually delimited/escaped so that no atom's disassembly can alter the token/parenthesis structure of the surrounding template, and add validation that the reconstructed sibling lists have the exact arity and coin/puzzle/solution types expected before use in `CATOuterPuzzle.solve()`.

### Proof of Concept
Could not be fully constructed/verified in this session: it depends on the exact escaping (or lack thereof) implemented by `clvm_tools.binutils.disassemble()` for atom values containing bytes such as `0x29` (`)`), `0x22` (`"`), or whitespace, and that source was not available in this repo's index to confirm. A concrete PoC would (1) craft an `Offer` whose requested payment includes a `CreateCoin` with a `memo_blob` `Program` whose atom, when `disassemble()`d, contains an unescaped `)`+extra list element sequence; (2) call `respond_to_offer`/`Offer.to_valid_spend()` on the counterparty side; (3) observe that `solver["sibling_solutions"].as_iter()` (or similar) yields more/different elements than the number of sibling coins, causing `CATOuterPuzzle.solve()`'s `zip(...)` to misalign siblings, coins, puzzles, and solutions.

@dataclass(frozen=True)
class CreateCoin(Condition):
    puzzle_hash: bytes32
    amount: uint64
    memos: list[bytes] | None = None
    memo_blob: Program | None = None

    def __post_init__(self) -> None:
        if self.memos is not None and self.memo_blob is not None:
            raise ValueError("Cannot have both memos and memo_blob")
        return super().__post_init__()

    def to_program(self) -> Program:
        condition_args = [ConditionOpcode.CREATE_COIN, self.puzzle_hash, self.amount]
        if self.memos is not None:
            condition_args.append(self.memos)
        elif self.memo_blob is not None:
            condition_args.append(self.memo_blob)
        condition: Program = Program.to(condition_args)
        return condition

    @classmethod
    def from_program(cls, program: Program) -> Self:
        potential_memos: Program = program.at("rrr")
        try:
            return cls(
                bytes32(program.at("rf").as_atom()),
                uint64(program.at("rrf").as_int()),
                (
                    None
                    if potential_memos == Program.NIL
                    else [memo.as_atom() for memo in potential_memos.at("f").as_iter()]
                ),
            )
        except ValueError:  # a bit of a hack to avoid doing the heavy lifting of switching the memo usage everywhere
            return cls(
                bytes32(program.at("rf").as_atom()),
                uint64(program.at("rrf").as_int()),
                memo_blob=potential_memos.at("f"),
            )

    def as_condition_args(self) -> list[bytes32 | uint64 | list[bytes] | Program | None]:
        return [self.puzzle_hash, self.amount, self.memos if self.memos is not None else self.memo_blob]

def decode_info_value(cls: Any, value: dict[str, Any] | list[Any] | Program | str) -> Any:
    if isinstance(value, dict):
        return cls(value)
    elif isinstance(value, list):
        return [decode_info_value(cls, v) for v in value]
    elif isinstance(value, Program) and value.atom is None:
        return value
    else:
        if isinstance(value, str):
            if value in {"()", ""}:  # special case
                return Program.to([])
            if value.startswith("0x"):
                return hexstr_to_bytes(value)
            expression: SExp = assemble(value)
        else:
            expression = value
        if expression.atom is None:
            return Program(expression)
        else:
            atom: bytes = expression.atom
            typ = type_for_atom(atom)
            if typ == Type.QUOTES:
                return bytes(atom).decode("utf8")
            elif typ == Type.INT:
                return int_from_bytes(atom)
            else:
                return atom
