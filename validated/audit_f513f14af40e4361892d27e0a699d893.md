### Title
`ReceivedOutput::read` deserializes untrusted bytes without binding `offset`/`output`/`outpoint` to any key, allowing forged "received" outputs - (File: networks/bitcoin/src/wallet/mod.rs)

### Summary
Analogous to the report's "unauthenticated `notifyFeeReceived` emits an inauthentic event," `ReceivedOutput::read` accepts fully attacker-controlled bytes to construct a `ReceivedOutput` — Serai's equivalent of a "funds received" event. The struct carries an `offset` (scalar tweak to the spending key), a `TxOut`, and an `OutPoint`, yet `read` performs no verification that `p2tr_script_buf(key + GENERATOR * offset)` equals `output.script_pubkey`, nor that the claimed `outpoint`/`value` exists on-chain. The authenticity link that `Scanner::scan_transaction` establishes (script_pubkey ↔ offset ↔ real txid/vout) is entirely absent on the deserialization path.

### Finding Description
`Scanner::scan_transaction` is the only constructor that produces an authentic `ReceivedOutput`: it looks the `script_pubkey` up in `self.scripts` and stamps the real `compute_txid()`/`vout` (networks/bitcoin/src/wallet/mod.rs:199-214). `ReceivedOutput::read` (lines 122-134), however, reconstructs the same type from arbitrary bytes via `Secp256k1::read_F` and `consensus_decode`, with no key, no script table, and no chain check:

```rust
pub fn read<R: Read>(r: &mut R) -> io::Result<ReceivedOutput> {
  let offset = Secp256k1::read_F(r)?;
  output = TxOut::consensus_decode(&mut buf_r)...;
  outpoint = OutPoint::consensus_decode(&mut buf_r)...;
  Ok(ReceivedOutput { offset, output, outpoint })
}
```

Any party who can feed bytes into this reader (network peers, DB/queue payloads processed by the multisig scheduler) can mint a `ReceivedOutput` that downstream code treats identically to a scanner-authenticated one — the same degradation of event authenticity as an unpermissioned `notifyFeeReceived`.

### Impact Explanation
- **Funds reported received that are not spendable**: a forged entry whose `output.script_pubkey` does not match `key + GENERATOR*offset` will be scheduled for spend; the multisig cannot produce a valid key-path signature for it, so the "received" funds can never actually be moved.
- **Nonexistent inputs**: a forged `outpoint`/`value` causes `SignableTransaction::new` to build and the FROST multisig to sign a transaction spending a UTXO that does not exist, wasting signing rounds and producing transactions that can never confirm.
- The authenticity invariant — "a `ReceivedOutput` implies the chain paid a registered script" — is broken for every consumer that trusts deserialized rather than scanned outputs.

### Likelihood Explanation
`ReceivedOutput` derives `PartialEq` and is `write`/`read` round-tripped explicitly for transport (the test at networks/bitcoin/tests/wallet.rs:73 demonstrates serialize→read as the intended replication path), so any untrusted byte source feeding the reader reaches this. Cost to exploit is trivial; impact is bounded to scheduler disruption and wasted/invalid signing rather than direct theft, consistent with Medium.

### Recommendation
Authenticate the deserialization path: either restrict `ReceivedOutput` construction to `Scanner::scan_transaction` (make `read` private/remove the `std` public reader), or have `read` take the `Scanner`/key and re-derive `p2tr_script_buf(key + GENERATOR*offset)`, rejecting bytes whose `script_pubkey` or offset do not match — i.e., enforce the same "access control" on who may assert a receipt that the original report recommends for `notifyFeeReceived`.

  pub fn scan_transaction(&self, tx: &Transaction) -> Vec<ReceivedOutput> {
    let mut res = Vec::new();
    for (vout, output) in tx.output.iter().enumerate() {
      // If the vout index exceeds 2**32, stop scanning outputs
      let Ok(vout) = u32::try_from(vout) else { break };

      if let Some(offset) = self.scripts.get(&output.script_pubkey) {
        res.push(ReceivedOutput {
          offset: *offset,
          output: output.clone(),
          outpoint: OutPoint::new(tx.compute_txid(), vout),
        });
      }
    }
    res
  }
