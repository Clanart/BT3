## Analysis

`setHasRejectedCredentialsForEndpoint` in [1](#0-0)  is purely a bookkeeping function: it records, per trampoline token, the set of endpoints for which credential lookup already failed/was rejected. It is called only in the branches where **no credential was found or provided** — e.g., in `trampoline-credential-helper.ts` when the user declines to sign in [2](#0-1)  or when `getCredential` returns nothing at all [3](#0-2) . Its only consumer, `getHasRejectedCredentialsForEndpoint`, is read in `withTrampolineEnv` solely to decide whether to rewrite a generic "terminal prompts disabled" git error into a friendlier "user cancelled authentication" message [4](#0-3) . There is no code path from this function that transmits a token, password, or passphrase anywhere — it never touches the credential value itself, only records "no credential was released for this endpoint."

The actual credential-release/host-matching logic lives elsewhere, in `getCredential`/`getGitHubCredential`/`getGenericCredential` in [5](#0-4) , and in `findGitHubTrampolineAccount`, which matches the requested remote URL against a stored account strictly by full origin equality (scheme + host + port) via `new URL(getHTMLURL(a.endpoint)).origin === parsedUrl.origin` [6](#0-5) . This is a strict origin comparison, not a prefix/substring/host-suffix check, so it isn't defeated by a malicious proxy, PAC response, or redirect target unless that target genuinely presents the exact origin the credential was issued for (in which case it's not an "unauthorized host" by definition). The `cred` map itself (including `url`/`host`/`protocol`) is populated by git's own credential-helper protocol input from the actual TCP/TLS connection git made, not by proxy/PAC metadata, so a PAC/proxy string or certificate error doesn't get to inject an arbitrary "endpoint" value that bypasses this origin check.

No vulnerability found for this question.

async function getCredential(cred: Credential, store: Store, token: string) {
  const ghCred = await getGitHubCredential(cred, store)

  if (ghCred) {
    return ghCred
  }

  const endpointKind = await getEndpointKind(cred, store)
  const accounts = await store.getAll()

  const endpoint = `${getCredentialUrl(cred)}`
  const apiEndpoint = getAPIEndpoint(endpoint)

  // If it appears as if the endpoint is a GitHub host and we don't have an
  // account for that endpoint then we should prompt the user to sign in.
  if (
    endpointKind !== 'generic' &&
    !accounts.some(a => a.endpoint === apiEndpoint)
  ) {
    if (getIsBackgroundTaskEnvironment(token)) {
      debug('background task environment, skipping prompt')
      return undefined
    }

    const account = await ui.promptForGitHubSignIn(endpoint)

    if (!account) {
      setHasRejectedCredentialsForEndpoint(token, endpoint)
    }

    return credWithAccount(cred, account)
  }

  // GitHub.com/GHE creds are only stored internally
  if (endpointKind !== 'generic') {
    return undefined
  }

  return useExternalCredentialHelper()
    ? getExternalCredential(cred, token)
    : getGenericCredential(cred, token)
}
