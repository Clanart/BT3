### Title
Unhandled crash in mempool `is_clvm_canonical()` / `is_atom_canonical()` via out-of-bounds atom length prefix in submitted spend bundle - (File: chia/full_node/mempool_manager.py)

### Summary
`add_spend_bundle()` → `validate_spend_bundle()` calls `is_clvm_canonical(bytes(coin_spend.puzzle_reveal))` and `is_clvm_canonical(bytes(coin_spend.solution))` on every coin spend of an untrusted, attacker-submitted `SpendBundle` before it is admitted to the mempool. [1](#0-0) 

### Finding Description
`is_atom_canonical()` parses a CLVM atom's variable-length size prefix (1–6 bytes) directly out of the raw byte buffer, reading `clvm_buffer[offset]` in a loop keyed off `prefix_len`, with no check that `offset` stays within `len(clvm_buffer)`: [2](#0-1) 

`is_clvm_canonical()` similarly walks the buffer byte-by-byte (`b = clvm_buffer[offset]`) advancing `offset` by `atom_len` returned from `is_atom_canonical`, again without validating that the computed `atom_len` or `offset` stays within the buffer bounds before the next iteration's `clvm_buffer[offset]` access: [3](#0-2) 

This is the direct structural analog to the libssh2 bug: a length field taken from untrusted input (`link_len` in libssh2; the atom size-prefix bits here) is used to advance a read cursor without validating it against the actual remaining buffer size before the next read/copy. In C, this manifests as a heap buffer over-read; in this Python code, the equivalent effect is an **unhandled `IndexError`** when `offset` walks past the end of `clvm_buffer` (e.g., a puzzle_reveal/solution that starts a valid-looking multi-byte length prefix but is truncated, or an atom_len that pushes `offset` past `len(clvm_buffer)` on the next loop iteration).

`is_clvm_canonical()`/`is_atom_canonical()` have no `try/except` around the indexing, and the call site in `validate_spend_bundle()` also has no try/except around the call: [4](#0-3) 

`validate_spend_bundle()` is invoked from `add_spend_bundle()`, which itself has no exception handling around the `await self.validate_spend_bundle(...)` call: [5](#0-4) 

An unhandled `IndexError` propagating out of the mempool admission path (rather than a controlled `Err.INVALID_COIN_SOLUTION` rejection) is a deviation from the intended validation contract: the function is designed to *reject* malformed CLVM as non-canonical (returning `False`), not to crash. A crafted `puzzle_reveal` or `solution` can trigger this crash path instead of a clean rejection.

### Impact Explanation
Mempool admission (`add_spend_bundle`) is on the hot path invoked for every spend bundle received from full-node peers, RPC submitters, and (indirectly) wallet users pushing transactions. An unhandled exception raised mid-validation, rather than being converted into a `MempoolInclusionStatus.FAILED` / `Err.INVALID_COIN_SOLUTION` result, can propagate up through the calling task. Depending on how the caller (full-node peer message handler / RPC transaction submission handler) wraps this coroutine, this can surface as a transaction-processing halt or unexpected task failure triggered by a single crafted, unsigned spend bundle from any unprivileged submitter — matching the "spend-triggered transaction-processing halt" impact category.

### Likelihood Explanation
The trigger requires only submitting a `SpendBundle` with a `puzzle_reveal` or `solution` blob containing a crafted multi-byte atom length-prefix header followed by insufficient trailing bytes (a `>= 0x80` lead byte with a 2–6 byte length field, but a buffer shorter than the header itself). No signature or coin ownership is required to reach `is_clvm_canonical()` — it runs before any CoinRecord/timelock checks in `validate_spend_bundle()`. Constructing such a buffer is trivial and does not require valid CLVM.

### Recommendation
Add explicit bounds checks in `is_atom_canonical()` before each `clvm_buffer[offset]` access (verify `offset < len(clvm_buffer)` for both the header bytes and prior to returning `1 + prefix_len + atom_len`), and in `is_clvm_canonical()` before dereferencing `clvm_buffer[offset]` in the main loop and before advancing `offset` by `atom_len`. On any out-of-range condition, return `False` (non-canonical) instead of raising, or explicitly catch `IndexError` at the `is_clvm_canonical` call site in `validate_spend_bundle()` and convert it to `Err.INVALID_COIN_SOLUTION`.

### Proof of Concept
Submit a `CoinSpend` whose `solution` (or `puzzle_reveal`) bytes are a single byte such as `0xFC` (indicating a 5-byte trailing length field, per the `0b11111110 == 0b11111100` branch in `is_atom_canonical`) with zero or few trailing bytes, e.g. `bytes.fromhex("fc")`. Passing this buffer to `is_clvm_canonical()` causes `is_atom_canonical(clvm_buffer, 0)` to attempt `clvm_buffer[1]` through `clvm_buffer[5]`, which are out of range, raising an uncaught `IndexError` instead of returning `(len, False)`. Wrapped in a `SpendBundle` and submitted via `add_spend_bundle()`, this reaches the unguarded call at `chia/full_node/mempool_manager.py:723-726` before any signature/coin-record checks occur.

def is_atom_canonical(clvm_buffer: bytes, offset: int) -> tuple[int, bool]:
    b = clvm_buffer[offset]
    if (b & 0b11000000) == 0b10000000:
        # 6 bits length prefix
        mask = 0b00111111
        prefix_len = 0
        min_value = 1
    elif (b & 0b11100000) == 0b11000000:
        # 5 + 8 bits length prefix
        mask = 0b00011111
        prefix_len = 1
        min_value = 1 << 6
    elif (b & 0b11110000) == 0b11100000:
        # 4 + 8 + 8 bits length prefix
        mask = 0b00001111
        prefix_len = 2
        min_value = 1 << (5 + 8)
    elif (b & 0b11111000) == 0b11110000:
        # 3 + 8 + 8 + 8 bits length prefix
        mask = 0b00000111
        prefix_len = 3
        min_value = 1 << (4 + 8 + 8)
    elif (b & 0b11111100) == 0b11111000:
        # 2 + 8 + 8 + 8 + 8 bits length prefix
        mask = 0b00000011
        prefix_len = 4
        min_value = 1 << (3 + 8 + 8 + 8)
    elif (b & 0b11111110) == 0b11111100:
        # 1 + 8 + 8 + 8 + 8 + 8 bits length prefix
        mask = 0b00000001
        prefix_len = 5
        min_value = 1 << (2 + 8 + 8 + 8 + 8)

    atom_len = b & mask
    for i in range(prefix_len):
        atom_len <<= 8
        offset += 1
        atom_len |= clvm_buffer[offset]

    return 1 + prefix_len + atom_len, atom_len >= min_value
```

def is_clvm_canonical(clvm_buffer: bytes) -> bool:
    """
    checks whether the CLVM serialization is all canonical representation.
    atoms can be serialized in more than one way by using more bytes than
    necessary to encode the length prefix. This functions ensures that all atoms are
    encoded with the shortest representation. back-references are not allowed
    and will make this function return false
    """
    assert clvm_buffer != b""

    offset = 0
    tokens_left = 1
    while True:
        b = clvm_buffer[offset]

        # pair
        if b == 0xFF:
            tokens_left += 1
            offset += 1
            continue

        # back references cannot be considered canonical, since they may be
        # encoded in many different ways
        if b == 0xFE:
            return False

        # small atom or NIL
        if b <= 0x80:
            tokens_left -= 1
            offset += 1
        else:
            atom_len, canonical = is_atom_canonical(clvm_buffer, offset)
            if not canonical:
                return False
            tokens_left -= 1
            offset += atom_len

        if tokens_left == 0:
            break

    # if there's garbage at the end, it's not canonical
    return offset == len(clvm_buffer)
```
