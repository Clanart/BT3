### Title
Fee/size calculation omits the OP_RETURN data output, producing transactions that underpay fees and can become stuck - (File: networks/bitcoin/src/wallet/send.rs)

### Summary
The external report's bug class is "value accounted in one place but not another, leaving funds trapped." In `SignableTransaction::new`, when an OP_RETURN `data` output is requested, the weight/vbyte estimation used for `needed_fee`, the minimum-relay-fee check, and the change-output calculation are all performed on a transaction template built only from `payments` (and optionally `change`) — the data output is never included. The resulting transaction therefore pays a fee computed for a smaller transaction than the one actually produced.

### Finding Description
`SignableTransaction::new` pushes the OP_RETURN output into `tx_outs` before estimating fees:

```rust
// networks/bitcoin/src/wallet/send.rs
if let Some(data) = data {
  tx_outs.push(TxOut {
    value: Amount::ZERO,
    script_pubkey: ScriptBuf::new_op_return(...),
  })
}
let (mut weight, vbytes) = Self::calculate_weight_vbytes(tx_ins.len(), payments, None);
```

`calculate_weight_vbytes` rebuilds a template `Transaction` whose `output` list is derived solely from `payments` plus the optional `change` output — it has no `data` parameter and never models the OP_RETURN output (send.rs:61-99). An OP_RETURN output carrying up to 80 bytes of data adds roughly 90+ bytes to the serialized transaction, none of which is priced.

Consequences:

1. `needed_fee = fee_per_vbyte * vbytes` is computed on the underestimated vsize.
2. The minimum-relay check `needed_fee < (DEFAULT_MIN_RELAY_TX_FEE * vbytes) / 1000` is evaluated against the underestimated `vbytes`, so a transaction can pass this check while its true feerate is below the relay minimum.
3. The change branch recomputes `fee_with_change = fee_per_vbyte * vbytes_with_change`, again without the data output, and sets `needed_fee` to that value. The final transaction's actual fee (`sum(inputs) - sum(outputs)`) equals this underpriced `needed_fee`, so the signed transaction's real feerate is strictly lower than `fee_per_vbyte` requested.

### Impact Explanation
Any caller constructing a `SignableTransaction` with `data` (which the API explicitly supports up to 80 bytes) produces a threshold-signed transaction that underpays its fee relative to the requested rate, and potentially below `DEFAULT_MIN_RELAY_TX_FEE`. Such a transaction will not relay or confirm — the inputs it spends remain locked behind an unusable signed transaction until the coordinator intervenes and re-signs with corrected inputs, a direct analog of "funds moved into a state where they cannot be spent." The fee shortfall is proportional to the omitted ~90+ byte output multiplied by the chosen feerate.

### Likelihood Explanation
Deterministic whenever `data.is_some()`. It does not require a malicious party — any public caller of `SignableTransaction::new` passing an `OP_RETURN` payload triggers it. The magnitude of the shortfall (a fixed ~90-byte omission) is enough to drop a marginal-fee transaction below relay minimums, but not enough to silently burn large amounts to miners.

### Recommendation
Pass the `data` payload (or the fully built `tx_outs`/`TxOut` list including the OP_RETURN output) into `calculate_weight_vbytes` so both the no-change and with-change weight estimates include it. Alternatively, construct the final `tx` first and compute `weight`/`vbytes` directly from `self.tx` after all outputs (payments, data, change) are known, e.g. by estimating change with a provisional push of a zero-valued change `TxOut` on the real output vector.

### Proof of Concept
```rust
// With a single input worth `input_sat`, payments totaling `payment_sat`,
// a change script, and data = vec![0; 80]:
let tx = SignableTransaction::new(
    inputs, &payments, Some(change_addr), Some(vec![0; 80]), fee_per_vbyte,
).unwrap();

// The real transaction includes the OP_RETURN output (~92 extra bytes),
// but needed_fee() was computed as if it didn't exist:
let real_vbytes = tx.transaction().vsize() as u64;
assert!(tx.needed_fee() < fee_per_vbyte * real_vbytes);

// Equivalently, the actual fee rate of the produced TX is below fee_per_vbyte:
assert!(tx.fee() < fee_per_vbyte * real_vbytes);
// With fee_per_vbyte chosen at the relay minimum, tx.fee() / real_vbytes
// falls under DEFAULT_MIN_RELAY_TX_FEE and the signed TX will not relay.
```
