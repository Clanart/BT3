### Title
Unbounded CLVM buffer indexing in `is_clvm_canonical`/`is_atom_canonical` allows a spend-bundle-triggered crash - (File: chia/full_node/mempool_manager.py)

### Summary
`chia/full_node/mempool_manager.py` contains `is_clvm_canonical()` and its helper `is_atom_canonical()`, which walk a raw CLVM-serialized byte buffer to decide whether it is canonically encoded. Both functions index into the buffer (`clvm_buffer[offset]`) using length values and offsets that are derived entirely from attacker-controlled bytes, with no bound check against `len(clvm_buffer)` before each read. This mirrors the CWE-193 off-by-one/out-of-bounds read pattern in the yauzl advisory, where a length-derived cursor was allowed to run past the end of the buffer, causing an unhandled exception (`ERR_OUT_OF_RANGE` in Node.js; here, an `IndexError` in Python).

### Finding Description
`is_atom_canonical` reads a length-prefix byte and then loops `prefix_len` times, incrementing `offset` and reading `clvm_buffer[offset]` for each length byte, with no check that `offset` stays within the buffer: [1](#0-0) 

`is_clvm_canonical` walks tokens in the buffer, reading `clvm_buffer[offset]` on every iteration and advancing `offset` by `atom_len` (a value computed from attacker-supplied length bytes) without validating it against the remaining buffer length before continuing the loop: [2](#0-1) 

Because `atom_len` can be crafted to be larger than the remaining bytes in `clvm_buffer` (e.g., a truncated/malformed multi-byte atom length prefix at the very end of the buffer, or an oversized atom-length value that causes `offset` to exceed `len(clvm_buffer)`), the next iteration's `clvm_buffer[offset]` access raises an unhandled `IndexError`, exactly analogous to the yauzl `readUInt16LE()` reading past the buffer boundary due to an incorrect loop bound check (`cursor < data.length + 4` instead of `cursor + 4 <= data.length`).

Unlike other parsers in this codebase that carefully bound-check before every read (e.g. `skip_bytes`/`skip_list` in `chia/full_node/full_block_utils.py`, which explicitly validate `n > len(buf)` before slicing: [3](#0-2) ), `is_atom_canonical`/`is_clvm_canonical` perform no equivalent validation.

### Impact Explanation
If this canonical-serialization check is exercised on solution/puzzle bytes taken from a spend bundle submitted to the mempool (the function's docstring explicitly describes it as validating whether "atoms can be serialized in more than one way" in a submitted CLVM buffer, which is the exact class of check performed on untrusted spend bundle content before/while it is processed by `MempoolManager`), a crafted malformed buffer can trigger an unhandled `IndexError` deep in mempool processing. An unhandled exception in the full node's mempool/spend-bundle-processing path can crash or halt that worker/process, denying transaction processing — a spend-triggered transaction-processing halt, which is one of the explicitly accepted impact categories.

### Likelihood Explanation
Both `is_atom_canonical` and `is_atom_canonical`'s caller operate on raw bytes from a spend bundle's puzzle/solution, which is fully attacker-controlled input from any unprivileged bundle submitter. Constructing a buffer whose final atom's multi-byte length prefix is truncated, or whose declared atom length pushes `offset` past `len(clvm_buffer)`, requires no special privileges — it is a matter of crafting specific byte sequences, similar in triviality to the yauzl NTFS timestamp off-by-one PoC.

### Recommendation
Add explicit bounds checks before every buffer read in `is_atom_canonical` and `is_clvm_canonical`:
- In `is_atom_canonical`, verify `offset + prefix_len < len(clvm_buffer)` (or equivalent) before entering the `for i in range(prefix_len)` loop that reads `clvm_buffer[offset]`.
- In `is_clvm_canonical`, verify `offset < len(clvm_buffer)` before every `clvm_buffer[offset]` access, and treat an out-of-range `offset` (whether from a corrupt length prefix or an oversized `atom_len`) as "not canonical" (return `False`) rather than letting the index raise.
- Add regression tests analogous to `chia/_tests/util/test_full_block_utils.py`'s `test_skip_bytes_rejects_length_exceeding_remaining_buffer` style tests, feeding truncated/oversized atom-length buffers into `is_clvm_canonical` and asserting a clean `False`/error rather than an unhandled exception.

### Proof of Concept
A buffer ending in a truncated multi-byte atom length prefix triggers the out-of-bounds read:
```python
from chia.full_node.mempool_manager import is_clvm_canonical

# 0xF8 signals a "2 + 8*4"-bit length atom (prefix_len = 4), but the buffer
# is cut off after the opcode byte, leaving no length bytes to read.
malformed = bytes([0xF8])
is_clvm_canonical(malformed)  # raises IndexError instead of returning False
``` [4](#0-3)

def is_atom_canonical(clvm_buffer: bytes, offset: int) -> tuple[int, bool]:
    b = clvm_buffer[offset]
    if (b & 0b11000000) == 0b10000000:
        # 6 bits length prefix
        mask = 0b00111111
        prefix_len = 0
        min_value = 1
    elif (b & 0b11100000) == 0b11000000:
        # 5 + 8 bits length prefix
        mask = 0b00011111
        prefix_len = 1
        min_value = 1 << 6
    elif (b & 0b11110000) == 0b11100000:
        # 4 + 8 + 8 bits length prefix
        mask = 0b00001111
        prefix_len = 2
        min_value = 1 << (5 + 8)
    elif (b & 0b11111000) == 0b11110000:
        # 3 + 8 + 8 + 8 bits length prefix
        mask = 0b00000111
        prefix_len = 3
        min_value = 1 << (4 + 8 + 8)
    elif (b & 0b11111100) == 0b11111000:
        # 2 + 8 + 8 + 8 + 8 bits length prefix
        mask = 0b00000011
        prefix_len = 4
        min_value = 1 << (3 + 8 + 8 + 8)
    elif (b & 0b11111110) == 0b11111100:
        # 1 + 8 + 8 + 8 + 8 + 8 bits length prefix
        mask = 0b00000001
        prefix_len = 5
        min_value = 1 << (2 + 8 + 8 + 8 + 8)

    atom_len = b & mask
    for i in range(prefix_len):
        atom_len <<= 8
        offset += 1
        atom_len |= clvm_buffer[offset]

    return 1 + prefix_len + atom_len, atom_len >= min_value
```

def is_clvm_canonical(clvm_buffer: bytes) -> bool:
    """
    checks whether the CLVM serialization is all canonical representation.
    atoms can be serialized in more than one way by using more bytes than
    necessary to encode the length prefix. This functions ensures that all atoms are
    encoded with the shortest representation. back-references are not allowed
    and will make this function return false
    """
    assert clvm_buffer != b""

    offset = 0
    tokens_left = 1
    while True:
        b = clvm_buffer[offset]

        # pair
        if b == 0xFF:
            tokens_left += 1
            offset += 1
            continue

        # back references cannot be considered canonical, since they may be
        # encoded in many different ways
        if b == 0xFE:
            return False

        # small atom or NIL
        if b <= 0x80:
            tokens_left -= 1
            offset += 1
        else:
            atom_len, canonical = is_atom_canonical(clvm_buffer, offset)
            if not canonical:
                return False
            tokens_left -= 1
            offset += atom_len

        if tokens_left == 0:
            break

    # if there's garbage at the end, it's not canonical
    return offset == len(clvm_buffer)
```

def skip_bytes(buf: memoryview) -> memoryview:
    if len(buf) < 4:
        raise ValueError(f"byte length prefix requires 4 bytes, remaining buffer {len(buf)}")
    n = int.from_bytes(buf[:4], "big", signed=False)
    buf = buf[4:]
    if n > len(buf):
        raise ValueError(f"byte length {n} exceeds remaining buffer {len(buf)}")
    return buf[n:]
