### Title
Payment to the multisig's own change address is a no-op that still burns the transaction fee — (File: networks/bitcoin/src/wallet/send.rs)

### Summary
`SignableTransaction::new` validates dust, solvency, and fee minimums, but never checks whether a payment's `script_pubkey` is the same as the transaction's own `change` script (or otherwise an address belonging to the spending multisig). Analogous to the Swapper issue where `tokenIn == tokenOut` pays a caller fee for a no-op, a payment whose script equals the change script produces a transaction whose entire effect is returning the inputs to the same wallet — a literal no-op — while still paying `needed_fee` in satoshis to miners and consuming a confirmed UTXO.

### Finding Description
In `SignableTransaction::new` (`networks/bitcoin/src/wallet/send.rs`), payments are converted directly into outputs:

```rust
let payment_sat = payments.iter().map(|payment| payment.1).sum::<u64>();
let mut tx_outs = payments
  .iter()
  .map(|payment| TxOut { value: Amount::from_sat(payment.1), script_pubkey: payment.0.clone() })
  .collect::<Vec<_>>();
```

(lines 187–191) and the change output is appended afterward with the same-wallet script (lines 224–235). No comparison is made between `payment.0` and `change` anywhere in the constructor — the only validations are the empty-input/output checks, `DustPayment`, `TooMuchData`, `TooLowFee`, and `NotEnoughFunds` (lines 157–221).

If a caller supplies `payments = [(change_script, X)]` with `change = Some(change_script)`, the resulting transaction spends `input_sat` and creates outputs all paying back to the same wallet scripts, while `needed_fee = fee_per_vbyte * vbytes` is irrevocably lost (line 206). Worse, the wallet's own `Scanner` (`networks/bitcoin/src/wallet/mod.rs`, `scan_transaction`, lines 199–214) matches outputs purely by `script_pubkey` against registered scripts — and since change/branch scripts are derived from the multisig key, the no-op payment output will be re-scanned as a fresh `ReceivedOutput`. An output that originated from Serai's own inputs becomes indistinguishable from a genuine external deposit, and the whole cycle can repeat, each iteration burning another fee.

### Impact Explanation
- Direct satoshi loss: every such transaction pays `needed_fee` for zero net movement of funds. Repeated triggers force the multisig to sign fee-burning no-op transactions and shrink the wallet's balance over time.
- The re-scanned self-payment re-enters the UTXO set as a "new" `ReceivedOutput`, potentially being re-attributed as a fresh deposit upstream and enabling the same funds to be counted twice in whatever crediting logic consumes `Scanner` results.

### Likelihood Explanation
The trigger is a payment list containing a script belonging to the multisig itself — e.g., the change address or branch address, both of which are publicly computable from the group key (`p2tr_script_buf(key + G*offset)`). Any unprivileged party who can cause a burn/withdrawal addressed to one of these scripts supplies the `payments` argument that reaches `SignableTransaction::new`. No privileged position is required; the missing check is entirely within in-scope code since both `payments` and `change` are already available to the constructor.

### Recommendation
In `SignableTransaction::new`, reject or skip any payment whose `script_pubkey` equals the provided `change` script (and, where the wallet's own script set is known, any other self-owned script). If all payments are no-ops and no `data` output exists, treat the transaction as having no effective outputs and return early rather than paying `needed_fee`. Additionally, `Scanner`/`scan_transaction` could tag outputs that appear in transactions spending Serai's own inputs, so self-payments are not re-registered as fresh deposits.

### Proof of Concept
Conceptual, against `SignableTransaction::new` in `networks/bitcoin/src/wallet/send.rs`:

```rust
let change_script = p2tr_script_buf(offset_change_key).unwrap();
// "Withdrawal" addressed to our own change address
let payments = &[(change_script.clone(), 10_000)];
let tx = SignableTransaction::new(
  vec![received_output],       // input worth >= 10_000 + fee
  payments,
  Some(change_script),         // same script as the payment
  None,
  fee_per_vbyte,
).unwrap();
// tx.fee() > 0 while every output pays back to the same wallet scripts:
// net wallet balance decreases by tx.fee() with no value leaving Serai.
// Scanner::scan_transaction(&tx.tx) re-registers the payment output
// as a new ReceivedOutput, completing the loop.
```

All outputs in the constructed `tx` belong to the same multisig (`scripts` map in `Scanner`), yet `needed_fee` (line 206) is consumed and `input_sat - payment_sat` may additionally be funneled into a change output on the same script — a pure fee for a no-op.
