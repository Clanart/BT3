### Title
Sign-in flow treats attacker-controlled remote hosts as trusted "Enterprise" GitHub, enabling credential phishing via unauthenticated GIT_ASKPASS/credential-helper prompts - (File: `app/src/lib/api.ts`, `app/src/lib/trampoline/trampoline-credential-helper.ts`)

### Summary
The C4 report's broken invariant is: an object (`Synth`) is trusted to belong to the pool's trust domain without checking its actual underlying token, letting an attacker mint/burn across pools at the wrong price. The Desktop analog is a similar "missing domain-binding check": `isGitHubHost()` in `app/src/lib/api.ts:2429-2491` classifies a git remote/submodule hostname as an "enterprise GitHub" endpoint using a loose substring regex instead of verifying the host is actually the account's trusted endpoint, and `getEndpointKind()` in `app/src/lib/trampoline/trampoline-credential-helper.ts:137-179` uses that classification to decide whether to show the user a GitHub credential-helper sign-in prompt that is presented as if the destination were a legitimate GitHub Enterprise host.

### Finding Description
When Git needs credentials for a remote (including a submodule remote encountered during a `--recursive` clone, see `app/src/lib/git/clone.ts:88-93`), the trampoline credential helper (`createCredentialHelperTrampolineHandler`, `app/src/lib/trampoline/trampoline-credential-helper.ts:220-259`) calls `getCredential` → `getEndpointKind`.

`getEndpointKind` first tries exact-match checks (`isGist`, `isDotCom`, `isGHE` in `app/src/lib/endpoint-capabilities.ts:47-68`, all of which parse the URL and compare `hostname` exactly), then falls back to `isGitHubHost(endpoint)` (`app/src/lib/api.ts:2435-2491`) when none of those exact checks match and no existing account origin matches (`findGitHubTrampolineAccount`, exact-origin match, `app/src/lib/trampoline/find-account.ts:20-29`).

Inside `isGitHubHost`, after excluding known third-party hosts (`app/src/lib/api.ts:2407-2427`), the function does:
```
// github.example.com,
if (/(^|\.)(github)\./.test(hostname)) {
  return true
}
```
This regex only requires the substring `github.` to appear at the start of the hostname or immediately after a dot. A hostname like `github.attacker.com`, `sub.github.evilcorp.io`, or a domain purchased/controlled by an attacker containing `github.` as a label satisfies this without any relationship to a real GitHub Enterprise install. Because there is no network round-trip performed for this branch (it returns before the `fetch(metaUrl, ...)` health-check further down), the classification is immediate and silent.

`getEndpointKind` then returns `'enterprise'` for such a host. Back in `getCredential` (`trampoline-credential-helper.ts:94-125`), because `endpointKind !== 'generic'` and the user has no account for this fabricated `apiEndpoint`, the code calls `ui.promptForGitHubSignIn(endpoint)` (`trampoline-ui-helper.ts:80-104`). This shows the standard "Sign in to GitHub Enterprise" dialog (`PopupType.SignIn`, `isCredentialHelperSignIn: true`) with `credentialHelperUrl` set to the attacker's host, and calls `dispatcher.beginEnterpriseSignIn` / `setSignInEndpoint(origin)` with the attacker's origin. From the user's point of view, Desktop itself — not a web page — is asking them to authenticate to what it labels a GitHub host, which is a strong social-engineering amplifier baked into a legitimate app-triggered dialog. If the user completes this OAuth/PAT sign-in flow, the resulting Account (including its token) is created bound to the attacker's endpoint, and Desktop will subsequently trust that endpoint as a valid, stored GitHub account going forward.

This differs from the recommended synth fix in the original report (`require(iSYNTH(synthOut).LayerONE() == TOKEN)`) only in domain: instead of binding a synth to its underlying token, Desktop should bind a "GitHub host" classification to the real registered endpoint/account, not to a substring match on the hostname.

### Impact Explanation
An attacker who controls a git remote or a submodule URL referenced by a cloned/fetched repository (e.g. a `.gitmodules` entry pointing to `https://github.enterprise-phish.com/...` or `https://sub.github.io.evil.net/...`) can cause GitHub Desktop to present its native "Sign in to GitHub Enterprise" UI, primed with an attacker-controlled endpoint, purely as a side effect of the victim cloning/fetching a repository with `--recursive` (the default for Desktop clones, see `app/src/lib/git/clone.ts:92`). If the victim completes sign-in, their GitHub credentials/OAuth token are sent to (and an account object is stored bound to) the attacker's server, which is an unauthorized OAuth/account-binding outcome and a credential exfiltration vector, entirely from a repository/submodule the user chose to clone or fetch — no local access, malware, or leaked credentials required.

### Likelihood Explanation
The trigger is a normal, expected Desktop action: cloning/fetching any public repository (potentially recommended, forked, or found via search) that has a crafted submodule/remote URL. The `isGitHubHost` fallback path is reached whenever the host isn't already a known GitHub.com/GHE/known-third-party host and no existing account matches the origin exactly — i.e., precisely the scenario an attacker controls. The false classification is deterministic (regex-based, no heuristics needed to defeat) and requires no timing or race condition. The remaining step (user completing sign-in) requires user interaction, which lowers likelihood somewhat versus a fully silent exploit, but the dialog is rendered by Desktop itself using GitHub Desktop's trusted UI chrome, making it considerably more convincing than a generic phishing page.

### Recommendation
Do not use substring/regex matching on hostnames to decide trust classification for credential prompts. `isGitHubHost` should only classify a host as an "enterprise" GitHub endpoint if:
- it exactly matches (or is a validated subdomain of) an endpoint the user has explicitly added as a GitHub Enterprise server, or
- the network probe (`x-github-request-id` / `x-github-enterprise-version` header check already present later in the function) succeeds — i.e., always require the live verification step and drop the `/(^|\.)(github)\./` shortcut entirely, since it provides no actual security guarantee and only saves one HTTP request.

Additionally, `getEndpointKind`'s "prompt for GitHub sign-in" branch should clearly and unambiguously display the exact untrusted hostname to the user before initiating `beginEnterpriseSignIn`, rather than only the endpoint URL buried inside a generic-looking "Sign in" dialog, so users can recognize spoofed lookalike domains.

### Proof of Concept
1. Attacker creates a public repository `evil/lure` with a `.gitmodules` file containing a submodule pointing at `https://github.enterprise-phish.com/foo/bar.git` (a domain the attacker registered and controls, serving valid TLS and returning a `401` with no special headers on any request, to force Git into the credential-helper path).
2. Victim clones `evil/lure` (or fetches it) using GitHub Desktop, which runs `git clone --recursive ...` (`app/src/lib/git/clone.ts:88-93`).
3. Git attempts to fetch the submodule from `github.enterprise-phish.com` and invokes the trampoline credential helper (`GIT_CONFIG_PARAMETERS` set in `app/src/lib/trampoline/trampoline-environment.ts:143`).
4. `getEndpointKind` runs: `isDotCom`/`isGHE`/`isGist` all return false (hostname doesn't match), `findGitHubTrampolineAccount` finds no matching origin, protocol is `https:`, so it calls `isGitHubHost('https://github.enterprise-phish.com/...')`.
5. `isKnownThirdPartyHost` returns false; the regex `/(^|\.)(github)\./.test('github.enterprise-phish.com')` returns `true` (the hostname starts with `github.`), so `isGitHubHost` returns `true` without ever reaching the network probe.
6. `getEndpointKind` returns `'enterprise'`. Since no account exists for the synthesized `apiEndpoint`, `getCredential` calls `ui.promptForGitHubSignIn('https://github.enterprise-phish.com/...')`.
7. Desktop shows its native "Sign in to GitHub Enterprise" dialog bound to `github.enterprise-phish.com`. If the victim signs in (OAuth or PAT), their credentials/token are sent to the attacker's endpoint and an `Account` is created and stored bound to that attacker-controlled endpoint.

I could not execute this end-to-end in a live Desktop instance from the index alone (no terminal/browser access in ask-only mode), so steps 6–7's exact dialog wording/flow are inferred from `trampoline-ui-helper.ts:80-104` and `dispatcher.beginEnterpriseSignIn`/`setSignInEndpoint` rather than observed at runtime; a Devin session with full repo/checkout access would be needed to confirm the exact rendered dialog text and finalize a fix. /**
 * Attempts to determine whether or not the url belongs to a GitHub host.
 *
 * This is a best-effort attempt and may return `undefined` if encountering
 * an error making the discovery request
 */
export async function isGitHubHost(url: string) {
  const { hostname } = new window.URL(url)

  const endpoint =
    hostname === 'github.com' || hostname === 'api.github.com'
      ? getDotComAPIEndpoint()
      : getEnterpriseAPIURL(url)

  if (isDotCom(endpoint) || isGHE(endpoint)) {
    return true
  }

  if (isKnownThirdPartyHost(hostname)) {
    return false
  }

  // github.example.com,
  if (/(^|\.)(github)\./.test(hostname)) {
    return true
  }

  // bitbucket.example.com, etc
  if (/(^|\.)(bitbucket|gitlab)\./.test(hostname)) {
    return false
  }

  if (getEndpointVersion(endpoint) !== null) {
    return true
  }

/** Implementation of the 'get' git credential helper command */
async function getCredential(cred: Credential, store: Store, token: string) {
  const ghCred = await getGitHubCredential(cred, store)

  if (ghCred) {
    return ghCred
  }

  const endpointKind = await getEndpointKind(cred, store)
  const accounts = await store.getAll()

  const endpoint = `${getCredentialUrl(cred)}`
  const apiEndpoint = getAPIEndpoint(endpoint)

  // If it appears as if the endpoint is a GitHub host and we don't have an
  // account for that endpoint then we should prompt the user to sign in.
  if (
    endpointKind !== 'generic' &&
    !accounts.some(a => a.endpoint === apiEndpoint)
  ) {
    if (getIsBackgroundTaskEnvironment(token)) {
      debug('background task environment, skipping prompt')
      return undefined
    }

    const account = await ui.promptForGitHubSignIn(endpoint)

    if (!account) {
      setHasRejectedCredentialsForEndpoint(token, endpoint)
    }

    return credWithAccount(cred, account)
  }

  // GitHub.com/GHE creds are only stored internally
  if (endpointKind !== 'generic') {
    return undefined
  }

  return useExternalCredentialHelper()
    ? getExternalCredential(cred, token)
    : getGenericCredential(cred, token)
}

const getEndpointKind = async (cred: Credential, store: Store) => {
  const credentialUrl = getCredentialUrl(cred)
  const endpoint = `${credentialUrl}`

  if (isGist(endpoint)) {
    return 'generic'
  }

  if (isDotCom(endpoint)) {
    return 'github.com'
  }

  if (isGHE(endpoint)) {
    return 'ghe.com'
  }

  // When Git attempts to authenticate with a host it captures any
  // WWW-Authenticate headers and forwards them to the credential helper. We
  // use them as a happy-path to determine if the host is a GitHub host without
  // having to resort to making a request ourselves.
  for (const [k, v] of cred.entries()) {
    if (k.startsWith('wwwauth[')) {
      if (v.includes('realm="GitHub"')) {
        return 'enterprise'
      } else if (/realm="(GitLab|Gitea|Atlassian Bitbucket)"/.test(v)) {
        return 'generic'
      }
    }
  }

  const existingAccount = await findGitHubTrampolineAccount(store, endpoint)
  if (existingAccount) {
    return isDotCom(existingAccount.endpoint) ? 'github.com' : 'enterprise'
  }

  // All GitHub hosts use HTTPS, so if the protocol is not HTTPS we can
  // assume that this is not a GitHub host.
  if (credentialUrl.protocol !== 'https:') {
    return 'generic'
  }

  return (await isGitHubHost(endpoint)) ? 'enterprise' : 'generic'
}

export const isDotCom = (ep: string) => {
  if (ep === getDotComAPIEndpoint()) {
    return true
  }

  const { hostname } = new URL(ep)
  return hostname === 'api.github.com' || hostname === 'github.com'

  public promptForGitHubSignIn(endpoint: string): Promise<Account | undefined> {
    return new Promise<Account | undefined>(async resolve => {
      const cb = (result: SignInResult) => {
        resolve(result.kind === 'success' ? result.account : undefined)
        this.dispatcher.closePopup(PopupType.SignIn)
      }

      const { hostname, origin } = new URL(endpoint)
      if (hostname === 'github.com') {
        this.dispatcher.beginDotComSignIn(cb)
      } else {
        this.dispatcher.beginEnterpriseSignIn(cb)
        await this.dispatcher.setSignInEndpoint(origin)
      }

      this.dispatcher.showPopup({
        type: PopupType.SignIn,
        isCredentialHelperSignIn: true,
        credentialHelperUrl: endpoint,
      })
    }).catch(e => {
      log.error(`Could not prompt for GitHub sign in`, e)
      return undefined
    })
  }
