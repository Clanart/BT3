### Title
ProtoJSON `Printer` in `JsonFormat.java` ignores `debug_redact` field option, exposing sensitive fields that TextFormat's redacted `DebugString` would mask - (File: `java/util/src/main/java/com/google/protobuf/util/JsonFormat.java`)

### Summary
Protobuf provides a documented, purpose-built anti-disclosure control: the `debug_redact` field option (declared in `descriptor.proto`) which causes `TextFormat`'s safe/debug printers to replace a field's value with `[REDACTED]` instead of emitting the plaintext value. This mirrors the invariant Rancher's advisory describes: certain fields (secrets, tokens) must never reach a log/debug sink in cleartext. In the Java `JsonFormat` printer, this redaction check is never consulted: `printField`/`printSingleFieldValue` serialize every field's raw value into JSON regardless of `debug_redact`, so an application that (a) marks a field `debug_redact=true` believing it is protected from appearing in logs, and (b) logs the ProtoJSON representation of the message (a very common pattern, e.g. via gRPC/HTTP transcoding logging, audit middlewares, or structured logging) will unconditionally leak the sensitive value in cleartext.

### Finding Description
`FieldOptions.debug_redact` is Protobuf's own safety invariant for preventing exactly the CWE-532 class of bug in the external report: sensitive field values (secrets, tokens) must not appear in debug/log output. This is enforced end-to-end in the C++/Java `TextFormat` code path:

- `src/google/protobuf/text_format.cc` `TryRedactFieldValue()` consults `TextFormat::GetRedactionState(field)` (built from `field->options().debug_redact()`), and when `redact_debug_string_` is set, substitutes `[REDACTED]` for the value [1](#0-0) , invoked from both `PrintField` (message-typed fields) and `PrintFieldValue` (scalar fields) before any value is emitted [2](#0-1) [3](#0-2) .
- The Java equivalent, `TextFormat.Printer.printFieldValue`, calls `shouldRedact(field, generator)` based on `field.getRedactionState()` before printing any value [4](#0-3) [5](#0-4) , and `Descriptors.java` computes/caches this redaction state from `FieldOptions.getDebugRedact()` [6](#0-5) .

In contrast, `JsonFormat.java`'s printer implementation contains no reference at all to `debug_redact`/redaction (confirmed by repo-wide search: zero matches in any JSON-related file, including `JsonFormat.java`, upb's JSON encoder, and Python's `json_format.py`). The JSON printer's `printField`, `printRepeatedFieldValue`, `printMapFieldValue`, and `printSingleFieldValue` methods unconditionally serialize every field's value to JSON with no redaction gate [7](#0-6) [8](#0-7) . This is true even for the `Any` expansion path (`printAny`), which recursively decodes and prints the packed message's fields with no redaction awareness either [9](#0-8) .

This mirrors the Rancher bug's structural pattern precisely: the redaction control exists and is correctly enforced on one output/serialization surface (Rancher's primary field-level redaction; Protobuf's `TextFormat`/`DebugFormat`), but a second surface that also carries the same underlying sensitive data (Rancher's `kubectl.kubernetes.io/last-applied-configuration` annotation duplicate; Protobuf's ProtoJSON output) is completely unaware of the redaction rule and leaks the value unredacted into whatever sink consumes it (audit logs in Rancher's case; application/audit logs in a Protobuf-consuming service).

### Impact Explanation
Any Protobuf-consuming application that marks fields `debug_redact = true` under the (reasonable, documented) assumption that this protects the field from appearing in debug/log output, but which uses `JsonFormat.printer().print(message)` (or the analogous JSON print path) for structured logging, audit trails, or error reporting, will have the "protected" field's plaintext value silently included in JSON logs. This is a direct information-disclosure primitive (CWE-532 analog) for any field the application owner explicitly flagged as sensitive — credentials, tokens, PII — with no bypass required by an attacker beyond simply having their attacker-controlled or server-generated sensitive value flow into a message field marked `debug_redact` and observed via a JSON-based logging/audit sink, exactly as in the Rancher case where secret `stringData` values leaked through a secondary (annotation-based) representation into audit logs.

### Likelihood Explanation
High for any codebase relying on `debug_redact` + JSON logging together: the omission is unconditional (there is no flag, mode, or configuration in `JsonFormat` that enables redaction), so every JSON-serialized message with a `debug_redact` field is affected. Given that ProtoJSON is the standard wire format for gRPC-Web/REST transcoding and is commonly logged for request/response auditing, exposure is realistic and requires no attacker sophistication — it's a silent gap in a documented security control, discoverable by reading `JsonFormat.java` and confirming the absence of `GetRedactionState`/`debug_redact` checks (as done above).

### Recommendation
Extend `JsonFormat.Printer` (and the corresponding upb/Python/C++ JSON printing code paths) to consult the same `FieldDescriptor.getRedactionState()` (Java) / `TextFormat::GetRedactionState()` (C++) logic used by `TextFormat`, and substitute a `"[REDACTED]"` (or omit) marker for fields where `redact == true`, at minimum in a "safe/debug JSON printer" mode analogous to `DebugFormat`. Document clearly that `JsonFormat.printer().print()` (the production JSON output) is not currently redaction-aware, so application authors do not mistakenly assume `debug_redact` protects JSON logging paths, mirroring Rancher's own remediation of explicitly redacting all leaking paths rather than just the primary field-level annotation.

### Proof of Concept
Using the repository's own test schema `RedactedFields` (`rust/test/unittest.proto` / `src/google/protobuf/unittest.proto`, which declares `string optional_redacted_string = 1 [debug_redact = true];`) [10](#0-9) :

1. Build `RedactedFields.newBuilder().setOptionalRedactedString("super-secret-token").build()`.
2. Call `DebugFormat.multiline().toString(message)` → output contains `optional_redacted_string: [REDACTED]` (verified by existing test `DebugFormatTest.messageFormat_debugRedactFieldIsRedacted`) [11](#0-10) .
3. Call `JsonFormat.printer().print(message)` → output is `{"optionalRedactedString":"super-secret-token"}` — the plaintext value is serialized in full because `printSingleFieldValue`/`printField` never check `debug_redact` [7](#0-6) .

An application that logs `JsonFormat.printer().print(message)` for audit/debug purposes — while trusting `debug_redact` to keep the field out of logs, as validated by step 2 — leaks the sensitive value via step 3, reproducing the Rancher-style "documented redaction control exists on one surface but not another consumed by logging" failure.

bool TextFormat::Printer::TryRedactFieldValue(
    const Message& message, const FieldDescriptor* field,
    BaseTextGenerator* generator, bool insert_value_separator) const {
  TextFormat::RedactionState redaction_state =
      DescriptorPool::MemoizeProjection(
          field, [](const FieldDescriptor* field) {
            return TextFormat::GetRedactionState(field);
          });
  if (redaction_state.redact) {
    if (redact_debug_string_) {
      IncrementRedactedFieldCounter();
      if (insert_value_separator) {
        generator->PrintMaybeWithMarker(MarkerToken(), ": ");
      }
      generator->PrintString(kFieldValueReplacement);
      if (insert_value_separator) {
        if (single_line_mode_) {
          generator->PrintLiteral(" ");
        } else {
          generator->PrintLiteral("\n");
        }
      }
      return true;
    }
  }
  return false;
}

    // Lazily calculates the redact state of the field, caching the result.
    RedactionState getRedactionState() {
      RedactionState state = redactionState;
      if (state == null) {
        // If the field is directly marked with debug_redact=true, then it is sensitive.
        synchronized (this) {
          state = redactionState;
          if (state == null) {
            FieldOptions options = getOptions();
            state = RedactionState.of(options.getDebugRedact());
            // Check if the FieldOptions contain any enums that are marked as debug_redact=true,
            // either directly or indirectly via a message option.
            for (Map.Entry<Descriptors.FieldDescriptor, Object> entry :
                options.getAllFields().entrySet()) {
              state =
                  RedactionState.combine(
                      state, isOptionSensitive(entry.getKey(), entry.getValue()));
              if (state.redact) {
                break;
              }
            }
            redactionState = state;
          }
        }
      }
      return state;
    }
