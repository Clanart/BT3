That, combined with the raw `.call` in `withdraw()`, completes the analog to the M-04 report.

### Title
Unchecked low-level `.call` in `withdraw()` accepts false transfer success for destroyed/non-existent ERC20 tokens, causing silent fund loss and false escrow settlement - (File: `evm/tron/contracts/apps/IntentGatewayV2.sol`)

### Summary
`IntentGatewayV2.placeOrder` lets any caller escrow an arbitrary ERC20 token address of their choosing with no allowlist restriction [1](#0-0) . When escrow is later released via `withdraw()`, the payout for non-native tokens is performed with a raw low-level `.call` that only checks the boolean `success` flag and never inspects `returndata`, and never verifies the target has contract code:

```solidity
(bool success,) = token.call(abi.encodeWithSelector(IERC20.transfer.selector, beneficiary, amount));
if (!success) revert TransferFailed();
``` [2](#0-1) 

Per EVM semantics, a `.call` to an address with no deployed bytecode (e.g., a token that has been `selfdestruct`ed after escrow but before withdrawal) returns `success = true` with empty `returndata`, exactly the scenario described in the QuickSwap `TransferHelper.safeTransfer` report. The same unchecked pattern also feeds the fee-token payout in the same function [3](#0-2)  and the `SweepDust` admin-request handler [4](#0-3) .

### Finding Description
Note that the rest of this contract, and the deposit path in `placeOrder`, correctly use OpenZeppelin's `SafeERC20.safeTransferFrom` (`using SafeERC20 for IERC20;`) [5](#0-4)  — that library does check `address(token).code.length > 0` before dispatching the call, which is the exact mitigation the QuickSwap judge recommended. However, `withdraw()`, which pays out escrowed tokens on `EscrowReleased`/`EscrowRefunded` [6](#0-5) , bypasses this safe wrapper and reverts to a bare `.call` that:
1. Does not check `token.code.length > 0` (no existence check), and
2. Does not decode/require `data.length == 0 || abi.decode(data,(bool))` (weaker even than the reported `TransferHelper.safeTransfer`, which at least checks the decoded boolean).

The corrupted value is `success` from `token.call(...)`: it is `true` even though zero tokens moved, because the target account no longer has code. `withdraw()` treats this as a valid transfer, then unconditionally decrements `_orders[commitment][token] -= amount` and sets `_filled[commitment] = beneficiary`, permanently recording the order as settled/refunded and emitting `EscrowReleased`/`EscrowRefunded`, even though the beneficiary received nothing.

### Impact Explanation
This produces false settlement-state acceptance and fund loss without needing any malicious relayer, prover, or admin: an unprivileged user places an order with a token they control (via `placeOrder`, which has no token allowlist) [1](#0-0) , funds the escrow (`safeTransferFrom` succeeds because the token exists at deposit time), then self-destructs the token contract before the fill/refund/withdrawal path executes. The subsequent `withdraw()` call silently "succeeds," escrow accounting is wiped, and the recorded beneficiary never receives real tokens — an irreversible loss/lock of the escrowed value with the protocol's own bookkeeping falsely showing completion.

### Likelihood Explanation
Likelihood is limited to the same "explicit external requirement" the QuickSwap judge acknowledged (an attacker-supplied destructible token), but here it requires no relayer/peer compromise and is directly reachable by any address calling public `placeOrder` with a token they created and can `selfdestruct`, then triggering solver-fill/refund/timeout flows that call `withdraw()`.

### Recommendation
Replace the raw `.call(...)` transfers in `withdraw()` (both the token loop and the fee-token payout) and in the `SweepDust` handler with `SafeERC20.safeTransfer`, consistent with the rest of the contract, so that transfers to destroyed/non-existent token contracts revert instead of silently marking escrow as settled.

### Proof of Concept
1. Attacker deploys `EvilToken` (standard ERC20 with an owner-gated `selfdestruct`).
2. Attacker calls `placeOrder` with `order.inputs[0].token = EvilToken`, depositing via `safeTransferFrom` (succeeds — token exists) [7](#0-6) .
3. Attacker triggers the refund/timeout path (or arranges a fill) so `withdraw()` is invoked for that commitment.
4. Before/at that call, attacker self-destructs `EvilToken`.
5. `token.call(abi.encodeWithSelector(IERC20.transfer.selector, beneficiary, amount))` returns `success = true` with no code executed [8](#0-7) .
6. `_orders[commitment][token] -= amount` and `EscrowReleased`/`EscrowRefunded` fire as if funds were paid, but the beneficiary's balance never changed — the escrowed value is unrecoverably lost from the protocol's perspective.

    function withdraw(WithdrawalRequest memory body, bool isRefund) internal {
        address beneficiary = address(uint160(uint256(body.beneficiary)));
        _filled[body.commitment] = beneficiary;

        // redeem escrowed tokens
        uint256 len = body.tokens.length;
        for (uint256 i; i < len;) {
            address token = address(uint160(uint256(body.tokens[i].token)));
            uint256 amount = body.tokens[i].amount;
            if (_orders[body.commitment][token] == 0) revert UnknownOrder();

            if (token == address(0)) {
                (bool sent,) = beneficiary.call{value: amount}("");
                if (!sent) revert InsufficientNativeToken();
            } else {
                (bool success,) = token.call(abi.encodeWithSelector(IERC20.transfer.selector, beneficiary, amount));
                if (!success) revert TransferFailed();
            }

            _orders[body.commitment][token] -= amount;
            unchecked {
                ++i;
            }
        }

        // redeem tx fees
        uint256 fees = _orders[body.commitment][TRANSACTION_FEES];
        if (fees > 0) {
            address feeToken = IDispatcher(host()).feeToken();
            (bool success,) = feeToken.call(abi.encodeWithSelector(IERC20.transfer.selector, beneficiary, fees));
            if (!success) revert TransferFailed();
            delete _orders[body.commitment][TRANSACTION_FEES];
        }

        if (isRefund) {
            emit EscrowRefunded({commitment: body.commitment});
        } else {
            emit EscrowReleased({commitment: body.commitment});
        }
    }
