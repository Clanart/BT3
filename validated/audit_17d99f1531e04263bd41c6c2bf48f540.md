### Title
Unvalidated DataLayer Mirror URLs Cause Server-Side Request Forgery (SSRF) Against Any Node Running the DataLayer Service - ([File: chia/data_layer/download_data.py])

### Summary
Any wallet user can register a DataLayer mirror with arbitrary URL strings via `DataLayer.add_mirror()`, which pushes them on-chain through a mirror coin. No component in the DataLayer service validates the scheme, host, or destination network of these URLs before other users' DataLayer services fetch data from them, allowing SSRF against any node that subscribes to or syncs that store.

### Finding Description
`DataLayer.add_mirror()` accepts a caller-supplied list of URL strings and pushes them on chain with no validation at all: [1](#0-0) 

These URLs are recorded via a mirror coin (`create_mirror_puzzle`), and every DataLayer wallet that is watching the corresponding singleton picks them up in `coin_added()` and stores them unmodified into local `dl_store`/`DataStore` records: [2](#0-1) 

Any peer running its own DataLayer service and subscribed to the same store id pulls these URLs via `update_subscriptions_from_wallet()`, only stripping a trailing slash — no scheme allowlist, no hostname/IP filtering: [3](#0-2) [4](#0-3) 

During normal sync (`fetch_and_validate()`), the service randomly selects one of these attacker-registered mirror URLs and issues outbound HTTP requests to it in order to download delta files: [5](#0-4) 

The actual network call is a plain `aiohttp` GET built by directly concatenating the attacker-controlled `server_info.url`: [6](#0-5) 

No part of this chain (`add_mirror`, `update_subscriptions_from_wallet`, `get_available_servers_for_store`, `http_download`) checks the URL's scheme (e.g. rejecting `file://`), resolves and blocks private/loopback/link-local/cloud-metadata IP ranges, or restricts redirects. This mirrors the CVE-2026-31910 bug class: a caller-supplied, syntactically unrestricted "location" string is handed to a factory/fetch path that performs an outbound request or file access without validating that the destination is safe, resulting in SSRF and, via crafted delta-file responses being written to `target_filename_path` under `client_foldername`, forced local file writes from attacker-influenced content.

### Impact Explanation
An unprivileged wallet user (anyone able to create a DataLayer store and pay the mirror-coin fee) can force every other participant's DataLayer node that subscribes to that store to make outbound HTTP GET requests to attacker-chosen hosts, including internal-network addresses, localhost services, or cloud metadata endpoints (`169.254.169.254`), when their DataLayer service periodically calls `fetch_and_validate()`. This is a classic blind SSRF: the attacker does not see the response directly, but can use response-timing/error side effects (server_misses_file vs. received_correct_file, subscription backoff behavior) as an oracle, or use it to probe/attack internal services reachable only from the victim's host. Because DataLayer subscriptions are meant to work with third-party, untrusted mirrors by design, this significantly widens the practical blast radius across the Chia network's DataLayer-enabled nodes.

### Likelihood Explanation
Likelihood is high: creating a store and calling `add_mirror()` with an arbitrary URL requires only a wallet transaction fee and no special permission, and any peer that discovers/subscribes to that store (which is the intended DataLayer usage pattern — subscribing to third-party stores for their data) will automatically and periodically perform outbound requests to the registered URL as part of `periodically_manage_data()`'s normal control loop.

### Recommendation
Validate mirror/server URLs before they are stored and before they are used for outbound requests: enforce an `http(s)://` scheme allowlist, resolve the hostname and reject requests to loopback, link-local, private, and metadata address ranges (unless explicitly configured for local/test use), and consider re-validating on every use since DNS can change between validation and request time (DNS rebinding). This should be enforced centrally in `DataLayer.add_mirror()`/`update_subscriptions_from_wallet()` and defensively again in `download_data.http_download()`.

### Proof of Concept
1. Attacker creates a DataLayer store via wallet RPC `create_new_dl`.
2. Attacker calls `add_mirror(store_id, urls=["http://169.254.169.254/latest/meta-data/"], amount, fee)` — this succeeds with no validation (`chia/data_layer/data_layer.py:965-970`).
3. Victim's DataLayer node subscribes to attacker's `store_id` (a normal, intended DataLayer workflow) and periodically runs `update_subscription()` → `update_subscriptions_from_wallet()`, which copies the URL verbatim into the local subscriptions table (`chia/data_layer/data_store.py:1668-1704`).
4. On the next sync cycle, `fetch_and_validate()` selects the attacker's URL from `servers_info` and calls `insert_from_delta_file()` → `download_file()` → `http_download()`, causing the victim's process to issue an outbound GET to the attacker-chosen internal/metadata address (`chia/data_layer/download_data.py:298-319`).

    async def update_subscriptions_from_wallet(self, store_id: bytes32, new_urls: list[str]) -> None:
        async with self.db_wrapper.writer() as writer:
            cursor = await writer.execute(
                "SELECT * FROM subscriptions WHERE from_wallet == 1 AND tree_id == :tree_id",
                {
                    "tree_id": store_id,
                },
            )
            old_urls = [row["url"] async for row in cursor]
            cursor = await writer.execute(
                "SELECT * FROM subscriptions WHERE from_wallet == 0 AND tree_id == :tree_id",
                {
                    "tree_id": store_id,
                },
            )
            from_subscriptions_urls = {row["url"] async for row in cursor}
            additions = {url for url in new_urls if url not in old_urls}
            removals = [url for url in old_urls if url not in new_urls]
            for url in removals:
                await writer.execute(
                    "DELETE FROM subscriptions WHERE url == :url AND tree_id == :tree_id",
                    {
                        "url": url,
                        "tree_id": store_id,
                    },
                )
            for url in additions:
                if url not in from_subscriptions_urls:
                    await writer.execute(
                        "INSERT INTO subscriptions(tree_id, url, ignore_till, num_consecutive_failures, from_wallet) "
                        "VALUES (:tree_id, :url, 0, 0, 1)",
                        {
                            "tree_id": store_id,
                            "url": url,
                        },
                    )

async def http_download(
    target_filename_path: Path,
    filename: str,
    proxy_url: str | None,
    server_info: ServerInfo,
    timeout: aiohttp.ClientTimeout,
    log: logging.Logger,
    max_delta_file_size: int,
) -> None:
    """
    Download a file from a server using aiohttp.
    Raises exceptions on errors
    """
    async with aiohttp.ClientSession() as session:
        headers = {"accept-encoding": "gzip"}
        async with session.get(
            server_info.url + "/" + filename,
            headers=headers,
            timeout=timeout,
            proxy=proxy_url,
        ) as resp:
            resp.raise_for_status()
