### Title
Quadratic-time transaction pop path in block building lets a single sender flood the proposer with cheaply-invalidated bundle/plain transactions - (File: work/builder/builder.go)

### Summary
The commonmark advisory describes an O(N²) blow-up caused by re-walking the full remaining sibling list every time a single element's "target" needs to be resolved. Kaia's block-building bundle machinery has the same shape: every time a transaction (bundle or plain) is rejected mid-block, `PopTxs` rebuilds a dependency index over the *entire remaining* transaction/bundle list, and this happens inside a per-transaction loop that runs once per remaining transaction in the block.

### Finding Description
`work/builder/builder.go`'s `PopTxs` calls `buildDependencyIndices(*txOrGens, *bundles, signer)` on every invocation: [1](#0-0) 

`buildDependencyIndices` is O(len(txs) + len(bundles)) — it iterates the *entire* remaining transaction list and bundle list each time it is called: [2](#0-1) 

`PopTxs` is invoked from `work/worker.go`'s `CommitTransactionLoop`, which processes the block's transaction list one element at a time (`incorporatedTxs[0]`) and calls `PopTxs` whenever the head transaction/bundle fails for several distinct reasons — `shouldDiscardBundle` returning true, a nil generated tx, missing blob space, `ErrNonceTooHigh`, `ErrTxTypeNotSupported`, `kerrors.ErrRevertedBundleByVmErr`, and `kerrors.ErrTxGeneration`: [3](#0-2) [4](#0-3) 

Because each `PopTxs` call costs O(N) (N = remaining transactions in the block being built) and the loop can call it once per remaining transaction, the aggregate worst-case cost is O(N²) — the same structural bug class as the commonmark "outward-walk" quadratic resolver, just realized through repeated full-list rebuilds rather than repeated sibling walks. `kerrors.ErrRevertedBundleByVmErr` is specifically the error path for a bundle transaction that reverts during EVM execution: [5](#0-4) 

The gasless module (a first-party, unprivileged-reachable bundling module) constructs one bundle per sender pair of approve/swap transactions, with essentially no cap on the number of distinct senders that can each contribute one gasless bundle to a block (`MaxBundleTxsInPending`/`MaxBundleTxsInQueue` gate bundle-tx counts, but default node config still permits ~100 bundle txs, and this bound does not limit the size of the *overall* transaction list `len(txs)` that `buildDependencyIndices` rescans each time): [6](#0-5) [7](#0-6) 

An attacker who submits many gasless approve/swap pairs from many distinct funded accounts, each swap crafted to revert on execution (e.g., a deadline/slippage condition that fails only during actual EVM execution rather than admission-time static checks), causes `commitBundleTransaction` to return `kerrors.ErrRevertedBundleByVmErr` for nearly every bundle processed. Each such failure triggers `PopTxs`, and each `PopTxs` call rescans the full remaining `incorporatedTxs`/`bundles` state via `buildDependencyIndices`, giving quadratic total cost in the number of transactions competing for the block.

### Impact Explanation
This directly slows down the block proposer's `ApplyTransactions` / `CommitTransactionLoop`, which runs under `params.BlockGenerationTimeLimit`. A resource-exhaustion / algorithmic-complexity DoS here would degrade or stall block production capacity for the affected proposer, consistent with CWE-407 (uncontrolled resource consumption via algorithmic complexity), analogous to the commonmark advisory's Availability-only impact.

### Likelihood Explanation
Reaching this path requires only submitting ordinary, admission-valid transactions (gasless approve/swap pairs from many accounts) that are crafted to revert during EVM execution rather than at tx-pool admission — no special privilege, peer, or validator role is needed. The severity is bounded by mempool-level limits (`ExecSlotsAll`/`NonExecSlotsAll`, `MaxBundleTxsInPending`/`MaxBundleTxsInQueue`), which constrain N to node-configured pool sizes rather than being fully unbounded like the commonmark input (~32 KB → 8,000 nodes). This materially reduces the achievable blow-up compared to the original advisory, and I was not able to fully verify, within the remaining budget, whether `ErrTxTypeNotSupported`/`ErrNonceTooHigh` paths (which are not gated by any bundle-specific cap) are practically triggerable by an attacker at scale against `incorporatedTxs` of pool-limit size, or what the realistic default `ExecSlotsAll`/`NonExecSlotsAll` values are that would bound N in practice.

### Recommendation
Avoid recomputing `buildDependencyIndices` from scratch inside `PopTxs` for every failure. Maintain the sender→indices and bundle→indices maps incrementally (update on removal) instead of rebuilding them O(N) per pop, or cap the number of `PopTxs` calls / total popped-transaction work per `ApplyTransactions` invocation to a value independent of adversarially-crafted revert patterns.

### Proof of Concept
Not independently constructed/executed; the above is derived from static code-path analysis of `work/builder/builder.go` and `work/worker.go`. A concrete PoC would require crafting on the order of hundreds of distinct-sender gasless approve/swap transaction pairs, each swap tx passing tx-pool admission but reverting during EVM execution, and measuring `ApplyTransactions` wall time growth as a function of the number of such bundles, to confirm quadratic scaling in practice.

func buildDependencyIndices(txs []*TxOrGen, bundles []*Bundle, signer types.Signer) (map[common.Address][]int, map[int][]int, error) {
	senderToIndices := make(map[common.Address][]int)
	bundleToIndices := make(map[int][]int)

	txHashToBundleIndices := make(map[common.Hash][]int)
	for i, bundle := range bundles {
		for _, tx := range bundle.BundleTxs {
			txHashToBundleIndices[tx.Id] = append(txHashToBundleIndices[tx.Id], i)
		}
		if bundle.TargetRequired && bundle.TargetTxHash != (common.Hash{}) {
			txHashToBundleIndices[bundle.TargetTxHash] = append(txHashToBundleIndices[bundle.TargetTxHash], i)
		}
	}

	for i, txOrGen := range txs {
		if txOrGen.IsConcreteTx() {
			tx, _ := txOrGen.GetTx(0)
			from, err := types.Sender(signer, tx)
			if err != nil {
				return nil, nil, err
			}
			senderToIndices[from] = append(senderToIndices[from], i)
		}

		for _, bundleIdx := range txHashToBundleIndices[txOrGen.Id] {
			bundleToIndices[bundleIdx] = append(bundleToIndices[bundleIdx], i)
		}
	}

	return senderToIndices, bundleToIndices, nil
}

func PopTxs(txOrGens *[]*TxOrGen, num int, bundles *[]*Bundle, signer types.Signer) {
	if len(*txOrGens) == 0 || num == 0 {
		return
	}

	senderToIndices, bundleToIndices, err := buildDependencyIndices(*txOrGens, *bundles, signer)
	if err != nil {
		logger.Error("Failed to build dependency indices", "err", err)
		ShiftTxs(txOrGens, num)
		return
	}

func (g *GaslessModule) ExtractTxBundles(txs []*types.Transaction, prevBundles []*builder.Bundle) []*builder.Bundle {
	// there are only at most two gasless transactions in pending for a sender
	bundles := []*builder.Bundle{}
	approveTxs := map[common.Address]*types.Transaction{}
	targetTxHash := common.Hash{}
	for _, tx := range txs {
		addr, err := types.Sender(g.signer, tx)
		if err != nil {
			continue
		}
		if g.IsApproveTx(tx) {
			approveTxs[addr] = tx
		} else if g.IsSwapTx(tx) && g.IsExecutable(approveTxs[addr], tx) {
			bundleTxs := builder.NewTxOrGenList(g.GetLendTxGenerator(approveTxs[addr], tx))
			if approveTxs[addr] != nil {
				bundleTxs = append(bundleTxs, builder.NewTxOrGenFromTx(approveTxs[addr]))
			}
			bundleTxs = append(bundleTxs, builder.NewTxOrGenFromTx(tx))

			b := builder.NewBundle(
				bundleTxs,
				targetTxHash,
				false,
			)

			targetTxHash = tx.Hash()

			isConflict := false
			for _, prev := range append(prevBundles, bundles...) {
				if prev.IsConflict(b) {
					isConflict = true
					break
				}
			}
			if isConflict {
				// Gasless transactions will just fail even if they aren't bundled.
				continue
			}
			bundles = append(bundles, b)
		} else {
			targetTxHash = tx.Hash()
		}
	}
	return bundles
}
