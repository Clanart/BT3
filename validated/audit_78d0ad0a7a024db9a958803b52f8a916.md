### Title
Identity Elliptic-Curve Point Accepted as DKG Encryption Key Enables Public Decryption of Secret Shares - ([File: crypto/dkg/pedpop/src/encryption.rs])

### Summary
The Apache Axis advisory (CWE-20: improper input validation) concerns a privileged-but-unvalidated input being fed into a sensitive operation. The Serai analog is the PedPoP DKG encryption layer: `EncryptionKeyMessage::read` accepts the recipient's ECDH public key (`enc_key`) via `C::read_G`, which enforces canonical encoding but does **not** reject the identity point. An unprivileged DKG participant can broadcast `enc_key = identity`, causing every honest participant's `encrypt` to compute the ECDH shared secret as `key * identity = identity` — a publicly known constant — so all secret shares "encrypted" to the malicious participant are decryptable by anyone who observes the ciphertexts. The codebase itself demonstrates the intended check: `Curve::read_G` in FROST rejects identity points [1](#0-0) , but the generic `Ciphersuite::read_G` used here does not [2](#0-1) .

### Finding Description
`EncryptionKeyMessage::read` parses the peer-supplied encryption key with `C::read_G(reader)?` and no identity or other validity check [3](#0-2) . The registered key is later used verbatim as the ECDH counterparty key in `encrypt(rng, context, from, to, msg)` [4](#0-3) , where the shared secret is `ecdh = public * private` [5](#0-4) . With `to = identity`, `ecdh` is the identity element for every per-message key, so `cipher()` derives a ChaCha20 key from a constant transcript input [6](#0-5) . The same missing check exists on the per-message `key` field in `EncryptedMessage::read` [7](#0-6) : a malicious *sender* can set `key = identity`, making `ecdh = enc_priv * identity = identity` on the recipient's decrypt path [8](#0-7) , again yielding a publicly computable stream key while the Schnorr PoP still verifies (the proof binds `msg.key`, and an identity public key has a valid signature for private key 0).

### Impact Explanation
The DKG's confidentiality for shares destined to (or sent by) the malicious participant collapses to a public broadcast: any party that obtains the `EncryptedMessage` ciphertexts — e.g., via the coordinator relaying share blobs in `processor/src/key_gen.rs` — can decrypt `SecretShare` plaintexts. Shares encrypted under an identity ECDH secret are a valid "key share recovery" primitive: an attacker running a 1-of-n DKG slot obtains t-1 additional shares for free if they can observe ciphertexts, undermining the threshold assumption. Additionally, because decryption "succeeds" (deterministically), blame attribution is confused rather than cleanly aborting.

### Likelihood Explanation
The attack requires only that the attacker control one DKG participant slot and observe ciphertext traffic (e.g., a malicious or compromised coordinator, or any party receiving forwarded/blame data). It requires no collusion, no broken BFT assumptions, and no leaked keys — it is reachable purely through bytes the attacker supplies to `EncryptionKeyMessage::read` / `EncryptedMessage::read`.

### Recommendation
Reject the identity point (and ideally validate subgroup membership where applicable, as `frost::Curve::read_G` does) in `EncryptionKeyMessage::read` for `enc_key` and in `EncryptedMessage::read` for `key`. Alternatively, check `ecdh.is_identity()` in `encrypt`/`decrypt`/`decrypt_with_proof` and abort as a fault of the key's owner.

### Proof of Concept
1. Malicious participant `m` calls `Encryption::new` then overwrites the published `enc_key` with `C::G::identity()` (private key known to be 0), serializing it in its `EncryptionKeyMessage`.
2. Every honest participant `h` calls `self.encryption.encrypt(rng, m, share)`, computing `ecdh = k * identity = identity`; `cipher()` derives `key = H(context || identity.to_bytes())` — computable by anyone.
3. Anyone observing the resulting `EncryptedMessage` ciphertext applies the same public ChaCha20 keystream and recovers `SecretShare` plaintexts for `m`'s slot without knowing any private key.

fn cipher<C: Ciphersuite>(context: [u8; 32], ecdh: &Zeroizing<C::G>) -> ChaCha20 {
  // Ideally, we'd box this transcript with ZAlloc, yet that's only possible on nightly
  // TODO: https://github.com/serai-dex/serai/issues/151
  let mut transcript = RecommendedTranscript::new(b"DKG Encryption v0.2");
  transcript.append_message(b"context", context);

  transcript.domain_separate(b"encryption_key");

  let mut ecdh = ecdh.to_bytes();
  transcript.append_message(b"shared_key", ecdh.as_ref());
  ecdh.as_mut().zeroize();

  let zeroize = |buf: &mut [u8]| buf.zeroize();

  let mut key = Cc20Key::default();
  let mut challenge = transcript.challenge(b"key");
  key.copy_from_slice(&challenge[.. 32]);
  zeroize(challenge.as_mut());

  // Since the key is single-use, it doesn't matter what we use for the IV
  // The issue is key + IV reuse. If we never reuse the key, we can't have the opportunity to
  // reuse a nonce
  // Use a static IV in acknowledgement of this
  let mut iv = Cc20Iv::default();
  // The \0 is to satisfy the length requirement (12), not to be null terminated
  iv.copy_from_slice(b"DKG IV v0.2\0");

  // ChaCha20 has the same commentary as the transcript regarding ZAlloc
  // TODO: https://github.com/serai-dex/serai/issues/151
  let res = ChaCha20::new(&key, &iv);
  zeroize(key.as_mut());
  res
}
