### Title
SchnorrAggregate::verify returns true for an empty signer set / empty signature, treating "nothing verified" as valid - (File: crypto/schnorr/src/aggregate.rs)

### Summary
The analog of "low-level `call` returns true even if the target contract does not exist" is `SchnorrAggregate::verify`: when presented with an aggregate signature containing zero nonces and an empty `keys_and_challenges` list, the verification formula degenerates to `multiexp` over a single `(-0) * G` term (or nothing), which is the identity, so `verify` returns `true` even though no signature was ever checked. The producing API (`SchnorrAggregator::complete`) explicitly rejects the empty case, proving the authors know an empty aggregate is meaningless, yet `verify` — the only check a verifier performs — has no such guard.

### Finding Description
`SchnorrAggregate::read` accepts a serialized aggregate whose `Rs` length prefix is `0` and `s` is zero (`36` bytes total: `00 00 00 00` + `0x00 * 32`) [1](#0-0) .

In `verify`, the only structural check is `self.Rs.len() != keys_and_challenges.len()`. With `Rs.len() == 0` and `keys_and_challenges == &[]`, this passes. The loop appends no `(z, R)` / `(z*c, key)` pairs, and the final push is `(-self.s, C::generator()) = (0, G)` [2](#0-1) . `multiexp_vartime` maps this to `Algorithm::Single`/`Null`, returning the group identity, so `is_identity()` is `true` [3](#0-2) .

By contrast, the aggregation side refuses this exact state: `SchnorrAggregator::complete` returns `None` when `self.sigs.is_empty()` [4](#0-3) . The asymmetry is the bug: the honest path can never produce an empty aggregate, but the verification path accepts one as valid.

### Impact Explanation
Any caller that treats `SchnorrAggregate::verify(dst, &[])`/`verify_aggregate(..., &[], msg, sig)` returning `true` as "a valid aggregate signature exists" accepts a forgery. The function's contract — "perform signature verification" — is violated: an attacker supplies 36 attacker-chosen bytes and the verifier reports success for a signature over a signer set containing no keys at all. This is precisely the reported bug class: the operation is marked successful (transaction "executed") even though the target object being verified doesn't exist. Downstream consumers that fail to independently enforce a nonzero signer weight/count (analogous to the missing destination validity check) will mark a batch/commit/authorization as cryptographically verified when nothing was.

### Likelihood Explanation
Reachable by any unprivileged party feeding bytes to `SchnorrAggregate::read` plus a `verify`/`verify_aggregate` call where the signer list is drawn from the same attacker-influenced message (e.g., a commit claiming zero signers). No secret material, collusion, or privileged position is needed — the forged "signature" is a fixed 36-byte constant. Exploitability is bounded by whether callers separately enforce signer thresholds; where they do, severity is limited, hence Medium rather than High.

### Recommendation
Mirror the producer-side guard in `verify`: return `false` early when `self.Rs.is_empty()` (equivalently `keys_and_challenges.is_empty()`), so the verifier enforces the same non-emptiness invariant as `SchnorrAggregator::complete`. Additionally, consider rejecting `R` values that are the identity during `read`, matching the defensive identity check already used for signature nonces elsewhere.

### Proof of Concept
```
// crypto/schnorr: forged empty aggregate signature
// bytes: [u32 len = 0][s = 0]
let mut sig_bytes = vec![0u8; 4];
sig_bytes.extend_from_slice(&[0u8; 32]);
let agg = SchnorrAggregate::<Ed25519>::read(&mut sig_bytes.as_slice()).unwrap();
// keys_and_challenges is empty: nothing is actually verified
assert!(agg.verify(b"Some DST", &[])); // returns true — forged "signature" accepted
```
The verifier-side fix (`if self.Rs.is_empty() { return false }`) makes this assertion fail, consistent with `SchnorrAggregator::complete` returning `None` for the same empty state.

pub fn multiexp_vartime<G: Group<Scalar: PrimeFieldBits>>(pairs: &[(G::Scalar, G)]) -> G {
  match algorithm(pairs.len()) {
    Algorithm::Null => Group::identity(),
    Algorithm::Single => pairs[0].1 * pairs[0].0,
    Algorithm::Straus(window) => straus_vartime(pairs, window),
    Algorithm::Pippenger(window) => pippenger_vartime(pairs, window),
  }
}
