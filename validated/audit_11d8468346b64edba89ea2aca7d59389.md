### Title
Permissionless gasless bundle-tx queue can be DoS'd by a single unprivileged sender, blocking legitimate gasless users - (File: kaiax/gasless/impl/tx_pool.go)

### Summary
The Kaia `gasless` kaiax module admits arbitrary, unauthenticated approve/swap transaction pairs into a shared, globally-capped `knownTxs` queue (`MaxBundleTxsInQueue`, default 200) with no per-sender quota or staking/whitelist requirement. Any transaction sender can permissionlessly fill this fixed-capacity slot pool with cheap, self-controlled ERC-20 tokens, permanently starving legitimate gasless users' `PreAddTx` calls — structurally the same "fixed-capacity, permissionless registration" DoS pattern as the referenced `Voter.sol`/`BribeRewarder` `MAX_BRIBES_PER_POOL` bug.

### Finding Description
`GaslessModule.PreAddTx` is the entry point that decides whether an approve/swap bundle transaction is admitted into the node's tracked "known bundle tx" queue: [1](#0-0) 

The check `uint(g.knownTxs.numQueue()) >= g.GetMaxBundleTxsInQueue()` is a single global counter shared by all senders on the node — there is no per-address, per-token, or whitelist-based restriction on who may occupy a queue slot: [2](#0-1) [3](#0-2) 

`IsModuleTx`/`IsBundleTx` only require that the transaction *look like* a valid approve/swap pair against the `GaslessSwapRouter` for some ERC-20 token — the token itself is unrestricted (all tokens allowed by default, `AllowedTokens: nil`), and the balance/allowance checks (`checkBalanceForApprove`, `checkBalanceForSwap`) are trivially satisfiable by an attacker who deploys their own worthless ERC-20, mints an arbitrary supply to themselves, and approves/self-trades against the router: [4](#0-3) [5](#0-4) 

An attacker can generate many distinct sender addresses (each is free, unprivileged), each with one approve+swap "bundle" transaction referencing worthless self-minted tokens, and submit them to the queue up to `MaxBundleTxsInQueue` (200 by default). Once full, `PreAddTx` will reject every subsequent legitimate gasless bundle transaction with `ErrBundleTxQueueFull`, exactly mirroring how a malicious actor filled the 5-slot `_bribesPerPriod[periods[i]][pool]` array in `Voter.sol` with worthless `BribeRewarder` instances to block genuine bribes.

### Impact Explanation
Gasless transactions are a core "gas abstraction" feature meant to let users without KAIA balances swap tokens and pay gas out of swap proceeds. A full queue means legitimate users' approve/swap bundles are rejected at the tx-pool admission stage (`PreAddTx`), denying them the gasless UX and effectively disabling the feature network-wide until the attacker's entries age out (`QueueTimeout` = 10s) or are otherwise evicted — but the attacker can trivially and continuously resubmit new bundle txs from fresh addresses to keep the queue saturated at negligible cost (only requires minting a worthless token and self-funding negligible KAIA for tx submission, no third-party value at risk). This denies availability of the gasless/auction-adjacent MEV path to genuine users, which is a scoped-in reachable path (gasless module).

### Likelihood Explanation
Likelihood is high: the queue admission check has no whitelist, no per-sender/per-token limit, and no cost beyond deploying a worthless ERC-20 and paying minimal gas for approve/swap-shaped transactions from disposable accounts, mirroring the original report's trivial replication with a single custom token contract and multiple contract instances.

### Recommendation
Add a per-sender (or per-token) cap on `knownTxs` queue occupancy in addition to (or instead of) the single global cap in `PreAddTx` (`kaiax/gasless/impl/tx_pool.go`), and/or require gasless bundle transactions to reference tokens from an operator-curated allow-list (`AllowedTokens`) rather than defaulting to "all tokens allowed", so that an attacker cannot use self-minted worthless tokens to occupy the shared queue capacity.

### Proof of Concept
Conceptual PoC (mirrors the report's steps against `Voter.sol`):
1. Deploy a worthless ERC-20 token; mint supply to an attacker-controlled address.
2. From N distinct throwaway EOAs (N approaching `MaxBundleTxsInQueue`, default 200, see `kaiax/gasless/config.go:51`), each construct a valid `[approveTx, swapTx]` pair against the deployed `GaslessSwapRouter` using the worthless token, satisfying `IsApproveTx`/`IsSwapTx` shape checks in `kaiax/gasless/impl/tx_pool.go`.
3. Submit all N bundle tx pairs to the node's tx pool; each passes `PreAddTx` and occupies a `knownTxs` queue slot (`kaiax/gasless/impl/tx_pool.go:46-51`) until `g.knownTxs.numQueue() >= MaxBundleTxsInQueue`.
4. A legitimate user submits a genuine approve/swap gasless bundle; `PreAddTx` returns `ErrBundleTxQueueFull`, and the transaction is rejected, denying the gasless feature to the honest user.

Note: I could not find any per-sender or per-token quota enforcement in the reviewed files (`kaiax/gasless/impl/tx_pool.go`, `kaiax/gasless/config.go`, `kaiax/gasless/impl/tx_counter.go`); if such logic exists elsewhere in the module (e.g., in txpool-level per-account limits not part of the `gasless` kaiax module itself), it was not surfaced by the available index and should be verified in a full checkout before treating this as conclusively unmitigated.

```go
func (g *GaslessModule) PreAddTx(tx *types.Transaction, local bool) error {
	g.knownTxsMu.RLock()
	defer g.knownTxsMu.RUnlock()

	if knownTx, ok := g.knownTxs.get(tx.Hash()); ok && knownTx.elapsedPromotedOrAddedTime() < KnownTxTimeout {
		return ErrUnableToAddKnownBundleTx
	}

	if g.IsBundleTx(tx) {
		if uint(g.knownTxs.numQueue()) >= g.GetMaxBundleTxsInQueue() {
			return ErrBundleTxQueueFull
		}
		g.knownTxs.add(tx, TxStatusQueue)
	}
	return nil
}
```

```go
func (g *GaslessModule) checkBalanceForApprove(approveArgs *ApproveArgs) error {
	token := approveArgs.Token
	bc := backends.NewBlockchainContractBackend(g.Chain, nil, nil)

	if g.GaslessConfig.ShouldCheckSenderCode() {
		if g.getCurrentHasCode(approveArgs.Sender) {
			return errors.New("sender with code is not allowed")
		}
	}

	if g.GaslessConfig.ShouldCheckToken() {
		tokenContract, err := sc_erc20.NewERC20(token, bc)
		if err != nil {
			return err
		}

		// tx.token.balanceOf(sender) > 0
		tokenBalance, err := tokenContract.BalanceOf(nil, approveArgs.Sender)
		if err != nil {
			return err
		}
		if tokenBalance.Sign() <= 0 {
			return fmt.Errorf("insufficient sender token balance: token=%s, have=%s, want=nonzero", token.Hex(), tokenBalance.String())
		}
	}
	return nil
```
