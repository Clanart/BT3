## Title
Attacker-controlled `Co-Authored-By` trailers are silently re-materialized into a new commit during Squash - (File: `app/src/ui/history/compare.tsx`)

## Summary
The exploited invariant in the MONA LisaVault report is that an attacker-controlled "referral" record was mechanically trusted and credited into a value-bearing state without independent verification. The closest reachable Desktop analog is the **Squash** workflow: co-author identities extracted from *any* commit being squashed — including commits that originated from another contributor, a fetched PR branch, or a fork — are automatically re-materialized as `Co-Authored-By` trailers on the brand-new squashed commit, with the "Co-authored by" UI pre-populated and pre-checked, before the user has typed or vetted them.

## Finding Description
When a user selects commits to squash, `onSquash` in `app/src/ui/history/compare.tsx` collects co-authors from **every** commit in the squash range (the target plus all commits being folded into it) via `getUniqueCoauthorsAsAuthors(allCommitsInSquash)`, then opens the commit-message popup with `showCoAuthoredBy: coAuthors.length > 0` and the field already populated: [1](#0-0) 

`getUniqueCoauthorsAsAuthors` simply de-duplicates and forwards whatever `Commit.coAuthors` were parsed out of each commit's raw trailers — there is no check that the current repository user actually authored, reviewed, or consented to that specific `name <email>` pair: [2](#0-1) 

`Commit.coAuthors` is populated purely by parsing `Co-Authored-By` trailers out of the commit's own message body — a value fully controlled by whoever authored that commit (which may not be the current Desktop user at all, e.g. a commit that was cherry-picked, fetched from a collaborator's branch, or merged from a fork): [3](#0-2) 

Separately, `getSquashedCommitDescription` explicitly strips the raw trailer text (`bodyNoCoAuthors`) out of the description text so it isn't duplicated as literal text in the body, confirming the trailers are *intentionally* meant to be regenerated structurally rather than carried as free text: [4](#0-3) 

The changelog confirms that the co-author list in the commit dialog is turned back into real `Co-Authored-By` trailers on commit ("Selecting a coauthor and committing adds coauthor trailer"), meaning whatever is pre-populated in `coAuthors` for the squash dialog will, by default, be written into the final commit unless the user manually notices and removes it: [5](#0-4) 

There is no guard anywhere in this path that validates the extracted `name`/`email` pair against the account performing the squash, against GitHub identity verification, or against any allow-list — the value is taken verbatim from attacker-influenced commit content and echoed into new, permanent commit metadata.

## Impact Explanation
This breaks the invariant that commit authorship/co-authorship metadata reflects the intent of the person performing the commit. An attacker who can get even one commit into the range being squashed (e.g., as a legitimate contributor on a shared feature branch, or via a commit fetched/cherry-picked from a fork or PR) can embed an arbitrary `Co-Authored-By: <any name> <any email>` trailer. When the victim later squashes that commit together with their own work — a normal, Desktop-promoted workflow — that attacker-chosen identity is silently carried into the new commit and, upon push, becomes permanent, publicly visible history attributed to/associated with the victim's push. This mirrors the "self-referral" pattern in the MONA LisaVault exploit: an untrusted, attacker-supplied identity record is mechanically trusted and materialized into a durable, value-bearing artifact (in this case, permanent commit provenance/attribution rather than token balances) without an independent trust check. It is a corruption-of-what-the-user-commits issue: the pushed commit's authorship metadata does not reflect what the user actually intended or reviewed.

## Likelihood Explanation
Medium. No local access, no malware, no elevated privileges are required — the only precondition is that the victim squashes a commit range that includes an attacker-authored commit, which happens routinely in collaborative branches, PR review-and-squash flows, and cherry-pick workflows. The dialog is pre-filled and pre-checked (`showCoAuthoredBy: true`), so a victim clicking through the squash dialog without carefully auditing the co-author list will commit the forged trailer without any explicit additional action.

## Recommendation
Do not silently pre-populate/pre-check the co-authors field with identities extracted from commits the current user did not author. At minimum, cross-reference extracted `Co-Authored-By` emails/names against the commit's own author/committer identity or a known-accounts list before offering to carry them forward, and require an explicit, per-identity opt-in (not a pre-checked bulk import) when squashing commits authored by someone other than the current Desktop user.

## Proof of Concept
1. Attacker contributes a commit to a shared branch (or the branch is fetched from attacker's fork) containing a commit message with a forged trailer, e.g.:
   ```
   Some innocuous change

   Co-Authored-By: Victim Name <victim@example.com>
   ```
2. Victim, working in GitHub Desktop, selects that commit plus one or more of their own commits and invokes **Squash** (`onSquash` in `app/src/ui/history/compare.tsx`).
3. `getUniqueCoauthorsAsAuthors` extracts `Victim Name <victim@example.com>` from the attacker's commit trailers and the Commit Message dialog opens with "Co-authored by" pre-populated and enabled.
4. Victim reviews only the summary/description, clicks "Squash N Commits", and pushes.
5. The resulting squashed commit now permanently carries `Co-Authored-By: Victim Name <victim@example.com>` in the public history, attributed via the victim's push, without the victim having typed that trailer themselves.

import uniqWith from 'lodash/uniqWith'
import { KnownAuthor } from '../models/author'
import { Commit } from '../models/commit'

export function getUniqueCoauthorsAsAuthors(
  commits: ReadonlyArray<Commit>
): ReadonlyArray<KnownAuthor> {
  const allCommitsCoAuthors = commits.flatMap(c => c.coAuthors)

  const uniqueCoAuthors = uniqWith(
    allCommitsCoAuthors,
    (a, b) => a.email === b.email && a.name === b.name
  )

  return uniqueCoAuthors.map(ca => {
    return { kind: 'known', name: ca.name, email: ca.email, username: null }
  })
}

/**
 * Extract any Co-Authored-By trailers from an array of arbitrary
 * trailers.

function extractCoAuthors(trailers: ReadonlyArray<ITrailer>) {
  const coAuthors = []

  for (const trailer of trailers) {
    if (isCoAuthoredByTrailer(trailer)) {
      const author = GitAuthor.parse(trailer.value)
      if (author) {
        coAuthors.push(author)
      }
    }
  }

  return coAuthors
}

import { Commit } from '../../models/commit'

export function getSquashedCommitDescription(
  commits: ReadonlyArray<Commit>,
  squashOnto: Commit
): string {
  const commitMessages = commits.map(
    c => `${c.summary.trim()}\n\n${c.bodyNoCoAuthors.trim()}`
  )

  const descriptions = [
    squashOnto.bodyNoCoAuthors.trim(),
    ...commitMessages,
  ].filter(d => d.trim() !== '')

  return descriptions.join('\n\n')
}
