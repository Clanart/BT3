### Title
Division-by-zero panic in `consolidatedNode.Split` crashes block finalization when a Prague proposer has zero CN and CL staking amounts - (File: `kaiax/staking/staking_info.go`)

### Summary
`FeeSplitter.addFees()` in the referenced Curves report reverts when `totalSupply()` evaluates to `0` because the denominator of a distribution formula becomes zero. The same bug class — an unguarded division whose denominator can legitimately reach `0` — exists in Kaia's reward-splitting logic for Prague/consensus-liquidity (KIP-226) rewards, in `consolidatedNode.Split()`.

### Finding Description
`consolidatedNode.Split(amount)` divides the CL portion of a reward by `totalAmount = StakingAmount + CLStakingInfo.CLStakingAmount`: [3](#0-2) 

This function is called unconditionally (i.e., without checking that `totalAmount > 0`) from `specWithProposerAndFunds` / `specWithProposerAndFundsFlex` when assigning the proposer's own reward, as long as the proposer's `consolidatedNode.CLStakingInfo` is non-nil: [4](#0-3) [5](#0-4) 

`StakingAmount` and `CLStakingInfo.CLStakingAmount` are both derived by floor-dividing raw wei amounts by `params.KAIA` (1 KAIA), so any staked amount under 1 KAIA rounds down to `0`: [6](#0-5) 

A `CLStakingInfo` entry is attached to a `consolidatedNode` whenever the node's `NodeId` appears in the CL registry, independent of stake size — there is no minimum-stake gate for CL registration in `consolidateNodes()`: [7](#0-6) 

Separately, validator eligibility to remain in the (non-demoted) council for `WeightedRandom` proposer selection is gated only on `CNStaking` amount vs `pset.MinimumStake`, and a governing node under single-governance mode is explicitly exempted from demotion regardless of its stake: [8](#0-7) 

Consequently, it is possible for the elected block proposer to have `StakingAmount == 0` (either genuinely zero CN stake, exempted via governing-node demotion bypass, or rounded down from a sub-1-KAIA amount) while also carrying a non-nil `CLStakingInfo` with `CLStakingAmount == 0` (rounded down similarly). In that case `totalAmount` in `Split()` is `0`, and `clAmount.Div(clAmount, totalAmount)` triggers a Go `math/big` division-by-zero **panic** (not a recoverable `error`).

### Impact Explanation
This code path executes inside `RewardModule.FinalizeState()`, which is called by every full node while processing a block's deferred rewards (state transition), not just by the proposer: [9](#0-8) 

A panic here during state transition would crash the node process for every node that processes the block (since the panic happens deterministically given the block/staking-info inputs), i.e., a consensus-wide chain halt/DoS rather than an isolated revert. This is more severe than the referenced Curves finding (which merely reverted an individual transaction) because it can take down the entire network from a single, deterministic staking configuration once the Prague/KIP-226 hardfork is active and consensus liquidity (CL) is in use.

### Likelihood Explanation
Requires: (1) Prague hardfork active with CL staking enabled, (2) the current block proposer's consolidated `StakingAmount` is 0 KAIA (attainable via sub-1-KAIA CNStaking rounding, or via the single-governance-mode demotion exemption for the governing node), and (3) that same proposer has a registered `CLStakingInfo` whose `CLStakingAmount` also rounds to 0 KAIA. None of these conditions require malicious behavior — they can arise from ordinary small-stake configurations or operator error, making this reachable without any adversarial coordination, only careful/adversarial staking amount selection by a legitimate staking-contract operator or CL depositor.

### Recommendation
Guard `consolidatedNode.Split()` against a zero `totalAmount` by returning `(amount, big.NewInt(0))` (or an explicit error) when `totalAmount.Sign() == 0`, mirroring how `assignStakingRewards`/`assignStakingRewardsFlex` already guard their excess-stake divisions by only dividing when the computed `totalExcess` is provably nonzero.

### Proof of Concept
Not runnable without the full node harness, but the logical trigger is:
1. Enable Prague/KIP-226 (`IsPrague = true`) with CL staking configured.
2. Configure the block proposer's CN staking contract with an amount `< 1 KAIA` (rounds to `StakingAmount = 0` per `kaiax/staking/impl/getter.go:287`), and register the same node in the CL registry with a CL stake `< 1 KAIA` (rounds to `CLStakingAmount = 0`).
3. Have this node be selected as (or remain eligible as, e.g., via single-governance-mode governing-node exemption) the block proposer.
4. During `FinalizeState`, `specWithProposerAndFunds`/`specWithProposerAndFundsFlex` calls `cn.Split(proposer)` for this proposer's `consolidatedNode`, hitting `totalAmount == 0` in `Split()` and panicking on `big.Int.Div` by zero, crashing all nodes finalizing that block.

func (c consolidatedNode) Split(amount *big.Int) (*big.Int, *big.Int) {
	if c.CLStakingInfo == nil {
		return amount, big.NewInt(0)
	}

	var (
		cnAmountBig = big.NewInt(int64(c.StakingAmount))
		clAmountBig = big.NewInt(int64(c.CLStakingInfo.CLStakingAmount))
		totalAmount = new(big.Int).Add(cnAmountBig, clAmountBig)
	)

	clAmount := new(big.Int).Mul(clAmountBig, amount)
	clAmount = clAmount.Div(clAmount, totalAmount)

	// The remaining amount is for the CN.
	cnAmount := big.NewInt(0).Sub(amount, clAmount)

	return cnAmount, clAmount
}

func (r *RewardModule) FinalizeState(header *types.Header, state *state.StateDB, txs []*types.Transaction, receipts []*types.Receipt) error {
	if r.GovModule.GetParamSet(header.Number.Uint64()).ProposerPolicy == uint64(istanbul.WeightedRandom) && common.EmptyHash(header.Root) {
		qualified, err := r.ValsetModule.GetQualifiedValidators(header.Number.Uint64())
		if err != nil {
			return err
		}
		useRewardAddress := valset.NewAddressSet(qualified).Contains(r.NodeAddress)

		if rewardAddr := r.GetRewardAddress(header.Number.Uint64(), r.NodeAddress); useRewardAddress && rewardAddr != (common.Address{}) {
			header.Rewardbase = rewardAddr
			logger.Trace("Use reward address for nodeValidator", "header.Number", header.Number.Uint64(), "nodeAddress", r.NodeAddress, "rewardbase", header.Rewardbase)
		} else {
			logger.Trace("No reward address for nodeValidator. Use node's rewardbase.", "header.Number", header.Number.Uint64(), "nodeAddress", r.NodeAddress, "rewardbase", header.Rewardbase)
		}
	}

	spec, err := r.GetDeferredReward(header, txs, receipts)
	if err != nil {
		return err
	}
	if err := spec.Validate(); err != nil {
		return err
	}
	for addr, amount := range spec.Rewards {
		state.AddBalance(addr, amount)
	}
	return nil
}
