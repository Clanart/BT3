# Title
`isGitHubHost` permanently caches an attacker-suppliable header instead of re-validating trust, letting a spoofed remote be misclassified as GitHub Enterprise and receive real OAuth credentials - (File: `app/src/lib/api.ts`)

### Summary
The external report's core defect is that a validity/trust decision (`Asset.lotPrice`) is gated on a single time-based signal (`oracleTimeout`) that doesn't reflect all the ways the underlying data can actually be invalid. The Desktop analog is `isGitHubHost()` in `app/src/lib/api.ts`, which decides whether an arbitrary HTTPS host should be trusted as a genuine GitHub/GHE server. It should always verify authenticity by checking for the `x-github-request-id` header on a live `/meta` response, but it short-circuits that check whenever a version number is already cached for the endpoint — and that cache is written from a self-declarable response header, with no expiration and no re-verification, ever.

### Finding Description
`isGitHubHost` performs a hostname-pattern check first, then falls back to: [1](#0-0) 
```
if (getEndpointVersion(endpoint) !== null) {
  return true
}
```
Only if there is no cached version does it perform the real check — an HTTPS `HEAD /meta` request that inspects the `x-github-request-id` response header: [2](#0-1) 

The cache read/write (`getEndpointVersion` / `updateEndpointVersion`) is defined in `app/src/lib/endpoint-capabilities.ts` and is backed by `localStorage` with no TTL, no signature, and no distinction between a header seen on a request that also proved legitimacy vs. one that didn't: [3](#0-2) 

The cache is populated by `tryUpdateEndpointVersionFromResponse`, which unconditionally trusts the `x-github-enterprise-version` header on *any* response from the endpoint, including the very same `/meta` probe request performed inside `isGitHubHost`: [4](#0-3) [5](#0-4) 

Because an attacker fully controls their own server, they can simply return a fabricated `x-github-enterprise-version` header on that first `/meta` probe (they do not need to forge `x-github-request-id`, which is the actual authenticity signal). This poisons `versionCache`/`rawVersionCache`/`localStorage` for that endpoint permanently. Every subsequent call to `isGitHubHost()` for the same host then hits the `getEndpointVersion(endpoint) !== null` fast path and returns `true` without ever checking `x-github-request-id` again — i.e., the one check that actually distinguishes "real GitHub(-Enterprise)" from "arbitrary server" is bypassed forever, not just for a bounded staleness window (unlike the oracle report, there isn't even a timeout here — the poisoned state never expires).

This classification feeds directly into the git credential helper's trust decision: [6](#0-5) 
`getEndpointKind` calls `isGitHubHost(endpoint)` for any HTTPS host it doesn't already recognize, and if it returns `true`, classifies the host as `'enterprise'` rather than `'generic'`. In `getCredential`, an `'enterprise'`/non-generic classification with no existing account for that endpoint triggers `ui.promptForGitHubSignIn(endpoint)`: [7](#0-6) 

If the user completes that sign-in flow (a normal, expected action for what they believe is connecting to a real GitHub Enterprise server), Desktop creates/stores a real `Account` (with a real OAuth token) bound to the attacker's endpoint. On every future git operation against that endpoint, `getGitHubCredential` will supply `account.login`/`account.token` as HTTP Basic credentials via `credWithAccount`: [8](#0-7) 

### Impact Explanation
This is a credential/token exfiltration and unauthorized-OAuth-binding primitive: an attacker who merely operates a server that the victim's Desktop instance talks to over HTTPS (e.g., as a custom git remote, or any endpoint the credential helper probes) can permanently and silently flip that host's trust classification from `'generic'` to `'enterprise'` by spoofing one response header. This removes the legitimate `x-github-request-id` authenticity check for that host forever, and steers the user toward a GitHub sign-in flow scoped to the attacker's endpoint. Any resulting account token is then handed to the attacker's server as Basic Auth on every subsequent git request, matching the "credential/token exfiltration" and "unauthorized OAuth or account binding" impact categories.

### Likelihood Explanation
No local access, admin rights, or pre-existing malware is required — only that the user's Desktop client makes at least one HTTPS request to the attacker-controlled endpoint (e.g., adding it as a remote, or the credential helper's own `/meta` probe), and that the response includes an attacker-chosen `x-github-enterprise-version` header, which is trivial for anyone running their own server. The requirement for the victim to click through a sign-in dialog reduces likelihood somewhat, but the underlying broken invariant — a permanent, unauthenticated cache entry silently substituting for a live authenticity check — is a structural bug that exists independent of that step and taints the trust decision indefinitely (`localStorage` persists across restarts).

### Recommendation
- Do not let a cached version number alone satisfy the "is this a genuine GitHub host" check; require that the cached entry itself was derived from a request that also passed the `x-github-request-id` authenticity check (e.g. cache a boolean "verified GitHub host" alongside the version, only when both headers agree).
- Add expiration/re-verification to the endpoint-version cache instead of storing it in `localStorage` indefinitely with no TTL.
- Treat `x-github-enterprise-version` as untrusted metadata unless corroborated by `x-github-request-id` (or another header that GH(E) servers cannot omit and third parties are unlikely to spoof) on the same response before caching it as proof of host identity.

### Proof of Concept
1. Attacker stands up an HTTPS server at `evil.example.com` that responds to `HEAD /meta?...` with header `x-github-enterprise-version: 3.9.0` but does **not** send `x-github-request-id`.
2. Victim's Desktop, for any reason (e.g. adding `https://evil.example.com/...` as a remote, or the credential helper probing an unrecognized HTTPS host in `getEndpointKind`), calls `isGitHubHost('https://evil.example.com')`.
   - `isDotCom`/`isGHE`/hostname-pattern checks fail.
   - `getEndpointVersion(endpoint)` is `null` initially, so it performs the `/meta` HEAD probe.
   - The probe response's `x-github-enterprise-version` header is cached via `tryUpdateEndpointVersionFromResponse` → `updateEndpointVersion` → written into `localStorage` unconditionally.
   - Because `x-github-request-id` was absent, `isGitHubHost` returns `false` *this first time*.
3. On any subsequent call to `isGitHubHost('https://evil.example.com')` (e.g., a later `getEndpointKind` invocation during another git operation to the same remote), `getEndpointVersion(endpoint) !== null` is now `true`, so the function returns `true` immediately — the `x-github-request-id` authenticity check is never performed again.
4. `getEndpointKind` now classifies `evil.example.com` as `'enterprise'`; with no existing account for that endpoint, `getCredential` invokes `ui.promptForGitHubSignIn('https://evil.example.com')`.
5. If the user signs in, the resulting OAuth Account/token is bound to `evil.example.com` and will be sent as Basic Auth credentials to that server on future git fetch/push operations.

Uncertain/unverified points: the exact UX copy and gating logic inside `ui.promptForGitHubSignIn` (its implementation wasn't inspected here) and the precise conditions under which `getEndpointKind` is invoked for a brand-new, never-seen HTTPS remote outside of the credential helper flow were not fully traced beyond the code cited above.

export function getEndpointVersion(endpoint: string) {
  const key = endpointVersionKey(endpoint)
  const cached = versionCache.get(key)

  if (cached !== undefined) {
    return cached
  }

  const raw = localStorage.getItem(key)
  const parsed = raw === null ? null : semver.parse(raw)

  if (parsed !== null) {
    versionCache.set(key, parsed)
  }

  return parsed
}

/**
 * Update the known version number for a given endpoint
 */
export function updateEndpointVersion(endpoint: string, version: string) {
  const key = endpointVersionKey(endpoint)

  if (rawVersionCache.get(key) !== version) {
    const parsed = semver.parse(version)
    localStorage.setItem(key, version)
    rawVersionCache.set(key, version)
    versionCache.set(key, parsed)
  }
}

/** Implementation of the 'get' git credential helper command */
async function getCredential(cred: Credential, store: Store, token: string) {
  const ghCred = await getGitHubCredential(cred, store)

  if (ghCred) {
    return ghCred
  }

  const endpointKind = await getEndpointKind(cred, store)
  const accounts = await store.getAll()

  const endpoint = `${getCredentialUrl(cred)}`
  const apiEndpoint = getAPIEndpoint(endpoint)

  // If it appears as if the endpoint is a GitHub host and we don't have an
  // account for that endpoint then we should prompt the user to sign in.
  if (
    endpointKind !== 'generic' &&
    !accounts.some(a => a.endpoint === apiEndpoint)
  ) {
    if (getIsBackgroundTaskEnvironment(token)) {
      debug('background task environment, skipping prompt')
      return undefined
    }

    const account = await ui.promptForGitHubSignIn(endpoint)

    if (!account) {
      setHasRejectedCredentialsForEndpoint(token, endpoint)
    }

    return credWithAccount(cred, account)
  }

const getEndpointKind = async (cred: Credential, store: Store) => {
  const credentialUrl = getCredentialUrl(cred)
  const endpoint = `${credentialUrl}`

  if (isGist(endpoint)) {
    return 'generic'
  }

  if (isDotCom(endpoint)) {
    return 'github.com'
  }

  if (isGHE(endpoint)) {
    return 'ghe.com'
  }

  // When Git attempts to authenticate with a host it captures any
  // WWW-Authenticate headers and forwards them to the credential helper. We
  // use them as a happy-path to determine if the host is a GitHub host without
  // having to resort to making a request ourselves.
  for (const [k, v] of cred.entries()) {
    if (k.startsWith('wwwauth[')) {
      if (v.includes('realm="GitHub"')) {
        return 'enterprise'
      } else if (/realm="(GitLab|Gitea|Atlassian Bitbucket)"/.test(v)) {
        return 'generic'
      }
    }
  }

  const existingAccount = await findGitHubTrampolineAccount(store, endpoint)
  if (existingAccount) {
    return isDotCom(existingAccount.endpoint) ? 'github.com' : 'enterprise'
  }

  // All GitHub hosts use HTTPS, so if the protocol is not HTTPS we can
  // assume that this is not a GitHub host.
  if (credentialUrl.protocol !== 'https:') {
    return 'generic'
  }

  return (await isGitHubHost(endpoint)) ? 'enterprise' : 'generic'
}
