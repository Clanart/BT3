### Title
Unhandled crash in mempool CLVM canonicality check via crafted spend-bundle puzzle/solution bytes - (File: `chia/full_node/mempool_manager.py`)

### Summary
`is_atom_canonical()` / `is_clvm_canonical()` in [1](#0-0)  is a hand-rolled CLVM byte-stream parser that runs on attacker-controlled `puzzle_reveal`/`solution` bytes from every submitted spend bundle, analogous to the Wireshark SPRT dissector parsing untrusted packet bytes. Like the CVE, the parser walks a length-prefixed structure without fully validating the branch/bounds invariants it assumes, so crafted input can hit an unhandled path.

### Finding Description
`validate_spend_bundle()` calls `is_clvm_canonical(bytes(coin_spend.puzzle_reveal))` and on the solution for every coin spend in an untrusted spend bundle, before any mempool-lock protected admission logic: [2](#0-1) 

`is_clvm_canonical()` walks the buffer byte-by-byte, dispatching to `is_atom_canonical()` for any lead byte `b` with `0x80 < b < 0xFF`: [3](#0-2) 

`is_atom_canonical()` decodes a length prefix and then reads `prefix_len` additional bytes directly out of `clvm_buffer` with **no bounds check**: [4](#0-3) 

If the lead byte encodes a length prefix that requires more bytes than remain in `clvm_buffer` (e.g. a single-byte buffer ending in `0xF8`-`0xFD`, which claims 2-5 trailing length bytes), the loop `atom_len |= clvm_buffer[offset]` raises an uncaught `IndexError` instead of returning a `bool`. This mirrors the CVE's root cause class — a parser that trusts internally-computed offsets/lengths against attacker data without verifying they stay within the buffer, leading to an out-of-bounds access on crafted input reachable purely by submitting a spend bundle (RPC `push_tx`, wallet `send_transaction`, or peer `new_transaction`/`respond_transaction`).

`add_transaction()` in `full_node.py` only wraps `pre_validate_spendbundle()` (the CLVM/BLS validation stage) in `try/except`, not `add_spend_bundle()`/`validate_spend_bundle()` where `is_clvm_canonical` executes: [5](#0-4) 

Since `add_spend_bundle()`/`validate_spend_bundle()` run inside `async with self.blockchain.priority_mutex.acquire(...)` with no surrounding exception handler around that block, an `IndexError` raised there propagates up uncaught.

### Impact Explanation
An uncaught exception inside the blockchain-mutex-guarded transaction-admission path can abort the coroutine holding `priority_mutex`, disrupting subsequent block/transaction processing that depends on that lock being released cleanly — this is a spend-triggered transaction-processing halt, matching the CVE's "denial of service via crafted packet/capture" class, but here via a crafted spend bundle. This is reachable by any unprivileged spend-bundle submitter (wallet RPC caller or P2P peer) without needing valid signatures over the crashing coin spend's true semantics — only a syntactically valid `SpendBundle` with a short/malformed puzzle_reveal or solution atom.

### Likelihood Explanation
Reaching this requires no special privilege: any RPC caller (`push_tx`) or any peer relaying a `new_transaction`/`respond_transaction` can supply a `SpendBundle` whose `puzzle_reveal` or `solution` bytes end with a byte in `0xF8-0xFD` immediately followed by fewer bytes than the encoded length prefix requires. `validate_clvm_and_signature` (Rust CLVM runner in `pre_validate_spendbundle`) is invoked first and could reject the malformed program before `is_clvm_canonical` runs, so whether this is actually reachable in the standard pipeline depends on whether the Rust CLVM deserializer accepts/normalizes truncated atoms in the same way the Python `is_atom_canonical` re-parses them — this interaction was not fully verifiable from the indexed code alone. This uncertainty is the main open question for confirming exploitability end-to-end.

### Recommendation
Add explicit bounds checks in `is_atom_canonical()` before dereferencing `clvm_buffer[offset]` (return `False`/raise a handled `ValueError` if `offset >= len(clvm_buffer)`), add an `else` branch in `is_atom_canonical()` to defensively handle the `b == 0xFF` case if it can ever reach this function, and wrap the `validate_spend_bundle()` call (or at least the `is_clvm_canonical` calls) in a try/except that converts unexpected exceptions into `Err.INVALID_COIN_SOLUTION` rather than allowing them to propagate out of the mutex-protected block.

### Proof of Concept
1. Construct a `CoinSpend` whose `puzzle_reveal` (or `solution`) serialized bytes are a single truncated atom, e.g. bytes `b"\xf8"` (lead byte `0xF8` claims a 2-byte trailing length prefix but the buffer ends immediately).
2. Wrap it in a `SpendBundle` and submit via `push_tx` RPC or as a peer `new_transaction`.
3. If `validate_clvm_and_signature` in the Rust layer does not reject this shape identically, execution reaches `validate_spend_bundle()` → `is_clvm_canonical(bytes(coin_spend.puzzle_reveal))` → `is_atom_canonical(clvm_buffer, 0)`, which executes `offset += 1; atom_len |= clvm_buffer[offset]` against an out-of-range index, raising an unhandled `IndexError`. [6](#0-5) 

**Caveat:** I could not fully confirm from the indexed code whether `validate_clvm_and_signature` (implemented in the `chia_rs` Rust extension, not indexed here) would reject such a truncated atom before `is_clvm_canonical` is reached, which is necessary to confirm the DoS is reachable end-to-end rather than intercepted earlier. If you need certainty on this interaction, a Devin session with full filesystem/dependency access (including the `chia_rs` source) would be required to trace the exact validation order and confirm exploitability.

def is_atom_canonical(clvm_buffer: bytes, offset: int) -> tuple[int, bool]:
    b = clvm_buffer[offset]
    if (b & 0b11000000) == 0b10000000:
        # 6 bits length prefix
        mask = 0b00111111
        prefix_len = 0
        min_value = 1
    elif (b & 0b11100000) == 0b11000000:
        # 5 + 8 bits length prefix
        mask = 0b00011111
        prefix_len = 1
        min_value = 1 << 6
    elif (b & 0b11110000) == 0b11100000:
        # 4 + 8 + 8 bits length prefix
        mask = 0b00001111
        prefix_len = 2
        min_value = 1 << (5 + 8)
    elif (b & 0b11111000) == 0b11110000:
        # 3 + 8 + 8 + 8 bits length prefix
        mask = 0b00000111
        prefix_len = 3
        min_value = 1 << (4 + 8 + 8)
    elif (b & 0b11111100) == 0b11111000:
        # 2 + 8 + 8 + 8 + 8 bits length prefix
        mask = 0b00000011
        prefix_len = 4
        min_value = 1 << (3 + 8 + 8 + 8)
    elif (b & 0b11111110) == 0b11111100:
        # 1 + 8 + 8 + 8 + 8 + 8 bits length prefix
        mask = 0b00000001
        prefix_len = 5
        min_value = 1 << (2 + 8 + 8 + 8 + 8)

    atom_len = b & mask
    for i in range(prefix_len):
        atom_len <<= 8
        offset += 1
        atom_len |= clvm_buffer[offset]

    return 1 + prefix_len + atom_len, atom_len >= min_value


def is_clvm_canonical(clvm_buffer: bytes) -> bool:
    """
    checks whether the CLVM serialization is all canonical representation.
    atoms can be serialized in more than one way by using more bytes than
    necessary to encode the length prefix. This functions ensures that all atoms are
    encoded with the shortest representation. back-references are not allowed
    and will make this function return false
    """
    assert clvm_buffer != b""

    offset = 0
    tokens_left = 1
    while True:
        b = clvm_buffer[offset]

        # pair
        if b == 0xFF:
            tokens_left += 1
            offset += 1
            continue

        # back references cannot be considered canonical, since they may be
        # encoded in many different ways
        if b == 0xFE:
            return False

        # small atom or NIL
        if b <= 0x80:
            tokens_left -= 1
            offset += 1
        else:
            atom_len, canonical = is_atom_canonical(clvm_buffer, offset)
            if not canonical:
                return False
            tokens_left -= 1
            offset += atom_len

        if tokens_left == 0:
            break

    # if there's garbage at the end, it's not canonical
    return offset == len(clvm_buffer)
