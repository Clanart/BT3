Found: the AuctionEntryPointMock contract has clearly missing access control — `setAuctioneer` and `setGasBufferEstimate` have **no modifier at all**, unlike the C4 bug's "modifier without require". This is a stronger analog (a total absence rather than a broken check), and it is reachable by any public-RPC/auction caller.

### Title
Unrestricted `setAuctioneer`/`setGasBufferEstimate` allow any address to hijack auction settlement configuration - (File: contracts/testing/system_contracts/AuctionEntryPointMock.sol)

### Summary
`AuctionEntryPointMock.sol` implements the entry point for Kaia's auction/MEV settlement flow, gating the sensitive `call` function with an `onlyProposer` modifier tied to `block.coinbase` [1](#0-0) . However the two functions that configure the trusted `auctioneer` address and the `gasBufferEstimate` used in bid/gas accounting are declared `public` with no modifier whatsoever, meaning any externally submitted transaction can call them directly.

### Finding Description
`setAuctioneer` writes directly to the `auctioneer` state variable with zero access restriction, and `setGasBufferEstimate` writes to `gasBufferEstimate` the same way: [2](#0-1) 
This mirrors the class of bug in the external report — sensitive configuration setters that are supposed to be permissioned but are trivially callable by any unprivileged sender — except here the modifier is missing entirely rather than merely broken. The `auctioneer` address is the trust anchor intended (per the commented-out signature-verification logic in `_verifyInputIntegrity`) to co-sign/attest auction transactions before they are executed via `call` [3](#0-2) . `gasBufferEstimate` is meant to represent trusted gas-accounting parameters for the auction settlement.

### Impact Explanation
An unprivileged transaction sender can overwrite `auctioneer` to an address they control, which — once the commented-out auctioneer signature check is enabled/relied upon — would let the attacker forge auctioneer approval for arbitrary `AuctionTx` payloads, or set it to `address(0)`/an unreachable address to permanently break auction validation for the whole system. Independently, resetting `gasBufferEstimate` to 0 or an extreme value could corrupt gas/fee accounting for the auction settlement path, potentially causing gas underpayment or reverts for legitimate proposer calls. Because this configuration data underlies auction bid settlement and could enable unauthorized value movement/redirection of auction proceeds, the impact is High.

### Likelihood Explanation
Likelihood is High: no signature, role check, or `onlyOwner`-style modifier of any kind gates these two setters, and the contract is otherwise wired into the live auction settlement flow (`onlyProposer`-gated `call`), so a single arbitrary transaction from any externally-owned account or contract is sufficient to trigger it.

### Recommendation
Add an owner/role-based modifier (e.g., `onlyOwner`) to both `setAuctioneer` and `setGasBufferEstimate`, consistent with the pattern already used correctly elsewhere in the codebase (e.g., `onlyOwner` in `Ownable.sol` [4](#0-3) , or `onlyOperators`/`onlyOwner` gating in `BridgeOperator.sol` [5](#0-4) ). At minimum, restrict these setters to a designated governance/owner address and require an explicit `require(msg.sender == owner, "not authorized")` check.

### Proof of Concept
```solidity
// Any random, unprivileged address can call these with no restriction:
AuctionEntryPointMock entry = AuctionEntryPointMock(auctionEntryPointAddr);

vm.prank(randomUser);
entry.setAuctioneer(attackerControlledAddress);

vm.prank(randomUser);
entry.setGasBufferEstimate(0);
```
Both calls succeed for any `msg.sender` since neither function carries an access-control modifier [2](#0-1) , unlike the properly-restricted `call` function which is `onlyProposer` [6](#0-5) .

Note: this file resides under `contracts/testing/system_contracts/` and is explicitly named `AuctionEntryPointMock.sol`, suggesting it may be a test/mock contract rather than the production auction entry point; I could not locate a non-mock production `AuctionEntryPoint.sol` in the indexed codebase to confirm whether the production contract has the same gap or already applies proper access control — this should be verified against the actual production contract before treating this as a live production finding.
