### Title
Governance parameter `kip71.gastarget` can be set to 0 with no validation, causing a division‑by‑zero panic in KIP‑71 base fee calculation and halting all Kaia nodes - (File: `params/kip71_config.go`, `kaiax/gov/param.go`)

### Summary
The Kaia governance module (`kaiax/gov`) is the analog of the `_setParams`/`setParams` pattern described in the external report: it lets a governance actor reparameterize protocol-critical values through `ParamSet.Set`/`PartialParamSet.Add`, gated only by a per-parameter `FormatChecker`. For `Kip71GasTarget` this checker is `noopFormatChecker`, which unconditionally returns `true`, i.e. there is no sanity/threshold check preventing the value from being set to `0`. That value is later used as a divisor in `KIP71Config.NextMagmaBlockBaseFee`, so setting it to `0` causes a `big.Int` division-by-zero panic on every node computing the next block's base fee — the exact "invalid parameter causes any dependent contract/function to revert/misbehave" scenario from the report, but here it crashes consensus-critical code instead of a smart contract call.

### Finding Description
`kaiax/gov/param.go` defines the parameter table `Params`, where `Kip71GasTarget` uses `noopFormatChecker`: [1](#0-0) 

`noopFormatChecker` always accepts the value: [2](#0-1) 

`PartialParamSet.Add` (used when building/casting a vote) only runs the canonicalizer and this `FormatChecker`, with no additional range check: [3](#0-2) 

The header-governance vote consistency check (`checkConsistency`) explicitly whitelists `gov.Kip71GasTarget` into the "no more checks here" bucket, confirming there is no additional validation anywhere in the vote pipeline: [4](#0-3) 

Once `GasTarget` is `0` and merged into the effective `ParamSet`/`KIP71Config` (via `ToKip71Config`), it feeds directly into `NextMagmaBlockBaseFee`: [5](#0-4) 

```go
gasTarget := kc.GasTarget
...
parentGasUsed := min(parentHeaderGasUsed, upperGasLimit)
if parentGasUsed == gasTarget {
    return makeEvenByFloor(parentBaseFee)
} else if parentGasUsed > gasTarget {
    ...
    gasUsedDelta := new(big.Int).SetUint64(parentGasUsed - gasTarget)
    x := new(big.Int).Mul(parentBaseFee, gasUsedDelta)
    y := x.Div(x, new(big.Int).SetUint64(gasTarget))   // division by zero when gasTarget == 0
``` [6](#0-5) 

Note that the code explicitly guards the analogous `BaseFeeDenominator == 0` case by falling back to `64`: [7](#0-6) 

...but no equivalent guard exists for `GasTarget == 0`. As soon as any block has `parentGasUsed > 0` (true for virtually every real block once transactions exist), the code takes the `parentGasUsed > gasTarget` branch and executes `x.Div(x, big.NewInt(0))`, which is documented to panic in Go's `math/big` package.

This function is called on the hot consensus path for every block once the Magma hardfork is active — in header verification (`VerifyMagmaHeader`), in fee history/gas price oracle logic, and in cross-chain bridge fee propagation: [8](#0-7) [9](#0-8) 

### Impact Explanation
Once `kip71.gastarget` is set to `0` via a governance vote transaction (header-governance vote or contract-governance parameter update, both of which reuse the same `Params`/`FormatChecker` table), every node in the network that computes `NextMagmaBlockBaseFee` for a block with nonzero gas usage will panic and crash. Because this routine runs in header verification and block finalization, this is not a localized failure — it causes a synchronized, network-wide denial of service / chain halt as soon as the parameter takes effect and the first non-empty block after it is processed. This is a High severity availability impact on the core chain, directly analogous to the report's "any contract depending on the function will return invalid values or revert, breaking several important interactions."

### Likelihood Explanation
The only precondition is a single accepted governance vote (or contract-governance parameter set call) with `kip71.gastarget = 0`. There is no format/threshold check anywhere in the vote-acceptance path (`PartialParamSet.Add`, `NewVoteData`, `checkConsistency`) that rejects zero, unlike the sibling parameters `Kip71LowerBoundBaseFee`/`Kip71UpperBoundBaseFee` which do have cross-field consistency checks. A single mistaken or malicious governance vote — exactly the "Alice accidentally includes an invalid value" scenario from the original report — is sufficient to trigger the panic on the very next non-empty block.

### Recommendation
Add a `FormatChecker` for `Kip71GasTarget` (and ideally `Kip71MaxBlockGasUsedForBaseFee`) in `kaiax/gov/param.go` that rejects `0`, mirroring the defensive fallback already present for `BaseFeeDenominator`. Additionally, as defense-in-depth, `NextMagmaBlockBaseFee` in `params/kip71_config.go` should guard against `gasTarget == 0` (e.g., treat it the same way `BaseFeeDenominator == 0` is handled) so that a bad parameter cannot crash node processing even if it slips past governance validation.

### Proof of Concept
1. As the governing node (single-mode governance) or via contract-governance, submit a governance vote/transaction setting `kip71.gastarget` to `0`. This passes validation because `Kip71GasTarget`'s `FormatChecker` is `noopFormatChecker` and `checkConsistency` performs no extra check for this key. [1](#0-0) [4](#0-3) 
2. Once the parameter is active (after the vote's effect block), any subsequent block with `GasUsed > 0` triggers `NextMagmaBlockBaseFee`'s `parentGasUsed > gasTarget` branch:
   ```go
   gasUsedDelta := new(big.Int).SetUint64(parentGasUsed - gasTarget) // = parentGasUsed
   x := new(big.Int).Mul(parentBaseFee, gasUsedDelta)
   y := x.Div(x, new(big.Int).SetUint64(gasTarget)) // gasTarget == 0 -> panics
   ``` [10](#0-9) 
3. Every node evaluating `VerifyMagmaHeader`/`NextMagmaBlockBaseFee` for that block panics, halting block processing network-wide.

func (kc *KIP71Config) VerifyMagmaHeader(headerBaseFee *big.Int, parentHeaderNumber *big.Int, parentHeaderBaseFee *big.Int, parentHeaderGasUsed uint64) error {
	if headerBaseFee == nil {
		return fmt.Errorf("header is missing baseFee")
	}
	// Verify the baseFee is correct based on the parent header.
	expectedBaseFee := kc.NextMagmaBlockBaseFee(parentHeaderNumber, parentHeaderBaseFee, parentHeaderGasUsed)
	if headerBaseFee.Cmp(expectedBaseFee) != 0 {
		return fmt.Errorf("invalid baseFee: have %s, want %s, parentBaseFee %s, parentGasUsed %d",
			headerBaseFee, expectedBaseFee, parentHeaderBaseFee, parentHeaderGasUsed)
	}
	return nil
}

func (kc *KIP71Config) NextMagmaBlockBaseFee(parentHeaderNumber *big.Int, parentHeaderBaseFee *big.Int, parentHeaderGasUsed uint64) *big.Int {
	// governance parameters
	lowerBoundBaseFee := new(big.Int).SetUint64(kc.LowerBoundBaseFee)
	upperBoundBaseFee := new(big.Int).SetUint64(kc.UpperBoundBaseFee)
	makeEvenByCeil(lowerBoundBaseFee)
	makeEvenByFloor(upperBoundBaseFee)

	// If the parent is the magma disabled block or genesis, then return the lowerBoundBaseFee (default 25ston)
	if parentHeaderNumber.Cmp(new(big.Int).SetUint64(0)) == 0 || parentHeaderBaseFee == nil {
		return makeEvenByFloor(lowerBoundBaseFee)
	}

	var baseFeeDenominator *big.Int
	if kc.BaseFeeDenominator == 0 {
		// To avoid panic, set the fluctuation range small
		baseFeeDenominator = new(big.Int).SetUint64(64)
	} else {
		baseFeeDenominator = new(big.Int).SetUint64(kc.BaseFeeDenominator)
	}
	gasTarget := kc.GasTarget
	upperGasLimit := kc.MaxBlockGasUsedForBaseFee

	// check the case of upper/lowerBoundBaseFee is updated by governance mechanism
	parentBaseFee := parentHeaderBaseFee
	if parentBaseFee.Cmp(upperBoundBaseFee) >= 0 {
		parentBaseFee = upperBoundBaseFee
	} else if parentBaseFee.Cmp(lowerBoundBaseFee) <= 0 {
		parentBaseFee = lowerBoundBaseFee
	}

	// upper gas limit cut off the impulse of used gas to upper bound
	parentGasUsed := min(parentHeaderGasUsed, upperGasLimit)
	if parentGasUsed == gasTarget {
		return makeEvenByFloor(parentBaseFee)
	} else if parentGasUsed > gasTarget {
		// shortcut. If parentBaseFee is already reached upperbound, do not calculate.
		if parentBaseFee.Cmp(upperBoundBaseFee) == 0 {
			return makeEvenByFloor(upperBoundBaseFee)
		}
		// If the parent block used more gas than its target,
		// the baseFee of the next block should increase.
		// baseFeeDelta = max(1, parentBaseFee * (parentGasUsed - gasTarget) / gasTarget / baseFeeDenominator)
		gasUsedDelta := new(big.Int).SetUint64(parentGasUsed - gasTarget)
		x := new(big.Int).Mul(parentBaseFee, gasUsedDelta)
		y := x.Div(x, new(big.Int).SetUint64(gasTarget))
		baseFeeDelta := math.BigMax(x.Div(y, baseFeeDenominator), common.Big1)
