### Title
Unrestricted PlotNFT Transfer While Exiting/Pool-Transition Pending Griefs New Owner - (File: chia/wallet/plotnft_wallet/plotnft_wallet.py)

### Summary
`PlotNFT2Wallet.transfer_plotnft` lets the current owner move their plot-NFT singleton to a new local wallet/fingerprint without checking whether the plot-NFT is mid-transition (`plotnft.exiting`, an unconfirmed `join_pool`/`leave_pool` spend, or an unconfirmed melt) or has any unconfirmed transaction outstanding. This mirrors the reported class of bug: a "position" (here, a pool-singleton lifecycle state) can be handed to a new owner while the old owner still has unresolved pending state, letting the old owner grief the new owner.

### Finding Description
`transfer_plotnft` (`chia/wallet/plotnft_wallet/plotnft_wallet.py:421-482`) fetches `plotnft = await self.get_current_plotnft()` and immediately builds a `new_user_config` spend, with no guard analogous to `PoolWallet.join_pool`/`self_pool`, which explicitly call `have_unconfirmed_transaction()` and reject the action if true (`chia/pools/pool_wallet.py:630-712`, e.g. line 635-638, 676-679). `leave_pool` on the new `PlotNFT2Wallet` does check `plotnft.exiting` before allowing a *new* leave (`plotnft_wallet.py:307-308`), but `transfer_plotnft` performs no equivalent check on `plotnft.pool_config`, `plotnft.exiting`, or outstanding unconfirmed spends before re-keying ownership.

Consequently, an old owner can:
- Broadcast a `leave_pool` transaction (setting local `plotnft_exiting_info` side effects, `plotnft_wallet.py:329-337`) and, in the same session, immediately call `transfer_plotnft` to hand off the singleton before that transition confirms.
- Because `transfer_plotnft` doesn't wait for or reject based on unconfirmed pool-state spends, the new owner may receive an NFT whose actual current on-chain lineage is different from what they observed, or whose pending `LEAVING_POOL`/relative-lock-height state and previously-broadcast reward puzzle hash (`rewards_claim_puzhash`, `plotnft_wallet.py:92-96`, derived from the *old* owner's local `PoolingShareState`) still races the transfer spend.
- If both spends attempt to consume the same plot-NFT coin, the result is a real, protocol-visible transaction-processing/state hazard for the new owner: whichever spend is not accepted leaves the new owner's wallet unable to cleanly track/resume the singleton (the sync-side `identify()`/`coin_added()` logic in the same file assumes a clean linear lineage per launcher id), or the new owner inherits a `LEAVING_POOL`/lock-height-encumbered plot-NFT they did not agree to.

### Impact Explanation
This is a Medium-severity issue: it does not directly forge assets or invalidate consensus, but it can cause loss of expected funds/usability for the new plot-NFT owner (receiving a locked/exiting singleton, conflicting spends, or reward routing tied to stale local pool config), analogous to the original GMX-position NFT griefing report. No admin/network-privilege is required — any local wallet owner performing a normal `transfer_plotnft` RPC/CLI call is affected.

### Likelihood Explanation
Requires the old owner to deliberately race their own `leave_pool`/`join_pool` transaction against a `transfer_plotnft` call, which is straightforward to script locally with the existing wallet RPC (`TransferPlotNFTCMD` / `nft_transfer_bulk`-style flows are analogous). Because no unconfirmed-transaction or exiting-state guard exists in `transfer_plotnft`, this is trivial to trigger deliberately, though it requires the malicious former owner's active participation (same trust model as the referenced report).

### Recommendation
Add the same guard pattern used in `PoolWallet.join_pool`/`self_pool` to `PlotNFT2Wallet.transfer_plotnft`: reject the transfer if `plotnft.exiting` is true, if `plotnft.pool_config` transition is otherwise mid-flight, or if there is an unconfirmed transaction against this plot-NFT wallet, forcing all pending pool-state transitions to confirm before ownership can change hands.

    async def transfer_plotnft(
        self,
        *,
        action_scope: WalletActionScope,
        target_wallet_fingerprint: int,
        fee: uint64 = uint64(0),
        extra_conditions: tuple[Condition, ...] = tuple(),
    ) -> None:
        """
        Because the wallet doesn't have broad support for MIPS-style custody, transferring using addresses is
        a bit complicated because transferring to the wrong kind of address could leave the wallet unable to
        sync/spend the PlotNFT. As a guard, we implement this endpoint as a transfer between local keys to make
        sure that we generate the correct kind of inner puzzle.

        This is not necessarily a permanent restriction, but solves the primary use case of transferring between
        a user's own wallets and keeps the implementation relatively simple for now.
        """
        plotnft = await self.get_current_plotnft()
        fee_hook = CreateCoinAnnouncement(msg=b"", coin_id=plotnft.coin.name())
        root_pubkey = await self.wallet_state_manager.wallet_node.keychain_proxy.get_key_for_fingerprint(
            fingerprint=target_wallet_fingerprint, private=False
        )
        if root_pubkey is None:
            raise RuntimeError(f"Error retrieving key for fingerprint {target_wallet_fingerprint}")
        wallet_pubkey = master_pk_to_wallet_pk_unhardened(root_pubkey, index=uint32(0))
        synthetic_pubkey = self.xch_wallet.convert_public_key_to_synthetic(wallet_pubkey)
        hint = self.xch_wallet.puzzle_hash_for_pk(wallet_pubkey)
        new_user_config = UserConfig(synthetic_pubkey=synthetic_pubkey)
        coin_spends = plotnft.new_user_config(
            user_config=new_user_config,
            hint=hint,
            extra_conditions=(fee_hook, *extra_conditions),
        )
        if fee > 0:
            await self.xch_wallet.create_tandem_xch_tx(
                fee=fee,
                action_scope=action_scope,
                extra_conditions=(fee_hook.corresponding_assertion(),),
            )

        spend_bundle = WalletSpendBundle(coin_spends, G2Element())
