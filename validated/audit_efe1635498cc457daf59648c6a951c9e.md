### Title
Missing (withdrawal_utxo_txid, withdrawal_utxo_vout) uniqueness lets one Bitcoin payout be credited to two Citrea withdrawal indices, enabling double reimbursement - (File: core/src/database/verifier.rs)

### Summary
`Database::get_payout_txs_for_withdrawal_utxos` joins `withdrawals` to `bitcoin_syncer_spent_utxos` purely on `(txid, vout)` equality, with no tie-back to a specific withdrawal `idx`, and the `withdrawals` table has no uniqueness constraint on `(withdrawal_utxo_txid, withdrawal_utxo_vout)`. An unprivileged attacker who makes two deposits and calls the Citrea Bridge contract's `withdraw()` twice with identical `(txId, outputId)` bytes for both withdrawals causes both `withdrawals` rows to store the same UTXO; a single real Bitcoin payout spending that UTXO is then joined and credited to both withdrawal indices, letting the paying operator be reimbursed twice for one fronted payout.

### Finding Description
Binding that must hold: for each withdrawal index `idx`, the number of BTC payouts credited to it via `update_payout_txs_and_payer_operator_xonly_pk` must equal the number of distinct on-chain payments actually fronted by an operator for that specific withdrawal. Before the exploit this is 1:1; after the exploit two indices (`i`, `j`) both receive a credit from the same single spend.

Path:
1. The attacker deposits twice, producing two `withdrawals` rows with distinct `idx` (`i`, `j`) and distinct `move_to_vault_txid`, via `Verifier::update_citrea_deposit_and_withdrawals` [1](#0-0) .
2. The attacker (fully unprivileged, per the stated capability to "call `withdraw` on the Citrea Bridge contract" and "choose the bytes of a withdrawal UTXO") calls Citrea's `withdraw()` twice, supplying the identical `(txId, outputId)` for both calls; `collect_withdrawal_utxos` faithfully returns these two `(idx, outpoint)` pairs to Clementine [2](#0-1) .
3. `Database::update_withdrawal_utxo_from_citrea_withdrawal` performs a plain per-`idx` `UPDATE` with no uniqueness check across rows, so both `i` and `j` end up with identical `withdrawal_utxo_txid`/`withdrawal_utxo_vout` [3](#0-2) . The schema confirms `withdrawals.idx` is the only primary key; there is no unique constraint on `(withdrawal_utxo_txid, withdrawal_utxo_vout)` [4](#0-3) .
4. An operator fronts exactly one real payout transaction `T` spending that shared UTXO once. `Database::get_payout_txs_for_withdrawal_utxos` joins solely on `(txid, vout)` and, because both `i` and `j` reference that UTXO, returns two rows: `(i, T)` and `(j, T)` [5](#0-4) .
5. `Verifier::update_finalized_payouts` iterates these two rows independently, re-parsing the same OP_RETURN from `T` twice and pushing two `(idx, T, operator_xonly_pk, block_hash)` tuples [6](#0-5) , then `update_payout_txs_and_payer_operator_xonly_pk` writes identical `payout_txid`/`payer_operator_xonly_pk`/`payout_tx_blockhash` into BOTH rows [7](#0-6) .
6. `PayoutCheckerTask::run_once` repeatedly calls `get_first_unhandled_payout_by_operator_xonly_pk`, which finds each `idx` independently (filtered only by operator pubkey and "not handled"), and calls `Operator::handle_finalized_payout` for each deposit separately, generating two separate kickoffs/reimbursements [8](#0-7) .
7. Verifier's `is_kickoff_malicious` check, which is the only guard against fraudulent kickoffs, only validates that `operator_xonly_pk` matches and the committed truncated block hash matches the DB's `payout_tx_blockhash` — both of which are now identical for `i` and `j` by construction, so this check passes for the second, "phantom" kickoff too [9](#0-8) .

No existing check (`Verifier::is_deposit_valid`, `is_kickoff_malicious`, the storage-proof/LCP checks, or a DB uniqueness constraint) verifies that a given spent-UTXO/payout is uniquely attributable to one withdrawal index.

### Impact Explanation
The paying operator receives two independent Reimburse-transaction payouts (drawn from two distinct kickoff/round collateral connectors) for a single real BTC payment fronted once. This is exactly the "operator reimbursed for a payout it never funded" Critical category: reimbursement for index `j` is granted despite no operator ever fronting a distinct payment for `j`. This depletes the operator's collateral pool and the bridge's presigned reimbursement structure faster than legitimate withdrawals justify, and is repeatable across any number of deposit/withdrawal pairs the attacker controls, and across any operator that happens to process the colliding withdrawal.

### Likelihood Explanation
The only precondition is that the attacker makes two deposits and calls Citrea's `withdraw()` twice with byte-identical `(txId, outputId)` values — both actions are explicitly within the stated unprivileged attacker capability set (deposit, call `withdraw`, choose UTXO bytes). No verifier, operator, or aggregator privilege, no key compromise, and no race condition beyond normal sequential Citrea sync is required. Cost is limited to the fees/collateral of making two ordinary bridge deposits.

### Recommendation
Add a database-level uniqueness constraint on `(withdrawal_utxo_txid, withdrawal_utxo_vout)` in the `withdrawals` table (or reject the second `update_withdrawal_utxo_from_citrea_withdrawal` write for a UTXO already assigned to a different `idx`), and change `get_payout_txs_for_withdrawal_utxos`'s join to also ensure only one `idx` per spent UTXO is ever credited (e.g., pick the lowest `idx` and flag/alert on collisions) so a single Bitcoin spend can never satisfy two withdrawal indices.

    async fn update_finalized_payouts(
        &self,
        dbtx: DatabaseTransaction<'_>,
        block_id: u32,
        block_cache: &block_cache::BlockCache,
    ) -> Result<(), BridgeError> {
        let payout_txids = self
            .db
            .get_payout_txs_for_withdrawal_utxos(Some(dbtx), block_id)
            .await?;

        let block = &block_cache.block;

        let block_hash = block.block_hash();

        let mut payout_txs_and_payer_operator_idx = vec![];
        for (idx, payout_txid) in payout_txids {
            let payout_tx_idx = block_cache.txids.get(&payout_txid);
            if payout_tx_idx.is_none() {
                tracing::error!(
                    "Payout tx not found in block cache: {:?} and in block: {:?}",
                    payout_txid,
                    block_id
                );
                tracing::error!("Block cache: {:?}", block_cache);
                return Err(eyre::eyre!("Payout tx not found in block cache").into());
            }
            let payout_tx_idx = payout_tx_idx.expect("Payout tx not found in block cache");
            let payout_tx = &block.txdata[*payout_tx_idx];
            // Find the first output that contains OP_RETURN
            let circuit_payout_tx = CircuitTransaction::from(payout_tx.clone());
            let op_return_output = get_first_op_return_output(&circuit_payout_tx);

            // If OP_RETURN doesn't exist in any outputs, or the data in OP_RETURN is not a valid xonly_pubkey,
            // operator_xonly_pk will be set to None, and the corresponding column in DB set to NULL.
            // This can happen if optimistic payout is used, or an operator constructs the payout tx wrong.
            let operator_xonly_pk = op_return_output
                .and_then(|output| parse_op_return_data(&output.script_pubkey))
                .and_then(|bytes| XOnlyPublicKey::from_slice(bytes).ok());

            if operator_xonly_pk.is_none() {
                tracing::info!(
                    "No valid operator xonly pk found in payout tx {:?} OP_RETURN. Either it is an optimistic payout or the operator constructed the payout tx wrong",
                    payout_txid
                );
            }

            tracing::info!(
                "A new payout tx detected for withdrawal {}, payout txid: {:?}, operator xonly pk: {:?}",
                idx,
                payout_txid,
                operator_xonly_pk
            );

            payout_txs_and_payer_operator_idx.push((
                idx,
                payout_txid,
                operator_xonly_pk,
                block_hash,
            ));
        }

        self.db
            .update_payout_txs_and_payer_operator_xonly_pk(
                Some(dbtx),
                payout_txs_and_payer_operator_idx,
            )
            .await?;

    async fn collect_withdrawal_utxos(
        &self,
        last_withdrawal_idx: Option<u32>,
        to_height: u64,
    ) -> Result<Vec<(u64, OutPoint)>, BridgeError> {
        let mut utxos = vec![];

        let mut start_idx = match last_withdrawal_idx {
            Some(idx) => idx + 1,
            None => 0,
        };

        loop {
            let withdrawal_utxo = self
                .contract
                .withdrawalUTXOs(U256::from(start_idx))
                .block(BlockId::Number(BlockNumberOrTag::Number(to_height)))
                .call()
                .await;
            match withdrawal_utxo {
                Err(e) if e.to_string().contains("execution reverted") => {
                    tracing::trace!("Withdrawal utxo not found for index, error: {:?}", e);
                    break;
                }
                Err(e) => return Err(e.into()),
                Ok(_) => {}
            }
            let withdrawal_utxo = withdrawal_utxo.expect("Failed to get withdrawal UTXO");
            let txid = withdrawal_utxo.txId.0;
            let txid =
                Txid::from_slice(txid.as_ref()).wrap_err("Failed to convert txid to Txid")?;
            let vout = withdrawal_utxo.outputId.0;
            let vout = u32::from_le_bytes(vout);
            let utxo = OutPoint { txid, vout };
            utxos.push((start_idx as u64, utxo));
            start_idx += 1;
        }
        Ok(utxos)
    }

    /// Sets the given payout txs' txid and operator index for the given index.
    pub async fn update_payout_txs_and_payer_operator_xonly_pk(
        &self,
        tx: Option<DatabaseTransaction<'_>>,
        payout_txs_and_payer_operator_xonly_pk: Vec<(
            u32,
            Txid,
            Option<XOnlyPublicKey>,
            bitcoin::BlockHash,
        )>,
    ) -> Result<(), BridgeError> {
        if payout_txs_and_payer_operator_xonly_pk.is_empty() {
            return Ok(());
        }
        // Convert all values first, propagating any errors
        let converted_values: Result<Vec<_>, BridgeError> = payout_txs_and_payer_operator_xonly_pk
            .iter()
            .map(|(idx, txid, operator_xonly_pk, block_hash)| {
                Ok((
                    i32::try_from(*idx).wrap_err("Failed to convert payout index to i32")?,
                    TxidDB(*txid),
                    operator_xonly_pk.map(XOnlyPublicKeyDB),
                    BlockHashDB(*block_hash),
                ))
            })
            .collect();
        let converted_values = converted_values?;

        let mut query_builder = QueryBuilder::new(
            "UPDATE withdrawals AS w SET
                payout_txid = c.payout_txid,
                payout_payer_operator_xonly_pk = c.payout_payer_operator_xonly_pk,
                payout_tx_blockhash = c.payout_tx_blockhash
                FROM (",
        );

        query_builder.push_values(
            converted_values.into_iter(),
            |mut b, (idx, txid, operator_xonly_pk, block_hash)| {
                b.push_bind(idx)
                    .push_bind(txid)
                    .push_bind(operator_xonly_pk)
                    .push_bind(block_hash);
            },
        );

        query_builder
            .push(") AS c(idx, payout_txid, payout_payer_operator_xonly_pk, payout_tx_blockhash) WHERE w.idx = c.idx");

        let query = query_builder.build();
        execute_query_with_tx!(self.connection, tx, query, execute)?;

        Ok(())
    }
