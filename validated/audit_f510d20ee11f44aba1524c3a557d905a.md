## Analog Found

### Title
Gasless swap-router's "sender must be EOA" flash-loan mitigation is a single, configurable mempool-time check that can be disabled or bypassed - (File: kaiax/gasless/config.go, kaiax/gasless/impl/tx_pool.go)

### Summary
Kaia's gasless module protects the `GaslessSwapRouter` settlement (`swapForGas`) from flash-loan/contract-based manipulation by rejecting senders "with code" — the same design pattern as Gro Protocol's `preventSmartContracts`/`switchEoaOnly()`. This protection is implemented as an optional, node-configurable check (`ShouldCheckSenderCode`), gated by `BalanceCheckLevel`, and is enforced only once, at transaction-pool admission time, rather than being re-validated against state at execution/inclusion time.

### Finding Description
The gasless module admits `approve`/`swapForGas` transactions into the bundle-tx pool via `GetCheckBalance()`, which calls `checkBalanceForApprove`/`checkBalanceForSwap`. Both functions gate the smart-contract-sender protection behind `g.GaslessConfig.ShouldCheckSenderCode()`: [1](#0-0) [2](#0-1) 

`ShouldCheckSenderCode()` returns true only when `BalanceCheckLevel >= BalanceCheckLevelAll`, and this level — along with all other balance/token checks — is a node-operator-configurable CLI flag (`gasless.balance-check-level`), not an immutable consensus rule: [3](#0-2) [4](#0-3) 

This mirrors exactly the pattern flagged in the external report: a single toggle (`BalanceCheckLevel`/`preventSmartContracts`) is the only barrier preventing smart-contract or code-bearing senders from interacting with a flash-loan-sensitive settlement path (the gasless swap that borrows KAIA from the block proposer via a synthetic `LendTx` and is repaid via `swapForGas`, priced by `GetAmountIn` from the DEX at execution time): [5](#0-4) 

Additionally, even when the check is enabled, it is performed once, at the moment the tx is checked for pool admission (`GetCheckBalance`), against `g.getCurrentHasCode(...)` at that block/state. There is no evidence in `IsExecutable`/`VerifyExecutable` (the function invoked right before bundling the `approve`+`swap`+synthetic `LendTx` into a block) that the sender-code check is re-run against the state as of actual inclusion: [6](#0-5) 
This creates the same category of risk described in the report — the "EOA-only" gate can be turned off by configuration, and independent of that, it is a point-in-time admission check rather than an execution-time invariant, so state changes between admission and inclusion (e.g., the account gaining code) are not re-checked.

### Impact Explanation
If `BalanceCheckLevel` is configured below `BalanceCheckLevelAll` (which is only a CLI default, not enforced by consensus), any contract account (or any account that later acquires code) can submit `approve`/`swapForGas` bundles. Because the gasless settlement price is computed live via `GetAmountIn` against the DEX pool and the module lends KAIA up front (before the swap is settled) via `GetLendTxGenerator`/`repayAmount`, a code-bearing sender could manipulate the DEX price atomically around its own swap (classic flash-loan sandwich) to under-repay the lender or extract value from the swap router, since the module explicitly relies on "sender is EOA" as its defense against this exact class of attack rather than any invariant enforced by the router contract itself.

### Likelihood Explanation
Medium. Exploitation requires either (a) a node operator/majority network configuration running with `BalanceCheckLevel < BalanceCheckLevelAll` (a supported, documented configuration, not merely a hypothetical), or (b) a race between admission-time state and inclusion-time state for a sender that acquires code (e.g., via an EIP-7702 SetCode transaction) between when the approve/swap bundle is validated for the pool and when it is actually assembled into a block by the same or another proposer. Both are plausible paths reachable from an ordinary transaction sender submitting an EIP-7702 SetCode tx plus a gasless approve/swap bundle, without needing any privileged role.

### Recommendation
Enforce the sender-code (and any other) check as a consensus-level invariant validated against the state at the moment of block assembly/execution (inside `VerifyExecutable`/`IsExecutable`), not merely at tx-pool admission gated by an operator-configurable flag. If the check must remain configurable, ensure `BalanceCheckLevelAll` (or at minimum the sender-code check) cannot be disabled without also disabling the entire gasless module, and re-validate `getCurrentHasCode` immediately before the `approve`+`swapForGas`+`LendTx` bundle is included in a block to close the TOCTOU window against EIP-7702/account-abstraction code changes occurring between mempool admission and block inclusion.

### Proof of Concept
1. Node operator (or default distribution) runs with `gasless.balance-check-level` set to `BalanceCheckLevelSwapAmount` (2) or lower — `ShouldCheckSenderCode()` returns `false`: [7](#0-6) 
2. Attacker deploys/controls a smart-contract account (or an EOA later upgraded via SetCode) and submits `approve(spender=GaslessSwapRouter, amount=MaxUint)` then `swapForGas(token, amountIn, minAmountOut, amountRepay, deadline)`.
3. `checkBalanceForApprove`/`checkBalanceForSwap` skip the "sender with code is not allowed" check entirely: [1](#0-0) 
4. The bundle is admitted, promoted (`IsReady`/`isSwapTxReady`), and executed with the proposer lending KAIA up front and being repaid based on live DEX pricing via `GetAmountIn`, allowing a contract-based sender to manipulate the DEX price around its own swap (the exact "flash loan manipulation" scenario the sender-code check exists to prevent), as confirmed by the existing regression test that only exercises this defense when the check is active: [8](#0-7)

func (g *GaslessModule) checkBalanceForSwap(swapArgs *SwapArgs, swapNonce uint64) error {
	token := swapArgs.Token
	bc := backends.NewBlockchainContractBackend(g.Chain, nil, nil)

	g.gaslessInfoMu.RLock()
	swapRouter := g.swapRouter
	g.gaslessInfoMu.RUnlock()

	// tx.minAmountOut >= tx.amountRepay
	minAmountOut := swapArgs.MinAmountOut
	amountRepay := swapArgs.AmountRepay
	if minAmountOut.Cmp(amountRepay) < 0 {
		return fmt.Errorf("insufficient minAmountOut: minAmountOut=%s, amountRepay=%s", minAmountOut.String(), amountRepay.String())
	}

	if g.GaslessConfig.ShouldCheckSenderCode() {
		if g.getCurrentHasCode(swapArgs.Sender) {
			return errors.New("sender with code is not allowed")
		}
	}

	if g.GaslessConfig.ShouldCheckSwapAmount() {
		// tx.amountIn >= gsr.getAmountIn(minAmountOut)
		routerContract, err := kip247.NewGaslessSwapRouterCaller(swapRouter, bc)
		if err != nil {
			return err
		}
		// Required token amountIn, given the current exchange rate and the declared minAmountOut.
		requiredAmountIn, err := routerContract.GetAmountIn(nil, token, minAmountOut)
		if err != nil {
			return err
		}
		if swapArgs.AmountIn.Cmp(requiredAmountIn) < 0 {
			return fmt.Errorf("insufficient amountIn: have=%s, want=%s", swapArgs.AmountIn.String(), requiredAmountIn.String())
		}
	}

func (g *GaslessModule) VerifyExecutable(approveTxOrNil, swapTx *types.Transaction) error {
	// Sx.
	swapArgs, ok := decodeSwapTx(swapTx, g.signer)
	if !ok {
		return ErrDecodeSwapTx
	}
	if !g.isSwapTx(swapArgs) {
		return ErrSwapTxInvalid
	}

	// Conditions involving ApproveTx
	if approveTxOrNil != nil {
		// Ax.
		approveArgs, ok := decodeApproveTx(approveTxOrNil, g.signer)
		if !ok {
			return ErrDecodeApproveTx
		}
		if !g.isApproveTx(approveArgs) {
			return ErrApproveTxInvalid
		}
		// AP1.
		if approveArgs.Sender != swapArgs.Sender {
			return ErrDifferentSenders
		}
		// SP1.
		if approveArgs.Token != swapArgs.Token {
			return fmt.Errorf("%w: approve token %s, swap token %s", ErrDifferentTokens, approveArgs.Token.Hex(), swapArgs.Token.Hex())
		}
		// SP2.
		if approveArgs.Amount.Cmp(swapArgs.AmountIn) < 0 {
			return fmt.Errorf("%w: approve amount %s, required amount %s", ErrInsufficientApproveAmount, approveArgs.Amount.String(), swapArgs.AmountIn.String())
		}
		// SP3.
		if approveTxOrNil.Nonce()+1 != swapTx.Nonce() {
			return fmt.Errorf("%w: approve nonce %d, swap nonce %d (expected %d)", ErrNonSequentialNonce, approveTxOrNil.Nonce(), swapTx.Nonce(), approveTxOrNil.Nonce()+1)
		}
		if nonce := g.getCurrentStateNonce(approveArgs.Sender); nonce != approveTxOrNil.Nonce() {
			return fmt.Errorf("%w: approve nonce %d, current nonce %d", ErrApproveNonceNotCurrent, approveTxOrNil.Nonce(), nonce)
		}
	} else {
		// SP3.
		if nonce := g.getCurrentStateNonce(swapArgs.Sender); nonce != swapTx.Nonce() {
			return fmt.Errorf("%w: swap nonce %d, current nonce %d", ErrSwapNonceNotCurrent, swapTx.Nonce(), nonce)
		}
	}

	// SP4.
	if swapArgs.AmountRepay.Cmp(repayAmount(approveTxOrNil, swapTx)) != 0 {
		return fmt.Errorf("%w: got %s, expected %s", ErrIncorrectRepayAmount, swapArgs.AmountRepay.String(), repayAmount(approveTxOrNil, swapTx).String())
	}

	return nil
}
