## Analysis

The Fei GenesisGroup issue is a case where a contract's internal accounting logic trusts a *forced* balance value (`address(this).balance`, corruptible via `SELFDESTRUCT`) instead of tracking deposits through its own accounting path (`purchase`), leading to permanently stuck funds. The Cosmos EVM analog exists in how `x/vm`'s StateDB reconciles native-token balance changes with `x/bank`, combined with the fact that precompiled contract addresses have no private key and only ever "spend" their own balance in response to `contract.Value()` of the *current* call, never their standing account balance.

Key facts gathered:
- Every dirty (non-self-destructed) EVM account is flushed through `Keeper.SetAccount` → `Keeper.SetBalance`, which computes `delta = target_uint256_balance - current_bank_balance` and **mints** the difference directly to that address's Cosmos account if positive. [1](#0-0) [2](#0-1) 
- `SELFDESTRUCT` credits the beneficiary purely via `StateDB.AddBalance`, which only touches the in-memory `stateObject` (journaled), with no invocation of the beneficiary's contract logic at all. [3](#0-2) 
- The WERC20 precompile's `Deposit`/`Withdraw` methods only ever act on `contract.Value()` (the value sent in the *current* call) — they never read or forward the precompile's own standing bank/EVM balance, and `Withdraw` is documented as an intentional no-op. [4](#0-3) 
- Normal deposit flow forces a `CommitWithCacheCtx()` *before* the precompile body executes precisely so that value transferred in via the CALL is reflected in `x/bank` before `Deposit` calls `SendCoins`; this reconciliation logic only runs for genuine precompile calls, not for a beneficiary that merely receives a forced `SELFDESTRUCT` transfer. [5](#0-4) 

### Title
Unauthorized native-token minting and permanent fund lock via `SELFDESTRUCT`-forced value transfer to precompile addresses - (File: x/vm/keeper/statedb.go, x/vm/statedb/statedb.go, precompiles/werc20/tx.go)

### Summary
Any EVM account can be forced to receive value via `SELFDESTRUCT` without executing any of its code (this is standard EVM semantics). In this repository, however, an account's EVM balance is *not* merely an accounting number — it is authoritative over the real `x/bank` balance: at commit time, `Keeper.SetBalance` mints new native coins to make the bank balance match the (forced) EVM balance. Precompile addresses (e.g. WERC20 at a fixed address) have no private key and no logic that can ever spend from their own standing balance — `Deposit`/`Withdraw` only operate on the value of the *current* call. An attacker can deploy a throwaway contract, fund it, and `SELFDESTRUCT` it with the precompile address as beneficiary, forcing the chain to mint new native coins into an address that can never spend them again.

### Finding Description
1. Attacker deploys a minimal contract, funds it with native token (paid for through a normal EVM transfer), then calls `SELFDESTRUCT(precompileAddress)`.
2. The EVM interpreter's `SELFDESTRUCT` opcode handling calls `StateDB.AddBalance(precompileAddress, balance, ...)`, which simply increases the in-memory `stateObject` balance of the precompile address and marks it dirty in the journal — no precompile `Run`/`Execute` logic executes for the beneficiary. [3](#0-2) 
3. At the end of the transaction, `StateDB.Commit()` iterates dirty accounts and, since the precompile address is not itself self-destructed, calls `keeper.SetAccount` → `keeper.SetBalance`. [6](#0-5) 
4. `SetBalance` computes the delta between the (forced) target uint256 balance and the actual current spendable bank coin balance of that Cosmos address and **mints** the shortfall via `bankWrapper.MintAmountToAccount`. [1](#0-0) 
5. The precompile address now legitimately owns real, newly minted native coins in `x/bank`. However, no code path exists that can move funds out of the precompile's own account: `Deposit`/`Withdraw` never read the precompile's own bank/EVM balance, only `contract.Value()` for the active call, and there is no signer/private key that can originate a transaction "from" the precompile address. [4](#0-3) 
6. This differs fundamentally from a normal `deposit()` call, where `CommitWithCacheCtx()` is invoked *before* the precompile body runs specifically to flush the pending balance change to `x/bank` so that `Deposit`'s subsequent `SendCoins` call succeeds and returns funds to the sender in the same transaction. [5](#0-4) That reconciliation/return path simply never runs when the transfer originates from `SELFDESTRUCT` rather than a `CALL` into the precompile.

This is structurally the same failure mode as the Fei GenesisGroup bug: an accounting mechanism (`SetBalance`'s mint-to-match logic) trusts a state value (`stateObject.Balance()`) that can be manipulated via `SELFDESTRUCT` outside of the intended deposit/purchase code path, and the result is unrecoverable value.

### Impact Explanation
This satisfies the Critical impact gate on two overlapping grounds:
- **Unauthorized minting / irreversible accounting corruption**: `SetBalance` mints brand-new native coins into a Cosmos account purely because a forced EVM balance value increased, without going through any legitimate mint-authorizing flow (e.g., a real deposit or IBC transfer). This inflates the on-chain circulating supply in `x/bank` for a value that has no genuine backing transaction.
- **Permanent freezing/locking of funds**: Since the destination is a precompile address with no owning key and no sweep-out logic, the minted coins are permanently unspendable — a real, user-triggerable, irreversible loss of value from the system, achievable by any unprivileged account.

### Likelihood Explanation
The attack requires only: (1) deploying an ordinary contract, (2) funding it with native token via a standard transfer, and (3) invoking `SELFDESTRUCT` with a precompile address as beneficiary — all standard, unprivileged EVM operations available to any user with minimal gas. No special permissions, validator collusion, or race conditions are required.

### Recommendation
- In `Keeper.SetBalance`/`Keeper.SetAccount` (`x/vm/keeper/statedb.go`), reject or safely reroute balance increases targeting registered precompile addresses (the precompile registry is already available to the EVM keeper), since precompiles should never organically hold a spendable native balance outside of a single call's `contract.Value()`.
- Alternatively/additionally, ensure `SELFDESTRUCT` beneficiary transfers targeting precompile addresses are disallowed at the EVM level (mirroring how normal Ethereum implementations already special-case precompiles for other operations), or have `DeleteAccount`/`Commit` refund such forced transfers back to the corresponding bank module/burn address rather than minting new supply that becomes unspendable.

### Proof of Concept
1. Deploy `Forwarder` contract:
```solidity
contract Forwarder {
    function kill(address payable target) external payable {
        selfdestruct(target);
    }
}
```
2. Call `Forwarder.kill{value: X}(WERC20_PRECOMPILE_ADDRESS)`.
3. Observe: `Keeper.SetBalance` (`x/vm/keeper/statedb.go:111-136`) mints `X` in native coin to the precompile's Cosmos account (`sdk.AccAddress(WERC20_PRECOMPILE_ADDRESS.Bytes())`), confirmable via `x/bank`'s `GetBalance` query for that address.
4. Confirm no method exists (`Deposit`, `Withdraw`, or any other) that reads or forwards the precompile's own standing balance — `precompiles/werc20/tx.go:26-80` — meaning the minted `X` is permanently unspendable.

// SetBalance update account's balance, compare with current balance first, then decide to mint or burn.
func (k *Keeper) SetBalance(ctx sdk.Context, addr common.Address, amount *uint256.Int) error {
	if amount == nil {
		return nil
	}
	cosmosAddr := sdk.AccAddress(addr.Bytes())
	coin := k.bankWrapper.SpendableCoin(ctx, cosmosAddr, types.GetEVMCoinDenom())

	balance := coin.Amount.BigInt()
	delta := new(big.Int).Sub(amount.ToBig(), balance)
	switch delta.Sign() {
	case 1:
		// mint
		if err := k.bankWrapper.MintAmountToAccount(ctx, cosmosAddr, delta); err != nil {
			return err
		}
	case -1:
		// burn
		if err := k.bankWrapper.BurnAmountFromAccount(ctx, cosmosAddr, new(big.Int).Neg(delta)); err != nil {
			return err
		}
	default:
		// not changed
	}
	return nil
}

// SelfDestruct marks the given account as self-destructed.
// This clears the account balance.
//
// The account's state object is still available until the state is committed,
// getStateObject will return a non-nil account after SelfDestruct.
func (s *StateDB) SelfDestruct(addr common.Address) uint256.Int {
	stateObject := s.getStateObject(addr)
	var prevBalance uint256.Int
	if stateObject == nil {
		return prevBalance
	}
	prevBalance = *(stateObject.Balance())
	s.journal.append(selfDestructChange{
		account:     &addr,
		prev:        stateObject.selfDestructed,
		prevbalance: new(uint256.Int).Set(stateObject.Balance()),
	})
	stateObject.markSelfDestructed()
	stateObject.account.Balance = new(uint256.Int)
	return prevBalance
}

// Commit writes the dirty states to keeper
// the StateDB object should be discarded after committed.
func (s *StateDB) Commit() error {
	// writeCache func will exist only when there's a call to a precompile.
	// It applies all the store updates preformed by precompile calls.
	if s.writeCache != nil {
		s.writeCache()
	}
	return s.commitWithCtx(s.ctx)
}

// CommitWithCacheCtx writes the dirty states to keeper using the cacheCtx.
// This function is used before any precompile call to make sure the cacheCtx
// is updated with the latest changes within the tx (StateDB's journal entries).
func (s *StateDB) CommitWithCacheCtx() error {
	return s.commitWithCtx(s.cacheCtx)
}

// commitWithCtx writes the dirty states to keeper
// using the provided context
func (s *StateDB) commitWithCtx(ctx sdk.Context) error {
	for _, addr := range s.journal.sortedDirties() {
		obj := s.stateObjects[addr]
		if obj.selfDestructed {
			if err := s.keeper.DeleteAccount(ctx, obj.Address()); err != nil {
				return errorsmod.Wrapf(err, "failed to delete account %s", obj.Address())
			}
		} else {
			if obj.code != nil && obj.dirtyCode {
				if len(obj.code) == 0 {
					s.keeper.DeleteCode(ctx, obj.CodeHash())
				} else {
					s.keeper.SetCode(ctx, obj.CodeHash(), obj.code)
				}
			}
			if err := s.keeper.SetAccount(ctx, obj.Address(), obj.account); err != nil {
				return errorsmod.Wrap(err, "failed to set account")
			}

			for _, key := range obj.dirtyStorage.SortedKeys() {
				valueBytes := obj.dirtyStorage[key].Bytes()
				if len(valueBytes) == 0 {
					s.keeper.DeleteState(ctx, obj.Address(), key)
				} else {
					s.keeper.SetState(ctx, obj.Address(), key, valueBytes)
				}
			}
		}
	}
	return nil

// Deposit handles the payable deposit function. It retrieves the deposited amount
// and sends it back to the sender using the bank keeper.
func (p Precompile) Deposit(
	ctx sdk.Context,
	contract *vm.Contract,
	stateDB vm.StateDB,
) ([]byte, error) {
	caller := contract.Caller()
	depositedAmount := contract.Value()

	callerAccAddress := sdk.AccAddress(caller.Bytes())
	precompileAccAddr := sdk.AccAddress(p.Address().Bytes())

	// Send the coins back to the sender
	if err := p.BankKeeper.SendCoins(
		ctx,
		precompileAccAddr,
		callerAccAddress,
		sdk.NewCoins(sdk.Coin{
			Denom:  evmtypes.GetEVMCoinExtendedDenom(),
			Amount: math.NewIntFromBigInt(depositedAmount.ToBig()),
		}),
	); err != nil {
		return nil, err
	}

	if err := p.EmitDepositEvent(ctx, stateDB, caller, depositedAmount.ToBig()); err != nil {
		return nil, err
	}

	return nil, nil
}

// Withdraw is a no-op and mock function that provides the same interface as the
// WETH contract to support equality between the native coin and its wrapped
// ERC-20 (e.g. ATOM and WEVMOS).
func (p Precompile) Withdraw(ctx sdk.Context, contract *vm.Contract, stateDB vm.StateDB, args []interface{}) ([]byte, error) {
	amount, ok := args[0].(*big.Int)
	if !ok {
		return nil, fmt.Errorf("invalid argument type: %T", args[0])
	}
	amountInt := math.NewIntFromBigInt(amount)

	caller := contract.Caller()
	callerAccAddress := sdk.AccAddress(caller.Bytes())
	nativeBalance := p.BankKeeper.SpendableCoin(ctx, callerAccAddress, evmtypes.GetEVMCoinDenom())
	if nativeBalance.Amount.Mul(types.ConversionFactor()).LT(amountInt) {
		return nil, fmt.Errorf("account balance %v is lower than withdraw balance %v", nativeBalance.Amount, amountInt)
	}

	if err := p.EmitWithdrawalEvent(ctx, stateDB, caller, amount); err != nil {
		return nil, err
	}
	return nil, nil
}

func (p Precompile) runNativeAction(evm *vm.EVM, contract *vm.Contract, action NativeAction) (bz []byte, err error) {
	stateDB, ok := evm.StateDB.(*statedb.StateDB)
	if !ok {
		return nil, errors.New(ErrNotRunInEvm)
	}

	// get the stateDB cache ctx
	ctx, err := stateDB.GetCacheContext()
	if err != nil {
		return nil, err
	}

	// take a snapshot of the current state before any changes
	// to be able to revert the changes
	snapshot := stateDB.MultiStoreSnapshot()
	events := ctx.EventManager().Events()

	// add precompileCall entry on the stateDB journal
	// this allows to revert the changes within an evm tx
	if err := stateDB.AddPrecompileFn(snapshot, events); err != nil {
		return nil, err
	}

	// commit the current changes in the cache ctx
	// to get the updated state for the precompile call
	if err := stateDB.CommitWithCacheCtx(); err != nil {
		return nil, err
	}
