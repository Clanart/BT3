## Analysis

The report's broken invariant is: an authorization/identity check is performed against the **wrong actor** (`msg.sender`, the caller) instead of the **actual beneficiary of the action** (`_receiver`), letting an attacker-controlled parameter silently substitute for the checked identity and bypass a security-relevant match.

The closest Desktop analog is in `getRepositoryFromPullRequest` / `openPullRequestFromUrl` in `app/src/ui/dispatcher/dispatcher.ts`. This path is triggered by an **unprivileged, attacker-influenced GitHub API object** (a Pull Request opened by anyone on any repository) reached via the `x-github-client://openRepo/...?pr=NNN` deep link — a link a user can be induced to click.

### Title
Deep-link PR checkout selects and mutates local repository based on attacker-controlled PR `head`/`base` clone URLs - (File: app/src/ui/dispatcher/dispatcher.ts)

### Summary
`openPullRequestFromUrl` fetches a pull request object from the API using attacker-supplied `url`/`pr` deep-link parameters, then uses fields from that PR object (`head.repo.clone_url`, `base.repo.clone_url` — both attacker-controlled, since anyone can open a PR with any head fork) to decide (a) which of the user's *already open, unrelated* local repositories to reuse via `getRepositoryFromPullRequest`/`doesRepositoryMatchUrl`, and (b) which remote URL to add and fetch/checkout into that repository via `_checkoutPullRequest`.

### Finding Description
`getRepositoryFromPullRequest` at [1](#0-0)  iterates over every currently-open local repository and matches it against `pullRequest.head.repo.clone_url` or `pullRequest.base.repo.clone_url` using `doesRepositoryMatchUrl`, which compares only hostname/owner/name via `urlsMatch` [2](#0-1) . Both `head` and `base` repo URLs come directly from the PR JSON returned by the GitHub API for the `pr` number supplied in the deep link — an object fully controllable by any GitHub user who opens a PR (including a PR whose `base` repo is the user's own public/forked project) at [3](#0-2) .

Once a matching local repository is found, `_checkoutPullRequest` is invoked with `pullRequest.head.repo.clone_url` (attacker-controlled fork URL) and `pullRequest.head.ref` (attacker-controlled branch name) [4](#0-3) . Inside `_findPullRequestBranch`, if no existing remote matches, Desktop silently runs `addRemote(repository, forkRemoteName, headCloneUrl)` and fetches it into the user's local repository, then checks out the fetched ref as `pr/{number}` [5](#0-4) .

This mirrors the report's bug class: the code performs its "is this the right repository/right actor" check against a value taken from the untrusted, attacker-supplied object (`pullRequest.head`/`base` clone URLs) rather than against something scoped to what the user actually opened or intended (e.g., the deep link's own `url` parameter, or requiring the PR's base repo to equal the URL the user clicked through). Similar to `msg.sender` vs `_receiver`, the identity used for the match/authorization-adjacent decision (which repo to operate on) is not the one the user actually intends — it is attacker-supplied.

### Impact Explanation
An attacker can craft a deep link (`x-github-client://openRepo/<attacker-or-victim-repo-url>?pr=<attacker-PR-number>`) pointing to a PR the attacker fully controls the `head` fork/branch of. If the victim has any locally open repository whose `origin`/`upstream` matches the PR's `head` or `base` clone URL (a very broad match — any fork relationship, or simply the victim already having that exact GitHub repo open), Desktop will silently add a new remote and fetch/checkout attacker-chosen commits into that working directory without confirmation beyond the initial click. This can plant attacker-controlled files/build scripts/hooks into a repository the victim trusts, potentially leading to code execution via build tooling, pre-commit hooks, or IDE auto-run features once the branch is checked out.

### Likelihood Explanation
Likelihood is high: opening arbitrary pull requests against any public repository is unprivileged and free, deep links are commonly clicked from browsers/chat/email, and the matching logic in `doesRepositoryMatchUrl`/`urlsMatch` only requires hostname+owner+name equality, not any confirmation that this is the PR the user meant to open or that the head repo is trusted.

### Recommendation
Do not select or mutate a local repository based on fields taken from the fetched PR object alone. Validate that the deep link's own `url` parameter (the URL the user is presumed to trust) matches the repository being opened before using `pullRequest.head`/`base` for remote/fetch operations, and require explicit user confirmation before adding a new remote and checking out a fork branch fetched via a protocol-handler-initiated flow, rather than doing so silently.

### Proof of Concept
1. Attacker opens a public repository `victim/project` (or any repo the target already has cloned) and forks it, pushing a branch containing a malicious `.vscode/tasks.json`, `Makefile`, or git hook.
2. Attacker opens a PR from their fork's branch against `victim/project`.
3. Attacker sends the victim a link: `x-github-client://openRepo/https://github.com/victim/project?pr=<PR#>`.
4. Victim (who already has `victim/project` cloned in Desktop) clicks the link.
5. `openPullRequestFromUrl` → `getRepositoryFromPullRequest` matches the victim's existing local repo via `base.repo.clone_url`, then `_checkoutPullRequest` adds the attacker's fork as a remote and checks out the attacker's branch as `pr/<PR#>` into the victim's working directory without further confirmation dialogs beyond the initial protocol-handler prompt.

**Uncertainty**: I could not confirm from the indexed code alone whether the OS/Electron shows an additional "Open in GitHub Desktop?" confirmation dialog before `handleAppURL` is invoked, which could reduce (but not eliminate) the practical likelihood — this would need to be verified in a full Devin session with access to `app/src/main-process/main.ts` and related protocol-registration code in full.

  private getRepositoryFromPullRequest(
    pullRequest: IAPIPullRequest
  ): RepositoryWithGitHubRepository | null {
    const state = this.appStore.getState()
    const repositories = state.repositories
    const headUrl = pullRequest.head.repo?.clone_url
    const baseUrl = pullRequest.base.repo?.clone_url

    // This likely means that the base repository has been deleted
    // and we don't support checking out from refs/pulls/NNN/head
    // yet so we'll bail for now.
    if (headUrl === undefined || baseUrl === undefined) {
      return null
    }

    for (const repository of repositories) {
      if (this.doesRepositoryMatchUrl(repository, headUrl)) {
        return repository
      }
    }

    for (const repository of repositories) {
      if (this.doesRepositoryMatchUrl(repository, baseUrl)) {
        return repository
      }
    }

    return null
  }

  private doesRepositoryMatchUrl(
    repo: Repository | CloningRepository,
    url: string
  ): repo is RepositoryWithGitHubRepository {
    if (repo instanceof Repository && isRepositoryWithGitHubRepository(repo)) {
      const originRepoUrl = repo.gitHubRepository.htmlURL
      const upstreamRepoUrl = repo.gitHubRepository.parent?.htmlURL ?? null

      if (originRepoUrl !== null && urlsMatch(originRepoUrl, url)) {
        return true
      }

      if (upstreamRepoUrl !== null && urlsMatch(upstreamRepoUrl, url)) {
        return true
      }
    }

    return false
  }

  public async _findPullRequestBranch(
    repository: RepositoryWithGitHubRepository,
    prNumber: number,
    headRepoOwner: string,
    headCloneUrl: string,
    headRefName: string
  ): Promise<Branch | undefined> {
    const gitStore = this.gitStoreCache.get(repository)
    const remotes = await getRemotes(repository)

    // Find an existing remote (regardless if set up by us or outside of
    // Desktop).
    let remote = remotes.find(r => urlMatchesRemote(headCloneUrl, r))

    // If we can't find one we'll create a Desktop fork remote.
    if (remote === undefined) {
      try {
        const forkRemoteName = forkPullRequestRemoteName(headRepoOwner)
        remote = await addRemote(repository, forkRemoteName, headCloneUrl)
      } catch (e) {
        this.emitError(
          new Error(
            `Couldn't find PR branch, adding remote failed: ${e.message}`
          )
        )
        return
      }
    }

    const remoteRef = `${remote.name}/${headRefName}`

    // Start by trying to find a local branch that is tracking the remote ref.
    let existingBranch = gitStore.allBranches.find(
      x => x.type === BranchType.Local && x.upstream === remoteRef
    )

    // If we found one, let's check it out and get out of here, quick
    if (existingBranch !== undefined) {
      return existingBranch
    }

    const findRemoteBranch = (name: string) =>
      gitStore.allBranches.find(
        x => x.type === BranchType.Remote && x.name === name
      )

    // No such luck, let's see if we can at least find the remote branch then
    existingBranch = findRemoteBranch(remoteRef)

    // It's quite possible that the PR was created after our last fetch of the
    // remote so let's fetch it and then try again.
    if (existingBranch === undefined) {
      try {
        await this._fetchRemote(repository, remote, FetchType.UserInitiatedTask)
        existingBranch = findRemoteBranch(remoteRef)
      } catch (e) {
        log.error(`Failed fetching remote ${remote?.name}`, e)
      }
    }

    if (existingBranch === undefined) {
      this.emitError(
        new Error(
          `Couldn't find branch '${headRefName}' in remote '${remote.name}'. ` +
            `A common reason for this is that the PR author has deleted their ` +
            `branch or their forked repository.`
        )
      )
      return
    }

    // For fork remotes we checkout the ref as pr/[123] instead of using the
    // head ref name since many PRs from forks are created from their default
    // branch so we'll have a very high likelihood of a conflicting local branch
    const isForkRemote =
      remote.name !== gitStore.defaultRemote?.name &&
      remote.name !== gitStore.upstreamRemote?.name

    if (isForkRemote) {
      return await this._createBranch(
        repository,
        `pr/${prNumber}`,
        remoteRef,
        false
      )
    }

    return existingBranch
  }
