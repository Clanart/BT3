### Title
Pointer precompile's `addCW20Pointer`/`addCW721Pointer`/`addCW1155Pointer` bypass the `RegisterPointerDisabled` admin switch enforced on the equivalent `MsgRegisterPointer` Cosmos message - (File: `precompiles/pointer/pointer.go`)

### Summary
`x/evm`'s `MsgRegisterPointer` handler checks the global `RegisterPointerDisabled` param before creating a CW→ERC pointer, but the EVM-side `pointer` precompile (address `0x...100b`), which performs the mirror-image ERC→CW pointer registration, never checks this flag. Any EVM caller can therefore register ERC20/ERC721/ERC1155→CW pointers through the precompile even after governance/admin has disabled pointer registration on the chain.

### Finding Description
`x/evm/keeper/msg_server.go`'s `RegisterPointer` explicitly gates on the admin-controlled param: [1](#0-0) 

This param is set via `MigrateDisableRegisterPointer`, i.e. it's a real, deliberately-introduced governance/ops kill switch for pointer creation: [2](#0-1) 

The `pointer` precompile, however, dispatches straight to `AddCW20`/`AddCW721`/`AddCW1155` without ever consulting `RegisterPointerDisabled` (or any equivalent check) — its only guards are `readOnly` and delegatecall rejection: [3](#0-2) [4](#0-3) 

This is architecturally identical to the Open WebUI bug: two code paths implement the same privileged capability (pointer registration between the CW and EVM worlds), one enforces the admin-controlled disable switch, the other — reachable directly by an ordinary EVM transaction sender — does not.

### Impact Explanation
If an operator disables pointer registration (`RegisterPointerDisabled = true`) — e.g., to freeze the pointer registry during an incident, migration, or to stop a class of contracts from acquiring CW-backed pointers — any unprivileged EVM account can still call the `pointer` precompile's `addCW20Pointer`/`addCW721Pointer`/`addCW1155Pointer` methods to create new ERC↔CW pointer mappings, fully bypassing the administrative control. This undermines the safety mechanism the flag was introduced for and lets untrusted callers keep creating pointer contracts (with associated `evm.Create` deployment and state-mapping side effects) against operator intent.

### Likelihood Explanation
High reachability: `addCW20Pointer`/`addCW721Pointer`/`addCW1155Pointer` are ordinary EVM precompile calls reachable via any transaction or `eth_call`/contract call to `0x...100b`, requiring only a valid CW20/CW721/CW1155 contract address as an argument — no special permission, association state, or governance action needed by the attacker.

### Recommendation
Add the same `RegisterPointerDisabled` (or an equivalent explicit gate) check to `PrecompileExecutor.AddCW20`, `AddCW721`, and `AddCW1155` in `precompiles/pointer/pointer.go` before proceeding to `evm.Create`/`UpsertERCCW*Pointer`, mirroring the check already present in `x/evm/keeper/msg_server.go`'s `RegisterPointer`. Centralize the check (e.g., in a shared helper called by both the precompile and the msg server) so future pointer-direction additions can't silently regress this control again.

### Proof of Concept
1. Chain admin/governance sets `RegisterPointerDisabled = true` (e.g., via `MigrateDisableRegisterPointer` or a param-change proposal), intending to block all further CW↔EVM pointer creation.
2. Confirm the Cosmos path is blocked: submitting `MsgRegisterPointer` for a CW20 contract returns `"registering CW->ERC pointers has been disabled"` per `x/evm/keeper/msg_server.go` lines 249–251.
3. As any unprivileged EVM account, call the `pointer` precompile at `0x000000000000000000000000000000000000100b` method `addCW20Pointer(cwAddr)` (or `addCW721Pointer`/`addCW1155Pointer`) for a live CW20/CW721/CW1155 contract.
4. Observe the call succeeds and deploys a new ERC pointer contract via `p.evmKeeper.UpsertERCCW20Pointer` (`precompiles/pointer/pointer.go` lines 134–163), despite `RegisterPointerDisabled` being set — demonstrating the precompile path bypasses the same administrative switch the Cosmos message enforces.

	if err != nil {
		return nil, 0, err

	if err := json.Unmarshal(res, &formattedRes); err != nil {

		return nil, 0, err
	}

	remainingGas = pcommon.GetRemainingGas(ctx, p.evmKeeper)
	return
