Based on my research, I found a genuine analog: `VCProofs.from_program()` in `chia/wallet/vc_wallet/vc_store.py` performs unbounded Python-level tree recursion over an attacker-influenced CLVM `Program`, exactly matching the "compose/resolve phase recursion without depth bound" bug class from the `yaml` advisory.

### Title
Unbounded recursion in `VCProofs.from_program()` causes RecursionError on deeply nested VC proof data - (File: chia/wallet/vc_wallet/vc_store.py)

### Summary
`VCProofs.from_program()` recursively walks a CLVM `Program` tree with no depth limit, mirroring the `yaml` compose-phase bug: a small, deeply-nested payload can exhaust the Python call stack and raise an uncaught `RecursionError` instead of a handled/expected exception type.

### Finding Description
`VCProofs.from_program()` recurses on `first`/`rest` whenever neither side is an atom, with no depth bound and no CLVM cost accounting: [1](#0-0) 

This program is untrusted, attacker-influenced data: it is the "VC proofs" tree associated with a Verified Credential, stored/retrieved via `VCStore.get_proofs_for_root()`, which deserializes it straight from stored bytes with `Program.from_bytes()`: [2](#0-1) 

The proofs program's *shape* (not just leaf content) is attacker/provider-controlled — a VC issuer (or anyone able to get a VC/CR-CAT credential accepted by a wallet, e.g. via `VerifiedCredential.get_next_from_coin_spend()` parsing spend data from the chain) can construct a proofs tree that is deeply left/right nested (e.g. thousands of `(a . (b . (c . ...)))` levels) while remaining tiny in byte size — the same "2 bytes per level" style compactness noted in the `yaml` advisory. `Program.at()`/`.first()`/`.rest()` calls used here have no recursion-depth guard, unlike `sha256_treehash()` in `chia/types/blockchain_format/tree_hash.py`, which was deliberately made iterative specifically to avoid "blowing out the python stack" on deeply nested CLVM data: [3](#0-2) 

`VCProofs.prove_keys()` has the identical unbounded-recursion pattern operating on the same untrusted tree: [4](#0-3) 

### Impact Explanation
A crafted VC proofs program can trigger a Python `RecursionError` deep inside wallet VC-sync/DB code. Because callers (`VCStore`, `VCWallet`, RPC handlers) generally catch specific exception types (`ValueError`, DB errors, etc.) rather than `BaseException`/`RecursionError`, this can propagate up and halt wallet processing of VC-related coin state (a spend-triggered transaction-processing halt for the wallet consuming VC data), analogous to the `yaml` `RangeError` bypassing `YAMLParseError`-only handlers. This is scoped to the wallet DID/VC/CR-CAT flow (in-scope per the reachable-path list: "NFT/DID ownership", "CAT/CR-CAT/VC flow").

### Likelihood Explanation
Reaching this code requires a VC/CR-CAT credential (proofs tree) to be processed by a wallet — this is a normal flow for wallet users interacting with Verified Credentials issued by a counterparty/provider, or a local RPC caller supplying proofs. The attacker only needs to control the shape of the CLVM proofs tree, which is cheap to construct (small serialized size, similar to the YAML PoC's 2–10 KB triggering thousands of nesting levels). No signature or special privilege is needed to construct such a tree.

### Recommendation
Bound recursion depth (or convert to an iterative stack-based walk, as already done for `sha256_treehash()`) in `VCProofs.from_program()` and `VCProofs.prove_keys()`; reject/limit CLVM proof trees whose nesting exceeds a sane maximum before recursive processing, and ensure callers catch `RecursionError` (or avoid it entirely via iteration) so malformed/hostile VC proof data cannot halt wallet processing.

### Proof of Concept
Conceptually (mirroring the yaml PoC's ~5000-level nested flow-sequence construction), build a CLVM program `(k1 . (k2 . (k3 . ... (kn . atom) ...)))` with deep left-nesting (or a fully skewed cons chain) as the encoded VC proofs bytes, store/return it via `VCStore.get_proofs_for_root()` (or embed it in an on-chain VC coin spend consumed by `VerifiedCredential`/`VCProofs` sync code), and call `VCProofs.from_program(Program.from_bytes(payload))`. With enough nesting depth (on the order of Python's default recursion limit, ~1000, well within a few KB), this raises an uncaught `RecursionError` rather than a handled `ValueError`.

Note: I could not fully verify the exact end-to-end call chain proving this is reachable purely from an unauthenticated network-received coin spend (vs. requiring the local wallet owner to already hold/process the VC), since some of the VC ingestion code paths in `chia/wallet/vc_wallet/vc_wallet.py` were not fully inspected due to tool-call budget constraints — a Devin session with full repo access should trace `VerifiedCredential.get_next_from_coin_spend()` and `VCWallet` sync handlers to confirm whether a purely on-chain, attacker-submitted spend bundle (no cooperating local wallet action) can reach `VCProofs.from_program()`.

    def from_program(prog: Program) -> VCProofs:
        first: Program = prog.at("f")
        rest: Program = prog.at("r")
        if first.atom is None and rest.atom is None:
            final_dict: dict[str, str] = {}

    def prove_keys(self, keys: list[str], tree: Program | None = None) -> Program:
        if tree is None:
            tree = self.as_program()

        first = tree.first()
        if first.atom is not None:
            if first.atom.decode("utf8") in keys:
                return tree
            else:
                tree_hash_as_atom: Program = Program.to(tree.get_tree_hash())
                return tree_hash_as_atom
        else:
            rest = tree.rest()
            first_tree = self.prove_keys(keys, first)
            rest_tree = self.prove_keys(keys, rest)
            if first_tree.atom is not None and rest_tree.atom is not None:
                tree_hash_as_atom = Program.to(
                    Program.to((first_tree, rest_tree)).get_tree_hash_precalc(
                        bytes32(first_tree.atom), bytes32(rest_tree.atom)
                    )
                )
                return tree_hash_as_atom
            else:
                new_tree: Program = first_tree.cons(rest_tree)
                return new_tree
