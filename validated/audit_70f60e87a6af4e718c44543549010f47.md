### Title
ReDoS via attacker-controlled hookify rule regex patterns evaluated on every tool call without timeout - ([File: plugins/hookify/core/rule_engine.py])

### Summary
Hookify rule files (`.claude/hookify.*.local.md`) are parsed unconditionally by `load_rules()` and their `pattern`/condition `pattern` fields are compiled and executed via `re.search` on attacker-influenced text (e.g. `command`, `new_string`, `content`) on every `PreToolUse`, `PostToolUse`, `Stop`, and `UserPromptSubmit` hook invocation, with no regex complexity validation and no execution timeout. A rule file containing a catastrophic-backtracking pattern (e.g. `(a+)+$`) can hang the hook process indefinitely when matched against adversarial text, stalling the tool-approval pipeline.

### Finding Description
`load_rules()` in [1](#0-0)  globs `.claude/hookify.*.local.md`, parses each file's YAML-like frontmatter, and builds `Rule`/`Condition` objects directly from untrusted `pattern` strings without any regex validation, length limit, or ReDoS-pattern detection. Every enabled rule is returned regardless of how the load was triggered.

This `load_rules()` call is not gated behind the `/hookify:list` command — it is invoked directly and unconditionally inside the hook executors on every relevant Claude Code action: `plugins/hookify/hooks/pretooluse.py` (line 52, before every `Bash`/`Edit`/`Write`/`MultiEdit` call), and similarly in `posttooluse.py`, `stop.py`, and `userpromptsubmit.py`. `list.md` itself only enumerates rule files for display purposes via the `Glob`/`Read` tools [2](#0-1)  and does not call `load_rules()`, so the exploitation path is not specific to the `/hookify:list` command — it is inherent to normal tool use whenever malicious rule files exist in `.claude/`.

The actual regex evaluation happens in `compile_regex()` (cached with `functools.lru_cache`) and `_regex_match()`: [3](#0-2) . `regex.search(text)` is called synchronously with no timeout, and `text` is attacker/user-controlled content such as the Bash `command` field, `new_string`/`content` of file edits, or `transcript`/`user_prompt` for Stop/UserPromptSubmit events (see `_extract_field`, [4](#0-3) ).

`pretooluse.py`'s `main()` only wraps execution in a generic `try/except Exception`, which cannot interrupt a CPU-bound regex hang — it will only catch exceptions raised after the call returns, not runtime blowups [5](#0-4) . There is no signal-based or thread-based timeout anywhere in the hookify hook scripts.

### Impact Explanation
If an attacker can get adversarial `.claude/hookify.*.local.md` files into a repository that a victim checks out (e.g. via a malicious PR/branch containing seemingly benign-looking rule files), any subsequent Bash command or file edit whose content triggers catastrophic backtracking against the crafted pattern will hang the `PreToolUse` (or `Stop`/`UserPromptSubmit`) hook process. Since Claude Code hooks are expected to return promptly, this causes the tool-approval pipeline to stall — a denial-of-service against the hook enforcement mechanism itself, potentially forcing timeout-based fallback behavior in the host application. This matches a hook engine hang/DoS impact against the approval gate.

### Likelihood Explanation
Feasibility is high given only repository-content-level access (no privilege escalation needed): an attacker just needs a `.claude/hookify.<name>.local.md` file with attacker-controlled `pattern`/`conditions[].pattern` merged into the victim's working tree (e.g., via a PR that adds such files, or a compromised/cloned branch), which is auto-loaded on the next Bash/Edit/Write tool call. Because `load_rules()` re-globs and re-parses all matching files on every hook invocation (no persistence check on file trust), the attack is fully repeatable with each qualifying tool use, and `lru_cache(maxsize=128)` on `compile_regex` does not mitigate the backtracking cost of `.search()` itself.

### Recommendation
- Enforce a wall-clock or CPU-time execution bound around `regex.search()` calls in `_regex_match()` (e.g., run in a subprocess/thread with a strict timeout, or use `re2`/`regex` module with backtracking limits) and fail safe (treat as non-match) on timeout.
- Validate/sanitize rule patterns at load time (`load_rule_file`/`Condition.from_dict`) to reject or flag patterns with nested quantifiers/known catastrophic-backtracking shapes.
- Consider treating `.claude/hookify.*.local.md` as untrusted when not authored locally (e.g., warn or require explicit opt-in/approval before auto-loading rule files that arrived via a git checkout rather than being created via `/hookify`).

### Proof of Concept
Unit/fuzz test plan for `plugins/hookify/core/rule_engine.py::RuleEngine._regex_match`:
1. Construct a `Condition(field="command", operator="regex_match", pattern=r"(a+)+$")` and wrap it in a `Rule` with `tool_matcher="Bash"`.
2. Build `input_data = {"tool_name": "Bash", "tool_input": {"command": "a"*40 + "!"}}` (classic catastrophic-backtracking trigger — no trailing match).
3. Call `RuleEngine()._regex_match(pattern, text)` (or `evaluate_rules`) wrapped with a wall-clock timeout (e.g. `signal.alarm(2)` or run in a subprocess with `timeout=2s`).
4. Assert the call does not return within the timeout window (demonstrating unbounded hang), proving no ReDoS protection exists.
5. As a fix-verification test, after adding a timeout/backtracking guard, assert the same call returns `False`/non-match within the bound (e.g. <200ms) instead of hanging.

```python
def load_rules(event: Optional[str] = None) -> List[Rule]:
    """Load all hookify rules from .claude directory.

    Args:
        event: Optional event filter ("bash", "file", "stop", etc.)

    Returns:
        List of enabled Rule objects matching the event.
    """
    rules = []

    # Find all hookify.*.local.md files
    pattern = os.path.join('.claude', 'hookify.*.local.md')
    files = glob.glob(pattern)

    for file_path in files:
        try:
            rule = load_rule_file(file_path)
            if not rule:
                continue

            # Filter by event if specified
            if event:
                if rule.event != 'all' and rule.event != event:
                    continue

            # Only include enabled rules
            if rule.enabled:
                rules.append(rule)

        except (IOError, OSError, PermissionError) as e:
            # File I/O errors - log and continue
            print(f"Warning: Failed to read {file_path}: {e}", file=sys.stderr)
            continue
        except (ValueError, KeyError, AttributeError, TypeError) as e:
            # Parsing errors - log and continue
            print(f"Warning: Failed to parse {file_path}: {e}", file=sys.stderr)
            continue
        except Exception as e:
            # Unexpected errors - log with type details
            print(f"Warning: Unexpected error loading {file_path} ({type(e).__name__}): {e}", file=sys.stderr)
            continue

    return rules
```

```python
    def _extract_field(self, field: str, tool_name: str,
                      tool_input: Dict[str, Any], input_data: Dict[str, Any] = None) -> Optional[str]:
        """Extract field value from tool input or hook input data.

        Args:
            field: Field name like "command", "new_text", "file_path", "reason", "transcript"
            tool_name: Tool being used (may be empty for Stop events)
            tool_input: Tool input dict
            input_data: Full hook input (for accessing transcript_path, reason, etc.)

        Returns:
            Field value as string, or None if not found
        """
        # Direct tool_input fields
        if field in tool_input:
            value = tool_input[field]
            if isinstance(value, str):
                return value
            return str(value)

        # For Stop events and other non-tool events, check input_data
        if input_data:
            # Stop event specific fields
            if field == 'reason':
                return input_data.get('reason', '')
            elif field == 'transcript':
                # Read transcript file if path provided
                transcript_path = input_data.get('transcript_path')
                if transcript_path:
                    try:
                        with open(transcript_path, 'r') as f:
                            return f.read()
                    except FileNotFoundError:
                        print(f"Warning: Transcript file not found: {transcript_path}", file=sys.stderr)
                        return ''
                    except PermissionError:
                        print(f"Warning: Permission denied reading transcript: {transcript_path}", file=sys.stderr)
                        return ''
                    except (IOError, OSError) as e:
                        print(f"Warning: Error reading transcript {transcript_path}: {e}", file=sys.stderr)
                        return ''
                    except UnicodeDecodeError as e:
                        print(f"Warning: Encoding error in transcript {transcript_path}: {e}", file=sys.stderr)
                        return ''
            elif field == 'user_prompt':
                # For UserPromptSubmit events
                return input_data.get('user_prompt', '')

        # Handle special cases by tool type
        if tool_name == 'Bash':
            if field == 'command':
                return tool_input.get('command', '')

        elif tool_name in ['Write', 'Edit']:
            if field == 'content':
                # Write uses 'content', Edit has 'new_string'
                return tool_input.get('content') or tool_input.get('new_string', '')
            elif field == 'new_text' or field == 'new_string':
                return tool_input.get('new_string', '')
            elif field == 'old_text' or field == 'old_string':
                return tool_input.get('old_string', '')
            elif field == 'file_path':
                return tool_input.get('file_path', '')

        elif tool_name == 'MultiEdit':
            if field == 'file_path':
                return tool_input.get('file_path', '')
            elif field in ['new_text', 'content']:
                # Concatenate all edits
                edits = tool_input.get('edits', [])
                return ' '.join(e.get('new_string', '') for e in edits)

        return None
```

```python
    def _regex_match(self, pattern: str, text: str) -> bool:
        """Check if pattern matches text using regex.

        Args:
            pattern: Regex pattern
            text: Text to match against

        Returns:
            True if pattern matches
        """
        try:
            # Use cached compiled regex (LRU cache with max 128 patterns)
            regex = compile_regex(pattern)
            return bool(regex.search(text))

        except re.error as e:
            print(f"Invalid regex pattern '{pattern}': {e}", file=sys.stderr)
            return False
```

```python
def main():
    """Main entry point for PreToolUse hook."""
    try:
        # Read input from stdin
        input_data = json.load(sys.stdin)

        # Determine event type for filtering
        # For PreToolUse, we use tool_name to determine "bash" vs "file" event
        tool_name = input_data.get('tool_name', '')

        event = None
        if tool_name == 'Bash':
            event = 'bash'
        elif tool_name in ['Edit', 'Write', 'MultiEdit']:
            event = 'file'

        # Load rules
        rules = load_rules(event=event)

        # Evaluate rules
        engine = RuleEngine()
        result = engine.evaluate_rules(rules, input_data)

        # Always output JSON (even if empty)
        print(json.dumps(result), file=sys.stdout)

    except Exception as e:
        # On any error, allow the operation and log
        error_output = {
            "systemMessage": f"Hookify error: {str(e)}"
        }
        print(json.dumps(error_output), file=sys.stdout)

    finally:
        # ALWAYS exit 0 - never block operations due to hook errors
        sys.exit(0)
```
