### Title
Unbounded `io.ReadAll(r.Body)` in NewRelic/Datadog RPC Tracing Middleware Bypasses `MaxRequestContentLength` and Enables Memory-Exhaustion DoS - (File: networks/rpc/http_newrelic.go)

### Summary
Kaia's HTTP JSON-RPC server enforces a request body size cap (`common.MaxRequestContentLength`, default 512KB) via `validateRequest` and `io.LimitReader` in the normal request path [1](#0-0) . However, when NewRelic or Datadog tracing is enabled (via `NEWRELIC_APP_NAME`/`NEWRELIC_LICENSE` or Datadog env vars), these tracing handlers are wrapped *outside* the size-checked handler and independently call `getRPCRequests(r)`, which performs `io.ReadAll(r.Body)` with no size limit whatsoever [2](#0-1) .

### Finding Description
`NewHTTPServer` builds the handler chain as `ddTracer(newRelic(timeoutHandler(vhost(cors(srv)))))` [3](#0-2) . When either tracer is active, the outermost handler (`newNewRelicHTTPHandler` or `newDatadogHTTPHandler`) executes first and unconditionally calls `getRPCRequests(r)` to extract the RPC method name for tracing tags before delegating to the inner handler [4](#0-3) . `getRPCRequests` reads the entire body into memory via `io.ReadAll(r.Body)` with no `MaxBytesReader`, `ContentLength` check, or `io.LimitReader`, then rebuffers it for downstream consumption [5](#0-4) . Only after this unbounded read does control reach the inner `srv.ServeHTTP`, where `validateRequest` finally checks `r.ContentLength` against `common.MaxRequestContentLength` [6](#0-5) . By the time that check runs, the full attacker-supplied payload has already been allocated in memory — the protection is applied too late to prevent the exhaustion. This mirrors the reported Skipper admission-webhook flaw: an unauthenticated/any-reachable HTTP endpoint performs `io.ReadAll` on a client-controlled body with no upstream size gate.

### Impact Explanation
Any public RPC caller with network access to a Kaia node's JSON-RPC HTTP endpoint (when NewRelic or Datadog tracing is configured, which is a supported production deployment pattern for observability) can send a multi-GB POST body to the RPC port. The node will attempt to buffer the entire payload in memory in `getRPCRequests`, exhausting available memory and causing the node process to be OOM-killed. This disrupts all JSON-RPC service (transaction submission, `eth_call`, block/state queries) until the process restarts, and if repeated, provides a sustained denial-of-service against public RPC endpoints — impacting downstream users, gasless relayers, auction bidders, and staking-related RPC dependents that rely on those nodes.

### Likelihood Explanation
Likelihood is Medium: the vulnerable code path is only active when the operator has enabled NewRelic or Datadog tracing via environment variables [7](#0-6) , a common configuration for production RPC nodes/endpoint providers monitoring API performance. No authentication or special privilege is required — a single unauthenticated HTTP POST with an oversized body is sufficient, matching the "any public-RPC caller" reachability required.

### Recommendation
Wrap `r.Body` in `getRPCRequests` with `io.LimitReader(r.Body, int64(common.MaxRequestContentLength))` (or `http.MaxBytesReader`) before calling `io.ReadAll`, consistent with the protection already applied in `newHTTPServerConn` [8](#0-7) . Alternatively, perform the `validateRequest`/`ContentLength` check before invoking any tracing middleware that reads the body.

### Proof of Concept
1. Start a Kaia node with `NEWRELIC_APP_NAME`/`NEWRELIC_LICENSE` (or Datadog tracer) environment variables set, enabling `newNewRelicHTTPHandler`/`newDatadogHTTPHandler` in the HTTP RPC handler chain.
2. From any network location with access to the RPC HTTP port, send `POST /` with `Content-Type: application/json` and a multi-GB request body (optionally via chunked transfer-encoding to avoid a large `Content-Length` header being pre-validated by intermediate proxies).
3. `newNewRelicHTTPHandler`/`newDatadogHTTPHandler` invoke `getRPCRequests(r)`, which calls `io.ReadAll(r.Body)` and buffers the entire multi-GB payload into memory before `validateRequest`'s `ContentLength` check is ever reached.
4. Repeated concurrent requests exhaust node memory, causing an OOM kill and denial of service for all RPC clients.

func validateRequest(r *http.Request) (int, error) {
	if r.Method == http.MethodPut || r.Method == http.MethodDelete {
		return http.StatusMethodNotAllowed, errors.New("method not allowed")
	}
	if r.ContentLength > int64(common.MaxRequestContentLength) {
		err := fmt.Errorf("content length too large (%d>%d)", r.ContentLength, int64(common.MaxRequestContentLength))
		return http.StatusRequestEntityTooLarge, err
	}

func getRPCRequests(r *http.Request) ([]*jsonrpcMessage, bool, error) {
	reqBody, err := io.ReadAll(r.Body)
	if err != nil {
		logger.Error("cannot read a request body", "err", err)
		return nil, false, err
	}

	r.Body = io.NopCloser(bytes.NewReader(reqBody))
	conn := &httpServerConn{Reader: io.NopCloser(bytes.NewReader(reqBody)), Writer: bytes.NewBufferString(""), r: r}

	codec := NewCodec(conn)

	defer codec.close()

	return codec.readBatch()
}
