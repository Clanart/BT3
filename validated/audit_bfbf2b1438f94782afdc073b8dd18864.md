### Title
`ReceivedOutput::read` deserializes attacker-supplied output/offset pairs with no binding check, letting an unprivileged party cause the wallet to report unspendable funds as received - (File: networks/bitcoin/src/wallet/mod.rs)

### Summary
The Copilot CLI bug is a classification/interpretation mismatch: a safety layer parses a command and declares it "read-only", while the real interpreter re-evaluates the same bytes and executes hidden operations. The Serai analog is a deserialization path that accepts a structural claim ("this offset spends this output") as valid without ever re-deriving the claim, so bytes that parse cleanly are treated as a confirmed received payment when they are not. `ReceivedOutput::read` consumes an untrusted scalar `offset`, a `TxOut`, and an `OutPoint`, and returns a `ReceivedOutput` that `Scanner` semantics treat as spendable funds — but no code checks that `output.script_pubkey == p2tr_script_buf(key + G * offset)`, nor that `outpoint` refers to a real confirmed output. [1](#0-0) 

### Finding Description
`Scanner::scan_transaction` is the only trusted producer of `ReceivedOutput`s: it constructs them solely for outputs whose `script_pubkey` is present in `self.scripts`, guaranteeing the recorded `offset` actually yields the spending key. [2](#0-1)  `ReceivedOutput::read` bypasses all of that. It reads:
1. `offset` via `Secp256k1::read_F` — canonical scalar check only.
2. `output` via `TxOut::consensus_decode` — any syntactically valid `TxOut`.
3. `outpoint` via `OutPoint::consensus_decode` — any syntactically valid outpoint.

There is no `key` field in `ReceivedOutput` and no verification anywhere on this path that `p2tr_script_buf(scanner_key + GENERATOR * offset)` equals `output.script_pubkey`, matching the check `register_offset` performs when legitimately registering scripts. [3](#0-2)  The result is a `ReceivedOutput` whose `output()`/`value()`/`outpoint()` are fully attacker-controlled, structurally indistinguishable from one produced by `scan_transaction`. [4](#0-3) 

### Impact Explanation
An unprivileged party who can supply serialized `ReceivedOutput` bytes (e.g., a coordinator, peer, or any upstream service feeding `ReceivedOutput::read`) can cause the wallet to report funds as received that are not spendable: arbitrary `TxOut`s belonging to third-party scripts, nonexistent outpoints, or outputs whose script does not match the claimed `offset`. Downstream signing (`SignableTransaction`/`send.rs` consumes `ReceivedOutput::offset` to re-key each input) will produce signatures under `key + offset` for inputs the wallet never controlled, so confirmed "received" balance cannot be moved — a direct impact on fund accounting with plausible trickle-up to crediting deposits that don't exist.

### Likelihood Explanation
Reachability is limited to deployments that deserialize `ReceivedOutput`s from untrusted transport rather than only from local `scan_block`/`scan_transaction` results; where it is reachable, crafting the bytes is trivial (all fields are attacker-chosen). No cryptographic break is required. Because the honest path enforces the script↔offset binding and this path silently doesn't, the mismatch is invisible until spend attempts fail.

### Recommendation
Either bind the output to the offset at read time — store the scanner key (or expected script) context and verify `output.script_pubkey == p2tr_script_buf(key + G*offset)` in `ReceivedOutput::read`/`read` callers — or make the type's invariant explicit by restricting deserialization to trusted sources and documenting that `ReceivedOutput` claims are unverified. Full validation (confirming `outpoint` exists on-chain and is mature, per the coinbase caveat in `scan_block`) requires chain access and belongs to the caller, but the script↔offset binding is checkable locally.

  pub fn read<R: Read>(r: &mut R) -> io::Result<ReceivedOutput> {
    let offset = Secp256k1::read_F(r)?;
    let output;
    let outpoint;
    {
      let mut buf_r = BufReader::with_capacity(0, r);
      output =
        TxOut::consensus_decode(&mut buf_r).map_err(|_| io::Error::other("invalid TxOut"))?;
      outpoint =
        OutPoint::consensus_decode(&mut buf_r).map_err(|_| io::Error::other("invalid OutPoint"))?;
    }
    Ok(ReceivedOutput { offset, output, outpoint })
  }
