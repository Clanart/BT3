### Title
Payout tx malleability via SIGHASH_SINGLE|ANYONECANPAY lets a third party strip the OP_RETURN and permanently deny operator reimbursement - (File: core/src/builder/transaction/operator_reimburse.rs, core/src/verifier.rs)

### Summary
The user's signature on `payout_tx` input 0 uses `TapSighashType::SinglePlusAnyoneCanPay`, which under BIP341 commits only to input 0's outpoint/amount/scriptPubKey and to output 0 - it does not commit to the number, order, or content of any other inputs or outputs. Because `Verifier::update_finalized_payouts` attributes a payout purely by scanning whatever transaction actually spends the withdrawal UTXO on-chain for an OP_RETURN, an unprivileged third party can extract input 0's witness and output 0 from operator A's broadcast-but-unconfirmed `payout_tx`, build a variant with the OP_RETURN (and thus the operator attribution) removed, and get that variant mined first.

### Finding Description
The broken binding: `withdrawals.payout_payer_operator_xonly_pk` for withdrawal `i` should equal the xonly pubkey of the operator whose funds actually paid output 0 of the transaction that spent the withdrawal UTXO (operator A). After the attack it equals `NULL`.

`create_payout_txhandler` builds the payout tx with 3 outputs (user output, anchor, OP_RETURN with `operator_xonly_pk`), but signs only input 0 with the sighash the user actually authorized: [1](#0-0) 

The user's signature is generated (in the reference flow, e.g. test helper `sign_withdrawal_output`) over a message that uses `TapSighashType::SinglePlusAnyoneCanPay`: [2](#0-1) 

`Operator::withdraw` verifies this same signature against `calculate_sighash_txin(0, in_signature.sighash_type)` computed over the operator's fully built transaction, and explicitly documents that the sighash type must be `SinglePlusAnyoneCanPay`: [3](#0-2) 

Per BIP341, `SIGHASH_SINGLE|ANYONECANPAY` hashes only the corresponding single input (outpoint, amount, scriptPubKey, sequence) and the corresponding single output (index 0). It does not hash `sha_outputs` over all outputs, nor `sha_prevouts`/`sha_sequences` over all inputs. Consequently, any third party who obtains input 0's witness and output 0 can freely construct a different transaction: same input 0 (witness reused verbatim) plus output 0, but arbitrary other inputs (attacker-funded, for fees) and arbitrary other outputs - including one with no OP_RETURN at all - without invalidating the Schnorr signature.

Attribution of a payout to an operator is done purely by inspecting whichever transaction the Bitcoin network actually confirms as spending the withdrawal UTXO, not by checking it against any specific txid the operator broadcast: [4](#0-3) 

`update_finalized_payouts` then looks for the first OP_RETURN output in that confirmed transaction and sets the payer to `None` if none is found or it doesn't parse as a valid xonly pubkey: [5](#0-4) 

That `None`/txid is written unconditionally to the `withdrawals` row for index `i`: [6](#0-5) 

Because the withdrawal UTXO can only be spent once, this state is permanent - a UNIQUE outpoint can't be re-spent by the honest operator once the attacker's variant confirms. `PayoutCheckerTask::run_once` for operator A depends entirely on `get_first_unhandled_payout_by_operator_xonly_pk(A)` matching `payout_payer_operator_xonly_pk = A`, which will never be true once the column is `NULL`: [7](#0-6) [8](#0-7) 

None of the listed guards (`is_deposit_valid`, `is_profitable`, `SECP.verify_schnorr`, `only_aggregator_and_self`, `is_kickoff_malicious`, `verify_storage_proofs`, `SPV::verify`, `lc_proof_verifier`, presigned tx graph, DB uniqueness constraints) protect against this: `SECP.verify_schnorr` in `withdraw` only checks that the user's signature is valid for the operator's own locally built tx before broadcasting - it does not, and cannot, prevent a third party from later reusing that same ANYONECANPAY/SINGLE signature in a different transaction that confirms instead. `is_kickoff_malicious` only fires later, when a kickoff is sent by some operator, and here no operator's kickoff would ever be triggered because `A` never sees itself as the attributed payer, so the malicious-kickoff check is never reached at all.

### Impact Explanation
Operator A funds the user's withdrawal by broadcasting a valid, fully signed `payout_tx` (real BTC leaves A's control to the user). Before it confirms, an unprivileged attacker rebuilds a variant that reuses input 0's witness and output 0 but drops the OP_RETURN attribution output, and gets that variant mined instead (e.g. via higher fee/fee-bumped competing broadcast). Once mined, the withdrawal's `payout_payer_operator_xonly_pk` becomes `NULL` permanently (the UTXO is spent, so no other payout tx can ever be confirmed for this withdrawal index). Operator A's `PayoutCheckerTask` never finds this withdrawal as unhandled for its own pubkey, so `handle_finalized_payout`/Kickoff is never triggered and the Reimburse path never becomes reachable. Operator A permanently loses the funds it fronted with no path to reimbursement - this matches the "Critical: an honest operator permanently unable to be reimbursed" category. The attack is repeatable against any operator and any withdrawal, each time the operator broadcasts a payout tx before it confirms, since it depends only on public mempool data.

### Likelihood Explanation
Preconditions are minimal and fully within the unprivileged attacker's described capabilities: monitor the public Bitcoin mempool, extract signature/output data from a broadcast transaction, and broadcast a new standard Bitcoin transaction with sufficient fee to be mined first. No verifier/operator/aggregator privilege, key share, or collateral is required. The only cost to the attacker is Bitcoin transaction fees required to outcompete the original `payout_tx` for confirmation (a normal fee-bumping/mempool race, well within reach of any market participant). This is deterministic given BIP341 `SIGHASH_SINGLE|ANYONECANPAY` semantics and does not depend on chain reorgs, hash power majority, or any implementation bug beyond the sighash choice - it is repeatable for every withdrawal handled by every operator.

### Recommendation
Do not rely on `SIGHASH_SINGLE|ANYONECANPAY` for the user's authorization when the operator's attribution/reimbursement OP_RETURN output must be bound to the confirmed transaction. Either: (1) have the user sign with `SIGHASH_ALL` (or `SIGHASH_ALL|ANYONECANPAY` if only input flexibility for fee funding is needed) so the signature commits to the full output set including the anchor and OP_RETURN outputs, preventing any output-set malleation; or (2) if `SINGLE|ANYONECANPAY` must be kept for compatibility, change attribution logic to not depend on which arbitrary transaction ends up spending the withdrawal UTXO on-chain - e.g., require the operator to pre-register/commit the exact intended payout txid or an equivalent unmalleable commitment (such as a covenant tying output 0 to a fixed operator OP_RETURN) so the protocol can distinguish the operator's real payout tx from any parasitic reuse of the same signature.

    /// Sets the given payout txs' txid and operator index for the given index.
    pub async fn update_payout_txs_and_payer_operator_xonly_pk(
        &self,
        tx: Option<DatabaseTransaction<'_>>,
        payout_txs_and_payer_operator_xonly_pk: Vec<(
            u32,
            Txid,
            Option<XOnlyPublicKey>,
            bitcoin::BlockHash,
        )>,
    ) -> Result<(), BridgeError> {
        if payout_txs_and_payer_operator_xonly_pk.is_empty() {
            return Ok(());
        }
        // Convert all values first, propagating any errors
        let converted_values: Result<Vec<_>, BridgeError> = payout_txs_and_payer_operator_xonly_pk
            .iter()
            .map(|(idx, txid, operator_xonly_pk, block_hash)| {
                Ok((
                    i32::try_from(*idx).wrap_err("Failed to convert payout index to i32")?,
                    TxidDB(*txid),
                    operator_xonly_pk.map(XOnlyPublicKeyDB),
                    BlockHashDB(*block_hash),
                ))
            })
            .collect();
        let converted_values = converted_values?;

        let mut query_builder = QueryBuilder::new(
            "UPDATE withdrawals AS w SET
                payout_txid = c.payout_txid,
                payout_payer_operator_xonly_pk = c.payout_payer_operator_xonly_pk,
                payout_tx_blockhash = c.payout_tx_blockhash
                FROM (",
        );

        query_builder.push_values(
            converted_values.into_iter(),
            |mut b, (idx, txid, operator_xonly_pk, block_hash)| {
                b.push_bind(idx)
                    .push_bind(txid)
                    .push_bind(operator_xonly_pk)
                    .push_bind(block_hash);
            },
        );

        query_builder
            .push(") AS c(idx, payout_txid, payout_payer_operator_xonly_pk, payout_tx_blockhash) WHERE w.idx = c.idx");

        let query = query_builder.build();
        execute_query_with_tx!(self.connection, tx, query, execute)?;

        Ok(())
    }
