### Title
No Rate Limiting on Daemon `validate_keyring_passphrase`/`unlock_keyring` RPCs Enables Unlimited Master-Passphrase Brute-Force - (File: `chia/daemon/server.py`)

### Summary
The chia daemon's websocket RPC handlers `validate_keyring_passphrase` and `unlock_keyring` check a submitted key against the keyring's single PBKDF2-HMAC-SHA256-derived master passphrase with no failed-attempt counter, delay, or lockout. Any client able to reach the daemon's local websocket (a "local RPC caller" per the local daemon RPC boundary) can issue unlimited passphrase guesses to unlock the encrypted keyring holding all wallet private keys.

### Finding Description
`WebSocketServer.validate_keyring_passphrase()` and `WebSocketServer.unlock_keyring()` call `Keychain.master_passphrase_is_valid(key, force_reload=True)` directly and return `success`/`error` immediately, with no attempt tracking: [1](#0-0) 

Compare this to the interactive CLI path `obtain_current_passphrase()`, which enforces `MAX_RETRIES = 3` and a `FAILED_ATTEMPT_DELAY = 0.5` before raising `KeychainMaxUnlockAttempts`: [2](#0-1) 

The RPC-facing `KeyringWrapper.master_passphrase_is_valid()` used by both daemon handlers has none of that throttling — it is a direct passthrough to `self.keyring.check_passphrase(...)`: [3](#0-2) 

The underlying KDF (`pbkdf2_hmac("sha256", ..., HASH_ITERS=100000)`) only slows a single guess; it provides no protection against a scripted client issuing thousands of `validate_keyring_passphrase`/`unlock_keyring` requests over the daemon websocket connection: [4](#0-3) 

As documented, the daemon RPC boundary's only gate is mutual TLS using the daemon's local certs plus config — there is no rate limiter at this layer:



### Impact Explanation
A successful brute-force of the master passphrase unlocks the local keyring, giving the caller access to every private key managed by that keychain (wallet keys, farmer/pool keys). This directly enables unauthorized coin movement: the attacker can derive wallet secret keys via `master_sk_to_wallet_sk`/`master_pk_to_wallet_pk_unhardened` (imported and used elsewhere in `chia/daemon/server.py`) and sign spend bundles moving the victim's funds without further authorization.

### Likelihood Explanation
Exploitation requires only the ability to open a websocket to the local daemon (satisfying the daemon's mTLS requirement), which any local RPC caller possessing the local client cert bundle (the standard chia CLI/GUI trust level) has. Once connected, the attacker can send unlimited `validate_keyring_passphrase` or `unlock_keyring` requests in a tight loop; weak or short user-set passphrases can be found in a bounded, unthrottled amount of time.

### Recommendation
Add per-connection/per-source failed-attempt tracking and exponential backoff or lockout to `validate_keyring_passphrase` and `unlock_keyring` in `chia/daemon/server.py`, mirroring the `MAX_RETRIES`/`FAILED_ATTEMPT_DELAY` behavior already used by the CLI's `obtain_current_passphrase()`, and raise/propagate `KeychainMaxUnlockAttempts` over the RPC path once the threshold is exceeded.

### Proof of Concept
1. Connect to the daemon's TLS websocket using the local daemon certs (as any local client does).
2. Repeatedly send `create_payload("validate_keyring_passphrase", {"key": <guess>}, "test", "daemon")` (or `unlock_keyring`) with different guesses in a loop, as exercised in `test_validate_keyring_passphrase_rpc`: [5](#0-4) 

3. Observe no lockout, delay increase, or connection drop occurs regardless of the number of consecutive failed guesses, allowing an automated brute-force of the master passphrase.

    async def unlock_keyring(self, websocket: WebSocketResponse, request: dict[str, Any]) -> dict[str, Any]:
        success: bool = False
        error: str | None = None
        key: str | None = request.get("key", None)
        if type(key) is not str:
            return {"success": False, "error": "missing key"}

        try:
            if Keychain.master_passphrase_is_valid(key, force_reload=True):
                Keychain.set_cached_master_passphrase(key)
                success = True
                # Inform the GUI of keyring status changes
                self.keyring_status_changed(await self.keyring_status(), "wallet_ui")
            else:
                error = "bad passphrase"
        except Exception as e:
            tb = traceback.format_exc()
            self.log.error(f"Keyring passphrase validation failed: {e} {tb}")
            error = "validation exception"

        if success and self.run_check_keys_on_unlock:
            try:
                self.log.info("Running check_keys now that the keyring is unlocked")
                check_keys(self.root_path)
                self.run_check_keys_on_unlock = False
            except Exception as e:
                tb = traceback.format_exc()
                self.log.error(f"check_keys failed after unlocking keyring: {e} {tb}")

        response: dict[str, Any] = {"success": success, "error": error}
        return response

def obtain_current_passphrase(prompt: str = DEFAULT_PASSPHRASE_PROMPT, use_passphrase_cache: bool = False) -> str:
    from chia.util.keyring_wrapper import KeyringWrapper

    """
    Obtains the master passphrase for the keyring, optionally using the cached
    value (if previously set). If the passphrase isn't already cached, the user is
    prompted interactively to enter their passphrase a max of MAX_RETRIES times
    before failing.
    """

    if use_passphrase_cache:
        passphrase, validated = KeyringWrapper.get_shared_instance().get_cached_master_passphrase()
        if passphrase:
            # If the cached passphrase was previously validated, we assume it's... valid
            if validated:
                return passphrase

            # Cached passphrase needs to be validated
            if KeyringWrapper.get_shared_instance().master_passphrase_is_valid(passphrase):
                KeyringWrapper.get_shared_instance().set_cached_master_passphrase(passphrase, validated=True)
                return passphrase
            else:
                # Cached passphrase is bad, clear the cache
                KeyringWrapper.get_shared_instance().set_cached_master_passphrase(None)

    # Prompt interactively with up to MAX_RETRIES attempts
    for i in range(MAX_RETRIES):
        colorama.init()

        passphrase = prompt_for_passphrase(prompt)

        if KeyringWrapper.get_shared_instance().master_passphrase_is_valid(passphrase):
            # If using the passphrase cache, and the user inputted a passphrase, update the cache
            if use_passphrase_cache:
                KeyringWrapper.get_shared_instance().set_cached_master_passphrase(passphrase, validated=True)
            return passphrase

        time.sleep(FAILED_ATTEMPT_DELAY)
        print("Incorrect passphrase\n")
    raise KeychainMaxUnlockAttempts
