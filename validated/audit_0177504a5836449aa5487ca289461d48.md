## Title
`retryPayload()` in `HyperbridgeLzEndpoint` bypasses the `whenNotPaused` guard that protects `onAccept()` - (File: `sdk/packages/lz-endpoint/contracts/HyperbridgeLzEndpoint.sol`)

## Summary
This is a direct analog of the LoopFi finding: a state-changing entrypoint (`onAccept`) is protected by `whenNotPaused`, but a second **public/permissionless** function performs the exact same underlying effect (delivering the message to the destination OApp via `lzReceive`) without that modifier, letting anyone push cross-chain message delivery through while the contract is paused.

## Finding Description
`HyperbridgeLzEndpoint` inherits OpenZeppelin's `Pausable` and gates its two primary message-delivery paths: [1](#0-0) [2](#0-1) 

`onAccept` is called by the ISMP host to deliver an inbound message; if the OApp's `lzReceive` reverts, the payload hash is stored for later retry instead of reverting the whole `onAccept` call: [3](#0-2) 

The stored payload is meant to be recovered via `retryPayload`, which performs the *same* privileged action — calling `lzReceive` on the destination OApp — but is declared **without** `whenNotPaused`: [4](#0-3) 

The function's own doc comment states it is "Permissionless: anyone may push a stuck payload through" — there is no `onlyOAppOrDelegate` or `onlyHost` restriction, and critically no pause check. Since `retryPayload` reaches the identical code path as `onAccept` (`ILayerZeroReceiver(receiver).lzReceive(...)`), pausing the endpoint does not actually stop message delivery for any payload that was previously stored (i.e., any message whose first delivery attempt reverted before the pause was activated, or that reverts for reasons unrelated to the pause).

This mirrors the CDPVault bug exactly: `deposit`/`withdraw` are `whenNotPaused`, but the underlying `modifyCollateralAndDebt` is public and unguarded, so callers achieve the same effect by calling the unguarded function directly. Here, `onAccept` is `whenNotPaused`, but `retryPayload` reaches the same `lzReceive` delivery logic and is unguarded and permissionless.

## Impact Explanation
An emergency `pause()` is the kill switch the owner relies on to halt all cross-chain execution (e.g., during an incident, a discovered bug in a connected OApp, or a migration). Because `retryPayload` is unauthenticated and unguarded by `whenNotPaused`, any address can still trigger execution of `lzReceive` on a destination OApp — including value-bearing effects such as minting/unlocking tokens for LayerZero OFTs routed through this adapter — while the protocol is supposed to be fully halted. This is unauthorized execution during a state the admin explicitly intended to freeze, directly undermining the pause invariant and enabling continued fund movement/logic execution that the operator believed was stopped.

## Likelihood Explanation
The precondition is simply the existence of at least one previously stored payload hash (any inbound message whose first `lzReceive` attempt reverted, which is an expected occurrence, not an attacker-controlled edge case — the code even anticipates and documents this retry flow). Once such an entry exists, invoking `retryPayload` requires no special privilege, no relayer/prover/admin compromise, and can be called by anyone at any time regardless of pause state.

## Recommendation
Add the `whenNotPaused` modifier to `retryPayload` (and to `lzCompose`, which similarly executes composed calls without a pause check), so that pausing the endpoint fully halts all inbound delivery paths, not just the primary `onAccept` route.

## Proof of Concept
1. A message is delivered via `onAccept`; the destination OApp's `lzReceive` reverts (e.g., transient revert, temporary blocklist, or contract state), so the payload hash is stored per [5](#0-4) .
2. The owner calls `pause()` on the endpoint (e.g., due to an incident), expecting all cross-chain execution to stop.
3. An unprivileged actor calls `retryPayload(receiver, origin, guid, message)` with the matching stored hash — this succeeds because `retryPayload` has no `whenNotPaused` check, executing `lzReceive` on the destination OApp exactly as `onAccept` would have.
4. Cross-chain execution (and any associated token mint/unlock logic in the OApp) proceeds despite the contract being paused, violating the intended emergency-stop invariant.

```text
    function retryPayload(
        address receiver,
        Origin calldata origin,
        bytes32 guid,
        bytes calldata message
    ) external payable {
        bytes32 stored = _inboundPayloadHashes[receiver][origin.srcEid][origin.sender][origin.nonce];
        if (stored == bytes32(0) || stored == NIL_PAYLOAD_HASH || stored != keccak256(abi.encode(guid, message))) {
            revert InvalidPayloadHash();
        }

        // Clear first; if the retry reverts, this deletion rolls back with the rest of the tx and
        // the payload remains recoverable.
        delete _inboundPayloadHashes[receiver][origin.srcEid][origin.sender][origin.nonce];

        ILayerZeroReceiver(receiver).lzReceive{value: msg.value}(origin, guid, message, msg.sender, "");
        emit InboundPayloadResolved(receiver, origin.srcEid, origin.sender, origin.nonce);
    }
```
