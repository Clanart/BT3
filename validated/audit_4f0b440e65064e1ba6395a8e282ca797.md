### Title
Untrusted `WWW-Authenticate` header from a git remote triggers an Enterprise sign-in/OAuth flow against an attacker-controlled endpoint - ([File: app/src/lib/trampoline/trampoline-credential-helper.ts])

### Summary
`getEndpointKind()` classifies an unknown Git remote host as GitHub Enterprise (`'enterprise'`) purely by inspecting the `wwwauth[...]` header values that Git forwards from the *remote server's* HTTP response, without any independent verification (e.g. hitting `/meta` or the API to confirm it's really a GitHub product). A malicious or compromised remote/proxy can set `WWW-Authenticate: ... realm="GitHub"` on its `401` response and cause Desktop to treat it as a legitimate GitHub Enterprise instance, invoking `promptForGitHubSignIn()` and kicking off the full Enterprise sign-in/OAuth device flow bound to the attacker's origin.

### Finding Description
When Git needs credentials for an HTTPS remote it invokes Desktop's trampoline credential helper (`createCredentialHelperTrampolineHandler`) with a `get` request. This flows into `getCredential()` → `getEndpointKind()`: [1](#0-0) 

The classification loop trusts attacker-controlled response headers captured by Git and relayed verbatim to Desktop: [2](#0-1) 

If `endpointKind` resolves to `'enterprise'` (or any non-`'generic'` value) and no existing account matches the host, Desktop unconditionally prompts a GitHub sign-in for that exact remote endpoint: [3](#0-2) 

`promptForGitHubSignIn()` then starts the real Enterprise sign-in UI/OAuth flow bound to the attacker's origin, since hostname isn't `github.com`: [4](#0-3) 

The only gate is a raw substring match on the `realm` value in a header the remote server fully controls — there is no cryptographic or API-based verification that the host is an actual GitHub Enterprise product (unlike `isDotCom`/`isGHE`, which check fixed domains, `enterprise` classification here is driven entirely by attacker-supplied header text). Existing guards (`isGist`, `isDotCom`, `isGHE` checks earlier in the function) only short-circuit for known GitHub-owned domains; they do nothing to stop an arbitrary third-party host from being accepted as `'enterprise'` via the header path.

### Impact Explanation
Once Desktop believes an arbitrary attacker-controlled host is a GitHub Enterprise Server, it will drive the user through `beginEnterpriseSignIn` / `setSignInEndpoint(origin)` and the full sign-in popup for that origin. This is a case of "unauthorized OAuth or account binding" to an attacker-chosen endpoint that the user never configured or intended to trust, effectively laundering the "GitHub Enterprise" trust indicator through a hostile git remote (which the user reached simply by adding a remote/cloning a repository configured with an attacker's URL, and doing a normal fetch/pull/clone that triggers a `401`). Any credentials/tokens the user enters or approves in that flow are then bound to and usable against the attacker's endpoint, and stored in `AccountsStore` keyed to that endpoint.

### Likelihood Explanation
Likelihood is limited by needing the user to perform a normal git network operation (fetch/clone/push) against a remote that the attacker controls or can respond on behalf of (e.g., a malicious/compromised git server, or a MITM proxy on an unauthenticated HTTP path before TLS enforcement, or a legitimate-looking generic git host set up by the attacker). No local access, admin rights, or pre-existing malware is required — this is triggered purely by the remote server's response content during ordinary Desktop usage, which matches the required attacker primitive of a "git remote/proxy response."

### Recommendation
Do not classify a remote as `'enterprise'` (with its elevated sign-in/OAuth trust) based solely on a `WWW-Authenticate` realm string supplied by the remote itself. Require corroboration via an authenticated API probe (e.g., `isGitHubHost()`'s existing `/meta`-style check) before elevating trust, or at minimum surface a clear "unverified GitHub Enterprise host" warning to the user before initiating the sign-in/OAuth popup for a previously-unknown endpoint.

### Proof of Concept
1. Set up a plain HTTPS git server (attacker-controlled), e.g. `https://evil.example.com/foo.git`.
2. Configure it to respond to unauthenticated Git HTTP requests with `401` and header `WWW-Authenticate: Basic realm="GitHub"`.
3. In GitHub Desktop, add this remote to any local repository and perform a `Fetch`/`Pull`.
4. Git invokes the credential helper; `trampoline-credential-helper.ts`'s `getEndpointKind()` sees the `wwwauth[...]` header containing `realm="GitHub"` and returns `'enterprise'`.
5. Because no account exists for `evil.example.com`, `getCredential()` calls `ui.promptForGitHubSignIn('https://evil.example.com/...')`, which opens the Enterprise sign-in flow bound to `https://evil.example.com`, despite the host having no relation to any real GitHub product.

const getEndpointKind = async (cred: Credential, store: Store) => {
  const credentialUrl = getCredentialUrl(cred)
  const endpoint = `${credentialUrl}`

  if (isGist(endpoint)) {
    return 'generic'
  }

  if (isDotCom(endpoint)) {
    return 'github.com'
  }

  if (isGHE(endpoint)) {
    return 'ghe.com'
  }

  // When Git attempts to authenticate with a host it captures any
  // WWW-Authenticate headers and forwards them to the credential helper. We
  // use them as a happy-path to determine if the host is a GitHub host without
  // having to resort to making a request ourselves.
  for (const [k, v] of cred.entries()) {
    if (k.startsWith('wwwauth[')) {
      if (v.includes('realm="GitHub"')) {
        return 'enterprise'
      } else if (/realm="(GitLab|Gitea|Atlassian Bitbucket)"/.test(v)) {
        return 'generic'
      }
    }
  }

  public promptForGitHubSignIn(endpoint: string): Promise<Account | undefined> {
    return new Promise<Account | undefined>(async resolve => {
      const cb = (result: SignInResult) => {
        resolve(result.kind === 'success' ? result.account : undefined)
        this.dispatcher.closePopup(PopupType.SignIn)
      }

      const { hostname, origin } = new URL(endpoint)
      if (hostname === 'github.com') {
        this.dispatcher.beginDotComSignIn(cb)
      } else {
        this.dispatcher.beginEnterpriseSignIn(cb)
        await this.dispatcher.setSignInEndpoint(origin)
      }

      this.dispatcher.showPopup({
        type: PopupType.SignIn,
        isCredentialHelperSignIn: true,
        credentialHelperUrl: endpoint,
      })
