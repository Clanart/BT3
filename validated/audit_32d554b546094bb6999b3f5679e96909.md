### Title
SSRF via unauthenticated on-chain DataLayer mirror URLs fetched by `http_download` - (File: `chia/data_layer/download_data.py`)

### Summary
Any DataLayer wallet participant can publish an arbitrary URL as a "mirror" for a DataLayer store by spending a small mirror coin on-chain via `DataLayer.add_mirror()`. Every other node that subscribes to that store id will later read the mirror URL from wallet state and issue an outbound HTTP GET to it from the DataLayer service process, with no scheme allow-list and no restriction against internal/private/loopback/link-local addresses — the same bug class as CVE-2020-35313 (WonderCMS `addCustomThemePluginRepository` SSRF via attacker-supplied theme/plugin URL).

### Finding Description
`DataLayer.add_mirror()` accepts a caller-supplied list of `urls` and simply requires the list to be non-empty before publishing it on-chain through `dl_new_mirror`: [1](#0-0) 

Any node subscribed to that store id pulls these mirror URLs into its local subscription table via `update_subscriptions_from_wallet()`, which reads `dl_get_mirrors` from wallet RPC and stores every URL verbatim: [2](#0-1) 

During the periodic `fetch_and_validate()` sync loop, one of these attacker-controlled `server_info.url` values is chosen (randomized) and passed to `insert_from_delta_file()` → `download_file()`: [3](#0-2) 

When no downloader plugin is configured (the default, plain-HTTP path), `download_file()` calls `http_download()`, which performs an unrestricted `aiohttp` GET request to `server_info.url + "/" + filename`: [4](#0-3) 

There is no validation anywhere in this path (`add_mirror`, `update_subscriptions_from_wallet`, `http_download`) that the URL uses `http`/`https`, that it does not resolve to loopback/link-local/private ranges (e.g. `127.0.0.1`, `169.254.169.254` cloud metadata, internal RPC ports), or that it points to a legitimate DataLayer server. The project's own module notes explicitly flag this as an unresolved trust boundary: "Plugin and mirror URLs are external trust inputs" and "Do not treat mirror URLs, plugins, or static file names as trusted data sources," confirming the design gap rather than an incidental oversight. [5](#0-4) [6](#0-5) 

The same unrestricted-URL pattern also exists for downloader/uploader plugin negotiation (`get_downloader()`, `get_uploaders()`), though those endpoints are normally operator-configured rather than attacker-supplied on-chain data: [7](#0-6) [8](#0-7) 

### Impact Explanation
Any user who can afford to spend a DataLayer mirror coin (a normal, permissionless wallet action reachable by any Data Layer client) can cause every other node that subscribes to that store to make outbound HTTP requests to attacker-chosen hosts/ports from their local DataLayer service. This enables classic SSRF outcomes: probing/reaching internal services not otherwise network-reachable, hitting cloud metadata endpoints (credential theft on cloud-hosted nodes), or abusing internal-only HTTP APIs (including localhost RPC-adjacent services) that trust requests originating from the host itself. Because the URL is embedded in an on-chain coin and consumed automatically by the periodic sync loop with no user confirmation, this is a wide-blast-radius, no-interaction SSRF affecting any DataLayer participant subscribed to the malicious store.

### Likelihood Explanation
High. Creating a mirror only requires calling the standard, exposed `add_mirror` DataLayer RPC/wallet action with an arbitrary URL string; no special privileges beyond normal wallet funds are needed. Any node that subscribes to the store (a normal DataLayer client action) will automatically fetch from the malicious URL on its regular `periodically_manage_data()` cycle without any manual approval step.

### Recommendation
Validate mirror/server URLs before storing and before issuing outbound requests: enforce an `http`/`https` scheme allow-list, resolve and reject hosts pointing to loopback, link-local (including `169.254.169.254`), private RFC1918 ranges, and other non-routable addresses (with re-resolution checks to prevent DNS rebinding), and consider requiring operator opt-in/allow-listing for mirror hosts rather than trusting arbitrary chain-published URLs implicitly in `add_mirror`, `update_subscriptions_from_wallet`, and `http_download`.

### Proof of Concept
1. Attacker (any funded wallet) calls `add_mirror(store_id, urls=["http://169.254.169.254/latest/meta-data/"], amount, fee)` to publish a malicious mirror URL on-chain for a DataLayer store, per `chia/data_layer/data_layer.py:965-970`.
2. Victim node runs a DataLayer service and (auto-)subscribes to `store_id`; `update_subscriptions_from_wallet()` (`chia/data_layer/data_layer.py:979-985`) pulls the malicious URL into the victim's local subscription table.
3. On the next `periodically_manage_data()` cycle, `fetch_and_validate()` selects the malicious `server_info.url` and calls `insert_from_delta_file()` → `download_file()` → `http_download()` (`chia/data_layer/download_data.py:298-319`), which issues `GET http://169.254.169.254/latest/meta-data/<filename>` directly from the victim's DataLayer process — demonstrating unrestricted outbound requests to attacker-chosen internal/cloud-metadata targets.

```python
    async def get_downloader(self, store_id: bytes32, url: str) -> PluginRemote | None:
        request_json = {"store_id": store_id.hex(), "url": url}
        for d in self.downloaders:
            async with aiohttp.ClientSession() as session:
                try:
                    async with session.post(
                        d.url + "/handle_download",
                        json=request_json,
                        headers=d.headers,
                        timeout=self.client_timeout,
                    ) as response:
                        res_json = await response.json()
                        if res_json["handle_download"]:
                            return d
                except Exception as e:
                    self.log.error(f"get_downloader could not get response: {type(e).__name__}: {e}")
        return None
```

```python
async def http_download(
    target_filename_path: Path,
    filename: str,
    proxy_url: str | None,
    server_info: ServerInfo,
    timeout: aiohttp.ClientTimeout,
    log: logging.Logger,
    max_delta_file_size: int,
) -> None:
    """
    Download a file from a server using aiohttp.
    Raises exceptions on errors
    """
    async with aiohttp.ClientSession() as session:
        headers = {"accept-encoding": "gzip"}
        async with session.get(
            server_info.url + "/" + filename,
            headers=headers,
            timeout=timeout,
            proxy=proxy_url,
        ) as resp:
            resp.raise_for_status()
```
