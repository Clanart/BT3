### Title
Bitcoin RPC client silently accepts plaintext `http://` URLs, leaving RPC credentials and all chain data unauthenticated - ([File: networks/bitcoin/src/rpc.rs])

### Summary
`Rpc::new` in `bitcoin-serai` builds its HTTP client via `simple_request::Client::with_connection_pool()`. In `common/request/src/lib.rs`, the TLS connector is built with `HttpsConnectorBuilder::...https_or_http()` after `res.enforce_http(false)`, meaning any `http://` URL is accepted and every request — including the `Authorization: Basic` header added by `request.with_basic_auth()` — is sent in cleartext with no server authentication. This is the same bug class as CVE-2023-31486 (HTTP::Tiny): transport security is opt-in by URL scheme rather than enforced, and nothing warns the caller that the channel is unauthenticated.

### Finding Description
- `Rpc::new(url)` stores the caller-supplied URL and reuses it verbatim for every request (`hyper::Request::post(&self.url)`), with `request.with_basic_auth()` attaching credentials [1](#0-0) [2](#0-1) 
- The underlying connector explicitly disables the HTTP-only restriction and wraps the connector with `https_or_http()`, so `http://` URLs never get TLS or certificate verification — the insecure path is silently permitted [3](#0-2) 
- All block/transaction authenticity guarantees depend on the transport: `get_block` and `get_transaction` only verify that the returned bytes hash to the *requested* hash, which is meaningless if the attacker controls what hash was requested or can shape scanner inputs [4](#0-3) 

### Impact Explanation
An unprivileged network attacker (not the node operator — no malicious-RPC assumption needed) positioned between the processor and the Bitcoin daemon can, when an `http://` endpoint is configured: (1) steal the RPC basic-auth credentials sent on every request, and (2) fully fabricate RPC responses — `getblockcount`, `getblock`, `getrawtransaction` — causing the wallet/Scanner to report outputs as received/confirmed that are not actually on-chain and therefore not spendable, or to hide real deposits. This maps to the accepted impact "funds reported received that are not spendable" plus credential disclosure, matching the CVE's C:H/I:H profile.

### Likelihood Explanation
Requires the node to be configured with an `http://` RPC URL — a plausible deployment choice since Bitcoin Core RPC is commonly reached over trusted networks/localhost, and the library gives no signal that the scheme disables authentication. Exploitation requires a network MITM position (AC:H, mirroring the CVE's 8.1 CVSS), but once present, no further interaction or privileges are needed; every `rpc_call` leaks credentials passively.

### Recommendation
Reject non-`https` URLs in `Rpc::new` (or provide an explicit `new_insecure_http` constructor requiring opt-in), so transport authentication is the default rather than scheme-dependent. Alternatively, in `simple-request`, build the connector with `.https_only()` instead of `.https_or_http()` and require callers to construct a plaintext `HttpConnector` deliberately.

### Proof of Concept
1. Configure `Rpc::new("http://<host>:8332".to_string())` — accepted without error.
2. On-path attacker observes `POST /` with `Authorization: Basic <base64 user:pass>` on the first `rpc_call("help", ...)` during `Rpc::new` — credentials recovered with zero interaction.
3. Attacker replies to `getblockcount`/`getblock` with fabricated JSON/hex describing a block containing a deposit to the vault's `script_pubkey`; `get_block` succeeds because the attacker also answers `getblockhash` consistently, and the Scanner records spendable-looking outputs that were never mined.   /// Perform an arbitrary RPC call.
  pub async fn rpc_call<Response: DeserializeOwned + Debug>(
    &self,
    method: &str,
    params: serde_json::Value,
  ) -> Result<Response, RpcError> {
    let mut request = Request::from(
      hyper::Request::post(&self.url)
        .header("Content-Type", "application/json")
        .body(
          serde_json::to_vec(&json!({ "jsonrpc": "2.0", "method": method, "params": params }))
            .unwrap()
            .into(),
        )
        .unwrap(),
    );
    request.with_basic_auth();
    let mut res = self
      .client
      .request(request)
      .await
      .map_err(|_| RpcError::ConnectionError)?
      .body()
      .await
      .map_err(|_| RpcError::ConnectionError)?;

    let res: RpcResponse<Response> =
      serde_json::from_reader(&mut res).map_err(|e| RpcError::InvalidJson(e.classify()))?;
    match res {
      RpcResponse::Ok { result } => Ok(result),
      RpcResponse::Err { error } => Err(RpcError::RequestError(error)),
    }
  }
