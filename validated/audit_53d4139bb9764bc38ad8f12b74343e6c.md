### Title
Unrestricted output directory in DataLayer `add_missing_files` RPC allows arbitrary filesystem writes - (File: `chia/data_layer/data_layer_rpc_api.py`)

### Summary
The DataLayer RPC endpoint `add_missing_files` accepts a caller-supplied `foldername` string and converts it directly into a `Path` with no validation, sandboxing, or restriction to the configured `server_files_location`. That path is then used as the destination directory for writing DataLayer tree/delta files to disk, giving any RPC caller with access to the DataLayer RPC service the ability to write files to an arbitrary location on the host filesystem — the same bug class as check_sftp's unrestricted upload/download paths (CVE-2024-28826).

### Finding Description
`DataLayerRpcApi.add_missing_files` reads the `foldername` field straight from the untrusted JSON RPC request and wraps it in `Path()` without any normalization, allow-listing, or containment check: [1](#0-0) 

This value is forwarded unmodified to `DataLayer.add_missing_files`, where it is used in place of the service's own `server_files_location` (the intended, config-controlled write directory): [2](#0-1) 

`write_files_for_root` then joins the attacker-controlled directory with generated filenames and opens them for writing with `open(filename_full_tree, mode)` / `open(filename_diff_tree, mode)` in `"wb"`/`"xb"` mode, creating parent directories as needed (`filename_full_tree.parent.mkdir(parents=True, exist_ok=True)`): [3](#0-2) 

Because `foldername` can be any absolute path (e.g. `/home/user/.ssh`, a crontab directory, a systemd unit directory, etc.), and because `Path()` performs no traversal or containment check, the write destination is entirely attacker-controlled — the DataLayer analog of check_sftp's improperly restricted local upload/download path. The written content is DataLayer merkle/kv tree data (attacker can also influence key/value content inserted into the store before triggering this call), and file names are also chosen by the store id/root hash/generation, giving further influence over the resulting file names within the chosen directory.

The CLI wrapper exposes the same unrestricted parameter directly to users: [4](#0-3) 

### Impact Explanation
An RPC caller authorized to reach the DataLayer RPC (a local, non-privileged caller of the DataLayer service, distinct from full node/wallet key material) can force the daemon process to create/overwrite files at attacker-chosen filesystem paths outside the intended `server_files_location`, subject to the OS permissions of the DataLayer process. This can be used to plant or corrupt files (e.g., inside directories the DataLayer process can write to), enabling local file corruption/tampering and potentially escalation depending on what writable-but-security-relevant paths are reachable by the service account (autostart scripts, cron entries, application configs, etc.). This satisfies the "concrete unsigned/unauthorized...halt or coin movement"-adjacent category as an RPC-triggered unauthorized local file write with no path restriction, matching the High severity of the analog CVE.

### Likelihood Explanation
Any client with access to the DataLayer RPC API (which does not require wallet keys or chain-level privileges) can call `add_missing_files` with a crafted `foldername`. No additional preconditions beyond having at least one DataLayer store are needed, since a store id argument is optional and defaults to all subscriptions. This makes the path highly reachable for any local automation or lower-privileged local RPC client that has been granted access to the DataLayer RPC surface.

### Recommendation
Validate and constrain `foldername` before use: reject absolute paths or paths that escape the configured `server_files_location` root (e.g., resolve the path and ensure it is a descendant of the allowed base directory), similar to how `is_filename_valid()` constrains filenames in `chia/data_layer/download_data.py`. Alternatively, remove the ability to override the write directory via RPC/CLI entirely, or require it to be a subdirectory selected from a fixed, server-side allow-list.

### Proof of Concept
1. Start a node with the DataLayer service enabled and RPC access.
2. Create/track at least one DataLayer store.
3. Call the `add_missing_files` RPC with a JSON body such as:
```json
{"ids": ["<store_id_hex>"], "overwrite": true, "foldername": "/home/victim/.ssh"}
```
via `chia data add_missing_files --directory /home/victim/.ssh` or a direct RPC call.
4. Observe that DataLayer `.dat` files are written directly under `/home/victim/.ssh` (or any other path reachable by the process), demonstrating unrestricted write-path control by the RPC caller.

    async def add_missing_files(self, store_id: bytes32, overwrite: bool, foldername: Path | None) -> None:
        root = await self.data_store.get_tree_root(store_id=store_id)
        latest_generation = root.generation
        full_tree_first_publish_generation = max(0, latest_generation - self.maximum_full_file_count + 1)
        singleton_record = (
            await self.wallet_rpc.dl_latest_singleton(DLLatestSingleton(launcher_id=store_id, only_confirmed=True))
        ).singleton
        if singleton_record is None:
            self.log.error(f"No singleton record found for: {store_id}")
            return
        max_generation = min(singleton_record.generation, root.generation)
        server_files_location = foldername if foldername is not None else self.server_files_location
        files = []
        for generation in range(1, max_generation + 1):
            root = await self.data_store.get_tree_root(store_id=store_id, generation=generation)
            res = await write_files_for_root(
                self.data_store,
                store_id,
                root,
                server_files_location,
                full_tree_first_publish_generation,
                overwrite,
                self.group_files_by_store,
            )
            files.append(res.diff_tree.name)

async def write_files_for_root(
    data_store: DataStore,
    store_id: bytes32,
    root: Root,
    foldername: Path,
    full_tree_first_publish_generation: int,
    overwrite: bool = False,
    group_by_store: bool = False,
) -> WriteFilesResult:
    if root.node_hash is not None:
        node_hash = root.node_hash
    else:
        node_hash = bytes32.zeros  # todo change

    filename_full_tree = get_full_tree_filename_path(foldername, store_id, node_hash, root.generation, group_by_store)
    filename_diff_tree = get_delta_filename_path(foldername, store_id, node_hash, root.generation, group_by_store)
    filename_full_tree.parent.mkdir(parents=True, exist_ok=True)

    written = False
    mode: Literal["wb", "xb"] = "wb" if overwrite else "xb"

    written_full_file = False
    if root.generation >= full_tree_first_publish_generation:
        try:
            with open(filename_full_tree, mode) as writer:
                await data_store.write_tree_to_file(root, node_hash, store_id, False, writer)
            written = True
            written_full_file = True
        except FileExistsError:
            pass

    try:
        with open(filename_diff_tree, mode) as writer:
            await data_store.write_tree_to_file(root, node_hash, store_id, True, writer)
        written = True
    except FileExistsError:
        pass

    return WriteFilesResult(written, filename_full_tree if written_full_file else None, filename_diff_tree)
