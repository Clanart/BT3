### Title
Auction bids pinned to a `TargetTxHash` are silently orphaned by unprivileged nonce/fee-bump replacement, letting the target sender extract MEV protection without paying the winning bid - (File: `kaiax/auction/impl/builder.go`, `work/worker.go`)

### Summary
`AuctionModule.ExtractTxBundles` matches a searcher's signed bid to a pending transaction purely by exact transaction hash (`bidTargetMap[txHash]`), and `Task.shouldDiscardBundle` in the block builder enforces that the bid bundle only executes if it immediately follows a transaction whose hash equals `bundle.TargetTxHash`. This is structurally the same "off-chain ID pinning" pattern flagged in the CantoIdentity report, where `_addList` pinned a subprotocol-registration to an assumed `_cidNFTID` that could be invalidated by another party's ordinary, unprivileged transaction.

### Finding Description
A searcher builds and EIP-712-signs a `Bid` (`kaiax/auction/bid.go`) that hard-codes `TargetTxHash`, the hash of a specific pending transaction observed in the public mempool/RPC. [1](#0-0) 

When building a block, `AuctionModule.ExtractTxBundles` looks up bids strictly by comparing each candidate transaction's `tx.Hash()` against the bid pool's target-hash map for the mining block; any hash mismatch means the bid is simply skipped (`continue`), producing no bundle at all. [2](#0-1) 

Because a transaction's hash is a function of `nonce`, `gasPrice`/fee fields, `data`, etc., any unprivileged, ordinary action can change it before it lands in a block:
- The target sender (or anyone able to induce a nonce change, e.g. the sender themselves re-submitting with a bumped gas price, or a competing transaction from the same sender being included first) causes the originally-observed transaction to be replaced/re-signed, producing a new hash.
- Because gas price / EIP-1559 fee bumps are also unprivileged and permitted at any time via the public RPC, the target's hash can change purely as an artifact of normal fee-market activity, without any malicious intent, mirroring the "busy period" scenario in the original report.

Even when a bid does match a still-pending target hash, `Task.shouldDiscardBundle` re-validates positional adjacency at commit time: the bid bundle is discarded, and its error propagated, unless it immediately follows a transaction with the exact matching hash and that transaction succeeded. [3](#0-2) 

If the pinned target disappears (replaced, dropped, or reordered) between when the searcher signs the bid and when the block is assembled, the auction winner's bid bundle is unconditionally dropped from block construction with no fallback, exactly as `CidNFT.add()` reverted when its pinned `_cidNFTID` no longer belonged to the caller.

### Impact Explanation
Auction/MEV bids in Kaia are meant to guarantee the searcher exclusive execution rights (and payment obligation) tied to a specific pending transaction for a fee. Because matching is by exact tx hash rather than by an invariant identity (e.g., sender+nonce, or an allow-listed target range), any unprivileged nonce/fee-bump activity by the *target's own sender*, or ordinary mempool churn during high load, can silently invalidate a paid-for/committed bid:
- The searcher's signed bid (which may already reflect a deposit/gas reservation per `BidPool.getBidTxGasLimit`/`SetGasLimit`) becomes worthless for that block, while the underlying target transaction still executes normally without the MEV-protection/backrun the bid was purchased for.
- This creates a fee/auction-abuse vector: a target sender can grief the auction by trivially rotating their own transaction's hash (bump gas price by 1 wei, or reorder their own nonces) to evade a losing/expensive bid, since matching requires bit-for-bit hash equality rather than semantic equivalence of "this sender's next action."
- At scale (busy blocks, high tx churn), legitimate bids are non-deterministically dropped from block building even absent any adversary, causing auction settlement to diverge from proposer/auctioneer expectations block-to-block for the same logical target action — a state-divergence/auction-settlement-theft risk (searchers pay signature/deposit costs without receiving the auction primary right they contracted for).

### Likelihood Explanation
High. No special privilege is required — the only actions needed are ordinary, publicly reachable RPC calls (submitting a replacement/fee-bumped transaction, or simply operating during high mempool churn). The same root-cause class was rated Medium severity and confirmed in the original CantoIdentity audit for an analogous "ID-pinned-at-signing-time, invalidated-by-unprivileged-reordering" bug.

### Recommendation
Do not pin auction bids to a raw transaction hash captured off-chain at signing time. Instead:
- Bind bids to sender+nonce (or another invariant tuple) and re-derive/re-validate the *current* hash of that sender/nonce pair at bundle-extraction and commit time in `AuctionModule.ExtractTxBundles`/`Task.shouldDiscardBundle`, rather than requiring bit-for-bit equality to a stale hash.
- Alternatively, require searchers to re-sign/re-submit bids whenever the target's replacement is detected, and expose an explicit "bid orphaned" recovery/refund path so griefed searchers are not silently dropped without recourse.

### Proof of Concept
1. Target user `Alice` broadcasts transaction `Tx_A` (nonce `n`, gas price `p`) via public RPC.
2. Searcher observes `Tx_A`, computes `Tx_A.Hash()`, and submits a signed `Bid{TargetTxHash: Tx_A.Hash(), Bid: X}` via the auction bid submission path, which is accepted into `BidPool.bidTargetMap[minedBlock]`. [4](#0-3) 
3. Before the target block is built, `Alice` (unprivileged, no malicious intent required) resubmits `Tx_A` with a bumped gas price to `p'` (a normal fee-bump replacement) — the resulting `Tx_A'.Hash()` differs from the original.
4. At block building time, `AuctionModule.ExtractTxBundles` iterates the mined block's candidate txs; `Tx_A'.Hash()` is not present in `bidTargetMap`, so `continue` is hit and no bid bundle is produced for it. [5](#0-4) 
5. `Tx_A'` executes normally in the block without the searcher's bid/backrun being applied; the searcher's paid/committed bid is wasted, and the auction proceeds as if no bid existed for Alice's action.

func (env *Task) shouldDiscardBundle(bundle *builder.Bundle) (bool, error) {
	if !bundle.TargetRequired {
		return false, nil
	}
	if env.tcount == 0 {
		return bundle.TargetTxHash != common.Hash{}, fmt.Errorf("target tx %s does not precede the bundle", bundle.TargetTxHash.Hex())
	} else {
		// if `env.tcount` is not zero, the `bundle.TargetTxHash` must not be empty hash
		if bundle.TargetTxHash != env.txs[env.tcount-1].Hash() {
			return true, fmt.Errorf("target tx %s does not precede the bundle", bundle.TargetTxHash.Hex())
		}
		if env.receipts[env.tcount-1].Status != types.ReceiptStatusSuccessful {
			return true, fmt.Errorf("target tx %s failed with status %d", bundle.TargetTxHash.Hex(), env.receipts[env.tcount-1].Status)
		}
	}
	return false, nil
}

func (bp *BidPool) AddBid(bid *auction.Bid) (common.Hash, error) {
	if atomic.LoadUint32(&bp.running) == 0 {
		return common.Hash{}, auction.ErrAuctionPaused
	}

	if err := bp.validateBid(bid); err != nil {
		return common.Hash{}, err
	}

	if err := bp.insertBid(bid); err != nil {
		return common.Hash{}, err
	}

	gasLimit, err := bp.getBidTxGasLimit(bid)
	if err != nil {
		return common.Hash{}, err
	}
	bid.SetGasLimit(gasLimit)

	bp.newBidCh <- bid

	return bid.Hash(), nil
}
