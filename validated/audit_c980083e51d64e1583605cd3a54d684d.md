### Title
`WombatStaking.withdraw()` and pool helpers hardcode the token recipient to `msg.sender`, permanently freezing principal for blacklisted stablecoin holders - (File: `wombat/WombatStaking.sol`, `wombat/WombatPoolHelper.sol`)

### Summary
`WombatStaking.withdraw()` always sends the withdrawn `depositToken` to the `_sender` parameter, which every pool helper (`WombatPoolHelper`, `WombatPoolHelperV2`, `AnkrBNBPoolHelper`) hardcodes to `msg.sender`. There is no way to specify an alternate recipient. If the `depositToken` is a blacklist-capable stablecoin (e.g. USDC) and the withdrawing wallet gets blacklisted, the `safeTransfer` in `withdraw()` will always revert, and the user has no alternative path to recover their principal.

### Finding Description
The user-facing entry point is `WombatPoolHelper.withdraw(uint256 _liquidity, uint256 _minAmount)`, which calls `IWombatStaking(wombatStaking).withdraw(lpToken, _liquidity, _minAmount, msg.sender)` and then unstakes via `IMasterMagpie(masterMagpie).withdrawFor(stakingToken, _liquidity, msg.sender)`. [1](#0-0) 

Inside `WombatStaking.withdraw()`, the underlying `depositToken` (e.g., USDC) is unconditionally transferred to `_sender`:
```solidity
IERC20(poolInfo.depositToken).safeTransfer(
    _sender,
    IERC20(poolInfo.depositToken).balanceOf(address(this)) - beforeWithdraw
);
``` [2](#0-1) 

Unlike the reward-distribution functions in this codebase (`BaseRewardPool.getReward`, `vlMGPBaseRewarder.getReward/getRewards`, `mWOMSVBaseRewarder.getReward`), which already accept an explicit `_receiver` parameter separate from `_account` [3](#0-2) , the principal-withdrawal path in `WombatStaking`/pool helpers provides no such flexibility — the recipient is always derived from `msg.sender` at every layer (`WombatPoolHelper.withdraw` → `WombatStaking.withdraw` → `safeTransfer(_sender, ...)`).

Critically, the staked position tracked in `MasterMagpie` (via `depositFor`/`withdrawFor`) is an internal balance keyed to the user's address, not a transferable ERC20/NFT position. `MasterMagpie.sol` exposes no `transfer` function for staking positions, so — unlike the original Uniswap V3 `tokenId` in the analog report, which is an ERC721 and can be transferred to a non-blacklisted address to work around the issue — a Wombat LP's staked position here cannot be moved to another wallet before withdrawal. This removes the workaround that made the original finding judge-rejected as "acceptable design."

### Impact Explanation
If a user's wallet is added to the blacklist of the pool's `depositToken` (e.g., USDC) after they have staked through `WombatPoolHelper`/`WombatStaking`, every subsequent `withdraw()` call reverts at the `safeTransfer` step. Since the staked position cannot be reassigned or transferred to a different address, and no recipient parameter exists anywhere in the withdrawal path, the user's principal (and any residual claim tied to it) becomes permanently unrecoverable — a genuine, unprivileged-wallet-triggered permanent freeze of funds.

### Likelihood Explanation
This requires the depositToken to be a blacklist-capable asset (e.g., USDC, USDT) and the user's own wallet to become blacklisted by that token's issuer — an event outside the protocol's control but realistic for centralized stablecoins commonly used as Wombat pool deposit tokens. No malicious admin or governance action is required; it is purely a consequence of the withdrawal function's rigid recipient handling.

### Recommendation
Add an explicit `recipient` parameter to `WombatPoolHelper.withdraw()`/`WombatPoolHelperV2.withdraw()`/`AnkrBNBPoolHelper.withdraw()` and thread it through to `WombatStaking.withdraw()`, replacing the hardcoded `msg.sender`/`_sender` token destination, mirroring the `_receiver` pattern already used in the reward-collection contracts.

### Proof of Concept
1. User deposits stablecoin `USDC` via `WombatPoolHelper.deposit()`, which stakes the resulting `stakingToken` into `MasterMagpie` under the user's address (non-transferable position).
2. User's address subsequently gets added to the USDC blacklist by the issuer.
3. User calls `WombatPoolHelper.withdraw(_liquidity, _minAmount)`.
4. Call chain reaches `WombatStaking.withdraw()`, which attempts `IERC20(USDC).safeTransfer(msg.sender, amount)` — this reverts because `msg.sender` is blacklisted.
5. Because the staked position is not transferable, the user cannot assign it to a non-blacklisted wallet, and no recipient override exists anywhere in the call path, so the deposited principal remains permanently locked in the contract.

        address _lpToken,
        uint256 _liquidity,
        uint256 _minAmount,
        address _sender
    ) nonReentrant whenNotPaused _onlyPoolHelper(_lpToken) external {
        Pool storage poolInfo = pools[_lpToken];

        _toMasterWomAndSendReward(_lpToken, _liquidity, false);

        uint256 beforeWithdraw = IERC20(poolInfo.depositToken).balanceOf(address(this));

            address(this),
            block.timestamp

            _sender,
            IERC20(poolInfo.depositToken).balanceOf(address(this)) - beforeWithdraw
        );

        emit NewWithdraw(_sender, poolInfo.depositToken, _liquidity);
    }
