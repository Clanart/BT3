Based on my research, I found a concrete local analog: **`HostManager.sol` and `BandwidthManager.sol` authenticate cross-chain admin messages by checking only the coarse chain-level `request.source`, never the module-level `request.from`** — exactly the same class of flaw as the seed report (checking a coarser identity property instead of the specific origin that actually matters).

### Title
Missing module-level (`request.from`) origin check on `HostManager.onAccept` allows any Hyperbridge-chain sender to forge privileged governance messages - (File: `evm/src/core/HostManager.sol`)

### Summary
`HostManager.onAccept` gates privileged `Withdraw` and `SetHostParam` actions solely on `request.source.equals(IHost(_params.host).hyperbridge())` [1](#0-0) . This only verifies which *chain* the message came from, not which *module/pallet* on that chain sent it. Compare this with `HyperFungibleTokenUpgradeable.onAccept`, which enforces both the chain check *and* an explicit module-identity check via `keccak256(request.from) != keccak256(expectedSource)` [2](#0-1) . `BandwidthManager` has the identical gap, per its own documentation: "checks `request.source == IDispatcher(_host).hyperbridge()`. Only messages dispatched from Hyperbridge are honored... no module-id lookup." [3](#0-2) 

### Finding Description
`request.source` is not attacker-influenced at the ISMP-dispatch layer — `pallet_ismp`'s `IsmpDispatcher::dispatch_request` unconditionally sets `source: self.host_state_machine()` for *every* outgoing request from the Hyperbridge chain, regardless of which pallet or account triggered the dispatch [4](#0-3) . This means `request.source == hyperbridge()` is true for literally any message leaving the chain — it carries zero information about which pallet/module actually authored the payload. The `request.from` field is the only wire-level signal of module identity, and it is fully attacker/caller-controlled by whichever code path invokes `dispatch_request` (the `from` field is passed straight through from `DispatchPost.from` [5](#0-4) ).

`HostManager.onAccept` treats the coarse, always-true `request.source` check as sufficient proof that the message is an authorized governance directive, and never checks `request.from` against an allow-listed pallet identity before calling `IHostManager(_params.host).withdraw(...)` or `updateHostParams(...)` [6](#0-5) . This is structurally identical to the reported Optimism bug: a privileged state-mutating path relies on a check that only validates a broad/trivially-true property of the message and skips validating the specific origin that should gate the action.

### Impact Explanation
If any dispatch path on the Hyperbridge chain lets a caller set an arbitrary `to` (destination contract) and `body` (payload) for a `DispatchPost` — which the public `IsmpDispatcher` interface is explicitly designed to allow modules/pallets to do [7](#0-6)  — the resulting message would target `HostManager` on any EVM chain with `body[0] = OnAcceptActions.Withdraw` or `OnAcceptActions.SetHostParam`, and `HostManager.onAccept` would execute it because it never verifies `request.from`. This can drain the fee token / native ETH balance of the `EvmHost` to an arbitrary beneficiary via `withdraw()`, or fully rewrite `HostParams` (handler, consensusClient, admin, hostManager, challengePeriod, etc.) via `updateHostParams()` — a complete compromise of the bridge's trust root on that chain.

### Likelihood Explanation
I could not confirm, within the code available to me, that a *production, permissionless* pallet extrinsic currently exposes fully attacker-controlled `to` + `body` for dispatch (the only concrete dispatch call sites I found — `pallet-ismp-demo`, `pallet-intents-coprocessor`'s governance dispatcher — use hardcoded `from`/bodies or are governance-gated internal calls, not directly user-facing with arbitrary body). The generic user-facing `send_message(origin, post: DispatchPost, fee)` pattern that would make this trivially exploitable is documented in `docs/content/developers/polkadot/dispatching.mdx` only as an illustrative example for pallet authors, not confirmed as live runtime code. This is a real and confirmed **missing-authentication defect in `HostManager.sol`/`BandwidthManager.sol`** (source-only check vs. the stricter source+from check used elsewhere in the same codebase), but full exploitability by an unprivileged, non-pallet-author attacker depends on whether any currently-deployed pallet routes user-influenced `to`/`body` through the generic dispatcher toward a `HostManager`/`BandwidthManager` address — which I was unable to verify from the indexed code.

### Recommendation
Add an explicit module-identity allowlist check in `HostManager.onAccept` (and `BandwidthManager.onAccept`), mirroring `HyperFungibleTokenUpgradeable`'s pattern: store the expected governance-pallet module id (`ModuleId::Pallet(...)`) and verify `keccak256(request.from) == keccak256(expectedGovernanceModuleId)` in addition to the `request.source == hyperbridge()` chain check, before executing `Withdraw`/`SetHostParam`/pricing-update actions.

### Proof of Concept
1. On the Hyperbridge chain, any code path capable of invoking `IsmpDispatcher::dispatch_request` (via `pallet_ismp::Pallet::<T>::dispatch_request`, which unconditionally sets `source = host_state_machine()` [8](#0-7) ) constructs a `DispatchPost { dest: StateMachine::Evm(target_chain), from: attacker_chosen_bytes, to: HostManager_address, timeout: 0, body: [0u8 /* Withdraw */, abi.encode(WithdrawParams{ beneficiary: attacker, token: fee_token, amount: full_balance }) ] }`.
2. The request is relayed and delivered to `EvmHost.dispatchIncoming`, which calls `HostManager.onAccept`.
3. `onAccept` checks only `request.source.equals(hyperbridge())` — true by construction — and never checks `request.from` [9](#0-8) .
4. `IHostManager(_params.host).withdraw(withdrawParams)` executes, transferring the host's fee-token balance to the attacker-chosen beneficiary.

    function onAccept(IncomingPostRequest calldata incoming) external override restrict(_params.host) {
        PostRequest calldata request = incoming.request;
        // Only the Hyperbridge parachain can send requests to this module.
        if (!request.source.equals(IHost(_params.host).hyperbridge())) revert UnauthorizedAction();

        OnAcceptActions action = OnAcceptActions(uint8(request.body[0]));
        if (action == OnAcceptActions.Withdraw) {
            // This is where governance & relayers can withdraw their revenue.
            WithdrawParams memory withdrawParams = abi.decode(request.body[1:], (WithdrawParams));
            IHostManager(_params.host).withdraw(withdrawParams);
        } else if (action == OnAcceptActions.SetHostParam) {
            HostParams memory hostParams = abi.decode(request.body[1:], (HostParams));
            IHostManager(_params.host).updateHostParams(hostParams);
        }
    }

		&self,
		request: DispatchRequest,
		fee: FeeMetadata<T>,
	) -> Result<H256, anyhow::Error> {
		// collect payment for the request
		if fee.fee != Zero::zero() {
			T::Currency::transfer(
				&fee.payer,
				&RELAYER_FEE_ACCOUNT.into_account_truncating(),
				fee.fee,
				Preservation::Expendable,
			)
			.map_err(|err| IsmpError::Custom(format!("Error withdrawing request fees: {err:?}")))?;
		}

		let request = match request {
			DispatchRequest::Get(dispatch_get) => {
				let get = GetRequest {
					source: self.host_state_machine(),
					dest: dispatch_get.dest,
					nonce: self.next_nonce(),
					from: dispatch_get.from,
					keys: dispatch_get.keys,
					height: dispatch_get.height,
					context: dispatch_get.context,
					timeout_timestamp: if dispatch_get.timeout == 0 {
						0
					} else {
						<T::TimestampProvider as UnixTime>::now()
							.as_secs()
							.saturating_add(dispatch_get.timeout)
					},
				};
				Request::Get(get)
			},
			DispatchRequest::Post(dispatch_post) => {
				let post = PostRequest {
					source: self.host_state_machine(),
					dest: dispatch_post.dest,
					nonce: self.next_nonce(),
					from: dispatch_post.from,
					to: dispatch_post.to,
					timeout_timestamp: if dispatch_post.timeout == 0 {
						0
					} else {
						<T::TimestampProvider as UnixTime>::now()
							.as_secs()
							.saturating_add(dispatch_post.timeout)
					},
					body: dispatch_post.body,
				};
				Request::Post(post)

		};
