### Title
Governance-settable `Kip71GasTarget = 0` causes division-by-zero panic in KIP-71 base fee calculation - (File: params/kip71_config.go)

### Summary
The `KIP71.GasTarget` governance parameter, which is a divisor in the KIP-71 (Magma) dynamic base fee formula, has no validation preventing it from being set to `0`. Unlike `Kip71BaseFeeDenominator`, which explicitly rejects `0` in its `FormatChecker`, `Kip71GasTarget` uses `noopFormatChecker`, allowing an all-zero value to be accepted into the governance parameter set. This value is later used unguarded as a divisor in `KIP71Config.NextMagmaBlockBaseFee`, causing a `big.Int` division-by-zero panic (analogous to CVE-2024-50287's unguarded division in `tpg_precalculate_line()`).

### Finding Description
The governance parameter registry defines `Kip71GasTarget` with a no-op format checker, in contrast to the sibling `Kip71BaseFeeDenominator` parameter which explicitly guards against zero: [1](#0-0) 

`GasTarget` is used directly as a divisor inside `NextMagmaBlockBaseFee`, which computes the next block's base fee (KIP-71 / Magma fork): [2](#0-1) 

Specifically:
- The code has a defensive zero-check for `BaseFeeDenominator == 0` (substituting a fallback value of `64`) at lines 71-76, but has **no equivalent guard for `GasTarget == 0`**.
- If `GasTarget == 0` and `parentGasUsed > 0` (true for essentially any non-empty block), execution takes the "gas used above target" branch: [3](#0-2) 
  `y := x.Div(x, new(big.Int).SetUint64(gasTarget))` divides by zero (`gasTarget` is `0`), which panics in Go's `math/big` package.
- If `parentGasUsed == 0 == GasTarget`, the function returns early without dividing (line 90-91), so the panic is only triggered once a block actually consumes gas — which happens on essentially every produced block.

This function is invoked from block header validation (`VerifyMagmaHeader`/`NextMagmaBlockBaseFee`) via `blockchain/block_validator.go`, and also from base-fee suggestion logic in `node/cn/gasprice/feehistory.go` and `node/cn/gasprice/gasprice.go`, and block assembly in `work/worker.go` — i.e., every node that validates or builds a block after the parameter takes effect.

### Impact Explanation
Once `GasTarget` is set to `0` via a governance vote/parameter update (a normal governance parameter change path, in-scope per the assessment rules), **every node in the network** panics while validating or producing the very next block with nonzero gas usage. This is a chain-halting denial of service affecting block assembly and header validation network-wide — a state-transition/consensus availability failure impacting all transaction senders, not merely the party that set the parameter. This matches the "state divergence between honest nodes / acceptance-of-invalid-block-class" impact category (in this case, total halt rather than divergence, but functionally a consensus-critical failure caused by an unguarded division, directly analogous to the reported kernel bug class).

### Likelihood Explanation
Likelihood is Medium: it requires a governance parameter change to set `Kip71GasTarget` to `0`, which is a legitimate, in-scope governance action but requires governance council approval rather than being reachable from an arbitrary unprivileged transaction. However, because there is no format-level validation rejecting `0` (unlike the analogous `BaseFeeDenominator` parameter which explicitly guards this exact class of bug), a single mis-configured or malicious governance proposal is sufficient to trigger a full network halt, with no other defense in depth (e.g., no `WARN_ON_ONCE`/early-return safeguard as recommended by the upstream Linux fix).

### Recommendation
Add a `FormatChecker` for `Kip71GasTarget` in `kaiax/gov/param.go` that rejects `0`, matching the existing pattern for `Kip71BaseFeeDenominator` (`return ok && v != 0`). Additionally, add a defensive zero-check inside `NextMagmaBlockBaseFee` in `params/kip71_config.go` (mirroring the existing `BaseFeeDenominator == 0` fallback) so that a `GasTarget == 0` value already present in an active chain configuration cannot cause a division-by-zero panic during header validation or block assembly.

### Proof of Concept
1. Submit/pass a governance vote setting `governance.kip71.gastarget` to `0` (accepted because `Kip71GasTarget`'s `FormatChecker` is `noopFormatChecker`): [4](#0-3) 
2. Once the parameter becomes active at the target block, any block with `GasUsed > 0` is produced or validated.
3. `NextMagmaBlockBaseFee` is invoked with `parentHeaderGasUsed > 0` and `kc.GasTarget == 0`; it takes the `parentGasUsed > gasTarget` branch and executes `x.Div(x, new(big.Int).SetUint64(0))`: [5](#0-4) 
4. Go's `big.Int.Div` panics on division by zero, crashing every node calling this path (block validators, block proposers, gas price oracle) — halting the chain.

```go
func (kc *KIP71Config) NextMagmaBlockBaseFee(parentHeaderNumber *big.Int, parentHeaderBaseFee *big.Int, parentHeaderGasUsed uint64) *big.Int {
	// governance parameters
	lowerBoundBaseFee := new(big.Int).SetUint64(kc.LowerBoundBaseFee)
	upperBoundBaseFee := new(big.Int).SetUint64(kc.UpperBoundBaseFee)
	makeEvenByCeil(lowerBoundBaseFee)
	makeEvenByFloor(upperBoundBaseFee)

	// If the parent is the magma disabled block or genesis, then return the lowerBoundBaseFee (default 25ston)
	if parentHeaderNumber.Cmp(new(big.Int).SetUint64(0)) == 0 || parentHeaderBaseFee == nil {
		return makeEvenByFloor(lowerBoundBaseFee)
	}

	var baseFeeDenominator *big.Int
	if kc.BaseFeeDenominator == 0 {
		// To avoid panic, set the fluctuation range small
		baseFeeDenominator = new(big.Int).SetUint64(64)
	} else {
		baseFeeDenominator = new(big.Int).SetUint64(kc.BaseFeeDenominator)
	}
	gasTarget := kc.GasTarget
	upperGasLimit := kc.MaxBlockGasUsedForBaseFee

	// check the case of upper/lowerBoundBaseFee is updated by governance mechanism
	parentBaseFee := parentHeaderBaseFee
	if parentBaseFee.Cmp(upperBoundBaseFee) >= 0 {
		parentBaseFee = upperBoundBaseFee
	} else if parentBaseFee.Cmp(lowerBoundBaseFee) <= 0 {
		parentBaseFee = lowerBoundBaseFee
	}

	// upper gas limit cut off the impulse of used gas to upper bound
	parentGasUsed := min(parentHeaderGasUsed, upperGasLimit)
	if parentGasUsed == gasTarget {
		return makeEvenByFloor(parentBaseFee)
	} else if parentGasUsed > gasTarget {
		// shortcut. If parentBaseFee is already reached upperbound, do not calculate.
		if parentBaseFee.Cmp(upperBoundBaseFee) == 0 {
			return makeEvenByFloor(upperBoundBaseFee)
		}
		// If the parent block used more gas than its target,
		// the baseFee of the next block should increase.
		// baseFeeDelta = max(1, parentBaseFee * (parentGasUsed - gasTarget) / gasTarget / baseFeeDenominator)
		gasUsedDelta := new(big.Int).SetUint64(parentGasUsed - gasTarget)
		x := new(big.Int).Mul(parentBaseFee, gasUsedDelta)
		y := x.Div(x, new(big.Int).SetUint64(gasTarget))
		baseFeeDelta := math.BigMax(x.Div(y, baseFeeDenominator), common.Big1)

		nextBaseFee := x.Add(parentBaseFee, baseFeeDelta)
		if nextBaseFee.Cmp(upperBoundBaseFee) > 0 {
			return makeEvenByFloor(upperBoundBaseFee)
		}
		return makeEvenByFloor(nextBaseFee)
	} else {
		// shortcut. If parentBaseFee is already reached lower bound, do not calculate.
		if parentBaseFee.Cmp(lowerBoundBaseFee) == 0 {
			return makeEvenByFloor(lowerBoundBaseFee)
		}
		// Otherwise if the parent block used less gas than its target,
		// the baseFee of the next block should decrease.
		// baseFeeDelta = parentBaseFee * (gasTarget - parentGasUsed) / gasTarget / baseFeeDenominator
		gasUsedDelta := new(big.Int).SetUint64(gasTarget - parentGasUsed)
		x := new(big.Int).Mul(parentBaseFee, gasUsedDelta)
		y := x.Div(x, new(big.Int).SetUint64(gasTarget))
		baseFeeDelta := x.Div(y, baseFeeDenominator)

		nextBaseFee := x.Sub(parentBaseFee, baseFeeDelta)
		if nextBaseFee.Cmp(lowerBoundBaseFee) < 0 {
			return makeEvenByFloor(lowerBoundBaseFee)
		}
		return makeEvenByFloor(nextBaseFee)
	}
}
```
