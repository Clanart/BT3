### Title
CW pointer contracts can forge ERC-20/721/1155 event logs in the synthetic EVM receipt without any provenance tying the log to an actual token balance change - ([File: app/receipt.go])

### Summary
`AddCosmosEventsToEVMReceiptIfApplicable` synthesizes EVM `Transfer`/`Mint`/`Approval` log entries for CW20/CW721/CW1155 pointer contracts directly from the raw `wasm` module events emitted during `MsgExecuteContract` calls, trusting the `action`, `amount`, `from`, `to`, `owner`, `sender`, `recipient` attributes verbatim with no cross-check against the pointer's actual token state.

### Finding Description
When a wasm contract that has been registered as a CW20/CW721/CW1155 pointer (`AddCW20`/`AddCW721`/`AddCW1155`, e.g. [1](#0-0) ) executes, `app.AddCosmosEventsToEVMReceiptIfApplicable` scans all `wasm`-type events in the tx's Cosmos events, matches the event's `_contract_address` attribute against the known pointer's CW contract address, and if it matches calls `translateCW20Event`/`translateCW721Event`/`translateCW1155Event` [2](#0-1) .

Those translators call `GetActionsFromWasmEvent`, which parses `action`, `amount`, `from`, `to`, `sender`, `recipient`, `owner`, `spender`, `operator`, and `token_id(s)` attributes straight out of the wasm event and builds an `Action` struct with no validation [3](#0-2) . `translateCW20Event` then emits a synthetic `ERC20TransferTopic` log carrying that `amount`, `from`, and `to` for any action type in `{"mint","burn","send","transfer","transfer_from","send_from","burn_from"}` [4](#0-3) , and `translateCW1155Event`/`translateCW721Event` do the same for their respective ERC event topics [5](#0-4) [6](#0-5) .

Nothing in this pipeline verifies that the emitted `wasm` event actually corresponds to a genuine balance/ownership change inside the CW contract's own state — it is the CW contract's own free-form event attributes (`action=mint`, `amount=<anything>`, `to=<anything>`) that drive the synthetic ERC log. Any account can permissionlessly deploy a CW20/CW721/CW1155-shaped contract and register it as a pointer (subject only to the contract answering `token_info`/`contract_info` queries, see `AddCW20`/`AddCW721` in [1](#0-0) ), then have that contract emit a `wasm` event with attacker-chosen `action`, `amount`, `from`, and `to` attributes that do not reflect any real CW20/721/1155 state mutation. The receipt/log-synthesis code accepts this event with no provenance check tying it back to an actual authorized state transition inside the pointee contract, directly mirroring the "exec lifecycle event forged without provenance" bug class in the external report: a downstream consumer (the receipt) treats attacker-supplied event data as an authoritative record of an underlying, authorized action.

### Impact Explanation
EVM JSON-RPC clients, indexers, exchanges, and bridges commonly rely on receipt `logs` (ERC20 `Transfer`, ERC721 `Transfer`, ERC1155 `TransferSingle/Batch`) as the canonical record of token movements. Because the log synthesis trusts wasm event attributes without validating them against actual contract storage/state changes, an attacker-controlled pointer contract can emit fabricated `Transfer`/`mint` events for arbitrary amounts and arbitrary `to` addresses that never actually moved any value. Any off-chain system that credits balances, arbitrage, or triggers withdrawals based on observing these synthetic Transfer logs can be tricked into crediting funds that were never actually transferred — a fund-loss vector via forged pointer-originated transfer events, matching the "unauthorized transfer via precompile or pointer" acceptance criterion.

### Likelihood Explanation
Any unprivileged user can deploy an arbitrary CosmWasm contract, register it as a CW20/CW721/CW1155 pointer via the permissionless `pointer` precompile (subject to it responding to a metadata query), and then call `MsgExecuteContract`/an EVM call routed through the wasmd precompile that makes the contract emit a crafted `wasm` event. This requires no special privileges, validator control, or race condition — only a standard transaction and a contract whose code emits the right event attributes. This is reachable purely through the standard tx/wasm/pointer/EVM-receipt path.

### Recommendation
Do not synthesize ERC-style events purely from free-form wasm event attributes. Either (a) restrict this translation to a small, fixed, non-spoofable set of official CW20/CW721/CW1155 reference contracts (verified by code hash) whose emitted attributes are guaranteed to match real state changes, or (b) cross-validate each synthesized log against an actual balance/ownership delta queried from the pointee contract's own state before/after execution (similar to a "provenance" check binding the event to a verified state transition), rejecting/discarding logs whose claimed transfer is not corroborated by an actual state change.

### Proof of Concept
1. Deploy a minimal CosmWasm contract `Evil` that implements a `token_info` query (to satisfy `AddCW20`) but whose `execute` entrypoint, regardless of input, emits:
   ```
   wasm: {_contract_address: <Evil>, action: "mint", amount: "1000000000000", to: "<attacker sei addr>"}
   ```
   without performing any real balance update in its own contract storage.
2. Call the `pointer` precompile's `addCW20Pointer(<Evil address>)` to register a CW20 ERC20 pointer contract for `Evil`.
3. Submit `MsgExecuteContract` targeting `Evil` (any payload).
4. Observe the resulting EVM transaction receipt (via `eth_getTransactionReceipt` or `eth_getLogs`): a synthetic `Transfer(0x0, attacker, 1000000000000)` log appears on the pointer's ERC20 address, generated by `AddCosmosEventsToEVMReceiptIfApplicable`/`translateCW20Event`, even though `Evil`'s own CW20 state never recorded any such mint. An off-chain indexer or bridge watching for `Transfer` events on the pointer address would incorrectly treat this as a legitimate mint.

func (app *App) translateCW1155Event(ctx sdk.Context, wasmEvent abci.Event, pointerAddr common.Address, contractAddr string) (res []*ethtypes.Log) {
	for _, action := range app.GetActionsFromWasmEvent(ctx, wasmEvent) {
		switch action.Type {
		case "transfer_single", "mint_single", "burn_single":
			fromHash := EmptyHash
			toHash := EmptyHash
			if action.Type != "mint_single" {
				fromHash = action.Owner
			}
			if action.Type != "burn_single" {
				toHash = action.Recipient
			}
			if action.TokenId == nil {
				continue
			}
			if action.Amount == nil {
				continue
			}
			dataHash1 := common.BigToHash(action.TokenId).Bytes()
			dataHash2 := common.BigToHash(action.Amount).Bytes()
			res = append(res, &ethtypes.Log{
				Address: pointerAddr,
				Topics: []common.Hash{
					ERC1155TransferSingleTopic,
					action.Sender,
					fromHash,
					toHash,
				},
				Data: append(dataHash1, dataHash2...),
			})
		case "transfer_batch", "mint_batch", "burn_batch":
			fromHash := EmptyHash
			toHash := EmptyHash
			if action.Type != "mint_batch" {
				fromHash = action.Owner
			}
			if action.Type != "burn_batch" {
				toHash = action.Recipient
			}
			if len(action.TokenIds) == 0 {
				continue
			}
			if len(action.Amounts) == 0 {
				continue
			}
			dataArgs := cw1155.GetParsedABI().Events["TransferBatch"].Inputs.NonIndexed()
			value, err := dataArgs.Pack(action.TokenIds, action.Amounts)
			if err != nil {
				logger.Error("Failed to parse TransferBatch event data", "err", err)
				continue
			}
			res = append(res, &ethtypes.Log{
				Address: pointerAddr,
				Topics: []common.Hash{
					ERC1155TransferBatchTopic,
					action.Sender,
					fromHash,
					toHash,
				},
				Data: value,
			})
		case "approve_all":
			res = append(res, &ethtypes.Log{
				Address: pointerAddr,
				Topics: []common.Hash{
					ERC1155ApprovalForAllTopic,
					action.Sender,
					action.Operator,
				},
				Data: TrueHash.Bytes(),
			})
		case "revoke_all":
			res = append(res, &ethtypes.Log{
				Address: pointerAddr,
				Topics: []common.Hash{
					ERC1155ApprovalForAllTopic,
					action.Sender,
					action.Operator,
				},
				Data: EmptyHash.Bytes(),
			})
		}
	}
	return
}

func (app *App) GetActionsFromWasmEvent(ctx sdk.Context, event abci.Event) (actions []*Action) {
	for _, attr := range event.Attributes {
		key := string(attr.Key)
		value := string(attr.Value)
		if key == "action" {
			actions = append(actions, &Action{Type: value})
			continue
		}
		if len(actions) == 0 {
			continue
		}
		curAction := actions[len(actions)-1]
		switch key {
		case "amount":
			curAction.Amount = safeBigIntFromString(value)
		case "amounts":
			curAction.Amounts = utils.Map(strings.Split(value, ","), safeBigIntFromString)
		case "token_id":
			curAction.TokenId = safeBigIntFromString(value)
		case "token_ids":
			curAction.TokenIds = utils.Map(strings.Split(value, ","), safeBigIntFromString)
		case "sender":
			curAction.Sender = app.GetEvmAddressHash(ctx, value)
		case "recipient":
			curAction.Recipient = app.GetEvmAddressHash(ctx, value)
		case "spender":
			curAction.Spender = app.GetEvmAddressHash(ctx, value)
		case "operator":
			curAction.Operator = app.GetEvmAddressHash(ctx, value)
		case "owner":
			curAction.Owner = app.GetEvmAddressHash(ctx, value)
		case "from":
			curAction.From = app.GetEvmAddressHash(ctx, value)
		case "to":
			curAction.To = app.GetEvmAddressHash(ctx, value)
		}
	}
	return
}
