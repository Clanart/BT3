No vulnerability found for this question.

**Reasoning:**

The premise conflates two unrelated mechanisms:

1. **"Add certificate" button does not use `suppressCertificateErrorFor`.** Clicking "Add certificate" in `UntrustedCertificate.onContinue` calls `props.onContinue(certificate)` [1](#0-0) , which in `app.tsx` is wired to `onContinueWithUntrustedCertificate`, calling `showCertificateTrustDialog(certificate, message)` [2](#0-1) . That proxies over IPC to `show-certificate-trust-dialog` in the main process, which invokes Electron's/OS's native `dialog.showCertificateTrustDialog`, i.e. it asks the OS to add the certificate to the system trust store [3](#0-2) . This is entirely disconnected from `suppress-certificate-error.ts`.

2. **`suppressCertificateErrorFor` is keyed by an exact, single-use URL string, not by host/origin.** The `suppressedUrls` set stores and checks the full URL string with exact equality [4](#0-3) . Its only caller, `isGitHubHost` in `api.ts`, deliberately appends a `crypto.randomUUID()` nonce to the probe URL specifically "to make sure our certificate error suppression only catches this request," and clears the suppression in a `finally` block immediately after the probe completes [5](#0-4) . There is no host-based or origin-based generalization anywhere in this logic.

3. **The renderer-side certificate handler only checks suppression for that identical, single-use URL** before deciding whether to surface the `UntrustedCertificate` popup [6](#0-5) . A MITM on a different (or even the same) host cannot reuse a stale suppression entry because the exact URL (with its unique nonce) is removed right after use, and no credential-bearing API/git request path calls `suppressCertificateErrorFor` at all.

Given both premises of the question are factually incorrect — the "Add certificate" UI action does not route through `suppressCertificateErrorFor`, and that function's suppression key is an exact, single-use, non-reusable URL rather than a host/origin — there is no bypass path for a MITM to exploit as described.

const suppressedUrls = new Set<string>()

export function suppressCertificateErrorFor(url: string) {
  suppressedUrls.add(url)
}

export function clearCertificateErrorSuppressionFor(url: string) {
  suppressedUrls.delete(url)
}

export function isCertificateErrorSuppressedFor(url: string) {
  return suppressedUrls.has(url)
}
