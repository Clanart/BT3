### Title
`ReceivedOutput::read` credits an output as spendable without checking the offset actually derives the output's `script_pubkey` — ([File: networks/bitcoin/src/wallet/mod.rs](networks/bitcoin/src/wallet/mod.rs))

### Summary
The bug class is "an operation's success is assumed while a required check/fallible step is skipped or its failure ignored, so the protocol credits value it never actually received." In `Vault.vy` the skipped check was the return value of the WETH `deposit()` call; here the skipped check is the consistency between a claimed scalar `offset` and the `script_pubkey` of the `TxOut` it purports to unlock. `ReceivedOutput::read` deserializes `(offset, output, outpoint)` from untrusted bytes and accepts the triple unconditionally.

### Finding Description
`ReceivedOutput` is Serai's representation of a spendable Bitcoin output: an `offset` scalar that, added to the scanner's internal key, yields the tweaked Taproot key controlling the output. Legitimate instances are only produced by `Scanner::scan_transaction`, which looks up `output.script_pubkey` in `self.scripts` and therefore guarantees `key + G*offset` maps to the output's script [1](#0-0) .

However, `ReceivedOutput::read` — the deserialization path used to reconstruct these objects from bytes — performs no such check. It reads a scalar via `Secp256k1::read_F`, then decodes an arbitrary `TxOut` and `OutPoint`, and returns `Ok(ReceivedOutput { offset, output, outpoint })` without verifying that `p2tr_script_buf(scanner_key + G*offset) == output.script_pubkey` [2](#0-1) . Analogous to the unchecked `raw_call` in `fund_account_eth()` (where the credited `msg.value` was never actually deposited), a deserialized `ReceivedOutput` credits the wallet with an output whose `offset` may not correspond to its `script_pubkey` at all. An unprivileged party feeding bytes into `ReceivedOutput::read` can therefore claim:

- an `offset` producing an odd internal key (no valid P2TR script exists — `p2tr_script_buf` returns `None` [3](#0-2) ),
- an `offset` deriving a completely different tweaked key than the output's, or
- a `script_pubkey` belonging to someone else entirely,

while the output is still reported as a spendable `ReceivedOutput` carrying a `value()` [4](#0-3) .

### Impact Explanation
Downstream signing consumes `output.offset()` to derive the spend key (`key + offset`, then TapTweak/parity handling as in `tweak_keys` [5](#0-4) ). For a forged `ReceivedOutput`, the produced Schnorr signature cannot satisfy the output's actual `script_pubkey`, so the input is unspendable. Any funds-accounting or transaction-construction logic that trusts `ReceivedOutput`s from `read` will report received funds that are not spendable — the same "credited but not owned" end state as the WETH margin bug. Depending on integrator flow, this can also induce the wallet to build transactions spending phantom inputs (wasting fees, or bricking a batch that aggregates the forged input with real ones).

### Likelihood Explanation
Reachable whenever `ReceivedOutput::read` is applied to bytes influenced by an untrusted party (coordinator messages, peer-provided scan results, or restored state an attacker can corrupt), which is the explicit threat model for the `read_*` APIs. The primitive itself is trivial: write any valid scalar encoding followed by any valid `TxOut`/`OutPoint`. Note: if `ReceivedOutput`s are only ever produced in-process by `Scanner` and never round-tripped through attacker-influenced bytes, this reduces to a defense-in-depth gap.

### Recommendation
Bind the offset to the output at deserialization or first use: add a `ReceivedOutput::verify(key)` / checked constructor that recomputes `p2tr_script_buf(key + G*offset)` and compares against `output.script_pubkey`, returning `None`/error on mismatch — i.e., do exactly what `Scanner::scan_transaction` does implicitly. Alternatively, store the scanner key (or the derived tweaked key) inside `ReceivedOutput` so consistency is structurally enforced rather than assumed.

### Proof of Concept
```rust
// networks/bitcoin context; attacker-controlled bytes fed to ReceivedOutput::read
use bitcoin::{TxOut, OutPoint, ScriptBuf, Amount, Txid, hashes::Hash};
use k256::Scalar;
use bitcoin_serai::wallet::ReceivedOutput;

let mut buf = vec![];
// Any scalar — does NOT need to derive the output's script_pubkey
buf.extend(Scalar::ONE.to_bytes());
// A TxOut paying to an arbitrary (e.g., attacker's) P2TR script
let foreign = TxOut {
  value: Amount::from_sat(100_000),
  script_pubkey: ScriptBuf::new_p2tr_tweaked(
    bitcoin::key::TweakedPublicKey::dangerous_assume_tweaked(/* attacker key */)
  ),
};
buf.extend(bitcoin::consensus::encode::serialize(&foreign));
buf.extend(bitcoin::consensus::encode::serialize(
  &OutPoint::new(Txid::from_raw_hash(/* any */), 0),
));

let claimed = ReceivedOutput::read(&mut &buf[..]).unwrap();
// Succeeds: no check that offset actually unlocks script_pubkey.
// claimed.value() == 100_000 is now reported as spendable by the multisig,
// yet signing with `key + claimed.offset()` cannot spend it.
assert_eq!(claimed.value(), 100_000);
```

Uncertainty: I could not trace every consumer of `ReceivedOutput::read` within the iteration budget to confirm an attacker-reachable deserialization path in production wiring (processor/coordinator crates are out of the listed scope); the finding stands on the missing consistency check in the in-scope `read` API itself, which is one of the enumerated untrusted-byte sinks.

pub fn p2tr_script_buf(key: ProjectivePoint) -> Option<ScriptBuf> {
  if key.to_encoded_point(true).tag() != Tag::CompressedEvenY {
    return None;
  }

  Some(ScriptBuf::new_p2tr_tweaked(TweakedPublicKey::dangerous_assume_tweaked(x_only(&key))))
}

  pub fn read<R: Read>(r: &mut R) -> io::Result<ReceivedOutput> {
    let offset = Secp256k1::read_F(r)?;
    let output;
    let outpoint;
    {
      let mut buf_r = BufReader::with_capacity(0, r);
      output =
        TxOut::consensus_decode(&mut buf_r).map_err(|_| io::Error::other("invalid TxOut"))?;
      outpoint =
        OutPoint::consensus_decode(&mut buf_r).map_err(|_| io::Error::other("invalid OutPoint"))?;
    }
    Ok(ReceivedOutput { offset, output, outpoint })
  }

  pub fn scan_transaction(&self, tx: &Transaction) -> Vec<ReceivedOutput> {
    let mut res = Vec::new();
    for (vout, output) in tx.output.iter().enumerate() {
      // If the vout index exceeds 2**32, stop scanning outputs
      let Ok(vout) = u32::try_from(vout) else { break };

      if let Some(offset) = self.scripts.get(&output.script_pubkey) {
        res.push(ReceivedOutput {
          offset: *offset,
          output: output.clone(),
          outpoint: OutPoint::new(tx.compute_txid(), vout),
        });
      }
    }
    res
  }
