### Title
Zero-slippage swap in `WombatBribeManager._swapFeesForBnb` allows theft of bribe fee value via sandwich/flash-loan price manipulation - (File: wombat/WombatBribeManager.sol)

### Summary
`WombatBribeManager` collects a protocol fee in reward tokens whenever a user claims bribes, and converts that fee into BNB by calling the `BNBZapper` contract. The swap is executed with a hard-coded minimum-output value of `0`, which removes all slippage protection and lets an attacker extract value from the swap through price manipulation, exactly the bug class described in the external report (harvested reward tokens swapped through an AMM router with `amountOutMin = 0`).

### Finding Description
`_swapFeesForBnb` iterates over the reward tokens/fee amounts collected from bribe pools and calls `IBNBZapper(PancakeZapper).zapInToken(...)` for each non-zero fee, passing `0` as the `minRec` parameter: [1](#0-0) 

`BNBZapper.zapInToken` (and the internal `previewAmount`/routing logic) uses `IPancakeRouter02` (a Uniswap-V2-style router) to swap the token into BNB via `getAmountsOut`/`swapExactTokensForTokens`-style routing, with no independent minimum-output enforcement beyond the caller-supplied `minRec`: [2](#0-1) 

Because `_swapFeesForBnb` always supplies `minRec = 0`, the swap accepts any output amount, no matter how unfavorable. This is the same root cause identified in the external report: a Uniswap-V2-router swap with zero minimum output performed as part of routine, permissionless reward/fee processing. An attacker can sandwich (or flash-loan-manipulate) the underlying Pancake pool for the given reward token/BNB pair immediately before and after the fee-swap transaction, capturing the difference between the manipulated and fair price. Since `_swapFeesForBnb` sends the output BNB to `msg.sender` (the account triggering the bribe claim/fee processing), any unprivileged wallet that triggers this code path exposes the collected protocol fee value to extraction, and because the swapped amount comes from protocol-collected bribe fees, third parties (the protocol/other bribe claimants) lose the value that leaks to the attacker performing the sandwich.

### Impact Explanation
This is a direct theft of value belonging to the protocol/other users: the fee amounts being swapped represent yield/fees accrued from bribe rewards, and an attacker can systematically capture a portion of that value on every fee-swap by manipulating the pool price around the transaction. As bribe/fee volumes grow, so does the extractable profit, mirroring the reasoning in the referenced report.

### Likelihood Explanation
The swap is reachable through the normal, permissionless bribe-claim/fee-processing flow (no privileged role is required to trigger `_swapFeesForBnb`, and the attack itself requires no special access — only the ability to trade in the relevant Pancake pool and to trigger the fee-swap transaction, achievable via a public claim call or by sandwiching a pending one). This makes the likelihood high whenever there is meaningful liquidity/fee volume.

### Recommendation
Do not hard-code `minRec = 0` in `_swapFeesForBnb`. Instead, either (a) compute an on-chain fair-value minimum output using a manipulation-resistant price source (e.g., TWAP) before calling `zapInToken`, or (b) require/accept a caller- or governance-configured minimum-output parameter with a sane default and revert if the realized output falls short, consistent with the fix pattern applied to `VaultCore`/`Buyback` in the referenced PRs.

### Proof of Concept
1. Attacker observes a pending or upcoming trigger of bribe-fee processing that will call `_swapFeesForBnb` for a given `rewardToken`.
2. Attacker front-runs by swapping a large amount of `rewardToken` into the Pancake `rewardToken`/BNB pool, depressing the `rewardToken` price relative to BNB.
3. The fee-processing transaction executes `zapInToken(rewardToken, feeAmount, 0, msg.sender)` at the manipulated price, yielding far less BNB than fair value [3](#0-2) .
4. Attacker back-runs by swapping BNB back into `rewardToken`, restoring the price and pocketing the difference extracted from the protocol fee swap, since the zero-slippage swap accepted the unfavorable rate unconditionally.

    function _swapFeesForBnb(address[][] memory rewardTokens, uint256[][] memory feeAmounts)
        internal
        returns (uint256 bnbAmount)
    {
        if(PancakeZapper == address(0)) revert PancakeZapperNotSet();
        uint256 bribeLength = rewardTokens.length;
        for (uint256 i; i < bribeLength; i++) {
            uint256 rewardLength = rewardTokens[i].length;
            for (uint256 j; j < rewardLength; j++) {
                if (rewardTokens[i][j] != address(0) && feeAmounts[i][j] > 0) {
                    _approveTokenIfNeeded(rewardTokens[i][j], PancakeZapper, feeAmounts[i][j]);
                    bnbAmount += IBNBZapper(PancakeZapper).zapInToken(
                        rewardTokens[i][j],
                        feeAmounts[i][j],
                        0,
                        msg.sender
                    );
                }
            }
        }
    }
