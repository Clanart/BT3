## Analysis Summary

The CVE-2020-16044 invariant that transfers is: **attacker-controlled wire data causes a previously-returned live reference to be invalidated (freed/reused) without the holder being notified, and a subsequent dereference of that stale reference is a genuine use-after-free** — not a benign discrepancy or misuse of an internal API.

I traced this into the Python C-extension (`api_implementation=cpp`) message/map binding, and found that this exact bug class was already discovered for **oneof fields** and explicitly fixed with a documented mitigation (`MaybeReleaseOneofBeforeMerge`/`FixupMessageAfterMerge`, regression test `testOneofSwitchMergeUAF`). However, the fix's own logic **deliberately excludes map fields**, and the maintainers' own test comments confirm the identical UAF class remains present and unmitigated for **message-valued map entries during `MergeFrom`**.

### Title
Use-after-free on Python C-extension message-map entries during `MergeFrom`/`MergeFromString` with colliding keys - (File: `python/google/protobuf/pyext/message.cc`)

### Summary
When the Python `cpp` (pyext) implementation merges a message containing a message-valued map field whose key collides with an existing entry in the destination map, the underlying C++ map node holding the old submessage is deallocated/replaced by `MergeFrom`, while a Python wrapper object obtained earlier via `msg.some_map[key]` still holds a raw `const Message*` pointer into the now-freed node. Attribute access on that stale Python wrapper after the merge is a use-after-free.

### Finding Description
`CMessage::MergeFrom` in the pyext binding calls the guard `MaybeReleaseOneofBeforeMerge`, which is designed to detach (rather than delete) Python wrapper objects whose underlying C++ submessage is about to be invalidated by a oneof switch: [1](#0-0) 

But `MaybeReleaseOneofBeforeMerge` explicitly restricts its release logic to non-repeated message fields, and its own comment states map fields are intentionally excluded because "it is overwrite": [2](#0-1) 

Meanwhile, the Python wrapper for a map value is cached keyed by the raw `const Message*` pointer via `BuildSubMessageFromPointer`/`child_submessages`, with no mechanism to invalidate it if that pointer is freed by an unrelated merge: [3](#0-2) [4](#0-3) 

The underlying C++ `MapFieldBase`/`UntypedMapBase::UntypedMergeFrom` allocates fresh nodes for every entry of the source map and then calls `InsertOrReplaceNode` for each key, which discards (frees, for non-arena maps, or logically retires) the destination's existing node for a colliding key: [5](#0-4) 

This is the same invalidation-without-notification pattern that was already identified and fixed for oneofs, but the map path has no equivalent protection.

### Impact Explanation
This directly matches the CVE-2020-16044 invariant: attacker-controlled binary bytes (a map entry with a key matching one already held live by application code) trigger deallocation of memory that a live, ordinary-use Python object still points to. Subsequent attribute access (e.g., `old_map_value.c`) reads/writes freed heap memory through the pyext `Message*` accessor path — heap corruption with read/write potential, matching a High severity UAF profile (CWE-416), reachable purely through the public `ParseFromString`/`MergeFromString`/`MergeFrom` APIs on the `cpp` implementation with no privileged access or hostile schema required.

### Likelihood Explanation
High. The trigger requires only:
1. An application using the `cpp` (pyext) implementation.
2. Holding a Python reference to a message-valued map entry (a very common pattern, e.g. `entry = msg.some_map[key]`).
3. Calling `MergeFrom`/`MergeFromString`/`ParseFromString` with attacker-controlled bytes containing the same map key.

No malformed schema, no privileged access, no huge/unbounded payload — a single colliding map key is sufficient.

### Recommendation
Extend the oneof UAF fix to message-valued map fields: before/during `MergeFrom` for map fields, detect any destination map keys with existing Python wrappers that collide with the source's keys, and reparent/detach those wrappers (using the same swap-instead-of-delete strategy already used by `InternalReparentFields`/`MaybeReleaseOneofBeforeMerge`) rather than letting the underlying C++ node be silently freed while a live Python wrapper still points to it.

### Proof of Concept
The maintainers' own test acknowledges and works around this exact condition for the `cpp` implementation, only asserting the safe (pure-Python) behavior and explicitly noting the C++ implementation would crash if exercised: [6](#0-5) 

Minimal reproduction outline (would require running against the `cpp` implementation to observe the crash/UAF, which I was not able to execute in this read-only analysis):

```python
msg.map_int32_foreign_message[111].c = 5
```

```text
PyObject* MapReflectionFriend::MessageMapGetItem(PyObject* _self,
                                                 PyObject* key) {
  MessageMapContainer* self = GetMessageMap(_self);

  MapKey map_key;

  if (!PythonToMapKey(self, key, &map_key)) {
    return nullptr;
  }

  // Mutable path: insert-or-lookup and return mutable submessage wrapper.
  if (Message* message = self->GetMutableMessage(); message != nullptr) {
    const Reflection* reflection = message->GetReflection();
    MapValueRef value;
    if (reflection->InsertOrLookupMapValue(
            message, self->parent_field_descriptor, map_key, &value)) {
      self->version++;
    }
    return GetCMessage(self, value.MutableMessageValue(), MESSAGE_MUTABLE);
  }

  // Frozen path: read-only lookup without mutation.
  PyErr_Clear();
  const Message* message = self->GetReadOnlyMessage();
  const Reflection* reflection = message->GetReflection();
  MapValueConstRef value;
  if (!reflection->LookupMapValue(*message, self->parent_field_descriptor,
                                  map_key, &value)) {
    return SetMessageFrozenError();
  }
  return GetCMessage(self, &value.GetMessageValue(), MESSAGE_FROZEN);
}
```

```text
void UntypedMapBase::UntypedMergeFrom(Arena* arena,
                                      const UntypedMapBase& other) {
  ABSL_DCHECK_EQ(arena, this->arena());
  if (other.empty()) return;

  // Do the merging in steps to avoid Key*Value number of instantiations and
  // reduce code duplication per instantation.
  NodeBase* nodes = nullptr;

  // First, allocate all the nodes without types.
  for (size_t i = 0; i < other.num_elements_; ++i) {
    NodeBase* new_node = AllocNode(arena);
    new_node->next = nodes;
    nodes = new_node;
  }

  // Then, copy the values.
  VisitValueType([&](auto value_type) {
    using Value = typename decltype(value_type)::type;
    NodeBase* out_node = nodes;

    // Get the ClassData once to avoid redundant virtual function calls.
    const internal::ClassData* class_data =
        std::is_same_v<MessageLite, Value>
            ? GetClassData(*other.GetValue<MessageLite>(other.begin().node_))
            : nullptr;

    for (auto it = other.begin(); !it.Equals(EndIterator()); it.PlusPlus()) {
      Value* out = GetValue<Value>(out_node);
      out_node = out_node->next;
      auto& in = *other.GetValue<Value>(it.node_);
      if constexpr (std::is_same_v<MessageLite, Value>) {
        class_data->PlacementNew(out, arena)->CheckTypeAndMergeFrom(in);
      } else {
        Arena::CreateInArenaStorage(out, arena, in);
      }
    }
  });

  // Finally, copy the keys and insert the nodes.
  VisitKeyType([&](auto key_type) {
    using Key = typename decltype(key_type)::type;
    for (auto it = other.begin(); !it.Equals(EndIterator()); it.PlusPlus()) {
      NodeBase* node = nodes;
      nodes = nodes->next;
      const Key& in = *other.GetKey<Key>(it.node_);
      Key* out = GetKey<Key>(node);
      if (!internal::InitializeMapKey(out, in, arena)) {
        Arena::CreateInArenaStorage(out, arena, in);
      }

      static_cast<KeyMapBase<Key>*>(this)->InsertOrReplaceNode(
          arena, static_cast<typename KeyMapBase<Key>::KeyNode*>(node));
    }
  });
}
```
