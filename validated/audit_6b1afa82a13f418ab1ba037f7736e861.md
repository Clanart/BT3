## Finding: Blind SSRF via Unauthenticated DataLayer Mirror URL Injection

This codebase has a direct analog to the BigBlueButton `insertDocument` SSRF: Chia's DataLayer mirror mechanism lets *any* unprivileged coin owner inject an attacker-controlled URL that gets associated with *any other user's* tracked DataLayer store, causing the victim's node to make an unvalidated outbound HTTP request to that URL.

### Title
Blind SSRF via unauthenticated DataLayer mirror coin URL injection - (File: `chia/data_layer/download_data.py`)

### Summary
The DataLayer mirror puzzle (`create_mirror_puzzle()`) is a permissionless `P2_PARENT` puzzle. Any wallet holding any spendable coin can create a "mirror" coin whose memo encodes an arbitrary `launcher_id` (a victim's DataLayer store id) and arbitrary URLs, with no relationship to or authorization from that store's owner. Any node tracking that `launcher_id` picks up the mirror record and later uses the attacker-supplied URL as an HTTP fetch target with no host/protocol validation, exactly mirroring the CVE-2023-33176 bug class (unvalidated user-supplied URL used for a server-initiated outbound fetch).

### Finding Description
- `create_mirror_puzzle()` returns `P2_PARENT.curry(Program.to(1))` [1](#0-0) . Anyone can create a coin at this puzzle hash by simply spending their own coin and setting a `CREATE_COIN` condition with arbitrary memos, as done in `DataLayerWallet.create_new_mirror()` [2](#0-1) .
- `get_mirror_info()` extracts `launcher_id` and URLs purely from the memos of that `CREATE_COIN` condition, with no cryptographic or ownership binding to the referenced `launcher_id` [3](#0-2) .
- On the receiving side, `DataLayerWallet.coin_added()` accepts any such mirror coin as long as the *victim's own wallet* is tracking that `launcher_id` (`is_launcher_tracked`) — it performs no check that the mirror was created by the store owner or any authorized party: [4](#0-3) .
- `DataLayer.update_subscriptions_from_wallet()` pulls all mirror URLs for a store from wallet RPC and merges them directly into the local subscription server list without any URL/host/scheme validation: [5](#0-4) .
- Those server URLs are later used in `fetch_and_validate()` → `insert_from_delta_file()` → `download_file()` → `http_download()`, which issues an `aiohttp` GET directly against the attacker-controlled URL with no protocol allowlist, no host denylist (loopback/link-local/RFC1918/cloud metadata), and no redirect restriction: [6](#0-5) , invoked from [7](#0-6) .

### Impact Explanation
Any user who submits a low-value spend bundle can force arbitrary other DataLayer nodes that track/subscribe to a given store to make outbound HTTP requests to attacker-chosen URLs (e.g., cloud metadata endpoints, internal RPC ports, or other internal-network services), constituting a blind SSRF from an unprivileged, permissionless action — matching CVSS Medium severity of the referenced CVE. This is a coin-store/DataLayer-reachable action requiring no privileges on the victim node and no interaction beyond the victim already tracking the targeted store (owner or subscriber).

### Likelihood Explanation
Likelihood is Medium-High: creating the malicious mirror coin only requires spending a trivially small coin (fee + mirror amount, which can be minimal) with a standard-wallet transaction; no special permissions, signatures tied to the target store, or social engineering are required. The victim's node automatically ingests the mirror record during normal sync (`coin_added`) and periodically performs the SSRF-triggering fetch during `periodically_manage_data()`/`update_subscription()` without any manual approval step.

### Recommendation
- In `DataLayerWallet.coin_added()`, reject/flag mirror coins whose implied `launcher_id` is not provably associated with the mirror-coin creator (e.g., require the mirror coin's origin to be traceable to a party authorized for that singleton, or otherwise disallow arbitrary third parties from injecting mirror records for launcher IDs they don't own).
- In `download_data.http_download()` / `DataLayer.get_downloader()` / `update_subscriptions_from_wallet()`, validate mirror/subscription URLs before use: enforce an allowed-protocol list, resolve and reject loopback/link-local/private/multicast/metadata addresses, and disable automatic redirect following (or re-validate the final redirect target) — mirroring the `presentationDownloadSupportedProtocols` / `presentationDownloadBlockedHosts` mitigation added upstream in BigBlueButton.
- Consider requiring explicit local operator opt-in (e.g., via `add_mirror`/`subscribe` RPC) before accepting on-chain mirror URLs discovered passively through wallet sync, rather than automatically merging them into the fetch target list.

### Proof of Concept
1. Attacker wallet spends any coin it owns, creating a `CREATE_COIN` to `create_mirror_puzzle().get_tree_hash()` with memo `[victim_store_launcher_id, b"http://169.254.169.254/latest/meta-data/"]` (mirrors `DataLayerWallet.create_new_mirror()`).
2. Victim's `DataLayerWallet`, which tracks `victim_store_launcher_id` (as owner or subscriber), observes the new coin in `coin_added()` and stores a `Mirror` record with the attacker's URL, since no ownership check is performed.
3. Victim's `DataLayer` service calls `update_subscriptions_from_wallet()`, merging the attacker URL into the store's subscription server list.
4. On the next sync cycle, `fetch_and_validate()`/`insert_from_delta_file()` calls `http_download()`, causing the victim node to issue an outbound HTTP GET to the attacker-chosen URL — a blind SSRF triggered entirely by an unprivileged on-chain spend.

```python
def get_mirror_info(
    parent_puzzle: Program | SerializedProgram, parent_solution: Program | SerializedProgram
) -> tuple[bytes32, list[bytes]]:
    assert type(parent_puzzle) is type(parent_solution)
    _, conditions = run_with_cost(parent_puzzle, INFINITE_COST, parent_solution)
    for condition in conditions.as_iter():
        if (
            condition.first().as_python() == ConditionOpcode.CREATE_COIN
            and condition.at("rf").as_python() == create_mirror_puzzle().get_tree_hash()
        ):
            memos: list[bytes] = condition.at("rrrf").as_python()
            launcher_id = bytes32(memos[0])
            return launcher_id, [url for url in memos[1:]]
    raise ValueError("The provided puzzle and solution do not create a mirror coin")
```

```python
        self, coin: Coin, height: uint32, peer: WSChiaConnection, coin_data: object | None, sync_scope: WalletSyncScope
    ) -> None:

            parent_state: CoinState = (
                await self.wallet_state_manager.wallet_node.get_coin_state([coin.parent_coin_info], peer=peer)
            )[0]
            parent_spend = await fetch_coin_spend(height, parent_state.coin, peer)
            assert parent_spend is not None
            launcher_id, urls = get_mirror_info(parent_spend.puzzle_reveal, parent_spend.solution)
            # Don't track mirrors with empty url list.
            if not urls:
                return
            if await self.wallet_state_manager.dl_store.is_launcher_tracked(launcher_id):
                ours: bool = await self.wallet_state_manager.get_wallet_for_coin(coin.parent_coin_info) is not None
                await self.wallet_state_manager.dl_store.add_mirror(
                    Mirror(
                        coin.name(),
                        launcher_id,
                        uint64(coin.amount),
                        Mirror.decode_urls(urls),
                        ours,
                        height,
                    )
                )
                await self.wallet_state_manager.add_interested_coin_ids([coin.name()])
```

```python
async def http_download(
    target_filename_path: Path,
    filename: str,
    proxy_url: str | None,
    server_info: ServerInfo,
    timeout: aiohttp.ClientTimeout,
    log: logging.Logger,
    max_delta_file_size: int,
) -> None:
    """
    Download a file from a server using aiohttp.
    Raises exceptions on errors
    """
    async with aiohttp.ClientSession() as session:
        headers = {"accept-encoding": "gzip"}
        async with session.get(
            server_info.url + "/" + filename,
            headers=headers,
            timeout=timeout,
            proxy=proxy_url,
        ) as resp:
            resp.raise_for_status()
```
