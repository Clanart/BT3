It triggers `_toMasterWomAndSendReward`, which ultimately calls `IBaseRewardPool(_rewarders[i]).queueNewRewards(rewardAmount, ...)`, injecting a lump-sum of harvested WOM/reward tokens into the `BaseRewardPool` instantly [2](#0-1) . ### Title
Reward Sniping via Flash-Deposit/Withdraw Sandwiching BaseRewardPool `queueNewRewards` Steals Unclaimed Yield From Long-Term Stakers - ([File: rewards/BaseRewardPool.sol])

### Summary
`BaseRewardPool` (and its variants `BaseRewardPoolV2`, `mWOMSVBaseRewarder`, `vlMGPBaseRewarder`) distribute externally-sourced reward tokens as an instantaneous, lump-sum increase to `rewardPerTokenStored`, weighted only by `totalStaked()` at the moment of distribution, with no minimum holding period. Because `MasterMagpie.deposit`/`withdraw` (and the pool-helper equivalents that call `_toMasterWomAndSendReward` → `harvest`) are unprivileged and unrestricted, any wallet can front-run a permissionless `WombatStaking.harvest()` call (or the `vote()` bribe distribution path) by depositing a large stake immediately before the reward injection and withdrawing immediately after, capturing a share of freshly-harvested yield that should have accrued only to genuine long-term stakers.

### Finding Description
`harvest(address _lpToken)` in `WombatStaking` can be called by anyone and is not gated to a manager or keeper role [1](#0-0) . It routes through `_toMasterWomAndSendReward`, which for bribe/vote flows calls `IBaseRewardPool(_rewarders[i]).queueNewRewards(rewardAmount, address(rewardTokens[i][j]))` [6](#0-5) .

`queueNewRewards`/`_provisionReward` in `BaseRewardPool` immediately updates `rewardPerTokenStored` using the reward amount divided by `totalStaked()` at that exact block [3](#0-2) . A user's claimable reward (`earned`) is `balance * (rewardPerToken - userRewardPerTokenPaid)`, so whoever holds a balance at the moment `rewardPerTokenStored` jumps captures a proportional share instantly — there is no requirement to have held the balance while the yield was being generated.

`MasterMagpie._deposit`/`_withdraw` have no cooldown, lock, or fee that would prevent immediate deposit-then-withdraw within the same block or across two adjacent transactions [5](#0-4) . An attacker can therefore:
1. Deposit a large stake `A` into the pool immediately before calling (or observing a pending) `harvest()`/`vote()` transaction that will inject reward `R` into `BaseRewardPool`.
2. Let the reward distribution transaction execute, which increases `rewardPerTokenStored` by `R * PRECISION / (S + A)` instead of `R * PRECISION / S` (where `S` is the pre-existing genuine stakers' total).
3. Immediately call `withdraw`, which internally calls `_harvestBaseRewarder` before decrementing the user's stake, letting the attacker claim `A * ΔrewardPerToken` and withdraw principal with zero cost, zero lock-up, and no fee.

This directly reduces the reward that would otherwise have accrued to the pre-existing stakers `S`, since the same fixed reward pot `R` is now divided among a larger denominator. This is the same underlying bug class as the reported `StakedYuzuUSD` issue — sandwiching a lump-sum yield injection with deposit/redeem to extract value that should belong to time-invested holders — except here the mechanism is `rewardPerTokenStored`-based emission rather than an ERC4626 exchange rate, and the "redemption fee" that partially mitigated the original bug does not exist at all in `MasterMagpie`/`BaseRewardPool`.

### Impact Explanation
Genuine long-term stakers in any Wombat pool routed through `BaseRewardPool`/`WombatStaking` permanently lose a portion of harvested yield to opportunistic flash-depositors every time `harvest()` or bribe `vote()` distributes rewards. This is a direct, repeatable theft of unclaimed yield from legitimate stakers with no compensating fee or cooldown, satisfying "theft ... of unclaimed yield."

### Likelihood Explanation
`harvest()` is permissionless and can be called by anyone at will (or observed via mempool and front-run), and `MasterMagpie.deposit`/`withdraw` are unrestricted for any staking token pool, making the exploit trivially and repeatedly executable by any ordinary wallet with sufficient capital (which can be flash-loaned if the staking token is available in a flash-loan-liquid form, or simply capital held temporarily for one or two blocks).

### Recommendation
Introduce a minimum holding/cooldown period between `deposit`/`depositFor` and `withdraw`/`withdrawFor` (or a decaying vesting schedule on newly queued rewards, similar to Synthetix's linear reward-rate release) in `BaseRewardPool`/`BaseRewardPoolV2`/`mWOMSVBaseRewarder`/`vlMGPBaseRewarder`, so that lump-sum reward injections via `queueNewRewards` cannot be captured by stakers who deposit immediately before and withdraw immediately after a distribution event.

### Proof of Concept
1. Long-term staker deposits `S` staking tokens into `MasterMagpie`/pool helper.
2. Attacker observes (or triggers) an imminent `WombatStaking.harvest()`/`vote()` call that will queue reward `R` to the corresponding `BaseRewardPool`.
3. Attacker calls `deposit`/`depositFor` with amount `A` in the block immediately prior.
4. `harvest()`/`vote()` executes, calling `queueNewRewards(R, rewardToken)`, which sets `rewardPerTokenStored += R * PRECISION / (S + A)` [7](#0-6) .
5. Attacker immediately calls `withdraw`, triggering `_harvestBaseRewarder` to claim `A * ΔrewardPerToken` before principal is returned [8](#0-7) .
6. Attacker nets `A/(S+A) * R` in reward tokens for a transient, sub-block deposit, while the pre-existing stakers `S` receive proportionally less of `R` than they would have absent the attacker's deposit.

    function _provisionReward(uint256 _amountReward, address _rewardToken) internal {
        IERC20(_rewardToken).safeTransferFrom(
            msg.sender,
            address(this),
            _amountReward
        );
        Reward storage rewardInfo = rewards[_rewardToken];
        rewardInfo.historicalRewards =
            rewardInfo.historicalRewards +
            _amountReward;
        if (this.totalStaked() == 0) {
            rewardInfo.queuedRewards += _amountReward;
        } else {
            if (rewardInfo.queuedRewards > 0) {
                _amountReward += rewardInfo.queuedRewards;
                rewardInfo.queuedRewards = 0;
            }
            rewardInfo.rewardPerTokenStored =
                rewardInfo.rewardPerTokenStored +
                (_amountReward * 10**stakingDecimals()) /
                this.totalStaked();
        }
