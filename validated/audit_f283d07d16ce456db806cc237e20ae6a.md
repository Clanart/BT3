### Title
Unauthenticated `ReceivedOutput` deserialization enables nonexistent deposits to be reported - ([File: networks/bitcoin/src/wallet/mod.rs](networks/bitcoin/src/wallet/mod.rs))

### Summary
`ReceivedOutput::read` accepts a scalar offset, `TxOut`, and `OutPoint` without proving that the referenced output exists or belongs to the scanner’s wallet. [1](#0-0) 

### Finding Description
`ReceivedOutput` represents a spendable output through an offset, output data, and an outpoint. [2](#0-1)  Its reader only deserializes those three attacker-controlled fields and immediately returns a populated `ReceivedOutput`. [1](#0-0)  Unlike `Scanner::scan_transaction`, which derives the object only after matching a transaction output’s `script_pubkey` and calculating its actual transaction ID, direct deserialization contains no ownership or chain-membership check. [3](#0-2) 

An attacker can select `offset = 0`, encode the wallet’s P2TR script as the `TxOut`, and choose an arbitrary nonexistent or spent `OutPoint`. [4](#0-3)  `SignableTransaction::new` then trusts the encoded value as input value and copies the claimed outpoint into the transaction. [5](#0-4)  The multisig check confirms only that the supplied offset derives the encoded script; it does not establish that the outpoint exists or is unspent. [6](#0-5) 

### Impact Explanation
Any component that treats deserialized `ReceivedOutput`s as received wallet funds can credit a deposit whose transaction output was never created on-chain. [1](#0-0)  The resulting balance is not spendable: signing may succeed locally because the encoded script matches the key, while Bitcoin consensus rejects the transaction for spending a nonexistent or already-spent prevout. [7](#0-6)  In an exchange or bridge accounting path, this can cause an attacker to be credited for funds the wallet never received.

### Likelihood Explanation
The attack requires only public information—the wallet’s P2TR script—and the ability to supply bytes to `ReceivedOutput::read` or a wrapper that calls it. [1](#0-0)  The affected path is reachable when serialized outputs cross an untrusted boundary, such as peer-supplied state, imported wallet data, or a compromised upstream producer. Deployments that only consume objects returned directly by `Scanner` after validating blocks are not exposed through that specific path. [8](#0-7) 

### Recommendation
Do not expose `ReceivedOutput::read` as an authority-producing wallet primitive. Store and deserialize an authenticated wallet snapshot, or make the type name/API explicit that deserialization does not establish receipt. Consumers should verify the claimed outpoint against a trusted Bitcoin view before crediting it: retrieve the transaction, verify inclusion in a confirmed block, verify the output index and script, and verify that the outpoint remains unspent according to the accepted chain. [3](#0-2) 

### Proof of Concept
Conceptually, an attacker knowing the wallet’s base script constructs serialized bytes containing:

```rust
offset    = Scalar::ZERO;
tx_out    = TxOut {
  value: Amount::from_sat(attacker_chosen_amount),
  script_pubkey: wallet_p2tr_script,
};
outpoint  = OutPoint {
  txid: nonexistent_or_spent_txid,
  vout: attacker_chosen_index,
};
```

`ReceivedOutput::read` accepts these bytes because it performs only scalar and consensus decoding. [1](#0-0)  A downstream wallet that reports `value()` as a received balance reports `attacker_chosen_amount`. [9](#0-8)  Passing the object to `SignableTransaction::new` uses that amount as spendable input value and inserts the forged prevout into the transaction. [5](#0-4)  Since the forged script is deliberately set to the wallet script, the `multisig` ownership check passes for `offset = 0`. [6](#0-5)

  /// Scan a transaction.
  pub fn scan_transaction(&self, tx: &Transaction) -> Vec<ReceivedOutput> {
    let mut res = Vec::new();
    for (vout, output) in tx.output.iter().enumerate() {
      // If the vout index exceeds 2**32, stop scanning outputs
      let Ok(vout) = u32::try_from(vout) else { break };

      if let Some(offset) = self.scripts.get(&output.script_pubkey) {
        res.push(ReceivedOutput {
          offset: *offset,
          output: output.clone(),
          outpoint: OutPoint::new(tx.compute_txid(), vout),
        });
      }
    }
    res
