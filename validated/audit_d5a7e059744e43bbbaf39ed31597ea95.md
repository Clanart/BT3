### Title
Deterministic `CachedPreprocess` reused across signing attempts enables nonce reuse and key share recovery - (File: coordinator/src/tributary/signing_protocol.rs)

### Summary
`preprocess_internal`/`share_internal` in the coordinator's signing protocol derive FROST nonces deterministically from a cached 32-byte seed stored in `CachedPreprocesses`, keyed only by the signing `context`. The cache is never consumed or invalidated: every call to `preprocess_internal`/`share_internal` for the same context decrypts the same seed and reconstructs the identical nonce pair via `AlgorithmSignMachine::from_cache`, publishing an identical preprocess message and using identical nonces in `sign()`.

### Finding Description
`preprocess_internal` reads `CachedPreprocesses::get(txn, &context)`; if absent it creates a machine, caches `machine.cache()` (XORed with a key derived from `context` and the private key), and in all cases calls `AlgorithmSignMachine::from_cache(algorithm, keys, CachedPreprocess(cached))` [1](#0-0) . `from_cache` calls `AlgorithmMachine::new(...).seeded_preprocess(cache)`, which deterministically regenerates the exact same nonces and commitments from the seed [2](#0-1) . `share_internal` then calls `preprocess_internal` again and `machine.sign(preprocesses, msg)` [3](#0-2) .

The danger is documented in the library itself: "A preprocess MUST only be used once. Reuse will enable third-party recovery of your private key share" [4](#0-3) . Because `from_cache` rebuilds the identical preprocess each time, the `share_internal` code path never rotates the seed — there is no `CachedPreprocesses::remove`/re-seed after a `sign` completes or fails. Two signing rounds for the same context (e.g., a retry with a different participant set or different `msg`) produce two signature shares using the same nonce `d + ρe` basis while the binding factors `ρ` and challenge `c` differ. From `s1 = d + ρ1·e + c1·λ1·x` and `s2 = d + ρ2·e + c2·λ2·x`, together with the known published nonces, the secret share `x` (scaled by the known Lagrange factor) is recoverable by linear algebra — a ROS-style / parallel-session nonce-reuse key recovery.

### Impact Explanation
An unprivileged participant who can trigger or observe a second signing attempt under the same context (e.g., by causing the first attempt to fail and be retried, or participating in two sign requests sharing a context) obtains the validator's FROST secret share, equivalently compromising the threshold key for that share holder — analogous to the "takeover" impact of the CVE. The encryption of the cache protects against DB reads but not against deterministic regeneration at sign time.

### Likelihood Explanation
Requires the same `context` to be signed twice. The context encodes the signing session; if session IDs or attempts are ever reused (reboots rebuilding `active_*` maps, coordinator re-issuance, retries), the reuse happens silently with no error or warning, since the code explicitly intends reuse for caching but never enforces single-use.

### Recommendation
Delete or ratchet the `CachedPreprocesses` entry atomically when `sign` is invoked (e.g., overwrite the seed with `H(seed)` after use, or track used preprocess hashes and refuse signing with a previously-published preprocess). At minimum, document and enforce that `context` must be unique per produced signature share, not merely per session.

### Proof of Concept
1. Observe a validator produce `preprocess` and `share1` for context `C`, message `m1`, signing set S.
2. Trigger a second `share_internal` for the same context `C` with message `m2` (same or different set). The regenerated nonces are identical; the published preprocess is byte-identical.
3. With `s_i = d + ρ_i·e + c_i·λ_i·x`, and `d, e` recoverable because both shares use the same `(d, e)` while `ρ_i, c_i` are public, solve for `x` — the validator's secret share — from the two equations.

  fn share_internal(
    &mut self,
    participants: &[<Ristretto as Ciphersuite>::G],
    mut serialized_preprocesses: HashMap<Participant, Vec<u8>>,
    msg: &[u8],
  ) -> Result<(AlgorithmSignatureMachine<Ristretto, Schnorrkel>, [u8; 32]), Participant> {
    let machine = self.preprocess_internal(participants).0;

    let mut participants = serialized_preprocesses.keys().copied().collect::<Vec<_>>();
    participants.sort();
    let mut preprocesses = HashMap::new();
    for participant in participants {
      preprocesses.insert(
        participant,
        machine
          .read_preprocess(&mut serialized_preprocesses.remove(&participant).unwrap().as_slice())
          .map_err(|_| participant)?,
      );
    }

    let (machine, share) = machine.sign(preprocesses, msg).map_err(|e| match e {
      FrostError::InternalError(e) => unreachable!("FrostError::InternalError {e}"),
      FrostError::InvalidParticipant(_, _) |
      FrostError::InvalidSigningSet(_) |
      FrostError::InvalidParticipantQuantity(_, _) |
      FrostError::DuplicatedParticipant(_) |
      FrostError::MissingParticipant(_) => unreachable!("{e:?}"),
      FrostError::InvalidPreprocess(p) | FrostError::InvalidShare(p) => p,
    })?;

    Ok((machine, share.serialize().try_into().unwrap()))
