### Title
GaslessSwapRouter's mempool admission and repay accounting use nominal `amountIn`/`minAmountOut`, ignoring fee-on-transfer token deductions - ([File: kaiax/gasless/impl/tx_pool.go])

### Summary
### Finding Description
The Kaia gasless-transaction module allows any public RPC caller to submit an `approve` + `swapForGas` transaction pair that gets bundled with a relayer-generated `LendTx` so that a fee is advanced in KAIA and later repaid (`amountRepay`) from ERC20 token swap proceeds. Before admitting such a bundle, `checkBalanceForSwap` validates the trade purely with nominal, declared values: it requires `minAmountOut >= amountRepay`, and separately requires `amountIn >= gsr.GetAmountIn(minAmountOut)`, i.e. the theoretical input needed to produce `minAmountOut` at current DEX rates. [1](#0-0) 

This mirrors the Slingshot root cause: the check computes and validates amounts *before* the value-eroding step (the ERC20 `transferFrom` that pulls `amountIn` tokens from the sender into the swap router) rather than validating the actually-received/actually-produced amount *after* it. If the swapped ERC20 token charges a fee on transfer (a fee-on-transfer/deflationary token), the router will receive less than the declared `amountIn`, so the DEX swap driven off that reduced balance yields a real output smaller than the `minAmountOut` that was used to admit the bundle and to size `amountRepay` to the block proposer/relayer. [2](#0-1) 

The whitelist that gates which ERC20 tokens can be used in this flow is configurable and, by default/openly, can allow arbitrary tokens: `AllowedTokens` is `nil` (meaning "all tokens are allowed") unless explicitly restricted by node operators via config/flags. [3](#0-2) 

Because a single unprivileged transaction sender fully controls which ERC20 `token` is passed to `swapForGas` (subject only to the allow-list), and the mempool/bundle-admission logic never re-derives the required amounts from actual pre/post balances of the router, this is directly reachable from a submitted transaction pair with no special privileges.

### Impact Explanation
If a fee-on-transfer token is admitted (default config allows all tokens), the discrepancy between the nominal `amountIn`/`minAmountOut` used for admission/repay accounting and the actual tokens received by `GaslessSwapRouter` can cause the swap to under-produce relative to `amountRepay`. Since `amountRepay` is meant to reimburse the entity that advanced gas via `LendTxGenerator` (the relayer/proposer), an under-collateralized settlement here constitutes fee/fee-delegation abuse and potential loss to the gas-lending party, or unexpected transaction failure/state divergence for the gasless bundle at execution time versus what was validated during mempool admission — the same "check-before-fee-erosion" pattern flagged in the original Slingshot report.

### Likelihood Explanation
Likelihood depends on node operators' `AllowedTokens` configuration; with the documented default (`nil` = all tokens allowed) or any permissive allow-list that includes a fee-on-transfer token, any public caller can trigger this simply by submitting a normal approve+swap pair using such a token, with no elevated privileges required.

### Recommendation
Validate settlement amounts using actual balances observed by `GaslessSwapRouter` immediately before and after the token `transferFrom`/DEX swap, rather than the nominal `amountIn`/`minAmountOut` used only for pre-execution/mempool estimation. Explicitly document (or enforce, e.g. via a balance-delta check in `checkBalanceForSwap`/on-chain equivalent) that fee-on-transfer or rebasing tokens are unsupported, and consider defaulting `AllowedTokens` to an explicit safe allow-list rather than "all tokens" to reduce exposure.

### Proof of Concept
1. Node operator runs with default `GaslessConfig` (`AllowedTokens = nil`), i.e., all ERC20 tokens usable in gasless swaps. [4](#0-3) 
2. An attacker/user deploys or uses an existing fee-on-transfer ERC20 token and obtains a balance/allowance sufficient to pass `checkBalanceForSwap`'s nominal `balance`/`allowance` and `GetAmountIn(minAmountOut)` checks. [5](#0-4) 
3. User submits `approve` + `swapForGas(token, amountIn, minAmountOut, amountRepay, deadline)` with `minAmountOut` just above `amountRepay`, both sized off the token's nominal transfer amount.
4. The relayer/proposer bundles a `LendTxGenerator` transaction advancing gas, expecting reimbursement of `amountRepay` from the swap.
5. Because the token deducts a transfer fee, `GaslessSwapRouter` receives fewer tokens than `amountIn`; the resulting DEX swap output is less than the `minAmountOut` value that was used to size and admit `amountRepay`, causing an unexpected shortfall/settlement mismatch relative to what the mempool validated.

func (g *GaslessModule) checkBalanceForSwap(swapArgs *SwapArgs, swapNonce uint64) error {
	token := swapArgs.Token
	bc := backends.NewBlockchainContractBackend(g.Chain, nil, nil)

	g.gaslessInfoMu.RLock()
	swapRouter := g.swapRouter
	g.gaslessInfoMu.RUnlock()

	// tx.minAmountOut >= tx.amountRepay
	minAmountOut := swapArgs.MinAmountOut
	amountRepay := swapArgs.AmountRepay
	if minAmountOut.Cmp(amountRepay) < 0 {
		return fmt.Errorf("insufficient minAmountOut: minAmountOut=%s, amountRepay=%s", minAmountOut.String(), amountRepay.String())
	}

	if g.GaslessConfig.ShouldCheckSenderCode() {
		if g.getCurrentHasCode(swapArgs.Sender) {
			return errors.New("sender with code is not allowed")
		}
	}

	if g.GaslessConfig.ShouldCheckSwapAmount() {
		// tx.amountIn >= gsr.getAmountIn(minAmountOut)
		routerContract, err := kip247.NewGaslessSwapRouterCaller(swapRouter, bc)
		if err != nil {
			return err
		}
		// Required token amountIn, given the current exchange rate and the declared minAmountOut.
		requiredAmountIn, err := routerContract.GetAmountIn(nil, token, minAmountOut)
		if err != nil {
			return err
		}
		if swapArgs.AmountIn.Cmp(requiredAmountIn) < 0 {
			return fmt.Errorf("insufficient amountIn: have=%s, want=%s", swapArgs.AmountIn.String(), requiredAmountIn.String())
		}
	}

	if g.GaslessConfig.ShouldCheckToken() {

		tokenContract, err := sc_erc20.NewERC20(token, bc)
		if err != nil {
			return err
		}

		// If SwapTx.nonce is the sender's next nonce, then there is no room for ApproveTx proceeding SwapTx.
		senderNonce := g.getCurrentStateNonce(swapArgs.Sender)
		noApproveTxPreceeds := swapNonce == senderNonce
		if noApproveTxPreceeds {
			// tx.token.allowance(sender, router) >= tx.amountIn
			approval, err := tokenContract.Allowance(nil, swapArgs.Sender, swapRouter)
			if err != nil {
				return err
			}
			if approval.Cmp(swapArgs.AmountIn) < 0 {
				return fmt.Errorf("insufficient approval: approval=%s, want=%s", approval.String(), swapArgs.AmountIn.String())
			}
		}

		// tx.token.balanceOf(sender) >= tx.amountIn
		balance, err := tokenContract.BalanceOf(nil, swapArgs.Sender)
		if err != nil {
			return err
		}
		if balance.Cmp(swapArgs.AmountIn) < 0 {

func mustParseAbi(abiJson string, funcName string) abi.Method {
	abi, err := abi.JSON(strings.NewReader(abiJson))
	if err != nil {
		panic(fmt.Errorf("failed to parse abi: %w", err))
	}
	method, ok := abi.Methods[funcName]
	if !ok {
		panic(fmt.Errorf("method %s not found", funcName))
	}
	return method
}

func decodeApproveTx(tx *types.Transaction, signer types.Signer) (*ApproveArgs, bool) {
	to, inputs, ok := decodeFunctionCall(tx, erc20ApproveFunc)
	if !ok {
		return nil, false
	}
	spender, ok := inputs["spender"].(common.Address)
	if !ok {
		return nil, false
	}
	amount, ok := inputs["amount"].(*big.Int)
	if !ok {
		return nil, false
	}
	from, err := types.Sender(signer, tx)
	if err != nil {
		return nil, false
	}
	return &ApproveArgs{
		Sender:  from,
		Token:   to,
		Spender: spender,
		Amount:  amount,
	}, true
