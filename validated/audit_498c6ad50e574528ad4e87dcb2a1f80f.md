### Title
Git argument injection via unsanitized `branch` parameter in "Open in Desktop" deep links - (File: app/src/lib/parse-app-url.ts)

### Summary
The Fantom report's core primitive is: a single validation gate that, if bypassed or insufficiently strict, permanently corrupts a trusted operation with no defense in depth. The GitHub Desktop analog is `parseAppURL`'s handling of the `branch` query parameter for the `openRepo` protocol action, which is validated only with `testForInvalidChars` — a regex that does not reject values beginning with `-`, allowing a crafted deep link to smuggle a git command-line flag into a later `checkout`/clone operation performed on the user's behalf.

### Finding Description
`parseAppURL` accepts a `branch` value straight from an attacker-controlled URL (`github-mac://openRepo/...?branch=...` or `x-github-client://openRepo/...`) and only rejects it if `testForInvalidChars` matches: [1](#0-0) 

That validator, `testForInvalidChars`, is built from `sanitize-ref-name.ts`'s `invalidCharacterRegex`, which strips/blocks control characters, `~^:?*[\|"<>`, `@{`, consecutive/leading/trailing dots, `.lock` suffix, and trailing `/` — but it never blocks a branch string that starts with `-` or `--`: [2](#0-1) 

Because a leading hyphen is technically a legal git ref character but is also universally interpreted by git as an option flag, a value like `--upload-pack=touch${IFS}pwned` or `--exec=...` can pass this filter untouched. The `IOpenRepositoryFromURLAction.branch` value is then forwarded to the dispatcher's open-repository/clone-and-checkout flow (`app/src/ui/dispatcher/dispatcher.ts`, which consumes `open-repository-from-url` actions) to be used as the ref for a checkout after cloning. If that value is passed to a `git` invocation without a `--` separator (the exact same class of bug fixed upstream in git tooling for `CVE-2017-1000117`-style attacks), an attacker-controlled deep link becomes an argument-injection primitive against the user's local git process.

### Impact Explanation
If the branch string reaches a `git checkout`/`git clone`-family invocation without an explicit `--` end-of-options marker, this enables arbitrary local command execution (via `--upload-pack=<cmd>` or similar flags) or, at minimum, corruption of the repository state the user believes they are opening — directly matching the accepted impact categories (code execution / silent corruption of what the user checks out), and it requires no local/physical access: the trigger is simply the victim clicking an "Open in Desktop" link, exactly the class of untrusted input (deep link) the task scope calls out.

### Likelihood Explanation
The `openRepo` protocol handler is a documented, user-facing feature (`x-github-client://`, `github-mac://`, `github-windows://`) reachable from any external web page, email, or chat message containing a crafted link — no interaction beyond a single click is required, and the existing `testForInvalidChars` guard gives a false sense of safety while not covering the specific `-`/`--` prefix class of git argument injection.

### Recommendation
Reject or neutralize branch/ref values that begin with `-` in `parseAppURL`/`testForInvalidChars` (returning `unknown` for such input, consistent with how invalid PR/branch formats are already rejected), and additionally ensure every git invocation that consumes a ref sourced from `open-repository-from-url` inserts a literal `--` separator before the ref argument so that even a hyphen-prefixed value cannot be parsed as an option by `git`.

### Proof of Concept
1. Attacker crafts: `github-mac://openRepo/https://github.com/octocat/Hello-World?branch=--upload-pack=touch%20/tmp/pwned;`
2. Victim clicks the link; `parseAppURL` parses it, `testForInvalidChars` does not flag the leading `-`, and `open-repository-from-url` action is dispatched with `branch: "--upload-pack=touch /tmp/pwned;"`. [3](#0-2) 
3. If the branch string is passed unguarded to the checkout/clone git invocation (not independently confirmed in this session due to tool-call limits — the exact call site inside `app/src/ui/dispatcher/dispatcher.ts` should be traced in a follow-up session to confirm whether a `--` separator is already used), the attacker-controlled flag is interpreted by git, resulting in code execution or repository corruption on the victim's machine.

**Caveat:** I confirmed the missing leading-hyphen guard in `parse-app-url.ts`/`sanitize-ref-name.ts` with certainty, but I was not able to fully trace the downstream `git` command construction in `dispatcher.ts` within this session's tool budget to verify whether a `--` separator is already applied there (which would neutralize the injection). This should be verified before treating the PoC as conclusively exploitable — starting a full Devin session with complete file access would allow tracing that exact call path.

```typescript
// See https://www.kernel.org/pub/software/scm/git/docs/git-check-ref-format.html
// ASCII Control chars and space, DEL, ~ ^ : ? * [ \
// | " < and > is technically a valid refname but not on Windows
// the magic sequence @{, consecutive dots, leading and trailing dot, ref ending in .lock
const invalidCharacterRegex =
  /[\x00-\x20\x7F~^:?*\[\\|""<>]+|@{|\.\.+|^\.|\.$|\.lock$|\/$/g

/** Sanitize a proposed reference name by replacing illegal characters. */
export function sanitizedRefName(name: string): string {
  return name.replace(invalidCharacterRegex, '-').replace(/^[-\+]*/g, '')
}

/** Validate that a reference does not contain any invalid characters */
export function testForInvalidChars(name: string): boolean {
  return invalidCharacterRegex.test(name)
}
```
