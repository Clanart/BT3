### Title
Cross-shop session confusion via unverified `params[:shop]` in `EnsureInstalled#installed_shop_session` - ([File: app/controllers/concerns/shopify_app/ensure_installed.rb])

### Summary
`EnsureInstalled` (legacy, non-token-exchange path) derives `current_shopify_domain` solely from the unsigned `params[:shop]` query parameter, sanitizes only its format, and uses it to look up and load the victim shop's stored session via `SessionRepository.retrieve_shop_session_by_shopify_domain`. Neither `check_shop_domain` nor `check_shop_known` nor `validate_non_embedded_session` cryptographically bind the request to the shop whose session is loaded, so `@shop`/`installed_shop_session` can be populated with an arbitrary known shop's session/token based purely on an attacker-supplied `shop` param.

### Finding Description
The call chain is: `check_shop_domain` → `current_shopify_domain` (`app/controllers/concerns/shopify_app/ensure_installed.rb:29-38`) reads `params[:shop]` and only runs it through `ShopifyApp::Utils.sanitize_shop_domain`, which validates *domain format* (must resolve to a trusted `*.myshopify.com`-style host) but performs no signature or ownership verification (`lib/shopify_app/utils.rb:14-27`).

`check_shop_known` (`ensure_installed.rb:50-59`) then sets `@shop = installed_shop_session`, which calls `SessionRepository.retrieve_shop_session_by_shopify_domain(current_shopify_domain)` (`ensure_installed.rb:40-42`) — a direct, unauthenticated lookup keyed only by that unverified domain string. If a stored session exists for the requested shop, this check passes silently; there is no redirect, since the shop is "known."

`validate_non_embedded_session` (`ensure_installed.rb:73-82`) is the only remaining gate. It short-circuits entirely via `loaded_directly_from_admin?` (i.e., `params[:embedded] == "1"` when the app is configured as embedded) with zero verification. In the non-embedded path it performs a live Shopify Admin REST call using the victim shop's stored access token, but this only proves the app's token for that shop is still valid — it proves nothing about who is making the current request. There is no ID token verification, no HMAC check, and no App Bridge session-token validation anywhere in this concern (that logic exists only in `ShopifyApp::TokenExchange`/`WithShopifyIdToken`, which is explicitly excluded in this scenario since `use_new_embedded_auth_strategy?` is false).

As a result, any unprivileged client that knows/guesses `victim.myshopify.com` and sends a request with `params[shop]=victim.myshopify.com` (optionally `embedded=1` to skip the live-token check entirely) will have `installed_shop_session` populated with the victim's real stored session object (including its access token), and any downstream controller code that trusts `installed_shop_session`/`@shop` as an authenticated context will execute using the victim's credentials.

### Impact Explanation
This is a cross-shop session confusion / authentication bypass: an attacker-controlled request can cause the app to act as, or expose data belonging to, a shop the attacker does not own, using only that shop's public domain name. This matches Shopify's HackerOne impact classes for "Improper access control / authorization" and "Broken authentication leading to cross-merchant data exposure," since any controller including `EnsureInstalled` treats `@shop`/`installed_shop_session` as proof of legitimate shop context without any signed proof of identity (JWT/HMAC/session token).

### Likelihood Explanation
Feasibility depends entirely on the host application: `EnsureInstalled` is a reusable concern shipped by this gem and is documented as the mechanism for protecting controllers when not using the new embedded/token-exchange auth strategy. Any app using this legacy mode is affected as long as (a) an attacker can guess/know a valid installed shop's `.myshopify.com` domain (these are often guessable/enumerable), and (b) the app has a stored session for that shop (i.e., it's installed). No secrets are required — only a crafted `shop` query parameter, and optionally `embedded=1` to bypass the live-token re-validation. This is fully repeatable and requires no attacker privilege beyond making an HTTP request.

### Recommendation
Do not derive `installed_shop_session` from an unauthenticated `params[:shop]`. For legacy (non-embedded, non-token-exchange) protection, require and verify an ID token / session token (or an HMAC-signed shop parameter as Shopify's OAuth callback produces) before trusting the shop domain used to load a session, mirroring what `ShopifyApp::WithShopifyIdToken`/`TokenExchange` already do for the new embedded auth strategy. At minimum, `validate_non_embedded_session`'s live API check should not be skippable via `embedded=1` alone, and no controller action should proceed with `installed_shop_session` bound to an unverified domain claim.

### Proof of Concept
```ruby
# test/controllers/concerns/ensure_installed_session_confusion_test.rb
class DummyController < ActionController::Base
  include ShopifyApp::EnsureInstalled
  def index
    render plain: installed_shop_session.shop
  end
end

test "installed_shop_session loads victim's session from unverified shop param" do
  victim_domain = "victim.myshopify.com"
  victim_session = ShopifyAPI::Auth::Session.new(shop: victim_domain, access_token: "victim-secret-token")
  ShopifyApp::SessionRepository.store_shop_session(victim_session)

  # Attacker request: no HMAC, no ID token, no proof of identity — just the guessed domain.
  get :index, params: { shop: victim_domain, embedded: "1" }

  assert_response :success
  assert_equal victim_domain, response.body
  # installed_shop_session in the controller now carries victim's real access token,
  # even though the requester never authenticated as victim.
end
```
Expected result: the action succeeds and `installed_shop_session` returns the victim shop's real stored session (with its access token) purely because the attacker supplied `shop=victim.myshopify.com`, confirming SESSION_BINDING is violated. [1](#0-0) [2](#0-1) [3](#0-2) [4](#0-3) [5](#0-4)

        uri = uri_from_shop_domain(shop_domain)

          no_shop_name_in_subdomain = uri.host == trusted_domain
