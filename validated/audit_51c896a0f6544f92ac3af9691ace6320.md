### Title
Duplicate inputs accepted in `SignableTransaction::new` — same `ReceivedOutput`/outpoint counted multiple times - ([File: networks/bitcoin/src/wallet/send.rs])

### Summary
Analogous to `addVault` accepting the same vault repeatedly in Olympus's registry, `SignableTransaction::new` accepts a `Vec<ReceivedOutput>` and performs no deduplication on `input.outpoint` or on the outputs themselves. The same spendable output can be inserted into the input list multiple times, inflating `input_sat` and producing a transaction whose input set contains the same UTXO more than once.

### Finding Description
`SignableTransaction::new` at `networks/bitcoin/src/wallet/send.rs` L150–256 builds `tx_ins` by mapping every `ReceivedOutput` directly into a `TxIn` keyed by `input.outpoint` (L177–185), and computes `input_sat` as a plain sum over all entries (L175). There is no check that the provided outpoints are distinct.

`ReceivedOutput` is reachable from untrusted bytes: `ReceivedOutput::read` (networks/bitcoin/src/wallet/mod.rs L122–134) deserializes an arbitrary offset, `TxOut`, and `OutPoint` with no consistency check between them — the `output` value and script are not bound to the `outpoint` at all. An attacker feeding crafted bytes to `read`, or any flow that merges received-output lists without dedup, can submit the same outpoint twice (with the same or different claimed `output`).

Consequences:

- The produced `tx.input` contains the same `previous_output` twice — a consensus-invalid transaction that cannot be confirmed, yet it still passes `NotEnoughFunds`, fee, dust, and weight checks and is handed to the FROST `TransactionMachine`, which will produce a fully valid threshold signature over an unbroadcastable transaction (`TransactionSignMachine::sign`, L355–398).
- `input_sat` counts the duplicated value twice, so the balance check at L215 and the change computation at L224–235 are computed on phantom funds. A transaction can be constructed that "funds" payments and change it does not actually have — the accounting (the registry-equivalent single source of truth) is incorrect even though the transaction itself is invalid.
- A duplicate entry with a *different* `output` value for the same outpoint additionally poisons `prevouts`, so the BIP-341 `Prevouts::All` sighash commits to a fabricated input amount — signers sign a message that misrepresents the real UTXO.

### Impact Explanation
The FROST threshold signature machinery is induced to sign a transaction that can never confirm, and the wallet's internal accounting of available funds (`input_sat`, change value, `fee()`) is silently corrupted by double-counted inputs. This mirrors the Olympus finding: a duplicated entry in an append-only list corrupts the protocol's single source of truth (here, the transaction's funded amount and prevout commitments) and wastes a signing round / produces a signed artifact that fails downstream.

### Likelihood Explanation
`ReceivedOutput::read` is a documented untrusted-input surface, and the processor aggregates outputs from multiple scan/ack paths (`save_outputs`/`ack_block` flows in processor/src/multisigs/scanner.rs). Any duplicate outpoint reaching the input list is accepted unconditionally. Exploitation yields a guaranteed-invalid signed transaction rather than fund theft, bounding this at Medium.

### Recommendation
In `SignableTransaction::new`, deduplicate `inputs` by `outpoint` (reject on `HashSet::insert` returning false) before computing `input_sat` and `tx_ins`. Additionally, reject duplicate `(outpoint)` regardless of differing `output` fields, since one outpoint maps to exactly one chain output.

### Proof of Concept
```rust
let dup = received_output.clone(); // same outpoint, same output
let tx = SignableTransaction::new(
  vec![received_output, dup],   // same UTXO twice
  &payments, change, None, fee_per_vbyte,
).unwrap();
// input_sat counted the output's value twice;
// tx.transaction().input has two TxIns with identical previous_output;
// threshold signing succeeds, producing a consensus-invalid transaction.
```
