## Analysis

The Starklane report's core broken invariant is: **an admin-controlled "disabled" flag blocks a settlement path for funds that were already committed/burned on the other side of the bridge**, even though that settlement is not itself a new deposit/risk-creating operation. The direct Hyperbridge analog is the `whenNotPaused` modifier applied to the *inbound settlement* functions of `HyperFungibleToken` / `WrappedHyperFungibleToken` (and their upgradeable variants), rather than being confined to the *outbound* `send()` entrypoint only.

### Title
Pausing blocks both minting and timeout-refund paths in `HyperFungibleToken`/`WrappedHyperFungibleToken`, stranding already-burned funds - (File: `sdk/packages/core/contracts/apps/HyperFungibleToken.sol`)

### Summary
`HyperFungibleToken.send()` burns tokens on the source chain and dispatches an ISMP POST request. Settlement of that burn happens either via `onAccept` (mint on destination) or, if it times out, via `onPostRequestTimeout` (re-mint/refund on source) [1](#0-0) . Both of these settlement callbacks — the *only* ways a user can ever recover value for tokens already burned — are gated by `whenNotPaused`, exactly like `send()` itself [2](#0-1) . The identical pattern exists in `WrappedHyperFungibleToken.onAccept`/`onPostRequestTimeout`, which additionally custody real ERC20/native value rather than mint/burn [3](#0-2) , and in both upgradeable versions [4](#0-3) [5](#0-4) .

### Finding Description
Because `onAccept` and `onPostRequestTimeout` are external functions invoked synchronously by the handler/host during `handlePostRequests`/`handlePostRequestTimeouts` [6](#0-5) [7](#0-6) , a revert inside the app (from `whenNotPaused`) reverts the whole relayer-submitted proof-delivery transaction. This is not merely "no new deposits allowed" (which would be the correct place to isolate a disable flag, per the original report's recommendation) — it also blocks the two functions that *settle funds already removed from user custody on the other chain*:
- If the destination-side app is paused, an inbound transfer cannot be minted to the beneficiary at all, and the message sits undelivered.
- If the source-side app is paused, a user whose transfer times out cannot receive their refund via `onPostRequestTimeout`, even though their tokens were already burned in `send()`.

There is no code path that separates "block new outbound `send()`" from "block settlement of already-initiated transfers," which is precisely the anti-pattern the external report flags in `Starklane.withdrawTokens`. `WrappedHyperFungibleToken` makes the impact concrete because it holds real custodied ERC20/native value rather than a mint/burn accounting token [8](#0-7) : a paused contract cannot release escrowed funds to either the destination beneficiary or the timeout refundee.

### Impact Explanation
While the ISMP message itself can in principle be re-submitted by a relayer once `unpause()` is called, the owner is the only party who can restore access, and there is no time bound on how long a pause can persist. During that window, users who already burned/escrowed tokens on one chain (via `send()`) have no way to recover value on either side — not through minting, not through timeout refund — reproducing the exact "funds locked because of a disabled flag on an already-committed settlement" pattern from the seed report, but now against actual custodied value in `WrappedHyperFungibleToken`.

### Likelihood Explanation
This requires no malicious relayer, prover, or governance actor — it is triggered by the token owner calling the documented, intended `pause()` function [9](#0-8)  during any maintenance/incident window while transfers are in flight, which is a realistic, expected operational scenario rather than an attack requiring privileged compromise.

### Recommendation
Do not gate `onAccept` and `onPostRequestTimeout` with `whenNotPaused`. Restrict the pause check to `send()` (and other functions that create *new* outbound risk), so that settlement of funds already burned/escrowed elsewhere can always complete regardless of the paused state — mirroring the fix recommended in the seed report for `Starklane.withdrawTokens`.

### Proof of Concept
1. User calls `send()` on chain A, burning `amount` tokens and dispatching a POST request to chain B (`HyperFungibleToken.send`, `sdk/packages/core/contracts/apps/HyperFungibleToken.sol:264-282`).
2. Owner calls `pause()` on the chain B token contract for an operational reason unrelated to this specific transfer.
3. Relayer submits `handlePostRequests` with a valid proof; `HandlerV2.handlePostRequests` calls `host.dispatchIncoming` → `onAccept`, which reverts due to `whenNotPaused` (`HyperFungibleToken.sol:291`), reverting the whole delivery.
4. The request later times out. Owner has since also paused chain A (or never unpauses chain B). Relayer submits `handlePostRequestTimeouts`; `onPostRequestTimeout` on chain A also reverts if chain A is paused (`HyperFungibleToken.sol:320`).
5. The user's tokens remain burned with no live path to mint, receive, or refund until an admin unpauses — funds effectively locked, matching the seed report's impact.

    function onAccept(IncomingPostRequest calldata incoming) external override onlyHost whenNotPaused {
        PostRequest calldata request = incoming.request;

        bytes memory expectedSource = _supportedChains[request.source];
        if (expectedSource.length == 0) revert UnsupportedChain();
        if (keccak256(request.from) != keccak256(expectedSource)) revert UnauthorizedSource();

        HyperFungibleToken.Message memory message = abi.decode(request.body, (HyperFungibleToken.Message));
        address beneficiary = _toAddr(message.to);

        if (_isWeth) {
            // Try a native-ETH push first (cheap for EOAs and payable contracts);
            // if the recipient cannot accept native value (no `receive()` / `fallback()
            // payable`), re-wrap the withdrawn ETH and deliver the underlying WETH as
            // an ERC-20 transfer instead. This mirrors the deposit-side flexibility of
            // `send()` (which accepts WETH from non-payable callers via `safeTransferFrom`)
            // so the refund path doesn't permanently lock funds for the same caller class.
            IWETH(_underlying).withdraw(message.amount);
            (bool sent,) = beneficiary.call{value: message.amount}("");
            if (!sent) {
                IWETH(_underlying).deposit{value: message.amount}();
                IERC20(_underlying).safeTransfer(beneficiary, message.amount);
            }
        } else {
            IERC20(_underlying).safeTransfer(beneficiary, message.amount);
        }

        if (message.data.length > 0) {
            ICallDispatcher(_dispatcher).dispatch(message.data);
        }

        emit Received({
            from: message.from,
            to: beneficiary,
            source: string(request.source),
            amount: message.amount
        });
    }

    function handlePostRequests(IHost host, PostRequestMessage calldata request) external notFrozen(host) {
        uint256 timestamp = block.timestamp;
        uint256 delay = timestamp - host.stateMachineCommitmentUpdateTime(request.proof.height);
        uint256 challengePeriod = host.challengePeriod();
        if (challengePeriod != 0 && challengePeriod > delay) revert ChallengePeriodNotElapsed();

        uint256 requestsLen = request.requests.length;
        MerkleMountainRange.Leaf[] memory leaves = new MerkleMountainRange.Leaf[](requestsLen);

        for (uint256 i = 0; i < requestsLen; ++i) {
            PostRequestLeaf memory leaf = request.requests[i];
            // check destination
            if (!leaf.request.dest.equals(host.host())) revert InvalidMessageDestination();
            // check time-out
            if (timestamp >= leaf.request.timeout()) revert MessageTimedOut();
            leaves[i] = MerkleMountainRange.Leaf(leaf.index, leaf.request.hash());
        }

        bytes32 root = host.stateMachineCommitment(request.proof.height).overlayRoot;
        if (root == bytes32(0)) revert StateCommitmentNotFound();
        bool valid = MerkleMountainRange.VerifyProof(root, request.proof.multiproof, leaves, request.proof.leafCount);
        if (!valid) revert InvalidProof();

        for (uint256 i = 0; i < requestsLen; ++i) {
            PostRequestLeaf memory leaf = request.requests[i];
            // duplicate request?
            if (host.requestReceipts(leaf.request.hash()) != address(0)) revert DuplicateMessage();
            host.dispatchIncoming(leaf.request, _msgSender());
        }
    }

    function handlePostRequestTimeouts(IHost host, PostRequestTimeoutMessage calldata message)
        external
        notFrozen(host)
    {
        uint256 delay = block.timestamp - host.stateMachineCommitmentUpdateTime(message.height);
        uint256 challengePeriod = host.challengePeriod();
        if (challengePeriod != 0 && challengePeriod > delay) revert ChallengePeriodNotElapsed();

        // fetch the state commitment
        StateCommitment memory state = host.stateMachineCommitment(message.height);
        if (state.stateRoot == bytes32(0)) revert StateCommitmentNotFound();
        uint256 timeoutsLength = message.timeouts.length;

        for (uint256 i = 0; i < timeoutsLength; ++i) {
            PostRequest memory request = message.timeouts[i];
            // timed-out?
            if (request.timeout() > state.timestamp) revert MessageNotTimedOut();

            // known request? also serves as source check
            bytes32 requestCommitment = request.hash();
            FeeMetadata memory meta = host.requestCommitments(requestCommitment);
            if (meta.sender == address(0)) revert UnknownMessage();

            bytes[] memory keys = new bytes[](1);
            keys[0] = bytes.concat(REQUEST_RECEIPTS_STORAGE_PREFIX, requestCommitment);

            // verify state trie non-membership proofs
            PolkadotTrie.StorageValue memory entry = PolkadotTrie.VerifyProof(state.stateRoot, message.proof, keys)[0];
            if (entry.value.length != 0) revert InvalidProof();

            host.dispatchTimeOut(PostRequestTimeout(request, _msgSender()), meta, requestCommitment);
        }
    }
