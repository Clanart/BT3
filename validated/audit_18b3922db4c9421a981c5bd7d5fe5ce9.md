### Title
Panic on unregistered decryptor index in PedPoP blame verification allows unprivileged denial of service - (File: crypto/dkg/pedpop/src/encryption.rs)

### Summary
The Xen CVE concerns a privileged component reachable by an untrusted party whose crafted input corrupts state and crashes the host. The Serai analog lives in PedPoP's blame/decryption path: `Decryption::decrypt_with_proof` indexes `self.enc_keys` with an attacker-influenced `decryptor` participant index using `HashMap`'s `[]` operator, which panics when the key is absent. A participant submitting a blame/accusation flow that resolves to a `decryptor` index that was never registered (e.g., a valid `Participant` value within the `u16` range but outside the registered set, or an index whose commitment round failed) causes a panic inside in-scope crypto code, aborting the calling task.

### Finding Description
`Decryption::new`/`register` populate `enc_keys` only for participants who registered an `EncryptionKeyMessage` (encryption.rs:348-361). During `decrypt_with_proof`, after verifying the accused's PoP signature, the code dereferences the accuser/decryptor's encryption key via `self.enc_keys[&decryptor]` (encryption.rs:388). If `decryptor` is not present in the map — which an unprivileged participant can arrange by triggering a blame verification naming a `Participant` index with no registered encryption key (the index is attacker-supplied protocol data, only constrained by `Participant::new` being nonzero) — the `Index` impl panics. There is no `get()`/`ok_or` fallible lookup and no check that `decryptor` was registered.

This is reachable entirely through public protocol inputs: the accuser index and the `EncryptedMessage`/`EncryptionKeyProof` bytes are attacker-controlled fields fed to `EncryptedMessage::read` and the blame/`decrypt_with_proof` API.

### Impact Explanation
A single malicious participant can crash the key-generation/blame-handling task of honest processors by supplying an accusation whose accuser/decryptor index is not in `enc_keys`. This is a denial of service of the DKG/blame flow — the same class as CVE-2016-7094 (unprivileged guest input crashing the privileged hypervisor): a small, crafted message terminates the privileged process handling it. Repeated submissions can prevent DKG completion or stall blame resolution.

### Likelihood Explanation
Any protocol participant can submit accusations/blame data; no threshold collusion, key compromise, or trusted-party misbehavior is required. The panic is deterministic whenever the supplied index is absent from the map — no race or negligible probability is involved. Impact is bounded to availability (a panic, not memory corruption or key leakage), matching a Medium severity.

### Recommendation
Replace the infallible map index at encryption.rs:388 with a fallible lookup and treat a missing key as `DecryptionError::InvalidProof`:

```rust
let Some(dec_key) = self.enc_keys.get(&decryptor) else {
  Err(DecryptionError::InvalidProof)?
};
proof
  .dleq
  .verify(
    &mut encryption_key_transcript(self.context),
    &[C::generator(), msg.key],
    &[*dec_key, *proof.key],
  )
  .map_err(|_| DecryptionError::InvalidProof)?;
```

Additionally, validate the accuser/decryptor index against `params.n()` before attempting decryption, mirroring the `included`-set validation performed elsewhere in `crypto/dkg`.

### Proof of Concept
1. Set up a `Decryption<C>` instance via `Decryption::new(context)` and register encryption keys for participants `1..=n` via `register`, deliberately omitting index `k` (e.g., a participant whose commitments were rejected, or an index `> n` that `Participant::new` still accepts).
2. As an attacker, produce an `EncryptedMessage<C, E>` carrying a valid PoP signature under a controlled key so the `msg.pop.verify(...)` check at encryption.rs:374-379 passes (the PoP challenge binds `from`, the key, and the ciphertext — all attacker-chosen).
3. Supply a valid `EncryptionKeyProof` DLEq for `proof.key` so the `dleq.verify` precondition is well-formed.
4. Call `decrypt_with_proof(from, k, msg, Some(proof))`. The line `self.enc_keys[&decryptor]` indexes a missing entry and panics, crashing the caller's task — confirmed reachable purely from attacker-supplied index and message bytes.
