### Title
Unvalidated `kip71.gastarget` Governance Parameter Allows Division-by-Zero Panic in Base Fee Calculation - (File: `params/kip71_config.go`)

### Summary
The `kip71.gastarget` governance parameter, which is used as a divisor when computing the next block's base fee under KIP-71/Magma, has no lower-bound validation (`noopFormatChecker`). A vote setting `GasTarget = 0` passes all format checks and, once ratified, causes a division-by-zero panic in `NextMagmaBlockBaseFee`, crashing every node that processes the affected block. This mirrors the reported pattern of "fixed funding rate parameters" (`maxFundingVelocity`/`maxVelocitySkew`) being settable via an authorized function without adequate bounds/safety checks.

### Finding Description
The governance parameter `Kip71GasTarget` is registered with a `noopFormatChecker` that accepts any `uint64` value, including zero: [1](#0-0) 

Unlike `Kip71LowerBoundBaseFee`/`Kip71UpperBoundBaseFee`, which have cross-parameter consistency checks in `checkConsistency`, and unlike `BaseFeeDenominator` whose zero-value is explicitly special-cased, `GasTarget` has no such protection anywhere in the vote-validation pipeline: [2](#0-1) 

`NewVoteData` only applies the `Canonicalizer` (type check to `uint64`) and the `FormatChecker` (no-op) before accepting the vote: [3](#0-2) 

Once ratified and effective, `GasTarget=0` is used directly as a divisor in `NextMagmaBlockBaseFee`, while only `BaseFeeDenominator == 0` is defensively handled: [4](#0-3) 

Specifically, when `parentGasUsed != gasTarget` (i.e. almost always once `gasTarget=0` since any real block will have gas used > 0), the code performs `x.Div(x, new(big.Int).SetUint64(gasTarget))`, which panics in Go's `math/big` on division by zero.

### Impact Explanation
Because `NextMagmaBlockBaseFee` is called deterministically by every node validating/building the next block's header (base fee verification and block assembly), a `gasTarget=0` value ratified into the governance parameter set will crash all honest nodes simultaneously the moment they process a block with non-zero gas usage after the parameter's activation height. This is a chain-halting denial-of-service impacting the entire network, not a resource-only or single-node issue, since it affects consensus-critical block processing (state transition / base fee computation) for all participants.

### Likelihood Explanation
The precondition is a ratified `kip71.gastarget` vote of `0`. This requires action from the party authorized to vote governance parameters (the governing node in `single` mode) — directly analogous to the `onlyOwner`-gated `setMaxFundingVelocity`/`setMaxVelocitySkew` functions in the original report, which also lacked safeguards on an owner-controlled critical parameter. As shown by the unit tests, `GasTarget=0` is never rejected by `NewVoteData`, `checkConsistency`, or `ParamSet.Set` — the only checks are type-based, not range-based, so a single vote transaction is sufficient to introduce the unsafe value; no additional exploit complexity is required once the vote is cast and ratified.

### Recommendation
Add a non-zero (and reasonably bounded) `FormatChecker` for `Kip71GasTarget` (and consider `Kip71MaxBlockGasUsedForBaseFee`) analogous to the existing `Kip71BaseFeeDenominator` checker (`v != 0`), and/or add a defensive `if gasTarget == 0` fallback inside `NextMagmaBlockBaseFee` similar to the existing `baseFeeDenominator == 0` handling, so that a bad or malicious governance vote cannot crash node execution.

### Proof of Concept
1. As the governing node, cast a vote: `governance_vote("kip71.gastarget", 0)`. This is accepted by `NewVoteData` in `kaiax/gov/headergov/vote.go` since `Kip71GasTarget`'s `FormatChecker` is a no-op that only checks the value is a `uint64` (see `kaiax/gov/param.go:324-334`).
2. The vote is ratified at the next epoch boundary and becomes effective at `(k+1)*epoch` per header governance semantics.
3. Once effective, any subsequent block with `parentHeaderGasUsed > 0` triggers `NextMagmaBlockBaseFee` (`params/kip71_config.go`) to execute `x.Div(x, new(big.Int).SetUint64(gasTarget))` with `gasTarget=0`, causing a `math/big` division-by-zero panic in every node computing/verifying the header's base fee, halting block processing network-wide.

func NewVoteData(voter common.Address, name string, value any) VoteData {
	param, ok := gov.Params[gov.ParamName(name)]
	if !ok {
		param, ok = gov.ValidatorParams[gov.ParamName(name)]
		if !ok {
			logger.Error("Invalid vote name", "name", name)
			return nil
		}
	}

	cv, err := param.Canonicalizer(value)
	if err != nil {
		logger.Error("Canonicalize error", "name", name, "value", value, "err", err)
		return nil
	}

	if !param.FormatChecker(cv) {
		logger.Error("Format check error", "name", name, "value", value)
		return nil
	}

	return &voteData{
		voter: voter,
		name:  gov.ParamName(name),
		value: cv,
	}
}
