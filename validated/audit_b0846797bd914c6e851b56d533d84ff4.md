### Title
`update_finalized_payouts` attributes a single Bitcoin payout to multiple Citrea withdrawal indices because the utxo→payout join has no deposit/move-txid component - ([File: core/src/verifier.rs], [File: core/src/database/verifier.rs])

### Summary
`Verifier::update_finalized_payouts` derives `(withdrawal_idx, payout_txid, operator_xonly_pk)` tuples from `Database::get_payout_txs_for_withdrawal_utxos`, which joins the `withdrawals` table to `bitcoin_syncer_spent_utxos` solely on `(withdrawal_utxo_txid, withdrawal_utxo_vout)` with no `deposit_id`/`move_to_vault_txid` disambiguator. Because `withdrawal_utxo_txid/vout` for each Citrea withdrawal index is populated verbatim from the caller-controlled `withdraw()` argument with no uniqueness constraint in `schema.sql`, two different withdrawal indices belonging to two different deposits can be registered with the identical outpoint, causing one real Bitcoin spend to be credited as the fronted payout for both.

### Finding Description
The broken binding: the code assumes `withdrawal_utxo -> exactly one (deposit_id, payout)` but the schema and query only enforce `withdrawal_utxo -> spending_txid`, i.e. `payout_txid(idx1) == payout_txid(idx2)` is possible whenever `withdrawal_utxo(idx1) == withdrawal_utxo(idx2)`.

- `withdrawals` has `idx int primary key` and unconstrained `withdrawal_utxo_txid bytea`, `withdrawal_utxo_vout int` [1](#0-0) .
- `update_withdrawal_utxo_from_citrea_withdrawal` writes the Citrea-supplied outpoint into the row for `citrea_idx` with no check against other rows [2](#0-1) .
- `Verifier::update_citrea_deposit_and_withdrawals` pulls each withdrawal's utxo straight from `collect_withdrawal_utxos` (which reads `withdrawalUTXOs(idx)` off the Citrea contract) and stores it per `idx` unconditionally [3](#0-2) [4](#0-3) .
- `get_payout_txs_for_withdrawal_utxos` joins `withdrawals w` to `bitcoin_syncer_spent_utxos bsu` on `bsu.txid = w.withdrawal_utxo_txid AND bsu.vout = w.withdrawal_utxo_vout`, filtered only by `block_id` — no `deposit_id`/move-txid term [5](#0-4) .
- `Verifier::update_finalized_payouts` iterates the returned `(idx, payout_txid)` pairs, parses the OP_RETURN of `payout_txid` once, and writes the same `operator_xonly_pk` into every matching `idx` via `update_payout_txs_and_payer_operator_xonly_pk` (which does a bulk `UPDATE ... WHERE w.idx = c.idx`, keyed only by `idx`, not by which utxo the tx actually intended to satisfy) [6](#0-5) [7](#0-6) .

Exploit flow: attacker makes deposit1 and deposit2 (two separate move-to-vault txids). Attacker calls Citrea `withdraw()` for both, supplying the *same* Bitcoin outpoint bytes as `withdrawal_utxo` for both `idx1` and `idx2`. When the block syncer ingests the block, both `withdrawals` rows (`idx1`, `idx2`) now reference the identical `(txid, vout)`. An operator (attacker-controlled or an honest operator being manipulated) fronts a real payout by spending that shared outpoint once, satisfying `idx1`'s intended recipient. The syncer records exactly one `bitcoin_syncer_spent_utxos` entry for that outpoint. `get_payout_txs_for_withdrawal_utxos` returns both `(idx1, txid)` and `(idx2, txid)` because both DB rows match that single spent-utxo record. `update_finalized_payouts` then marks `idx2` as paid by the same operator's `xonly_pk`, even though no payment was ever made to `idx2`'s designated recipient. `PayoutCheckerTask`, driven by `get_first_unhandled_payout_by_operator_xonly_pk`, subsequently treats `idx2` as an unhandled payout owed to that operator and calls `Operator::handle_finalized_payout` for deposit2's outpoint, initiating a kickoff/reimbursement for a payout the operator never funded [8](#0-7) .

None of the listed guards intervene: `is_deposit_valid`, `verify_storage_proofs`, `SPV::verify`, and `is_kickoff_malicious` all validate per-deposit/per-kickoff facts and never check whether the same `withdrawal_utxo` value has been reused across unrelated deposit indices; there is no DB uniqueness constraint on `(withdrawal_utxo_txid, withdrawal_utxo_vout)` to reject the second `withdraw()` registration.

### Impact Explanation
A single fronted Bitcoin payment gets recorded as satisfying two (or more) independent Citrea withdrawal indices belonging to different deposits. The operator who fronted only one payment is credited as the payer for a second deposit it never actually paid out to, letting it drive that deposit's kickoff/reimbursement flow and be reimbursed for a payout it never funded — matching the Critical category "an operator reimbursed for a payout it never funded." This is repeatable per pair of attacker-controlled deposits/withdrawals that share a crafted `withdrawal_utxo` value, so the blast radius scales with the number of colliding withdrawal registrations the attacker is willing to submit.

### Likelihood Explanation
The only precondition is the ability to call the Citrea `withdraw()` entrypoint twice with attacker-chosen `withdrawal_utxo` bytes for two different deposits — explicitly granted to the unprivileged attacker in this audit's threat model — plus normal deposit fees. No verifier, operator, or aggregator privilege is required, and the divergence is entirely a server-side database/query design gap (missing `deposit_id`/move-txid key), not dependent on hash power, key compromise, or Citrea consensus manipulation. This makes the issue straightforward to trigger repeatedly.

### Recommendation
Include `move_to_vault_txid` (or `deposit_id`) as part of the join/update key in `get_payout_txs_for_withdrawal_utxos` and `update_payout_txs_and_payer_operator_xonly_pk`, and/or enforce a uniqueness constraint on `(withdrawal_utxo_txid, withdrawal_utxo_vout)` in the `withdrawals` table (or reject a `withdraw()` registration whose utxo already exists for a different `idx`) so that a single Bitcoin spend can only ever satisfy the one withdrawal index it was registered against.

```rust
// core/src/database/verifier.rs - proof of collision via test
#[tokio::test]
async fn duplicate_withdrawal_utxo_across_two_deposits_credits_same_payout_twice() {
    let config = create_test_config_with_thread_name().await;
    let db = Database::new(&config).await.unwrap();
    let mut dbtx = db.begin_transaction().await.unwrap();

    let shared_utxo = bitcoin::OutPoint {
        txid: bitcoin::Txid::from_byte_array([0x11; 32]),
        vout: 0,
    };
    let payout_txid = bitcoin::Txid::from_byte_array([0x22; 32]);

    // Two unrelated deposits/withdrawals (idx 1 and idx 2) with different move-to-vault txids
    let move_txid_1 = bitcoin::Txid::from_byte_array([0xAA; 32]);
    let move_txid_2 = bitcoin::Txid::from_byte_array([0xBB; 32]);
    db.upsert_move_to_vault_txid_from_citrea_deposit(Some(&mut dbtx), 1, &move_txid_1).await.unwrap();
    db.upsert_move_to_vault_txid_from_citrea_deposit(Some(&mut dbtx), 2, &move_txid_2).await.unwrap();

    let block_id = db.insert_block_info(Some(&mut dbtx), &BlockHash::all_zeros(), &BlockHash::all_zeros(), 0).await.unwrap();
    db.insert_txid_to_block(&mut dbtx, block_id, &payout_txid).await.unwrap();
    // A single real spend of shared_utxo
    db.insert_spent_utxo(&mut dbtx, block_id, &payout_txid, &shared_utxo.txid, shared_utxo.vout.into()).await.unwrap();

    // Attacker registers the SAME withdrawal_utxo for both idx=1 and idx=2 (Citrea-side attacker control)
    db.update_withdrawal_utxo_from_citrea_withdrawal(Some(&mut dbtx), 1, shared_utxo, block_id).await.unwrap();
    db.update_withdrawal_utxo_from_citrea_withdrawal(Some(&mut dbtx), 2, shared_utxo, block_id).await.unwrap();

    // Assert the join returns the SAME payout_txid for BOTH idx 1 and idx 2 from one real spend
    let txs = db.get_payout_txs_for_withdrawal_utxos(Some(&mut dbtx), block_id).await.unwrap();
    assert_eq!(txs.len(), 2);
    assert!(txs.contains(&(1, payout_txid)));
    assert!(txs.contains(&(2, payout_txid))); // <- conflation: idx2 never had a real payment

    dbtx.commit().await.unwrap();
}
```

```rust
    /// Sets the given payout txs' txid and operator index for the given index.
    pub async fn update_payout_txs_and_payer_operator_xonly_pk(
        &self,
        tx: Option<DatabaseTransaction<'_>>,
        payout_txs_and_payer_operator_xonly_pk: Vec<(
            u32,
            Txid,
            Option<XOnlyPublicKey>,
            bitcoin::BlockHash,
        )>,
    ) -> Result<(), BridgeError> {
        if payout_txs_and_payer_operator_xonly_pk.is_empty() {
            return Ok(());
        }
        // Convert all values first, propagating any errors
        let converted_values: Result<Vec<_>, BridgeError> = payout_txs_and_payer_operator_xonly_pk
            .iter()
            .map(|(idx, txid, operator_xonly_pk, block_hash)| {
                Ok((
                    i32::try_from(*idx).wrap_err("Failed to convert payout index to i32")?,
                    TxidDB(*txid),
                    operator_xonly_pk.map(XOnlyPublicKeyDB),
                    BlockHashDB(*block_hash),
                ))
            })
            .collect();
        let converted_values = converted_values?;

        let mut query_builder = QueryBuilder::new(
            "UPDATE withdrawals AS w SET
                payout_txid = c.payout_txid,
                payout_payer_operator_xonly_pk = c.payout_payer_operator_xonly_pk,
                payout_tx_blockhash = c.payout_tx_blockhash
                FROM (",
        );

        query_builder.push_values(
            converted_values.into_iter(),
            |mut b, (idx, txid, operator_xonly_pk, block_hash)| {
                b.push_bind(idx)
                    .push_bind(txid)
                    .push_bind(operator_xonly_pk)
                    .push_bind(block_hash);
            },
        );

        query_builder
            .push(") AS c(idx, payout_txid, payout_payer_operator_xonly_pk, payout_tx_blockhash) WHERE w.idx = c.idx");

        let query = query_builder.build();
        execute_query_with_tx!(self.connection, tx, query, execute)?;

        Ok(())
    }
```

```rust
    async fn update_finalized_payouts(
        &self,
        dbtx: DatabaseTransaction<'_>,
        block_id: u32,
        block_cache: &block_cache::BlockCache,
    ) -> Result<(), BridgeError> {
        let payout_txids = self
            .db
            .get_payout_txs_for_withdrawal_utxos(Some(dbtx), block_id)
            .await?;

        let block = &block_cache.block;

        let block_hash = block.block_hash();

        let mut payout_txs_and_payer_operator_idx = vec![];
        for (idx, payout_txid) in payout_txids {
            let payout_tx_idx = block_cache.txids.get(&payout_txid);
            if payout_tx_idx.is_none() {
                tracing::error!(
                    "Payout tx not found in block cache: {:?} and in block: {:?}",
                    payout_txid,
                    block_id
                );
                tracing::error!("Block cache: {:?}", block_cache);
                return Err(eyre::eyre!("Payout tx not found in block cache").into());
            }
            let payout_tx_idx = payout_tx_idx.expect("Payout tx not found in block cache");
            let payout_tx = &block.txdata[*payout_tx_idx];
            // Find the first output that contains OP_RETURN
            let circuit_payout_tx = CircuitTransaction::from(payout_tx.clone());
            let op_return_output = get_first_op_return_output(&circuit_payout_tx);

            // If OP_RETURN doesn't exist in any outputs, or the data in OP_RETURN is not a valid xonly_pubkey,
            // operator_xonly_pk will be set to None, and the corresponding column in DB set to NULL.
            // This can happen if optimistic payout is used, or an operator constructs the payout tx wrong.
            let operator_xonly_pk = op_return_output
                .and_then(|output| parse_op_return_data(&output.script_pubkey))
                .and_then(|bytes| XOnlyPublicKey::from_slice(bytes).ok());

            if operator_xonly_pk.is_none() {
                tracing::info!(
                    "No valid operator xonly pk found in payout tx {:?} OP_RETURN. Either it is an optimistic payout or the operator constructed the payout tx wrong",
                    payout_txid
                );
            }

            tracing::info!(
                "A new payout tx detected for withdrawal {}, payout txid: {:?}, operator xonly pk: {:?}",
                idx,
                payout_txid,
                operator_xonly_pk
            );

            payout_txs_and_payer_operator_idx.push((
                idx,
                payout_txid,
                operator_xonly_pk,
                block_hash,
            ));
        }

        self.db
            .update_payout_txs_and_payer_operator_xonly_pk(
                Some(dbtx),
                payout_txs_and_payer_operator_idx,
            )
            .await?;

        Ok(())
    }
```

```rust
    async fn collect_withdrawal_utxos(
        &self,
        last_withdrawal_idx: Option<u32>,
        to_height: u64,
    ) -> Result<Vec<(u64, OutPoint)>, BridgeError> {
        let mut utxos = vec![];

        let mut start_idx = match last_withdrawal_idx {
            Some(idx) => idx + 1,
            None => 0,
        };

        loop {
            let withdrawal_utxo = self
                .contract
                .withdrawalUTXOs(U256::from(start_idx))
                .block(BlockId::Number(BlockNumberOrTag::Number(to_height)))
                .call()
                .await;
            match withdrawal_utxo {
                Err(e) if e.to_string().contains("execution reverted") => {
                    tracing::trace!("Withdrawal utxo not found for index, error: {:?}", e);
                    break;
                }
                Err(e) => return Err(e.into()),
                Ok(_) => {}
            }
            let withdrawal_utxo = withdrawal_utxo.expect("Failed to get withdrawal UTXO");
            let txid = withdrawal_utxo.txId.0;
            let txid =
                Txid::from_slice(txid.as_ref()).wrap_err("Failed to convert txid to Txid")?;
            let vout = withdrawal_utxo.outputId.0;
            let vout = u32::from_le_bytes(vout);
            let utxo = OutPoint { txid, vout };
            utxos.push((start_idx as u64, utxo));
            start_idx += 1;
        }
        Ok(utxos)
    }
```
