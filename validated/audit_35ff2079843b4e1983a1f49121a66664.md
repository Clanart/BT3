## Title
Users can front-run `castVotes` to steal a disproportionate share of bribe yield by momentarily inflating their vote weight - (File: `wombat/WombatBribeManager.sol`)

### Summary
`WombatBribeManager.vote()` / `unvote()` let any vlMGP holder instantly move voting weight between pools, and the permissionless `castVotes()` function harvests all bribes accrued for each pool since the last cast and distributes them through `queueNewRewards`, whose per-share accounting is calculated against the pool's *current* `totalStaked()`. Because there is no delay, cooldown, or snapshotting between changing vote weight and a bribe harvest, an attacker can watch a pending `castVotes()` transaction in the mempool, front-run it by shifting a large amount of vlMGP voting power into the targeted pool, capture a share of that pool's entire pending bribe payout proportional to their inflated share, and immediately `unvote()` afterward to reclaim their voting power — stealing yield that should have accrued to the pool's genuine long-term voters. This mirrors the referenced PoolTogether issue, where an actor could observe a state-revealing/distribution-triggering transaction and manipulate their balance beforehand to capture value meant for others.

### Finding Description
`vote()` updates `pool.totalVoteInVlmgp` and calls `IBribeRewardPool(pool.rewarder).stakeFor(msg.sender, delta)` synchronously, with no lock-up: [1](#0-0) 

`unvote()` symmetrically removes the vote and withdraws it from the rewarder instantly: [2](#0-1) 

`BribeRewardPool.stakeFor` / `withdrawFor` update `totalSupply` (i.e., `totalStaked()`) and the user's balance immediately, with reward accounting (`updateRewards`) settled at call time: [3](#0-2) 

`castVotes()` is a public, permissionless function ("gas intensive, hence a fee is given to the caller") that rebalances on-chain votes and, through `wombatStaking.vote()`, harvests bribes and calls `queueNewRewards` for each pool's rewarder: [4](#0-3) 

`queueNewRewards` → `_provisionReward` distributes the harvested lump sum by increasing `rewardPerTokenStored` proportionally to `totalStaked()` **at the moment the reward is provisioned**, not proportionally to time-weighted participation: [5](#0-4) 

Since a user's vote weight in a pool (and thus their share of `totalStaked()`) can be inflated an instant before `castVotes()` executes and withdrawn an instant after, with no minimum holding period, an attacker can insert themselves into the reward distribution snapshot without having actually contributed voting weight for any meaningful duration, diluting/stealing the yield that should go to voters who committed their vlMGP for the whole period since the last cast.

### Impact Explanation
This allows an unprivileged vlMGP holder to repeatedly extract a disproportionate share of bribe rewards accrued by long-term voters for any pool, each time `castVotes()` (or `voteAndCast`) is called — which is a normal, frequent, permissionless protocol operation. This constitutes theft of unclaimed yield from honest voters, satisfying the "theft ... of unclaimed yield" impact criterion.

### Likelihood Explanation
Likelihood is high: `castVotes()`/`voteAndCast()` are public and regularly triggered (anyone can call them for a caller fee), so pending calls are visible in the mempool. The attacker only needs an existing vlMGP position (no privileged access) and enough available/unused voting power (`getUserVotable`) to shift into the targeted pool for one transaction before immediately reversing it — a standard sandwich pattern requiring no special capital lock-up beyond gas and existing vlMGP.

### Recommendation
Decouple bribe-reward accrual from instantaneous vote weight: e.g., snapshot vote weights over time (time-weighted average), enforce a minimum holding/cooldown period between `vote()`/`unvote()` calls on the same pool relative to `castVotes()`, or accrue bribe rewards continuously per-second (like the MGP emission model) rather than distributing harvested lump sums against the instantaneous `totalStaked()`.

### Proof of Concept
1. Attacker holds vlMGP with unused votable power (`getUserVotable(attacker) > 0`).
2. Attacker observes a pending `castVotes()` (or `voteAndCast()`) transaction in the mempool that will harvest a large pending bribe for pool `P` (`previewBribes`/`previewBnbAmountForHarvest` can be used to identify a profitable target).
3. Attacker front-runs with `vote([P], [largeDelta])`, calling `WombatBribeManager.vote()` at `wombat/WombatBribeManager.sol:182-220`, which calls `BribeRewardPool.stakeFor` at `rewards/BribeRewardPool.sol:57-67`, inflating `totalSupply` for pool `P`'s rewarder just before harvest.
4. The pending `castVotes()` executes, harvesting bribes and calling `queueNewRewards` → `_provisionReward` (`rewards/BaseRewardPoolV2.sol:290-313`), which increases `rewardPerTokenStored` based on the now-inflated `totalStaked()`, crediting the attacker's newly added balance with a share of the full harvested reward.
5. Attacker immediately calls `unvote(P)` (`wombat/WombatBribeManager.sol:222-237`), which triggers `getReward`/claim via `withdrawFor(..., true)`, realizing the attacker's disproportionate reward share and returning their voting power for reuse, at the expense of the pool's genuine long-term voters.

    function _provisionReward(uint256 _amountReward, address _rewardToken) internal {
        IERC20(_rewardToken).safeTransferFrom(
            msg.sender,
            address(this),
            _amountReward
        );
        Reward storage rewardInfo = rewards[_rewardToken];
        rewardInfo.historicalRewards =
            rewardInfo.historicalRewards +
            _amountReward;

        if (totalStaked() == 0) {
            rewardInfo.queuedRewards += _amountReward;
        } else {
            if (rewardInfo.queuedRewards > 0) {
                _amountReward += rewardInfo.queuedRewards;
                rewardInfo.queuedRewards = 0;
            }
            rewardInfo.rewardPerTokenStored =
                rewardInfo.rewardPerTokenStored +
                (_amountReward * 10**stakingTokenDecimals) /
