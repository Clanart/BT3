### Title
Missing bounds check in canonical-CLVM-atom length-prefix parsing causes unhandled `IndexError` on attacker-controlled mempool spend bundles - ([File: chia/full_node/mempool_manager.py])

### Summary
`is_atom_canonical()` and its caller `is_clvm_canonical()` in `chia/full_node/mempool_manager.py` parse the CLVM atom length-prefix encoding of a spend bundle's puzzle reveal / solution bytes by indexing directly into the raw `bytes` object (`clvm_buffer[offset]`) while advancing `offset` according to attacker-supplied length-prefix bytes, without ever checking `offset` against `len(clvm_buffer)`. [1](#0-0) 

### Finding Description
`is_atom_canonical(clvm_buffer, offset)` reads `b = clvm_buffer[offset]`, determines `prefix_len` (0–5 extra bytes) from the top bits of `b`, then loops `prefix_len` times doing `offset += 1; atom_len |= clvm_buffer[offset]` with no check that `offset` is still within the buffer. [1](#0-0) 

`is_clvm_canonical(clvm_buffer)` drives this loop over a full CLVM-serialized buffer, again indexing `clvm_buffer[offset]` without a bounds guard, relying solely on well-formed input to terminate the `while True` loop. [2](#0-1) 

This is directly analogous to the CVE-2019-7578 bug class: a length-prefixed/tag-driven parser (`InitIMA_ADPCM` in SDL's WAV parser) that advances a read cursor based on attacker-controlled length fields without validating the cursor stays within the buffer, producing an out-of-bounds read. Here, a spend bundle whose puzzle reveal or solution bytes end exactly on (or before) a multi-byte atom length-prefix marker (e.g., last byte is `0xFC`–`0xFF` with insufficient trailing bytes) will cause `offset` to walk past `len(clvm_buffer) - 1`, and the next `clvm_buffer[offset]` access is an out-of-bounds index. In Python, unlike C, a `bytes` object indexed out of range raises `IndexError` rather than silently returning adjacent heap memory, so this is not a memory-disclosure primitive; the practical consequence is an unhandled exception during spend-bundle processing rather than the classic C-style over-read.

### Impact Explanation
If this function is invoked during spend-bundle admission/eligibility checks (e.g., DEDUP/fast-forward eligibility determination) without the caller wrapping it in a broad exception handler, a single unprivileged spend-bundle submitter could trigger an unhandled `IndexError` while the full node attempts to classify or validate the bundle for mempool inclusion. This maps to the "spend-triggered transaction-processing halt" impact category: a crafted, syntactically truncated CLVM buffer inside an otherwise-parseable `CoinSpend` could interrupt normal mempool-manager processing for that request.

### Recommendation
Add an explicit bounds check in `is_atom_canonical` before each `clvm_buffer[offset]` access (e.g., `if offset >= len(clvm_buffer): return ..., False` / raise a well-defined `ValueError`), and add the same guard at the top of the `is_clvm_canonical` loop before `b = clvm_buffer[offset]`. Additionally, confirm and, if necessary, harden the call site(s) so that any parsing exception from these functions is caught and translated into a normal "non-canonical"/invalid-spend-bundle rejection rather than propagating as an unhandled exception.

### Proof of Concept
Construct a `clvm_buffer` (e.g., as a spend's puzzle reveal or solution byte string) that ends immediately after a multi-byte atom length-prefix marker, such as a buffer whose final byte is `0xFC` (indicating a 5-byte length prefix: `mask = 0b00000001`, `prefix_len = 5`) with fewer than 5 trailing bytes actually present. Calling `is_clvm_canonical(clvm_buffer)` on this buffer causes `is_atom_canonical` to increment `offset` past the end of the buffer and execute `clvm_buffer[offset]`, raising `IndexError: index out of range` instead of returning a controlled `False`/error result. def is_atom_canonical(clvm_buffer: bytes, offset: int) -> tuple[int, bool]:
    b = clvm_buffer[offset]
    if (b & 0b11000000) == 0b10000000:
        # 6 bits length prefix
        mask = 0b00111111
        prefix_len = 0
        min_value = 1
    elif (b & 0b11100000) == 0b11000000:
        # 5 + 8 bits length prefix
        mask = 0b00011111
        prefix_len = 1
        min_value = 1 << 6
    elif (b & 0b11110000) == 0b11100000:
        # 4 + 8 + 8 bits length prefix
        mask = 0b00001111
        prefix_len = 2
        min_value = 1 << (5 + 8)
    elif (b & 0b11111000) == 0b11110000:
        # 3 + 8 + 8 + 8 bits length prefix
        mask = 0b00000111
        prefix_len = 3
        min_value = 1 << (4 + 8 + 8)
    elif (b & 0b11111100) == 0b11111000:
        # 2 + 8 + 8 + 8 + 8 bits length prefix
        mask = 0b00000011
        prefix_len = 4
        min_value = 1 << (3 + 8 + 8 + 8)
    elif (b & 0b11111110) == 0b11111100:
        # 1 + 8 + 8 + 8 + 8 + 8 bits length prefix
        mask = 0b00000001
        prefix_len = 5
        min_value = 1 << (2 + 8 + 8 + 8 + 8)

    atom_len = b & mask
    for i in range(prefix_len):
        atom_len <<= 8
        offset += 1
        atom_len |= clvm_buffer[offset]

    return 1 + prefix_len + atom_len, atom_len >= min_value

def is_clvm_canonical(clvm_buffer: bytes) -> bool:
    """
    checks whether the CLVM serialization is all canonical representation.
    atoms can be serialized in more than one way by using more bytes than
    necessary to encode the length prefix. This functions ensures that all atoms are
    encoded with the shortest representation. back-references are not allowed
    and will make this function return false
    """
    assert clvm_buffer != b""

    offset = 0
    tokens_left = 1
    while True:
        b = clvm_buffer[offset]

        # pair
        if b == 0xFF:
            tokens_left += 1
            offset += 1
            continue

        # back references cannot be considered canonical, since they may be
        # encoded in many different ways
        if b == 0xFE:
            return False

        # small atom or NIL
        if b <= 0x80:
            tokens_left -= 1
            offset += 1
        else:
            atom_len, canonical = is_atom_canonical(clvm_buffer, offset)
            if not canonical:
                return False
            tokens_left -= 1
            offset += atom_len

        if tokens_left == 0:
            break

    # if there's garbage at the end, it's not canonical
    return offset == len(clvm_buffer)
