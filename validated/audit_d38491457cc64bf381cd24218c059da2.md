### Title
mWOM minting does not account for non-standard/fee-on-transfer WOM transfers, allowing over-minted mWOM unbacked by actual WOM received - (File: wombat/mWOM.sol)

### Summary
`mWOM._convert` mints mWOM tokens to the caller equal to the user-supplied `_amount` parameter instead of the amount of WOM actually received by the contract via `safeTransferFrom`. Unlike other deposit paths in this codebase (e.g. `WombatStaking.deposit`, `WombatPoolHelper._deposit`) which measure balance-before/balance-after to determine the actual amount received, `mWOM._convert` trusts the caller-supplied amount directly for both accounting (`totalConverted`) and minting.

### Finding Description
`convert`, `convertAndStake`, `deposit`, and `incentiveDeposit` on `mWOM` all route through the internal `_convert` function: [1](#0-0) 

The function transfers `_amount` of WOM from `msg.sender` either to `wombatStaking` or to `address(this)`, but never verifies the amount actually received: [2](#0-1) 

It then unconditionally mints `_amount` of mWOM (1:1) and increments `totalConverted` by `_amount`, regardless of what was actually transferred in. This contrasts with the pattern used elsewhere in the same codebase — e.g. `WombatStaking.deposit` explicitly computes `lpReceived` from a before/after balance diff before minting the receipt token: [3](#0-2) 

and `WombatPoolHelper._deposit` similarly diffs balances before staking: [4](#0-3) 

mWOM's `_convert` lacks this balance-diff safeguard, so if the underlying WOM token (or any future token configured via `setWombatStaking`) ever deducts a transfer fee, rebases, or otherwise delivers less than `_amount` to the recipient, the contract will still mint the full `_amount` of mWOM and record the full `_amount` in `totalConverted`, even though less WOM backing was actually received/locked.

### Impact Explanation
mWOM is meant to represent a 1:1 claim, and its supply/`totalConverted` figure underpins the WOM/mWOM peg relied upon by `SmartWomConvert` (which computes ratios and swap amounts against `womMWomPool`) and by veWOM locking accounting via `_lockWom`/`totalAccumulated`. Any discrepancy between the amount minted and the amount of WOM actually custodied/locked directly inflates mWOM supply beyond its backing, which is a protocol-insolvency-class issue: mWOM would no longer be fully redeemable/backed 1:1, degrading the peg and value for all mWOM holders permanently, not just an individual depositor.

### Likelihood Explanation
The exploitability is entirely dependent on the token behavior configured as `wom` in the contract (via `__mWom_init`/no setter for `wom` shown, but `wombatStaking` is admin-settable). Under ordinary WOM token behavior (standard ERC20, no fee) this issue does not trigger. It is a latent accounting defect: the code fails to verify actual proceeds anywhere in the mint path, unlike the rest of the codebase's deposit functions which consistently apply the balance-diff pattern for this exact reason.

### Recommendation
In `mWOM._convert`, measure the actual WOM (or contract balance) received via a before/after balance check on the transfer target, and use that measured amount — not the caller-supplied `_amount` — for minting mWOM and updating `totalConverted`, consistent with the balance-diff pattern already used in `WombatStaking.deposit` and `WombatPoolHelper._deposit`.

### Proof of Concept
1. Assume WOM (or a future asset wired into `wombatStaking`) is configured with a transfer fee, or `wombatStaking`/receiving address enforces a deduction on receipt.
2. User calls `mWOM.deposit(100)`; `_convert(100, false, false)` executes `IERC20(wom).safeTransferFrom(msg.sender, address(this), 100)`, but the contract only receives `95` due to fee.
3. `_mint(msg.sender, 100)` still mints 100 mWOM, and `totalConverted += 100`, even though only 95 WOM is held by the contract.
4. Repeated over time, mWOM's minted supply diverges from actual locked/held WOM backing, breaking the 1:1 assumption relied on by `SmartWomConvert.currentRatio()`/`maxSwapAmount()` and veWOM accounting in `_lockWom`. [1](#0-0)

    function _convert(uint256 _amount, bool _forStake, bool _doConvert) whenNotPaused nonReentrant internal {
        if (_doConvert) {
            if (wombatStaking == address(0))
                revert WombatStakingNotSet();
            IERC20(wom).safeTransferFrom(msg.sender, wombatStaking, _amount);
            _lockWom(_amount, false);

        } else {
            IERC20(wom).safeTransferFrom(msg.sender, address(this), _amount);
        }

        if(_forStake) {
            if (helper == address(0))
                revert HelperNotSet();
            _mint(address(this), _amount);
            IERC20(address(this)).safeApprove(helper, _amount);
            ISimpleHelper(helper).depositFor(_amount, address(msg.sender));
            IERC20(address(this)).safeApprove(helper, 0);
        } else {
            _mint(msg.sender, _amount);
        }

        totalConverted = totalConverted + _amount;
        emit mWomMinted(msg.sender, _amount);
    }
