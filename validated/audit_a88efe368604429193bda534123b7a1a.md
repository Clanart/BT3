### Title
Unauthenticated script-pubkey-only matching misclassifies external payments as internal outputs, silently stripping their embedded instructions - ([File: networks/bitcoin/src/wallet/mod.rs](networks/bitcoin/src/wallet/mod.rs))

### Summary
Analogous to the Open WebUI report — where an unsanitized, attacker-controlled `filename` field determined server-side handling while the `Content-Type` guard checked a different field — the Bitcoin `Scanner` classifies a received output solely by the attacker-controllable `script_pubkey` field, with no check that the output was created under the protocol's intended deposit flow. Because every registered script (external, branch, change, forward) is a publicly derivable P2TR key (`key + G·offset`), any unprivileged party can produce outputs matching internal `Change`/`Branch`/`Forwarded` scripts. The processor then labels them with the corresponding internal `OutputType` and deliberately does **not** attach the transaction's embedded instruction data, which is only applied to `OutputType::External`. The deposit is absorbed as protocol-owned change/branch funds: credited to no account and not refunded.

### Finding Description
`Scanner::scan_transaction` indexes `self.scripts` purely by `output.script_pubkey`, returning a `ReceivedOutput` carrying the registered scalar offset, for any transaction output paying to a registered script — regardless of who created it or why [1](#0-0) . The scripts map is built in `Scanner::new`/`register_offset` over `p2tr_script_buf(key + G·offset)` where the offsets used by the processor are deterministic public values: `Secp256k1::hash_to_F(KEY_DST, b"branch"|b"change"|b"forward")` with `KEY_DST = b"Serai Bitcoin Output Offset"` [2](#0-1) . Anyone can compute these taproot addresses from the public group key.

In `Bitcoin::get_outputs`, each matched output is mapped back to an `OutputType` via `kinds[offset_repr]`, then the embedded `InInstruction` data extracted by `extract_serai_data` is attached **only** when `output.kind == OutputType::External`; for all other kinds `data` stays `vec![]` [3](#0-2) . Like the report's `ext = file.filename.split(".")[-1]` consuming an unguarded field while the MIME check looked elsewhere, here the `script_pubkey` alone determines classification while the instruction payload — the field carrying depositor intent — is discarded based on that classification. The resulting `Output { kind: Change/Branch/Forwarded, data: [] }` enters the multisig scheduler as ordinary protocol-owned UTXOs, so the deposit is neither credited nor refunded via `PlanFromScanning::Refund` (refunds are only constructed around instruction-bearing external deposits).

### Impact Explanation
A payment sent to the publicly computable change/branch/forward script of an active multisig is reported as received by the scanner yet is invisible to the deposit/refund pipeline: its `data` is empty, so no `InInstruction` is ever evaluated and no refund address is honored. The funds become spendable only as generic multisig change, so the sender's balance is never credited and the protocol silently absorbs the coins — funds reported received that are not spendable for the depositor's purpose. This is reachable with purely public inputs: the attacker/victim broadcasts a standard Bitcoin transaction; no validator key, RPC control, or collusion is required.

### Likelihood Explanation
The internal scripts are deterministic functions of the group key, so integrators, UIs, or phished users can realistically construct deposits to them (e.g., an address-derivation bug or malicious address substitution in a deposit flow). It requires the sender to pay to a non-external derived script, which does not happen in the honest default flow, keeping this at Medium rather than High — consistent with the report's authenticated-but-low-privilege reachability.

### Recommendation
Bind classification to intent rather than script alone, mirroring the advisory's fix of canonicalizing the attacker-controlled field before using it:

- In `Bitcoin::get_outputs` (`processor/src/networks/bitcoin.rs`), only emit `OutputType::External` outputs when scanning blocks for deposits, and handle internal scripts (change/branch/forward created by the processor's own transactions) through a separate trusted path that does not rely on `scan_transaction` over arbitrary mempool/chain transactions.
- Alternatively, attach `extract_serai_data(tx)` regardless of `kind` and treat any output carrying a decodable `InInstruction` as an external deposit, so instruction-bearing payments to derived scripts are still credited or refunded rather than silently absorbed.
- Document that `Scanner`/`register_offset` scripts must never be offered as deposit addresses.

let change_script = p2tr_script_buf(key + ProjectivePoint::GENERATOR * offset).unwrap();

// Attacker/victim broadcasts a tx paying `change_script` and including an

let tx = Transaction { /* output: TxOut { value: 50_000, script_pubkey: change_script },
                          plus OP_RETURN output with instruction data */ };

// Scanner::scan_transaction returns a ReceivedOutput (script match succeeds).
// Bitcoin::get_outputs maps it to OutputType::Change and, per the
// `if output.kind == OutputType::External` guard, leaves `data` empty.
// Result: the 50k sats enter the scheduler as protocol change; the

  pub fn scan_transaction(&self, tx: &Transaction) -> Vec<ReceivedOutput> {
    let mut res = Vec::new();
    for (vout, output) in tx.output.iter().enumerate() {
      // If the vout index exceeds 2**32, stop scanning outputs
      let Ok(vout) = u32::try_from(vout) else { break };

      if let Some(offset) = self.scripts.get(&output.script_pubkey) {
        res.push(ReceivedOutput {
          offset: *offset,
          output: output.clone(),
          outpoint: OutPoint::new(tx.compute_txid(), vout),
        });
      }
    }

fn scanner(

) -> (Scanner, HashMap<OutputType, Scalar>, HashMap<Vec<u8>, OutputType>) {
  let mut scanner = Scanner::new(key).unwrap();
  let mut offsets = HashMap::from([(OutputType::External, Scalar::ZERO)]);

  let zero = Scalar::ZERO.to_repr();
  let zero_ref: &[u8] = zero.as_ref();
  let mut kinds = HashMap::from([(zero_ref.to_vec(), OutputType::External)]);

  let mut register = |kind, offset| {
    let offset = scanner.register_offset(offset).expect("offset collision");
    offsets.insert(kind, offset);

    let offset = offset.to_repr();
    let offset_ref: &[u8] = offset.as_ref();
    kinds.insert(offset_ref.to_vec(), kind);
  };
