### Title
Auction bid pool reads `auctionEntryPointVersion` outside its lock in `getBidTxGasLimit`, creating a TOCTOU window analogous to ebtables' unsynchronized table-field access - ([File: kaiax/auction/impl/bid_pool.go])

### Summary
The Linux ebtables bug fixed a race where the table struct (`table->ops`) could be read/replaced without holding the mutex the whole time, allowing a caller to observe a partially-updated table. `BidPool.getBidTxGasLimit` in Kaia's auction module exhibits the same class of bug: it locks `auctionInfoMu` only to read `bidTxGasBuffer`, releases the lock, and then reads `bp.auctionEntryPointVersion` unsynchronized, while `updateAuctionInfo` (called from `PostInsertBlock` on every new block) can concurrently overwrite `auctioneer`, `auctionEntryPoint`, `auctionEntryPointVersion`, and `bidTxGasBuffer` as a single atomic unit under `Lock()`.

### Finding Description
`BidPool.AddBid` executes three separate critical sections against fields that are meant to be updated together as one unit:
1. `validateBid` → `validateBidSigs` takes `auctionInfoMu.RLock()` and validates the bid's searcher/auctioneer signatures against the *current* `auctionEntryPoint`, `auctionEntryPointVersion`, and `auctioneer` [1](#0-0) .
2. `insertBid` takes the separate `bidMu` lock and inserts the bid into `bidMap`/`bidTargetMap`/`bidWinnerMap` [2](#0-1) .
3. `getBidTxGasLimit` takes `auctionInfoMu.RLock()` only long enough to copy `bidTxGasBuffer`, releases it, and then reads `bp.auctionEntryPointVersion` **without holding any lock** to build the auction calldata used for gas estimation [3](#0-2) .

Meanwhile, `updateAuctionInfo` replaces `auctioneer`, `auctionEntryPoint`, `auctionEntryPointVersion`, and `bidTxGasBuffer` together, and also clears the entire bid pool (`clearBidPool`) whenever any of these four values changes, all under a single `Lock()` [4](#0-3) . This function is invoked once per block from `PostInsertBlock`, i.e. on every new block, concurrently with any pending `AddBid` calls from RPC (`SubmitBid`) or from the p2p bid-message handler [5](#0-4) [6](#0-5) [7](#0-6) .

This is architecturally the same defect class as the ebtables report: multiple fields that must be treated as one consistent "table" (auctioneer/entryPoint/version/gasBuffer) are updated together under a single lock, but readers take the lock piecemeal (or, in this case, not at all for one of the fields), so a reader can observe a torn combination — e.g. `bidTxGasBuffer` from before an update alongside `auctionEntryPointVersion` from after an update (or vice versa), or a version read concurrently with a write (data race on the `string` field, since Go string reads/writes are not atomic without `sync/atomic`).

### Impact Explanation
The practical consequence is that `EncodeAuctionCallData(bid, bp.auctionEntryPointVersion)` at line 490 can be called with a version string that doesn't correspond to the entry-point contract/version pair that was actually validated (or is being validated concurrently), because `auctionEntryPointVersion` is read with no synchronization at all. This can produce:
- A miscalculated gas limit stored on the `Bid` via `bid.SetGasLimit(gasLimit)`, based on calldata encoded for the wrong auction-entrypoint ABI/version.
- Because `clearBidPool()` runs whenever the auctioneer/entry point rotates, a bid validated against the outgoing auctioneer's signature can still be inserted into `bidMap`/`bidTargetMap` moments after (or during) the swap, since `validateBidSigs`, `insertBid`, and `getBidTxGasLimit` are three independently-locked steps rather than one atomic transaction — echoing the exact "partially-filled/torn table" hazard the ebtables patch closed.
- Downstream, this bid (built with a stale/mismatched version encoding) is exposed via `GetTargetTxMap`/`ExtractTxBundles` for block building and settlement, potentially causing the on-chain `AuctionEntryPoint.resolve()` call to be executed with an under/over-estimated gas limit or malformed calldata relative to the currently active entry point — risking either bid execution failure (denial of settlement) or, in the worst case, execution against unintended contract semantics if the ABI differs across versions.

### Likelihood Explanation
This is a genuinely reachable, low-privilege path: `SubmitBid` is a public/permissionless RPC entry point [6](#0-5)  and `HandleBid` is reachable from the p2p bid gossip channel, both of which drive `AddBid`. `updateAuctionInfo` fires on every block via `PostInsertBlock`, so the race window opens once per block during normal operation, and any bidder submitting bids around block boundaries (which is the common, expected usage pattern for time-sensitive MEV/auction bids) can trigger it. However, this depends on genuinely-unsynchronized field access being exploitable rather than just a benign race (Go's race detector would flag it, but functional impact on-chain requires the version/ABI to actually differ between blocks, i.e. an actual entry-point upgrade/rotation event), so likelihood of *exploitable* value impact (vs. just gas-limit miscalculation) is Medium.

### Recommendation
Consolidate `auctioneer`, `auctionEntryPoint`, `auctionEntryPointVersion`, and `bidTxGasBuffer` into a single struct/snapshot that is read with one lock acquisition (mirroring the two-stage-removal fix's principle of "never expose a partially-filled struct"). Specifically:
- In `getBidTxGasLimit`, take `auctionInfoMu.RLock()` once and read `bidTxGasBuffer` and `auctionEntryPointVersion` together before calling `EncodeAuctionCallData`.
- Consider re-validating bid signatures against the auction-info snapshot captured at insertion time (or rejecting/rechecking bids whose validation snapshot no longer matches the current auction info) so that a bid signed against a since-rotated auctioneer cannot be persisted into the live bid pool after `updateAuctionInfo` swaps it out.

### Proof of Concept
1. Configure a chain where `AuctionEntryPoint`'s version/auctioneer is set to be rotated at a known block boundary (via the Registry/AuctionEntryPoint contracts) so that `PostInsertBlock` → `updateAuctionInfo` changes `auctionEntryPointVersion` (and hence `bp.auctionEntryPoint`) exactly at block N.
2. From an external client, call `auction_submitBid` (`SubmitBid`) with a bid signed for the pre-rotation entry point/version, timed so that `validateBidSigs` (line ~397) runs and passes just before block N's `PostInsertBlock` executes `updateAuctionInfo`/`clearBidPool`.
3. Interleave a second goroutine invoking `PostInsertBlock` for block N concurrently, so that `getBidTxGasLimit`'s unlocked read of `bp.auctionEntryPointVersion` (line 490) executes between the old and new writes performed by `updateAuctionInfo` (line 196-213).
4. Run under `go test -race` on a modified `TestUpdateAuctionInfo`/`AddBid` concurrency test (similar to the existing `TestBidPool_ConcurrentAddBid_OneWinnerPerSender`) driving `AddBid` and `updateAuctionInfo` in parallel goroutines; observe the Go race detector flag the concurrent unsynchronized read/write on `auctionEntryPointVersion`, and/or observe a bid inserted into `bidMap` whose signature was validated against a now-superseded auctioneer/entry-point pair.

func (bp *BidPool) updateAuctionInfo(auctioneer common.Address, auctionEntryPoint common.Address, auctionEntryPointVersion string, bidTxGasBuffer uint64) {
	bp.auctionInfoMu.Lock()
	defer bp.auctionInfoMu.Unlock()

	if bp.auctioneer == auctioneer && bp.auctionEntryPoint == auctionEntryPoint && bp.auctionEntryPointVersion == auctionEntryPointVersion && bp.bidTxGasBuffer == bidTxGasBuffer {
		return
	}

	// Clear the existing auction pool since the auctioneer or auction entry point address is changed.
	bp.clearBidPool()

	bp.auctioneer = auctioneer
	bp.auctionEntryPoint = auctionEntryPoint
	bp.auctionEntryPointVersion = auctionEntryPointVersion
	bp.bidTxGasBuffer = bidTxGasBuffer

	logger.Info("Update auction info", "auctioneer", auctioneer, "auctionEntryPoint", auctionEntryPoint, "auctionEntryPointVersion", auctionEntryPointVersion, "bidTxGasBuffer", bidTxGasBuffer)
}

func (bp *BidPool) insertBid(bid *auction.Bid) error {
	bp.bidMu.Lock()
	defer bp.bidMu.Unlock()

	var (
		blockNumber  = bid.BlockNumber
		targetTxHash = bid.TargetTxHash
		sender       = bid.Sender
	)

	// Re-check bidWinnerMap here — two concurrent bids can pass validateBid together.
	if _, ok := bp.bidMap[bid.Hash()]; ok {
		return auction.ErrBidAlreadyExists
	}
	if bp.senderHasDifferentWinner(bid) {
		return auction.ErrBidSenderExists
	}

	// If same block number, same target tx hash exists, replace it if it's better
	if existingBid, ok := bp.bidTargetMap[blockNumber][targetTxHash]; ok {
		// FCFS if the bid is the same.
		if existingBid.Bid.Cmp(bid.Bid) >= 0 {
			return auction.ErrLowBid
		}

		logger.Trace("Replace bid", "old", existingBid.Hash(), "new", bid.Hash())
		delete(bp.bidMap, existingBid.Hash())
		delete(bp.bidWinnerMap[blockNumber], existingBid.Sender)
	} else {
		if int64(len(bp.bidMap)) >= bp.maxBidPoolSize {
			logger.Info("Bid pool is full", "maxBidPoolSize", bp.maxBidPoolSize, "bid", bid.Hash())
			return auction.ErrBidPoolFull
		}
	}

	hash := bid.Hash()

	bp.initializeBidMap(blockNumber)

	bp.bidMap[hash] = bid
	bp.bidTargetMap[blockNumber][targetTxHash] = bid
	bp.bidWinnerMap[blockNumber][sender] = hash

	numBidsGauge.Update(int64(len(bp.bidMap)))

	logger.Trace("Add bid", "bid", hash)

	return nil
}

func (bp *BidPool) validateBidSigs(bid *auction.Bid) error {
	bp.auctionInfoMu.RLock()
	defer bp.auctionInfoMu.RUnlock()

	if bid.SearcherSig == nil || len(bid.SearcherSig) != crypto.SignatureLength {
		return auction.ErrInvalidSearcherSig
	}
	if bid.AuctioneerSig == nil || len(bid.AuctioneerSig) != crypto.SignatureLength {
		return auction.ErrInvalidAuctioneerSig
	}

	// Verify the EIP712 signature.
	if err := bid.ValidateSearcherSig(bp.ChainConfig.ChainID, bp.auctionEntryPoint, bp.auctionEntryPointVersion); err != nil {
		return err
	}

	// Verify the auctioneer signature.
	if err := bid.ValidateAuctioneerSig(bp.auctioneer); err != nil {
		return err
	}

	return nil
}

func (a *AuctionModule) PostInsertBlock(block *types.Block) error {
	if a.Downloader.Synchronising() || !a.ChainConfig.IsRandaoForkEnabled(block.Number()) {
		atomic.CompareAndSwapUint32(&a.bidPool.running, 1, 0)
		return nil
	}

	if !a.updateAuctionInfo(block.Number()) {
		logger.Debug("stop auction since auctioneer or auction entry point is not set")
		atomic.CompareAndSwapUint32(&a.bidPool.running, 1, 0)
		return nil
	}

	atomic.CompareAndSwapUint32(&a.bidPool.running, 0, 1)

	txHashMap := make(map[common.Hash]struct{})
	for _, tx := range block.Transactions() {
		txHashMap[tx.Hash()] = struct{}{}
	}
	a.bidPool.removeOldBids(block.Number().Uint64(), txHashMap)

	return nil
}

func (api *AuctionAPI) SubmitBid(ctx context.Context, bidInput BidInput) RPCOutput {
	numBidRequestCounter.Inc(1)
	if api.a.IsDisabled() {
		return makeRPCOutput(EMPTY_HASH, auction.ErrAuctionDisabled)
	}

	//  1. directly send target transaction
	targetTx, errTxDecode := toTx(bidInput.TargetTxRaw)
	if errTxDecode != nil {
		return makeRPCOutput(EMPTY_HASH, errTxDecode)
	}
	if targetTx.Hash() != bidInput.TargetTxHash {
		return makeRPCOutput(EMPTY_HASH, auction.ErrInvalidTargetTxHash)
	}
	errTargetTxSend := api.a.Backend.SendTx(ctx, targetTx)
	// ignore known transaction related errors against target tx validation
	if errTargetTxSend != nil && !(strings.HasPrefix(errTargetTxSend.Error(), "known transaction:") || errors.Is(errTargetTxSend, gasless_impl.ErrUnableToAddKnownBundleTx)) {
		return makeRPCOutput(EMPTY_HASH, errTargetTxSend)
	}

	// 2. add bid
	bid := ToBid(bidInput)
	bidHash, errValidateBid := api.a.bidPool.AddBid(bid)
	return makeRPCOutput(bidHash, errValidateBid)
}
