### Title
Fixed `GaslessLenderMinBal` threshold checked only once at Init lets the gasless CN lender advance LendTx it cannot actually cover - (File: kaiax/gasless/impl/init.go, kaiax/gasless/impl/constant.go, kaiax/gasless/impl/getter.go)

### Summary
The gasless module gates whether a consensus node (CN) will act as a "lender" of native KAIA for gasless swaps by comparing its balance to a single hardcoded constant, `GaslessLenderMinBal = big.NewInt(1e18)` (1 KAIA), checked exactly once at `Init()`. The actual amount the CN commits to lend per bundle (`lendAmount`) is computed from the arbitrary, sender-controlled gas parameters of the approve/swap transactions and is never re-validated against the CN's real, currently-available balance before the `LendTx` is generated and included in a block.

### Finding Description
`GaslessLenderMinBal` is a fixed, non-configurable constant: [1](#0-0) 

It is used only once, during module initialization, to decide whether to disable the gasless module for a CN based on a snapshot balance check: [2](#0-1) 

However, the actual amount the CN (as `msg.sender`/lender) sends via the generated `LendTx` is computed per-bundle as the sum of the approve and swap transactions' fees, which are attacker/user-controlled via `GasFeeCap`/`GasTipCap`/`GasLimit` of the submitted approve/swap transactions: [3](#0-2) 

This `lendAmount` directly becomes the `Value` of the generated native-KAIA transfer transaction from the CN to the swap sender: [4](#0-3) 

Nowhere in `checkBalanceForApprove` / `checkBalanceForSwap` (the per-tx admission checks run when transactions enter the pool) or in `ExtractTxBundles` (which is invoked at block-assembly time to build the `[LendTx, ApproveTx, SwapTx]` bundle) is the CN's *current* balance compared against the *actual* `lendAmount` required for that specific bundle: [5](#0-4) [6](#0-5) 

Because the one-time `GaslessLenderMinBal` (1 KAIA) is a fixed value unrelated to the real, per-transaction lend requirement (which scales with gas price × gas limit of user-submitted transactions, and can be driven arbitrarily higher by a submitter setting large `GasFeeCap`/`GasLimit` on their approve/swap transactions, or simply by many bundles accumulating before the CN's balance is re-checked), the module can keep constructing and including `LendTx`s whose value exceeds what the CN can actually afford at execution time. This mirrors the reported bug class: a single hardcoded amount, sized for one "typical" scenario, is silently wrong/insufficient for other legitimate parameter ranges reachable by an ordinary transaction sender, and the check is performed once rather than validated against the actual value needed at the point of use.

### Impact Explanation
If the CN's balance is not re-checked against the real `lendAmount` at bundle-construction/block-assembly time, a proposer could attempt to include a `LendTx` that it cannot fund (balance dropped below required lend amount due to previous lends in the same block, other outgoing transactions, or a swap/approve tx with unusually high gas parameters). This can lead to state divergence between honest nodes (if some nodes reject the resulting block/transaction execution differently) or to acceptance of a transaction/bundle that should not have been includable, since the go/no-go decision was made against a static, unrelated threshold (1 KAIA) rather than the real obligation. This satisfies the "unauthorized value movement" / "state divergence between honest nodes" criteria for a valid analog.

### Likelihood Explanation
Any unprivileged transaction sender can submit an approve+swap gasless transaction pair with elevated `GasFeeCap`/`GasLimit` (still passing the existing `checkBalanceForSwap`/`checkBalanceForApprove` validations, which don't bound gas price/limit), inflating `lendAmount` far beyond the fixed 1 KAIA sizing basis used at `Init()`. Because the CN's balance is only sampled once at startup and never re-validated per-bundle against the real amount to be lent, this condition is reachable purely through normal transaction submission by an unprivileged sender, without needing a malicious peer/validator/node.

### Recommendation
Replace the one-time fixed `GaslessLenderMinBal` check with a per-bundle (or at minimum, per-block) validation that compares the CN's current, live balance against the actual `lendAmount(approveTxOrNil, swapTx)` computed for that specific bundle before including the generated `LendTx`. If the CN cannot cover the specific bundle's lend amount, that bundle should be dropped/excluded rather than relying on a static minimum-balance heuristic set at initialization.

### Proof of Concept
1. Start a CN with balance just above `GaslessLenderMinBal` (1 KAIA), which passes the `Init()` check in [2](#0-1) .
2. Submit an approve+swap gasless transaction pair as an ordinary user with `GasFeeCap`/`GasLimit` set high enough that `lendAmount` (approveTx.Fee() + swapTx.Fee(), per [3](#0-2) ) exceeds the CN's actual remaining balance at block-assembly time (e.g., after several such bundles have already been lent out in the same or prior blocks).
3. `ExtractTxBundles` ( [6](#0-5) ) still constructs and returns the bundle with the oversized `LendTx`, since it performs no live-balance-vs-lendAmount check; the module's earlier "no lending" decision was already fixed at `Init()` time and never revisited per bundle.

func lendAmount(approveTxOrNil, swapTx *types.Transaction) *big.Int {
	r := new(big.Int)

	// R2 = ApproveTx.Fee() if exists
	if approveTxOrNil != nil {
		r.Add(r, approveTxOrNil.Fee())
	}

	// R3 = SwapTx.Fee()
	r.Add(r, swapTx.Fee())

	// LendAmount = R2 + R3
	return r
}

func (g *GaslessModule) GetCheckBalance() func(tx *types.Transaction) error {
	return func(tx *types.Transaction) error {
		if approveArgs, ok := decodeApproveTx(tx, g.signer); ok {
			return g.checkBalanceForApprove(approveArgs)
		}
		if swapArgs, ok := decodeSwapTx(tx, g.signer); ok {
			return g.checkBalanceForSwap(swapArgs, tx.Nonce())
		}
		return errors.New("not a gasless transaction") // should not happen because IsModuleTx is called before GetCheckBalance
	}
}

func (g *GaslessModule) checkBalanceForApprove(approveArgs *ApproveArgs) error {
	token := approveArgs.Token
	bc := backends.NewBlockchainContractBackend(g.Chain, nil, nil)

	if g.GaslessConfig.ShouldCheckSenderCode() {
		if g.getCurrentHasCode(approveArgs.Sender) {
			return errors.New("sender with code is not allowed")
		}
	}

	if g.GaslessConfig.ShouldCheckToken() {
		tokenContract, err := sc_erc20.NewERC20(token, bc)
		if err != nil {
			return err
		}

		// tx.token.balanceOf(sender) > 0
		tokenBalance, err := tokenContract.BalanceOf(nil, approveArgs.Sender)
		if err != nil {
			return err
		}
		if tokenBalance.Sign() <= 0 {
			return fmt.Errorf("insufficient sender token balance: token=%s, have=%s, want=nonzero", token.Hex(), tokenBalance.String())
		}
	}
	return nil
}

func (g *GaslessModule) ExtractTxBundles(txs []*types.Transaction, prevBundles []*builder.Bundle) []*builder.Bundle {
	// there are only at most two gasless transactions in pending for a sender
	bundles := []*builder.Bundle{}
	approveTxs := map[common.Address]*types.Transaction{}
	targetTxHash := common.Hash{}
	for _, tx := range txs {
		addr, err := types.Sender(g.signer, tx)
		if err != nil {
			continue
		}
		if g.IsApproveTx(tx) {
			approveTxs[addr] = tx
		} else if g.IsSwapTx(tx) && g.IsExecutable(approveTxs[addr], tx) {
			bundleTxs := builder.NewTxOrGenList(g.GetLendTxGenerator(approveTxs[addr], tx))
			if approveTxs[addr] != nil {
				bundleTxs = append(bundleTxs, builder.NewTxOrGenFromTx(approveTxs[addr]))
			}
			bundleTxs = append(bundleTxs, builder.NewTxOrGenFromTx(tx))

			b := builder.NewBundle(
				bundleTxs,
				targetTxHash,
				false,
			)

			targetTxHash = tx.Hash()

			isConflict := false
			for _, prev := range append(prevBundles, bundles...) {
				if prev.IsConflict(b) {
					isConflict = true
					break
				}
			}
			if isConflict {
				// Gasless transactions will just fail even if they aren't bundled.
				continue
			}
			bundles = append(bundles, b)
		} else {
			targetTxHash = tx.Hash()
		}
	}
	return bundles
}
