### Title
Gasless module trusts the registered `GaslessSwapRouter` address without verifying it conforms to the expected KIP-247 interface before lending KAIA against it - ([File: kaiax/gasless/impl/getter.go])

### Summary
The `Manager.sol` report flags that a contract address is used for a security-critical role (`metadataRenderer`) without any check that it actually implements the expected interface, so a malformed/incompatible deployment silently breaks the protocol. The same pattern exists in Kaia's gasless module: the `GaslessSwapRouter` address is read every block from the `SystemRegistry`/Multicall contract and is trusted implicitly for validating and executing gasless swaps — there is no interface/bytecode verification that the registered address actually behaves like a KIP-247 `GaslessSwapRouter` before the node starts issuing `LendTx`s against it.

### Finding Description
`updateAddresses` fetches the current `swapRouter` and `allowedTokens` from the registry-resolved Multicall contract every block and stores them with no validation beyond the address being non-zero: [1](#0-0) 

This `swapRouter` value is subsequently used both to authorize transactions (`isApproveTx`/`isSwapTx` only check `spender == swapRouter` / `Router == swapRouter`) and to make live calls into the contract assuming it implements the router ABI (`GetAmountIn`): [2](#0-1) [3](#0-2) 

Once a `SwapTx` targeting this address passes the pool's structural checks, the proposer unconditionally generates and signs a `LendTx` that transfers real KAIA value to the sender from the block-proposer's own key, *before* the swap actually executes: [4](#0-3) 

Nowhere in this flow (registry lookup → `updateAddresses` → `isSwapTx`/`isApproveTx` → `checkBalanceForSwap` → `GetLendTxGenerator`) is there any check (ERC-165/KIP-13 style, or otherwise) that the address registered as `GaslessSwapRouter` is actually a contract implementing the expected KIP-247 `swapForGas`/`getAmountIn` semantics that guarantee the sender repays the lent amount. The module’s security model (proposer lends KAIA, expects repayment from the swap) implicitly assumes the registered router is well-formed, exactly the assumption the external report warns against for `metadataRenderer`.

### Impact Explanation
If governance (via `Registry.register`, a call reachable by any account that currently holds governance/owner rights over the registry, or more importantly if a mistaken/incompatible address is registered as `GaslessSwapRouter`) points `GaslessSwapRouter` to a contract that does not correctly implement the KIP-247 interface — e.g., a contract whose `swapForGas` accepts the call but does not perform the token pull/swap/repay, or whose `getAmountIn` returns manipulable/incorrect values — the pool logic (`checkBalanceForSwap`, `isSwapTx`) will still treat the transaction as a valid gasless swap because it only pattern-matches on function selector and address equality, never on actual interface conformance. The proposer's `LendTx` unconditionally transfers KAIA out of the proposer/lending account irrespective of whether the swap genuinely repays it, since value transfer and repayment are two independent transactions tied together only by best-effort bundling logic, not an atomic on-chain guarantee enforced against the router's real behavior. This can result in loss of proposer-lent KAIA (a fee-delegation/gasless settlement abuse) whenever the registered router is misconfigured or non-conformant, mirroring the "protocol ceases to function correctly / breaks core invariant" impact in the original report.

### Likelihood Explanation
The registry `register` call for `GaslessSwapRouterName` is a governance-controlled but still permissioned transaction reachable through the normal transaction/registry mechanism; the module has no independent defense-in-depth check on the value it reads. Any accidental misconfiguration (wrong address, upgraded contract with changed semantics, or a router deployed with a bug) is sufficient to trigger the described impact — no malicious node/validator collusion is required, only an incorrect on-chain registration, which the report's rules classify as a legitimate governance-parameter-reachable path.

### Recommendation
Before trusting a newly observed `GaslessSwapRouter` address in `updateAddresses`, verify that the contract exposes the expected KIP-247 interface (e.g., via a KIP-13/ERC-165 `supportsInterface` check similar to `kip13.NewInterfaceIdentifierCaller` already used elsewhere in the codebase for contract validation), or otherwise sanity-check that `getAmountIn`/`swapForGas` behave as expected (e.g., a bounded gas static call returning plausible values) prior to enabling lending against it. If validation fails, the module should fall back to treating `swapRouter` as unset (same as the existing "something wrong with multicall contract" fallback path) rather than optimistically trusting the address.

### Proof of Concept
1. Governance (or a misconfigured/compromised registry admin) calls `Registry.register(GaslessSwapRouterName, maliciousOrBrokenRouter, targetBlock)` pointing to a contract that accepts `swapForGas(...)` calls (matching the 4-byte selector) but does not perform any real token swap/repayment (e.g., a no-op or reentrant contract).
2. At `targetBlock`, `getGaslessInfo` (`kaiax/gasless/impl/getter.go:369-389`) reads this address as the new `swapRouter` with no interface check, and `updateAddresses` stores it.
3. A user submits `ApproveTx`(token → spender=maliciousRouter, max) followed by `SwapTx`(to=maliciousRouter, swapForGas(...)) with `amountRepay` computed to satisfy `checkBalanceForSwap`'s `getAmountIn` call, which the malicious router can freely misreport since it is never checked for genuine behavior.
4. The gasless builder (`kaiax/gasless/impl/builder.go:28-72`) bundles `[LendTx, ApproveTx, SwapTx]`; `GetLendTxGenerator` (`kaiax/gasless/impl/getter.go:273-313`) creates and signs a `LendTx` transferring `lendAmount` KAIA from the proposer's node key to the sender.
5. Because the router contract does not enforce genuine repayment logic, the swap executes "successfully" from the pool's perspective while the proposer's KAIA lent in `LendTx` is not genuinely recovered, resulting in fund loss to the block proposer/lending party.

func (g *GaslessModule) GetLendTxGenerator(approveTxOrNil, swapTx *types.Transaction) *builder.TxOrGen {
	var src []byte
	if approveTxOrNil != nil {
		src = append(src, approveTxOrNil.Hash().Bytes()...)
	}
	src = append(src, swapTx.Hash().Bytes()...)
	bundleHash := crypto.Keccak256Hash(src)

	gen := func(nonce uint64) (*types.Transaction, error) {
		var (
			chainId = g.InitOpts.ChainConfig.ChainID
			signer  = types.LatestSignerForChainID(chainId)
			key     = g.InitOpts.NodeKey
		)

		to, err := types.Sender(signer, swapTx)
		if err != nil {
			return nil, err
		}

		tx, err := types.NewTransactionWithMap(types.TxTypeEthereumDynamicFee, map[types.TxValueKeyType]interface{}{
			types.TxValueKeyNonce:      nonce,
			types.TxValueKeyTo:         &to,
			types.TxValueKeyAmount:     lendAmount(approveTxOrNil, swapTx),
			types.TxValueKeyData:       common.Hex2Bytes("0x"),
			types.TxValueKeyGasLimit:   params.TxGas,
			types.TxValueKeyGasFeeCap:  swapTx.GasFeeCap(),
			types.TxValueKeyGasTipCap:  swapTx.GasTipCap(),
			types.TxValueKeyAccessList: types.AccessList{},
			types.TxValueKeyChainID:    chainId,
		})
		if err != nil {
			return nil, err
		}

		err = tx.Sign(signer, key)
		return tx, err
	}

	return builder.NewTxOrGenFromGen(gen, bundleHash)
}

func (g *GaslessModule) updateAddresses(header *types.Header) error {
	g.gaslessInfoMu.Lock()
	defer g.gaslessInfoMu.Unlock()

	swapRouter, tokens, err := getGaslessInfo(g.Chain, header)
	// proceed even if there is something wrong with multicall contract
	if err != nil {
		g.swapRouter = common.Address{}
		g.allowedTokens = map[common.Address]bool{}
		logger.Warn("there is something wrong with multicall contract", "err", err.Error())
		return nil
	}

	g.swapRouter = swapRouter

	g.allowedTokens = map[common.Address]bool{}
	for _, addr := range tokens {
		// all tokens are allowed if nil
		if g.GaslessConfig.AllowedTokens == nil {
			g.allowedTokens[addr] = true
		}
		for _, allowed := range g.GaslessConfig.AllowedTokens {
			if addr == allowed {
				g.allowedTokens[addr] = true
			}
		}
	}

	return nil
}
