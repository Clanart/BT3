### Title
Payout attribution (OP_RETURN operator pubkey) is not bound to the funder of a payout transaction, allowing an unprivileged party to credit an arbitrary uninvolved operator with a reimbursement it never funded - ([File: core/src/builder/transaction/operator_reimburse.rs])

### Summary
The binding claimed by the protocol is: `payout_payer_operator_xonly_pk` (as recorded by `Verifier::update_finalized_payouts`) == the xonly pubkey of the entity that actually supplied the real BTC value satisfying the withdrawal's output0. In reality, `update_finalized_payouts` derives this attribution purely from an unauthenticated OP_RETURN byte string parsed out of whichever transaction happens to spend the committed withdrawal UTXO, with no cryptographic or economic proof that the named key contributed anything to that transaction.

### Finding Description
`create_payout_txhandler` builds the payout transaction with a single witness-committed input (the tiny, dust-value withdrawal UTXO signed by the withdrawer with `SinglePlusAnyoneCanPay`) and an OP_RETURN output carrying a raw, **unsigned** operator xonly pubkey: [1](#0-0) 

Because the sighash flag is `SIGHASH_SINGLE | ANYONECANPAY`, the signature only commits to input[0] and output[0]: [2](#0-1) 

The withdrawal UTXO itself is dust (`WITHDRAWAL_EMPTY_UTXO_SATS = 550` sats), far less than the actual withdrawal amount paid at output[0], confirming that the real value flowing to output[0] must come from additional inputs that anyone completing the tx supplies (in the operator's own `withdraw()` flow, via bitcoind's `fund_raw_transaction` with `add_inputs: true`): [3](#0-2) [4](#0-3) 

Nothing ties those additional funding inputs, or the OP_RETURN pubkey, to any signature. The verifier's block scanner blindly trusts the OP_RETURN content of whatever transaction spends the withdrawal outpoint: [5](#0-4) [6](#0-5) 

This is then used directly to select which operator's `PayoutCheckerTask` will treat the withdrawal as its own and drive it through `handle_finalized_payout`, kickoff, and eventual reimbursement: [7](#0-6) 

The only later consistency check compares the payout's OP_RETURN key against the *kickoff*'s own declared operator key (`is_kickoff_malicious`), which is a self-consistency check, not an ownership/funding proof: [8](#0-7) 

Because `ANYONECANPAY` explicitly permits third parties to add inputs/outputs, any unprivileged party who obtains the withdrawer's `SinglePlusAnyoneCanPay` signature over input0/output0 (e.g. from a prior failed withdraw attempt, an operator's mempool broadcast, or the aggregator relay) can build their own new transaction: reuse input0+output0 as-is, add their own funding input(s) to make the transaction balance, and append an OP_RETURN naming any operator's xonly pubkey — including one belonging to an operator who never participated. The bridge circuit itself repeats the same trust-without-proof pattern, deriving `operator_xonlypk` straight from the OP_RETURN bytes with no signature check: [9](#0-8) 

No existing guard (`SECP.verify_schnorr` only authenticates input0/output0, not the OP_RETURN; `is_kickoff_malicious` only checks self-consistency between payout and kickoff; database uniqueness constraints only prevent double-crediting the same withdrawal) closes this gap.

### Impact Explanation
An operator `P` can be credited with `payout_payer_operator_xonly_pk = P` and can complete the full reimbursement flow (kickoff → challenge timeout → reimburse) for a withdrawal it never fronted, receiving the deposit's vault-held `bridge_amount` funds. This directly matches the Critical impact category "an operator reimbursed for a payout it never funded." It is repeatable for any withdrawal whose SinglePlusAnyoneCanPay signature becomes observable (mempool, failed RPC attempts, or aggregator relays), and for any operator `P` chosen by the attacker, since the OP_RETURN commitment is entirely outside the signed sighash. The blast radius spans all withdrawals and all operators using the standard (non-optimistic) payout path.

### Likelihood Explanation
The precondition is simply that the `SinglePlusAnyoneCanPay` signature for a withdrawal becomes visible to an outside party — a realistic occurrence given operators broadcast payout transactions to the public mempool, and given retry paths (`withdraw` RPC calls that fail on one operator but succeed on another, per test helper `create_withdrawal_transaction_and_check_tx_outs`) already circulate the same signature to multiple operators. The attacker must fund enough additional Bitcoin to satisfy output[0] (since dust input0 is far below the withdrawal amount), so the attack has a real BTC cost proportional to the withdrawal amount, but no privileged access, key material, or gRPC calls to any operator are required — the attacker only needs to construct and broadcast a valid Bitcoin transaction directly to the network.

### Recommendation
Bind the OP_RETURN operator attribution cryptographically to the payout transaction's actual funder: e.g., require the "fronting" operator's own key to sign a commitment covering the OP_RETURN output (and ideally all outputs/inputs beyond input0/output0), or require the additional funding inputs' script_pubkeys to correspond to the address controlled by the OP_RETURN xonly pubkey, and have `update_finalized_payouts`/the bridge circuit verify this before attributing/crediting a payout to an operator.

pub fn create_payout_txhandler(
    input_utxo: UTXO,
    output_txout: TxOut,
    operator_xonly_pk: XOnlyPublicKey,
    user_sig: taproot::Signature,
    _network: bitcoin::Network,
) -> Result<TxHandler<Signed>, BridgeError> {
    let txin = SpendableTxIn::new_partial(input_utxo.outpoint, input_utxo.txout);

    let output_txout = UnspentTxOut::from_partial(output_txout.clone());

    let op_return_txout = op_return_txout(PushBytesBuf::from(operator_xonly_pk.serialize()));

    let mut txhandler = TxHandlerBuilder::new(TransactionType::Payout)
        .with_version(NON_STANDARD_V3)
        .add_input(
            NormalSignatureKind::NotStored,
            txin,
            SpendPath::KeySpend,
            DEFAULT_SEQUENCE,
        )
        .add_output(output_txout)
        .add_output(UnspentTxOut::from_partial(anchor_output(
            NON_EPHEMERAL_ANCHOR_AMOUNT,
        )))
        .add_output(UnspentTxOut::from_partial(op_return_txout))
        .finalize();
    txhandler.set_p2tr_key_spend_witness(&user_sig, 0)?;
    txhandler.promote()
}

    /// Sets the given payout txs' txid and operator index for the given index.
    pub async fn update_payout_txs_and_payer_operator_xonly_pk(
        &self,
        tx: Option<DatabaseTransaction<'_>>,
        payout_txs_and_payer_operator_xonly_pk: Vec<(
            u32,
            Txid,
            Option<XOnlyPublicKey>,
            bitcoin::BlockHash,
        )>,
    ) -> Result<(), BridgeError> {
        if payout_txs_and_payer_operator_xonly_pk.is_empty() {
            return Ok(());
        }
        // Convert all values first, propagating any errors
        let converted_values: Result<Vec<_>, BridgeError> = payout_txs_and_payer_operator_xonly_pk
            .iter()
            .map(|(idx, txid, operator_xonly_pk, block_hash)| {
                Ok((
                    i32::try_from(*idx).wrap_err("Failed to convert payout index to i32")?,
                    TxidDB(*txid),
                    operator_xonly_pk.map(XOnlyPublicKeyDB),
                    BlockHashDB(*block_hash),
                ))
            })
            .collect();
        let converted_values = converted_values?;

        let mut query_builder = QueryBuilder::new(
            "UPDATE withdrawals AS w SET
                payout_txid = c.payout_txid,
                payout_payer_operator_xonly_pk = c.payout_payer_operator_xonly_pk,
                payout_tx_blockhash = c.payout_tx_blockhash
                FROM (",
        );

        query_builder.push_values(
            converted_values.into_iter(),
            |mut b, (idx, txid, operator_xonly_pk, block_hash)| {
                b.push_bind(idx)
                    .push_bind(txid)
                    .push_bind(operator_xonly_pk)
                    .push_bind(block_hash);
            },
        );

        query_builder
            .push(") AS c(idx, payout_txid, payout_payer_operator_xonly_pk, payout_tx_blockhash) WHERE w.idx = c.idx");

        let query = query_builder.build();
        execute_query_with_tx!(self.connection, tx, query, execute)?;

        Ok(())
    }

        let mut dbtx = self.db.begin_transaction().await?;

            citrea_idx,
            move_to_vault_txid

            .db
            .get_deposit_data_with_move_tx(Some(&mut dbtx), move_to_vault_txid)

            .operator
            .handle_finalized_payout(
                &mut dbtx,
                deposit_data.get_deposit_outpoint(),
