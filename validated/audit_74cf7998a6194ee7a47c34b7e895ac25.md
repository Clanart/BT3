### Title
Uncontrolled Resource Consumption via unbounded Python recursion in offer puzzle-driver matching - ([File: chia/wallet/outer_puzzles.py])

### Summary
`match_puzzle()` and the associated outer-puzzle drivers (`CATOuterPuzzle`, `SingletonOuterPuzzle`, `OwnershipOuterPuzzle`, `MetadataOuterPuzzle`, `CROuterPuzzle`) recursively call themselves through the `also` chain for every curried layer found in an attacker-supplied `puzzle_reveal`. This recursion is pure Python call-stack recursion with no depth limit, directly analogous to the Elasticsearch "deeply nested ingest pipeline" bug (CVE-2024-23450): a crafted deeply-nested input drives unbounded recursive processing and crashes the process, before any CLVM cost accounting can bound the work.

### Finding Description
`match_puzzle()` in [1](#0-0)  iterates registered drivers and calls `driver.match(puzzle)`. Every driver's `match()` implementation recursively calls `self._match(...)` (which is `match_puzzle` again) on the puzzle's inner layer when constructing the `also` field, e.g. in `CATOuterPuzzle.match()`: [2](#0-1) 
and identically in `OwnershipOuterPuzzle.match()`, `SingletonOuterPuzzle.match()`, `MetadataOuterPuzzle.match()`, and `CROuterPuzzle.match()`: [3](#0-2) [4](#0-3) [5](#0-4) 

`get_inner_puzzle()` and `get_inner_solution()` for each of these drivers similarly recurse through the `also` chain with no depth bound, e.g.: [6](#0-5) 

This machinery is reached directly from untrusted, counterparty-supplied offer data. `Offer.from_spend_bundle()` calls `match_puzzle(UnknownPuzzle(known_program=coin_spend.puzzle_reveal))` on every coin spend contained in a received offer file: [7](#0-6) 
and `Offer._get_offered_coins()` likewise calls `match_puzzle`, `get_inner_puzzle`, and `get_inner_solution` on `parent_spend.puzzle_reveal` taken straight from the offer's coin spends when the wallet inspects/accepts an offer: [8](#0-7) 

A malicious offer counterparty can craft a `puzzle_reveal` that curries the CAT/ownership/singleton/metadata/CR outer-puzzle mod (or any combination of them) thousands of layers deep. Each layer costs only a handful of CLVM atoms to encode (cheap in bytes) but forces one additional Python stack frame per call in `match_puzzle` → driver `.match()` → `self._match()` → ... . Since there is no explicit recursion-depth cap in this code path (unlike `sha256_treehash`, which is deliberately implemented iteratively specifically "so we don't have to worry about blowing out the python stack" — [9](#0-8) ), Python's recursion limit is exhausted, raising an uncaught `RecursionError`.

### Impact Explanation
Any wallet user or Data Layer client processing an untrusted offer file (via CLI/RPC offer inspection or acceptance flow) can be crashed with a single crafted offer, because `Offer.from_spend_bundle` / `_get_offered_coins` are invoked before any CLVM-cost-bounded execution takes place. This matches the reachable, resource-consumption impact class validated by the report ("a spend-triggered transaction-processing halt"): an attacker-controlled artifact (here an offer file/spend bundle) causes uncontrolled recursive resource consumption that crashes wallet transaction processing, denying service to the wallet node/process handling offers.

### Likelihood Explanation
High feasibility: constructing an arbitrarily deep chain of curried outer-puzzle mods (CAT-in-CAT, singleton-in-singleton, ownership/metadata/CR nesting) is cheap and entirely under the control of the party creating the offer file; no signature or on-chain validity is required to trigger the crash, since the crash occurs during Python-side puzzle matching before signature/CLVM verification.

### Recommendation
Bound recursion depth explicitly in `match_puzzle`/driver `match()`, `get_inner_puzzle()`, and `get_inner_solution()` (e.g., pass and decrement a max-depth counter, or convert the "also" chain traversal to an iterative loop similar to `sha256_treehash`). Reject/short-circuit puzzle reveals whose outer-puzzle nesting exceeds a sane limit (e.g., a few dozen layers) before invoking any of these drivers, and ensure the resulting `RecursionError`/failure is caught and surfaced as a normal offer-parsing error rather than crashing the process.

### Proof of Concept
Conceptually:
1. Take any innermost puzzle (e.g., `ACS = Program.to(1)`).
2. Repeatedly wrap it with `construct_cat_puzzle(CAT_MOD, tail, inner)` (as done in the existing test `test_cat_outer_puzzle`, which nests it once: [10](#0-9) ) tens of thousands of times to build a deeply nested `puzzle_reveal`.
3. Build a `CoinSpend`/`WalletSpendBundle`/`Offer` using this puzzle as the parent-coin `puzzle_reveal`, mimicking `Offer.from_spend_bundle`.
4. Feed the resulting offer file to a victim wallet's offer-parsing/accept flow (`Offer.from_spend_bundle` / `Offer._get_offered_coins`), which calls `match_puzzle` recursively through the "also" chain and exhausts the Python call stack, crashing the process with an unhandled `RecursionError`.

        self, constructor: PuzzleInfo, puzzle_reveal: UnknownPuzzle, solution: Program | None = None
    ) -> Program | None:

            )

    @classmethod
    def from_spend_bundle(cls, bundle: WalletSpendBundle) -> Offer:
        # Because of the `to_spend_bundle` method, we need to parse the dummy CoinSpends as `requested_payments`
        requested_payments: dict[bytes32 | None, list[NotarizedPayment]] = {}
        driver_dict: dict[bytes32, PuzzleInfo] = {}
        leftover_coin_spends: list[CoinSpend] = []
        for coin_spend in bundle.coin_spends:
            driver = match_puzzle(UnknownPuzzle(known_program=coin_spend.puzzle_reveal))
            if driver is not None:
                asset_id = create_asset_id(driver)
                assert asset_id is not None
                driver_dict[asset_id] = driver
            else:
                asset_id = None
            if coin_spend.coin.parent_coin_info == bytes32.zeros:
                notarized_payments: list[NotarizedPayment] = []
                for payment_group in Program.from_serialized(coin_spend.solution).as_iter():
                    nonce = bytes32(payment_group.first().as_atom())
                    payment_args_list = payment_group.rest().as_iter()
                    notarized_payments.extend(
                        [NotarizedPayment.from_condition_and_nonce(condition, nonce) for condition in payment_args_list]
                    )

                requested_payments[asset_id] = notarized_payments
            else:
                leftover_coin_spends.append(coin_spend)
