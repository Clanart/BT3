### Title
`CallDispatcher.dispatch` has no access control, letting anyone drain residual token/ETH balances left by other users' predispatch/postdispatch swaps - (File: evm/src/utils/CallDispatcher.sol)

### Summary
The external report's core broken invariant is: *a shared, privileged execution surface (infinite-allowance vault / arbitrary-call executor) is reachable without any binding to the specific operation that was supposed to authorize it, letting an unrelated party pull value that was only meant to be moved atomically as part of someone else's transaction.* The local analog is `CallDispatcher`, the singleton contract that `IntentGatewayV2` uses to execute all `predispatch`/`postdispatch`/`output.call` order calldata. `CallDispatcher.dispatch()` has no caller restriction at all, and the gateway's sweep logic after dispatching only sweeps tokens that are explicitly listed in `order.inputs` / `order.output.assets`, not "whatever the dispatcher ended up holding." Any ERC20 balance or dust that lands in `CallDispatcher` outside that enumerated list (e.g., a swap-path byproduct, reward token, or fee-on-transfer/refund residue during a predispatch or postdispatch swap) is fully attacker-drainable by anyone calling `CallDispatcher.dispatch()` directly with a crafted `Call[]`.

### Finding Description
`CallDispatcher.dispatch` is a bare, unauthenticated entrypoint: [1](#0-0) 

There is no `onlyGateway`/`onlyOwner` modifier — any address can call `dispatch(bytes)` with an arbitrary ABI-encoded `Call[]` and have `CallDispatcher` execute `to.call{value: call.value}(call.data)` for each entry, using whatever balance the contract currently holds.

`IntentGatewayV2`/`IntentsBase` treat `CallDispatcher` as a single shared, persistent contract (`_params.dispatcher`), not a fresh per-order instance. During `placeOrder`'s predispatch flow, and during fill's `_execute` postdispatch flow, tokens are transferred into the dispatcher, arbitrary order-supplied calldata is run, and then only the tokens named in the order are swept back: [2](#0-1) 

The sweep loop iterates `outputsLen` (`order.output.assets`) — and the equivalent predispatch sweep iterates `order.inputs` — so only tokens present in those order-declared lists get pulled back into the gateway. Any other asset the dispatcher acquires as a side effect of the untrusted call it just executed (multi-hop swap remainder in an intermediate token, LP/reward token from `predispatch` unwrap flows, fee-on-transfer surplus in a token that isn't `order.inputs[i].token`, etc.) is left sitting in `CallDispatcher`'s balance indefinitely, because the contract is reused across all orders.

Because `dispatch()` is callable by anyone, an attacker does not need to be a peer, relayer, guardian, or admin — they only need to observe (or brute-force) that `CallDispatcher` is holding a stray balance and then call `dispatch()` themselves with a `Call` that transfers that token/ETH out to their own address. This is structurally the same "shared privileged surface + incomplete cleanup + no caller binding" pattern flagged in the external report's `Provisioner` (infinite allowance to a vault that itself allows arbitrary calls), just instantiated as "shared executor contract with no caller check and non-exhaustive sweep."

### Impact Explanation
This is a direct, unprivileged fund-loss path: value belonging to the protocol/users (residual tokens from someone else's order execution) sitting in a contract that is reachable by any EOA with zero authentication is drainable to an attacker-chosen beneficiary. It matches the bounty's "stealing or loss of funds" / "unauthorized transaction or execution" / "wrong beneficiary or amount" categories, since the extraction requires only a public call to `CallDispatcher.dispatch()` — no malicious peer, relayer, prover, or admin needed.

### Likelihood Explanation
Likelihood depends on how often `CallDispatcher` actually accrues an un-swept asset outside the order's declared token list. Multi-hop swaps, non-1:1 refunds, or third-party reward-token distributions during predispatch/postdispatch calldata execution are realistic given that the SDK/docs explicitly document Uniswap swap patterns being executed through `CallDispatcher` (e.g. `evm/tests/foundry/IntentGatewayV2Test.sol` `testPostdispatchTokenSweep`, and the HFT calldata-execution docs). Whenever that happens, the drain window is open until anyone notices and calls `dispatch()` — the access-control gap itself is unconditional and always present, only the presence of a stray balance is scenario-dependent, which is why this is flagged as a real but likelihood-bounded finding rather than a guaranteed drain on every order.

### Recommendation
- Restrict `CallDispatcher.dispatch()` to only be callable by the registered `IntentGatewayV2` (or a small allow-list of trusted gateway contracts), e.g. an `onlyGateway` modifier set at construction/initialization.
- Alternatively/additionally, make the sweep in `_execute` (and the predispatch equivalent) sweep the dispatcher's *entire* balance of any token touched by the just-executed calls (or maintain a token allow-list independent from the order's declared assets) rather than only the tokens explicitly enumerated in `order.inputs`/`order.output.assets`, so no residual value can accumulate in the shared contract between transactions.
- Consider deploying a fresh, single-use dispatcher (e.g. via `CREATE2`/clone) per order execution instead of reusing one singleton contract across all orders, eliminating the cross-order balance-carryover risk entirely.

### Proof of Concept
1. A user or solver places/fills an order whose `predispatch`/`postdispatch` calldata routes through a multi-hop swap or a protocol that pays out an incidental reward/refund token not listed in `order.inputs`/`order.output.assets` (a realistic scenario given the documented Uniswap-swap `Call[]` patterns).
2. `IntentsBase._execute` (or the predispatch equivalent in `IntentGatewayV2.placeOrder`) dispatches the calls via `ICallDispatcher(dispatcher).dispatch(...)`, then sweeps back only the tokens in the order's declared list, leaving the incidental token/ETH balance inside `CallDispatcher`.
3. Any attacker, at any later time, calls `CallDispatcher.dispatch(abi.encode(calls))` directly (no gateway involvement, no signature, no permission check required — see [3](#0-2) ), with `calls = [{to: strayToken, value: 0, data: abi.encodeWithSelector(IERC20.transfer.selector, attacker, strayToken.balanceOf(dispatcher))}]`.
4. The stray balance is transferred to the attacker, permanently and irrecoverably, with no trace back to any privileged actor.

    function dispatch(bytes memory encoded) external {
        Call[] memory calls = abi.decode(encoded, (Call[]));
        uint256 callsLen = calls.length;
        for (uint256 i = 0; i < callsLen; ++i) {
            Call memory call = calls[i];
            uint32 size;
            address to = call.to;
            assembly {
                size := extcodesize(to)
            }

            if (size == 0) {
                revert NotContract(to);
            }

            (bool success, bytes memory result) = to.call{value: call.value}(call.data);
            if (!success) revert CallFailed(to, result);
        }
    }

    function _execute(Order calldata order, uint256 outputsLen) internal {
        if (order.output.call.length == 0) return;

        address dispatcher = _params.dispatcher;
        ICallDispatcher(dispatcher).dispatch(order.output.call);

        Call[] memory sweepCalls = new Call[](outputsLen);
        uint256 sweepCount = 0;

        for (uint256 i; i < outputsLen;) {
            address token = address(uint160(uint256(order.output.assets[i].token)));

            if (token == address(0)) {
                uint256 balance = dispatcher.balance;
                if (balance > 0) {
                    sweepCalls[sweepCount] = Call({to: address(this), value: balance, data: ""});
                    sweepCount++;
                    emit DustCollected(token, balance);
                }
            } else {
                uint256 balance = IERC20(token).balanceOf(dispatcher);
                if (balance > 0) {
                    sweepCalls[sweepCount] = Call({
                        to: token,
                        value: 0,
                        data: abi.encodeWithSelector(IERC20.transfer.selector, address(this), balance)
                    });
                    sweepCount++;
                    emit DustCollected(token, balance);
                }
            }

            unchecked {
                ++i;
            }
        }

        if (sweepCount > 0) {
            Call[] memory finalCalls = new Call[](sweepCount);
            for (uint256 i; i < sweepCount;) {
                finalCalls[i] = sweepCalls[i];
                unchecked {
                    ++i;
                }
            }
            ICallDispatcher(dispatcher).dispatch(abi.encode(finalCalls));
        }
    }
