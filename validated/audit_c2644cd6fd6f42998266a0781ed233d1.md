### Title
Unbacked MGP minted via manipulated router swap output in bull-mode reward locking - ([File: wombat/ArbWomUp2.sol])

### Summary
`_bullMGP` uses the raw output of `ROUTER.swapExactTokensForTokens` (`amounts[1]`) to compute the MGP amount locked into `vlMGP`, applying a bonus multiplier on top of that raw output. Because the caller-supplied `_minMGPRec` only enforces a floor (not a fair-price ceiling), and there is no TWAP/oracle sanity check, an attacker can sandwich the BUSD→MGP pool in the same transaction/block to temporarily depress the MGP price, inflate `amounts[1]`, and cause more MGP than economically justified by the `busdReward` to be locked to their own account from the contract's reserves.

### Finding Description
`incentiveDeposit(_amount, _minMGPRec, _bullMode=true)` computes a legitimate `busdReward` from the WOM-deposit tier system [1](#0-0) , then calls `_bullMGP(rewardToSend, _minMGPRec, msg.sender)`.

Inside `_bullMGP`, the BUSD reward is swapped for MGP via a single pancake-style pair, and the swap's actual output `amounts[1]` is used directly, unscaled by any reference price, to compute the amount locked into `vlMGP`: [2](#0-1) 

Key issues:
- `_minMGPRec` is chosen by the caller (the attacker themselves, since `msg.sender` is both caller and beneficiary), so it can trivially be set to `0` or a low value — it only prevents the attacker from receiving *too little*, it does nothing to prevent the swap from returning an inflated amount.
- `amounts[1]` is the router's live spot-price output for a single BUSD/MGP pool, with no TWAP, no external oracle check, and no cap relative to pool depth or a reference busdReward/MGP fair-value ratio.
- `mgpAmountToLcok = amounts[1] * (DENOMINATOR + bullBonusRatio) / DENOMINATOR` is funded by the contract's own MGP balance (the swap only returns `amounts[1]` MGP, but the contract approves/locks `amounts[1]` plus a bonus percentage from its own pre-funded reserve) — so any manipulation-induced inflation of `amounts[1]` also inflates the bonus paid out of protocol reserves.
- `nonReentrant`/`whenNotPaused` do not defend against price manipulation — they only prevent reentrancy and don't validate the swap output against a fair reference price.

An attacker can, in one atomic transaction (or via flash loan / same-block ordering), first sell MGP into the BUSD/MGP pool to depress the MGP price, then call `incentiveDeposit(..., _bullMode=true)` with `_minMGPRec=0`, causing the router to return an inflated `amounts[1]` for the fixed BUSD input, and finally buy back MGP to restore the pool, paying only AMM fees for the round trip. The net result is more MGP locked to the attacker's `vlMGP` position than the `busdReward` should have purchased at fair market price, funded from the contract's own MGP reserve.

### Impact Explanation
This is a theft of protocol-held (unbacked) MGP: the bonus/locked amount is computed off a manipulable spot price rather than a value anchored to the actual `busdReward` earned, allowing an attacker to extract more MGP from the contract's reserves than the reward tier system intends. This matches "theft of unclaimed yield / unbacked MGP locked via manipulated swap output," a direct economic loss to protocol reserves backing the bonus program.

### Likelihood Explanation
Feasibility depends on the depth of the actual BUSD/MGP liquidity pool used by `ROUTER` and on `bullBonusRatio`. Since this is a legacy Arbitrum-airdrop-era single-pair pancake-style router integration (no TWAP/oracle), and the attacker fully controls `_minMGPRec` (their own transaction parameter) with no other slippage guard, the only cost to the attacker is AMM swap fees on the manipulation round-trip. If the pool is thin relative to `busdReward` size and `bullBonusRatio` is non-trivial, the attack is profitable and fully repeatable per `incentiveDeposit` call, requiring only capital for the temporary price push (flash-loanable) and no privileged role.

### Recommendation
- Do not use raw AMM swap output (`amounts[1]`) directly to compute the locked/bonus amount. Instead, compute the bonus based on the `busdReward` input value converted at a manipulation-resistant reference price (e.g., TWAP oracle, or a fixed/admin-set conversion rate), and use the router only to execute the actual swap, with `amounts[1]` bounded to be within an acceptable range of that reference price.
- Enforce a maximum acceptable output (or maximum deviation from expected price) in addition to the minimum, so an inflated swap output cannot be exploited.
- Consider requiring the swap output to be verified against a TWAP or multiple-block-averaged price before applying `bullBonusRatio`, or cap `_busdAmount` swaps to a small fraction of pool reserves per transaction.

### Proof of Concept
Foundry fork test plan:
1. Fork BSC/Arbitrum mainnet at a block where the BUSD/MGP pancake-style pool used by `ROUTER` exists with realistic (but not overly deep) liquidity.
2. Deploy/attach `ArbWomUp2`, configure `busd`, `mgp`, `vlMGP`, `bullBonusRatio`, `ROUTER` via `setup`.
3. Fund the contract with BUSD (reward pool) and MGP (bonus reserve), and set `rewardMultiplier`/`rewardTier` so an attacker account has an eligible `busdReward` for a given WOM deposit.
4. Baseline run: call `incentiveDeposit(_amount, _minMGPRec, true)` under unmanipulated pool state; record `mgpAmountToLcok_baseline` from the `VLMGPRewarded` event.
5. Attack run (fresh fork state): 
   a. Attacker contract flash-loans/holds MGP, sells a large MGP amount into the BUSD/MGP pool to depress MGP price.
   b. In the same transaction, call `incentiveDeposit(_amount, 0, true)`.
   c. Immediately buy back MGP to restore the pool price (repay flash loan if used).
6. Assert `mgpAmountToLcok_attack` (from `VLMGPRewarded`/`vlMGP` position of attacker) is materially greater than `mgpAmountToLcok_baseline` for the identical `busdReward` input, and that the attacker's net MGP gain (locked amount minus round-trip AMM fees/slippage cost) is positive — demonstrating extraction of unbacked MGP from the contract's reserve.

    function incentiveDeposit(
        uint256 _amount, uint256 _minMGPRec, bool _bullMode
    ) external _checkAmount(_amount) whenNotPaused nonReentrant {
        if (_amount == 0) return;

        uint256 rewardToSend = this.getRewardAmount(_amount, msg.sender);
        _deposit(_amount);
        claimedReward[msg.sender] += rewardToSend;
        
        if (_bullMode) {
            _bullMGP(rewardToSend, _minMGPRec, msg.sender);
        } else {
            IERC20(busd).transfer(msg.sender, rewardToSend);
            emit BUSDRewarded(msg.sender, rewardToSend);
        }
    }

    function _bullMGP(uint256 _busdAmount, uint256 _minRec, address _account) internal {
        IERC20(busd).safeApprove(address(ROUTER), _busdAmount);
        
        address[] memory path = new address[](2);
        path[0] = busd;
        path[1] = mgp;
        uint256[] memory amounts = ROUTER.swapExactTokensForTokens(
            _busdAmount,
            _minRec,
            path,
            address(this),
            block.timestamp
        );

        uint256 mgpAmountToLcok = amounts[1] * (DENOMINATOR + bullBonusRatio) / DENOMINATOR; // get bull mode bonus
        IERC20(mgp).approve(address(vlMGP), mgpAmountToLcok);
        vlMGP.lockFor(mgpAmountToLcok, _account);

        emit VLMGPRewarded(_account, _busdAmount, mgpAmountToLcok);
    }
