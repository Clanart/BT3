### Title
Unbounded byte-index read in CLVM canonical-serialization check can raise an unhandled `IndexError` on a crafted spend bundle - ([File: chia/full_node/mempool_manager.py])

### Summary
`is_atom_canonical()` and `is_clvm_canonical()` in `chia/full_node/mempool_manager.py` decode CLVM atom length-prefixes by repeatedly indexing into a caller-supplied `bytes` buffer without ever checking that the computed offset stays within the buffer's length, mirroring the out-of-bounds array access class described in CVE-2021-1094 (unchecked index into an attacker-influenced buffer leading to a crash/DoS).

### Finding Description
`is_atom_canonical(clvm_buffer, offset)` inspects the leading byte at `clvm_buffer[offset]` to determine how many additional length-prefix bytes follow (`prefix_len`, up to 5), then loops: [1](#0-0) 

Each iteration does `offset += 1; atom_len |= clvm_buffer[offset]` without any check that `offset < len(clvm_buffer)`. The only length validation anywhere in this code path is the caller-side `assert clvm_buffer != b""` inside `is_clvm_canonical()`, which only rejects a fully empty buffer, not a buffer that is merely too short for the length prefix it advertises: [2](#0-1) 

A buffer whose first byte's high bits indicate a large length prefix (e.g. matching the `0b11111100`/`0b11111110` mask branch, which claims 5 additional prefix bytes) but which does not actually contain that many trailing bytes will cause `clvm_buffer[offset]` to index past the end of `bytes`, raising a Python `IndexError`. This is the direct analog of the NVIDIA driver's OOB array access: a short/malformed length-prefixed buffer drives the index past the allocated bounds.

### Impact Explanation
`is_clvm_canonical()`/`is_atom_canonical()` are part of the mempool's CLVM-serialization canonicality checking, documented alongside `pre_validate_spendbundle()` as core mempool-manager logic that processes attacker-supplied spend-bundle bytes (`chia/full_node/mempool_manager.py`). If this code path is exercised on attacker-controlled bytes without an enclosing `try/except IndexError`, a single malformed/truncated spend bundle can raise an uncaught exception during mempool admission, which is a spend-triggered denial-of-service on the transaction-processing path — analogous to the "denial of service" impact called out in the NVIDIA advisory.

### Likelihood Explanation
I was not able to fully confirm, within the available context, the exact call site that invokes `is_clvm_canonical()`/`is_atom_canonical()` on submitter-controlled bytes during `pre_validate_spendbundle()`, nor whether an outer `except Exception`/`except ValueError` wrapper already converts a raised `IndexError` into a handled `ValidationError` before it can crash a worker. The function signatures and lack of bounds checks are concrete and verifiable, but reachability/exception-handling at the call site is not fully verified with the tools available in this pass.

### Recommendation
Add explicit bounds checks in `is_atom_canonical()` before each `clvm_buffer[offset]` access (e.g., `if offset >= len(clvm_buffer): return ..., False` or raise a well-defined parsing error), and in `is_clvm_canonical()`'s main loop, so that a truncated/malformed buffer with an over-claiming length prefix is rejected deterministically instead of raising an uncaught `IndexError`. Ensure any caller of these functions on network/mempool-submitted data wraps them in exception handling that converts parsing failures into a `ValidationError`/`Err` rather than letting a raw `IndexError` propagate.

### Proof of Concept
```python
from chia.full_node.mempool_manager import is_clvm_canonical

# A single byte whose top bits (0b11111100) claim a 5-byte length prefix,
# but the buffer contains no trailing bytes at all.
malformed = bytes([0b11111101])
is_clvm_canonical(malformed)  # raises IndexError: index out of range

```python
def is_clvm_canonical(clvm_buffer: bytes) -> bool:
    """
    checks whether the CLVM serialization is all canonical representation.
    atoms can be serialized in more than one way by using more bytes than
    necessary to encode the length prefix. This functions ensures that all atoms are
    encoded with the shortest representation. back-references are not allowed
    and will make this function return false
    """
    assert clvm_buffer != b""

    offset = 0
    tokens_left = 1
    while True:
        b = clvm_buffer[offset]

        # pair
        if b == 0xFF:
            tokens_left += 1
            offset += 1
            continue

        # back references cannot be considered canonical, since they may be
        # encoded in many different ways
        if b == 0xFE:
            return False

        # small atom or NIL
        if b <= 0x80:
            tokens_left -= 1
            offset += 1
        else:
            atom_len, canonical = is_atom_canonical(clvm_buffer, offset)
            if not canonical:
                return False
            tokens_left -= 1
            offset += atom_len
