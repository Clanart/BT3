### Title
Payout OP_RETURN is unsigned and can be stripped by anyone who observes the mempool tx, permanently blocking reimbursement of the honest operator who fronted the withdrawal - ([File: core/src/builder/transaction/operator_reimburse.rs])

### Summary
`create_payout_txhandler` signs the payout transaction's input and output 0 with the user's `SinglePlusAnyoneCanPay` signature, but the OP_RETURN output at index 2 (which carries the operator's x-only pubkey used to bind the payout to the reimbursing operator) is never covered by any signature. Any unprivileged party who observes the broadcast, unconfirmed payout transaction can construct and get mined a variant transaction that reuses the same signed input/output pair but omits the OP_RETURN, permanently breaking the on-chain attribution `payout_payer_operator_xonly_pk == kickoff_data.operator_xonly_pk` for the honest operator that fronted the withdrawal.

### Finding Description
The binding claimed by the protocol is:
`stored_operator_xonly_pk (withdrawals.payout_payer_operator_xonly_pk, derived from the confirmed payout tx's OP_RETURN) == kickoff_data.operator_xonly_pk (the operator who actually fronted the withdrawal and later kicks off for reimbursement)`.

In `create_payout_txhandler` [1](#0-0) , the transaction has 3 outputs: user payout (index 0), anchor (index 1), and OP_RETURN with `operator_xonly_pk` (index 2). Only input 0 is signed, using the sighash type `SinglePlusAnyoneCanPay` [2](#0-1) , which by BIP-341/BIP-118 semantics commits **only** to input 0 and output 0 — outputs 1 and 2 are entirely unsigned. This is consistent with `parse_withdrawal_sig_params`, which explicitly enforces `SinglePlusAnyoneCanPay` on the user's signature and documents that the signature is "only valid for this pubkey"/"amount" (i.e., output 0) [3](#0-2) .

Because the honest operator's payout tx is broadcast to the (public) Bitcoin mempool before confirmation, any observer can extract the witness for input 0 (a Taproot key-path signature with no covering commitment to outputs 1/2) and build a new transaction that:
- spends the same withdrawal outpoint (input 0, same signature/witness) — this double-spends the honest operator's transaction,
- keeps output 0 (the user payout, still verifying against the same signature),
- omits or replaces the OP_RETURN output.

If this variant is confirmed instead of the honest operator's original broadcast, `Verifier::update_finalized_payouts` computes `get_first_op_return_output(&circuit_payout_tx)` → `None`, so `operator_xonly_pk` is stored as `NULL` in `withdrawals.payout_payer_operator_xonly_pk` [4](#0-3) . Later, `Verifier::is_kickoff_malicious` reads this back and, seeing `operator_xonly_pk_opt == None`, unconditionally treats the kickoff as malicious: `"No operator xonly pk found in payout tx OP_RETURN, assuming malicious"` → `Ok(true)` [5](#0-4) . This triggers a Challenge against the honest operator's kickoff [6](#0-5) .

Critically, once challenged, `Operator::send_asserts` cannot proceed: it fetches `payout_op_xonly_pk_opt` from the DB and returns a hard error if it is `None` — `"Payout operator xonly pk not found in payout info DB while sending asserts..."` [7](#0-6) . Without asserts, the operator cannot reach `DisproveTimeout`/`Reimburse`; instead verifiers will eventually be able to send `AssertTimeout`, burning the operator's kickoff collateral, and the `Reimburse` transaction (which requires the disprove timeout path) becomes unreachable [8](#0-7) .

No existing guard prevents this: `SECP.verify_schnorr` in `Operator::withdraw` only checks the signature against the exact sighash the operator itself computed for the honest tx at broadcast time [2](#0-1)  — it says nothing about what gets mined. `is_kickoff_malicious`, `is_deposit_valid`, and the bridge circuit (`bridge_circuit` in circuits-lib) all assume the OP_RETURN is present and treat its absence as attributable to "an optimistic payout or the operator constructed the payout tx wrong" [9](#0-8)  — they do not distinguish "operator's fault" from "third party stripped the unsigned output after broadcast."

### Impact Explanation
The honest operator who correctly fronted a user's withdrawal (10 BTC-scale bridge deposit) becomes permanently unable to be reimbursed: `is_kickoff_malicious` returns `true` for their legitimate kickoff, `send_asserts` errors out before any disprove-resistant BitVM chain can be built, and the operator's kickoff/round collateral is exposed to `AssertTimeout`/challenge slashing while the `Reimburse` transaction path is blocked. This matches the Critical category "an honest operator permanently unable to be reimbursed" / "an honest operator's collateral burned." The attack is repeatable against any deposit/withdrawal and against any operator, since the flaw is structural (unsigned OP_RETURN) rather than tied to one instance.

### Likelihood Explanation
Preconditions: an existing deposit with `move_txid`, a registered withdrawal in Citrea, and the honest operator's payout tx sitting unconfirmed in the mempool (a normal, brief window in every payout). The attacker needs no privileged role — only the ability to observe the public mempool/network, construct a standard Bitcoin transaction re-using the publicly visible witness for input 0, fund it with their own UTXOs for fees, and get it broadcast/mined before the original (e.g., via RBF since `Operator::withdraw` funds via `fund_raw_transaction` with `replaceable: None`, which typically defaults to wallet/node RBF policy, or via a same/higher-feerate race). Attacker cost is minimal (network relay fee only, no bridge deposit required for this specific transaction). This is realistically exploitable during normal operation because the payout transaction is necessarily broadcast and visible before confirmation.

### Recommendation
Bind the operator's x-only pubkey (and/or the deposit's move-to-vault txid) into the *signed* part of the payout transaction, e.g., by having the operator co-sign the payout tx (script-path or an additional signature covering all outputs) or by using a sighash type that also commits to the OP_RETURN output, so that no unsigned output can be altered/stripped without invalidating the transaction. Alternatively, require the OP_RETURN output to be output 0 (or otherwise within the `SinglePlusAnyoneCanPay`-covered index) is not sufficient since `SIGHASH_SINGLE` only covers one output — a full redesign to include the operator identity as part of the committed message (e.g., appended to the sighash via an additional operator signature over the whole transaction) is required.

/// Creates a [`TxHandler`] for the `reimburse_tx`.
///
/// This transaction is sent by the operator if no challenge was sent, or a challenge was sent but no disprove was sent, to reimburse the operator for their payout.
///
/// # Inputs
/// 1. MoveToVaultTx: Utxo containing the deposit
/// 2. KickoffTx: Reimburse connector utxo in the kickoff
/// 3. RoundTx: Reimburse connector utxo in the round (for the given kickoff index)
///
/// # Outputs
/// 1. Reimbursement output to the operator
/// 2. Anchor output for CPFP
///
/// # Arguments
/// * `move_txhandler` - The move-to-vault transaction handler for the deposit.
/// * `round_txhandler` - The round transaction handler for the round.
/// * `kickoff_txhandler` - The kickoff transaction handler for the kickoff.
/// * `kickoff_idx` - The kickoff index of the operator's kickoff.
/// * `paramset` - Protocol parameter set.
/// * `operator_reimbursement_address` - The address to reimburse the operator.
///
/// # Returns
/// A [`TxHandler`] for the reimburse transaction, or a [`BridgeError`] if construction fails.
pub fn create_reimburse_txhandler(
    move_txhandler: &TxHandler,
    round_txhandler: &TxHandler,
    kickoff_txhandler: &TxHandler,
    kickoff_idx: usize,
    paramset: &'static ProtocolParamset,
    operator_reimbursement_address: &bitcoin::Address,
) -> Result<TxHandler, BridgeError> {
    let builder = TxHandlerBuilder::new(TransactionType::Reimburse)
        .with_version(NON_STANDARD_V3)
        .add_input(
            NormalSignatureKind::Reimburse1,
            move_txhandler.get_spendable_output(UtxoVout::DepositInMove)?,
            builder::script::SpendPath::ScriptSpend(0),
            DEFAULT_SEQUENCE,
        )
        .add_input(
            NormalSignatureKind::Reimburse2,
            kickoff_txhandler.get_spendable_output(UtxoVout::ReimburseInKickoff)?,
            builder::script::SpendPath::ScriptSpend(0),
            DEFAULT_SEQUENCE,
        )
        .add_input(
            NormalSignatureKind::OperatorSighashDefault,
            round_txhandler.get_spendable_output(UtxoVout::ReimburseInRound(
                kickoff_idx,
                paramset.num_kickoffs_per_round,
            ))?,
            builder::script::SpendPath::KeySpend,
            DEFAULT_SEQUENCE,
        );

    Ok(builder
        .add_output(UnspentTxOut::from_partial(TxOut {
            value: move_txhandler
                .get_spendable_output(UtxoVout::DepositInMove)?
                .get_prevout()
                .value,
            script_pubkey: operator_reimbursement_address.script_pubkey(),
        }))
        .add_output(UnspentTxOut::from_partial(
            builder::transaction::anchor_output(paramset.anchor_amount()),
        ))
        .finalize())
}

pub fn create_payout_txhandler(
    input_utxo: UTXO,
    output_txout: TxOut,
    operator_xonly_pk: XOnlyPublicKey,
    user_sig: taproot::Signature,
    _network: bitcoin::Network,
) -> Result<TxHandler<Signed>, BridgeError> {
    let txin = SpendableTxIn::new_partial(input_utxo.outpoint, input_utxo.txout);

    let output_txout = UnspentTxOut::from_partial(output_txout.clone());

    let op_return_txout = op_return_txout(PushBytesBuf::from(operator_xonly_pk.serialize()));

    let mut txhandler = TxHandlerBuilder::new(TransactionType::Payout)
        .with_version(NON_STANDARD_V3)
        .add_input(
            NormalSignatureKind::NotStored,
            txin,
            SpendPath::KeySpend,
            DEFAULT_SEQUENCE,
        )
        .add_output(output_txout)
        .add_output(UnspentTxOut::from_partial(anchor_output(
            NON_EPHEMERAL_ANCHOR_AMOUNT,
        )))
        .add_output(UnspentTxOut::from_partial(op_return_txout))
        .finalize();
    txhandler.set_p2tr_key_spend_witness(&user_sig, 0)?;
    txhandler.promote()
}

#[allow(clippy::result_large_err)]
pub fn parse_withdrawal_sig_params(
    params: WithdrawParams,
) -> Result<(u32, taproot::Signature, OutPoint, ScriptBuf, Amount), Status> {
    let mut input_signature =
        taproot::Signature::from_slice(&params.input_signature).map_err(|e| {
            Status::invalid_argument(format!("Can't convert input to taproot Signature - {e}"))
        })?;

    // If the Taproot sighash type is Default (no explicit type attached; i.e. a 64-byte
    // signature without a sighash flag), normalize it to SinglePlusAnyoneCanPay.
    // Prior to v0.5 this was Clementine's implicit behavior; we retain it here for
    // backwards compatibility when a 64-byte signature is provided.
    if input_signature.sighash_type == TapSighashType::Default {
        tracing::warn!(
            "Input signature for withdrawal {} has sighash type default, setting to SinglePlusAnyoneCanPay", params.withdrawal_id,
        );
        input_signature.sighash_type = TapSighashType::SinglePlusAnyoneCanPay;
    }

    // enforce sighash type here
    if input_signature.sighash_type != TapSighashType::SinglePlusAnyoneCanPay {
        return Err(Status::invalid_argument(format!(
            "Input signature has wrong sighash type, SinglePlusAnyoneCanPay expected, got {}",
            input_signature.sighash_type
        )));
    }
