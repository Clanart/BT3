### Title
Forged `ReceivedOutput` deserialization can report arbitrary Bitcoin funds as spendable - ([File: networks/bitcoin/src/wallet/mod.rs](networks/bitcoin/src/wallet/mod.rs))

### Summary
`ReceivedOutput::read` accepts a scalar offset, an arbitrary consensus-encoded `TxOut`, and an arbitrary `OutPoint`, then returns them as a spendable received output without validating the script shape, key relationship, scanner provenance, or on-chain existence of the claimed outpoint. [1](#0-0) 

### Finding Description
`ReceivedOutput` represents an output together with the scalar offset needed to spend it and its claimed `TxOut`/`OutPoint`. [2](#0-1)  Its parser only performs canonical scalar decoding and generic Bitcoin consensus decoding, with no check that `output.script_pubkey` is P2TR, corresponds to `offset` under an expected group key, or was actually produced by `Scanner`. [3](#0-2)  The legitimate construction path is `Scanner::scan_transaction`, which only creates a `ReceivedOutput` after matching an on-chain transaction output’s `script_pubkey` against a registered spend script. [4](#0-3) 

### Impact Explanation
An attacker-controlled byte string can deserialize to a `ReceivedOutput` naming a nonexistent `OutPoint` and a P2TR output controlled by an unrelated key while still exposing a positive `value()`. [5](#0-4)  Any caller using this parser for untrusted wallet/output state can therefore report funds as received even though Serai cannot spend them and the referenced output need not exist. [1](#0-0) 

### Likelihood Explanation
The forged encoding is just `offset.to_bytes()`, followed by `serialize(&output)` and `serialize(&outpoint)`, matching `ReceivedOutput::write`. [6](#0-5)  Exploitation only requires the attacker to reach an API or storage path that passes attacker-controlled bytes to `ReceivedOutput::read`; no malformed encoding, race, or cryptographic break is needed. [3](#0-2) 

### Recommendation
Do not expose `ReceivedOutput::read` as a trusted reconstruction mechanism for unauthenticated data. [1](#0-0)  Reconstruct outputs only through `Scanner::scan_transaction`, or authenticate stored scanner results and validate that the script is an expected registered P2TR script before accepting the deserialized value. [4](#0-3)  If raw deserialization remains necessary, require the expected scanner key as an argument and recompute the accepted script/offset relationship instead of trusting arbitrary decoded fields. [7](#0-6) 

### Proof of Concept
From `networks/bitcoin/src/wallet/mod.rs`, the accepted wire format is scalar bytes, then a consensus `TxOut`, then a consensus `OutPoint`. [6](#0-5) 

```rust
use bitcoin::{
  consensus::encode::serialize,
  key::TweakedPublicKey,
  Amount, OutPoint, ScriptBuf, TxOut,
};
use frost::curve::Secp256k1;
use k256::{ProjectivePoint, Scalar};
use bitcoin_serai::wallet::ReceivedOutput;

// Any P2TR-looking script not controlled by the Serai key is sufficient.
let unrelated_p2tr = ScriptBuf::new_p2tr_tweaked(
  TweakedPublicKey::dangerous_assume_tweaked(
    /* x-only key controlled by the attacker or with unknown discrete log */
  )
);

let forged_output = TxOut {
  value: Amount::from_sat(100_000),
  script_pubkey: unrelated_p2tr,
};

let forged_outpoint = OutPoint::default();

let mut bytes = Vec::new();
bytes.extend(Scalar::ZERO.to_bytes());
bytes.extend(serialize(&forged_output));
bytes.extend(serialize(&forged_outpoint));

let parsed = ReceivedOutput::read(&mut bytes.as_slice()).unwrap();
assert_eq!(parsed.value(), 100_000);
assert_eq!(parsed.outpoint(), &forged_outpoint);
```

`ReceivedOutput::read` accepts those bytes despite the outpoint and script never having been observed through `Scanner::scan_transaction` or bound to the expected key. [3](#0-2)
