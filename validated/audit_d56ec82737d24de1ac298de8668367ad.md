### Title
Unauthenticated `NonceGen` RPC Allows Session-Eviction DoS That Permanently Stalls Deposit Finalization - (`core/src/rpc/verifier.rs`, `core/src/verifier.rs`, `core/src/servers.rs`)

---

### Summary

When `client_verification = false` (a valid, non-mainnet configuration), the verifier's `NonceGen` gRPC endpoint is completely unauthenticated. Any network-reachable attacker can flood it with requests, filling the bounded `AllSessions` store (`MAX_NUM_SESSIONS = 2000`) and evicting legitimate deposit-signing sessions. When the aggregator subsequently calls `DepositSign` with the evicted session ID, the verifier returns "Session not found," aborting the deposit. A sustained flood prevents any deposit from ever completing, permanently locking depositors' BTC in the deposit UTXO.

---

### Finding Description

**Access-control gate is optional and disabled by config**

`create_grpc_server` in `core/src/servers.rs` wraps the verifier service with either `OnlyAggregatorAndSelf` (cert-pinned mTLS) or `Noop` (no auth), depending solely on `config.client_verification`:

```rust
if config.client_verification {
    OnlyAggregatorAndSelf { aggregator_cert, our_cert: client_cert }
} else {
    Noop   // ← zero authentication
}
``` [1](#0-0) 

`client_verification = false` is a documented, supported configuration for non-mainnet deployments. The mainnet guard in `check_mainnet_requirements` only fires at process startup for `Network::Bitcoin`; it does not prevent a misconfigured or non-mainnet verifier from running with `Noop`. [2](#0-1) 

**`NonceGen` mutates shared in-memory state without any caller check**

The `nonce_gen` RPC handler calls `Verifier::nonce_gen`, which generates fresh MuSig2 secret nonces and inserts a new `NonceSession` into the global `AllSessions` map: [3](#0-2) [4](#0-3) 

**Bounded store with LRU eviction of oldest sessions**

`AllSessions` enforces two hard limits: `MAX_NUM_SESSIONS = 2000` and `MAX_ALL_SESSIONS_BYTES = 2 GB`. When either limit is exceeded, `add_new_session_with_id` evicts the **oldest** session (FIFO via `session_queue`): [5](#0-4) [6](#0-5) 

**Legitimate deposit sessions are evicted**

During `new_deposit`, the aggregator calls `NonceGen` on each verifier to obtain a session ID, then passes that ID inside `DepositSignSession` to `DepositSign`. Inside `deposit_sign`, the verifier immediately calls `remove_session_with_id(session_id)`: [7](#0-6) 

If the session was evicted between `NonceGen` and `DepositSign`, `remove_session_with_id` returns `Err("Session not found")`, which propagates as a gRPC error and aborts the entire deposit pipeline.

**Unbounded `used_ids` memory leak compounds the issue**

Every `NonceGen` call permanently inserts the session ID into `used_ids: HashSet<u128>`, which is never pruned. An attacker making millions of calls causes unbounded heap growth independent of the session eviction. [8](#0-7) [9](#0-8) 

---

### Impact Explanation

A sustained flood of `NonceGen` calls (≥ 2001 calls with `num_nonces = 1`) evicts all legitimate deposit sessions. Every `DepositSign` call from the aggregator fails with "Session not found." The aggregator must restart the entire deposit flow, but the attacker can immediately evict the new sessions too. Depositors' BTC remains locked in the deposit UTXO indefinitely. The bridge's peg-in liveness is broken for as long as the attack continues.

---

### Likelihood Explanation

- **Trigger**: Any host that can reach the verifier's gRPC TCP port when `client_verification = false`.
- **Precondition**: `client_verification = false` is the default in the example `.env` file's first block and is a valid non-mainnet setting. Testnet4 and regtest deployments are directly affected.
- **Cost**: 2001 lightweight gRPC streaming calls; each returns immediately after inserting one 132-byte nonce. The rate-limit layer (`ratelimit_req_count = 1000` per interval) slows but does not stop a sustained attacker across multiple intervals.
- **No privileged keys required**. [10](#0-9) 

---

### Recommendation

1. **Enforce authentication on `NonceGen` regardless of `client_verification`**: The `NonceGen` endpoint must only be callable by the aggregator or the verifier itself. Move the cert-pinning check out of the optional `client_verification` branch for sensitive endpoints, or add a per-method guard inside the `nonce_gen` handler.

2. **Bind session IDs to the caller's identity**: Include the aggregator's cert fingerprint or a deposit-outpoint commitment in the session ID so that a session created by the aggregator cannot be confused with one created by an attacker.

3. **Prune `used_ids`**: Cap or periodically clear `used_ids` to prevent unbounded memory growth.

4. **Enforce `client_verification = true` on all non-regtest networks**: Extend `check_mainnet_requirements` to cover testnet4 and signet, or make `client_verification = false` a hard error outside of `cfg(test)`.

---

### Proof of Concept

```
# Attacker (no cert required when client_verification=false):
for i in $(seq 1 2001); do
  grpcurl -plaintext verifier:PORT clementine.ClementineVerifier/NonceGen \
    '{"num_nonces": 1}' &
done
wait

# Now the aggregator calls new_deposit → NonceGen → DepositSign:
# DepositSign fails: "Session not found" for every verifier
# Deposit pipeline aborts; depositor's BTC remains locked.
```

The attacker repeats the flood every time the aggregator retries, sustaining the DoS indefinitely.

    pub async fn nonce_gen(
        &self,
        num_nonces: u32,
    ) -> Result<(u128, Vec<PublicNonce>), BridgeError> {
        // reject if too many nonces are requested
        if num_nonces > NUM_NONCES_LIMIT {
            return Err(eyre::eyre!(
                "Number of nonces requested is too high, max allowed is {}, requested: {}",
                NUM_NONCES_LIMIT,
                num_nonces
            )
            .into());
        }
        if num_nonces == 0 {
            return Err(
                eyre::eyre!("Number of nonces requested is 0, cannot generate nonces").into(),
            );
        }
        let (sec_nonces, pub_nonces): (Vec<SecretNonce>, Vec<PublicNonce>) = (0..num_nonces)
            .map(|_| {
                // nonce pair needs keypair and a rng
                let (sec_nonce, pub_nonce) = musig2::nonce_pair(&self.signer.keypair)?;
                Ok((sec_nonce, pub_nonce))
            })
            .collect::<Result<Vec<(SecretNonce, PublicNonce)>, BridgeError>>()?
            .into_iter()
            .unzip();

        let session = NonceSession { nonces: sec_nonces };

        // save the session
        let session_id = {
            let all_sessions = &mut *self.nonces.lock().await;
            all_sessions.add_new_session_with_random_id(session)?
        };

        Ok((session_id, pub_nonces))
    }
