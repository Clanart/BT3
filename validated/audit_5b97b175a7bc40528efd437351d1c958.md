### Title
Unauthenticated one-shot DoS via unbounded `io.ReadAll` in NewRelic/Datadog RPC middleware bypasses `MaxRequestContentLength` — ([File: networks/rpc/http_newrelic.go])

### Summary
When NewRelic or Datadog APM tracing is enabled on a Kaia JSON-RPC HTTP server (`NEWRELIC_APP_NAME`/`NEWRELIC_LICENSE` or `DD_TRACE_ENABLED` env vars), every inbound request — including from any unauthenticated, unprivileged public RPC caller — is first passed through `getRPCRequests`, which reads the entire request body into memory with no size limit whatsoever, before the normal `Content-Length`/`MaxRequestContentLength` enforcement in `validateRequest` ever runs. This exactly mirrors the Bandit chunked-body bug class: an outer request-body reader silently ignores the configured size cap and buffers the whole body, letting a single request exhaust memory.

### Finding Description
`getRPCRequests` reads the body unconditionally with no bound: [1](#0-0) 

This function is invoked by both middleware wrappers before the underlying handler (and thus before any size validation) runs: [2](#0-1) [3](#0-2) 

`NewHTTPServer` wires these middlewares as the *outermost* layer, wrapping `newCorsHandler`/`newVHostHandler`/`http.TimeoutHandler`, which is the layer that eventually calls `Server.ServeHTTP` where `validateRequest` performs the `Content-Length` cap check: [4](#0-3) [5](#0-4) [6](#0-5) 

By contrast, the normal (non-APM) path caps the body via `io.LimitReader(r.Body, MaxRequestContentLength)` in `newHTTPServerConn` — but that protection is only reached *after* `getRPCRequests` has already fully buffered the body when APM tracing is enabled: [7](#0-6) 

Because Go's `net/http` server will happily stream an arbitrarily large `Transfer-Encoding: chunked` (or simply a huge `Content-Length`) body to `r.Body`, and `io.ReadAll` has no cap, a single request with an oversized or chunked body causes the entire payload to be materialized in memory before any size check — precisely the "size cap silently dropped" bug class from the report, just at the Go/net-http layer instead of Bandit's own HTTP/1 reader.

### Impact Explanation
Any unauthenticated public JSON-RPC caller can send one HTTP POST request with a very large (or `Transfer-Encoding: chunked`) body to any RPC endpoint on a Kaia node that has NewRelic or Datadog APM enabled, causing the node process to buffer the entire body in memory via `io.ReadAll`, independent of the operator-configured `MaxRequestContentLength`. This can exhaust node memory and crash the process (OOM), taking down a public RPC/EN node — a availability-only impact matching CWE-770 (Allocation of Resources Without Limits).

### Likelihood Explanation
NewRelic and Datadog APM integrations are common production observability practices for RPC-facing nodes; enabling either sets this vulnerable code path as the entry point for every RPC request. No authentication, valid JSON-RPC method, or special network position is required — only reachability to the public HTTP RPC port.

### Recommendation
Wrap `r.Body` with `io.LimitReader(r.Body, common.MaxRequestContentLength)` (or equivalently reuse `newHTTPServerConn`'s limiting logic) inside `getRPCRequests` in `networks/rpc/http_newrelic.go`, before calling `io.ReadAll`, and reject/short-circuit with an error (mirroring `validateRequest`'s `413`) when the limit is exceeded, so the cap is enforced consistently regardless of whether APM middleware is active.

### Proof of Concept
```
# On a node started with NEWRELIC_APP_NAME/NEWRELIC_LICENSE (or DD_TRACE_ENABLED=true) set:
curl -X POST http://<rpc-host>:<port>/ \
  -H "Content-Type: application/json" \
  -H "Transfer-Encoding: chunked" \
  --data-binary @- <<'EOF' &
{ generate/stream a multi-GB JSON body here, e.g. via a script that
  writes chunked frames of {"jsonrpc":"2.0","method":"eth_chainId","id":1,...padding...} }
EOF
```
Sending this single request causes `getRPCRequests` → `io.ReadAll(r.Body)` to buffer the full body in the node process before `validateRequest`'s `MaxRequestContentLength` check is ever reached, regardless of how small that configured cap is.

func NewHTTPServer(cors []string, vhosts []string, timeouts HTTPTimeouts, srv http.Handler) *http.Server {
	timeouts = sanitizeTimeouts(timeouts)
	// Wrap the CORS-handler within a host-handler
	handler := newCorsHandler(srv, cors)
	handler = newVHostHandler(vhosts, handler)
	handler = http.TimeoutHandler(handler, timeouts.ExecutionTimeout, "timeout")

	// If os environment variables for NewRelic exist, register the NewRelicHTTPHandler
	nrApp := newNewRelicApp()
	if nrApp != nil {
		handler = newNewRelicHTTPHandler(nrApp, handler)
	}

	// If os environment variables for Datadog exist, register the NewDatadogHTTPHandler
	ddTracer := newDatadogTracer()
	if ddTracer != nil {
		handler = newDatadogHTTPHandler(ddTracer, handler)
	}

	return &http.Server{
		Handler:      handler,
		ReadTimeout:  timeouts.ReadTimeout,
		WriteTimeout: timeouts.WriteTimeout,
		IdleTimeout:  timeouts.IdleTimeout,
	}
}

func (s *Server) ServeHTTP(w http.ResponseWriter, r *http.Request) {
	// Permit dumb empty requests for remote health-checks (AWS)
	if r.Method == http.MethodGet && r.ContentLength == 0 && r.URL.RawQuery == "" {
		return
	}
	if code, err := validateRequest(r); err != nil {
		http.Error(w, err.Error(), code)
		return
	}

func validateRequest(r *http.Request) (int, error) {
	if r.Method == http.MethodPut || r.Method == http.MethodDelete {
		return http.StatusMethodNotAllowed, errors.New("method not allowed")
	}
	if r.ContentLength > int64(common.MaxRequestContentLength) {
		err := fmt.Errorf("content length too large (%d>%d)", r.ContentLength, int64(common.MaxRequestContentLength))
		return http.StatusRequestEntityTooLarge, err
	}
