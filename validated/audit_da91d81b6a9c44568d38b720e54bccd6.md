### Title
Scanner registers immature coinbase outputs as spendable, letting any miner poison the spend queue with inputs that cannot be spent - (networks/bitcoin/src/wallet/mod.rs)

### Summary
The bug class in the reference report is a queueing/processing pipeline that accepts an entry from an untrusted party whose later processing fails, blocking the entire queue. In Serai's Bitcoin scanner, `Scanner::scan_block` iterates over `block.txdata` including `txdata[0]` — the coinbase transaction — and registers any output paying a registered script as a `ReceivedOutput`, a type documented as "a spendable output." Coinbase outputs are unspendable for 100 blocks (COINBASE_MATURITY), so an output deposited by an arbitrary miner enters the set of spendable inputs yet produces transactions Bitcoin consensus will reject.

### Finding Description
`Scanner::scan_block` at `networks/bitcoin/src/wallet/mod.rs:221-227` calls `scan_transaction` on every transaction in the block, including the coinbase. `scan_transaction` (`mod.rs:199-214`) matches `output.script_pubkey` against the registered scripts and emits a `ReceivedOutput { offset, output, outpoint }` with no check of whether the outpoint's transaction is a coinbase or its confirmation depth. The code even acknowledges this in the comment at `mod.rs:218-220`, stating a "post-processing pass is needed to remove those outputs" — but no such filtering exists in the library, and `ReceivedOutput` carries no flag marking it immature.

Downstream, `SignableTransaction::new` (`networks/bitcoin/src/wallet/send.rs:150-256`) treats every input's `ReceivedOutput` identically: it builds `TxIn`s from `input.outpoint` (`send.rs:177-185`), computes `input_sat` (`send.rs:175`), and `TransactionSignMachine::sign` produces BIP-341 key-spend signature hashes over `Prevouts::All` (`send.rs:373-397`). `SignableTransaction`/`TransactionMachine` have no maturity or coinbase check, so the threshold signature completes successfully over a transaction spending an immature coinbase output — a transaction every Bitcoin node rejects under `bad-txns-premature-spends`.

Analogous to the rollover queue: the malicious entry is not rejected at enqueue time (scan), poisons batch construction (SignableTransaction), and only fails at final processing (broadcast), where the entire batch — including all honest inputs co-batched with it — is invalidated. Each re-attempt re-includes the poisoned input since nothing marks it unusable.

### Impact Explanation
An unprivileged Bitcoin miner can direct a coinbase payout to the Serai vault's p2tr script (or any registered offset's script). The scanner reports the output as received, the batch signer co-spends it alongside legitimate deposits, and the resulting signed transaction is permanently invalid until maturity — breaking the spend/batch pipeline for that attempt and every reattempt that re-selects the output, matching the "funds reported received that are not spendable" / blocked-queue impact class. Repeated payouts extend the disruption indefinitely (a new immature output each block the miner wins). Severity: Medium — permanent-failure DoS of withdrawal batching, recoverable only via out-of-band input filtering.

### Likelihood Explanation
Requires winning a Bitcoin block, which any miner or mining pool can do routinely; no Serai validator status, key material, or cooperation is needed — only broadcasting a standard Bitcoin transaction (the coinbase) to the vault address. Pool payouts to arbitrary addresses are common practice, so this can also occur without malicious intent.

### Recommendation
Track coinbase status and confirmation depth in `Scanner`/`ReceivedOutput`: reject coinbase outpoints in `scan_block` (skip `block.txdata[0]` or detect `tx.is_coinbase()`), or carry a maturity flag on `ReceivedOutput` and have `SignableTransaction::new` reject immature inputs. Alternatively, require a minimum confirmation count parameter on the scan interface so callers cannot construct `ReceivedOutput`s for outputs below maturity.

```rust
// In-scope: networks/bitcoin/src/wallet/mod.rs
let mut scanner = Scanner::new(group_key).unwrap();
// Attacker mines a block whose coinbase pays the vault script:
// block.txdata[0] is a coinbase tx; its output.script_pubkey == vault p2tr script

assert_eq!(received.len(), 1); // immature coinbase output reported as spendable

// Downstream: SignableTransaction::new(vec![received[0]], payments, ...)
// succeeds in fee/weight math and sign() produces a valid FROST signature over

// coinbase — rejected by every node, blocking the whole batch.
```
