### Title
Payout reimbursement is attributed by an unauthenticated OP_RETURN field, letting anyone force an operator to be credited for a withdrawal it never funded - (File: core/src/verifier.rs)

### Summary
`update_finalized_payouts` attributes a withdrawal payout to an operator purely by parsing an `OP_RETURN` output of whatever transaction happens to spend the `withdrawal_utxo`, with no cryptographic proof that the named operator authorized, signed, or funded that specific payout.

### Finding Description
When a transaction spends a tracked `withdrawal_utxo`, the verifier's chain-sync logic in `update_finalized_payouts` reads the payer's identity straight out of the spending transaction's `OP_RETURN` output and writes it to the database as the credited operator: [1](#0-0) 

```
let operator_xonly_pk = op_return_output
    .and_then(|output| parse_op_return_data(&output.script_pubkey))
    .and_then(|bytes| XOnlyPublicKey::from_slice(bytes).ok());
...
payout_txs_and_payer_operator_idx.push((idx, payout_txid, operator_xonly_pk, block_hash));
```
This value is persisted with no signature check tying it to the actual operator: [2](#0-1) 

The spending transaction that sets this field is normally built by `create_payout_txhandler` (`core/src/builder/transaction/operator_reimburse.rs`) using the withdrawal requester's pre-committed `in_signature`/`in_outpoint` (public data that authorizes anyone possessing it to spend the dust withdrawal UTXO), plus additional inputs the payer supplies to fund `out_amount`. The `OP_RETURN` payload containing the "payer" operator's xonly public key is plain, unsigned data baked into the transaction by whoever assembles it — it is not authenticated by that operator's private key. Because the underlying spend only requires the user's already-public signature over the withdrawal parameters (visible once the withdrawal request is registered/observed on Citrea), any unprivileged party can construct and broadcast to Bitcoin a payout transaction that correctly pays the user the required amount, while stamping an arbitrary *other*, legitimately-registered operator's `xonly_pk` into the `OP_RETURN` field.

Downstream, this DB-recorded attribution is trusted without re-verification:
- `PayoutCheckerTask::run_once` automatically picks up "unhandled" payouts for the operator's own key and proceeds straight into `handle_finalized_payout` → kickoff → reimbursement flow: [3](#0-2) 
- `validate_payer_is_operator` only checks that the DB-recorded `payer_xonly_pk` equals the operator's own key — it never checks that the operator actually broadcast or signed the payout tx itself: [4](#0-3) 

This is the same bug class as the ZetaChain finding: an unvalidated/unauthenticated value (there, `gasPrice` set in memory before `PostVoteGasPrice` validates it; here, an `operator_xonly_pk` accepted from an untrusted, unauthenticated `OP_RETURN` field before any proof that operator actually funded/authorized the payout) is committed to durable state and then relied upon by later privileged logic (outbound voting there; kickoff/reimbursement here), breaking the custody binding "operator credited == party that paid."

### Impact Explanation
An unprivileged Bitcoin-transaction-broadcaster can front a withdrawal payment out of their own funds but assign credit to any other registered operator by simply writing that operator's xonly public key into the `OP_RETURN` output. The victim operator's automated `PayoutCheckerTask` will then dispatch the full kickoff/reimbursement pipeline and pull `bridge_amount` BTC out of the move-to-vault UTXO to "reimburse" a payout it never made — i.e., an operator is reimbursed for a payout it never funded. This maps directly to the specified Critical impact category.

### Likelihood Explanation
The precondition is only knowledge of the public withdrawal parameters (`input_signature`, `input_outpoint`, `output_script_pubkey`, `output_amount`) that are exposed once a withdrawal is registered on Citrea, and the ability to fund and broadcast a standard Bitcoin transaction — no operator/verifier/aggregator role, TLS credential, or key compromise is required. This makes the attack straightforwardly reachable by any external actor monitoring pending withdrawals.

### Recommendation
Do not trust the plaintext `OP_RETURN` payer identity as sufficient proof of payout attribution. Require the claiming operator to additionally provide (and have the verifier/state-machine independently check) a cryptographic signature over the payout details, or otherwise bind operator attribution to something the operator alone can produce (e.g., require the payout transaction's additional funding inputs to originate from a UTXO/script provably controlled by that operator's key, or require an explicit signed claim message from the operator before crediting it in `update_payout_txs_and_payer_operator_xonly_pk`), mirroring the referenced fix pattern of only committing state after it has been validated/authenticated.

### Proof of Concept
1. Monitor Citrea for a new withdrawal request, obtaining the public `(input_signature, input_outpoint, output_script_pubkey, output_amount)` withdrawal parameters and the deposit's registered operator set (`deposit_data.get_operators()`).
2. Independently build a Bitcoin transaction spending the `withdrawal_utxo` (using the public `input_signature`), adding attacker-funded inputs to cover `output_amount`, and set the `OP_RETURN` output to the `xonly_pk` of some other legitimate, registered operator O (not the attacker), following the same structure as `create_payout_txhandler` in `core/src/builder/transaction/operator_reimburse.rs`.
3. Broadcast this transaction to Bitcoin and let it confirm.
4. The verifier's block sync calls `update_finalized_payouts` (`core/src/verifier.rs:2283-2353`), parses the `OP_RETURN`, and records operator O as the payer via `update_payout_txs_and_payer_operator_xonly_pk`.
5. Operator O's `PayoutCheckerTask` (`core/src/task/payout_checker.rs:39-111`) detects the "unhandled payout" credited to it, calls `handle_finalized_payout`, and proceeds through kickoff, ultimately claiming reimbursement from the bridge's collateral/vault funds for a payment operator O never made or authorized.

    async fn run_once(&mut self) -> Result<Self::Output, BridgeError> {
        let mut dbtx = self.db.begin_transaction().await?;
        let unhandled_payout = self
            .db
            .get_first_unhandled_payout_by_operator_xonly_pk(
                Some(&mut dbtx),
                self.operator.signer.xonly_public_key,
            )
            .await?;

        if unhandled_payout.is_none() {
            return Ok(false);
        }

        let (citrea_idx, move_to_vault_txid, payout_tx_blockhash) =
            unhandled_payout.expect("Must be Some");

        tracing::info!(
            "Unhandled payout found for withdrawal {}, move_txid: {}",
            citrea_idx,
            move_to_vault_txid
        );

        let deposit_data = self
            .db
            .get_deposit_data_with_move_tx(Some(&mut dbtx), move_to_vault_txid)
            .await?;
        if deposit_data.is_none() {
            return Err(eyre::eyre!("Fronted withdrawal for move tx {move_to_vault_txid} found, but the signatures for the deposit are not found in the db.").into());
        }

        let deposit_data = deposit_data.expect("Must be Some");

        let kickoff_txid = self
            .operator
            .handle_finalized_payout(
                &mut dbtx,
                deposit_data.get_deposit_outpoint(),
                payout_tx_blockhash,
            )
            .await?;

    /// For a deposit_id checks that the payer for that deposit is the operator, and the payout blockhash and kickoff txid are set.
    async fn validate_payer_is_operator(
        &self,
        dbtx: Option<DatabaseTransaction<'_>>,
        deposit_id: u32,
    ) -> Result<(BlockHash, Txid), BridgeError> {
        let (payer_xonly_pk, payout_blockhash, kickoff_txid) = self
            .db
            .get_payer_xonly_pk_blockhash_and_kickoff_txid_from_deposit_id(dbtx, deposit_id)
            .await?;

        tracing::info!(
            "Payer xonly pk and kickoff txid found for the requested deposit, payer xonly pk: {:?}, kickoff txid: {:?}",
            payer_xonly_pk,
            kickoff_txid
        );

        // first check if the payer is the operator, and the kickoff is handled
        // by the PayoutCheckerTask, meaning kickoff_txid is set
        let (payout_blockhash, kickoff_txid) = match (
            payer_xonly_pk,
            payout_blockhash,
            kickoff_txid,
        ) {
            (Some(payer_xonly_pk), Some(payout_blockhash), Some(kickoff_txid)) => {
                if payer_xonly_pk != self.signer.xonly_public_key {
                    return Err(eyre::eyre!(
                        "Payer is not own operator for deposit, payer xonly pk: {:?}, operator xonly pk: {:?}",
                        payer_xonly_pk,
                        self.signer.xonly_public_key
                    )
                    .into());
                }
                (payout_blockhash, kickoff_txid)
            }
            _ => {
                return Err(eyre::eyre!(
                    "Payer info not found for deposit, payout blockhash: {:?}, kickoff txid: {:?}",
                    payout_blockhash,
                    kickoff_txid
                )
                .into());
            }
        };
