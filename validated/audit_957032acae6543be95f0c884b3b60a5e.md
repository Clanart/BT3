## Title
Self-relayed oversized message bodies let an attacker mint unbounded reputation and drain real `$BRIDGE` collator rewards - (File: `modules/pallets/messaging-incentives/src/lib.rs`)

### Summary
`pallet-messaging-incentives` mints `ReputationAsset` to whoever signs a delivered ISMP message, scaled purely by `max(body_size, 32)` bytes, with no cap and no linkage to any real cost paid on Hyperbridge. Because dispatching from Polkadot-SDK chains through Hyperbridge is free at the protocol layer (no per-byte protocol fee — only an optional relayer tip that a self-relaying attacker can set to zero), an attacker can pad the body of a message they dispatch and relay themselves to mint reputation far in excess of any value they contributed to the network. `pallet-collator-manager` then converts that reputation directly into the top collator slot, which continuously receives real `$BRIDGE` token transfers from the treasury via `note_author`. This mirrors the Ditto discount-fee bug: a reward is minted in proportion to a quantity the attacker fully controls (bytes / discount magnitude) rather than to the real economic value/cost actually incurred, letting the attacker capture more value than they contribute.

### Finding Description
`Pallet::message_bytes` sums `max(body.len(), 32)` across the requests in a message with no upper bound: [1](#0-0) 

`on_executed` then mints `rate * bytes` of `ReputationAsset` to the account recovered from the message's own `signer` field — i.e., whoever submitted/relayed the message to Hyperbridge, which can be the same account that authored the underlying request: [2](#0-1) 

There is no check that the byte count reflects genuine application payload, no per-account/per-session cap, and no relation to a real fee actually paid to Hyperbridge for that dispatch. The docs confirm dispatch from Polkadot-SDK source chains carries **no protocol fee** at all — only an optional relayer tip that a self-relayer can set to zero: [3](#0-2) 

`pallet-collator-manager` ranks candidates purely by `ReputationAsset` balance and selects the highest-reputation controllers as the new collator set each session: [4](#0-3) 

Once selected, the collator's account (`author`) is paid a real, transferable `CollatorReward` from the treasury on every authored block via `note_author` — this is the point where soulbound reputation converts into real fund extraction: [5](#0-4) 

The `state-coprocessor` pallet reuses the exact same unbounded, un-costed minting logic keyed only by `total_bytes`, confirming the pattern is systemic rather than an isolated oversight: [6](#0-5) 

The root cause parallels the Ditto discount-fee bug precisely: the reward-minting formula is driven by a value the attacker fully controls (message body padding) rather than by the real cost/fee actually collected by the protocol, so a self-interested actor can trigger the reward path deliberately and extract value disproportionate to what they contributed.

### Impact Explanation
An attacker with an account on any chain connected to Hyperbridge can dispatch messages with artificially padded bodies (megabyte-scale, bounded only by the source chain's own message-size/weight limits) and relay them under their own signing key at zero protocol fee. This mints arbitrarily large `ReputationAsset` balances, letting the attacker unseat legitimate collators every session and continuously receive real `$BRIDGE` `CollatorReward` payouts from the treasury — a direct, repeatable transfer of protocol funds to an actor whose reputation does not reflect genuine relaying/consensus/BEEFY-proving effort. This is unauthorized value extraction from the treasury and manipulates the security-critical collator-selection process (host/consensus management), matching the bounty's "stealing or loss of funds" and "logic attack" categories.

### Likelihood Explanation
No privileged role, compromised relayer/prover, or malicious peer is required — any account that can dispatch and self-relay an ISMP message (a normal, permissionless capability by design) can pad the body and claim the mint. The only cost is the source chain's own transaction/weight cost for a large payload, which is unrelated to and far cheaper than the reputation/BRIDGE value gained, exactly as the original discount-fee exploit made the discount penalty cheaper to trigger than the fee it yielded.

### Recommendation
Decouple the reputation/reward mint from attacker-controlled body size. Options: cap the per-message/per-account mintable bytes per session, tie the mint rate to an actual fee paid to Hyperbridge (so cost and reward scale together), require the relaying account to be distinct from the message's originating app/account, or rate-limit `ReputationMinted` accrual per controller per session independent of message volume/size.

### Proof of Concept
1. Deploy/own an app on any chain connected to Hyperbridge (e.g., an EVM testnet or a permissioned parachain the attacker controls).
2. From that app, dispatch an ISMP `PostRequest` with `body` padded to the maximum size the source chain's weight/gas limits allow (no relayer fee needs to be attached).
3. Run the relayer role yourself: submit the `RequestMessage` with a valid proof to Hyperbridge, signing with your own sr25519/secp key so `Pallet::relayer_for` resolves to your own controller account (`modules/pallets/messaging-incentives/src/lib.rs:140-153`).
4. `on_executed` mints `MintPerByte * body.len()` reputation to your controller account with no cap (`modules/pallets/messaging-incentives/src/lib.rs:160-186`).
5. Repeat across sessions/messages to outrank all other collator candidates in `new_session`'s reputation sort (`modules/pallets/collator-manager/src/lib.rs:511-538`).
6. Once selected, `note_author` pays your account real `$BRIDGE` `CollatorReward` from the treasury on every block you author (`modules/pallets/collator-manager/src/lib.rs:475-497`), for effort/cost that does not reflect genuine network service.

		match message {
			Message::Request(req) => req
				.requests
				.iter()
				.map(|p| core::cmp::max(p.body.len() as u32, 32))
				.sum::<u32>(),
			_ => 0,
		}
	}

impl<T: Config> FeeHandler for Pallet<T>
where
	T::AccountId: From<[u8; 32]>,
{
	fn on_executed(
		messages: Vec<MessageWithWeight>,
		_events: Vec<IsmpEvent>,
	) -> DispatchResultWithPostInfo {
		let rate = MintPerByte::<T>::get();
		if !rate.is_zero() {
			for mw in &messages {
				let bytes = Self::message_bytes(&mw.message);
				let bytes_balance: BalanceOf<T> = (bytes as u128).saturated_into();
				let amount = rate.saturating_mul(bytes_balance);
				if amount.is_zero() {
					continue;
				}
				if let Some(relayer) = Self::relayer_for(&mw.message) {
					match T::ReputationAsset::mint_into(&relayer, amount) {
						Ok(_) =>
							Self::deposit_event(Event::ReputationMinted { relayer, bytes, amount }),
						Err(err) => log::warn!(
							target: "messaging-incentives",
							"reputation mint failed for {bytes}b: {err:?}",
						),
					}
				}
			}
		}
		Ok(PostDispatchInfo { actual_weight: None, pays_fee: Pays::No })
	}

	impl<T: Config> pallet_authorship::EventHandler<T::AccountId, BlockNumberFor<T>> for Pallet<T> {
		fn note_author(author: T::AccountId) {
			let reward = CollatorReward::<T>::get();

			if reward > Zero::zero() {
				let treasury_account = T::TreasuryAccount::get().into_account_truncating();

				let result = T::NativeCurrency::transfer(
					&treasury_account,
					&author,
					reward,
					frame_support::traits::ExistenceRequirement::KeepAlive,
				);

				if result.is_ok() {
					Self::deposit_event(Event::CollatorRewarded {
						collator: author,
						amount: reward,
					});
				}
			}
		}
	}
