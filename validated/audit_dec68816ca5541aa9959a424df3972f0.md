### Title
Stale `LastRewardedHeight` watermark lets a relayer collect a windfall `pallet-consensus-incentives` reward spanning a period when incentives were disabled - (File: `modules/pallets/consensus-incentives/src/impls.rs`)

### Summary
`pallet-consensus-incentives` rewards a relayer `(LatestHeight - baseline) * CostPerBlock` for delivering a `ConsensusMessage`, where `baseline` is a persisted watermark `LastRewardedHeight`. The watermark is only advanced when `StateMachinesCostPerBlock` is configured (`Some`); while it is unset (`None`) the pallet silently skips both the reward *and* the watermark update, even though the underlying `IsmpHost` height keeps advancing from unpaid consensus updates. When incentives are re-enabled, the stale watermark makes the very next relayer to deliver a `ConsensusMessage` collect a reward for the *entire* elapsed span, including all the blocks relayed for free by other relayers while incentives were off — an analog of the BathBuddy bug where an accrual/rate window is decoupled from actual participation.

`update_cost_per_block`/`remove_incentives` toggle `StateMachinesCostPerBlock` but never touch `LastRewardedHeight`: [3](#0-2) 

Because relayers keep delivering `ConsensusMessage`s (unpaid) to advance `IsmpHost`'s view of the remote chain regardless of whether the incentive is configured, `latest_commitment_height`/`previous_commitment_height` continue to move forward while `StateMachinesCostPerBlock` is `None`. `LastRewardedHeight` is frozen at whatever value it held before the pallet was disabled. When governance re-enables the incentive via `update_cost_per_block`, the first relayer whose `ConsensusMessage` triggers `on_executed`/`process_message` afterward is paid for `latest_height - LastRewardedHeight`, i.e. for every block advanced during the entire disabled window plus the new delivery — not just their own contribution.

### Impact Explanation
This lets a single relayer (an unprivileged, ordinary protocol participant — no compromised key, no malicious admin, no front-run required) receive treasury funds sized for work they did not perform, at the expense of the treasury and the relayers who actually delivered the disabled-period updates for free. This is a "wrong beneficiary or amount" fund-movement bug on the treasury-funded reward path, matching the Hyperbridge bridged-asset pivot that rewards must move exactly once and only to the rightful beneficiary/amount. The transfer is real (`T::Currency::transfer` from `TreasuryAccount`) and a matching reputation asset is also over-minted.

### Likelihood Explanation
Disabling and re-enabling per-chain incentives is an ordinary, expected governance operation (e.g., pausing to update cost, temporary suspension, migrations), so the disabled window is a realistic and even routine event, not an edge case requiring a compromised actor. Any relayer racing to be first to deliver a `ConsensusMessage` right after re-enable automatically captures the full windfall — no special privileges or coordination needed, only normal message submission timing that is already open to all relayers.

### Recommendation
When `remove_incentives` clears `StateMachinesCostPerBlock`, also snapshot the current `latest_commitment_height` into `LastRewardedHeight` (or otherwise mark the disabled span as "already paid/ineligible") so that re-enabling the reward starts accruing strictly from the moment the reward is turned back on, rather than replaying the entire idle interval to whichever relayer happens to deliver next.

### Proof of Concept
1. Governance calls `update_cost_per_block(state_machine_id, cost)` — incentive active, `LastRewardedHeight = H0` after the first paid update.
2. Governance calls `remove_incentives(state_machine_id)` — `StateMachinesCostPerBlock` cleared; `LastRewardedHeight` stays at `H0`. [4](#0-3) 
3. Over the next period, relayers deliver many unpaid `ConsensusMessage`s advancing the remote chain's commitment height from `H0` to `H_N` (large gap). Since `StateMachinesCostPerBlock` is `None`, `process_message` returns immediately without touching `LastRewardedHeight`. [5](#0-4) 
4. Governance calls `update_cost_per_block(state_machine_id, cost)` again to resume incentives.
5. Any relayer (attacker) submits the next `ConsensusMessage`. `calculate_reward` computes `baseline = LastRewardedHeight = H0`, `blocks = H_N+δ - H0`, and pays `(H_N+δ - H0) * cost` entirely to this one relayer via `T::Currency::transfer` from the treasury, plus mints matching reputation tokens. [6](#0-5) 

The relayer thus collects rewards for the full disabled window that other relayers already relayed for free, draining the treasury by an amount disproportionate to actual work performed in that transaction.

	fn process_message(
		state_machine_height: StateMachineHeight,
		state_machine_id: StateMachineId,
		relayer_account: T::AccountId,
	) -> Result<(), Error<T>> {
		if let Some(block_cost) = StateMachinesCostPerBlock::<T>::get(state_machine_id) {
			let reward = Self::calculate_reward(&state_machine_id, block_cost)?;

			if reward.is_zero() {
				return Ok(());
			}

			T::Currency::transfer(
				&T::TreasuryAccount::get().into_account_truncating(),
				&relayer_account,
				reward,
				Preservation::Expendable,
			)
			.map_err(|_| Error::<T>::RewardTransferFailed)?;

			Self::deposit_event(Event::<T>::RelayerRewarded {
				relayer: relayer_account.clone(),
				amount: reward,
				state_machine_height,
			});

			T::ReputationAsset::mint_into(&relayer_account, reward.saturated_into())
				.map_err(|_| Error::<T>::ReputationMintFailed)?;

			LastRewardedHeight::<T>::mutate(state_machine_id, |watermark| {
				*watermark = Some(watermark.unwrap_or_default().max(state_machine_height.height));
			});
		}
		Ok(())
	}

	#[pallet::call]
	impl<T: Config> Pallet<T> {
		/// Update cost per block for a state machine
		#[pallet::call_index(0)]
		#[pallet::weight(T::WeightInfo::update_cost_per_block())]
		pub fn update_cost_per_block(
			origin: OriginFor<T>,
			state_machine_id: StateMachineId,
			cost_per_block: <T as pallet_ismp::Config>::Balance,
		) -> DispatchResult {
			T::IncentivesOrigin::ensure_origin(origin)?;

			StateMachinesCostPerBlock::<T>::mutate(state_machine_id.clone(), |maybe_cost| {
				*maybe_cost = Some(cost_per_block);
			});

			Self::deposit_event(Event::<T>::StateMachineCostPerBlockUpdated {
				state_machine_id,
				cost_per_block,
			});

			Ok(())
		}

		/// Update cost per block for a state machine
		#[pallet::call_index(1)]
		#[pallet::weight(T::WeightInfo::update_cost_per_block())]
		pub fn remove_incentives(
			origin: OriginFor<T>,
			state_machine_id: StateMachineId,
		) -> DispatchResult {
			T::IncentivesOrigin::ensure_origin(origin)?;

			StateMachinesCostPerBlock::<T>::remove(state_machine_id.clone());

			Self::deposit_event(Event::<T>::StateMachineCostPerBlockRemoved { state_machine_id });

			Ok(())
		}
	}
