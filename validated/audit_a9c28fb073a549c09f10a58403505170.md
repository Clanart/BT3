### Title
Unbounded RLP-Decode Loop in Public `debug_isGaslessTx` RPC Enables Memory/CPU Exhaustion DoS - ([File: kaiax/gasless/impl/api.go])

### Summary
The public RPC method `debug_isGaslessTx` accepts an arbitrary-length list of raw transaction byte strings and RLP-decodes every element into a `*types.Transaction` object in a loop, *before* validating that the list length is 1 or 2 (the only sizes the function actually processes). There is no upper bound on `len(rawTxs)` or on the cumulative size of the raw transaction bytes, so a single unauthenticated JSON-RPC call can force the node to perform unbounded decoding work and unbounded heap allocation.

### Finding Description
`GaslessAPI.IsGaslessTx` is defined as:

```go
func (s *GaslessAPI) IsGaslessTx(ctx context.Context, rawTxs []hexutil.Bytes) *GaslessTxResponse {
	if len(rawTxs) == 0 {
		return ToResponse(errors.New("no transactions provided"))
	}
	txs := make([]*types.Transaction, 0, len(rawTxs))
	for i, rawTx := range rawTxs {
		...
		tx := new(types.Transaction)
		if err := rlp.DecodeBytes(rawTx, tx); err != nil {
			return ToResponse(...)
		}
		txs = append(txs, tx)
	}
	// length check happens only AFTER all decoding is done
	if len(txs) == 1 { ... }
	if len(txs) == 2 { ... }
	return ToResponse(fmt.Errorf("expected 1 or 2 transactions, got %d", len(txs)))
}
``` [2](#0-1) 

The vulnerable pattern mirrors the vLLM advisory exactly: a size/count limit that is logically meant to gate processing (here: "only 1 or 2 txs are meaningful") is enforced only *after* the expensive per-element decode loop has already run to completion, rather than before or during iteration. Because `rawTxs []hexutil.Bytes` comes directly from the JSON-RPC request body with no server-side cap on array length or element size, and `rlp.DecodeBytes` allocates a full `*types.Transaction` (including nested signature/account-key/payload structures) for each entry, an attacker can submit tens of thousands of entries — each a valid or near-valid RLP-encoded transaction blob — to make the node allocate and decode a correspondingly large amount of data in a single request handler invocation.

This RPC handler is registered with `Public: true` on the `debug` namespace [3](#0-2) , so it is reachable by any RPC caller without special privileges, exactly the class of caller in scope for this analysis (public-RPC caller).

By contrast, other tx-count-bearing structures in this codebase enforce their limits either before or during the loop (e.g., `AccountKeyWeightedMultiSig.CheckInstallable`/`MaxNumKeysForMultiSig` bound [4](#0-3) , `decodeResponseList`'s `limit` check performed per-item during the decode loop [5](#0-4) , and the `BidMsg` size-gate that runs *before* `msg.Decode` [6](#0-5) ). `IsGaslessTx` breaks this pattern by decoding unboundedly first and checking afterward.

### Impact Explanation
A single unauthenticated RPC request can drive the node to allocate memory and burn CPU proportional to an attacker-chosen, effectively unbounded number of transaction-decode operations, with no application-level cap on `len(rawTxs)` or total payload size (beyond whatever generic HTTP/WS body-size limit the RPC transport applies, which is typically megabytes, not transaction-count-aware). This can degrade or crash an endpoint node (denial of service against the RPC-serving node), matching CWE-770 (Allocation of Resources Without Limits) as in the source advisory. It does not directly enable value theft or state divergence, but denial of service against a public-RPC endpoint node is a legitimate Medium-severity availability impact.

### Likelihood Explanation
High likelihood of exploitability: the endpoint is a plain, public, unauthenticated JSON-RPC method taking a raw `[]hexutil.Bytes` array; no code path restricts the number of elements or requires any pre-conditions (balance, signature validity, nonce, etc.) before the decode loop runs. Constructing many syntactically-valid RLP transaction blobs (they need not have valid signatures to reach `rlp.DecodeBytes`) is trivial for an attacker.

### Recommendation
Bound the size of `rawTxs` up front (e.g., reject requests where `len(rawTxs) > 2` before entering the decode loop, since the function only ever meaningfully processes 1 or 2 elements), and/or impose a cumulative byte-size cap on the raw transaction payloads prior to decoding, consistent with the size-gate pattern already used for `BidMsg` at `node/cn/handler.go:1289`.

### Proof of Concept
Send a single JSON-RPC call to any node exposing the `debug` namespace:
```
curl http://<node>:8551 -X POST -H 'Content-Type: application/json' --data '
{"jsonrpc":"2.0","id":1,"method":"debug_isGaslessTx","params":[[
  "0x<validRlpTx1>", "0x<validRlpTx2>", ... repeated tens of thousands of times ...
]]}'
```
Each element is decoded into a full `*types.Transaction` via `rlp.DecodeBytes` inside the loop at `kaiax/gasless/impl/api.go:79-95` before the function ever checks that only 1 or 2 transactions are supported, causing large memory allocation and CPU usage proportional to the attacker-supplied array length.

// IsGaslessTx checks if the given raw transactions form a valid gasless transaction
// It returns a detailed result explaining why a transaction is not a valid gasless transaction if it's not
func (s *GaslessAPI) IsGaslessTx(ctx context.Context, rawTxs []hexutil.Bytes) *GaslessTxResponse {
	if len(rawTxs) == 0 {
		return ToResponse(errors.New("no transactions provided"))
	}

	// Decode the raw transactions
	txs := make([]*types.Transaction, 0, len(rawTxs))
	for i, rawTx := range rawTxs {
		if len(rawTx) == 0 {
			return ToResponse(fmt.Errorf("empty transaction at index %d", i))
		}

		// Handle Ethereum transaction envelope
		if 0 < rawTx[0] && rawTx[0] < 0x7f {
			rawTx = append([]byte{byte(types.EthereumTxTypeEnvelope)}, rawTx...)
		}

		tx := new(types.Transaction)
		if err := rlp.DecodeBytes(rawTx, tx); err != nil {
			return ToResponse(fmt.Errorf("failed to decode transaction at index %d: %v", i, err))
		}

		txs = append(txs, tx)
	}

	// Check if the transactions form a valid gasless transaction
	// Case 1: A single swap transaction
	if len(txs) == 1 {
		swapTx := txs[0]
		if !s.b.IsSwapTx(swapTx) {
			return ToResponse(errors.New("transaction is not a swap transaction"))
		}

		return ToResponse(s.b.VerifyExecutable(nil, swapTx))
	}

	// Case 2: An approve transaction followed by a swap transaction
	if len(txs) == 2 {
		approveTx := txs[0]
		swapTx := txs[1]

		if !s.b.IsApproveTx(approveTx) {
			return ToResponse(errors.New("first transaction is not an approve transaction"))
		}

		if !s.b.IsSwapTx(swapTx) {
			return ToResponse(errors.New("second transaction is not a swap transaction"))
		}

		err := s.b.VerifyExecutable(approveTx, swapTx)
		return ToResponse(err)
	}

	return ToResponse(fmt.Errorf("expected 1 or 2 transactions, got %d", len(txs)))
}

func decodeResponseList[T any](msg p2p.Msg, limit int) ([]T, error) {
	stream := rlp.NewStream(msg.Payload, uint64(msg.Size))
	if _, err := stream.List(); err != nil {
		return nil, errResp(ErrDecode, "msg %v: %v", msg, err)
	}
	var items []T
	for {
		var item T
		if err := stream.Decode(&item); err == rlp.EOL {
			return items, nil
		} else if err != nil {
			return nil, errResp(ErrDecode, "msg %v: %v", msg, err)
		}
		if len(items) >= limit {
			return nil, errResp(ErrTooManyItems, "msg %v: limit %d", msg, limit)
		}
		items = append(items, item)
	}
}
