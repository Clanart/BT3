### Title
`Scanner::scan_transaction` reports zero-value and dust outputs as received funds without a minimum-value check - (File: networks/bitcoin/src/wallet/mod.rs)

### Summary
The external report describes a "received amount" computed as a balance difference guarded by `balanceAfter >= balanceBefore`, which passes when the received amount is zero — funds are reported as received when nothing usable arrived. The analogous shape in Serai's in-scope code is `Scanner::scan_transaction`, which admits a `ReceivedOutput` solely on `script_pubkey` equality with no `value > 0` (or value >= dust) check, so a zero-value output is reported as a received, spendable output.

### Finding Description
`Scanner::scan_transaction` iterates `tx.output` and pushes a `ReceivedOutput` for every output whose `script_pubkey` appears in `self.scripts` [1](#0-0) . `ReceivedOutput::value()` simply returns `output.value.to_sat()` [2](#0-1)  with no validation that the value is nonzero or economically spendable. The crate itself defines `DUST = 546` and enforces it for outgoing payments in `SignableTransaction::new` (`*amount < DUST` → `DustPayment`) [3](#0-2) , and enforces it again when deciding whether a change output is worth creating (`value >= DUST`) [4](#0-3)  — but never applies the same minimum to inbound scanned outputs. Like the OpenQ `>=` check, the implicit predicate "output exists" admits the boundary case "output exists but carries zero (or below-dust) value."

### Impact Explanation
An unprivileged party can mine (or get mined) a transaction paying a 0-value, or below-dust, output to a script the scanner watches. The scanner then reports a `ReceivedOutput` — an output the wallet treats as funds received — that cannot actually be spent: a 0-value input contributes nothing while still requiring a signature and adding vbytes, and a below-dust input costs more in fees than its value. If such an output is later selected as an input to `SignableTransaction::new`, it inflates `input_sat` accounting with effectively worthless inputs and produces signatures over prevouts whose spend is economically irrational, and any downstream accounting keyed on `ReceivedOutput::value()` treats the phantom value as real. This matches the report's accepted-impact class: "funds reported received that are not spendable."

### Likelihood Explanation
Constructing a transaction with a 0-value or dust output to the Serai multisig's script requires no privileges — only knowledge of the public script_pubkey/address, which is necessarily public since anyone can deposit. Such transactions are non-standard for relay but are consensus-valid when mined (0-value outputs are legal; miners can include their own transactions). The cost to an attacker is negligible, while each accepted phantom output is permanently reported by the scanner.

### Recommendation
Inside `Scanner::scan_transaction`, reject outputs whose `value.to_sat()` is below the spendable minimum:

```rust
if let Some(offset) = self.scripts.get(&output.script_pubkey) {
  if output.value.to_sat() < crate::wallet::DUST { continue; }
  res.push(ReceivedOutput { ... });
}
```

Note `DUST` is currently defined in `send.rs` [5](#0-4) ; it should be hoisted or referenced so both the send path and the scan path share the same threshold — the mirror of the report's recommended `balanceAfter > balanceBefore` fix.

### Proof of Concept
Conceptual: an attacker constructs a regtest/mainnet transaction with `TxOut { value: Amount::ZERO, script_pubkey: p2tr_script_buf(group_key).unwrap() }` and gets it mined. Calling `scanner.scan_transaction(&tx)` returns a `ReceivedOutput` with `value() == 0` [6](#0-5) , indistinguishable in kind from a genuine deposit and emitted as received funds despite contributing nothing spendable.

```rust
  pub fn scan_transaction(&self, tx: &Transaction) -> Vec<ReceivedOutput> {
    let mut res = Vec::new();
    for (vout, output) in tx.output.iter().enumerate() {
      // If the vout index exceeds 2**32, stop scanning outputs
      let Ok(vout) = u32::try_from(vout) else { break };

      if let Some(offset) = self.scripts.get(&output.script_pubkey) {
        res.push(ReceivedOutput {
          offset: *offset,
          output: output.clone(),
          outpoint: OutPoint::new(tx.compute_txid(), vout),
        });
      }
    }
    res
  }
```
