### Title
Inconsistent ACL enforcement in legacy Bank precompile `send()` bypasses tokenfactory `AllowList` and `BlockedAddr` restrictions - (File: precompiles/bank/legacy/v600/bank.go)

### Summary
The Bank precompile's `send()` handler is implemented in two structurally different ways across the codebase's version history. The current/latest implementation (`precompiles/bank/bank.go`) and mid-generation legacy versions (v601, v603, v605, v606, v610, v614, v620, v630, v640, v65, v66) build a `banktypes.MsgSend` and route it through `p.bankMsgServer.Send(...)`, which enforces `IsInDenomAllowList` for both sender and receiver and `BlockedAddr` for the receiver. However, an earlier lineage of legacy precompile versions (v552, v555, v562, v580, v600) calls `p.bankKeeper.SendCoins(...)` directly instead of the message server. `BaseSendKeeper.SendCoins` performs balance movement and receiver account creation only — it does **not** call `IsInDenomAllowList` or `BlockedAddr`, both of which are ACL checks that `msgServer.Send` enforces at [1](#0-0) . [2](#0-1) [3](#0-2) [4](#0-3) 

### Finding Description
Sei enforces tokenfactory denom-level access control ("AllowList") to restrict which addresses may hold or receive a `factory/...` denom — this is a first-class ACL primitive documented and tested at both the bank message-server layer and the keeper layer [5](#0-4) . This ACL is meant to be enforced uniformly for any coin transfer, analogous to how Consul was supposed to uniformly enforce ACLs "across all API endpoints" per CVE-2020-7955.

The Cosmos `MsgSend` handler correctly enforces this ACL by checking `IsInDenomAllowList` for both the sender and receiver, and `BlockedAddr` for the receiver, before calling `SendCoins`: [6](#0-5) 

The EVM Bank precompile is a second entry point into the same underlying balances, reachable by any EVM caller holding an ERC20-native-pointer contract for a tokenfactory denom. The current precompile correctly enforces the same ACL by routing through `bankMsgServer.Send` rather than calling `SendCoins` directly: [7](#0-6) 

However, several legacy precompile implementations retained in the codebase (`precompiles/bank/legacy/v552/bank.go`, `v555/bank.go`, `v562/bank.go`, `v580/bank.go`, `v600/bank.go`) call `p.bankKeeper.SendCoins(ctx, senderSeiAddr, receiverSeiAddr, ...)` directly, entirely skipping the `IsInDenomAllowList` / `BlockedAddr` checks: [8](#0-7) [9](#0-8) 

`BaseSendKeeper.SendCoins` itself contains no ACL enforcement — it only calls `SendCoinsWithoutAccCreation` and creates the receiver account if missing: [3](#0-2) 

The gate that is missing (`IsInDenomAllowList`, `BlockedAddr`) lives one layer up, in `msgServer.Send`/`MultiSend`, not in the shared `SendCoins` primitive: [10](#0-9) 

If any of these legacy precompile code paths remain live/dispatchable in a currently-running binary (e.g. selected via an upgrade-height precompile-version dispatcher, which is the pattern used throughout `precompiles/*/legacy/vNNN/` directories in this codebase for historical replay/consistency), an ERC20-native-pointer contract call into that legacy `send()` implementation would move tokenfactory-denom balances into or out of accounts that are explicitly excluded by a denom's `AllowList`, or into `BlockedAddr` addresses — completely bypassing the ACL that the Cosmos-native `MsgSend` path enforces.

### Impact Explanation
Tokenfactory `AllowList` is a supply-control/compliance primitive (e.g., KYC-gated or permissioned tokens) that token issuers rely on to restrict transferability to approved counterparties. A pointer-contract holder for such a denom could use the affected legacy Bank precompile `send()` path to transfer allow-listed tokens to or from addresses that are not in the `AllowList`, or to addresses on the `BlockedAddr` list (e.g., module or burn addresses), which is an authorization bypass enabling unauthorized transfer of restricted assets — directly matching this scan's "unauthorized transfer via precompile" impact class.

### Likelihood Explanation
Reachability depends on whether Sei's precompile version-dispatch mechanism (used to replay historical EVM execution exactly, per `evmrpc/AGENTS.md`'s consistency requirements) can still route a live transaction to one of these legacy `Precompile`/`PrecompileExecutor.send()` implementations rather than always using the current `precompiles/bank/bank.go` version. I was not able to conclusively determine from the index whether these legacy versions are dispatched only for historical replay/tracing (in which case the current impact would be limited to `debug_trace*` replay of already-committed state, not new fund movement) or whether they remain reachable for new transactions under some upgrade-height condition. This is the main uncertainty in this finding, and would need to be confirmed by inspecting the precompile version-selection/dispatch code (not found within the indexed context) before treating this as immediately exploitable on a live chain.

### Recommendation
Audit the precompile version-dispatch mechanism to confirm whether `precompiles/bank/legacy/v552`, `v555`, `v562`, `v580`, and `v600` `send()` implementations can still be invoked for new (non-replay) EVM transactions. If so, patch each of these legacy `send()` implementations to route through `bankMsgServer.Send` (as the current and later legacy versions do) instead of calling `bankKeeper.SendCoins` directly, so `IsInDenomAllowList` and `BlockedAddr` are enforced uniformly regardless of entry point (Cosmos `MsgSend`, current Bank precompile, or any live legacy Bank precompile version). If these versions are strictly for historical trace replay against already-committed state, document this explicitly and add a hard runtime assertion that they cannot be reached from `eth_sendRawTransaction`/live message execution.

### Proof of Concept
1. Token issuer creates a tokenfactory denom `factory/{issuer}/kyc` and sets `AllowList{Addresses: [addrA]}` via `MsgSetDenomMetadata`/allow-list configuration, per [11](#0-10) , so only `addrA` may hold/receive the denom.
2. `addrA` deploys/holds an ERC20-native-pointer contract for `factory/{issuer}/kyc` (`GetERC20NativePointer`).
3. If the chain is at (or replaying) an execution context that dispatches to one of the affected legacy Bank precompile versions (v552/v555/v562/v580/v600), the pointer contract calls the Bank precompile `send(from=addrA, to=addrB, denom="factory/{issuer}/kyc", amount)` where `addrB` is **not** in the `AllowList`.
4. Because that `send()` implementation calls `p.bankKeeper.SendCoins` directly (bypassing `IsInDenomAllowList`), the transfer succeeds and `addrB` receives allow-listed tokens, whereas the equivalent Cosmos `MsgSend` from `addrA` to `addrB` would be rejected with `"%s is not allowed to receive funds"` per [12](#0-11) .

func (k msgServer) Send(goCtx context.Context, msg *types.MsgSend) (*types.MsgSendResponse, error) {
	ctx := sdk.UnwrapSDKContext(goCtx)

	if err := k.IsSendEnabledCoins(ctx, msg.Amount...); err != nil {
		return nil, err
	}

	from, err := sdk.AccAddressFromBech32(msg.FromAddress)
	if err != nil {
		return nil, err
	}
	to, err := sdk.AccAddressFromBech32(msg.ToAddress)
	if err != nil {
		return nil, err
	}

	allowListCache := make(map[string]AllowedAddresses)
	if !k.IsInDenomAllowList(ctx, from, msg.Amount, allowListCache) {
		return nil, sdkerrors.Wrapf(sdkerrors.ErrUnauthorized, "%s is not allowed to send funds", msg.FromAddress)
	}

	if k.BlockedAddr(to) || !k.IsInDenomAllowList(ctx, to, msg.Amount, allowListCache) {
		return nil, sdkerrors.Wrapf(sdkerrors.ErrUnauthorized, "%s is not allowed to receive funds", msg.ToAddress)
	}

	err = k.SendCoins(ctx, from, to, msg.Amount)

func (p PrecompileExecutor) send(ctx sdk.Context, caller common.Address, method *abi.Method, args []interface{}, value *big.Int, readOnly bool) ([]byte, error) {
	if readOnly {
		return nil, errors.New("cannot call send from staticcall")
	}
	if err := pcommon.ValidateNonPayable(value); err != nil {
		return nil, err
	}

	if err := pcommon.ValidateArgsLength(args, 4); err != nil {
		return nil, err
	}
	denom := args[2].(string)
	if denom == "" {
		return nil, errors.New("invalid denom")
	}
	pointer, _, exists := p.evmKeeper.GetERC20NativePointer(ctx, denom)
	if !exists || pointer.Cmp(caller) != 0 {
		return nil, fmt.Errorf("only pointer %s can send %s but got %s", pointer.Hex(), denom, caller.Hex())
	}
	amount := args[3].(*big.Int)
	if amount.Cmp(utils.Big0) == 0 {
		// short circuit
		return method.Outputs.Pack(true)
	}
	senderSeiAddr, err := p.accAddressFromArg(ctx, args[0])
	if err != nil {
		return nil, err
	}
	receiverSeiAddr, err := p.accAddressFromArg(ctx, args[1])
	if err != nil {
		return nil, err
	}

	if err := p.bankKeeper.SendCoins(ctx, senderSeiAddr, receiverSeiAddr, sdk.NewCoins(sdk.NewCoin(denom, sdk.NewIntFromBigInt(amount)))); err != nil {
		return nil, err
	}

	return method.Outputs.Pack(true)
}

// IsInDenomAllowList checks if the given address is allowed to send the given coins.
// The check is performed only fot token factory denoms. For each token factory denom,
// it checks if there is allow list for the given denom. If there is no allow list,
// the address is allowed to send the coins. If there is an allow list, the address is
// allowed to send the coins only if it is in the allow list.
func (k BaseSendKeeper) IsInDenomAllowList(ctx sdk.Context, addr sdk.AccAddress, coins sdk.Coins, cache map[string]AllowedAddresses) bool {
	for _, coin := range coins {
		// Skip if denom does not contain the token factory prefix
		if !strings.HasPrefix(coin.Denom, TokenFactoryPrefix) {
			continue
		}

		allowedAddresses := k.getAllowedAddresses(ctx, cache, coin.Denom)
		// skip if there is no allow list for the denom
		if len(allowedAddresses.set) == 0 {
			continue
		}

		if !allowedAddresses.contains(addr) {
			return false
		}
	}
	return true
}

func (p PrecompileExecutor) send(ctx sdk.Context, caller common.Address, method *abi.Method, args []interface{}, value *big.Int, readOnly bool) ([]byte, uint64, error) {
	if readOnly {
		return nil, 0, errors.New("cannot call send from staticcall")
	}
	if err := pcommon.ValidateNonPayable(value); err != nil {
		return nil, 0, err
	}

	if err := pcommon.ValidateArgsLength(args, 4); err != nil {
		return nil, 0, err
	}
	denom := args[2].(string)
	if denom == "" {
		return nil, 0, errors.New("invalid denom")
	}
	pointer, _, exists := p.evmKeeper.GetERC20NativePointer(ctx, denom)
	if !exists || pointer.Cmp(caller) != 0 {
		return nil, 0, fmt.Errorf("only pointer %s can send %s but got %s", pointer.Hex(), denom, caller.Hex())
	}
	amount := args[3].(*big.Int)
	if amount.Cmp(utils.Big0) == 0 {
		// short circuit
		bz, err := method.Outputs.Pack(true)
		return bz, pcommon.GetRemainingGas(ctx, p.evmKeeper), err
	}
	senderSeiAddr, err := p.accAddressFromArg(ctx, args[0])
	if err != nil {
		return nil, 0, err
	}
	receiverSeiAddr, err := p.accAddressFromArg(ctx, args[1])
	if err != nil {
		return nil, 0, err
	}

	msg := &banktypes.MsgSend{
		FromAddress: senderSeiAddr.String(),
		ToAddress:   receiverSeiAddr.String(),
		Amount:      sdk.NewCoins(sdk.NewCoin(denom, sdk.NewIntFromBigInt(amount))),
	}

	err = msg.ValidateBasic()
	if err != nil {
		return nil, 0, err
	}

	if _, err = p.bankMsgServer.Send(sdk.WrapSDKContext(ctx), msg); err != nil {
		return nil, 0, err
	}

	bz, err := method.Outputs.Pack(true)
	return bz, pcommon.GetRemainingGas(ctx, p.evmKeeper), err
}
