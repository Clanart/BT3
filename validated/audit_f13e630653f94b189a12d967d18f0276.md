### Title
`ReceivedOutput::read` persists independently attacker-controlled offset, TxOut, and OutPoint anchors, letting `SignableTransaction`/`multisig` sign a sighash over mismatched prevout data - (File: networks/bitcoin/src/wallet/mod.rs)

### Summary
Analogous to the FastGPT flaw where a caller-supplied `datasetId` is persisted and later treated as an ownership anchor, `ReceivedOutput` binds together three independently deserialized fields — `offset`, `output` (script_pubkey + value), and `outpoint` — with no consistency check tying them to reality or to each other. `ReceivedOutput::read` accepts all three verbatim [1](#0-0) . Downstream code then makes authorization-equivalent decisions off different anchors: `SignableTransaction::new` builds `TxIn`s from `outpoint`, computes value/fee from `output`, and derives the signing key from `offset` [2](#0-1) , while `multisig` only checks `offset` against the *claimed* `script_pubkey`, never against the actual on-chain UTXO [3](#0-2) .

### Finding Description
- `ReceivedOutput::read` deserializes `offset` via `Secp256k1::read_F`, `TxOut` and `OutPoint` via `consensus_decode`, trusting all three [4](#0-3) .
- There is no binding that `outpoint` actually resolves to `output`, nor that `offset` came from `Scanner::register_offset`. `Scanner::scan_transaction` is the only producer that keeps them coherent, keyed by `script_pubkey` [5](#0-4) , yet the type is independently deserializable and is embedded in `Output::read` [6](#0-5) .
- `SignableTransaction::new` uses `input.outpoint` for the input, `input.output` for `prevouts`/value accounting, and `input.offset` for signing-key derivation [7](#0-6) [8](#0-7) .
- `multisig` anchors correctness only on `p2tr_script_buf(offset.group_key()) == prevouts[i].script_pubkey` — a check between two attacker-supplied fields [9](#0-8) .
- `Output::key` derives the owning key as `script_key - offset·G`, so a forged `offset` re-attributes a scanned-looking output to an arbitrary base key [10](#0-9) .

### Impact Explanation
An attacker who can feed bytes to `ReceivedOutput::read`/`Output::read` (a persisted or transmitted output record) creates a "mixed object": the identity anchor (`outpoint`, used by `Output::id`/`tx_id` [11](#0-10) ) points at a real UTXO belonging to anyone, while the spend anchor (`offset`, `TxOut`) claims arbitrary script/value. The FROST group then produces a valid Schnorr signature over a BIP-341 sighash committing to fabricated prevout data — signing an unintended message — and the wallet reports funds as received that are not spendable (the transaction is invalid on-chain or spends someone else's UTXO reference). A mischosen `offset` also mis-attributes ownership via `Output::key`, the cross-tenant analog.

### Likelihood Explanation
Medium. Exploitation requires attacker-controlled bytes reaching `ReceivedOutput::read`/`Output::read` rather than the self-consistent `Scanner` path; where that path exists (stored output records, coordinator-submitted outputs), no secret is needed — only a valid `OutPoint` of any UTXO plus a `TxOut` whose `script_pubkey` equals `p2tr(base_key + offset·G)` for the attacker-chosen `offset`. All checks the wallet performs are internal-consistency checks between attacker-controlled fields, so they always pass; failure surfaces only at broadcast.

### Recommendation
Make `ReceivedOutput` construction the only way to instantiate the type: have `read`/`Output::read` verify consistency (e.g., re-derive that `offset` yields a script the owning `Scanner` registered, or store the base key alongside and check `p2tr_script_buf(base + offset·G) == output.script_pubkey`), and have `SignableTransaction::new`/`multisig` confirm `prevouts[i]`/`outpoint` against chain data or a scanner-derived record rather than trusting the serialized tuple.

### Proof of Concept
1. Attacker picks any real on-chain `OutPoint` (a UTXO belonging to a third party) and a victim group base key `K` (public).
2. Attacker chooses `offset = o`, sets `TxOut.script_pubkey = p2tr(K + o·G)` with an arbitrary `value`, and serializes `ReceivedOutput { offset: o, output, outpoint }`.
3. `ReceivedOutput::read` accepts it; `Output::id`/`tx_id` anchor to the real UTXO; `Output::key()` returns `K`, attributing it to the victim group.
4. `SignableTransaction::new` builds a tx spending that outpoint with the fabricated value; `multisig(&keys.offset(o))` succeeds since `p2tr_script_buf(keys.offset(o).group_key())` equals the claimed script [9](#0-8) .
5. The threshold group signs a sighash over prevout data that does not match the real UTXO — a valid signature on an unintended, unbroadcastable transaction — while balance accounting credited `value` as received.

    let offset = Secp256k1::read_F(r)?;
    let output;
    let outpoint;
    {
      let mut buf_r = BufReader::with_capacity(0, r);
      output =
        TxOut::consensus_decode(&mut buf_r).map_err(|_| io::Error::other("invalid TxOut"))?;
      outpoint =
        OutPoint::consensus_decode(&mut buf_r).map_err(|_| io::Error::other("invalid OutPoint"))?;
    }
    Ok(ReceivedOutput { offset, output, outpoint })
  }

  pub fn scan_transaction(&self, tx: &Transaction) -> Vec<ReceivedOutput> {
    let mut res = Vec::new();
    for (vout, output) in tx.output.iter().enumerate() {
      // If the vout index exceeds 2**32, stop scanning outputs
      let Ok(vout) = u32::try_from(vout) else { break };

      if let Some(offset) = self.scripts.get(&output.script_pubkey) {
        res.push(ReceivedOutput {
          offset: *offset,
          output: output.clone(),
          outpoint: OutPoint::new(tx.compute_txid(), vout),
        });
      }
    }
    res
  }

  pub fn multisig(self, keys: &ThresholdKeys<Secp256k1>) -> Option<TransactionMachine> {
    let mut sigs = vec![];
    for i in 0 .. self.tx.input.len() {
      let offset = keys.clone().offset(self.offsets[i]);
