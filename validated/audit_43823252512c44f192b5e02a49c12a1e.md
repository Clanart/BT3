## Analysis

`Precompile.Execute` in `precompiles/bank/bank.go` never inspects `contract.Value()`, unlike `precompiles/erc20/erc20.go`, which explicitly rejects any call carrying `value > 0` with `ErrCannotReceiveFunds`: [1](#0-0) 

The bank precompile's `Execute` goes straight to `cmn.SetupABI` and dispatches to `Balances`, `TotalSupply`, or `SupplyOf` without any value check: [2](#0-1) 

All bank methods are query-type (`IsTransaction` always returns `false`), so a normal `CALL` (not `STATICCALL`) with `value > 0` and a valid selector (e.g., `balances(address)`) is accepted without any read-only conflict: [3](#0-2) [4](#0-3) 

The EVM is constructed with standard go-ethereum `core.CanTransfer`/`core.Transfer` semantics for the block context: [5](#0-4) 

Under normal go-ethereum `Call` semantics, the value transfer (moving balance from caller to the precompile address in the StateDB) is performed *before* the precompiled contract's `Run` is invoked, and is only rolled back if `Run` returns an error causing the call to revert. Since a valid `balances`/`totalSupply`/`supplyOf` call to the bank precompile succeeds (no error), the call does not revert, and the value transfer to the bank precompile address (`0x...0804`) becomes permanent.

The bank precompile exposes no method to move funds out of its own address — it is read-only (`Balances`, `TotalSupply`, `SupplyOf`) — and address `0x...0804` has no corresponding private key, so funds credited there through this path cannot be recovered by any subsequent transaction. This mirrors exactly the risk the erc20 precompile explicitly documents and guards against: [6](#0-5) [7](#0-6) 

By contrast, `werc20` explicitly handles a `payable` deposit and immediately sends the received value back to the caller via `BankKeeper.SendCoins`, avoiding any stranding: [8](#0-7) 

No equivalent guard or refund/recovery mechanism exists in `precompiles/bank/bank.go`, and no global/dispatcher-level check (e.g., in `x/vm/keeper/precompiles.go`) rejects nonzero-value calls into non-payable static precompiles: [9](#0-8) .

This is a legitimate design flaw: an unprivileged EOA/contract can `CALL` the bank precompile with `msg.value > 0` and a valid selector, and the call succeeds while the native value becomes permanently locked at an address with no owner and no withdrawal path.

### Title
Bank precompile fails to reject `msg.value`, permanently stranding native EVM balance at address 0x...0804 - (File: precompiles/bank/bank.go)

### Summary
`Precompile.Execute` in `precompiles/bank/bank.go` does not check `contract.Value()` before processing valid query calls, unlike the erc20 precompile which explicitly guards against this with `ErrCannotReceiveFunds`. A value-bearing `CALL` to the bank precompile with a valid selector succeeds, permanently locking the transferred native balance at the precompile address.

### Finding Description
Go-ethereum's standard `Call` semantics (used here via `core.CanTransfer`/`core.Transfer`) move `msg.value` from caller to callee in the StateDB before invoking the callee's code/`Run`. For precompiles, this transfer is only undone if `Run` returns an error causing the whole call to revert. The bank precompile's `Execute` dispatches valid method calls (`balances`, `totalSupply`, `supplyOf`) successfully regardless of `contract.Value()`, so the call does not revert and the value transfer persists. Because the bank precompile only implements read-only query methods and exposes no send/withdraw functionality, and address `0x...0804` has no private key, any value sent this way is unrecoverable by ordinary transaction flow.

### Impact Explanation
Funds sent by any unprivileged caller (EOA or contract) via a value-bearing call to the bank precompile are permanently and irreversibly locked, corresponding to a Critical, unauthorized, irreversible loss of user funds — the exact class of impact the erc20 precompile's `ErrCannotReceiveFunds` guard was designed to prevent.

### Likelihood Explanation
Trivially triggerable by any unprivileged user issuing a normal `CALL` with nonzero value and any valid bank method selector (e.g., `balances(address)`); no special privileges are required. The main mitigating factor is that most legitimate integrations wouldn't intentionally send value to a query-only precompile, but accidental sends (e.g., from generic multicall/proxy contracts that forward `msg.value`) are plausible.

### Recommendation
Add the same guard used in `precompiles/erc20/erc20.go` to `precompiles/bank/bank.go`'s `Execute`: reject any call where `contract.Value().Sign() == 1` with an error (causing the whole call to revert and the value transfer to be rolled back), consistent with all other non-payable precompiles.

### Proof of Concept
Deploy a test contract that performs `bankPrecompile.call{value: 1}(abi.encodeWithSelector(BALANCES_SELECTOR, someAddress))`. Because `balances` is a valid method and `Execute` never inspects `contract.Value()`, the call returns successfully; the caller's native balance decreases by 1, and the balance at `0x...0804` increases by 1 with no way to move it out afterward — confirming permanent, unauthorized loss of the sent value.

// Execute executes the precompiled contract bank query methods defined in the ABI.
func (p Precompile) Execute(ctx sdk.Context, contract *vm.Contract, readOnly bool) ([]byte, error) {
	method, args, err := cmn.SetupABI(p.ABI, contract, readOnly, p.IsTransaction)
	if err != nil {
		return nil, err
	}

	var bz []byte
	switch method.Name {
	// Bank queries
	case BalancesMethod:
		bz, err = p.Balances(ctx, method, args)
	case TotalSupplyMethod:
		bz, err = p.TotalSupply(ctx, method, args)
	case SupplyOfMethod:
		bz, err = p.SupplyOf(ctx, method, args)
	default:
		return nil, fmt.Errorf(cmn.ErrUnknownMethod, method.Name)
	}

	return bz, err
}

// SetupABI runs the initial setup required to run a transaction or a query.
// It returns the ABI method, initial gas and calling arguments.
func SetupABI(
	api abi.ABI,
	contract *vm.Contract,
	readOnly bool,
	isTransaction func(name *abi.Method) bool,
) (method *abi.Method, args []interface{}, err error) {
	// NOTE: This is a special case where the calling transaction does not specify a function name.
	// In this case we default to a `fallback` or `receive` function on the contract.

	// Simplify the calldata checks
	isEmptyCallData := len(contract.Input) == 0
	isShortCallData := len(contract.Input) > 0 && len(contract.Input) < 4
	isStandardCallData := len(contract.Input) >= 4

	switch {
	// Case 1: Calldata is empty
	case isEmptyCallData:
		method, err = emptyCallData(api, contract)

	// Case 2: calldata is non-empty but less than 4 bytes needed for a method
	case isShortCallData:
		method, err = methodIDCallData(api)

	// Case 3: calldata is non-empty and contains the minimum 4 bytes needed for a method
	case isStandardCallData:
		method, err = standardCallData(api, contract)
	}

	if err != nil {
		return nil, nil, err
	}

	// return error if trying to write to state during a read-only call
	if readOnly && isTransaction(method) {
		return nil, nil, vm.ErrWriteProtection
	}

// Deposit handles the payable deposit function. It retrieves the deposited amount
// and sends it back to the sender using the bank keeper.
func (p Precompile) Deposit(
	ctx sdk.Context,
	contract *vm.Contract,
	stateDB vm.StateDB,
) ([]byte, error) {
	caller := contract.Caller()
	depositedAmount := contract.Value()

	callerAccAddress := sdk.AccAddress(caller.Bytes())
	precompileAccAddr := sdk.AccAddress(p.Address().Bytes())

	// Send the coins back to the sender
	if err := p.BankKeeper.SendCoins(
		ctx,
		precompileAccAddr,
		callerAccAddress,
		sdk.NewCoins(sdk.Coin{
			Denom:  evmtypes.GetEVMCoinExtendedDenom(),
			Amount: math.NewIntFromBigInt(depositedAmount.ToBig()),
		}),
	); err != nil {
		return nil, err
	}

	if err := p.EmitDepositEvent(ctx, stateDB, caller, depositedAmount.ToBig()); err != nil {
		return nil, err
	}

	return nil, nil
}

// GetPrecompileInstance returns the address and instance of the static or dynamic precompile associated with the
// given address, or return nil if not found.
func (k *Keeper) GetPrecompileInstance(
	ctx sdktypes.Context,
	address common.Address,
) (*Precompiles, bool, error) {
	params := k.GetParams(ctx)
	// Get the precompile from the static precompiles
	if precompile, found, err := k.GetStaticPrecompileInstance(&params, address); err != nil {
		return nil, false, err
	} else if found {
		addressMap := make(map[common.Address]vm.PrecompiledContract)
		addressMap[address] = precompile
		return &Precompiles{
			Map:       addressMap,
			Addresses: []common.Address{precompile.Address()},
		}, found, nil
	}

	// Since erc20Keeper is optional, we check if it is nil, in which case we just return that we didn't find the precompile
	if k.erc20Keeper == nil {
		return nil, false, nil
	}

	// Get the precompile from the dynamic precompiles
	precompile, found, err := k.erc20Keeper.GetERC20PrecompileInstance(ctx, address)
	if err != nil || !found {
		return nil, false, err
	}
	addressMap := make(map[common.Address]vm.PrecompiledContract)
	addressMap[address] = precompile
	return &Precompiles{
		Map:       addressMap,
		Addresses: []common.Address{precompile.Address()},
	}, found, nil
}
