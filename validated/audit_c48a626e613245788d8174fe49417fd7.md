### Title
Consensus-incentive rewards are computed with the *current* `CostPerBlock` over the entire un-rewarded backlog, letting a relayer collect a retroactively inflated payout the instant governance raises the rate — (File: modules/pallets/consensus-incentives/src/impls.rs)

### Summary
`pallet-consensus-incentives` pays relayers `(latest_height - baseline) * CostPerBlock` on every accepted consensus proof, where `CostPerBlock` is read live from `StateMachinesCostPerBlock` at the moment of payout, not the rate that was in effect while each of those blocks was actually relayed/verified. This is the same broken invariant as the `RateLimit.configureCaller` bug: a configuration value change (`update_cost_per_block`) takes effect *instantly* and is applied to *all* unclaimed backlog in one shot, rather than only to blocks going forward from the change.

### Finding Description
`calculate_reward` computes the baseline from `LastRewardedHeight` (or `previous_commitment_height` as a fallback) and multiplies the full `blocks = latest_height - baseline` span by whatever `block_cost` is currently stored: [4](#0-3) 

`update_cost_per_block` overwrites `StateMachinesCostPerBlock` unconditionally and takes effect on the very next `process_message` call — there is no snapshotting of the rate per-height, no vesting/cooldown, and no bound on how large `blocks` can be before payout: [5](#0-4) 

`LastRewardedHeight` only advances *after* a successful reward, and `process_message` (called from `on_executed` for every accepted `ConsensusMessage`) pays out to whichever relayer's signature is recovered from the message: [6](#0-5) 

The consequence: if a chain's consensus updates go unclaimed for a stretch (no relayer bothers to submit, or the relayer intentionally withholds submission), a large backlog of blocks accumulates between `LastRewardedHeight` and the state machine's `latest_commitment_height`. If governance then raises `CostPerBlock` (a routine parameter tuning intended to affect *future* relaying), the very next proof submission pays the *entire backlog* at the new, higher rate — exactly like `configureCaller` granting an instantly usable allowance instead of gating it behind the interval it was meant to apply to.

### Impact Explanation
This is a direct, unbounded transfer out of `TreasuryAccount` that exceeds what governance intended when setting the new rate: the payout for blocks 1..N that were priced at the old (lower) rate is instead computed at the new rate. Because `blocks` is unbounded and the multiplication has no cap, the magnitude scales with however long the backlog was allowed to grow, i.e. potential large fund loss from the treasury to a single relayer for work that was priced differently at the time it happened. This satisfies the bounty's "stealing or loss of funds" / "logic attack" categories.

### Likelihood Explanation
No malicious peer, prover, or compromised key is required — any relayer permissionlessly delivering the next `ConsensusMessage` for a state machine collects the reward under `calculate_reward`'s current-rate-over-full-backlog formula. The only precondition is a backlog existing at the time governance updates `CostPerBlock`, which is a routine, expected operational event (rate tuning), not an attacker-controlled admin compromise. A relayer who notices governance is about to raise (or has just raised) the rate for a chain with a stale `LastRewardedHeight` has a pure economic incentive to be first to submit and capture the inflated backlog payout.

### Recommendation
Do not apply the live `CostPerBlock` to backlog accrued before the rate changed. Either:
- Snapshot/checkpoint the reward owed up to the block at which `update_cost_per_block` is called (force a settlement of `blocks_so_far * old_cost` and reset `LastRewardedHeight` to the current height as part of the governance call), so new rates only apply going forward; or
- Store cost-per-block changes with effective-height metadata and compute the reward as a sum over the piecewise rate history rather than a single multiplication by the current rate.

### Proof of Concept
1. Governance sets `StateMachinesCostPerBlock[chain] = 1` via `update_cost_per_block`.
2. No relayer submits a consensus proof for `chain` for a long period; `latest_commitment_height` advances by, say, 100,000 blocks past `LastRewardedHeight`/`previous_commitment_height`.
3. Governance raises the rate: `update_cost_per_block(chain, 1000)`.
4. A relayer immediately submits the next valid `ConsensusMessage` for `chain`. `on_executed` → `process_message` → `calculate_reward` computes `reward = 100_000 * 1000` instead of the intended `100_000 * 1` (or a mix reflecting the old rate for the backlog and the new rate only going forward).
5. `T::Currency::transfer` pays the relayer the inflated amount straight from `TreasuryAccount`, and `LastRewardedHeight` is bumped to `latest_height`, closing out the exploit with no trace of the mispriced backlog.

	fn process_message(
		state_machine_height: StateMachineHeight,
		state_machine_id: StateMachineId,
		relayer_account: T::AccountId,
	) -> Result<(), Error<T>> {
		if let Some(block_cost) = StateMachinesCostPerBlock::<T>::get(state_machine_id) {
			let reward = Self::calculate_reward(&state_machine_id, block_cost)?;

			if reward.is_zero() {
				return Ok(());
			}

			T::Currency::transfer(
				&T::TreasuryAccount::get().into_account_truncating(),
				&relayer_account,
				reward,
				Preservation::Expendable,
			)
			.map_err(|_| Error::<T>::RewardTransferFailed)?;

			Self::deposit_event(Event::<T>::RelayerRewarded {
				relayer: relayer_account.clone(),
				amount: reward,
				state_machine_height,
			});

			T::ReputationAsset::mint_into(&relayer_account, reward.saturated_into())
				.map_err(|_| Error::<T>::ReputationMintFailed)?;

			LastRewardedHeight::<T>::mutate(state_machine_id, |watermark| {
				*watermark = Some(watermark.unwrap_or_default().max(state_machine_height.height));
			});
		}
		Ok(())
	}

	/// Calculate the reward for a message based on the state machine id
	fn calculate_reward(
		state_machine_id: &StateMachineId,
		block_cost: <T as pallet_ismp::Config>::Balance,
	) -> Result<<T as pallet_ismp::Config>::Balance, Error<T>> {
		let host = <T::IsmpHost>::default();
		let latest_height = host
			.latest_commitment_height(state_machine_id.clone())
			.map_err(|_| Error::<T>::CouldNotGetStateMachineHeight)?;
		let previous_height =
			host.previous_commitment_height(state_machine_id.clone()).unwrap_or_default();

		// Use the rewarded watermark as the baseline and fall back to the previous height until
		// the first reward is recorded for this chain. The watermark only moves forward, so a
		// height that is rolled back and later resubmitted is not paid for a second time.
		let baseline = LastRewardedHeight::<T>::get(state_machine_id).unwrap_or(previous_height);

		let blocks = latest_height.saturating_sub(baseline);

		let blocks_as_balance: <T as pallet_ismp::Config>::Balance = blocks.saturated_into();
		let reward = blocks_as_balance.saturating_mul(block_cost);

		Ok(reward)
	}

		/// Update cost per block for a state machine
		#[pallet::call_index(0)]
		#[pallet::weight(T::WeightInfo::update_cost_per_block())]
		pub fn update_cost_per_block(
			origin: OriginFor<T>,
			state_machine_id: StateMachineId,
			cost_per_block: <T as pallet_ismp::Config>::Balance,
		) -> DispatchResult {
			T::IncentivesOrigin::ensure_origin(origin)?;

			StateMachinesCostPerBlock::<T>::mutate(state_machine_id.clone(), |maybe_cost| {
				*maybe_cost = Some(cost_per_block);
			});

			Self::deposit_event(Event::<T>::StateMachineCostPerBlockUpdated {
				state_machine_id,
				cost_per_block,
			});

			Ok(())
		}
