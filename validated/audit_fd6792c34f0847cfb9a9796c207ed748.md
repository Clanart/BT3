### Title
One withdrawal_utxo shared by two withdrawal indices lets a single payout tx credit an operator twice - ([File: core/src/database/verifier.rs])

### Summary
The Citrea Bridge `withdraw` call lets an unprivileged caller register the same `input_outpoint` bytes for two distinct `withdrawal_id`/deposit indices `i != j`. Clementine's sync code writes that outpoint into both `withdrawals` rows without any uniqueness check, and `Database::get_payout_txs_for_withdrawal_utxos` joins on `(withdrawal_utxo_txid, withdrawal_utxo_vout)`, so a single confirmed payout transaction spending that one outpoint produces two `(idx, payout_txid)` rows, both crediting the same operator's `xonly_pk` via `update_payout_txs_and_payer_operator_xonly_pk`.

### Finding Description
Binding claimed: for a real Bitcoin UTXO spent by payout transaction `P`, `count(distinct idx credited with payout_txid == P) == 1`.

Trace:
- `Verifier::update_citrea_deposit_and_withdrawals` (`core/src/verifier.rs:2248-2262`) iterates `new_withdrawals` returned by `CitreaClientT::collect_withdrawal_utxos` (`core/src/citrea.rs:458-496`) and calls `Database::update_withdrawal_utxo_from_citrea_withdrawal(idx, withdrawal_utxo, ...)` unconditionally for each `idx` [1](#0-0) .
- `update_withdrawal_utxo_from_citrea_withdrawal` performs a bare `UPDATE withdrawals SET withdrawal_utxo_txid=$2, withdrawal_utxo_vout=$3 ... WHERE idx=$1` with no check that the outpoint is not already assigned to a different `idx` [2](#0-1) .
- The `withdrawals` table schema has no `UNIQUE` constraint on `(withdrawal_utxo_txid, withdrawal_utxo_vout)`, only `idx` is a primary key [3](#0-2) .
- Because the Citrea Bridge contract (out-of-scope third-party contract) does not reject a caller registering an already-used outpoint for a different withdrawal id, the attacker can drive both `withdrawals[i]` and `withdrawals[j]` to the identical `withdrawal_utxo_txid/vout`.
- Once any operator legitimately fronts one real payout for one of these indices, and that transaction confirms and is observed spending the shared outpoint (`bitcoin_syncer_spent_utxos`), `get_payout_txs_for_withdrawal_utxos` joins `bsu.txid = w.withdrawal_utxo_txid AND bsu.vout = w.withdrawal_utxo_vout` and returns **both** `(i, P)` and `(j, P)` [4](#0-3) .
- `Verifier::update_finalized_payouts` consumes exactly this list and, for every returned `(idx, payout_txid)`, extracts the operator xonly pk from `P`'s OP_RETURN and pushes `(idx, payout_txid, operator_xonly_pk, block_hash)` for both `i` and `j` into `update_payout_txs_and_payer_operator_xonly_pk` [5](#0-4) , which does a batched `UPDATE ... FROM (VALUES ...) WHERE w.idx = c.idx` — writing the payer's `xonly_pk` and `payout_tx_blockhash` into both rows [6](#0-5) .
- Later, `PayoutCheckerTask::run_once` independently discovers each unhandled payout via `get_first_unhandled_payout_by_operator_xonly_pk` (keyed by `idx`, not by `payout_txid`) and calls `Operator::handle_finalized_payout` per index to start the kickoff/reimbursement process for that deposit [7](#0-6) . `Verifier::is_kickoff_malicious` validates each kickoff purely against the per-`move_txid` `payout_info` row (operator pk match + committed blockhash match) [8](#0-7) , and since both rows `i` and `j` now independently carry consistent `payout_payer_operator_xonly_pk`/`payout_tx_blockhash` values, this check passes for **both** deposits even though only one Bitcoin UTXO was ever actually spent to front a withdrawal.

Root cause: the system infers "withdrawal `idx` was fronted by operator `pk`" solely from an on-chain UTXO spend matched by `(txid, vout)`, but that UTXO location is not enforced to be unique per `withdrawals.idx`. No code path (`is_deposit_valid`, `is_profitable`, `SECP.verify_schnorr`, DB constraints) checks cross-index uniqueness of `withdrawal_utxo_txid/vout`.

### Impact Explanation
Both deposit `i` and deposit `j` are distinct vault deposits (each locking `bridge_amount` BTC). After the collision, the operator that fronted the single real payout can drive the kickoff/reimbursement state machine for **both** deposit indices — because verifiers' `is_kickoff_malicious` check passes for both — and pull BTC from the Reimburse output of the presigned tx graph for both deposits, while having only actually paid one withdrawal recipient once. This is "an operator reimbursed for a payout it never funded," a listed Critical impact: BTC leaves a deposit's reimbursement path without a matching fronted withdrawal for that specific deposit. The attack is repeatable per distinct pair of deposits the attacker (or a colluding withdrawer) controls, and works against any operator, since the crediting logic is agnostic to which operator processed which specific `idx`.

### Likelihood Explanation
Preconditions: the attacker needs two already-vaulted deposits (own funds, standard deposit flow) and the ability to call the Citrea Bridge `withdraw` contract function twice with attacker-chosen `input_outpoint` bytes for two different withdrawal ids — explicitly granted in the threat model ("choose the bytes of a withdrawal UTXO"). No verifier/operator/aggregator privilege, key share, or collateral is required from the attacker. Cost is limited to normal deposit amounts and Bitcoin fees for the single payout transaction; the extra reimbursement is realized by whichever operator processes the (shared) withdrawal, meaning this either requires operator complicity to profit financially, or, absent complicity, still produces a state where verifiers will co-sign a kickoff for a deposit that was never really fronted — a protocol invariant violation exploitable purely by the unprivileged attacker's registration action, independent of any operator's intent.

### Recommendation
Enforce uniqueness of `(withdrawal_utxo_txid, withdrawal_utxo_vout)` across the `withdrawals` table (e.g., add a partial unique index and reject/flag conflicting `update_withdrawal_utxo_from_citrea_withdrawal` calls), and change `get_payout_txs_for_withdrawal_utxos` / `update_finalized_payouts` to only credit a payout to a single winning `idx` per physical UTXO spend (e.g., first-registered `idx` wins, or require the payout tx's OP_RETURN/output to bind to the specific `deposit_id`/`idx` it's fronting and verify that binding before crediting).

async fn duplicate_withdrawal_utxo_causes_double_credit() {

    let db = Database::new(&config).await.unwrap();

        txid: bitcoin::Txid::from_byte_array([0x11; 32]),
        vout: 0,
    };
    let payout_txid = Txid::from_byte_array([0x99; 32]);
    let move_txid_i = Txid::from_byte_array([0xAA; 32]);
    let move_txid_j = Txid::from_byte_array([0xBB; 32]);
    let (idx_i, idx_j) = (0u32, 1u32);

    let block_id = db.insert_block_info(Some(&mut dbtx), &BlockHash::all_zeros(), &BlockHash::all_zeros(), 0).await.unwrap();
    db.insert_txid_to_block(&mut dbtx, block_id, &payout_txid).await.unwrap();
    db.insert_spent_utxo(&mut dbtx, block_id, &payout_txid, &shared_utxo.txid, shared_utxo.vout.into()).await.unwrap();

    // Two distinct deposits...
    db.upsert_move_to_vault_txid_from_citrea_deposit(Some(&mut dbtx), idx_i, &move_txid_i).await.unwrap();
    db.upsert_move_to_vault_txid_from_citrea_deposit(Some(&mut dbtx), idx_j, &move_txid_j).await.unwrap();

    // ...but attacker registers the SAME withdrawal_utxo bytes for both withdrawal indices
    db.update_withdrawal_utxo_from_citrea_withdrawal(Some(&mut dbtx), idx_i, shared_utxo, block_id).await.unwrap();
    db.update_withdrawal_utxo_from_citrea_withdrawal(Some(&mut dbtx), idx_j, shared_utxo, block_id).await.unwrap();

    // Simulate Verifier::update_finalized_payouts observing the single confirmed payout tx
    let rows = db.get_payout_txs_for_withdrawal_utxos(Some(&mut dbtx), block_id).await.unwrap();

    // BINDING: exactly one idx should be credited per real UTXO spend.
    assert_eq!(rows.len(), 1, "expected exactly one (idx, payout_txid) row for one real BTC spend, got {rows:?}");
}

    pub async fn update_payout_txs_and_payer_operator_xonly_pk(
        &self,
        tx: Option<DatabaseTransaction<'_>>,
        payout_txs_and_payer_operator_xonly_pk: Vec<(
            u32,
            Txid,
            Option<XOnlyPublicKey>,
            bitcoin::BlockHash,
        )>,
    ) -> Result<(), BridgeError> {
        if payout_txs_and_payer_operator_xonly_pk.is_empty() {
            return Ok(());
        }
        // Convert all values first, propagating any errors
        let converted_values: Result<Vec<_>, BridgeError> = payout_txs_and_payer_operator_xonly_pk
            .iter()
            .map(|(idx, txid, operator_xonly_pk, block_hash)| {
                Ok((
                    i32::try_from(*idx).wrap_err("Failed to convert payout index to i32")?,
                    TxidDB(*txid),
                    operator_xonly_pk.map(XOnlyPublicKeyDB),
                    BlockHashDB(*block_hash),
                ))
            })
            .collect();
        let converted_values = converted_values?;

        let mut query_builder = QueryBuilder::new(
            "UPDATE withdrawals AS w SET
                payout_txid = c.payout_txid,
                payout_payer_operator_xonly_pk = c.payout_payer_operator_xonly_pk,
                payout_tx_blockhash = c.payout_tx_blockhash
                FROM (",
        );

        query_builder.push_values(
            converted_values.into_iter(),
            |mut b, (idx, txid, operator_xonly_pk, block_hash)| {
                b.push_bind(idx)
                    .push_bind(txid)
                    .push_bind(operator_xonly_pk)
                    .push_bind(block_hash);
            },
        );

        query_builder
            .push(") AS c(idx, payout_txid, payout_payer_operator_xonly_pk, payout_tx_blockhash) WHERE w.idx = c.idx");

        let query = query_builder.build();
        execute_query_with_tx!(self.connection, tx, query, execute)?;

        Ok(())
    }

#[async_trait]
impl<C> Task for PayoutCheckerTask<C>
where
    C: CitreaClientT,
{
    type Output = bool;
    const VARIANT: TaskVariant = TaskVariant::PayoutChecker;

    async fn run_once(&mut self) -> Result<Self::Output, BridgeError> {
        let mut dbtx = self.db.begin_transaction().await?;
        let unhandled_payout = self
            .db
            .get_first_unhandled_payout_by_operator_xonly_pk(
                Some(&mut dbtx),
                self.operator.signer.xonly_public_key,
            )
            .await?;

        if unhandled_payout.is_none() {
            return Ok(false);
        }

        let (citrea_idx, move_to_vault_txid, payout_tx_blockhash) =
            unhandled_payout.expect("Must be Some");

        tracing::info!(
            "Unhandled payout found for withdrawal {}, move_txid: {}",
            citrea_idx,
            move_to_vault_txid
        );

        let deposit_data = self
            .db
            .get_deposit_data_with_move_tx(Some(&mut dbtx), move_to_vault_txid)
            .await?;
        if deposit_data.is_none() {
            return Err(eyre::eyre!("Fronted withdrawal for move tx {move_to_vault_txid} found, but the signatures for the deposit are not found in the db.").into());
        }

        let deposit_data = deposit_data.expect("Must be Some");

        let kickoff_txid = self
            .operator
            .handle_finalized_payout(
                &mut dbtx,
                deposit_data.get_deposit_outpoint(),
                payout_tx_blockhash,
            )
            .await?;

        // fetch and save the LCP for if we get challenged and need to provide proof of payout later
        let (_, payout_block_height) = self
            .operator
            .db
            .get_block_info_from_hash(Some(&mut dbtx), payout_tx_blockhash)
            .await?
            .ok_or_eyre("Couldn't find payout blockhash in bitcoin sync")?;

        let _ = self
            .operator
            .citrea_client
            .fetch_validate_and_store_lcp(
                payout_block_height as u64,
                citrea_idx,
                &self.operator.db,
                Some(&mut dbtx),
                self.operator.config.protocol_paramset(),
            )
            .await?;

        #[cfg(feature = "automation")]
        self.operator.end_round(&mut dbtx).await?;

        self.db
            .mark_payout_handled(Some(&mut dbtx), citrea_idx, kickoff_txid)
            .await?;

        dbtx.commit().await?;

        Ok(true)
    }
