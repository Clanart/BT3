### Title
Bandwidth allowance is irrevocably drained on failed/misrouted requests, and replay-by-design lets the drain repeat - ([File: parachain/runtimes/gargantua/src/ismp.rs])

### Summary
The external report's core defect is an **"event-based" authorization**: a boolean/control-flow check (`result.success`) gates a sensitive, stateful action, but the check and the state mutation it protects are not atomically bound together — so the mutation can be applied even when the thing it was supposed to gate never actually completes. The same pattern exists in Hyperbridge's bandwidth-metering path: `pallet-bandwidth`'s `BandwidthGate::try_consume` mutates the paid byte allowance *before* the request is successfully routed to its destination module, and if routing subsequently fails, ISMP's batch-request handler does not roll back that mutation — it only deletes the request receipt so the message can be replayed. The allowance is gone; the message was never delivered; and the failure mode is specifically designed to allow resubmission, so the same paid-for bandwidth can be drained again on every retry.

### Finding Description
`ProxyModule::on_accept` consumes bandwidth unconditionally (for non-purchase messages) as the very first step, before it even knows whether the request can be routed to a real destination module: [1](#0-0) 

```rust

        id if id == ModuleId::Pallet(pallet_bandwidth::pallet::PALLET_BANDWIDTH) => ...,
        pallet_hyper_fungible_token::PALLET_ID => ...,
        _ => Err(anyhow!("Destination module not found")),

```

`try_consume` is a real state mutation, not a read-only check: it decrements `remaining_bytes` on the FIFO `Allowance` list (a byte balance the app actually paid BRIDGE for) and pops exhausted subscriptions: [2](#0-1) 

Once `try_consume` succeeds, the function proceeds to resolve `request.to` into a `ModuleId` and dispatch to the destination pallet. If `request.to` doesn't match a known pallet (`_ => Err(anyhow!("Destination module not found"))`), or if the destination module's own `on_accept` fails, the whole `on_accept` call returns `Err` — **after** the bandwidth was already spent.

The ISMP core request handler's per-request error path only deletes the receipt (to permit a retry) — it does not compensate or restore any state the failed `on_accept` already mutated, and the overall batch-processing function does not abort the extrinsic on a per-item failure: [3](#0-2)

Because the collected per-request results are folded into `MessageResult::Request { events: result, weight }` rather than causing the surrounding extrinsic to return an overall `Err`, the extrinsic commits — including the bandwidth-gate's storage mutation for the failed item. The protocol's own documentation confirms this design intent (deliberately allowing replay after a failed `on_accept`), but only discusses receipts/state, not the fact that upstream router-level side effects (bandwidth) are exempt from this replay-safety: [4](#0-3) 

### Impact Explanation
An app's bandwidth allowance is a purchased asset (BRIDGE-denominated, see `docs/content/developers/evm/bandwidth/overview.mdx`). Because `try_consume` runs unconditionally ahead of routing, and a failed route deletes the receipt specifically to enable **replay**, any unprivileged relayer can repeatedly submit a request whose `from` matches a funded app but whose `to` is garbage (or whose destination module rejects it), draining that app's entire prepaid `Allowance` bucket to zero without a single message ever being delivered. This is a direct "bandwidth balances must move exactly once and only to the rightful beneficiary" violation from the Impact Gate: bandwidth moves to nobody, repeatedly, purely from resubmitting a malformed/unroutable request that the protocol itself is designed to let be replayed.

### Likelihood Explanation
No privileged actor, malicious relayer/prover, or leaked key is required. Submitting an ISMP request through the standard relayer path with a legitimate `from` (the target app's module id) and an unroutable/garbage `to` is an entirely public, unprivileged action — the relayer only needs to construct and submit a valid membership proof for the request, which the request handler happily accepts and routes into `on_accept` before the failure occurs. The failure is then designed to be retried indefinitely (receipt deleted), making repeated draining trivial.

### Recommendation
Make bandwidth consumption conditional on routing success, or make the whole `on_accept` execution (including the gate mutation) transactional so it is rolled back whenever the downstream dispatch/module lookup fails. Concretely: move the `try_consume` call to run only after the destination module is resolved and its own `on_accept` call has returned `Ok`, or wrap the entire `ProxyModule::on_accept` body in a `#[transactional]`/`with_storage_layer` block so a downstream `Err` (unknown module, module-level failure) reverts the bandwidth deduction along with everything else.

### Proof of Concept
1. Fund `pallet-bandwidth`'s `Allowance` for `(source_chain, app)` via the normal purchase flow (`BandwidthManager.purchase()` → `pallet-bandwidth::on_accept`).
2. As any relayer, submit a `RequestMessage` whose `PostRequest.from == app` (the funded module id) and `to` set to bytes that do not decode into any known `ModuleId` (or to a pallet id whose own `on_accept` will reject the payload), with a valid membership proof for that request.
3. `ProxyModule::on_accept` runs `try_consume` first (bandwidth decremented, `BandwidthConsumed` event emitted), then fails to route (`Destination module not found` or a downstream `on_accept` error).
4. `modules/ismp/core/src/handlers/request.rs` catches the `Err`, deletes the request receipt, and the overall extrinsic still succeeds — the bandwidth deduction is committed.
5. Because the receipt was deleted, the identical request commitment can be resubmitted (or a new nonce'd garbage request created) and step 2–4 repeated until `Allowance` for `(source, app)` is fully drained, with zero requests ever successfully delivered to the app.

impl<T: Config> BandwidthGate for Pallet<T> {
	fn try_consume(
		source: &ismp::host::StateMachine,
		app: &[u8],
		bytes: u32,
	) -> Result<(), GateError> {
		let key = AppKey::truncate_from(app.to_vec());
		if Allowlist::<T>::contains_key(source, &key) {
			return Ok(());
		}

		let need: u128 = bytes.into();
		let now = <T as pallet_ismp::Config>::TimestampProvider::now().as_secs();

		let total = pallet::Allowance::<T>::mutate(source, &key, |list| {
			// Sweep expired in-place. Order-preserving.
			list.retain(|s| s.expires_at > now);

			if list.is_empty() {
				return Err(GateError::NoAllowance);
			}

			let total: u128 = list.iter().map(|s| s.remaining_bytes).sum();
			if total < need {
				return Err(GateError::Insufficient { remaining: total, required: need });
			}

			// Drain from the front in insertion order. Once a sub is
			// fully consumed, pop it and continue with the next.
			// `get_mut` defends against a malformed list that satisfies
			// the `total >= need` precheck but is structurally empty;
			// we'd otherwise panic via `list[0]`.
			let mut left = need;
			while left > 0 {
				let Some(head) = list.get_mut(0) else {
					return Err(GateError::NoAllowance);
				};
				let take = head.remaining_bytes.min(left);
				head.remaining_bytes = head.remaining_bytes.saturating_sub(take);
				left = left.saturating_sub(take);
				if head.remaining_bytes == 0 {
					list.remove(0);
				}
			}

			Ok(total)
		})?;

		Self::deposit_event(Event::BandwidthConsumed {
			source: *source,
			app: key,
			bytes: need,
			remaining: total - need,
		});
		Ok(())
	}

It's important to note that if the `IsmpModule::on_accept` does not return `Ok`, the receipt of this request will not be persisted, allowing the request to be **replayed**. Consequently, the `IsmpModule` is responsible for maintaining all invariants before modifying it's internal state to prevent partial state changes that could result in critical vulnerabilities in their request handler. This model ensures that if a request cannot be executed successfully on a destination state machine, it can time out gracefully on the source.
