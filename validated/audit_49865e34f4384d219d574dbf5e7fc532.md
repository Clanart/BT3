### Title
`WombatBribeManager` swaps bribe fee tokens for BNB with hardcoded zero minimum return, exposing funds to sandwich attacks - (File: wombat/WombatBribeManager.sol)

### Summary
`WombatBribeManager._swapFeesForBnb` calls `IBNBZapper(PancakeZapper).zapInToken` with `minRec` hardcoded to `0`, meaning any swap of bribe reward tokens to BNB performed during vote-casting has no slippage protection whatsoever, allowing MEV searchers to sandwich the trade and extract value that should go to the caller.

### Finding Description
`castVotes` (reachable via the public/external `voteAndCast` and `castVotesAndClaimBribes` functions, callable by any unprivileged wallet) optionally swaps collected bribe fee tokens for BNB when `swapForBnb` is `true`. This path funnels into `_swapFeesForBnb`, which for every non-zero fee amount calls the zapper with a minimum-received amount fixed at `0`: [1](#0-0) 

That zero value is passed straight through to `PancakeRouter.swapExactTokensForETH` inside `BNBZapper._swapTokenForBNB`, which enforces no minimum output: [2](#0-1) 

This is functionally identical to the reported bug class: a contract that frequently swaps tokens through an AMM without specifying an estimated/minimum return amount, letting MEV searchers sandwich the trade. `BNBZapper` even exposes a `previewAmount`/`previewTotalAmount` helper that could be used to compute a reasonable `minRec` off-chain, but `WombatBribeManager` never uses it and hardcodes `0` instead: [3](#0-2) 

The entry points are unprivileged and public: [4](#0-3) [5](#0-4) 

### Impact Explanation
Any wallet calling `voteAndCast(..., swapForBnb=true)` or `castVotesAndClaimBribes(..., swapForBnb=true)` triggers an on-chain swap of the accumulated bribe fee tokens for BNB with zero minimum output. An MEV searcher monitoring the mempool can sandwich this transaction, front-running to move the price against the swap and back-running to capture the difference, directly stealing value out of protocol-held bribe fees that would otherwise be delivered to the caller as their vote-casting incentive. This is a direct, quantifiable loss of user/protocol funds triggered purely by normal, permissionless usage of the voting/bribe-claim flow.

### Likelihood Explanation
`castVotes` with `swapForBnb=true` is intended to be called routinely (it is the standard incentive mechanism for keeping votes up to date), and the fee amounts accumulate over time before being swept, making the trade sizes and the resulting sandwich opportunity substantial and predictable. Because the code path is fully permissionless and unprivileged (`voteAndCast`, `castVotesAndClaimBribes`), any ordinary MGP voter triggers the vulnerable swap, and any MEV bot watching the mempool can exploit it deterministically — no privileged access or unusual conditions required.

### Recommendation
Do not hardcode `minRec = 0` in `_swapFeesForBnb`. Compute an expected output via `BNBZapper.previewAmount`/`previewTotalAmount` (or an on-chain TWAP/oracle) and apply a configurable slippage tolerance to derive a non-zero minimum, or allow the caller to supply a `minRec` parameter (with a sane on-chain lower bound check) so the swap reverts if returns fall outside acceptable slippage.

### Proof of Concept
1. Bribe fee tokens accumulate in `WombatBribeManager` from `castVotes`.
2. Any wallet calls `voteAndCast(lps, deltas, true)` or `castVotesAndClaimBribes(lps, true)`.
3. This invokes `_swapFeesForBnb`, which calls `IBNBZapper(PancakeZapper).zapInToken(token, feeAmount, 0, msg.sender)` — see [6](#0-5) .
4. `BNBZapper._swapTokenForBNB` executes `ROUTER.swapExactTokensForETH(amount, 0, path, receiver, block.timestamp)` — see [7](#0-6) .
5. An MEV bot observing the pending transaction front-runs with a buy to move the pool price, lets the zero-slippage swap execute at the worse price, then back-runs with a sell, capturing the price difference at the expense of the swap's output that should have gone to `msg.sender`.

    function _swapFeesForBnb(address[][] memory rewardTokens, uint256[][] memory feeAmounts)
        internal
        returns (uint256 bnbAmount)
    {
        if(PancakeZapper == address(0)) revert PancakeZapperNotSet();
        uint256 bribeLength = rewardTokens.length;
        for (uint256 i; i < bribeLength; i++) {
            uint256 rewardLength = rewardTokens[i].length;
            for (uint256 j; j < rewardLength; j++) {
                if (rewardTokens[i][j] != address(0) && feeAmounts[i][j] > 0) {
                    _approveTokenIfNeeded(rewardTokens[i][j], PancakeZapper, feeAmounts[i][j]);
                    bnbAmount += IBNBZapper(PancakeZapper).zapInToken(
                        rewardTokens[i][j],
                        feeAmounts[i][j],
                        0,
                        msg.sender
                    );
                }
            }
        }
    }
