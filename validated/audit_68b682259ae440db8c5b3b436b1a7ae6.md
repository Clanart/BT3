### Title
Permissionless Pointer Creation Trusts Unverified CW20/CW721/CW1155 Contract Interfaces - ([File: precompiles/pointer/pointer.go])

### Summary
The `pointer` precompile (`0x000000000000000000000000000000000000100b`) lets **any caller** create an ERC20/ERC721/ERC1155 pointer contract for an arbitrary CosmWasm contract address via `addCW20Pointer`, `addCW721Pointer`, and `addCW1155Pointer`. The only "validation" performed is a single smart query (`token_info` or `contract_info`) checked for the presence of `name`/`symbol` fields; there is no verification that the target contract actually implements the full CW20/CW721/CW1155 message/query interface it is later trusted to expose (`transfer`, `transfer_from`, `balance`, `allowance`, `mint`, etc.). This mirrors the reported Allo.sol issue: strategy/pointer registration accepts arbitrary contract addresses without validating interface conformance, and later state-changing calls are blindly forwarded to that contract.

### Finding Description
`AddCW20` in `precompiles/pointer/pointer.go` (and its legacy variants) resolves the bech32 address, issues a `wasmdKeeper.QuerySmart(ctx, cwAddress, {"token_info":{}})` call, and only checks that the JSON response has `name`/`symbol` keys before deploying an `ERC20`-style pointer contract that will be trusted by every downstream EVM consumer: [1](#0-0) 
`AddCW721` performs an analogous `contract_info` check: [2](#0-1) 
`AddCW1155` similarly only checks `contract_info`: [3](#0-2) 

None of these functions restrict who may call them — any EVM transaction sender or CosmWasm user can register a pointer for a contract they authored themselves. The generated pointer contract (`CW20ERC20Pointer.sol`) unconditionally forwards `transfer`, `transferFrom`, and `approve` calls to the underlying CW address via the wasmd precompile, trusting that the CW contract executes the standard CW20 semantics (moving balances, updating allowances) correctly: [4](#0-3) 

Because only `token_info`/`contract_info` is checked, an attacker can deploy a CosmWasm contract that answers `token_info`/`contract_info` with a plausible `name`/`symbol` but implements broken or malicious logic for `transfer`, `transfer_from`, `balance`, or `allowance` (e.g., silently no-op transfers, always-succeeding no-effect execute messages, or asymmetric balance updates). Registering the pointer for such a contract is fully permissionless, so the resulting ERC20/ERC721/ERC1155 pointer — which looks and behaves like a normal token from the ABI/interface perspective — will be trusted by EVM-side integrations (wallets, DEXs, bridges) that rely on standard ERC-20/721/1155 semantics.

Additionally, the field extraction itself is unsafe: `formattedRes["name"].(string)` and `formattedRes["symbol"].(string)` are unchecked type assertions. If a CW contract's `token_info`/`contract_info` response omits these fields or returns a non-string type, the assertion panics (`interface conversion: interface {} is nil, not string`). Unlike other precompiles (e.g. `precompiles/addr/addr.go`, `precompiles/slashing/legacy/v67/slashing.go`) which install a `defer recover()` inside their `Execute` dispatcher, the pointer executor's `AddCW20`/`AddCW721`/`AddCW1155` functions do not appear to wrap this logic in a local recover; the only recovery available is whatever exists further up the call chain (e.g. cosmos-sdk's `baseapp.runTx` panic handling), so the practical blast radius of this path could not be fully confirmed from the indexed code.

### Impact Explanation
The primary, confidently reachable impact is the same class described in the source report: **funds lockup / loss of tokens** for anyone who interacts with a pointer contract wrapping a non-conformant CW20/CW721/CW1155 contract. Because pointer creation is permissionless and validation is limited to a metadata query, a malicious actor can create pointer tokens whose `transfer`/`transferFrom`/`balance` behavior diverges from what ERC20/721/1155 consumers assume, leading to stuck balances, incorrect accounting, or unusable approvals for victims who trust the pointer as a standard token.

### Likelihood Explanation
High. Any address can call `addCW20Pointer`/`addCW721Pointer`/`addCW1155Pointer` on the pointer precompile with a bech32 address of a CosmWasm contract of their own design (deploying such a contract via wasmd is itself an unprivileged action), so no special access is required to exploit this weakness.

### Recommendation
Before registering a pointer, validate that the target contract implements more than the metadata query: perform additional smart queries/dry-run executions corresponding to the full expected CW20/CW721/CW1155 interface (e.g. `balance`, `allowance`, and a harmless `transfer`/no-op check), and reject registration if any required message is unsupported or behaves unexpectedly. Also replace the unchecked type assertions (`formattedRes["name"].(string)`) with safe, checked assertions that return an explicit error rather than panicking when fields are missing or of the wrong type.

### Proof of Concept
1. Deploy a CosmWasm contract whose `query { token_info {} }` handler returns a valid `{name, symbol, decimals, total_supply}` JSON (satisfying `AddCW20`'s check) but whose `execute { transfer {...} }` handler is a no-op (always returns `Ok` without moving any balance), matching the structure exercised in `precompiles/pointer/legacy/v552/pointer.go` lines 196-224 and `contracts/src/CW20ERC20Pointer.sol` lines 79-96.
2. Call `addCW20Pointer(cwAddr)` on the pointer precompile at `0x000000000000000000000000000000000000100b` — this succeeds because only `token_info` is checked.
3. Any EVM user calling `transfer`/`transferFrom` on the resulting pointer ERC20 contract believes tokens moved (transaction succeeds), but the underlying CW20 balance never actually changes, resulting in fund loss/lockup for the victim relying on the pointer's ERC20 semantics.

func (p Precompile) AddCW20(ctx sdk.Context, method *ethabi.Method, caller common.Address, args []interface{}, value *big.Int, evm *vm.EVM, suppliedGas uint64, hooks *tracing.Hooks) (ret []byte, remainingGas uint64, err error) {
	if err := pcommon.ValidateNonPayable(value); err != nil {

		return nil, 0, err

	existingAddr, existingVersion, exists := p.evmKeeper.GetERC20CW20Pointer(ctx, cwAddr)
	if exists {

	}
	cwAddress, err := sdk.AccAddressFromBech32(cwAddr)
	if err != nil {
		return nil, 0, err
	}
	res, err := p.wasmdKeeper.QuerySmart(ctx, cwAddress, []byte("{\"token_info\":{}}"))
	if err != nil {
		return nil, 0, err
	}
	formattedRes := map[string]interface{}{}
	if err := json.Unmarshal(res, &formattedRes); err != nil {
		return nil, 0, err
	}
	name := formattedRes["name"].(string)
	symbol := formattedRes["symbol"].(string)
	constructorArguments := []interface{}{
		cwAddr, name, symbol,
	}

	if err := pcommon.ValidateNonPayable(value); err != nil {
		return nil, 0, err
	}

		return nil, 0, err
	}
	cwAddr := args[0].(string)
	cwAddress, err := sdk.AccAddressFromBech32(cwAddr)
	if err != nil {
		return nil, 0, err
	}
	res, err := p.wasmdKeeper.QuerySmartSafe(ctx, cwAddress, []byte("{\"contract_info\":{}}"))
	if err != nil {
		return nil, 0, err
	}
	formattedRes := map[string]interface{}{}
	if err := json.Unmarshal(res, &formattedRes); err != nil {
		return nil, 0, err
	}
	name := formattedRes["name"].(string)
	symbol := formattedRes["symbol"].(string)
	contractAddr, err := p.evmKeeper.UpsertERCCW1155Pointer(ctx, evm, cwAddr, utils.ERCMetadata{Name: name, Symbol: symbol})
	if err != nil {
		return nil, 0, err
	}

	ret, err = method.Outputs.Pack(contractAddr)
	remainingGas = pcommon.GetRemainingGas(ctx, p.evmKeeper)
	return
}

    function transfer(address to, uint256 amount) public override returns (bool) {
        require(to != address(0), "ERC20: transfer to the zero address");
        string memory recipient = _formatPayload("recipient", _doubleQuotes(AddrPrecompile.getSeiAddr(to)));
        string memory amt = _formatPayload("amount", _doubleQuotes(Strings.toString(amount)));
        string memory req = _curlyBrace(_formatPayload("transfer", _curlyBrace(_join(recipient, amt, ","))));
        _execute(bytes(req));
        return true;
    }

    function transferFrom(address from, address to, uint256 amount) public override returns (bool) {
        require(to != address(0), "ERC20: transfer to the zero address");
        string memory sender = _formatPayload("owner", _doubleQuotes(AddrPrecompile.getSeiAddr(from)));
        string memory recipient = _formatPayload("recipient", _doubleQuotes(AddrPrecompile.getSeiAddr(to)));
        string memory amt = _formatPayload("amount", _doubleQuotes(Strings.toString(amount)));
        string memory req = _curlyBrace(_formatPayload("transfer_from", _curlyBrace(_join(_join(sender, recipient, ","), amt, ","))));
        _execute(bytes(req));
        return true;
    }

    function _execute(bytes memory req) internal returns (bytes memory) {
        (bool success, bytes memory ret) = WASMD_PRECOMPILE_ADDRESS.delegatecall(
            abi.encodeWithSignature(
                "execute(string,bytes,bytes)",
                Cw20Address,
                bytes(req),
                bytes("[]")
            )
        );
        require(success, "CosmWasm execute failed");
        return ret;
    }
