### Title
Governance-disabled CW↔EVM pointer registration is bypassable via the `pointer` precompile - ([File: precompiles/pointer/pointer.go])

### Summary
The `RegisterPointerDisabled` parameter is meant to let governance globally disable creation of new CW↔ERC pointers. It is enforced only in the Cosmos `MsgRegisterPointer` handler, but the EVM `pointer` precompile (`0x100b`) methods that create the exact same pointers (`addNativePointer`, `addCW20Pointer`, `addCW721Pointer`, `addCW1155Pointer`) never check this flag, so any EVM transaction sender can still create pointers after governance disables the feature.

### Finding Description
`x/evm/keeper/msg_server.go`'s `RegisterPointer` handler explicitly gates pointer creation on the governance-controlled flag before doing any state mutation: [1](#0-0) 

This mirrors the correct pattern the OnionShare advisory says is missing: check the policy flag before the state-mutating operation. The flag is read from module params: [2](#0-1) 

and there is even a migration that flips it on by default in some upgrade: [3](#0-2) 

However, the `pointer` precompile — a second, independently-reachable entry point into the exact same pointer-creation logic (`UpsertERCNativePointer`, `UpsertERCCW20Pointer`, `UpsertERCCW721Pointer`, `UpsertERCCW1155Pointer`) — performs no such check anywhere in its dispatch or method implementations: [4](#0-3) [5](#0-4) [6](#0-5) 

None of `AddNative`, `AddCW20`, `AddCW721`, or `AddCW1155` reads `p.evmKeeper.GetRegisterPointerDisabled(ctx)` (or any equivalent) before calling the corresponding `UpsertERC*Pointer` keeper method. This is structurally identical to the OnionShare root cause: the policy ("disable this feature") is enforced at one code path (`ReceiveModeRequest`/route handler in OnionShare; `MsgRegisterPointer` in sei-chain) but not at the lower-level/alternate sink that actually performs the write (`_get_file_stream`/`ReceiveModeFile` in OnionShare; the `pointer` precompile executors in sei-chain), which both reach the same underlying resource-creation code.

### Impact Explanation
When governance disables pointer registration (e.g., in response to abuse, a compromised code template, or to freeze the pointer registry during an incident), any unprivileged EVM transaction sender can still call the `pointer` precompile directly to register new CW20/CW721/CW1155/native pointers, completely defeating the governance-enforced restriction. Since pointers back real token transfer/dispatch logic between the CW and EVM worlds (and the CW20 pointer flow instantiates a wasm contract as the pointer), an attacker can continue creating pointer contracts — including registering pointers for malicious/spoofed CW or native denoms — after the chain operator has intentionally shut this feature off, undermining an operator security control and potentially exposing users to pointer contracts the operator specifically intended to block.

### Likelihood Explanation
Trivial and fully attacker-controlled: any account can call the `pointer` precompile at `0x100b` with a normal EVM transaction; no special privilege, association state, or governance access is required beyond what is already needed to call any precompile.

### Recommendation
Add a `k.GetRegisterPointerDisabled(ctx)` check at the top of `PrecompileExecutor.Execute` (or in each of `AddNative`, `AddCW20`, `AddCW721`, `AddCW1155`) in `precompiles/pointer/pointer.go`, returning an error identical to the one used in `x/evm/keeper/msg_server.go`'s `RegisterPointer` ("registering CW->ERC pointers has been disabled") whenever the flag is set, before any call into `UpsertERC*Pointer`. Add regression tests (mirroring `TestRegisterPointerDisabled` in `x/evm/keeper/msg_server_test.go`) that call the precompile executors directly with `RegisterPointerDisabled = true` and assert no pointer is created and no `EventTypePointerRegistered` event fires.

### Proof of Concept
1. Governance sets `RegisterPointerDisabled = true` via a param-change proposal (as validated by `x/evm/keeper/msg_server_test.go`'s `TestRegisterPointerDisabled`).
2. Confirm `MsgRegisterPointer` now fails with "registering CW->ERC pointers has been disabled" as shown in that test.
3. From any account, send an EVM transaction calling `pointer.addCW20Pointer(cwAddress)` (or `addNativePointer`/`addCW721Pointer`/`addCW1155Pointer`) on precompile address `0x000000000000000000000000000000000000100b`.
4. Observe the call succeeds and returns a new pointer contract address — `precompiles/pointer/pointer.go`'s `AddCW20` never consults `GetRegisterPointerDisabled`, so `UpsertERCCW20Pointer` executes unconditionally, proving the governance-disabled restriction is bypassed through the EVM entry point.

func (p PrecompileExecutor) AddNative(ctx sdk.Context, method *ethabi.Method, caller common.Address, args []interface{}, value *big.Int, evm *vm.EVM, hooks *tracing.Hooks) (ret []byte, remainingGas uint64, err error) {
	if err := pcommon.ValidateNonPayable(value); err != nil {
		return nil, 0, err
	}
	if err := pcommon.ValidateArgsLength(args, 1); err != nil {
		return nil, 0, err
	}
	token := args[0].(string)
	metadata, metadataExists := p.bankKeeper.GetDenomMetaData(ctx, token)
	if !metadataExists {
		return nil, 0, fmt.Errorf("denom %s does not have metadata stored and thus can only have its pointer set through gov proposal", token)
	}
	name := metadata.Name
	symbol := metadata.Symbol
	var decimals uint8
	for _, denomUnit := range metadata.DenomUnits {
		if denomUnit.Exponent > uint32(decimals) && denomUnit.Exponent <= math.MaxUint8 {
			decimals = uint8(denomUnit.Exponent)
			name = denomUnit.Denom
			symbol = denomUnit.Denom
			if len(denomUnit.Aliases) > 0 {
				name = denomUnit.Aliases[0]
			}
		}
	}
	contractAddr, err := p.evmKeeper.UpsertERCNativePointer(ctx, evm, token, utils.ERCMetadata{Name: name, Symbol: symbol, Decimals: decimals})
	if err != nil {
		return nil, 0, err
	}

	ret, err = method.Outputs.Pack(contractAddr)
	remainingGas = pcommon.GetRemainingGas(ctx, p.evmKeeper)
	return
}

func (p PrecompileExecutor) AddCW20(ctx sdk.Context, method *ethabi.Method, caller common.Address, args []interface{}, value *big.Int, evm *vm.EVM, hooks *tracing.Hooks) (ret []byte, remainingGas uint64, err error) {
	if err := pcommon.ValidateNonPayable(value); err != nil {
		return nil, 0, err
	}
	if err := pcommon.ValidateArgsLength(args, 1); err != nil {
		return nil, 0, err
	}
	cwAddr := args[0].(string)
	cwAddress, err := sdk.AccAddressFromBech32(cwAddr)
	if err != nil {
		return nil, 0, err
	}
	res, err := p.wasmdKeeper.QuerySmartSafe(ctx, cwAddress, []byte("{\"token_info\":{}}"))
	if err != nil {
		return nil, 0, err
	}
	formattedRes := map[string]interface{}{}
	if err := json.Unmarshal(res, &formattedRes); err != nil {
		return nil, 0, err
	}
	name := formattedRes["name"].(string)
	symbol := formattedRes["symbol"].(string)
	contractAddr, err := p.evmKeeper.UpsertERCCW20Pointer(ctx, evm, cwAddr, utils.ERCMetadata{Name: name, Symbol: symbol})
	if err != nil {
		return nil, 0, err
	}

	ret, err = method.Outputs.Pack(contractAddr)
	remainingGas = pcommon.GetRemainingGas(ctx, p.evmKeeper)
	return
}
