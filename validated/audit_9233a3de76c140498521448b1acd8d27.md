## Finding

Based on the WooFi bug-class (an unnecessary same-asset swap fee charged when wrapping/unwrapping native coin for a token that is functionally identical), I found a concrete local analog in Hyperbridge's custom Uniswap-V2-compatible AMM wrapper used for native-fee payments.

### Title
Native-fee dispatch pays a real AMM swap fee to convert ETH→WETH instead of a free wrap when `UniV4UniswapV2Wrapper` is the configured router - (File: `evm/src/utils/uniswapv2/UniV4UniswapV2Wrapper.sol`)

### Summary
`EvmHost.dispatch()`, `EvmHost.fundRequest()`, and `IntentGatewayV2.placeOrder()`/`fillOrder()` all convert native-token fee payments into the protocol `feeToken()` by calling `swapETHForExactTokens(fee, [WETH, feeToken], ...)` on the configured `uniswapV2` router [1](#0-0) . On deployments where the router param points to `UniV4UniswapV2Wrapper` (used to route V2-shaped calls through Uniswap V4 pools) and the chain's `feeToken()` is configured to be the same address as the chain's wrapped-native asset (`_params.WETH`), this call silently executes a real, fee-charging V4 pool swap between native ETH and WETH instead of a free `IWETH.deposit()` wrap — because `swapETHForExactTokens` never checks whether `path[1]` is the same underlying asset as the wrapped native token.

### Finding Description
`UniV4UniswapV2Wrapper.swapETHForExactTokens` builds a `PoolKey` directly from `path[1]` with `currency0 = address(0)` (native ETH) and `currency1 = path[1]`, then executes a `V4_SWAP` through the Universal Router: [2](#0-1) 

```solidity
function swapETHForExactTokens(uint256 amountOut, address[] calldata path, address recipient, uint256 deadline)
    external payable returns (uint256[] memory amounts)
{
    PoolKey memory poolKey = _createPoolKey(path[1]);
    ...
    IUniversalRouter(_params.universalRouter).execute{value: msg.value}(...);
```

`_createPoolKey` always sets `currency0 = address(0)` (native) and `currency1 = tokenOut`: [3](#0-2) 

Unlike `getAmountsIn`/`getAmountsOut`, which explicitly special-case "is this token really native" via `_isNativeToken` (`token == address(0) || token == _params.WETH`) [4](#0-3) , `swapETHForExactTokens` has **no such check**. If `path[1] == _params.WETH`, the function still builds a valid `PoolKey{currency0: address(0), currency1: WETH}` — a real, tradeable ETH/WETH pool in Uniswap V4's ETH-native accounting model — and executes an actual `SWAP_EXACT_OUT_SINGLE` against that pool, paying the pool's LP fee, instead of doing a trivial `IWETH(weth).deposit()`.

This wrapper is invoked from every native-fee payment path in the protocol:
- `EvmHost.dispatch(DispatchPost)` / `dispatch(DispatchGet)` / `fundRequest()`, whenever `msg.value > 0`, unconditionally swap via `path = [WETH, feeToken()]` [1](#0-0) 
- `IntentGatewayV2.placeOrder()` / `fillOrder()` fee-swap logic, same `path = [WETH, feeToken]` pattern [5](#0-4) 

If a Hyperbridge deployment's governance configures `feeToken()` to be the chain's own wrapped-native asset (plausible on chains that lack a deep-liquidity stablecoin and instead settle fees in WETH/WBNB/WMATIC) while using `UniV4UniswapV2Wrapper` as the `uniswapV2Router`, then **every unprivileged user** who pays a dispatch/order fee in native token on that chain is charged a real AMM swap fee purely to convert ETH into its own wrapped representation — economically identical assets — mirroring exactly the WooFi `sgETH→WETH` "unnecessary WETH↔WETH fee" bug class, except here the loss is real (a real pool with real fee tiers exists for ETH/WETH under V4's native-currency model, so the swap doesn't revert like a standard V2 pair with `IDENTICAL_ADDRESSES` would).

### Impact Explanation
Every native-token fee payment on an affected deployment (Hyperbridge message dispatch, GET/POST requests, request funding, and Intent Gateway order placement/fill) permanently loses a percentage of the paid fee to LP swap fees for no economic benefit — pure value destruction charged to ordinary users, matching the bounty's "stealing or loss of funds" impact class. Because the check is missing at the wrapper level (not the caller level), this affects every current and future caller of `dispatch()`/`fundRequest()`/`placeOrder()`/`fillOrder()` on any chain configured this way, not a one-off integration mistake.

### Likelihood Explanation
Triggering requires no malicious actor, relayer, or governance compromise — only a legitimate governance configuration choice (fee token = wrapped native asset, common on chains without deep stablecoin liquidity) combined with using the V4 wrapper for the swap router. Once configured, the bug fires automatically and deterministically on every native-fee payment; there is no way for a normal user to avoid it while paying fees in native token.

### Recommendation
In `UniV4UniswapV2Wrapper.swapETHForExactTokens` (and the analogous `swapExactTokensForETH`), short-circuit when `path[1]` (or `path[0]`) is the wrapped-native asset itself: perform a plain `IWETH(weth).deposit{value: msg.value}()` / `withdraw()` and forward funds directly, bypassing the V4 pool swap entirely, mirroring the `_isNativeToken` check already present in `getAmountsIn`/`getAmountsOut`. Alternatively, enforce at `EvmHost`/`IntentGatewayV2` configuration time that `feeToken() != WETH` when a swap-based native-fee rail is in use.

### Proof of Concept
1. Deploy `EvmHost` with `_hostParams.uniswapV2 = UniV4UniswapV2Wrapper` and `feeToken() = WETH` (the chain's wrapped-native asset).
2. Any user calls `EvmHost.dispatch(DispatchPost)` with `msg.value = post.fee` (paying via native token).
3. `EvmHost.dispatch` calls `UniV4UniswapV2Wrapper.swapETHForExactTokens(post.fee, [WETH, WETH], address(this), ...)`.
4. `_createPoolKey(WETH)` returns `PoolKey{currency0: address(0), currency1: WETH}`; the Universal Router executes a real `SWAP_EXACT_OUT_SINGLE` against that pool, charging the pool's fee tier (e.g., 0.05%–1%) on the full fee amount, even though the "input" and "output" assets are economically the same unit of value.
5. Repeat for `fundRequest()`, `dispatch(DispatchGet)`, and `IntentGatewayV2.placeOrder`/`fillOrder` — identical unnecessary-fee loss on every native-paid call.

```text
    function swapETHForExactTokens(uint256 amountOut, address[] calldata path, address recipient, uint256 deadline)
        external
        payable
        returns (uint256[] memory amounts)
    {
        PoolKey memory poolKey = _createPoolKey(path[1]);

        bytes[] memory params = new bytes[](3);
        params[0] = abi.encode(poolKey, true, uint128(amountOut), uint128(msg.value), bytes(""));
        params[1] = abi.encode(poolKey.currency0, uint256(0), false);
        params[2] = abi.encode(poolKey.currency1, recipient, amountOut);

        bytes[] memory inputs = new bytes[](1);
        inputs[0] = abi.encode(
            abi.encodePacked(uint8(Actions.SWAP_EXACT_OUT_SINGLE), uint8(Actions.SETTLE), uint8(Actions.TAKE)), params
        );

        // Snapshot standing balance (excluding inbound msg.value) so the refund is the swap-call delta only,
        // immune to any ETH that lands on the wrapper from outside the router (e.g., selfdestruct, coinbase).
        uint256 balanceBefore = address(this).balance - msg.value;

        IUniversalRouter(_params.universalRouter).execute{value: msg.value}(
            abi.encodePacked(bytes1(uint8(Commands.V4_SWAP))), inputs, deadline
        );

        uint256 refundETH = address(this).balance - balanceBefore;

        if (refundETH > 0) {
            (bool success,) = msg.sender.call{value: refundETH}("");
            require(success, "ETH refund failed");
        }

        amounts = new uint256[](2);
        amounts[0] = msg.value - refundETH;
        amounts[1] = amountOut;
    }
```
