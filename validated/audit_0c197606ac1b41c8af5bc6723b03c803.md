### Title
Unprivileged `donateRewards` call lets an attacker flush accumulated `queuedRewards` onto a self-controlled minimal stake - ([File: rewards/BaseRewardPoolV2.sol])

### Summary
`BribeRewardPool` inherits `_provisionReward` and the public, access-control-free `donateRewards` function from `BaseRewardPoolV2`. If a pool has `totalStaked() == 0` while rewards are being queued (accumulating in `rewardInfo.queuedRewards`), an attacker can stake a negligible amount through MasterMagpie and then call `donateRewards(0, _rewardToken)` themselves, which is enough to trigger the `else` branch of `_provisionReward` and flush the entire `queuedRewards` balance into `rewardPerTokenStored` divided by the attacker's own tiny `totalStaked()`. The attacker can then claim nearly all previously queued rewards for a negligible stake.

### Finding Description
`BribeRewardPool` (`rewards/BribeRewardPool.sol`) extends `BaseRewardPoolV2` and does not override `donateRewards` or `_provisionReward`. Both are defined in `rewards/BaseRewardPoolV2.sol`: [1](#0-0) 

`donateRewards` has **no access control** (`onlyManager` is not applied), unlike `queueNewRewards`: [2](#0-1) 

The critical logic is the branch on `totalStaked() == 0`. When the branch flips from true to false, any pending `queuedRewards` is added to `_amountReward` and divided by the *current* `totalStaked()`:
```
if (rewardInfo.queuedRewards > 0) {
    _amountReward += rewardInfo.queuedRewards;
    rewardInfo.queuedRewards = 0;
}
rewardInfo.rewardPerTokenStored += (_amountReward * 10**stakingTokenDecimals) / totalStaked();
```
For `BribeRewardPool`, `totalStaked()` is the internally tracked `totalSupply`, updated only via `stakeFor`/`withdrawFor` which are `onlyOperator` (MasterMagpie) callable — reachable by any user through a normal MasterMagpie deposit: [3](#0-2) 

Exploit flow:
1. A `BribeRewardPool` accumulates rewards while nobody has staked yet (`totalStaked() == 0`), so `queuedRewards` grows via `queueNewRewards` calls from the (privileged) reward manager — this is a normal, expected pre-launch/idle-pool condition, not attacker-induced.
2. Attacker deposits a minimal amount of the staking token through MasterMagpie, which calls `stakeFor`, moving `totalStaked()` from 0 to a tiny nonzero value that is 100% attacker-owned.
3. Attacker (unprivileged, no `onlyManager` role needed) calls `donateRewards(0, _rewardToken)` directly on the pool. Since `isRewardToken[_rewardToken]` is already true, this call succeeds and executes `_provisionReward(0, _rewardToken)`.
4. Because `totalStaked()` is now nonzero, the `else` branch fires: all of `queuedRewards` (accumulated over potentially a long idle period) is divided by the attacker's tiny `totalStaked()`, producing a massive `rewardPerTokenStored` jump.
5. Attacker calls `getReward`/`getRewards` (via MasterMagpie) and receives essentially all of the previously queued rewards, disproportionate to their negligible stake.

No existing modifier prevents this: `donateRewards` has no `onlyManager`/`onlyOperator`/`nonReentrant` restriction, and there is no minimum-stake or time-lock safeguard on the `totalStaked()==0 → nonzero` transition.

### Impact Explanation
This is theft of unclaimed yield: an attacker with a negligible stake can capture nearly the entirety of rewards that were queued for legitimate future stakers of a `BribeRewardPool`. This matches the "theft of unclaimed yield" impact class in scope.

### Likelihood Explanation
Preconditions: a `BribeRewardPool` must have accrued `queuedRewards` while `totalStaked() == 0` (plausible for newly created bribe pools, or pools where all stakers have withdrawn). Capital required is negligible (minimum stake unit + gas). The attack is fully self-contained — the attacker triggers both the stake and the reward-flush transaction (`donateRewards`) themselves, requiring no cooperation or timing dependency on the reward manager, making it deterministic and repeatable across any pool exhibiting the precondition.

### Recommendation
- Restrict `donateRewards` with `onlyManager` (or remove/rework the unrestricted public donation entry point), so an attacker cannot unilaterally trigger the `queuedRewards` flush.
- When transitioning `totalStaked()` from 0 to nonzero, avoid instantly crediting all `queuedRewards` to whoever holds the current (possibly tiny) stake — e.g., distribute over time, require a minimum stake/duration before flushing, or snapshot eligible stakers before allowing the flush.
- Consider requiring `_amountReward > 0` in `donateRewards`/`_provisionReward` to prevent triggering the flush with a zero-value donation.

### Proof of Concept
Foundry test plan:
1. Deploy `MasterMagpie`, a staking token, a reward token, and a `BribeRewardPool` (via `BaseRewardPoolV2` constructor) registered with MasterMagpie as `operator`.
2. As the reward manager, call `queueNewRewards(1000e18, rewardToken)` multiple times while no one has staked (`totalStaked() == 0`), confirming via `rewards(rewardToken).queuedRewards` that it accumulates to e.g. 3000e18 and `rewardPerTokenStored` stays 0.
3. As `attacker` (unprivileged EOA), call `MasterMagpie.deposit(stakingToken, 1)` (1 wei of staking token) so `BribeRewardPool.totalStaked() == 1`.
4. As `attacker`, call `BribeRewardPool.donateRewards(0, rewardToken)` directly.
5. Assert `rewards(rewardToken).queuedRewards == 0` and `rewardPerTokenStored` jumped to reflect `3000e18 * 1e18 / 1`.
6. Call `MasterMagpie.multiclaim`/`getReward` for `attacker` and assert `earned(attacker, rewardToken) ≈ 3000e18`, i.e., attacker with 1 wei of stake claims nearly the entire queued reward pool, versus a fair share that would be near-zero relative to normal stakers.

```text
    function _provisionReward(uint256 _amountReward, address _rewardToken) internal {
        IERC20(_rewardToken).safeTransferFrom(
            msg.sender,
            address(this),
            _amountReward
        );
        Reward storage rewardInfo = rewards[_rewardToken];
        rewardInfo.historicalRewards =
            rewardInfo.historicalRewards +
            _amountReward;

        if (totalStaked() == 0) {
            rewardInfo.queuedRewards += _amountReward;
        } else {
            if (rewardInfo.queuedRewards > 0) {
                _amountReward += rewardInfo.queuedRewards;
                rewardInfo.queuedRewards = 0;
            }
            rewardInfo.rewardPerTokenStored =
                rewardInfo.rewardPerTokenStored +
                (_amountReward * 10**stakingTokenDecimals) /
                totalStaked();
        }
        emit RewardAdded(_amountReward, _rewardToken);
    }
```
