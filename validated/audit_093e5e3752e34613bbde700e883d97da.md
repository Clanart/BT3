## Title
Gas-fee front-loading via unconditional `LendTx` allows a gasless-swap sender to grief the block proposer / extract free KAIA when the bundled `SwapTx` reverts - (File: kaiax/gasless/impl/builder.go, kaiax/gasless/impl/getter.go)

### Summary
The reported zAuction/zNS issue is a generic "gas griefing by unauthorized/unfunded off-chain-dependent submission" bug class: a party (bidder) whose funds/approval are required for success is not re-verified immediately before an expensive/valuable on-chain action is taken on their behalf, letting them cause the paying party to lose value. The closest reachable analog in this Kaia codebase is the `kaiax/gasless` module (KIP-247), where the block proposer unconditionally sends real KAIA to the gasless-transaction sender via a generated `LendTx` *before* the sender's `GaslessSwapTx` is guaranteed to succeed, with no atomic rollback tying the loan to swap success.

### Finding Description
`GaslessModule.ExtractTxBundles` builds a bundle of `[LendTxGenerator, ApproveTx(optional), SwapTx]` whenever `IsExecutable(approveTxOrNil, swapTx)` passes: [1](#0-0) 

`VerifyExecutable` only checks static/decoded conditions (sender match, token match, approved amount ≥ amountIn, sequential nonce, current state nonce, and that `amountRepay` matches the expected formula) - it does **not** re-verify the sender's actual token balance at bundle-building time: [2](#0-1) 

The token-balance check (`checkBalanceForApprove`) is performed only once, at tx-pool admission time via `GetCheckBalance`, and is explicitly documented as omitted for the swap step itself and not re-checked at inclusion: [3](#0-2) [4](#0-3) 

`GetLendTxGenerator` (`MakeLendTx`) unconditionally constructs and signs a **value-transfer transaction from the proposer's own key to the sender**, funded for `lendAmount(approveTxOrNil, swapTx)` KAIA, and this `LendTx` is placed *first* in the bundle, ahead of `ApproveTx`/`SwapTx`: [5](#0-4) 

Because `LendTx`, `ApproveTx`, and `SwapTx` are three **separate, independently-executed transactions** in the block (not one atomic on-chain call), there is no on-chain mechanism forcing `LendTx`'s value transfer to be rolled back if the subsequent `SwapTx` reverts. The repayment of the lent amount is expected to happen inside `SwapForGas` on the router contract as part of the swap execution (per `AmountRepay` semantics), but if `SwapTx` reverts for any reason that is not caught by the module's static pre-checks (e.g., price movement causing `minAmountOut`/slippage failure inside the router, front-running that drains the token balance/allowance between pool-admission and block-inclusion, or any other execution-time revert not covered by `VerifyExecutable`), the `LendTx` has already unconditionally transferred real KAIA to the sender, and that value is not recovered.

This mirrors the reported bug class precisely: a transaction whose success depends on conditions/funds controlled by another account (the swap sender) is executed by a different party (the block proposer, acting like the "on-chain caller" in the original report) without a final guard immediately before the costly/valuable action, exposing the proposer to loss.

### Impact Explanation
If exploited, a malicious "gasless" user can obtain real KAIA (`lendAmount`, computed from `swapTx.Fee()` + optional `approveTx.Fee()`) funded from the block proposer's own balance without ever completing/repaying the swap, because the `SwapTx` deliberately or incidentally reverts after the `LendTx` has already executed. This is a form of unauthorized value extraction from the block proposer (a Kaia CN operator), i.e., direct fee/value theft rather than mere wasted gas — worse than the "gas griefing" framed in the original report, since here real value (KAIA) moves before success is guaranteed. Repeated at scale this drains proposer funds (`AuctionLenderMinBal`/gasless lending balance) and could also be used to selectively grief specific proposers.

### Likelihood Explanation
Reachable by any unprivileged user who can submit a standards-conforming `ApproveTx`/`SwapTx` pair to the mempool: the balance check that gates pool admission is a point-in-time check (`GetCheckBalance`), and nothing re-verifies the balance/slippage conditions at block-building or execution time other than the nonce and static-argument checks in `VerifyExecutable`. An attacker only needs to cause the swap to fail after admission (e.g., a self-triggered prior transaction draining the token, or exploiting normal price/slippage movement window) to trigger the free lend. Likelihood is Medium: it requires precise timing/knowledge of block construction and possibly some griefing capital, but no privileged access.

### Recommendation
- Re-verify the sender's actual on-chain token balance/allowance (not just static call decoding) immediately before generating the `LendTx`, at the same point the bundle is finalized for inclusion (as close as possible to actual execution state).
- Make loan disbursement conditional/atomic with successful swap execution — e.g., have the router pull the repayment via a pre-authorized mechanism inside the same transaction as the loan, or refuse to include `LendTx` unless a dry-run/static `eth_call` of the router's `swapForGas` against the *current* head state confirms success.
- Consider tracking and capping per-sender/per-block lending exposure, and monitoring/reverting the whole bundle (not committing `LendTx`) if the following `SwapTx` fails, similar to the existing `shouldDiscardBundle` logic used for target-tx bundles.

### Proof of Concept
1. Attacker holds `X` tokens > 0 (passes `checkBalanceForApprove`/`GetCheckBalance` at admission) and submits a valid `ApproveTx` (nonce N) then `SwapTx` (nonce N+1) with `minAmountOut` set to a value that will only barely be satisfied at submission time, or arranges (via a separate legitimately-included prior transaction in the same or an adjacent block) for the router's live conditions (e.g. token balance, DEX price) to shift so that `swapForGas` will revert on execution.
2. The gasless bundling logic in `ExtractTxBundles`/`VerifyExecutable` only checks static decode conditions and nonce sequencing (`kaiax/gasless/impl/builder.go:38-51`, `kaiax/gasless/impl/getter.go:211-266`), so the bundle `[LendTxGenerator, ApproveTx, SwapTx]` is still produced.
3. The proposer signs and includes `LendTx` (from `GetLendTxGenerator`, `kaiax/gasless/impl/getter.go:268-313`), transferring `lendAmount` KAIA to the attacker's address, ahead of `SwapTx`.
4. `SwapTx` executes and reverts (per the manipulated on-chain condition), so no repayment to the proposer occurs, but the attacker has already received the lent KAIA in the earlier, independently-successful `LendTx`.

Note: full confirmation of the exact repayment mechanics requires inspecting the on-chain `GaslessSwapRouter` contract source (only its Go bindings, `contracts/bindings/kip247/GaslessSwapRouter.go`, were indexed, not its Solidity source), so the precise revert conditions inside `swapForGas` that would trigger this scenario could not be fully verified from the indexed code; a Devin session with full repository access would be needed to inspect `contracts/system_contracts/kip247/GaslessSwapRouter.sol` (or equivalent) to confirm whether repayment is pulled atomically or is dependent on the swap's own success path.

// VerifyExecutable checks if the given transactions form a valid gasless transaction
// It returns an error explaining why the transaction is not executable if it's not,
// and a boolean indicating whether the transaction is executable
func (g *GaslessModule) VerifyExecutable(approveTxOrNil, swapTx *types.Transaction) error {
	// Sx.
	swapArgs, ok := decodeSwapTx(swapTx, g.signer)
	if !ok {
		return ErrDecodeSwapTx
	}
	if !g.isSwapTx(swapArgs) {
		return ErrSwapTxInvalid
	}

	// Conditions involving ApproveTx
	if approveTxOrNil != nil {
		// Ax.
		approveArgs, ok := decodeApproveTx(approveTxOrNil, g.signer)
		if !ok {
			return ErrDecodeApproveTx
		}
		if !g.isApproveTx(approveArgs) {
			return ErrApproveTxInvalid
		}
		// AP1.
		if approveArgs.Sender != swapArgs.Sender {
			return ErrDifferentSenders
		}
		// SP1.
		if approveArgs.Token != swapArgs.Token {
			return fmt.Errorf("%w: approve token %s, swap token %s", ErrDifferentTokens, approveArgs.Token.Hex(), swapArgs.Token.Hex())
		}
		// SP2.
		if approveArgs.Amount.Cmp(swapArgs.AmountIn) < 0 {
			return fmt.Errorf("%w: approve amount %s, required amount %s", ErrInsufficientApproveAmount, approveArgs.Amount.String(), swapArgs.AmountIn.String())
		}
		// SP3.
		if approveTxOrNil.Nonce()+1 != swapTx.Nonce() {
			return fmt.Errorf("%w: approve nonce %d, swap nonce %d (expected %d)", ErrNonSequentialNonce, approveTxOrNil.Nonce(), swapTx.Nonce(), approveTxOrNil.Nonce()+1)
		}
		if nonce := g.getCurrentStateNonce(approveArgs.Sender); nonce != approveTxOrNil.Nonce() {
			return fmt.Errorf("%w: approve nonce %d, current nonce %d", ErrApproveNonceNotCurrent, approveTxOrNil.Nonce(), nonce)
		}
	} else {
		// SP3.
		if nonce := g.getCurrentStateNonce(swapArgs.Sender); nonce != swapTx.Nonce() {
			return fmt.Errorf("%w: swap nonce %d, current nonce %d", ErrSwapNonceNotCurrent, swapTx.Nonce(), nonce)
		}
	}

	// SP4.
	if swapArgs.AmountRepay.Cmp(repayAmount(approveTxOrNil, swapTx)) != 0 {
		return fmt.Errorf("%w: got %s, expected %s", ErrIncorrectRepayAmount, swapArgs.AmountRepay.String(), repayAmount(approveTxOrNil, swapTx).String())
	}

	return nil
}

// MakeLendTx creates a transaction with following properties:
// L1. LendTx.type = 0x7802 (TxTypeEthereumDynamicFee)
// L2. LendTx.from = proposer
// L3. LendTx.to = SwapTx.from
// L4. LendTx.value = LendAmount(approveTxOrNil, swapTx)
func (g *GaslessModule) GetLendTxGenerator(approveTxOrNil, swapTx *types.Transaction) *builder.TxOrGen {
	var src []byte
	if approveTxOrNil != nil {
		src = append(src, approveTxOrNil.Hash().Bytes()...)
	}
	src = append(src, swapTx.Hash().Bytes()...)
	bundleHash := crypto.Keccak256Hash(src)

	gen := func(nonce uint64) (*types.Transaction, error) {
		var (
			chainId = g.InitOpts.ChainConfig.ChainID
			signer  = types.LatestSignerForChainID(chainId)
			key     = g.InitOpts.NodeKey
		)

		to, err := types.Sender(signer, swapTx)
		if err != nil {
			return nil, err
		}

		tx, err := types.NewTransactionWithMap(types.TxTypeEthereumDynamicFee, map[types.TxValueKeyType]interface{}{
			types.TxValueKeyNonce:      nonce,
			types.TxValueKeyTo:         &to,
			types.TxValueKeyAmount:     lendAmount(approveTxOrNil, swapTx),
			types.TxValueKeyData:       common.Hex2Bytes("0x"),
			types.TxValueKeyGasLimit:   params.TxGas,
			types.TxValueKeyGasFeeCap:  swapTx.GasFeeCap(),
			types.TxValueKeyGasTipCap:  swapTx.GasTipCap(),
			types.TxValueKeyAccessList: types.AccessList{},
			types.TxValueKeyChainID:    chainId,
		})
		if err != nil {
			return nil, err
		}

		err = tx.Sign(signer, key)
		return tx, err
	}

	return builder.NewTxOrGenFromGen(gen, bundleHash)
}

func (g *GaslessModule) GetCheckBalance() func(tx *types.Transaction) error {
	return func(tx *types.Transaction) error {
		if approveArgs, ok := decodeApproveTx(tx, g.signer); ok {
			return g.checkBalanceForApprove(approveArgs)
		}
		if swapArgs, ok := decodeSwapTx(tx, g.signer); ok {
			return g.checkBalanceForSwap(swapArgs, tx.Nonce())
		}
		return errors.New("not a gasless transaction") // should not happen because IsModuleTx is called before GetCheckBalance
	}
}

func (g *GaslessModule) checkBalanceForApprove(approveArgs *ApproveArgs) error {
	token := approveArgs.Token
	bc := backends.NewBlockchainContractBackend(g.Chain, nil, nil)

	if g.GaslessConfig.ShouldCheckSenderCode() {
		if g.getCurrentHasCode(approveArgs.Sender) {
			return errors.New("sender with code is not allowed")
		}
	}

	if g.GaslessConfig.ShouldCheckToken() {
		tokenContract, err := sc_erc20.NewERC20(token, bc)
		if err != nil {
			return err
		}

		// tx.token.balanceOf(sender) > 0
		tokenBalance, err := tokenContract.BalanceOf(nil, approveArgs.Sender)
		if err != nil {
			return err
		}
		if tokenBalance.Sign() <= 0 {
			return fmt.Errorf("insufficient sender token balance: token=%s, have=%s, want=nonzero", token.Hex(), tokenBalance.String())
		}
	}
	return nil
}
