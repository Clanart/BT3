### Title
Consensus reward hijacking via unauthenticated batch tail in `handle_unsigned` — treasury funds drained to an unrelated relayer - ([File: modules/pallets/consensus-incentives/src/impls.rs])

### Summary
`pallet-consensus-incentives`'s `FeeHandler::on_executed` authenticates a relayer by checking **only the first message** in an ISMP batch (`messages.get(0)`), then pays out treasury-funded rewards for **every** `StateMachineUpdated` event produced by the **entire batch**, regardless of which specific message produced it. This is structurally identical to the ZetaChain analog: a check on "at least one/only the first" message grants privileged treatment (fund distribution) to the whole heterogeneous batch, letting an unprivileged submitter collect rewards for consensus work they never signed for.

### Finding Description
`pallet_ismp::Call::handle_unsigned` is an unsigned extrinsic that "permits anyone [to] execute ISMP messages for free" as long as the proofs are valid [1](#0-0) . It accepts an arbitrary `Vec<Message>` batch mixing any combination of `Consensus`, `Request`, `Response`, `Timeout` messages, and after successful execution invokes every configured `FeeHandler::on_executed(messages, events)` with the flattened list of messages and events for the whole batch [2](#0-1) .

`pallet-consensus-incentives` implements this hook to reward the relayer who advances a remote chain's consensus state:

```rust

``` [3](#0-2) 

The authentication scope (message `[0]`'s signer) and the reward scope (`events` from **all** messages in the batch) are mismatched. Any `Consensus` message beyond index 0 in the same `handle_unsigned` call needs **no signature at all** to have its `StateMachineUpdated` event counted, because the `events` vector passed to `on_executed` is the flattened output of `execute()` over the entire batch, not scoped per-message [4](#0-3) .

Because consensus proofs are public data (finality proofs derived from the source chain's own gossip/RPC, not secret or exclusive to any particular relayer), any unprivileged actor can:
1. Construct or copy a set of N valid consensus proofs for N different `state_machine_id`s (or sequential updates for the same one), advancing real state — data anyone can obtain, no special relaying rights required.
2. Wrap them as `Message::Consensus` entries in a single `handle_unsigned` batch.
3. Put **only one** of them at index 0 with a `signer` field self-signed by the attacker's own throwaway sr25519 keypair over `keccak256(consensus_proof)` — this signature only proves the attacker holds *a* private key, not that they did any privileged work.
4. Leave all other `Consensus` messages in the batch with an empty/garbage `signer` (irrelevant — never checked).

`on_executed` will recover the attacker's account from message `[0]` and pay the full `Reward = (LatestHeight - PreviousHeight) * CostPerBlock` treasury payout for **every** state machine whose commitment advanced anywhere in the batch [5](#0-4) , transferring treasury funds via `T::Currency::transfer` and minting reputation to a single self-controlled account [6](#0-5) .

Existing guards do not stop this: `handle_unsigned`'s `ValidateUnsigned::validate_unsigned` only checks that message proofs are individually valid via `Self::execute(...)`, and assigns pool priority/`provides` tags per `StateMachineUpdated` event — it performs no per-message signer/authorization binding that would prevent one signer from claiming credit for another message's advance [7](#0-6) . The `IsmpCallFilter` in the nexus runtime only blocks BEEFY-consensus messages from `handle_unsigned`, unrelated to this batching/attribution flaw [8](#0-7) .

### Impact Explanation
This is a direct treasury fund-drain / wrong-beneficiary bug: `T::TreasuryAccount` funds and `ReputationAsset` are transferred to an account that did not perform (or authenticate) the corresponding relaying work for most of the reward it collects. An attacker can systematically batch every pending consensus update across all tracked state machines behind their own self-signed message `[0]`, capturing 100% of consensus-relay rewards network-wide with a single cheap signature, starving legitimate relayers of their incentive and draining the treasury faster than intended by the `CostPerBlock` economic model. This satisfies the bounty's "stealing or loss of funds" / "wrong beneficiary or amount" impact class.

### Likelihood Explanation
High. The path requires only an unprivileged account able to submit an unsigned `handle_unsigned` extrinsic (by design, "anyone" can) with publicly obtainable consensus proofs and a self-generated sr25519 keypair — no relayer registration, admin rights, or compromised keys are needed. The bug is a straightforward mismatch between per-message authentication and whole-batch effect attribution, and is trivially reachable every time multiple pending consensus updates exist simultaneously (a common, expected operational condition given multiple tracked state machines).

### Recommendation
Bind reward attribution to the specific message that produced each `StateMachineUpdated` event rather than to `messages[0]`. Concretely, iterate the executed messages, and for each `Message::Consensus` entry independently recover and verify its own `signer`, then only credit the state-machine(s)/height advance(s) that specific message's execution actually produced (e.g., by correlating each `Consensus` message's `consensus_state_id` to its own `StateMachineUpdated` event(s) rather than aggregating all events in the batch against a single globally-selected signer).

### Proof of Concept
1. Identify N state machines with pending, publicly-derivable consensus finality proofs (e.g. `chain_A`, `chain_B`, ... `chain_N`), each configured with `StateMachinesCostPerBlock`.
2. Attacker generates a throwaway sr25519 keypair `K`.
3. Attacker builds `messages = [Consensus(proof_A, signer = sign_K(keccak256(proof_A))), Consensus(proof_B, signer = <empty/garbage>), ..., Consensus(proof_N, signer = <empty/garbage>)]`.
4. Submit via `pallet_ismp::Call::handle_unsigned { messages }` as an unsigned transaction — `Self::execute(messages)` succeeds because every proof is individually valid [4](#0-3) .
5. `on_executed` in `consensus-incentives` recovers `relayer_account = K` from `messages[0]` only, then iterates the full `events` list (containing `StateMachineUpdated` for `chain_A..chain_N`) and pays `K` the reward for every one of them [9](#0-8) .
6. Result: attacker's account `K` receives treasury funds and reputation for N chains' worth of consensus-relay work while only having authenticated (self-signed) one of the N messages.

	/// Calculate the reward for a message based on the state machine id
	fn calculate_reward(
		state_machine_id: &StateMachineId,
		block_cost: <T as pallet_ismp::Config>::Balance,
	) -> Result<<T as pallet_ismp::Config>::Balance, Error<T>> {
		let host = <T::IsmpHost>::default();
		let latest_height = host
			.latest_commitment_height(state_machine_id.clone())
			.map_err(|_| Error::<T>::CouldNotGetStateMachineHeight)?;
		let previous_height =
			host.previous_commitment_height(state_machine_id.clone()).unwrap_or_default();

		// Use the rewarded watermark as the baseline and fall back to the previous height until
		// the first reward is recorded for this chain. The watermark only moves forward, so a
		// height that is rolled back and later resubmitted is not paid for a second time.
		let baseline = LastRewardedHeight::<T>::get(state_machine_id).unwrap_or(previous_height);

		let blocks = latest_height.saturating_sub(baseline);

		let blocks_as_balance: <T as pallet_ismp::Config>::Balance = blocks.saturated_into();
		let reward = blocks_as_balance.saturating_mul(block_cost);

		Ok(reward)
	}

	fn on_executed(
		messages: Vec<MessageWithWeight>,
		events: Vec<IsmpEvent>,
	) -> DispatchResultWithPostInfo {
		let maybe_relayer_account = messages.get(0).and_then(|first_message| {
			if let Message::Consensus(consensus_msg) = &first_message.message {
				let data = sp_io::hashing::keccak_256(&consensus_msg.consensus_proof);
				Signature::decode(&mut &consensus_msg.signer[..])
					.ok()
					.and_then(|sig| sig.verify_and_get_sr25519_pubkey(&data, None).ok())
					.map(|pub_key| pub_key.into())
			} else {
				None::<[u8; 32]>
			}
		});

		if let Some(relayer_account) = maybe_relayer_account {
			// When a batch contains multiple `StateMachineUpdated` events for the
			// same `state_machine_id` (sequential consensus updates for the same
			// chain), `calculate_reward` reads the same persisted
			// `(latest_commitment_height, previous_commitment_height)` pair on
			// every iteration and pays the same block-span reward N times.
			// Collapse the per-state-machine event stream to the single highest
			// `latest_height` so each state machine receives one reward per
			// batch, sized by the actual span of its commitment advance.
			let mut highest_per_state_machine: BTreeMap<StateMachineId, u64> = BTreeMap::new();
			for event in events {
				if let IsmpEvent::StateMachineUpdated(update) = event {
					highest_per_state_machine
						.entry(update.state_machine_id)
						.and_modify(|h| {
							if update.latest_height > *h {
								*h = update.latest_height;
							}
						})
						.or_insert(update.latest_height);
				}
			}

			for (state_machine_id, latest_height) in highest_per_state_machine {
				let state_machine_height =
					StateMachineHeight { id: state_machine_id.clone(), height: latest_height };

				let _ = Self::process_message(
					state_machine_height,
					state_machine_id,
					relayer_account.clone().into(),
				);
			}
		}
