Based on my analysis, there is a genuine local analog to the reported Executor/Axelar bug class: the shared `CallDispatcher` contract has an **unauthenticated arbitrary-call entrypoint** that can hold user/protocol funds mid-flow, exactly mirroring the "receiver contract holds funds but its execution trigger is callable by anyone" pattern from the report.

### Title
Unauthenticated `CallDispatcher.dispatch()` allows theft of tokens temporarily/residually held by the shared dispatcher - (File: `evm/src/utils/CallDispatcher.sol`)

### Summary
`CallDispatcher.dispatch(bytes)` is `external` with **no access control whatsoever** — no `onlyOwner`, no allowlist of callers, no restriction to the apps that are supposed to use it (`HyperFungibleToken`, `WrappedHyperFungibleToken`, `IntentGatewayV2`). [1](#0-0) 

This mirrors the reported bug class precisely: a contract that is designed to briefly custody funds during a composable "execute arbitrary calldata" step is reachable by anyone, so any balance it holds — even momentarily or as leftover residue — can be pulled out by an unrelated third party before the legitimate orchestrator sweeps it.

### Finding Description
Multiple apps intentionally route tokens through the same `CallDispatcher` instance to support composable "transfer-and-swap" flows:

- `HyperFungibleToken.onAccept` mints tokens to `beneficiary`, and if `beneficiary` is set to the `CallDispatcher` address (as the docs explicitly recommend for swap flows), then calls `ICallDispatcher(_dispatcher).dispatch(message.data)` to consume them. [2](#0-1) 
- `IntentGatewayV2` / `IntentsBase._execute` transfers order output assets to the dispatcher, executes attacker/solver-influenced `order.output.call`, and then sweeps back **only the tokens listed in `order.output.assets` (`outputsLen`)** — nothing else: [3](#0-2) 

Because the sweep in `_execute` is scoped strictly to the declared output token set, any token balance that ends up on the dispatcher outside that set — e.g. from a swap inside `order.output.call` that yields a token not declared as an output, dust from a partially-executed multi-hop call, or a fee-on-transfer/skim side effect — is left on the dispatcher indefinitely. Since `dispatch()` has no caller restriction, any unprivileged address can later call `CallDispatcher.dispatch()` directly with a `Call[]` such as `{to: leftoverToken, data: abi.encodeWithSelector(IERC20.transfer.selector, attacker, balance)}` and drain it. The same applies to the HFT/WrappedHFT flow if `message.data` fails to fully spend the minted/unlocked balance sent to the dispatcher-as-beneficiary.

This is the direct analog of the Axelar `Executor` finding: the fund-holding contract's execution trigger (`dispatch`/`executeWithToken`) is not gated to the legitimate orchestrator, so anyone can race to claim balances the contract is holding.

### Impact Explanation
Funds temporarily or residually held by the shared `CallDispatcher` — user output tokens, protocol dust, or bridged HFT/WrappedHFT balances routed through it for composability — can be stolen by any unprivileged third party who simply calls `dispatch()` with a crafted `Call[]`. This is a direct loss-of-funds / unauthorized-execution primitive matching the bounty's "stealing or loss of funds" and "unauthorized transaction or execution" categories.

### Likelihood Explanation
No privileged actor, relayer, prover, or admin is required. Any address that notices a nonzero token/ETH balance on the well-known, publicly-listed `CallDispatcher` address (a fixed, documented contract per chain) can immediately call `dispatch()` to exfiltrate it. The likelihood of leftover/uinswept balances existing depends on swap-slippage, multi-hop calldata, or fee-on-transfer tokens in `order.output.call` / `message.data`, all of which are realistic in composable DeFi routing.

### Recommendation
Restrict `CallDispatcher.dispatch()` to a caller allowlist (e.g., only the registered app contracts: `IntentGatewayV2`, `HyperFungibleToken`, `WrappedHyperFungibleToken`) via an `onlyAuthorizedCaller` modifier, or deploy a fresh, single-use dispatcher per call (e.g., via `CREATE2`/ephemeral proxy) so no shared, persistently-reachable balance can ever exist. Additionally, `_execute`'s sweep logic should sweep the dispatcher's *entire* balance of any token touched during `dispatch`, not just the declared `output.assets`, to avoid stranding non-declared tokens.

### Proof of Concept
1. A solver's `order.output.call` (postdispatch calldata) routes output tokens through a DEX that yields a small amount of an intermediate/reward token not listed in `order.output.assets` (e.g., a DEX loyalty token, or slippage-induced excess of a swap-path intermediate).
2. `IntentsBase._execute` calls `ICallDispatcher(dispatcher).dispatch(order.output.call)`, then builds `sweepCalls` only for `order.output.assets[i]` — the stray token is never included and remains on the dispatcher. [4](#0-3) 
3. Attacker (anyone, no special role) calls `CallDispatcher.dispatch(abi.encode([Call({to: strayToken, value: 0, data: abi.encodeWithSelector(IERC20.transfer.selector, attacker, strayToken.balanceOf(dispatcher))})]))` directly — this succeeds because `dispatch` has no access control. [1](#0-0) 
4. The stray token balance, which should have been swept as protocol dust, is now in the attacker's wallet.

    function dispatch(bytes memory encoded) external {
        Call[] memory calls = abi.decode(encoded, (Call[]));
        uint256 callsLen = calls.length;
        for (uint256 i = 0; i < callsLen; ++i) {
            Call memory call = calls[i];
            uint32 size;
            address to = call.to;
            assembly {
                size := extcodesize(to)
            }

            if (size == 0) {
                revert NotContract(to);
            }

            (bool success, bytes memory result) = to.call{value: call.value}(call.data);
            if (!success) revert CallFailed(to, result);
        }
    }

    function _execute(Order calldata order, uint256 outputsLen) internal {
        if (order.output.call.length == 0) return;

        address dispatcher = _params.dispatcher;
        ICallDispatcher(dispatcher).dispatch(order.output.call);

        Call[] memory sweepCalls = new Call[](outputsLen);
        uint256 sweepCount = 0;

        for (uint256 i; i < outputsLen;) {
            address token = address(uint160(uint256(order.output.assets[i].token)));

            if (token == address(0)) {
                uint256 balance = dispatcher.balance;
                if (balance > 0) {
                    sweepCalls[sweepCount] = Call({to: address(this), value: balance, data: ""});
                    sweepCount++;
                    emit DustCollected(token, balance);
                }
            } else {
                uint256 balance = IERC20(token).balanceOf(dispatcher);
                if (balance > 0) {
                    sweepCalls[sweepCount] = Call({
                        to: token,
                        value: 0,
                        data: abi.encodeWithSelector(IERC20.transfer.selector, address(this), balance)
                    });
                    sweepCount++;
                    emit DustCollected(token, balance);
                }
            }

            unchecked {
                ++i;
            }
        }

        if (sweepCount > 0) {
            Call[] memory finalCalls = new Call[](sweepCount);
            for (uint256 i; i < sweepCount;) {
                finalCalls[i] = sweepCalls[i];
                unchecked {
                    ++i;
                }
            }
            ICallDispatcher(dispatcher).dispatch(abi.encode(finalCalls));
        }
    }
