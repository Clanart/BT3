### Title
`aptos move verify-package` never compares on-chain bytecode to the locally-compiled bytecode, only compares package metadata - (File: `aptos-move/cli/src/stored_package.rs`)

### Summary
The Aptos CLI's `verify-package` command is documented and intended to prove that "on-chain bytecode matches a local source tree" [1](#0-0)  . In practice, `VerifyPackage::execute` fetches the on-chain `PackageRegistry` with `with_bytecode = false`, so it never downloads the actual on-chain module bytecode, and `CachedPackageMetadata::verify()` only diffs `PackageMetadata` fields (`name`, `deps`, `modules` [name/source/source_map/extension], `manifest`, `upgrade_policy`, `extension`, `source_digest`) - never the raw compiled bytes that were actually published and are executed by the VM.

### Finding Description
`VerifyPackage::execute` builds the package locally, extracts its metadata, then pulls the on-chain registry without bytecode and calls `package.verify(&compiled_metadata)`: [2](#0-1) 

`CachedPackageRegistry::create` only populates the `bytecode` map when `with_bytecode` is `true`; `VerifyPackage` calls it with `false`: [3](#0-2) [4](#0-3) 

`verify()` itself only compares `PackageMetadata` struct fields — none of which contain the compiled module bytecode. `ModuleMetadata` only carries `name`, gzipped `source`, gzipped `source_map`, and an `extension`; the field `source_digest` is a hash over the *source text*, not over the compiled bytecode: [5](#0-4) [6](#0-5) 

The actual bytecode that the VM executes is stored separately, as a normal on-chain "module" resource fetched via `get_account_module`, which is completely decoupled from `PackageMetadata`. `code::publish_package`/`request_publish[_with_allowed_deps]` never asserts that the published `code: vector<vector<u8>>` was compiled from the `modules[].source` in the same transaction's metadata — the Move VM's bytecode verifier only checks that the bytes are well-formed, compatible (if policy requires it), and satisfy allowed-dependency constraints; it has no notion of "this bytecode must match this source": [7](#0-6) [8](#0-7) 

Because nothing on-chain ties bytecode to declared source, and the CLI verifier compares only metadata (which can independently be made to match a legitimate source tree), a publisher can submit arbitrary bytecode alongside metadata whose `source`/`source_digest`/`manifest` genuinely correspond to an honest, auditable source file, while the actually-stored, actually-executing bytecode differs (e.g., contains additional logic, backdoors, or omitted checks). `verify-package` will report "Successfully verified source of package" even though the executing bytecode was never rebuilt from source and byte-compared.

### Impact Explanation
This breaks the "verified bytes, package metadata, dependency declarations must match committed module bytes" invariant. Users, auditors, or downstream tooling (indexers, wallets, marketplaces) that rely on `aptos move verify-package` (as advertised in the CLI docs) to determine that a published contract's bytecode matches an audited/reviewed source tree can be misled into trusting malicious bytecode as if it were the reviewed code. This is a code-safety/publish-verification bypass with real trust impact for any workflow gating trust decisions (fund deposits, listing on registries, granting elevated permissions) on `verify-package` output.

### Likelihood Explanation
High likelihood of triggering under normal usage: any account (unprivileged) can publish a package with metadata containing an honest source/`source_digest` while supplying different bytecode in the same `publish_package_txn`/`object_code_deployment::publish` call — there is no on-chain or CLI-side linkage enforcing bytecode-from-source correspondence in this comparison. No special privileges, race conditions, or governance interaction are required; it's a straightforward call ordering artifact (`with_bytecode = false`) plus a metadata-only comparison.

### Recommendation
- In `VerifyPackage::execute`, call `CachedPackageRegistry::create(client, self.account, true)` to fetch actual on-chain bytecode, and extend `verify()` to additionally compare each module's on-chain bytecode bytes against `BuiltPackage`'s freshly-compiled bytecode (`pack.extract_code()`), not just metadata.
- Consider hashing compiled bytecode into `PackageMetadata` (or a companion on-chain field) at publish time so mismatches between declared source and executed bytecode can be detected/enforced independent of the CLI tool.
- Update the CLI documentation to accurately reflect current behavior until the bytecode comparison is implemented, since it currently overstates the verification guarantee.

### Proof of Concept
1. Compile an honest Move package `P` from source `S`; extract its `PackageMetadata` `M_honest` (`extract_metadata()`), which includes `source_digest` computed over `S`.
2. Craft a maliciously modified bytecode module `B_evil` (e.g., recompiled from a backdoored variant of `S`, or hand-patched bytecode) that is bytecode-verifier-valid and (if `compatible` policy) compatible with any prior version.
3. Publish via `code::publish_package_txn(owner, bcs(M_honest), vec![B_evil])` — nothing in `code.move`/native `request_publish` checks that `B_evil` was compiled from `M_honest.modules[0].source`.
4. A reviewer runs `aptos move verify-package --account owner` against the honest source `S`. `VerifyPackage::execute` rebuilds `S` locally, gets `compiled_metadata == M_honest`, fetches the on-chain registry with `with_bytecode=false`, and calls `verify()`, comparing only metadata fields — all of which match `M_honest`. The command prints `"Successfully verified source of package"` despite `B_evil` (not `S`) being the code actually running on-chain.

Note: This analysis is based on the code available in the indexed snapshot; I was not able to fully trace every call site of `PackageMetadata`/bytecode handling (e.g., whether any indexer or other Aptos tooling independently cross-checks bytecode hashes) due to index size limits. If deeper verification of all consumers of `verify-package` output is needed, a full-repository Devin session would be required to confirm there is no other bytecode-linking check elsewhere in the stack.

    pub async fn create(
        client: Client,
        addr: AccountAddress,
        with_bytecode: bool,
    ) -> anyhow::Result<Self> {
        // Need to use a different type to deserialize JSON
        let inner = client
            .get_account_resource_bcs::<PackageRegistry>(addr, "0x1::code::PackageRegistry")
            .await?
            .into_inner();
        let mut bytecode = BTreeMap::new();
        if with_bytecode {
            for pack in &inner.packages {
                for module in &pack.modules {
                    let bytes = client
                        .get_account_module(addr, &module.name)
                        .await?
                        .into_inner()
                        .bytecode
                        .0;
                    bytecode.insert(module.name.clone(), bytes);
                }
            }
        }
        Ok(Self { inner, bytecode })
    }

    pub fn verify(&self, package_metadata: &PackageMetadata) -> anyhow::Result<()> {
        let self_metadata = self.metadata;

        if self_metadata.name != package_metadata.name {
            bail!(
                "Package name doesn't match {} : {}",
                package_metadata.name,
                self_metadata.name
            )
        } else if self_metadata.deps != package_metadata.deps {
            bail!(
                "Dependencies don't match {:?} : {:?}",
                package_metadata.deps,
                self_metadata.deps
            )
        } else if self_metadata.modules != package_metadata.modules {
            bail!(
                "Modules don't match {:?} : {:?}",
                package_metadata.modules,
                self_metadata.modules
            )
        } else if self_metadata.manifest != package_metadata.manifest {
            bail!(
                "Manifest doesn't match {:?} : {:?}",
                package_metadata.manifest,
                self_metadata.manifest
            )
        } else if self_metadata.upgrade_policy != package_metadata.upgrade_policy {
            bail!(
                "Upgrade policy doesn't match {:?} : {:?}",
                package_metadata.upgrade_policy,
                self_metadata.upgrade_policy
            )
        } else if self_metadata.extension != package_metadata.extension {
            bail!(
                "Extensions doesn't match {:?} : {:?}",
                package_metadata.extension,
                self_metadata.extension
            )
        } else if self_metadata.source_digest != package_metadata.source_digest {
            bail!(
                "Source digests doesn't match {:?} : {:?}",
                package_metadata.source_digest,
                self_metadata.source_digest
            )
        }

        Ok(())
    }

fn native_request_publish(
    context: &mut SafeNativeContext,
    _ty_args: &[Type],
    mut args: VecDeque<Value>,
) -> SafeNativeResult<SmallVec<[Value; 1]>> {
    debug_assert!(matches!(args.len(), 4 | 5));
    let with_allowed_deps = args.len() == 5;

    context.charge(CODE_REQUEST_PUBLISH_BASE)?;

    let policy = safely_pop_arg!(args, u8);
    let mut code = vec![];
    for module in safely_pop_arg!(args, Vec<Value>) {
        let module_code = module.value_as::<Vec<u8>>()?;

        context.charge(CODE_REQUEST_PUBLISH_PER_BYTE * NumBytes::new(module_code.len() as u64))?;
        code.push(module_code);
    }

    let allowed_deps = if with_allowed_deps {
        let mut allowed_deps: BTreeMap<AccountAddress, BTreeSet<String>> = BTreeMap::new();

        for dep in safely_pop_arg!(args, Vec<Value>) {
            let (account, module_name) = unpack_allowed_dep(dep)?;

            let entry = allowed_deps.entry(account);

            if let Entry::Vacant(_) = &entry {
                // TODO: Is the 32 here supposed to indicate the length of an account address in bytes?
                context.charge(CODE_REQUEST_PUBLISH_PER_BYTE * NumBytes::new(32))?;
            }

            context
                .charge(CODE_REQUEST_PUBLISH_PER_BYTE * NumBytes::new(module_name.len() as u64))?;
            entry.or_default().insert(module_name);
        }

        Some(allowed_deps)
    } else {
        None
    };

    let mut expected_modules = BTreeSet::new();
    for name in safely_pop_arg!(args, Vec<Value>) {
        let str = get_move_string(name)?;

        // TODO(Gas): fine tune the gas formula
        context.charge(CODE_REQUEST_PUBLISH_PER_BYTE * NumBytes::new(str.len() as u64))?;
        expected_modules.insert(str);
    }

    let destination = safely_pop_arg!(args, AccountAddress);

    // Add own modules to allowed deps
    let allowed_deps = allowed_deps.map(|mut allowed| {
        allowed
            .entry(destination)
            .or_default()
            .extend(expected_modules.clone());
        allowed
    });

    let code_context = context.extensions_mut().get_mut::<NativeCodeContext>();
    if code_context.requested_module_bundle.is_some() || !code_context.enabled {
        // Can't request second time or if publish requests are not allowed.
        return Err(SafeNativeError::abort(EALREADY_REQUESTED));
    }
    code_context.requested_module_bundle = Some(PublishRequest {
        destination,
        bundle: ModuleBundle::new(code),
        expected_modules,
        allowed_deps,
        check_compat: policy != ARBITRARY_POLICY,
    });

    Ok(smallvec![])
}
