### Title
Cross-chain order cancellation from destination allows overwriting a completed fill's escrow beneficiary, stealing the filler's payout - (File: `evm/src/apps/intentsv2/ExtrinsicIntents.sol`)

### Summary
`_cancelFromDest()` unconditionally overwrites `_filled[commitment]` and dispatches a `RefundEscrow` message back to the source chain, with **no check that the order was already filled** on the destination chain. `_fillCrossChain()` sets `_filled[commitment] = msg.sender` and delivers the filler's output tokens to the beneficiary *before* its `RedeemEscrow` message reaches the source chain [1](#0-0) . Because `_cancelFromDest` never checks that state, it can stomp a completed fill and redirect the source-chain escrow to the user via `RefundEscrow` instead of to the filler via `RedeemEscrow` [2](#0-1) .

### Finding Description
This mirrors the Rigor `inviteSC` bug exactly: a counterparty-binding value (`_filled[commitment]` / who is entitled to the escrow) is overwritten by a party (the order owner, `order.user`) even though the current state already reflects a confirmed, delivered obligation by another party (the filler), and no signature/consent from that other party is required or checked.

Concretely:
- `fillOrder()` on the destination chain routes cross-chain fills into `_fillCrossChain`, which immediately sets `_filled[commitment] = msg.sender` (the filler) and pays the beneficiary the output tokens, before dispatching a `RedeemEscrow` POST back to source [3](#0-2) .
- `cancelOrder`'s destination-chain path, `_cancelFromDest`, is reachable by the order owner before the deadline (and by anyone after the deadline) [4](#0-3) . It does **not** read or validate `_filled[commitment]` before proceeding — unlike `fillOrder`, which explicitly checks `if (_filled[commitment] != address(0)) revert Filled();` [5](#0-4) . `_cancelFromDest` simply reassigns `_filled[commitment] = address(uint160(uint256(order.user)))` and fires a `RefundEscrow` message [6](#0-5) .
- On the source chain, `onAccept` processes whichever of `RedeemEscrow`/`RefundEscrow` arrives and calls `_withdraw()`, which finalizes by unconditionally setting `_filled[body.commitment] = beneficiary` and paying out the escrow to that beneficiary — it does not check which kind was already finalized, or whether escrow was already released [7](#0-6) , [8](#0-7) .

Attack sequence: user places an order, deadline `D`. A filler fills it before `D` on the destination chain (delivers output tokens to beneficiary, `_filled[commitment]` now equals the filler). The `RedeemEscrow` message is in flight (not yet delivered/relayed to source). Before that message lands, the user (order owner — an unprivileged actor with no elevated permission needed, just the party who placed the order) calls `cancelOrder()` again on the destination chain while `block.number < order.deadline`. Because `_cancelFromDest` has no guard on `_filled[commitment]` already being set to the filler, it overwrites `_filled[commitment]` to the user's own address and dispatches `RefundEscrow` to source. If `RefundEscrow` reaches the source chain and calls `_withdraw` before `RedeemEscrow` does, the escrow is paid to the user instead of the filler — the filler already delivered real output tokens on the destination chain and receives nothing.

### Impact Explanation
Direct fund loss: the filler already transferred real value (`totalRequired + beneficiaryShare` output tokens) to the order's beneficiary on the destination chain, but a race lets the user reclaim the escrowed input tokens on the source chain instead of paying the filler — the same "steal the counterparty's already-earned payout by rebinding the settlement target" primitive as the Rigor report (subcontractor loses task budget after work is confirmed/done). This is unauthorized redirection of escrowed funds to the wrong beneficiary, matching the bounty's "stealing or loss of funds" / "wrong beneficiary" / "double-claim" categories.

### Likelihood Explanation
This requires no malicious relayer, prover, or admin — it only needs message-ordering/timing between two independently-dispatched ISMP POST messages (`RedeemEscrow` from destination, `RefundEscrow` from destination), both submitted by ordinary unprivileged actors (filler and order owner respectively) through the normal public `fillOrder`/`cancelOrder` entrypoints. Relative delivery order across two different dispatches is not something the contract enforces, so the outcome is attacker-influenceable by whichever party can get their message relayed first (e.g., by paying a higher relayer fee), not merely by luck.

### Recommendation
In `_cancelFromDest`, require `_filled[commitment] == address(0)` before allowing cancellation (mirroring the `Filled()` check already used in `fillOrder`), so a destination-side fill can never be overwritten by a later cancellation. On the source chain, `_withdraw`/`onAccept` should also reject a `RefundEscrow` (or `RedeemEscrow`) for a commitment whose escrow has already been finalized, rather than relying solely on the destination-side guard, to close any second point of trust.

### Proof of Concept
1. User places a cross-chain `Order` with `deadline = D`.
2. Filler calls `fillOrder()` on the destination chain before `D`; `_fillCrossChain` sets `_filled[commitment] = filler` and pays out `order.output` tokens to the beneficiary, then dispatches `RedeemEscrow` to source [9](#0-8) .
3. Before the `RedeemEscrow` message is relayed/delivered to source, the user calls `cancelOrder()` again on the destination chain (still `block.number < D`, so `order.user == msg.sender` passes the only check) [10](#0-9) . `_cancelFromDest` overwrites `_filled[commitment]` and dispatches `RefundEscrow` to source.
4. If the `RefundEscrow` message is delivered/relayed to the source chain before `RedeemEscrow`, `onAccept` → `_withdraw` pays the escrowed input tokens back to the user [7](#0-6) . The filler, who already delivered output tokens in step 2, never receives the escrow.

    function _fillCrossChain(Order calldata order, FillOptions calldata options, bytes32 commitment) internal {
        uint256 outputsLen = order.output.assets.length;

        _filled[commitment] = msg.sender;

        uint256 msgValue = msg.value;
        address beneficiary = address(uint160(uint256(order.output.beneficiary)));
        TokenInfo[] memory outputFills = new TokenInfo[](outputsLen);

        for (uint256 i; i < outputsLen; i++) {
            bytes32 outputToken = order.output.assets[i].token;
            if (options.outputs[i].token != outputToken) revert InvalidInput();

            address token = address(uint160(uint256(outputToken)));
            uint256 totalRequired = order.output.assets[i].amount;
            uint256 solverAmount = options.outputs[i].amount;

            if (solverAmount < totalRequired) revert InvalidInput();

            uint256 dust = solverAmount - totalRequired;
            uint256 beneficiaryShare = 0;
            uint256 protocolShare = 0;

            if (dust > 0) {
                if (order.output.call.length > 0) {
                    protocolShare = dust;
                } else {
                    protocolShare = (dust * _params.surplusShareBps) / 10_000;
                    beneficiaryShare = dust - protocolShare;
                }
            }

            if (token == address(0)) {
                if (msgValue < solverAmount) revert InsufficientNativeToken();
                uint256 beneficiaryTotal = totalRequired + beneficiaryShare;
                (bool sent,) = beneficiary.call{value: beneficiaryTotal}("");
                if (!sent) revert InsufficientNativeToken();
                msgValue -= (beneficiaryTotal + protocolShare);
            } else {
                IERC20(token).safeTransferFrom(msg.sender, beneficiary, totalRequired + beneficiaryShare);
                if (protocolShare > 0) {
                    IERC20(token).safeTransferFrom(msg.sender, address(this), protocolShare);
                }
            }
            if (protocolShare > 0) emit DustCollected(token, protocolShare);
            outputFills[i] = TokenInfo({token: outputToken, amount: totalRequired});
        }

        _execute(order, outputsLen);

        address hostAddr = host();
        bytes memory body = bytes.concat(
            bytes1(uint8(RequestKind.RedeemEscrow)),
            abi.encode(
                WithdrawalRequest({
                    commitment: commitment, tokens: order.inputs, beneficiary: bytes32(uint256(uint160(msg.sender)))
                })
            )
        );
        DispatchPost memory request = DispatchPost({
            dest: order.source,
            to: abi.encodePacked(_instance(order.source)),
            body: body,
            timeout: 0,
            fee: options.relayerFee,
            payer: msg.sender
        });

        if (options.nativeDispatchFee > 0 && msgValue >= options.nativeDispatchFee) {
            IDispatcher(hostAddr).dispatch{value: options.nativeDispatchFee}(request);
            msgValue -= options.nativeDispatchFee;
        } else {
            dispatchWithFeeToken(request);
        }

        // Refund any unspent native tokens to the solver.
        if (msgValue > 0) {
            (bool sent,) = msg.sender.call{value: msgValue}("");
            if (!sent) revert InsufficientNativeToken();
        }

        emit OrderFilled({commitment: commitment, filler: msg.sender, outputs: outputFills, inputs: order.inputs});
    }

    function _cancelFromDest(Order calldata order, CancelOptions calldata options, bytes32 commitment) internal {
        if (order.deadline >= _blockNumber()) {
            if (order.user != bytes32(uint256(uint160(msg.sender)))) revert Unauthorized();
        }

        _filled[commitment] = address(uint160(uint256(order.user)));

        bytes memory body = bytes.concat(
            bytes1(uint8(RequestKind.RefundEscrow)),
            abi.encode(WithdrawalRequest({commitment: commitment, tokens: order.inputs, beneficiary: order.user}))
        );

        DispatchPost memory request = DispatchPost({
            dest: order.source,
            to: abi.encodePacked(_instance(order.source)),
            body: body,
            timeout: 0,
            fee: options.relayerFee,
            payer: msg.sender
        });

        address hostAddr = host();
        if (msg.value > 0) {
            IDispatcher(hostAddr).dispatch{value: msg.value}(request);
        } else {
            dispatchWithFeeToken(request);
        }
    }
