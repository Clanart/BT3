## Title
Unbounded unbonding/redelegation queue processed in a single EndBlock loop can stall block production - (File: `sei-cosmos/x/staking/keeper/val_state_change.go`)

### Summary
The reported Perennial bug is a DoS caused by an unbounded pending-position queue that must be fully drained in a single settlement loop, letting an attacker (or organic congestion) grow the queue until processing it exceeds the gas/time budget and bricks every subsequent transaction. The `sei-cosmos` staking module has the same structural pattern: `BlockValidatorUpdates`, which runs unconditionally on every `EndBlock`, drains **all** unbonding-delegation and redelegation entries whose maturity time has passed with no per-block cap on how many entries can be processed at once.

### Finding Description
`BlockValidatorUpdates` calls `DequeueAllMatureUBDQueue` and `DequeueAllMatureRedelegationQueue`, both of which iterate every timeslice up to the current block time and return the full, unbounded list of matured `(delegator, validator)` pairs; the function then loops over the entire list, invoking `CompleteUnbonding`/`CompleteRedelegation` (bank transfers, state writes, event emission) for each one, with no batching or per-block work limit. [1](#0-0) 

`DequeueAllMatureUBDQueue` has no size cap — it concatenates every timeslice from time 0 up to the current block time in one pass: [2](#0-1) 

Entries are only bounded per `(delegator, validator)` pair via `HasMaxUnbondingDelegationEntries`, which caps entries for a single pair but does nothing to limit the total number of distinct pairs that can mature in the same timeslice: [3](#0-2) 

Because the completion time for a new unbonding entry is computed as `ctx.BlockHeader().Time.Add(k.UnbondingTime(ctx))`, all `MsgUndelegate`/`MsgBeginRedelegate` transactions included in the *same block* land in exactly the same queue timeslice (since `UnbondingTime` is a constant chain parameter). An attacker can spread cheap, ordinary delegations across many distinct accounts, undelegate all of them within one block, and have all resulting entries mature together in a single future block — at which point `BlockValidatorUpdates` must process them all in one unbounded loop.

By contrast, the governance module (`sei-cosmos/x/gov/abci.go`) explicitly introduces a `MaxVotesProcessedPerBlock` work budget specifically to avoid unbounded EndBlock work of this kind: [4](#0-3) 
No equivalent budget exists for the UBD/redelegation queues, showing this specific class of issue was addressed in one module but not the other.

Separately, `EndBlock`/`BeginBlock` execution in this codebase runs without an enforced block gas meter (confirmed by a test comment noting the block gas meter was removed for tx execution), so this unbounded loop cannot OOG-panic the way the Perennial `Market` bug does — but it will still consume real wall-clock time proportional to the number of matured entries, since every entry triggers KV-store reads/writes and a bank transfer. [5](#0-4) 

### Impact Explanation
If a sufficiently large number of `(delegator, validator)` pairs are engineered to mature in the same block (via ordinary, unprivileged `MsgUndelegate`/`MsgBeginRedelegate` transactions from many funded accounts), `BlockValidatorUpdates` must process the entire batch synchronously and deterministically on every validator during `EndBlock`. This is consensus-critical work that all validators must perform identically before the block can be committed; a sufficiently large batch can push per-block processing time well past normal block intervals, causing network-wide block delay (a listed acceptable impact — "block delay beyond 2.5 seconds"), and in extreme cases repeated, sustained batches could be used to keep inflating processing time across consecutive blocks.

### Likelihood Explanation
Reaching this state requires no privileged access, no validator/node compromise, and no governance action — only ordinary delegate/undelegate transactions from a number of funded accounts, submitted so their undelegations fall in the same block (and thus the same completion-time timeslice). The cost is the minimum stake required per account plus ordinary transaction fees; the number of accounts needed scales with how many matured entries are needed to produce a meaningful delay, so likelihood is a function of the affordable attack size versus how much per-entry work (`CompleteUnbonding`/`CompleteRedelegation`) costs in wall-clock time. This mirrors the original Perennial finding's judged severity: the precondition (accumulating a large unbounded batch) is achievable at low cost by an ordinary user without needing any external/faulty actor.

### Recommendation
Introduce a per-block work budget for `DequeueAllMatureUBDQueue`/`DequeueAllMatureRedelegationQueue` processing in `BlockValidatorUpdates`, analogous to the `MaxVotesProcessedPerBlock` budget already used in the governance module: process only up to N matured entries per `EndBlock`, leaving the remainder in the queue (keyed by their original maturity time) to be drained across subsequent blocks. Alternatively, bound the total number of distinct pending entries that can share the same completion timeslice, or process the queue in bounded batches keyed by an internal cursor rather than draining it entirely in one call.

### Proof of Concept
1. Fund N distinct accounts, each with the minimum stake needed to delegate to a validator.
2. In a single block B, submit N `MsgDelegate` (or use pre-existing delegations) followed by N `MsgUndelegate` transactions from the N accounts to one or more validators. Each resulting `UnbondingDelegation` entry receives `completionTime = B.Time + UnbondingTime`, placing all N entries in the same UBD queue timeslice (`sei-cosmos/x/staking/keeper/delegation.go:354-366`).
3. When the chain reaches block time `B.Time + UnbondingTime`, `staking.EndBlocker` → `BlockValidatorUpdates` calls `DequeueAllMatureUBDQueue`, which returns all N pairs at once, then loops calling `CompleteUnbonding` for each of the N entries within that single `EndBlock` (`sei-cosmos/x/staking/keeper/val_state_change.go:32-58`).
4. Scaling N (number of Sybil-able but individually-funded accounts) increases the wall-clock time this single `EndBlock` call takes, since there is no per-block cap, unlike the equivalent gov-module cleanup which enforces `MaxVotesProcessedPerBlock`.

// DequeueAllMatureUBDQueue returns a concatenated list of all the timeslices inclusively previous to
// currTime, and deletes the timeslices from the queue.
func (k Keeper) DequeueAllMatureUBDQueue(ctx sdk.Context, currTime time.Time) (matureUnbonds []types.DVPair) {
	store := ctx.KVStore(k.storeKey)

	// gets an iterator for all timeslices from time 0 until the current Blockheader time
	unbondingTimesliceIterator := k.UBDQueueIterator(ctx, ctx.BlockHeader().Time)
	defer func() { _ = unbondingTimesliceIterator.Close() }()

	for ; unbondingTimesliceIterator.Valid(); unbondingTimesliceIterator.Next() {
		timeslice := types.DVPairs{}
		value := unbondingTimesliceIterator.Value()
		k.cdc.MustUnmarshal(value, &timeslice)

		matureUnbonds = append(matureUnbonds, timeslice.Pairs...)

		store.Delete(unbondingTimesliceIterator.Key())
	}

	return matureUnbonds
}

// Undelegate unbonds an amount of delegator shares from a given validator. It
// will verify that the unbonding entries between the delegator and validator
// are not exceeded and unbond the staked tokens (based on shares) by creating
// an unbonding object and inserting it into the unbonding queue which will be
// processed during the staking EndBlocker.
func (k Keeper) Undelegate(
	ctx sdk.Context, delAddr sdk.AccAddress, valAddr sdk.ValAddress, sharesAmount sdk.Dec,
) (time.Time, error) {
	validator, found := k.GetValidator(ctx, valAddr)
	if !found {
		return time.Time{}, types.ErrNoDelegatorForAddress
	}

	if k.HasMaxUnbondingDelegationEntries(ctx, delAddr, valAddr) {
		return time.Time{}, types.ErrMaxUnbondingDelegationEntries
	}

	returnAmount, err := k.Unbond(ctx, delAddr, valAddr, sharesAmount)
	if err != nil {
		return time.Time{}, err
	}

	// transfer the validator tokens to the not bonded pool
	if validator.IsBonded() {
		k.bondedTokensToNotBonded(ctx, returnAmount)
	}

	completionTime := ctx.BlockHeader().Time.Add(k.UnbondingTime(ctx))
	ubd := k.SetUnbondingDelegationEntry(ctx, delAddr, valAddr, ctx.BlockHeight(), completionTime, returnAmount)
	k.InsertUBDQueue(ctx, ubd, completionTime)
