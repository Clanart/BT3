## Analysis

The external report's broken invariant is: **a privileged action (`setAdmin`) trusts an attacker-reachable input with no authorization check**, letting the caller escalate and drain funds. The closest reachable Desktop analog is **a privileged main-process capability (opening arbitrary OS-level content via `shell.openExternal`) that trusts renderer-supplied strings with no protocol allow-list at the trust boundary**, even though a partial guard exists at exactly one call site.

Most other "access-control"-shaped surfaces I checked in this codebase are already hardened:
- IPC sender identity is checked via `isTrustedIPCSender` in `app/src/main-process/ipc-main.ts:53-65` [1](#0-0) 
- `open-repository-from-url`'s `filepath` param is validated with `isAbsolute`/`resolveWithin` containment checks in `app/src/ui/dispatcher/dispatcher.ts:1957-1972` [2](#0-1) 
- Clone path traversal is blocked by `sanitizeCloneName`/`isClonePathSensitive` in `app/src/lib/remote-parsing.ts:88-116` and `app/src/lib/git/clone.ts:16-47` [3](#0-2) [4](#0-3) 
- Markdown-rendered links are gated to `https?` before ever reaching a click handler: `app/src/ui/lib/sandboxed-markdown.tsx:292-305` [5](#0-4) 

But that last guard is enforced **only in one renderer component** (`sandboxed-markdown.tsx`), not at the actual trust boundary — the main-process IPC handler that performs the privileged OS action.

### Title
Missing protocol allow-list in `open-external` IPC handler lets any renderer-supplied string reach `shell.openExternal` - (File: app/src/main-process/main.ts)

### Summary
The main-process `open-external` IPC handler accepts any string from the renderer and passes it directly to Electron's `shell.openExternal`, only using the `http(s)` check for logging — not for gating the call. The one place in the codebase that does enforce a protocol allow-list (`setupLinkInterceptor` in `sandboxed-markdown.tsx`) is a renderer-side, per-component check, not an invariant enforced at the actual privilege boundary (the main process). Any current or future caller of `openExternal`/`open-external` that forwards a URL sourced from repository or GitHub API data without first validating its scheme bypasses that lone check.

### Finding Description
`ipcMain.handle('open-external', ...)` in `app/src/main-process/main.ts` does this:
```
ipcMain.handle('open-external', async (_, path: string) => {
  const pathLowerCase = path.toLowerCase()
  if (pathLowerCase.startsWith('http://') || pathLowerCase.startsWith('https://')) {
    log.info(`opening in browser: ${path}`)
  }
  try {
    await shell.openExternal(path)
    return true
  } ...
})
``` [6](#0-5) 

The `http(s)` check only controls a log line; there is no `else return false` branch, so **any scheme is forwarded to `shell.openExternal` unconditionally**. This handler is exposed to the renderer as the app-wide "open a link/URL" primitive (`app/src/lib/ipc-shared.ts`, `main-process-proxy.ts`).

Multiple renderer call sites forward URLs to this same OS-level primitive without any protocol check of their own, e.g.:
- `LinkButton.onClick` calls `shell.openExternal(uri)` directly for any `uri` prop passed to it — `app/src/ui/lib/link-button.tsx:83-86` [7](#0-6) 
- `AppStore._openInBrowser(url)` calls `shell.openExternal(url)` directly with no scheme validation — `app/src/lib/stores/app-store.ts:7594-7597` [8](#0-7) 
- `release-notes-dialog.tsx`'s `onMarkdownLinkClicked` calls `shell.openExternal(url)` directly — `app/src/ui/release-notes/release-notes-dialog.tsx:206-208` [9](#0-8) 

The only place that filters to `https?:` before invoking `onMarkdownLinkClicked` is `setupLinkInterceptor` in `sandboxed-markdown.tsx:292-305`. That means the "safe scheme" invariant is currently expressed as a UI-layer habit in one file, not as a hard guarantee at the IPC/main-process boundary where the actual OS-level action (`shell.openExternal`) is performed. This is structurally analogous to the FPR contract's `setAdmin`: the privileged action (`openExternal`, capable of invoking OS URL/protocol handlers, `file:`/UNC paths, or registered custom-protocol executables) is reachable through a path whose only protection is a check that lives outside of, and is not enforced by, the privileged function itself.

### Impact Explanation
Electron's `shell.openExternal` is explicitly called out in Electron's own security guidance (#17/#20) as dangerous when passed unsanitized data, because non-`http(s)` schemes can trigger OS shell/protocol handlers — on Windows this includes invoking registered custom URI handlers, `file:`/UNC path execution, or launching arbitrary local applications, which can lead to local code execution outside of any git-repository sandbox. Because the enforcement point (`sandboxed-markdown.tsx`) is separate from the privileged sink (`main.ts`'s `open-external` handler and the various direct `shell.openExternal` call sites), any current or future code path that forwards attacker-influenced content (e.g., a PR/issue/comment body field, a repo homepage URL, or other GitHub API-sourced string) to one of the unguarded call sites reaches the OS shell with no scheme restriction.

### Likelihood Explanation
I could not, within the scope of this review, positively confirm a currently-reachable code path where a non-`http(s)` scheme sourced directly from attacker-controlled repository/API content flows into `LinkButton`, `_openInBrowser`, or the `open-external` IPC handler without first passing through the `sandboxed-markdown.tsx` https-only filter — most of the API-derived URLs I inspected (`htmlURL`, PR links) are values GitHub itself controls. This finding should therefore be treated as a **defense-in-depth gap / missing invariant enforcement at the trust boundary** rather than a confirmed, fully-chained exploit: the guard exists in one component but is absent from the actual privileged primitive, so its safety depends entirely on every future caller remembering to re-implement the same check.

### Recommendation
Move the scheme allow-list into the privileged boundary itself rather than relying on a single renderer component:
- In `ipcMain.handle('open-external', ...)` (`app/src/main-process/main.ts:581-597`), reject (return `false`, do not call `shell.openExternal`) any `path` whose scheme is not in an explicit allow-list (`http:`, `https:`, `mailto:` if needed).
- Apply the same allow-list inside `shell.openExternal`/`_openInBrowser` wrappers in `app/src/lib/stores/app-store.ts` and `app/src/ui/lib/link-button.tsx` so the check is centralized and cannot be bypassed by any call site that forgets it.

### Proof of Concept
Conceptual PoC (not independently verified end-to-end against a live attacker-controlled sink):
1. Renderer code calls `ipcRenderer.invoke('open-external', 'somecustomscheme://payload')` (or any component using `LinkButton uri="somecustomscheme://payload"` / `dispatcher.openInBrowser('somecustomscheme://payload')`).
2. `main.ts`'s handler logs nothing meaningful (it isn't `http(s)`) but still calls `shell.openExternal('somecustomscheme://payload')` unconditionally — see `app/src/main-process/main.ts:581-597`.
3. Electron/OS dispatches the URI to whatever handler is registered for `somecustomscheme:`, which — depending on what's installed on the victim's machine — may launch arbitrary local applications or perform OS-level actions outside GitHub Desktop's control, with no user-visible warning inside the app itself.

export function sanitizeCloneName(name: string): string | null {
  const components = name.split(/[/\\:]/)

  let lastComponent = ''
  for (let i = components.length - 1; i >= 0; i--) {
    if (components[i].length > 0) {
      lastComponent = components[i]
      break
    }
  }

  if (lastComponent.length === 0) {
    return null
  }

  if (lastComponent.endsWith('.git')) {
    lastComponent = lastComponent.slice(0, -4)
  }

  if (
    lastComponent === '..' ||
    lastComponent === '.' ||
    lastComponent.length === 0
  ) {
    return null
  }

  return lastComponent
}

function isClonePathSensitive(unresolvedClonePath: string): boolean {
  const clonePath = Path.resolve(unresolvedClonePath).toLowerCase()
  const home = Path.resolve(homedir()).toLowerCase()

  if (clonePath === home) {
    return true
  }

  const sensitiveLocations = [
    Path.join(home, '.ssh'),
    Path.join(home, '.gnupg'),
    Path.join(home, '.config'),
    Path.join(home, '.config', 'git'),
    Path.join(home, '.gitconfig'),
  ]

  if (__WIN32__) {
    const appData = process.env.APPDATA
    if (appData) {
      sensitiveLocations.push(appData.toLowerCase())
      sensitiveLocations.push(Path.join(appData, 'gnupg').toLowerCase())
    }
  }

  for (const sensitive of sensitiveLocations) {
    if (clonePath === sensitive || clonePath.startsWith(sensitive + Path.sep)) {
      return true
    }
  }

  return false
}
