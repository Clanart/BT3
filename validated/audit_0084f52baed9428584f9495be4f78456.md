### Title
Unbounded recursive outer-puzzle "also"-chain unwrapping in offer parsing leads to Python recursion/stack exhaustion (analog of CVE-2024-4140) - ([File: chia/wallet/trading/offer.py])

### Summary
CVE-2024-4140 describes Email-MIME's failure to bound recursion depth/part count when parsing attacker-supplied multipart messages, leading to excessive memory/CPU use (DoS). The analogous pattern in this codebase is `Offer._get_offered_coins()` in `chia/wallet/trading/offer.py`, which recursively unwinds a coin spend's outer-puzzle "layers" via `match_puzzle()` / `get_inner_puzzle()` / `get_inner_solution()` with no limit on layer/recursion depth, driven entirely by attacker-controlled curried puzzle structure inside an offer file.

### Finding Description
`Offer._get_offered_coins()` iterates every `CoinSpend` in an offer bundle and, for each one, calls `match_puzzle(parent_puzzle)` [1](#0-0) , which walks the `driver_lookup` table and recurses through each outer-puzzle driver's `match`, `get_inner_puzzle`, and `get_inner_solution` methods via the `also` chain [2](#0-1) .

Every driver implementation (`CATOuterPuzzle`, `OwnershipOuterPuzzle`, `MetadataOuterPuzzle`, `SingletonOuterPuzzle`, `CROuterPuzzle`, etc.) recurses into `self._match`/`self._get_inner_puzzle`/`self._get_inner_solution` for its `also()` sub-driver whenever the puzzle reveal is curried with another recognized outer-puzzle mod inside it, e.g.: [3](#0-2) [4](#0-3) [5](#0-4) 

None of these recursive match/uncurry chains enforce a maximum nesting depth. A `puzzle_reveal` can be crafted (e.g. `construct_cat_puzzle(CAT_MOD, tail, construct_cat_puzzle(CAT_MOD, tail, construct_cat_puzzle(...)))`, nested arbitrarily deep, or mixing CAT/CR/Ownership/Metadata/Singleton layers) so that `match_puzzle` and the paired `get_inner_puzzle`/`get_inner_solution` calls recurse to a depth chosen entirely by the attacker who authored the offer file. This mirrors the MIME bug class: a document format that supports arbitrary nesting depth, parsed by code that recurses once per nesting level without a depth/part-count cap.

Critically, `_get_offered_coins()` also uses `cost_left = INFINITE_COST` when running the *inner* puzzle for each parent spend [6](#0-5) , so ordinary CLVM cost metering that would otherwise bound resource use does not constrain this parsing path — the driver-matching recursion itself is not CLVM-cost-metered at all, since it is pure Python-level curried-argument unwrapping (`uncurry_puzzle`, `curried_args`, `also()`), independent of `run_with_cost`.

### Impact Explanation
An attacker can construct a spend bundle (offer file) whose puzzle reveals contain many nested recognized outer-puzzle layers. When any wallet user, offer counterparty, or RPC caller inspects/summarizes/loads that offer (a routine, low-trust action performed before signing or accepting a trade), `match_puzzle`/`get_inner_puzzle`/`get_inner_solution` recurse once per crafted layer. Because Python has a finite call-stack recursion limit, sufficiently deep nesting raises an uncaught `RecursionError`, crashing/halting the wallet's offer-processing code path (a spend/offer-triggered transaction-processing halt) for any user who merely inspects a malicious offer — without the attacker needing to spend real CLVM cost, since the outer-puzzle driver recursion is unmetered and happens outside of `run_with_cost`'s cost tracking. This is a legitimate availability impact reachable by an unprivileged offer counterparty who supplies a malicious offer to a victim wallet.

### Likelihood Explanation
Likelihood is Medium: constructing nested outer-puzzle layers (CAT-of-CAT, CR-of-CAT, Ownership-of-Metadata-of-Singleton, etc.) requires only standard puzzle-construction helpers already present in the wallet code (`construct_cat_puzzle`, `construct_cr_layer`, `puzzle_for_ownership_layer`, etc.), no signature or on-chain validity is required to trigger the crash since it happens during local parsing/summary generation before broadcast, and any wallet user who opens an untrusted `.offer` file or receives one via a trading UI is exposed.

### Recommendation
Add an explicit maximum recursion/nesting-depth limit to `match_puzzle`, `get_inner_puzzle`, and `get_inner_solution` (and their per-driver `also()`-chain implementations) in `chia/wallet/outer_puzzles.py` and the individual outer-puzzle driver classes, rejecting puzzles that exceed a small, fixed number of layers (mirroring the depth/part-count caps added by the Email-MIME patch). Additionally, bound `_get_offered_coins()`'s use of `INFINITE_COST` with the standard mempool/tx cost limit so offer summarization cannot bypass normal resource accounting.

### Proof of Concept
1. Construct a deeply nested CAT puzzle: `p = ACS; for i in range(N): p = construct_cat_puzzle(CAT_MOD, tail, p)` with `N` in the thousands (well beyond Python's default recursion limit of ~1000).
2. Build a `CoinSpend`/`WalletSpendBundle` whose `puzzle_reveal` is this deeply nested puzzle, wrap it into an `Offer` object (`Offer.from_spend_bundle`), and serialize it as an offer file.
3. Have a victim wallet call the offer-summary/inspection code path that invokes `Offer._get_offered_coins()` (reachable via the wallet RPC `get_offer_summary`/trade-manager offer-inspection flow) on the attacker-supplied offer.
4. Observe `match_puzzle()` recursing through `CATOuterPuzzle.match()`'s `self._match` chain `N` times, raising `RecursionError` and halting offer processing for the wallet.

def match_puzzle(puzzle: UnknownPuzzle) -> PuzzleInfo | None:
    for driver in driver_lookup.values():
        potential_info: PuzzleInfo | None = driver.match(puzzle)
        if potential_info is not None:
            return potential_info
    return None


def construct_puzzle(constructor: PuzzleInfo, inner_puzzle: Program) -> Program:

    def match(self, puzzle: UnknownPuzzle) -> PuzzleInfo | None:
        args = match_cat_puzzle(puzzle)
        if args is None:
            return None
        _, tail_hash, inner_puzzle = args
        constructor_dict: dict[str, Any] = {
            "type": "CAT",
            "tail": "0x" + tail_hash.as_atom().hex(),
        }
        next_constructor = self._match(UnknownPuzzle(known_program=inner_puzzle))
        if next_constructor is not None:
            constructor_dict["also"] = next_constructor.info
        return PuzzleInfo(constructor_dict)

    def get_inner_puzzle(
        self, constructor: PuzzleInfo, puzzle_reveal: UnknownPuzzle, solution: Program | None = None
    ) -> Program | None:
        args = match_cat_puzzle(puzzle_reveal)
        if args is None:
            raise ValueError("This driver is not for the specified puzzle reveal")
        _, _, inner_puzzle = args
        also = constructor.also()
        if also is not None:
            deep_inner_puzzle: Program | None = self._get_inner_puzzle(
                also,
                UnknownPuzzle(known_program=inner_puzzle),
                solution.first() if solution is not None else None,
            )
            return deep_inner_puzzle
        else:
            return inner_puzzle
