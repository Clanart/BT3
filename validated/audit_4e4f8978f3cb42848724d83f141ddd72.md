### Title
DataLayer permissionless mirror URLs cause Server-Side Request Forgery on subscribed nodes - ([File: chia/data_layer/data_layer.py])

### Summary
Any wallet-connected spend-bundle submitter can create an on-chain "mirror" coin for an arbitrary DataLayer store (`launcher_id`) embedding arbitrary attacker-controlled URLs in its memos, with no authorization or ownership check tying the mirror to the store owner. A node that subscribes to that store will later pull these URLs into its server list and issue outbound HTTP requests to them via `http_download`, exactly analogous to the PostHog `slack_incoming_webhook` SSRF where an unvalidated, attacker-influenced URL is fetched by the server.

### Finding Description
`create_mirror_puzzle()` returns a generic anyone-can-spend puzzle (`P2_PARENT.curry(Program.to(1))`), so any spend bundle can create a coin with this puzzle hash and place `[launcher_id, *urls]` in the coin memos: [1](#0-0) 

`DataLayerWallet.coin_added` observes any coin with this puzzle hash, extracts `launcher_id` and `urls` from the parent spend via `get_mirror_info`, and — as long as the wallet is tracking that `launcher_id` (which happens automatically for any subscribed/owned store) — stores it as a `Mirror` record with **no check that the mirror creator owns or controls the store/singleton**: [2](#0-1) 

`DataLayer.update_subscriptions_from_wallet()` then pulls all mirror URLs for the store id (regardless of who published them) and feeds them straight into the local subscription server list: [3](#0-2) 

During the periodic sync loop, `fetch_and_validate()` randomly selects one of these server URLs and attempts to download delta files from it via `insert_from_delta_file()` → `download_file()` → `http_download()`, with no validation that the URL is not pointing at internal/loopback/link-local/metadata endpoints: [4](#0-3) [5](#0-4) 

The client_timeout/HTTP behavior and error handling around this fetch are visible from tests exercising `insert_from_delta_file`/`download_file` with attacker-arbitrary `ServerInfo(url=...)` values, confirming the URL is used directly for outbound requests with no allow-list or destination restriction: [6](#0-5) 

### Impact Explanation
Any user able to submit a spend bundle (no special privilege, no ownership of the DataLayer singleton) can force any node subscribed to that store — potentially operated by a third party who never asked to trust the attacker — to make outbound HTTP requests to attacker-chosen destinations. This can be used to:
- Probe/pivot into internal network services or cloud metadata endpoints reachable from the victim host (classic SSRF information disclosure/pivot).
- DoS via slow/hanging endpoints, since each fetch attempt occupies the sync loop for that store (mitigated somewhat by timeouts and the failure-backoff mechanism, but still a forced outbound connection to attacker infrastructure).
- Leak node IP/fingerprinting information to the attacker's server (server logs which store/node fetched a given delta filename).

This satisfies the "coin-set divergence"/reachable-impact bar loosely as an information-disclosure/SSRF primitive triggered by a single, unauthorized, permissionless on-chain action (creating a mirror coin), matching the CVE-2025-1521 bug class (unauthenticated/low-privilege user supplies a URL that the server fetches without validation).

### Likelihood Explanation
High likelihood of reachability: creating a mirror coin requires only a standard spend bundle to a well-known puzzle hash with memos — no special wallet ownership of the target `launcher_id`/store is enforced anywhere in `coin_added`. Any node that subscribes to (or owns and syncs) that store id will pick up the attacker's mirror URL the next time `update_subscription()`/`fetch_and_validate()` runs. The `.cursor/context/data-layer.md` notes explicitly warn "Do not treat mirror URLs, plugins, or static file names as trusted data sources," indicating the developers were aware mirror URLs are an external trust boundary, but no destination validation (e.g., blocking private/loopback/link-local ranges) is implemented in `http_download`/`download_file`.

### Recommendation
- In `DataLayerWallet.coin_added`, restrict mirror acceptance to mirrors created by the store owner (verify authority over the singleton) or otherwise document/enforce that mirrors are informational-only and require explicit local operator opt-in/allow-listing before being dialed.
- In `download_data.py`'s `http_download`/`download_file`, validate resolved URLs against a deny-list of private/loopback/link-local/metadata address ranges (SSRF hardening) before issuing requests, and support operator-configurable mirror URL allow-lists.
- Rate-limit/backoff more aggressively per store id to reduce DoS potential from spam mirrors.

### Proof of Concept
1. Attacker (any wallet holder, no relationship to the store owner) submits a spend bundle creating a coin with `puzzle_hash == create_mirror_puzzle().get_tree_hash()` and memos `[launcher_id_of_target_store, b"http://169.254.169.254/latest/meta-data/", ...]`, as demonstrated by the mirror-creation flow in: [7](#0-6) 
2. Victim node subscribed to `launcher_id` confirms the coin; `coin_added` records the attacker's URL as a `Mirror` for that store with no ownership check (lines cited above).
3. On the next `periodically_manage_data()`/`update_subscription()` cycle, `update_subscriptions_from_wallet()` copies the URL into the local server list, and `fetch_and_validate()` randomly selects and dials it via `http_download`, causing the victim node to issue an outbound request to the attacker-chosen internal/arbitrary address.

Note: I was not able to inspect the full body of `http_download()` itself (only its call sites and signature) due to index truncation of `download_data.py` between the shown line ranges; a Devin session with full file access should confirm whether any destination filtering already exists there before implementing the fix.

```python
def create_mirror_puzzle() -> Program:
    return P2_PARENT.curry(Program.to(1))


MIRROR_PUZZLE_HASH = create_mirror_puzzle().get_tree_hash()


def get_mirror_info(
    parent_puzzle: Program | SerializedProgram, parent_solution: Program | SerializedProgram
) -> tuple[bytes32, list[bytes]]:
    assert type(parent_puzzle) is type(parent_solution)
    _, conditions = run_with_cost(parent_puzzle, INFINITE_COST, parent_solution)
    for condition in conditions.as_iter():
        if (
            condition.first().as_python() == ConditionOpcode.CREATE_COIN
            and condition.at("rf").as_python() == create_mirror_puzzle().get_tree_hash()
        ):
            memos: list[bytes] = condition.at("rrrf").as_python()
            launcher_id = bytes32(memos[0])
            return launcher_id, [url for url in memos[1:]]
```

```python
    async def coin_added(
        self, coin: Coin, height: uint32, peer: WSChiaConnection, coin_data: object | None, sync_scope: WalletSyncScope
    ) -> None:
        if coin.puzzle_hash == create_mirror_puzzle().get_tree_hash():
            parent_state: CoinState = (
                await self.wallet_state_manager.wallet_node.get_coin_state([coin.parent_coin_info], peer=peer)
            )[0]
            parent_spend = await fetch_coin_spend(height, parent_state.coin, peer)
            assert parent_spend is not None
            launcher_id, urls = get_mirror_info(parent_spend.puzzle_reveal, parent_spend.solution)
            # Don't track mirrors with empty url list.
            if not urls:
                return
            if await self.wallet_state_manager.dl_store.is_launcher_tracked(launcher_id):
                ours: bool = await self.wallet_state_manager.get_wallet_for_coin(coin.parent_coin_info) is not None
                await self.wallet_state_manager.dl_store.add_mirror(
                    Mirror(
                        coin.name(),
                        launcher_id,
                        uint64(coin.amount),
                        Mirror.decode_urls(urls),
                        ours,
                        height,
                    )
                )
                await self.wallet_state_manager.add_interested_coin_ids([coin.name()])
```

```python
async def download_file(
    data_store: DataStore,
    target_filename_path: Path,
    store_id: bytes32,
    root_hash: bytes32,
    generation: int,
    server_info: ServerInfo,
    proxy_url: str | None,
    downloader: PluginRemote | None,
    timeout: aiohttp.ClientTimeout,
    client_foldername: Path,
    timestamp: int,
    log: logging.Logger,
    grouped_by_store: bool,
    group_downloaded_files_by_store: bool,
    max_delta_file_size: int,
) -> bool:
    if target_filename_path.exists():
        return True
    filename = get_delta_filename(store_id, root_hash, generation, grouped_by_store)

    if downloader is None:
        # use http downloader - this raises on any error
        try:
            await http_download(
                target_filename_path, filename, proxy_url, server_info, timeout, log, max_delta_file_size
            )
        except (asyncio.TimeoutError, aiohttp.ClientError, MaxDeltaFileSizeExceededError):
            new_server_info = await data_store.server_misses_file(store_id, server_info, timestamp)
            log.info(
                f"Failed to download {filename} from {new_server_info.url}."
                f"Miss {new_server_info.num_consecutive_failures}."
            )
            log.info(f"Next attempt from {new_server_info.url} in {new_server_info.ignore_till - timestamp}s.")
            return False
        return True
```
