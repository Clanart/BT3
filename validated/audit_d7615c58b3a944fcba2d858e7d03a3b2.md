### Title
TokenFactory Denom Allow-List Bypassed via EVM Bank Precompile `send`/`sendNative` - (File: precompiles/bank/bank.go)

### Summary
The tokenfactory "restricted denom" allow-list is only enforced in the Cosmos `MsgSend`/`MsgMultiSend` handler path (`sei-cosmos/x/bank/keeper/msg_server.go`), which explicitly calls `IsInDenomAllowList` before invoking `SendCoins`. The underlying keeper primitives — `BaseSendKeeper.SendCoins`, `SendCoinsWithoutAccCreation`, and `SendCoinsAndWei` in `sei-cosmos/x/bank/keeper/send.go` — do not perform this check themselves. The EVM `bank` precompile (`precompiles/bank/bank.go`, plus every legacy version under `precompiles/bank/legacy/*`) calls these keeper methods directly from `send()` and `sendNative()`, never routing through `MsgSend` or calling `IsInDenomAllowList`.

### Finding Description
`IsInDenomAllowList` is a route-specific check, not a keeper-level invariant. `sei-cosmos/x/bank/keeper/msg_server.go`'s `Send` builds an `allowListCache` and calls `k.IsInDenomAllowList(ctx, from, ...)` and `k.IsInDenomAllowList(ctx, to, ...)` before calling `k.SendCoins`. But `BaseSendKeeper.SendCoins` itself (`sei-cosmos/x/bank/keeper/send.go:164`) simply calls `SendCoinsWithoutAccCreation` → `sendCoinsWithoutAccCreation`, which does `SubUnlockedCoins` + `AddCoins` with no allow-list check anywhere in that call chain. The same is true of `SendCoinsAndWei`, used by the bank precompile's `sendNative`.

The EVM bank precompile's `send` method (`precompiles/bank/bank.go` and legacy versions e.g. `precompiles/bank/legacy/v600/bank.go:121`) and `sendNative` method (`precompiles/bank/bank.go:251`) call `p.bankKeeper.SendCoins` / `p.bankKeeper.SendCoinsAndWei` directly with a Sei sender/receiver address derived from the EVM caller, completely bypassing the `IsInDenomAllowList` gate that `MsgSend` enforces. This mirrors the Gitea root cause exactly: a scope restriction ("public-only"/here, "denom allow-list") is checked only in one handler (`orgs` direct GET / here, `MsgSend`) while a semantically-equivalent alternate code path (`user/orgs` / here, ERC20-pointer-driven EVM `bank.send`/`bank.sendNative`) reaches the same underlying data/funds without the guard being re-applied, because the guard depends on being explicitly invoked by the caller rather than being embedded in the shared primitive.

### Impact Explanation
Token-factory denom creators can restrict transferability of a denom to a specific allow-list of addresses (e.g., for compliance, KYC-gated, or vesting/lockup tokens) via `SetDenomAllowList`. Any holder of such a denom who is *not* on the allow-list is expected to be unable to move it via `MsgSend`. Via the EVM bank precompile (reachable by any EOA or contract that holds an ERC20 pointer to the restricted denom and is a valid pointer caller), the same restricted funds can be transferred to arbitrary addresses, circumventing the intended access control. This is an unauthorized-transfer-style bypass of a fund-movement restriction enforced by module authority (tokenfactory allow-list), reachable from an ordinary EVM transaction.

### Likelihood Explanation
Reachable by any external, unprivileged party: an EOA/contract that (a) is associated with an EVM address, (b) holds balance of the allow-list-restricted token-factory denom, and (c) is the registered ERC20 native pointer contract for that denom (for `send`) or simply calls `sendNative` for the sei-native precompile with `usei`/token-factory denoms carrying value. No special privilege, validator, or governance action is required — a single EVM transaction suffices.

### Recommendation
Move the `IsInDenomAllowList` check into the shared keeper primitives (`SendCoinsWithoutAccCreation`/`sendCoinsWithoutAccCreation` and `SendCoinsAndWei`) in `sei-cosmos/x/bank/keeper/send.go`, so that every caller — `MsgSend`, the EVM bank precompile, and any future caller — is uniformly subject to the allow-list, rather than requiring each call site to remember to invoke `IsInDenomAllowList` explicitly before calling `SendCoins`.

### Proof of Concept
1. Denom authority creates token-factory denom `factory/<authority>/restricted` and calls `SetDenomAllowList` restricting transfers to `{addr1, addr2}`.
2. `addr3` (not on the allow list) somehow holds balance of `factory/<authority>/restricted` (e.g. received before the allow-list was set, or via a module-to-account mint/send which is exempt from the allow-list check by design).
3. `addr3` associates an EVM address and registers/uses the ERC20 native pointer for `factory/<authority>/restricted`, or if the denom is `usei`, directly calls the bank precompile's `sendNative(receiver)` with value.
4. Calling `precompiles/bank/bank.go`'s `send`/`sendNative` from the EVM address mapped to `addr3` succeeds and moves the restricted denom to an arbitrary receiver, even though the equivalent `MsgSend(addr3 -> receiver)` would fail with `"... is not allowed to send funds"` per `sei-cosmos/x/bank/keeper/msg_server.go:44`.

func (k msgServer) Send(goCtx context.Context, msg *types.MsgSend) (*types.MsgSendResponse, error) {
	ctx := sdk.UnwrapSDKContext(goCtx)

	if err := k.IsSendEnabledCoins(ctx, msg.Amount...); err != nil {
		return nil, err
	}

	from, err := sdk.AccAddressFromBech32(msg.FromAddress)
	if err != nil {
		return nil, err
	}
	to, err := sdk.AccAddressFromBech32(msg.ToAddress)
	if err != nil {
		return nil, err
	}

	allowListCache := make(map[string]AllowedAddresses)
	if !k.IsInDenomAllowList(ctx, from, msg.Amount, allowListCache) {
		return nil, sdkerrors.Wrapf(sdkerrors.ErrUnauthorized, "%s is not allowed to send funds", msg.FromAddress)
	}

	if k.BlockedAddr(to) || !k.IsInDenomAllowList(ctx, to, msg.Amount, allowListCache) {
		return nil, sdkerrors.Wrapf(sdkerrors.ErrUnauthorized, "%s is not allowed to receive funds", msg.ToAddress)
	}

func (p PrecompileExecutor) send(ctx sdk.Context, caller common.Address, method *abi.Method, args []interface{}, value *big.Int, readOnly bool) ([]byte, error) {
	if readOnly {
		return nil, errors.New("cannot call send from staticcall")
	}
	if err := pcommon.ValidateNonPayable(value); err != nil {
		return nil, err
	}

	if err := pcommon.ValidateArgsLength(args, 4); err != nil {
		return nil, err
	}
	denom := args[2].(string)
	if denom == "" {
		return nil, errors.New("invalid denom")
	}
	pointer, _, exists := p.evmKeeper.GetERC20NativePointer(ctx, denom)
	if !exists || pointer.Cmp(caller) != 0 {
		return nil, fmt.Errorf("only pointer %s can send %s but got %s", pointer.Hex(), denom, caller.Hex())
	}
	amount := args[3].(*big.Int)
	if amount.Cmp(utils.Big0) == 0 {
		// short circuit
		return method.Outputs.Pack(true)
	}
	senderSeiAddr, err := p.accAddressFromArg(ctx, args[0])
	if err != nil {
		return nil, err
	}
	receiverSeiAddr, err := p.accAddressFromArg(ctx, args[1])
	if err != nil {
		return nil, err
	}

	if err := p.bankKeeper.SendCoins(ctx, senderSeiAddr, receiverSeiAddr, sdk.NewCoins(sdk.NewCoin(denom, sdk.NewIntFromBigInt(amount)))); err != nil {
		return nil, err
	}

	return method.Outputs.Pack(true)
}
