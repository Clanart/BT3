### Title
Auction module falls back to v2.1 ABI/typehash without verifying the actual deployed AuctionEntryPoint version, causing bid‑verification/encoding mismatch - (File: `blockchain/system/auction.go`, `kaiax/auction/eip712.go`)

### Summary
The Sherlock report describes bond `Auctioneer` constructors that accept an `IBondTeller` parameter without checking that the concrete teller implementation matches the market type, silently changing market semantics. The Kaia auction/MEV module has an analogous pattern: the on-chain `AuctionEntryPoint` contract type (v2.1 vs v3.0) is never strictly validated before the node encodes calldata and computes the EIP-712 signature digest for bids — an "unknown"/unexpected version silently falls back to the v2.1 ABI and typehash.

### Finding Description
`ReadAuctionVersion` queries the deployed entry point's `AUCTION_VERSION()` view to distinguish v2.1 (`"0.0.1"`) from v3.0 (`"0.0.2"`): [1](#0-0) 

That returned string is threaded through as a bare string (`auctionEntryPointVersion`) into both calldata encoding and EIP-712 hashing, and both call sites treat any value other than the exact literal `"0.0.2"` as v2.1 — including empty strings, RPC/call errors that get swallowed, or any unrecognized value: [2](#0-1) 

The EIP-712 digest computation exhibits the identical fallback logic, silently defaulting to the v2.1 struct typehash for anything that isn't recognized as v2 or v3: [3](#0-2) 

This "version" value is fetched once per block/update and cached in `BidPool.auctionEntryPointVersion`, then used both to build the bid transaction calldata (`getBidTxGasLimit`, `GetBidTxGenerator`) and to verify searcher signatures against the pool: [4](#0-3) [5](#0-4) [6](#0-5) 

Nowhere is there a check that confirms the fetched `AUCTION_VERSION()` string is one of the two known, supported values before proceeding — any failure to read it correctly (temporary RPC/state error, an entry point deployed without that view, or a version string drift) causes the node to silently treat the entry point as v2.1, exactly mirroring the original bug class where the auctioneer/teller type is never asserted and the code proceeds with mismatched assumptions about what interface/ABI the counterparty actually implements.

### Impact Explanation
If a node's cached `auctionEntryPointVersion` diverges from the actual deployed contract type (e.g. one honest node fails to fetch `AUCTION_VERSION()` on a given block due to transient state-read issues while others succeed, or the value transitions during a contract upgrade window), that node will:
1. Compute the wrong EIP-712 struct hash when validating `bid.SearcherSig`/`bid.AuctioneerSig` in `validateBidSigs`, causing it to accept or reject bids inconsistently with other honest nodes — a state/behavior divergence across the bid-pool/mempool layer for the same underlying bids.
2. Build calldata with the wrong `AuctionTx` struct (missing `maxGasPrice` for v3) via `EncodeAuctionCallData`, producing a bid transaction that will revert on-chain against the real v3 entry point, breaking bid settlement (auction/MEV proceeds not realized, fee/bid value not captured) for that node's self-generated bid transactions while other nodes' correctly-encoded transactions succeed.

This falls under acceptable "state divergence between honest nodes" and disruption of auction settlement/fee capture, both explicitly permitted impact categories.

### Likelihood Explanation
This requires no privileged access — it is reachable purely by the normal auction lifecycle (governance/registry updating the entry-point address/version, or any node experiencing a transient failure reading `AUCTION_VERSION()` from state). Any bidder or the auctioneer itself submitting bids during a version-ambiguous window would trigger the divergence; no malicious peer/validator behavior is needed, only a benign version mismatch or read failure, making this a plausible medium-likelihood condition during any planned v2.1→v3.0 auction entry-point migration.

### Recommendation
Do not silently fall back to v2.1 semantics on an unrecognized/unreadable `AUCTION_VERSION()`. Instead:
- Return and propagate an explicit error when `ReadAuctionVersion` fails or returns a value outside the known set `{AuctionVersionV2, AuctionVersionV3}`.
- Have `EncodeAuctionCallData`, `GetHashTypedData`, and `validateBidSigs` reject (rather than default) on an unknown version, pausing bid acceptance/inclusion for that entry point until the version can be confirmed, analogous to requiring the bond auctioneer constructor to assert the teller type before accepting it.

### Proof of Concept
Conceptual reproduction (no live PoC executed, limited to static analysis of the cited code paths):
1. Deploy/upgrade the `AuctionEntryPoint` system contract to v3.0 (`AUCTION_VERSION() == "0.0.2"`).
2. On a node where the state read for `AUCTION_VERSION()` transiently fails or returns an unexpected string (e.g., during the registry's block-delayed activation window described in `ReadAuctioneer`'s comment about v2.1 vs v3.0 selector reuse), `BidPool.updateAuctionInfo` caches an `auctionEntryPointVersion` that is neither `"0.0.1"` nor `"0.0.2"`.
3. `validateBidSigs` → `bid.ValidateSearcherSig(..., bp.auctionEntryPointVersion)` → `GetHashTypedData` falls into the `else` branch and computes the v2.1 digest against a live v3.0 contract, while other honest nodes that successfully read `"0.0.2"` compute the v3.0 digest for the same bid — producing different accept/reject outcomes for identical bids across the network.
4. Simultaneously, `EncodeAuctionCallData` on the affected node packs the v2.1 `AuctionTx` (without `maxGasPrice`), producing a bid transaction that reverts when executed against the deployed v3.0 `AuctionEntryPoint.call(...)`.

// ReadAuctionVersion reads the AUCTION_VERSION view from the given entry-point
// contract. The result distinguishes v2.1 ("0.0.1") from v3.0 ("0.0.2") so
// callers can pick the appropriate EIP-712 typehash and ABI.
//
// The v3.0 binding is used for the call: AUCTION_VERSION() is a public-constant
// getter with the same selector on both v2.1 and v3.0 contracts, so the same
// typed binding works against either deployment.
func ReadAuctionVersion(backend bind.ContractCaller, contractAddr common.Address, num *big.Int) (string, error) {
	caller, err := contractsv3.NewIAuctionEntryPointCaller(contractAddr, backend)
	if err != nil {
		return "", err
	}
	return caller.AUCTIONVERSION(&bind.CallOpts{BlockNumber: num})
}

// entry-point contract. version must match the on-chain AUCTION_VERSION of the
// active contract; "0.0.2" selects the v3.0 ABI (with maxGasPrice), any other

func EncodeAuctionCallData(bid *auction.Bid, version string) ([]byte, error) {
	if version == auction.AuctionVersionV3 {
		maxGasPrice := bid.MaxGasPrice
		if maxGasPrice == nil {
			maxGasPrice = new(big.Int)
		}
		input := contractsv3.IAuctionEntryPointAuctionTx{
			TargetTxHash:  bid.TargetTxHash,
			BlockNumber:   new(big.Int).SetUint64(bid.BlockNumber),
			Sender:        bid.Sender,
			To:            bid.To,
			Nonce:         new(big.Int).SetUint64(bid.Nonce),
			Bid:           bid.Bid,
			MaxGasPrice:   maxGasPrice,
			CallGasLimit:  new(big.Int).SetUint64(bid.CallGasLimit),
			Data:          bid.Data,
			SearcherSig:   bid.SearcherSig,
			AuctioneerSig: bid.AuctioneerSig,
		}
		return abiV3.Pack("call", input)
	}

	// auction.AuctionVersionV2 or unknown version: default to v2.1 ABI.
	input := contracts.IAuctionEntryPointAuctionTx{

		BlockNumber:   new(big.Int).SetUint64(bid.BlockNumber),

// GetHashTypedData returns the EIP-712 digest for the bid.
// version must match the on-chain AUCTION_VERSION of the entry-point contract
// the bid targets; "0.0.2" selects the v3.0 struct typehash (with maxGasPrice),
// any other value falls back to the v2.1 typehash.
func (b *Bid) GetHashTypedData(chainId *big.Int, verifyingContract common.Address, version string) []byte {
	if chainId == nil {
		return nil
	}

	domain := EIP712Domain{
		EIP712DomainTypeHash: eip712TypeHash,
		NameHash:             auctionNameHash,
		VersionHash:          crypto.Keccak256Hash([]byte(version)),
		ChainId:              chainId,
		VerifyingContract:    verifyingContract,
	}

	domainSeparator := EncodeEIP712(domain)

	var structHash []byte
	if version == AuctionVersionV3 {
		structHash = EncodeEIP712(bidV3{b})
	} else if version == AuctionVersionV2 {
		structHash = EncodeEIP712(b)
	} else {
		// Unknown version: default to v2.1 typehash.
		structHash = EncodeEIP712(b)
	}

	return crypto.Keccak256([]byte{0x19, 0x01}, domainSeparator, structHash)

func (bp *BidPool) updateAuctionInfo(auctioneer common.Address, auctionEntryPoint common.Address, auctionEntryPointVersion string, bidTxGasBuffer uint64) {
	bp.auctionInfoMu.Lock()
	defer bp.auctionInfoMu.Unlock()

	if bp.auctioneer == auctioneer && bp.auctionEntryPoint == auctionEntryPoint && bp.auctionEntryPointVersion == auctionEntryPointVersion && bp.bidTxGasBuffer == bidTxGasBuffer {
		return
	}

	// Clear the existing auction pool since the auctioneer or auction entry point address is changed.
	bp.clearBidPool()

	bp.auctioneer = auctioneer
	bp.auctionEntryPoint = auctionEntryPoint
	bp.auctionEntryPointVersion = auctionEntryPointVersion
	bp.bidTxGasBuffer = bidTxGasBuffer

	logger.Info("Update auction info", "auctioneer", auctioneer, "auctionEntryPoint", auctionEntryPoint, "auctionEntryPointVersion", auctionEntryPointVersion, "bidTxGasBuffer", bidTxGasBuffer)
}

func (bp *BidPool) validateBidSigs(bid *auction.Bid) error {
	bp.auctionInfoMu.RLock()
	defer bp.auctionInfoMu.RUnlock()

	if bid.SearcherSig == nil || len(bid.SearcherSig) != crypto.SignatureLength {
		return auction.ErrInvalidSearcherSig
	}
	if bid.AuctioneerSig == nil || len(bid.AuctioneerSig) != crypto.SignatureLength {
		return auction.ErrInvalidAuctioneerSig
	}

	// Verify the EIP712 signature.
	if err := bid.ValidateSearcherSig(bp.ChainConfig.ChainID, bp.auctionEntryPoint, bp.auctionEntryPointVersion); err != nil {
		return err
	}

	// Verify the auctioneer signature.
	if err := bid.ValidateAuctioneerSig(bp.auctioneer); err != nil {
		return err
	}

	return nil
}

func (a *AuctionModule) GetBidTxGenerator(tx *types.Transaction, bid *auction.Bid) *builder.TxOrGen {
	gen := func(nonce uint64) (*types.Transaction, error) {
		var (
			chainId           = a.InitOpts.ChainConfig.ChainID
			signer            = types.LatestSignerForChainID(chainId)
			auctionEntryPoint = a.bidPool.GetAuctionEntryPoint()
			key               = a.InitOpts.NodeKey
		)

		data, err := system.EncodeAuctionCallData(bid, a.bidPool.GetAuctionEntryPointVersion())
		if err != nil {
			return nil, err
		}

		if bid.GetGasLimit() == 0 {
			gasLimit, err := a.bidPool.getBidTxGasLimit(bid)
			if err != nil {
				return nil, err
			}
			bid.SetGasLimit(gasLimit)
		}

		tx, err := types.NewTransactionWithMap(types.TxTypeEthereumDynamicFee, map[types.TxValueKeyType]interface{}{
			types.TxValueKeyNonce:      nonce,
			types.TxValueKeyTo:         &auctionEntryPoint,
			types.TxValueKeyAmount:     common.Big0,
			types.TxValueKeyData:       data,
			types.TxValueKeyGasLimit:   bid.GetGasLimit(),
			types.TxValueKeyGasFeeCap:  tx.GasFeeCap(),
			types.TxValueKeyGasTipCap:  tx.GasTipCap(),
			types.TxValueKeyAccessList: types.AccessList{},
			types.TxValueKeyChainID:    chainId,
		})
		if err != nil {
			return nil, err
		}

		err = tx.Sign(signer, key)

		return tx, err
	}
