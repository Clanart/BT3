### Title
Forged DKG ciphertext can leak another participant’s ECDH key through blame proofs - ([File: crypto/dkg/pedpop/src/lib.rs])

### Summary
`KeyMachine::calculate_share` returns an `EncryptionKeyProof` before verifying the encrypted message’s proof-of-possession signature. An attacker can reuse the per-message public key from a victim’s ciphertext, attach a syntactically valid but incorrect PoP and malformed ciphertext, and receive a blame proof containing the ECDH shared key that also decrypts the victim’s message.

### Finding Description
Each `EncryptedMessage` carries a per-message public `key`, a Schnorr PoP over that key, and encrypted bytes [1](#0-0) . The implementation explicitly notes that reusing another sender’s key would let a blame proof reveal the ECDH key for the original message [2](#0-1) .

`Encryption::decrypt` only queues the PoP into a batch verifier, then immediately decrypts the message and returns an `EncryptionKeyProof` containing the ECDH key [3](#0-2) . In `calculate_share`, malformed plaintext causes an early `InvalidShare` error with `blame: Some(blame)` before `batch.verify_with_vartime_blame()` is reached [4](#0-3) . The PoP is only checked later by that batch verification [5](#0-4) .

The resulting proof can be supplied to `decrypt_with_proof`, which verifies that the disclosed point is the correct ECDH key for the registered recipient key and message key, then decrypts the ciphertext with it [6](#0-5) .

### Impact Explanation
A participant can cause disclosure of the ECDH key protecting another participant’s encrypted secret share. Publishing the erroneous blame proof lets observers verify the proof against the victim’s original per-message key and recover that victim’s secret-share plaintext. This violates the DKG’s confidentiality mechanism and leaks secret-share material to an unprivileged participant using only protocol messages.

### Likelihood Explanation
The attacker only needs a previously transmitted victim `EncryptedMessage`, a participant index under which to submit a message, and malformed ciphertext bytes that fail scalar decoding. Choosing ciphertext that is non-canonical makes the early error deterministic. The forged PoP does not need to verify because scalar decoding returns before the queued PoP batch verification executes.

### Recommendation
Do not construct or return an `EncryptionKeyProof` until the message PoP has been verified. The simplest fix is to verify `msg.pop` synchronously in `Encryption::decrypt` before computing or returning blame material. Alternatively, ensure `calculate_share` cannot return an early error containing `blame` before the decryption batch item has been checked.

### Proof of Concept
1. Observe victim Alice’s valid `EncryptedMessage` to Bob and extract its serialized `key`.
2. Construct an attacker `EncryptedMessage` for Bob using:
   - `key`: Alice’s per-message public key.
   - `pop`: any canonical but incorrect Schnorr signature, such as a non-identity `R` and arbitrary scalar `s`.
   - `msg`: bytes guaranteed not to decode as a scalar, such as an all-`0xff` field encoding.
3. Submit the forged message under the attacker’s participant ID to Bob’s `KeyMachine::calculate_share`.
4. Bob’s `decrypt` computes `ECDH(Bob_encryption_secret, Alice_message_key)` and returns the corresponding `EncryptionKeyProof` before the invalid PoP is checked.
5. The malformed scalar causes `calculate_share` to return `PedPoPError::InvalidShare { blame: Some(proof) }`.
6. Publishing that proof discloses the same ECDH key used by Alice’s original message; `Decryption::decrypt_with_proof` can then decrypt Alice’s original ciphertext and recover her secret-share bytes.
