## Analysis Result

### Title
Unchecked type assertion on attacker-controlled CW20/CW721 query response causes a Go panic in the `pointer` precompile - (`precompiles/pointer/pointer.go`)

### Summary
The `pointer` precompile's `AddCW20` (and equivalent `AddCW721`/`AddCW1155` handlers across all `precompiles/pointer/legacy/*/pointer.go` versions) queries an arbitrary, caller-supplied CW20 contract address and blindly type-asserts fields out of its JSON response without checking for presence or type, causing an unrecovered Go panic (the functional analog of GPAC's NULL-pointer dereference on a malformed/crafted input) when the target contract is attacker-controlled and returns a non-conforming response.

### Finding Description
`AddCW20` lets any caller pass an arbitrary bech32 contract address (`cwAddr`), queries it with `{"token_info":{}}`, unmarshals the raw JSON into a generic `map[string]interface{}`, and then does: [1](#0-0) 
```
formattedRes := map[string]interface{}{}
...
name := formattedRes["name"].(string)
symbol := formattedRes["symbol"].(string)
```
This is a bare, unchecked type assertion (`x.(string)`) instead of the safe two-value form (`v, ok := x.(string)`). If the target contract's `token_info` query response omits `"name"`/`"symbol"`, or returns them as a non-string JSON type (number, bool, null, object), `formattedRes["name"]` yields `nil` (or a wrong-typed value) and `.(string)` panics with `interface conversion: interface {} is nil, not string`. This same unguarded pattern is present in every version of the pointer precompile examined (`v552`, `v555`, `v562`, `v575`, `v580`, `v600`, `v605`, `v606`, `v610`, `v620`, `v630`, current `pointer.go`), and mirrors CVE-2021-31257's root cause: dereferencing/using a value from parsed, attacker-controlled input without validating that the expected field/pointer actually exists.

Critically, unlike sibling precompiles (`addr`, `oracle`, `params`, `solo`), which each install a `defer func() { if r := recover(); r != nil { err = ... } }()` at the top of their `Execute`/`RunAndCalculateGas` entrypoints to convert panics into ordinary `error` returns: [2](#0-1) 
the `pointer` precompile's `Execute`/`RunAndCalculateGas` has **no such recover guard**: [3](#0-2) 
so a panic raised inside `AddCW20` propagates unrecovered out of the precompile call.

### Impact Explanation
Any unprivileged EVM caller can trigger this by deploying a trivial CW20-shaped CosmWasm contract whose `token_info` query handler returns JSON lacking `name`/`symbol` (or with non-string values), then calling `pointer.addCW20Pointer(<that contract>)`. Whether this becomes a tx-level failure (caught by an upstream recover somewhere in the ABCI/msg-router stack) or escalates to a full RPC-node crash depends on which call path reaches it: state-changing pointer-registration transactions may be shielded by `baseapp`'s message-execution recovery, but synchronous simulation paths (e.g. `eth_call`/`eth_estimateGas`/`debug_traceCall` invoking the same EVM opcode path without an equivalent recover) are the more concerning surface, since an unrecovered Go panic terminates the whole process, not just the request goroutine.

### Likelihood Explanation
High for triggering the panic itself — deploying a non-conforming CW20-look-alike contract and calling `addCW20Pointer` against it requires no privilege and no race condition, only a standard CosmWasm deploy + EVM precompile call. The main uncertainty is how far up the panic propagates before being caught, which I could not fully confirm within the available tooling (I could not trace every intermediate layer between `evm.Call` into this precompile and the top-level ABCI/RPC panic-recovery wrappers).

### Recommendation
Use the safe two-value type assertion (`name, ok := formattedRes["name"].(string); if !ok { return nil, 0, fmt.Errorf(...) }`) for every field pulled from `formattedRes` in `AddCW20` (and the equivalent CW721/CW1155 paths), and/or add the same `defer recover()` guard already present in `addr`, `oracle`, `params`, and `solo` to the `pointer` precompile's `Execute`/`RunAndCalculateGas`.

### Proof of Concept
1. Deploy a CosmWasm contract that implements a `token_info` query returning `{}` (or `{"name": 123, "symbol": null}`) instead of the expected `{"name": "...", "symbol": "...", ...}` shape.
2. From any EVM account, call the `pointer` precompile at `0x000000000000000000000000000000000000100b` (`PointerAddress`, see [4](#0-3) ), invoking `addCW20Pointer(<contract address>)`.
3. `AddCW20` unmarshals the response and executes `formattedRes["name"].(string)`, panicking because the key is absent/nil or non-string.
4. Because `Execute`/`RunAndCalculateGas` in `precompiles/pointer/pointer.go` has no `recover()`, the panic propagates out of the precompile call unguarded (contrast with `precompiles/addr/addr.go` lines 93-99 which does guard it). [5](#0-4)
