### Title
Unprivileged sender can craft outputs to internal offset addresses (Forwarded/Change/Branch) which are silently dropped, halting crediting of real funds - ([File: processor/src/networks/bitcoin.rs](processor/src/networks/bitcoin.rs))

### Summary
The bug class in the external report is a publicly reachable `mint` that lets anyone pre-create an artifact (a token with a predictable id) that the authorized path would have created, causing the intended operation to be dropped/blocked. The Serai analog is the Bitcoin scanner's offset-address scheme: `scanner(key)` deterministically derives `Branch`, `Change`, and `Forwarded` scripts from nothing but the public group key plus public `hash_to_F` offsets (`b"branch"`, `b"change"`, `b"forward"` under `KEY_DST`), and `get_outputs` classifies any on-chain output paying to one of those scripts as that internal `OutputType` — with no authorization or provenance check on who created the output. Any unprivileged party can compute these addresses and send BTC to them, causing the output to be misclassified and dropped instead of credited.

### Finding Description
In `processor/src/networks/bitcoin.rs`, `scanner()` builds the full `Scanner` by registering three fixed, publicly derivable offsets via `Secp256k1::hash_to_F(KEY_DST, ...)`, and `register` panics on collision (`expect("offset collision")`). [1](#0-0) 

`get_outputs` then scans every non-coinbase transaction and assigns `kind` purely by matching `output.script_pubkey` against the registered scripts — matching script_pubkey only, exactly the shape called out for this class. [2](#0-1) 

Downstream, `scanner_event_to_multisig_event` in `processor/src/multisigs/mod.rs` treats `OutputType::Forwarded` outputs as internal forwarding artifacts: it only emits an instruction when `ForwardedOutputDb::take_forwarded_output` finds a previously recorded instruction, and then unconditionally removes every output that isn't `OutputType::External` via `outputs.retain(|output| output.kind() == OutputType::External)`. [3](#0-2) 

Therefore an output an attacker creates to the `Forwarded` (or `Change`/`Branch`) script:
1. passes the `>= N::DUST` filter and enters `outputs`,
2. finds no matching entry in `ForwardedOutputDb`, so no instruction is produced,
3. is dropped by the `retain` and never reported as received funds.

The offsets and scripts are pure functions of the public group key (`key + G * offset`), so the attacker needs no secret material — identical to "anyone can call mint with an arbitrary token id".

### Impact Explanation
Funds genuinely received on-chain are never surfaced to the processor: the Serai chain is never told the deposit exists, so the bitcoin is neither credited to a user nor schedulable/spendable, despite being held under a key the threshold group controls. This matches "funds reported received that are not spendable" in inverse (real, spendable funds never reported) and replicates the report's systemic-halt consequence: attacker-forged internal outputs also poison the forwarding flow, since real `Forwarded` outputs produced by the multisig's own forwarding plan can be interleaved with attacker outputs at the same script, corrupting the `take_forwarded_output` matching and the `instruction.balance.amount.0 -= tx.0.fee()` accounting.

### Likelihood Explanation
Reachable by any Bitcoin user with public inputs only: the group key is public, `KEY_DST = b"Serai Bitcoin Output Offset"` and the three offset labels are constants in the source, so `p2tr_script_buf(key + G*hash_to_F(...))` is computable by anyone, and sending a transaction to a P2TR address requires no authorization. Cost is only the dust threshold `N::DUST` plus fees. The only mitigating factor is that an attacker donating funds to grief the accounting has bounded motive, hence Medium rather than High.

### Recommendation
Distinguish internally generated outputs from externally created ones instead of trusting script classification alone. Concretely: for `OutputType::Forwarded` (and `Change`/`Branch`), only emit/retain the output if a matching entry exists in `ForwardedOutputDb` (or a corresponding planned-transaction/eventuality record); drop or separately quarantine unregistered internal-kind outputs rather than letting them flow through the forwarded/change paths, so an attacker paying to a known internal script cannot interfere with the accounting of genuine outputs. Optionally, have the forwarded-output DB record expected `(txid, vout)`/amounts at plan creation so `take_forwarded_output` matches the exact output rather than presence-at-script.

### Proof of Concept
1. Observe the multisig's public group key `K` (public on Serai when the set is declared).
2. Compute `forward_offset = Secp256k1::hash_to_F(b"Serai Bitcoin Output Offset", b"forward")` (incrementing until `p2tr_script_buf(K + G*offset)` returns `Some`, per `register_offset` in `networks/bitcoin/src/wallet/mod.rs:180-196`).
3. Broadcast a Bitcoin transaction paying ≥ `N::DUST` sats to `p2tr_script_buf(K + G*forward_offset)`.
4. `Bitcoin::get_outputs` returns the output as `Output { kind: OutputType::Forwarded, .. }` (`processor/src/networks/bitcoin.rs:695`).
5. In `scanner_event_to_multisig_event`, `ForwardedOutputDb::take_forwarded_output` returns `None` (no instruction was ever planned for this attacker-created output), and `outputs.retain(kind == External)` drops it — the deposit is never reported to the chain and the funds sit unspendable by the protocol's accounting. The same technique against the `Change`/`Branch` scripts creates phantom internal outputs that collide with the scanner's assumptions (`assert_eq!(output.key(), key)` / panic-on-duplicate-scan paths), griefing the scan/forward pipeline.

// Always construct the full scanner in order to ensure there's no collisions
fn scanner(
  key: ProjectivePoint,
) -> (Scanner, HashMap<OutputType, Scalar>, HashMap<Vec<u8>, OutputType>) {
  let mut scanner = Scanner::new(key).unwrap();
  let mut offsets = HashMap::from([(OutputType::External, Scalar::ZERO)]);

  let zero = Scalar::ZERO.to_repr();
  let zero_ref: &[u8] = zero.as_ref();
  let mut kinds = HashMap::from([(zero_ref.to_vec(), OutputType::External)]);

  let mut register = |kind, offset| {
    let offset = scanner.register_offset(offset).expect("offset collision");
    offsets.insert(kind, offset);

    let offset = offset.to_repr();
    let offset_ref: &[u8] = offset.as_ref();
    kinds.insert(offset_ref.to_vec(), kind);
  };

  register(
    OutputType::Branch,
    *BRANCH_OFFSET.get_or_init(|| Secp256k1::hash_to_F(KEY_DST, b"branch")),
  );
  register(
    OutputType::Change,
    *CHANGE_OFFSET.get_or_init(|| Secp256k1::hash_to_F(KEY_DST, b"change")),
  );
  register(
    OutputType::Forwarded,
    *FORWARD_OFFSET.get_or_init(|| Secp256k1::hash_to_F(KEY_DST, b"forward")),
  );
