## Title
Inconsistent phishing/host-validation checks between `EmbeddedApp` and `CallbackController` allow OAuth callback redirect bypass via unsanitized `host` param - (File: `app/controllers/shopify_app/callback_controller.rb`)

### Summary
The gem implements two structurally similar "is this embed host safe to redirect to" checks. `ShopifyApp::EmbeddedApp#safe_embedded_app_url`/`deduced_phishing_attack?` fully validates a decoded `host` value — rejecting control characters, backslashes, and embedded userinfo (`@`) *before* calling `ShopifyApp::Utils.sanitize_shop_domain` [1](#0-0) . `ShopifyApp::CallbackController#deduced_phishing_attack?`, which performs the analogous "verify the host before redirecting the OAuth callback" check, omits the `unsafe_embedded_host?` hardening entirely and hands the raw decoded host straight to `sanitize_shop_domain` [2](#0-1) . This is the same bug class as the reported ERC-1155 issue: one code path enforces the complete set of checks, a sibling path performing the same conceptual operation enforces only a subset.

### Finding Description
`EmbeddedApp#deduced_phishing_attack?(decoded_host)` explicitly guards against known URL-parser-inconsistency bypasses (backslash-as-slash confusion, control characters, and `user@host` userinfo smuggling) before trusting `sanitize_shop_domain`'s result: [3](#0-2) 

The test suite confirms these are deliberate, security-motivated checks (e.g. rejecting `evil.com\@store.myshopify.com` and `evil.com@store.myshopify.com`): [4](#0-3) 

`CallbackController`, which performs the OAuth callback redirect (`redirect_to_app`) using the same untrusted `host` request parameter, computes `decoded_host` via `ShopifyAPI::Auth.embedded_app_url(params[:host])` and only checks `sanitize_shop_domain(URI(decoded_host).host)` — it never calls `unsafe_embedded_host?` or any equivalent character/userinfo screening: [5](#0-4) 

Because both methods exist to answer the identical question — "is this Shopify-supplied `host` value safe to build a redirect target from?" — but only one of them applies the full hardening, an attacker completing the OAuth callback with a crafted `host` can potentially cause `redirect_to_app` to build a redirect URL (`"#{decoded_host}#{return_to}"`) using a host value that would have been rejected by the more defensive `EmbeddedApp` implementation.

### Impact Explanation
If the incomplete check allows an attacker-controlled/crafted host authority through, `CallbackController#redirect_to_app` performs `redirect_to(redirect_to, allow_other_host: true)` with `allow_other_host: true`, meaning Rails will not block the browser from being redirected off-domain. This is an open-redirect / phishing primitive directly after the OAuth install flow, which is the exact scenario the `EmbeddedApp` hardening was added to prevent for other embedded redirect flows.

### Likelihood Explanation
The `host` param on the OAuth callback route is attacker/merchant-controlled and reaches this code on every completed callback, requiring only that a victim be lured through (or complete) an OAuth flow with a manipulated `host` value — no privileged access is required.

### Recommendation
Apply the same `unsafe_embedded_host?` validation (or reuse `EmbeddedApp#safe_embedded_app_url`) inside `CallbackController#deduced_phishing_attack?`/`decoded_host` so both redirect-safety checks are implemented consistently, e.g.:
```diff
 def decoded_host
-  @decoded_host ||= ShopifyAPI::Auth.embedded_app_url(params[:host])
+  @decoded_host ||= safe_embedded_app_url(params[:host])
 end
```
and route `redirect_to_app` through the same `unsafe_embedded_host?`/`sanitize_shop_domain` pipeline used by `EmbeddedApp`.

### Proof of Concept
1. Start OAuth for a real shop, then intercept the callback request to `ShopifyApp.configuration.login_callback_url`.
2. Set `host` to a Base64 value engineered to smuggle a different navigation target past `URI(...).host`/`sanitize_shop_domain` while still passing (analogous to the values the `EmbeddedApp` test suite explicitly blocks, e.g. userinfo/backslash smuggling payloads) [4](#0-3) .
3. Complete the callback; because `CallbackController#deduced_phishing_attack?` never calls `unsafe_embedded_host?`, the crafted host is not rejected the way the equivalent `EmbeddedApp` path would reject it, and `redirect_to_app` issues `redirect_to(..., allow_other_host: true)` [6](#0-5)  using the unvalidated host.

**File:** lib/shopify_app/controller_concerns/embedded_app.rb (L52-85)
```ruby
    def safe_embedded_app_url(host)
      decoded_host = Base64.decode64(host.to_s)
      return if deduced_phishing_attack?(decoded_host)

      ShopifyAPI::Auth.embedded_app_url(Base64.strict_encode64(decoded_host))
    end

    def deduced_phishing_attack?(decoded_host)
      sanitized_host = ShopifyApp::Utils.sanitize_shop_domain(decoded_host) unless unsafe_embedded_host?(decoded_host)
      if sanitized_host.nil?
        message = "Host param for redirect to embed app in admin is not from a trusted domain, " \
          "redirecting to root as this is likely a phishing attack."
        ShopifyApp::Logger.info(message)
      end
      sanitized_host.nil?
    end

    def unsafe_embedded_host?(decoded_host)
      return true if decoded_host.empty? || !decoded_host.valid_encoding?
      return true if unsafe_embedded_host_characters?(decoded_host)

      embedded_host_authority(decoded_host).include?("@")
    end

    def unsafe_embedded_host_characters?(decoded_host)
      decoded_host.each_char.any? do |character|
        character_code = character.ord
        character_code <= 0x20 || character_code == 0x7f || character == "\\"
      end
    end

    def embedded_host_authority(decoded_host)
      decoded_host.sub(%r{\Ahttps?://}i, "").split(%r{[/?#]}, 2).first.to_s
    end
```

    def redirect_to_app
      if ShopifyAPI::Context.embedded?
        return_to = session.delete(:return_to)
        redirect_to = if fully_formed_url?(return_to)
          return_to
        else
          "#{decoded_host}#{return_to}"
        end

        redirect_to = ShopifyApp.configuration.root_url if deduced_phishing_attack?
        redirect_to(redirect_to, allow_other_host: true)
      else
        redirect_to(return_address)
      end
    end

    def fully_formed_url?(return_to)
      uri = Addressable::URI.parse(return_to)
      uri.present? && uri.scheme.present? && uri.host.present?
    end

    def decoded_host
      @decoded_host ||= ShopifyAPI::Auth.embedded_app_url(params[:host])
    end
