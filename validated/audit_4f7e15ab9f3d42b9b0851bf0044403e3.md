## Finding: Spoofable "GitHub Enterprise" identity via unauthenticated `WWW-Authenticate` header leads to OAuth token disclosure to attacker-controlled git host

### Title
Malicious git remote can impersonate GitHub Enterprise via a forged `WWW-Authenticate: realm="GitHub"` header, causing Desktop to bind and send the user's GitHub OAuth credential to that host - (File: `app/src/lib/trampoline/trampoline-credential-helper.ts`)

### Summary
The external report is about the app trusting *any* certificate for a claimed identity because no pinning ties the connection to a specific, expected identity. The closest reachable Desktop analog is not TLS pinning itself, but a structurally identical trust failure: Desktop's git-credential trampoline decides whether a remote HTTPS host is a legitimate "GitHub" endpoint (and therefore worth handing GitHub OAuth credentials to) based on **unauthenticated, attacker-suppliable data** — an HTTP `WWW-Authenticate` response header or a heuristic hostname/JSON probe — rather than any pinned or otherwise verified identity.

### Finding Description
`getEndpointKind()` in [1](#0-0)  determines whether a git remote should be treated as `'github.com'`, `'enterprise'`, or `'generic'`. For a `https://` remote that Git is authenticating against, aside from the hardcoded `isDotCom`/`isGHE` checks, the function inspects response headers forwarded from the remote server itself: [2](#0-1) 

If the server (attacker-controlled) returns a header value containing `realm="GitHub"`, the endpoint is immediately classified as `'enterprise'` — with no verification against a known list of hosts, no certificate pinning, and no cross-check against previously trusted GHE endpoints. As a fallback, `isGitHubHost()` in [3](#0-2)  applies further weak heuristics (hostname regex `/(^|\.)(github)\./`, or presence of an `x-github-request-id` header in a `/meta` probe response) to reach the same `'enterprise'` classification — again purely based on values the remote server controls.

Once classified as `'enterprise'`, `getCredential()` in [4](#0-3)  will, if no account is already associated with that endpoint, invoke `ui.promptForGitHubSignIn(endpoint)` to have the user sign in via GitHub OAuth, and then bind the resulting account (with its `login`/`token`) to the attacker-chosen `endpoint` string. On subsequent requests, `findGitHubTrampolineAccount` will match that stored account and `credWithAccount()` will supply the GitHub OAuth token as the git Basic Auth password for that same attacker-controlled host — sent directly to the attacker's server.

This mirrors the report's broken invariant exactly: identity is established purely from a value the remote peer supplies (a certificate in the report; a `WWW-Authenticate` realm string or hostname heuristic here), with no pinning or independent verification. There's no cert-pinning equivalent here either — Desktop never confirms that the "GitHub Enterprise" identity is real (e.g. via a signed/pinned credential, a user allow-list, or TLS certificate chain check against a known root).

### Impact Explanation
An attacker who controls a git remote a user is directed to clone/fetch/push from (e.g., via a malicious repository URL shared with the victim, or a URL substituted by a compromised proxy/on-path party) can:
1. Serve `WWW-Authenticate: Basic realm="GitHub"` on an authentication challenge for a non-GitHub HTTPS host.
2. Cause Desktop to treat that host as a legitimate "GitHub Enterprise" instance and prompt the user to authenticate with their real GitHub OAuth credentials.
3. Have Desktop subsequently transmit the resulting OAuth token to that attacker-controlled host as HTTP Basic Auth credentials on every future git operation against it — token/credential exfiltration and unauthorized account binding to a malicious endpoint, matching the "Valid Impact" categories (credential/token exfiltration, unauthorized OAuth/account binding, attacker-controlled git remote).

### Likelihood Explanation
The `realm="GitHub"` check is a single unauthenticated string match with no other corroboration, making it trivial for anyone running a git-over-HTTPS server to trigger. It requires no local access, no admin rights, and no pre-existing malware or leaked credentials — only that the victim adds/uses the attacker's remote (a normal, expected user action, e.g. cloning a link). This satisfies the "attacker controls a git remote/proxy response" bar from the task's Valid Impact section.

### Recommendation
- Do not classify a remote as an authoritative "enterprise" (GitHub) endpoint based solely on a self-declared `WWW-Authenticate` realm string or on `isGitHubHost()`'s hostname/`x-github-request-id` heuristics.
- Require the user to explicitly add/confirm GitHub Enterprise endpoints (as already done for `isDotCom`/`isGHE`), or, at minimum, only auto-classify as enterprise when the endpoint matches a previously user-confirmed/stored account (`findGitHubTrampolineAccount`), never purely from header/heuristic content controlled by the remote.
- If heuristic detection must remain for UX reasons, gate it behind an explicit, per-endpoint user confirmation step ("This looks like a GitHub Enterprise server — sign in?") that clearly displays the endpoint URL before any OAuth token is associated with it, and never silently persist the binding.

### Proof of Concept
1. Attacker stands up an HTTPS git server at `https://evil.example.com/repo.git`.
2. Attacker configures the server to answer unauthenticated Git HTTP requests with `WWW-Authenticate: Basic realm="GitHub"`.
3. Victim clones `https://evil.example.com/repo.git` in GitHub Desktop.
4. Git's credential trampoline invokes the `get` handler; `getEndpointKind()` matches the `wwwauth[...]` entry containing `realm="GitHub"` and returns `'enterprise'` (`app/src/lib/trampoline/trampoline-credential-helper.ts:157-165`).
5. Because no account exists for `evil.example.com`, `ui.promptForGitHubSignIn(endpoint)` is invoked, prompting the victim to authenticate with their real GitHub account.
6. The resulting account/token is bound to the `evil.example.com` endpoint and returned as git credentials, which Git then sends (as Basic Auth) directly to the attacker's server on this and all future requests to that remote.

Note: I was not able to inspect `ui.promptForGitHubSignIn` / `trampoline-ui-helper.ts` implementation in this session (not returned by search) to confirm the exact OAuth flow and storage details end-to-end; this should be verified in a full session to confirm the token binding/storage step precisely, but the header-driven classification and its lack of verification is directly confirmed in the cited code.

async function getCredential(cred: Credential, store: Store, token: string) {
  const ghCred = await getGitHubCredential(cred, store)

  if (ghCred) {
    return ghCred
  }

  const endpointKind = await getEndpointKind(cred, store)
  const accounts = await store.getAll()

  const endpoint = `${getCredentialUrl(cred)}`
  const apiEndpoint = getAPIEndpoint(endpoint)

  // If it appears as if the endpoint is a GitHub host and we don't have an
  // account for that endpoint then we should prompt the user to sign in.
  if (
    endpointKind !== 'generic' &&
    !accounts.some(a => a.endpoint === apiEndpoint)
  ) {
    if (getIsBackgroundTaskEnvironment(token)) {
      debug('background task environment, skipping prompt')
      return undefined
    }

    const account = await ui.promptForGitHubSignIn(endpoint)

    if (!account) {
      setHasRejectedCredentialsForEndpoint(token, endpoint)
    }

    return credWithAccount(cred, account)
  }

const getEndpointKind = async (cred: Credential, store: Store) => {
  const credentialUrl = getCredentialUrl(cred)
  const endpoint = `${credentialUrl}`

  if (isGist(endpoint)) {
    return 'generic'
  }

  if (isDotCom(endpoint)) {
    return 'github.com'
  }

  if (isGHE(endpoint)) {
    return 'ghe.com'
  }

  // When Git attempts to authenticate with a host it captures any
  // WWW-Authenticate headers and forwards them to the credential helper. We
  // use them as a happy-path to determine if the host is a GitHub host without
  // having to resort to making a request ourselves.
  for (const [k, v] of cred.entries()) {
    if (k.startsWith('wwwauth[')) {
      if (v.includes('realm="GitHub"')) {
        return 'enterprise'
      } else if (/realm="(GitLab|Gitea|Atlassian Bitbucket)"/.test(v)) {
        return 'generic'
      }
    }
  }

  const existingAccount = await findGitHubTrampolineAccount(store, endpoint)
  if (existingAccount) {
    return isDotCom(existingAccount.endpoint) ? 'github.com' : 'enterprise'
  }

  // All GitHub hosts use HTTPS, so if the protocol is not HTTPS we can
  // assume that this is not a GitHub host.
  if (credentialUrl.protocol !== 'https:') {
    return 'generic'
  }

  return (await isGitHubHost(endpoint)) ? 'enterprise' : 'generic'
}

/**
 * Attempts to determine whether or not the url belongs to a GitHub host.
 *
 * This is a best-effort attempt and may return `undefined` if encountering
 * an error making the discovery request
 */
export async function isGitHubHost(url: string) {
  const { hostname } = new window.URL(url)

  const endpoint =
    hostname === 'github.com' || hostname === 'api.github.com'
      ? getDotComAPIEndpoint()
      : getEnterpriseAPIURL(url)

  if (isDotCom(endpoint) || isGHE(endpoint)) {
    return true
  }

  if (isKnownThirdPartyHost(hostname)) {
    return false
  }

  // github.example.com,
  if (/(^|\.)(github)\./.test(hostname)) {
    return true
  }

  // bitbucket.example.com, etc
  if (/(^|\.)(bitbucket|gitlab)\./.test(hostname)) {
    return false
  }

  if (getEndpointVersion(endpoint) !== null) {
    return true
  }

  // Add a unique identifier to the URL to make sure our certificate error
  // supression only catches this request
  const metaUrl = `${endpoint}/meta?ghd=${crypto.randomUUID()}`

  const ac = new AbortController()
  const timeoutId = setTimeout(() => ac.abort(), 2000)
  suppressCertificateErrorFor(metaUrl)
  try {
    const response = await fetch(metaUrl, {
      headers: { 'user-agent': getUserAgent() },
      signal: ac.signal,
      credentials: 'omit',
      method: 'HEAD',
      redirect: 'error',
    })

    tryUpdateEndpointVersionFromResponse(endpoint, response)

    return response.headers.has('x-github-request-id')
  } catch (e) {
    log.debug(`isGitHubHost: failed with endpoint ${endpoint}`, e)
    return undefined
  } finally {
    clearTimeout(timeoutId)
    clearCertificateErrorSuppressionFor(metaUrl)
  }
}
