### Title
Any unprivileged payer can grief a victim app's prepaid bandwidth via cheap-tier FIFO eviction - ([File: modules/pallets/bandwidth/src/lib.rs])

### Summary
`pallet-bandwidth` credits an `(app_chain, app)` bucket with a new `Subscription` on every purchase, appending to a `BoundedVec` capped at `MAX_SUBSCRIPTIONS` (1024). When the list is full, `push_subscription` silently evicts the **oldest** entry to make room for the new one [1](#0-0) . Crucially, `purchase()` on `BandwidthManager.sol` lets *any* caller credit *any* `(chain, app)` pair — the `app` and `chain` fields are arbitrary bytes chosen by the payer, not the app itself [2](#0-1) , and `on_accept` on the pallet side only checks that the purchase came from the registered manager, not that the buyer is affiliated with the app being credited [3](#0-2) .

### Finding Description
This mirrors the WatchPug "dust position" pattern: a cheap, self-triggered action forces a costlier legitimate position out of a shared, capacity-bounded slot, and the victim has no way to prevent it because the mechanism is permissionless by design ("any deployment can sponsor any app on any chain" per the pallet's own doc comment [4](#0-3) ).

Concretely:
1. A legitimate app buys a high-value, long-duration tier (e.g., TierFour, months=12) for `(chainX, appY)`, which is appended to `Allowance::<T>::get(chainX, appY)`.
2. An attacker — who needs no relationship to `appY` — repeatedly calls `BandwidthManager.purchase(app=appY, tier=cheapest, months=1, chain=chainX)` targeting the exact same `(chainX, appY)` key, at whatever the cheapest configured tier price is.
3. Once the list for `(chainX, appY)` reaches `MAX_SUBSCRIPTIONS` (1024), each further attacker purchase evicts the **oldest** entry via `list.remove(0)` in `push_subscription`, emitting `SubscriptionEvicted { lost_bytes, ... }` [5](#0-4) .
4. Because eviction removes from the front (FIFO / oldest-first) and the drain order is also front-to-back, the attacker can force out the app's real, still-unused, high-value subscription entirely before it is ever drained by `BandwidthGate::try_consume`, simply by pushing enough cheap dust subscriptions after it.

The corrupted value is the `Allowance::<T>` `SubscriptionList` for the victim `(app_chain, app)` key: a subscription the victim paid real money for is deleted from state and its `remaining_bytes` are permanently unusable, while the attacker only spent the price of however many cheap-tier purchases were needed to fill/roll the FIFO. No relayer, prover, admin, or governance actor is required — `purchase()` is a fully permissionless entrypoint gated only by fee-token balance [6](#0-5) .

Existing guards do not stop this path:
- The cap-and-evict logic is intentional (documented behavior for "pathological repeat-buy" by the same app), but nothing restricts *who* can push onto a given app's list — `purchase()` has no authorization tied to `app`.
- `Allowlist` bypass and `force_credit` are admin-only mitigations that do not protect an app that hasn't been allowlisted.
- There is no minimum-tier-value floor, no rate limiting, and no per-payer accounting that would make griefing another app's bucket economically irrational or restricted.

### Impact Explanation
This is a direct funds-loss vector: bandwidth is a prepaid resource purchased with real fee-token value (`BandwidthManager.purchase()` pulls ERC20 from the buyer), and `SubscriptionEvicted` documents explicitly that eviction destroys "what the user paid for and won't get to use" [7](#0-6) . An attacker can force a victim's expensive, long-duration credit out of the ledger for the cost of many cheap-tier purchases, which is an asymmetric, attacker-favorable cost structure identical in spirit to the referenced report (cheap self-triggered action blocks/destroys a costlier legitimate state).

### Likelihood Explanation
Medium-High. `purchase()` requires no special permission — only fee-token balance and gas/transaction throughput to push ~1024+ dust purchases into the target's FIFO. The `app` and `chain` fields of the purchase message are fully attacker-controlled, so any observer of `BandwidthCredited`/`OrderPlaced`-style events (or simply an app's known address) can target it. The main cost to the attacker is bounded by `cheapest_tier_price * (up to 1024 purchases)`, which can be made arbitrarily cheap by governance's own tier configuration (tiers are governance-set SKUs and nothing forces a "floor" price high enough to deter this).

### Recommendation
- Scope who may credit an `(app_chain, app)` bucket: e.g., require the purchase to originate from (or be explicitly authorized by) the app itself, or track buckets per `(payer, app_chain, app)` so third parties cannot push into another payer's queue.
- Alternatively, do not evict on cap; instead reject the purchase (`Err`) when the FIFO is full, forcing new purchases to wait for natural drain/expiry rather than destroying existing paid-for capacity.
- Consider a per-tier minimum price floor and/or a rate limit on subscriptions accepted per `(app_chain, app)` within a time window from a single unaffiliated payer to raise the cost of griefing.

### Proof of Concept
1. Governance configures `TierOne` with a very small `price18d` and `TierFour` with high `bytes`/`duration_secs` and high price (as in the docs example) via `set_tier`/`dispatch_set_tiers` [8](#0-7) .
2. Legitimate app `Y` on chain `X` calls `BandwidthManager.purchase(app=Y, tier=TierFour, months=12, chain="EVM-X")`, appending a high-value `Subscription` to `Allowance::<T>::get(X, Y)`.
3. Attacker (unrelated to `Y`) repeatedly calls `BandwidthManager.purchase(app=Y, tier=TierOne, months=1, chain="EVM-X")` — reusing the same `(chain, app)` key — until `Allowance::<T>::get(X, Y).len() == MAX_SUBSCRIPTIONS` (1024) and then once more.
4. `push_subscription` evicts index 0 (the oldest entry) via `list.remove(0)` and emits `Event::SubscriptionEvicted { app_chain: X, app: Y, tier: TierFour, lost_bytes: <victim's remaining bytes> }` [5](#0-4) , confirming the victim's paid subscription (or any subscription ahead of the attacker's dust entries in FIFO order) is deleted from state before ever being consumed by the gate.
5. Repeat/interleave purchases to push the eviction pointer forward until the victim's specific entry — which sits at the front of the FIFO immediately after being purchased — is the one removed, at a fraction of its cost.

		/// Append a fresh subscription with a fixed expiry. If the list
		/// is already at `MaxSubscriptions`, evict the oldest entry and
		/// emit [`Event::SubscriptionEvicted`] so the lost bytes are
		/// auditable. Returns the new subscription's `expires_at`.
		fn push_subscription(
			app_chain: &StateMachine,
			app: &AppKey,
			tier: TierIndex,
			bytes: BandwidthBytes,
			duration_secs: u64,
		) -> u64 {
			let now = <T as pallet_ismp::Config>::TimestampProvider::now().as_secs();
			let expires_at = now.saturating_add(duration_secs);
			let new_sub =
				Subscription { tier, remaining_bytes: bytes, expires_at, purchased_at: now };

			let evicted = Allowance::<T>::mutate(app_chain, app, |list| {
				let evicted = if list.len() == MAX_SUBSCRIPTIONS as usize {
					Some(list.remove(0))
				} else {
					None
				};
				// Capacity is now guaranteed; try_push can't fail.
				let _ = list.try_push(new_sub);
				evicted
			});

			if let Some(old) = evicted {
				Self::deposit_event(Event::SubscriptionEvicted {
					app_chain: *app_chain,
					app: app.clone(),
					tier: old.tier,
					lost_bytes: old.remaining_bytes,
				});
			}

			expires_at
		}

	impl<T: Config> IsmpModule for Pallet<T> {
		fn on_accept(&self, request: PostRequest) -> Result<Weight, anyhow::Error> {
			let manager = BandwidthManager::<T>::get(&request.source).ok_or_else(|| {
				anyhow::anyhow!(format!("no bandwidth manager registered for {:?}", request.source))
			})?;

			if request.from != manager.0.to_vec() {
				return Err(anyhow::anyhow!(format!(
					"purchase from unauthorised sender on {:?}: expected {:x?}, got {:x?}",
					request.source, manager.0, request.from
				)));
			}

			let msg = PurchaseMessage::try_from(request.body.as_slice())?;
			let tier = TierIndex::try_from(msg.tier)
				.map_err(|_| anyhow::anyhow!(format!("unknown tier discriminant {}", msg.tier)))?;
			let cfg = Tiers::<T>::get(tier)
				.ok_or_else(|| anyhow::anyhow!(format!("tier {:?} is not configured", tier)))?;

			let bytes = cfg.bytes.saturating_mul(msg.months as u128);
			let duration = cfg.duration_secs.saturating_mul(msg.months as u64);

			let key = AppKey::truncate_from(msg.app);
			let expires_at = Self::push_subscription(&msg.chain, &key, tier, bytes, duration);

			Self::deposit_event(Event::BandwidthCredited {
				app_chain: msg.chain,
				app: key,
				paid_from: request.source,
				tier,
				bytes,
				expires_at,
			});

			Ok(Weight::zero())
		}

    function purchase(bytes calldata app, uint256 tier, uint256 months, bytes calldata chain)
        external
        returns (bytes32 commitment)
    {
        if (app.length == 0 || chain.length == 0 || months == 0) revert InvalidPurchase();
        uint256 price18d = tierPrice[tier];
        if (price18d == 0) revert UnknownTier();

        uint256 total18d = price18d * months;
        address feeToken = IDispatcher(_host).feeToken();
        uint8 dec = IERC20Metadata(feeToken).decimals();
        uint256 scale = 10 ** (18 - dec);
        if (total18d % scale != 0) revert PriceNotRepresentable();
        uint256 amount = total18d / scale;

        IERC20(feeToken).safeTransferFrom(msg.sender, address(this), amount);

        BandwidthPurchaseMsg memory body = BandwidthPurchaseMsg({
            app: app,
            tier: tier,
            months: months,
            chain: chain
        });

        commitment = IDispatcher(_host).dispatch(
            DispatchPost({
                dest: IDispatcher(_host).hyperbridge(),
                to: PALLET_BANDWIDTH_MODULE_ID,
                body: abi.encode(body),
                timeout: 0,
                fee: 0,
                payer: address(this)
            })
        );
