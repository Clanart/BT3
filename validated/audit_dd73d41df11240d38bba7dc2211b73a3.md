### Title
KIP-247 gasless swap deadline is validated only at tx-pool admission/reset, not at block-inclusion readiness — enabling execution of stale, sandwich-vulnerable swaps - ([File: kaiax/gasless/impl/tx_pool.go])

### Summary
The `RiskFund.swapPoolsAsset` finding is about a swap function that lacks a real, execution-time-enforced deadline, letting stale swaps be mined arbitrarily far in the future and be sandwiched. The Kaia analog is the KIP-247 gasless-swap flow: the user-supplied `deadline` in a `swapForGas` transaction is checked in `checkBalanceForSwap` [1](#0-0)  which is only invoked from `GetCheckBalance()` [2](#0-1) . That function is wired into transaction-pool admission (`validateTx`) and periodic list re-validation (`txList.Filter`) [3](#0-2) , but the actual pending→ready promotion path used right before block assembly, `IsReady`/`isReady`/`isSwapTxReady`, only calls `IsExecutable`/`VerifyExecutable`, which never re-checks the deadline [4](#0-3) . Consequently, a `swapForGas` transaction that already passed the deadline check once can still be promoted and included in a block after its `deadline` has elapsed, defeating the purpose of the deadline parameter and exposing the (already gas-lent) user to stale-price execution and sandwich/MEV extraction, analogous to the reported RiskFund issue.

### Finding Description
`SwapArgs.Deadline` is decoded from the swap calldata and is only checked once, inside `checkBalanceForSwap`:
```go
// tx.deadline >= currentTimestamp
deadline := swapArgs.Deadline
if deadline.Cmp(g.Chain.CurrentBlock().Time()) < 0 {
    return fmt.Errorf("insufficient deadline: ...")
}
``` [1](#0-0) 

This function is reached from `GetCheckBalance()` [2](#0-1) , which the generic tx pool calls at initial `validateTx` time [5](#0-4)  and again inside `txList.Filter`, which is used to periodically drop transactions that fail balance/module checks [6](#0-5) .

However, the module-specific readiness/promotion logic that decides whether a gasless swap tx is actually eligible to be pulled into `pending`/ready for block building goes through a completely separate path — `IsReady` → `isReady` → `isSwapTxReady` → `IsExecutable`/`VerifyExecutable` [7](#0-6) [8](#0-7) . `VerifyExecutable` checks sender/token/nonce/repay-amount consistency (S1–S4, AP1, SP1–SP4) but contains no deadline check at all. Since `Filter()` is only invoked opportunistically (e.g. on `reset()`/balance re-checks), a swap tx that was valid (deadline in the future) when first admitted can remain in the pool and be promoted to `pending`/included in a block after its deadline has passed, if no intervening `Filter` pass happens to catch it before block assembly.

This mirrors the C4 report's root cause: a deadline value exists on paper, but is not strictly enforced at the point of actual on-chain execution, so a transaction can execute at an arbitrarily later time than the user intended.

### Impact Explanation
If a stale `swapForGas` transaction is included in a block after its `deadline`, the user's swap executes against then-current AMM pricing that they no longer agreed to. Because gasless swaps are also tied to gas repayment (`amountRepay`) to the block proposer, a stale-but-still-passing `minAmountOut`/repay check can be exploited by a proposer/searcher (who controls transaction ordering and timing, including via the `AuctionEntryPoint`/bid-pool ordering logic) to sandwich the swap or simply delay inclusion until slippage favors the extractor, resulting in direct value loss to the gasless-swap user and unauthorized value transfer to the extractor. This satisfies the "concrete unauthorized value movement" bar since real KAIA/token value moves via the AMM swap execution.

### Likelihood Explanation
Likelihood is moderate: it requires (a) a legitimate `swapForGas` transaction to remain pending for longer than intended (e.g., low gas price, network congestion, or deliberate proposer delay) and (b) the `Filter`/reset re-validation to not run (or not remove the tx) before the block containing it is built. Because block proposers/searchers (an "auction bidder" role explicitly in scope) control transaction ordering and timing in Kaia's block-building pipeline, a malicious or opportunistic proposer can deliberately hold a gasless swap transaction until its price becomes favorable for extraction, since nothing in `isSwapTxReady`/`IsExecutable` blocks late inclusion.

### Recommendation
Add an explicit deadline check to `VerifyExecutable` (or to `isSwapTxReady`) so the module can never promote a `GaslessSwapTx` for inclusion in the block currently being built if `deadline < currentBlockTime`, mirroring the check already present in `checkBalanceForSwap`. Ensure this check runs at the exact point of promotion (`IsReady`), not only during periodic pool `Filter`/admission, so a deadline-expired swap is never actually executed regardless of how long it has been sitting in the pool.

### Proof of Concept
1. User signs `swapForGas(token, amountIn, minAmountOut, amountRepay, deadline)` with `deadline = now + 60s`, expecting quick inclusion.
2. Tx passes `checkBalanceForSwap` at submission time (`deadline >= currentTimestamp`) [1](#0-0)  and is admitted to the pool.
3. A proposer/searcher observes the pending gasless swap and deliberately withholds it from blocks for >60s (e.g., prioritizing other bundles), while `txList.Filter` re-validation does not happen to run in that exact window, or runs against a pool copy that doesn't immediately evict it before the next block is assembled.
4. When finally promoted, `isSwapTxReady`/`IsExecutable`/`VerifyExecutable` [4](#0-3)  perform no deadline check, so the swap is included and executed on-chain well past its `deadline`, at a price the user no longer agreed to — enabling sandwich extraction by the same proposer/searcher who delayed it.

// Check promotion condition and enforce pending pool flow control.
func (g *GaslessModule) IsReady(txs map[uint64]*types.Transaction, next uint64, ready types.Transactions) bool {
	g.knownTxsMu.Lock()
	defer g.knownTxsMu.Unlock()

	tx, ok := txs[next]
	if !ok {
		return false
	}

	if !g.isReady(txs, next, ready) {
		return false
	}

	if g.IsBundleTx(tx) {
		// If prev tx is bundle tx, there's no need to check the knownTxs limit because it has been checked in the previous `IsReady()` execution.
		isPrevTxBundleTx := len(ready) != 0 && g.IsBundleTx(ready[len(ready)-1])
		if isPrevTxBundleTx {
			g.knownTxs.add(tx, TxStatusPending)
			return true
		}

		maxBundleTxsInPending := g.GetMaxBundleTxsInPending()
		if maxBundleTxsInPending != math.MaxUint64 {
			numExecutable := uint(g.knownTxs.numExecutable())

			numSeqTxs := uint(1)
			for i := next + 1; i < next+uint64(len(txs)); i++ {
				if tx, ok := txs[i]; ok && g.IsBundleTx(tx) {
					numSeqTxs++
				} else {
					break
				}
			}

			// false if there is possibility of exceeding max bundle tx num
			if numExecutable+numSeqTxs > maxBundleTxsInPending {
				logger.Trace("Not promoting a tx because of exceeding max bundle tx num", "tx", tx.Hash().String(), "numExecutable", numExecutable, "maxBundleTxsInPending", maxBundleTxsInPending)
				return false
			}
		}

		g.knownTxs.add(tx, TxStatusPending)
	}

	return true
}

// Check promotion condition.
func (g *GaslessModule) isReady(txs map[uint64]*types.Transaction, i uint64, ready types.Transactions) bool {
	tx := txs[i]

	if g.IsApproveTx(tx) && i < uint64(math.MaxUint64) {
		return g.isApproveTxReady(tx, txs[i+1])
	}

	if g.IsSwapTx(tx) {
		var prevTx *types.Transaction
		if len(ready) > 0 {
			prevTx = ready[len(ready)-1]
		}
		return g.isSwapTxReady(tx, prevTx)
	}

	return false
}

func (l *txList) Filter(sender common.Address, pool *TxPool) (types.Transactions, types.Transactions) {
	// Filter out all the transactions above the account's funds
	removed := l.txs.Filter(func(tx *types.Transaction) bool {
		senderBalance := pool.getBalance(sender)
		// Drop a tx if it is marked as un-executable on block generation process.
		if tx.IsMarkedUnexecutable() {
			return true
		}
		// Since there are mutable values such as accountKey in the state, a tx can be invalidated with the state change.
		if tx.Validate(pool.currentState, pool.signer, pool.currentBlockNumber, true) != nil {
			return true
		}
		// In case of fee-delegated transactions, the comparison value should consider tx fee and fee ratio.
		if tx.IsFeeDelegatedTransaction() {
			feePayer, _ := tx.FeePayer()
			feePayerBalance := pool.getBalance(feePayer)
			feeRatio, isRatioTx := tx.FeeRatio()

			// Handling the special case when the sender and fee payer are the same.
			if sender == feePayer {
				return senderBalance.Cmp(tx.Cost()) < 0
			}
			if isRatioTx {
				feeByFeePayer, feeBySender := types.CalcFeeWithRatio(feeRatio, tx.Fee())
				return senderBalance.Cmp(new(big.Int).Add(tx.Value(), feeBySender)) < 0 || feePayerBalance.Cmp(feeByFeePayer) < 0
			} else {
				return senderBalance.Cmp(tx.Value()) < 0 || feePayerBalance.Cmp(tx.Fee()) < 0
			}
		}

		// balance check for module transaction
		for _, module := range pool.modules {
			if module.IsModuleTx(tx) {
				if checkBalance := module.GetCheckBalance(); checkBalance != nil {
					return checkBalance(tx) != nil
				}
				break
			}
		}

		// For other transactions, all tx cost should be payable by the sender.
		return senderBalance.Cmp(tx.Cost()) < 0
	})

func (g *GaslessModule) IsExecutable(approveTxOrNil, swapTx *types.Transaction) bool {
	err := g.VerifyExecutable(approveTxOrNil, swapTx)
	if err != nil {
		return false
	}
	return true
}

// VerifyExecutable checks if the given transactions form a valid gasless transaction
// It returns an error explaining why the transaction is not executable if it's not,
// and a boolean indicating whether the transaction is executable
func (g *GaslessModule) VerifyExecutable(approveTxOrNil, swapTx *types.Transaction) error {
	// Sx.
	swapArgs, ok := decodeSwapTx(swapTx, g.signer)
	if !ok {
		return ErrDecodeSwapTx
	}
	if !g.isSwapTx(swapArgs) {
		return ErrSwapTxInvalid
	}

	// Conditions involving ApproveTx
	if approveTxOrNil != nil {
		// Ax.
		approveArgs, ok := decodeApproveTx(approveTxOrNil, g.signer)
		if !ok {
			return ErrDecodeApproveTx
		}
		if !g.isApproveTx(approveArgs) {
			return ErrApproveTxInvalid
		}
		// AP1.
		if approveArgs.Sender != swapArgs.Sender {
			return ErrDifferentSenders
		}
		// SP1.
		if approveArgs.Token != swapArgs.Token {
			return fmt.Errorf("%w: approve token %s, swap token %s", ErrDifferentTokens, approveArgs.Token.Hex(), swapArgs.Token.Hex())
		}
		// SP2.
		if approveArgs.Amount.Cmp(swapArgs.AmountIn) < 0 {
			return fmt.Errorf("%w: approve amount %s, required amount %s", ErrInsufficientApproveAmount, approveArgs.Amount.String(), swapArgs.AmountIn.String())
		}
		// SP3.
		if approveTxOrNil.Nonce()+1 != swapTx.Nonce() {
			return fmt.Errorf("%w: approve nonce %d, swap nonce %d (expected %d)", ErrNonSequentialNonce, approveTxOrNil.Nonce(), swapTx.Nonce(), approveTxOrNil.Nonce()+1)
		}
		if nonce := g.getCurrentStateNonce(approveArgs.Sender); nonce != approveTxOrNil.Nonce() {
			return fmt.Errorf("%w: approve nonce %d, current nonce %d", ErrApproveNonceNotCurrent, approveTxOrNil.Nonce(), nonce)
		}
	} else {
		// SP3.
		if nonce := g.getCurrentStateNonce(swapArgs.Sender); nonce != swapTx.Nonce() {
			return fmt.Errorf("%w: swap nonce %d, current nonce %d", ErrSwapNonceNotCurrent, swapTx.Nonce(), nonce)
		}
	}

	// SP4.
	if swapArgs.AmountRepay.Cmp(repayAmount(approveTxOrNil, swapTx)) != 0 {
		return fmt.Errorf("%w: got %s, expected %s", ErrIncorrectRepayAmount, swapArgs.AmountRepay.String(), repayAmount(approveTxOrNil, swapTx).String())
	}

	return nil
}
