### Title
PedPoP accepts identity (or any unauthenticated) encryption keys, making the ECDH share cipher publicly decryptable - (File: crypto/dkg/pedpop/src/encryption.rs)

### Summary
`EncryptionKeyMessage::read` parses the recipient's `enc_key` with `C::read_G`, which validates canonical encoding but does not reject the identity point, and the registered encryption key carries no proof of possession. A participant who broadcasts the identity point as their `enc_key` causes every other participant to derive an ECDH shared secret of identity, so the ChaCha20 keystream protecting their secret shares is publicly computable (and identical across all senders).

### Finding Description
`EncryptionKeyMessage::read` reads `enc_key` via `C::read_G`, which only checks point validity and canonicality — the identity point passes [1](#0-0) [2](#0-1) . `Decryption::register` stores whatever `enc_key` a participant supplied with no PoP or identity check [3](#0-2) . When a sender encrypts a share, `ecdh` computes `to * key`; with `to` = identity the shared secret is identity regardless of the sender's random `key` [4](#0-3) . `cipher` derives the ChaCha20 key solely from the context and the serialized ECDH point, with a fixed IV `b"DKG IV v0.2\0"` [5](#0-4) . The per-message `pop` proves knowledge of the sender's ephemeral `key` (whose public part `msg.key` is transmitted), but nothing binds or validates the *recipient's* registered `enc_key` [6](#0-5) . This mirrors the advisory's "downgrade to a cipher/integrity-free mode" class: the public input `enc_key = identity` silently degrades the share encryption to a keystream anyone can recompute.

### Impact Explanation
Every `EncryptedMessage` sent to the malicious participant is encrypted under the same publicly derivable keystream (context is the shared session context; ECDH output is always identity). Any observer of the authenticated channel — or the malicious participant's own messages relayed by others — can recompute `cipher(context, identity)` and recover all `n-1` secret shares addressed to that participant, yielding their full FROST `ThresholdKeys` secret share. Combined with the attacker's own share, a 2-of-n multisig's group secret key is directly recoverable; for larger `t`, the attacker gains an extra share toward threshold. Additionally, identical keystream across all senders means ciphertexts XOR to plaintext XORs even without decryption. This is key share recovery reachable purely via a public `EncryptionKeyMessage`.

### Likelihood Explanation
Any DKG participant can register an identity `enc_key` by encoding the canonical identity point in their broadcast commitment message; `verify_r1`/`register` perform no identity or PoP check on `enc_key` [7](#0-6) . The attack is deterministic, requires no collusion beyond the attacker's own participation, and leaves no blame-able trace since all proofs verify.

### Recommendation
Reject the identity point (and ideally low-order points) in `EncryptionKeyMessage::read`, or require a Schnorr proof of possession for `enc_key` at registration time in `Decryption::register`. Alternatively bind `enc_key` knowledge into the commitments PoK in `generate_coefficients`.

### Proof of Concept
1. Malicious participant `l` constructs an `EncryptionKeyMessage` whose `enc_key` field is the canonical encoding of `C::G::identity()` (e.g., all-zero bytes for Ristretto), with any valid `Commitments` PoK.
2. Every honest sender `s` calls `encrypt(rng, context, s, identity, share)`; `ecdh` returns `identity`, so `cipher(context, identity)` produces keystream `K` and `msg.ciphertext = share ⊕ K`.
3. Any observer (or `l` itself) recomputes `K` from the public context and identity encoding, then XORs each ciphertext to recover the raw `SecretShare<C::F>` bytes destined for `l`.
4. `l` sums the recovered shares to obtain its finalized threshold secret share — equivalent to what `calculate_share` would produce — and additionally obtains every other participant's contribution, enabling key recovery once the attacker's combined share knowledge reaches `t`.

  fn read_G<R: Read>(reader: &mut R) -> io::Result<Self::G> {
    let mut encoding = <Self::G as GroupEncoding>::Repr::default();
    reader.read_exact(encoding.as_mut())?;

    let point = Option::<Self::G>::from(Self::G::from_bytes(&encoding))
      .ok_or_else(|| io::Error::other("invalid point"))?;
    if point.to_bytes().as_ref() != encoding.as_ref() {
      Err(io::Error::other("non-canonical point"))?;
    }
    Ok(point)
  }

fn cipher<C: Ciphersuite>(context: [u8; 32], ecdh: &Zeroizing<C::G>) -> ChaCha20 {
  // Ideally, we'd box this transcript with ZAlloc, yet that's only possible on nightly
  // TODO: https://github.com/serai-dex/serai/issues/151
  let mut transcript = RecommendedTranscript::new(b"DKG Encryption v0.2");
  transcript.append_message(b"context", context);

  transcript.domain_separate(b"encryption_key");

  let mut ecdh = ecdh.to_bytes();
  transcript.append_message(b"shared_key", ecdh.as_ref());
  ecdh.as_mut().zeroize();

  let zeroize = |buf: &mut [u8]| buf.zeroize();

  let mut key = Cc20Key::default();
  let mut challenge = transcript.challenge(b"key");
  key.copy_from_slice(&challenge[.. 32]);
  zeroize(challenge.as_mut());

  // Since the key is single-use, it doesn't matter what we use for the IV
  // The issue is key + IV reuse. If we never reuse the key, we can't have the opportunity to
  // reuse a nonce
  // Use a static IV in acknowledgement of this
  let mut iv = Cc20Iv::default();
  // The \0 is to satisfy the length requirement (12), not to be null terminated
  iv.copy_from_slice(b"DKG IV v0.2\0");

  // ChaCha20 has the same commentary as the transcript regarding ZAlloc
  // TODO: https://github.com/serai-dex/serai/issues/151
  let res = ChaCha20::new(&key, &iv);
  zeroize(key.as_mut());
  res
}

fn pop_challenge<C: Ciphersuite>(
  context: [u8; 32],
  nonce: C::G,
  key: C::G,
  sender: Participant,
  msg: &[u8],
) -> C::F {
  let mut transcript = RecommendedTranscript::new(b"DKG Encryption Key Proof of Possession v0.2");
  transcript.append_message(b"context", context);

  transcript.domain_separate(b"proof_of_possession");

  transcript.append_message(b"nonce", nonce.to_bytes());
  transcript.append_message(b"key", key.to_bytes());
  // This is sufficient to prevent the attack this is meant to stop
  transcript.append_message(b"sender", sender.to_bytes());
  // This, as written above, doesn't hurt
  transcript.append_message(b"message", msg);
  // While this is a PoK and a PoP, it's called a PoP here since the important part is its owner
  // Elsewhere, where we use the term PoK, the important part is that it isn't some inverse, with
  // an unknown to anyone discrete log, breaking the system
  C::hash_to_F(b"DKG-encryption-proof_of_possession", &transcript.challenge(b"schnorr"))
}
