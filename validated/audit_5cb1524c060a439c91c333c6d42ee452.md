### Title
JIT (just-in-time) staking allows unprivileged attacker to snipe newly queued rewards with zero duration risk - (File: rewards/BaseRewardPool.sol)

### Summary
`BaseRewardPool._provisionReward` (invoked by `queueNewRewards`/`donateRewards`) distributes the *entire* incoming reward amount in a single instantaneous update to `rewardPerTokenStored`, based only on `totalStaked()` at that exact block, with no time-weighting, vesting period, or `periodFinish`/`rewardRate` streaming mechanism. Because `earned()` computes a user's share purely from their *current* live balance (`balanceOf(_account)` reads directly from `MasterMagpie`) multiplied by the delta since their last `userRewardPerTokenPaid` checkpoint, any staker present at the moment the reward is provisioned captures a full pro-rata share regardless of how long they were actually staked.

### Finding Description
`_provisionReward` in `rewards/BaseRewardPool.sol` performs: [1](#0-0) 
```
rewardInfo.rewardPerTokenStored =
    rewardInfo.rewardPerTokenStored +
    (_amountReward * 10**stakingDecimals()) /
    this.totalStaked();
```
This is a one-shot accumulator bump, not a Synthetix-style linear reward stream (there is no `periodFinish`, `rewardRate`, or `lastUpdateTime` in this contract). `earned()` then computes: [2](#0-1) 
using `balanceOf(_account)`, which is fetched live from `MasterMagpie.stakingInfo` rather than a snapshot: [3](#0-2) 

A user's `userRewardPerTokenPaid` checkpoint is only advanced via `_updateFor`, called through the `updateReward` modifier on `getReward` (or via `MasterMagpie._harvestBaseRewarder`, invoked before `user.amount` is changed on deposit/withdraw). Since `MasterMagpie.deposit`/`withdraw` have no minimum staking duration, cooldown, or lock: [4](#0-3) [5](#0-4) 
an attacker can:
1. Deposit a large amount of `stakingToken` into `MasterMagpie` immediately before (front-running) a manager's `queueNewRewards` call (or, since `donateRewards` is fully permissionless for already-registered reward tokens, the attacker doesn't even need to wait for a manager — they can call `donateRewards` themselves right after depositing): [6](#0-5) 
2. Once `rewardPerTokenStored` is bumped, the attacker's `earned()` reflects the full pro-rata share of the newly injected reward computed against their current balance, despite having staked for 0 elapsed time.
3. Attacker withdraws immediately afterward via `MasterMagpie.withdraw`, which harvests the reward through `_harvestBaseRewarder` before decrementing `user.amount`.

No modifier, `nonReentrant`, `whenNotPaused`, or index-checkpoint logic prevents this, because the reward-per-token model here is fundamentally a "snapshot at distribution time" dividend model rather than a time-decayed stream — the checks that exist (`onlyManager` on `queueNewRewards`) only gate *who can inject rewards*, not *who can capture them*, and `donateRewards` bypasses even that gate for already-registered tokens.

### Impact Explanation
This results in theft of unclaimed yield from legitimate long-term stakers: capital that was staked for 0 (or near-0) duration captures reward proportional to its size relative to `totalStaked()`, diluting the share that should have accrued to stakers who held positions throughout the relevant period. This matches the Immunefi impact class "theft of unclaimed yield" for the affected reward pool.

### Likelihood Explanation
Feasibility depends entirely on capital availability, not privilege: any EOA/contract holding (or flash-loanable, if `stakingToken` supports flash loans) the pool's staking token can execute this. Front-running a manager's `queueNewRewards` transaction requires visibility into a public mempool, which is achievable on most chains this protocol may deploy to, though harder on chains with private/sequenced mempools. The much stronger and 100%-reliable variant does not require front-running at all: since `donateRewards` is public and permissionless for any already-registered reward token, the attacker can deposit, self-trigger `donateRewards`, and withdraw entirely within their own control, with no dependency on manager timing. This makes the exploit fully repeatable and requires only capital (temporarily) plus gas.

### Recommendation
Redesign reward provisioning to stream rewards linearly over a fixed duration (Synthetix-style `rewardRate`/`periodFinish`/`lastUpdateTime`), so `rewardPerToken()` accrues based on elapsed time rather than being dumped instantly on `totalStaked()` at the moment of injection. Alternatively, enforce a minimum staking duration/cooldown before a user's balance is eligible to receive a share of a given reward injection, or snapshot stakers' balances prior to the block in which `_provisionReward` executes.

### Proof of Concept
Foundry test outline:
1. Deploy `MasterMagpie`, `BaseRewardPool` for a staking token, with a `victim` staker already holding stake for N blocks.
2. Attacker deposits a large amount `X` of `stakingToken` into `MasterMagpie` in block T.
3. In the same or next block, call `rewarder.donateRewards(amountReward, rewardToken)` (or have a manager call `queueNewRewards`), which bumps `rewardPerTokenStored` based on `totalStaked()` (now including `X`).
4. Attacker calls `MasterMagpie.withdraw(stakingToken, X)` in block T+1, triggering `_harvestBaseRewarder` → `getReward`, transferring out `earned(attacker, rewardToken)`.
5. Assert `earned(attacker, rewardToken) > 0` and that `earned(attacker) / totalRewardDistributed ≈ X / totalStaked()` — i.e., proportional to capital, not to the (near-zero) staking duration — while `victim`'s realized share is correspondingly diluted below what their time-weighted stake should have earned.

    function _provisionReward(uint256 _amountReward, address _rewardToken) internal {
        IERC20(_rewardToken).safeTransferFrom(
            msg.sender,
            address(this),
            _amountReward
        );
        Reward storage rewardInfo = rewards[_rewardToken];
        rewardInfo.historicalRewards =
            rewardInfo.historicalRewards +
            _amountReward;
        if (this.totalStaked() == 0) {
            rewardInfo.queuedRewards += _amountReward;
        } else {
            if (rewardInfo.queuedRewards > 0) {
                _amountReward += rewardInfo.queuedRewards;
                rewardInfo.queuedRewards = 0;
            }
            rewardInfo.rewardPerTokenStored =
                rewardInfo.rewardPerTokenStored +
                (_amountReward * 10**stakingDecimals()) /
                this.totalStaked();
        }

    function _deposit(address _stakingToken, address _account, uint256 _amount, bool _isVlmgp) internal {
        updatePool(_stakingToken);

        PoolInfo storage pool = tokenToPoolInfo[_stakingToken];
        UserInfo storage user = userInfo[_stakingToken][_account];

        if (user.amount > 0) {
            _harvestMGP(_stakingToken, _account);
        }
        _harvestBaseRewarder(_stakingToken, _account);

        user.amount = user.amount + _amount;
        if (!_isVlmgp) {
            user.available = user.available + _amount;
            IERC20(pool.stakingToken).safeTransferFrom(address(msg.sender), address(this), _amount);
        }
        user.rewardDebt = (user.amount * pool.accMGPPerShare) / 1e12;

        if (_amount > 0)
            if (!_isVlmgp)
                emit Deposit(_account, _stakingToken, _amount);
            else
                emit DepositNotAvailable(_account, _stakingToken, _amount);
    }

    /// @notice internal function to deal with withdraw staking token
    function _withdraw(address _stakingToken, address _account, uint256 _amount, bool _isVlMgp) internal {
        _harvestAndUnstake(_stakingToken, _account, _amount, _isVlMgp);

        if (!_isVlMgp)
            IERC20(tokenToPoolInfo[_stakingToken].stakingToken).safeTransfer(address(msg.sender), _amount);
        emit Withdraw(_account, _stakingToken, _amount);
    }

    function _harvestAndUnstake(address _stakingToken, address _account, uint256 _amount, bool _isVlMgp) internal {
        updatePool(_stakingToken);

        UserInfo storage user = userInfo[_stakingToken][_account];

        if (!_isVlMgp && user.available < _amount)
            revert WithdrawAmountExceedsStaked();
        else if(user.amount < _amount && _isVlMgp)
            revert UnlockAmountExceedsLocked();
        
        _harvestMGP(_stakingToken, _account);
        _harvestBaseRewarder(_stakingToken, _account);

        user.amount = user.amount - _amount;
        
        if(!_isVlMgp)
            user.available = user.available - _amount;
        user.rewardDebt = (user.amount * tokenToPoolInfo[_stakingToken].accMGPPerShare) / 1e12;
    }
