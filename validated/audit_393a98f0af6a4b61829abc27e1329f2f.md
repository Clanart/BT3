### Title
Missing timestamp/deadline validation in App Proxy signature verification allows indefinite replay of signed requests - (File: `lib/shopify_app/controller_concerns/app_proxy_verification.rb`)

### Summary
`ShopifyApp::AppProxyVerification#query_string_valid?` verifies that a request's `signature` query parameter matches an HMAC computed over the other query parameters, but it never validates the `timestamp` parameter that Shopify includes in every signed app-proxy request. This is the same class of bug as the reported UniswapV3 issue: a parameter that exists specifically to bound the validity window of an operation (`deadline` for the swap, `timestamp` for the signed proxy request) is present in the data but is silently ignored, so a signed payload remains valid forever instead of only within its intended time window.

### Finding Description
`query_string_valid?` pulls the `signature` out of the query hash and recomputes the HMAC over the remaining parameters (which include `timestamp`), then compares it with `ActiveSupport::SecurityUtils.secure_compare`: [1](#0-0) 

The `timestamp` value is only used as an input to the HMAC calculation — it is never compared against the current time to reject stale requests: [2](#0-1) 

`verify_proxy_request` simply calls `query_string_valid?` and returns `403` only if the signature itself doesn't match; there is no separate freshness check: [3](#0-2) 

This mirrors the report's root cause exactly: a signed operation carries a time-bound parameter (`timestamp`/`deadline`), but the verifying code path never enforces that bound, so a previously valid, correctly-signed request can be replayed by anyone who obtains it (e.g., via browser history, proxy/CDN logs, referrer leakage, or a shared/public link) at any point in the future and will still be accepted as valid.

### Impact Explanation
Any request URL that was once legitimately signed by Shopify for the app proxy endpoint remains permanently "valid" from this module's perspective. If such a URL leaks (logs, browser history, Referer headers, shared screenshots, etc.), an unrelated anonymous party can replay it indefinitely and have the application treat it as an authentic, freshly-issued Shopify app-proxy request, since `AppProxyVerification` is the sole check gating these endpoints (`skip_before_action :verify_authenticity_token` plus `before_action :verify_proxy_request`) and provides no other freshness/session binding.

### Likelihood Explanation
Exploitation requires only that an attacker previously observe one valid signed app-proxy query string (no secret knowledge or privileged access needed) and no unrelated-merchant/anonymous session — any actor who captures a URL, e.g. from logs or a forwarded link, can trigger the vulnerable code path directly.

### Recommendation
Validate the `timestamp` query parameter against the current time (with a small, bounded tolerance window) inside `verify_proxy_request`/`query_string_valid?`, rejecting requests whose `timestamp` is outside that window, mirroring the recommendation to enforce `deadline` in the original report.

### Proof of Concept
1. Capture any legitimately signed app-proxy request URL, e.g. `?shop=some-store.myshopify.com&path_prefix=%2Fapps%2Fmy-app&timestamp=1466106083&signature=<valid_sig>` (structurally identical to the fixture in the test suite): [4](#0-3) 
2. Replay the exact same query string against the app-proxy endpoint at any later date/time.
3. `query_string_valid?` recomputes the HMAC over the same parameters (including the now-stale `timestamp`) and it still matches the `signature`, so `verify_proxy_request` allows the request through with no `403`, because the timestamp is never checked for staleness.

    def query_string_valid?(query_string)
      query_hash = Rack::Utils.parse_query(query_string)

      signature = query_hash.delete("signature")
      return false if signature.nil?

      ActiveSupport::SecurityUtils.secure_compare(
        calculated_signature(query_hash),
        signature,
      )
    end
```

    def calculated_signature(query_hash_without_signature)
      sorted_params = query_hash_without_signature.collect { |k, v| "#{k}=#{Array(v).join(",")}" }.sort.join

      OpenSSL::HMAC.hexdigest(
        OpenSSL::Digest.new("sha256"),
        ShopifyApp.configuration.secret,
        sorted_params,
      )
    end
```
