### Title
`SchnorrAggregate::verify` vacuously accepts a forged empty aggregate signature (`Rs = []`, `s = 0`) - ([File: crypto/schnorr/src/aggregate.rs])

### Summary
`SchnorrAggregate::verify` checks `self.Rs.len() != keys_and_challenges.len()` and then verifies that the multiexp of the weighted pairs equals identity. When both lists are empty, the only remaining pair is `(-s, G)`, so an attacker-supplied signature with `s = 0` verifies as `true`. This is the same bug class as the Carapace report: a guard that reduces to a trivially-true condition on a degenerate (zero/empty) input, letting an otherwise-impossible state pass verification.

### Finding Description
In `crypto/schnorr/src/aggregate.rs`, `verify` (lines 127-146) does:

```rust
if self.Rs.len() != keys_and_challenges.len() {
  return false;
}
...
pairs.push((-self.s, C::generator()));
multiexp_vartime(&pairs).is_identity().into()
```

`SchnorrAggregate::read` (lines 77-88) reads a `u32` count, that many `G` elements, and then one `F` — all from untrusted bytes. An attacker can supply `len = 0x00000000` followed by the canonical encoding of `0` for `s`. If the verifier calls `verify(dst, &[])` (an empty `keys_and_challenges` slice), the length check passes (`0 == 0`), `pairs` becomes just `[(-0, G)]`, and `multiexp_vartime` returns the identity — `verify` returns `true`.

Note that `SchnorrAggregator::complete` (lines 175-178) explicitly refuses to produce an empty aggregate (`if self.sigs.is_empty() { return None; }`), showing the protocol intends aggregates to be non-empty. `verify`, however, does not enforce this invariant on the deserialization path, so bytes that `complete` could never produce still verify.

### Impact Explanation
A `SchnorrAggregate` that no aggregator could ever emit is accepted as valid by `verify`. Any caller that treats a successful `verify` as "at least the expected signatures were aggregated" can be handed a forged artifact. Depending on the caller, this can be used to claim an empty signer set authorized a message, or to satisfy code paths that require a present-and-valid aggregate signature, with only ~36 bytes of attacker-controlled input.

### Likelihood Explanation
Requires a verifier that can be driven into calling `verify` with an empty `keys_and_challenges` slice while accepting the signature blob from an untrusted source — plausible wherever aggregate signatures are deserialized and the signer set is derived from the same or parallel untrusted input. Reachable purely via `SchnorrAggregate::read` on attacker bytes; no key material or validator cooperation needed. Severity: Medium — it is a signature-acceptance bypass, but only on the degenerate empty-statement boundary, analogous in scope to the original report's zero-`totalProtection` edge.

### Recommendation
Reject empty aggregates in `verify`, mirroring `SchnorrAggregator::complete`:

```diff
   pub fn verify(&self, dst: &'static [u8], keys_and_challenges: &[(C::G, C::F)]) -> bool {
+    if self.Rs.is_empty() {
+      return false;
+    }
     if self.Rs.len() != keys_and_challenges.len() {
       return false;
     }
```

Optionally also reject `s == 0`, though the non-empty check suffices to restore the intended invariant.

### Proof of Concept
```rust
// Attacker-controlled bytes: u32 count = 0, then s = 0 (canonical F encoding)
let mut bytes = vec![0u8; 4 + C::F::NUM_BITS as usize / 8]; // len prefix + zero scalar
let agg = SchnorrAggregate::<C>::read(&mut &bytes[..]).unwrap();
assert!(agg.Rs().is_empty());
// Vacuously verifies
assert!(agg.verify(b"some-dst", &[]));
```

The check `self.Rs.len() != keys_and_challenges.len()` reduces to `0 != 0` (false), `pairs = [(-0, G)]`, and `multiexp_vartime` of a zero-scalar pair is the identity, so `verify` returns `true` — a signature that `SchnorrAggregator::complete` is explicitly forbidden from ever producing.   pub fn verify(&self, dst: &'static [u8], keys_and_challenges: &[(C::G, C::F)]) -> bool {
```rust
    if self.Rs.len() != keys_and_challenges.len() {
      return false;
    }

    let mut digest = DigestTranscript::<C::H>::new(dst);
    digest.domain_separate(b"signatures");
    for (_, challenge) in keys_and_challenges {
      digest.append_message(b"challenge", challenge.to_repr());
    }

    let mut pairs = Vec::with_capacity((2 * keys_and_challenges.len()) + 1);
    for (i, (key, challenge)) in keys_and_challenges.iter().enumerate() {
      let z = weight(&mut digest);
      pairs.push((z, self.Rs[i]));
      pairs.push((z * challenge, *key));
    }
    pairs.push((-self.s, C::generator()));
    multiexp_vartime(&pairs).is_identity().into()
  }
```
