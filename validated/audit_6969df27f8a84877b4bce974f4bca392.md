### Title
Insertion of Sensitive Authentication Data Into Sent Data on Cross-Origin Redirect in Farmer Pool Protocol Client - (File: chia/farmer/farmer.py)

### Summary
The GitLab DAST report describes a scanner leaking cross-site cookies to a redirect target during an authorization request. The analogous pattern in this codebase is `make_pool_protocol_request()` in `chia/farmer/farmer.py`, which is used by `_pool_get_auth()` to fetch a pooling-v2 auth token. The request is issued via `aiohttp.ClientSession(trust_env=True).request(method, url, ...)` [1](#0-0)  without disabling redirects. For GET requests (used by `/auth`), the signed authentication parameters (`launcher_id`, `timestamp`, `signature`) are passed as `params` on the query string [2](#0-1) . aiohttp follows HTTP redirects by default (temporary 302/307 included) and resends the same query string/headers to the new Location, without same-origin restriction, since `allow_redirects`/`max_redirects` are never overridden anywhere in the codebase.

### Finding Description
`_pool_get_auth()` builds a signed authentication message (`AugSchemeMPL.sign(singleton_owner_sk_to_authv2_key(...), message)`) over the current timestamp, `launcher_id`, and `target_puzzle_hash`, and sends it as a `GetAuthRequest` to the pool's `/auth` (or `/v2/auth`) endpoint [3](#0-2) . This request goes through `make_pool_protocol_request`, which performs the HTTP call with default aiohttp redirect handling and puts the request payload into query `params` for GET [4](#0-3) .

Separately, the codebase shows the developers were aware that pool redirects are attacker-influenceable: `_pool_get_pool_info()` explicitly inspects `client_response.history` and only accepts a new `pool_url` when *all* redirects in the chain were permanent (301/308), rejecting 302/307 redirects as a source of URL takeover [5](#0-4) , and this exact distinction is unit-tested [6](#0-5) . However, no equivalent redirect-history check, `allow_redirects=False`, or same-origin restriction exists for `make_pool_protocol_request()` itself, i.e., for the `/auth` GET call that carries the cryptographic authentication signature in the URL/query string. If a pool endpoint (reachable simply by the user configuring their own pool_url, or via a pool operator turning malicious/compromised, or a MITM against the pool's HTTP layer before the pool's own redirect logic) responds to the `/auth` request with any redirect status, aiohttp will transparently follow it and resend the identical query-string signature and metadata to the new target host — an out-of-origin destination the farmer did not intend to trust.

### Impact Explanation
The leaked `GetAuthRequest` (timestamp, launcher_id, signature) is exactly the artifact needed to authenticate to the pool's `/auth` endpoint and obtain a v2 pooling `authentication_token`, which is subsequently used by the farmer to authorize POST `/partial` submissions and interactions that affect the farmer's `PoolingShareState` (points, error handling, and pool_state bookkeeping) [7](#0-6) . A party that captures the redirected signature/timestamp/launcher_id (within the message's freshness window) can independently request an authentication token directly from the real pool for that launcher, allowing pool-account impersonation without ever possessing the private key material — a coin-identity/authorization confusion analogous to session-token leakage, and it can degrade pool state (`missing_partials`, `invalid_partials`, stale point accounting) which affects reward accrual for the plotnft's pooled coin.

### Likelihood Explanation
Reachability requires only a spend-bundle/coin identity already in the reachable set for this analysis: a wallet user's own plotnft pool URL configuration, or exposure to any pool endpoint that returns a redirect on `/auth` (302/307 are standard HTTP responses any server or intermediary can emit) is sufficient — no privileged network position beyond controlling/impersonating the configured pool host response is needed, and the vulnerable code path (`make_pool_protocol_request`) is exercised on every pooling-v2 authentication-token refresh cycle in `_get_current_authentication_token()` [8](#0-7) .

### Recommendation
- In `make_pool_protocol_request()`, disable automatic redirect following (`allow_redirects=False`) for authenticated calls, or explicitly validate that any redirect target shares scheme+host+port with the configured `pool_url` before re-sending signed parameters, mirroring the 301/308-only acceptance logic already used in `_pool_get_pool_info()` [5](#0-4) .
- Avoid placing signed authentication material in the URL query string for GET requests; prefer POST with body, and never resend body/query auth data across a redirect to a different origin.
- Add coverage similar to `test_farmer.py`'s pool_info redirect cases but for `_pool_get_auth`/`make_pool_protocol_request`, asserting the signature/timestamp/launcher_id are not resent to a redirected, off-origin URL.

### Proof of Concept
1. Configure a plotnft with `pool_url` pointing to an attacker-controlled or compromised HTTP endpoint (or intercept the legitimate pool's `/auth` response, e.g., via a misconfigured reverse proxy at the pool).
2. Farmer calls `_get_current_authentication_token()` → `_pool_get_auth()` → `make_pool_protocol_request(method="GET", endpoint_name="auth", ...)`, sending `{launcher_id, timestamp, signature}` as query parameters to `pool_url/v2/auth` [9](#0-8) .
3. The endpoint responds with `302 Found` (or `307`) and `Location: https://attacker.example/auth`.
4. Because `aiohttp.ClientSession.request` follows redirects by default and `allow_redirects` is never set to `False` in `make_pool_protocol_request` [10](#0-9) , the client automatically re-issues the GET with the identical query string (containing `signature`, `timestamp`, `launcher_id`) to `attacker.example`.
5. The attacker now holds a valid, unexpired signed authentication request for the farmer's `launcher_id` and can present it directly to the legitimate pool's `/auth` endpoint to mint an `authentication_token` for that farmer before it expires, without ever having access to the farmer's authentication private key.

    async def _get_current_authentication_token(
        self, pool_config: PoolingShareState, authentication_token_timeout: uint8
    ) -> str | pool_protocol.ErrorResponse | None:
        if pool_config.version == 1:
            return str(pool_protocol.get_current_authentication_token(authentication_token_timeout))
        elif pool_config.version == 2:
            cached_auth_token = self.authentication_tokens.get(pool_config.launcher_id, None)
            if cached_auth_token is None or datetime.fromtimestamp(
                cached_auth_token[1], tz=timezone.utc
            ) < datetime.fromtimestamp(self.get_current_time(), tz=timezone.utc):
                auth_response = await self._pool_get_auth(pool_config)
                if isinstance(auth_response, pool_protocol.GetAuthResponse):
                    self.authentication_tokens[pool_config.launcher_id] = (
                        auth_response.authentication_token,
                        auth_response.expiration,
                    )
                    return auth_response.authentication_token
                else:
                    return auth_response
            else:
                # seems sketchy because in theory we should check for non-None here but
                # the auth token can't be None AND expired so semantics guarantee a non-None, non-expired token here
                return cached_auth_token[0]
        else:
            raise ValueError("Unknown pool protocol version specified in pooling config")

    async def _pool_get_auth(
        self, pool_config: PoolingShareState
    ) -> pool_protocol.GetAuthResponse | pool_protocol.ErrorResponse | None:
        timestamp = self.get_current_time()
        message = bytes(timestamp) + bytes(pool_config.launcher_id) + pool_config.target_puzzle_hash
        authentication_sk: PrivateKey | None = self.get_authentication_sk(pool_config)
        if authentication_sk is None:
            return None
        signature: G2Element = AugSchemeMPL.sign(singleton_owner_sk_to_authv2_key(authentication_sk), message)
        response, _ = await make_pool_protocol_request(
            self=self,
            pool_config=pool_config,
            method="GET",
            endpoint_name="auth",
            request=pool_protocol.GetAuthRequest(
                launcher_id=pool_config.launcher_id,
                timestamp=timestamp,
                signature=signature,
            ),
            response_type=pool_protocol.GetAuthResponse,
        )
        return response
