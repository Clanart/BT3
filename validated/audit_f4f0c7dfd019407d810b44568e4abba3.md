### Title
Nil-pointer dereference in legacy precompile error handling (missing `GetDBImpl` nil check) can crash EVM JSON-RPC/trace nodes - ([File: precompiles/common/legacy/v575/precompiles.go])

### Summary
The reported CometBFT fix added missing error/nil checks before use to prevent a panic. sei-chain has an analogous bug: several legacy precompile implementations call `state.GetDBImpl(evm.StateDB).SetPrecompileError(err)` without checking whether `GetDBImpl` returned `nil`, while later versions of the same function explicitly added that nil check — evidence that the unguarded call is unsafe in some reachable EVM execution path.

### Finding Description
`HandlePrecompileError` in the legacy precompile packages `v575`, `v605`, `v606`, and `v610` is implemented as: [1](#0-0) [2](#0-1) [3](#0-2) [4](#0-3) 

Each unconditionally dereferences the result of `state.GetDBImpl(evm.StateDB)`. In contrast, starting from `v614` and in the current `precompiles/common/precompiles.go`, the same function was hardened to guard against a `nil` result: [5](#0-4) [6](#0-5) 

`Prepare` in these same legacy versions already checks `ctxer == nil` and returns an error rather than proceeding, which confirms `GetDBImpl(evm.StateDB)` can legitimately return `nil` on some `vm.StateDB` implementations used in the codebase: [7](#0-6) 

These legacy `Run`/`HandlePrecompileError` code paths are reachable in production: `Keeper.CustomPrecompiles` selects the legacy (per-upgrade) precompile map instead of the always-current one whenever the context `IsTracing()` is set: [8](#0-7) 
`ctx.IsTracing()` is set on the tracing backend used by public `debug_trace*` JSON-RPC calls (e.g. profile/trace tracing backend construction), so a client requesting a trace against a historical block that used one of these older precompile versions runs through the vulnerable `Run`/`HandlePrecompileError` path: [9](#0-8) 

### Impact Explanation
If `GetDBImpl(evm.StateDB)` returns `nil` while executing one of the unguarded legacy `HandlePrecompileError` implementations (v575/v605/v606/v610) and a precompile call in that traced/historical context returns a non-nil error, the code panics on a nil-pointer dereference. Because this executes inside request handling for a public JSON-RPC `debug_trace*` (or other tracing) call, an unauthenticated RPC client could crash the goroutine servicing the request; depending on how panics from tracer/EVM execution are recovered elsewhere in the stack, this can surface as a crash of a default-configuration RPC node or, at minimum, an unrecoverable panic bubbling out of EVM execution for that request.

### Likelihood Explanation
Likelihood is not fully confirmed: the exact circumstance under which `state.GetDBImpl(evm.StateDB)` returns `nil` for a tracing/historical `vm.StateDB` was not verified in this pass (statedb.go implementation of `GetDBImpl` itself was not read in this session). The presence of an identical nil check added later in `v614`+ strongly suggests this was a real, previously-encountered failure mode reached from the tracing code path, rather than a purely defensive addition.

### Recommendation
Backport the `v614`+ nil-check pattern (`if sdb := state.GetDBImpl(evm.StateDB); sdb != nil { sdb.SetPrecompileError(err) }`) into the still-reachable legacy `HandlePrecompileError` implementations in `v575`, `v605`, `v606`, and `v610`, since these remain callable for historical-height tracing/eth_call requests via `Keeper.CustomPrecompiles`.

### Proof of Concept
Not independently reproduced in this session (no execution environment available); the analysis is based on static comparison of `HandlePrecompileError` across precompile version folders and the `ctx.IsTracing()` dispatch in `Keeper.CustomPrecompiles`/`evmrpc/trace_profile.go`. A concrete PoC would require confirming a `vm.StateDB` value used in a `debug_trace*` call for a block executed under precompile version v575/v605/v606/v610 for which `state.GetDBImpl` returns `nil`, then triggering a precompile call that returns a non-nil error in that context.

func (k *Keeper) CustomPrecompiles(ctx sdk.Context) map[common.Address]vm.PrecompiledContract {
	if !ctx.IsTracing() {
		return k.latestCustomPrecompiles
	}
	versions := k.GetCustomPrecompilesVersions(ctx)
	cp := make(map[common.Address]vm.PrecompiledContract, len(k.customPrecompiles))
	for addr, versioned := range k.customPrecompiles {
		cp[addr] = versioned[versions[addr]]
	}
	return cp
}
