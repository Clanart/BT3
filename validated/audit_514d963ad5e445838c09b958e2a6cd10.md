### Title
SSRF via unauthenticated Data Layer mirror URL injection triggering server-side HTTP fetch - (File: chia/data_layer/download_data.py)

### Summary
Any unprivileged user who can submit a spend bundle can create a "mirror" coin for an arbitrary DataLayer `launcher_id` (including a store they do not own) that embeds attacker-controlled URLs in the coin memos. A DataLayer service that syncs that store will read those URLs from wallet state and issue outbound HTTP GET/POST requests to them without validating that they are legitimate DataLayer servers, mirroring the pattern in CVE-2025-60319 (PerfreeBlog's `uploadAttachByUrl`, which fetches attacker-supplied URLs server-side with no authorization check).

### Finding Description
`create_mirror_puzzle()` returns a fixed, non-owner-specific puzzle (`P2_PARENT.curry(Program.to(1))`) [2](#0-1) . Any wallet can spend any coin controlled by any P2_PARENT puzzle to create a `CREATE_COIN` output to this puzzle hash with memos `[launcher_id, url1, url2, ...]`, and `get_mirror_info()` extracts `launcher_id` and URLs from that condition with no verification that the sender owns or controls `launcher_id` [3](#0-2) . This mirror record is surfaced by `dl_get_mirrors` / `get_mirrors_for_launcher` and consumed by `DataLayer.update_subscriptions_from_wallet()`, which pulls all mirror URLs for a store id and feeds them into the local `DataStore` subscription list without filtering by trust [4](#0-3) .

During the periodic sync loop, `fetch_and_validate()` iterates `servers_info` (built from those subscription URLs), shuffles them, and calls `insert_from_delta_file()` → `download_file()` → `http_download()`, which performs `session.get(server_info.url + "/" + filename, ...)` via `aiohttp` with no allow-list, no restriction on scheme/host, and no protection against internal/loopback/link-local targets [5](#0-4) [6](#0-5) . The module's own documentation explicitly notes: "Do not treat mirror URLs, plugins, or static file names as trusted data sources" [7](#0-6) , and "Mirror and plugin URLs are external trust inputs" [8](#0-7)  — confirming this is a recognized but only partially mitigated risk (mitigation is limited to filename-shape validation and content re-verification against wallet roots, not to URL/host validation before the request is made).

### Impact Explanation
An attacker who is any unprivileged wallet user (able to submit a spend bundle creating a small-value coin) can force any node running a DataLayer service that subscribes to a targeted `store_id` to make outbound HTTP requests to attacker-chosen hosts/ports (including internal network addresses, cloud metadata endpoints, or other local services) at a time and cadence the attacker controls, by continually publishing new mirror coins/urls for that launcher_id. This is a classic SSRF: it can be used for internal network reconnaissance/pivoting, hitting internal-only admin endpoints, or abusing the DataLayer node as a source of outbound-request amplification. It does not by itself grant unsigned coin movement or supply inflation, but it is a concrete server-side request forgery reachable by an unauthorized/unprivileged on-chain actor, matching the reachable class of bug in the reference CVE.

### Likelihood Explanation
Likelihood is real but moderate: it requires (1) the victim node to be running the DataLayer service and to actually be subscribed to / tracking the targeted store, and (2) mirror URLs to not otherwise be filtered by operator configuration. Creating a mirror coin costs only a small amount and a standard fee, and the mirror memo format is not authenticated to `launcher_id` ownership, so any chain participant can inject URLs for stores they don't control [9](#0-8) . The bug class is reachable purely through "Data Layer client" actions listed as in-scope.

### Recommendation
- When consuming mirror records in `update_subscriptions_from_wallet()` / `get_mirrors()`, validate that the mirror's `launcher_id` matches a store actually owned/subscribed intentionally by policy, and/or require operator-side allow-listing of mirror hosts before they are added to `servers_info`.
- In `http_download()` (`chia/data_layer/download_data.py`), validate the resolved host against a deny-list of private/loopback/link-local ranges (SSRF hardening) before issuing the request, similar to standard SSRF mitigations for user-influenced outbound fetch targets.
- Consider requiring mirror creation to be signed/tied to the actual `launcher_id`'s owner (e.g., via singleton state) rather than an unauthenticated `CREATE_COIN` memo convention.

### Proof of Concept
1. Attacker crafts and broadcasts a standard spend bundle that creates a coin with puzzle hash `create_mirror_puzzle().get_tree_hash()` and `CREATE_COIN` memos `[victim_launcher_id, "http://169.254.169.254/latest/meta-data/", ...]`, mirroring the exact flow exercised in `create_new_mirror()`/`dl_new_mirror` [10](#0-9)  but for an arbitrary `launcher_id` not owned by the attacker.
2. Once confirmed on chain, any full/DataLayer node that calls `dl_get_mirrors`/`update_subscriptions_from_wallet` for `victim_launcher_id` picks up the attacker URL into `servers_info` [4](#0-3) .
3. On the next `periodically_manage_data()` cycle, `fetch_and_validate()` selects the attacker server URL and `http_download()` issues an outbound GET to the attacker-chosen URL/host [11](#0-10) [12](#0-11) .

```python
def create_mirror_puzzle() -> Program:
    return P2_PARENT.curry(Program.to(1))


MIRROR_PUZZLE_HASH = create_mirror_puzzle().get_tree_hash()


def get_mirror_info(
    parent_puzzle: Program | SerializedProgram, parent_solution: Program | SerializedProgram
) -> tuple[bytes32, list[bytes]]:
    assert type(parent_puzzle) is type(parent_solution)
    _, conditions = run_with_cost(parent_puzzle, INFINITE_COST, parent_solution)
    for condition in conditions.as_iter():
        if (
            condition.first().as_python() == ConditionOpcode.CREATE_COIN
            and condition.at("rf").as_python() == create_mirror_puzzle().get_tree_hash()
        ):
            memos: list[bytes] = condition.at("rrrf").as_python()
            launcher_id = bytes32(memos[0])
            return launcher_id, [url for url in memos[1:]]
    raise ValueError("The provided puzzle and solution do not create a mirror coin")
```

```python
async def http_download(
    target_filename_path: Path,
    filename: str,
    proxy_url: str | None,
    server_info: ServerInfo,
    timeout: aiohttp.ClientTimeout,
    log: logging.Logger,
    max_delta_file_size: int,
) -> None:
    """
    Download a file from a server using aiohttp.
    Raises exceptions on errors
    """
    async with aiohttp.ClientSession() as session:
        headers = {"accept-encoding": "gzip"}
        async with session.get(
            server_info.url + "/" + filename,
            headers=headers,
            timeout=timeout,
            proxy=proxy_url,
        ) as resp:
            resp.raise_for_status()
            size = int(resp.headers.get("content-length", 0))
            max_delta_file_size_bytes = max_delta_file_size * 1024 * 1024
            if size > max_delta_file_size_bytes:
                raise MaxDeltaFileSizeExceededError(f"Maximum delta file size exceeded: {max_delta_file_size} MiB.")
            log.debug(f"Downloading delta file {filename}. Size {size} bytes.")
```
