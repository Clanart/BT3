### Title
Unauthenticated `ClementineAggregator::Withdraw` RPC Combined with Optional `aggregator_verification_address` Allows Any Caller to Trigger Operator Payout Transactions — (`core/src/rpc/aggregator.rs`, `core/src/rpc/operator.rs`, `core/src/rpc/interceptors.rs`)

---

### Summary

The aggregator's `Withdraw` gRPC endpoint carries no caller authentication: the aggregator server does not enforce client certificates. When `aggregator_verification_address` is absent from the operator's config (the default in the shipped TOML template), the operator's `Withdraw` handler also skips its only application-level identity check. Any network-reachable party can call `Aggregator::Withdraw`, which the aggregator relays to operators under its own trusted certificate, causing operators to create and broadcast payout transactions for registered withdrawal UTXOs without any authorisation from the legitimate initiator.

---

### Finding Description

**Step 1 – Aggregator server has no caller authentication.**

The documentation explicitly states:

> "The aggregator does not enforce client certificates but does use TLS for encryption." [1](#0-0) 

In `create_grpc_server`, when `client_verification` is `false` the `Noop` interceptor is installed, which passes every request unconditionally:

```rust
Interceptors::Noop => Ok(req),
``` [2](#0-1) 

The aggregator server is started with this `Noop` path, so any client that can reach the aggregator's TCP port may call any RPC method, including `Withdraw`.

**Step 2 – Aggregator forwards the request to operators under its own trusted certificate.**

`AggregatorServer::withdraw` performs no caller identity check and immediately fans the request out to all matching operators: [3](#0-2) 

Each forwarded call is made with the aggregator's own gRPC client, which presents the aggregator's mTLS certificate.

**Step 3 – Operator's mTLS interceptor accepts the aggregator certificate.**

The `OnlyAggregatorAndSelf` interceptor allows any request whose leaf certificate matches the pinned aggregator cert:

```rust
} else if leaf_cert == aggregator_cert || leaf_cert == our_cert {
    Ok(req)
``` [4](#0-3) 

**Step 4 – Operator's `Withdraw` handler skips the only application-level check when `aggregator_verification_address` is `None`.**

```rust
if let Some(address_in_config) = self.operator.config.aggregator_verification_address {
    // ... ECDSA signature recovery and comparison
}
// falls through directly to self.operator.withdraw(...)
``` [5](#0-4) 

`aggregator_verification_address` is typed `Option<alloy::primitives::Address>`: [6](#0-5) 

It is **absent** from the shipped TOML reference config: [7](#0-6) 

When the field is not present in the TOML, `serde` deserialises it as `None`, the `if let Some(...)` block is never entered, and the operator proceeds directly to `self.operator.withdraw(...)`.

**Step 5 – `operator.withdraw` creates and queues the payout transaction.**

The function fetches the withdrawal UTXO from Citrea, verifies profitability, constructs the payout `TxHandler` using the caller-supplied taproot signature, and enqueues it in `TxSender` for broadcasting: [8](#0-7) 

**Complete attack path (no privileged keys required):**

1. Attacker connects to the aggregator's gRPC endpoint (no client certificate required).
2. Attacker calls `ClementineAggregator::Withdraw` supplying a valid `withdrawal

    pub async fn withdraw(
        &self,
        withdrawal_index: u32,
        in_signature: taproot::Signature,
        in_outpoint: OutPoint,
        out_script_pubkey: ScriptBuf,
        out_amount: Amount,
    ) -> Result<Transaction, BridgeError> {
        tracing::info!(
            "Withdrawing with index: {}, in_signature: {:?}, in_outpoint: {:?}, out_script_pubkey: {}, out_amount: {}",
            withdrawal_index,
            in_signature,
            in_outpoint,
            out_script_pubkey,
            out_amount
        );

        // Prepare input and output of the payout transaction.
        let input_prevout = self.rpc.get_txout_from_outpoint(&in_outpoint).await?;
        let input_utxo = UTXO {
            outpoint: in_outpoint,
            txout: input_prevout,
        };
        let output_txout = TxOut {
            value: out_amount,
            script_pubkey: out_script_pubkey,
        };

        // Check Citrea for the withdrawal state.
        let withdrawal_utxo = self
            .db
            .get_withdrawal_utxo_from_citrea_withdrawal(None, withdrawal_index)
            .await?;

        if withdrawal_utxo != input_utxo.outpoint {
            return Err(eyre::eyre!("Input UTXO does not match withdrawal UTXO from Citrea: Input Outpoint: {0}, Withdrawal Outpoint (from Citrea): {1}", input_utxo.outpoint, withdrawal_utxo).into());
        }

        let operator_withdrawal_fee_sats =
            self.config
                .operator_withdrawal_fee_sats
                .ok_or(BridgeError::ConfigError(
                    "Operator withdrawal fee sats is not specified in configuration file"
                        .to_string(),
                ))?;
        if !Self::is_profitable(
            input_utxo.txout.value,
            output_txout.value,
            self.config.protocol_paramset().bridge_amount,
            operator_withdrawal_fee_sats,
        ) {
            return Err(eyre::eyre!("Not enough fee for operator").into());
        }

        let user_xonly_pk = &input_utxo
            .txout
            .script_pubkey
            .try_get_taproot_pk()
            .wrap_err("Input utxo script pubkey is not a valid taproot script")?;

        let payout_txhandler = builder::transaction::create_payout_txhandler(
            input_utxo,
            output_txout,
            self.signer.xonly_public_key,
            in_signature,
            self.config.protocol_paramset().network,
        )?;
