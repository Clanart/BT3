### Title
PedPoG DKG encryption keys accepted without identity check or proof of possession: registering the identity point makes all shares sent to that participant world-decryptable - (File: crypto/dkg/pedpop/src/encryption.rs)

### Summary
Analogous to the Airflow "ignored permission" bug (a resource served without enforcing the check meant to gate it), `Decryption::register` stores a participant-supplied ECDH public key (`EncryptionKeyMessage.enc_key`) with no identity rejection and no proof of possession. Because `ecdh` multiplies this point by a fresh ephemeral scalar, an `enc_key` of the identity element yields a fixed, publicly computable shared secret (the identity point). Every secret share a sender encrypts to that participant is then protected only by a ChaCha20 keystream that any passive observer can recompute, giving an unprivileged third party access to that participant's DKG secret share — a resource only the intended recipient should be able to read.

### Finding Description
In `crypto/dkg/pedpop/src/encryption.rs`:

- `EncryptionKeyMessage::read` (line 57-59) decodes `enc_key` with `C::read_G`, the base `Ciphersuite::read_G`, which performs only canonical decoding. This contrasts with `Curve::read_G` in `crypto/frost/src/curve/mod.rs` (lines 125-131), which explicitly rejects identity — evidence the codebase treats unfiltered identity as dangerous, yet the PedPoP path (where `C: Ciphersuite`, not `Curve`) applies no such check.
- `Decryption::register` (lines 351-362) inserts `msg.enc_key` into `enc_keys` unconditionally. There is no proof-of-possession or validity requirement on the long-term encryption key; the PoP exists only on the per-message ephemeral key inside `EncryptedMessage`.
- `Encryption::encrypt` (line 466) calls `encrypt(rng, context, self.i, self.decryption.enc_keys[&participant], msg)`, which computes `ecdh(&key, to)` = `to * key` (lines 95-97, 154). If `to` is identity, the shared point is identity regardless of `key`.
- `cipher` (lines 101-133) derives the ChaCha20 key from `transcript("DKG Encryption v0.2", context, shared_key_bytes)` with the fixed IV `b"DKG IV v0.2\0"`. With `shared_key = identity`, the entire keystream is a deterministic function of the public `context` and the well-known identity encoding — computable by anyone.

`SecretShareMachine::generate_secret_shares` in `crypto/dkg/pedpop/src/lib.rs` (lines 359-370) encrypts `polynomial(&self.coefficients, l)` for each other participant `l` under `enc_keys[l]`. If `l` registered `enc_key = identity`, the resulting `EncryptedMessage` ciphertext is trivially decryptable by any observer of the (assumed authenticated but not necessarily confidential) channel.

Notably, the code comments (lines 84-90) discuss reusing someone else's ephemeral key `X` for the blame-leak attack, but the registered recipient key itself is never validated.

### Impact Explanation
Any passive observer who sees the `EncryptedMessage` ciphertexts addressed to the malicious participant can recompute `cipher(context, identity)` and recover that participant's PedPoP secret share `f_j(l)` in plaintext — unauthorized disclosure of a secret resource, i.e. key share recovery by an unprivileged party. Each additional participant who registers an identity (or otherwise uncontrolled/garbage) encryption key widens the leak. Because threshold security assumes `t` shares are required and each share is known only to its holder, publishing even one share reduces the effective security margin of the resulting `ThresholdKeys` group key for the entire multisig; combined with any partial compromise the group key can be recovered. This directly violates the DKG's confidentiality guarantee on the share distribution round.

### Likelihood Explanation
The attack requires only that the attacker register `enc_key = identity` in their broadcast `EncryptionKeyMessage` — a single public-input byte string fed through `EncryptionKeyMessage::read`/`Decryption::register`. It is trivially cheap, indistinguishable from normal protocol flow (no honest peer can detect it, since the point decodes canonically), and deterministically leaks every share ciphertext addressed to the attacker to all observers. The reporter of the ciphertext (a full node, relayer, or any channel eavesdropper) needs no privileges, no collusion, and no further interaction. The leak is passive and reliable rather than probabilistic.

### Recommendation
- In `EncryptionKeyMessage::read` or `Decryption::register`, reject identity and non-subgroup points: either require `C: Curve` and use `Curve::read_G` (which already rejects identity), or explicitly check `!bool::from(enc_key.is_identity())`.
- Require a proof of possession over the registered `enc_key` (e.g., a Schnorr PoK transcripted with `context` and the participant index), so the key is bound to a known discrete log and cannot be the identity or a controllable low-order point.
- Optionally, defense in depth: in `encrypt`, reject/abort if `ecdh(&key, to).is_identity()`, so a malformed recipient key can never silently downgrade the ciphertext to a public keystream.

### Proof of Concept
```rust
// Conceptual PoC on any C: Ciphersuite used with PedPoP.
// Participant `evil` (index e) broadcasts an EncryptionKeyMessage whose
// enc_key is the identity point:

let mut msg_bytes = Commitments::serialize(/* valid commitments + PoK */).unwrap();
msg_bytes.extend(<C::G as GroupEncoding>::to_bytes(&C::G::identity()).as_ref());
// Identity encodes canonically; C::read_G accepts it.
let evil_msg = EncryptionKeyMessage::<C, Commitments<C>>::read(&mut msg_bytes.as_slice(), params).unwrap();

// Every honest participant calls self.encryption.register(e, evil_msg), storing
// enc_keys[e] = identity with no error.

// In generate_secret_shares, honest sender j computes:
//   ecdh(&ephemeral_key, identity) == identity
//   cipher(context, identity) -> ChaCha20 keystream K = f(public context, identity bytes)

// An eavesdropper captures EncryptedMessage { key: g*k, pop, msg: share ^ K } for
// recipient e and recomputes K identically:
let shared = C::G::identity();              // ecdh result, attacker-computable
let mut plaintext = ciphertext.clone();
cipher::<C>(public_context, &Zeroizing::new(shared)).apply_keystream(plaintext.as_mut());
// `plaintext` is now participant e's raw SecretShare<F::Repr> — recovered with no secrets.
```

Uncertainty note: the exploit assumes `Ciphersuite::read_G` does not reject the identity point for the concrete suites in use (kp256/dalek-ff-group). The existence of a separate identity-rejecting `Curve::read_G` in `crypto/frost/src/curve/mod.rs` indicates the base `Ciphersuite::read_G` is permissive, but the exact per-suite decode behavior was not fully enumerated; if a given suite rejects identity at decode time, the same attack applies with any point whose discrete log the attacker controls to force a predictable ECDH result (identity being the canonical case since there is no PoP requirement on `enc_key`).
