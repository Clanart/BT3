### Title
Unauthenticated `eth_sendTransaction` / `eth_signTransaction` sign with any key present in the node's local keyring, allowing impersonation of any hosted address - ([File: evmrpc/send.go])

### Summary
The EVM JSON-RPC surface exposes `eth_accounts`, `eth_sendTransaction`, and `eth_signTransaction` on every node (not gated behind the `EnableTestAPI`/non-live-chain check that protects the `test` namespace). These handlers load a local OS keyring with `keyring.BackendTest` and sign/broadcast a transaction for whatever `from` address the RPC **caller** supplies, with no proof-of-ownership challenge (no signature, no passphrase, no session token). Any address whose private key happens to be resident in that keyring can be driven to sign and broadcast arbitrary transactions by an unauthenticated remote caller — conceptually the same "use a credential you were never entitled to, to act as another account" pattern as the GitLab report, except the credential here is a locally-hosted ECDSA key rather than a leaked API token.

### Finding Description
`InfoAPI.Accounts` enumerates every address in the node's local test-backend keyring and returns it to any caller: [1](#0-0) 

`SendAPI.SendTransaction` / `SendAPI.SignTransaction` both funnel into `signTransaction`, which opens that same keyring and signs with whatever key matches the attacker-supplied `from` address — no signature, session, or password is required from the RPC caller to prove they control that address: [2](#0-1) 

The keyring itself is opened directly against the node's home directory with the unauthenticated `test` backend: [3](#0-2) 

These three RPC methods (`Accounts`, `SendTransaction`, `SignTransaction`) are registered unconditionally as part of `InfoAPI`/`SendAPI` in the JSON-RPC server's `apis` list — unlike the `test` namespace, which is explicitly gated by `config.EnableTestAPI && !evmCfg.IsLiveChainID(ctx)`, `InfoAPI`/`SendAPI` are always exposed: [4](#0-3) 

Consistent with `evmrpc/AGENTS.md`'s directive that "every exported method on a registered API struct is automatically a live, unaudited RPC endpoint," `Accounts`, `SendTransaction`, and `SignTransaction` are exported methods on `InfoAPI`/`SendAPI`, both registered via `RegisterName`, and thus reachable by any public RPC client with no further authorization step: [5](#0-4) 

The repo's own tooling relies on a single, hardcoded, widely-reused dev private key (`57acb95d82739866a5c29e40b0aa2590742ae50425b7dd5b5d279a986370189e`) across multiple deployment/loadtest scripts that populate node keyrings for local/dev/loadtest environments: [6](#0-5) [7](#0-6) 

### Impact Explanation
If a node hosts any key in its local `test`-backend keyring (a common pattern for local/dev/loadtest/CI deployments, or any operator who once ran `seid keys add` against the node's home dir), an unauthenticated remote caller who learns that address (trivially, via `eth_accounts`, which enumerates them for free) can call `eth_sendTransaction`/`eth_signTransaction` with that `from` address and have the node sign and broadcast transactions as that account — draining funds, transferring tokens, or performing any on-chain action that account is authorized to do. This is a direct unauthorized-transfer / fund-loss primitive reachable purely from the public EVM JSON-RPC surface, without the caller ever presenting a valid signature.

### Likelihood Explanation
Likelihood is highest on non-mainnet deployments (localnet, devnet, loadtest clusters) where the repo's own tooling seeds keyrings with well-known, hardcoded private keys shared across scripts, and where `eth_accounts` freely discloses which addresses are hosted. On a hardened mainnet validator/full-node that never populated its `test` keyring, the attack surface collapses to `"from address does not have hosted key"` errors — but the code path itself performs no authentication check regardless of environment, so any operator who ever loads a key into that keyring (for local signing convenience, testing, or misconfiguration) is immediately and silently exposed to remote impersonation.

### Recommendation
- Gate `InfoAPI.Accounts`, `SendAPI.SendTransaction`, and `SendAPI.SignTransaction` behind the same `EnableTestAPI && !IsLiveChainID` (or a dedicated, off-by-default) flag that already protects the `test` namespace, rather than exposing them unconditionally.
- If node-hosted signing must remain available, require an explicit, out-of-band authorization step (e.g., admin-only bind address, mTLS, or a passphrase supplied per call) before the keyring is used to sign on a caller's behalf.
- Audit all deployment/loadtest tooling that seeds keyrings with shared hardcoded private keys and stop reusing the same key across environments that might be reachable from a public RPC endpoint.

### Proof of Concept
1. Identify a node whose EVM JSON-RPC endpoint is public and whose local `test` keyring has a hosted key (e.g., any local/dev/loadtest deployment following `loadtest/contracts/deploy_erc20.sh`).
2. `curl -s --data '{"jsonrpc":"2.0","id":1,"method":"eth_accounts","params":[]}' <rpc>` to enumerate hosted addresses (see `evmrpc/info.go` `Accounts`).
3. `curl -s --data '{"jsonrpc":"2.0","id":1,"method":"eth_sendTransaction","params":[{"from":"<hosted-address>","to":"<attacker-address>","value":"0x<amount>"}]}' <rpc>` — the node signs and broadcasts the transaction using the hosted private key with no proof of ownership from the caller (`evmrpc/send.go` `signTransaction`).

func (i *InfoAPI) Accounts(ctx context.Context) (result []common.Address, returnErr error) {
	startTime := time.Now()
	defer func() {
		recordMetricsWithError(ctx, "eth_Accounts", i.connectionType, startTime, returnErr, recover())
	}()
	kb, err := getTestKeyring(i.homeDir)
	if err != nil {
		return []common.Address{}, err
	}
	for addr := range getAddressPrivKeyMap(kb) {
		result = append(result, common.HexToAddress(addr))
	}
	return result, nil
}

func (s *SendAPI) SignTransaction(ctx context.Context, args apitypes.SendTxArgs, _ *string) (result *export.SignTransactionResult, returnErr error) {
	startTime := time.Now()
	defer func() {
		recordMetricsWithError(ctx, "eth_signTransaction", s.connectionType, startTime, returnErr, recover())
	}()
	unsignedTx, err := args.ToTransaction()
	if err != nil {
		return nil, err
	}
	signedTx, err := s.signTransaction(unsignedTx, args.From.Address().Hex())
	if err != nil {
		return nil, err
	}
	data, err := signedTx.MarshalBinary()
	if err != nil {
		return nil, err
	}
	return &export.SignTransactionResult{Raw: data, Tx: signedTx}, nil
}

func (s *SendAPI) SendTransaction(ctx context.Context, args export.TransactionArgs) (result common.Hash, returnErr error) {
	startTime := time.Now()
	defer func() {
		recordMetricsWithError(ctx, "eth_sendTransaction", s.connectionType, startTime, returnErr, recover())
	}()
	if err := args.SetDefaults(ctx, s.backend, false); err != nil {
		return common.Hash{}, err
	}
	var unsignedTx = args.ToTransaction(ethtypes.LegacyTxType)
	signedTx, err := s.signTransaction(unsignedTx, args.From.Hex())
	if err != nil {
		return common.Hash{}, err
	}
	data, err := signedTx.MarshalBinary()
	if err != nil {
		return common.Hash{}, err
	}
	return s.SendRawTransaction(ctx, data)
}

func (s *SendAPI) signTransaction(unsignedTx *ethtypes.Transaction, from string) (*ethtypes.Transaction, error) {
	kb, err := getTestKeyring(s.homeDir)
	if err != nil {
		return nil, err
	}
	privKey, ok := getAddressPrivKeyMap(kb)[from]
	if !ok {
		return nil, errors.New("from address does not have hosted key")
	}
	chainId := s.keeper.ChainID(s.ctxProvider(LatestCtxHeight))
	signer := ethtypes.LatestSignerForChainID(chainId)
	return ethtypes.SignTx(unsignedTx, signer, privKey)
}

func getTestKeyring(homeDir string) (keyring.Keyring, error) {
	clientCtx := client.Context{}.WithViper("").WithHomeDir(homeDir)
	clientCtx, err := config.ReadFromClientConfig(clientCtx)
	if err != nil {
		return nil, err
	}
	return client.NewKeyringFromBackend(clientCtx, keyring.BackendTest)
}

func getAddressPrivKeyMap(kb keyring.Keyring) map[string]*ecdsa.PrivateKey {
	res := map[string]*ecdsa.PrivateKey{}
	keys, err := kb.List()
	if err != nil {
		return res
	}
	for _, key := range keys {
		localInfo, ok := key.(keyring.LocalInfo)
		if !ok {
			// will only show local key
			continue
		}
		if localInfo.GetAlgo() != hd.Secp256k1Type {
			fmt.Printf("Skipping address %s because it isn't signed with secp256k1\n", localInfo.Name)
			continue
		}
		priv, err := legacy.PrivKeyFromBytes([]byte(localInfo.PrivKeyArmor))
		if err != nil {
			continue
		}
		privHex := hex.EncodeToString(priv.Bytes())
		privKey, err := crypto.HexToECDSA(privHex)
		if err != nil {
			continue
		}
		address := crypto.PubkeyToAddress(privKey.PublicKey)
		res[address.Hex()] = privKey
	}
	return res
}

**File:** evmrpc/AGENTS.md (L58-70)
```markdown
## Exported receivers are RPC surface — treat every export as a new endpoint

`go-ethereum`'s `rpc.Server` registers **every exported method** on a `Service`
struct passed to `RegisterName` (see `evmrpc/server.go`) as a callable JSON-RPC
method, named by lower-casing the method's first letter and prefixing with the
service's namespace (e.g. `InfoAPI.GasPriceHelper` → `eth_gasPriceHelper`).
This applies to `InfoAPI`, `FilterAPI`, `DebugAPI`, and every other struct
registered as a `Service` in `server.go` — there is no separate allowlist step
for "internal" helper methods.

**Any exported method added to a registered API struct is automatically a
live, unaudited RPC endpoint** — with no request validation, no rate-limit
review, and no `sei_*`-style gating unless someone deliberately adds it.
```
