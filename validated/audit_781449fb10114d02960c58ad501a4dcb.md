### Title
Cached FROST preprocess is reused without invalidation, so a second distinct message under the same context is signed with identical nonces, leaking the secret share - (File: coordinator/src/tributary/signing_protocol.rs)

### Summary

The external report's bug class — "a core operation assumes a cached/derived state is fresh and synced, but nothing enforces that invariant" — maps directly onto `SigningProtocol::preprocess_internal`. A preprocess seed is generated once per `context`, stored in the `CachedPreprocesses` DB table, and then *reused* on every subsequent signing call for that context. `sign.rs` explicitly states a cached preprocess "MUST only be used once. Reuse will enable third-party recovery of your private key share" [1](#0-0) , yet the coordinator never deletes or rotates the cached seed after it has produced a signature share.

### Finding Description

In `preprocess_internal`, the flow is:

1. If `CachedPreprocesses::get(txn, &context)` is empty, a fresh preprocess is generated and the seed is stored (XOR-encrypted under the signing key) [2](#0-1) .
2. The cached seed is then decrypted and passed to `AlgorithmSignMachine::from_cache` [3](#0-2) .

There is no `del`/`take` of `CachedPreprocesses` after signing. `share_internal` calls `preprocess_internal` again [4](#0-3) , and `DkgConfirmer::complete` calls `share_internal` yet again [5](#0-4) .

Because `from_cache` feeds the seed into `ChaCha20Rng::from_seed`, every invocation deterministically regenerates the *same* FROST nonces (`d`, `b`) and the same commitments [6](#0-5) . The message signed is `set_keys_message(set, removed, key_pair)` where `key_pair` is an argument supplied independently to `share` and to `complete` [7](#0-6) . Nothing binds the cached seed to the message it first signed, and nothing enforces that only one message is ever signed per context — the exact "unsynced cache" assumption from the report.

If two distinct messages (e.g., `share` called with `key_pair` A, then `complete` or a second `share` called with `key_pair` B under the same `(b"DkgConfirmer", attempt)` context — possible across a coordinator restart/re-key, since the DB cache persists while the in-memory machine is rebuilt) are signed, the attacker obtains two shares `s1 = d + ρ·b + λ·c1·x` and `s2 = d + ρ·b + λ·c2·x` with identical nonces, yielding `x = (s1 − s2)/(λ(c1 − c2))`: full recovery of the node's MuSig secret key share.

### Impact Explanation

Nonce reuse in FROST/Schnorr is a secret-share-recovery primitive. The victim node's Ristretto secret share — which backs the MuSig key authorizing validator-set key confirmations — is recoverable by anyone who observes both signature shares (broadcast over the authenticated tributary layer). Compromise of `t` such shares compromises the validator set's key. The code itself acknowledges the severity: reuse "enables recovery of your private key share" [8](#0-7) .

### Likelihood Explanation

The cache is keyed only by `context = (b"DkgConfirmer", attempt)` [9](#0-8) , and persists in the DB across restarts. Any path that causes a second `share_internal` under the same context with a different `key_pair` — a DKG re-run within the attempt after reboot, or `complete` being invoked with a `key_pair` that differs from the one `share` signed — triggers reuse. I could not fully verify in the remaining iterations whether `handle.rs` guarantees `share`/`complete` always see an identical `key_pair`; the finding holds that the *invariant is unenforced* (no DB deletion, no message binding in the cache key), matching the report's "no on-chain check that cache is synced" class. Severity: Medium (key-share recovery possible, but requires a divergent-message path rather than being unconditionally reachable by a pure network outsider).

### Recommendation

- Delete (or single-use consume) `CachedPreprocesses` once `share_internal` succeeds — store the serialized share/signature for re-derivation in `complete` instead of re-signing.
- Alternatively, bind the message into the cache key (`CachedPreprocesses::set(txn, (context, hash(msg)), …)`) and refuse to sign a second distinct message under one context.
- Have `complete` reuse the stored `AlgorithmSignatureMachine`/share rather than recomputing `share_internal` with a caller-supplied `key_pair`; assert the `key_pair` matches what was signed in `share`.

### Proof of Concept

1. Coordinator processes a DKG confirmation for `attempt = k`; `preprocess_internal` stores seed `S` under `context = (b"DkgConfirmer", k)` and `share` emits `s1` over `msg_A = set_keys_message(set, removed, kp_A)`.
2. `CachedPreprocesses` retains `S` — it is never cleared [10](#0-9) .
3. `complete` (or a second `share` after restart, where the DB seed survives but the machine does not) is invoked with `kp_B ≠ kp_A`; `preprocess_internal` reloads `S`, `seeded_preprocess` regenerates identical nonces, and `s2` over `msg_B` is emitted.
4. From `s1`, `s2`, and the public binding factors/challenges, compute `x = (s1 − s2) / (λ·(c1 − c2))` to recover the node's secret share, since `d + ρ·b` cancels.

Caveat: confirm in `coordinator/src/tributary/handle.rs` that a divergent `key_pair` between `share` and `complete` is reachable (e.g., via retry/attempt semantics); even if all current callers happen to pass identical values, the single-use invariant documented in `sign.rs` is structurally unenforced.

  fn seeded_preprocess(
    self,
    seed: CachedPreprocess,
  ) -> (AlgorithmSignMachine<C, A>, Preprocess<C, A::Addendum>) {
    let mut params = self.params;

    let mut rng = ChaCha20Rng::from_seed(*seed.0);
    let (nonces, commitments) = Commitments::new::<_>(
      &mut rng,
      params.keys.original_secret_share(),
      &params.algorithm.nonces(),
    );
    let addendum = params.algorithm.preprocess_addendum(&mut rng, &params.keys);

    let preprocess = Preprocess { commitments, addendum };

    // Also obtain entropy to randomly sort the included participants if we need to identify blame
    let mut blame_entropy = [0; 32];
    rng.fill_bytes(&mut blame_entropy);
    (
      AlgorithmSignMachine { params, seed, nonces, preprocess: preprocess.clone(), blame_entropy },
      preprocess,
    )
  }
