### Title
`castVotes` unwinds all real on-chain veWOM votes to zero when `totalVlMgpInVote` reaches 0 while `poolInfos[_lp].totalVoteInVlmgp` stays nonzero (delegatedPool desync) - ([File: wombat/WombatBribeManager.sol])

### Summary
`castVotes` computes each pool's `targetVote` only when `totalVlMgpInVote != 0`; otherwise `targetVote` defaults to `0` for every pool regardless of `poolInfos[_lp].totalVoteInVlmgp` [1](#0-0) . Because `vote()`/`unvote()` deliberately exclude `delegatedPool`'s contributions from `totalVlMgpInVote` while still updating `pool.totalVoteInVlmgp` [2](#0-1) [3](#0-2) , `totalVlMgpInVote` can fall to zero (once all non-delegated voters unvote) while pools still carry nonzero `totalVoteInVlmgp` from `delegatedPool` and still have nonzero currently-cast on-chain votes. Any unprivileged caller invoking the public `castVotes` in that state forces `votes[i] = -currentVote` for every pool, wiping all real veWOM votes on `wombatStaking` to zero.

### Finding Description
`totalVlMgpInVote` is a global aggregate that is only incremented/decremented for callers that are not `delegatedPool`:
```solidity
if (msg.sender != delegatedPool) {
    if (totalUserVote > 0) {
        userTotalVotedInVlmgp[msg.sender] += uint256(totalUserVote);
        totalVlMgpInVote += uint256(totalUserVote);
    } else {
        userTotalVotedInVlmgp[msg.sender] -= uint256(-totalUserVote);
        totalVlMgpInVote -= uint256(-totalUserVote);
    }
}
``` [4](#0-3) 
The same exclusion applies in `unvote()` [5](#0-4) . In both functions, however, `pool.totalVoteInVlmgp` (the per-pool tally) is updated unconditionally for every caller, including `delegatedPool` [6](#0-5) [7](#0-6) .

This means: if `delegatedPool` votes for a pool, `poolInfos[lp].totalVoteInVlmgp` increases but `totalVlMgpInVote` does not. If, subsequently, every non-delegated voter fully `unvote()`s their own stake (a normal, permissionless action any vlMGP holder can perform on their own tokens), `totalVlMgpInVote` returns exactly to `0`, while `poolInfos[lp].totalVoteInVlmgp` for the delegated pool(s) remains nonzero, and the actual on-chain veWOM allocation from a prior successful `castVotes()` (`currentVote = getVoteForLp(...)`) also remains nonzero.

Any unprivileged address can then call the public, access-control-free `castVotes(bool)`:
```solidity
uint256 targetVote = 0;
if (totalVlMgpInVote != 0) {
    targetVote = targetVoteInLMGP * totalVotes() / totalVlMgpInVote;
}
if (targetVote >= currentVote) {
    votes[i] = int256(targetVote - currentVote);
} else {
    votes[i] = int256(targetVote) - int256(currentVote);
}
``` [8](#0-7) 
Since `totalVlMgpInVote == 0`, `targetVote` stays `0` for every pool in the loop, so `votes[i] = -currentVote` for all pools that had nonzero on-chain votes, and this delta array is submitted straight to `wombatStaking.vote(...)` [9](#0-8) , unwinding every pool's real veWOM allocation to zero — including `delegatedPool`'s legitimately-cast votes that were never touched by any unvote — even though `poolInfos[lp].totalVoteInVlmgp` still reflects nonzero intended allocation.

No modifier, pause, or reentrancy guard prevents this: `castVotes` and `unvote` are both `public` with no caller restriction, and the zero-division guard `if (totalVlMgpInVote != 0)` is exactly the mechanism that produces the wrong result instead of preventing it.

### Impact Explanation
This causes governance/vote-integrity manipulation: an unprivileged caller can force a full reset of all Wombat gauge votes cast by the protocol's `wombatStaking` contract, disconnecting the actual on-chain veWOM allocation from the bribe manager's internal `totalVoteInVlmgp` bookkeeping used for bribe reward distribution. This wipes `delegatedPool`'s and any other voter's active vote weight without their consent, matching the "governance voting result manipulation" impact class. It also can misdirect/void bribe reward accrual for pools whose on-chain votes are zeroed while internal per-pool vote credit remains, corrupting reward attribution until the state is manually corrected by another `vote`/`castVotes` cycle.

### Likelihood Explanation
Requires `delegatedPool` to be actively used (a normal, expected operational configuration referenced throughout the contract — e.g., `IDelegateVoteRewardPool(delegatedPool).harvestAll()` in `castVotes`) [10](#0-9) , and requires all non-delegated voters to fully unvote at some point (their own permissionless action, needing no attacker capital) so that `totalVlMgpInVote` hits exactly `0`. Once that state occurs — which can happen naturally during low-participation periods or be raced/timed by an attacker who is one of the last remaining voters — any address, including a fresh unprivileged EOA, can trigger the exploit by simply calling `castVotes(false)`. No special privilege, flash loan, or governance access is required, and the attack is repeatable each time the zero-vote-total window recurs.

### Recommendation
Remove the `delegatedPool` exclusion asymmetry: either count `delegatedPool`'s votes into `totalVlMgpInVote` as well, or maintain a separate `totalVlMgpInVote`-equivalent denominator per accounting stream so that `targetVote` computation in `castVotes` never zeroes real per-pool allocations solely because the *regular*-voter aggregate is zero while delegated allocations are still outstanding. Additionally, guard `castVotes` so that when `totalVlMgpInVote == 0` but `pool.totalVoteInVlmgp > 0` (i.e., only delegated/other non-tracked votes exist), it does not blindly submit `votes[i] = -currentVote`.

### Proof of Concept
Foundry fork test plan:
1. Deploy/fork `WombatBribeManager`, `wombatStaking`, `veWom`, `voter`, and set `delegatedPool` to a mock `IDelegateVoteRewardPool`.
2. Regular user A locks vlMGP, calls `vote()` to allocate to pool P1; `delegatedPool` calls `vote()` to allocate to pool P2.
3. Call `castVotes(false)` — assert `getVoteForLp(P1) > 0` and `getVoteForLp(P2) > 0` on-chain.
4. User A calls `unvote(P1)` — assert `totalVlMgpInVote() == 0` while `poolInfos[P2].totalVoteInVlmgp > 0`.
5. From an unrelated unprivileged address, call `castVotes(false)`.
6. Assert `getVoteForLp(P2) == 0` (delegatedPool's real vote was wiped) despite `poolInfos[P2].totalVoteInVlmgp` remaining nonzero, confirming the desync-driven vote wipe.
