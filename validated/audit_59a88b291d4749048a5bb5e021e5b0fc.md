### Title
Unhandled `IndexError` in CLVM canonical-form check on truncated atom length prefix crashes spend-bundle validation - ([File: chia/full_node/mempool_manager.py])

### Summary
`is_atom_canonical()` in `chia/full_node/mempool_manager.py` reads variable-length atom-length-prefix bytes from an attacker-controlled buffer (`coin_spend.puzzle_reveal` / `coin_spend.solution`) without checking that enough bytes remain in the buffer before indexing into it. [1](#0-0)  This mirrors the underlying bug class in CVE-2021-38201, where `xdr_set_page_base` advanced/read past the bounds of a buffer while parsing a variable-length, attacker-influenced structure (NFS READ_PLUS), causing an out-of-bounds access.

### Finding Description
`is_clvm_canonical()` is called directly on every coin spend's `puzzle_reveal` and `solution` bytes inside `MempoolManager.validate_spend_bundle()`, which runs for every incoming, unauthenticated spend bundle before it is admitted to the mempool: [2](#0-1) 

Inside `is_atom_canonical(clvm_buffer, offset)`, once a length-prefix marker byte (`0x81`-`0xFD`, excluding `0xFE`/`0xFF`) is found, the function unconditionally advances `offset` and indexes `clvm_buffer[offset]` for `prefix_len` (up to 5) additional bytes to build up `atom_len`, with no bounds check against `len(clvm_buffer)`: [3](#0-2) 

If the caller `is_clvm_canonical()` reaches the last byte(s) of the buffer and that byte is a length-prefix marker requiring more trailing bytes than actually remain (e.g. a buffer that ends right after a `0xF8`-class marker byte with fewer than the required 4 trailing length bytes), `clvm_buffer[offset]` indexes past the end of the `bytes` object and Python raises an uncaught `IndexError`. [4](#0-3)  Unlike the C-language slab-out-of-bounds in the kernel, Python's memory safety turns this into a hard exception rather than silent memory corruption, but the reachable effect is the same class of bug: parsing a truncated/malformed variable-length-prefixed field drives the read cursor past the buffer boundary.

Neither `is_clvm_canonical()` nor its call site in `validate_spend_bundle()` wraps this logic in a `try/except`, so a crafted `puzzle_reveal` or `solution` with a truncated multi-byte atom-length prefix as its trailing bytes will raise an unhandled `IndexError` during mempool admission of an arbitrary spend bundle.

### Impact Explanation
This is reachable purely from a submitted spend bundle — no privileged access, peer trust, or CLVM execution success is required; the check runs on raw serialized bytes prior to/alongside coin/condition validation. An uncaught exception during `validate_spend_bundle()`/`add_spend_bundle()` in the async transaction-processing path can abort processing of that request and, depending on how the calling task/coroutine is supervised, disrupt the full node's mempool admission pipeline for that spend — a spend-triggered transaction-processing halt matching the "resource-only/DoS" bug class of the reference CVE, adapted to chia's memory-safe implementation.

### Likelihood Explanation
High likelihood of triggering the crash: constructing a `puzzle_reveal` or `solution` whose final bytes are a length-prefix marker byte (e.g. `0xF8`) followed by fewer than the required trailing bytes is trivial and entirely under attacker control, requiring no valid signature or successful CLVM execution to reach this code path (the check happens on the raw byte buffer inside `validate_spend_bundle`, before/alongside execution-result processing).

### Recommendation
Add explicit bounds checks in `is_atom_canonical()` before indexing `clvm_buffer[offset]` for each of the `prefix_len` trailing bytes, returning "not canonical" (or raising a handled/expected error) instead of indexing out of range. Additionally, wrap the `is_clvm_canonical()` calls in `validate_spend_bundle()` with an exception boundary that maps any parsing failure to `Err.INVALID_COIN_SOLUTION` rather than allowing an `IndexError` to propagate.

### Proof of Concept
Construct a `coin_spend.solution` (or `puzzle_reveal`) whose raw bytes end in a truncated 4-byte-length-prefix atom marker, e.g. a buffer ending in `\xf8` with zero trailing bytes (or `\xf8\x01\x02` with only 3 of the 4 required trailing bytes present) as the last atom of an otherwise well-formed CLVM list/pair structure. Submit a `SpendBundle` containing this as the `solution` for a coin spend; when `MempoolManager.validate_spend_bundle()` calls `is_clvm_canonical(bytes(coin_spend.solution))`, the walk reaches the truncated marker byte and `is_atom_canonical()` indexes past the end of the buffer, raising an unhandled `IndexError` instead of returning a normal `INVALID_COIN_SOLUTION` rejection. def is_atom_canonical(clvm_buffer: bytes, offset: int) -> tuple[int, bool]:
```python
    b = clvm_buffer[offset]
    if (b & 0b11000000) == 0b10000000:
        # 6 bits length prefix
        mask = 0b00111111
        prefix_len = 0
        min_value = 1
    elif (b & 0b11100000) == 0b11000000:
        # 5 + 8 bits length prefix
        mask = 0b00011111
        prefix_len = 1
        min_value = 1 << 6
    elif (b & 0b11110000) == 0b11100000:
        # 4 + 8 + 8 bits length prefix
        mask = 0b00001111
        prefix_len = 2
        min_value = 1 << (5 + 8)
    elif (b & 0b11111000) == 0b11110000:
        # 3 + 8 + 8 + 8 bits length prefix
        mask = 0b00000111
        prefix_len = 3
        min_value = 1 << (4 + 8 + 8)
    elif (b & 0b11111100) == 0b11111000:
        # 2 + 8 + 8 + 8 + 8 bits length prefix
        mask = 0b00000011
        prefix_len = 4
        min_value = 1 << (3 + 8 + 8 + 8)
    elif (b & 0b11111110) == 0b11111100:
        # 1 + 8 + 8 + 8 + 8 + 8 bits length prefix
        mask = 0b00000001
        prefix_len = 5
        min_value = 1 << (2 + 8 + 8 + 8 + 8)

    atom_len = b & mask
    for i in range(prefix_len):
        atom_len <<= 8
        offset += 1
        atom_len |= clvm_buffer[offset]

    return 1 + prefix_len + atom_len, atom_len >= min_value
```
