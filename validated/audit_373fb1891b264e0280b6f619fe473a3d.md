### Title
Precision-mismatch integer overflow in `TimeUtil::FromString` nanosecond scaling bypasses range validation - (File: `src/google/protobuf/util/time_util.cc`)

### Summary
`TimeUtil::FromString` parses a textual `Duration` (e.g. `"1.123456789012s"`) by splitting it into a seconds part and a fractional ("nanos") part, then scales the fractional digits up to nanosecond precision using `nanos * Pow(10, 9 - nanos_part.length())` [1](#0-0) . When the attacker-controlled fractional-digit count exceeds 9, the exponent `9 - nanos_part.length()` goes negative; `Pow()` treats a negative exponent as zero iterations and returns `1` instead of a fractional divisor [2](#0-1) , so the raw (unscaled, potentially far-larger-than-999999999) digit value is used directly and then narrowed with `static_cast<int32_t>` when stored into the `Duration.nanos` field [3](#0-2) .

### Finding Description
The invariant that fails is the same class as the ZNS report: a user/attacker-controlled scale parameter (`precisionMultiplier` in ZNS, the fractional-digit count in this analog) must remain compatible with a fixed reference precision (token decimals in ZNS, the fixed 9-digit nanosecond precision here), and the code never validates that compatibility before performing division/multiplication that can silently produce a wildly wrong value. Here, `nanos_part.length()` is derived directly from an attacker-supplied Duration string and is not bounded to `<= 9` before being used as an exponent input to `Pow(10, 9 - nanos_part.length())` [2](#0-1) [4](#0-3) . The subsequent `IsDurationValid(*duration)` check [5](#0-4)  is meant to be the safety net (analogous to the missing `_validateConfig()` check the ZNS report recommends), but because the raw 64-bit `nanos` value is truncated to `int32_t` via `static_cast` before that check runs, an overflow can wrap the value into the nominally "valid" `[-999999999, 999999999]` range, defeating the validation and yielding a `Duration` whose `nanos` field bears no numerical relationship to the digits the caller supplied.

### Impact Explanation
An application that exposes `TimeUtil::FromString` (or equivalent duration-text parsing) to untrusted input (e.g., accepting a duration string from a client request and converting it to a `Duration` proto) can be made to silently store an incorrect nanosecond value that passes internal validation, corrupting downstream time-based logic (timeouts, rate limits, billing intervals, scheduling) without any parse error being raised — directly mirroring the ZNS impact of a price silently computed as an unintended value due to unchecked precision-scale mismatch.

### Likelihood Explanation
Likelihood is Medium: the attacker needs only to supply a Duration string with more than 9 fractional digits, which is a simple, low-effort, fully attacker-controlled bounded text input; there is no fuzzing or timing complexity required. The main uncertainty is whether the specific consuming application exposes `TimeUtil::FromString` directly to untrusted input versus using the JSON WKT Duration/Timestamp parser in `src/google/protobuf/json/internal/parser.cc`, which I could not fully confirm has (or lacks) an equivalent, separately-implemented digit-count cap in this checkout — this should be verified before treating the finding as confirmed against the primary ProtoJSON ingestion path.

### Recommendation
In `TimeUtil::FromString` (`src/google/protobuf/util/time_util.cc`), reject or clamp `nanos_part` to a maximum of 9 digits before computing the scaling exponent, and change `Pow` (or the call site) to explicitly reject negative exponents rather than silently returning `1`. Perform the `int32_t` narrowing check (or an explicit magnitude bound check) prior to, not after, relying on `IsDurationValid` for correctness, so overflow cannot mask an out-of-range value as valid.

### Proof of Concept
Given the traced logic in `src/google/protobuf/util/time_util.cc:238-280` [6](#0-5) , calling `TimeUtil::FromString("1.123456789012s", &duration)` with a 12-digit fractional part produces `nanos_part.length() == 12`, so `Pow(10, 9 - 12) == Pow(10, -3)`, and since the `for (int i = 0; i < y; ++i)` loop in `Pow` never executes for negative `y` [2](#0-1) , it returns `1`. The raw parsed `nanos = 123456789012` is then narrowed via `static_cast<int32_t>(nanos)` when calling `duration->set_nanos(...)` [7](#0-6) , which truncates/wraps the 64-bit value into 32 bits — an implementation-defined/wrapping operation that can land inside `[-999999999, 999999999]` and thus pass `IsDurationValid` [5](#0-4) , silently yielding a `Duration` with a `nanos` value unrelated to the intended `0.123456789012` seconds. I was not able to execute this locally to capture concrete numeric output before the tool budget ran out, so this reproduction is traced from source but not empirically confirmed; a background session with build/test tooling would be needed to run the exact wrap-around numbers and confirm which specific overflowed value results.

bool TimeUtil::FromString(absl::string_view value, Duration* duration) {
  if (value.length() <= 1 || value[value.length() - 1] != 's') {
    return false;
  }
  bool negative = (value[0] == '-');
  size_t sign_length = (negative ? 1 : 0);
  // Parse the duration value as two integers rather than a float value
  // to avoid precision loss.
  std::string seconds_part, nanos_part;
  size_t pos = value.find_last_of('.');
  if (pos == std::string::npos) {
    seconds_part = std::string(
        value.substr(sign_length, value.length() - 1 - sign_length));
    nanos_part = "0";
  } else {
    seconds_part = std::string(value.substr(sign_length, pos - sign_length));
    nanos_part = std::string(value.substr(pos + 1, value.length() - pos - 2));
  }
  char* end;
  static_assert(sizeof(int64_t) == sizeof(long long),
                "sizeof int64_t is not sizeof long long");
  int64_t seconds = std::strtoll(seconds_part.c_str(), &end, 10);
  if (end != seconds_part.c_str() + seconds_part.length()) {
    return false;
  }
  int64_t nanos = std::strtoll(nanos_part.c_str(), &end, 10);
  if (end != nanos_part.c_str() + nanos_part.length()) {
    return false;
  }
  nanos = nanos * Pow(10, static_cast<int>(9 - nanos_part.length()));
  if (negative) {
    // If a Duration is negative, both seconds and nanos should be negative.
    seconds = -seconds;
    nanos = -nanos;
  }
  duration->set_seconds(seconds);
  duration->set_nanos(static_cast<int32_t>(nanos));
  if (!IsDurationValid(*duration)) {
    duration->Clear();
    return false;
  }
  return true;
}
