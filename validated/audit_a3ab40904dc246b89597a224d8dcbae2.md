### Title
Stop-hook review-set intersection logic drops committed changes after `git commit --amend`, causing the Stop-hook security review to silently skip dangerous edits - (File: `plugins/security-guidance/hooks/diffstate.py`)

### Summary
`compute_v2_review_set` computes the reviewable file set as the intersection `dirty_now & changed_since(baseline_sha)`. The `dirty_now` term is only populated from `git status --porcelain` plus a linear-HEAD-advance check (`_is_ancestor(head_at_capture, current_head)`). A completely normal git operation — `git commit --amend` (or any history-rewriting op such as `rebase`, `reset --soft && commit`, `cherry-pick`, squash) — replaces `head_at_capture` with a sibling commit rather than a descendant, so the ancestor check fails and the amended file's change is never added to `dirty_now`, while the working tree is clean (nothing in `git status`). Because `review_set` is an *intersection* rather than a union, the file is dropped from review entirely even though `changed_since` (diff against `baseline_sha`) still shows it as changed.

### Finding Description
`consume_stop_state` (`plugins/security-guidance/hooks/diffstate.py:74-113`) snapshots `baseline_sha` and `head_at_capture` under lock for the Stop hook [1](#0-0) . `handle_stop_hook` then calls `compute_v2_review_set(cwd, baseline_sha, head_at_capture, untracked_at_baseline)` to derive the set of files that will actually be sent to the LLM security reviewer [2](#0-1) .

Inside `compute_v2_review_set`:
- `dirty_now` = `tracked_dirty | new_untracked` from `git status`, extended only when `head_at_capture` is a strict git ancestor of the current `HEAD` (i.e. HEAD moved forward via ordinary commits) [3](#0-2) .
- `changed_since` = `git diff --name-only <baseline_sha>` against the *current worktree*, which reflects any committed or uncommitted change regardless of how HEAD got there [4](#0-3) .
- `review_set = dirty_now & changed_since` [5](#0-4) .

`_is_ancestor` uses `git merge-base --is-ancestor maybe_ancestor descendant` [6](#0-5) . After `git commit --amend`, the new HEAD's parent is the *same* parent as the pre-amend commit — the pre-amend commit (`head_at_capture`) is a sibling of the new commit, not an ancestor, so `_is_ancestor` returns `False`. The "HEAD advanced linearly" branch is skipped, `diff_base` stays `"HEAD"`, and no extra paths are unioned into `dirty_now`. Since the amend also commits any working-tree edits, `git status` is now clean, so `dirty_now` for the amended file is empty. `changed_since`, however, still contains the file because it diffs `baseline_sha` against the live worktree/HEAD. The intersection `dirty_now & changed_since` is therefore empty for that file, so it is silently excluded from `review_paths` and never reaches `parse_diff_into_files` / `analyze_code_security` — the file bypasses the Stop-hook LLM vulnerability scan entirely, with no error or warning surfaced (metrics simply show a smaller `review_set_count`).

`touched_paths`, which is what `record_touched_path`/`consume_stop_state` actually track per edited file, is not used to construct `review_paths` at all — it is only reported as a diagnostic count (`touched_paths_count`) [7](#0-6) . So there is no secondary check tying the review set back to the files Claude actually edited; the review set is derived purely from git state, and that git-state derivation has the gap described above.

No existing guard (allowlist, workspace binding, `_is_ancestor` fallback, or `touched_paths` cross-check) currently closes this gap — the amend/rewrite case is not handled anywhere in `compute_v2_review_set` or its callers.

### Impact Explanation
This breaks the stated invariant that "the review set must stay bound to the right repo, baseline, and touched paths": a file Claude modified and committed can be made invisible to the Stop-hook security reviewer using only an ordinary git operation (`git commit --amend`) with no special privilege. Any dangerous code (secret exfiltration, command injection, path traversal, SSRF, etc.) introduced this way ships without ever being flagged by the pattern rules pass being the only backstop, and the Stop-hook LLM diff review — the "final review" layer described in the plugin's own architecture — never sees it. This is a security-control bypass that lets attacker-influenced (e.g., prompt-injected) agent actions commit unreviewed vulnerable code, which can then be pushed/merged, i.e. a scoped bypass of Claude Code's automated code-security guardrail.

### Likelihood Explanation
The trigger is a single, extremely common git operation (`git commit --amend`), requiring no admin/maintainer privilege, no leaked credentials, and no social engineering beyond normal agentic workflow (Claude commonly amends commits to fix messages or squash small fixups, and a prompt-injected instruction in repository content — e.g. a README or issue asking Claude to "clean up the commit" — can reliably induce this). It is fully reproducible: any turn where Claude edits a file, commits it, then amends (with or without further changes) will exhibit the drop.

### Recommendation
Change the "HEAD advanced" detection so it isn't strictly ancestor-based, or fall back to a union rather than an intersection when the ancestor check fails. Concretely: when `head_at_capture != current_head` but `head_at_capture` is *not* an ancestor of `current_head` (amend/rebase/reset case), still include `_git_name_only(repo, f"{head_at_capture}...{current_head}")` (or diff `head_at_capture` directly against current HEAD) into `dirty_now`, instead of leaving `dirty_now` unchanged. Alternatively, drop the intersection semantics and instead review `changed_since` directly, using `dirty_now`/`touched_paths` only to prioritize rather than to filter out files.

### Proof of Concept
Integration test plan (extends existing `compute_v2_review_set` test suite):
1. Init a temp git repo, commit an initial safe file, capture `baseline_sha = capture_git_baseline(cwd)` and `head_at_capture = _git_rev_parse_head(cwd)` (simulating UPS).
2. Write a dangerous file (e.g. `os.system(user_input)`), `git add -A && git commit -m "wip"`.
3. `git commit --amend -m "fixed message"` (no content change, or add one more line) — this reproduces the sibling-commit scenario.
4. Assert `_is_ancestor(cwd, head_at_capture, _git_rev_parse_head(cwd))` is `False`.
5. Call `compute_v2_review_set(cwd, baseline_sha, head_at_capture, {})` and assert the dangerous file path IS present in `review_paths` (expected/fixed behavior) — currently the test would show it is ABSENT, demonstrating the bypass.
6. Assert `metrics["review_set_count"] == 0` and `metrics["changed_since_count"] >= 1`, proving the intersection zeroed out a genuinely changed, unreviewed file.

def _is_ancestor(cwd, maybe_ancestor, descendant):
    """True if `maybe_ancestor` is reachable from `descendant` (i.e. HEAD
    moved forward via commit/merge, not sideways via checkout)."""
    try:
        result = subprocess.run(
            [*GIT_CMD, "merge-base", "--is-ancestor", maybe_ancestor, descendant],
            cwd=cwd, capture_output=True, text=True, timeout=5,
        )
        return result.returncode == 0
    except (subprocess.TimeoutExpired, FileNotFoundError, OSError):
        return False
