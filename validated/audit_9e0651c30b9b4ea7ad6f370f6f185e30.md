### Title
Missing access control on `setAuctioneer()`/`setGasBufferEstimate()` allows any account to hijack the auction entry point - ([File: contracts/testing/system_contracts/AuctionEntryPointMock.sol])

### Summary
`AuctionEntryPointMock.sol`'s `setAuctioneer()` and `setGasBufferEstimate()` functions are declared `public` with no access-control modifier at all, mirroring the reported Teller `setCollateralEscrowBeacon()` bug class where a privileged setter lacked an owner/admin check.

### Finding Description
`setAuctioneer(address _auctioneer)` and `setGasBufferEstimate(uint256 _gasBufferEstimate)` are `public` functions that directly overwrite the `auctioneer` and `gasBufferEstimate` state variables without any `onlyOwner`, `onlyProposer`, or other restriction: [1](#0-0) 
Compare this with the `call()` function in the same contract, which is properly gated by the `onlyProposer` modifier (`msg.sender == block.coinbase`): [2](#0-1) 
The `auctioneer` address is the trusted party whose signature (`auctioneerSig`) is meant to authorize/validate searcher bids in the full (non-mocked) auction flow, as referenced in the commented-out verification logic: [3](#0-2) 
This contract is wired into the node's auction/bid encoding and decoding logic used for gasless/auction-bundle inclusion in block assembly, via `blockchain/system/auction.go`, which reads `auctioneer()` and `gasBufferEstimate()` from the entry point to validate and process bids: [4](#0-3) 

### Impact Explanation
Any unprivileged account can submit a transaction calling `setAuctioneer(attackerAddress)` on the entry point, replacing the legitimate auctioneer with an address the attacker controls. Since the auctioneer's signature is the trust anchor validating that a bid was approved by the real auctioneer (per the intended, non-commented verification logic), an attacker-controlled auctioneer can forge `auctioneerSig` values for arbitrary `AuctionTx` bids, allowing the attacker to inject or approve fraudulent auction/gasless bids that get included by the block proposer — this is auction/gasless settlement theft. Additionally, `setGasBufferEstimate()` being unrestricted allows manipulation of the gas buffer used in gas-refund accounting for auction transactions, potentially enabling gas-refund/fee abuse.

### Likelihood Explanation
High: no privileges, signature, or special conditions are required — a single plain transaction from any account triggers the vulnerable setter. This is directly reachable by any transaction sender interacting with the deployed `AuctionEntryPointMock` (or an equivalently-unprotected variant of the production auction entry point contract).

### Recommendation
Add an `onlyOwner` (or equivalent governance/admin-restricted) modifier to `setAuctioneer()` and `setGasBufferEstimate()`, matching the access-control pattern already used elsewhere in the codebase (e.g., `Ownable.onlyOwner` at `contracts/libs/openzeppelin-contracts-v2/contracts/ownership/Ownable.sol` lines 35-38, or the `onlyProposer` pattern already present in this same file). Ensure the production (non-mock) `AuctionEntryPoint`/`Kip249`/`Kip249V3` contracts referenced by `contracts/bindings/auction/Kip249.go` and `contracts/bindings/auctionv3/Kip249V3.go` (`changeAuctioneer`, `changeDepositVault`, `changeGasParameters`) apply equivalent restrictions; their Solidity source was not available in this index, so this must be independently confirmed against the actual production contract.

### Proof of Concept
1. Deploy or use the existing `AuctionEntryPointMock` at its system-contract address.
2. From any arbitrary account (no special role required), send a transaction calling `setAuctioneer(attacker)`.
3. `auctioneer` state variable is now `attacker`, with no revert and no ownership check: [5](#0-4) 
4. The attacker can now sign `auctioneerSig` for arbitrary `AuctionTx` structs, which would pass the auctioneer-signature check in the intended (uncommented) production logic, enabling forged/malicious bid approval.

*Note: the currently indexed `AuctionEntryPointMock.sol` has its cryptographic verification steps commented out, so the concrete signature-forgery consequence could not be directly confirmed against production `Kip249`/`Kip249V3` Solidity source, which was not present in this index — only the compiled Go bindings (`contracts/bindings/auction/Kip249.go`, `contracts/bindings/auctionv3/Kip249V3.go`) were found. It is recommended to verify against the full production Solidity source in a Devin session with complete repository access.*

func ReadAuctioneer(backend bind.ContractCaller, contractAddr common.Address, num *big.Int) (common.Address, error) {
	caller, err := contracts.NewIAuctionEntryPointCaller(contractAddr, backend)
	if err != nil {
		return common.Address{}, err
	}

	opts := &bind.CallOpts{BlockNumber: num}
	return caller.Auctioneer(opts)
}

func ReadGasBufferEstimate(backend bind.ContractCaller, contractAddr common.Address, num *big.Int) (uint64, error) {
	caller, err := contracts.NewIAuctionEntryPointCaller(contractAddr, backend)
	if err != nil {
		return 0, err
	}
	opts := &bind.CallOpts{BlockNumber: num}
	buffer, err := caller.GasBufferEstimate(opts)
	if err != nil {
		return 0, err
	}
	return buffer.Uint64(), nil
}
