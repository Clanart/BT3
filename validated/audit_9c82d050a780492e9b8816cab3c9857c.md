### Title
Unauthenticated miner-controlled coinbase outputs are reported as spendable received funds - ([File: networks/bitcoin/src/wallet/mod.rs])

### Summary
The Weblate bug class — an unauthenticated party causing the system to perform operations on attacker-controlled inputs — maps onto Serai's Bitcoin scanner: any third party (a miner) can craft a coinbase transaction paying to a Serai multisig script, and `Scanner::scan_block` will report that output as a received, spendable output even though coinbase outputs are immature for 100 blocks. The processor's scan pipeline applies only a `DUST` filter, not a maturity filter, so these outputs flow into the scheduler/signing pipeline as if spendable.

### Finding Description
`Scanner::scan_block` iterates `block.txdata` in full, including `txdata[0]` (the coinbase), matching every output purely by `script_pubkey` against the registered scripts [1](#0-0) . `scan_transaction` builds a `ReceivedOutput` for any match with no check that the containing transaction is a coinbase or immature [2](#0-1) . The doc comment acknowledges coinbase scanning but delegates maturity handling to a "post-processing pass" [3](#0-2)  — yet the only filter in the processor's scan loop is `output.balance().amount.0 >= N::DUST`; there is no coinbase/maturity check before outputs are pushed into the `ScannerEvent::Block` event and saved [4](#0-3) . `SignableTransaction::new` then consumes `ReceivedOutput`s as inputs unconditionally [5](#0-4) .

### Impact Explanation
An external party who mines a block (or causes a coinbase paying a Serai address, e.g., via a mining pool payout policy they control) gets an output registered as received funds. Any later Plan that includes it as an input produces a transaction spending an immature coinbase, which Bitcoin consensus/relay rejects (`bad-txns-premature-spend-of-coinbase`). The resulting batch stalls: `need_ack` back-pressure halts further scanning until ack [6](#0-5) , so an attacker can repeatedly stall or wedge the signing pipeline at zero protocol cost beyond mining, and funds are reported received that are not (yet) spendable — matching the accepted impact class.

### Likelihood Explanation
Requires winning/controlling a coinbase output, which any miner can do without any Serai privilege or cooperation. Payout-to-arbitrary-address coinbases are common (pool payouts), so this can occur organically as well as adversarially. Once the output is scanned, inclusion in a spend Plan is a normal scheduler path, so trigger likelihood is moderate; impact is bounded to a stall/failed relay rather than key compromise, fitting Medium.

### Recommendation
In `scan_block`/`scan_transaction` (or in `get_outputs` in `processor/src/networks/bitcoin.rs`), skip outputs from `tx.is_coinbase()` transactions, or tag `ReceivedOutput`s with a maturity height and have the scheduler exclude inputs younger than 100 confirmations. The check belongs where outputs are emitted (before `save_outputs`/`emit`), not delegated to callers.

### Proof of Concept
1. Mine a regtest/mainnet block whose coinbase `txdata[0]` contains a `TxOut` with `script_pubkey == p2tr_script_buf(group_key)` and value ≥ `DUST`.
2. After `N::CONFIRMATIONS`, `Scanner::scan_block` returns a `ReceivedOutput` for that coinbase outpoint (no coinbase check at `mod.rs:221-227`); the processor emits it via `ScannerEvent::Block` and persists it (`scanner.rs:562-704`).
3. Build `SignableTransaction::new(vec![that_output], payments, change, None, fee)` — it succeeds — and sign; `TransactionSignatureMachine::complete` produces a tx spending an immature coinbase.
4. `send_raw_transaction`/relay rejects it (`premature spend of coinbase`), and the un-acked batch keeps the scanner paused per `need_ack`.

  pub fn scan_transaction(&self, tx: &Transaction) -> Vec<ReceivedOutput> {
    let mut res = Vec::new();
    for (vout, output) in tx.output.iter().enumerate() {
      // If the vout index exceeds 2**32, stop scanning outputs
      let Ok(vout) = u32::try_from(vout) else { break };

      if let Some(offset) = self.scripts.get(&output.script_pubkey) {
        res.push(ReceivedOutput {
          offset: *offset,
          output: output.clone(),
          outpoint: OutPoint::new(tx.compute_txid(), vout),
        });
      }
    }
    res
