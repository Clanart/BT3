### Title
Silent swallowing of `InvalidProtocolBufferException` in `LazyFieldLite`/`LazyField` causes corrupted lazy sub-message data to be replaced with a default instance while the outer `parseFrom`/`mergeFrom` reports success - (File: `java/core/src/main/java/com/google/protobuf/LazyFieldLite.java`)

### Summary
`LazyFieldLite`, the (still-used, non-deprecated) legacy implementation backing Java `[lazy=true]` fields and `MessageSet` extensions, catches `InvalidProtocolBufferException` internally at three points — `ensureInitialized()`, `mergeFrom(CodedInputStream, ExtensionRegistryLite)`, and `mergeValueAndBytes()` — and, per its own comments, deliberately does **not** rethrow or log. Instead it marks the field `corrupted` and substitutes `defaultInstance`/leaves the prior value unchanged. The enclosing message's `parseFrom`/`mergeFrom` call therefore returns successfully even though a sub-message the attacker controlled was truncated/garbage, exactly mirroring the report's pattern of a downstream step failing and being swallowed while the overall operation is credited as a full success.

### Finding Description
`LazyFieldLite.ensureInitialized(MessageLite defaultInstance)` (lines 468-497) is the delayed-parse routine invoked the first time a lazy field's getter is called: [1](#0-0) 

```java
protected void ensureInitialized(MessageLite defaultInstance) {
  ...
  try {
    if (delayedBytes != null) {
      MessageLite parsedValue =
          defaultInstance.getParserForType().parseFrom(delayedBytes, extensionRegistry);
      this.value = parsedValue;
      this.memoizedBytes = delayedBytes;
    } else { ... }
  } catch (InvalidProtocolBufferException e) {
    // Nothing is logged and no exceptions are thrown. Clients will be unaware that this proto
    // was invalid.
    this.corrupted = true;
    this.value = defaultInstance;
    this.memoizedBytes = ByteString.EMPTY;
  }
}
```

The same defensive-swallow pattern recurs in `mergeFrom(CodedInputStream, ExtensionRegistryLite)`: [2](#0-1) 

and in `mergeValueAndBytes`: [3](#0-2) 

The consuming API surface is the standard public `MessageLite.parseFrom`/`Builder.mergeFrom` entry points; when the top-level message contains a field marked `[lazy = true]` (or is a `MessageSet` item routed through `LazyField extends LazyFieldLite`), the *outer* parse succeeds and returns `true`/a built message, even though the *inner* bytes for that specific field never validly decoded. The failed step (decoding the lazy sub-message) is exactly analogous to the report's "step 11" — wrapped so its failure cannot propagate, while the wrapping operation ("performUpkeep"/`parseFrom`) is still treated as a full, successful completion.

Newer code (`InternalLazyField`, added later, with `ExtensionRegistryLite.LazyExtensionMode.LAZY_VERIFY_ON_ACCESS`) explicitly acknowledges this is a defect class: it throws `InvalidProtobufRuntimeException` in the new mode, while explicitly retaining the "old behavior" of silently returning the default instance for backward compatibility: [4](#0-3) 

This confirms the maintainers recognize silent corruption as a real hazard, yet `LazyFieldLite` (the base class still used by generated Lite code and `MessageSet`/`LazyField`) retains the silent-swallow behavior unconditionally, with no mode flag to opt into strict verification.

### Impact Explanation
An attacker who controls the serialized bytes of one lazy field inside an otherwise well-formed message can force that field to decode to its empty default instance without any parse error being surfaced anywhere in the call chain: `parseFrom` returns normally, `IsInitialized`-style checks on the outer message see nothing wrong (the field is "present" as `defaultInstance`), and no exception/log is emitted (`corrupted` is a private, unexposed flag). Application logic that trusts a successful `parseFrom` result to mean "the data is valid" will silently operate on missing/blanked business data for that field — the direct analog of the team not receiving SALT because step 11 quietly failed. This is a data-integrity failure reachable purely through the public parse API, without any special privileges, matching a Medium-severity "state/asset inconsistency from silently-swallowed failure" class.

### Likelihood Explanation
Likelihood is moderate: it requires (a) a schema that uses `[lazy = true]` fields or `MessageSet` extensions (a supported, documented protobuf feature, not exotic), and (b) an attacker-controlled or corrupted byte range specifically inside that lazy sub-message while keeping the outer message's tag/length framing valid — straightforward to construct since the lazy bytes are stored/re-serialized as an opaque length-delimited blob. No race conditions, no privilege escalation, and no interaction with unrelated hardening (recursion/size limits) are needed to trigger it.

### Recommendation
- Propagate lazy-field corruption to the caller by default (as `LAZY_VERIFY_ON_ACCESS` does for `InternalLazyField`) rather than silently substituting the default instance in `LazyFieldLite.ensureInitialized`/`mergeFrom`/`mergeValueAndBytes`.
- At minimum, expose the `corrupted` flag publicly (e.g., via `isCorrupted()`) so consuming code can check it after a successful parse, and log the swallowed exception instead of discarding it silently.
- Migrate remaining `LazyFieldLite`/`LazyField` (MessageSet) users onto the same verify-on-access semantics used by `InternalLazyField`, removing the legacy silent-default behavior once compatibility constraints allow.

### Proof of Concept
1. Define a proto2 message with a field `optional Sub payload = 1 [lazy = true];` where `Sub` has some required/important content.
2. Serialize a valid outer message where `payload`'s length-delimited bytes are replaced with random/garbage bytes of a plausible length (outer tag/length framing remains syntactically correct).
3. Call `Outer.parseFrom(bytes)` via the standard generated Lite API. The call returns successfully (no exception).
4. Call `outer.getPayload()` — this invokes `LazyFieldLite.ensureInitialized`, which catches `InvalidProtocolBufferException` internally and returns `Sub.getDefaultInstance()`. No exception, no log entry, and `outer`'s overall parse status remains "success." The application cannot distinguish this from a legitimately-empty `payload` field, confirming that a partial/failed decode step is silently credited as a fully successful parse of the whole message, mirroring the report's invariant failure.

Note: I was unable to fully confirm at which release version `[lazy = true]` code generation currently routes through `LazyFieldLite` vs. `InternalLazyField` for all supported configurations, nor whether recent releases have flipped the default `LazyExtensionMode`; if `LAZY_VERIFY_ON_ACCESS` is now the enforced default for all generated `[lazy=true]` fields (not just `MessageSet`), the exposure would be reduced to legacy/opt-out configurations only. Confirming the current default requires inspecting `ExtensionRegistryLite`'s static default and the current codegen path for lazy fields, which I did not have iterations left to trace conclusively.

  /** Might lazily parse the bytes that were previously passed in. Is thread-safe. */
  protected void ensureInitialized(MessageLite defaultInstance) {
    if (value != null) {
      return;
    }
    synchronized (this) {
      if (value != null) {
        return;
      }
      try {
        if (delayedBytes != null) {
          // The extensionRegistry shouldn't be null here since we have delayedBytes.
          MessageLite parsedValue =
              defaultInstance.getParserForType().parseFrom(delayedBytes, extensionRegistry);
          this.value = parsedValue;
          this.memoizedBytes = delayedBytes;
        } else {
          this.value = defaultInstance;
          this.memoizedBytes = ByteString.EMPTY;
        }
      } catch (InvalidProtocolBufferException e) {
        // Nothing is logged and no exceptions are thrown. Clients will be unaware that this proto
        // was invalid.
        this.corrupted = true;
        this.value = defaultInstance;
        this.memoizedBytes = ByteString.EMPTY;
      }
    }
  }
