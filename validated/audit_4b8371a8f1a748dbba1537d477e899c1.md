### Title
Server-Side Request Forgery (SSRF) via attacker-controlled Data Layer mirror URLs - (File: `chia/data_layer/data_layer.py`)

### Summary
Any Data Layer client that subscribes to a store can be made to send outbound HTTP/HTTPS requests to arbitrary attacker-chosen hosts/ports, because the URLs used to locate download servers for a store originate from on-chain "mirror" coins that anyone can create with a spend bundle, and are consumed without any host/IP allow-listing before the node's DataLayer service issues requests to them.

### Finding Description
A mirror coin is a plain, permissionless CLVM object: `create_mirror_puzzle()` curries a fixed puzzle (`P2_PARENT.curry(Program.to(1))`), and its `CREATE_COIN` condition's memo field carries a `launcher_id` plus an arbitrary list of URL byte-strings [1](#0-0) . Because the puzzle hash is fixed and public, any wallet user can construct a spend bundle that creates such a coin for any `launcher_id`, memoized with arbitrary URLs — this requires no special privilege, only the ability to submit a spend bundle.

When a `DataLayerWallet` observes a coin being added whose puzzle hash matches `create_mirror_puzzle().get_tree_hash()`, it decodes the attacker-chosen URLs from the memo and, if the corresponding `launcher_id` (store) is tracked by this node, stores them via `dl_store.add_mirror` [2](#0-1) .

The `DataLayer` service later reads these server URLs via `get_available_servers_for_store` and iterates over them, issuing outbound requests through `insert_from_delta_file` → `download_file` → `http_download` using the raw, attacker-supplied `server_info.url` with no validation that it isn't a loopback, link-local, RFC1918, or cloud-metadata address [3](#0-2) . The same unrestricted-URL pattern also lets an attacker-registered mirror coerce the node's `get_downloader` plugin dispatch to POST arbitrary JSON containing the mirror's `url` to configured downloader plugins [4](#0-3) .

This matches the CVE-2022-0508 bug class: a value the application treats as a "resource locator" is taken from untrusted, remotely-supplied data and used directly to originate outbound requests, with no destination restriction.

### Impact Explanation
Any node that runs DataLayer and subscribes to a store can be forced to make outbound TCP/HTTP connections to internal-only or otherwise restricted network endpoints (e.g., `127.0.0.1`, RFC1918 ranges, or cloud metadata services), enabling internal network reconnaissance/port-scanning and, depending on deployment topology, disclosure of response content indirectly through timing/behavior. Because mirror creation is a normal, low-cost spend that any wallet can submit on-chain, this is broadly reachable and not limited to malicious peers or operators. Severity is Medium, consistent with the CVSS 6.5 rating of the analog PeerTube SSRF, since no direct coin-value theft or consensus divergence results, but a confidentiality/integrity-adjacent network-boundary bypass is achieved.

### Likelihood Explanation
Likelihood is high for any node participating in Data Layer subscriptions: mirror-coin creation is unauthenticated and cheap, requiring only the standard mirror puzzle and a `CREATE_COIN` condition with attacker-controlled memos, and the resulting URL is trusted end-to-end from wallet sync into the DataLayer HTTP fetch path.

### Recommendation
Validate and restrict `server_info.url` (and downloader/uploader plugin URLs derived from mirror data) before use in `http_download`/`download_file`/`get_downloader`: enforce an allow-list of schemes (`https`/`http`), reject loopback/link-local/private IP ranges and non-standard ports unless explicitly configured by the node operator, and consider resolving DNS to re-check the resolved IP prior to connecting (to defeat DNS-rebinding). Consider requiring operator opt-in/config-level allow-listing for mirror servers rather than trusting all on-chain-announced mirrors automatically.

### Proof of Concept
1. Attacker creates and pushes a spend bundle that spends a coin into `create_mirror_puzzle()`'s puzzle hash with a `CREATE_COIN` condition whose memo list is `[launcher_id, b"http://169.254.169.254/latest/meta-data/"]` (or `http://127.0.0.1:<internal-port>/...`), where `launcher_id` is the `store_id` of a Data Layer store the victim node subscribes to.
2. The victim's `DataLayerWallet.coin_added` observes the new mirror coin, calls `get_mirror_info` to decode the URL, and stores it via `dl_store.add_mirror` since the `launcher_id` is tracked [2](#0-1) .
3. On the next `fetch_and_validate` cycle, `DataLayer` pulls this URL from `get_available_servers_for_store` and calls `insert_from_delta_file`/`download_file`, which issues an outbound HTTP request to the attacker-chosen internal address [3](#0-2) .

def create_mirror_puzzle() -> Program:
    return P2_PARENT.curry(Program.to(1))


MIRROR_PUZZLE_HASH = create_mirror_puzzle().get_tree_hash()


def get_mirror_info(
    parent_puzzle: Program | SerializedProgram, parent_solution: Program | SerializedProgram
) -> tuple[bytes32, list[bytes]]:
    assert type(parent_puzzle) is type(parent_solution)
    _, conditions = run_with_cost(parent_puzzle, INFINITE_COST, parent_solution)
    for condition in conditions.as_iter():
        if (
            condition.first().as_python() == ConditionOpcode.CREATE_COIN
            and condition.at("rf").as_python() == create_mirror_puzzle().get_tree_hash()
        ):
            memos: list[bytes] = condition.at("rrrf").as_python()
            launcher_id = bytes32(memos[0])
            return launcher_id, [url for url in memos[1:]]
    raise ValueError("The provided puzzle and solution do not create a mirror coin")

    async def get_downloader(self, store_id: bytes32, url: str) -> PluginRemote | None:
        request_json = {"store_id": store_id.hex(), "url": url}
        for d in self.downloaders:
            async with aiohttp.ClientSession() as session:
                try:
                    async with session.post(
                        d.url + "/handle_download",
                        json=request_json,
                        headers=d.headers,
                        timeout=self.client_timeout,
                    ) as response:
                        res_json = await response.json()
                        if res_json["handle_download"]:
                            return d
                except Exception as e:
                    self.log.error(f"get_downloader could not get response: {type(e).__name__}: {e}")
        return None
