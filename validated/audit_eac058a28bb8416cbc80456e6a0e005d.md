### Title
Quadratic-blowup denial of service in `Offer.get_cancellation_coins()` via chained coin-announcement dependencies - ([File: chia/wallet/trading/offer.py])

### Summary
`Offer.get_cancellation_coins()` resolves inter-coin dependencies inside an offer by repeatedly calling `detect_dependent_coin()`, which does a full linear scan over all remaining coin names/dependencies/announcements on every invocation. Because the outer loop invokes this resolver up to N times (once per coin removed), a specially-crafted offer with N coins chained together through `ASSERT_COIN_ANNOUNCEMENT`/`CREATE_COIN_ANNOUNCEMENT` dependencies (opcodes 61/60) forces Θ(N²) work, directly analogous to the CommonMark `AttributesListener::findTargetAndDirection()` bug where each of N adjacent nodes performs an O(N) outward walk before being resolved.

### Finding Description
`detect_dependent_coin()` is a triple-nested scan: [1](#0-0) 

For each remaining coin name it walks all of that coin's dependencies, and for each dependency it walks the entire `announcement_dict` (all coins) looking for a match. `get_cancellation_coins()` builds `dependencies`/`announcements` from every non-addition coin spend's `CREATE_COIN_ANNOUNCEMENT` (`60`) / `ASSERT_COIN_ANNOUNCEMENT` (`61`) conditions, then loops calling `detect_dependent_coin()` and removing one coin (and its dependents) per iteration until no more dependent coins are found: [2](#0-1) 

If an offer is constructed so that coin 1 asserts an announcement made by coin 2, coin 2 asserts one from coin 3, and so on in a chain of N coins, each call to `detect_dependent_coin()` must scan through most of the remaining `names`/`deps`/`announcement_dict` before finding (or failing to find) a match, and this scan repeats once per removed coin — giving Θ(N²) behavior overall, unbounded by any CLVM cost accounting (the CLVM `run_with_cost` calls only bound the *initial* per-spend condition-parsing cost, not the subsequent Python-level dependency-resolution loop).

### Impact Explanation
This code path runs entirely in the victim wallet's process when handling a pending offer/trade — e.g. via `TradeManager.cancel_pending_offers()`, which is reachable from the `cancel_offer`/`cancel_offers` wallet RPC endpoints: [3](#0-2) 

`cancel_pending_offers()` calls `Offer.from_bytes(trade.offer).get_cancellation_coins()` for each trade being cancelled: [4](#0-3) 

A malicious offer counterparty (or a locally-crafted offer with a deliberately pathological announcement/dependency chain) that gets accepted into the wallet's trade store and later cancelled would cause the wallet's cancel/cancel-all RPC call to stall the wallet's synchronous processing (the call is made under `wallet_state_manager.lock`), degrading wallet availability. This is availability-only (no coin-set divergence, no unauthorized spend), matching the "spend-triggered transaction-processing halt" category, but bounded to the local wallet process rather than full-node consensus.

### Likelihood Explanation
Reachability requires the attacker's offer to actually be accepted as a pending trade in the victim's wallet (e.g. the victim made/received the offer and it's stored via `save_trade`), and then for the victim (or an automated `cancel_offers --cancel_all`) to trigger cancellation. This is a plausible but not trivially triggered path — it depends on wallet UX/RPC usage patterns rather than raw mempool/network exposure. I was not able to fully verify, within the available search budget, whether any upstream size/complexity limit already bounds the number of coin spends or announcement conditions inside an `Offer` before `get_cancellation_coins()` runs (aside from the per-spend CLVM cost check in `Offer.__init__`/`conditions()`, which does not bound the number of *coins*, only the CLVM execution cost per spend) — this uncertainty should be resolved by a deeper review of `Offer.__init__` and `WalletSpendBundle` validation before finalizing severity.

### Recommendation
Replace the O(N) linear announcement lookup in `detect_dependent_coin()` with a precomputed reverse index (announcement value → coin name), and/or resolve all dependent-coin removals in a single linear/topological pass instead of repeatedly restarting the triple-nested scan for each removal, reducing total complexity from Θ(N²) (or worse) to O(N).

### Proof of Concept
Construct an `Offer` (or `WalletSpendBundle`) with N coin spends, each emitting:
- `CREATE_COIN_ANNOUNCEMENT` with message `M_i`
- `ASSERT_COIN_ANNOUNCEMENT` asserting `M_{i+1}` (i.e., coin i depends on coin i+1's announcement)

forming a dependency chain of length N (e.g., N = 5,000–10,000). Call `offer.get_cancellation_coins()` (directly, or via `TradeManager.cancel_pending_offers()`/`cancel_offer` RPC after storing the trade) and observe that the wall-clock time grows quadratically with N, consistent with the nested-scan structure in `detect_dependent_coin()` at [1](#0-0) .

```python
def detect_dependent_coin(
    names: list[bytes32], deps: dict[bytes32, list[bytes32]], announcement_dict: dict[bytes32, list[bytes32]]
) -> tuple[bytes32, bytes32] | None:
    # First, we check for any dependencies on coins in the same bundle
    for name in names:
        for dependency in deps[name]:
            for coin, announces in announcement_dict.items():
                if dependency in announces and coin != name:
                    # We found one, now remove it and anything that depends on it (except the "provider")
                    return name, coin
    return None
```

```python
    def get_cancellation_coins(self) -> list[Coin]:
        # First, we're going to gather:
        dependencies: dict[bytes32, list[bytes32]] = {}  # all of the hashes that each coin depends on
        announcements: dict[bytes32, list[bytes32]] = {}  # all of the hashes of the announcement that each coin makes
        coin_names: list[bytes32] = []  # The names of all the coins
        additions = self.additions()
        for spend in [cs for cs in self._bundle.coin_spends if cs.coin not in additions]:
            name = bytes32(spend.coin.name())
            coin_names.append(name)
            dependencies[name] = []
            announcements[name] = []
            conditions: Program = run_with_cost(spend.puzzle_reveal, INFINITE_COST, spend.solution)[1]
            for condition in conditions.as_iter():
                if condition.first() == 60:  # create coin announcement
                    announcements[name].append(
                        AssertCoinAnnouncement(asserted_id=name, asserted_msg=condition.at("rf").as_python()).msg_calc
                    )
                elif condition.first() == 61:  # assert coin announcement
                    dependencies[name].append(bytes32(condition.at("rf").as_python()))

        # We now enter a loop that is attempting to express the following logic:
        # "If I am depending on another coin in the same bundle, you may as well cancel that coin instead of me"
        # By the end of the loop, we should have filtered down the list of coin_names to include only those that will
        # cancel everything else
        while True:
            removed = detect_dependent_coin(coin_names, dependencies, announcements)
            if removed is None:
                break
            removed_coin, provider = removed
            removed_announcements: list[bytes32] = announcements[removed_coin]
            remove_these_keys: list[bytes32] = [removed_coin]
            while True:
                for coin, deps in dependencies.items():
                    if set(deps) & set(removed_announcements) and coin != provider:
                        remove_these_keys.append(coin)
                removed_announcements = []
                for coin in remove_these_keys:
                    dependencies.pop(coin)
                    removed_announcements.extend(announcements.pop(coin))
                coin_names = [n for n in coin_names if n not in remove_these_keys]
                if removed_announcements == []:
                    break
                else:
                    remove_these_keys = []

        return [cs.coin for cs in self._bundle.coin_spends if cs.coin.name() in coin_names]
```
