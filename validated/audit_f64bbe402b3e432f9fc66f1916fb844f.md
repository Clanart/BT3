### Title
Weak `isGitHubHost` hostname-pattern match lets an attacker-controlled host masquerade as GitHub Enterprise, causing credential helper to treat it as a trusted GitHub endpoint - (File: `app/src/lib/api.ts`)

### Summary
`isGitHubHost()` uses the regex `/(^|\.)(github)\./.test(hostname)` as a fast-path heuristic to decide whether an unknown remote host "is" a GitHub (Enterprise) host. Any attacker who can register or control a domain such as `github.attacker.com` satisfies this pattern, even though it has no real relationship to GitHub. This function feeds `getEndpointKind()` in the Git credential trampoline, which decides how the credential helper should respond to a Git host's authentication challenge for an arbitrary remote/proxy the user is interacting with.

### Finding Description
`isGitHubHost` is meant to distinguish genuine GitHub/GHE hosts from third-party hosts (GitLab, Bitbucket, etc.) so that Desktop only offers GitHub OAuth-derived credentials to genuine GitHub endpoints. Its fallback heuristic, intended to catch self-hosted GHES instances that follow the `github.<company-domain>` naming convention, is: [3](#0-2) 
This pattern only checks that the string "github." appears at the very start of the hostname (or immediately after a dot), with no further validation that the remainder of the hostname corresponds to a domain the user has actually registered as an Enterprise account. Consequently, `github.evil.com`, `github.notgithub.io`, or any subdomain the attacker chooses that begins with `github.` will satisfy the check and short-circuit to `return true` before the function ever attempts the safer `x-github-request-id` header verification later in the same function. This mirrors the reported bytestring bug's broken invariant: a partial/prefix match is treated as a full equality/identity check, producing an incorrect "true" for data that only superficially resembles the trusted value.

This function is consumed by `getEndpointKind`, which is the decision point the trampoline credential helper uses when Git asks Desktop to supply credentials for an arbitrary host (triggered whenever the user clones/fetches/pushes to a remote URL, including one controlled by an attacker via a malicious link, submodule URL, or proxy): [4](#0-3) 
If none of the earlier, more precise checks (`isDotCom`, `isGHE`, WWW-Authenticate realm header, cached account) resolve the host, `getEndpointKind` falls back to `isGitHubHost(endpoint)`, and any positive result is classified as `'enterprise'` — a classification the caller uses to fill in the corresponding stored GitHub/GHE account's OAuth token as the Git credential for that host.

### Impact Explanation
If an attacker controls (or can register) a hostname beginning with `github.` — a low bar, since it requires no relationship to the real github.com — a victim who clones/fetches/pushes to a URL on that host (e.g., via a malicious repository link, a compromised/attacker-controlled submodule remote, or an on-path proxy presenting such a hostname) can cause Desktop's credential helper to classify the host as `'enterprise'` and hand over the user's stored GitHub OAuth token as an HTTP Basic/Bearer credential to that attacker-controlled host. This is a credential/token exfiltration primitive reachable purely by getting the user to interact with a crafted remote URL — no local access, malware, or leaked credentials required.

### Likelihood Explanation
Exploitability depends on `isGitHubHost`'s earlier, stronger checks (`isDotCom`, `isGHE`, `isKnownThirdPartyHost`, and the later live `x-github-request-id` HTTP probe) not already resolving the classification first — the weak regex is only reached as a fallback. For a host the attacker fully controls, the attacker can simply avoid responding with `x-github-request-id`/matching a known-third-party pattern, but the vulnerable regex check runs and returns `true` *before* that network probe even executes, meaning the flawed heuristic alone is sufficient to short-circuit to `true`. The realistic precondition is: the user has (or the app derives) a remote/URL pointing at an attacker-chosen `github.*` hostname and performs a Git operation that triggers credential negotiation.

### Recommendation
Replace the substring/prefix heuristic with an allowlist or stricter validation tied to hosts the user has actually configured as GitHub Enterprise accounts (i.e., only trust hosts matching `account.endpoint`/`isGHE`/`isDotCom` for known accounts), or require the live `x-github-request-id` verification (already implemented later in the function) to be authoritative rather than short-circuited by the regex guess. At minimum, do not classify unknown hosts as `'enterprise'` credential targets based on a naming convention alone.

### Proof of Concept
1. Attacker registers `github.attacker-mitm.com` (or any subdomain that begins with `github.`) and configures it as an HTTP git remote/proxy the victim will access (e.g., via a crafted clone URL, a submodule pointing at it, or a MITM proxy presenting this Host header).
2. Victim performs `git fetch`/`git clone`/`git push` in GitHub Desktop against that host; Git invokes the trampoline credential helper for authentication.
3. `getEndpointKind` fails to resolve via `isDotCom`/`isGHE`/cached account/realm header, and calls `isGitHubHost('https://github.attacker-mitm.com')`.
4. `isGitHubHost` evaluates `/(^|\.)(github)\./.test('github.attacker-mitm.com')` → `true`, returning `true` immediately without the network probe.
5. `getEndpointKind` returns `'enterprise'`, causing the trampoline to supply the user's stored GitHub Enterprise/GitHub.com OAuth token as the Git credential to the attacker's host.

/**
 * Attempts to determine whether or not the url belongs to a GitHub host.
 *
 * This is a best-effort attempt and may return `undefined` if encountering
 * an error making the discovery request
 */
export async function isGitHubHost(url: string) {
  const { hostname } = new window.URL(url)

  const endpoint =
    hostname === 'github.com' || hostname === 'api.github.com'
      ? getDotComAPIEndpoint()
      : getEnterpriseAPIURL(url)

  if (isDotCom(endpoint) || isGHE(endpoint)) {
    return true
  }

  if (isKnownThirdPartyHost(hostname)) {
    return false
  }

  // github.example.com,
  if (/(^|\.)(github)\./.test(hostname)) {
    return true
  }

const getEndpointKind = async (cred: Credential, store: Store) => {
  const credentialUrl = getCredentialUrl(cred)
  const endpoint = `${credentialUrl}`

  if (isGist(endpoint)) {
    return 'generic'
  }

  if (isDotCom(endpoint)) {
    return 'github.com'
  }

  if (isGHE(endpoint)) {
    return 'ghe.com'
  }

  // When Git attempts to authenticate with a host it captures any
  // WWW-Authenticate headers and forwards them to the credential helper. We
  // use them as a happy-path to determine if the host is a GitHub host without
  // having to resort to making a request ourselves.
  for (const [k, v] of cred.entries()) {
    if (k.startsWith('wwwauth[')) {
      if (v.includes('realm="GitHub"')) {
        return 'enterprise'
      } else if (/realm="(GitLab|Gitea|Atlassian Bitbucket)"/.test(v)) {
        return 'generic'
      }
    }
  }

  const existingAccount = await findGitHubTrampolineAccount(store, endpoint)
  if (existingAccount) {
    return isDotCom(existingAccount.endpoint) ? 'github.com' : 'enterprise'
  }

  // All GitHub hosts use HTTPS, so if the protocol is not HTTPS we can
  // assume that this is not a GitHub host.
  if (credentialUrl.protocol !== 'https:') {
    return 'generic'
  }

  return (await isGitHubHost(endpoint)) ? 'enterprise' : 'generic'
}
