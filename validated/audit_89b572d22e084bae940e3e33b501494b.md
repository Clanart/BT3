### Title
Attacker-controlled `ThresholdKeys` deserialization triggers quadratic Lagrange interpolation DoS - ([File: crypto/dkg/src/lib.rs](crypto/dkg/src/lib.rs))

### Summary
`ThresholdKeys::read` accepts a serialized participant count `n` and threshold `t` of up to 65,535, then `ThresholdKeys::new` computes the group key using independently calculated Lagrange factors. Each factor scans the complete participant list, making construction `O(t²)` for `t == n`. [1](#0-0) [2](#0-1) [3](#0-2) 

### Finding Description
The deserializer reads attacker-controlled `t`, `n`, and participant index `i` from six bytes, optionally reads `n` coefficients, then reads `n` verification shares before calling `ThresholdKeys::new`. [1](#0-0) 

For Lagrange interpolation, `ThresholdKeys::new` constructs `included = 1..=t` and calls `interpolation_factor` once for every included participant. [3](#0-2)  Each `interpolation_factor` call iterates over the whole `included` list and performs field operations proportional to `t`. [2](#0-1) 

With `t = n = 65,535`, deserialization performs approximately `65,535² = 4,294,836,225` inner-loop iterations after consuming roughly two megabytes of serialized scalar and point encodings. [4](#0-3) [5](#0-4) 

### Impact Explanation
A single small serialized `ThresholdKeys` object can cause billions of field operations and inversions during deserialization. If `ThresholdKeys::read` is exposed to peer-controlled protocol bytes or stored objects, an unprivileged sender can consume disproportionate CPU resources and stall the processing thread.

This is the same bug class as the referenced ReDoS issue: a compact public input selects a pathological polynomial workload, even though the implementation does not use regular expressions. The affected primitive is the explicit `ThresholdKeys::read` untrusted-byte surface.

### Likelihood Explanation
The attacker controls both `t` and `n`, and `ThresholdParams::new` permits `t == n` as long as neither is zero and `i <= n`. [6](#0-5)  The body needs only well-formed field and group encodings, with no secret knowledge or privileged role. [7](#0-6) 

The quadratic work is unconditional for valid serialized Lagrange keys; duplicate indexes and out-of-range participants are not involved because deserialization itself emits the sequential map `1..=n`. [8](#0-7) 

### Recommendation
Avoid independently recomputing every Lagrange coefficient. Calculate all coefficients in linear time using a total numerator product plus batch inversion, or precompute prefix/suffix products. Alternatively, derive the group key through a representation that avoids per-participant interpolation at key-construction time.

If `ThresholdKeys::read` accepts untrusted data, also enforce a deployment-appropriate maximum `n` before allocating vectors or maps and before entering `ThresholdKeys::new`.

### Proof of Concept
Construct a serialized `ThresholdKeys<C>` containing:

1. `C::ID.len()` as `u32`, followed by `C::ID`.
2. `t = 65,535`, `n = 65,535`, and `i = 1`.
3. Interpolation selector `1` for `Interpolation::Lagrange`.
4. One canonical nonzero scalar for `secret_share`.
5. `65,535` canonical group encodings for verification shares.
6. Pass the buffer to `ThresholdKeys::<C>::read`.

That input reaches `ThresholdKeys::new`, where the group-key calculation invokes the `O(n)` Lagrange factor routine `65,535` times. [9](#0-8) [3](#0-2)

  fn interpolation_factor(&self, i: Participant, included: &[Participant]) -> F {
    match self {
      Interpolation::Constant(c) => c[usize::from(u16::from(i) - 1)],
      Interpolation::Lagrange => {
        let i_f = F::from(u64::from(u16::from(i)));

        let mut num = F::ONE;
        let mut denom = F::ONE;
        for l in included {
          if i == *l {
            continue;
          }

          let share = F::from(u64::from(u16::from(*l)));
          num *= share;
          denom *= share - i_f;
        }

        // Safe as this will only be 0 if we're part of the above loop
        // (which we have an if case to avoid)
        num * denom.invert().unwrap()
      }
