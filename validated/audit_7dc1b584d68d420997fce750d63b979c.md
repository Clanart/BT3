Based on my investigation, I don't find a valid analog for this vulnerability class in the chia-blockchain codebase.

The WJLP bug is specific to Yeti Finance's wrapped-LP-token architecture: `WJLP` maintains an **internal accounting ledger** (staked balance per user in a Masterchef-style contract) that is separate from the actual custody of the underlying JLP tokens. The bug arises because `ActivePool.sendCollateralsUnwrap` withdraws real tokens via `unwrapFor` but fails to call `_userUpdate` to sync the internal ledger, letting users double-claim rewards against a stale balance.

Chia's coin-set model does not have this class of bug because there is no decoupled internal balance ledger that can desync from actual asset custody:

- `PoolWallet.claim_pool_rewards` directly consumes the actual p2-singleton reward coins into the singleton lineage via `create_absorb_spend` — the "reward" and its consumption are the same on-chain object, not a separately tracked balance. [1](#0-0) 
- `PlotNFT2Wallet.claim_rewards` similarly spends the actual reward coins (`removals=[reward.coin for reward in rewards_to_claim]`) rather than decrementing a cached counter. [2](#0-1) 
- `CRCATWallet.claim_pending_approval_balance` selects and spends the actual `CoinType.CRCAT_PENDING` coins to move them into spendable state; balance is always derived from `get_unspent_coins_for_wallet` over real coin records, never a separately maintained "staked" counter.
