### Title
Unauthenticated SSRF via DataLayer mirror URL registration for arbitrary/unowned stores - (File: chia/data_layer/data_layer_wallet.py)

### Summary
`DataLayerWallet.create_new_mirror()` lets any wallet user publish an on-chain "mirror" coin advertising arbitrary URLs for **any** `launcher_id` (store id), including stores the caller does not own, with no scheme or destination allowlisting. [1](#0-0)  Any DataLayer node that later subscribes to that store id will treat the attacker-supplied URL as a legitimate mirror server and issue an outbound HTTP request to it via `http_download()`, without validating the URL against a scheme/host allowlist. [2](#0-1) 

### Finding Description
`create_new_mirror()` builds a standard `CREATE_COIN` to the well-known `create_mirror_puzzle()` puzzle hash, with `memos=[[launcher_id, *urls]]`. It performs no check that the caller's wallet owns or controls `launcher_id`, and no validation of the URL contents (scheme, host, internal-address filtering): [1](#0-0) 

This RPC is directly reachable by an ordinary wallet user via `dl_new_mirror` / the `add_mirror` DataLayer RPC, requiring only a standard coin spend and fee — the same trust level as any other wallet transaction: [3](#0-2) [4](#0-3) 

Once confirmed on chain, any other node's `DataLayer` service will discover this URL as an available "server" for the targeted store id (`get_available_servers_for_store`) and will attempt to fetch delta/full files from it during `fetch_and_validate()`, using a plain, unauthenticated `aiohttp` GET against the attacker-controlled URL with no scheme allow-list or private-network exclusion: [5](#0-4) [2](#0-1) 

This mirrors the CVE-2026-50112 bug class: an authenticated, low-privileged actor supplies a URL that is blindly trusted and fetched by a backend service (here, the DataLayer server/mirror-sync loop) without re-validating scheme/destination, enabling SSRF against internal or otherwise-unreachable hosts from the fetching node.

Note: unlike the CloudStack report, chia's downloaded content is parsed into the DataStore via `insert_into_data_store_from_file()`, which reconstructs the Merkle tree and requires it to match the wallet-advertised root hash before being committed, so this path does not appear to grant arbitrary code execution or unauthenticated data poisoning — the impact is limited to SSRF (server-side request forgery / internal network probing), not the RCE component of the original CVE.

### Impact Explanation
A single confirmed, low-cost spend bundle lets an attacker force any DataLayer node that later subscribes to the targeted store (which can be arbitrarily chosen, even a store the attacker doesn't own) to make outbound HTTP requests to attacker-chosen internal addresses (e.g., cloud metadata endpoints, other local services, or internal-only management ports on the operator's network). This is a persistent, on-chain-anchored SSRF primitive that any node syncing DataLayer subscriptions will unknowingly trigger.

### Likelihood Explanation
High reachability: creating a mirror coin requires only a normal wallet transaction (small XCH amount + fee) via a public RPC/CLI (`dl_new_mirror`/`add_mirror`), with no ownership check on the target store and no URL validation. The only precondition is that some node subscribes to the targeted store id, which is normal DataLayer usage.

### Recommendation
- In `DataLayerWallet.create_new_mirror()` / the `add_mirror` RPC path, validate mirror URLs against an allowlist of schemes (`http`/`https` only) and reject private/internal/loopback/link-local addresses before broadcasting the mirror coin, or at minimum re-validate at fetch time in `http_download()`/`fetch_and_validate()` before issuing the outbound request.
- Consider requiring that only the store's owning wallet (or a locally configured trust list) can register mirrors that are automatically fetched, or require explicit user opt-in per mirror URL/host before a node's sync loop will contact it.

### Proof of Concept
1. Attacker chooses any `launcher_id` (their own or someone else's store) and calls `dl_new_mirror` (or `chia data add_mirror`) with `urls=["http://169.254.169.254/latest/meta-data/"]` or an internal RPC/service address, paying a nominal amount+fee.
2. Transaction confirms on chain; `DataLayerStore.add_mirror()` persists the mirror record for that `launcher_id`.
3. Any node that later subscribes to that store id runs `update_subscription()` → `fetch_and_validate()`, discovers the attacker's URL via `get_available_servers_for_store`, and calls `http_download()`, causing that node to issue an outbound GET request to the attacker-chosen internal target. async def http_download(
    target_filename_path: Path,
    filename: str,
    proxy_url: str | None,
    server_info: ServerInfo,
    timeout: aiohttp.ClientTimeout,
    log: logging.Logger,
    max_delta_file_size: int,
) -> None:
    """
    Download a file from a server using aiohttp.
    Raises exceptions on errors
    """
    async with aiohttp.ClientSession() as session:
        headers = {"accept-encoding": "gzip"}
        async with session.get(
            server_info.url + "/" + filename,
            headers=headers,
            timeout=timeout,
            proxy=proxy_url,
        ) as resp:
            resp.raise_for_status()
            size = int(resp.headers.get("content-length", 0))
            max_delta_file_size_bytes = max_delta_file_size * 1024 * 1024
            if size > max_delta_file_size_bytes:
                raise MaxDeltaFileSizeExceededError(f"Maximum delta file size exceeded: {max_delta_file_size} MiB.")
