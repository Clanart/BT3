## Analysis Result

This confirmed: `x/evm/state/balance.go` `getSeiAddress()` resolves an EVM sender's bank account via `s.k.GetSeiAddressOrDefault(s.ctx, evmAddr)`, which returns the cast address (`sdk.AccAddress(evmAddr[:])`) only until an association exists, and switches permanently to the true `seiAddr` once `SetAddressMapping` is called [1](#0-0) , matching `x/evm/keeper/address.go`'s `GetSeiAddressOrDefault` [2](#0-1) .

The association flow (`AssociationHelper.AssociateAddresses` / `MigrateBalance`) explicitly refuses to reuse a cast account holding vesting/locked funds — it only migrates `SpendableCoins` and the wei balance, and only removes/reclaims the cast account when `LockedCoins` is zero [3](#0-2) , a behavior directly exercised by `TestAssociateAddressesDoesNotReuseVestingCastAccount` [4](#0-3) . This is reachable by any user calling the public `associate`/`associatePubKey` methods of the `addr` precompile at `0x1004` [5](#0-4) , or automatically via `EVMAddressDecorator.AnteHandle` on any Cosmos-signed tx [6](#0-5) .

### Title
Locked/vesting balance stranded and permanently unreachable at the cast address after EVM↔Sei address association - (File: `utils/helpers/associate.go`)

### Summary
When a user calls the `addr` precompile's `associate`/`associatePubKey` (or the address gets associated implicitly through the ante handler), any bank balance locked in the account at the "cast address" (`sdk.AccAddress(evmAddr[:])`, e.g. a vesting grant made before the account has a registered pubkey) is left behind. Only spendable coins and wei are migrated to the newly-associated real Sei address; the underlying account holding `LockedCoins` is neither migrated nor removed, and once the address mapping is set, all future EVM balance/state operations from that EVM key permanently resolve to the new real Sei address instead of the cast address, orphaning the locked account and any coins it accrues as its vesting schedule unlocks.

### Finding Description
`AssociationHelper.AssociateAddresses` calls `MigrateBalance`, which moves `SpendableCoins` and the wei balance from `castAddr` to `seiAddr`, but explicitly skips migrating anything still subject to `LockedCoins` and only deletes the cast `BaseAccount` when `LockedCoins` is zero [7](#0-6) . Additionally, `AssociateAddresses` will not "reuse" the cast account (to preserve its account number/sequence for the new Sei address) if that account is not a plain `BaseAccount` with no pubkey — a vesting account is explicitly excluded, forcing a brand-new account to be created for `seiAddr` while the vesting account at `castAddr` is left untouched [8](#0-7) , verified by `TestAssociateAddressesDoesNotReuseVestingCastAccount` [4](#0-3) .

Before association, EVM state transitions signed by the same private key resolve their Sei-side balance via `GetSeiAddressOrDefault`, which returns the cast address when no mapping exists [2](#0-1) , so the EVM-tx path is the natural way to interact with funds sitting at the cast address (since the cast address itself has no registered pubkey and cannot be spent via a normal Cosmos-signed transaction). Once `SetAddressMapping` runs (as part of `AssociateAddresses`, `x/evm/keeper/address.go:10`), every subsequent EVM operation from that key resolves through `x/evm/state/balance.go`'s `getSeiAddress` to the real `seiAddr` instead [1](#0-0) . Any locked coins still sitting in the abandoned cast account — including future vesting tranches that unlock over time — become permanently unreachable: the cast address has no pubkey to sign a native Cosmos tx, and the only alternate path (routing an EVM transaction through the mapping) now points at a different account entirely.

### Impact Explanation
This causes concrete, permanent freezing of funds: any usei/wei balance subject to `LockedCoins` (e.g., a vesting grant issued to the cast form of an EVM address prior to association) becomes irrecoverable once that EVM address is associated, satisfying the "permanent freezing of funds" bar. The association action itself is unprivileged and can be triggered by the account holder (or, per the ante-handler path, implicitly by any signer of a Cosmos tx), so the vulnerable transition is user/attacker-reachable, not merely a passive risk.

### Likelihood Explanation
Occurrence requires a bank balance (locked coins/vesting) to exist at the cast address of an EVM key before that key calls `associate`/`associatePubKey` or signs a Cosmos tx that triggers auto-association — a realistic scenario for any workflow that grants vesting to a "cast" Sei address derived from a known EVM address ahead of the user completing formal association (e.g., airdrops/vesting programs targeting EVM users who haven't yet associated). Once that condition holds, the loss is deterministic and irreversible on the very first association call.

### Recommendation
`MigrateBalance`/`AssociateAddresses` should also migrate the full account balance held under `LockedCoins` (e.g., by moving the vesting account's underlying schedule/state to the new Sei address, or by tracking a mapping so the vesting account's future unlocks are still redeemable by the associated owner) instead of silently abandoning it. At minimum, association should be blocked/warned when the cast address still holds a nonzero `LockedCoins` balance until an explicit migration path for vesting/locked funds exists.

### Proof of Concept
1. A vesting grant is created for `castAddr = sdk.AccAddress(evmAddr[:])` with `LockedCoins` > 0 (e.g., via `x/auth/vesting`), as modeled by `TestAssociateAddressesDoesNotReuseVestingCastAccount` [4](#0-3) .
2. The owner of the private key behind `evmAddr` calls the `addr` precompile `associate(v, r, s, customMessage)` at `0x1004`, invoking `associateAddresses` → `AssociateAddresses` → `MigrateBalance` [5](#0-4) [3](#0-2) .
3. Only `SpendableCoins`/wei move to the new `seiAddr`; the vesting account (and its locked/future-unlocking balance) remains at `castAddr`, which now has no pubkey path and is no longer targeted by `GetSeiAddressOrDefault` for any subsequent EVM activity from that key [2](#0-1) [1](#0-0) .
4. As the vesting schedule advances, the now-spendable portion at `castAddr` can never be withdrawn by the user through either the Cosmos-native path (no pubkey registered on that account) or the EVM path (mapping now points elsewhere), permanently freezing those funds.

func (p AssociationHelper) AssociateAddresses(ctx sdk.Context, seiAddr sdk.AccAddress, evmAddr common.Address, pubkey cryptotypes.PubKey, migrateUseiOnly bool) error {
	castAddr := sdk.AccAddress(evmAddr[:])
	if !castAddr.Equals(seiAddr) && p.accountKeeper.GetAccount(ctx, seiAddr) == nil {
		castAcc := p.accountKeeper.GetAccount(ctx, castAddr)
		castBaseAcc, ok := castAcc.(*authtypes.BaseAccount)
		if ok && castBaseAcc.GetPubKey() == nil && p.bankKeeper.LockedCoins(ctx, castAddr).IsZero() {
			p.accountKeeper.SetAccount(ctx, authtypes.NewBaseAccount(seiAddr, pubkey, castBaseAcc.GetAccountNumber(), castBaseAcc.GetSequence()))
		}
	}
	p.evmKeeper.SetAddressMapping(ctx, seiAddr, evmAddr)
	acc := p.accountKeeper.GetAccount(ctx, seiAddr)
	if acc == nil {
		acc = p.accountKeeper.NewAccountWithAddress(ctx, seiAddr)
	}
	if acc.GetPubKey() == nil {
		if err := acc.SetPubKey(pubkey); err != nil {
			return err
		}
		p.accountKeeper.SetAccount(ctx, acc)
	}
	return p.MigrateBalance(ctx, evmAddr, seiAddr, migrateUseiOnly)
}

func (p AssociationHelper) MigrateBalance(ctx sdk.Context, evmAddr common.Address, seiAddr sdk.AccAddress, migrateUseiOnly bool) error {
	castAddr := sdk.AccAddress(evmAddr[:])
	if castAddr.Equals(seiAddr) {
		return nil
	}
	var castAddrBalances sdk.Coins
	if migrateUseiOnly {
		castAddrBalances = sdk.Coins{p.bankKeeper.GetBalance(ctx, castAddr, "usei")}
	} else {
		castAddrBalances = p.bankKeeper.SpendableCoins(ctx, castAddr)
	}
	if !castAddrBalances.IsZero() {
		if err := p.bankKeeper.SendCoins(ctx, castAddr, seiAddr, castAddrBalances); err != nil {
			return err
		}
	}
	castAddrWei := p.bankKeeper.GetWeiBalance(ctx, castAddr)
	if !castAddrWei.IsZero() {
		if err := p.bankKeeper.SendCoinsAndWei(ctx, castAddr, seiAddr, sdk.ZeroInt(), castAddrWei); err != nil {
			return err
		}
	}
	if p.bankKeeper.LockedCoins(ctx, castAddr).IsZero() {
		p.accountKeeper.RemoveAccount(ctx, authtypes.NewBaseAccountWithAddress(castAddr))
	}
	return nil
}

func (p PrecompileExecutor) associate(ctx sdk.Context, method *abi.Method, args []interface{}, value *big.Int) (ret []byte, remainingGas uint64, err error) {
	if err := pcommon.ValidateNonPayable(value); err != nil {
		return nil, 0, err
	}

	if err := pcommon.ValidateArgsLength(args, 4); err != nil {
		return nil, 0, err
	}

	// v, r and s are components of a signature over the customMessage sent.
	// We use the signature to construct the user's pubkey to obtain their addresses.
	v := args[0].(string)
	r := args[1].(string)
	s := args[2].(string)
	customMessage := args[3].(string)

	rBytes, err := decodeHexString(r)
	if err != nil {
		return nil, 0, err
	}
	sBytes, err := decodeHexString(s)
	if err != nil {
		return nil, 0, err
	}
	vBytes, err := decodeHexString(v)
	if err != nil {
		return nil, 0, err
	}

	vBig := new(big.Int).SetBytes(vBytes)
	rBig := new(big.Int).SetBytes(rBytes)
	sBig := new(big.Int).SetBytes(sBytes)

	// Derive addresses
	vBig = new(big.Int).Add(vBig, utils.Big27)

	customMessageHash := crypto.Keccak256Hash([]byte(customMessage))
	evmAddr, seiAddr, pubkey, err := helpers.GetAddresses(vBig, rBig, sBig, customMessageHash)
	if err != nil {
		return nil, 0, err
	}

	return p.associateAddresses(ctx, method, evmAddr, seiAddr, pubkey)
}

func (p PrecompileExecutor) associatePublicKey(ctx sdk.Context, method *abi.Method, args []interface{}, value *big.Int) (ret []byte, remainingGas uint64, err error) {
	if err := pcommon.ValidateNonPayable(value); err != nil {
		return nil, 0, err
	}

	if err := pcommon.ValidateArgsLength(args, 1); err != nil {
		return nil, 0, err
	}

	// Takes a single argument, a compressed pubkey in hex format, excluding the '0x'
	pubKeyHex := args[0].(string)

	pubKeyBytes, err := hex.DecodeString(pubKeyHex)
	if err != nil {
		return nil, 0, err
	}

	// Parse the compressed public key
	pubKey, err := btcec.ParsePubKey(pubKeyBytes)
	if err != nil {
		return nil, 0, err
	}

	// Convert to uncompressed public key
	uncompressedPubKey := pubKey.SerializeUncompressed()

	evmAddr, seiAddr, pubkey, err := helpers.GetAddressesFromPubkeyBytes(uncompressedPubKey)
	if err != nil {
		return nil, 0, err
	}

	return p.associateAddresses(ctx, method, evmAddr, seiAddr, pubkey)
}

func (p PrecompileExecutor) associateAddresses(ctx sdk.Context, method *abi.Method, evmAddr common.Address, seiAddr sdk.AccAddress, pubkey cryptotypes.PubKey) (ret []byte, remainingGas uint64, err error) {
	// Check that address is not already associated
	_, found := p.evmKeeper.GetEVMAddress(ctx, seiAddr)
	if found {
		return nil, 0, fmt.Errorf("address %s is already associated with evm address %s", seiAddr, evmAddr)
	}

	// Associate Addresses:
	associationHelper := helpers.NewAssociationHelper(p.evmKeeper, p.bankKeeper, p.accountKeeper)
	err = associationHelper.AssociateAddresses(ctx, seiAddr, evmAddr, pubkey, false)
	if err != nil {
		return nil, 0, err
	}

	ret, err = method.Outputs.Pack(seiAddr.String(), evmAddr)
	return ret, pcommon.GetRemainingGas(ctx, p.evmKeeper), err
}

//nolint:revive
func (p *EVMAddressDecorator) AnteHandle(ctx sdk.Context, tx sdk.Tx, simulate bool, next sdk.AnteHandler) (sdk.Context, error) {
	sigTx, ok := tx.(authsigning.SigVerifiableTx)
	if !ok {
		return ctx, sdkerrors.Wrap(sdkerrors.ErrTxDecode, "invalid tx type")
	}
	signers := sigTx.GetSigners()
	for _, signer := range signers {
		if evmAddr, associated := p.evmKeeper.GetEVMAddress(ctx, signer); associated {
			ctx.EventManager().EmitEvent(sdk.NewEvent(evmtypes.EventTypeSigner,
				sdk.NewAttribute(evmtypes.AttributeKeyEvmAddress, evmAddr.Hex()),
				sdk.NewAttribute(evmtypes.AttributeKeySeiAddress, signer.String())))
			continue
		}
		acc := p.accountKeeper.GetAccount(ctx, signer)
		if acc.GetPubKey() == nil {
			logger.Error("missing pubkey for signer", "signer", signer)
			ctx.EventManager().EmitEvent(sdk.NewEvent(evmtypes.EventTypeSigner,
				sdk.NewAttribute(evmtypes.AttributeKeySeiAddress, signer.String())))
			continue
		}
		pk, err := btcec.ParsePubKey(acc.GetPubKey().Bytes())
		if err != nil {
			logger.Debug("failed to parse pubkey for account, likely due to the fact that it isn't on secp256k1 curve", "account", acc.GetPubKey(), "err", err)
			ctx.EventManager().EmitEvent(sdk.NewEvent(evmtypes.EventTypeSigner,
				sdk.NewAttribute(evmtypes.AttributeKeySeiAddress, signer.String())))
			continue
		}
		evmAddr, err := helpers.PubkeyToEVMAddress(pk.SerializeUncompressed())
		if err != nil {
			logger.Error("failed to get EVM address from pubkey", "err", err)
			ctx.EventManager().EmitEvent(sdk.NewEvent(evmtypes.EventTypeSigner,
				sdk.NewAttribute(evmtypes.AttributeKeySeiAddress, signer.String())))
			continue
		}
		ctx.EventManager().EmitEvent(sdk.NewEvent(evmtypes.EventTypeSigner,
			sdk.NewAttribute(evmtypes.AttributeKeyEvmAddress, evmAddr.Hex()),
			sdk.NewAttribute(evmtypes.AttributeKeySeiAddress, signer.String())))
		p.evmKeeper.SetAddressMapping(ctx, signer, evmAddr)
		associationHelper := helpers.NewAssociationHelper(p.evmKeeper, p.evmKeeper.BankKeeper(), p.accountKeeper)
		if err := associationHelper.MigrateBalance(ctx, evmAddr, signer, false); err != nil {
			logger.Error("failed to migrate EVM address balance", "address", evmAddr, "err", err)
			return ctx, err
		}
	}
