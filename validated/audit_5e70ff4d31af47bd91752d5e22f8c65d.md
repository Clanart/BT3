### Title
Deserialization of identity encryption keys forces ECDH to the identity point, exposing DKG secret shares to any observer - (File: crypto/dkg/pedpop/src/encryption.rs)

### Summary
`EncryptionKeyMessage::read` and `EncryptedMessage::read` deserialize curve points with `Ciphersuite::read_G`, which enforces canonical encodings but explicitly does *not* reject the identity point (the identity-rejecting variant, `Curve::read_G`, lives in `crypto/frost` and is not used here). A DKG participant can therefore register an identity encryption public key. Every secret share encrypted "to" that participant then uses an ECDH shared point equal to the identity, making the ChaCha20 keystream key publicly derivable and revealing the plaintext shares to any third party that observes the authenticated channel.

### Finding Description
The PedPoP encryption module derives each message's cipher from a transcript of the ECDH shared point:

- `ecdh(private, public) = public * private` — `crypto/dkg/pedpop/src/encryption.rs:95-97` [1](#0-0) 
- `cipher()` builds `ChaCha20` keyed by `H(context || ecdh.to_bytes())` with a fixed IV — `crypto/dkg/pedpop/src/encryption.rs:101-133` [2](#0-1) 

Encryption computes `ecdh(key, enc_keys[participant])` where `enc_keys[participant]` is the destination's registered public key — `crypto/dkg/pedpop/src/encryption.rs:466` [3](#0-2) .

Registration reads `enc_key` via `C::read_G` (i.e. `Ciphersuite::read_G`) and stores it with no identity or validity check — `crypto/dkg/pedpop/src/encryption.rs:57-59` and `:360` [4](#0-3) [5](#0-4) .

`Ciphersuite::read_G` only checks that the bytes are a canonical encoding; the identity encoding is canonical and is accepted — `crypto/ciphersuite/src/lib.rs:91-101` [6](#0-5) . The identity-rejecting wrapper exists only in `Curve::read_G` — `crypto/frost/src/curve/mod.rs:125-131` [7](#0-6)  — which is used for FROST nonce commitments (`crypto/frost/src/nonce.rs:34-36`) but not for the DKG encryption keys.

Likewise, `SchnorrSignature::read` accepts an identity `R` (`crypto/schnorr/src/lib.rs:51-53`), so a `pop` of `(R = identity, s = 0)` trivially satisfies the verification equation `s·G == R + c·A` when `A = key = identity` — `crypto/schnorr/src/lib.rs:88-99` [8](#0-7) .

### Impact Explanation
When a malicious participant registers `enc_key = identity`, every honest participant who encrypts a share for them computes `ecdh = identity * k = identity`. The ChaCha20 key becomes `H(context || identity_bytes)`, where `context` is the public DKG session transcript value. Anyone who can observe the ciphertext — other participants, relayers, or anyone the authenticated channel broadcasts to — can recompute the keystream and recover the plaintext secret share. This converts untrusted deserialization input into recovery of secret share material that was meant to be confidential to the (malicious) recipient, degrading the threshold key's confidentiality to any passive observer without requiring collusion.

### Likelihood Explanation
The attack requires the malicious participant to submit one malformed `EncryptionKeyMessage` during DKG setup — a single 32/33-byte identity encoding that parses successfully. No honest-party misbehavior or special timing is needed. Exploitation value is bounded by how much of the DKG transcript is visible to the attacker beyond their own share, which is protocol/deployment dependent, so severity is Medium rather than High.

### Recommendation
Reject identity points when reading encryption keys. In `EncryptionKeyMessage::read` and `EncryptedMessage::read` (and `EncryptionKeyProof::read`), add an `is_identity()` check after `C::read_G`, mirroring `Curve::read_G` in `crypto/frost/src/curve/mod.rs:125-131`. Alternatively, assert `enc_key`/`key` are non-identity inside `Decryption::register` and `Decryption::decrypt_with_proof`/`Encryption::decrypt` so the invariant holds regardless of the read path.

```rust
// EncryptionKeyMessage::read succeeds because Ciphersuite::read_G
// accepts the canonical identity encoding.
let mut msg = vec![];
// ... inner M::read bytes for params ...
msg.extend(C::G::identity().to_bytes().as_ref()); // enc_key = identity
let reg: EncryptionKeyMessage<C, M> =
    EncryptionKeyMessage::read(&mut msg.as_slice(), params).unwrap();

// Every honest party's encrypt() for P_mal now does:
//   ecdh(k, identity) == identity
//   cipher key = H("DKG Encryption v0.2" || context || "encryption_key"
//                  || identity.to_bytes())
// which any observer of the ciphertext can recompute, yielding
// the plaintext share sent to P_mal.

// The accompanying EncryptedMessage PoP also validates trivially:
// key = identity, pop = SchnorrSignature { R: identity, s: 0 }
//   verify: s·G == R + c·A  =>  0 == identity + c·identity  == identity ✓
```

```rust
fn cipher<C: Ciphersuite>(context: [u8; 32], ecdh: &Zeroizing<C::G>) -> ChaCha20 {
  // Ideally, we'd box this transcript with ZAlloc, yet that's only possible on nightly
  // TODO: https://github.com/serai-dex/serai/issues/151
  let mut transcript = RecommendedTranscript::new(b"DKG Encryption v0.2");
  transcript.append_message(b"context", context);

  transcript.domain_separate(b"encryption_key");

  let mut ecdh = ecdh.to_bytes();
  transcript.append_message(b"shared_key", ecdh.as_ref());
  ecdh.as_mut().zeroize();

  let zeroize = |buf: &mut [u8]| buf.zeroize();

  let mut key = Cc20Key::default();
  let mut challenge = transcript.challenge(b"key");
  key.copy_from_slice(&challenge[.. 32]);
  zeroize(challenge.as_mut());

  // Since the key is single-use, it doesn't matter what we use for the IV
  // The issue is key + IV reuse. If we never reuse the key, we can't have the opportunity to
  // reuse a nonce
  // Use a static IV in acknowledgement of this
  let mut iv = Cc20Iv::default();
  // The \0 is to satisfy the length requirement (12), not to be null terminated
  iv.copy_from_slice(b"DKG IV v0.2\0");

  // ChaCha20 has the same commentary as the transcript regarding ZAlloc
  // TODO: https://github.com/serai-dex/serai/issues/151
  let res = ChaCha20::new(&key, &iv);
  zeroize(key.as_mut());
  res
}
```

```rust
  fn read_G<R: Read>(reader: &mut R) -> io::Result<Self::G> {
    let mut encoding = <Self::G as GroupEncoding>::Repr::default();
    reader.read_exact(encoding.as_mut())?;

    let point = Option::<Self::G>::from(Self::G::from_bytes(&encoding))
      .ok_or_else(|| io::Error::other("invalid point"))?;
    if point.to_bytes().as_ref() != encoding.as_ref() {
      Err(io::Error::other("non-canonical point"))?;
    }
    Ok(point)
  }
```
