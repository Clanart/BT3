### Title
`SignableTransaction`/`multisig` never verifies declared prevout values, letting forged `ReceivedOutput`s cause the threshold key to sign transactions committing to non-existent funds - (File: networks/bitcoin/src/wallet/send.rs)

### Summary
Analogous to `Gate1.accessSuck()` calling `vat.suck()` with nothing ensuring the drawn amount stays below the vow's surplus buffer, `SignableTransaction::new` and `multisig` consume caller/scanner-supplied `ReceivedOutput`s and sign `TapSighash` commitments over their claimed `TxOut` values with nothing ensuring those values correspond to real on-chain UTXOs. The only integrity check binds the prevout's `script_pubkey` to the derived offset key — the committed `value` is trusted blindly.

### Finding Description
`SignableTransaction::new` takes `Vec<ReceivedOutput>` as `inputs` and uses `input_sat` (the sum of the *declared* prevout values) to check solvency: `if input_sat < (payment_sat + needed_fee) { Err(NotEnoughFunds) }` [1](#0-0) . The prevouts are then stored verbatim into the transaction: `prevouts: inputs.drain(..).map(|input| input.output).collect()` [2](#0-1) .

At signing time, `multisig` only verifies the *script* of each prevout matches the key derivation: `if p2tr_script_buf(offset.group_key())? != self.prevouts[i].script_pubkey { None? }` [3](#0-2) . `sign` then computes `cache.taproot_key_spend_signature_hash(i, &Prevouts::All(&self.tx.prevouts), TapSighashType::Default)`, which commits the FROST signature share to the *claimed* value of every input [4](#0-3) . `ReceivedOutput` is deserializable from untrusted bytes via `ReceivedOutput::read` [5](#0-4)  — its `output` field (a full `TxOut` including `value`) is attacker-controlled data once it enters this pipeline, exactly the "assume the buffer is big enough" trust the MakerDAO annotation wrongly relied on.

### Impact Explanation
An unprivileged party who can inject or corrupt a `ReceivedOutput` (e.g., via `ReceivedOutput::read`-deserialized bytes fed into `SignableTransaction::new`) causes the honest threshold signers to produce a BIP-341 signature committing to input amounts that do not exist on-chain. Two consequences: (1) the signed transaction is consensus-invalid — the threshold has expended a signing attempt and produced a TX that can never confirm, burning the plan/eventuality and stalling funds; (2) combined with `fee()` (`sum(inputs) - sum(outputs)`) [6](#0-5) , an inflated declared value makes the constructed transaction "report" receiving/committing funds that are not actually spendable. The signature itself is valid for the signed message, so blame attribution in `complete` will not flag any participant [7](#0-6) .

### Likelihood Explanation
Reachable whenever the `ReceivedOutput` pipeline carries attacker-influenced bytes (the crate exposes `ReceivedOutput::read` for exactly this untrusted-input surface). It requires no malicious validator, no collusion, and no leaked key — just one forged output with a correct `script_pubkey` (which is publicly derivable from the group key and offset) and an arbitrary `value`. The missing check is unconditional: there is no code path that ever compares a prevout's declared value against chain state inside the in-scope signing path.

### Recommendation
In `SignableTransaction::new` (or `multisig`), do not trust the `TxOut` embedded in `ReceivedOutput` beyond what was actually observed on-chain: treat `scan_transaction` results as the sole source of prevouts (they copy `output` verbatim from the block [5](#0-4) ), and document/enforce that `ReceivedOutput`s constructed or read from untrusted sources must be re-validated against the referenced outpoint before signing — the equivalent of actually calling `vow.heal()` rather than commenting that it "can" be called.

### Proof of Concept
```rust
// From networks/bitcoin/src/wallet/send.rs shape:
// Attacker crafts a ReceivedOutput whose `output` has the honest
// script_pubkey (publicly derivable) but an inflated `value`.
let forged = TxOut {
  value: Amount::from_sat(21_000_000_0000_0000), // does not exist on-chain
  script_pubkey: p2tr_script_buf(group_key).unwrap(), // passes the multisig() check
};
let fake_input = ReceivedOutput { offset: Scalar::ZERO, output: forged, outpoint: some_real_outpoint };

// input_sat is computed from the forged value, so the solvency check passes.
let tx = SignableTransaction::new(vec![fake_input], &payments, change, None, fee).unwrap();
// All honest participants sign taproot sighashes committing to the fake amount.
let signed = sign(&keys, &tx); // produces a valid FROST signature
// `signed` is consensus-invalid: Prevouts::All committed to a value the UTXO
// does not carry. The plan's signing attempt is consumed and cannot confirm.
```

  pub fn multisig(self, keys: &ThresholdKeys<Secp256k1>) -> Option<TransactionMachine> {
    let mut sigs = vec![];
    for i in 0 .. self.tx.input.len() {
      let offset = keys.clone().offset(self.offsets[i]);
      if p2tr_script_buf(offset.group_key())? != self.prevouts[i].script_pubkey {
        None?;
      }

      sigs.push(AlgorithmMachine::new(Schnorr::new(), keys.clone().offset(self.offsets[i])));
    }

    Some(TransactionMachine { tx: self, sigs })
  }
