### Title
Distribution precompile `rewards()` accepts value but never refunds/consumes it, permanently stranding sent usei/wei - ([File: precompiles/distribution/distribution.go])

### Summary
The `rewards()` view method of the distribution precompile (address `0x...1007`) is missing the `pcommon.ValidateNonPayable(value)` guard that every other query method in the same file enforces. Because the EVM `CALL` opcode transfers `value` (usei/wei) into the precompile's associated account balance before the precompile logic runs, and `rewards()` never inspects, consumes, or refunds `value`, any usei/wei sent along with a call to `rewards()` becomes permanently stranded in the precompile's account.

### Finding Description
In `precompiles/distribution/distribution.go`, the `Execute` dispatcher routes `RewardsMethod` directly to `p.rewards(ctx, method, args)` without passing or validating `value`: [1](#0-0) 

Every other read-only method in the file (`params`, `validatorOutstandingRewards`, `validatorCommission`, `validatorSlashes`, `delegationRewards`, `delegatorValidators`, `delegatorWithdrawAddress`, `communityPool`) calls `p.validateInput(value, args, N)`, which internally calls `pcommon.ValidateNonPayable(value)` and rejects any nonzero value: [2](#0-1) 

`rewards()` itself only validates argument length — it never checks `value`: [3](#0-2) 

This is exactly analogous to the reported `SwapRouter` bug class: a function that can receive native value (ETH/usei) but has a code path where the value is not consumed and not refunded, leaving it stranded in the contract's balance where it can be extracted by other logic (e.g., `withdrawDelegationRewards`/`withdrawValidatorCommission`, which do call `HandlePaymentUsei` to shift `value` from the precompile account to the payer, or, generically, any keeper/precompile call that debits the module's/precompile's usei balance) — or simply lost forever since the module account has no code path that refunds it.

The Solidity/JS test suite comment for this exact function documents the awareness of this quirk without treating it as fixed: [4](#0-3) 

Mechanically, in `RunAndCalculateGas` (the dynamic-gas precompile entrypoint used by all precompiles including distribution), `value` is passed straight through to `Execute` without any framework-level transfer-back or non-payable enforcement — each precompile method is individually responsible for validating/handling `value`: [5](#0-4) 

Since the EVM's call semantics already moved the caller's usei/wei into the precompile's associated Sei account balance as part of the `CALL` (this is the standard mechanism `HandlePaymentUsei`/`HandlePaymentUseiWei` are built to reverse for other methods), and `rewards()` performs no such reversal, the funds simply sit in the precompile's associated account.

### Impact Explanation
Any unprivileged EVM transaction sender or contract that calls `rewards(address)` on the distribution precompile with a nonzero `msg.value` will have that usei/wei permanently removed from their control and credited to the distribution precompile's associated Sei account, with no built-in path in this method to get it back. This is a direct, reachable fund-loss bug from a single transaction — matching the "concrete fund loss" bar. It requires only calling a public precompile function with value attached; no privileged actor, governance, or malicious peer is needed.

### Likelihood Explanation
High likelihood of accidental triggering: any integrator (wallet, dApp, aggregator) that naively attaches `value` to `rewards()` calls (e.g., due to copy-paste from a payable withdraw call, or an integration bug) will silently lose funds with no revert to signal the mistake — unlike sibling view methods, which correctly revert via `ValidateNonPayable`. It can also be triggered deliberately/repeatedly by an attacker seeking to grief a victim's funds by encouraging calls through such a vulnerable integration, or exploited as a griefing/DoS-by-fund-loss vector against contracts that proxy calls to this precompile.

### Recommendation
Add the same `pcommon.ValidateNonPayable(value)` check to the `rewards()` dispatch path that all sibling read-only distribution methods already use, e.g.:
```go
case RewardsMethod:
    if err = pcommon.ValidateNonPayable(value); err != nil {
        return nil, 0, err
    }
    return p.rewards(ctx, method, args)
```
or equivalently update `rewards(ctx, method, args)` to accept `value` and call `p.validateInput(value, args, 1)` like the other query methods.

### Proof of Concept
1. Associate an EVM address with a Sei address and ensure it holds usei.
2. Call the distribution precompile (`0x0000000000000000000000000000000000001007`) function `rewards(address)` via `eth_sendRawTransaction`/`eth_call`-style transaction with `value: 1000000000000000000` (1 SEI in wei) attached.
3. Observe: the call succeeds and returns valid reward data (no revert), because `rewards()` never calls `ValidateNonPayable` or otherwise touches `value`.
4. Check the sender's usei balance before/after: it decreased by the sent value, and the distribution precompile's associated Sei account balance increased by that amount, with no compensating transfer back to the sender — the funds are stranded, contrasting with `withdrawDelegationRewards`, which uses `HandlePaymentUsei` to properly return unintended value transfers.

func (p PrecompileExecutor) validateInput(value *big.Int, args []interface{}, expectedArgsLength int) error {
	if err := pcommon.ValidateNonPayable(value); err != nil {
		return err
	}

	if err := pcommon.ValidateArgsLength(args, expectedArgsLength); err != nil {
		return err
	}

	return nil
}

func (d DynamicGasPrecompile) RunAndCalculateGas(evm *vm.EVM, caller common.Address, callingContract common.Address, input []byte, suppliedGas uint64, value *big.Int, hooks *tracing.Hooks, readOnly bool, isFromDelegateCall bool) (ret []byte, remainingGas uint64, err error) {
	operation := fmt.Sprintf("%s_unknown", d.name)
	defer func() {
		HandlePrecompileError(err, evm, operation)
		if err != nil {
			fmt.Printf("precompile %s encountered error: %v\n", d.name, err)
			err = vm.ErrExecutionReverted
		}
	}()
	ctxer := state.GetDBImpl(evm.StateDB)
	if ctxer == nil {
		return nil, 0, errors.New("cannot get context from EVM")
	}
	// Resolve the target method from the 4-byte selector only. The argument
	// payload is intentionally NOT decoded yet: ABI decoding of attacker-
	// controlled calldata can cost far more than len(input) (a single string can
	// be referenced by many array/tuple slots), so it must be paid for out of the
	// gas the caller supplied. The static-precompile path charges RequiredGas in
	// vm.RunPrecompiledContract before running; that step is skipped for
	// dynamic-gas precompiles, so we apply the equivalent charge here.
	methodID, err := ExtractMethodID(input)
	if err != nil {
		return nil, 0, err
	}
	method, err := d.MethodById(methodID)
	if err != nil {
		return nil, 0, err
	}
	operation = method.Name

	ctx := ctxer.Ctx()
	// Install the gas meter derived from the supplied EVM gas, then charge for
	// decoding the calldata BEFORE decoding it. A call that cannot afford the
	// decode is rejected here, before the parse/allocation work is performed.
	// chargeDecodeGas scopes the out-of-gas recovery to just these charges, so an
	// executor that later exhausts its gas keeps its normal (propagating)
	// out-of-gas semantics.
	gasLimit := d.executor.EVMKeeper().GetCosmosGasLimitFromEVMGas(ctx.WithGasMeter(sdk.NewInfiniteGasMeterWithMultiplier(ctx)), suppliedGas)
	ctx = ctx.WithGasMeter(sdk.NewGasMeterWithMultiplier(ctx, gasLimit))
	if err = d.chargeDecodeGas(ctx, method, input); err != nil {
		return nil, 0, err
	}

	args, err := method.Inputs.Unpack(input[4:])
	if err != nil {
		return nil, 0, err
	}
	em := ctx.EventManager()
	ctx = ctx.WithEventManager(sdk.NewEventManager())
	ctx = ctx.WithEVMPrecompileCalledFromDelegateCall(isFromDelegateCall)
	ret, remainingGas, err = d.executor.Execute(ctx, method, caller, callingContract, args, value, readOnly, evm, suppliedGas, hooks)
	if err != nil {
		return ret, remainingGas, err
	}
	events := ctx.EventManager().Events()
	if len(events) > 0 {
		em.EmitEvents(ctx.EventManager().Events())
	}
	return ret, remainingGas, err
}
