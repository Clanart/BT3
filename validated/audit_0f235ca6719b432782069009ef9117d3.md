## Analysis: SSRF Analog in Chia DataLayer Mirror/Subscription URL Handling

The Label Studio bug class (unvalidated, attacker-controlled URLs fetched server-side with no SSRF protections) has a direct analog in Chia's DataLayer mirror/subscription mechanism.

### Title
Unvalidated On-Chain Mirror URLs Enable SSRF in DataLayer Subscription Fetching - (File: `chia/data_layer/download_data.py`)

### Summary
Any DataLayer/wallet user can publish an arbitrary URL on-chain via the `add_mirror` RPC. Any other node that subscribes to that store (a normal, expected DataLayer client action) will automatically pull that URL from the wallet and issue an outbound HTTP GET to it on a periodic timer, with zero validation of the destination host/IP.

### Finding Description
`DataLayerRpcApi.add_mirror`/`DataLayer.add_mirror` lets an unprivileged wallet owner publish a coin on-chain containing a list of URLs, with no scheme/host/IP restriction: [1](#0-0) 

These on-chain mirror coins are picked up by any wallet tracking the singleton (`coin_added` in `DataLayerWallet`) and stored verbatim: [2](#0-1) 

A subscribing DataLayer service periodically syncs these mirror URLs into its own local subscriptions table via `update_subscriptions_from_wallet`, again with no validation: [3](#0-2) [4](#0-3) 

The background sync loop (`periodically_manage_data` → `update_subscription` → `fetch_and_validate`) then uses these stored server URLs to make outbound HTTP requests via `http_download`, which issues `session.get(server_info.url + "/" + filename, ...)` with no destination-address checks whatsoever — not even the (bypassable) DNS-based blocklist that Label Studio had: [5](#0-4) [6](#0-5) 

The project's own internal documentation explicitly notes that mirror URLs are "external trust inputs" whose *content* must be verified — but this only covers data integrity, not the SSRF risk of the *request itself*: [7](#0-6) 

The equivalent client-facing `subscribe` RPC also accepts arbitrary URLs directly from the caller without validation: [8](#0-7) [9](#0-8) 

### Impact Explanation
Unlike Label Studio (which at least attempted DNS-based SSRF filtering that could be bypassed via redirects/DNS rebinding), Chia's DataLayer performs **no filtering at all**. Any actor who creates/controls a DataLayer store and publishes a mirror URL (e.g., `http://169.254.169.254/latest/meta-data/`, `http://127.0.0.1:<internal-rpc-port>/`, or an internal service address) can cause every node that subscribes to that store to automatically issue periodic outbound HTTP requests to that address. This can be used to probe/access internal network services or cloud instance metadata endpoints from the perspective of any operator running a DataLayer node that mirrors third-party stores — a normal, expected DataLayer client workflow.

### Likelihood Explanation
High reachability: publishing a mirror coin only requires normal wallet/DL RPC access (`add_mirror`) and a small fee — no special privilege. Subscribing to third-party stores is a core, encouraged DataLayer usage pattern (mirroring), and the sync loop runs automatically and repeatedly (`periodically_manage_data`), so exploitation requires no interaction beyond a victim subscribing to the attacker's store.

### Recommendation
Before issuing any outbound request in `http_download` (and in `add_mirror`/`subscribe` validation paths), resolve and validate the destination against private/link-local/metadata IP ranges (RFC1918, `169.254.0.0/16`, loopback, etc.), re-validate after redirects, and consider disabling automatic redirect-following for mirror fetches, mirroring the fix eventually needed for CVE-2023-47116 (validate the resolved IP at connection time, not just the parsed hostname).

### Proof of Concept
1. Attacker creates a DataLayer store and runs `add_mirror` with `urls=["http://169.254.169.254/latest/meta-data/"]` (or an internal RFC1918 address), paying the on-chain fee.
2. A victim operator's DataLayer node, following normal usage, calls `subscribe` on the attacker's `store_id`.
3. On the victim's next `periodically_manage_data` cycle, `update_subscriptions_from_wallet` pulls the malicious mirror URL into the local subscriptions table, and `fetch_and_validate`/`http_download` issues an unauthenticated GET request to that internal/metadata address from the victim's node — with no scheme, host, or IP-range checks anywhere in the path.

```python
    async def update_subscriptions_from_wallet(self, store_id: bytes32, new_urls: list[str]) -> None:
        async with self.db_wrapper.writer() as writer:
            cursor = await writer.execute(
                "SELECT * FROM subscriptions WHERE from_wallet == 1 AND tree_id == :tree_id",
                {
                    "tree_id": store_id,
                },
            )
            old_urls = [row["url"] async for row in cursor]
            cursor = await writer.execute(
                "SELECT * FROM subscriptions WHERE from_wallet == 0 AND tree_id == :tree_id",
                {
                    "tree_id": store_id,
                },
            )
            from_subscriptions_urls = {row["url"] async for row in cursor}
            additions = {url for url in new_urls if url not in old_urls}
            removals = [url for url in old_urls if url not in new_urls]
            for url in removals:
                await writer.execute(
                    "DELETE FROM subscriptions WHERE url == :url AND tree_id == :tree_id",
                    {
                        "url": url,
                        "tree_id": store_id,
                    },
                )
            for url in additions:
                if url not in from_subscriptions_urls:
                    await writer.execute(
                        "INSERT INTO subscriptions(tree_id, url, ignore_till, num_consecutive_failures, from_wallet) "
                        "VALUES (:tree_id, :url, 0, 0, 1)",
                        {
                            "tree_id": store_id,
                            "url": url,
                        },
                    )
```

```python
async def http_download(
    target_filename_path: Path,
    filename: str,
    proxy_url: str | None,
    server_info: ServerInfo,
    timeout: aiohttp.ClientTimeout,
    log: logging.Logger,
    max_delta_file_size: int,
) -> None:
    """
    Download a file from a server using aiohttp.
    Raises exceptions on errors
    """
    async with aiohttp.ClientSession() as session:
        headers = {"accept-encoding": "gzip"}
        async with session.get(
            server_info.url + "/" + filename,
            headers=headers,
            timeout=timeout,
            proxy=proxy_url,
        ) as resp:
            resp.raise_for_status()
            size = int(resp.headers.get("content-length", 0))
```

```python
    async def subscribe(self, request: dict[str, Any]) -> EndpointResult:
        """
        subscribe to singleton
        """
        store_id = request.get("id")
        if store_id is None:
            raise Exception("missing store id in request")

        store_id_bytes = bytes32.from_hexstr(store_id)
        urls = request.get("urls", [])
        await self.service.subscribe(store_id=store_id_bytes, urls=urls)
        return {}
```
