### Title
`SignableTransaction` signs transactions paying an unbounded fee with no maximum-fee check — ([File: networks/bitcoin/src/wallet/send.rs](https://github.com/bsaldua/serai--015/blob/main/networks/bitcoin/src/wallet/send.rs))

### Summary
The yAxis finding describes a swap executed without a minimum return amount, letting third parties (MEV searchers/miners) extract the unbounded difference. The Serai analog lives in `SignableTransaction::new`: the transaction's actual fee is defined as `sum(inputs) - sum(outputs)`, yet the code only computes a *minimum* `needed_fee` and never bounds the fee from above. Whenever a change output is omitted — or falls below `DUST` — every satoshi of the remainder is handed to miners, just as an unbounded slippage trade hands the difference to whoever mines it.

### Finding Description
`SignableTransaction::new` computes `needed_fee = fee_per_vbyte * vbytes` and checks only that the inputs can cover it (`input_sat < payment_sat + needed_fee` → `NotEnoughFunds`). [1](#0-0)  The change logic only *adds* a change output if `input_sat - payment_sat - fee_with_change >= DUST`; otherwise the remainder silently becomes fee. [2](#0-1)  And if `change` is `None` entirely, the documented behavior is that "all leftover funds will become part of the paid fee" — with no comparison against `needed_fee`, no cap, and no error. [3](#0-2)  `fee()` confirms the signed transaction pays `prevouts - outputs`, which can exceed `needed_fee` by an arbitrary amount. [4](#0-3) 

Crucially, this transaction is what the FROST threshold group signs: `TransactionSignMachine::sign` commits to `Prevouts::All` and the exact output set via the Taproot sighash, so the oversized fee is consensus-locked into a valid, irrevocable signature produced by the threshold. [5](#0-4) 

### Impact Explanation
Funds controlled by a threshold key can be irreversibly donated to miners. Any caller or upstream component that builds a transaction without a change output — or whose change computation leaves a sub-dust-but-large gap relative to intended fee — produces a signature the network will happily mine, transferring `sum(inputs) - sum(outputs)` to the miner. This is the Bitcoin analogue of "swap with no minimum return": the protocol signs away an unbounded amount of value to whoever includes the transaction. Note also that `ReceivedOutput`s fed into `SignableTransaction::new` can originate from `Scanner::scan_block`/`scan_transaction`, i.e., transactions third parties broadcast to the group's addresses; an input set assembled from attacker-contributed outputs combined with a missing change output inflates the burned fee.

### Likelihood Explanation
Medium. Reaching it requires constructing a transaction whose inputs substantially exceed payments without a reclaiming change output — a scenario the API explicitly supports (`change: Option<ScriptBuf>`, consolidation-style and no-change calls are exercised in tests). Unlike a Curve swap, no searcher's active manipulation is even required: the loss is self-inflicted at signing time and guaranteed once the transaction broadcasts. The trigger conditions (omitted change, or a change remainder mis-estimated relative to the dust threshold) are ordinary integration outcomes rather than exotic states.

### Recommendation
Mirror the "always specify a minimum return" mitigation: enforce a maximum fee. After the output set is finalized, assert `fee() <= needed_fee` (or within a small tolerance, e.g. `needed_fee + DUST` to cover the dropped-change case) and return a new `TransactionError::ExcessFee` otherwise. Additionally, when `change` is `None` and the leftover exceeds `needed_fee` by more than dust, refuse to construct the transaction rather than silently burning the remainder.

### Proof of Concept
In `SignableTransaction::new`, take `inputs` with `input_sat = 1_000_000`, `payments = [(addr, 1000)]`, `change = None`, `fee_per_vbyte` adequate. `needed_fee` is ~few hundred sats; the check at line 215 passes; no change output is added; `fee()` returns `1_000_000 - 1_000 = 999_000` sats — roughly 1000× the intended fee — and `TransactionSignMachine::sign` produces threshold shares committing to exactly that fee via `Prevouts::All` sighash. The same leak occurs for `change = Some(..)` when the leftover lands below `DUST` after `fee_with_change`, just bounded by the dust threshold. No code path ever compares the realized fee to an upper bound.
