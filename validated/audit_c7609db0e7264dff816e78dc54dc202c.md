### Title
Any `type_url` is embedded into TextFormat output without escaping, allowing structure/field injection - ([File: src/google/protobuf/text_format.cc])

### Summary
The hyper advisory's failed invariant is: a value that is placed into a structured, delimiter-based serialization (an HTTP header) was written to the output stream without filtering the control characters (`\r`/`\n`) that the format uses as record separators, letting attacker data escape its slot and inject/split additional "records" (here, HTTP headers/requests). The Protobuf analog is `TextFormat::Printer::PrintAny` (and its Java/Python equivalents), which writes the `Any.type_url` string field directly into the TextFormat "record" as `[type_url] { ... }` using the raw, non-escaping `BaseTextGenerator::PrintString`, instead of the field-value printer that CEscapes strings elsewhere in TextFormat.

### Finding Description
Everywhere else in TextFormat, string field values are passed through an escaping routine before being written: e.g. `TextFormat::FastFieldValuePrinter::PrintString` calls `ContainsCharactersToCEscape`/`absl::CEscape` to turn `\n`, `\r`, `"`, `\`, and other control bytes into backslash escapes [1](#0-0) , and the Java/Python printers apply the same discipline (`TextFormatEscaper.escapeText`, `text_encoding.CEscape`) [2](#0-1) [3](#0-2) .

However, when TextFormat expands a `google.protobuf.Any` message (a feature enabled via `SetExpandAny(true)`, which is on by default for `DebugString()`/`PrintToString()`), the `type_url` field — itself an attacker-controlled `string` field inside the parsed `Any` message — is written unescaped:
```
generator->PrintLiteral("[");
generator->PrintString(type_url);
generator->PrintLiteral("]");
``` [4](#0-3) 
Here `generator->PrintString` is `BaseTextGenerator::PrintString`, the raw output-stream writer, not the field-value CEscape path. `type_url` is only checked for containing a `/` via `ParseAnyTypeUrl`/`GetAnyFieldDescriptors` [5](#0-4) ; there is no character-set validation (despite `any.proto`'s comment stating the type URL "must consist only of alphanumeric characters, percent-encoded escapes, and characters in the following set: `/-.~_!$&()*+,;=`" — this is documentation only, not enforced by the parser) [6](#0-5) .

The same unescaped pattern exists in the Java printer, `generator.print(typeUrl);` inside `printAny` [7](#0-6) , and in the pure-Python printer, `self.out.write('%s[%s]%s ' % (self.indent * ' ', message.type_url, colon))` [8](#0-7) . In all three implementations, a `type_url` value containing `"`, newlines, `{`/`}` or a full fabricated field/value sequence (e.g. `type.googleapis.com/x\ninjected_field: "evil"\nfoo {`) is copied verbatim into the emitted TextFormat text, exactly analogous to hyper writing an unescaped header value containing `\r\n` into the wire format.

Since `Any` messages are ordinary embedded messages that a bounded, otherwise-valid Protobuf payload can carry (an attacker fully controls the bytes of `type_url` and the enclosing `value` field, both are just protobuf `string`/`bytes` fields), this is reachable through a supported public parse API (`ParseFromString`/`MergeFrom` producing a message that is later rendered with `DebugString()`/`TextFormat::PrintToString()` with `expand_any_` enabled, which is the default for debug printing).

### Impact Explanation
If application code parses trusted-schema Protobuf, calls `DebugString()`/`ShortDebugString()`/`TextFormat::PrintToString()` for logging, and that TextFormat text is later machine-parsed (e.g., re-ingested by `TextFormat::Parse`, fed to a downstream log-parsing/alerting pipeline that treats TextFormat as structured records, or displayed in a context expecting well-formed key/value lines), an attacker who controls the contents of an `Any` field can inject spurious "fields," terminate the bracketed Any block early, or otherwise corrupt/split the record boundaries of the emitted text — the same "message splitting" effect the hyper advisory describes, but at the TextFormat-record level rather than the HTTP-header level. This maps to integrity impact (I:L) similar to the CVSS vector in the report; it does not by itself grant code execution or memory corruption.

### Likelihood Explanation
Likelihood is moderate-to-low in practice: exploitation requires (a) an application that expands `Any` in TextFormat output (default behavior for `DebugString`), and (b) a downstream consumer that treats that TextFormat text as machine-parsed/structured rather than purely human-readable debug logs. Because `expand_any_` printing and re-parsing of debug strings by another structured parser is an unusual but plausible application pattern (e.g., logging pipelines that regex-parse debug dumps, or round-tripping via `TextFormat::Merge`), this is a real but narrower-audience analog than the original hyper header-splitting bug, which affected any HTTP consumer.

### Recommendation
Escape `type_url` the same way ordinary string field values are escaped before writing it inside the `[...]` bracket in `TextFormat::Printer::PrintAny` (C++), `TextFormat.Printer.printAny` (Java), and `_Printer._TryPrintAsAnyMessage` (Python) — i.e., route it through `FastFieldValuePrinter::PrintString`/`TextFormatEscaper.escapeText`/`text_encoding.CEscape` instead of the raw `PrintString`/`print`/`out.write`. Additionally, consider validating `type_url` against the character set documented in `any.proto` before accepting it as valid for expansion, refusing to expand (falling back to the raw `type_url`/`value` bytes form) if it contains control characters.

### Proof of Concept
Conceptually (cannot execute in this environment):
1. Construct a raw Protobuf message containing a `google.protobuf.Any` field whose serialized bytes set:
   - field 1 (`type_url`, string) = `"type.googleapis.com/foo.Bar\ninjected_field: \"pwned\"\ndummy {"`
   - field 2 (`value`, bytes) = a validly serialized `foo.Bar` message
2. Parse this bounded, well-formed binary payload with the standard public API (`Message::ParseFromString`) using a trusted schema that includes `foo.Bar` in the type registry.
3. Call `TextFormat::PrintToString()` (or `DebugString()`) on the parsed message.
4. Observe that the output contains the raw, unescaped newline and injected text from `type_url`, e.g.:
   ```
   any_value {
     [type.googleapis.com/foo.Bar
   injected_field: "pwned"
   dummy {] {
     ...
   }
   }
   ```
   breaking the expected single-line bracketed-field structure of the TextFormat record, the same class of "record splitting" the hyper advisory addresses for HTTP headers. Full end-to-end verification (running the actual code) was not performed in this session; the analysis is based on direct reading of the `PrintAny` implementations in C++, Java, and Python shown above.

bool ContainsCharactersToCEscape(absl::string_view val) {
  bool needs_escape = false;
  for (unsigned char c : val) {
    needs_escape |=
        ((c < 32) | (c > 126) | (c == '"') | (c == '\'') | (c == '\\'));
  }
  return needs_escape;
}

}  // namespace

void TextFormat::FastFieldValuePrinter::PrintString(
    const std::string& val, BaseTextGenerator* generator) const {
  generator->PrintLiteral("\"");
  if (!val.empty()) {
    if (ABSL_PREDICT_FALSE(ContainsCharactersToCEscape(val))) {
      generator->PrintString(absl::CEscape(val));
    } else {
      generator->PrintString(val);
    }
  }
  generator->PrintLiteral("\"");
}

def _MakeStrEscapes():

  for i in range(0, 128):
    if not _AsciiIsPrint(i):
      ret[i] = r'\%03o' % i
  ret[ord('\t')] = r'\t'  # optional escape

  ret[ord('\r')] = r'\r'  # optional escape
  ret[ord('"')] = r'\"'  # necessary escape
  ret[ord("'")] = r'\''  # optional escape
  ret[ord('\\')] = r'\\'  # necessary escape

bool GetAnyFieldDescriptors(const Message& message,
                            const FieldDescriptor * PROTOBUF_NULLABLE *
                                PROTOBUF_NONNULL type_url_field,
                            const FieldDescriptor * PROTOBUF_NULLABLE *
                                PROTOBUF_NONNULL value_field) {
  const Descriptor* descriptor = message.GetDescriptor();
  if (descriptor->full_name() != kAnyFullTypeName) {
    return false;
  }
  *type_url_field = descriptor->FindFieldByNumber(1);
  *value_field = descriptor->FindFieldByNumber(2);
  return (*type_url_field != nullptr &&
          (*type_url_field)->type() == FieldDescriptor::TYPE_STRING &&
          *value_field != nullptr &&
          (*value_field)->type() == FieldDescriptor::TYPE_BYTES);
}
