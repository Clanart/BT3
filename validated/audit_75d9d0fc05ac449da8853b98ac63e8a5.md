#### Binding claimed broken
`output_txout.value` used in the broadcast `payout_tx` == the withdrawal amount attested by the withdrawer's Schnorr `user_sig` given off-chain to the operator.

#### Why the binding actually holds
`parse_withdrawal_sig_params` in `core/src/rpc/parser/operator.rs` enforces that `input_signature.sighash_type` must be `TapSighashType::SinglePlusAnyoneCanPay` (rejecting anything else, and normalizing bare 64-byte sigs to that type), before the request ever reaches `Operator::withdraw`. [1](#0-0) 

`create_payout_txhandler` builds the payout tx with the input at index 0 spent via `SpendPath::KeySpend`, and `set_p2tr_key_spend_witness(&user_sig, 0)` places the user's signature on that input. [2](#0-1) 

`Operator::withdraw` computes the sighash it actually verifies against as `payout_txhandler.calculate_sighash_txin(0, in_signature.sighash_type)` and checks it with `SECP.verify_schnorr` against the user's x-only pubkey, before ever broadcasting. [3](#0-2) 

`calculate_pubkey_spend_sighash` (used by the sighash calculator for key-spend inputs) computes the BIP341 taproot sighash via `taproot_key_spend_signature_hash`, feeding in `sighash_type`. [4](#0-3) 

For `SIGHASH_SINGLE|ANYONECANPAY` (BIP341), the sighash commits to the output at the same index as the input being spent (index 0 here, i.e. exactly `output_txout`), including both its `value` and `script_pubkey`; `ANYONECANPAY` only relaxes the *input* commitment (so operator can add funding inputs), not the output commitment. This is core BIP341/BIP143 semantics, not something this repo can bypass. Consequently, the off-chain `user_sig` cryptographically binds the exact `(value, script_pubkey)` of `output_txout` — an attacker/operator cannot change `output_txout.value` and reuse the same signature; `SECP.verify_schnorr` would fail, and the tx also would fail to validate on the Bitcoin network at broadcast/confirmation time (the same BIP341 rule applies to full nodes and thus miners), so it could never be included in a block and would never produce a valid SPV proof for `bridge_circuit` to consume.

The other RPC path (`aggregator.rs::optimistic_payout` and `Verifier::sign_optimistic_payout`) performs the equivalent check via `calculate_pubkey_spend_sighash(0, input_signature.sighash_type)` + `SECP.verify_schnorr`. [5](#0-4) [6](#0-5) 

So the equality the question worries about is enforced *before* `bridge_circuit` even runs — by Schnorr signature verification over a BIP341 sighash that is pinned to `SinglePlusAnyoneCanPay`, which necessarily commits to the exact output amount and script. `bridge_circuit` doesn't need to re-derive the amount from Citrea state because Bitcoin consensus itself (via the taproot key-spend signature) already guarantees that the confirmed `payout_tx`'s output 0 is exactly what the withdrawer signed off on. The circuit's role is only to prove that a *confirmed* `payout_tx` correctly spends the specific withdrawal outpoint that Citrea recorded (`(txid, vout)` match via `verify_storage_proofs`), which is a different and already-satisfied binding.

pub fn create_payout_txhandler(
    input_utxo: UTXO,
    output_txout: TxOut,
    operator_xonly_pk: XOnlyPublicKey,
    user_sig: taproot::Signature,
    _network: bitcoin::Network,
) -> Result<TxHandler<Signed>, BridgeError> {
    let txin = SpendableTxIn::new_partial(input_utxo.outpoint, input_utxo.txout);

    let output_txout = UnspentTxOut::from_partial(output_txout.clone());

    let op_return_txout = op_return_txout(PushBytesBuf::from(operator_xonly_pk.serialize()));

    let mut txhandler = TxHandlerBuilder::new(TransactionType::Payout)
        .with_version(NON_STANDARD_V3)
        .add_input(
            NormalSignatureKind::NotStored,
            txin,
            SpendPath::KeySpend,
            DEFAULT_SEQUENCE,
        )
        .add_output(output_txout)
        .add_output(UnspentTxOut::from_partial(anchor_output(
            NON_EPHEMERAL_ANCHOR_AMOUNT,
        )))
        .add_output(UnspentTxOut::from_partial(op_return_txout))
        .finalize();
    txhandler.set_p2tr_key_spend_witness(&user_sig, 0)?;
    txhandler.promote()
}

    pub fn calculate_pubkey_spend_sighash(
        &self,
        txin_index: usize,
        sighash_type: TapSighashType,
    ) -> Result<TapSighash, BridgeError> {
        let prevouts_vec: Vec<&TxOut> = self
            .txins
            .iter()
            .map(|s| s.get_spendable().get_prevout())
            .collect();
        let mut sighash_cache: SighashCache<&bitcoin::Transaction> =
            SighashCache::new(&self.cached_tx);
        let prevouts = match sighash_type {
            TapSighashType::SinglePlusAnyoneCanPay
            | TapSighashType::AllPlusAnyoneCanPay
            | TapSighashType::NonePlusAnyoneCanPay => {
                bitcoin::sighash::Prevouts::One(txin_index, prevouts_vec[txin_index])
            }
            _ => bitcoin::sighash::Prevouts::All(&prevouts_vec),
        };

        let sig_hash = sighash_cache
            .taproot_key_spend_signature_hash(txin_index, &prevouts, sighash_type)
            .wrap_err("Failed to calculate taproot sighash for key spend")?;
