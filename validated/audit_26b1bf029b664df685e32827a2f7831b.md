## Title
Governance-controlled `kip71.gastarget` accepts zero, causing a division-by-zero panic in `NextMagmaBlockBaseFee` - (File: `params/kip71_config.go`)

## Summary
The KIP-71 dynamic base-fee formula divides by the governance parameter `GasTarget` without any zero-check, while the governance-vote pipeline that sets this parameter uses a no-op format checker that accepts `0` as a valid value. A governing node's vote to set `kip71.gastarget = 0`, once ratified at an epoch boundary, causes every node computing the next block's base fee to panic on integer division by zero — a consensus-wide denial of service, directly analogous to CVE-2016-8667's "large interval reload value causes divide-by-zero" pattern (here the analog is a governance-supplied divisor value of zero rather than a raw interval value).

## Finding Description
`NextMagmaBlockBaseFee` computes the base-fee delta using `gasTarget` as a divisor in two branches: [1](#0-0) [2](#0-1) 

Both branches perform `x.Div(x, new(big.Int).SetUint64(gasTarget))` where `gasTarget := kc.GasTarget`, taken straight from the governance parameter set with no guard against zero: [3](#0-2) 

Contrast this with the sibling parameter `BaseFeeDenominator`, for which the same function explicitly special-cases a zero value to avoid a panic: [4](#0-3) 

No equivalent protection exists for `GasTarget`. The root cause is in the governance parameter registry: `Kip71GasTarget`'s `FormatChecker` is `noopFormatChecker`, which always returns `true`, unlike `Kip71BaseFeeDenominator` which explicitly rejects `0`: [5](#0-4) 

`noopFormatChecker` is defined to unconditionally accept any value: [6](#0-5) 

The vote is validated purely through the `Canonicalizer`/`FormatChecker` pair in `NewVoteData` — since `Kip71GasTarget` uses `uint64Canonicalizer` and `noopFormatChecker`, a vote value of `0` passes cleanly: [7](#0-6) 

`checkConsistency`, which is the only additional consensus-level guard applied during `VerifyVote`, has no special case for `Kip71GasTarget` beyond accepting any value that already passed the format check: [8](#0-7) 

This confirms `GasTarget=0` can be validly voted, ratified, and become the active parameter set at the next epoch, at which point `NextMagmaBlockBaseFee` — invoked during header verification and base-fee computation for every block after Magma — divides by zero.

## Impact Explanation
Once `kip71.gastarget` is ratified as `0`, every full node (honest or not) computing the next block's base fee via `KIP71Config.NextMagmaBlockBaseFee` will panic with a Go runtime division-by-zero error whenever `parentGasUsed != gasTarget` (which is guaranteed to be true, i.e. `parentGasUsed > 0 = gasTarget`, unless the parent block used exactly zero gas). This crashes the node process network-wide, since block header preparation/verification and RPC-facing gas price suggestion (`SuggestPrice`/`SuggestTipCap` via `NextMagmaBlockBaseFee`-derived values) are on the hot path for all nodes, not an isolated validator. This is a chain-halting denial-of-service impacting the entire network's availability, going beyond a single-node crash.

## Likelihood Explanation
Setting the value requires a governance vote to be cast and ratified, which per the module's `single`-mode governance normally requires being the designated governing node (or, in `none` mode, any GC member). This is a privileged rather than fully anonymous-attacker path, but it is squarely within the "governance parameters" analog category permitted by scope, and it represents a real gap: the validation logic clearly intended to guard against zero divisors (as shown by the `BaseFeeDenominator` special case and its dedicated `FormatChecker`) but missed doing so for `GasTarget`, which is used identically as a divisor in the same formula.

## Recommendation
Add a zero-value guard to `Kip71GasTarget`'s `FormatChecker` (mirroring `Kip71BaseFeeDenominator`'s `v != 0` check) in `kaiax/gov/param.go`, and additionally add a defensive fallback in `NextMagmaBlockBaseFee` in `params/kip71_config.go` (as already done for `BaseFeeDenominator`) so that a zero `GasTarget` cannot reach the division regardless of how it entered the parameter set (e.g., via genesis config or legacy chain data).

## Proof of Concept
1. As the governing node (or any GC member under `none` mode), call `governance_vote("kip71.gastarget", 0)`. This passes `NewVoteData` because `Kip71GasTarget`'s `FormatChecker` is `noopFormatChecker`. [9](#0-8) 
2. The vote is inscribed in `header.Vote` when this node becomes proposer, and other nodes accept it via `VerifyVote`/`checkConsistency`, which does not reject `Kip71GasTarget` values. [10](#0-9) 
3. At the next epoch boundary, the vote is ratified into `header.Governance`, making `GasTarget = 0` the active parameter from `(k+1)*epoch` onward.
4. On the next block after activation with `parentGasUsed > 0`, `NextMagmaBlockBaseFee` executes `x.Div(x, new(big.Int).SetUint64(gasTarget))` with `gasTarget = 0`, causing a division-by-zero panic on every node computing/verifying that header. [1](#0-0)

// NewVoteData returns a valid, canonical vote data.
// If return is not nil, the name and the value is valid.
// The format of the value is checked, but consistency and deprecation are NOT checked.
// Deprecation (gov.DeprecatedAt) is the caller's responsibility — see Vote() and VerifyVote().
func NewVoteData(voter common.Address, name string, value any) VoteData {
	param, ok := gov.Params[gov.ParamName(name)]
	if !ok {
		param, ok = gov.ValidatorParams[gov.ParamName(name)]
		if !ok {
			logger.Error("Invalid vote name", "name", name)
			return nil
		}
	}

	cv, err := param.Canonicalizer(value)
	if err != nil {
		logger.Error("Canonicalize error", "name", name, "value", value, "err", err)
		return nil
	}

	if !param.FormatChecker(cv) {
		logger.Error("Format check error", "name", name, "value", value)
		return nil
	}

	return &voteData{
		voter: voter,
		name:  gov.ParamName(name),
		value: cv,
	}
}

func (h *headerGovModule) VerifyVote(header *types.Header) error {
	if len(header.Vote) == 0 {
		return nil
	}

	var (
		vb       headergov.VoteBytes = header.Vote
		blockNum                     = header.Number.Uint64()
	)

	vote, err := vb.ToVoteData()
	if err != nil {
		logger.Error("ToVoteData error", "num", blockNum, "vote", vb, "err", err)
		return err
	}

	if gov.DeprecatedAt(vote.Name(), h.ChainConfig.Rules(header.Number)) {
		logger.Error("Vote is deprecated", "num", blockNum, "name", vote.Name())
		return ErrDeprecatedVote
	}

	council, err := h.ValSet.GetCouncil(blockNum)
	if err != nil {
		return err
	}

	// check if the voter is in council
	if !slices.Contains(council, vote.Voter()) {
		return ErrInvalidKeyValue
	}

	// check if Voter is the block proposer.
	author, err := h.Chain.Sealer().Author(header)
	if err != nil {
		return err
	}
	if author != vote.Voter() {
		return ErrInvalidVoter
	}

	// In single mode, only the governing node can write header.Vote after Permissionless.
	params := h.GetParamSet(blockNum)
	if h.ChainConfig.IsPermissionlessForkEnabled(new(big.Int).SetUint64(blockNum)) &&
		params.GovernanceMode == "single" &&
		vote.Voter() != params.GoverningNode {
		return ErrVotePermissionDenied
	}

	return h.checkConsistency(blockNum, vote)
