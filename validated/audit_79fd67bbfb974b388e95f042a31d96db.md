### Title
Generic Git credential helper stores and replays credentials over unencrypted `http://` remotes without warning - (File: `app/src/lib/trampoline/trampoline-credential-helper.ts`)

### Summary
GitHub Desktop's Enterprise sign-in flow explicitly rejects non-HTTPS URLs via `validateURL` in `app/src/ui/lib/enterprise-validate-url.ts`, which throws `InvalidProtocolErrorName` for anything other than `https:`. However, the "generic" Git credential path — used whenever Git needs credentials for a non-GitHub remote (or a GitHub-like host it fails to positively identify) — has no such restriction. A user can add/clone a remote using a plain `http://` URL, and when Git prompts for a username/password, Desktop will collect it via the `GenericGitAuthentication` dialog, persist it in the OS credential store, and automatically replay it for that endpoint/host on every future non-interactive Git operation, all without ever validating or warning about the unencrypted scheme.

### Finding Description
The trampoline credential helper's `getEndpointKind` function in [1](#0-0)  classifies a credential request as `'generic'` whenever it cannot identify the host as GitHub.com/GHE by cached account, host-header heuristics, or protocol. Once classified `'generic'`, `getCredential` calls `getGenericCredential`, which looks up a saved credential via `findGenericTrampolineAccount` in [2](#0-1)  keyed only by `urlWithoutCredentials(remoteUrl)` — i.e., protocol + host + path, with no scheme enforcement, as shown in [3](#0-2) . If no saved credential exists, it calls `promptForCredential`, which opens the `GenericGitAuthentication` dialog defined in [4](#0-3) . This dialog only displays the URL as a `<Ref>` for context — it never inspects `remoteUrl`'s scheme, and it never warns the user that the endpoint is unencrypted. On submit, credentials are persisted via `setGenericCredential` → `TokenStore.setItem`, and subsequently `storeCredential`/`getGenericCredential` in [5](#0-4)  will transparently replay the stored password for that endpoint on every future Git network operation (`fetch`, `pull`, `push`, `clone`), including background/non-interactive ones, again with no protocol check anywhere in the chain.

By contrast, the sign-in path used for GitHub/GitHub Enterprise explicitly guards against this exact class of issue: [6](#0-5)  rejects non-`https:` protocols outright. No equivalent guard exists on the generic credential path, so the "broken invariant" from the Peggo report — accepting and silently using an unencrypted, non-local endpoint for sensitive traffic without rejection or warning — has a direct analog here: Desktop happily stores and replays plaintext-HTTP-bound credentials.

### Impact Explanation
An attacker positioned on the same local network as the Desktop user (e.g. shared Wi-Fi, corporate LAN, compromised router) who can intercept traffic to an `http://` git remote can perform a classic man-in-the-middle attack: capture the Basic-Auth credentials Git sends over plaintext HTTP the first time, or actively respond to the HTTP Git smart-protocol handshake to harvest the username/password submitted via the `GenericGitAuthentication` dialog. Once captured, these are real, reusable account credentials (often a Personal Access Token, as the dialog itself suggests using) for whatever generic Git hosting service (GitLab, Gitea, Bitbucket, self-hosted Gitea/Gogs, etc.) the token is scoped to. This matches the report's required impact category: credential/token exfiltration via a network position the attacker naturally has (no local/physical access or malware needed), triggered simply by the user adding an `http://` remote.

### Likelihood Explanation
Likelihood is moderate: it requires (1) a user configuring or cloning a repository whose remote URL uses `http://` rather than `https://` — plausible for internal, legacy, or self-hosted Git servers that don't have TLS configured — and (2) an attacker sharing the local network path. Unlike the sign-in flow, nothing in the UI or credential flow nudges the user away from `http://`; the dialog text focuses purely on entering a PAT, reinforcing the impression that the exchange is safe.

### Recommendation
Mirror the existing Enterprise sign-in protection: before prompting for or storing generic Git credentials in `getGenericCredential`/`promptForCredential` (`app/src/lib/trampoline/trampoline-credential-helper.ts`), inspect the credential URL's protocol. If it is `http:` and the host is not local (reusing the same loopback-detection logic already implemented for BYOK providers in `isLocalBaseUrl`, `app/src/lib/copilot/byok.ts`), either refuse to store/send the credential automatically or surface an explicit warning in the `GenericGitAuthentication` dialog (`app/src/ui/generic-git-auth/generic-git-auth.tsx`) that credentials will be transmitted unencrypted and are vulnerable to network interception.

### Proof of Concept
1. On a shared/untrusted network, add a remote to a local repository pointing at an attacker-controlled or MITM-able host using `http://git.internal.example/repo.git`.
2. Run `git fetch`/`git pull` through Desktop; Git invokes the `desktop` credential helper, which cannot identify the host as GitHub and classifies it `'generic'` (`getEndpointKind`).
3. Desktop shows the `GenericGitAuthentication` dialog (no scheme warning) and the user enters a username/PAT.
4. Desktop stores the credential via `setGenericCredential` keyed by the plain-HTTP endpoint, and on every subsequent fetch/push automatically resends it in the clear over the same `http://` connection — an on-path attacker captures it trivially, exactly as described in the Peggo report's exploit scenario.

const getEndpointKind = async (cred: Credential, store: Store) => {
  const credentialUrl = getCredentialUrl(cred)
  const endpoint = `${credentialUrl}`

  if (isGist(endpoint)) {
    return 'generic'
  }

  if (isDotCom(endpoint)) {
    return 'github.com'
  }

  if (isGHE(endpoint)) {
    return 'ghe.com'
  }

  // When Git attempts to authenticate with a host it captures any
  // WWW-Authenticate headers and forwards them to the credential helper. We
  // use them as a happy-path to determine if the host is a GitHub host without
  // having to resort to making a request ourselves.
  for (const [k, v] of cred.entries()) {
    if (k.startsWith('wwwauth[')) {
      if (v.includes('realm="GitHub"')) {
        return 'enterprise'
      } else if (/realm="(GitLab|Gitea|Atlassian Bitbucket)"/.test(v)) {
        return 'generic'
      }
    }
  }

  const existingAccount = await findGitHubTrampolineAccount(store, endpoint)
  if (existingAccount) {
    return isDotCom(existingAccount.endpoint) ? 'github.com' : 'enterprise'
  }

  // All GitHub hosts use HTTPS, so if the protocol is not HTTPS we can
  // assume that this is not a GitHub host.
  if (credentialUrl.protocol !== 'https:') {
    return 'generic'
  }

  return (await isGitHubHost(endpoint)) ? 'enterprise' : 'generic'
}

export async function findGenericTrampolineAccount(
  trampolineToken: string,
  remoteUrl: string
) {
  const parsedUrl = new URL(remoteUrl)
  const endpoint = urlWithoutCredentials(remoteUrl)

  const login =
    parsedUrl.username === ''
      ? getGenericUsername(endpoint)
      : parsedUrl.username

  if (!login) {
    return undefined
  }

  const token = await memoizedGetGenericPassword(
    trampolineToken,
    endpoint,
    login
  )

  if (!token) {
    // We have a username but no password, that warrants a warning
    log.warn(`credential: generic password for ${remoteUrl} missing`)
    return undefined
  }

  return { login, endpoint, token }
}
