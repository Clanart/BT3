### Title
`ThresholdKeys::read` accepts attacker-controlled verification shares/group key without verifying they match the secret share — deserialized keys become a fully attacker-owned "multisig" key - (File: crypto/dkg/src/lib.rs)

### Summary
The FreeScout bug class is "mass assignment": an update routine fills a record from attacker-supplied fields without checking that a security-critical field (the password) is absent/consistent. The structural analog in Serai is `ThresholdKeys::read` / `ThresholdKeys::new` in `crypto/dkg`, which deserializes a complete key package — threshold params, interpolation coefficients, secret share, and all `n` verification shares — from untrusted bytes, and never checks that the loaded `secret_share` is consistent with `verification_shares[params.i()]`. The group key is computed solely from the deserialized verification shares (`crypto/dkg/src/lib.rs:376-378`), so whoever supplies the bytes fully controls the identity (group key) the key material claims to belong to, regardless of the embedded secret share.

### Finding Description
`ThresholdKeys::read` (`crypto/dkg/src/lib.rs:574-633`) reads `t`, `n`, `i`, an interpolation variant (with `n` attacker-chosen constant coefficients), one `secret_share`, and `n` verification shares, then calls `ThresholdKeys::new`. `new` (`crypto/dkg/src/lib.rs:349-391`) only checks:

- `verification_shares.len() == n`
- no participant index exceeds `n`
- `t == n` when `Interpolation::Constant` is used

It then derives `group_key` as `sum(verification_shares[i] * interpolation_factor(i, {1..=t}))` — entirely from the serialized verification shares. There is no check that `C::generator() * secret_share == verification_shares[i]` (the equivalent of FreeScout's missing ownership/consistency check on the sensitive field). Compare with `recover_key` (`crypto/dkg/recovery/src/lib.rs:80-82`), which *does* verify `C::generator() * recovered == group_key` — the codebase knows this invariant matters, but `read`/`new` never enforce it.

An unprivileged party who can feed bytes to `ThresholdKeys::read` (a surface the audit scope explicitly admits, e.g. key material loaded from storage/`GeneratedKeysDb::read_keys` in `processor/src/key_gen.rs:57-58`, or an integrator importing key packages) can supply `t = 1, n = 1, i = 1`, a verification share `V = G*x` for an `x` they know, and any `secret_share`. All validation passes; `group_key()` returns `V`, a key whose discrete log the attacker knows.

### Impact Explanation
`ThresholdKeys` objects are trusted after deserialization: `group_key()` is asserted equal to previously recorded key-pair values and used to register network deposit keys (`processor/src/key_gen.rs:98-119`), and the keys are used directly to instantiate signing machines (`AlgorithmMachine::new`, `musig(...).into()`, `networks/bitcoin/src/wallet/send.rs:281`). If an attacker-controlled key package is loaded:

- The reported group key is one whose discrete logarithm the attacker knows. Any funds addressed to it (or signatures it produces, since `sign` produces a valid FROST share for the fabricated single-party view) are under the attacker's sole control — the analog of "change their password, then log in as them."
- Alternatively, a mismatched `secret_share` causes every signature share this holder emits to fail `verify_share`/batch blame, permanently bricking the key — but the key still registers successfully first, so deposits already routed to it are unrecoverable.

This is secret-key-level compromise of a "threshold" key purely through attacker-chosen deserialized fields, with no curve or hash misuse required.

### Likelihood Explanation
Medium. Exploitation requires write influence over bytes later deserialized by `ThresholdKeys::read` (a serialized key package store, an import path, or an integrator that accepts key packages), analogous to FreeScout's "user with the right to edit other users." It does not require breaking BFT, collusion, or leaked secrets. The missing check is unconditional — every read succeeds regardless of share/group-key consistency — so once the write primitive exists the attack is deterministic.

### Recommendation
In `ThresholdKeys::new`, after computing `group_key`, additionally require `C::generator() * secret_share.deref() == verification_shares[&params.i()]` (or an equivalent consistency proof), rejecting the key package with a new `DkgError` variant on mismatch. This mirrors the check `recover_key` already performs and closes the mass-assignment gap at the trust boundary where untrusted bytes become trusted key material.

### Proof of Concept
```rust
use crypto::dkg::{ThresholdKeys, ThresholdParams, Interpolation};
use crypto::ciphersuite::Ciphersuite;
use crypto::frost::curve::Secp256k1; // any in-scope Ciphersuite
use group::GroupEncoding;
use zeroize::Zeroizing;

// Attacker knows x; victim/importer does not.
let x = <Secp256k1 as Ciphersuite>::F::random(&mut OsRng);
let attacker_vshare = Secp256k1::generator() * x;

// Craft a serialized ThresholdKeys: t=1, n=1, i=1, Lagrange,
// arbitrary secret_share (e.g. 1), one verification share = G*x.
let mut bytes = vec![];
bytes.extend(4u32.to_le_bytes());
bytes.extend(Secp256k1::ID);
bytes.extend(1u16.to_le_bytes()); // t
bytes.extend(1u16.to_le_bytes()); // n
bytes.extend(1u16.to_le_bytes()); // i = Participant(1)
bytes.push(1);                    // Interpolation::Lagrange
bytes.extend(<Secp256k1 as Ciphersuite>::F::ONE.to_repr().as_ref()); // bogus secret_share
bytes.extend(attacker_vshare.to_bytes().as_ref());

let keys = ThresholdKeys::<Secp256k1>::read(&mut bytes.as_slice()).unwrap();
// group_key is entirely attacker-controlled despite secret_share != x
assert_eq!(keys.group_key(), attacker_vshare);
// Invariant that recover_key enforces is violated here:
assert_ne!(
  Secp256k1::generator() * keys.original_secret_share().deref(),
  keys.group_key()
);
```
The read succeeds, `group_key()` returns a key the attacker fully controls, and any downstream consumer (key registration, `multisig()` construction, `recover_key` on matching packages) treats it as a legitimate threshold key.
