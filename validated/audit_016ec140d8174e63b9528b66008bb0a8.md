## Title
Single reverting CL pool call in `MultiCallDPStakingInfo` can halt reward finalization for every validator - (File: kaiax/staking/impl/getter.go)

### Summary
The Kaia staking module aggregates consensus-liquidity (CL) staking data for **all** validators in a single external call (`MultiCallDPStakingInfo`), and any failure of that single call is propagated as a hard error that aborts `GetStakingInfo()` for the entire block — exactly the "one bad component blocks everyone" pattern described in the BakerFi `MultiStrategyVault` report, where a single paused Strategy blocked withdrawals from all strategies.

### Finding Description
`StakingModule.getFromState()` reads validator staking data via the `MultiCall` system contract. For Prague/CL-enabled chains, it additionally aggregates every registered CL pool's staking info in one shot through `readCLInfo()`: [1](#0-0) 

```go
readCLInfo := func() (clRegistryResult, error) {
    ...
    clRes, err = contract.MultiCallDPStakingInfo(callOpts)
    if err != nil {
        return clRes, staking.ErrCLRegistryCall(err)
    }
    return clRes, nil
}
```

`MultiCallDPStakingInfo` internally enumerates **all** CL pools registered in `CLRegistry` and pulls staking amounts for each of them in one aggregated on-chain call (`getAllCLs()` plus per-pool balance queries), mirroring the vault's `_deallocateAssets`/`_allocateAssets` pattern of looping over every "strategy" (here, CL pool) in a single transaction. [2](#0-1) 

Any error from that single call — whether from an individual CL pool reverting, self-destructing, running out of gas, or otherwise misbehaving — is turned into a hard error (`ErrCLRegistryCall`) and returned all the way up through `getFromState` → `getFromStateByNumber` → `GetStakingInfo`: [3](#0-2) 

`GetStakingInfo` is a required dependency of the reward module used at every block's deferred reward distribution: [4](#0-3) 

```go
func (r *RewardModule) FinalizeState(header *types.Header, state *state.StateDB, txs []*types.Transaction, receipts []*types.Receipt) error {
    ...
    spec, err := r.GetDeferredReward(header, txs, receipts)
    if err != nil {
        return err
    }
    ...
}
```

`GetDeferredReward` calls `StakingModule.GetStakingInfo(num)` internally (via `assignStakingRewards`/consolidated node computation using `si.ConsolidatedNodes()` which needs `CLStakingInfos`). Because the whole `StakingInfo` structure — covering *every* validator's stake, not just the CL pool that misbehaves — is returned as a single unit, one misbehaving/paused CL pool anywhere in `CLRegistry` makes `GetStakingInfo` fail for the entire chain, which makes `FinalizeState` return an error for the block, exactly as the paused Strategy in `MultiStrategyVault` made withdrawals fail for the whole vault rather than only the affected strategy.

### Impact Explanation
`FinalizeState` is called during consensus block finalization for every block once the Prague hardfork (consensus liquidity, KIP-226) is active. If any single CL pool contract becomes non-responsive (reverts, runs out of gas on a large internal loop, is deliberately bricked by its owner, or is otherwise "paused"), `MultiCallDPStakingInfo` reverts and every node deterministically fails to finalize the block's rewards. Since all honest nodes execute the same deterministic call against the same state, this does not cause state divergence, but it **halts block finalization/reward distribution network-wide** — a complete denial of service for block production, not merely a loss of funds in one component. This is analogous to, and arguably more severe than, the original finding because the "vault" here is the entire Kaia reward/staking pipeline rather than a single user-facing DeFi vault.

### Likelihood Explanation
CL pools are user/staker-deployed permissionless liquidity contracts registered under `CLRegistry` (per KIP-226), so any staker/operator error, malicious CL pool deployment, or a legitimately "paused" CL pool integration (mirroring the exact AAVE-pause scenario from the original report) is sufficient to trigger this path. No validator/network compromise is required — only the existence of one bad CL pool entry that reverts when its data is fetched during the routine, once-per-block `MultiCallDPStakingInfo` aggregation.

### Recommendation
Do not let a single CL pool's failure abort the aggregate call. Options:
- Make `MultiCallDPStakingInfo` (or its Go wrapper) tolerant of failures on individual CL pools, e.g. by using low-level `staticcall`/try-catch per pool inside the aggregation contract and skipping/zeroing out unreachable pools instead of reverting the whole batch.
- In `readCLInfo()`, distinguish between a systemic error (AddressBook/CLRegistry not installed) and a per-pool failure, and exclude the specific failing CL pool from `StakingInfo` rather than propagating a hard error for the entire block.
- Add bounded gas/error isolation around each per-pool sub-call so that one bricked pool cannot become a chain-wide liveness bug.

### Proof of Concept
1. A staker registers a CL pool contract in `CLRegistry` (permissionless per KIP-226).
2. The CL pool's balance/state-query function is made to revert (either by design — pausing itself, similar to AAVE V3 pool pause — or via a bug that causes it to run out of gas when queried via `MultiCallDPStakingInfo`).
3. At the next block after Prague activation, every node's `StakingModule.getFromState()` calls `readCLInfo()` → `contract.MultiCallDPStakingInfo(callOpts)`, which reverts because of the single bad CL pool.
4. `GetStakingInfo` returns `staking.ErrCLRegistryCall(err)` for **all** validators, not just the misbehaving CL pool's beneficiary.
5. `RewardModule.FinalizeState` (`kaiax/reward/impl/blockstate.go`) receives this error from `GetDeferredReward` and returns it, causing block finalization to fail deterministically on every honest node — halting reward distribution/block production chain-wide until the offending CL pool entry is manually addressed.

func (s *StakingModule) GetStakingInfo(num uint64) (*staking.StakingInfo, error) {
	isKaia := s.ChainConfig.IsKaiaForkEnabled(new(big.Int).SetUint64(num))
	sourceNum := sourceBlockNum(num, isKaia, s.stakingInterval)

	// Try cache first
	if si, ok := s.stakingInfoCache.Get(sourceNum); ok {
		return si.(*staking.StakingInfo), nil
	}

	// Only before Kaia, try the database
	if !isKaia {
		if si := ReadStakingInfo(s.ChainKv, sourceNum); si != nil {
			s.stakingInfoCache.Add(sourceNum, si)
			return si, nil
		}
	}

	// Read from the state
	si, err := s.getFromStateByNumber(sourceNum)
	if err != nil {
		return nil, err
	}

	// Only before Kaia, write to database
	if !isKaia {
		WriteStakingInfo(s.ChainKv, sourceNum, si)
	}

	// Cache it
	s.stakingInfoCache.Add(sourceNum, si)
	return si, nil
}

	readCLInfo := func() (clRegistryResult, error) {
		var clRes clRegistryResult
		// If Registry is not installed, do not handle CL staking info.
		// In private network, Randao and Prague hardfork can be activated at the same block.
		// It leads to staking info inconsistency between block processing and rpc query since the Registry hasn't been installed when finalizing the header.

	}

func (r *RewardModule) FinalizeState(header *types.Header, state *state.StateDB, txs []*types.Transaction, receipts []*types.Receipt) error {
	if r.GovModule.GetParamSet(header.Number.Uint64()).ProposerPolicy == uint64(istanbul.WeightedRandom) && common.EmptyHash(header.Root) {
		qualified, err := r.ValsetModule.GetQualifiedValidators(header.Number.Uint64())
		if err != nil {
			return err
		}
		useRewardAddress := valset.NewAddressSet(qualified).Contains(r.NodeAddress)

		if rewardAddr := r.GetRewardAddress(header.Number.Uint64(), r.NodeAddress); useRewardAddress && rewardAddr != (common.Address{}) {
			header.Rewardbase = rewardAddr
			logger.Trace("Use reward address for nodeValidator", "header.Number", header.Number.Uint64(), "nodeAddress", r.NodeAddress, "rewardbase", header.Rewardbase)
		} else {
			logger.Trace("No reward address for nodeValidator. Use node's rewardbase.", "header.Number", header.Number.Uint64(), "nodeAddress", r.NodeAddress, "rewardbase", header.Rewardbase)
		}
	}

	spec, err := r.GetDeferredReward(header, txs, receipts)
	if err != nil {
		return err
	}
	if err := spec.Validate(); err != nil {
		return err
	}
	for addr, amount := range spec.Rewards {
		state.AddBalance(addr, amount)
	}
	return nil
}
