Confirmed: `CallDispatcher` (`evm/src/utils/CallDispatcher.sol`) is a single shared, persistent, stateless-logic contract (one `_params.dispatcher` address reused across every `placeOrder`/`fillOrder` call on the gateway). It has no access control on which tokens it can hold and no per-call isolation — any ERC20 `transfer` to its address, or any leftover token balance from an arbitrary `order.output.call`/`order.predispatch.call` execution, simply accumulates in its balance until something sweeps it out.

### Title
`placeOrder`'s predispatch sweep credits escrow from `CallDispatcher`'s full token balance, not the amount actually contributed by the order - (File: `evm/src/apps/IntentGatewayV2.sol`)

### Summary
`placeOrder`'s predispatch-funded path reads `IERC20(token).balanceOf(dispatcher)` and transfers the entire balance into the gateway as the order's "received" input, checking only `balance >= requiredAmount`. This is the same broken pattern as the seed report: the credited value is derived from a contract's on-chain balance rather than the amount actually supplied by the caller in the current call, so any token balance that happens to already sit on the shared `CallDispatcher` (dust from other orders' arbitrary calldata, direct external transfers, etc.) can be scooped into an attacker's own order for free.

### Finding Description
In `placeOrder`, when `order.predispatch.call.length > 0 && order.predispatch.assets.length > 0`: [1](#0-0) 

The flow is:
1. Transfer `order.predispatch.assets[i].amount` to `dispatcher` and run the user-supplied `predispatch.call`.
2. For each `order.inputs[i]`, read `balance = IERC20(token).balanceOf(dispatcher)` and require only `balance >= requiredAmount`.
3. Build a `transfer(address(this), balance)` call that sweeps the dispatcher's **entire** balance for that token into the gateway — not just `requiredAmount`, and not just what this transaction's `predispatch.assets` transfer contributed.
4. Any amount above `order.inputs[i].amount` is logged as `DustCollected`; the rest becomes `order.inputs[i].amount` (the "received" amount) and is escrowed for the caller's order via `_orders[commitment][token]`.

`CallDispatcher` (`evm/src/utils/CallDispatcher.sol`) is a single shared, unrestricted-relay contract used by *every* order's predispatch step and by `IntentsBase._execute`'s postdispatch calldata step: [2](#0-1) 

`_execute` only sweeps tokens that are explicitly listed in `order.output.assets` after running arbitrary calldata (`order.output.call`) through the dispatcher. Any token that ends up on the dispatcher as a side effect of that arbitrary calldata (e.g., a DEX swap producing a different token than the ones listed, approval remnants, a solver's calldata bug, or simply someone sending tokens to the publicly-known dispatcher address by mistake) is **not** swept and persists indefinitely as a stray balance on `CallDispatcher`.

Because `placeOrder`'s predispatch step trusts `balanceOf(dispatcher)` as the source of truth for "how much came in", any unprivileged caller can:
- Craft `order.inputs[0] = {token: X, amount: <trivial>}` and `predispatch.assets = {token: X, amount: <trivial nonzero>}` with a no-op `predispatch.call` (an empty `Call[]` dispatched, satisfying the `.length > 0` checks trivially), and
- Set `order.inputs[0].amount` up to the full stray balance of token `X` sitting on `dispatcher`.

The contract will pull dispatcher's *entire* balance of `X` into the gateway and either escrow it as "received" for the attacker's order (if it happens to be ≤ requested) or split any excess as `DustCollected` — in either case, tokens that were never contributed by the caller in this transaction, and that may belong to the protocol (unswept residue destined for `SweepDust` governance) or another unrelated order/user, get absorbed into the attacker's own order funding.

This directly parallels the `Controller.dctStake` bug: the "amount actually staked/escrowed" is computed from `balanceOf(contract)` rather than the value the caller is charged/attributed for in the current call, letting a caller benefit from balance that isn't theirs to claim.

### Impact Explanation
An unprivileged caller can fund (or partially fund) their own cross-chain/same-chain swap order using tokens that are not their own — tokens are moved out of the shared `CallDispatcher` into the attacker's escrowed order without a corresponding contribution, and later released to a solver or refunded to the attacker on cancellation. This is unauthorized appropriation of funds sitting in a Hyperbridge-controlled contract (`CallDispatcher`), i.e., fund loss for the protocol/other order flows and unauthorized transaction/execution beyond what the caller actually paid for.

### Likelihood Explanation
Requires only a public, unprivileged `placeOrder` call with a trivially crafted no-op predispatch call and knowledge that stray balance exists (or was placed there, e.g., by directly transferring tokens to the well-known `CallDispatcher` address, or by any prior order's arbitrary calldata leaving unswept dust). No relayer, prover, admin, or malicious peer is needed — it is entirely reachable by a single normal user transaction against the public `placeOrder` entrypoint.

### Recommendation
Track the amount actually contributed by *this order's* `predispatch.assets` transfer (e.g., snapshot `balanceOf(dispatcher)` immediately before crediting the predispatch assets for this specific token and compute the delta produced only by the predispatch call's expected output), rather than reading `dispatcher`'s ambient total balance. Alternatively, require `CallDispatcher` to be deployed per-order (ephemeral) or to zero out/track its balance atomically per invocation so stray balances can never be attributed to an unrelated caller's escrow.

### Proof of Concept
1. Some stray `USDC` balance exists on the shared `CallDispatcher` (e.g., left over from another order's arbitrary `output.call` swap that produced USDC instead of the listed output token, or simply sent there directly by any party).
2. Attacker calls `placeOrder` with:
   - `predispatch.assets = [{token: USDC, amount: 1}]` (trivial, satisfies `amount == 0` revert-avoidance)
   - `predispatch.call = abi.encode(emptyCalls)` (no-op `Call[]`, satisfies `.length > 0`)
   - `order.inputs = [{token: USDC, amount: <stray_balance_amount>}]`
3. In the predispatch sweep loop, `balance = IERC20(USDC).balanceOf(dispatcher)` equals `1 (attacker's own contribution) + stray_balance_amount`, which satisfies `balance >= requiredAmount`.
4. The full balance is swept to the gateway; `received` is computed as `balance - balancesBefore[i]`, crediting the attacker's order with the stray tokens they never contributed, minus a trivial fee difference emitted as dust.
5. The attacker's order is now escrowed with tokens they did not pay for, which a solver can later fill (paying attacker output tokens) or which the attacker can cancel/refund to themselves. [3](#0-2) [4](#0-3)

/**
 * @title The CallDispatcher
 * @author Polytope Labs (hello@polytope.technology)
 *
 * @notice This contract is used to dispatch calls to other contracts.
 */
contract CallDispatcher is ICallDispatcher {
    /**
     * @dev error thrown when the target is not a contract.
     */
    error NotContract(address target);

    /**
     * @dev error thrown when a call fails.
     */
    error CallFailed(address target, bytes result);

    /**
     * @dev Receive function to accept ETH transfers
     */
    receive() external payable {}

    /**
     *  @dev reverts if the target is not a contract or if any of the calls reverts.
     */
    function dispatch(bytes memory encoded) external {
        Call[] memory calls = abi.decode(encoded, (Call[]));
        uint256 callsLen = calls.length;
        for (uint256 i = 0; i < callsLen; ++i) {
            Call memory call = calls[i];
            uint32 size;
            address to = call.to;
            assembly {
                size := extcodesize(to)
            }

            if (size == 0) {
                revert NotContract(to);
            }

            (bool success, bytes memory result) = to.call{value: call.value}(call.data);
            if (!success) revert CallFailed(to, result);
        }
    }
}
