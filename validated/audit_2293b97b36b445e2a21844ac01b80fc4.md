### Title
`ThresholdKeys::read` triggers quadratic Lagrange interpolation over an attacker-controlled participant count, enabling CPU DoS - (File: crypto/dkg/src/lib.rs)

### Summary
Analogous to the `ua-parser-js` advisory (unbounded attacker-controlled input reaching a costlier-than-linear computation), `ThresholdKeys::<C>::read` accepts a fully attacker-controlled `n`/`t` pair and then performs `O(t^2)` field work inside `ThresholdKeys::new` when deriving `group_key` via Lagrange `interpolation_factor`. A ~2 MB serialized blob specifying `t = n = 65535` forces ~4.3 billion field multiplications and 65,535 field inversions, a polynomial CPU blowup relative to input size with no length limit enforced before the expensive computation.

### Finding Description
`ThresholdKeys::read` reads `t`, `n`, and `i` directly from the untrusted stream, then reads `n` group elements into `verification_shares` and calls `ThresholdKeys::new` (`crypto/dkg/src/lib.rs:591-631`). `ThresholdParams::new` only enforces `t <= n` and `i <= n`, so an attacker may set `t = n = 65535` — the maximum encodable in two bytes (`crypto/dkg/src/lib.rs:166-179`). `ThresholdKeys::new` then computes the group key as `verification_shares[i] * interpolation.interpolation_factor(i, &t)` summed over `t` participants (`crypto/dkg/src/lib.rs:376-378`). With `Interpolation::Lagrange` (a single `0x01` byte in the input), each `interpolation_factor` call loops over all `t` entries performing two field multiplications per entry and a field inversion (`crypto/dkg/src/lib.rs:229-247`). Total work is therefore `t * t` field multiplications plus `t` inversions plus `t` variable-time scalar multiplications — quadratic in a value the attacker fully controls, while the input only grows linearly (`n * 32` bytes for compressed points). The same quadratic pattern exists in `ThresholdKeys::view`, which calls `interpolation_factor` once per included participant (`crypto/dkg/src/lib.rs:500-507`), reachable from `SignMachine::sign` with an attacker-influenced `included` set (`crypto/frost/src/sign.rs:283-312`).

### Impact Explanation
Any service that calls `ThresholdKeys::read` on bytes an unprivileged party can supply (the explicitly in-scope sink) can be made to burn CPU quadratically in a 16-bit length field. At `t = n = 65535`, a single ~2 MB message yields roughly 4.3 x 10^9 field multiplications and 65,535 inversions — orders of magnitude more expensive than producing the input, directly mirroring the advisory's "parsing time growing polynomially with input length" availability-only impact.

### Likelihood Explanation
Reachability requires an integrator to deserialize `ThresholdKeys` from untrusted input; the threat model accepts exactly this path. The attacker controls `t`, `n`, `i`, the interpolation tag, and all share bytes, and there is no cap on `n` beyond `u16::MAX`. No secret material or collusion is needed — the cost is incurred purely during deserialization/`new`, before any key validation can reject the input. Residual uncertainty: the interpolation tag `1` (Lagrange) path is confirmed, and the same bound applies to `Constant` (which additionally requires `t == n`, satisfied here), so both tags trigger the quadratic `group_key` computation.

### Recommendation
Cap `n`/`t` in `ThresholdKeys::read` to a protocol-appropriate maximum (e.g., the `MAX_KEY_SHARES_PER_SET` bound used elsewhere in the codebase) before reading `verification_shares` or constructing `ThresholdKeys`, and/or compute `group_key` with a single multiexp using precomputed interpolation factors derived once rather than per-participant `O(t)` products.

### Proof of Concept
```rust
use std::io;
use ciphersuite::Ciphersuite;
use ciphersuite::Ristretto;
use dkg::{Participant, ThresholdKeys};

fn main() {
    // t = n = u16::MAX, i = 1, Lagrange interpolation
    let t: u16 = u16::MAX;
    let n: u16 = u16::MAX;

    let mut buf = vec![];
    buf.extend(u32::try_from(Ristretto::ID.len()).unwrap().to_le_bytes());
    buf.extend(Ristretto::ID);
    buf.extend(t.to_le_bytes());
    buf.extend(n.to_le_bytes());
    buf.extend(Participant::new(1).unwrap().to_bytes());
    buf.push(1); // Interpolation::Lagrange
    // secret_share = 1
    let mut repr = <Ristretto as Ciphersuite>::F::ONE.to_repr();
    buf.extend(repr.as_ref());
    // n verification shares = generator encoding
    let g = Ristretto::generator().to_bytes();
    for _ in 0 .. n {
        buf.extend(g.as_ref());
    }
    // ~2 MB of input

    let start = std::time::Instant::now();
    let _ = ThresholdKeys::<Ristretto>::read::<&[u8]>(&mut buf.as_ref());
    // group_key derivation performs ~t^2 field multiplications + t inversions
    println!("elapsed: {:?}", start.elapsed());
}
```
