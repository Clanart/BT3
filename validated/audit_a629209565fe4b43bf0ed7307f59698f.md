### Title
Validator Stake and Consensus-Liquidity Amount Are Derived From Raw Native Balance, Enabling Direct-Transfer Inflation of Reward Weight and Staking Eligibility — (File: kaiax/staking/impl/getter.go)

### Summary
The Kaia `kaiax/staking` module computes each validator's staking amount (and, since the Prague/KIP-226 hardfork, its Consensus Liquidity `CLStakingAmount`) directly from the *native token balance* of the registered `CNStaking` / `CLPool` contract addresses, rather than from an internally tracked deposit ledger. This is the same bug class as the "Inflation of Pool Balances" report: relying on `balanceOf`/native-balance queries as the source of truth for an accounting invariant, instead of maintaining an internal credit record distinct from raw transfers into the contract's address.

### Finding Description
`parsePermissionlessCallResult` in `kaiax/staking/impl/getter.go` builds `StakingInfo.StakingAmounts` from an `amounts` array and `CLStakingInfo.CLStakingAmount` from `clRes.StakingAmounts`, both divided by `params.KAIA` and used as-is as the "effective stake": [1](#0-0) 

The unit tests confirm these amounts are taken verbatim from the native KAIA balance placed at the staking/CLPool addresses in genesis allocation — e.g. `CLPool1` funded with `20_000_000 * KAIA` produces `CLStakingAmount: 20_000_000`, with a 1:1 correspondence between raw balance and reported stake: [2](#0-1) 

`CLStakingInfo` itself is just `{CLNodeId, CLPoolAddr, CLStakingAmount}` — a plain snapshot of an address's balance, with no separate bookkeeping of "legitimately staked" vs. "arbitrarily transferred" funds: [3](#0-2) 

This raw balance-derived amount is then used to split rewards proportionally between the CN and its CL pool: [4](#0-3) 

...and to compute each validator's share of the staking reward budget, both in the Kore rule and the newer Flex rule: [5](#0-4) [6](#0-5) 

Because `CNStaking` and `CLPool` addresses are public, permissionless contract/EOA addresses, any transaction sender (including an unprivileged staker, or even a third party) can send a plain native-token transfer directly to a validator's `CNStaking` or `CLPool` address. This inflates the measured `StakingAmount`/`CLStakingAmount` exactly as in the reported StargatePool bug — no deposit/staking-authorization flow is required — and the inflated figure is fed straight into:
1. Minimum-stake eligibility checks (`cn.StakingAmount < minStake`).
2. Threshold-based reward-share calculations (`assignStakingRewardsFlex`, `assignStakingRewards`).
3. The CN/CL reward split ratio (`consolidatedNode.Split`).
4. Gini-coefficient-based validator scoring (`StakingInfo.Gini`).

### Impact Explanation
An inflated `StakingAmount`/`CLStakingAmount` directly redirects block rewards: a validator (or its CLPool owner) can artificially cross the `minStake`/`StakingRewardThreshold` boundary, or increase its proportional share of the reward budget relative to honest validators, purely by moving native KAIA into the pool's address rather than through the legitimate staking/consensus-liquidity deposit mechanism. This is a concrete reward-redirection/value-misallocation vector, since honest validators' shares are computed as a ratio against the (inflated) total stake pool (`totalExcessInt`/`totalExcess` in `assignStakingRewards`/`assignStakingRewardsFlex`), meaning inflation by one party dilutes rewards owed to others while amplifying the attacker-controlled validator's share once the KAIA can be withdrawn or reused after each interval snapshot.

### Likelihood Explanation
High reachability: the action requires only a standard value-transfer transaction from any account to a publicly known `CNStaking`/`CLPool` address — no special privileges, no contract interaction beyond a plain transfer. The staking snapshot is taken periodically (`SourceNum`), so the attacker only needs the balance inflated at the snapshot block, then can withdraw/reuse the funds afterward (depending on the staking/CLPool contract's withdrawal rules, which are external to this module and not verified here).

### Recommendation
Do not treat the raw native balance of `CNStaking`/`CLPool` addresses as the authoritative "staking amount." Maintain (or query) an internally tracked, permissioned deposit ledger (e.g., a `stakedAmount` accounting variable updated only through the legitimate stake/deposit function) separate from the address's raw balance, and use that internal ledger — not `GetBalance`/`balanceOf` — when computing `StakingAmounts` and `CLStakingAmount` in `kaiax/staking/impl/getter.go`. If the existing `CNStaking`/`CLPool` system contracts already expose an authoritative "staked" accessor distinct from balance, use that accessor instead of the raw balance in the multicall/result-parsing path.

### Proof of Concept
1. Identify a validator's registered `CLPool` address (or `CNStaking` address) via the `AddressBook`/`CLRegistry`, both of which are publicly readable.
2. From any account, submit an ordinary native-token transfer transaction sending KAIA to that `CLPool`/`CNStaking` address (no special call data required).
3. At the next `StakingInfo` snapshot (`SourceNum`), `parsePermissionlessCallResult` reads the address's balance and reports the inflated amount as `CLStakingAmount`/`StakingAmounts`, as demonstrated by the exact balance-to-`CLStakingAmount` correspondence in [7](#0-6) .
4. The inflated amount is used unmodified by `assignStakingRewards`/`assignStakingRewardsFlex` and `consolidatedNode.Split` to compute reward shares and stake-threshold eligibility, redirecting rewards disproportionate to genuinely staked/committed funds.

*Note: I could not retrieve the exact source lines of the native-balance query call inside `kaiax/staking/impl/getter.go` (only match counts were available before the tool budget was exhausted), so the precise call site (e.g., `GetBalance`) is inferred from the surrounding parsing function and confirmed indirectly through the test fixtures. If a Devin session is needed to confirm the exact multicall/RPC call that produces `amounts`/`clRes.StakingAmounts`, I recommend inspecting `kaiax/staking/impl/getter.go` in full for the function that issues the balance query prior to `parsePermissionlessCallResult`.*

func (c consolidatedNode) Split(amount *big.Int) (*big.Int, *big.Int) {
	if c.CLStakingInfo == nil {
		return amount, big.NewInt(0)
	}

	var (
		cnAmountBig = big.NewInt(int64(c.StakingAmount))
		clAmountBig = big.NewInt(int64(c.CLStakingInfo.CLStakingAmount))
		totalAmount = new(big.Int).Add(cnAmountBig, clAmountBig)
	)

	clAmount := new(big.Int).Mul(clAmountBig, amount)
	clAmount = clAmount.Div(clAmount, totalAmount)

	// The remaining amount is for the CN.
	cnAmount := big.NewInt(0).Sub(amount, clAmount)

	return cnAmount, clAmount
}

// assignStakingRewardsFlex assigns staking rewards to stakers according to their staking amounts.
// Returns the allocation and the remainder.
func assignStakingRewardsFlex(config *reward.RewardConfig, budget *big.Int, si *staking.StakingInfo) (map[common.Address]*big.Int, *big.Int) {
	var (
		minStake  = config.MinimumStake.Uint64()
		threshold = config.StakingRewardThreshold.Uint64()
		isPrague  = config.Rules.IsPrague

		cns            = si.ConsolidatedNodes()
		excessInt      = make(map[common.Address]uint64)
		totalExcessInt = uint64(0)
	)

	// Calculate the excess stakes (the amount over the threshold) for each CN.
	for _, cn := range cns {
		// If the CNStaking is less than minStake, skip it. Even if (CNStaking + CLStaking) could be more than minStake,
		// the CNStaking alone must be at least minStake to be eligible.
		if cn.StakingAmount < minStake {
			continue
		}

		amount := cn.StakingAmount
		if isPrague && cn.CLStakingInfo != nil {
			amount += cn.CLStakingInfo.CLStakingAmount
		}

		// Excess is the amount over the threshold (not over minStake).
		if amount > threshold {
			excessInt[cn.RewardAddr] = amount - threshold
			totalExcessInt += excessInt[cn.RewardAddr]
		}
	}

	// Distribute the budget to the CNs based on the excess stakes.
	var (
		totalExcess = new(big.Int).SetUint64(totalExcessInt)
		remaining   = new(big.Int).Set(budget)
		alloc       = make(map[common.Address]*big.Int)
	)
	for _, cn := range cns {
		if excessInt[cn.RewardAddr] <= 0 {
			continue
		}
		excess := new(big.Int).SetUint64(excessInt[cn.RewardAddr])

		// The KAIA unit will cancel out:
		// reward (kei) = excess (KAIA) * budget (kei) / totalExcess (KAIA)
		reward := new(big.Int).Div(new(big.Int).Mul(excess, budget), totalExcess)
		if reward.Sign() <= 0 {
			continue
		}

		// If Prague and CL is configured for this CN, split the reward between CN and CL.
		if isPrague && cn.CLStakingInfo != nil {
			cnAmount, clAmount := cn.Split(reward)
			alloc[cn.RewardAddr] = cnAmount
			alloc[cn.CLStakingInfo.CLPoolAddr] = clAmount
		} else {
			alloc[cn.RewardAddr] = reward
		}
		remaining.Sub(remaining, reward)
	}
	return alloc, remaining
}

// assignStakingRewards assigns staking rewards to stakers according to their staking amounts.
// Returns the allocation and the remainder.
func assignStakingRewards(config *reward.RewardConfig, stakersReward *big.Int, si *staking.StakingInfo) (map[common.Address]*big.Int, *big.Int) {
	var (
		cns               = si.ConsolidatedNodes()
		minStake          = config.MinimumStake.Uint64()
		totalExcessInt    = uint64(0) // sum of excess stakes (the amount over minStake) over all stakers
		cnTotalStakingMap = make(map[common.Address]uint64)
		isPrague          = config.Rules.IsPrague
	)
	for _, cn := range cns {
		// If the CNStaking is less than minStake, skip it.
		if cn.StakingAmount >= minStake {
			// Calculate total staking amount once
			cnTotalStakingAmount := cn.StakingAmount
			if isPrague && cn.CLStakingInfo != nil {
				cnTotalStakingAmount += cn.CLStakingInfo.CLStakingAmount
			}
			totalExcessInt += cnTotalStakingAmount - minStake
			cnTotalStakingMap[cn.RewardAddr] = cnTotalStakingAmount
		}
	}

	var (
		totalExcess = new(big.Int).SetUint64(totalExcessInt)
		remaining   = new(big.Int).Set(stakersReward)
		alloc       = make(map[common.Address]*big.Int)
	)
	for _, cn := range cns {
		cnTotalStakingAmount := cnTotalStakingMap[cn.RewardAddr]
		if cnTotalStakingAmount > minStake {
			// The KAIA unit will cancel out:
			// reward (kei) = excess (KAIA) * stakersReward (kei) / totalExcess (KAIA)
			excess := new(big.Int).SetUint64(cnTotalStakingAmount - minStake)
			if reward := new(big.Int).Div(new(big.Int).Mul(excess, stakersReward), totalExcess); reward.Sign() > 0 {
				if isPrague && cn.CLStakingInfo != nil {
					// The remaining amount will be added to the cnAmount.
					cnAmount, clAmount := cn.Split(reward)
					alloc[cn.RewardAddr] = cnAmount
					alloc[cn.CLStakingInfo.CLPoolAddr] = clAmount
				} else {
					alloc[cn.RewardAddr] = reward
				}
				remaining.Sub(remaining, reward)
			}
		}
	}
	return alloc, remaining
}
