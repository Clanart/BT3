### Title
Small-amount NFT royalty payments truncate to zero via integer division, allowing offer takers to bypass royalty payments - (File: chia/wallet/nft_wallet/nft_wallet.py)

### Summary
`NFTWallet.compute_royalty_amount()` and `NFTWallet.royalty_calculation()` compute NFT trade royalties using integer division (`abs(amount) // royalty_split * percentage // MAX_ROYALTY_BASIS_POINTS`), which is the same rounding-to-zero pattern flagged in the external report's `InsuranceFund.depositFor()` (`shares = amount * _totalSupply / _pool`). When the fungible amount offered/requested for an NFT is small relative to `10000` basis points, the computed royalty can truncate to `0`, silently skipping the royalty payment that the NFT creator is entitled to.

### Finding Description
`compute_royalty_amount` performs the division without any minimum-amount or non-zero-result enforcement other than rejecting `percentage > 10000`: [1](#0-0) 

The wallet's own test suite documents that small amounts intentionally truncate to zero rather than reverting or scaling up: [2](#0-1) 

This same rounding behavior is duplicated in `NFTWallet.royalty_calculation()`, used to summarize expected royalties for both sides of a trade: [3](#0-2) 

And in `make_nft1_offer()`, the code even explicitly filters out trade prices whose royalty computation rounds to zero rather than rejecting the trade or forcing a minimum amount: [4](#0-3) 

Royalty payments in the offer flow are only generated when `payment_list`/`payment_sum` is non-zero; a zero-royalty payment is simply skipped: [5](#0-4) 

Since an offer's fungible amount is chosen by the offer maker/taker, a party can deliberately structure a trade (e.g., very small XCH/CAT amount, or splitting across multiple royalty-eligible NFTs via `royalty_split`) so `amount // royalty_split * percentage // 10000 == 0`, resulting in a trade that completes with the NFT transferred but zero royalty paid to the creator's `royalty_address`.

### Impact Explanation
This lets any offer counterparty avoid paying legitimate NFT creator royalties on low-value trades or trades split across multiple royalty-bearing assets, directly costing the royalty-address holder their entitled payment on a settled offer. This is an "offer settlement" defect: the trade completes (NFT ownership transfers) while the economically-guaranteed royalty payment silently disappears due to integer truncation, rather than being proportionally reduced or rejected.

### Likelihood Explanation
Any wallet user constructing or accepting an NFT offer controls the offered/requested amounts and can trivially pick values that make `amount * percentage // 10000` round to zero (for a royalty percentage of, e.g., 100 basis points = 1%, any offered amount below 100 units of the base currency truncates entirely). No special privileges, network position, or races are required — a single spend-bundle-generating offer accept is sufficient.

### Recommendation
Apply a scaling-factor technique as suggested by the analogous report (multiply by a large constant before dividing, then divide back down), or explicitly reject/round-up trades whose computed royalty would be zero while `amount * percentage > 0`, in `compute_royalty_amount()` and `royalty_calculation()` in `chia/wallet/nft_wallet/nft_wallet.py`. Alternatively, enforce a minimum offer/request amount per royalty-bearing NFT such that `amount * percentage >= MAX_ROYALTY_BASIS_POINTS` before allowing the trade to proceed.

### Proof of Concept
1. Mint an NFT with a nonzero `royalty_percentage` (e.g., 100 = 1%) and `royalty_address` set to the creator.
2. Create an offer requesting the NFT for a small XCH amount, e.g. `50` mojos (`test_small_amount_truncates_to_zero` reproduces the exact arithmetic: `compute_royalty_amount(offered_amount=-50, royalty_split=1, percentage=100)` returns `uint64(0)`): [2](#0-1) 
3. Accept the offer via `respond_to_offer`; because `payment_sum == 0`, no royalty coin is created and the trade settles with the NFT transferred but zero payment to `royalty_address`. [5](#0-4)

```python
def compute_royalty_amount(offered_amount: int, royalty_split: int, percentage: int) -> uint64:
    """Compute royalty using integer arithmetic, validating against overflow and excessive percentage."""
    if percentage > MAX_ROYALTY_BASIS_POINTS:
        raise ValueError(f"NFT royalty percentage {percentage} exceeds 100% ({MAX_ROYALTY_BASIS_POINTS} basis points)")
    amount = abs(offered_amount) // royalty_split * percentage // MAX_ROYALTY_BASIS_POINTS
    royalty = uint64(amount)
    if royalty >= abs(offered_amount):
        raise ValueError("Royalty amount meets or exceeds the offered amount")
    return royalty
```

```python
    @staticmethod
    def royalty_calculation(
        royalty_assets_dict: dict[Any, tuple[Any, uint16]],
        fungible_asset_dict: dict[Any, uint64],
    ) -> dict[Any, list[dict[str, Any]]]:
        summary_dict: dict[Any, list[dict[str, Any]]] = {}
        for id, royalty_info in royalty_assets_dict.items():
            address, percentage = royalty_info
            summary_dict[id] = []
            for name, amount in fungible_asset_dict.items():

                    {
                        "asset": name,
                        "address": address,
                        "amount": abs(amount) // len(royalty_assets_dict) * percentage // MAX_ROYALTY_BASIS_POINTS,
                    }
                )

        return summary_dict
```
