### Title
Missing deadline check in `GaslessModule.VerifyExecutable`/`IsExecutable` allows bundling of expired SwapTx into `LendTx` bundles - (File: kaiax/gasless/impl/getter.go)

### Summary
`GaslessModule.VerifyExecutable` (aliased by `IsExecutable`) is the authoritative "is this gasless transaction pair valid/executable" check used both by the public `gasless_isGaslessTx` RPC API and by the block-building bundling logic. Unlike the analogous `checkBalanceForSwap` function used for tx-pool admission, `VerifyExecutable` never validates `SwapArgs.Deadline` against the current block timestamp.

### Finding Description
The documented conditions checked by `VerifyExecutable` (Sx, Ax, AP1, SP1–SP4) are enumerated in the comment at [1](#0-0) , and none of them include the deadline. The implementation confirms this — it decodes and validates the swap/approve pair, sender match, token match, approval amount, nonce sequencing, and repay amount, but never inspects `swapArgs.Deadline`: [2](#0-1) .

By contrast, the tx-pool admission path `checkBalanceForSwap` explicitly enforces `tx.deadline >= currentTimestamp` [3](#0-2) , exactly mirroring the reported Marketplace pattern where one validation entry point (`validate()`) omits an expiry check that a sibling entry point (`swap()`) enforces.

Critically, `VerifyExecutable`/`IsExecutable` is not just a query helper — it is invoked directly in the block-building/bundling path `GaslessModule.ExtractTxBundles`, which decides whether a `SwapTx` (with its optional preceding `ApproveTx`) is bundled together with a generated `LendTx` for execution: [4](#0-3) . Since the deadline check only occurs once at tx-pool admission time (`checkBalanceForSwap`) and is not re-verified at bundling/execution time, a swap transaction that was valid at submission but whose `deadline` has since elapsed (e.g., it sat in the pool waiting on nonce ordering, or block production was delayed) can still be judged "executable" by `IsExecutable` and bundled with a freshly-generated `LendTx` that transfers KAIA to the sender to cover gas.

### Impact Explanation
If `IsExecutable` erroneously reports an expired `SwapTx` as executable, the block-builder generates and includes a `LendTx` (via `GetLendTxGenerator`) that transfers KAIA from the block proposer/lending account to the sender, expecting to be repaid via the on-chain `swapForGas` call in the same bundle. If the swap router contract itself enforces its own on-chain `deadline` check inside `swapForGas` (not verifiable in the indexed Solidity sources available), the swap call would revert, meaning the `LendTx` payout could occur without the expected repayment/swap succeeding within the bundle, leading to fund loss for the lender/proposer or a bundle that partially executes with the lent KAIA not recovered. If the on-chain contract does not itself enforce the deadline, an expired-but-still-profitable-looking swap could be executed against stale pricing conditions, causing settlement using outdated amounts.

### Likelihood Explanation
The gap is only exploitable when a `SwapTx`'s deadline elapses between pool admission and bundle inclusion — plausible under network congestion, delayed nonce-predecessor transactions, or during nonce-sequential approve+swap pairs where the swap waits behind the approve tx. This is a timing-dependent condition rather than a directly attacker-triggerable one, and its severity depends on whether the on-chain `GaslessSwapRouter.swapForGas` contract independently re-validates the deadline (which could not be confirmed from the available Solidity sources in the index).

### Recommendation
Add the same `deadline >= currentTimestamp` (or equivalent based on the block being built) check inside `VerifyExecutable` in `kaiax/gasless/impl/getter.go`, so that both the tx-pool admission path and the bundling/execution path (`ExtractTxBundles`) consistently reject expired `SwapTx`s before generating and including a `LendTx`.

### Proof of Concept
1. Submit a valid `ApproveTx` (nonce N) followed by a `SwapTx` (nonce N+1) with `deadline = now + 300`, both passing `checkBalanceForSwap` at submission time.
2. Delay block production (e.g., due to network conditions) past `now + 300` while the `ApproveTx` is still pending ahead of the `SwapTx` in the pool.
3. When the block builder calls `ExtractTxBundles`, `IsSwapTx(tx) && IsExecutable(approveTx, tx)` returns `true` for the now-expired `SwapTx` because `VerifyExecutable` never checks `swapArgs.Deadline`, at `kaiax/gasless/impl/builder.go:40` and `kaiax/gasless/impl/getter.go:214-266`.
4. The builder generates a `LendTx` transferring KAIA to the sender and bundles it with the expired `SwapTx`; whether this results in fund loss depends on the on-chain contract's own deadline enforcement, which is unverified in this repository's indexed contents.

func (g *GaslessModule) VerifyExecutable(approveTxOrNil, swapTx *types.Transaction) error {
	// Sx.
	swapArgs, ok := decodeSwapTx(swapTx, g.signer)
	if !ok {
		return ErrDecodeSwapTx
	}
	if !g.isSwapTx(swapArgs) {
		return ErrSwapTxInvalid
	}

	// Conditions involving ApproveTx
	if approveTxOrNil != nil {
		// Ax.
		approveArgs, ok := decodeApproveTx(approveTxOrNil, g.signer)
		if !ok {
			return ErrDecodeApproveTx
		}
		if !g.isApproveTx(approveArgs) {
			return ErrApproveTxInvalid
		}
		// AP1.
		if approveArgs.Sender != swapArgs.Sender {
			return ErrDifferentSenders
		}
		// SP1.
		if approveArgs.Token != swapArgs.Token {
			return fmt.Errorf("%w: approve token %s, swap token %s", ErrDifferentTokens, approveArgs.Token.Hex(), swapArgs.Token.Hex())
		}
		// SP2.
		if approveArgs.Amount.Cmp(swapArgs.AmountIn) < 0 {
			return fmt.Errorf("%w: approve amount %s, required amount %s", ErrInsufficientApproveAmount, approveArgs.Amount.String(), swapArgs.AmountIn.String())
		}
		// SP3.
		if approveTxOrNil.Nonce()+1 != swapTx.Nonce() {
			return fmt.Errorf("%w: approve nonce %d, swap nonce %d (expected %d)", ErrNonSequentialNonce, approveTxOrNil.Nonce(), swapTx.Nonce(), approveTxOrNil.Nonce()+1)
		}
		if nonce := g.getCurrentStateNonce(approveArgs.Sender); nonce != approveTxOrNil.Nonce() {
			return fmt.Errorf("%w: approve nonce %d, current nonce %d", ErrApproveNonceNotCurrent, approveTxOrNil.Nonce(), nonce)
		}
	} else {
		// SP3.
		if nonce := g.getCurrentStateNonce(swapArgs.Sender); nonce != swapTx.Nonce() {
			return fmt.Errorf("%w: swap nonce %d, current nonce %d", ErrSwapNonceNotCurrent, swapTx.Nonce(), nonce)
		}
	}

	// SP4.
	if swapArgs.AmountRepay.Cmp(repayAmount(approveTxOrNil, swapTx)) != 0 {
		return fmt.Errorf("%w: got %s, expected %s", ErrIncorrectRepayAmount, swapArgs.AmountRepay.String(), repayAmount(approveTxOrNil, swapTx).String())
	}

	return nil
}

func (g *GaslessModule) ExtractTxBundles(txs []*types.Transaction, prevBundles []*builder.Bundle) []*builder.Bundle {
	// there are only at most two gasless transactions in pending for a sender
	bundles := []*builder.Bundle{}
	approveTxs := map[common.Address]*types.Transaction{}
	targetTxHash := common.Hash{}
	for _, tx := range txs {
		addr, err := types.Sender(g.signer, tx)
		if err != nil {
			continue
		}
		if g.IsApproveTx(tx) {
			approveTxs[addr] = tx
		} else if g.IsSwapTx(tx) && g.IsExecutable(approveTxs[addr], tx) {
			bundleTxs := builder.NewTxOrGenList(g.GetLendTxGenerator(approveTxs[addr], tx))
			if approveTxs[addr] != nil {
				bundleTxs = append(bundleTxs, builder.NewTxOrGenFromTx(approveTxs[addr]))
			}
			bundleTxs = append(bundleTxs, builder.NewTxOrGenFromTx(tx))

			b := builder.NewBundle(
				bundleTxs,
				targetTxHash,
				false,
			)

			targetTxHash = tx.Hash()

			isConflict := false
			for _, prev := range append(prevBundles, bundles...) {
				if prev.IsConflict(b) {
					isConflict = true
					break
				}
			}
			if isConflict {
				// Gasless transactions will just fail even if they aren't bundled.
				continue
			}
			bundles = append(bundles, b)
		} else {
			targetTxHash = tx.Hash()
		}
	}
	return bundles
}
