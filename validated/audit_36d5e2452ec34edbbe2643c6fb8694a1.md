### Title
Payout transaction's OP_RETURN operator-attribution byte is not covered by the user's payout signature, allowing an unprivileged third party to reassign/erase payout credit - ([File: core/src/builder/transaction/operator_reimburse.rs])

### Summary
`create_payout_txhandler` builds a Payout transaction whose only signed input uses `SpendPath::KeySpend` with the user's `taproot::Signature` under a `SIGHASH_SINGLE|ANYONECANPAY`-style sighash (per the error message in `Operator::withdraw`), which by BTC consensus rules commits only to input 0 and output 0 (the user payout output). The second output — the OP_RETURN carrying the fronting operator's x-only pubkey — is never covered by that signature, so anyone possessing the (public) withdrawal parameters (`in_outpoint`, `in_signature`, `out_script_pubkey`, `out_amount` — obtainable from the Citrea `withdraw()` call data per the stated threat model) can independently reconstruct a bit-for-bit valid alternative Payout transaction with the identical input/output-0 but an arbitrary OP_RETURN payload, fund it with their own inputs, and race it to confirmation.

### Finding Description
The binding claimed: `operator_credited == operator_that_paid`, i.e., the x-only pubkey embedded in the mined Payout tx's OP_RETURN (used by the bridge circuit/kickoff flow to identify who fronted the withdrawal) must equal the operator that actually funded and broadcast the winning transaction.

Trace:
- `Operator::withdraw` (`core/src/operator.rs:594-637`) checks (a) the input outpoint matches the DB-registered `withdrawal_utxo`, (b) `is_profitable` on values only, and (c) `SECP.verify_schnorr` against `sighash = payout_txhandler.calculate_sighash_txin(0, in_signature.sighash_type)` [1](#0-0) . None of these checks constrain the OP_RETURN output content beyond what `create_payout_txhandler` itself hard-codes.
- `create_payout_txhandler` (`core/src/builder/transaction/operator_reimburse.rs:407-436`) builds output 0 (user payout), an anchor output, and an OP_RETURN output containing `operator_xonly_pk.serialize()` — the pubkey of whichever caller/operator happens to be constructing the tx — then signs only input 0 with `set_p2tr_key_spend_witness` [2](#0-1) . The doc comment explicitly states the OP_RETURN carries "operators x-only pubkey that fronts the peg-out" [3](#0-2) .
- Because the wrap_err message on the signature check demands "SinglePlusAnyoneCanPay" sighash type [4](#0-3) , the user's signature commits only to input 0 and output 0 under BIP-341/BIP-118 semantics; output 1 (anchor) and output 2 (OP_RETURN) are unconstrained by that signature. Any party holding the withdrawal parameters can therefore assemble a structurally different-but-input/output0-identical transaction, attach their own funding inputs, and put any pubkey (or garbage) into the OP_RETURN slot.
- Nothing downstream in `Operator::withdraw` re-derives or commits the OP_RETURN before broadcast, and no musig2/N-of-N signature covers this output either — the whole Payout transaction is single-party (operator) signed via key-spend, with the OP_RETURN's content decided unilaterally and unauthenticated by whichever party's raw transaction gets mined first.
- Existing guards (`is_deposit_valid`, `is_profitable`, `SECP.verify_schnorr`) validate only the outpoint match, fee economics, and the input signature — none of them assert anything about the OP_RETURN bytes, so they do not close this gap.

### Impact Explanation
Whichever raw transaction (honest operator's RBF-funded copy, or an attacker's independently-funded twin with a swapped OP_RETURN) gets mined first permanently fixes the on-chain attribution byte for that specific withdrawal, since the shared input outpoint can only be spent once. If the attacker's twin wins:
- The operator that actually ran the legitimate `withdraw()` flow, verified profitability, and funded the transaction via `fund_raw_transaction`/RBF is denied the reimbursement credit their capital outlay earned, because the mined bytes attest a different operator's pubkey (or no valid operator at all).
- This is repeatable per-withdrawal and requires no special privilege beyond broadcasting a Bitcoin transaction and knowing the (publicly obtainable) withdrawal parameters, matching the "Critical – an honest operator permanently unable to be reimbursed" category (or, if the OP_RETURN payload matches no real operator's kickoff key, the deposit's move-to-vault funds could become unreimbursable by anyone).

### Likelihood Explanation
Preconditions are only what the threat model already grants an unprivileged attacker: read access to the withdrawal parameters (input outpoint, user signature, output script/amount) via the Citrea `withdraw()` call, and the ability to fund and broadcast a competing Bitcoin transaction with normal fees. No `client_verification`/TLS bypass is even required for this specific variant, since the attacker does not need to call the operator's gRPC at all — they can build and submit the twin transaction directly to bitcoind, racing the honest operator's fee-bumped copy. The cost is only the attacker's own funding-input value plus fees, and the race is winnable via standard fee/RBF tactics.

### Recommendation
Bind the OP_RETURN operator-attribution output to the user's signature (e.g., have the user sign a sighash mode that also commits to all outputs, or require the operator's own signature/commitment over the OP_RETURN via a separate, verifiable mechanism such as a per-operator presigned template or an additional covenant), so the mined attribution cannot be substituted by any party other than the legitimate signer/operator pair.

pub fn create_payout_txhandler(
    input_utxo: UTXO,
    output_txout: TxOut,
    operator_xonly_pk: XOnlyPublicKey,
    user_sig: taproot::Signature,
    _network: bitcoin::Network,
) -> Result<TxHandler<Signed>, BridgeError> {
    let txin = SpendableTxIn::new_partial(input_utxo.outpoint, input_utxo.txout);

    let output_txout = UnspentTxOut::from_partial(output_txout.clone());

    let op_return_txout = op_return_txout(PushBytesBuf::from(operator_xonly_pk.serialize()));

    let mut txhandler = TxHandlerBuilder::new(TransactionType::Payout)
        .with_version(NON_STANDARD_V3)
        .add_input(
            NormalSignatureKind::NotStored,
            txin,
            SpendPath::KeySpend,
            DEFAULT_SEQUENCE,
        )
        .add_output(output_txout)
        .add_output(UnspentTxOut::from_partial(anchor_output(
            NON_EPHEMERAL_ANCHOR_AMOUNT,
        )))
        .add_output(UnspentTxOut::from_partial(op_return_txout))
        .finalize();
    txhandler.set_p2tr_key_spend_witness(&user_sig, 0)?;
    txhandler.promote()
}
