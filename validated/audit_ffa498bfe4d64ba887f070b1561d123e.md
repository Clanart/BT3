### Title
Divide-by-Zero Panic in KIP-71 Base Fee Calculation When `GasTarget` is Zero - (File: `params/kip71_config.go`)

### Summary
`KIP71Config.NextMagmaBlockBaseFee` divides by `gasTarget` (the governance parameter `governance.kip71.gastarget` / `Kip71GasTarget`) in two branches without any zero-guard, unlike the sibling `BaseFeeDenominator` parameter which explicitly falls back to a safe default of `64` when zero. If `GasTarget` is ever `0` while `parentGasUsed > 0`, this results in a `big.Int.Div` call with a zero divisor, which panics in Go's `math/big` package.

### Finding Description
`NextMagmaBlockBaseFee` is executed by every full node/validator for every block after the Magma hardfork, both when validating headers (`VerifyMagmaHeader`) and when preparing new blocks. The function explicitly guards `BaseFeeDenominator` against zero: [1](#0-0) 

However, `gasTarget` receives no equivalent protection: [2](#0-1) 

When `parentGasUsed != gasTarget`, the code divides by `gasTarget` directly: [3](#0-2) [4](#0-3) 

If `gasTarget == 0` and `parentGasUsed > 0` (the overwhelmingly common case, since any non-empty block uses gas), the code takes the "usage above target" branch and executes `x.Div(x, new(big.Int).SetUint64(gasTarget))` with a zero-valued `big.Int`, which panics with "division by zero" — this is the direct analog of the OpenCV `getDescriptorSize` divide-by-zero (CWE-369): an externally influenceable parameter reaching an unguarded integer division.

`GasTarget` is a `gov` module parameter (`Kip71GasTarget`) that governing nodes/governance can vote to change via governance transactions, and it is consumed on every block's base-fee computation through `pset.ToKip71Config()`: [5](#0-4) 

Whether the parameter's `FormatChecker` currently rejects `0` could not be conclusively verified within the available tool budget — the `BaseFeeDenominator` format checker explicitly requires `v != 0`: [6](#0-5) 
but I was unable to confirm the same for `Kip71GasTarget` before running out of iterations; this is a gap that would need to be checked in the `gov/param.go` `Params` table entry for `Kip71GasTarget`.

### Impact Explanation
If a zero `GasTarget` is accepted by governance (or reachable through any other path that bypasses format validation, e.g. genesis configuration or a governance replay/migration bug), every node computing the next block's base fee via `NextMagmaBlockBaseFee` — which runs unconditionally on all Magma+ blocks with nonzero gas usage — will panic. This is a chain-halting denial of service affecting all full nodes and validators simultaneously, which is a severe consensus-availability impact (all honest nodes crash identically, rather than diverging, but the effect on chain liveness is a Medium/High-severity impact consistent with the rules' "state divergence between honest nodes" / invalid-block-acceptance category, since it prevents any node from producing or verifying blocks).

### Likelihood Explanation
Likelihood depends entirely on whether `GasTarget == 0` can pass the `Kip71GasTarget` parameter's `FormatChecker` during a governance vote. This requires either a missing/weak validation in `kaiax/gov/param.go` for `Kip71GasTarget`, or misconfigured genesis. I was not able to confirm this within the session — if the checker mirrors `BaseFeeDenominator`'s `v != 0` requirement, the bug is not reachable and this analog would not apply.

### Recommendation
Add an explicit zero-guard for `gasTarget` in `NextMagmaBlockBaseFee`, mirroring the existing fallback for `BaseFeeDenominator` (e.g., substitute a safe non-zero default such as `params.DefaultGasTarget` when `kc.GasTarget == 0`). Additionally, verify and, if missing, add a `FormatChecker` for `Kip71GasTarget` in `kaiax/gov/param.go` that rejects `0`, consistent with `Kip71BaseFeeDenominator`.

### Proof of Concept
1. Via governance, set `governance.kip71.gastarget` (`Kip71GasTarget`) to `0` (pending confirmation that the format checker permits this value).
2. Once the new parameter is active and a block with `GasUsed > 0` is produced under the Magma fork, any node computing `NextMagmaBlockBaseFee(parentHeaderNumber, parentHeaderBaseFee, parentHeaderGasUsed)` — reached via `params/kip71_config.go:92` (`parentGasUsed > gasTarget` branch) — executes `x.Div(x, new(big.Int).SetUint64(0))`, which panics in Go's `math/big`.
3. This crash occurs in header verification (`VerifyMagmaHeader`) and block preparation paths across all full nodes/validators, halting the chain.
