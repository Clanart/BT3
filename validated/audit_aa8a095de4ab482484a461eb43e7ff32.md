### Title
Unrestricted duplicate `CnStakingV4` proxy deployment for the same owner via `CnStakingV4Factory.deployCnStaking` - (File: `blockchain/system/permissionless.go`, contract binding `contracts/bindings/cnstakingv4factory/CnStakingV4Factory.go`)

### Summary
`CnStakingV4Factory` exposes a public, paid transaction `deployCnStaking(address _owner)` that any caller can invoke with an arbitrary `_owner` argument to spin up a new `CnStakingV4` beacon proxy. [1](#0-0)  The factory only exposes `isDeployedCnStaking(address)` / `isDeployedPublicDelegation(address)` (keyed by the deployed proxy address) and `getDeployer(address)` (mapping a proxy back to its deployer), but no query that maps an *owner* to a proxy and no visible guard preventing the same `_owner` from being passed to `deployCnStaking`/`deployCnStakingWithPD` multiple times to create additional proxies for that owner. [2](#0-1)  This mirrors the reported Catalyst-Exchange bug class: a factory contract that permits repeated/duplicate deployment of what looks like a canonical vault (here, a validator's staking contract) because it never validates "has this vault/owner already been deployed."

### Finding Description
The factory is deployed and registered as the canonical `CnStakingFactory` system contract during permissionless genesis setup, and each validator's `CnStakingV4` staking proxy is created by calling `deployCnStaking(manager)` on it. [3](#0-2)  Once the permissionless hard fork is active, this factory address is reachable by any transaction sender on-chain (not just the genesis bootstrap flow), because `deployCnStaking`/`deployCnStakingWithPD` are plain public/payable transactor methods with no ownership check bound to `msg.sender` visible in the bindings — the `_owner` parameter is caller-supplied. [4](#0-3)  The only bookkeeping exposed is per-proxy (`isDeployedCnStaking`, `getDeployer`), not per-owner, so nothing stops a malicious caller from invoking `deployCnStaking(victimOwner)` again for an owner address that already has a legitimate staking proxy, producing a second, unrelated `CnStakingV4` proxy that also claims `victimOwner` as its owner. This is structurally identical to the Catalyst-Exchange finding: the deploy entrypoint lacks a "has this identity already been deployed" check before minting a new instance.

### Impact Explanation
A duplicate `CnStakingV4`/`PublicDelegation` proxy that reports the same `owner` as a legitimate validator's staking contract can be used to deceive delegators/stakers who resolve the "official" staking address off-chain (e.g., from a dApp, explorer, or documentation referencing the owner) into sending `delegate()` stake to the wrong, attacker-controlled-context proxy. Since staking/delegation moves KAIA value into the proxy (`cfg.Value`/`delegate()` in the genesis flow illustrates the value-transfer pattern used by every `deployCnStaking` caller) [5](#0-4) , misdirected delegations to a duplicate, non-canonical proxy constitute value movement/reward-eligibility confusion for an unprivileged public caller — matching the "unauthorized value movement" bar for this scan. It also tarnishes the reputation of the real validator/owner, exactly as described in the original report.

### Likelihood Explanation
Medium. Exploitation only requires a single public transaction calling `deployCnStaking(_owner)` (or `deployCnStakingWithPD`) with an already-used `_owner` address; no privileged role, governance approval, or validator status is required by the factory interface as exposed. The main uncertainty is whether the underlying Solidity source (not present in this indexed repo, only compiled bindings) contains an off-chain-invisible `require` that reverts on duplicate owners — this could not be confirmed from the available Go bindings and generated ABI, since the source-level guard logic is not indexed here.

### Recommendation
Add an on-chain mapping from `owner` (not just from deployed proxy address) to its `CnStakingV4`/`PublicDelegation` proxy in `CnStakingV4Factory`, and require `deployCnStaking`/`deployCnStakingWithPD` to revert if a proxy already exists for the given `_owner` (unless explicitly re-authorized by governance/registry). Expose a `getStakingContractByOwner(address)` view so downstream consumers (AddressBookV2, delegators, explorers) can authoritatively resolve the canonical proxy for a given owner instead of relying on off-chain sources.

### Proof of Concept
Conceptual PoC (Solidity source not available in this index to give exact bytecode-level PoC):
1. Validator `V` legitimately calls `factory.deployCnStaking(V)`, producing canonical proxy `P1` — mirrors the `deployCnStakingPerValidator` flow. [6](#0-5) 
2. Any unprivileged address `A` (attacker) then calls `factory.deployCnStaking(V)` again, passing the same owner `V`.
3. Because `deployCnStaking` takes `_owner` as a free parameter with no observed "owner already has a proxy" guard, a second proxy `P2` is created, also reporting `V` as `owner`. [1](#0-0) 
4. Delegators who are directed to `P2` (e.g., through phishing, a stale explorer link, or attacker-controlled front end) call `delegate()` and send KAIA into `P2` instead of the canonical `P1`, resulting in stake/value being sent to a duplicate, unofficial contract.

// deployCnStakingPerValidator deploys a CnStaking proxy per validator via Factory and
// stakes KAIA via delegate() (step 3).
// Switches cfg.Origin to each validator's manager so that Factory tracks the correct deployer.
func deployCnStakingPerValidator(cfg *runtime.Config, config *AllocPermissionlessConfig, result *allocPermissionlessResult) error {
	factoryABI, _ := cnstakingv4factory.CnStakingV4FactoryMetaData.GetAbi()
	cnStakingABI, _ := cnstakingv4.CnStakingV4MetaData.GetAbi()

	for i := range config.NodeIds {
		cfg.Origin = config.NodeInfos[i].Manager
		retData, err := evmCallABIReturn(cfg, result.factory, factoryABI, "deployCnStaking", config.NodeInfos[i].Manager)
		if err != nil {
			return fmt.Errorf("deployCnStaking[%d]: %w", i, err)
		}
		proxyAddr := common.BytesToAddress(retData[12:32])

		cfg.Value = config.StakeAmts[i]
		if err := evmCallABI(cfg, proxyAddr, cnStakingABI, "delegate"); err != nil {
			return fmt.Errorf("delegate[%d]: %w", i, err)
		}
		cfg.Value = new(big.Int)

		config.NodeInfos[i].StakingContract = proxyAddr
	}
	return nil
}
