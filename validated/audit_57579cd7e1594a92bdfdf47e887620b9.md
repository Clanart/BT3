### Title
`Scanner::scan_block` reports immature coinbase outputs as spendable `ReceivedOutput`s, enabling signing of invalid spends - ([File: networks/bitcoin/src/wallet/mod.rs])

### Summary
Analogous to consuming oracle data without a sequencer-uptime check, `Scanner::scan_block` consumes block data without checking a critical validity condition: coinbase maturity. It feeds `block.txdata[0]` (the coinbase) through `scan_transaction` like any other transaction, returning its outputs as ordinary spendable `ReceivedOutput`s. Coinbase outputs are unspendable for 100 blocks; `ReceivedOutput` carries no maturity/COINBASE flag, and `SignableTransaction::new` performs no maturity check either.

### Finding Description
`Scanner::scan_block` iterates over all of `block.txdata`, including the coinbase transaction:

```rust
pub fn scan_block(&self, block: &Block) -> Vec<ReceivedOutput> {
  let mut res = Vec::new();
  for tx in &block.txdata {
    res.extend(self.scan_transaction(tx));
  }
  res
}
``` [1](#0-0) 

Any coinbase output paying a registered script becomes a `ReceivedOutput` indistinguishable from a mature one: the struct stores only `offset`, `output`, and `outpoint` — no block height or coinbase marker. [2](#0-1)  `SignableTransaction::new` then builds and eventually signs a transaction spending whatever `ReceivedOutput`s it is given, checking only dust, fee, and weight — never maturity. [3](#0-2)  The only mitigation is a doc comment telling callers to post-filter or use `block.txdata[1 ..]`; nothing in the API enforces it, and once a `ReceivedOutput` is produced the information needed to detect immaturity (the containing transaction) has been discarded. [4](#0-3) 

### Impact Explanation
An unprivileged miner can pay a Serai-registered script in the coinbase transaction of a block (miners control coinbase outputs). A consumer of this library calling `scan_block` will report those funds as received and spendable. If such an output is passed to `SignableTransaction::new`, the threshold group produces a fully valid Schnorr signature over a transaction that Bitcoin consensus rejects (immature coinbase spend) — burning the signing round and, in a FROST setting, consuming a nonce session on an unattainable outcome. If the immature output is commingled with real inputs, the entire payment transaction is invalid, temporarily freezing all co-spent funds until maturity and leaking the intended payment graph.

### Likelihood Explanation
Requires a miner to direct a coinbase output at the scanned script and a downstream caller to use `scan_block` without manual filtering — plausible since the API name implies block-level scanning is safe. Effect is a denial of service on wallet operations and wasted signing rounds rather than theft; funds eventually become spendable after 100 confirmations. Medium/Low severity.

### Recommendation
Skip `block.txdata[0]` inside `scan_block`, or tag `ReceivedOutput` with a maturity flag/block height so `SignableTransaction::new` can reject immature inputs. Alternatively add an `is_mature(height)` accessor so the check is possible from the type itself, mirroring the sequencer-uptime guard pattern: validate external-state prerequisites at the point of consumption, not via documentation.

### Proof of Concept
```rust
// A miner crafts a block whose coinbase pays p2tr_script_buf(group_key).
let block: Block = rpc.get_block(...); // coinbase pays our script
let scanner = Scanner::new(key).unwrap();
let outputs = scanner.scan_block(&block); // includes the immature coinbase output
assert_eq!(outputs[0].outpoint(), &OutPoint::new(block.txdata[0].compute_txid(), 0));

// Funds are "received" — feeding them into SignableTransaction::new produces a
// transaction the network rejects as an immature coinbase spend:
let signable = SignableTransaction::new(outputs, &[(payment_script, 1000)], None, None, 2).unwrap();
// signable.multisig(&keys) signs successfully; broadcast fails consensus validation.
```
The library's own test demonstrates the coinbase output being returned by `scan_block`, relying on an out-of-band 100-block mining step for maturity rather than any check in the code. [5](#0-4)
