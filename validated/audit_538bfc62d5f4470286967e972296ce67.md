### Title
Invalid DKG share bypasses PoP verification and reveals the ECDH key for a copied encryption key - ([File: crypto/dkg/pedpop/src/lib.rs](crypto/dkg/pedpop/src/lib.rs))

### Summary
An unauthenticated-ordering bug in `KeyMachine::calculate_share` lets a DKG participant copy an honest message’s ephemeral encryption key, submit a malformed encrypted share under their own identity, and usually cause the victim to return a decryption proof before the copied key’s proof-of-possession is verified. [1](#0-0)  The published `EncryptionKeyProof` contains the ECDH shared point needed to decrypt the honest message that originally used the copied key. [2](#0-1) 

### Finding Description
`EncryptedMessage::read` accepts the attacker-controlled `key`, `pop`, and encrypted `msg` fields without authenticating them. [3](#0-2)  During share calculation, `Encryption::decrypt` computes `ecdh(enc_key, msg.key)`, decrypts the message, and constructs an `EncryptionKeyProof` containing that shared point. [4](#0-3)  Although the supplied Schnorr PoP is queued for batch verification, verification is deferred until after every supplied share has been decrypted and decoded. [5](#0-4) [6](#0-5) 

If the forged ciphertext decrypts to a non-canonical scalar, `calculate_share` immediately returns `PedPoPError::InvalidShare` with `blame: Some(blame)`, bypassing the queued PoP verification entirely. [7](#0-6)  The processor propagates that blame proof in `ProcessorMessage::InvalidShare`, making the leaked ECDH point available to other parties. [8](#0-7)  The code explicitly recognizes this copied-key blame attack class and relies on the per-message PoP to prevent it, but the early scalar-decoding error path bypasses that defense. [9](#0-8) 

### Impact Explanation
An attacker can copy the `key` field from an observed honest `EncryptedMessage` addressed to a victim and place it in a forged share whose ciphertext decrypts to a non-canonical scalar. [3](#0-2)  The victim calculates `victim_enc_key * copied_key`, which is the same ECDH shared point used by the honest message, and returns it inside a serialized `EncryptionKeyProof`. [10](#0-9) [11](#0-10)  Anyone holding the observed honest ciphertext can then derive the ChaCha20 stream and recover the plaintext secret share because `cipher` derives its stream key directly from that ECDH point. [12](#0-11) [13](#0-12) 

The disclosed plaintext is the DKG secret-share contribution sent by the honest sender to the accusing participant. [14](#0-13)  If the attacker obtains enough share contributions for a participant, they can reconstruct that participant’s resulting private key share. [15](#0-14) 

### Likelihood Explanation
The attacker only needs to supply an `EncryptedMessage` to `calculate_share`; no validator privileges, collusion, private-key material, or valid PoP for the copied ephemeral key is required. [16](#0-15)  A random forged ciphertext is sufficient because random bytes generally decode to a non-canonical field representation, triggering the early `from_repr` error before batch verification. [7](#0-6)  The attack can be repeated with fresh forged messages until the early error occurs. [1](#0-0) 

### Recommendation
Verify the encrypted message’s Schnorr PoP before decrypting, decoding, or returning an `EncryptionKeyProof` for it. [17](#0-16)  In particular, `Encryption::decrypt` should synchronously reject a message whose `pop` fails `pop_challenge`, or `calculate_share` should complete verification of all queued decryption PoPs before deserializing plaintext or emitting blame. [18](#0-17)  No decryption proof should be produced for a message that has not first been authenticated as originating from the accused participant and using its own ephemeral key. [9](#0-8) 

### Proof of Concept
The following protocol-level PoC assumes participant `A` has already sent victim `V` an honest `EncryptedMessage`, which the attacker observes and copies:

```rust
// Fields copied from an honest EncryptedMessage addressed to victim V.
let copied_key = honest_msg.key.clone();

// Arbitrary bytes selected by the attacker.
let forged_msg = EncryptedMessage::<C, SecretShare<C::F>> {
    key: copied_key,
    pop: syntactically_valid_schnorr_signature, // Invalid for this key/message/sender.
    msg: Zeroizing::new(SecretShare(random_bytes)),
};

// Victim calls:
//   calculate_share(&mut rng, map![attacker => forged_msg])
//
// Encryption::decrypt computes:
//   shared = victim_enc_key * copied_key
// and returns EncryptionKeyProof { key: shared, ... } before the invalid PoP
// is batch-verified.

// With high probability, decrypting random_bytes produces non-canonical field
// bytes, causing calculate_share to return:
//   PedPoPError::InvalidShare {
//     participant: attacker,
//     blame: Some(encryption_key_proof_for_shared),
//   }
```

The returned `EncryptionKeyProof` discloses the same ECDH point that decrypts the observed honest ciphertext. [2](#0-1)  Applying `cipher(context, proof.key)` to the honest message’s encrypted `msg` recovers its plaintext `SecretShare`. [19](#0-18) [13](#0-12)

      self.params.i(),

    let mut blames = HashMap::new();
    for (l, share_bytes) in shares.drain() {

      let share =

      );

      let (l, blame) = match id {
        BatchId::Decryption(l) => (l, None),
        BatchId::Share(l) => (l, Some(blames.remove(&l).unwrap())),
      };
