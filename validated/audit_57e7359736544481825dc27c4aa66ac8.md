**Reasoning:** `CommitIdentity.parseIdentity` in [1](#0-0)  only parses a git author/committer ident string (`NAME <EMAIL> DATE TZ`) into name, email, date, and timezone-offset fields for display purposes (avatars, commit message attribution, co-author lists). It is consumed in places like `app/src/lib/git/log.ts` and `app/src/models/commit.ts` purely to build commit metadata objects, and in UI components such as `app/src/ui/changes/commit-message.tsx` and `app/src/models/avatar.ts` for rendering author info.

This code has no involvement in determining which files are staged, discarded, or pushed — that logic lives entirely in the status/diff parsing paths (e.g., `git status --porcelain` parsing, diff parsing), which are separate from `CommitIdentity`. A malformed or crafted identity string here would at worst cause a thrown parse error (`Couldn't parse identity ...`) or a mis-displayed name/email/date, not a mismatch between what Desktop shows as the file set to commit/discard/push and what actually happens. The premise in the question — that this file's parsing controls "the file set Desktop shows as staged/discarded/pushed" — does not match what the code actually does, so the described invariant and exploit scenario are not applicable to this target.

  public static parseIdentity(identity: string): CommitIdentity {
    // See fmt_ident in ident.c:
    //  https://github.com/git/git/blob/3ef7618e6/ident.c#L346
    //
    // Format is "NAME <EMAIL> DATE"
    //  Markus Olsson <j.markus.olsson@gmail.com> 1475670580 +0200
    //
    // Note that `git var` will strip any < and > from the name and email, see:
    //  https://github.com/git/git/blob/3ef7618e6/ident.c#L396
    //
    // Note also that this expects a date formatted with the RAW option in git see:
    //  https://github.com/git/git/blob/35f6318d4/date.c#L191
    //
    const m = identity.match(/^(.*?) <(.*?)> (\d+) (\+|-)?(\d{2})(\d{2})/)
    if (!m) {
      throw new Error(`Couldn't parse identity ${identity}`)
    }

    const name = m[1]
    const email = m[2]
    // The date is specified as seconds from the epoch,
    // Date() expects milliseconds since the epoch.
    const date = new Date(parseInt(m[3], 10) * 1000)

    if (isNaN(date.valueOf())) {
      throw new Error(`Couldn't parse identity ${identity}, invalid date`)
    }

    // The RAW option never uses alphanumeric timezone identifiers and in my
    // testing I've never found it to omit the leading + for a positive offset
    // but the docs for strprintf seems to suggest it might on some systems so
    // we're playing it safe.
    const tzSign = m[4] === '-' ? '-' : '+'
    const tzHH = m[5]
    const tzmm = m[6]

    const tzMinutes = parseInt(tzHH, 10) * 60 + parseInt(tzmm, 10)
    const tzOffset = tzMinutes * (tzSign === '-' ? -1 : 1)

    return new CommitIdentity(name, email, date, tzOffset)
  }
