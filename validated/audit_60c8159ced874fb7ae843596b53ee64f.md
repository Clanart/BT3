### Title
`PedPoPError::InvalidShare` embeds the ECDH decryption key for the victim's secret share in an error DTO, leaking it via `Debug`/serialization - (File: crypto/dkg/pedpop/src/encryption.rs)

### Summary
Mirroring the Tolgee class (a publicly-exposed response object carrying secret fields), `KeyMachine::calculate_share` returns `PedPoPError::InvalidShare { blame: Option<EncryptionKeyProof<C>> }` to its caller whenever a remote participant sends a malformed share. The embedded `EncryptionKeyProof` contains `key: Zeroizing<C::G>` — the raw ECDH shared point which is the sole input to `cipher()` that decrypts that secret-share ciphertext. Both `PedPoPError` and `EncryptionKeyProof` derive `Debug`, and `EncryptionKeyProof::serialize()` is public, so the decryption key is emitted verbatim into error logs / upstream callers, turning an "invalid share" error into a disclosure of key-equivalent material for that message.

### Finding Description
In `crypto/dkg/pedpop/src/lib.rs` `KeyMachine::calculate_share` (lines 476–499), every incoming `EncryptedMessage` is decrypted via `Encryption::decrypt`, which also produces an `EncryptionKeyProof` whose `key` field is `ecdh::<C>(&self.enc_key, msg.key)` (`crypto/dkg/pedpop/src/encryption.rs:487-499`). On deserialization failure (`C::F::from_repr` returns `None`, attacker-controlled by sending non-canonical share bytes), the code returns `PedPoPError::InvalidShare { participant: l, blame: Some(blame.clone()) }` (line 480-482). `EncryptionKeyProof` is declared `#[derive(Clone, PartialEq, Eq, Debug, Zeroize)]` at `encryption.rs:260-264`, so its `key` — the ECDH shared point — is printed by `Debug` and written by `serialize()`/`write()` (`encryption.rs:267-280`). `cipher::<C>(context, &proof.key)` fully reconstructs the ChaCha20 stream that decrypts the message (`encryption.rs:101-133, 392`).

### Impact Explanation
An unprivileged DKG participant who submits a malformed secret share causes the victim to construct an error object containing the ECDH shared decryption key for that message. Whoever obtains the error (via `Debug` formatting in logs, error propagation, or `EncryptionKeyProof::serialize()`) and the corresponding `EncryptedMessage` ciphertext recovers the victim's secret-share plaintext (`Zeroizing<E>` after `apply_keystream`). That share is the sender's polynomial evaluated at the victim's index; collecting `t` such shares (or combining with compromised validators) exposes secret key material that the protocol's per-message-key design explicitly tried to compartmentalize (`encryption.rs:78-90` comments on avoiding exactly this kind of side-effect leakage). The blame proof is meant to be revealed deliberately through `BlameMachine::blame`, not to ride inside every routine error return/Debug print.

### Likelihood Explanation
Triggering the error path requires only that a DKG participant send share bytes that fail `C::F::from_repr` — trivially reachable with untrusted bytes fed to `EncryptedMessage::read` / `calculate_share`. Exploitation additionally requires access to the victim's error output (logs or a caller that forwards the error) plus the ciphertext; secret-share messages are transmitted on authenticated channels, narrowing the ciphertext-observer set. Hence Medium rather than Critical: real secret leakage, but conditioned on error handling/telemetry outside the crate.

### Recommendation
Do not place `EncryptionKeyProof` inside `PedPoPError::InvalidShare` on the automatic error path. Return only the faulty `Participant` from `calculate_share`, and have callers obtain blame material exclusively through `BlameMachine::blame`/`AdditionalBlameMachine::blame` where disclosure is an explicit decision. At minimum, implement a manual `fmt::Debug` for `EncryptionKeyProof` that uses `finish_non_exhaustive()` (matching the redacted `Debug` impls for `SecretShare`, `ThresholdCore`, `KeyMachine`, and `Encryption`) and remove `key` from the derived `Debug`, and gate `serialize()`/`write()` behind explicit blame workflows.

   C::F::from_repr fails at lib.rs:480 → Err(InvalidShare { participant: l,
   blame: Some(proof) }).
4. The error is logged/propagated; `{:?}` on PedPoPError prints proof.key, or the
   caller serializes it.
5. Observer with the EncryptedMessage ciphertext computes
   cipher(context, proof.key).apply_keystream(msg) → victim's share from l.
