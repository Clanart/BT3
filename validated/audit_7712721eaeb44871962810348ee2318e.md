### Title
Fee-on-transfer LP tokens cause over-minting of receipt tokens and protocol insolvency in `WombatStaking.depositLP` - (File: wombat/WombatStaking.sol)

### Summary
`WombatStaking.depositLP` trusts the caller-supplied `_lpAmount` parameter instead of measuring the LP token amount actually received by the contract, unlike the sibling `deposit` function which correctly measures the actual balance delta before minting receipt tokens.

### Finding Description
In `WombatStaking.deposit`, the contract measures the LP amount it actually received from the underlying Wombat pool before minting receipt tokens or forwarding stake to MasterWombat: [1](#0-0) 

However, `WombatStaking.depositLP` — which lets a `PoolHelper` transfer an existing LP token directly from a user into the contract — skips this check entirely. It transfers `_lpAmount` via `safeTransferFrom`, then unconditionally uses the caller-supplied `_lpAmount` (not the actual balance delta) both to stake into MasterWombat via `_toMasterWomAndSendReward` and to mint receipt tokens: [2](#0-1) 

If the `lpAddress` token registered for a pool ever deducts a transfer fee (or otherwise delivers less than `_lpAmount` to the contract, e.g. via rebasing/deflationary mechanics), the contract will:
1. Mint the full `_lpAmount` of receipt tokens to the depositor, even though fewer LP tokens were actually received.
2. Report/stake the full `_lpAmount` to MasterWombat accounting, inflating recorded stake beyond the LP tokens actually custodied.

This directly breaks the 1:1 backing invariant between minted receipt tokens (via `IMintableERC20(poolInfo.receiptToken).mint`) and the LP tokens actually held by `WombatStaking`, since `IPoolHelper` contracts (e.g. `WombatPoolHelper.depositLP`, `AnkrBNBPoolHelper.depositLP`) expose this path to any ordinary user without special privilege: [3](#0-2) 

Because withdrawal (`WombatStaking.withdraw`) burns receipt tokens and pays out the underlying deposit token based on recorded LP liquidity, an inflated receipt-token supply relative to actual LP custody means some depositors will be unable to withdraw their fair share — the pool becomes insolvent for the last withdrawers.

### Impact Explanation
If a fee-on-transfer/deflationary token is ever used as the `lpAddress`/`depositToken` for a registered Wombat pool, every `depositLP` call permanently and silently mints excess receipt tokens relative to the real LP balance held by `WombatStaking`. This constitutes a protocol insolvency condition — later users attempting to withdraw their legitimately deposited funds could find the contract short of LP tokens, resulting in reverted withdrawals or funds effectively frozen/lost for the remaining receipt-token holders.

### Likelihood Explanation
Likelihood depends entirely on whether a pool is registered (by the pool admin via `registerPool`) with an `lpAddress`/`depositToken` that has transfer fees or deflationary behavior. Wombat AMM LP tokens are not typically fee-on-transfer today, which limits real-world likelihood, but the contract provides no defense-in-depth and no validation against this token class — a single misconfigured/future pool registration silently introduces insolvency, and the inconsistency with the `deposit` function's careful before/after balance accounting shows this is an overlooked code path rather than an intentional design choice.

### Recommendation
Mirror the pattern already used in `deposit`: measure `IERC20(poolInfo.lpAddress).balanceOf(address(this))` before and after `safeTransferFrom` in `depositLP`, and use the actual delta (not the caller-supplied `_lpAmount`) for both `_toMasterWomAndSendReward` and `IMintableERC20(poolInfo.receiptToken).mint`.

### Proof of Concept
1. Admin registers a pool where `lpAddress` is a token with, e.g., a 1% transfer fee (or any token type where `balanceOf` delta on transfer differs from the transferred amount).
2. User calls `WombatPoolHelper.depositLP(1000)` → `WombatStaking.depositLP(lpAddress, 1000, user)`.
3. `safeTransferFrom(user, address(this), 1000)` actually delivers only 990 LP tokens to `WombatStaking` due to the fee.
4. `_toMasterWomAndSendReward(_lpAddress, 1000, true)` stakes/reports 1000 to MasterWombat, and `IMintableERC20(receiptToken).mint(msg.sender, 1000)` mints 1000 receipt tokens — 10 more than the LP tokens actually custodied.
5. Repeating this deposit accumulates a growing gap between receipt-token supply and real LP-token custody, until withdrawals for some users fail or drain funds meant for others.
