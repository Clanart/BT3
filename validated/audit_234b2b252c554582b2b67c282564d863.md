### Title
Unbounded recursive RLP decoding of nested `AccountKeyRoleBased` allows attacker-controlled stack overflow via a single `TxTypeAccountUpdate`/`TxTypeFeeDelegatedAccountUpdate` transaction - (File: blockchain/types/accountkey/account_key_role_based.go)

### Summary
`AccountKeyRoleBased.DecodeRLP` recursively decodes nested `AccountKey` values by re-invoking `rlp.DecodeBytes` on each sub-key blob, and if a sub-key's type is again `AccountKeyTypeRoleBased`, `AccountKeySerializer.DecodeRLP` re-enters `AccountKeyRoleBased.DecodeRLP`, recursing through the Go call stack with no depth limit. The composite-type rejection (`kerrors.ErrNestedCompositeType`) is only enforced *after* decoding completes, in `CheckInstallable`/`CheckUpdatable`. This mirrors the CosmWasm bug class described in the report: unbounded recursive decoding of attacker-controlled nested structures, performed before any validation/limits are applied, causing a stack overflow.

### Finding Description
`AccountKeyRoleBased.DecodeRLP` decodes the outer list as `[][]byte` and then, per element, calls `rlp.DecodeBytes(b, &serializer)`: [1](#0-0) 

`AccountKeySerializer.DecodeRLP` reads the key type, allocates the corresponding `AccountKey` instance via `NewAccountKey`, then calls `s.Decode(serializer.key)`, which dispatches back to that key's own `DecodeRLP`: [2](#0-1) 

If the encoded `keyType` is again `AccountKeyTypeRoleBased`, this calls back into `AccountKeyRoleBased.DecodeRLP`, which again decodes a nested `[][]byte` and recurses per-element into `AccountKeySerializer.DecodeRLP`. Each nesting level costs only a handful of RLP header bytes, so an attacker can encode extremely deep nesting (tens of thousands of levels) with a moderate payload size, well within the byte-size budget available in a transaction `Key` field.

The only defense against nested `AccountKeyRoleBased` keys, `IsCompositeType`/`ErrNestedCompositeType`, is applied only *after* the whole structure is fully decoded, inside `CheckInstallable`: [3](#0-2) 
and `CheckUpdatable`: [4](#0-3) 
i.e., recursion happens unconditionally during RLP decode, and the nested-type rejection only prevents the resulting (already fully materialized) key from being *installed/updated* — it does not bound the decode-time recursion depth. `TestAccountUpdateRoleBasedKeyNested` confirms `ErrNestedCompositeType` is only surfaced from `txpool.AddRemote` and block execution — i.e. after the transaction and its `Key` field have already been RLP-decoded: [5](#0-4) 

The transaction's account-update `Key` field is itself just an opaque byte blob at the outer transaction encoding level (`txInternalDataAccountUpdateSerializable.Key []byte`): [6](#0-5) 
and that byte blob is subsequently decoded through the `AccountKeySerializer`/`AccountKeyRoleBased` recursive path described above, meaning any node that decodes the transaction's account key (mempool ingestion, RPC decode, or block execution) will recurse to the attacker-chosen depth before any composite-type check runs.

Additionally, `KaiaAPI.DecodeAccountKey`, a public RPC method, independently triggers the same unbounded recursive decode on arbitrary attacker-supplied bytes without any pre-decode depth limiting: [7](#0-6) 

Go's runtime panics with a fatal, unrecoverable "stack overflow" error (not a normal `panic`/`recover`-able error) once a goroutine's stack exceeds the runtime's maximum stack size, crashing the entire node process — this cannot be caught by any `defer/recover` in the transaction-processing pipeline.

### Impact Explanation
Any single unprivileged transaction (or public JSON-RPC call to `kaia_decodeAccountKey`) containing a deeply nested `AccountKeyRoleBased` blob can crash any full/consensus node that attempts to decode it: mempool ingestion (`txpool.AddRemote`), full-block validation on all nodes, or public RPC servers exposing `DecodeAccountKey`. Because the crash is a fatal Go runtime stack overflow (not a recoverable error), it terminates the entire process, not just the goroutine handling the request — resulting in denial of service across the network as the malicious transaction propagates to peers and is decoded by each of them.

### Likelihood Explanation
The attack requires only crafting one RLP-encoded `AccountKeyRoleBased` value with many levels of self-nesting and submitting it as the `Key` field of an ordinary `TxTypeAccountUpdate`/`TxTypeFeeDelegatedAccountUpdate` transaction, or supplying it directly to the public `kaia_decodeAccountKey` RPC endpoint. No special privileges, signatures beyond a normal account key, or state assumptions are needed — the recursive decode occurs unconditionally before signature/authorization or composite-type checks run. This is straightforward to construct and reach.

### Recommendation
Enforce a maximum recursion/nesting depth check before or during `AccountKeyRoleBased.DecodeRLP` (and generally in `AccountKeySerializer.DecodeRLP`), rejecting any key whose keyType is `AccountKeyTypeRoleBased` when already inside a nested decode context, instead of only checking `IsCompositeType`/`ErrNestedCompositeType` after full decoding completes. Alternatively, add an explicit depth counter threaded through `DecodeRLP` (or use a bounded iterative decode) that aborts decoding once a small depth limit (e.g., 1) is exceeded, matching the "no nested RoleBasedKey" invariant already intended by the codebase.

### Proof of Concept
Conceptually:
1. Build a minimal `AccountKeyLegacy`/`AccountKeyPublic` leaf key blob `L`.
2. Wrap it as `RoleBased_0 = RLP([ RLP([keyType=RoleBased, RLP([L])]) ])` — an `AccountKeyRoleBased` whose only role slot is itself an `AccountKeyRoleBased`.
3. Repeat step 2 N times (`RoleBased_i = RLP([ RLP([keyType=RoleBased, RLP([RoleBased_(i-1)])]) ])`), each iteration adding only a few bytes of RLP overhead, to reach N in the tens of thousands with a payload of a few hundred KB (within typical tx data / RPC payload limits).
4. Submit `RoleBased_N` either as: (a) the `Key` field of a `TxTypeAccountUpdate` transaction sent via `eth_sendRawTransaction`/`txpool.AddRemote`, or (b) directly as the argument to the `kaia_decodeAccountKey` RPC call (`api/api_kaia.go:DecodeAccountKey`).
5. Decoding recurses through `AccountKeySerializer.DecodeRLP` → `AccountKeyRoleBased.DecodeRLP` → ... N times before any `CheckInstallable`/`CheckUpdatable`/`ErrNestedCompositeType` check is reached, exhausting the goroutine's stack and triggering a fatal, unrecoverable Go runtime stack-overflow crash on the node.

func (a *AccountKeyRoleBased) DecodeRLP(s *rlp.Stream) error {
	enc := [][]byte{}
	if err := s.Decode(&enc); err != nil {
		return err
	}

	keys := make([]AccountKey, len(enc))
	for i, b := range enc {
		serializer := NewAccountKeySerializer()
		if err := rlp.DecodeBytes(b, &serializer); err != nil {
			return err
		}
		keys[i] = serializer.key
	}

	*a = (AccountKeyRoleBased)(keys)

	return nil
}

func (a *AccountKeyRoleBased) CheckInstallable(currentBlockNumber uint64) error {
	// A zero-role key is not allowed.
	if len(*a) == 0 {
		return kerrors.ErrZeroLength
	}
	// Do not allow undefined roles.
	if len(*a) > (int)(RoleLast) {
		return kerrors.ErrLengthTooLong
	}
	for i := 0; i < len(*a); i++ {
		// A composite key is not allowed.
		if (*a)[i].IsCompositeType() {
			return kerrors.ErrNestedCompositeType
		}
		// If any key in the role cannot be initialized, return an error.
		if err := (*a)[i].CheckInstallable(currentBlockNumber); err != nil {
			return err
		}
	}
	return nil
}

func (a *AccountKeyRoleBased) CheckUpdatable(newKey AccountKey, currentBlockNumber uint64) error {
	if newKey, ok := newKey.(*AccountKeyRoleBased); ok {
		lenOldKey := len(*a)
		lenNewKey := len(*newKey)
		// If no key is to be replaced, it is regarded as a fail.
		if lenNewKey == 0 {
			return kerrors.ErrZeroLength
		}
		// Do not allow undefined roles.
		if lenNewKey > (int)(RoleLast) {
			return kerrors.ErrLengthTooLong
		}
		for i := range lenNewKey {
			switch {
			// A composite key is not allowed.
			case (*newKey)[i].IsCompositeType():
				return kerrors.ErrNestedCompositeType
			// If newKey is longer than oldKey, init the new attributes.
			case i >= lenOldKey:
				if err := (*newKey)[i].CheckInstallable(currentBlockNumber); err != nil {
					return err
				}
			// Do nothing for AccountKeyTypeNil
			case (*newKey)[i].Type() == AccountKeyTypeNil:

			// Check whether the newKey is replacable or not
			default:
				if err := CheckReplacable((*a)[i], (*newKey)[i], currentBlockNumber); err != nil {
					return err
				}
			}
		}
		return nil
	}
	// Update is not possible if the type is different.
	return kerrors.ErrDifferentAccountKeyType
}

func (serializer *AccountKeySerializer) DecodeRLP(s *rlp.Stream) error {
	if err := s.Decode(&serializer.keyType); err != nil {
		return err
	}

	var err error
	serializer.key, err = NewAccountKey(serializer.keyType)
	if err != nil {
		return err
	}

	return s.Decode(serializer.key)
}
