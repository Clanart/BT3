## Analog Found

### Title
Out-of-bounds buffer read in CLVM canonical-encoding parser via crafted atom length prefix - (File: `chia/full_node/mempool_manager.py`)

### Summary
The CVE describes a stack-based buffer overflow in `asn1_find_node()` caused by the parser trusting an encoded structure's internal length/offset fields without validating them against the actual buffer boundaries, allowing a crafted file to drive the parser past the end of its backing buffer. The same bug class — a hand-rolled byte-offset walker that advances `offset` based on values *decoded from the untrusted buffer itself* without checking those values against the remaining buffer length — exists in `is_atom_canonical()` / `is_clvm_canonical()` in `chia/full_node/mempool_manager.py`, which parses attacker-supplied `puzzle_reveal` and `solution` bytes from every submitted spend bundle.

### Finding Description
`is_atom_canonical()` decodes a variable-length atom-size prefix (1–6 bytes) directly from `clvm_buffer` and then reads `prefix_len` additional bytes to build `atom_len`, indexing `clvm_buffer[offset]` in a loop with no check that `offset` stays within `len(clvm_buffer)`: [1](#0-0) 

`is_clvm_canonical()` then trusts the returned `atom_len` and advances its own `offset` by that amount without validating that `offset + atom_len <= len(clvm_buffer)`, then loops back and re-indexes `clvm_buffer[offset]`: [2](#0-1) 

Both functions are invoked unconditionally, on fully attacker-controlled bytes, inside `MempoolManager.validate_spend_bundle()` for every coin spend in every incoming spend bundle, to decide `ELIGIBLE_FOR_DEDUP` status: [3](#0-2) 

A spend bundle whose `puzzle_reveal` or `solution` ends with a truncated atom-length header (e.g., a byte indicating a 4-byte length prefix with fewer than 4 trailing bytes actually present, or an atom whose encoded length exceeds the remaining buffer) causes `clvm_buffer[offset]` to be indexed past the end of the buffer. In Python this raises an uncaught `IndexError` rather than corrupting memory, but the underlying root cause — an offset-walking parser that trusts self-declared length fields from untrusted input instead of bounds-checking against the real buffer size — is the exact bug class described in the report (`asn1_find_node()`'s unchecked node/offset traversal).

### Impact Explanation
`validate_spend_bundle()` runs synchronously in the mempool admission path for every submitted spend bundle, and the `is_clvm_canonical()` calls at lines 723–726 are not wrapped in a try/except at that call site. An unprivileged party who submits a spend bundle (via full-node RPC, wallet, or peer gossip that reaches `add_spend_bundle`) with a crafted truncated/oversized atom-length prefix in `puzzle_reveal` or `solution` can trigger an unhandled `IndexError` during mempool admission for that spend bundle, i.e. a spend-triggered transaction-processing halt for that request path. This matches the "spend-triggered transaction-processing halt" impact category.

### Likelihood Explanation
Reachability is high: any unprivileged spend-bundle submitter can control the exact bytes of `puzzle_reveal` and `solution`. The check runs on every coin spend of every bundle entering `validate_spend_bundle()`, with no upstream length/format validation that would reject a truncated atom header before it reaches this code (CLVM deserialization itself may accept many malformed-but-parseable byte layouts, and this function operates on the raw serialized bytes rather than a fully-parsed tree). No special privileges, timing, or race conditions are required — a single, deterministic malformed spend bundle is sufficient to reach the vulnerable indexing.

### Recommendation
In `is_atom_canonical()`, bound-check each prefix byte read against `len(clvm_buffer)` before indexing, and validate that the decoded `atom_len` does not cause `offset + atom_len` to exceed `len(clvm_buffer)`. In `is_clvm_canonical()`, check `offset < len(clvm_buffer)` before every `clvm_buffer[offset]` access and treat any out-of-range condition as "not canonical" (return `False`) rather than letting an exception propagate. Additionally, ensure the call site in `validate_spend_bundle()` (or a shared wrapper) converts any unexpected exception from canonical-encoding checks into a proper `Err`/`ValidationError` rather than allowing it to escape uncaught.

def is_atom_canonical(clvm_buffer: bytes, offset: int) -> tuple[int, bool]:
    b = clvm_buffer[offset]
    if (b & 0b11000000) == 0b10000000:
        # 6 bits length prefix
        mask = 0b00111111
        prefix_len = 0
        min_value = 1
    elif (b & 0b11100000) == 0b11000000:
        # 5 + 8 bits length prefix
        mask = 0b00011111
        prefix_len = 1
        min_value = 1 << 6
    elif (b & 0b11110000) == 0b11100000:
        # 4 + 8 + 8 bits length prefix
        mask = 0b00001111
        prefix_len = 2
        min_value = 1 << (5 + 8)
    elif (b & 0b11111000) == 0b11110000:
        # 3 + 8 + 8 + 8 bits length prefix
        mask = 0b00000111
        prefix_len = 3
        min_value = 1 << (4 + 8 + 8)
    elif (b & 0b11111100) == 0b11111000:
        # 2 + 8 + 8 + 8 + 8 bits length prefix
        mask = 0b00000011
        prefix_len = 4
        min_value = 1 << (3 + 8 + 8 + 8)
    elif (b & 0b11111110) == 0b11111100:
        # 1 + 8 + 8 + 8 + 8 + 8 bits length prefix
        mask = 0b00000001
        prefix_len = 5
        min_value = 1 << (2 + 8 + 8 + 8 + 8)

    atom_len = b & mask
    for i in range(prefix_len):
        atom_len <<= 8
        offset += 1
        atom_len |= clvm_buffer[offset]

    return 1 + prefix_len + atom_len, atom_len >= min_value


def is_clvm_canonical(clvm_buffer: bytes) -> bool:
    """
    checks whether the CLVM serialization is all canonical representation.
    atoms can be serialized in more than one way by using more bytes than
    necessary to encode the length prefix. This functions ensures that all atoms are
    encoded with the shortest representation. back-references are not allowed
    and will make this function return false
    """
    assert clvm_buffer != b""

    offset = 0
    tokens_left = 1
    while True:
        b = clvm_buffer[offset]

        # pair
        if b == 0xFF:
            tokens_left += 1
            offset += 1
            continue

        # back references cannot be considered canonical, since they may be
        # encoded in many different ways
        if b == 0xFE:
            return False

        # small atom or NIL
        if b <= 0x80:
            tokens_left -= 1
            offset += 1
        else:
            atom_len, canonical = is_atom_canonical(clvm_buffer, offset)
            if not canonical:
                return False
            tokens_left -= 1
            offset += atom_len

        if tokens_left == 0:
            break

    # if there's garbage at the end, it's not canonical
    return offset == len(clvm_buffer)
