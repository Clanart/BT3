## Finding

### Title
Loose hostname pattern in `isGitHubHost()` lets attacker-controlled hosts be misidentified as GitHub, weakening credential/cert-trust decisions - (File: `app/src/lib/api.ts`)

### Summary
The report's bug class is a conditional trust/integrity check that is defined by an incomplete predicate (a role variant that isn't covered), letting attacker-controlled state slip past validation without the developer's knowledge. The closest real analog in this Desktop codebase is `isGitHubHost()` in `app/src/lib/api.ts`, whose "is this a GitHub host" predicate is a loose regex rather than a strict allow-list, so a fully attacker-controlled hostname can be classified as a trusted GitHub endpoint.

### Finding Description
`isGitHubHost()` is meant to answer "does this URL belong to a GitHub host" and is consumed by the git credential helper, `app/src/lib/trampoline/trampoline-credential-helper.ts`, which decides whether to hand out stored account credentials/tokens for a given remote host during git network operations. [1](#0-0) 

After failing the strict `isDotCom`/`isGHE` checks and the known-third-party-host list, the function falls back to:

```
// github.example.com,
if (/(^|\.)(github)\./.test(hostname)) {
  return true
}
```

This regex only requires the literal substring `github.` to be preceded by either the start of the hostname or a dot. It is not anchored to a specific registrable domain, so any hostname that merely *starts with* `github.` — e.g. `github.attacker-domain.com`, a domain fully controlled by an attacker who registers it — satisfies `(^|\.)(github)\.` and causes `isGitHubHost()` to return `true`, exactly like a real `github.example.com` GitHub Enterprise instance would.

Just as the original report's `check_autorization_policy` treated one role (`PERMISSION_LEVEL_FUND_MANAGER`) as the complete set requiring integrity checks and silently skipped an equally-privileged role (`PERMISSION_LEVEL_ALL`), this function treats "hostname textually starts with `github.`" as equivalent to "hostname belongs to GitHub," without validating the actual registrable domain/owner of that host — the intended invariant (only real GitHub/GHE domains are trusted) is only partially enforced.

### Impact Explanation
If `isGitHubHost()`'s result is used by the trampoline credential helper (`app/src/lib/trampoline/trampoline-credential-helper.ts`, which also imports the same suppression/host-check helpers) to decide it is safe to answer a `git credential fill` request with the user's GitHub token/credentials for that host, an attacker who controls a remote (e.g., a malicious `git@github.attacker.com` clone URL, a submodule URL, or an LFS endpoint pointed at such a domain) could get Desktop to treat their server as a GitHub endpoint and leak the user's stored OAuth token/credentials to it. The same misclassification also feeds `suppressCertificateErrorFor`, which is used to avoid showing certificate warnings for legitimate GHE self-signed setups — a false positive here means TLS certificate errors could be silently suppressed for an attacker's own host as well. [2](#0-1) 

### Likelihood Explanation
The attacker precondition matches the allowed threat model exactly: they control a git remote/repo URL (via clone URL, submodule, or LFS server reference) that a victim adds or fetches from — no local access, no admin rights, no leaked credentials required. Registering a domain of the form `github.<anything>` is trivial and entirely within attacker control.

### Recommendation
Replace the loose prefix/substring regex with a strict registrable-domain check (e.g., verify the hostname's eTLD+1 exactly equals a known GitHub Enterprise domain, or require confirmation via the authenticated `/meta` probe already implemented later in the function for genuinely unknown hosts) rather than trusting `(^|\.)(github)\.` as a stand-in for "is a GitHub host." Do not let a soft heuristic gate credential disclosure or certificate-error suppression; require the stronger `x-github-request-id` probe (already present) for any host that isn't on the explicit dotcom/GHE allow-list.

### Proof of Concept
1. Attacker registers `github.attacker-domain.com` and hosts a git server there (or simply an HTTPS endpoint responding to `HEAD /meta`).
2. Attacker sends the victim a clone URL / adds it as a submodule / LFS remote: `https://github.attacker-domain.com/foo/bar.git`.
3. When Desktop performs a git network operation against this remote, the trampoline credential helper's host classification calls `isGitHubHost('https://github.attacker-domain.com/...')`.
4. `hostname = 'github.attacker-domain.com'` fails the `isDotCom`/`isGHE` and known-third-party checks, but matches `/(^|\.)(github)\./` since it starts with `github.` — the function returns `true` without ever confirming domain ownership.
5. Depending on how the credential helper consumes this result, Desktop may treat the attacker's host as a legitimate GitHub endpoint for credential-fill or certificate-error-suppression purposes.

**Caveat:** I confirmed `isGitHubHost()`'s flawed matching logic and that it is imported/used in `app/src/lib/trampoline/trampoline-credential-helper.ts`, but I was not able to view the exact lines in that file that consume the boolean result before this session ended; the concrete downstream action (credential fill vs. some other gating) should be verified in that file to confirm severity before treating this as fully proven.

```typescript
/**
 * Attempts to determine whether or not the url belongs to a GitHub host.
 *
 * This is a best-effort attempt and may return `undefined` if encountering
 * an error making the discovery request
 */
export async function isGitHubHost(url: string) {
  const { hostname } = new window.URL(url)

  const endpoint =
    hostname === 'github.com' || hostname === 'api.github.com'
      ? getDotComAPIEndpoint()
      : getEnterpriseAPIURL(url)

  if (isDotCom(endpoint) || isGHE(endpoint)) {
    return true
  }

  if (isKnownThirdPartyHost(hostname)) {
    return false
  }

  // github.example.com,
  if (/(^|\.)(github)\./.test(hostname)) {
    return true
  }
```
