## Title
DataLayer mirror URLs are attacker-controlled and automatically fetched by any subscribing node, enabling Server-Side Request Forgery (SSRF) - (File: `chia/data_layer/data_layer.py`, `chia/data_layer/download_data.py`, `chia/wallet/db_wallet/db_wallet_puzzles.py`)

### Summary
Chia's DataLayer mirror mechanism lets any coin owner attach an arbitrary list of URL strings ("mirrors") to a DataLayer store by spending a coin to the `MIRROR_PUZZLE_HASH` puzzle hash with the store's `launcher_id` and URL memos [1](#0-0) . Any node that subscribes to that store (a normal, expected DataLayer client operation) will automatically read those on-chain mirror URLs via wallet RPC and issue outbound HTTP GET/POST requests to them without any validation of scheme, host, or target address, matching the "deprecated service creating an SSRF risk" bug class in the reported advisory.

### Finding Description
`DataLayer.update_subscriptions_from_wallet()` pulls mirror URLs for a store directly from wallet RPC (`dl_get_mirrors`) and stores them for later use with no filtering [2](#0-1) . These URLs originate from on-chain mirror coins created via `create_mirror_puzzle()`/`MIRROR_PUZZLE_HASH`, whose only content check is that a `CREATE_COIN` condition target that puzzle hash and carries a `launcher_id` + URL memo list — there is no restriction that the mirror creator must own or control the target store, and no validation of the URL contents (scheme, host, IP range) [1](#0-0) .

During normal sync, `DataLayer.fetch_and_validate()` selects one of these server URLs and calls `insert_from_delta_file()` → `download_file()` [3](#0-2) [4](#0-3) . `download_file()` performs a raw `http_download` (or POST to a plugin) against the attacker-chosen URL string with no allow-list, no SSRF protections (no blocking of `localhost`, link-local/metadata addresses such as `169.254.169.254`, private RFC1918 ranges, or non-http(s) schemes), and no restriction that it be a public/well-known DataLayer host [4](#0-3) . `DataLayer.get_downloader()` similarly POSTs unauthenticated JSON payloads (including the mirror URL) to configured downloader plugin URLs [5](#0-4) .

Because subscribing to a store (an ordinary Data Layer client action, e.g., via `subscribe` RPC as exercised in tests [6](#0-5) ) causes the node's background `periodically_manage_data()` loop to automatically call `update_subscription()` → `fetch_and_validate()` for every subscribed store, an attacker who creates a store and publishes malicious mirror URLs (e.g., pointing at internal infrastructure, cloud metadata endpoints, or other local services on the victim's network) can force any node that later subscribes to (or is auto-subscribed to) that store to issue outbound requests to those internal targets — classic SSRF, achieved purely by publishing on-chain mirror coins, no privileged/network-layer access required.

### Impact Explanation
This is reachable by an ordinary Data Layer client: any user can create a store, add mirror coins with arbitrary URLs (e.g., `http://169.254.169.254/latest/meta-data/`, `http://internal-admin:8080/...`, or a local RPC/plugin endpoint), and wait for other nodes to subscribe. Because mirror discovery/sync is designed to be automatic and periodic, no active social engineering step beyond getting a victim to subscribe (which is the entire intended use case of DataLayer sharing) is needed. This can be used to probe/attack internal network services reachable only from the victim's host, exfiltrate data from internal endpoints via response leakage in logs, or pivot into cloud metadata services to steal credentials — a Critical-class SSRF impact analogous to the GitLab CVE-2020-10077 report.

### Likelihood Explanation
High. Creating a mirror coin only requires a standard spend bundle with a `CREATE_COIN` output to `MIRROR_PUZZLE_HASH` carrying a `launcher_id` and URL memos — no special privileges, and this is exactly the mechanism `add_mirror`/`dl_new_mirror` exposes through the wallet RPC [7](#0-6) . The victim path (subscribe → periodic sync → fetch_and_validate → download_file) is the normal operational flow of DataLayer, not an edge case.

### Recommendation
Validate and restrict mirror/downloader/plugin URLs before making outbound requests in `download_file()`, `get_downloader()`, and anywhere URLs are consumed from `dl_get_mirrors`/`update_subscriptions_from_wallet()`: enforce `http(s)` scheme only, resolve and reject requests to loopback, link-local, private, and cloud-metadata address ranges, and consider requiring operator opt-in/allow-listing of mirror hosts rather than blind automatic fetch from on-chain-published URLs.

### Proof of Concept
1. Attacker creates a DataLayer store (`create_data_store`) and obtains `store_id`/`launcher_id`.
2. Attacker calls `add_mirror(store_id, urls=["http://169.254.169.254/latest/meta-data/iam/security-credentials/"], amount, fee)`, which spends a coin to `MIRROR_PUZZLE_HASH` with the malicious URL as memo [7](#0-6) [8](#0-7) .
3. Victim node subscribes to `store_id` (a routine DataLayer client action) via the `subscribe` RPC, as shown in test helpers [6](#0-5) .
4. Victim's periodic sync loop calls `update_subscriptions_from_wallet()` (pulling the attacker's URL) then `fetch_and_validate()` → `insert_from_delta_file()` → `download_file()`, which issues an outbound HTTP request from the victim's process to the attacker-chosen internal/metadata address with no restriction [2](#0-1) [4](#0-3) .

```python
def create_mirror_puzzle() -> Program:
    return P2_PARENT.curry(Program.to(1))


MIRROR_PUZZLE_HASH = create_mirror_puzzle().get_tree_hash()


def get_mirror_info(
    parent_puzzle: Program | SerializedProgram, parent_solution: Program | SerializedProgram
) -> tuple[bytes32, list[bytes]]:
    assert type(parent_puzzle) is type(parent_solution)
    _, conditions = run_with_cost(parent_puzzle, INFINITE_COST, parent_solution)
    for condition in conditions.as_iter():
        if (
            condition.first().as_python() == ConditionOpcode.CREATE_COIN
            and condition.at("rf").as_python() == create_mirror_puzzle().get_tree_hash()
        ):
            memos: list[bytes] = condition.at("rrrf").as_python()
            launcher_id = bytes32(memos[0])
            return launcher_id, [url for url in memos[1:]]
    raise ValueError("The provided puzzle and solution do not create a mirror coin")
```

```python
    async def get_downloader(self, store_id: bytes32, url: str) -> PluginRemote | None:
        request_json = {"store_id": store_id.hex(), "url": url}
        for d in self.downloaders:
            async with aiohttp.ClientSession() as session:
                try:
                    async with session.post(
                        d.url + "/handle_download",
                        json=request_json,
                        headers=d.headers,
                        timeout=self.client_timeout,
                    ) as response:
                        res_json = await response.json()
                        if res_json["handle_download"]:
                            return d
                except Exception as e:
                    self.log.error(f"get_downloader could not get response: {type(e).__name__}: {e}")
        return None
```

```python
async def download_file(
    data_store: DataStore,
    target_filename_path: Path,
    store_id: bytes32,
    root_hash: bytes32,
    generation: int,
    server_info: ServerInfo,
    proxy_url: str | None,
    downloader: PluginRemote | None,
    timeout: aiohttp.ClientTimeout,
    client_foldername: Path,
    timestamp: int,
    log: logging.Logger,
    grouped_by_store: bool,
    group_downloaded_files_by_store: bool,
    max_delta_file_size: int,
) -> bool:
    if target_filename_path.exists():
        return True
    filename = get_delta_filename(store_id, root_hash, generation, grouped_by_store)

    if downloader is None:
        # use http downloader - this raises on any error
        try:
            await http_download(
                target_filename_path, filename, proxy_url, server_info, timeout, log, max_delta_file_size
            )
        except (asyncio.TimeoutError, aiohttp.ClientError, MaxDeltaFileSizeExceededError):
            new_server_info = await data_store.server_misses_file(store_id, server_info, timestamp)
            log.info(
                f"Failed to download {filename} from {new_server_info.url}."
                f"Miss {new_server_info.num_consecutive_failures}."
            )
            log.info(f"Next attempt from {new_server_info.url} in {new_server_info.ignore_till - timestamp}s.")
            return False
        return True
```
