### Title
Payout tx OP_RETURN operator attribution is unauthenticated, allowing anyone with the public withdrawer signature to mis-credit reimbursement to an arbitrary operator - (File: core/src/builder/transaction/operator_reimburse.rs)

### Summary
`create_payout_txhandler()` signs the Payout transaction's input and output 0 with `SIGHASH_SINGLE|ANYONECANPAY`, leaving the anchor and the OP_RETURN output (which encodes `operator_xonly_pk`, the party credited with fronting the withdrawal) completely outside the signed message. Because the withdrawer's signature, input outpoint, and output parameters are all published on Citrea when `withdraw()`/`safeWithdraw()` is called, any unprivileged party can independently assemble and broadcast a valid Payout transaction with an arbitrary `operator_xonly_pk` in the OP_RETURN, and neither `storage_proof.rs::verify_storage_proofs` nor `verifier.rs::update_finalized_payouts` validate that the credited operator is the party that actually built or funded the transaction.

### Finding Description
The broken binding is:
`operator_xonly_pk parsed from Payout-tx OP_RETURN (verifier.rs::update_finalized_payouts, L2319-2321)` **should equal** `the xonly-pk of the party that actually funded/broadcast the confirmed Payout transaction`.

Trace:
1. `create_payout_txhandler()` (`core/src/builder/transaction/operator_reimburse.rs:407-436`) builds an input spent via `SpendPath::KeySpend` using only `user_sig`, plus an unsigned-by-that-sig output0, anchor, and `op_return_txout(operator_xonly_pk)` at index 2. `txhandler.set_p2tr_key_spend_witness(&user_sig, 0)` only supplies the witness for input 0 — the sighash committed by `SinglePlusAnyoneCanPay` covers only input 0 and output 0 (per BIP341), never the anchor or the OP_RETURN.
2. `WithdrawParams` (`core/src/rpc/clementine.proto:239-253`) — `input_signature`, `input_outpoint`, `output_script_pubkey`, `output_amount` — is exactly what is committed on Citrea via the bridge contract `withdraw()`/`safeWithdraw()` call, i.e. public calldata readable by anyone once a withdrawal is initiated.
3. `operator_xonly_pk` is **not** part of `WithdrawParams` at all; it is always injected as `self.signer.xonly_public_key` in `Operator::withdraw()` (`core/src/operator.rs:620-626`). This means the field is fully attacker-controllable outside of Clementine's own gRPC surface: an attacker does not need to call any Clementine RPC — they only need `user_sig`, `input_outpoint`, and `output_script_pubkey/amount` (all public via Citrea calldata) to call `create_payout_txhandler()` themselves (or hand-assemble the same transaction) with any xonly-pk of their choosing in the OP_RETURN, then broadcast it directly to the Bitcoin network, bypassing `aggregator_verification_address` checks and `only_aggregator_and_self` gating entirely (those only protect Clementine's own RPC endpoints, not raw Bitcoin broadcast).
4. `circuits-lib/src/bridge_circuit/storage_proof.rs::verify_storage_proofs()` (L44-133) only verifies the withdrawal outpoint/vout storage proof (`user_wd_outpoint`, `vout`) against Citrea's state root; it never touches the OP_RETURN.
5. `verifier.rs::update_finalized_payouts()` (L2283-2352) is the sole place that determines "who fronted this withdrawal": it takes whichever transaction is found on-chain spending the tracked withdrawal outpoint, and blindly parses `operator_xonly_pk` from its first OP_RETURN (L2311-2321), with zero cryptographic link to who actually constructed/funded/broadcast that transaction.
6. This DB record is then trusted unconditionally by `task/payout_checker.rs::PayoutCheckerTask` (which looks up `get_first_unhandled_payout_by_operator_xonly_pk(self.operator.signer.xonly_public_key)` and automatically drives `handle_finalized_payout`→kickoff→reimbursement for any payout attributed to that pubkey) and by `verifier.rs::is_kickoff_malicious()` (L1859-1915), which only checks that the *DB-recorded* OP_RETURN pubkey equals the kickoff's `operator_xonly_pk` — it never checks that the real fronting party matches.

Because a UTXO can only be spent once, the attacker cannot "prove both work" in a single confirmed chain — but they don't need to: they only need their maliciously-labeled transaction to be the one that gets mined (a normal fee/first-seen race, since only output 0 is fixed by the signature and everything else, including fee-bumping inputs, is free to add). Once mined, `update_finalized_payouts` records the attacker-chosen `operator_xonly_pk`, permanently and irreversibly (the UTXO is spent, so the honest operator's version of the same payout tx can never confirm), and any operator (`X`) whose pubkey the attacker placed in the OP_RETURN will be auto-credited and auto-reimbursed via their own legitimately presigned kickoff/round/reimburse chain, even though `X` never funded or built that transaction. Conversely, the honest operator that actually intended to front the withdrawal permanently loses the ability to be reimbursed, and if it later submits a kickoff anyway, `is_kickoff_malicious` will flag it as malicious (DB pubkey ≠ its own), risking collateral loss via the challenge/disprove flow.

None of the audit's listed guards close this gap: `SECP.verify_schnorr` only checks the signature is valid for input0/output0 (not that OP_RETURN matches the signer); `is_profitable`/`only_aggregator_and_self`/`aggregator_verification_address` only gate Clementine's own RPC, not raw broadcast; `is_kickoff_malicious`, `verify_storage_proofs`, `SPV::verify`, `lc_proof_verifier`, and `total_work_and_watchtower_flags` never inspect who funded the tx versus who is named in OP_RETURN; the presigned transaction graph only prevents an outsider from *personally* claiming a reimbursement (they lack operator keys), but does not stop them from *mis-attributing* a real operator's key.

### Impact Explanation
- An operator can be reimbursed (paid from the deposit's `move_to_vault` UTXO via `create_reimburse_txhandler`) for a payout it never funded or broadcast, matching the "operator reimbursed for a payout it never funded" Critical category.
- The honest operator that actually intended to front the withdrawal is permanently unable to be reimbursed once the withdrawal UTXO is spent by the attacker's transaction, and risks having its collateral burned if it still submits a kickoff (rejected as malicious by `is_kickoff_malicious`), matching two more Critical categories ("honest operator permanently unable to be reimbursed" and "honest operator's collateral burned").
- This is repeatable across every withdrawal and every registered operator, since the flaw is structural (unsigned OP_RETURN + unauthenticated DB attribution), not tied to a specific deposit or operator.

### Likelihood Explanation
The only preconditions are: a withdrawal has been initiated on Citrea (`withdraw`/`safeWithdraw`), which necessarily publishes `input_signature`, `input_outpoint`, `output_script_pubkey`, and `output_amount` in public calldata; and the attacker is capable of constructing and broadcasting a standard Bitcoin transaction and paying fees — both are explicitly granted attacker capabilities. No key share, collateral, or Clementine gRPC access is required, since the attacker can reuse Clementine's own open-source `create_payout_txhandler()` logic (or hand-build an equivalent tx) entirely off Clementine's infrastructure. Attacker cost is limited to Bitcoin transaction fees needed to win the mining/mempool race against the honest operator's version of the same payout.

### Recommendation
Bind the OP_RETURN operator identity to the signed portion of the transaction, e.g. by having the withdrawer's signature cover an additional commitment to the intended fronting operator (via `SIGHASH_ALL` restricted to a fixed operator, or a separate protocol-level authorization step verified before `update_finalized_payouts` accepts a payout as valid), or require the operator crediting itself to also prove control of the funding inputs (e.g., require operator's own signature over the funded inputs, verified against the operator's registered pubkey, before recording `payout_payer_operator_xonly_pk`).

pub fn create_payout_txhandler(
    input_utxo: UTXO,
    output_txout: TxOut,
    operator_xonly_pk: XOnlyPublicKey,
    user_sig: taproot::Signature,
    _network: bitcoin::Network,
) -> Result<TxHandler<Signed>, BridgeError> {
    let txin = SpendableTxIn::new_partial(input_utxo.outpoint, input_utxo.txout);

    let output_txout = UnspentTxOut::from_partial(output_txout.clone());

    let op_return_txout = op_return_txout(PushBytesBuf::from(operator_xonly_pk.serialize()));

    let mut txhandler = TxHandlerBuilder::new(TransactionType::Payout)
        .with_version(NON_STANDARD_V3)
        .add_input(
            NormalSignatureKind::NotStored,
            txin,
            SpendPath::KeySpend,
            DEFAULT_SEQUENCE,
        )
        .add_output(output_txout)
        .add_output(UnspentTxOut::from_partial(anchor_output(
            NON_EPHEMERAL_ANCHOR_AMOUNT,
        )))
        .add_output(UnspentTxOut::from_partial(op_return_txout))
        .finalize();
    txhandler.set_p2tr_key_spend_witness(&user_sig, 0)?;
    txhandler.promote()
}

pub fn verify_storage_proofs(
    storage_proof: &StorageProof,
    state_root: [u8; 32],
) -> (WithdrawalOutpointTxid, u32, MoveTxid) {
    let utxo_storage_proof: EIP1186StorageProof =
        serde_json::from_str(&storage_proof.storage_proof_utxo)
            .expect("Failed to deserialize UTXO storage proof");

    let vout_storage_proof: EIP1186StorageProof =
        serde_json::from_str(&storage_proof.storage_proof_vout)
            .expect("Failed to deserialize vout storage proof");

    let deposit_storage_proof: EIP1186StorageProof =
        serde_json::from_str(&storage_proof.storage_proof_deposit_txid)
            .expect("Failed to deserialize deposit storage proof");

    let storage_address: U256 = {
        let mut keccak = Keccak256::new();
        keccak.update(UTXOS_STORAGE_INDEX);
        let hash = keccak.finalize();
        U256::from_be_bytes(
            <[u8; 32]>::try_from(&hash[..]).expect("Hash slice has incorrect length"),
        )
    };

    let storage_key_utxo: alloy_primitives::Uint<256, 4> =
        storage_address + U256::from(storage_proof.index * 2);

    let storage_key_vout: alloy_primitives::Uint<256, 4> =
        storage_address + U256::from(storage_proof.index * 2 + 1);

    let storage_address_deposit: U256 = {
        let mut keccak = Keccak256::new();
        keccak.update(DEPOSIT_STORAGE_INDEX);
        let hash = keccak.finalize();
        U256::from_be_bytes(
            <[u8; 32]>::try_from(&hash[..]).expect("Hash slice has incorrect length"),
        )
    };

    let deposit_storage_key: alloy_primitives::Uint<256, 4> =
        storage_address_deposit + U256::from(storage_proof.index);

    let deposit_storage_key_bytes = deposit_storage_key.to_be_bytes::<32>();

    if deposit_storage_key_bytes != deposit_storage_proof.key.as_b256().0 {
        panic!(
            "Invalid deposit storage key. left: {:?} right: {:?}",
            deposit_storage_key_bytes,
            deposit_storage_proof.key.as_b256().0
        );
    }

    if storage_key_utxo.to_be_bytes() != utxo_storage_proof.key.as_b256().0 {
        panic!(
            "Invalid withdrawal UTXO storage key. left: {:?} right: {:?}",
            storage_key_utxo.to_be_bytes::<32>(),
            utxo_storage_proof.key.as_b256().0
        );
    }

    if storage_key_vout.to_be_bytes() != vout_storage_proof.key.as_b256().0 {
        panic!(
            "Invalid withdrawal vout storage key. left: {:?} right: {:?}",
            storage_key_vout.to_be_bytes::<32>(),
            vout_storage_proof.key.as_b256().0
        );
    }

    storage_verify(&utxo_storage_proof, state_root);

    storage_verify(&deposit_storage_proof, state_root);

    storage_verify(&vout_storage_proof, state_root);

    let buf: [u8; 32] = vout_storage_proof.value.to_be_bytes();

    // ENDIANNESS SHOULD BE CHECKED THIS FIELD IS 4 BYTES in the contract
    let vout = u32::from_le_bytes(
        buf[28..32]
            .try_into()
            .expect("Vout value conversion failed"),
    );

    let wd_outpoint = WithdrawalOutpointTxid(utxo_storage_proof.value.to_be_bytes());

    let move_txid = MoveTxid(deposit_storage_proof.value.to_be_bytes());

    (wd_outpoint, vout, move_txid)
}

    async fn is_kickoff_malicious(
        &self,
        kickoff_witness: Witness,
        deposit_data: &mut DepositData,
        kickoff_data: KickoffData,

    ) -> Result<bool, BridgeError> {

                .get_cached_tx()
                .compute_txid();

        let payout_info = self
            .db
            .get_payout_info_from_move_txid(Some(dbtx), move_txid)
            .await?;
        let Some((operator_xonly_pk_opt, payout_blockhash, _, _)) = payout_info else {
            tracing::warn!(
                "No payout info found in db for move txid {move_txid}, assuming malicious"
            );
            return Ok(true);
        };

        let Some(operator_xonly_pk) = operator_xonly_pk_opt else {
            tracing::warn!("No operator xonly pk found in payout tx OP_RETURN, assuming malicious");
            return Ok(true);
        };

        if operator_xonly_pk != kickoff_data.operator_xonly_pk {
            tracing::warn!("Operator xonly pk for the payout does not match with the kickoff_data");
            return Ok(true);
        }

            kickoff_data.round_idx,
            kickoff_data.kickoff_idx,
            self.config.protocol_paramset(),
        );

            kickoff_witness,
            &[wt_derive_path],
            self.config.protocol_paramset(),
        )?;
        let blockhash_data = commits.first();
        // only last 20 bytes of the blockhash is committed
        let truncated_blockhash = &payout_blockhash[12..];
        if let Some(committed_blockhash) = blockhash_data {
            if committed_blockhash != truncated_blockhash {
                tracing::warn!("Payout blockhash does not match committed hash: committed: {:?}, truncated payout blockhash: {:?}",
                        blockhash_data, truncated_blockhash);
                return Ok(true);
            }
        } else {
            return Err(eyre::eyre!("Couldn't retrieve committed data from witness").into());
        }
        Ok(false)
    }

    async fn update_finalized_payouts(
        &self,
        dbtx: DatabaseTransaction<'_>,
        block_id: u32,
        block_cache: &block_cache::BlockCache,
    ) -> Result<(), BridgeError> {
        let payout_txids = self
            .db
            .get_payout_txs_for_withdrawal_utxos(Some(dbtx), block_id)
            .await?;

        let block = &block_cache.block;

        let block_hash = block.block_hash();

        let mut payout_txs_and_payer_operator_idx = vec![];
        for (idx, payout_txid) in payout_txids {
            let payout_tx_idx = block_cache.txids.get(&payout_txid);
            if payout_tx_idx.is_none() {
                tracing::error!(
                    "Payout tx not found in block cache: {:?} and in block: {:?}",
                    payout_txid,
                    block_id
                );
                tracing::error!("Block cache: {:?}", block_cache);
                return Err(eyre::eyre!("Payout tx not found in block cache").into());
            }
            let payout_tx_idx = payout_tx_idx.expect("Payout tx not found in block cache");
            let payout_tx = &block.txdata[*payout_tx_idx];
            // Find the first output that contains OP_RETURN
            let circuit_payout_tx = CircuitTransaction::from(payout_tx.clone());
            let op_return_output = get_first_op_return_output(&circuit_payout_tx);

            // If OP_RETURN doesn't exist in any outputs, or the data in OP_RETURN is not a valid xonly_pubkey,
            // operator_xonly_pk will be set to None, and the corresponding column in DB set to NULL.
            // This can happen if optimistic payout is used, or an operator constructs the payout tx wrong.
            let operator_xonly_pk = op_return_output
                .and_then(|output| parse_op_return_data(&output.script_pubkey))
                .and_then(|bytes| XOnlyPublicKey::from_slice(bytes).ok());

            if operator_xonly_pk.is_none() {
                tracing::info!(
                    "No valid operator xonly pk found in payout tx {:?} OP_RETURN. Either it is an optimistic payout or the operator constructed the payout tx wrong",
                    payout_txid
                );
            }

            tracing::info!(
                "A new payout tx detected for withdrawal {}, payout txid: {:?}, operator xonly pk: {:?}",
                idx,
                payout_txid,
                operator_xonly_pk
            );

            payout_txs_and_payer_operator_idx.push((
                idx,
                payout_txid,
                operator_xonly_pk,
                block_hash,
            ));
        }

        self.db
            .update_payout_txs_and_payer_operator_xonly_pk(
                Some(dbtx),
                payout_txs_and_payer_operator_idx,
            )
            .await?;

        Ok(())
