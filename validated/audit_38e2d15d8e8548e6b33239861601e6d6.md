### Title
Unbounded EVM Gas in Static Call Queries via CosmWasm Query Bindings - (File: x/evm/keeper/evm.go)

### Summary
The `getEvmGasLimitFromCtx` function in `x/evm/keeper/evm.go` still returns `math.MaxUint64` as the EVM gas limit whenever the underlying Cosmos SDK gas meter has a `Limit()` of zero (an infinite gas meter, which is what queries and static-call contexts use). This value flows directly into `StaticCallEVM`, which is reachable by any CosmWasm contract via the `wasmd` query bindings (`x/evm/client/wasm/query.go`), allowing an unprivileged wasm-query caller to trigger unbounded EVM execution.

### Finding Description
`k.callEVM` computes the gas budget for a static EVM call from `k.getEvmGasLimitFromCtx(ctx)`: [1](#0-0) 

When the calling context uses an infinite gas meter (`ctx.GasMeter().Limit() <= 0`), the function short-circuits and returns `math.MaxUint64` instead of applying any cap: [2](#0-1) 

This is exactly the code path described in the external report; the value is unconditionally passed as the `gas` argument to the EVM call function: [3](#0-2) 

`StaticCallEVM` builds a read-only EVM using `sdk.NewInfiniteGasMeterWithMultiplier(ctx)` as its execution context, guaranteeing that `getEvmGasLimitFromCtx` takes the `math.MaxUint64` branch: [4](#0-3) [5](#0-4) 

`StaticCallEVM` is directly reachable by any unprivileged CosmWasm contract through the wasm query binding `HandleStaticCall`, exposed by `x/evm/client/wasm/query.go`, which any CW contract can invoke via a smart query with attacker-controlled `to`/`data`: [6](#0-5) 

Because no external gas limit is imposed on this query path, and no separate bound is enforced in `callEVM`/`StaticCallEVM`, an attacker can deploy an EVM contract with an expensive but non-reverting loop (e.g., heavy storage reads/writes or hashing loop) and repeatedly invoke it through a CW contract's smart-query interface (which, in turn, calls `HandleStaticCall`), causing the query-serving node to spend unbounded CPU time per query with no gas-based cutoff.

### Impact Explanation
Because CosmWasm smart queries are commonly proxied by full/RPC nodes to serve client requests (and can also be invoked in message-handling contexts with infinite/large gas meters), an attacker can craft a CW contract that calls `StaticCallEVM` against an EVM contract executing a computationally unbounded loop. Since the EVM gas budget for this call is `math.MaxUint64`, there is no mechanism to bound execution time; the query handler will run until it either exhausts real wall-clock resources or the underlying EVM interpreter naturally halts (which the attacker controls to never happen quickly). Repeated invocation of such a query can degrade query-serving nodes and, if this code path is also reachable in message-execution contexts that share the same infinite gas meter pattern, can slow block processing, i.e., a resource-exhaustion / degraded-availability vector against RPC/query nodes.

### Likelihood Explanation
Any address can deploy an EVM contract and any CosmWasm contract author (which is a permissionless, unprivileged action) can implement a query handler that calls into the `x/evm` wasm query bindings with a `to` address of the attacker's expensive contract. No special privileges, precompile access, or governance action is required — this is directly reachable from a public wasm smart-query request.

### Recommendation
Cap the returned gas value in `getEvmGasLimitFromCtx` when `ctx.GasMeter().Limit() <= 0` to a fixed, reasonable maximum (e.g., a per-query EVM gas cap parameter) instead of `math.MaxUint64`, mirroring standard `eth_call`/`eth_estimateGas` gas-cap patterns used by go-ethereum RPC servers. This preserves the ability to execute static calls for legitimate use cases while bounding worst-case per-query execution cost.

### Proof of Concept
1. Deploy an EVM contract whose fallback/entry function performs a very large, non-reverting loop of storage writes/reads (e.g., a loop bound by a large but finite iteration count, sized so it would exceed any sane block gas limit if metered normally).
2. Deploy or use an existing CosmWasm contract that implements a smart-query calling the `evm` wasm query binding `static_call` (`HandleStaticCall` in `x/evm/client/wasm/query.go`) targeting the deployed EVM contract's expensive function.
3. Issue repeated `wasmd` smart-queries (or CW inter-contract queries) against this contract from any client — no on-chain fee is required for a query, and `getEvmGasLimitFromCtx` returns `math.MaxUint64` because the query context's gas meter has `Limit() == 0`.
4. Observe that the EVM executes the expensive loop with no gas-based cutoff, consuming disproportionate CPU/time on the serving node relative to the cost/effort required by the attacker to issue the query.

func (k *Keeper) StaticCallEVM(ctx sdk.Context, from sdk.AccAddress, to *common.Address, data []byte) ([]byte, error) {
	// Static EVM execution must reproduce consensus precompile behavior, even
	// when entered from an ABCI query or historical RPC context.
	ctx = ctx.WithIsABCIQuery(false)

	evm, err := k.createReadOnlyEVM(ctx, from)
	if err != nil {
		return nil, err
	}
	return k.callEVM(ctx, k.GetEVMAddressOrDefault(ctx, from), to, nil, data, func(caller common.Address, addr *common.Address, input []byte, gas uint64, _ *big.Int) ([]byte, uint64, error) {
		return evm.StaticCall(caller, *addr, input, gas)
	})
}

func (k *Keeper) callEVM(ctx sdk.Context, from common.Address, to *common.Address, val *sdk.Int, data []byte, f EVMCallFunc) ([]byte, error) {
	evmGasLimit := k.getEvmGasLimitFromCtx(ctx)
	value := utils.Big0
	if val != nil {
		value = val.BigInt()
	}
	ret, leftoverGas, err := f(from, to, data, evmGasLimit, value)
	k.consumeEvmGas(ctx, evmGasLimit-leftoverGas)
	if err != nil {
		return nil, err
	}
	return ret, nil
}

func (k *Keeper) createReadOnlyEVM(ctx sdk.Context, from sdk.AccAddress) (*vm.EVM, error) {
	executionCtx := ctx.WithGasMeter(sdk.NewInfiniteGasMeterWithMultiplier(ctx))
	stateDB := state.NewDBImpl(executionCtx, k, true)
	gp := k.GetGasPool()
	blockCtx, err := k.GetVMBlockContext(executionCtx, gp)
	if err != nil {
		return nil, err
	}
	sstore := k.GetSstoreSetGasEIP2200(ctx)
	cfg := types.DefaultChainConfig().EthereumConfigWithSstore(k.ChainID(ctx), &sstore)
	txCtx := vm.TxContext{Origin: k.GetEVMAddressOrDefault(ctx, from)}
	evm := vm.NewEVM(*blockCtx, stateDB, cfg, vm.Config{}, k.CustomPrecompiles(ctx))
	evm.SetTxContext(txCtx)
	return evm, nil
}

func (k *Keeper) getEvmGasLimitFromCtx(ctx sdk.Context) uint64 {
	seiGasRemaining := ctx.GasMeter().Limit() - ctx.GasMeter().GasConsumedToLimit()
	if ctx.GasMeter().Limit() <= 0 {
		return math.MaxUint64
	}
	if ctx.ChainID() != Pacific1ChainID || ctx.BlockHeight() >= 119821526 {
		ctx = ctx.WithGasMeter(sdk.NewInfiniteGasMeterWithMultiplier(ctx))
	}
	evmGasBig := sdk.NewDecFromInt(sdk.NewIntFromUint64(seiGasRemaining)).Quo(k.GetPriorityNormalizer(ctx)).TruncateInt().BigInt()
	if evmGasBig.Cmp(MaxUint64BigInt) > 0 {
		evmGasBig = MaxUint64BigInt
	}
	return evmGasBig.Uint64()
}

func (h *EVMQueryHandler) HandleStaticCall(ctx sdk.Context, from string, to string, data []byte) ([]byte, error) {
	fromAddr, err := sdk.AccAddressFromBech32(from)
	if err != nil {
		return nil, err
	}
	var toAddr *common.Address
	if to != "" {
		toSeiAddr := common.HexToAddress(to)
		toAddr = &toSeiAddr
	}
	res, err := h.k.StaticCallEVM(ctx, fromAddr, toAddr, data)
	if err != nil {
		return nil, err
	}
	response := bindings.StaticCallResponse{EncodedData: base64.StdEncoding.EncodeToString(res)}
	return json.Marshal(response)
}
