Based on the code investigated, I found a concrete Desktop analog: the deep-link (`x-github-client://openRepo/...`) handler resolves an attacker-supplied URL against a user's already-open repositories using only a coarse host/owner/name string match, then performs a silent branch checkout using an attacker-controlled branch name — without any confirmation or verification that the branch is expected/safe, mirroring the "missing check that the object belongs to this particular contract/owner" pattern in the report.

### Title
Deep link `openRepo` action performs silent branch checkout using unverified attacker-controlled URL/branch match - (File: app/src/ui/dispatcher/dispatcher.ts)

### Summary
`parseAppURL` in [1](#0-0)  accepts a `x-github-client://openRepo/<url>?branch=<name>` deep link and forwards the raw `url` and `branch` to the dispatcher. `openBranchNameFromUrl` then resolves an existing repository purely via `doesRepositoryMatchUrl`/`urlsMatch` string comparison of the origin/upstream `htmlURL`, and if it matches, immediately fetches and checks out the attacker-supplied branch name with no user confirmation prompt: [2](#0-1) 

### Finding Description
The invariant broken here is analogous to the report: the code accepts an externally supplied identifier (the branch name / clone URL in the deep link) and performs a privileged, state-mutating action (a branch checkout, which changes the user's working directory contents) based solely on a loose string match (`urlsMatch`) between the link's URL and an already-tracked repository — without verifying that the deep link itself was expected, or requiring any user confirmation before switching the working tree state: [3](#0-2) 
`openOrCloneRepository` performs the lookup exclusively via `doesRepositoryMatchUrl`: [4](#0-3) 
Once matched, `checkoutLocalBranch` is invoked directly with the caller-supplied `branch` string, checking out any local branch by that name with no additional gate: [5](#0-4) 

This is triggered end-to-end from the OS-level protocol handler with no user gesture beyond clicking a link: [6](#0-5)  and dispatched straight into the app without any origin check: [7](#0-6) 

### Impact Explanation
A malicious webpage, email, or README containing a crafted `x-github-client://openRepo/https://github.com/<victim-org>/<victim-repo>?branch=<attacker-chosen-branch>` link can, if the user has that repository already cloned and open in Desktop, silently switch the checked-out branch in the user's working directory when they click the link — without any confirmation dialog showing what will change. If the target branch (locally present via prior fetches, e.g. a stale local tracking branch or one the attacker got merged/pushed) contains different files or build/CI configuration, this can lead to the user unknowingly committing on top of, building, or running code from an unintended branch, i.e., silent corruption of what the user believes they are working on/committing. This matches the report's core impact class: an attacker-controlled reference is accepted and acted upon without validating it belongs to the expected context, causing state corruption for the legitimate owner.

### Likelihood Explanation
The `filepath` parameter is protected by both `isAbsolute` and `resolveWithin` checks against path traversal [8](#0-7) , showing the developers are aware that deep-link content is untrusted — but the same rigor was not applied to the `branch` checkout path, which executes unconditionally as soon as a matching repository is found. Exploitation only requires the victim to have the target repository already open in Desktop and to click a link (or be redirected to one), which is a normal Desktop user action, not local/physical access, malware, or credential compromise. This keeps likelihood a step higher than a purely theoretical issue, though it does depend on the victim already having a relevant local branch to switch to and does not by itself achieve code execution — it is limited to a silent checkout/state-corruption primitive.

### Recommendation
Before performing `checkoutLocalBranch` in `openBranchNameFromUrl` (or `_checkoutPullRequest` in `openPullRequestFromUrl`), surface a confirmation dialog identifying the target repository, current branch, and the branch that will be checked out, requiring explicit user consent, mirroring the treatment already given to `filepath`. Additionally, harden `urlsMatch`/`doesRepositoryMatchUrl` matching to be stricter (e.g., requiring case-sensitive host/owner/name equality already done) and to fail closed rather than silently substitute a different local branch when ambiguity exists.

### Proof of Concept
1. Victim has `https://github.com/acme/webapp` cloned and open in GitHub Desktop, with a local branch `release-old` still present from a prior fetch.
2. Attacker crafts and delivers (e.g., in a phishing email or malicious website) the link:
   `x-github-client://openRepo/https://github.com/acme/webapp?branch=release-old`
3. Victim clicks the link. `main.ts`'s `open-url`/`handleAppURL` fires [9](#0-8) , `parseAppURL` extracts `{name: 'open-repository-from-url', url: 'https://github.com/acme/webapp', branch: 'release-old'}` [1](#0-0) , and `dispatchURLAction` → `openRepositoryFromUrl` → `openBranchNameFromUrl` is invoked [10](#0-9) .
4. Because the URL matches the already-open repository's `htmlURL`, Desktop fetches and silently checks out `release-old` in the victim's working directory with no confirmation prompt, changing tracked files under the victim without their explicit awareness of the branch switch.

  private doesRepositoryMatchUrl(
    repo: Repository | CloningRepository,
    url: string
  ): repo is RepositoryWithGitHubRepository {
    if (repo instanceof Repository && isRepositoryWithGitHubRepository(repo)) {
      const originRepoUrl = repo.gitHubRepository.htmlURL
      const upstreamRepoUrl = repo.gitHubRepository.parent?.htmlURL ?? null

      if (originRepoUrl !== null && urlsMatch(originRepoUrl, url)) {
        return true
      }

      if (upstreamRepoUrl !== null && urlsMatch(upstreamRepoUrl, url)) {
        return true
      }
    }

    return false
  }

  private async openRepositoryFromUrl(action: IOpenRepositoryFromURLAction) {
    const { url, pr, branch, filepath } = action

    let repository: Repository | null

    if (pr !== null) {
      repository = await this.openPullRequestFromUrl(url, pr)
    } else if (branch !== null) {
      repository = await this.openBranchNameFromUrl(url, branch)
    } else {
      repository = await this.openOrCloneRepository(url)
    }

    if (repository === null) {
      return
    }

    if (filepath !== null) {
      if (isAbsolute(filepath)) {
        log.error(`Refusing to open absolute path: ${filepath}`)
        return
      }

      const resolved = await resolveWithin(repository.path, filepath)

      if (resolved !== null) {
        shell.showItemInFolder(resolved)
      } else {
        log.error(
          `Prevented attempt to open path outside of the repository root: ${filepath}`
        )
      }
    }
  }

  private async openBranchNameFromUrl(
    url: string,
    branchName: string
  ): Promise<Repository | null> {
    const repository = await this.openOrCloneRepository(url)

    if (repository === null) {
      return null
    }

    // ensure a fresh clone repository has it's in-memory state
    // up-to-date before performing the "Clone in Desktop" steps
    await this.appStore._refreshRepository(repository)

    // if the repo has a remote, fetch before switching branches to ensure
    // the checkout will be successful. This operation could be a no-op.
    await this.appStore._fetch(repository, FetchType.UserInitiatedTask)

    await this.checkoutLocalBranch(repository, branchName)

    return repository
  }

  private async checkoutLocalBranch(repository: Repository, branch: string) {
    let shouldCheckoutBranch = true

    const state = this.repositoryStateManager.get(repository)
    const branches = state.branchesState.allBranches

    const { tip } = state.branchesState

    if (tip.kind === TipState.Valid) {
      shouldCheckoutBranch = tip.branch.nameWithoutRemote !== branch
    }

    const localBranch = branches.find(b => b.nameWithoutRemote === branch)

    // N.B: This looks weird, and it is. _checkoutBranch used
    // to behave this way (silently ignoring checkout) when given
    // a branch name string that does not correspond to a local branch
    // in the git store. When rewriting _checkoutBranch
    // to remove the support for string branch names the behavior
    // was moved up to this method to not alter the current behavior.
    //
    // https://youtu.be/IjmtVKOAHPM
    if (shouldCheckoutBranch && localBranch !== undefined) {
      await this.checkoutBranch(repository, localBranch)
    }
  }
