### Title
Missing zero-address validation in `bank.sendNative()` allows permanent loss of funds - (File: `precompiles/bank/bank.go`)

### Summary
The `sendNative` transaction of the `bank` precompile at `0x0000000000000000000000000000000000001001` accepts a destination Cosmos-format address as a raw bech32 string and only validates that the string is non-empty and successfully bech32-decodes. Unlike the sibling `send` method, which routes recipients through `accAddressFromArg` and explicitly rejects the zero address, `sendNative` never checks whether the decoded `sdk.AccAddress` is the all-zero address. A user can therefore send `usei`/wei value that is subtracted from their balance to an address nobody controls, permanently losing the funds — the same "recovery/agent set to 0" fund-loss bug class described in the external report.

### Finding Description
In `precompiles/bank/bank.go`, `send()` resolves both `fromAddress` and `toAddress` through `accAddressFromArg`, which explicitly rejects the zero `common.Address`: [1](#0-0) 

However `sendNative()` takes the recipient as a `string` (`toNativeAddress`) and only checks it's non-empty before decoding it with `sdk.AccAddressFromBech32`, with no subsequent check that the resulting `AccAddress` is non-zero: [2](#0-1) 

The bech32 encoding of 20 zero bytes with the `sei` HRP is a perfectly valid, decodable bech32 string (any caller can compute the correct checksum for an all-zero payload), so `AccAddressFromBech32` will succeed and `p.bankKeeper.SendCoinsAndWei` will move real value to that unrecoverable address. This precompile is reachable directly from any EVM transaction sender (payable call to the bank precompile), matching the analog's "recovery == 0" pattern that leads to `sendToRecovery()` burning funds to the zero address.

### Impact Explanation
Any account that calls `bank.sendNative(zeroBech32Address)` with a nonzero `msg.value` will have that `usei`/wei balance irrevocably transferred to the zero Cosmos address, which has no known private key. This is a direct, concrete, permanent loss of funds for the caller (and could be used adversarially to trick a contract or integration into losing funds if it forwards user-supplied destination strings unchecked to `sendNative`). This matches the "concrete fund loss or permanent freezing" impact bar.

### Likelihood Explanation
The bug is trivially reachable: it only requires an EVM transaction calling the public `bank` precompile's `sendNative` function with a bech32-encoded zero address and nonzero value — no special privileges, precompile abuse chain, or governance/validator involvement is required. The main constraint is that it typically requires either user error or a vulnerable calling contract passing an attacker-controlled/zero destination address, so likelihood is moderate but the check is trivially cheap to add and matches an already-fixed analogous check in `send()`.

### Recommendation
Add an explicit check in `sendNative()` (mirroring `accAddressFromArg`) that rejects `receiverSeiAddr` when it equals the zero-value `sdk.AccAddress` (e.g., `bytes.Equal(receiverSeiAddr, make([]byte, len(receiverSeiAddr)))` or comparing against `sdk.AccAddress(common.Address{}.Bytes())`), returning an error such as `"invalid addr"` before calling `SendCoinsAndWei`.

### Proof of Concept
1. Compute the bech32 encoding of the 20-byte all-zero payload under the `sei` HRP (a valid Cosmos address string with a correct checksum can be generated by anyone, e.g., via `sdk.AccAddress(make([]byte, 20)).String()`).
2. From any associated EVM account, call `IBank(BANK_CONTRACT).sendNative{value: X}(zeroBech32Address)` at `precompiles/bank/bank.go` `sendNative()`.
3. The call succeeds: `sdk.AccAddressFromBech32` decodes without error, `HandlePaymentUseiWei`/`SendCoinsAndWei` transfer `X` usei/wei to the zero address, and the funds become permanently unrecoverable since no private key corresponds to the zero address.

func (p PrecompileExecutor) accAddressFromArg(ctx sdk.Context, arg interface{}) (sdk.AccAddress, error) {
	addr := arg.(common.Address)
	if addr == (common.Address{}) {
		return nil, errors.New("invalid addr")
	}
	seiAddr, found := p.evmKeeper.GetSeiAddress(ctx, addr)
	if !found {
		// return the casted version instead
		return sdk.AccAddress(addr[:]), nil
	}
	return seiAddr, nil
}
