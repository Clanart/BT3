### Title
Permissionless `harvestAll()` enables reward-sniping — attackers stake into `delegatedPool`, self-trigger a lump-sum bribe harvest, and withdraw immediately to steal pro-rata yield from long-term voters - ([File: rewards/DelegateVoteRewardPool.sol])

### Summary
`DelegateVoteRewardPool.harvestAll()` is `external` with no access control and no minimum-holding-period guard, and it immediately converts freshly harvested bribes into `rewardPerTokenStored` using the *current* `totalSupply`. An attacker can `vote()` into `delegatedPool` (calling `stakeFor`), call `harvestAll()` themselves in the same or next block, and `unvote()` (calling `withdrawFor`) right after, capturing a full pro-rata share of bribes that accrued over the entire period since the last harvest — despite having staked for only moments.

### Finding Description
`harvestAll()` pulls bribes accrued by the delegate pool's aggregate vote position and dumps them straight into `rewardPerTokenStored` via `_queueNewRewardsWithoutTransfer`: [1](#0-0) [2](#0-1) 

Unlike a synthetix-style streaming reward (`rewardRate` × elapsed time), this contract has no time-based drip: the entire harvested lump sum is distributed instantly, weighted only by `totalSupply` at the moment `harvestAll()` executes. There is no snapshot of historical stake-time, and the `stakeFor`/`withdrawFor` `updateRewards` modifier only sets the caller's baseline to whatever `rewardPerTokenStored` is *at call time* — it does not prevent a staker who joined seconds ago from claiming a share of rewards that accrued to the bribe pools before they staked: [3](#0-2) 

`harvestAll()` has no `onlyOperator`, `onlyOwner`, or any modifier at all, so any unprivileged address can call it: [1](#0-0) 

The exploit sequence:
1. Attacker calls `WombatBribeManager.vote(...)` allocating votes to `delegatedPool`, which routes into `DelegateVoteRewardPool.stakeFor(attacker, amount)` — this sets `totalSupply += amount` and snapshots attacker's `userRewardPerTokenPaid` at the pre-harvest value.
2. Attacker calls `harvestAll()`, triggering `IWombatBribeManager(operator).claimAllBribes(address(this))`: [4](#0-3) 
   This claims bribes accrued to the delegate pool's total vote-weight (contributed by all past and present voters) and instantly folds them into `rewardPerTokenStored`, computed using `totalSupply` that now includes the attacker's just-added stake.
3. Attacker calls `withdrawFor` (via `unvote`), whose `updateRewards` modifier computes `earned = balance * (rewardPerTokenStored_new - userRewardPerTokenPaid_old)`, giving the attacker a share of rewards proportional to their balance — not to how long they were actually staked — then transfers it out via `_getReward`.

Existing checks that fail to stop this: `onlyOperator` only restricts who can call `stakeFor`/`withdrawFor` (must go through `WombatBribeManager`, which any user can call via `vote`/`unvote`); there is no `nonReentrant` issue here since no reentrancy is needed; there is no cooldown, vesting, or time-weighted-average-balance mechanism guarding reward distribution.

### Impact Explanation
This is theft of unclaimed yield: honest, long-term voters who kept the delegate pool's votes allocated to bribe-producing LPs for the full accrual period have their bribes diluted by a flash staker capturing a pro-rata share for near-zero holding duration. This matches "theft of unclaimed yield" in the accepted impact classes. The magnitude scales with the size of the harvested batch and the attacker's stake fraction of `totalSupply` at harvest time; an attacker can also flash-loan/borrow the underlying vote-eligible tokens to inflate their share before harvesting (loan flashability is explicitly listed as within scope for the attacker model).

### Likelihood Explanation
- No privileged role or admin action required — fully triggerable by any EOA/contract.
- Feasible in a single transaction (via a helper contract atomically calling vote → harvestAll → unvote) or across two blocks with front-running.
- Repeatable every time bribes accumulate between harvests, and anyone can call `harvestAll()` at will, making the timing entirely attacker-controlled.
- Capital requirement is only whatever amount of stake/vote-token is needed to be included as a voter into `delegatedPool`; larger capital yields proportionally larger theft, but even modest capital captures a share of the batch.

### Recommendation
Replace the instantaneous, current-totalSupply-weighted reward injection with a time-weighted / streaming distribution model (e.g., Synthetix-style `rewardRate` over a fixed `rewardsDuration`, updated on `lastUpdateTime`), so that newly staked balances only start earning from the point they entered, and cannot retroactively claim a share of rewards that accrued before their stake existed. Alternatively, restrict `harvestAll()` to a trusted keeper/role and/or add a minimum stake-duration requirement (time-lock) before a `withdrawFor`/`unvote` is allowed to claim newly harvested rewards.

### Proof of Concept
Foundry test plan:
1. Deploy `DelegateVoteRewardPool`, mock `WombatBribeManager` (mocking `claimAllBribes` to return a fixed lump-sum bribe amount representing bribes accrued "over time"), and a reward token.
2. Voter A stakes (via mocked `stakeFor`) a large balance and holds it for many blocks (simulating long-term voting).
3. Attacker calls `stakeFor(attacker, smallAmount)` (simulating `vote()`).
4. Attacker immediately calls `harvestAll()`, which invokes the mocked `claimAllBribes` returning the accrued lump sum, causing `_manageRewards` → `_queueNewRewardsWithoutTransfer` to update `rewardPerTokenStored` using `totalSupply = VoterA.balance + attacker.balance`.
5. Attacker immediately calls `withdrawFor(attacker, smallAmount, true)` (simulating `unvote()`), claiming `earned(attacker, token)`.
6. Assert: `earned(attacker, token) > 0` and `earned(attacker, token) / lumpSum ≈ attacker.balance / totalSupply` (attacker's instantaneous balance share), while attacker's actual staked duration (1 block) is negligible compared to Voter A's holding period — demonstrating reward capture disproportionate to time-weighted stake, i.e., `earned(attacker) > pro_rata_share_by_time(attacker)`.

    ) external override onlyOperator updateRewards(_for, rewardTokens) {
        totalSupply = totalSupply + _amount;
        _balances[_for] = _balances[_for] + _amount;
        _updateVote();

        emit Staked(_for, _amount);
    }

    function withdrawFor(
        address _for,
        uint256 _amount,
        bool _claim
    ) external override onlyOperator updateRewards(_for, rewardTokens) {
        totalSupply = totalSupply - _amount;
        _balances[_for] = _balances[_for] - _amount;
        _updateVote();

        emit Withdrawn(_for, _amount);

        if (_claim) {
            _getReward(_for);
        }
    }
