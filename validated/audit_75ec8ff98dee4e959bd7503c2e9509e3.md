### Title
Payout OP_RETURN operator attribution is unauthenticated, letting anyone reassign payout credit via SIGHASH_SINGLE|ANYONECANPAY malleability — ([File: core/src/operator.rs])

### Summary
### Finding Description
The Astaria analog is a callback that never authenticates who invoked it, forcing recipients to trust unverified "who paid" data. Clementine has the same class of gap in how it attributes the on-chain payout ("fronting") transaction to an operator.

`Operator::withdraw` verifies only that the given `in_signature` is a valid Schnorr signature over the payout transaction with the **caller-supplied** `sighash_type`: [1](#0-0) 

The docstring itself states the expected type is `SinglePlusAnyoneCanPay`. That sighash flag commits only to the single input being spent and the output at the same index (`output_txout`, the user payout output) — it does **not** commit to the third output, the OP_RETURN carrying `operator_xonly_pk`: [2](#0-1) 

Once a payout transaction with this signature type is broadcast (or even just built and shared, e.g. observed unconfirmed in the mempool), any unprivileged party can take the same user signature and input, keep the same paid output (so the user's transfer is untouched and thus not detectable as tampering), but rebuild the transaction with a **different** `operator_xonly_pk` in the OP_RETURN output (belonging to a different, real, registered operator, or an invalid one), and get that variant confirmed on Bitcoin instead of the original.

Downstream, verifiers derive payout attribution *exclusively* from this on-chain OP_RETURN field, with no cross-check against who actually funded/signed the transaction as the payer: [3](#0-2) [4](#0-3) 

That stored `payout_payer_operator_xonly_pk` is later compared against the operator who actually sends the kickoff (`kickoff_data.operator_xonly_pk`) to decide whether the kickoff is malicious: [5](#0-4) 

and a mismatch causes verifiers to flag the kickoff as malicious and queue a `Challenge` transaction: [6](#0-5) 

### Impact Explanation
This breaks the "operator credited versus the party that paid" binding: the honest operator who actually funded the withdrawal from their own wallet (`fund_raw_transaction` / `sign_raw_transaction_with_wallet` in `Operator::withdraw`) can have their payout attribution stolen or nulled by anyone who can observe/replay the SIGHASH_SINGLE|ANYONECANPAY-signed input before it confirms. Once the malleated variant confirms with a wrong/absent operator key:
- The honest operator's later kickoff (which legitimately committed the correct payout blockhash) will fail the `operator_xonly_pk != kickoff_data.operator_xonly_pk` check in `is_kickoff_malicious`, causing verifiers to treat their honest kickoff as malicious and send a Challenge.
- The honest operator, having genuinely paid the user, cannot be reimbursed through the normal path (`send_asserts` explicitly errors if `payout_op_xonly_pk != kickoff_data.operator_xonly_pk`, per `core/src/operator.rs:1290-1295`), and is put through a forced disprove/challenge process, risking their round collateral being burned.

This matches the Critical impact class: "an honest operator permanently unable to be reimbursed" and/or "an honest operator's collateral burned."

### Likelihood Explanation
The precondition is that the operator uses (or is required to use, per the code's own error message) `SinglePlusAnyoneCanPay` sighash for the payout transaction's sole signature check, which by design leaves the OP_RETURN output unauthenticated. Any observer of the pending/broadcast payout transaction (mempool visibility, or knowledge of the withdrawal's signature/outpoint) — no special role, keys, or protocol privilege required — can exploit this. The main uncertainty is the practical race: the malleated transaction must confirm instead of (or in place of) the operator's original broadcast, which depends on mempool/RBF dynamics I could not fully verify from the indexed code (e.g., whether `send_raw_transaction`/RBF settings make replacement trivial). This should be validated with a Devin session that can inspect the full RBF/tx-sender behavior and mempool policy in this repo.

### Recommendation
Require the payout transaction's signature to cover all outputs (e.g., `SIGHASH_ALL`) for any output whose content affects protocol accounting (specifically the OP_RETURN operator-attribution output), or otherwise bind the OP_RETURN operator pubkey to a value that is authenticated by a signature the attacker cannot forge/replay without also being the legitimate payer (e.g., include the operator's own signature over the OP_RETURN commitment separate from the user's ANYONECANPAY signature, or use `SIGHASH_SINGLE` without `ANYONECANPAY` combined with covering all non-anchor outputs).

### Proof of Concept
1. Operator O builds and broadcasts (or merely shares/exposes to the network) `payout_tx` per `create_payout_txhandler`, with input `user_utxo` signed by the user using `SIGHASH_SINGLE | SIGHASH_ANYONECANPAY`, output[0] = user payout, output[2] = OP_RETURN(`O_xonly_pk`).
2. Attacker A observes the unconfirmed transaction (mempool) and extracts `user_sig`, `in_outpoint`, `output_txout`.
3. A calls `create_payout_txhandler` locally with the same `input_utxo`/`output_txout`/`user_sig`, but sets `operator_xonly_pk = O2_xonly_pk` (a different registered operator, or garbage bytes) in the OP_RETURN.
4. Because the user's signature only commits to input 0 and output 0 (SIGHASH_SINGLE|ANYONECANPAY), the modified transaction verifies identically at `SECP.verify_schnorr` in `Operator::withdraw`/`is_kickoff_malicious`'s downstream consumers.
5. A broadcasts the modified transaction with a higher fee (or otherwise wins the mempool race) so it confirms instead of O's original.
6. `update_finalized_payouts` records `payout_payer_operator_xonly_pk = O2_xonly_pk` (or `NULL`) for this withdrawal.
7. When O later sends its legitimate kickoff (having actually paid the user and knowing the correct payout blockhash), `is_kickoff_malicious` sees `operator_xonly_pk (O2) != kickoff_data.operator_xonly_pk (O)` and flags O's kickoff as malicious, triggering a challenge against O despite O having genuinely fronted the withdrawal.

pub fn create_payout_txhandler(
    input_utxo: UTXO,
    output_txout: TxOut,
    operator_xonly_pk: XOnlyPublicKey,
    user_sig: taproot::Signature,
    _network: bitcoin::Network,
) -> Result<TxHandler<Signed>, BridgeError> {
    let txin = SpendableTxIn::new_partial(input_utxo.outpoint, input_utxo.txout);

    let output_txout = UnspentTxOut::from_partial(output_txout.clone());

    let op_return_txout = op_return_txout(PushBytesBuf::from(operator_xonly_pk.serialize()));

    let mut txhandler = TxHandlerBuilder::new(TransactionType::Payout)
        .with_version(NON_STANDARD_V3)
        .add_input(
            NormalSignatureKind::NotStored,
            txin,
            SpendPath::KeySpend,
            DEFAULT_SEQUENCE,
        )
        .add_output(output_txout)
        .add_output(UnspentTxOut::from_partial(anchor_output(
            NON_EPHEMERAL_ANCHOR_AMOUNT,
        )))
        .add_output(UnspentTxOut::from_partial(op_return_txout))
        .finalize();
    txhandler.set_p2tr_key_spend_witness(&user_sig, 0)?;
    txhandler.promote()
}

    pub async fn handle_kickoff<'a>(
        &'a self,
        dbtx: DatabaseTransaction<'a>,
        kickoff_witness: Witness,
        mut deposit_data: DepositData,
        kickoff_data: KickoffData,
        challenged_before: bool,
    ) -> Result<bool, BridgeError> {
        let is_malicious = self
            .is_kickoff_malicious(kickoff_witness, &mut deposit_data, kickoff_data, dbtx)
            .await?;

        let deposit_outpoint = deposit_data.get_deposit_outpoint();

        let (_signed_txs, tx_metadata, challenge_tx) = self
            .get_signed_txs_for_kickoff(dbtx, kickoff_data, deposit_data)
            .await?;

        if is_malicious {
            tracing::warn!(
                "Malicious {} detected. {} Challenge tx: {} for deposit {}",
                kickoff_data,
                match challenged_before {
                    false => "This is the first malicious kickoff in the current round.",
                    true => "This is not the first malicious kickoff in the current round.",
                },
                bitcoin::consensus::encode::serialize_hex(&challenge_tx),
                deposit_outpoint
            );
            // do not automatically send challenge txs on mainnet or testnet4
            if !challenged_before
                && !matches!(
                    self.config.protocol_paramset().network,
                    bitcoin::Network::Bitcoin | bitcoin::Network::Testnet4
                )
            {
                #[cfg(feature = "automation")]
                self.tx_sender
                    .add_tx_to_queue(
                        dbtx,
                        TransactionType::Challenge,
                        &challenge_tx,
                        &[],
                        Some(tx_metadata),
                        self.config.protocol_paramset(),
                        None,
                    )
                    .await?;
            }

    /// Sets the given payout txs' txid and operator index for the given index.
    pub async fn update_payout_txs_and_payer_operator_xonly_pk(
        &self,
        tx: Option<DatabaseTransaction<'_>>,
        payout_txs_and_payer_operator_xonly_pk: Vec<(
            u32,
            Txid,
            Option<XOnlyPublicKey>,
            bitcoin::BlockHash,
        )>,
    ) -> Result<(), BridgeError> {
        if payout_txs_and_payer_operator_xonly_pk.is_empty() {
            return Ok(());
        }
        // Convert all values first, propagating any errors
        let converted_values: Result<Vec<_>, BridgeError> = payout_txs_and_payer_operator_xonly_pk
            .iter()
            .map(|(idx, txid, operator_xonly_pk, block_hash)| {
                Ok((
                    i32::try_from(*idx).wrap_err("Failed to convert payout index to i32")?,
                    TxidDB(*txid),
                    operator_xonly_pk.map(XOnlyPublicKeyDB),
                    BlockHashDB(*block_hash),
                ))
            })
            .collect();
        let converted_values = converted_values?;

        let mut query_builder = QueryBuilder::new(
            "UPDATE withdrawals AS w SET
                payout_txid = c.payout_txid,
                payout_payer_operator_xonly_pk = c.payout_payer_operator_xonly_pk,
                payout_tx_blockhash = c.payout_tx_blockhash
                FROM (",
        );

        query_builder.push_values(
            converted_values.into_iter(),
            |mut b, (idx, txid, operator_xonly_pk, block_hash)| {
                b.push_bind(idx)
                    .push_bind(txid)
                    .push_bind(operator_xonly_pk)
                    .push_bind(block_hash);
            },
        );

        query_builder
            .push(") AS c(idx, payout_txid, payout_payer_operator_xonly_pk, payout_tx_blockhash) WHERE w.idx = c.idx");

        let query = query_builder.build();
        execute_query_with_tx!(self.connection, tx, query, execute)?;

        Ok(())
    }
