### Title
`associatePubKey` precompile lets anyone associate an arbitrary pubkey (and migrate its funds) without proving ownership of the corresponding private key - ([File: precompiles/addr/addr.go])

### Summary
The `addr` precompile's `associatePubKey` entry point takes a raw compressed public key supplied by the caller, derives the corresponding Sei and EVM addresses from it, and permanently binds them via `AssociateAddresses` — all without any signature proof that the caller (or anyone) actually controls the private key for that pubkey. This mirrors the H-15 bug class: a value that determines an important account identity (here, a pubkey/target address) is accepted and acted upon without verifying its ownership.

### Finding Description
`associatePublicKey` decodes the caller-supplied pubkey hex, parses it, and derives `evmAddr`/`seiAddr` directly from it, with no signature check at all: [1](#0-0) 

This contrasts with the sibling `associate` method, which requires an ECDSA signature (`v, r, s`) over a message and recovers the pubkey from that signature, thereby proving the caller who submitted the transaction had access to sign with that key: [2](#0-1) 

Both paths funnel into `associateAddresses`, which only checks that the target Sei address isn't already associated, then calls `AssociationHelper.AssociateAddresses`, which permanently maps the EVM<->Sei address pair, sets the account pubkey, and migrates the corresponding "cast address" balance (spendable coins and wei) into the Sei address: [3](#0-2) [4](#0-3) 

Because `associatePubKey` requires only knowledge of a public key (which is not secret — it can be observed from any transaction the true owner has ever sent, or from their EVM address inverse-derivation is not even needed since the pubkey itself can leak in many ways), an attacker can front-run and permanently associate any target's pubkey to lock in the mapping before the legitimate owner does. Since `associateAddresses` rejects the call if the Sei address is "already associated," the true key owner is then permanently unable to associate that identity themselves once an attacker (or anyone) has done it first with the same pubkey (the outcome would be identical addresses either way since it's derived from the same pubkey bytes, but this does establish account state — e.g. `SetPubKey`, account creation, and fund migration from the "cast address" — happening at a time and in a context not chosen or authorized by the key owner).

### Impact Explanation
The primary damage is that `AssociateAddresses` triggers `MigrateBalance`, which moves all spendable coins and wei balance from the `castAddr` (the bank-style address derived by casting the EVM address bytes into an `AccAddress`) into the newly associated `seiAddr`. An attacker who knows a victim's pubkey (which is often publicly obtainable) can call `associatePubKey` to force this association and balance migration to occur, and once done it cannot be re-triggered or reversed by the victim (association is permanent, guarded by the "already associated" check). This can create unauthorized changes of account state and forced fund migration timing on behalf of a user who never authorized the specific transaction, and can also be used to front-run and grief a user's own attempt to call `associate`/`associatePubKey`, since after the attacker's call, the real owner's subsequent association call will revert with `address %s is already associated`.

### Likelihood Explanation
Reachable directly and cheaply by any public EVM/CosmWasm caller in a single precompile call, requiring only knowledge of a target's public key (not a secret) and no special privileges. Pubkeys are exposed on-chain by any prior Cosmos-signed transaction (`GetPubKeys()`), so many holders of Sei-native pubkeys are exposed to this.

### Recommendation
Require proof of ownership before deriving/associating an address from a raw pubkey — e.g. require a signature (as `associate` already does) over a challenge message that verifies under the supplied pubkey, or remove/restrict the pubkey-only association path, or gate `MigrateBalance` behind an additional check that the transaction sender's EVM address matches the derived `evmAddr`/`castAddr` before moving funds.

### Proof of Concept
1. Attacker observes a target's Cosmos-format public key `pk` (e.g. from any Cosmos tx the target has broadcast, from block explorers, or leaked otherwise) without needing the target's private key.
2. Attacker calls the `addr` precompile method `associatePubKey(pk)` from any EVM account.
3. `associatePublicKey` (precompiles/addr/addr.go:205-236) parses `pk`, derives `evmAddr`/`seiAddr` via `helpers.GetAddressesFromPubkeyBytes`, and calls `associateAddresses`, which is not gated by any signature check tying `pk` to the calling account.
4. `AssociateAddresses` (utils/helpers/associate.go:34-55) sets the address mapping, sets the account's pubkey, and calls `MigrateBalance`, moving any spendable coins/wei sitting at the `castAddr` (derived from `evmAddr`) into `seiAddr` — funds movement and permanent identity binding triggered entirely by the attacker's transaction, on behalf of the victim, without the victim's participation or consent.
5. Any subsequent legitimate `associate`/`associatePubKey` call by the true key owner for the same `seiAddr` now reverts with `"address %s is already associated with evm address %s"` (precompiles/addr/addr.go:243), permanently locking in the attacker-triggered association.

func (p PrecompileExecutor) associate(ctx sdk.Context, method *abi.Method, args []interface{}, value *big.Int) (ret []byte, remainingGas uint64, err error) {
	if err := pcommon.ValidateNonPayable(value); err != nil {
		return nil, 0, err
	}

	if err := pcommon.ValidateArgsLength(args, 4); err != nil {
		return nil, 0, err
	}

	// v, r and s are components of a signature over the customMessage sent.
	// We use the signature to construct the user's pubkey to obtain their addresses.
	v := args[0].(string)
	r := args[1].(string)
	s := args[2].(string)
	customMessage := args[3].(string)

	rBytes, err := decodeHexString(r)
	if err != nil {
		return nil, 0, err
	}
	sBytes, err := decodeHexString(s)
	if err != nil {
		return nil, 0, err
	}
	vBytes, err := decodeHexString(v)
	if err != nil {
		return nil, 0, err
	}

	vBig := new(big.Int).SetBytes(vBytes)
	rBig := new(big.Int).SetBytes(rBytes)
	sBig := new(big.Int).SetBytes(sBytes)

	// Derive addresses
	vBig = new(big.Int).Add(vBig, utils.Big27)

	customMessageHash := crypto.Keccak256Hash([]byte(customMessage))
	evmAddr, seiAddr, pubkey, err := helpers.GetAddresses(vBig, rBig, sBig, customMessageHash)
	if err != nil {
		return nil, 0, err
	}

	return p.associateAddresses(ctx, method, evmAddr, seiAddr, pubkey)

func (p PrecompileExecutor) associatePublicKey(ctx sdk.Context, method *abi.Method, args []interface{}, value *big.Int) (ret []byte, remainingGas uint64, err error) {
	if err := pcommon.ValidateNonPayable(value); err != nil {
		return nil, 0, err
	}

	if err := pcommon.ValidateArgsLength(args, 1); err != nil {
		return nil, 0, err
	}

	// Takes a single argument, a compressed pubkey in hex format, excluding the '0x'
	pubKeyHex := args[0].(string)

	pubKeyBytes, err := hex.DecodeString(pubKeyHex)
	if err != nil {
		return nil, 0, err
	}

	// Parse the compressed public key
	pubKey, err := btcec.ParsePubKey(pubKeyBytes)
	if err != nil {
		return nil, 0, err
	}

	// Convert to uncompressed public key
	uncompressedPubKey := pubKey.SerializeUncompressed()

	evmAddr, seiAddr, pubkey, err := helpers.GetAddressesFromPubkeyBytes(uncompressedPubKey)
	if err != nil {
		return nil, 0, err
	}

	return p.associateAddresses(ctx, method, evmAddr, seiAddr, pubkey)

func (p PrecompileExecutor) associateAddresses(ctx sdk.Context, method *abi.Method, evmAddr common.Address, seiAddr sdk.AccAddress, pubkey cryptotypes.PubKey) (ret []byte, remainingGas uint64, err error) {
	// Check that address is not already associated
	_, found := p.evmKeeper.GetEVMAddress(ctx, seiAddr)
	if found {
		return nil, 0, fmt.Errorf("address %s is already associated with evm address %s", seiAddr, evmAddr)
	}

	// Associate Addresses:
	associationHelper := helpers.NewAssociationHelper(p.evmKeeper, p.bankKeeper, p.accountKeeper)
	err = associationHelper.AssociateAddresses(ctx, seiAddr, evmAddr, pubkey, false)
	if err != nil {
		return nil, 0, err
	}

	ret, err = method.Outputs.Pack(seiAddr.String(), evmAddr)
	return ret, pcommon.GetRemainingGas(ctx, p.evmKeeper), err
}

func (p AssociationHelper) AssociateAddresses(ctx sdk.Context, seiAddr sdk.AccAddress, evmAddr common.Address, pubkey cryptotypes.PubKey, migrateUseiOnly bool) error {
	castAddr := sdk.AccAddress(evmAddr[:])
	if !castAddr.Equals(seiAddr) && p.accountKeeper.GetAccount(ctx, seiAddr) == nil {
		castAcc := p.accountKeeper.GetAccount(ctx, castAddr)
		castBaseAcc, ok := castAcc.(*authtypes.BaseAccount)
		if ok && castBaseAcc.GetPubKey() == nil && p.bankKeeper.LockedCoins(ctx, castAddr).IsZero() {
			p.accountKeeper.SetAccount(ctx, authtypes.NewBaseAccount(seiAddr, pubkey, castBaseAcc.GetAccountNumber(), castBaseAcc.GetSequence()))
		}
	}
	p.evmKeeper.SetAddressMapping(ctx, seiAddr, evmAddr)
	acc := p.accountKeeper.GetAccount(ctx, seiAddr)
	if acc == nil {
		acc = p.accountKeeper.NewAccountWithAddress(ctx, seiAddr)
	}
	if acc.GetPubKey() == nil {
		if err := acc.SetPubKey(pubkey); err != nil {
			return err
		}
		p.accountKeeper.SetAccount(ctx, acc)
	}
	return p.MigrateBalance(ctx, evmAddr, seiAddr, migrateUseiOnly)
}
