### Title
Flash-deposit reward-sniping via permissionless `harvest()` and snapshot-based reward accounting - (File: `wombat/WombatStaking.sol`, `rewards/BaseRewardPoolV2.sol`)

### Summary
`WombatStaking.harvest()` is a permissionless function that pulls pending WOM rewards from Wombat's `MasterWombat` and immediately distributes them to `BaseRewardPoolV2` via `queueNewRewards`, which spreads the harvested amount over the *current* `totalStaked()` snapshot with no time-weighting. Because deposits/withdrawals via `WombatPoolHelper` have no lock-up or cooldown, an attacker can inflate their share of `totalStaked()` immediately before triggering a harvest, capture a disproportionate slice of yield that accrued to long-term depositors, and withdraw right after — the same "sandwich the profit-distribution event" pattern described in the referenced report.

### Finding Description
`harvest()` is callable by anyone as long as the pool is active [1](#0-0) , and internally calls `_toMasterWomAndSendReward`, which withdraws/harvests pending WOM from `MasterWombat` and forwards it to the pool's rewarder via `_sendRewards` → `queueNewRewards` [2](#0-1) [3](#0-2) .

In `BaseRewardPoolV2`, `_provisionReward` (invoked by `queueNewRewards`) distributes the newly harvested amount by dividing it by `totalStaked()`, which is simply the *current* balance of the staking token held by `MasterMagpie` at the moment of the call — a single snapshot, not a time-weighted accrual: [4](#0-3) . `totalStaked()` itself is defined as the live balance: [5](#0-4) .

Deposits and withdrawals through `WombatPoolHelper` have no lock or cooldown period before a user can exit — `deposit`/`depositLP` and `withdraw` can be called back-to-back in the same transaction/block [6](#0-5) . `WombatStaking.deposit`/`depositLP` mint the receipt token to the depositor only *after* triggering `_toMasterWomAndSendReward` for the pre-deposit state [7](#0-6) , so a depositor's own deposit call does not dilute existing holders — but this only protects the deposit step, not a **separate, immediately-following** call to the permissionless `harvest()`.

This allows the following flow within one block (or few blocks):
1. Attacker calls `depositLP`/`deposit` with a very large amount of LP tokens, minting a large receipt-token balance and inflating `totalStaked()` in `MasterMagpie`.
2. Attacker (or anyone) calls `WombatStaking.harvest(lpToken)` directly — no restriction prevents calling it a second time right after a deposit. Any WOM rewards that had accrued in `MasterWombat` since the last harvest (potentially significant, since `harvest` can be neglected for a while) get pulled and immediately spread pro-rata over the now-inflated `totalStaked()`.
3. Attacker calls `getReward`/claims their share of the newly queued reward, then immediately calls `withdraw` to exit their large LP position.

Because `rewardPerTokenStored` accounting has no vesting or minimum holding period, the attacker captures a share of yield proportional to their temporarily-inflated stake even though they held no position while that yield was accruing, diluting the rewards owed to genuine long-term LPs — directly analogous to the flash-loan sandwich of a profit-realization event in the referenced Malt finding.

### Impact Explanation
This is a direct theft of unclaimed yield from legitimate LPs/stakers: the WOM rewards that accrued over time to existing depositors are redistributed to a flash/JIT depositor who never bore the risk or time exposure that generated the yield. This matches the "theft or permanent freezing of unclaimed yield" acceptance criterion.

### Likelihood Explanation
`harvest()` is explicitly permissionless and expected to be called by anyone (it has no `onlyOwner`/`onlyManager` restriction, only `whenNotPaused` and `_onlyActivePool`) [1](#0-0) . Deposits/withdrawals have no cooldown, so the attack requires only capital (which can be flash-loaned if a lending market for the LP/deposit token exists) and gas, making it executable by any ordinary wallet whenever a meaningful amount of unharvested WOM has accumulated.

### Recommendation
- Make reward accrual time-weighted per staker (e.g., checkpoint balances and integrate rewards over the staking duration) rather than a single `amount / totalStaked()` snapshot at harvest time.
- Alternatively, introduce a minimum holding/cooldown period between deposit and withdrawal (or between deposit and reward eligibility) in `WombatPoolHelper`/`WombatStaking` to prevent same-block or same-transaction deposit-harvest-withdraw sequences.
- Consider restricting who can trigger `harvest()` opportunistically, or debouncing it (e.g., minimum interval since last harvest) to reduce the window for stake-inflation attacks.

### Proof of Concept
1. Let a nontrivial amount of WOM rewards accrue in `MasterWombat` for a given pool (i.e., nobody has called `harvest()` for a while).
2. Attacker calls `WombatPoolHelper.depositLP(largeAmount)` → `WombatStaking.depositLP` mints a large receipt-token balance to the attacker, inflating `MasterMagpie`'s tracked `totalStaked()` for that pool [8](#0-7) .
3. Attacker (or an accomplice) calls `WombatStaking.harvest(lpToken)` in the same/next block, which pulls the pending WOM and calls `queueNewRewards`, computing `rewardPerTokenStored += amount * 10**decimals / totalStaked()` using the now-inflated `totalStaked()` [9](#0-8) .
4. Attacker claims their proportional share via the rewarder's `getReward`, then calls `WombatPoolHelper.withdraw` to exit the large LP position immediately [10](#0-9) .
5. Net effect: attacker captured yield proportional to a stake they held for a single block, at the expense of long-term LPs who actually earned it.

        Pool storage poolInfo = pools[_lpToken];

        address[] memory bonusTokens = assetToBonusRewards[_lpToken];
        uint256 bonusTokensLength = bonusTokens.length;

        uint256 womBeforeBalance = IERC20(wom).balanceOf(address(this));

            _stakeToWombatMaster(_lpToken, lpAmount); // triggers harvest from wombat exchange

        uint256 womRewards = IERC20(wom).balanceOf(address(this)) - womBeforeBalance;
        _sendRewards(_lpToken, wom, poolInfo.rewarder, womRewards);

        for (uint256 i; i < bonusTokensLength; i++) {
            uint256 bonusBalanceDiff = IERC20(bonusTokens[i]).balanceOf(address(this)) - beforeBalances[i];

                _sendRewards(_lpToken, bonusTokens[i], poolInfo.rewarder, bonusBalanceDiff);
            }
        }

    function _sendRewards(
        address _lpToken,
        address _rewardToken,
        address _rewarder,
        uint256 _amount
    ) internal {
        if (_amount == 0) return;
        uint256 originalRewardAmount = _amount;

        if (!isPoolFeeFree[_lpToken]) {
            for (uint256 i = 0; i < feeInfos.length; i++) {
                Fees storage feeInfo = feeInfos[i];

                if (feeInfo.isActive) {
                    address rewardToken = _rewardToken;
                    uint256 feeAmount = (originalRewardAmount * feeInfo.value) / DENOMINATOR;
                    _amount -= feeAmount;
                    uint256 feeTosend = feeAmount;

                    if (feeInfo.isMWOM && rewardToken == wom) {
                        if (smartWomConverter != address(0)) {
                            IERC20(wom).safeApprove(smartWomConverter, feeAmount);
                            uint256 beforeBalnce = IMWom(mWom).balanceOf(address(this));
                            IConverter(smartWomConverter).smartConvert(feeAmount, 0);
                            rewardToken = mWom;
                            feeTosend = IMWom(mWom).balanceOf(address(this)) - beforeBalnce;
                        } else {
                            IERC20(wom).safeApprove(mWom, feeAmount);
                            uint256 beforeBalnce = IMWom(mWom).balanceOf(address(this));
                            IMWom(mWom).deposit(feeAmount);
                            rewardToken = mWom;
                            feeTosend = IMWom(mWom).balanceOf(address(this)) - beforeBalnce;
                        }
                    }

                    if (!feeInfo.isAddress) {
                        IERC20(rewardToken).safeApprove(feeInfo.to, 0);
                        IERC20(rewardToken).safeApprove(feeInfo.to, feeTosend);
                        IBaseRewardPool(feeInfo.to).queueNewRewards(feeTosend, rewardToken);
                    } else {
                        IERC20(rewardToken).safeTransfer(feeInfo.to, feeTosend);
                        emit RewardPaidTo(feeInfo.to, rewardToken, feeTosend);
                    }
                }
            }
        }

        IERC20(_rewardToken).safeApprove(_rewarder, 0);
        IERC20(_rewardToken).safeApprove(_rewarder, _amount);
        IBaseRewardPool(_rewarder).queueNewRewards(_amount, _rewardToken);

    function _provisionReward(uint256 _amountReward, address _rewardToken) internal {
        IERC20(_rewardToken).safeTransferFrom(
            msg.sender,
            address(this),
            _amountReward
        );
        Reward storage rewardInfo = rewards[_rewardToken];
        rewardInfo.historicalRewards =
            rewardInfo.historicalRewards +
            _amountReward;

        if (totalStaked() == 0) {
            rewardInfo.queuedRewards += _amountReward;
        } else {
            if (rewardInfo.queuedRewards > 0) {
                _amountReward += rewardInfo.queuedRewards;
                rewardInfo.queuedRewards = 0;
            }
            rewardInfo.rewardPerTokenStored =
                rewardInfo.rewardPerTokenStored +
                (_amountReward * 10**stakingTokenDecimals) /
                totalStaked();
        }
        emit RewardAdded(_amountReward, _rewardToken);
