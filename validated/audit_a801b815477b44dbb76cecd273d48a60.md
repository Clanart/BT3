### Title
TextFormat `printAny` writes attacker-controlled `type_url` into the debug-string bracket syntax without any escaping - ([File: java/core/src/main/java/com/google/protobuf/TextFormat.java])

### Summary
The external report is about Zope2's `ZPublisher.HTTPRequest._scrubHeader`, which fails to strip LF characters from attacker-controlled data before it is embedded into the raw HTTP header text stream, letting an attacker inject additional headers/response content by breaking the delimiter semantics of a structured text protocol. The transferable invariant is: *when an attacker-controlled string is embedded into a structured/delimited text output, every character that has special meaning in that format's grammar (here, control characters and the format's own delimiters) must be escaped before being written, or the attacker can inject extra structure.*

TextFormat is protobuf's own delimited text protocol, and its normal string-field printer (`TextFormatEscaper.escapeText`, `java/core/src/main/java/com/google/protobuf/TextFormatEscaper.java:93-149`) enforces exactly this invariant for STRING fields [1](#0-0) . However, `Printer.printAny()` bypasses this escaping entirely for the `type_url` field of a `google.protobuf.Any` message and writes it verbatim between the bracket delimiters `[` and `]` that constitute TextFormat's own Any-expansion syntax.

### Finding Description
`TextFormat.Printer.printAny()` reads the `type_url` string field directly from the parsed message and prints it unescaped: [2](#0-1) 

Compare this to the normal STRING field-printing path, which always routes through `TextFormatEscaper.escapeText`/`escapeDoubleQuotesAndBackslashes`, escaping newlines, carriage returns, quotes, backslashes, and other control characters: [1](#0-0) 

`printAny` is invoked automatically whenever a message's descriptor full name is `google.protobuf.Any`, on every call to `Printer.print()` (i.e., on `DebugString()`, `ShortDebugString()`, `TextFormat.printToString()`, etc.) — there is no opt-in flag in the Java implementation: [3](#0-2) 

`type_url` is an ordinary proto3 `string` field of `Any` [4](#0-3) , so any client that can get a bounded, well-formed binary/ProtoJSON payload containing an `Any` submessage parsed into memory (a `MergeFrom`/`ParseFrom` call using a schema that includes `Any`, which is common) fully controls its byte content: `\n`, `\r`, `"`, `]`, `{`, `}` are all legal bytes in a proto3 string field and require no schema or registry cooperation. The type-resolution step (`typeRegistry.getDescriptorForTypeUrl`) only needs the trailing `/full.type.Name` suffix to match a known type; the URL prefix before the last `/` is completely free-form and is never validated or escaped before being printed [5](#0-4) .

This differs from the C++ implementation, which parses the URL through `internal::ParseAnyTypeUrl`, which validates the prefix against a restricted URI character set and validates the trailing type name as dot-separated identifiers before printing — rejecting control characters, `]`, `{`, etc. — as documented in `any.proto`'s comment on the allowed character set (`/-.~_!$&()*+,;=`, percent-encoding only) [6](#0-5) [7](#0-6) . The Java path has no equivalent validation before printing — it merely checks `typeUrl.isEmpty()` and successfully resolving a `Descriptor` for the suffix; the raw string is used as-is for both bracket display and (implicitly) trusted to not contain delimiter-breaking characters.

### Impact Explanation
`DebugString()`/`toString()`/`TextFormat.printToString()` output is widely consumed for logging, debugging dashboards, test assertions, and sometimes fed back into `TextFormat.merge()` by tooling that treats it as a structured, re-parseable format. If `type_url` contains characters such as `]`, `\n`, `{`/`}`, an attacker can:
- Break out of the intended `[type_url] { ... }` bracket structure, injecting fabricated field lines that appear to belong to the outer/sibling message in log lines or diagnostic tools that scrape TextFormat output.
- Corrupt round-tripping: TextFormat is documented as being able to re-parse its own DebugString output for many uses (tests, RPC debugging tools); an unescaped `type_url` value breaks the grammar and can silently misattribute injected fake field/value pairs, an integrity failure of the produced text artifact analogous to header/response splitting in HTTP.

This does not itself grant memory corruption or code execution; the impact is confined to corruption/misrepresentation of the produced text artifact and any downstream logic (log parsers, diff tools, alerting pipelines) that trusts TextFormat's grammar — consistent with the "confidentiality: none, integrity: high" profile of the CVE-2012-5486 analog.

### Likelihood Explanation
Reaching this code only requires:
1. A schema that includes `google.protobuf.Any` (extremely common, e.g. gRPC status details, event/audit systems),
2. An attacker able to supply the bytes for that `Any.type_url` field through any supported public parse API (`mergeFrom`, JSON parse, etc.), and
3. Application code (or protobuf's own logging/toString paths) calling `DebugString()`/`toString()`/`TextFormat.printToString()` on the parsed message — again very common in error/log paths.

No malicious schema, forged MiniTable, or privileged access is needed. This makes the likelihood high, though the practical blast radius depends on what "consumes" the produced text (the same assumption CVE-2012-5486 makes about an HTTP-layer consumer of the injected header).

### Recommendation
In `TextFormat.Printer.printAny()`, escape `typeUrl` (via `TextFormatEscaper.escapeText`) before printing it between the `[`/`]` delimiters, or — matching the C++ behavior — validate the type URL's prefix/type-name character set (reject control characters, unescaped `]`, `{`, `}`, whitespace, etc.) before accepting it into the bracket syntax. This should mirror the validation already performed by `internal::ParseAnyTypeUrl`/`ConsumeAnyTypeUrlOrFullTypeName` in the C++ implementation.

### Proof of Concept
Conceptually (not executed, no test harness available in this session):
1. Construct a `DynamicMessage` (or a message with an `Any` field) where `Any.type_url` is set to a value such as `type.googleapis.com/proto2_unittest.TestAllTypes]\noptional_int32: 999 #`, and `Any.value` is a valid serialized `TestAllTypes`.
2. Call `TextFormat.printer().usingTypeRegistry(registryWithTestAllTypes).printToString(message)`.
3. Expected (safe) output would escape the injected `]`/`\n`; actual output based on the traced code path at `java/core/src/main/java/com/google/protobuf/TextFormat.java:459-461` prints the type_url raw, producing malformed/injected TextFormat structure such as:
   ```
   value {
     [type.googleapis.com/proto2_unittest.TestAllTypes]
   optional_int32: 999 #] {
       optional_int32: 12345
     }
   }
   ```
   demonstrating that the bracket/field grammar of the produced text is corrupted by attacker-controlled content, analogous to a header/line-injection in the Zope2 case. This was traced from source; it was not executed against a live build in this session, so exact byte-for-byte output should be confirmed by a build/test run before filing.

message Any {
  // Identifies the type of the serialized Protobuf message with a URI reference
  // consisting of a prefix ending in a slash and the fully-qualified type name.
  //
  // Example: type.googleapis.com/google.protobuf.StringValue
  //
  // This string must contain at least one `/` character, and the content after
  // the last `/` must be the fully-qualified name of the type in canonical
  // form, without a leading dot. Do not write a scheme on these URI references
  // so that clients do not attempt to contact them.
  //
  // The prefix is arbitrary and Protobuf implementations are expected to
  // simply strip off everything up to and including the last `/` to identify
  // the type. `type.googleapis.com/` is a common default prefix that some
  // legacy implementations require. This prefix does not indicate the origin of
  // the type, and URIs containing it are not expected to respond to any
  // requests.
  //
  // All type URL strings must be legal URI references with the additional
  // restriction (for the text format) that the content of the reference
  // must consist only of alphanumeric characters, percent-encoded escapes, and
  // characters in the following set (not including the outer backticks):
  // `/-.~_!$&()*+,;=`. Despite our allowing percent encodings, implementations
  // should not unescape them to prevent confusion with existing parsers. For
  // example, `type.googleapis.com%2FFoo` should be rejected.
  //
  // In the original design of `Any`, the possibility of launching a type
  // resolution service at these type URLs was considered but Protobuf never
  // implemented one and considers contacting these URLs to be problematic and
  // a potential security issue. Do not attempt to contact type URLs.
  string type_url = 1;
