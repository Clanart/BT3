## Finding: Near-Zero `tokenPrice` Rounding in `SimplexPaymaster` Allows Free Gas Sponsorship

The CGDA report's core broken invariant is: **an integer/fixed-point pricing formula, fed by a legitimate combination of parameter magnitudes, can round down to (near-)zero, and nothing in the contract enforces a floor.** The local analog in this repo is `SimplexPaymaster._tokenPrice` at [1](#0-0) , which is consumed by OpenZeppelin's `PaymasterERC20._erc20Cost` (documented inline as `erc20Cost = weiCost * tokenPrice / 1e18`, see [2](#0-1) ).

### Title
Integer-division truncation in `SimplexPaymaster._tokenPrice` can zero out the ERC-20 gas price, letting any user sponsor gas for free and drain the paymaster's EntryPoint deposit — (File: `evm/src/utils/SimplexPaymaster.sol`)

### Summary
`_tokenPrice` computes `(nativeUsd * 10^tokenDecimals * (10000+markupBps)) / (tokenUsd * 10000)` using two independently-sourced, legitimate Chainlink price feeds and a governance-set `tokenDecimals`/`markupBps`. For any registered token whose USD value is large relative to `nativeUsd * 10^tokenDecimals`, Solidity's floor division drives `tokenPrice` to `0`. Since `PaymasterERC20._erc20Cost` multiplies by `tokenPrice`, a zero price makes every subsequent gas sponsorship using that token cost `0` tokens — exactly the "near-zero/zero-value swap" class flagged in the CGDA report, for which the accepted mitigation was to explicitly forbid a zero-value outcome.

### Finding Description
`_tokenPrice` at [1](#0-0)  has no floor/minimum check. `_getOraclePrice` at [3](#0-2)  only rejects stale or non-positive answers — it does not bound the *ratio* between the native-asset price and a registered token's price.

Governance can legitimately register any ERC-20 with a Chainlink feed via `RegisterToken` ( [4](#0-3) , `_registerToken` at line 243), including a token whose per-unit USD value is far larger than `nativeUsd` scaled by its own decimals (e.g., an 8-decimal wrapped-BTC-style token at $60,000 on a chain whose native gas asset trades at a few cents). This is a normal, non-malicious governance/oracle configuration — no compromised admin, oracle, or peer is required.

Once such a token is active, `_fetchDetails` ( [5](#0-4) ) is called by *any* unprivileged user submitting a `PackedUserOperation` with that token in `paymasterData`, and it returns `tokenPrice = 0`. `PaymasterERC20._erc20Cost` (inherited, not reproduced here but referenced in the doc comment) then computes `erc20Cost = weiCost * 0 / 1e18 = 0`, so the `transferFrom`/`permit` prefund step pulls zero tokens while the paymaster still pays the real gas cost out of its EntryPoint deposit (funded via `swapAndDeposit`, [6](#0-5) ).

### Impact Explanation
This is a direct loss-of-funds path: the paymaster's EntryPoint-deposited native balance — funded by the protocol/treasury — is drained by unlimited free-gas UserOperations, with the attacker paying nothing in the nominally-required ERC-20. This matches the bounty's "stealing or loss of funds" / "logic attacks" categories: an unprivileged caller triggers unauthorized-value execution (zero-cost sponsorship) purely through normal, permissionless paymaster usage once a legitimately-registered token's price ratio crosses the truncation threshold.

### Likelihood Explanation
No malicious relayer, prover, governance actor, or leaked key is needed. The only precondition is a registered token/native-asset price pair (governance-set, not attacker-controlled) whose ratio pushes `tokenPrice` below `1` under floor division — plausible for low-decimal, high-USD-value tokens paired with a low-USD-value native gas asset, which is a realistic deployment scenario (e.g., an inflated or otherwise low-priced native chain token). Every UserOp using that token thereafter is exploitable by anyone with EntryPoint access, with no code path re-checking `tokenPrice != 0`.

### Recommendation
Add an explicit floor check in `_tokenPrice` (and/or `_fetchDetails`/`estimateTokenCost`) that reverts when the computed price is `0` (or below some minimum non-zero value), mirroring the CGDA fix's requirement that near-zero/zero-price scenarios be blocked rather than silently accepted. Additionally, validate at `RegisterToken` time that the token/native price ratio, combined with `tokenDecimals`, cannot degrade `tokenPrice` to zero across the oracle's expected price range.

### Proof of Concept
1. Governance registers a native oracle reporting `nativeUsd = $0.01` (8-decimal Chainlink format → `1e6`) and registers a token (e.g., an 8-decimal wrapped asset) whose oracle reports `tokenUsd = $60,000` (→ `6e12`), with `markupBps = 500`.
2. Compute `_tokenPrice`: `(1e6 * 1e8 * 10500) / (6e12 * 10000) = 1.05e15 / 6e16 = 0.0175` → floors to `0` in Solidity integer division.
3. Any user submits a `PackedUserOperation` with `paymasterData` mode `0x01` (approve) referencing this token; `_fetchDetails` returns `tokenPrice = 0`.
4. `PaymasterERC20._erc20Cost` computes `erc20Cost = weiCost * 0 / 1e18 = 0`; the prefund `transferFrom` pulls `0` tokens from the sender while the EntryPoint still deducts real gas cost from `SimplexPaymaster`'s deposit — repeatable indefinitely to drain the deposit. [7](#0-6) [8](#0-7)

    /// @dev Returns the token to charge and its price relative to native gas.
    ///
    ///      PaymasterERC20 computes `erc20Cost = weiCost * tokenPrice / 1e18`,
    ///      so tokenPrice must be token base units per wei, scaled by 1e18:
    ///        tokenPrice = (nativeUsd * 10^tokenDecimals) / tokenUsd
    ///      e.g. BNB at $600, USDC at $1 with 6 decimals: 0.001 BNB (1e15 wei)
    ///      should cost 0.60 USDC (600000 units), giving tokenPrice = 6e8, which
    ///      is exactly (600e8 * 1e6) / 1e8. Markup is applied on top.
    function _fetchDetails(
        PackedUserOperation calldata userOp,
        bytes32 /* userOpHash */
    ) internal view override returns (uint256 validationData, IERC20 token, uint256 tokenPrice) {
        bytes calldata data = userOp.paymasterData();
        if (data.length < 21) revert InvalidPaymasterData(data.length);

        uint8 mode = uint8(data[0]);
        if (mode > 0x01) revert InvalidMode(mode);

        address tokenAddr = address(bytes20(data[1:21]));

        TokenConfig memory cfg = tokenConfigs[tokenAddr];
        if (address(cfg.tokenOracle) == address(0)) revert TokenNotRegistered(tokenAddr);
        if (!cfg.active) revert TokenNotActive(tokenAddr);

        tokenPrice = _tokenPrice(cfg);
        token = IERC20(tokenAddr);
        validationData = 0; // no time-range restriction
    }

    function _tokenPrice(TokenConfig memory cfg) internal view returns (uint256) {
        uint256 nativeUsd = _getOraclePrice(nativeOracle, nativeOracleDecimals);
        uint256 tokenUsd = _getOraclePrice(cfg.tokenOracle, cfg.tokenOracleDecimals);

        return (nativeUsd * (10 ** cfg.tokenDecimals) * (10_000 + markupBps)) / (tokenUsd * 10_000);
    }

    /// @dev Fetch a Chainlink price normalized to 8 decimals.
    ///      Reverts on stale or non-positive answers.
    function _getOraclePrice(AggregatorV3Interface oracle, uint8 oracleDecimals) internal view returns (uint256) {
        (, int256 answer, , uint256 updatedAt, ) = oracle.latestRoundData();

        if (answer <= 0) revert InvalidOraclePrice(address(oracle), answer);
        if (block.timestamp - updatedAt > maxOracleAge) {
            revert StaleOraclePrice(address(oracle), updatedAt);
        }

        if (oracleDecimals < 8) {
            return uint256(answer) * (10 ** (8 - oracleDecimals));
        } else if (oracleDecimals > 8) {
            return uint256(answer) / (10 ** (oracleDecimals - 8));
        }
        return uint256(answer);
    }
