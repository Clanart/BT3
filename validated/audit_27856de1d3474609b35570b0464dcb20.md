### Title
Unpriced super-linear ABI-decode cost in static Cosmos precompiles allows CPU-DoS-for-cheap on EVM calls - (File: precompiles/common/precompiles.go)

### Summary
The `TraceContextPropagator.Extract` advisory is a case where a header is parsed at a cost far higher than what the caller is charged for supplying it, letting a single request burn disproportionate CPU. The same *underpriced-parse* pattern exists in sei-chain's static (non-dynamic-gas) Cosmos precompiles: `RequiredGas` is charged linearly per input byte, but the actual argument decode performed in `Prepare` can cost up to `O(len(input)^2)` when calldata encodes ABI types containing strings, because the Go ABI decoder copies each string payload once per slot that references it.

### Finding Description
`precompiles/common/precompiles.go` defines the generic static-precompile flow used by `bank`, `gov`, `addr`, `auth`, `authz`, `evidence`, and `params` precompiles: [1](#0-0) 

`RequiredGas` simply delegates to the module-specific executor's `RequiredGas(input[4:], method)`, and go-ethereum's `vm.RunPrecompiledContract` uses this value only as a *pre-check* (`suppliedGas >= RequiredGas(input)`) before calling `Run`. `Run` then calls `Prepare`, which unconditionally does the real decode: [2](#0-1) 

For the legacy static precompile variant (same pattern, still shipped for older EVM upgrade heights): [3](#0-2) 

The codebase's own documentation of the decode cost confirms the danger of doing this unpriced: [4](#0-3) 

The fix for this exact problem — bounding/pricing the decode *before* calling `Unpack` — was implemented, but only for the `DynamicGasPrecompile` code path (`RunAndCalculateGas` / `chargeDecodeGas`), which the code comments explicitly say bypasses the static `RequiredGas` pre-check: [5](#0-4) [6](#0-5) 

Static precompiles (bank/gov/addr/auth/authz/evidence/params), however, still call `method.Inputs.Unpack(argsBz)` directly in `Prepare` with only a flat/linear `RequiredGas` charge computed from `len(argsBz)` (as seen in the legacy `RequiredGas` implementation), never invoking `DecodeGasCost`/`decodeStringCopyBytes`. `DecodeGasCost` and its `maxDecodeWalkOps` traversal cap exist only in `precompiles/common/precompiles.go`'s `DynamicGasPrecompile` path and the generated `v67` copy — not wired into the static `Precompile.RequiredGas`/`Prepare` used by the other precompile modules.

### Impact Explanation
Any of the affected static precompiles that expose a method accepting a dynamic ABI type capable of containing strings (`string`, `string[]`, or tuples/arrays containing strings) is reachable by an unprivileged EVM transaction sender or `eth_call`/`eth_estimateGas` RPC caller. Because go-ethereum only requires `suppliedGas >= RequiredGas(input)` (linear in `len(input)`) before invoking `Run`→`Prepare`→`Unpack`, an attacker can construct calldata whose ABI-encoded array/tuple slots reference overlapping string payloads, causing the decoder inside `Prepare` to perform up to `O(len(input)^2)` byte-copy work while paying only linear gas for it. This can be triggered by a single submitted EVM transaction (consuming validator CPU during block execution) or hammered via public JSON-RPC `eth_call`/`eth_estimateGas` against a full/RPC node, degrading node performance — a resource-exhaustion issue analogous to the `TraceContextPropagator.Extract` CWE-770 CPU-DoS.

### Likelihood Explanation
Exploitability depends on whether any reachable static precompile method signature actually contains a dynamic string-bearing type in its ABI arguments (this could not be fully confirmed within the available investigation — enumerating every precompile module's ABI method signatures for string-containing dynamic types was not completed). If such a method exists (e.g. in `gov`, which commonly takes string metadata/JSON fields), the attack requires no privilege, no funds beyond intrinsic gas, and no cooperation from any other party, making likelihood Medium-High conditional on that method-signature confirmation.

### Recommendation
Route all static (non-dynamic-gas) `Precompile.Prepare`/`RequiredGas` implementations through the same `DecodeGasCost`/`decodeStringCopyBytes` pricing and `maxDecodeWalkOps` bound already implemented for `DynamicGasPrecompile`, so the pre-check gas value reflects the true worst-case decode cost (or reject/charge before calling `Unpack`) for every precompile module that accepts dynamic string-bearing ABI types.

### Proof of Concept
Not fully constructible without confirming which static precompile method(s) accept string-containing dynamic ABI arguments; the mechanism (linear `RequiredGas` pre-check vs. potentially quadratic `Unpack` cost documented in `precompiles/common/decode_cost.go`) is demonstrated by code inspection above, but an end-to-end exploit transaction against a specific precompile method was not verified in this pass.

		return sdk.Context{}, nil, nil, err

		return sdk.Context{}, nil, nil, err
	}

// chargeDecodeGas charges the (already-installed) gas meter for decoding the
// calldata, before it is decoded: a length-proportional scan cost that also
// bounds the DecodeGasCost scan, then the string-copy surcharge from
// DecodeGasCost. Its out-of-gas / overflow recovery is deliberately scoped to
// just these charges — a call that cannot afford the decode reverts here, while
// an executor that later exhausts its gas keeps its normal propagating
// out-of-gas semantics. Anything other than a gas-meter panic is re-raised.
func (d DynamicGasPrecompile) chargeDecodeGas(ctx sdk.Context, method *abi.Method, input []byte) (err error) {
	defer func() {
		if r := recover(); r != nil {
			switch r.(type) {
			case sdk.ErrorOutOfGas, sdk.ErrorGasOverflow:
				err = fmt.Errorf("%v", r)
			default:
				panic(r)
			}
		}
	}()
	scanCost := DefaultGasCost(input, false)
	ctx.GasMeter().ConsumeGas(scanCost, fmt.Sprintf("%s precompile calldata scan", d.name))
	decodeCost, ok := DecodeGasCost(method.Inputs, input)
	if !ok {
		// Calldata is structurally invalid (Unpack would reject it too); reject
		// now, without attempting the decode.
		return fmt.Errorf("invalid calldata encoding for %s", d.name)
	}
	// DecodeGasCost already includes scanCost; charge only the remaining
	// (string-copy) portion so the decode is priced exactly once.
	ctx.GasMeter().ConsumeGas(decodeCost-scanCost, fmt.Sprintf("%s precompile calldata decode", d.name))
	return nil
}

func (p Precompile) RequiredGas(input []byte, isTransaction bool) uint64 {
	argsBz := input[4:] // first four bytes are method ID

	if isTransaction {
		return storetypes.KVGasConfig().WriteCostFlat + (storetypes.KVGasConfig().WriteCostPerByte * uint64(len(argsBz)))
	}

	return storetypes.KVGasConfig().ReadCostFlat + (storetypes.KVGasConfig().ReadCostPerByte * uint64(len(argsBz)))
}

// DecodeGasCost returns the gas to charge for ABI-decoding a dynamic precompile
// call's calldata (the full input, including the 4-byte selector) given the
// method's argument list. ok is false when the calldata is structurally invalid
// (or too deeply nested to price cheaply); the caller should reject such input
// rather than decode it, since the real decoder would reject it too.
//
// The Go ABI decoder's cost is dominated by copying `string` payloads: it
// materializes each string via string(output[begin:end]), and because a single
// string can be referenced by many array/tuple slots, the copied volume can be
// super-linear in len(input) (worst case ~len(input)^2). `bytes` values are
// excluded because the decoder reslices them without copying. The charge is
// therefore a linear pass over the input (DefaultGasCost) plus the string-copy
// volume the decoder would produce, priced at the KV read-per-byte rate.
