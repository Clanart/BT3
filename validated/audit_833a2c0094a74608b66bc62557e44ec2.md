### Title
Unauthenticated OP_RETURN operator attribution in `payout_tx` allows misattributed/stolen reimbursement credit - (File: core/src/builder/transaction/operator_reimburse.rs)

### Summary
The `payout_tx` created by `create_payout_txhandler` spends the user's withdrawal UTXO using only a `SinglePlusAnyoneCanPay` signature over input 0 / output 0, while the OP_RETURN output that records *which operator fronted the withdrawal* is never covered by that signature. Any party who obtains the pre-signed withdrawal input (broadcast on the P2P network before confirmation, or otherwise available) can rebuild and rebroadcast the transaction with a different operator's `xonly_pk` in the OP_RETURN output, hijacking the reimbursement credit that the downstream kickoff/BitVM flow relies on.

### Finding Description
`create_payout_txhandler` builds the payout with:
- Input 0: the user's withdrawal UTXO, spent via `SpendPath::KeySpend` and signed only with the user's `taproot::Signature` (`SinglePlusAnyoneCanPay`).
- Output 0: user's payout.
- Output 1: anchor.
- Output 2: an OP_RETURN containing `operator_xonly_pk`, the identity that will later be credited with fronting the payout. [1](#0-0) 

`SIGHASH_SINGLE | ANYONECANPAY` only commits to the single input being spent and the output at the *same index* (index 0). It does **not** commit to output 1 (anchor) or output 2 (the OP_RETURN carrying `operator_xonly_pk`). This is confirmed by the operator's own `withdraw` flow, which verifies the user signature strictly against `sighash_txin(0, ...)`: [2](#0-1) 

Because the OP_RETURN payload is not bound by any signature, any party who can see the partially-broadcast/mempool transaction (or otherwise reconstruct the same signed input+output-0 pair) can build an alternative transaction spending the same withdrawal UTXO with the same valid witness, but substituting an arbitrary registered operator's `xonly_pk` in the OP_RETURN output, and get it confirmed instead (e.g. via fee-bumping/RBF race).

Downstream, the confirmed OP_RETURN value is the sole source of truth for "who paid":
- `update_finalized_payouts` parses the OP_RETURN of whichever payout tx actually confirms and writes it as `payout_payer_operator_xonly_pk` for that withdrawal index, with no further authentication. [3](#0-2) 
- This DB column is exclusively used to determine the credited operator: `get_payout_info_from_move_txid`/`get_first_unhandled_payout_by_operator_xonly_pk` key off it. [4](#0-3) 
- `validate_payer_is_operator` then trusts this column to decide which operator is authorized to drive the reimbursement/kickoff flow for the deposit. [5](#0-4) 
- `PayoutCheckerTask` automatically picks up "unhandled payouts" attributed to the local operator's own `xonly_public_key` and proceeds to kickoff/handle reimbursement without any further check that the operator actually funded the payout. [6](#0-5) 
- `is_kickoff_malicious` similarly trusts the OP_RETURN-derived operator key to decide whether a kickoff for that deposit is legitimate. [7](#0-6) 

The equality the protocol needs to hold is:
`operator credited in payout_payer_operator_xonly_pk == operator whose broadcast tx actually paid/fronted the withdrawal`

Because the OP_RETURN is unsigned, this equality can be broken by any unprivileged third party who intercepts the in-flight payout transaction and substitutes the OP_RETURN before confirmation, since the tx is otherwise still valid (input signature only binds input+output 0).

### Impact Explanation
This breaks the "operator credited versus the party that paid" binding explicitly called out as in-scope Critical impact. Consequences:
- An operator that never fronted a payout can be recorded as the payer and then automatically proceed through `PayoutCheckerTask`/kickoff to be reimbursed for a payout it never fronted (Critical: "an operator reimbursed for a payout it never funded").
- Since `payout_payer_operator_xonly_pk`/`payout_txid` are recorded once per withdrawal index (first-confirmed transaction wins, see `update_payout_txs_and_payer_operator_xonly_pk`), the honest operator that actually raced to pay/broadcast the original payout can be permanently excluded from being credited for that withdrawal (Critical: "an honest operator permanently unable to be reimbursed").

### Likelihood Explanation
Exploitation requires only observing an unconfirmed `payout_tx` (e.g. in the mempool) before it confirms and winning a fee/RBF race with a modified OP_RETURN — no operator, verifier, watchtower, or privileged role is required, and no secret key of the impersonated operator is needed since the OP_RETURN is plaintext public data. The window exists for every non-optimistic payout, making this a broadly reachable, purely network-level attack once a payout transaction is visible pre-confirmation.

### Recommendation
Bind the operator attribution to the signature that actually authorizes the payout, e.g. by using `SIGHASH_ALL` (or `SIGHASH_SINGLE|ANYONECANPAY` combined with covering the OP_RETURN output within the signed output set) so the OP_RETURN operator identity cannot be altered without invalidating the user's signature, or otherwise cryptographically commit the crediting operator's identity as part of the presigned withdrawal request rather than deriving it post-hoc from a mutable on-chain OP_RETURN.

### Proof of Concept
1. Operator A calls `withdraw`, which builds `payout_tx` via `create_payout_txhandler` with output 2 = OP_RETURN(A.xonly_pk), signed only over input 0 / output 0 with `SinglePlusAnyoneCanPay`. [2](#0-1) 
2. Operator A broadcasts `payout_tx` to the Bitcoin network; it enters the mempool unconfirmed.
3. Attacker observes the mempool transaction, copies the input (with A's still-valid witness, since it only commits input 0 + output 0) and output 0, but replaces output 2 with OP_RETURN(B.xonly_pk) for an arbitrary registered operator B, and rebroadcasts with a higher fee (RBF) so it displaces A's transaction.
4. Once mined, `update_finalized_payouts` parses the confirmed tx's OP_RETURN and records B as `payout_payer_operator_xonly_pk` for that withdrawal index. [8](#0-7) 
5. Operator B's `PayoutCheckerTask` sees the withdrawal as an "unhandled payout" attributed to itself and proceeds to kickoff and eventually get reimbursed for a payout it never fronted, while operator A — the one who actually initiated/paid the withdrawal — is permanently excluded from being the recorded payer for this withdrawal index. [6](#0-5)

pub fn create_payout_txhandler(
    input_utxo: UTXO,
    output_txout: TxOut,
    operator_xonly_pk: XOnlyPublicKey,
    user_sig: taproot::Signature,
    _network: bitcoin::Network,
) -> Result<TxHandler<Signed>, BridgeError> {
    let txin = SpendableTxIn::new_partial(input_utxo.outpoint, input_utxo.txout);

    let output_txout = UnspentTxOut::from_partial(output_txout.clone());

    let op_return_txout = op_return_txout(PushBytesBuf::from(operator_xonly_pk.serialize()));

    let mut txhandler = TxHandlerBuilder::new(TransactionType::Payout)
        .with_version(NON_STANDARD_V3)
        .add_input(
            NormalSignatureKind::NotStored,
            txin,
            SpendPath::KeySpend,
            DEFAULT_SEQUENCE,
        )
        .add_output(output_txout)
        .add_output(UnspentTxOut::from_partial(anchor_output(
            NON_EPHEMERAL_ANCHOR_AMOUNT,
        )))
        .add_output(UnspentTxOut::from_partial(op_return_txout))
        .finalize();
    txhandler.set_p2tr_key_spend_witness(&user_sig, 0)?;
    txhandler.promote()
}

        &self,
        dbtx: Option<DatabaseTransaction<'_>>,
        deposit_id: u32,
    ) -> Result<(BlockHash, Txid), BridgeError> {
        let (payer_xonly_pk, payout_blockhash, kickoff_txid) = self
            .db
            .get_payer_xonly_pk_blockhash_and_kickoff_txid_from_deposit_id(dbtx, deposit_id)
            .await?;

        tracing::info!(
            "Payer xonly pk and kickoff txid found for the requested deposit, payer xonly pk: {:?}, kickoff txid: {:?}",
            payer_xonly_pk,
            kickoff_txid
        );

        // first check if the payer is the operator, and the kickoff is handled
        // by the PayoutCheckerTask, meaning kickoff_txid is set
        let (payout_blockhash, kickoff_txid) = match (
            payer_xonly_pk,
            payout_blockhash,
            kickoff_txid,
        ) {
            (Some(payer_xonly_pk), Some(payout_blockhash), Some(kickoff_txid)) => {
                if payer_xonly_pk != self.signer.xonly_public_key {
                    return Err(eyre::eyre!(
                        "Payer is not own operator for deposit, payer xonly pk: {:?}, operator xonly pk: {:?}",
                        payer_xonly_pk,
                        self.signer.xonly_public_key
                    )
                    .into());
                }
                (payout_blockhash, kickoff_txid)
            }
            _ => {
                return Err(eyre::eyre!(
                    "Payer info not found for deposit, payout blockhash: {:?}, kickoff txid: {:?}",
                    payout_blockhash,
                    kickoff_txid
                )
                .into());
            }
        };

        tracing::info!(
            "Payer xonly pk, payout blockhash and kickoff txid found and valid for own operator for the requested deposit id: {}, payer xonly pk: {:?}, payout blockhash: {:?}, kickoff txid: {:?}",
            deposit_id,
            payer_xonly_pk,
            payout_blockhash,
            kickoff_txid
        );

        Ok((payout_blockhash, kickoff_txid))
    }

    pub async fn get_payout_info_from_move_txid(
        &self,
        tx: Option<DatabaseTransaction<'_>>,
        move_to_vault_txid: Txid,
    ) -> Result<Option<(Option<XOnlyPublicKey>, BlockHash, Txid, i32)>, BridgeError> {
        let query = sqlx::query_as::<_, (Option<XOnlyPublicKeyDB>, BlockHashDB, TxidDB, i32)>(
            "SELECT w.payout_payer_operator_xonly_pk, w.payout_tx_blockhash, w.payout_txid, w.idx
             FROM withdrawals w
             WHERE w.move_to_vault_txid = $1
               AND w.payout_txid IS NOT NULL
               AND w.payout_tx_blockhash IS NOT NULL",
        )
        .bind(TxidDB(move_to_vault_txid));

        let result: Option<(Option<XOnlyPublicKeyDB>, BlockHashDB, TxidDB, i32)> =
            execute_query_with_tx!(self.connection, tx, query, fetch_optional)?;

        result
            .map(|(operator_xonly_pk, block_hash, txid, deposit_idx)| {
                Ok((
                    operator_xonly_pk.map(|pk| pk.0),
                    block_hash.0,
                    txid.0,
                    deposit_idx,
                ))
            })
            .transpose()
    }

    pub async fn get_first_unhandled_payout_by_operator_xonly_pk(
        &self,
        tx: Option<DatabaseTransaction<'_>>,
        operator_xonly_pk: XOnlyPublicKey,
    ) -> Result<Option<(u32, Txid, BlockHash)>, BridgeError> {
        let query = sqlx::query_as::<_, (i32, Option<TxidDB>, Option<BlockHashDB>)>(
            "SELECT w.idx, w.move_to_vault_txid, w.payout_tx_blockhash
             FROM withdrawals w
             WHERE w.payout_txid IS NOT NULL
                AND w.is_payout_handled = FALSE
                AND w.payout_payer_operator_xonly_pk = $1
                ORDER BY w.idx ASC
             LIMIT 1",
        )
        .bind(XOnlyPublicKeyDB(operator_xonly_pk));

        let results = execute_query_with_tx!(self.connection, tx, query, fetch_optional)?;

        results
            .map(|(citrea_idx, move_to_vault_txid, payout_tx_blockhash)| {
                Ok((
                    u32::try_from(citrea_idx).wrap_err("Failed to convert citrea index to u32")?,
                    move_to_vault_txid
                        .expect("move_to_vault_txid Must be Some")
                        .0,
                    payout_tx_blockhash
                        .expect("payout_tx_blockhash Must be Some")
                        .0,
                ))
            })
            .transpose()
    }
