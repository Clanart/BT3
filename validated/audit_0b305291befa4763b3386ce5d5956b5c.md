### Title
Unrecovered type-assertion panic in the pointer precompile's CW20/CW721 registration allows a permissionless denial of service - (File: precompiles/pointer/pointer.go)

### Summary
The MISP bug class is "a caller-controlled value bypasses semantic validation before being persisted/consumed, and the consumer later performs an unchecked decode/type-conversion that panics, breaking functionality for other users." The closest reachable analog in sei-chain is in the pointer precompile: `AddCW20`/`AddCW721` query an attacker-deployed CosmWasm contract for `token_info`/`contract_info`, JSON-decode the response into `map[string]interface{}`, and then perform unchecked type assertions (`formattedRes["name"].(string)`, `formattedRes["symbol"].(string)`) with no `ok` check and no `recover()` guarding this call path.

### Finding Description
`AddCW20` and `AddCW721` in `precompiles/pointer/pointer.go` (and every legacy version, e.g. `precompiles/pointer/legacy/v67/pointer.go`) do: [1](#0-0) 

The contract queried via `p.wasmdKeeper.QuerySmartSafe` is fully attacker-controlled — any user can deploy a CosmWasm contract that answers `{"token_info":{}}` with a JSON object where `"name"` or `"symbol"` is a non-string value (a number, boolean, array, or object) instead of a string, while still satisfying CW20/CW721 minimal shape requirements enough to pass any pre-checks that exist. The bank-module `Metadata.Validate()` pattern that MISP's report is analogous to (semantic validation only on a structurally-typed field) does not apply here because there is no CW20/CW721 response schema enforcement before Go performs the raw type assertion: [2](#0-1) 

Unlike other precompiles in this codebase, which defend the exact same class of failure with a `defer recover()` around `Execute` (see `precompiles/addr/*.go` and `precompiles/solo/*.go`): [3](#0-2) 
the pointer precompile executor has **no** such recover wrapper around `AddCW20`/`AddCW721`. The outer `Run` wrapper in `precompiles/common/*` only recovers/handles `error` return values, not Go runtime panics from failed type assertions: [4](#0-3) 

A failed type assertion (`x.(string)` when `x` is not a string) is a Go runtime panic, which is not an `error` value — it will propagate up through `Execute`, through `Run`, into the go-ethereum EVM `Call`, and up into the SEI EVM message-processing code. Whether it is caught depends on whether some outer wrapper (e.g., ante handler or `ApplyMessage` caller) has a blanket `recover()`, but no defensive `recover()` exists specifically for this precompile call chain the way it does for `addr` and `solo` precompiles. The project's own integration test explicitly documents that any panic reaching the EVM trace is considered a defect ("a 'panic occurred' trace would mean a consensus-relevant unhandled error path"): [5](#0-4) 

### Impact Explanation
`addCW20Pointer`/`addCW721Pointer` are permissionless: any EVM transaction sender can deploy a CosmWasm contract and then call the pointer precompile to register a pointer for it. If the runtime panic from the unchecked type assertion is not recovered by an upstream generic recover (which is uncertain from static review alone, but is treated in-repo as a serious bug per the "must not surface as panic" test comment), it can crash or corrupt the transaction-processing goroutine for that block, producing an availability failure for the node processing the tx — a chain-level halt/DoS risk analogous to the MISP scenario where a single malformed persisted record broke a shared code path for all subsequent callers. Even in the best case where some higher-level recover exists, this is an unhandled-error path that the project's own tests flag as unacceptable, and it deterministically fails validation of untrusted external input (attacker-controlled contract response) without any error return, unlike the sibling `AddNative` path which goes through `GetDenomMetaData` (protobuf-typed, no free-form JSON decode).

### Likelihood Explanation
High: no privilege is required, deploying a CW20/CW721-like contract that returns a non-string `name`/`symbol` field from `token_info`/`contract_info` is straightforward, and calling `addCW20Pointer`/`addCW721Pointer` is a normal permissionless EVM transaction. This exists identically across essentially every historical and current version of the pointer precompile (`v552` through the current `precompiles/pointer/pointer.go`), indicating it has never been patched.

### Recommendation
Replace the unchecked type assertions with checked assertions (`name, ok := formattedRes["name"].(string); if !ok { return nil, 0, fmt.Errorf(...) }`) for both `name` and `symbol` in `AddCW20` and `AddCW721`, and add a `defer recover()` guard around the pointer precompile's `Execute`/`AddCW20`/`AddCW721`, consistent with the pattern already used in `precompiles/addr` and `precompiles/solo`, so malformed/attacker-controlled CW20/CW721 query responses fail with a normal EVM revert instead of an unrecovered Go panic.

### Proof of Concept
1. Deploy a CosmWasm contract that implements a `token_info` query handler returning `{"name": 12345, "symbol": "X", "decimals": 6, "total_supply": "0"}` (i.e. `name` is a JSON number, not a string), satisfying whatever minimal CW20 shape is otherwise expected.
2. From any EVM account, call the pointer precompile's `addCW20Pointer(cwAddress)` method (bech32 address of the deployed contract).
3. Precompile execution reaches:
```go
res, _ := p.wasmdKeeper.QuerySmartSafe(ctx, cwAddress, []byte(`{"token_info":{}}`))
formattedRes := map[string]interface{}{}
json.Unmarshal(res, &formattedRes)
name := formattedRes["name"].(string)   // panics: interface conversion, float64 is not string
```
4. The type assertion panics with `interface conversion: interface {} is float64, not string`, propagating out of the precompile's `Execute` uncaught (no `recover()` present in `precompiles/pointer/pointer.go`, unlike `precompiles/addr` and `precompiles/solo`), producing the "panic occurred" trace state the project's own tests explicitly forbid.

func (p Precompile) Run(evm *vm.EVM, caller common.Address, callingContract common.Address, input []byte, value *big.Int, readOnly bool, isFromDelegateCall bool, hooks *tracing.Hooks) (bz []byte, err error) {
	operation := fmt.Sprintf("%s_unknown", p.name)
	defer func() {
		HandlePrecompileError(err, evm, operation)
		if err != nil {
			err = vm.ErrExecutionReverted
		}
	}()
	ctx, method, args, err := p.Prepare(evm, input)
	if err != nil {
		return nil, err
	}

	operation = method.Name
	em := ctx.EventManager()
	ctx = ctx.WithEventManager(sdk.NewEventManager())
	ctx = ctx.WithEVMPrecompileCalledFromDelegateCall(isFromDelegateCall)
	bz, err = p.executor.Execute(ctx, method, caller, callingContract, args, value, readOnly, evm, hooks)
	if err != nil {
		return bz, err
	}
	events := ctx.EventManager().Events()
	if len(events) > 0 {
		em.EmitEvents(ctx.EventManager().Events())
	}
	return bz, err
}

/**
 * The load-bearing legacy assertion: a precompile that runs out of gas mid-execution
 * must surface as a plain EVM "execution reverted" in traces — never as a Go panic
 * (a "panic occurred" trace would mean a consensus-relevant unhandled error path).
 */
export async function expectTraceRevertedNotPanicked(txHash: string): Promise<void> {
    const trace = await traceTransaction(txHash);
    const error = trace.error ?? '';
    expect(error, `trace of ${txHash} must carry an error`).to.not.equal('');
    expect(error, 'precompile failure must not surface as a panic').to.not.include('panic');
    expect(error, 'precompile failure must trace as an execution revert').to.include(
        'execution reverted',
    );
}
