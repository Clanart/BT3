### Title
Unbounded Bitcoin fee rate can burn user payments as miner fees - ([File: networks/bitcoin/src/wallet/send.rs])

### Summary
`SignableTransaction::new` accepts an arbitrary `fee_per_vbyte` and enforces only Bitcoin’s minimum relay fee, with no upper bound or sanity limit relative to the requested payments. [1](#0-0) [2](#0-1) 

### Finding Description
The constructor calculates the required fee as `fee_per_vbyte * vbytes` and rejects only transactions whose fee is below the default relay minimum. [2](#0-1)  It then allows that fee to consume the input value before assigning any remainder to change. [3](#0-2) 

The Bitcoin processor obtains this parameter from the median fee rate of transactions in the sampled block and passes it directly into `SignableTransaction::new`. [4](#0-3) [5](#0-4)  Because ordinary Bitcoin users can broadcast transactions with unusually large fees, an unprivileged party who controls the majority of non-coinbase transactions in the sampled block can raise the median fee rate without any protocol-side maximum.

Before constructing the final transaction, Serai amortizes the calculated fee across the planned payments and drops payments whose post-fee amount becomes dust. [6](#0-5) [7](#0-6)  Consequently, an inflated sampled fee can reduce a withdrawal to dust or remove it entirely while Serai still creates a transaction paying the inflated fee.

### Impact Explanation
A manipulated fee rate causes Serai to sign transactions paying substantially more Bitcoin to miners than users should reasonably be charged. If the estimated fee exceeds a payment’s value, the payment is dropped rather than delivered; if a change output exists, the remaining wallet funds are reduced by the inflated fee. [8](#0-7) [9](#0-8) 

### Likelihood Explanation
Exploitation requires influencing the median fee of the block selected for estimation, generally by ensuring that most sampled non-coinbase transactions carry an elevated fee. This requires paying mining fees or otherwise controlling enough block transactions, but it does not require compromising validators, the Bitcoin RPC server, private keys, or signing shares. [10](#0-9) 

### Recommendation
Bound `fee_per_vbyte` before constructing a transaction. In particular:

- enforce a protocol-defined maximum sat/vbyte in `SignableTransaction::new`;
- use checked arithmetic for `fee_per_vbyte * vbytes` and `payment_sat + needed_fee`;
- cap the selected median at a configured maximum reasonable fee;
- sample fees across multiple finalized blocks rather than accepting the median of one externally influenced block;
- refuse to sign a transaction whose fee exceeds an explicit fraction of the input value or requested payment amount.

### Proof of Concept
Assume the sampled block’s attacker-controlled transactions make `median_fee` return `R = 1_000` sat/vbyte, and the resulting transaction is `V = 100` vbytes. `SignableTransaction::new` computes `needed_fee = R * V = 100_000` sats and accepts it because only the lower relay bound is checked. [2](#0-1) 

For a planned payment of `40_000` sats, `prepare_send` attempts to amortize the `100_000`-sat fee from the payment, reduces it below dust, and drops it. [11](#0-10)  If the input is `150_000` sats and change is configured, the final constructor call creates only a `50_000`-sat change output while committing `100_000` sats as miner fees. [9](#0-8)  The user’s `40_000`-sat withdrawal is therefore not delivered, and the wallet additionally funds the inflated fee.

  // This function panics on a node which doesn't follow the Bitcoin protocol, which is deemed fine
  async fn median_fee(&self, block: &Block) -> Result<Fee, NetworkError> {
    let mut fees = vec![];
    if block.txdata.len() > 1 {
      for tx in &block.txdata[1 ..] {
        let mut in_value = 0;
        for input in &tx.input {
          let mut input_tx = input.previous_output.txid.to_raw_hash().to_byte_array();
          input_tx.reverse();
          in_value += self
            .rpc
            .get_transaction(&input_tx)
            .await
            .map_err(|_| NetworkError::ConnectionError)?
            .output[usize::try_from(input.previous_output.vout).unwrap()]
          .value
          .to_sat();
        }
        let out = tx.output.iter().map(|output| output.value.to_sat()).sum::<u64>();
        fees.push((in_value - out) / u64::try_from(tx.vsize()).unwrap());
      }
    }
    fees.sort();
    let fee = fees.get(fees.len() / 2).copied().unwrap_or(0);

    // The DUST constant documentation notes a relay rule practically enforcing a
    // 1000 sat/kilo-vbyte minimum fee.
    Ok(Fee(fee.max(1)))
  }
