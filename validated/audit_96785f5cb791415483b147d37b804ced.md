### Title
Use of Fixed 2300-Gas `.transfer()` in `WSEI.withdraw()` Can Permanently Freeze Withdrawer Funds - (File: `contracts/src/WSEI.sol`)

### Summary
The canonical Wrapped SEI (`WSEI`) ERC20-wrapper contract, compiled/embedded at `x/evm/artifacts/wsei` and deployable on-chain via the `deploy-wsei` CLI command, implements `withdraw()` using Solidity's legacy `payable(msg.sender).transfer(wad)` call instead of a low-level `call` with gas forwarding.

### Finding Description
`WSEI.withdraw()` burns the caller's internal balance and then unwraps native value back to `msg.sender` using `.transfer()`: [1](#0-0) 

`.transfer()` hardcodes a 2300 gas stipend for the receiver's `receive`/`fallback` execution. Any `msg.sender` that is itself a contract (a wallet, multisig, DeFi vault, EVM-pointer contract, or any address abstraction contract) whose `receive()`/`fallback()` logic needs more than 2300 gas — which is easy to exceed once `SSTORE`/cold-account access costs from EIP‑2929-style gas schedules are counted — will always have the internal `.transfer()` call revert. Because `withdraw()` performs `balanceOf[msg.sender] -= wad` before the transfer and the whole transaction reverts on failure, the call never succeeds, and the caller's wrapped balance can never be redeemed for native SEI through this contract. Every other Sei precompile-based native-transfer path (the `bank` precompile's `sendNative`, seen across `precompiles/bank/bank.go` and its `legacy/*` versions) instead moves value through `SendCoinsAndWei` rather than a fixed-gas EVM value transfer, so this fragility is specific to the `WSEI` contract's own Solidity logic, not to Sei's core native-transfer machinery. [2](#0-1) [3](#0-2) 

### Impact Explanation
Any contract account that deposits native SEI into `WSEI` (via `deposit()`/`receive()`/`fallback()`) and later attempts `withdraw()` risks permanent freezing of those funds if its own receive logic costs more than 2300 gas to execute. This is a genuine "permanent freezing of funds" condition reachable purely by a contract deployer/depositor's own transaction sequence, matching the accepted impact class for this analog.

### Likelihood Explanation
Likelihood is moderate: it requires the withdrawing address to be a contract with non-trivial `receive`/`fallback` logic (common for smart-contract wallets, multisigs, or any contract that emits events or updates state on receiving ETH). Plain EOA withdrawals are unaffected since EOAs have no code to execute and always succeed within the 2300-gas stipend.

### Recommendation
Replace `payable(msg.sender).transfer(wad)` in `WSEI.withdraw()` with a low-level call that forwards all remaining gas and checks the return value, e.g.:
```solidity
(bool success, ) = msg.sender.call{value: wad}("");
require(success, "WSEI: transfer failed");
```
or use OpenZeppelin's `Address.sendValue`. Recompile and re-embed the updated bytecode/ABI in `x/evm/artifacts/wsei`.

### Proof of Concept
1. Deploy a receiver contract whose `receive()` function performs a state-changing operation costing more than 2300 gas (e.g., writing to a cold storage slot).
2. From that contract, call `WSEI.deposit()` with some native SEI value, then call `WSEI.withdraw(wad)`.
3. Observe that `payable(msg.sender).transfer(wad)` reverts due to out-of-gas in the receiver's `receive()`, reverting the whole `withdraw()` transaction and leaving `balanceOf[msg.sender]` permanently locked with no code path to redeem it back to native SEI through this contract.

```text
contract WSEI {
    string public name     = "Wrapped Sei";
    string public symbol   = "WSEI";
    uint8  public decimals = 18;

    event  Approval(address indexed src, address indexed guy, uint wad);
    event  Transfer(address indexed src, address indexed dst, uint wad);
    event  Deposit(address indexed dst, uint wad);
    event  Withdrawal(address indexed src, uint wad);

    mapping (address => uint)                       public  balanceOf;
    mapping (address => mapping (address => uint))  public  allowance;

    fallback() external payable {
        deposit();
    }
    receive() external payable {
        deposit();
    }
    function deposit() public payable {
        balanceOf[msg.sender] += msg.value;
        emit Deposit(msg.sender, msg.value);
    }
    function withdraw(uint wad) public {
        require(balanceOf[msg.sender] >= wad);
        balanceOf[msg.sender] -= wad;
        payable(msg.sender).transfer(wad);
        emit Withdrawal(msg.sender, wad);
    }
```
