### Title
Unhandled `ValueError` in `uncurry_innerpuz` from attacker-crafted DID puzzle causes wallet spend-processing crash - (File: chia/wallet/did_wallet/did_wallet_puzzles.py)

### Summary
`uncurry_innerpuz()` assumes that any puzzle whose uncurried `mod` equals `DID_INNERPUZ_MOD` was curried with exactly 5 arguments, and unconditionally unpacks them via `list(args.as_iter())` without verifying the arity. An attacker can construct a coin spend whose puzzle embeds the exact `DID_INNERPUZ_MOD` bytecode but curries it with a different number of parameters, causing `list.unpack` to raise an uncaught `ValueError` deep inside the function, which is never wrapped in `try/except`. This is analogous to the TensorFlow `DeserializeSparse` bug, where shape-inference code assumed a fixed structure (rank ≥ 1, last dim 3) of externally supplied data and dereferenced it without validation, crashing the process on malformed input.

### Finding Description
`is_did_innerpuz()` only checks equality of the *mod* (`inner_f == DID_INNERPUZ_MOD`), not the number of curried arguments: [1](#0-0) 

`Program.uncurry()` extracts an arbitrary number of curried arguments purely from the curry-list shape `(4 (1 . arg) rest)`; it does not tie the argument count to how the extracted `mod` actually consumes them at run time: [2](#0-1) 

Because the DID inner-puzzle mod is a fixed, publicly known CLVM constant, any spend-bundle submitter can build a puzzle reveal that:
1. Uses the exact `DID_INNERPUZ_MOD` bytecode as the "quoted inner" mod, so `mod == DID_INNERPUZ_MOD` passes.
2. Curries it with fewer (or more) than 5 arguments.

When such a coin is observed by a wallet tracking DID/singleton activity (e.g. during `coin_added`, `create_new_did_wallet_from_coin_spend`, `current_p2_puzzle_hash`, `create_update_spend`, `create_message_spend`, `generate_eve_spend`, or `find_lost_did` in `wallet_state_manager.py`), `uncurry_innerpuz` is invoked and the 5-way tuple unpack raises an unhandled `ValueError`, which is not caught anywhere in the call chain (only the `args is None` / `uncurried is None` case is guarded): [3](#0-2) [4](#0-3) [5](#0-4) 

This same code path is reached through `wallet_state_manager.py` during coin-state sync, so an attacker only needs to get a maliciously crafted coin observed by a victim wallet (e.g. by sending funds to a puzzle hash the wallet is watching, or by having the victim call `manual_nft_search`/`find_lost_did` on an attacker-supplied coin id) to trigger the crash.

### Impact Explanation
An unhandled exception during coin-state processing halts the coroutine handling that spend/coin, disrupting the wallet's synchronization/transaction-processing pipeline for the affected wallet — a spend-triggered processing halt matching the accepted impact classes (denial of service against wallet operation triggered by a single crafted, unsigned puzzle reveal). This does not require any privileged access; any spend-bundle submitter or Data Layer/DID-lookup caller can supply a puzzle with the correct mod but wrong arity.

### Likelihood Explanation
The DID inner-puzzle mod bytecode is public (`chia_puzzles_py.programs.DID_INNERPUZ`), so crafting a coin puzzle with matching mod bytecode but a different curry arity requires no special access or cryptographic material — only standard CLVM curry construction. The vulnerable code paths (`coin_added`, `find_lost_did`, `manual_nft_search`, `current_p2_puzzle_hash`, etc.) are exercised during normal wallet sync of tracked/interesting coins, making the trigger conditions easily reachable by an unprivileged party who can get their crafted coin observed by a victim wallet.

### Recommendation
Validate the curried argument count in `uncurry_innerpuz()` (and any other driver relying on fixed-arity unpacking after mod-only equality checks) before unpacking, e.g.:
```python
args_list = list(args.as_iter())
if len(args_list) != 5:
    return None
p2_puzzle, id_list, num_of_backup_ids_needed, singleton_struct, metadata = args_list
```
Apply the same defensive check to other `uncurry_*` helpers (e.g. `uncurry_pool_member_inner_puzzle`, `uncurry_pool_waitingroom_inner_puzzle`, `UncurriedNFT.uncurry`) that unpack `args.as_iter()` into a fixed tuple after only checking mod equality, and ensure all wallet-side callers wrap unpacking in try/except so a malformed on-chain puzzle degrades to "unrecognized puzzle" rather than crashing the sync task.

### Proof of Concept
1. Take the public `DID_INNERPUZ` bytecode (`chia_puzzles_py.programs.DID_INNERPUZ`).
2. Curry it with only 2 arguments instead of the expected 5, e.g. `Program.from_bytes(DID_INNERPUZ).curry(p2_puzzle_hash, some_value)`.
3. Wrap this in a singleton puzzle (`create_singleton_puzzle`) and create/spend a coin using it (any solution, the run itself need not succeed — only puzzle-reveal parsing matters).
4. Get a victim wallet to observe this coin (e.g., as a child of a coin it is watching, or by calling `find_lost_did`/`manual_nft_search` against this coin id).
5. `uncurry_innerpuz()` is invoked; `inner_f == DID_INNERPUZ_MOD` succeeds; `list(args.as_iter())` yields 2 elements; the 5-target tuple unpack raises `ValueError: not enough values to unpack (expected 5, got 2)`, which propagates uncaught out of the wallet coroutine handling that coin.

```python
    """
    Check if a puzzle is a DID inner mode
    :param inner_f: puzzle

    """
    return inner_f == DID_INNERPUZ_MOD


def uncurry_innerpuz(puzzle: Program) -> tuple[Program, Program, Program, Program, Program] | None:
    """
    Uncurry a DID inner puzzle
    :param puzzle: DID puzzle
    :return: Curried parameters
    """
    r = puzzle.uncurry()
    if r is None:
        return r
    inner_f, args = r
    if not is_did_innerpuz(inner_f):
        return None

    p2_puzzle, id_list, num_of_backup_ids_needed, singleton_struct, metadata = list(args.as_iter())
    return p2_puzzle, id_list, num_of_backup_ids_needed, singleton_struct, metadata
```

```python
    def uncurry(self) -> tuple[Program, Program]:
        def match(o: CLVMStorage, expected: bytes) -> None:
            if o.atom != expected:
                raise ValueError(f"expected: {expected.hex()}")

        try:
            # (2 (1 . <mod>) <args>)
            ev, quoted_inner, args_list = self.as_iter()
            match(ev, b"\x02")
            if TYPE_CHECKING:
                # this being False is presently handled in the TypeError exception handler below
                assert quoted_inner.pair is not None
            match(quoted_inner.pair[0], b"\x01")
            mod = quoted_inner.pair[1]
            args = []
            while args_list.pair is not None:
                # (4 (1 . <arg>) <rest>)
                cons, quoted_arg, rest = args_list.as_iter()
                match(cons, b"\x04")
                if TYPE_CHECKING:
                    # this being False is presently handled in the TypeError exception handler below
                    assert quoted_arg.pair is not None
                match(quoted_arg.pair[0], b"\x01")
                args.append(quoted_arg.pair[1])
                args_list = rest
            match(args_list, b"\x01")
            return Program.to(mod), Program.to(args)
        except ValueError:  # too many values to unpack
            # when unpacking as_iter()
            # or when a match() fails
            return self, self.to(0)
        except TypeError:  # NoneType not subscriptable
            # when an object is not a pair or atom as expected
            return self, self.to(0)
```
