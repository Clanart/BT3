## Missing Ownership/Path-Scope Check in Harvester RPC `delete_plot` Endpoint - (File: `chia/harvester/harvester.py`)

### Summary
The harvester RPC `/delete_plot` endpoint accepts an arbitrary `filename` from the RPC caller and deletes it from disk with no check that the path is a tracked plot or that it resides inside a configured plot directory. This mirrors the reported CVE-2024-9919 bug class (an endpoint that performs privileged file/directory deletion without verifying the caller is authorized to act on that specific target), reachable by any local RPC caller with harvester RPC access.

### Finding Description
`HarvesterRpcApi.delete_plot()` pulls `filename` straight out of the untrusted request dict and forwards it to `Harvester.delete_plot()`: [1](#0-0) 

`Harvester.delete_plot()` calls `remove_plot(Path(str_path))` directly: [2](#0-1) 

`remove_plot()` performs no validation whatsoever beyond existence — it does not check that the path is one of the plots tracked in `PlotManager.plots`, nor that it is contained within any directory returned by `get_plot_directories()`: [3](#0-2) 

Contrast this with `add_plot_directory`/`remove_plot_directory`, which at least validate that the path exists, is a directory, and is present in the configured `plot_directories` list before mutating config: [4](#0-3) 

No equivalent scope check exists for `delete_plot`. Any caller able to reach the harvester RPC surface (an "unprivileged" caller relative to full-node/wallet key material, e.g., a monitoring integration or third-party tool granted only harvester RPC access, or any process able to reach the local RPC port before/without the intended access-control layer) can pass an arbitrary absolute or relative path — including paths outside any plot directory — and have it unlinked by the harvester process. This is a direct filesystem-side-effect analog to the huntr/CVE-2024-9919 report: "the endpoint does not verify authorization/ownership before performing destructive deletion," just substituting "any file the harvester process can unlink" for "any directory the target app can delete."

### Impact Explanation
An authorized-but-unauthorized-for-this-resource RPC caller can delete arbitrary files reachable by the harvester process (config files, other plot files not intended for removal, unrelated data on shared volumes), causing farming disruption, loss of plot files, or corruption of harvester state/config. Because deletion is irreversible and happens in the harvester's own filesystem context, this can knock a farmer offline (rewards/plot loss) and, depending on shared-path deployments, delete data belonging to other services.

### Likelihood Explanation
Exploitation requires only a single JSON RPC call (`POST /delete_plot` or the daemon websocket wrapper) with a `filename` value — no crafted spend bundle, chain state, or privileged key material is needed. The bug is trivially reachable by anything that can talk to the harvester RPC endpoint, and the missing check is a straightforward code-review-visible omission (compare to the directory-add/remove validation that does exist).

### Recommendation
In `Harvester.delete_plot()` (or `HarvesterRpcApi.delete_plot()`), resolve the requested path and verify it matches an entry currently tracked in `self.plot_manager.plots` (or, at minimum, that its resolved parent is one of `get_plot_directories(self.root_path)`) before calling `remove_plot()`. Reject with a `ValueError`/`RpcError` otherwise, consistent with the existing validation style used by `add_plot_directory`/`remove_plot_directory`.

### Proof of Concept
1. Connect to the harvester RPC (HTTP or via daemon passthrough) with valid but "harvester-RPC-only" access.
2. Send:
```json
POST /delete_plot
{"filename": "/absolute/path/to/any/other/file/or/plot/not/managed/by/this/harvester"}
```
3. `HarvesterRpcApi.delete_plot()` → `Harvester.delete_plot()` → `remove_plot()` unlinks the file unconditionally since it only checks `path.exists()`, with no verification that the path belongs to the harvester's known plot set or configured plot directories.

```python
def add_plot_directory(root_path: Path, str_path: str) -> dict[str, Any]:
    path: Path = Path(str_path).resolve()
    if not path.exists():
        raise ValueError(f"Path doesn't exist: {path}")
    if not path.is_dir():
        raise ValueError(f"Path is not a directory: {path}")
    log.debug(f"add_plot_directory {str_path}")
    with lock_and_load_config(root_path, "config.yaml") as config:
        if str(Path(str_path).resolve()) in get_plot_directories(root_path, config):
            raise ValueError(f"Path already added: {path}")
        if not config["harvester"]["plot_directories"]:
            config["harvester"]["plot_directories"] = []
        config["harvester"]["plot_directories"].append(str(Path(str_path).resolve()))
        save_config(root_path, "config.yaml", config)
    return config


def remove_plot_directory(root_path: Path, str_path: str) -> None:
    log.debug(f"remove_plot_directory {str_path}")
    with lock_and_load_config(root_path, "config.yaml") as config:
        str_paths: list[str] = get_plot_directories(root_path, config)
        # If path str matches exactly, remove
        if str_path in str_paths:
            str_paths.remove(str_path)

        # If path matches full path, remove
        new_paths = [Path(sp).resolve() for sp in str_paths]
        if Path(str_path).resolve() in new_paths:
            new_paths.remove(Path(str_path).resolve())

        config["harvester"]["plot_directories"] = [str(np) for np in new_paths]
        save_config(root_path, "config.yaml", config)
```
