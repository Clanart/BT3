### Title
Identity verification shares bypass `Curve::read_G` rejection via `ThresholdKeys::read`, yielding an identity group key under which signatures are trivially forgeable - ([File: crypto/dkg/src/lib.rs])

### Summary
Analogous to the MaxKB report — where a network policy enforced inside `connect()` is bypassed because `sendto(MSG_FASTOPEN)` reaches the kernel without ever calling the hooked function — Serai enforces "identity point rejection" only in `Curve::read_G` (`crypto/frost/src/curve/mod.rs:125`), but `ThresholdKeys::read` deserializes verification shares through `<C as Ciphersuite>::read_G` (`crypto/dkg/src/lib.rs:622`), which performs canonical-encoding checks yet does not reject the identity (`crypto/ciphersuite/src/lib.rs:91-101`). `ThresholdKeys::new` (`crypto/dkg/src/lib.rs:349-391`) validates only the count and index range of the shares — never non-identity — and computes `group_key` as the interpolated sum of `verification_shares[1..=t]` (line 376-378). An attacker who supplies the serialized `ThresholdKeys` bytes can encode every one of the first `t` verification shares as the canonical identity encoding, causing `group_key` to become the identity point, for which Schnorr/FROST signatures are forgeable by anyone.

### Finding Description
- `Curve::read_G` explicitly rejects identity points after decoding (`crypto/frost/src/curve/mod.rs:123-131`): "Read a point from a reader, rejecting identity." This is the "hooked connect()" — the layer where the security invariant lives.
- `ThresholdKeys::read` reads all `n` verification shares with `<C as Ciphersuite>::read_G(reader)` (`crypto/dkg/src/lib.rs:620-623`). `Ciphersuite::read_G` (`crypto/ciphersuite/src/lib.rs:91-101`) only checks that `from_bytes` succeeds and that the encoding is canonical — the identity point's canonical encoding (all-zero bytes) passes.
- `ThresholdKeys::new` checks `verification_shares.len() == n` and `participant <= n` (`crypto/dkg/src/lib.rs:355-365`), then computes `group_key = Σ_{i ∈ 1..=t} verification_shares[i] * interpolation_factor(i, 1..=t)` (lines 376-378). If `verification_shares[1..=t]` are all identity, every term is `identity * λ = identity`, so `group_key = identity`.
- No consistency check exists between `secret_share` and `verification_shares[i]`, nor any identity check on the resulting `group_key`, so `ThresholdKeys::new` returns `Ok` for this crafted input.

The identity rejection in `Curve::read_G` is thus completely bypassed on the `ThresholdKeys::read` path, exactly as `sendto` bypassed the `connect()` hook: the same primitive (deserializing a group element that must be non-identity) is reached through an alternate entry point where the check is absent.

### Impact Explanation
With `core.group_key = identity` and `scalar = 1`, `offset = 0`, `group_key()` returns the identity point (`crypto/dkg/src/lib.rs:445-447`). Signature verification for Schnorr checks `s·G == R + c·A` (`crypto/schnorr/src/lib.rs:88-110`). With `A = identity`, the equation reduces to `s·G == R`, so *anyone* can forge a valid signature on *any* message: pick arbitrary `s`, set `R = s·G`, compute `c = H(R, A, m)`, and `s·G = R + c·identity` holds unconditionally. Since `ThresholdView::group_key` (line 527) propagates this identity key into the FROST signing machine, `AlgorithmSignatureMachine::complete` (`crypto/frost/src/sign.rs:465`) accepts such forgeries as legitimately produced signatures, and any downstream system treating the group key as the multisig's public key accepts attacker-forged signatures — enabling unauthorized spends/authorizations. This matches the accepted impact class "a forged proof or signature."

### Likelihood Explanation
Reachability is per the scan rules: untrusted bytes fed to `ThresholdKeys::read` are an in-scope input class. The attacker only needs to control the serialized byte stream; constructing it requires no secrets — `t = n` (or `t < n` with `Interpolation::Lagrange`), all `n` verification-share slots filled with the 32-byte (or curve-appropriate) canonical identity encoding, and any canonical scalar as `secret_share`. `Participant` indexes, curve ID, and interpolation tag are all attacker-chosen fields. The attack requires no interaction with honest participants and no computational work; it is a pure deserialization-path validation gap. Caveat: exploitation presumes a deployment where serialized `ThresholdKeys` cross a trust boundary (e.g., key material delivered by an untrusted party or restored from attacker-influenced storage); the code itself does not document that input as trusted-only.

### Recommendation
In `ThresholdKeys::new` (`crypto/dkg/src/lib.rs:349`), reject identity verification shares and an identity resulting `group_key`:

```rust
for share in verification_shares.values() {
  if share.is_identity().into() { Err(DkgError::...)?; }
}
// after computing group_key:
if group_key.is_identity().into() { Err(DkgError::...)?; }
```

Alternatively/additionally, have `ThresholdKeys::read` deserialize verification shares through an identity-rejecting reader equivalent to `Curve::read_G`, so the invariant is enforced at every deserialization entry point — not just the FROST-specific one.

### Proof of Concept
```rust
// For any C: Ciphersuite where C::G::identity().to_bytes() is canonical
// (true for all PrimeGroup encodings used here, e.g. 32 zero bytes for Ristretto)
let t: u16 = 2; let n: u16 = 3; let i: u16 = 1;
let mut serialized = vec![];
serialized.extend(u32::try_from(C::ID.len()).unwrap().to_le_bytes());
serialized.extend(C::ID);
serialized.extend(t.to_le_bytes());
serialized.extend(n.to_le_bytes());
serialized.extend(i.to_le_bytes());            // our participant index
serialized.push(1);                            // Interpolation::Lagrange
serialized.extend(C::F::ONE.to_repr().as_ref()); // arbitrary secret_share
for _ in 1 ..= n {
  // identity encoding passes Ciphersuite::read_G's canonicality check
  serialized.extend(C::G::identity().to_bytes().as_ref());
}

let keys = ThresholdKeys::<C>::read(&mut serialized.as_ref()).unwrap();
assert!(bool::from(keys.group_key().is_identity())); // accepted: identity group key

// Forgery under identity group key for any message m:
let s = C::F::random(&mut OsRng);
let R = C::generator() * s;
let c = hram(&R, &keys.group_key(), m); // challenge as used by the verifier
assert!(SchnorrSignature { R, s }.verify(keys.group_key(), c)); // s·G == R + c·identity
```
