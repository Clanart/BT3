## Analog Found: Arbitrary File Deletion via Harvester `delete_plot` RPC (No Path Restriction)

### Title
Unrestricted Arbitrary File Deletion via `delete_plot` Harvester RPC Endpoint - (File: `chia/harvester/harvester_rpc_api.py`)

### Summary
The CVE describes MacDown accepting an unsanitized path (`file:///` or `../`) from an untrusted "shared note" and using it directly for file operations, causing arbitrary file access outside the intended directory. The Chia harvester's `delete_plot` RPC endpoint has the analogous root cause: it takes a caller-supplied path string and passes it straight to a filesystem-unlink call with no check that the path resolves inside any of the harvester's configured plot directories.

### Finding Description
The RPC handler extracts `filename` directly from the request body and forwards it unmodified: [1](#0-0) 

This calls `Harvester.delete_plot()`, which does no validation before unlinking: [2](#0-1) 

The underlying `remove_plot()` helper only checks existence, never checks that `path` is inside a directory returned by `get_plot_directories()`, nor that it has a `.plot`/`.plot2` extension, nor that it was ever tracked by `PlotManager`: [3](#0-2) 

`Path(str_path)` accepts both absolute paths and `../`-relative traversal sequences, so any string reachable by the RPC caller becomes a target for `unlink()` with no containment check — the same class of missing-path-containment bug as the referenced CVE. This is documented as intentional-but-unguarded behavior: "`delete_plot()` unlinks the supplied path, triggers refresh, and emits a `plots` state change. There is no extra ownership model in this module; RPC authorization and local file permissions are the relevant gates."

### Impact Explanation
A caller with access to the harvester RPC (e.g., a local RPC client, farming pool management tooling, or any automation that proxies harvester RPC calls) can delete arbitrary files reachable by the harvester process's OS permissions — not just plot files. This includes the harvester's own config, database files, or other files under the same user account, causing denial of service (loss of farming capability, corrupted state, or destruction of unrelated data) without any plot-directory containment check.

### Likelihood Explanation
Exploitation requires only a single RPC call to `delete_plot` with a crafted `filename` value; no complex conditions are needed since the code performs no path validation whatsoever beyond an existence check.

### Recommendation
In `remove_plot()` (or in `Harvester.delete_plot()` before calling it), resolve the supplied path and verify it is strictly contained within one of the configured plot directories (via `get_plot_directories()`), and ideally require the path to already be a plot known to `PlotManager.plots`. Reject the request otherwise.

### Proof of Concept
1. Obtain harvester RPC access (as an RPC client permitted to call harvester endpoints).
2. Call `delete_plot` with `{"filename": "/root/.chia/mainnet/config/config.yaml"}` (or any other absolute/traversal path reachable by the harvester process).
3. Observe the target file is unlinked via `chia/plotting/util.py:remove_plot()` with no containment check, even though it was never a configured plot file.
