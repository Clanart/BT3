### Title
Division by zero when GasTarget governance parameter is 0 in `NextMagmaBlockBaseFee` - (File: `params/kip71_config.go`)

### Summary
`NextMagmaBlockBaseFee()` computes the KIP-71 dynamic base fee for the next block using `GasTarget` as a divisor without ever checking that it is non-zero, unlike the sibling parameter `BaseFeeDenominator`, which the same function explicitly guards against being zero.

### Finding Description
In `params/kip71_config.go`, the function `NextMagmaBlockBaseFee` explicitly protects against `BaseFeeDenominator == 0`: [1](#0-0) 
However, `GasTarget` (`kc.GasTarget`) is used directly as a `big.Int` divisor in both the "gas used above target" and "gas used below target" branches with no equivalent zero-check: [2](#0-1) [3](#0-2) 
If `GasTarget` is ever 0 (a governance-settable value per `kaiax/gov/param.go` / `kaiax/gov/paramset.go`, referenced widely across `kaiax/gov/headergov`), and `parentGasUsed != gasTarget` (which is essentially guaranteed once `GasTarget == 0`, since `parentGasUsed` would have to also equal exactly 0 to avoid entering the divide branches), the code performs `x.Div(x, new(big.Int).SetUint64(gasTarget))` with a zero divisor. `big.Int.Div` panics on division by zero in Go.

This mirrors the structure of the reported bug class exactly: a value that can reach zero through legitimate on-chain configuration is used unchecked as a denominator in a fee/reward calculation, while a structurally similar sibling value (`BaseFeeDenominator`) in the very same function received the zero-guard and this one did not — the same "fixed one function, missed the sibling" pattern described in the external report for `_calculateClaim()` vs `_calculateEmissionsClaim()`.

### Impact Explanation
`NextMagmaBlockBaseFee` is invoked on every block during header verification (`VerifyMagmaHeader`) and base fee computation post-Magma fork, meaning a panic here is consensus-critical: it would crash node processes computing/verifying the base fee for the very next block, potentially causing a chain-wide halt or a crash-loop across all full nodes and validators that process the affected block, rather than a contained revert of one user's transaction. This is a Denial-of-Service class issue reachable purely through a governance-approved parameter change, with no attacker-controlled transaction needed once the parameter is set.

### Likelihood Explanation
Reaching this state requires `GasTarget` to be set to `0` through the governance parameter mechanism (`kaiax/gov`). I was not able to fully confirm within the available context whether the governance module enforces a non-zero validator/range check on `GasTarget` when a vote sets this parameter (I found extensive references to `GasTarget` in `kaiax/gov/param.go`, `kaiax/gov/paramset.go`, and `kaiax/gov/headergov`, but did not verify the exact validation logic due to tool-call limits). If such validation exists and rejects zero, this specific analog would not be exploitable; if it does not, the likelihood is that of any governance-parameter misconfiguration (requires validator/governance-body action, not a plain unprivileged transaction), which is why this should be scoped as an in-scope "governance parameters" analog per the given rules rather than dismissed outright.

### Recommendation
Add an explicit zero-check/fallback for `kc.GasTarget` in `NextMagmaBlockBaseFee`, symmetric to the existing `BaseFeeDenominator == 0` guard, e.g., substituting a safe default (or rejecting the governance parameter value at the point it is set/validated in `kaiax/gov`) before it is used as a divisor.

### Proof of Concept
1. Via the governance module, propose and successfully vote to set `reward.gastarget` (or the corresponding KIP-71 parameter key referenced in `kaiax/gov/param.go`) to `0`.
2. Once the parameter takes effect at the next epoch/param-set boundary, any block whose parent used gas ≠ 0 will trigger `NextMagmaBlockBaseFee` to execute `x.Div(x, new(big.Int).SetUint64(0))`.
3. This causes a runtime panic in the node process computing/verifying the header base fee, crashing the node process during header validation or base-fee suggestion (`node/cn/gasprice/gasprice.go`'s `isRelaxedNetwork` also calls this same function), impacting consensus-critical processing chain-wide.
