### Title
Cooling-down mWOMSV holders receive 100% of rewards instead of forfeiting a decayed share, stealing yield from fully-locked lockers - (File: rewards/mWOMSVBaseRewarder.sol)

### Summary
`mWOMSVBaseRewarder._calExpireForfeit` sets `rewardableAmount = _amount` unconditionally, so `forfeitAmount` is always `0`, unlike the sibling `vlMGPBaseRewarder._calExpireForfeit` which correctly scales `rewardableAmount` by `vlMGP.getRewardablePercentWAD(_account)`. Any mWOMSV holder who is mid-cooldown (or even fully expired-but-unclaimed) receives their entire accrued `userRewards[token][account]` with no decay, when the intended design (mirrored in `mWomSV.getRewardablePercentWAD`) is for cooling-down balances to forfeit a time-decayed share back into the pool for fully-locked holders.

### Finding Description
`mWOMSVBaseRewarder._sendReward` computes `forfeitAmount = _calExpireForfeit(_account, userRewards[_rewardToken][_account])` before paying out [1](#0-0) . In the vlMGP analog, `_calExpireForfeit` calls `vlMGP.getRewardablePercentWAD(_account)` to compute the fraction of the user's balance that is still "fully locked" (as opposed to sitting in an active or expired cooldown slot), and only that fraction is paid out — the rest is queued back as `ForfeitRewardAdded` [2](#0-1) .

In `mWOMSVBaseRewarder`, the equivalent function instead does:
```
uint256 rewardableAmount = _amount;
if (rewardableAmount > _amount) revert InvalidRewardableAmount();
uint256 forfeitAmount = _amount - rewardableAmount;
```
`mWOMSV.getRewardablePercentWAD(_account)` is never called, so `rewardableAmount` always equals `_amount`, making `forfeitAmount` structurally always `0` [3](#0-2) . Yet `mWomSV.sol` implements the exact same `getRewardablePercentWAD` logic as `VLMGP.sol`, decaying the reward share for tokens sitting in `userUnlockings` cooldown slots [4](#0-3) , confirming this decay mechanism was intended for mWOMSV lockers too but was never wired into the rewarder.

Exploit flow: an attacker stakes mWOMSV in MasterMagpie, calls `mWomSV.startUnlock` to begin cooldown (or waits for an already-expired unlock slot), then calls `getReward`/`getRewards` (routed through `MasterMagpie.multiclaim`) while `balanceOf(account)` in the rewarder still reflects the full mWOMSV stake. Because `_calExpireForfeit` never queries `getRewardablePercentWAD`, the attacker receives 100% of `userRewards[token][account]` instead of the decayed share a fully-locked holder would receive under the vlMGP-equivalent logic. No modifier, `nonReentrant` guard, or reward-index update prevents this — the bug is a missing computation, not a bypassed check.

### Impact Explanation
This is theft of unclaimed yield: fully-locked, honest mWOMSV lockers are supposed to receive the forfeited share redistributed via `_queueNewRewardsWithoutTransfer`/`ForfeitRewardAdded`, but because `forfeitAmount` is always `0`, that redistribution never happens and cooling-down holders keep 100% of rewards they should have partially forfeited. This matches the Immunefi "theft of unclaimed yield" impact class and directly harms long-term lockers who lose the yield share they were meant to receive from decaying cooldown balances.

### Likelihood Explanation
This requires no special privileges — any address holding mWOMSV can call `mWomSV.startUnlock`, wait, and claim via `MasterMagpie.getReward`/`getRewards`. It is deterministic and repeatable for every claim cycle by every cooling-down or expired-but-unclaimed holder, with the only "cost" being the normal cost of acquiring/staking mWOMSV, which is not attacker capital at risk.

### Recommendation
Update `mWOMSVBaseRewarder._calExpireForfeit` to mirror `vlMGPBaseRewarder._calExpireForfeit`: compute `uint256 rewardablePercentWAD = mWOMSV.getRewardablePercentWAD(_account);` and `uint256 rewardableAmount = _amount * rewardablePercentWAD / 1e18;` before deriving `forfeitAmount`.

### Proof of Concept
Foundry test plan:
1. Deploy `mWomSV`, `mWOMSVBaseRewarder`, `MasterMagpie` per existing test fixtures.
2. Attacker stakes mWOMSV via MasterMagpie; queue rewards into the rewarder so `userRewards[token][attacker] > 0`.
3. Attacker calls `mWomSV.startUnlock(amount, slot)` to place part/all of the balance into `userUnlockings` cooldown.
4. Warp time forward (either mid-cooldown or past `endTime`/`coolDownInSecs`), so `mWomSV.getRewardablePercentWAD(attacker) < 1e18`.
5. Attacker calls `MasterMagpie.multiclaim`/`mWOMSVBaseRewarder.getReward(attacker, attacker)`.
6. Assert `toSend == userRewards[token][attacker]` (full amount, forfeitAmount == 0) in `mWOMSVBaseRewarder`.
7. Repeat identical cooldown state against `vlMGPBaseRewarder`+`VLMGP` and assert `forfeitAmount > 0` there, proving the divergence and the missing decay logic in the mWOMSV path.

    function _calExpireForfeit(address _account, uint256 _amount) internal view returns (uint256) {
        uint256 rewardableAmount = _amount;
        if (rewardableAmount > _amount)
            revert InvalidRewardableAmount();

        uint256 forfeitAmount = _amount - rewardableAmount;
        
        if (forfeitAmount < (_amount / 1000)) {  // if forfeitAmount is smaller than 0.1% ignore to save gas fee
            forfeitAmount = 0;
            rewardableAmount = _amount;

    function getRewardablePercentWAD(address _user) override public view returns(uint256 percent) {
        uint256 fullyInLock = getUserTotalLocked(_user);
        uint256 inCoolDown = getUserAmountInCoolDown(_user);
        uint256 userTotalmWomSV = fullyInLock + inCoolDown;
        if (userTotalmWomSV == 0)
            return 0;
        percent = fullyInLock * 1e18 / userTotalmWomSV;

        uint256 timeNow = block.timestamp;
        UserUnlocking[] storage userUnlocking = userUnlockings[_user];

        for (uint256 i; i < userUnlocking.length; i++) {
            if (userUnlocking[i].amountInCoolDown > 0) {
                if (block.timestamp > userUnlocking[i].endTime) {// fully unlocked 
                    percent += userUnlocking[i].amountInCoolDown * 1e18 * (userUnlocking[i].endTime - userUnlocking[i].startTime)
                        / userTotalmWomSV / (timeNow - userUnlocking[i].startTime);
                }
                else {// still in cool down 
                    percent += userUnlocking[i].amountInCoolDown * 1e18 / userTotalmWomSV;
                }

            }
        }

        return percent;
    }
