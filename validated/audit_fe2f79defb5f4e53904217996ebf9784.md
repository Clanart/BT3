### Title
Unhandled `IndexError` in mempool CLVM canonical-form check on attacker-controlled spend bundle bytes causes spend-processing exception during mempool admission - ([File: chia/full_node/mempool_manager.py])

### Summary
`is_clvm_canonical()` / `is_atom_canonical()` in `chia/full_node/mempool_manager.py` parse the raw serialized CLVM bytes of a submitted `CoinSpend`'s `puzzle_reveal` and `solution` to decide DEDUP/fast-forward eligibility during mempool admission. The parser indexes into the buffer using length values taken directly from the buffer's own header bytes, without ever validating that the buffer actually contains that many remaining bytes.

### Finding Description
`is_atom_canonical(clvm_buffer, offset)` reads a multi-byte length-prefix atom header: [1](#0-0) 

The prefix-decoding loop does `offset += 1; atom_len |= clvm_buffer[offset]` for `prefix_len` iterations with no bounds check against `len(clvm_buffer)`. It then returns `1 + prefix_len + atom_len` as the "length to skip" — again without checking whether `atom_len` bytes actually exist in the remaining buffer.

`is_clvm_canonical()` drives this over the whole buffer: [2](#0-1) 
It does `offset += atom_len` (the untrusted, unvalidated skip length) and then loops back to `b = clvm_buffer[offset]`. If `atom_len` was crafted to be larger than the remaining bytes, this next read overruns the buffer and Python raises `IndexError: index out of range` rather than gracefully returning `False`.

This function is invoked directly, with no surrounding `try/except`, on attacker-controlled bytes during spend-bundle admission: [3](#0-2) 
`validate_spend_bundle()` is called by `add_spend_bundle()` with no exception handling around it either: [4](#0-3) 

Existing tests confirm the function is reachable with attacker-controlled non-canonical/truncated encodings and is exercised as part of normal mempool admission (`test_mempool_requires_canonical_clvm`, `test_atom_not_canonical`), but those tests only cover truncated *prefix* bytes long enough to avoid crossing the true buffer boundary in the outer loop — they do not cover the case where the *body* length encoded in the header exceeds the remaining bytes, which is the case that skips past the end of the buffer in `is_clvm_canonical`'s second read. [5](#0-4) 

This is functionally analogous to the reported FastDDS bug class: a remote, unprivileged party (any spend-bundle submitter) supplies a malformed serialized payload whose embedded length field is inconsistent with the actual buffer size, and the receiving parser trusts that length field when advancing/reading, producing an out-of-bounds access instead of a controlled parse failure.

### Impact Explanation
An `IndexError` raised inside `validate_spend_bundle()` is not caught anywhere in the call chain shown (`add_spend_bundle` → `validate_spend_bundle` → `is_clvm_canonical`). Depending on how the RPC/protocol layer that ultimately invokes `add_spend_bundle` for incoming transactions handles unexpected exceptions, this can propagate as an unhandled exception during spend-bundle processing, disrupting transaction admission for that request/task. This falls squarely into the "spend-triggered transaction-processing halt" impact category rather than memory-safety-heap-overflow-with-code-execution (Python bounds-checks arrays and raises `IndexError` instead of true heap corruption), so the severity ceiling is lower than the C++ original, but the reachability (any wallet or peer submitting a spend bundle with a crafted `puzzle_reveal`/`solution`) and the lack of local exception handling at the parsing call site make this a legitimate DoS-class analog.

### Likelihood Explanation
Likelihood is high for triggering the parse fault itself: constructing a `CoinSpend` whose `puzzle_reveal` or `solution` bytes end with a truncated/oversized atom-length header is trivial and requires no signature validation to reach this code path (the canonical check happens before/alongside other validation in `validate_spend_bundle`). Whether this actually crashes the full node process or is caught by an outer handler elsewhere in `full_node.py` (not fully confirmed by the exploration performed) determines whether the practical impact is "transaction rejected with a stack trace logged" versus a more severe processing halt; this uncertainty should be resolved by tracing the exact call sites in `full_node.py` (`respond_transaction`/RPC push_tx handlers) that invoke `add_spend_bundle`.

### Recommendation
Add explicit bounds checks in `is_atom_canonical()` before each buffer read/index (mirroring the defensive pattern already used in `chia/full_node/full_block_utils.py`'s `skip_bytes`/`skip_list`, which validate remaining-buffer length before trusting an embedded length prefix), and have `is_atom_canonical`/`is_clvm_canonical` return `False` (non-canonical) rather than raise on any out-of-range access. Additionally, wrap the canonical-form check call site in `validate_spend_bundle()` with explicit handling that treats any parsing exception as `Err.INVALID_COIN_SOLUTION` rather than letting it propagate.

### Proof of Concept
Construct a `CoinSpend` whose `solution` (or `puzzle_reveal`) is a single top-level atom whose header declares a 5-byte length prefix but only provides 1 trailing byte, e.g. bytes `\xfc\xff` (header byte `0xFC` signals a 5-byte length prefix per the `0b11111100`/`mask=0b00000001` branch, but the buffer ends immediately after 1 more byte, well short of both the prefix bytes and the declared atom body). Submitting a `SpendBundle` containing this as `solution` to `MempoolManager.add_spend_bundle()`/`validate_spend_bundle()` reaches the unguarded `is_clvm_canonical(bytes(coin_spend.solution))` call at `chia/full_node/mempool_manager.py:723-726`, and `is_atom_canonical`'s prefix-decoding loop (`chia/full_node/mempool_manager.py:177-181`) indexes past the end of the buffer, raising `IndexError` before any `try/except` in the admission path catches it — mirroring `chia/_tests/clvm/test_chialisp_deserialization.py`'s `serialized_atom_overflow()` helper pattern used to build oversized/truncated atom headers, but targeted at the un-bounds-checked `is_atom_canonical` path instead of the (already exception-tolerant) chialisp deserializer.

```python
def is_atom_canonical(clvm_buffer: bytes, offset: int) -> tuple[int, bool]:
    b = clvm_buffer[offset]
    if (b & 0b11000000) == 0b10000000:
        # 6 bits length prefix
        mask = 0b00111111
        prefix_len = 0
        min_value = 1
    elif (b & 0b11100000) == 0b11000000:
        # 5 + 8 bits length prefix
        mask = 0b00011111
        prefix_len = 1
        min_value = 1 << 6
    elif (b & 0b11110000) == 0b11100000:
        # 4 + 8 + 8 bits length prefix
        mask = 0b00001111
        prefix_len = 2
        min_value = 1 << (5 + 8)
    elif (b & 0b11111000) == 0b11110000:
        # 3 + 8 + 8 + 8 bits length prefix
        mask = 0b00000111
        prefix_len = 3
        min_value = 1 << (4 + 8 + 8)
    elif (b & 0b11111100) == 0b11111000:
        # 2 + 8 + 8 + 8 + 8 bits length prefix
        mask = 0b00000011
        prefix_len = 4
        min_value = 1 << (3 + 8 + 8 + 8)
    elif (b & 0b11111110) == 0b11111100:
        # 1 + 8 + 8 + 8 + 8 + 8 bits length prefix
        mask = 0b00000001
        prefix_len = 5
        min_value = 1 << (2 + 8 + 8 + 8 + 8)

    atom_len = b & mask
    for i in range(prefix_len):
        atom_len <<= 8
        offset += 1
        atom_len |= clvm_buffer[offset]

    return 1 + prefix_len + atom_len, atom_len >= min_value
```

```python
def is_clvm_canonical(clvm_buffer: bytes) -> bool:
    """
    checks whether the CLVM serialization is all canonical representation.
    atoms can be serialized in more than one way by using more bytes than
    necessary to encode the length prefix. This functions ensures that all atoms are
    encoded with the shortest representation. back-references are not allowed
    and will make this function return false
    """
    assert clvm_buffer != b""

    offset = 0
    tokens_left = 1
    while True:
        b = clvm_buffer[offset]

        # pair
        if b == 0xFF:
            tokens_left += 1
            offset += 1
            continue

        # back references cannot be considered canonical, since they may be
        # encoded in many different ways
        if b == 0xFE:
            return False

        # small atom or NIL
        if b <= 0x80:
            tokens_left -= 1
            offset += 1
        else:
            atom_len, canonical = is_atom_canonical(clvm_buffer, offset)
            if not canonical:
                return False
            tokens_left -= 1
            offset += atom_len

        if tokens_left == 0:
            break

    # if there's garbage at the end, it's not canonical
    return offset == len(clvm_buffer)
```
