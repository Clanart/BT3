### Title
Spoofed `WWW-Authenticate` header from an attacker-controlled remote triggers a GitHub Enterprise sign-in bound to an attacker-controlled endpoint - ([File: app/src/lib/trampoline/trampoline-credential-helper.ts])

### Summary
`getEndpointKind()` in the git credential-helper trampoline classifies an arbitrary HTTPS remote as GitHub Enterprise (`'enterprise'`) solely because the remote's HTTP 401 response contained a `WWW-Authenticate` header whose value includes `realm="GitHub"`. That value is fully attacker-controlled (it comes verbatim from the server Git is talking to). Once classified as `'enterprise'`, Desktop automatically pops the real "Sign in to GitHub Enterprise" dialog and binds it to the attacker's own host, without any origin allow-listing or verification.

### Finding Description
When Git needs credentials for an HTTPS remote it invokes Desktop's credential-helper trampoline (`createCredentialHelperTrampolineHandler` → `getCredential`), passing along any `wwwauth[]` fields it captured from the server's `WWW-Authenticate` response header.

`getEndpointKind` uses these fields as a "happy path" heuristic: [1](#0-0) 

If the value contains `realm="GitHub"`, the function returns `'enterprise'` for the endpoint — regardless of the actual hostname, TLS certificate, or any other verification against github.com/GHE: [2](#0-1) 

This classification feeds directly into `getCredential`. When the endpoint is not `'generic'` and no existing account matches it, Desktop calls `ui.promptForGitHubSignIn(endpoint)`: [3](#0-2) 

`promptForGitHubSignIn` then binds the real Enterprise sign-in UI to the attacker's origin: [4](#0-3) 

Because `hostname !== 'github.com'`, it calls `dispatcher.beginEnterpriseSignIn(cb)` and `dispatcher.setSignInEndpoint(origin)` where `origin` is derived from the attacker-controlled credential URL. This launches Desktop's legitimate, trusted-looking GitHub Enterprise sign-in flow (basic auth or OAuth) but targets the attacker's server as the "enterprise" endpoint.

The broken invariant: **only a real GitHub/GHE server should ever cause Desktop's GitHub sign-in flow to be triggered and bound to its endpoint.** Here, any git server the user clones from, adds as a remote, or is redirected to via a MITM/rogue proxy can forge this trust signal simply by returning a crafted `WWW-Authenticate` header on a 401 response — no TLS pinning, hostname allow-list, or `.well-known`/API probe is required before trusting the realm string.

### Impact Explanation
An attacker who controls a git remote (e.g. a malicious/rogue git server the victim is told to clone from) or who can tamper with the HTTP response (a MITM proxy on an untrusted network) can cause GitHub Desktop to present its official "Sign in to GitHub Enterprise" experience pointed at the attacker's own host. A user who completes this flow (enters username/password, or a device/OAuth code) sends credentials or authorization material to the attacker-controlled endpoint, since the sign-in endpoint (`setSignInEndpoint(origin)`) is the attacker's origin, not github.com. This can lead to credential/token exfiltration and an account being bound to an attacker-supplied endpoint inside Desktop's account store — both explicitly in-scope impact categories (unauthorized OAuth/account binding, credential exfiltration).

### Likelihood Explanation
The attacker only needs to control (or intercept) a single HTTP(S) response to a git credential-fetch request — something already reachable in the report's allowed threat model ("attacker controls ... a git remote/proxy response"). No local access, no prior compromise, and no unusual user action beyond normal "clone/fetch from an untrusted remote" and completing a sign-in dialog that visually matches the legitimate flow is required, making this moderately likely for a targeted social/supply-chain attack (e.g., luring someone to clone a "GHE" repo).

### Recommendation
Do not trust the `WWW-Authenticate: realm="GitHub"` value as a sufficient signal to classify a host as GitHub Enterprise. At minimum:
- Require the network probe (`isGitHubHost(endpoint)`, already used as the fallback at line 178) to also validate hosts flagged via the `wwwauth` heuristic before elevating them to `'enterprise'`.
- Only auto-trigger the Enterprise/dotcom sign-in popup for hosts that pass this verification, or surface a distinct, clearly-labeled warning UI when the trust signal comes solely from a self-reported header rather than a verified GitHub API response.
- Consider caching/allow-listing verified GHE hosts so repeated sign-in prompts aren't spoofable per-connection.

### Proof of Concept
1. Attacker stands up an HTTPS git server (or MITM proxy) at `https://attacker.example/victim/repo.git`.
2. Victim adds/clones this remote in GitHub Desktop.
3. On the first authenticated Git operation (fetch/clone), the attacker's server returns `401 Unauthorized` with header `WWW-Authenticate: Basic realm="GitHub"`.
4. Git forwards this via `wwwauth[0]=...` to Desktop's credential-helper trampoline (`createCredentialHelperTrampolineHandler` → `getCredential` → `getEndpointKind`).
5. `getEndpointKind` returns `'enterprise'` purely from the header match (`trampoline-credential-helper.ts:157-165`), with no account found for `attacker.example`.
6. `getCredential` calls `ui.promptForGitHubSignIn('https://attacker.example')`.
7. `promptForGitHubSignIn` calls `dispatcher.beginEnterpriseSignIn` + `dispatcher.setSignInEndpoint('https://attacker.example')` and shows the real Sign-In popup, with the endpoint field pointed at the attacker's server.
8. If the victim proceeds with sign-in, their credentials/OAuth exchange are sent to `attacker.example`.

Note: I was not able to inspect `dispatcher.beginEnterpriseSignIn` / `setSignInEndpoint` implementations in this session (ran out of tool budget), so the exact wire protocol used during sign-in (basic auth vs. OAuth device flow, and whether any additional endpoint validation exists further down that call chain) should be confirmed by reviewing `app/src/ui/dispatcher/dispatcher.ts` and the sign-in store before finalizing severity/exploitability.

/** Implementation of the 'get' git credential helper command */
async function getCredential(cred: Credential, store: Store, token: string) {
  const ghCred = await getGitHubCredential(cred, store)

  if (ghCred) {
    return ghCred
  }

  const endpointKind = await getEndpointKind(cred, store)
  const accounts = await store.getAll()

  const endpoint = `${getCredentialUrl(cred)}`
  const apiEndpoint = getAPIEndpoint(endpoint)

  // If it appears as if the endpoint is a GitHub host and we don't have an
  // account for that endpoint then we should prompt the user to sign in.
  if (
    endpointKind !== 'generic' &&
    !accounts.some(a => a.endpoint === apiEndpoint)
  ) {
    if (getIsBackgroundTaskEnvironment(token)) {
      debug('background task environment, skipping prompt')
      return undefined
    }

    const account = await ui.promptForGitHubSignIn(endpoint)

    if (!account) {
      setHasRejectedCredentialsForEndpoint(token, endpoint)
    }

    return credWithAccount(cred, account)
  }

const getEndpointKind = async (cred: Credential, store: Store) => {
  const credentialUrl = getCredentialUrl(cred)
  const endpoint = `${credentialUrl}`

  if (isGist(endpoint)) {
    return 'generic'
  }

  if (isDotCom(endpoint)) {
    return 'github.com'
  }

  if (isGHE(endpoint)) {
    return 'ghe.com'
  }

  // When Git attempts to authenticate with a host it captures any
  // WWW-Authenticate headers and forwards them to the credential helper. We
  // use them as a happy-path to determine if the host is a GitHub host without
  // having to resort to making a request ourselves.
  for (const [k, v] of cred.entries()) {
    if (k.startsWith('wwwauth[')) {
      if (v.includes('realm="GitHub"')) {
        return 'enterprise'
      } else if (/realm="(GitLab|Gitea|Atlassian Bitbucket)"/.test(v)) {
        return 'generic'
      }
    }
  }

  const existingAccount = await findGitHubTrampolineAccount(store, endpoint)
  if (existingAccount) {
    return isDotCom(existingAccount.endpoint) ? 'github.com' : 'enterprise'
  }

  // All GitHub hosts use HTTPS, so if the protocol is not HTTPS we can
  // assume that this is not a GitHub host.
  if (credentialUrl.protocol !== 'https:') {
    return 'generic'
  }

  return (await isGitHubHost(endpoint)) ? 'enterprise' : 'generic'
}

  public promptForGitHubSignIn(endpoint: string): Promise<Account | undefined> {
    return new Promise<Account | undefined>(async resolve => {
      const cb = (result: SignInResult) => {
        resolve(result.kind === 'success' ? result.account : undefined)
        this.dispatcher.closePopup(PopupType.SignIn)
      }

      const { hostname, origin } = new URL(endpoint)
      if (hostname === 'github.com') {
        this.dispatcher.beginDotComSignIn(cb)
      } else {
        this.dispatcher.beginEnterpriseSignIn(cb)
        await this.dispatcher.setSignInEndpoint(origin)
      }

      this.dispatcher.showPopup({
        type: PopupType.SignIn,
        isCredentialHelperSignIn: true,
        credentialHelperUrl: endpoint,
      })
    }).catch(e => {
      log.error(`Could not prompt for GitHub sign in`, e)
      return undefined
    })
  }
