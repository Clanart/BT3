### Title
Git credential helper classifies arbitrary HTTP remotes as GitHub Enterprise via unauthenticated `WWW-Authenticate` header, enabling credential-phishing sign-in prompts - (File: `app/src/lib/trampoline/trampoline-credential-helper.ts`)

### Summary
When Git performs HTTP authentication against a remote, it forwards any `WWW-Authenticate` response headers to Desktop's credential helper as `wwwauth[]` fields. `getEndpointKind` treats the mere presence of `realm="GitHub"` in that header as sufficient proof that an arbitrary, attacker-controlled host is a legitimate GitHub Enterprise instance, without any authenticity check equivalent to a certificate/identity validation. This "happy path" is explicitly used to skip the app's own verification (`isGitHubHost`), which does perform an actual network round-trip to confirm the identity of the host.

### Finding Description
`getEndpointKind` in [1](#0-0) . This bypasses the legitimate, network-based verification path, `isGitHubHost`, which is only invoked as a fallback when no such header is present [2](#0-1) .

Once classified as `'enterprise'`, `getCredential` checks whether a stored account already exists for the derived `apiEndpoint`; if not, it calls `ui.promptForGitHubSignIn(endpoint)` [3](#0-2) . `promptForGitHubSignIn` then [4](#0-3) .

The attacker only needs to control an HTTP(S) git remote — e.g. a repository the victim clones/fetches from an untrusted host, or a corporate proxy — and respond to Git's authentication probe with a crafted `WWW-Authenticate: Basic realm="GitHub"` header. No certificate pinning, hostname allow-list, or the app's own `isGitHubHost` check is consulted once this header is present, because the header check runs before, and short-circuits, the identity verification.

### Impact Explanation
This reproduces the report's broken invariant — "no checks to verify authenticity before trusting an object as a legitimate/validated entity" — mapped onto GitHub Desktop's trust boundary between untrusted remotes and its native GitHub authentication UI. Concretely:
- A victim who adds/fetches from a malicious or compromised HTTP git remote can be shown Desktop's real "Sign in to GitHub Enterprise" dialog for a host that is not actually GitHub, increasing the odds the victim enters a personal access token or completes an OAuth/browser flow believing they are authenticating to a trusted GitHub Enterprise instance.
- Any credentials/PAT/OAuth token the victim supplies in that flow are bound to the attacker's endpoint (`credWithAccount`) and will subsequently be sent by git as Basic Auth to that same attacker-controlled host on the next credential fill, i.e. captured directly by the attacker.
- This satisfies "unauthorized OAuth or account binding, credential/token exfiltration" driven purely by attacker-controlled server responses to a git fetch/clone — no local access or prior compromise required.

### Likelihood Explanation
Setting a `WWW-Authenticate` header on a 401 response is basic, unauthenticated HTTP server behavior — any git host the victim is pointed to (public clone URL, malicious mirror, transparent proxy) can trivially include `realm="GitHub"`. The victim's only required action is a normal git operation (clone/fetch/push) against that remote, which Desktop performs automatically as part of everyday use.

### Recommendation
Do not treat the `WWW-Authenticate` realm string as authoritative. Always corroborate it with an independent check (the existing `isGitHubHost` network probe, and/or TLS certificate/hostname validation) before classifying a host as `'enterprise'`/GitHub and before invoking `promptForGitHubSignIn`. At minimum, require the host to pass `isGitHubHost` (or match a hostname allow-list/known pattern) in addition to the header hint, rather than allowing the header alone to short-circuit verification.

### Proof of Concept
1. Stand up an HTTP server that responds to Git's credential probe (a `GET`/`HEAD` on the repo path) with `401` and header `WWW-Authenticate: Basic realm="GitHub"`.
2. Have the victim clone/fetch from `https://attacker.example.com/foo.git` in GitHub Desktop.
3. Git forwards the `wwwauth[]=Basic realm="GitHub"` value to Desktop's credential helper via `getCredential`/`getEndpointKind` [5](#0-4) .
4. Since no account exists for `attacker.example.com`, Desktop shows its native GitHub Enterprise "Sign in" popup bound to that origin [6](#0-5) .
5. If the victim completes sign-in (PAT or browser OAuth), the resulting credential is handed back to git and transmitted as Basic Auth to `attacker.example.com`, exfiltrating it.

/**
 * Attempts to determine whether or not the url belongs to a GitHub host.
 *
 * This is a best-effort attempt and may return `undefined` if encountering
 * an error making the discovery request
 */
export async function isGitHubHost(url: string) {
  const { hostname } = new window.URL(url)

  const endpoint =
    hostname === 'github.com' || hostname === 'api.github.com'
      ? getDotComAPIEndpoint()
      : getEnterpriseAPIURL(url)

  if (isDotCom(endpoint) || isGHE(endpoint)) {
    return true
  }

  if (isKnownThirdPartyHost(hostname)) {
    return false
  }

  // github.example.com,
  if (/(^|\.)(github)\./.test(hostname)) {
    return true
  }

  // bitbucket.example.com, etc
  if (/(^|\.)(bitbucket|gitlab)\./.test(hostname)) {
    return false
  }

  if (getEndpointVersion(endpoint) !== null) {
    return true
  }

  // Add a unique identifier to the URL to make sure our certificate error
  // supression only catches this request
  const metaUrl = `${endpoint}/meta?ghd=${crypto.randomUUID()}`

  const ac = new AbortController()
  const timeoutId = setTimeout(() => ac.abort(), 2000)
  suppressCertificateErrorFor(metaUrl)
  try {
    const response = await fetch(metaUrl, {
      headers: { 'user-agent': getUserAgent() },
      signal: ac.signal,
      credentials: 'omit',
      method: 'HEAD',
      redirect: 'error',
    })

    tryUpdateEndpointVersionFromResponse(endpoint, response)

    return response.headers.has('x-github-request-id')
  } catch (e) {
    log.debug(`isGitHubHost: failed with endpoint ${endpoint}`, e)
    return undefined
  } finally {
    clearTimeout(timeoutId)
    clearCertificateErrorSuppressionFor(metaUrl)
  }
}
