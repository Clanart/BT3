### Title
Deterministic nonce reuse across distinct DKG confirmation messages leaks validator key share - (File: coordinator/src/tributary/signing_protocol.rs)

### Summary
The FROST `AlgorithmSignMachine` derives its nonces deterministically from a `CachedPreprocess` seed (`ChaCha20Rng::from_seed`), and `SigningProtocol::preprocess_internal` stores that seed keyed only by `context = (b"DkgConfirmer", attempt)`. Both `DkgConfirmer::share` and `DkgConfirmer::complete` call `share_internal`, which re-runs `preprocess_internal` and therefore regenerates the identical nonce. The signed message is `set_keys_message(set, removed, key_pair)`, where `key_pair` is a caller-supplied argument that can differ between invocations while the context (and hence the nonce) stays fixed. Two shares published under the same nonce with different challenges reveal the validator's secret share linearly. [1](#0-0) [2](#0-1) [3](#0-2) 

### Finding Description
`AlgorithmMachine::seeded_preprocess` seeds `ChaCha20Rng` from `CachedPreprocess`, so all nonce material is a pure function of the seed. `SigningProtocol::preprocess_internal` caches that seed in `CachedPreprocesses` keyed solely by `context`; for `DkgConfirmer` the context is `(b"DkgConfirmer", self.attempt)`. `share_internal` rebuilds the sign machine from the cached seed and then calls `machine.sign(preprocesses, msg)` where `msg = set_keys_message(...)` is computed from the `key_pair` argument. `DkgConfirmer::share` publishes a share for one `key_pair`/`preprocesses` input, and `complete` later calls `share_internal` again — same seed, same nonces — with potentially different `preprocesses` and `key_pair`. Per the FROST spec comment in the same file, "it is explicitly unsafe to reuse nonces across signing sessions," and safety is argued only because received messages are BFT-finalized; however the `msg` is locally derived from `key_pair` (the DKG result being confirmed), not from the BFT-ordered preprocesses. If the confirmable `key_pair` for a given attempt ever differs between the `share` and `complete` executions (e.g., the transaction carries a different `KeyPair` on re-execution, or a `Partial` rebuild shares the attempt context), the same nonce `d + be` is used to produce shares `s1 = d + be·rho + λ·x·c1` and `s2 = d + be·rho + λ·x·c2` with `c1 ≠ c2`. The file itself flags this as an unreviewed area: "TODO: We also need to review how we're handling Processor preprocesses" and the missing "preprocess-matches-presumed-preprocess check."

### Impact Explanation
Schnorr/FROST nonce reuse across two distinct challenges is the classic key-recovery equation: `x = (s1 - s2) / (λ·(c1 - c2))`. Both shares are published on-chain/in the protocol transcript, so any observer can recover the validator's MuSig secret key — the root-of-trust key used to confirm DKG results — without any privileged position. This is a direct analog of the CVE class (stale/swapped state exposing sensitive information): the stale cached nonce is "swapped" into a signing context with a different message.

### Likelihood Explanation
Exploitation requires `share`/`complete` to be invoked twice under the same `(b"DkgConfirmer", attempt)` context with differing `msg` or preprocess sets. The BFT ordering argument in the header only covers the *received* preprocesses; it does not bind `key_pair`, which is independently derived per call. Rebuild/re-execution paths (partial rebuilds are noted as dangerous but only "accepted" as a bound, not enforced) and retries of confirmation transactions for the same attempt can re-execute `sign` with a different `set_keys_message`. Reachable entirely from publicly observable shares once triggered.

### Recommendation
Include the message (or a commitment to `key_pair`/`removed`) in the `CachedPreprocesses` context key, or store the signed `msg` alongside the cached seed and refuse to sign a different message with the same cached preprocess. Additionally implement the noted TODO: verify the on-chain preprocesses match the locally presumed preprocess before publishing shares.

### Proof of Concept
1. `DkgConfirmer::share(preprocesses_A, key_pair_1)` executes `share_internal` → `preprocess_internal` loads seed `S` cached under `(b"DkgConfirmer", attempt)` → `seeded_preprocess(S)` produces nonce `k`; share `s1 = k·rho + λ·x·H(R‖P‖m1)` is emitted.
2. `DkgConfirmer::complete(preprocesses_B, key_pair_2, shares)` executes `share_internal` again → same seed `S` → same nonce `k` and same nonce commitments `R`; share `s2 = k·rho + λ·x·H(R‖P‖m2)` is produced.
3. Observer computes `x = (s1 - s2)·(λ·(H(...m1) - H(...m2)))⁻¹`, recovering the validator's private key share.

  fn seeded_preprocess(
    self,
    seed: CachedPreprocess,
  ) -> (AlgorithmSignMachine<C, A>, Preprocess<C, A::Addendum>) {
    let mut params = self.params;

    let mut rng = ChaCha20Rng::from_seed(*seed.0);
    let (nonces, commitments) = Commitments::new::<_>(
      &mut rng,
      params.keys.original_secret_share(),
      &params.algorithm.nonces(),
    );
    let addendum = params.algorithm.preprocess_addendum(&mut rng, &params.keys);

    let preprocess = Preprocess { commitments, addendum };

    // Also obtain entropy to randomly sort the included participants if we need to identify blame
    let mut blame_entropy = [0; 32];
    rng.fill_bytes(&mut blame_entropy);
    (
      AlgorithmSignMachine { params, seed, nonces, preprocess: preprocess.clone(), blame_entropy },
      preprocess,
    )
  }

  fn share_internal(
    &mut self,
    preprocesses: HashMap<Participant, Vec<u8>>,
    key_pair: &KeyPair,
  ) -> Result<(AlgorithmSignatureMachine<Ristretto, Schnorrkel>, [u8; 32]), Participant> {
    let participants = self.spec.validators().iter().map(|val| val.0).collect::<Vec<_>>();
    let preprocesses =
      threshold_i_map_to_keys_and_musig_i_map(self.spec, &self.removed, self.key, preprocesses).1;
    let msg = set_keys_message(
      &self.spec.set(),
      &self.removed.iter().map(|key| Public::from(key.to_bytes())).collect::<Vec<_>>(),
      key_pair,
    );
    self.signing_protocol().share_internal(&participants, preprocesses, &msg)
  }
  // Get the share for this confirmation, if the preprocesses are valid.
  pub(crate) fn share(
    &mut self,
    preprocesses: HashMap<Participant, Vec<u8>>,
    key_pair: &KeyPair,
  ) -> Result<[u8; 32], Participant> {
    self.share_internal(preprocesses, key_pair).map(|(_, share)| share)
  }

  pub(crate) fn complete(
    &mut self,
    preprocesses: HashMap<Participant, Vec<u8>>,
    key_pair: &KeyPair,
    shares: HashMap<Participant, Vec<u8>>,
  ) -> Result<[u8; 64], Participant> {
    let shares =
      threshold_i_map_to_keys_and_musig_i_map(self.spec, &self.removed, self.key, shares).1;

    let machine = self
      .share_internal(preprocesses, key_pair)
      .expect("trying to complete a machine which failed to preprocess")
      .0;

    DkgConfirmerSigningProtocol::<'_, T>::complete_internal(machine, shares)
  }
