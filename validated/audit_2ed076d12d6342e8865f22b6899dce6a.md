### Title
Payout OP_RETURN attribution is not covered by the user's signature, letting any funder hijack another operator's reimbursement credit - (File: core/src/builder/transaction/operator_reimburse.rs)

### Summary
The `payout_tx` that fronts a Citrea withdrawal only has its user input and the user-payout output (index 0) bound by the user's `SIGHASH_SINGLE|ANYONECANPAY` signature. The OP_RETURN output that records which operator "fronted" the withdrawal — the sole piece of on-chain data used later to decide who gets reimbursed — is unsigned and freely mutable. Any party able to fund the transaction (add the missing input value and replace it before confirmation) can rewrite the OP_RETURN to point to a different `operator_xonly_pk`, hijacking the reimbursement credit for a withdrawal it never funded for the user.

### Finding Description
`create_payout_txhandler` builds the payout transaction with:
- input 0: the withdrawal UTXO, spent with `SpendPath::KeySpend` using the user's `taproot::Signature` (`SinglePlusAnyoneCanPay`, per the RPC docs and verification logic),
- output 0: the user payout (covered by SIGHASH_SINGLE since it shares the input's index),
- output 1: anchor (uncommitted),
- output 2: `OP_RETURN` with `operator_xonly_pk.serialize()` (uncommitted). [1](#0-0) 

`SIGHASH_SINGLE | ANYONECANPAY` only binds the signed input and the output at the *same index* as that input. Outputs 1 and 2 (anchor and OP_RETURN) are outside the commitment, and `ANYONECANPAY` explicitly allows adding other inputs. The operator doc-comment on `internal_withdraw`/`withdraw` even states the payout tx is "funded ... using TxSender RBF option," confirming that funding (and thus the anchor/OP_RETURN outputs) is completed after the user signs, by whichever party broadcasts. [2](#0-1) 

Later, the protocol determines "who fronted the withdrawal" purely by parsing this same, unsigned OP_RETURN field from the confirmed on-chain transaction: [3](#0-2) 

and persists it as the `payout_payer_operator_xonly_pk` binding used to authorize reimbursement: [4](#0-3) 

That binding is then trusted to decide which operator's kickoff is legitimate (`is_kickoff_malicious`) and which operator is queued for reimbursement (`PayoutCheckerTask` / `handle_finalized_payout`): [5](#0-4) [6](#0-5) 

Because the OP_RETURN is unsigned, any entity that can add funding inputs to the still-unconfirmed payout transaction (RBF) can rebroadcast a variant with the identical signed input and identical user-facing output 0 (so the user still gets paid, the signature still verifies), but with output 2 rewritten to name a different `operator_xonly_pk`. The equality the protocol relies on — "operator that actually funded the payout" == "operator recorded in the payout tx OP_RETURN" — is not enforced by any signature, and can be broken by whoever wins the RBF race.

### Impact Explanation
If exploited, the reimbursement credit (`payout_payer_operator_xonly_pk`) can be attributed to an operator who did not supply the funding, or invalidated (set to an unregistered pubkey). This maps directly to the Critical impact category "an operator reimbursed for a payout it never funded" / "an honest operator permanently unable to be reimbursed" — the honest operator who intended to front the withdrawal can be preempted by another party's higher-fee RBF replacement, losing the ability to later claim the `Reimburse` tx for that deposit, while an attacker's chosen `operator_xonly_pk` is falsely recorded as payer.

### Likelihood Explanation
The attack only requires observing the broadcast (but unconfirmed) payout transaction in the mempool and constructing a fee-bumped `ANYONECANPAY` replacement — no privileged role, key compromise, or protocol misconfiguration is needed. The window is exactly the interval between broadcast and confirmation, which for Bitcoin can be non-trivial (multiple blocks), making it a realistic race for anyone monitoring the mempool.

### Recommendation
Bind the payout attribution to the user's signature, e.g. by including the OP_RETURN operator commitment inside the sighash the user signs (not possible with pure `SINGLE|ANYONECANPAY` on a single output) or by using a signature scheme/commitment (e.g., `SIGHASH_ALL` for the relevant outputs, or a separate covenant/commitment) that fixes the operator identity at signing time so it cannot be altered by whoever funds/broadcasts the transaction later.

### Proof of Concept
1. Operator A calls `withdraw`, producing a `payout_tx` with input 0 = withdrawal UTXO (user-signed, `SinglePlusAnyoneCanPay`), output 0 = user payout, output 2 = OP_RETURN(`A.xonly_pk`); TxSender queues it for RBF funding. [1](#0-0) 
2. Before confirmation, Operator/party B observes the mempool transaction, reuses the same signed input 0 and output 0 (the signature still validates because they are untouched and `SIGHASH_SINGLE|ANYONECANPAY` permits arbitrary other inputs/outputs), adds its own funding input(s) sufficient to cover output 0's value plus higher fees, and sets output 2 = OP_RETURN(`B.xonly_pk`).
3. B broadcasts this replacement with a higher fee; it confirms instead of A's original.
4. `update_finalized_payouts` parses the confirmed tx's OP_RETURN and records `payout_payer_operator_xonly_pk = B` in the `withdrawals` table. [3](#0-2) 
5. `PayoutCheckerTask`/`handle_finalized_payout` subsequently treats B as the legitimate payer and queues B (not A) for the kickoff/reimbursement flow, even though B did not front funds toward the user's payout output. [6](#0-5)

pub fn create_payout_txhandler(
    input_utxo: UTXO,
    output_txout: TxOut,
    operator_xonly_pk: XOnlyPublicKey,
    user_sig: taproot::Signature,
    _network: bitcoin::Network,
) -> Result<TxHandler<Signed>, BridgeError> {
    let txin = SpendableTxIn::new_partial(input_utxo.outpoint, input_utxo.txout);

    let output_txout = UnspentTxOut::from_partial(output_txout.clone());

    let op_return_txout = op_return_txout(PushBytesBuf::from(operator_xonly_pk.serialize()));

    let mut txhandler = TxHandlerBuilder::new(TransactionType::Payout)
        .with_version(NON_STANDARD_V3)
        .add_input(
            NormalSignatureKind::NotStored,
            txin,
            SpendPath::KeySpend,
            DEFAULT_SEQUENCE,
        )
        .add_output(output_txout)
        .add_output(UnspentTxOut::from_partial(anchor_output(
            NON_EPHEMERAL_ANCHOR_AMOUNT,
        )))
        .add_output(UnspentTxOut::from_partial(op_return_txout))
        .finalize();
    txhandler.set_p2tr_key_spend_witness(&user_sig, 0)?;
    txhandler.promote()
}

    /// Sets the given payout txs' txid and operator index for the given index.
    pub async fn update_payout_txs_and_payer_operator_xonly_pk(
        &self,
        tx: Option<DatabaseTransaction<'_>>,
        payout_txs_and_payer_operator_xonly_pk: Vec<(
            u32,
            Txid,
            Option<XOnlyPublicKey>,
            bitcoin::BlockHash,
        )>,
    ) -> Result<(), BridgeError> {
        if payout_txs_and_payer_operator_xonly_pk.is_empty() {
            return Ok(());
        }
        // Convert all values first, propagating any errors
        let converted_values: Result<Vec<_>, BridgeError> = payout_txs_and_payer_operator_xonly_pk
            .iter()
            .map(|(idx, txid, operator_xonly_pk, block_hash)| {
                Ok((
                    i32::try_from(*idx).wrap_err("Failed to convert payout index to i32")?,
                    TxidDB(*txid),
                    operator_xonly_pk.map(XOnlyPublicKeyDB),
                    BlockHashDB(*block_hash),
                ))
            })
            .collect();
        let converted_values = converted_values?;

        let mut query_builder = QueryBuilder::new(
            "UPDATE withdrawals AS w SET
                payout_txid = c.payout_txid,
                payout_payer_operator_xonly_pk = c.payout_payer_operator_xonly_pk,
                payout_tx_blockhash = c.payout_tx_blockhash
                FROM (",
        );

        query_builder.push_values(
            converted_values.into_iter(),
            |mut b, (idx, txid, operator_xonly_pk, block_hash)| {
                b.push_bind(idx)
                    .push_bind(txid)
                    .push_bind(operator_xonly_pk)
                    .push_bind(block_hash);
            },
        );

        query_builder
            .push(") AS c(idx, payout_txid, payout_payer_operator_xonly_pk, payout_tx_blockhash) WHERE w.idx = c.idx");

        let query = query_builder.build();
        execute_query_with_tx!(self.connection, tx, query, execute)?;

        Ok(())
    }
