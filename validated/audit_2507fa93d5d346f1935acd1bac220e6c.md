### Title
ThresholdKeys deserialization allows quadratic Lagrange interpolation denial of service - ([File: crypto/dkg/src/lib.rs](crypto/dkg/src/lib.rs))

### Summary
`ThresholdKeys::read` accepts attacker-controlled `t` and `n` values as `u16`, then deserializes `n` verification shares and invokes `ThresholdKeys::new`. [1](#0-0)  With Lagrange interpolation and `t == n == u16::MAX`, a roughly 2 MiB Ristretto encoding triggers `t` calls to `interpolation_factor`, each of which iterates over all `t` included participants, resulting in approximately 4.29 billion field operations before `read` returns. [2](#0-1) [3](#0-2) 

### Finding Description
The deserializer reads `t`, `n`, and `i` directly from the serialized input, supports `Interpolation::Lagrange`, and reads `n` group elements into `verification_shares`. [4](#0-3)  `ThresholdParams::new` permits every nonzero `t <= n`, so `t = n = 65,535` is accepted. [5](#0-4)  `ThresholdKeys::new` then calculates the group key by evaluating an interpolation factor for each of the first `t` participants. [3](#0-2)  For `Interpolation::Lagrange`, each factor performs an `O(included.len())` numerator and denominator calculation, making construction `O(t²)`. [6](#0-5) 

### Impact Explanation
An unprivileged caller supplying bytes to `ThresholdKeys::read` can make a processor spend disproportionate CPU time on a compact serialized object. [7](#0-6)  For 65,535 participants, the loop performs more than 4 billion scalar multiplications and comparisons, excluding hashing, point decoding, inversion, and allocation overhead. [8](#0-7)  This matches the reported bug class: ordinary-sized attacker input activates an algorithm whose cost grows far faster than its byte length, enabling denial of service against services deserializing supplied threshold-key encodings. [3](#0-2) 

### Likelihood Explanation
The attack only requires choosing Lagrange encoding and maximum supported `t`/`n`; no malformed participant index, invalid point, secret knowledge, or protocol collusion is needed. [9](#0-8)  The required payload is about 2 MiB for 32-byte verification shares, plus a secret-share scalar and header fields, while causing billions of field operations. [10](#0-9)  Since `ThresholdKeys::read` is a public deserialization API, any application that accepts serialized `ThresholdKeys` from untrusted input exposes this path. [11](#0-10) 

### Recommendation
Bound `n` to a protocol-supported maximum before reading or interpolation, rather than accepting any nonzero `u16`. [5](#0-4)  For Lagrange interpolation, cache participant values or derive a basis-independent representation so key construction is not quadratic; alternatively, precompute the group key during DKG output rather than reconstructing it with `O(t²)` work during deserialization. [2](#0-1)  The format should also serialize and validate an explicit participant count that cannot exceed deployment limits before `Vec`/`HashMap` population. [12](#0-11) 

### Proof of Concept
```rust
use std::io;
use ff::Field;
use group::GroupEncoding;
use dalek_ff_group::Ristretto;
use ciphersuite::Ciphersuite;
use frost::ThresholdKeys;

fn malicious_threshold_keys() -> Vec<u8> {
  let mut bytes = vec![];

  // Curve identifier expected by ThresholdKeys::read.
  bytes.extend(u32::try_from(Ristretto::ID.len()).unwrap().to_le_bytes());
  bytes.extend(Ristretto::ID);

  // t = n = u16::MAX, i = 1.
  bytes.extend(u16::MAX.to_le_bytes());
  bytes.extend(u16::MAX.to_le_bytes());
  bytes.extend(1u16.to_le_bytes());

  // Interpolation::Lagrange.
  bytes.push(1);

  // secret_share.
  bytes.extend(<Ristretto as Ciphersuite>::F::ONE.to_repr().as_ref());

  // n canonical verification shares.
  let point = Ristretto::generator().to_bytes();
  for _ in 1 ..= u16::MAX {
    bytes.extend(point.as_ref());
  }

  bytes
}

fn main() -> io::Result<()> {
  let bytes = malicious_threshold_keys();
  // This enters ThresholdKeys::new and performs approximately
  // u16::MAX * u16::MAX Lagrange coefficient operations.
  let _ = ThresholdKeys::<Ristretto>::read(&mut bytes.as_slice())?;
  Ok(())
}
```

  /// The interpolation factor for this participant, within this signing set.
  fn interpolation_factor(&self, i: Participant, included: &[Participant]) -> F {
    match self {
      Interpolation::Constant(c) => c[usize::from(u16::from(i) - 1)],
      Interpolation::Lagrange => {
        let i_f = F::from(u64::from(u16::from(i)));

        let mut num = F::ONE;
        let mut denom = F::ONE;

          if i == *l {
            continue;
