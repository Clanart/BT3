### Title
Bandwidth gate is not enforced on the `GetResponse` delivery path, letting apps consume bandwidth for free by using GET requests instead of POST — ([File: parachain/runtimes/gargantua/src/ismp.rs], [File: parachain/runtimes/nexus/src/ismp.rs])

### Summary
The bandwidth accounting model requires every non-purchase, non-allowlisted message from a metered source chain to be paid for through `BandwidthGate::try_consume` before it is processed [1](#0-0) . This is enforced in `ProxyModule::on_accept` (the `PostRequest` path) on both the Nexus and Gargantua runtimes [2](#0-1) [3](#0-2) . However, the sibling `on_response` handler for `GetResponse` messages — which is the callback invoked when a remote state-proof (`Get`) request resolves — never calls `try_consume` at all, on either runtime [4](#0-3) [5](#0-4) . The Gargantua comment even claims the gate "mirrors the request path in `on_accept`," but the code that would perform the deduction is absent.

### Finding Description
This is the same class of bug as the reported flash-loan interest-accrual mismatch: a shared metering/state-update step (`accrue_interest` there, `BandwidthGate::try_consume` here) is invoked on one path that touches an account/resource, but not on a structurally parallel path that touches the same resource.

`pallet-bandwidth`'s subscription ledger is meant to be drained by "every non-purchase POST request from a registered source chain" via `try_consume`, which sweeps expired entries, checks sufficiency, and deducts `remaining_bytes` from the FIFO head [6](#0-5) . In the runtime router, this call is wired into `on_accept` for inbound `PostRequest`s destined for the local chain [2](#0-1) .

The ISMP module trait also defines `on_response` for `GetResponse` — the callback fired when a cross-chain storage-proof read (`Request::Get`) resolves and is delivered back to the originating module [7](#0-6) . Both runtime routers implement this callback, but neither calls `BandwidthGate::try_consume`, despite the response payload (proof-carrying storage values) being attributable to the same `(source, app)` accounting keys used for POST bytes:

```rust
fn on_response(&self, response: GetResponse) -> Result<Weight, anyhow::Error> {
    // Bandwidth gate. Mirrors the request path in `on_accept`: the chain
    // and module that produced the response pay for the bytes they
    // deliver. Compiled out when the `no-bandwidth` flag is on.
    if response.dest_chain() != HostStateMachine::get() {
        return Ok(Weight::from_parts(0, 0));
    }
    let dest = &response.get.from;
    let pallet_id = ModuleId::from_bytes(dest).map_err(|err| Error::Custom(err.to_string()))?;
    match pallet_id {
        pallet_ismp_demo::PALLET_ID =>
            pallet_ismp_demo::IsmpModuleCallback::<Runtime>::default().on_response(response),
        _ => Err(anyhow!("Destination module not found")),
    }
}
``` [4](#0-3) 

The comment explicitly documents the intended invariant ("the chain and module that produced the response pay for the bytes they deliver") but the enforcement code that would call `try_consume` was never added — an inconsistency identical in shape to `end_flashloan` skipping `accrue_interest` for the repayment pool while `start_flashloan` calls it for the borrow pool.

### Impact Explanation
The bandwidth market is designed so that a metered `(source_chain, app)` pair must maintain a paid subscription before any inbound message is processed; insufficient balance causes `GateError::Insufficient`/`GateError::NoAllowance` rejection with no mutation [8](#0-7) . Because the `GetResponse` path performs no deduction, any module/app whose traffic can be shaped as GET-request/response round-trips (instead of POST requests) bypasses the paid-bandwidth model entirely — effectively an unlimited free-bandwidth channel for any registered source chain, undermining the "bandwidth balances must move exactly once and only to the rightful beneficiary and amount" invariant. This directly nullifies the value of the on-chain subscription ledger (`Allowance` storage) for any traffic on this path, causing the protocol's bandwidth revenue/accounting model to be silently circumvented — a logic attack on the metering invariant rather than mere gas/DoS noise, since it defeats the paid-resource enforcement the bounty scope calls out explicitly ("bandwidth balances must move exactly once").

### Likelihood Explanation
No privileged actor, relayer collusion, or malformed proof is required — any application dispatching `Request::Get` requests through the standard ISMP flow will have its response delivered through `on_response` without ever touching `BandwidthGate`. This is a straightforward, deterministic control-flow gap reachable by any unprivileged app on a registered source chain, making it trivially and repeatedly triggerable.

### Recommendation
Add a `BandwidthGate::try_consume(&response.dest_chain(), &response.get.from, encoded_len)` call (mirroring the `on_accept` block, including the `is_purchase_message`-style allowlist/purchase bypass logic where applicable) at the top of `on_response` in both `parachain/runtimes/gargantua/src/ismp.rs` and `parachain/runtimes/nexus/src/ismp.rs`, before dispatching to the destination module callback, so response bytes are metered exactly as request bytes are.

### Proof of Concept
1. Register a `BandwidthManager` for a source chain and configure a tier so an app has a finite `remaining_bytes` allowance (per the standard purchase flow) [9](#0-8) .
2. Deplete the app's POST-based allowance to zero (or never purchase one at all).
3. From the same app/source chain, dispatch a `Request::Get` (storage-proof read) targeting Hyperbridge/Nexus/Gargantua state, sized arbitrarily large.
4. When the corresponding `GetResponse` is delivered, `ProxyModule::on_response` runs and calls the destination module's callback directly — no `try_consume` check occurs, so the message is processed regardless of the app's (zero or nonexistent) bandwidth allowance, and no `BandwidthConsumed`/rejection event is ever emitted for it.
5. Repeat indefinitely: GET-based traffic for this app never touches `Allowance` storage, giving it unmetered bandwidth while POST traffic from the same app would be gated and charged.

Note: I could not fully trace whether any other layer (e.g., pallet-state-coprocessor's own dispatch-side accounting in `modules/pallets/state-coprocessor/src/impls.rs`) independently meters GET-response bytes before I ran out of investigation budget; if such metering exists elsewhere on the *response* delivery path specifically (as opposed to the GET *request* dispatch side), it would mitigate this finding and should be checked before treating this as fully unmitigated.

## The Gate

Every non-purchase POST request from a registered source chain runs through `BandwidthGate::try_consume(source, app, bytes)`:

1. If the app is on the **allowlist** for that source, return `Ok` without touching the ledger.
2. Sweep expired subscriptions in place.
3. If no live subscriptions remain → `GateError::NoAllowance`.
4. Sum `remaining_bytes` across live entries. If the sum is short → `GateError::Insufficient { remaining, required }`. **No mutation happens in this case** — the caller can retry after a top-up.
5. Otherwise drain from the head until the requested bytes are satisfied. Pop entries that hit zero. Emit `BandwidthConsumed` with the post-deduct remaining.

The "no mutation on insufficient" property is load-bearing: it means a top-up race is safe — if a message arrives between when an app notices it's short and when the top-up lands, the message stays rejectable rather than half-consuming the subscription.
```

## End-to-End Flow

The full lifecycle of a buyer-app pair, from cold-start to dispatch:

**Setup (one-time, per source chain):**

1. **Deploy.** `BandwidthManager(owner)` is deployed on the source chain.
2. **Bind host.** Owner calls `setHost(hostAddr)` — one-shot.
3. **Register.** Governance calls `pallet-bandwidth::set_manager(source, manager_addr)` on Hyperbridge.
4. **Configure tiers.** Governance sets `(bytes, duration_secs)` on the pallet via `set_tier`, then pushes the price side to the manager via `dispatch_set_tiers`.

Until every step lands, purchases fail — usually `UnknownManager` (pallet) or `UnknownTier()` (manager).

**Purchase (per top-up):**

5. **Approve.** Buyer approves the manager for `tier.price × months` scaled to the local fee token's decimals.
6. **Call `purchase()`.** Manager pulls the fee token, encodes a `BandwidthPurchaseMsg { app, tier, months, chain }`, and dispatches an ISMP POST to `pallet-bandwidth` (recipient `"BWMARKET"`) with `timeout: 0` and `fee: 0`. Emits `BandwidthPurchased` with the dispatch commitment.
7. **Deliver.** A relayer carries the message to Hyperbridge.
8. **Credit.** Pallet's `on_accept` checks `request.from` matches the registered manager, decodes the body, looks up `TierConfig`, computes `bytes × months` and `duration_secs × months`, and appends a fresh `Subscription` to the `(app_chain, app)` FIFO list. Emits `BandwidthCredited { app_chain, app, paid_from, tier, bytes, expires_at }`. If the list was at the 1024 cap, the oldest entry is evicted with `SubscriptionEvicted`.

impl<T: Config> BandwidthGate for Pallet<T> {
	fn try_consume(
		source: &ismp::host::StateMachine,
		app: &[u8],
		bytes: u32,
	) -> Result<(), GateError> {
		let key = AppKey::truncate_from(app.to_vec());
		if Allowlist::<T>::contains_key(source, &key) {
			return Ok(());
		}

		let need: u128 = bytes.into();
		let now = <T as pallet_ismp::Config>::TimestampProvider::now().as_secs();

		let total = pallet::Allowance::<T>::mutate(source, &key, |list| {
			// Sweep expired in-place. Order-preserving.
			list.retain(|s| s.expires_at > now);

			if list.is_empty() {
				return Err(GateError::NoAllowance);
			}

			let total: u128 = list.iter().map(|s| s.remaining_bytes).sum();
			if total < need {
				return Err(GateError::Insufficient { remaining: total, required: need });
			}

			// Drain from the front in insertion order. Once a sub is
			// fully consumed, pop it and continue with the next.
			// `get_mut` defends against a malformed list that satisfies
			// the `total >= need` precheck but is structurally empty;
			// we'd otherwise panic via `list[0]`.
			let mut left = need;
			while left > 0 {
				let Some(head) = list.get_mut(0) else {
					return Err(GateError::NoAllowance);
				};
				let take = head.remaining_bytes.min(left);
				head.remaining_bytes = head.remaining_bytes.saturating_sub(take);
				left = left.saturating_sub(take);
				if head.remaining_bytes == 0 {
					list.remove(0);
				}
			}

			Ok(total)
		})?;

		Self::deposit_event(Event::BandwidthConsumed {
			source: *source,
			app: key,
			bytes: need,
			remaining: total - need,
		});
		Ok(())
	}
