### Title
Missing timestamp freshness check in App Proxy signature verification allows indefinite replay of captured signed requests - ([File: lib/shopify_app/controller_concerns/app_proxy_verification.rb])

### Summary
`ShopifyApp::AppProxyVerification#query_string_valid?` validates the HMAC signature of an incoming Shopify App Proxy request but never checks the age of the `timestamp` parameter that is part of the signed payload. Any request whose query string (including its `signature`) was captured once by an attacker remains valid forever, since the module performs only a static signature check with no expiry/deadline enforcement — the exact bug class described in the external report (`_performLiquidation` lacking a `deadline` check on an otherwise validly-signed operation).

### Finding Description
`query_string_valid?` extracts the `signature` param, recomputes the HMAC over the remaining sorted query params (which include `timestamp`), and compares it with `ActiveSupport::SecurityUtils.secure_compare`: [1](#0-0) 

Nowhere in `AppProxyVerification` (or `verify_proxy_request`) is `query_hash["timestamp"]` compared against the current time to reject stale requests: [2](#0-1) 

Shopify signs the app-proxy URL with a `timestamp`, expecting apps to also validate freshness; `shopify_app` only validates the signature's correctness, not the timestamp's recency — an analog of the missing `deadline` check in the DeFi report, where a validly-signed operation (fair swap price / valid HMAC) is still accepted with no bound on when it can be executed.

### Impact Explanation
Because there is no expiry check, any app-proxy URL that becomes visible to a third party (browser history, shared screenshots, server logs, Referer headers, proxy/CDN logs, `app_proxy_route` links shared in support tickets, etc.) remains a permanently valid, authenticated request. An attacker who obtains one such URL can replay it indefinitely to `AppProxyVerificationController`-derived endpoints for that shop, invoking app-proxy actions as if it were a fresh, legitimate request from that shop's storefront — effectively an "accepted forged/stale signed request" from an anonymous party once a single valid URL has leaked.

### Likelihood Explanation
Moderate. Exploitation requires an attacker to first obtain one legitimately-signed app-proxy query string (e.g., via referrer leakage, shared links, or log exposure), which is a realistic and common leak vector for URL-embedded signatures. No knowledge of the app secret is required — only capture of one prior valid request, after which it can be replayed by anyone, at any time, since `shopify_app` performs no timestamp/deadline validation itself.

### Recommendation
Add a freshness check to `AppProxyVerification#verify_proxy_request` / `query_string_valid?`: parse `timestamp` and reject requests older than a small tolerance window (e.g., a few minutes), similar to how OAuth/webhook timestamps are commonly bounded. This mirrors the report's remediation of adding a `deadline` parameter/check before accepting an otherwise-validly-signed operation.

### Proof of Concept
1. A legitimate storefront visitor triggers an app-proxy request; the resulting signed URL (`shop=...&timestamp=...&signature=...`) is captured by an attacker (e.g., via a shared link, browser history sync, or exposed server/CDN access log).
2. At any later time — hours, days, or longer — the attacker replays the exact same query string to the app-proxy endpoint.
3. `query_string_valid?` in `lib/shopify_app/controller_concerns/app_proxy_verification.rb` recomputes the HMAC over the same params and finds it matches, since `timestamp` is never checked against the current time: [3](#0-2) 
4. `verify_proxy_request` allows the stale, replayed request through, executing the app-proxy action as if it were current.

```ruby
    def query_string_valid?(query_string)
      query_hash = Rack::Utils.parse_query(query_string)

      signature = query_hash.delete("signature")
      return false if signature.nil?

      ActiveSupport::SecurityUtils.secure_compare(
        calculated_signature(query_hash),
        signature,
      )
    end

    def calculated_signature(query_hash_without_signature)
      sorted_params = query_hash_without_signature.collect { |k, v| "#{k}=#{Array(v).join(",")}" }.sort.join

      OpenSSL::HMAC.hexdigest(
        OpenSSL::Digest.new("sha256"),
        ShopifyApp.configuration.secret,
        sorted_params,
      )
    end
```
