### Title
Permissionless `donateRewards` lets an attacker time-flush a zero-stake reward backlog and capture it as sole staker - (File: rewards/BaseRewardPool.sol)

### Summary
`BaseRewardPool.donateRewards()` is callable by anyone and internally calls `_provisionReward()`, which folds `rewards[token].queuedRewards` into `rewardPerTokenStored` only when `totalStaked() != 0` at that exact call. Because staking/unstaking via `MasterMagpie.deposit`/`withdraw` is instant with no lock, an attacker can deposit a minimal stake while `totalStaked()` is otherwise zero, call `donateRewards(1, rewardToken)` to force the entire accumulated `queuedRewards` backlog to be divided by `totalStaked()` (i.e. their own stake), harvest the reward through the withdraw path, and withdraw — capturing the whole backlog for themselves instead of it reaching the eventual, legitimate future stakers.

### Finding Description
`_provisionReward()` computes: [1](#0-0) 

When `totalStaked() == 0`, incoming rewards are merely added to `queuedRewards` (a real token transfer occurs via `safeTransferFrom`, so the tokens sit in the contract). Once `totalStaked()` becomes non-zero and *any* caller invokes `_provisionReward` again (via the permissionless `donateRewards`), the entire `queuedRewards` backlog is folded into `rewardPerTokenStored`, divided by whatever `totalStaked()` happens to be at that instant: [2](#0-1) 

Because `donateRewards` is unauthenticated and accepts `_amountReward` down to 1 wei, and `totalStaked()` reads `IERC20(stakingToken).balanceOf(operator)` live at call time, an attacker fully controls *when* the flush happens and can guarantee they are the only staker present at that instant (since the precondition is that `totalStaked()` was previously zero — nobody else is staked). Deposit/withdraw in `MasterMagpie` are instant, with no cooldown or lock, and both trigger reward harvesting through `_harvestBaseRewarder`, so an attacker can, in one transaction:
1. `MasterMagpie.deposit(stakingToken, tinyAmount)` — becomes the only staker, `totalStaked() == tinyAmount`.
2. `BaseRewardPool.donateRewards(1, rewardToken)` — flushes the entire `queuedRewards` backlog into `rewardPerTokenStored`, computed as `backlog * 10**decimals / tinyAmount`.
3. `MasterMagpie.withdraw(stakingToken, tinyAmount)` — triggers `_harvestBaseRewarder` → `getReward`, paying out `earned = balanceOf * Δ(rewardPerToken) / 10**decimals ≈ entire backlog`, regardless of how small `tinyAmount` was, because the algebra cancels out the stake size when the attacker is the sole staker.

The claim in the question that `historicalRewards` desynchronizes from `IERC20(_rewardToken).balanceOf(address(this))` is not accurate — every `_provisionReward` call performs a real `safeTransferFrom`, so `historicalRewards` (a monotonic cumulative counter) and the actual token balance both increase consistently; there is no broken balance/accounting invariant there. The real, valid issue is the economic one: the timing of the backlog's release into `rewardPerTokenStored` is attacker-controlled, letting them appropriate rewards that accrued while nobody was staked.

### Impact Explanation
An attacker can steal an entire `queuedRewards` backlog for a reward token, at negligible capital cost (a minimal stake, since payout is independent of stake size when they are the sole staker at flush time). This is a direct theft of yield that was intended to eventually accrue to the pool's genuine future stakers as new deposits/rewards flow in. This matches "High – Theft of unclaimed yield."

### Likelihood Explanation
Preconditions: `totalStaked() == 0` for the pool with a non-trivial `queuedRewards` balance (this occurs naturally whenever a reward pool has no stakers and a manager calls `queueNewRewards`, or when all users have withdrawn). Capital needed is minimal (a tiny stake in the staking token, or none if the attacker already holds some). The attack is atomic (single transaction: deposit → donate 1 wei → withdraw) and repeatable across any pool/reward token where such a backlog exists, no special privileges required, and no existing modifier (`onlyManager`, `nonReentrant`, pausability) blocks this specific unauthenticated flush of accumulated backlog.

### Recommendation
- Restrict `donateRewards` (or at least the backlog-release logic) so the timing of flushing `queuedRewards` cannot be triggered by an arbitrary unprivileged actor at a moment of their choosing; e.g., require `onlyManager`/`onlyMasterMagpie` for any provisioning that can trigger a queued-backlog release, or decouple "donation of new rewards" from "release of previously queued backlog" so a donation only affects current-period reward-per-token, not the historical backlog.
- Alternatively, when releasing `queuedRewards`, distribute it based on a stake snapshot from *before* the triggering transaction (e.g., a checkpointed/time-weighted total staked) rather than the instantaneous `totalStaked()` read in the same transaction that triggers the flush.
- Consider adding a minimum time-lock/vesting on newly released `queuedRewards` so instantaneous stake-then-withdraw sequences cannot fully capture backlogs.

### Proof of Concept
Hardhat/Foundry test plan:
1. Deploy `BaseRewardPool` with `stakingToken`, `rewardToken`, and `MasterMagpie` wired together; set a manager.
2. Ensure `totalStaked() == 0` (no deposits).
3. As manager, call `queueNewRewards(largeAmount, rewardToken)` — verify `rewards[rewardToken].queuedRewards == largeAmount` and `rewardPerTokenStored` unchanged (since `totalStaked()==0`).
4. As attacker (unprivileged EOA), in one transaction:
   a. `MasterMagpie.deposit(stakingToken, 1)` (or any minimal amount) — attacker becomes sole staker.
   b. `BaseRewardPool.donateRewards(1, rewardToken)` (1 wei, permissionless) — assert `rewardPerTokenStored` jumps by `(largeAmount+1) * 10**decimals / 1`.
   c. `MasterMagpie.withdraw(stakingToken, 1)` — triggers harvest; assert attacker receives `~largeAmount` of `rewardToken` via `RewardPaid` event / balance change.
5. Assert: attacker's net reward token gain ≈ `largeAmount` (the entire backlog), for negligible cost (1 wei donation + minimal stake amount + gas).
6. Assert: no other legitimate staker (who deposits later) can ever claim any portion of the pre-existing backlog, confirming the value was fully diverted to the attacker via timing control of `donateRewards`.

```text
    function _provisionReward(uint256 _amountReward, address _rewardToken) internal {
        IERC20(_rewardToken).safeTransferFrom(
            msg.sender,
            address(this),
            _amountReward
        );
        Reward storage rewardInfo = rewards[_rewardToken];
        rewardInfo.historicalRewards =
            rewardInfo.historicalRewards +
            _amountReward;
        if (this.totalStaked() == 0) {
            rewardInfo.queuedRewards += _amountReward;
        } else {
            if (rewardInfo.queuedRewards > 0) {
                _amountReward += rewardInfo.queuedRewards;
                rewardInfo.queuedRewards = 0;
            }
            rewardInfo.rewardPerTokenStored =
                rewardInfo.rewardPerTokenStored +
                (_amountReward * 10**stakingDecimals()) /
                this.totalStaked();
        }
        emit RewardAdded(_amountReward, _rewardToken);
```
