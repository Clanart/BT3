## Title
`aptos move verify-package` performs metadata-only comparison and never checks committed module bytecode against `source_digest`/locally-compiled bytes - ([File: aptos-move/cli/src/stored_package.rs])

### Summary
The Aptos analog of the external "stuck deposit due to no reconciliation" bug-class is a **verification/trust gap between declared package metadata and the actually-committed module bytecode**. `CachedPackageRegistry::verify` (`aptos-move/cli/src/stored_package.rs:193-241`) — invoked by the `aptos move verify-package` CLI command (`aptos-move/cli/src/commands.rs:2098-2140`) — only compares `PackageMetadata` fields (`name`, `deps`, `modules` (i.e. `ModuleMetadata{name, source, source_map, extension}`), `manifest`, `upgrade_policy`, `extension`, `source_digest`) between the locally-built package and the on-chain `PackageRegistry`. It never fetches or diffs the actual on-chain compiled bytecode (`code: vector<vector<u8>>`) against what the local sources would compile to.

### Finding Description
`VerifyPackage::execute` calls `CachedPackageRegistry::create(client, self.account, false)` with `with_bytecode = false`: [1](#0-0) 

Because `with_bytecode` is `false`, `CachedPackageRegistry::create` never populates the `bytecode` map at all: [2](#0-1) 

`verify()` then only performs field-by-field equality checks on the declarative `PackageMetadata`, never touching real bytecode: [3](#0-2) 

On-chain, `PackageMetadata.source_digest` is purely a self-reported string ("constructed by first building the sha256 of each individual source... and sha256 them again") with no cryptographic binding enforced by any Move or native code between that digest, the `ModuleMetadata.source`/`source_map` fields, and the actual `code` bytes accepted by `code::publish_package`/`code::request_publish_with_allowed_deps`: [4](#0-3) [5](#0-4) 

The on-chain publish flow (`publish_package`) validates module names, compatibility (structurally, on bytecode), dependency policy, and coexistence — but nothing ties the arbitrary, attacker-controlled `ModuleMetadata.source`/`source_map`/`source_digest` fields to the real bytecode that gets loaded: [6](#0-5) 

**Root cause**: a publisher (or an attacker who compromises a publisher's flow, e.g., a phishing-based publish or supply-chain attack) can submit `code: vector<vector<u8>>` bytecode compiled from a *malicious* module while setting `PackageMetadata.modules[i].source` (and `source_digest`) to the gzip-compressed source of a legitimate, audited module of the same name. The on-chain acceptance logic never verifies that the declared source corresponds to the bytecode being stored. Anyone who later runs `aptos move verify-package --account <addr>` to confirm the deployed code matches known-good source will get "Successfully verified source of package" even though the real bytecode is different, because `verify()` only compares metadata fields that are equally attacker-controlled — it never pulls or diffs actual module bytecode.

### Impact Explanation
This breaks the "mismatch between verified bytes, package metadata, and committed module bytes" invariant explicitly named in the publish-path threat model. Downstream consumers relying on `aptos move verify-package` (a documented, user-facing trust mechanism: "Build the package locally and verify that the on-chain copy matches") could be misled into trusting malicious bytecode as if it were the audited, open-sourced code, because the CLI check compares only self-reported metadata against equally self-reported metadata rather than actual compiled artifacts. This is a code-safety/verification gap with real trust-chain consequences for anyone doing due diligence before depending on or interacting with a package (dependency vetting, protocol integrations, wallets displaying "verified source"). It does not, however, directly bypass compatibility or upgrade-authority checks — it is a verification/attestation defect rather than an unauthorized-write primitive.

### Likelihood Explanation
Likelihood is moderate: exploiting it requires the ability to publish the malicious package in the first place (i.e., control over the target module address or resource/object account), which is the normal publisher-authority model — no privilege escalation is required beyond that. What's novel is that the *verification tool itself* provides false assurance to third parties, which can be leveraged in social-engineering/supply-chain scenarios (e.g., "here's my code, here's the on-chain address, run verify-package to confirm") without requiring any additional privileged access.

### Recommendation
- Have `verify-package` default to fetching bytecode (`with_bytecode = true`) and compile the local package to raw `CompiledModule` bytes, then byte-for-byte compare against `client.get_account_module(...)` bytecode for every module in the package, in addition to the existing metadata comparisons.
- Independently recompute `source_digest` from the declared `ModuleMetadata.source` fields and compare it to the on-chain `source_digest`.
- Consider adding an on-chain (or indexer-side) invariant that ties `ModuleMetadata.source_map`/`source` hashes to the compiled bytecode at publish time so that malformed or spoofed metadata is rejected before being persisted in `PackageRegistry`.

### Proof of Concept
1. Compile a legitimate, audited module `M` and note its gzip-compressed source bytes `S_legit`.
2. Compile a malicious module `M'` with the same module name/address but different logic (bytecode `B_evil`).
3. Construct a `PackageMetadata` whose `modules[0] = ModuleMetadata { name: "M", source: S_legit, source_map: <legit_map>, extension: None }` and `source_digest` computed over `S_legit`, but pass `code = [B_evil]` to `code::publish_package_txn`.
4. Publish via `aptos move publish` (or `object_code_deployment::publish`) — `code.move`'s `publish_package` only checks upgrade policy/compatibility/dependency/coexistence on the bytecode's own module names/functions, not against the declared `source` field, so the transaction succeeds.
5. A third party runs `aptos move verify-package --account <addr>` against the legitimate open-source repository for `M`. Because `CachedPackageRegistry::verify` only diffs `PackageMetadata` fields (which match, since the attacker faithfully copied `S_legit`/`source_digest`) and never fetches/diffs the real bytecode, the CLI reports `"Successfully verified source of package"` even though the deployed module is actually `B_evil`.

    pub async fn create(
        client: Client,
        addr: AccountAddress,
        with_bytecode: bool,
    ) -> anyhow::Result<Self> {
        // Need to use a different type to deserialize JSON
        let inner = client
            .get_account_resource_bcs::<PackageRegistry>(addr, "0x1::code::PackageRegistry")
            .await?
            .into_inner();
        let mut bytecode = BTreeMap::new();
        if with_bytecode {
            for pack in &inner.packages {
                for module in &pack.modules {
                    let bytes = client
                        .get_account_module(addr, &module.name)
                        .await?
                        .into_inner()
                        .bytecode
                        .0;
                    bytecode.insert(module.name.clone(), bytes);
                }
            }
        }
        Ok(Self { inner, bytecode })
    }

    pub fn verify(&self, package_metadata: &PackageMetadata) -> anyhow::Result<()> {
        let self_metadata = self.metadata;

        if self_metadata.name != package_metadata.name {
            bail!(
                "Package name doesn't match {} : {}",
                package_metadata.name,
                self_metadata.name
            )
        } else if self_metadata.deps != package_metadata.deps {
            bail!(
                "Dependencies don't match {:?} : {:?}",
                package_metadata.deps,
                self_metadata.deps
            )
        } else if self_metadata.modules != package_metadata.modules {
            bail!(
                "Modules don't match {:?} : {:?}",
                package_metadata.modules,
                self_metadata.modules
            )
        } else if self_metadata.manifest != package_metadata.manifest {
            bail!(
                "Manifest doesn't match {:?} : {:?}",
                package_metadata.manifest,
                self_metadata.manifest
            )
        } else if self_metadata.upgrade_policy != package_metadata.upgrade_policy {
            bail!(
                "Upgrade policy doesn't match {:?} : {:?}",
                package_metadata.upgrade_policy,
                self_metadata.upgrade_policy
            )
        } else if self_metadata.extension != package_metadata.extension {
            bail!(
                "Extensions doesn't match {:?} : {:?}",
                package_metadata.extension,
                self_metadata.extension
            )
        } else if self_metadata.source_digest != package_metadata.source_digest {
            bail!(
                "Source digests doesn't match {:?} : {:?}",
                package_metadata.source_digest,
                self_metadata.source_digest
            )
        }

        Ok(())
    }

    public fun publish_package(owner: &signer, pack: PackageMetadata, code: vector<vector<u8>>) acquires PackageRegistry {
        // Disallow incompatible upgrade mode. Governance can decide later if this should be reconsidered.
        assert!(
            pack.upgrade_policy.policy > upgrade_policy_arbitrary().policy,
            error::invalid_argument(EINCOMPATIBLE_POLICY_DISABLED),
        );

        let addr = signer::address_of(owner);
        if (!exists<PackageRegistry>(addr)) {
            move_to(owner, PackageRegistry { packages: vector::empty() })
        };

        // Checks for valid dependencies to other packages
        let allowed_deps = check_dependencies(addr, &pack);

        // Check package against conflicts
        // To avoid prover compiler error on spec
        // the package need to be an immutable variable
        let module_names = get_module_names(&pack);

        // Record, per module in this package, the object's transitive root owner at (re)publish, so
        // lazy self-init can detect a later transfer of the object or an ancestor since that module
        // was published (see `init::internal_maybe_initialize`). Objects only; feature-gated.
        if (features::is_lazy_module_initialization_enabled() && object::is_object(addr)) {
            let owner = object::address_to_object<object::ObjectCore>(addr).root_owner();
            module_names.for_each_ref(|name| {
                init::record_deploy_owner(addr, *name.bytes(), owner);
            });
        };
        let package_immutable = &borrow_global<PackageRegistry>(addr).packages;
        let len = package_immutable.length();
        let index = len;
        let upgrade_number = 0;
        package_immutable.enumerate_ref(|i, old| {
            let old: &PackageMetadata = old;
            if (old.name == pack.name) {
                upgrade_number = old.upgrade_number + 1;
                check_upgradability(old, &pack, &module_names);
                index = i;
            } else {
                check_coexistence(old, &module_names)
            };
        });

        // Assign the upgrade counter.
        pack.upgrade_number = upgrade_number;

        let packages = &mut borrow_global_mut<PackageRegistry>(addr).packages;
        // Update registry
        let policy = pack.upgrade_policy;
        if (index < len) {
            pack.modules.for_each_ref(|m| {
                let m: &ModuleMetadata = m;
                init::reset_initialized(addr, *m.name.bytes());
            });
            *packages.borrow_mut(index) = pack
        } else {
            packages.push_back(pack)
        };

        event::emit(PublishPackage {
            code_address: addr,
            is_upgrade: upgrade_number > 0
        });

        // Request publish
        if (features::code_dependency_check_enabled())
            request_publish_with_allowed_deps(addr, module_names, allowed_deps, code, policy.policy)
        else
        // The new `request_publish_with_allowed_deps` has not yet rolled out, so call downwards
        // compatible code.
            request_publish(addr, module_names, code, policy.policy)
    }
