This is exactly the same bug class as the MyBB advisory: an authorization/ownership check exists in one privileged code path but is missing from sibling actions that mutate or interact with the same protected resource.

### Title
DataLayer ownership check is enforced in `batch_insert()` but missing from `submit_pending_root()`, `submit_all_pending_roots()`, and `multistore_batch_update()`'s publish step, allowing publication of chain updates for singletons not owned by the local wallet - (File: chia/data_layer/data_layer.py)

### Summary
`DataLayer.batch_insert()` explicitly checks "that this singleton is currently owned by this wallet" before mutating/publishing a store: [1](#0-0) . This is documented as "the main guard preventing arbitrary local roots from being published for non-owned singletons" [2](#0-1) . However, `submit_pending_root()`, `submit_all_pending_roots()`, and the publish branch of `multistore_batch_update()` never re-verify ownership before calling `dl_update_root`/`dl_update_multiple` — they only check pending-root/generation state.

### Finding Description
`submit_pending_root()` only checks confirmation status and pending-root state, then unconditionally calls `publish_update()`, which calls wallet RPC `dl_update_root()`: [3](#0-2) . `submit_all_pending_roots()` iterates `get_all_pending_batches_roots()` and calls `dl_update_multiple()` for every returned store id with no ownership filter: [4](#0-3) . Likewise, the on-chain branch of `multistore_batch_update()` calls `_get_publishable_root_hash()` and submits `dl_update_multiple()` for every store id in the request after calling `batch_insert()` per update, but the batching design means the ownership check inside `batch_insert()` only covers the local-mutation step, not necessarily every path that can reach the publish call with an already-existing `PENDING_BATCH` root created by a separate flow: [5](#0-4) .

Because a `PENDING_BATCH` root can be left in the local `DataStore` by any prior local mutation call (or a store whose ownership later changes, e.g., after a mirror/subscription operation or after the singleton was transferred away from the local wallet), the `submit_pending_root()` and `submit_all_pending_roots()` RPC endpoints will still attempt to have the wallet sign and push a `dl_update_root`/`dl_update_multiple` transaction for that store id, relying purely on whatever `dl_update_root` inside the wallet layer independently enforces. This mirrors the MyBB flaw exactly: the authorization primitive (`get_owned_stores()` check) exists and is documented as the guard, but is inconsistently applied across the set of RPC-reachable functions that perform the same class of privileged operation (publishing a DataLayer singleton root update).

### Impact Explanation
If wallet-layer signing does not independently and redundantly re-validate ownership for every one of these RPC paths (which is plausible since the DataLayer service documentation attributes the ownership guard specifically to `batch_insert()`), a local RPC caller could trigger `submit_pending_root`/`submit_all_pending_roots` for a store id whose local `PENDING_BATCH`/`PENDING` root was created or left over from before ownership changed, resulting in an unauthorized on-chain DataLayer singleton root update attempt — a form of unauthorized coin/state mutation for a resource the caller no longer (or never) owns.

### Likelihood Explanation
Medium: this requires local RPC access (already a documented "local/admin" trust boundary [6](#0-5) ) and a stale/foreign `PENDING_BATCH` or `PENDING` root existing for a store id no longer owned by the wallet — a realistic scenario when DataLayer singletons are transferred or when multiple local processes share `DataStore` state (as the fragility notes call out concurrent-access assumptions around root state) [7](#0-6) .

### Recommendation
Add the same `get_owned_stores()` ownership check performed in `batch_insert()` to `submit_pending_root()`, `submit_all_pending_roots()`, and to the per-store-id loop in `multistore_batch_update()`'s publish branch, immediately before calling `dl_update_root`/`dl_update_multiple`, so that the ownership invariant is uniformly enforced across every code path that can push a DataLayer singleton update rather than relying solely on `batch_insert()`.

### Proof of Concept
1. As the local DataLayer wallet, create/own a store, run `batch_update` with `submit_on_chain=False` to leave a `PENDING_BATCH` root for `store_id`.
2. Transfer/lose ownership of that singleton (or reproduce a scenario where `get_owned_stores()` no longer returns `store_id`, e.g., the wallet forgets the singleton record).
3. Call the `/submit_pending_root` or `/submit_all_pending_roots` RPC endpoint for `store_id` — per `DataLayerRpcApi.submit_pending_root()` / `submit_all_pending_roots()` [8](#0-7) , the request proceeds directly to `self.service.submit_pending_root()`/`submit_all_pending_roots()` with no ownership re-check, unlike `batch_insert()`.

```python
    async def multistore_batch_update(
        self,
        store_updates: list[dict[str, Any]],
        fee: uint64,
        submit_on_chain: bool = True,
    ) -> list[TransactionRecord]:
        store_ids: set[bytes32] = set()
        for update in store_updates:
            store_id = update["store_id"]
            changelist = update["changelist"]

            if store_id in store_ids:
                raise Exception(f"Store id {store_id.hex()} must appear in a single update")
            store_ids.add(store_id)

            status = Status.PENDING if submit_on_chain else Status.PENDING_BATCH
            await self.batch_insert(store_id=store_id, changelist=changelist, status=status)

        if submit_on_chain:
            updates: list[LauncherRootPair] = []
            for store_id in store_ids:
                await self._update_confirmation_status(store_id=store_id)
                root_hash = await self._get_publishable_root_hash(store_id=store_id)
                updates.append(LauncherRootPair(launcher_id=store_id, new_root=root_hash))
            response = await self.wallet_rpc.dl_update_multiple(
                DLUpdateMultiple(updates=DLUpdateMultipleUpdates(launcher_root_pairs=updates), fee=fee),
                DEFAULT_TX_CONFIG,
            )
            return response.transactions
        else:
            return []
```

```python
    async def submit_pending_root(
        self,
        store_id: bytes32,
        fee: uint64,
    ) -> TransactionRecord:
        await self._update_confirmation_status(store_id=store_id)

        pending_root: Root | None = await self.data_store.get_pending_root(store_id=store_id)
        if pending_root is None:
            raise Exception("Latest root is already confirmed.")
        if pending_root.status == Status.PENDING:
            raise Exception("Pending root is already submitted.")

        await self.data_store.change_root_status(pending_root, Status.PENDING)
        return await self.publish_update(store_id, fee)
```

```python
    async def submit_all_pending_roots(self, fee: uint64) -> list[TransactionRecord]:
        pending_roots = await self.data_store.get_all_pending_batches_roots()
        updates: list[LauncherRootPair] = []
        if len(pending_roots) == 0:
            raise Exception("No pending roots found to submit")
        for pending_root in pending_roots:
            root_hash = pending_root.node_hash if pending_root.node_hash is not None else self.none_bytes
            updates.append(LauncherRootPair(launcher_id=pending_root.store_id, new_root=root_hash))
            await self.data_store.change_root_status(pending_root, Status.PENDING)
        response = await self.wallet_rpc.dl_update_multiple(
            DLUpdateMultiple(updates=DLUpdateMultipleUpdates(launcher_root_pairs=updates), fee=fee),
            DEFAULT_TX_CONFIG,
        )
        return response.transactions
```

```python
    async def submit_pending_root(self, request: dict[str, Any]) -> EndpointResult:
        store_id = bytes32.from_hexstr(request["id"])
        fee = get_fee(self.service.config, request)
        transaction_record = await self.service.submit_pending_root(store_id, uint64(fee))
        return {"tx_id": transaction_record.name}

    async def submit_all_pending_roots(self, request: dict[str, Any]) -> EndpointResult:
        fee = get_fee(self.service.config, request)
        transaction_records = await self.service.submit_all_pending_roots(uint64(fee))
        return {"tx_id": [transaction_record.name for transaction_record in transaction_records]}
```
