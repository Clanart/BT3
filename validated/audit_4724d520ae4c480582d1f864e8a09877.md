### Title
Unsynchronized read of `auctionEntryPointVersion` in `BidPool.getBidTxGasLimit` races with concurrent `updateAuctionInfo` writes - (File: kaiax/auction/impl/bid_pool.go)

### Summary
`BidPool` protects its auction-info fields (`auctioneer`, `auctionEntryPoint`, `auctionEntryPointVersion`, `bidTxGasBuffer`) with the `auctionInfoMu` RWMutex, and every accessor except one takes that lock before touching these fields. `getBidTxGasLimit`, which runs on the per-bid hot path triggered by every `auction_submitBid` RPC call, releases the lock after reading `bidTxGasBuffer` and then reads `bp.auctionEntryPointVersion` completely unsynchronized, while the block-processing goroutine can concurrently overwrite that same field via `updateAuctionInfo`. This is the same bug class as CVE-2024-46780 (nilfs2): a value that is properly protected everywhere else is read without the required lock, making the read racy against a concurrent writer that can replace/mutate it at any time.

### Finding Description
`BidPool.auctionEntryPointVersion` is a mutable `string` field guarded by `auctionInfoMu`. All correct accessors take the lock before reading it: [1](#0-0) 

and the field is written under the write lock in `updateAuctionInfo`: [2](#0-1) 

However, `getBidTxGasLimit` releases `auctionInfoMu` right after copying `bidTxGasBuffer`, and then reads `bp.auctionEntryPointVersion` directly, with no lock held: [3](#0-2) 

`updateAuctionInfo` (the writer) is invoked from `AuctionModule.PostInsertBlock` on every new block, i.e. from the block-processing goroutine, completely independent of and concurrent with bid submission: [4](#0-3) 

`getBidTxGasLimit` is called from `AddBid`, which is reachable directly from the public `auction_submitBid` RPC (`AuctionAPI.SubmitBid` -> `bidPool.AddBid`): [5](#0-4) [6](#0-5) 

Because a Go `string` is a two-word header (pointer + length), a concurrent unsynchronized write to `bp.auctionEntryPointVersion` while another goroutine reads it can produce a torn/inconsistent read (a pointer/length pair that never existed together), which is passed into `system.EncodeAuctionCallData(bid, bp.auctionEntryPointVersion)`. This is directly analogous to the nilfs2 issue: a mutable, lock-protected value exposed through most accessors is read from an externally-reachable code path without the required mutual exclusion, risking undefined memory access/behavior rather than a simple stale read.

### Impact Explanation
An externally reachable, unprivileged transaction/bid sender (any caller of `auction_submitBid`) can trigger `getBidTxGasLimit` at high frequency. If a block boundary lands during that window (which happens on every new block once auctions are active), the read of `auctionEntryPointVersion` races with the writer in `updateAuctionInfo`. On the Go runtime this is at minimum a data race (detectable/UB under the memory model) that can corrupt the effective string value fed into `EncodeAuctionCallData`, potentially causing the wrong ABI/typehash to be used for gas estimation, a panic (index out of range / invalid memory reference from a torn string header), or a node crash — all triggerable by an unprivileged public RPC caller, and capable of causing divergent/incorrect gas-limit computation for bid transactions across nodes (state/behavior divergence) or a liveness DoS on the node processing bids.

### Likelihood Explanation
This requires no special privilege — the attacker is the ordinary auction bid submitter, and the race window opens naturally on every block once the auction system is active (any block during which the auctioneer/entry-point/version changes, or any block boundary contended with a live SubmitBid call). A bidder can maximize the likelihood by submitting bids in a tight loop to coincide with block-insertion timing, making the race practically reproducible.

### Recommendation
Extend the `auctionInfoMu.RLock()` critical section in `getBidTxGasLimit` to cover the read of `bp.auctionEntryPointVersion` as well (mirroring the pattern already used in `validateBidSigs`), e.g.:
```go
bp.auctionInfoMu.RLock()
buffer := bp.bidTxGasBuffer
entryPointVersion := bp.auctionEntryPointVersion
bp.auctionInfoMu.RUnlock()

data, err := system.EncodeAuctionCallData(bid, entryPointVersion)
```
Audit other `BidPool`/`AuctionModule` fields for similarly partial lock coverage.

### Proof of Concept
1. Start a node with the auction module enabled and Randao fork active so `PostInsertBlock` regularly calls `updateAuctionInfo`, which mutates `auctionEntryPointVersion` under `auctionInfoMu.Lock()`.
2. From an unprivileged client, continuously call `auction_submitBid` with valid `BidInput` payloads so that `AddBid` -> `getBidTxGasLimit` is executed at high frequency.
3. Run the node with `-race` (or under sustained load) while blocks are being inserted; observe the Go race detector flag the concurrent unsynchronized read of `bp.auctionEntryPointVersion` in `getBidTxGasLimit` against the write in `updateAuctionInfo`, confirming the exact same "read exposed value without required lock" defect class as CVE-2024-46780.

(Note: I could not execute this PoC in this environment; the analysis is based on static code review of the cited call paths and lock usage.)

func (bp *BidPool) updateAuctionInfo(auctioneer common.Address, auctionEntryPoint common.Address, auctionEntryPointVersion string, bidTxGasBuffer uint64) {
	bp.auctionInfoMu.Lock()
	defer bp.auctionInfoMu.Unlock()

	if bp.auctioneer == auctioneer && bp.auctionEntryPoint == auctionEntryPoint && bp.auctionEntryPointVersion == auctionEntryPointVersion && bp.bidTxGasBuffer == bidTxGasBuffer {
		return
	}

	// Clear the existing auction pool since the auctioneer or auction entry point address is changed.
	bp.clearBidPool()

	bp.auctioneer = auctioneer
	bp.auctionEntryPoint = auctionEntryPoint
	bp.auctionEntryPointVersion = auctionEntryPointVersion
	bp.bidTxGasBuffer = bidTxGasBuffer

	logger.Info("Update auction info", "auctioneer", auctioneer, "auctionEntryPoint", auctionEntryPoint, "auctionEntryPointVersion", auctionEntryPointVersion, "bidTxGasBuffer", bidTxGasBuffer)
}

func (bp *BidPool) AddBid(bid *auction.Bid) (common.Hash, error) {
	if atomic.LoadUint32(&bp.running) == 0 {
		return common.Hash{}, auction.ErrAuctionPaused
	}

	if err := bp.validateBid(bid); err != nil {
		return common.Hash{}, err
	}

	if err := bp.insertBid(bid); err != nil {
		return common.Hash{}, err
	}

	gasLimit, err := bp.getBidTxGasLimit(bid)
	if err != nil {
		return common.Hash{}, err
	}
	bid.SetGasLimit(gasLimit)

	bp.newBidCh <- bid

	return bid.Hash(), nil
}

func (a *AuctionModule) PostInsertBlock(block *types.Block) error {
	if a.Downloader.Synchronising() || !a.ChainConfig.IsRandaoForkEnabled(block.Number()) {
		atomic.CompareAndSwapUint32(&a.bidPool.running, 1, 0)
		return nil
	}

	if !a.updateAuctionInfo(block.Number()) {
		logger.Debug("stop auction since auctioneer or auction entry point is not set")
		atomic.CompareAndSwapUint32(&a.bidPool.running, 1, 0)
		return nil
	}

	atomic.CompareAndSwapUint32(&a.bidPool.running, 0, 1)

	txHashMap := make(map[common.Hash]struct{})
	for _, tx := range block.Transactions() {
		txHashMap[tx.Hash()] = struct{}{}
	}
	a.bidPool.removeOldBids(block.Number().Uint64(), txHashMap)

	return nil
}

// updateAuctionInfo updates the auctioneer address and auction entry point address for the given block number.
// It expects the `num` is after Randao fork.
// It returns true if the non-zero auctioneer address and auction entry point address are set, otherwise false.

func (api *AuctionAPI) SubmitBid(ctx context.Context, bidInput BidInput) RPCOutput {
	numBidRequestCounter.Inc(1)
	if api.a.IsDisabled() {
		return makeRPCOutput(EMPTY_HASH, auction.ErrAuctionDisabled)
	}

	//  1. directly send target transaction
	targetTx, errTxDecode := toTx(bidInput.TargetTxRaw)
	if errTxDecode != nil {
		return makeRPCOutput(EMPTY_HASH, errTxDecode)
	}
	if targetTx.Hash() != bidInput.TargetTxHash {
		return makeRPCOutput(EMPTY_HASH, auction.ErrInvalidTargetTxHash)
	}
	errTargetTxSend := api.a.Backend.SendTx(ctx, targetTx)
	// ignore known transaction related errors against target tx validation
	if errTargetTxSend != nil && !(strings.HasPrefix(errTargetTxSend.Error(), "known transaction:") || errors.Is(errTargetTxSend, gasless_impl.ErrUnableToAddKnownBundleTx)) {
		return makeRPCOutput(EMPTY_HASH, errTargetTxSend)
	}

	// 2. add bid
	bid := ToBid(bidInput)
	bidHash, errValidateBid := api.a.bidPool.AddBid(bid)
	return makeRPCOutput(bidHash, errValidateBid)
}
