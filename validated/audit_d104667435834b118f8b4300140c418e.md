### Title
`aptos move verify-package` never compares actual on-chain bytecode, only self-reported metadata - ([File: aptos-move/cli/src/commands.rs, aptos-move/cli/src/stored_package.rs])

### Summary
The `aptos move verify-package` CLI command is documented as verifying "that the on-chain copy matches" a local source tree [1](#0-0) , and its own doc comment says it "verifies the bytecode matches a local compilation of the Move code" [2](#0-1) . In practice, it only compares the `PackageMetadata` struct fields — none of which are the actual compiled module bytes.

### Finding Description
`VerifyPackage::execute` builds the package locally, extracts its `PackageMetadata`, fetches the on-chain `PackageRegistry` with `CachedPackageRegistry::create(client, self.account, false)` (note `with_bytecode = false`), and then calls `package.verify(&compiled_metadata)`: [3](#0-2) 

`CachedPackageMetadata::verify` only asserts equality of `name`, `deps`, `modules` (which is `ModuleMetadata`: name, gzipped `source`, `source_map`, `extension` — not bytecode), `manifest`, `upgrade_policy`, `extension`, and `source_digest`: [4](#0-3) 

The actual on-chain compiled module bytecode is a separate on-chain artifact (fetched via `client.get_account_module`, populated only when `with_bytecode = true` in `CachedPackageRegistry::create`) [5](#0-4) . `VerifyPackage` never sets `with_bytecode = true`, never calls `registry.get_bytecode(...)`, and never compares the fetched module bytes against the locally compiled `compiled_units` (`pack.extract_code()`). `DownloadPackage` does use `get_bytecode` when `--bytecode` is passed [6](#0-5) , but `VerifyPackage` does not.

Root cause: `code::publish_package_txn(owner, metadata_serialized, code)` accepts `metadata` and `code` (the real bytecode bundle) as two independent, unrelated transaction arguments [7](#0-6) . Nothing on-chain enforces that `ModuleMetadata.source`/`source_map` in the metadata actually correspond to the bytecode in `code`; the framework's `check_dependencies`/`request_publish` validation only checks module names, dependency policy, and compatibility of the bytecode itself — it never checks that the declared `source`/`source_digest` metadata matches the bytecode being published [8](#0-7) . So a publisher can submit benign-looking source metadata alongside arbitrary, unrelated compiled bytecode, and the CLI's `verify-package` tool — the tool users are told to run for "code review and reproducibility" before trusting a package [9](#0-8)  — will report success without ever inspecting the deployed bytecode.

### Impact Explanation
Users, auditors, and dependency consumers rely on `verify-package` to confirm that on-chain code matches published source before depending on or trusting a package. Since the tool silently skips bytecode comparison, a malicious or compromised publisher can publish arbitrary bytecode (e.g. containing backdoors, different logic, or bypassing intended module init/behavior) while presenting innocuous source/metadata that passes `verify-package` cleanly. Anyone who uses `verify-package` output as a security/code-review gate is misled into false confidence about deployed code, directly matching the "mismatch between verified bytes, package metadata... and committed module bytes" publish-safety impact category.

### Likelihood Explanation
High: this requires no special privilege beyond the ability to publish any package (permissionless on Aptos), and the mismatch is triggered simply by supplying source/source_map metadata that doesn't match the real compiled module bytes — something already fully under the publisher's control at transaction-construction time, with no on-chain or CLI-side cross-check ever performed.

### Recommendation
In `VerifyPackage::execute`, create the `CachedPackageRegistry` with `with_bytecode = true`, and extend `CachedPackageMetadata::verify` (or add a new check) to fetch each module's on-chain bytecode via `get_bytecode` and byte-compare it against the corresponding entry in the locally compiled `compiled_units`, failing verification on any mismatch.

### Proof of Concept
1. Author package `P` with module `m.move` containing only a harmless `public fun f() {}`.
2. Compile a *different*, malicious module bytecode for the same module name/address (e.g. hand-crafted `.mv` bytes with extra unsafe logic), independent of the source in step 1.
3. Publish via `code_publish_package_txn(metadata_serialized, code)` where `metadata_serialized` embeds the benign source from step 1 but `code` is the malicious bytecode from step 2 — the framework's `publish_package`/`request_publish` checks (name uniqueness, dependency policy, compatibility) do not compare metadata source content to `code` bytes, so this succeeds.
4. Run `aptos move verify-package --account <addr>` against the original benign local source package `P`. Because `VerifyPackage::execute` never fetches or diffs on-chain bytecode, `package.verify(&compiled_metadata)` succeeds and prints "Successfully verified source of package", even though the deployed bytecode is entirely different from what was reviewed.

    async fn execute(self) -> CliTypedResult<&'static str> {
        // First build the package locally to get the package metadata
        let build_options = BuildOptions {
            install_dir: self.move_options.output_dir.clone(),
            bytecode_version: fix_bytecode_version(
                self.move_options.bytecode_version,
                self.move_options.language_version,
            ),
            ..self.included_artifacts.build_options(&self.move_options)?
        };
        let w = self.env.writer();
        let pack = BuiltPackage::build_to(&w, self.move_options.get_package_path()?, build_options)
            .map_err(|e| CliError::MoveCompilationError(format!("{:#}", e)))?;
        let compiled_metadata = pack.extract_metadata()?;

        // Now pull the compiled package
        let client = self.rest_options.client(&self.profile_options)?;
        let registry = CachedPackageRegistry::create(client, self.account, false).await?;
        let package = registry
            .get_package(pack.name())
            .await
            .map_err(|s| CliError::CommandArgumentError(s.to_string()))?;

        // We can't check the arbitrary, because it could change on us
        if package.upgrade_policy() == UpgradePolicy::arbitrary() {
            return Err(CliError::CommandArgumentError(
                "A package with upgrade policy `arbitrary` cannot be downloaded \
                since it is not safe to depend on such packages."
                    .to_owned(),
            ));
        }

        // Verify that the source digest matches
        package.verify(&compiled_metadata)?;

        Ok("Successfully verified source of package")
    }

impl CachedPackageRegistry {
    /// Creates a new registry.
    pub async fn create(
        client: Client,
        addr: AccountAddress,
        with_bytecode: bool,
    ) -> anyhow::Result<Self> {
        // Need to use a different type to deserialize JSON
        let inner = client
            .get_account_resource_bcs::<PackageRegistry>(addr, "0x1::code::PackageRegistry")
            .await?
            .into_inner();
        let mut bytecode = BTreeMap::new();
        if with_bytecode {
            for pack in &inner.packages {
                for module in &pack.modules {
                    let bytes = client
                        .get_account_module(addr, &module.name)
                        .await?
                        .into_inner()
                        .bytecode
                        .0;
                    bytecode.insert(module.name.clone(), bytes);
                }
            }
        }
        Ok(Self { inner, bytecode })
    }
