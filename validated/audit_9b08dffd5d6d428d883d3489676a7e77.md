### Title
CPI signer-seed PDA derivation (`Pubkey::create_program_address`) is unmetered, allowing hashing work far above the flat `invoke_units` charge - (File: program-runtime/src/cpi.rs)

### Summary
`cpi_common` charges a single flat `invoke_units` (946 CU by default) for the entire CPI syscall, then calls `translate_signers`, which runs `Pubkey::create_program_address` (SHA256-based) once per signer-seed-set, each with up to `MAX_SEEDS` seeds of up to `MAX_SEED_LEN` bytes, up to `MAX_SIGNERS` signer sets — none of which is charged any additional compute. The standalone `SyscallCreateProgramAddress`/`SyscallTryFindProgramAddress` syscalls charge `create_program_address_units` (1500 CU) per invocation for exactly the same hashing work, showing the intended per-derivation cost that CPI's signer path skips entirely.

### Finding Description
In `cpi_common` (`program-runtime/src/cpi.rs:773-808`), the only compute charged for the whole CPI call is: [1](#0-0) 
before `translate_signers` is invoked. `translate_signers` itself performs no compute-meter consumption at all: [2](#0-1) 
It iterates up to `MAX_SIGNERS` signer-seed sets (checked at line 646-648), and for each set iterates up to `MAX_SEEDS` seeds (checked at line 658-660), calling `Pubkey::create_program_address` per signer (line 667) — a SHA256-based hashing operation over the concatenated seed bytes and program id.

By contrast, the dedicated `sol_create_program_address`/`sol_try_find_program_address` syscalls that perform the identical hashing operation charge `create_program_address_units` (1500 CU by default, see `execution_budget.rs:211`) per single call: [3](#0-2) 

This means invoking a program with `MAX_SIGNERS` signer-seed sets, each with `MAX_SEEDS` maximal-length seeds, performs up to `MAX_SIGNERS` SHA256-based `create_program_address` calls "for free" inside one CPI, whereas replicating the same hashing work via the standalone syscalls would cost `MAX_SIGNERS * create_program_address_units` (e.g., 16 * 1500 = 24,000 CU) against a flat CPI charge of ~946 CU. Because CPI nesting depth (`MAX_INSTRUCTION_STACK_DEPTH`/`_SIMD_0268`) and total CPI count per transaction (`max_instruction_trace_length`) are bounded but non-trivial (dozens of CPIs per transaction), an attacker-controlled program can repeat this pattern across many CPIs within a single transaction, extracting far more real SHA256 hashing work than the compute budget nominally prices for that transaction.

Existing guards (`MAX_SIGNERS`, `MAX_SEEDS`, `MAX_SEED_LEN` length checks) prevent unbounded seed sizes/counts, but they only bound the *maximum per-call* amplification — they do not add any compute charge proportional to the hashing performed, so the flat `invoke_units` fee under-prices the CPI's true cost whenever signer seeds are used.

### Impact Explanation
This falls under the "materially underpriced compute" bounty category: real CPU work (SHA256 hashing for PDA derivation) scales with attacker-supplied signer-seed count/length, but the CU charge for CPI does not scale at all. Aggregated over many CPIs in a transaction (bounded by `max_instruction_trace_length`), this allows meaningfully more real computation per unit of CU purchased than the compute-budget model assumes, which can be used to degrade validator processing throughput within the CU budget accounting.

### Likelihood Explanation
Fully attacker-reachable: the attacker deploys an ordinary sBPF program and controls `signers_seeds_addr`/`signers_seeds_len` for every `sol_invoke_signed`/`invoke_signed` call, with no privileged access required. It is deterministic and repeatable — every CPI call with maximal signer seeds reproduces the same unmetered hashing work, and the pattern can be repeated across the bounded number of CPIs allowed per transaction.

### Recommendation
Charge compute proportional to the PDA-derivation work performed inside `translate_signers`, mirroring the cost model already used by `SyscallCreateProgramAddress` (i.e., consume `create_program_address_units`, or a cost derived from `sha256_base_cost`/`sha256_byte_cost` scaled by total seed bytes) once per signer-seed-set processed in `translate_signers`/`cpi_common`, rather than relying solely on the flat `invoke_units` charge.

```rust
pub fn translate_signers(
    program_id: &Pubkey,
    signers_seeds_addr: u64,
    signers_seeds_len: u64,
    invoke_context: &InvokeContext,
) -> Result<Vec<Pubkey>, Error> {
    let check_aligned = invoke_context.get_check_aligned();
    let memory_mapping = invoke_context.memory_contexts.memory_mapping()?;
    if signers_seeds_len > 0 {
        let signers_seeds = translate_slice::<VmSlice<VmSlice<u8>>>(
            memory_mapping,
            signers_seeds_addr,
            signers_seeds_len,
            check_aligned,
        )?;
        if signers_seeds.len() > MAX_SIGNERS {
            return Err(Box::new(CpiError::TooManySigners));
        }
        Ok(signers_seeds
            .iter()
            .map(|signer_seeds| {
                let untranslated_seeds = translate_slice::<VmSlice<u8>>(
                    memory_mapping,
                    signer_seeds.ptr(),
                    signer_seeds.len(),
                    check_aligned,
                )?;
                if untranslated_seeds.len() > MAX_SEEDS {
                    return Err(Box::new(InstructionError::MaxSeedLengthExceeded) as Error);
                }
                let seeds_bytes = untranslated_seeds
                    .iter()
                    .map(|untranslated_seed| {
                        translate_vm_slice(untranslated_seed, memory_mapping, check_aligned)
                    })
                    .collect::<Result<Vec<_>, Error>>()?;
                Pubkey::create_program_address(&seeds_bytes, program_id)
                    .map_err(|err| Box::new(CpiError::BadSeeds(err)) as Error)
            })
            .collect::<Result<Vec<_>, Error>>()?)
```
