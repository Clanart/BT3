### Title
Fee and weight are calculated on a transaction template that omits the OP_RETURN data output, underestimating `needed_fee` - (File: networks/bitcoin/src/wallet/send.rs)

### Summary
`SignableTransaction::new` appends a user-controlled `OP_RETURN` output to `tx_outs` (lines 194-202) but then calls `calculate_weight_vbytes(tx_ins.len(), payments, None)` (line 204), which reconstructs the transaction from `payments` only. The OP_RETURN output is never included in the weight/vbytes measurement, so `needed_fee` and `fee_with_change` are computed over a smaller value than the real transaction — a direct analog of computing a fee over the wrong base amount.

### Finding Description
In `SignableTransaction::new`, the data output is pushed to `tx_outs` before the weight calculation:

- `tx_outs.push(TxOut { value: Amount::ZERO, script_pubkey: ScriptBuf::new_op_return(...) })` at send.rs:194-202
- `let (mut weight, vbytes) = Self::calculate_weight_vbytes(tx_ins.len(), payments, None)` at send.rs:204

`calculate_weight_vbytes` (send.rs:62-127) builds its template `Transaction` from `payments` and an optional `change` script only. It has no parameter for the data output, so the up-to-80-byte OP_RETURN output (allowed at send.rs:171) contributes ~89+ vbytes that are never counted. The same omission affects the change branch at send.rs:225-227 (`fee_with_change`) and the `MAX_STANDARD_TX_WEIGHT` check at send.rs:241.

Consequences:
- Without change, the leftover becomes the fee, so the tx overpays rather than hitting the intended `fee_per_vbyte` — charged on a basis that ignores part of the spend.
- With change, `change = input_sat - payment_sat - fee_with_change` (send.rs:228-230) is inflated by the unaccounted OP_RETURN size, so the real fee rate falls below `fee_per_vbyte` and can fall below `DEFAULT_MIN_RELAY_TX_FEE` — yet the `TooLowFee` check at send.rs:211 also uses the underestimated `vbytes`, so it passes while the broadcast transaction would not meet the minimum relay fee.
- `weight > MAX_STANDARD_TX_WEIGHT` (send.rs:241) can pass on the template while the actual signed transaction exceeds the standard weight limit.

An unprivileged caller reaches this purely through the public `data: Option<Vec<u8>>` argument to `SignableTransaction::new`.

### Impact Explanation
The threshold can produce and sign a transaction whose effective fee rate is lower than the caller-specified `fee_per_vbyte`, potentially below the minimum relay fee, or whose weight exceeds standardness limits — the signed transaction may not propagate/confirm, leaving funds effectively unspendable until the transaction is reconstructed. This is a concrete incorrect fee computation reachable from public inputs.

### Likelihood Explanation
Triggers whenever `data` is supplied together with a `change` output (the common case for Serai's OP_RETURN-bound Bitcoin sends) or whenever the OP_RETURN pushes the template near the standardness boundary. Deterministic, not adversary-dependent.

### Recommendation
Pass the data output into `calculate_weight_vbytes` (e.g., accept `data: Option<&[u8]>` or the fully-formed `tx_outs`) so both the no-change and with-change weight/vbytes calculations, the `TooLowFee` check, and the `MAX_STANDARD_TX_WEIGHT` check all measure the transaction that will actually be signed.

### Proof of Concept
```rust
// payments: one output; change: Some(script); data: Some(vec![0; 80])
// In SignableTransaction::new:
//   tx_outs gets [payment, OP_RETURN(80 bytes), change]
//   but vbytes measured on tx with output == payments only (send.rs:85-99, 204)
//
// OP_RETURN output size ~= 8 (value) + ~1 (len) + ~2 (opcode+push) + 80  ~= 91 bytes => ~91 vbytes
// needed_fee = fee_per_vbyte * vbytes is short by ~91 * fee_per_vbyte sats
// change = input_sat - payment_sat - fee_with_change is inflated by that amount
// Actual paid fee rate = (inputs - outputs) / real_vbytes < fee_per_vbyte
// If fee_per_vbyte * real_vbytes < DEFAULT_MIN_RELAY_TX_FEE * real_vbytes / 1000,
// the signed tx is below minimum relay fee while passing the TooLowFee check.
```
