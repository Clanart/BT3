### Title
`SmartWomConvert.smartConvert` relies on a manipulable spot-price ratio from the WOM/mWOM pool, allowing atomic extraction of over-priced mWOM - (File: `wombat/SmartWomConvert.sol`)

### Summary
`SmartWomConvert.smartConvert()` decides how much of a user's deposited WOM is converted 1:1 into mWOM versus routed through an AMM buyback swap, based on `currentRatio()`, a value read live from the `womMWomPool` via `IWombatRouter.getAmountOut`. Because this is a spot-price read from an on-chain AMM pool, it can be manipulated within the same transaction (analogous to the `fShareRatio`/`getReserveBalance()` flash-manipulation pattern in the referenced report), letting an attacker force the function to skip the buyback discount and mint mWOM 1:1 even when mWOM is trading below peg.

### Finding Description
`currentRatio()` queries the live AMM state of `womMWomPool`: [1](#0-0) 

`smartConvert()` uses this value to decide the `convertRatio` passed into `_convertFor`: [2](#0-1) 

If `mWomToWom >= buybackThreshold`, `convertRatio` stays at `DENOMINATOR`, meaning the entire deposited amount is minted as mWOM at a 1:1 rate via `IMWom(mWom).deposit(convertAmount)` inside `_convertFor`, with no buyback swap discount applied: [3](#0-2) 

Because `currentRatio()` is a spot price derived from the pool's instantaneous cash/liability state (via `getAmountOut`), an unprivileged wallet can push the mWOM/WOM ratio above `buybackThreshold` with a single large swap (optionally amplified with a flash loan of WOM or mWOM) immediately before calling `smartConvert()`, then reverse the swap afterward in the same transaction. This is directly analogous to the reported `fShareRatio` manipulation via `fsd.getReserveBalance()` — a protocol-critical ratio computed from a balance/price that is atomically alterable by the caller in the same transaction, feeding into a minting/allocation decision.

### Impact Explanation
By artificially inflating `currentRatio()` above `buybackThreshold` for the duration of the transaction, an attacker forces `smartConvert` to mint mWOM 1:1 for WOM even though the true market price of mWOM is below peg. This means the attacker extracts mWOM at a rate more favorable than the fair market rate, which is paid for out of the shared mWOM backing/reserve — diluting the value backing mWOM for all existing holders (a form of protocol insolvency / theft of value from other unprivileged mWOM holders), not just the caller's own funds.

### Likelihood Explanation
`smartConvert` is a public/external function callable by any wallet, and Wombat-style stableswap pools can have their spot price temporarily moved with a sufficiently large swap. Combined with WOM/mWOM being loanable/swappable on open markets, an attacker only needs enough capital (or a flash loan) to move the pool's cash/liability momentarily, execute the deposit, then reverse the swap — all within one transaction, with no cooldown or TWAP protection in place.

### Recommendation
Do not rely on an instantaneous `getAmountOut` spot-price read for `currentRatio()`. Use a time-weighted average price (TWAP) from the pool, or require the ratio/threshold check to be based on a value that cannot be moved atomically within a single transaction (e.g., a cached ratio updated with a minimum delay/cooldown between updates and usage), similar to the "wait at least one block" mitigation recommended in the referenced report for `fShareRatio`.

### Proof of Concept
1. Attacker takes a flash loan of WOM (or mWOM) and performs a large swap against `womMWomPool` to push the mWOM→WOM `getAmountOut` price above `buybackThreshold`.
2. In the same transaction, attacker calls `SmartWomConvert.smartConvert(_amountIn, _mode)` — `currentRatio()` now reports a ratio ≥ `buybackThreshold`, so `convertRatio` is set to `DENOMINATOR` and the whole `_amountIn` is minted 1:1 as mWOM via `IMWom(mWom).deposit(convertAmount)` inside `_convertFor` (`wombat/SmartWomConvert.sol:199-202`).
3. Attacker reverses the initial swap against `womMWomPool` in the same transaction and repays the flash loan.
4. Attacker now holds mWOM minted at the favorable 1:1 rate despite the pool's real (unmanipulated) price showing mWOM below peg, diluting the value backing for all other mWOM holders.

```text
    function smartConvert(uint256 _amountIn, uint256 _mode) external returns (uint256 obtainedmWomAmount) {
        if (_amountIn == 0) revert MustNoBeZero();

        uint256 convertRatio = DENOMINATOR;
        uint256 mWomToWom = currentRatio();

        if (mWomToWom < buybackThreshold) {
            uint256 maxSwap = maxSwapAmount();
            uint256 amountToSwap = _amountIn > maxSwap ? maxSwap : _amountIn;
            uint256 convertAmount = _amountIn - amountToSwap;
            convertRatio = convertAmount * DENOMINATOR / _amountIn;
        }

        return _convertFor(_amountIn, convertRatio, _amountIn, msg.sender, _mode);
    }
```
