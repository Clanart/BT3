Based on my investigation, I found a concrete analog in the clone flow where an externally-supplied value flows into the app's persisted clone parameters without the same validation that other branch-name-consuming code paths apply.

### Title
Unsanitized API-supplied `defaultBranch` used to drive clone operation - (File: `app/src/ui/clone-repository/clone-repository.tsx`)

### Summary
The external report's core issue is that an untrusted value (`duration`) is accepted and persisted/used without any bound or validation, breaking downstream logic with no way to correct it afterward. The Desktop analog is the `defaultBranch` value returned from the GitHub API's clone-info lookup, which is taken as-is and handed to the clone dispatcher without going through the same ref-name validation (`sanitizedRefName`/`testForInvalidChars`) that Desktop applies elsewhere for branch names (e.g. in branch creation and rename flows).

### Finding Description
When a user clones a repository through the "Clone Repository" dialog, `resolveCloneInfo()` calls `api.fetchRepositoryCloneInfo(owner, name, protocol)` [1](#0-0)  to fetch clone metadata from the GitHub API, including a `defaultBranch` field. That value is then passed straight into `this.props.dispatcher.clone(url, path, { defaultBranch })` in `cloneImpl` with no sanitization or format checks applied to `defaultBranch` itself [2](#0-1) .

By contrast, elsewhere in the codebase, branch names that originate from user or repository input are explicitly sanitized before being used with git: `sanitizedRefName`/`testForInvalidChars` strip or reject illegal ref characters and leading `-`/`+` characters specifically to prevent argument-injection-style ref names from reaching `git` invocations [3](#0-2) . Similarly, the clone target directory name derived from a repository name goes through `sanitizeCloneName()` to prevent path traversal via a malicious owner/repo string [4](#0-3) , and that sanitizer is called at the two points a name is turned into a path in `clone-repository.tsx` [5](#0-4) [6](#0-5) .

The `defaultBranch` field, however, has no equivalent guard before being threaded into the clone options. This value comes directly from a GitHub API response for the repository being cloned — an object an attacker can fully control if the attacker controls (or can get a victim to clone) the target repository, since `default_branch`-derived metadata is repository-configurable.

### Impact Explanation
If the unsanitized `defaultBranch` value is ultimately used to build the arguments for the underlying `git clone`/`git checkout` invocation (the same class of argument-injection risk that `sanitizedRefName` was introduced to prevent for other ref inputs), a value engineered to look like a git command-line flag (e.g., a value starting with `-`) could alter the behavior of the git subprocess launched by Desktop, rather than being cleanly rejected or escaped. This is analogous to the report's concern that an unvalidated value gets baked into state ("saved... without the ability to update it") and later corrupts the intended operation.

I was not able to directly confirm the exact downstream git command construction inside the underlying clone implementation (e.g., `app/src/lib/git/clone.ts`) in this pass, since it wasn't returned by search — that file should be checked directly to confirm whether `defaultBranch` is passed as a raw `--branch <value>` argument or otherwise interpolated unescaped into the git invocation.

### Likelihood Explanation
The trigger path is unprivileged: a user simply needs to clone a repository whose GitHub API metadata (`default_branch`) has been set to a malicious value by the repository owner/attacker, then use Desktop's normal "Clone a Repository" flow. No local access, admin rights, or social engineering beyond "clone this repo" is required, which matches the valid-impact criteria (attacker controls a GitHub API object consumed by Desktop).

### Recommendation
Validate/sanitize the `defaultBranch` value returned from `fetchRepositoryCloneInfo` using the same `sanitizedRefName`/`testForInvalidChars` checks applied to other branch names before it is passed to `dispatcher.clone()`, and reject or neutralize values that fail git's ref-name rules (in particular leading `-`/`+`) before they can reach any git subprocess invocation.

### Proof of Concept
1. Attacker creates/controls a GitHub repository and sets metadata such that the API's clone-info response reports a `default_branch` value crafted to resemble a git flag (e.g. beginning with `-`).
2. Victim opens Desktop, uses "Clone a Repository," and selects/enters the attacker's repository.
3. `resolveCloneInfo()` fetches this `defaultBranch` value unmodified [7](#0-6) .
4. `cloneImpl` forwards it verbatim to `dispatcher.clone(url, path, { defaultBranch })` [8](#0-7)  with no equivalent of `sanitizedRefName` applied, unlike other branch-name-consuming paths in the codebase.

Confirming actual exploitability requires inspecting how `defaultBranch` is consumed in the clone implementation itself, which I could not retrieve in this session — I recommend a Devin session with full file access to trace `dispatcher.clone` → `app/src/lib/git/clone.ts` (or equivalent) to confirm whether this value reaches a git argument list unescaped.

// See https://www.kernel.org/pub/software/scm/git/docs/git-check-ref-format.html
// ASCII Control chars and space, DEL, ~ ^ : ? * [ \
// | " < and > is technically a valid refname but not on Windows
// the magic sequence @{, consecutive dots, leading and trailing dot, ref ending in .lock
const invalidCharacterRegex =
  /[\x00-\x20\x7F~^:?*\[\\|""<>]+|@{|\.\.+|^\.|\.$|\.lock$|\/$/g

/** Sanitize a proposed reference name by replacing illegal characters. */
export function sanitizedRefName(name: string): string {
  return name.replace(invalidCharacterRegex, '-').replace(/^[-\+]*/g, '')
}

/** Validate that a reference does not contain any invalid characters */
export function testForInvalidChars(name: string): boolean {
  return invalidCharacterRegex.test(name)
}

export function sanitizeCloneName(name: string): string | null {
  const components = name.split(/[/\\:]/)

  let lastComponent = ''
  for (let i = components.length - 1; i >= 0; i--) {
    if (components[i].length > 0) {
      lastComponent = components[i]
      break
    }
  }

  if (lastComponent.length === 0) {
    return null
  }

  if (lastComponent.endsWith('.git')) {
    lastComponent = lastComponent.slice(0, -4)
  }

  if (
    lastComponent === '..' ||
    lastComponent === '.' ||
    lastComponent.length === 0
  ) {
    return null
  }

  return lastComponent
}
