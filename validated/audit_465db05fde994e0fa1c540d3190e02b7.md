Confirmed: `dispatchIncoming(GetResponse)` in `evm/src/core/EvmHost.sol` never clears `_requestCommitments[commitment]` after paying the relayer fee, while the timeout path `dispatchTimeOut(GetRequestTimeout,...)` independently re-implements the identical "delete-then-refund" pattern from `_requestCommitments`. This is exactly the kind of duplicated state-mutation logic the external report warns about (repeated bespoke handling instead of one shared invariant-preserving function) — and here the duplication has produced a real inconsistency.

### Title
Unbounded double payment of GET request relayer fee via stale timeout proof after response already delivered - (File: evm/src/core/EvmHost.sol)

### Summary
`dispatchIncoming(GetResponse)` pays the GET request's fee to the response relayer but does not delete `_requestCommitments[commitment]` afterward, unlike every other completion path (`dispatchIncoming(PostRequest)` receipt logic and both `dispatchTimeOut` overloads) which clear their corresponding state before paying out. Because the fee-bearing commitment survives a successful response delivery, a still-valid (but stale) timeout non-membership proof can later be used to trigger a second payout of the same fee.

### Finding Description
Fee accounting for GET requests is duplicated across two independently-implemented code paths instead of a single shared "settle and clear" function:
- `dispatchIncoming(GetResponse)` [1](#0-0)  pays `_requestCommitments[commitment].fee` to the relayer but leaves `_requestCommitments[commitment]` intact.
- `dispatchTimeOut(GetRequestTimeout, ...)` [2](#0-1)  deletes `_requestCommitments[commitment]` and refunds the same `fee` amount to `meta.sender`, using a `meta` value fetched by the handler from `host.requestCommitments(commitment)` right before the call.

The timeout entrypoint `handleGetRequestTimeouts` in `evm/src/core/HandlerV2.sol` [3](#0-2)  only verifies:
1. That the request is timed out relative to the *timestamp of the proof height supplied* (`request.timeout() > state.timestamp` must be false), and
2. A non-membership proof that the response receipt was absent *at that specific historical height*.

Neither check looks at whether a response was delivered later (at a more recent height) before the timeout claim is submitted. Since GET responses are processed as soon as they are relayed (independent of the request's on-chain state), it is possible for a genuine response to arrive and pay out the relayer fee, and afterward for someone to submit a timeout proof anchored at an earlier finalized height (one that predates the response) to trigger the refund path. Because `_requestCommitments[commitment]` was never cleared by the response path, `host.requestCommitments(commitment)` in the handler still returns a non-zero `meta.fee`, so `dispatchTimeOut` pays it out a second time.

### Impact Explanation
This causes double payment of protocol fee-token funds out of the host contract's `feeToken()` balance for a single GET request — once to the response relayer, once as a "timeout refund" to the original sender — directly matching the bounty's "stealing or loss of funds" and "double-claim/double-settlement" categories. It also causes `onGetTimeout` to be invoked on the destination application after `onGetResponse` already fired for the same request, an unauthorized/duplicate execution path that application logic built on the assumption of exactly-once callbacks would not expect.

### Likelihood Explanation
No malicious relayer, prover, or admin collusion is required. Any unprivileged party holding a valid (older) non-membership state proof for the destination chain — obtainable from ordinary chain history/finalized headers — can submit `handleGetRequestTimeouts` after the legitimate response has already been processed, as long as the request's timeout timestamp has technically elapsed relative to that older height's timestamp. Because relayers race to submit responses/timeouts for fees, this scenario (a response landing shortly after or around the timeout boundary) is a realistic race rather than a contrived edge case.

### Recommendation
Delete `_requestCommitments[commitment]` in `dispatchIncoming(GetResponse)` immediately after successfully paying the relayer (mirroring the pattern already used in `dispatchIncoming(PostRequest)` and both `dispatchTimeOut` overloads), and/or have `handleGetRequestTimeouts` re-check `host.requestCommitments(commitment)` for non-zero `sender` at current state (not just at the historical proof height) before allowing settlement. Consolidating the "resolve fee-bearing commitment exactly once" logic into a single shared internal function, rather than reimplementing it separately for response and timeout paths, would prevent this class of bug from recurring.

### Proof of Concept
1. Alice dispatches a `GetRequest` with `timeoutTimestamp = T100` and a non-zero fee recorded in `_requestCommitments[commitment]`.
2. At real time `T110`, relayer R1 submits the legitimate response via `HandlerV2.handleGetResponses`, which calls `EvmHost.dispatchIncoming(GetResponse)` [4](#0-3) ; `onGetResponse` succeeds, fee is paid to R1, `_requestCommitments[commitment]` remains set (not deleted).
3. Attacker R2 obtains a finalized destination-chain state proof from an earlier height `H` whose `state.timestamp = T105` (`> T100`, so `request.timeout() > state.timestamp` is false) where the response receipt key was still absent (since the response was only recorded at `T110`).
4. R2 calls `HandlerV2.handleGetRequestTimeouts` with this proof; the non-membership check passes and `host.dispatchTimeOut(GetRequestTimeout(...), meta, commitment)` is invoked with `meta.fee` still non-zero.
5. `EvmHost.dispatchTimeOut` [2](#0-1)  deletes the commitment and transfers `meta.fee` to `meta.sender` (Alice) a second time — the same fee amount has now left the contract twice for a single request, and the destination app additionally receives a spurious `onGetTimeout` call after already processing `onGetResponse`.

    function dispatchIncoming(GetResponse memory response, address relayer) external restrict(_hostParams.handler) {
        // replay protection
        bytes32 commitment = response.request.hash();
        _responseReceipts[commitment] = ResponseReceipt({
            relayer: relayer,
            responseCommitment: response.hash()
        });

        (bool success,) = _bytesToAddress(response.request.from)
            .call(abi.encodeWithSelector(IApp.onGetResponse.selector, IncomingGetResponse(response, relayer)));

        if (!success) {
            // so that it can be retried
            delete _responseReceipts[commitment];
            return;
        }

        // reward the relayer fee
        uint256 fee = _requestCommitments[commitment].fee;
        if (fee != 0) {
            IERC20(feeToken()).safeTransfer(relayer, fee);
        }
        emit GetRequestHandled({commitment: commitment, relayer: relayer});
    }

    function dispatchTimeOut(
        GetRequestTimeout memory timeout,
        FeeMetadata memory meta,
        bytes32 commitment
    ) external restrict(_hostParams.handler) {
        // replay protection
        delete _requestCommitments[commitment];
        (bool success,) = _bytesToAddress(timeout.request.from)
            .call(abi.encodeWithSelector(IApp.onGetTimeout.selector, timeout));

        if (!success) {
            // so that it can be retried
            _requestCommitments[commitment] = meta;
            return;
        }

        if (meta.fee != 0) {
            // refund relayer fee
            IERC20(feeToken()).safeTransfer(meta.sender, meta.fee);
        }
        emit GetRequestTimeoutHandled({commitment: commitment, dest: string(timeout.request.dest)});
    }

    function handleGetRequestTimeouts(IHost host, GetTimeoutMessage calldata message) external notFrozen(host) {
        uint256 delay = block.timestamp - host.stateMachineCommitmentUpdateTime(message.height);
        uint256 challengePeriod = host.challengePeriod();
        if (challengePeriod != 0 && challengePeriod > delay) revert ChallengePeriodNotElapsed();

        // fetch the state commitment
        StateCommitment memory state = host.stateMachineCommitment(message.height);
        if (state.stateRoot == bytes32(0)) revert StateCommitmentNotFound();
        uint256 timeoutsLength = message.timeouts.length;

        for (uint256 i = 0; i < timeoutsLength; ++i) {
            GetRequest memory request = message.timeouts[i];
            // timed-out?
            if (request.timeout() > state.timestamp) revert MessageNotTimedOut();

            bytes32 commitment = request.hash();
            FeeMetadata memory meta = host.requestCommitments(commitment);
            if (meta.sender == address(0)) revert UnknownMessage();

            bytes[] memory keys = new bytes[](1);
            keys[0] = bytes.concat(RESPONSE_RECEIPTS_STORAGE_PREFIX, commitment);

            // verify state trie non-membership proofs
            PolkadotTrie.StorageValue memory entry = PolkadotTrie.VerifyProof(state.stateRoot, message.proof, keys)[0];
            if (entry.value.length != 0) revert InvalidProof();

            host.dispatchTimeOut(GetRequestTimeout(request, _msgSender()), meta, commitment);
        }
    }
