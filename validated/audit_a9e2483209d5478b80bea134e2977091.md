### Title
Unbounded pagination loop in `CW721ERC721Pointer.balanceOf` allows gas-exhaustion DoS against any caller that queries an NFT holder's balance - ([File: contracts/src/CW721ERC721Pointer.sol])

### Summary
`CW721ERC721Pointer.balanceOf` implements ERC-721 `balanceOf` by repeatedly paginating the underlying CosmWasm CW721 contract's `tokens` query (1000 tokens per page) in a `while` loop with no upper bound on the number of pages, and no gas/iteration cap enforced by the pointer contract itself. This mirrors the reported `fetchUnhealthyAccounts` bug class: an unbounded loop whose iteration count is driven by state size that an attacker fully controls (their own NFT holdings), reachable from any EVM caller (including another contract composing with the pointer inside a state-changing transaction).

### Finding Description
`balanceOf` builds a CosmWasm `tokens` query with `limit:1000` and loops, calling `WasmdPrecompile.query` and `JsonPrecompile.extractAsBytesList` once per page, until the CW721 contract returns an empty `tokens` list: [1](#0-0) 

The number of loop iterations is `ceil(numTokensOwned / 1000)`. `numTokensOwned` is the count of CW721 tokens owned by `owner_` in the underlying wasm contract's state — a value that any address can inflate arbitrarily, up to the limits of the underlying CW721 contract, simply by minting (or having someone mint) a very large number of tokens to itself, or by receiving many token transfers. Each loop iteration performs a full CosmWasm query round-trip (`WasmdPrecompile.query`) plus JSON parsing (`JsonPrecompile.extractAsBytesList`), which is comparatively expensive gas-wise, and there is no cap on the number of pages processed before the function reverts or returns.

This directly parallels the reported vulnerability class: `fetchUnhealthyAccounts` iterated an attacker-influenced, unbounded array; here, `balanceOf` iterates an attacker-inflatable, unbounded number of pages. Both differ from the safe patterns found elsewhere in the codebase (e.g., the `auth` precompile's `accounts(bytes pageKey)` which returns a single bounded page plus a `nextKey` for the caller to continue pagination themselves — see `precompiles/auth/auth.go`), because `balanceOf` performs *all* pagination internally, inside a single call, rather than deferring pagination control to the caller.

### Impact Explanation
`balanceOf` is a `view` function that is expected to be cheap and is commonly called on-chain by other EVM contracts composing with ERC-721 tokens (e.g., marketplaces, lending protocols, airdrop contracts checking eligibility, ERC721Enumerable-style wrappers). Because Sei's pointer contracts route to precompiles and their gas accounting follows the CosmWasm gas costs of the underlying queries, an account holding a very large number of CW721 tokens (attacker-controlled, since the attacker can mint/transfer tokens to itself in the underlying CW721 contract they don't need to own/control, or simply accumulate many tokens through normal transfers) makes any transaction that calls `balanceOf(attacker)` on the pointer consume proportionally large, unbounded gas. This can:
- Cause `eth_call`/gas estimation for legitimate integrations to fail or be prohibitively expensive.
- Cause a state-changing transaction from an unrelated third-party contract that calls `balanceOf` (e.g., during a transfer hook, eligibility check, or accounting step) to run out of gas and revert, effectively enabling a targeted DoS against any protocol that composes with this specific CW721 pointer for a chosen address.
- In the worst case, if invoked in a path metered close to block gas limits, it could push per-tx execution time up, though this is bounded to a single tx/gas-limit and does not itself halt validators.

This is a reachable, unprivileged-triggerable growth of computation that is not properly bounded, aligning with a "Medium" severity gas-griefing/DoS analog rather than a fund-loss bug, since impact is confined to transaction failure/gas cost of a specific counterparty interaction rather than direct loss of funds, chain halt, or consensus split. There is no evidence in the reachable code that this can crash a public RPC node or delay blocks by 2.5s+; the loop is bounded by the transaction's own gas limit and terminates (with an OOG revert) rather than looping indefinitely at the node level.

### Likelihood Explanation
Likelihood is straightforward: any user can mint/acquire many tokens on the underlying CW721 contract (subject to that contract's own mint permissions/gas costs) and then any counterparty who calls `balanceOf` on the ERC-721 pointer for that address pays the cost. No special privileges are needed to trigger the expensive path — only ordinary CW721 minting/transfers followed by an ordinary EVM read (or an internal call from another contract).

### Recommendation
- Bound the pagination loop in `balanceOf` with an explicit maximum number of pages/iterations (revert or return a partial/capped result once exceeded), similar to the bounded-scan approach used in `sei-cosmos/types/query/pagination.go` (`MaxScanLimit`, iteration budgets).
- Consider not implementing `balanceOf` via full enumeration at all; instead cache/track balances at the pointer level via transfer event bookkeeping, or explicitly document/require callers to avoid relying on `balanceOf` gas cost being constant for CW721-backed pointers with unbounded holdings.
- If full enumeration must remain, charge gas proportional to the number of underlying pages fetched (mirroring the `GasCostPerByte` pattern used in the `json` precompile) so that the caller's supplied gas is consumed predictably and fails fast rather than silently degrading performance.

2. As any user, mint (or otherwise acquire, e.g. via transfers) a very large number of tokens (e.g., 500,000) to a single Sei address on the underlying CW721 contract — bounded only by gas/economic cost of minting, which the attacker controls and can amortize over many transactions/blocks.
3. Have a third-party contract (or an `eth_call`/transaction) invoke `CW721ERC721Pointer.balanceOf(attackerAddress)`.

    function balanceOf(address owner_) public view override returns (uint256) {
        if (owner_ == address(0)) {
            revert ERC721InvalidOwner(address(0));
        }
        uint256 numTokens = 0;
        string memory startAfter;
        string memory qb = string.concat(
            string.concat("\"limit\":1000,\"owner\":\"", AddrPrecompile.getSeiAddr(owner_)),
            "\""
        );
        bytes32 terminator = keccak256("{\"tokens\":[]}");

        bytes[] memory tokens;
        uint256 tokensLength;
        string memory req = string.concat(string.concat("{\"tokens\":{", qb), "}}");
        bytes memory response = WasmdPrecompile.query(Cw721Address, bytes(req));
        while (keccak256(response) != terminator) {
            tokens = JsonPrecompile.extractAsBytesList(response, "tokens");
            tokensLength = tokens.length;
            numTokens += tokensLength;
            startAfter = string.concat(",\"start_after\":", string(tokens[tokensLength-1]));
            req = string.concat(
                string.concat("{\"tokens\":{", string.concat(qb, startAfter)),
                "}}"
            );
            response = WasmdPrecompile.query(Cw721Address, bytes(req));
        }
        return numTokens;
    }
