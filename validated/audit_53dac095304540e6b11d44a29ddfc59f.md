### Title
Unbounded CLVM atom length parsing in mempool canonicalization check can raise unhandled `IndexError` on crafted spend bundles - (File: `chia/full_node/mempool_manager.py`)

### Summary
`is_atom_canonical()` and its caller `is_clvm_canonical()` in `chia/full_node/mempool_manager.py` parse a raw CLVM byte buffer by indexing `clvm_buffer[offset]` directly, based on a length prefix decoded from the buffer itself, without ever validating that `offset`/`atom_len` stay within the bounds of `clvm_buffer` before advancing and re-indexing it in the calling loop.

### Finding Description
`is_atom_canonical()` decodes a length-prefix from the current byte and then reads `prefix_len` additional bytes by incrementing `offset` and indexing `clvm_buffer[offset]` in a loop, with no check that `offset < len(clvm_buffer)`: [1](#0-0) 

The caller, `is_clvm_canonical()`, walks the buffer with an `offset` variable that is advanced by the just-computed `atom_len` (`offset += atom_len`) and then unconditionally re-indexes `clvm_buffer[offset]` on the next loop iteration, with no bounds check that `offset` is still less than `len(clvm_buffer)`: [2](#0-1) 

This mirrors the structural root cause in the reported Firebird CVE-2026-33337: a length/size field taken from attacker-controlled serialized data (the "slice descriptor"/cstring length in Firebird, the CLVM atom length prefix here) is used to advance a read cursor without validating it against the actual remaining buffer size, allowing a crafted length value to walk the cursor past the end of the allocated buffer.

### Impact Explanation
In Firebird (C/C++), the analogous unchecked length leads to an out-of-bounds memory write/read (buffer overflow), causing memory corruption or a crash. In this Python code, the same unvalidated-length pattern instead produces an out-of-bounds `IndexError` when a crafted CLVM buffer (e.g., an atom whose declared length prefix runs past the end of the actual buffer) is parsed. If this exception is not caught by a broad handler somewhere upstream in the spend-bundle admission pipeline, it can propagate and interrupt mempool/spend-bundle processing for the node handling the crafted bundle — a spend-triggered transaction-processing halt, which is within the impact scope of this analog hunt.

### Likelihood Explanation
`is_clvm_canonical()`/`is_atom_canonical()` operate purely on the raw CLVM byte buffer decoded from spend-bundle data, and the length-prefix decoding logic is fully attacker-controllable by any entity able to submit a spend bundle (an unprivileged submitter). Constructing a buffer with a declared atom length exceeding the actual remaining bytes is a simple, low-cost crafting exercise — no signatures or special privileges are needed to reach this parsing code, only that the function is invoked before/as part of validating the bundle.

### Recommendation
In `is_atom_canonical()`, validate that `offset + prefix_len` and the computed `atom_len` never exceed `len(clvm_buffer)` before indexing/advancing, returning a non-canonical/invalid result (or raising a well-defined `ValueError`) instead of indexing out of bounds. Likewise, in `is_clvm_canonical()`, before each `clvm_buffer[offset]` read, assert `offset < len(clvm_buffer)` and fail cleanly (return `False`) rather than letting an `IndexError` propagate. Ensure any caller of `is_clvm_canonical()` on untrusted spend-bundle data wraps calls (or the function itself performs bounds checks) so malformed input cannot raise an unhandled exception during mempool processing.

### Proof of Concept
1. Construct a CLVM buffer with a single top-level atom (`tokens_left = 1`) whose first byte is `0xC0` (5+8 bit length-prefix marker, `prefix_len = 1`), immediately followed by end-of-buffer (no further bytes).
2. Call `is_clvm_canonical(buffer)`.
3. Trace: `b <= 0x80` is false, so `is_atom_canonical(clvm_buffer, offset)` is invoked; the loop `for i in range(prefix_len): ... offset += 1; atom_len |= clvm_buffer[offset]` indexes `clvm_buffer[1]`, which is out of range for a 1-byte buffer, raising `IndexError` instead of a graceful validation failure.
4. If this function is reached on attacker-controlled spend-bundle bytes without an enclosing try/except in the mempool admission path, the `IndexError` propagates and disrupts processing of that spend bundle. [3](#0-2)

def is_atom_canonical(clvm_buffer: bytes, offset: int) -> tuple[int, bool]:
    b = clvm_buffer[offset]
    if (b & 0b11000000) == 0b10000000:
        # 6 bits length prefix
        mask = 0b00111111
        prefix_len = 0
        min_value = 1
    elif (b & 0b11100000) == 0b11000000:
        # 5 + 8 bits length prefix
        mask = 0b00011111
        prefix_len = 1
        min_value = 1 << 6
    elif (b & 0b11110000) == 0b11100000:
        # 4 + 8 + 8 bits length prefix
        mask = 0b00001111
        prefix_len = 2
        min_value = 1 << (5 + 8)
    elif (b & 0b11111000) == 0b11110000:
        # 3 + 8 + 8 + 8 bits length prefix
        mask = 0b00000111
        prefix_len = 3
        min_value = 1 << (4 + 8 + 8)
    elif (b & 0b11111100) == 0b11111000:
        # 2 + 8 + 8 + 8 + 8 bits length prefix
        mask = 0b00000011
        prefix_len = 4
        min_value = 1 << (3 + 8 + 8 + 8)
    elif (b & 0b11111110) == 0b11111100:
        # 1 + 8 + 8 + 8 + 8 + 8 bits length prefix
        mask = 0b00000001
        prefix_len = 5
        min_value = 1 << (2 + 8 + 8 + 8 + 8)

    atom_len = b & mask
    for i in range(prefix_len):
        atom_len <<= 8
        offset += 1
        atom_len |= clvm_buffer[offset]

    return 1 + prefix_len + atom_len, atom_len >= min_value


def is_clvm_canonical(clvm_buffer: bytes) -> bool:
    """
    checks whether the CLVM serialization is all canonical representation.
    atoms can be serialized in more than one way by using more bytes than
    necessary to encode the length prefix. This functions ensures that all atoms are
    encoded with the shortest representation. back-references are not allowed
    and will make this function return false
    """
    assert clvm_buffer != b""

    offset = 0
    tokens_left = 1
    while True:
        b = clvm_buffer[offset]

        # pair
        if b == 0xFF:
            tokens_left += 1
            offset += 1
            continue

        # back references cannot be considered canonical, since they may be
        # encoded in many different ways
        if b == 0xFE:
            return False

        # small atom or NIL
        if b <= 0x80:
            tokens_left -= 1
            offset += 1
        else:
            atom_len, canonical = is_atom_canonical(clvm_buffer, offset)
            if not canonical:
                return False
            tokens_left -= 1
            offset += atom_len

        if tokens_left == 0:
            break

    # if there's garbage at the end, it's not canonical
    return offset == len(clvm_buffer)
