### Title
Deterministic CachedPreprocess reuse across signing sessions sharing a context enables nonce reuse and threshold key-share recovery - (File: coordinator/src/tributary/signing_protocol.rs)

### Summary

`SigningProtocol::preprocess_internal` derives FROST nonces deterministically from a `CachedPreprocess` stored in the DB, keyed only by `self.context` (the `DataSpecification { topic, label, attempt }`). The FROST API contract — "This cached preprocess MUST only be used once. Reuse of it enables recovery of your private key share" (`crypto/frost/src/sign.rs:211-214`) — is never enforced: the cache entry is never deleted or marked consumed, and `share_internal` regenerates the identical nonce set via `from_cache` → `seeded_preprocess` for every sign executed under the same context. If the coordinator ever runs two distinct signing rounds under the same `DataSpecification` (e.g., a re-attempt or second accumulation under the same `attempt` with a different participant subset or message), the same nonces `(d, e)` are committed to twice, and the published signature shares leak the secret share. ### Finding Description

In `preprocess_internal` (coordinator/src/tributary/signing_protocol.rs:100-148):

1. The preprocess machine is created deterministically: if `CachedPreprocesses::get(txn, &context)` already exists, no new randomness is drawn — the stored 32-byte seed is decrypted and fed to `AlgorithmSignMachine::from_cache`, which calls `seeded_preprocess(cache)` (crypto/frost/src/sign.rs:268-274). The same `(context, key)` therefore always produces the identical `self.nonces` vector and identical serialized preprocess.
2. There is no "consumed" flag: `CachedPreprocesses` is written once and read on every subsequent invocation under that context. Nothing prevents a second `sign` under the same context.
3. `share_internal` (signing_protocol.rs:150-181) calls `preprocess_internal` again and then `machine.sign(preprocesses, msg)`. In `AlgorithmSignMachine::sign` (crypto/frost/src/sign.rs:386-398), the effective nonce contribution is `actual = base + binding_factor * actual_seed` and `share = algorithm.sign_share(&view, &Rs, nonces, msg)` — a Schnorr-style linear equation `share_i = (d_i + ρ_i·e_i) + c·λ_i·s_i`.
4. The `context` is the `DataSpecification` used for accumulation in `handle_application_tx` (`data_spec = DataSpecification { topic, label, attempt }`, coordinator/src/tributary/handle.rs:294-295). Because the attempt counter is the only session-differentiator, any path that causes a second `share_internal` execution under the same attempt — a retry after a failed round, a second `DataSet::Participating` accumulation assembled from a different signer subset under the same attempt, or a reboot re-running share generation while the coordinator feeds a different participant set — regenerates the identical `(d_i, e_i)` pair.

With two shares from the same signer under the same context but different signing sets or messages, an observer (any fellow validator who sees the on-chain/p2p share data — all inputs here are public network data) obtains:

```
share_A = (d + ρ_A·e) + c_A·λ_A·s
share_B = (d + ρ_B·e) + c_B·λ_B·s
```

Since ρ, c, λ are all publicly computable from the transcripts, this is two linear equations in two unknowns (`d + ρ·e` components cancel via the known commitment points — concretely the verifier equation `share_i·G = bound_i + c_i·λ_i·Y_i`), yielding the secret share `s_i` directly. Recovering `t` shares this way — or even fewer given the threshold structure — compromises the group key.

### Impact Explanation

Reuse of a FROST nonce across two distinct signature shares is equivalent to ECDSA/Schnorr nonce reuse: the signer's secret share `s_i` is recoverable by linear algebra over the public shares and publicly computable binding factors/challenges. An unprivileged participant (or anyone who observes the signed share data, which is broadcast publicly through the tributary) who can induce or observe a second signing round under the same `DataSpecification` recovers key shares; at `t` compromised shares the external-network group key (e.g., the Bitcoin multisig key spending real funds) is fully recoverable. This maps precisely to the CVE class: a restriction that exists on paper ("MUST only be used once") is not enforced by policy in code.

### Likelihood Explanation

The unsafe condition is triggered whenever two `share_internal`/`sign` executions occur for the same `context` with differing message or participant set. `share_internal` is invoked per signing round keyed by the `DataSpecification` attempt; retry paths, rebooted-node re-execution (the DB-cached seed survives restarts by design, so a node that reboots mid-round deterministically reproduces its nonce while the coordinator may have assembled a different participant set), or accumulation reaching `Ready` twice under one attempt all satisfy the precondition. No attacker-controlled secret material is needed — only the ability to influence when/which preprocess data is accumulated, which any validator participating in the tributary protocol can affect. The determinism is deliberate (it exists so the share phase can regenerate the machine), but the absence of a consumed-once marker turns a safe single-use pattern into a reuse primitive.

### Recommendation

- Track nonce consumption: after `share_internal` completes `sign` for a context, overwrite/delete `CachedPreprocesses` for that context (or store a `used` flag) and refuse to sign again under the same `(context)` — require the coordinator to bump `attempt` for every logical re-sign.
- Alternatively, mix the signing-session challenge (e.g., the `preprocesses` transcript commitment or the full `msg`) into the nonce-derivation seed inside `seeded_preprocess`/`from_cache`, so that even a repeated context produces different nonces for different sessions.
- Document and assert at the `SigningProtocol` layer that each `DataSpecification` admits exactly one signing session.

### Proof of Concept

1. A validator `P_i` participates in signing session S under `DataSpecification { topic: T, label: SignData, attempt: a }`, generating preprocess commitments `C_i = (D_i, E_i)` from the cached seed.
2. The first round fails or a second accumulation under `attempt = a` is assembled with a different participant set `included' ≠ included` (different Lagrange coefficients `λ'` and binding factors `ρ'`).
3. `P_i` calls `share_internal` again → `preprocess_internal` returns the same cached seed → `from_cache`/`seeded_preprocess` regenerates identical nonces `(d_i, e_i)` → `sign` emits share `s'_i = (d_i + ρ'_i·e_i) + c'·λ'_i·s_i`.
4. Observer computes `s_i = (s_i·λ_i·c − s'_i·λ'_i·c' adjusted by the known bound commitments)` — concretely, since `D_i, E_i` are identical, `bound_i` is identical and `share·G − bound_i = c·λ_i·Y_i`, giving `Y_i = s_i·G` scaled by known `c·λ` values; comparing two rounds yields `s_i` in the clear via `(share_A·c_B·λ_B − share_B·c_A·λ_A) / (c_A·λ_A·c_B·λ_B − ...)`, i.e., standard two-equation linear solve for `s_i`.
