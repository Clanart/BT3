### Title
Blame proof leaks ECDH key for messages with unverified PoP in PedPoP `calculate_share` - (File: crypto/dkg/pedpop/src/lib.rs)

### Summary
`KeyMachine::calculate_share` returns an `InvalidShare` error carrying a blame `EncryptionKeyProof` — which publicly reveals the victim's ECDH shared key for the message's ephemeral key — before the batch verification that would have validated the message's proof-of-possession (PoP) ever runs. An unauthenticated sender can therefore make a victim emit a decryption key for an attacker-chosen `msg.key`, re-enabling the exact share-theft attack the PoP was added to prevent.

### Finding Description
The bug class from the external report is "missing origin validation on a channel that exposes secret data." The PedPoP encryption layer has exactly this shape: `EncryptedMessage` carries a Schnorr PoP so that only the legitimate originator of `msg.key` can induce the recipient to reveal the ECDH key `enc_key * msg.key` inside a blame proof. The code comments describe the attack this prevents: Eve observes Alice's message to Bob using key `X`, replays `X` to Bob, and Bob's blame proof reveals `bX`, decrypting Alice's real secret share to Bob. [1](#0-0) 

The protection is bypassed by ordering in `calculate_share`:

1. `self.encryption.decrypt(...)` only *queues* the PoP verification into `batch`; it does not verify it. It unconditionally computes `ecdh(enc_key, msg.key)` and returns the `EncryptionKeyProof { key, dleq }`. [2](#0-1) 
2. Back in `calculate_share`, the decrypted bytes are parsed with `C::F::from_repr`. If the plaintext is a non-canonical scalar, the function returns early via `ok_or_else` with `PedPoPError::InvalidShare { participant: l, blame: Some(blame) }` — the blame proof is released *before* `batch.verify_with_vartime_blame()` at line 493 is ever reached. [3](#0-2) 

So a message with a garbage/unsigned PoP still causes the victim to generate and return a valid `EncryptionKeyProof` revealing `enc_key_victim * msg.key` (with a DLEq proving correctness against the victim's registered encryption key). Note the contrast with the batch-failure path, which deliberately maps a `BatchId::Decryption` failure to `blame: None` precisely because the PoP failure means no blame proof should exist — the `from_repr` early-return path leaks the proof for a message that would have failed that same check. [4](#0-3) 

The DLEq inside `EncryptionKeyProof` binds the revealed point to `enc_keys[decryptor]` and the attacker-chosen `msg.key`, so third parties can use it in `decrypt_with_proof` to decrypt the corresponding ciphertext. [5](#0-4) 

### Impact Explanation
An attacker who observes a victim's inbound secret-share traffic (e.g., Alice's `EncryptedMessage` to Bob carrying ephemeral key `X`) sends Bob a forged share message with `msg.key = X` and an invalid/missing PoP. With high probability the decrypted garbage is a non-canonical scalar (e.g., ~7/8 chance for a ~2^252-order field), causing Bob's `calculate_share` to return `InvalidShare` with a blame proof revealing `bX`. Anyone holding that proof can run `Decryption::decrypt_with_proof` to recover the keystream for `X` and decrypt Alice's real secret share to Bob. Each leaked share is one polynomial evaluation contributing to Bob's FROST secret; leaking shares to a participant for `t` independent senders (or across sessions/context reuse) recovers that participant's secret key share, equivalent to the report's "steal the victim's secret data over an unvalidated channel" impact.

### Likelihood Explanation
Reachability is high: the only inputs are the attacker-controlled `EncryptedMessage` fields fed to `calculate_share` (via `EncryptedMessage::read` / coordinator `Shares` handling). The trigger probability per attempt is the probability the keystream-masked plaintext is non-canonical, which is large; the attacker needs no valid signature and no knowledge of any secret. Exploitation requires the surrounding protocol to publish or return the blame proof, which is the intended behavior of `PedPoPError::InvalidShare { blame }` and the processor's `InvalidShare` message path. [6](#0-5) 

### Recommendation
Verify the PoP before releasing any blame material: in `calculate_share`, do not attach `blame` to the `from_repr` failure unless the batch PoP verification for `BatchId::Decryption(l)` has succeeded — e.g., run `batch.verify_with_vartime_blame()` before interpreting decrypted plaintext, or verify `msg.pop` inline inside `Encryption::decrypt` and return `None` blame on PoP failure. Structurally, `Encryption::decrypt` should not emit an `EncryptionKeyProof` for a message whose origin authentication has not yet been confirmed.

### Proof of Concept
1. Victim Bob registers `enc_key_b` and runs `KeyMachine::calculate_share`.
2. Attacker observes any prior `EncryptedMessage` to Bob with ephemeral key `X` (e.g., Alice's share to Bob).
3. Attacker submits `EncryptedMessage { key: X, pop: <invalid signature>, msg: <32 arbitrary bytes> }` under any `Participant` index.
4. `decrypt` queues the (failing) PoP, computes `bX`, and returns `EncryptionKeyProof { key: bX, dleq: valid }`.
5. `from_repr` on the garbage plaintext fails with probability ≈ 1 − l/2^256; `calculate_share` returns `InvalidShare { blame: Some(proof) }` without ever calling `batch.verify`.
6. The revealed `bX` plus its DLEq satisfies `decrypt_with_proof`'s check against `enc_keys[Bob]`, so the attacker decrypts Alice's original ciphertext and recovers Alice's secret share to Bob. [7](#0-6)

    &self,
    from: Participant,
    decryptor: Participant,
    mut msg: EncryptedMessage<C, E>,
    // There's no encryption key proof if the accusation is of an invalid signature
    proof: Option<EncryptionKeyProof<C>>,
  ) -> Result<Zeroizing<E>, DecryptionError> {
    if !msg.pop.verify(
      msg.key,
      pop_challenge::<C>(self.context, msg.pop.R, msg.key, from, msg.msg.deref().as_ref()),
    ) {
      Err(DecryptionError::InvalidSignature)?;
    }

    if let Some(proof) = proof {
      // Verify this is the decryption key for this message
      proof
        .dleq
        .verify(
          &mut encryption_key_transcript(self.context),
          &[C::generator(), msg.key],
          &[self.enc_keys[&decryptor], *proof.key],
        )
        .map_err(|_| DecryptionError::InvalidProof)?;

      cipher::<C>(self.context, &proof.key).apply_keystream(msg.msg.as_mut().as_mut());
      Ok(msg.msg)
    } else {
      Err(DecryptionError::InvalidProof)
    }
  }
