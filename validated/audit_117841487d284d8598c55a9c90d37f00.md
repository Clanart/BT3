### Title
Auction bid data fields (`Nonce`, `To`, `MaxGasPrice`) are accepted into the bid pool without any validation - ([File: kaiax/auction/impl/bid_pool.go])

### Summary
The Babylon report identifies that `validateBabylonDepositRequest()` fails to validate certain fields of the deposit request (`TxnLockHeight` not checked at all, `Value`/`LockTime` checked against the wrong bounds), which can cause the request to be approved locally while later being rejected or mishandled by the external protocol (Babylon's indexer), leading to stuck funds. The same bug class - a request/data structure with fields that are silently skipped during acceptance validation - exists in Kaia's `auction` module (KIP-249), where a searcher-submitted `Bid` is accepted into the `BidPool` via `AddBid()`/`validateBid()` without validating all of its signed fields.

### Finding Description
`kaiax/auction/impl/bid_pool.go`'s `validateBid()` only checks a fixed subset of fields documented in `kaiax/auction/README.md` ("Bid pool validation rules" 1–6): [1](#0-0) 

These checks cover: duplicate/sender-winner conflict, `BlockNumber` range, `Bid > 0`, `Data` size, `CallGasLimit` limit, and the two signatures. However, `auction.BidData` also carries `Nonce`, `To`, and `MaxGasPrice` fields that are part of the EIP-712-signed payload but are **never independently validated** by `validateBid()`: [2](#0-1) 

- `Nonce` is not checked against the searcher's current on-chain nonce (or the nonce tracked by `AuctionEntryPoint`) before the bid is admitted to the pool and later turned into a bundle by `ExtractTxBundles()`.
- `To` is never validated (e.g., against an allow-list or against the target tx recipient), even though it directly determines the call target of the generated `BidTx`.
- `MaxGasPrice`, an optional field intended to bound the gas price the searcher is willing to pay, is accepted into the pool and hashed/signed but is not enforced anywhere in `validateBid()`.

This mirrors exactly the Babylon bug class: `TxnLockHeight` was "not validated at all," which allowed a locally-accepted request to be silently invalid from the perspective of the downstream system (Babylon's indexer). Here, a `Bid` with a stale/incorrect `Nonce`, an arbitrary `To`, or an unenforced `MaxGasPrice` is fully accepted by `BidPool.AddBid()` → `insertBid()` and is used by `AuctionModule.ExtractTxBundles()` to build a mandatory (`TargetRequired: true`) bundle around the winning bid: [3](#0-2) 

Because the on-chain `AuctionEntryPoint.call()` is the only place nonce/searcher-consistency is meant to be re-verified (see `_verifyInputIntegrity` in the mock, which even has bid/searcher-nonce checks commented out), and because the actual system contract's enforcement of `MaxGasPrice`/`Nonce` cannot be confirmed from this repository, a searcher can get a bid admitted to the pool and selected as "winner" for a block/target tx pair even though key fields required for it to be executable were never locally checked.

### Impact Explanation
If the on-chain `AuctionEntryPoint` does not independently re-derive and enforce these same bounds (which is plausible given the commented-out nonce/signature checks visible in the test mock contract), a searcher can occupy the winner slot for a target transaction with a bid whose `Nonce`/`To`/`MaxGasPrice` are inconsistent with what was actually signed/intended, causing the winning bid execution to either (a) fail at execution time — discarding the entire bundle via `commitBundleTransaction`'s atomic revert, denying the honest searcher inclusion, or (b) if `MaxGasPrice` is meant to cap the gas price ultimately charged/lent for the `BidTx` and is not enforced by the pool, allow acceptance of a bid whose effective cost diverges from what the searcher actually authorized, echoing the auction/gasless "settlement theft" impact category. This can also block competing bidders for the same `blockNumber`/`targetTxHash` slot (`senderHasDifferentWinner` reservation) with a bid that can never validly execute, effectively griefing legitimate auction settlement.

### Likelihood Explanation
Likelihood is Medium: any unprivileged auction bidder can call `auction_submitBid` and construct a `BidData` with an inconsistent `Nonce`, arbitrary `To`, or no/incorrect `MaxGasPrice`, since `validateBid()` performs no field-level check on any of them before admission. Whether this translates into direct fund loss depends on the on-chain `AuctionEntryPoint` contract's own validation, which is out of scope for this repository and could not be confirmed to fully cover these fields (the in-repo mock explicitly leaves nonce/signature re-verification commented out).

### Recommendation
Extend `validateBid()` in `kaiax/auction/impl/bid_pool.go` to explicitly validate all signed `BidData` fields before admission, in particular:
- Verify `bid.Nonce` matches the searcher's current nonce as tracked by `AuctionEntryPoint` (via `GetNoncesAndDeposits`) at admission time, and re-check at bundle-build time in `ExtractTxBundles()`.
- Validate `bid.To` against the expected/allowed target (e.g., must equal `AuctionEntryPoint` or a defined allow-list).
- If `MaxGasPrice` is meant to bound the searcher's exposure, enforce it against the gas price ultimately used to build/execute the `BidTx` in `GetBidTxGenerator`, rather than leaving it unenforced.

### Proof of Concept
1. A searcher signs a `Bid` (`auction_submitBid`) with a valid `TargetTxHash`/`BlockNumber`/`Bid`/`Data`/signatures, but sets `Nonce` to a value that does not match its current sequencing nonce (or omits/misconfigures `MaxGasPrice`).
2. `BidPool.AddBid()` → `validateBid()` accepts it because none of rules 1–6 check `Nonce`/`To`/`MaxGasPrice`. [1](#0-0) 
3. The bid wins the slot for its `blockNumber`/`targetTxHash` (reserving that sender via `bidWinnerMap`), blocking other legitimate bids for the same target. [4](#0-3) 
4. `ExtractTxBundles()` builds a mandatory bundle around this bid without re-checking `Nonce`/`To`/`MaxGasPrice`. [3](#0-2) 
5. At block-build time the bundle either reverts entirely (denying the target tx and the legitimate auction slot) or, if the entry-point contract's own bounds are looser than intended, executes with parameters the searcher's local pool never verified.

func (bp *BidPool) insertBid(bid *auction.Bid) error {
	bp.bidMu.Lock()
	defer bp.bidMu.Unlock()

	var (
		blockNumber  = bid.BlockNumber
		targetTxHash = bid.TargetTxHash
		sender       = bid.Sender
	)

	// Re-check bidWinnerMap here — two concurrent bids can pass validateBid together.
	if _, ok := bp.bidMap[bid.Hash()]; ok {
		return auction.ErrBidAlreadyExists
	}
	if bp.senderHasDifferentWinner(bid) {
		return auction.ErrBidSenderExists
	}

	// If same block number, same target tx hash exists, replace it if it's better
	if existingBid, ok := bp.bidTargetMap[blockNumber][targetTxHash]; ok {
		// FCFS if the bid is the same.
		if existingBid.Bid.Cmp(bid.Bid) >= 0 {
			return auction.ErrLowBid
		}

		logger.Trace("Replace bid", "old", existingBid.Hash(), "new", bid.Hash())
		delete(bp.bidMap, existingBid.Hash())
		delete(bp.bidWinnerMap[blockNumber], existingBid.Sender)
	} else {
		if int64(len(bp.bidMap)) >= bp.maxBidPoolSize {
			logger.Info("Bid pool is full", "maxBidPoolSize", bp.maxBidPoolSize, "bid", bid.Hash())
			return auction.ErrBidPoolFull
		}
	}

	hash := bid.Hash()

	bp.initializeBidMap(blockNumber)

	bp.bidMap[hash] = bid
	bp.bidTargetMap[blockNumber][targetTxHash] = bid
	bp.bidWinnerMap[blockNumber][sender] = hash

	numBidsGauge.Update(int64(len(bp.bidMap)))

	logger.Trace("Add bid", "bid", hash)

	return nil
}

func (bp *BidPool) validateBid(bid *auction.Bid) error {
	blockNumber := bid.BlockNumber

	bp.bidMu.RLock()

	// Check if the auction tx is already in the pool.
	if _, ok := bp.bidMap[bid.Hash()]; ok {
		bp.bidMu.RUnlock()
		return auction.ErrBidAlreadyExists
	}

	// 1. The `bid.Sender` must not be in the winner list of the same block number if the new bid isn't equal to the previous bid.
	if bp.senderHasDifferentWinner(bid) {
		bp.bidMu.RUnlock()
		return auction.ErrBidSenderExists
	}
	bp.bidMu.RUnlock()

	curBlock := bp.Chain.CurrentBlock()
	if curBlock == nil {
		return auction.ErrBlockNotFound
	}

	// 2. The `bid.BlockNumber` must be in range of `[currentBlockNumber + 1, currentBlockNumber + allowFutureBlock]`.
	curNum := curBlock.NumberU64()
	if blockNumber <= curNum || blockNumber > curNum+allowFutureBlock {
		return auction.ErrInvalidBlockNumber
	}

	// 3. The `bid.Bid` must be greater than 0.
	if bid.Bid.Sign() <= 0 {
		return auction.ErrZeroBid
	}

	// 4. The data size must be less than the maximum limit.
	if uint64(len(bid.Data)) > BidTxMaxDataSize {
		return auction.ErrExceedMaxDataSize
	}

	// 5. The gas limit must be less than the maximum limit.
	if bid.CallGasLimit > BidTxMaxCallGasLimit {
		return auction.ErrExceedMaxCallGasLimit
	}

	// 6. The `bid.SearcherSig` and `bid.AuctioneerSig` must be valid.
	if err := bp.validateBidSigs(bid); err != nil {
		return err
	}

	return nil
}

func (a *AuctionModule) ExtractTxBundles(txs []*types.Transaction, prevBundles []*builder.Bundle) []*builder.Bundle {
	bundles := []*builder.Bundle{}
	curBlock := a.Chain.CurrentBlock()
	if curBlock == nil || atomic.LoadUint32(&a.bidPool.running) == 0 {
		return bundles
	}

	miningBlock := curBlock.NumberU64() + 1
	bidTargetMap := a.bidPool.GetTargetTxMap(miningBlock)
	if len(bidTargetMap) == 0 {
		return bundles
	}

	for _, tx := range txs {
		txHash := tx.Hash()
		bid, ok := bidTargetMap[txHash]
		if !ok {
			continue
		}
		b := builder.NewBundle(
			builder.NewTxOrGenList(a.GetBidTxGenerator(tx, bid)),
			txHash,
			true,
		)

		isConflict := false
		for _, prev := range append(prevBundles, bundles...) {
			if prev.IsConflict(b) {
				isConflict = true
				break
			}
		}
		if isConflict {
			continue
		}
		bundles = append(bundles, b)
	}

	return bundles
}
