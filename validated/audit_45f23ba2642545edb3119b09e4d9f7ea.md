### Title
Attacker-controlled remote host can spoof `x-github-request-id` to force Desktop into the GitHub Enterprise sign-in flow, tricking the user into performing OAuth against a malicious server - (File: `app/src/lib/api.ts`)

### Summary
`isGitHubHost()` decides — based solely on an HTTP response header the *remote server itself controls* — whether an unknown Git remote should be treated as a GitHub Enterprise host. That classification directly drives `getEndpointKind()` in the credential-helper trampoline, which in turn decides whether Desktop pops the full GitHub Enterprise **sign-in/OAuth** dialog for that remote instead of the generic Git credential prompt. Because the trust decision is derived entirely from data the attacker's server returns, an attacker who controls a git remote (the exact threat model called out for this task) can force this classification unconditionally. [1](#0-0) 

### Finding Description
`isGitHubHost(url)` is a "best effort" detector used to decide whether an arbitrary remote host is a GitHub/GHE instance: [2](#0-1) 

It issues a `HEAD` request to `${endpoint}/meta?ghd=<uuid>` and trusts the result purely based on `response.headers.has('x-github-request-id')`. This is not a signed or otherwise verifiable token — it is a plain HTTP response header that **any server can emit**, including one fully controlled by an attacker who supplied the git remote URL. The function even goes out of its way to call `suppressCertificateErrorFor(metaUrl)` so that self-signed/invalid TLS certs on that host don't block the probe.

This function is consumed by the credential-helper trampoline to classify what kind of authentication flow to use for an unknown host: [3](#0-2) 

If `isGitHubHost()` returns `true`, `getEndpointKind()` returns `'enterprise'` rather than `'generic'`. That, in turn, changes the behavior of `getCredential()`: [4](#0-3) 

Instead of falling back to the generic Git credential manager/prompt (`getGenericCredential`/`promptForCredential`), Desktop invokes `ui.promptForGitHubSignIn(endpoint)`, which for non-`github.com` hosts calls `dispatcher.beginEnterpriseSignIn(cb)` and `dispatcher.setSignInEndpoint(origin)`, launching the real GitHub Enterprise sign-in UI pointed at the attacker's `origin`: [5](#0-4) 

The broken invariant: Desktop treats "the remote said it's GitHub" as equivalent to "this endpoint is trustworthy enough to run the GitHub Enterprise authentication/OAuth flow against." No cryptographic proof, allow-list, or user confirmation backs this decision — a self-reported header from an untrusted party is sufficient. The existing guards (`isKnownThirdPartyHost` deny-list, hostname regex heuristics for `bitbucket`/`gitlab`) only apply *before* the network probe and do nothing to stop a server that simply echoes the expected header; they are fail-open toward anything not on the deny-list.

### Impact Explanation
Once the Enterprise sign-in flow is launched against an attacker-chosen `origin`, Desktop builds OAuth authorization/token URLs from that origin (`getHTMLURL(endpoint)`, `getOAuthAuthorizationURL`, `requestOAuthToken`) using the app's hard-coded `ClientID`/`ClientSecret`: [6](#0-5) 

Because the "enterprise" endpoint is entirely attacker-supplied, the OAuth handshake (including the app's client secret and, in the PAT-based enterprise fallback, whatever credentials the user enters) is conducted with a server the attacker controls, rather than a real GHE instance — i.e. an unprivileged remote can steer a trusted, first-class Desktop credential/OAuth flow to itself. This satisfies the "unauthorized OAuth" / "credential exfiltration" class of impact: the user believes they are authenticating to a legitimate enterprise host (because Desktop's own sign-in UI, not a phishing page, is shown) when in fact the endpoint was chosen by the attacker's cloned/fetched remote.

### Likelihood Explanation
The attacker only needs to control the Git remote (the exact scenario named in this task's Valid Impact list — "a git remote/proxy response"). No local access, malware, or leaked credentials are required. The header the server must return (`x-github-request-id`) is undocumented to the client as a secret and trivial to add to any HTTP response. The check happens automatically whenever Git needs credentials for a host Desktop doesn't already have an account for (`getCredential`), i.e. on a normal `clone`/`fetch`/`push` against the attacker's HTTPS remote — no unusual user action beyond adding/using the remote is required.

### Recommendation
- Do not use a spoofable response header as the sole signal for whether to run a privileged (OAuth/sign-in) flow. Require the host to be pre-registered (already-known enterprise endpoint) or require explicit user confirmation before Desktop launches the sign-in/OAuth UI for a newly discovered host.
- If auto-detection via `/meta` must be kept, validate a value that a hostile server cannot forge (e.g., verify against a known GitHub Enterprise `/meta` payload schema and combine with an explicit user prompt: "This looks like a GitHub Enterprise instance — sign in?") rather than silently upgrading the credential flow.
- At minimum, do not suppress certificate errors for hosts being probed this way, and treat `isGitHubHost() === true` on a first encounter as a *suggestion* requiring user confirmation, not an automatic trigger for the OAuth/enterprise sign-in path.

### Proof of Concept
1. Attacker hosts a git remote at `https://evil.example.com/repo.git` (or a repo the victim clones/fetches from that host) and configures `api.evil.example.com` to answer `HEAD /meta?ghd=*` with header `x-github-request-id: 1234` (any value).
2. Victim adds/clones this remote in GitHub Desktop and performs a fetch/push, triggering Git's credential-helper protocol against the trampoline.
3. `getEndpointKind()` calls `isGitHubHost('https://evil.example.com')`, which hits `https://api.evil.example.com/meta?ghd=<uuid>`; the attacker's server returns the spoofed header, so `isGitHubHost` resolves `true` and `getEndpointKind` returns `'enterprise'`. [3](#0-2) 
4. `getCredential()` sees `endpointKind !== 'generic'` and no existing account, so it calls `ui.promptForGitHubSignIn('https://evil.example.com')`. [7](#0-6) 
5. `promptForGitHubSignIn` launches Desktop's genuine Enterprise sign-in dialog and OAuth flow scoped to `origin = https://evil.example.com`, sending the app's OAuth client id/secret and/or the user's entered credentials to the attacker-controlled server. [8](#0-7)

export function getOAuthAuthorizationURL(
  endpoint: string,
  state: string
): string {
  const urlBase = getHTMLURL(endpoint)
  const scope = encodeURIComponent(oauthScopes.join(' '))

  return new window.URL(
    `/login/oauth/authorize?client_id=${ClientID}&scope=${scope}&state=${state}`,
    urlBase
  ).toString()
}

export async function requestOAuthToken(
  endpoint: string,
  code: string
): Promise<string | null> {
  try {
    const urlBase = getHTMLURL(endpoint)
    const response = await request(
      urlBase,
      null,
      'POST',
      'login/oauth/access_token',
      {
        client_id: ClientID,
        client_secret: ClientSecret,
        code: code,
      }
    )
    tryUpdateEndpointVersionFromResponse(endpoint, response)

    const result = await parsedResponse<IAPIAccessToken>(response)
    return result.access_token
  } catch (e) {
    log.warn(`requestOAuthToken: failed with endpoint ${endpoint}`, e)
    return null
  }
}

  public promptForGitHubSignIn(endpoint: string): Promise<Account | undefined> {
    return new Promise<Account | undefined>(async resolve => {
      const cb = (result: SignInResult) => {
        resolve(result.kind === 'success' ? result.account : undefined)
        this.dispatcher.closePopup(PopupType.SignIn)
      }

      const { hostname, origin } = new URL(endpoint)
      if (hostname === 'github.com') {
        this.dispatcher.beginDotComSignIn(cb)
      } else {
        this.dispatcher.beginEnterpriseSignIn(cb)
        await this.dispatcher.setSignInEndpoint(origin)
      }

      this.dispatcher.showPopup({
        type: PopupType.SignIn,
        isCredentialHelperSignIn: true,
        credentialHelperUrl: endpoint,
      })
    }).catch(e => {
      log.error(`Could not prompt for GitHub sign in`, e)
      return undefined
    })
  }
