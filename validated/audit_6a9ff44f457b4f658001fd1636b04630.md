### Title
Auction bid pool is fully wiped whenever the on-chain `Auctioneer`/`bidTxGasBuffer` config changes, silently stripping an already-won bidder of their slot after the target transaction is already broadcast - ([File: kaiax/auction/impl/bid_pool.go])

### Summary
The `AuctionEntryPoint` contract's owner controls the `Auctioneer` address and `bidTxGasBuffer` value that the Kaia client reads every block. Any change to either value causes the client's in-memory bid pool — including bids that have **already won their slot** for an upcoming block — to be unconditionally wiped, with no restriction tied to whether a bid has already been accepted/committed. This mirrors the reported bug class: a privileged party can, at any time and with no "before the outcome is locked" guard, strip an already-determined winner of their prize/slot.

### Finding Description
Every block, `AuctionModule.updateAuctionInfo` re-reads the `Auctioneer` address and `bidTxGasBuffer` from the `AuctionEntryPoint`/`SystemRegistry` system contracts: [1](#0-0) 

The result is passed unconditionally to `BidPool.updateAuctionInfo`, which compares the new values to the cached ones and, on **any** difference (auctioneer address, entry point address, entry point version, or `bidTxGasBuffer`), clears the entire bid pool — including `bidWinnerMap`, which tracks bids that have already been admitted as the winner for a specific future block: [2](#0-1) 

Critically, the bid pool's admission rule already enforces "only one winner per sender per block" via `senderHasDifferentWinner`/`bidWinnerMap` — i.e., once a bid is admitted, it is treated as the locked-in winner for that block: [3](#0-2) 

However, `SubmitBid` (the public RPC entrypoint reachable by any searcher) immediately relays the raw *target* transaction into the mempool independent of the bid's fate, before or in parallel with bid admission: [4](#0-3) 

This creates a race: the target transaction (which produces the value/MEV opportunity for the searcher) is already broadcast and may be mined, but the auction operator (whoever controls `Auctioneer`/`bidTxGasBuffer` on `AuctionEntryPoint`) can, at any moment before the target block is built, change either config value and unconditionally wipe the searcher's already-admitted winning bid via `clearBidPool()`. The bid tx (which is what would carry the searcher's payment obligation and be inserted right after the target tx per `ExtractTxBundles`) is dropped from the pool and never generated/attached, so the block is built without the accompanying bid transaction.

Unlike the referenced `setGoldenEggFee` bug, there is no `onlyBeforeXXXPhase`-style guard restricting when the `Auctioneer`/`bidTxGasBuffer` can be changed relative to a bid that has already won its slot in `bidWinnerMap`.

### Impact Explanation
An auction operator/proposer with control over `AuctionEntryPoint`'s `Auctioneer` or `bidTxGasBuffer` value can, at any time, invalidate an already-locked-in winning bid after the corresponding target transaction has already been relayed/mined via `SubmitBid`. This decouples the value-producing target transaction from the payment-bearing bid transaction: the searcher's beneficial transaction can land on-chain while the auction proposer never receives the accompanying bid payment that the auction was supposed to guarantee, i.e., fee/auction-settlement value extraction without the associated payment being enforced. This is a Medium-severity settlement-integrity issue affecting the gasless/auction module's guarantee that a winning bid's payment is bundled with its target transaction.

### Likelihood Explanation
Reaching this requires only: (1) a searcher submitting a bid via the public `auction_submitBid` RPC (unprivileged), and (2) any change to `Auctioneer` or `bidTxGasBuffer` on the real `AuctionEntryPoint` contract (owner-privileged, but occurs through ordinary contract administration, not an attack on the client itself) occurring between bid admission and block assembly. Since `updateAuctionInfo` runs on every block via `PostInsertBlock` and compares against cached state with no debounce or "in-flight winner" protection, any legitimate operational change to these parameters (e.g., rotating the auctioneer key, adjusting gas buffer estimates) will trigger this stripping behavior, making it plausible in normal operation rather than requiring an unusual attack sequence.

### Recommendation
Before clearing the bid pool on an `Auctioneer`/`bidTxGasBuffer` change, preserve or re-validate already-admitted winning bids for the next `allowFutureBlock` window (e.g., only clear bids that are not yet locked into `bidWinnerMap` for imminent blocks), or delay applying `Auctioneer`/`bidTxGasBuffer` changes until after the currently pending winner-slots have been consumed — analogous to gating the `setGoldenEggFee`-style change behind a "before phase concludes" check.

### Proof of Concept
1. Searcher calls `auction_submitBid` with a valid signed bid for `blockNumber = N`; `SubmitBid` immediately relays `targetTx` to the mempool (`kaiax/auction/impl/api.go:132`) and the bid is admitted into `bidWinnerMap[N][sender]` (`kaiax/auction/impl/bid_pool.go:345-394`).
2. Before block `N` is assembled, the `AuctionEntryPoint` owner calls `changeAuctioneer` (or the gas buffer estimate changes) on-chain.
3. At the next `PostInsertBlock`, `updateAuctionInfo` detects the differing `Auctioneer`/`bidTxGasBuffer` and calls `bp.clearBidPool()`, wiping `bidWinnerMap`, `bidTargetMap`, and `bidMap` entirely (`kaiax/auction/impl/bid_pool.go:186-213`), confirmed by `TestBidPool_UpdateAuctionInfo` and `TestBidPool_UpdateAuctionInfo_DifferentGasBufferEstimate` (`kaiax/auction/impl/bid_pool_test.go:447-548`).
4. Block `N` is built containing `targetTx` (already broadcast in step 1) but without the bid transaction, since the bid pool no longer has any record of it.

Note: I was unable to locate the actual Solidity source for the production `AuctionEntryPoint`/`Kip249V3` contract (only Go bindings and a test-only mock were indexed), so the exact access-control conditions on `changeAuctioneer`/gas-buffer setters in the real contract could not be fully verified from the available index; a Devin session with full repository access would be needed to confirm those details.

func (a *AuctionModule) updateAuctionInfo(num *big.Int) bool {
	auctioneer := common.Address{}
	auctionEntryPointAddr := common.Address{}
	auctionEntryPointVersion := ""
	bidTxGasBuffer := uint64(0)

	defer func() {
		a.bidPool.updateAuctionInfo(auctioneer, auctionEntryPointAddr, auctionEntryPointVersion, bidTxGasBuffer)
	}()

	header := a.Chain.GetHeaderByNumber(num.Uint64())
	if header == nil {
		return false
	}
	_, err := a.Chain.StateAt(header.Root)
	if err != nil {
		return false
	}

	backend := backends.NewBlockchainContractBackend(a.Chain, nil, nil)

	// 1. Read auction entry point address
	auctionEntryPointAddr, err = system.ReadActiveAddressFromRegistry(backend, system.AuctionEntryPointName, num)
	if err != nil {
		return false
	}

	if auctionEntryPointAddr == (common.Address{}) {
		return false
	}

	// 2. Read auctioneer address
	auctioneer, err = system.ReadAuctioneer(backend, auctionEntryPointAddr, num)
	if err != nil {
		return false
	}

	if auctioneer == (common.Address{}) {
		return false
	}

	// 3. Read gas buffer estimate
	bidTxGasBuffer, err = system.ReadGasBufferEstimate(backend, auctionEntryPointAddr, num)
	if err != nil {
		return false
	}

// clearBidPool clears the bid pool.
func (bp *BidPool) clearBidPool() {
	bp.bidMu.Lock()
	defer bp.bidMu.Unlock()

	bp.bidMap = make(map[common.Hash]*auction.Bid)
	bp.bidTargetMap = make(map[uint64]map[common.Hash]*auction.Bid)
	bp.bidWinnerMap = make(map[uint64]map[common.Address]common.Hash)
}

// updateAuctionInfo updates the auction info if the auctioneer or auction entry point address is changed.
func (bp *BidPool) updateAuctionInfo(auctioneer common.Address, auctionEntryPoint common.Address, auctionEntryPointVersion string, bidTxGasBuffer uint64) {
	bp.auctionInfoMu.Lock()
	defer bp.auctionInfoMu.Unlock()

	if bp.auctioneer == auctioneer && bp.auctionEntryPoint == auctionEntryPoint && bp.auctionEntryPointVersion == auctionEntryPointVersion && bp.bidTxGasBuffer == bidTxGasBuffer {
		return
	}

	// Clear the existing auction pool since the auctioneer or auction entry point address is changed.
	bp.clearBidPool()

	bp.auctioneer = auctioneer
	bp.auctionEntryPoint = auctionEntryPoint
	bp.auctionEntryPointVersion = auctionEntryPointVersion
	bp.bidTxGasBuffer = bidTxGasBuffer

	logger.Info("Update auction info", "auctioneer", auctioneer, "auctionEntryPoint", auctionEntryPoint, "auctionEntryPointVersion", auctionEntryPointVersion, "bidTxGasBuffer", bidTxGasBuffer)
}

// senderHasDifferentWinner reports whether a different bid from the same sender
// already exists in the winner list for this block. Caller must hold bidMu.
func (bp *BidPool) senderHasDifferentWinner(bid *auction.Bid) bool {
	hash, ok := bp.bidWinnerMap[bid.BlockNumber][bid.Sender]
	if !ok {
		return false
	}
	return !bid.Equals(bp.bidMap[hash])
}

func (api *AuctionAPI) SubmitBid(ctx context.Context, bidInput BidInput) RPCOutput {
	numBidRequestCounter.Inc(1)
	if api.a.IsDisabled() {
		return makeRPCOutput(EMPTY_HASH, auction.ErrAuctionDisabled)
	}

	//  1. directly send target transaction
	targetTx, errTxDecode := toTx(bidInput.TargetTxRaw)
	if errTxDecode != nil {
		return makeRPCOutput(EMPTY_HASH, errTxDecode)
	}
	if targetTx.Hash() != bidInput.TargetTxHash {
		return makeRPCOutput(EMPTY_HASH, auction.ErrInvalidTargetTxHash)
	}
	errTargetTxSend := api.a.Backend.SendTx(ctx, targetTx)
	// ignore known transaction related errors against target tx validation
	if errTargetTxSend != nil && !(strings.HasPrefix(errTargetTxSend.Error(), "known transaction:") || errors.Is(errTargetTxSend, gasless_impl.ErrUnableToAddKnownBundleTx)) {
		return makeRPCOutput(EMPTY_HASH, errTargetTxSend)
	}

	// 2. add bid
	bid := ToBid(bidInput)
	bidHash, errValidateBid := api.a.bidPool.AddBid(bid)
	return makeRPCOutput(bidHash, errValidateBid)
