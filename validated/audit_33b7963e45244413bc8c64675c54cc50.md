### Title
`Scanner::scan_block` reports coinbase outputs as spendable, bypassing Bitcoin's coinbase-maturity rule - (File: networks/bitcoin/src/wallet/mod.rs)

### Summary

The bug class in CVE-2017-7889 is a protection mechanism (`CONFIG_STRICT_DEVMEM`) that exists but is not enforced over a specific range (the first megabyte), letting an unprivileged user reach restricted state. In `bitcoin-serai`, the analog is `Scanner::scan_block`: Bitcoin's consensus rule that coinbase outputs are immature for 100 blocks exists, but the scanner iterates over `block.txdata` starting at index 0 and emits `ReceivedOutput`s for coinbase outputs indistinguishable from normal ones. A miner (an unprivileged party who only needs to send Serai a valid block containing a coinbase output paying to the scanned key) can cause funds to be reported as received that are not actually spendable.

### Finding Description

`Scanner::scan_transaction` iterates all outputs of a transaction and returns a `ReceivedOutput` whenever `output.script_pubkey` matches a registered script (networks/bitcoin/src/wallet/mod.rs:199-214). `scan_block` then calls it for `tx in &block.txdata` — including `txdata[0]`, the coinbase (mod.rs:221-227). There is no check that the transaction is the coinbase or any maturity tracking on the resulting `ReceivedOutput`.

The producer-side code does enforce this distinction: `processor`'s `get_outputs` explicitly iterates `&block.txdata[1 ..]` with the comment "Skip the coinbase transaction which is burdened by maturity" (processor/src/networks/bitcoin.rs:690-691), proving the protection is intended but only enforced at one layer. The in-scope wallet library, however, exposes `scan_block` as the natural API and hands out `ReceivedOutput`s that `SignableTransaction::new` will happily consume and that FROST signers will sign a spend for — a transaction that can never confirm until maturity, and whose inputs the wallet has already committed.

A doc comment on `scan_block` notes the coinbase is "bound by maturity" and suggests callers use `scan_transaction` on `block.txdata[1 ..]` instead, but the function still performs and returns the unfiltered scan, so the unsafe result is the default behavior of the exported API.

### Impact Explanation

Funds are reported received that are not spendable: an attacker mining a block (or a miner on the network generally) can include a coinbase output paying to a Serai scanned script; `scan_block` returns it as a `ReceivedOutput`. Any downstream consumer that credits deposits or builds spends from `scan_block` results will treat immature coinbase value as usable. If spent via `SignableTransaction`/`TransactionMachine`, the signed transaction is consensus-invalid for 100 blocks (wasting the signing session and locking the selected inputs); if credited as a deposit, the protocol accounts for funds it cannot actually move during the maturity window, and a reorg of the coinbase destroys them entirely.

### Likelihood Explanation

Reachability requires a coinbase output paying to the scanned key, which only miners produce — but miners are unprivileged third parties, and any party that mines a block can target the well-known group key/address. The trigger is a single crafted on-chain transaction (the coinbase), matching the "Bitcoin transactions they send" reachability criterion. The probability depends on a miner bothering to target the key, so likelihood is moderate; impact when triggered (mis-credited or unspendable funds, wasted signing attempts) is real but bounded, supporting Medium overall.

### Recommendation

Skip `block.txdata[0]` inside `Scanner::scan_block` itself (mirroring `processor`'s `get_outputs`), or tag `ReceivedOutput`s produced from coinbase transactions so callers can enforce maturity. If scanning the coinbase is kept, the return type should distinguish maturity-bound outputs rather than relying on a doc comment and caller discipline.

### Proof of Concept

```rust
// networks/bitcoin: construct a block whose coinbase pays to the scanned key
let key: ProjectivePoint = ...; // even-Y group key
let mut scanner = Scanner::new(key).unwrap();

// Attacker (miner) crafts a coinbase tx paying to p2tr_script_buf(key)
let coinbase = Transaction {
    version: Version(2),
    lock_time: LockTime::ZERO,
    input: vec![TxIn {
        previous_output: OutPoint::null(), // coinbase input
        script_sig: ScriptBuf::new(),
        sequence: Sequence::MAX,
        witness: Witness::new(),
    }],
    output: vec![TxOut {
        value: Amount::from_sat(50_0000_0000),
        script_pubkey: p2tr_script_buf(key).unwrap(),
    }],
};
let block = Block { header: ..., txdata: vec![coinbase] };

let outputs = scanner.scan_block(&block);
// outputs[0] is a ReceivedOutput with offset 0, reported as spendable,
// yet consensus forbids spending it for 100 blocks.
assert_eq!(outputs.len(), 1); // BUG: immature coinbase reported as received
```
