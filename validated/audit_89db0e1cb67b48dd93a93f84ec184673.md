### Title
DataLayer mirror-URL SSRF: any coin spend can inject an attacker-controlled URL that a peer's DataLayer service will fetch with no host/IP validation - (File: `chia/data_layer/download_data.py`)

### Summary
Any user can create a low-cost "mirror" coin on chain whose memo encodes an arbitrary URL for a given DataLayer store (`launcher_id`). Any other node that tracks that store's singleton (the store owner or any subscriber) will automatically ingest that URL as a subscription/mirror server and later have its DataLayer service issue outbound HTTP requests to it via `http_download()`, with no validation that the URL does not resolve to a private, loopback, or link-local address.

### Finding Description
The DataLayer wallet watches for coins spent to the well-known mirror puzzle hash. In `DataLayerWallet.coin_added()`, when such a coin appears, the wallet decodes the `launcher_id` and `urls` straight from the parent coin's puzzle reveal/solution and, if the `launcher_id` is a tracked launcher, stores the mirror (URLs) unconditionally: [1](#0-0) 

Anyone can produce such a coin: `create_new_mirror()` simply spends XCH to `create_mirror_puzzle().get_tree_hash()` with `memos=[[launcher_id, *urls]]` — there is no ownership check on `launcher_id`, so an attacker can target *any* store id that a victim node is tracking, not just their own: [2](#0-1) 

The DataLayer service periodically pulls these mirror URLs from wallet state and feeds them straight into the local subscription table with no filtering of the URL's host/scheme: [3](#0-2) 

During the sync loop, `fetch_and_validate()` picks a server URL from that table and calls `insert_from_delta_file()`, which in turn calls `download_file()` → `http_download()`: [4](#0-3) [5](#0-4) 

`http_download()` performs a bare `aiohttp` GET against `server_info.url + "/" + filename` with no IP/hostname classification whatsoever — the same class of gap as the CloudTAK `/api/esri*` report (no SSRF/private-IP guard before the outbound `fetch`): [6](#0-5) 

The existing project code and tests already demonstrate that arbitrary/loopback URLs are accepted as mirror/server URLs end-to-end, e.g. `http://127.0.0.1/8000` is stored and later dispatched as a real fetch target: [7](#0-6) 

Even the `downloader` (plugin) path constructs a POST to `downloader.url + "/download"` with attacker-influenced `server_info.url` embedded in the JSON body, again without any host classification: [8](#0-7) 

### Impact Explanation
This lets an unprivileged spend-bundle submitter (anyone who can pay a small XCH fee/amount to create a mirror coin) force outbound HTTP requests from any other DataLayer node that tracks the targeted `launcher_id` — the store owner's own service or any subscriber's service. Because `http_download()` writes the raw response body to disk and then attempts to parse it as delta-file content via `data_store.insert_into_data_store_from_file()`, this is a full SSRF primitive against internal services/cloud metadata reachable from the victim host: the attacker controls the destination, and a crafted response designed to superficially resemble a delta file can cause its content to be processed by the DataLayer parser. Even absent a parseable payload, the victim node still performs the network round-trip against the attacker-chosen host/port (probing internal services, hitting instance metadata endpoints, or DoSing an internal admin port), and failures are silently absorbed by the mirror ban/backoff logic, making this attractive for internal network reconnaissance from a fully remote, low-privilege actor.

### Likelihood Explanation
Likelihood is high: creating a mirror coin requires only a normal wallet spend (any account, any small fee/amount) and does not require ownership of the targeted `launcher_id`/store — the `coin_added()` handler only checks that the launcher id is *tracked*, which is true for every subscriber and every owner of that store. Any store with external subscribers (the primary intended use case of DataLayer mirrors) is automatically exposed to this attack. The victim's periodic sync loop (`periodically_manage_data()` / `update_subscription()`) runs unattended in the background, so no user interaction is required on the victim side beyond having subscribed to or created the targeted store.

### Recommendation
Validate mirror/server URLs before they are persisted as subscription servers and again immediately before every outbound fetch in `http_download()` / `get_downloader()` / plugin `download_file()` calls: resolve the hostname and reject loopback, link-local, private (RFC1918), and other non-routable/metadata ranges (mirroring the guard pattern the report highlights for CloudTAK's `isSafeUrl`). Additionally, consider restricting which `launcher_id`s a mirror coin may target relative to the coin's actual on-chain announcement/authority, or at minimum rate-limit/backoff mirror ingestion from unauthenticated on-chain data more aggressively before it is trusted as a fetch target.

### Proof of Concept
1. Attacker (any wallet, no special privilege) picks a victim `launcher_id` that is known to have external subscribers (or is the attacker's own launcher a victim node is tracking).
2. Attacker calls `create_new_mirror(launcher_id, amount, urls=[b"http://169.254.169.254/latest/meta-data/"], action_scope, fee=...)` (as exercised in `chia/_tests/wallet/db_wallet/test_dl_wallet.py:557-612` and `chia/_tests/wallet/rpc/test_dl_wallet_rpc.py:281-292`) and broadcasts the resulting spend bundle.
3. Once confirmed, any node tracking that `launcher_id` picks up the mirror via `DataLayerWallet.coin_added()` (`chia/data_layer/data_layer_wallet.py:775-800`) and stores it via `DataLayerStore.add_mirror()`.
4. The victim's `DataLayer.update_subscriptions_from_wallet()` (`chia/data_layer/data_layer.py:979-985`) copies the URL into the local subscription table.
5. On the next `periodically_manage_data()` cycle, `fetch_and_validate()` selects that server and calls `insert_from_delta_file()` → `download_file()` → `http_download()` (`chia/data_layer/download_data.py:110-145,298-324`), causing the victim process to issue a real outbound GET to the attacker-chosen internal/metadata address.

```python
async def download_file(
    data_store: DataStore,
    target_filename_path: Path,
    store_id: bytes32,
    root_hash: bytes32,
    generation: int,
    server_info: ServerInfo,
    proxy_url: str | None,
    downloader: PluginRemote | None,
    timeout: aiohttp.ClientTimeout,
    client_foldername: Path,
    timestamp: int,
    log: logging.Logger,
    grouped_by_store: bool,
    group_downloaded_files_by_store: bool,
    max_delta_file_size: int,
) -> bool:
    if target_filename_path.exists():
        return True
    filename = get_delta_filename(store_id, root_hash, generation, grouped_by_store)

    if downloader is None:
        # use http downloader - this raises on any error
        try:
            await http_download(
                target_filename_path, filename, proxy_url, server_info, timeout, log, max_delta_file_size
            )
        except (asyncio.TimeoutError, aiohttp.ClientError, MaxDeltaFileSizeExceededError):
            new_server_info = await data_store.server_misses_file(store_id, server_info, timestamp)
            log.info(
                f"Failed to download {filename} from {new_server_info.url}."
                f"Miss {new_server_info.num_consecutive_failures}."
            )
            log.info(f"Next attempt from {new_server_info.url} in {new_server_info.ignore_till - timestamp}s.")
            return False
        return True
```

```python
async def http_download(
    target_filename_path: Path,
    filename: str,
    proxy_url: str | None,
    server_info: ServerInfo,
    timeout: aiohttp.ClientTimeout,
    log: logging.Logger,
    max_delta_file_size: int,
) -> None:
    """
    Download a file from a server using aiohttp.
    Raises exceptions on errors
    """
    async with aiohttp.ClientSession() as session:
        headers = {"accept-encoding": "gzip"}
        async with session.get(
            server_info.url + "/" + filename,
            headers=headers,
            timeout=timeout,
            proxy=proxy_url,
        ) as resp:
            resp.raise_for_status()
            size = int(resp.headers.get("content-length", 0))
            max_delta_file_size_bytes = max_delta_file_size * 1024 * 1024
            if size > max_delta_file_size_bytes:
                raise MaxDeltaFileSizeExceededError(f"Maximum delta file size exceeded: {max_delta_file_size} MiB.")
            log.debug(f"Downloading delta file {filename}. Size {size} bytes.")
```
