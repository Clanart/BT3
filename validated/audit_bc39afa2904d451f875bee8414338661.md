### Title
Unauthenticated blame evaluation lets any party cause an honest participant to be declared faulty - (File: crypto/dkg/pedpop/src/lib.rs)

### Summary
Analogous to the referenced access-control flaw (an endpoint reachable by any authenticated user, with no check that the caller is authorized for the action), PedPoP's blame path performs no authorization check that the accusation actually originates from the claimed `recipient`. `BlameMachine::blame` / `AdditionalBlameMachine::blame` accept a caller-supplied `recipient` (the accuser) and, when the provided `EncryptionKeyProof` is `None` or fails verification, deterministically return `recipient` as the faulty party. Since the encrypted secret-share messages the API operates on are exchanged/publicly observable, an unprivileged third party can invoke the blame oracle with an honest victim's index and garbage/absent proof bytes, and the machine will always condemn the victim.

### Finding Description
`blame_internal` in `crypto/dkg/pedpop/src/lib.rs` takes `sender`, `recipient`, `msg`, and `proof` entirely from the caller. It calls `Decryption::decrypt_with_proof` (`crypto/dkg/pedpop/src/encryption.rs`), which:

1. Verifies `msg.pop` (a Schnorr PoP over `pop_challenge(context, R, msg.key, from, msg)`). This authenticates that `msg` was authored by `sender` — but `from` is the *sender*, and the challenge does not bind the intended `recipient` at all. A genuinely delivered `sender → R` ciphertext is equally valid under any claimed `recipient`.
2. If `proof` is `Some`, verifies the accuser's DLEq proof tying `msg.key` to `enc_keys[recipient]`. If `proof` is `None`, or the DLEq fails, it returns `DecryptionError::InvalidProof`.

`blame_internal` then maps `InvalidProof` → `recipient` (the accuser is faulty). The intent is "an accuser who cannot prove the decryption key for a well-formed message is lying." But nothing proves the caller *is* `recipient` or that `recipient` ever made the accusation. `AdditionalBlameMachine::new` is even explicitly designed to evaluate blame "regardless of if the caller was a member of the DKG protocol," and `AdditionalBlameMachine::blame` is a pure function of public inputs (`commitment_msgs` were already broadcast; `msg` and `proof` are attacker-chosen bytes read via `EncryptedMessage::read`/`EncryptionKeyProof::read`).

Relevant code (from `crypto/dkg/pedpop/src/lib.rs`):
- `blame_internal` returns `recipient` on `DecryptionError::InvalidProof`, with no authentication of the accusation (`self.encryption.decrypt_with_proof(sender, recipient, msg, proof)`).
- `decrypt_with_proof` in `crypto/dkg/pedpop/src/encryption.rs` returns `InvalidProof` whenever `proof` is `None` or the DLEq check fails, after the PoP check passes for any authentic sender message.

The PoP in `pop_challenge` binds `(context, R, key, from, ciphertext)` — no recipient field — so a real `sender → R` share message verifies for the forged tuple `(sender, victim)`.

### Impact Explanation
The blame oracle's verdict is consumed by the DKG/deployment layer to identify and penalize faulty participants (in Serai's design this feeds slashing/blame outcomes). An attacker with no protocol privilege can take a legitimately published `EncryptedMessage` authored by any `sender`, call the blame API with `recipient = victim`, `proof = None` (or malformed bytes), and obtain a verdict declaring the honest `victim` faulty — every time, deterministically. This converts public transcript data into a forged accusation that attributes fault to an innocent party, a false-positive slashing/blame primitive enabled by the missing authorization check on the accuser identity.

### Likelihood Explanation
Reachable by any party that can observe or obtain the protocol's share messages (they are transmitted between participants and, in Serai's architecture, relayed so blame can be adjudicated by non-participants). Requires no secret keys, no collusion, and no malformed cryptographic objects — `proof = None` suffices. The only prerequisite is invoking the blame evaluation, which `AdditionalBlameMachine` explicitly supports for non-participants. Deterministic success.

### Recommendation
Bind the accusation to its issuer:
- Include the `recipient`/accuser identity in `pop_challenge` (or in a dedicated accusation challenge) so a ciphertext is only adjudicable for the party it was addressed to.
- Require `blame`/`blame_internal` to verify an authentication artifact from `recipient` (e.g., a Schnorr signature over `(context, sender, msg)` under `enc_keys[recipient]`, or require a valid `EncryptionKeyProof` — returning a distinct error rather than blaming `recipient` when `proof` is `None`).
- Treat `proof: None` as an invalid/incomplete accusation that cannot resolve to blaming `recipient`, rather than as evidence of the recipient's fault.

### Proof of Concept
```rust
// Context: a completed commitment round for participants 1..=n.
// `commitment_msgs` are public; `real_msg` is the EncryptedMessage<SecretShare>
// actually sent from `sender` to some honest party R (observed on the wire).

let blame_machine = AdditionalBlameMachine::<Ristretto>::new(
    context,          // publicly derivable [u8; 32]
    params.n(),
    commitment_msgs,  // public commitment messages
).unwrap();

// Victim = any honest participant index V; sender = any participant that
// published a real share message (PoP verifies against `from = sender`).
let victim = Participant::new(2).unwrap();
let sender = Participant::new(1).unwrap();

// No EncryptionKeyProof at all: the attacker is not the real recipient and
// cannot produce one. blame_internal -> decrypt_with_proof -> InvalidProof
// -> returns `recipient` = victim as the faulty party.
let blamed = blame_machine.blame(sender, victim, real_msg.clone(), None);
assert_eq!(blamed, victim); // honest victim condemned by a third party
```

The same outcome is produced via `BlameMachine::blame(...)` with `proof = None` or with an `EncryptionKeyProof` whose DLEq fails: any invalid/missing proof resolves to `recipient` fault, with no check that the accusation was ever made by `recipient`.
